# 5.3 TCP 回射服务器程序：str_echo 函数

> [5.2 服务器 main](../5.2_Server_Main.md) · [5.4 客户 main](../5.4_Client_Main.md) · `writen`：[Ch 3.9](../../Chapter03_SocketProgramIntro/3.9_Readn_Writen_Readline.md)

## 核心主旨与关键论据

`str_echo` 是服务器**子进程的业务核心**：从已连接套接字读数据，**原样写回**。它体现了 TCP **字节流** 在服务器侧的典型处理模式——**读多少、回多少**（直到对端关闭）。

---

## 核心知识点与代码拆解

### 典型逻辑（伪代码）

```c
void str_echo(int sockfd)
{
    ssize_t n;
    char line[MAXLINE];

    again:
    while ( (n = read(sockfd, line, MAXLINE)) > 0)
        Writen(sockfd, line, n);    /* 把本次读到的 n 字节全部写回 */

    if (n < 0 && errno == EINTR)
        goto again;                 /* 被信号打断则重试（包裹函数常内置） */

    /* n == 0：对端关闭，正常返回 */
}
```

### 三个 API 的分工

| 调用 | 作用 | 为何这样选 |
|------|------|------------|
| **`read`（循环）** | 从网络读入缓冲区 | TCP **无记录边界**；一次 read 可能小于可用数据，也可能一次读多行 |
| **`writen`** | 保证把本次 `n` 字节**全部**写回 | 避免短写（short write） |
| **返回条件 `n==0`** | 对端发 **FIN**，半关闭读侧 EOF | 子进程返回 → `exit` → 发 FIN |

### 为何用 read 而非 readline

| | `read` + 循环 | `readline` |
|--|---------------|------------|
| 语义 | **透传字节块** | 按 `\n` 取一行 |
| 适用 | Echo、代理、隧道 | 文本行协议（FTP 命令等） |
| 缓冲 | 每次最多 MAXLINE，可含半行 | 内部静态缓冲，见 Ch 3.9 线程安全问题 |

回射服务**不关心行边界**：客户发 `"hello\n"` 可能被拆成两次 read，服务器仍按读到的块回射，客户 `readline` 最终拼成一行。

---

## 逻辑脉络与因果关系

```text
客户 writen 一行 → 网络（可能分片）→ 服务器 read 得 n 字节
→ writen 回射 n 字节 → 客户 readline 收齐
… 重复直到客户 close → 服务器 read 返回 0 → str_echo 返回 → 子 exit
```

---

## 易错细节与重点结论

| 易错 | 纠正 |
|------|------|
| read 一次以为读完一行 | 服务器应用 **while (n>0)**，不是读一次就 writen 一次就结束函数（除非 n=0） |
| writen 换成 write | 可能短写，协议错乱 |
| n=0 当错误 | **0 = 正常 EOF**，对端关闭 |
| 子进程 str_echo 里再 fork | 每连接一线程/一进程，**不要再 fork** |
