# 5.8 POSIX 信号处理

> [5.9 SIGCHLD](../5.9_SIGCHLD_Process.md) · [5.13 SIGPIPE](../5.13_SIGPIPE_Signal.md)

---

## 核心主旨与关键论据

**信号（Signal）** 通知进程「某事件发生」，也称**软件中断**。网络服务器必须用可靠方式注册处理函数，并在慢系统调用被中断后正确恢复 —— 否则 `accept`/`read` 随机失败或僵尸泛滥。

---

## 核心知识点

### 信号处置三种方式

| 处置 | 含义 |
|------|------|
| **捕获**（自定义函数） | 执行 sigaction 指定的 handler |
| **`SIG_IGN`** | 忽略（**SIGKILL、SIGSTOP 不可忽略**） |
| **`SIG_DFL`** | 默认，多数为终止进程 |

### 为何不用传统 `signal()`

- 历史上各系统对 `signal` 语义不一致（是否自动重启、是否可靠递送）  
- **POSIX 规定用 `sigaction`**

### 本书 `Signal()` 包裹函数

- 首字母大写，内部 **`sigaction`**  
- 提供可移植、可预期的 POSIX 语义  

### `SA_RESTART` 的关键作用

| 场景 | 无 SA_RESTART | 有 SA_RESTART |
|------|---------------|---------------|
| 阻塞在 `accept`/`read` | 信号来 → 慢调用返回 **-1, errno=EINTR** | 内核**自动重启**该调用 |
| 编程负担 | 须手动循环重试（Read/Accept 包裹常做） | 减少 EINTR 散落 |

注意：SIGCHLD 处理函数里调用的 **`waitpid` 不应被 SA_RESTART 无限重启** —— 通常 handler 很短，返回后 accept 继续。

## 易错细节与重点结论

| 易错 | 纠正 |
|------|------|
| 在信号处理函数里 `printf` | **非异步信号安全**，可能死锁 |
| 以为所有信号会排队 | **同类型信号可能丢失**（5.10） |
| 多线程程序用同一套 handler | 应用 **`pthread_sigmask`**、`sigwait`（进阶） |
| Pthread 函数错用 errno | 线程 API 错误在**返回值**，不是 errno（Ch 1.4） |
