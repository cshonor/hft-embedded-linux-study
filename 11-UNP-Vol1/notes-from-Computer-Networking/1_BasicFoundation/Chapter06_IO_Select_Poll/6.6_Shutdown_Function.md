# 6.6 shutdown 函数

> [6.7 终极 str_cli](../6.7_Str_Cli_Final_Revised.md) · close：[Ch 4.9](../../Chapter04_BasicTCPSocket/4.9_Close_Function.md)

---

## 核心主旨与对比分析

常规终止用 **`close`**，无法满足批量输入的**半关闭**需求。**`shutdown`** 精确切断全双工的一个方向。

```c
int shutdown(int sockfd, int howto);
```

---

## close 的两大局限

| # | 局限 |
|---|------|
| **1** | **引用计数** — `close` 只减计数；`fork` 后未必真发 FIN |
| **2** | **全双工** — `close` 同时关掉读+写两个方向 |

---

## shutdown 的突破

- **无视引用计数**，直接触发 TCP 终止序列（对指定方向）  
- **`howto` 精确控制**：

| 常量 | 含义 |
|------|------|
| **`SHUT_RD` (0)** | 关**读半部**；丢弃接收缓冲现有数据；后续对端数据被确认后丢弃 |
| **`SHUT_WR` (1)** | **半关闭写** — 发完发送缓冲 → **FIN**；**不能再 write**，**仍可 read** |
| **`SHUT_RDWR` (2)** | 读写全关 |

**批量输入关键**：stdin EOF 后调用 **`Shutdown(sockfd, SHUT_WR)`** — 只关写，继续收服务器回射。

---

## 易错细节与重点结论

| 易混 | 纠正 |
|------|------|
| shutdown = close | shutdown **不关 fd**，只影响连接方向 |
| SHUT_WR 后还能 write？ | 再写可能 **SIGPIPE**（若对端已 RST） |
| 半关闭 = TCP 半关闭状态 | 应用层主动 **SHUT_WR** 触发协议层 FIN |
