<a id="ch1-2-connect"></a>

## 一、`connect()` — 把「去哪台:哪个端口」交给内核

```c
connect(sockfd, (SA *) &servaddr, sizeof(servaddr));
```

| 项 | 说明 |
|----|------|
| **`sockfd`** | `socket()` 成功返回的描述符 |
| **`(SA *) &servaddr`** | `SA` = `#define SA struct sockaddr`；把 **`sockaddr_in*`** 转成**通用地址指针**（BSD 惯例，以后 IPv6 / 别的族也用同一套 API 形状） |
| **`sizeof(servaddr)`** | 必须传**真实结构体大小**，让内核知道是 IPv4 的 `sockaddr_in` |
| **内核行为** | 读 `servaddr` 里的 **目的 IP + 目的端口** → 路由 → 发 **TCP SYN**（三次握手） |
| **返回值 < 0** | 失败；**禁止**对**同一个** `sockfd` 再 `connect` |
| **失败后正确做法** | `close(sockfd)` → 重新 `socket()` → 再填地址 → 再 `connect` |

## 二、`read()` 循环 — TCP 没有「一次读一包」

```c
while ((n = read(sockfd, recvline, MAXLINE)) > 0) {
    recvline[n] = 0;
    fputs(recvline, stdout);
}
if (n < 0) err_sys("read error");
```

| `read` 返回值 | 含义 |
|---------------|------|
| **> 0** | 本次读到的字节数 `n`（可能小于 MAXLINE） |
| **== 0** | 对端 **关闭写方向**（常见：收到 **FIN**），数据流结束 → **正常退出循环** |
| **< 0** | 出错（查 `errno`；信号中断 `EINTR` 见 [Ch 3.9](../Chapter03_SocketProgramIntro/3.9_Readn_Writen_Readline.md)） |

**为何必须 `while`？** TCP 是**字节流**，内核接收缓冲区**没有应用层报文边界**。Daytime 一次发 26 字节，你的进程可能被分成 **10 + 16** 两次 `read` 才拿全。

**`recvline[n] = 0`**：`read` 只写二进制，**不带 `'\0'`**；加 NUL 后 `fputs` 才能当 C 字符串打印（协议本身不需要 `\0`）。

## 三、应用层 ↔ 内核（一张表）

| 你调用的 API | 内核 / 协议在干什么 |
|--------------|---------------------|
| `socket` | 创建套接字，分配 **fd** |
| 填 `servaddr` | 仅在**进程内存**；须已是正确 **IP + 端口（网络序）** |
| `connect` | **三次握手**，建立连接控制块 |
| `read` | 从该连接的 **TCP 接收缓冲区** 拷贝到用户缓冲区 |
| `exit` / `close` | 关闭 fd，通常发 **FIN**，四次挥手 |

**13 端口**：IANA 标准 **Daytime** 服务，返回人类可读时间字符串（明文 TCP）。
