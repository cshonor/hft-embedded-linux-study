|----|------|

| 步骤 | 说明 |

### 3. 协议无关定义

代码**不写死** `AF_INET` / `AF_INET6`，**不固定** `sockaddr_in` / `sockaddr_in6`；由 API 在**运行期**根据域名/服务返回对应地址结构 — **一套代码兼容双栈**。

## 二、关键函数与结构体（IPv4 / IPv6 / 无关对照）

| 分类 | IPv4（1.2 硬编码） | IPv6 硬编码（图 1-6） | 协议无关 |
|------|-------------------|----------------------|----------|
| **地址族** | `AF_INET` | `AF_INET6` | **`AF_UNSPEC`**（hints，自动选） |
| **地址结构** | `sockaddr_in` | `sockaddr_in6` | **`sockaddr *`**、`addrinfo` 链表 |
| **地址存储** | `in_addr`（32 bit） | `in6_addr`（128 bit） | **`ai_addr`** 自动封装 |
| **解析 API** | `gethostbyname`（仅 v4、非线程安全） | 无单一等价 | **`getaddrinfo`**（全协议、可重入） |

### 结构体简要定义

```c
/* IPv4 */
struct sockaddr_in {
    sa_family_t     sin_family;   /* AF_INET */
    in_port_t       sin_port;
    struct in_addr  sin_addr;     /* 32 bit */
    char            sin_zero[8];
};

/* IPv6 */
struct sockaddr_in6 {
    sa_family_t     sin6_family;  /* AF_INET6 */
    in_port_t       sin6_port;
    uint32_t        sin6_flowinfo;
    struct in6_addr sin6_addr;    /* 128 bit */
    uint32_t        sin6_scope_id;
};

/* 协议无关：getaddrinfo 输出 */
struct addrinfo {
    int              ai_family;    /* AF_INET / AF_INET6 */
    int              ai_socktype;
    int              ai_protocol;
    socklen_t        ai_addrlen;
    struct sockaddr *ai_addr;    /* 指向 in 或 in6 */
    struct addrinfo *ai_next;      /* 多结果链表 */
};
```

## 三、执行流程原理

### 1. 硬编码痛点（1.2 → IPv6）

迁移 IPv6 至少改动：

| # | 改动 |
|---|------|
| 1 | `AF_INET` → `AF_INET6` |
| 2 | `sockaddr_in` → `sockaddr_in6` |
| 3 | `sin_*` → `sin6_*` |
| 4 | `inet_pton(AF_INET, …)` → `AF_INET6` |
| 5 | `socket` / `connect` 所用地址长度 |

改完 = **绑定 IPv6 的新耦合代码**，**无法同时双栈**。

### 2. 图 1-6：IPv6 硬编码客户端

**仅替换协议相关宏与结构体** — **治标不治本**。

→ [code/1.3/…/daytimetcpcli6.c](./code/1.3_ProtocolIndependence/original_c/daytimetcpcli6.c)

### 3. 最优：协议无关链路

```text
入参(主机名 + 服务名)
  → getaddrinfo(hints.ai_family = AF_UNSPEC)
  → addrinfo 链表（可能含多条 v4/v6 地址）
  → for (rp = res; rp; rp = rp->ai_next)
        socket(rp->ai_family, rp->ai_socktype, rp->ai_protocol)
        connect(rp->ai_addr, rp->ai_addrlen)  /* 成功则 break */
  → freeaddrinfo(res)
```

**全程无协议宏/固定结构体硬编码** — 由 DNS + 内核选择可用协议。

**`daytimetcpcligai.c` 关键片段**：

```c
hints.ai_family   = AF_UNSPEC;
hints.ai_socktype = SOCK_STREAM;
getaddrinfo(argv[1], "daytime", &hints, &res);
for (rp = res; rp != NULL; rp = rp->ai_next) {
    sockfd = socket(rp->ai_family, rp->ai_socktype, rp->ai_protocol);
    if (connect(sockfd, rp->ai_addr, rp->ai_addrlen) == 0)
        break;
    close(sockfd);
}
freeaddrinfo(res);
```

<a id="ch1-3-pitfalls"></a>

## 五、易错点与坑点

| # | ❌ 错误 | ✅ 规范 |
|---|--------|--------|
| 1 | 支持 v6 时全局替换 `AF_INET`/`sockaddr_in` | **遗漏、双栈维护翻倍**；新 IP 版本又要重构 |
| 2 | 部分硬编码 + 部分 `getaddrinfo`，乱强转 `sockaddr_in*` | **越界/未定义行为** |
| 3 | 继续用 `gethostbyname`/`getservbyname` | 统一 **`getaddrinfo` + `freeaddrinfo`**，`AF_UNSPEC` |

## 六、拓展：IPv4 / IPv6 首部与地址空间

| 项目 | IPv4 | IPv6 |
|------|------|------|
| **地址长度** | 32 bit（4 B） | 128 bit（16 B） |
| **地址空间** | ≈ 2³²（42.9 亿） | ≈ 2¹²⁸ |
| **首部** | 可变 20–60 B（含选项） | **固定 40 B**，扩展走扩展头 |
| **书写** | `192.168.1.1` | `2001:db8::1` |
| **转发** | 首部字段多，校验复杂 | 固定首部，转发更高效 |

## 七、学习总结 / 考点

| # | 要点 |
|---|------|
| 1 | **硬编码协议 = 短期能用、长期难维护** |
| 2 | 双栈默认 **`hints.ai_family = AF_UNSPEC`** |
