# 5.13 SIGPIPE 信号

> 前置：[5.12](../5.12_Server_Process_Abort.md) · RST：[5.15](../5.15_Server_Host_Restart.md)

---

## 核心主旨与关键论据

接续 5.12：若客户端在收到 **RST** 之后，**不 read** 而继续 **`write`**，内核向进程发 **`SIGPIPE`**；默认行为是**终止整个进程**。高可靠服务必须在初始化时 **`SIG_IGN` SIGPIPE**。

---

## 核心机制

| 条件 | 结果 |
|------|------|
| 向已收到 **RST** 的套接字 **write** | 内核发 **`SIGPIPE`** 给进程 |
| 默认处置 **SIG_DFL** | **进程被杀死** |
| 捕获或忽略 SIGPIPE | `write` 返回 **-1**，**`errno = EPIPE`** |

### 与 5.12 的衔接

- 5.12：用户输入后 writen → RST → **readline 得 0** 退出（未必触发 SIGPIPE）  
- 5.13：强调**继续写**已复位连接 → **SIGPIPE / EPIPE**

---

## 易错细节与重点结论

**标准防线**（服务器/客户端初始化处）：

```c
Signal(SIGPIPE, SIG_IGN);   /* 或 signal(SIGPIPE, SIG_IGN) 在包裹里 */
```

| 若不忽略 | 风险 |
|----------|------|
| 某一客户异常 | **整个** echo 服务器进程被 SIGPIPE 杀死，其它客户全断 |

| 易混 | 纠正 |
|------|------|
| EPIPE 与 ECONNRESET | EPIPE 在 **write**；ECONNRESET 多在 **read**（对端 RST 后读） |
| 只对服务器设 | **客户端**同样应忽略，避免写已关闭连接时自杀 |

---

> 💡 **后续拓展留白**  
> - `MSG_NOSIGNAL`（Linux send）替代忽略 SIGPIPE  
> - 多进程服务器是否每个子进程都要设 SIG_IGN
