3.1

引言

章级精读：../study.md#ch03-1 · 上一章：ch02

本节核心目标

明确链路层在 TCP/IP 中的使命：收发 IP 数据报，屏蔽物理介质差异。

核心要点

  • 链路层为网络层提供本地交付与封装（以太网、Wi‑Fi、PPP 等）。
  • 多种链路技术并存 → 上层 IP 保持统一（IP-on-everything）。
  • MTU：单链路一次可传的最大载荷上限（以太网常见 1500 B）→ 3.8。

与上下层

应用 → TCP/UDP → IP 数据报 → 链路层帧 → 物理比特
  • 换链路类型（光纤/Wi‑Fi）通常不必改 IP 语义。
3.2

以太网与 IEEE 802 局域网/城域网标准

章级精读：../study.md#ch03-2 · 自顶向下：§6.3 MAC · §6.4 以太网/交换 · 交换机：3.4 · Hub 嗅探：Wireshark §2.3.2

本节核心目标

掌握集线器 Hub、以太网帧格式、共享式 → 交换式介质访问演进（CSMA/CD 与冲突域），以及 VLAN/QoS/链路聚合要点。

802 地图：802.3 以太网 + 802.1Q/p/AX + 802.3x → 3.4 总览

一、介质访问机制演进（大白话）

1）经典共享式以太网（Hub 时代）

集线器（Hub）基础属性

项 说明
工作层级 物理层；只处理电/光信号，不识别 MAC、不解析帧
本质 多端口中继器：信号放大、整形、转发
拓扑 物理星型，逻辑总线型——所有端口共用一条总线
组网 总线型 / 集线器 Hub 星型；半双工

转发与域

项 说明
转发规则 收到信号后向除入端口外所有端口泛洪，不区分目标 → 本网段主机都能收到（利于嗅探 → 混杂模式）
冲突域 整台 Hub 所有端口 = 1 个冲突域；多机同时发 → 信号冲突
广播域 整台 Hub = 1 个广播域
双工 / 带宽 半双工；全体端口共享带宽（如 10Mbps Hub 全员瓜分）

CSMA/CD（考试简答 · 四步）

共享信道必须靠 CSMA/CD 规避冲突：

  1. 先听后发（载波监听）：发送前侦听信道是否空闲
  2. 边发边听（冲突检测）：发送中持续检测是否冲突
  3. 冲突停发：发现冲突立即停止，发阻塞信号通知全网
  4. 随机重传（退避）：二进制指数退避后重试

Hub 优缺点

优点 缺点
结构简单、价格低廉 冲突频发，主机越多效率越低
早期小型组网 流量全网可见，安全性极差，易嗅探
半双工 + 共享带宽；已被交换机全面替代（MAC 泛洪可让交换机泛洪像 Hub → 3.10）

2）现代交换式以太网（Switch，当前主流）

项 说明
组网 交换机星型；端口常 全双工
机制 端口点对点；基于 MAC 地址表 转发，不再靠 CSMA/CD 协调整网
  1. 交换机查 MAC 表，只向目标端口转发（不是 Hub 那样所有端口都收到）
  2. 全双工时收发物理分离，可同时发+收，无信号冲突

冲突域：每个交换机端口 ≈ 独立冲突域（常缩小到单个端点）；交换网内基本无经典冲突。

3）Hub 与交换机核心对比（直接背）

对比项 集线器（Hub） 交换机（Switch）
工作层 物理层 数据链路层
转发方式 全网广播 基于 MAC 表 精准转发
冲突域 整设备 1 个 每端口独立（全双工下常无冲突）
广播域 1 个 1 个（未划 VLAN）；VLAN 可再分
双工 半双工 全双工（常见）
带宽 所有端口共享 单端口独享
CSMA/CD 必须 基本不需要

口诀：Hub 半双工 CSMA/CD 一大域 · Switch 全双工 MAC 表 端口各一域

现状：Hub 基本不用了

现在几乎被交换机完全取代——日常组网直接选交换机，不用考虑集线器。

Hub（集线器） Switch（交换机）
层级 一层（物理层） 二层
域 / 带宽 所有端口同一冲突域、共享带宽 每端口独立带宽，点对点转发
转发 一台发 → 所有端口广播 → 卡顿、冲突、不安全 查 MAC 表只转目标口 → 快、少冲突、隐私好
速率 多为 10/100M，性能差 千兆/万兆常见
现状 早已淘汰，买不到全新主流 Hub 家用 / 企业标配

Hub 还有场景吗？

场景 说明
家用 / 办公 彻底不用
极特殊 老旧工业设备、抓包（Hub 全网广播便于监听 → §2.3.2）、古董机房调试
考试 / 原理 理解 CSMA/CD、冲突域、与交换机对比；MAC 泛洪可让交换机暂时「像 Hub」→ 3.10

背一句：Hub = 一层共享总线、泛洪、已淘汰；Switch = 二层 MAC 转发、现网标准（含 802.3x PAUSE 流控 → 3.3 §五，Hub 不支持）。

易混 纠正
Hub vs 交换机 Hub 不识 MAC；交换机 学 MAC、按端口转
Hub vs 路由器 Hub 在 L1；路由器在 L3，改 IP 路径
真 Hub vs 假 Hub 真 Hub 串线可见双向流量；假 Hub（实为交换机）无效

→ WiFi 用 CSMA/CA（避免冲突，不是 CD）→ 3.5 大白话 · 隐藏终端/RTS/CTS · 自顶向下 §6.3

二、以太网帧（必背 · 考试精简）

Ethernet II 帧结构（最常用）

字段 字节 核心作用
目的 MAC 6B 二层寻址，接收方物理地址
源 MAC 6B 二层寻址，发送方物理地址
类型（EtherType） 2B 上层协议分用（见下表）
载荷（数据） 46–1500 B 上层 IP 数据报；MTU = 1500 B；不足 46 B 填充
FCS 4B CRC 检错；以太网只检错、不重传，坏帧直接丢弃

常见 EtherType

值 协议
0x0800 IPv4
0x0806 ARP
0x86DD IPv6

EtherType vs IP Protocol：EtherType 是 L2→L3 路标（只定 IPv4/IPv6/ARP）；IP Protocol 是 L3→内层 路标（ICMP/TCP/UDP）— 口诀：二层定三层，三层定内层 → ch01 §分用

整体格式

目的MAC(6B) | 源MAC(6B) | 类型(2B) | 数据(46–1500B) | FCS(4B)
  • 帧总长：64～1518 B（不含前导码 7B + SFD 1B）

三、进阶 802.1 族（必背考点）

1）802.1Q VLAN（虚拟局域网）

  • 在源 MAC 与类型字段之间插入 4 B VLAN 标签（Tag）
  • 作用：隔离广播域（交换机已隔离冲突域）→ 3.4
  • 带 Tag 帧长：68～1522 B

TCI 字段详解：PCP + DEI + VID

4 B VLAN 标签 = TPID（2B） + TCI（2B） TCI（16 bit） = PCP（3 bit） + DEI（1 bit） + VID（12 bit）

TPID(0x8100, 2B) | PCP(3b) | DEI(1b) | VID(12b)  ← 合在 TCI 里
字段 位数 要点
TPID 16 bit 固定 0x8100，表示这是 VLAN 帧
PCP 3 bit 802.1p 二层 QoS，0–7，数字越大优先级越高
DEI 1 bit 可丢弃标识（旧称 CFI）
VID 12 bit VLAN ID，可用 1–4094

PCP 常用等级（考点）

PCP 典型业务
0 尽力而为（默认）— 普通网页、下载
1 背景 — 备份、日志
3 关键业务 — 视频会议
5 实时视频 — 流媒体
6 语音 — VoIP
7 网络控制 — 路由协议、交换机管理

DEI（Drop Eligible Indicator）

值 含义
0 正常；拥塞时优先保留
1 低优先级；拥塞时优先丢弃

→ 配合 QoS：流量监管、拥塞时保关键业务

VID（VLAN Identifier）

值 说明
0 仅优先级标记，不表示 VLAN
1 交换机默认 VLAN（端口出厂多在 VLAN 1）
1–4094 可用 VLAN ID（考试常考）
4095 保留，不可用
范围 12 bit 共 4096 个编号（0–4095）

考试填空/简答精简版

  • 802.1Q Tag = TPID 0x8100 + TCI（PCP 3b + DEI 1b + VID 12b）
  • PCP：0–7，越大越优先；6 语音、7 网络控制
  • DEI：1 = 拥塞时先丢
  • VID：1–4094 可用；0/4095 不用；1 为默认 VLAN

2）802.1p 与 802.1q 的关系

说明
802.1q VID → VLAN / 广播域隔离
802.1p PCP → 二层 QoS 优先级（写在同一 Tag 的 TCI 里）

3）802.1AX（原 802.3ad）链路聚合 LACP

  • 多根物理链路捆绑成一条逻辑链路 1. 提升总带宽 2. 冗余：一条断了自动切换
  • 协商帧 EtherType：0x8809；常用组播 MAC 传 LACP

必背三句话

  1. 以太网：二层 MAC 寻址、MTU = 1500、CRC 检错不重传
  2. 冲突域：交换机端口隔离 · 广播域：VLAN（802.1Q） 隔离
  3. 802.1p：QoS 优先级 · 802.1AX：链路聚合

四、30 秒写卷子 + 易混

介质访问：Hub · CSMA/CD · 一大冲突域 · Switch · 每端口一域

帧：Ethernet II · 0x0800/0806/86DD · 64–1518B · MTU 1500 · FCS 只检错

802.1Q：TPID 0x8100 · TCI=PCP(3)+DEI(1)+VID(12) · VID 1–4094 · PCP 0–7

易混 纠正
帧 vs 分组 帧 = 链路层；IP 分组 = 网络层
CSMA/CD vs CA CD = 有线以太网；CA = WiFi
冲突域 vs 广播域 交换机拆冲突域；802.1Q 拆广播域
MTU vs 帧长 MTU 1500 = 载荷上限；最小帧 64 B（含填充）

五、自测（6 题）

  1. Hub 组网为何必须用 CSMA/CD？交换机为何可以取消？
  2. EtherType 0x0806 表示什么？以太网收到坏帧会重传吗？
  3. 802.1Q 插在帧的什么位置？TPID 是多少？
  4. 交换机隔离的是冲突域还是广播域？VLAN 隔离哪个？
  5. VID 可用范围？PCP=6 通常对应什么业务？DEI=1 表示什么？
  6. CSMA/CD 四步各是什么？
答案
  1. Hub 同一冲突域，需 CSMA/CD；交换机端口隔离 + 常全双工。
  2. ARP；不重传，丢弃坏帧（靠上层 TCP 等）。
  3. 源 MAC 与类型字段之间；TPID 0x8100。
  4. 交换机默认主要拆冲突域；VLAN 拆广播域。
  5. 1–4094；VoIP 语音；拥塞时优先丢弃。
  6. 先听后发 → 边发边听 → 冲突停发 → 二进制指数退避重传。

3.3

全双工、省电、自动协商和 802.3x 流量控制

章级精读：../study.md#ch03-3 · CSMA/CD 与交换：3.2 §一

本节核心目标

掌握半/全双工、自动协商、WoL/EEE 省电唤醒与双工不匹配；了解 802.3x PAUSE、802.1X。

一、双工模式：半双工 vs 全双工

1）半双工（Half-duplex）

项 说明
行为 同一时刻只能发或只能收，不能同时进行
机制 依赖 CSMA/CD 防碰撞
场景 Hub、老旧共享式以太网

2）全双工（Full-duplex）

项 说明
行为 收发物理分离，可同时发+收
冲突 交换机点对点链路，CSMA/CD 基本失效、冲突消失
场景 现代交换机 + 网线默认全双工；千兆及以上几乎只用全双工

二、自动协商（Auto-negotiation）

1）协商什么

两端自动匹配共同支持的：

  • 速率：10 / 100 / 1000 Mbps
  • 双工：半双工 / 全双工
  • 流控（可选）

优先级（速率越高越优；同速率下全双工 > 半双工）

1000M 全双工 > 1000M 半双工 > 100M 全双工 > 100M 半双工 > 10M 全双工 > 10M 半双工

2）标准规定

速率 自动协商
10/100M 可选（可关）
1000M（千兆） 强制开启，不能关闭

3）核心规则（考试必背）

情况 结果
两端都自动协商 通常协商到最优（多为全双工）
一端强制全双工、另一端自动协商 自动协商端常降级为半双工 → 双工不匹配 → 大量丢包、延迟高
光纤以太网 不支持自动协商 → 必须手动配速率/双工

三、10 行极简背诵版

  1. 半双工：收发不能同时；要 CSMA/CD；Hub 时代。
  2. 全双工：可同时收发；交换点对点无经典冲突。
  3. 自动协商：匹配 10/100/1000M + 半/全双工 + 流控。
  4. 优先级：速率优先，同速率全双工 > 半双工。
  5. 千兆：自动协商强制开。
  6. 两端自协商 → 通常全双工最优。
  7. 一端强全双工、一端自协商 → 半双工不匹配 → 丢包。
  8. 光纤：手动配置，不自协商。
  9. 全双工交换网：CSMA/CD 基本消失。
  10. 一句话：自协商配速率双工；全双工交换无冲突。

四、省电与唤醒（考点完整版）

1）WoL 与魔术包（Magic Packet）— 考试标准答案

前置硬件条件

  1. 电脑关机/休眠：CPU、内存断电，系统不运行
  2. 主板电源仍给网卡待机低压电 → 网卡超低功耗监听
  3. BIOS/UEFI + 网卡 + 系统均开启 WoL

魔术包结构（核心 · 固定 102 B）

6 B 全 FF（FF FF FF FF FF FF） + 目标 MAC 重复 16 次（16 × 6 B = 96 B）
  • 常通过 UDP 端口 9、以太网广播帧 发送
  • 二层（数据链路层）；不依赖 IP、不依赖 OS

完整工作流程

  1. 发送端构造魔术广播包，在局域网内广播
  2. 关机主机仅网卡监听（CPU 不参与）
  3. 网卡识别：6×FF 前缀 + 自身 MAC 连续 16 次
  4. 网卡向主板电源管理芯片发唤醒电信号
  5. 主板上电 → 整机启动（等同按电源键）

关键特点（必背）

# 要点
1 二层硬件触发，OS 不必运行
2 靠广播，一般仅同一局域网可唤醒
3 只校验 MAC，不校验 IP
4 识别与唤醒由网卡硬件完成，CPU 不参与

简答题 10 行背诵版

  1. 关机/休眠：CPU、内存停；网卡待机供电监听。
  2. 须开 BIOS + 网卡 WoL。
  3. 魔术包 = 6×FF + MAC×16（共 102 B）。
  4. 常用 UDP/9、广播帧、二层。
  5. 发送端发广播魔术包。
  6. 网卡独立监听，系统不运行。
  7. 匹配 FF 前缀 + 本机 MAC×16。
  8. 网卡触发主板电源芯片。
  9. 整机唤醒。
  10. 同网段广播；纯硬件、不认 IP。

2）IEEE 802.3az（EEE，高效节能以太网）

  • 链路空闲 → 端口低功耗休眠（收发电路降耗）
  • 有流量 → 快速唤醒，恢复 100M/1000M 等协商速率
  • 交换机常见：Auto-Power-Down — 无链路/空闲时停供端口电

3）Wi‑Fi 省电（补充）

  • 802.11 Power Save：STA 定时休眠，AP 缓存待发数据，终端定期唤醒收包 → 3.5

填空 / 简答精简版

  1. WoL：休眠靠网卡低功耗监听；6×FF + MAC×16 魔术包唤醒
  2. EEE（802.3az）：端口空闲休眠、有流唤醒
  3. 核心：省电 = 设备/端口低功耗；唤醒 = 二层特殊帧触发

五、802.3x 流量控制（考试完整版）

与 Hub 无关：802.3x / PAUSE 是交换机、全双工网卡的二层机制；Hub 是半双工一层设备，不支持、也发不了 PAUSE → 3.2 Hub 现状

1）在哪完成？（标准定位）

对，完全是交换机（二层）的事（交换机 ↔ 交换机、交换机 ↔ 主机网卡均可发/收）。

项 说明
标准 IEEE 802.3x 全双工流量控制
工作层 数据链路层（MAC 控制子层）
设备 交换机、支持流控的网卡
不用 Hub（半双工、一层）、半双工以太网（靠 CSMA/CD）

2）什么时候发 PAUSE？

一句话：接收端端口缓冲区快满了 → 向直连的发送端发 PAUSE。

场景 谁可能发
交换机 ↔ 交换机 任一侧端口拥塞都可发
交换机 ↔ 服务器/主机 交换机或网卡（若开启流控）

方向：谁要被“撑爆”，谁就发 PAUSE（不是固定只有交换机发）。

3）PAUSE 帧机制（五步流程）

  1. 接收端（交换机端口 / 网卡）缓冲区将满
  2. 向直连对端发 PAUSE 帧（见下节结构）
  3. 帧内 Pause Time：暂停时长，单位 = 512 bit 时间（0～65535）
  4. 发送端收到后暂停该链路发送一段时间，等对端清空缓存
  5. 逐跳（hop-by-hop）：只控相邻一跳，不能跨多台交换机传播

4）Type 字段：0x8808 是什么？

以太网帧 2 字节 Type/Length：

Type 含义
0x0800 普通数据 · IPv4
0x0806 ARP
0x8808 MAC 控制帧（再看 Opcode 区分种类）
0x8809 LACP（链路聚合，见 3.2）

PAUSE：Type = 0x8808 + Opcode = 0x0001 → 表示「请暂停发送」。

5）目的 MAC 为何是「组播」？

MAC 分三类：

类型 特征 示例
单播 给一个设备 00-xx-xx-xx-xx-xx
组播 给一组设备；首字节最低位 = 1 PAUSE、IPv4 组播映射等
广播 所有人 ff:ff:ff:ff:ff:ff

→ MAC 与 IPv4 组播/广播判定规则不同、非一一绑定：ch09.3 完整对照

PAUSE 固定目的 MAC（保留组播，与 IP 无关）：

01-80-C2-00-00-01

支持 802.3x 的设备识别该 DA；开启流控的端口才响应。

6）PAUSE 帧完整结构（按字节）

最小以太网帧 64 字节（不含前导码时常记载荷部分）：

字段 长度 值 / 说明
前导码 + SFD 8 7 B 前导 + 1 B 帧起始（硬件用）
目的 MAC（DA） 6 01-80-C2-00-00-01（固定组播）
源 MAC（SA） 6 发送方端口 MAC
Type 2 0x8808（MAC 控制帧）
Opcode 2 0x0001（= PAUSE）
Pause Time 2 暂停时间（×512 bit 时间）
Padding 42 全 0，凑满最小帧
FCS 4 CRC 校验

三数必背：DA 01-80-C2-00-00-01 · Type 0x8808 · Opcode 0x0001

7）关键特点（必背）

项 说明
工作层 二层 MAC 控制，与上层协议无关
范围 只控直连链路，不能跨设备

8）与 TCP 拥塞控制（高频）

1.1 大白话：为什么冲突域变成「每个端口」？

以前：集线器 Hub（半双工）

  • 所有电脑共享一条总线，抢一条路说话
  • 两人同时发 → 全网冲突
  • 必须 CSMA/CD 监听整网 → 整个网络 = 一个大冲突域

现在：交换机 + 全双工

每个端口是物理分开的一对线：

  主机 ──发线──▶ 交换机端口
  主机 ◀──收线──  交换机端口
  • 发、收两条线分开，互不抢信道
  • A 走端口 1、B 走端口 2 → A、B 之间不会冲突（不同线、不同端口）

为什么冲突只在「端口内部」？

  • 只有同一台主机在自己端口的发/收线对上同时乱发，才可能在该端口内部产生信号问题
  • 端口 1 与端口 2：线路完全独立 → 永远不会互相冲突
  • 冲突域 = 每个端口一个独立小盒子；不再是整网一个大域

结论：冲突从「整网/整条通道」→「单端口内部」；CSMA/CD 失效。

1.2 大白话：端口是「双向」的（输入/输出看当前这一帧）

核心：对！入端口完全可以变成出端口。 端口不固定叫输入或输出——这一帧从哪进、从哪出，才决定谁是入/出。

例子：端口 1、端口 2

时刻 发生的事 端口 1 端口 2
A → B A 发帧给 B 输入（帧从 1 进） 输出（从 2 发出）
B → A B 回复 A 输出（从 1 发出） 输入（帧从 2 进）

所以：端口 1 一会儿输入、一会儿输出；MAC 表记的是 MAC ↔ 端口，不管上一帧是进还是出，要发给该 MAC 时，这个口就是输出。

终极一句：端口双向；仅对当前这一帧，不向本帧的入端口泛洪/回发。

1.3 大白话：泛洪发给谁？（补牢）

考试铁律：这一帧从哪个口进来，这一帧绝不从该口再发出去；发给其余所有口。

  • 每一帧只有一个入端口（本帧的 ingress）
  • 不存在同一帧多个入端口

和「双向」不矛盾

  • 帧从端口 1 进 → 泛洪时不发回 1（刚进来再发回无意义，还可能环路）
  • 不代表端口 1 永远不能输出——下一帧完全可以从端口 1 输出给别的口

例子：交换机 端口 1、2、3、4

情况 A — 已知单播
  帧从 端口1 进，目的 MAC 在 端口3
  → 只转发到 端口3

情况 B — 未知单播 / 广播 / 组播（泛洪）
  帧从 端口1 进
  → 发给：端口2、端口3、端口4
  → 绝不发回 端口1
你的疑问 答案
入端口几个？ 每帧只有 1 个（从哪进就是哪）
泛洪发给谁？ 除入端口外所有其他口
会发回进来的口吗？ 绝对不会

三句背诵

  1. 全双工：每端口收发分离 → 冲突域 → 单端口；端口间不冲突。
  2. 端口双向：入/出看当前帧；MAC 表记 MAC↔端口。
  3. 泛洪：本帧从某口进 → 本帧不发回该口；下一帧可从该口出。

二、STP / RSTP 生成树（考试极简背诵版）

1）物理环路的 3 个危害（同一拓扑例子）

拓扑：S1 ↔ S2 用两根网线互联（冗余），形成物理环路；电脑 A 接在 S1，发广播帧（如 ARP）。

        [A]──S1══链路1══S2
              ╲        ╱
               ╲链路2╱
                ╲    ╱
                 S1─S2  （环路）

危害 1：帧无限泛洪（无限转圈）

  1. A 发广播 → 到 S1
  2. S1 经链路 1 → S2
  3. S2 经链路 2 → 又回 S1
  4. S1 再发 S2、S2 再发 S1…… → 同一帧在两台交换机之间永远转圈，无限复制、无限转发

危害 2：广播风暴（网络卡死）

  • 广播帧本来就要泛洪所有端口
  • 环路里每转一圈复制一遍 → 包越来越多 → 带宽占满、CPU 爆满，局域网瘫痪，大家都上不了网

危害 3：MAC 地址表震荡

  1. S1 先学到：A 的 MAC 在端口 1
  2. 环路转一圈，A 的帧又从另一根线进来
  3. S1 又记：A 在端口 2 → 一会儿端口 1、一会儿端口 2，表疯狂刷新 → 转发出错、交换机混乱

2）STP / RSTP 到底是什么？（全程用 S1–S2 例子）

STP：交换机之间的规则，自动把环路里其中一根网线逻辑关掉——线还插着、灯还亮，数据不许走。 RSTP：更快版 STP，干的事一样。

同一拓扑（与 §1 相同）：

  链路1：S1 端口1 ═════ S2 端口1
  链路2：S1 端口2 ═════ S2 端口2
        （物理上是环 → 会风暴/泛洪）

STP 目标：两根线只让一根通，另一根逻辑堵掉 → 环变树。

四步选举（通俗版 + 例子）

步 干什么 本例（假设 S1 赢）
① 根桥 Bridge ID 最小 = 优先级 + MAC，越小越优（默认优先级 32768） S1 = 根桥（老大），S2 是小弟
② 根端口 RP 非根交换机上，到根桥路径开销最小的口（回家最近的门） S2 端口 1 = RP（经链路 1 回 S1 最近）
③ 指定端口 DP 每条链路上，离根更近的一侧负责转发 链路 2：S1 端口 2 = DP（更靠近根）
④ 阻塞端口 BP 剩下的口 → 逻辑关掉，不转发 S2 端口 2 = BP（既不是 RP 也不是 DP）

什么叫「逻辑阻断」？

说明
物理 网线插着、链路 UP、灯亮
逻辑 交换机软件禁止该端口转发/学习帧

像门还在，但锁死不让进——线没拔，数据不许走。 本例：链路 1 工作；链路 2 物理在，S2 端口 2 被 STP 锁死 → 环路消失。 链路 1 断了，STP/RSTP 会打开备份口顶上（收敛时间 STP 慢、RSTP 快）。

STP 802.1D RSTP 802.1w

✅ 第二步记法：每台非根桥挑回家（去根桥）最近的那一个口。

③ 选指定端口 DP（每条链路一个）

指定端口 DP：这一段网线两端，离根桥更近（到根路径开销更小）的那一侧；负责这条链路上的转发。 根桥的所有端口天生都是 DP。

4 S2↔S3 S2→根=1 S3→根=2 S2（更近）

✅ 第三步记法：一根线拿出来，比两端谁离根近，近的那边 = DP。

④ 阻塞端口 BP

规则：既不是 RP，也不是 DP → 逻辑阻塞。

六句话复盘（四台版笔记）

  1. 桥 ID 最小 → S0 根桥。
  2. 非根桥各一个 RP：S1、S2 直连 S0；S3 开销相同时 选桥 ID 小的邻居（S1）。
  3. 每条链路 DP 在离根近的一侧；S0 各口皆 DP。
  4. S3 连 S2 = BP，逻辑阻断。
  5. 逻辑阻断 = 硬件正常、业务数据不许转发。
  6. RSTP = 同样选举，故障切换更快。 → RP 和 DP 会不会是同一个口？ 见 §4。

4）RP / DP / 转发 / 开销：角色分清（四台拓扑）

基础概念（用词统一）

词 大白话
端口转发 帧从入端口进，从另一端口出；能转发业务数据 = 工作口
路径开销 到根桥的「路程」；越小越优（本笔记每段链路 = 1）
阻塞 不转发业务帧（仍可收发 BPDU）

先记死一句 RP：站在单台非根交换机上 → 往根桥走（回中心），全机只有 1 个 DP：站在单条物理链路上 → 这条线往外传的负责人，每条线只有 1 个

非根桥上：1 个 RP + 可有多个 DP（连不同邻居的若干条线各有一个 DP 侧在「对端」或本机，见下表）。

小区类比：S0 = 小区大门（根桥）· RP = 每栋楼的主楼道（回家最近） · DP = 楼间通道的通行口（负责递话）

根桥 S0：为什么「所有口都是 DP」？

事实 说明
根桥到根的路径开销 = 0，全网最小
任意连着根的链路 比两端开销，根桥侧永远更小 → 该侧必为 DP
本例 S0 连 S1、连 S2 的两个口 全是 DP（正常转发），没有 RP 
  S0 [根] ──DP── S1   （S1 对端 = S1 的 RP）
       └──DP── S2   （S2 对端 = S2 的 RP）

根桥是全网数据集散中心：各口都负责和周边交换机双向互通。

易混两点

误区 正解
DP = 只出不进？ 否。DP 端口双向转发（能收能发），只是这条链路上 STP 认定的主导转发口。
只有根桥才有 DP？ 否。非根桥也可以有 DP。例：链路 S1↔S3 → S1 侧 = DP（非根 S1 上的口），S3 侧 = S3 的 RP。

S3 连 S1 的口 无 连 S2 的口

四条链路：逐段看 RP 与 DP（同一拓扑 §3）

链路 到根开销 DP（链路负责人） 对端常见角色

S2↔S3 S2=1，S3=2 S2 侧 S3 侧 = BP（既非 S3 的 RP，也非本链 DP）

关键（链路 3）：S3 连 S1 的口 —— 在 S3 上是 RP；在 S1↔S3 这条线上 DP 在 S1 侧。 👉 RP 和 DP 不是同一个物理口；是链路两端两个不同交换机上的两个口。

核心疑问：本机的 RP 会不会变成本机的 DP？

情况 结论
同一台交换机、同一个口 不会。RP = 向上回根；DP = 向下/向邻居主导转发，方向相反，互斥。例：S3 连 S1 的口只是 S3 的 RP，不会是 S3 的 DP。
一条链路的两端 一端多为 DP，对端多为 RP（S0↔S1、S1↔S3 等）。这是两个设备上的两个口，不是「一个口变身」。
根桥 S0 没有 RP；所有口都是 DP（向外转发）。

一句话：同一物理口，不能既是本机 RP 又是本机 DP；链路上一端 DP、一端常是 RP（或一端 BP）。

方向 路径

S0 回包 → S3 终端 S0 → S1 → 经 DP（S1 连 S3 一侧） → S3 → 终端
备份线 S2↔S3 S3 连 S2 口 BP，不转发业务；S1↔S3 断了 后该口可重新选举（常升为 新 RP），RSTP 更快

五句极简笔记（RP/DP 专抄）

  1. 根桥：到根开销 0 → 所有端口都是 DP（集散中心，双向转发）。
  2. 非根桥：1 个 RP（回根）+ 可有 DP（向邻居，如 S1 连 S3）+ 其余或 BP。
  3. DP：每条链路唯一、双向；到根开销更小的一侧当选。
  4. 同口不能既本机 RP 又本机 DP；链路上常 一端 DP、一端 RP（不同设备的两口）。
  5. BP：既非 RP 也非 DP → 逻辑阻断。

简答题标准答案（可直接抄）

  1. 环路危害（S1–S2 双链路）：无限转圈 · 广播风暴 · MAC 震荡。
  2. STP 是什么：自动逻辑堵一条冗余线，物理环变无环树。
  3. 四步（两台 S1 根）：根桥 → RP → DP → BP（例：S2:P2 阻塞）。
  4. 四步（四台 S0 根）：S0 根 · S1/S2 RP 指 S0 · S3 RP 指 S1（开销同比桥 ID）· 链路 4 S3 侧 BP。
  5. RP：非根桥唯一，到根开销最小，回中心；不能与本机 DP 同口。
  6. DP：每条链路唯一、双向转发；离根更近一侧当选；根桥全部 DP（开销 0）。
  7. 非根也有 DP：如 S1↔S3 上 S1 侧 DP、S3 侧 RP（两端不同口，不是变身）。
  8. DP ≠ 只出不进：能收能发，是链路主导口。
  9. 逻辑阻断：既非 RP 也非 DP；网线正常，业务不转发。
  10. STP 收敛 30–50 s；RSTP 1–2 s，选举规则同。
  11. BPDU：交换机间交换 STP/RSTP 拓扑信息。

三、交换机 L2 vs 路由器 L3（边界精准版）

1）交换机 = 二层（L2，数据链路层）

  • 只看 MAC 地址
  • 管同一局域网内部（同一广播域 / 常同一 VLAN 内）
  • 例：公司一个部门、一个 VLAN 里电脑互访

2）路由器 = 三层（L3，网络层）

  • 看 IP 地址（会改 TTL 等）
  • 管不同网段、不同 VLAN、内网与外网
  • 例：
  • 部门 A（VLAN 10）↔ 部门 B（VLAN 20）
  • 公司内网 ↔ 互联网
  • 大型园区、不同 AS 之间

1）先认角色（纠正 + 通俗定义）

名词 大白话
STA（站点） 连 Wi‑Fi 的终端：手机、电脑、平板
AP（接入点） 无线路由器的 Wi‑Fi 天线 / 无线部分；负责收发无线信号，STA 连的就是它

一句话对照

  • AP = 无线入口（Wi‑Fi 这边）
  • DS = 有线出口（接外网、接其他有线设备的那一侧）
  • 你说的「DS 连接 Wi‑Fi（AP）和后端线路」完全成立。

家里链路（场景拆分）

2）为什么 Wi‑Fi 最多 4 个 MAC，网线只有 2 个？

联动 DS：数据要在「无线 AP」和「有线 DS」之间来回走，就有两层收发对象——① 当下无线端直接收发（手机↔AP）② 最终在 DS/外网里的真正目标 → 所以需要多组 MAC（A1～A4）区分。

有线（网线直连）：A 直接发给 B，中间无转发 → 只需 源 MAC + 目的 MAC（2 个）。

无线（必经 AP）：存在两层关系：

  1. 当下这一跳：谁直接发、谁直接收（手机 ↔ AP）
  2. 最终目标：业务真正要去哪（外网服务器 / 另一台手机）

一层地址不够 → 802.11 用 A1～A4 最多 4 个 MAC。

字段 常记 含义（与流向无关，记死）
A1 RA 直接接收方 — 这帧当下第一个要交到谁手里（下一跳）
A2 TA 直接发送方 — 这帧当下是谁发出来的
A3 — 分场景：BSSID / 最终源或最终目的 MAC
A4 — 仅 WDS / AP 无线中继；普通手机上网不用

家用连路由：只用 A1、A2、A3；A4 仅 AP↔AP 桥接。

To DS = 1 数据要进入 / 去往 DS（To = 去往）

4）CSMA/CA、隐藏终端、RTS/CTS（核心机制）

为何不用有线的 CSMA/CD？

  • 有线：一根线同时只能一家发，能边发边听冲突 → CSMA/CD。
  • 无线：自己发射时会盖住周围信号，听不到别人是否在发 → 不能可靠「边发边检测」→ 改用 CSMA/CA（冲突避免）：先发前协商、提前避让，而不是撞了再停。

隐藏终端（hidden node）

  手机A ····· AP ····· 手机B
  A、B 互相听不见，但都能听见 AP
  • A 听信道空 → 发；B 也听信道空 → 发 → 两路信号在 AP 处撞车。
  • 互相看不见、却在 AP 撞车的站 = 隐藏终端。

RTS/CTS（专门缓解隐藏终端）

缩写 含义
RTS Request To Send —「我要占信道一段时间」
CTS Clear To Send — AP 回复「可以发，大家别抢」

流程：RTS → CTS → 数据 → ACK。周围站（含隐藏终端）都能听到 AP 的 CTS → 按 NAV 静默 → 避免在 AP 处撞车。

人话：RTS/CTS = 先打招呼占坑，再传大包。→ 时序详图：§五

5）从头到尾串一遍

  1. STA 上网必经 AP；AP 背后有线网 = DS，用 To DS / From DS 标流向。
  2. 因有「直接跳」与「最终目标」，帧里最多 4 个 MAC（家用常用 3 个）。
  3. 无线有隐藏终端，不能用 CSMA/CD。
  4. 用 CSMA/CA + 可选 RTS/CTS 提前避冲突。

6）极简背诵版

  1. AP = 无线入口；DS = AP 背后整套有线主干（不是一根线）。
  2. 同 WiFi 互传（简化）0/0；上传 1/0；下载 0/1；AP 桥接 1/1 + A4。
  3. 有线 2 MAC；Wi‑Fi 最多 4 MAC（无线一跳 + 最终目标）。
  4. 隐藏终端 → CSMA/CA + RTS/CTS 提前防冲突。

一、教材那句话怎么理解？

CSMA/CA（冲突避免） 无线电难以像网线那样可靠检测冲突 → 用退避与可选 RTS/CTS 缓解隐藏终端。

拆开 大白话
CSMA/CA 载波监听多路访问 / 冲突避免；Wi‑Fi（802.11） 用这个
CSMA/CD 冲突检测；有线以太网（Hub 半双工时代） 用这个
为何无线难检测冲突 发的时候听不到别人、信号强弱差大 → 不能可靠「边发边听」 → 只能 尽量避免（CA）
退避 信道空后随机等一会儿再发，减少同时抢信道
RTS/CTS 可选短帧预约，专门帮隐藏终端

二、CSMA/CA 怎么干活？和 CSMA/CD 有啥区别？

1）CSMA/CA 流程（通俗）

  1. 想发 → 先听无线信道：有没有人在说话？
  2. 忙 → 一直等到空闲。
  3. 空闲 → 不马上发，再抽一个随机时间（退避）再发（大家号码不同，少撞车）。
  4. 时间到、信道仍空 → 发数据。
  5. 对方回 ACK；没收到 ACK → 认为丢包/冲突 → 退避窗口加大，再随机重传。

2）一句话对比

CSMA/CD（有线） CSMA/CA（无线）
策略 边发边听，冲突了立刻停、发干扰、后退重传 不检测冲突，靠监听 + 随机退避 + ACK 避免冲突
典型场景 Hub 半双工共享网线 802.11 Wi‑Fi

3）无线为什么不能用 CSMA/CD？

原因 说明
收发共用天线 正在发的时候，收不到别人的信号（自己信号太强）→ 近端掩蔽
信号衰减大 远处冲突信号很弱，很难判断是不是碰撞
结论 做不到网线那种可靠冲突检测 → 只能改成 CA（避免）

→ 有线 Hub/半双工详解：3.2 · 交换机全双工后 CSMA/CD 消失：3.3 · 3.4

三、退避是什么？（二进制指数退避）

排队类比：信道空后，不是大家一起往前冲，而是每人随机抽一个号，按号排队；号小的先发。

  • 从 0～退避窗口 里随机选一个数，倒计时结束再检查信道。
  • 没收到 ACK（认为冲突/丢包）→ 窗口翻倍，再随机选 → 冲突越多，等得越久、越「谨慎」。
  • 教材常叫 二进制指数退避（与 study.md §3.5 中 DIFS/SIFS 配合使用）。

四、隐藏终端（hidden node）— 重点例子

场景：A、B（AP）、C

    A ·········  B(AP) ········· C
    └─能听见B─┘         └─能听见B─┘
    A 和 C 互相听不见（墙/距离）
步骤 发生了什么
1 A 要发给 B，听信道：没声音（因为听不到 C）
2 C 也要发给 B，听信道：也没声音（听不到 A）
3 A、C 同时往 B 发
4 在 B 处两路信号撞在一起、数据全乱；A、C 自己不知道

这就是 隐藏终端：互相听不见，却同时打向同一个 AP；只靠「先听 + 随机退避」解决不了（因为根本听不到对方）。

五、RTS/CTS 完整时序（A → AP，C 为隐藏终端）

整体顺序：RTS → CTS → 数据帧 → ACK

角色 说明
A 发送端
B(AP) 接入点 / 接收端
C 隐藏终端（能收到 B，收不到 A）
缩写 全称 作用
RTS Request To Send 「我要占用信道传数据，请批准」
CTS Clear To Send 「批准；这段时间所有人别占信道」

步骤 1：A 发 RTS

  • A 听信道空闲 → 发短帧 RTS 给 B。
  • 传播： mainly A ↔ B；C 收不到 RTS，此时 C 不知情。

步骤 2：B 回 CTS（广播静音）

  • B 收到 RTS → 立刻 CTS，帧里带信道占用时长（NAV）。
  • 传播：B 覆盖内所有站（含 A、C）。
  • C 听到 CTS → 立刻静默，倒计时结束前不抢信道。

步骤 3：A 发正式数据

  • A 收到 CTS → 开始传业务数据；C 全程静默，不干扰。

步骤 4：B 回 ACK

  • B 收齐数据 → ACK 告知 A 成功；信道占用结束，全网恢复 CSMA/CA 竞争。

时间轴简图（背诵版）

时间线 →————————————————————————————————————————→

A:     [发RTS]───────[收CTS]──────[发数据]──────[收ACK]
B(AP): [收RTS]───────[发CTS]──────[收数据]──────[发ACK]
C:     (听不到RTS)──────────[收到CTS]───(静默)───(静默结束)

NAV（虚拟载波监听）：CTS 等帧里带「还要占信道多久」；即使物理听不清发射方，也按 NAV 预约、暂不发送 → study.md §3.5.

关键考点

问 答
为何能解决隐藏终端？ A、C 互听不见，但都能听见 AP 的 CTS → C 被强制静默 → 不会与 A 同时在 B 处撞车。
何时开 RTS/CTS？ 可选；大包开（避冲突收益大）；小包关（多两次握手，反而慢）。
对比有线 CSMA/CD 有线：边发边听，冲突立刻停；无线：先预约（RTS/CTS）提前规避，靠 ACK 判断成败。

五句话复盘（专抄）

  1. CSMA/CA：无线用；先听 → 空闲 → 随机退避 → 发 → ACK；避免冲突，不 检测。
  2. 不用 CSMA/CD：发时听不到别人（近端掩蔽），没法边发边检测碰撞。
  3. 隐藏终端：A、C 互听不见，却同时向同一 AP 发 → 在 AP 处撞车；单靠退避不够。
  4. RTS/CTS：短帧预约；CTS 让能听见 AP 的站都静音（如 C）；大包常用。
  5. 顺序：RTS → CTS → Data → ACK；CTS 发出时 C 闭嘴。

六、802.11 帧：A1～A4 与上网场景（考试版）

走不走 DS、同 WiFi 互传：§零.3 · BSS/SSID：§七

对比 以太网 802.11
MAC 数 2 最多 4
原因 端到端直连 经 AP 转发，要分当下跳与最终源/目的

1）A1～A4 固定定义（与 To DS/From DS 无关）

地址 含义 记忆
A1（RA） 直接接收方 永远是当下要收包的那台
A2（TA） 直接发送方 永远是当下发包的那台
A3 BSSID 或 最终源/目的 MAC 看场景填
A4 原始发送设备 仅 WDS / AP↔AP 中继

2）手机 ↔ AP：三个常规场景（只用 3 个地址）

场景 To DS From DS
手机 → AP 上传 1 0
AP → 手机 下载 0 1
AP ↔ AP WDS 1 1（启用 A4）

场景 1：手机 → AP（上行）

  • A1 = AP 的 MAC（帧先给路由器）
  • A2 = 手机 MAC
  • A3 = 最终目的 MAC（外网服务器、局域网有线设备等）

人话：手机递给路由器，路由器再转最终目的地。

场景 2：AP → 手机（下行）

  • A1 = 手机 MAC
  • A2 = AP MAC
  • A3 = 原始来源 MAC（外网服务器、有线电脑等）

人话：外网/有线 → DS → AP → 无线 → 手机。

场景 3：AP ↔ AP 无线中继 / WDS（四个地址全用）

地址 填谁
A1 对端 AP
A2 本地 AP
A3 BSSID
A4 最原始发送设备的 MAC

普通终端上网遇不到；家用几乎不用 A4。

3）汇总背诵表

通信方向 To DS From DS 地址数 A1 A2 A3 A4
手机 → AP（上传） 1 0 3 AP 手机 最终目的 —
AP → 手机（下载） 0 1 3 手机 AP 原始源 —
AP ↔ AP（WDS） 1 1 4 对端 AP 本 AP BSSID 原始发送者

三句

  1. 手机与路由器通信，只用 A1/A2/A3；只有 AP 互当中继才用 A4。
  2. A1 = 当下收包方，A2 = 当下发包方，永远不变。
  3. A3 在上行常是最终目的，下行常是原始源；也常作 BSSID（见下）。

七、BSS、SSID、BSSID 与上线流程

1）SSID vs BSSID（最易混）

名称 本质 用途
SSID Wi‑Fi 名称（字符串），如 Home-WiFi、CMCC 给人看、搜索列表里显示

2）BSS 与 ESS

词 大白话

3）手机连 WiFi：扫描 → 认证 → 关联（三大步）

802.11 标准流程（大白话）：

│ 找SSID  │    │ 密码/WPA握手 │    │ AP 分配 AID     │    │ 加密   │
└─────────┘    └──────────────┘    └─────────────────┘    └────────┘

抓包提示：帧交换常见为 802.11 Auth → Assoc → EAPOL 四次握手；下文按「扫描 → 验密码 → 登记 AID」记忆，与口语一致。

① 扫描（Scan）

方式 怎么做 得到什么
被动扫描 听 AP 定时广播的 Beacon SSID、BSSID、信号强弱、信道
主动扫描 手机发 Probe Request，AP 回 Probe Response 同上，通常更快、更耗电

人话：手机「看到」周围有哪些 WiFi 名字（SSID），底层靠 BSSID（路由器 MAC） 区分同名 WiFi。

② 认证（Authentication）— 验密码

你选中一个 SSID，输入密码。认证 = 核对密码对不对。

步骤 说明
802.11 底层认证 家用多为 开放认证（Open System），帧层面几乎直接过
WPA2 / WPA3 四次握手：验密码、协商加密密钥
失败 密码错 → 卡在这一步，不会进入关联

→ 安全演进：§八

③ 关联（Association）— 注册，拿 AID

密码过了之后，手机发：我要正式加入你这个 BSS。

  • AP 回复 Association Response，分配 AID（Association ID）
  • AP 内存里一张表：AID ↔ 手机 MAC（在路由器/AP 里，不在光猫）
  • 作用：AP 知道「几号 AID 是哪台手机」，方便管理和转发

人话：关联 = 在 AP 里登记注册，发你一个站内编号 AID。

背一句：扫描 = 找 WiFi → 认证 = 验密码 → 关联 = 注册拿 AID

4）易混纠正：AID ≠ A1～A4

A1～A4 AID
是什么 802.11 帧头里的 MAC 地址字段位 AP 分配的关联编号（1、2、3…）
谁填 发每一帧时按场景写入（如 A1=接收方 MAC） 关联成功时 AP 分配
在哪 每个数据/管理帧头部 仅 AP 内部表，不给用户看
例子 A1=手机 MAC（下行时） AID=5 表示「第 5 号已关联设备」

纠正常见口误

  • ❌ 「连 WiFi 时 AP 分配 A1」
  • ✅ 「连 WiFi 时 AP 分配 AID，并在表里登记 AID ↔ 手机 MAC」
  • A1 是帧里写的当下接收方 MAC，不是分配出来的编号。

注册表在哪？ → AP/路由器 的内存（不是光猫）。

5）五句专抄（帧 + 管理）

  1. A1/A2 固定 = 当下收/发；AID = 关联编号，二者完全不同。
  2. SSID=名字，BSSID=AP 无线 MAC；BSS=一台 AP+下属 STA。
  3. 上线：扫描 → 认证（密码）→ 关联（AID 表）。
  4. AID 表在 AP：AID ↔ 手机 MAC。
  5. 业务加密靠 WPA2 四次握手（属认证阶段）→ §八。

十、简答题 / 背诵（可直接抄）

  1. CSMA/CA：无线用；先听 → 空闲 → 随机退避 → 发 → 等 ACK；不检测冲突，只避免冲突。
  2. 为何不用 CSMA/CD：发时听不到别人（近端掩蔽），无法可靠边发边检测碰撞。
  3. CSMA/CD vs CA：有线 CD=冲突后立刻停；无线 CA=退避+ACK 尽量避免。
  4. 隐藏终端：A、C 互听不见，却同时向同一 AP(B) 发 → 在 AP 处冲突。
  5. RTS/CTS：短帧预约；CTS 让所有能听见 AP 的站静音；缓解隐藏终端；大包常用。
  6. 退避：随机等待 + 冲突后指数增大窗口，分散发送时间。
  7. RTS→CTS→Data→ACK 顺序；CTS 期间 C 被静音。
  8. 安全：WEP 废弃 → WPA2(AES) → WPA3。
  9. 802.11 帧：最多 4 MAC；手机↔AP 常 3 个；WDS 用 A4。
  10. SSID / BSSID；上线：扫描 → 认证(密码/四次握手) → 关联(AID)；AID≠A1。

3.6

点到点协议（PPP）与 HDLC 对照

章级精读：../study.md#ch03-6 · §3.8 MTU · ch06 PPPoE

本节核心目标

分清 HDLC / PPP 定位与对比；掌握 LCP + 认证 + NCP 建立顺序；理解 PPP 未废止 与 PPPoE 为何仍主流。

一、PPP 没有被「废掉」

说法 事实
老式 电话线 + Modem 拨号 基本淘汰 ✓
PPP 协议本身 仍在大量使用 ✗ 没废止

仍在用的场景

  • 家庭/小区 PPPoE（网线/光猫拨号，底层仍是 PPP）
  • 4G/5G、物联网拨号、运营商专线、部分 VPN
  • 跨厂商路由器串口互联（兼容性优于 HDLC）

一句：PPP 告别了老式电话线，换了封装（如 PPPoE）继续当广域网点到点主力。

二、HDLC（高级数据链路控制）

1）是什么

ISO 制定的面向比特链路层协议；早期标准点到点/点到多点；常用于广域网串行链路（运营商专线、路由器串口）。

2）核心特点

点 说明
面向比特 按二进制比特处理，不是按字节拆
拓扑 全双工；标准版无丰富寻址（默认两端直连）
定界 标志位 01111110（0x7E）；比特填充（bit stuffing） 避免数据和标志冲突
版本 标准 HDLC：无多协议、无认证 · 思科私有 HDLC：可载多协议，思科串口默认

3）优缺点与现状

✅ ❌
结构简单、开销小、效率高 通用性差（厂商版常不互通）
链路层可带序号/确认/流控 无认证、无 IP 自动协商

现在：多见于同厂商路由器串行专线、电信 SDH/E1、帧中继；民用几乎见不到。

Control：I 帧（带序号/确认）· S 帧 · U 帧。

三、PPP（点到点协议）

1）定位

IETF · 面向字节 · 点到点 · 全双工；专门补强 HDLC：跨厂商兼容、认证、灵活协商、多网络层协议（IP、历史 IPX 等）。

2）三大组件（必考：LCP + 认证 + NCP）

组件 干什么 大白话

环回 (Loopback)

章级精读：../study.md#ch03-7 · Ch2 特殊地址：2.5 · 自顶向下：§6.6 环回

本节核心目标

分清 API（软件接口） 与 Loopback 环回口；掌握 127.0.0.0/8、::1、不可路由、Router-ID 与 远程管理。

零、软件接口（API）— 别和环回口混名

软件接口 = 程序/模块之间按约定交换数据、调用功能的交互点（代码层规范，不是网线）。

类型 例子
API 支付接口、微信登录、系统函数调用
Web 接口 REST（JSON/HTTP）、SOAP、gRPC
模块间 函数、类方法、进程间调用

作用：解耦、复用、标准化，让不同语言/系统能互调。

例：Python 调 C++ 库 → 通过 API 传参拿结果。

易混：这里的「接口」≠ 路由器上的 Loopback 逻辑接口（下文专讲）。

一、回环地址大白话（127.0.0.0/8 + 实操）

1）基础定义

回环地址（Loopback）：专门给本机自己和自己通信用的虚拟地址。

  • 不经过真实网卡，不走网线 / Wi‑Fi
  • 数据在操作系统内部直接折返
项 说明
网段 127.0.0.0 ~ 127.255.255.255（整个 127.0.0.0/8）
最常用 127.0.0.1（localhost）
127.0.0.0 该网段的网络号，不分配给主机做通信

2）核心特点

特点 大白话
与物理网卡无关 没插网线、没连 WiFi、禁用网卡，127.0.0.1 仍能通 — 系统虚拟「内部通道」
本机都能访问 任意网卡、任意程序访问 127.x.x.x，都指向本机自己
数据不出本机 发往 127 的包被 OS 拦截，不进局域网、不上外网

3）例子

例 1：本地 Web / 数据库

  • 服务监听 127.0.0.1:8080
  • 本机浏览器打开 http://127.0.0.1:8080 → ✅
  • 同 WiFi 另一台手机访问 127.0.0.1 → ❌（127 只认当前这台）

例 2：自检协议栈

ping 127.0.0.1
# Windows: ping 127.0.0.1 -n 4
结果 含义
能通 本机 TCP/IP 协议栈正常（与网线、路由器无关）
不通 系统网络组件异常，先查驱动/协议栈

4）127.0.0.0 vs 127.0.0.1

地址 角色
127.0.0.0 网段标识（网络号），代表整个 /8，不用于主机通信
127.0.0.1 网段内主机地址，日常测试、本地服务一律用它

5）路由表（对应「所有接口都能通」）

系统默认有一条规则：

目标 127.0.0.0/8 → 全部走本地回环接口（lo / Loopback）

所以不管有多少物理网口，访问 127 网段最终都导向本机内部。

6）极简总结

  1. 127.0.0.0/8 = 整段回环，本机自访。
  2. 日常用 127.0.0.1；127.0.0.0 只是网段名。
  3. 断网也能 ping 通；数据绝不离开本机。
  4. 本机所有程序、所有接口都能访问它。

二、127.0.0.1 / ::1 与「不可路由」（规范补充）

IPv4：127.0.0.0/8

项 内容
范围 127.0.0.0 – 127.255.255.255
常用 127.0.0.1；主机名 localhost 常解析到此
行为 协议栈内折返，不出物理网卡
路由 路由器不转发 → 不可路由

IPv6：::1/128

与 127.0.0.1 同级：IPv6 本机回环，同样不可路由。

为何不可路由？

RFC：环回仅本机使用，不能跨路由器转发 → 防误进公网。

应用 send → 目的 127.0.0.1 → 不进真实网卡 → 本机 recv

三、Loopback 环回接口（虚拟口）

点 大白话
是什么 纯软件虚拟接口，无物理网卡
状态 永远 Up
流量 不经过物理链路，协议栈内折返

主机 vs 路由器（易混）

PC / 服务器 路由器 / 三层交换机
127.0.0.1 系统自带环回地址 也可用
Loopback 口 常指上述逻辑 独立虚拟接口 Lo0，可配任意 IP（如 1.1.1.1/32）

四、Router-ID（路由协议「身份证号」）

项 说明
是什么 OSPF/BGP 等里唯一标识一台路由器的 32 位 ID

一句：Loopback = 路由器稳定虚拟身份证；Router-ID = 协议用这个身份证认设备。

五、远程管理（为何绑 Loopback）

项 说明
是什么 经 SSH / Telnet / Web 远程配设备，不用机房 Console
为何用 Loopback IP 稳定（物理口断管理不断）· 唯一好记 · 可 ACL 只放行环回 SSH
典型 Loopback0: 1.1.1.1/32 → 全网路由可达 → ssh 1.1.1.1

一句：Loopback 当管理 IP = 远程管理更不怕物理口断线。

MTU 和路径 MTU (PMTU)

章级精读：../study.md#ch03-8 · 以太网帧与 MTU：3.2 §二 · ICMP：ch08 · TCP MSS：ch13 · UDP 分片：ch10

本节核心目标

掌握 MTU、PMTU、PMTUD、DF 位与 TCP MSS 的关系；理解为何分片是性能杀手及 ICMP 黑洞。

一、MTU（最大传输单元）

MTU = 链路层一帧能装下的最大 IP 包大小（字节）（指 IP 层载荷上限，不是整帧含以太网头）。

1）典型值

链路 MTU（常见）
以太网 / Wi‑Fi 1500（最常见）
回环 lo 常 65535（逻辑，仅本机）→ 3.7
PPP / 隧道 常更小（如 1476、1400）→ 3.9

1500 里装什么（以太网举例）

┌──────── IP 包 ≤ 1500 ────────┐
│ IP 头(20) + TCP 头(20) + 数据  │  ← MTU 管这层
└────────────────────────────────┘
  不含：以太网帧头(14) + FCS(4)   ← 链路层额外开销

2）MTU 过大 → 分片或丢包

你发 IP 包 > 当前链路 MTU（如 2000 B），路由器出口只有 1500：

IP 首部 DF 位 路由器行为
DF = 0（允许分片） 切成多片分别转发 → IP 分片（性能差、易丢一片全废、易乱序）
DF = 1（禁止分片） 直接丢弃，并回 ICMP：Fragmentation Needed（Type 3 Code 4），带上该跳 MTU

→ DF 位详解：§二 · PMTUD：§四

结论：分片 = 性能杀手 → 尽量在发送端就控制包长（PMTUD + MSS）。

二、DF=1（Don't Fragment，不分片）

DF = Don't Fragment，在 IPv4 首部 3 位 Flags 里的 1 位（与 MF 等同域；与 标识 IPID 不同字段）：

→ 首部示意图：3.9 IPv4 首部图（标志行 = DF/MF，标识行 = IPID）

DF 含义
0 允许分片（默认）
1 禁止分片

好记：DF=1 ≈ 给包贴「易碎，勿拆」——路由器不能拆，只能丢或放行。

1）发送方设 DF=1，会发生什么？

步 谁 做什么
1 发送方 IP 头 DF 位置 1，发出大包（如按本地 MTU 1500）
2 中途路由器 包 > 出口 MTU（如 1400）且 DF=1 → 不能分片 → 丢弃
3 路由器 回 ICMP：需要分片但设置了 DF（Type 3, Code 4），附带该跳 MTU
4 发送方 收到 ICMP → 知道路径上有更小 MTU → 后续包缩到 ≤ 该 MTU 再发

超简流程（背图）

发送方: DF=1 + 大包(如1500)
           │
           ▼
    某跳 MTU 不够? ──否──► 一路畅通
           │
          是
           ▼
    路由器: 丢弃(不能拆) + ICMP Type3 Code4(带MTU)
           │
           ▼
    发送方: 收 ICMP → 调小发包长度 → 重发(仍 DF=1)
           │
           └──► 重复直到不丢 → 得到 PMTU

2）为什么要主动设 DF=1？（PMTUD）

目的：探测整条路径的 PMTU，避免中途 IP 分片。

  • 发 DF=1 + 尽量大的包 → 丢包 + ICMP → 下调长度 → 重试
  • 直到不再触发 ICMP → PMTU 稳定 → 以后都发 ≤ PMTU 的包，全程不分片

分片为何要避免：慢、易乱序、丢一片整包废、部分防火墙/NAT 对分片处理差。

→ 完整步骤：§四 PMTUD

3）DF=1 常见坑（ICMP 黑洞）

许多防火墙会 丢弃或过滤 ICMP「需要分片」：

现象 原因
TCP 能握手，数据传不动 SYN 小包过；数据大包被丢；ICMP 到不了发送方
发送方 一直按旧 MTU 发大包 → PMTU 永远调不下来

俗称 PMTU 黑洞 / ICMP 黑洞 → 排障见 §四。

4）和本节其他概念

概念 一句话
MTU 单链路最大 IP 包（以太网常 1500）
PMTU 整条路径上 MTU 的最小值
PMTUD 靠 DF=1 + ICMP 探出 PMTU
MSS PMTU − IP 头 − TCP 头（TCP 单次最大数据，常 1460）

三、路径 MTU（PMTU）

PMTU = 从源到目的整条路径上，所有链路 MTU 的最小值（瓶颈决定上限）。

例子

电脑 ──1500──► 路由器 ──1400──► VPN ──1500──► 服务器
                              ↑
                         PMTU = 1400（最窄的一段）

四、PMTUD（路径 MTU 发现）

目的：探测 PMTU，让发送方一开始就用不超过 PMTU 的包，避免中途被路由器分片。

IPv4 工作步骤

发包(DF=1, 按本地 MTU 1500)
    │
    ▼
路径上 MTU 够吗？ ──是──► 稳定 PMTU，正常传
    │
    否（丢包）
    ▼
路由器/设备：丢弃 + ICMP「需要分片」(带该跳 MTU)
    ▼
发送方收到 ICMP → 下调 PMTU → 重发(仍 DF=1)
    ▼
重复直到不再触发 ICMP → 得到路径 PMTU
步 说明
1 发送方设 DF=1，按本地 MTU（如 1500）发包
2 某跳更小 → 丢包 + ICMP Fragmentation Needed（含 MTU）
3 发送方 降低 PMTU，重试
4 直到包能通 → 稳定 PMTU

IPv6

  • 路由器绝不对 IPv6 做分片（除源端）→ 强制依赖 PMTUD
  • 过大包 → ICMPv6 Packet Too Big

关键坑：防火墙拦 ICMP

现象 原因
能建 TCP 连接，传不动数据 SYN 小包过；数据大包被丢；ICMP 被墙拦 → 发送方不知道要降 PMTU
俗称 PMTU 黑洞 / ICMP 黑洞

排障：临时允许 ICMP Type 3 Code 4 / v6 PTB；或手动调小接口 MTU / MSS。

五、和 TCP MSS 的关系

概念 含义
MTU 链路层一帧能承载的 IP 包最大长度
MSS TCP 单次能发的最大数据字节数 ≈ MTU − IP 头 − TCP 头

以太网常见

MSS = 1500 − 20(IP) − 20(TCP) = 1460 字节
  • PMTUD 得到 PMTU 后，TCP 会把 MSS 设为 PMTU − 40（IPv4 典型头长）→ 在端上分段，不走 IP 分片
  • TCP 分段（按 MSS）在主机做；IP 分片在路由器做 — 前者好，后者差

→ UDP 无 MSS，大包只能依赖 IP 分片或应用自己切片 → ch10

六、易混对照

易混 纠正
MTU vs MSS MTU 管 IP 包；MSS 管 TCP 纯数据
分片在哪做 IP 分片 = 路由器；TCP 分段 = 本机按 MSS
PMTU vs MTU MTU = 单跳；PMTU = 整条路径最小 MTU
DF=0 允许中途 IP 分片
DF=1 禁止分片；配合 PMTUD

七、一句话笔记（可直接背）

  • MTU：链路一帧最大 IP 载荷，以太网 1500。
  • DF=1：易碎勿拆；过大 → 路由器 丢 + ICMP Type3 Code4。
  • 大包 + DF=0：路由器 分片（性能差）。
  • PMTUD：发 DF=1 大包，靠 ICMP 探路 → PMTU，全程避免分片。
  • 风险：ICMP 被墙拦 → 黑洞（能握手、传不动数据）。
  • MSS = PMTU − 40（典型），TCP 在源头控大小。

八、自测

  1. 以太网 MTU 1500，TCP MSS 大约多少？
  2. DF=1 时路由器遇到超大包怎么办？
  3. PMTU 黑洞现象与原因？
  4. IPv6 为何更依赖 PMTUD？
参考答案
  1. 1460（1500−20−20，头长可变时按实际减）。
  2. 丢弃，发 ICMP Fragmentation Needed（若未被拦）。
  3. 大包被丢但 ICMP 不到发送方，PMTU 无法下调，连接「假活」。
  4. 中间设备不对 IPv6 分片，必须源端或 PMTUD 控制长度。

隧道基础

章级精读：../study.md#ch03-9 · MTU/PMTUD：3.8 · 网关隧道：HTTP ch08（应用层对照）

本节核心目标

分清 IPID ≠ IPIP；Type vs 协议号；IPIP/GRE 作 三层 VPN 隧道（+IPsec 才安全）；掌握封装、VXLAN 对照及 MTU/NAT。

隧道思想：在一种协议载荷里再套一层头，让内层包穿越当前网络不原生支持的路径；隧道端点解封后继续转发。

零、名词与层级（先掰清楚）

1）IPID ≠ IPIP（极易混）

名词 是什么 记法
IPID IPv4 首部里的 16 位标识字段，主要用于分片/重组 不是协议，别当隧道名
IPIP（IP-in-IP） 隧道协议，把 IP 包套进 IP 里传 协议号 = 4

口语里把「IP 套 IP」说成 IPIP；若写成 IPID，多半是把 Identification 字段和 IP-in-IP 协议搞混了。

2）IPIP、GRE 属于哪一层？

结论（背这句）

  • ✅ IPIP、GRE 都是「网络层 / IP 型（三层）隧道协议」
  • ❌ 不是链路层（二层 / 以太网帧）协议
协议 OSI 位置 IP 协议号 封装什么
IPIP 三层 4 仅 IPv4 包（外层 IP + 内层整包 IP）
GRE 三层 47 任意三层包（外层 IP + GRE 头 + 内层）

中间路由器按 外层 IP 路由（三层转发）；内层对它们透明，到隧道出口才剥壳。

3）为什么像「链路」？（逻辑链路 vs 本质）

隧道在运维上常配 tunnel0 之类接口，对上层像一根虚拟点对点专线：

视角 表现
对上层 像普通网卡：配 IP、跑路由、跑 OSPF
对下层 实际用 IP 包在公网/骨干里转发，不是二层 MAC 逐跳交换

一句：逻辑上是链路，本质是 IP（三层）封装。

4）和二层隧道对照（IPIP / GRE / VXLAN）

对比项 IPIP GRE VXLAN（对照用）
层级 三层（IP 型） 三层（IP 型） 二层 overlay（以太网帧 over UDP/IP）
协议号 / 端口 IP 4 IP 47 UDP 4789（常见）
封装对象 仅 IPv4 多种 L3（IPv4/IPv6/IPX…） 以太网帧（整帧）
组播 ❌ ✅ ✅（L2 广播域延伸）
典型场景 容器网、简单 IP 隧道 企业 VPN、IPv6 过渡、传路由协议 数据中心 / SDN 多租户 L2

→ IPIP / GRE 细节见 §一、§二

5）一句话总结

  • IPID：IP 头里的编号字段，不是协议。
  • IPIP、GRE：都是 三层 IP 型隧道，协议号 4 / 47，把三层包套进外层 IP 转发；不是二层链路协议。

零附、协议号在哪？二层 Type vs 三层 Protocol

网络里有两个容易混的「类型/协议」字段，位置不同、含义不同。

位置 字段 长度 回答的问题
以太网帧头 类型 / 长度（EtherType） 2 字节 帧载荷是 IPv4、IPv6 还是 ARP 等 → 3.2 EtherType
IP 首部 协议（Protocol） 1 字节 IP 载荷里是 TCP、UDP、ICMP 还是 IPIP/GRE 等

1）二层：以太网类型字段（不变样）

EtherType 含义
0x0800 帧里是 IPv4 包
0x86DD 帧里是 IPv6 包
0x0806 ARP（对照）

IPIP / GRE 不会改变 EtherType：隧道只是把 IP 包再套一层 IP；线上走的仍是 IPv4 帧，交换机眼里就是普通 IP，Type 仍是 0x0800，看不出里面是隧道。

2）三层：IP 首部协议号（区分 IPIP/GRE 的关键）

当 IP 载荷不是 TCP/UDP，而是 又一层网络层封装 时，靠 Protocol 字段 区分：

Protocol 上层载荷
1 ICMP
4 IPIP（内层又是一个 IP 包）
6 TCP
17 UDP
47 GRE（后跟 GRE 头 + 内层包）

Protocol 字段在哪？

  • 在 IPv4 首部里，从首部第 0 字节起偏移 9 的那 1 字节（图上「上层协议」，8 bit）
  • 不在以太网帧头；抓包时在 Internet Protocol Version 4 → Protocol 一列看

协议号写在外层 IP 头里。以太网 Type 仍是 0x0800，看不出里面是 IPIP/GRE。

一、IP-in-IP（IPIP）

类型：网络层（IP 型）三层隧道——最简单的 IP 封装；不是链路层协议。

典型形式

[ 外层 IP 头 · 协议号 = 4 ] + [ 内层 IP 头 ] + [ 内层数据 ]

ASCII 结构

┌──────────── 外层 IP（穿越当前网）────────────┐
│ 协议字段 = 4 (IPIP)                          │
│ 载荷 = 整个「旧 IP 包」                      │
│   ┌────── 内层 IP 头 ──────┐                 │
│   │  内层数据              │                 │
│   └────────────────────────┘                 │
└──────────────────────────────────────────────┘

说明（大白话）

点 内容
怎么封 把整个旧 IP 包（头+数据）当载荷，外面再加一个新 IP 头
干什么 跨异构网透传：IPv4 over IPv4、IPv6 over IPv4 等
场景 容器网络（Calico / Flannel 等）、简单 IP 隧道
限制 只装 IP（不能装 IPX 等）；无加密/认证；仅单播
开销 小（只多一层 IP 头）

一句：IP 包套 IP 包，轻量隧道，只传 IP。VPN 场景见 §三附。

二、GRE（Generic Routing Encapsulation）

类型：网络层（IP 型）三层隧道，通用多协议封装；不是链路层协议。

典型形式

[ 外层 IP 头 · 协议号 = 47 ] + [ GRE 头 ] + [ 内层协议包 ]

内层可以是 IPv4 / IPv6 / IPX / AppleTalk 等。

三层封装（书上叫法 ↔ 笔记）

图上英文 中文 在 GRE 里通常是什么
Delivery header（Transport protocol） 投递/外层头 外层 IP（隧道两端公网 IP，负责把整坨 GRE 包送到对端）
GRE header（Encapsulation protocol） 封装头 GRE 头（标明内层协议类型等）
Payload packet（Passenger protocol） 载荷/乘客包 被隧道携带的原始包（内层 IP、路由协议报文等）

好记：外层送货（Delivery）→ GRE 贴标签 → 里面坐乘客（Payload）。

ASCII 结构

┌──────── Delivery：外层 IP（协议=47）────────┐
│  ┌── GRE 头（Encapsulation）──┐             │
│  │  指明 Passenger 类型       │             │
│  └───────────────────────────┘             │
│     ┌── Payload：内层包 ──────┐            │
│     └─────────────────────────┘            │
└────────────────────────────────────────────┘

和 MTU / DF=1：封装后总长度 = Delivery + GRE + Payload。若 Payload 已按以太网 1500 发，再加头会 > 链路 MTU → 入口可能 丢包 + ICMP 3/4（DF=1 时）→ 内层有效 MTU 约 1500 − 24 ≈ 1476。→ 3.8 DF/PMTUD

GRE 首部字段（位图）

字段 要点
C =1 时带 Checksum 可选项
K =1 时带 Key 可选项（区分隧道内多路流）
Protocol Type（16 bit） 标明 乘客协议类型，作用类似以太网 EtherType（如 0x0800=内层 IPv4）
Version GRE 版本，常见 0

别混两个「类型」

位置 字段 例
外层 IP 头 Protocol = 47 告诉路由器：载荷是 GRE
GRE 头里 Protocol Type = 0x0800 告诉解封端：乘客是 IPv4

→ 外层 47 与帧头 0x0800 的分工见 §零附

说明（大白话）

点 内容
怎么封 外层 IP + GRE 头 + 内层任意网络层协议
干什么 跨网透传多种协议；常传 组播 / 路由协议（OSPF、BGP）
场景 企业 VPN、混合云、IPv6 过渡（IPv6 over IPv4）
安全 无加密（实战常 GRE + IPsec）
开销 比 IPIP 多 GRE 头，稍大，功能更强

一句：GRE 是「万能管道」，能装各种协议，VPN / 路由穿越常用。

对比项 IP-in-IP（IPIP） GRE
层级 三层 / IP 型 三层 / IP 型

三附、IPIP / GRE 做经典三层 VPN

IPIP、GRE 都是经典三层 VPN 隧道技术：在公网 IP 上建虚拟隧道，把私网报文套进公网 IP 包里转发。协议号见 §零附（IPIP=4，GRE=47）。

1）为什么适合做 VPN？

点 说明
原理 封装私网报文，在公网里当普通 IP 包传
中间路由器 只认外层公网 IP，看不到内层私网地址（基础隔离）
两端 隧道入口/出口设备解封后，按内层私网地址继续转发 
[私网A] ──隧道入口──► 外层公网IP ──公网──► 外层公网IP ──隧道出口──► [私网B]
                         ↑ 中间设备只路由这层
                         载荷 = 内层私网 IP 包

2）IPIP 做 VPN

项 内容
协议号 IPv4 Protocol = 4
结构 外层 IP + 内层 IP（纯双层 IP，无 GRE 等额外头）
优点 结构极简、开销小、转发快
限制 只封装 IPv4；不支持组播 → 难跑 OSPF/RIP 等动态路由
场景 简单点对点静态 VPN，只要单播业务、追求速度（也见容器 overlay）

3）GRE 做 VPN（企业更常用）

项 内容
协议号 IPv4 Protocol = 47
结构 外层 IP + GRE 头 + 内层报文（IPv4/IPv6/非 IP 均可）
优点 组播/广播可过隧道 → 能载 OSPF/BGP 等；跨站点组网灵活
开销 比 IPIP 多 GRE 头（约 4 B 起，常按 +24 B 估总封装）
场景 企业分支互联、跨地域内网打通、要同步路由或组播

4）共同短板（考点）

短板 说明
不加密、不防篡改 只是封装转发，载荷明文 → 纯 GRE/IPIP 常叫隧道，不算安全 VPN
工程标配 GRE/IPIP 负责组网（封装） + IPsec 负责加密/认证 → 企业安全 VPN 
内层私网包 → [GRE 或 IPIP 封装] → [可选 IPsec 加密] → 公网 IP 转发

5）VPN 向对比速记

协议 协议号 组播 / 动态路由 加密 常用 VPN 场景
IPIP 4 ❌ 无（配 IPsec） 简易点对点、纯单播
GRE 47 ✅ 无（配 IPsec） 分支互联、要跑路由协议

6）一句话

IPIP、GRE 靠三层 IP 封装在公网上拉虚拟链路，是传统 VPN 的基础隧道；GRE 功能更强用得更多；真要安全必须叠 IPsec（或 TLS 等）。

四、外层 / 内层包头（谁在干活）

外层包头（Outer） 内层包头（Inner）
作用 在当前传输网里路由穿越 解封后按原始目的继续转发
地址 隧道两端公网/底层 IP（如两机房公网） 原始包的源/目的（可私网、IPv6）
中间设备 只看外层，不管里面协议 到隧道出口才剥外层、看内层

一句：外层负责「过路」，内层负责「到终点」；中间只认外层，出口才看内层。

[ 外层：隧道入口公网 → 出口公网 ]  中间路由器只转发这层
      └─ 载荷 = [ 内层：真实源/目的 + 数据 ]  出口剥外层后按内层走

五、隧道与 MTU、NAT、PMTUD（高频）

1）有效 MTU 变小（核心）

基准 以太网常见 1500 B
隧道额外头 IPIP +约 20 B（外层 IPv4）· GRE +约 24 B（外层 IP+GRE）· GRE+IPsec +约 50～70 B
结果 隧道内有效 MTU ≈ 1500 − 开销
例 GRE：1500 − 24 = 1476 B（内层包不能超过，否则封装后超 MTU → 丢或分片）

→ 详解：3.8 MTU / PMTUD

2）NAT 与隧道

点 说明
NAT 改什么 通常改外层 IP/端口；内层私网 IP 不被 NAT 改
常见问题 GRE / IPsec 等无端口，不易穿越 NAT
常见解法 NAT-T（IPsec）、GRE over UDP、VXLAN（UDP 封装，NAT 可改端口）

3）PMTUD（路径 MTU 发现）

作用：动态发现路径上最小 MTU，避免大包被 silently 丢弃。

IPv4 原理（简）

  1. 发包 DF=1（禁止分片）
  2. 某段 MTU 更小 → 路由器丢包 + ICMP 3/4（需要分片但 DF=1）
  3. 发送方减小包长/MSS 后重发

隧道场景

现象 处理
隧道压低路径 MTU 内层有效载荷更小
ICMP 被防火墙拦 PMTUD 失效 → 大包卡死、小包正常
工程手段 隧道口 MTU 设小（1400/1476）；TCP MSS 钳位（adjust-mss）

一句：隧道加头 → MTU 变小；NAT 主要动外层；PMTUD 靠 ICMP，ICMP 被拦易丢大包。

六、易混

易混 正解
EtherType vs IP Protocol 0x0800 在帧头（载荷是 IPv4）；4/47 在 IP 头（载荷是 IPIP/GRE）
IPID vs IPIP IPID = 首部字段（分片用）；IPIP = 隧道协议 4
IPIP/GRE vs 链路层 二者都是 IP 型三层；不是以太网 二层协议
隧道口 vs 真链路 tunnel 接口像网线，底下仍是 IP 封装
隧道 vs NAT 隧道再封装；NAT 改头（多改外层）
隧道 vs 代理 隧道 IP 层；代理 应用层
IPIP/GRE vs VXLAN IPIP/GRE = L3 隧道；VXLAN = L2 over UDP
递归隧道 套娃加头，MTU 更易爆

典型攻击（L2 / 接入层常见）

1）MAC 泛洪（MAC Flooding / CAM 表耗尽）

项 说明

→ 交换基础：3.4 · 嗅探前提：Wireshark §2.1

2）STP 劫持（Root Bridge Hijack / 生成树欺骗）

① BPDU 是什么（大白话）

BPDU = Bridge Protocol Data Unit（桥协议数据单元） — 交换机之间用来商量 STP 的专用二层报文（不是 IP 包，不是用户上网流量）。

通俗点 说明
为啥要 STP 交换机连成环会 广播风暴；STP 自动「剪掉」多余链路，留一棵无环树
怎么商量 交换机互发 BPDU 打招呼（默认约 每 2 秒）
BPDU 里有什么 桥优先级、MAC、路径开销、端口角色 等
商量结果 全网比数据 → 选出 根桥（Bridge ID 最小 = 优先级 + MAC）→ 定 RP/DP/BP，阻塞冗余口

环上例子（三步）

  1. 几台交换机成环，不停互发 BPDU
  2. 比 优先级 + MAC，最小 的当 根桥（网络「中心」）
  3. 其余交换机根据 BPDU 关掉一条多余线，环路消失

👉 BPDU = 交换机的「聊天消息」，专门协商 STP 拓扑。→ 选举细节：3.4 STP

② 什么是「伪造 BPDU」

伪造 = 不是正规交换机自动生成的，而是攻击者用工具手写、冒充合法 BPDU 往外发。

真实 BPDU 伪造 BPDU
谁发的 正常交换机（协议栈自动） 攻击者电脑/设备（Yersinia、Scapy 等）
内容 反映本机真实 Bridge ID、开销 常把 优先级改成 0 等，故意全网最优
交换机反应 正常选举、收敛 分不清真假，只认报文里的数 → 以为来了更强根桥

劫持过程（四步）

  1. 正常：交换机互发真 BPDU → 合法根桥 → 网络稳定
  2. 接入：攻击者电脑插在某个接入口
  3. 造假：手工构造假 BPDU，优先级 = 0（或更小 Bridge ID）发出去
  4. 收敛：邻居交换机认为「新根桥来了」→ 全网 STP 重算 → 流量尽量经攻击者 → 嗅探 / 篡改

③ 串联（STP 劫持在考什么）

步 概念
1 BPDU：交换机协商 STP 的沟通报文
2 伪造 BPDU：人为制作的假聊天消息
3 STP 劫持：用假 BPDU 抢根桥 → 流量绕到攻击者

本质（别记错）

  • ❌ 不是伪装成交换机、也不是伪造普通业务帧
  • ✅ 是伪造 BPDU（二层 STP 控制报文）

一句话（考试/面试）

STP 劫持 = 发优先级 0 的假 BPDU → 骗全网认我为根桥 → 流量全过我这里。

图意：攻击者从接入口打入 Fake BPDU（二层控制帧，非业务 IP 包）→ 交换机按 STP 重选根 → 拓扑以攻击者为中心收敛。

正常 vs 被劫持（流量怎么走）

正常（合法根桥 S0 在核心）

        [S0 根桥·核心]
       /    |    \
    S1      S2      S3
   /  \    /  \    ...
  PC  PC  PC  PC

业务流：各交换机按 STP 算好的 RP/DP 转发，一般不经过边缘随机 PC。

被劫持（攻击者 Att 抢根）

        [Att 假根桥]  ← 伪造 BPDU，Bridge ID 最优
       /    |    \
    S1      S2      S3
   /  \    /  \
  PC  PC  PC  PC

业务流：为「回根/经根」路径被拉向 Att → Att 可嗅探/篡改再转发。

④ 配套防御（对着原理记）

配置 大白话 防什么
BPDU Guard 接 PC 的口一旦收到任何 BPDU（真假不论）→ 端口 shutdown 从源头拦：私接交换机 + 伪造 BPDU 进网
Root Guard 该口不能当根端口/不能让外侧当根 就算收到假 BPDU，外侧也抢不走根桥

→ STP 背景：3.4 · BPDU 名词：§①

4）ARP 基础 → 伪造 / 欺骗（L2/L3 交界）

先搞懂 ARP 干什么、表在哪，再讲攻击。

① ARP 是干嘛的？

通信要两套地址配合：

地址 层级 作用
IP 三层（逻辑） 找哪台主机
MAC 二层（物理） 找哪块网卡

ARP（Address Resolution Protocol，地址解析协议）：已知对方 IP，查出对应 MAC。

例子（本机 192.168.1.10 要访问网关 192.168.1.1）

  1. 发 ARP 广播：「谁是 192.168.1.1？请告诉 MAC！」
  2. 网关 单播 ARP 应答：「我是 192.168.1.1，MAC 是 aa-bb-cc-dd-ee-ff」
  3. 双方写入 ARP 表，以后同网段通信直接用 MAC 转发，不必每次都广播

→ 报文格式与流程：ch04 §4.2

② ARP 表（ARP 缓存）存在哪里？

ARP 表 = IP ↔ MAC 对应表

项 说明
存在哪 每台设备的内存里（本机内核/协议栈；路由器、三层交换机也有 ARP/邻居缓存）
谁有 电脑、手机、路由器等；普通二层交换机一般不帮终端维护 ARP 表（只按 MAC 转发）
特点 动态、有老化时间（超时删除）；IP/MAC 变了会更新

本机查看

Windows:  arp -a
Linux:    ip neigh
IP 地址 MAC 地址
192.168.1.1 aa-bb-cc-dd-ee-ff
192.168.1.20 11-22-33-44-55-66

→ 缓存与超时：4.3 · 4.6

③ 什么是 ARP 伪造 / ARP 欺骗？

原理：ARP 没有身份验证；设备收到 ARP 应答（有时还有无故应答）往往直接信、立刻改表，不核实发送者是不是真主人。

攻击者：主动发伪造 ARP → 篡改受害者内存里的 IP→MAC 映射。

中间人（MITM）四步

正常：  PC(192.168.1.10) ──► 网关(192.168.1.1 真MAC) ──► 外网

1. 攻击者告诉 PC：「192.168.1.1 的 MAC 是我」→ PC 的 ARP 表里网关 IP 绑到攻击者 MAC
2. 攻击者告诉网关：「192.168.1.10 的 MAC 是我」→ 网关回程也指向攻击者
3. PC 发出的包 → 二层先送到攻击者 → 攻击者再转给真网关
4. 攻击者可嗅探、篡改（上层无 TLS 时危害大）

两种常见方向

类型 篡改谁 效果
欺骗终端 主机的 ARP 表 主机以为网关/邻居 MAC 是攻击者
欺骗网关 路由器 ARP 表 回程流量也经攻击者

③附、ARP 攻击只能在同一局域网（二层广播域）

结论：对。 ARP 欺骗/伪造只能在本局域网（同一广播域）内发起；外网隔着路由器够不着你的 ARP 表。

原因 说明
ARP 靠广播 请求常是 二层广播；广播帧不会跨路由器转发
路由器隔离 路由器把网络划成多个广播域；外网发来的 ARP 广播进不了你家内网
二层范围 ARP 在局域网内传递；跨网段主机收不到你的 ARP，也改不了你本机表项

例子

场景
✅ 能攻击 你、同事、蹭 Wi‑Fi 的人 — 同一台交换机/同一路由器 LAN 口（同一网段/广播域）
❌ 不能 外网网友、异地电脑 — 中间隔着路由器/NAT/公网，ARP 到不了

补充

  1. 同一 Wi‑Fi 通常仍是同一广播域 → 可以 ARP 欺骗（除非做了无线客户端隔离）。
  2. 对方若经 VPN / 隧道 逻辑接入你的内网，相当于进了同一 L2/L3 可达范围 → 也可能发起 ARP 攻击（视隧道类型而定）。

一句话

ARP 靠广播传播，路由器拦广播 → 攻击只局限在局域网内部。

→ 正常转发为何也仅限 LAN：ch04 §广播域边界

④ 和 STP 劫持对比（一起背）

STP 劫持 ARP 伪造
伪造什么 BPDU（二层 STP 控制） ARP 报文
改掉什么 根桥 / 生成树拓扑 ARP 表（IP–MAC）
结果 流量绕路经攻击者 流量绕路经攻击者
共性 伪造协议报文 → 改变转发路径 同左

⑤ 极简总结

  1. ARP：IP 查 MAC，衔接三层与二层。
  2. ARP 表：IP+MAC，在设备内存，会老化。
  3. ARP 伪造：发假 ARP 改别人表 → MITM / 劫持。
  4. 范围：仅同一广播域/LAN；路由器隔广播，外网不能直接 ARP 你。

防护原则（链路层加固）

1）物理与逻辑隔离

手段 作用
端口安全（Port-Security） 限制单端口最大 MAC 数、绑定固定 MAC
802.1X 接入身份认证，未认证不能上网
VLAN 划分 缩小广播域，隔离业务/办公/管理网
私有 VLAN / 端口隔离 同 VLAN 内主机互不可见，防横向渗透

2）不信任接入交换机 / 接入端口

配置（示例） 作用
接入口禁用 DTP（switchport nonegotiate） 防 Trunk 伪造、VLAN 跳跃
接入口 BPDU Guard 收到 BPDU → 端口 shutdown，防私接交换机 / STP 劫持
Root Guard 防非法设备成为根桥
核心服务器/网关 静态 CAM 绑定 防动态学习被泛洪/欺骗扰乱

3）风暴抑制

限制广播/组播/单播风暴，防带宽与 CPU 被打满。

与端到端安全（重要结论）

  • 链路层加固 ≠ 端到端安全。
  • L2 防护（端口安全、STP 防护、VLAN）只能防局域网内底层劫持/嗅探。
  • 必须配合 TLS/SSL、IPsec、VPN、强认证 等高层安全，才能防跨网窃取与篡改。

# 考点 MAC 泛洪 STP 劫持 ARP 欺骗
1 攻击对象 交换机 CAM 表 STP 拓扑 / BPDU 主机 ARP 缓存
2 主要手段 海量不同源 MAC 帧 伪造 BPDU（非伪装交换机）、抢根 伪造 ARP Reply

一层话区分

  • MAC 泛洪：搞垮交换机学习表，让别人流量被泛洪出来。
  • STP 劫持：伪造 BPDU 抢根桥，让路径绕到攻击者（不是伪装交换机）。
  • ARP 欺骗：搞垮主机地址解析，让帧送到攻击者 MAC。

一句话总结（背记）

链路层攻击利用交换机/无线/ARP 的默认信任，通过 MAC 泛洪、STP 劫持、无线嗅探、ARP 欺骗 实现嗅探与劫持；防护靠 端口安全、802.1X、VLAN、BPDU/Root Guard、私有 VLAN，但 L2 加固不能替代 TLS/IPsec 等端到端加密。
