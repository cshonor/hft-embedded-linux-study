6.1

引言

章级精读：study.md#ch06-1 · 地址：ch02 · DHCP 协议：6.2 · SLAAC：6.3

本节核心目标

理解为什么需要动态、自动化的主机网络参数配置，以及 IPv4/IPv6 分别用哪些机制实现「即插即用」。

DHCP 是什么（通俗速记）

DHCP（Dynamic Host Configuration Protocol，动态主机配置协议）核心：自动给内网设备分配 IP 地址。

主要功能

# 功能 说明
1 自动分配 IP 手机、电脑等开机后，不用手动填 IP、子网掩码、网关、DNS — DHCP 服务器自动下发
2 地址租期管理 IP 不是永久占用；到期续租，避免多台设备 IP 冲突
3 统一下发网络参数 顺带配置 网关、DNS 服务器 — 设备拿到参数即可上网

常见场景

家里/公司的 路由器 默认开启 DHCP，所有连 Wi‑Fi、插网线 的设备都靠它分配地址。

一句总结：帮你自动配上网地址，省去手动设置网络的麻烦。

→ 协议细节：6.2 DHCP · 失败回退 APIPA：6.3 · 与桥接/NAT 关系：6.8 虚拟机实战

一、为什么不能一直手动配？

手动填写 IP、子网掩码、默认网关、DNS 的问题：

问题 说明
规模化 易出错、难维护、管理成本高
移动化 手机/笔记本频繁换网，无法静态写死
用户能力 企业/家庭设备多，用户无专业知识

一句话：规模化 + 移动化 → 手动配置不可扩展。

二、目标：即插即用（Plug-and-Play）

设备接入网线/Wi‑Fi 后，自动获得：

  • 地址（IPv4 / IPv6）
  • 网关、DNS、NTP 等

无需人工干预 — 开机就能上网。

三、协议栈自举顺序（关键逻辑）

网络启动是分层递进的：

flowchart LR
  L2[L2 链路接通] --> L3[L3 参数自动获取]
  L3 --> DNS[DNS 解析]
  DNS --> APP[应用层业务]
  1. L2 链路接通（以太网 / Wi‑Fi 连接建立）
  2. L3 参数自动获取：DHCP（IPv4） / SLAAC + DHCPv6（IPv6） → 地址、网关、DNS
  3. DNS → 应用：解析域名，开始上网/业务

没有 L3 自动配置，上层 TCP/UDP/应用都是「无源之水」。

→ 前置：ch05 IP · ch04 ARP

四、本章两条主线

1）DHCP（IPv4 主流，有状态）

项 说明
机制 服务器集中管理地址池，分配 IP + 掩码 + 网关 + DNS + 租期 等
特点 服务器记录绑定状态（有状态）
场景 企业内网、家庭路由器、运营商宽带、IPv4 全网标准

→ 详：6.2 DHCP 协议

2）SLAAC / APIPA（无服务器自动配置）

机制 说明 场景
APIPA（IPv4 备用） DHCP 失败时自动生成 169.254.0.0/16 链路本地地址；仅内网互通，不能跨路由 Windows 等「自动专用 IP」
SLAAC（IPv6 原生，无状态） 路由器发 RA（路由通告） 给前缀；主机用「前缀 + 接口 ID」拼地址；无需 DHCP 服务器，路由器不记录谁用了哪个地址 IPv6 零配置、智能家居、物联网

→ 详：6.3 SLAAC

五、DHCP vs SLAAC（一句话）

DHCP（有状态） SLAAC（无状态）
谁给地址 服务器分配 + 全套参数 设备自己生成；路由器只给前缀
适合 集中管理、需审计的网络 零配置、高扩展
典型 IPv4 主流 IPv6 标配

拓展（预留）

  • DHCPv6 与 SLAAC 组合（RA 标志位 M/O）
  • 与 ch02 特殊地址 中 169.254/16 对照

抓包/实操记录

（待填：ipconfig /all 或 nmcli 看 DHCP 租约与 DNS）

疑问与总结

L2 通了还不够 — 必须自动拿到 L3 参数，TCP/应用才有路可走。

6.2

动态主机配置协议 (DHCP)

章级精读：study.md#ch06-2 · DORA：study.md#ch06-2-dora · 租期：study.md#ch06-2-lease · SLAAC 对照：6.3 · 免费 ARP/ACD：ch04 §4.8

本节核心目标

掌握 BOOTP 演进、地址池/租期、DORA 交互流程、DHCPv6 与 DUID 标识。

一、历史与传输载体

1. 协议演进

BOOTP DHCP
关系 引导程序协议（RFC 951） BOOTP 的增强扩展
报文 二者格式向下兼容 在 BOOTP 基础上增加选项与租期
分配 静态绑定 IP（表项预配置） 动态从地址池分配 + 租期管理
回收 无租期，地址长期占用 到期释放 → 地址循环复用

一句：BOOTP =「发一张固定票」；DHCP =「租一张可续期的票」。

→ 演进链：6.1 引言 · RARP/BOOTP/DHCP

2. 传输层与端口（IPv4）

基于 UDP（应用层协议，却在网络层初始化阶段起决定性作用）：

角色 端口
DHCP 客户端 68
DHCP 服务器 67

3. 收发方式

阶段 方式 原因
初期（Discover/Request 等） 广播 客户端尚无 IP（0.0.0.0），无法单播
续租 Renew（T1） 通常 单播 原服务器 已有 IP，已知服务器地址
重绑定 Rebind（T2） 广播 原服务器无响应，向任意可用服务器求助

→ 跨网段：DHCP Relay 把广播转为单播，giaddr 标识中继 → study §6.2.5 中继

二、地址池与租期 (Lease)

1. 地址池

DHCP 服务器预先维护一段空闲 IP 范围（地址池 / scope）；客户端申请时，服务器从池中选取未占用地址分配。

概念 说明
地址池 可分配网段，如 192.168.1.100–200
保留/静态绑定 按 MAC/client-id 固定映射（仍走 DHCP 流程，但总是同一 IP）

2. 租期机制（核心三时间点）

分配的 IP 并非永久；附带有效租期 T。

定时器 时机 行为 俗称
T1 ≈ 0.5T（50%） 客户端向原分配 DHCP 服务器单播续租（Renew） 续租
T2 ≈ 0.875T（87.5%） T1 失败 → 向全网任意 DHCP 服务器广播续租（Rebind） 重绑定
到期 T 客户端停用当前 IP，释放；地址回归地址池 — 
0 ─────── T1(50%) ─────── T2(87.5%) ─────── T(100%)
         续租原服务器      广播找任意服务器      释放，重新 DORA

续租失败后果：T1、T2 均失败 → 租期到期 → 停用 IP → 重新发起 DORA 申请新地址。

通俗：IP 像短租公寓 — 过半先找原房东续；房东不在就满世界问；到期搬出，房间给别人。

三、IPv4 经典 DORA 四步交互

客户端从零获取 IP、掩码、网关、DNS、租期 等参数的完整流程；初始阶段全程广播。

步骤 报文 行为与含义
1 DISCOVER（发现） 客户端广播：「谁是 DHCP 服务器？」（源 IP 0.0.0.0）
2 OFFER（提供） 服务器从地址池预留 IP，广播/单播回复地址及配置参数（可能多台同时 Offer）
3 REQUEST（请求） 客户端选定一台，广播 Request：「我要这个 IP，其他服务器请释放」
4 ACK（确认） 被选服务器最终确认，下发完整参数（IP、掩码、网关、DNS、租期 T 等）

补充：服务器拒绝分配 → NAK（Not Acknowledged）。

二层 / 三层（抓包对照）

步骤 L3 IP（典型） L2 目的 MAC
Discover 0.0.0.0 → 255.255.255.255 广播 FF:FF:…
Offer Server → 255.255.255.255 或单播 广播或客户端 MAC
Request 0.0.0.0 → 255.255.255.255 广播
ACK Server → 广播或单播 客户端 MAC

Request 为何也广播？ 让网内所有曾 Offer 的服务器知道客户端选了谁，释放未中标地址，避免池被占死。

→ 消息格式（BOOTP 兼容）：study §6.2.2 · 常用 Option：study §6.2.3

四、DHCPv6 核心要点

IPv6 地址配置方式与 IPv4 差异大；DHCPv6 定位需与 SLAAC 对照。

1. 地址分配方式区分

方式 机制 是否需要 DHCPv6
SLAAC（无状态自动配置） 路由器 RA 报文 → 主机自动生成地址 否（仅地址）→ 6.3
DHCPv6 有状态 服务器统一分配 IPv6 地址 + DNS 等 是
DHCPv6 无状态 不分配地址（SLAAC 已有），只下发 DNS/域名 等选项 部分（Information-Request）

2. 客户端标识 DUID

IPv4 DHCP DHCPv6
客户端标识 硬件地址 chaddr（网卡 MAC） DUID（DHCP Unique Identifier）
特点 换网卡可能变 永久稳定，不受网卡/地址变化影响

3. 端口与交互名称

项 值
客户端端口 546
服务器端口 547
四步（类比 DORA） Solicit → Advertise → Request → Reply
寻址 少用广播；常用组播 ff02::1:2（All_DHCP_Relay_Agents_and_Servers）

五、实验 Lab

Wireshark 过滤器：bootp  或  dhcp
  1. 断开 / 重新连接网络（或 ipconfig /release + /renew、dhclient -r + 重启）
  2. 观察完整 DORA 四步：Discover → Offer → Request → Ack
  3. 可选：查看 Option 1/3/6/15（掩码、网关、DNS、域名）与 Lease Time
过滤器 用途
bootp BOOTP/DHCP 共用载荷
dhcp.option.dhcp == 1 Discover
dhcp.option.dhcp == 2 Offer

六、易混考点

易混 正确
DHCP 是网络层协议 UDP 应用层，但在获取 IP 之前运行
初期为何必须广播 客户端无 IP（0.0.0.0），无法单播寻址
BOOTP vs DHCP BOOTP 静态、无租期；DHCP 动态池 + 租期 + 选项
T1 vs T2 T1 → 原服务器单播；T2 → 任意服务器广播
续租失败 到期释放 IP → 重新 DORA
v6 只靠 DHCPv6 常见 SLAAC + RA；DHCPv6 可有状态或仅下发 DNS
v4 标识 vs v6 chaddr (MAC) vs DUID
# 考点速记
1 UDP 67/68；DORA；T1≈50% / T2≈87.5%
2 Request 广播 = 通知未选中服务器释放 Offer
3 DHCPv6：546/547；DUID；Solicit/Advertise/Request/Reply
4 SLAAC 无状态 vs DHCPv6 有状态 → 6.3

拓展

分配后 ARP/Probe 冲突检测 → ch04 免费 ARP/ACD · study §Probe

疑问与总结

背：BOOTP→DHCP；UDP 67/68；DORA 广播起步；T1/T2/到期；v6 看 SLAAC vs DHCPv6 + DUID。

6.3

无状态地址自动配置 (SLAAC)

章级精读：study.md#ch06-3 · DHCPv6 对照：6.2 §IPv6 · ND/RA：ch08 §8.5 · 免费 ARP/ACD：ch04 §4.8

本节核心目标

掌握 APIPA（IPv4 链路本地） 与 IPv6 SLAAC — 无 DHCP 服务器场景下的零配置配址，以及 M/O 标志 与 DHCPv6 的分工。

一、IPv4 APIPA（链路本地地址）

项 说明
触发条件 DHCP 服务器不可达（超时/无响应）
地址段 自动分配 169.254.0.0/16（RFC 3927）
冲突检测 依靠 免费 ARP / ACD（Address Conflict Detection）校验地址唯一性
范围 仅本地链路有效，不能跨路由 
DHCP 失败 → 随机选 169.254.x.x → 免费 ARP 探测冲突 → 可用则启用

→ 地址分类：ch02 §2.5 · ACD 细节：ch04 §4.8

二、IPv6 SLAAC 流程（无状态自动配址）

SLAAC（Stateless Address Autoconfiguration）：主机根据路由器通告自行合成全球单播地址，无需中心化地址分配服务器记录租约。

流程

步骤 报文 说明
1 RS（Router Solicitation，路由器请求） 主机主动发报文，询问网络前缀（也可被动等 RA）
2 RA（Router Advertisement，路由器通告） 路由器回复，下发网段前缀、M/O 控制标志位、跳数等
3 地址合成 RA 前缀 + 接口标识 IID → 完整 IPv6 全球单播地址 
主机 --[ RS 组播 ]--> 路由器
主机 <--[ RA 带 Prefix + M/O ]-- 路由器
地址 = Prefix + IID（默认 EUI-64）

IID 生成（默认 EUI-64）

项 说明
规则 48 bit MAC 中间插入 0xFFFE，翻转 U/L 位（第 7 位）
隐私扩展 RFC 4941：随机 IID、定期更换，防 MAC 追踪 → study §6.3.2

→ ICMPv6 NDP：ch08 §8.5

三、M/O 标志位（核心区分）

RA 报文中 ICMPv6 Router Advertisement 的标志位决定是否与 DHCPv6 配合：

标志 名称 置 1 含义
M Managed 启用 有状态 DHCPv6 — 地址由 DHCPv6 分配（非 SLAAC）
O OtherConfig 仅向 DHCPv6 获取 DNS、域名 等附加参数；地址仍由 SLAAC 生成
M O 行为
0 0 纯 SLAAC — 仅 RA 前缀拼地址
0 1 SLAAC 地址 + DHCPv6 无状态（Information-Request 要 DNS 等）
1 * 有状态 DHCPv6 分配地址（SLAAC 不用于地址）

结论：SLAAC 不强制搭配 DHCPv6 — 是否使用、用于地址还是仅 DNS，由 RA 的 M/O 标志决定。

→ DHCPv6 模式对照：6.2 §IPv6

四、易混考点

# 要点
1 APIPA 是 IPv4 零配置方案；SLAAC 是 IPv6 主流零配置方案
2 SLAAC 靠 RA 完成地址生成；是否用 DHCPv6 取决于 M/O 标志
3 IID 默认采用 EUI-64 规则生成（可换隐私扩展随机 IID）
易错 正确
SLAAC 一定配 DHCPv6 看 M/O；可纯 SLAAC（M=0,O=0）
O=1 时地址也靠 DHCPv6 O=1 仅要 DNS 等；地址仍 SLAAC
APIPA 可跨网段路由 169.254/16 仅链路本地
M 与 O 同义 M=有状态地址；O=仅其他配置

考点速记

  1. APIPA：DHCP 不可达 → 169.254/16 + 免费 ARP/ACD
  2. SLAAC：RS → RA → 前缀+IID；IID 默认 EUI-64
  3. M/O：M=有状态 DHCPv6 地址；O=SLAAC 地址 + DHCPv6 要 DNS
  4. SLAAC ≠ 必须 DHCPv6

疑问与总结

背：APIPA 169.254+ACD；SLAAC=RS/RA+前缀拼IID；M 管地址、O 管 DNS；二者都是零配置，族别不同。

6.4

DHCP 和 DNS 交互

章级精读：study.md#ch06-4 · DHCP 基础：6.2 · DNS 动态更新：ch11 §11.5 · 公共 DDNS：ch11 §11.7

本节核心目标

理解 DDNS（动态 DNS 更新） — 联动 DHCP 与 DNS，在 IP 变动时维持域名 ↔ IP 映射可用。

一、业务痛点

现象 后果
DHCP 动态分配地址 租约续期、重连、漫游 → 客户端 IP 频繁变动
DNS A/AAAA 仍为旧 IP 域名与 IP 映射失效
用户按主机名访问 解析到错误地址 → 无法连通 
DHCP 换 IP → DNS 记录未更新 → ping host.name 仍指向旧地址 → 访问失败

核心矛盾：DHCP 让 IP 变；业务希望主机名 不变且始终可达。

二、DDNS（动态 DNS 更新）

1. 作用

IP 变更时，自动同步更新 DNS 的 A（IPv4）/ AAAA（IPv6） 记录，维持域名与当前 IP 的对应关系。

2. 执行主体

发起方 场景
DHCP 服务器 分配/续租/释放地址后，代客户端向 DNS 提交更新（企业常见）
客户端 主机自行向 DNS 发送动态更新（RFC 2136 等）

二者均可；具体取决于网络策略与 DHCP/DNS 集成方式。

3. 安全要求

项 说明
风险 无认证时，攻击者可恶意篡改 A/AAAA → 劫持、投毒
缓解 必须配置身份认证，如 TSIG（Transaction SIGnature）、GSS-TSIG（AD 域常见）
原则 仅授权主体可更新指定 FQDN 记录

→ DNS 动态更新报文：ch11 §11.5

三、实际应用

场景 说明
企业 AD 域 域内 PC 获 DHCP 地址后自动注册 A/AAAA + PTR，主机名即 FQDN
家用路由器 内网设备主机名自动注册到本地 DNS / mDNS 类服务
公网动态 IP 家庭宽带 IP 变化时，客户端向 DynDNS 等服务商更新（思路同源） → ch11 §11.7

考点速记

# 要点
1 DDNS 核心：联动 DHCP 与 DNS，动态刷新域名–IP 映射（A/AAAA）
2 执行主体：DHCP 服务器或客户端均可发起更新
3 安全要点：必须做身份认证（如 TSIG），避免记录被篡改
易错 正确
DDNS 只更新 PTR 主要更新 A/AAAA（正向）；PTR 反向常一并维护
任何人可改 DNS 需 TSIG/ACL 等认证授权
IP 变了 DNS 自动跟 需 DDNS 机制主动推送更新

疑问与总结

背：DHCP 换 IP 致 DNS 失效 → DDNS 刷 A/AAAA；服务器或客户端发起；必须 TSIG 认证。

6.5

以太网上的 PPP (PPPoE)

章级精读：study.md#ch06-5 · PPP 基础/LCP/认证：ch03 §3.6 · 内网 DHCP：6.2

本节核心目标

掌握 PPPoE 的作用、三阶段流程 与 外网 PPPoE + 内网 DHCP 的双层地址架构。

一、作用与本质

项 说明
场景 家庭宽带接入 — 在以太网环境实现 PPP 点到点特性
核心诉求 运营商完成账号认证、动态分配公网 IP
封装 PPP 报文封装进以太网帧 → PPP over Ethernet（PPPoE） 
[光猫/路由器] --以太网--> [运营商 BRAS] 
         以太网帧内载荷 = PPP（认证 + IPCP 配址）

一句：PPPoE = 以太网承载 PPP，用于宽带拨号认证 + 地址分配。

→ PPP 未废止、LCP/PAP/CHAP：ch03 §3.6

二、完整工作流程

1. 发现阶段（PPPoE Discovery）

通过 PADI → PADO → PADR → PADS 交互，在以太网上建立 PPPoE 会话（获得 Session ID）。

报文 方向 含义
PADI 客户端 → 广播 PPPoE Active Discovery Initiation
PADO 服务器 → 单播 Offer
PADR 客户端 → 单播 Request
PADS 服务器 → 单播 Session-confirmation

2. 链路 & 认证（PPP 阶段）

步骤 协议 说明
LCP Link Control Protocol 协商链路参数（MRU、认证方式等）
认证 PAP / CHAP 账号密码验证（CHAP 更安全）

3. 地址协商

步骤 协议 说明
IPCP IP Control Protocol（NCP 之一） 获取公网 IP、网关、DNS 等参数 
发现(PADI/PADO/PADR/PADS) → LCP → PAP/CHAP → IPCP → 数据传输

三阶段口诀：会话发现 → LCP+认证 → IPCP 配 IP

三、与 DHCP 的层级关系

层级 机制 获得地址
外网侧 路由器/光猫 PPPoE 拨号 运营商分配的公网 IP
内网侧 终端 DHCP 向路由器申请 私网 IP（192.168.x.x 等） 
[PC DHCP] → [家用路由器 内网私网] 
              ↓ PPPoE 拨号
         [运营商 公网 IP]

二者分属不同层级，互不冲突 — 典型架构：外网 PPPoE + 内网 DHCP，双层地址分配。

→ DHCP DORA：6.2

考点速记

# 要点
1 PPPoE = 以太网承载 PPP；宽带拨号认证 + 地址分配
2 三阶段：会话发现 → LCP + 认证 → IPCP 配 IP

易错 正确

IPCP 属于发现阶段 IPCP 在 PPP 阶段，发现之后

背：PPPoE=以太网包PPP；PADI四步发现→LCP→PAP/CHAP→IPCP拿公网IP；家里DHCP私网、光猫PPPoE公网。

6.8

实战：DHCP、桥接、NAT 与虚拟机网络

章级精读：study.md#ch06-8 · DHCP 通俗：6.1 §DHCP 是什么 · 私网地址：ch02 §2.5 · NAT 原理：ch07 §7.3

本节核心目标

结合物理网络与虚拟机场景，讲清 NAT（网络地址转换）、桥接、DHCP 三者分工 — 重点搞懂虚拟机 NAT 为何是「套了两层 NAT」。

术语：NAT = Network Address Translation（网络地址转换），不是 NVP 等其他缩写。

一句总览：NAT = 地址翻译官；DHCP = 自动发 IP 的服务；桥接/NAT = 虚拟机网络模式 — 模式决定通路，DHCP 决定参数怎么填。

一、标准 NAT 原本的作用（物理网络）

NAT 核心 = 内网 IP ↔ 公网 IP 互相转换

步骤 说明
① 内网私网 手机、电脑都是私有内网 IP（如 192.168.x.x）— 公网不能直接路由
② 出站翻译 家用路由器做 NAT：内网 IP → 换成运营商分配的唯一公网 IP → 数据才能上互联网
③ 回包翻译 外网回包时，路由器再把公网 IP 转回对应内网 IP，发给设备

一句：NAT 是「翻译官」，负责内网和外网地址转换。

→ 详：ch07 §7.3 NAPT

二、虚拟机 NAT 模式：套了「两层 NAT」（困惑关键点）

虚拟机软件（VMware / VirtualBox / libvirt）虚拟出一套独立小局域网，结构分两层：

第一层：虚拟机 ↔ 虚拟网卡（虚拟机内部子网）

组件 作用
虚拟 DHCP 给 VM 分配软件自定义私网 IP（如 192.168.122.x）
虚拟 NAT 网关 在虚拟子网内做地址转换
  • VM 拿到的是虚拟私网 IP
  • 该网段与真机所在家里局域网完全分开

第二层：虚拟网关 ↔ 物理主机 ↔ 真实路由器

环节 翻译
虚拟 NAT VM 192.168.122.x → 物理主机本机 IP（如 192.168.1.10）
物理 NAT 主机 IP → 家里路由器 → 公网 IP（如 110.xx.xx.xx）→ 互联网 
虚拟机 → 虚拟子网(虚拟NAT) → 真机网卡 → 家里路由器(物理NAT) → 互联网

一句总结：虚拟机 NAT 只是把 NAT 机制嵌套了一层 — 原理与标准 NAT 相同，多了一级虚拟网络。

三、桥接模式：为什么没有这层嵌套？

桥接 = 虚拟机直接「插队」进真实局域网

项 桥接 NAT
虚拟子网 无 有（如 192.168.122.0/24）
虚拟 NAT 无 有
IP 来源 家里路由器 DHCP 虚拟 DHCP
网段 与真机同网段（如 192.168.1.x） 异网段
上网 NAT 层数 仅路由器一层 NAT 虚拟 NAT + 路由器 NAT

四、用地址举例，直观看懂区别

假设：

  • 物理主机 IP：192.168.1.10（家里路由 DHCP）
  • 家里路由公网 IP：110.xx.xx.xx

1）虚拟机 NAT 模式

项 值
VM IP 192.168.122.20（虚拟 DHCP，独立网段）

访问百度：

192.168.122.20 →【虚拟 NAT】→ 192.168.1.10 →【路由器 NAT】→ 110.xx.xx.xx → 互联网

特点：手机、另一台电脑找不到 192.168.122.x 网段 → 无法主动访问 VM

2）虚拟机桥接模式

项 值
VM IP 192.168.1.11（路由 DHCP，与真机同网段）

访问百度：

192.168.1.11 → 直接交路由器 →【路由器 NAT】→ 110.xx.xx.xx → 互联网

特点：同 Wi‑Fi 下设备可直接访问 VM

五、DHCP 与 NAT/桥接：三者分工（串起来）

概念 类型 干什么
NAT 地址翻译机制 内网 IP ↔ 公网 IP；VM NAT = 多嵌一层虚拟 NAT
桥接 / NAT 模式 VM 网络拓扑 决定 VM 接哪张网、经几层 NAT
DHCP 配参服务 自动发 IP、掩码、网关、DNS — 与 NAT/桥接是两套东西
# 要点
1 桥接、NAT 两种模式都可以开 DHCP（也可手填静态 IP）
2 NAT/桥接 = 网络通路规则
3 DHCP = IP 地址分配服务 
         ┌─ 桥接 → 路由 DHCP → 192.168.1.x → 一层物理 NAT 上网
VM 网络 ─┤
         └─ NAT   → 虚拟 DHCP → 192.168.122.x → 虚拟 NAT + 物理 NAT 上网

→ DHCP 协议：6.2

六、内网 IP & 子网掩码（补充）

私网 IP

192.168.x.x / 10.x.x.x / 172.16~31.x.x — 仅局域网有效，公网不认。DHCP 下发的基本都是私网 IP。

子网掩码（判同网段）

家用常见 255.255.255.0：IP ∧ 掩码 = 网络号 — 相同则同网段直连，不同则经网关。

设备 IP 网络号
宿主机 192.168.1.10/24 192.168.1.0
桥接 VM 192.168.1.11/24 192.168.1.0 → 同网段
NAT VM 192.168.122.20/24 192.168.122.0 → 异网段

→ ch02 §2.5

需求 选

VM 能上网 + 外界不可主动连入 NAT

# 要点
1 NAT：地址翻译；VM NAT = 虚拟内网 + 虚拟翻译，再叠路由器 NAT
2 桥接：VM 直连真实局域网，无虚拟中间层，仅一层物理 NAT 上网

易错 正确
写成 NVP NAT（Network Address Translation）
VM NAT 只有一层 NAT 虚拟 NAT + 路由器 NAT 两层
