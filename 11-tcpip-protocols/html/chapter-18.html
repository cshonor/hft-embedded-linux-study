引言

章级精读：../study.md

本节核心目标

建立网络安全的全局视角：威胁 → 原则 → 密码学 → 协议层防御。

安全三要素 (CIA)

要素 含义 网络威胁
机密性 (Confidentiality) 数据不被窃听 明文传输、中间人
完整性 (Integrity) 数据不被篡改 伪造、注入
可用性 (Availability) 服务不被中断 DDoS、RST 注入

网络安全层次

应用层:  HTTPS / SFTP / SSH
传输层:  TLS / DTLS
网络层:  IPSec / VPN
链路层:  802.1X / MACSec

每一层都有自己的安全机制，但端到端加密（TLS）是最常用的。

HFT 关联

安全维度 HFT 需求
机密性 交易策略/订单不可泄露 → TLS/专线
完整性 行情/订单不可篡改 → MAC/签名
可用性 交易不可中断 → DDoS 防护 + 冗余

18.2

安全原则

章级精读：../study.md

本节核心目标

掌握网络安全的核心设计原则。

关键原则

原则 含义
纵深防御 多层安全，不依赖单一机制
最小权限 只授予必要的访问权限
默认拒绝 未明确允许的即拒绝
失败安全 出错时进入安全状态（如断开而非放行）
开放设计 安全不依赖算法保密（Kerckhoffs 原则）

信任边界

互联网 (不可信) → 防火墙 → DMZ (半可信) → 内网 (可信) → 核心交易 (高可信)

每跨越一个信任边界都需要认证 + 加密。

HFT 关联

HFT 交易网络通常在数据中心内部（可信），但跨数据中心 WAN 需要加密。交易服务器应遵循最小权限原则——只开放必要的端口和连接。

  2. "纵深防御"为什么比单层防御更可靠？
  3. HFT 交易网络的信任边界在哪里？

类型 机制 示例

密码学基础

章级精读：../study.md

本节核心目标

掌握对称加密、非对称加密、哈希、MAC 的基本概念。

四大原语

原语 用途 示例
对称加密 加密大量数据 AES-256
非对称加密 密钥交换/签名 RSA, ECDH
哈希 完整性验证 SHA-256
MAC 认证+完整性 HMAC-SHA256

对称 vs 非对称

对称 非对称
密钥 加解密同一密钥 公钥加密，私钥解密
速度 快（硬件加速） 慢
用途 数据加密 密钥交换/签名
问题 如何安全分享密钥？ 速度慢

TLS 的做法：非对称交换密钥 → 对称加密数据。

哈希 vs MAC

哈希 MAC
输入 任意数据 数据 + 密钥
输出 固定长度摘要 固定长度认证码
验证完整性 ✓ ✓
验证身份 ✗ ✓（需要密钥）

HFT 关联

原语 HFT 用途
AES 交易数据加密（TLS 内部）
ECDH TLS 1.3 密钥交换（0-RTT）
SHA-256 行情/订单完整性验证
HMAC 消息认证

  1. 对称和非对称加密的区别？TLS 如何结合使用？
  2. 哈希和 MAC 的区别是什么？
  3. 为什么 ECDH 比 RSA 更适合 TLS 1.3？

PKI 与证书

章级精读：../study.md · 密码学：18.4

本节核心目标

理解 PKI（公钥基础设施）和 X.509 证书的作用。

PKI 组成

CA (证书颁发机构)
  ↓ 签发
证书 (绑定公钥与身份)
  ↓ 验证
依赖方 (验证证书链 → 信任公钥)
组件 作用
CA 受信任的第三方，签发证书
证书 绑定公钥与域名/组织
私钥 证书持有者保密
信任链 根 CA → 中间 CA → 终端证书

证书内容

X.509 Certificate:
  Subject: CN=example.com
  Public Key: RSA-2048 / ECDSA-P256
  Issuer: Let's Encrypt R3
  Validity: 2024-01-01 to 2024-04-01
  Signature: CA's signature on above
  Extensions: SAN (subjectAltName), KeyUsage, ...

证书验证

1. 收到证书 → 检查签名链 → 根 CA 在信任库中？
2. 检查有效期 → 未过期？
3. 检查吊销列表 (CRL/OCSP) → 未被吊销？
4. 检查域名匹配 (SAN) → 与连接目标一致？

HFT 关联

HFT 交易系统可使用自签 CA（内部信任）或硬件证书（HSM 存储）。TLS 握手的证书验证增加延迟——TLS 1.3 通过预共享密钥（PSK）支持 0-RTT。

自测题

  1. CA 的作用是什么？为什么需要信任链？
  2. 证书验证需要检查哪些内容？
  3. TLS 1.3 的 0-RTT 如何避免证书验证延迟？

IPSec

章级精读：../study.md · VPN

本节核心目标

理解 IPSec 的两种模式和核心协议。

IPSec 组成

协议 作用
AH (Authentication Header) 认证 + 完整性（不加密）
ESP (Encapsulating Security Payload) 加密 + 认证
IKE 密钥交换（基于 Diffie-Hellman）

传输模式 vs 隧道模式

模式 加密范围 用途
传输模式 仅载荷 主机到主机
隧道模式 整个 IP 包 VPN（站点到站点） 
传输模式: [IP头] [ESP头] [加密载荷]
隧道模式: [新IP头] [ESP头] [加密(原IP头+载荷)]

HFT 关联

IPSec 用于跨数据中心 WAN 加密——透明于应用层，但加密/解密有性能开销。硬件 IPSec 卸载可降低 CPU 开销。

TLS 与 DTLS

章级精读：../study.md · PKI：18.5

本节核心目标

理解 TLS 握手流程、TLS 1.3 改进和 DTLS。

TLS 1.2 vs 1.3

TLS 1.2 TLS 1.3
握手 2 RTT 1 RTT
0-RTT 不支持 支持（会话恢复）
密钥交换 RSA/DHE/ECDHE 仅 ECDHE
加密 CBC/RC4/etc 仅 AEAD (AES-GCM/ChaCha20)
证书 明文传输 加密

TLS 1.3 握手

Client → Server: ClientHello (含密钥共享)
Server → Client: ServerHello + 证书 + Finished (加密)
Client → Server: Finished (加密)
→ 1 RTT 完成

0-RTT (会话恢复):
Client → Server: ClientHello + 早期数据 (加密)
→ 0 RTT 发送数据

DTLS

DTLS = UDP 上的 TLS。解决 UDP 无连接下的安全问题（如 WebRTC、CoAP）。

TLS DTLS
传输 TCP UDP
可靠性 TCP 保证 自行处理重传
分片 TCP 分段 自行处理分片

HFT 关联

TLS 特性 HFT 影响
TLS 1.3 1-RTT 首次连接延迟降低
0-RTT 会话恢复几乎无延迟
AEAD 加密 AES-GCM 硬件加速 → CPU 开销低
证书加密 隐私提升

注意：TLS 0-RTT 有重放攻击风险——不适合非幂等交易指令。

DNSSEC

章级精读：../study.md · DNS：ch11

本节核心目标

理解 DNSSEC 的签名链和验证机制。

DNSSEC 解决的问题

传统 DNS 无认证 → 可被缓存投毒 → DNSSEC 通过数字签名验证数据来源。

签名链

根 (Root) → 签名 → TLD (.com) → 签名 → 权威 (example.com)
  ↑ K root key                ↑ DS record               ↑ RRSIG
记录 作用
RRSIG 记录的数字签名
DNSKEY 公钥（验证 RRSIG）
DS 委派签名（父区对子区公钥的哈希）
CDNSKEY/CDS 自动委派信号

验证流程

1. 递归器收到 example.com A 记录 + RRSIG
2. 用 example.com 的 DNSKEY 验证 RRSIG
3. 用 .com 的 DS 验证 example.com 的 DNSKEY
4. 用根的 DS 验证 .com 的 DNSKEY
5. 用信任锚（根 KSK）验证根 → 信任链完整

DNSSEC 不加密 DNS → 仅验证完整性 + 来源。加密需 DoT/DoH。

HFT 关联

HFT 系统一般不依赖公网 DNS → DNSSEC 价值有限。但使用公网 DNS 时应启用验证。

DKIM

章级精读：../study.md

本节核心目标

理解 DKIM 邮件签名机制。

DKIM 工作原理

1. 发件方邮件服务器用私钥对邮件签名
2. 签名放入 DKIM-Signature 头
3. 收件方查询发件域的 DNS TXT 记录获取公钥
4. 用公钥验证签名 → 确认邮件确实来自该域

相关协议

协议 作用
SPF 指定哪些 IP 可代表该域发邮件
DKIM 邮件内容数字签名
DMARC 整合 SPF+DKIM，指定失败处理策略

HFT 关联

DKIM 与 HFT 无直接关系，但交易确认邮件的完整性验证可防止邮件篡改。

协议攻击

本节核心目标

了解跨层协议攻击的典型模式。

攻击矩阵

攻击 层 机制 防御
ARP 欺骗 链路 伪造 ARP Reply 动态 ARP 检测
DNS 投毒 应用 伪造 DNS 响应 DNSSEC
TCP RST 注入 传输 伪造 RST 加密 (TLS)
ICMP Redirect 网络 伪造重定向 禁用接受
VLAN 跳跃 链路 伪造 VLAN 标签 端口配置
BCP38 缺失 网络 源地址伪造 源地址验证

跨层攻击

攻击者可组合多层攻击： 1. ARP 欺骗 → 成为中间人 2. DNS 投毒 → 重定向流量 3. TLS 剥离 → 降级为明文

防御：每层都需独立防护 + 端到端加密。

HFT 关联

攻击 HFT 影响
ARP 欺骗 行情被劫持
DNS 投毒 交易流量被重定向
RST 注入 交易连接中断
VLAN 跳跃 交易网络被渗透

防御：交换机端口绑定 + 专线 + 加密 + 监控。
