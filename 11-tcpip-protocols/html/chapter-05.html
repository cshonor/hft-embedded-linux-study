5.1

引言

章级精读：study.md#ch05-1 · 上一章：ch04 ARP · ch01 端到端

本节核心目标

明确 IP 在 TCP/IP 中的核心地位与服务语义。

一、IP 的核心地位

  • IP（Internet Protocol） 是 TCP/IP 网络层的核心协议，整个互联网通信都围绕 IP 展开。
  • 所有跨网数据 必须经由 IP 转发，向上支撑 TCP/UDP，向下适配各种链路（以太网、Wi‑Fi 等）。
  • 提供 统一寻址 + 逐跳转发 的「细腰」作用：异构网络都用 IP 地址互通，路由器只看 IP 头转发。

→ 沙漏模型：ch01 · 地址结构：ch02

二、IP 服务语义（核心特性）

1）无连接（Connectionless）

  • 不维护每条流（per‑flow）的状态。
  • 每个 IP 数据报 独立选路、独立转发，前后包无关联。
  • 类比：每张明信片单独写地址、单独投递，不用先打电话确认对方是否准备好。

2）尽力而为（Best‑Effort）

不保证 含义
送达 丢包不重传（由 TCP 等上层补）
顺序 不同路径可导致乱序
无重复 路由回环或复制可能产生重复包

3）出错 / 拥塞处理

  • 网络出错或拥塞时，路由器常直接丢弃数据包。
  • 可能回送 ICMP 差错报告（目的不可达、超时等）给上层，但不保证一定回。

三、IP 与传输层（TCP/UDP）分工

IP（网络层）负责

职责 说明
寻址 全局唯一 IP 地址，定位主机
路由/转发 逐跳把包从源主机送到目的主机
分片/重组 适配不同链路 MTU

一句话：IP 管「送到哪台机器」。

TCP（传输层）负责

职责 说明
可靠性 确认、超时重传、去重、排序
拥塞控制 + 流量控制 防网络过载、防发送方压垮接收方
进程寻址 端口号，把数据交给主机上的对应应用

一句话：TCP 管「送到哪个进程、保证可靠」。

分工总结

层次 特性
网络层（IP） 无连接、尽力而为、逐跳转发、统一寻址
传输层（TCP） 面向连接、可靠、端到端、拥塞/流量控制

复杂逻辑（可靠、重传、拥塞）放在端系统（TCP）；网络核心（路由器）只做简单转发 — 这是互联网可扩展的关键（端到端原则）。

拓展（预留）

  • UDP 与 IP 的「无连接」叠加关系
  • 与自顶向下 §4.1 数据平面 对照

抓包/实操记录

（待填：Wireshark 只看 IP 头 TTL 递减，不涉及 TCP 状态）

疑问与总结

IP = 全球统一地址 + 尽力而为转发；可靠性与拥塞交给端上的 TCP。

5.2

IPv4 头部和 IPv6 头部

章级精读：study.md#ch05-2 · 分用：ch01 §分用 · 扩展头：5.3 · 分片：ch10

本节核心目标

对比 IPv4 可变头 与 IPv6 固定 40 字节头 的设计差异与核心字段。

一、整体核心差异

维度 IPv4 IPv6
头部长度 可变：最小 20 B，带选项最大 60 B 固定 40 B，无内嵌选项
设计思路 功能内嵌主头；分片复杂；每跳校验和开销大 基础头只留转发必需字段；额外功能 → 扩展头按需挂载
转发效率 变长解析 + 校验和更新 固定头 → ASIC/NP 流水线友好

Protocol 字段（三层 → IP 载荷分用）

项 说明
位置 IPv4 首部 第 9 字节（TTL 与首部校验和之间）
作用 标明 IP 载荷是 ICMP、TCP 还是 UDP
口诀 二层定三层，三层定内层
值 载荷 层次
1 ICMP 网络层（封装在 IP 内）
6 TCP 传输层
17 UDP 传输层

IPv6 用 Next Header（含扩展头链 → 5.3 §链式规则）。

→ ch01 §分用 · ch08 ICMP

二、IPv4 核心字段（必记）

字段 核心作用 补充说明
TTL 每经过一跳路由器 −1，防报文环路 IPv6 对应 Hop Limit，逻辑一致
TOS / DS+ECN 早期服务类型；现为 DSCP（差分服务）+ ECN（显式拥塞通知） QoS 优先级、拥塞标记
头部校验和 仅对 IP 首部完整性校验 逐跳路由器须重算、更新 → 转发开销大
标识 / 标志(DF/MF) / 片偏移 控制 IP 分片与重组 路由器可中途分片；DF=1 = 禁止分片

IPv4 分片 = 网络层分片，中间路由器可介入。

三、IPv6 头部：删减、新增、改造

1）直接移除

移除项 原因
头部校验和 L2 FCS + L4（TCP/UDP）校验已覆盖；减少路由器运算
路由器级分片 中间路由器不分片；过大 → 丢弃 + ICMPv6 Packet Too Big → 源主机分片
标识 / DF/MF / 片偏移 不再出现在 基础头（极端场景见扩展头 → 5.3）

2）新增

  • 流标签（Flow Label）：标识同一类数据流 → QoS、流量调度、快速转发 场景：视频/语音等长流，设备可基于流标签处理，无需反复解析五元组。

3）功能迁移

  • IPv4 选项 → IPv6 扩展头链表（5.3）
  • 优势：基础头固定；常规转发不必解析扩展头；仅安全/分片/路由等场景才遍历。

4）同源字段更名

  • IPv4 TTL → IPv6 Hop Limit（每跳递减，防环路）

字段对照速查

字段 IPv4 IPv6
头长 IHL，20–60 B 固定 40 B
QoS ToS → DSCP/ECN Traffic Class
流标签 无 20 bit Flow Label
长度 Total Length（含头） Payload Length（不含头）
寿命 TTL Hop Limit
上层 Protocol Next Header
校验和 有，每跳更新 无
分片 主头字段 + 路由器可分片 仅源分片 + 扩展头

四、易混：IP 分片 vs TCP 分段（必考）

IPv4 分片（网络层） TCP 分段（传输层）
触发方 中间路由器（或源主机） 端系统（源主机）
依据 链路 MTU MSS（两端协商）
对象 整个 IP 报文 TCP 数据载荷
层级 三层 四层

总结：三层管「链路能否承载」；四层管「应用数据如何拆」— 层级、触发主体、依据完全不同。

→ ch03 §MTU · ch10 分片

五、极简背诵清单

  1. IPv4：头长可变（20–60 B）；有头校验和；路由器可分片；选项内嵌主头。
  2. IPv6：头长固定 40 B；无头校验和；路由器不分片；新增流标签；选项 → 扩展头。
  3. 分片 = 网络层（MTU / 路由器）；分段 = 传输层（MSS / 端主机）。

拓展（预留）

  • PMTUD 与 DF=1 → ch03
  • IPv6 固定头与硬件转发流水线

抓包/实操记录

（待填：Wireshark 对比 v4 Identification/Fragment 与 v6 仅源分片）

疑问与总结

v6 用固定头 + 去校验和 + 源分片，换路由器线速；v4 分片别和 TCP 分段混。

5.3

IPv6 扩展头部

章级精读：study.md#ch05-3 · IPv6 固定头：5.2 §三 · 分片：ch10 · IPsec：ch18 · ICMPv6：ch08

本节核心目标

理解 IPv6 菊花链（daisy-chaining） 扩展头设计、Next Header 串联规则，以及各常见扩展头的用途与转发语义。

一、核心设计思想

# 要点
1 基础头部固定 40 字节，无可变选项字段 → 主干路由器仅解析主头，转发效率高
2 附加功能（路由、分片、安全、逐跳控制等）剥离为扩展头部，菊花链（链式）依次串联
3 扩展头按需添加；无对应功能则不携带 → 兼顾转发性能与功能扩展性

背景：IPv4 Options 内嵌主头、变长解析、每跳校验和 → 拖慢路由器；IPv6 将「非每跳必需」功能下沉到扩展头 → 5.2 对比

二、链式规则 & Next Header 字段

报文结构

IPv6 主头 → 扩展头1 → 扩展头2 → … → 上层协议（TCP/UDP/ICMPv6）

Next Header（下一个头部）

位于每个头部中，标识紧随其后的头部类型 — 串联扩展链的核心字段。

位置 Next Header 指向
主头 第一个扩展头，或直接指向上层协议（无扩展头时）
每个扩展头 下一个扩展头，或最终上层协议
链末扩展头 承载的传输层 / ICMPv6 等协议

链式示意

[ IPv6 固定头 NH=0 ] → [ 逐跳选项 NH=43 ] → [ 路由头 NH=44 ] → [ 分片头 NH=6 ] → [ TCP ] → Data

IPv4 的 Protocol 字段在 IPv6 中由 Next Header 承担分用职责（含扩展头链）→ 5.2 §Protocol

三、常见扩展头及用途

扩展头 NH 值* 主要作用 补充说明
逐跳选项头 (Hop-by-Hop) 0 全网所有转发节点必须解析处理 唯一要求沿途路由器逐跳读取的扩展头
路由头 (Routing Header) 43 IPv6 源路由，指定转发路径节点列表 控制报文途经的网络节点；移动性等场景
分片头 (Fragment Header) 44 报文分片与重组 仅源主机负责分片；中间路由器不分片
目标选项头 (Destination Options) 60 仅最终目的节点解析生效 存放目的端才处理的附加选项
ESP 50 IPsec 加密 网络层安全 → ch18
AH 51 IPsec 认证 完整性校验，不加密载荷

* Next Header 协议号；上层常见：6=TCP、17=UDP、58=ICMPv6

分片行为（必考）

IPv4 IPv6
分片位置 主头字段；路由器可分片 分片头扩展头；仅源节点分片
过大报文 路由器可能分片转发 路由器丢弃 + ICMPv6 Packet Too Big → 源主机调整 MTU 后端到端分片

→ 详：ch10 分片 · ch08 ICMPv6

四、IPv4 vs IPv6（易混）

维度 IPv4 IPv6
主头 可变（含 Options，20–60 B） 固定 40 B，无内嵌选项
附加功能 Options 内嵌主头 扩展头按需链式挂载
路由器分片 可以 不可以
中间节点解析 可能需解析 Options 默认只读主头；除 Hop-by-Hop 外多数扩展头透明转发

五、考点速记

# 要点
1 IPv6 主头固定 40 字节，无变长选项，主干转发开销远低于 IPv4
2 扩展头以菊花链串联，靠 Next Header 标识后继头部
3 扩展头按需携带，非必选；中间路由器默认不解析大部分扩展头
4 IPv6 分片：仅源节点用分片头；转发设备不执行分片
5 Hop-by-Hop（NH=0） 是唯一要求每台路由器处理的扩展头
易错 正确
所有扩展头每台路由器都解析 仅 逐跳选项 必须逐跳处理
IPv6 路由器仍可分片 仅源主机分片；过大 → Packet Too Big
Next Header 只在主头里 每个头部都有 Next Header，形成链

六、Lab / 抓包

过滤器（Wireshark） 用途
ipv6 所有 IPv6
ipv6.nxt == 0 逐跳选项头
ipv6.nxt == 44 分片头
ipv6.nxt == 6 主头后直接 TCP（无扩展头或链末为 TCP）

展开 IPv6 包时沿 Next Header 字段逐层下钻，可验证扩展头链顺序。

拓展

疑问与总结

背：40 B 固定主头 + Next Header 菊花链 + 按需扩展 + 仅源分片 + Hop-by-Hop 唯一逐跳解析。

5.4

IP 转发与路由协议（ARP → IGP → BGP）

章级精读：../study.md#ch05-4 · ARP：ch04 §4.2 · 精编 LPM：04 §4.3 · 控制平面：§5 · BGP 与 CIDR：ch02 §2.4

本节核心目标

掌握 LPM 转发、直接/间接交付；理清 ARP（局域网） 与 IGP / EGP（BGP） 分工；能串起 主机 → 网关 → 公网 完整路径。

一、完整转发分两段（结合 ARP）

段 范围 靠什么
① 局域网 同一广播域 ARP：内网 IP ↔ 直连 MAC；广播出不了路由器 → ch04 广播域
② 跨网段 / 公网 路由器之间 三层路由协议 维护路由表，逐跳转发

主机侧规则：同网段用 ARP 找对方；跨网段一律先发给网关（边缘路由器）。

[ 内网：ARP + 以太网 ] → 网关 → [ 运营商/公网：IGP + BGP 路由 ]

二、名词纠正 + 统一术语

纠正 正解
❌ DGP 无此标准词
❌ IGB 应为 IGP（Internal Gateway Protocol）
✅ AS 自治系统（Autonomous System）：一家运营商或一个大型企业，在 BGP 里常作为一个整体编号（如 AS100）
✅ IGP 内部网关协议（OSPF / IS-IS / RIP…）
✅ BGP 边界网关协议，不同 AS 之间用（属于 EGP 这一类）
✅ EGP 外部网关协议（类别名）；现网跨 AS 几乎全是 BGP

分工一句话

类型 管什么
IGP 同一个 AS 内部的路由（企业内网、运营商骨干内网）
BGP AS 与 AS 之间（不同运营商对接、公网前缀交换）

二附、核心结论：AS ≠ 局域网；IGP 管内、BGP 站门口

1）一个 AS 内部 ≠ 局域网

易混 正解
AS = 一个大局域网？ 否。AS 里是大量路由器 + 多级网段的三层网络，有无数逐跳转发
跨网段怎么转？ 不靠 ARP 串完全网；路由器之间靠 IGP 选下一跳；每一跳只在当前直连广播域里 ARP

结论：AS 内部路由器之间的选路、跳转 → 全程 IGP（OSPF/IS-IS…）。

2）BGP 只工作在「AS 与 AS 的边界」

  • 包在本 AS 内部爬升/横穿 → 只用 IGP
  • 包到达本 AS 边缘出口，下一跳要进另一个 AS（别家运营商/外网）→ 才用 BGP 与邻居 AS 交换路由、定跨 AS 下一跳

3）一句话区分边界（背）

AS 里面：IGP 当家（内部路由器互访、一跳一跳） AS 门口：BGP 站岗（不同 AS 对接、交换公网路由）

4）易错两点

# 易错 纠正
1 同一 AS 里也跑 BGP？ 内部不用 BGP 做域内选路；跨 AS 主要靠 BGP
2 边缘路由器一张表？ IGP 条目（内网前缀）+ BGP 条目（外网/其他 AS）共存；查表时 LPM 选最优，再 ARP 下一跳 MAC

三、IGP（内部网关协议）

适用范围：一个机构、一家运营商内部。

常见 IGP 备注
OSPF 企业网、运营商内常用
IS-IS 运营商骨干常见
RIP 小规模、老环境
EIGRP Cisco 环境

作用

  • 让内部所有路由器互相学习去往各内网前缀的路由
  • 路由信息只在域内传播，不用来和别的运营商直接交换全网表

例子：小区路由器 → 本地机房 → 省会骨干，这一段运营商内部跳数，靠 OSPF / IS-IS（IGP） 维护。

四、BGP（边界网关协议，属于 EGP）

适用范围：不同 AS、不同运营商之间（互联网「网间」路由）。

作用

  • 各大网络之间交换可达的 IP 前缀（路径属性、策略）
  • 决定跨运营商流量从哪个出口走
  • 边缘路由器上大量公网 / 外网路由，主要靠 BGP 学到

你的理解对：边缘路由器去往外网、跨运营商的路由，主要由 BGP 管理。

→ 深入：ch02 BGP 与 AS

五、边缘路由器：IGP + BGP 两张「地图」并存

一台企业/运营商边缘路由器的路由表里通常同时有：

条目来源 去往哪里 典型协议
IGP 本企业 / 本运营商内部各网段 OSPF、IS-IS…
BGP（EGP） 互联网、其他运营商、其他 AS 的前缀 BGP

每一跳转发时：仍遵循 查路由表 → 得下一跳 IP → 本广播域内 ARP 下一跳 MAC（与 ch04 相同）。

六、串一遍：家宽 → AS100 → AS200 → 服务器

路径：家庭网 → 运营商 A（AS100） → 运营商 B（AS200） → 目标服务器

步 位置 协议/机制
1 终端 → 家里网关 局域网：ARP 解析网关 MAC
2 进入 AS100 内部 各级路由器转发；选路、下一跳 → IGP 全权（OSPF/IS-IS）
3 AS100 边缘出口 再往前要离开本 AS → BGP 与相邻 AS 交换路由，定跨 AS 下一跳
4 进入 AS200 内部 again → IGP 转发至目标网段
5 末端局域网 ARP 交给目标主机 
PC --ARP--> 家网关 --IGP...IGP--> AS100边缘 --BGP--> AS200边缘 --IGP...IGP--> 目的网 --ARP--> 服务器
         └──── AS100 内 IGP ────┘              └──── AS200 内 IGP ────┘

简化版（单运营商外访）：PC ARP 网关 → 边缘 BGP 选外网 → 域内 IGP 跳 → 对端 IGP/BGP → 末端 ARP。

七、背诵（ARP / IGP / BGP）

  1. ARP：只管同广播域；跨网段找网关；不用 ARP 串完整 AS。
  2. AS 内：IGP 当家（不是一个大局域网）。
  3. AS 边界：BGP 站岗（跨 AS / 运营商）；AS 内不用 BGP。
  4. 边缘路由表：IGP 条目 + BGP 条目 共存；每跳仍 路由 IP + ARP MAC。

八、最长前缀匹配 (LPM)

  • 目的 IP 与多条路由前缀匹配时，选掩码最长（最具体）的一条。
  • 查表五步、经典例题 → 04 §4.3 LPM
  • 路由器查 FIB 转发；主机查 路由表 决定本机发出还是交网关。

5.5

移动 IP（Mobile IP）

章级精读：study.md#ch05-5 · 间接交付：ch04 §4.2 · IP 隧道：ch03 §3.9 · IPv6 路由头：5.3

本节核心目标

理解移动 IP 的 MN / HA / CoA 三角角色、间接寻址（indirection） 与 IP 隧道转发机制，以及与现代 LTE / PMIPv6 的关系。

零、易混辨析：住宅 IP（Residential）≠ 移动 IP 里的家乡地址

结论先说：日常说的 「住宅 IP」 与移动 IP 协议里的 MN / 家乡地址（HoA） 完全两个体系 — 只是中文都带「住宅/家乡」，极易混。

1）日常说的「住宅 IP」（Residential IP）

项 说明
一句 运营商分给普通家庭宽带的公网 IP
来源 电信/联通/移动家宽拨号（如 113.xxx.xxx.xxx）
特点 对应真实家庭用户出口；风控常当真人；可静态或动态（重拨会变）
归属 公网 IP 的用途/归属地分类（相对机房 IP、数据中心 IP）
与移动 IP 无关 — 不参与 MN/HA/CoA 协议

你在家里上网，对外出口就是一个 住宅 IP。

2）移动 IP 里的 MN、家乡地址 HoA、CoA

术语 含义
移动 IP 设备跨网漫游时保持同一逻辑 IP、连接不断（公司 Wi‑Fi → 家 → 4G）
MN Mobile Node = 会跑的终端（手机、笔记本）— 是设备，不是 IP
家乡地址 HoA MN 的永久逻辑 IP（「身份证号」）；对外长期用 HoA；属家乡网络
CoA Care-of Address = 当前接入网的临时 IP（外地位置）

数据路径（在外地）：

通信方 → 发往 HoA（家乡）→ HA 截获 → 隧道 → CoA（当前位置）→ MN

课本有时把 HoA 译成「归属地址/住宅地址」→ 勿与 Residential 住宅 IP 混为一谈。

3）一句话对比

住宅 IP（日常） 家乡地址 HoA（移动 IP）
强调 我家宽带的公网出口，来源是家庭 这台设备的固定身份 IP，位置可动
体系 公网 IP 类型/风控分类 Mobile IP 协议逻辑概念
是否一定是家宽 是（定义即家庭宽带） 否 — HoA 可是内网或公网，≠ 家宽 IP

4）极简对照表（考试/理解）

名词 属于什么 核心意思
住宅 IP（Residential） 公网 IP 类型 家庭宽带分配的 IP，真实用户
MN 移动 IP 协议 会移动的终端（手机/笔记本）
家乡地址 HoA 移动 IP 协议 MN 的永久固定 IP（身份）
转交地址 CoA 移动 IP 协议 MN 当前网络的临时 IP（位置）

flowchart LR
  CN[通信方] -->|目的=HoA| HA[HA 家乡代理]
  HA -->|IP-in-IP 隧道 外层目的=CoA| MN[MN @ 外地网络]
  MN -.->|注册 CoA| HA
步骤 说明
① MN 在外地获 CoA，向 HA 注册
② HA 维护 HoA ↔ CoA 映射
③ 发往 HoA 的包到家乡网 → HA 隧道 → CoA → MN

→ 在家无 CoA、直连：§四 在家 vs 外地 · 角色详解：§一

一、核心角色

术语 全称 作用
MN 移动节点（Mobile Node） 可跨网络漫游的终端；对外固定使用家乡地址通信
HA 家乡代理（Home Agent） 部署在 MN 家乡网络；注册中心 + 数据转接点（见下）
CoA 转交地址（Care-of Address） MN 接入外地网络时获得的临时 IP；标识当前物理位置

HA 的双重角色（易漏考点）

角色 做什么
① 注册中心 MN 在外地拿到 CoA 后注册给 HA；HA 建立 家乡地址 → CoA 映射表
② 数据转接 外部仍发往老家乡地址的包到达 HA → 查映射 → 隧道封装转发到当前 CoA → MN 在外地收到

一句：HA 不光登记 MN 在哪，还要靠 CoA 映射帮 MN 转接数据，让外面的人不用改目的地址就能找到已经移走的 MN。

外部 ──(目的仍是 10.0.0.2)──► HA ──查表 10.0.0.2→20.1.1.3──► 隧道 ──► MN @ CoA

通信方 ──(目的=家乡地址)──► 家乡网络 ──► HA 截获
                                              │
                                    IP 隧道封装（外层目的=CoA）
                                              ▼
                                         MN @ 外地网络

大白话：三个词各指什么？（易混）

词 指什么 不是什么
MN 移动节点 = 那台会跑来跑去的设备本身（手机、笔记本） 不是「一个 IP 号码」；IP 是挂在 MN 上的
家乡地址 MN 归属的逻辑 IP（如 10.0.0.2），对外长期不变 在家时 MN 直接用这个地址上网
CoA 同一台 MN 在外地网络拿到的临时 IP（如 20.1.1.3） 不是另一台主机；是「这台设备此刻在哪、从哪接入」的地址
HA 家乡网络里的注册中心 + 转发枢纽 不是 MN 本人；是替所有归属本网的 MN 做登记和隧道转接的设备/网关

对照你的说法： - ✅ HA = 注册 + 转发，没错。 - ⚠️ MN = 设备；「本地注册的主机地址」更准确叫 家乡地址；CoA 是同一设备在外地的临时地址。

HA 有多少台？一用户一台吗？

问题 答案
一用户一 HA？ 否 — 不会给每个 MN 单独配一台 HA
实际部署 通常 一个区域 / 一个运营商网络 / 一个校园网 部署 一台（或一套）HA
管谁 管理所有归属该家乡网络的 MN 的 CoA 注册表 与 隧道转发
例子 某高校校园网设 一个 HA → 管全校师生笔记本、手机漫游

→ 蜂窝网里「漫游锚点」也是类似思路：运营商级共享设施，不是一人一锚点。

二、核心设计思路

# 要点
1 通信地址不变：无论 MN 漫游到哪，对外始终用家乡地址 → 上层应用无感知
2 流量转发机制：HA 与 MN 间建立双向 IP 隧道 → 往来流量经隧道转发至 MN 当前 CoA
3 核心思想：地址间接寻址（indirection） — 屏蔽终端网络位置变化

与常规路由对比：正常 IP 寻址 = 目的地址即物理可达位置；Mobile IP = 目的地址固定在家乡，真实位置由 CoA + 隧道间接到达。

→ 隧道封装：ch03 §3.9 隧道基础

三、基础工作流程

# 步骤
1 MN 在外地网络上线，获取本地 CoA，向 HA 注册当前 CoA
2 HA 记录映射：家乡地址 ↔ CoA
3 通信方发往 MN 家乡地址的报文，路由至家乡网络，由 HA 截获
4 HA 将报文封装进 IP 隧道（如 IP-in-IP），外层目的 = CoA，转发至外地
5 MN 回程报文可直连通信方，或同样经隧道回传（双向隧道）

咖啡馆案例（MN 离开公司）

  1. MN 在外地通过 DHCP 获 CoA，向 HA 注册
  2. 外部仍发往 MN 原 IP（家乡地址） 的包被 HA 拦截
  3. HA IP-in-IP 隧道封装，外层目的 = CoA → MN 在外地收到内层原报文

四、在家 vs 在外地（必分清）

关键：CoA 与隧道只在 MN 离开家乡网络时才启用；在家时 HA 就是普通网关，不走 Mobile IP 隧道。

场景 A：MN 在家（本地，无 CoA）

项 说明
MN 地址 家乡地址 10.0.0.2（就在家乡子网内）
CoA 无 — MN 物理就在家乡网，不需要转交地址
HA 角色 正常当默认网关（或子网内直连）
数据路径 通信方 ↔ 10.0.0.2 直接来回，与普通主机无异 
通信方 ──► 10.0.0.2 (MN 在家乡 LAN)     直接交付，无隧道
         HA 仅作网关时：MN 出网经 HA 转发，但不截获「发往 10.0.0.2」的包做隧道

场景 B：MN 在外地（漫游，启用 CoA + 隧道）

项 说明
MN 逻辑地址 对外仍是 10.0.0.2（家乡地址不变）
CoA 在外地外网拿到临时地址，如 20.1.1.3
注册 MN 把 CoA 20.1.1.3 报给 HA
HA 映射 10.0.0.2 → 20.1.1.3
入向数据 发往 10.0.0.2 的包 → HA 截获 → 隧道封装 → 外层目的 20.1.1.3 → MN 在外地收到
回程 MN 发往外部的包常可直连（源 IP 仍可用 10.0.0.2 或经 HA，视实现） 
通信方 ──(目的 10.0.0.2)──► 家乡网 HA
                              │ 查表：10.0.0.2 → CoA 20.1.1.3
                              └── 隧道 ──► 20.1.1.3 ──► MN @ 外地

对照表（考点）

在家（本地） 在外地（漫游）
CoA 不需要 必须有（如 20.1.1.3）
HA 普通网关 锚点 + 隧道端点
发往 10.0.0.2 的包 直连 MN HA 截获并隧道到 CoA
隧道 无 有

一句：在家 = 普通 IP 上网；外出 = 注册 CoA → HA 维护映射 → 隧道间接投递。

五、易混：Wi-Fi 漫游 vs Mobile IP

Wi-Fi 漫游 Mobile IP
层次 常 L2（同一 ESS 内切换） L3 跨网段/跨运营商
地址 可能换 IP（视 DHCP） 家乡地址不变
目标 链路层连续覆盖 会话不因换网中断（理想模型）

六、补充说明 & 现代演进

点 说明
本质 代理 + 隧道 → IP 地址与物理接入网络解耦
模型定位 本书基础概念模型 — 理解 indirection 的核心
现代实践 蜂窝/Wi-Fi 漫游多不再单纯用传统 Mobile IP；主流 LTE 切换、PMIPv6（代理移动 IPv6） 等增强方案

→ PMIPv6 思想：网络侧代理（类似 HA 角色）替终端维护绑定，减轻 MN 负担。

七、实例：手机蜂窝跨省漫游（对照模型）

用湖北手机号出省上网理解课本 Mobile IP — 好记、也对应考点。

1. 理论对应（Mobile IP ↔ 手机漫游）

移动 IP 手机漫游（例：湖北卡）
MN 移动节点 手机
家乡网络 湖北运营商网络（归属地）
家乡地址 运营商分配、逻辑归属湖北的 IP / 用户身份
HA 家乡代理 湖北运营商核心网关 / 漫游锚点
外地网络 出差所在外省基站网络
CoA 转交地址 在外省基站拿到的本地临时 IP

2. 网络层面（全国通用流量时代）

# 步骤
1 到外省，手机连当地基站 → 获本地 CoA 临时 IP
2 当地基站将位置、临时 IP 上报归属地（湖北）漫游锚点（≈ HA）
3 外网数据 → 先路由到湖北归属网络 → 归属地隧道封装 → 转发至当前外省 CoA 
外网 ──► 湖北归属网(HA) ──隧道──► 外省 CoA ──► 手机(MN)

一句：工程上就是 Mobile IP 的 间接寻址 + 隧道转发（实现多为 LTE/5G / PMIPv6 类架构，非 RFC 3344 原教旨）。

3. 流量计费 & 归属（常问）

项 现行（三大运营商主流）
全国通用流量 在湖北或任意省份使用，统一扣套餐通用流量，无额外漫游费
不存在 「到外地单独算一种漫游流量费」（早年规则已取消）
对比 早年 现在
套餐 省内流量 + 国内漫游流量 分开；出省优先扣漫游，用完加价 多数套餐标注全国通用
老套餐残留 — 少数仍有省内专属流量 → 出省不能用省内包，自动走全国通用

4. IP 表现小细节

观察 说明
公网 IP 归属地 人在外地，上网 IP 常显示为当前省份出口（用当地 CoA/当地 PGW）
账号 / 资费归属 仍是湖北（归属地不变）→ 对应「逻辑家乡地址 / 身份不变」

5. 串起来（考点）

# 要点
1 手机漫游 = 工程化 Mobile IP：位置变（CoA 变），归属身份 / 逻辑地址不变
2 运营商核心网 HA 锚点 + 隧道 → 无缝上网
3 资费：国内无跨省流量漫游额外收费（通用流量全国通）
4 协议演进：PMIPv6、LTE/5G 代理移动 — 思想同课本，实现更轻量

一句话：湖北卡去外地上网，扣套餐全国流量不加漫游费；网络上靠运营商漫游隧道转发，与课本 Mobile IP 逻辑一致。

→ 家乡地址何时绑定、APP 为何「永远看到 MN」：§八 HoA 绑定时间线

八、家乡地址 HoA 何时绑定网卡？（蜂窝工程视角）

一句话：系统网卡绑定家乡地址 HoA，是在设备第一次接入「自己的家乡网络」时，由运营商/网络侧分配、写入网卡配置，长期固定不变（卡/号不变则基本终身不变）。

课本：MN = 设备；HoA（Home Address） = 家乡地址。下文「APP 看到的 MN」指 HoA 这个逻辑身份 IP。

分阶段时间线

阶段 何时 发生什么
① 永久绑定 第一次在归属地（家乡）开机入网（办号、首次注册运营商） 核心网分配长期固定 HoA → 写入系统/蜂窝网卡配置 → 网卡 ↔ HoA 绑定完成；此后系统永远对外宣称此地址
② 在家重连 在家乡重启、飞行模式、断网重连 自动复用已绑定的 HoA，不重新分配；APP 新建连接仍用 HoA 作源地址
③ 外地漫游 出省/出国，拿到底层 CoA HoA 绑定不动；CoA 仅底层路由/隧道用；APP 仍只认 HoA，不知道 CoA
④ 关机换网 正常关机、换 Wi‑Fi、换基站 HoA 不变；仅 换号/换卡/运营商重分配 才会换 HoA

APP 怎么「记住」HoA？

易混 事实
APP 自己缓存 MN 否 — 系统网卡从首次在家入网就绑定了 HoA
APP 每次拿本机地址 调系统接口 → 拿到的永远是 HoA；对端记录的源地址也是 HoA
漫游后 APP 要改地址 否 — 全程 运营商分配 → 系统绑定 → APP 直接用 → 漫游也不变

三句话精炼（可插总结）

  1. HoA 在首次在家乡网络入网时由运营商分配并写入网卡，卡不变则终身不变。
  2. 漫游只加底层 CoA，HoA 绑定与 APP 可见的本机地址都不变。
  3. 不是 APP 记地址，是系统网卡从第一次就固定了对外身份。

九、速记要点

# 要点
1 三大角色：MN（设备）、HA（注册+转接）、CoA（外地临时 IP，同一设备）
2 家乡地址永久不变，靠 隧道 + CoA 完成漫游转发
3 底层逻辑：间接寻址（indirection）
4 现代：LTE / PMIPv6 演进；HA/锚点多为区域/运营商级，非一用户一台
易错 正确
CoA 是对外通信地址 对外仍是家乡地址；CoA 仅当前位置（在家无 CoA）
在家也用隧道 仅在外地注册 CoA 后才走 HA 隧道；在家直连
HA 只是注册中心 注册 + 转接：靠 CoA 映射隧道转发，外部仍用家乡地址寻址
HA 转发所有回程流量 回程常可直连；入向才经 HA 隧道转接
手机 4G/5G = 传统 Mobile IP 多为 LTE/PMIPv6 等，概念相通实现不同
出省上网加漫游流量费 现行全国通用流量统一扣费，无额外漫游费（见 §七 蜂窝实例）
APP 漫游后要换本机 IP 系统网卡首次在家绑定 HoA；APP 永远拿 HoA，CoA 对 APP 不可见 → §八
住宅 IP = 移动 IP 家乡地址 无关 — 住宅 IP=家宽公网类型；HoA=协议逻辑身份 → §零

疑问与总结

背：MN+HA+CoA；家乡地址不变；HA 隧道到 CoA；indirection。

5.6

IP 数据报的主机处理

章级精读：study.md#ch05-6 · 多网卡交付：ch04 §4.2 · IPv6 地址：ch02 · 安全：5.7

本节核心目标

掌握 强/弱主机模型（RFC 1122）对多网卡/VPN/环回收发的影响，以及 IPv6 源/目的地址选择（RFC 6724）的优先级规则与开发绑定要点。

一、强主机 vs 弱主机模型（RFC 1122，IPv4/IPv6 通用）

核心差异：接收/发送是否绑定接口 — 直接决定多网卡、VPN、环回场景的包收发规则。

1. 强主机模型（Strong Host）

规则 说明
接收 仅当 目的 IP = 接收接口的地址 时，才接收该包
发送 仅当 源 IP = 出站接口的地址 时，才允许从该接口发包
特点 接口隔离、安全性高；多网卡/VPN 需严格匹配接口与 IP
典型系统 Windows Vista+、Linux、所有 IPv6 栈默认

2. 弱主机模型（Weak Host）

规则 说明
接收 只要 目的 IP 属于本机任一接口，无论从哪个接口收到都接收
发送 源 IP 可与出站接口 IP 不同，仅需 属于本机
特点 连通性好、配置简单；易受多宿主欺骗（外网口收到内网目的 IP 的包）
典型系统 Windows XP、Windows Server 2003（IPv4 默认）

3. 对比表（必考）

维度 强主机 弱主机
接收条件 目的 IP = 接收接口 IP 目的 IP ∈ 本机所有接口 IP
发送条件 源 IP = 出站接口 IP 源 IP ∈ 本机所有接口 IP
安全性 高（接口隔离） 低（易被欺骗）
连通性 一般（需匹配接口） 好（跨接口通）
默认系统 Win7+ / Linux / IPv6 Win XP/2003（IPv4）

4. 场景影响（多网卡 / VPN / 环回）

场景 强主机 弱主机
多网卡 eth0 的 IP 包只能从 eth0 收 可从任意接口收
VPN 须 VPN 接口 IP 匹配目的 IP 才收 可能导致流量泄露到错误接口
环回 通常仅 lo 收 127.0.0.1 物理接口也可能收（异常路径）

二、IPv6 地址选择（RFC 6724）

IPv6 主机常有多地址（全球 / ULA / 链路本地）、多前缀；出站时内核自动选源 IP + 目的 IP。开发跨接口服务需显式绑定或策略路由。

1. 核心目标

  • 多地址/多前缀下选最优源/目的 IP（范围、隐私、前缀匹配）
  • 避免内核自动选错源（如用链路本地访问全球网络）

2. 源地址选择规则（按优先级，必考）

# 规则
1 同地址优先：候选源 IP = 目的 IP → 直接选中
2 匹配范围：源 IP 范围 ≥ 目的 IP 范围（链路本地→全球，不能跨范围）
3 避免废弃地址：优先首选生命周期 > 0；不选 Deprecated
4 移动 IPv6 主地址：优先 Home Address（固定网络几乎不用）
5 优先出站接口：优先路由选出站接口上的地址
6 匹配标签：源/目的 addrlabel 一致（策略路由常用）
7 优先临时地址：优先 RFC 4941 隐私临时地址（防溯源）
8 最长前缀匹配：与目的 IP 前缀匹配最长的源 IP

3. 目的地址选择（RFC 6724 补充）

优先：可用 + 匹配范围 + 非废弃 + 本地前缀 + 原生 IPv6；避免 6to4 / Teredo 等隧道地址（若存在更优候选）。

三、开发 / 运维要点（Go / Rust / 跨接口服务）

要点 做法
多接口必显式绑定 Go：net.Dialer.LocalAddr；Rust：SocketAddr 指定源 IP/接口
策略路由兜底 多 VPN/多专线：ip rule / iptables 锁定出站接口
IPv4 收紧入站 Win：netsh interface ipv4 set interface …；Linux：rp_filter、相关 sysctl（与接口绑定策略配合）

→ 发送路径排障：ip route get <dst> · ip -6 route get <dst>

四、考点速记

# 要点
1 强主机：接口绑定收发，安全；弱主机：本机全局收发，连通性好
2 IPv6 默认强主机；RFC 6724 定义 8 条源地址选择规则
3 多网卡/VPN：强主机须 接口–IP 严格匹配，否则丢包
4 跨接口服务：必须显式指定源 IP / 出站接口
易错 正确
Linux 默认弱主机 Linux / Win7+ / IPv6 默认强主机
多地址 IPv6 内核总选对 须理解 RFC 6724 或 bind
弱主机更安全 强主机更安全；弱主机易跨接口欺骗

Go / Rust

  • Go：net.InterfaceAddrs 列接口；Dialer{LocalAddr: &net.TCPAddr{IP: src}} 绑源
  • Rust：socket2 / std::net + bind 到具体 SocketAddr；容器多网卡注意 policy routing
  • 实践：ip route get 验证内核选的源与出接口是否与预期一致

疑问与总结

背：强=接口绑定（默认现代栈）；弱=本机任一接口；IPv6 出站看 RFC 6724 八条 + 开发必 bind。

5.7

与 IP 相关的攻击

章级精读：study.md#ch05-7 · IP 欺骗详读：ch02 §2.8 · ARP 联动：ch04 §4.11 · PMTUD：ch03 §3.8 · 分片：ch10

本节核心目标

认识 IP 欺骗 与 IP 分片攻击 的原理、危害与防护，理解 IP 层无身份认证的本质及与上层/运维安全的关系。

一、IP 欺骗（IP Spoofing）

原理

IP 头部 源地址字段可随意伪造 — 协议本身无身份校验机制（设计于互信环境）。

攻击者 1.1.1.1 --(源 IP 伪造为 2.2.2.2)--> 服务器/防火墙 --> 受害者
接收方误以为来自 2.2.2.2，可能开放基于 IP 的信任

危害

# 危害
1 绕过基于 IP 白名单 / IP 信任 的访问控制
2 构造 反射式 DDoS：伪造受害者 IP 向服务器发包 → 应答流量全部涌向受害者

→ 反射/放大 DDoS 与 UDP/DNS/NTP 等：ch10 §安全

主流防护

方案 说明
BCP 38 运营商/边界执行入站路由过滤 — 丢弃源地址不属于该入接口合法网段的报文
uRPF（单播反向路径转发） 校验源 IP 反向路由是否存在且与入接口一致；不存在则丢弃

uRPF 模式

模式 行为
严格（Strict） 源 IP 必须精确匹配入接口所在子网
松散（Loose） 只要路由表中存在到源 IP 的路由即可

→ 详读：ch02 §2.8 防护 · ch01 架构威胁

二、IP 分片攻击

原理

利用 畸形分片、分片重叠、超长分片，使目标主机重组时出现解析异常 → 内存溢出、系统崩溃。

类型 说明
重叠分片 经典 Teardrop 攻击 — 片偏移重叠，旧栈重组崩溃
永不完成的片 占满重装缓冲，耗尽内存 / nf_conntrack
过小/异常片 边界过滤对象

→ ch10 Teardrop 变体 · IPv6 仅源分片：5.3

现状与防护

层 措施
协议栈 现代 OS 已加固重组逻辑，原生 Teardrop 类风险大幅降低
边界运维 限制异常分片 — 拦截过小/畸形/重叠分片
减少分片 启用 PMTUD（路径 MTU 发现） — DF=1 + ICMP PTB → 源端控制包长 → ch03 §PMTUD

三、核心安全原则

IP 协议设计之初不具备身份认证、加密能力，仅负责寻址与转发。

层次 手段
上层协议 TLS（传输/应用）、IPsec（网络层 ESP/AH → ch18）
网络运维 BCP 38、uRPF、分片管控、ICMP 策略（勿拦 PTB）
应用设计 不依赖源 IP 作为身份；令牌 / 证书认证

四、与链路层 ARP 欺骗的联动

层 攻击 组合效果
L2 ARP 欺骗 伪造 MAC ↔ IP 映射 同广播域 MITM → ch04 §4.11
L3 IP 欺骗 伪造源 IP 越权、反射 DDoS
L2 + L3 ARP 劫持 + IP 伪造 更强的窃听/篡改/放大攻击面

一句：防火墙（L3）拦不住 ARP（L2）；IP 层也不验源 — 需分层防御。

五、考点速记

# 要点
1 IP 欺骗：伪造源 IP → 越权访问、反射 DDoS；防护：BCP 38、uRPF
2 分片攻击：畸形/重叠分片 → 重组漏洞；代表 Teardrop；防护：边界控分片、PMTUD
3 本质：IP 层无安全校验 → 靠 TLS/IPsec + 网络策略
4 联动：常与 ARP 欺骗（ch04）组合，二层+三层伪造
易错 正确
防火墙能防 IP 欺骗 需边界入站过滤（BCP38/uRPF）；内网仍可能伪造
Teardrop 现代仍高危 栈已加固；边界仍应滤异常分片
拦 ICMP 更安全 误拦 PTB → PMTUD 黑洞、大包卡死

疑问与总结

背：源 IP 可伪造（BCP38/uRPF）；分片畸形（Teardrop/滤片/PMTUD）；IP 无身份 → TLS + 不信 IP。
