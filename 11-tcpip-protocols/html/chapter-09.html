9.1

引言：单播 / 广播 / 组播

章级精读：study.md#ch09-1 · 广播详：9.2 · 组播地址/MAC：9.3 · IGMP Snooping：9.4

本节核心目标

区分 单播 / 广播 / 组播 的定义、局域网内本质差异与本地链路范围 — 澄清「LAN 里看起来一样」的误区。

核心结论：局域网二层环境下观感可能相似，但本质、机制、使用场景完全不同 — 并非没有区别。

一、基础定义

1. 广播（Broadcast）

项 说明
IPv4 主机位全 1（如 192.168.1.255）或 255.255.255.255 受限广播
语义 一对全体 — 本子网所有主机
二层 MAC FF:FF:FF:FF:FF:FF
规则 本网段所有主机网卡都会接收、上送协议栈 — 无法选择性拒绝
路由 路由器默认不转发

→ 详：9.2 广播

2. 组播（Multicast）

项 说明
IPv4 224.0.0.0/4（224～239）
语义 一对多（指定群体）
二层 MAC 组播 MAC，IPv4 映射前缀 01:00:5E
规则 只有加入对应组播组的主机才接收；未加入者网卡/栈可直接丢弃
路由 224.0.0.0/24 不跨路由；其余段可配 PIM 跨网段 → 9.3 §传播

3. 单播（对照）

模式 语义 典型范围
单播 一对一 全球路由
广播 一对子网内全部 不跨路由器
组播 一对订阅组 LAN + 可控域；Internet 组播另论

二、局域网内核心区别（重点）

1. 接收对象不同（最关键）

广播 组播
发给谁 网段内所有设备 — 不管需不需要 主动加入该组的设备
无关设备 也要收帧、上送协议栈处理 底层直接过滤，开销极小
例 ARP、DHCP Discover — 全网收到 视频流、服务发现 — 仅订阅者

2. 底层 MAC 与过滤机制不同

广播 组播
MAC 固定 FF:FF:FF:FF:FF:FF 01:00:5E + 映射
交换机 泛洪到所有端口 IGMP Snooping 可只转发到有成员的端口 → 9.4 加组/IGMP

3. 设计初衷不同

广播 组播
用途 地址解析、初始发现（尚无 IP/未建立通信）— 兜底 一对多数据流（直播、监控、路由同步）— 批量分发
典型 ARP、DHCP、NetBIOS OSPF 组播、IPTV、视频会议

4. 扩展能力不同

广播 组播
跨网段 永远无法（路由器隔离） 配置 IGMP + PIM 等可跨路由器
链路本地 限本网段 224.0.0.0/24 同样限本网段，与广播「范围感」相近

三、误区：「局域网里看起来没区别」

为何观感相似？

场景 说明
① 低端交换机无 IGMP Snooping 组播帧被像广播一样泛洪到所有端口 → 行为表现一致，协议本质未变
② 链路本地组播 224.0.0.0/24 路由器不转发，与广播一样限本网段 → 加深「差不多」错觉

处理逻辑仍不同（考点）

广播 组播
未订阅设备 系统层都要解析报文（至少到 L3/L4 判丢弃） 没加组的主机，网卡/驱动可硬件丢包，CPU 不参与

一句：交换机泛洪是实现偷懒；广播 vs 组播的语义与主机处理路径仍然不同。

四、极简对比总结

特性 广播 组播
通信模型 一对全部 一对指定群组
接收权限 强制接收，无法拒绝 主动加组才接收
跨路由 不支持 配置组播路由可支持
设备开销 高 — 全网都要处理 低 — 仅组成员
典型用途 ARP、DHCP、全网通知 视频流、路由协议、群组数据

五、为何强调「本地」

  • 广播/无控组播若全球转发 → 风暴、路由器状态爆炸。
  • 本章聚焦 LAN 上的 IGMP/MLD + 交换机行为。

→ 地址段：ch02 §2.5

考点速记

# 要点
1 LAN 里观感可似，本质不同 — 广播=全员；组播=订户
2 广播 MAC FF:FF… 泛洪；组播 01:00:5E + Join/IGMP
3 无 Snooping 时组播表现像广播，但未加组可硬件丢
4 广播永不跨路由；组播可配 PIM 跨网
5 广播=发现兜底；组播=一对多流
易错 正确
局域网广播组播没区别 接收对象、MAC、跨路由、CPU 开销均不同
组播一定比广播省交换机带宽 无 IGMP Snooping 时交换机仍可能泛洪
组播和广播都不能跨路由 组播可（非 224.0.0/24 + PIM）；广播永远不能

疑问与总结

背：广播=全员强制收；组播=加组才收；无 Snooping 表现像广播但主机逻辑不同；广播不跨路由，组播可跨。

9.2

广播（Broadcast）

章级精读：study.md#ch09-2 · 单播/组播/MAC 映射：9.3 · Smurf：ch08 §8.7 · DHCP/ARP：ch06 §6.2 · ND 组播：ch08 §8.5

本节核心目标

掌握 IPv4 受限广播 vs 定向广播 的区别与转发规则；理解 IPv6 无广播、用组播替代 的设计原因与典型地址。

一、IPv4 广播类型

1. 受限广播（Limited Broadcast）

项 说明
地址 255.255.255.255
范围 仅本地链路（LAN）；路由器永不转发
用途 主机启动时未知自身 IP/掩码 → DHCP Discover、ARP 请求
二层 目的 MAC = FF:FF:FF:FF:FF:FF；交换机泛洪到所有端口 
DHCP Discover / ARP Request → 255.255.255.255 → 不跨路由 → 本网所有主机收到

→ ch06 DORA · ch04 ARP

2. 定向广播（Directed Broadcast）

项 说明
地址 网络前缀 + 主机位全 1（如 192.168.1.255/24）
计算 定向广播 = IP \| (~subnet_mask)
范围 特定子网；现代路由器默认丢弃（防 Smurf 攻击）
用途 早期跨子网管理、远程唤醒（WOL）；现网极少用

例：192.168.1.100/24 → 定向广播 192.168.1.255

→ Smurf：ch08 §8.7

3. 对比表

特性 受限广播 定向广播
地址 255.255.255.255 子网主机位全 1（如 192.168.1.255）
转发 不跨路由器 默认不转发（可配置开启，现网禁）
典型场景 DHCP、ARP 传统子网广播（已淘汰）
安全风险 低（本地） 高（易被放大攻击）
二层 MAC FF:FF:FF:FF:FF:FF 通常同为 FF:FF:FF:FF:FF:FF

二、广播的影响

影响 说明
二层泛洪 所有端口收到 → 所有主机必须接收并处理（至少到 L3 判丢弃）
资源浪费 无关主机也耗 CPU 与带宽
广播风暴 环路/异常流量 → 全网瘫痪；网络越大越严重
典型依赖 DHCP、ARP、NetBIOS 等

一句：广播的代价是「子网内每台机器都要碰一下」— 组播用过滤把成本压到订户 → 9.3

三、IPv6：无广播，用组播替代

1. 核心设计

项 说明
取消广播 避免「无差别全网推送」的低效与风险
组播替代 前缀 FF00::/8
原理 只对感兴趣的节点发送 — 非组成员不处理

2. 关键组播地址（链路本地 FF02::/16）

地址 作用
FF02::1 所有节点 — 替代 IPv4 子网广播
FF02::2 所有路由器
FF02::1:FFXX:XXXX 请求节点组播（Solicited-Node）— 替代 ARP

3. 替代逻辑

IPv4 IPv6
子网广播 FF02::1 等特定组播
ARP 广播 NS + Solicited-Node 组播

→ ND/MLD：ch08 §8.5 · ch02 IPv6

四、考点 / 面试速记

# 要点
1 受限广播：255.255.255.255，不路由，用于 DHCP/ARP
2 定向广播：主机位全 1，默认丢弃，防 Smurf
3 IPv6 无广播 → FF02::1 等组播替代
4 广播危害：泛洪 → CPU 浪费 → 风暴；IPv6 组播更高效
易错 正确
定向广播可随意跨网转发 现代默认禁止转发
IPv6 有 255.255.255.255 等价物 无广播；用 FF02::/16 链路组播
广播 MAC 随 directed/limited 变化 以太网目的 MAC 均为 FF:FF:FF:FF:FF:FF
组播 = 广播的 IPv6 版 组播是按需订阅，非全员洪泛

Lab

# 受限广播（需 OS 允许）
ping 255.255.255.255

# 定向广播（现代 OS/路由常拒）
ping 192.168.1.255

# IPv6 全体节点（替代广播 ping）
ping ff02::1%eth0   # Linux 需指定接口

疑问与总结

背：255.255.255.255 不路由→DHCP/ARP；x.x.x.255 定向默认禁；v6 无广播→FF02::1；广播=全员泛洪。

9.3

组播：MAC 与 IPv4 单播/组播/广播

章级精读：../study.md#ch09-3 · IPv4 特殊地址：ch02 §2.5 · PAUSE 二层组播（与 IP 无关）：3.3 §五 · UDP 绑定：ch10

本节核心目标

分清 MAC 层 与 IPv4 层 的单播/组播/广播判定规则；理解二者不是一一绑定，以及 IPv4 组播 → MAC 组播 的标准映射；区分 IP 组播 MAC 与 纯二层控制帧 MAC（如 PAUSE）。

名词：单播、组播、广播（不用「主播」）。

一、MAC 地址（48 bit，二层）

1）单播 / 组播：只看首字节最低位

MAC 格式：字节1 : 字节2 : 字节3 : 字节4 : 字节5 : 字节6

规则 判定
第 1 字节最低位（bit 0）= 0 MAC 单播（唯一设备）
第 1 字节最低位 = 1 MAC 组播（一组设备）

例子

  • 单播：00:1a:2b:3c:4d:5e → 首字节 00 = 00000000，末位 0
  • 组播：01:80:C2:00:00:01（PAUSE）→ 首字节 01 = 00000001，末位 1

2）MAC 广播

固定 FF:FF:FF:FF:FF:FF，视为特殊组播，本网段所有端口都会处理。

3）MAC 6 字节怎么理解

部分 位数 作用
前 3 字节（OUI） 24 bit 厂商编号，出厂固化
后 3 字节 24 bit 厂商自定义，全球唯一单播 MAC

单播/组播标识只在第 1 字节最低 1 bit，与 OUI、后 3 字节无关。

背一句：MAC 只靠首字节末位分单播/组播；广播 = 全 F。

二、IPv4 地址（32 bit，三层）

分网络位 + 主机位；判定靠地址段、主机位取值，与 MAC 完全不同。

1）IPv4 组播（D 类）

范围：224.0.0.0 ~ 239.255.255.255（224.0.0.0/4）

用途：一对多（视频、路由协议、设备发现等）→ 2.5 特殊地址

核心结论：224.0.0.0～239.255.255.255 是 IPv4 组播地址段；大部分默认仅在局域网传播，只有特定范围 + 组播路由（PIM 等） 配置后才可跨网段/公网。

2）分段划分 & 传播范围

IPv4 组播整体 224.0.0.0/4，按用途与路由规则分三类：

① 本地链路组播 224.0.0.0 ~ 224.0.0.255（224.0.0.0/24）

项 说明
规则 路由器一律不转发 — 严格限制在当前局域网（二层网段）
用途 邻居发现、路由协议、局域网设备交互
典型地址 224.0.0.1 所有组播主机 · 224.0.0.2 所有组播路由器 · 224.0.0.5/6 OSPF
场景 同网段设备能收到；跨路由器直接阻断 
ping 224.0.0.1 → 同交换机/Wi‑Fi 能收到 → 经路由器到另一网段 → 收不到

② 全网组播 224.0.1.0 ~ 224.0.1.255

项 说明
规则 默认允许路由器转发，可跨网段、跨公网传播
用途 互联网全局服务、公共设备发现

③ 机构/私有组播 224.0.2.0 ~ 239.255.255.255

子段 规则
224.0.2.0 ~ 238.255.255.255 通用组播 — 须网络设备开启 PIM 等组播路由 才能跨网段；家用/普通企业路由默认不转发，仅局域网内生效
239.0.0.0 ~ 239.255.255.255 管理/本地组播（admin-scope） — 类比私网 IP，禁止公网路由，仅企业/园区/局域网内部

3）单播 / 广播 / 组播 传播对比

类型 跨路由行为（默认）
单播 一对一，正常跨路由全网转发
广播 255.255.255.255 等 — 路由器不转发，限局域网 → 9.2
组播 224.0.0.0/24 天生不跨路由；其余段依赖 PIM 等配置

4）日常场景总结

# 要点
1 家用/普通局域网：未配组播路由 → 组播基本只在当前 LAN 内
2 运营商/大型专网手动开启组播路由后，部分地址段才可跨网段
3 239.x 仅组织内；224.0.0.x 仅链路本地

→ IGMP/PIM：9.4 · study §9.4

5）IPv4 广播

核心：主机位全部置 1

类型 规则 例
子网广播（常用） 本网段主机位全 1 192.168.1.0/24 → 192.168.1.255
有限广播 固定 255.255.255.255（通常不路由，限本网）

6）IPv4 单播

除组播、广播、网络号、保留地址外，常规主机地址；主机位不能全 0 或全 1（子网内）。

三、MAC 组播 与 IPv4 组播：一一对应吗？

结论

不是自由一一绑定，而是三层包封装进二层帧的承载关系：

  1. 上层发 IPv4 组播包 → 下层须封装为 MAC 组播帧 才能在以太网上传；
  2. 一个 IPv4 组播地址按 IANA 规则映射到 固定前缀的 MAC 组播，不是任意配对。

标准映射（必背）

项 值
IPv4 组播段 224.0.0.0/4
以太网 MAC 组播前缀 01:00:5E（IANA）
映射 取 IPv4 的低 23 bit，填入 MAC 后 23 bit

例：224.0.0.1

IPv4:  11100000.00000000.00000000.00000001
       └─ D类 ─┘
取低 23 bit: 0000000 00000000 00000001
MAC:   01:00:5E : 00 : 00 : 01  →  01:00:5E:00:00:01

碰撞：32 个不同 IPv4 组播 IP 可能映射到同一 MAC → 网卡/驱动可能收到未订阅组，靠 IGMP + 套接字 Join 在三层丢弃 → 见下文「三层过滤」。 → 交换机转发全流程：9.7 §IP→MAC 流程

与 PAUSE 等二层组播的区别

MAC 组播地址 归属
01:00:5E:xx:xx:xx IPv4 组播 IP 映射（承载三层组播包）
01:80:C2:00:00:01 802.3x PAUSE，纯二层控制，与 IP 组播无关
FF:FF:FF:FF:FF:FF 广播

四、判定规则对比表

维度 MAC（二层 48 bit） IPv4（三层 32 bit）
单播 首字节最低位 = 0 常规地址；主机位不全 0 / 不全 1
组播 首字节最低位 = 1 224.0.0.0 ~ 239.255.255.255
广播 固定 FF:FF:FF:FF:FF:FF 子网主机位全 1 / 255.255.255.255
区分方式 单个比特位 整段范围 + 主机位
关系 硬件按 MAC 转发/过滤 路由、IGMP、套接字按 IP 处理

五、三层过滤（组播收包）

1. 网卡硬件过滤器（按 MAC 粗筛，不完美）
2. 驱动
3. IP / 套接字 — JoinGroup 后丢弃未订阅的组播包
坑 说明
32→1 MAC 碰撞 收到未订阅 IP 的组播帧
多网卡 JoinMulticast 须指定 Interface
未 Join 收不到；Join 错网卡 → IGMP Report 发错口

→ Go/Rust：JoinMulticast / join_multicast_v4

六、考点：组播地址段与传播

# 要点
1 组播段：224.0.0.0/4（224～239）
2 224.0.0.0/24：不跨路由，OSPF/224.0.0.1 等
3 239.x：私有组播，不进公网
4 其余跨网段需 PIM；家用默认仅 LAN
5 vs 单播可全网 vs 广播不路由 vs 组播看段
易错 正确
所有组播都能跨公网 大部分默认仅局域网
224.0.0.1 能 ping 到别的网段 路由器不转发 /24 链路本地
239.x 与 224.0.0.x 一样 239=组织内私有；224.0.0.x=链路本地

七、IPv6（简述）

  • 组播前缀 ff00::/8；映射规则见 study.md §9.3。
  • 看不到 ARP/IPv4 组播时，找 ICMPv6 135/136（NDP）。

八、一句话总结

  1. MAC 靠首字节最低位分单播/组播；广播 = 全 F。
  2. IPv4 靠 224/4 分组播，靠主机位全 1 分子网广播。
  3. 规则独立；IP 组播包封装进 MAC 组播帧传输，按 01:00:5E + 低 23 bit 映射，非任意绑定。
  4. PAUSE 等 01:80:C2:… 是纯二层控制 MAC，与 IP 组播无关。

疑问与总结

  • ARP 请求用 广播 MAC + 目标 IP 单播/未知，不是组播映射。
  • 子网广播 IP 帧目的 MAC 常为 FF:FF:FF:FF:FF:FF。
  • 考试：先判 IP 是组播还是广播，再写 对应 MAC；PAUSE 只背 01:80:C2:00:00:01，不要和 01:00:5E 混。
9.4

IGMP 和 MLD：加入组播组与 Snooping

章级精读：study.md#ch09-4 · 广播 vs 组播：9.1 §LAN 区别 · 组播地址段：9.3 §传播 · UDP socket：ch10 · ND/MLD：ch08 §8.5

本节核心目标

一句：加入组播组 = 告诉系统/网卡「我要收这个组的流量」 — 底层靠 IGMP 跟路由器打招呼。

一、加入组播组原理

项 说明
组播地址 224.0.0.0 ~ 239.255.255.255
你要收某组（如 239.1.1.1） 见下三步 
① 应用/系统发 IGMP Join（Report）：「我要 239.1.1.1」
② 路由器记录：该端口有人要这个组
③ 发往 239.1.1.1 的流量 → 只转给加了组的主机

与广播的区别

广播 组播
接收 强制所有人收，不管要不要 只有主动加入的才收
过滤 网卡/栈都要处理 未加组者网卡底层过滤，不占 CPU

→ 9.1 广播 vs 组播

地址段回顾

段 说明
224.0.0.0/24 链路本地，路由器不转发，仅 LAN — 类似广播但可 selective join
239.0.0.0/8 私有组播，企业/局域网内，公网不路由

二、Windows 命令行加入（临时，测试）

管理员 cmd：

:: 1. 看网卡名
netsh interface ipv4 show interfaces

:: 2. 加入组（网卡名按实际改：以太网 / Ethernet / Wi-Fi）
netsh interface ipv4 add joinmulticastgroup name="以太网" group=239.1.1.1

:: 3. 查看已加入的组
netsh interface ipv4 show joins

:: 4. 退出组
netsh interface ipv4 delete joinmulticastgroup name="以太网" group=239.1.1.1

三、Linux 命令行加入（临时）

# 1. 看网卡
ip a    # eth0 / enp0s3 等

# 2. 确保组播开启（默认通常已开）
sudo ip link set eth0 multicast on

# 3. 加入组
sudo ip maddr add 239.1.1.1 dev eth0

# 4. 查看
ip maddr show dev eth0

# 5. 退出组
sudo ip maddr del 239.1.1.1 dev eth0

四、程序里怎么加（实际工作）

Python / C++ / Java / Go / Rust 本质相同：

  1. 创建 UDP socket
  2. setsockopt：IP_ADD_MEMBERSHIP（指定组播 IP + 网卡）
  3. 内核自动发 IGMP Report 给路由器

Python 极简例子

import socket

mc_ip = "239.1.1.1"
mc_port = 1234

s = socket.socket(socket.AF_INET, socket.SOCK_DGRAM)
s.bind(("", mc_port))

# 加入组播组（0.0.0.0 = 默认网卡；生产环境指定本机接口 IP）
mreq = socket.inet_aton(mc_ip) + socket.inet_aton("0.0.0.0")
s.setsockopt(socket.IPPROTO_IP, socket.IP_ADD_MEMBERSHIP, mreq)

# 收包 ...
# 离开：IP_DROP_MEMBERSHIP（同 mreq 结构）
选项 作用
IP_ADD_MEMBERSHIP 加入组 → 触发 IGMP Join
IP_DROP_MEMBERSHIP 离开组
IP_MULTICAST_IF 指定从哪块网卡发/收组播

→ 详：ch10 UDP 组播

五、IGMP (IPv4) / MLD (IPv6) 报文

报文 方向 作用
Report（Join） 主机 → 路由器 加入组播组
Query 路由器 → 子网 还有谁在看？刷新软状态
Leave（v2+） 主机 → 路由器 快速离组（v2）
  • 路由器维护组播转发表（软状态）；超时无 Report → 停止向 LAN 转发该组。

六、版本要点

版本 进步
v1/v2 加入/离开、报告抑制
IGMPv3 / MLDv2 SSM：订阅 (S,G) 特定源，更安全

七、IGMP Snooping（交换机）

项 说明
作用 交换机偷听 IGMP → 只向有订阅者的端口转发组播
无 Snooping 组播可能被当广播泛洪 → 9.1 §误区 · 9.7 交换机分工

八、实战：「别人收得到我收不到」

# 排查
1 未 Join / 未 IP_ADD_MEMBERSHIP
2 未指定网卡 Join 组播
3 未响应 Query → 几分钟后被 Snooping 掐流
4 Wi‑Fi/AP 未透传组播

定期 Report 或由栈自动响应 Query。

考点速记

# 要点
1 加组 = IGMP Join/Report；内核 IP_ADD_MEMBERSHIP
2 路由器靠 Report 建软状态；Query 刷新
3 Snooping = 交换机按 IGMP 精准转发
4 无 Join 不收；广播强制全员收
5 239.x 私有；224.0.0/24 链路本地不跨路由
易错 正确
绑 UDP 端口就能收组播 须 IP_ADD_MEMBERSHIP 触发 IGMP
加组 = 改 IP 地址 加组是订阅，不改变主机单播 IP
Linux ip maddr add 永久生效 临时；程序退出或 del 即离组

疑问与总结

背：加组=IGMP Join；Win netsh / Linux ip maddr / 程序 IP_ADD_MEMBERSHIP；Snooping 精准转发；没加组不收。

9.7

实战：交换机、路由器与组播转发

章级精读：study.md#ch09-7 · 广播 vs 组播：9.1 · 组播 IP→MAC：9.3 §映射 · 加组/IGMP：9.4 · 交换机：ch03 §3.4

本节核心目标

结合二层交换机、三层路由器、IGMP、组播 MAC/IP，理清 LAN 内组播谁记录、谁转发、谁收包 — 纠正「组播=广播」「交换机认 IP」等混淆。

一、局域网里：交换机 vs 路由器（网关）

1. 核心分工

设备 层次 认什么 作用
交换机 二层（数据链路层） MAC 地址 同网段内转发；不路由、不跨网段
路由器（网关） 三层（网络层） IP 地址 跨网段、跨 LAN 路由转发

→ 硬件/MAC表/路由表/交换矩阵：ch03 §3.12

同网段 A ↔ B     → 全程交换机（MAC 转发），不经网关
A → 其他网段/外网 → 包发给网关（路由器），由路由器按 IP 路由

一句：同局域网靠交换机，跨网关/跨网段靠路由器 ✅

补充 说明
三层交换机 二层交换 + 三层路由；内网不同 VLAN/网段可不经外接路由器，分工逻辑不变

2. 广播与交换机

收到广播帧（MAC FF:FF:FF:FF:FF:FF）→ 交换机默认转发到所有端口 → 局域网广播泛滥。

→ 9.2 广播

二、组播：设备怎么记录？交换机有没有对应功能？

1. 两个关键协议/技术

技术 运行位置 作用
IGMP 主机 ↔ 路由器/三层设备 主机报告 加入/退出 组播组；三层设备记录：哪个网段有哪些主机订阅哪个组播 IP
IGMP Snooping 二层交换机 交换机不认 IP，偷听 IGMP → 建 组播地址 → 端口 表 
IGMP：三层维护「谁要哪个组播 IP」（软状态）
Snooping：二层根据偷听到的 IGMP，维护「组播流量走哪些端口」

→ 加组命令/API：9.4 §加入组播

2. 两种交换机，行为完全不同

情况 1：傻瓜交换机（无 IGMP Snooping）

项 行为
能力 只认 MAC，不懂 IGMP
组播帧 与广播帧一样 → 全端口泛洪
主机端 未加组的主机：网卡硬件丢弃，不上 CPU — 与广播不同

情况 2：网管型交换机（开启 IGMP Snooping）

步骤 行为
① 主机发 IGMP Join → 交换机侦听
② 记录：该组播组 = 接收 Join 的端口
③ 后续组播流量 → 只转发到已记录端口，不全网泛洪

结论：交换机靠 IGMP Snooping 管理组播转发；订阅信息源头由路由器/三层设备通过 IGMP 维护。

→ 9.1 §误区：看起来没区别

三、组播 IP 与组播 MAC 的对应关系

1. 固定映射规则

项 值
组播 IP 224.0.0.0/4
组播 MAC 前缀 01:00:5E（IANA）
规则 MAC 前 24 bit 固定 01:00:5E；后 23 bit = 组播 IP 的后 23 bit

例：组播 IP 224.0.0.1 → MAC 01:00:5E:00:00:01

→ 详算、32:1 碰撞：9.3 §映射

2. 完整转发流程

① 发送方：目的 IP = 224.x.x.x；目的 MAC = 01:00:5E:xx:xx:xx（按规则计算）

② 交换机（看二层 MAC）：
   - 识别组播帧
   - 有 Snooping → 查组播表，只转对应端口
   - 无 Snooping → 当广播，全端口泛洪

③ 接收主机：
   - 网卡看目的 MAC = 组播 MAC
   - 已 Join 该组 → 上交协议栈
   - 未 Join → 网卡丢弃，系统无感知

3. 纠正误区

误区 正确
看到 224 IP 就变成广播 IP 是 L3 标识；MAC 是 L2 标识 — 交换机只看 MAC 决定洪泛/精准转发
组播在 LAN 里一定像广播 仅无 Snooping 的傻瓜交换机才泛洪；有 Snooping 则精准转发

四、整体串讲总结

# 要点
1 同 LAN → 交换机（MAC）；跨网段 → 路由器/网关（IP）
2 IGMP：主机 ↔ 三层，记录谁订阅哪个组播 IP
3 IGMP Snooping：二层偷听 IGMP，组播 → 端口 精准转发
4 224/x → 01:00:5E + IP 低 23 bit；主机加组才收
5 傻瓜交换机组播表现像广播；协议与主机处理逻辑仍不同

考点速记

易错 正确
交换机认 IP 做组播转发 交换机认 MAC；组播精准靠 IGMP Snooping
IGMP 跑在交换机上 IGMP = 主机↔三层；Snooping = 二层侦听
组播 IP 直接当广播 MAC IP 224/4 → MAC 01:00:5E + 映射
同网段要经过网关 同网段直连，不经网关

疑问与总结

背：同网段交换机MAC转发；跨网段走路由；IGMP三层记订阅、Snooping二层定端口；224→01:00:5E；加组才收。
