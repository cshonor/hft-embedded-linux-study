2.1

引言

章级精读：../study.md#ch02-1 · 上一章：ch01

本节核心目标

理解 IP 地址在网络层的寻址与路由识别角色，以及与链路层 MAC 的分工。

核心要点

  • IP 地址标识流量的来源与去向，支撑全球可扩展路由。
  • 与 MAC：L2 相邻交付 vs L3 端到端逻辑标识（见 ch04 ARP）。
  • 全球分配需 IANA → RIR → ISP/组织 协调，避免重复分配导致不可路由冲突。

易混

  • IP 给接口，不是给“整机一张卡”的抽象机器；多网卡 = 多个 IP。
  • DNS 名 是应用层便利，协议栈转发看的是 数字 IP。
2.2

表示 IP 地址

章级精读：../study.md#ch02-2

本节核心目标

掌握 IPv4 / IPv6 的书写规范与常见表示陷阱。

IPv4：点分四组（极简）

IPv4 地址 = 32 位二进制 = 4 字节 = 点分十进制（四段）

要点 说明
总长度 32 bit
分组 4 段，每段 8 bit = 1 字节
写法 每段转十进制 0–255，用 . 隔开
例子 165.195.130.107

二进制 ↔ 点分（以 192.168.1.1 为例）

32 位：11000000 10101000 00000001 00000001
4×8： 11000000 . 10101000 . 00000001 . 00000001
十进制：192 . 168 . 1 . 1

为什么每段是 0–255？

  • 8 位最大 11111111 → 255；最小 00000000 → 0
  • 任一段 > 255 的 IPv4 都非法（如 256.x.x.x、192.168.1.300）

一句话：32 位分 4 段，每段 8 位 0–255，点分隔 → 点分十进制。

→ 与 自顶向下 §4.3 · UNP 3.2 地址结构（in_addr 存这 32 位，网络字节序）

练习（先自己做，再对答案）

题 1 · 二进制 → 点分

把下面 32 位写成点分十进制：

10101100 . 00011111 . 00111000 . 11000011

答案

172.31.56.195

（10101100=172，00011111=31，00111000=56，11000011=195）

题 2 · 点分 → 二进制（写每段 8 位即可）

10.0.0.1 对应的 4 段二进制是？

答案 
00001010 . 00000000 . 00000000 . 00000001

题 3 · 判断合法 IPv4（对 / 错）

地址 合法？
192.168.0.1
300.1.1.1
192.168.1
0.0.0.0
答案
地址 合法？ 原因
192.168.0.1 ✅ 四段，每段 ≤255
300.1.1.1 ❌ 300 > 255
192.168.1 ❌ 只有 3 段，缺一字节
0.0.0.0 ✅ 全 0 合法（常表示「本机/未指定」语义，见 2.5）

IPv6：块/字段（极简）

要点 说明
总长 128 bit
分块 8 块（字段）× 16 bit
写法 8 组 4 位十六进制，用 : 分隔
展开例 2001:0db8:0000:0000:0001:0000:0000:0001

规则表（可直接背）

规则 说明 :: 次数
基本格式 128 bit → 8 组 16 bit 十六进制，: 分隔 —
前导零 每组开头的 0 可省，至少留 1 个字符（0db8→db8，0000→0） —
零压缩 连续一个或多个全 0 块用 :: 代替 ≤ 1
内嵌 IPv4 末 32 bit 写成 IPv4 点分，双栈过渡 —

两种简化（必考）

1）前导零省略（组内）

2001:0db8:0000:0000:0001:0000:0000:0001
→  2001:db8:0:0:1:0:0:1

2）零压缩 ::（整条地址只能用一次）

2001:db8:0:0:1:0:0:1
→  2001:db8::1:0:0:1
特殊地址 展开 压缩
未指定 0:0:0:0:0:0:0:0 ::
回环 0:0:0:0:0:0:0:1 ::1

为什么 :: 只能一次？ a::b::c 无法确定每个 :: 各补几个 0 块 → 歧义、非法。

内嵌 IPv4（过渡）

末 32 bit 可写成 IPv4 点分。最常见：IPv4-mapped

项 内容
格式 ::ffff:IPv4
结构 前 80 bit 为 0 + 16 bit ffff + 后 32 bit IPv4
例 ::ffff:192.0.2.1 ≡ 0000:…:0000:ffff:c000:0201（展开）

易混：IPv4 兼容 ::1.2.3.4 已废弃（RFC 4291）→ 用 映射 ::ffff:x.x.x.x。

一句话背诵

128 bit = 8×16 bit 十六进制块；前导零可省；全零块可压 :: 且 ≤1 次；末尾可写 ::ffff:IPv4。

/数字 = 前多少个二进制位（不是几段）。例：2000::/3 只看最左 3 bit → 2.7 示意图

→ 章级 RFC 5952：study.md §2.2 · §4.3 IPv6

IPv6 练习（完整 ↔ 压缩 ↔ 内嵌 IPv4）

题 1 · 展开 → 最简压缩

把下面地址写成最简合法形式（前导零 + 一次 ::）：

2001:0db8:0000:0000:0000:0000:0000:0001

答案

2001:db8::1

（中间连续 6 个全 0 块 → ::）

题 2 · 判断合法写法

地址 合法？
2001:db8::1
2001::db8::1
::1
::ffff:192.0.2.1
答案
地址 合法？ 原因
2001:db8::1 ✅ 仅一处 ::
2001::db8::1 ❌ 两处 ::
::1 ✅ 回环
::ffff:192.0.2.1 ✅ IPv4-mapped

题 3 · 内嵌 IPv4 → 写出映射形式

主机 IPv4 为 10.1.2.3，写成 IPv4-mapped IPv6 字符串。

答案

::ffff:10.1.2.3

题 4 · 还原块数（进阶）

fe80::1 展开后一共是几个 16 bit 块？（数清楚 :: 补了几个 0 块）

答案

8 块。fe80 + :: 补 6 个 0 块 + 1 → fe80:0:0:0:0:0:0:1。

易混考点

  • 把 IPv6 当“更长 IPv4”背十进制 — 考试/抓包以 十六进制块 为准。
  • :: 用两次 → 非法 表示。
2.3

基本的 IP 地址结构

章级精读：../study.md#ch02-3 · 2.4 CIDR · 2.2 表示法 精编：04 §4.3 有类/CIDR

本节核心目标

串起 分类寻址 → 子网/VLSM → CIDR → IPv6，并掌握 IPv4 广播 与 IPv6 IID（EUI-64）。

一、演进脉络（IPv4 → IPv6）

分类 A/B/C/D/E → 子网+掩码(FLSM) → VLSM → CIDR/聚合 → IPv6(128位,/64,IID,无广播)

1）分类寻址（Classful，RFC 791）

类 网络位 : 主机位 问题
A 8 : 24 主机位太多 → 严重浪费
B 16 : 16 B 类枯竭（ROAD 背景）
C 24 : 8 小网够用，大网不够
D 组播 —
E 保留 —

固定边界 → 路由表膨胀、分配不灵活。

2）子网 + 掩码（FLSM）

  • 从主机号借位划子网；掩码定网络/子网/主机边界。
  • 同一主网掩码固定（定长子网）。
  • 例：192.168.1.0/24，掩码 255.255.255.0 → 隔离广播域。

3）VLSM（可变长子网掩码）

  • 同一主网内不同前缀长度（CIDR 思想在子网内的应用）。
  • 例：点对点 /30（2 个可用地址）；大部门 /23（约 510 主机）。
  • 按需分配，减少浪费；需 OSPF/IS-IS/BGP 等无类路由协议。
FLSM VLSM
掩码 全网相同 各子网可不同
浪费 点对点也占 /24 等 可按需 /30、/31

4）CIDR（无类域间路由）

  • 抛弃 A/B/C 刚性类界；只用 前缀 + 主机位（a.b.c.d/x）。
  • 路由聚合（超网）：多条短前缀合并为更短一条 → 减核心路由表项。
  • 背景：B 类枯竭 + ROAD → 见 2.4 CIDR+聚合（含 192.1.12.0/22 例题）

5）演进到 IPv6

项 IPv6
长度 128 bit
编址 无分类；常见单播 /64 前缀 + 64 bit IID
广播 无；用组播（如 ff02::1 所有节点）
主机标识 IID（≈ IPv4 主机号）

二、单播 vs 广播 vs 组播（必考 · 新手易懂）

结合 IPv4/IPv6、路由规则与典型协议，一次性分清。

1）核心定义（通信方式）

类型 模式 说明
单播 Unicast 一对一 一个发送方 → 一个接收方
广播 Broadcast 一对全体 一个发送方 → 本网段所有设备（仅 IPv4）
组播 Multicast 一对部分 一个发送方 → 加入该组的设备

2）核心区别总表（直接背诵）

对比项 单播 广播 组播
通信模式 一对一 一对全部（同子网） 一对指定群组
IPv4 是否存在 ✅ 是 ✅ 是 ✅ 是
IPv6 是否存在 ✅ 是 ❌ 彻底取消 ✅ 完全替代广播
能否跨路由器 ✅ 可路由转发 ❌ 路由器默认阻断 ✅ 可跨网段（IGMP/MLD）
能否设为主机 IP ✅ 正常主机地址 ❌ 禁止分配 ❌ 仅作目的地址
IPv4 地址特征 主机位非全 0/全 1 主机位全 1 D 类 224.0.0.0/4

→ 与 MAC 单播/组播/广播对照及 01:00:5E 映射：ch09.3 | IPv6 地址特征 | 2000::/3 全球单播 | 无 | ff00::/8（ff 开头） | | 典型协议/场景 | HTTP、TCP、上网、远程 | ARP、DHCP 发现 | 直播、IPTV、OSPF 等 |

→ 组播地址块详解：2.5 · 单播分配：2.7

3）通俗举例

  • 单播：私聊，只发给指定一个人。
  • 广播：教室里大喊，全班所有人都听见。
  • 组播：兴趣小组通知，只有进组的同学能收到。

4）网段举例：192.168.1.0/24

地址 值 能否分配给主机
网络地址 192.168.1.0（主机位全 0） ❌
单播 192.168.1.1 – 192.168.1.254 ✅
定向广播 192.168.1.255（主机位全 1） ❌ 仅目的
受限广播 255.255.255.255 ❌ 仅目的

5）考点补充（易混）

  1. IPv6 没有广播 原广播功能用组播实现，如 ff02::1 = 链路内所有节点（对照 v4 广播语义）。

  2. 一对多时的流量效率（同一份内容发给很多人） 组播 > 单播 > 广播 - 广播：子网内每台都要处理，浪费最大。 - 单播：N 个接收者往往要发 N 份拷贝。 - 组播：网络侧尽量复制一份流，只投递给订阅者（直播、流媒体）。

  3. 使用限制 - 网络地址（主机位全 0）与广播地址（主机位全 1）都不能当主机 IP。 - 组播、广播一般只做目的地址，极少作源地址。

6）极简速记口诀

  • 单播：一对一，到处走，正常 IP 随便用
  • 广播：一对全，不出网，主机位全 1，IPv6 已淘汰
  • 组播：一对群，可路由，直播路由全靠它

三、广播计算与 IPv6 接口标识（IID）

IPv4 广播（计算）

  • 定义：主机位全 1（在给定前缀下）。
  • 计算：广播 = 网络地址 OR (NOT 掩码) 例：192.168.1.0/24 → 192.168.1.255
类型 地址 行为
定向广播 主机位全 1 特定子网内所有主机
受限广播 255.255.255.255 仅本地链路，路由器不转发

IPv6 单播与 IID

IPv6 单播（常见）= 网络前缀(常 64 bit) + 接口标识 IID(64 bit)

IID 作用：标识接口（≈ IPv4 主机号部分）。

生成方式 说明
EUI-64 48 bit MAC → 中间插 FF:FE → 64 bit；第 1 字节 U/L 位取反
隐私扩展 随机 IID，防 MAC 追踪

EUI-64 例题

MAC：00-0C-29-0C-47-D5
→ 拆 24+24，中间 FF:FE → 000C:29FF:FE0C:47D5
→ U/L 取反 → IID：020C:29FF:FE0C:47D5

必背对比

IPv4 IPv6
广播 有（主机位全 1） 无
同等功能 子网广播 / 255.255.255.255 组播（如 ff02::1）
接口标识 主机号（在前缀内） IID（64 bit）

四、30 秒写卷子（浓缩背诵）

演进 1. 分类 A/B/C → 固定边界，浪费、表大 2. 子网+掩码 → 划子网，FLSM，隔离广播域 3. VLSM → 同网不同掩码，省地址 4. CIDR → 无类前缀，路由聚合 5. IPv6 → 128 位，/64+IID，无广播

单播 / 广播 / 组播 - 单播：一对一、2000::/3、正常 IP - 广播：一对全、不出网、主机位全 1；v6 无 - 组播：224/4、ff00::/8；一对多效率 组播 > 单播 > 广播

广播与 IID - IPv4 广播 = 主机位全 1；受限 = 255.255.255.255 - IPv6 IID = 接口 64 bit；无广播，用 组播

2.4

CIDR 与路由聚合

章级精读：../study.md#ch02-4 · 编址演进 · 2.6 分配 控制平面：§5 BGP · 精编：§4.3 CIDR

本节核心目标

搞懂两件事：CIDR 让前缀可以按需变长；路由聚合 把一堆小网段打包成一条大路由，路由器少记很多条。

一句话 CIDR = 前缀随便变长（/24、/25、/26 都行，不再死磕 A/B/C 类） 路由聚合 = 一堆小网段打包成一个大网段，路由器只记 1 条，路由表变短

一、大白话 + 城市小区类比（IPv4）

1）CIDR（无分类编址）

不再固定「A 类一定 /8、C 类一定 /24」，前缀长度可以灵活变长，大网段、小区按需切，少浪费地址。

2）往下分：城市 → 区 → 小区

层级 比喻 例子 说明
城市 一大片 192.168.1.0/24 前缀 24 位，整块城市
区 城市拆两半 192.168.1.0/25、192.168.1.128/25 前缀变 /25，每块更小
小区 区再拆 192.168.1.0/26、192.168.1.64/26 … 前缀变 /26，更小

👉 越往下分：前缀数字越大（/24 → /25 → /26），网段越小

/数字 = 前多少个二进制位是网络部分（和 2.7 IPv6 /3 同一套规则）

3）往上聚：小区 → 区 → 城市（路由聚合 / 超网）

运营商那边不记一堆 /26、一堆 /25，而是打包汇总成一条，例如：

路由器只记：192.168.1.0/24  →  这一片都往这儿走
不用记：     一堆 /25、一堆 /26

效果：路由表条目大幅减少，转发更快、更省内存。

口诀（必背）

方向 规律
往下分 前缀变大 /24 → /25 → /26，网段变小
往上聚 前缀变小 /26 → /25 → /24，网段变大，路由变少

二、笔记可直接抄（标准大白话）

  1. CIDR（无分类编址） 不再固定 A/B/C 类，前缀可以灵活变长：大网段用 /24，往下分区用 /25，分小区用 /26，按需划分，不浪费地址。

  2. 路由聚合（超网） 把下面一堆小网段（/25、/26）汇总成一个大网段 /24，路由器只存这一条路由，大幅减少路由表数量，提高转发效率。

三、和 BGP 怎么串起来？（CIDR 绑定版）

BGP = AS 和 AS 之间，互相交换「CIDR 聚合后的大网段」 它不会把小区 /26、区 /25 发到全球，只传城市 /24 这种最外层汇总路由。

用城市例子走一遍

企业内网：  小区 /26 → 区 /25 → 城市 /24（CIDR 聚合汇总）
                    ↓
对外宣告：  用 BGP 告诉其他运营商：
            「这个 x.x.x.0/24 大段，在我这里」
层级 谁管 发不发全球
/26、/25 企业/园区内部 ❌ 不往外发
/24（聚合后） 边界 + BGP ✅ 只发这种大前缀

教学用 192.168.1.0/24 当比喻；真实互联网 BGP 宣告的是公网前缀（PA/PI），私网不会进全球 BGP 表。

笔记可直接抄（概念对齐）

干什么
CIDR 内部划分 + 向上聚合（小网段打包成 /24）
BGP AS 之间的协议，只传递聚合后的大前缀（最外层汇总地址）

逻辑链条（必背）

内网细分（/26、/25） → CIDR 聚合（/24） → BGP 对外宣告（/24）

终极一句：CIDR 负责打包汇总，BGP 负责把汇总后的大网段，在互联网上发给其他运营商。

→ 边界宣告在 2.7 · 分得地址≠全球可达：2.6 · BGP 详解：§5.3 BGP

四、考试加厚（需要算题时再展开）

点开：CIDR 表、聚合三步法、例题、拓扑敏感、自测

CIDR 专业要点

Classless Inter-Domain Routing — 无类前缀，废除 A/B/C 刚性边界

要点 说明
格式 网络前缀 + 主机位，/x 任意
掩码 /24 ↔ 255.255.255.0
解决问题 地址枯竭 + 为聚合打基础（缓解 ROAD）
前缀 用途
/32 主机路由
/31 点对点（2 地址）
/0 默认路由

路由聚合原理

  • 多条连续、前缀高位相同的小路由 → 一条更短前缀（超网）
  • 找最长公共前缀（LCP）；聚合后前缀变短、覆盖变大

三步：① 转二进制 ② 从左找相同位 → 新前缀长度 ③ 网络地址 = 公共前缀 + 主机位全 0

例题：192.1.12.0/24～192.1.15.0/24 四个

第三字节 12–15 前 6 bit 相同 → /22
→ 192.1.12.0/22

聚合条件：连续 · 高位相同 · 聚合后前缀变短

BGP：ISP 向上游常只通告聚合路由 → 2.6

拓扑敏感（易聚合 vs 难聚合）

难聚合：核心多条 /24 各指不同路由器
易聚合：核心一条 /22 覆盖 .24–.27

→ 章级图：study.md §2.4

概念 一句话
CIDR 无类 IP/x，按需分前缀
聚合 连续小前缀 → 更短一条，表项少

  2. 单条 172.16.0.0/16 能随意「聚成」/8 吗？

答案：1）一般不能（第三字节不连续/公共前缀不够）。2）不能——聚合是合并多条连续小路由，不是把单条随意缩短。

一、IPv4 五大特殊块（大白话 + 例子）

1）组播 224.0.0.0/4（D 类）

范围：224.0.0.0 – 239.255.255.255

地址 含义 例子
224.0.0.1 本网段所有主机 同一交换机/VLAN 下电脑都能收；路由器不往外发
224.0.0.2 本网段所有路由器 OSPF、RIP 等路由协议常用

总结：224 开头 = 组播，一般只在当前局域网有效，不会像公网单播那样跑遍整个互联网。→ 对比 2.3 广播/组播

2）受限广播 255.255.255.255/32

是不是全网互联网都收到？→ 绝对不是！

  • 仅限当前局域网（本 VLAN、本交换机）
  • 路由器默认丢弃，不转发到外网、不跨 AS

例子：DHCP 发现时 0.0.0.0 → 255.255.255.255，只在你家/公司内网喊一声，运营商和互联网收不到。

255.255.255.255 = 只喊自己小区，不喊全世界。

（子网定向广播如 192.168.1.255/24 也是主机位全 1，同样不跨路由 → 2.3）

3）环回 127.0.0.0/8

范围：127.0.0.0 – 127.255.255.255

127 后面能随便变吗？→ 可以！

  • 常用 127.0.0.1（localhost）
  • 127.0.0.5、127.10.20.30 都行
  • 只要以 127 开头 → 不经过物理网卡出站，本机进程之间通信

例子：本机起 Web 服务，浏览器访问 http://127.0.0.5:8080，不用联网。

4）链路本地 APIPA 169.254.0.0/16

何时出现：DHCP 失败 / 没网线 / 没拿到地址 → 系统自动配 169.254.x.x

例子：电脑拿到 169.254.88.99 → 只能和同网段同样 169.254 的设备互访，不能上网。

5）文档测试 192.0.2.0/24（TEST-NET）

专门给教材、RFC 示例、实验用；公网永不分配、不可路由。

例子：书上写「服务器 192.0.2.10」——现实中不存在这台公网机，不会和真 IP 冲突。

笔记可直接抄（五条）

  1. 组播 224/4：224.0.0.1 = 本网段所有主机；224.0.0.2 = 本网段所有路由器；仅局域网内。
  2. 受限广播 255.255.255.255/32：仅本局域网；路由器不转发，不会传遍互联网。
  3. 环回 127/8：开头 127 即可（如 127.0.0.1、127.5.5.5）；本机内部，不走网卡。
  4. 链路本地 169.254/16：DHCP 失败自动分配；只能内网互访，不能上网。
  5. 文档 192.0.2.0/24：课本专用假 IP，不上公网。

2.6

分配

章级精读：../study.md#ch02-6 · 站点规划：2.7

本节核心目标

掌握 全球 IP 空间的层级分配体系、和 DNS 的异同（结构像、访问时不一样），以及 WHOIS/RDAP 溯源。

一、层级结构（必考 · 记死这条链）

IANA（全球池）→ RIR（5 大区域）→ LIR/ISP/大企业 → 终端用户/站点前缀

1）IANA（Internet Assigned Numbers Authority）

项 说明
角色 全球顶级地址管家（ICANN 运营）
职责 管理 IPv4/IPv6 总池；分给 5 个 RIR（不直接给 ISP/用户）；兼管 AS 号、DNS 根、协议端口
粒度 IPv4 典型 /8；IPv6 典型 /12 或 /23 等超大块

2）五大 RIR（Regional Internet Registry）

缩写 负责区域 备注
APNIC 亚太（中国、日本、韩国、澳洲等） 中国 IP 查 APNIC
ARIN 北美（美、加等）
RIPE NCC 欧洲、中东、中亚
LACNIC 拉美、加勒比
AFRINIC 非洲

3）LIR / ISP / 大型企业

  • LIR（Local Internet Registry）：本地注册机构，多为 ISP 或大企业。
  • 从 RIR 拿块，再分给：下游小 ISP、企业/机房、家庭用户（IPv4 常经 NAT）。

4）终端用户或站点前缀

  • 企业/家庭：公网前缀（IPv6 常见 /56、/64）或内网 + NAT（IPv4）。
  • 公网 IP 必须层层分配 → 全球唯一、不重叠。

二、IANA 发 IP vs DNS 域名（大白话）

IP 分配体系 = DNS 域名体系：层级结构一模一样，都是从上往下分。 但「平时上网访问」时，走的完全不是一条路。

1）结构对比：都是「总管家 → 大区 → 下面一层层分」

IP 地址（IANA 体系） DNS 域名
总管家 IANA（全球 IP 总池） 根服务器（13 组逻辑根 A–M）
下一层 5 个 RIR（APNIC 等） 顶级域（.com、.cn …）
再往下 ISP / 大企业（LIR） 二级域（baidu.com）
最底 用户 / 站点 具体主机（www.baidu.com） 
IP：  IANA → RIR → ISP → 用户
DNS： 根   → TLD → 权威 → 网站

→ DNS 细节：自顶向下 §2.4 DNS

2）访问时完全不一样（最易混）

用 IP 直接访问（如 1.1.1.1）

  • 全程不经过 IANA、不经过 RIR、不查 DNS 根
  • IANA 只管地址怎么发出去，不管数据包怎么跑
  • 数据靠 BGP 路由 在运营商线路里一层层转发 → 2.4 CIDR+BGP

一句话：IANA 只管发 IP，不管传数据。

用域名访问（如 www.baidu.com）

  1. 先 DNS 解析：本地缓存 → 递归 DNS → 根 → .com → 百度权威 → 拿到 IP
  2. 再按 IP 走 BGP 路由 访问（这一步和「直接敲 IP」一样）

3）根服务器每天这么多查询，会崩吗？

一般不会，三个原因：

原因 大白话
多镜像 13 组逻辑根（A–M），全球大量镜像，流量分散
缓存 电脑、路由器、运营商 DNS 解析完会缓存；绝大多数请求到不了根
只指路 根只告诉你「.com 去问谁」，不存网页内容，负载很轻

5）五句逻辑（直接抄笔记）

  1. IANA 分配 IP：从上到下发地址，只管归属，不管数据包怎么走。
  2. DNS 解析域名：根服务器从上到下指路，把域名翻译成 IP。
  3. IP 访问：直接 BGP 路由，全程不经过 IANA、DNS 根。
  4. 域名访问：先 DNS（可能查到根）→ 得 IP → 再 BGP。
  5. 根服务器不易崩：多镜像 + 缓存 + 只指路不存内容。

三、WHOIS / RDAP 溯源（大白话）

先搞懂几个词

词 大白话
ISP 互联网服务提供商 = 卖宽带/流量、分公网 IP 的公司。中国移动、联通、电信都是 ISP；国外 Verizon、AT&T 也是
WHOIS 查 IP/域名是谁家的 = IP/域名的「户口本查询」（老工具，文本）
RDAP 新版 WHOIS = 功能一样，格式是 JSON，更规范，优先用
curl 命令行里的「迷你浏览器」= 在终端里发 HTTPS 请求；RDAP 走网页，所以常用 curl 去查

层级一句通

IANA 总管 → 分给五大 RIR（亚太是 APNIC）→ 分给 ISP（如中国移动）→ 分给你
想查 IP 是谁家的？→ WHOIS 或 RDAP（RDAP 用 curl 访问）

三条命令（复制就能跑）

# 1）WHOIS：查 IP 归属（系统需已安装 whois）
whois 223.5.5.5

# 2）RDAP：去 APNIC 查同一 IP（返回 JSON）
curl https://rdap.apnic.net/ip/223.5.5.5

# 3）RDAP 看得更清爽（有 jq 时；没有可跳过）
curl -s https://rdap.apnic.net/ip/223.5.5.5 | jq ".name, .country, .entities[0].vcardArray"

示例 223.5.5.5 常为公共 DNS 等；以查询结果里的组织名为准。文档网段可用 203.0.113.0 练手。

WHOIS 典型会看到：属于哪家（ISP/公司）、来自哪个 RIR、分配时间、联系人、abuse 举报邮箱。

WHOIS vs RDAP（专业对照）

WHOIS RDAP
协议 传统，TCP 43 现代（RFC 7480），HTTPS + JSON
格式 文本，各 RIR 不统一 结构化、统一、Unicode
怎么查 whois <IP> curl https://rdap.<RIR>/ip/<IP>

RIR RDAP 基址（亚太示例）
APNIC https://rdap.apnic.net/ip/
ARIN https://rdap.arin.net/registry/ip/

溯源三要素（WHOIS/RDAP 和 BGP 啥关系？）

WHOIS/RDAP = 查档案（谁买的、谁负责，静态登记） BGP = 跑路线（数据包怎么走，实时路由） 不是一个东西，溯源攻击时常常两个一起用。

WHOIS / RDAP BGP
像什么 户口本、分配档案 实时导航图
记什么 CIDR 分给谁、联系人、abuse 邮箱 哪个 AS 在宣告、流量从哪条路径来
存在哪 五大 RIR 官方库（APNIC 等） 各路由器里的 路由表（运营商之间点对点交换，不是广播）

1）前缀归属

大白话：CIDR 把一大段（如 223.5.0.0/16）分给中国移动，移动再切成 /24 分给下面。

这些「谁拿到哪段」的记录，存在 RIR 数据库里（APNIC、ARIN…）——谁拿了哪个 /16//24、分给谁、何时分配。

WHOIS/RDAP = 读这份官方档案 → 前缀归属 = 这个 CIDR 网段是谁家的

2）滥用投诉（Abuse）

登记 IP 时必须留投诉邮箱（如 abuse@xxx.com）：

我这个网段下的用户要是发垃圾邮件、攻击、诈骗、DDoS，请发邮件到这里，我来处理/封 IP。

WHOIS/RDAP 把 abuse 邮箱查出来 → 你被某 IP 攻击 → 发邮件给对应运营商追责。

3）路由溯源（和 BGP 配合）

易混纠正：BGP 不广播；是运营商之间一对一交换路由信息（和 2.4 里「对外只发聚合大前缀」是一回事）。

两步配合：

  1. RDAP/WHOIS：这个 IP 属于哪个 AS（自治系统，如中国移动 AS9808）、哪家运营商
  2. BGP 路由表 / 路径工具：攻击流量从哪条线路、经过哪些 AS 跳过来的
被 IP 攻击 → RDAP：归属中国移动 → 查 BGP 路径：电信 → 移动 → 你
路由溯源 = 谁家的 IP + 流量怎么走过来的

卡点：本地 BGP 记的是「出去的路」，怎么知道别人怎么「进来」？

你先理解对了：本地路由器的 BGP 表、AS‑PATH，记的是：

我要去某个 IP，要经过哪些 AS（出去的方向）

疑惑：别人攻击我，流量是进来的；表里只有出去的路，怎么溯源？

核心一句：在对称路由假设下（教学/常考常用），别人怎么来 ≈ 你怎么去的反向。

你家 AS1 ──要去──▶ 电信 AS2 ──▶ 移动 AS3   （本地 BGP：AS‑PATH = AS1 → AS2 → AS3）

移动 AS3 访问你：  AS3 → AS2 → AS1         （进来的反向路径）
说明
本地 BGP 表 记本机出去到某前缀的 AS‑PATH
别人进来 常假设与出去同一条路，方向相反
注意 现网可能有非对称路由；精确路径要靠抓包/全网视图，不要死背「永远对称」

第二个关键：溯源不靠你家里那张小表 → 见下节「公开 BGP 库」

卡点：有没有「全球统一的 BGP 中央数据库」？所有 AS 表一样吗？

先纠正最大误区：没有一个全球统一、大家都去同步的 BGP 中央库！ 互联网没有中心；BGP 是 AS 之间分布式、点对点互相传路由，不是全体抄同一份数据库。

真正的 BGP 怎么跑

移动 AS9808 ←──BGP邻居──→ 电信 AS4134 ←──→ 联通 … ←──→ 国外运营商
  • 每个运营商 = 一个 AS
  • 两两建邻居，一对一交换自己知道的路由
  • 没有总服务器，各 AS 各自维护自己的路由表

那「公开 BGP 数据库」是啥？

互联网里的 BGP 公开 BGP 数据库（溯源用）
谁用 各运营商自己的路由器 我们查路径、做溯源
怎么来 AS 之间点对点交换 第三方（RouteViews、RIPE RIS、bgp.he.net…）与大量 AS 建邻居，收集路由后整理成网站
是不是中心库 不是 也不是互联网在用的中心库，只是收集结果的展示

真正的 AS 根本不用这些网站；它们只给自己路由器跑 BGP。

每个 AS 的 BGP 表一样吗？

绝对不一样。 每个 AS 只存自己用得到的路径：

AS 表里大概有什么
你公司 到电信、移动、默认路由…
美国运营商 欧美、日韩相关前缀…
非洲某 ISP 可能不知道中国内部细路由

为啥公开库上路径「看起来像全局」？ 因为第三方收集了很多 AS 发出来的路由，拼成上帝视角给我们查；不是全世界 AS 表都相同。

数据源 能看什么

五句写笔记

  1. 本地 BGP 表：记本机出去的 AS‑PATH。
  2. 对称假设：别人进来 ≈ 出去路径的反向（现网可能不对称）。
  3. 互联网 BGP：无中心库，AS 点对点交换；各 AS 表各不相同。
  4. 公开 BGP 库：第三方收集，给人类溯源用，不是运营商在用的中心库。

2.7

单播地址分配

章级精读：../study.md#ch02-7 · 2.6 全球分配 · DHCP：ch06 · NAT：ch07 · 私有地址：2.5 · 单播/广播/组播：2.3 §二

本节核心目标

搞懂：正常 IP 怎么分——内网用私有地址，外网用公网 PA/PI；需要时再记 PA/PI、多宿主等考试点。

一句话通透 单播地址 = 正常能用的 IP。分配就是：内网用私有 IP，外网用公网 PA/PI IP。

一、大白话核心

单播地址 = 普通可用的 IP 地址

给每台设备一个唯一标识，用来一对一上网、通信。

  • 广播、组播是特殊地址，不能当普通 IP 用 → 2.3 对比
  • 电脑、手机、服务器日常用的，全都是单播地址
  • 192.168、10 开头这些私有 IP，也是单播（只是不能直接在公网上路由，常配合 NAT）

二、关键名词（通俗版）

名词 大白话
PA 地址 运营商给的公网 IP。换运营商往往要换 IP；便宜，小公司、只连一家 ISP 够用
PI 地址 自己申请的永久公网 IP（跟运营商无关）。换运营商可以不换 IP；适合大公司、多家运营商备用
ISP 运营商：拉网线、分公网 IP、帮你连上互联网
边界宣告 企业有了公网 IP 后，用 BGP 告诉其他运营商「这个聚合后的大网段（如 /24）在我这里」→ 2.4 CIDR+BGP
DHCP 内网自动给电脑分 IP、掩码、网关、DNS，不用手输

三、企业怎么分配 IP（最简单逻辑）

1）内网（公司内部）

  • 用私有 IP（192.168.x.x、10.x.x.x、172.16–31.x.x）
  • 按部门/楼层划 VLAN，每段一个子网
  • 用 DHCP 自动分配；服务器、网关可固定 IP

2）外网（上互联网）

  • 用 PA 或 PI 公网 IP
  • 只连一家运营商 → 一般用 PA
  • 多家运营商备份（多宿主）→ 一般用 PI
  • 在出口路由器做边界宣告，让外网能访问

典型场景（扫一眼）

场景 怎么做
家里上网 私有 IP + 路由器 NAT + DHCP
公司内网 私有 IP + VLAN + DHCP
公司对外 PA/PI 公网 IP + 边界宣告

四、IPv6 全球单播（通俗讲）

斜杠后面的数字 = 前面多少个二进制位，不是多少段！ /3 = 前 3 个 bit，不是 3 段；/64 = 前 64 个 bit，不是 64 段。

先记地址长什么样

  • IPv6 一共 128 bit = 8 段 × 16 bit（每段 4 个十六进制数）→ 2.2 写法

2000::/3 到底是啥？

  • /3：只看地址最开头 3 个二进制位，固定为 001
  • 第一段十六进制常以 2 开头（2 = 0010，最高 3 bit 是 001）
  • 所以：2000::/3 = 所有以 2/3 开头的 IPv6 = 全球公网单播地址

和 8 段的关系：/3 只划了最左边 3 bit，和后面 7 段、125 bit 无关；别当成「前 3 段」。

极简示意图（/3 在哪）

128 bit（写成 8 段 × 16 bit，例如 2001:db8:…）

/3 只看最左边 3 个二进制位：

│ 0 │ 0 │ 1 │  … 随便变 …                                   │
└───┴───┴───┴──────────────────────────────────────────────┘
  ↑ 固定 001  →  落在 2000::/3（全球单播块）

/64 常考（网络 vs 主机）：
┌──────────── 前 64 bit ────────────┬──────── 后 64 bit ────────┐
│ 网络侧（常 ≈ 前 4 段）             │  IID / 设备 ID（常 ≈ 后 4 段）│
└───────────────────────────────────┴───────────────────────────┘
写法 含义（都是二进制位）
IPv4 /24 前 24 bit 是网络部分
IPv6 /3 前 3 bit 固定 → 全球单播块
IPv6 /64 前 64 bit 常作网络；后 64 bit 常作 IID

笔记可直接抄的一段

IPv6 全球单播地址：2000::/3 含义：前 3 个二进制位固定为 001，代表全球唯一公网 IP。 地址结构：全球路由前缀 + 子网 ID + 接口标识 IID（64 bit）

  • 公司内网 IPv6「私有」：fd00::/8（ULA） —— 这里的 /8 同样是前 8 个 bit，不是 8 段
  • IID 细节 → 2.3

与 IP 地址相关的攻击

章级精读：../study.md#ch02-8 · ch01 信任/分层攻击 · ch18 安全 · 自顶向下 §8 分层表

本节核心目标

一、IP 欺骗（IP Spoofing）——核心攻击

1）根因（必考）

  • IP 协议不校验源 IP 真实性：源地址由发送端填写，网络层默认信任
  • UDP、ICMP 等无连接/弱状态最易伪造；TCP 有三次握手相对难，仍有 SYN Flood、RST 劫持 等

2）原理

攻击者构造源 IP 被伪造的 IP 包：

  • 伪装受信任主机（内网 IP、白名单服务器 IP）
  • 或伪造受害者 IP 为源，发动反射攻击

3）典型危害

# 危害 说明
1 身份伪装/越权 绕过基于 IP 的 ACL
2 反射型 DDoS（放大） 伪造受害者 IP 向 DNS/NTP/SSDP/Memcached 发请求 → 大流量响应打向受害者
3 会话劫持/中断 伪造 TCP RST 断开合法连接
4 溯源困难 真实攻击源被隐藏

→ 与 1.8 §IP 欺骗 · §3.5 TCP 联动

二、主流防护手段（考试必背）

1）BCP 38 —— 边界入站过滤

项 说明
全称 Best Current Practice 38（IETF 推荐）
做法 ISP/企业边界丢弃源地址不属于本 AS/本网段的入站包
一句话 你家的 IP 只能从你家接口进来

2）uRPF —— 单播反向路径转发

项 说明
原理 以源 IP 查路由：若回包应走的接口 ≠ 入接口 → 丢弃（伪造）
Strict 严格：回包接口必须 = 入接口（常用）
Loose 宽松：只查是否存在路由，不校验接口
地位 BCP 38 的标准实现之一

3）应用层加固

  • 不依赖 IP 做身份：TLS、会话令牌、API Key、MFA
  • 监控：源 IP 突变、流量突增、告警
  • 反射服务：DNS/NTP 等 源校验、限速、白名单

→ 深化：ch18 TLS · §8.5 防火墙

三、易混概念

易混 纠正
IP 欺骗 vs 改目的 IP 只伪造源 IP，目的 IP 正常
反射攻击 IP 欺骗 + 放大；第三方当放大器
IPv4 vs IPv6 欺骗门槛 v6 有 IPsec、SLAAC/RA-Guard 等，更难但非不可能
IP 欺骗 vs 扫描/嗅探 本节侧重源地址伪造；扫描见章级表

四、30 秒写卷子

  • 根因：网络层不验源 IP
  • 危害：伪装、反射 DDoS、RST 劫持、难溯源
  • BCP 38：边界丢弃非本网段源入站包
  • uRPF：反向路径与入接口一致性
  • 核心：网络层（BCP38/uRPF）+ 应用层（不信 IP 身份）
