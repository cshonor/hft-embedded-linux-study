7.1

引言

章级精读：study.md#ch07-1 · 端到端：ch01 §端到端 · 防火墙：7.2 · NAT：7.3

本节核心目标

理解 防火墙与 NAT 作为现代网络边界「守门员」的定位、作用与代价，认清它们如何破坏端到端透明却又不可或缺。

一、背景：为何需要 Middlebox（中间设备）

早期互联网设计是端到端透明：

  • 网络只负责转发，不修改包、不过滤
  • 双方直接用真实 IP 通信 — 对等、简单、可扩展

现实两大压力：

压力 后果
IPv4 地址枯竭 公网 IP 不够，大量设备无法直接获得公网地址
安全威胁激增 内网主机漏洞多、易被攻击，需要边界防护

→ 必须在网络边缘部署 防火墙 + NAT 等中间设备，打破端到端透明，换取 安全 + 地址复用。

→ ch01 端到端原则 · ch02 私网地址

二、核心角色：防火墙 vs NAT

flowchart LR
  INET[Internet] <-->|过滤| FW[防火墙]
  FW <-->|地址翻译| NAT[NAT]
  NAT <--> LAN[内网主机]

1）防火墙（Firewall）

项 说明
定位 网络边界的「流量警察」
过滤 按规则（源/目的 IP、端口、协议）放行/丢弃
隔离 阻止非法外网访问内网，减少攻击面
集中策略 不必每台主机单独防护

一句话：防火墙 = 受限连通 + 策略过滤 → 7.2

2）NAT（网络地址转换）

项 说明
定位 地址「翻译官」
地址复用 私网（10/8、172.16/12、192.168/16）多主机共享少量公网 IP
隐藏内网 外网只见 NAT 公网 IP，不见内网真实地址
PAT 同一公网 IP 用不同端口区分不同内网连接

一句话：NAT = 私网→公网地址转换 + 共享公网 IP → 7.3

设备 主要作用
防火墙 受限连通、策略过滤
NAT 私网多主机共享少量公网地址

三、核心代价：破坏端到端透明

代价 说明
身份不透明 地址/端口被改写；对端看不到真实源 IP/端口
主动连接受限 外网默认无法主动访问内网 → P2P/自托管服务困难
应用兼容 需 ALG（FTP、IPsec、SIP 等）；P2P/VoIP 需 STUN/TURN/ICE
状态开销 NAT/防火墙维护会话表 → 延迟与故障点

→ 7.4 NAT 穿透

四、开发与架构的默认前提

现代应用必须假设存在 NAT/防火墙：

  • 不能依赖固定公网 IP
  • 须实现保活（心跳），防 NAT 会话超时
  • 服务端需端口映射/DMZ 或 P2P 穿透
  • 排障更复杂（真实 IP 隐藏、映射端口不定）

五、为何「明知破坏透明，却仍必需」

原因 说明
IPv4 枯竭 无 NAT 则无法支撑海量设备联网
安全边界 防火墙是中小企业/家庭最经济的边界防护
现实妥协 端到端理想 vs 安全+成本 → NAT+防火墙是折中

7.2

防火墙

章级精读：study.md#ch07-2 · 前节：7.1 引言 · NAT：7.3 · 端到端：ch01

本节核心目标

理解防火墙在可信/不可信网络边界上的作用，以及包过滤与应用层网关（代理）两类机制的原理与差异。

一、基本概念

防火墙部署于可信内部网络与不可信外部网络的边界，是一套软硬件组合。它依据预设规则对往来数据包进行管控：

  • 阻止未授权访问、恶意流量进入内网
  • 放行合法通信
  • 为内网主机提供边界安全防护

早期网络没有防火墙时，主机直接暴露在公网，任意外网主机都能发起连接，安全风险极高。防火墙由此成为网络边界的标准组件。

→ 边界定位：7.1 Middlebox

二、包过滤防火墙（Packet Filtering Firewall）

最基础、应用最广的防火墙形态，工作在网络层与传输层，通常集成在路由器中。

1）工作原理

路由器本身具备 IP 转发能力；包过滤在转发前增加检查逻辑：

  1. 读取数据包的 IP 首部、TCP/UDP 首部信息
  2. 与管理员配置的规则逐条匹配
  3. 根据结果转发或丢弃

2）过滤依据（核心检查字段）

层次 字段
IP 层 源 IP、目的 IP、协议号（TCP/UDP/ICMP 等）
传输层 TCP/UDP 源端口、目的端口
TCP 专属 控制标志位（SYN、ACK、FIN、RST、PSH 等）

3）基础规则逻辑举例（原理 + iptables）

→ 一页纸背诵：§3 考点

规则 1：拒绝外网主动建连（识别纯 SYN）

项 说明
原理 TCP 连接发起方先发 SYN=1、ACK=0（纯 SYN）；外网入向纯 SYN = 主动连进来（扫描、暴力破解、木马回连）
策略 只允许内网主动向外发起连接，不允许外网主动向内发起
通俗 ✅ 你访问外网网站（你先 SYN） · ❌ 外网机器发「我要连你」的 SYN 
# 外网网卡 eth0；丢弃 TCP 纯 SYN（入站）
iptables -A INPUT -i eth0 -p tcp --syn -j DROP
# --syn 等价于 --tcp-flags SYN,ACK,RST,FIN SYN

注意：无状态规则会误伤合法 SYN-ACK 回程；生产环境多用 有状态（ESTABLISHED,RELATED）配合，见 §4 有状态。

规则 2：仅允许访问外网 80/443（最小权限）

项 说明
原理 最小权限：只开放必要服务端口，其余全关
端口 80 HTTP · 443 HTTPS
通俗 内网机器只能上网浏览，不能对外 SSH、连数据库、发 SMTP 等 
# 出站：内网 → 外网
iptables -A OUTPUT -p tcp --dport 80 -j ACCEPT
iptables -A OUTPUT -p tcp --dport 443 -j ACCEPT
iptables -A OUTPUT -j DROP   # 其余出站默认拒绝（放最后）

规则 3：屏蔽恶意 IP（黑名单）

项 说明
原理 对已知攻击源 / 恶意 IP 或网段，最前面直接丢弃
通俗 「坏人 IP」拉黑 → 连都连不上 
# 拉黑单个恶意源 IP（入站）
iptables -A INPUT -s 203.0.113.45 -j DROP
# 拉黑网段 /24
iptables -A INPUT -s 198.51.100.0/24 -j DROP
# 也可拦目的 IP（防内网访问恶意服务器，出站）
iptables -A OUTPUT -d 198.51.100.0/24 -j DROP

三条规则合在一起的匹配顺序（必考）

防火墙规则 从上到下匹配，首个命中即停止（First Match）：

顺序 规则 动作
1 黑名单恶意 IP DROP
2 拒绝外网主动 纯 SYN DROP
3 允许必要端口 80/443（及已建立连接等） ACCEPT
4 默认拒绝所有未明确允许的流量 DROP 
黑名单 → 拒 SYN → 允许 80/443 → 默认 DROP

→ ACL 通用原则：7.5 · study §7.5

一页纸背诵版

# 一句 易错
1 外网入向 纯 SYN → DROP（防外网主动建连） 无状态 --syn 可能误伤；生产用 conntrack/ESTABLISHED
2 出站仅 80/443 ACCEPT，其余 DROP（最小权限） 规则顺序：允许在前，默认 DROP 在最后
3 黑名单 IP/网段 放最前 DROP 可拦 源（入站）或 目的（出站）
4 顺序：黑 → 拒 SYN → 允端口 → 默认拒 First Match；具体规则在前

4）无状态 vs 有状态包过滤

（1）无状态包过滤（Stateless）

每一个数据包被独立判断；设备不记录过往通信或连接状态。

优点 缺点
逻辑简单、转发快、硬件开销小 安全性弱；难区分「正常应答」与「伪造包」，易被恶意构造报文绕过

（2）有状态包过滤（状态检测防火墙）

在无状态基础上增加连接状态表，跟踪 TCP/UDP 会话：

  1. 内网向外发起连接（首包），规则放行 → 状态表记录 五元组（源 IP、目的 IP、源端口、目的端口、协议）
  2. 外网返回的应答包若匹配状态表 → 直接放行，无需重匹配全部规则
  3. 连接断开或会话超时 → 删除表项

特点：兼顾性能与安全性，是目前主流的包过滤方案。

→ 状态检测流程：study.md §TCP 状态

5）包过滤的优缺点

优点 缺点
部署简单、吞吐量大、延迟低 不解析应用层
可复用现有路由器 无法识别应用层攻击（恶意请求、病毒、违规内容）
对复杂协议、动态端口协议适配差

典型实现：iptables / nftables、商用防火墙策略。

三、应用层网关（代理防火墙 / Application-Level Gateway）

简称代理防火墙，工作在应用层，与包过滤原理完全不同。

易混：此处是代理型防火墙；NAT 语境下的 ALG（应用层网关） 是修正 FTP/SIP 等载荷中地址的另一类组件 → 7.3 ALG

1）工作架构

代理防火墙多为多网卡主机，不做单纯 IP 转发，而是内外网之间的「中转节点」：

sequenceDiagram
  participant C as 内网客户端
  participant P as 代理防火墙
  participant S as 外网服务器
  C->>P: TCP 连接 ①
  P->>P: 解析应用层、校验
  P->>S: TCP 连接 ②（新建）
  S-->>P: 响应
  P-->>C: 转发
  1. 内网客户端 → 与防火墙建立 TCP 连接
  2. 防火墙解析应用层请求，校验合法性
  3. 防火墙主动新建独立连接访问外网服务器
  4. 外网响应经防火墙回传内网客户端

内外网主机没有直接的端到端连接 — 防火墙是两条独立连接的终点。

2）核心特性

特性 说明
深度应用层解析 完整解析 HTTP、FTP、Telnet 等；可检查请求内容、指令、文件 → 拦截恶意代码、违规指令、病毒
隐藏内网拓扑 外网只见防火墙 IP，无法获知内网真实地址与结构
附加能力 用户认证、访问日志、内容缓存、细粒度策略

3）优缺点

优点 缺点
安全等级高，可防应用层威胁 流量须经应用层解析与中转 → 延迟大、吞吐量低
精细化管控业务流量 易成网络瓶颈
每种应用协议常需单独代理模块，通用性差，维护复杂

四、DMZ 非军事区（延伸架构）

实际组网中，防火墙常划分 DMZ 隔离网段：

  • 放置对象：对外服务的服务器（Web、邮件、DNS 等）
  • 规则设计：
  • 外网 → 仅能访问 DMZ，不能直入内网
  • 内网 → 可按需访问 DMZ 与外网
  • 作用：即便 DMZ 服务器被攻破，攻击者也难以直接渗透到核心内网
路径 典型策略
Internet → DMZ 仅开放必要服务（80/443 等）
Intranet → Internet/DMZ 较宽松
DMZ → Intranet 通常严禁（防横向渗透）

五、两种防火墙核心区别

维度 包过滤防火墙 应用层网关（代理）
工作层级 网络层 + 传输层 应用层
核心行为 IP 转发 + 逐包头部检查 双重连接 + 解析应用数据
性能 高吞吐、低延迟 低吞吐、高延迟
安全深度 基于头部与状态，偏基础 可防应用层威胁，更全面
理解应用语义 否 是

拓展（预留）

  • 防火墙 vs IDS（检测报警 vs 阻断准入）
  • 自顶向下：§8.5 防火墙

抓包/实操记录

→ 三条基础规则 + iptables：§3 规则举例 · 背诵版

7.3

网络地址转换 (NAT)

章级精读：study.md#ch07-3 · 速记卡：#ch07-3-cheat · 通俗版：04 §4.3 NAT 易懂 · 工作过程：#ch4-3-nat-flow · 穿透：7.4

本节核心目标

掌握 NAT 作用/本质/转换对象/执行位置/映射表；基本 NAT vs NAPT、Hairpin、ALG、四类 NAT 映射（P2P） — 考试/面试够用。

NAT 基础五要点（速记）

# 要点
1 作用：私网复用公网 IP，隐藏内网、缓解 IPv4 地址枯竭
2 本质：改写 IP 首部（源/目的 IP）+ 维护状态映射表
3 对象：基本 NAT 只改 IP（一对一/多对多）；NAPT 改 IP+端口（多对一，最常见）
4 位置：部署在网络边界网关（路由器/防火墙）；数据平面改写包，控制平面维护表项
5 状态：内网五元组 ↔ 公网五元组；老化超时释放映射

→ 出站/入站分步：04 §4.3 工作过程

通俗：NAT = 前台总机 — 外面只看到一个公网号码，内网很多分机靠端口/映射表区分。

基本 NAT vs NAPT（必背）

类型 行为 映射关系 公网 IP 利用率
基本 NAT（No-PAT） 只转换 IP，不改端口 一对一 / 多对多（公网 IP 池） 低 — 一会话占一公网 IP
NAPT（PAT / 重载 NAT） 同时转换 IP + 端口 多对一（最常见） 极高 — 一公网 IP 承载数千会话
场景 常用类型
家庭 / 公司上网 NAPT
内网服务器对外提供服务 静态 NAT / 端口映射（静态 PAT）

→ 与防火墙关系：NAT 常集成在同一边界盒 → 7.2

Hairpin / NAT 环回（发夹）

项 说明
场景 内网主机用公网 IP 访问同网段另一内网服务（或访问映射到本机的公网 IP）
问题 普通 NAT 回包源 IP 不匹配 → 连接失败
原理 网关同时做 DNAT（目的转内网 IP）+ SNAT（源转网关 IP），流量「发夹式」转回内网
用途 内外网统一用公网域名/IP 访问服务 
内网 A ──(目的=公网IP)──► NAT 网关 ── DNAT+SNAT ──► 内网 B
                              └── 发夹，不真正出公网

→ study §7.3.4 Hairpinning

ALG（应用层网关）

项 说明
背景 NAT 只改 IP 头；FTP/SIP/RTSP 等协议载荷里嵌内网 IP/端口 → 对端仍连私网地址 → 失败
作用 解析应用层载荷，把里面的私网 IP/端口改成公网 IP/端口
典型 FTP 主动模式（PORT 命令）、SIP、RTSP
冲突 TLS 加密后 ALG 无法解析载荷 → 催生被动 FTP、STUN/TURN 穿透

易混：NAT ALG（改载荷）≠ 防火墙 应用层代理（拆双连接）→ 7.2 §代理

NAT 映射类型（P2P 穿透）

按 RFC 3489 / 5389 四类（STUN 语境）；P2P 友好度从高到低：

# 类型 行为 打洞难度
1 全锥 / Full Cone（端点独立 EIM + 宽松过滤） 内网 IP:Port → 固定公网 IP:Port；任意外网 IP 可回连 最易
2 限制锥 / Restricted Cone（EIM + 地址相关 ADF） 固定公网映射；仅曾主动访问过的外网 IP 可回连 较易
3 端口限制锥 / Port-Restricted 固定公网映射；仅曾访问过的外网 IP:Port 可回连 较难
4 对称型 / Symmetric NAT（ADM） 内网 IP:Port + 不同目的 → 不同公网 IP:Port 最难，常需 TURN 中继

口诀：全锥易、限制中、端口难、对称靠中继

→ 与 study EIM/ADM/EIF/ADF 对照：study §7.3.2–7.3.3 · 穿透协议：7.4 NAT 穿越

本书术语 STUN 四类
EIM 映射无关目的 Full / Restricted / Port-Restricted 的前半
ADM 映射随目的变 Symmetric
EIF vs ADF 过滤 决定「谁能打进来」— Filtering 常比 Mapping 更影响 P2P

NAT 精简速记卡（背诵版 + 易错点）

→ 详述见上文：基础 · NAPT · Hairpin · ALG · 四类

一、基础核心

# 要点
1 作用：复用私网 IP、隐藏内网，解决 IPv4 地址不足
2 本质：改写 IP/端口，维护状态映射表，表项超时老化
3 部署：网络边界网关（路由器/防火墙）

二、基本 NAT & NAPT（高频考点）

类型 要点
基本 NAT 仅转换 IP；一对一/多对多；IP 利用率低
NAPT (PAT) 转换 IP+端口；多对一；主流家用/企业上网
对外发布 静态 NAT / 端口映射

三、Hairpin NAT（发夹环回）

项 要点
场景 内网主机用公网 IP 访问内网服务
实现 网关同时 SNAT + DNAT
作用 内外网共用同一公网地址访问业务

四、ALG 应用层网关

项 要点
原因 FTP/SIP/RTSP 载荷内嵌私网 IP/端口，普通 NAT 无法处理
功能 解析应用层，改写内嵌地址与端口
局限 TLS 加密无法解析 → 被动 FTP、STUN/TURN

五、NAT 四类型（P2P 穿透，难度递增）

# 类型 要点
1 全锥 Full Cone 映射固定；任意外网可访问 → 最易打洞
2 地址限制锥 仅访问过的外网 IP 可回连
3 端口限制锥 仅访问过的外网 IP:Port 可回连
4 对称 Symmetric 不同目标 → 不同映射 → 最难，靠 TURN

口诀：全锥易，限制中，端口难，对称靠中继

六、易错点汇总

# 易错 正确
1 NAPT 只靠 IP 区分会话 靠端口区分内网不同主机 → 多对一核心
2 ALG 对加密协议有效 仅明文协议；TLS 失效
3 内网可用公网 IP 互访 普通 NAT 不支持；须开 Hairpin
4 对称 NAT 有固定映射 无固定端口映射 → P2P 最大障碍

  • FTP 失败：试被动模式；企业网 ALG 关/开都可能导致异常

疑问与总结

背：五要点；NAPT 多对一；Hairpin 发夹；ALG 改载荷；全锥→对称，对称靠 TURN。

7.4

NAT 穿越 (NAT Traversal)

章级精读：study.md#ch07-4 · NAT 类型决定成败：7.3 §四类 NAT · Open NAT/UPnP：7.5

本节核心目标

掌握 UDP 打洞、STUN / TURN / ICE 与 映射保活 — WebRTC、游戏、P2P 考点与实战。

一、UDP 打洞（Hole Punching）

1. 流程

步骤 说明
① 主动外联 内网主机向公网对端/信令服务器主动发 UDP
② 建立映射 NAT 生成外向端口映射（reflexive 公网 IP:Port）
③ 反向打入 对端向该 (公网 IP, 端口) 发包 → 利用 NAT 会话表允许回连 
内网 A → 主动发包 → NAT 建映射 → 对端 B 向 (公网IP:Port) 回包 → 穿入内网 A

常经信令服务器协调 A、B 同时向对方发探测包，NAT 视为由内向外合法流 → 开针孔。

2. 原理

利用 NAT 连接跟踪 / 会话表：内网先发起的外向流会在表项中记录映射；对端若命中同一五元组（或宽松过滤策略允许），反向报文可通过。

3. 成败关键：NAT 类型

NAT 类型 打洞难度
全锥 Full Cone 最易 — 固定映射，任意外网可回连
限制 / 端口限制 中等 — 过滤策略更严
对称 Symmetric 最难 — 不同目的 → 不同映射，打洞常失败 → 需 TURN

→ 四类详解：7.3 §映射类型 · 口诀：全锥易，对称靠中继

二、NAT 穿越三剑客（STUN / TURN / ICE）

协议 核心作用 备注
STUN 查询自身 NAT 映射后的公网 IP + 端口 纯查询，不转发业务流量
TURN 打洞失败时做流量中继转发 兜底；消耗服务器带宽/成本高
ICE 自动收集各类候选地址、连通性探测，择优选择传输路径 组合 STUN/TURN；WebRTC 标配 
ICE 收集候选 → STUN 获 reflexive 地址 → 直连/打洞探测 → 失败则 TURN relay
协议 机制 限制
STUN 反射寻址 轻量；难穿对称 NAT
TURN 中继 成功率高；带宽成本高
ICE 交互式连接建立 自动选最优路径

三、开发实战

语言 库
Go pion/ice、pion/webrtc
Rust webrtc-rs、libp2p 搭配 STUN

退化场景排查

连接降级走 TURN 时，优先排查：

原因 说明
对称 NAT 打洞失败最常见根因
UDP 防火墙拦截 边界/本机阻 UDP
会话超时 映射被清，探测时已失效

四、映射保活

项 说明
问题 NAT 表项存在空闲超时 — 长时间无流量映射被清除
后果 对端无法再通过原公网端口回连 → 断连
解决 定时 STUN Binding 刷新 或应用层心跳包

→ TCP 侧保活：ch17 Keepalive

考点速记

# 要点
1 打洞依赖主动建流产生的 NAT 外向映射
2 STUN 查地址 · TURN 做中继 · ICE 路径优选
3 降级至 TURN → 大概率 对称 NAT 打洞失败
4 必须 心跳/刷新绑定，防 NAT 超时断连
易错 正确
STUN 转发业务流量 STUN 仅查询 reflexive 地址
TURN 是首选 TURN 是兜底；直连/打洞优先
打洞与 NAT 类型无关 全锥易、对称最难
映射永久有效 有空闲超时 → 需 保活

疑问与总结

背：主动发包建映射 → 对端反向打入；STUN/TURN/ICE 分工；对称 NAT → TURN；心跳防超时。

7.5

配置包过滤防火墙和 NAT

章级精读：study.md#ch07-5 · ACL/iptables 示例：7.2 §三条规则 · 状态耗尽：7.7 · 过滤先于 NAT：study §7.5 架构

本节核心目标

掌握 ACL 匹配顺序、动态端口映射（UPnP/PCP） 与 conntrack 运维 — 包过滤与 NAT 的配置与交互层面。

一、ACL 访问控制列表

1. 匹配规则

原则 说明
遍历顺序 自上而下逐条匹配
First Match 第一条命中规则立即执行，不再后续匹配
默认策略 末尾通常 DENY/DROP（隐式或显式）

2. 编写原则

原则 说明
细在前、宽在后 精细化规则靠前，宽泛规则靠后
默认拒绝 末尾配置 默认拒绝（DENY/DROP） — 白名单思维
先过滤后 NAT 过滤规则应先于 NAT 转换；否则攻击/垃圾流占满状态表 → study 架构要点

3. 标准规则顺序（实战 / 考点）

与 7.2 §三条基础规则 + iptables 一致：

顺序 规则 动作
1 黑名单拦截恶意 IP/网段 DROP
2 拒绝外网主动 纯 SYN 连接 DROP
3 放行业务端口（如 80/443）及已建立会话 ACCEPT
4 全部默认丢弃 DROP 
黑名单 → 拒 SYN → 允许 80/443 → 默认 DROP

一句：先匹配先生效，细规则在前，默认拒绝收尾。

二、动态端口映射协议（Open NAT）

终端/应用自动向边界 NAT 设备申请入站端口映射，实现「外网能连进来」（游戏、P2P、VoIP 等）。

协议 特点
UPnP IGD 传统主流；终端自动申请入站映射；家用路由器常见；认证弱
NAT-PMP Apple 等早期方案；较 UPnP 简洁
PCP IETF 新一代；映射生命周期、安全性、功能优于 UPnP；CGN 环境更规范
场景 策略
家用 常开启 — 游戏/BT/VoIP 依赖 Open NAT
企业 一般禁用 — 防恶意端口暴露、未授权入站、入侵

风险提示：UPnP 允许内网应用自行打洞入站 → 企业网视为扩大攻击面。

→ NAT 类型与 P2P：7.3 · 穿透：7.4

三、运维要点

连接跟踪表 conntrack

项 说明
作用 记录 NAT / 防火墙 会话状态（五元组映射、TCP 状态等）
查看 Linux：conntrack -L · /proc/net/nf_conntrack
iptables iptables -L -n -v 查看规则命中计数

状态表耗尽

现象 原因
无法新建连接 conntrack / NAT 映射表占满
业务中断 新用户/新会话无法建立；已有连接可能仍存活
安全类 攻击者伪造大量半开连接 → 状态表耗尽 DoS → 7.7

缓解：限制每源新建速率、合理超时、扩容表项（仍有限）；关键服务 DMZ 或公网 v6。

考点速记

# 要点
1 ACL：先匹配先生效；细规则在前；默认拒绝收尾
2 标准顺序：黑名单 → 拒 SYN → 80/443 → 默认 DROP
3 动态映射：UPnP 经典；NAT-PMP/PCP 替代/增强；企业多关闭
4 conntrack 满 → 新连接失败（状态表耗尽）
5 先过滤后 NAT — 避免垃圾流占满映射表
易错 正确
规则越宽泛越靠前 具体规则在前，默认 DROP 最后
UPnP 企业标配 企业一般禁用；家用常见
NAT 表满只影响 NAT 防火墙 conntrack 满同样断新连接

疑问与总结

背：ACL 自上而下 First Match；黑→SYN→80/443→DROP；UPnP 家用/企业禁；conntrack 满则断新连。

7.6

IPv4/IPv6 共存和过渡中的 NAT

章级精读：study.md#ch07-6 · NAPT/CGN 基础：7.3 · DNS64 细节：ch11 §11.9

本节核心目标

掌握 DS-Lite、NAT64/DNS64 两类 IPv6 演进中的 NAT 过渡技术 — 定位、原理与考点区分。

定位：二者均为过渡技术，最终目标是全原生 IPv6 端到端通信；NAT 在 v6 时代常作协议桥梁，而非仅省地址。

一、DS-Lite（Dual-Stack Lite）

原理

环节 说明
用户侧 内网仍跑 IPv4 私网；CPE B4 将 IPv4 报文封装进 IPv6 隧道
传输 封装后的 IPv4 over IPv6 经运营商 IPv6 网络送达
运营商侧 AFTR（CGN 设备）解封装，对 IPv4 做 NAPT 后上公网 
[内网 IPv4] → B4 封装 → IPv6 隧道 → AFTR 解封装 + NAPT → 公网 IPv4

作用

  • 减少运营商对公网 IPv4 地址的消耗 — 家庭侧不再分配独立公网 v4
  • 适配 IPv6 演进 — 承载层走 v6，业务层暂保留 v4

→ CGN / 大规 NAT：7.3

二、NAT64 + DNS64（纯 IPv6 终端访问 IPv4 服务）

场景：终端仅有 IPv6，需访问存量 IPv4-only 服务器（网站、API 等）。

1. DNS64

项 说明
触发 客户端查域名，权威 DNS 无 AAAA、仅有 A（IPv4）
合成 DNS64 服务器将 IPv4 嵌入特殊前缀，返回合成 AAAA
标准前缀 64:ff9b::/96（Well-Known Prefix）

例：IPv4 203.0.113.1 → AAAA 64:ff9b::203.0.113.1

2. NAT64

项 说明
方向 IPv6 ↔ IPv4 双向协议翻译与转发
工作 识别目标地址中的嵌入 IPv4，改写首部（v6→v4 或 v4→v6），维护映射表
配合 必须与 DNS64 闭环 — 客户端拿到「伪 v6」地址后，NAT64 才能译回真实 v4

3. 适用场景

仅拥有 IPv6 的终端 访问 存量 IPv4 业务 — 运营商/企业 v6-only 网络中的典型过渡方案。

→ DNS 流程：ch11 §11.9

补充区分：DS-Lite vs NAT64

维度 DS-Lite NAT64 + DNS64
用户协议栈 仍用 IPv4（私网） 用户只有 IPv6
核心机制 IPv4 over IPv6 隧道 + 运营商侧 CGN/NAPT 协议层 v6↔v4 翻译 + DNS 合成 AAAA
谁省 v4 运营商侧集中 NAPT，少发公网 v4 给家庭 终端侧无 v4；边缘 NAT64 对接 v4 互联网
典型部署 运营商宽带 CPE（B4/AFTR） v6-only 移动/企业网访问 v4 网站

一句：DS-Lite 是「用户仍 v4，靠 v6 隧道传」；NAT64 是「用户仅 v6，协议翻译对接 v4」。

三、核心考点

# 要点
1 DS-Lite：IPv4 over IPv6 隧道 + 运营商侧 CGN/NAPT → 节省公网 IPv4
2 NAT64/DNS64：组合实现 纯 IPv6 主机访问 IPv4 网络（DNS64 合成 64:ff9b::/96 AAAA → NAT64 双向翻译）
3 定位：均为过渡技术；长期目标是 原生 IPv6 端到端
易错 正确
DS-Lite 用户只有 v6 用户侧仍跑 IPv4 私网
NAT64 单独够用 需 DNS64 配合合成 AAAA
过渡技术 = 永久方案 过渡 — 最终全 v6 端到端

疑问与总结

背：DS-Lite = v4 封装进 v6 隧道 + AFTR 做 NAPT；NAT64/DNS64 = 纯 v6 访 v4（前缀 64:ff9b::/96）；二者都是过渡，不是终态。

7.7

与防火墙和 NAT 相关的攻击

章级精读：study.md#ch07-7 · conntrack 运维：7.5 §运维 · 源 IP 不可信：ch05 §5.7

本节核心目标

认识 应用层隧道绕过防火墙 与 NAT/防火墙状态耗尽 — 状态化中间件引入的可用性与隐蔽通道风险。

一、防火墙攻击：应用层隧道绕过

原理

项 说明
手法 恶意流量封装在 80/443 等必放行端口内传输
典型 HTTPS 隧道内嵌 C2（远控） 流量 — 端口过滤视为「正常 Web」
本质 绕过端口级/包过滤 ACL，利用「业务端口开放」策略 
防火墙：443 放行 → 攻击者 HTTPS 隧道 → 内网 C2 / 数据渗出

防护

手段 说明
TLS 检测/解密 检查加密载荷（企业代理、SSL 中间人 — 有隐私与合规成本）
正向代理 强制流量经代理审查，非直连
流量行为分析 连接频率、字节模式、DNS/ SNI 异常等 — 不依赖明文

→ ACL 端口放行策略：7.2 §三条规则 · 7.5

二、NAT 状态耗尽攻击 (State Exhaustion)

原理

项 说明
手法 向 NAT/防火墙发送大量新建/半开连接（如伪造 SYN flood）
结果 conntrack 连接跟踪表 / NAT 映射表占满
影响 新连接无法建立 → 内网用户断网（已有连接可能仍存活）

特点

项 说明
NAT 定位 侧重地址转换，并非专业安全设备
瓶颈 状态表容量有限 → 易成为可用性单点
与 7.5 关联 表满现象同 7.5 §conntrack — 此处强调主动攻击触发

一句：打爆连接跟踪表，破坏的是可用性，不一定是机密性。

三、缓解方案

# 手段 说明
1 限流 限制单 IP / 单源新建连接速率；每源映射数上限
2 调优 缩短会话老化超时；扩容 conntrack 表项（/proc/sys/net/netfilter/nf_conntrack_max — 仍有限）
3 架构优化 核心业务部署 DMZ；或原生 IPv6 直连，规避 NAT 状态瓶颈

过滤先于 NAT：先 Drop 垃圾流，减少占表 — 7.5 架构

补充：其他状态化攻击面

攻击 说明
分片绕过 操纵分片偏移，非法 L4 信息在首包审查后于内网重组 — 严格碎片策略
状态注入 伪造 ACK/序列号误导状态表

→ 源 IP 伪造：ch05 §5.7 · uRPF、TCP MSS 限制

考点速记

# 要点
1 隧道绕过：利用常用开放端口（80/443） 隐藏恶意流量
2 状态耗尽：打爆 conntrack / NAT 映射表 → 新连接失败 → 可用性 DoS
3 防护：限流、调超时/扩表、架构拆分（DMZ/v6）、TLS 检测/代理/行为分析
易错 正确
NAT 能防 DDoS NAT 非安全设备；状态表满 → 断新连
只开 443 就安全 HTTPS 隧道可藏 C2 — 需深度检测或行为分析
扩表一劳永逸 扩容有限；需 限流 + 过滤先于 NAT

cat /proc/sys/net/netfilter/nf_conntrack_max     # 上限

疑问与总结

背：443 隧道 bypass 端口过滤；SYN flood 打满 conntrack 断新连；限流+超时+DMZ/v6 缓解。
