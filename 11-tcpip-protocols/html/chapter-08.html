引言

章级精读：../study.md · IP：ch05

本节核心目标

理解 ICMP 作为 IP 层控制与诊断协议的角色。

核心要点

ICMP（Internet Control Message Protocol）工作在 IP 层之上，用于传递错误报告和网络诊断信息。

功能 ICMP 类型 示例
错误报告 Destination Unreachable (3) 路由不可达、端口不可达
诊断 Echo Request/Reply (8/0) ping
路由控制 Redirect (5) 更优路由通知
PMTUD Fragmentation Needed (3/4) 路径 MTU 发现
IPv6 ND ICMPv6 133-137 邻居发现

ICMP 不是什么

  • 不是传输层协议——不携带应用数据
  • 不是可靠协议——不重传、不确认
  • 不是路由协议——仅传递控制信息

HFT 关联

ICMP 类型 HFT 用途
Echo (ping) 延迟监控、链路健康检查
PTB (3/4) PMTUD，避免 UDP 分片
Redirect (5) 数据中心路由优化
Port Unreachable UDP 服务探测

注意：防火墙过滤 ICMP 会破坏 PMTUD → UDP 大包黑洞。

  3. ping 用的什么 ICMP 类型？

ICMP 报文格式

章级精读：../study.md

本节核心目标

掌握 ICMP 报文结构和 Type/Code 字段。

报文结构

┌──────────────────────────────────────┐
│ Type (8) │ Code (8) │ Checksum (16) │
├──────────────────────────────────────┤
│           Rest of Header (32)         │
├──────────────────────────────────────┤
│           Data (variable)             │
└──────────────────────────────────────┘
字段 说明
Type 消息类型（0-255）
Code 类型下的子码
Checksum 覆盖整个 ICMP 报文
Rest of Header 因 Type 而异（如 Echo 的 ID+Seq）

常用 Type

Type 名称 用途
0 Echo Reply ping 响应
3 Destination Unreachable 不可达报告
5 Redirect 路由重定向
8 Echo Request ping 请求
11 Time Exceeded TTL 超时（traceroute）
12 Parameter Problem IP 头错误

HFT 关联

理解 ICMP Type/Code 有助于调试网络问题——如收到 Type 3 Code 4 (Fragmentation Needed) 说明 UDP 包太大需要 PMTUD。

自测题

  1. ICMP Type=8 和 Type=0 分别是什么？它们如何配合工作？
  2. Type=11 在 traceroute 中起什么作用？
  3. ICMP Checksum 覆盖哪些内容？

ICMP 错误消息

章级精读：../study.md · IP：ch05

本节核心目标

掌握 Destination Unreachable 和 Time Exceeded 错误消息。

Destination Unreachable (Type 3)

Code 含义 典型场景
0 Net Unreachable 路由表中无目标网络
1 Host Unreachable 到达目标网络但主机无响应
2 Protocol Unreachable IP 协议号不支持
3 Port Unreachable UDP/TCP 端口未监听
4 Fragmentation Needed PMTUD 核心消息
5 Source Route Failed 源路由失败

Port Unreachable (3/3)：UDP 发到未监听端口 → ICMP Type 3 Code 3 回给发送方。

Fragmentation Needed (3/4)：路由器收到 DF=1 且超 MTU 的包 → 丢弃 + 发 ICMP PTB → 发送方降低包大小。

Time Exceeded (Type 11)

Code 含义
0 TTL 超时（转发中）
1 分片重组超时

traceroute 原理：逐步增加 TTL → 每跳路由器返回 ICMP Time Exceeded → 记录路径。

# traceroute 工作原理
TTL=1 → 第一跳路由器 → ICMP Time Exceeded
TTL=2 → 第二跳路由器 → ICMP Time Exceeded
...
TTL=N → 到达目标 → ICMP Echo Reply

ICMP 错误的限制

  • 不为 ICMP 错误消息发送 ICMP 错误（防风暴）
  • 不为广播/组播发 ICMP 错误
  • 不为分片非首片发 ICMP 错误
  • 速率限制（防 DDoS）

HFT 关联

错误消息 HFT 影响
Port Unreachable UDP 服务不可用检测
Fragmentation Needed PMTUD 核心——分片黑洞排查
Time Exceeded 网络路径诊断

  1. Type 3 Code 4 消息在 PMTUD 中起什么作用？
  2. traceroute 如何利用 ICMP Time Exceeded？
  3. 为什么 ICMP 错误消息不回应 ICMP 错误？

ICMP 查询消息与 Ping

章级精读：../notes.md

本节核心目标

理解 Echo Request/Reply 和 ping 的工作原理。

Echo 机制

发送方 → Echo Request (Type=8, ID=x, Seq=n)
接收方 → Echo Reply  (Type=0, ID=x, Seq=n)
字段 说明
Identifier 匹配请求与响应（同一 ping 会话）
Sequence Number 递增，用于计算 RTT 和丢包率
Data 可选时间戳/自定义数据

Ping 的功能

# 基本 ping
ping -c 4 8.8.8.8

# 输出:
# 64 bytes from 8.8.8.8: icmp_seq=1 ttl=117 time=12.3 ms
# 64 bytes from 8.8.8.8: icmp_seq=2 ttl=117 time=11.8 ms

# 指定包大小（测试 PMTUD）
ping -s 1472 -M do 8.8.8.8  # -M do = 设 DF 位

# 洪泛模式（HFT 延迟测试）
ping -f 8.8.8.8  # 需要 root

RTT 计算

发送 Echo Request 时记录 t1
收到 Echo Reply 时记录 t2
RTT = t2 - t1

注意：ICMP 处理在内核中，RTT 包含内核处理延迟。HFT 延迟测试用 UDP/TCP 更真实。

HFT 关联

Ping 用途 HFT 场景
延迟监控 持续 ping 对端，监控 RTT 变化
链路健康 快速 ping 检测链路断开
PMTUD ping -s N -M do 探测路径 MTU
路径诊断 ping -R 记录路由（有限）

局限：ICMP 优先级低，部分路由器限速/丢弃 ICMP → ping RTT 不代表真实延迟。

自测题

  1. Echo Request 和 Echo Reply 的 Type 分别是什么？
  2. ping -s 1472 -M do 测试什么？
  3. 为什么 ping RTT 可能不等于真实 TCP/UDP 延迟？

IPv6 邻居发现 (NDP)

章级精读：../study.md · ARP：ch04

本节核心目标

理解 ICMPv6 邻居发现协议（NDP），对比 ARP 的差异。

NDP vs ARP

ARP (IPv4) NDP (IPv6)
协议层 链路层之上 ICMPv6（IP 层）
传输 广播 组播（Solicited-Node）
消息类型 Request/Reply RS/RA/NS/NA
安全 无 SEND（可选加密）
状态 无状态 可有状态（DAD）

ICMPv6 NDP 消息

Type 消息 用途
133 Router Solicitation (RS) 请求路由器通告
134 Router Advertisement (RA) 路由器通告前缀/参数
135 Neighbor Solicitation (NS) 解析邻居 MAC（替代 ARP Request）
136 Neighbor Advertisement (NA) 邻居 MAC 回复（替代 ARP Reply）
137 Redirect 路由重定向

地址解析流程

1. 主机 A 要发送到 2001:db8::1
2. 发 NS (ICMPv6 Type 135) 到 Solicited-Node 组播地址
   FF02::1:FF00:1 (基于目标 IPv6 后 24 位)
3. 目标主机收到 → 回 NA (Type 136) 含其 MAC
4. 主机 A 缓存邻居条目

优势：用组播而非广播 → 不打扰无关主机。

DAD (Duplicate Address Detection)

主机配置 IPv6 地址前先发 NS 确认无冲突 → 如果收到 NA 说明地址已被使用。

HFT 关联

IPv6 NDP 的组播地址解析比 ARP 广播更高效——不干扰无关主机。但首次解析仍有延迟，需预热邻居缓存。

  1. NDP 用什么替代 ARP 的广播请求？

  3. DAD 的作用是什么？

ICMPv4/v6 转换

章级精读：../study.md · NAT64：ch07

本节核心目标

理解 ICMP 在 IPv4/IPv6 转换中的处理。

转换需求

NAT64 网关在 IPv4 和 IPv6 之间翻译时，ICMP 消息也需要翻译：

IPv4 ICMP IPv6 ICMPv6 说明
Type 3 Code 3 (Port Unreach) Type 1 Code 4 端口不可达
Type 3 Code 4 (Frag Needed) Type 2 (Packet Too Big) PMTUD
Type 8/0 (Echo) Type 128/129 Ping
Type 11 (Time Exceeded) Type 3 (Time Exceeded) TTL 超时

MTU 翻译

ICMP PTB 消息中的 MTU 值也需要调整（IPv6 最小 MTU=1280）：

IPv4 PTB: MTU=1500 → IPv6 PTB: MTU=1280 (最小值)

HFT 关联

HFT 系统一般不涉及 ICMP 转换——数据中心统一 IPv4 或 IPv6。但跨数据中心 WAN 可能经过 NAT64。

ICMP 攻击

章级精读：../study.md · 安全：ch18

本节核心目标

理解利用 ICMP 的攻击及防御策略。

主要攻击

攻击 机制 防御
Smurf 伪造源 IP → ping 广播地址 → 放大 禁止广播 ICMP
ICMP 隧道 ICMP Data 字段封装数据 → 绕过防火墙 深度检测 ICMP
Redirect 欺骗 伪造 ICMP Redirect → 劫持路由 忽略 Redirect 或验证
PTB 伪造 伪造 ICMP PTB → 强制降低 MTU → 性能攻击 验证 PTB 来源
Ping of Death 超大 ICMP 包 → 旧系统崩溃 现代内核已修复

Smurf 攻击

攻击者 → 广播地址 (伪造源 IP = 受害者)
  ICMP Echo Request → 网络中所有主机回复 Echo Reply
  → 全部打向受害者
  放大率 = 网络中主机数

防御：路由器禁止向广播地址转发 ICMP（BCP 38/RFC 2827）。

ICMP Redirect

路由器发 Redirect 告知主机"有更优路径" → 主机更新路由表。攻击者可伪造 Redirect 劫持流量。

# Linux: 禁用 ICMP Redirect 接受
sysctl net.ipv4.conf.all.accept_redirects=0
sysctl net.ipv4.conf.default.accept_redirects=0
sysctl net.ipv6.conf.all.accept_redirects=0

HFT 关联

攻击 HFT 影响
PTB 伪造 MTU 被恶意降低 → 吞吐下降
Redirect 欺骗 流量被劫持 → 信息泄露
ICMP 隧道 隐蔽通道 → 数据泄露

防御：防火墙限制 ICMP 类型 + 加密 + 专线隔离。

  3. 为什么应该禁用 ICMP Redirect 接受？
