1.1

体系结构原则

英文：Architecture Principles 章级精读：../study.md#ch01-principles

本节核心目标

弄懂互联网最根本的三个设计思路，就能理解网络为何如此运转。

精简研学版

1. 分组交换 (Packet Switching)

  • 数据拆分为独立分组传输，链路多路复用，不独占通道。
  • 相较电路交换：容错性更强；单点链路故障不阻断整体通信。

2. 端到端论点 (End-to-End Argument)

复杂业务语义必须在通信两端系统完整实现；底层网络仅提供尽力而为的基础转发。

适合端点实现 中间网络局限
重传、校验 脱离应用场景
业务安全 设备升级成本高
功能迭代 适配性差

3. 命运共享 (Fate Sharing)

  • 连接状态留存于通信端点，不托管给中间路由设备。
  • 中间节点恢复后，端点可接续通信，不会因网络侧状态丢失而彻底中断。

易混：端到端 ≠ 全功能上移应用层；命运共享 ≠ 中间设备永不坏。

新手易懂版

这一节讲互联网最根本的三个设计思路。

一、分组交换

简单理解：把大文件拆成一个个小数据包来传送。

  • 日常类比：寄大件快递，拆成多个小包裹分开运，不用单独占用整条运输路线。
  • 对比电路交换：打电话那样独占线路，线路坏了通话直接断。
  • 优势：一条线路出问题，数据包可以换路；线路也能同时供很多人用，网络不容易彻底瘫痪。

二、端到端论点

核心想法：复杂功能交给两台通信的电脑/设备处理；中间路由器、交换机只负责单纯转发。

适合放在两端设备做的事：数据纠错、重发、加密保密、开发新功能。

中间网络只做简单转发就好——若把复杂功能放在沿途设备上：

  • 没法贴合不同软件、不同场景的需求
  • 更新功能要改全网设备，成本高、麻烦

补充误区：不是所有功能都丢给终端；基础转发仍由中间网络负责。

三、命运共享

通俗解释：通信相关的记录信息，保存在收发两端设备里，不要只存在中途网络设备上。

  • 举例：两台电脑传文件，中途路由器临时掉线。
  • 只要两台电脑本身没崩溃，网络恢复后往往能接着传，不必从零重来（具体协议行为因 TCP/应用而异，原则是状态跟端点走）。

两个容易搞错的知识点

  1. 端到端 ≠ 所有网络功能都要在电脑软件里实现。
  2. 命运共享 ≠ 网络设备不会坏；是靠端点留存状态，尽量让通信不要轻易断干净。

四、部署架构演进：C/S → B/S（与 HTTP/TCP/IP 对齐）

书上 1.1 讲「互联网宪法」三原则；C/S、B/S 是怎么用这些原则做业务——和 1.5 C/S·P2P · 自顶向下 §2.1 互补，本节侧重演进时间线。

人话定义

全称 你要装啥 例子
C/S Client / Server 专用客户端 QQ、迅雷、老版财务软件
B/S Browser / Server 浏览器即可 淘宝网页、网课、钉钉网页版

演进时间线（必背顺序）

① 两层 C/S     客户端 ──────────────► 数据库
   胖客户端：界面+逻辑+连库都在客户端；内网财务/进销存
   问题：每台装软件、升级累；直连库不安全、并发弱

② 三层 C/S     客户端 ──► 应用服务器 ──► 数据库
   逻辑上移到应用层；仍要装专用软件

③ B/S          浏览器 ──► Web服务器 ──► 应用服务器 ──► 数据库
   把「客户端」换成浏览器；业务全在服务器；通信统一 HTTP/HTTPS

两层 C/S 结构图（胖客户端直连库）

  • 客户机：界面 + 业务逻辑 + 直连数据库 的连接都在本机（胖客户端）。
  • 服务器：实质是 DBMS（数据库管理系统），主要存数据、执行 SQL。
  • 数据请求：客户端发查询/更新，服务器返回结果——没有单独的应用服务器层。
  • 典型问题：升级要逐台装客户端；客户端握有库账号，安全与并发都差。

三层 C/S（过渡，无独立配图）

客户机（瘦一点）── 数据请求 ──► 应用服务器（业务逻辑）──► 数据库
  • 业务逻辑从客户端抽到应用服务器；客户端仍要安装，但不再直连数据库。
  • 仍不如 B/S 省事；现代桌面软件、游戏、部分企业内网仍常见此形态。

B/S 为何取代大量桌面 C/S： 免安装 · 只升服务器全网更新 · Win/Mac/手机同源 · 与 HTTP 天然一致。

B/S 结构图（瘦客户端）

  • 浏览器：极瘦——渲染页面、表单输入；不算业务权威。
  • Web / 应用服务器：极厚——业务逻辑、权限、会话；符合 端到端论点（复杂语义在端点系统，此处「端点」含服务器进程）。
  • 数据库：持久化；不让浏览器直连（两层 C/S 的老毛病）。

一句话对比

C/S B/S
安装/升级 要装客户端，逐台升级 浏览器即用，升服务器即可
跨平台 差（常绑 Windows） 好
性能/复杂 UI 通常更强 复杂交互、大文件略弱
应用层协议 常 私有协议（自定义 TCP 端口） HTTP/HTTPS 标配

和你已学协议栈对齐

B/S 一次网页访问：
浏览器 ── HTTP/HTTPS（应用层）──► Web/应用服务器
         └── TCP ── IP ── 链路层（以太网 / Wi‑Fi / PPPoE 三选一）

老 C/S：
专用客户端 ── 常非 HTTP 的 TCP/UDP ──► 应用服务器
原则 在 B/S 里的体现
端到端 TLS、重传、业务校验在浏览器+服务器两端；路由器只转发
命运共享 会话/TCP 状态在端点（浏览器 cookie、服务器 session），不靠中间路由器记业务状态
分组交换 每个 HTTP 响应拆成 IP 分组，多路复用链路

→ HTTP 四段报文：§2.2 HTTP · 链路层日常场景：§6.1 三选一

后续拓展留白

  • [ ] 前后端分离：Vue/React + REST API（B/S 内部再演进）
  • [ ] 混合架构：Electron / Flutter（网页技术写「客户端」，本质仍 C/S）
  • [ ] 云原生：微服务 + Docker/K8s + Serverless
  • [ ] 安全：C/S 逆向 · B/S HTTPS / CSRF / XSS

30 秒背诵版

C/S 要装软件、快但升级烦；B/S 浏览器就行、好维护、走 HTTP。演进：两层 C/S → 三层 C/S → 浏览器换客户端。

1.2

设计和实现

英文：Design and Implementation 章级精读：../study.md

本节核心目标

分清网络规则标准与实际运行程序；弄懂分层及封装 / 复用 / 分解。

精简研学版

分层 (Layering)

  • 复杂通信拆成多层，每层只处理一个方面（寻址、可靠传输、应用语义等）。
  • 改动某层实现不影响其他层（如换网卡驱动不改 HTTP 逻辑）。
  • OSI 七层（理论） vs TCP/IP 四层（实务）。

封装、复用、分解

术语 方向 含义
封装 发送 上层数据加本层首部，层层包裹
复用 发送 多路数据共用一条链路，靠首部区分
分解 接收 自外向内拆首部，交给正确上层 
应用数据 → 传输层首部 → 网络层首部 → 链路层首部 → 帧

实现要点

  • 同一标准可有多种实现（性能、缓冲策略不同）。
  • 抓包可见逐层首部，非杂乱整体。

新手通俗版

本节分清：规则怎么写（标准）和设备上怎么跑（实现）。

一、分层设计

把复杂网络通信拆成多层，每层只做专属任务：

  • 寻址找设备、稳定传数据、软件交互各司其职。
  • 好处：改某一层程序，不影响其他层；换硬件驱动也不用改网页、聊天软件逻辑。
  • 两类模型：理论常用 OSI 七层；实际上网多用 TCP/IP 四层。

二、封装、复用、分解

1. 封装 发送时，每一层给收到的数据加上本层头部，层层包裹。

简单流程：

原始聊天文字 → 加传输层标签 → 加网络地址标签 → 加链路设备标签 → 完整数据包

2. 复用 多条数据共用一条线路，靠头部里的标识区分，不会互相混淆。

3. 分解 接收方从外到内依次拆掉头部，按标识把数据交给对应的程序（正确的端口/协议）。

三、实际实现要点

  1. 统一标准，不同系统可以写不同的程序实现同一套规则，运行效率、处理方式会有差别。
  2. 抓包时能看到一层层包裹的头部，并不是一团杂乱数据。

OSI 七层 vs TCP/IP 四层（新手对比）

一句话总览

模型 定位
OSI 七层 专家设计的理想理论模型，分得细，用于学习、理解、排错
TCP/IP 四层 互联网实际在用的模型，合并简化 OSI，所有上网设备按它工作

对应关系（从上到下）

OSI 七层（理论） TCP/IP 四层（实务） 简单理解
应用层 应用层 微信、浏览器（你直接用的功能）
表示层 （合并到应用层） 加密、格式转换（如 HTTPS）
会话层 （合并到应用层） 建立/断开连接（登录、退出）
传输层 传输层 TCP 靠谱送、UDP 快送；端口号
网络层 网络层 IP 地址、路由器选路
数据链路层 网络接口层 帧、MAC、网卡、交换机
物理层 网络接口层 网线、光纤、WiFi 的 0/1 信号

OSI 七层通俗讲

层 角色 协议/设备举例
7 应用 你直接用的软件 HTTP、FTP、SMTP
6 表示 翻译+加密 HTTPS 里的加密与编码
5 会话 连接管理员 登录后保持在线
4 传输 快递总管 TCP（网页/文件）、UDP（直播/游戏）；端口 80=网页
3 网络 导航员 IP、路由器
2 数据链路 打包+验错 帧、MAC、网卡、交换机
1 物理 传信号 网线、光纤、WiFi

TCP/IP 四层通俗讲

层 对应 OSI 内容
4 应用 7+6+5 HTTP/HTTPS、DNS、FTP、SMTP
3 传输 4 TCP、UDP、端口号
2 网络 3 IP、路由
1 网络接口 2+1 以太网、WiFi(802.11)、PPP；帧+物理传输

为何有两个模型？

  • OSI：标准化、教学、排错逻辑清晰，但太复杂，设备很少完全按七层实现。
  • TCP/IP：实用、简单、好实现，互联网从早期沿用至今。

新手记住 3 点

  1. 理论看 OSI，实际上网用 TCP/IP 四层。
  2. 上层=软件（应用），中层=传输（TCP/UDP），下层=硬件（网线+网卡）。
  3. 发送：从上到下打包；接收：从下到上拆包（见上文 封装与分解）。

ASCII 极简对比图

  【你用的软件】  浏览器 / 微信 / DNS
        │
  OSI 7,6,5  ─┐
  TCP/IP 应用层 ┘  HTTP / HTTPS / DNS …
        │
  OSI 4 ─┐
  TCP/IP 传输层 ┘   TCP（可靠）  UDP（快）  + 端口号
        │
  OSI 3 ─┐
  TCP/IP 网络层 ┘   IP 地址 + 路由器
        │
  OSI 2,1 ─┐
  TCP/IP 网络接口层 ┘  帧/MAC + 网线/WiFi/光纤
        │
     [ 对端设备，自下而上拆包 ]
1.3

TCP/IP 协议族结构和协议

章级导读：../study.md · 端口分解：#ch1-port

本节核心目标

掌握全书采用的 ARPANET / TCP/IP 参考模型各层职责，以及 IP 地址 + 端口号 如何实现主机到进程的交付。

ARPANET 参考模型（全书主线）

层 典型协议 职责
应用层 HTTP、DNS、SMTP… 应用语义、报文格式
传输层 TCP、UDP 端到端进程间交付、可靠性/无连接选择
网络层 IPv4 / IPv6、ICMP 主机到主机、路由与分片
链路层 以太网、Wi‑Fi、PPP… 相邻节点帧传输

（书中常把链路与网络之间的细节并入“链路层”讨论。）

寻址与端口

  • IP 地址：标识主机（网络层）。
  • 端口号（16 位）：在同一主机上标识应用程序进程/套接字（传输层）。
  • 接收方用 目的 IP + 目的端口（及协议号）做分解，把段交给正确应用。
五元组（TCP）：源 IP、源端口、目的 IP、目的端口、协议
四元组（UDP）：同上（无连接状态）

与 OSI 的对照（速记）

  • OSI 更细（会话层、表示层独立）；TCP/IP 实用合并到应用层。
  • 学习时以 TCP/IP 四层 抓包、读 Stevens 后续章节为准。
  • 新手详解 + 对照表 + ASCII 图 → 1.2 §OSI vs TCP/IP
1.4

Internet、内联网和外联网

章级导读：../study.md

本节核心目标

区分三种网络范围的边界、访问策略与典型部署（防火墙、VPN）。

概念对照

类型 范围 访问特点
Internet（互联网） 全球公共互联 默认面向公众路由可达（受策略限制）
Intranet（内联网） 企业/机构内部专用 私有地址、防火墙隔离，员工内部访问
Extranet（外联网） 内网的有限外延 经 VPN 等向合作伙伴/特定外部用户开放受控区域

部署要点

  • Intranet 常用 RFC1918 私有地址 + NAT（见第 7 章）。
  • Extranet 强调身份认证、最小权限、审计，而非“整网裸露公网”。
  • 安全边界：默认拒绝、按需放行（与 1.8 攻击面呼应）。

易混

  • Extranet 不是第二个 Internet，而是内网策略下的可控对外窗口。
1.5

设计应用 (Designing Applications)

章级导读：../study.md · Socket：#ch1-socket

本节核心目标

理解 C/S 与 P2P 架构差异，以及应用如何通过 API（套接字） 使用协议栈。

客户机 / 服务器 (C/S)

  • 服务器：被动监听、长期运行，处理并发请求（多进程/多线程/事件驱动）。
  • 客户端：主动发起连接/请求。
  • 典型：Web、邮件、数据库访问。

→ C/S → B/S 演进、HTTP 对齐：1.1 §四

对等 (P2P)

  • 节点既消费又提供服务（如 Skype、BitTorrent）。
  • 优势：去中心、扩展性好、分担带宽与存储。
  • 代价：NAT 穿透、成员管理、内容可用性更复杂。
C/S P2P
中心性 明确服务器 常无固定中心
扩展 服务器可能成为瓶颈 节点越多资源越多
运维 集中升级 版本/信誉分散

API 与套接字 (Socket)

  • 应用程序不直接操作网卡，通过 Socket API 与内核协议栈交互（socket / bind / listen / connect / send / recv 等）。
  • 套接字 = IP + 端口 + 协议 在主机上的抽象端点。
  • 与 Computer Networking 2.7 编程章可交叉练习。
1.6

标准化进程 (Standardization Process)

章级导读：../study.md

本节核心目标

了解 Internet 协议如何由社区制定并演进为事实标准。

IETF

  • Internet 工程任务组 (IETF)：通过工作组讨论、实现与互操作经验推动协议成熟。
  • 文化：运行代码 (running code) 与开放文档并重。

RFC 与标准轨迹

  • 技术文档以 RFC（Request for Comments） 发布（如 TCP、IP、HTTP 早期版本）。
  • 演进路径（简化）：草案 → Proposed Standard → Internet Standard (STD)，旧版可被更新或废弃。
  • 读协议：以最新 RFC + 勘误为准，注意 “Historic / Experimental” 标记。

实践建议

  • 抓包异常时对照 RFC 首部字段定义。
  • 厂商扩展常写进 RFC 或厂商文档；互操作问题先查是否偏离标准。
1.7

实现和软件分发

章级导读：../study.md

本节核心目标

建立 TCP/IP 实现史 脉络，理解 BSD 网络栈 对现代操作系统的影响。

Berkeley 软件分发 (BSD)

  • BSD 系统附带完整、可研究的 TCP/IP 实现（如 4.2BSD、4.3BSD、4.4BSD-Lite）。
  • 许多 API 语义、数据结构、ioctl 行为源自 BSD，成为事实标准。

对现代系统的影响

系统族 关系
Linux 网络栈与 Socket 语义大量借鉴 BSD 传统
macOS / iOS 源自 BSD 系
Windows Winsock 抽象与 BSD Socket 概念对齐（API 细节不同）

学习意义

  • 读 Stevens 示例代码时，errno、非阻塞、SIGIO 等常与 BSD 起源相关。

1.8

与 Internet 体系结构相关的攻击

章级导读：../study.md · 1.1 端到端/命运共享 · 全书安全：第 18 章 厚版背诵（分层总表+防御+链路对齐）：自顶向下 §8 一页表

本节核心目标

认识早期 Internet 默认信任、明文传输 带来的基础威胁；理解攻击与 分层架构 的对应关系，以及 TLS / IPsec / 防火墙 等演进的动机（与 1.1 端到端 论点一致：复杂安全语义应在端点闭合）。

设计背景

  • 早期侧重连通性与简单性，缺乏原生身份、完整性、机密性机制。
  • 中间网络被假定为「可能出错但非恶意」→ 与今日威胁模型差距大。
  • 根因常是架构假设过时，不是单一实现 bug；不能仅靠「信任运营商」。

典型攻击总表（本章级 · 补全）

攻击 原理（人话） 关联层 防御要点（预告）
IP 欺骗 (Spoofing) 伪造源 IP，接收方以为是可信主机，难以溯源 网络层（IP） BCP38/uRPF 详读
DoS / 拒绝服务 海量无效流量 / 半开连接，耗尽带宽、CPU、连接表 多层面 限速、CDN、SYN Cookie、清洗
窃听 (Eavesdropping) 明文或无线链路上抓包，直接看账号密码等 链路嗅探 + 应用明文 TLS/HTTPS、WPA3
ARP 欺骗 伪造 ARP 响应，改内网 IP→MAC 表，流量被劫持 链路层（ARP） DAI、802.1X；上层加密
MAC 欺骗 / MAC 泛洪 伪造源 MAC，或塞满交换机 CAM 表 → 泛洪、易被监听 链路层（帧/交换机） 端口安全、MAC 绑定、VLAN
TCP 劫持 / 会话劫持 猜到 TCP 序号，插入会话，篡改或冒充通信 传输层（TCP） 强随机 ISN、TLS
SYN 洪泛 (SYN Flood) 大量 SYN 不回 ACK，占满半开连接表 传输层（TCP） SYN Cookie、防火墙
UDP 洪水 海量 UDP 占满带宽或拖垮应用（含反射放大） 传输层（UDP） 限速、关不必要 UDP 端口
DNS 欺骗 / 缓存投毒 伪造 DNS 应答，域名→恶意 IP（钓鱼） 应用层（DNS） DNSSEC、DoH/DoT
HTTP 劫持 / MITM 中间截获 HTTP，改页面、插广告、偷密码 链路→应用 HTTPS + HSTS、证书校验

→ 与已学协议栈逐节对照：top_down 分层表

每层一句话（串 HTTP / TCP / IP / 链路）

层 核心（你已学） 典型攻击 本质
链路 帧、MAC、ARP、交换机 ARP 欺骗、MAC 欺骗/泛洪、无线窃听 内网默认信任，缺身份验证
网络 IP、路由 IP 欺骗、分片攻击、ICMP 洪水 不验源 IP，只管转发
传输 端口、TCP 握手/SEQ SYN 洪水、TCP 劫持、UDP 洪水 握手与序号可伪造/预测

浏览器 ── HTTPS/TLS（应用层机密+完整+鉴别）──► 服务器
         └── TCP ── IP ── 以太网 / Wi‑Fi（§6.1 三选一）

考点 · 30 秒背诵

  • 链路：ARP 欺骗 · MAC 欺骗/泛洪 · 无线窃听
  • 网络：IP 欺骗 · ICMP/分片类
  • 传输：SYN 洪水 · TCP 劫持 · UDP 洪水
  • 应用：HTTP 劫持 · DNS 欺骗 · SQL 注入 · XSS

口诀：链偷 ARP MAC，网骗 IP，传 SYN 劫，应 HTTP DNS 注。

  • 攻击根因 = 架构假设过时；端到端安全要求在端点语义上闭合（1.1）。
  • 加密 ≠ 鉴别；仅有 TLS 信道仍须校验证书，防 MITM。
