# 11.1 引言

> 章级精读：[../study.md#ch11-1](study.md#ch11-1) · 应用层入口：§2.4

## 本节核心目标

理解 DNS 作为 Internet **分布式电话簿**的角色，以及它为什么必须分布式。

---

## 核心要点

- 人类用**域名**（`www.example.com`），协议栈用 **IP**
- DNS 提供 **名字 ↔ 地址**（及邮件路由等）映射
- 与 [ch10 UDP/53](../chapter10-udp-ip-fragment/study.md) 承载查询/应答

---

## 为什么必须分布式

| 因素 | 说明 |
|------|------|
| **规模** | 全球数十亿节点，单库无法维护 |
| **延迟** | 单点查询延迟不可接受 |
| **容错** | 单点故障 = 全网瘫痪 |
| **管理** | 各域自治，不可能全球统一写入 |

解决方案：**分层命名空间 + 委派 + 缓存**。

---

## DNS 在协议栈中的位置

```
应用层:  HTTP → 需要解析 www.example.com
         ↓ 调用 getaddrinfo()
DNS 层:  解析器 → UDP/53 → 递归服务器 → 权威服务器
         ↓ 返回 IP
传输层:  TCP 连接到该 IP
```

DNS 是应用层的「基础设施」——几乎所有网络应用启动时都需要它。

---

## HFT 关联

| 场景 | DNS 角色 |
|------|---------|
| 交易服务器连接 | 预解析 IP，避免运行时 DNS 延迟 |
| 行情源发现 | 组播地址固定，但控制面可能用 DNS |
| 容灾切换 | DNS TTL 控制切换速度（但 60s 仍是 HFT 的 eternity） |

**HFT 最佳实践**：启动时解析 + `/etc/hosts` 硬编码 + 禁用运行时 DNS 查询。
