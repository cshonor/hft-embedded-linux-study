## 本节核心目标

掌握 DNS 主要攻击面及缓解策略。

---

## 缓存投毒

**原理**：伪造 DNS 响应，匹配 Transaction ID + 源端口 → 递归器缓存恶意记录。

| 攻击变体 | 机制 |
|----------|------|
| **Kaminsky 攻击** | 发海量伪造响应，提高 Transaction ID 碰撞概率 |
| **生日攻击** | 大量并行查询 + 伪造响应 → 概率碰撞 |

**缓解**：
- 随机化 Transaction ID（16-bit → 65536 种可能）
- 随机化源端口（16-bit → ~64000 种可能）
- 合计搜索空间 ~2^32 → 投毒难度大幅提高
- **DNSSEC** 签名验证（终极方案）
- 0x20 编码（查询名大小写随机化）
- QNAME 最小化

---

## 放大 DDoS

```
攻击者 → DNS 服务器（伪造源 IP = 受害者）
  查询: "ANY ." + EDNS0（30B 请求）
  响应: 3000B → 打向受害者
  放大率: ~100x
```

**缓解**：
- BCP38 源地址校验
- 服务器限速
- 禁用 ANY 查询（现代 DNS 服务器默认）

---

## DNSSEC

| 概念 | 说明 |
|------|------|
| **签名链** | 根 → TLD → 权威，逐级签名 |
| **RRSIG** | 记录的数字签名 |
| **DNSKEY** | 公钥 |
| **DS** | 委派签名（父区对子区公钥的哈希签名） |
| **验证** | 递归器验证签名链 → 拒绝伪造应答 |

DNSSEC 不加密 DNS 流量，仅验证**数据完整性 + 来源真实性**。

---

## HFT 关联

| 威胁 | HFT 影响 |
|------|---------|
| 缓存投毒 | 交易流量被导向恶意服务器 → 信息泄露/伪造交易 |
| 放大 DDoS | 网络拥塞 → 行情/交易延迟 |
| DNSSEC 验证延迟 | 增加 DNS 查询时间 |

**HFT 建议**：硬编码 IP + VPN/专线 + 不依赖公网 DNS。
