# 11.4 DNS 缓存

> 章级精读：[../study.md#ch11-4](study.md#ch11-4)

## 本节核心目标

理解 DNS 缓存的**弱一致性**模型、TTL 机制和迁移实践。

---

## 核心概念

| 术语 | 说明 |
|------|------|
| **TTL** | 权威设定的记录生存时间（秒） |
| **负缓存** | 缓存 **NXDOMAIN**，避免反复无效查询 |
| **缓存层级** | 浏览器 → OS → 递归器 → 权威 |

---

## TTL 的影响

```
权威设定 TTL=3600s
  → 递归器缓存 1 小时
  → 全球所有递归器最长 1 小时后刷新
  → 迁移 IP 后最长 1 小时内旧 IP 仍被使用
```

**TTL 是延迟与一致性的折中**：
- TTL 长 → 缓存命中率高、延迟低 → 但迁移慢
- TTL 短 → 迁移快 → 但查询负载高、延迟增加

---

## 迁移实践

```
1. 迁移前 24-48h: 降低 TTL 到 60s
2. 等待旧 TTL 过期（全球缓存刷新）
3. 切换 IP（更新权威记录）
4. 验证全球递归器返回新 IP
5. 迁移后: 恢复 TTL 到正常值
```

---

## 权威应答 vs 缓存应答

| | 权威应答 | 缓存应答 |
|--|----------|----------|
| AA 标志 | **AA=1** | 无 AA |
| 数据来源 | 本地区域文件 | 上游递归查询 |
| TTL | 原始设定值 | 剩余倒计时 |

---

## 缓存投毒风险

伪造响应匹配 **Transaction ID** + **源端口** → 缓存恶意记录。

**缓解**：
- 随机化 Transaction ID（16-bit）
- 随机化源端口（16-bit）
- DNSSEC 签名验证
- 0x20 编码（大小写随机化）

---

## HFT 关联

| 场景 | 策略 |
|------|------|
| 交易服务器 IP | `/etc/hosts` 硬编码，跳过 DNS |
| 容灾切换 | 不依赖 DNS TTL——用 VIP/Anycast 即时切换 |
| 监控端点 | 短 TTL + 主动刷新 |
