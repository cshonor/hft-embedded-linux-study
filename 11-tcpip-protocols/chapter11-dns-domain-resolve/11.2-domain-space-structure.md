# 11.2 DNS 名称空间

> 章级精读：[../study.md#ch11-2](study.md#ch11-2)

## 本节核心目标

掌握 DNS 倒置树状名称空间结构和**委派（Delegation）**机制。

---

## 树状结构

```text
. (根)
├── TLD (.com, .cn, .org, …)
│   └── SLD (example.com)
│       └── 子域 / 主机名 (www, mail, api, …)
└── ccTLD (.uk, .jp, …)
```

| 术语 | 说明 |
|------|------|
| **域 (Domain)** | 名称空间中的一棵**子树**，逻辑管理边界 |
| **标签 (Label)** | 点分每一段；单标签 ≤ **63** 字节 |
| **FQDN** | 叶到根的完整名，标准以 **`.`** 结尾（`www.example.com.`） |
| **TLD** | 根下第一层：gTLD（`.com`）、ccTLD（`.cn`） |

---

## 命名语法

- 单标签 ≤ **63 B**；FQDN（含点）≤ **255 B**
- 字符：经典 **L-D-H**（Letter-Digit-Hyphen）；现代 **IDN** 国际化域名用 Punycode 编码

```
www.example.com.       ← FQDN（末尾点表示根）
  │   │      │  │
  │   │      │  └─ 根标签（空）
  │   │      └──── TLD: com
  │   └─────────── SLD: example
  └─────────────── 主机名: www
```

---

## 委派机制

父域通过 **NS 记录**将子域管理权交给子域的名称服务器：

```
.com 的 NS 记录中:  example.com → ns1.example.com, ns2.example.com
→ .com 不再管理 example.com 下的具体记录
→ 查询 www.example.com 时，.com 返回 NS 委派信息
```

**核心效果**：无单一机构持有全网数据；管理权逐级下放。

---

## 域名 vs 主机名

| | 域名 | 主机名 |
|--|------|--------|
| 含义 | **行政/管理**边界 | **具体节点** |
| 关系 | 可无主机（仅父节点） | 必属某域 |
| 例子 | `example.com` | `www.example.com` |
