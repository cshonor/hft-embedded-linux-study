# 16.2 经典算法

> 章级精读：[../study.md#ch16-2](../study.md#ch16-2)

## 本节核心目标

掌握 **慢启动、拥塞避免、Tahoe/Reno** 与 **AIMD** 哲学。

---

## AIMD 哲学

**无拥塞时加性增，拥塞时乘性减**：

```
无拥塞: cwnd += 1/RTT  (线性增长)
拥塞:   cwnd *= 0.5    (减半)
```

为什么不是线性减？因为拥塞是"全员"问题——乘性减让所有流同时降速，快速缓解拥塞。

---

## 慢启动 (Slow Start)

- 初值：**cwnd = 1×SMSS**（量级）
- 每收到一个 ACK → cwnd **+1** → 每个 RTT 约**翻倍**（指数增长）
- 直至 **cwnd ≥ ssthresh** → 切换到拥塞避免

「慢」是相对旧协议一次发满 awnd 而言——实际增长很快（指数）。

```
RTT 0: cwnd=1
RTT 1: cwnd=2
RTT 2: cwnd=4
RTT 3: cwnd=8
RTT 4: cwnd=16
```

---

## 拥塞避免 (Congestion Avoidance)

- **cwnd ≥ ssthresh**：每 RTT **cwnd += 1**（每 ACK **+1/cwnd**）→ **线性**增长

```
RTT 0: cwnd=16
RTT 1: cwnd=17
RTT 2: cwnd=18
```

---

## 拥塞检测

| 信号 | 典型反应 |
|------|----------|
| **超时** | cwnd→1，ssthresh=cwnd/2（最狠） |
| **3 dup ACK** | 快速重传/恢复（较温和） |

---

## Tahoe vs Reno

| 算法 | 丢包信号 | 反应 |
|------|----------|------|
| **Tahoe** | 3 dup ACK 或超时 | **cwnd=1**，慢启动 |
| **Reno** | 3 dup ACK | **快速恢复**：ssthresh=cwnd/2，cwnd=ssthresh+3 |
| **Reno** | 超时 | cwnd=1，慢启动（同 Tahoe） |

**快速恢复**细节：恢复期每多 1 dup ACK → cwnd+1；收到新 ACK → cwnd=ssthresh，退出。

---

## 代码示例

```bash
# 查看 Linux 拥塞控制算法
sysctl net.ipv4.tcp_congestion_control
# 输出: cubic (默认)

# 查看可用算法
sysctl net.ipv4.tcp_available_congestion_control
# 输出: reno cubic bbr

# 查看连接的 cwnd
ss -ti
# 输出示例: cubic wscale:7,7 rto:280 rtt:12.5/5 cwnd:10 ssthresh:20
```

## HFT 关联

| 算法 | HFT 影响 |
|------|---------|
| 慢启动 | 新连接初始吞吐低 → 预热连接 |
| AIMD | 丢包后吞吐减半 → 延迟增加 |
| CUBIC | Linux 默认，HFT 控制面够用 |
