# 12.1 引言

> 章级精读：[../study.md#ch12-1-1](study.md#ch12-1-1) · 对比 UDP：[ch10](../chapter10-udp-ip-fragment/study.md)

## 本节核心目标

理解 TCP 的核心特性：**面向连接、可靠、字节流、全双工**。

---

## TCP 核心特性

| 特性 | TCP | 对比 UDP |
|------|-----|----------|
| 连接 | 面向连接（三次握手） | 无连接 |
| 可靠性 | **保证**（重传+确认） | 不保证 |
| 顺序 | **保序**（序号重组） | 可能乱序 |
| 数据模式 | **字节流**（无边界） | 保留报文边界 |
| 流控 | 滑动窗口（rwnd） | 无 |
| 拥塞控制 | AIMD/CUBIC/BBR | 无 |
| 首部 | ≥20B + 选项 | 固定 8B |

---

## TCP 服务模型

```
应用层:  write(fd, data, 1000)
TCP层:   将 1000B 切分为段 → 加序号 → 发送 → 确认 → 重传
接收方:  TCP 重组 → 按原顺序交付 1000B → read(fd, buf, 1000)
```

**字节流语义**：`write(1000B)` 可能被拆成多个段发送；`read()` 可能一次只读到 500B——应用层需自己组装。这与 UDP 的 `sendto`/`recvfrom` 一一对应完全不同。

---

## HFT 关联

| TCP 特性 | HFT 影响 |
|----------|---------|
| 可靠性 | 重传 → 延迟尖峰（不利） |
| 字节流 | 需要应用层分帧（不利） |
| 拥塞控制 | AIMD 降速 → 吞吐波动（不利） |
| 有序 | 保序但队头阻塞（不利） |
| 连接状态 | 握手开销（可接受，预热解决） |

**结论**：TCP 适合 HFT 控制面（管理/日志），不适合热路径（行情/订单）。
