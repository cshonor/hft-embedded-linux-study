# 10.8 UDP 路径 MTU 发现

> 章级精读：[../study.md#ch10-5](study.md#ch10-5) · ICMP PTB：[ch08](../chapter08-icmpv4-icmpv6/study.md)

## 本节核心目标

理解 PMTUD 工作原理，掌握 UDP 应用如何避免分片。

---

## PMTUD 流程

```text
1. 发送方: IP 报文设 DF=1，发出
2. 中间路由器: 若 MTU < 报文大小 → 丢弃 + 发 ICMP PTB (Type 3 Code 4)
3. 发送方: 收到 PTB → 降低报文大小 → 重发
4. 重复直到成功
```

**问题**：ICMP PTB 可能被防火墙过滤（"PMTUD 黑洞"），发送方不知道该减小包。

---

## Linux PMTUD 相关

```c
// 设置 PMTUD 策略
int val = IP_PMTUDISC_DO;    // 总是设 DF，超限则收 ICMP PTB
// IP_PMTUDISC_DONT  → 允许分片
// IP_PMTUDISC_WANT  → 设 DF 但允许分片（折中）
// IP_PMTUDISC_PROBE → 设 DF 但不使用 PMTU 缓存（用于探测）
setsockopt(fd, IPPROTO_IP, IP_MTU_DISCOVER, &val, sizeof(val));

// 读取当前路径 MTU
int mtu;
socklen_t len = sizeof(mtu);
getsockopt(fd, IPPROTO_IP, IP_MTU, &mtu, &len);
// UDP 最大安全载荷 = mtu - 20(IP头) - 8(UDP头)
```

---

## PMTUD 黑洞检测

现代 Linux 内核有 PMTUD 黑洞检测（`net.ipv4.tcp_mtu_probing`），但 UDP 需要应用层自己处理：

1. 发送大包 → 超时无响应 → 可能是 PTB 被过滤
2. 回退到较小包大小（如 1280B，IPv6 最小 MTU）
3. 逐步探测更大数据包

---

## HFT 关联

| 场景 | 策略 |
|------|------|
| 行情分发 | 固定 ≤1400B，不做 PMTUD（简单可预测） |
| 跨数据中心 | 已知 MTU=9000（jumbo frame），直接用 |
| WAN 交易 | PMTUD + 超时回退到 1280B |
