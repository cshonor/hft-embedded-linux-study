# 10.10 UDP 数据报长度

> 章级精读：[../study.md#ch10-6](study.md#ch10-6)

## 本节核心目标

理解 UDP 数据报长度的理论极限与实际限制。

---

## 理论最大值

| 限制因素 | 最大值 |
|----------|--------|
| UDP Length 字段（16-bit） | 65535 字节（含 8B 头） |
| UDP 载荷 | 65527 字节 |
| IPv4 Total Length（16-bit） | 65535 字节 |
| IPv6 Payload Length（16-bit） | 65535 字节（jumbo 有例外） |

---

## 实际限制

| 场景 | 实际最大载荷 |
|------|-------------|
| 标准以太网 MTU=1500 | **1472** 字节（1500 - 20 IP - 8 UDP） |
| VLAN (MTU=1504) | ~1472 字节 |
| PPPoE (MTU=1492) | **1464** 字节 |
| VXLAN/Geneve (MTU~1450) | ~1422 字节 |
| Jumbo Frame (MTU=9000) | **8972** 字节 |
| 互联网安全值 | **≤1200** 字节（穿越各种隧道） |

**超过实际 MTU → IP 分片 → 丢包放大风险**

---

## sendto 与 recvfrom 行为

```c
// 发送：内核接受 > MTU 的数据报，但会分片
sendto(fd, buf, 8192, 0, &dst, sizeof(dst));  // 会分片

// 接收：缓冲区必须足够大，否则截断
char buf[65535];
int n = recvfrom(fd, buf, sizeof(buf), 0, &src, &len);
// n = 实际收到的完整数据报字节数
```

**注意**：UDP 保留报文边界——一次 `recvfrom` = 一个完整数据报。如果缓冲区小于数据报，多余部分**静默丢弃**（除非用 `MSG_TRUNC`）。

---

## HFT 关联

| 场景 | 推荐大小 |
|------|---------|
| 组播行情（L2 深度） | ≤1400B，不分片 |
| FPGA 网络帧 | 固定 64B / 128B / 256B |
| 日志/审计 | 可大但设 DF + PMTUD |
