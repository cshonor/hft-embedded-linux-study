# 10.1 引言

> 章级精读：[../study.md#ch10-1](../study.md#ch10-1) · 对比 TCP：[ch12](../../chapter12-tcp-basic/study.md)

## 本节核心目标

明确 UDP **无连接、不可靠、保留报文边界** 的语义，理解它为何是 QUIC/VXLAN/WebRTC 的基础运载层。

---

## 核心要点

| 特性 | UDP | 对比 TCP |
|------|-----|----------|
| 连接 | **无**握手状态 | 三次握手 + 状态机 |
| 可靠/顺序 | **不保证**（靠应用或 QUIC） | 序号 + 重传 + 重组 |
| 边界 | 一次 `sendto` = 一个 **datagram** | 字节流，无边界 |
| 拥塞控制 | **无** → 发太快可压垮路径与接收缓冲 | cwnd + AIMD |
| 头部开销 | **8 字节**固定 | ≥20 字节 + 选项 |

---

## 为什么 UDP 仍然重要

UDP 把端到端语义裁剪到「端口多路复用 + 可选数据完整性覆盖」，不做可靠性、不做流控、不做拥塞控制——**把所有复杂决策交给应用层**。这恰好是现代高性能场景需要的：

- **DNS**：一问一答，握手开销不可接受
- **VXLAN/Geneve**：数据中心 overlay 封装，内核转发路径短
- **QUIC/HTTP3**：在 UDP 上重建可靠性 + 多路复用 + 0-RTT，避开内核 TCP 栈的局限
- **WebRTC**：实时音视频，延迟敏感，偶尔丢包可接受
- **SNMP/Trap**：网管监控，不能因网络拥塞而阻塞

---

## UDP 不改变 IP 的什么

UDP 不修改 IP TTL、ToS、`Don't Fragment` 标志——这些仍由套接字选项或内核策略控制：

```c
// 设置 TTL
setsockopt(fd, IPPROTO_IP, IP_TTL, &ttl, sizeof(ttl));
// 设置 TOS/DSCP（HFT 常用 CS6/CS7 标记关键流量）
setsockopt(fd, IPPROTO_IP, IP_TOS, &tos, sizeof(tos));
// 设置 DF 位（禁止分片）
int val = IP_PMTUDISC_DO;
setsockopt(fd, IPPROTO_IP, IP_MTU_DISCOVER, &val, sizeof(val));
```

## HFT 关联

| 场景 | UDP 的角色 |
|------|-----------|
| 组播行情分发 | 一份数据同时到多个交易节点，UDP 组播天然适合 |
| 内核旁路对比 | DPDK/AF_XDP 绕过内核，但 fallback 路径仍走 UDP socket |
| FPGA → 服务器 | FPGA 网卡发出 UDP 组播帧，服务器用 `SO_REUSEPORT` 多进程收 |
| 交易心跳/序号 | 简单 UDP 报文比 TCP 重传机制更适合「最新值优先」语义 |

**注意**：HFT 行情一般用 UDP 组播 + 应用层 FEC/序号检测，而非 TCP——丢一个包不能阻塞后续行情。
