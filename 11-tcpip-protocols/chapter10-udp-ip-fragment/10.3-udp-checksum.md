# 10.3 UDP 校验和

> 章级精读：[../study.md#ch10-3](study.md#ch10-3) · IP 校验和：[ch05](../chapter05-ip-protocol/study.md)

## 本节核心目标

掌握 UDP 校验和的**伪首部**机制，理解 IPv4 vs IPv6 的差异。

---

## 伪首部（Pseudo Header）

UDP 校验和不仅覆盖 UDP 首部 + 数据，还覆盖一个**不实际发送的伪首部**——包含源 IP、目的 IP、协议号和 UDP 长度：

```
┌ Pseudo Header ──────────────────────────┐  ← 不参与链路上真实发送
│ Src IP (32 / 128)                       │
│ Dst IP (32 / 128)                       │
│ Zero (8 bits) │ Proto (8)=17 │ UDP Len │
└ Pseudo Header ──────────────────────────┘
        + UDP header + Payload  → one's complement sum → Checksum field
```

**为什么要伪首部？** IP 首部没有覆盖上层载荷的校验（IPv6 甚至没有自身校验和）。伪首部让接收方验证：数据确实到达了正确的 IP 和协议端口——防止错投。

---

## IPv4 vs IPv6 差异

| 项目 | IPv4 | IPv6 |
|------|------|------|
| IP 首部自身校验和 | 有（[ch05](../chapter05-ip-protocol/study.md)） | **无** |
| UDP Checksum = 0 | 合法：表示「发送方跳过计算」 | **非法**：必须计算，结果 0 时存 0xFFFF |
| 典型工程结论 | 许多栈仍计算 UDP checksum | **必须开启** |

IPv4 允许跳过校验和是历史遗留——现代网络中强烈不建议关闭。IPv6 强制要求是因为 IP 层不再校验，上层必须承担。

## 计算过程

```c
// 内核/libc 中的校验和计算（简化概念）
uint16_t udp_checksum(struct iphdr *ip, struct udphdr *udp, uint8_t *payload) {
    // 1. 构造伪首部
    struct {
        uint32_t saddr;
        uint32_t daddr;
        uint8_t  zero;
        uint8_t  proto;   // 17 = UDP
        uint16_t udp_len;
    } pseudo = { ip->saddr, ip->daddr, 0, 17, udp->len };

    // 2. 对伪首部 + UDP 首部 + 载荷做 one's complement sum
    uint32_t sum = 0;
    sum = csum_partial(&pseudo, sizeof(pseudo), sum);
    sum = csum_partial(udp, ntohs(udp->len), sum);

    // 3. 折叠进位取反
    sum = (sum & 0xffff) + (sum >> 16);
    return ~sum;
}
```

## NAT 与校验和

NAT 重写 IP 地址后**必须重算 UDP 校验和**（因为伪首部包含 IP 地址）。这是 NAT 设备的性能开销之一，也是硬件 offload 的重要场景。

---

## HFT 关联

- **NIC checksum offload**：现代网卡在硬件中计算/验证 UDP 校验和，CPU 零开销
- **DPDK**：用户态直接收包时需自行校验，或依赖网卡 offload 标记 `PKT_RX_L4_CKSUM_GOOD`
- **组播行情**：校验和失败 → 静默丢包，应用层序号检测是唯一兜底
