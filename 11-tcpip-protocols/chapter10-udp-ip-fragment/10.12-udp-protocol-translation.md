# 10.12 UDP 协议转换

> 章级精读：[../study.md#ch10-8](study.md#ch10-8) · NAT64：[ch07](../chapter07-firewall-nat/study.md)

## 本节核心目标

理解 UDP 在 IPv4/IPv6 转换（NAT64/DNS64）和 NAT 穿越中的行为。

---

## NAT 对 UDP 的影响

| 行为 | 说明 |
|------|------|
| 地址重写 | 源 IP:Port → NAT 公网 IP:Port |
| 校验和重算 | 伪首部含 IP → NAT 必须重算 |
| 映射超时 | UDP 无连接 → NAT 依赖空闲超时回收映射（常 30-120s） |
| 对称 vs Full Cone | 不同 NAT 类型对入站包过滤策略不同 |

---

## NAT64 (IPv6 → IPv4)

```text
[IPv6 Only Client] → [NAT64 Gateway] → [IPv4 Server]

UDP 包: src=[IPv6]:port → NAT64 → src=[IPv4 NAT]:port
```

- DNS64 合成 AAAA 记录（`64:ff9b::` 前缀映射 IPv4）
- NAT64 维护 IPv6-IPv4 映射表

---

## STUN/TURN/ICE

UDP NAT 穿越的经典框架：

| 协议 | 作用 |
|------|------|
| **STUN** | 客户端发现自己的公网映射（IP:Port） |
| **TURN** | 中继服务器（当 P2P 直连失败时） |
| **ICE** | 编排框架：先试直连 → STUN → TURN |

---

## HFT 关联

HFT 系统通常在数据中心内直连，不涉及 NAT。但跨数据中心 WAN 交易可能经过 NAT/防火墙——UDP 映射超时可导致静默丢包，需应用层心跳保活。
