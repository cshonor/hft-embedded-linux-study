# 15.5 流量控制与窗口管理

## 本节核心目标

掌握 **Advertised Window**（rwnd）机制、滑动窗口、零窗口、SWS、Autotuning。

---

## 滑动窗口

```
| 已确认 | 已发未确认(在途) | 可发(可用窗口) | 不可发 |
  ^左沿      ^SND.NXT          ^右沿
  ← ACK 推进左沿          ← rwnd 限制右沿
```

| 术语 | 含义 |
|------|------|
| **Advertised Window (rwnd)** | 接收方通告的接收能力 |
| **Usable Window** | rwnd − 已发未确认 |
| **左沿** | 已确认边界；随 ACK 右移 |
| **右沿** | 左沿 + rwnd |
| **SND.NXT** | 下一待发送字节 |

---

## rwnd vs cwnd

| | rwnd | cwnd |
|--|------|------|
| 解决 | **接收方**慢 | **网络**堵 |
| 谁通告 | 接收方 TCP 首部 | 发送方**自行估算** |
| 有效发送 | **min(rwnd, cwnd)** | 同左 |

---

## 零窗口与 Persist Timer

通告窗口 **= 0** → 发送方停发。若窗口更新丢失 → 永久死锁。

**Persist Timer**：周期发 **Window Probe**（1 字节探测），迫使对端 ACK 中带新窗口。

---

## 糊涂窗口综合征 (SWS)

接收方通告极小窗口 + 发送方发极小段 → 链路被头部占满。

| 方 | 对策 |
|----|------|
| **接收方（Clark）** | 除非可增 ≥1 MSS 或 ≥缓冲区一半，否则不增大通告窗 |
| **发送方** | 仅当数据达 MSS、收到 ACK、或满足 Clark 阈值才发 |

---

## 大缓存与 Autotuning

**LFN / 大 BDP** 需 [Window Scale](../chapter13-tcp-connection-manage/13.3-tcp-options.md)（突破 64KB）。

```bash
# Linux Autotuning
sysctl net.ipv4.tcp_window_scaling    # 默认 1
sysctl net.ipv4.tcp_rmem              # 接收缓冲 min/default/max
# Autotuning 动态调 SO_RCVBUF，填满管道
```
