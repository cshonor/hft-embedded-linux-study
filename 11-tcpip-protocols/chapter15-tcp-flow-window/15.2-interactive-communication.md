# 15.2 交互式通信

> 章级精读：[../study.md#ch15-2](study.md#ch15-2)

## 本节核心目标

理解交互式数据流的开销和延迟特征。

---

## 交互模式

- **每键一字节** → 一包（Rlogin/SSH）
- 有效载荷占比：1B 数据 + ~40B 头（20 IP + 20 TCP）→ **PPS** 压力巨大

---

## Rlogin 回显四步

```
1. Client → Server: 按键 1B
2. Server → Client: ACK
3. Server → Client: 回显数据
4. Client → Server: ACK
```

高 RTT 下每键可见延迟 ≈ 2×RTT；10 键/s ≈ **40 报文/s**（未优化时）。

---

## 优化

| 优化 | 效果 |
|------|------|
| Delayed ACK | 减少 ACK 数量（合并第2/3步） |
| Nagle | 合并小包 |
| TCP_NODELAY | 禁用 Nagle → 交互延迟降低 |

---

## HFT 关联

HFT 的 TCP 控制面（如管理指令、日志）类似交互式流——小包、延迟敏感。`TCP_NODELAY` 是标准配置。
