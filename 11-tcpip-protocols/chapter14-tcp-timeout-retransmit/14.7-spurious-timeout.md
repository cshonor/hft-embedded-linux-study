# 14.7 伪超时 (Spurious Timeout)

> 章级精读：[../study.md#ch14-7](study.md#ch14-7) · Eifel：[ch16 §16.4](../chapter16-tcp-congestion-control/16.4-eifel-response.md)

## 本节核心目标

理解伪超时的成因、检测方法和撤销机制。

---

## 什么是伪超时

RTO 溢出但数据**未丢**——只是延迟了（延迟尖峰、路径切换）→ 伪重传。

```
0.000s  发送 seq=1
0.200s  RTO 超时 → 重传 seq=1
0.210s  原始 seq=1 的 ACK 到达 → 才发现没丢！
→ 已经错误地减半了 cwnd（性能损失）
```

---

## 检测方法

| 方法 | 原理 |
|------|------|
| **DSACK** | 接收方标明收到重复数据 → 若对应刚超时重传 → 伪超时 |
| **Eifel** | 时间戳 TSecr 指向**原段**而非重传段 → 原段其实到了 |
| **F-RTO** | 无时间戳时，超时后先发新数据，观 ACK 推断伪超时 |

---

## Eifel 检测详解

```
原始段: TS=1000
重传段: TS=1000 (相同，因为是重传)

ACK 回来: TSecr=1000 → 对应原始段
         (如果对应重传段，TSecr 仍是 1000，但时序不同)

关键: Eifel 比较 ACK 到达时间与重传时间
     → 如果 ACK 在重传后极短时间到达 → 很可能是原始段的 ACK → 伪超时
```

---

## Eifel Response

伪超时确认后 → **撤销**误缩的 cwnd / ssthresh → 避免性能雪崩。

---

## HFT 关联

无线/移动网络延迟尖峰常见 → 伪超时频发。HFT 有线环境相对稳定，但跨数据中心 WAN 仍可能遇到路径切换尖峰。
