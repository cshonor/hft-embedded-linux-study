# 14.2 简单超时与重传

> 章级精读：[../study.md#ch14-2](../study.md#ch14-2)

## 本节核心目标

理解基本的超时重传机制和**指数退避**。

---

## 超时重传流程

```text
0.000s  发送 seq=1:1025
1.500s  超时 → 第1次重传 seq=1:1025（间隔 RTO）
4.500s  超时 → 第2次重传（间隔 ×2 = 3s）
10.500s 超时 → 第3次重传（间隔 ×2 = 6s）
22.500s 超时 → 第4次重传（间隔 ×2 = 12s）
```

---

## 指数退避

| 重传次数 | 间隔（初 RTO≈1.5s） | 累计等待 |
|----------|---------------------|----------|
| 1 | 1.5s | 1.5s |
| 2 | 3s | 4.5s |
| 3 | 6s | 10.5s |
| 4 | 12s | 22.5s |
| 5 | 24s | 46.5s |

**本质**：拥塞时主动降注入（保守）。RTO 过小 → 伪重传浪费带宽；过大 → 吞吐崩塌。

---

## Linux 参数

```bash
# tcp_retries2: 已建立连接的最大重传次数（默认15）
#   超过后放弃连接
sysctl net.ipv4.tcp_retries2

# tcp_retries1: 重传次数达到后开始报告错误（默认3）
sysctl net.ipv4.tcp_retries1
```

---

## HFT 关联

TCP 指数退避对 HFT 不友好——丢包后第二次重传就等 3s，远超交易容忍。这就是为什么 HFT 倾向：
- UDP 组播 + 应用层 FEC
- 专线/Dedicated Link 无丢包
- TCP 仅用于非延迟敏感的控制面
