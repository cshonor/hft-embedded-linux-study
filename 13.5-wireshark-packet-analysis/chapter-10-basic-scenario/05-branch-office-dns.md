# 10.5 分公司之困

> 本章：[chapter-summary.md](./chapter-summary.md) · 全书：[../README.md](../README.md) · DNS 区域传送：[§9.2.5](../chapter-09-application-layer-proto/02-dns-protocol.md)

**核心主旨**：跨 WAN 访问总部应用失败——**UDP 53 放行但 TCP 53 被挡** 导致 DNS 同步/大响应失败。

## 核心知识点

### 故障现象

- **分公司**用户无法访问**总部内网**应用；**外网正常**。

### 分析过程

| 位置 | 抓包发现 |
|------|----------|
| **客户端** | 查分公司本地 DNS → 响应 **Server failure**（解析链上游失败） |
| **分公司 DNS 服务器** | 向总部主 DNS 查询时不用 UDP 53，而是 **TCP 53 SYN** |
| | **无 SYN/ACK**，TCP **重传** |

### 深层机制

| 机制 | 说明 |
|------|------|
| DNS over TCP | 响应过大、**AXFR/IXFR 区域传送**时必须 TCP 53 |
| 防火墙误配 | 总部路由器/防火墙 **只放行 UDP 53** |
| 结果 | 合法 **TCP 53** 被拦 → 分公司无法同步区域 → 内网名解析失败 |

### 结论与修复

- 在 WAN 防火墙上对信任分公司 IP **同时放行 UDP/TCP 53**（或 DNS 专用策略）。
- 验证：`tshark -Y "tcp.port==53"` 见完整三次握手。

## 抓包/实操记录

| 检查 | 命令/过滤 |
|------|-----------|
| 客户端 | `dns.flags.rcode != 0` 查失败响应 |
| DNS 服务器 | `tcp.port == 53 && tcp.flags.syn==1` |
| 对比总部 | 同查询在总部侧是否仅有 UDP |

## 疑问与总结

- 「外网通、总部不通」→ 优先 **Split DNS / 专线 DNS** 路径，而非默认公网 DNS。
- 安全与可用：限制 TCP 53 **源 IP** 为已知从服务器，而非全网开放。
