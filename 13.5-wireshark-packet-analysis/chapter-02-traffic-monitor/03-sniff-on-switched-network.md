# 2.3 在交换式网络中进行嗅探

> 本章：[chapter-summary.md](./chapter-summary.md) · 全书：[../README.md](../README.md)

**核心主旨**：交换机按 CAM 表精准转发，普通端口可视范围极窄；必须用镜像、Hub 介入、TAP 或 ARP 污染之一扩大可见流量。

## 核心知识点

### 逻辑前置

- 交换机：**全双工** + **单播只出目的端口**。
- 嗅探器直连普通口：只见 **广播/组播** + **本机收发**。
- 要分析他人通信 → 下面四种技术至少择一。

---

### 2.3.1 端口镜像（Port Mirroring / SPAN）

| 项 | 说明 |
|----|------|
| **做法** | 在交换机 CLI/Web 将若干**源端口**流量**复制**到**目的端口**（接嗅探器） |
| **优点** | 不改终端拓扑、可在线配置、**不留伪造包脚印**（首选） |

**易错 / 高危：流量过载**

```text
例：23 个全双工 100Mbps 口 → 镜像到 1 个 100Mbps 口
理论峰值可达 23×100×2 ≈ 4600Mbps >> 单口上限
```

| 后果 | 说明 |
|------|------|
| 镜像口丢包 | 抓到的 pcap **不完整** |
| 交换机背板压力 | 极端时内部交换受阻，**全网变慢甚至中断** |

**实践**：只镜像**必要端口**；目的口速率 ≥ 源口聚合峰值；高负载用 **10G 镜像口** 或 TAP。

---

### 2.3.2 集线器输出（Hubbing Out）

> Hub 原理（物理层、全网泛洪、半双工）：[TCP/IP §3.2 Hub](../../../TCP-IP-Volume1-Protocols/chapter03-link-layer/3.2-ethernet-ieee802-encapsulation.md#ch03-2-hub)

```text
[交换机] —— [Hub] —— 目标主机
              └── 嗅探器
```

| 项 | 说明 |
|----|------|
| **逻辑** | 物理串入目标线路，Hub 再次**广播**该主机进出流量 |
| **优势** | 交换机**不支持镜像**、且有物理接触权时的替代 |
| **劣势** | 目标链路降为 **半双工** → 性能下降、碰撞风险 |
| **避坑** | 必须是**真 Hub**（10Mbps 常见）；「假 Hub」实为交换机 → 两台电脑互嗅验证 |

---

### 2.3.3 网络分流器（Network Tap）

| 项 | 说明 |
|----|------|
| **定义** | 串联在线路两端的**硬件**探针，**旁路复制**比特流，尽量不干扰业务 |
| **适用** | 千兆/万兆、光纤、需**无痕**且镜像口不够用时 |

| 类型 | 端口 | 特点 |
|------|------|------|
| **聚合 Tap（3 口）** | 1 个 Monitor | 双向流量合到单监听口；**1 块网卡**即可 |
| **非聚合 Tap（4 口）** | Monitor A / B | 入向、出向**分口**；需双网卡或合并分析 |

**选型**：一般优先**聚合**（线材少）；极高带宽或必须严格区分方向时用**非聚合**。

---

### 2.3.4 ARP 缓存污染（ARP Cache Poisoning）

| 机制 | 说明 |
|------|------|
| ARP 信任 | 设备会接受**未请求的 ARP 应答**（Gratuitous ARP）并更新缓存 |
| MITM 思路 | 向目标与网关各发**伪造 ARP**，使双方把对方 IP 映射到**攻击者 MAC** |
| 结果 | 流量**经嗅探机转发** → 可见双向通信 |

| 风险 | 说明 |
|------|------|
| 拓扑被改写 | 违背「无痕」原则 |
| 瓶颈 | 目标 1Gbps、嗅探机 100Mbps → 嗅探机成**瓶颈**，类似 **DoS** |
| 丢包 | 分析数据严重不完整，业务瘫痪 |

> **进阶（了解）**：部分工具支持**非对称** ARP 污染，只劫持单向以减轻负载——仍属高风险，仅授权渗透/实验环境使用。

**警示**：交换机无镜像、主机又不能下线时的**急救**手段；日常排障**优先镜像 / TAP**。

## 抓包/实操记录

| 场景 | 建议 |
|------|------|
| 企业接入交换机 | 配置 **SPAN**，Wireshark 接镜像口 |
| 数据中心 | **TAP** + 聚合口进采集机 |
| 实验 MITM | 虚拟机内 `arpspoof` / 仅隔离 lab；抓包看网关 MAC 是否变为攻击机 |
| 过滤器 | 镜像后仍用 `host x.x.x.x` 缩小范围 |

## 疑问与总结

| 方法 | 无痕 | 性能影响 | 权限/条件 |
|------|------|----------|-----------|
| 端口镜像 | ✅ | 镜像口过载风险 | 需管交换机 |
| TAP | ✅ | 极低 | 需断线串联、预算 |
| Hub out | 中 | 半双工降级 | 物理接触 |
| ARP 污染 | ❌ | 可能灾难性 | 高权限 + 法律授权 |

- 与 [§2.5](./05-deployment-guidelines.md) 选型表对照决策。
