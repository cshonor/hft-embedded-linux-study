# 11.3 从 TCP 错误控制和流量控制中学到的

> 本章：[chapter-summary.md](./chapter-summary.md) · 全书：[../README.md](../README.md) · 抓包点：[第2章](../chapter-02-traffic-monitor/chapter-summary.md)

**核心主旨**：**在哪抓**才能看到重传 vs 重复 ACK；零窗口把锅甩给**主机性能**。

## 核心知识点

### 三条排障选址法则

| 现象 | 包在哪出现 | 嗅探器应放 |
|------|------------|------------|
| **重传** | 由**发送方**再发丢失段 | **发送端**或靠近发送端（客户端上传慢 → 客户端侧；下载慢 → 服务器侧或客户端看 Dup ACK） |
| **Duplicate ACK** | **接收方**发现乱序后发出 | **接收端**或靠近接收端 |
| **Zero Window** | **接收方**宣告无缓冲 | 在**宣告方**抓包最清晰；责任在**该主机性能** |

### 记忆口诀

```text
看重传 → 去发送端
看 Dup ACK → 去接收端
看 Zero Window → 接收端背压，查主机不查光缆（先）
```

### 与第 10 章对照

| 案例 | TCP 线索 |
|------|----------|
| 丢失网页 SYN 黑洞 | 重传，无 Dup ACK（对端无响应） |
| 打印机 | Zero Window + 重传 |
| 上游 SYN 黑洞 | 重传，非零窗口 |

## 抓包/实操记录

| 场景 | 建议 |
|------|------|
| 用户抱怨「下载慢」 | 客户端抓：看 **Dup ACK / 下行重传** |
| 用户抱怨「上传慢」 | 服务器或客户端抓：**上行重传** |
| 服务端卡 | 服务器抓：**Zero Window 由谁发出** |

## 疑问与总结

- 镜像口单向时可能**只见一侧**重传；必要时两端各抓一段对照。
- 无线/高丢包：Dup ACK 与重传可能非常多，先 `tcp.stream eq N` 隔离单连接。
