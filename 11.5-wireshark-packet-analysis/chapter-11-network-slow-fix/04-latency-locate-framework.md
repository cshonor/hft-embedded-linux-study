# 11.4 定位高延迟的原因

> 本章：[chapter-summary.md](./chapter-summary.md) · 全书：[../README.md](../README.md) · HTTP：[§9.3](../chapter-09-application-layer-proto/03-http-protocol.md)

**核心主旨**：用握手与 HTTP 前几个包的 **Time Delta**，把延迟钉在**线路 / 客户端 / 服务端**之一。

## 核心知识点

### 11.4.1 正常通信基准

| 阶段 | 正常量级（教材参考） |
|------|----------------------|
| SYN → 完成握手 + HTTP GET 发出 + 服务器首包 HTTP 数据 | 全程常 **< 0.1s**（局域网/优质链路） |

> 广域网/移动网放宽，但**同环境前后对比**更重要。

---

### 11.4.2 慢速通信—线路延迟

| 测量 | `SYN` → `SYN/ACK` 间隔巨大（如 **>0.8s**） |
|------|------------------------------------------|
| 逻辑 | 握手由**内核**完成，无应用负载 → 慢在**路径设备/距离/丢包重传** |
| 排查 | 路由、防火墙、VPN、物理链路；非 Web 服务器代码 |

**列**：`Time` 格式选 **Delta** 或 **Relative**，看包 1–2 间隔。

---

### 11.4.3 通信缓慢—客户端延迟

| 测量 | 握手末 **ACK** → 首个 **HTTP GET** 间隔大（如 **>1.3s**） |
|------|------------------------------------------------------|
| 逻辑 | 链路已通；慢在**浏览器/杀软/代理/本机 CPU** 构建请求 |
| 排查 | 客户端进程、扩展、系统负载 |

---

### 11.4.4 通信缓慢—服务器延迟

| 测量 | 服务器 **ACK（确认 GET）** → 首个 **HTTP 响应数据** 间隔大（如 **>0.9s**） |
|------|-----------------------------------------------------------------------|
| 逻辑 | 网络与客户端请求正常；慢在**服务端应用**（DB、脚本、磁盘） |
| 排查 | 应用日志、DB、线程池；非交换机 |

---

### 11.4.5 延迟定位框架（黄金法则）

```text
SYN ──[ 线路延迟 ]──► SYN/ACK

ACK（握手完成）──[ 客户端延迟 ]──► 第7层请求（HTTP GET）

ACK（确认收到 GET）──[ 服务端延迟 ]──► 第7层响应数据
```

| Wireshark 技巧 | 说明 |
|----------------|------|
| **Time Delta** | 列显示与上一包间隔 |
| `tcp.time_delta` | 显示过滤器（字段视版本） |
| 自定义列 | `frame.time_delta_displayed` |
| Transcalc 等插件 | 批量统计握手各段（拓展） |

## 抓包/实操记录

| 练习 | 步骤 |
|------|------|
| 标三段时间 | 单 `tcp.stream` + HTTP，`Delta` 列读三段 |
| 对照 baseline | 用 [§11.5](./05-network-baseline.md) 正常 HTTP 抓包对比 |
| tshark | `-T fields -e frame.number -e frame.time_delta -e http.request` |

## 疑问与总结

- HTTPS 需在解密后看 HTTP 时间点，否则只能测 **TLS 握手**各段。
- 慢可能是**多段叠加**；分别量再相加，勿只凭总时间猜。
