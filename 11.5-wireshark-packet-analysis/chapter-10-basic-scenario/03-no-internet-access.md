# 10.3 无法访问 Internet

> 本章：[chapter-summary.md](./chapter-summary.md) · 全书：[../README.md](../README.md)

**核心主旨**：三种常见「上不了网/上不了某站」——用 **DNS 有无响应、是否查 DNS、SYN 后有无 SYN/ACK/RST** 定位层级。

## 核心知识点

### 10.3.1 网关配置问题

| 现象 | 内网通，**外网全断** |
|------|----------------------|
| 抓包 | ARP 解析**默认网关 MAC** 正常 |
| | 向**外网 DNS**（首选/备用）发查询 → **无任何 DNS 响应** |
| | 查询重复后超时 |
| 推断 | 出站被丢 → **默认网关错误**或**路由器未转发/NAT 故障** |
| 焦点 | 客户端网关 IP、路由器 WAN、ACL |

**特征表**：有 ARP 网关 + **DNS 请求无响应**（非单站）

---

### 10.3.2 意外重定向（hosts 劫持）

| 现象 | 仅 **Google 等特定站** 不可用 |
|------|-------------------------------|
| 抓包 | **没有 DNS 查询** |
| | 直接向 **内网网关 IP** 发 **TCP SYN :80** |
| | 网关立即 **RST/ACK** |
| 推断 | 名称解析被**本地 hosts** 或恶意软件映射到**未开 Web 的网关 IP** |
| 焦点 | `C:\Windows\System32\drivers\etc\hosts`（及 Linux `/etc/hosts`） |

**特征表**：**无 DNS** + 连错 IP + **快速 RST**

**过滤器**：`tcp.flags.reset==1 && ip.dst==<网关IP>`

---

### 10.3.3 上游问题

| 现象 | **某外部站** 全网不可达（其他外网正常） |
|------|----------------------------------------|
| 抓包 | **DNS 成功** 返回正确 IP |
| | 向该 IP **SYN** → **无 SYN/ACK 也无 RST** |
| | 长时间 **TCP 重传** |
| 推断 | 本地 DNS/路由正常；故障在 **ISP 丢包、目标宕机、远端防火墙** |
| 焦点 | 换网络/路径 traceroute；对端抓包 |

**特征表**：DNS OK + **SYN 黑洞重传**

---

### 三种场景对照

| 场景 | DNS | TCP 结果 | 查哪里 |
|------|-----|----------|--------|
| 网关错 | 外网 DNS **无响应** | 可能都无后续 | 网关/NAT |
| hosts | **无查询** | **RST** 来自网关 | hosts/恶意软件 |
| 上游 | **有 A 记录** | **重传无应答** | ISP/目标/路径 |

## 抓包/实操记录

| 练习 | 模拟观察 |
|------|----------|
| 网关 | 错配网关后抓 `dns` 仅见 query 无 response |
| hosts | 加一行 `google.com` → 网关 IP，看无 dns 有 RST |
| 上游 | 对不可达 IP ping/trace + SYN 重传 |

## 疑问与总结

- 先画 **「DNS → TCP → HTTP」** 哪一步断。
- 与 [§10.1](./01-lost-web-content.md) 区别：10.1 是**部分**资源旧缓存；10.3 是**整类访问**模式异常。
