# 4.3 时间显示格式与相对参考

> 本章：[chapter-summary.md](./chapter-summary.md) · 全书：[../README.md](../README.md)

**核心主旨**：时间字段是分析**延迟、时序、多文件对照**的核心；掌握格式切换、时间参考点与时间偏移。

## 核心知识点

### 时间显示格式

每个包由抓包主机 OS 打**时间戳**。Packet List 的 **Time** 列格式可切换：

| 格式（常见） | 含义 |
|--------------|------|
| **绝对**（如 UTC / 自 UNIX 纪元） | 真实时钟时间，便于与日志对齐 |
| **相对**（Relative） | 相对**上一包**或**第一包**的秒数 |
| **Delta** | 与**上一显示包**的时间差 |
| **Elapsed** | 相对捕获开始 |

设置：`View` → `Time Display Format`；或列标题右键。

### 数据包时间参考（Time Reference）

| 项 | 说明 |
|----|------|
| **操作** | 右键包 → `Set/Unset Time Reference`（或 `Time Shift` 菜单邻近项） |
| **显示** | 参考包旁出现 **`*REF*`** |
| **效果** | 后续包时间列以该包为 **t = 0** 显示相对时间 |
| **场景** | 某事件（如 SYN、DHCP Discover）触发的一串后续行为 |

### 时间偏移（Time Shift）

| 问题 | 原因 |
|------|------|
| 合并多文件后事件顺序错乱 | 各设备**时钟未同步** |

| 解决 | 操作 |
|------|------|
| **Time Shift** | 对选中包或整文件统一加/减偏移（如全体 **+2分5秒**） |
| 前提 | 已知两 trace 间固定时差（用已知同步事件对齐） |

> **拓展**：生产多探针应用 **NTP/chrony** 强同步，从源头减少 Shift 手工量。

### 与延迟分析的关系

- **Delta / 相对 REF**：看「请求后多久出应答」。
- 配合 TCP **Follow Stream**、**RTT** 列（后续章节）定位慢在哪一跳。

## 抓包/实操记录

| 练习 | 步骤 |
|------|------|
| REF | 对 TCP SYN 设 Time Reference → 看 SYN-ACK 相对秒数 |
| 格式切换 | Relative vs Delta 对比同一 HTTP 事务 |
| Shift | 故意用两台时钟差 2 分钟的 pcap 合并 → Shift 对齐后再 Merge 分析 |

## 疑问与总结

- 时间戳精度依赖 OS；高负载主机可能**戳抖动**。
- Shift 修正的是**显示与分析对齐**，不改变线上真实 RTT；报告需注明是否做过 Shift。
