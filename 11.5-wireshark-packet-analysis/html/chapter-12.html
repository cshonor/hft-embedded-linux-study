network-reconnaissance

本章：chapter-summary.md · 全书：../README.md · TCP 握手：§8.1

核心主旨：攻击前收集开放端口、服务与 OS 信息——在 pcap 里认 SYN 扫描与被动/主动指纹。

核心知识点

12.1.1 SYN 扫描（半开扫描）

项 说明
别名 隐秘扫描、半开扫描
特点 快、跨平台、常无完整连接日志（无最终 ACK）

开放端口

扫描方 SYN → 目标 SYN/ACK → 扫描方不发 ACK（放弃握手）
Wireshark 线索 单端口会话常约 5 包（含扫描方对 SYN/ACK 的 重传，因无 ACK 完成）

关闭端口

扫描方 SYN → 目标 RST

| 线索 | 会话常仅 2 包 |

过滤器

用途 表达式
扫描 SYN tcp.flags.syn==1 && tcp.flags.ack==0
大量短会话 Conversations → TCP，短流、多目的端口
对单受害者 ip.addr==<victim> && tcp.flags.syn==1

12.1.2 操作系统指纹

类型 机制
被动 只听受害者自发流量，不发探测包
主动 发特制包（Nmap -O），比响应指纹库

被动常用字段

字段 差异示例
IP TTL 初值 Windows 常 128；Linux/macOS 常 64（经跳数递减）
DF 位 是否设 Don't Fragment
TCP MSS 选项中最大段大小
TCP Window 初始窗口大小

标准未统一默认值 → 各 OS 栈实现不同 → 可推断。

| 工具拓展 | p0f 等对镜像流量实时被动指纹 |

抓包/实操记录

实验 说明
实验环境 仅对自己 lab 主机 nmap -sS
数包 开放 80：SYN→SYN/ACK→(重传)×n；关闭：SYN→RST
TTL 首包 ip.ttl 记录 OS 线索

疑问与总结

  • 防火墙可能 DROP SYN → 表现为超时重传，非 RST（与关闭端口不同）。
  • 与 §10.3.3 SYN 黑洞区分：扫描是多端口模式。
12.2

流量操纵

本章：chapter-summary.md · 全书：../README.md · ARP：§7.1 · §2.3.4

核心主旨：MITM 与会话劫持在包里的痕迹——异常 ARP、MAC 突变、明文 Cookie。

核心知识点

12.2.1 ARP 缓存污染（MITM）

逻辑 伪造 ARP，使 A、B 流量经攻击者转发

抓包异常线索

线索 说明
非广播 ARP 请求 单播 ARP Req，且内容与「问网关 MAC」不符常规
未请求的 ARP Reply Gratuitous / 单方面 Reply，把网关 IP → 攻击者 MAC
MAC 突变 同一目的 IP（外网） 的帧，以太网 DST MAC 从真网关变为攻击者 MAC

过滤器：arp · arp.opcode==2 · 对比前后 eth.dst

| 防御 | 静态 ARP、DAI、802.1X、加密（TLS） |

拓展：SSL Stripping + ARP 污染：降级 HTTPS → 明文 HTTP 再截 Cookie。

12.2.2 会话劫持

步骤 抓包可见
1 MITM 或镜像看到 明文 HTTP
2 Set-Cookie / 请求头 Cookie: PHPSESSID=...
3 攻击者浏览器植入同 Cookie → 冒充用户

| 防御 | HTTPS、HttpOnly/Secure Cookie、短会话、绑定 IP/UA |

Wireshark：http.cookie · Follow TCP Stream 搜 Cookie:

抓包/实操记录

练习 操作
对比 Gratuitous §7.1.4 合法 vs 攻击者高频伪造
HTTP 明文 实验网登录 HTTP 站，MITM lab 中导出 Cookie 字段

合规：仅在授权 lab；生产嗅探需书面授权。

疑问与总结

  • 全链路 TLS 1.3 时 Cookie 不可见，除非终端被控或密钥泄露。
  • 与 §10.2 区别：10.2 是配置错密码，12.2 是主动窃听/篡改。
12.3

漏洞利用

本章：chapter-summary.md · 全书：../README.md · HTTP：§9.3

核心主旨：从 IDS 告警定位会话，在 pcap 中拆 载荷特征 与 C2 明文交互。

核心知识点

12.3.1 极光行动（Operation Aurora，2010）

攻击链（教材）

钓鱼邮件 → 点击 → HTTP 302 → 恶意页面 → IE 漏洞 → 系统沦陷
包层特征 说明
混淆 JavaScript <script> 内大量编码/十六进制，不可读
隐藏 iframe 静默 GET 伪装 GIF；实为 shellcode 载体
反向 Shell 受害机主动连攻击者 4321 等端口
明文 C2 Follow Stream 可见 C:\Documents and Settings\... 等 cmd 交互

过滤器：http.response.code==302 · tcp.port==4321 · http contains "iframe"

12.3.2 远程访问木马（RAT）

起点 IDS（Snort 等） 告警 → 特征串定位 pcap

示例特征（教材）

41 4E 41 42 49 4C 47 49 7C  →  ASCII "ANABILGI|"
阶段 抓包
命令 攻击者发 CAPSCREEN60 等
回传 新 TCP 会话上传数据（截图）
File Carving Follow Stream 导出 JPG 可能损坏

JPEG 修复

步骤 操作
1 在十六进制中找 FF D8 与 JFIF
2 剥除木马附加的控制头
3 保存为 .jpg 验证

Wireshark：Export Objects → HTTP/FTP（若适用）；或 Follow Stream → Raw → 外部 hex 编辑。

抓包/实操记录

任务 命令/操作
搜特征 tcp contains "ANABILGI" 或 Edit → Find Packet → Hex
跟 C2 tcp.stream eq N + Follow
IDS 联动 告警时间戳对齐 pcap frame.time

疑问与总结

  • 现代样本多 TLS C2，明文 RAT 多见于 lab/老样本。
  • 分析恶意 pcap：断外网、虚拟机、勿双击样本。
12.4

漏洞利用工具包与勒索软件

本章：chapter-summary.md · 全书：../README.md · 基线：§11.5

核心主旨：EK（Angler）挂马链 + 勒索软件（CryptoWall）C2 POST 的 pcap 表征。

核心知识点

C2「签到」表征（CryptoWall 4 类）

特征 说明
行为 内网主机 → 外部恶意 IP，重复 HTTP POST
URL 随机路径/参数，如 /76N1Lm.php?n=x4tk7...
体 结构相似的二进制或表单数据（密钥交换）

过滤器：http.request.method == "POST" · http.host / ip.dst 黑名单对照

感染链（Angler EK → 载荷）

步 抓包线索
1 合法站被挂 用户从 Bing 等进正常站；响应 HTML 含恶意重定向 JS
2 着陆页 302/JS redirect 到第三方；GET 无扩展名乱码文件名
3 探测利用 下发 Flash（application/x-shockwave-flash）等漏洞文件
4 载荷 后台 GET 大体积、无正常扩展名 二进制 → 运行 → POST C2 
正常浏览 → 重定向 → EK 着陆 → 漏洞文件 → 勒索软件 → 周期性 POST C2

| 与基线比 | 新外部 IP、新 POST 模式、Protocol Hierarchy 中 HTTP POST 占比飙升 |

抓包/实操记录

分析顺序 操作
1 Statistics → Conversations → 找异常外联 IP
2 http.request.method==POST 分组看 URI 模式
3 回溯第一条外联前是否有 302、flash、大文件下载
4 IOC：域名/IP 写入防火墙；样本交沙箱

疑问与总结

  • 加密 C2（HTTPS）需 TLS 解密或 JA3/SNI 等元数据，无法直接读 POST body。
  • 与 §12.1 关系：先扫描再投递；或钓鱼跳过扫描。
