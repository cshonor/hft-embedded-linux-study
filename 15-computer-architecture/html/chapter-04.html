4.1

section-4.1-4.2-向量架构

DLP 与向量指令

数据级并行（DLP）：一条指令对 多个数据元素 施加相同操作。

向量架构 典型流程：

内存 → 加载向量寄存器 → 向量 ALU 运算 → 写回内存

通过 流水线化向量单元 与 大寄存器文件 隐藏内存延迟、吃满带宽。

RISC-V 向量扩展 (RV64V) 关键机制

多泳道 (Multiple Lanes)

概念 说明
Lane 并行流水线，每周期完成多个元素
峰值吞吐 lanes × 每 lane 每周期元素数

向量长度与条带挖掘 (Strip mining)

问题 解法
程序向量长度 ≠ 硬件最大向量长度 (mvl) 向量长度寄存器 vl 指定本次有效长度
条带挖掘 长循环分块：每轮处理 ≤ mvl 个元素，直至完成

向量掩码 (Vector-Mask / Predicate)

用途 说明
条件循环向量化 谓词寄存器控制 哪些元素 真正执行/写回
避免分支 if 在向量中变成 掩码运算

步幅、收集-散布

访问模式 指令/机制
单位步幅 连续内存 — 最优
非单位步幅 (Stride) 多维数组列/行访问
收集 (Gather) / 散布 (Scatter) 索引向量间接寻址 — 稀疏矩阵

硬件需求： 多 独立 memory bank 支撑并行访存带宽。

HFT 视角
热路径宜 连续、固定 stride 批量处理（如一次解 N 档 bid/ask）— 类似条带挖掘
Gather/Scatter 延迟高、带宽差 — 订单簿指针追逐 不宜 SIMD 化
RVV 思路可类比理解 AVX-512 长度与掩码（→ 4.3）
4.3

section-4.3-多媒体SIMD扩展

起源与实现

为加速 图形、音频 等 窄数据类型（8/16 位）：

  • 在宽 ALU 上 切分进位链
  • 一周期处理多个短数据 — x86 MMX → SSE → AVX → AVX-512

与「真」向量架构的三大差距（早期）

缺陷 后果
无向量长度寄存器 长度常编码在指令或固定 — 条带挖掘不灵活
无步幅 / 收集-散布 非连续访问难向量化
无掩码寄存器（早期） 条件分支难向量化；AVX-512 后改善

→ 编译器 自动向量化困难，长期依赖 手写 intrinsics / 库（如 Intel MKL、Eigen）。

Roofline 性能模型

二维图：性能屋顶 vs 算术强度 (Arithmetic Intensity)

[ \text{算术强度} = \frac{\text{浮点运算次数}}{\text{访问内存字节数}} ]

区域 瓶颈
低算术强度 内存带宽（斜线以下贴内存屋顶）
高算术强度 峰值算力（平顶）

用途： 判断算法在特定 CPU/GPU 上 算力 bound 还是带宽 bound。

HFT 视角
批量回放：对百万 tick 做统计/特征 — Roofline 判断该 加核/AVX 还是 优化访存
固定格式行情解析：算术强度 中等 — AVX 解多路 price/qty 可能划算
实盘单 tick：强度极低（几次运算/百字节）— 在 内存延迟/分支 侧，不在 SIMD 屋顶

4.4

section-4.4-GPU架构

CUDA 与 SIMT

SIMT (Single Instruction, Multiple Thread)：一条指令驱动 一组线程 并行（NVIDIA Warp = 32 线程）。

层次 CUDA 术语 类比
网格 Grid 整个向量化问题 / 大循环
线程块 Thread Block 可协作的工作组
执行单元 SM (Streaming Multiprocessor) 多线程 SIMD 处理器

调度： 硬件将 warp 锁步 执行同一条指令；用 超多线程 隐藏 DRAM 延迟。

内存层次

类型 范围 速度
Private 单线程寄存器/局部 最快
Local / Shared 同 Block 内共享 片上，快
Global 全 Grid 大但慢（DRAM）

地址合并 (Address Coalescing)：warp 内线程访问 相邻地址 → 合并为少量事务 → 带宽利用率高；散乱访问 则效率暴跌。

分支发散 (Branch Divergence)

if-else 时 warp 内线程走不同路径：

  1. 硬件 先执行 THEN 路径（掩码屏蔽不满足线程）
  2. 再执行 ELSE 路径
  3. 有效吞吐 ≈ 单路径 — 发散严重时 GPU 优势消失
HFT 视角
GPU 适用：离线回测、蒙特卡洛、ML 训练/批量推理、大规模风险仿真
不适用：交易所 colo tick-to-trade — 延迟、确定性、PCIe 往返不可接受
若用 GPU 做研究：注意 合并访存、少发散分支 — 与 Ch2 局部性同构
SmartNIC/FPGA 是另一路线（→ Ch7 DSA、13-DPDK）
4.5

section-4.5-循环级并行检测

编译器向量化/SIMD 化的前提是找到 可并行的循环迭代。

循环携带依赖 (Loop-carried dependence)

概念 说明
迭代间依赖 第 i 次迭代的结果被第 i+k 次使用
无携带依赖 各迭代独立 → 可向量化

例子：

// 可向量：每次迭代写不同 a[i]
for (i = 0; i < n; i++) a[i] = b[i] + c[i];

// 不可直接向量：归约
for (i = 0; i < n; i++) sum += a[i];

依赖检测：GCD 测试

对仿射访问下标 (a \cdot i + b) 与 (c \cdot i + d) 的依赖，用 最大公约数 (GCD) 等测试判断是否存在跨迭代冲突。

编译器流水线： 依赖分析 → 若安全则向量化 / 展开 / 软件流水线。

增强并行：标量扩展等

技术 作用
归约 (Reduction) 识别 特殊并行归约（树形加和）
标量扩展 将部分依赖循环 transform 为可并行形式
循环交换 / 分块 改善访问模式（衔接 Ch2、4.2 条带挖掘）
HFT 视角
手写热循环前自问：迭代间有没有 RAW？ — 有则 SIMD 需掩码或改算法
#pragma omp simd / 编译器报告 -fopt-info-vec — 看 为何未向量化
归约（如全市场成交量累加）适合 批量离线，不适合单 tick 关键路径

section-4.6-4.8-交叉问题实例与陷阱

4.6 能耗与 DLP

策略 特点
快而窄 高频率乱序 CPU — 高单线程性能，功耗大
慢而宽 多泳道向量、降频降压 — 同吞吐下能耗可低一个数量级

启示： DLP 架构适合 吞吐型 workload；与 HFT「低延迟单线程」目标常 错位。

4.7 实例：Tegra vs Tesla、Core i7 vs GTX 280

对比 要点
移动 GPU (Tegra) vs 服务器 GPU (Tesla) 规模、带宽、双精度、功耗墙
Core i7 vs GTX 280 GPU 在 计算密集 + 大工作集 上峰值极高
Gather-Scatter 无硬件支持时 SIMD 潜力 大打折扣 — 稀疏/间接访问是 GPU/AVX 共同软肋
HFT 视角
选型：实盘 CPU 调延迟，研究集群 GPU 调吞吐 — 勿混为一谈
i7 单线程低延迟 + 复杂分支仍常胜 GPU 小 batch

4.8 谬误与陷阱

谬误 真相
只看向量峰值性能 启动开销 (Start-up overhead) — 短向量/短循环得不偿失
GPU 线程越多越好 散乱访存 再多线程也救不了带宽；合并访问才是关键
SIMD = 总是更快 分支、依赖、对齐、gather 成本可抵消收益
忽略数据布局 SoA vs AoS 决定能否向量化（→ Ch2）
