3.1

section-3.1-ILP概念与挑战

什么决定能否并行？

两条指令能否在同一周期或重叠执行，取决于 相关性（Dependence）。

相关性类型 含义 例子
数据相关（真相关） 后一条使用前一条写过的值 r2 = r1 + 1 依赖 r1 = ...
名字相关 同名寄存器/存储，但无真数据流 反相关、输出相关
控制相关 分支决定后续是否执行 if (x) { ... }

名字相关细分：

类型 别名 说明
反相关 (Antidependence) WAR 读后写 — 先读旧值，后写同名
输出相关 (Output dependence) WAW 写后写 — 两次写同一名字

流水线冒险

冒险 对应 本质
RAW 数据相关 写后读 — 最常见、最难躲
WAW 输出相关 写后写
WAR 反相关 读后写

处理器必须 检测并处理冒险，维持：

  • 程序顺序 (Program order) — 对外可见的语义顺序
  • 数据流正确性 — 读到的应是「应该读到」的值
HFT 视角
热循环里 长 RAW 链（价格→信号→数量→校验）→ IPC 低，即使用乱序 CPU
虚函数/分支密集 策略逻辑 → 控制冒险 + 分支预测失败惩罚
微优化前先看：依赖链长度、分支可预测性（perf branch-misses）
3.2

section-3.2-编译器揭示ILP

循环展开 (Loop Unrolling)

做法 效果
复制循环体 多次 减少 分支次数（每 N 次迭代才判一次）
调整循环终止与归纳变量 暴露更多 独立指令 供调度
配合寄存器分配 减少循环内 RAW 链对流水线的束缚

直觉： 分支 = 控制冒险 + 预测压力；展开后编译器/CPU 有更大 指令窗口 做调度。

展开度 权衡
过小 分支开销仍显著
过大 ICache 压力、寄存器溢出到栈（反而变慢）
HFT 视角
固定 tick 处理 批量 N 档行情 时，手动或编译器展开内层循环 — 常见于 checksum/解码
-O3 -funroll-loops 对 极热小循环 可试；务必 benchmark + 看 ICache miss
展开不能替代 数据布局（Ch2）— miss 时 ILP 无米下锅

3.3

section-3.3-高级分支预测

流水线加深 + 多发射 → 一次分支预测错误可浪费 十余条甚至更多 在飞指令 → 分支惩罚极高。

动态分支预测演进

预测器 思路
相关预测器 (Correlating) 利用 其他分支历史 预测当前分支 —「分支行为相关」
锦标赛预测器 (Tournament) 局部 vs 全局 预测器 自适应选择 谁更准
标记混合 / TAGE 多表、不同历史长度；当前高性能 CPU 常用方案

要点： 预测的是 方向（跳/不跳）；取指还需 目标地址（→ 3.7 BTB）。

可预测 难预测
计数器 % 2 == 0 数据依赖分支 if (price > threshold)
极少走的 error 路径 哈希表、红黑树查找
likely/unlikely 标注的冷路径 订单类型 switch 若分布均匀
HFT 视角
perf stat -e branches,branch-misses — branch-miss 率应进 回归测试
热路径：无分支（cmov、位运算、查表）、分支外提、separate hot/cold 函数
状态机：用 表驱动 替代长 if-else 链 — 利于预测与 ICache
别在 tick 热路径里打 log（隐含分支 + syscall）
3.4

section-3.4-3.5-动态调度与Tomasulo

顺序 vs 乱序

模式 行为
顺序发射、顺序执行 遇 RAW 且无法旁路 → 停顿
动态调度 乱序执行、乱序完成 — 操作数就绪即可执行，不必等程序顺序上更早的慢指令

限制： 仍须保证 数据流正确性；WAR/WAW 需额外处理。

Tomasulo 算法核心

指令 → 保留站 (Reservation Station) 等待操作数
     → 操作数到齐 → 执行
     → 结果经 CDB (Common Data Bus) 广播给所有等待该结果的保留站
机制 作用
保留站 缓冲未就绪指令，解耦发射与执行
寄存器重命名 动态消除 WAR/WAW — 逻辑寄存器映射到更多物理寄存器
CDB 广播 结果一产生即转发，减少 RAW 停顿
HFT 视角
你 看不见 Tomasulo，但感受到：独立指令可并行、长延迟 load 阻塞后续依赖链
load 使用点 尽量靠后排列（编译器调度）— 给硬件隐藏 miss 的窗口
重命名 不解决 cache miss — Ch2 仍是第一战场
3.6

section-3.6-硬件推测与ROB

克服控制相关

硬件推测 (Hardware speculation)：

  1. 预测 分支方向
  2. 在分支 未解决前 按预测方向 取指、执行
  3. 预测错误 → 撤销 推测路径上的状态

重排序缓冲区 (ROB)

动态推测 = 分支预测 + 动态调度 + ROB。

原则 说明
乱序执行 保留站/CDB 层面可乱序
顺序提交 (In-order commit) 仅当指令 非推测 且位于 ROB 队首逻辑顺序时，才更新 架构状态（寄存器/内存）
推测错误 清空 ROB 中错误路径，恢复预测前状态
精确异常 顺序提交保证异常点 可精确定位 — 对 OS 重要

内存推测更谨慎： store 通常需等退休/commit 规则满足才对外可见。

HFT 视角
分支预测失败 = 流水线清空 — 数十周期级惩罚，远大于一条加法
热路径 减少不可预测分支 比启用更激进 -O3 更有效
侧信道（Spectre 类）与推测执行有关 — 交易代码一般 不处理不可信指针；了解即可
精确异常 对你写用户态策略影响小；内核/驱动相关
3.7

section-3.7-3.9-多发射与指令交付

多发射 (Multiple Issue)

要使 CPI < 1，每周期须 发射多条指令。

类型 调度 代表
静态超标量 编译器决定发射包 部分嵌入式
VLIW / EPIC 编译器显式打包 Itanium 路线
动态推测超标量 硬件运行时调度 x86 Core 系列

瓶颈： 不仅执行单元要够，还要 前端每周期供给足够指令。

BTB 与取指

组件 作用
BTB (Branch Target Buffer) 缓存分支 目标地址 — 预测正确时 零周期 分支惩罚（与方向预测配合）
集成取指单元 预取、对齐、处理 taken 分支后的取指流

实现权衡：ROB vs 物理寄存器重命名

现代高性能 CPU 常用 大量物理寄存器 + 重命名，ROB 管 提交顺序；细节因厂商而异。

共同目标： 在 功耗/面积 预算内最大化 有效 ILP。

HFT 视角
宽发射 + 深流水线 → 频率高但 分支/miss 惩罚深
i7 类：4-wide 发射 + SMT — 单线程仍可能吃不满发射宽度若分支/miss 多
调优目标：让热基本块 IPC 接近 1+，而非追逐峰值 GHz
ICache：热代码 紧凑、内联克制 — 前端供给不及会 stall fetch

3.11

section-3.11-多线程技术

当 ILP 无法隐藏 cache miss 的长延迟 时，可让 多线程共享 同一处理器的功能单元 — 从 ILP 过渡到 TLP（衔接 Ch5）。

模型 行为
粗粒度多线程 一线程 stall（如 miss）才切换 — 切换开销大
细粒度多线程 每个周期轮换线程 — 隐藏停顿，单线程变慢
SMT (同步多线程) 同一周期 混合发射 多线程指令；建基于乱序超标量 + 重命名

SMT 要点： 利用已有 重命名与动态调度，让功能单元在一线程 stall 时被 其他线程 使用。

HFT 视角
Intel 超线程 (HT)：逻辑核共享物理执行单元 — 两线程争用 ROB、LSU、cache
低延迟实盘常见做法：BIOS/OS 关 HT，一物理核绑一关键线程 — 换 尾延迟确定性
非关键任务（日志、监控）可放 非隔离核 或 SMT sibling
SMT ≠ 多核并行 — Ch5 讲 真多核 与一致性
3.12

section-3.12-实例分析-Cortex-A53与Core-i7

与 Ch2 §2.6 同一对 CPU，本章从 ILP 视角 对照。

ARM Cortex-A53

维度 设计
定位 移动 / 嵌入式，能效
执行 双发射、静态顺序 执行（in-order）
推测 无激进乱序推测
分支 相对简单预测

ILP 策略： 靠 编译器 在顺序核上排好指令；硬件简单、省电。

HFT 视角
非典型实盘 CPU；理解 顺序核 — miss/依赖直接 stall，无 ROB 深推测

Intel Core i7-6700

维度 设计
定位 桌面 / 服务器，峰值性能
流水线 深、乱序、推测
发射 多发射超标量
SMT 支持 同步多线程（每核 2 逻辑线程）
分支 TAGE 类 高级预测 + BTB

ILP 策略： 硬件尽最大努力挖掘 ILP；功耗与面积换 IPC。

HFT 视角
colo Xeon/Core 同级 思路类似 — 善用乱序但 别触发 miss/分支风暴
压测对比：关 SMT、绑核、taskset — 观察 P99 变化
与 Ch2 合读：i7 = 激进 cache 预取 + 激进 ILP + SMT

ILP 维度对照

Cortex-A53 Core i7-6700
发射 2-wide，顺序 4-wide，乱序
推测 弱 强（ROB）
SMT 无 有
分支预测 简单 TAGE + BTB
适用 PMD/IoT 服务器/HFT 主机

本章小结

Ch3 链路：相关性 → 冒险 → 编译器展开/调度 → 分支预测 → Tomasulo/重命名 → 推测+ROB → 多发射+BTB → SMT。

HFT 落地优先级：

  1. 减分支、提可预测性（3.1–3.3）
  2. 减 cache miss（Ch2）— 否则 ILP 空转
  3. 绑核、慎 SMT（3.11–3.12）
