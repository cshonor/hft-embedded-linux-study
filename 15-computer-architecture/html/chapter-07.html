7.1

section-7.1-7.2-DSA设计原则

背景

趋势 后果
摩尔定律放缓 晶体管增长变慢
Dennard 终结 不能靠提频白嫖性能
通用 CPU 单线程停滞 转向 领域专用

DSA 定义： 为 某一计算领域 高度优化；其他任务仍跑在 通用处理器 上。

五大设计原则

1. 专用内存，最小化数据移动

通用 CPU DSA
复杂 cache 层次 Scratchpad（软件管理暂存器内存）
不可预测 miss 可预测 数据放置

能耗事实： 数据移动往往比 算术 更费电。

2. 资源投入算术与片上存储

摒弃 乱序、SMT 等大面积微架构 → 换成 成百上千简单 MAC/ALU。

3. 用最简单的并行形式

若 2D SIMD 或 VLIW 够用的领域，不用复杂多线程。

4. 缩减数据大小与类型

手段 效果
INT8/INT16 代替 FP32/64 带宽、算力密度 ↑
领域足够精度即可 内存受限 领域收益巨大

5. 领域语言 (DSL)

TensorFlow、Halide 等 — 编译/映射到 DSA 硬件。

HFT 视角
固定格式行情解码 = 窄类型 + 规则并行 — 类似 DSA 思维，即使用 CPU 也宜 表驱动 + SIMD
Scratchpad 直觉：mlock 热数据、hugepage、无 page fault — 追求 确定性延迟（与 TPU 单线程确定性同源）
FPGA 行情 filter：专用逻辑 换通用分支（→ 7.5 Catapult）
别在 tick 路径盲目 INT8 量化 — 金融精度与合规先验证

section-7.3-深度神经网络领域

核心运算

运算 说明
矩阵/向量乘 占算力主体
激活函数 ReLU 等非线性
卷积 可转化为矩阵乘（im2col 等）

三类网络

类型 结构 典型用途
MLP 全连接 基础特征映射
CNN 卷积 + 池化 计算机视觉；模板计算 (Stencil)
RNN/LSTM 循环状态 语音、序列、时间依赖

训练 vs 推理

阶段 特点
Training 反向传播、大批量、FP32/混合精度、极高算力与 HBM 带宽
Inference 延迟敏感、可 量化、批大小常更小

优化手段：

技术 作用
Batching 提高利用率
Quantization FP32 → 定点/INT8，推理加速
HFT 视角
alpha 研究：离线训练 CNN/RNN/Transformer — GPU/Crest 类
实盘推理：若用 ML 信号，多为 低 QPS、严格尾延迟 — 更像 TPU 推理 问题，非训练
订单簿/LOB 多为 规则逻辑；ML 多在 特征/信号层，与 DNN 硬件选型解耦
Stencil 直觉可类比 二维 order book 快照 局部窗口 — 但 HFT 少用 CNN 于 tick 路径
7.4

section-7.4-Google-TPU

定位

属性 说明
形态 数据中心 DNN 推理 ASIC
非目标 通用 CPU 替代、灵活训练

微架构要点

组件 规模/特点
脉动阵列 (Systolic array) 65,536 个 8-bit MAC
片上统一缓冲区 最高 24 MiB scratchpad 风格
指令风格 CISC、单线程、确定性 执行
数据类型 INT8 推理为主

脉动阵列直觉： 数据在 PE 网格中 节律流动，乘加在本地完成，减少访存。

为何适合云端推理

需求 TPU 匹配
高吞吐推理 巨大 MAC 阵列
99% 尾延迟 无乱序/无 SMT — 行为可预测
能效 砍掉通用机制
HFT 视角
TPU 优化 批量推理 SLA — 与 HFT 单 tick 超低延迟 不同问题域
可借鉴：确定性执行模型（少推测、少共享）对 尾延迟 的价值 — 实盘 CPU 也关 HT/省电扰动
INT8 量化推理 ≠ 交易价格精度；风控模型 若上生产需单独验证

section-7.5-Microsoft-Catapult

定位

属性 说明
形态 数据中心 FPGA 加速器
部署 Bump-on-a-wire — 串接在网络路径上（NIC 旁）
初期用途 Bing 搜索排序：特征提取、ML 打分
扩展 CNN 等可重配置 workload

编程模型

层次 说明
Shell 系统级外壳 — PCIe、DMA、网络接口
Role 应用级逻辑 — 开发者专注算法

降低 RTL 全栈难度，支持 部分重配置。

HFT 视角
最接近交易场景的 DSA 案例之一：在 网线路上 做解析/过滤/聚合
SmartNIC、FPGA 行情解码、inline checksum — 同「bump-in-the-wire」哲学
灵活度 FPGA > ASIC；峰值能效 ASIC > FPGA — 量产后才固化 ASIC

7.6

section-7.6-Intel-Crest

定位

属性 说明
目标 DNN 训练（非推理尾延迟）
数值格式 Flexpoint — 16 位矩阵 + 共享 5 位指数
内存 HBM2 高带宽
互连 极高 片间带宽 — 多芯片扩展

Flexpoint 直觉： 比 FP32 省位宽，比纯 INT 动态范围好 — 训练数值稳定性与密度折中。

目标： 训练速度相对 CPU 两个数量级 提升。

HFT 视角
研究侧：大规模因子/深度学习训练 — 与实盘路径分离
HBM + 多芯片 = 带宽 bound 训练；实盘 tick 仍是 延迟 bound
Flexpoint 思路：领域定制 数值格式 — 交易定点（fixed-point）在 embedded 风控里偶有类似
7.7

section-7.7-Pixel-Visual-Core

定位

属性 说明
设备 PMD — 手机成像管线
类型 图像处理单元 (IPU)
计算 2D PE 阵列 + 模板/卷积类运算

关键结构

机制 作用
2D Line Buffers 滑动窗口行缓冲 — 卷积/stencil 局部复用
Halo（晕圈）通信 边界像素在 PE 间交换
2D SIMD 匹配图像空间并行

原则体现： 专用片上缓冲 + 最简 2D 并行 + 窄类型。

HFT 视角
PMD 级 DSA — 与 colo 服务器无关
Line buffer / stencil 思想可类比 滑动窗口指标（VWAP、rolling vol）— 软件实现时注意 复用 vs 重算
SOC 集成（→ 7.8）：多 IP 块共存 — 类比 CPU + NIC FPGA + GPU 异构机

section-7.8-7.11-综合对比与陷阱

7.8 SoC 集成

现代 手机/边缘 SoC 集成：

应用 CPU + GPU + ISP/IPU + DSP + 基带 + …

DSA 以 IP 块 形式复用 — 面积与功耗预算内各司其职。

HFT 视角
服务器异构：x86 + SmartNIC FPGA + 可选 GPU — 同类「分工」逻辑

7.9–7.10 CPU vs GPU vs TPU（Roofline）

书中用 Roofline 对比 Haswell CPU、NVIDIA K80 GPU、Google TPU（DNN 推理）：

结论（数量级） TPU vs 通用
性能 约 15–30×（推理任务）
性能/瓦特 约 30–80×

原因： 去掉乱序/SMT 等、INT8、巨大脉动阵列、scratchpad 减数据移动。

→ Ch4 Roofline

HFT 视角
同一 Roofline 可用于判断：行情解析 是算力 bound 还是内存 bound
高 MAC 吞吐 不能 直接换成 低 ns 发单 — 指标是 延迟分位数 非 IPS

7.11 谬误与陷阱

类型 内容 真相
谬误 定制芯片必花 1 亿美元 简化 DSA（无复杂通用核）NRE 可低得多
陷阱 只用 吞吐量 (IPS) 评 DNN 硬件 在线服务有 严格响应时间 — 与 TPU 确定性设计相关
陷阱 忽视 编程/移植成本 DSL、编译器、Shell/Role 生态决定落地
