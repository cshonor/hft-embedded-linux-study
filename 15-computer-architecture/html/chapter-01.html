1.1

section-1.1-1.2-引言与计算机分类

技术趋势的转变

背景 含义
Dennard 缩放定律终结 晶体管缩小不再等比例降低功耗密度
摩尔定律放缓 晶体管密度增长变慢，单靠缩小工艺换性能越来越难
ILP 红利见顶 超标量、乱序、深流水线带来的指令级并行收益递减

行业转向： 不再指望「免费」提频与 ILP，转而挖掘：

并行维度 缩写 典型手段
数据级并行 DLP SIMD、向量、GPU
线程级并行 TLP 多核、多线程
请求级并行 RLP 多请求流水线、WSC 规模扩展
领域特定 DSA 为特定 workload 定制硬件（如 AI 加速器、FPGA 行情解析）
HFT 视角
单机 HFT：TLP（绑核、少共享）+ 数据局部性 比再挖 ILP 更现实
行情解析、checksum、批量解码 → SIMD/DLP 候选
交易所侧 colo：服务器（Server） 类别；策略研究机：桌面/PMD

五大计算类别

类别 典型场景 设计侧重
物联网 / 嵌入式 传感器、MCU 功耗、成本、实时性
个人移动设备 (PMD) 手机、平板 能效、电池
桌面计算 PC、工作站 性价比、交互响应
服务器 数据库、Web、交易 吞吐、可靠性、扩展
集群 / 仓储级 (WSC) 超大规模数据中心 规模经济、每瓦性能

HFT 实盘机 落在 服务器；回测/研究集群可能触及 WSC 思路（批量任务、成本/瓦特优化）。

Flynn 分类法

按 指令流 (I) 与 数据流 (D) 划分：

类型 指令 数据 例子
SISD 单 单 传统单核顺序执行
SIMD 单 多 AVX/NEON 向量指令
MISD 多 单 少见（流水线不同阶段对同一数据）
MIMD 多 多 多核多线程
HFT 视角
多策略进程 / 多核绑核 → MIMD
固定宽度行情解码、批量价格运算 → SIMD 优化候选
热路径常是 SISD 精心调优 + 外围 MIMD 分工（I/O 核 vs 策略核）

section-1.3-定义计算机体系结构

架构师的工作 不限于 ISA，而是三层叠加：

指令集架构 (ISA)     ← 程序员可见的指令、寄存器、内存模型
      ↓
计算机组织 (微架构)   ← 流水线、缓存、分支预测、乱序执行
      ↓
硬件实现             ← 工艺、版图、时钟、物理设计

设计约束

在满足功能的前提下，在多维约束间 权衡：

约束 问题
价格 芯片面积、产量、学习曲线
功耗 / 能量 散热、机房电费、电池（PMD）
性能 响应时间、吞吐
可用性 / 可靠性 MTTF、冗余、修复时间

要点： 同一 ISA 可有多种微架构实现（如 x86 的不同代 CPU）；换 CPU 可能 ISA 不变、微架构大变 — 程序行为（尤其是时序、cache）会变。

HFT 视角
你写的 C++/Go 针对 ISA + ABI；延迟调优针对 微架构 + OS（cache 行、NUMA、prefetch）
选型时问：这颗 CPU 的微架构对我的 hot loop 友好吗？（L3 大小、内存通道、AVX 宽度）
「换同 ISA 新 CPU」≠ 性能线性提升 — 要 重新 profile
1.4

section-1.4-1.6-技术成本与功耗趋势

1.4 技术趋势

集成电路、DRAM、Flash、磁盘、网络等技术 不同步演进。

重要经验法则：

带宽（吞吐量）的增长速度 ≥ 延迟（响应时间）改善速度的平方

含义 HFT 直觉
链路「标称 Gbps」涨得快 单次事务延迟难同比下降
内存容量涨、随机访问延迟难降 局部性 比「买更大 DRAM」更关键
10G→100G 网卡 仍要盯 P99 尾延迟、中断/coalescing，不能只看线速

1.5 功耗与能量

功耗与能量已成为微处理器设计的 首要制约。

概念 说明
动态功耗 与开关活动、电压、频率相关；(P \propto C V^2 f) 量级直觉
DVFS 动态电压频率调节 — 降频降压换能效
暗硅 (dark silicon) 散热限制下，芯片上许多晶体管 无法同时全速开启
HFT 视角
Turbo / 睿频 受功耗墙限制 — 多核全负载时单核峰值频率可能下降
isolcpus + 绑核：减少无关核唤醒，降低 package 功耗竞争
机房 TDP / 散热 决定能否长期维持峰值频率 — colo 选型要看 sustained vs burst

1.6 成本趋势

硬件成本受 时间、产量、商品化 影响：

因素 作用
学习曲线 产量翻倍，单位成本下降
良率 缺陷率影响可用 die 数
商品化 标准品（DRAM、SSD）比定制 ASIC 便宜

芯片成本核心公式（直觉）：

[ \text{芯片成本} \propto \frac{\text{晶圆成本}}{\text{良率} \times \text{每片晶圆合格 die 数}} ]

面积越大 → 每片晶圆 die 数越少 → 单颗成本越高。

HFT 视角
实盘用 成熟服务器平台（商品化）通常优于早期定制硅 — 除非延迟收益可量化覆盖 NRE
FPGA/智能网卡：性能/瓦特/成本 三角要用 TCA 式思维 算账（类比交易 TCA）
1.7

section-1.7-1.8-可靠性与性能量化

1.7 可靠性 (Dependability)

指标 含义
MTTF Mean Time To Failure — 平均故障间隔时间
FIT Failures In Time — 每 十亿小时 的故障数（MTTF 的倒数量级）
MTTR Mean Time To Repair — 平均修复时间
可用性 系统可提供服务的时间比例；与 MTTF、MTTR 相关

关系直觉： 可用性 ↑ ← MTTF ↑ 或 MTTR ↓（冗余、热备、快速 failover）。

HFT 视角
交易所对接：双机热备、链路冗余 — 可用性直接等于「能否下单」
单点故障（网卡、交换机、进程）要有 检测 + 切换时间 预算
「软件 bug」不算 FIT 里的硬件故障，但 同等影响可用性 — 要靠测试与风控

1.8 性能评估

黄金法则：

执行时间（响应时间） 是唯一一致、可靠的性能衡量标准。

误区 正确做法
只看峰值 MIPS / FLOPS 测 真实 workload 的 wall-clock
只看平均延迟 HFT 必看 尾延迟 (P99/P999)
算术平均 SPECRatio 多基准汇总用 几何平均数 (Geometric Mean)

常见基准家族：

系列 用途
SPEC CPU 通用计算性能（整型/浮点）
SPECpower 性能-功耗权衡（服务器能效）
TPC 事务处理（数据库类负载）

几何平均为何重要： 算术平均会被「某一基准暴涨」拉高，掩盖短板；几何平均更反映 乘法意义上的整体比。

HFT 视角
自有 benchmark：端到端 tick-to-trade、replay 回放 — 不用 SPEC 代替
对比两台机器：固定 相同输入 trace、相同内核/网卡配置
报告 中位数 + P99 + max；几何平均可用于 多场景 replay 套件 汇总
→ 压测方法：14-HFT ch10 · 06.6-Systems-Performance Ch12 基准测试

section-1.9-计算机设计的量化原则

全书最重要的设计 尺子 — 后续各章都是这些原则在具体子系统上的展开。

利用并行性 (Take Advantage of Parallelism)

层次 手段
请求级 多连接、流水线服务
线程级 多核、超线程
数据级 SIMD、向量
指令级 流水线、超标量（收益递减）

局部性原理 (Principle of Locality)

类型 定义 硬件对应
时间局部性 最近访问的项可能很快被再次访问 cache 命中
空间局部性 地址相邻的项往往被一起访问 cache line、预取

→ 深入：Ch 2 存储器层次 · 02-CSAPP Ch6

HFT 视角
订单簿：SoA vs AoS、热字段同 cache line、冷数据分离
行情：顺序访问 友好；随机指针追逐毁 cache
false sharing：两核写同一 cache line 的不同字 → 性能崩塌（→ Ch2 / Ch5）

关注常见情况 (Focus on the Common Case)

在 出现频率高 的路径上投入优化，整体收益最大。

HFT 视角
优化 99% 行情包路径；罕见 admin 消息可慢
分支预测：likely/unlikely 或重排让 hot branch 在前

阿姆达尔定律 (Amdahl's Law)

增强系统某一部分，整体加速比受限于 未被增强部分所占时间比例。

[ S = \frac{1}{(1 - p) + \frac{p}{k}} ]

  • (p) — 可优化部分占整体时间比例
  • (k) — 该部分加速倍数

核心： 若 90% 时间在串行段，整体最多 ~10×，再优化剩余 10% 收益有限。

HFT 视角
端到端 = 收包 + 解码 + 策略 + 发单 + 内核/排队 — profile 找 最大 p
优化占 1% 的函数 10× → 几乎无感；优化占 60% 的解码 2× → 显著
→ CSAPP 1.9 Amdahl

处理器性能公式

[ \text{CPU 时间} = \text{IC} \times \text{CPI} \times \text{时钟周期时间} ]

因子 含义 优化方向
IC (Instruction Count) 指令条数 算法、编译器、ISA 选择
CPI (Cycles Per Instruction) 每条指令平均周期 流水线、cache miss、分支
时钟周期时间 频率倒数 工艺、散热墙

HFT： 热路径同时压 IC（内联、去虚调用）与 CPI（cache、分支）与 频率稳定性（绑核、禁节能）。

section-1.10-1.12-综合运用与谬误陷阱

1.10 综合运用 (Putting It All Together)

通过 真实服务器配置 与基准（如 SPECpower）对比，展示 性能 × 价格 × 功耗 三维权衡。

维度 要问的问题
性能 在我的 workload 下 wall-clock 多少？
价格 $/性能 或 $/瓦特是否可接受？
功耗 机房散热、电费、能否 sustained turbo？

案例直觉（Dell PowerEdge 类服务器）： 更高配置不一定线性更快 — 要看瓶颈在 CPU、内存带宽还是 I/O。

HFT 视角
colo 机器选型：replay 基准 + 功耗墙 同看
「加核」对单线程热路径可能 零收益 — Amdahl + 绑核策略

1.11–1.12 谬误与陷阱 (Fallacies and Pitfalls)

谬误 真相
峰值性能 ≈ 实际性能 差距极大；峰值 marketing 数字少用于工程决策
硬件增强一定同时提高能效 并不绝对；更高 IPC/频率可能增功耗
只看单一指标 MIPS、核数、GHz 都不能代替端到端时间
忽略常见情况 优化冷门路径浪费面积与复杂度
假设内存与 CPU 同速增长 带宽-延迟鸿沟持续存在
HFT 视角
网卡 线速 Gbps ≠ 你的策略 tick-to-trade
「新 CPU 代数」要 同 trace 重测；勿外推 SPEC 比值
低延迟优化常 增功耗（busy poll、全核满载）— 要算 $/纳秒 与散热
