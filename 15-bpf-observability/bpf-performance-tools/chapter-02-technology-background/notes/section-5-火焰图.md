# 2.5 火焰图（读法 / 特性 / 变体）

> 底本：《BPF之巅》第 2 章技术背景，2.5 节（印刷 p42–45，含 2.5.1–2.5.5）

火焰图是 Brendan Gregg 的招牌发明，本节讲它如何从调用栈数据生成、怎么读、有哪些变体。

## 2.5.1–2.5.2 调用栈信息 → 剖析

采样得到的调用栈（每栈若干帧）按"栈底→栈顶"逐帧拼接计数。例如采样两次 `main→func_a→func_c`、一次 `main→func_a`，得到每帧的计数。这一步把海量栈数据压缩成可画的树。

## 2.5.3 火焰图怎么画

- 每个帧一个矩形；**宽度 ∝ 该帧出现次数（频率）**；Y 轴是栈深（上=被调者）。
- 同层帧按**字母序**排列（不是时间序！）。
- 颜色随机（暖色系），仅为了区分相邻矩形，无数据含义。

## 2.5.4 读法要点（书中的核心经验）

1. **先看最宽的"塔"**——占比最大的代码路径最值得优化。
2. **自顶向下找宽_plateau_（平顶）**——顶部无子帧的宽矩形是叶子函数，直接热点。
3. X 相邻不代表时间相邻；比较两个矩形宽度才有意义。
4. 火焰图显示的是**采样占比**（on-CPU 时间份额），不是单次调用耗时。

## 2.5.5 变体

| 变体 | 数据源 | 回答的问题 |
|---|---|---|
| CPU 火焰图（on-CPU） | PMC/定时采样 | CPU 时间去哪了 |
| off-CPU 火焰图 | 调度器事件 | 阻塞/等待时间去哪了 |
| 内存火焰图 | malloc/free/页错误 | 谁分配/占用了内存 |
| 差分火焰图 | 优化前后两图对比 | 优化生效了吗 |
| 冰柱图 | 火焰图倒置 | 视觉偏好 |

## HFT 关联

- HFT 延迟分析两大杀手锏：**on-CPU 火焰图**（交易线程热路径、找宽塔=最耗时函数）+ **off-CPU 火焰图**（行情线程为何被挂起：锁、page fault、futex 等待）。两者合起来覆盖"在跑"和"没在跑"的全部时间。
- 差分火焰图用于验证调优：改动前各抓一份，对比确认热点迁移。
- 注意：perf 采样对被观测进程有微开销，HFT 生产机上建议短窗口、低频率（如 49Hz）采样。

## 陷阱

- 把 X 轴当时间轴读（"左边先执行"）——错，是字母序。
- on-CPU 火焰图看不到睡眠/阻塞：交易系统"线程闲着但延迟高"要看 off-CPU 图。
- 采样频率与目标工作负载频率锁相（如都恰好 100Hz）会引入偏差 → 用 99Hz 这类质数频率。

## 自测

<details>
<summary>1. 火焰图中矩形的宽度、高度、颜色各代表什么？</summary>

宽度=该帧在采样中的出现频率（时间占比）；高度=调用深度（Y 轴向上是被调者）；颜色无数据含义，仅视觉区分。
</details>

<details>
<summary>2. 为什么用 99Hz 而不是 100Hz 采样？</summary>

避免与负载固有周期（如 100Hz 的定时器）锁步采样（lockstep sampling），造成系统性偏差。
</details>

<details>
<summary>3. off-CPU 火焰图解决什么问题？</summary>

展示线程不在 CPU 上运行时的时间分布（等锁、IO、调度延迟等），与 on-CPU 图互补。
</details>
