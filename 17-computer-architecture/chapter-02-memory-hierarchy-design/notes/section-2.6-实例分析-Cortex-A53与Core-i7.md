## 2.6 实例分析：ARM Cortex-A53 与 Intel Core i7-6700

两个 **设计目标截然不同** 的真实处理器，展示同一套层次思想的不同取舍。

---

### ARM Cortex-A53 — 移动 / 嵌入式 (PMD)

| 维度 | 设计选择 |
|------|----------|
| **定位** | 能效优先，非峰值性能 |
| **缓存** | 相对 **简单的两级** cache |
| **TLB** | **微型 TLB**，面积与功耗约束 |
| **预取** | 保守 — 省电、可预测 |

**启示：** 在功耗预算内，用 **足够但不过度** 的层次结构服务 PMD workload。

| HFT 视角 |
|----------|
| 一般不用于低延迟实盘；理解 **「简单层次 + 小 TLB」** 在边缘/网关设备上的行为 |

---

### Intel Core i7-6700 — 桌面 / 服务器

| 维度 | 设计选择 |
|------|----------|
| **定位** | 高性能，复杂 **乱序** 流水线 |
| **缓存** | **三级** — L1/L2 per core，**L3 共享** |
| **预取** | **极其激进** 的硬件预取 |
| **非阻塞** | 深度配合乱序执行 |

**启示：** 为常见桌面/服务器负载（顺序扫描、规则 stride）优化 AMAT；非常规访问可能 **预取适得其反**。

| HFT 视角 |
|----------|
| **colo 服务器常见类似层次** — L3 共享意味着多策略/多线程 **争用 LLC** |
| 绑核 + 减少跨核共享数据 → 降低 L3 争用与 false sharing |
| 压测时换 **同代不同 SKU**（L3 大小不同）可能显著改变 replay 性能 |
| 与 [16-Systems-Performance Ch7](../../../14-systems-performance/chapter-07-memory/) 的 NUMA/TLB 观测对照 |

---

### 对照总表

| | Cortex-A53 | Core i7-6700 |
|---|------------|--------------|
| 目标 | 功耗 | 性能 |
| Cache 级数 | ~2 级 | 3 级 + 共享 L3 |
| TLB | 小 | 大 |
| 预取 | 保守 | 激进 |
| 典型场景 | 手机、IoT | 桌面、交易服务器 |


### 常见陷阱

- 用 Cortex-A53 的 cache 行为推断 i7 性能 — 两者预取策略（保守 vs 激进）、缓存层次（2 级 vs 3 级）、TLB 大小差异极大；行为不可互相推断
- 以为 i7 激进预取一定更快 — 对 **不规则访问模式**（哈希表、指针追逐），激进预取可能 **预取污染** → 反而比保守预取慢
- 换同代不同 SKU 不重新压测 — L3 容量差异（如 8MB vs 12MB）可能显著改变 replay 性能，尤其是多策略争用 LLC 的场景

### 自测题（点击展开）

<details>
<summary>Q1. Cortex-A53 和 Core i7-6700 在缓存层次和预取策略上的主要差异是什么？</summary>

A53：2 级 cache，保守预取（省电、可预测）。i7：3 级 cache（L3 共享），**激进预取**（为顺序扫描/规则 stride 优化）。A53 为功耗设计，i7 为性能设计。

</details>

<details>
<summary>Q2. 为什么 i7 的激进预取对某些 HFT 负载反而有害？</summary>

激进预取对 **顺序扫描** 友好，但对 **哈希表/指针追逐** 等不规则访问 → 预取无用 line → 挤掉热数据 → miss rate 上升 → 性能下降。HFT 订单簿查找、链表遍历等场景需 profile 确认预取是否有害。

</details>

<details>
<summary>Q3. HFT colo 服务器为什么要注意 L3 共享？绑核有什么帮助？</summary>

L3 多核共享 → 多策略/多线程工作集之和超 L3 → **互挤失效**（LLC eviction）。绑核隔离 → 每核工作集独享 L3 分区（Intel CAT 可硬件隔离）→ 减少 cross-core eviction → 降低 miss rate。

</details>
