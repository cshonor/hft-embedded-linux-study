## RFC 3542 Builder/Parser API

相对 IPv4 手工 TLV，POSIX 提供**构建与解析**函数族。

### 构建（发送）

```text
inet6_opt_init()     → 初始化缓冲区
inet6_opt_append()   → 追加选项（自动对齐/填充）
inet6_opt_finish()   → 完成
```

### 解析（接收）

| 函数 | 作用 |
|------|------|
| **`inet6_opt_next()`** | 迭代选项 |
| **`inet6_opt_find()`** | 按类型查找 |

避免手算 padding 与对齐错误。

## 个人学习总结

IPv6 Hop-by-Hop / Destination 选项：Hop-by-Hop=每个路由器处理，Destination=仅目的端处理。通过 `setsockopt(IPV6_HOPOPTS/IPV6_DSTOPTS)` 设置，格式为 TLV 序列。

**一句话**：Hop-by-Hop=沿途每跳都看（如路由器警报），Destination=只有终点看（如移动 IPv6）。

> 易考点：Hop-by-Hop 选项影响转发性能（每跳都需解析），应尽量少用。Router Alert 选项用于组播。
