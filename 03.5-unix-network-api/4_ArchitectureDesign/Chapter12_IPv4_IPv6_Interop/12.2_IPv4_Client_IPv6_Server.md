# 12.2 IPv4 客户与 IPv6 服务器

> [Ch 7.8 IPV6_V6ONLY](../../1_BasicFoundation/Chapter07_SocketOption/7.8_IPv6_Socket_Option.md) · [12.4 测试宏](12.4_IPv6_Address_Macro.md)

---

## 核心机制：双栈服务器的降维兼容

双栈主机上，监听 **`AF_INET6`** 的服务器**能否**接纯 IPv4 客户？

**可以 — 内核全自动处理。**

---

## 底层交互步骤

```text
① 服：socket(AF_INET6) → bind(in6addr_any / ::) → listen
② 客：IPv4 connect → 向双栈主机 IPv4 地址发 TCP SYN
③ 内核：
     IPv4 SYN 到达 → 发现端口被 IPv6 监听套接字占用
     将客户 32 位 IPv4 转为 128 位 IPv4-mapped IPv6
     例：192.168.1.1 → ::ffff:192.168.1.1
④ 服：accept/recvfrom → 看到合法 sockaddr_in6，不知底层走 IPv4
⑤ 服：send → 目的为 mapped 地址 → 内核封装为 IPv4 报文回客
```

---

## 重点结论

**绑定通配地址的 IPv6 监听套接字，可同时处理 IPv6 与 IPv4 客户** — 不必为两种协议各起一个监听进程。

---

## 防坑：`IPV6_V6ONLY`

若只要 **纯 IPv6**、拒绝 IPv4 映射：

```c
setsockopt(fd, IPPROTO_IPV6, IPV6_V6ONLY, &on, ...);  /* on = 1 */
```

详见 [Ch 7.8](../../1_BasicFoundation/Chapter07_SocketOption/7.8_IPv6_Socket_Option.md)。

---

## 个人学习总结

IPv4 客户端连接 IPv6 服务器：服务器 `socket(AF_INET6)` + `bind(::)` + `IPV6_V6ONLY=0`。内核将 IPv4 地址映射为 `::ffff:a.b.c.d`，客户端正常用 `AF_INET` socket 连接。

**一句话**：v6 服务器 bind ::（全零）+V6ONLY=0，自动接受 v4 客户端，对端地址显示为 ::ffff:v4。

> 易考点：accept 返回的客户端地址结构是 sockaddr_in6，但 sin6_addr 是 v4-mapped 格式。
