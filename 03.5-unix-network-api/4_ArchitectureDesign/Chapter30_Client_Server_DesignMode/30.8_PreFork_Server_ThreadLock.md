# 30.8 预先派生子进程：accept 使用线程上锁保护

> [30.7 文件锁](30.7_PreFork_Server_FileLock.md) · [30.9 传 fd](30.9_PreFork_Server_Fd_Transfer.md) · [Ch 26 互斥量](../../2_AdvancedSkill/Chapter26_Thread/study.md)

## 优化

弃文件锁 → **`mmap` 共享内存**中的 **`pthread_mutex_t`**（**`PTHREAD_PROCESS_SHARED`**）保护 `accept`。

---

## 结论（多进程范式）

**Prefork + 共享内存互斥锁抢 `accept`** = 多进程架构中**性能最优**的抢占模式；上锁开销极低。

**Nginx 类思想**：进程隔离容错 + 高效 accept 分发。

---

## 选型：稳定性

第三方库不可重入、需**单客户崩溃不拖全网关** → 优选此范式。

---

## 个人学习总结

Pre-fork 线程锁服务器：用 `pthread_mutex`（进程间共享，PTHREAD_PROCESS_SHARED）替代文件锁。比 flock 快——内存操作 vs 系统调用。

**一句话**：线程锁=flock 的加速版——pthread_mutex 住共享内存，省去系统调用开销。

> 易考点：mutex 需放在 `mmap(MAP_SHARED)` 共享内存中 + `pthread_mutexattr_setpshared(SHARED)` 才能跨进程使用。
