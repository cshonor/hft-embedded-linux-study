# 30.10 TCP 并发服务器：每个客户一个线程

> [Ch 26 线程](../../2_AdvancedSkill/Chapter26_Thread/study.md) · [30.11 线程池](30.11_PreThread_Server_SingleAccept.md)

---

## 运作机制

```text
主线程 accept → pthread_create 处理该客户
（非 fork）
```

---

## 优势

线程创建/销毁通常比进程快 **一个数量级以上**。

---

## 痛点

| 风险 | 后果 |
|------|------|
| 无内存隔离 | 一线程段错误或 **`exit()`** → **整进程**崩溃 |
| 库要求 | 所用库须 **线程安全** |

---

## 个人学习总结

TCP 并发线程服务器：accept→pthread_create→新线程处理客户端→主线程继续 accept。比 fork 轻量（线程创建快于进程创建），共享地址空间。

**一句话**：fork→pthread_create，进程→线程，共享内存省去 IPC，但需注意线程安全。

> 易考点：线程模型需处理临界区（mutex），但共享数据无需 IPC。线程创建比 fork 快 5-10 倍。
