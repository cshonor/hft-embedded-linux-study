# 30.5 TCP 并发服务器：每个客户一个子进程

> [Ch 4.7 fork](../../1_BasicFoundation/Chapter04_BasicTCPSocket/4.7_Fork_Exec_Function.md) · [Ch 5 并发回射](../../1_BasicFoundation/Chapter05_TCP_Client_Server_Demo/study.md)

---

## 运作机制

```text
主进程：listen + accept 循环
  新连接 → fork
    子进程：处理已连接套接字
    父进程：close 已连接 fd，继续 accept
```

---

## 优势

| 点 | 说明 |
|----|------|
| 隔离 | 一客户崩溃**不**拖垮其他 |
| 简单 | 代码直观、安全 |

---

## 痛点

海量**短连接**（早期 HTTP/1.0）：**`fork` CPU 开销** 可超过网络 I/O 处理本身。

---

## 个人学习总结

TCP 并发 fork 服务器：accept→fork→子进程处理客户端→父进程继续 accept。经典 Unix 并发模型，每个客户端独立进程。

**一句话**：accept+fork=最经典的并发服务器模型，进程隔离安全但 fork 开销大。

> 易考点：fork 后父进程 close(connfd) 子进程 close(listenfd)，避免 fd 泄漏。SIGCHLD 需处理避免僵尸。
