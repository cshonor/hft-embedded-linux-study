## 架构重构

书中**重写**第 17 章 `get_ifi_info` — 底层从 `ioctl(SIOCGIFCONF)` 改为 **`sysctl` + `NET_RT_IFLIST`**。

---

## 数据流解析

内核返回的缓冲区交织两类消息：

| 消息 | 内容 |
|------|------|
| **`if_msghdr`** | 接口级：索引、`sockaddr_dl`（名 + **MAC**） |
| **`ifa_msghdr`** | 地址级：该接口上 IPv4/IPv6 单播、掩码、广播 |

```text
遍历可变长流
  → 见 if_msghdr：新建 ifi_info 节点
  → 见后续 ifa_msghdr：把 IP/掩码/广播挂到该接口
```

---

## 相对 ioctl 版的优势

| 点 | 说明 |
|----|------|
| 无截断 | Two-Pass sysctl |
| IPv4 + IPv6 | 同一套解析路径 |
| MAC | 从 `sockaddr_dl` 直接得到 |
| 健壮性 | 不依赖加倍猜缓冲区 |

仍是多播、代理、拓扑发现程序的**基石**。

---

## 个人学习总结

`get_ifi_info` 路由套接字版：用 sysctl(NET.RT_IFLIST) 获取所有网络接口信息，解析 if_msghdr 中的接口名、MTU、标志、地址等。替代 ioctl SIOCGIFCONF 方案。

**一句话**：get_ifi_info 路由版=sysctl IFLIST 查接口列表，比 ioctl SIOCGIFCONF 更完整（含广播/掩码/目的地址）。

> 易考点：sysctl IFLIST 一次返回所有接口所有地址，ioctl 需多次调用。UNP 推荐用 sysctl。
