## 核心主旨与时代背景

早期 Unix（如 `routed`）只能靠晦涩、**平台相关**的 `ioctl` 读写内核路由表。

**4.3BSD Reno** 引入 **路由套接字（Routing Socket）**：将路由表抽象为 **`AF_ROUTE`** 域，应用像收发网络数据一样与内核路由基础设施对话。

---

## 三大核心能力

| # | 方向 | 能力 |
|---|------|------|
| 1 | 进程 → 内核 | 写路由套接字：**增 / 删 / 改** 路由表项 |
| 2 | 内核 → 进程 | **异步事件推送**（相对 `ioctl` 的最大进步）：ICMP 重定向等导致路由变化时，内核把变更**广播**给所有打开路由套接字的进程 |
| 3 | 进程 ↔ 内核 | **`sysctl`** 一次性、无截断倾印完整路由表或接口配置 |

---

## 创建与权限

```c
int sockfd = socket(AF_ROUTE, SOCK_RAW, 0);
```

| 项 | 说明 |
|----|------|
| 域 | **`AF_ROUTE`** |
| 类型 | **`SOCK_RAW`** |
| 写权限 | 仅 **root**（同原始套接字写限制） |

## 个人学习总结

路由套接字（routing socket）概述：`socket(AF_ROUTE, SOCK_RAW, AF_INET)` 创建路由套接字，可读写内核路由表。特权进程可修改路由表，普通进程可查询。

**一句话**：AF_ROUTE=内核路由表的"管理通道"，写=改路由表（需 root），读=监听路由变化。

> 易考点：路由套接字消息格式是 rt_msghdr + sockaddr 序列，不是普通 read/write。
