# 23.9 心搏和地址不可达

> [23.4 SCTP_PEER_ADDR_CHANGE](23.4_SCTP_Notification_Msg.md) · [Ch 2.5 SCTP](../../1_BasicFoundation/Chapter02_TCP_UDP_SCTP/2.5_SCTP_Protocol.md)

---

## 与 TCP Keep-Alive 对比

TCP 默认 Keep-Alive 可达 **2 小时**量级；SCTP 原生 **心搏（Heartbeat）** 管理**多路径**。

---

## 工作原理

| 状态 | 行为 |
|------|------|
| 备用路径空闲 | 周期性发 **HEARTBEAT** Chunk |
| 多次超时无 **HEARTBEAT ACK** | 该 IP 标 **Inactive（不可达）** |
| 业务数据 | 切到其他健康路径 |

内核可发 **`SCTP_PEER_ADDR_CHANGE`** 通知应用。

---

## 应用层干预

**`SCTP_PEER_ADDR_PARAMS`**：调心搏间隔等（强行关闭心搏一般不推荐）。

---

## 个人学习总结

心跳与地址不可达检测：SCTP heartbeat 定期探测备用路径活性。`SCTP_PEER_ADDR_PARAMS` 可按地址配置 heartbeat 间隔。地址不可达时触发 SCTP_PEER_ADDR_CHANGE 通知。

**一句话**：heartbeat=定期 ping 备用路径，不可达→PEER_ADDR_CHANGE 通知→切 primary，可达→切回。

> 易考点：heartbeat 默认只对非 primary 地址开启，primary 用重传超时检测。可强制开启。
