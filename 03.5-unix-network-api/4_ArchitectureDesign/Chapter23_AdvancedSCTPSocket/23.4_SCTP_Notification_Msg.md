## 事件驱动深化

订阅 **`SCTP_EVENTS`** 后，内核将状态变更作为**通知**与数据混在 `sctp_recvmsg` 路径（**`MSG_NOTIFICATION`**）。

本节强调高级程序**必须处理**的类型：

| 通知 | 含义 |
|------|------|
| **`SCTP_ASSOC_CHANGE`** | 关联建立、正常/异常终止 |
| **`SCTP_PEER_ADDR_CHANGE`** | 多宿路径 **不可达 / 恢复可达** — 监控、HA |
| **`SCTP_SEND_FAILED`** | 消息穷尽重传仍失败 → 业务回滚 |

Ch 9.14 已列基础类型；本章侧重**运维与多宿**场景。

---

## 个人学习总结

SCTP 通知消息：通过 SCTP_EVENTS 订阅关联事件（SCTP_ASSOC_CHANGE、SCTP_PEER_ADDR_CHANGE、SCTP_SEND_FAILED 等）。通知和数据复用同一 socket，用 msg_flags 区分。

**一句话**：订阅 SCTP_EVENTS→recvmsg 看到 MSG_NOTIFICATION→解析 sctp_notification 联合体判断事件类型。

> 易考点：SCTP_SEND_FAILED 通知表示某消息发送失败（含原始数据），可用于应用层重传决策。
