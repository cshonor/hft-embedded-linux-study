27.1

概述

Ch 7 套接字选项 · Ch 14 sendmsg · study.md

核心主旨

多数应用无需操作 IP 层首部；诊断工具、测量、特殊路由策略则需控制或观察 IP 报文路径。

IPv4 vs IPv6 架构

IPv4 IPv6
机制 首部最多 40 字节固定“选项”区 扩展首部菊花链，长度灵活
现状 极少使用、多被过滤 工程化 API（RFC 3542）
编程 手工 TLV 裸字节 inet6_opt_* / inet6_rth_*

资料说明

上传资料截至第 8 章；第 27 章框架来自目录（约第 13 页），细节按 UNP 第 3 版整理，请与全本对照验证。

个人学习总结

IP 选项概述：IPv4 头部可选 TLV（Type-Length-Value）选项——源路由、记录路由、时间戳等。IPv6 用扩展头（Extension Header）替代，更灵活。通过 setsockopt IP_OPTIONS 设置。

一句话：IPv4 选项=头部 TLV（40 字节上限），IPv6 选项=扩展头链（无上限），API 不同。

易考点：IPv4 选项很少用，大多数路由器忽略或丢弃带选项的包，ping -R 是少数用途。

27.2

IPv4 选项

27.3 源路由 · Ch 7 getsockopt

API

getsockopt / setsockopt(sockfd, IPPROTO_IP, IP_OPTIONS, ...);
项 说明
级别 IPPROTO_IP
选项名 IP_OPTIONS
格式 无内核辅助结构 — 须按 RFC 791 TLV 手工拼接裸字节

常见选项（理论）

选项 作用 局限
记录路由（RR） 沿途路由器填入出口 IP 40 字节上限 → 最多约 9 个 IP，公网几乎无用
时间戳（Timestamp） 记录到达时间与 IP 同上，现代极少启用

个人学习总结

IPv4 包选项：setsockopt(IP_OPTIONS) 设置 IPv4 头部选项。选项格式：code(1B)+len(1B)+ptr(1B)+data。常用选项：LSRR/SSRR（源路由）、RR（记录路由）、TS（时间戳）。

一句话：IP_OPTIONS=往 IP 头部塞 TLV 选项，ping -R 用 RR 记录路径，traceroute 用 LSRR。

易考点：IP 头部+选项总长最多 60 字节（IHL 4 bit，最大 15×4=60），选项最多 40 字节。

27.3

IPv4 源路径选项

27.2 IPv4 选项 · 27.6 IPv6 路由首部

核心主旨

源路由：由发送端（非路由器）指定数据报必经的中间节点。

类型 行为
严格源路由（SSRR） 必须严格按列表逐跳；非直连下一跳 → 丢弃
宽松源路由（LSRR） 必须经过列表节点，节点间可经未列出路由器

编程要点

方向 机制
发送 构造 IP 列表 → setsockopt(IP_OPTIONS)
接收（TCP） SYN 带源路由 → 内核反转路径，应答原路返回

现实：全网封杀

风险 后果
IP 欺骗、绕过防火墙拓扑 核心路由器/防火墙见源路由选项 → 静默丢弃

现代网络编程：仅作理论了解，勿依赖生产路径。

个人学习总结

IPv4 源路由选项：LSRR（宽松源路由）指定途经节点、SSRR（严格源路由）指定完整路径。setsockopt(IP_OPTIONS) 设置。用于 traceroute 和网络诊断。

一句话：LSRR=必须经过这些节点（可经过其他），SSRR=只经过这些节点（严格路径）。

易考点：源路由是安全风险（可绕过防火墙），大多数路由器默认禁用。现代网络基本不用。

27.4

IPv6 扩展首部

27.5 步跳/目的选项 · Ch 12 IPv6

菊花链（Daisy-Chain）

IPv6 用 Next Header 串联扩展首部，典型顺序：

IPv6 基本首部
  → 步跳选项（Hop-by-Hop）     /* 必须第一个；路径上每跳都处理 */
  → 目的选项（Destination）    /* 仅目的主机处理 */
  → 路由首部（Routing）
  → 分片（Fragment）
  → AH / ESP（IPsec）
  → TCP / UDP / …
首部 特点
Hop-by-Hop 唯一要求路径上每个路由器检查的首部
Destination 仅终点处理

个人学习总结

IPv6 扩展头：IPv6 用扩展头链替代 IPv4 选项——逐跳选项、路由头、分片头、目的选项、AH、ESP。每个扩展头有 Next Header 字段串联下一个。

一句话：IPv4 选项=塞进 40 字节头部，IPv6 扩展头=独立链表串联，无 40 字节限制。

易考点：扩展头顺序有规范要求——Hop-by-Hop 必须第一，之后是 Dest Options、Routing、Fragment、AH、ESP、Dest Options、TCP/UDP。

27.5

IPv6 步跳选项和目的地选项

27.4 扩展首部链 · 27.7 粘附选项

RFC 3542 Builder/Parser API

相对 IPv4 手工 TLV，POSIX 提供构建与解析函数族。

构建（发送）

inet6_opt_init()     → 初始化缓冲区
inet6_opt_append()   → 追加选项（自动对齐/填充）
inet6_opt_finish()   → 完成

解析（接收）

函数 作用
inet6_opt_next() 迭代选项
inet6_opt_find() 按类型查找

避免手算 padding 与对齐错误。

个人学习总结

IPv6 Hop-by-Hop / Destination 选项：Hop-by-Hop=每个路由器处理，Destination=仅目的端处理。通过 setsockopt(IPV6_HOPOPTS/IPV6_DSTOPTS) 设置，格式为 TLV 序列。

一句话：Hop-by-Hop=沿途每跳都看（如路由器警报），Destination=只有终点看（如移动 IPv6）。

易考点：Hop-by-Hop 选项影响转发性能（每跳都需解析），应尽量少用。Router Alert 选项用于组播。

27.6

IPv6 路由首部

27.3 IPv4 源路由 · 27.8 历史 API

机制（Type 0，已废弃）

类似 IPv4 宽松源路由；构建 API：

inet6_rth_init()
inet6_rth_add()      /* 逐个添加必经 IPv6 节点 */
inet6_rth_reverse()  /* 反转收到的路由首部 */

安全：RFC 5095

Type 0 路由首部可被用于 DoS 放大（两节点间无限弹射）→ RFC 5095 正式废弃。

现代内核多默认拒绝 Type 0 — 学习 API 时须知历史背景，勿在生产依赖。

个人学习总结

IPv6 路由头（Routing Header）：类似 IPv4 源路由，指定数据包途经的节点。Type 2 用于移动 IPv6（单地址），Type 0 已废弃（安全风险）。

一句话：IPv6 Routing Header=IPv4 源路由的继任者，Type 0 废弃（安全），Type 2 仅供移动 IP。

易考点：RH Type 0 可指定任意路径绕过防火墙，RFC 5095 废弃。现代实现默认丢弃 Type 0。

27.7

IPv6 粘附选项（Sticky Options）

Ch 14.5 sendmsg 辅助数据 · Ch 15.7 SCM_RIGHTS

两种传递途径

方式 API 作用域
辅助数据 sendmsg 的 msg_control 仅当前一个数据报（UDP 常用）
粘附选项 setsockopt（如 IPPROTO_IPV6, IPV6_DSTOPTS） 套接字级：此后所有报文（含 TCP 各分节、write）自动附带

选型

单包实验 / UDP 每包不同扩展首部  → sendmsg 辅助数据
TCP 客户端全程相同扩展首部       → setsockopt 粘附

理解单次生效 vs 全局生效的控制面差异。

个人学习总结

IPv6 粘性选项（Sticky Options）：setsockopt(IPV6_RTHDR/IPV6_HOPOPTS) 设置后对该 socket 所有后续包自动生效（"粘住"）。无需每次 sendmsg 携带。对应辅助数据（ancillary data）方式是每包指定。

一句话：粘性=setsockopt 一次设好所有包都带，辅助数据=每次 sendmsg 单独指定。

易考点：粘性选项适合"所有包都用相同选项"场景，辅助数据适合"每包不同选项"场景，二者可混用。

27.8

历史性 IPv6 高级 API

27.5 inet6_opt_*

RFC 2292 vs RFC 3542

标准 说明
RFC 2292（旧） 函数前缀非 inet6_；结构体长度/对齐不统一
RFC 3542（当前） inet6_opt_* / inet6_rth_* — 应优先使用

工程建议

新代码只使用 RFC 3542 API，勿依赖旧宏与原型。

个人学习总结

历史 IPv6 API：早期的 IPv6 选项 API（如 IPV6_PKTINFO 的旧用法）已被 RFC 3542 取代。旧 API 不支持粘性选项，只支持辅助数据。移植时需更新到新 API。

一句话：RFC 2292（旧）→RFC 3542（新），主要差异是支持粘性选项+更清晰的 ancillary data 定义。

易考点：旧 API 用 IPV6_PKTOPTIONS getsockopt 获取选项，新 API 直接用 IPV6_RTHDR 等 setsockopt。

小结

study.md

章节核心提炼

1. IPv4 选项的黄昏

40 字节上限 + 防火墙封杀 → RR/源路由 现代无实用价值，理论了解即可。

2. IPv6 工程化

扩展首部菊花链 → 可扩展；用 inet6_opt_* / inet6_rth_* 构建解析。

3. Type 0 路由已废

RFC 5095 — 勿依赖 IPv6 Type 0 路由首部。

4. 双轨控制面

辅助数据 sendmsg 粘附 setsockopt
生效 单包 整套接字

学习路径

Ch14 辅助数据 → Ch27 IPv6 扩展首部 → Ch28 原始套接字/ICMP

个人学习总结

IP 选项总结：IPv4 用 IP_OPTIONS 设置头部 TLV（40B 上限），IPv6 用扩展头链（无上限）。IPv6 选项可通过粘性（setsockopt 一次）或辅助数据（每包）设置。源路由选项因安全风险基本废弃。

一句话：IPv4 选项=40B TLV 头部，IPv6 选项=扩展头链+粘性/辅助两种设置方式，源路由已废弃。

HFT 关联：IP 选项基本不用在 HFT 中（增加路由器处理延迟），但理解 IPv6 扩展头有助于排查组播/移动 IP 问题。
