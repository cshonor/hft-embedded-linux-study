19.1

概述

Ch 18 路由套接字 · 19.2 读写 · study.md

核心主旨

IPsec 在网络层为 IP 流量提供 AH（认证） 与 ESP（加密）。核心是 SA（Security Association）：算法、认证方式、密钥等参数集合。

架构分离与 PF_KEY

层 职责
内核 加解密、封包/解包（高 CPU、低延迟）
用户态 IKE 等密钥协商（isakmpd、racoon 等）
桥梁 密钥管理套接字 PF_KEY / AF_KEY — 把协商结果写入内核 IPsec 引擎

创建套接字

int sockfd = socket(PF_KEY, SOCK_RAW, PF_KEY_V2);
项 说明
协议族 PF_KEY（亦作 AF_KEY）
类型 SOCK_RAW
协议 PF_KEY_V2
权限 须 root（同路由套接字、原始套接字写操作）

与 Ch 18 类比

二者均为 特殊协议族 + 结构化二进制消息，非普通字节流。

资料说明

上传资料截至第 8 章；第 19 章框架来自目录，细节按 UNP 第 3 版整理，请与全本对照验证。

个人学习总结

密钥管理套接字（PF_KEY）概述：socket(PF_KEY, SOCK_RAW, PF_KEY_V2) 创建密钥管理套接字，用于与内核 IPsec（AH/ESP）子系统交互——添加/删除/查询安全关联（SA）和安全策略（SP）。

一句话：PF_KEY=IPsec 的"管理通道"，用户态 IKE 守护进程通过它向内核下发 SA/SP。

易考点：PF_KEY 是 RFC 2367 定义的跨平台协议，Linux 另有 XFRM netlink 接口。

19.2

读和写

Ch 18.3 rt_msghdr · 19.3 SADB_DUMP

通信模型

与路由套接字类似：经 read / write 交换结构化二进制消息，非流式文本。

统一首部：sadb_msg（<net/pfkeyv2.h>）

字段 含义
sadb_msg_version 常为 PF_KEY_V2
sadb_msg_type SADB_ADD、SADB_DUMP、SADB_ACQUIRE 等
sadb_msg_len 整条消息长度，单位 8 字节（64 位）
sadb_msg_seq 请求/应答匹配
sadb_msg_pid 进程标识，匹配用

扩展（Extensions）

sadb_msg
  + sadb_sa      （SPI、生存期等）
  + sadb_address （源/目的 IP）
  + sadb_key     （认证/加密密钥）
  + …
陷阱 说明
8 字节对齐 各扩展须 64 位对齐；解析时按长度指针步进
长度单位 sadb_msg_len 等为 8 字节块数，非字节数

任一 sadb_ext 长度算错 → 内核拒收消息。

个人学习总结

PF_KEY 读写：写=send 发送 sadb_msg 消息（SADB_ADD/SADB_DELETE/SADB_GET 等），读=read 接收内核回复或 SA 过期通知。消息格式是 sadb_msg 头 + 若干 sadb_ext 扩展。

一句话：写 PF_KEY=发 SADB_* 命令操作 SA/SP，读=接收回复+SA 过期/删除事件。

易考点：SADB_REGISTER 注册 SA 过期通知，内核在 SA 即将过期时发 SADB_EXPIRE 消息。

19.3

倾泻安全关联数据库

19.2 sadb_msg · 19.4 静态 SA

核心主旨

内核维护 SADB（Security Association Database） — 当前有效 SA 集合。调试或状态同步时可请求完整快照。

SADB_DUMP 流程

① 构造 sadb_msg：type = SADB_DUMP，指定 satype（如 SADB_SATYPE_ESP）
② write 到 PF_KEY 套接字
③ while read：
     每条消息 = 一条 SA 记录
     末包 sadb_msg_seq 特殊标记（常为 0，依实现）→ 倾泻结束
点 说明
多部分流 SADB 可能很大，内核无法单包返回全部
循环 read 应用须持续读至结束标记

个人学习总结

安全数据库转储：SADB_DUMP 命令转储内核中所有 SA（Security Association Database）。需要 root 权限，返回多条 sadb_msg 消息。

一句话：SADB_DUMP=dump 全部 SA 列表，类似 ip xfrm state show 的底层实现。

易考点：dump 返回的消息中每条包含一个 SA 的完整信息（加密算法、密钥、SPI、生命周期等）。

19.4

创建静态安全关联

19.3 SADB_DUMP · 19.5 动态 SA

核心场景

无 IKE 守护进程时，管理员用 SADB_ADD 向内核硬编码 SA（含明文密钥）— 静态 SA。

生产环境慎用；密钥长期不变风险高。

组装步骤（繁琐）

步 内容
1 sadb_msg，type = SADB_ADD
2 sadb_sa：SPI（同目的 IP 下区分 SA 的唯一索引）
3 sadb_address：源 IP、目的 IP 各一块
4 sadb_key：命令行十六进制密钥 → 二进制，附认证/加密密钥扩展
5 对齐：每扩展长度为 8 字节整数倍，不足则 padding
6 write → 合法则 SADB 立即激活

个人学习总结

静态安全关联创建：SADB_ADD 手动添加 SA——指定源/目的地址、SPI、加密/认证算法、密钥。适用于静态 VPN 配置，无需 IKE 自动协商。

一句话：SADB_ADD=手动创建 SA（指定算法+密钥），IKE 自动协商=动态创建 SA，两者最终都调内核 SA 接口。

易考点：静态 SA 的密钥不会自动更新，安全性差，生产环境应使用 IKE（racoon/strongSwan）自动协商。

19.5

动态维护安全关联

19.4 静态 SA · 19.6 小结

核心主旨

大规模 / 动态 IP 环境依赖 动态 SA + IKE — 这才是 PF_KEY 的设计使命。

异步协作状态机（无 SA 时首包需加密）

① 内核 → IKE（SADB_ACQUIRE）
   业务 IP 包需 ESP，SADB 无匹配 SA
   → 挂起该包 → PF_KEY 发 ACQUIRE（含源/目的 IP）

② IKE → 内核（SADB_GETSPI）
   为即将建立的入站 SA 向内核申请唯一 SPI

③ IKE ↔ 远端 IKE（UDP 500 / ISAKMP）
   Diffie-Hellman、证书验证、会话密钥

④ IKE → 内核（SADB_UPDATE）
   密钥、算法、生存期写入 SADB
   → 唤醒 ① 中挂起的 IP 包 → ESP 加密发出
消息 方向 作用
SADB_ACQUIRE 内核 → 用户态 “需要 SA，请协商”
SADB_GETSPI IKE → 内核 预分配 SPI
SADB_UPDATE IKE → 内核 激活 SA、解冻数据面

实战意义

理解 ACQUIRE 捕获与响应循环 — VPN / IPsec 网关后端调试的底层逻辑。

个人学习总结

动态安全关联维护：SADB_REGISTER 注册监听→内核发 SADB_EXPIRE（软过期）→IKE 协商新 SA→SADB_UPDATE 更新→旧 SA SADB_DELETE。实现 SA 自动轮换。

一句话：动态 SA 生命周期=注册监听→软过期通知→IKE 协商新密钥→UPDATE→硬过期 DELETE。

易考点：软过期（soft lifetime）=提前通知用户态协商新 SA，硬过期（hard lifetime）=内核强制删除旧 SA。

19.6

小结

study.md

章节核心提炼

1. 控制面与数据面解耦

PF_KEY / AF_KEY 划分边界：

  • 机制：内核高性能加解密（数据面）
  • 策略：用户态 IKE 协商与鉴权（控制面）

2. 繁杂的内存拼接

须精通 C 指针与 64 位对齐；sadb_ext 长度错误 → 内核拒收。

3. 异步事件基石

SADB_ACQUIRE 事件循环 — 企业级 VPN / IPsec 网关必备。

4. 与 Ch 18 对照

Ch 18 路由 Ch 19 PF_KEY
域 AF_ROUTE PF_KEY
首部 rt_msghdr sadb_msg
对齐 sockaddr 紧凑排列 8 字节扩展
典型守护进程 routed isakmpd / racoon

个人学习总结

PF_KEY 密钥管理总结：通过 sadb_msg 消息与内核 IPsec 交互——DUMP 查询、ADD 创建、UPDATE 更新、DELETE 删除、REGISTER 注册监听。是 IKE 守护进程的底层接口。

一句话：PF_KEY=IPsec 的管理 API，IKE 守护进程（racoon/strongSwan）通过它向内核下发 SA/SP。

HFT 关联：交易所专线如果用 IPsec 加密，理解 PF_KEY 有助于排查 SA 协商失败/过期丢包问题。
