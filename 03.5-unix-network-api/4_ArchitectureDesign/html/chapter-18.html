18.1

概述

Ch 17 ioctl · 18.3 读写 · study.md

核心主旨与时代背景

早期 Unix（如 routed）只能靠晦涩、平台相关的 ioctl 读写内核路由表。

4.3BSD Reno 引入 路由套接字（Routing Socket）：将路由表抽象为 AF_ROUTE 域，应用像收发网络数据一样与内核路由基础设施对话。

三大核心能力

# 方向 能力
1 进程 → 内核 写路由套接字：增 / 删 / 改 路由表项
2 内核 → 进程 异步事件推送（相对 ioctl 的最大进步）：ICMP 重定向等导致路由变化时，内核把变更广播给所有打开路由套接字的进程
3 进程 ↔ 内核 sysctl 一次性、无截断倾印完整路由表或接口配置

创建与权限

int sockfd = socket(AF_ROUTE, SOCK_RAW, 0);
项 说明
域 AF_ROUTE
类型 SOCK_RAW
写权限 仅 root（同原始套接字写限制）

资料说明

上传资料截至第 8 章；第 18 章框架来自目录，细节按 UNP 第 3 版整理，请与全本对照验证。

个人学习总结

路由套接字（routing socket）概述：socket(AF_ROUTE, SOCK_RAW, AF_INET) 创建路由套接字，可读写内核路由表。特权进程可修改路由表，普通进程可查询。

一句话：AF_ROUTE=内核路由表的"管理通道"，写=改路由表（需 root），读=监听路由变化。

易考点：路由套接字消息格式是 rt_msghdr + sockaddr 序列，不是普通 read/write。

18.2

数据链路套接字地址结构

Ch 29 数据链路访问 · 18.3 rt_msghdr

核心结构：sockaddr_dl

定义于 <net/if_dl.h>，处理 MAC / 链路层 地址：

struct sockaddr_dl {
    uint8_t      sdl_len;    /* 结构体总长度 */
    sa_family_t  sdl_family; /* AF_LINK */
    uint16_t     sdl_index;  /* 接口索引，如 1=lo0，2=eth0 */
    uint8_t      sdl_type;   /* IFT_ETHER 等 */
    uint8_t      sdl_nlen;   /* 接口名长度 */
    uint8_t      sdl_alen;   /* MAC 地址长度 */
    uint8_t      sdl_slen;   /* 链路层选择子长度 */
    char         sdl_data[]; /* 接口名 + MAC 连续存放 */
};

易错：内存布局

sdl_data 不是普通 C 字符串：

[ 接口名如 "eth0" ][ MAC 如 00:11:22:33:44:55 ]
错误 正确
printf("%s", sdl_data) 用 sdl_nlen 跳过接口名，再按 sdl_alen 取 MAC

路由消息里常夹杂 sockaddr_dl — 解析 rtm_addrs 时必须识别 AF_LINK。

个人学习总结

数据链路套接字地址（sockaddr_dl）：BSD 路由套接字中用于表示链路层地址，包含接口名、接口索引、链路层地址（MAC）。是 if_msghdr 消息的一部分。

一句话：sockaddr_dl=路由消息中的链路层地址，含接口名+索引+MAC 地址。

易考点：sockaddr_dl 不用于 bind/connect，只在路由套接字消息中作为地址信息出现。

18.3

读和写

18.1 概述 · 18.4 sysctl · Ch 17.9 勿用 ioctl 路由

统一首部：rt_msghdr

进程与路由套接字交换的消息均以 rt_msghdr 打头：

字段 含义
rtm_msglen 整条消息长度
版本 协议版本
rtm_type RTM_ADD / RTM_DELETE / RTM_GET / 通知类型等
rtm_addrs 后续紧跟哪些 sockaddr 的位掩码

读写 API 与普通套接字相同：write / read（或 send / recv）。

rtm_addrs 与紧凑打包

一次路由操作常需多个地址（目的、网关、掩码等）。内核用 掩码 + 连续排列 省内存：

rt_msghdr
  [ 若 RTA_DST  → sockaddr 目的 ]
  [ 若 RTA_GATEWAY → sockaddr 网关 ]
  [ 若 RTA_NETMASK → 可能被压缩的掩码 ]
  ...

解析难点

问题 后果
IPv4 sockaddr_in vs IPv6 sockaddr_in6 长度不同 指针步进必须按实际 sa_len
掩码可能被“压缩” 不能假设固定 16 字节
夹杂 sockaddr_dl 需按 AF_LINK 分支

书中用宏逐步“挖出”每个地址 — C 指针与对齐的终极练习。

内核 → 进程：事件广播

路由表因 ICMP 重定向、守护进程更新等变化时，内核向所有打开 AF_ROUTE 的进程发送通知消息 — ioctl 无法做到。

个人学习总结

路由套接字读写：写=sendto 发送 rt_msghdr 消息（RTM_ADD/RTM_DELETE/RTM_GET 等），读=read 接收内核路由变化通知。消息体是 rt_msghdr 头 + 若干 sockaddr。

一句话：写路由套接字=发送 RTM_* 命令改路由表，读=被动接收路由变化事件。

易考点：RTM_GET 查询路由表时，内核返回的消息可能比请求大（多个匹配项），需循环读取。

18.4

sysctl 操作

Ch 17.5 SIOCGIFCONF 截断 · 18.5 get_ifi_info

核心主旨：取代有缺陷的 ioctl

ioctl(SIOCGIFCONF) 等存在缓冲区静默截断 — sysctl 为 POSIX 推荐的现代方案。

int sysctl(int *name, u_int namelen,
           void *oldp, size_t *oldlenp,
           void *newp, size_t newlen);

MIB 层次化 name[]

访问路由 / 接口时常用层级：

层 典型值 含义
1 CTL_NET 网络子系统
2 AF_ROUTE 路由
3 0 协议号
4 AF_INET / 0 地址族或全部
5 NET_RT_DUMP / NET_RT_IFLIST 倾印路由表 / 接口列表

Two-Pass：规避截断

① sysctl(name, oldp=NULL)     → oldlenp 得到所需精确字节数
② malloc(oldlen)
③ sysctl(name, oldp=buf)      → 完整、无截断取回数据
对比 ioctl sysctl
长度 猜缓冲区，可能截断 先问长度再分配
路由表 不便完整导出 NET_RT_DUMP

个人学习总结

sysctl 路由信息查询：通过 sysctl NET.RT 子树可获取路由表（NET.RT_DUMP）、接口列表（NET.RT_IFLIST）等。比路由套接字读取更安全（无需 root）。

一句话：sysctl=只读查询路由表/接口表的系统调用，无需 root，比 AF_ROUTE 更安全。

易考点：sysctl 返回的是连续的 if_msghdr/rt_msghdr 消息块，需按 len 字段逐个解析。

18.5

get_ifi_info 函数

Ch 17.6 ioctl 版 · 18.4 sysctl · Ch 21 多播

架构重构

书中重写第 17 章 get_ifi_info — 底层从 ioctl(SIOCGIFCONF) 改为 sysctl + NET_RT_IFLIST。

数据流解析

内核返回的缓冲区交织两类消息：

消息 内容
if_msghdr 接口级：索引、sockaddr_dl（名 + MAC）
ifa_msghdr 地址级：该接口上 IPv4/IPv6 单播、掩码、广播 
遍历可变长流
  → 见 if_msghdr：新建 ifi_info 节点
  → 见后续 ifa_msghdr：把 IP/掩码/广播挂到该接口

相对 ioctl 版的优势

点 说明
无截断 Two-Pass sysctl
IPv4 + IPv6 同一套解析路径
MAC 从 sockaddr_dl 直接得到
健壮性 不依赖加倍猜缓冲区

仍是多播、代理、拓扑发现程序的基石。

个人学习总结

get_ifi_info 路由套接字版：用 sysctl(NET.RT_IFLIST) 获取所有网络接口信息，解析 if_msghdr 中的接口名、MTU、标志、地址等。替代 ioctl SIOCGIFCONF 方案。

一句话：get_ifi_info 路由版=sysctl IFLIST 查接口列表，比 ioctl SIOCGIFCONF 更完整（含广播/掩码/目的地址）。

易考点：sysctl IFLIST 一次返回所有接口所有地址，ioctl 需多次调用。UNP 推荐用 sysctl。

18.6

接口名字和索引函数

Ch 7 套接字选项 · Ch 21 IPv6 多播

为何需要

IPv6 多播、IPV6_MULTICAST_IF、部分选项用 接口索引 而非名称 — 必须在 名称 ↔ 索引 间转换。

POSIX 四个标准 API

函数 作用
if_nametoindex(const char *ifname) 名 → 索引；不存在返回 0
if_indextoname(unsigned ifindex, char *ifname) 索引 → 名，写入调用者缓冲区
if_nameindex(void) 动态数组：系统全部 (名, 索引) 对
if_freenameindex(struct if_nameindex *ptr) 释放 if_nameindex 分配的内存

底层实现（常见 Unix）

许多系统上，这 4 个函数内部正是：

打开 AF_ROUTE 路由套接字
  → sysctl(NET_RT_IFLIST) 或 RTM_GET 类消息
  → 解析 if_msghdr / sockaddr_dl

应用层应优先用 POSIX API，而非自己重复解析路由消息。

个人学习总结

if_nametoindex/if_indextoname/if_nameindex：接口名与索引互转的便携函数。if_nameindex 返回全部接口的 {name, index} 数组，用完需 if_freenameindex 释放。

一句话：if_nametoindex="eth0"→2，if_indextoname=2→"eth0"，if_nameindex=一次性获取全部。

易考点：接口索引在 IPv6 组播（IPV6_MULTICAST_IF）和路由套接字中都需要，不是从 0 开始。

18.7

小结

study.md

章节核心提炼

1. 内核与用户态的异步桥梁

AF_ROUTE 打破路由表黑盒：

  • 自定义路由协议（OSPF/BGP 守护进程）可写表项
  • 事件广播让应用对链路断开、IP 漂移、ICMP 重定向等毫秒级响应

2. 指针偏移的艺术

掌握 rt_msghdr + rtm_addrs + 紧凑 sockaddr 群 的步进解析 — 与 sockaddr_dl 的 sdl_nlen/sdl_alen 同属一类难点。

3. sysctl 全面胜出

相对 ioctl 的历史包袱与截断缺陷：

先问长度 → malloc → 再取数据

是现代获取路由表、接口拓扑的基石。

4. get_ifi_info 双实现

章 实现
Ch 17 ioctl + SIOCGIFCONF
Ch 18 sysctl + NET_RT_IFLIST（推荐理解方向）

学习路径

Ch17 ioctl 局限 → Ch18 AF_ROUTE + sysctl → Ch21 多播选接口

个人学习总结

路由套接字总结：AF_ROUTE 读写内核路由表，sysctl 只读查询路由/接口信息，if_nametoindex 等便携函数做接口名索引互转。三者层次递减，便携性递增。

一句话：AF_ROUTE（改路由表）> sysctl（查路由/接口表）> if_nameindex（查接口名）——从底层到高层。

HFT 关联：交易系统需动态感知网卡状态变化（主备切换），可监控路由套接字的事件通知实现。
