12.1

概述

核心主旨与时代背景

IPv4 → IPv6 过渡漫长，长期并存：

主机类型 说明
纯 IPv4 仅 AF_INET
纯 IPv6 仅 AF_INET6
双栈（Dual-stack） 同时支持两者

本章问题：双栈主机上，IPv4 应用与 IPv6 应用如何互通？ 内核扮演 “隐形翻译官”。

资料说明

上传资料截至第 8 章；第 12 章框架来自目录，细节按 UNP 第 3 版整理，请与全本对照验证。

个人学习总结

IPv4/IPv6 互操作概述：双栈（dual-stack）主机同时运行 IPv4 和 IPv6 协议栈。IPv6 socket 可通过 IPV6_V6ONLY 选项控制是否接受 IPv4 映射地址。

一句话：双栈=一台机器同时跑 v4/v6，一个 v6 socket 默认可收 v4 连接（映射地址 ::ffff:a.b.c.d）。

易考点：IPV6_V6ONLY=1 时 v6 socket 只收 v6，=0（默认）时 v4 映射地址也接受。

12.2

IPv4 客户与 IPv6 服务器

Ch 7.8 IPV6_V6ONLY · 12.4 测试宏

核心机制：双栈服务器的降维兼容

双栈主机上，监听 AF_INET6 的服务器能否接纯 IPv4 客户？

可以 — 内核全自动处理。

底层交互步骤

① 服：socket(AF_INET6) → bind(in6addr_any / ::) → listen
② 客：IPv4 connect → 向双栈主机 IPv4 地址发 TCP SYN
③ 内核：
     IPv4 SYN 到达 → 发现端口被 IPv6 监听套接字占用
     将客户 32 位 IPv4 转为 128 位 IPv4-mapped IPv6
     例：192.168.1.1 → ::ffff:192.168.1.1
④ 服：accept/recvfrom → 看到合法 sockaddr_in6，不知底层走 IPv4
⑤ 服：send → 目的为 mapped 地址 → 内核封装为 IPv4 报文回客

重点结论

绑定通配地址的 IPv6 监听套接字，可同时处理 IPv6 与 IPv4 客户 — 不必为两种协议各起一个监听进程。

防坑：IPV6_V6ONLY

若只要 纯 IPv6、拒绝 IPv4 映射：

setsockopt(fd, IPPROTO_IPV6, IPV6_V6ONLY, &on, ...);  /* on = 1 */

详见 Ch 7.8。

个人学习总结

IPv4 客户端连接 IPv6 服务器：服务器 socket(AF_INET6) + bind(::) + IPV6_V6ONLY=0。内核将 IPv4 地址映射为 ::ffff:a.b.c.d，客户端正常用 AF_INET socket 连接。

一句话：v6 服务器 bind ::（全零）+V6ONLY=0，自动接受 v4 客户端，对端地址显示为 ::ffff:v4。

易考点：accept 返回的客户端地址结构是 sockaddr_in6，但 sin6_addr 是 v4-mapped 格式。

12.3

IPv6 客户与 IPv4 服务器

Ch 11.9 AI_V4MAPPED · 12.2 反向场景

核心场景

双栈主机上的 IPv6 客户 连接 纯 IPv4 服务器。

底层交互步骤

① 服：AF_INET 套接字，bind 0.0.0.0
② 客：getaddrinfo + AI_V4MAPPED
     DNS 仅 A 记录 → 转为 ::ffff:x.x.x.x 填入 addrinfo
③ 客：connect(映射地址)
④ 内核：发现 IPv6 套接字连 mapped 地址 → 底层发 IPv4 SYN
⑤ 服：正常 IPv4 连接，常规处理

与 12.2 的不对称性

方向 无额外设备时
IPv4 客 → IPv6 服（双栈） ✅ 内核映射
IPv6 客 → IPv4 服（双栈客户侧） ✅ 客户内核转换
纯 IPv6 客 → 纯 IPv4 服 ❌ IPv4 栈无法理解 128 位地址

跨协议需 NAT64 / DNS64 等网络层设施 — 非本章双栈本地机制。

个人学习总结

IPv6 客户端连接 IPv4 服务器：getaddrinfo 返回 v4 地址，内核在 connect 时将 v6 socket 自动转为 v4 连接（或直接用 v4 地址创建 socket）。取决于实现——Linux 上 v6 socket 不能 connect v4 地址。

一句话：v6 客户端连 v4 服务器=大多数实现不支持，需 getaddrinfo 返回 v4 地址后用 v4 socket。

易考点：跨协议连接的前提是双栈主机，单栈 v6 主机无法直连 v4 服务器（需 NAT64/DNS64）。

12.4

IPv6 地址测试宏

12.2 混合连接 · Ch 3.6 inet 系列

为何需要

IPv6 服务器会同时收到：

  • 原生 IPv6 连接
  • IPv4-mapped 的“伪 IPv6”连接

业务（黑名单、归属地、日志）常需知底层真实协议。

宏定义（<netinet/in.h>）

IN6_IS_ADDR_V4MAPPED(const struct in6_addr *ap)
返回值 含义
非 0 实为 IPv4 客户；前 96 位为 ::ffff:0:0
0 真 IPv6 地址

用法

accept 得到 sockaddr_in6 后：

IN6_IS_ADDR_V4MAPPED(&addr6.sin6_addr) == true
  → 取最后 32 位还原真实 IPv4

个人学习总结

IPv6 地址宏：IN6_IS_ADDR_V4MAPPED 判断是否 v4 映射地址，IN6_IS_ADDR_LOOPBACK 判断回环，IN6_IS_ADDR_MULTICAST 判断组播。提取 v4 地址用 IN6_MAP_V4MAPPED_TO_INADDR。

一句话：一组 IN6_IS_ADDR_* 宏判断 v6 地址类型，v4-mapped 提取用 IN6_MAP_V4MAPPED_TO_INADDR。

易考点：服务器收到 v4 客户端连接后，用 IN6_IS_ADDR_V4MAPPED 判断来源协议，决定是否做 v4 特殊处理。

12.5

源代码可移植性

Ch 11 协议无关 API · Ch 3.2 sockaddr_storage

核心原则

编写在 纯 IPv4 / 纯 IPv6 / 双栈 上均可编译运行的代码。

黄金法则

# 规则 说明
1 勿硬编码 AF_INET / AF_INET6 由解析结果决定
2 getaddrinfo 主机名 + 服务名 → 遍历 addrinfo，ai_family/ai_socktype/ai_addr 直接传给 socket、connect、bind
3 sockaddr_storage accept、保存对端地址时用；勿仅用 sockaddr_in
4 getnameinfo 二进制地址 → 可读字符串；替代 inet_ntoa/inet_ntop（后者需预知协议族）

与互操作的关系

应用层遵循上述范式 → 双栈内核自动完成 IPv4-mapped 等转换 → 协议升级对业务 近乎零感知。

个人学习总结

源码可移植性：用 getaddrinfo/getnameinfo 替代 gethostbyname/inet_addr，用 sockaddr_storage 替代固定大小结构，用 IN6_* 宏判断地址类型。避免硬编码 AF_INET。

一句话：可移植三件套——getaddrinfo（协议无关）、sockaddr_storage（足够大）、IN6_* 宏（类型判断）。

易考点：协议无关编程的核心是 getaddrinfo 遍历 addrinfo 链表逐个尝试 bind/connect。

12.6

小结

study.md

章节核心提炼

1. 互操作枢纽

双栈内核 + IPv4-mapped IPv6 地址（::ffff:IPv4）。

2. 服务端优势

通配绑定的 IPv6 监听套接字 = 同时收 IPv4 / IPv6 — 降低向 IPv6 演进的运维成本。

3. 单向包容

能力 范围
双栈本地 IPv4↔IPv6 映射互通
跨异构网 需 NAT64/DNS64 等

4. 代码演进

严格使用 Ch 11 的 getaddrinfo / getnameinfo + sockaddr_storage；需区分真 IPv6 时用 IN6_IS_ADDR_V4MAPPED；仅 IPv6 监听时设 IPV6_V6ONLY。

学习路径

Ch11 解析 API → Ch12 双栈互操作 → Ch15 UDS / Ch21 多播（继续协议无关）

个人学习总结

IPv4/IPv6 互操作总结：双栈主机默认 v6 socket 接受 v4 映射地址连接，通过 IPV6_V6ONLY 控制。可移植代码用 getaddrinfo + sockaddr_storage 实现协议无关。

一句话：双栈=一个 v6 socket 搞定 v4/v6，可移植=getaddrinfo+sockaddr_storage 忘掉 AF_INET。

HFT 关联：交易系统应做协议无关编程，getaddrinfo 同时解析 v4/v6 地址，由 DNS 决定优先协议。
