15.1

概述

Ch 12 互操作 · 15.2 地址结构 · study.md

核心主旨

Unix 域协议不是广域网协议，而是同一主机上进程间通信（IPC），复用套接字 API（socket、bind、connect、read、write 等）。

协议族：AF_LOCAL（历史上 AF_UNIX，等价）。

为何优先于 TCP 环回？

优势 说明
性能 同机常约为 TCP localhost 的 约 2 倍 — 少校验和、序列号、IP 封装等协议栈开销
描述符传递 无亲缘关系进程间传递已打开 fd（15.7）
凭证传递 内核附带真实 UID/GID（15.8），应用层不可伪造

典型场景

本机微服务、Sidecar、Master/Worker（Nginx/Gunicorn）、需把 accept 到的连接交给工作进程。

资料说明

上传资料截至第 8 章；第 15 章框架来自目录，细节按 UNP 第 3 版整理，请与全本对照验证。

个人学习总结

Unix 域协议（AF_UNIX/AF_LOCAL）：同机进程间通信，不走网络协议栈，性能高于 TCP loopback。地址是文件系统路径名。

一句话：Unix Domain=同机 IPC 的"捷径"，比 TCP loopback 快 2-3 倍，地址是路径名不是 IP:port。

HFT 关联：同机交易组件间通信用 AF_UNIX 比 TCP loopback 延迟更低，省去 TCP 协议栈开销。

15.2

Unix 域套接字地址结构

Ch 3.2 sockaddr · 15.4 bind 陷阱

struct sockaddr_un（<sys/un.h>）

struct sockaddr_un {
    sa_family_t sun_family; /* AF_LOCAL / AF_UNIX */
    char        sun_path[]; /* 绝对或相对路径名 */
};
项 说明
协议族 AF_LOCAL ≡ AF_UNIX
标识 文件系统路径名，非 TCP 端口号

文件系统介入

bind 时在路径下创建类型为 s（socket） 的真实文件。

对比 网络套接字 Unix 域
地址 IP:端口 路径名文件

路径长度

sun_path 有最大长度（实现相关，常约 108 字节）— 过长路径 bind 失败。

个人学习总结

sockaddr_un 结构：sun_family=AF_UNIX，sun_path[108] 存路径名。bind 时自动创建路径文件（需有写权限），unlink 后才能重新 bind。

一句话：sun_path 是文件路径，bind 创建该文件，close 不删除——必须手动 unlink。

易考点：路径长度上限 108 字节（包括 ），超长返回 ENAMETOOLONG。也可用 Linux 抽象命名空间（路径首字节为 ）。

15.3

socketpair 函数

Ch 4.7 fork · 15.5 流式

核心机制：全双工“管道”

pipe 通常半双工；socketpair 创建两个已互连、全双工的 Unix 域套接字。

int socketpair(int family, int type, int protocol, int sockfd[2]);
参数 典型值
family AF_LOCAL
type SOCK_STREAM 或 SOCK_DGRAM
protocol 0

写入 sockfd[0] 的数据可从 sockfd[1] 读，反之亦然。

典型用法

socketpair → fork
  父：close(sockfd[1])，用 sockfd[0]
  子：close(sockfd[0])，用 sockfd[1]
→ 父子极速双向通道

个人学习总结

socketpair 创建一对已连接的匿名 Unix 域 socket（双向管道）。只适用于 AF_UNIX，返回两个 fd 互相可读写。

一句话：pipe=单向管道，socketpair=双向管道，父子进程各持一端通信。

易考点：socketpair 通常在 fork 前调用，父关一端子关另一端，形成双向 IPC 通道。

15.4

套接字函数

15.2 地址 · Ch 4 bind/close

AF_LOCAL 下的特殊行为

1. bind 占坑陷阱

情况 结果
sun_path 已存在 EADDRINUSE

最佳实践：bind 前 unlink(path) 删除旧 socket 文件残留。

2. 权限

客户端连接需：

  • 套接字所在目录有 x（进入） 权限
  • 套接字文件本身有 w（写） 权限

3. close 不删文件

关闭套接字不会自动 unlink 路径 — 退出前未清理会留下无法使用的垃圾 socket 文件。

守护进程：启动时 unlink + 正常退出时再次清理。

个人学习总结

Unix 域 socket 的基本函数与 inet 完全相同——socket/bind/listen/accept/connect/read/write。区别仅在于地址结构用 sockaddr_un，path 替代 IP:port。

一句话：API 和 TCP 一模一样，只是 AF_INET→AF_UNIX、sockaddr_in→sockaddr_un、IP:port→path。

易考点：connect 一个不存在的 path 返回 ENOENT，bind 到已存在 path 返回 EADDRINUSE（需先 unlink）。

15.5

Unix 域字节流客户/服务器程序

Ch 4 TCP 回射 · 15.6 数据报对比

SOCK_STREAM 特性

与 TCP 类似：全双工、无消息边界的字节流。

对比 TCP 环回 Unix 域流
介质 仍走完整 TCP 栈 内核内存拷贝为主
丢包/乱序 有 无（同机）
拥塞/Nagle 有 无 网络拥塞语义

连接失败

connect 到某路径时：

情况 错误
路径存在但不是 socket 文件 失败
无进程 listen ECONNREFUSED

个人学习总结

Unix 域流式 C/S：服务器 socket(AF_UNIX, SOCK_STREAM) → bind(path) → listen → accept；客户端 connect(path)。代码与 TCP C/S 几乎一样，只改地址族和路径。

一句话：把 TCP C/S 代码的 AF_INET→AF_UNIX、sockaddr_in→sockaddr_un 就是 Unix 域流式 C/S。

HFT 关联：同机行情转发用 AF_UNIX SOCK_STREAM，避免 TCP 协议栈的 Nagle/ACK 延迟（但仍需设 TCP_NODELAY 等价物——Unix 域无 Nagle）。

15.6

Unix 域数据报客户/服务器程序

Ch 8 UDP · 15.5 字节流

SOCK_DGRAM 特性

类似 UDP：保留消息边界。

与 UDP 的关键差异

点 UDP（网络） Unix 域数据报
可靠性 可能丢包 单机内可靠，内核保证不丢不乱序
发送阻塞 几乎不阻塞 接收缓冲满时 sendto 可阻塞；O_NONBLOCK → EWOULDBLOCK
客户 bind 常可不 bind 必须先 bind 自己的路径，否则服无法 sendto 回包

易错

照搬 UDP 客户“不 bind”习惯 → Unix 域数据报无法收到应答。

个人学习总结

Unix 域数据报 C/S：socket(AF_UNIX, SOCK_DGRAM) → bind(path) → recvfrom/sendto。类似 UDP 但同机可靠无丢包（内核缓冲区满除外）。

一句话：AF_UNIX+SOCK_DGRAM=同机版 UDP，可靠不丢（无网络栈），但有缓冲区上限。

易考点：Unix 域数据报不需要 connect（可选），sendto 指定对端 path 即可。客户端也需 bind 一个路径才能接收回射。

15.7

描述符传递（Passing Descriptors）

Ch 14.5 sendmsg · Ch 14.6 辅助数据

核心问题

fork 子进程可继承 fd；无亲缘关系的两进程如何让 B 使用 A 已打开的文件/套接字？

错误 正确
把整数 3 当普通数据发给 B fd 仅是进程内索引；B 的 3 可能无关

实质：内核在 B 中分配新 fd，指向与 A 相同的内核文件表项。

API 要求

必须用 sendmsg / recvmsg + msghdr 辅助数据（Ancillary Data）：

字段 值
cmsg_level SOL_SOCKET
cmsg_type SCM_RIGHTS
数据区 要传递的 int fd（可多个）

实战：Master/Worker

Master（root）bind :80 → accept 得 connfd
  → 经 Unix 域 + SCM_RIGHTS 把 connfd 交给 Worker
Worker（低权）直接 read/write 该连接

Nginx、Gunicorn 等架构的核心机制之一。

个人学习总结

fd 传递（SCM_RIGHTS）：通过 Unix 域 socket 的辅助消息（ancillary data）在进程间传递文件描述符。发送方用 sendmsg+CMSG(SCM_RIGHTS)，接收方用 recvmsg 解析 cmsg。

一句话：SCM_RIGHTS=Unix 域 socket 的"超能力"——跨进程传 fd，内核在接收端复制 fd 表项。

HFT 关联：高性能服务器用 fd 传递让 worker 进程直接处理已 accept 的连接，避免 fork 开销。nginx 用类似机制。

15.8

接收发送者的凭证

15.7 辅助数据 · Ch 13 守护进程（待笔记）

核心主旨

接收方需知发送方真实身份（是否 root、是否同组）— 不能信任应用层自报“我是 root”。

内核担保

Unix 域允许通过辅助数据由内核附带 UID / GID — 应用层无法伪造。

平台/机制 说明
部分 BSD SCM_CREDS
Linux SO_PASSCRED + SCM_CREDENTIALS 等组合

具体宏与选项因系统而异 — 查阅本机 man 页。

与 15.7 的关系

同属 sendmsg/recvmsg + cmsghdr 辅助数据通道；SCM_RIGHTS 传 fd，凭证类 cmsg_type 传身份。

个人学习总结

发送方凭证传递：通过 SCM_CREDENTIALS（Linux）或 LOCAL_PEERCRED（BSD）传递 PID/UID/GID。接收方可验证对端身份，实现权限控制。

一句话：SCM_RIGHTS 传 fd，SCM_CREDENTIALS 传身份（pid/uid/gid），都是 Unix 域 socket 的辅助消息。

易考点：Linux 还可用 SO_PEERCRED getsockopt 直接获取对端凭证（无需消息交互），更简单。

15.9

小结

study.md

章节核心提炼

1. 同机 IPC 最优解

明确同机部署 → 优先 AF_LOCAL，弃 TCP 127.0.0.1 — 性能与延迟明显改善。

2. 文件系统清理

bind 创建真实 socket 文件 → 启动 unlink(path)、退出时清理 — 守护进程基本素养。

3. 特权与架构

sendmsg + SCM_RIGHTS 描述符传递 — Master/Worker、多进程分担连接的内功。

4. 流 vs 报

类型 要点
SOCK_STREAM 类 TCP，无网络丢包语义
SOCK_DGRAM 类 UDP 但有边界；可靠；客户须 bind

学习路径

Ch14 sendmsg/辅助数据 → Ch15 UDS + fd 传递 → Ch13 守护进程实践

个人学习总结

Unix 域协议总结：AF_UNIX 同机 IPC 比 TCP loopback 更快，地址用文件路径。核心特性：socketpair（双向管道）、SCM_RIGHTS（传 fd）、SO_PEERCRED（验证身份）。API 与 TCP 完全兼容。

一句话：Unix Domain=同机 IPC 最优解，快于 TCP loopback，fd 传递和凭证验证是杀手锏。

HFT 关联：同机交易组件间用 AF_UNIX + SCM_RIGHTS 实现零拷贝 fd 传递，避免数据在进程间复制。
