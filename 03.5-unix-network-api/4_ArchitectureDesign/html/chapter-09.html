9.1

概述

Ch 2.5 SCTP · Ch 8 · 9.2 · study.md

核心主旨

SCTP（Stream Control Transmission Protocol）：

特性 说明
可靠性 类似 TCP
消息边界 面向消息（非 TCP 字节流）
多宿 Multihoming 多端点多 IP
多流 Multi-streaming 关联内多条独立流

传统 bind/connect/read/write 不足以表达 SCTP → 本章 专用 C API。

与 TCP/UDP 对照

TCP UDP SCTP
抽象 字节流 不可靠数据报 可靠消息 + 流
连接 1 对 1 无连接 关联 Association

资料说明

上传资料正文截至第 8 章；目录含第 9 章框架，细节按 UNP 第 3 版整理，请与全本对照验证。

个人学习总结

SCTP = Stream Control Transmission Protocol，面向消息、多流、多宿。四握手机制（INIT/INIT-ACK/COOKIE-ECHO/COOKIE-ACK）防 SYN Flood，关联（association）替代连接（connection）。

一句话：TCP 可靠流 + UDP 消息边界 + 多流避免头阻塞 + 多宿冗余路径。

HFT 关联：SCTP 多宿天然支持双网卡冗余，但金融交易实际用 TCP+UDP 居多，SCTP 多见于电信信令网。

9.2

接口模型

Ch 4 TCP API · Ch 10

两种套接字模型

1. 一到一（One-to-One）

项 说明
类型 SOCK_STREAM + IPPROTO_SCTP
API 与 TCP 相同：socket → bind → listen → accept / connect
目的 TCP 应用最小改动迁移（IPPROTO_TCP → IPPROTO_SCTP）
局限 一个 fd ↔ 一个关联

2. 一到多（One-to-Many）

项 说明
类型 SOCK_SEQPACKET
API 服：无 accept；客：可不 connect
优势 一个 fd 管理多个关联；多关联消息可交错，无需每关联一新 fd

选型

场景 模型
熟悉 TCP、每连接一线程/进程 一到一
高并发短关联、UDP 式状态机 一到多 + sctp_sendmsg/recvmsg

个人学习总结

SCTP 接口模型分一到一（one-to-one，SOCK_STREAM）和一到多（one-to-many，SOCK_SEQPACKET）。一到一类似 TCP，一到多单个 socket 管理多个关联。

一句话：一到一=TCP 风格（accept 分流），一到多=UDP 风格（recvmsg 带 src addr）但保持连接状态。

易考点：一到多模型下一个 socket 可服务数千关联，无需 fork/thread，适合短消息高频场景。

9.3

sctp_bindx 函数

Ch 4.4 bind

核心机制

标准 bind 只能绑一个 IP（或通配）。

多宿端点需同时绑定多个本地 IP → sctp_bindx 动态增删地址。

操作标志

标志 作用
SCTP_BINDX_ADD_ADDR 追加绑定地址
SCTP_BINDX_REM_ADDR 移除绑定地址

个人学习总结

sctp_bindx 一次绑定多个地址到同一 socket，实现多宿（multihoming）。参数：sd、addr 数组、addrcnt、flags（SCTP_BINDX_ADD_ADDR / SCTP_BINDX_REM_ADDR）。

一句话：bind 只绑一个地址，sctp_bindx 批量增删地址，支撑多宿冗余。

易考点：多宿地址必须同一 port，内核自动在主路径失败时切换备用路径。

9.4

sctp_connectx 函数

Ch 4.3 connect

核心主旨

向多宿远端发起关联。

connect sctp_connectx
目标 单个 IP IP 地址数组

底层行为

内核按数组顺序尝试各地址，直至建立关联或全部失败 — 利用 SCTP 多宿路径选择。

个人学习总结

sctp_connectx 一次发起到多个对端地址的连接，内核选择可达地址建立关联。返回 primary addr。

一句话：connect 连一个地址，sctp_connectx 连一组地址，内核自动选路。

HFT 关联：多宿连接的 primary/backup 路径切换由 heartbeat 检测触发，切换时间通常 0.5-1s。

9.5

sctp_getpaddrs 函数

9.6 sctp_freepaddrs · 9.7 本地地址

核心主旨

获取指定 SCTP 关联中对端（Peer）的全部多宿 IP 地址。

用途

  • 关联存活期间对端可能 ASCONF 增删地址
  • 探测对端可达路径、调试多宿拓扑

易错细节

函数 malloc 返回地址数组 → 用完必须 sctp_freepaddrs（9.6），否则泄漏。

个人学习总结

sctp_getpaddrs 获取对端（peer）所有绑定的地址列表。返回 sockaddr 数组，需配合 sctp_freepaddrs 释放。

一句话：getpaddrs=获取 peer 地址列表，getladdrs=获取 local 地址列表，用完必须 free。

易考点：返回的地址数量和顺序不保证，调用方应遍历全部。

9.6

sctp_freepaddrs 函数

9.5 sctp_getpaddrs

核心主旨

释放 sctp_getpaddrs 分配的内存。

重点结论

与 getpaddrs 成对调用 — 不可省略。

个人学习总结

sctp_freepaddrs 释放 sctp_getpaddrs 返回的地址数组内存。必须配对调用，否则内存泄漏。

一句话：getpaddrs/freepaddrs 是一对，getladdrs/freeladdrs 是一对，谁分配谁释放。

易考点：Linux 实现中这组函数底层用 getsockopt(SCTP_PEER_ADDR_PARAMS) 获取。

9.7

sctp_getladdrs 函数

9.8 sctp_freeladdrs · 9.5 对端地址

核心主旨

获取指定关联中本地（Local）正在使用的全部绑定 IP 地址。

个人学习总结

sctp_getladdrs 获取本端（local）所有绑定地址列表，配合 sctp_freeladdrs 释放。

一句话：local 地址=bindx 绑定的那些，peer 地址=connectx/connect 对端报告的那些。

易考点：关联建立后两端地址列表都可能变化（动态增删），不应缓存。

9.8

sctp_freeladdrs 函数

9.7 sctp_getladdrs

核心主旨

释放 sctp_getladdrs 动态分配的内存。

个人学习总结

sctp_freeladdrs 释放 sctp_getladdrs 返回的内存。与 sctp_freepaddrs 用法完全相同。

一句话：四个函数两对——getpaddrs/freepaddrs 管 peer，getladdrs/freeladdrs 管 local。

易考点：面试常问"如何获取 SCTP 关联的所有地址"——答 getpaddrs+getladdrs。

9.9

sctp_sendmsg 函数

Ch 8 sendto · 9.10

核心主旨

SCTP 核心发送 API；一到多模型取代 sendto/write。

关键 sctp_sndrcvinfo 字段

字段 作用
sinfo_stream 指定流号（缓解队头阻塞）
sinfo_flags 如 SCTP_UNORDERED 无序交付；SCTP_EOF 终止关联
sinfo_ppid 净荷协议标识（业务类型标记）
sinfo_timetolive 消息生存期，过期未发则丢弃

个人学习总结

sctp_sendmsg 是 SCTP 发送的核心函数，支持指定 stream、TTL、context、PPID 等。比 sendto 多了 stream 和消息级控制。

一句话：sendto 只管发数据，sctp_sendmsg 还能选 stream、设 TTL、带 context 通知。

HFT 关联：TTL 参数可限制消息在网络中存活时间，超时内核丢弃并通知，适合行情更新丢弃旧数据。

9.10

sctp_recvmsg 函数

9.9 · 9.14 通知

核心主旨

SCTP 核心接收 API；填充 sctp_sndrcvinfo。

可解析信息

字段 含义
sinfo_assoc_id 来自哪个关联（一到多必备）
sinfo_stream 流号
消息完整性 是否完整 SCTP 用户消息（分片已合并）
SSN 流序号

与通知

recvmsg 标志 MSG_NOTIFICATION → 读到的是事件而非用户数据（见 9.14）。

个人学习总结

sctp_recvmsg 接收 SCTP 消息，返回数据并填充 stream、ssn、flags、rcvinfo 等元信息。msg_flags 区分普通数据 vs 通知。

一句话：recvfrom 只收数据，sctp_recvmsg 还告诉你来自哪个 stream、消息标志、关联信息。

易考点：MSG_EOR 标志表示一个完整消息结束，SCTP 是面向消息的所以天然有边界。

9.11

sctp_opt_info 函数

Ch 7.2 getsockopt

核心主旨

一到多套接字上有多个关联 — 通用 getsockopt 无法指定「哪一个关联」。

sctp_opt_info：传入 关联 ID（assoc_id），读取该关联的选项/状态（如 RTO）。

个人学习总结

sctp_opt_info 封装 getsockopt/setsockopt 的 SCTP 专用选项查询/设置。用于一到多模型中按 assoc_id 操作特定关联。

一句话：普通 getsockopt 操作 socket 级别，sctp_opt_info 按 assoc_id 操作单个关联级别。

易考点：一到多模型中一个 socket 有多个关联，必须用 assoc_id 区分操作目标。

9.12

sctp_peeloff 函数

9.2 一到多 · Ch 26 线程

核心魔法：关联剥离

场景：一到多服处理大量短关联；某一关联变为长耗时传输（大文件）。

newfd = sctp_peeloff(sockfd, assoc_id);
效果 说明
从一到多 fd 剥离 指定 assoc_id
返回新 fd 一到一形式，专责该关联

优势

长连接交独立线程/进程；主 fd 继续处理短关联 — UDP 式并发 + TCP 式长连接兼得。

个人学习总结

sctp_peeloff 将一到多 socket 中的某个关联"剥离"为独立的一到一 socket。用于将特定关联迁移到单独线程/进程处理。

一句话：peeloff=从一到多 socket 上"摘下"一个关联变成独立 fd，类似 accept 但不新建连接。

易考点：peeloff 后原 socket 中该关联不再可见，新 fd 可用普通 send/recv。

9.13

shutdown 函数

Ch 6.6 shutdown · Ch 2.8 SCTP 终止

与 TCP 的差异

TCP SCTP
shutdown 可半关闭（SHUT_WR：不发仍可收） 不支持半关闭
shutdown → 启动关联终止序列

调用表现

发起后双方不应再发新业务数据；用于排空缓冲区、可靠传完排队数据后关闭关联。

个人学习总结

SCTP 的 shutdown 是优雅关闭（graceful shutdown），三步握手（SHUTDOWN/SHUTDOWN-ACK/SHUTDOWN-COMPLETE），不同于 TCP 的四步 FIN。close 则是立即关闭。

一句话：TCP close=FIN 四步挥手，SCTP shutdown=三步挥手且不允许半关闭（无 SHUT_WR 状态）。

易考点：SCTP 不支持 TCP 那样的半关闭（half-close），shutdown 后双向都不传数据。

9.14

通知 (Notifications)

9.10 sctp_recvmsg · Ch 7 SCTP 选项

核心主旨

SCTP 事件通知：订阅后作为带内消息与数据混在接收路径中（非信号）。

机制

步 说明
订阅 套接字选项 SCTP_EVENTS 等
读取 sctp_recvmsg 且 MSG_NOTIFICATION → 解析通知结构体，非用户载荷

典型类型

通知 含义
SCTP_ASSOC_CHANGE 关联建立/关闭/失败
SCTP_PEER_ADDR_CHANGE 对端多宿地址可达性变化（路径切换）
SCTP_SEND_FAILED 指定消息最终未送达
SCTP_SHUTDOWN_EVENT 对端关闭

重点结论

主接收循环须区分 数据 vs 通知 — 对拓扑动荡（网卡、多宿切换）做业务响应。

个人学习总结

SCTP 通知（notification）机制：当关联事件发生（建连/断连/地址变化/发送失败等），内核通过同一个 socket 投递控制消息。订阅方式：setsockopt(SCTP_EVENTS)。

一句话：通知=SCTP 的"事件回调"，数据消息和事件消息复用同一 fd，用 msg_flags 区分。

易考点：MSG_NOTIFICATION flag 表示收到的是事件通知而非数据，需解析 sctp_notification 结构。

小结

study.md · Ch 10 · Ch 23 高级 SCTP

章节核心提炼

1. 范式升级

从「单字节流」→ 管理 多 IP 路径 + 多独立消息流 的关联（Association）。

2. 核心工具链

sctp_sendmsg / sctp_recvmsg — 流号、PPID、无序、TTL、assoc_id。

3. 架构灵活性

组件 作用
一到多 单 fd 多关联
sctp_peeloff 长连接剥离为独立 fd

4. 状态感知

Notifications + MSG_NOTIFICATION — 关联/地址/发送失败/关闭事件。

5. 地址 API 成对释放

getpaddrs/getladdrs ↔ freepaddrs/freeladdrs

API 速记

多宿 bind：sctp_bindx
多宿 connect：sctp_connectx
发/收核心：sctp_sendmsg / sctp_recvmsg
 per-assoc 选项：sctp_opt_info
长连接：sctp_peeloff
无 TCP 式半关闭：shutdown 终止关联

个人学习总结

SCTP 基础 API 全景：bindx/connectx（多宿连接）、sendmsg/recvmsg（消息级收发）、peeloff（关联剥离）、opt_info（关联级操作）、notification（事件订阅）。接口设计围绕"关联"和"流"两个核心概念。

一句话：SCTP API = TCP API 超集，多了多宿、多流、消息边界、事件通知四大能力。

HFT 关联：SCTP 消息边界天然适合 FIX/FAST 协议帧，多流避免行情和交易互相阻塞，但实际部署 SCTP 不如 TCP 普及。
