## 章节核心提炼

### 1. 控制面与数据面解耦

**`PF_KEY` / `AF_KEY`** 划分边界：

- **机制**：内核高性能加解密（数据面）  
- **策略**：用户态 IKE 协商与鉴权（控制面）  

### 2. 繁杂的内存拼接

须精通 C 指针与 **64 位对齐**；`sadb_ext` 长度错误 → 内核拒收。

### 3. 异步事件基石

**`SADB_ACQUIRE`** 事件循环 — 企业级 VPN / IPsec 网关必备。

### 4. 与 Ch 18 对照

| | Ch 18 路由 | Ch 19 PF_KEY |
|---|------------|--------------|
| 域 | `AF_ROUTE` | `PF_KEY` |
| 首部 | `rt_msghdr` | `sadb_msg` |
| 对齐 | sockaddr 紧凑排列 | **8 字节**扩展 |
| 典型守护进程 | `routed` | `isakmpd` / `racoon` |

## 个人学习总结

PF_KEY 密钥管理总结：通过 sadb_msg 消息与内核 IPsec 交互——DUMP 查询、ADD 创建、UPDATE 更新、DELETE 删除、REGISTER 注册监听。是 IKE 守护进程的底层接口。

**一句话**：PF_KEY=IPsec 的管理 API，IKE 守护进程（racoon/strongSwan）通过它向内核下发 SA/SP。

> HFT 关联：交易所专线如果用 IPsec 加密，理解 PF_KEY 有助于排查 SA 协商失败/过期丢包问题。
