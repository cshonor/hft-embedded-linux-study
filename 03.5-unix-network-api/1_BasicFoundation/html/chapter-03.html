概述

3.2 地址结构

核心主旨与关键论据

套接字编程起步：套接字地址结构是用户进程与内核传递「通信端点」的媒介。本章覆盖：结构体类型、值—结果参数、网络字节序、地址转换 API、readn/writen。

逻辑脉络

  1. 结构体 — 明确 IP + 端口如何存放
  2. 长度传递 — 进程↔内核双向规则不同
  3. 协议演进 — inet_addr → inet_pton；sock_ntop 协议无关

💡 后续拓展留白
- 内核如何按 sa_family 分发到协议栈

个人学习总结

本章是套接字编程的地基：地址结构体 → 字节序 → 地址转换 → 循环读写。

一句话：所有 socket API 的地址参数都是 sockaddr* 强转，端口/IP 必须网络字节序。

学习路线：3.2 结构体 → 3.3 值-结果 → 3.4 字节序 → 3.7 pton/ntop → 3.9 readn/writen，按此顺序过关即可。

3.2

套接字地址结构

3.3 值—结果 · 3.4 字节序

核心主旨与关键论据

套接字函数需要指向套接字地址结构的指针；不同协议族有不同定义。所有通信端点 = IP + 端口，必须按协议族正确装填，且端口/IP 用网络字节序。

1. IPv4：sockaddr_in（<netinet/in.h>）

成员 说明
sin_len 可选，8 位；4.3BSD-Reno 加；POSIX 不强制
sin_family 必须 AF_INET
sin_port 16 位端口，网络字节序（htons）
sin_addr 32 位 IPv4（struct in_addr），网络字节序
sin_zero 填充 0，与通用结构对齐（常 16 字节）

2. 通用：sockaddr

  • ANSI C 前无 void *，故定义通用结构让 bind/connect 接受任意协议族地址
  • 调用时必须强转：
bind(sockfd, (struct sockaddr *)&servaddr, sizeof(servaddr));

3. IPv6：sockaddr_in6

  • sin6_family = AF_INET6
  • sin6_port、sin6_addr（128 位）
  • sin6_flowinfo、sin6_scope_id
  • 可能有 64 位对齐 要求

4. sockaddr_storage（新通用）

  • 空间容纳任意套接字地址结构
  • 满足最苛刻内存对齐
  • 协议无关代码常用作「足够大的缓冲区」

易错细节与重点结论

陷阱 后果
忘记 htons/htonl 连错端口/IP
用 sockaddr_in 大小传给 IPv6 API 溢出/错误
未 bzero 结构体 随机垃圾字段

💡 后续拓展留白
- 四种结构体内存布局图

个人学习总结

套接字地址结构按协议族分：IPv4 用 sockaddr_in（16B），IPv6 用 sockaddr_in6（28B），通用用 sockaddr（强转）或 sockaddr_storage（足够大+对齐安全）。

一句话：bind/connect 只认 sockaddr*，所以 sockaddr_in* 必须强转；端口和 IP 必须网络字节序（htons/htonl）。

HFT 关联：协议无关代码用 sockaddr_storage 做缓冲区，getaddrinfo 遍历结果直接填入，无需区分 v4/v6。

3.3

值—结果参数

3.2 地址结构 · socklen_t：Ch 1.11

核心主旨与关键论据

套接字地址结构在用户进程与内核间传递时，长度参数随方向变化 — 值—结果参数（Value-Result Argument）。

进程 → 内核（纯 Value）

函数 传递
bind, connect, sendto 结构体指针 + 整数长度（如 sizeof(servaddr)）

内核已知拷贝字节数 → 防越界读用户空间。

内核 → 进程（Value-Result）

函数 传递
accept, recvfrom, getsockname, getpeername 结构体指针 + socklen_t * 长度指针
时机 长度含义
调用时（Value） 缓冲区最大容量
返回时（Result） 内核实际写入字节数

POSIX 规定长度类型为 socklen_t（64 位兼容，Ch 1.11）。

逻辑脉络

bind/connect：我告诉内核「结构体有多大」
accept/recvfrom：我告诉内核「你最多写多少」；返回后告诉我「你写了多少」

💡 后续拓展留白
- 与缓冲区溢出防护的关系

个人学习总结

进程→内核传值（bind/connect），内核→进程传值-结果（accept/recvfrom）。

一句话：socklen_t* 是"我告诉你缓冲多大，你告诉我实际写了多少"。

易错：accept 传 sizeof(cliaddr) 而非 &len，编译不报错但长度语义错误。

3.4

字节排序函数

核心主旨

主机小端/大端不同；TCP/IP 首部整数强制大端（网络字节序）。必须用 htons/htonl/ntohs/ntohl 显式转换。

函数 用途
htons 16 位端口
htonl 32 位 IPv4
ntohs / ntohl 主机可读

64 位系统中 l 仍指 32 位。

易错细节

忘记转换 → 小端机上连错端口（如 13 变成 3328 等「字节颠倒」现象）。

个人学习总结

TCP/IP 强制大端（网络字节序），主机可能小端。htons/htonl 转网络序，ntohs/ntohl 转主机序。

一句话：h=host, n=network, s=short(16位端口), l=long(32位IP)；64 位系统 l 仍是 32 位。

HFT 关联：DPDK rte_cpu_to_be_16/32 对应 htons/htonl，底层用 x86 bswap 指令。

3.5

字节操纵函数

核心主旨

地址结构含 0 字节，不能用 strcpy。初始化用 bzero（本书偏好）而非易写反参数的 memset。

函数族 说明
Berkeley bzero(dest, nbytes) — 2 参数
ANSI memset(dest, c, len) — 值与长度易写反

重点结论

memset(&addr, sizeof(addr), 0) 类错误编译器不报错，运行时行为诡异。

个人学习总结

地址结构含 0 字节，不能用 strcpy。用 bzero 或 memset 初始化。

一句话：memset(&addr, sizeof(addr), 0) 参数写反编译器不报错——值和长度搞反是经典 bug。

现代 C 推荐 memset，C23 有 memset_explicit（清敏感数据防编译器优化删除）。

3.6

inet_aton、inet_addr 和 inet_ntoa

3.7 inet_pton

核心主旨

IPv4 点分十进制 ↔ 32 位网络序二进制。

函数 说明
inet_aton 成功 1，失败 0 — 推荐
inet_addr 废弃；错返 INADDR_NONE(255.255.255.255) 与广播冲突
inet_ntoa 返回静态缓冲区 — 不可重入，禁多线程/嵌套

个人学习总结

旧 IPv4 地址转换 API，全部已被 inet_pton/inet_ntop 取代。

禁用理由：inet_addr 错返 INADDR_NONE 与广播地址冲突；inet_ntoa 静态缓冲不可重入。

一句话：看到遗留代码里的 inet_addr/ntoa，直接替换成 inet_pton/ntop。

3.7

inet_pton 和 inet_ntop

3.8 sock_ntop

核心主旨

p = presentation，n = numeric。支持 AF_INET / AF_INET6。

int inet_pton(int family, const char *strptr, void *addrptr);
const char *inet_ntop(int family, const void *addrptr, char *strptr, size_t len);
inet_pton 返回 含义
1 成功
0 非法格式
-1 family 不支持，errno 如 EAFNOSUPPORT

inet_ntop：调用者提供缓冲 → 线程安全。INET_ADDRSTRLEN(16)、INET6_ADDRSTRLEN(46)。

个人学习总结

presentation ↔ numeric，支持 IPv4/IPv6，线程安全。

一句话：inet_pton(AF_INET, "1.2.3.4", &addr.sin_addr) 转二进制；inet_ntop(..., str, sizeof(str)) 转字符串。

调用者提供缓冲区 → 线程安全。INET_ADDRSTRLEN=16, INET6_ADDRSTRLEN=46。

3.8

sock_ntop 和相关函数

核心主旨

inet_ntop 仍要传 family。Stevens sock_ntop(sockaddr*, len) 内查 sa_family 自动区分 v4/v6，输出 "ip:port"，减少 switch(family)。

易错细节

早期实现若用静态缓冲 → 并发需 TLS 或调用者缓冲。

个人学习总结

Stevens 封装的协议无关地址打印函数，内查 sa_family 自动区分 v4/v6。

一句话：inet_ntop 要传 family，sock_ntop 传 sockaddr* 即可——减少 switch(family) 样板。

实际工程中调试打印对端地址常用此模式。

3.9

readn、writen 和 readline 函数

TCP 无边界：Ch 2.4 · Ch 1.2 循环 read

核心主旨与关键论据

TCP 字节流无记录边界。单次 read/write 可能返回少于请求的字节（短计数） — 正常现象，非错误。固定长度协议必须用 readn/writen。

readn / writen 逻辑

/* 伪逻辑 */
while (nleft > 0) {
    if ( (nread = read(fd, ptr, nleft)) < 0) {
        if (errno == EINTR)
            continue;      /* 信号中断，重试 */
        else
            return -1;
    } else if (nread == 0)
        return count - nleft;  /* EOF，可能短读 */
    nleft -= nread;
    ptr += nread;
}
return count;
要点 说明
while 直到读/写满 n 或出错/EOF
EINTR continue，非真错
writen 对称，保证 n 字节全部写入

readline 演进

实现 问题
每次 read 1 字节 1KB 行 ≈ 1000 次系统调用，极慢
内部缓冲 my_read 一次读大块，再逐字节找 \n
陷阱 静态缓冲 → 非线程安全；与 select 混用可能状态错乱

易错细节

易错 纠正
一次 read 读满协议 TCP 必须循环或 readn
stdio fgets 用于双工 socket 易死锁（Ch 5）
readline 多线程 需每线程独立缓冲或加锁

💡 后续拓展留白
- readn 源码全文粘贴

个人学习总结

TCP 字节流无边界，read/write 可能返回短计数——正常现象。固定长度协议必须 readn/writen 循环读写。

一句话：readn = while 循环直到读满 n 或 EOF；EINTR 要 continue 不是错。

HFT 关联：DPDK 绕过内核 syscall，不存在短读问题——但理解 readn 逻辑有助于协议设计。

3.10

小结

核心提炼

主题 要点
结构体 sockaddr_in / in6 / storage + 强转 sockaddr
长度 bind 传值；accept 传 socklen_t* 值—结果
字节序 htons 族
地址 inet_pton 族；勿 inet_ntoa 重入
TCP readn/writen + EINTR

个人学习总结

本章五件套：结构体（sockaddr_in/in6/storage）+ 值-结果参数 + 字节序（htons）+ 地址转换（inet_pton/ntop）+ 循环读写（readn/writen）。

考试速记：bind 传值，accept 传 socklen_t*；勿 inet_ntoa（静态缓冲）；TCP 必须 readn。

这五个知识点是后续所有章节的地基，Ch4 开始组装 TCP C/S。
