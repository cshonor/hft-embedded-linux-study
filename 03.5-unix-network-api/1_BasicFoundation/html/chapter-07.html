7.1

概述

上一章：Ch 6 · 7.2 getsockopt/setsockopt

核心主旨与关键机制

套接字 API 提供机制，动态获取和修改套接字底层默认行为 — 统称 套接字选项（Socket Options）。

三大控制入口

入口 作用域
getsockopt / setsockopt 套接字层级（本章主体）
fcntl 套接字作为 fd 的通用文件控制（非阻塞、信号驱动）
ioctl 更底层设备/网口控制（Ch 17）

逻辑脉络

Ch6 多路复用 + 半关闭
→ Ch7 调内核行为：TIME_WAIT 重启(REUSEADDR)、保活、缓冲、Nagle、linger、超时
→ Ch16 fcntl 非阻塞
→ Ch17 ioctl 网口

💡 后续拓展留白
- 各 OS 选项与内核协议栈执行层映射差异

个人学习总结

套接字选项三大入口：getsockopt/setsockopt（套接字层）、fcntl（fd 通用控制）、ioctl（底层设备控制，Ch17）。

一句话：Ch7 调内核行为——TIME_WAIT 重启用 REUSEADDR、保活用 KEEPALIVE、禁 Nagle 用 NODELAY。

高频选项：SO_REUSEADDR、SO_KEEPALIVE、SO_RCVBUF/SNDBUF、TCP_NODELAY、SO_LINGER。

7.2

getsockopt 和 setsockopt 函数

7.4 状态继承 · 值—结果：Ch 3.3

核心主旨

专用于操作套接字选项，作用域从通用套接字层到具体协议层。

int getsockopt(int sockfd, int level, int optname,
               void *optval, socklen_t *optlen);
int setsockopt(int sockfd, int level, int optname,
               const void *optval, socklen_t optlen);

参数逻辑

参数 说明
level 解释选项的协议层：SOL_SOCKET、IPPROTO_IP、IPPROTO_IPV6、IPPROTO_TCP、IPPROTO_SCTP 等
optname 具体宏，如 SO_KEEPALIVE、TCP_NODELAY
optval 选项值（int 或结构体）
optlen 长度；getsockopt 时为值—结果参数（防内核写越界）

选项两大基本类型

类型 setsockopt 语义
二元标志 optval 指向 int：0=关，非0=开
数据值 传递整数（缓冲大小）或结构体（如 struct linger）

易错细节

陷阱 说明
optlen 传错 getsockopt 必须给足够大的缓冲区
level/optname 不匹配 如 TCP 选项用 IPPROTO_TCP，非 SOL_SOCKET

💡 后续拓展留白
- 常用选项 level/optname 速查表

个人学习总结

getsockopt(sockfd, level, optname, optval, &optlen) / setsockopt(...) — level 选协议层，optname 选具体选项。

两层：SOL_SOCKET（通用）、IPPROTO_TCP（TCP 特有）、IPPROTO_IP（IP 层）。

一句话：optval 是值-结果参数——getsockopt 传缓冲区进去，返回实际长度。

7.3

检查选项是否受支持并获取默认值

核心主旨

不同 OS/内核版本对选项支持不一致；可用工具程序遍历选项 + getsockopt 输出系统默认值。

实用要点与代码逻辑

设计 说明
不遇错即 exit 某选项 getsockopt 失败 → 判定本系统不支持，非致命
典型 errno EOPNOTSUPP、ENOPROTOOPT
#ifdef SCTP、多播等选项仅在协议栈编译进内核时存在

逻辑脉络

开发前/移植时运行 checkopts 类程序
→ 确认 SO_REUSEPORT、SCTP_* 等是否可用
→ 再写生产 setsockopt

💡 后续拓展留白
- 本机跑一次选项探测脚本记录

个人学习总结

不同 OS/协议栈支持的选项不同——代码应探测支持性再使用，不能假设。

一句话：getsockopt 返回 -1 + ENOPROTOOPT 表示不支持。

工程实践：关键选项（如 TCP_NODELAY）在所有平台都支持，可跳过探测。

7.4

套接字状态

7.5 通用选项 · accept 继承：Ch 4.6

核心主旨

部分选项行为依赖套接字当前状态；TCP 监听套接字 → 已连接套接字 的选项继承极易踩坑。

状态继承原则（极其关键）

accept 返回的 connfd 从 listenfd 继承诸多选项，例如：

  • SO_KEEPALIVE
  • SO_RCVBUF / SO_SNDBUF
  • TCP_MAXSEG
  • 等

设置时机陷阱

目标 正确时机
影响所有将来 accept 的连接 在 listen 之前 对 listenfd setsockopt
只改某一个 connfd 对该 connfd 单独设置（accept 之后）

TCP 缓冲区与窗口规模

  • SO_RCVBUF 与 Window Scale 协商有关
  • 协商发生在 SYN（三次握手）
  • 故：服务器在 listen 前设；客户在 connect 前设 SO_RCVBUF

易错细节与重点结论

错误 后果
accept 后才给 listenfd 设 SO_KEEPALIVE 已建立连接不继承新值
客户 connect 后才设 SO_RCVBUF 窗口协商可能已错过最佳时机

考试一句：要影响 accept 出来的连接 → 先设监听套接字，再 listen。

💡 后续拓展留白
- 继承选项完整列表（附录）

个人学习总结

选项设置时机：有些必须在 listen/connect 前设（如 SO_RCVBUF），有些随时可设。

关键规则：accept 返回的 connfd 继承 listenfd 的选项——所以 SO_REUSEADDR 等要在 listen 前设在 listenfd 上。

SO_RCVBUF 在 listen 前设才影响 accept 后的连接缓冲区大小。

7.5

通用套接字选项

级别 SOL_SOCKET · TIME_WAIT：Ch 2.7 · select 水位：6.3

核心主旨

最常用、考试最高频的套接字选项层；影响所有协议类型（但部分仅对 UDP/TCP 有意义）。

1. SO_BROADCAST

项 说明
功能 UDP 数据报套接字允许发广播
限制 TCP 字节流套接字绝不能开

2. SO_ERROR

项 说明
功能 获取并清除套接字待处理异步错误
机制 仅 getsockopt；select 显示异常就绪后调用，读 optval 得 errno，内核随后清零

3. SO_KEEPALIVE

项 说明
功能 TCP 周期性保活探测（默认约 2 小时无数据则发 probe）
结果 1 收到 ACK → 正常
结果 2 收到 RST → 对端曾崩溃重启 → ECONNRESET
结果 3 无响应 → 多次重试后 ETIMEDOUT / EHOSTUNREACH

关联 Ch 5.14「不发数据不知主机死」。

4. SO_LINGER（重点 / 易错）

struct linger { int l_onoff; int l_linger; };
配置 行为
l_onoff = 0（默认） close 立即返回；内核后台发完缓冲
l_onoff = 1, l_linger = 0 中止关闭：丢发送缓冲，发 RST 非 FIN → 避免 TIME_WAIT
l_onoff = 1, l_linger > 0 close 阻塞直到数据+FIN 被确认，或超时 → 超时返回 EWOULDBLOCK

考点：RST 关闭 vs 正常 FIN；在途数据丢失风险。

5. SO_RCVBUF / SO_SNDBUF

  • 调节内核接收/发送缓冲区大小
  • 大文件、高 BDP「长胖管道」需更大缓冲
  • TCP：接收缓冲影响通告滑动窗口（与 Ch 2.11、7.4 时机相关）

6. SO_RCVLOWAT / SO_SNDLOWAT

  • 低水位：多少数据/空间才触发 select/poll 就绪
  • TCP 默认：接收 1 字节，发送常 2048 字节空闲

7. SO_RCVTIMEO / SO_SNDTIMEO

  • 对 read/write 设 timeval 超时
  • 超时 → -1，errno = EWOULDBLOCK

8. SO_REUSEADDR / SO_REUSEPORT（高频）

SO_REUSEADDR

# 用途
1 TIME_WAIT 仍占端口时，重启监听服务器（并发 TCP 服务器必设）
2 同端口多实例，绑定 IP 不同（一具体一通配）
3 单进程多 IP 多次 bind 同端口
4 完全重复捆绑（通常多播）

SO_REUSEPORT

  • 更彻底的完全重复捆绑；所有绑定进程都须设此选项
  • UDP 多播并发收、Linux 3.9+ 多进程负载均衡（Nginx 等）

易错细节速查

选项 一句
REUSEADDR 重启 bind 不因 TIME_WAIT 失败
LINGER=0 RST，无 TIME_WAIT，丢数据
KEEPALIVE 长空闲探测，非应用心跳
BROADCAST 仅 UDP

💡 后续拓展留白
- SO_LINGER 与 CLOSE_WAIT 堆积
- SO_REUSEPORT 内核分发算法

个人学习总结

SOL_SOCKET 高频选项全集：

选项 用途
SO_REUSEADDR TIME_WAIT 端口重用
SO_KEEPALIVE 长空闲 TCP 探测
SO_RCVBUF/SNDBUF 收发缓冲区大小
SO_LINGER close 行为（0=RST, >0=等）
SO_BROADCAST UDP 广播权限

HFT 关联：SO_RCVBUF 设大减少丢包；TCP_NODELAY 是必设项。

IPv4 套接字选项

核心选项（IPv4 网络层）

选项 说明

  • 普通 TCP/UDP 不要乱开 IP_HDRINCL
  • IP_TTL 与 traceroute 探测相关（Ch 2 / Ch 28）

- 源路由选项安全历史

个人学习总结

IPPROTO_IP 层选项：IP_TTL、IP_TOS（服务类型）、IP_OPTIONS（源路由等）。

一句话：IP_TOS 可设 DSCP/ECN 标记——网络 QoS 的应用层入口。

HFT 关联：IP_TOS 设低延迟标记，路由器可能优先转发（依赖网络配置）。

7.7

ICMPv6 套接字选项

级别 IPPROTO_ICMPV6

核心选项

ICMP6_FILTER

  • 配置 ICMPv6 过滤器
  • 声明原始套接字上只接收哪些 ICMPv6 类型
  • 减少内核 → 用户空间无关报文复制

个人学习总结

ICMPv6_FILTER — 过滤接收的 ICMPv6 消息类型。IPv6 中 ICMPv6 承担更多功能（NDP、MLD）。

一句话：raw ICMPv6 socket 用此选项减少不关心的消息干扰。

与 IPv4 的 raw ICMP 对比：IPv6 把更多控制功能交给 ICMPv6。

IPv6 套接字选项

级别 IPPROTO_IPV6 · 双栈：Ch 12

核心选项

选项 说明
IPV6_DONTFRAG UDP/原始套接字是否允许 IPv6 自动分片
IPV6_PATHMTU 获取到目的的 路径 MTU（Ch 2.11）
IPV6_V6ONLY AF_INET6 套接字仅 IPv6 vs 允许 IPv4 映射（双栈）

易错细节

  • IPV6_V6ONLY=1：避免意外接受 IPv4 映射连接（安全/语义清晰）
  • 路径 MTU 与 UDP 大数据、DF 位策略相关

💡 后续拓展留白
- 与 Ch 12 IPv4/IPv6 互操作对照

个人学习总结

IPPROTO_IPV6 选项：IPV6_V6ONLY（禁双栈映射）、IPV6_PATHMTU（获取路径 MTU）。

一句话：IPV6_V6ONLY=1 时套接字只收 IPv6，不接受 IPv4-mapped 地址。

双栈服务器设 V6ONLY=0 可用一个 IPv6 socket 同时服务 v4/v6 客户。

7.9

TCP 套接字选项

级别 IPPROTO_TCP · MSS：Ch 2.6 / 2.11

1. TCP_MAXSEG

项 说明
功能 获取/设置 MSS
时机 SYN 时通告；连接建立后不能增大

2. TCP_NODELAY（极度重要）

Nagle 算法

  • 若连接上有未确认数据，缓冲小分节，等 ACK 再合并发送
  • 目的：减少 WAN 小分组泛滥

与延迟 ACK 的死锁

客户发小包1 → 等 ACK（Nagle）
服务器收包1 → 延迟 ACK（想捎带回射）
→ 双方互等 → 可达 ~200ms 无谓延迟

适用场景

SSH、X11、实时游戏等需即时发出小数据 → 必须 TCP_NODELAY

设置 效果
默认（Nagle 开） 交互延迟可能大
TCP_NODELAY=1 禁用 Nagle，小包立刻发

易错细节

易混 纠正
NODELAY = 更快总是好？ 高吞吐 bulk 传输可能更差（更多小报文）
Linux TCP_CORK 与 NODELAY 相反方向聚合（留白）

💡 后续拓展留白
- TCP_CORK vs TCP_NODELAY（HTTP 大响应）

个人学习总结

IPPROTO_TCP 选项：TCP_NODELAY（禁 Nagle）、TCP_MAXSEG（MSS）、TCP_KEEPALIVE（探测参数）。

一句话：TCP_NODELAY 禁用 Nagle 算法——小包立即发送，不等待合并。

HFT 关联：TCP_NODELAY 是 HFT 必设——Nagle 延迟与延迟 ACK 互锁可导致 ~200ms 延迟。

7.11

fcntl 函数

非阻塞详述：Ch 16 · 信号驱动：Ch 25

核心主旨

fcntl（File Control）也作用于套接字 fd，控制最高频 I/O 特性。

int fcntl(int fd, int cmd, ... /* int arg */);

核心 cmd

操作 命令 效果
非阻塞 I/O F_SETFL + O_NONBLOCK read/write/connect/accept 不能立刻完成 → EWOULDBLOCK，不睡眠
信号驱动 I/O F_SETFL + O_ASYNC 状态变化 → 内核向属主发 SIGIO
套接字属主 F_SETOWN 指定接收 SIGIO/SIGURG 的进程/进程组

易错细节：改状态标志的正确姿势（必考）

错误（覆盖其它标志）

fcntl(sockfd, F_SETFL, O_NONBLOCK);  /* 危险！清空 O_APPEND、O_ASYNC 等 */

正确（GET → OR → SET）

int flags = fcntl(sockfd, F_GETFL, 0);
flags |= O_NONBLOCK;
fcntl(sockfd, F_SETFL, flags);

逻辑脉络

Ch6 select 服务器阻塞 read → DoS
→ Ch7 fcntl 非阻塞铺垫
→ Ch16 系统使用非阻塞 + select/epoll

💡 后续拓展留白
- fcntl O_NONBLOCK vs ioctl FIONBIO

个人学习总结

fcntl(sockfd, F_SETFL, flags | O_NONBLOCK) — 设置套接字非阻塞。

三步：F_GETFL 取当前 → 位或 O_NONBLOCK → F_SETFL 写回。不能直接 F_SETFL = O_NONBLOCK（会清其他标志）。

HFT 关联：非阻塞 I/O + epoll = Linux 高并发标准模型。DPDK 绕过这层直接轮询。

7.12

小结

study.md · 下一章：Ch 8 UDP

章节核心提炼

1. 选项 = 业务微调弹性

默认适合通用场景；高性能、异常控制、实时交互需 setsockopt/fcntl。

2. 服务器必备

bind 之前对 listenfd：

setsockopt(listenfd, SOL_SOCKET, SO_REUSEADDR, &on, sizeof(on));

避免 TIME_WAIT 导致重启 Address already in use（Ch 2.7、5.x）。

3. 性能调优

选项 用途
SO_SNDBUF / SO_RCVBUF 缓冲、窗口（listen/connect 前设）
TCP_NODELAY 禁用 Nagle，低延迟交互

4. 关闭语义

SO_LINGER 改变 close：正常后台发、阻塞等 FIN、或 RST 中止（无 TIME_WAIT）。

5. 通向高性能

fcntl GET→OR→SET O_NONBLOCK → Ch 16。

易错清单

点 一句
继承 影响 accept 子连接 → listen 前设 listenfd
REUSEADDR 重启监听必设
LINGER=0 RST，丢在途数据
fcntl SETFL 必须 F_GETFL 再 OR
Nagle 与延迟 ACK 互等 200ms

💡 后续拓展留白
- 阶段一 Ch1～7 选项默写表

个人学习总结

套接字选项是调内核协议栈行为的旋钮。高频五件套：REUSEADDR（重启用）、KEEPALIVE（保活）、RCVBUF（缓冲）、LINGER（close行为）、NODELAY（禁Nagle）。

继承规则：connfd 继承 listenfd 选项 → listen 前设在 listenfd 上。

fcntl 设非阻塞是通向 Ch16 非阻塞 I/O 的入口。
