# 6.5 批量输入

> [6.6 shutdown](../6.6_Shutdown_Function.md) · [6.4 select 版 str_cli](../6.4_Str_Cli_Revised.md)

---

## 核心主旨与案例数据

6.4 在**人敲键盘**时完美；若输入重定向为文件（`client < input.txt`）**批量输入**，会暴露严重逻辑缺陷。

---

## 问题重现

| 现象 | 原因 |
|------|------|
| `fgets` 极快读到 **stdin EOF** | 文件读完 |
| `str_cli` **立刻 return → exit** | 整个进程退出 |
| **在途数据丢失** | 已 `writen` 的请求 + 服务器回射仍在网络/服务器缓冲；客户端 **close** 掐断连接，回射被丢弃 |

---

## 核心诉求

stdin 遇到 EOF 时**不能**直接关掉整个 TCP 连接，需告诉对端：

> **「我发完了，但我还能继续收你的数据。」**

→ 需要 **半关闭写方向**（**`shutdown(SHUT_WR)`**），见 6.6、6.7。

---

## 逻辑脉络

```text
交互式：EOF = 用户不想聊了 → exit 合理
批量式：EOF = 输入文件结束 ≠ 不再接收回射
→ 须 shutdown 写半部 + 继续 select 读 sockfd
```

---

## 易错细节与重点结论

| 易混 | 纠正 |
|------|------|
| stdin EOF 就 exit | 批量场景应 **shutdown 写**，继续读 |
| 以为 writen 完就收到回射 | TCP 有 RTT 与管道延迟 |
