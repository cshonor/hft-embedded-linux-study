# 1.2 一个简单的时间获取客户程序

## 一、五步法（第 2 步：IP 和端口分开看）

| # | 步骤 | 做什么 |
|---|------|--------|
| 1 | `socket` | 创建 TCP/IPv4 套接字 → 得到 `sockfd` |
| 2 | **填服务器地址** | 往 `sockaddr_in servaddr` 里写 **IP + 端口**（见下表） |
| 3 | `connect` | 把地址交给内核 → **三次握手** |
| 4 | `while (read…)` | 循环读 TCP **字节流**（可能分多次） |
| 5 | `exit` / `close` | 关连接（发 FIN） |

### 第 2 步必记：哪个是 IP？哪个是端口？

连服务器要像打电话：**拨哪个号（IP）** + **分机几（端口）**。1.2 里写进 **`struct sockaddr_in servaddr`**：

| 你要填的 | 结构体字段 | 1.2 代码 | 数据从哪来 |
|----------|------------|----------|------------|
| **IP 地址** | **`sin_addr`** | `inet_pton(AF_INET, argv[1], &servaddr.sin_addr)` | 命令行 **`argv[1]`**，如 `"127.0.0.1"` |
| **端口号** | **`sin_port`** | `servaddr.sin_port = htons(13);` | 固定 **13**（Daytime 服务） |
| **IPv4** | **`sin_family`** | `servaddr.sin_family = AF_INET;` | 和 `socket(AF_INET,…)` 一致 |
| **先清零** | 整个 `servaddr` | `bzero(&servaddr, sizeof(servaddr));` | 避免垃圾字节 |

```text
  argv[1] "192.168.0.1" ──inet_pton──► sin_addr   （IP，4 字节）
  整数 13 ──htons───────────────► sin_port  （端口，网络序）
                    servaddr
                         │
                    connect()
                         ▼
                   内核：连到 该IP:13
```

**「网络字节序」**只影响**怎么把数字写进 `sin_port` / `sin_addr`**（端口用 `htons`；IP 用 `inet_pton`）。详解见下方折叠 [C 新手与字节序](#c-faq)。

```text
socket → 填 servaddr(IP+端口) → connect → while read → exit
```

## 二、API 速查

<a id="ch1-2-socket"></a>

### `socket()` 三个参数（1.2 只用 IPv4，没写 IPv6）

```c
sockfd = socket(AF_INET, SOCK_STREAM, 0);
```

| 参数 | 1.2 取值 | 什么意思 |
|------|----------|----------|
| **① 地址族** | **`AF_INET`** | **用 IPv4 地址**（点分如 `192.168.0.1`）。告诉内核：后面 `sockaddr_in` / `inet_pton` 都按 **4 字节 IPv4** 来，不是 IPv6。 |
| **② 套接字类型** | **`SOCK_STREAM`** | **字节流、可靠、有序** → 就是 **TCP**。 |
| **③ 协议** | **`0`** | **默认**：前面已选 TCP 流式时，由系统选 **TCP 协议**（一般不必手写 `IPPROTO_TCP`）。 |

**什么叫「IPv4 地址族」？**

- **族（family）** = 用哪一套地址格式。
- **`AF_INET`** = **Address Family, Internet** = **IPv4 那一套**（32 位 IP）。
- 你没写 IPv6，所以这里**不是** `AF_INET6`；1.3 才会出现 IPv6 / 协议无关。

**返回值 `sockfd`：**

| 返回值 | 含义 |
|--------|------|
| **≥ 0** | 成功，得到一个整数 **套接字描述符**（像"网络连接的句柄"），后面 `connect` / `read` 都用它 |
| **< 0** | 失败，查 **`errno`**（如资源不够）；**不能**拿这个 fd 去 `connect` |

| API | 一句话 | 展开 |
|-----|--------|------|
| `connect(…)` | 交内核三次握手；失败须 close 再 socket | 见下方折叠 [API 精读](#api-detail) |
| `read` / `while` | TCP 无边界；`n==0` 为 FIN | 见下方折叠 [API 精读](#api-detail) |

```c
struct sockaddr_in {
    sin_family;   /* AF_INET */
    sin_port;     /* 端口 ← htons(13) */
    sin_addr;     /* IP   ← inet_pton(..., argv[1], ...) */
    sin_zero[8];  /* 填 0 */
};
```

### `connect()` — 把「去哪台:哪个端口」交给内核

```c
connect(sockfd, (SA *) &servaddr, sizeof(servaddr));
```

| 项 | 说明 |
|----|------|
| **`sockfd`** | `socket()` 成功返回的描述符 |
| **`(SA *) &servaddr`** | `SA` = `#define SA struct sockaddr`；把 **`sockaddr_in*`** 转成**通用地址指针**（BSD 惯例，以后 IPv6 / 别的族也用同一套 API 形状） |
| **`sizeof(servaddr)`** | 必须传**真实结构体大小**，让内核知道是 IPv4 的 `sockaddr_in` |
| **内核行为** | 读 `servaddr` 里的 **目的 IP + 目的端口** → 路由 → 发 **TCP SYN**（三次握手） |
| **返回值 < 0** | 失败；**禁止**对**同一个** `sockfd` 再 `connect` |
| **失败后正确做法** | `close(sockfd)` → 重新 `socket()` → 再填地址 → 再 `connect` |

---

<a id="ch1-2-read"></a>

### `read()` 循环 — TCP 没有「一次读一包」

```c
while ((n = read(sockfd, recvline, MAXLINE)) > 0) {
    recvline[n] = 0;
    fputs(recvline, stdout);
}
if (n < 0) err_sys("read error");
```

| `read` 返回值 | 含义 |
|---------------|------|
| **> 0** | 本次读到的字节数 `n`（可能小于 MAXLINE） |
| **== 0** | 对端 **关闭写方向**（常见：收到 **FIN**），数据流结束 → **正常退出循环** |
| **< 0** | 出错（查 `errno`；信号中断 `EINTR` 见 [Ch 3.9](../Chapter03_SocketProgramIntro/3.9_Readn_Writen_Readline.md)） |

**为何必须 `while`？** TCP 是**字节流**，内核接收缓冲区**没有应用层报文边界**。Daytime 一次发 26 字节，你的进程可能被分成 **10 + 16** 两次 `read` 才拿全。

**`recvline[n] = 0`**：`read` 只写二进制，**不带 `'\0'`**；加 NUL 后 `fputs` 才能当 C 字符串打印（协议本身不需要 `\0`）。

### 应用层 ↔ 内核（一张表）

| 你调用的 API | 内核 / 协议在干什么 |
|--------------|---------------------|
| `socket` | 创建套接字，分配 **fd** |
| 填 `servaddr` | 仅在**进程内存**；须已是正确 **IP + 端口（网络序）** |
| `connect` | **三次握手**，建立连接控制块 |
| `read` | 从该连接的 **TCP 接收缓冲区** 拷贝到用户缓冲区 |
| `exit` / `close` | 关闭 fd，通常发 **FIN**，四次挥手 |

**13 端口**：IANA 标准 **Daytime** 服务，返回人类可读时间字符串（明文 TCP）。

### C 零基础 FAQ

**`argc != 2` 是什么意思？**

| 命令 | `argc` |
|------|--------|
| `./daytimetcpcli` | 1 ❌ 没 IP |
| `./daytimetcpcli 127.0.0.1` | 2 ✅ |
| `./daytimetcpcli 1.1.1.1 x` | 3 ❌ 参数太多 |

- **`argc`**：参数个数；**`argv[0]`** 程序名，**`argv[1]`** 本程序的 **IP 字符串**。
- 代码 **`if (argc != 2)`**：不是「不能等于 2」，而是 **「不等于 2 就报错」**。

**`bzero` 是什么？**

```c
bzero(&servaddr, sizeof(servaddr));
```

把 `servaddr` **整块清零**。未赋值成员若是随机值，`connect` 可能异常。
等价 `memset(&servaddr, 0, sizeof(servaddr))`；BSD/POSIX 提供，UNP 老代码常用。

**`inet_pton` 三个参数**

```c
inet_pton(AF_INET, argv[1], &servaddr.sin_addr);
```

| 参数 | 作用 |
|------|------|
| `AF_INET` | 按 **IPv4** 解析 |
| `argv[1]` | **输入**：`"192.168.0.1"` 这种人看的字符串 |
| `&sin_addr` | **输出**：4 字节**二进制**（已是网络序） |

「转成二进制网络序」= 变成协议栈用的 `C0 A8 00 01`，不是再打印字符串。`<=0` 表示 IP 格式非法。

<a id="ch1-2-byteorder"></a>

### 网络字节序（深化）

**主机序 vs 网络序**

| 术语 | 含义 |
|------|------|
| **主机字节序** | 你 CPU 存多字节数的习惯（x86 多为**小端**） |
| **网络字节序** | TCP/IP 规定线上用**大端**（高位字节在前） |

**端口为什么要 `htons(13)`？**

端口在 `sin_port` 里占 **2 字节**。整数 **13** = `0x000D`：

| 存法 | 两字节 | 协议读到的端口 |
|------|--------|----------------|
| ✅ `htons(13)` 网络序 | `00` `0D` | **13** |
| ❌ 小端机直接 `sin_port=13` | `0D` `00` | **3328** 等错误值 |

**IP 和 `192.168.0.1`**

| 形式 | 和大端的关系 |
|------|----------------|
| 字符串 `"192.168.0.1"` | 给人看的，谈不上字节序 |
| `inet_pton` 写入 `sin_addr` | **4 字节网络序**：`C0 A8 00 01`（与点分从左到右一致） |

**勿**在 `inet_pton` 之后再 `htonl(sin_addr)`。

**字节序易错（仅列主笔记未写的）**

| ❌ | ✅ |
|----|-----|
| 以为 `192.168.0.1` 字符串本身是「大端」 | 字符串 → **pton** → 二进制 |
| 小端 PC 上端口不转 | **凡进 `sin_port` 必 htons** |

> 函数全集：[Ch 3.4](../Chapter03_SocketProgramIntro/3.4_ByteOrderFunction.md)

</details>

<a id="ch1-2-exam-detail"></a>

### 完整源码（书中逻辑）

```c
#include    "unp.h"

int main(int argc, char **argv)
{
    int                 sockfd, n;
    char                recvline[MAXLINE + 1];
    struct sockaddr_in  servaddr;

    if (argc != 2)
        err_quit("usage: a.out <IPaddress>");

    if ((sockfd = socket(AF_INET, SOCK_STREAM, 0)) < 0)
        err_sys("socket error");

    bzero(&servaddr, sizeof(servaddr));
    servaddr.sin_family = AF_INET;
    servaddr.sin_port   = htons(13);
    if (inet_pton(AF_INET, argv[1], &servaddr.sin_addr) <= 0)
        err_quit("inet_pton error for %s", argv[1]);

    if (connect(sockfd, (SA *) &servaddr, sizeof(servaddr)) < 0)
        err_sys("connect error");

    while ((n = read(sockfd, recvline, MAXLINE)) > 0) {
        recvline[n] = 0;
        if (fputs(recvline, stdout) == EOF)
            err_sys("fputs error");
    }
    if (n < 0)
        err_sys("read error");

    exit(0);
}
```

### 逐行 ↔ 五步法

| 行 | 代码 | 五步法 / 要点 |
|----|------|----------------|
| 入参 | `argc != 2` | 必须 **argv[1]=IP** → [C FAQ](#ch1-2-faq) |
| ① | `socket(AF_INET, SOCK_STREAM, 0)` | 创建 IPv4 TCP → [socket 三参数](#ch1-2-socket) |
| ② | `bzero` + `sin_*` + `htons(13)` + `inet_pton` | **sin_addr=IP，sin_port=端口** → [主笔记表](#ch1-2-flow) |
| ③ | `connect(..., (SA*)...)` | 三次握手 → [API 精读·connect](#ch1-2-connect) |
| ④ | `while (read > 0)` + `recvline[n]=0` | 流式循环读 → [API 精读·read](#ch1-2-read) |
| ⑤ | `exit(0)` | 进程结束关 fd；生产建议显式 `close(sockfd)` |

<details>
<summary><b>附录 · 为何固定端口 13（Daytime / RFC 865）</b></summary>

<a id="ch1-daytime-port"></a>

**没错：13 是 Daytime 的官方标准端口，TCP（及 UDP）均为 13。**

| 依据 | 说明 |
|------|------|
| **RFC 865** | 定义 **Daytime** 服务 → **TCP/UDP 端口 13** |
| 行为 | 客户端连上后，服务端返回**人类可读的日期+时间字符串**，发完常关连接 |
| 与 UNP 1.2/1.5 | 正是书上「时间获取」示例 |

```text
客户端：connect  目标 IP : 13
服务端：bind     0.0.0.0 : 13   （INADDR_ANY + htons(13)）
```

两端必须**同一端口**；改一端不改另一端会连不上。

### UNP 入门常用标准端口（对照）

| 端口 | 服务 | 作用 |
|------|------|------|
| **13** | **Daytime** | 返回时间字符串（**本章**） |
| 7 | Echo | 回显收到的数据 |
| 19 | Chargen | 持续发送字符流（测吞吐） |
| 37 | Time | 自 1900 起的秒数（二进制，非本章） |

> [2.12 标准因特网服务](../Chapter02_TCP_UDP_SCTP/2.12_StandardInternetService.md)

<a id="ch1-daytime-privileged"></a>

### 关键细节

**知名端口 / 特权端口（< 1024）**

| 事实 | 影响 |
|------|------|
| **13 < 1024** | Linux 上**普通用户**默认 **不能 `bind(13)`**（需 **root** 或 `CAP_NET_BIND_SERVICE`） |
| 书上示例 | 常假设有权限，或 root 跑服务端 |

**改成非标准端口（如 8888、10013）**

| 项 | 说明 |
|----|------|
| 能否跑通 | **能** — 服务端 `bind` 某端口，客户端 `connect` **同一端口** 即可 |
| 协议含义 | **不再是** IANA 标准 Daytime 端口，只是你自己的 TCP 时间服务 |
| 改法 | C：`htons(13)` → `htons(10013)`；Rust：`"IP:13"` → `"IP:10013"` **两边一起改** |

**现代 Linux 与系统自带 Daytime**

多数发行版**默认不启**系统 `daytime`（13）服务（安全/无用）。
因此 **1.5 自写服务端监听 13** 才能和 **1.2 客户端** 联调；与系统服务冲突时再换端口或停系统服务。

<a id="ch1-daytime-10013"></a>

### 非 root 本地测试：改用 10013（可选）

**仓库默认保持 13**，与 UNP / RFC 一致。无 root 时可**自行改端口**：

| 位置 | 修改 |
|------|------|
| C 客户端 `1.2_daytimetcpcli.c` | `htons(13)` → `htons(10013)`；或 `getaddrinfo` 服务名 `"10013"` |
| C 服务端 `1.5_daytimesrv.c` | `htons(13)` → `htons(10013)` |
| Rust 客户端 | `format!("{host}:13")` → `:10013` |
| Rust 服务端 | `bind("0.0.0.0:13")` → `0.0.0.0:10013` |

**速记**：RFC865 → 13/TCP → 人读时间串；客户端连 IP:13，服务端 bind :13；<1024 要权限；系统常无 daytime，自写 1.5 测。

</details>

<summary><b>附录 · Rust Daytime 客户端对照</b></summary>

<a id="ch1-2-rust"></a>

### 和 C 的对应关系

| C（1.2） | Rust |
|----------|------|
| `argc` / `argv[1]` | `env::args()`，`len() == 2` |
| `socket` + `connect` | `TcpStream::connect("IP:13")` |
| `sin_addr` + `sin_port` | `format!("{host}:13")`，库内解析+网络序 |
| `while (read > 0)` | `loop { read; break if n==0 }` |
| `recvline[n]=0` + `fputs` | `from_utf8_lossy(&buf[..n])` |
| `exit` 关 fd | `stream` **Drop** |

### 核心逻辑

```rust
let addr = format!("{host}:13");
let mut stream = TcpStream::connect(&addr)?;
let mut buf = [0u8; MAXLINE];
loop {
    let n = stream.read(&mut buf)?;
    if n == 0 { break; }
    print!("{}", String::from_utf8_lossy(&buf[..n]));
}
```

- **TCP 仍须循环 read**；`n == 0` 同 C 的 `read == 0`。
- **connect 失败**须重新 `TcpStream::connect`，不能复用失败的流。

```bash
cargo run -- 127.0.0.1
```

<a id="rust-debug-display"></a>

**结论：思路像，机制完全不同**

| 层面 | 说法 |
|------|------|
| **表象** | 都要「实现指定方法」才能用好内置语法（打印等）→ 和 Python **魔法方法**很像 |
| **内核** | Python = **运行时动态查找**（鸭子）；Rust = **编译期静态绑定 Trait** |

| Rust | Python | 分工 |
|------|--------|------|
| **`{}`** | `print(x)` → **`__str__`** | 给人看 ≈ **`Display`** |
| **`{:?}`** | `repr(x)` → **`__repr__`** | 调试用 ≈ **`Debug`** |

Rust **刻意拆开** Display / Debug；Python 也拆 `__str__` / `__repr__`，所以**体感高度相似**，但**检查时机与约束方式不同**。

**核心三大区别：**

1. **检查时机**：Python 运行时找方法；Rust 编译期检查是否 `impl`
2. **约束范围**：Python 碰巧有方法就行（鸭子）；Rust 泛型可 `T: Trait`，入参必须实现
3. **实现归属**：Python 写在类内部；Rust `impl Trait for Type` 可与类型定义解耦

**背**：`{}`→Display（常手写）；`{:?}`→Debug（常 derive）；Rust 编译查 Trait；Python 运行找魔法方法。

</details>
