# Rust 附录 · `Debug` / `Display`、Trait 与 Python 魔法方法

> UNP 示例：[daytimesrv.rs](./code/1.5_SimpleTimeServer/rewrite_rust/daytimesrv.rs) 的 `{:?}` · [1.2 Rust](./1.2_Appendix_Rust客户端.md)

<a id="rust-debug-display"></a>

## 结论：思路像，机制完全不同

| 层面 | 说法 |
|------|------|
| **表象** | 都要「实现指定方法」才能用好内置语法（打印等）→ 和 Python **魔法方法**很像 |
| **内核** | Python = **运行时动态查找**（鸭子）；Rust = **编译期静态绑定 Trait** |

| Rust | Python | 分工 |
|------|--------|------|
| **`{}`** | `print(x)` → **`__str__`** | 给人看 ≈ **`Display`** |
| **`{:?}`** | `repr(x)` → **`__repr__`** | 调试用 ≈ **`Debug`** |

Rust **刻意拆开** Display / Debug；Python 也拆 `__str__` / `__repr__`，所以**体感高度相似**，但**检查时机与约束方式不同**。

<a id="rust-python-compare"></a>

## 一、对照举例

### Python：魔法方法（写在类**内部**）

```python
class User:
    def __str__(self):      # 对应 Rust Display
        return "用户名xxx"
    def __repr__(self):     # 对应 Rust Debug
        return "User{...}"

u = User()
print(u)    # 运行时找 __str__；没写也能过编译，打印可能怪
```

### Rust：Trait（`impl` 可在类型**外部**）

```rust
#[derive(Debug)]   // 编译器自动 impl Debug
struct User { name: String }

impl std::fmt::Display for User {   // Display 必须手写
    fn fmt(&self, f: &mut std::fmt::Formatter<'_>) -> std::fmt::Result {
        write!(f, "用户名：{}", self.name)
    }
}

let u = User { name: "aa".into() };
println!("{:?}", u);   // OK：有 Debug
// println!("{}", u);  // 编译错误：没 Display
```

**UNP**：`SystemTime` 自带 **`Debug`** → [daytimesrv.rs](./code/1.5_SimpleTimeServer/rewrite_rust/daytimesrv.rs) 可用 `format!("{:?}", …)`；要像 C `ctime` 需自写 **`Display`** 或换库。

<a id="rust-three-diff"></a>

## 二、核心三大区别（重点）

### 1. 检查时机

| | Python 魔法方法 | Rust Trait |
|---|-----------------|------------|
| 何时检查 | **运行时**才在对象上找方法 | **编译期**检查是否 `impl` |
| 漏写后果 | 编译**不拦**，跑起来才怪 / 报错 | **编译直接失败** |

### 2. 约束范围

**Python（鸭子）** — 函数不声明接口，**碰巧有方法就行**：

```python
def show(x):
    print(x)   # 任意对象，有 __str__ 就能用
```

**Rust** — 泛型可 **`T: Trait`**，入参**必须**实现该 Trait：

```rust
fn show<T: std::fmt::Display>(x: T) {
    println!("{}", x);
}
// show(没实现 Display 的类型);  // 编译失败
```

### 3. 实现归属

| | Python | Rust |
|---|--------|------|
| 写在哪 | **类/结构体内部** | **`impl Trait for Type`**，常与类型定义**解耦** |
| 扩展性 | 一般只能改自己的类 | 可为自有类型实现；改**别人**的类型受**孤儿规则**限制 |

<a id="rust-vs-duck"></a>

## 三、Trait ≠ 鸭子类型（再举一例）

```python
# Python：无静态约束
def test(x):
    x.hello()
```

```rust
trait Hello { fn hello(&self); }
fn test<T: Hello>(x: T) { x.hello(); }
// test(未 impl Hello 的类型);  // 编译期拦截
```

`#[derive(Debug)]` = 编译器**自动写** `impl Debug`，仍是**静态契约**，不是动态鸭子。

---

<a id="rust-summary"></a>

## 四、通俗一句话

> **长得像**：都靠固定命名的能力开启内置语法（打印、运算符等）。  
> **本质不同**：Python 魔法方法 = **运行动态钩子**；Rust Trait = **静态接口契约（编译校验）**。

**背**：`{}`→Display（常手写）；`{:?}`→Debug（常 derive）；Rust 编译查 Trait；Python 运行找魔法方法。

---

<a id="rust-wasm"></a>

## 五、延伸（Wasm）

Rust 编译进 Wasm 前已完成 Trait 检查，一般**不会出现**「运行时才发现没实现某方法」——对比 JS/Python 的动态查找，与「网络代码尽早用类型系统挡 bug」同一思路。
