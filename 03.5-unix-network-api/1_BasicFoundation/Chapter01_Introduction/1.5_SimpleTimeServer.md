## 本节要会什么

**TCP 服务端六步法** + 分清 **`listenfd`（只 accept）** 与 **`connfd`（只读写一路客户）**；**迭代服务器** = 串行，同一时刻只服务一个客户端。

**端口 13（Daytime / RFC865）**：`bind` **`htons(13)`** → 见 [1.2 端口说明](./1.2_SimpleTimeClient.md#daytime-port) · **与图 1-5 客户端联合流程** → [1.12 C/S 时序](./1.12_Summary.md#ch1-cs-overview)

<a id="ch1-5-flow"></a>

## 一、整体流程（服务端六步）

| # | 步骤 | API / 行为 |
|---|------|------------|
| 1 | 创建监听套接字 | `Socket` → **`listenfd`** |
| 2 | 绑定地址端口 | **`Bind`**：`INADDR_ANY` + **`htons(13)`** |
| 3 | 被动监听 | **`Listen(listenfd, LISTENQ)`** |
| 4 | 等客户连入 | **`Accept`** 阻塞 → 返回 **`connfd`** |
| 5 | 发时间字符串 | `time` / `ctime` / **`snprintf`** → **`Write(connfd, …)`** |
| 6 | 关本会话 | **`Close(connfd)`** → 回到步骤 4 |

```text
socket → bind(0.0.0.0:13) → listen → for(;;) { accept → write → close(connfd) }
```

> **迭代**：新连接必须等上一客户 **`close(connfd)`** 后，下一次 `accept` 才会处理它（排队）。

---

<a id="ch1-5-fd"></a>

## 二、listenfd vs connfd（核心）

| | **listenfd** | **connfd** |
|---|--------------|------------|
| **创建** | `Socket` 一次 | 每次 `Accept` 一个新 fd |
| **用途** | **只** `Accept` 新连接 | **只** 本会话的 `read`/`write` |
| **生命周期** | 进程全程不关 | 处理完该客户就 **`Close`** |
| ❌ 禁止 | 在 listenfd 上 read/write | 用 connfd 去 accept |

**绑定谁？** `sin_addr = htonl(INADDR_ANY)` → **0.0.0.0**，本机**所有网卡**的 13 端口都可连（不必写死 `192.168.x.x`）。

---

<a id="ch1-5-api"></a>

## 三、关键 API 对照

| API | 要点 |
|-----|------|
| **`Bind`** | `INADDR_ANY` + `htons(13)`；端口网络序 |
| **`Listen(fd, LISTENQ)`** | **backlog** ≈ 全连接队列上限；`listenfd` 进入被动监听 |
| **`Accept(listenfd, …)`** | 阻塞；三次握手完成后返回**新** `connfd` |
| **`snprintf`** | 限长写 buff；**禁用 `sprintf`** 防溢出 |
| **`Write(connfd, …)`** | TCP 流式发出时间串 |
| **`Close(connfd)`** | 只关本会话；**不要** `close(listenfd)` |

半连接 / 全连接 → 见下方折叠 [listen 队列](#listen-queue)

<a id="ch1-5-runtime"></a>

## 四、逻辑时序

```text
listenfd = socket → bind → listen →
  accept 阻塞 → 握手完成得 connfd →
  组时间串 → write → close(connfd) →
  回到 accept（下一客户）
```

<a id="ch1-5-cheat"></a>

## 五、易错陷阱

| ❌ | ✅ |
|----|-----|
| 在 **listenfd** 上 read/write | 只用 **connfd** 做 I/O |
| **sprintf** | **snprintf(buff, sizeof(buff), …)** |
| **close(listenfd)** | 只 **Close(connfd)** |
| 以为迭代能同时服务多人 | 串行；并发见 Ch 4/5 **fork** |

## 八、个人学习总结

1. **listenfd** 只 accept；**connfd** 只服务一次会话。
2. **INADDR_ANY** = 全网卡监听，服务端常规写法。
3. **迭代** 串行；全连接队列可堆满 → 生产用 fork / 多路复用。
4. **snprintf** 限长；禁用 sprintf。

**30 字**：bind 全零地址、listen、循环 accept、写时间、关 connfd。

### 被动打开时内核有两类队列

客户端 `connect`（主动打开）后，服务端在 **`listen` 之后、`accept` 之前**，内核要为每个到来的连接维护状态。常分成：

| 队列 | 俗称 | 里有什么 | 何时离开 |
|------|------|----------|----------|
| **半连接队列** | SYN 队列 | 收到 **SYN**，三次握手**未完成** | 握手完成 → 移入全连接队列；或超时丢弃 |
| **全连接队列** | accept 队列 | 三次握手**已完成**，等待应用 **`accept`** 取走 | 你的进程 **`Accept` 成功** → 变成 `connfd` |

```text
客户 SYN ──► [半连接队列] ──握手完成──► [全连接队列] ──accept()──► connfd（应用）
```

### `Listen(listenfd, LISTENQ)` 里的 backlog 管什么？

| 要点 | 说明 |
|------|------|
| **`LISTENQ`（backlog）** | 应用传给 `listen` 的第二个参数；历史上各 OS 解释不一，**现代 Linux 上主要限制「全连接队列」相关容量**（与 `somaxconn` 等取 min） |
| **半连接队列** | 长度常由 **`tcp_max_syn_backlog`** 等**内核参数**控制，**不是**你写 `LISTENQ` 单独设死的 |
| **1.5 迭代服务器的坑** | 你在 **`Write` + `Close` 之前不会 `accept` 下一个** → 全连接队列里可以堆很多已完成握手、但还没被 `accept` 的连接；队列满 → 新连接可能被拒或丢弃 |

**背一句**：`LISTENQ` ≈ 「已完成握手、等着 `accept` 的客户」能排多长；**半连接**另由内核调。

### 和 1.5 迭代模型的关系

| 现象 | 原因 |
|------|------|
| 多客户同时连 | 握手可在内核队列里完成，但**应用串行**：一次只处理一个 `connfd` |
| 处理很慢时客户「连不上」 | 全连接队列满 / 半连接 SYN 洪泛等 → 需 **fork / 线程 / epoll**（Ch 4/5） |
| **listenfd 不能 read/write** | 数据路径在 **connfd**；队列在内核，不靠你在 listenfd 上 I/O |

### 常见内核参数（了解即可）

| 参数（Linux 示例） | 作用 |
|--------------------|------|
| `net.core.somaxconn` | 与 `listen` backlog 共同 cap 全连接队列 |
| `net.ipv4.tcp_max_syn_backlog` | 半连接（SYN）队列相关上限 |

调优属运维；写 1.5 程序只需：**`Listen(fd, LISTENQ)` 用原书宏，知道队列会满即可**。

### C 原版（UNP 标准 · 大写包裹）

```c
#include "unp.h"

int main(int argc, char **argv)
{
    int listenfd, connfd;
    struct sockaddr_in servaddr;
    char buff[MAXLINE];
    time_t ticks;

    listenfd = Socket(AF_INET, SOCK_STREAM, 0);

    bzero(&servaddr, sizeof(servaddr));
    servaddr.sin_family      = AF_INET;
    servaddr.sin_addr.s_addr = htonl(INADDR_ANY); /* 0.0.0.0 全网卡 */
    servaddr.sin_port        = htons(13);

    Bind(listenfd, (SA *)&servaddr, sizeof(servaddr));
    Listen(listenfd, LISTENQ);

    for (;;) {
        connfd = Accept(listenfd, NULL, NULL);

        ticks = time(NULL);
        snprintf(buff, sizeof(buff), "%.24s\r\n", ctime(&ticks));
        Write(connfd, buff, strlen(buff));

        Close(connfd);
    }
}
```

> 仓库文件：[1.5_daytimesrv.c](./1.5_daytimesrv.c)

### Rust 对等（迭代逻辑）

```rust
use std::io::Write;
use std::net::TcpListener;
use std::time::SystemTime;

fn main() -> std::io::Result<()> {
    let listener = TcpListener::bind("0.0.0.0:13")?;
    println!("daytime server listen on :13");

    for stream in listener.incoming() {
        let mut conn = stream?;
        let time_str = format!("{:?}\r\n", SystemTime::now());
        conn.write_all(time_str.as_bytes())?;
    }
    Ok(())
}
```

| C | Rust |
|---|------|
| `listenfd` | `listener` 全程存活 |
| `connfd` | 每次 `accept` / `incoming` 的 `TcpStream`，块结束 **Drop** = `Close` |
