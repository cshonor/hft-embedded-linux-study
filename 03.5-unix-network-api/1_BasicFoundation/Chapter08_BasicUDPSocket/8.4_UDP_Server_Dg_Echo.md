# 8.4 UDP 回射服务器程序：dg_echo 函数

> [8.3 main](8.3_UDP_Server_Main.md)

---

## 核心机制

```c
void dg_echo(int sockfd, struct sockaddr *pcliaddr, socklen_t clilen)
{
    int    n;
    socklen_t len;
    char   mesg[MAXLINE];

    for (;;) {
        len = clilen;
        n = Recvfrom(sockfd, mesg, MAXLINE, 0, pcliaddr, &len);
        Sendto(sockfd, mesg, n, 0, pcliaddr, len);
    }
}
```

---

## 迭代服务器模型（Iterative Server）

| 点 | 说明 |
|----|------|
| **单进程** | `while(1)` 交替处理**多个客户**乱序到达的报文 |
| **多数 UDP 服务器** | **迭代**，不必像 TCP 那样每连接 **fork** |
| **原因** | 无 per-connection 状态独占；一报文一处理 |

---

## 易错细节

| 陷阱 | 说明 |
|------|------|
| 业务极慢 | 单进程阻塞在慢处理 → 接收队列满 → **丢包**（8.13） |
| 以为要 fork | UDP 默认可迭代；高负载才要线程/进程池 |

## 个人学习总结

`dg_echo` = recvfrom 收数据报 → sendto 原路回射。用 recvfrom 得到的客户地址直接 sendto 回去。

**一句话**：UDP 回射服务器核心就两行——recvfrom + sendto，无状态。

> 与 TCP str_echo 对比：TCP 需要循环 read（字节流），UDP 一次 recvfrom 就是一个完整消息。
