# 5.15 服务器主机崩溃后重启

> [5.14 崩溃](../5.14_Server_Host_Crash.md) · RST

---

## 核心主旨与关键论据

主机**崩溃后快速重启**：内存中 **TCP 连接状态全部丢失**，但客户仍以为旧连接有效。客户再发数据 → 服务器协议栈**无匹配连接** → 回 **RST** → 客户 **`read` 得 ECONNRESET**。

---

## 异常场景拆解

| 步 | 说明 |
|----|------|
| 1 | 重启后服务器**无**崩溃前的 TCB |
| 2 | 客户认为连接仍在，**write** 或 keepalive 探测 |
| 3 | 服务器收到「陌生」四元组数据 → **RST** |
| 4 | 客户阻塞在 **`read`**（或 readline）→ 返回 **-1**，**`errno = ECONNRESET`**（Connection reset by peer） |

---

## 易错细节与重点结论

|  errno / 现象 | 典型场景 |
|---------------|----------|
| **ETIMEDOUT** | 5.14 黑洞、无 ICMP |
| **ECONNRESET** | 5.15 重启后 RST、5.12 后 writen 再 read |
| **EPIPE** | 5.13 向 RST 连接 write |

**一句**：重启 = **状态丢失 + RST**，比纯超时**更快**暴露错误（一旦发数据）。
