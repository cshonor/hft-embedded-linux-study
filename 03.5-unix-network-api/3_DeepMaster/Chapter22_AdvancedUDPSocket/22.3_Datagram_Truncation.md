# 22.3 数据报截断

> [14.5 MSG_TRUNC](../../2_AdvancedSkill/Chapter14_AdvancedIO_Func/14.5_Recvmsg_Sendmsg_Func.md) · [14.7 FIONREAD](../../2_AdvancedSkill/Chapter14_AdvancedIO_Func/14.7_Pending_Data_Check.md)

---

## 核心异常

UDP 报文长度 **>** 用户缓冲区 → **截断**（超出部分丢弃）。

---

## 各平台差异（排错重灾区）

| 行为 | 说明 |
|------|------|
| **Berkeley 传统** | 静默截断，**无错误** |
| **SVR4** | 返回错误，`errno = EMSGSIZE` |
| **POSIX / 现代** | 用 **`recvmsg`** 时 **`msg_flags` 含 `MSG_TRUNC`** |

---

## 重点结论

健壮 UDP 接收：**`recvmsg` + 每次检查 `MSG_TRUNC`**。

---

> 💡 **后续拓展留白**  
> - `FIONREAD` 先探测下一报文长度再分配缓冲

## 个人学习总结

UDP 数据报截断：如果接收缓冲区小于数据报 → 数据报被截断，超出部分**永久丢弃**（不像 TCP 留在缓冲区）。

**MSG_TRUNC**：recvmsg 标志，返回数据报的实际长度（即使只读了部分）。

**一句话**：UDP recvfrom 缓冲不够 → 截断丢数据 → 用 MSG_TRUNC 至少知道原始长度。

> HFT 关联：行情包应预分配足够大的缓冲区（如 1500 MTU）防止截断。
