# 22.2 接收标志、目的 IP 地址和接口索引

> [14.5 recvmsg](../../2_AdvancedSkill/Chapter14_AdvancedIO_Func/14.5_Recvmsg_Sendmsg_Func.md) · [14.6 辅助数据](../../2_AdvancedSkill/Chapter14_AdvancedIO_Func/14.6_Auxiliary_Data.md)

---

## 业务痛点

`bind(INADDR_ANY)` 的 UDP 服：`recvfrom` 只知**源地址**，不知：

- 数据报**发往本机哪个 IP**（多宿主回复）  
- **从哪块网卡**收到（接口索引）

---

## 机制：recvmsg + 辅助数据

### IPv4

| 选项 | 辅助数据 |
|------|----------|
| **`IP_RECVDSTADDR`** | 目的 IPv4 |
| **`IP_RECVIF`** | 接口索引 |

遍历 `cmsghdr`：`cmsg_level == IPPROTO_IP`，类型 `IP_RECVDSTADDR` / `IP_RECVIF`。

### IPv6

| 选项 | 内容 |
|------|------|
| **`IPV6_RECVPKTINFO`** | 单一 **`in6_pktinfo`**（目的地址 + 接口 index） |

比 IPv4 分离选项更统一。

---

## 个人学习总结

IP_PKTINFO/IPV6_PKTINFO — 通过 recvmsg 辅助数据获取收包的**目的 IP**和**入接口索引**。

**场景**：服务器 bind INADDR_ANY + 多网卡 → 需知数据报到哪个 IP 才能正确回复。

**一句话**：IP_PKTINFO 告诉你"这个包是发给哪个本地 IP 的"——多网卡回复必须用同一 IP 做源。

> 用 recvmsg + cmsghdr 获取，不能用 recvfrom。
