## TCP vs UDP

| TCP | UDP |
|-----|-----|
| `accept` → **新**已连接套接字 | **无 accept**，全进**同一**套接字队列 |

---

## fork 新端口模式（笨拙）

```text
主进程 recvfrom → fork
子进程：新建 UDP 套接字 + 临时端口 → 从此套接字 sendto 应答
```

**客户端限制**：须接受**应答源端口 ≠ 请求目的端口**；严格 NAT/四元组校验会**丢应答**。

---

## 实践倾向

多数 UDP 服（如 DNS）：**迭代**或**线程/Worker 池共享单套接字**，而非 per-client fork 新端口。

## 个人学习总结

UDP 并发服务器困境：UDP 无连接 → 无法像 TCP 那样 fork 一连接一子进程。每个 recvfrom 都可能是新客户。

**方案**：①迭代（适合短处理）②fork 后子进程用 connect 绑定客户地址（临时 TCP 化）③线程池。

**一句话**：UDP 并发 = 手动跟踪客户身份 → fork/线程 + 客户地址映射。

> 实际工程中 UDP 迭代服务器 + select 即可处理多数场景。
