# 22.9 IPv6 路径 MTU 控制

---

## 背景

| | IPv4 | IPv6 |
|--|------|------|
| 路由器分片 | 可以 | **绝不**（仅源主机分片） |
| PMTUD | 重要 | **更关键** |

---

## 套接字选项

| 选项 | 作用 |
|------|------|
| **`IPV6_USE_MIN_MTU = 1`** | 不做 PMTUD，按最小 MTU **1280** 分片；规避 ICMPv6 “Packet Too Big” 被防火墙丢导致的 **PMTU 黑洞** |
| **`IPV6_RECVPATHMTU`** | 收到 “Packet Too Big” 时，将最新路径 MTU 经**辅助数据**通知应用 |

---

## 个人学习总结

PMTU（Path MTU）发现：发送大于路径 MTU 的包 → 路由器返回 ICMP "Fragmentation Needed" → 发送方减小包大小。

**IPV6_MTU**：getsockopt 获取发现的路径 MTU。IPv6 路由器不分片——超 MTU 直接丢 + ICMP 通知。

**一句话**：IPv6 不允许路由器分片——应用必须自己控制包大小 ≤ PMTU。

> HFT 关联：行情包应 ≤ MTU（通常 1500）避免分片延迟和丢包风险。
