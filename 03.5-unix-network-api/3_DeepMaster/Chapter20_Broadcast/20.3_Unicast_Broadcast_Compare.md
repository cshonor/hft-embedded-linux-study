# 20.3 单播和广播的比较

---

## 单播接收流程

```text
网卡收帧 → 硬件比对目的 MAC
  不匹配（且非组播/广播 MAC）→ 硬件丢弃，不占 CPU
  匹配 → 中断 → IP 查目的 IP → UDP 查端口 → 入套接字队列
```

---

## 广播的代价

```text
目的 IP/MAC 为广播 → 子网每台主机网卡都必须收帧 → 中断上送
→ IP 交 UDP → 无进程监听该端口 → 丢弃（可能 ICMP 端口不可达）
```

---

## 核心论据

**未参与协议的主机仍承担 CPU/中断开销** — 高频广播须迁向**多播**（Ch 21）；亦是 **IPv6 废除广播** 的理由之一。

---

## 个人学习总结

广播 vs 单播的链路层代价：单播 → 一次 ARP + 一个目的 MAC；广播 → 无 ARP，目的 MAC 全 1，但**链路上所有主机都被中断**。

**一句话**：广播不省带宽——每个主机都要中断处理，即使丢弃。

> 广播"免费"发送 N 份拷贝，但 N 台主机都要付费（中断+处理）。
