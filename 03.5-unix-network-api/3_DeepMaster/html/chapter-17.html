17.1

概述

Ch 26 · 17.2 ioctl · study.md

核心主旨

ioctl（I/O Control）：无法归入 read/write 或 getsockopt/setsockopt 的底层操作，历史上常经此完成。

本章四大应用领域：

领域 节
套接字操作 17.3
文件描述符操作 17.4
网络接口配置 17.5–17.7
ARP / 路由表 17.8–17.9

历史演进与 POSIX 替代

功能 现代替代
非阻塞、信号驱动 I/O fcntl
带外标记 sockatmark
路由表、ARP 遍历 路由套接字（Ch 18）、Netlink
本机网卡拓扑 SIOCGIFCONF 长期仍不可替代

易错细节

ioctl 可移植性差，参数类型无编译期检查 — 新代码优先 POSIX 专用 API。

资料说明

上传资料截至第 8 章；第 17 章按 UNP 第 3 版体系整理，请与全本对照验证。

个人学习总结

ioctl 是套接字/文件/网络接口的"杂项控制"入口——getsockopt 做不到的底层操作走 ioctl。

三入口对比：getsockopt（套接字选项）、fcntl（fd 通用控制）、ioctl（设备/网口级控制）。

现代趋势：路由用 Ch18 路由套接字替代 ioctl——更结构化、更可移植。

17.2

ioctl 函数

17.3

函数原型

int ioctl(int fd, int request, ... /* void *arg */);
项 说明
成功 通常 0
失败 -1，errno
fd 打开的文件或套接字描述符
request 命令宏（FIONBIO、SIOCGIFCONF 等）
arg 指针或整数，类型完全由 request 决定

重点结论

request 传统上编码操作类型、读写方向、参数大小 — 无类型安全，调用方须与文档严格匹配。

个人学习总结

int ioctl(int fd, int request, ...) — 万能控制接口，request 决定操作类型。

一句话：ioctl 是"参数个数和类型都变"的可变参数函数——request 编码定义语义。

缺点：类型不安全、参数可变、可移植性差——不同 OS 的 request 值不同。

17.3

套接字操作

Ch 7.11 fcntl · Ch 24 带外（待学）

套接字层级命令

命令 作用
SIOCATMARK 读指针是否在 OOB 标记上；arg 为 int*，1/0
SIOCGPGRP / SIOCSPGRP 获取/设置套接字 进程/进程组（SIGIO、SIGURG）

POSIX 替代

ioctl 推荐
SIOCATMARK sockatmark(sockfd)
SIOCGPGRP / SIOCSPGRP fcntl F_GETOWN / F_SETOWN

个人学习总结

套接字级 ioctl：SIOCATMARK（查 OOB 标记）、SIOCGIFCONF（获取接口列表）、FIONBIO（设非阻塞，等价 fcntl O_NONBLOCK）。

一句话：SIOCATMARK 配合 sockatmark 检查带外数据标记位置（Ch24）。

FIONBIO 设非阻塞已被 fcntl O_NONBLOCK 取代——后者更标准。

17.4

文件操作

Ch 16 非阻塞 · 14.7 FIONREAD

命令（套接字与普通 fd 均可）

命令 作用
FIONBIO arg 指向 int：0 清除 / 非 0 设置 非阻塞
FIOASYNC 设置/清除 信号驱动 I/O（O_ASYNC）
FIONREAD arg 指向 int：返回接收缓冲区排队未读字节数

对比结论

ioctl(FIONBIO) fcntl(O_NONBLOCK)
调用次数 一次 常需 GET 再 SET
POSIX 不推荐 规范要求

FIONREAD 与 14.7 探测排队数据一致，不阻塞。

个人学习总结

文件级 ioctl：FIONREAD（待读字节数）、FIOASYNC（信号驱动 I/O）、FIOSETOWN（设 SIGIO 接收进程）。

一句话：FIONREAD 不消费数据，只查缓冲区有多少字节可读。

FIOASYNC + FIOSETOWN 是 Ch25 信号驱动 I/O 的前提。

17.5

接口配置

17.6 get_ifi_info · 17.7

核心主旨

多播、路由守护进程、代理等启动时常需：本机有哪些网卡？IP、掩码？

ioctl + <net/if.h> 提供拓扑发现。

核心结构

结构 用途
struct ifreq 单个接口 单项属性（ifr_name、ifr_addr、ifr_netmask…）
struct ifconf 缓冲区数组，装多个 ifreq

SIOCGIFCONF（值—结果参数）

ioctl(fd, SIOCGIFCONF, &ifc);
调用前 调用后
ifc.ifc_buf 指向大缓冲区 内核填入各接口 ifreq
ifc.ifc_len = 缓冲区大小 ifc.ifc_len = 实际写入字节数

致命陷阱：缓冲区截断

缓冲区过小时，许多传统 Unix 不报错，只静默截断填满缓冲区。

防错：循环加倍分配并重试 SIOCGIFCONF，直到返回的 ifc.ifc_len 严格小于 提供的容量，才确认无截断。

个人学习总结

SIOCGIFCONF 获取所有网络接口列表——但返回的 ifconf 结构有截断陷阱：缓冲区不够大时静默截断，不报错。

解法：循环调用，每次加倍缓冲区直到返回的 ifc_len 不增长。

一句话：SIOCGIFCONF 是获取网卡列表的旧方式——现代用 getifaddrs() 或 sysctl 替代。

HFT 关联：多网卡机器需枚举接口绑定特定网卡——DPDK 有自己的接口管理。

17.6

get_ifi_info 函数

17.5 SIOCGIFCONF · Ch 18.5（路由套接字版）

核心封装

直接处理 SIOCGIFCONF 的缓冲区伸缩、解析、IPv4/IPv6 步长对齐极其繁琐 — 书中 get_ifi_info 封装。

功能

  • 透明调用底层 ioctl
  • 处理缓冲区加倍重试、对齐
  • 返回 ifi_info 链表

ifi_info 典型字段

字段 内容
接口名 eth0、lo0
索引 接口 index
单播 IP sockaddr
掩码、广播地址
标志 广播/多播/P2P/UP 等

地位

编写多播、底层协议、代理时的基石工具函数。

个人学习总结

Stevens 封装 get_ifi_info(family, doaliases) — 基于 SIOCGIFCONF 返回 ifi_info 结构链表（接口名、IP、掩码、广播地址）。

一句话：get_ifi_info = 统一的接口信息获取封装——屏蔽不同 OS 的 ioctl 差异。

现代替代：getifaddrs() 更简洁；DPDK 用 rte_eth_dev_info 获取网卡信息。

17.7

接口操作

17.5

用法

SIOCGIFCONF 得到接口名 → 填入 ifreq.ifr_name → 针对单个网卡 ioctl。

Get 命令（常用）

命令 获取
SIOCGIFADDR 单播 IP
SIOCGIFBRDADDR 广播地址
SIOCGIFNETMASK 子网掩码
SIOCGIFDSTADDR P2P 远端地址
SIOCGIFFLAGS 标志位（UP、LOOPBACK、MULTICAST 等）

Set 命令

如 SIOCSIFADDR、SIOCSIFFLAGS 等。

限制 说明
权限 所有 Set 操作需 root

个人学习总结

接口控制 ioctl：SIOCGIFFLAGS（获取标志：UP/RUNNING/PROMISC）、SIOCSIFFLAGS（设置标志——需 root）。

一句话：SIOCSIFFLAGS 可启停网卡、设混杂模式——需要 CAP_NET_ADMIN 权限。

混杂模式（PROMISC）用于抓包——tcpdump 底层设此标志。

17.8

ARP 高速缓存操作

Ch 18 路由套接字

核心机制

ioctl 直接操作内核 ARP 表（IP → MAC）。

  • 结构：<net/if_arp.h> 的 struct arpreq

三大命令

命令 作用 权限
SIOCGARP 按 IP 查 MAC 普通用户通常可
SIOCSARP 增/改表项（静态绑定、防欺骗） root
SIOCDARP 删除表项 root

个人学习总结

ARP 缓存 ioctl：SIOCGARP（查询）、SIOCSARP（添加）、SIOCDARP（删除）——操作 ARP 缓存表。

一句话：ARP ioctl 操控 IPv4→MAC 映射表——调试网络可达性时有用。

IPv6 用 NDP（邻居发现协议）替代 ARP——ioctl 不同。现代用 netlink 替代这些 ioctl。

17.9

路由表操作

Ch 18 路由套接字

传统 ioctl 命令

部分 Unix 提供：

命令 作用
SIOCADDRT 添加路由
SIOCDELRT 删除路由
  • 结构：<net/route.h> 的 struct rtentry

重点结论（架构指引）

新代码不要用 ioctl 操作路由表。

问题 说明
被动变化 ICMP 重定向、路由守护进程更新时，ioctl 无法异步通知应用
现代做法 AF_ROUTE 路由套接字（Ch 18）、Linux Netlink

个人学习总结

路由表 ioctl：SIOCADDRT/SIOCDELRT——添加/删除路由表项（需 root）。

一句话：路由 ioctl 已过时——现代用 Ch18 路由套接字（AF_ROUTE/netlink）替代。

路由套接字更结构化、支持异步通知，是现代路由管理首选。

17.10

小结

study.md

章节核心提炼

1. 历史遗物与现用利器

  • 无类型安全的古老接口
  • 非阻塞、OOB、信号属主 → fcntl / sockatmark
  • 路由/ARP 动态管理 → 路由套接字 / Netlink

2. 不可替代的拓扑探索

  • SIOCGIFCONF：获取本机网卡列表的正统手段（许多环境）
  • 截断无报警 → 加倍缓冲区重试
  • get_ifi_info：封装为 ifi_info 链表

3. 底层特权干预

  • ifreq：类 ifconfig 的接口配置
  • arpreq：类 arp 的静态/动态 ARP 管理（root 写操作）

ioctl 使用决策树

非阻塞/异步/OOB 属主？ → fcntl / sockatmark
本机有哪些网卡/IP？     → SIOCGIFCONF + get_ifi_info
改接口/ARP？            → ifreq/arpreq（常需 root）
动态路由？              → 勿 ioctl；用 Ch18 路由套接字

个人学习总结

ioctl 是历史遗留的"万能控制接口"——类型不安全、可移植性差，但大量功能仍依赖它。

核心功能：SIOCGIFCONF（接口列表）、FIONREAD（待读字节）、SIOCGIFFLAGS（接口状态）。

趋势：路由→AF_ROUTE/netlink；接口→getifaddrs；非阻塞→fcntl。ioctl 逐渐被替代但未消亡。

HFT 关联：DPDK 完全不用 ioctl——有自己的 PMD 驱动直接操作网卡寄存器。
