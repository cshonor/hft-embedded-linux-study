20.1

概述

核心主旨

模式 说明
单播 一点对一点
广播 向 LAN 内所有节点发（本章）
多播 向订阅组发（Ch 21）

广播限制在局域网：路由器通常不转发，防广播风暴。

点 说明

资料说明

上传资料截至第 8 章；第 20 章按 UNP 第 3 版体系整理，请与全本对照验证。

个人学习总结

广播 = 一对全——一个发送方，同子网所有主机都收。需 SO_BROADCAST 权限 + UDP。

一句话：广播只限 UDP，只在本子网内有效，路由器不转发定向广播。

HFT 关联：广播在现代 HFT 中少用——组播更灵活（跨子网、可控接收者）。

20.2

广播地址

地址分类（IPv4）

将 IPv4 分为 netid + hostid（子网划分后实际四类）：

类型 形式 路由行为
受限广播 255.255.255.255 路由器绝不转发；仅限本链路
指向网络 netid 固定，hostid 全 1（如 10.255.255.255） 理论上可转发到该网络；现代路由器多默认禁用
子网定向广播 子网 hostid 全 1（如 192.168.42.0/24 → 192.168.42.255） 最常用；接口发链路层广播帧
全子网定向 子网位+主机位全 1 已过时，易混淆

链路层

目的 IP 为广播 → 常映射以太网 FF:FF:FF:FF:FF:FF。

个人学习总结

IPv4 广播地址：受限广播 255.255.255.255（不路由）和定向广播（子网全 1，如 192.168.1.255）。

一句话：255.255.255.255 只在本网传播；192.168.1.255 可跨路由器到达目标子网（但默认被路由器丢弃）。

子网广播地址 = 网络号 | ~掩码。如 192.168.1.0/24 → 192.168.1.255。

20.3

单播和广播的比较

单播接收流程

网卡收帧 → 硬件比对目的 MAC
  不匹配（且非组播/广播 MAC）→ 硬件丢弃，不占 CPU
  匹配 → 中断 → IP 查目的 IP → UDP 查端口 → 入套接字队列

广播的代价

目的 IP/MAC 为广播 → 子网每台主机网卡都必须收帧 → 中断上送
→ IP 交 UDP → 无进程监听该端口 → 丢弃（可能 ICMP 端口不可达）

核心论据

未参与协议的主机仍承担 CPU/中断开销 — 高频广播须迁向多播（Ch 21）；亦是 IPv6 废除广播 的理由之一。

个人学习总结

广播 vs 单播的链路层代价：单播 → 一次 ARP + 一个目的 MAC；广播 → 无 ARP，目的 MAC 全 1，但链路上所有主机都被中断。

一句话：广播不省带宽——每个主机都要中断处理，即使丢弃。

广播"免费"发送 N 份拷贝，但 N 台主机都要付费（中断+处理）。

20.4

使用广播的 dg_cli 函数

Ch 8 UDP 客户 · Ch 7.5 SO_BROADCAST · 17.7 SIOCGIFBRDADDR

改造要点

UDP 单播客户 → 广播客户，改动很小。

SO_BROADCAST（强制）

向广播地址 sendto 前必须：

int on = 1;
setsockopt(sockfd, SOL_SOCKET, SO_BROADCAST, &on, sizeof(on));

未设置 → 内核拒绝发送，errno = EACCES。

实现步骤

socket(UDP) → setsockopt(SO_BROADCAST)
→ 目的地址：子网广播（192.168.x.255）或 255.255.255.255
→ 循环 sendto 请求 + recvfrom 收多台服务器应答

勿硬编码广播地址 — 可用 ioctl SIOCGIFBRDADDR 取本网卡子网广播地址。

易错：IP 分片

广播数据报通常不允许分片 → 载荷须 < 接口 MTU（以太网约 1500 − IP/UDP 头）。

个人学习总结

广播版 dg_cli：sendto 目标改为广播地址 → 同子网所有接收者 recvfrom。

关键：发送方需 setsockopt(SO_BROADCAST) 获取权限，否则 EACCES。

接收方无需特殊设置——正常 bind + recvfrom 即可收到广播。

20.5

竞争状态

Ch 6.9 pselect · Ch 8.7 超时

核心主旨

广播客户一发多收：多台服务器几乎同时应答；常用 alarm(2) + recvfrom 收集约 2 秒后退出。

SIGALRM + recvfrom 混用 → 竞争状态。

错误时序（信号丢失）

1. alarm(2)
2. 其他代码（日志等）—— 竞争窗口
3. 2 秒到，SIGALRM 先触发并处理完
4. 才调用 recvfrom
5. 再无应答 → recvfrom 永久阻塞（超时已被“消耗”）

终极方案：pselect

1. sigprocmask 阻塞 SIGALRM（保持 Pending，不打断）
2. 准备 I/O
3. pselect：原子地解除 SIGALRM 阻塞并睡眠
4. 睡眠中信号 → pselect 以 EINTR 返回
5. 返回后恢复掩码，继续阻塞 SIGALRM

重点结论

需精细超时 + 并发到达时，pselect 可免疫「检查与睡眠之间」的竞态；或改用 带超时的 select 轮询模型。

💡 后续拓展留白
- Linux signalfd 将信号转为可读事件

个人学习总结

广播 dg_cli 竞态：alarm 超时 SIGALRM 与 recvfrom 阻塞竞态——信号可能在 recvfrom 返回前到达。

解法：用 pselect 临时屏蔽信号，或用 setjmp/longjmp 从信号处理器跳转。

一句话：alarm + 阻塞 recvfrom = 经典竞态——用 pselect 或 SIGIO 替代。

现代方案：SO_RCVTIMEO 超时最简洁，无信号竞态。

20.6

小结

study.md · Ch 21 多播

章节核心提炼

1. 范围与协议

  • 广播 = LAN 内高侵入通信
  • 255.255.255.255、子网定向广播最常见
  • 仅 UDP；IPv6 用多播

2. 安全锁

必须 SO_BROADCAST，否则 EACCES。

3. 代价

穿透单播 MAC 硬件过滤，全子网主机协议栈处理 — 理解后更易接受 IPv6/多播设计。

4. 一发多收防死锁

  • 初级：alarm + recvfrom（有竞态）
  • 生产：pselect 或 select 超时

广播 vs 多播（预告 Ch 21）

广播 多播
接收方 子网全部主机 加入组的主机
IPv6 无 标准方案

个人学习总结

广播 = UDP 子网内一对全。需要 SO_BROADCAST 权限。255.255.255.255 不路由，定向广播默认被路由器丢弃。

竞态：alarm+recvfrom 有信号竞态 → 用 pselect 或 SO_RCVTIMEO 替代。

广播已被组播取代——组播可控接收者列表、可跨子网、更高效。
