25.1

概述

Ch 6.2 I/O 模型 · 25.2 · study.md

核心主旨

Ch 6 五种 I/O 模型之一：信号驱动式 I/O（Signal-Driven I/O）。

对比 行为
阻塞 I/O 进程阻塞在 read/write
非阻塞 轮询 + EWOULDBLOCK
信号驱动 内核在 fd 就绪时发 SIGIO，进程继续做别的事

核心理念

告诉内核：“描述符可 I/O 时，用 SIGIO 通知我。”

等待阶段进程不阻塞在读写上。

资料说明

上传资料截至第 8 章；第 25 章按 UNP 第 3 版体系整理，请与全本对照验证。

个人学习总结

信号驱动 I/O = SIGIO 通知——fd 可读时内核发 SIGIO 信号，应用在信号处理器中 read。

三步启用：①fcntl F_SETOWN 设接收进程 ②fcntl O_ASYNC（或 FIOASYNC）开异步通知 ③非阻塞 I/O。

一句话：SIGIO = "内核主动告诉你有数据了"——类似硬件中断，不用轮询。

历史定位：SIGIO 被 epoll 的边缘触发取代——现代几乎不用。

25.2

套接字的信号驱动式 I/O

Ch 7.11 fcntl · 17.4 FIOASYNC · 24.2 SIGURG

开启 SIGIO 三步骤（必须全部完成）

1. sigaction(SIGIO, handler, ...)     /* 建立 SIGIO 处理函数 */
2. fcntl(fd, F_SETOWN, pid/pgrp)      /* 套接字属主：信号发给谁 */
3. fcntl(fd, F_SETFL, O_ASYNC)        /* 或 ioctl FIOASYNC：开启异步 I/O */

缺任一步 → 无 SIGIO。

UDP：理想用武之地

仅两种情形触发 SIGIO：

事件 处理
数据报到达 可安全 recvfrom
异步错误 可读错误状态

收到 SIGIO → 明确可读或出错。

TCP：几乎无用

触发 SIGIO 的事件过多且语义含混：

  • listen 上新连接就绪
  • 各种断开/半关闭状态变化
  • 数据到达
  • 发送缓冲区有空（可写）
  • 异步错误

收到 SIGIO 时不知是哪一种 → 盲目 read/write 易 EWOULDBLOCK。

特例（偏门）

仅对 listenfd 开信号驱动时，SIGIO 常表示 accept 就绪 — 少数高并发优化曾探索。

💡 后续拓展留白
- listen 专用 SIGIO 与 epoll 对比

个人学习总结

SIGIO 对 UDP 有效——每个数据报到达发一个 SIGIO。对 TCP 几乎无用——太多事件触发 SIGIO（连接建立/数据到达/关闭等）。

一句话：SIGIO 适合 UDP（每包一个信号），不适合 TCP（事件太多无法区分）。

TCP 的 SIGIO 无法告诉你"是连接还是数据还是关闭"——无法据此编程。

25.3

使用 SIGIO 的 UDP 回射服务器程序

Ch 8.4 dg_echo · Ch 16 非阻塞 · Ch 5.8 信号

架构：生产者-消费者

角色 职责
生产者（SIGIO 处理函数） 循环 非阻塞 recvfrom 直至 EWOULDBLOCK（信号不排队，须抽干）→ 入全局队列
消费者（主循环） 从队列取 → sendto 回射

竞态与信号掩码（黄金法则）

主循环与处理函数并发访问全局队列 — 须当多线程一样保护。

错误 后果
if (empty) sleep() 无掩码 判断空与睡眠之间 SIGIO 入队 → 永久睡死

正确流程：

1. sigprocmask 阻塞 SIGIO
2. 若队列空 → sigsuspend（原子解除阻塞并睡眠）
3. 取数据、改队列指针 — 均在 SIGIO 阻塞的临界区内
4. sigprocmask 恢复

个人学习总结

SIGIO UDP 回射服务器架构：信号处理器设 flag → 主循环 sigsuspend 等信号 → 收到 SIGIO → 从队列取数据报处理 → 回复。

关键：sigprocmask 屏蔽 SIGIO + sigsuspend 原子解除屏蔽并等待——防丢失信号。

一句话：SIGIO UDP = 信号驱动 + 数据报队列 + sigsuspend 同步——比 select 复杂。

信号排队不保证——多个数据报可能只产生一个 SIGIO，需在处理器中循环 recvfrom。

25.4

小结

study.md

章节核心提炼

1. 机制局限

  • 信号上下文切换开销
  • TCP 状态复杂 → 几乎仅适用于 UDP

2. 并发底线

单线程 + 异步信号处理函数 = 必须用 sigprocmask / sigsuspend 保护共享队列临界区。

3. 历史地位

传统 Unix 提升 UDP 接收的偏门手段；现代已被 epoll / kqueue 等事件驱动取代（无信号竞态）。

I/O 模型演进（Ch 6 → 25）

阻塞 → 非阻塞轮询 → select/poll → 信号驱动(UDP) → epoll/kqueue
TCP 服务器：select/epoll >> SIGIO

个人学习总结

信号驱动 I/O 用 SIGIO 通知 fd 就绪。适合 UDP，不适合 TCP。需要 O_ASYNC + F_SETOWN + 非阻塞。

竞态处理：sigprocmask 屏蔽 + sigsuspend 等待——防信号在处理 flag 前丢失。

现代替代：epoll 边缘触发（ET）= SIGIO 的进化——无需信号、无需屏蔽、更可控。

HFT 关联：不用 SIGIO——epoll ET 或 DPDK 轮询是现代选择。
