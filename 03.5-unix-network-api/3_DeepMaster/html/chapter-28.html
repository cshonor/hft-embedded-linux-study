28.1

概述

Ch 25 · 28.2 创建 · study.md

核心主旨

此前应用多在传输层（TCP/UDP/SCTP）。

原始套接字（Raw Socket）：越过传输层，直接与网络层（IPv4/IPv6）及 ICMP、IGMP 等交互。

应用场景

# 场景
1 ICMP/IGMP — ping、traceroute
2 自定义传输层协议（非 TCP/UDP 的 IP 协议号）
3 自构 IP 首部 — IP_HDRINCL（扫描、测试等，须合法授权）

局限预告

无法用普通 SOCK_RAW 截获本机 TCP/UDP 流量 → 须 Ch 29 数据链路层（BPF/libpcap）。

资料说明

上传资料截至第 8 章；第 28 章按 UNP 第 3 版体系整理，请与全本对照验证。

个人学习总结

原始套接字 SOCK_RAW — 绕过传输层，直接读写 IP 层数据包。需 root 权限。

用途：ping（ICMP）、traceroute（TTL 递增）、自定义协议、抓包。

一句话：raw socket = "自己构造 IP 头和传输层"——完全控制报文内容。

HFT 关联：HFT 不用 raw socket——DPDK 比 raw socket 更底层（链路层），且无需 root syscall 开销。

28.2

原始套接字创建

Ch 7.2 setsockopt

创建 API

int sockfd = socket(AF_INET, SOCK_RAW, protocol);
/* 或 AF_INET6 */
参数 说明
protocol IPPROTO_ICMP、IPPROTO_IGMP 或自定义协议号

特权限制（极重要）

仅 root（超级用户） 可创建 SOCK_RAW — 防伪造源 IP 等危险报文注入。

IP_HDRINCL

默认 内核自动拼接 IP 首部
IP_HDRINCL=1 应用自供完整 IP 首部（sendto 数据含 IP 头） 
setsockopt(sockfd, IPPROTO_IP, IP_HDRINCL, &on, sizeof(on));

个人学习总结

socket(AF_INET, SOCK_RAW, protocol) — 创建原始套接字。protocol 指定接收哪种协议（IPPROTO_ICMP、IPPROTO_TCP 等）。

IP_HDRINCL：setsockopt 设此选项 → 发送时包含自己构造的 IP 头；不设 → 内核填 IP 头。

一句话：IP_HDRINCL=1 时发送数据从 IP 头开始；=0 时从传输层开始，内核补 IP 头。

需 CAP_NET_RAW 或 root 权限才能创建 raw socket。

28.3

原始套接字输出

28.2 · Ch 3.4 字节序

未开启 IP_HDRINCL（默认）

应用提供 内核行为
数据 = IP 载荷 填 IP ID、长度、分片、校验和、TTL、选路发送

应用不能改源 IP 等 IP 层字段。

已开启 IP_HDRINCL

sendto 数据须含完整 IPv4 首部。

内核干预（跨平台不一致）：

字段 常见行为
ip_id 应用填 0 → 内核生成唯一值
ip_sum 内核重算校验和
源 IP 0 → 路由选外出接口 IP；显式指定 → 可能 IP 伪造（仅限授权测试）
ip_len / ip_off Berkeley：曾要求主机序；Linux 等多要求网络序 — 移植雷区

个人学习总结

发送：IP_HDRINCL=1 时自己填 IP 头（版本、长度、TTL、协议、校验和等）；=0 时内核填 IP 头，只填传输层数据。

一句话：IP_HDRINCL=1 → 完全自控 IP 包；=0 → 内核帮你填 IP 头。

校验和：IP 头校验和可填 0（内核计算）；TCP/UDP 校验和必须自己算（含伪首部）。

28.4

原始套接字输入

28.3 · Ch 29 链路层（待笔记）

内核上送原始套接字的 3 类报文

  1. 内核不认识的 IP 协议（如无模块的 OSPF 89 等）
  2. 多数 ICMP（Echo Request 等常由内核自处理，Echo Reply 等多上报）
  3. 所有 IGMP

绝不上送 TCP/UDP 分节 → 嗅探用 Ch 29 BPF/pcap。

匹配条件（AND）

多进程多 raw fd 时，复制到某套接字须全部满足：

# 条件
1 socket 时 protocol≠0 → 到达报文 IP 协议字段须匹配
2 bind 本地 IP → 目的 IP 须匹配
3 connect 远端 IP → 源 IP 须匹配

IPv4 vs IPv6 读取差异

IPv4 raw IPv6 raw
recvfrom 内容 含完整 IPv4 首部 不含 IPv6 首部和扩展头
应用解析 须跳过 IP 头（≥20 字节，有选项更长） 首字节即 ICMPv6 等上层

个人学习总结

接收：raw socket 收到匹配 protocol 的 IP 包副本——内核同时给 raw socket 和正常协议栈各一份。

过滤：内核收到 TCP/UDP 包会先检查是否有对应 raw socket 在监听该协议。

一句话：raw socket 收到的是含 IP 头的完整包——可以分析所有字段。

raw socket 收不到分片——只有重组后的完整包才递交给 raw socket。

28.5

ping 程序

28.2 · 28.4

机制

ping = ICMP 原始套接字应用。

方向 类型
发送 ICMP Echo Request（类型 8）
接收 ICMP Echo Reply（类型 0）

标识与序列号

字段 用法
Identifier 常填 PID，区分同机多个 ping
Sequence 递增
载荷 发送时写入时间戳，Reply 时算 RTT

接收过滤

原始套接字会收到本机所有 ICMP Echo Reply → 须核对 Identifier == 本进程 PID，否则丢弃。

个人学习总结

ping 实现：raw socket(IPPROTO_ICMP) → 构造 ICMP ECHO_REQUEST → sendto → recvfrom ECHO_REPLY → 计算 RTT。

一句话：ping = ICMP echo 请求-应答 + RTT 计算——raw socket 的经典应用。

ICMP 类型 8（请求）/ 0（应答）；标识符用 PID 区分多个 ping 实例。

28.6

traceroute 程序

Ch 7.6 IP 选项 · 28.4 ICMP 接收

核心机制

利用 TTL + ICMP 错误，非专用协议。

流程（经典 UDP 探测版）

1. 普通 UDP 套接字 → 目标高端口（33434+）
2. setsockopt(IP_TTL, 1) → sendto
3. 第一跳路由器：TTL→0 → ICMP Time Exceeded → raw ICMP 套接字收 → 源 IP = 第一跳
4. TTL=2,3,4,... 重复
5. 到达目标：端口无监听 → ICMP Port Unreachable → 追踪结束
组件 作用
UDP send 探测包
ICMP raw recv 读 Time Exceeded / Port Unreachable

现代变种

防火墙常拦 UDP 探测 → ICMP 或 TCP SYN 探测（tcptraceroute 等）。

💡 后续拓展留白
- tcptraceroute / Paris traceroute

个人学习总结

traceroute 实现：递增 TTL 发 UDP/TCP 包 → 每跳路由器返回 ICMP TIME_EXCEEDED → 到达目的返回 PORT_UNREACHABLE。

一句话：traceroute = TTL 递增 + ICMP 超时收集——逐跳绘制路由路径。

原理：TTL=1 到第一跳路由器被丢弃→ICMP 超时；TTL=2 到第二跳→以此类推。

28.7

一个 ICMP 消息守护程序

Ch 8.9 异步 ICMP · Ch 15 Unix 域（待笔记）

痛点

未 connect 的 UDP 套接字：异步 ICMP 错误（端口不可达等）常不传递给应用（Ch 8.9）→ 客户端盲目 recvfrom 超时。

icmpd 架构

1. 后台守护进程 icmpd
2. 原始 ICMP 套接字 — 捕获本机相关 ICMP 错误
3. ICMP 载荷含原 IP 头 + 原 UDP 头前 8 字节（含端口）
4. 解析本地源端口 → 经 Unix 域套接字等 IPC 推送给对应 UDP 应用

地位

在 UDP connect / 现代 API 普及前，将网络层错误桥接到应用层的经典模式。

个人学习总结

icmpd = 独立 ICMP 守护进程，统一接收所有 raw ICMP → 通过 Unix domain socket 将错误异步通知给 UDP/TCP 应用。

解决的问题：未 connect 的 UDP socket 收不到 ICMP 错误——icmpd 代收并转发。

一句话：icmpd = "ICMP 错误中转站"——让普通 socket 也能获知 ICMP 不可达等错误。

这是 Stevens 的设计模式——现代 Linux 内核已直接将 ICMP 错误传递给 connected UDP socket。

28.8

小结

study.md · Ch 29

章节核心提炼

1. 打破传输层壁垒

Raw socket → 用户态构造/处理 IP 层 — ping、traceroute、路由守护进程等基础设施。

2. 发送/接收细节

方向 要点
发 IP_HDRINCL、字节序移植、校验和/源 IP 内核规则
收 内核下放规则；IPv4 含 IP 头 vs IPv6 不含

3. 非万能

不能截获本机 TCP/UDP → Ch 29 链路层嗅探。

工具与 API 对照

工具 主要 API
ping ICMP raw
traceroute UDP + TTL + ICMP raw
tcpdump BPF / datalink（Ch 29）
icmpd ICMP raw + Unix 域 IPC

个人学习总结

raw socket = SOCK_RAW，需 root，可收发自定义 IP 包。经典应用：ping（ICMP echo）、traceroute（TTL 递增）。

IP_HDRINCL：控制发送时是否自填 IP 头。接收获得含 IP 头的完整包副本。

icmpd：Stevens 设计的 ICMP 错误中转守护进程——现代内核已内置此功能。

HFT 关联：raw socket 有 syscall 开销——DPDK 在链路层直接收发，比 raw socket 更底层更快。
