11.1

概述

阶段一收束：Ch 8 · 11.2 DNS · study.md

核心主旨与关键论据

此前程序依赖 点分十进制 IP + 数字端口；真实应用更常用 主机名、服务名。

本章目标：

能力 说明
名字 ↔ 地址 主机名、服务名与套接字地址互转
协议无关 同一代码同时支持 IPv4 / IPv6

逻辑脉络

旧范式：inet_addr + 硬编码端口 + sockaddr_in
新范式：getaddrinfo(hostname, service, hints, &res) → 遍历 ai_addr 链表
反向：getnameinfo(sockaddr, …) → 可读主机名/服务名

重点结论

  • 客户端解析连接：优先 getaddrinfo
  • 服务端展示对端：优先 getnameinfo
  • 避免：gethostbyname / gethostbyaddr（IPv4 局限、不可重入）

资料说明

上传资料正文截至第 8 章；第 11 章按全书目录与 UNP 第 3 版体系整理，请与教材对照验证。

个人学习总结

从"硬编码 IP+数字端口"升级到"主机名+服务名"解析，核心 API 是 getaddrinfo/getnameinfo，实现协议无关编程。

一句话：getaddrinfo 替代 gethostbyname + getservbyname，一个调用同时解析名字+服务+协议族。

现代 UNP 编程第一步：所有地址解析走 getaddrinfo，禁止用旧 API。

11.2

域名系统

11.1 · 11.6 getaddrinfo

核心定义

DNS（Domain Name System）：主机名 ↔ IP；亦可反向解析。

资源记录（RR）

类型 作用
A 主机名 → 32 位 IPv4
AAAA 主机名 → 128 位 IPv6（“quad A”）
PTR IP → 主机名（反向解析）
MX 域的邮件交换器
CNAME 别名 → 规范名（如 www、ftp）

解析器与名字服务器

应用 → getaddrinfo 等解析器 API
     → 读 /etc/resolv.conf 等
     → UDP/TCP 查询 DNS 服务器

个人学习总结

DNS 层次结构：根域 → TLD → 权威服务器。记录类型：A（IPv4）、AAAA（IPv6）、PTR（反向）、CNAME（别名）、MX（邮件）。

一句话：DNS 是分布式的、有缓存的、UDP 53 端口的查询系统。

调试工具：dig +short、nslookup、host；DNS 缓存可能影响 HFT 连接——启动时预解析。

11.3

gethostbyname 函数

11.4 gethostbyaddr · 替代：11.6

核心主旨

最早 POSIX 主机名解析 API：主机名 → IPv4。

struct hostent *gethostbyname(const char *hostname);
结果 说明
成功 hostent *
失败 NULL，查 h_errno

hostent 要点

  • h_aliases：别名数组
  • h_addr_list：多个 IPv4 地址指针（多宿）

易错细节与局限性

问题 说明
仅 IPv4 无协议无关性
线程不安全 返回静态 hostent，多线程易覆盖
现状 新代码应改用 getaddrinfo

个人学习总结

gethostbyname(name) — 旧 API，只支持 IPv4，返回静态结构体，不可重入。

禁用理由：①仅 IPv4 ②静态缓冲线程不安全 ③错误码用 h_errno 而非 errno。

替代：getaddrinfo 支持 IPv4/IPv6 + 线程安全 + 协议无关。

11.4

gethostbyaddr 函数

11.3 · 替代：11.17 getnameinfo

核心机制

与 gethostbyname 相反：IP 地址 → 主机名（反向解析）。

  • DNS 查 in-addr.arpa 域下的 PTR 记录

局限性

点 说明
IPv4 专有 同 gethostbyname
静态结构 不可重入（见 11.18）
现代替代 getnameinfo + NI_NUMERICHOST 等标志

个人学习总结

gethostbyaddr(addr, len, family) — 旧反向解析 API，同样不可重入、仅 IPv4。

一句话：地址→主机名用 getnameinfo 替代，支持 IPv4/IPv6 + 线程安全。

反向解析依赖 PTR 记录——可能未配置或延迟更新，不可依赖。

11.5

getservbyname 和 getservbyport 函数

11.6 getaddrinfo（服务名一并解析）

核心主旨

用 服务名（"ftp"、"http"）代替硬编码端口；双向映射。

函数 方向
getservbyname 服务名 + 协议（如 "udp"）→ servent（含端口）
getservbyport 网络字节序端口 + 协议 → 服务名

底层机制

通常读本地 /etc/services。

易错细节

  • getservbyport 的端口必须是网络字节序
  • 现代代码：在 getaddrinfo 的 service 参数 直接传 "http" 或 "80"

个人学习总结

getservbyname("http", "tcp") → 端口号；查 /etc/services 文件。

一句话：服务名↔端口映射，被 getaddrinfo 的 service 参数取代。

现代 API 直接传 "80" 或 "http" 给 getaddrinfo，无需单独调 getservbyname。

11.6

getaddrinfo 函数

本章核心 · 11.7 · 11.8 · 11.12 tcp_connect

核心主旨

现代解析基石：主机名→IP + 服务名→端口，返回可直接用于 socket/connect/bind 的 addrinfo 链表；IPv4/IPv6 协议无关。

int getaddrinfo(const char *hostname, const char *service,
                const struct addrinfo *hints, struct addrinfo **result);

参数要点

参数 说明
hostname 主机名、点分 IP，或 NULL（配合 AI_PASSIVE）
service 服务名（"http"）或端口字符串（"80"）
hints 调用者期望的套接字类型（极关键）
result 输出链表头

hints 常用字段

字段 典型值
ai_family AF_INET / AF_INET6 / AF_UNSPEC
ai_socktype SOCK_STREAM / SOCK_DGRAM
ai_flags AI_PASSIVE（bind 用通配地址）

result 节点

每个节点含 ai_addr/ai_addrlen，可直接传给套接字 API。

重点结论（防错实践）

for (rp = res; rp; rp = rp->ai_next) {
    fd = socket(rp->ai_family, rp->ai_socktype, rp->ai_protocol);
    if (connect(fd, rp->ai_addr, rp->ai_addrlen) == 0)
        break;   /* 成功 */
    close(fd);
}
freeaddrinfo(res);

业务代码不必手写 sockaddr_in / sockaddr_in6 — 遍历链表直到 connect/bind 成功。

个人学习总结

核心 API：getaddrinfo(host, service, &hints, &res) → 返回 addrinfo 链表，每项含已就绪的 sockaddr。

hints 关键字段：ai_family（AF_INET/AF_INET6/AF_UNSPEC）、ai_socktype（SOCK_STREAM/DGRAM）、ai_flags（AI_PASSIVE 服务器端、AI_V4MAPPED）。

一句话：getaddrinfo 把"名字→地址+端口+协议族"一步到位，遍历 res 链表逐个尝试 connect/bind。

协议无关编程的基石——同代码支持 IPv4/IPv6。

11.7

gai_strerror 函数

11.6 getaddrinfo

错误处理机制

getaddrinfo 不设置 errno / h_errno，以非零返回值表示错误。

const char *gai_strerror(int ecode);

将 EAI_AGAIN、EAI_NONAME 等转为可读字符串。

易错细节

  • 勿用 strerror(errno) 解释 getaddrinfo 失败
  • 与 freeaddrinfo 配对：失败时若已分配 result 仍须释放（视实现；失败时常 result==NULL）

个人学习总结

gai_strerror(error) — getaddrinfo 错误码转字符串，替代 h_errno。

一句话：getaddrinfo 失败返回非零错误码（非 -1），用 gai_strerror 打印。

错误码和 errno 不同体系——不能 perror，必须 gai_strerror。

11.8

freeaddrinfo 函数

11.6

内存管理规则

getaddrinfo 分配的 addrinfo 链表及其中 sockaddr 均为 malloc。

void freeaddrinfo(struct addrinfo *ai);

易错细节（内存泄漏）

用完链表（已 connect/bind 成功或全部失败）后必须 freeaddrinfo，否则长驻服务器会泄漏。

个人学习总结

freeaddrinfo(res) — 释放 getaddrinfo 返回的链表。

一句话：getaddrinfo 分配内存，用完必须 freeaddrinfo 释放——否则内存泄漏。

用法：遍历完链表后一次性 freeaddrinfo(res)，不要逐项 free。

11.9

getaddrinfo 函数：IPv6

11.6 · 11.10 例子

协议混合逻辑

hints.ai_family = AF_UNSPEC 时，解析器可能同时返回 IPv4 与 IPv6 节点。

重要 flags

标志 作用
AI_V4MAPPED 仅 A 记录、但请求 AF_INET6 时，返回 IPv4-mapped IPv6（如 ::ffff:x.x.x.x）
AI_ALL 与上组合：正常 IPv6 + 将 IPv4 也作 mapped 形式一并返回

易错细节

  • 勿混淆 纯 IPv4 地址 与 v4-mapped v6 地址 的 sockaddr 长度与 ai_family
  • 遍历链表时按节点的 ai_family 建套接字，勿假设单一族

个人学习总结

IPv6 相关 hints flags：AI_V4MAPPED（IPv6 socket 映射 IPv4）、AI_ALL（配合 V4MAPPED 返回全部）、AI_ADDRCONFIG（仅有相应地址时才返回）。

一句话：AI_V4MAPPED 让 IPv6-only 代码也能连 IPv4 服务器——内核做 v4-mapped 地址转换。

双栈服务器：设 AI_PASSIVE + AF_UNSPEC，getaddrinfo 返回 IPv6 sockaddr（含 mapped v4）。

11.10

getaddrinfo 函数：例子

11.6 · 11.11 host_serv

案例 1：客户端

项 值
hostname "www.kame.net"
service "http"
hints AF_UNSPEC, SOCK_STREAM

结果：该主机所有 IPv4/IPv6 地址链表，端口均为 80。

案例 2：服务器 bind

项 值
hostname NULL
service "ftp"
hints AI_PASSIVE, SOCK_STREAM

结果：通配地址（IPv4 0.0.0.0 或 IPv6 ::），端口 21，供 bind。

逻辑脉络

客户端：有名主机 + 服务名 → 多地址 connect 尝试
服务端：NULL + AI_PASSIVE → 监听所有接口

个人学习总结

getaddrinfo 实战示例：客户端遍历 res 尝试 connect，服务器用 AI_PASSIVE 遍历 res 尝试 bind。

客户端模式：for (res) { socket → connect → break }，第一个成功就用。

服务器模式：for (res) { socket → setsockopt(REUSEADDR) → bind → break }。

这是协议无关 C/S 的标准模板——记住这个循环结构。

11.12

tcp_connect 函数

11.6 · TCP：Ch 4

核心主旨

协议无关的 TCP 客户端连接封装。

getaddrinfo → for 遍历链表:
    socket → connect
    成功 → break 返回 fd
    失败 → close(fd)，试下一节点
freeaddrinfo（在封装内或调用方）

实用要点

  • 屏蔽目标 多 IP / v4+v6 混合
  • 实现透明 故障转移（Failover）
  • 第一个 connect 失败不致命，继续试链表

易错细节

  • 循环内失败须 close 当前套接字，避免 fd 泄漏
  • 全部失败后返回错误，勿返回未连接 fd

个人学习总结

tcp_connect(host, service) — Stevens 封装：getaddrinfo + 遍历 connect，返回已连接 sockfd。

一句话：tcp_connect = 协议无关的 connect——调用者不需要关心 IPv4/IPv6。

客户端连接标准封装，替代手动 socket+connect+inet_pton。

11.13

tcp_listen 函数

11.12 · SO_REUSEADDR：Ch 7.5

核心主旨

协议无关的 TCP 监听套接字封装。

getaddrinfo（AI_PASSIVE）→ for:
    socket → setsockopt(SO_REUSEADDR) → bind → listen
    任一成功 → 返回 listenfd
    bind 失败 → close(fd)，下一节点

易错细节

点 说明
bind 失败 必须先 close 再试下一地址
多地址 可能只需一个 listenfd 绑定通配或某一接口
v6-only 栈 链表内容与系统策略有关

个人学习总结

tcp_listen(host, service, &addrlen) — Stevens 封装：getaddrinfo(AI_PASSIVE) + 遍历 bind+listen，返回 listenfd。

一句话：tcp_listen = 协议无关的服务器监听——自动设 SO_REUSEADDR。

服务器端标准封装，替代手动 socket+bind+listen。host 传 NULL = INADDR_ANY。

    socket（不 connect）
    成功 → 返回 sockfd + 目标 sockaddr*（供 sendto）

与 TCP 版区别：不调用 connect，保留无连接 sendto 模型。

11.15

udp_connect 函数

Ch 8.11 UDP connect · 11.14

核心主旨

在 11.14 逻辑上增加 connect → 已连接 UDP 套接字。

收益 说明
API 后续 write/read
安全 内核过滤非绑定源
错误 ICMP 异步错误可上报（如 ECONNREFUSED）

udp_connect(host, service) — 封装：getaddrinfo + connect（UDP connect 不发握手，只绑定对端）。

UDP connect 的好处：收 ICMP 异步错误 + 内核做源地址过滤。

11.17

getnameinfo 函数

11.6 getaddrinfo · 替代 11.4

核心主旨

getaddrinfo 的互补：sockaddr → 可读 主机名 + 服务名字符串；IPv4/IPv6 协议无关。

替代 gethostbyaddr + getservbyport。

常用 flags

标志 作用
NI_NUMERICHOST 只返回数字 IP，不做 DNS 反向解析（避免慢/超时）
NI_NUMERICSERV 只返回数字端口，不查 /etc/services
NI_DGRAM 指明 UDP（同端口 TCP/UDP 服务名可能不同）

易错细节

  • 日志/调试常用 NI_NUMERICHOST 避免阻塞
  • 缓冲区长度须满足 NI_MAXHOST / NI_MAXSERV

个人学习总结

getnameinfo(sa, salen, host, hostlen, serv, servlen, flags) — sockaddr → 主机名+服务名（getaddrinfo 的逆操作）。

flags：NI_NUMERICHOST（返回 IP 而非域名，免 DNS 查询）、NI_NUMERICSERV（返回端口号）。

一句话：getnameinfo 替代 gethostbyaddr，支持 IPv4/IPv6 + 线程安全。

调试打印对端地址时用 NI_NUMERICHOST 避免阻塞 DNS 反查。

11.18

可重入函数

11.3 · 11.19 _r 版

核心概念

历史函数（gethostbyname、inet_ntoa 等）在并发下的致命缺陷：不可重入。

根源

函数用 静态内存 存放结果并返回指针 → 多线程 数据竞争：

线程 A 调用 → 结果写入静态区
上下文切换 → 线程 B 调用 → 覆盖
线程 A 再读 → 数据错误

解决方案（三层）

层级 做法
1 系统 _r 可重入扩展（11.19）
2 互斥锁 / 线程特定数据 TLS
3 推荐：getaddrinfo / getnameinfo（调用方分配缓冲区）

重点结论

新代码：全面换用 getaddrinfo 族，天然线程安全。

个人学习总结

旧 API（gethostbyname/addr、inet_ntoa）使用静态缓冲 → 多线程不安全。

可重入方案：getaddrinfo/getnameinfo（自带缓冲）、inet_ntop（调用者传缓冲）、_r 变体（gethostbyname_r）。

一句话：多线程环境禁用所有返回静态缓冲的函数——用 getaddrinfo 或 _r 变体。

HFT 关联：多线程网络程序中这是必须检查的——静态缓冲导致间歇性数据覆盖。

11.19

gethostbyname_r 和 gethostbyaddr_r 函数

11.18

历史补救

带 _r（Reentrant） 后缀：调用者提供 缓冲区 与长度，结果写入调用方内存，避免静态区竞争。

现状

问题 说明
参数不一致 Linux 与 Solaris 等 _r 原型不同
可移植性差 难以写跨平台代码
最佳实践 弃用，改用 getaddrinfo

个人学习总结

gethostbyname_r / gethostbyaddr_r — 旧 API 的可重入版本，调用者提供缓冲区。

一句话：_r 变体是过渡方案——新代码直接用 getaddrinfo/getnameinfo，不需要 _r。

不同 OS 的 _r 签名不同（Linux vs Solaris），可移植性差。

11.20

作废的 IPv6 地址解析函数

历史演进备忘

IPv6 草案期曾出现、后被废弃：

函数 说明
gethostbyname2 在 gethostbyname 上增加地址族参数
getipnodebyname / getipnodebyaddr 动态分配、试图可重入 + IPv6，接口笨重

RFC 3493 以 getaddrinfo / getnameinfo 取代。

重点结论

阅读旧代码时识别这些符号；新代码勿用。

个人学习总结

历史遗留的 IPv6 地址转换宏（inet6_option_ 等），已被 RFC 3542 的 inet6_opt_ 取代。

一句话：全部作废——IPv6 选项处理用 RFC 3542 API（inet6_opt_/inet6_rth_）。

了解即可，不需要实际使用这些旧宏。

11.21

其他网络相关信息

辅助数据库

除主机/服务外，Unix 还有：

数据库 文件 函数
网络名 /etc/networks getnetbyname / getnetbyaddr
协议名 /etc/protocols getprotobyname / getprotobynumber

协议号示例：tcp=6, udp=17, icmp=1 — 创建原始套接字时常用。

与 getaddrinfo 关系

日常 TCP/UDP 应用以 getaddrinfo 的 service 参数 为主；协议数据库多用于底层或特殊套接字。

个人学习总结

getnetbyname/getnetbyaddr（网络信息）、getprotobyname/getprotobynumber（协议信息）——查 /etc/networks 和 /etc/protocols。

一句话：这些 API 极少使用——了解存在即可。

实际工程中直接用数字常量（IPPROTO_TCP=6）而非名字查询。
