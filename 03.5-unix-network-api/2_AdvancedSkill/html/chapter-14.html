14.2

套接字超时

Ch 6 select · Ch 7.5 SO_RCVTIMEO · Ch 8.7 UDP 丢包

核心机制

网络 I/O 不能无限阻塞（崩溃服务器、黑洞路由、UDP 丢包等）。

三种超时技术（截然不同）：

1. alarm + SIGALRM

alarm(sec) → 阻塞 read/connect → 超时则 SIGALRM → 系统调用 EINTR
易错 说明
信号复杂 多线程掩码、与既有 alarm 冲突
可重入 须在慢系统调用中正确处理 EINTR

2. select / poll 超时（最通用、最安全）

select 带 timeout → 可读/可写再 read/write/connect
  • 适用于 read/write 与 非阻塞 connect 超时
  • 与 Ch 6、Ch 8.7 一脉相承

3. SO_RCVTIMEO / SO_SNDTIMEO

  • setsockopt 绑定 timeval 到套接字
  • 超时后 read/recv 等返回 -1，errno = **EWOULDBLOCK**（非 EINTR）
  • 不能限制 connect（POSIX；部分系统有非标准扩展）

重点结论

场景 推荐
通用、含 connect select/poll
单套接字简单读超时 SO_RCVTIMEO
遗留/简单程序 alarm（慎用）

💡 后续拓展留白
- read_timeout / connect_timeout 封装模板

个人学习总结

套接字超时三种方法：①alarm + SIGALRM（有竞态）②select/poll 设置超时（推荐）③SO_RCVTIMEO/SO_SNDTIMEO（最简洁）。

一句话：优先用 SO_RCVTIMEO——内核级超时，返回 EWOULDBLOCK，无信号竞态。

alarm 的问题：信号可能与系统调用竞态——pselect 可解决但更复杂。

14.3

recv 和 send 函数

Ch 8.11 已连接 UDP · Ch 3.9 readn

核心主旨

类似 read/write，但仅用于套接字，多 flags 参数。

ssize_t recv(int sockfd, void *buff, size_t nbytes, int flags);
ssize_t send(int sockfd, const void *buff, size_t nbytes, int flags);

常用 flags

标志 方向 作用
MSG_DONTROUTE send 绕过路由（直连网段；RIP/诊断）
MSG_DONTWAIT 两者 单次非阻塞，不改 fcntl
MSG_OOB 两者 带外数据（Ch 24）
MSG_PEEK recv 窥看缓冲区，不移除数据
MSG_WAITALL recv 尽量读满 nbytes（类 readn）

易错细节

  • MSG_WAITALL：遇信号、断开、错误仍可能 短读
  • MSG_PEEK + 再 read = 两次系统调用（见 14.7）

个人学习总结

recv(fd, buf, len, flags) / send(fd, buf, len, flags) — 比 read/write 多 flags 参数。

高频 flags：MSG_PEEK（窥探不消费）、MSG_DONTWAIT（临时非阻塞）、MSG_WAITALL（等满 n 字节）、MSG_OOB（带外数据）。

一句话：MSG_WAITALL 替代 readn——内核帮你循环读，减少用户态循环。

14.4

readv 和 writev 函数

Ch 7.9 TCP_NODELAY

核心机制

术语 含义
聚集写（Gather Write） 多缓冲区 → 一次系统调用写出
分散读（Scatter Read） 一次读入 → 填入多个缓冲区 
ssize_t readv(int filedes, const struct iovec *iov, int iovcnt);
ssize_t writev(int filedes, const struct iovec *iov, int iovcnt);

struct iovec { void *iov_base; size_t iov_len; };

实用场景：HTTP 响应

方案 问题
两次 write 两次系统调用；Nagle 下可能多包延迟
memcpy 拼一大块再 write CPU/内存拷贝浪费
writev 内核组装进同一 TCP 段，原子性、开销小

个人学习总结

readv(fd, iov, iovcnt) / writev(fd, iov, iovcnt) — 一次系统调用读写多个不连续缓冲区（聚集/分散 I/O）。

一句话：writev 把"HTTP 头 + HTTP 体"一次 write——减少 syscall 次数。

HFT 关联：减少 syscall = 减少上下文切换 = 降低延迟。发送行情包时用 writev 拼接多个字段。

14.5

recvmsg 和 sendmsg 函数

14.6 辅助数据 · Ch 8 recvfrom

核心主旨

Unix 网络 API 中最通用的 I/O：涵盖 read/write、recv/send、recvfrom/sendto、readv/writev，并支持辅助数据。

msghdr 结构

struct msghdr {
  void         *msg_name;       /* 地址（无连接套接字，同 recvfrom 的 from） */
  socklen_t     msg_namelen;
  struct iovec *msg_iov;        /* iovec 数组 */
  int           msg_iovlen;
  void         *msg_control;    /* 辅助数据缓冲区 */
  socklen_t     msg_controllen;
  int           msg_flags;      /* recvmsg：由内核填写 */
};

msg_flags 机制（易错）

API flags 传递
recv 参数按值传入内核
recvmsg 调用参数指定控制标志；msg_flags 由内核返回

内核可设 msg_flags 示例：

标志 含义
MSG_TRUNC UDP 报文被截断
MSG_CTRUNC 辅助数据被截断
MSG_BCAST / MSG_MCAST 链路层广播/多播收到

个人学习总结

recvmsg/sendmsg — 最通用的 socket I/O，一次调用可同时：收数据 + 对端地址 + 辅助数据（cmsghdr）。

msghdr 结构：msg_iov（数据缓冲向量）+ msg_name（对端地址）+ msg_control（辅助数据）。

一句话：recvmsg = recvfrom + readv + 辅助数据，一步到位。

14.6

辅助数据

14.5 recvmsg · Ch 15.7 传递 fd（待学）

核心概念

辅助数据（Ancillary Data）：负载之外的元信息，经 msg_control 传递。

格式：一个或多个 cmsghdr + 数据，严格对齐。

五个宏（必须用，禁止手算偏移）

宏 作用
CMSG_FIRSTHDR(&mhdr) 第一个 cmsghdr
CMSG_NXTHDR(&mhdr, cmsg) 下一个
CMSG_DATA(cmsg) 数据区起始指针
CMSG_LEN(length) 本条长度（含头+数据，不含尾部填充）
CMSG_SPACE(length) 分配本条所需总空间（含对齐填充）

典型应用

场景 选项/协议
UDP 目的地址 IPv4 IP_RECVDSTADDR；IPv6 IPV6_PKTINFO
接收接口索引 随 pktinfo
传递打开的文件描述符 Unix 域套接字（Ch 15）
进程凭证 Unix 域 credentials

易错细节

  • 32/64 位对齐不同 → 手工指针加减必错
  • msg_controllen 不足 → MSG_CTRUNC

个人学习总结

辅助数据（cmsghdr）通过 recvmsg/sendmsg 传递带外信息：SCM_RIGHTS（传 fd）、IP_PKTINFO（收包目的 IP）、IP_TTL、IPv6 扩展头。

操作宏：CMSG_FIRSTHDR / CMSG_NXTHDR / CMSG_DATA / CMSG_SPACE / CMSG_LEN。

一句话：SCM_RIGHTS 通过 Unix domain socket 传 fd——Ch15 的核心机制。

HFT 关联：SCM_RIGHTS 用于进程间共享 mmap 内存或 socket fd。

14.7

排队的数据量

Ch 16 非阻塞 · 14.3 MSG_PEEK

实用痛点

想知道接收缓冲区有多少字节可读，且不被阻塞。

三种技术

# 方法 说明
1 非阻塞 I/O fcntl 设非阻塞 → read；无数据则 EWOULDBLOCK
2 MSG_PEEK 有数据则复制返回但不消费；两次系统调用（peek + read），慢
3 ioctl(FIONREAD) 立即返回，第三参数填入排队字节数

重点结论

高性能路径优先 FIONREAD 或 非阻塞试探；避免依赖 MSG_PEEK 双调用。

个人学习总结

ioctl(fd, FIONREAD, &n) — 查看套接字接收缓冲区待读字节数，不消费数据。

一句话：FIONREAD 读前置探测——知道有多少数据可读再分配缓冲区。

MSG_PEEK 也能窥探但只看一个包；FIONREAD 看全部缓冲。

14.8

套接字和标准 I/O

Ch 6 select · Ch 4.9 close/shutdown

核心主旨

可用 fdopen 把套接字变成 FILE * 用 printf/fgets — 在套接字编程中通常是灾难。

四大死穴

# 问题
1 读写转换：同一 FILE * 上先读后写须 fflush/fseek 等
2 缓冲不可见：数据在用户态 stdio 缓冲里时，select/poll 看不见 → 死锁
3 全缓冲：套接字默认全缓冲，未 fflush 则不发往网络，握手中断
4 半关闭：难精确 shutdown，缓冲残留丢数据

重点结论

普通网络通信 + select/poll 多路复用：

严禁混用 stdio 与底层多路复用 — 用 read/write/recv/send 并自管用户缓冲。

💡 后续拓展留白
- setvbuf 取消缓冲仍不如原生 API 的场景分析

个人学习总结

禁止混用套接字 read/write 和 stdio（fdopen/fgets/fputs）——stdio 有内部缓冲，与 select 配合会导致数据"已读但未消费"。

一句话：socket 要么全用 read/write，要么全用 stdio——不能混。

经典 bug：fgets 消费了数据但留在 stdio 缓冲 → select 不再报就绪 → 死锁。

14.9

高级轮询技术

Ch 6 select/poll

核心背景（C10K）

select/poll 每次 O(N) 扫描全部描述符，连接上万时成为瓶颈。

原书第 3 版重点

/dev/poll（Solaris）

open /dev/poll → write 注册 fd → ioctl(DP_POLL) 阻塞
→ 只返回就绪 fd，无需每次传巨大 fd_set

kqueue（FreeBSD）

kqueue() 创建队列 → kevent() 注册/取事件（struct kevent）
  • 不限套接字：文件变更、进程退出、信号等
  • 性能约 O(活跃事件)

时代补充（对照现代 Linux）

API 要点
epoll Nginx/Redis 常用；LT 水平触发 vs ET 边缘触发
共性 避免线性扫描全表 fd

个人学习总结

高级 I/O 多路复用：kqueue（BSD）、/dev/poll（Solaris）、epoll（Linux）。

epoll 优势：O(1) 就绪列表——不像 select/poll 每次 O(N) 扫描全部 fd。

三步：epoll_create → epoll_ctl(ADD/MOD/DEL) → epoll_wait。

HFT 关联：epoll + 非阻塞 I/O 是 Linux 高并发标准模型；DPDK 连 epoll 都绕过，直接轮询。

14.10

T/TCP：事务目的 TCP

历史背景

事务型请求（如 DNS 少量数据）用常规 TCP 过重：三次握手 + 四次挥手。

T/TCP 机制（已淘汰）

  • 缓存主机状态，在 SYN 中捎带数据，缩短延迟

现状结论

问题 说明
重放攻击 安全漏洞
实施复杂 业界废弃

现代替代：HTTP Keep-Alive、QUIC（UDP 快速握手）、SCTP 等。

个人学习总结

T/TCP（TCP for Transactions）——历史扩展，用三段报文完成 connect+数据+FIN，减少 RTT。

一句话：T/TCP 已被 RFC 废弃——现代用 TCP Fast Open（TFO）替代，原理类似。

了解即可，实际工程中几乎不会遇到 T/TCP。

14.11

小结

study.md

章节核心提炼

1. 超时体系

select/poll + 超时 最通用；SO_RCVTIMEO 简单读超时；alarm 慎用。

2. 底层接口终点

recvmsg/sendmsg + msghdr + cmsghdr 宏 — 多播寻址、fd 传递（见 Ch 15.7）、目的 IP 等高级能力。

3. 缓冲敬畏

  • writev 聚集写，少拷贝、少 syscall
  • 勿 stdio + select — 亲手掌控字节流
  • 高并发：kqueue / epoll 等事件驱动

能力阶梯

read/write → recv/send(flags) → readv/writev → recvmsg/sendmsg(+辅助数据)
复用：select/poll → epoll/kqueue/devpoll

个人学习总结

高级 I/O 五件套：超时（SO_RCVTIMEO）、recv/send flags、readv/writev（减少 syscall）、recvmsg/sendmsg（辅助数据）、epoll（O(1) 多路复用）。

禁令：勿混用 stdio 和 socket I/O——缓冲冲突导致死锁。

HFT 关联：writev 减少 syscall + epoll 减少轮询开销 = 双重降延迟。
