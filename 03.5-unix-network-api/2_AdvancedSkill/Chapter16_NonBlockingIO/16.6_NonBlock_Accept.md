# 16.6 非阻塞 accept

> [Ch 4.6 accept](../../1_BasicFoundation/Chapter04_BasicTCPSocket/4.6_Accept_Function.md) · [Ch 6.8 TCP 服修订](../../1_BasicFoundation/Chapter06_IO_Select_Poll/6.8_TCP_Server_Revised.md)

---

## 核心主旨

即使用非阻塞读写，**监听套接字也必须非阻塞 accept** — 否则存在隐蔽死锁。

---

## 致命时序：被中止的连接（Aborted Connection）

```text
1. 客户端 SYN 完成 → 进入已完成连接队列
2. select：listenfd 可读 → 唤醒服务器
3. 缝隙：客户端发 RST（进程被杀、SO_LINGER 等）
4. Berkeley 类实现：内核从队列中**悄悄移除**该连接
5. 服务器调用**阻塞** accept → 队列已空 → **永久睡眠**
6. 单线程服务器挂死，其他就绪 fd 永不处理
```

---

## 黄金法则

`select`/`poll` 处理 **listenfd** 时：

**必须 `O_NONBLOCK` on listen socket**

- 队列为空时 `accept` → **EWOULDBLOCK**  
- 应用**忽略**该错误，回到 `select` 主循环  

---

## 重点结论

非阻塞 **accept** 是应对 select 就绪与内核队列变化之间 **竞态** 的**强制防御**，高可用网关的底线。
