# 5.7 `readv` / `writev` — 散布/聚集 I/O

## 本节讲什么

`readv`/`writev` 用**一次系统调用**读写**多个不连续缓冲区**。本节回答三个问题：

1. `struct iovec` 是什么？「散布读（scatter）/ 聚集写（gather）」分别指什么？
2. 内核怎么把用户态的 `iovec` 数组变成一次 I/O？
3. 相比循环多次 `read`/`write`，`readv`/`writev` 的优势和原子性边界在哪？

---

## 1. 原型与内核链路

```c
#include <sys/uio.h>
struct iovec {
    void  *iov_base;   /* 缓冲区起始地址 */
    size_t iov_len;    /* 缓冲区长度 */
};

ssize_t readv(int fd, const struct iovec *iov, int iovcnt);
ssize_t writev(int fd, const struct iovec *iov, int iovcnt);
```

- **散布读（scatter read）**：`readv` 把一段连续数据**分散**到多个缓冲区。
- **聚集写（gather write）**：`writev` 把多个缓冲区的数据**聚集**成一段连续写出。

```
用户态 writev(fd, iov, 3)
      ▼
SYSCALL_DEFINE3(writev)              fs/read_write.c:1046
      ▼
do_writev(fd, vec, vlen, 0)          fs/read_write.c:964
      ├─ fdget_pos(fd)               ← 取 struct file + 偏移
      ├─ file_ppos()                 ← 取 f_pos 指针
      └─ vfs_writev(file, vec, vlen, ppos, flags)   fs/read_write.c:922
           ├─ import_iovec(ITER_SOURCE, vec, ...)   ← 把用户 iovec 拷进内核
           │     构造 iov_iter（统一迭代器）
           └─ do_iter_writev / call_write_iter    ← 一次写完所有段
```

`import_iovec`（`fs/read_write.c:913/:930`）是关键：它把用户态的 `iovec` 数组拷贝到内核，构造一个 `struct iov_iter`，之后底层 I/O 用统一的迭代器接口遍历所有段，**一次系统调用完成多段传输**。

## 2. 用法示例

```c
struct iovec iov[3];
iov[0].iov_base = buf0; iov[0].iov_len = 100;
iov[1].iov_base = buf1; iov[1].iov_len = 200;
iov[2].iov_base = buf2; iov[2].iov_len = 50;

ssize_t n = writev(fd, iov, 3);   /* 一次聚集写出 350 字节 */
```

## 3. 优势与原子性边界

| 优势 | 说明 |
|------|------|
| 减少 syscall | 1 次 `writev` 替代 N 次 `write`，降低用户态/内核态切换开销 |
| 单次操作完整性 | 一次 `writev` 传输的数据块，对普通文件而言不会被其他进程的 `write` 从中间交错（单次调用原子） |
| 协议友好 | 固定头 + 变长体（header + payload）一次写出，天然对应协议帧格式 |

> ⚠️ 原子性边界：`writev` 的原子性是「单次调用内不与其他 `write` 交错」，但**返回值仍可能小于所有 `iov_len` 之和**（部分写/短读，需按返回值判断实际传了多少）。它**不保证**「要么全写、要么不写」。

## 4. HFT / 嵌入式关联

| 场景 | 本节机制的兑现 |
|------|----------------|
| 协议帧组装 | `writev` 一次写出「帧头 + 载荷」，避免拼大缓冲区的内存拷贝 |
| 行情消息分发 | `readv` 一次读入 header + body 到不同缓冲区，省去解析时的手工切分 |
| 减少上下文切换 | HFT 热点路径上少一次 syscall 就是少一次陷入内核的延迟 |
| 与 `sendmsg`/`recvmsg` 同源 | socket 的 `sendmsg`/`recvmsg` 内部也用 `iovec`/`iov_iter`（见 Ch56-61） |

## 5. 代码示例

```c
#include <stdio.h>
#include <string.h>
#include <fcntl.h>
#include <sys/uio.h>
#include <unistd.h>

/* writev: 一次聚集写出 header + body */
int main(void) {
    int fd = open("/tmp/msg.bin", O_WRONLY | O_CREAT | O_TRUNC, 0644);

    const char *header = "HDR:";         /* 帧头 */
    const char *body   = "payload-data"; /* 载荷 */

    struct iovec iov[2];
    iov[0].iov_base = (void *)header;  iov[0].iov_len = strlen(header);
    iov[1].iov_base = (void *)body;    iov[1].iov_len = strlen(body);

    ssize_t n = writev(fd, iov, 2);    /* 一次写出两段 */
    printf("writev 写了 %zd 字节\n", n);

    close(fd);
    return 0;
}
```

<details>
<summary>代码自测（Q&A）</summary>

**Q1：`readv`/`writev` 的作用是什么？「scatter」和「gather」分别指？**
A：`readv` 把连续数据**分散（scatter）**到多个缓冲区，`writev` 把多个缓冲区**聚集（gather）**成一次写出。两者都用一次系统调用处理多个 `struct iovec`，减少 syscall 次数。

**Q2：`struct iovec` 里两个字段分别是什么？**
A：`iov_base` 是缓冲区起始地址（`void *`），`iov_len` 是缓冲区长度（`size_t`）。`readv`/`writev` 接收 `iovec` 数组 + 数组长度 `iovcnt`。

**Q3：`writev` 相比循环多次 `write` 的优势？**
A：① 少 syscall（1 次 vs N 次），降低用户/内核切换开销；② 一次调用传输的数据块不会被其他进程的 `write` 从中间交错；③ 天然适配「固定头 + 变长体」的协议帧，省去手工拼接缓冲区的内存拷贝。

**Q4：`writev` 保证「要么全写、要么不写」吗？**
A：不保证。`writev` 的原子性是「单次调用内不与其他 `write` 交错」，但返回值仍可能小于所有 `iov_len` 之和（部分写）。必须检查返回值判断实际传输量，需要时循环补写。

**Q5：内核是怎么把用户态的 `iovec` 数组变成一次 I/O 的？**
A：`vfs_readv`/`vfs_writev`（`fs/read_write.c:905/:922`）调用 `import_iovec` 把用户态 `iovec` 数组拷贝到内核，构造 `struct iov_iter` 统一迭代器，然后底层用 `call_read_iter`/`call_write_iter` 遍历所有段一次完成传输。`iov_iter` 是内核统一的多缓冲迭代抽象。

</details>
