### fcntl 命令

| cmd | 功能 | 说明 |
|-----|------|------|
| `F_DUPFD` | 复制 fd | 返回 >= arg 的最小可用 fd |
| `F_DUPFD_CLOEXEC` | 复制 fd + CLOEXEC | 同上，设置 O_CLOEXEC |
| `F_GETFD` | 获取 fd 标志 | 仅 `FD_CLOEXEC` |
| `F_SETFD` | 设置 fd 标志 | 设置 `FD_CLOEXEC` |
| `F_GETFL` | 获取文件状态标志 | O_RDONLY/O_NONBLOCK/O_APPEND 等 |
| `F_SETFL` | 设置文件状态标志 | 只能改 O_APPEND/O_NONBLOCK/O_ASYNC/O_DIRECT |
| `F_GETLK` | 获取文件锁 | 参见 Ch55 |
| `F_SETLK` | 设置文件锁 | 参见 Ch55 |

### 三层结构模型

```
进程 fd 表          内核打开文件表          inode 表
[0] → stdin        ┌──────────┐         ┌──────────┐
[1] → stdout   ┌──→│ pos=100  │    ┌───→│ inode #5 │
[2] → stderr   │   │ flags    │    │   │ size=1KB │
[3] ──────────┘   │ O_WRONLY │    │   │ blocks   │
[4] ──────────────→│ pos=50   │────┘   └──────────┘
                   │ O_RDONLY │
                   └──────────┘
```

- `dup2(3, 4)` 后 fd 3 和 4 指向**同一个**打开文件表项（共享偏移量）
- `open()` 两次返回不同 fd，指向**不同**的打开文件表项（独立偏移量）

### 原子操作对比

| 操作 | 非原子方式 | 原子方式 | 竞争风险 |
|------|-----------|---------|---------|
| 创建文件 | `access()` + `open(O_CREAT)` | `open(O_CREAT\|O_EXCL)` | TOCTOU |
| 追加写入 | `lseek(SEEK_END)` + `write()` | `open(O_APPEND)` | 偏移量竞争 |
| 定位读写 | `lseek()` + `read()` | `pread()` | 偏移量被其他线程修改 |

### pread/pwrite vs lseek+read/write

| 特性 | lseek+read/write | pread/pwrite |
|------|-----------------|-------------|
| 偏移量 | 修改 fd 偏移量 | 不修改 |
| 线程安全 | 否（共享偏移量） | 是 |
| 系统调用次数 | 2 次 | 1 次 |
| 原子性 | 无 | 有 |

## HFT / 嵌入式关联

- **多线程日志**：`pread`/`pwrite` 避免共享 fd 的偏移量竞争
- **非阻塞 I/O**：`O_NONBLOCK` + `epoll` 实现事件驱动
- **散布 I/O**：`readv`/`writev` 一次系统调用完成多缓冲区操作，减少 user/kernel 切换
- **O_DIRECT**：绕过页缓存，HFT 直接写盘场景
- **mkstemp**：安全创建临时文件，避免 `mktemp` 的 TOCTOU

## 代码自测

<details>
<summary>1. dup2(fd, 2) 和 close(2); fcntl(fd, F_DUPFD, 2) 的区别？</summary>

`dup2(fd, 2)` 原子地关闭 fd 2 并将 fd 复制到 2。`close(2); fcntl(fd, F_DUPFD, 2)` 分两步，中间可能被信号中断或另一线程抢占 fd 2。在多线程或信号处理程序中应使用 `dup2` 或 `F_DUPFD_CLOEXEC`。
</details>

<details>
<summary>2. F_GETFL 返回的 access mode 怎么判断？</summary>

不能直接 `& O_RDONLY`（O_RDONLY 是 0）。需用 `mask = result & O_ACCMODE`，然后判断 mask 是 `O_RDONLY`(0)、`O_WRONLY`(1) 还是 `O_RDWR`(2)。
</details>

<details>
<summary>3. readv 如何实现一次读取头部+数据体？</summary>

```c
struct iovec iov[2];
iov[0].iov_base = &header;  iov[0].iov_len = sizeof(header);
iov[1].iov_base = body_buf; iov[1].iov_len = body_len;
ssize_t n = readv(fd, iov, 2);
```

一次系统调用完成两个不连续缓冲区的读取，比分两次 `read` 更高效。
</details>
