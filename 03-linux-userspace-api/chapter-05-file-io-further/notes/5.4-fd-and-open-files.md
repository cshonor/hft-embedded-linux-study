# 5.4 fd 与打开文件的关系（Relationship Between File Descriptors and Open Files）

## 本节讲什么

`lseek` 改的到底是「fd 数字」还是别的什么？为什么 `dup` 出来的两个 fd 会互相影响偏移，而两次 `open` 同一路径却互不影响？本节回答四个问题：

1. 内核里与「一个打开的文件」相关的**三层结构**分别是什么、各存什么？
2. 文件偏移（`lseek` 改的那个）存在哪一层？
3. 两次 `open` 同一路径，偏移为什么独立，但 `i-node` 是同一个？
4. 状态标志存在哪一层——和偏移是同一层吗？

本节把原书 **Listing 5-1 系列里最经典的那个实验**（`multi_descriptors.c`，习题 5-6 解答）跑通并逐轮打印。

## 1. 三层结构

```
   ① 进程的 fd 表                ② 打开文件表项                ③ i-node 表
   （进程私有）                  （可被多 fd/多进程共享）        （全局共享）
┌──────────────────┐      ┌──────────────────────┐      ┌──────────────────┐
│ fd 0 ──▶ ...     │      │ f_mode   访问模式      │      │ i_mode  文件类型   │
│ fd 3 ───────────────▶   │ f_pos    文件偏移      │─────▶│ i_ino   inode 号   │
│ fd 4 ───────────────▶   │ f_flags  状态标志      │      │ i_size  文件大小   │
│ fd 5 ──────┐            │ f_count  引用计数      │      │ i_op/i_fop 操作表  │
└────────────┼────────────┘ f_op    操作函数表      │      │ 数据块映射         │
             └──────────▶ └──────────────────────┘      └──────────────────┘
                 另一个打开文件表项（独立的偏移）
```

| 层 | 内核结构 | 归属 | 关键字段 | 谁共享 |
|----|---------|------|---------|--------|
| ① | `struct files_struct` / `struct fdtable`（`fdtable.h:49` / `:27`） | 进程私有 | `fd` 数组（`:29` `struct file __rcu **fd;`），下标就是 fd 号 | `fork` 后父子**共享同一份**（写时复制整个 `files_struct`） |
| ② | `struct file`（`fs.h:992`） | **可共享** | `f_mode`(`:1004`) / `f_count`(`:1005`) / `f_pos`(`:1007`) / `f_flags`(`:1008`) / `f_op`(`:1014`) | **`dup` 复制的就是它**；`fork` 后父子也共享 |
| ③ | `struct inode`（`fs.h:639`） | 全局 | `i_ino`(`:660`) / `i_size`(`:673`) / `i_op`(`:651`) | 所有打开者（含「各自 open」的） |

**读法**：同一行（`dup` / `fork`）→ 共享 ②（**共享偏移与状态标志**）；不同行（各自 `open`）→ 各自的 ②（**各自偏移**），但可能指向同一个 ③（同一个文件）。

## 2. 三个「怪现象」一次说清

| 现象 | 原因 |
|------|------|
| `dup(fd)` 出来的新 fd，`lseek` 一个、另一个也动 | 两者的 ① 表项不同（fd 号不同），但都指向**同一个 ②**；`f_pos` 在 ② 里 |
| 两次 `open` 同一路径，`lseek` 互不影响 | 各自 `open` 产生**两个独立的 ②**，各有各的 `f_pos` |
| 两次 `open` 同一路径，`fstat` 得到的 `st_ino` 相同 | `st_ino` 来自 **③**，而 ③ 是全局 inode 缓存里的同一个对象 |
| `fcntl(fd, F_SETFL, ...)` 改完 `O_APPEND`，`dup` 出的那个 fd 也变了 | `f_flags` 也在 ② 里 |
| 但 `fcntl(fd, F_SETFD, FD_CLOEXEC)` 不影响 `dup` 出的那个 fd | `FD_CLOEXEC` 在 **①** 的 fd 表项里，不在 ② |

最后两行是本节的**鉴别器**：学会了三层结构，就应该能一眼判断「这个属性是共享的、那个不是」。

## 3. 代码：逐轮打印内容与三个偏移

原书 `multi_descriptors.c`（习题 5-6 解答）的思想是：`fd1 = open(O_TRUNC)`、`fd2 = dup(fd1)`、`fd3 = open(O_RDWR)`，然后做四步写入，每步后 `system("cat a")` 打印文件内容。CE 沙箱里**没有 `/bin/sh`**（`system()` 返回 `32512`），所以自编 demo 用原生 `read()` 复刻同一串操作，并额外打印三个 fd 的当前偏移。

完整源码 [`code/c5_4_fd_open_files.c`](../code/c5_4_fd_open_files.c)：

```c
/* c5_4_fd_open_files.c — §5.4 文件描述符与打开文件的关系：三层结构
 *
 * 内核里访问一个文件要经过三张表：
 *     进程的 fd 表           系统级打开文件表             i-node 表
 *   ┌──────────────┐      ┌────────────────────┐      ┌──────────────┐
 *   │ 0,1,2 ...    │      │ 打开文件表项        │      │  i-node      │
 *   │ fd1 ───────────────▶│ 文件偏移 f_pos      │─────▶│  文件元数据   │
 *   │ fd2 ───────────────▶│ 状态标志 f_flags    │      │  文件内容     │
 *   │ fd3 ──────┐         └────────────────────┘      └──────────────┘
 *   └───────────┼───────────┘         ▲
 *               └─────────────────────┘ 另一个打开文件表项（各自独立的偏移）
 *
 * dup 让两个 fd 指向**同一个**打开文件表项 → 共享偏移与状态标志；
 * 再 open 一次则是**另一个**表项 → 偏移各算各的，但 i-node 是同一个。
 *
 * 本 demo 复刻原书 multi_descriptors.c（习题 5-6）的四步写入，并在每步之后
 * 用一个额外的只读 fd 把文件真读出来看——原书靠 system("cat a") 打印，
 * CE 沙箱里没有 /bin/sh，所以改用原生 read()。
 *
 * 编译: gcc -O0 -Wall -Wextra -o c5_4_fd_open_files c5_4_fd_open_files.c
 */
#define _GNU_SOURCE
#include <fcntl.h>
#include <stdio.h>
#include <string.h>
#include <sys/stat.h>
#include <unistd.h>
#include <errno.h>

#define FILE_A "/tmp/c5_multi_a"

/* 另开一个只读 fd 把全文读出来（这个 fd 是第 4 个打开文件表项，不影响上面三个的偏移） */
static void dump(const char *tag)
{
    int r = open(FILE_A, O_RDONLY);
    char buf[64];
    ssize_t n;

    if (r < 0) {
        printf("    [%s] 打开失败: %s\n", tag, strerror(errno));
        return;
    }
    n = read(r, buf, sizeof buf - 1);
    if (n < 0)
        n = 0;
    buf[n] = '\0';
    printf("    [%-16s] 内容 = \"%s\"\n", tag, buf);
    close(r);
}

static long cur(int fd)
{
    return (long) lseek(fd, 0, SEEK_CUR);
}

static void state(int fd1, int fd2, int fd3)
{
    printf("    偏移: fd1=%ld fd2=%ld fd3=%ld  (fd1/fd2 永远相等)\n",
           cur(fd1), cur(fd2), cur(fd3));
}

int main(void)
{
    int fd1 = open(FILE_A, O_RDWR | O_CREAT | O_TRUNC, 0600);
    int fd2, fd3;
    struct stat s1, s3;

    if (fd1 < 0) {
        perror("open fd1");
        return 1;
    }
    fd2 = dup(fd1);                     /* 同一个打开文件表项 */
    fd3 = open(FILE_A, O_RDWR);         /* 另一个打开文件表项 */
    if (fd2 < 0 || fd3 < 0) {
        perror("dup/open");
        return 1;
    }
    printf("== 0. 三个 fd 就位 ==\n");
    printf("    fd1=open(O_RDWR|O_CREAT|O_TRUNC) -> %d\n", fd1);
    printf("    fd2=dup(fd1)                     -> %d\n", fd2);
    printf("    fd3=open(O_RDWR)                 -> %d\n", fd3);
    printf("    fd1/fd2 同一打开文件表项；fd3 是另一个表项\n");

    fstat(fd1, &s1);
    fstat(fd3, &s3);
    printf("    i-node：fd1 的 st_ino=%llu、fd3 的 st_ino=%llu，同一个（都是 %llu）\n",
           (unsigned long long) s1.st_ino, (unsigned long long) s3.st_ino,
           (unsigned long long) s1.st_ino);

    printf("\n== 1. write(fd1, \"Hello,\", 6) ==\n");
    if (write(fd1, "Hello,", 6) != 6)
        perror("write1");
    dump("写 fd1 后");
    state(fd1, fd2, fd3);

    printf("\n== 2. write(fd2, \" world\", 6) —— 接着 fd1 的偏移往后写 ==\n");
    if (write(fd2, " world", 6) != 6)
        perror("write2");
    dump("写 fd2 后");
    state(fd1, fd2, fd3);

    printf("\n== 3. lseek(fd2, 0, SEEK_SET) —— 只动 fd2，但 fd1 的偏移也跟着回 0 ==\n");
    if (lseek(fd2, 0, SEEK_SET) == (off_t) -1)
        perror("lseek");
    dump("lseek 后");
    state(fd1, fd2, fd3);

    printf("\n== 4. write(fd1, \"HELLO,\", 6) —— 从 0 开始覆盖 ==\n");
    if (write(fd1, "HELLO,", 6) != 6)
        perror("write3");
    dump("写 fd1 后");
    state(fd1, fd2, fd3);

    printf("\n== 5. write(fd3, \"Gidday\", 6) —— fd3 的偏移还停在 0 ==\n");
    if (write(fd3, "Gidday", 6) != 6)
        perror("write4");
    dump("写 fd3 后");
    state(fd1, fd2, fd3);

    printf("\n== 6. 状态标志也在打开文件表项里，所以 fd1/fd2 共享、fd3 不共享 ==\n");
    fcntl(fd2, F_SETFL, fcntl(fd2, F_GETFL) | O_APPEND);   /* 只对 fd2 设 */
    printf("    fd1 F_GETFL=0x%05x O_APPEND=%d\n",
           fcntl(fd1, F_GETFL), !!(fcntl(fd1, F_GETFL) & O_APPEND));
    printf("    fd2 F_GETFL=0x%05x O_APPEND=%d\n",
           fcntl(fd2, F_GETFL), !!(fcntl(fd2, F_GETFL) & O_APPEND));
    printf("    fd3 F_GETFL=0x%05x O_APPEND=%d  ← 独立表项，不受影响\n",
           fcntl(fd3, F_GETFL), !!(fcntl(fd3, F_GETFL) & O_APPEND));

    close(fd1);
    close(fd2);
    close(fd3);
    return 0;
}
```

    fd1 F_GETFL=0x08402 O_APPEND=1
    fd2 F_GETFL=0x08402 O_APPEND=1

```

逐条看：

| 轮次 | 内容 | fd1 | fd2 | fd3 | 说明 |
|------|------|-----|-----|-----|------|
| 1 `write(fd1,"Hello,",6)` | `Hello,` | 6 | 6 | 0 | `fd1`/`fd2` 是同一表项，一起走到 6 |
| 2 `write(fd2," world",6)` | `Hello, world` | 12 | 12 | 0 | 从 6 续写。**`fd3` 完全不动**（它有自己的表项） |
| 3 `lseek(fd2,0,SEEK_SET)` | `Hello, world` | 0 | 0 | 0 | **只对 `fd2` 调 `lseek`，`fd1` 也回到 0**——这是「共享偏移」最直观的一刀 |
| 4 `write(fd1,"HELLO,",6)` | `HELLO, world` | 6 | 6 | 0 | 从 0 覆盖，原先的 `Hello,` 被盖掉 |
| 5 `write(fd3,"Gidday",6)` | `Gidday world` | 6 | 6 | 6 | `fd3` 的偏移一直停在 **0**，所以从开头覆盖——得到 `Gidday world` |

第 0 段的 `st_ino=2`（两个 fd 都是 2）是本节的**第二把刀**：**偏移独立 ≠ inode 独立**。`fd1` 与 `fd3` 是两个表项、两个偏移，但指同一个 inode——因为它们本来就是同一个文件（都是 `/tmp/c5_multi_a`）。

第 6 段把「状态标志也在 ② 里」也钉死：只对 `fd3` 之外的某个 fd 设 `O_APPEND`，`fd1`/`fd2` 一起变（`0x08402`），`fd3` 岿然不动（`0x08002`）。

> **`0x08402` 里三部分**：`0x2` = `O_RDWR`、`0x8000` = 内核补的 `O_LARGEFILE`、`0x400` = `O_APPEND`。

## 4. 原书程序：`multi_descriptors.c`（习题 5-6 解答）

/* multi_descriptors.c

   Show the interaction of multiple descriptors accessing the same
   file (some via the same shared open file table entry).
*/
#include <sys/stat.h>
#include <fcntl.h>
#include "tlpi_hdr.h"

int
main(int argc, char *argv[])
{
    int fd1, fd2, fd3;
#define file "a"
    char cmd[] = "cat " file "; echo";

    fd1 = open(file, O_RDWR | O_CREAT | O_TRUNC, S_IRUSR | S_IWUSR);
    if (fd1 == -1)
        errExit("open fd1");
    fd2 = dup(fd1);
    if (fd2 == -1)
        errExit("dup");
    fd3 = open(file, O_RDWR);
    if (fd3 == -1)
        errExit("open fd3");

    /* 'fd1' and 'fd2' share same open file table entry (and thus file
       offset). 'fd3' has its own open file table entry, and thus a
       separate file offset. */

    if (write(fd1, "Hello,", 6) == -1)
        errExit("write1");
    system(cmd);
    if (write(fd2, " world", 6) == -1)
        errExit("write2");
    system(cmd);
    if (lseek(fd2, 0, SEEK_SET) == -1)
        errExit("lseek");
    if (write(fd1, "HELLO,", 6) == -1)
        errExit("write3");
    system(cmd);
    if (write(fd3, "Gidday", 6) == -1)
        errExit("write4");
    system(cmd);

    if (close(fd1) == -1)
        errExit("close output");
    if (close(fd2) == -1)
        errExit("close output");
    if (close(fd3) == -1)
        errExit("close output");
    exit(EXIT_SUCCESS);
}
```

## 5. `f_count`：为什么关掉一个 fd 文件还在

`struct file->f_count`（`include/linux/fs.h:1005`）是**引用计数**。`dup` / `fork` 都会让它 +1，`close` 则 −1；**只有减到 0 时内核才真正释放这个打开文件表项**。这解释了两个家常现象：

- `fd1 = open(...); fd2 = dup(fd1); close(fd1);` → 用 `fd2` 仍然能正常读写（表项还活着）。
- `fork` 之后父子都 `close` 同一个 fd，文件才真正关闭。

inode 的 `i_count` 是同一套逻辑（只是层级在 ③）。理解「引用计数」是理解「为什么 `unlink` 之后还能读写已打开的文件」的前提（见 [5.11](5.11-dev-fd.md) 的实测）。

## 6. HFT / 嵌入式关联

| 场景 | 本节机制的兑现 |
|------|----------------|
| 多线程读同一 fd | 偏移在 ② 里**共享**，多线程 `lseek`+`read` 会互相错位 → 必须用 `pread`（[5.6](5.6-pread-pwrite.md)） |
| I/O 重定向 | `dup2(fd, STDOUT_FILENO)` 让「stdout」这个**号**指向新的 ②，所有 `printf` 自动改道——这是 shell `>` 的机制 |
| `fork` 后日志错乱 | 父子共享 ②，父 `lseek` 会动到子的位置 → 派生进程要写自己的日志就**重新 `open`**（拿到独立表项） |
| 状态标志意外共享 | `dup` 出来的 fd 上 `F_SETFL(O_NONBLOCK)`，原 fd 一并变非阻塞 → 排障时要想到这一层 |
| 嵌入式 `fork` 省 fd | 引用计数让 `close` 的时机更宽松，但在 fd 稀缺的嵌入式上仍要「谁 open 谁 close」，别指望计数兜底 |
| 追踪真实来源 | `readlink /proc/self/fd/N` 看到的是 ② 指向的 `dentry`，不是 fd 号——排查重定向问题用它 |

**Q1：文件偏移 `f_pos` 存在三层结构的哪一层？**
A：第 ② 层，打开文件表项（`struct file->f_pos`，`include/linux/fs.h:1007`）。所以 `dup`/`fork` 共享它，各自 `open` 则不共享。这是 `include/linux/fs.h:1007` 那一行「一行代码解释三类现象」的地方。

**Q2：实测里 `fd1` 和 `fd3` 的 `st_ino` 都是 `2`，说明什么？**
A：说明它们指向**同一个 inode**（第 ③ 层全局共享）。但这**不代表**它们共享偏移——实测 `fd1` 的偏移是 6 时 `fd3` 还是 0。**「共享 inode」和「共享打开文件表项」是两件不同的事**。

**Q3：`lseek(fd2, 0, SEEK_SET)` 之后为什么 `fd1` 也回到 0？**
A：因为 `fd2 = dup(fd1)`，两者指向同一个打开文件表项（`f_count` 变成 2），`f_pos` 是表项里的字段。只对 `fd2` 调 `lseek`，改的是那个共享字段。

**Q4：`FD_CLOEXEC` 在 `dup` 之后会被继承吗？**
A：不会。`FD_CLOEXEC` 在第 ① 层的 fd 表项里，`dup` 只共享第 ② 层。想让新 fd 也带 `FD_CLOEXEC`，用 `F_DUPFD_CLOEXEC`（实测 `F_GETFD=0x1`，见 [5.5](5.5-duplicating-fds.md)）。

**Q5：为什么 `close(fd1)` 之后用 `fd2` 还能读写？**
A：因为 `struct file->f_count`（`include/linux/fs.h:1005`）是引用计数，`dup` 时 +1、`close` 时 −1，只有减到 0 才真正释放打开文件表项。

**Q6：原书 `multi_descriptors.c` 在 CE 上为什么没有任何输出？**
A：它靠 `system("cat a; echo")` 打印文件内容，而 CE 沙箱里没有 `/bin/sh`，`system()` 返回 `32512`（`127<<8`）。程序逻辑没错，是环境缺 shell。自编的 `c5_4_fd_open_files.c` 用原生 `read()` 代替 `cat` 完成同样的展示。

**Q7：两个进程各自 `open` 同一文件，它们的偏移共享吗？**
A：不共享（两个独立的第 ② 层表项），但它们指向同一个第 ③ 层 inode。所以「一个进程 `lseek` 到末尾」不会影响另一个进程的位置——**这正是 `O_APPEND` 存在的必要性之一**：不共享偏移时，想追加就得自己定位，而定位+写两步之间有竞态（[5.1](5.1-atomicity-race-conditions.md)）。
