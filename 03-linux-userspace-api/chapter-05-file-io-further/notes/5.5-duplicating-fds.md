# 5.5 `dup` / `dup2` / `dup3` — 复制文件描述符

## 本节讲什么

`dup` 家族用来「复制文件描述符」，是 shell 管道、I/O 重定向的基石。本节回答三个问题：

1. `dup` / `dup2` / `dup3` 三者的区别是什么？复制后新旧 fd 共享什么？
2. 为什么 `dup2` 的「先关目标再复制」是**原子**的，而 `close` + `fcntl(F_DUPFD)` 不是？
3. `dup2` 复制出的 fd 为什么不继承 `FD_CLOEXEC`？该怎么处理？

---

## 1. 原型与内核链路

```c
#include <unistd.h>
int dup(int oldfd);                          /* 返回最小可用编号，指向同一打开描述 */
int dup2(int oldfd, int newfd);              /* 指定目标编号；newfd 已开则先原子 close */
int dup3(int oldfd, int newfd, int flags);   /* Linux 特有；flags 可带 O_CLOEXEC */
```

```
用户态 dup2(oldfd, newfd)
      ▼
SYSCALL_DEFINE2(dup2, ...)            fs/file.c（缓存未收录，架构说明）
      → ksys_dup3(oldfd, newfd, 0)
      → do_dup2(oldfd, newfd, 0)      ← 关键：原子完成「关 newfd + 复制」
      → f_dupfd / dup_fd

等价路径：fcntl(oldfd, F_DUPFD / F_DUPFD_CLOEXEC, min)
      ▼
do_fcntl()                            fs/fcntl.c:316
      F_DUPFD         → f_dupfd(argi, filp, 0)         :326
      F_DUPFD_CLOEXEC → f_dupfd(argi, filp, O_CLOEXEC) :329
```

复制后的新旧 fd **指向同一个打开文件描述**（同一个 `struct file`，`f_count` 引用计数 +1），因此**共享文件偏移 `f_pos` 和状态标志 `f_flags`**（见 [5.4](5.4-fd-and-open-files.md)）。

## 2. 三者的区别

| 函数 | 目标编号 | 已占用时 | `FD_CLOEXEC` |
|------|---------|---------|-------------|
| `dup(oldfd)` | 最小可用 | — | 不继承（新 fd 无 `FD_CLOEXEC`） |
| `dup2(oldfd, newfd)` | 指定 `newfd` | **原子**关闭再复制 | 不继承 |
| `dup3(oldfd, newfd, flags)` | 指定 `newfd` | 原子关闭再复制 | 可 `O_CLOEXEC` 一步设置 |
| `fcntl(F_DUPFD_CLOEXEC)` | ≥ 指定下限 | 选最小可用 | 继承式设置 `FD_CLOEXEC` |

## 3. 典型用途：I/O 重定向

```c
/* shell 的 `cmd > file.txt` 核心 */
int fd = open("file.txt", O_WRONLY | O_CREAT | O_TRUNC, 0644);
dup2(fd, STDOUT_FILENO);   /* stdout 指向 file.txt */
close(fd);                 /* 关掉多余副本 */
execvp(cmd, argv);         /* 新程序继承重定向后的 stdout */
```

## 4. 常见陷阱

**陷阱 1：`dup2` 复制出的 fd 不继承 `FD_CLOEXEC`**

```c
dup2(oldfd, newfd);   /* newfd 没有 FD_CLOEXEC */
```

`dup2` 的语义是「复制 oldfd 到 newfd」，而 `FD_CLOEXEC` 是 **fd 表项**的标志，不会被复制。若希望 `exec` 时自动关闭，需 `dup3(oldfd, newfd, O_CLOEXEC)` 或事后 `fcntl(newfd, F_SETFD, FD_CLOEXEC)`。

**陷阱 2：`dup2` 目标已打开会先关**

```c
dup2(oldfd, newfd);   /* newfd 已开 → 先 close(newfd) 再复制 */
```

这是**原子**的（内核 `do_dup2` 里完成），不存在「关闭后、复制前」被信号/线程插入的窗口。若不想覆盖，用 `fcntl(F_DUPFD)` 选一个空闲编号。

**陷阱 3：共享偏移的意外**

```c
int fd2 = dup(fd1);
lseek(fd1, 0, SEEK_SET);   /* fd2 的偏移也变了！ */
```

`dup` 复制的是「指向同一 `struct file` 的指针」，偏移共享。想要独立偏移请用 `open` 重新打开。

## 5. HFT / 嵌入式关联

| 场景 | 本节机制的兑现 |
|------|----------------|
| 日志重定向 | 交易进程 `fork` 后 `dup2` 把 stdout/stderr 指向日志文件 |
| 管道串联 | `dup2(pipefd[1], STDOUT_FILENO)` 实现多进程流水线（见 Ch44 管道） |
| 防 exec 泄漏 | `dup3(..., O_CLOEXEC)` 或 `F_DUPFD_CLOEXEC` 避免子进程继承 socket/文件句柄 |
| 嵌入式串口 | `dup2` 把串口 fd 复制为标准输入输出，让程序「不感知」底层设备 |

## 6. 代码示例

```c
#include <stdio.h>
#include <fcntl.h>
#include <unistd.h>

/* dup/dup2/dup3: 复制文件描述符 */
int main(void) {
    int fd = open("/dev/null", O_WRONLY);
    int new_fd = dup(fd);            /* 返回最小可用 fd */
    int fd10   = dup2(fd, 10);       /* 复制到 fd=10 */
#ifdef __linux__
    int fd11   = dup3(fd, 11, O_CLOEXEC); /* 复制到 11 并设 CLOEXEC */
#endif
    printf("dup: %d, dup2(fd,10): %d\n", new_fd, fd10);
    close(fd); close(new_fd); close(fd10);
    return 0;
}
```

<summary>代码自测（Q&A）</summary>

**Q1：`dup2(oldfd, newfd)` 和 `dup(oldfd)` 的区别？**
A：`dup` 返回**最小可用** fd；`dup2` **指定**目标编号 `newfd`（已占用则先原子关闭再复制）。`dup2` 用于重定向（把 fd 钉在 stdin/stdout 等固定编号上），`dup` 用于随便复制一个。

**Q2：`dup` 复制的 fd 有独立的文件偏移吗？**
A：没有。`dup` 复制的 fd 指向**同一个打开文件描述**（同一个 `struct file`），共享 `f_pos` 和 `f_flags`。`lseek` 通过任一 fd 都会影响另一个。

**Q3：以下代码在 `exec` 后，stdin 指向什么？为什么？**
```c
int fd = open("f.txt", O_RDONLY);
dup2(fd, STDIN_FILENO);
execvp("cat", argv);
```
A：`exec` 后 stdin（fd 0）仍指向 `f.txt`，因为 `dup2` 复制出的 fd **默认没有 `FD_CLOEXEC`**，`exec` 不会关闭它。这正是 shell 重定向的原理——子程序继承被重定向的 fd。

**Q4：`dup2(fd, 2)` 和 `close(2); fcntl(fd, F_DUPFD, 2)` 为什么前者更安全？**
A：`dup2` 的「关 2 + 复制」在内核 `do_dup2` 里**原子**完成，中间无窗口；`close(2)` 和 `fcntl` 是两步，中间可能被信号中断或另一线程抢占 fd 2，导致复制到错误位置。多线程/信号环境应优先 `dup2`/`dup3`。

**Q5：想复制 fd 且 `exec` 后自动关闭，有几种写法？**
A：三种：① `dup3(oldfd, newfd, O_CLOEXEC)`；② `fcntl(oldfd, F_DUPFD_CLOEXEC, min)`；③ `dup2` 后 `fcntl(newfd, F_SETFD, FD_CLOEXEC)`（但③有竞态窗口，不推荐多线程下用）。①和②是原子的。

</details>
