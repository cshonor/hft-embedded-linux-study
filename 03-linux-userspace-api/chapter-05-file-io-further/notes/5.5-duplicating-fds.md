## 本节讲什么

`dup` 家族是 shell 管道和 I/O 重定向的基石。本节回答五个问题：

1. `dup` / `dup2` / `dup3` / `F_DUPFD` 四个接口到底差在哪（只有三条差异）？
2. 复制出来的 fd 共享什么、不共享什么？
3. 为什么 `dup2` 的「先关目标再复制」是**原子**的，而 `close` + `F_DUPFD` 不是？
4. `dup2(fd, fd)` 和 `dup3(fd, fd, 0)` 为什么**行为不同**（一个成功、一个 `EINVAL`）？
5. 代码里怎么「既复制 fd、又防 `exec` 泄漏」？

---

## 1. 四条差异，三个维度

| 接口 | 新号怎么选 | 目标号已占用 | `CLOEXEC` |
|------|-----------|-------------|-----------|
| `dup(fd)` | 最小可用号 | — | ❌ 不带 |
| `dup2(old, new)` | 指定 `new` | **先关掉它** | ❌ 不带 |
| `dup3(old, new, flags)` | 指定 `new` | 先关掉它 | ✅ `flags` 只能是 `O_CLOEXEC` |
| `fcntl(fd, F_DUPFD, min)` | **不小于 `min`** 的最小可用号 | — | ❌ 不带 |
| `fcntl(fd, F_DUPFD_CLOEXEC, min)` | 不小于 `min` | — | ✅ 带 |

**只要记住这三个维度**（新号策略 / 覆盖策略 / CLOEXEC），这张表就不用背。

**关键在 `fs/file.c:1307` 的 `alloc_fd()`**：fd 的分配是在 `files->file_lock` 保护下完成的。这就是「`F_DUPFD` 是 `close(new)+dup2` 的原子替代品」的源码依据——`close` 与复制之间没有窗口让别的线程抢走那个号。

## 3. 代码：六段对照

完整源码 [`code/c5_5_dup.c`](../code/c5_5_dup.c)：

```c
/* c5_5_dup.c — §5.5 复制文件描述符：dup / dup2 / dup3 / F_DUPFD
 *
 * 四个接口的差别只有两条：**新号怎么选**、**目标号已占用怎么办**、**CLOEXEC 带不带**。
 *   dup(fd)                 最小可用号，不带 CLOEXEC
 *   dup2(old, new)          指定 new；若 new 已打开则先关掉它；old==new 时特例：
 *                           不关，直接校验 old 有效后原样返回
 *   dup3(old, new, flags)   Linux 特有；old==new 报 EINVAL；flags 只能是 O_CLOEXEC
 *   fcntl(fd, F_DUPFD, min) 不小于 min 的最小可用号（dup2 的"原子版"替代品）
 *
 * 编译: gcc -O0 -Wall -Wextra -o c5_5_dup c5_5_dup.c
 */
#define _GNU_SOURCE
#include <fcntl.h>
#include <stdio.h>
#include <string.h>
#include <unistd.h>
#include <errno.h>

int main(void)
{
    const char *p = "/tmp/c5_dup.txt";
    int fd = open(p, O_RDWR | O_CREAT | O_TRUNC, 0644);

    if (fd < 0) {
        perror("open");
        return 1;
    }
    write(fd, "ABCDEFGHIJ", 10);

    printf("== 1. dup() 取「最小可用号」——所以关掉 0 之后它会给 0 ==\n");
    printf("  fd = %d\n", fd);
    {
        int d = dup(fd);

        printf("  dup(fd)                     -> %d（3 已被占，给最小的空号）\n", d);
        close(d);
        close(0);                               /* 故意腾出 0 号 */
        d = dup(fd);
        printf("  close(0) 之后 dup(fd)       -> %d  ← 把 0 号占了\n", d);
        close(d);
    }
    /* 0 号已经关了，后面 open 会拿到 0；先把它补回来，免得干扰 */
    if (open("/dev/null", O_RDONLY) != 0)
        fprintf(stderr, "警告：没能补回 0 号\n");

    printf("\n== 2. dup2(old, new)：指定目标号，必要时先关旧的 ==\n");
    {
        int r = dup2(fd, 7);

        printf("  dup2(fd, 7)                 -> %d，7 号现在指向同一打开文件表项\n", r);
        printf("    偏移共享验证：write(7) 前 fd 的偏移=%ld\n", (long) lseek(fd, 0, SEEK_CUR));
        lseek(7, 4, SEEK_SET);
        printf("    lseek(7, 4) 之后 fd 的偏移=%ld  ← 一个动了两个都动\n",
               (long) lseek(fd, 0, SEEK_CUR));
        close(7);
    }

    printf("\n== 3. dup2(fd, fd)：old == new 的特例，不关、直接返回原号 ==\n");
    printf("  dup2(fd, fd) -> %d（fd 本身）\n", dup2(fd, fd));
    {
        int rc = dup2(999, 999);                 /* 先调用、后取 errno */

        printf("  dup2(999, 999) -> %d errno=%d (%s)  ← 此时要校验 old 有效\n",
               rc, errno, strerror(errno));
    }

    printf("\n== 4. dup3(old, new, flags)：Linux 特化版，old==new 直接 EINVAL ==\n");
    {
        int rc = dup3(fd, fd, 0);

        printf("  dup3(fd, fd, 0) -> %d errno=%d (%s)\n",
               rc, errno, strerror(errno));
    }
    {
        int d = dup3(fd, 20, O_CLOEXEC);

        printf("  dup3(fd, 20, O_CLOEXEC) -> %d，F_GETFD=0x%x（FD_CLOEXEC=0x%x 已置）\n",
               d, fcntl(d, F_GETFD), FD_CLOEXEC);
        close(d);
    }

    printf("\n== 5. CLOEXEC 差异：dup 不带，dup3 才带 ==\n");
    {
        int a = dup(fd);
        int b = dup3(fd, 30, O_CLOEXEC);

        printf("  dup(fd)          -> %d F_GETFD=0x%x\n", a, fcntl(a, F_GETFD));
        printf("  dup3(fd,30,CLOEXEC) -> %d F_GETFD=0x%x\n", b, fcntl(b, F_GETFD));
        printf("  （CLOEXEC 的意思是 exec 之后这个 fd 会被自动关掉）\n");
        close(a);
        close(b);
    }

    printf("\n== 6. 错误路径 ==\n");
    {
        int rc = dup(999);

        printf("  dup(999)      -> %d errno=%d (%s)\n", rc, errno, strerror(errno));
    }
    {
        int rc = dup2(999, 7);

        printf("  dup2(999, 7)  -> %d errno=%d (%s)\n", rc, errno, strerror(errno));
    }

    close(fd);
    return 0;
}
```

编译运行：

```bash
gcc -O0 -Wall -Wextra -o c5_5_dup c5_5_dup.c && ./c5_5_dup
```

CE（gcc 13.3.0 / x86-64 / Ubuntu 24.04）实测：

```text
== 1. dup() 取「最小可用号」——所以关掉 0 之后它会给 0 ==
  fd = 3
  dup(fd)                     -> 4（3 已被占，给最小的空号）
  close(0) 之后 dup(fd)       -> 0  ← 把 0 号占了

== 2. dup2(old, new)：指定目标号，必要时先关旧的 ==
  dup2(fd, 7)                 -> 7，7 号现在指向同一打开文件表项
    偏移共享验证：write(7) 前 fd 的偏移=10
    lseek(7, 4) 之后 fd 的偏移=4  ← 一个动了两个都动

== 3. dup2(fd, fd)：old == new 的特例，不关、直接返回原号 ==
  dup2(fd, fd) -> 3（fd 本身）
  dup2(999, 999) -> -1 errno=9 (Bad file descriptor)  ← 此时要校验 old 有效

== 4. dup3(old, new, flags)：Linux 特化版，old==new 直接 EINVAL ==
  dup3(fd, fd, 0) -> -1 errno=22 (Invalid argument)
  dup3(fd, 20, O_CLOEXEC) -> 20，F_GETFD=0x1（FD_CLOEXEC=0x1 已置）

== 5. CLOEXEC 差异：dup 不带，dup3 才带 ==
  dup(fd)          -> 4 F_GETFD=0x0
  dup3(fd,30,CLOEXEC) -> 30 F_GETFD=0x1
  （CLOEXEC 的意思是 exec 之后这个 fd 会被自动关掉）

== 6. 错误路径 ==
  dup(999)      -> -1 errno=9 (Bad file descriptor)
  dup2(999, 7)  -> -1 errno=9 (Bad file descriptor)
```

逐条看：

| 观察 | 说明 |
|------|------|
| `dup(fd)` → `4`，`close(0)` 之后 → **`0`** | 「最小可用号」是**真的**最小——连 0 号也不放过。**0/1/2 只是约定，不是保留**（同 [4.1](../../chapter-04-file-io-universal/notes/4.1-overview.md) 的结论）。这也意味着：先 `close(0)` 再 `dup` 是「悄悄劫持 stdin」的一条路 |
| `dup2(fd, 7)` → `7`；`lseek(7, 4)` 后**原 fd 的偏移 = 4** | 两个 fd 指向同一打开文件表项，共享 `f_pos`（[5.4](5.4-fd-and-open-files.md) 的三层结构） |
| `dup2(fd, fd)` → `3`（原号），**不报错** | `fs/file.c:1273` 的 `if (unlikely(newfd == oldfd))` 特例：不关、不复制，只校验有效性后原样返回。**POSIX 如此规定** |
| `dup2(999, 999)` → `-1 errno=9 (EBADF)` | 特例分支里**要**校验 `oldfd` 有效（`fs/file.c:1278-1279` 的 `files_lookup_fd_rcu` 失败即 `-EBADF`）。所以「`old == new` 就一定成功」是错的 |
| `dup3(fd, fd, 0)` → `-1 errno=22 (EINVAL)` | **与 `dup2` 相反**！`fs/file.c:1241-1242` 直接 `return -EINVAL;`。这是 Linux 特有的行为差异，写可移植代码时要注意 |
| `dup3(..., O_CLOEXEC)` → 新号的 `F_GETFD=0x1` | `dup`/`dup2` 复制后 `F_GETFD=0x0`（不带 CLOEXEC）；只有 `dup3`（或 `F_DUPFD_CLOEXEC`）能顺手置上 |
| `dup(999)` / `dup2(999, 7)` → `EBADF` | 源 fd 无效 |

## 4. 为什么 `dup3` 比 `dup2` 多两个「脾气」

读 `ksys_dup3` 的头部就能看懂 `dup3` 为什么这么「挑剔」——它要**先校验再动手**：

```c
if ((flags & ~O_CLOEXEC) != 0)          fs/file.c:1238-1239
        return -EINVAL;                 ← flags 里不许有别的东西
if (unlikely(oldfd == newfd))           fs/file.c:1241-1242
        return -EINVAL;                 ← 不做「特例」，直接拒绝
if (newfd >= rlimit(RLIMIT_NOFILE))     fs/file.c:1244-1245
        return -EBADF;                  ← 目标号超限
```

`dup3` 是「一个语义干净的新接口」：参数错了就报错，不做位置特判，也因此**不需要 `dup2` 那套 `old==new` 的隐藏分支**。工程上推荐 `dup3`，除非要兼容非 Linux。

## 5. `F_DUPFD` 的「原子替代」到底指什么

设想「把 stdout 换成文件」这个需求，两种写法：

| 写法 | 是否原子 | 问题 |
|------|---------|------|
| `close(1); fd = fcntl(oldfd, F_DUPFD, 1);` | ❌ | `close` 与 `fcntl` 之间，**另一个线程可能 `open` 拿到 1 号** → 你复制到的是被人抢过的号，或者干脆拿不到 1 |
| `dup2(oldfd, 1)` | ✅ | 内核在 `files->file_lock` 内一次完成「关旧的 + 装新的」（`fs/file.c:1105` `do_dup2`） |
| `fcntl(oldfd, F_DUPFD, 1)`（不 close） | ✅ 但语义不同 | `alloc_fd(1, ...)`（`fs/file.c:1307`）在锁内找「≥1 的最小空号」——若 1 已被占，它会给 2、3……**不会**替换 1 |

所以准确的说法是：**`F_DUPFD` 的「分配」是原子的，但「替换指定号」这件事只有 `dup2`/`dup3` 能做**。习题 5-4 要求用 `fcntl` 实现 `dup2`，正是逼你把这两步想清楚——见 [5.14](5.14-exercises.md)。

## 6. HFT / 嵌入式关联

| 场景 | 本节机制的兑现 |
|------|----------------|
| shell 重定向 | `ls > out.txt` 就是 `fork` + `dup2(fd, 1)` + `exec`；理解 `dup2` 就理解了 shell |
| 守护进程重绑标准流 | 守护化时 `dup2(devnull, 0/1/2)`；若 fd 0/1/2 已关闭，`open` 会**先拿到 0**（`dup` 的最小可用号策略同理） |
| 防 fd 泄漏给 `exec` | 复制 fd 给子进程时一律用 `dup3(old, new, O_CLOEXEC)` 或 `F_DUPFD_CLOEXEC`，避免子程序持有交易 socket |
| 多线程换 stdout | 必须用 `dup2`，不能用 `close`+`fcntl`——后者在 fd 号上会与别的线程竞态（`fs/file.c:1307` 才是锁内的那一步） |
| 嵌入式 fd 稀缺 | `dup` 只增引用计数不复制打开文件表项（内存开销极小），是「同一设备多个别名」的廉价手段 |
| 可移植性 | `dup3` 是 Linux 特有（`fs/file.c:1266`）；要跨平台就用 `fcntl(F_DUPFD_CLOEXEC)`，语义等价且 POSIX.1-2008 有 |

<summary>代码自测（Q&A）</summary>

**Q1：`dup` / `dup2` / `dup3` 三者最核心的差别是什么？**
A：三个维度：**新号怎么选**（`dup` 取最小可用 / `dup2`、`dup3` 指定）、**目标号已占用怎么办**（`dup` 不涉及 / `dup2`、`dup3` 先关掉）、**带不带 `CLOEXEC`**（只有 `dup3` 能通过 `flags` 带）。`dup2(old,new)` 遇 `old==new` 走特例返回原号；`dup3` 遇 `old==new` 直接 `EINVAL`（`fs/file.c:1241-1242`）。

**Q2：`dup2(fd, fd)` 返回什么？为什么？**
A：返回 `fd` 本身且**不报错**——`fs/file.c:1273` 的 `if (unlikely(newfd == oldfd))` 特例分支：不关、不复制，只校验 `oldfd` 有效性后原样返回。但 `dup2(999, 999)` 会返回 `-1 errno=9 (EBADF)`（`:1278-1279`），因为特例分支仍然校验源 fd。

**Q3：为什么说 `close(1); fcntl(oldfd, F_DUPFD, 1);` 不安全？**
A：`close` 与 `fcntl` 是两个系统调用，中间那段窗口里另一个线程可能 `open` 拿到 1 号。而 fd 的分配在内核里是 `files->file_lock` 保护的（`fs/file.c:1307` `alloc_fd`），只有 `dup2`/`dup3` 的「关+装」是在同一把锁内一次完成的（`fs/file.c:1105` `do_dup2`）。

**Q4：`F_DUPFD(fd, 1)` 会替换掉 1 号吗？**
A：不会。它是「不小于 1 的最小**空**号」；1 号已占用时会给 2、3……。它和 `dup2` 的语义不同：`dup2` 是「替换指定号」，`F_DUPFD` 是「在指定下界之上找空号」。

**Q5：`dup` 出来的新 fd 共享原 fd 的 `FD_CLOEXEC` 吗？**
A：不共享。`FD_CLOEXEC` 在 fd 表项（第 ① 层），`dup` 只共享打开文件表项（第 ② 层）。实测 `dup(fd)` 后 `F_GETFD=0x0`，而 `dup3(fd,30,O_CLOEXEC)` 后 `F_GETFD=0x1`。

**Q6：`dup(fd)` 会不会返回 0 号？**
A：会。实测 `close(0)` 之后 `dup(fd)` 就拿到了 `0`。**0/1/2 只是约定，不是保留**——所以「复制 fd」的代码如果不小心关了标准输入，可能悄悄把 stdin 劫持掉，这种 bug 很难查。

**Q7：做 I/O 重定向时该用哪个接口？**
A：用 `dup2`（或 `dup3`，若只跑 Linux 且想带 `CLOEXEC`）。它是原子的替换语义，正是 shell `>`、`2>&1` 的底层做法。
