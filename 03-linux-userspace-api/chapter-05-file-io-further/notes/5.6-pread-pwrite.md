# 5.6 `pread` / `pwrite` — 指定偏移读写

> 本章：[TLPI 第 05 章 — File I/O: Further Details](../README.md)

## 本节讲什么

`pread`/`pwrite` 是「在指定偏移处读写、但**不改变**文件当前偏移」的原子 I/O。本节回答三个问题：

1. `pread` 和 `lseek`+`read` 组合到底差在哪？为什么多线程下前者安全、后者会乱？
2. 内核里 `pread` 为什么能做到「用参数偏移、不碰 `f_pos`」？
3. `pread` 有哪些限制（哪些对象不能用）？

---

## 1. 原型与内核链路

```c
#include <unistd.h>
ssize_t pread(int fd, void *buf, size_t count, off_t offset);
ssize_t pwrite(int fd, const void *buf, size_t count, off_t offset);
```

```
用户态 pread(fd, buf, count, pos)
      ▼
SYSCALL_DEFINE4(pread64, fd, buf, count, pos)   fs/read_write.c:672
      ▼
ksys_pread64(fd, buf, count, pos)               fs/read_write.c:652
      if (pos < 0)  return -EINVAL;
      f = fdget(fd);
      ret = -ESPIPE;
      if (f.file->f_mode & FMODE_PREAD)         ← 对象必须支持「指定偏移读」
          ret = vfs_read(f.file, buf, count, &pos);   ← 传 &pos，不是 f_pos！
      fdput(f);
```

关键点：`vfs_read(file, buf, count, &pos)` 传入的是**局部变量 `pos` 的地址**，而不是 `file->f_pos` 的地址。所以读完后，`struct file` 的 `f_pos` **原封不动**——这正是 `pread` 与 `read` 的本质区别。`pwrite` 对称（`ksys_pwrite64` → `vfs_write(..., &pos)`）。

## 2. 核心语义

| 特性 | 说明 |
|------|------|
| 偏移来源 | 参数 `offset`，**不读也不写** 文件的 `f_pos` |
| 原子性 | 单次调用内「定位 + 读写」原子完成 |
| 与 `lseek`+`read` 的差异 | `lseek`+`read` 是两次调用，中间 `f_pos` 可能被其他线程改掉 |
| 返回后偏移 | 文件 `f_pos` **保持不变** |

## 3. 多线程安全：为什么 `pread` 比 `lseek`+`read` 强

共享 fd 的偏移（`f_pos`）只有一个，多线程用 `lseek`+`read` 会互相踩：

```
线程 A: lseek(fd, 100, SEEK_SET)  → f_pos = 100
线程 B: lseek(fd, 500, SEEK_SET)  → f_pos = 500   ← 覆盖了 A！
线程 A: read(fd, buf, 10)         → 从 500 读！错误
```

`pread(fd, buf, 10, 100)` 用局部 `pos`，不碰共享的 `f_pos`，多线程调用互不干扰，天然线程安全。

## 4. 限制

| 限制 | 原因 |
|------|------|
| 不可用于管道/socket/终端 | 这些对象不可 seek，没有「指定偏移」的概念，内核返回 `-ESPIPE`（`f_mode` 无 `FMODE_PREAD`/`FMODE_PWRITE`） |
| `offset` 不能为负 | `ksys_pread64` 里 `if (pos < 0) return -EINVAL` |

## 5. HFT / 嵌入式关联

| 场景 | 本节机制的兑现 |
|------|----------------|
| 多线程回测引擎 | 多个线程各自 `pread` 同一历史数据文件的不同偏移，互不干扰 |
| 并发写日志槽位 | 按「记录号 × 记录大小」计算偏移，用 `pwrite` 定点写入，无需锁偏移 |
| 减少 syscall | `pread` 一次调用替代 `lseek`+`read` 两次，降低陷入内核的延迟 |
| 数据库页读取 | 按页号随机 `pread` 是 DB 引擎（如 SQLite/LevelDB）随机读的标准姿势 |

## 6. 代码示例

```c
#include <stdio.h>
#include <fcntl.h>
#include <unistd.h>

/* pread/pwrite: 指定偏移读写，不改变 f_pos */
int main(void) {
    int fd = open("/tmp/pread_test.txt", O_RDWR | O_CREAT | O_TRUNC, 0644);
    write(fd, "0123456789ABCDEF", 16);

    /* pread 从偏移 5 读 3 字节，不改变 f_pos */
    char buf[4];
    pread(fd, buf, 3, 5);
    buf[3] = '\0';
    printf("pread(5,3): %s\n", buf);

    /* f_pos 仍在 16（未被 pread 改变） */
    printf("offset after pread: %ld (unchanged)\n",
           (long)lseek(fd, 0, SEEK_CUR));   /* 16 */

    /* pwrite 在偏移 10 处写，也不改变 f_pos */
    pwrite(fd, "XYZ", 3, 10);
    pread(fd, buf, 3, 10);
    buf[3] = '\0';
    printf("pwrite(10,XYZ): %s\n", buf);

    close(fd);
    return 0;
}
```

<summary>代码自测（Q&A）</summary>

**Q1：`pread` 和 `lseek(SEEK_SET)` + `read` 的本质区别是什么？**
A：`pread` 把「定位 + 读」合并成**一次原子调用**，用参数 `offset` 定位、不修改文件 `f_pos`。`lseek`+`read` 是两次调用，中间 `f_pos` 可能被其他线程/信号打断后改变，导致读到错误位置。多线程共享 fd 时 `pread` 线程安全，`lseek`+`read` 不安全。

**Q2：`pread` 读完后，文件的当前偏移（`f_pos`）是多少？**
A：**不变**。内核 `ksys_pread64` 调用 `vfs_read(file, buf, count, &pos)`，传入的是局部变量 `pos` 的地址，而非 `file->f_pos`。所以 `f_pos` 保持 `pread` 调用前的值。

**Q3：对管道调用 `pread` 会怎样？**
A：返回 `-1`，`errno = ESPIPE`。管道/socket/终端不可 seek，没有「指定偏移」语义。内核 `ksys_pread64` 里 `if (!(f_mode & FMODE_PREAD)) return -ESPIPE`，普通文件才有 `FMODE_PREAD`。

**Q4：`pread` 的 `offset` 传负数会怎样？**
A：返回 `-1`，`errno = EINVAL`。`ksys_pread64` 开头 `if (pos < 0) return -EINVAL`。偏移必须是合法非负值。

**Q5：`preadv`/`pwritev` 是什么？**
A：`pread`/`pwrite` 的「散布/聚集」版本，一次系统调用在指定偏移处读写**多个不连续缓冲区**（`struct iovec` 数组），内核入口 `do_preadv`/`do_pwritev`（`fs/read_write.c:994/:1017`），结合了 [5.6](5.6-pread-pwrite.md) 的「指定偏移」和 [5.7](5.7-readv-writev.md) 的「多缓冲」两个特性。

</details>
