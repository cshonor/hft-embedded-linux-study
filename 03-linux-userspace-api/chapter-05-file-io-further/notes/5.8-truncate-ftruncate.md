## 本节讲什么

`truncate` / `ftruncate` 干同一件事——**把文件长度改成指定值**，差别只在「用路径」还是「用 fd」。本节回答四个问题：

1. 两个函数怎么选？权限检查点为什么不同？
2. 长度**变短**和**变长**分别发生什么？「撑长」会不会真的占磁盘？
3. 怎么用 `st_size` 与 `st_blocks*512` 的差值**证明**「洞」存在？
4. 失败路径为什么有的报 `EACCES`、有的报 `EINVAL`、有的报 `EISDIR`——源码里的分界线在哪？

第 3 问是本节的核心：**「逻辑大小」和「物理占用」是两件事**，本节用一组干净的 2 倍关系把它钉死。

## 1. 原型与两条路径

```c
#include <unistd.h>
int truncate (const char *pathname, off_t length);   /* 按路径名 */
int ftruncate(int fd, off_t length);                 /* 按 fd */
/* 成功返回 0；失败返回 -1 并设 errno */
```

| | `truncate(path, len)` | `ftruncate(fd, len)` |
|---|---|---|
| 定位方式 | 路径名（走 namei 解析） | 已打开的 fd |
| 内核入口 | `do_sys_truncate`（`fs/open.c:123`） | `do_sys_ftruncate`（`fs/open.c:157`） |
| 写权限检查 | `inode_permission(..., MAY_WRITE)`（`vfs_truncate`，`fs/open.c:90`） | 检查 `f_mode & FMODE_WRITE`（`fs/open.c:179`） |
| 需要 fd 可写吗 | 不涉及 fd | **需要**（只读 fd → `EINVAL`） |
| 权限不足的错误 | **`EACCES`** | `EINVAL` |
| 目标已打开有偏移 | 不影响任何人的 `f_pos` | 不影响 `f_pos`（游标可以留在原处） |

两条路径最终都汇到 `do_truncate`（`fs/open.c:40`）→ `notify_change`（`fs/open.c:66`），由具体文件系统去改 inode 的 `i_size` 并调整块映射。

## 2. 变短 vs 变长

| 方向 | 发生什么 | 磁盘 |
|------|---------|------|
| `len` **小于**当前长度 | 尾部数据**真的没了**（不可恢复） | 尾部整块被释放，`st_blocks` 下降 |
| `len` **大于**当前长度 | 文件逻辑变长，新区域读出全 0 | **不分配数据块**——是「洞」（稀疏文件） |

「撑长」对应 POSIX 的 `lseek` + `write` 也能做到（[4.7](../../chapter-04-file-io-universal/notes/4.7-lseek.md)），但 `ftruncate` 更直接：**一次调用给定新的逻辑长度**，不需要写任何数据。

## 3. 代码：六段实测

完整源码 [`code/c5_8_truncate.c`](../code/c5_8_truncate.c)：

```c
/* c5_8_truncate.c — §5.8 截断文件：truncate() / ftruncate()
 *
 * 两个函数干同一件事，差别只在「用路径还是用 fd」：
 *   truncate(path, len)  —— 按路径名，需要该文件的写权限
 *   ftruncate(fd, len)   —— 按 fd，需要 fd 是**可写的**打开方式
 *
 * len 小于当前长度 = 砍掉尾部（数据真没了）；大于当前长度 = 撑长，多出来的
 * 部分读出来是 0，但**不分配磁盘块**（是个洞）——这点用 st_blocks 看得最清楚。
 *
 * 演示六件事：
 *   1) 砍短：读回来的内容跟着短
 *   2) 撑长：新区域读出全 0，st_blocks 不变（洞）
 *   3) 对照：手动写 4096 个 0 字节，st_blocks 会涨
 *   4) 按路径 truncate 也管用
 *   5) 失败路径：不存在的文件 ENOENT / 只读 fd EINVAL / 目录 EISDIR / 负长度 EINVAL
 *   6) truncate 之后偏移可以超过新的文件末尾，但读是 0
 *
 * 编译: gcc -O0 -Wall -Wextra -o c5_8_truncate c5_8_truncate.c
 */
#define _GNU_SOURCE
#include <fcntl.h>
#include <stdio.h>
#include <string.h>
#include <sys/stat.h>
#include <unistd.h>
#include <errno.h>

static void st(const char *tag, int fd)
{
    struct stat s;

    fstat(fd, &s);
    printf("    [%-14s] st_size=%5lld  st_blocks*512=%5lld（物理）\n",
           tag, (long long) s.st_size, (long long) s.st_blocks * 512);
}

/* 读 [off, off+n) 这一段，看看是不是全 0 */
static int region_is_zero(int fd, off_t off, size_t n)
{
    char buf[4096];
    ssize_t got = pread(fd, buf, n, off);

    if (got <= 0)
        return -1;
    for (ssize_t i = 0; i < got; i++)
        if (buf[i] != 0)
            return 0;
    return 1;
}

int main(void)
{
    const char *p = "/tmp/c5_trunc.txt";
    const char *q = "/tmp/c5_trunc_zeros.txt";
    int fd = open(p, O_RDWR | O_CREAT | O_TRUNC, 0644);

    if (fd < 0) {
        perror("open");
        return 1;
    }
    write(fd, "ABCDEFGHIJKLMNOPQRSTUVWXYZ", 26);     /* 26 字节 */
    printf("== 0. 准备 ==\n");
    st("26 字节", fd);

    printf("\n== 1. ftruncate(fd, 10)：砍掉尾部 16 字节 ==\n");
    if (ftruncate(fd, 10) == -1)
        perror("ftruncate");
    st("截到 10", fd);
    {
        char b[64];
        ssize_t n = pread(fd, b, sizeof b - 1, 0);

        b[n > 0 ? n : 0] = '\0';
        printf("    内容变成 \"%s\"\n", b);
    }

    printf("\n== 2. ftruncate(fd, 8192)：撑长，新区域是洞 ==\n");
    if (ftruncate(fd, 8192) == -1)
        perror("ftruncate");
    st("撑到 8192", fd);
    printf("    [4096,8192) 读出全 0？%s\n",
           region_is_zero(fd, 4096, 4096) == 1 ? "是" : "否");
    printf("    ↑ 逻辑长度 8192，物理占用还停在 4096 —— 多出来的那 4096 字节是「洞」\n");

    printf("\n== 3. 对照：真的写 4096 个 0 字节，物理占用就会涨 ==\n");
    {
        int zf = open(q, O_RDWR | O_CREAT | O_TRUNC, 0644);
        char zeros[8192];

        memset(zeros, 0, sizeof zeros);
        write(zf, zeros, sizeof zeros);
        st("写满 8192", zf);
        printf("    ↑ 同样 8192 字节逻辑长度，物理实打实占了 8192（是上面那个的两倍）\n");
        close(zf);
        unlink(q);
    }

    printf("\n== 4. truncate(path, 5)：按路径名截断 ==\n");
    if (truncate(p, 5) == -1)
        perror("truncate");
    st("truncate 到 5", fd);

    printf("\n== 5. 失败路径 ==\n");
    {
        int rc = truncate("/tmp/c5_not_exist", 5);

        printf("    truncate(\"/tmp/c5_not_exist\", 5) -> %d errno=%d (%s)\n",
               rc, errno, strerror(errno));
    }
    {
        int rfd = open(p, O_RDONLY);
        int rc = ftruncate(rfd, 5);

        printf("    ftruncate(只读 fd, 5)          -> %d errno=%d (%s)\n",
               rc, errno, strerror(errno));
        close(rfd);
    }
    {
        int rc = truncate("/tmp", 5);

        printf("    truncate(\"/tmp\", 5)            -> %d errno=%d (%s)\n",
               rc, errno, strerror(errno));
    }
    {
        int rc = ftruncate(fd, -1);

        printf("    ftruncate(fd, -1)              -> %d errno=%d (%s)\n",
               rc, errno, strerror(errno));
    }

    printf("\n== 6. 截短之后，游标可以留在原处（但读不到东西）==\n");
    lseek(fd, 100, SEEK_SET);                    /* 新的末尾才 5 */
    {
        char b[8];
        ssize_t n = read(fd, b, sizeof b);

        printf("    lseek 到 100 再 read -> %ld（0 = 已经越过 EOF）\n", (long) n);
        printf("    f_pos 现在 = %ld\n", (long) lseek(fd, 0, SEEK_CUR));
    }

    close(fd);
    return 0;
}
```

编译运行：

```bash
gcc -O0 -Wall -Wextra -o c5_8_truncate c5_8_truncate.c && ./c5_8_truncate
```

CE（gcc 13.3.0 / x86-64 / Ubuntu 24.04）实测：

```text

== 1. ftruncate(fd, 10)：砍掉尾部 16 字节 ==
    [截到 10     ] st_size=   10  st_blocks*512= 4096（物理）
    内容变成 "ABCDEFGHIJ"

== 2. ftruncate(fd, 8192)：撑长，新区域是洞 ==
    [撑到 8192   ] st_size= 8192  st_blocks*512= 4096（物理）
    [4096,8192) 读出全 0？是
    ↑ 逻辑长度 8192，物理占用还停在 4096 —— 多出来的那 4096 字节是「洞」

== 3. 对照：真的写 4096 个 0 字节，物理占用就会涨 ==
    [写满 8192   ] st_size= 8192  st_blocks*512= 8192（物理）
    ↑ 同样 8192 字节逻辑长度，物理实打实占了 8192（是上面那个的两倍）

== 4. truncate(path, 5)：按路径名截断 ==
    [truncate 到 5] st_size=    5  st_blocks*512= 4096（物理）

== 5. 失败路径 ==
    truncate("/tmp/c5_not_exist", 5) -> -1 errno=2 (No such file or directory)
    ftruncate(只读 fd, 5)          -> -1 errno=22 (Invalid argument)
    truncate("/tmp", 5)            -> -1 errno=21 (Is a directory)
    ftruncate(fd, -1)              -> -1 errno=22 (Invalid argument)

== 6. 截短之后，游标可以留在原处（但读不到东西）==
    lseek 到 100 再 read -> 0（0 = 已经越过 EOF）
    f_pos 现在 = 100
```

逐条看：

| 观察 | 说明 |
|------|------|
| 准备阶段：26 字节，物理 **4096** | 小于一个块（4096）的文件也会占满一个块——**这是文件系统的最小分配粒度** |
| `ftruncate(fd, 10)`：`st_size` 26 → **10**，物理仍 4096 | 数据真的砍掉了（内容变成 `ABCDEFGHIJ`），但因为还是「不足一个块」，物理占用不变 |
| `ftruncate(fd, 8192)`：`st_size` → **8192**，物理**仍是 4096** | **本节核心**。逻辑 8192、物理 4096——差的那 4096 字节就是「洞」。新区域读出来全是 0（实测确认） |
| 对照：手动写 4096 个 0 → 物理 **8192** | 同样 8192 字节的逻辑长度，**实打实占了 8192**（是上面的 2 倍）。这一组对照证明「洞不是 0 数据，而是**没有分配块**」 |
| `truncate(path, 5)`：`st_size` → 5，物理 4096 | 路径版本行为一致；从 8192 砍到 5 释放了第二个块 |
| `truncate("/tmp/c5_not_exist", 5)` → `ENOENT` | 路径解析失败（`user_path_at`，`fs/open.c:133`） |
| `ftruncate(只读 fd, 5)` → **`EINVAL`** | `fs/open.c:179`：`if (!S_ISREG(inode->i_mode) \|\| !(f.file->f_mode & FMODE_WRITE))` → `error = -EINVAL` |
| `truncate("/tmp", 5)` → **`EISDIR`** | `fs/open.c:80-81`：`if (S_ISDIR(inode->i_mode)) return -EISDIR;`。同处的注释原文还说明了「非普通非目录 → `EINVAL`」 |
| `ftruncate(fd, -1)` → `EINVAL` | `fs/open.c:164-166`（ftruncate 版）与 `:47-48`（`do_truncate` 版）都拦负数长度 |
| 截短后 `lseek(100)` + `read` → **0**，`f_pos` 仍是 **100** | `ftruncate` **不重置**任何人的游标。游标可以落在 EOF 之后——这是合法的，只是读不到东西 |

> **「超出一个块」为什么是 4096？** 这是 CE 沙箱所用文件系统的块大小。判断洞的正确方法是 `st_size > st_blocks * 512`，而且要注意：**差值的意义依赖文件系统**（有的 FS 会预分配、有的会延迟分配）。

## 4. 失败路径的分界线（源码级）

`vfs_truncate` 的头部把「哪些对象不能截断」写得非常清楚（`fs/open.c:79-83`）：

```c
/* For directories it's -EISDIR, for other non-regulars - -EINVAL */
if (S_ISDIR(inode->i_mode))
        return -EISDIR;
if (!S_ISREG(inode->i_mode))
        return -EINVAL;
```

后续的检查顺序与错误码：

| 顺序 | 检查 | 位置 | 错误码 |
|------|------|------|--------|
| 1 | 目录 | `fs/open.c:80-81` | `EISDIR` |
| 2 | 非普通文件（设备、FIFO…） | `fs/open.c:82-83` | `EINVAL` |
| 3 | 挂载点只读 | `fs/open.c:85`（`mnt_want_write`） | `EROFS` |
| 4 | 无写权限 | `fs/open.c:90`（`inode_permission(MAY_WRITE)`） | **`EACCES`** |
| 5 | 只增文件（`chattr +a`） | `fs/open.c:94-96`（`IS_APPEND`） | `EPERM` |
| 6 | 有租约（lease） | `fs/open.c:106`（`break_lease`） | 租约相关 |
| 7 | 路径版 `length < 0` | `fs/open.c:129-130` | `EINVAL` |

**所以「权限不足」有两种码**：路径版（`truncate`）在 `inode_permission` 处返回 **`EACCES`**；fd 版（`ftruncate`）走的是 `f_mode` 检查（`fs/open.c:179`），返回 **`EINVAL`**。原书 `t_truncate.c` 在 CE 上跑 `/proc/version` 得到 `truncate: Permission denied`，正是第 4 条（`EACCES`）的现场。

```c
/* t_truncate.c

   Demonstrate the use of the truncate() system call to truncate the file
   named in argv[1] to the length specified in argv[2]
*/
#include "tlpi_hdr.h"

int
main(int argc, char *argv[])
{
    if (argc != 3 || strcmp(argv[1], "--help") == 0)
        usageErr("%s file length\n", argv[0]);

    if (truncate(argv[1], getLong(argv[2], GN_ANY_BASE, "length")) == -1)
        errExit("truncate");

    exit(EXIT_SUCCESS);
}
```

它只做一件事：解析 `argv[2]` 成长整数，然后 `truncate(argv[1], n)`。注意 `argv[2]` 是用 `getLong(argv[2], GN_ANY_BASE, "length")` 解析的（支持 `10` / `0x10` / `010` 三种进制），所以本仓库的 `tlpi_hdr.h` 替身必须提供 `getLong`。

```bash
gcc -O0 -Wall -Wextra -o t_truncate t_truncate.c
./t_truncate /proc/version 10      # 权限不足
./t_truncate --help                # 用法提示
```

CE 实测：

```text
truncate: Permission denied
```

```text
Usage: ./output.s file length
```

第一条是 `errExit("truncate")` 的输出——`/proc` 下的文件不可写，`inode_permission` 返回 `EACCES`（对应第 4 节的第 4 条）。第二条是 `usageErr` 的输出；参数不足或 `--help` 时打印，`argv[0]` 在 CE 上被固定成 `./output.s`。

## 6. 常见坑

| 坑 | 说明 |
|------|------|
| 用 `st_size` 判断「文件占多少磁盘」 | 错。要看 `st_blocks * 512`（或 `* 512` 之外的块大小常量）；稀疏文件两者能差很多倍 |
| 以为「撑长」会预分配磁盘 | 不会。新区域是洞，只有真写数据才分配块（第 3 段对照实证） |
| 在只读 fd 上 `ftruncate` 想「清空文件」 | `EINVAL`。必须以 `O_WRONLY`/`O_RDWR` 打开 |
| 用 `truncate("dir", ...)` 企图清空目录 | `EISDIR`。删除目录内容的唯一办法是逐个 `unlink` |
| 以为 `ftruncate` 会把游标复位到 0 | 它**不动** `f_pos`。实测截短到 5 之后把游标留在 100 完全合法，只是 `read` 返回 0 |
| 把「截短」当可逆操作 | 截短丢弃的数据**无法恢复**。这是 `O_TRUNC` 之外第二常见的「误删数据」来源 |
| 负数长度 | `EINVAL`（`fs/open.c:47-48` / `:129-130`） |
| 32 位平台截断大文件 | `do_sys_ftruncate` 的 `small` 标志与 `MAX_NON_LFS`（`include/linux/fs.h:1048`）会拦下超过 2 GiB 的长度，除非 `O_LARGEFILE` 已设（`:172-174`）。见 [5.10](5.10-large-files.md) |

## 7. HFT / 嵌入式关联

| 场景 | 本节机制的兑现 |
|------|----------------|
| 预分配日志段 | 用 `ftruncate` 把日志文件「撑」到目标长度，之后只 `pwrite` 固定偏移——避免运行期分配块造成的写延迟抖动 |
| 稀疏快照 | 内存镜像、行情全量快照常是「稀疏文件」：逻辑很大、物理很小；备份/传输工具必须认识稀疏（见 [习题 4-2](../../chapter-04-file-io-universal/notes/4.10-exercises.md)） |
| 循环日志截断 | 滚动日志清空用 `ftruncate(fd, 0)`，比 `O_TRUNC` 重开更省（保住已有 fd 与打开文件表项） |
| 嵌入式 flash 寿命 | 「撑长 + 稀疏写」在日志式/FTL 介质上不一定省写放大；`st_blocks` 与真实擦除次数可能不对应——**要看具体 FS/FTL** |
| 只增审计区 | `chattr +a` 的目录/文件上 `truncate` 报 `EPERM`（`fs/open.c:94-96`），这是内核提供的「不可删改」保护 |
| 容器/沙箱里 `truncate` 失败 | 常见原因是只读挂载（`EROFS`）而不是权限——排查时先看 `mount` 再看 mode |

<summary>代码自测（Q&A）</summary>

**Q1：`truncate` 和 `ftruncate` 有什么区别？**
A：干同一件事（改文件长度），差别在**定位方式**与**权限检查点**。路径版 `truncate` 走 `user_path_at` + `inode_permission(MAY_WRITE)`（`fs/open.c:133`、`:90`），权限不足报 `EACCES`；fd 版 `ftruncate` 检查 `f_mode & FMODE_WRITE`（`fs/open.c:179`），只读 fd 报 `EINVAL`。

**Q2：`ftruncate(fd, 8192)` 把 10 字节的文件撑到 8192，会占多少磁盘？**
A：**不额外占**。实测 `st_size = 8192` 但 `st_blocks*512 = 4096`（仍是 1 个块）——多出来的 4096 字节是「洞」，读出来是全 0。对照实验：手动写 4096 个 0 字节，`st_blocks*512` 立刻涨到 **8192**（是 2 倍）。

**Q3：怎么判断一个文件有洞？**
A：比较 `st_size` 与 `st_blocks * 512`（后者是实际分配的字节数）。前者明显大于后者就说明有洞。**只看 `st_size` 判断不了**——这是本仓库反复强调的一条。

**Q4：`truncate("/tmp", 5)` 返回什么？**
A：`-1 errno=21 (EISDIR)`。`vfs_truncate` 的 `fs/open.c:80-81` 明确返回 `-EISDIR`，同处注释还写着「非目录的非常规文件 → `EINVAL`」。

**Q5：为什么在只读 fd 上 `ftruncate` 报 `EINVAL` 而不是 `EACCES`？**
A：因为 fd 版走的是 `fs/open.c:179` 的 `if (!S_ISREG(...) || !(f.file->f_mode & FMODE_WRITE))` → `error = -EINVAL;`。它检查的是「这个打开的文件能不能写」（`f_mode`），不是「你有没有权限改这个 inode」。

**Q6：`ftruncate` 会把文件偏移重置为 0 吗？**
A：不会。实测截短到 5 字节后，把游标 `lseek` 到 100 再 `read` 返回 0，且 `f_pos` 停在 100。**截断只改 `i_size`，不动任何打开文件表项的 `f_pos`**。

**Q7：`truncate` 截短的数据能恢复吗？**
A：不能。截短会把尾部的块释放掉，数据真的没了。这就是它比 `O_TRUNC` 更危险的地方——`O_TRUNC` 至少是「打开时」的显式动作，而 `ftruncate(fd, 0)` 可以发生在任何时刻、任何一行代码。

**Q8：`MAX_NON_LFS` 是什么？在哪个文件？**
A：`include/linux/fs.h:1048`，定义为 `((1UL<<31) - 1)`，即 2 GiB − 1。`do_sys_ftruncate` 用它拦住没有大文件支持的 32 位进程（`fs/open.c:184` 的 `if (small && length > MAX_NON_LFS)`）；若 `O_LARGEFILE` 已设则 `small = 0`（`:172-174`），检查跳过。
