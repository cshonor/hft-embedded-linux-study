## 本节讲什么

`truncate`/`ftruncate` 直接设置文件大小，不经过「写数据」。本节回答三个问题：

1. `truncate`（按路径）和 `ftruncate`（按 fd）的区别是什么？各自需要什么权限？
2. 把文件「截断得更小」和「扩展得更大」分别发生什么？
3. 为什么 `ftruncate` 是共享内存、稀疏文件、预分配空间的通用手段？

---

## 1. 原型与内核链路

```c
#include <unistd.h>
#include <sys/types.h>
int truncate(const char *path, off_t length);   /* 按路径，无需打开 */
int ftruncate(int fd, off_t length);            /* 按 fd，需以写方式打开 */
```

```
用户态 ftruncate(fd, length)
      ▼
SYSCALL_DEFINE2(ftruncate, fd, length)   fs/open.c:203
      ▼
do_sys_ftruncate(fd, length, small)      fs/open.c:157
      ├─ length < 0                       → -EINVAL
      ├─ fdget(fd) 失败                   → -EBADF
      ├─ !S_ISREG(inode) 或 !(f_mode&FMODE_WRITE) → -EINVAL
      │     （必须是普通文件，且 fd 以写方式打开）
      ├─ IS_APPEND(inode) append-only 文件 → -EPERM
      ├─ security_file_truncate()         ← LSM 安全检查
      └─ do_truncate(idmap, dentry, length, ...)   fs/open.c:40
           ├─ length < 0 → -EINVAL
           ├─ newattrs.ia_size = length    ← 直接设 i_size
           ├─ dentry_needs_remove_privs()  ← 清除 suid/sgid/capabilities
           └─ notify_change()              ← 通知 inode 变更（含 mtime/ctime）
```

`truncate` 走 `do_sys_truncate`（内部 `user_path_at` 解析路径后同样落到 `do_truncate`），区别只是「按路径查找 inode」vs「按 fd 取 `struct file`」。

## 2. 行为语义

| 场景 | 结果 |
|------|------|
| `length` < 当前大小 | **截断**到 `length`，超出部分的数据被丢弃 |
| `length` > 当前大小 | **扩展**，新增区域填充 0（读出来是 `\0`），磁盘上形成**稀疏文件**（空洞不占块） |
| `length` == 当前大小 | 无大小变化（但可能更新 mtime） |

## 3. 典型用途

- **清空文件**：`ftruncate(fd, 0)` 等价于「删内容、保留 inode」，比 `open(O_TRUNC)` 重开更直接。
- **预分配空间**：先 `ftruncate` 到目标大小，再随机写各槽位（配合 `pwrite`），适合定长记录文件。
- **共享内存**：`ftruncate` 设置共享内存对象大小（SysV 共享内存 Ch48、POSIX 共享内存 Ch54）。
- **创建稀疏文件**：`ftruncate(fd, 10GB)` 得到一个「逻辑 10GB、物理几乎不占块」的文件。

## 4. HFT / 嵌入式关联

| 场景 | 本节机制的兑现 |
|------|----------------|
| 定长记录文件 | `ftruncate` 预分配 N×记录大小，`pwrite` 定点写槽位，随机读写无碎片 |
| 内存映射前定大小 | `mmap` 前 `ftruncate` 把文件撑到目标大小，否则映射后写越界会 `SIGBUS`（见 Ch49） |
| 共享内存 | 进程间用 `ftruncate` 设置共享内存对象大小（Ch48/Ch54） |
| 快速清空日志 | `ftruncate(fd, 0)` 秒清文件，避免反复 `open(O_TRUNC)` 的开销 |

## 5. 代码示例

```c
#include <stdio.h>
#include <fcntl.h>
#include <unistd.h>

/* truncate/ftruncate: 设置文件大小 */
int main(void) {
    /* ftruncate 预分配 1MB 文件（稀疏） */
    int fd = open("/tmp/big.dat", O_RDWR | O_CREAT, 0644);
    if (ftruncate(fd, 1024 * 1024) < 0) perror("ftruncate");
    printf("size: %ld\n", (long)lseek(fd, 0, SEEK_END));

    /* 清空文件 */
    ftruncate(fd, 0);
    printf("after ftruncate(0): %ld\n", (long)lseek(fd, 0, SEEK_END));

    close(fd);
    return 0;
}
```

<details>
<summary>代码自测（Q&A）</summary>

**Q1：`truncate` 和 `ftruncate` 的区别？**
A：`truncate(path, length)` 按**路径**定位文件，**不需要先打开**（但需要目录写权限）；`ftruncate(fd, length)` 按**已打开的 fd** 操作，要求 fd **以写方式打开**（`f_mode & FMODE_WRITE`），且是普通文件。两者最终都落到 `do_truncate`。

**Q2：把文件 `ftruncate` 到比当前更大的大小会怎样？**
A：文件被**扩展**，新增区域填充 0（读出来是 `\0`）。若扩展幅度大，中间形成**文件空洞（sparse）**——逻辑大小很大，但空洞区不分配磁盘块，实际占用极小。

**Q3：`ftruncate` 一个 append-only 文件会怎样？**
A：返回 `-1`，`errno = EPERM`。`do_sys_ftruncate` 检查 `IS_APPEND(inode)`，append-only 文件（`chattr +a`）禁止截断，防止绕过强制追加语义。

**Q4：`ftruncate` 需要什么权限？**
A：fd 必须**以写方式打开**（`FMODE_WRITE`），且对象必须是**普通文件**（`S_ISREG`），否则 `-EINVAL`。此外 `do_truncate` 会清除文件的 suid/sgid/capabilities（`dentry_needs_remove_privs`），防止特权位残留。

**Q5：`mmap` 一个文件前为什么常先 `ftruncate`？**
A：`mmap` 映射的长度不能超过文件大小，否则访问映射区超出文件末尾的部分会触发 `SIGBUS`。先 `ftruncate(fd, target_size)` 把文件撑到目标大小，再 `mmap`，映射区内才能安全读写（详见 Ch49）。

</details>
