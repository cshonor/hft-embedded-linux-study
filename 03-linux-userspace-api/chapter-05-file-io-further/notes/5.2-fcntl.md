## 本节讲什么

`fcntl()` 是文件描述符的「万能控制开关」。本节回答三个问题：

1. `fcntl()` 的 `cmd` 有哪些，各自操作哪一层？
2. 「fd 标志」和「文件状态标志」两组标志为什么不能混？各存在哪、各用什么 `cmd` 读写？
3. `F_SETFL` 为什么改不了读写模式（`O_RDONLY`/`O_WRONLY`/`O_RDWR`）？

---

## 1. 原型与内核链路

```c
#include <fcntl.h>
int fcntl(int fd, int cmd, ...);
```

```
用户态 fcntl(fd, cmd, arg)
      ▼
SYSCALL_DEFINE3(fcntl, fd, cmd, arg)   fs/fcntl.c:441
      ▼
do_fcntl(fd, cmd, arg, filp)           fs/fcntl.c:316
      switch (cmd) {
        F_DUPFD         → f_dupfd(argi, filp, 0)            :326
        F_DUPFD_CLOEXEC → f_dupfd(argi, filp, O_CLOEXEC)    :329
        F_GETFD         → get_close_on_exec(fd) ? FD_CLOEXEC : 0   :331
        F_SETFD         → set_close_on_exec(fd, argi & FD_CLOEXEC) :334
        F_GETFL         → filp->f_flags                     :338
        F_SETFL         → setfl(fd, filp, argi)             :342
        ...
      }
```

## 2. 主要 `cmd` 一览

| cmd | 作用 | 操作哪一层 |
|-----|------|-----------|
| `F_DUPFD` | 复制 fd（类似 `dup`，返回 ≥ arg 的最小可用 fd） | 进程 fd 表 |
| `F_DUPFD_CLOEXEC` | 复制 fd 并置 `FD_CLOEXEC` | 进程 fd 表 |
| `F_GETFD` / `F_SETFD` | 读 / 写 **fd 标志**（主要是 `FD_CLOEXEC`） | 进程 fd 表项 |
| `F_GETFL` / `F_SETFL` | 读 / 写 **文件状态标志**（`O_APPEND`/`O_NONBLOCK`…） | 打开文件描述的 `f_flags` |
| `F_GETLK` / `F_SETLK` / `F_SETLKW` | 记录锁（字节范围锁） | 见 Ch55 |

## 3. 两组标志勿混（高频考点）

| | 存在哪 | 例子 | `dup` 后共享？ | 读写 cmd |
|--|--------|------|--------------|---------|
| **fd 标志** | 进程 fd 表项 | `FD_CLOEXEC` | 每个 fd **私有** | `F_GETFD` / `F_SETFD` |
| **文件状态标志** | 打开文件描述 | `O_APPEND`、`O_NONBLOCK` | **共享** | `F_GETFL` / `F_SETFL` |

`FD_CLOEXEC`：`exec` 时内核自动关闭该 fd，防止句柄泄漏到子程序。

## 4. 常见陷阱

**陷阱 1：`F_SETFL` 改不了访问模式**

```c
fcntl(fd, F_SETFL, O_WRONLY);  /* 无效！ */
```

`F_SETFL` 只能改 `O_APPEND`/`O_NONBLOCK`/`O_ASYNC`/`O_DIRECT` 等**状态标志**，不能改 `O_RDONLY`/`O_WRONLY`/`O_RDWR`——访问模式在 `open` 时确定，由 `setfl()`（`fs/fcntl.c:37`）校验，它会拒绝改变 `f_flags` 中的访问模式位。

**陷阱 2：`F_GETFL` 解析访问模式要 `O_ACCMODE`**

```c
int flags = fcntl(fd, F_GETFL);
int acc = flags & O_ACCMODE;   /* 正确 */
/* 错误：flags & O_WRONLY，因为 O_RDONLY == 0，永远测不出 */
```

`O_RDONLY` 通常是 `0`，`O_WRONLY`=1，`O_RDWR`=2，必须用 `O_ACCMODE` 掩码取低 2 位判断。

**陷阱 3：`F_SETFL` 会覆盖，不是按位或**

```c
fcntl(fd, F_SETFL, O_NONBLOCK);   /* 覆盖了 O_APPEND 等其他标志！ */
fcntl(fd, F_SETFL, fcntl(fd, F_GETFL) | O_NONBLOCK);  /* 正确：先读再或 */
```

**陷阱 4：`open` + `F_SETFD(FD_CLOEXEC)` 有竞态窗口**

```c
int fd = open(...);
fcntl(fd, F_SETFD, FD_CLOEXEC);  /* open 与 fcntl 之间 exec 可能泄漏 fd */
```

多线程下另一线程可能在此间隙 `exec`。用 `open(path, O_CLOEXEC)` 一步到位（见 [5.3](5.3-open-file-status-flags.md)）。

## 5. HFT / 嵌入式关联

| 场景 | 本节机制的兑现 |
|------|----------------|
| 非阻塞 fd | `F_SETFL` 设 `O_NONBLOCK` 是所有事件驱动网络代码（`epoll`）的前置 |
| 防 exec 泄漏 | `F_SETFD(FD_CLOEXEC)` / `O_CLOEXEC` 防交易子进程继承不该有的 socket/文件句柄 |
| 重定向 | `F_DUPFD` 实现安全复制 fd，避免 `dup2` 前 `close` 的竞态 |
| 设备 fd 控制 | 嵌入式设备文件（如 `/dev/ttyS0`）用 `fcntl` 设波特率/标志 |

## 6. 代码示例

```c
#include <stdio.h>
#include <fcntl.h>
#include <unistd.h>

/* fcntl: 获取/设置 fd 属性 */
int main(void) {
    int fd = open("/tmp/fcntl_test.txt", O_RDWR | O_CREAT, 0644);

    /* F_GETFL：读文件状态标志 */
    int flags = fcntl(fd, F_GETFL);
    printf("access mode: %s\n",
           (flags & O_ACCMODE) == O_RDONLY ? "RDONLY" :
           (flags & O_ACCMODE) == O_WRONLY ? "WRONLY" : "RDWR");

    /* F_SETFL：设 O_NONBLOCK（先读回再或，避免覆盖） */
    fcntl(fd, F_SETFL, flags | O_NONBLOCK);
    printf("O_NONBLOCK set: %s\n",
           (fcntl(fd, F_GETFL) & O_NONBLOCK) ? "yes" : "no");

    /* F_GETFD：读 fd 标志 */
    printf("FD_CLOEXEC: %s\n",
           (fcntl(fd, F_GETFD) & FD_CLOEXEC) ? "yes" : "no");

    close(fd);
    return 0;
}
```

<details>
<summary>代码自测（Q&A）</summary>

**Q1：`fcntl(fd, F_SETFL, flags)` 能改哪个标志？**
A：只能改**文件状态标志**：`O_APPEND`、`O_NONBLOCK`、`O_ASYNC`、`O_DIRECT` 等。**不能**改访问模式 `O_RDONLY`/`O_WRONLY`/`O_RDWR`（`open` 时确定），也不能改 `O_CREAT`/`O_EXCL`/`O_TRUNC` 这些只在 `open` 时有意义的标志。

**Q2：`FD_CLOEXEC` 是文件状态标志，存在打开文件描述里吗？**
A：不是。`FD_CLOEXEC` 是 **fd 标志**，存在**进程 fd 表项**里（每个 fd 私有，`dup` 不共享）。文件状态标志（`O_APPEND` 等）才存在打开文件描述的 `f_flags` 里。读写 `FD_CLOEXEC` 用 `F_GETFD`/`F_SETFD`，不是 `F_GETFL`/`F_SETFL`。

**Q3：`fcntl(fd, F_SETFL, O_NONBLOCK)` 有什么问题？**
A：`F_SETFL` 会**整体覆盖** `f_flags`，把已有的 `O_APPEND` 等其他标志一并清掉。正确做法是先 `F_GETFL` 读回，再 `| O_NONBLOCK`：`fcntl(fd, F_SETFL, fcntl(fd, F_GETFL) | O_NONBLOCK)`。

**Q4：`F_GETFL` 拿到 flags 后怎么判断访问模式？**
A：用 `flags & O_ACCMODE` 取低 2 位，再与 `O_RDONLY`(0)/`O_WRONLY`(1)/`O_RDWR`(2) 比较。不能直接 `flags & O_RDONLY`，因为 `O_RDONLY == 0`，任何 flags 与它相与都是 0。

**Q5：`F_DUPFD` 和 `dup` 有什么区别？**
A：`dup(fd)` 返回最小可用 fd；`F_DUPFD` 返回 **≥ 指定参数** 的最小可用 fd（可指定下限），且 `F_DUPFD_CLOEXEC` 能同时设 `FD_CLOEXEC`，避免了「复制 + 设标志」两步之间的竞态。

</details>
