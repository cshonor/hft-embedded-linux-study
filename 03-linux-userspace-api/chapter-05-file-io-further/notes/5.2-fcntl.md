## 本节讲什么

`fcntl()` 是第 5 章的**枢纽**：它一个人干了「复制文件描述符、读写标志、设异步 I/O 通知对象、记录锁、管道容量调节」五类活。本节回答四个问题：

1. `fcntl()` 的命令空间有多大？哪些属于本章、哪些属于后面的章节？
2. `F_GETFL` / `F_SETFL` 读写的是什么？为什么读回来的值**不等于**你传进去的？
3. `F_GETFD` / `F_SETFD` 和它们差在哪（一句话：一个属于「打开的文件」，一个属于「哪一个 fd」）？
4. `F_GETOWN` / `F_SETOWN` 为什么存在（谁会因为文件事件给你发信号）？

## 1. 原型与内核入口

```c
#include <fcntl.h>
int fcntl(int fd, int cmd, ... /* arg */);
/* 返回值随 cmd 而变；失败一律返回 -1 并设 errno */
```

`fcntl` 是**变参**函数：`F_GETFD`/`F_GETFL`/`F_GETOWN` 这类读取命令不需要第三个参数，其余需要。内核侧（v6.6）：

```
用户态 fcntl(fd, cmd, arg)
      ▼
SYSCALL_DEFINE3(fcntl, unsigned int, fd, unsigned int, cmd, unsigned long, arg)
                                              fs/fcntl.c:441
      ▼
do_fcntl(fd, cmd, arg, f.file)                fs/fcntl.c:316
      switch (cmd) {
      case F_DUPFD:            fs/fcntl.c:325
      case F_GETFD:            fs/fcntl.c:331
      case F_SETFD:            fs/fcntl.c:334
      case F_GETFL:            fs/fcntl.c:338
      case F_SETFL:            fs/fcntl.c:341
      case F_GETOWN:           fs/fcntl.c:367
      case F_SETOWN:           fs/fcntl.c:378
      }
```

> 32 位 ABI 走 `SYSCALL_DEFINE3(fcntl64, ...)`（`fs/fcntl.c:465`）——因为 `F_GETLK`/`F_SETLK` 的 `struct flock` 里含 64 位偏移，需要单独入口做 compat 转换。

## 3. 代码：五组命令逐个跑

完整源码 [`code/c5_2_fcntl.c`](../code/c5_2_fcntl.c)：

```c
/* c5_2_fcntl.c — §5.2 fcntl()：一个系统调用，五类活
 *
 * fcntl 是 Ch5 的枢纽。本 demo 把它最常用的几组命令逐个跑一遍：
 *   F_GETFL / F_SETFL   —— 文件状态标志（后 3 位是访问模式）
 *   F_GETFD / F_SETFD   —— 文件描述符标志（只有 FD_CLOEXEC 一个）
 *   F_DUPFD / F_DUPFD_CLOEXEC —— 按「不小于 arg」复制 fd
 *   F_GETOWN / F_SETOWN —— 异步 I/O 的信号接收者（SIGIO/SIGURG 发给谁）
 *   错误路径：未知命令 → EINVAL，坏 fd → EBADF
 *
 * 编译: gcc -O0 -Wall -Wextra -o c5_2_fcntl c5_2_fcntl.c
 */
#define _GNU_SOURCE
#include <fcntl.h>
#include <signal.h>
#include <stdio.h>
#include <string.h>
#include <unistd.h>
#include <errno.h>

/* 把 F_GETFL 的返回值里我们关心的位逐个人话化 */
static void show_fl(int fl)
{
    int acc = fl & O_ACCMODE;

    printf("    0x%05x 访问模式=%s%s%s%s%s\n", fl,
           acc == O_RDONLY ? "O_RDONLY" : acc == O_WRONLY ? "O_WRONLY" :
           acc == O_RDWR ? "O_RDWR" : "?",
           (fl & O_APPEND) ? " | O_APPEND" : "",
           (fl & O_NONBLOCK) ? " | O_NONBLOCK" : "",
           (fl & O_ASYNC) ? " | O_ASYNC(FASYNC)" : "",
           (fl & O_LARGEFILE) ? " | O_LARGEFILE(内核补的)" : "");
}

int main(void)
{
    const char *p = "/tmp/c5_fcntl.txt";
    int fd = open(p, O_RDWR | O_CREAT | O_TRUNC, 0644);

    if (fd < 0) {
        perror("open");
        return 1;
    }
    write(fd, "hello", 5);

    printf("== 1. F_GETFL / F_SETFL：文件状态标志 ==\n");
    printf("  open 时给的 O_RDWR，F_GETFL 读回来是：\n");
    show_fl(fcntl(fd, F_GETFL));
    printf("  F_SETFL(O_NONBLOCK) 之后：\n");
    if (fcntl(fd, F_SETFL, fcntl(fd, F_GETFL) | O_NONBLOCK) == -1)
        perror("F_SETFL");
    show_fl(fcntl(fd, F_GETFL));
    printf("  注意 O_LARGEFILE(0x8000) 不是 open 时写的，是内核在 fs/open.c 里补的\n");

    printf("\n== 2. F_GETFD / F_SETFD：文件描述符标志（只有 CLOEXEC）==\n");
    printf("  初始 F_GETFD = 0x%x（FD_CLOEXEC=0x%x 未置位）\n", fcntl(fd, F_GETFD), FD_CLOEXEC);
    fcntl(fd, F_SETFD, FD_CLOEXEC);
    printf("  F_SETFD(FD_CLOEXEC) 后 F_GETFD = 0x%x\n", fcntl(fd, F_GETFD));

    printf("\n== 3. F_DUPFD / F_DUPFD_CLOEXEC：按最小值复制 ==\n");
    {
        int a = fcntl(fd, F_DUPFD, 50);              /* 不小于 50 的最小可用号 */
        int b = fcntl(fd, F_DUPFD_CLOEXEC, 60);      /* 同上，且带 FD_CLOEXEC */

        printf("  F_DUPFD(50)         -> %d, F_GETFD=0x%x\n", a, a >= 0 ? fcntl(a, F_GETFD) : 0);
        printf("  F_DUPFD_CLOEXEC(60) -> %d, F_GETFD=0x%x（CLOEXEC 已在）\n",
               b, b >= 0 ? fcntl(b, F_GETFD) : 0);
        if (a >= 0) close(a);
        if (b >= 0) close(b);
    }

    printf("\n== 4. F_GETOWN / F_SETOWN：异步 I/O 的通知对象 ==\n");
    printf("  F_GETOWN 初始 = %d\n", fcntl(fd, F_GETOWN));
    if (fcntl(fd, F_SETOWN, getpid()) == -1)
        perror("F_SETOWN");
    printf("  F_SETOWN(getpid()=%ld) 后 F_GETOWN = %d\n", (long) getpid(), fcntl(fd, F_GETOWN));

    printf("\n== 5. 错误路径 ==\n");
    {
        /* 注意：调用必须先做完再取 errno。写成 printf(..., fcntl(...), errno)
           会因为求值顺序而读到调用之前的旧 errno（这里会错报成 0）。 */
        int rc = fcntl(fd, 0x7fffffff);          /* 未知命令 */

        printf("  fcntl(fd, 0x7fffffff) -> %d errno=%d (%s)\n",
               rc, errno, strerror(errno));
    }
    {
        int rc = fcntl(999, F_GETFL);            /* 坏 fd */

        printf("  fcntl(999, F_GETFL)   -> %d errno=%d (%s)\n",
               rc, errno, strerror(errno));
    }

    close(fd);
    return 0;
}
```

编译运行：

```bash
gcc -O0 -Wall -Wextra -o c5_2_fcntl c5_2_fcntl.c && ./c5_2_fcntl
```

CE（gcc 13.3.0 / x86-64 / Ubuntu 24.04）实测：

```text
== 1. F_GETFL / F_SETFL：文件状态标志 ==
  open 时给的 O_RDWR，F_GETFL 读回来是：
    0x08002 访问模式=O_RDWR
  F_SETFL(O_NONBLOCK) 之后：
    0x08802 访问模式=O_RDWR | O_NONBLOCK
  注意 O_LARGEFILE(0x8000) 不是 open 时写的，是内核在 fs/open.c 里补的

== 2. F_GETFD / F_SETFD：文件描述符标志（只有 CLOEXEC）==
  初始 F_GETFD = 0x0（FD_CLOEXEC=0x1 未置位）
  F_SETFD(FD_CLOEXEC) 后 F_GETFD = 0x1

== 3. F_DUPFD / F_DUPFD_CLOEXEC：按最小值复制 ==
  F_DUPFD(50)         -> 50, F_GETFD=0x0
  F_DUPFD_CLOEXEC(60) -> 60, F_GETFD=0x1（CLOEXEC 已在）

== 4. F_GETOWN / F_SETOWN：异步 I/O 的通知对象 ==
  F_GETOWN 初始 = 0
  F_SETOWN(getpid()=2) 后 F_GETOWN = 2

== 5. 错误路径 ==
  fcntl(fd, 0x7fffffff) -> -1 errno=22 (Invalid argument)
  fcntl(999, F_GETFL)   -> -1 errno=9 (Bad file descriptor)
```

逐条看：

| 观察 | 说明 |
|------|------|
| `open(..., O_RDWR)` 之后 `F_GETFL = 0x08002` | `0x2` 是 `O_RDWR`；`0x8000` 是内核补的 `O_LARGEFILE`（`fs/open.c:1444` 一带）。**读回来的值 ≠ 你传进去的 flags** |
| `F_SETFL(O_NONBLOCK)` → `0x08802` | 只多了 `0x800`。demo 里写的是 `fcntl(fd, F_SETFL, fcntl(fd, F_GETFL) \| O_NONBLOCK)`——**必须读-改-写**，因为 `F_SETFL` 会整体覆盖状态位（见第 4 节） |
| `F_GETFD` 初始 `0x0`，`F_SETFD(FD_CLOEXEC)` 后 `0x1` | `F_GETFD`/`F_SETFD` 只有一位有意义（`FD_CLOEXEC = 0x1`），和 `F_GETFL` 那堆 `O_*` 完全是两套 |
| `F_DUPFD(50)` → `50`，`F_DUPFD_CLOEXEC(60)` → `60` 且 `F_GETFD=0x1` | 「不小于 arg 的最小可用号」。`F_DUPFD_CLOEXEC` 顺手置上 `FD_CLOEXEC`——这是「复制 fd 又不泄漏给 `exec`」的原子做法 |
| `F_GETOWN` 初始 `0`，`F_SETOWN(getpid())` 后 `2` | 未设置时是 `0`（无接收者）。设成本进程 pid 后读回同一个数 |
| `fcntl(fd, 0x7fffffff)` → `EINVAL` | 未知命令。**注意不是 `ENOTTY`**——`fcntl` 用 `EINVAL` 表达「不认识这条命令」，`ioctl` 才用 `ENOTTY`（见 [4.8](../../chapter-04-file-io-universal/notes/4.8-ioctl.md)） |
| `fcntl(999, F_GETFL)` → `EBADF` | 坏 fd。读写命令都先校验 fd（`fdget` 失败即 `-EBADF`） |

> **代码纪律：`errno` 必须先取值再打印。** 本 demo 初版写成 `printf("... errno=%d", fcntl(...), errno)`，gcc 的求值顺序不确定，读到的是调用**之前**的旧 `errno`，八处全错报成 `Success`。现在源码里是 `int rc = fcntl(...); printf(..., rc, errno, ...)`。

## 4. `F_SETFL` 的语义细节

`F_SETFL` 的内核实现在 `fs/fcntl.c:37` 的 `setfl()`。它先做一串校验，最后才是那一行关键赋值（`:81`）：

```c
filp->f_flags = (arg & SETFL_MASK) | (filp->f_flags & ~SETFL_MASK);
```

含义：**`arg` 里只有落在 `SETFL_MASK` 内的位会被采纳，其余位一律保留原值**。而 `SETFL_MASK` 是（`fs/fcntl.c:35`）：

```c
#define SETFL_MASK (O_APPEND | O_NONBLOCK | O_NDELAY | O_DIRECT | O_NOATIME)
```

这一个宏就解释了「为什么 `F_SETFL` 改不了访问模式、也改不了 `O_CREAT`」——它们根本不在掩码里。完整实测见 [5.3](5.3-open-file-status-flags.md)。

`setfl()` 在赋值前还会做几项检查（读源码才看得见的那部分）：

| 检查 | 位置 | 失败返回 |
|------|------|---------|
| 只增文件上**不能清除** `O_APPEND`（`IS_APPEND(inode)`） | `fs/fcntl.c:46-47` | `-EPERM` |
| `O_NOATIME` 只能由属主或 superuser **首次设置** | `fs/fcntl.c:50-52` | `-EPERM` |
| `O_NDELAY` 顺带补上 `O_NONBLOCK`（SunOS 兼容） | `fs/fcntl.c:55-57` | — |
| 非 FIFO 上开 `O_DIRECT` 而文件系统不支持 | `fs/fcntl.c:60-63` | `-EINVAL` |
| 调用 `f_op->check_flags`（文件系统自定义校验） | `fs/fcntl.c:65-66` | 文件系统决定 |
| `FASYNC` 交给 `f_op->fasync` 去设（见第 5 节） | `fs/fcntl.c:71-79` | 文件系统决定 |

## 5. `F_GETOWN` / `F_SETOWN`：异步 I/O 的通知对象

只要一个 fd 被设成异步模式（`O_ASYNC` 或 `F_SETFL(FASYNC)`），有事件时内核会发 `SIGIO`——**发给谁**就由 `F_SETOWN` 决定。`f_owner` 存在打开文件描述里（`struct file`）：

```
F_SETOWN     → f_setown(filp, who, force)          fs/fcntl.c:115
                 └─ __f_setown(filp, pid, type, force)   fs/fcntl.c:107
                    写 filp->f_owner.pid / .uid / .pid_type
F_GETOWN     → f_getown(filp)                      fs/fcntl.c:151
F_SETOWN_EX  → f_setown_ex(filp, arg)              fs/fcntl.c:167
F_GETOWN_EX  → f_getown_ex(filp, arg)              fs/fcntl.c:207
F_GETOWNER_UIDS → f_getowner_uids(filp, arg)       fs/fcntl.c:247
```

| 参数 | 含义 |
|------|------|
| 正数 | 发给该 **PID** 的进程 |
| 负数 | 发给进程组 ID 为 `-who` 的**所有进程** |
| `_EX` 变体 | 用 `struct f_owner_ex` 明确指定 `F_OWNER_PID` / `F_OWNER_PGRP` / `F_OWNER_TID` |

> `O_ASYNC` 有个著名的坑：普通文件上 `F_SETFL(O_ASYNC)` **静默失败**——`SETFL_MASK` 里没有 `FASYNC`，它要靠 `f_op->fasync` 钩子设（`fs/fcntl.c:71` 注释原文：`->fasync() is responsible for setting the FASYNC bit.`），而普通文件没有这个钩子。同一段代码换到管道就生效（`fs/pipe.c:1230` 有 `.fasync = pipe_fasync`）。完整实测见 [5.3](5.3-open-file-status-flags.md)。

## 6. HFT / 嵌入式关联

| 场景 | 本节机制的兑现 |
|------|----------------|
| 运行时切非阻塞 | `fcntl(fd, F_SETFL, F_GETFL\|O_NONBLOCK)` 是 socket/管道改非阻塞的标准姿势，不必重开 fd（保住已建立的连接） |
| 必须读-改-写 | `F_SETFL` 整体覆盖状态位（`fs/fcntl.c:81`），直接传 `O_NONBLOCK` 会把访问模式抹成 `O_RDONLY`；封装时别省那一次 `F_GETFL` |
| `F_DUPFD_CLOEXEC` | 起子进程（风控沙箱、插件回测）时复制 fd 又不泄漏——一条命令完成「复制 + 设 CLOEXEC」，没有两步之间的窗口 |
| 异步通知 | `F_SETOWN` + `O_ASYNC` 是 `SIGIO` 驱动模型的开关；如今更常用 `epoll`/`io_uring`（[Ch63](../../chapter-63-alternative-i-o-models/notes/63.3-signal-driven-i-o.md)），但老设备驱动仍走这条路 |
| 嵌入式设备 fd | 设备节点同样吃 `fcntl`：`F_GETFL` 查访问模式、`F_SETFL` 切 `O_NONBLOCK`（串口读必须非阻塞或 `VMIN=0`） |
| 错误码辨析 | `fcntl` 未知命令 → `EINVAL`；`ioctl` 未知命令 → `ENOTTY`。日志里看到哪个，能直接判断是哪个调用出的问题 |

<summary>代码自测（Q&A）</summary>

**Q1：为什么 `F_GETFL` 读回来的值不等于你 `open` 时传的 `flags`？**
A：因为内核会按平台补位。实测 `open(p, O_RDWR|O_CREAT|O_TRUNC, 0644)` 之后 `F_GETFL = 0x08002`，比 `O_RDWR`(`0x2`) 多出 `0x8000`——那是内核在 `open` 入口补的 `O_LARGEFILE`（`fs/open.c:1444` 一带）。所以判断访问模式必须用 `O_ACCMODE` 掩码取低 2 位，不能直接比整数。

**Q2：`F_SETFL` 会不会覆盖掉别的状态位？**
A：会。`fs/fcntl.c:81` 是 `filp->f_flags = (arg & SETFL_MASK) | (filp->f_flags & ~SETFL_MASK);`——`arg` 在 `SETFL_MASK`（`fs/fcntl.c:35`）内的位**整体替换**。所以标准写法是 `fcntl(fd, F_SETFL, fcntl(fd, F_GETFL) | O_NONBLOCK)`，不能只传 `O_NONBLOCK`。

**Q3：`F_GETFD` 和 `F_GETFL` 有什么区别？**
A：`F_GETFD` 读的是**文件描述符标志**，只有 `FD_CLOEXEC` 一位有意义（实测 `0x0` ↔ `0x1`）；`F_GETFL` 读的是**文件状态标志**（访问模式 + `O_APPEND`/`O_NONBLOCK`/…）。前者属于「哪一个 fd」，后者属于「打开的文件」——`dup` 之后共享的是后者。

**Q4：`F_DUPFD` 和 `dup2` 有什么分工？**
A：`dup2(old, new)` 指定一个**确切**的目标号（必要时先关掉占用者）；`fcntl(fd, F_DUPFD, min)` 只要求「不小于 `min`」。后者是前者的**原子替代品**——`close(new)` + `fcntl(F_DUPFD, new)` 两步里目标号不会被抢（实测 `F_DUPFD(50) -> 50`）。`F_DUPFD_CLOEXEC` 再多做一件事：顺手置上 `FD_CLOEXEC`（实测 `F_GETFD=0x1`）。

**Q5：`F_SETOWN` 里的负数参数是什么含义？**
A：正数是 pid（发给单个进程），负数是进程组 —— 发给进程组 ID 为 `-who` 的所有进程。要精确指定「进程 / 进程组 / 线程」，用 `F_SETOWN_EX`（`fs/fcntl.c:167`）配 `struct f_owner_ex`。

**Q6：为什么 `F_SETFL(O_ASYNC)` 在普通文件上设不上？**
A：因为 `SETFL_MASK`（`fs/fcntl.c:35`）里**没有 `FASYNC`**。它由 `f_op->fasync` 钩子单独处理（`fs/fcntl.c:71` 注释：`->fasync() is responsible for setting the FASYNC bit.`），普通文件没有这个钩子，所以既不报错也不生效。同一段代码在管道上就成功（`fs/pipe.c:1230` 有 `.fasync = pipe_fasync`）。
