# 5.11 `/dev/fd` — 通过路径访问已打开的 fd

## 本节讲什么

`/dev/fd/N` 让你「用路径名」去访问一个**已经打开**的文件描述符 N。本节回答三个问题：

1. `open("/dev/fd/N")` 到底做了什么？和 `dup(N)` 是一回事吗？
2. `/dev/fd` 在 Linux 上的真实实现是什么？
3. 为什么 shell 脚本里会看到 `cmd < /dev/fd/3` 这种写法？

---

## 1. 语义：`open("/dev/fd/N")` ≈ 复制 fd N

```c
int fd = open("/dev/fd/0", O_RDONLY);   /* 约等于 dup(0)，得到 stdin 的副本 */
```

`open("/dev/fd/N")` 返回一个**新的 fd**，它指向与 fd N **相同的打开文件描述**——等价于 `dup(N)` 的效果（共享偏移与状态标志，见 [5.4](5.4-fd-and-open-files.md) / [5.5](5.5-duplicating-fds.md)）。

> ⚠️ 细节差异：`open("/dev/fd/N", flags)` 不是无条件等于 `dup(N)`——`open` 传入的 `flags`（如访问模式）必须与 fd N 的打开方式**兼容**。例如 fd N 是只读的，`open("/dev/fd/N", O_WRONLY)` 会失败。且 `/dev/fd/N` 走的是路径解析（procfs 符号链接），而 `dup` 直接复制 fd 表项，二者语义近似但路径不同。

## 2. Linux 实现：`/dev/fd` → `/proc/self/fd`

Linux 上 `/dev/fd` 本身是一个**符号链接**，指向 `/proc/self/fd`：

```
/dev/fd          ──(符号链接)──▶  /proc/self/fd
/dev/fd/0        ──▶  /proc/self/fd/0   ← fd 0（stdin）的「魔符号链接」
/dev/fd/1        ──▶  /proc/self/fd/1   ← fd 1（stdout）
```

`/proc/self/fd/N` 是 **magic symlink（魔符号链接）**：内核不按普通路径解析它，而是识别出「这是当前进程的 fd N」，进而把 `open` 变成对 fd N 的复制（引用同一个 `struct file`）。实现位于 `fs/proc/fd.c`（procfs 的 `proc_fd_link` / `tid_fd_revalidate`）。

## 3. 用途

- **shell 重定向**：`cmd < /dev/fd/3` 让 `cmd` 的 stdin 指向「当前 shell 的 fd 3」——常用于把已打开的文件描述符传给子进程。
- **弥补 exec 无法传 fd**：`exec` 只能继承 fd 0/1/2 或 `FD_CLOEXEC` 未设的 fd，`/dev/fd/N` 提供了一种「用路径间接引用 fd」的补充手段。
- **C 里复制 fd 的路径化写法**：`open("/dev/fd/1", O_WRONLY)` 得到 stdout 副本。

## 4. HFT / 嵌入式关联

| 场景 | 本节机制的兑现 |
|------|----------------|
| shell 编排进程 | 交易脚本用 `/dev/fd/N` 在管道间传递 fd，避免 `dup` 手写 |
| 调试/工具链 | 把已打开的 socket/日志 fd 以路径形式交给子工具 |
| 嵌入式脚本 | busybox shell 下用 `/dev/fd/N` 做重定向（若无 `/proc` 挂载则不可用） |

## 5. 代码示例

```c
#include <fcntl.h>
#include <unistd.h>
#include <stdio.h>

/* /dev/fd/N: 打开等价于复制 fd N */
int main(void) {
    /* 打开 /dev/fd/1 得到 stdout 的副本 */
    int fd2 = open("/dev/fd/1", O_WRONLY);
    if (fd2 < 0) { perror("open /dev/fd/1"); return 1; }
    write(fd2, "via /dev/fd/1\n", 14);
    printf("open(\"/dev/fd/1\") = fd %d\n", fd2);

    close(fd2);
    return 0;
}
```

<details>
<summary>代码自测（Q&A）</summary>

**Q1：`open("/dev/fd/N", O_RDONLY)` 和 `dup(N)` 是一回事吗？**
A：**效果近似但不完全等价**。两者都得到「指向同一打开文件描述」的新 fd（共享偏移/状态标志）。但 `open("/dev/fd/N")` 走路径解析（procfs 魔符号链接），传入的 `flags` 必须与 fd N 的打开方式兼容；`dup(N)` 直接复制 fd 表项，无 flags 校验。`dup` 更快更直接，`/dev/fd/N` 主要用于「用路径引用 fd」的场景。

**Q2：Linux 上 `/dev/fd` 的真实实现是什么？**
A：`/dev/fd` 是**符号链接**，指向 `/proc/self/fd`。`/proc/self/fd/N` 是「魔符号链接（magic symlink）」，内核不按普通路径解析，而是把它识别为当前进程的 fd N，把 `open` 变成对 fd N 的引用复制。实现位于 `fs/proc/fd.c`。

**Q3：`open("/dev/fd/N", O_WRONLY)` 在什么情况下会失败？**
A：当 fd N 不是以可写方式打开时（如 stdin 是只读的），`open("/dev/fd/0", O_WRONLY)` 会失败——因为请求的访问模式与 fd N 的实际打开模式不兼容。`dup` 则无此限制。

**Q4：shell 里 `cmd < /dev/fd/3` 是什么意思？**
A：让 `cmd` 的 stdin 指向「当前 shell 的 fd 3」。即把 shell 已打开的 fd 3 以路径方式传给子进程，等价于把 fd 3 重定向到 cmd 的 stdin（fd 0）。

**Q5：嵌入式环境用 `/dev/fd/N` 有什么前提？**
A：需要 `/proc` 文件系统**已挂载**（因为 `/dev/fd` 指向 `/proc/self/fd`）。若嵌入式/busybox 环境未挂载 `/proc`，`/dev/fd/N` 不可用，此时应直接用 `dup`/`dup2` 复制 fd。

</details>
