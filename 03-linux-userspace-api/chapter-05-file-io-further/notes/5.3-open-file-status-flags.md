# 5.3 打开文件状态标志（Open File Status Flags）

## 本节讲什么

上一节讲了 `fcntl()` 的 `F_GETFL`/`F_SETFL`，本节聚焦它们操作的对象——**打开文件状态标志（open file status flags）**。回答四个问题：

1. `f_flags` 里到底有哪些位？怎么正确解析访问模式？
2. 哪些标志可以事后用 `F_SETFL` 改，哪些只能在 `open` 时定死？
3. `F_SETFL` 改不了的时候**会不会报错**？（答案会颠覆直觉）
4. 为什么同一段设 `O_ASYNC` 的代码，在普通文件上「没反应」、换到管道就生效？

第 3、4 问是本节的**两个反直觉现场**，都跑了实测。

---

## 1. 两组标志：先分清层

`fcntl` 的两组读写命令操作的是**两个不同层次**的东西——这是本章最容易混的一处：

| | 文件描述符标志（fd flags） | 打开文件状态标志（status flags） |
|---|---|---|
| 读写命令 | `F_GETFD` / `F_SETFD` | `F_GETFL` / `F_SETFL` |
| 存哪 | 进程 fd 表项（`files_struct` 的一枚位） | 打开文件表项（`struct file->f_flags`） |
| 只有一个成员 | ✅ `FD_CLOEXEC` | ❌ 一堆 `O_*` |
| `dup` 后 | **不共享** | **共享** |

> 判断口诀：**「这个标志是描述『打开的文件』的，还是描述『哪一个 fd』的？」** `FD_CLOEXEC` 是「exec 时要不要关掉**这个号**」——明显属于 fd；`O_APPEND` 是「写的时候要不要跳到末尾」——属于打开的文件。

## 2. `f_flags` 里的位分三类

| 类别 | 成员 | 能否用 `F_SETFL` 事后改 |
|------|------|------------------------|
| **访问模式** | `O_RDONLY`(0) / `O_WRONLY`(1) / `O_RDWR`(2)，占 `O_ACCMODE` 掩码 `0x3` | ❌ **永远不能**（`open` 那一刻定死） |
| **持续状态** | `O_APPEND` / `O_NONBLOCK`(`O_NDELAY`) / `O_ASYNC`(`FASYNC`) / `O_DIRECT` / `O_NOATIME` | ✅ 能（就是 `SETFL_MASK` 那五个） |
| **`open` 一次性开关** | `O_CREAT` / `O_EXCL` / `O_TRUNC` / `O_NOCTTY` | ❌ 不是「持续状态」，事后设了也无效 |

第三类为什么「不是持续状态」？因为它们是**动作**不是**属性**——`O_TRUNC` 的意思是「打开的时候顺手清空」，文件已经打开了，「打开的时候」这个时刻早就过去了。内核在 `fs/open.c:945` 甚至主动把它们**从 `f_flags` 里清掉**：

```c
f->f_flags &= ~(O_CREAT | O_EXCL | O_NOCTTY | O_TRUNC);
```

所以事后你**根本读不到**这些位——第 3 节的实测正好证实这一点。

## 3. 代码：四段实测

完整源码 [`code/c5_3_status_flags.c`](../code/c5_3_status_flags.c)：

```c
/* c5_3_status_flags.c — §5.3 打开文件状态标志：哪些能在 open 之后改？
 *
 * 关键事实：F_SETFL 只能改「状态标志」里的一小撮，而且访问模式（O_RDONLY/
 * O_WRONLY/O_RDWR）**改不了**——它是 open 那一刻就定死的。内核里干这件事的是
 * fs/fcntl.c 的 setfl()：它只认 O_APPEND / FASYNC / O_NONBLOCK / O_DIRECT /
 * O_NOATIME，其余位直接无视（不报错，静默忽略）。
 *
 * 演示四件事：
 *   1) F_SETFL 能改的：O_APPEND / O_ASYNC / O_NONBLOCK（读回 F_GETFL 验证）
 *   2) F_SETFL 改不了的：O_CREAT / O_TRUNC / O_EXCL —— 静默忽略
 *   3) 访问模式改不了：只读 fd 上 F_SETFL(O_WRONLY) 之后照样写不进去
 *   4) 状态标志属于「打开文件表项」：dup 出来的 fd 共享它
 *
 * 编译: gcc -O0 -Wall -Wextra -o c5_3_status_flags c5_3_status_flags.c
 */
#define _GNU_SOURCE
#include <fcntl.h>
#include <stdio.h>
#include <string.h>
#include <unistd.h>
#include <errno.h>

static const char *accmode(int fl)
{
    switch (fl & O_ACCMODE) {
    case O_RDONLY: return "O_RDONLY";
    case O_WRONLY: return "O_WRONLY";
    case O_RDWR:   return "O_RDWR";
    default:       return "?";
    }
}

int main(void)
{
    const char *p = "/tmp/c5_status.txt";
    int fd = open(p, O_WRONLY | O_CREAT | O_TRUNC, 0644);

    if (fd < 0) {
        perror("open");
        return 1;
    }
    write(fd, "0123456789", 10);

    printf("== 1. F_SETFL 能改的标志 ==\n");
    printf("  起始: F_GETFL=0x%05x (%s) O_APPEND=%d O_ASYNC=%d O_NONBLOCK=%d\n",
           fcntl(fd, F_GETFL), accmode(fcntl(fd, F_GETFL)),
           !!(fcntl(fd, F_GETFL) & O_APPEND), !!(fcntl(fd, F_GETFL) & O_ASYNC),
           !!(fcntl(fd, F_GETFL) & O_NONBLOCK));

    for (int i = 0; i < 3; i++) {
        int bit = i == 0 ? O_APPEND : i == 1 ? O_ASYNC : O_NONBLOCK;
        const char *nm = i == 0 ? "O_APPEND" : i == 1 ? "O_ASYNC" : "O_NONBLOCK";

        int fl = fcntl(fd, F_GETFL);

        if (fcntl(fd, F_SETFL, fl | bit) == -1)
            printf("  F_SETFL(%s) 失败: %s\n", nm, strerror(errno));
        else
            printf("  F_SETFL(%s) -> F_GETFL=0x%05x，该位=%d\n",
                   nm, fcntl(fd, F_GETFL), !!(fcntl(fd, F_GETFL) & bit));
        /* 复位，免得互相干扰 */
        fcntl(fd, F_SETFL, fcntl(fd, F_GETFL) & ~bit);
    }

    printf("    为什么 O_ASYNC 这一行没设上？看内核 v6.6 fs/fcntl.c:35：\n");
    printf("      #define SETFL_MASK (O_APPEND | O_NONBLOCK | O_NDELAY | O_DIRECT | O_NOATIME)\n");
    printf("    这个掩码里**没有 FASYNC**；同文件还有一句注释：\n");
    printf("      \"->fasync() is responsible for setting the FASYNC bit.\"\n");
    printf("    也就是说它要靠 file_operations->fasync 钩子去设。普通文件没有这个钩子，\n");
    printf("    于是 F_SETFL(O_ASYNC) 既不报错、也不生效 —— 「静默失败」的典型。\n");
    {
        int pp[2];

        if (pipe(pp) == 0) {                     /* 管道有 .fasync = pipe_fasync */
            int fl = fcntl(pp[0], F_GETFL);

            if (fcntl(pp[0], F_SETFL, fl | O_ASYNC) == -1)
                printf("    管道上 F_SETFL(O_ASYNC) 失败: %s\n", strerror(errno));
            else
                printf("    同一段代码换到管道（fs/pipe.c:1230 有 .fasync）：F_GETFL=0x%05x，"
                       "O_ASYNC 位=%d\n",
                       fcntl(pp[0], F_GETFL), !!(fcntl(pp[0], F_GETFL) & O_ASYNC));
            close(pp[0]);
            close(pp[1]);
        }
    }

    printf("\n== 2. F_SETFL 改不了的标志（静默忽略，不报错）==\n");
    {
        int before = fcntl(fd, F_GETFL);
        int rc = fcntl(fd, F_SETFL, before | O_CREAT | O_TRUNC | O_EXCL);
        int after = fcntl(fd, F_GETFL);

        printf("  F_SETFL(O_CREAT|O_TRUNC|O_EXCL) 返回 %d（成功），但：\n", rc);
        printf("    before=0x%05x  after=0x%05x  变化=0x%05x\n",
               before, after, before ^ after);
        printf("    O_CREAT=%d O_TRUNC=%d O_EXCL=%d —— 一个都没进去\n",
               !!(after & O_CREAT), !!(after & O_TRUNC), !!(after & O_EXCL));
        printf("  O_CREAT/O_TRUNC/O_EXCL 是「open 时的一次性开关」，不是持续状态\n");
    }

    printf("\n== 3. 访问模式改不了 ==\n");
    {
        int rfd = open(p, O_RDONLY);

        fcntl(rfd, F_SETFL, fcntl(rfd, F_GETFL) | O_WRONLY);
        printf("  只读 fd 上 F_SETFL(O_WRONLY) 后 F_GETFL 的访问模式 = %s\n",
               accmode(fcntl(rfd, F_GETFL)));
        errno = 0;
        ssize_t n = write(rfd, "X", 1);
        printf("  往里 write -> %ld errno=%d (%s)\n", (long) n, errno, strerror(errno));
        close(rfd);
    }

    printf("\n== 4. 状态标志跟着「打开文件表项」走，所以 dup 出来的 fd 共享 ==\n");
    {
        int d = dup(fd);

        printf("  dup 前: fd F_GETFL=0x%05x  dup-fd F_GETFL=0x%05x\n",
               fcntl(fd, F_GETFL), fcntl(d, F_GETFL));
        fcntl(d, F_SETFL, fcntl(d, F_GETFL) | O_APPEND);   /* 只动 dup 的那个 */
        printf("  只对 dup-fd 设 O_APPEND 后：\n");
        printf("    fd     F_GETFL=0x%05x O_APPEND=%d\n",
               fcntl(fd, F_GETFL), !!(fcntl(fd, F_GETFL) & O_APPEND));
        printf("    dup-fd F_GETFL=0x%05x O_APPEND=%d  ← 两个一起变\n",
               fcntl(d, F_GETFL), !!(fcntl(d, F_GETFL) & O_APPEND));
        close(d);
    }

    close(fd);
    return 0;
}
```

编译运行：

```bash
gcc -O0 -Wall -Wextra -o c5_3_status_flags c5_3_status_flags.c && ./c5_3_status_flags
```

CE（gcc 13.3.0 / x86-64 / Ubuntu 24.04）实测：

```text
== 1. F_SETFL 能改的标志 ==
  起始: F_GETFL=0x08001 (O_WRONLY) O_APPEND=0 O_ASYNC=0 O_NONBLOCK=0
  F_SETFL(O_APPEND) -> F_GETFL=0x08401，该位=1
  F_SETFL(O_ASYNC) -> F_GETFL=0x08001，该位=0
  F_SETFL(O_NONBLOCK) -> F_GETFL=0x08801，该位=1
    为什么 O_ASYNC 这一行没设上？看内核 v6.6 fs/fcntl.c:35：

    这个掩码里**没有 FASYNC**；同文件还有一句注释：
      "->fasync() is responsible for setting the FASYNC bit."
    也就是说它要靠 file_operations->fasync 钩子去设。普通文件没有这个钩子，
    于是 F_SETFL(O_ASYNC) 既不报错、也不生效 —— 「静默失败」的典型。
    同一段代码换到管道（fs/pipe.c:1230 有 .fasync）：F_GETFL=0x02000，O_ASYNC 位=1

== 2. F_SETFL 改不了的标志（静默忽略，不报错）==
  F_SETFL(O_CREAT|O_TRUNC|O_EXCL) 返回 0（成功），但：
    before=0x08001  after=0x08001  变化=0x00000
    O_CREAT=0 O_TRUNC=0 O_EXCL=0 —— 一个都没进去
  O_CREAT/O_TRUNC/O_EXCL 是「open 时的一次性开关」，不是持续状态

== 3. 访问模式改不了 ==
  只读 fd 上 F_SETFL(O_WRONLY) 后 F_GETFL 的访问模式 = O_RDONLY
  往里 write -> -1 errno=9 (Bad file descriptor)

== 4. 状态标志跟着「打开文件表项」走，所以 dup 出来的 fd 共享 ==
  dup 前: fd F_GETFL=0x08001  dup-fd F_GETFL=0x08001
  只对 dup-fd 设 O_APPEND 后：
    fd     F_GETFL=0x08401 O_APPEND=1
    dup-fd F_GETFL=0x08401 O_APPEND=1  ← 两个一起变
```

逐条看：

| 观察 | 说明 |
|------|------|
| 起始 `F_GETFL=0x08001` | `0x1` = `O_WRONLY`，`0x8000` = 内核补的 `O_LARGEFILE`。**解析访问模式要用 `O_ACCMODE`（`0x3`）掩码**，本 demo 用 `accmode()` 助手做这件事 |
| `F_SETFL(O_APPEND)` / `(O_NONBLOCK)` 都成功（`0x08401` / `0x08801`） | 这两个都在 `SETFL_MASK` 里 |
| `F_SETFL(O_ASYNC)` → **位仍是 0，且没有报错** | **本节第一个反直觉现场**。`O_ASYNC` 与 `FASYNC` 是同一个位；掩码里没有它，普通文件也没有 `f_op->fasync` 钩子 → **静默失败** |
| 同段代码在**管道**上：`F_GETFL=0x02000`，`O_ASYNC` 位=1 | 对照组成立。`fs/pipe.c:1230` 有 `.fasync = pipe_fasync`，钩子在，`setfl()` 才能通过它把位置上 |
| `F_SETFL(O_CREAT\|O_TRUNC\|O_EXCL)` 返回 `0`，`before == after`，变化 `0x00000` | **本节第二个反直觉现场**：`F_SETFL` **不报错**。这三个位被 `fs/open.c:945` 从 `f_flags` 里清掉了，又不在 `SETFL_MASK` 里，所以「什么都不做」就是它的行为 |
| 只读 fd 上 `F_SETFL(O_WRONLY)`，访问模式仍是 `O_RDONLY`，`write` → `EBADF` | 访问模式**不在掩码里**，改不动。而且 `f_mode` 里的 `FMODE_WRITE` 早在 `open` 时就没设，所以 `write` 被 `EBADF` 拦住 |
| 只对 `dup-fd` 设 `O_APPEND`，`fd` 的 `O_APPEND` 也变 1 | 状态标志在打开文件表项里，`dup` 出来的两个 fd 指向**同一个**表项 → 共享。这也预告了 [5.4](5.4-fd-and-open-files.md) 的三层结构 |

## 4. 「静默失败」为什么值得单独讲

第 2、第 3 段实测暴露的同一个模式：

> **`fcntl(fd, F_SETFL, x)` 返回 0，不代表 `x` 生效了。**

它的真实语义是「把 `f_flags` 里 `SETFL_MASK` 覆盖的位换成 `arg & SETFL_MASK`」——**掩码之外的入参被无声丢弃**。`arg` 里只有 `O_CREAT` 这种全不在掩码内的位时，这个调用就是一次「什么都没做的成功」。

工程上的后果：

- 想「把只读 fd 改成可写」→ 以为 `F_SETFL(O_WRONLY)` 就行 → **实际什么都没发生**，错误在几十行之后的 `write` 才暴露（`EBADF`，且容易被误判成 fd 泄漏）。
- 想「设 `O_ASYNC`」→ 普通文件上静默无效 → 上层的 `SIGIO` 永远不来，排查方向容易跑偏到信号。

**防御姿势**：改完之后**立刻 `F_GETFL` 读回**验证。这正是本 demo 每一段都在做的事。

## 5. `setfl()` 的完整校验清单

`fs/fcntl.c:37` 的 `setfl()` 在最后那行赋值（`:81`）之前，有一串「先拦后改」的检查。这些是**书上不会写、读源码才有**的部分：

| 顺序 | 检查 | 位置 | 结果 |
|------|------|------|------|
| 1 | 只增文件（`IS_APPEND(inode)`）上想**清掉** `O_APPEND` | `:46-47` | `-EPERM` |
| 2 | 非属主/root 想**首次**设 `O_NOATIME` | `:50-52` | `-EPERM` |
| 3 | `arg` 含 `O_NDELAY` 且 `O_NONBLOCK != O_NDELAY` → 补上 `O_NONBLOCK` | `:55-57` | 继续 |
| 4 | 非 FIFO 上设 `O_DIRECT`，但文件不支持（无 `FMODE_CAN_ODIRECT`） | `:60-63` | `-EINVAL` |
| 5 | 文件系统的 `f_op->check_flags(arg)` | `:65-66` | 由文件系统决定 |
| 6 | `FASYNC` 交给 `f_op->fasync(fd, filp, on)` | `:71-79` | 由文件系统决定（无钩子则静默） |
| 7 | 赋值：`filp->f_flags = (arg & SETFL_MASK) \| (filp->f_flags & ~SETFL_MASK)` | `:81` | 成功 |
| 8 | 同步 `filp->f_iocb_flags = iocb_flags(filp)` | `:82` | — |

> 注意第 4 项和第 6 项：**`O_DIRECT` 和 `FASYNC` 都可能返回非 `EINVAL` 的错误，也可能静默无效**——取决于具体文件系统/设备的 `f_op`。所以「`F_SETFL` 一定返回 0 或 `EINVAL`」也是错的。

## 6. HFT / 嵌入式关联

| 场景 | 本节机制的兑现 |
|------|----------------|
| 只读行情文件 | 想「就地改成可写」是**不可能**的（访问模式不可变）。必须重新 `open`——这决定了数据加载层的接口设计（读写模式要在最外层一次定好） |
| 运行时切非阻塞 | `O_NONBLOCK` 在掩码里（`fs/fcntl.c:35`）→ 可以在建连之后随时切换，这是 `epoll` 边缘触发 + 非阻塞收发的实现基础 |
| `O_DIRECT` 旁路页缓存 | 在掩码里，可事后开；但非 FIFO 且 FS 不支持时**静默失败**（`:60-63` 只在缺 `FMODE_CAN_ODIRECT` 时报 `EINVAL`）→ 低延迟落盘要**读回验证** |
| `O_ASYNC` / `SIGIO` | 普通文件静默无效，管道/socket 有效 → 别在普通文件上指望 `SIGIO`；现代做法是 `epoll`（[Ch63](../../chapter-63-alternative-i-o-models/notes/63.3-signal-driven-i-o.md)） |
| 嵌入式只增日志区 | `IS_APPEND` 的文件上**清不掉** `O_APPEND`（`:46-47` 报 `EPERM`）——这是内核级的「日志只许追加」保护，配合 `chattr +a` 使用 |
| 改完必验 | 嵌入式上 `F_SETFL` 的静默失败极难现场排查（没有终端、日志又少）→ 封装成函数并在其中 `F_GETFL` 断言 |

<details>
<summary>代码自测（Q&A）</summary>

**Q1：`F_SETFL` 能改哪些标志？**
A：只有 `SETFL_MASK`（`fs/fcntl.c:35`）里那五个：`O_APPEND` / `O_NONBLOCK` / `O_NDELAY` / `O_DIRECT` / `O_NOATIME`。赋值语句是 `fs/fcntl.c:81`：`filp->f_flags = (arg & SETFL_MASK) | (filp->f_flags & ~SETFL_MASK);`。实测 `O_APPEND`、`O_NONBLOCK` 都成功置位。

**Q2：`F_SETFL(fd, O_WRONLY)` 能把只读 fd 变成可写吗？**
A：不能，而且**不报错**。访问模式不在 `SETFL_MASK` 里，实测改完 `F_GETFL` 的访问模式仍是 `O_RDONLY`，随后 `write` 返回 `-1 errno=9 (EBADF)`。要改访问模式只能重新 `open`。

**Q3：`F_SETFL(O_CREAT|O_TRUNC|O_EXCL)` 为什么一点效果都没有？**
A：因为这三个是「`open` 时的一次性开关」，内核在 `fs/open.c:945` 就主动把它们从 `f_flags` 里清掉了（`f->f_flags &= ~(O_CREAT | O_EXCL | O_NOCTTY | O_TRUNC);`），同时它们也不在 `SETFL_MASK` 里。实测 `before == after`，变化 `0x00000`，但调用返回 `0`（成功）——**这是「静默忽略」而非「报错」**。

**Q4：为什么普通文件上 `F_SETFL(O_ASYNC)` 无效，管道上却有效？**
A：`O_ASYNC` 与 `FASYNC` 是同一个位，它**不在** `SETFL_MASK` 里。`fs/fcntl.c:71` 的注释原文写着 `->fasync() is responsible for setting the FASYNC bit.`——即要靠 `file_operations->fasync` 钩子去设。普通文件没有这个钩子（静默失败），管道有（`fs/pipe.c:1230` 的 `.fasync = pipe_fasync`）。实测同一段代码在管道上 `F_GETFL=0x02000`、`O_ASYNC` 位=1。

**Q5：为什么说「`F_SETFL` 返回 0 不代表生效」？**
A：因为它的语义是「采纳 `arg & SETFL_MASK`」，掩码外的位被**无声丢弃**。返回 0 只表示「这次调用没有出错」。所以稳妥做法是改完立刻 `F_GETFL` 读回验证——本节的 demo 每段都这么做。

**Q6：`O_SYNC` / `O_DSYNC` 能用 `F_SETFL` 事后开吗？**
A：不在 `SETFL_MASK`（`fs/fcntl.c:35`）里，所以不能。它们必须在 `open` 时指定。讨论见 [Ch13](../../chapter-13-file-io-buffering/README.md)。

**Q7：`O_NDELAY` 和 `O_NONBLOCK` 是什么关系？**
A：在 Linux 上它们是**同一个值**（历史遗留：`O_NDELAY` 是 System V 的叫法）。`setfl()` 里还有一段 SunOS 兼容代码（`fs/fcntl.c:55-57`）：若 `O_NONBLOCK != O_NDELAY` 且 `arg` 含 `O_NDELAY`，就补上 `O_NONBLOCK`。

</details>
