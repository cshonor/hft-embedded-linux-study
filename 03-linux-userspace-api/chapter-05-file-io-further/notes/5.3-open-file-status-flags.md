# 5.3 打开文件状态标志（Open File Status Flags）

> 本章：[TLPI 第 05 章 — File I/O: Further Details](../README.md)

> - 上一节：[5.2 `fcntl()`](5.2-fcntl.md)

## 本节讲什么

上一节讲了 `fcntl()` 的 `F_GETFL`/`F_SETFL`，本节聚焦它们操作的对象——**打开文件状态标志（open file status flags）**。回答三个问题：

1. `F_GETFL` 拿回来的 `f_flags` 里到底有哪些位？怎么正确解析访问模式？
2. 哪些标志可以事后用 `F_SETFL` 改，哪些只能在 `open` 时定死？
3. 内核 `setfl()` 在真正修改前做了哪些校验？

---

## 1. 状态标志的归属

文件状态标志存在**打开文件描述**（`struct file` 的 `f_flags` 字段）里，与 fd 标志（`FD_CLOEXEC`，存进程 fd 表项）是两回事（见 [5.2](5.2-fcntl.md)）。`F_GETFL` 直接读 `filp->f_flags`：

```c
/* fs/fcntl.c:338 */
case F_GETFL:
    err = filp->f_flags;   /* 返回打开文件描述的状态标志 */
    break;
case F_SETFL:
    err = setfl(fd, filp, argi);   /* :342 */
    break;
```

## 2. 获取：`F_GETFL` 与访问模式解析

```c
int flags = fcntl(fd, F_GETFL);
if (flags & O_APPEND)    /* 追加模式 */
if (flags & O_NONBLOCK)  /* 非阻塞模式 */

/* 访问模式必须用 O_ACCMODE 掩码 */
int acc = flags & O_ACCMODE;   /* O_RDONLY(0) / O_WRONLY(1) / O_RDWR(2) */
```

> 陷阱：`O_RDONLY == 0`，所以 `flags & O_RDONLY` 恒为 0，必须 `flags & O_ACCMODE` 再比较。

## 3. 设置：`F_SETFL` 可改 vs 不可改

| 可修改（`F_SETFL`） | 不可修改（只在 `open` 时设定） |
|---------------------|------------------------------|
| `O_APPEND` | `O_RDONLY` / `O_WRONLY` / `O_RDWR`（访问模式） |
| `O_NONBLOCK` | `O_CREAT` |
| `O_ASYNC` | `O_TRUNC` |
| `O_DIRECT` | `O_EXCL` |
| `O_NOATIME`（需 owner） | `O_CLOEXEC`（那是 **fd 标志**，用 `F_SETFD`） |

## 4. 内核 `setfl()` 的校验链（`fs/fcntl.c:37`）

`F_SETFL` 不是无脑赋值，内核 `setfl()` 在修改前做多重校验：

```c
static int setfl(int fd, struct file *filp, unsigned int arg)
{
    /* 1) O_APPEND 不能被清除，若 inode 标记为 append-only（chattr +a） */
    if (((arg ^ filp->f_flags) & O_APPEND) && IS_APPEND(inode))
        return -EPERM;

    /* 2) O_NOATIME 只能由 owner 或特权用户设置 */
    if ((arg & O_NOATIME) && !(filp->f_flags & O_NOATIME))
        if (!inode_owner_or_capable(...))
            return -EPERM;

    /* 3) 兼容：O_NDELAY 等同 O_NONBLOCK */
    if (O_NONBLOCK != O_NDELAY)
        if (arg & O_NDELAY)  arg |= O_NONBLOCK;

    /* 4) O_DIRECT 需要底层支持 FMODE_CAN_ODIRECT */
    if (!S_ISFIFO(inode->i_mode) && (arg & O_DIRECT) &&
        !(filp->f_mode & FMODE_CAN_ODIRECT))
        return -EINVAL;

    /* 5) 交给具体文件系统的 check_flags 钩子（若有） */
    if (filp->f_op->check_flags)
        error = filp->f_op->check_flags(arg);
    ...
}
```

注意：`setfl` **不校验访问模式位**——因为 `F_SETFL` 传入的 `arg` 里访问模式位根本不会被应用（内核只取状态标志位，访问模式在 `open` 时已固化在 `f_mode` 里）。

## 5. HFT / 嵌入式关联

| 场景 | 本节机制的兑现 |
|------|----------------|
| 运行时切换非阻塞 | `F_SETFL` 动态开关 `O_NONBLOCK`，网络/管道 I/O 常用（见 [5.9](5.9-nonblocking-io.md)） |
| `O_APPEND` 追加日志 | 打开后可用 `F_SETFL` 追加 `O_APPEND`（但注意 append-only 文件不可清除） |
| `O_DIRECT` 绕过页缓存 | HFT 低延迟落盘场景，需底层设备支持 `FMODE_CAN_ODIRECT`，否则 `setfl` 返回 `EINVAL` |
| 先 `F_GETFL` 再或 | 避免 `F_SETFL` 覆盖已有标志，是并发安全设置状态标志的唯一正确姿势 |

## 6. 代码示例

```c
#include <stdio.h>
#include <fcntl.h>
#include <unistd.h>

/* 5.3 状态标志：F_GETFL/F_SETFL 的正确用法 */
int main(void) {
    int fd = open("/tmp/flags.txt", O_RDWR | O_CREAT, 0644);

    /* 读回状态标志，正确解析访问模式 */
    int flags = fcntl(fd, F_GETFL);
    printf("access mode: %d (0=RDONLY 1=WRONLY 2=RDWR)\n",
           flags & O_ACCMODE);

    /* 追加 O_APPEND（先读再或，避免覆盖） */
    fcntl(fd, F_SETFL, flags | O_APPEND);
    printf("O_APPEND now: %s\n",
           (fcntl(fd, F_GETFL) & O_APPEND) ? "yes" : "no");

    close(fd);
    return 0;
}
```

<details>
<summary>代码自测（Q&A）</summary>

**Q1：`F_GETFL` 拿到的 flags，怎么判断文件是以 `O_WRONLY` 打开的还是 `O_RDWR`？**
A：用 `flags & O_ACCMODE` 取低 2 位：`0`→`O_RDONLY`、`1`→`O_WRONLY`、`2`→`O_RDWR`。不能 `flags & O_WRONLY`（`O_WRONLY` 恰好是 1 可以测出，但 `O_RDONLY==0` 会漏判），统一用 `O_ACCMODE` 最稳妥。

**Q2：哪些标志可以用 `F_SETFL` 修改？哪些只能 `open` 时定死？**
A：可改：`O_APPEND`、`O_NONBLOCK`、`O_ASYNC`、`O_DIRECT`、`O_NOATIME`（需 owner）。不可改：访问模式（`O_RDONLY`/`O_WRONLY`/`O_RDWR`）、`O_CREAT`、`O_TRUNC`、`O_EXCL`。`O_CLOEXEC` 是 fd 标志，用 `F_SETFD` 而非 `F_SETFL`。

**Q3：`setfl()` 为什么会对「清除 `O_APPEND`」返回 `EPERM`？**
A：当文件被标记为 append-only（`chattr +a`，即 `IS_APPEND(inode)` 为真）时，内核禁止通过 `F_SETFL` 把 `O_APPEND` 位从 `f_flags` 清掉，防止绕过强制追加语义。`setfl` 检测到 `O_APPEND` 位被翻转且 inode 是 append-only 时返回 `-EPERM`。

**Q4：`F_SETFL` 设 `O_DIRECT` 一定成功吗？**
A：不一定。`setfl` 检查 `!(filp->f_mode & FMODE_CAN_ODIRECT)` 时返回 `-EINVAL`——底层文件系统/设备不支持 direct I/O 就无法设置。`O_DIRECT` 也不是「更快」的万能药，见 Ch13 对页缓存的讨论。

**Q5：`O_NDELAY` 和 `O_NONBLOCK` 什么关系？**
A：两者语义相同（非阻塞），历史遗留两个名字。内核 `setfl` 里有 `if (O_NONBLOCK != O_NDELAY) if (arg & O_NDELAY) arg |= O_NONBLOCK;`——即传 `O_NDELAY` 会自动补上 `O_NONBLOCK`，保证二者等价。新代码应统一用 `O_NONBLOCK`。

</details>
