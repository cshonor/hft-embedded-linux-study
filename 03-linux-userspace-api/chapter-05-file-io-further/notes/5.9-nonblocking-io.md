## 本节讲什么

`O_NONBLOCK` 改的不是「读写的语义」，而是**「内核发现现在做不了这件事」时怎么办**：

- **阻塞模式**：把进程挂起（睡在等待队列里），直到能做为止；
- **非阻塞模式**：立刻返回 `-1`，`errno = EAGAIN`。

本节回答四个问题：

1. `EAGAIN` 和 `EWOULDBLOCK` 是什么关系？
2. 非阻塞之后就永远看不到 `EINTR` 了吗？（不）
3. 为什么阻塞读会被**信号打断**——`SA_RESTART` 在这里扮演什么角色？
4. `O_NONBLOCK` 对**普通文件**有效吗？为什么「打开非阻塞」只能 `open`，而「改成非阻塞」可以 `fcntl`？

---

## 1. 原型与语义

```c
int fd = open(path, O_RDONLY | O_NONBLOCK);
/* 或者事后改（[5.3](5.3-open-file-status-flags.md) 里验证过 O_NONBLOCK 在 SETFL_MASK 内） */
fcntl(fd, F_SETFL, fcntl(fd, F_GETFL) | O_NONBLOCK);
```

| 对象 | 阻塞模式 | 非阻塞模式 |
|------|---------|-----------|
| 空管道 / FIFO / socket 读 | 挂起等数据 | `read` → `-1 EAGAIN` |
| 满管道 / FIFO / socket 写 | 挂起等空间 | `write` → `-1 EAGAIN` |
| **普通文件** | — | **通常无效**（本地磁盘 I/O 不「等待事件」） |

> **`open` 一个 FIFO 时的 `O_NONBLOCK` 完全是另一套规则。** 内核 `fifo_open()` 里按访问模式分三种情况，并且每条都注明依据是 POSIX.1：

```c
/* O_RDONLY */
/*
 *  POSIX.1 says that O_NONBLOCK means return with the FIFO
 *  opened, even when there is no process writing the FIFO.
 */
if (!is_pipe && !pipe->writers) {
        if ((filp->f_flags & O_NONBLOCK)) {
                /* suppress EPOLLHUP until we have seen a writer */
                filp->f_version = pipe->w_counter;
        } else {
                if (wait_for_partner(pipe, &pipe->w_counter))   /* 阻塞等写端 */
                        goto err_rd;
        }
}
```

| `open` 的访问模式 | 无对端时阻塞模式 | 无对端时 `O_NONBLOCK` |
|------------------|-----------------|---------------------|
| `O_RDONLY`（`fs/pipe.c:1137-1141`） | 挂着等写端出现（`:1152`） | **立刻成功返回**（`:1147-1150`） |
| `O_WRONLY`（`fs/pipe.c:1159-1166`） | 挂着等读端出现（`:1173`） | **`-1 errno=ENXIO`**（`:1164`、`:1165`） |
| `O_RDWR`（`fs/pipe.c:1179-1184`） | POSIX.1 说「未定义」；Linux **从不阻塞**（「the process can at least talk to itself」） | 同左 |

**读 `read` 的规则则与环境无关**：「没有写端」不是「暂时没数据」——所有写端关闭后，`read` 返回 **0（EOF）**，不论阻塞还是非阻塞。

## 2. 内核：`EAGAIN` 从哪里来

以管道为例（`fs/pipe.c`）——读端：

```c
if (!pipe->writers)
        break;
if (ret)
        break;
if ((filp->f_flags & O_NONBLOCK) ||          /* fs/pipe.c:345 */
    (iocb->ki_flags & IOCB_NOWAIT)) {
        ret = -EAGAIN;                        /* fs/pipe.c:347 */
        break;
}
```

写端（空间不足时）：

```c
if (!pipe_full(head, pipe->tail, pipe->max_usage))
        continue;

/* Wait for buffer space to become available. */
if ((filp->f_flags & O_NONBLOCK) ||           /* fs/pipe.c:550 */
    (iocb->ki_flags & IOCB_NOWAIT)) {
        if (!ret)
                ret = -EAGAIN;                /* fs/pipe.c:553 */
        break;
}
```

两处形态完全一样，都是**「条件不满足 → 如果非阻塞就 `-EAGAIN` 直接返回；否则去睡眠等待」**。这就是 `O_NONBLOCK` 的全部含义：**把「等待」换掉，而不是把「失败」换掉。**

> 管道容量也可运行时查改：`F_GETPIPE_SZ` 返回 `pipe->max_usage * PAGE_SIZE`（`fs/pipe.c:1404-1405`）；`F_SETPIPE_SZ` 走 `pipe_set_size()`（`:1401-1402`）。

## 3. 代码：四段实测

完整源码 [`code/c5_9_nonblocking.c`](../code/c5_9_nonblocking.c)：

```c
/* c5_9_nonblocking.c — §5.9 非阻塞 I/O：O_NONBLOCK 到底改了谁的行为
 *
 * 关键在于「内核发现现在做不了这件事」时怎么办：
 *   阻塞模式  —— 把进程挂起（睡在等待队列里），直到能做为止
 *   非阻塞模式 —— 立刻返回 -1，errno = EAGAIN (EWOULDBLOCK)
 *
 * 而且这个开关**可以在运行时改**（F_SETFL），不用重新 open。
 *
 * 演示四件事：
 *   1) 空管道读：非阻塞 → EAGAIN
 *   2) 同一根管道换回阻塞模式 → read 挂起，被 SIGALRM 打断（EINTR）
 *   3) 有数据时阻塞读立刻返回
 *   4) 管道写满：非阻塞 → EAGAIN（阻塞模式会一直等到有人读）
 *
 * 编译: gcc -O0 -Wall -Wextra -o c5_9_nonblocking c5_9_nonblocking.c
 */
#define _GNU_SOURCE
#include <fcntl.h>
#include <signal.h>
#include <stdio.h>
#include <string.h>
#include <unistd.h>
#include <errno.h>

static void on_alarm(int sig)
{
    (void) sig;                              /* 只用来打断阻塞的 read() */
}

int main(void)
{
    int pp[2];
    char buf[256];
    ssize_t n;

    if (pipe(pp) == -1) {
        perror("pipe");
        return 1;
    }

    printf("== 1. 空管道 + O_NONBLOCK：立刻 EAGAIN，绝不等待 ==\n");
    fcntl(pp[0], F_SETFL, fcntl(pp[0], F_GETFL) | O_NONBLOCK);
    errno = 0;
    n = read(pp[0], buf, sizeof buf);
    printf("    read(空管道, O_NONBLOCK) -> %ld errno=%d (%s)\n",
           (long) n, errno, strerror(errno));
    printf("    EAGAIN=%d，它的别名 EWOULDBLOCK=%d（同一数值）\n", EAGAIN, EWOULDBLOCK);

    printf("\n== 2. 换回阻塞模式：read 会挂起，靠信号把它打断 ==\n");
    fcntl(pp[0], F_SETFL, fcntl(pp[0], F_GETFL) & ~O_NONBLOCK);
    printf("    现在 F_GETFL 里的 O_NONBLOCK 位 = %d\n",
           !!(fcntl(pp[0], F_GETFL) & O_NONBLOCK));
    {
        struct sigaction sa;

        memset(&sa, 0, sizeof sa);
        sa.sa_handler = on_alarm;
        sigemptyset(&sa.sa_mask);
        /* 注意：**不能**带 SA_RESTART，否则被信号打断的系统调用会自动重来 */
        sa.sa_flags = 0;
        sigaction(SIGALRM, &sa, NULL);
        alarm(1);
        errno = 0;
        n = read(pp[0], buf, sizeof buf);        /* 挂在这一行上，1 秒后被 SIGALRM 打断 */
        alarm(0);
        printf("    阻塞 read(空管道, 无数据) -> %ld errno=%d (%s)\n",
               (long) n, errno, strerror(errno));
        printf("    EINTR=%d —— 慢系统调用被信号打断的经典现场\n", EINTR);
    }

    printf("\n== 3. 有数据时阻塞读立刻返回 ==\n");
    write(pp[1], "hello", 5);
    memset(buf, 0, sizeof buf);
    n = read(pp[0], buf, sizeof buf);
    printf("    read -> %ld 字节 \"%.*s\"\n", (long) n, (int) n, buf);

    printf("\n== 4. 写满的管道 + O_NONBLOCK：EAGAIN ==\n");
    {
        char chunk[1024];
        long total = 0;

        memset(chunk, 'w', sizeof chunk);
        fcntl(pp[1], F_SETFL, fcntl(pp[1], F_GETFL) | O_NONBLOCK);
        for (;;) {
            n = write(pp[1], chunk, sizeof chunk);
            if (n <= 0)
                break;
            total += n;
        }
        printf("    一口气塞进 %ld 字节后停下（errno=%d %s）\n",
               total, errno, strerror(errno));
        printf("    F_GETPIPE_SZ 报告的容量 = %d\n", fcntl(pp[1], F_GETPIPE_SZ));
        errno = 0;
        n = write(pp[1], "x", 1);
        printf("    再写 1 字节 -> %ld errno=%d (%s)\n", (long) n, errno, strerror(errno));
    }

    close(pp[0]);
    close(pp[1]);
    return 0;
}
```

编译运行（第 2 段会真等 1 秒，靠 `SIGALRM` 打断）：

```bash
gcc -O0 -Wall -Wextra -o c5_9_nonblocking c5_9_nonblocking.c && ./c5_9_nonblocking
```

CE（gcc 13.3.0 / x86-64 / Ubuntu 24.04）实测：

```text
== 1. 空管道 + O_NONBLOCK：立刻 EAGAIN，绝不等待 ==
    read(空管道, O_NONBLOCK) -> -1 errno=11 (Resource temporarily unavailable)
    EAGAIN=11，它的别名 EWOULDBLOCK=11（同一数值）

== 2. 换回阻塞模式：read 会挂起，靠信号把它打断 ==
    现在 F_GETFL 里的 O_NONBLOCK 位 = 0
    阻塞 read(空管道, 无数据) -> -1 errno=4 (Interrupted system call)
    EINTR=4 —— 慢系统调用被信号打断的经典现场

== 3. 有数据时阻塞读立刻返回 ==
    read -> 5 字节 "hello"

== 4. 写满的管道 + O_NONBLOCK：EAGAIN ==
    一口气塞进 65536 字节后停下（errno=11 Resource temporarily unavailable）
    F_GETPIPE_SZ 报告的容量 = 65536
    再写 1 字节 -> -1 errno=11 (Resource temporarily unavailable)
```

逐条看：

| 观察 | 说明 |
|------|------|
| 空管道 + `O_NONBLOCK` → `-1 errno=11` | `fs/pipe.c:345-347` 那条分支。**立刻返回，绝不等待**——这是「忙轮询」的合法实现基础 |
| `EAGAIN=11`、`EWOULDBLOCK=11` | 在 Linux 上**是同一个数值**。可移植代码里写 `if (errno == EAGAIN \|\| errno == EWOULDBLOCK)` 是历史习惯；Linux 上等价 |
| 清掉 `O_NONBLOCK` 位后（`F_GETFL` 显示 `=0`）阻塞 `read` → `-1 errno=4` | **关键**：非阻塞不是「防止 `EINTR`」。切回阻塞后立刻暴露了「被信号打断」这件事 |
| `EINTR=4` —— 靠 `alarm(1)` + `SIGALRM` 打断 | demo 里 `sigaction` 的 `sa_flags = 0`，**故意不带 `SA_RESTART`**。若带 `SA_RESTART`，内核会自动重启这个 `read`，程序就永远等不到 `EINTR` 了 |
| 有数据时 `read` → **5 字节 `"hello"`** | 阻塞模式下「有数据就立刻返回」，不会等缓冲区满。这是「阻塞」的完整定义：只在**做不了**的时候等 |
| 一口气塞进 **65536** 字节后停下 | 管道默认容量 64 KiB，非阻塞写塞满后返回 `-1 EAGAIN` |
| `F_GETPIPE_SZ = 65536` | 与内核 `pipe->max_usage * PAGE_SIZE`（`fs/pipe.c:1405`）一致。注意 [5.7](5.7-readv-writev.md) 那个 demo 用 `F_SETPIPE_SZ` 把它压到过 4096 |
| 满了之后再写 1 字节 → `EAGAIN` | 一个字节都塞不进去。注意这是 `EAGAIN` 而不是「部分写返回 0」——`write` 在完全没空间时**不返回 0**（返回 0 在 `write` 里不是合法结果） |

## 4. `EINTR` 与 `SA_RESTART`：本节最容易混的一处

很多人把 `O_NONBLOCK` 和 `EINTR` 混为一谈，以为「设了非阻塞就不会被信号打断」。事实是：

| | `EAGAIN` | `EINTR` |
|---|---|---|
| 触发原因 | **条件不满足**（没数据 / 没空间） | **被信号打断**（信号处理函数返回后内核不重启该调用） |
| 是否受 `O_NONBLOCK` 影响 | ✅ 只有非阻塞模式才可能 | ❌ 阻塞模式下才常见；非阻塞下也可能（比如已到达后被信号打断） |
| 应对 | 稍后再试（`poll`/`select`/延迟重试） | 区分「信号已处理」与「真错误」，然后**重试**（[4.10 的 `writeAll`](../../chapter-04-file-io-universal/notes/4.10-exercises.md) 演示过这个循环） |
| 受 `SA_RESTART` 影响 | ❌ | ✅ 设了就会**自动重来**，用户态看不到 `EINTR` |

**判断「慢系统调用是否被重启」的三种情况**（TLPI 21.5 的结论，这里给出可验证的落点）：

| 调用类型 | `SA_RESTART` 未设 | `SA_RESTART` 已设 |
|---------|------------------|------------------|
| 可中断的「慢」调用（`read`/`write`/`open` 等） | `EINTR`（实测 `errno=4`） | 自动重启，不返回 |
| 已经传输了**部分**数据的调用 | 返回已传输的字节数（**不是** `EINTR`） | 同左 |
| 其他调用（`epoll_wait` 等） | 一定 `EINTR`（**从不**自动重启） | 一定 `EINTR` |

## 5. 对普通文件有效吗

**通常无效。** 普通文件的读写在多数情况下不需要「等待某个事件」——数据要么在页缓存里（立刻返回），要么从磁盘读（会让进程睡眠，但那是 I/O 等待，`O_NONBLOCK` 不改变它）。所以：

| 对象 | `O_NONBLOCK` 的作用 |
|------|-------------------|
| 管道 / FIFO | ✅ 决定「没数据/没空间」时是等还是 `EAGAIN` |
| socket | ✅ 同上（网络编程的基础） |
| 终端 / 串口 | ✅ 配合 `VMIN=0`/`VTIME` 或直接非阻塞读 |
| 字符设备（部分） | ✅ 由驱动决定 |
| **普通文件** | ⚠️ **基本无影响**。不要指望它解决磁盘 I/O 的延迟问题 |
| 打开了强制锁的文件 | ✅ 有影响（锁冲突时不会无限等） |

> 嵌入式上最容易踩的一条：**串口**。`open("/dev/ttyS0", O_RDONLY)` 后 `read` 会一直挂到有数据；要么打开时带 `O_NONBLOCK`，要么用 `termios` 的 `VMIN=0` + `VTIME`（行/字节超时）。两者是不同机制，别混用。

## 6. HFT / 嵌入式关联

| 场景 | 本节机制的兑现 |
|------|----------------|
| `epoll` 边缘触发 | **必须**配非阻塞 fd（[Ch63](../../chapter-63-alternative-i-o-models/notes/63.4-the-epoll-api.md)）。ET 模式下要一次读到 `EAGAIN` 才算读干净——`EAGAIN` 在这里是**正常退出条件**，不是错误 |
| 忙轮询（busy-poll） | 低延迟场景主动选择「非阻塞 + 紧循环」而不是 `epoll`，用 CPU 换确定性延迟。这时 `EAGAIN` 是每秒可能出现几百万次的常态 |
| 无锁环缓冲对接 | 非阻塞 `write` 返回 `EAGAIN` = 「下游没跟上」，是**背压信号**，可据此切换为丢弃或阻塞策略 |
| 信号 + 慢系统调用 | 交易进程常用 `SIGALRM`/心跳信号打断长阻塞；此时**必须**处理 `EINTR`，且要清楚 `SA_RESTART` 的影响（否则心跳永远不触发或永远被打断） |
| 嵌入式串口 | `O_NONBLOCK` 或 `VMIN/VTIME`；`EAGAIN` 时不要当错误打日志（会刷爆串口） |
| 管道容量 | `F_GETPIPE_SZ` / `F_SETPIPE_SZ`（`fs/pipe.c:1401-1405`）可调吞吐上限——默认 64 KiB（实测），高吞吐场景会显式放大 |
| 普通文件误区 | 想在普通文件上靠 `O_NONBLOCK` 降低延迟是**无效**的；要降低延迟应该考虑 `O_DIRECT`（[5.3](5.3-open-file-status-flags.md)）、`mmap`（[Ch49](../../chapter-49-memory-mappings/README.md)）或 `io_uring`（[Ch63](../../chapter-63-alternative-i-o-models/notes/63.4-the-epoll-api.md)） |

<summary>代码自测（Q&A）</summary>

**Q1：`EAGAIN` 和 `EWOULDBLOCK` 是同一个东西吗？**
A：在 Linux 上是同一个数值（实测都 `= 11`）。POSIX 允许它们不同，所以可移植代码常写 `errno == EAGAIN || errno == EWOULDBLOCK`；Linux 上这个 `||` 是冗余的。

**Q2：设了 `O_NONBLOCK` 就不会遇到 `EINTR` 了吗？**
A：**不是**。`EAGAIN` 和 `EINTR` 是两件不同的事：前者是「条件不满足」，后者是「被信号打断」。实测把 `O_NONBLOCK` 清掉后，阻塞 `read` 立刻被 `SIGALRM` 打断并返回 `EINTR`。

**Q3：为什么 demo 里 `sigaction` 的 `sa_flags` 要写 0（不带 `SA_RESTART`）？**
A：因为带 `SA_RESTART` 时内核会**自动重启**被信号打断的慢系统调用，`read` 就不会返回 `EINTR` 了——本节的演示点就没了。想知道「信号真的打断了什么」，必须不带 `SA_RESTART`。

**Q4：`O_NONBLOCK` 对普通文件有用吗？**
A：基本没用。普通文件的读写多数不需要「等待事件」，`O_NONBLOCK` 改变不了磁盘 I/O 的等待。它真正起作用的对象是管道、FIFO、socket、终端/串口和部分字符设备。

**Q5：`O_NONBLOCK` 下的 `write` 在完全没空间时返回什么？**
A：`-1 EAGAIN`（实测写满 65536 字节后再写 1 字节 → `errno=11`）。注意 **`write` 返回 `0` 不是合法结果**——`0` 只在 `read` 里表示 EOF。

**Q6：为什么「打开时非阻塞」用 `open` 的 `O_NONBLOCK`，「事后非阻塞」却能用 `fcntl`？**
A：因为 `O_NONBLOCK` 属于**打开文件状态标志**（`struct file->f_flags`），它在 `SETFL_MASK`（`fs/fcntl.c:35`）里，所以 `F_SETFL` 能改。而访问模式、`O_CREAT` 这类不共享、不持久的位就改不了（[5.3](5.3-open-file-status-flags.md)）。

**Q7：`F_GETPIPE_SZ` 返回的容量是怎么算的？**
A：`pipe->max_usage * PAGE_SIZE`（`fs/pipe.c:1404-1405`）。实测默认是 `65536`（64 KiB）。可用 `F_SETPIPE_SZ` 调整（走 `pipe_set_size()`，`:1402`）——[5.7](5.7-readv-writev.md) 那个 demo 把它压到过 4096。

**Q8：FIFO 的 `open` 和 `read` 遇到 `O_NONBLOCK` 分别怎样？**
A：要分开看。`open` 的规则在 `fifo_open()` 里，每条都注明 POSIX.1 依据：`O_RDONLY|O_NONBLOCK` **立刻成功返回**（即使没有写端，`fs/pipe.c:1137-1150`）；`O_WRONLY|O_NONBLOCK` 且无读端 → **`-1 errno=ENXIO`**（`fs/pipe.c:1159-1166`）；`O_RDWR` 在 POSIX.1 里「未定义」，Linux 实现**从不阻塞**（`fs/pipe.c:1179-1184`）。而 `read` 的规则与环境无关：所有写端关闭后一律返回 **0（EOF）**，阻塞与非阻塞相同。
