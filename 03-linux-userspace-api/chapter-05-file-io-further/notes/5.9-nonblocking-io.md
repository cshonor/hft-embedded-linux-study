# 5.9 非阻塞 I/O（`O_NONBLOCK`）

## 本节讲什么

`O_NONBLOCK` 让「可能阻塞」的 I/O 变成「立即返回」。本节回答三个问题：

1. `O_NONBLOCK` 对哪些对象生效？为什么对普通磁盘文件**通常无效**？
2. 非阻塞读/写失败时返回什么、`errno` 是什么？和真正的错误怎么区分？
3. `O_NONBLOCK` 为什么**不等于**异步 I/O（AIO）？

---

## 1. 语义：不睡、立刻返回

`O_NONBLOCK` 的核心是**轮询式语义**：当操作无法立即完成时，内核**不把进程挂起睡眠**，而是立刻返回 `-1` + `errno = EAGAIN`/`EWOULDBLOCK`，让调用方稍后重试。

| 对象 | 非阻塞行为 |
|------|-----------|
| **普通磁盘文件** | **通常无效果**——磁盘读不靠「非阻塞」变快，`read` 几乎总能立即返回（页缓存命中）或短暂等待 |
| **管道 / FIFO** | 读端无数据时 `read` 立即 `-1` + `EAGAIN`；写端满时 `write` 立即 `-1` + `EAGAIN` |
| **socket** | 无数据可读/发送缓冲满时，`read`/`write` 立即 `-1` + `EAGAIN`（`EWOULDBLOCK` 同值） |
| **终端** | 读不到数据时立即返回 |

> `O_NONBLOCK` ≠ 异步 AIO。它只是「不睡、立刻返回」的同步轮询语义；真正的异步是「发起请求后立即返回，完成时内核通知」（见 Ch63 epoll / POSIX AIO）。

## 2. 如何设置

两种方式，效果相同（都写进 `file->f_flags`）：

```c
/* 方式 1：open 时指定 */
int fd = open(path, O_RDWR | O_NONBLOCK);

/* 方式 2：fcntl 动态切换（先读再或，避免覆盖） */
int flags = fcntl(fd, F_GETFL);
fcntl(fd, F_SETFL, flags | O_NONBLOCK);
```

内核 `setfl`（`fs/fcntl.c:37`）里有 `if (arg & O_NDELAY) arg |= O_NONBLOCK;`——历史别名 `O_NDELAY` 被归一为 `O_NONBLOCK`（见 [5.3](5.3-open-file-status-flags.md)）。

## 3. 非阻塞读写的返回值判断

```c
ssize_t n = read(fd, buf, sizeof(buf));
if (n < 0) {
    if (errno == EAGAIN || errno == EWOULDBLOCK)
        /* 只是「现在没数据」，不是错误，稍后重试 */
    else
        /* 真错误 */
}
```

| 返回 | 含义 |
|------|------|
| `> 0` | 读到/写了 n 字节 |
| `0` | EOF（读端）/ 对端关闭 |
| `-1` + `EAGAIN`/`EWOULDBLOCK` | **暂时无数据/无空间**，非错误，可重试 |
| `-1` + 其他 errno | 真错误 |

## 4. HFT / 嵌入式关联

| 场景 | 本节机制的兑现 |
|------|----------------|
| 事件驱动网络 | `O_NONBLOCK` + `epoll` 是 HFT 网络代码的标准骨架（见 Ch63） |
| 非阻塞连接 | `connect` 设 `O_NONBLOCK` 可并发发起多路连接，避免串行阻塞 |
| 忙轮询替代睡眠 | 嵌入式实时采集时用非阻塞读 + 轮询，避免进程睡眠引入调度延迟 |
| 避免死锁 | 双向管道（父子双向通信）用非阻塞避免双方同时阻塞等待 |

## 5. 代码示例

```c
#include <fcntl.h>
#include <unistd.h>
#include <errno.h>
#include <stdio.h>

/* O_NONBLOCK: 管道读端设为非阻塞 */
int main(void) {
    int pipefd[2];
    if (pipe(pipefd) < 0) { perror("pipe"); return 1; }

    /* 读端设非阻塞 */
    int flags = fcntl(pipefd[0], F_GETFL);
    fcntl(pipefd[0], F_SETFL, flags | O_NONBLOCK);

    char buf[64];
    ssize_t n = read(pipefd[0], buf, sizeof(buf));
    if (n < 0) {
        if (errno == EAGAIN || errno == EWOULDBLOCK)
            printf("read 返回 -1, errno=EAGAIN（无数据可读）\n");
        else
            perror("read");
    }

    /* 写入数据后非阻塞读就能拿到 */
    write(pipefd[1], "hi", 2);
    n = read(pipefd[0], buf, sizeof(buf));
    printf("第二次 read: %zd 字节: %.*s\n", n, (int)n, buf);

    close(pipefd[0]); close(pipefd[1]);
    return 0;
}
```

<details>
<summary>代码自测（Q&A）</summary>

**Q1：`O_NONBLOCK` 对普通磁盘文件有效吗？**
A：通常**无效**。普通文件的 `read`/`write` 几乎总能立即返回（页缓存命中或短暂等待），`O_NONBLOCK` 主要针对**可能阻塞**的对象——管道/FIFO/socket/终端。磁盘 I/O 的「非阻塞」要靠 AIO/`O_DIRECT` 等机制，不是 `O_NONBLOCK`。

**Q2：非阻塞 `read` 返回 `-1` + `EAGAIN` 是错误吗？**
A：不是。`EAGAIN`（与 `EWOULDBLOCK` 同值）表示「**现在**没有数据可读」，是正常信号，调用方应稍后重试或交给 `epoll` 等待。真正的错误是其他 `errno`（如 `EBADF`、`EFAULT`）。

**Q3：`O_NONBLOCK` 和异步 I/O（AIO）是一回事吗？**
A：不是。`O_NONBLOCK` 是**同步**语义——调用立即返回 `EAGAIN`，但**数据并未被读**，要你自己重试；AIO 是**异步**语义——发起读请求后立即返回，内核在后台完成，完成时**通知**你。前者是「不睡」，后者是「不等」。

**Q4：`open(path, O_RDWR | O_NONBLOCK)` 和 `fcntl(F_SETFL)` 设非阻塞，效果一样吗？**
A：一样，最终都写进 `file->f_flags` 的 `O_NONBLOCK` 位。区别是 `open` 一次性、`fcntl` 可运行时**动态开关**（配合 `F_GETFL` 先读回再或）。`fcntl` 方式适合「同一 fd 有时阻塞有时非阻塞」的场景。

**Q5：双向管道父子通信为什么要用非阻塞？**
A：若父子都用阻塞模式读写同一管道，可能双方同时阻塞等待对方（父等读、子等读），造成死锁。设 `O_NONBLOCK` 让「无数据时立即返回」，配合轮询或 `select`/`epoll` 打破死锁（详见 Ch44 管道）。

</details>
