## 练习 5-1：改写 Listing 5-3，用标准接口 + `off_t` 造大文件

### 题干（原书 Exercise 5-1，逐字）

> Modify the program in Listing 5-3 to use standard file I/O system calls (`open()` and `lseek()`) and the `off_t` data type. Compile the program with the `_FILE_OFFSET_BITS` macro set to 64, and test it to show that a large file can be successfully created.

**要点拆解**：

| 要求 | 原 Listing 5-3（`large_file.c`） | 改写后 |
|------|--------------------------------|--------|
| 打开 | `open64()` | `open()` |
| 偏移类型 | `off64_t` | `off_t` |
| 定位 | `lseek64()` | `lseek()` |
| 编译期开关 | `#define _LARGEFILE64_SOURCE` | `-D_FILE_OFFSET_BITS=64` |

### 实现

完整源码 [`code/ex5_1_large_file_offset_bits.c`](../code/ex5_1_large_file_offset_bits.c)：

```c
/* ex5_1_large_file_offset_bits.c — 原书习题 5-1
 *
 * 题目（逐字）：
 *   Modify the program in listing 5-3 to use standard file I/O system
 *   calls (open() and lseek()) and the off_t data type.  Compile the
 *   program with the _FILE_OFFSET_BITS macro set to 64, and test it to
 *   show that a large file can be successfully created.
 *
 * 原书 Listing 5-3（large_file.c）用的是**显式 LFS API**：open64()/lseek64()/off64_t。
 * 本题要求改成标准接口 + off_t，靠编译期宏 _FILE_OFFSET_BITS=64 把 off_t 悄悄换成
 * 64 位——这样同一份源码在 32 位平台上也能处理大文件。
 *
 * 编译: gcc -O0 -Wall -Wextra -o ex5_1_large_file_offset_bits ex5_1_large_file_offset_bits.c
 */
#define _FILE_OFFSET_BITS 64        /* 关键：让 off_t / lseek / open 全部走 64 位 */
#define _GNU_SOURCE
#include <fcntl.h>
#include <signal.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <sys/resource.h>
#include <unistd.h>
#include <errno.h>

static volatile sig_atomic_t xfsz = 0;

static void on_xfsz(int sig)
{
    (void) sig;
    xfsz = 1;
}

int main(int argc, char *argv[])
{
    const char *path;
    off_t off;
    int fd;
    struct rlimit rl;

    if (argc != 3) {
        fprintf(stderr, "Usage: %s pathname offset\n", argv[0]);
        return 1;
    }
    path = argv[1];
    off = (off_t) atoll(argv[2]);

    printf("== 习题 5-1：标准接口 + _FILE_OFFSET_BITS=64 ==\n");
    printf("    _FILE_OFFSET_BITS = %d\n", _FILE_OFFSET_BITS);
    printf("    sizeof(off_t) = %zu 字节（32 位平台默认 4；靠上面的宏变 8）\n",
           sizeof(off_t));
    if (getrlimit(RLIMIT_FSIZE, &rl) == 0)
        printf("    RLIMIT_FSIZE soft=%lld hard=%lld\n",
               (long long) rl.rlim_cur, (long long) rl.rlim_max);

    fd = open(path, O_RDWR | O_CREAT, S_IRUSR | S_IWUSR);
    if (fd == -1) {
        perror("open");
        return 1;
    }

    printf("\n    请求偏移 = %lld（4 GiB 的 off_t 只有 8 字节类型才装得下）\n",
           (long long) off);
    if (lseek(fd, off, SEEK_SET) == (off_t) -1) {
        perror("lseek");
        return 1;
    }
    printf("    lseek -> %lld 成功\n", (long long) lseek(fd, 0, SEEK_CUR));

    /* 装个 handler，好让超限时 write 返回 EFBIG 而不是把进程杀掉 */
    {
        struct sigaction sa;

        memset(&sa, 0, sizeof sa);
        sa.sa_handler = on_xfsz;
        sigemptyset(&sa.sa_mask);
        sa.sa_flags = 0;
        sigaction(SIGXFSZ, &sa, NULL);
    }

    errno = 0;
    {
        ssize_t n = write(fd, "test", 4);

        if (n == -1) {
            printf("    write -> -1 errno=%d (%s)，SIGXFSZ handler=%d\n",
                   errno, strerror(errno), (int) xfsz);
            printf("    ↑ 拦住它的是 RLIMIT_FSIZE（沙箱 16 MiB），不是 off_t 宽度\n");
            printf("      在真实机器上把 ulimit -f 放开，这一步就能写出真正的大文件\n");
        } else {
            printf("    write -> %ld 字节，文件创建成功\n", (long) n);
        }
    }

    close(fd);
    return 0;
}
```

### 实测（CE）

```text
== 习题 5-1：标准接口 + _FILE_OFFSET_BITS=64 ==
    _FILE_OFFSET_BITS = 64
    sizeof(off_t) = 8 字节（32 位平台默认 4；靠上面的宏变 8）
    RLIMIT_FSIZE soft=16777216 hard=16777216

    请求偏移 = 4294967296（4 GiB 的 off_t 只有 8 字节类型才装得下）
    lseek -> 4294967296 成功
    write -> -1 errno=27 (File too large)，SIGXFSZ handler=1
    ↑ 拦住它的是 RLIMIT_FSIZE（沙箱 16 MiB），不是 off_t 宽度
      在真实机器上把 ulimit -f 放开，这一步就能写出真正的大文件
```

**解读**：

| 观察 | 说明 |
|------|------|
| `_FILE_OFFSET_BITS = 64` | 宏已经生效；`sizeof(off_t) = 8` 就是它的直接后果。在 32 位平台上，这个宏会把 `off_t` 重定向到 `off64_t`（见 [5.10](5.10-large-files.md) 的双侧源码解释表） |
| `lseek -> 4294967296` **成功** | 「能不能表示 4 GiB 偏移」这一步**已经过关**——这正是本题的验收点。注意此刻文件**没有变大**（`lseek` 只动游标，不写就不分配块） |
| `write -> -1 errno=27 (EFBIG)` | 拦住它的是 **`RLIMIT_FSIZE = 16 MiB`**（沙箱限制），跟 `off_t` 宽度无关。默认动作是先发 `SIGXFSZ` 杀掉进程，装了 handler 就能拿到 `EFBIG` |
| 与 Listing 5-3 的对照 | 原书 `large_file.c` 用 `_LARGEFILE64_SOURCE` + `open64/lseek64`，在同一个沙箱里被 `SIGXFSZ (25)` 直接杀（`signal SIGXFSZ (25)`）——**结论完全一致**，只是显式的 `*64` 接口没机会装 handler 而已 |

> **本题真正的收获**：`_FILE_OFFSET_BITS=64` 解决的是「**类型宽度**」，而真正阻止你写出大文件的是「**资源上限**」（`RLIMIT_FSIZE`）和「**文件系统上限**」（`s_maxbytes`）。两者是独立的两层，别混为一谈。

## 练习 5-2：带 `O_APPEND` 时 `lseek` 到文件头再写，数据落哪？

### 题干（原书 Exercise 5-2，逐字）

> Write a program that opens an existing file for writing with the `O_APPEND` flag, and then seeks to the beginning of the file before writing some data. Where does the data appear in the file? Why?

**先猜一下**（很多人第一反应是「数据会写到文件开头，因为刚 `lseek` 到 0」）——**错了**。

### 实现

完整源码 [`code/ex5_2_append_seek.c`](../code/ex5_2_append_seek.c)：

```c
/* ex5_2_append_seek.c — 原书习题 5-2
 *
 * 题目（逐字）：
 *   Write a program that opens and existing file for writing with the
 *   O_APPEND flag, and then seeks to the beginning of the file before
 *   writing some data.  Where does the data appear in the file?  Why?
 *
 * 答案：数据落在**文件末尾**。因为 O_APPEND 改变了 write() 的语义——内核在每次
 * write 时自己原子地跳到末尾再写，f_pos 被无视（不过写完后 f_pos 会被更新到新末尾）。
 *
 * 本 demo 同时跑「带 O_APPEND」和「不带 O_APPEND」两条路，把差别摆在一起看。
 *
 * 编译: gcc -O0 -Wall -Wextra -o ex5_2_append_seek ex5_2_append_seek.c
 */
#define _GNU_SOURCE
#include <fcntl.h>
#include <stdio.h>
#include <string.h>
#include <unistd.h>
#include <errno.h>

static void dump(const char *tag, const char *path)
{
    int r = open(path, O_RDONLY);
    char b[64];
    ssize_t n = r < 0 ? -1 : read(r, b, sizeof b - 1);

    if (n < 0)
        n = 0;
    b[n] = '\0';
    if (r >= 0)
        close(r);
    printf("    [%s] 内容 = \"%s\"（%ld 字节）\n", tag, b, (long) n);
}

static void make_file(const char *path)
{
    int fd = open(path, O_WRONLY | O_CREAT | O_TRUNC, 0644);

    if (fd < 0 || write(fd, "0123456789", 10) != 10)
        perror("make_file");
    if (fd >= 0)
        close(fd);
}

int main(void)
{
    const char *pa = "/tmp/c5_append_flag.txt";
    const char *pb = "/tmp/c5_no_append_flag.txt";
    char b[16];

    make_file(pa);
    make_file(pb);

    printf("== 准备：两个文件都是 \"0123456789\"（10 字节）==\n");

    printf("\n== A. 带 O_APPEND：先正常追加，再 lseek(0) 后追加 ==\n");
    {
        int fd = open(pa, O_WRONLY | O_APPEND);

        if (fd < 0) {
            perror("open O_APPEND");
            return 1;
        }
        write(fd, "AAA", 3);
        printf("    write(\"AAA\",3) 后 f_pos = %ld\n", (long) lseek(fd, 0, SEEK_CUR));
        dump("写完 AAA", pa);

        lseek(fd, 0, SEEK_SET);
        printf("    lseek(fd, 0, SEEK_SET) 后 f_pos = %ld\n", (long) lseek(fd, 0, SEEK_CUR));
        write(fd, "BBB", 3);
        printf("    在 f_pos=0 处 write(\"BBB\",3) 之后 f_pos = %ld\n",
               (long) lseek(fd, 0, SEEK_CUR));
        dump("写完 BBB", pa);
        printf("    → 数据还是追加到末尾：O_APPEND 让内核每次 write 都自己跳到末尾\n");

        close(fd);
    }

    printf("\n== B. 不带 O_APPEND：同样两步操作 ==\n");
    {
        int fd = open(pb, O_WRONLY);

        if (fd < 0) {
            perror("open");
            return 1;
        }
        write(fd, "AAA", 3);
        printf("    write(\"AAA\",3) 后 f_pos = %ld\n", (long) lseek(fd, 0, SEEK_CUR));
        dump("写完 AAA", pb);

        lseek(fd, 0, SEEK_SET);
        write(fd, "BBB", 3);
        printf("    在 f_pos=0 处 write(\"BBB\",3) 之后 f_pos = %ld\n",
               (long) lseek(fd, 0, SEEK_CUR));
        dump("写完 BBB", pb);
        printf("    → 这次老老实实从偏移 0 开始覆盖\n");

        close(fd);
    }

    printf("\n== 结论 ==\n");
    printf("    O_APPEND 与 f_pos 是两回事：前者是打开文件表项上的一个标志，\n");
    printf("    让 write() 在**同一个原子步骤**里定位到末尾再写；后者只是一个游标。\n");
    printf("    用 lseek 想\"绕开\"O_APPEND 是做不到的。\n");

    memset(b, 0, sizeof b);
    return 0;
}
```

编译运行：

```bash
gcc -O0 -Wall -Wextra -o ex5_2_append_seek ex5_2_append_seek.c && ./ex5_2_append_seek
```

### 实测（CE）

```text
== 准备：两个文件都是 "0123456789"（10 字节）==

== A. 带 O_APPEND：先正常追加，再 lseek(0) 后追加 ==
    write("AAA",3) 后 f_pos = 13
    [写完 AAA] 内容 = "0123456789AAA"（13 字节）
    lseek(fd, 0, SEEK_SET) 后 f_pos = 0
    在 f_pos=0 处 write("BBB",3) 之后 f_pos = 16
    [写完 BBB] 内容 = "0123456789AAABBB"（16 字节）
    → 数据还是追加到末尾：O_APPEND 让内核每次 write 都自己跳到末尾

== B. 不带 O_APPEND：同样两步操作 ==
    write("AAA",3) 后 f_pos = 3
    [写完 AAA] 内容 = "AAA3456789"（10 字节）
    在 f_pos=0 处 write("BBB",3) 之后 f_pos = 3
    [写完 BBB] 内容 = "BBB3456789"（10 字节）
    → 这次老老实实从偏移 0 开始覆盖

== 结论 ==
    O_APPEND 与 f_pos 是两回事：前者是打开文件表项上的一个标志，
    让 write() 在**同一个原子步骤**里定位到末尾再写；后者只是一个游标。
    用 lseek 想"绕开"O_APPEND 是做不到的。
```

**解读**：

| 观察 | 说明 |
|------|------|
| A 组：`lseek(fd, 0, SEEK_SET)` 后 `f_pos` **确实变成了 0** | `lseek` 是老实执行的——它确实把游标挪到了 0 |
| A 组：但写完之后 `f_pos = 16`，内容变成 `"0123456789AAABBB"` | **数据仍然去了末尾**。内核在 `write` 内部把「定位到 `i_size`」重做了一遍，`lseek` 的结果被**覆盖** |
| A 组：`f_pos` 从 0 变成 16 | 这个细节说明内核不只是「忽略」了 `f_pos`，而是**把它改成了写入后的新末尾**（10+3+3=16） |
| B 组：同样两步操作，结果从偏移 0 开始覆盖 | 没有 `O_APPEND` 时 `lseek` 的后果完全兑现，`"AAA"`/`"BBB"` 把前 3 字节覆盖掉，文件**没有变长** |
| 内核依据 | `generic_write_checks_count()`：`if (iocb->ki_flags & IOCB_APPEND) iocb->ki_pos = i_size_read(inode);`（`fs/read_write.c:1666-1667`）——**每次写之前都重设一次**，所以用户态的 `lseek` 永远无效 |

**答案是**：数据出现在**文件末尾**。因为 `O_APPEND` 不是一个「打开时的动作」，而是**打开文件表项上的一个持续性标志**：内核在每一次 `write()` 内部、在持有 inode 锁的情况下，把偏移强制设成 `i_size`，然后再写。这个「定位 + 写」是**同一个原子步骤**，用户态的 `lseek` 无法插手。

## 练习 5-3：为什么 `O_APPEND` 的原子性是必要的

### 题干（原书 Exercise 5-3，逐字）

> This exercise is designed to demonstrate why the atomicity guaranteed by opening a file with the `O_APPEND` flag is necessary. Write a program that takes up to three command-line arguments:
>
> `$ atomic_append filename num-bytes [x]`
>
> This file should open the specified filename (creating it if necessary) and append `num-bytes` bytes to the file by using `write()` to write a byte at a time. By default, the program should open the file with the `O_APPEND` flag, but if a third command-line argument (`x`) is supplied, then the `O_APPEND` flag should be omitted, and instead the program should perform an `lseek(fd, 0, SEEK_END)` call before each `write()`. Run two instances of this program at the same time without the `x` argument to write 1 million bytes to the same file:
>
> `$ atomic_append f1 1000000 & atomic_append f1 1000000`
>
> Repeat the same steps, writing to a different file, but this time specifying the `x` argument:
>
> `$ atomic_append f2 1000000 x & atomic_append f2 1000000 x`
>
> List the sizes of the files f1 and f2 using `ls -l` and explain the difference.

### 原书解答（`atomic_append.c`，page 110）

完整源码 [`code/atomic_append.c`](../code/atomic_append.c)，逐字镜像（这**不是** listing，是原书随书分发的习题解答文件）：

```c
/*************************************************************************\
*                  Copyright (C) Michael Kerrisk, 2026.                   *
*                                                                         *
* This program is free software. You may use, modify, and redistribute it *
* under the terms of the GNU General Public License as published by the   *
* Free Software Foundation, either version 3 or (at your option) any      *
* later version. This program is distributed without any warranty.  See   *
* the file COPYING.gpl-v3 for details.                                    *
\*************************************************************************/

/* atomic_append.c

   Demonstrate the difference between using nonatomic lseek()+write()
   and O_APPEND when writing to a file.

   Usage: file num-bytes [x]

   The program write 'num-bytes' bytes to 'file' a byte at a time. If
   no additional command-line argument is supplied, the program opens the
   file with the O_APPEND flag. If a command-line argument is supplied, the
   O_APPEND is omitted when calling open(), and the program calls lseek()
   to seek to the end of the file before calling write(). This latter
   technique is vulnerable to a race condition, where data is lost because
   the lseek() + write() steps are not atomic. This can be demonstrated
   by looking at the size of the files produced by these two commands:

        atomic_append f1 1000000 & atomic_append f1 1000000

        atomic_append f2 1000000 x & atomic_append f2 1000000 x
*/
#include <sys/stat.h>
#include <fcntl.h>
#include <stdbool.h>
#include "tlpi_hdr.h"

int
main(int argc, char *argv[])
{
    if (argc < 3 || strcmp(argv[1], "--help") == 0)
        usageErr("%s file num-bytes [x]\n"
                 "        'x' means use lseek() instead of O_APPEND\n",
                 argv[0]);

    bool useLseek = argc > 3;
    int flags = useLseek ? 0 : O_APPEND;
    int numBytes = getInt(argv[2], 0, "num-bytes");

    int fd = open(argv[1], O_RDWR | O_CREAT | flags, S_IRUSR | S_IWUSR);
    if (fd == -1)
        errExit("open");

    for (int j = 0; j < numBytes; j++) {
        if (useLseek)
            if (lseek(fd, 0, SEEK_END) == -1)
                errExit("lseek");
        if (write(fd, "x", 1) != 1)
            fatal("write() failed");
    }

    printf("%ld done\n", (long) getpid());
    exit(EXIT_SUCCESS);
}
```

关键就在这三行（`:44-46`）：

```c
    bool useLseek = argc > 3;
    int flags = useLseek ? 0 : O_APPEND;
```

以及循环体（`:52-58`）——**一次只写 1 字节**，这是把竞态窗口放到最大的手法：

```c
    for (int j = 0; j < numBytes; j++) {
        if (useLseek)
            if (lseek(fd, 0, SEEK_END) == -1)
                errExit("lseek");
        if (write(fd, "x", 1) != 1)
            fatal("write() failed");
    }
```

### 实测（CE）

运行时两个实例必须**并发**，沙箱里用 `&` 起两个进程：

```bash
gcc -O0 -Wall -Wextra -o atomic_append atomic_append.c
./atomic_append /tmp/f1.bin 200000 & ./atomic_append /tmp/f1.bin 200000
./atomic_append /tmp/f2.bin 200000 x & ./atomic_append /tmp/f2.bin 200000 x
```

侧记：本章 [5.1 的 demo](5.1-atomicity-race-conditions.md)（`c5_1_atomicity.c`，完整源码见该篇）把这套对照压缩进了一个进程（`fork` 两个子进程），跑出来的数字就是本节的硬证据：

```text
== 1. 两个写者并发写同一文件（各 200000 字节，一次一字节）==

-- O_APPEND：内核把「移到末尾 + 写」做成不可分割的一步 --
  写完后 st_size = 400000（期望 400000）

-- lseek+write：两步之间有窗口，两个进程会互相踩 --
  写完后 st_size = 391764（期望 400000）-> 丢 8236 字节
```

**「丢多少」是浮动的**：数值取决于两个进程被内核调度交错的密度，每次跑都可能不同（8236 只是本次的值，别当常量）。原书作者在真机上跑 100 万字节得到的是 `f1 = 2000000`（一个不丢）与 `f2 ≈ 1.2 MB`（丢了几十万）这样的量级差异——**方向一致，具体数字不可复现**。这也是 `atomic_append.c` 的注释里只给命令、不给期望数字的原因。

**解读**：

| 组 | 打开方式 | 每字节的操作 | 结果 |
|----|---------|-------------|------|
| `f1` | `O_APPEND` | 一次 `write(fd, "x", 1)` | 严格 `st_size = 2 × numBytes`，**一字节不丢** |
| `f2` | 无 `O_APPEND` | `lseek(fd, 0, SEEK_END)` **然后** `write(fd, "x", 1)` | 明显短于 `2 × numBytes`，**丢了** |

丢的机制（[5.1](5.1-atomicity-race-conditions.md) 已详述）：

```
进程 A                          进程 B
lseek(0, SEEK_END) → 位置 = 100
                                lseek(0, SEEK_END) → 位置 = 100   ← 两个都读到同一个末尾
write("x") 写在 100 → 长度 101
                                write("x") 写在 100 → 长度 101   ← 覆盖了 A 的那一字节
```

两个进程各自 `open` → **各自一个打开文件表项** → 各自的 `f_pos`。它们的 `lseek` 都读到「当时」的同一个末尾，于是两次写落在**同一偏移**上相互覆盖。**单字节 `write` 本身是原子的，是 `lseek` + `write` 这一对不原子。**

### 顺手验证 5-1 的另一半：`O_EXCL`

同一个 `c5_1_atomicity.c` 还演示了「先查再建」的 TOCTOU（第 2、3 段）：

```text
== 2. 先 open 检查、再 open 创建（没有 O_EXCL）==
  [PID     7] 不存在 → 我创建了它！
  [PID     8] 不存在 → 我创建了它！
  两个进程都声称「我创建了它」——但它们只创建了一个文件

== 3. 换成 O_CREAT|O_EXCL：检查与创建合成一个原子操作 ==
  [PID     9] O_EXCL 成功：确实是我创建的（唯一赢家）
  [PID    10] O_EXCL 失败 errno=17 (File exists)：别人抢先创建了
```

这正好是原书 Listing 5-1（`bad_exclusive_open.c`，page 90）想说的那件事——它的写法是「先 `open(O_CREAT|O_EXCL)`，失败再 `open(O_CREAT)`」，所以**第二个进程不会看到任何错误**：

```text
[PID 2] File "/dev/null" already exists
```

## 练习 5-4：用 `fcntl()` + `close()` 实现 `dup()` / `dup2()`

### 题干（原书 Exercise 5-4，逐字）

> Implement `dup()` and `dup2()` using `fcntl()` and, where necessary, `close()`. (You may ignore the fact that `dup2()` and `fcntl()` return different `errno` values for some error cases.) For `dup2()`, remember to handle the special case where `oldfd` equals `newfd`. In this case, you should check whether `oldfd` is valid, which can be done by, for example, checking if `fcntl(oldfd, F_GETFL)` succeeds. If `oldfd` is not valid, then the function should return `-1` with `errno` set to `EBADF`.

**要点拆解**：

| 要求 | 手段 |
|------|------|
| `dup(fd)` | `fcntl(fd, F_DUPFD, 0)` —— 取 ≥ 0 的最小可用号 |
| `dup2(fd, newfd)` | `close(newfd)`（若已打开）→ `fcntl(fd, F_DUPFD, newfd)` |
| `oldfd == newfd` 特例 | **不能关、不能复制**，但必须校验 `oldfd` 有效（用 `fcntl(oldfd, F_GETFL)` 试探） |

### 实现

完整源码 [`code/ex5_4_my_dup.c`](../code/ex5_4_my_dup.c)：

```c
/* ex5_4_my_dup.c — 原书习题 5-4
 *
 * 题目（逐字）：
 *   Implement dup() and dup2() using fcntl() and, where necessary,
 *   close().  (You may ignore the fact that dup2() and fcntl() return
 *   different errno values for some error cases.)  For dup2(), remember to
 *   handle the special case where oldfd equals newfd.  In this case, you
 *   should check whether oldfd is valid, which can be done by, for
 *   example, checking if fcntl(oldfd, F_GETFL) succeeds.  If oldfd is not
 *   valid, then the function should return -1 with errrno set to EBADF.
 *
 * 思路：
 *   my_dup(fd)         = fcntl(fd, F_DUPFD, 0)      —— 0 表示「不小于 0 的最小可用号」
 *   my_dup2(old, new)  = 先处理 old == new 的特例（只校验有效性，别关它！）
 *                        否则先 close(new) 腾号，再 fcntl(old, F_DUPFD, new)
 *
 * 讲这个题的意义在于：dup2() 的"若 new 已打开就先关掉它"这一步，只有在
 * fcntl(F_DUPFD) 这个原语之上才是安全的（关完之后目标号一定空着，不会被抢）。
 *
 * 编译: gcc -O0 -Wall -Wextra -o ex5_4_my_dup ex5_4_my_dup.c
 */
#define _GNU_SOURCE
#include <fcntl.h>
#include <stdio.h>
#include <string.h>
#include <unistd.h>
#include <errno.h>

/* dup() 的等价实现：复制到「不小于 0 的最小可用号」 */
static int my_dup(int fd)
{
    return fcntl(fd, F_DUPFD, 0);
}

/* dup2() 的等价实现 */
static int my_dup2(int oldfd, int newfd)
{
    if (newfd < 0) {                    /* 负数号不合法（dup2 对它是 EBADF） */
        errno = EBADF;
        return -1;
    }

    if (oldfd == newfd) {
        /* 特例：不能 close 再 dup——那会把唯一的 fd 弄丢。
           只需要校验 oldfd 是否有效即可。 */
        return fcntl(oldfd, F_GETFL) == -1 ? -1 : newfd;
    }

    /* 先确认 oldfd 有效（也让错误码是 EBADF 而不是别的东西） */
    if (fcntl(oldfd, F_GETFL) == -1)
        return -1;

    close(newfd);                       /* newfd 原样打开着就先关掉（关一个没开的号也只是 EBADF） */
    return fcntl(oldfd, F_DUPFD, newfd);   /* 取「不小于 newfd 的最小可用号」——此时就是 newfd */
}

int main(void)
{
    const char *p = "/tmp/c5_mydup.txt";
    int fd = open(p, O_RDWR | O_CREAT | O_TRUNC, 0644);

    if (fd < 0) {
        perror("open");
        return 1;
    }
    write(fd, "ABCDEFGHIJ", 10);

    printf("== 1. my_dup() 与真 dup() 对照 ==\n");
    {
        int a = my_dup(fd);
        int b = dup(fd);
        char x[4] = { 0 }, y[4] = { 0 };

        printf("    my_dup(%d) -> %d    真 dup(%d) -> %d\n", fd, a, fd, b);
        lseek(a, 3, SEEK_SET);                      /* a 动偏移 */
        printf("    lseek(a, 3) 之后：a 的 f_pos=%ld，原 fd 的 f_pos=%ld（共享）\n",
               (long) lseek(a, 0, SEEK_CUR), (long) lseek(fd, 0, SEEK_CUR));
        lseek(fd, 0, SEEK_SET);
        if (read(a, x, 3) != 3 || read(fd, y, 3) != 3)
            perror("read");
        printf("    经由 a 和原 fd 各读 3 字节：\"%s\" / \"%s\"（同一个打开文件表项）\n", x, y);
        close(a);
        close(b);
    }

    printf("\n== 2. my_dup2(fd, 42)：指定目标号 ==\n");
    {
        int r = my_dup2(fd, 42);

        printf("    my_dup2(%d, 42) -> %d\n", fd, r);
        printf("    lseek(42, 7) 之后原 fd 的 f_pos = %ld（共享偏移，确认是同一个表项）\n",
               (long) (lseek(42, 7, SEEK_SET), lseek(fd, 0, SEEK_CUR)));
        close(42);
    }

    printf("\n== 3. my_dup2(fd, fd)：old == new 的特例 ==\n");
    printf("    my_dup2(%d, %d) -> %d（原样返回，不能关也不能复制）\n",
           fd, fd, my_dup2(fd, fd));
    {
        int rc = my_dup2(999, 999);              /* 先调用、后取 errno */

        printf("    my_dup2(999, 999) -> %d errno=%d (%s)  ← 无效 fd 必须报 EBADF\n",
               rc, errno, strerror(errno));
    }
    {
        int rc = dup2(999, 999);

        printf("    真 dup2(999, 999) -> %d errno=%d (%s)  ← 行为一致\n",
               rc, errno, strerror(errno));
    }

    printf("\n== 4. 目标号已被占用时，先关再复制 ==\n");
    {
        int other = open("/dev/null", O_RDONLY);     /* 占一个新号 */

        printf("    先用 /dev/null 占住 %d 号\n", other);
        printf("    my_dup2(%d, %d) -> %d，随后向 %d 写数据看落到哪里：\n",
               fd, other, my_dup2(fd, other), other);
        if (write(other, "ZZZ", 3) != 3)
            perror("write");
        {
            int rf = open(p, O_RDONLY);
            char b[32];
            ssize_t n = read(rf, b, sizeof b - 1);

            b[n > 0 ? n : 0] = '\0';
            close(rf);
            printf("    文件现在是 \"%s\"  ← 说明 %d 号确实被 my_dup2 重新指向了文件\n",
                   b, other);
        }
        close(other);
    }

    printf("\n== 5. 错误路径 ==\n");
    {
        int rc = my_dup(999);

        printf("    my_dup(999)      -> %d errno=%d (%s)\n", rc, errno, strerror(errno));
    }
    {
        int rc = my_dup2(999, 7);

        printf("    my_dup2(999, 7)  -> %d errno=%d (%s)\n",
               rc, errno, strerror(errno));
    }

    close(fd);
    return 0;
}
```

编译运行：

```bash
gcc -O0 -Wall -Wextra -o ex5_4_my_dup ex5_4_my_dup.c && ./ex5_4_my_dup
```

```text

    my_dup(3) -> 4    真 dup(3) -> 5
    lseek(a, 3) 之后：a 的 f_pos=3，原 fd 的 f_pos=3（共享）

== 2. my_dup2(fd, 42)：指定目标号 ==

    lseek(42, 7) 之后原 fd 的 f_pos = 7（共享偏移，确认是同一个表项）

== 3. my_dup2(fd, fd)：old == new 的特例 ==
    my_dup2(3, 3) -> 3（原样返回，不能关也不能复制）
    my_dup2(999, 999) -> -1 errno=9 (Bad file descriptor)  ← 无效 fd 必须报 EBADF
    真 dup2(999, 999) -> -1 errno=9 (Bad file descriptor)  ← 行为一致

== 4. 目标号已被占用时，先关再复制 ==
    先用 /dev/null 占住 4 号
    my_dup2(3, 4) -> 4，随后向 4 写数据看落到哪里：
    文件现在是 "ABCDEFGZZZ"  ← 说明 4 号确实被 my_dup2 重新指向了文件

== 5. 错误路径 ==
    my_dup(999)      -> -1 errno=9 (Bad file descriptor)
    my_dup2(999, 7)  -> -1 errno=9 (Bad file descriptor)
```

**解读**：

| 观察 | 说明 |
|------|------|
| `my_dup(3) -> 4`，紧接着 `dup(3) -> 5` | 手写版先占了 4 号，所以真 `dup` 拿到 5。**两者结果都是「最小可用号」**，只是取的时刻不同 |
| `lseek(a, 3)` 之后原 fd 的 `f_pos` 也变成 `3`；两次读分别是 `"ABC"` / `"DEF"` | 手写版**确实**做出了「共享打开文件表项」——这正是 `F_DUPFD` 的语义（[5.5](5.5-duplicating-fds.md) 的内核链路：`f_dupfd()` → `alloc_fd()` → 同一个 `struct file`，`f_count++`） |
| `my_dup2(3, 3) -> 3` | 特例处理正确：**原样返回**，既不关也不复制 |
| `my_dup2(999, 999) -> EBADF`，与真 `dup2` **完全一致** | 这是题干专门点名的要求：`old == new` 时也不能跳过「`old` 是否有效」的校验。手写版的 `F_GETFL` 试探成功复刻了这个行为 |
| `my_dup2(3, 4) -> 4`，随后写数据落到**文件**（`"ABCDEFGZZZ"`） | 「目标号已被 `/dev/null` 占用 → 先 `close(4)` 再 `F_DUPFD`」这条路径生效了 |

**与内核实现的差距**（诚实版）：

| 项 | 本题实现（`close` + `F_DUPFD`） | 真 `dup2` / 内核 |
|----|-------------------------------|-----------------|
| 原子性 | **不原子**：`close(4)` 与 `F_DUPFD` 之间可被信号/线程插入 | 原子（`fs/file.c:1105` `do_dup2`，一次拿住 fd 表锁） |
| 目标号被抢占 | 有窗口：另一线程可能在这两步之间拿到 4 号 | 无窗口 |
| `errno` 细节 | 与 `dup2` 可能不同（题干允许忽略） | 按 POSIX 定义 |
| 用户态可见行为 | 单线程受控场景下**完全等价** | — |

> 顺带印证 [5.5](5.5-duplicating-fds.md) 的一条：`dup3(old, new, flags)` 在 `old == new` 时直接 `-EINVAL`（`fs/file.c:1241-1242`），而 `dup2` 是「原样返回」——**POSIX 与 Linux 在这里故意不一致**。

## 练习 5-5：验证复制出来的 fd 共享偏移与状态标志

### 题干（原书 Exercise 5-5，逐字）

> Write a program to verify that duplicated file descriptors share a file offset value and open file status flags.

### 实现

完整源码 [`code/ex5_5_shared_offset_flags.c`](../code/ex5_5_shared_offset_flags.c)：

```c
/* ex5_5_shared_offset_flags.c — 原书习题 5-5
 *
 * 题目（逐字）：
 *   Write a program to verify that duplicated file descriptors share a
 *   file offset value and open file status flags.
 *
 * 要验证的是两样东西「共享」，同时要看清一样东西「不共享」：
 *   ✅ 文件偏移 f_pos          —— 共享（在打开文件表项里）
 *   ✅ 打开文件状态标志 F_GETFL —— 共享（同上）
 *   ❌ 文件描述符标志 F_GETFD   —— **不共享**（在 fd 表那一层，FD_CLOEXEC 各算各的）
 * 第三点是本题的鉴别器：如果连 FD_CLOEXEC 都"共享"，说明对三层结构理解错了。
 *
 * 编译: gcc -O0 -Wall -Wextra -o ex5_5_shared_offset_flags ex5_5_shared_offset_flags.c
 */
#define _GNU_SOURCE
#include <fcntl.h>
#include <stdio.h>
#include <string.h>
#include <unistd.h>
#include <errno.h>

int main(void)
{
    const char *p = "/tmp/c5_share.txt";
    int fd1 = open(p, O_RDWR | O_CREAT | O_TRUNC, 0644);
    int fd2, fd3;

    if (fd1 < 0) {
        perror("open");
        return 1;
    }
    write(fd1, "ABCDEFGHIJ", 10);
    fd2 = dup(fd1);                     /* 同一个打开文件表项 */
    fd3 = open(p, O_RDWR);              /* 另一个打开文件表项 */

    printf("== 0. 三个 fd：fd1=%d  fd2=dup(fd1)=%d  fd3=open()=%d ==\n", fd1, fd2, fd3);
    printf("    fd1/fd2 共享打开文件表项；fd3 独立\n\n");

    printf("== 1. 偏移共享 ==\n");
    lseek(fd1, 0, SEEK_SET);
    lseek(fd2, 0, SEEK_SET);
    lseek(fd3, 0, SEEK_SET);
    printf("    先把三个都摆到 0：fd1=%ld fd2=%ld fd3=%ld\n",
           (long) lseek(fd1, 0, SEEK_CUR), (long) lseek(fd2, 0, SEEK_CUR),
           (long) lseek(fd3, 0, SEEK_CUR));
    {
        char b[4] = { 0 };

        if (read(fd1, b, 3) != 3)
            perror("read");
        printf("    从 fd1 读 3 字节后：fd1=%ld fd2=%ld fd3=%ld\n",
               (long) lseek(fd1, 0, SEEK_CUR), (long) lseek(fd2, 0, SEEK_CUR),
               (long) lseek(fd3, 0, SEEK_CUR));
        printf("    → fd2 跟着动了（共享），fd3 没动（独立）\n");
    }

    printf("\n== 2. 状态标志共享（F_GETFL）==\n");
    printf("    初始：fd1=0x%05x fd2=0x%05x fd3=0x%05x\n",
           fcntl(fd1, F_GETFL), fcntl(fd2, F_GETFL), fcntl(fd3, F_GETFL));
    fcntl(fd2, F_SETFL, fcntl(fd2, F_GETFL) | O_APPEND);    /* 只对 fd2 设置 */
    printf("    只对 fd2 设 O_APPEND 之后：\n");
    printf("      fd1=0x%05x O_APPEND=%d\n",
           fcntl(fd1, F_GETFL), !!(fcntl(fd1, F_GETFL) & O_APPEND));
    printf("      fd2=0x%05x O_APPEND=%d\n",
           fcntl(fd2, F_GETFL), !!(fcntl(fd2, F_GETFL) & O_APPEND));
    printf("      fd3=0x%05x O_APPEND=%d\n",
           fcntl(fd3, F_GETFL), !!(fcntl(fd3, F_GETFL) & O_APPEND));
    printf("    → fd1 跟着变了（共享），fd3 没变（独立打开文件表项）\n");

    printf("\n== 3. 别搞错：描述符标志（F_GETFD）**不**共享 ==\n");
    printf("    初始：fd1 F_GETFD=0x%x fd2 F_GETFD=0x%x\n",
           fcntl(fd1, F_GETFD), fcntl(fd2, F_GETFD));
    fcntl(fd2, F_SETFD, FD_CLOEXEC);            /* 只对 fd2 设置 */
    printf("    只对 fd2 设 FD_CLOEXEC 之后：\n");
    printf("      fd1 F_GETFD=0x%x FD_CLOEXEC=%d\n",
           fcntl(fd1, F_GETFD), !!(fcntl(fd1, F_GETFD) & FD_CLOEXEC));
    printf("      fd2 F_GETFD=0x%x FD_CLOEXEC=%d\n",
           fcntl(fd2, F_GETFD), !!(fcntl(fd2, F_GETFD) & FD_CLOEXEC));
    printf("    → 只有 fd2 有。CLOEXEC 属于「哪一个 fd」，不属于「打开的文件」\n");

    printf("\n== 4. 小结（三层结构各管什么）==\n");
    printf("    进程 fd 表      :  fd 号 → 打开文件表项指针；FD_CLOEXEC 存在这里\n");
    printf("    打开文件表项     :  f_pos 偏移、f_flags 状态标志；dup/fork 共享它\n");
    printf("    i-node 表       :  文件类型、权限、大小、数据块；所有打开者共享\n");

    close(fd1);
    close(fd2);
    close(fd3);
    return 0;
}
```

```text
      fd2=0x08402 O_APPEND=1
      fd3=0x08002 O_APPEND=0
    → fd1 跟着变了（共享），fd3 没变（独立打开文件表项）

== 3. 别搞错：描述符标志（F_GETFD）**不**共享 ==
    初始：fd1 F_GETFD=0x0 fd2 F_GETFD=0x0
    只对 fd2 设 FD_CLOEXEC 之后：
      fd1 F_GETFD=0x0 FD_CLOEXEC=0
      fd2 F_GETFD=0x1 FD_CLOEXEC=1
    → 只有 fd2 有。CLOEXEC 属于「哪一个 fd」，不属于「打开的文件」

== 4. 小结（三层结构各管什么）==
    进程 fd 表      :  fd 号 → 打开文件表项指针；FD_CLOEXEC 存在这里
    打开文件表项     :  f_pos 偏移、f_flags 状态标志；dup/fork 共享它
    i-node 表       :  文件类型、权限、大小、数据块；所有打开者共享
```

**解读**：

| 观察 | 说明 |
|------|------|
| 从 fd1 读 3 字节 → `fd1=3` **且** `fd2=3`，而 `fd3` 仍是 `0` | **偏移共享**得证。`f_pos` 在 `struct file` 里（`include/linux/fs.h:1007`），`dup` 产出的两个 fd 指向同一个 `struct file` |
| 只对 fd2 设 `O_APPEND` → fd1 的 `F_GETFL` 也变成 `0x08402` | **状态标志也共享**得证。`f_flags` 同样在 `struct file` 里（`:1008`） |
| `fd3` 两者都没跟着变 | 它是**另一次 `open`** 的产物，有**自己的** `struct file`。这正是 `open` 与 `dup` 的根本区别 |
| 只对 fd2 设 `FD_CLOEXEC` → **只有** fd2 的 `F_GETFD = 0x1` | 题干只要求验证前两项，但这一条是**最容易被搞错**的：`FD_CLOEXEC` 属于**层 ①**（fd 表项），所以 `dup` 出来的新 fd **不**继承它（`fs/file.c:1286` 的 `dup` → `__dentry_open` 之外的分配路径不会带上 `FD_CLOEXEC`） |

> 这道题与练习 5-6 是同一件事的**代码版**与**推演版**——题干只要求「验证偏移和标志共享」，而本仓库的实现顺手把「哪一层管什么」补全了，因为**只验证前两项会让人误以为「所有东西都共享」**。

## 练习 5-6：逐行推演多个描述符的输出

### 题干（原书 Exercise 5-6，逐字）

> After each of the calls to `write()` in the following code, explain what the content of the output file would be, and why:

```c
fd1 = open(file, O_RDWR | O_CREAT | O_TRUNC, S_IRUSR | S_IWUSR);
fd2 = dup(fd1);
fd3 = open(file, O_RDWR);
write(fd1, "Hello,", 6);
write(fd2, " world", 6);
lseek(fd2, 0, SEEK_SET);
write(fd1, "HELLO,", 6);
write(fd3, "Gidday", 6);
```

> **⚠️ 一处转载差异（诚实标注）**：部分网上转载把第 5 行写成 `write(fd2, "world", 6)`（丢了前导空格）。**man7 官方分发版本**（`fileio/multi_descriptors.c`，即原书 page 111 的解答）写的是 `" world"`（6 字节，含前导空格）——下面按官方版本推演。二者差别会体现在最终内容上（详见末尾）。

### 前置：三个描述符的关系

| fd | 怎么来的 | 指向 |
|----|---------|------|
| `fd1` | `open(file, O_RDWR\|O_CREAT\|O_TRUNC)` | **表项 A**，偏移 0，文件被截断为 0 字节 |
| `fd2` | `dup(fd1)` | **表项 A**（与 fd1 同一个），偏移**共享** |
| `fd3` | `open(file, O_RDWR)` | **表项 B**（新的），偏移**独立**，从 0 开始 |

### 逐行推演

| # | 调用 | 表项 A（fd1/fd2）偏移 | 表项 B（fd3）偏移 | 文件内容 | 为什么 |
|---|------|---------------------|------------------|---------|--------|
| 0 | （初始） | `0` | `0` | `""`（0 字节） | `O_TRUNC` 把文件清空 |
| 1 | `write(fd1, "Hello,", 6)` | `6` | `0` | `"Hello,"` | 从偏移 0 写 6 字节。**fd3 的偏移不动**（不同表项） |
| 2 | `write(fd2, " world", 6)` | `12` | `0` | `"Hello, world"` | fd2 与 fd1 **共享偏移**，所以接着从 6 写到 12 |
| 3 | `lseek(fd2, 0, SEEK_SET)` | `0` | `0` | `"Hello, world"`（不变） | `lseek` 改的是**表项 A** 的偏移 → **fd1 的偏移也回到 0**；此时 fd3 也是 0 |
| 4 | `write(fd1, "HELLO,", 6)` | `6` | `0` | `"HELLO, world"` | 因为上一步把 fd1 的偏移也拖回了 0，这次写**覆盖前 6 字节** |
| 5 | `write(fd3, "Gidday", 6)` | `6` | `6` | `"Gidday world"` | fd3 的偏移**一直是 0**，所以从 0 开始覆盖前 6 字节 |

**最终内容：`"Gidday world"`（12 字节）。**

三个「为什么」：

1. **第 2 步为什么接着写** —— `dup` 共享打开文件表项，所以 `f_pos` 是同一个变量。
2. **第 4 步为什么回到开头** —— `lseek(fd2, 0)` 改的也是那个共享的 `f_pos`，**fd1 被动跟着回 0**。这是本题最容易漏的一环：很多人以为「我只动了 fd2」。
3. **第 5 步为什么覆盖开头** —— fd3 是**独立表项**，它的偏移从未被写过，始终是 0。

### 实现与实测（本仓库的复刻版）

原书解答 `multi_descriptors.c`（page 111）在每次写之后插一句 `system("cat a; echo")` 让你**亲眼看到**文件内容的变化。完整源码 [`code/multi_descriptors.c`](../code/multi_descriptors.c)（逐字镜像）：

```c
/* multi_descriptors.c

   Show the interaction of multiple descriptors accessing the same
   file (some via the same shared open file table entry).
*/
#include <sys/stat.h>
#include <fcntl.h>
#include "tlpi_hdr.h"

int
main(int argc, char *argv[])
{
    int fd1, fd2, fd3;
#define file "a"
    char cmd[] = "cat " file "; echo";

    fd1 = open(file, O_RDWR | O_CREAT | O_TRUNC, S_IRUSR | S_IWUSR);
    if (fd1 == -1)
        errExit("open fd1");
    fd2 = dup(fd1);
    if (fd2 == -1)
        errExit("dup");
    fd3 = open(file, O_RDWR);
    if (fd3 == -1)
        errExit("open fd3");

    /* 'fd1' and 'fd2' share same open file table entry (and thus file
       offset). 'fd3' has its own open file table entry, and thus a
       separate file offset. */

    if (write(fd1, "Hello,", 6) == -1)
        errExit("write1");
    system(cmd);
    if (write(fd2, " world", 6) == -1)
        errExit("write2");
    system(cmd);
    if (lseek(fd2, 0, SEEK_SET) == -1)
        errExit("lseek");
    if (write(fd1, "HELLO,", 6) == -1)
        errExit("write3");
    system(cmd);
    if (write(fd3, "Gidday", 6) == -1)
        errExit("write4");
    system(cmd);

    if (close(fd1) == -1)
        errExit("close output");
    if (close(fd2) == -1)
        errExit("close output");
    if (close(fd3) == -1)
        errExit("close output");
    exit(EXIT_SUCCESS);
}
```

**它在 CE 沙箱里没有输出**：因为 `system()` 要 `fork+exec` 一个 `/bin/sh`，而沙箱里**没有 `/bin/sh`**（`system()` 返回 `32512`）。这不是程序错，是环境限制（见 [5.13 的沙箱环境限制表](5.13-summary.md)）。

所以本仓库另写了一个**不依赖 `system()`** 的复刻版 [`code/c5_4_fd_open_files.c`](../code/c5_4_fd_open_files.c)，把每一步的**偏移和内容**都打印出来：

```c
/* c5_4_fd_open_files.c — §5.4 文件描述符与打开文件的关系：三层结构
 *
 * 内核里访问一个文件要经过三张表：
 *     进程的 fd 表           系统级打开文件表             i-node 表
 *   ┌──────────────┐      ┌────────────────────┐      ┌──────────────┐
 *   │ 0,1,2 ...    │      │ 打开文件表项        │      │  i-node      │
 *   │ fd1 ───────────────▶│ 文件偏移 f_pos      │─────▶│  文件元数据   │
 *   │ fd2 ───────────────▶│ 状态标志 f_flags    │      │  文件内容     │
 *   │ fd3 ──────┐         └────────────────────┘      └──────────────┘
 *   └───────────┼───────────┘         ▲
 *               └─────────────────────┘ 另一个打开文件表项（各自独立的偏移）
 *
 * dup 让两个 fd 指向**同一个**打开文件表项 → 共享偏移与状态标志；
 * 再 open 一次则是**另一个**表项 → 偏移各算各的，但 i-node 是同一个。
 *
 * 本 demo 复刻原书 multi_descriptors.c（习题 5-6）的四步写入，并在每步之后
 * 用一个额外的只读 fd 把文件真读出来看——原书靠 system("cat a") 打印，
 * CE 沙箱里没有 /bin/sh，所以改用原生 read()。
 *
 * 编译: gcc -O0 -Wall -Wextra -o c5_4_fd_open_files c5_4_fd_open_files.c
 */
#define _GNU_SOURCE
#include <fcntl.h>
#include <stdio.h>
#include <string.h>
#include <sys/stat.h>
#include <unistd.h>
#include <errno.h>

#define FILE_A "/tmp/c5_multi_a"

/* 另开一个只读 fd 把全文读出来（这个 fd 是第 4 个打开文件表项，不影响上面三个的偏移） */
static void dump(const char *tag)
{
    int r = open(FILE_A, O_RDONLY);
    char buf[64];
    ssize_t n;

    if (r < 0) {
        printf("    [%s] 打开失败: %s\n", tag, strerror(errno));
        return;
    }
    n = read(r, buf, sizeof buf - 1);
    if (n < 0)
        n = 0;
    buf[n] = '\0';
    printf("    [%-16s] 内容 = \"%s\"\n", tag, buf);
    close(r);
}

static long cur(int fd)
{
    return (long) lseek(fd, 0, SEEK_CUR);
}

static void state(int fd1, int fd2, int fd3)
{
    printf("    偏移: fd1=%ld fd2=%ld fd3=%ld  (fd1/fd2 永远相等)\n",
           cur(fd1), cur(fd2), cur(fd3));
}

int main(void)
{
    int fd1 = open(FILE_A, O_RDWR | O_CREAT | O_TRUNC, 0600);
    int fd2, fd3;
    struct stat s1, s3;

    if (fd1 < 0) {
        perror("open fd1");
        return 1;
    }
    fd2 = dup(fd1);                     /* 同一个打开文件表项 */
    fd3 = open(FILE_A, O_RDWR);         /* 另一个打开文件表项 */
    if (fd2 < 0 || fd3 < 0) {
        perror("dup/open");
        return 1;
    }
    printf("== 0. 三个 fd 就位 ==\n");
    printf("    fd1=open(O_RDWR|O_CREAT|O_TRUNC) -> %d\n", fd1);
    printf("    fd2=dup(fd1)                     -> %d\n", fd2);
    printf("    fd3=open(O_RDWR)                 -> %d\n", fd3);
    printf("    fd1/fd2 同一打开文件表项；fd3 是另一个表项\n");

    fstat(fd1, &s1);
    fstat(fd3, &s3);
    printf("    i-node：fd1 的 st_ino=%llu、fd3 的 st_ino=%llu，同一个（都是 %llu）\n",
           (unsigned long long) s1.st_ino, (unsigned long long) s3.st_ino,
           (unsigned long long) s1.st_ino);

    printf("\n== 1. write(fd1, \"Hello,\", 6) ==\n");
    if (write(fd1, "Hello,", 6) != 6)
        perror("write1");
    dump("写 fd1 后");
    state(fd1, fd2, fd3);

    printf("\n== 2. write(fd2, \" world\", 6) —— 接着 fd1 的偏移往后写 ==\n");
    if (write(fd2, " world", 6) != 6)
        perror("write2");
    dump("写 fd2 后");
    state(fd1, fd2, fd3);

    printf("\n== 3. lseek(fd2, 0, SEEK_SET) —— 只动 fd2，但 fd1 的偏移也跟着回 0 ==\n");
    if (lseek(fd2, 0, SEEK_SET) == (off_t) -1)
        perror("lseek");
    dump("lseek 后");
    state(fd1, fd2, fd3);

    printf("\n== 4. write(fd1, \"HELLO,\", 6) —— 从 0 开始覆盖 ==\n");
    if (write(fd1, "HELLO,", 6) != 6)
        perror("write3");
    dump("写 fd1 后");
    state(fd1, fd2, fd3);

    printf("\n== 5. write(fd3, \"Gidday\", 6) —— fd3 的偏移还停在 0 ==\n");
    if (write(fd3, "Gidday", 6) != 6)
        perror("write4");
    dump("写 fd3 后");
    state(fd1, fd2, fd3);

    printf("\n== 6. 状态标志也在打开文件表项里，所以 fd1/fd2 共享、fd3 不共享 ==\n");
    fcntl(fd2, F_SETFL, fcntl(fd2, F_GETFL) | O_APPEND);   /* 只对 fd2 设 */
    printf("    fd1 F_GETFL=0x%05x O_APPEND=%d\n",
           fcntl(fd1, F_GETFL), !!(fcntl(fd1, F_GETFL) & O_APPEND));
    printf("    fd2 F_GETFL=0x%05x O_APPEND=%d\n",
           fcntl(fd2, F_GETFL), !!(fcntl(fd2, F_GETFL) & O_APPEND));
    printf("    fd3 F_GETFL=0x%05x O_APPEND=%d  ← 独立表项，不受影响\n",
           fcntl(fd3, F_GETFL), !!(fcntl(fd3, F_GETFL) & O_APPEND));

    close(fd1);
    close(fd2);
    close(fd3);
    return 0;
}
```

额外收获两点：

| 观察 | 说明 |
|------|------|
| `st_ino` 两个都是 `2` | **两个不同表项指向同一个 inode**——这是三层结构最直白的一张照片（[5.4](5.4-fd-and-open-files.md)）。偏移不同、inode 相同 |

## 练习 5-7：用 `read()`/`write()` + `malloc` 实现 `readv()`/`writev()`

### 题干（原书 Exercise 5-7，逐字）

> Implement `readv()` and `writev()` using `read()`, `write()`, and suitable functions from the `malloc` package (Section 7.1.2).

### 实现

完整源码 [`code/ex5_7_readv_by_read.c`](../code/ex5_7_readv_by_read.c)：

```c
/* ex5_7_readv_by_read.c — 原书习题 5-7
 *
 * 题目（逐字）：
 *   Implement readv() and writev() using read() and write(), and
 *   suitable functions from the malloc package (Section 7.1.2).
 *
 * 做法：
 *   my_writev = 先把各段"聚集"到一块 malloc 出来的连续内存，再一次 write()
 *   my_readv  = 先 read() 到一块连续内存，再按 iov 切分"分散"拷到各段
 * 注意短读/短写：n 可能小于总长，切分时不能越界。
 *
 * 编译: gcc -O0 -Wall -Wextra -o ex5_7_readv_by_read ex5_7_readv_by_read.c
 */
#define _GNU_SOURCE
#include <fcntl.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <sys/uio.h>
#include <unistd.h>
#include <errno.h>

static size_t iov_total(const struct iovec *iov, int cnt)
{
    size_t t = 0;

    for (int i = 0; i < cnt; i++)
        t += iov[i].iov_len;
    return t;
}

/* 用 read() + malloc 实现 readv()：读进连续缓冲，再分散到各段 */
static ssize_t my_readv(int fd, const struct iovec *iov, int cnt)
{
    size_t total = iov_total(iov, cnt);
    char *buf = malloc(total > 0 ? total : 1);
    ssize_t n;

    if (buf == NULL) {
        errno = ENOMEM;
        return -1;
    }
    n = read(fd, buf, total);
    if (n > 0) {
        ssize_t done = 0;

        for (int i = 0; i < cnt && done < n; i++) {
            size_t chunk = iov[i].iov_len;

            if ((size_t) (n - done) < chunk)
                chunk = (size_t) (n - done);        /* 短读：只拷剩下的 */
            memcpy(iov[i].iov_base, buf + done, chunk);
            done += (ssize_t) chunk;
        }
    }
    free(buf);
    return n;
}

/* 用 write() + malloc 实现 writev()：先聚集到连续缓冲，再一次写出 */
static ssize_t my_writev(int fd, const struct iovec *iov, int cnt)
{
    size_t total = iov_total(iov, cnt);
    char *buf = malloc(total > 0 ? total : 1);
    ssize_t n;
    size_t off = 0;

    if (buf == NULL) {
        errno = ENOMEM;
        return -1;
    }
    for (int i = 0; i < cnt; i++) {
        memcpy(buf + off, iov[i].iov_base, iov[i].iov_len);
        off += iov[i].iov_len;
    }
    n = write(fd, buf, total);
    free(buf);
    return n;
}

static char *slurp(const char *path, ssize_t *len)
{
    int fd = open(path, O_RDONLY);
    static char buf[256];
    ssize_t n;

    if (fd < 0)
        return NULL;
    n = read(fd, buf, sizeof buf - 1);
    close(fd);
    if (n < 0)
        n = 0;
    buf[n] = '\0';
    *len = n;
    return buf;
}

int main(void)
{
    const char *pa = "/tmp/c5_iov_real.bin";     /* 用真 writev 写 */
    const char *pb = "/tmp/c5_iov_mine.bin";     /* 用 my_writev 写 */
    const char *hdr = "REC1|";
    const char *tail = "|END";
    char body[8];

    memcpy(body, "abcdefgh", 8);

    printf("== 1. 真 writev 与手写 my_writev 的对照 ==\n");
    {
        struct iovec iov[3];
        int fa = open(pa, O_RDWR | O_CREAT | O_TRUNC, 0644);
        int fb = open(pb, O_RDWR | O_CREAT | O_TRUNC, 0644);
        ssize_t na, nb;

        iov[0].iov_base = (void *) hdr;  iov[0].iov_len = strlen(hdr);
        iov[1].iov_base = body;          iov[1].iov_len = sizeof body;
        iov[2].iov_base = (void *) tail; iov[2].iov_len = strlen(tail);

        na = writev(fa, iov, 3);
        nb = my_writev(fb, iov, 3);
        printf("    真 writev  -> %ld 字节\n", (long) na);
        printf("    my_writev  -> %ld 字节\n", (long) nb);
        close(fa);
        close(fb);

        {
            ssize_t la, lb;
            char *ca = slurp(pa, &la);
            char *cb = slurp(pb, &lb);

            printf("    两个文件内容：\"%s\" / \"%s\"\n", ca ? ca : "?", cb ? cb : "?");
            printf("    memcmp -> %s\n",
                   (la == lb && memcmp(ca, cb, (size_t) la) == 0) ? "完全相同" : "不同");
        }
    }

    printf("\n== 2. my_readv 把整条记录分散读回来 ==\n");
    {
        int fd = open(pa, O_RDONLY);
        char h[8] = { 0 }, t[8] = { 0 }, b[16] = { 0 };
        struct iovec iov[3];
        ssize_t n;

        iov[0].iov_base = h;  iov[0].iov_len = 5;
        iov[1].iov_base = b;  iov[1].iov_len = 8;
        iov[2].iov_base = t;  iov[2].iov_len = 4;
        n = my_readv(fd, iov, 3);
        printf("    my_readv -> %ld 字节（请求 %zu）\n",
               (long) n, iov_total(iov, 3));
        printf("    三段 = \"%s\" / \"%s\" / \"%s\"\n", h, b, t);
        close(fd);
    }

    printf("\n== 3. 短读时 my_readv 不能越界 ==\n");
    {
        int fd = open(pa, O_RDONLY);
        char b[64];
        struct iovec iov[3];
        ssize_t n;

        memset(b, 0x7f, sizeof b);               /* 先填成 0x7f，方便看有没有被写坏 */
        lseek(fd, 0, SEEK_END);
        printf("    文件总长 = %ld\n", (long) lseek(fd, 0, SEEK_CUR));
        lseek(fd, (off_t) (lseek(fd, 0, SEEK_CUR) - 3), SEEK_SET);   /* 只剩 3 字节 */

        iov[0].iov_base = b;      iov[0].iov_len = 5;    /* 第一段就要 5，最多只给 3 */
        iov[1].iov_base = b + 8;  iov[1].iov_len = 5;
        iov[2].iov_base = b + 16; iov[2].iov_len = 5;
        n = my_readv(fd, iov, 3);
        printf("    my_readv 请求 15 字节 -> 返回 %ld\n", (long) n);
        printf("    第一段前 3 字节 = \"%.3s\"，第二段首字节 = 0x%02x（没被碰）\n",
               b, (unsigned char) b[8]);
        close(fd);
    }

    printf("\n== 4. 代价：真 readv/writev 是 1 次系统调用，我们这版是 1 次 malloc + 1 次系统调用 ==\n");
    printf("    内核自己的实现不用中间缓冲——它直接把用户态的各段拼进 page 里，\n");
    printf("    所以段很多时，readv/writev 省的不只是系统调用，还有一次全量内存拷贝。\n");

    unlink(pa);
    unlink(pb);
    return 0;
}
```

### 实测（CE）

```text
== 1. 真 writev 与手写 my_writev 的对照 ==
    真 writev  -> 17 字节
    my_writev  -> 17 字节
    两个文件内容："REC1|abcdefgh|END" / "REC1|abcdefgh|END"
    memcmp -> 完全相同

== 2. my_readv 把整条记录分散读回来 ==
    my_readv -> 17 字节（请求 17）
    三段 = "REC1|" / "abcdefgh" / "|END"

== 3. 短读时 my_readv 不能越界 ==
    文件总长 = 17
    my_readv 请求 15 字节 -> 返回 3
    第一段前 3 字节 = "END"，第二段首字节 = 0x7f（没被碰）

== 4. 代价：真 readv/writev 是 1 次系统调用，我们这版是 1 次 malloc + 1 次系统调用 ==
    内核自己的实现不用中间缓冲——它直接把用户态的各段拼进 page 里，
    所以段很多时，readv/writev 省的不只是系统调用，还有一次全量内存拷贝。
```

**思路**：`malloc` 一块 `sum(iov_len)` 大小的临时缓冲 → 一次 `read`/`write` 搬运 → 再把数据「分发」到各段 / 「收集」到缓冲。

**解读**：

| 观察 | 说明 |
|------|------|
| `my_writev` 与真 `writev` 输出**逐字节相同**（`memcmp -> 完全相同`） | 功能等价：把 N 段不连续内存「收集」成一段连续字节流再写出 |
| `my_readv` 能把三段正确分散读回 | 反向操作：一次读进缓冲，再按 `iov_len` 逐段 `memcpy` 到调用者给的各段 |
| **第 3 段是本题的关键**：请求 15 字节时返回 3，且**第二段首字节仍是 `0x7f`（未被碰）** | 这是 `readv` 语义里最容易被忽略的一条：**短读时不能多写**。若实现成「每次都把 `sum` 字节分发下去」，就会**越界写调用者的缓冲区**。手写版必须按**实际读到的字节数**逐段扣减 |
| 「1 次 malloc + 1 次系统调用」的代价 | 真实现是 **1 次系统调用、0 次额外拷贝**（内核用 `import_iovec` 只拷 `struct iovec` 描述符，共 `UIO_FASTIOV = 8` 个走栈上数组，超出才 kmalloc，然后把各段直接拼进 page）。手写版多了「一次全量内存拷贝 + 一次动态分配」 |

**语义上要对齐的三件事**（原书第 7.1.2 节之所以点名 `malloc`，就是因为这三条）：

| 语义 | 说明 |
|------|------|
| 返回「实际字节数」 | 可能小于请求总量（短读/部分写），**不能**假设等于 `sum(iov_len)` |
| 短读时按段**顺序**填充 | 前面的段先填满；只填了 `k` 字节时，第 `k+1` 字节所在的段**只动前几个字节**，其余保持原样 |
| 总请求量上限 | `IOV_MAX = 1024` 段（`sysconf(_SC_IOV_MAX)` 实测 `1024`，对应 `include/uapi/linux/uio.h:28` 的 `UIO_MAXIOV`）。手写版还要自己防 `sum` 溢出 |

## HFT / 嵌入式关联

| 练习 | 实战兑现 |
|------|---------|
| 5-1 大文件 | 行情 tick 归档、录制回放文件动辄几十 GB。`_FILE_OFFSET_BITS=64` 只解决**类型宽度**；设备上真正卡你的是 `ulimit -f` / `s_maxbytes`——两道门都要过 |
| 5-2 `O_APPEND` 无视 `lseek` | 想「在文件中间改一个字段」就不能用 `O_APPEND` 打开；反过来，用 `O_APPEND` 打开的日志 fd **不可能**被误改成随机写——这是一个安全性质 |
| 5-3 `O_APPEND` 原子性 | 多进程行情日志、多个 worker 写同一个 tape：**必须** `O_APPEND`。实测一次竞争就丢 8236 字节；交易环境里这就是「成交回报丢失」 |
| 5-4 手写 `dup2` | 理解「`close`+`fcntl` **不原子**」是排查 fd 串号 bug 的关键。重定向标准输出（`dup2(fd, 1)`）必须用系统调用，不能手写两步 |
| 5-5 共享偏移/标志 | `fork` 之后父子共享偏移 → 并发读同一文件会互相抢游标。**正确做法是各自 `open`，或改用 `pread`**（[5.6](5.6-pread-pwrite.md)） |
| 5-6 多描述符推演 | 排查「文件内容被莫名覆盖」类故障的思维模型：先画出「哪几个 fd 共享表项」，再逐次 `write` 推偏移。嵌入式日志乱序/丢行多半就是这里出错 |
| 5-7 手写 `readv` | 协议解析里「头部 + 变长载荷」一次读出（[5.7](5.7-readv-writev.md)）。手写版能跑但要记住：**短读时不许越界**——这是把 `readv` 用在网络/串口时最常见的内存破坏来源 |

<summary>代码自测（Q&A）</summary>

**Q1：习题 5-1 里 `_FILE_OFFSET_BITS=64` 到底做了什么？**
A：它让 glibc 的预处理把 `off_t` **透明替换**成 64 位类型——不改源码、不改函数名，只改编译期宏。实测 `sizeof(off_t) = 8`。原书 Listing 5-3 走的是另一条路：显式 `#define _LARGEFILE64_SOURCE` + `open64()/lseek64()/off64_t`。**两者都能表示 4 GiB 偏移**；区别只是「透明替换」还是「显式别名」。

**Q2：习题 5-1 在沙箱里为什么写不出 4 GiB 文件？**
A：因为 `RLIMIT_FSIZE` 被限成 `16777216`（16 MiB）。`lseek` 到 `4294967296` 是**成功**的（说明类型宽度已过关），但 `write` 会先触发 `SIGXFSZ`（默认动作杀进程），装了 handler 后得到 `errno=27 (EFBIG)`。真机上 `ulimit -f unlimited` 即可。**结论：拦你的是资源上限，不是 `off_t` 宽度。**

**Q3：习题 5-2 的答案是什么？为什么？**
A：数据出现在**文件末尾**。`O_APPEND` 是打开文件表项上的**持续标志**，内核在每次 `write()` 内部把偏移强制设成 `i_size`（`fs/read_write.c:1666-1667`：`if (iocb->ki_flags & IOCB_APPEND) iocb->ki_pos = i_size_read(inode);`）——所以用户态的 `lseek(0)` 是**无效的**。实测：`lseek` 后 `f_pos` 确实变成 0，但写完之后 `f_pos = 16`、内容 `"0123456789AAABBB"`。**对照**：不带 `O_APPEND` 时，同样操作从偏移 0 覆盖，得到 `"BBB3456789"`。

**Q4：习题 5-3 里 `x` 那一组为什么丢数据？丢多少是固定的吗？**
A：因为 `lseek(fd, 0, SEEK_END)` 和 `write(fd, "x", 1)` 是**两步**，两个进程各自 `open` 就有**各自**的 `f_pos`，两边都可能读到同一个「旧末尾」，于是写到同一偏移上相互覆盖。**丢多少不固定**——取决于调度交错的密度，本章实测一次是 391764/400000（丢 8236），换一次跑就不同。所以笔记里给「数量级差异」而不是「固定数字」。

**Q5：习题 5-4 的手写 `dup2` 和真 `dup2` 差在哪？**
A：差在**原子性**。手写版是 `close(newfd)` + `fcntl(oldfd, F_DUPFD, newfd)` 两步，中间可被信号或其他线程插入（另一线程可能抢走 `newfd`）；真 `dup2` 在 `fs/file.c:1105` 的 `do_dup2()` 里一次拿住 fd 表锁完成。题干明确说「你可以忽略 `errno` 差异」，但**没**说可以忽略原子性——单线程受控场景下两者行为等价，多线程下必须用 `dup2`。

**Q6：习题 5-4 里 `oldfd == newfd` 为什么不能直接返回？**
A：可以直接返回**结果**，但**不能跳过校验**。题干原文：「you should check whether `oldfd` is valid, which can be done by, for example, checking if `fcntl(oldfd, F_GETFL)` succeeds. If `oldfd` is not valid, then the function should return `-1` with `errno` set to `EBADF`。」实测：`my_dup2(3,3) -> 3`，但 `my_dup2(999,999) -> -1 errno=9 (EBADF)`，与真 `dup2` 一致。内核里的对应位置是 `fs/file.c:1273-1282`。

**Q7：习题 5-5 里除了偏移和标志，「还有什么」是不共享的？**
A：**`FD_CLOEXEC`**（描述符标志）。它在**层 ①**（进程 fd 表项）上，而偏移 `f_pos` 与状态标志 `f_flags` 在**层 ②**（`struct file`）上。所以 `dup` 出来的新 fd：共享偏移和状态标志，但**不继承** `FD_CLOEXEC`。实测：只对 fd2 设 `FD_CLOEXEC`，fd1 的 `F_GETFD` 仍是 `0x0`。这也是 `dup3(..., O_CLOEXEC)` 存在的原因——`dup2` 无法为新 fd 原子地设这个位。

**Q8：习题 5-6 的第 4 步，为什么 `write(fd1, "HELLO,", 6)` 会写到文件开头？**
A：因为第 3 步的 `lseek(fd2, 0, SEEK_SET)` 改的是 **fd1 和 fd2 共享的那个 `f_pos`**。所以「只对 fd2 做的操作」把 fd1 也拖到了 0。很多人只推 fd2 的偏移，忘了 fd1 跟着变——**这是本题的核心陷阱**。

**Q9：习题 5-6 的第 5 步为什么是 `fd3` 覆盖开头？**
A：因为 `fd3` 是**独立 `open`** 出来的，有自己的 `struct file` 和自己的 `f_pos`，而它**从未被写过**——偏移一直是 0。所以它从 0 开始覆盖前 6 字节，得到 `"Gidday world"`。实测第 6 段还从侧面确认了这一点：只对 fd1 设 `O_APPEND`，fd3 的 `F_GETFL` 不受影响。

**Q10：原书解答 `multi_descriptors.c` 在本仓库的 CE 沙箱里为什么一点输出都没有？**
A：它靠 `system("cat a; echo")` 显示文件内容，而沙箱里**没有 `/bin/sh`**（`system()` 返回 `32512`）。程序本身没错，是环境限制。本仓库因此另写了一个用 `printf` + `lseek(fd, 0, SEEK_CUR)` 打印偏移的复刻版 `c5_4_fd_open_files.c`，把「内容 + 三个偏移」全部显式打出来。

**Q11：习题 5-7 手写 `readv` 最容易错在哪？**
A：**短读时的越界写**。真 `readv` 的语义是：只填实际读到的字节，按 `iov` 顺序逐段消耗；读完 `k < sum(iov_len)` 字节后，第 `k+1` 字节所在的段**只改前几个字节，其余保持原样**。手写版如果把「一次 `read` 到缓冲」的结果无条件按 `iov_len` 全量分发，就会写调用者没打算让它写的内存。实测：请求 15 字节时返回 3，第二段首字节仍是 `0x7f`（未被碰）。

**Q12：手写版和真 `readv`/`writev` 的性能差距在哪？**
A：多了**一次 `malloc` + 一次全量内存拷贝**。真实现里 `import_iovec` 只拷贝 `struct iovec` 描述符本身（`UIO_FASTIOV = 8` 个以内走栈上 `iovstack` 数组，更多才 `kmalloc`），然后把用户态的各段**直接拼进 page cache**，不做中间整块缓冲。所以段数越多、单段越大，差距越明显——这也正是 `readv`/`writev` 存在的理由（[5.7](5.7-readv-writev.md)）。
