## 练习题

### 练习 1：dup2 vs close+fcntl

解释 `dup2(fd, 2)` 和 `close(2); fcntl(fd, F_DUPFD, 2)` 的区别，为什么前者更安全？

### 练习 2：pread/pwrite 的线程安全

为什么 `pread`/`pwrite` 比 `lseek`+`read`/`write` 更适合多线程？给出一个具体的竞态场景。

### 练习 3：readv 实现 header+body 读取

实现一个函数，用 `readv` 从文件一次读取固定头部和变长数据体。

**要求**：
- 头部结构包含 `uint32_t magic` 和 `uint32_t body_len`
- 先用 `read` 读 8 字节头部
- 再用 `readv` 将头部和数据体一次读取（优化：预分配大缓冲区）

### 练习 4：非阻塞读取

打开一个 FIFO 的读端，使用 `O_NONBLOCK`。当没有写端打开时，`read` 返回什么？当有写端但无数据时呢？

## 参考答案

### 练习 1 答案

| 特性 | `dup2(fd, 2)` | `close(2); fcntl(fd, F_DUPFD, 2)` |
|------|-------------|----------------------------------|
| 原子性 | 原子 | 非原子（两步操作） |
| 信号安全 | 是 | 否（close 和 fcntl 之间可能被中断） |
| 线程安全 | 是 | 否（另一个线程可能抢占 fd 2） |
| 目标已打开 | 自动关闭再复制 | 需手动 close |

### 练习 2 答案

**竞态场景**：两个线程共享同一 fd 操作同一文件。

```
线程 A: lseek(fd, 100, SEEK_SET)  → 偏移量=100
线程 B: lseek(fd, 500, SEEK_SET)  → 偏移量=500
线程 A: read(fd, buf, 10)         → 从 500 开始读！错误
```

`pread(fd, buf, 10, 100)` 不修改偏移量，多线程调用互不干扰。

### 练习 3 参考代码

```c
struct msg_header {
    uint32_t magic;
    uint32_t body_len;
};

ssize_t read_message(int fd, struct msg_header *hdr, char *body, size_t body_cap) {
    /* 先读头部 */
    ssize_t n = read(fd, hdr, sizeof(*hdr));
    if (n != sizeof(*hdr)) return -1;
    if (hdr->body_len > body_cap) return -1;

    /* 用 readv 一次读取头部+数据体（演示 readv 用法） */
    struct iovec iov[2];
    iov[0].iov_base = hdr;
    iov[0].iov_len = sizeof(*hdr);
    iov[1].iov_base = body;
    iov[1].iov_len = hdr->body_len;

    /* 注意：需要先 lseek 回退头部位置 */
    lseek(fd, -sizeof(*hdr), SEEK_CUR);
    return readv(fd, iov, 2);
}
```

### 练习 4 答案

| 场景 | read 返回值 | errno |
|------|------------|-------|
| 无写端打开 | 0 (EOF) | — |
| 有写端但无数据 | -1 | EAGAIN |
| 有写端且有数据 | 实际字节数 | — |
| 所有写端关闭后 | 0 (EOF) | — |

**关键区别**：`O_NONBLOCK` 下，FIFO 有写端但无数据返回 -1/EAGAIN；无写端返回 0/EOF。阻塞模式下，无数据会阻塞等待，无写端返回 0/EOF。

## HFT / 嵌入式关联

- **readv/writev**：HFT 协议解析中一次读取 header+payload，减少系统调用
- **O_NONBLOCK**：所有 HFT 网络代码的基础
- **pread**：多线程回测引擎并行读取历史数据文件
