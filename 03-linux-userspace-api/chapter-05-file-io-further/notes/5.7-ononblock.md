## 要点

| 对象 | 行为 |
|------|------|
| **普通磁盘文件** | 通常 **无效果**（读盘一般不靠这个变「非阻塞」） |
| 管道 / FIFO / socket / 终端 | 无数据时 `read` 立即 `-1`，`errno=EAGAIN`/`EWOULDBLOCK` |

> `O_NONBLOCK` ≠ 异步 AIO；只是「不睡、立刻返回」的轮询式语义。

---

---

## 与 C 语言学习的关系

本节的 `read()` 是 K&R 第 8 章（8.2 节）的核心系统调用。K&R 用 `read(fd, buf, n)` 演示了低级 I/O。与 C 标准库 `fread()` 不同，`read()` 无缓冲、直接系统调用。理解短读（short read）是 C 系统编程的基本功——K&R 的 copy.c 示例就利用了 `read` 返回实际字节数的特性。

---

## HFT / 嵌入式关联

| 路线 | |
|------|--|
| 嵌入式 | `dup2` 重定向；`O_CLOEXEC` 防 exec 泄漏；设备 fd 的 `fcntl` |
| HFT | `pread`/`pwrite` 并发；少 `lseek` 竞态；非阻塞多用于 socket/管道 |

## 常见陷阱

1. **短读未处理**

```c
/* 假设一次读完 */
ssize_t n = read(fd, buf, 1024);
/* n 可能 < 1024 */
```

read 返回值可能小于请求字节数（short read）。网络和管道尤其常见，必须循环读。

2. **EINTR 未处理**

```c
/* 信号中断后 read 返回 -1, errno=EINTR */
/* 不是错误，应重试 */
```

信号中断系统调用时返回 -1 且 errno=EINTR。应该重试，或用 SA_RESTART 自动重启。

3. **EOF 判断错误**

```c
/* 用 feof 预判 EOF → 多读一次 */
while (!feof(fp)) { fgets(...); }
/* 正确：检查返回值 */
while (fgets(buf, sz, fp) != NULL) { ... }
```

read 返回 0 表示 EOF。不要用 feof 预判（feof 只在读取越过后才为真）。

## 自测题

**题目 1（选择）：** `read()` 返回 0 表示什么？
A. 出错
B. EOF
C. 没有数据
D. 需要重试

<details>
<summary>参考答案</summary>

B。返回 0 表示已到达文件末尾（EOF）。返回 -1 表示出错，返回 >0 表示读到的字节数。

</details>

**题目 2（判断）：** `read` 一定会读满请求的字节数。

<details>
<summary>参考答案</summary>

错误。read 可能返回少于请求的字节数（short read），尤其在管道、socket、终端上。必须循环读。

</details>

**题目 3（踩坑）：** 以下代码有什么问题？
```c
char buf[1024];
read(fd, buf, sizeof(buf));
buf[strlen(buf)] = '\0';
```

<details>
<summary>参考答案</summary>

1) read 不保证以 null 结尾；2) 没检查返回值；3) strlen 在未终止的 buf 上越界。应检查返回值并手动加 `\0`。

</details>

**题目 4（应用）：** 写一个安全的 readall 函数，确保读满 n 字节或遇到 EOF。

<details>
<summary>参考答案</summary>

```c
ssize_t readall(int fd, void *buf, size_t n) {
    size_t total = 0;
    while (total < n) {
        ssize_t r = read(fd, (char*)buf+total, n-total);
        if (r < 0 && errno == EINTR) continue;
        if (r < 0) return -1;
        if (r == 0) break; /* EOF */
        total += r;
    }
    return total;
}
```

</details>
