## 本节讲什么

临时文件无处不在（编译器中间产物、日志轮转、下载缓存），但「怎么安全地建」是个经典陷阱。本节回答三个问题：

1. `mkstemp` / `tmpfile` / `mkdtemp` 各自怎么用、什么场景选哪个？
2. 为什么 `tmpnam` / `mktemp` 是**不安全的**，本质缺陷是什么？
3. 如何让临时文件「关闭时自动删除」？

---

## 1. 安全 API 一览

| 函数 | 原型 | 返回 | 删除时机 |
|------|------|------|---------|
| `mkstemp` | `int mkstemp(char *template)` | fd（已创建，`0600`） | 需手动 `unlink` |
| `tmpfile` | `FILE *tmpfile(void)` | `FILE*` | **关闭时自动删除** |
| `mkdtemp` | `char *mkdtemp(char *template)` | 目录名 | 需手动 `rmdir` |

- **`mkstemp`**：模板末尾必须是 `XXXXXX`（6 个 X），函数原子地创建文件并用唯一随机串替换 X。文件权限 `0600`，返回 fd。
- **`tmpfile`**：创建匿名临时文件（`O_TMPFILE` 或 `mkstemp`+立即 `unlink` 的等价物），返回 `FILE*`，关闭时自动删除。
- **`mkdtemp`**：创建唯一临时**目录**。

## 2. 为什么不安全：`tmpnam` / `mktemp` 的 TOCTOU

```c
char *name = tmpnam(NULL);        /* 返回一个「看似可用」的文件名 */
int fd = open(name, O_CREAT);     /* 竞态！另一进程可能已抢先创建/替换 */
```

`tmpnam` 只返回一个**可预测/未保留**的文件名，`open` 是**独立**的第二步。两步之间另一进程可能：
- 抢先创建同名文件（你 `open` 到别人的文件）；
- 用符号链接把名字指向敏感文件（如 `/etc/passwd`）。

这正是 [5.1](5.1-atomicity-race-conditions.md) 讲的 TOCTOU。`mkstemp` 用 `O_CREAT | O_EXCL` 在**内核一次调用内**「生成随机名 + 独占创建」，消除竞态窗口。

## 3. 让临时文件「关闭时自动删除」

`mkstemp` 创建的文件要手动删。技巧：**创建后立即 `unlink`**，利用「文件被 unlink 后仍可被已打开的 fd 访问，最后一个 fd 关闭时真正删除」的语义：

```c
char template[] = "/tmp/myappXXXXXX";
int fd = mkstemp(template);   /* 创建 + 返回 fd */
unlink(template);             /* 立即 unlink：目录里看不到，但 fd 仍可读写 */
/* ... 用 fd 读写 ... */
close(fd);                    /* 最后一个引用关闭 → 文件被真正回收 */
```

这等价于 `tmpfile()` 的行为（匿名临时文件），但用 fd 而非 `FILE*`。

## 4. HFT / 嵌入式关联

| 场景 | 本节机制的兑现 |
|------|----------------|
| 原子写配置文件 | 先写临时文件，再 `rename` 覆盖，避免进程崩溃留下半写文件 |
| 多进程唯一临时名 | `mkstemp` 的 `O_EXCL` 保证并发下每个进程拿到不同文件 |
| 敏感数据落盘 | `mkstemp` 的 `0600` 权限 + 立即 `unlink`，避免临时文件被其他进程读取 |
| 嵌入式 tmpfs | 临时文件放 `tmpfs`（内存），重启自动消失，无需清理 |

## 5. 代码示例

```c
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
#include <fcntl.h>
#include <string.h>

/* mkstemp: 安全创建临时文件 + 立即 unlink 实现自动删除 */
int main(void) {
    char template[] = "/tmp/myappXXXXXX";
    int fd = mkstemp(template);
    if (fd == -1) { perror("mkstemp"); return 1; }
    printf("创建临时文件: %s\n", template);

    unlink(template);          /* 立即删除目录项，关闭 fd 时自动回收 */

    write(fd, "temp data", 9); /* fd 仍可正常读写 */
    close(fd);                 /* 关闭 → 文件真正被删除 */
    return 0;
}
```

<details>
<summary>代码自测（Q&A）</summary>

**Q1：`mkstemp` 的 template 格式是什么？**
A：以 `XXXXXX`（恰好 6 个大写 X）**结尾**的字符串，如 `"/tmp/myappXXXXXX"`。`mkstemp` 会用唯一随机串替换这 6 个 X，并原地写回 template。注意 template 必须是**可写的字符数组**（`char template[] = ...`），不能是字符串字面量（`char *` 指向只读段会崩）。

**Q2：为什么不能用 `tmpnam`？**
A：`tmpnam` 只返回一个**未保留**的文件名，真正创建靠后续独立的 `open`，两步之间存在 TOCTOU 竞态——另一进程可能抢先创建同名文件或符号链接攻击。`mkstemp` 用 `O_CREAT|O_EXCL` 在单次调用内原子完成「生成名 + 独占创建」，无竞态窗口。

**Q3：如何创建「关闭时自动删除」的临时文件？**
A：两种：① `tmpfile()`（返回 `FILE*`，关闭自动删除）；② `mkstemp()` 后**立即 `unlink`**——文件目录项被移除，但已打开的 fd 仍可读写，最后一个 fd 关闭时内核真正回收该文件。

**Q4：`mkstemp` 创建的临时文件权限是多少？**
A：`0600`（仅 owner 可读写）。这是安全设计——临时文件常含敏感数据，默认不开放给同组/其他用户。

**Q5：`mkstemp` 和 `tmpfile` 怎么选？**
A：需要**路径名**（如后续要 `rename` 成正式文件）用 `mkstemp`；只需要一个**匿名**临时文件、用 `FILE*` 流操作、关闭即删，用 `tmpfile`（等价于 `mkstemp`+立即 `unlink`，但封装成 stdio 流）。

</details>
