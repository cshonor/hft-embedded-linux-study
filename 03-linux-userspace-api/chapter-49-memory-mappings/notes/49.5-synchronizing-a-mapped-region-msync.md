# 49.5 同步映射区：msync()

> 源码核验：Linux v6.6 · `mm/msync.c`（`SYSCALL_DEFINE3(msync):32` · `vfs_fsync_range()` 调用 `:96`）· `mm/page-writeback.c`（脏页回写）
> 本章：[TLPI 第 49 章 — Memory Mappings](../README.md)
> - 上一节：[49.4 文件映射](49.4-file-mappings.md)
> - 下一节：[49.6 mmap flags 补充细节](49.6-additional-mmap-flags.md)

## 本节讲什么

`msync` 把 `MAP_SHARED` 映射的脏页刷回磁盘。三个灵魂问题：

1. 三种模式差在哪？（`MS_SYNC` 阻塞落盘；`MS_ASYNC` 现代 Linux 里是 **no-op**；`MS_INVALIDATE` 丢干净页缓存）
2. 什么时候真的需要它？（担心**崩溃丢失**时——别的进程的**可见性**从来不靠 msync，page cache 本来就是全局的）
3. 它和 mlock 什么关系？（`MS_INVALIDATE` 作用在锁定区 → `EBUSY`，实测验证）

```c
#include <sys/mman.h>
int msync(void *addr, size_t length, int flags);
/* flags: MS_SYNC | MS_ASYNC | MS_INVALIDATE（前两者互斥） */
```

---

## 要点

### 三种模式（含现代内核的真实行为）

| flags | POSIX 语义 | Linux v6.6 真实行为（msync.c:32 逐行核验） |
|-------|-----------|---------------------------------------------|
| `MS_SYNC` | 阻塞直到脏页写到磁盘 | 逐 VMA 调 `vfs_fsync_range(file, fstart, fend, 1)`（:96）——真同步 |
| `MS_ASYNC` | 调度后台回写，立即返回 | **no-op**！内核 2.6.19 起自带脏页追踪，page cache 的脏页由回写线程自动管理，无需「提醒」 |
| `MS_INVALIDATE` | 丢弃 page cache 中的干净页 | 对 `VM_LOCKED`（mlock）区直接 `EBUSY`（:81-84） |

⭐ **MS_ASYNC 的历史**：TLPI 写作年代（2010）`MS_ASYNC` 确实有「启动回写」语义；现代 man page 明确注明 *"Since Linux 2.6.19, MS_ASYNC is in fact a no-op"*。老代码里的 `msync(p, len, MS_ASYNC)` 现在只是心理安慰。

### msync 真正解决什么

| 需求 | 靠什么 |
|------|--------|
| **别的进程立刻读到我的修改** | 什么都不用做——SHARED 写的就是 page cache，天然全局可见 |
| **崩溃后数据还在磁盘** | `msync(MS_SYNC)`——唯一保证 |
| **内存占用太大想丢干净页** | `msync(MS_INVALIDATE)`（罕见） |

### 内核路径（v6.6 实测核验）

```
msync(2) → SYSCALL_DEFINE3(msync)            mm/msync.c:32
 ├─ flags 校验（:39-46）：
 │    未知标志 → EINVAL；MS_SYNC+MS_ASYNC 同传 → EINVAL；addr 未页对齐 → EINVAL
 ├─ 遍历 [start,end) 的每个 VMA：
 │    ├─ 空洞区间：跳过，但记 unmapped_error（最终返回 ENOMEM）
 │    ├─ MS_INVALIDATE && VM_LOCKED → EBUSY（:81-84，实测验证）
 │    └─ MS_SYNC && file && VM_SHARED：
 │         vfs_fsync_range(file, fstart, fend, 1)   :96
 │         （同步等磁盘——所以 MS_SYNC 的延迟≈磁盘 fsync）
 └─ MAP_PRIVATE 映射：循环体里 file 分支不满足 → 直接滑过（无操作）
```

要点：**PRIVATE 映射调 msync 无任何效果**（不报错，白调）——msync 只对 `VM_SHARED + vm_file` 的 VMA 有意义。

### 错误码速查

| errno | 条件 | 实测 |
|-------|------|------|
| `EINVAL` | flags 非法 / SYNC+ASYNC 同传 / addr 未对齐 | ✓（22） |
| `ENOMEM` | 区间含未映射空洞（结束后统一返回） | — |
| `EBUSY` | `MS_INVALIDATE` 遇 mlock 区 | ✓（16） |

---

## HFT / 嵌入式关联

| 路线 | 要点 |
|------|------|
| 嵌入式 | 掉电保护：关键配置/日志写 SHARED 映射后 `MS_SYNC` 强制落 flash（eMMC/NAND 的 fsync 含 FTL 层刷写，毫秒级，别放热路径）；`MS_INVALIDATE` 做外设缓存一致性冲洗（罕见但嵌入式 debug 用过） |
| HFT | 热路径**永不碰 MS_SYNC**（一次 = 一次真 fsync，毫秒级）；审计日志缓冲用单独线程攒批刷；**可见性需求是伪需求**（page cache 天然共享），只有崩溃持久性才需要 msync——分清两者能省掉一半无谓调用 |

## 代码示例

```c

/* msync 语义实测：EINVAL / EBUSY 两个错误码（完整可跑版）
 * 实测（WSL Ubuntu，gcc -O2 -Wall -Wextra，2026-09-05）：
 *   步骤4 msync(MS_SYNC|MS_ASYNC) = -1 errno=22(Invalid argument)
 *   步骤5 mlock 区上 msync(MS_INVALIDATE) = -1 errno=16(Device or resource busy)
 */
#define _GNU_SOURCE
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <fcntl.h>
#include <errno.h>
#include <sys/mman.h>
#include <unistd.h>

int main(void)
{
    long pagesz = sysconf(_SC_PAGESIZE);
    size_t P = (size_t)pagesz;

    int fd = open("/tmp/ch49_sync.dat", O_RDWR | O_CREAT | O_TRUNC, 0644);
    if (fd < 0) { perror("open"); return 1; }
    if (ftruncate(fd, (off_t)P) != 0) { perror("ftruncate"); return 1; }

    char *shar = mmap(NULL, P, PROT_READ | PROT_WRITE, MAP_SHARED, fd, 0);
    if (shar == MAP_FAILED) { perror("mmap"); return 1; }
    strcpy(shar, "dirty data");

    /* 1. MS_SYNC：真同步落盘（阻塞到磁盘完成） */
    if (msync(shar, P, MS_SYNC) != 0) perror("msync MS_SYNC");
    printf("MS_SYNC 完成：脏页已落盘\n");

    /* 2. 互斥标志 → EINVAL */
    errno = 0;
    int r = msync(shar, P, MS_SYNC | MS_ASYNC);
    printf("msync(MS_SYNC|MS_ASYNC) = %d errno=%d(%s)，预期 EINVAL\n",
           r, errno, r ? strerror(errno) : "OK");

    /* 3. mlock 区 + MS_INVALIDATE → EBUSY */
    char *lk = mmap(NULL, P, PROT_READ | PROT_WRITE,
                    MAP_SHARED | MAP_ANONYMOUS, -1, 0);
    if (lk == MAP_FAILED) { perror("mmap lk"); return 1; }
    lk[0] = 1;
    if (mlock(lk, P) != 0) { perror("mlock"); return 1; }
    errno = 0;
    r = msync(lk, P, MS_INVALIDATE);
    printf("mlock 区上 msync(MS_INVALIDATE) = %d errno=%d(%s)，预期 EBUSY\n",
           r, errno, r ? strerror(errno) : "OK");

    munlock(lk, P);
    munmap(lk, P);
    munmap(shar, P);
    close(fd);
    unlink("/tmp/ch49_sync.dat");
    return 0;
}
```

## 自测题

**题目 1（选择）：** 进程 A `MAP_SHARED` 映射写入后**没有调用任何 msync**，进程 B 映射同一文件读，能看到修改吗？

A. 不能，必须先 msync　B. 能，立即看到　C. 能，但延迟不定　D. 只有 MS_ASYNC 后能看到

<details>
<summary>参考答案</summary>

**B**。SHARED 映射的写直接落在 page cache 页（`wp_page_shared():3276` 原地改页），page cache 是全局唯一的——B 的读缺页拿到同一物理页。msync 只解决「磁盘持久性」，与可见性无关。这个误解在面试和 code review 中出现频率极高。

</details>

**题目 2（判断）：** `msync(p, len, MS_ASYNC)` 在现代 Linux 上会启动后台回写。

<details>
<summary>参考答案</summary>

错误。自 2.6.19 起 `MS_ASYNC` 是 **no-op**——内核的脏页追踪 + 平衡回写线程已全自动，MS_ASYNC 的「提醒」职责被彻底取代。man 2 msync 的 NOTES 明确写了这一点。需要确定性落盘只有 `MS_SYNC`。

</details>

**题目 3（应用）：** 交易程序把成交记录写进 `MAP_SHARED` 映射的日志文件，要求「进程崩溃不丢、机器断电最多丢 1 秒」，怎么设计刷盘节奏？

<details>
<summary>参考答案</summary>

独立刷盘线程每 ≤1s 调一次 `msync(区间, MS_SYNC)`（对增量区间，避免整段重扫）；写线程永不阻塞在 fsync。注意三点：① MS_SYNC 的延迟 ≈ 磁盘 fsync（HDD 毫秒级/NVMe 几十 µs~百 µs），必须在旁路线程；② 关键字段用定长记录 + 序号，崩溃恢复时容忍半条记录；③ 别忘了 fsync 日志文件**本身的新增块**（ftruncate/pwrite 的元数据也走 fsync 路径，`vfs_fsync_range` 已覆盖）。

</details>
