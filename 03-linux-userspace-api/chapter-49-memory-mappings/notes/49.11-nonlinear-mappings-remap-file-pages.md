# 49.11 非线性映射：remap_file_pages()

> 源码核验：Linux v6.6 · `mm/mmap.c`（emulation 层 `SYSCALL_DEFINE5(remap_file_pages):2952` · `pr_warn_once`:2962 注释 *"Emulation of deprecated remap_file_pages() syscall"*）

> - 上一节：[49.10 MAP_FIXED](49.10-the-map-fixed-flag.md)
> - 下一节：[49.12 总结](49.12-summary.md)

## 本节讲什么

`remap_file_pages()` 允许「一个 VMA 的不同虚页指向文件的不同页」——打破线性对应。三个灵魂问题：

1. 为什么需要非线性？（数据库/索引引擎想让「虚拟连续的 B 树区」对应「文件里散乱的页」）
2. 它现在是什么状态？（**v6.6 只剩 emulation**：内核收到调用就打 dmesg 警告，然后用 munmap+mmap+MAP_FIXED 重建——原始实现 3.16 就删了）
3. 现在怎么实现同样需求？（多个小 VMA 拼接，或干脆别用 mmap）

---

## 要点

### 概念：线性 vs 非线性

```
普通（线性）映射:  虚页 0 → 文件页 0
                  虚页 1 → 文件页 1
                  虚页 2 → 文件页 2

非线性映射:        虚页 0 → 文件页 4096
                  虚页 1 → 文件页 0
                  虚页 2 → 文件页 8192
```

### 历史与现状

| 时点 | 状态 |
|------|------|
| 2.6 内核早期 | 原生实现：VMA 带 `VM_NONLINEAR` 标志，页表随意指——**复杂度炸弹**（与反碎片、KSM、THP 全都打架） |
| Linux 3.16（2014） | 原生实现删除 |
| v6.6（本文核验） | **纯 emulation**：`mm/mmap.c:2952` 的 `SYSCALL_DEFINE5` 收到调用后：① `pr_warn_once()` 在 dmesg 记录 *"uses deprecated remap_file_pages() syscall"*（:2962）② 内部等价于 **munmap 目标区间 + mmap(...MAP_FIXED) 重建** |

```
SYSCALL_DEFINE5(remap_file_pages, ...)          mm/mmap.c:2952
 ├─ pr_warn_once("... deprecated ...")          :2962  ← dmesg 可见指纹
 └─ has_pending_nonlinear_op → munmap + 重建（本质是普通 mmap 的包装）
```

**现代调用 remap_file_pages = 慢速绕路的 mmap**，没有任何性能优势，只留兼容。

### 为什么被删（架构教训）

非线性 VMA 打破了「一个 VMA ↔ 一段连续文件区间」的核心不变量：
- 反向映射（rmap）复杂化：同一 VMA 的页指向文件各处，优先级搜索树退化
- 与 THP/KSM/compaction 的交互全是特判
- 收益人口极窄（数据库大多早有自己的 buffer pool，不走 mmap）

**这是「通用机制里塞特例」最终被偿还的经典案例**——内核设计里不变量的价值高于单点性能。

### 替代方案

```c
/* 需求：把文件第 2 页映射到虚址 p，第 0 页到 p+4096（自定义排列） */
mmap(p,      4096, PROT_READ|PROT_WRITE, MAP_SHARED|MAP_FIXED, fd, 8192);
mmap(p+4096, 4096, PROT_READ|PROT_WRITE, MAP_SHARED|MAP_FIXED, fd, 0);
```

代价：每段一个 VMA（map_count 消耗，上限 `vm.max_map_count` 默认 65530）；TLB/缺页行为不变（反正都是按页缺的）。更现代的选择：**别映射**——数据库用 pread/pwrite + 自管 buffer pool（PostgreSQL 的决策路径正是如此）。

## 代码示例

```c

/* 非线性映射的现代实现：多 mmap + MAP_FIXED 拼接
 * 实测（WSL Ubuntu，gcc -O2 -Wall -Wextra，2026-09-05）：
 *   page 0 (file page 2): PAGE2    ← 虚页 0 指向文件第 2 页
 *   page 1 (file page 1): PAGE1    ← 虚页 1 保持原位
 */
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <fcntl.h>
#include <unistd.h>
#include <sys/mman.h>

int main(void)
{
    long pagesz = sysconf(_SC_PAGESIZE);
    size_t P = (size_t)pagesz;

    int fd = open("/tmp/ch49_nonlin.dat", O_RDWR | O_CREAT | O_TRUNC, 0644);
    if (fd < 0) { perror("open"); return 1; }
    if (ftruncate(fd, (off_t)(3 * P)) != 0) { perror("ftruncate"); return 1; }

    /* 写 3 页标记：PAGE0/PAGE1/PAGE2 */
    char tmp[16];
    for (int i = 0; i < 3; i++) {
        snprintf(tmp, sizeof tmp, "PAGE%d", i);
        if (pwrite(fd, tmp, strlen(tmp), (off_t)(i * P)) < 0) { perror("pwrite"); return 1; }
    }

    char *p = mmap(NULL, 3 * P, PROT_READ | PROT_WRITE, MAP_SHARED, fd, 0);
    if (p == MAP_FAILED) { perror("mmap"); return 1; }

    /* 非线性重排：虚页 0 改指文件页 2（remap_file_pages 的现代等价物） */
    void *r = mmap(p, P, PROT_READ | PROT_WRITE,
                   MAP_SHARED | MAP_FIXED, fd, (off_t)(2 * P));
    if (r == MAP_FAILED) { perror("mmap FIXED"); return 1; }

    printf("page 0 (file page 2): %.6s\n", p);          /* PAGE2 */
    printf("page 1 (file page 1): %.6s\n", p + P);      /* PAGE1 */
    printf("page 2 (file page 2): %.6s\n", p + 2 * P);  /* PAGE2（同页双视图！） */

    munmap(p, 3 * P);
    close(fd);
    unlink("/tmp/ch49_nonlin.dat");
    return 0;
}
```

注意第三个输出：虚页 0 与虚页 2 现在指向**同一个文件页**——多 mmap 天然支持「一页多视图」，这本来就是非线性映射的能力子集。

## 自测题

**题目 1（选择）：** v6.6 内核收到 `remap_file_pages()` 调用会？

A. 原生快速处理　B. dmesg 警告 + 内部走 mmap 重建　C. 直接返回 ENOSYS　D. SIGSYS 杀进程

<details>
<summary>参考答案</summary>

**B**。`mm/mmap.c:2952` 的 emulation 层：`pr_warn_once()`（:2962）记录弃用警告，然后等价于 munmap+mmap(MAP_FIXED) 重建——功能兼容但性能无优势，只保老程序不崩。

</details>

**题目 2（判断）：** 「一页多视图」（两个虚址指同一文件页）在纯线性 mmap 模型下无法实现。

<details>
<summary>参考答案</summary>

错误。**两个独立的 mmap 就行**（示例代码第三个输出）：同文件同 offset 映射两次，page cache 页天然共享——线性模型完全支持多对一。非线性映射的独有能力是「**一个 VMA 内部**的乱序对应」，而不是多视图本身。多数实际需求（多视图/稀疏页）线性 mmap 都覆盖。

</details>

**题目 3（论述）：** 从 remap_file_pages 的生死看内核设计原则。

<details>
<summary>参考答案</summary>

三点：① **不变量优先**——「VMA ↔ 连续文件区间」不变量支撑了 rmap/THP/KSM 等一整套机制，非线性特例让所有下游都要特判；② **特例的维护成本随时间复利**——3.16 删除时其性能收益早已被普通 mmap 的优化追平；③ **兼容层保迁移**——删除原生实现但保留 syscall emulation + dmesg 指纹，给用户态十年缓冲。同样的思维适用于任何长生命周期系统：给特例找通用表达式，而不是在核心路径开口子。

</details>
