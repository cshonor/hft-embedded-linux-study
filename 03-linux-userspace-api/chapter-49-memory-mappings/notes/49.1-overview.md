## 本节讲什么

**`mmap` 的本质：只在进程虚拟地址空间「画一块区域」，建立映射关系，不立刻把数据搬进内存。**
访问这块虚拟地址才会触发缺页中断，由内核把磁盘/设备数据填进物理页。所以第一件事是分清三样东西：

| 概念 | 是什么 | 谁触发 |
|------|--------|--------|
| `mmap` | 用户态「画一块虚拟区间」，建立 虚址 ↔ 文件/设备/匿名页 的映射 | 进程主动调用 |
| 缺页中断（page fault） | CPU 内存管理机制：访问未映射/未加载地址时陷入内核填页 | CPU 硬件，**不等于 mmap** |
| 共享 / 私有 | `mmap` 的 `flags` 控制多进程是否共用同一物理页 | `MAP_SHARED` / `MAP_PRIVATE` |

> **一句话**：`mmap` 给进程虚拟地址画一块区域，可以映射到**同一份物理内存**实现多进程共享；但**设备能不能让你映射，由设备驱动说了算**——独占访问靠驱动锁，不是 `mmap` 自带能力。

生命周期：`fork` 继承映射；**`exec` / 退出** 销毁全部映射。

## 要点

### `mmap` 的三类映射对象

| 对象 | `fd` / `offset` | 缺页时内核从哪填 | 典型场景 |
|------|-----------------|------------------|----------|
| **磁盘文件** | `fd` + 页对齐 `offset` | 页缓存（page cache） | 文件共享、加载 text 段 |
| **设备 DMA 缓冲区** | 设备 `fd` | 驱动提供的内存页（`remap_pfn_range` / `dma_mmap_*`） | 网卡/采集卡零拷贝、帧缓冲 |
| **匿名内存** | `MAP_ANONYMOUS`、`fd=-1` | 零页 + 首写 COW 分配 | malloc 一类、父子共享 |

### 四大组合

| | `MAP_PRIVATE` | `MAP_SHARED` |
|--|---------------|--------------|
| **文件** | COW；改不回文件；加载 text/只读文件 | 改可见且可回盘；无关进程 IPC |
| **匿名** | 私有堆式分配（malloc 一类） | **仅亲缘**（fork 继承）IPC |

### 共享型设备 vs 独占型设备

| 设备类型 | 例子 | `mmap` 的用法 |
|----------|------|---------------|
| **共享型** | 共享文件、共享设备缓冲区 | 多进程 `MAP_SHARED` 映射**同一份物理内存**，一个改、其他进程都看得见 |
| **独占型** | 麦克风、独占采集卡 | ❌ 不是给每个进程各做一份 mmap；✅ **设备驱动里做独占锁**，同一时刻只允许一个进程 `mmap` 成功，别的进程调用 `mmap` 失败/阻塞 |

> **关键**：互斥逻辑写在**设备驱动**里，`mmap` 只是驱动对外暴露缓冲区的手段，本身不提供任何互斥。

生命周期：`fork` 继承映射；**`exec` / 退出** 销毁全部映射。

## HFT / 嵌入式关联

| 路线 | 要点 |
|------|------|
| 嵌入式 | **设备 DMA 缓冲区 mmap**：`/dev/mem`、帧缓冲（framebuffer）、网卡/采集卡寄存器——用户态直接读写设备内存，省掉 read/write 的 syscall + 一次拷贝 |
| HFT | **低延迟零拷贝**：把网卡（DPDK 大页 + mmap）的 DMA 环形缓冲区映射进用户态，报文「网卡 DMA 直写用户态页」，不经过内核协议栈拷贝；共享型设备多进程 `MAP_SHARED` 看同一份行情 |

> 独占设备在 HFT 里同样成立：**锁在驱动**。例：一个采集卡同一时刻只让一个进程 mmap，驱动用 `mutex`/原子变量守卫 `fops->mmap`，抢不到就返回 `-EBUSY`。

## 代码示例

```c

/* 四大映射组合演示：MAP_PRIVATE vs MAP_SHARED × 文件 vs 匿名 */
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <fcntl.h>
#include <sys/mman.h>
#include <sys/wait.h>
#include <unistd.h>

int main(void) {
    /* 1) MAP_PRIVATE 文件映射 — COW，修改不回盘 */
    int fd = open("/tmp/ch49_demo.txt", O_RDWR | O_CREAT | O_TRUNC, 0644);
    write(fd, "original", 8);
    char *priv = mmap(NULL, 8, PROT_READ | PROT_WRITE, MAP_PRIVATE, fd, 0);
    priv[0] = 'X';  /* 写入触发 COW，不影响文件 */
    printf("MAP_PRIVATE after write: %.8s\n", priv);

    /* 2) MAP_SHARED 文件映射 — 修改可回盘 */
    char *shared = mmap(NULL, 8, PROT_READ | PROT_WRITE, MAP_SHARED, fd, 0);
    shared[0] = 'S';  /* msync 后写回文件 */
    msync(shared, 8, MS_SYNC);

    /* 3) MAP_SHARED|MAP_ANONYMOUS — 父子 IPC */
    char *anon = mmap(NULL, 64, PROT_READ | PROT_WRITE,
                      MAP_SHARED | MAP_ANONYMOUS, -1, 0);
    strcpy(anon, "fork-ipc");
    pid_t pid = fork();
    if (pid == 0) { printf("child: %s\n", anon); _exit(0); }
    wait(NULL);

    /* 4) MAP_PRIVATE|MAP_ANONYMOUS — 私有堆式分配 */
    char *heap_like = mmap(NULL, 64, PROT_READ | PROT_WRITE,
                           MAP_PRIVATE | MAP_ANONYMOUS, -1, 0);
    strcpy(heap_like, "private anon");

    munmap(priv, 8); munmap(shared, 8); munmap(anon, 64); munmap(heap_like, 64);
    close(fd);
    return 0;
}

```

## 设备独占：锁在驱动（伪代码）

```c
/* 驱动侧：独占设备同一时刻只允许一个进程 mmap */
static int mic_mmap(struct file *filp, struct vm_area_struct *vma)
{
    /* 原子变量实现「拿得到才映射」的独占锁 */
    if (!atomic_add_unless(&mic_open, 1, 1))
        return -EBUSY;             /* 已被别的进程独占 → mmap 失败 */

    /* 把设备 DMA 缓冲区物理页映射进用户态虚拟地址 */
    return remap_pfn_range(vma, vma->vm_start,
                           mic_dma_paddr >> PAGE_SHIFT,
                           vma->vm_end - vma->vm_start,
                           vma->vm_page_prot);
}

static int mic_release(struct inode *i, struct file *filp)
{
    atomic_set(&mic_open, 0);      /* 释放独占 */
    return 0;
}
```

> 注意：**互斥逻辑完全在驱动**（`atomic_add_unless` + `-EBUSY`），`mmap` 系统调用本身不提供「独占」能力——它只是把驱动暴露的缓冲区挂到进程虚拟地址上。
