# 49.2 创建映射：mmap()

## 本节讲什么

`mmap` 在进程虚拟地址空间**画一块区域**（建立一个 VMA），建立「虚址区间 ↔ 文件/匿名后备」的映射关系。三个灵魂问题：

1. 画区时发生了什么？（选地址 → 建 VMA → 挂树——**一颗物理页都不分配**）
2. 六个参数各自的坑？（offset 必须页对齐；prot 不能超 fd 模式；flags 必须含 SHARED/PRIVATE 之一）
3. 失败返回什么？（`MAP_FAILED` = `(void*)-1`，**不是 NULL**——与 malloc 的最大差异）

```c
#include <sys/mman.h>
void *mmap(void *addr, size_t length, int prot, int flags,
           int fd, off_t offset);
/* 成功返回映射起始地址（内核选）；失败返回 MAP_FAILED 并设 errno */
```

---

## 要点

### 参数六元组精讲

| 参数 | 规则 | 坑 |
|------|------|-----|
| `addr` | `NULL` 推荐（内核自选）；非 NULL 非固定时只是**提示**，内核可挪走 | 期望返回 `addr` 而没用 `MAP_FIXED` → 地址几乎必然不同 |
| `length` | **向上取整到页边界**（映射尾页部分可用） | 写越 `length`（但同页内）不报错——最后一页是整页 |
| `prot` | `PROT_NONE/READ/WRITE/EXEC` 组合 | 不得超过 fd 的 open 模式（`O_RDONLY` + `PROT_WRITE` → `EACCES`） |
| `flags` | 必须含 `MAP_SHARED` 或 `MAP_PRIVATE` **之一**（两者语义互斥） | 缺了或都给 → `EINVAL` |
| `fd` | 文件映射必填；`MAP_ANONYMOUS` 时被忽略（惯例传 -1） | 匿名时内核根本不碰 fd（传啥都行，但 -1 是可读性惯例） |
| `offset` | **必须页对齐**（`EINVAL`） | 想映射「文件第 100 字节起」？先算 `offset=100&~(pagesize-1)`，指针再偏移 100 |

### 返回值：MAP_FAILED 不是 NULL

```c
void *p = mmap(NULL, len, PROT_READ|PROT_WRITE, MAP_PRIVATE|MAP_ANONYMOUS, -1, 0);
if (p == NULL)   ...   /* 错：mmap 不返回 NULL */
if (p == MAP_FAILED) { perror("mmap"); exit(1); }   /* 对 */
```

`MAP_FAILED` 定义为 `((void *) -1)`。内核选地址永远避开 0 和 -1 附近的页，NULL 恒不可能。

### addr 非 NULL 时的三种命运

| flags | 内核行为 |
|-------|----------|
| 无 `MAP_FIXED` | addr 是 hint：以 addr 为起点**向上**找空洞（`arch_get_unmapped_area():1726`，bottom-up）；拿不到就别处返回 |
| `MAP_FIXED` | 精确落在 addr，**静默覆盖**已有映射（见 [49.10](49.10-the-map-fixed-flag.md)） |
| `MAP_FIXED_NOREPLACE` | 精确落 addr；被占 → `EEXIST`（不覆盖，4.17+） |

### 内核路径：从 syscall 到 VMA 挂树（v6.6 坐标）

```
mmap(2)
 └─ ksys_mmap_pgoff():1382
     ├─ fd 合法性：fdget()，失败 EBADF
     └─ vm_mmap_pgoff → do_mmap():1203
         ├─ length==0 → EINVAL；溢出检查
         ├─ flags 校验（_MAP_VALIDATE；SHARED/PRIVATE 二选一）
         ├─ 计算 vm_flags：prot + flags 翻译成内核位图
         │    （VM_SHARED/VM_MAYWRITE/VM_GROWSDOWN…，mmap_min_addr 检查）
         ├─ 文件：security_mmap_file(LSM)、mapping 预检查
         └─ get_unmapped_area():1801
             └─ arch_get_unmapped_area():1726（bottom-up）/ topdown 变体
                 从 hint/上次 mmap 地址附近找第一个够大的空洞
         mmap_region():2662【画区】
         ├─（MAP_FIXED）先 do_vmi_munmap():2693 拆旧映射
         ├─ accountable_mapping：私有可写 → 记账 swap 预留（VM_ACCOUNT，
         │    可被 MAP_NORESERVE 关闭，见 49.9）
         ├─ vma_merge():863 尝试：与 prev/next VMA 属性相同且紧贴 → 合并进现有 VMA
         ├─（合并失败）vm_area_alloc：从 slab 分配 vm_area_struct
         ├─ vma_link():395
         │    ├─ maple tree 插入（v6.6 起 VMA 用 maple tree 组织，旧版红黑树）
         │    └─ 文件映射：挂进 mapping->i_mmap（反向映射）
         └─ MAP_POPULATE → 立即 populate（预缺页）
```

### vm_area_struct（`include/linux/mm_types.h:565`）——一个 VMA 的身份证

| 字段 | 含义 |
|------|------|
| `vm_start` / `vm_end` | 虚拟区间 `[start, end)`，页对齐 |
| `vm_page_prot` | 缺页时建立 PTE 用的保护位（prot 翻译而来） |
| `vm_flags` | `VM_SHARED`/`VM_MAYREAD`/`VM_LOCKED`/`VM_ACCOUNT`…（内核内部位图，与 mmap flags 不同） |
| `vm_file` / `vm_pgoff` | 后备文件（持引用计数）与文件内页偏移 |
| `vm_ops` | 文件映射的缺页回调（`fault`→filemap_fault 等） |
| `anon_vma` | 匿名页的反向映射锚点（COW/父子链） |

一个 VMA 管一段**属性完全相同**的连续虚址——这就是为什么 `munmap` 中间一页会把 VMA 分裂成两个（见 [49.3](49.3-unmapping-a-mapped-region-munmap.md) 实测）。

### fd 的生命周期独立于映射

`mmap` 后 `close(fd)` 映射依然有效——`vm_area_struct.vm_file` 持有 `struct file` 的引用计数，close 只减你自己那份。实测验证（[49.3 实验](49.3-unmapping-a-mapped-region-munmap.md)）。

### 错误码速查

| errno | 条件 |
|-------|------|
| `EINVAL` | length=0 / offset 未页对齐 / flags 非法（无 SHARED/PRIVATE） |
| `EBADF` | 文件映射但 fd 不合法 |
| `EACCES` | prot 超 fd 打开模式 / fd 是目录 |
| `ENOMEM` | 地址空间耗尽（map_count 上限 `sysctl vm.max_map_count` 默认 65530）/ 无空洞 |
| `ETXTBSY` | `MAP_DENYWRITE` 冲突（exec 中文件） |

## HFT / 嵌入式关联

| 路线 | 要点 |
|------|------|
| 嵌入式 | 匿名映射替代 malloc 做页对齐缓冲（DMA 描述符环、帧缓冲）；`/dev/mem` + `MAP_FIXED` 把寄存器映射到固定虚址（无 MMU 的 NOMMU 体系 mmap 语义完全不同，见 uClinux 文档） |
| HFT | 行情/订单缓冲用 `mmap(MAP_SHARED|MAP_ANONYMOUS)` 跨进程零拷贝；**页对齐 + 固定 length** 利于 THP 对齐（`MADV_HUGEPAGE` 需 2MB 对齐才生效）；`MAP_POPULATE` 启动预填消除首触缺页（微秒级毛刺 × 缓冲页数 = 可观） |

## 代码示例

```c

/* mmap 生命周期实测：画区≠填页（maps/smaps 双口径）
 * 实测（WSL Ubuntu，gcc -O2 -Wall -Wextra，2026-09-05）：
 *   步骤1 mmap p=0x7ef676812000（未触碰，两侧 guard 为 PROT_NONE）
 *     [未触碰] VMA条数=1  Rss=0 kB          ← 画区完成，零物理页
 *   步骤2 读触碰第 0 页（do_anonymous_page 走零页分支）
 *     [读触碰] VMA条数=1  Rss=0 kB          ← 零页 present 但不计 RSS
 *   步骤3 写触碰第 0 页（分配私有物理页）
 *     [写触碰] VMA条数=1  Rss=4 kB          ← COW 真页才进 RSS
 *   步骤5 close(fd) 后读文件映射："FDLIFE"  ← fd 关了映射还活着
 */
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <fcntl.h>
#include <errno.h>
#include <sys/mman.h>
#include <unistd.h>

static long smaps_rss(void *addr)
{
    FILE *fp = fopen("/proc/self/smaps", "r");
    if (!fp) return -1;
    char line[300];
    unsigned long lo, hi, a = (unsigned long)addr;
    long rss = -1;
    int in_target = 0;
    while (fgets(line, sizeof line, fp)) {
        if (sscanf(line, "%lx-%lx", &lo, &hi) == 2)
            in_target = (a >= lo && a < hi);
        else if (in_target && strncmp(line, "Rss:", 4) == 0) {
            sscanf(line + 4, "%ld", &rss);
            break;
        }
    }
    fclose(fp);
    return rss;
}

int main(void)
{
    long pagesz = sysconf(_SC_PAGESIZE);
    size_t P = (size_t)pagesz;

    /* PROT_NONE guard 包夹观察区：防观察区的 VMA 被相邻分配 merge 吞并
     * （v1 实测教训：fopen(/proc/self/smaps) 自身 malloc→mmap，
     *  与观察区紧贴且 flags 相同 → vma_merge 吞掉边界，VMA 条数错乱） */
    char *raw = mmap(NULL, 5 * P, PROT_NONE, MAP_PRIVATE | MAP_ANONYMOUS, -1, 0);
    if (raw == MAP_FAILED) { perror("mmap raw"); return 1; }
    char *p = mmap(raw + P, 3 * P, PROT_READ | PROT_WRITE,
                   MAP_PRIVATE | MAP_ANONYMOUS | MAP_FIXED, -1, 0);
    if (p == MAP_FAILED) { perror("mmap"); return 1; }

    printf("mmap p=%p（未触碰）Rss=%ld kB ← 画区完成，物理页为 0\n",
           (void *)p, smaps_rss(p));

    volatile char c = p[0]; (void)c;    /* 读触碰：映射零页 */
    printf("读触碰后 Rss=%ld kB ← 零页不计入 RSS\n", smaps_rss(p));

    p[0] = 1;                           /* 写触碰：分配真页 */
    printf("写触碰后 Rss=%ld kB ← COW 真页进 RSS\n", smaps_rss(p));

    /* close(fd) 后映射存活 */
    int fd = open("/tmp/ch49_a.dat", O_RDWR | O_CREAT | O_TRUNC, 0644);
    if (fd < 0) { perror("open"); return 1; }
    if (write(fd, "FDLIFE", 6) != 6) { perror("write"); return 1; }
    char *f = mmap(NULL, 6, PROT_READ, MAP_PRIVATE, fd, 0);
    if (f == MAP_FAILED) { perror("mmap file"); return 1; }
    close(fd);
    printf("close(fd) 后读文件映射：\"%.6s\" ← vma->vm_file 持引用\n", f);

    munmap(p, 3 * P);
    munmap(raw, 5 * P);
    munmap(f, 6);
    unlink("/tmp/ch49_a.dat");
    return 0;
}
```

## 自测题

**题目 1（选择）：** `mmap(NULL, 4096, PROT_READ, MAP_PRIVATE, fd, 100)` 返回什么错误？fd 打开模式为 O_RDONLY。

A. 成功　B. `EINVAL`　C. `EACCES`　D. `EBADF`

<details>
<summary>参考答案</summary>

**B（EINVAL）**——offset=100 未页对齐。prot=PROT_READ 没超过 O_RDONLY 模式（不触发 EACCES）。页对齐是 offset 参数自己的硬性要求，与 prot 无关。

</details>

**题目 2（判断）：** `mmap` 成功返回时，`length` 字节的物理内存已经分配好了。

<details>
<summary>参考答案</summary>

错误。mmap 只建 VMA（画区），一颗物理页都没有——实测 `mmap` 后 `Rss=0 kB`。物理页在首次访问时按缺页中断逐页分配（匿名走 `do_anonymous_page`，文件走 `filemap_fault`）。例外：`MAP_POPULATE` 标志强制立即预填充。

</details>

**题目 3（应用）：** 为什么实验程序要用 PROT_NONE 页包夹观察区？

<details>
<summary>参考答案</summary>

两个原因：① `vma_merge()`（mm/mmap.c:863）会把**属性相同且地址紧贴**的相邻 VMA 合并成一个——观察工具自身的 `fopen`（内部 malloc→mmap 一个新 VMA）如果恰好紧贴观察区且 flags 相同，观察区的边界就被吞掉，maps 里的条数失真（实测踩过：VMA 条数=0）；② guard 的 PROT_NONE 与观察区的 RW flags 不同，merge 必然拒绝，观察窗口的边界被钉死。这本身就是 vma_merge 语义的活体演示。

</details>
