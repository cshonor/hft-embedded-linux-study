# 49.4 文件映射

> 源码核验：Linux v6.6 · `mm/memory.c`（`do_wp_page():3338` · `wp_page_copy():3053` · `wp_page_shared():3276` · `copy_present_pte():923`）· `mm/filemap.c`（page cache 查找 `filemap_fault`）

## 本节讲什么

文件映射把**页缓存（page cache）**按需挂进进程虚址。三个灵魂问题：

1. PRIVATE 读的是什么？（**page cache 原页**——私有只承诺写之后；实测 v1 曾在此翻车）
2. 越过文件尾访问映射会怎样？（**SIGBUS**——映射合法（VMA 覆盖）但页无后备，与 SIGSEGV 的分界线）
3. 修改对别人可见吗？（SHARED 立即可见：写的就是 page cache；PRIVATE 永不可见：COW 副本）

---

## 要点

### PRIVATE vs SHARED 文件映射：内核路径速查

| 环节 | `MAP_PRIVATE` 文件 | `MAP_SHARED` 文件 |
|------|--------------------|-------------------|
| 读 | 缺页把 **page cache 页直接映射进来**（不复制！多进程读同一物理页） | 同左——共享同一 page cache 页 |
| 首写 | `do_wp_page():3338` → 私有分支 → `wp_page_copy():3053`：**复制 page cache 页内容到私有匿名页**，此后与文件脱钩 | `do_wp_page():3369` → `wp_page_shared():3276`：**原地改 PTE 可写 + 页标脏**，写的直接就是 page cache 页 |
| 其他进程可见？ | ❌（各写各的副本） | ✅（page cache 即唯一真相） |
| 写回磁盘？ | ❌ 永不 | ✅ 脏页由回写线程异步落盘（`msync` 可强制立即） |
| 零页参与？ | 仅"映区超出文件尾"的空白部分读挂零页 | ❌ |

### ⭐ 可见性规则的精确表述（实测三连验证）

> **MAP_PRIVATE 是 copy-on-WRITE，不是 copy-on-ACCESS。**

| 页的状态 | 别人改 page cache 后，我读到什么 |
|----------|----------------------------------|
| 我**从未写过**这页 | **别人的修改**（我的 PTE 还指着 page cache 原页！） |
| 我**写过**这页（任意一字节） | **我的快照**（整页已 COW，写一个字节就定格整页） |

```
实测（WSL Ubuntu，2026-09-05，v1→v2→v3 三版连环）：
  v1：fork 后子写 shar[0]='S'，父读 priv[0] → 'S'（不是预写的 'O'！）
      ← 推翻「PRIVATE=快照」的直觉：未写过的页跟随 page cache
  v2：父在 fork 前写 priv[1]='K'，fork 后子改 shar，父读 priv[0] → 'O'
      ← 意外：写 priv[1]（同页）把 priv[0] 也定格了——COW 粒度是页
  v3：对照组放不同页（页 0 不写 / 页 1 写 'K'）：
      priv[0]='S'（跟随）  priv[4096]='K'（快照）  ← 双双命中
```

### 越界访问的两种死法

| 信号 | 含义 | 触发条件 |
|------|------|----------|
| **SIGSEGV** | 虚址**无 VMA 覆盖**（映射之外） | 访问未映射区/已 munmap 区/prot 禁止的操作 |
| **SIGBUS** | 虚址**有 VMA 但无后备页** | 文件映射越过 EOF（文件被 truncate）/ 磁盘坏块 / 稀疏洞未分配 |

实测：映射 2 页文件 → `ftruncate` 缩到 1 页 → 访问第 2 页 `shar[4096]` → **捕获 SIGBUS**（缺页处理走到 `filemap_fault` 发现 offset ≥ i_size）。

### fd 关闭与映射生命周期

`mmap` 后 `close(fd)` 映射仍有效（`vm_area_struct.vm_file` 持引用，实测验证见 [49.2](49.2-creating-a-mapping-mmap.md)）。文件被删（unlink）也一样——页缓存与 inode 的引用还活着。**杀掉映射的只有三件事：munmap / 进程退出 / exec。**

## HFT / 嵌入式关联

| 路线 | 要点 |
|------|------|
| 嵌入式 | SHARED 只读映射共享固件/ROMFS 镜像省 RAM；fork 后 PRIVATE 首写 COW 共享只读段零拷贝（busybox 型多进程布局） |
| HFT | SHARED 映射跨进程共享订单簿/行情**零拷贝**（写=写 page cache，无 syscall、无拷贝）；读多写少场景用 PRIVATE 借 COW 省内存——但**记住可见性规则**：策略进程「以为的快照」若从未写過，行情写入端一改它就读到新值——需要真快照时必须自己先触碰一页定格 |

## 代码示例

```c

/* PRIVATE vs SHARED 可见性 + SIGBUS 实测（v3 最终版）
 * 实测（WSL Ubuntu，gcc -O2 -Wall -Wextra，2026-09-05）：
 *   步骤2 fork 后父观察:
 *     priv[0]='S'（页 0 未写→跟随 page cache）
 *     priv[4096]='K'（页 1 写过→整页 COW 快照）
 *     shar[0]='S' shar[4096]='T'（SHARED 全局可见）
 *   步骤3 文件截断到 1 页，访问映射第 2 页 shar[4096]……捕获 SIGBUS ✓
 */
#define _GNU_SOURCE
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <fcntl.h>
#include <errno.h>
#include <signal.h>
#include <setjmp.h>
#include <sys/mman.h>
#include <sys/wait.h>
#include <unistd.h>

static sigjmp_buf jb;
static void bus_handler(int sig) { (void)sig; siglongjmp(jb, 1); }

int main(void)
{
    long pagesz = sysconf(_SC_PAGESIZE);
    size_t P = (size_t)pagesz;
    size_t len = 2 * P;                    /* 映射 2 页 */

    int fd = open("/tmp/ch49_b.dat", O_RDWR | O_CREAT | O_TRUNC, 0644);
    if (fd < 0) { perror("open"); return 1; }
    if (write(fd, "ORIGORIG", 8) != 8) { perror("write"); return 1; }
    if (ftruncate(fd, (off_t)len) != 0) { perror("ftruncate"); return 1; }

    char *priv = mmap(NULL, len, PROT_READ | PROT_WRITE, MAP_PRIVATE, fd, 0);
    char *shar = mmap(NULL, len, PROT_READ | PROT_WRITE, MAP_SHARED,  fd, 0);
    if (priv == MAP_FAILED || shar == MAP_FAILED) { perror("mmap"); return 1; }

    /* 对照组放不同页：页 1 父 fork 前写 'K'（整页 COW 定格）；页 0 不写（跟随） */
    priv[P] = 'K';
    pid_t pid = fork();
    if (pid == 0) {
        priv[0] = 'P';                     /* 子 COW：只影响子进程副本 */
        shar[0] = 'S';                     /* 直接写 page cache：全局可见 */
        shar[P] = 'T';
        _exit(0);
    }
    wait(NULL);
    printf("fork 后父观察:\n");
    printf("  priv[0]='%c'（页 0 未写→跟随 page cache）\n", priv[0]);
    printf("  priv[%ld]='%c'（页 1 写过→整页 COW 快照）\n", (long)P, priv[P]);
    printf("  shar[0]='%c' shar[%ld]='%c'（SHARED 全局可见）\n",
           shar[0], (long)P, shar[P]);

    /* SIGBUS：文件截断到 1 页，访问第 2 页（越过 EOF 无后备） */
    if (ftruncate(fd, (off_t)P) != 0) { perror("ftruncate 2"); return 1; }
    signal(SIGBUS, bus_handler);
    printf("文件截断到 1 页，访问映射第 2 页……");
    fflush(stdout);
    if (sigsetjmp(jb, 1) == 0) {
        volatile char c = shar[P]; (void)c;
        printf("读取成功（异常！）\n");
    } else {
        printf("捕获 SIGBUS ✓（映射合法但页无后备）\n");
    }

    munmap(priv, len);
    munmap(shar, len);
    close(fd);
    unlink("/tmp/ch49_b.dat");
    return 0;
}
```

## 自测题

**题目 1（选择）：** 进程 A 以 `MAP_PRIVATE` 映射文件，从未写入页 0。进程 B 以 `MAP_SHARED` 映射同一文件并修改了文件页 0。A 读页 0 得到？

A. 文件原内容　B. B 修改后的内容　C. 全 0　D. 未定义

<details>
<summary>参考答案</summary>

**B**。A 的 PTE 仍指向 page cache 原页（从未 COW），B 的修改直接写在 page cache 页上，A 读到修改。MAP_PRIVATE 只在**自己写**的那一刻才定格快照。实测三连（v1）正是这个结论的出处。

</details>

**题目 2（判断）：** 文件映射越界访问（文件 4KB、映射 8KB、访问 offset 6KB）触发 SIGSEGV。

<details>
<summary>参考答案</summary>

错误，是 **SIGBUS**。虚址在 VMA 内（映射合法），但后备文件不够——缺页处理发现 offset ≥ i_size，无法提供数据页，发 SIGBUS。SIGSEGV 是「VMA 都不存在」，两者的判定层次不同（内存管理子系统 vs 文件层后备）。实测验证：截断到 1 页后访问第 2 页捕获 SIGBUS。

</details>

**题目 3（应用）：** 写一个「行情快照」策略进程，要求行情写入进程落盘的更新不影响已读到的行情，怎么设计？

<details>
<summary>参考答案</summary>

用 `MAP_PRIVATE` 映射，**启动后先逐页写一遍**（例如 memset 或拷贝到本地）把整段定格成 COW 快照——此后的读与 page cache 脱钩。注意 COW 粒度是页：只写过页内 1 字节，整页（4KB）都定格。代价：每页多一份物理内存拷贝。若嫌贵：只定格真正要读的页区间（稀疏触碰），或者用 `msync`+独立文件做版本化快照。

</details>
