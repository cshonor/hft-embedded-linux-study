## 本节讲什么

`munmap` 从进程地址空间**删除一段 VMA 区间**，顺带释放区间内该进程私有的物理页与页表项。三个灵魂问题：

1. 删掉的是什么？（VMA 区间 + PTE + 私有页的引用——不是「擦除内存」）
2. 域内的脏页去哪了？（MAP_SHARED 的脏页由内核回写机制异步落盘，munmap 不等待；要保证先 `msync`）
3. 部分解除会发生什么？（**VMA 分裂**——一个 VMA 变两个，实测可见）

```c
#include <sys/mman.h>
int munmap(void *addr, size_t length);
/* 返回 0 成功；-1 失败（EINVAL：addr 未页对齐） */
```

---

## 要点

### 行为规则

| 规则 | 说明 |
|------|------|
| `addr` **必须页对齐** | 否则 `EINVAL`（内核不取整、不静默修正） |
| `length` 向上取整 | 同 mmap |
| 区间内**未映射的空洞** | **静默忽略**——munmap 允许覆盖空洞+映射混合区间，全部拆掉 |
| MAP_PRIVATE 修改 | 随私有页释放而**丢弃**（本来就不回文件） |
| MAP_SHARED 脏页 | 留在 page cache，回写线程**异步**落盘——munmap 返回 ≠ 数据在磁盘 |
| 访问已解除区 | 缺页 → **SIGSEGV**（该虚址已无 VMA 覆盖） |
| 进程退出/exec | 全部映射自动解除（mm_struct 销毁路径批量做） |

### ⭐ VMA 分裂：munmap 中间一页的实测

映射 3 页 → `munmap(p + pagesize, pagesize)`（只拆中间页）：

```
实测（WSL Ubuntu，2026-09-05）：
  munmap 前 maps 条数=1
  munmap 后 maps 条数=2      ← [p, p+P) 和 [p+2P, p+3P) 两个独立 VMA
  Rss=4 kB                   ← 第 0 页写过仍驻留；中间页被释放
```

`do_vmi_align_munmap():2452` 的处理：区间两端若切在 VMA 中间，先 **split** 出「被删部分」——VMA 从 1 个变 3 个，中间的标记 detach 后销毁，剩下 2 个。**map_count 也会随之变化**（大量分裂受 `vm.max_map_count` 默认 65530 限制）。

### 内核路径（v6.6 坐标）

```
munmap(2)
 └─ __vm_munmap():2918
     └─ do_vmi_munmap():2618
         └─ do_vmi_align_munmap():2452
             ├─ vma 找齐：mas_walk 定位 start/end 所在 VMA
             ├─ 两端切割：start 落在 VMA 内部 → vma_split（VMA 分裂的来源）
             ├─ 摘除：受影响 VMA 标记 detached，从 maple tree 批量移除
             │    （mmap_write_lock 全程持有——munmap 是重操作）
             └─ unmap_region():2575
                 ├─ unmap_vmas：逐 PTE 拆映射
                 │    └─ zap_pte_range：清 PTE，私有页引用--（归零则释放回 buddy）
                 │       文件页：从 page cache 摘除引用（页本身通常留在 cache）
                 ├─ free_pgtables：整段页表页（PTE 页本身）释放
                 └─ tlb_finish_mmu：批量刷 TLB（惰性批次化，减少 IPI 次数）
```

**TLB shootdown**：munmap 拆掉 PTE 后，别的 CPU 核上可能还缓存着旧翻译——必须发 IPI 让所有核的 TLB 作废该区间。多核服务器上大区间 munmap 的开销主要在这批 IPI（这也是 THP 存在的理由之一：一个 2MB 页一条 TLB 项，shootdown 对象少 512 倍）。

### msync 与 munmap 的先后

「保证 SHARED 脏页落盘再解除」的正确顺序：

```c
msync(p, len, MS_SYNC);   /* 阻塞到磁盘写完 */
munmap(p, len);           /* 之后解除才安全 */
```

munmap 自身**不提供任何落盘保证**（脏页留在 page cache 交给回写线程）。崩溃窗口 = munmap 后、回写完成前。

---

## HFT / 嵌入式关联

| 路线 | 要点 |
|------|------|
| 嵌入式 | NOMMU 体系 munmap 粒度受限（只能整段、地址必须与原 mmap 完全一致）；RAM 紧张设备上「及时 munmap 大映射」比「等退出」更能压住碎片 |
| HFT | 行情缓冲换版时 `munmap`+重建会引发：①TLB shootdown IPI（打断其他忙轮询核！）；②新映射首触缺页——替代方案是 `MADV_DONTNEED`（只清页保 VMA，见 [50.4](../../chapter-50-virtual-memory/notes/50.4-advising-future-memory-usage-patterns-ma.md)）。**换缓冲尽量避免 munmap** |

## 代码示例

```c

/* munmap 部分解除：VMA 分裂实测（maps 条数 1→2）
 * 实测（WSL Ubuntu，gcc -O2 -Wall -Wextra，2026-09-05）：
 *   步骤4 munmap 中间页（VMA 分裂）
 *     [分裂后] VMA条数=2  Rss=4 kB
 */
#include <stdio.h>
#include <stdlib.h>
#include <fcntl.h>
#include <sys/mman.h>
#include <unistd.h>

/* 统计 maps 中完全落在 [start,start+len) 内的 VMA 条数 */
static int maps_count(void *start, size_t len)
{
    FILE *fp = fopen("/proc/self/maps", "r");
    if (!fp) return -1;
    char line[300];
    unsigned long lo, hi, s = (unsigned long)start, e = s + (unsigned long)len;
    int n = 0;
    while (fgets(line, sizeof line, fp))
        if (sscanf(line, "%lx-%lx", &lo, &hi) == 2 && lo >= s && hi <= e)
            n++;
    fclose(fp);
    return n;
}

int main(void)
{
    long pagesz = sysconf(_SC_PAGESIZE);
    size_t P = (size_t)pagesz;

    /* PROT_NONE guard 包夹，防观察区被相邻 vma_merge 吞并 */
    char *raw = mmap(NULL, 5 * P, PROT_NONE, MAP_PRIVATE | MAP_ANONYMOUS, -1, 0);
    if (raw == MAP_FAILED) { perror("mmap raw"); return 1; }
    char *p = mmap(raw + P, 3 * P, PROT_READ | PROT_WRITE,
                   MAP_PRIVATE | MAP_ANONYMOUS | MAP_FIXED, -1, 0);
    if (p == MAP_FAILED) { perror("mmap"); return 1; }
    p[0] = 1;                                  /* 第 0 页驻留 */

    printf("munmap 前 VMA 条数=%d\n", maps_count(p, 3 * P));

    if (munmap(p + P, P) != 0) { perror("munmap"); return 1; }
    printf("munmap 中间页后 VMA 条数=%d（预期 2：VMA 分裂）\n",
           maps_count(p, 3 * P));

    /* 访问已解除的中间页 → SIGSEGV（此处不演示崩溃，只验证两端仍可访问） */
    p[0] = 2;
    p[2 * P] = 3;
    printf("两端页仍可访问：p[0]=%d p[2P]=%d\n", p[0], p[2 * (int)P]);

    munmap(p, P);
    munmap(p + 2 * P, P);
    munmap(raw, 5 * P);
    return 0;
}
```

## 自测题

**题目 1（选择）：** `munmap(p + 100, 8192)` 其中 p 页对齐、4KB 页。结果？

A. 成功，从 p+100 拆 8192 字节　B. `EINVAL`　C. 成功，但 addr 未对齐被静默取整　D. `ENOMEM`

<details>
<summary>参考答案</summary>

**B（EINVAL）**。munmap 的 addr **必须页对齐**，内核既不取整也不挪移。正确写法：算好包含 p+100 的页（`addr = (char*)(((uintptr_t)(p+100)) & ~(pagesize-1))`），length 覆盖到目标尾部。

</details>

**题目 2（判断）：** `munmap` 一段含未映射空洞的区间会失败。

<details>
<summary>参考答案</summary>

错误。munmap 对区间内的空洞**静默忽略**，只拆除实际存在的映射部分（成功返回 0）。这与 `mlock`（跳过空洞）宽松、与 `msync`（空洞导致最终返回 ENOMEM）严格的行为形成三方对比——同族 API 对空洞的策略并不统一，记忆点：munmap 最宽容。

</details>

**题目 3（应用）：** 为什么说「在忙轮询的多核交易机上，大区间 munmap 是全局税」？

<details>
<summary>参考答案</summary>

munmap 拆 PTE 后必须**作废所有 CPU 上缓存的旧翻译**（TLB shootdown）——内核向每个可能持有该区间翻译的核发 IPI，中断信号会打断那些核上正在跑的忙轮询线程（哪怕它们根本不碰这块内存），造成几十微秒的抖动，摊到所有核上。规避：① 用 `MADV_DONTNEED` 替代（清页但保 VMA，同样有 shootdown 但页数可控）；② 用 THP 减少 TLB 项数量；③ 在 RCU 风格的「换代窗口」（交易间隙）集中做地址空间手术。

</details>
