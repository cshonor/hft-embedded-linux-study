## 要点

### 两种匿名映射方式

| 方式 | flags | 可移植性 |
|------|-------|----------|
| `MAP_ANONYMOUS` | `MAP_SHARED\|MAP_ANONYMOUS`, fd=-1 | Linux/BSD（非 POSIX） |
| `/dev/zero` | 映射 `/dev/zero` 文件 | POSIX 可移植 |

### MAP_SHARED vs MAP_PRIVATE 匿名映射

| | `MAP_SHARED\|MAP_ANONYMOUS` | `MAP_PRIVATE\|MAP_ANONYMOUS` |
|--|----------------------------|------------------------------|
| 用途 | 父子进程共享内存 | 分配零初始化内存 |
| fork 后 | 子进程共享同一映射 | 子进程获得 COW 副本 |
| 等价于 | 共享内存 IPC | 类似 `malloc`（但无 free） |

### 修改可见性与回写对比速记

| flag | 修改其他进程可见？ | 写回文件？ | 零页 COW？ |
|---|---|---|---|
| `MAP_PRIVATE` 匿名 | ❌ 不可见 | ❌ 无文件可回 | ✅ 有（读挂零页，首写实分页） |
| `MAP_SHARED` 匿名 | ✅ 可见（同物理页） | ❌（无后备文件；**有后备的是 swap**） | 读 hole 也挂零页（shmem SGP_READ），**仅写实分页** |
| `MAP_PRIVATE` 文件 | ❌ | ❌ | ✅（读共享 page cache，首写复制走人） |
| `MAP_SHARED` 文件 | ✅ | ✅ 脏页异步回写 | ❌ 无（写直接进 page cache） |

### 典型用法：父子进程共享内存

```c
/* MAP_ANONYMOUS | MAP_SHARED: fork 后父子共享 */
int *shared = mmap(NULL, sizeof(int), PROT_READ|PROT_WRITE,
                   MAP_SHARED|MAP_ANONYMOUS, -1, 0);
*shared = 0;
if (fork() == 0) {
    *shared = 42;  /* 子进程写 */
    _exit(0);
}
wait(NULL);
printf("parent sees: %d\n", *shared);  /* 42 */
```

### 与 malloc 的区别

| | `malloc` | `mmap(MAP_ANONYMOUS)` |
|--|---------|----------------------|
| 可 free | 是 | 否（需 munmap） |
| 粒度 | 任意大小 | 页对齐（4KB） |
| 共享 | 否 | 可（MAP_SHARED） |
| 初始化 | 不保证 | 零初始化 |
| 底层 | 小块 brk / 大块（≥128KB）mmap——**全是 `MAP_PRIVATE` 匿名映射** | — |

## 零页与 COW 的内核真相

### 零页是什么

| 属性 | 值 |
|------|-----|
| 本体 | `ZERO_PAGE(0)`——内核镜像里一个特殊只读物理页，内容全 0 |
| 符号 | `zero_pfn`（`mm/memory.c:164`），`init_zero_pfn():172` 在启动早期把它的 PFN 存进全局变量 |
| 磁盘后备 | **无**。开机就在内存，永不换出 |
| 共享范围 | **全局所有进程**——谁的匿名私有页没被写过，PTE 就指它 |
| 归属 | 不属于任何进程：**RSS 都不计入它**（后面实测验证） |

### 读路径：挂零页

`do_anonymous_page()`（`mm/memory.c:4067`）对「读触发的缺页」：

```c
/* Use the zero-page for reads */
if (!(vmf->flags & FAULT_FLAG_WRITE) &&
        !mm_forbids_zeropage(vma->vm_mm)) {          // :4086
        entry = pte_mkspecial(pfn_pte(my_zero_pfn(vmf->address),
                        vma->vm_page_prot));          // :4088  ← PTE 指向零页
        ...
        goto setpte;                                  // 只装 PTE，不分配任何页
}
```

关键：**分配的只有页表项，一页物理内存都没给你**。之后读这页永远读零页的 0，MMU 不报错——PTE 存在、有映射，只是指向只读共享页。`pte_mkspecial` 标记它"特殊"，`vm_normal_page()` 会跳过它（rmap/回收不认识零页）。

顺带：`mm_forbids_zeropage()` 为真的场景是 KVM 等——虚拟机脏页追踪要求每页可追踪，零页共享会破坏语义，此时读也实分页。

### 写路径：直接分配清零新页（⚠ 精确说法）

写触发的缺页不走上面那个 if，直接（`:4102-4104`）：

```c
/* Allocate our own private page. */
if (unlikely(anon_vma_prepare(vma))) ...
folio = vma_alloc_zeroed_movable_folio(vma, vmf->address);   // :4104
...
entry = mk_pte(&folio->page, vma->vm_page_prot);
if (vma->vm_flags & VM_WRITE)
        entry = pte_mkwrite(pte_mkdirty(entry), vma);        // :4121 可写+脏
```

所以「COW 复制零页」的**精确版本**是：

> 首写匿名私有页：**分配一个全新清零物理页（无 memcpy）**，把 PTE 从零页改指它。逻辑上是"写时复制"，物理上零页根本没被复制——目标本来就是全 0，分配清零页等价且更省（清零有硬件优化的 `clear_page`，比拷贝快）。

真发生"从零页复制"判定的是 `wp_page_copy():3072`——但那是 **fork 之后**的场景：父子共指零页 + 双方 PTE 均被写保护，一方写时 `is_zero_pfn(pte_pfn(vmf->orig_pte))` 命中，同样**跳过拷贝**直接清零新页。

### fork 的 COW：copy_present_pte 双向写保护

fork 复制页表时（`copy_present_pte():923`）：

```c
/*
 * If it's a COW mapping, write protect it both
 * in the parent and the child
 */
if (is_cow_mapping(vm_flags) && pte_write(pte)) {      // :960
        ptep_set_wrprotect(src_mm, addr, src_pte);     // 父也写保护！
        pte = pte_wrprotect(pte);                      // 子写保护
}
```

三个要点：

1. **父进程的 PTE 也被写成只读**——COW 是父子双方同时进入只读态，谁先写谁触发 `do_wp_page()`。
2. `is_cow_mapping()` 即 `!(flags & (VM_SHARED | VM_MAYSHARE))`——**`MAP_SHARED` 映射完全绕过 COW**：父子直接共指同一物理页，谁写都不复制（这正是"共享"语义的内核实现，也解释了上面对比表最后一列）。
3. 写触发后的分流在 `do_wp_page():3338`：
   - `:3369` `VM_SHARED|VM_MAYSHARE` → `wp_page_shared():3276`——**原地改 PTE 可写 + 标脏**，不复制；
   - 私有映射 → 若该页确认独占（fork 后对方已写走/未共享）→ `wp_page_reuse():3009` 原地复用；真共享着 → `wp_page_copy():3053` 分配新页 + 复制内容（源是零页则免拷贝）。

### 匿名 SHARED：读 hole 也有零页捷径，写才实分页

`do_anonymous_page():4076` 开头一行挡死零页捷径：

```c
if (vma->vm_flags & VM_SHARED)
        return VM_FAULT_SIGBUS;    // 匿名共享映射不走这条路径
```

匿名 `MAP_SHARED` 的 VMA 由 shmem（tmpfs）接管。但「共享必须实分页」只对了一半——shmem 对**读 hole** 同样有零页捷径（`mm/shmem.c:1993` 注释原文）：

```c
/*
 * SGP_READ: succeed on hole, with NULL folio, letting caller zero.
 * SGP_NOALLOC: fail on hole, with NULL folio, letting caller fail.
 */
```

读 fault 拿到 NULL folio 后映射全局零页（`shmem.c:2906` `.page = ZERO_PAGE(0)`）。这在语义上完全成立：hole 里还没人写过，读出来必然全 0，指零页和指一个清零页无法区分。一旦有任何一方**写**（SGP_WRITE），shmem 才分配真页放进 page cache——此后所有进程的读 fault 都命中真页，共享语义由此建立。

所以精确结论是：**零页优化覆盖到 shmem 读 hole；共享的“实分页”门槛只卡在写上**。下面 demo 的 B 段实测验证：SHARED 匿名全量读 RSS 不涨，写一半 RSS +128MB。

### malloc 与 overcommit 的会计真相

- malloc 大块（glibc 阈值默认 128KB）→ `mmap(MAP_PRIVATE|MAP_ANONYMOUS)` → 仅仅登记了 VMA，物理账上一页未付；
- RSS 不涨、`/proc/meminfo` 的 Committed_AS 也不按全量记（默认 overcommit heuristic 只对"明显超过 RAM+swap"说不）；
- **物理页分配被推迟到每次首写的那一下缺页**——所以"申请 1TB 成功"和"物理内存耗尽 OOM"可以相隔任意久。

## HFT / 嵌入式关联

| 路线 | 要点 |
|------|------|
| 嵌入式 | 匿名共享映射是父子进程 IPC 最简单方式；只读大数组让零页兜底，省下整个数组的 RAM |
| HFT | `MAP_SHARED\|MAP_ANONYMOUS` 用于父子共享行情数据，零拷贝；预分配 arena 但只写热区——冷区一直由零页"免费"占位，RSS 反映真实热区 |
| HFT | 懒分配=确定性敌人：首写延迟里藏着缺页+清零+可能的内存回收，热路径上要么启动时 `mlock`+全量触碰，要么接受首次访问的毛刺 |

## 代码示例

```c
/* zero_page_demo.c — Ch49.7：零页 vs 实分页的 RSS 实测
 * A. MAP_PRIVATE 匿名：映射后 / 全量读后 / 写一半后 三阶段观测
 * B. MAP_SHARED 匿名（shmem）：读不占 RSS（SGP_READ hole 零页）vs 写才实分页
 * 编译：gcc -O2 -Wall -Wextra -o zero_page_demo zero_page_demo.c
 */
#define _GNU_SOURCE
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <sys/mman.h>
#include <unistd.h>

#define MB (1024UL * 1024)
#define SIZE (256UL * MB)          /* 256MB，页大小 4KB → 65536 页 */

/* /proc/self/statm 第 2 列 = resident（单位：页） */
static long rss_pages(void)
{
    long size, resident;
    FILE *f = fopen("/proc/self/statm", "r");
    if (!f) return -1;
    if (fscanf(f, "%ld %ld", &size, &resident) != 2) resident = -1;
    fclose(f);
    return resident;
}

static void report(const char *tag, long base)
{
    long r = rss_pages();
    long ps = sysconf(_SC_PAGESIZE);
    printf("  %-28s RSS = %7.1f MB（相对 %+.1f MB）\n",
           tag, (double)r * ps / MB, (double)(r - base) * ps / MB);
}

int main(void)
{
    long ps = sysconf(_SC_PAGESIZE);
    printf("页大小 %ld B，映射 %lu MB\n", ps, SIZE / MB);

    /* ========== A. MAP_PRIVATE 匿名：零页三阶段 ========== */
    char *p = mmap(NULL, SIZE, PROT_READ | PROT_WRITE,
                   MAP_PRIVATE | MAP_ANONYMOUS, -1, 0);
    if (p == MAP_FAILED) { perror("mmap"); return 1; }
    long base = rss_pages();
    report("A1 映射完成（未触碰）", base);

    /* 全量只读扫描：每页都读 1 字节 → 65536 次读缺页全挂零页 */
    for (size_t i = 0; i < SIZE; i += (size_t)ps)
        if (p[i] != 0) { printf("非零?! 破坏假设\n"); return 1; }
    report("A2 全量读一遍后", base);

    /* 写前一半：32768 次写缺页 → 32768 个清零实页 */
    memset(p, 0x5A, SIZE / 2);
    report("A3 写前一半后", base);

    printf("  解读：读 256MB → RSS 纹丝不动（零页共享不计入）；"
           "写 128MB → RSS 恰好 +128MB\n");
    munmap(p, SIZE);

    /* ========== B. MAP_SHARED 匿名：shmem 对照组 ========== */
    char *s = mmap(NULL, SIZE, PROT_READ | PROT_WRITE,
                   MAP_SHARED | MAP_ANONYMOUS, -1, 0);
    if (s == MAP_FAILED) { perror("mmap shared"); return 1; }
    long base2 = rss_pages();
    for (size_t i = 0; i < SIZE; i += (size_t)ps)
        (void)s[i];               /* 只读不写 */
    report("B1 SHARED 全量读一遍后", base2);
    memset(s, 0x5A, SIZE / 2);    /* 写前一半：shmem 实分页 */
    report("B2 SHARED 写前一半后", base2);
    munmap(s, SIZE);
    return 0;
}
```

实测输出（WSL2 / 12 核，4KB 页，gcc -O2 零告警）：

```text
页大小 4096 B，映射 256 MB
  A1 映射完成（未触碰）        RSS =     1.4 MB（相对 +0.1 MB）
  A2 全量读一遍后              RSS =     1.4 MB（相对 +0.1 MB）
  A3 写前一半后                RSS =   129.4 MB（相对 +128.1 MB）
  解读：读 256MB → RSS 纹丝不动（零页共享不计入）；写 128MB → RSS 恰好 +128MB
  B1 SHARED 全量读一遍后       RSS =     1.5 MB（相对 +0.0 MB）
  B2 SHARED 写前一半后         RSS =   129.5 MB（相对 +128.0 MB）
```

三点解读：

1. **A2 纹丝不动是零页的直接证据**：65536 个 PTE 都装上了、256MB 读全成功，RSS 一页没涨——它们全指同一个全局零页。
2. **A3 精确 +128MB** 验证「首写才实分页」；分配的是清零新页（不是复制零页，见前文精确辨析）。
3. **B1 是打破直觉的一组**：SHARED 匿名全量读 RSS 也不涨——shmem 读 hole 同样挂零页（SGP_READ，`shmem.c:1993`）；B2 写一半 +128MB 才实分页。「共享必须实分页」的门槛只卡在**写**上。

## 自测题

**题目 1（概念）：** `mmap` 返回成功、也读到了全 0，物理内存分配了吗？

<details>
<summary>参考答案</summary>

没有（就这批被读过的页而言）。读路径的缺页由 `do_anonymous_page():4086` 用零页满足：只装 PTE，不分配物理页。零页是内核全局共享的只读页，连 RSS 都不计入。真正的物理页分配推迟到首写。

</details>

**题目 2（精确辨析）：** 「首写匿名私有页时，内核分配新页并**复制零页内容**」——这句话哪里不精确？

<details>
<summary>参考答案</summary>

`do_anonymous_page()` 写路径（`:4104`）直接调 `vma_alloc_zeroed_movable_folio()` 分配**清零**新页，没有发生"从零页复制"的 memcpy——目标本来就是全 0，清零等价且更快。"从零页复制"的判定只出现在 fork 之后的 `wp_page_copy():3072`（`is_zero_pfn` 特判），且那里同样跳过拷贝。逻辑上叫 COW，物理上是"换页+清零"。

</details>

**题目 3（fork）：** fork 后父子对匿名私有页各写一次，物理页从 1 页变成几页？谁的 PTE 先失去写权限？

<details>
<summary>参考答案</summary>

2 页。`copy_present_pte():960` 在 fork 复制页表时就把**父子双方**的 PTE 都写保护（`ptep_set_wrprotect` 父 + `pte_wrprotect` 子）；先写的一方走 `wp_page_copy()` 分配自己的新页，后写的一方此时独占原页，走 `wp_page_reuse()` 原地改回可写——所以是 1(共享) → 2(各一份)。

</details>

**题目 4（对比）：** 匿名 `MAP_SHARED` 映射首读分配物理页吗？什么时候才分配？

<details>
<summary>参考答案</summary>

首读不分配。`do_anonymous_page():4076` 开头 `VM_SHARED → SIGBUS` 挡死零页捷径，匿名共享 VMA 由 shmem 接管；但 shmem 对读 hole 也有零页捷径（`shmem.c:1993`「SGP_READ: succeed on hole, with NULL folio, letting caller zero」）——读 fault 拿到 NULL folio 后映射全局零页。**写 fault（SGP_WRITE）才分配真页放进 page cache**，此后所有映射者的读都命中真页，共享语义建立。demo 实测：SHARED 匿名全量读 RSS +0.0MB，写一半后 +128.0MB。

</details>

**题目 5（面试高频）：** 「malloc 很大内存返回成功但物理内存没分配」完整链条是什么？三个环节各对应哪个内核机制？

<details>
<summary>参考答案</summary>

① glibc 大块（≥128KB）走 `mmap(MAP_PRIVATE|MAP_ANONYMOUS)`——只登记 VMA；② 读触发的缺页由零页满足（`do_anonymous_page` 读路径）——RSS 不涨；③ 首写才分配清零实页（写路径）。overcommit 默认策略（heuristic）允许 VMA 总量超 RAM+swap，所以"申请成功"与"物理耗尽 OOM"可以相隔任意久。

</details>
