## 本节讲什么

`mremap` 是 Linux 特有的「映射版 realloc」：原地扩/缩映射，必要时整段搬家。三个灵魂问题：

1. 原地扩展的条件？（紧邻高地址方向有**够大的空洞**——没空洞时无 `MREMAP_MAYMOVE` 直接 `ENOMEM`）
2. 搬家时数据怎么办？（**PTE 级搬家**：物理页不动，只把页表项搬到新虚址——比 memcpy 快一个数量级）
3. `MREMAP_DONTUNMAP` 是什么？（5.13+ 新玩具：搬走 PTE 但旧虚址**留空壳**，读回零页）

```c
#define _GNU_SOURCE
#include <sys/mman.h>
void *mremap(void *old_address, size_t old_size, size_t new_size,
             int flags, /* void *new_address (MREMAP_FIXED 时) */);
/* flags: MREMAP_MAYMOVE | MREMAP_FIXED | MREMAP_DONTUNMAP(4, Linux 5.13+) */
```

---

## 要点

### 三种操作语义

| 操作 | 条件 | 结果 |
|------|------|------|
| **原地扩展** | `[old_end, old_end + (new-old))` 是空洞 | 地址不变，VMA 长大 |
| **搬家扩展** | 原地不行 + 带 `MREMAP_MAYMOVE` | 新地址（`move_vma():583`：PTE 搬迁），**数据逻辑保留** |
| **收缩** | new < old | 地址不变，尾部 munmap（脏 SHARED 页照常回写） |
| **DONTUNMAP** | 匿名映射 + MAYMOVE + new==old | 新地址得 PTE，旧地址 VMA 保留但读回**零页** |

原地失败且无 MAYMOVE → `MAP_FAILED` + `ENOMEM`（**实测验证**：紧贴阻挡下 errno=12）。

### 错误码表（`vma_to_resize():746` 分支对照）

| errno | 分支（v6.6 坐标） |
|-------|-------------------|
| `EFAULT` | old 区间不在任何 VMA 内 / old_len 超出 VMA 尾（:754/:775） |
| `EINVAL` | DONTUNMAP 用在 VM_DONTEXPAND/VM_PFNMAP 上（:770）等 |
| `EAGAIN` | 扩张会超 `RLIMIT_MEMLOCK`（`mlock_future_ok` :790） |
| `ENOMEM` | 无 MAYMOVE 且原地不行 / map_count 超限 / swap 预留不足（VM_ACCOUNT :793） |

### ⭐ 内核路径：PTE 级搬家（为什么快）

```
mremap(2) → SYSCALL_DEFINE5(mremap)         mm/mremap.c:908
 ├─ vma_to_resize():746                     定位并校验 old VMA
 ├─ new == old：收缩路径 → vma_shrink（尾部 munmap）
 └─ mremap_to():800
     └─ move_vma():583
         ├─ take_rmap_locks():105           锁 anon_vma/i_mmap（反向映射一致性）
         ├─ move_page_tables                【核心】逐 PMD 批量把 PTE 从旧虚址
         │    摘下挂到新虚址——物理页不动！
         ├─ 旧 VMA 区间 munmap
         └─ （DONTUNMAP）旧 VMA 保留、PTE 不搬走的部分清空 → 零页
```

**物理页一个都没动，动的只是页表**。4KB 页的 PTE 搬运是内存内的位操作；这正是 `realloc` 大块内部走 mremap 的原因——扩 128MB→256MB 若靠 memcpy 要搬 128GB/s 级带宽好几毫秒，mremap 原地扩展是**零拷贝**。

### MREMAP_DONTUNMAP 的语义（实测验证）

```
实测（WSL Ubuntu，2026-09-05）：
  DONTUNMAP: 旧 0x75800c513000 → 新 0x75800c511000
    新地址 data="DATA"           ← PTE 搬到新地址，内容完整
    旧地址 d[0]=0x00             ← 旧地址变空壳，读回零填充
```

用途：无锁迁移缓冲（读者还握着旧指针的窗口期内旧地址合法可读——只是读到 0）、构建 userspace 双视图。限制：仅匿名映射（文件映射/PFNMAP 拒绝）、必须 MAYMOVE、new_size 必须 == old_size。

### 与 glibc realloc 的关系

glibc 对**大块**（≥ mmap 阈值，默认 128KB，动态调整）的 malloc 走 mmap；对应 realloc 走 `mremap(MREMAP_MAYMOVE)`——这是「realloc 大块几乎免费」的底层真相。小块在堆内（brk 区）realloc 仍可能 memcpy。

---

## HFT / 嵌入式关联

| 路线 | 要点 |
|------|------|
| 嵌入式 | 环形缓冲按流量扩容：mremap 原地扩（PTE 级）避免复制吞吐缓冲；NOMMU 无 mremap（无页表可搬） |
| HFT | 订单池动态扩容用 `mremap(MREMAP_MAYMOVE)`——**迁移是页表操作不是数据拷贝**，128MB 池扩容在 µs 量级；坑：搬家后地址变了，所有缓存了旧指针的代码（对象池 freelist、硬件 DMA 描述符）必须失效重建——所以宁可 mmap 预留大虚拟区 + MAP_NORESERVE + 按需 populate，也不让地址漂移 |

## 代码示例

```c

/* mremap 原地/受阻/搬家/收缩/DONTUNMAP 全景实测
 * 实测（WSL Ubuntu，gcc -O2 -Wall -Wextra，2026-09-05）：
 *   步骤1 原地扩展 1→2 页: 0x...515000 → 0x...515000（地址不变）data="hello"
 *   步骤2 vic=0x...514000 blk=0x...517000（vic 上方紧贴 blk）
 *     mremap 无 MAYMOVE 被挡: Cannot allocate memory（errno=12 预期 ENOMEM）
 *     mremap MAYMOVE 成功: 0x...514000 → 0x...512000（地址改变）data="VICTIM"
 *   步骤3 收缩 2→1 页: 0x...512000 → 0x...512000（地址不变）data="VICTIM"
 *   步骤4 MAP_FIXED_NOREPLACE 覆盖: EEXIST（见 49.10）
 *   步骤5 DONTUNMAP: 旧 0x...513000 → 新 0x...511000
 *     新地址 data="DATA" / 旧地址 d[0]=0x00（零填充）
 */
#define _GNU_SOURCE
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <errno.h>
#include <sys/mman.h>
#include <unistd.h>

#ifndef MREMAP_DONTUNMAP
#define MREMAP_DONTUNMAP 4
#endif

int main(void)
{
    long pagesz = sysconf(_SC_PAGESIZE);
    size_t P = (size_t)pagesz;

    /* 1. 自造空洞：mmap 3 页 → munmap 上 2 页 → 剩 1 页且上方空洞 */
    char *big = mmap(NULL, 3 * P, PROT_READ | PROT_WRITE,
                     MAP_PRIVATE | MAP_ANONYMOUS, -1, 0);
    if (big == MAP_FAILED) { perror("mmap big"); return 1; }
    if (munmap(big + P, 2 * P) != 0) { perror("munmap hole"); return 1; }
    strcpy(big, "hello");
    char *m1 = mremap(big, P, 2 * P, 0);       /* 无 MAYMOVE，上方空洞 */
    if (m1 == MAP_FAILED) perror("原地扩展");
    else printf("原地扩展 1→2 页: %p → %p data=\"%s\"\n",
                (void *)big, (void *)m1, m1);

    /* 2. 紧贴阻挡（top-down 分配器让 vic 紧贴 blk 下方） */
    char *blk = mmap(NULL, P, PROT_READ | PROT_WRITE,
                     MAP_PRIVATE | MAP_ANONYMOUS, -1, 0);
    char *vic = mmap(NULL, P, PROT_READ | PROT_WRITE,
                     MAP_PRIVATE | MAP_ANONYMOUS, -1, 0);
    if (blk == MAP_FAILED || vic == MAP_FAILED) { perror("mmap blk/vic"); return 1; }
    strcpy(vic, "VICTIM");

    errno = 0;
    char *blocked = mremap(vic, P, 2 * P, 0);  /* 无 MAYMOVE，上方被挡 */
    printf("受阻+无MAYMOVE: %s(errno=%d 预期 %d)\n",
           blocked == MAP_FAILED ? "MAP_FAILED" : "意外成功",
           errno, ENOMEM);

    errno = 0;
    char *moved = mremap(vic, P, 2 * P, MREMAP_MAYMOVE);
    if (moved == MAP_FAILED) perror("MAYMOVE");
    else printf("MAYMOVE 搬家: %p → %p data=\"%s\"\n",
                (void *)vic, (void *)moved, moved);

    /* 3. 收缩 */
    char *shr = mremap(moved, 2 * P, P, 0);
    if (shr != MAP_FAILED)
        printf("收缩 2→1 页: %p → %p data=\"%s\"\n",
               (void *)moved, (void *)shr, shr);

    /* 5. MREMAP_DONTUNMAP：新旧并存，旧地址零填充 */
    char *d = mmap(NULL, P, PROT_READ | PROT_WRITE,
                   MAP_PRIVATE | MAP_ANONYMOUS, -1, 0);
    strcpy(d, "DATA");
    char *d2 = mremap(d, P, P, MREMAP_MAYMOVE | MREMAP_DONTUNMAP);
    if (d2 == MAP_FAILED) {
        perror("DONTUNMAP（内核 < 5.13 或限制）");
    } else {
        printf("DONTUNMAP: 旧 %p → 新 %p\n", (void *)d, (void *)d2);
        printf("  新地址 data=\"%s\" / 旧地址 d[0]=0x%02x（零填充）\n",
               d2, (unsigned char)d[0]);
    }
    return 0;
}
```

## 自测题

**题目 1（选择）：** `mremap(p, 4096, 8192, 0)` 时 p 上方紧贴另一个映射，返回？

A. 成功，搬家到新地址　B. `MAP_FAILED`，errno=`ENOMEM`　C. `MAP_FAILED`，errno=`EAGAIN`　D. `MAP_FAILED`，errno=`EINVAL`

<details>
<summary>参考答案</summary>

**B（ENOMEM）**。无 `MREMAP_MAYMOVE` 且原地无空洞 → 内核不搬、直接失败。要搬家必须显式授权 MAYMOVE。实测 errno=12。

</details>

**题目 2（判断）：** `mremap` 搬家时要复制所有数据到新物理页。

<details>
<summary>参考答案</summary>

错误。`move_page_tables` 搬的是**页表项**（PTE 从旧虚址摘下挂到新虚址），物理页纹丝不动——这就是 mremap 快的本质。代价：TLB shootdown（旧翻译全部作废，IPI 广播）+ rmap 锁（`take_rmap_locks():105`，反向映射一致性）。

</details>

**题目 3（应用）：** 用 `MREMAP_DONTUNMAP` 设计「策略热切换」：新策略引擎就绪前旧引擎继续服务。

<details>
<summary>参考答案</summary>

把策略参数页 `mremap(p, len, len, MAYMOVE|DONTUNMAP)` → 新地址 d2：新引擎绑定 d2 预热（读参数 + 构建索引），旧引擎继续用旧地址 p（注意：读到的是**零**，不是旧数据——所以参数页不能直接切！）。正确用法：p 是「旧引擎私有已写页」才安全……实际上 DONTUNMAP 的旧地址不保留数据，所以热切换的正确结构是：**引擎自己 mmap 双页 + futex 序号**，DONTUNMAP 用于把「预热好的新页」以零拷贝方式挂到服务虚址。核心陷阱：任何「旧地址还能读到旧数据」的假设都是错的（实测 d[0]=0x00）。

</details>
