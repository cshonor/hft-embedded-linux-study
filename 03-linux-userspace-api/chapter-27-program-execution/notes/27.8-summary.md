# 27.8 Summary

> 本章：[TLPI 第 27 章 — Program Execution](./README.md)

## 本章回顾

### exec 函数族

| 函数 | 路径搜索 | 参数形式 | 环境变量 | 标准 |
|------|---------|---------|---------|------|
| `execve(path, argv, envp)` | 否 | 数组 | 自定义 | POSIX |
| `execv(path, argv)` | 否 | 数组 | 继承 | POSIX |
| `execvp(file, argv)` | 是 | 数组 | 继承 | POSIX |
| `execvpe(file, argv, envp)` | 是 | 数组 | 自定义 | GNU |
| `execl(path, arg, ...)` | 否 | 列表 | 继承 | POSIX |
| `execlp(file, arg, ...)` | 是 | 列表 | 继承 | POSIX |
| `execle(path, arg, ..., envp)` | 否 | 列表 | 自定义 | POSIX |

### 命名规律

| 后缀 | 含义 |
|------|------|
| `v` | argv 为数组（vector） |
| `l` | argv 为参数列表（list，以 NULL 结尾） |
| `p` | 搜索 PATH 环境变量 |
| `e` | 自定义 envp 环境变量 |

### exec 后继承的属性

| 继承 | 不继承 |
|------|--------|
| PID, PPID | 程序代码/数据（全部替换） |
| real UID/GID | 栈/堆 |
| 打开的文件描述符（无 FD_CLOEXEC） | 已设置 CLOEXEC 的 fd |
| 当前工作目录 | 信号处理程序（恢复为默认） |
| umask | attached shared memory |
| CPU 亲和性 | 信号掩码（取决于 exec） |
| 进程开始时间 | — |

### exec 与 set-user-ID

| 文件 setuid 位 | exec 后 effective UID |
|---------------|---------------------|
| 无 setuid 位 | 不变（= real UID） |
| 有 setuid 位 | 设为文件 owner UID |
| 有 setgid 位 | effective GID 设为文件 group |

### exec 失败的常见原因

| errno | 含义 |
|-------|------|
| `ENOENT` | 文件不存在 |
| `EACCES` | 无执行权限 |
| `E2BIG` | 参数/环境变量太大 |
| `ENOEXEC` | 文件格式不正确 |
| `ETXTBSY` | 文件正在被写入 |
| `ENOMEM` | 内存不足 |

### system() 回顾

| 特性 | 说明 |
|------|------|
| 内部实现 | `fork()` + `exec("/bin/sh -c cmd")` + `waitpid()` |
| 安全风险 | 命令注入（用户输入被 shell 解释） |
| 替代方案 | `fork()` + `execvp()` / `posix_spawn()` |

## HFT / 嵌入式关联

- **进程管理**：HFT 用 `fork()` + `exec()` 启动策略进程、行情处理进程等
- **安全**：绝不使用 `system()`，所有外部命令执行用 `exec` 系列
- **FD_CLOEXEC**：防止 fd 泄漏到子进程，特别是网络连接 fd
- **嵌入式**：`execvp` 搜索 `PATH`，嵌入式系统需确保 PATH 正确设置
- **posix_spawn**：比 fork+exec 更轻量，嵌入式资源受限场景可用

## 代码自测

<details>
<summary>1. exec 后哪些属性会变？哪些不变？</summary>

**变**：程序代码/数据/栈/堆全部替换、信号处理程序恢复为默认、CPU 时间统计清零
**不变**：PID/PPID、real UID/GID、打开的 fd（无 CLOEXEC 的）、CWD、umask、CPU 亲和性、nice 值、已 attach 的共享内存
</details>

<details>
<summary>2. execvp 如何搜索 PATH？</summary>

`execvp("ls", argv)` 依次搜索 `PATH` 环境变量中的每个目录（用 `:` 分隔），查找名为 `ls` 的可执行文件。如果找到且有执行权限就执行。如果文件名包含 `/`（如 `./myprog`），不搜索 PATH 直接使用。PATH="" 表示只搜索当前目录。
</details>

<details>
<summary>3. 如何防止 fd 泄漏到 exec 的子进程？</summary>

方法 1：对每个 fd 设置 `FD_CLOEXEC`（`fcntl(fd, F_SETFD, FD_CLOEXEC)`）
方法 2：打开时使用 `O_CLOEXEC` flag（`open(path, O_RDONLY | O_CLOEXEC)`）
方法 3：exec 前手动 `close()` 所有不需要的 fd
方法 4：`closefrom(fd)` 关闭 fd 及以上（非标准，但 Linux/BSD 有）

推荐方法 2，因为它是原子的——在 open 和 fcntl 之间不会被信号打断。
</details>
