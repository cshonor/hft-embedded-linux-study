## 与 C 语言学习的关系

`epoll` 是 Linux 高性能 I/O 的核心。理解 `epoll_event` 结构体和 `EPOLLIN/EPOLLOUT` 标志需要 C 语言的 struct、位运算和文件描述符知识。ET vs LT 模式的差异直接影响 C 代码的读写循环结构。

## 常见陷阱

1. **ET 模式未读完**

```c
/* Edge Triggered: 只通知一次 */
epoll_ctl(epfd, EPOLL_CTL_ADD, fd, &ev);  /* ev.events = EPOLLIN|EPOLLET */
/* 必须循环读到 EAGAIN */
```

ET 模式下事件只通知一次。如果没读完，下次不会再通知。必须循环读到 EAGAIN。

2. **EPOLL_CTL_ADD 重复添加**

```c
epoll_ctl(epfd, EPOLL_CTL_ADD, fd, &ev);
/* 下次又 ADD 同一 fd → EEXIST */
```

已添加的 fd 再次 ADD 会返回 EEXIST。应该用 EPOLL_CTL_MOD 修改。

3. **fd 关闭后未从 epoll 移除**

```c
close(fd);  /* epoll 仍引用 → 可能通知已关闭的 fd */
```

close fd 后 epoll 会自动移除，但如果 fd 被复用可能收到旧事件。建议先 epoll_ctl(DEL) 再 close。

## 自测题

**题目 1（选择）：** epoll 的 LT（水平触发）和 ET（边沿触发）的区别？
A. 没有区别
B. LT 只要数据在就一直通知，ET 只在状态变化时通知一次
C. ET 比 LT 快
D. LT 比 ET 快

<details>
<summary>参考答案</summary>

B。LT 只要 fd 上有可读/可写数据就一直通知。ET 只在状态变化（如新数据到达）时通知一次，必须一次读完。

</details>

**题目 2（判断）：** `epoll_wait` 返回的事件中，fd 一定有数据可读。

<details>
<summary>参考答案</summary>

不一定。可能是错误事件（EPOLLERR）、挂起事件（EPOLLHUP）等。需要检查 events 字段。

</details>

**题目 3（踩坑）：** 以下 ET 模式代码有什么问题？
```c
/* EPOLLET 模式 */
char buf[1024];
int n = read(fd, buf, sizeof(buf));
if (n > 0) process(buf, n);
```

<details>
<summary>参考答案</summary>

ET 模式下只读了一次。如果还有数据没读完，不会再收到通知。必须循环读直到返回 EAGAIN：
`while ((n = read(fd, buf, sizeof(buf))) > 0) process(buf, n);`

</details>

**题目 4（应用）：** 写代码：创建 epoll，添加一个监听 socket。

<details>
<summary>参考答案</summary>

```c
int epfd = epoll_create1(0);
struct epoll_event ev;
ev.events = EPOLLIN;
ev.data.fd = listen_fd;
epoll_ctl(epfd, EPOLL_CTL_ADD, listen_fd, &ev);
```

</details>
