# 52.10 Summary

> 本章：[TLPI 第 52 章](./README.md)

## 本节讲什么

第 52 章总结：POSIX 消息队列的完整 API、特性优势和与 SysV 消息队列的对比。

## 要点

### API 总览

| API | 用途 |
|-----|------|
| `mq_open()` | 创建/打开消息队列 |
| `mq_close()` | 关闭描述符 |
| `mq_unlink()` | 删除队列名 |
| `mq_send()` | 发送消息 |
| `mq_receive()` | 接收消息 |
| `mq_timedsend()` | 带超时发送 |
| `mq_timedreceive()` | 带超时接收 |
| `mq_getattr()` | 获取属性 |
| `mq_setattr()` | 设置属性（仅 flags） |
| `mq_notify()` | 注册异步通知 |

### 消息队列属性

| 属性 | 可设时机 | 说明 |
|------|---------|------|
| `mq_maxmsg` | 创建时 | 最大消息数 |
| `mq_msgsize` | 创建时 | 单条消息上限 |
| `mq_flags` | 运行时 | O_NONBLOCK |
| `mq_curmsgs` | 只读 | 当前消息数 |

### vs SysV 消息队列

| 特性 | SysV MQ | POSIX MQ |
|------|---------|----------|
| API | 复杂（semid_ds + msgctl） | 简洁（mq_*） |
| 消息大小 | MSGMAX 限制 | 自定义 |
| 优先级 | mtype 近似 | 真正的 prio |
| 超时 | 不支持 | mq_timedsend/recv |
| 异步通知 | 无 | mq_notify |
| 生命周期 | 内核持久 | 需 mq_unlink |
| I/O 多路复用 | 不支持 | Linux: 支持 |

### 通知机制

| 方式 | 说明 |
|------|------|
| `SIGEV_SIGNAL` | 信号通知，需 SA_SIGINFO |
| `SIGEV_THREAD` | 创建线程回调 |
| `SIGEV_NONE` | 取消通知 |
| 单次规则 | 通知后自动取消，需重新注册 |

### 优先级排序

```
发送: prio=0(normal) prio=5(high) prio=10(urgent)
接收顺序: prio=10 → prio=5 → prio=0
同 prio: FIFO
```

## HFT / 嵌入式关联

- HFT 订单队列：优先级保证紧急订单先处理
- 超时控制：交易消息不无限等待
- 异步通知：线程模式处理消息，不阻塞主循环
- 嵌入式精确控制队列容量，内存友好

## 代码自测

<details>
<summary>POSIX 消息队列相比 SysV 消息队列的三个主要优势是什么？</summary>

1. **超时控制**：`mq_timedsend`/`mq_timedreceive` 支持超时等待，SysV MQ 无此功能
2. **异步通知**：`mq_notify` 可在队列变非空时通知进程（信号或线程回调），SysV MQ 只能轮询或阻塞
3. **真正优先级**：`mq_send` 有 `prio` 参数，内核按优先级排序接收顺序。SysV MQ 的 mtype 不是真正的优先级，语义不同

</details>
