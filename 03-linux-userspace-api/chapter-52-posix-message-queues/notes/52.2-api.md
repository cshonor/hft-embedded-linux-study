```c
mqd_t mq_open(const char *name, int oflag, /* mode, attr if O_CREAT */);
```

## 与 C 语言学习的关系

System V IPC（消息队列、信号量、共享内存）是 Unix 进程间通信的传统机制。这些 API 使用 `key_t` 和 `int` ID，需要 C 语言的类型和 struct 知识。注意 SVIPC 资源不会随进程退出自动释放——这是和 pipe/fifo 的重要区别，需要手动清理。

## 常见陷阱

1. **IPC 资源未释放**

```c
/* 创建共享内存段 */
int shmid = shmget(key, size, IPC_CREAT|0666);
/* 进程退出后段仍存在! */
```

System V IPC 资源持久存在于内核中，不会随进程退出自动释放。必须显式调用 shmctl(shmid, IPC_RMID, NULL) 删除。

2. **ftok 路径失效**

```c
key_t key = ftok("/tmp/myapp", 'A');
/* /tmp/myapp 被删或重建 → key 变化 */
```

ftok 基于文件 inode 生成 key。如果文件被删除重建，inode 变化，key 不同。应使用稳定的文件路径。

3. **信号量初始值未设置**

```c
int semid = semget(key, 1, IPC_CREAT|0666);
/* 初始值不确定（通常是0） */
/* 需要手动 SETVAL */
```

新创建的信号量初始值不确定。必须用 semctl(semid, 0, SETVAL, val) 显式设置初始值。

## 自测题

**题目 1（选择）：** System V IPC 的三种类型是？
A. pipe, FIFO, socket
B. 消息队列, 信号量, 共享内存
C. mutex, condvar, barrier
D. mmap, shm, sem

<details>
<summary>参考答案</summary>

B。System V IPC 包含消息队列（msgq）、信号量（semaphore）和共享内存（shared memory）三种。

</details>

**题目 2（判断）：** System V IPC 资源会随进程退出自动释放。

<details>
<summary>参考答案</summary>

错误。SVIPC 资源持久存在于内核中，不会随进程退出自动释放。必须显式删除（如 shmctl(IPC_RMID)）。

</details>

**题目 3（踩坑）：** 以下代码有什么问题？
```c
key_t key = ftok("/tmp/app", 'A');
int shmid = shmget(key, 4096, IPC_CREAT|0666);
char *p = shmat(shmid, NULL, 0);
/* 使用 p ... */
/* 程序退出，没有 shmdt 和 shmctl(IPC_RMID) */
```

<details>
<summary>参考答案</summary>

1) 没有 shmdt(p) 解除附加；2) 没有 shmctl(shmid, IPC_RMID, NULL) 删除段。段会一直存在于内核中直到手动删除或系统重启。

</details>

**题目 4（应用）：** 写代码创建共享内存段，附加，使用后正确清理。

<details>
<summary>参考答案</summary>

```c
int shmid = shmget(IPC_PRIVATE, 4096, IPC_CREAT|0666);
char *p = shmat(shmid, NULL, 0);
/* 使用 p ... */
shmdt(p);
shmctl(shmid, IPC_RMID, NULL);
```

</details>
