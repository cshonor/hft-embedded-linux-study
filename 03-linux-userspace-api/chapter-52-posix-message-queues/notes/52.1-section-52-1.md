## 与 C 语言学习的关系

本节涉及 `close()`，对应 K&R 8.3 节。C 语言中资源管理靠手动——没有 C++ 的 RAII。`close` 必须在所有代码路径上调用，这是 C 语言内存/资源管理的核心训练点。

## 常见陷阱

1. **close 返回值未检查**

```c
close(fd);  /* NFS 上可能报延迟错误 */
```

close 可能返回错误（尤其在 NFS 上）。不检查会丢失延迟的写错误。生产代码应检查。

2. **fd 泄漏**

```c
int fd = open(...);
if (error) return;  /* fd 泄漏! */
close(fd);
```

打开 fd 后，在所有错误路径上都必须 close。用 goto cleanup 模式或 RAII。

3. **double close**

```c
close(fd);
/* ... */
close(fd);  /* 可能关闭了复用的 fd */
```

close 后 fd 被回收。如果另一个 open 复用了同一编号，double close 会关错文件。close 后应置 -1。

## 自测题

**题目 1（选择）：** `close(fd)` 后 fd 的值变为？
A. 0
B. -1
C. 不变但不可用
D. 自动设为 -1

<details>
<summary>参考答案</summary>

C。close 不会修改 fd 变量的值，但该 fd 编号已被回收，可被后续 open 复用。建议手动置 -1。

</details>

**题目 2（判断）：** `close` 不可能失败。

<details>
<summary>参考答案</summary>

错误。close 可能失败，尤其在 NFS 上。延迟的写错误可能在 close 时才报告。

</details>

**题目 3（踩坑）：** 以下代码有什么问题？
```c
int fd = open("f.txt", O_RDONLY);
if (read(fd, buf, n) < 0)
    return -1;
close(fd);
```

<details>
<summary>参考答案</summary>

read 失败时直接 return，没有 close(fd)，导致 fd 泄漏。应改为 goto cleanup 或在 return 前 close。

</details>

**题目 4（应用）：** 写一个安全的文件读取函数，确保所有路径都关闭 fd。

<details>
<summary>参考答案</summary>

```c
int read_file(const char *path, char *buf, size_t n) {
    int fd = open(path, O_RDONLY);
    if (fd < 0) return -1;
    ssize_t r = read(fd, buf, n);
    close(fd);
    return (r < 0) ? -1 : r;
}
```

</details>
