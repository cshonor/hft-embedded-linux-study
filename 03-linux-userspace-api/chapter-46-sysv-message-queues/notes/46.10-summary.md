# 46.10 Summary

> 本章：[TLPI 第 46 章](../README.md)

## 本节讲什么

第 46 章总结：System V 消息队列的完整 API、使用模式和局限性。

## 要点

### API 总览

| API | 用途 |
|-----|------|
| `ftok()` | 生成 IPC key |
| `msgget()` | 创建/打开消息队列 |
| `msgsnd()` | 发送消息 |
| `msgrcv()` | 接收消息 |
| `msgctl(IPC_RMID)` | 删除队列 |
| `msgctl(IPC_STAT)` | 获取队列信息 |
| `msgctl(IPC_SET)` | 修改队列属性 |
| `ipcs -q` | 查看系统队列 |
| `ipcrm -q` | 删除队列 |

### 消息结构

```c
struct my_msg {
    long mtype;    /* 消息类型（>0，用于筛选） */
    char mtext[1]; /* 消息体（变长） */
};
```

### msgrcv 筛选模式

| mtype 参数 | 行为 |
|------------|------|
| 0 | 接收第一条消息 |
| > 0 | 接收 mtype 等于此值的第一条 |
| < 0 | 接收 mtype <= |mtype| 的最小 mtype 消息 |

### 关键标志

| 标志 | 函数 | 效果 |
|------|------|------|
| `IPC_CREAT` | msgget | 创建队列 |
| `IPC_EXCL` | msgget | 独占创建 |
| `IPC_NOWAIT` | msgsnd/msgrcv | 非阻塞 |
| `MSG_NOERROR` | msgrcv | 截断而非错误 |

### 生命周期

```
msgget(IPC_CREAT) → 创建
  ↓
msgsnd() → 发送消息
  ↓
msgrcv() → 接收消息
  ↓
msgctl(IPC_RMID) → 删除
```

**注意**：进程退出后队列和消息仍存在，直到 IPC_RMID 或系统重启。

### 主要缺陷

1. 消息大小受 MSGMAX 限制
2. 不支持 epoll/select
3. 无超时控制
4. IPC 资源泄漏（进程退出不清理）
5. 性能不如 POSIX MQ/pipe/socket

### 推荐替代

| 场景 | 推荐 |
|------|------|
| 进程间消息 | POSIX MQ / socketpair |
| 低延迟通信 | 共享内存 + eventfd |
| 异步通知 | eventfd + epoll |

## HFT / 嵌入式关联

- HFT 通信优先使用 POSIX MQ 或 socket
- 共享内存 + eventfd 实现极低延迟
- 遗留系统维护：`ipcs -q` 监控，`ipcrm -q` 清理

## 代码自测

<details>
<summary>SysV 消息队列的 mtype 为负值时 msgrcv 的行为是什么？</summary>

`msgrcv` 的 `msgtyp` 参数为负值时，读取队列中 mtype **小于或等于** |msgtyp| 的消息中 **mtype 最小的**那一条。例如 msgtyp=-3，会读取 mtype <= 3 的消息中 mtype 最小的。这可以实现"读取优先级 <= N 的最高优先级消息"的语义。注意 mtype 始终为正（0 不可用），负 msgtyp 的绝对值是上限。

</details>
