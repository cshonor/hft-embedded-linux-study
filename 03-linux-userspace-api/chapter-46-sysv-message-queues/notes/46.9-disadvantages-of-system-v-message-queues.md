# 46.9 Disadvantages of System V Message Queues

> 本章：[TLPI 第 46 章](../README.md)

## 本节讲什么

System V 消息队列的设计缺陷和局限性，以及为什么现代应用应优先考虑 POSIX 消息队列、管道、socket 或其他 IPC 机制。

## 要点

### 主要缺点

| 缺点 | 说明 |
|------|------|
| 消息大小限制 | 受 MSGMAX 限制（通常 8KB） |
| 无超时控制 | msgrcv 不支持超时等待 |
| 队列持久性 | 进程退出后消息残留，需手动清理 |
| 无优先级 | mtype 虽可排序但非真正优先级 |
| 无异步通知 | 不能像 POSIX MQ 那样通知消息到达 |
| 内核限制多 | MSGMNI/MSGMNB/MSGMAX 系统级限制 |
| 不支持 epoll/select | 消息队列 fd 不可用于 I/O 多路复用 |
| 复杂数据类型 | 消息体需自定义序列化 |

### 无 I/O 多路复用

```c
/* 以下不工作！消息队列 ID 不是文件描述符 */
int msqid = msgget(...);
/* epoll_ctl(epfd, EPOLL_CTL_ADD, msqid, ...);  ← 不可用 */
/* select(&msqid); ← 不可用 */
```

必须单独创建线程或 `fork` 来等待消息。

### vs POSIX 消息队列

| 特性 | SysV MQ | POSIX MQ |
|------|---------|----------|
| API | 复杂（semid_ds + msgctl） | 简洁（mq_open/send/recv） |
| 大小限制 | MSGMAX（~8KB） | 可配置（mq_msgsize） |
| 超时等待 | 不支持 | `mq_timedreceive` |
| 优先级 | mtype（有限） | `mq_prio` |
| 异步通知 | 无 | `mq_notify`（信号/线程） |
| I/O 复用 | 不支持 | Linux: `mq_getattr` + 特殊 fd |
| 生命周期 | 内核持久 | 取决于 unlink |
| 消息边界 | 有 | 有 |

### vs 管道/socket

| 特性 | SysV MQ | pipe | socketpair |
|------|---------|------|------------|
| 消息边界 | 有 | 无（流） | 可选 |
| I/O 多路复用 | 不支持 | 支持 | 支持 |
| 优先级 | mtype | 无 | 无 |
| 超时 | 无 | SO_RCVTIMEO | SO_RCVTIMEO |
| 性能 | 中 | 高 | 高 |
| 适用 | 进程间消息 | 流式数据 | 双向通信 |

### 推荐替代方案

| 场景 | 推荐 |
|------|------|
| 进程间消息传递 | POSIX 消息队列 / socketpair |
| 同主机流式数据 | pipe / socket |
| 异步通知 | eventfd + epoll |
| 低延迟通信 | 共享内存 + 信号量 |
| 跨主机通信 | TCP/UDP socket |

## HFT / 嵌入式关联

- HFT 新开发避免 SysV MQ，使用 POSIX MQ 或 socketpair
- 共享内存 + eventfd 实现极低延迟通信
- 嵌入式维护遗留系统：定期 `ipcs -q` 清理残留队列

## 代码示例

```bash
#!/bin/bash
# SysV MQ 清理脚本

# 查看残留队列
echo "=== Message Queues ==="
ipcs -q

# 清理所有无主队列
ipcs -q | awk 'NR>3 && $3 != "root" {print $2}' | \
while read qid; do
    echo "Removing queue $qid..."
    ipcrm -q "$qid"
done
```

### POSIX MQ 替代示例

```c
/* 替代 SysV MQ 的 POSIX MQ 版本 */
#include <mqueue.h>

/* 创建/打开消息队列 */
mqd_t mqd = mq_open("/hft_orders",
    O_CREAT | O_RDWR, 0644, NULL);

/* 发送消息（支持优先级） */
mq_send(mqd, data, len, prio);

/* 带超时接收 */
struct timespec ts = {.tv_sec = time(NULL) + 5};
mq_timedreceive(mqd, buf, size, &prio, &ts);

/* 关闭和删除 */
mq_close(mqd);
mq_unlink("/hft_orders");
```

## 代码自测

<details>
<summary>为什么 SysV 消息队列不能用于 epoll/select 多路复用？</summary>

SysV 消息队列返回的是 IPC ID（整数），不是文件描述符。epoll 和 select 只能操作文件描述符。Linux 不提供将 IPC ID 转换为 fd 的接口（不像 POSIX MQ 可以获取 fd）。因此使用 SysV MQ 时必须单独线程阻塞等待消息，无法与其他 I/O 事件统一管理。POSIX MQ 在某些 Linux 版本上支持获取 fd 用于 epoll。

</details>
