### 练习 1：消息队列优先级

**题目**：使用 mtype 实现优先级消息队列。优先级 1 为最高，5 为最低。发送多条不同优先级消息，验证接收顺序。

<details>
<summary>参考答案</summary>

```c
#include <sys/msg.h>
#include <string.h>
#include <stdio.h>

typedef struct { long mtype; char text[64]; } msg_t;

int main() {
    int msqid = msgget(IPC_PRIVATE, IPC_CREAT | 0666);

    /* 按非优先级顺序发送 */
    msg_t m;
    m.mtype = 3; strcpy(m.text, "normal");
    msgsnd(msqid, &m, sizeof(m.text), 0);

    m.mtype = 1; strcpy(m.text, "urgent!");
    msgsnd(msqid, &m, sizeof(m.text), 0);

    m.mtype = 5; strcpy(m.text, "low");
    msgsnd(msqid, &m, sizeof(m.text), 0);

    m.mtype = 1; strcpy(m.text, "urgent2");
    msgsnd(msqid, &m, sizeof(m.text), 0);

    /* 用负 mtype 读取：mtype <= N 的最小 mtype */
    /* msgrcv(msgtyp=-1) → mtype <= 1 的最小 → 读取 mtype=1 */
    while (msgrcv(msqid, &m, sizeof(m.text), -1, IPC_NOWAIT) != -1) {
        printf("pri=%ld: %s\n", m.mtype, m.text);
    }
    /* 输出:
       pri=1: urgent!
       pri=1: urgent2
       pri=3: normal
       pri=5: low
    */

    msgctl(msqid, IPC_RMID, NULL);
    return 0;
}
```

</details>

### 练习 2：安全发送大文件

**题目**：消息队列 MSGMAX 限制为 8192，如何发送 100KB 的文件？设计分块协议。

<details>
<summary>参考答案</summary>

```c
/* 协议：
 * 请求消息: mtype=1, { client_pid, cmd=GET, path }
 * 回复消息块: mtype=client_pid, { seq, total, len, data[7000] }
 * EOF 标记: seq=-1, len=0
 */

#define CHUNK_SIZE 7000  /* < MSGMAX-8192 留余量 */

typedef struct {
    long mtype;        /* 1=请求, client_pid=回复 */
    pid_t client_pid;
    int  cmd;
    char path[256];
} req_t;

typedef struct {
    long mtype;        /* client_pid */
    int  seq;
    int  total;
    int  len;
    char data[CHUNK_SIZE];
} chunk_t;

void send_file(int msqid, pid_t client_pid, const char *path) {
    int fd = open(path, O_RDONLY);
    if (fd < 0) {
        /* 发送错误块 */
        chunk_t err = { .mtype = client_pid, .seq = -1, .len = 0 };
        msgsnd(msqid, &err, sizeof(err) - sizeof(long) - sizeof(err.data), 0);
        return;
    }

    off_t size = lseek(fd, 0, SEEK_END);
    lseek(fd, 0, SEEK_SET);
    int total = (size + CHUNK_SIZE - 1) / CHUNK_SIZE;

    chunk_t chunk;
    int seq = 0;
    ssize_t n;
    while ((n = read(fd, chunk.data, CHUNK_SIZE)) > 0) {
        chunk.mtype = client_pid;
        chunk.seq = seq++;
        chunk.total = total;
        chunk.len = n;
        msgsnd(msqid, &chunk,
               sizeof(chunk) - sizeof(long) - sizeof(chunk.data) + n, 0);
    }

    /* EOF 标记 */
    chunk.mtype = client_pid;
    chunk.seq = -1;
    chunk.len = 0;
    msgsnd(msqid, &chunk,
           sizeof(chunk) - sizeof(long) - sizeof(chunk.data), 0);
    close(fd);
}
```

</details>

### 练习 3：为什么不用 SysV MQ

**题目**：列出三个不推荐在 HFT 系统中使用 SysV 消息队列的理由，并给出替代方案。

<details>
<summary>参考答案</summary>

1. **不支持 I/O 多路复用**：SysV MQ 返回 IPC ID 而非 fd，不能用于 epoll/select。HFT 交易系统需要统一管理网络、定时器、消息等事件，无法多路复用意味着需要单独线程阻塞等待。替代：socketpair 或 POSIX MQ。

2. **消息大小限制**：MSGMAX 限制（~8KB）迫使大消息分块发送，增加系统调用次数和延迟。HFT 行情快照可能数十 KB。替代：共享内存传递大数据 + eventfd 通知。

3. **无超时控制**：标准 `msgrcv` 不支持超时等待，`IPC_NOWAIT` 只能非阻塞返回。HFT 场景需要精确控制等待时间避免死锁。替代：POSIX MQ 的 `mq_timedreceive` 或 socket 的 `SO_RCVTIMEO`。

</details>
