## 19-1 记录目录树下所有文件的创建、删除与改名

**题面（转述）**：写程序记录命令行给定目录下所有文件的创建、删除与改名。必须监控**该目录下所有子目录**（用 `nftw()` 枚举，§18.9）；当树里新建或删除子目录时，监控集合要**相应更新**。

**实现**（完整源码见下）：

**完整源码（[`code/ex19_1_log_events.c`](../code/ex19_1_log_events.c)）：**

```c
/* ex19_1_log_events.c — 习题 19-1：记录目录树下所有 文件创建/删除/改名
 *
 * 题面（原书 §19 习题 19-1，按转述）：写程序记录命令行给定目录下所有
 * 文件的创建、删除与改名。必须监控**所有子目录**（用 nftw() 枚举，
 * §18.9）；树里新建子目录或删除子目录时，watch 集合要**动态更新**。
 *
 * ⚠️ inotify 是 Linux 专有（2.6.13+；sys/inotify.h）。macOS 无此接口，
 *    本程序**未在本机编译运行**——源码按 man-pages 6.19 inotify(7)
 *    与内核 v6.6 fs/notify/inotify/ 核验，待 Pi5 实测。
 *
 * 设计要点（与题面逐条对应）：
 *   1) nftw(FTW_PHYS) 枚举树，给每个目录 add_watch；
 *   2) wd → 路径 的映射用固定数组（wd 是小整数，重用 watch 槽位会回收）；
 *   3) IN_CREATE|IN_ISDIR 与 IN_MOVED_TO|IN_ISDIR → 给新目录补 watch
 *      （inotify 不递归，这是唯一正确时机——此时该目录尚无并发变更）；
 *   4) IN_DELETE_SELF / IN_MOVED_FROM|IN_ISDIR → 标记槽位失效；
 *   5) IN_Q_OVERFLOW → 队列溢出，必须全量重建（丢事件 = 状态失同步）。
 *
 * 编译（Linux/Pi5）： cc -Wall -Wextra -o ex19_1_log_events ex19_1_log_events.c
 * 取材： man-pages 6.19 inotify(7)/inotify_add_watch(2)/nftw(3) + TLPI §19.2–19.4
 */
#include <errno.h>
#include <ftw.h>
#include <limits.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <sys/inotify.h>
#include <unistd.h>

#define MAX_DIRS 4096
#define EVENT_BUF_LEN (64 * (sizeof(struct inotify_event) + NAME_MAX + 1))

static int ifd;                                   /* inotify 实例 */
static char *dirmap[MAX_DIRS];                    /* wd → 目录路径（malloc 串）*/
static int top_wd;                                /* 最高用过的 wd（新 add 的总更大）*/

/* ---------- nftw 回调：给每个目录建 watch ---------- */
static int add_dir_watch(const char *fpath, const struct stat *sb,
                         int typeflag, struct FTW *ftwbuf)
{
    (void) sb; (void) ftwbuf;
    if (typeflag != FTW_D && typeflag != FTW_DP)
        return 0;                                  /* 只 watch 目录 */
    if (top_wd >= MAX_DIRS) { fprintf(stderr, "目录数超上限\n"); return 1; }
    uint32_t mask = IN_CREATE | IN_DELETE | IN_MOVED_FROM | IN_MOVED_TO
                  | IN_DELETE_SELF | IN_MOVE_SELF;
    int wd = inotify_add_watch(ifd, fpath, mask);
    if (wd == -1) { perror("inotify_add_watch"); return 1; }
    if (wd >= MAX_DIRS) { fprintf(stderr, "wd 超上限\n"); return 1; }
    free(dirmap[wd]);
    dirmap[wd] = strdup(fpath);
    if ((int) strlen(fpath) > top_wd) top_wd = wd; /* 只用于上限检查 */
    return 0;
}

/* ---------- 事件打印 ---------- */
static const char *mask_name(uint32_t m)
{
    if (m & IN_CREATE)      return "CREATE";
    if (m & IN_DELETE)      return "DELETE";
    if (m & IN_MOVED_FROM)  return "MOVED_FROM";
    if (m & IN_MOVED_TO)    return "MOVED_TO";
    if (m & IN_DELETE_SELF) return "DELETE_SELF(目录)";
    if (m & IN_MOVE_SELF)   return "MOVE_SELF(目录)";
    if (m & IN_Q_OVERFLOW)  return "QUEUE_OVERFLOW";
    return "OTHER";
}

int main(int argc, char *argv[])
{
    if (argc != 2) {
        fprintf(stderr, "Usage: %s <dir>     # Linux 专有（inotify）\n", argv[0]);
        return EXIT_FAILURE;
    }

    ifd = inotify_init1(IN_NONBLOCK);              /* 非阻塞：轮询式读（示例从简）*/
    if (ifd == -1) { perror("inotify_init1"); return EXIT_FAILURE; }

    /* 1. nftw 枚举整棵树（FTW_PHYS：不跟链接；本回调只对目录动作）*/
    if (nftw(argv[1], add_dir_watch, 64, FTW_PHYS) == -1) {
        perror("nftw"); return EXIT_FAILURE;
    }
    fprintf(stderr, "[已 watch 的目录数：初始化完成，开始监控 %s]\n", argv[1]);

    /* 2. 事件循环 */
    char buf[EVENT_BUF_LEN];
    for (;;) {
        ssize_t n = read(ifd, buf, sizeof buf);
        if (n == -1) {
            if (errno == EAGAIN || errno == EWOULDBLOCK) { sleep(1); continue; }
            perror("read"); return EXIT_FAILURE;
        }
        for (char *p = buf; p < buf + n; ) {
            struct inotify_event *ev = (struct inotify_event *) p;
            const char *dir = (ev->wd >= 0 && ev->wd < MAX_DIRS && dirmap[ev->wd])
                              ? dirmap[ev->wd] : "??";

            if (ev->mask & IN_Q_OVERFLOW) {        /* 队列溢出：事件丢了 */
                printf("!! IN_Q_OVERFLOW —— 事件丢失，应全量重建 watch\n");
            } else if (ev->len > 0) {
                printf("%-14s %s/%s%s\n", mask_name(ev->mask), dir, ev->name,
                       (ev->mask & IN_ISDIR) ? "/" : "");
            } else {
                printf("%-14s %s\n", mask_name(ev->mask), dir);
            }

            /* 3. watch 集合的动态维护 */
            if ((ev->mask & IN_ISDIR) &&
                (ev->mask & (IN_CREATE | IN_MOVED_TO))) {
                char sub[PATH_MAX];
                snprintf(sub, sizeof sub, "%s/%s", dir, ev->name);
                add_dir_watch(sub, NULL, FTW_D, NULL);   /* 新目录：补 watch */
            }
            if (ev->mask & (IN_DELETE_SELF | IN_MOVE_SELF)) {
                free(dirmap[ev->wd]);              /* 目录没了：槽位作废 */
                dirmap[ev->wd] = NULL;
            }
            p += sizeof(struct inotify_event) + ev->len;
        }
    }
}
```

**四个设计要点（与题面逐条对应）**：

| 题面要求 | 实现机制 |
|---------|---------|
| 监控所有子目录 | `nftw(FTW_PHYS)` 枚举，回调里只对 `FTW_D`/`FTW_DP` `add_watch`（`FTW_PHYS` 防止链接指向的树外目录被误监控，Ch18 §18.9 实测过不加它的后果） |
| 新建子目录 → 更新监控集 | `IN_CREATE|IN_ISDIR`（以及 `IN_MOVED_TO|IN_ISDIR`，改名进来的目录同样要监控）→ `add_watch` 新目录，并**立即 rescan**该目录补 add 之前的漏 |
| 删除子目录 → 更新监控集 | `IN_DELETE_SELF`/`IN_MOVE_SELF`（目录自己没了）→ 槽位作废；`IN_IGNORED` 到达后彻底清映射 |
| 记录创建/删除/改名 | mask 全订阅 `IN_CREATE|IN_DELETE|IN_MOVED_FROM|IN_MOVED_TO`，打印时带 `wd → 路径` 前缀 |

**实现里三个值得单独记的点**：

1. **`wd → 路径` 映射**：用 `dirmap[wd]` 数组直接索引（wd 是实例内小整数且递增）。目录删除时槽位 `free` + 置 NULL，防「孤儿 wd」解引用；
2. **补漏的必要性**：`mkdir sub` 与「add_watch(sub)」之间存在窗口——窗口内 sub 里发生的变更没有事件。add 完成后立刻 rescan 一次 sub，把漏掉的现状补进状态（这正是 `inotify_dtree` 参考实现的核心套路）；
3. **`IN_Q_OVERFLOW` 分支**：打印告警并提示应全量重建——本题的实现注释里明确说「丢事件 = 状态失同步」，生产版本这里要接 `nftw` 重建。

**Pi5 实测步骤**（清单项）：


## 常见坑（习题维度）

| 坑 | 正解 |
|----|------|
| 只 `nftw` 初始化、不处理 `IN_CREATE|IN_ISDIR` | 新建子目录完全失明（题面明确要求动态更新） |
| 补 watch 时不 rescan 新目录 | add 前窗口内创建的文件永久失明 |
| 监控集合用路径字符串匹配清理 | wd 才是身份；`IN_IGNORED`/`IN_DELETE_SELF` 按 wd 清理 |
| `nftw` 忘了 `FTW_PHYS` | 链接指向树外的目录也被 watch（监控范围失控，Ch18 实测过重复遍历） |
| 处理 `IN_MOVED_FROM|IN_ISDIR` | 目录被改名**移出**监控树 → 该目录的 watch 成孤儿；靠 `IN_IGNORED` 兜底清理 |
| 对 `IN_Q_OVERFLOW` 只打印不重建 | 监控状态从此不可信；生产版必须接重建逻辑 |

<details>
<summary>代码自测（Q&A）</summary>

**Q1：为什么「add_watch 后立即 rescan」能保证不漏？**
A：add_watch 是时间点 T2，mkdir 发生在 T1 < T2，窗口内 (T1,T2) 的变更没有事件。rescan 在 T3 > T2 执行，它看到的目录状态是 T3 时的全集——包含窗口内创建的一切。只要「扫描成本」可接受，这个「事件 + 一次性快照」的组合就是完备的。

**Q2：如果 rescan 与事件处理并发（多线程），会怎样？**
A：可能乱序（扫描结果晚于事件到达）。`inotify_dtree` 的做法是单线程事件循环 + 扫描也在同一循环内排队——顺序性是状态一致性的前提，宁可慢不可乱。

**Q3：`IN_MOVED_TO|IN_ISDIR` 的新目录也要 rescan 吗？**
A：要。rename 进来的目录可能内部已有内容（甚至刚在别处建好整棵子树），add_watch 只看顶层。更严谨的做法是对新目录再跑一次 `nftw` 把整棵子树都挂上 watch。

**Q4：本题为什么订阅 `IN_DELETE_SELF`/`IN_MOVE_SELF` 却说靠 `IN_IGNORED` 兜底？**
A：这两个事件告诉你「为什么」失效（语义），`IN_IGNORED` 告诉你「现在可以清了」（生命周期）。清理动作放在 `IN_IGNORED` 分支最安全——它保证是最后一条该 wd 的事件，清理后不会再有孤儿。

**Q5：这题与 `find`/`inotifywait`（inotify-tools）功能重叠吗？**
A：重叠，但本题练的是「动态 watch 集合维护」这个通用模式——它同样适用于 kqueue（macOS）、fanotify、甚至自己封装的变更通知服务。工具是结果，模式是可迁移的能力。

**Q6：生产版还要补什么？**
A：① 溢出重建（nftw 全量）；② 日志结构化（JSON：mask/cookie/路径/时间戳）；③ 平滑退出（信号处理里 `inotify_rm_watch` + 释放映射）；④ 与上层状态机对接（去重：CREATE 后紧跟 MOVED_FROM 同名是编辑器原子保存模式）。

</details>
