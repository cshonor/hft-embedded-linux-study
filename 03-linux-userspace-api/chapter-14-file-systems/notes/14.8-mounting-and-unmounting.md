## 本节讲什么

挂载与卸载是「谁能改文件系统命名空间」这件事的入口，所以它**天生是特权操作**。这一节钉四件事：

1. **API 形状**：`mount(2)` 五参数、`umount(2)`/`umount2(2)` 两/三参数，以及 `MS_*` 那套标志位。
2. **本容器里所有 `mount()`/`umount2()` 都必然 `EPERM(1)`** —— 因为 `CapEff` 全 0（没有 `CAP_SYS_ADMIN`）。但**失败顺序**本身有教学价值（见第 5 节）。
3. **四套位值不要混**：`MS_*`（uapi 入参）/ `MNT_*`（内核 per-mount）/ `ST_*`（statfs）/ `MOUNT_ATTR_*`（`mount_setattr`）。
4. **原书示例怎么跑**：`t_mount.c`（Listing 14-1, p.268）与 `t_umount.c` 在本容器里只能拿到**错误路径** —— 但错误路径正是「别把 `errExit` 当成功」的教材。

## 1. `mount(2)`：14.8.1

```c
#include <sys/mount.h>

int mount(const char *source, const char *target,
          const char *fstype, unsigned long mountflags,
          const void *data);
```

| 参数 | 含义 | 常见坑 |
|------|------|--------|
| `source` | 设备路径 / `"none"` / `NULL` | **bind mount 时忽略**；`tmpfs` 惯例写 `"none"` |
| `target` | 挂载点（必须是**已存在的目录**） | 不存在 → `ENOENT(2)`（本机实测，见第 5 节） |
| `fstype` | 文件系统类型字符串（`"ext4"`/`"tmpfs"`/`"overlay"`…） | 内核用它查 `file_system_type` 表；**权限检查排在这一步之前**（本机实测） |
| `mountflags` | `MS_*` 位组合 | 见第 4 节的常量表 |
| `data` | 文件系统私有选项字符串（`"size=20480k,nr_inodes=100"`） | 各文件系统自己解析，`mount(8)` 只是搬运工 |

返回值：`0` 成功，`-1` 失败并设 `errno`。

### `MS_REMOUNT`：不卸载改选项

`mount(source, target, NULL, MS_REMOUNT | 新标志, data)` —— 用同一个 `target` 再调一次。它**不会重新读设备**，只改**这个挂载点**的选项。`mount -o remount,rw /` 就是这条路。

### `MS_MOVE`：原子搬移

把一个挂载点整体搬到另一个位置（`mount(NULL, new, NULL, MS_MOVE, NULL)`）。是**原子**的，中间不存在「两边都看不到」的窗口 —— 这是它比「先 mount 再 umount」好的地方。

## 2. `umount(2)` / `umount2(2)`：14.8.2

```c
#include <sys/mount.h>

int umount(const char *target);
int umount2(const char *target, int flags);
```

| flag | 值（本机实测） | 语义 |
|------|---------------|------|
| `MNT_FORCE` | `1` | 强制卸载（即使还有打开的文件）。**只有部分文件系统支持**；可能丢数据 |
| `MNT_DETACH` | `2` | **懒卸载**：立刻把这个挂载点从命名空间摘掉，但已打开的引用还能继续用，等引用归零才真正释放 |
| `MNT_EXPIRE` | `4` | 「标记过期」：如果它正忙就**什么都不做**并返回 `EAGAIN`；如果已经第三次被标记就卸载。**不能与 `MNT_DETACH`/`MNT_FORCE` 同时用** |
| `UMOUNT_NOFOLLOW` | `8` | 如果 `target` 是符号链接，不要解引用（防「用符号链接骗 root 卸错地方」） |

默认（`umount(2)` 等价于 `umount2(target, 0)`）的失败条件：**还有进程打开着该文件系统上的文件、或有 cwd 在那里、或有挂载点嵌套** → `EBUSY`。

> TLPI 特别提醒：`EBUSY` 是**正常的保护机制**，不是错误。`MNT_DETACH` 就是为了绕开它而存在的（「先摘名，后释放」）。本容器因为权限全无，连 `EBUSY` 都测不到 —— 见下。

## 3. 本容器为什么必然失败：`CapEff` 全 0

<!--OUT:c14_8_mount_umount|after=① 为什么必然失败,until=② mount-->

```text
  CapPrm:	0000000000000000
  CapEff:	0000000000000000
  NoNewPrivs:	1
  CAP_SYS_ADMIN 是 bit 21（掩码 0x200000）。CapEff 全 0 ⇒ mount/umount 一律 EPERM。
```

读法：

- `/proc/self/status` 里的 `CapPrm`/`CapEff` 是**能力位掩码的十六进制**。`0000000000000000` = **一个能力都没有**。
- `CAP_SYS_ADMIN` 是 **bit 21**（掩码 `0x200000`），它是 `mount()`/`umount2()`/`pivot_root()`/`setns()` 这些操作的准入门槛。
- `NoNewPrivs: 1` 表示「**不允许通过 setuid/setgid/文件能力**获得新权限」（`PR_SET_NO_NEW_PRIVS`）。所以连「换个 setuid 程序再挂」这条路都堵死了。

> 这两个字段是**排查任何「为什么我说了不算」问题的第一站**：`cat /proc/self/status | grep -E 'Cap|NoNewPrivs'`。容器里跑特权操作失败，先看这里，再看 `errno`。

## 4. `mount(2)` 的六种调用：全失败，但失败方式不同

<!--OUT:c14_8_mount_umount|after=② mount,until=③ umount2-->

```text
  -t tmpfs none /app                 -> -1  errno= 1 (Operation not permitted)
  (NULL,NULL) MS_REC|MS_PRIVATE /    -> -1  errno= 1 (Operation not permitted)
  -t no_such_fs_type                 -> -1  errno= 1 (Operation not permitted)
  MS_BIND /tmp -> /app               -> -1  errno= 1 (Operation not permitted)
  -t tmpfs none /no/such/dir         -> -1  errno= 2 (No such file or directory)
  -t tmpfs none /proc/version        -> -1  errno= 1 (Operation not permitted)
  ↑ 注意顺序：**target 不存在** 时先报 ENOENT(2)，
    target 存在但**参数合法**时才是 EPERM(1)；
    「fstype 是假的」也报 EPERM —— 说明权限检查排在 fstype 解析之前。
```

六种调用分成了**两类失败**，这个分组本身就是信息：

| 调用 | `errno` | 说明了什么 |
|------|---------|-----------|
| `-t tmpfs none /app` | `1 EPERM` | 参数完全合法，**只差权限** |
| `(NULL,NULL) MS_REC\|MS_PRIVATE /` | `1 EPERM` | 改**挂载传播属性**也要 `CAP_SYS_ADMIN` |
| `-t no_such_fs_type` | `1 EPERM` | **fstype 是假的也报 EPERM** ⇒ 权限检查排在 fstype 解析**之前** |
| `MS_BIND /tmp -> /app` | `1 EPERM` | bind mount 同样要特权 |
| `-t tmpfs none /no/such/dir` | `2 ENOENT` | **target 不存在**的检查排在权限检查**之前** |
| `-t tmpfs none /proc/version` | `1 EPERM` | target 存在但不是目录 → 仍先撞权限门 |

**这个顺序值得记**：`mount()` 里先 `user_path_at(target, LOOKUP_FOLLOW, &path)` 拿目标路径（不存在就 `ENOENT`），再做权限检查（`may_mount()` → `ns_capable(mnt_userns, CAP_SYS_ADMIN)`），**之后**才去查 `fstype`。

**所以「本容器的 `EPERM` 什么都不能证明」这件事要反过来用**：它**证明了参数检查已经通过**。当你在一台有权限的机器上拿到 `EPERM`，要怀疑的是能力/命名空间，而不是参数拼写。

## 5. 原书示例：`t_mount.c` 与 `t_umount.c`

TLPI 的 Listing 14-1（p.268）就是 `t_mount.c`：一个把 `mountflags` 字母（`b`、`r`、`S`…）翻译成 `MS_*` 位、然后调 `mount(2)` 的小工具。

完整源码 [`code/t_mount.c`](../code/t_mount.c)：

```c
/*************************************************************************\

/* t_mount.c

   Demonstrate the use of mount(2) to create a mount point.

   Usage: as described in usageError()

   Examples:
        t_mount -t ext3 /dev/sda12 /testfs

        t_mount -t ext2 -f r -o nogrpid /dev/sda9 /mydir ext2
                (The "r" for flags specifies that the file system
                is to be mounted read-only.)

   This program is Linux-specific.
*/
#include <sys/mount.h>
#include "tlpi_hdr.h"

#ifndef MS_DIRSYNC      /* May not be defined in older glibc headers */
#define MS_DIRSYNC 128
#endif

#ifndef MS_BIND         /* May not be defined in older glibc headers */
#define MS_BIND 4096
#endif

#ifndef MS_MOVE         /* May not be defined in older glibc headers */
#define MS_MOVE 8192
#endif

#ifndef MS_REC          /* May not be defined in older glibc headers */
#define MS_REC 16384
#endif

#ifndef MS_UNBINDABLE   /* May not be defined in older glibc headers */
#define MS_UNBINDABLE (1<<17) /* change to unbindable */
#endif

#ifndef MS_PRIVATE      /* May not be defined in older glibc headers */
#define MS_PRIVATE (1<<18) /* change to private */
#endif

#ifndef MS_SLAVE        /* May not be defined in older glibc headers */
#define MS_SLAVE (1<<19) /* change to slave */
#endif

#ifndef MS_SHARED       /* May not be defined in older glibc headers */
#define MS_SHARED (1<<20) /* change to shared */
#endif

#ifndef MS_LAZYTIME
#define MS_LAZYTIME     (1<<25)
#endif

static void
usageError(const char *progName, const char *msg)
{
    if (msg != NULL)
        fprintf(stderr, "%s", msg);

    fprintf(stderr, "Usage: %s [options] source target\n\n", progName);
    fprintf(stderr, "Available options:\n");
#define fpe(str) fprintf(stderr, "    " str)    /* Shorter! */
    fpe("-t fstype        [e.g., 'ext2' or 'reiserfs']\n");
    fpe("-o data          [file system-dependent options,\n");
    fpe("                 e.g., 'bsdgroups' for ext2]\n");
    fpe("-f mountflags    can include any of:\n");
#define fpe2(str) fprintf(stderr, "            " str)
    fpe2("b - MS_BIND         create a bind mount\n");
    fpe2("d - MS_DIRSYNC      synchronous directory updates\n");
    fpe2("l - MS_MANDLOCK     permit mandatory locking\n");
    fpe2("L - MS_LAZYATIME    lazy atime updates\n");
    fpe2("m - MS_MOVE         atomically move subtree\n");
    fpe2("A - MS_NOATIME      don't update atime (last access time)\n");
    fpe2("V - MS_NODEV        don't permit device access\n");
    fpe2("D - MS_NODIRATIME   don't update atime on directories\n");
    fpe2("E - MS_NOEXEC       don't allow executables\n");
    fpe2("S - MS_NOSUID       disable set-user/group-ID programs\n");
    fpe2("p - MS_PRIVATE      mark as private\n");
    fpe2("r - MS_RDONLY       read-only mount\n");
    fpe2("c - MS_REC          recursive mount\n");
    fpe2("T - MS_RELATIME     relative atime updates\n");
    fpe2("R - MS_REMOUNT      remount\n");
    fpe2("h - MS_SHARED       mark as shared\n");
    fpe2("v - MS_SLAVE        mark as slave\n");
    fpe2("s - MS_SYNCHRONOUS  make writes synchronous\n");
    fpe2("u - MS_UNBINDABLE   mark as unbindable\n");
    exit(EXIT_FAILURE);
}

int
main(int argc, char *argv[])
{
    unsigned long flags;
    char *data, *fstype;
    int j, opt;

    flags = 0;
    data = NULL;
    fstype = NULL;

    while ((opt = getopt(argc, argv, "o:t:f:")) != -1) {
        switch (opt) {
        case 'o':
            data = optarg;
            break;

        case 't':
            fstype = optarg;
            break;

        case 'f':
            for (j = 0; j < (int) strlen(optarg); j++) {

                /* In this version of the program we support more flags than
                   in the version of the program shown in the book */

                switch (optarg[j]) {
                case 'b': flags |= MS_BIND;             break;
                case 'd': flags |= MS_DIRSYNC;          break;
                case 'l': flags |= MS_MANDLOCK;         break;
                case 'm': flags |= MS_MOVE;             break;
                case 'A': flags |= MS_NOATIME;          break;
                case 'V': flags |= MS_NODEV;            break;
                case 'D': flags |= MS_NODIRATIME;       break;
                case 'E': flags |= MS_NOEXEC;           break;
                case 'S': flags |= MS_NOSUID;           break;
                case 'p': flags |= MS_PRIVATE;          break;
                case 'r': flags |= MS_RDONLY;           break;
                case 'c': flags |= MS_REC;              break;
                case 'T': flags |= MS_RELATIME;         break;
                case 'R': flags |= MS_REMOUNT;          break;
                case 'h': flags |= MS_SHARED;           break;
                case 'v': flags |= MS_SLAVE;            break;
                case 's': flags |= MS_SYNCHRONOUS;      break;
                case 'u': flags |= MS_UNBINDABLE;       break;
                default:  usageError(argv[0], NULL);
                }
            }
            break;

        default:
            usageError(argv[0], NULL);
        }
    }

    if (argc != optind + 2)
        usageError(argv[0], "Wrong number of arguments\n");

    if (mount(argv[optind], argv[optind + 1], fstype, flags, data) == -1)
        errExit("mount");

    exit(EXIT_SUCCESS);
}
```

## 6. 四套位值：不要混

同一个「`nosuid`」在四个地方有四个不同的数值：

| 层 | 前缀 | 处所 | 例（`nosuid`） |
|----|------|------|---------------|
| `mount(2)` 入参 | `MS_*` | `include/uapi/linux/mount.h` | `MS_NOSUID = 2` |
| 内核 per-mount | `MNT_*` | `include/linux/mount.h` | `MNT_NOSUID = 0x01` |
| statfs/statvfs | `ST_*` | `include/linux/statfs.h` / glibc `bits/statvfs.h` | `ST_NOSUID = 2`（§14.11） |
| `mount_setattr` | `MOUNT_ATTR_*` | `include/uapi/linux/mount.h` | `MOUNT_ATTR_NOSUID = 0x02` |

⑤ 段把前两套并排列出来了（实际运行结果）：

<!--OUT:c14_8_mount_umount|after=⑤ MS_*-->

```text
  | 用户态 MS_*（uapi）      | 内核 mnt_flags（MNT_*） |
  | MS_NOSUID   = 2         | MNT_NOSUID   = 0x01     |
  | MS_NODEV    = 4         | MNT_NODEV    = 0x02     |
  | MS_NOEXEC   = 8         | MNT_NOEXEC   = 0x04     |
  | MS_NOATIME  = 1024      | MNT_NOATIME  = 0x08     |
  | MS_NODIRATIME= 2048     | MNT_NODIRATIME = 0x10   |
  | MS_RELATIME = 2097152   | MNT_RELATIME = 0x20     |
  | MS_RDONLY   = 1         | MNT_READONLY = 0x40     |
  值完全不同 —— 它们属于两层：MS_* 是 mount(2) 的入参编码，
  MNT_* 存在 vfsmount->mnt_flags 里，是挂载**实例**的选项。
  第三套是 statfs 的 ST_*（见 §14.11），第四套是 mount_setattr() 的 MOUNT_ATTR_*。

=== c14_8 done ===
```

**为什么会有「两套」**：`MS_*` 是**系统调用的参数编码**（用户态 → 内核的传输格式），`MNT_*` 是**内核内部 `struct vfsmount.mnt_flags` 的存储格式**。它们不是「新老版本」的关系，而是**两个不同的接口层**。混淆的后果很典型：拿 `MS_NOSUID(2)` 去 `& MNT_*` 掩码判断，会得到完全错误的结论。

④ 段给出本章用到的常量（逐字取自本机头文件，**这些值由 ABI 固定，不会变**）：

<!--OUT:c14_8_mount_umount|after=④ 本章用到,until=⑤ MS_*-->

```text
  MS_RDONLY      = 0x1        MS_NOSUID     = 0x2
  MS_NODEV       = 0x4        MS_NOEXEC    = 0x8
  MS_SYNCHRONOUS = 0x10       MS_REMOUNT   = 0x20
  MS_BIND        = 0x1000     MS_MOVE      = 0x2000
  MS_REC         = 0x4000     MS_PRIVATE   = 0x40000
  MS_SLAVE       = 0x80000    MS_SHARED    = 0x100000
  MS_RELATIME    = 0x200000   MS_LAZYTIME  = 0x2000000
  MNT_FORCE=1  MNT_DETACH=2  MNT_EXPIRE=4  UMOUNT_NOFOLLOW=8
```

## 7. 补充：原书的 overlayfs 示例是一个 **shell 脚本**

TLPI 第 14 章的补充文件里有一个 `filesys/overlayfs_example.sh`，它演示 **overlayfs**（联合文件系统）—— 这是本章唯一一个「一个挂载点上叠多个来源」的例子：

```bash
#!/bin/sh
#
# OverlayFS example

if [ $# -ne 1 ] ; then
    echo "Usage: $0 <directory-name>"
    exit 1
fi

set -e

mkdir $1
cd $1

mkdir upper lower1 lower2 work merged

echo 'From lower 1' > lower1/all_low
echo 'From lower 2' > lower2/all_low

echo 'From lower 1' > lower1/all
echo 'From lower 2' > lower2/all

echo 'From lower 2' > lower2/lower_2

echo 'From lower 1' > lower1/hidden

mkdir lower1/dir_1
touch lower1/dir_1/file

sudo mount -t overlay \
	 -o lowerdir=./lower1:./lower2,upperdir=./upper,workdir=./work \
	 overlay ./merged

echo 'Upper' >> merged/all
rm merged/hidden

# ls merged
```

**为什么这一节用 `bash` 代码块而不是 `c`**：这个文件是 **shell 脚本**（`#!/bin/sh`），它不是 C 程序、不参与编译、也不需要 `gcc`。本仓库的约定是「按文件真实语言标注围栏」—— `.sh` 用 `bash`/`sh`，`.c` 用 `c`。

这个脚本想演示的 overlayfs 语义（本容器跑不了，因为 `mount` 是 `EPERM`）：

| 操作 | 期望结果 |
|------|---------|
| `lower1/all` 与 `lower2/all` 都存在 | 合并后 `merged/all` 的内容来自 **lower1**（`lowerdir` 列表**靠前**的优先） |
| `lower2/lower_2` 只有 lower2 有 | `merged/lower_2` 可见 |
| `lower1/hidden` 只有 lower1 有 | 可见；`rm merged/hidden` 会在 upper 里生成一个 **whiteout**（把下层的同名项遮住） |
| `echo 'Upper' >> merged/all` | 触发 **copy-up**：`all` 被整体复制到 `upper/` 再追加 |
| `all_low`（两个 lower 都有、upper 没有） | 仍是 lower1 的版本 |

> 本容器里能看到的 overlayfs **实际用法**不是这个脚本，而是 `/cefs/**` 那套 `autofs + squashfs`（§14.7）—— 它是「按需挂只读镜像」，与 overlayfs 的「多层合并 + 可写上层」是两种不同的问题。

## 完整源码

完整源码 [`code/c14_8_mount_umount.c`](../code/c14_8_mount_umount.c)：

```c
/* c14_8_mount_umount.c —— TLPI §14.8 Mounting and Unmounting File Systems
 *
 *  §14.8.1 mount() / §14.8.2 umount() 与 umount2()。
 *
 *  这一节最值得实测的不是「怎么调成功」，而是**失败时的 errno 顺序**：
 *  内核在真正尝试挂载之前会先做路径查找、再做权限检查，
 *  所以「fstype 是假的」这种参数错，在无特权容器里**根本轮不到被检查**。
 *
 *  本 demo 逐条试错并报告 errno：
 *    ① 先证明自己为什么没权限：/proc/self/status 的 CapEff
 *    ② mount() 的六种调用（好参数 / 坏 fstype / 坏 target / bind / propagation）
 *    ③ umount2() 的四个 flag
 *    ④ 本章用到的 MS_* 与 MNT_* 常量（逐字取自本机头文件）
 *    ⑤ 「MS_* 是 ABI 层、MNT_* 是内核内部层」——两套位值完全不同
 *
 *  编译：gcc -O0 -Wall -Wextra -o c14_8 c14_8_mount_umount.c
 */
#define _GNU_SOURCE
#include <sys/mount.h>
#include <sys/stat.h>
#include <sys/types.h>
#include <errno.h>
#include <fcntl.h>
#include <stdio.h>
#include <string.h>
#include <unistd.h>

static void sec(const char *t)
{
    printf("\n== %s ==\n", t);
}

static void try_mount(const char *desc, const char *src, const char *tgt,
                      const char *fstype, unsigned long flags)
{
    int r;

    errno = 0;
    r = mount(src, tgt, fstype, flags, NULL);
    if (r == -1)
        printf("  %-34s -> -1  errno=%2d (%s)\n", desc, errno, strerror(errno));
    else
        printf("  %-34s ->  0  **成功**\n", desc);
}

static void try_umount2(const char *desc, const char *tgt, int flags)
{
    int r;

    errno = 0;
    r = umount2(tgt, flags);
    if (r == -1)
        printf("  %-34s -> -1  errno=%2d (%s)\n", desc, errno, strerror(errno));
    else
        printf("  %-34s ->  0  **成功**\n", desc);
}

int main(void)
{
    /* ---------- ① 能力 ---------- */
    sec("① 为什么必然失败：CapEff 里没有 CAP_SYS_ADMIN");
    {
        int fd = open("/proc/self/status", O_RDONLY);
        char buf[8192];
        ssize_t n = fd == -1 ? -1 : read(fd, buf, sizeof(buf) - 1);
        if (n > 0) {
            buf[n] = '\0';
            for (char *l = strtok(buf, "\n"); l != NULL; l = strtok(NULL, "\n"))
                if (!strncmp(l, "CapEff", 6) || !strncmp(l, "CapPrm", 6) ||
                    !strncmp(l, "NoNewPrivs", 10))
                    printf("  %s\n", l);
        }
        if (fd != -1)
            close(fd);
    }
    printf("  CAP_SYS_ADMIN 是 bit 21（掩码 0x200000）。CapEff 全 0 ⇒ mount/umount 一律 EPERM。\n");

    /* ---------- ② mount(2) ---------- */
    sec("② mount(2) 的六种调用");
    try_mount("-t tmpfs none /app", "none", "/app", "tmpfs", 0);
    try_mount("(NULL,NULL) MS_REC|MS_PRIVATE /", NULL, "/", NULL, MS_REC | MS_PRIVATE);
    try_mount("-t no_such_fs_type", "none", "/app", "no_such_fs_type", 0);
    try_mount("MS_BIND /tmp -> /app", "/tmp", "/app", NULL, MS_BIND);
    try_mount("-t tmpfs none /no/such/dir", "none", "/no/such/dir", "tmpfs", 0);
    try_mount("-t tmpfs none /proc/version", "none", "/proc/version", "tmpfs", 0);
    printf("  ↑ 注意顺序：**target 不存在** 时先报 ENOENT(2)，\n");
    printf("    target 存在但**参数合法**时才是 EPERM(1)；\n");
    printf("    「fstype 是假的」也报 EPERM —— 说明权限检查排在 fstype 解析之前。\n");

    /* ---------- ③ umount2(2) ---------- */
    sec("③ umount2(2) 的四个 flag");
    try_umount2("umount2(\"/\", 0)", "/", 0);
    try_umount2("umount2(\"/\", MNT_FORCE)", "/", MNT_FORCE);
    try_umount2("umount2(\"/\", MNT_DETACH)", "/", MNT_DETACH);
    try_umount2("umount2(\"/\", MNT_EXPIRE)", "/", MNT_EXPIRE);
    try_umount2("umount2(\"/no/such/dir\", 0)", "/no/such/dir", 0);
    try_umount2("umount2(\"/app\", 0)", "/app", 0);
    printf("  ↑ MNT_FORCE / MNT_DETACH / MNT_EXPIRE 都先撞同一道权限门，\n");
    printf("    所以无法在本容器里比较它们的语义差别（只能按 man 2 umount2 讲）。\n");

    /* ---------- ④ 常量 ---------- */
    sec("④ 本章用到的常量（逐字取自本机头文件）");
    printf("  MS_RDONLY      = %#-10lx MS_NOSUID     = %#lx\n",
           (unsigned long) MS_RDONLY, (unsigned long) MS_NOSUID);
    printf("  MS_NODEV       = %#-10lx MS_NOEXEC    = %#lx\n",
           (unsigned long) MS_NODEV, (unsigned long) MS_NOEXEC);
    printf("  MS_SYNCHRONOUS = %#-10lx MS_REMOUNT   = %#lx\n",
           (unsigned long) MS_SYNCHRONOUS, (unsigned long) MS_REMOUNT);
    printf("  MS_BIND        = %#-10lx MS_MOVE      = %#lx\n",
           (unsigned long) MS_BIND, (unsigned long) MS_MOVE);
    printf("  MS_REC         = %#-10lx MS_PRIVATE   = %#lx\n",
           (unsigned long) MS_REC, (unsigned long) MS_PRIVATE);
    printf("  MS_SLAVE       = %#-10lx MS_SHARED    = %#lx\n",
           (unsigned long) MS_SLAVE, (unsigned long) MS_SHARED);
    printf("  MS_RELATIME    = %#-10lx MS_LAZYTIME  = %#lx\n",
           (unsigned long) MS_RELATIME, (unsigned long) MS_LAZYTIME);
    printf("  MNT_FORCE=%d  MNT_DETACH=%d  MNT_EXPIRE=%d  UMOUNT_NOFOLLOW=%d\n",
           MNT_FORCE, MNT_DETACH, MNT_EXPIRE, UMOUNT_NOFOLLOW);

    /* ---------- ⑤ 两套位值 ---------- */
    sec("⑤ MS_* 与 MNT_* 是两套完全不同的位（内核内部对不上 ABI）");
    printf("  | 用户态 MS_*（uapi）      | 内核 mnt_flags（MNT_*） |\n");
    printf("  | MS_NOSUID   = %-9lu | MNT_NOSUID   = 0x01     |\n", (unsigned long) MS_NOSUID);
    printf("  | MS_NODEV    = %-9lu | MNT_NODEV    = 0x02     |\n", (unsigned long) MS_NODEV);
    printf("  | MS_NOEXEC   = %-9lu | MNT_NOEXEC   = 0x04     |\n", (unsigned long) MS_NOEXEC);
    printf("  | MS_NOATIME  = %-9lu | MNT_NOATIME  = 0x08     |\n", (unsigned long) MS_NOATIME);
    printf("  | MS_NODIRATIME= %-8lu | MNT_NODIRATIME = 0x10   |\n", (unsigned long) MS_NODIRATIME);
    printf("  | MS_RELATIME = %-9lu | MNT_RELATIME = 0x20     |\n", (unsigned long) MS_RELATIME);
    printf("  | MS_RDONLY   = %-9lu | MNT_READONLY = 0x40     |\n", (unsigned long) MS_RDONLY);
    printf("  值完全不同 —— 它们属于两层：MS_* 是 mount(2) 的入参编码，\n");
    printf("  MNT_* 存在 vfsmount->mnt_flags 里，是挂载**实例**的选项。\n");
    printf("  第三套是 statfs 的 ST_*（见 §14.11），第四套是 mount_setattr() 的 MOUNT_ATTR_*。\n");

    printf("\n=== c14_8 done ===\n");
    return 0;
}
```

## 常见坑

| # | 坑 | 正解 |
|---|----|------|
| 1 | 以为 `umount()` 失败就是「目标不存在」 | 常见第一位是 `EBUSY`（有进程打开着/有 cwd 在那儿）。本容器里第一位是 `EPERM` |
| 2 | 用 `MNT_FORCE` 当「万能强制卸载」 | 它**只有部分文件系统支持**，且可能丢数据。要「先摘名后释放」用 `MNT_DETACH` |
| 3 | 把 `MNT_EXPIRE` 当普通 flag 用 | 它的语义是「标记过期」：忙 → `EAGAIN` 且什么都不做。**不能与 `MNT_DETACH`/`MNT_FORCE` 同时用** |
| 4 | 以为 `EPERM` 说明参数错了 | `EPERM` 说明**参数已通过检查**，只差权限（第 4 节六种调用的对照） |
| 5 | 拿 `MS_NOSUID(2)` 去匹配 `MNT_NOSUID(0x01)` | 两套位值属于两层接口。见第 6 节 |
| 6 | 忘了解引用符号链接的风险 | `UMOUNT_NOFOLLOW(8)` 就是为「别被符号链接骗」准备的 |
| 7 | 以为 `mount` 能挂到任意路径 | target 必须是**已存在的目录**（文件只对 `MS_BIND` 单文件 bind 有意义）。不存在 → `ENOENT` |
| 8 | 用 `2>/dev/null` 跑原书程序然后说「没输出」 | `errExit`/`usageErr` 写的是 **stderr**。本节的实测块全部取自 stderr |
| 9 | 以为 CE 的 `output.s` 是程序名 | 那是 CE 给产物起的名字；`usageErr` 用 `argv[0]`，所以用法行会显示 `./output.s` |
| 10 | 以为容器里 `root` 就能 `mount` | 容器里 UID 0 ≠ 有 `CAP_SYS_ADMIN`。看 `/proc/self/status` 的 `CapEff` |

## HFT / 嵌入式关联

| 场景 | 结论怎么用 |
|------|-----------|
| **`mount` 只在启动时做一次** | 挂载要过能力检查 + 命名空间锁，且**不可被中断地改可见性**。HFT 里把所有挂载都放在启动/initramfs 阶段完成，热路径永不出现 `mount` |
| **`MNT_DETACH` 是「换盘」的正确工具** | 「不中断地换数据盘」= `mount` 新盘到临时点 → `mount(MS_MOVE)` 到目标（原子）→ 旧盘 `MNT_DETACH`。比 `umount` 再 `mount` 好：旧盘上已打开的文件不会被 `EBUSY` 卡住 |
| **`MS_RDONLY` 要 `MS_REMOUNT`（不能只 remount 一个位）** | `mount -o remount,rw` 有历史坑：某些内核要求 `MS_REMOUNT` 时把**原有的其他 flag 一起带上**，否则会被意外清掉。现代内核（v5.12+）改用 `mount_setattr` 才能真正「只改一个属性」 |
| **嵌入式只读 rootfs + overlay** | 典型做法：squashfs 只读下层 + tmpfs/JFFS2 可写上层，用 overlayfs 合并成 `/`。掉电只需保护上层（小分区），下层永远一致 —— 这是「掉电安全 + 可写」的标准解 |
| **`/proc/self/status` 是容器排障第一站** | 任何「明明 root 却 EPERM」的现场，先 `grep Cap /proc/self/status`。容器运行时降权（drop capabilities）是常态，不是故障 |
| **`MS_NOSUID` / `MS_NODEV` / `MS_NOEXEC` 是数据盘的标配** | HFT 上挂载纯数据分区时三个都加：`nosuid`（防提权）、`nodev`（防伪造设备节点）、`noexec`（防执行落盘的二进制）。本容器的 `/tmp` 实测就带这三个（§14.10） |
| **嵌入式 flash 的挂载选项** | JFFS2/UBIFS 上 `noatime`（或 `relatime`）能显著减少元数据写 —— 直接换算成 NAND 寿命。ext4 上 `discard`/`commit=30` 也是这类「用挂载选项换 IO 特性」的例子（§14.7 的 `/app` super opts 实测） |

<summary>代码自测（Q&A）</summary>

**Q1：本容器的 `mount()` 为什么一定失败？**

A：因为 `/proc/self/status` 里 `CapPrm = CapEff = 0`，而 `mount()` 要求 `CAP_SYS_ADMIN`（bit 21，掩码 `0x200000`）。同时 `NoNewPrivs: 1` 封死了「靠 setuid/文件能力提权」的路。所以无论参数怎么拼，都是 `EPERM(1)`。

**Q2：既然全失败，这个 demo 还有什么信息量？**

A：**失败顺序**。本机实测：target 不存在 → `ENOENT(2)`；target 存在（哪怕是 `/proc/version` 这种非目录）→ `EPERM(1)`；**fstype 是假的**→ 还是 `EPERM(1)`。这证明内核的顺序是「先解析 target → 再查权限 → 最后才看 fstype」。所以「`EPERM` 说明参数是对的」这条推论是可以用的。

**Q3：`MNT_DETACH` 与 `MNT_FORCE` 的差别？**

A：`MNT_FORCE` 是**要求文件系统立刻放弃**（即使还有打开的文件），只有部分文件系统支持，可能丢数据。`MNT_DETACH` 是**懒卸载**：立刻把挂载点从命名空间摘掉（新路径看不见了），但已打开的引用可以继续用，等引用归零内核再真正释放。本容器两个都测不了（都是 `EPERM`），差别只能按 `man 2 umount2` 讲。

**Q4：为什么 `MS_NOSUID = 2` 而 `MNT_NOSUID = 0x01`？**

A：因为它们属于**两个不同的接口层**。`MS_*` 是 `mount(2)` 的入参编码（用户态传进内核的格式，定义在 `include/uapi/linux/mount.h`）；`MNT_*` 是内核对「这个挂载实例的选项」的存储格式（`struct vfsmount.mnt_flags`，定义在 `include/linux/mount.h`）。内核收到 `MS_*` 后会把它们**翻译**成 `MNT_*` 存起来。

**Q5：原书程序的输出为什么在 stderr？**

A：因为它们用 `errExit()`/`usageErr()` 报错，而 TLPI 的错误处理函数（`lib/error_functions.c`）写的是 **`stderr`**。这是「错误信息不该混进正常输出」的通用做法 —— 所以想用 `>` 重定向抓它们是没有用的，得用 `2>`。

**Q6：`overlayfs_example.sh` 为什么用 `bash` 代码块？**

A：因为它是 **shell 脚本**（`#!/bin/sh`），不是 C 程序。本仓库约定围栏标注要跟文件真实语言一致：`.c` 用 `c`、`.sh` 用 `bash`/`sh`。混用会让人误以为这段要 `gcc` 编译。

**Q7：`mount -o remount,rw /` 有什么坑？**

A：`MS_REMOUNT` 在传统 ABI 里是**整体替换**该挂载点的 `MS_*` 集合，所以只传 `MS_RDONLY` 想「加个只读」可能把别的标志一起清掉（历史上 `mount(8)` 为此需要读 `/etc/mtab` 拼齐原标志）。v5.12 起有了 `mount_setattr(2)` + `MOUNT_ATTR_*`，才真正支持「只改一个属性的某个位」，这也是四套位值里最新那套存在的原因。

</details>
