## 要点

```c
#include <sys/mount.h>
int mount(const char *source, const char *target,
          const char *fstype, unsigned long mountflags,
          const void *data);
int umount(const char *target);
int umount2(const char *target, int flags);
```

### 常用 `mountflags`

| 标志 | 含义 |
|------|------|
| `MS_RDONLY` | 只读 |
| `MS_NOEXEC` | 禁止执行 |
| `MS_NOSUID` | 忽略 setuid/setgid |
| `MS_REMOUNT` | 改挂载选项（不卸） |
| `MS_BIND` | 绑定挂载（目录树镜像） |

### `umount2`

| 标志 | 含义 |
|------|------|
| `MNT_FORCE` | 强制；忙时慎用，易丢数据 |
| `MNT_DETACH` | 懒卸载：已打开可继续，引用尽再真正卸 |

默认：仍有打开文件、或 cwd 在该 FS 上 → `umount` 失败（`EBUSY`）。

Demo（需 root）：[`code/mount_bind_demo.c`](./code/mount_bind_demo.c)

## 与 C 语言学习的关系

`exec` 家族与 `fork` 配合是 Unix 进程模型的基石。C 语言的 `main` 函数参数 `argc/argv` 在 `exec` 时传入。理解 `execvp` 如何搜索 PATH 需要理解 C 字符串数组和 NULL 终止约定。

## 常见陷阱

1. **fd 泄漏到 exec**

```c
int fd = open(...);
execvp(prog, argv);  /* fd 仍然打开 */
```

默认情况下 exec 后 fd 仍然打开。设 FD_CLOEXEC 或用 O_CLOEXEC 防止泄漏。

2. **exec 后代码继续执行**

```c
execvp(prog, argv);
printf("这里会执行吗?");  /* 会! exec 失败时 */
```

exec 成功时不返回，当前进程映像被替换。只有 exec 失败时才返回 -1。必须检查返回值。

3. **PATH 搜索差异**

```c
execlp("ls", "ls", NULL);   /* 搜索 PATH */
execl("/bin/ls", "ls", NULL);  /* 不搜索 PATH */
```

execlp/execvp 搜索 PATH，execl/execv 不搜索。用错可能找不到程序。

## 自测题

**题目 1（选择）：** `exec` 成功后会发生什么？
A. 创建新进程
B. 替换当前进程映像
C. 返回旧进程
D. 什么也不发生

<details>
<summary>参考答案</summary>

B。exec 用新程序替换当前进程映像。PID 不变，代码段/数据段/堆栈被替换。成功时不返回。

</details>

**题目 2（判断）：** `exec` 失败时返回 -1，原程序继续执行。

<details>
<summary>参考答案</summary>

正确。exec 失败时返回 -1，当前进程映像不变，代码继续执行。成功时不返回。

</details>

**题目 3（踩坑）：** 以下代码有什么问题？
```c
execvp("ls", args);
perror("exec failed");
```

<details>
<summary>参考答案</summary>

没有检查 execvp 返回值。应该：
`if (execvp("ls", args) < 0) { perror("exec"); exit(1); }`
perror 本身没问题，但应该配合 exit 确保失败后退出。

</details>

**题目 4（应用）：** 写代码：fork + exec 执行 `ls -l`，父进程等待子进程结束。

<details>
<summary>参考答案</summary>

```c
pid_t pid = fork();
if (pid == 0) {
    execlp("ls", "ls", "-l", NULL);
    perror("exec"); exit(1);
}
wait(NULL);
```

</details>
