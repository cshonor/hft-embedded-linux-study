## 本节讲什么

TLPI 这一节列了五个「高级」特性。本容器的麻烦是：**这五个特性全都需要 `CAP_SYS_ADMIN`，一个都做不了**（§14.8 已证明 `CapEff` 全 0）。

所以本节的策略是**反过来**：不去「造」这些挂载，而是**在一张已经存在的挂载表里把它们一一认出来**。这张表是 CE 容器自己的 —— 它恰好把五个特性全用上了。

| 子节 | 特性 | 本容器怎么认出来 |
|------|------|----------------|
| 14.9.1 | 一个 FS 挂到多个挂载点 | 数 `mountinfo` 里同一个 `major:minor` 出现几次（② 段） |
| 14.9.2 | 同一挂载点上叠多层 | `mount ID`/`parent ID` 的父子链 + `master:N`（①、②） |
| 14.9.3 | per-mount 选项 vs super 选项 | `mountinfo` 里的 **两栏**（④ 段） |
| 14.9.4 | bind mount | `root != /`（③ 段） |
| 14.9.5 | 递归 bind mount | `MS_BIND\|MS_REC` —— 本机只能证明它同样被权限挡住（⑤ 段） |

> ⚠️ **本轮实测里 `mountinfo` 共 66 条**（`c14_9`）/ **65 个挂载点**（`c14_7`）—— 两个作业**不是同一台宿主**，所以数字不同。**跨作业比较挂载点数量没有意义**（§14.2 的「环境会变」）。

### 14.9.1 Mounting a File System at Multiple Mount Points

同一文件系统可以被挂到多个挂载点。用户态的指纹就是「**同一个 `major:minor` 出现多次**」：

<!--OUT:c14_9_advanced_mount|after=② 14.9.1,until=③ 14.9.4-->

```text
  202:1      10 次：/lib /usr/lib /usr/share/zoneinfo /etc/localtime /lib64 /lib32 /usr/bin/stdbuf /usr/libexec/coreutils/libstdbuf.so /usr/local/bin/dumb-init /app
  0:51        2 次：/etc/passwd /etc/shadow
  0:7         4 次：/dev/null /dev/zero /dev/random /dev/urandom
```

三个分组各有含义：

| 设备号 | 次数 | 是什么 |
|--------|-----|--------|
| `202:1` | **10** | 同一个 ext4 超级块被投到 10 个路径。这是「根文件系统被拆散挂进容器」的典型形态 |
| `0:51` | 2 | `/etc/passwd` / `/etc/shadow`（两个**内容不同**的单文件 bind，同属一个 tmpfs 超级块） |
| `0:7` | 4 | `/dev/null`、`/dev/zero`、`/dev/random`、`/dev/urandom`（同一个 devtmpfs） |

**怎么和 bind mount 区分？** 同一设备出现多次**不一定**是 bind（`mount /dev/sda1 /mnt/a; mount /dev/sda1 /mnt/b` 也会这样）。要判 bind，看 `root`（14.9.4）。

**工程意义**：这是「同一个超级块的所有挂载点共享页缓存与 inode 缓存」的直接后果。所以 `/lib` 与 `/usr/lib` 同时被读时**不会有第二份页缓存** —— 这对内存敏感的容器/嵌入式很重要。

### 14.9.2 Stacking Multiple Mounts on the Same Mount Point

TLPI 讲的「叠加」有两种读法，别混：

| 形态 | 含义 | 识别方式 |
|------|------|---------|
| **同一个挂载点上叠多层** | 后挂的遮住先挂的；卸载最上面一层，下面就露出来 | 两条记录**挂载点相同**、`parent ID` 指向前一条的 `mount ID` |
| **挂载树上的父子关系** | 一个挂载点位于另一个挂载点内部（如 `/cefs` 里挂 `/cefs/bb`） | `parent ID` 链条 |

`mountinfo` 的 **`mount ID` / `parent ID` 两列**就是为还原这棵树而存在的 —— 这也是 `findmnt` 能画出树形输出的原因（`/proc/mounts` 里没有这两列，画不出来）。

本容器里 `/cefs` → `/cefs/bb` → `/cefs/bb/bb69...` 就是三层的父链（`autofs` 目录里按需挂 `squashfs`）。

### 14.9.3 Mount Flags That Are Per-Mount Options

这条最容易讲错，但 `mountinfo` 里**两栏并排**放着，一眼可辨：

<!--OUT:c14_9_advanced_mount|after=④ 14.9.3-->

```text
  /        per-mount = ro,relatime                       
           super     = rw,uid=113,gid=113,inode64
  /tmp     per-mount = rw,nosuid,nodev,noexec,relatime   
           super     = rw,size=20480k,nr_inodes=100,uid=113,gid=113,inode64
  /app     per-mount = rw,relatime                       
           super     = rw,discard,errors=remount-ro,commit=30
  ↑ per-mount 栏里的 nosuid/nodev/noexec 是**这一个挂载点**的选项；
    super 栏里的 rw/size=/nr_inodes= 是**整个超级块**的属性。
    同一个超级块可以被挂成多个挂载点、各自给不同的 per-mount 选项 ——
    这正是为什么 MS_* 需要拆成 MS_* (ABI) 和 MNT_* (per-mount) 两套。

== ⑤ 试一次 bind mount（预期被挡住） ==
  mount("/tmp", "/app", NULL, MS_BIND, NULL) -> -1 errno=1 (Operation not permitted)
  mount(..., MS_BIND|MS_REC, NULL)                -> -1 errno=1 (Operation not permitted)
  ↑ 递归与不递归都撞同一道 CAP_SYS_ADMIN 门，本机无法对比两者差异。

=== c14_9 done ===
```

| 栏 | 归谁所有 | 例子 |
|----|---------|------|
| **per-mount**（第 6 个字段） | **这个挂载点**（`struct vfsmount.mnt_flags`） | `nosuid,nodev,noexec`、`ro`、`relatime` |
| **super**（`-` 之后最后一栏） | **整个超级块**（`struct super_block.s_flags` + 文件系统私有选项） | `rw`、`size=20480k`、`nr_inodes=100`、`discard`、`commit=30` |

关键判断：

- **`nosuid`/`nodev`/`noexec`/`noatime` 只能 per-mount** —— 因为它们描述的是「通过这个入口访问时的行为」。
- **`rw`/`ro` 两边都有**：`super` 栏里的 `rw` 是「超级块可写」，per-mount 栏里的 `ro` 是「从这个挂载点看是只读的」。本机 `/` 就是 **per-mount `ro` + super `rw`** —— 一个完美的例子。
- **`size=`/`nr_inodes=` 是文件系统私有选项**，只能在 super 栏出现（tmpfs 用它们定容量上限，见 §14.10）。
- **同一个超级块可以被挂成多个挂载点、各自给不同的 per-mount 选项**。`/app`（`rw,relatime`）与 `/lib`（`ro,relatime`）共用 `202:1`，但一个可写一个只读 —— 这就是 per-mount 选项的存在理由，也是内核必须把 `MS_*`（ABI）拆成 `MNT_*`（per-mount）的原因（§14.8 第 6 节）。

> 本容器 `/tmp` 的 per-mount 是 `rw,nosuid,nodev,noexec,relatime`，super 是 `rw,size=20480k,nr_inodes=100,uid=113,gid=113,inode64` —— 安全选项在 per-mount、容量选项在 super。这张对照表值得背。

### 14.9.4 Bind Mounts

**判据只有一条：`root != /`。** `root` 字段说的是「被挂上来的，是源文件系统里的哪棵子树」：

<!--OUT:c14_9_advanced_mount|after=③ 14.9.4,until=④ 14.9.3-->

```text
  root=/usr/lib                                 -> /lib                               (ext4)
  root=/usr/lib                                 -> /usr/lib                           (ext4)
  root=/usr/share/zoneinfo                      -> /usr/share/zoneinfo                (ext4)
  root=/usr/share/zoneinfo/Etc/UTC              -> /etc/localtime                     (ext4)
  root=/dynamic_file.1//deleted                 -> /etc/passwd                        (tmpfs)
  root=/dynamic_file.2//deleted                 -> /etc/shadow                        (tmpfs)
  root=/usr/lib64                               -> /lib64                             (ext4)
  root=/usr/lib32                               -> /lib32                             (ext4)
  root=/null                                    -> /dev/null                          (devtmpfs)
  root=/zero                                    -> /dev/zero                          (devtmpfs)
  root=/urandom                                 -> /dev/random                        (devtmpfs)
  root=/urandom                                 -> /dev/urandom                       (devtmpfs)
  root=/usr/bin/stdbuf                          -> /usr/bin/stdbuf                    (ext4)
  root=/usr/libexec/coreutils/libstdbuf.so      -> /usr/libexec/coreutils/libstdbuf.so (ext4)
  root=/usr/local/bin/dumb-init                 -> /usr/local/bin/dumb-init           (ext4)
  root=/tmp/compiler-explorer-compilerbsaH6R    -> /app                               (ext4)
  共 16 条 bind mount（root != /）
  ↑ 这些就是 bind mount：源是设备上的一个子目录，挂到另一处。
```

逐条读这张表（共 **16** 条 bind）：

| `root=` | 挂到 | 说明 |
|---------|------|------|
| `/usr/lib` | `/lib` **和** `/usr/lib` | **同一棵子树投两次** ⇒ `/lib` 与 `/usr/lib` 的 `st_ino` 相同（§14.7 实测都是 `4243`） |
| `/usr/share/zoneinfo/Etc/UTC` | `/etc/localtime` | **单文件 bind**：时区文件是从 `zoneinfo` 里挑一个投过来的 |
| `/dynamic_file.1//deleted` | `/etc/passwd` | 单文件 bind + 源已被 unlink（§14.4 的 `nlink=0`） |
| `/null`、`/zero`、`/urandom` | `/dev/null` 等 | devtmpfs 里**单个设备节点**的 bind —— 所以 `/dev` 的 `st_dev` 与 `/dev/null` 的**不同** |
| `/tmp/compiler-explorer-compilerXXXXXX` | `/app` | **`/app` 本身就是 bind mount**（编译目录被投成 `/app`） |

**bind mount 的语义要点**：

1. **它不创建新的超级块** —— 目标挂载点的 `major:minor` 与源**同一个**（这也是「数设备号」能发现它的原因）。
2. **它可以把单文件作为目标**（普通 mount 只能挂目录）。本机 `/etc/passwd`、`/dev/null`、`/etc/localtime` 全是单文件 bind。
3. **可以给 bind 出来的挂载点一套独立的 per-mount 选项** —— 这就是「同一个可写目录，在一个入口 `ro`、在另一个入口 `rw`」的实现方式（本机 `/lib` 是 `ro`、`/app` 是 `rw`，共用 `202:1`）。
4. **`MS_BIND` 时 `source`/`fstype`/`data` 是忽略的**：内核直接从 source 路径上取 dentry。
5. **`mount --bind` 之后再 `mount --bind` 会叠一层**（叠加挂载，14.9.2）。要「替换」得先卸载或叠新的。

### 14.9.5 Recursive Bind Mounts

`MS_BIND | MS_REC` 会把源目录下**所有子挂载**一起 bind 过来；只用 `MS_BIND` 则**只 bind 「一个点」**（源目录下的子挂载**不会**跟着过来，那里会露出底下被遮住的内容）。

本容器的情况很直接：

<!--OUT:c14_9_advanced_mount|after=⑤ 试一次 bind-->

```text
  mount("/tmp", "/app", NULL, MS_BIND, NULL) -> -1 errno=1 (Operation not permitted)
  mount(..., MS_BIND|MS_REC, NULL)                -> -1 errno=1 (Operation not permitted)
  ↑ 递归与不递归都撞同一道 CAP_SYS_ADMIN 门，本机无法对比两者差异。

=== c14_9 done ===
```

**递归与不递归都撞同一道 `CAP_SYS_ADMIN` 门** —— 所以「两者差在哪」在本机无法用实测对比，只能按 `man 2 mount` 的 `MS_REC` 段落讲。

> 这一条的现实意义很大：容器运行时把 `/` bind 进新命名空间时**必须用 `MS_REC`**，否则新命名空间里会看到「宿主上被遮住的东西」—— 典型的逃逸面。反过来，故意「只 bind 一个点、不递归」也是一种隔离手段（把源下面的挂载全部替换成底下的内容）。

| 记号 | 含义 |
|------|------|
| `shared:N` | 这个挂载属于**共享组 N**（`mount --make-shared`）。同组的挂载会互相传播 |
| `master:N` | 这个挂载**从组 N 接收**传播事件（`mount --make-slave`） |
| `propagate_from:N` | 传播事件的**来源组** |
| `unbindable` | 标记为不可 bind（`mount --make-unbindable`） |

**本机 60 条带 optional field**（其中大量是 `/cefs/**` 的 `master:N`）。这一栏是「挂载命名空间/容器」的核心证据：

- **`master:N` 表示「这个挂载是 slave」**：宿主上新增/删除挂载**不会**传播到这里（单向），但从它的 master 组来的事件会。容器运行时正是靠它做到「宿主挂新盘，容器里不一定看得到」。
- **没有 optional field 的挂载是 private**（默认），完全不参与传播。
- **`/lib`、`/app` 这些是 `master:1`** ⇒ 它们从一个共享组接收传播；`/dev/null` 等是 `master:2` ⇒ 另一个组。

> ⚠️ **`master:N` 的 N 会随每次运行变**（本轮 `1`/`2`/`211`/`337`/…）；具体数字不要写进断言，只能断言「这一栏存在」。

## 完整源码

完整源码 [`code/c14_9_advanced_mount.c`](../code/c14_9_advanced_mount.c)：

```c
/* c14_9_advanced_mount.c —— TLPI §14.9 Advanced Mount Features
 *
 *  官方 14.9 有五个子节：
 *    14.9.1 Mounting a File System at Multiple Mount Points
 *    14.9.2 Stacking Multiple Mounts on the Same Mount Point
 *    14.9.3 Mount Flags That Are Per-Mount Options
 *    14.9.4 Bind Mounts
 *    14.9.5 Recursive Bind Mounts
 *
 *  ⚠️ 本容器不给 CAP_SYS_ADMIN —— 这五件事**一件都做不了**（全 EPERM）。
 *  但它们的**结果**全都留在 /proc/self/mountinfo 里，所以本 demo 换个方向：
 *  不去「造」这些挂载，而是**在一张已经存在的挂载表里把它们认出来**。
 *
 *    ① optional fields（propagation）—— shared / master / propagate_from
 *    ② 14.9.1 的证据：同一 major:minor 出现在多个 mount point
 *    ③ 14.9.4 的证据：root 字段 ≠ / ，说明挂的是源设备的某个**子树**
 *    ④ 14.9.5 的证据：同一设备的多条记录里，root 前缀成组出现（recursive 的痕迹）
 *    ⑤ 14.9.3 的实证：per-mount options 与 super options 是两栏，值可以不一致
 *    ⑥ 试一次 MS_BIND|MS_REC，确认本容器确实被挡住
 *
 *  编译：gcc -O0 -Wall -Wextra -o c14_9 c14_9_advanced_mount.c
 */
#define _GNU_SOURCE
#include <sys/mount.h>
#include <sys/stat.h>
#include <sys/sysmacros.h>
#include <sys/types.h>
#include <errno.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <unistd.h>

#define MAXLINE 4096
#define MAXREC  256

static void sec(const char *t)
{
    printf("\n== %s ==\n", t);
}

struct rec {
    char id[16], parent[16], dev[32], root[512], mp[512], opts[256];
    char fstype[64], source[256], sopts[512], optf[256];
};

static int split_line(char *line, struct rec *r)
{
    char *tok[64];
    int ntok = 0, dash = -1;
    char *p = line;

    memset(r, 0, sizeof(*r));
    while (*p != '\0' && ntok < 64) {
        while (*p == ' ')
            p++;
        if (*p == '\0')
            break;
        tok[ntok++] = p;
        while (*p != '\0' && *p != ' ')
            p++;
        if (*p != '\0')
            *p++ = '\0';
    }
    for (int i = 0; i < ntok; i++)
        if (!strcmp(tok[i], "-")) { dash = i; break; }
    if (ntok < 6 || dash < 6)
        return -1;
    snprintf(r->id, sizeof(r->id), "%s", tok[0]);
    snprintf(r->parent, sizeof(r->parent), "%s", tok[1]);
    snprintf(r->dev, sizeof(r->dev), "%s", tok[2]);
    snprintf(r->root, sizeof(r->root), "%s", tok[3]);
    snprintf(r->mp, sizeof(r->mp), "%s", tok[4]);
    snprintf(r->opts, sizeof(r->opts), "%s", tok[5]);
    r->optf[0] = '\0';
    for (int i = 6; i < dash; i++) {
        if (i > 6 && strlen(r->optf) + 1 < sizeof(r->optf))
            strncat(r->optf, ",", sizeof(r->optf) - strlen(r->optf) - 1);
        if (strlen(r->optf) + strlen(tok[i]) + 1 < sizeof(r->optf))
            strncat(r->optf, tok[i], sizeof(r->optf) - strlen(r->optf) - 1);
    }
    if (dash + 1 < ntok)
        snprintf(r->fstype, sizeof(r->fstype), "%s", tok[dash + 1]);
    if (dash + 2 < ntok)
        snprintf(r->source, sizeof(r->source), "%s", tok[dash + 2]);
    if (dash + 3 < ntok)
        snprintf(r->sopts, sizeof(r->sopts), "%s", tok[dash + 3]);
    return 0;
}

int main(void)
{
    static struct rec recs[MAXREC];
    int n = 0;

    {
        FILE *fp = fopen("/proc/self/mountinfo", "r");
        char line[MAXLINE];
        if (fp == NULL) {
            printf("  mountinfo 打不开 errno=%d\n", errno);
            return 0;
        }
        while (fgets(line, sizeof(line), fp) != NULL && n < MAXREC) {
            size_t len = strlen(line);
            if (len > 0 && line[len - 1] == '\n')
                line[len - 1] = '\0';
            if (split_line(line, &recs[n]) == 0)
                n++;
        }
        fclose(fp);
    }
    printf("\n（/proc/self/mountinfo 共 %d 条）\n", n);

    /* ---------- ① propagation ---------- */
    sec("① optional fields = 挂载传播（propagation）信息");
    {
        int shown = 0;
        for (int i = 0; i < n; i++) {
            if (recs[i].optf[0] != '\0' && strstr(recs[i].optf, "deleted") == NULL) {
                printf("  %-40s opt=%-16s\n", recs[i].mp, recs[i].optf);
                shown++;
            }
        }
        if (shown == 0)
            printf("  所有条目都没有 optional field（都是 private 挂载）\n");
        else
            printf("  共 %d 条带 optional field\n", shown);
        printf("  ↑ shared:<N> 表示属于共享组 N；master:<N> 表示从组 N 接收传播事件；\n");
        printf("    propagate_from:<N> 表示事件的来源。这一栏就是 14.9.2「叠加挂载」与\n");
        printf("    14.9.5「递归」在用户态留下的痕迹。\n");
    }

    /* ---------- ② 14.9.1 多挂载点 ---------- */
    sec("② 14.9.1 的证据：一个设备挂到多个挂载点");
    {
        for (int i = 0; i < n; i++) {
            int cnt = 0;
            char list[600];

            list[0] = '\0';
            for (int j = 0; j < n; j++) {
                if (!strcmp(recs[i].dev, recs[j].dev)) {
                    cnt++;
                    if (strlen(list) + strlen(recs[j].mp) + 2 < sizeof(list)) {
                        if (list[0] != '\0')
                            strncat(list, " ", sizeof(list) - strlen(list) - 1);
                        strncat(list, recs[j].mp, sizeof(list) - strlen(list) - 1);
                    }
                }
            }
            /* 只报第一次出现的那个设备 */
            int seen = 0;
            for (int k = 0; k < i; k++)
                if (!strcmp(recs[k].dev, recs[i].dev))
                    seen = 1;
            if (!seen && cnt > 1)
                printf("  %-10s %2d 次：%s\n", recs[i].dev, cnt, list);
        }
    }

    /* ---------- ③ 14.9.4 bind 的证据 ---------- */
    sec("③ 14.9.4 的证据：root 不等于 / —— 挂的是源设备的某一棵子树");
    {
        int shown = 0;
        for (int i = 0; i < n; i++) {
            if (strcmp(recs[i].root, "/") != 0) {
                printf("  root=%-40s -> %-34s (%s)\n", recs[i].root, recs[i].mp,
                       recs[i].fstype);
                shown++;
            }
        }
        if (!shown)
            printf("  没有任何条目的 root 不是 /（没有 bind mount）\n");
        else
            printf("  共 %d 条 bind mount（root != /）\n", shown);
        printf("  ↑ 这些就是 bind mount：源是设备上的一个子目录，挂到另一处。\n");
    }

    /* ---------- ④ per-mount vs super options ---------- */
    sec("④ 14.9.3 的证据：per-mount options 与 super options 是两栏");
    {
        for (int i = 0; i < n; i++) {
            if (!strcmp(recs[i].mp, "/tmp") || !strcmp(recs[i].mp, "/app") ||
                !strcmp(recs[i].mp, "/"))
                printf("  %-8s per-mount = %-34s\n  %-8s super     = %s\n",
                       recs[i].mp, recs[i].opts, "", recs[i].sopts);
        }
        printf("  ↑ per-mount 栏里的 nosuid/nodev/noexec 是**这一个挂载点**的选项；\n");
        printf("    super 栏里的 rw/size=/nr_inodes= 是**整个超级块**的属性。\n");
        printf("    同一个超级块可以被挂成多个挂载点、各自给不同的 per-mount 选项 ——\n");
        printf("    这正是为什么 MS_* 需要拆成 MS_* (ABI) 和 MNT_* (per-mount) 两套。\n");
    }

    /* ---------- ⑤ 实测 bind ---------- */
    sec("⑤ 试一次 bind mount（预期被挡住）");
    {
        errno = 0;
        if (mount("/tmp", "/app", NULL, MS_BIND, NULL) == -1)
            printf("  mount(\"/tmp\", \"/app\", NULL, MS_BIND, NULL) -> -1 errno=%d (%s)\n",
                   errno, strerror(errno));
        else
            printf("  成功\n");
        errno = 0;
        if (mount("/tmp", "/app", NULL, MS_BIND | MS_REC, NULL) == -1)
            printf("  mount(..., MS_BIND|MS_REC, NULL)                -> -1 errno=%d (%s)\n",
                   errno, strerror(errno));
        else
            printf("  成功\n");
        printf("  ↑ 递归与不递归都撞同一道 CAP_SYS_ADMIN 门，本机无法对比两者差异。\n");
    }

    printf("\n=== c14_9 done ===\n");
    return 0;
}
```

## 常见坑

| # | 坑 | 正解 |
|---|----|------|
| 1 | 以为「同一设备出现多次」就是 bind mount | 普通 mount 也能挂多次。bind 的判据是 `root != /` |
| 2 | 以为 bind mount 会复制数据 | 不复制、不建新超级块。目标与源的 `major:minor` **相同** |
| 3 | 以为 bind mount 只能挂目录 | **单文件也能 bind**（本机 `/etc/passwd`、`/dev/null`、`/etc/localtime`） |
| 4 | 以为 `nosuid` 是超级块属性 | `nosuid`/`nodev`/`noexec` 是 **per-mount**；`size=`/`nr_inodes=` 才是 super 级 |
| 5 | 以为 `mountinfo` 里的 `ro`/`rw` 只有一处 | **两处**：per-mount 栏与 super 栏。本机 `/` 是 per-mount `ro` + super `rw` |
| 6 | 拿 `/proc/mounts` 去还原挂载树 | `mounts` 没有 `mount ID`/`parent ID`。画树必须用 `mountinfo` |
| 7 | 以为 `MS_BIND` 会带上源下面的子挂载 | 不会，只 bind「一个点」。要递归得加 **`MS_REC`** |
| 8 | 把 `master:N` 的 N 写进断言 | N 是运行时分配的组 ID，每次运行不同。只能断言「有 optional field」 |
| 9 | 以为 `/dev/null` 是 `/dev` 目录里的普通文件 | `/dev` 是 tmpfs，`/dev/null` 在 devtmpfs 上 —— `st_dev` 不同，是单文件 bind |
| 10 | 跨作业比较挂载点数量 | 本机 `c14_9` 报 66 条、`c14_7` 报 65 个 —— **不同宿主**。只在同一次运行内比较 |

## HFT / 嵌入式关联

| 场景 | 结论怎么用 |
|------|-----------|
| **`ro` 与 `rw` 各有两层** | 「让某个入口只读」用 bind + per-mount `ro`，源超级块仍可写。HFT 里「数据目录只让某一进程看到只读视图」就是这个手法 |
| **bind mount 是零成本的视图层** | 不复制数据、不建超级块、共享页缓存。比复制省空间、比符号链接可控（可以给独立选项、能挡 `..` 逃逸） |
| **`MS_REC` 决定容器隔离是否成立** | 把宿主 `/` bind 进容器而**不加 `MS_REC`**，会露出被遮挡的内容 —— 这是经典的容器逃逸面。反过来，「不递归地 bind 一个点」是刻意的隔离手法 |
| **`master:N` 决定「宿主挂盘容器看不看得到」** | 容器的挂载是 slave（`master:N`）⇒ 宿主挂载事件不传播进来。排查「容器里为什么看不到新挂的数据盘」就看这一栏（§14.7） |
| **嵌入式 rootfs 的最小挂载集** | 只需 `/`（只读）+ `/dev`（devtmpfs）+ `/proc` + `/sys` + `/tmp`（tmpfs）+ 一个可写数据分区。**per-mount 别忘 `nosuid,nodev,noexec`** —— 嵌入式设备被拿到物理访问权时，这三个选项是最后一道门 |
| **叠加挂载是「不重启换版本」的工具** | 把新版本目录挂到同一个挂载点上（叠一层），验证通过就保持、有问题就 `umount` 露出旧版本。比重启服务快，但**必须保证旧版本还被别的进程打开时不会被破坏** |
| **内存账要算对** | 同一个超级块挂多次**不重复占页缓存**。做容器内存预算时把 `/lib`、`/usr/lib`、`/app` 当成同一份（它们就是同一个 ext4 实例） |

<summary>代码自测（Q&A）</summary>

**Q1：怎么在一张挂载表里认出 bind mount？**

A：看 `mountinfo` 的 **`root` 字段**。`root=/` 是把整个文件系统挂上来；`root=<其它路径>` 表示只把源文件系统的某个子树投过来 —— 那就是 bind。本机 16 条这样的记录，包括单文件 bind（`/etc/passwd`、`/dev/null`、`/etc/localtime`）。

**Q2：`MS_BIND` 与 `MS_BIND|MS_REC` 差在哪？**

A：只 `MS_BIND` 时只 bind **一个点**：源目录下如果还有别的挂载（子挂载），**不会**一起 bind 过来，那里会露出被遮住的内容。加 `MS_REC` 会把整棵子树（含所有子挂载）一起 bind。本机两者都是 `EPERM`，差别只能按 `man 2 mount` 讲。

**Q3：`mountinfo` 里 per-mount 与 super 两栏分别装什么？**

A：per-mount 栏（第 6 字段）装**这个挂载点**的选项：`ro`、`nosuid`、`nodev`、`noexec`、`noatime`、`relatime` 等。super 栏（`-` 之后最后一栏）装**整个超级块**的属性与文件系统私有选项：`rw`、`size=20480k`、`nr_inodes=100`、`discard`、`commit=30`。本机 `/tmp` 两栏分别是 `rw,nosuid,nodev,noexec,relatime` 与 `rw,size=20480k,nr_inodes=100,uid=113,gid=113,inode64`。

**Q4：为什么同一个超级块的 `/lib` 是只读而 `/app` 可写？**

A：因为 **per-mount 选项是每个挂载点各自一份**。`/lib` 的 per-mount 是 `ro,relatime`，`/app` 是 `rw,relatime`，但两者 super 栏都是 `rw,discard,errors=remount-ro,commit=30`（同一超级块）。这正是 bind mount 能当「只读视图」用的原因。

**Q5：`master:1` 是什么意思？**

A：`mountinfo` optional fields 里的**传播**记号：`master:N` 表示这个挂载是组 N 的 **slave**（从组 N 接收传播事件，但自己这边的事件不外传）。`shared:N` 是同组共享。本机 `/lib`、`/app` 是 `master:1`，`/dev/*` 是 `master:2`。数字每次运行会变，别写死。

**Q6：为什么 `/dev` 和 `/dev/null` 的 `st_dev` 不同？**

A：因为 `/dev` 是 `tmpfs`，而 `/dev/null` 是从 **devtmpfs** 单文件 bind 过来的（`mountinfo` 里 `root=/null`、`fstype=devtmpfs`）。两个不同超级块 ⇒ `st_dev` 不同。这条正好也证明了「bind mount 不建新超级块、设备号取自源」。

**Q7：`/cefs/**` 那一大堆挂载是怎么来的？**

A：是 **autofs**（`/cefs` 挂 `autofs`，子目录 `master:N` 表示 slave 传播）。首次访问 `/cefs/xx` 时触发自动挂载，把 CE 的编译器镜像（squashfs，来自 `/dev/loopN`）挂上去。`/dev/loop*` 那 24 个回环设备就是它们的本体（§14.2 实测）。**具体名字随镜像滚动变化，不能写进断言。**
