## 本节讲什么

inode 是文件系统的核心数据结构。这一节钉四件事：

1. **inode 号只在同一个文件系统内唯一** —— 必须配 `st_dev` 才有意义。这也是硬链接**不能跨文件系统**的根本原因。
2. **文件名不在 inode 里**，它与 inode 号一起放在**目录的数据块**里。所以「硬链接」不是「复制文件」，而是「目录里再加一条名字」。
3. **数据块的真正释放条件是「`nlink == 0` 且没有打开的 fd」** —— `unlink()` 只是删名字，不是删数据。
4. **`st_size`（逻辑大小）≠ `st_blocks × 512`（物理占用）**：稀疏文件的洞不占块，而小文件因为有块分配的最小粒度反而「占得比内容多」。

## 1. inode 里有什么

`struct stat` 就是 inode 的用户态投影（TLPI §14.4 的那张表）：

| 字段 | 在 inode 里的来源 | 备注 |
|------|------------------|------|
| `st_dev` | 不是 inode 里的字段 | 是「这个 inode 属于哪个文件系统实例」。**给 `st_ino` 定域用** |
| `st_ino` | inode 号 | 只在同一 `st_dev` 内唯一 |
| `st_mode` | 类型位（`S_IFMT`）+ 权限位 | 类型位是**权威**，文件名/后缀什么都证明不了 |
| `st_nlink` | 硬链接计数 | 归零才可能释放数据 |
| `st_uid` / `st_gid` | 属主 | |
| `st_size` | 逻辑大小 | 对目录是「目录数据块的大小」，对符号链接是「链接目标长度」 |
| `st_blocks` | 实际分配的块数 | **单位固定 512 字节**，与 `st_blksize`/`f_bsize` 无关 |
| `st_blksize` | 推荐 I/O 大小 | 不是块大小 |
| `st_atime` / `st_mtime` / `st_ctime` | 访问 / 修改 / inode 变更时间 | `ctime` 在**改权限、改属主、改链接数**时都会动，不是「创建时间」 |

<!--OUT:c14_4_inode|after=① inode 号只在同一个,until=② 硬链接-->

```text
  /      : st_dev=0:65    st_ino=1
  /proc  : st_dev=0:72    st_ino=1
  → 两个 inode 号相同，但 st_dev 不同 → **不是同一个对象**
    inode 号必须配上 st_dev 才有意义，这就是硬链接不能跨 FS 的原因。
  /app   : st_dev=259:2     st_ino=358790

  把一个真实文件的 inode 全字段摊开（就是 TLPI §14.4 的那张表）：
  /etc/passwd
    st_dev=0:63    (设备号，同一 FS 内相同，用来给 inode 号「定域」)
    st_ino=2            (inode 号)
    st_mode=0000644 reg  (S_IFMT + 权限位)
    st_nlink=0           (硬链接计数)
    st_size=50           st_blocks=8        (× 512 字节 = 4096 字节物理占用)
    st_blksize=4096      (该 FS 的「推荐 I/O 块大小」)
```

**本节的第一个惊喜藏在实测里**：`/etc/passwd` 的 `st_nlink=0`。

一个**正正常常能读**的文件，硬链接计数是 0 —— 这看起来矛盾，其实完全合理。看 §14.7 的实测：

```text
  /etc/passwd              root=/dynamic_file.1//deleted         fstype=tmpfs source=none
```

它是**单文件 bind mount**：宿主上先造一个临时文件、打开它、把文件 `unlink()`（于是 `nlink` 归 0）、再把那个「已打开的文件」bind mount 到容器的 `/etc/passwd` 上。所以容器里看到的就是**一个 nlink=0 但活着的 inode** —— 这正好是下面 ③ 段要讲的现象，只是舞台从「你的程序」换成了「容器运行时」。

> `root=` 字段里那个 `//deleted` 是内核给「已 unlink 但还被引用」的 dentry 打的标记，详见 §14.7。

## 2. inode 号必须配 `st_dev`：`/` 与 `/proc` 的 inode 号都是 1

① 段的输出里有一对非常干净的证据：

```text
  /      : st_dev=0:65    st_ino=1
  /proc  : st_dev=0:72    st_ino=1
  → 两个 inode 号相同，但 st_dev 不同 → **不是同一个对象**
```

两个完全不同的文件系统，**根目录的 inode 号都是 1**（这是惯例：inode #1 通常是文件系统的「坏块表/orphan list」，而根目录的号由超级块指定；tmpfs 与 procfs 都把根目录放在 1）。所以：

- 比较两个路径「是不是同一个文件」，必须**同时**比 `st_dev` 与 `st_ino`（`stat(2)` 手册里专门提过这一点）。
- 硬链接之所以不能跨文件系统，就是因为硬链接的实现只是「在目录数据块里写一条 `(名字, inode号)`」—— 而 inode 号是**每个文件系统独立的命名空间**，跨过去就没有意义了。

③ 段的实测给出了这个限制的 API 级表现：

```text
  link 到 /tmp（另一个 FS）-> -1 errno=18 (Invalid cross-device link)
```

`EXDEV(18)` 就是 `<errno.h>` 里的 `EXDEV`，注释名是 `Invalid cross-device link`。

## 3. 硬链接：目录里再加一条名字

`link(2)` 做的事，用一句话说清楚：**在目标目录的数据块里加一条 `(新名字 → 已有 inode 号)`，并把 inode 的 `nlink` 加一**。

<!--OUT:c14_4_inode|after=② 硬链接,until=③ unlink-->

```text
  写入 12 字节到 /app/c14_4_a
  link 前: ino=358793     nlink=1
  link 后: a  ino=358793     nlink=2
           b  ino=358793     nlink=2
  → 两条路径 ino 相同，nlink 从 1 变 2；**没有复制数据块**
  link 到 /tmp（另一个 FS）-> -1 errno=18 (Invalid cross-device link)
  unlink("b") 后: nlink=1（数据一个字节都没动）
```

三个关键读数：

| 观察 | 结论 |
|------|------|
| `link` 前 `nlink=1`，后 `nlink=2`，**两条路径 `ino` 相同** | 没有复制数据块，只是多了一个目录项 |
| `link` 到另一个文件系统 → `errno=18 (EXDEV)` | inode 号不能跨文件系统引用 |
| `unlink("b")` 后 `nlink=1` | 删的是**名字**，inode 还在，数据一个字节都没动 |

## 4. `unlink` 之后 fd 还能读：释放的三个条件

这是全章最值得记住的一段：

<!--OUT:c14_4_inode|after=③ unlink,until=④ st_size-->

```text
  unlink("a") 后 stat 失败 errno=2 (No such file or directory) —— 名字没了
  但**已打开的 fd 仍能读**：读回 12 字节 "hello inode"
  → 真正的数据块释放条件是：nlink == 0 **且** 没有打开的 fd
```

`unlink("a")` 之后 `stat("/app/c14_4_a")` 报 `ENOENT(2)`（名字确实没了），但**已经打开的那个 fd 照样把 12 字节读回来了**。

原因在于 VFS 层有**两套引用计数**，它们分开走：

| 计数 | 归谁 | 归零时发生什么 |
|------|------|--------------|
| `i_nlink`（磁盘上的 `st_nlink`） | inode | 标记「没人要这个名字了」 |
| `i_count`（内存中的引用数） | `struct inode` | 内存里的 inode 对象可以回收 |

- `unlink()` 只减 `i_nlink`。
- `open()` 打开一个文件会让 dentry/inode 的引用数 +1，`close()` 时 -1。
- **只有 `i_nlink == 0` 且 `i_count == 0` 时，ext4 才会真正释放数据块**（`fs/ext4/` 里在 `ext4_evict_inode()` 里做）。

所以「一个进程打开着文件、另一个进程把它 `unlink` 掉」，文件在磁盘上依然占着空间直到那个 fd 被关闭。这就是「`df` 显示盘满、`du` 却算不出来」的经典原因 —— 也是 §14.7 里 `/etc/passwd` 那个 `nlink=0` 的来路。

## 5. `st_size` vs `st_blocks`：逻辑大小与物理占用是两件事

<!--OUT:c14_4_inode|after=④ st_size-->

```text
  写 1 个字节   : st_size=1      st_blocks=8    物理 4096 字节  (1)
  稀疏文件      : st_size=1048577 st_blocks=8    物理 4096 字节  (lseek→1048576, write=1)
  → 逻辑大小 1 MiB+1，物理只有最后一小块 —— 中间的洞没有分配块
  写 4096 字节  : st_size=4096   st_blocks=8    物理 4096 字节  (write=4096)

=== c14_4 done ===
```

三组读数，三种现象：

| 实验 | `st_size` | `st_blocks`（× 512） | 说明 |
|------|-----------|---------------------|------|
| 写 1 个字节 | 1 | 8 × 512 = 4096 | **块分配的最小粒度**是 4096 字节（`f_bsize`），1 字节也要占一整块 |
| 稀疏文件（`lseek` 到 1 MiB 再写 1 字节） | 1048577 | 8 × 512 = 4096 | 中间 1 MiB **全是洞**，一个块都没分配 |
| 写 4096 字节 | 4096 | 8 × 512 = 4096 | 正好一块 |

两条推论：

1. **`du` 与 `ls -l` 为什么经常对不上**：`ls -l` 打 `st_size`（逻辑），`du` 打 `st_blocks×512`（物理）。稀疏文件、`prealloc`、`fallocate`、压缩文件系统、reflink 都会让两者差很远。
2. **稀疏文件是「合法的」**：`read()` 读到洞时返回的是**零字节**（不是短读、不是错误），这是文件系统层补齐的。所以「用 `lseek` 跳过一段」在语义上等于「写了一段零」——但物理上完全不同。

> ⚠️ **`st_blocks` 的单位是固定的 512 字节**，与 `st_blksize`、`f_bsize` 都无关。这一点在内核 `fs/stat.c` 的 `generic_fillattr()`/文件系统自己的 `getattr` 里就是「扇区数」口径（`inode->i_blocks`），所以 `st_blocks × 512` 才是字节数。

## 完整源码

完整源码 [`code/c14_4_inode.c`](../code/c14_4_inode.c)：

```c
/* c14_4_inode.c —— TLPI §14.4 I-nodes
 *
 *  一节的三个硬结论，各配一个可观测实验：
 *    ① inode 号**只在同一个文件系统内唯一** —— 不同 FS 上可以重复
 *       实验：同时 stat("/") 与 stat("/proc")，两者的 inode 号可以一模一样
 *    ② 文件名在目录的数据块里，不在 inode 里；硬链接就是「目录里两条名字
 *       指向同一个 inode」 —— 实验：link() 前后 st_nlink 与 st_ino
 *    ③ inode 里的数据块指针决定「逻辑大小 ≠ 物理占用」
 *       实验：st_size 与 st_blocks 的对比（稀疏文件、以及小文件的对齐开销）
 *       再加一个「unlink 之后 fd 还能读」——证明释放发生在「链接计数为 0
 *       且无人打开」之后
 *
 *  编译：gcc -O0 -Wall -Wextra -o c14_4 c14_4_inode.c
 */
#define _GNU_SOURCE
#include <sys/stat.h>
#include <sys/sysmacros.h>
#include <sys/types.h>
#include <errno.h>
#include <fcntl.h>
#include <stdio.h>
#include <string.h>
#include <unistd.h>

static void sec(const char *t)
{
    printf("\n== %s ==\n", t);
}

/* 打 inode 的全字段（TLPI §14.4 的那张表） */
static void show_inode(const char *path)
{
    struct stat st;
    const char *kind;

    if (stat(path, &st) == -1) {
        printf("  stat(%s) errno=%d (%s)\n", path, errno, strerror(errno));
        return;
    }
    kind = S_ISDIR(st.st_mode) ? "dir" : S_ISREG(st.st_mode) ? "reg" :
           S_ISLNK(st.st_mode) ? "lnk" : S_ISCHR(st.st_mode) ? "chr" :
           S_ISBLK(st.st_mode) ? "blk" : S_ISFIFO(st.st_mode) ? "fifo" :
           S_ISSOCK(st.st_mode) ? "sock" : "???";
    printf("  %s\n", path);
    printf("    st_dev=%u:%-5u (设备号，同一 FS 内相同，用来给 inode 号「定域」)\n",
           major(st.st_dev), minor(st.st_dev));
    printf("    st_ino=%-12llu (inode 号)\n", (unsigned long long) st.st_ino);
    printf("    st_mode=%07o %-4s (S_IFMT + 权限位)\n",
           (unsigned) st.st_mode & 077777, kind);
    printf("    st_nlink=%-11lu (硬链接计数)\n", (unsigned long) st.st_nlink);
    printf("    st_size=%-12lld st_blocks=%-8lld (× 512 字节 = %lld 字节物理占用)\n",
           (long long) st.st_size, (long long) st.st_blocks,
           (long long) st.st_blocks * 512);
    printf("    st_blksize=%-9lu (该 FS 的「推荐 I/O 块大小」)\n",
           (unsigned long) st.st_blksize);
}

int main(void)
{
    /* ---------- ① inode 号的作用域 ---------- */
    sec("① inode 号只在同一个文件系统内唯一");
    {
        struct stat a, b, c;
        int r1 = stat("/", &a);
        int r2 = stat("/proc", &b);
        int r3 = stat("/app", &c);

        if (r1 == 0 && r2 == 0) {
            printf("  /      : st_dev=%u:%-5u st_ino=%llu\n",
                   major(a.st_dev), minor(a.st_dev), (unsigned long long) a.st_ino);
            printf("  /proc  : st_dev=%u:%-5u st_ino=%llu\n",
                   major(b.st_dev), minor(b.st_dev), (unsigned long long) b.st_ino);
            printf("  → 两个 inode 号%s，但 st_dev 不同 → **不是同一个对象**\n",
                   a.st_ino == b.st_ino ? "相同" : "不同");
            printf("    inode 号必须配上 st_dev 才有意义，这就是硬链接不能跨 FS 的原因。\n");
        }
        if (r3 == 0)
            printf("  /app   : st_dev=%u:%-5u st_ino=%llu\n",
                   major(c.st_dev), minor(c.st_dev), (unsigned long long) c.st_ino);

        printf("\n  把一个真实文件的 inode 全字段摊开（就是 TLPI §14.4 的那张表）：\n");
        show_inode("/etc/passwd");
    }

    /* ---------- ② 硬链接 ---------- */
    sec("② 硬链接 = 目录里的第二条名字指向同一个 inode");
    {
        struct stat st;
        int fd;

        unlink("/app/c14_4_a");
        unlink("/app/c14_4_b");

        fd = open("/app/c14_4_a", O_WRONLY | O_CREAT | O_TRUNC, 0644);
        if (fd == -1) {
            printf("  open errno=%d (%s)\n", errno, strerror(errno));
        } else {
            ssize_t n = write(fd, "hello inode\n", 12);
            printf("  写入 %zd 字节到 /app/c14_4_a\n", n);
            close(fd);

            stat("/app/c14_4_a", &st);
            printf("  link 前: ino=%-10llu nlink=%lu\n",
                   (unsigned long long) st.st_ino, (unsigned long) st.st_nlink);

            if (link("/app/c14_4_a", "/app/c14_4_b") == -1) {
                printf("  link errno=%d (%s)\n", errno, strerror(errno));
            } else {
                struct stat s2;
                stat("/app/c14_4_a", &st);
                stat("/app/c14_4_b", &s2);
                printf("  link 后: a  ino=%-10llu nlink=%lu\n",
                       (unsigned long long) st.st_ino, (unsigned long) st.st_nlink);
                printf("           b  ino=%-10llu nlink=%lu\n",
                       (unsigned long long) s2.st_ino, (unsigned long) s2.st_nlink);
                printf("  → 两条路径 ino %s，nlink 从 1 变 2；**没有复制数据块**\n",
                       st.st_ino == s2.st_ino ? "相同" : "不同");

                /* 跨 FS 硬链接 */
                errno = 0;
                if (link("/app/c14_4_a", "/tmp/c14_4_c") == -1)
                    printf("  link 到 /tmp（另一个 FS）-> -1 errno=%d (%s)\n",
                           errno, strerror(errno));
                else
                    printf("  link 到 /tmp -> 0（意外）\n");
            }

            /* 删掉一条名字 */
            unlink("/app/c14_4_b");
            stat("/app/c14_4_a", &st);
            printf("  unlink(\"b\") 后: nlink=%lu（数据一个字节都没动）\n",
                   (unsigned long) st.st_nlink);

            /* ---------- ③ unlink 之后 fd 还能读 ---------- */
            sec("③ unlink 之后：名字没了，已打开的 fd 仍能读");
            fd = open("/app/c14_4_a", O_RDONLY);
            if (fd != -1) {
                char buf[32];
                ssize_t n;

                unlink("/app/c14_4_a");
                if (stat("/app/c14_4_a", &st) == -1)
                    printf("  unlink(\"a\") 后 stat 失败 errno=%d (%s) —— 名字没了\n",
                           errno, strerror(errno));
                n = read(fd, buf, sizeof(buf) - 1);
                if (n > 0) {
                    buf[n] = '\0';
                    printf("  但**已打开的 fd 仍能读**：读回 %zd 字节 \"%s\"\n", n,
                           strcmp(buf, "hello inode\n") == 0 ? "hello inode" : buf);
                }
                close(fd);
                printf("  → 真正的数据块释放条件是：nlink == 0 **且** 没有打开的 fd\n");
            }
        }
    }

    /* ---------- ④ st_size vs st_blocks ---------- */
    sec("④ st_size（逻辑大小）vs st_blocks（物理占用，512 字节单位）");
    {
        struct stat st;
        int fd;
        const char *p = "/app/c14_4_size";

        unlink(p);
        fd = open(p, O_WRONLY | O_CREAT | O_TRUNC, 0644);
        if (fd != -1) {
            /* 只写 1 个字节 —— ext4 会按块分配，所以物理占用远大于 1 */
            ssize_t n = write(fd, "X", 1);
            close(fd);
            stat(p, &st);
            printf("  写 1 个字节   : st_size=%-6lld st_blocks=%-4lld 物理 %lld 字节  (%zd)\n",
                   (long long) st.st_size, (long long) st.st_blocks,
                   (long long) st.st_blocks * 512, n);
        }

        unlink(p);
        /* 稀疏文件：lseek 跳过 1 MiB 再写 1 个字节 */
        fd = open(p, O_WRONLY | O_CREAT | O_TRUNC, 0644);
        if (fd != -1) {
            off_t off = lseek(fd, 1024 * 1024, SEEK_SET);
            ssize_t n = write(fd, "Y", 1);
            close(fd);
            stat(p, &st);
            printf("  稀疏文件      : st_size=%-6lld st_blocks=%-4lld 物理 %lld 字节  (lseek→%lld, write=%zd)\n",
                   (long long) st.st_size, (long long) st.st_blocks,
                   (long long) st.st_blocks * 512, (long long) off, n);
            printf("  → 逻辑大小 1 MiB+1，物理只有最后一小块 —— 中间的洞没有分配块\n");
        }

        /* 把小文件读一遍，看物理量有没有变化（至少能说明丢零/预读机制存在） */
        unlink(p);
        fd = open(p, O_WRONLY | O_CREAT | O_TRUNC, 0644);
        if (fd != -1) {
            char buf[4096];
            memset(buf, 'Z', sizeof(buf));
            ssize_t n = write(fd, buf, sizeof(buf));
            close(fd);
            stat(p, &st);
            printf("  写 4096 字节  : st_size=%-6lld st_blocks=%-4lld 物理 %lld 字节  (write=%zd)\n",
                   (long long) st.st_size, (long long) st.st_blocks,
                   (long long) st.st_blocks * 512, n);
        }
        unlink(p);
    }

    printf("\n=== c14_4 done ===\n");
    return 0;
}
```

## 常见坑

| # | 坑 | 正解 |
|---|----|------|
| 1 | 拿 `st_ino` 单独判断「是不是同一个文件」 | 必须**同时**比 `st_dev`。本容器 `/` 与 `/proc` 的 `st_ino` 都是 `1` |
| 2 | 以为 `unlink()` 会立刻释放空间 | 只在 `nlink==0` **且** 没有打开的 fd 时才释放（本节 ③） |
| 3 | 以为「硬链接」会复制数据 | 只是目录数据块里多一条 `(名字, inode号)`；`nlink` +1 |
| 4 | 以为 `st_ctime` 是「创建时间」 | 它是 **inode 变更时间**：改权限、改属主、改链接数都会动它 |
| 5 | 用 `ls -l` 的字节数估磁盘占用 | `ls -l` 是 `st_size`（逻辑）。物理占用要 `du` / `st_blocks × 512` |
| 6 | 以为 `st_blocks` 单位是 `st_blksize` | 单位固定 **512 字节**（扇区口径），与 `st_blksize` 无关 |
| 7 | 以为「文件名存在 inode 里」 | 名字在**目录的数据块**里。所以 inode 可以有 0 个名字（`nlink=0` 但活着） |
| 8 | 以为跨文件系统的 `link()` 会「想办法成功」 | 一律 `EXDEV(18)`。要等价效果只能用符号链接或 bind mount |
| 9 | 看到 `st_nlink=0` 就以为文件坏了 | 本机 `/etc/passwd` 就是 `nlink=0`（单文件 bind mount 自「已 unlink 的源」）。见 §14.7 |
| 10 | 以为 `direct I/O` 能绕开 inode | `O_DIRECT` 绕的是**页缓存**，不是 inode —— 元数据（`stat`）永远要过 inode |

## HFT / 嵌入式关联

| 场景 | 结论怎么用 |
|------|-----------|
| **`df` 满了、`du` 不认** | 第一嫌疑就是「有进程打开着一个已被 unlink 的文件」。查法：`lsof +L1`，或者扫 `/proc/*/fd` 找带 `(deleted)` 的条目（本节 `/proc/self/fd/3 -> /etc/passwd (deleted)` 就是它） |
| **行情进程的日志轮转** | 正确做法是 `rename()` + 让写者重开；如果写者一直握着旧 fd，旧文件在 `nlink=0` 之后仍占满磁盘 —— 轮转「看起来成功、磁盘不释放」的经典故障 |
| **海量小文件必须看 inode** | 「一个快照一个文件」的场景里，`st_nlink`/inode 开销与文件数是线性关系。inode 用尽时 `open` 报 `ENOSPC`，而 `write` 到已打开文件仍然成功 —— 出错点很反直觉 |
| **嵌入式 flash 与稀疏文件** | 稀疏文件在 FTL 上**未必省空间**（取决于是否 TRIM/丢弃零页）。在 eMMC 上依赖「洞不占块」是不可靠的假设 |
| **`st_blocks` 才是「真实 I/O 量」的近似** | 评估一次落盘刷了多少数据，看 `st_blocks` 的增量比看 `st_size` 靠谱（但要除以 8 得 KiB） |
| **inode 号不是 ID，别拿它做 key** | 「inode 号 + 设备号」才唯一。文件被重写（`O_TRUNC`/新建）会换 inode，而「删了再建」甚至可能**撞回同一个号**（ext4 有 `orphan` 复用）—— 用它做持久化标识会翻车 |

<summary>代码自测（Q&A）</summary>

**Q1：为什么 `/` 和 `/proc` 的 `st_ino` 都是 1？**

A：因为 inode 号是**每个文件系统内部**的编号，两个不同的文件系统各自从自己的 inode 空间编号。惯例上根目录的 inode 号由超级块指定（tmpfs 用 1、procfs 用 1），而 inode #1 在 ext 系列里留给坏块表/orphan 链。所以「都是 1」不代表同一个对象 —— 判决条件是 `st_dev` 不同。

**Q2：硬链接为什么不能跨文件系统？**

A：因为硬链接的实现是「在目录的数据块里写一条 `(名字, inode号)`」。inode 号只在同一文件系统内有意义；跨文件系统写一个号过去，`lookup` 时不知道该去哪个文件系统的 inode 表里找。所以内核直接返回 `EXDEV(18)`（本节实测）。

**Q3：`unlink()` 之后数据什么时候真正被释放？**

A：`i_nlink == 0` **且** `i_count == 0`。前者由 `unlink()` 递减，后者是内存中 inode 对象的引用数（被打开的 `struct file`、被缓存的 dentry 等都会 +1）。本节的实测：`unlink("a")` 后 `stat` 失败，但已打开的 fd 仍读回 12 字节。

**Q4：写 1 个字节为什么 `st_blocks` 就是 8（4096 字节）？**

A：文件系统分配空间的**最小单位是块**（`f_bsize` = 4096 字节），不是字节。并且 ext4 有「延迟分配」，但它只影响「什么时候分配」，不影响「一次分配多大」。所以 1 字节的内容占一整块，`st_blocks = 4096/512 = 8`。

**Q5：稀疏文件读出来是什么？**

A：洞的部分读到的是**零字节**（`'\0'`），不是短读也不是错误。所以 `lseek` 跳过 + 只写尾部，与「写满零再写尾部」在 `read()` 语义上等价，物理占用完全不同。本节的实测：`st_size=1048577` 而 `st_blocks=8`。

**Q6：本机 `/etc/passwd` 的 `st_nlink=0` 怎么解释？**

A：它是**单文件 bind mount**。§14.7 的 mountinfo 实测显示 `/etc/passwd` 的 `root=/dynamic_file.1//deleted`、`fstype=tmpfs`：宿主上造了临时文件、打开、`unlink`（nlink 归 0），再把那个「活着的已删除文件」挂进容器。这正是本节 ③ 段现象的容器化用法。

**Q7：`st_ctime` 什么时候会变？**

A：**inode 内容变化**时：写文件改 `st_mtime` 与 `st_ctime`；`chmod`/`chown`/`link`/`unlink` 只改 `st_ctime`（不改 mtime）。所以 `ctime` **不是**创建时间 —— Linux 在 `statx(2)` 里才有真正的 `stx_btime`（`STATX_BTIME`）。
