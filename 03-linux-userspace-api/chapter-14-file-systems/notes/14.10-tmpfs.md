## 本节讲什么

tmpfs 是「一个没有块设备的文件系统」的样板。它把文件内容放在**页缓存/匿名页**里，所以没有「顺序写、寻道、磨损」这些概念，但也就有了「掉电即失、容量由内存决定」这些特性。这一节钉四件事：

1. **tmpfs 是 `nodev` 文件系统**：`/proc/filesystems` 里带 `nodev` 前缀 ⇒ 挂它不需要块设备（`source` 写 `none` 就行）。
2. **它的容量与 inode 上限是「挂载时定死的两个数」**：`size=` 与 `nr_inodes=` 直接对应 `statfs()` 的 `f_blocks × f_frsize` 与 `f_files` —— 可以逐项对账。
3. **`f_bfree` 与 `f_ffree` 是两条独立的线**：写 1 MiB 掉 256 个块但只掉 1 个 inode；inode 只在**创建**时消耗。
4. **`fsid` 才是「是不是同一个超级块」的判据**：本机 `/` 与 `/sys` 的 `fsid` **完全相同** ⇒ `/sys` 只是 `/` 上的空目录，**sysfs 从未挂载**。

## 1. `nodev`：tmpfs 与「设备」的分界线

`/proc/filesystems` 列出内核编译时注册的所有文件系统，前面带 `nodev` 的表示**不需要块设备**：

<!--OUT:c14_10_tmpfs|after=① /proc/filesystems,until=② /tmp 在-->

```text
  /proc/filesystems 里与 tmpfs 有关的那一行：（见下）
    [nodev	tmpfs]
  ↑ `nodev` 前缀 = 这个文件系统**不需要块设备**就能挂载。
    这一栏正是 14.1「设备特殊文件」与 14.3「文件系统」的分界线：
    有 nodev 的文件系统用 `mount -t tmpfs none /mnt`（source 写 none 就行）。
```

这一栏正是 §14.1（设备特殊文件）与 §14.3（文件系统）的**分界线**：

| | 需要块设备 | `nodev`（不需要） |
|---|---|---|
| 挂载方式 | `mount /dev/sda1 /mnt` | `mount -t tmpfs none /mnt` |
| 容量来源 | **设备的物理容量** | **内存**（+ `size=` 选项） |
| 例子 | ext4、xfs、squashfs | tmpfs、proc、sysfs、devtmpfs、ramfs、overlay |

## 2. `/tmp` 的挂载记录：`size=` 在哪一栏

<!--OUT:c14_10_tmpfs|after=② /tmp 在,until=③ statfs-->

```text
  702 683 0:58 / /tmp rw,nosuid,nodev,noexec,relatime - tmpfs none rw,size=20480k,nr_inodes=100,uid=113,gid=113,inode64
    fstype       = tmpfs
    per-mount    = rw,nosuid,nodev,noexec,relatime
    super opts   = rw,size=20480k,nr_inodes=100,uid=113,gid=113,inode64
  ↑ 注意三点：① source 是 **none**（tmpfs 背后没有设备）；
    ② size= 与 nr_inodes= 出现在 **super options** 一栏（它们属于超级块，
       不是 per-mount 选项）；③ per-mount 一栏的 nosuid/nodev/noexec
       是挂载时给这一个挂载点加的加固选项（都写在小写那一栏）。
```

三个要点：

1. **`source` 是 `none`** —— tmpfs 背后没有设备，`mountinfo` 的 `source` 栏写 `none`。
2. **`size=` / `nr_inodes=` 出现在 super options 栏**（`-` 之后那一栏），因为它们是**超级块级**属性（§14.9.3）。
3. **`nosuid,nodev,noexec` 在 per-mount 栏** —— 这是挂载时给**这一个挂载点**加的加固选项（§14.8/§14.9.3 讲过为什么它们只能是 per-mount）。

## 3. 逐项对账：`size=` 就是 `f_blocks × f_frsize`

这一节最能说明「选项字符串与 `statfs` 是同一件事的两种表示」：

<!--OUT:c14_10_tmpfs|after=③ statfs,until=④ 四个路径-->

```text
  f_type    = 0x1021994 (tmpfs)
  f_bsize   = 4096   f_frsize = 4096
  f_blocks  = 5120   f_bfree = 5120   f_bavail = 5120
  f_files   = 100   f_ffree = 99
  f_namelen = 255
  f_blocks × f_frsize = 20971520 字节 (20.00 MiB)
  super opts 的 size=20480k = 20971520 字节 (20.00 MiB)
  校验 1（容量）: 两者完全一致 ✔ —— size= 就是 f_blocks × f_frsize
  super opts 的 nr_inodes=100
  校验 2（inode 数）: 与 f_files 完全一致 ✔ —— nr_inodes= 就是 f_files
  ↑ 结论：tmpfs 的容量与 inode 上限是**挂载时定死的两个数**，
    不是「动态探测磁盘」。所以 tmpfs 上的 write 失败理由是 ENOSPC，
    但原因可能是**块用完了**，也可能是**inode 用完了**（两者要分开看）。
```

对账结果（**两条都完全一致**）：

| 挂载选项（super 栏） | `statfs()` 字段 | 校验 |
|---------------------|----------------|------|
| `size=20480k` = `20971520` 字节 | `f_blocks(5120) × f_frsize(4096)` = `20971520` | ✔ 20.00 MiB |
| `nr_inodes=100` | `f_files = 100` | ✔ |

**所以 tmpfs 上的 `write()` 报 `ENOSPC` 有两种完全不同的原因**：

- **块用完了**（`f_bfree == 0`）
- **inode 用完了**（`f_ffree == 0`）

两者要分开监控。极端例子：本机 `/tmp` 的 `nr_inodes=100`，在 20 MiB 容量下**建 100 个空文件就会耗尽 inode**，而此时还有 20 MiB「空间」—— `df -h` 会显示「还有 99% 可用」，`open(O_CREAT)` 却报 `ENOSPC`。

## 4. `fsid`：判断「是不是同一个超级块」的唯一判据

这一节是本篇的**核心**：

<!--OUT:c14_10_tmpfs|after=④ 四个路径,until=⑤ 没有 size-->

```text
  /      f_type=0x01021994  fsid=7c6ce3ea,05539714  blocks=1949384   files=1949384  
  /dev   f_type=0x01021994  fsid=f6a84c15,3505e34a  blocks=1949384   files=1949384  
  /tmp   f_type=0x01021994  fsid=b0beb878,9982e2d5  blocks=5120      files=100      
  /sys   f_type=0x01021994  fsid=7c6ce3ea,05539714  blocks=1949384   files=1949384  
  ↑ 判据是 **fsid**（超级块的身份证），不是路径，也不是 f_type。
    · / 与 /dev 与 /tmp 的 fsid 两两不同 ⇒ 三个**独立**的 tmpfs 实例
    · /sys 的 fsid 与 / **完全相同** ⇒ /sys 只是 / 上的一个空目录，
      **sysfs 根本没挂**。所以 /sys/fs、/sys/dev/block 这类路径都不存在
      —— 「路径存在 ≠ 那个文件系统已挂载」，这是 mount 命名空间最容易骗人的地方。
    · 另外注意 / 与 /dev 的 f_files == f_blocks：来自
      mm/shmem.c:139-145 的 min3(nr_pages - totalhigh_pages(), nr_pages / 2, ...)，
      64 位无 highmem 机器上 totalhigh_pages()==0，取到的就是 nr_pages/2。
```

读法：

| 路径 | `f_type` | `fsid` | 结论 |
|------|----------|--------|------|
| `/` | `0x01021994` | `7c6ce3ea,05539714` | tmpfs 实例 **A** |
| `/dev` | `0x01021994` | `f6a84c15,3505e34a` | tmpfs 实例 **B**（独立） |
| `/tmp` | `0x01021994` | `b0beb878,9982e2d5` | tmpfs 实例 **C**（独立） |
| `/sys` | `0x01021994` | `7c6ce3ea,05539714` | **与 `/` 完全相同** ⇒ 就是 `/`！ |

**四条结论**：

1. **`f_type` 相同不代表同一个实例** —— `/`、`/dev`、`/tmp` 三个 `f_type` 一样但 `fsid` 两两不同。
2. **`fsid` 相同才是同一个超级块** —— `/sys` 与 `/` 的 `fsid` **一模一样**，所以 `/sys` 只是 `/` 上的一个**空目录**。
3. **由此推出「sysfs 根本没挂」** —— 所以 `/sys/dev/block` 这类路径不存在（§14.2 的 ⑥ 段用 `errno=2` 也证明了这一点，这里是更硬的证据）。
4. **「路径存在 ≠ 文件系统已挂载」** —— 这是挂载命名空间最容易骗人的地方。`/sys` 是容器 rootfs 里预先 `mkdir` 出来的空目录，没有任何东西挂在上面。

> 顺带解释输出里那句「`/` 与 `/dev` 的 `f_files == f_blocks`」：`mm/shmem.c:139-145` 的默认 inode 上限是
> `min3(nr_pages - totalhigh_pages(), nr_pages / 2, ULONG_MAX / BOGO_INODE_SIZE)`。
> 64 位无 highmem 的机器上 `totalhigh_pages() == 0`，取到的就是 `nr_pages / 2`；而块数上限也是 `totalram_pages() / 2`（`mm/shmem.c:134-137`）—— **两者都是「内存页数的一半」，所以在这些实例上恰好相等**。

## 5. 没有 `size=` 时的默认上限：由内存决定

<!--OUT:c14_10_tmpfs|after=⑤ 没有 size,until=⑥ 在 /tmp-->

```text
  MemTotal        = 15595076 kB = 15969357824 字节
  MemTotal / 2    = 7984678912 字节
  / 的容量上限    = 7984676864 字节 (7.44 GiB)  [f_blocks × f_frsize]
  比值            = 100.00%
  MemAvailable    = 13989180 kB   Shmem = 2224 kB
  → 本机上二者**恰好相等**：totalram_pages() 恰好等于 MemTotal/4096，
     所以「默认上限 = 物理内存的一半」在这里是**精确**成立的。
    无论哪种情况，`size=` 缺省时 tmpfs 的上限都**由内存决定、与磁盘无关**，
     这就是它和 ext4（上限来自块设备容量）最根本的差别。
  对照：/tmp 有显式 size=20480k ⇒ 上限 20 MiB，与内存大小无关（见 ③）。
        /dev 没有 size= ⇒ 上限同样是「默认值」（见 ④ 的 blocks 一列）。
```

| 量 | 实测 |
|----|------|
| `MemTotal` | `15595076 kB` = `15969357824` 字节 |
| `MemTotal / 2` | `7984678912` 字节 |
| `/` 的容量上限（`f_blocks × f_frsize`） | `7984676864` 字节（7.44 GiB） |
| 比值 | **100.00%** |
| `MemAvailable` / `Shmem` | `13989180 kB` / `2224 kB` |

本机上二者**恰好相等**（差的那 2048 字节来自内核按页取整）。这是 `mm/shmem.c:134-137` 的直接后果：

```c
static unsigned long shmem_default_max_blocks(void)
{
	return totalram_pages() / 2;
}
```

**无论是否恰好相等，结论都一样**：`size=` 缺省时 tmpfs 的上限**由内存决定、与磁盘无关** —— 这就是它与 ext4（上限来自块设备容量）最根本的差别。

对照：

| 实例 | `size=` | 上限 |
|------|---------|------|
| `/tmp` | 显式 `size=20480k` | **20 MiB**，与内存无关 |
| `/`、`/dev` | 无 | 内存的一半 |
| `/sys` | — | 它就不是独立的 tmpfs（见第 4 节） |

> `Shmem = 2224 kB` 是 `/proc/meminfo` 里 tmpfs 内容占用的页（`Documentation/filesystems/tmpfs.rst:37-38`：**all tmpfs pages will be shown as "Shmem" in /proc/meminfo**）。所以「tmpfs 到底吃了多少内存」看这一栏，不要看 `free` 的 `buff/cache` 猜。

## 6. `f_bfree` 与 `f_ffree` 是两条独立的线

<!--OUT:c14_10_tmpfs|after=⑥ 在 /tmp,until=⑦ 本容器-->

```text
  write(1048576 字节) 返回 1048576
  f_bfree: 5120 -> 4864  (差 -256 块 = -1048576 字节)
  f_ffree: 99 -> 98  (差 -1)
  ↑ 1 MiB / 4096 = 256 块 —— 块数与 inode 数是**两条独立的线**。
    inode 只在**创建**时消耗（与文件大小无关），块在**写数据**时消耗。
  已删除 /tmp/c14_10_tmpfs_probe.bin
  删除后 f_bfree = 5120, f_ffree = 99（回到初始值附近）
```

| 量 | 变化 | 说明 |
|----|------|------|
| `f_bfree` | `5120 → 4864`（**-256 块**） | `1048576 / 4096 = 256` —— 写数据消耗**块** |
| `f_ffree` | `99 → 98`（**-1**） | 只消耗了**一个** inode（文件只有一个） |
| 删除后 | `f_bfree = 5120`、`f_ffree = 99` | 都回到初始值附近 |

**这张对照表值得背**：**inode 在「创建」时消耗，块在「写数据」时消耗。** 所以：

- 建 10000 个小空文件 → `f_ffree` 掉 10000，`f_bfree` 几乎不动（每个文件至少一格目录项，但目录项算块）。
- 往一个文件里写 1 GiB → `f_bfree` 掉 262144 块，`f_ffree` 一点不掉。

> 输出里写的是「回到初始值附近」而不是「完全等于」—— 因为**目录本身**也占块（`/tmp` 下多了一个目录项，删除后目录块的释放时机取决于实现）。这种「差一点点」的诚实标注比「完全恢复」更可靠。

## 完整源码

完整源码 [`code/c14_10_tmpfs.c`](../code/c14_10_tmpfs.c)：

```c
/* c14_10_tmpfs.c —— TLPI §14.10 A Virtual Memory File System: tmpfs
 *
 *  tmpfs 的数据不落在任何块设备上，而是**匿名页**（可被换出到 swap）。
 *  所以它的容量上限不是「磁盘剩余空间」，而是两个挂载选项：
 *      -o size=<N>        块数上限（默认 = 物理内存的一半）
 *      -o nr_inodes=<N>   inode 数上限（默认按内存页数推算）
 *  源码坐标（Linux v6.6）：
 *      mm/shmem.c:134-137   shmem_default_max_blocks()  → totalram_pages() / 2
 *      mm/shmem.c:139-145   shmem_default_max_inodes()  → min3(nr_pages - totalhigh_pages(),
 *                                                            nr_pages / 2,
 *                                                            ULONG_MAX / BOGO_INODE_SIZE)
 *
 *  本 demo 用容器里现成的三个 tmpfs 实例（/、/dev、/tmp）做六件事：
 *    ① /proc/filesystems 里 tmpfs 的登记（`nodev` 前缀是什么意思）
 *    ② /tmp 的 mountinfo 记录逐字段拆解（source 是 none，super opts 带 size=/nr_inodes=）
 *    ③ statfs("/tmp") 的 blocks/files 与 size=20480k / nr_inodes=100 逐项对账
 *    ④ 三个实例的 fsid 两两不同 ⇒ 三个独立超级块；
 *       而 /sys 的 fsid 与 / **完全相同** ⇒ /sys 只是 / 上的一个空目录，
 *       并没有挂 sysfs —— 「路径存在 ≠ 那个文件系统已挂载」的实证
 *    ⑤ 默认上限与 RAM 的关系（读 /proc/meminfo 的 MemTotal 现场算比值，
 *       并按实测比值决定结论文字 —— 不同宿主机上这个比值可能是 100.00%）
 *    ⑥ 在 /tmp 里真写一个 1 MiB 文件，看 f_bfree 与 f_ffree 两条线各自怎么动
 *
 *  ⚠️ tmpfs 的内容在内存里，掉电即失；本容器**无法演示重启**，所以「不落盘」
 *     这一条只能靠源码与参数说明，不能靠实测断言。
 *
 *  编译：gcc -O0 -Wall -Wextra -o c14_10 c14_10_tmpfs.c
 */
#include <sys/statfs.h>
#include <sys/types.h>
#include <errno.h>
#include <fcntl.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <unistd.h>

#define MAXLINE 1024
#define TMPFS_MAGIC 0x01021994

static void sec(const char *t)
{
    printf("\n== %s ==\n", t);
}

static void human(unsigned long long b, char *out, size_t n)
{
    if (b >= (1ULL << 30))
        snprintf(out, n, "%.2f GiB", (double)b / (double)(1ULL << 30));
    else if (b >= (1ULL << 20))
        snprintf(out, n, "%.2f MiB", (double)b / (double)(1ULL << 20));
    else
        snprintf(out, n, "%llu B", b);
}

static int slurp(const char *path, char *buf, size_t n)
{
    int fd = open(path, O_RDONLY);
    ssize_t r;

    if (fd == -1)
        return -1;
    r = read(fd, buf, n - 1);
    close(fd);
    if (r < 0)
        return -1;
    buf[r] = '\0';
    return 0;
}

/* /proc/meminfo 的值都是 kB；找不到返回 0 */
static unsigned long meminfo_kb(const char *key)
{
    static char buf[8192];
    char *p;

    if (slurp("/proc/meminfo", buf, sizeof(buf)) == -1)
        return 0;
    p = strstr(buf, key);
    if (p == NULL)
        return 0;
    return strtoul(p + strlen(key), NULL, 10);
}

/* 在 /proc/self/mountinfo 里按 mount point 精确查找一条记录。
 * 记录格式：[id] [parent] [maj:min] [root] [mount point] [opts] [optional-fields]... - [fstype] [source] [super-opts] */
static int mi_record(const char *mp, char *opts, size_t no, char *fstype, size_t nf,
                     char *sopts, size_t ns, char *lineout, size_t nl)
{
    FILE *fp = fopen("/proc/self/mountinfo", "r");
    char line[MAXLINE];
    int found = -1;

    if (fp == NULL)
        return -1;
    while (fgets(line, sizeof(line), fp) != NULL) {
        char orig[MAXLINE];
        char *tok[16];
        int nt = 0, dash = -1;
        char *p = line;
        size_t L = strlen(line);

        if (L > 0 && line[L - 1] == '\n')
            line[L - 1] = '\0';
        /* 分词会往 line 里插 NUL，所以先把原始整行留一份用来打印 */
        snprintf(orig, sizeof(orig), "%s", line);
        while (*p != '\0' && nt < 16) {
            while (*p == ' ')
                p++;
            if (*p == '\0')
                break;
            tok[nt++] = p;
            while (*p != '\0' && *p != ' ')
                p++;
            if (*p != '\0')
                *p++ = '\0';
        }
        if (nt < 10 || strcmp(tok[4], mp) != 0)
            continue;
        for (int i = 0; i < nt; i++)
            if (!strcmp(tok[i], "-")) {
                dash = i;
                break;
            }
        if (dash < 0)
            continue;
        snprintf(opts, no, "%s", tok[5]);
        if (dash + 1 < nt)
            snprintf(fstype, nf, "%s", tok[dash + 1]);
        if (dash + 3 < nt)
            snprintf(sopts, ns, "%s", tok[dash + 3]);
        snprintf(lineout, nl, "%s", orig);
        found = 0;
        break;
    }
    fclose(fp);
    return found;
}

/* 从 "rw,size=20480k,nr_inodes=100,..." 里取出 name= 后面的值（不含逗号） */
static int opt_value(const char *sopts, const char *name, char *out, size_t n)
{
    const char *p = sopts;
    size_t len = strlen(name);

    while ((p = strstr(p, name)) != NULL) {
        if (p == sopts || p[-1] == ',') {
            const char *v = p + len;
            const char *end = strchr(v, ',');
            size_t L = end ? (size_t)(end - v) : strlen(v);
            if (L >= n)
                L = n - 1;
            memcpy(out, v, L);
            out[L] = '\0';
            return 0;
        }
        p += len;
    }
    return -1;
}

/* "20480k" / "16m" / "100" -> 字节数（无后缀按字节）；返回 -1 表示不是 size 值 */
static long long opt_bytes(const char *v)
{
    char *end = NULL;
    long long x = strtoll(v, &end, 10);

    if (end == NULL || end == v || x < 0)
        return -1;
    if (*end == '\0')
        return x;
    if ((*end == 'k' || *end == 'K') && end[1] == '\0')
        return x * 1024;
    if ((*end == 'm' || *end == 'M') && end[1] == '\0')
        return x * 1024 * 1024;
    if ((*end == 'g' || *end == 'G') && end[1] == '\0')
        return x * 1024LL * 1024 * 1024;
    return -1;
}

static unsigned long long fsbytes(const struct statfs *sf)
{
    unsigned long long fr = sf->f_frsize ? (unsigned long long)sf->f_frsize
                                        : (unsigned long long)sf->f_bsize;
    return (unsigned long long)sf->f_blocks * fr;
}

{
```

## 常见坑

| # | 坑 | 正解 |
|---|----|------|
| 1 | 把 tmpfs 当「磁盘」估容量 | 没写 `size=` 时上限是**内存的一半**（`mm/shmem.c:136`），与磁盘无关 |
| 2 | 只看 `df -h` 判断 tmpfs 是否写满 | **inode 也可能是瓶颈**。本机 `/tmp` 只有 100 个 inode，`df` 显示 99% 空闲时 `open(O_CREAT)` 已可能 `ENOSPC` |
| 3 | 以为 `f_type` 相同就是同一个文件系统 | 必须比 **`fsid`**。本机 `/`、`/dev`、`/tmp` 三个 `f_type` 相同、`fsid` 两两不同 |
| 4 | 用 `stat("/sys")` 成功来判断 sysfs 已挂 | `/sys` 与 `/` 的 `fsid` **相同** ⇒ 那只是 `/` 上的空目录，sysfs 从未挂载 |
| 5 | 以为 tmpfs 内容一定会被换出 | `tmpfs.rst:14-17` 写的是 **if swap was enabled for the tmpfs mount** —— 有条件。默认装配下不一定 |
| 6 | 到 `free` 的 `buff/cache` 里找 tmpfs 占用 | 看 `/proc/meminfo` 的 **`Shmem`** 栏（`tmpfs.rst:37-38`） |
| 7 | 以为 `nr_inodes=` 是「最多能放多少文件」的精确值 | 它是 inode 总数的硬上限，但**目录、符号链接、设备节点也都各占一个 inode**。实际能放的文件更少 |
| 8 | 以为 tmpfs 挂载需要设备名 | `source` 写 `none` 即可；`nodev` 前缀就是「不需要块设备」的标记 |
| 9 | 以为 `size=` 是 per-mount 选项 | 它在 **super options** 栏。所以同一个 tmpfs 超级块的所有挂载点**共享**这个上限 |
| 10 | 以为卸载后「空间被释放」用 `df` 看就行 | 卸载会丢掉**全部内容**（`tmpfs.rst:10-17`）。别把它当缓冲层用 |

## HFT / 嵌入式关联

| 场景 | 结论怎么用 |
|------|-----------|
| **热数据放 tmpfs，但必须算内存账** | tmpfs 页算在 `Shmem` 里，**和进程匿名页竞争同一份内存**。放多少 tmpfs 数据 = 少多少进程可用内存。用 `/proc/meminfo` 的 `Shmem` 监控，不要凭目录名猜 |
| **tmpfs 写失败有两种原因** | 块满 vs inode 满。监控脚本必须**两个都看**（`f_bfree` 与 `f_ffree`），否则「还有空间却写不进去」会变成悬案 |
| **`/dev/shm` 是 POSIX 共享内存的落点** | `shm_open()` 的实现在 `/dev/shm`（tmpfs）。所以「共享内存段」在 `/proc/meminfo` 里也是 `Shmem`。容器默认 `/dev/shm` 往往只有 64 MiB —— 这是容器里跑多进程共享内存程序最经典的坑 |
| **嵌入式 tmpfs 大小要显式写死** | 产品上 `/tmp` 必须 `size=`（本机 `/tmp` 就是 20 MiB）：否则一个日志写飞就吃掉半个内存，直接 OOM。**`nr_inodes=` 也建议显式给**，防止 inode 被刷满 |
| **掉电安全的边界** | tmpfs 上的数据 100% 会丢。嵌入式上「配置/密钥写 `/etc`」如果 `/etc` 是 tmpfs，重启即失 —— 这是「改了配置不生效」的常见原因 |
| **`fsid` 判重的实战用法** | 想确认「这两个目录是不是同一个 tmpfs」：比 `statfs` 的 `fsid`，不要比 `f_type`、不要比路径、更不要比 `df` 输出。本笔记 `/sys` 的例子就是「路径看着像独立文件系统、实际是空目录」 |
| **swap 与 tmpfs 的耦合** | 有 swap 时 tmpfs 可以换出，于是「内存盘」不再保证低延迟（换出后访问要读盘）。HFT 的延迟敏感场景应当**禁用 swap**，或者接受「tmpfs 可能被换出」这个风险 |

<details>
<summary>代码自测（Q&A）</summary>

**Q1：怎么证明 `/sys` 上的 sysfs 其实没挂？**

A：`statfs("/sys").fsid` 与 `statfs("/").fsid` **完全相同**（本机都是 `7c6ce3ea,05539714`）—— 同一个超级块 ⇒ `/sys` 只是 `/` 上的一个空目录。旁证：`/sys/dev`、`/sys/block` 都是 `ENOENT(2)`（§14.2 的 ⑥ 段）。**判据是 `fsid`，不是 `f_type`，也不是路径是否存在。**

**Q2：`/tmp` 的 `size=20480k` 与 `statfs` 的哪个字段对应？**

A：`f_blocks × f_frsize`。本机 `5120 × 4096 = 20971520 = 20480 × 1024`，完全一致。同理 `nr_inodes=100` 对应 `f_files = 100`。所以挂载选项与 `statfs` 字段是**同一件事的两种表示**。

**Q3：写了 1 MiB 到 `/tmp`，为什么 `f_bfree` 掉 256 而 `f_ffree` 只掉 1？**

A：`1048576 / 4096 = 256` 块；而 inode **只在创建文件时消耗一次**，与写入多少数据无关。本机实测：`f_bfree 5120→4864`、`f_ffree 99→98`。这条对照说明「块」与「inode」是两条独立的线。

**Q4：tmpfs 没写 `size=` 时上限是多少？**

A：`totalram_pages() / 2`（`mm/shmem.c:134-137`）。本机实测 `/` 的上限刚好等于 `MemTotal/2`（比值 100.00%）。所以它**由内存决定**，与磁盘无关；而 `/tmp` 显式写了 `size=20480k`，上限就是 20 MiB，与内存无关。

**Q5：tmpfs 的 inode 默认上限是怎么算的？**

A：`mm/shmem.c:139-145`：`min3(nr_pages - totalhigh_pages(), nr_pages / 2, ULONG_MAX / BOGO_INODE_SIZE)`。64 位无 highmem 的机器上 `totalhigh_pages() == 0`，取到 `nr_pages / 2` —— 和块数上限相同，所以本机 `/` 与 `/dev` 的 `f_files == f_blocks`。

**Q6：`/proc/meminfo` 里哪一栏是 tmpfs 的占用？**

A：**`Shmem`**（`tmpfs.rst:37-38`：all tmpfs pages will be shown as "Shmem" in /proc/meminfo）。`/dev/shm` 的 POSIX 共享内存也算在这里。不要从 `buff/cache` 去反推。

**Q7：tmpfs 的内容会不会被换出到 swap？**

A：**有条件**。`tmpfs.rst:14-17` 说的是 `is able to swap unneeded pages out to swap space, **if swap was enabled for the tmpfs mount**`。本容器没有任何 swap（`SwapTotal` 为 0），所以这两件事都测不了 —— 建议的严谨写法是标注「依据官方文档，未实测」。
