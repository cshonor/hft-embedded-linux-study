# 14.10 A Virtual Memory File System: tmpfs

> 本章：[TLPI 第 14 章 — File Systems](./README.md)

## 本节讲什么

介绍 tmpfs——Linux 基于内存的虚拟文件系统。文件数据完全驻留在页缓存中，不写磁盘，重启后数据丢失。

## 要点

### tmpfs 特性

| 特性 | 说明 |
|------|------|
| 存储介质 | 内存（RAM）+ swap（可能换出） |
| 持久性 | 无（重启丢失） |
| 速度 | 接近内存读写速度 |
| 大小限制 | 挂载时指定 `size=`，默认为 RAM 的 50% |
| 特殊用途 | `/tmp`、`/dev/shm`、`/run`、`/sys/fs/cgroup` |

### tmpfs vs ramfs vs 磁盘文件系统

| 特性 | tmpfs | ramfs | ext4 |
|------|-------|-------|------|
| 存储 | RAM + swap | RAM only | 磁盘 |
| 大小限制 | 有（size=） | 无（可能 OOM） | 磁盘大小 |
| Swap | 支持 | 不支持 | — |
| 持久性 | 无 | 无 | 有 |
| 用途 | /tmp, /dev/shm | 内核内部 | 通用 |

### 挂载选项

```bash
# 基本挂载
mount -t tmpfs -o size=1G tmpfs /mnt/tmp

# 常见选项
mount -t tmpfs -o size=512M,mode=1777,uid=1000,gid=1000 tmpfs /mnt/tmp
```

| 选项 | 默认 | 说明 |
|------|------|------|
| `size=N` | RAM 50% | 最大容量 |
| `nr_blocks=N` | — | 最大块数 |
| `nr_inodes=N` | — | 最大 inode 数 |
| `mode=NNN` | 1777 | 权限 |
| `uid=N` | 0 | 属主 UID |
| `gid=N` | 0 | 属组 GID |
| `mpol=...` | — | NUMA 策略 |

### 系统默认 tmpfs 挂载

| 挂载点 | 用途 | 典型大小 |
|--------|------|---------|
| `/dev/shm` | POSIX 共享内存 | RAM 的 50% |
| `/run` | 运行时文件（PID 等） | RAM 的 5-10% |
| `/tmp` | 临时文件（部分发行版） | RAM 的 50% |
| `/sys/fs/cgroup` | cgroup2 | 小 |

### tmpfs 内存使用

```
写入 1GB 文件到 tmpfs:
  → 页缓存分配 1GB（匿名页）
  → 如果 RAM 不足 → 换出到 swap
  → 读取时从 swap 换回 RAM
  → umount / 删除 → 立即释放
```

- tmpfs 页面标记为匿名页（anonymous page），可被换出
- `free -m` 中的 `shared` 列包含 tmpfs 占用
- `df` 命令显示 tmpfs 使用量

## HFT / 嵌入式关联

- **共享内存**：`/dev/shm` 是 POSIX `shm_open` 的默认路径，HFT 进程间共享行情数据
- **临时数据**：HFT 回测中间结果放 `/tmp`（tmpfs），避免磁盘 I/O
- **NUMA**：`mpol=bind:0` 绑定 tmpfs 到特定 NUMA 节点，减少跨节点访问延迟
- **嵌入式**：无磁盘的嵌入式系统用 tmpfs 作为可写文件系统
- **启动加速**：init 脚本 tmp 文件放 tmpfs，启动更快
- **容量控制**：HFT 场景下 tmpfs size 不可过大，防止挤压行情数据

## 代码示例

```bash
# 检查 tmpfs 使用情况
df -h /dev/shm /tmp /run

# 挂载 tmpfs
sudo mount -t tmpfs -o size=2G,mode=1777 tmpfs /mnt/hft_shm

# /etc/fstab 永久挂载
tmpfs /mnt/hft_shm tmpfs size=2G,mode=1777,mpol=bind:0 0 0

# 查看进程的 tmpfs 文件
lsof /dev/shm
```

```c
/* 在 tmpfs 上创建文件 */
int fd = open("/dev/shm/market_data", O_CREAT|O_RDWR, 0644);
ftruncate(fd, 4096 * 1024);  /* 4MB */
void *p = mmap(NULL, 4096*1024, PROT_READ|PROT_WRITE, MAP_SHARED, fd, 0);
/* 多进程通过 /dev/shm/market_data 共享内存 */
```

## 代码自测

<details>
<summary>1. tmpfs 和 ramfs 的区别？为什么 tmpfs 更常用？</summary>

- **ramfs**：纯内存，无大小限制，可能导致 OOM（持续分配直到耗尽 RAM，无法回收）
- **tmpfs**：有大小限制（`size=`），支持 swap 换出，可控制用量

tmpfs 更常用因为：(1) 有大小限制防止 OOM；(2) 支持 swap，内存压力时可以换出；(3) 内核维护统计信息；(4) 是 tmpfs 而非 ramfs 被用于 `/tmp`/`/dev/shm`/`/run`。
</details>

<details>
<summary>2. tmpfs 中的文件被 swap out 后，性能有什么影响？</summary>

tmpfs 页面被换出后，读取需要从 swap 空间换回 RAM，产生磁盘 I/O 延迟（如果 swap 在 SSD 上约 50-100μs，HDD 上约 5-10ms）。对于 HFT 场景，这可能导致微秒级操作突然变成毫秒级延迟。因此 HFT 系统：(1) 关闭 swap（`swapoff -a`）；(2) 限制 tmpfs 大小；(3) 用 `mlock` 锁定关键共享内存。
</details>

<details>
<summary>3. 如何限制 tmpfs 的 inode 数量？为什么需要限制？</summary>

`mount -t tmpfs -o nr_inodes=10000 tmpfs /mnt/tmp`。限制 inode 防止大量小文件耗尽内存（每个 inode 占用约 320 字节内核内存）。恶意程序可以创建大量小文件消耗系统内存，限制 inode 数量是一种防护。
</details>
