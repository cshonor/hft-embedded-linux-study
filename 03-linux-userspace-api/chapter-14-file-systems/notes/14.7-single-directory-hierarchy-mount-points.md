## 本节讲什么

Unix 最优雅的设计之一：**所有文件系统都被挂到一棵树上**，没有「盘符」。这一节钉四件事：

1. **`/proc/self/mountinfo` 是唯一权威的「现在挂了什么」判据**（不是 `/etc/mtab`、不是目录是否存在）。它的字段比 `/proc/mounts` 多得多，能做 `mounts` 做不到的判定。
2. **挂载点下面原来的内容被「遮盖」**，不是被删除。卸载后原样回来 —— 这意味着「被遮盖的目录里原来有什么」是不可见的（只有 bind mount 的手法才用得上）。
3. **`root` ≠ `/` 就是 bind mount 的指纹**。本容器里有 **10 个挂载点共用同一个设备 `259:2`**，还有**单文件 bind**（`/etc/passwd`）。
4. **`stat().st_dev` 与 `mountinfo` 的 `major:minor` 是同一个数**（同一台机器上必然相等）。这条纠正了一个常见的过度解读。

## 1. `mountinfo` 的逐字段拆解

`/proc/self/mountinfo` 每行有 **10 个固定字段 + 可变长度的 optional fields**（以 `-` 分隔）。用 `/lib` 这一行看：

<!--OUT:c14_7_mount_points|after=① 一条 mountinfo,until=② 全部挂载点-->

```text
  原始字段：
    mount ID     = 964
    parent ID    = 963
    major:minor  = 259:2
    root         = /usr/lib
    mount point  = /lib
    mnt options  = ro,relatime
    opt fields   = master:1
    fstype       = ext4
    source       = /dev/root
    super opts   = rw,discard,errors=remount-ro,commit=30
```

| 字段 | 实测值 | 含义 | 谁在 `mounts` 里没有 |
|------|--------|------|---------------------|
| **mount ID** | `964` | 这个挂载点的唯一 ID | ✗ `mounts` 没有 |
| **parent ID** | `963` | 父挂载点 ID —— **据此能还原挂载树** | ✗ |
| **major:minor** | `259:2` | 这个挂载点后面那个**超级块**的设备号 | ✗ |
| **root** | `/usr/lib` | **被挂载的是源文件系统里的哪棵子树**。不等于 `/` 就是 bind mount | ✗ |
| **mount point** | `/lib` | 挂在哪儿 | ✓ |
| **mnt options** | `ro,relatime` | **per-mount** 选项（每个挂载点各自一份） | 部分 |
| **opt fields** | `master:1` | 可变长度段：`master:N` = **共享挂载**（propagation）的 peer group ID；还有 `shared:`/`propagate_from:`/`unbindable` | ✗ |
| **fstype** | `ext4` | 文件系统类型 | ✓ |
| **source** | `/dev/root` | 挂载源（**内核给的名字**，不一定是真实设备节点） | ✓ |
| **super opts** | `rw,discard,errors=remount-ro,commit=30` | **superblock 级**选项（同一超级块的所有挂载点共享） | 部分 |

**「`dev` 字段」的坑**：`mounts` 第 1 列那个 `dev` 是「源设备的 `major:minor`」，而 `mountinfo` 里这个位置是「**挂载点背后超级块的** `major:minor`」—— 在 bind mount 上两者**完全不同**（源的设备号 vs 目标超级块的号）。做判定必须用 `mountinfo`。

### 为什么 `source` 是 `/dev/root`？

因为内核给根文件系统起名叫 `/dev/root`（这是 `root=` 的默认值）。真实设备是 `/dev/nvme0n1p1` 之类，但容器里 `/dev` 下根本没有块设备节点（§14.1 实测）。**`source` 只是一个字符串，不代表这个路径现在可用**。

>
> ⚠️ **`/cefs` 那 30 行是 CE 的编译器镜像**（每个编译器/库一个 squashfs）。它们**每次运行都可能不同**（镜像滚动更新）⇒ 写进笔记的只能是「结构」，具体名字随时会变。

## 3. 同一个设备挂到多个挂载点 = bind mount 的指纹

把「设备号出现几次」数出来，bind mount 就自己冒出来了：

<!--OUT:c14_7_mount_points|after=③ 同一设备,until=④ 两个挂载点-->

```text
  259:2     出现 10 次：/lib /usr/lib /usr/share/zoneinfo /etc/localtime /lib64 /lib32 /usr/bin/stdbuf /usr/libexec/coreutils/libstdbuf.so /usr/local/bin/dumb-init /app
  0:69      出现  2 次：/etc/passwd /etc/shadow
  0:7       出现  4 次：/dev/null /dev/zero /dev/random /dev/urandom
```

| 设备号 | 出现次数 | 这些挂载点是什么 |
|--------|---------|----------------|
| `259:2` | **10** | 同一个 ext4 超级块被 bind 到 10 个路径。其中 `/lib` / `/usr/lib` 是「同一棵子树投两次」，`/app` 是「投的是 `/tmp/compiler-explorer-compilerXXXXXX`」 |
| `0:69` | 2 | `/etc/passwd` / `/etc/shadow` —— 两个**内容不同**的单文件 bind（看 `root=` 就分得开：`/dynamic_file.1` vs `/dynamic_file.2`） |
| `0:7` | 4 | `/dev/null` 等四个设备节点，全来自同一个 devtmpfs |

**「同一个 `major:minor` 出现多次」不一定是 bind mount** —— 同一块盘可以被挂多次（`mount /dev/sda1 /mnt/a; mount /dev/sda1 /mnt/b`），那也是同一个设备号。要区分「是不是 bind」，看 **`root` 字段是否等于 `/`**（§14.9.4 专门讲这个判据）。

## 4. `root` 字段 + `st_ino`：同一棵子树被投射了两次

单看设备号不够，「`root` 里写的是源文件系统的哪个子树」才是决议条件。④ 段用 `st_ino` 做交叉验证：

<!--OUT:c14_7_mount_points|after=④ 两个挂载点,until=⑤ 挂载遮盖-->

```text
  /lib      dev=259:2     ino=4243
  /usr/lib  dev=259:2     ino=4243   <<< 同一个 inode
  /lib64    或 /usr/lib64 stat 失败
  /lib32    或 /usr/lib32 stat 失败
```

`/lib` 与 `/usr/lib` 的 `st_ino` **完全相同（4243）**，且 `st_dev` 也相同 ⇒ 它们是**同一个 inode 的两个名字**（就是 §14.4 讲的硬链接的极端形态：同一个目录被 bind 到两个路径）。

这带来一个实际的排查工具：**「`/lib` 和 `/usr/lib` 到底是同一份还是两份？」** 不要看内容、不要看大小 —— 比 `st_dev` 与 `st_ino`。都相同就是同一个对象。

> `/lib64` / `/lib32` 在本机 `stat` 失败（那是「或」路径，两个都不存在）—— 说明 `mountinfo` 里列出的挂载点**不保证路径可达**（这里是因为 `stat` 走的是「`/lib64` **或** `/usr/lib32`」的探测写法，两者都不在）。这也是一条值得记住的边界：**`mountinfo` 反映的是挂载表，不是「路径一定存在」**。

## 5. 挂载遮盖：被盖住的东西你看不到

`/etc/passwd` 这一行是全篇最有教育意义的一条：

<!--OUT:c14_7_mount_points|after=⑤ 挂载遮盖,until=⑥ 核对-->

```text
  /etc/passwd              root=/dynamic_file.1//deleted         fstype=tmpfs source=none
  /etc/shadow              root=/dynamic_file.2//deleted         fstype=tmpfs source=none
  stat(/etc/passwd) 看到的是 dev=0:69 ino=2 —— 即上面那条挂载的内容
  ↑ root 里的 "//deleted" 表示源在宿主上**已经被删除**，只剩打开着的引用；
    这是「用挂载把单个文件换掉」的手法（容器给 /etc/passwd 注入口令的做法）。
```

三件事一起看：

1. **`root=/dynamic_file.1//deleted`** —— 源文件在宿主上**已经被 `unlink`**，只剩一个打开着的引用（§14.4 讲的 `nlink=0`）。内核在 `d_path()` 时给这种 dentry 加上 `//deleted` 标记。
2. **`source=none`、`fstype=tmpfs`** —— bind mount 的「源」不是设备，所以 `source` 是 `none`；超级块还是原来那个 tmpfs 的。
3. **`stat("/etc/passwd")` 看到 `dev=0:69 ino=2`** —— **不是**它所在的 `/etc` 目录（`/` 那个 tmpfs，`st_dev` 不同）。这就是「挂载遮盖」：`/etc/passwd` 这个路径名现在指向**挂载进去的那个 inode**，容器 rootfs 里原本的 `/etc/passwd` 依然存在但**永久不可见**（除非在另一个挂载命名空间里看）。

**这个手法的工程用途**：容器运行时想给一个容器换 `/etc/passwd`（注入口令/用户），不需要改镜像、不需要重建文件系统 —— 造一个临时文件，把它单向 bind 到 `/etc/passwd` 上就行。`unlink` 源文件还能避免「别的地方漏看到这个临时文件」。

## 6. `st_dev` 与 `mountinfo` 的 `major:minor`：同台机器上必然相等

关于这两个字段，网上常见一种说法是「语义不同，不能比较」。**本机实测证明那个说法是错的**（至少在这里）：

<!--OUT:c14_7_mount_points|after=⑥ 核对-->

```text
  mountinfo: /app 这一条的 major:minor = 259:2   （root=/tmp/compiler-explorer-compilerMUQsoS, fstype=ext4）
  stat():    stat("/app").st_dev 解出来 = 259:2
  ↑ 两个字段说的是**同一个 sb->s_dev**，不是两种编号：
    mountinfo 打印的是原始的 MAJOR:MINOR（fs/proc_namespace.c），
    stat() 交给你的是**编码过**的值（fs/stat.c 用 new_encode_dev），
    glibc 的 major()/minor() 就是那个编码的逆运算（__gnu_dev_major）。
    所以同一台机器上它们必然相等 —— 对不上就说明**不是同一个容器**。

=== c14_7 done ===
```

两处都是 `259:2`。原因在实现：

| | 打印的是什么 | 代码坐标 |
|---|---|---|
| `mountinfo` 的 `major:minor` | **原始**的 `MAJOR:MINOR`（直接用 `%u:%u` 打） | `fs/proc_namespace.c` 的 `show_mountinfo()` |
| `stat()` 的 `st_dev` | **编码过**的 `dev_t`（`new_encode_dev()`） | `fs/stat.c` 的 `vfs_getattr()` → `cp_statx()` |
| `major()` / `minor()` | 把上面那个编码**解回来** | glibc `sys/sysmacros.h` 的 `__gnu_dev_major`/`__gnu_dev_minor` |

`new_encode_dev()` 的编码是：低 8 位放 minor 的低 8 位，接着 12 位放 major，接着 12 位放 minor 的高位 —— 所以 `st_dev` 打印出来的**十进制数不是 `major:minor`**，但 `major(st_dev)` / `minor(st_dev)` 一定还原出 `mountinfo` 里的那两个数。

> ✅ **结论**：同一台机器、同一个挂载点上，「`mountinfo` 的 `major:minor`」与「`stat().st_dev` 解出来的 `major:minor`」**必须相等**；对不上就说明两次查询落在**不同的容器/命名空间**里（这正是 §14.2 那条「跨作业比较设备号无效」的另一种表现）。

## 完整源码

完整源码 [`code/c14_7_mount_points.c`](../code/c14_7_mount_points.c)：

```c
/* c14_7_mount_points.c —— TLPI §14.7 Single Directory Hierarchy and Mount Points
 *
 *  §14.7 的两个核心概念——「单一目录树」与「挂载点遮盖」——在用户态
 *  唯一的权威入口是 /proc/self/mountinfo。它不是一张平表，而是**一棵树**：
 *
 *    字段 1  = mount ID
 *    字段 2  = parent ID      → 这两个字段拼出挂载树的父子结构
 *    字段 3  = major:minor    → 设备号
 *    字段 4  = root           → 被挂载子树的**根**在源设备上的路径
 *    字段 5  = mount point    → 挂在当前目录树的哪个位置
 *    字段 6  = per-mount options（单挂载点选项）
 *    之后    = 0 个或多个 optional fields（propagation 信息）
 *    " - "   = 分隔符
 *    之后    = fstype / source / super options
 *
 *  本 demo 用四个实验把这棵树讲清：
 *    ① 取一条逐字段拆解
 *    ② 列出所有挂载点（mount point ← fstype source）
 *    ③ **同一设备挂到多个挂载点** —— bind mount 最硬的指纹
 *    ④ 两个路径 st_ino 相同 —— 证明是同一棵子树的两次投射
 *      （外加一个「单文件被 bind 覆盖」的真实例子：/etc/passwd）
 *
 *  编译：gcc -O0 -Wall -Wextra -o c14_7 c14_7_mount_points.c
 */
#define _GNU_SOURCE
#include <sys/stat.h>
#include <sys/sysmacros.h>
#include <sys/types.h>
#include <errno.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <unistd.h>

#define MAXLINE 4096
#define MAXREC  256

static void sec(const char *t)
{
    printf("\n== %s ==\n", t);
}

struct rec {
    char id[16], parent[16], dev[32], root[512], mp[512], opts[256];
    char fstype[64], source[256], sopts[512], optf[256];
};

static int split_line(char *line, struct rec *r)
{
    char *tok[64];
    int ntok = 0;
    char *p = line;
    int dash = -1;

    memset(r, 0, sizeof(*r));
    /* 按空格切 */
    while (*p != '\0' && ntok < 64) {
        while (*p == ' ')
            p++;
        if (*p == '\0')
            break;
        tok[ntok++] = p;
        while (*p != '\0' && *p != ' ')
            p++;
        if (*p != '\0')
            *p++ = '\0';
    }
    for (int i = 0; i < ntok; i++)
        if (!strcmp(tok[i], "-")) { dash = i; break; }
    if (ntok < 6 || dash < 6 || dash + 3 >= ntok) {
        /* dash+3 > ntok 时 source 可能为空，仍接受 */
        if (ntok < 6 || dash < 6)
            return -1;
    }
    snprintf(r->id, sizeof(r->id), "%s", tok[0]);
    snprintf(r->parent, sizeof(r->parent), "%s", tok[1]);
    snprintf(r->dev, sizeof(r->dev), "%s", tok[2]);
    snprintf(r->root, sizeof(r->root), "%s", tok[3]);
    snprintf(r->mp, sizeof(r->mp), "%s", tok[4]);
    snprintf(r->opts, sizeof(r->opts), "%s", tok[5]);
    /* 6..dash-1 是 optional fields，用逗号串起来 */
    r->optf[0] = '\0';
    for (int i = 6; i < dash; i++) {
        if (i > 6 && strlen(r->optf) + 1 < sizeof(r->optf))
            strncat(r->optf, ",", sizeof(r->optf) - strlen(r->optf) - 1);
        if (strlen(r->optf) + strlen(tok[i]) + 1 < sizeof(r->optf))
            strncat(r->optf, tok[i], sizeof(r->optf) - strlen(r->optf) - 1);
    }
    if (dash + 1 < ntok)
        snprintf(r->fstype, sizeof(r->fstype), "%s", tok[dash + 1]);
    if (dash + 2 < ntok)
        snprintf(r->source, sizeof(r->source), "%s", tok[dash + 2]);
    if (dash + 3 < ntok)
        snprintf(r->sopts, sizeof(r->sopts), "%s", tok[dash + 3]);
    return 0;
}

static int load(struct rec *recs)
{
    FILE *fp = fopen("/proc/self/mountinfo", "r");
    char line[MAXLINE];
    int n = 0;

    if (fp == NULL) {
        printf("  /proc/self/mountinfo 打不开 errno=%d (%s)\n", errno, strerror(errno));
        return 0;
    }
    while (fgets(line, sizeof(line), fp) != NULL && n < MAXREC) {
        size_t len = strlen(line);
        if (len > 0 && line[len - 1] == '\n')
            line[len - 1] = '\0';
        if (split_line(line, &recs[n]) == 0)
            n++;
    }
    fclose(fp);
    return n;
}

int main(void)
{
    static struct rec recs[MAXREC];
    int n = load(recs);

    if (n == 0) {
        printf("  没读到挂载信息\n");
        return 0;
    }

    /* ---------- ① 逐字段拆解 ---------- */
    sec("① 一条 mountinfo 的逐字段拆解");
    for (int i = 0; i < n; i++) {
        if (!strcmp(recs[i].fstype, "ext4")) {
            struct rec *r = &recs[i];
            printf("  原始字段：\n");
            printf("    mount ID     = %s\n", r->id);
            printf("    parent ID    = %s\n", r->parent);
            printf("    major:minor  = %s\n", r->dev);
            printf("    root         = %s\n", r->root);
            printf("    mount point  = %s\n", r->mp);
            printf("    mnt options  = %s\n", r->opts);
            printf("    opt fields   = %s\n", r->optf[0] ? r->optf : "（无）");
            printf("    fstype       = %s\n", r->fstype);
            printf("    source       = %s\n", r->source);
            printf("    super opts   = %s\n", r->sopts);
            break;
        }
    }

    /* ---------- ② 全部挂载点 ---------- */
    sec("② 全部挂载点（mount_point ← fstype source）");
    for (int i = 0; i < n; i++)
        printf("  %-40s %-10s %s\n", recs[i].mp, recs[i].fstype,
               recs[i].source[0] ? recs[i].source : "(无)");
    printf("  共 %d 个挂载点\n", n);

    /* ---------- ③ 同一设备、多个挂载点 ---------- */
    sec("③ 同一设备挂到多个挂载点 = bind mount 的指纹");
    {
        int used[MAXREC];
        memset(used, 0, sizeof(used));
        for (int i = 0; i < n; i++) {
            int cnt = 0;
            char list[1024];

            if (used[i])
                continue;
            list[0] = '\0';
            for (int j = 0; j < n; j++) {
                if (!strcmp(recs[i].dev, recs[j].dev)) {
                    used[j] = 1;
                    cnt++;
                    if (strlen(list) + strlen(recs[j].mp) + 2 < sizeof(list)) {
                        if (list[0] != '\0')
                            strncat(list, " ", sizeof(list) - strlen(list) - 1);
                        strncat(list, recs[j].mp, sizeof(list) - strlen(list) - 1);
                    }
                }
            }
            if (cnt > 1) {
                printf("  %-9s 出现 %2d 次：%s\n", recs[i].dev, cnt, list);
                if (strlen(list) > 200)
                    printf("           （列表已截断）\n");
            }
        }
    }

    /* ---------- ④ 两条路径一个 inode ---------- */
    sec("④ 两个挂载点的 st_ino 相同 → 同一棵子树被投射了两次");
    {
        const char *pairs[][2] = {
            {"/lib", "/usr/lib"},
            {"/lib64", "/usr/lib64"},
            {"/lib32", "/usr/lib32"},
        };
        for (size_t k = 0; k < sizeof(pairs) / sizeof(pairs[0]); k++) {
            struct stat a, b;
            if (stat(pairs[k][0], &a) == 0 && stat(pairs[k][1], &b) == 0) {
                printf("  %-9s dev=%u:%-5u ino=%llu\n", pairs[k][0],
                       major(a.st_dev), minor(a.st_dev), (unsigned long long) a.st_ino);
                printf("  %-9s dev=%u:%-5u ino=%llu   %s\n", pairs[k][1],
                       major(b.st_dev), minor(b.st_dev), (unsigned long long) b.st_ino,
                       (a.st_ino == b.st_ino && a.st_dev == b.st_dev)
                           ? "<<< 同一个 inode" : "（不同）");
            } else {
                printf("  %-9s 或 %-9s stat 失败\n", pairs[k][0], pairs[k][1]);
            }
        }
    }

    /* ---------- ⑤ 挂载遮盖 ---------- */
    sec("⑤ 挂载遮盖：被挂载点下面原来是什么，用户永远看不到");
    {
        struct stat st;
        for (int i = 0; i < n; i++) {
            if (strstr(recs[i].root, "//deleted") != NULL) {
                printf("  %-24s root=%-32s fstype=%s source=%s\n",
                       recs[i].mp, recs[i].root, recs[i].fstype, recs[i].source);
            }
        }
        if (stat("/etc/passwd", &st) == 0)
            printf("  stat(/etc/passwd) 看到的是 dev=%u:%u ino=%llu —— 即上面那条挂载的内容\n",
                   major(st.st_dev), minor(st.st_dev), (unsigned long long) st.st_ino);
        printf("  ↑ root 里的 \"//deleted\" 表示源在宿主上**已经被删除**，只剩打开着的引用；\n");
        printf("    这是「用挂载把单个文件换掉」的手法（容器给 /etc/passwd 注入口令的做法）。\n");
    }

    /* ---------- ⑥ stat().st_dev 与 mountinfo 的 major:minor 是同一个数 ---------- */
    sec("⑥ 核对：stat(\"/app\").st_dev 与 mountinfo 里 /app 那条的 major:minor");
    {
        struct stat st;
        int hit = 0;

        for (int i = 0; i < n; i++) {
            if (strcmp(recs[i].mp, "/app") != 0)
                continue;
            hit = 1;
            printf("  mountinfo: /app 这一条的 major:minor = %s   （root=%s, fstype=%s）\n",
                   recs[i].dev, recs[i].root, recs[i].fstype);
        }
        if (!hit)
            printf("  mountinfo 里没有 /app 这一条\n");

        if (stat("/app", &st) == 0) {
            printf("  stat():    stat(\"/app\").st_dev 解出来 = %u:%u\n",
                   major(st.st_dev), minor(st.st_dev));
            printf("  ↑ 两个字段说的是**同一个 sb->s_dev**，不是两种编号：\n"
                   "    mountinfo 打印的是原始的 MAJOR:MINOR（fs/proc_namespace.c），\n"
                   "    stat() 交给你的是**编码过**的值（fs/stat.c 用 new_encode_dev），\n"
                   "    glibc 的 major()/minor() 就是那个编码的逆运算（__gnu_dev_major）。\n"
                   "    所以同一台机器上它们必然相等 —— 对不上就说明**不是同一个容器**。\n");
        } else {
            printf("  stat(/app) 失败 errno=%d (%s)\n", errno, strerror(errno));
        }
    }

    printf("\n=== c14_7 done ===\n");
    return 0;
}
```

## 常见坑

| # | 坑 | 正解 |
|---|----|------|
| 1 | 用 `/etc/mtab` 判断挂载状态 | 本容器里 `/etc/mtab` **不存在**；`/proc/mounts` 是**指向 `self/mounts` 的符号链接**。权威来源是 `/proc/self/mountinfo` |
| 2 | 以为「目录存在」=「文件系统已挂」 | `/sys` 目录存在但 sysfs 没挂（§14.2 的 `errno=2` 实测）。判据只能是 `mountinfo` |
| 3 | 拿 `mounts` 的第 1 列当超级块设备号 | 那是**源设备**号。bind mount 上两者不同。要超级块设备号用 `mountinfo` 的 `major:minor` |
| 4 | 以为「同一设备号出现多次」就是 bind mount | 普通 mount 同一设备到多处也会重复。bind 的判据是 **`root != /`** |
| 5 | 以为卸载后挂载点里原来的东西没了 | 只是被**遮盖**，卸载后原样恢复。被遮盖期间它在自己的命名空间里仍然存在（只是这个名字指向别处） |
| 6 | 以为 `source` 是个可用路径 | 本机是 `/dev/root`，而 `/dev` 下**没有块设备节点**。它只是内核给的字符串 |
| 7 | 以为 `/dev` 和 `/dev/null` 是同一个文件系统 | `/dev` = `0:70` tmpfs，`/dev/null` = `0:7` devtmpfs，**不同**。这正是「单文件 bind」的证据 |
| 8 | 说「`st_dev` 与 `mountinfo` 的 `major:minor` 语义不同、不能比较」 | 同台机器上**必须相等**（本节 ⑥ 实测两边都是 `259:2`）。它们是同一个 `sb->s_dev` 的两种表示 |
| 9 | 以为 `mountinfo` 里列出的路径一定存在 | `/lib64`、`/lib32` 在 `mountinfo` 里有条目，但 `stat` 失败（本节 ④） |
| 10 | 把 `/cefs/**` 的具体名字写进断言 | 那是 CE 的编译器镜像，**会随镜像滚动更新**。只能断言结构（autofs + squashfs），不能断言具体名字 |

## HFT / 嵌入式关联

| 场景 | 结论怎么用 |
|------|-----------|
| **存储分层靠挂载点** | 「热数据 tmpfs、冷数据磁盘」的实现就是两个挂载点。判定某条路径到底在哪种介质上，**不能看路径名**，要 `statfs().f_type`（tmpfs = `0x01021994`）或 `stat().st_dev` |
| **`/proc/self/mountinfo` 是唯一可靠的运行时判据** | 编排/健康检查脚本里判断「数据盘挂上了没有」，用 `findmnt`（读 mountinfo）/直接读 mountinfo。用 `test -d /data` 会误判（目录可以预先建） |
| **bind mount 做「零拷贝视图」** | 把同一个只读数据目录 bind 到多个路径，比复制省空间、比符号链接安全（符号链接能被 `..` 逃出、能被 `O_NOFOLLOW` 拒掉；bind 是真正独立的挂载点，可以带独立的 `ro`/`nosuid` 选项） |
| **嵌入式的最小 rootfs** | 典型布局：`/` 只读 squashfs（或 `romfs`）+ `/tmp` tmpfs + `/data` 可写分区 + `/dev` devtmpfs。**`/dev` 必须由内核 `devtmpfs` 自动填充**，否则设备节点要手写 `mknod`（受 `/etc/init.d` 的启动顺序影响，很脆） |
| **`autofs` 与按需挂载** | 本容器 `/cefs/**` 用的就是 autofs：首次访问才触发挂载。嵌入式上常用于「按需挂载 U 盘/网络盘」，收益是启动时间与常驻内存，代价是**第一次访问的延迟不可预测** —— HFT 里不能放在关键路径 |
| **`master:N` 是命名空间/传播的指纹** | `mountinfo` 的 optional field 里 `master:N` 表示这个挂载属于某个共享 peer group（`mount --make-shared`）。容器运行时用它把宿主与容器的挂载传播解耦。排查「容器里为什么看不到宿主新挂的盘」就看它（§14.9.1） |
| **容器根是 tmpfs 的后果** | 本容器 `/` 是 tmpfs ⇒ 「写在 `/` 下的东西全在内存里」，`df /` 看到的容量是**内存的一半左右**（§14.10 实测）。把这点当成「容器磁盘」会严重误判容量与掉电行为 |

<details>
<summary>代码自测（Q&A）</summary>

**Q1：为什么不能靠 `ls /sys/dev` 判断 sysfs 挂没挂？**

A：因为「目录存在」什么都证明不了 —— 任何有权限的进程都能 `mkdir`。本容器 `/sys` 目录存在（`stat` 成功，`st_dev=0:71`），但 `/sys/dev`、`/sys/block` 都是 `ENOENT(2)`，且 §14.10 用 `fsid` 证明 `/sys` 与 `/` 是**同一个超级块** ⇒ sysfs 从未挂载。唯一判据是 `/proc/self/mountinfo` 里有没有一条挂载点等于 `/sys` 的记录。

**Q2：`mountinfo` 里 `root` 字段是干什么的？**

A：它指明「被挂上来的**源文件系统里的哪棵子树**」。`root=/` 表示整个文件系统；`root=/usr/lib` 表示只是那个文件系统的 `/usr/lib` 子树被投到挂载点上 —— 这就是 **bind mount 的指纹**。它还决定「挂载点下的相对路径怎么映射到源里的路径」（可用于 `openat2` 的 `RESOLVE_IN_ROOT` 与 chroot 语义）。

**Q3：怎么区分「同一设备挂到两个挂载点」和「bind mount」？**

A：看 `root`。`root=/` 就是「整个文件系统被挂两次」；`root=<某个非 / 路径>` 就是 bind。本机 `/lib` 那条的 `root=/usr/lib` ⇒ 是 bind（把源文件系统的 `/usr/lib` 投到 `/lib`）。

**Q4：`/etc/passwd` 的 `//deleted` 是谁加的？为什么它是 `nlink=0`？**

A：宿主上造了个临时文件、打开、然后 `unlink()` —— 于是它的 `st_nlink` 归 0，但因为有打开的 fd，inode 与数据都还在。内核 `d_path()` 在把这个 dentry 转成路径字符串时，发现它已被 unlink，就在末尾加 `//deleted`。这就是 §14.4 讲的「`nlink==0` 且无人打开才释放」的工程化用法。

**Q5：为什么 `/proc/mounts` 不可靠？**

A：本机 `/proc/mounts` 是**指向 `/proc/self/mounts` 的符号链接**，字段少（6 个），没有 `root`、`mount ID`、`parent ID`、optional fields。而 `/etc/mtab` 在本容器里**不存在**。要做「是不是 bind」「有没有共享传播」这类判定，只有 `mountinfo` 够用。

**Q6：同一台机器上 `stat().st_dev` 和 `mountinfo` 的 `major:minor` 会不会不一样？**

A：不会。两者都是 `sb->s_dev`：`mountinfo` 用 `%u:%u` 打**原始**值，`stat` 交给你 `new_encode_dev()` 编过码的值，而 glibc 的 `major()`/`minor()` 就是它的逆运算。本机实测两边都是 `259:2`。若对不上，说明两次查询在**不同的挂载命名空间/容器**里。

**Q7：本机 `/` 是 tmpfs，这有什么实际后果？**

A：写 `/` 下的数据**全在内存里**（可换出，见 §14.10），掉电/容器销毁即失；`df /` 看到的容量约为内存的一半（`shmem_default_max_blocks() = totalram_pages()/2`）。把 `/` 当持久盘用会丢数据，把它当「磁盘」估容量会严重误判。

</details>
