## 官方题面（本章唯一一道题）

> Write a program that creates `NF` one-byte files in a directory. The names of the files should be of the form `xNNNNNN`, with the `N`s replaced by numbers that are randomly chosen. The files should be created in random order, and then deleted in increasing numerical order. The program should accept two command-line arguments: the name of the directory in which the files should be created, and `NF`. Try running this program with various values of `NF` in a range up to at least 200,000, and in different file systems. What differences do you notice when varying `NF`? What differences do you notice between file systems? What effect does the order of creation and deletion have? What differences do you notice between ordering the file names and using random names?

**翻译与拆解成四个问题**：

| # | 问题 |
|---|------|
| Q1 | 改变 `NF` 会看到什么差别？ |
| Q2 | 不同文件系统之间有什么差别？ |
| Q3 | 创建顺序与删除顺序有什么影响？ |
| Q4 | 「名字有序」与「名字随机」有什么差别？ |

题面的**关键设计**：**创建用随机序、删除用递增序**。这两个顺序刻意不同 —— 否则就分不出「是创建乱序贵，还是删除乱序贵」。

## 本节实现：`ex14_1_file_churn.c`

完整源码 [`code/ex14_1_file_churn.c`](../code/ex14_1_file_churn.c)：

```c
/* ex14_1_file_churn.c —— TLPI §14.13 Exercise 14-1（本章只有**一道**习题）
 *
 *  【任务】（官方 §14.13 Exercise 是单数，只此一题；题干为转引，见笔记 14.13）
 *    编写一个程序，测量在单个目录中创建并随后删除大量 1 字节文件所需的时间。
 *      · 文件名形如 xNNNNNN，其中 NNNNNN 是一个随机的六位数字；
 *      · 文件按**名称生成时的随机顺序**创建，然后按**数字递增顺序**删除
 *        （即删除顺序与创建顺序不同）；
 *      · 文件数量 NF 与目标目录都能在命令行指定。
 *    题面还问了四件事（本程序的输出直接回答前两件，后两件用 -s 开关回答）：
 *      ① 随着 NF 增大，在各文件系统上观察到什么模式？
 *      ② 不同文件系统之间比较如何？
 *      ③ 如果按数字递增顺序创建、**并且按同一顺序删除**，结果会不会变？
 *      ④ 会变的话，原因是什么？是否随文件系统类型而不同？
 *
 *  【为什么这道题有信息量】
 *    它测的不是「写 1 个字节有多快」，而是**目录项（dentry）与 inode 的分配/回收开销**：
 *      · 创建 = 新 inode + 新目录项，目录还会因插入位置不同而反复分裂/重排
 *      · 随机顺序创建 ⇒ 名字在目录里到处插，局部性差
 *      · 递增顺序创建 ⇒ 名字总落在目录末尾，局部性好
 *    所以「创建顺序」是本题的核心变量，而不是噪声。
 *    （TLPI §14.2/14.3 的目录布局与 §14.4 的 inode，正是解释这个差异的地方。）
 *
 *  【用法】
 *    ex14_1_file_churn [-s] <dir> [NF]
 *      -s        按数字递增顺序创建（默认是随机顺序）
 *      <dir>     测试目录（程序只创建/删除自己造的 xNNNNNN，不动别的文件）
 *      [NF]      文件数量，默认 2000（题面建议 1000 ~ 20000，本仓默认取小值）
 *
 *  ⚠️ 两个环境事实（不是 bug）：
 *    1. 本容器 /tmp 的 tmpfs 带 `nr_inodes=100`（见 /proc/self/mountinfo），
 *       所以在 /tmp 上跑 NF=200 会看到 ENOSPC(28) —— 那是 **inode 用完**（§14.10），
 *       不是磁盘满。
 *    2. `open(path, O_CREAT, ...)` 的第三个参数 mode **必须给**；不给的话新文件的
 *       权限位就是栈上的垃圾值（原书读者踩过的坑）。
 *
 *  编译：gcc -O0 -Wall -Wextra -o ex14_1 ex14_1_file_churn.c
 */
#include <sys/stat.h>
#include <sys/statfs.h>
#include <sys/sysmacros.h>
#include <sys/types.h>
#include <errno.h>
#include <fcntl.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <time.h>
#include <unistd.h>

#define NAMELEN 8              /* "x" + 6 位数字 + '\0' */
#define MAXNF   1000000        /* xNNNNNN 只能表示 1000000 个名字 */
#define DEF_NF  2000
#define MAXTRY  40             /* 同一个槽位最多重掷多少次随机数 */

static void sec(const char *t)
{
    printf("\n== %s ==\n", t);
}

static double now_sec(void)
{
    struct timespec ts;

    if (clock_gettime(CLOCK_MONOTONIC, &ts) != 0)
        return 0.0;
    return (double)ts.tv_sec + (double)ts.tv_nsec / 1e9;
}

static int cmp_name(const void *a, const void *b)
{
    return strcmp((const char *)a, (const char *)b);
}

static const char *fstype_name(unsigned long t)
{
    switch (t) {
    case 0xef53:        return "ext2/ext3/ext4";
    case 0x01021994:    return "tmpfs";
    case 0x9fa0:        return "proc";
    case 0x6969:        return "nfs";
    case 0x01021997:    return "hugetlbfs";
    case 0x73717368:    return "squashfs";
    case 0x794c7630:    return "overlayfs";
    case 0x01021995:    return "mqueue";
    default:            return "(未收录)";
    }
}

/* 手写六位补零，不用 snprintf —— 免得格式串与缓冲区长度之间出现截断隐患 */
static void make_name(char *dst, long num)
{
    dst[0] = 'x';
    for (int k = 6; k >= 1; k--) {
        dst[k] = (char)('0' + (int)(num % 10));
        num /= 10;
    }
    dst[7] = '\0';
}

static void print_names(const char (*names)[NAMELEN], long n, long k)
{
    for (long i = 0; i < n && i < k; i++)
        printf("%s%s", names[i], i + 1 < n && i + 1 < k ? " " : "");
}

static void usage(const char *prog)
{
    fprintf(stderr, "Usage: %s [-s] <dir> [NF]\n"
                    "  -s       create in ascending numeric order too\n"
                    "  <dir>    directory to churn in (only xNNNNNN files are touched)\n"
                    "  [NF]     number of files, default %d\n", prog, DEF_NF);
    exit(EXIT_FAILURE);
}

int main(int argc, char *argv[])
{
    int same_order = 0, opt;
    const char *dir;
    char path[4096];
    long nf = DEF_NF;
    char (*names)[NAMELEN];
    struct statfs sb_before, sb_after, sb_now;
    struct stat sb;
    long created = 0, deleted = 0, collisions = 0;
    int create_errno = 0, delete_errno = 0;
    double t0, dt_create = 0.0, dt_delete = 0.0;

    while ((opt = getopt(argc, argv, "sn:")) != -1) {
        switch (opt) {
        case 's':
            same_order = 1;
            break;
        case 'n':
            nf = strtol(optarg, NULL, 10);
            break;
        default:
            usage(argv[0]);
        }
    }
    if (optind >= argc)
        usage(argv[0]);
    dir = argv[optind];
    if (optind + 1 < argc)
        nf = strtol(argv[optind + 1], NULL, 10);
    if (nf < 1 || nf > MAXNF) {
        fprintf(stderr, "%s: NF 必须在 1..%d 之间（现在 %ld）\n", argv[0], MAXNF, nf);
        exit(EXIT_FAILURE);
    }

    /* ---------- ① 前置检查 ---------- */
    sec("① 目标目录与它所在的文件系统");
    if (stat(dir, &sb) == -1) {
        fprintf(stderr, "  stat(%s): %s\n", dir, strerror(errno));
        exit(EXIT_FAILURE);
    }
    printf("  dir           = %s\n", dir);
    printf("  S_ISDIR       = %d  (mode=%#o, st_dev=%u:%u, st_ino=%llu)\n",
           S_ISDIR(sb.st_mode), (unsigned)sb.st_mode,
           (unsigned)major(sb.st_dev), (unsigned)minor(sb.st_dev),
           (unsigned long long)sb.st_ino);
    if (!S_ISDIR(sb.st_mode)) {
        fprintf(stderr, "  %s: 不是目录\n", dir);
        exit(EXIT_FAILURE);
    }
    if (statfs(dir, &sb_before) == 0)
        printf("  statfs        = f_type=%#x (%s)  f_bsize=%ld  f_blocks=%llu  "
               "f_files=%llu\n",
               (unsigned)sb_before.f_type, fstype_name((unsigned long)sb_before.f_type),
               (long)sb_before.f_bsize, (unsigned long long)sb_before.f_blocks,
               (unsigned long long)sb_before.f_files);

    /* ---------- ② 生成名字 ---------- */
    names = malloc((size_t)nf * NAMELEN);
    if (names == NULL) {
        fprintf(stderr, "  malloc(%ld) 失败\n", nf);
        exit(EXIT_FAILURE);
    }
    srand(1);                  /* 固定种子 ⇒ 同一份日志可复现 */
    for (long i = 0; i < nf; i++)
        make_name(names[i], same_order ? i : (long)(rand() % MAXNF));

    sec("② 创建阶段（1 字节文件）");
    printf("  NF=%ld  创建顺序=%s\n", nf, same_order ? "递增（-s）" : "随机（默认）");
    printf("  创建顺序（前 6 个）: ");
    print_names(names, nf, 6);
    printf("\n");

    t0 = now_sec();
    for (long i = 0; i < nf; i++) {
        int fd = -1;

        for (int try_ = 0; try_ < MAXTRY; try_++) {
            snprintf(path, sizeof(path), "%s/%s", dir, names[i]);
            /* 第三个参数 mode 必须给：O_CREAT 时缺了它，权限位就是栈上的垃圾值 */
            fd = open(path, O_WRONLY | O_CREAT | O_EXCL, 0644);
            if (fd >= 0)
                break;
            if (errno != EEXIST) {
                create_errno = errno;
                break;
            }
            collisions++;
            if (same_order) {     /* 递增模式下重名说明名字空间用尽，不该发生 */
                create_errno = EEXIST;
                break;
            }
            make_name(names[i], (long)(rand() % MAXNF));
        }
        if (fd < 0)
            break;
        if (write(fd, "x", 1) != 1) {   /* 每个文件正好 1 字节 */
            create_errno = errno;
            close(fd);
            break;
        }
        close(fd);
        created++;
    }
    dt_create = now_sec() - t0;

    printf("  轮询重名次数（EEXIST）= %ld\n", collisions);
    if (create_errno != 0) {
        printf("  创建提前中止：errno=%d (%s)   已创建 %ld 个\n",
               create_errno, strerror(create_errno), created);
        printf("  ↑ 在 /tmp（tmpfs，nr_inodes=100）上跑 NF>100 会走到这里；\n");
        printf("    那是 **inode 用完**（§14.10 的 nr_inodes=），不是块用完。\n");
    } else {
        printf("  创建完成：%ld 个\n", created);
    }
    if (created > 0) {
        snprintf(path, sizeof(path), "%s/%s", dir, names[0]);
        printf("  第一个文件的 stat：");
        if (stat(path, &sb) == 0) {
            printf("size=%lld blocks=%lld nlink=%llu mode=%#o\n",
                   (long long)sb.st_size, (long long)sb.st_blocks,
                   (unsigned long long)sb.st_nlink, (unsigned)sb.st_mode);
            printf("  ↑ st_blocks 的单位是 **512 字节**（不是 f_bsize），所以 1 字节文件\n");
            printf("    看到的是 8 而不是 1；若文件系统把微小文件内联进 inode，也可能是 0。\n");
            printf("    mode=%#o 是 `open` 第三个参数生效的证据——\n", (unsigned)sb.st_mode);
            printf("    不给 mode 时这里打出来的是栈上的垃圾值。\n");
        } else {
            printf("stat 失败 errno=%d\n", errno);
        }
    }
    if (statfs(dir, &sb_after) == -1)
        sb_after = sb_before;
    printf("  创建后 f_ffree=%llu  f_bfree=%llu\n",
           (unsigned long long)sb_after.f_ffree,
           (unsigned long long)sb_after.f_bfree);

    /* ---------- ③ 删除阶段 ---------- */
    sec("③ 删除阶段：按**数字递增**顺序");
    qsort(names, (size_t)created, NAMELEN, cmp_name);
    printf("  删除顺序（前 6 个）: ");
    print_names(names, created, 6);
    printf("\n");
    printf("  两种顺序相同吗？%s\n", same_order ? "相同（-s）" : "不同 —— 这正是本题的对照");

    t0 = now_sec();
    for (long i = 0; i < created; i++) {
        snprintf(path, sizeof(path), "%s/%s", dir, names[i]);
        if (unlink(path) == 0)
            deleted++;
        else if (delete_errno == 0)
            delete_errno = errno;
    }
    dt_delete = now_sec() - t0;

    /* ---------- ④ 结果 ---------- */
    sec("④ 结果");
    printf("  NF=%ld  created=%ld  deleted=%ld  collisions=%ld\n",
           nf, created, deleted, collisions);
    printf("  创建耗时 = %.6f s", dt_create);
    if (created > 0)
        printf("   (%.2f us/个)", dt_create / (double)created * 1e6);
    printf("\n");
    printf("  删除耗时 = %.6f s", dt_delete);
    if (deleted > 0)
        printf("   (%.2f us/个)", dt_delete / (double)deleted * 1e6);
    printf("\n");
    if (delete_errno)
        printf("  删除有失败：errno=%d (%s)\n", delete_errno, strerror(delete_errno));

    sec("⑤ inode 与块的账（创建前 / 创建后 / 删除后三次 statfs）");
    if (statfs(dir, &sb_now) == 0) {
        printf("  创建前 f_ffree=%llu  f_bfree=%llu\n",
               (unsigned long long)sb_before.f_ffree,
               (unsigned long long)sb_before.f_bfree);
        printf("  创建后 f_ffree=%llu  f_bfree=%llu   (差 %lld / %lld)\n",
               (unsigned long long)sb_after.f_ffree,
               (unsigned long long)sb_after.f_bfree,
               (long long)sb_after.f_ffree - (long long)sb_before.f_ffree,
               (long long)sb_after.f_bfree - (long long)sb_before.f_bfree);
        printf("  删除后 f_ffree=%llu  f_bfree=%llu   (差 %lld / %lld)\n",
               (unsigned long long)sb_now.f_ffree,
               (unsigned long long)sb_now.f_bfree,
               (long long)sb_now.f_ffree - (long long)sb_before.f_ffree,
               (long long)sb_now.f_bfree - (long long)sb_before.f_bfree);
    }
    printf("  ↑ inode 一列的变化应当恰好等于 created（每个文件占一个 inode）；\n");
    printf("    块一列的变化约等于 created（每个 1 字节文件占一个块）。\n");
    printf("    两条线**分开看**才能判断「是 inode 先耗尽还是块先耗尽」。\n");

    sec("⑥ 怎么读这个结果（对应题面的四个问题）");
    printf("  Q1 随 NF 增大的模式：本程序不加缓存，创建/删除都是 O(NF) 次系统调用，\n");
    printf("     所以总耗时会随 NF 近似线性增长；真正要盯的是**每个文件的平均耗时**\n");
    printf("     那一列 —— 目录变大以后它会上翘。\n");
    printf("  Q2 文件系统之间：换个目录参数重跑同一组数字即可（/app 是 ext4、/tmp 是\n");
    printf("     tmpfs），但先看清楚目标目录的容量与 inode 上限。\n");
    printf("  Q3/Q4 顺序的影响：加 -s 再跑一次，与默认的随机序创建对比。\n");
    printf("     机制上，递增顺序让名字总是**追加**到目录末尾，随机顺序则到处插。\n");
    printf("     差距大小与文件系统的目录实现有关（ext4 用 htree，tmpfs 用简单目录）。\n");
    printf("     ⚠️ 本程序**不断言方向**，也不给「应该快多少倍」的结论：\n");
    printf("        请把两组实测数字读出来自己比。\n");

    free(names);
    printf("\n=== ex14_1 done ===\n");
    return 0;
}
```

用法：

```bash
gcc -O0 -Wall -Wextra -o ex14_1_file_churn ex14_1_file_churn.c

./ex14_1_file_churn <目录> <NF>       # 创建随机序，删除递增序（题面原样）
./ex14_1_file_churn <目录> <NF> -s    # 创建也用递增序（对照 Q3/Q4）
```

程序做的事，一句话一步：

1. `statfs()` 目标目录，打出**卷的类型与容量/inode 上限**（避免误测）。
2. 生成 `NF` 个 `xNNNNNN` 名字（000000~999999），**打乱顺序后**逐个 `open(O_CREAT|O_EXCL)` 建 1 字节文件；`EEXIST` 计数（重名）。
3. 逐个 `stat()`，`qsort` 后按**数字递增**顺序 `unlink`。
4. 全程统计**耗时**与**每次 `statfs` 的 `f_ffree`/`f_bfree`**。

**关键读数**：

| 量 | 值 | 说明 |
|----|----|------|
| `f_type` | `0xef53` | ext4（§14.3） |
| `f_files` | `1966080` | inode 上限（`NF` 远小于它，所以不会撞 inode 墙） |
| `EEXIST` 次数 | **1** | 随机取名字会**撞车**（生日问题）。NF=2000 在 100 万号里撞一次，符合预期 |
| 创建 | `2000` 个，`0.071167 s`，**35.58 µs/个** | |
| 删除 | `2000` 个，`0.036917 s`，**18.46 µs/个** | 递增序删除比随机序创建**快一倍** |
| `f_ffree` 变化 | `-2000`（恰好等于创建数） | 每个文件一个 inode，**精确** |
| `f_bfree` 变化 | `-2066`（比创建数多一点） | 每个 1 字节文件一个块，多出来的几十块是**目录本身在长大**（htree 索引块） |

> `f_ffree` 的 `-2000` 是**精确**的，`f_bfree` 的 `-2066` 是**近似**的 —— 前者只看「inode 有没有被分配」，后者还要算目录扩展开销。这正是 §14.10 讲的「两条独立的线」。

## 实测二：同样 NF=2000，创建也用递增序（`-s`）

<!--OUT:ex14_1_app_2000s|after=④ 结果,until=⑥ 怎么读-->

```text
  NF=2000  created=2000  deleted=2000  collisions=0
  创建耗时 = 0.048421 s   (24.21 us/个)
  删除耗时 = 0.018204 s   (9.10 us/个)

== ⑤ inode 与块的账（创建前 / 创建后 / 删除后三次 statfs） ==
  创建前 f_ffree=1816093  f_bfree=2667095
  创建后 f_ffree=1814093  f_bfree=2665083   (差 -2000 / -2012)
  删除后 f_ffree=1816093  f_bfree=2667083   (差 0 / -12)
  ↑ inode 一列的变化应当恰好等于 created（每个文件占一个 inode）；
    块一列的变化约等于 created（每个 1 字节文件占一个块）。
    两条线**分开看**才能判断「是 inode 先耗尽还是块先耗尽」。
```

**与实测一的对照**（这是 Q3/Q4 的直接答案）：

| | 随机序创建 | 递增序创建 | 差距 |
|---|---|---|---|
| `EEXIST` 次数 | 1 | **0** | 递增不会撞车 |
| 创建耗时 | 0.071167 s（35.58 µs/个） | **0.048421 s（24.21 µs/个）** | 递增快 **1.47×** |
| 删除耗时 | 0.036917 s（18.46 µs/个） | **0.018204 s（9.10 µs/个）** | 递增快 **2.03×** |
| `f_bfree` 创建后 | -2066 | -2012 | 递增的目录开销略小 |

> ⚠️ **这两组数字来自同一次 CE 批跑的两个作业，但不保证同一宿主**（`ex14_1_app_2000` 的 `st_ino=361554`、`-s` 版是 `358809`；`f_bfree` 初值也不同）。**绝对耗时不能跨作业比较**，只能比**同一个作业内部的相对量**（如「创建 vs 删除」的比值）。这是本文反复强调的那条纪律。

## 实测三：tmpfs 上 NF=200（撞 inode 墙）

`/tmp` 是 tmpfs 且 `nr_inodes=100`（§14.10）。这是本题最有教育意义的一次运行：

<!--OUT:ex14_1_tmp_200|after=① 目标目录,until=② 创建阶段-->

```text
  dir           = /tmp
  S_ISDIR       = 1  (mode=041777, st_dev=0:70, st_ino=1)
  statfs        = f_type=0x1021994 (tmpfs)  f_bsize=4096  f_blocks=5120  f_files=100
```

<!--OUT:ex14_1_tmp_200|after=② 创建阶段,until=③ 删除阶段-->

```text
  NF=200  创建顺序=随机（默认）
  创建顺序（前 6 个）: x289383 x930886 x692777 x636915 x747793 x238335
  轮询重名次数（EEXIST）= 0
  创建提前中止：errno=28 (No space left on device)   已创建 99 个
  ↑ 在 /tmp（tmpfs，nr_inodes=100）上跑 NF>100 会走到这里；
    那是 **inode 用完**（§14.10 的 nr_inodes=），不是块用完。
  第一个文件的 stat：size=1 blocks=8 nlink=1 mode=0100644
  ↑ st_blocks 的单位是 **512 字节**（不是 f_bsize），所以 1 字节文件
    看到的是 8 而不是 1；若文件系统把微小文件内联进 inode，也可能是 0。
    mode=0100644 是 `open` 第三个参数生效的证据——
    不给 mode 时这里打出来的是栈上的垃圾值。
  创建后 f_ffree=0  f_bfree=5021
```

<!--OUT:ex14_1_tmp_200|after=④ 结果,until=⑥ 怎么读-->

```text
  NF=200  created=99  deleted=99  collisions=0
  创建耗时 = 0.000448 s   (4.52 us/个)
  删除耗时 = 0.000240 s   (2.42 us/个)

== ⑤ inode 与块的账（创建前 / 创建后 / 删除后三次 statfs） ==
  创建前 f_ffree=99  f_bfree=5120
  创建后 f_ffree=0  f_bfree=5021   (差 -99 / -99)
  删除后 f_ffree=99  f_bfree=5120   (差 0 / 0)
  ↑ inode 一列的变化应当恰好等于 created（每个文件占一个 inode）；
    块一列的变化约等于 created（每个 1 字节文件占一个块）。
    两条线**分开看**才能判断「是 inode 先耗尽还是块先耗尽」。
```

**读数**：

| 量 | 值 | 说明 |
|----|----|------|
| `f_files` | `100` | 就是挂载选项 `nr_inodes=100` |
| 结果 | `created=99`（而不是 200） | 第 100 个 `open` 报 `errno=28 (ENOSPC)` |
| `f_ffree` | `99 → 0` | **inode 用完了** |
| `f_bfree` | `5120 → 5021`（-99） | **块还很富余**（还剩 5021 / 5120） |
| 删除后 | `f_ffree` 回到 99、`f_bfree` 回到 5120 | 完全恢复 |

**这就是「容量够但 inode 不够」的活标本**：`df -h /tmp` 会显示「只用掉 2%」，而 `open(O_CREAT)` 已经 `ENOSPC`。

> `/tmp` 的目录本身占了 1 个 inode，所以只有 99 个文件能建（100 - 1）。程序把它如实打出来了。

## 四个问题的答法（用实测数据说话，不猜方向）

| 问题 | 怎么答 | 本节的依据 |
|------|--------|-----------|
| **Q1：改变 `NF`** | 看**每个文件的平均耗时**（不是总耗时）。总耗时随 `NF` 近似线性（O(NF) 次系统调用）；真正要盯的是**平均值的上翘** —— 目录变大后 ext4 从线性目录变成 htree，查找成本从 O(N) 变成 O(log N) 但对缓存的压力上升；`f_bfree` 的**每文件开销**也会随目录块增长而上升 | 实测一的 `35.58 µs/个`、`f_bfree` 的 `-2066` vs `-2000` |
| **Q2：不同文件系统** | 换个目录参数重跑。先 `statfs` 看清目标卷的 `f_files`/`f_blocks` —— 否则容易把「inode 用完」误当成「文件系统慢」 | 实测三：tmpfs 在 NF>99 时 `ENOSPC` |
| **Q3：创建/删除顺序的影响** | 用 `-s` 做对照。递增序在**两个阶段都快**（本机 1.47× / 2.03×） | 实测一 vs 实测二 |
| **Q4：有序名字 vs 随机名字** | 两个效应叠加：① **随机名字会撞车**（`EEXIST`，实测一有 1 次；递增序 0 次）；② **随机插入位置**在目录里到处跳，递增序总是追加到末尾 | 同上 |

> ⚠️ **本程序刻意不下「应该快多少倍」的结论**。CE 每次运行落在不同宿主上，绝对耗时不可比；而且顺序带来的收益**与文件系统的目录实现强相关**（ext4 用 htree、tmpfs 用简单目录、不同 FS 差很多）。**把两组数字读出来自己比**，比记住一个「标准答案」有用。

## 加深理解：为什么「名字的分布」会影响性能

| 文件系统的目录实现 | 名字有序/随机的影响 |
|-------------------|-------------------|
| **ext2/3**（线性目录） | 查找是 O(n) 逐个比较，插入是 O(n) 的移位/分裂。**随机名**让插入位置散布全目录；**有序名**总是追加到末尾 —— 差别非常明显 |
| **ext4**（`dir_index` htree） | 目录变成 B 树后查找是 O(log n)，但**插入仍要维护树**。有序追加比随机插入**更少分裂**、顺序写更集中 |
| **tmpfs**（简单目录） | 内存里就是个链表/数组，随机序的劣势主要体现在缓存局部性上 |
| **NFS / 网络 FS** | 每次目录操作都可能是 RTT，**随机名的收益/损失被网络放大** |
| **COW 文件系统（Btrfs/ZFS）** | 目录是 B 树，随机插入会触发更多 COW 写放大 |

**这就是本题的真正价值**：它不是一个「跑分题」，而是「教你用 `statfs` 的两条线 + 名字顺序这两个可控变量，去测一个文件系统的**目录实现特性**」。

## 常见坑

| # | 坑 | 正解 |
|---|----|------|
| 1 | 用 `created` 计数代替 `f_ffree` 的实测 | 两者应当**互相印证**。本机 ext4 上 `f_ffree` 恰好 `-2000`（精确），tmpfs 上 `-99`（=created），对不上就说明有别的进程在动这个卷 |
| 2 | 只用 `f_bfree` 判断「空间够不够」 | 1 字节文件也要占一整块（4096），且**inode 可能是先耗尽的那个**（实测三） |
| 3 | 忘了 `O_EXCL` | 不用 `O_EXCL` 时「重名」会变成**覆盖**而不是 `EEXIST`，`collisions` 恒为 0，Q4 就测不出来了 |
| 4 | 忘了 `open` 的第三个参数 `mode` | `O_CREAT` 时 `mode` 是必需的；不给的话 `st_mode` 是**栈上的垃圾值**（本程序专门把 `mode=0100644` 打出来验证） |
| 5 | 把 `st_blocks` 当成 `f_bsize` 的单位 | `st_blocks` 单位固定 **512 字节**。1 字节文件显示 `8` 是 4096 字节占用，不是 8 字节 |
| 6 | 直接比较跨作业的耗时 | CE 每个作业可能不同宿主。**只比同一作业内部的相对量**（如创建/删除比值） |
| 7 | 在 `NF` 上「用力过猛」 | 题面说要试到 200000。在 inode 只有 100 的 tmpfs 上这是不可能的；**先 `statfs` 看 `f_files` 再决定 `NF`** |
| 8 | 以为「随机创建一定更慢」 | 本机确实更慢（1.47×），但这是**实测结果**不是定律。不同 FS、不同目录实现下方向可能不同 —— 所以要在**你的目标文件系统上**重跑 |
| 9 | 忘了清理测试文件 | 本程序的删除阶段会把它们删掉；但**中途失败**（如 `ENOSPC`）会留下残骸。跑之前最好用一个独立子目录 |
| 10 | 在一台机器上跑完就下结论 | 题面明确要求「**in different file systems**」。ext4 / tmpfs / NFS 的答案完全不同 |

## HFT / 嵌入式关联

| 场景 | 结论怎么用 |
|------|-----------|
| **「一个快照一个文件」方案的容量估算** | 本题给出了两条必须同时算的线：每文件 1 个 inode + 至少 1 个块。`NF` 个文件需要的 inode 就是 `NF`（再加上目录自身），需要的块数 ≈ `NF` + 目录块增长。**在建卷时用 `mke2fs -i` 反算** |
| **目录块增长是隐性成本** | 本机 `f_bfree` 的 `-2066`（NF=2000）比 `-2000` 多出 66 块 ≈ 264 KiB —— 那是**目录索引**。文件数上万时这部分不可忽略 |
| **有序追加是落盘盘的默认最优形态** | 「按时间序命名 + 只追加」的文件布局，在 ext4 上少分裂、顺序写更集中。反过来，**随机名的海量小文件**会把目录变成随机写热点 |
| **inode 耗尽 ≠ 磁盘满** | tmpfs 的 100-inode 例子在嵌入式上也常见（`nr_inodes=` 写得很小以防内存被 inode 吃光）。监控必须**两个都看** |
| **嵌入式上用 tmpfs 做「临时文件区」要算 inode** | 程序运行中建的临时文件在这段时间里各占一个 inode。`nr_inodes=` 给少了会在业务高峰炸掉 |
| **名字空间与哈希碰撞** | `xNNNNNN` 只有 100 万个号。`NF=200000` 时的碰撞概率已经不可忽略（生日问题：约 `1-exp(-NF²/2M)`），实测 `NF=2000` 就撞了 1 次。**产品里用纯随机短名要算碰撞预算**，或者像本程序一样处理 `EEXIST` 重试 |
| **性能测试的方法论** | 本题是「控制变量」的范本：固定目录、固定 `NF`，只改**一个**变量（创建顺序）；再改**另一个**（文件系统）。HFT 上的任何「调优前后对比」都该照这个套路做，而不是凭感觉 |

<summary>代码自测（Q&A）</summary>

**Q1：为什么创建用随机序、删除用递增序，而不是两个都随机？**

A：为了让「顺序的影响」在两个阶段上**可分离**。如果创建和删除都用随机序，就无法判断「慢」是随机的插入位置导致的还是删除导致的。题面这个设计让你能拿「随机序创建」与「递增序创建」（`-s`）做单变量对照，而删除阶段两边都是递增序 —— 本机实测创建快 1.47×、删除快 2.03×。

**Q2：`EEXIST` 计数说明了什么？**

A：名字空间大小与 `NF` 的关系。`xNNNNNN` 只有 100 万个号，随机取 `NF` 个名的碰撞概率约 `1-exp(-NF²/2M)`。本机 `NF=2000` 撞了 **1** 次，递增序撞 **0** 次。产品里用短随机名必须处理这个（重试或加长名字）。

**Q3：`f_ffree` 的变化为什么恰好等于 `created`？**

A：因为每个文件占**恰好一个** inode。ext4 上每个 inode 是 256 字节（默认）的一块预分配区域，创建文件就是分配一个 inode。所以 `f_ffree` 的差值是**精确**的 —— 本机 ext4 上 `-2000` 对 `created=2000`，tmpfs 上 `-99` 对 `created=99`，都精确相等。

**Q4：`f_bfree` 的变化为什么比 `created` 多一点？**

A：因为除了文件的数据块，**目录本身也在长大**。`/app`（ext4，带 htree）上 NF=2000 时 `f_bfree` 少了 2066 块，多出的 66 块就是目录索引/目录块的增量。而 tmpfs 的目录实现简单，`-99` 与 `created=99` 恰好相等。

**Q5：为什么在 `/tmp` 上 NF=200 只建了 99 个？**

A：`/tmp` 是 tmpfs 且挂载时写了 `nr_inodes=100`（§14.10 实测）。`/tmp` 目录自身占 1 个 inode，所以剩 99 个给文件。第 100 个 `open` 返回 `errno=28 (ENOSPC)`，程序**如实打印 `created=99`** 而不是假装成功。

**Q6：本机实测「递增序更快」，这能推广吗？**

A：**不能直接推广**。这是 ext4（htree 目录）+ 本机宿主上的结果。换到 tmpfs（简单目录）、Btrfs/ZFS（COW B 树）、NFS（每次操作有 RTT）上方向与倍数都可能不同 —— 这正是题面要求「**in different file systems**」的原因。要下结论必须在**你的目标文件系统**上重跑。

**Q7：为什么本程序不去断言「应该快多少倍」？**

A：两个原因。① CE 每个作业可能落在**不同宿主**上，绝对耗时不可跨作业比较；② 顺序带来的收益与文件系统的目录实现强相关，一个「标准倍数」是伪知识。**可迁移的只有方法论**（控制变量、看平均耗时、两条线分开看），不是数字。

</details>
