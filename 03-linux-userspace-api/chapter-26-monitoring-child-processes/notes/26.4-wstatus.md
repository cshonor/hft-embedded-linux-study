## 本节讲什么

仅当 `WIFEXITED` 为真时用 `WEXITSTATUS`。 ---

## 要点

| 宏 | 含义 |
|----|------|
| `WIFEXITED` → `WEXITSTATUS` | 正常退出 + 退出码 |
| `WIFSIGNALED` → `WTERMSIG` | 信号杀死；`WCOREDUMP`（Linux） |
| `WIFSTOPPED` → `WSTOPSIG` | 暂停（需 WUNTRACED） |
| `WIFCONTINUED` | 继续（需 WCONTINUED） |

仅当 `WIFEXITED` 为真时用 `WEXITSTATUS`。

## 与 C 语言学习的关系

信号处理是 C 语言异步编程的核心。`signal`/`sigaction` 的 handler 是函数指针——需要理解 C 语言的函数指针。`volatile sig_atomic_t` 涉及 C 语言的 `volatile` 关键字和原子性概念。

## 常见陷阱

1. **signal() 不可移植**

```c
signal(SIGINT, handler);  /* 行为不一致 */
```

signal() 在不同系统上行为不一致（是否自动恢复默认、handler 期间是否阻塞自身）。生产代码用 sigaction()。

2. **handler 中调用不安全函数**

```c
void handler(int sig) {
    printf("got signal\n");  /* printf 不安全! */
}
```

printf/malloc 等不是异步信号安全函数。handler 中只能调用异步信号安全函数（如 write）。

3. **信号竞态**

```c
/* 检查标志后处理，但信号可能在此间到达 */
if (flag) { ... }  /* TOCTOU */
```

信号可能在检查和处理之间到达。需要用 sigprocmask 阻塞信号或用 volatile sig_atomic_t。

## 自测题

**题目 1（选择）：** `SIGKILL` 和 `SIGSTOP` 的共同特点是？
A. 可以被捕获
B. 可以被忽略
C. 可以被阻塞
D. 都不能被捕获/忽略/阻塞

<details>
<summary>参考答案</summary>

D。SIGKILL 和 SIGSTOP 不能被捕获、忽略或阻塞。这是设计上的保证。

</details>

**题目 2（判断）：** 可以在信号处理函数中安全地调用 `printf`。

<details>
<summary>参考答案</summary>

错误。printf 不是异步信号安全函数。它使用 stdio 缓冲区和 malloc，在信号处理函数中调用可能导致死锁或数据损坏。用 write 代替。

</details>

**题目 3（踩坑）：** 以下代码有什么问题？
```c
volatile int flag = 0;
void handler(int sig) { flag = 1; }
int main() {
    signal(SIGINT, handler);
    while (!flag) { /* busy wait */ }
    printf("done\n");
}
```

<details>
<summary>参考答案</summary>

1) signal() 不可移植，应用 sigaction；2) busy wait 浪费 CPU，应用 pause() 或 sigsuspend()；3) printf 在信号后的主循环中调用是安全的，但如果信号在 printf 执行中到来则不安全。

</details>

**题目 4（应用）：** 写代码用 sigaction 捕获 SIGINT 并设置标志。

<details>
<summary>参考答案</summary>

```c
volatile sig_atomic_t flag = 0;
void handler(int sig) { flag = 1; }
struct sigaction sa = {0};
sa.sa_handler = handler;
sigemptyset(&sa.sa_mask);
sa.sa_flags = SA_RESTART;
sigaction(SIGINT, &sa, NULL);
```

</details>
