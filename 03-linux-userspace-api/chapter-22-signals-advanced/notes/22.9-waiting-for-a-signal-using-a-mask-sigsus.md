# 22.9 使用掩码等待信号：`sigsuspend()`

> 源码核验：Linux v6.6 · `kernel/signal.c`（`sigsuspend:4650` · `SYSCALL_DEFINE2(rt_sigsuspend):4669` · `SYSCALL_DEFINE0(pause):4639` · `set_user_sigmask:3131`）
> 本章：[TLPI 第 22 章 — Signals: Advanced Features](../README.md)
> - 上一节：[22.8 实时信号](22.8-realtime-signals.md)
> - 下一节：[22.10 同步等待信号](./22.10-synchronously-waiting-for-a-signal.md)

## 本节讲什么

1. `sigsuspend()` 解决什么竞态——回顾 `pause()` 那个无法用锁消除的窗口
2. 它的**原子四步**在内核里如何实现，与 `pause()` 其实只差三行
3. 标准使用范式：为什么必须先阻塞再 `sigsuspend`，以及为什么用 `while` 而非 `if`

---

## 一、它解决什么问题

回顾 [Ch20.14](../../chapter-20-signals-fundamentals/notes/20.14-waiting-for-a-signal-pause.md) 的致命竞态：

```c
sigprocmask(SIG_UNBLOCK, &mask, NULL);   /* ① 解除阻塞 */
                                          /* ← 窗口：信号在此到达并递送完毕 */
pause();                                  /* ② 等待 → 永远等不到，进程永久挂起 */
```

这个问题**无法用锁或关中断解决**——信号递送发生在内核返回用户态的边界，与用户态锁无关。

`sigsuspend()` 把 ①② 合并成**一个系统调用**，从根本上消除窗口。

---

## 二、接口与原子四步

```c
#include <signal.h>

int sigsuspend(const sigset_t *mask);
/* 返回：总是 -1，errno 总是 EINTR */
```

**原子完成四步**：

| 步骤 | 动作 |
|------|------|
| ① | 保存当前掩码到 `saved_sigmask` |
| ② | 把掩码**替换为** `mask` |
| ③ | 挂起等待信号 |
| ④ | 被唤醒后**恢复**原掩码，返回 |

> **关键**：是「**替换**」而非「相对解除」。`sigsuspend(&mask)` 期间生效的就是你传入的 `mask`，不是"在原掩码上解除某些位"。

---

## 三、内核实现：与 `pause()` 只差三行

把两个实现并排看（`kernel/signal.c`）：

```c
// :4639 —— pause()
SYSCALL_DEFINE0(pause)
{
	while (!signal_pending(current)) {
		__set_current_state(TASK_INTERRUPTIBLE);
		schedule();
	}
	return -ERESTARTNOHAND;
}

// :4650 —— sigsuspend()
static int sigsuspend(sigset_t *set)
{
	current->saved_sigmask = current->blocked;   // ① 保存
	set_current_blocked(set);                    // ② 替换掩码

	while (!signal_pending(current)) {           // ③ 与 pause 完全相同的循环
		__set_current_state(TASK_INTERRUPTIBLE);
		schedule();
	}
	set_restore_sigmask();                       // ④ 恢复
	return -ERESTARTNOHAND;
}
```

**等待循环与 `pause()` 完全相同**。`sigsuspend` 多的只是前后各一行半的掩码操作——但因为**都在同一次系统调用内**，就获得了原子性。

> **核心洞察**：原子性不来自"做了更多事"，而来自"**这些事在一次系统调用里做完**"。用户态分开写两个 syscall，中间必然存在可被信号插入的窗口。

## 四、标准使用范式

```c
sigset_t block, orig, wait_mask;

/* ① 先阻塞目标信号 —— 让它们在临界区期间堆积在 pending，不会丢 */
sigemptyset(&block);
sigaddset(&block, SIGUSR1);
sigprocmask(SIG_BLOCK, &block, &orig);

/* ② 构造"等待期间"的掩码 = 原掩码去掉要等的信号 */
wait_mask = orig;
sigdelset(&wait_mask, SIGUSR1);

/* ③ 原子地：临时放行 SIGUSR1 → 等待 → 回到阻塞态 */
while (!got_signal)                    /* ← while，不是 if */
    sigsuspend(&wait_mask);

/* ④ 此时掩码已自动恢复为阻塞态 */
sigprocmask(SIG_SETMASK, &orig, NULL);
```

**为什么这个范式正确**：

| 阶段 | SIGUSR1 状态 |
|------|-------------|
| 临界区（阻塞态） | 到达的信号进 pending，**不丢失** |
| `sigsuspend` 调用瞬间 | 若已有 pending → **立即递送并唤醒**（根本不睡） |
| `sigsuspend` 等待中 | 信号到达 → 递送并唤醒 |
| 唤醒后 | 掩码自动回到阻塞态，可安全清理 |

**两条路径都不丢**：信号要么在等待前堆积（随后被递送唤醒），要么在等待期间直接唤醒——**没有第三种可能**。

> **为什么用 `while` 而不是 `if`**：`sigsuspend()` 可能被**任何**未被阻塞的信号唤醒，而返回值**无法区分**是哪一个（总是 `-1/EINTR`）。所以要用标志位循环判断。

## 五、与相关接口对比

| 接口 | 原子操作 | 同时等 I/O | 返回 |
|------|----------|-----------|------|
| `pause()` | ❌ 无掩码操作，有竞态 | ❌ | `-1/EINTR` |
| **`sigsuspend(&mask)`** | ✅ 改掩码 + 等待 + 恢复 | ❌ | `-1/EINTR` |
| `pselect(n, ..., &sigmask)` | ✅ 改掩码 + select + 恢复 | ✅ | 就绪 fd 数 |
| `ppoll(fds, n, ts, &sigmask)` | ✅ 改掩码 + poll + 恢复 | ✅ | 就绪 fd 数 |
| `epoll_pwait(ep, ev, max, tmo, &sigmask)` | ✅ 改掩码 + epoll_wait + 恢复 | ✅ | 就绪 fd 数 |
| `sigwaitinfo(&set, &info)` | 同步取信号，**不跑 handler** | ❌ | 信号编号 |

后三者通过 `set_user_sigmask()`（`kernel/signal.c:3131`）在内核里原子完成「改掩码 → 等待 → 恢复」。

> **`sigsuspend` 的局限**：只能等信号，不能同时等 I/O。需要「同时等信号和 socket」时用 `ppoll`/`epoll_pwait` 或 signalfd（[22.11](22.11-fetching-signals-via-a-file-descriptor.md)）。

---

## HFT / 嵌入式关联

| 路线 | 要点 |
|------|------|
| 嵌入式 | `sigsuspend` 原子「放行目标信号 + 休眠」，修掉了 `pause()` 的竞态，是嵌入式等待异步信号的正确原语。必须配合「先 `SIG_BLOCK` → `wait_mask` 去掉目标 → `while` 循环」范式。注意它**总是返回 `EINTR`**，这是正常行为不是错误；`SIGHUP` 配置重载是典型用例 |
| HFT | 虽然原子，但 `sigsuspend` 仍是**阻塞休眠**，无法同时等行情数据——HFT 主循环不用它。仅当信号是唯一唤醒源的管理线程可用；否则用 signalfd 或 `epoll_pwait(..., &sigmask)`，把信号与 I/O 统一到一个 `epoll_wait` 里 |

## 代码示例

### 一、`t_sigsuspend.c`（Listing 22-5）

本节的核心是「`sigsuspend` 用一次调用完成『换掩码 + 睡下』，消除 `sigsuspend` 前的竞态窗口」。`t_sigsuspend` 故意造出一个 4 秒的临界区（屏蔽 `SIGINT`/`SIGQUIT`），让读者在临界区里按 `^C`，再看信号是不是**恰好**在 `sigsuspend` 点被处理——这是本节灵魂输出的来源。

完整源码（[`code/t_sigsuspend.c`](../code/t_sigsuspend.c)）：

```c
/*************************************************************************\
*                  Copyright (C) Michael Kerrisk, 2026.                   *
*                                                                         *
* This program is free software. You may use, modify, and redistribute it *
* under the terms of the GNU General Public License as published by the   *
* Free Software Foundation, either version 3 or (at your option) any      *
* later version. This program is distributed without any warranty.  See   *
* the file COPYING.gpl-v3 for details.                                    *
\*************************************************************************/

/* Listing 22-5 */

/* t_sigsuspend.c

   A short program to demonstrate why sigsuspend(&mask) is preferable to
   calling sigprocmask(SIG_SETMASK, &mask, NULL) + pause() separately.
   (By default this program uses sigsuspend(). To make it use pause(),
   compile using "cc -DUSE_PAUSE".)

   Usage: t_sigsuspend [sleep-time]

   Send the SIGINT signal to this program by typing control-C (^C).
   (Terminate the program using SIGQUIT, i.e., type control-\ (^\).)

   This program contains extra code that does not appear in the version shown
   in the book. By defining USE_PAUSE when compiling, we can replace the use of
   sigsuspend() by the nonatomic sigprocmask() + pause(). This allows us to
   show that doing the latter way will cause some signals to be lost.
*/
#define _GNU_SOURCE     /* Get strsignal() declaration from <string.h> */
#include <string.h>
#include <signal.h>
#include <time.h>
#include "signal_functions.h"           /* Declarations of printSigMask()
                                           and printPendingSigs() */
#include "tlpi_hdr.h"

/* Global variable incremented each time SIGINT is handled */

static volatile int sigintCnt = 0;
static volatile sig_atomic_t gotSigquit = 0;

static void
handler(int sig)
{
    printf("Caught signal %d (%s)\n", sig, strsignal(sig));
                                        /* UNSAFE (see Section 21.1.2) */
    if (sig == SIGQUIT)
        gotSigquit = 1;
    sigintCnt++;
}

int
main(int argc, char *argv[])
{
    int loopNum;
#ifdef USE_PAUSE
    int sleepTime;
#endif
    time_t startTime;
    sigset_t origMask, blockMask;
    struct sigaction sa;

    printSigMask(stdout, "Initial signal mask is:\n");

    sigemptyset(&blockMask);
    sigaddset(&blockMask, SIGINT);
    sigaddset(&blockMask, SIGQUIT);

#ifdef USE_PAUSE
    sleepTime = (argc > 1) ? getInt(argv[1], GN_NONNEG, NULL) : 0;
#endif

    /* Block SIGINT and SIGQUIT - at this point we assume that these signals
      are not already blocked (obviously true in this simple program) so that
      'origMask' will not contain either of these signals after the call. */

    if (sigprocmask(SIG_BLOCK, &blockMask, &origMask) == -1)
        errExit("sigprocmask - SIG_BLOCK");

    /* Set up handlers for SIGINT and SIGQUIT */

    sigemptyset(&sa.sa_mask);
    sa.sa_flags = 0;
    sa.sa_handler = handler;
    if (sigaction(SIGINT, &sa, NULL) == -1)
        errExit("sigaction");
    if (sigaction(SIGQUIT, &sa, NULL) == -1)
        errExit("sigaction");

    /* Loop until SIGQUIT received */

    for (loopNum = 1; !gotSigquit; loopNum++) {
        printf("=== LOOP %d\n", loopNum);

        /* Simulate a critical section by delaying a few seconds */

        printSigMask(stdout, "Starting critical section, signal mask is:\n");
        for (startTime = time(NULL); time(NULL) < startTime + 4; )
            continue;                   /* Run for a few seconds elapsed time */

#ifndef USE_PAUSE
        /* The right way: use sigsuspend() to atomically unblock
           signals and pause waiting for signal */

        printPendingSigs(stdout,
                "Before sigsuspend() - pending signals:\n");
        if (sigsuspend(&origMask) == -1 && errno != EINTR)
            errExit("sigsuspend");
#else

        /* The wrong way: unblock signal using sigprocmask(),
           then pause() */

        if (sigprocmask(SIG_SETMASK, &origMask, NULL) == -1)
            errExit("sigprocmask - SIG_SETMASK");

        /* At this point, if SIGINT arrives, it will be caught and
           handled before the pause() call and, in consequence,
           pause() will block. (And thus only another SIGINT signal
           AFTER the pause call() will actually cause the pause()
           call to be interrupted.)  Here we make the window between
           the two calls a bit larger so that we have a better
           chance of sending the signal. */

        if (sleepTime > 0) {
            printf("Unblocked SIGINT, now waiting for %d seconds\n", sleepTime);
            for (startTime = time(NULL);
                    time(NULL) < startTime + sleepTime; )
                continue;
            printf("Finished waiting - now going to pause()\n");
        }

        /* And now wait for the signal */

        pause();

        printf("Signal count = %d\n", sigintCnt);
        sigintCnt = 0;
#endif
    }

    /* Restore signal mask so that signals are unblocked */

    if (sigprocmask(SIG_SETMASK, &origMask, NULL) == -1)
        errExit("sigprocmask - SIG_SETMASK");

    printSigMask(stdout, "=== Exited loop\nRestored signal mask to:\n");

    /* Do other processing... */

    exit(EXIT_SUCCESS);
}
```

编译（macOS 26.6.2 / arm64 · clang 23.1.0）：

```bash
$CC $D -Wall -Wextra -o t_sigsuspend        t_sigsuspend.c        get_num.c signal_functions.c
```

实测输出（运行中在临界区内按一次 `^C`、再按 `^\` 退出）：

```text
Initial signal mask is:
        <empty signal set>
=== LOOP 1
Starting critical section, signal mask is:
        2 (Interrupt: 2)
        3 (Quit: 3)
Before sigsuspend() - pending signals:
        2 (Interrupt: 2)          ← 临界区（busy 4s）内到达的 SIGINT 变 pending
Caught signal 2 (Interrupt: 2)    ← 精确在 sigsuspend 点被处理，无竞态窗口
=== LOOP 2
...
=== Exited loop
Restored signal mask to:
        <empty signal set>
```

**逐条解读**：
- `Initial signal mask is: <empty signal set>`：起步掩码为空；随后 `SIG_BLOCK` 把 `SIGINT`(2)/`SIGQUIT`(3) 挡上，`origMask` 记为「临界区之前」的掩码（空集）。
- `Starting critical section, signal mask is: 2 / 3`：4 秒 busy-loop 期间两个信号都在屏蔽中，任何 `^C`/`^\` 只会进 pending，不会执行 handler——避免「临界区被信号打断」。
- `Before sigsuspend() - pending signals: 2 (Interrupt: 2)`：临界区里按下的 `SIGINT` 老老实实躺在 pending 队列里。这一行同时证明了「信号没丢」和「还没被处理」。
- `Caught signal 2 (Interrupt: 2)`：`sigsuspend(&origMask)` **一次系统调用**完成「把掩码替换为 `origMask`（放行 INT/QUIT）+ 挂起等待」。pending 的 `SIGINT` 在这同一次调用内递送、handler 跑完、`sigsuspend` 返回 `-1/EINTR`。**「放行」和「睡下」之间没有任何可被信号插入的窗口**——这就是本节「原子四步」的实测形态。
- `=== LOOP 2` 直到 `^\`：`SIGQUIT` 让 `gotSigquit=1` 退出循环。注意循环第二轮时掩码被 `sigsuspend` 自动恢复为调用前的阻塞态，无需手动重设。
- `Restored signal mask to: <empty signal set>`：`SIG_SETMASK` 把掩码还原为空集。`sigsuspend` 返回后掩码已经是「调用前」的值，这里的显式恢复是为后续「正常睡眠」铺路。
- 对照 `-DUSE_PAUSE` 版：源码把 `sigsuspend` 换成 `sigprocmask(SIG_SETMASK)` + `pause()` 两步，并给出 `sleepTime` 把窗口撑大——**信号在这两步之间到达就会被 handler 提前消费，`pause()` 随后永久睡死**。这正是本节要消除的竞态。

**源码坐标**：TLPI **Listing 22-5**；`man 2 sigsuspend`（「原子替换掩码并挂起」）· `man 2 sigprocmask` · `man 2 pause` · `man 7 signal`。内核坐标：`kernel/signal.c:4650` `sigsuspend()`（正文「与 pause() 只差三行」已引）。

### 二、`sigsuspend_wait.c`（自编 demo）

Listing 22-5 是教学版，带 `printSigMask` 等辅助与 4 秒临界区。这个自编 demo 抽出**最小可用的生产范式**：装 handler → 先 `SIG_BLOCK` → 构造等待掩码 → `while (!got) sigsuspend(...)`。约 40 行，不依赖 `signal_functions.c`，单独 `clang` 即可编。

完整源码（[`code/sigsuspend_wait.c`](../code/sigsuspend_wait.c)）：

```c
/* Safe wait: block SIGINT, then sigsuspend with mask that unblocks it.
 * cc -Wall -Wextra -o sigsuspend_wait sigsuspend_wait.c && ./sigsuspend_wait
 */
#include <signal.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <unistd.h>

static volatile sig_atomic_t got = 0;

static void on_int(int sig)
{
    (void)sig;
    got = 1;
}

int main(void)
{
    struct sigaction sa;
    sigset_t block, prev, wait_mask;

    memset(&sa, 0, sizeof(sa));
    sa.sa_handler = on_int;
    sigemptyset(&sa.sa_mask);
    if (sigaction(SIGINT, &sa, NULL) == -1) {
        perror("sigaction");
        return EXIT_FAILURE;
    }

    sigemptyset(&block);
    sigaddset(&block, SIGINT);
    if (sigprocmask(SIG_BLOCK, &block, &prev) == -1) {
        perror("sigprocmask");
        return EXIT_FAILURE;
    }

    wait_mask = prev;
    sigdelset(&wait_mask, SIGINT);

    printf("pid=%ld  waiting with sigsuspend — press Ctrl+C\n", (long)getpid());
    while (!got)
        sigsuspend(&wait_mask); /* returns -1/EINTR after handler */

    sigprocmask(SIG_SETMASK, &prev, NULL);
    printf("got SIGINT safely\n");
    return 0;
}
```

编译（macOS 26.6.2 / arm64 · clang 23.1.0）：

```bash
$CC -Wall -Wextra -o sigsuspend_wait        sigsuspend_wait.c
```

实测输出（按一次 `^C`）：

```text
pid=10949  waiting with sigsuspend — press Ctrl+C
got SIGINT safely                             ← exit=0，掩码复原
```

**逐条解读**：
- `pid=10949  waiting with sigsuspend — press Ctrl+C`：程序打印自己的 PID 并进入等待。注意是**先 `sigprocmask(SIG_BLOCK, {SIGINT}, &prev)`** 才等——这样 `^C` 在任何时刻到达都不会跑默认动作，只会进 pending。
- `wait_mask = prev; sigdelset(&wait_mask, SIGINT);`：等待掩码 = 「原掩码去掉 SIGINT」。传入 `sigsuspend` 的是**睡眠期间的完整掩码**，不是「要等哪些信号」——这是本节的头号易错点。
- `while (!got) sigsuspend(&wait_mask);`：单次 `sigsuspend` 可能被其它信号打断（返回 `-1/EINTR` 而 `got` 仍为 0），`while` 负责重睡。若只调一次，遇到无关信号就白返回了。
- `got SIGINT safely` 且 `exit=0`：断言 `^C` 没有杀死进程——handler 只置了标志，掩码在 `sigsuspend` 返回时自动复原，随后再显式 `sigprocmask(SIG_SETMASK, &prev, NULL)` 收尾。这与 `t_sigsuspend` 的「无竞态窗口」是同一个机制的两种写法。
- 对比 `t_sigsuspend`：后者为了教学牺牲了简洁（4 秒 busy-loop + 打印掩码/pending），本 demo 是可直接抄进生产代码的骨架。

**源码坐标**：自编 demo（非原书 Listing）；`man 2 sigsuspend` · `man 2 sigprocmask` · `man 7 signal`。配套：22.10 的 `sigwaitinfo` 是「不跑 handler」的替代路线。

### 三、教学补充片段（非 `code/`，未实测）

```c
/* suspenddemo.c —— sigsuspend 范式 vs pause 竞态
 * 编译: gcc -o suspenddemo suspenddemo.c */
#define _GNU_SOURCE
#include <signal.h>
#include <stdio.h>
#include <unistd.h>

static volatile sig_atomic_t got = 0;
static void handler(int sig) { if (sig == SIGUSR1) got = 1; }

int main(void)
{
    struct sigaction sa = {0};
    sa.sa_handler = handler;
    sigemptyset(&sa.sa_mask);
    sa.sa_flags = 0;                      /* 不用 SA_RESTART */
    sigaction(SIGUSR1, &sa, NULL);

    sigset_t block, orig, wait_mask;
    sigemptyset(&block);
    sigaddset(&block, SIGUSR1);

    /* ① 先阻塞，让信号堆积在 pending */
    sigprocmask(SIG_BLOCK, &block, &orig);
    raise(SIGUSR1);                       /* 进 pending，不会丢 */

    /* ② 构造等待掩码：原掩码去掉 SIGUSR1 */
    wait_mask = orig;
    sigdelset(&wait_mask, SIGUSR1);

    /* ③ while 循环：其他信号也会让 sigsuspend 返回 */
    int loops = 0;
    while (!got && loops < 5) {
        printf("sigsuspend 等待中 (第 %d 次)...\n", ++loops);
        sigsuspend(&wait_mask);           /* 原子：放行 → 等待 → 恢复 */
    }

    printf("被唤醒，got=%d（pending 的 SIGUSR1 在调用瞬间即递送）\n", got);

    /* ④ 掩码已自动恢复为阻塞态，再手动还原 */
    sigprocmask(SIG_SETMASK, &orig, NULL);
    return 0;
}
```

**对照实验**：把第 ③ 步换成

```c
sigprocmask(SIG_SETMASK, &wait_mask, NULL);   /* 解除阻塞 */
pause();                                       /* 信号已在此前递送 → 永久挂起 */
```

即可复现 `pause()` 竞态。

|------|------|
| ① | 保存当前掩码到 `saved_sigmask` |
| ② | 把掩码**替换**为参数 `mask` |
| ③ | 挂起等待信号 |
| ④ | 被唤醒后**恢复**原掩码，返回 `-1/EINTR` |

内核实现（`kernel/signal.c:4650`）：

```c
static int sigsuspend(sigset_t *set)
{
	current->saved_sigmask = current->blocked;   // ①
	set_current_blocked(set);                    // ②
	while (!signal_pending(current)) {           // ③
		__set_current_state(TASK_INTERRUPTIBLE);
		schedule();
	}
	set_restore_sigmask();                       // ④
	return -ERESTARTNOHAND;
}
```

**原子性的来源**：这四步在**同一次系统调用内**完成。用户态若分开写 `sigprocmask()` + `pause()`，两个 syscall 之间必然存在可被信号插入的窗口。

对比 `pause()`（`:4639`）——等待循环**完全相同**，只是少了前后各一行半的掩码操作。所以原子性不来自"做了更多事"，而来自"**这些事在一次系统调用里做完**"。

</details>

<details>
<summary><b>问 2：</b>为什么标准范式要求「先阻塞目标信号，再 <code>sigsuspend</code>」？</summary>

因为要保证信号**不丢失**。

**如果不先阻塞**：

```
   检查标志 (got == 0)  → true
                          ← 信号在此到达并递送，got = 1
   sigsuspend(&mask)    ← 信号已处理完，永远等不到第二次 → 挂起 ❌
```

**先阻塞的标准流程**：

| 阶段 | SIGUSR1 状态 |
|------|-------------|
| 临界区（阻塞态） | 到达的信号进 **pending**，不丢失 |
| `sigsuspend` 调用瞬间 | 若已有 pending → **立即递送并唤醒**（根本不睡） |
| `sigsuspend` 等待中 | 信号到达 → 递送并唤醒 |
| 唤醒后 | 掩码自动回到阻塞态 |

**两条路径都覆盖**：信号要么在等待前堆积（随后被递送唤醒），要么在等待期间直接唤醒——**没有第三种可能**，所以不会丢。

**关键机制**：`sigsuspend` 替换掩码后，内核会检查 pending；若已有未决信号，会**立即递送**而不进入睡眠。这正是「先阻塞」能生效的原因。

</details>

<details>
<summary><b>问 3：</b><code>sigsuspend()</code> 期间生效的掩码是什么？是「在原掩码上解除某些位」吗？</summary>

**是「替换」，不是「相对解除」。**

`sigsuspend(&mask)` 期间生效的就是**你传入的 `mask`**，内核执行 `set_current_blocked(set)`——整体替换，而非在原掩码上做并集/差集。

**推论与常见错误**：

1. 想「等待时解除对 SIGUSR1 的阻塞」，必须传入一个**不含 SIGUSR1 的完整掩码**——通常先取出原掩码，再 `sigdelset` 掉目标：

```c
sigprocmask(SIG_BLOCK, NULL, &wait_mask);   /* 取当前掩码 */
sigdelset(&wait_mask, SIGUSR1);
sigsuspend(&wait_mask);
```

2. **典型错误**——传一个「只包含要等信号」的掩码：

```c
sigset_t only; sigemptyset(&only); sigaddset(&only, SIGUSR1);
sigsuspend(&only);       /* ❌ 等待期间只阻塞 SIGUSR1，其他全部放行 */
```

这与预期恰好相反——本想只放行 SIGUSR1，结果把**其他所有信号**都解除了阻塞。

3. 传空集 `sigsuspend(&empty)` 表示等待期间**不阻塞任何信号**（合法，但任何信号都能唤醒它）。

</details>

<details>
<summary><b>问 4：</b>为什么推荐用 <code>while</code> 循环而不是 <code>if</code>？</summary>

因为 `sigsuspend()` **可能被你不想等的信号唤醒**，而返回值无法区分是哪一个。

```c
/* ❌ 错误：任何信号都会让 sigsuspend 返回 */
if (!got)
    sigsuspend(&wait_mask);

/* ✅ 正确：用标志位循环 */
while (!got)
    sigsuspend(&wait_mask);
```

**三个原因**：

1. `sigsuspend` 总是返回 `-1`，`errno == EINTR`——**不告诉你是哪个信号**
2. 等待期间生效的掩码是 `wait_mask`，其中**其他信号可能未被阻塞**，它们都能唤醒 `sigsuspend`
3. 即便只放行了一个信号，仍可能有终端信号、定时器等干扰

**正确的标志位循环**：

```c
static volatile sig_atomic_t got = 0;
static void handler(int sig) { if (sig == SIGUSR1) got = 1; }   /* 只认目标信号 */

while (!got)            /* 被其他信号唤醒时 got 仍为 0 → 继续等 */
    sigsuspend(&wait_mask);
```

**注意**：标志必须是 `volatile sig_atomic_t`（[Ch21.1](../../chapter-21-signal-handlers/notes/21.1-designing-signal-handlers.md)）——缺 `volatile` 会因编译器缓存优化而永远看不到 handler 的修改，缺 `sig_atomic_t` 则可能读到半写的垃圾值。

</details>

<details>
<summary><b>问 5：</b><code>sigsuspend</code> 能同时等待 I/O 吗？有什么替代？</summary>

**不能**。`sigsuspend` 只能等信号，期间无法同时监听 socket / 文件描述符。

**替代方案**：

| 方案 | 机制 | 适用 |
|------|------|------|
| **`pselect(nfds, ..., &sigmask)`** | 原子「改掩码 + select + 恢复」 | select 语义 |
| **`ppoll(fds, n, ts, &sigmask)`** | 原子「改掩码 + poll + 恢复」 | poll 语义 |
| **`epoll_pwait(ep, ev, max, tmo, &sigmask)`** | 原子「改掩码 + epoll_wait + 恢复」 | **高并发首选** |
| **`signalfd` + `epoll`** | 信号变 fd，与 I/O 一起监听 | **最干净** |

前三者通过 `set_user_sigmask()`（`kernel/signal.c:3131`）在内核里原子完成「改掩码 → 等待 → 恢复」。

**`epoll_pwait` 示例**：

```c
sigset_t mask;
sigemptyset(&mask);
sigaddset(&mask, SIGTERM);
sigprocmask(SIG_BLOCK, &mask, NULL);          /* 平时阻塞 */

sigset_t wait_mask;
sigprocmask(SIG_BLOCK, NULL, &wait_mask);
sigdelset(&wait_mask, SIGTERM);               /* 只在 epoll_wait 期间放行 */

int n = epoll_pwait(epfd, events, MAX, -1, &wait_mask);
```

**HFT 首选 signalfd**（[22.11](22.11-fetching-signals-via-a-file-descriptor.md)）：把信号变成一个 fd，与行情 socket 一起放进同一个 `epoll_wait`——零额外竞态、零 handler、可 `read()` 出每一次信号，且处理代码运行在普通上下文（可随意 `printf`/`malloc`）。

</details>
