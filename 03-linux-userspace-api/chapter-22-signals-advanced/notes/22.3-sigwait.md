## 要点

**不跑 handler**，从 pending 里同步取出信号。

```c
int sigwait(const sigset_t *set, int *sig);
int sigwaitinfo(const sigset_t *set, siginfo_t *info);
int sigtimedwait(const sigset_t *set, siginfo_t *info,
                 const struct timespec *timeout);
```

多线程推荐：

1. 关心的信号在所有线程上**先阻塞**  
2. 专用线程循环 `sigwaitinfo`  
3. 处理逻辑可 `malloc`/`printf`/加锁  

前提：目标信号必须已阻塞，否则可能先异步进 handler。

Demo：[`code/sigwaitinfo_loop.c`](./code/sigwaitinfo_loop.c)

## 常见陷阱

1. **僵尸进程**

```c
fork();
/* 父进程不 wait → 子进程变僵尸 */
```

子进程退出后如果父进程不 wait，子进程变成僵尸（Z 状态），占用 PID 和少量内存。

2. **wait 只等第一个**

```c
wait(&status);  /* 只等任意一个子进程 */
```

wait 等待任意一个子进程。如果有多个子进程，需要循环 wait 或用 waitpid 指定 PID。

3. **status 宏使用错误**

```c
wait(&status);
if (status == 0) ...  /* 错误 */
if (WIFEXITED(status)) ...  /* 正确 */
```

不能直接用 status 值判断。必须用 WIFEXITED/WEXITSTATUS/WIFSIGNALED/WTERMSIG 宏。

## 自测题

**题目 1（选择）：** `wait(&status)` 中 status 的值 0 表示什么？
A. 子进程退出码 0
B. 不能直接判断
C. 子进程被信号杀死
D. 等待失败

<details>
<summary>参考答案</summary>

B。不能直接用 status 值判断。必须用 WIFEXITED(status) 等宏解析。status=9 可能表示被 SIGKILL 杀死，也可能不是。

</details>

**题目 2（判断）：** `waitpid(pid, &status, WNOHANG)` 会阻塞等待子进程退出。

<details>
<summary>参考答案</summary>

错误。WNOHANG 表示非阻塞，如果子进程还没退出立即返回 0。不带 WNOHANG 才会阻塞。

</details>

**题目 3（踩坑）：** 以下代码有什么问题？
```c
pid_t pid = fork();
if (pid == 0) exit(42);
wait(&status);
printf("exit code: %d\n", status);
```

<details>
<summary>参考答案</summary>

status 不能直接用。应该：
`WEXITSTATUS(status)` 提取退出码。
`printf("exit code: %d\n", WEXITSTATUS(status));`

</details>

**题目 4（应用）：** 写代码等待指定子进程，获取退出码或终止信号。

<details>
<summary>参考答案</summary>

```c
int status;
waitpid(pid, &status, 0);
if (WIFEXITED(status))
    printf("exit: %d\n", WEXITSTATUS(status));
else if (WIFSIGNALED(status))
    printf("signal: %d\n", WTERMSIG(status));
```

</details>
