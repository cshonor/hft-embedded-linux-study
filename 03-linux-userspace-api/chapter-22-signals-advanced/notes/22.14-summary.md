# 22.14 总结

> 本章：[TLPI 第 22 章 — 高级信号处理](../README.md)

## 本节回顾

| 小节 | 主题 | 关键 API |
|------|------|----------|
| 22.1-22.4 | handler 设计、siginfo_t | `SA_SIGINFO` |
| 22.5-22.6 | 异步信号安全、sig_atomic_t | async-signal-safe |
| 22.7 | 信号处理函数常见错误 | errno 保存/恢复 |
| 22.8 | 系统调用中断与重启 | `SA_RESTART` |
| 22.9 | sigsuspend | `sigsuspend()` |
| 22.10 | 同步等待 | `sigwaitinfo`, `sigtimedwait` |
| 22.11 | signalfd | `signalfd()` |
| 22.12 | 进程间通信 | `sigqueue()` |
| 22.13 | 遗留 API | `signal`, `sigset` 等 |

### 核心要点

1. `sigsuspend` 消除 `pause` 竞态 — 原子等待
2. `sigwaitinfo` 同步收信号 — 不跑 handler
3. `signalfd` 融入 epoll — 统一事件循环
4. `sigqueue` + 实时信号 — 可排队、可携带数据
5. 遗留 API 全部弃用 — 统一用 `sigaction`

## 与后续衔接

- Ch26 进程间通信 — 信号是最原始的 IPC

## 代码自测

<details>
<summary>1. sigsuspend 如何消除 pause 的竞态？</summary>

sigsuspend 将"解除信号阻塞"和"等待信号"合并为一个原子操作。这样信号不可能在解除阻塞和进入等待之间到达并丢失。
</details>

<details>
<summary>2. signalfd 的前置条件是什么？</summary>

目标信号必须先被 `sigprocmask` 阻塞，否则信号会触发 handler 而非到达 signalfd。创建后通过 `read` 读取 `signalfd_siginfo` 结构。
</details>
