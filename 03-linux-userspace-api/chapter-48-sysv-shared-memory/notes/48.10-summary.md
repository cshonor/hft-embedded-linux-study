# 48.10 Summary

> 本章：[TLPI 第 48 章](./README.md)

## 本节讲什么

第 48 章总结：System V 共享内存的完整 API、使用模式和同步需求。

## 要点

### API 总览

| API | 用途 |
|-----|------|
| `shmget()` | 创建/获取共享内存段 |
| `shmat()` | 映射到进程地址空间 |
| `shmdt()` | 解除映射 |
| `shmctl(IPC_RMID)` | 标记删除 |
| `shmctl(IPC_STAT)` | 获取属性 |
| `shmctl(SHM_LOCK)` | 锁定在物理内存 |
| `ipcs -m` | 查看系统共享内存 |
| `ipcrm -m` | 删除共享内存段 |

### 生命周期

```
shmget(IPC_CREAT) → 创建段
  ↓
shmat() → 映射到进程
  ↓
直接读写共享内存（需同步）
  ↓
shmdt() → 解除映射
  ↓
shmctl(IPC_RMID) → 标记删除（nattch=0 后回收）
```

### 关键特性

| 特性 | 说明 |
|------|------|
| 最快 IPC | 零拷贝，直接内存访问 |
| 无同步 | 需配合信号量/互斥锁 |
| 内核持久 | 进程退出不删除 |
| 地址不同 | 各进程虚拟地址可能不同 |
| 指针无效 | 共享内存中的指针不能跨进程使用 |

### 同步机制选择

| 机制 | 适用 |
|------|------|
| SysV 信号量 | 跨进程互斥 |
| POSIX 信号量 | 跨进程，更简洁 |
| pthread 互斥锁 | 跨进程需 PTHREAD_PROCESS_SHARED |
| 原子操作 | 简单 flag/counter |
| 文件锁 | 低频同步 |

### vs mmap

| 特性 | SysV shm | mmap(MAP_SHARED) |
|------|----------|-------------------|
| API | shmget/shmat | mmap |
| 持久性 | 内核持久 | 取决于映射源 |
| 管理工具 | ipcs/ipcrm | 无标准工具 |
| 移植性 | Unix | POSIX |
| 推荐 | 遗留系统 | 现代应用 |

## HFT / 嵌入式关联

- HFT 行情共享：最快 IPC，纳秒级延迟
- `SHM_LOCK` 防止换出，保证访问不缺页
- 多策略进程只读映射行情快照
- 现代推荐 `mmap(MAP_SHARED | MAP_HUGETLB)` 替代

## 代码自测

<details>
<summary>为什么共享内存需要同步机制？没有同步会怎样？</summary>

共享内存允许多个进程同时读写同一块物理内存，但内核不提供任何同步保证。如果两个进程同时修改同一数据结构（如链表、计数器），会产生数据竞争：读写交错导致数据损坏、计数错误、链表断裂等问题。必须使用信号量、互斥锁或原子操作确保关键区的互斥访问。这是共享内存作为最快 IPC 的代价：性能最高，但同步责任完全由程序员承担。

</details>
