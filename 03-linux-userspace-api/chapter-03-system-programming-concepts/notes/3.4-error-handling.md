## 本节讲什么

这是本章**最容易出错**的一节。TLPI 用一整节讲 `errno`，因为「先看返回值、失败才读 `errno`」这条范式几乎每个人都会在某次 debug 里违反一次。

本节用三个 demo 把 `errno` 钉死：

| demo | 干什么 |
|------|--------|
| `c3_4_errno.c` | 把 `errno` 的**六条硬规则**逐条实测（含线程私有地址对比） |
| `c3_5_errno_traps.c` | 六种典型误用，逐个用实测输出打脸 |
| `c3_13_efault.c` | 把 `EFAULT` 具体化：六种坏指针喂给 `write`，看内核怎么拦 |

## 1. `errno` 的六条硬规则

出处：`man errno(3)` + `man intro(2)`（TLPI 3.4 节把这些散落的规则集中讲了一遍）。

| # | 规则 | 违反后果 |
|---|------|----------|
| 1 | **先看返回值，失败才读 `errno`** | 成功路径上读到的是脏值 |
| 2 | **成功的调用不会把 `errno` 清零** | 用 `if (errno != 0)` 判成败 → 必误报 |
| 3 | `errno` 是一个**可赋值的左值宏**（`#define errno (*__errno_location())`） | 可以手动 `errno = 0` 来「清场」 |
| 4 | `errno` 是**线程私有**的（TLS） | 用它做线程间通信 → 拿不到别的线程的值 |
| 5 | 判断失败必须**紧邻读取**：中间插一条可能失败的调用就会冲掉 | 读到的是中间那次调用的错误 |
| 6 | 库函数失败**不一定**设 `errno`（看各自 man 的 NOTES） | `NULL`/`-1` 不等于「`errno` 有意义」 |

> 规则 2 是本节的核心：**`errno` 是「上一次失败的原因」，不是「当前状态」**。所以它天然不能被用来判断「刚才那步成没成功」。

## 2. 代码示例 A：六条规则逐条实测

源码：[../code/c3_4_errno.c](../code/c3_4_errno.c)

```c
/* TLPI 第 03 章 §3.4 —— errno 范式的六条硬规则 + 一次实测
 *
 * 六条规则（man errno(3) / intro(2)）：
 *   1. 先看返回值，再读 errno —— errno 只在「失败」时有意义
 *   2. **成功的调用不会把 errno 清零**  ← 本节最常被写错的一条
 *   3. errno 是「左值宏」：#define errno (*__errno_location())，所以能赋值
 *   4. errno 是线程私有（TLS）的：每个线程一份自己的 errno
 *   5. 判断「某个调用有没有失败」必须紧邻读取：中间插一条可能失败的调用就会冲掉
 *   6. 库函数失败**不一定**设 errno（看各自 man 的 NOTES）
 *
 * 编译：gcc -O0 -Wall -Wextra -pthread -o c3_4 c3_4_errno.c
 */
#define _GNU_SOURCE
#include <errno.h>
#include <fcntl.h>
#include <pthread.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <unistd.h>

static int *g_main_errno_addr;
static int *g_thread_errno_addr;

static void *worker(void *arg)
{
    (void) arg;
    /* 先把本线程的 errno 弄成非零，证明它跟主线程互相独立 */
    errno = 12345;
    g_thread_errno_addr = &errno;
    printf("  线程：   &errno = %p   errno = %d\n", (void *) &errno, errno);
    return NULL;
}

int main(void)
{
    setvbuf(stdout, NULL, _IONBF, 0);
    int save;

    printf("=== 规则 2 实测：成功的调用不会清零 errno ===\n");
    errno = 0;
    int fd = open("/dev/null", O_RDONLY);          /* 必然成功 */
    printf("  errno=0 时 open(\"/dev/null\") 成功 → fd=%d，errno=%d\n", fd, errno);

    /* 先人为制造一个非零 errno，再跑一个成功的调用 */
    open("/definitely/not/here", O_RDONLY);        /* 必然失败，errno 被设上 */
    save = errno;
    printf("  制造失败后                     errno=%d (%s)\n", save, strerror(save));

    close(fd);
    close(-1);                                     /* 这个会失败 */
    printf("  紧接着再做一次成功的 close      → close(fd) 的返回值被忽略，errno 仍是 %d\n",
           errno);
    printf("  ↑ 结论：**errno 不会被成功调用清掉**，所以「errno != 0 就说明上一步失败」是错的\n\n");

    printf("=== 规则 3 实测：errno 是可赋值的左值宏 ===\n");
    errno = 0;
    printf("  errno = 0 之后读回 = %d\n", errno);
    errno = EDOM;
    printf("  errno = EDOM(%d) 之后读回 = %d (%s)\n", EDOM, errno, strerror(errno));
    printf("  errno 的地址（即 __errno_location()）= %p\n\n", (void *) &errno);
    errno = 0;

    printf("=== 规则 4 实测：errno 是线程私有的 ===\n");
    g_main_errno_addr = &errno;
    errno = 999;
    printf("  主线程：&errno = %p   errno = %d\n", (void *) g_main_errno_addr, errno);
    pthread_t tid;
    if (pthread_create(&tid, NULL, worker, NULL) == 0) {
        pthread_join(tid, NULL);
        printf("  两个地址%s → errno 是 TLS，多线程下各自失败互不干扰\n",
               g_main_errno_addr == g_thread_errno_addr ? "相同（意外！）" : "不同");
    } else {
        printf("  pthread_create 失败\n");
    }
    printf("  主线程的 errno 仍是 %d（没被线程里那次赋值影响）\n\n", errno);

    printf("=== 规则 5 实测：中间插一条调用会冲掉 errno ===\n");
    errno = 0;
    int bad = open("/definitely/not/here", O_RDONLY);
    int saved = errno;                    /* ✅ 紧邻读取 */
    printf("  失败 open → bad=%d，立刻读 errno=%d (%s)\n", bad, saved, strerror(saved));

    errno = 0;
    bad = open("/definitely/not/here", O_RDONLY);
    printf("  失败 open → bad=%d，但中间先 printf 了一次（它自己可能碰 errno）\n", bad);
    printf("  之后才读 errno=%d\n", errno);
    printf("  ↑ 顺序上「printf 之后再读」在本次碰巧还对，但这是运气；范式要求紧邻读\n\n");

    printf("=== 规则 6 实测：库函数失败不一定设 errno ===\n");
    errno = 0;
    double d = strtod("0.0", NULL);       /* 成功，不该碰 errno */
    printf("  strtod(\"0.0\") = %g，errno = %d\n", d, errno);
    errno = 0;
    d = strtod("1e9999", NULL);           /* 溢出 → 规范要求设 ERANGE */
    printf("  strtod(\"1e9999\") = %g，errno = %d (%s)\n", d, errno, strerror(errno));

    errno = 0;
    char *e = getenv("___definitely_not_set___");
    printf("  getenv(不存在) = %p，errno = %d  ← NULL 不代表出错，读 man NOTES\n",
           (void *) e, errno);
    return 0;
}
```

编译与运行（CE 复核，gcc 13.3.0 / x86-64 / Ubuntu 24.04，`-O0 -Wall -Wextra -pthread`，**build code = 0，diagnostics = 0**）：

```text
=== 规则 2 实测：成功的调用不会清零 errno ===
  errno=0 时 open("/dev/null") 成功 → fd=3，errno=0
  制造失败后                     errno=2 (No such file or directory)
  紧接着再做一次成功的 close      → close(fd) 的返回值被忽略，errno 仍是 9
  ↑ 结论：**errno 不会被成功调用清掉**，所以「errno != 0 就说明上一步失败」是错的

=== 规则 3 实测：errno 是可赋值的左值宏 ===
  errno = 0 之后读回 = 0
  errno = EDOM(33) 之后读回 = 33 (Numerical argument out of domain)
  errno 的地址（即 __errno_location()）= 0x7eae35ea86c8

=== 规则 4 实测：errno 是线程私有的 ===
  主线程：&errno = 0x7eae35ea86c8   errno = 999
  线程：   &errno = 0x7eae35bff648   errno = 12345
  两个地址不同 → errno 是 TLS，多线程下各自失败互不干扰
  主线程的 errno 仍是 999（没被线程里那次赋值影响）

=== 规则 5 实测：中间插一条调用会冲掉 errno ===
  失败 open → bad=-1，立刻读 errno=2 (No such file or directory)
  失败 open → bad=-1，但中间先 printf 了一次（它自己可能碰 errno）
  之后才读 errno=2
  ↑ 顺序上「printf 之后再读」在本次碰巧还对，但这是运气；范式要求紧邻读

=== 规则 6 实测：库函数失败不一定设 errno ===
  strtod("0.0") = 0，errno = 0
  strtod("1e9999") = inf，errno = 34 (Numerical result out of range)
  getenv(不存在) = (nil)，errno = 0  ← NULL 不代表出错，读 man NOTES
```

### 逐条解读

| 段 | 读数 | 说明 |
|----|------|------|
| 规则 2 | 失败留下 `errno=2`，随后 `close(fd)` 成功 **但 `errno` 仍是 9** | 实验设计很讲究：先制造 `ENOENT(2)`，再故意 `close(-1)` 把 `errno` 改成 `EBADF(9)`——于是能同时证明「成功调用不动 `errno`」**和**「`errno` 会被覆盖」 |
| 规则 3 | `errno = EDOM(33)` 后读回 33 | 能赋值 ⇒ 它必然是宏（展开成 `*(__errno_location())`），不是普通变量。所以「取 `errno` 的地址」其实取的是 TLS 里那个 `int` 的地址 |
| 规则 4 | 主线程 `0x7eae35ea86c8` vs 线程 `0x7eae35bff648` | **地址不同** ⇒ 实实在在的两份。线程里 `errno = 12345` 不影响主线程的 999 |
| 规则 5 | 「printf 之后再读」这次碰巧还是 2 | 这是**运气**：glibc 的 `printf` 在成功路径上通常不碰 `errno`。范式要求「紧邻读」，不能靠运气 |
| 规则 6 | `strtod("1e9999")` → `inf` + `errno=34`（`ERANGE`） | 溢出时设 `ERANGE` 是 POSIX 要求；但 `strtod` 成功后**不保证**清零 |
| 规则 6 | `getenv(不存在)` → `NULL`，`errno = 0` | **`NULL` 不代表出错**。`getenv` 的 man NOTES 明确说「找不到」不是错误。不查文档就报 `errno` 会冤枉库函数 |

## 3. 代码示例 B：六种误用逐个打脸

源码：[../code/c3_5_errno_traps.c](../code/c3_5_errno_traps.c)

```c
/* TLPI 第 03 章 §3.4 —— errno 六种典型误用，逐个实测打脸
 *
 * 每条误用都给出「错在哪 → 实测现象 → 正确写法」。
 * 编译：gcc -O0 -Wall -Wextra -pthread -o c3_5 c3_5_errno_traps.c
 */
#define _GNU_SOURCE
#include <errno.h>
#include <fcntl.h>
#include <pthread.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <unistd.h>

static char *g_saved_strerror1;
static char *g_saved_strerror2;

static void *worker(void *arg)
{
    (void) arg;
    /* 误用 ⑤：多线程里共享 strerror 的静态缓冲 */
    g_saved_strerror2 = strerror(EACCES);
    return NULL;
}

int main(void)
{
    setvbuf(stdout, NULL, _IONBF, 0);

    printf("=== 误用 1：用「errno != 0」判上一步是否失败 ===\n");
    errno = 0;
    int fd = open("/dev/null", O_RDONLY);
    printf("  成功 open 后 errno = %d（干净场景下确实是 0）\n", errno);
    close(fd);
    errno = 0;
    open("/definitely/not/here", O_RDONLY);   /* 失败，留下 ENOENT */
    fd = open("/dev/null", O_RDONLY);         /* 又成功，但 errno 不会归零 */
    printf("  失败一次再成功一次，errno = %d (%s)  → 用 errno!=0 判成功/失败必然误报\n",
           errno, strerror(errno));
    close(fd);
    printf("  正确：判返回值。open 失败才返回 -1，此时 errno 才有意义\n\n");

    printf("=== 误用 2：不查返回值，直接读 errno ===\n");
    errno = 0;
    char *p = getenv("___not_set___");
    printf("  getenv(不存在) 返回 %p，errno = %d\n", (void *) p, errno);
    printf("  → 返回 NULL 是「没找到」，不是「出错」；不查文档就报错会冤枉库函数\n\n");

    printf("=== 误用 3：把 errno 当普通全局变量跨线程传 ===\n");
    errno = 7;
    pthread_t tid;
    if (pthread_create(&tid, NULL, worker, NULL) == 0) {
        pthread_join(tid, NULL);
    }
    printf("  主线程 errno = %d（线程里设的 EACCES=%d 完全没影响主线程）\n", errno, EACCES);
    printf("  → errno 是 __thread 变量，每线程一份；不能用它做线程间通信\n\n");

    printf("=== 误用 4：长期保存 strerror 返回的指针 ===\n");
    g_saved_strerror1 = strerror(ENOENT);
    printf("  第一次 strerror(ENOENT) → %p  \"%s\"\n", (void *) g_saved_strerror1,
           g_saved_strerror1);
    g_saved_strerror1 = strerror(EACCES);      /* 下一次调用覆写同一块静态缓冲 */
    printf("  再调 strerror(EACCES)  → %p  \"%s\"\n", (void *) g_saved_strerror1,
           g_saved_strerror1);
    char *again = strerror(ENOENT);
    printf("  第三次 strerror(ENOENT)→ %p  \"%s\"\n", (void *) again, again);
    printf("  → 地址恒定为同一块静态缓冲，**保存指针等于保存「最后一次」的结果**\n");
    printf("    正确：立刻 strcpy/strdup 到自己缓冲；或改用 strerror_r\n\n");

    printf("=== 误用 5：多线程共享 strerror 的静态缓冲 ===\n");
    if (pthread_create(&tid, NULL, worker, NULL) == 0) {
        pthread_join(tid, NULL);
    }
    printf("  线程里算出的指针 %p，主线程拿它的结果 = \"%s\"\n", (void *) g_saved_strerror2,
           g_saved_strerror2);
    printf("  → 两个线程写同一块缓冲，谁后写谁赢 → 数据竞争\n");
    printf("    正确：用 strerror_r / strerror_l，各自传入自己的缓冲\n\n");

    printf("=== 误用 6：把 perror 当万能报错，丢掉上下文 ===\n");
    errno = ENOENT;
    printf("  perror 输出（到 stderr）：");
    fflush(stdout);
    perror("c3_5");
    printf("  perror(msg) 等价于 fprintf(stderr, \"%%s: %%s\\n\", msg, strerror(errno))\n");
    printf("  它只给「哪一步 + 什么错」，给不了「哪个路径、哪个 fd」——业务上下文要自己带\n\n");

    printf("=== 附：glibc 的 %%m 扩展（等价于 strerror(errno)，但不用另起参数）===\n");
    errno = EACCES;
    printf("  printf 里的 %%m 直接展开：errno=%d 就是 \"%m\"\n", errno);
    printf("  ↑ 这是 glibc 私有扩展，可移植代码里别用\n");
    errno = 0;
    return 0;
}
```

编译与运行（CE 复核，`-O0 -Wall -Wextra -pthread`，**build code = 0，diagnostics = 0**）：

```text
=== 误用 1：用「errno != 0」判上一步是否失败 ===
  成功 open 后 errno = 0（干净场景下确实是 0）
  失败一次再成功一次，errno = 2 (No such file or directory)  → 用 errno!=0 判成功/失败必然误报
  正确：判返回值。open 失败才返回 -1，此时 errno 才有意义

=== 误用 2：不查返回值，直接读 errno ===
  getenv(不存在) 返回 (nil)，errno = 0
  → 返回 NULL 是「没找到」，不是「出错」；不查文档就报错会冤枉库函数

=== 误用 3：把 errno 当普通全局变量跨线程传 ===
  主线程 errno = 7（线程里设的 EACCES=13 完全没影响主线程）
  → errno 是 __thread 变量，每线程一份；不能用它做线程间通信

=== 误用 4：长期保存 strerror 返回的指针 ===
  第一次 strerror(ENOENT) → 0x7ac7f39cb77a  "No such file or directory"
  再调 strerror(EACCES)  → 0x7ac7f39cb850  "Permission denied"
  第三次 strerror(ENOENT)→ 0x7ac7f39cb77a  "No such file or directory"
  → 地址恒定为同一块静态缓冲，**保存指针等于保存「最后一次」的结果**
    正确：立刻 strcpy/strdup 到自己缓冲；或改用 strerror_r

=== 误用 5：多线程共享 strerror 的静态缓冲 ===
  线程里算出的指针 0x7ac7f39cb850，主线程拿它的结果 = "Permission denied"
  → 两个线程写同一块缓冲，谁后写谁赢 → 数据竞争
    正确：用 strerror_r / strerror_l，各自传入自己的缓冲

=== 误用 6：把 perror 当万能报错，丢掉上下文 ===
  perror 输出（到 stderr）：  perror(msg) 等价于 fprintf(stderr, "%s: %s\n", msg, strerror(errno))
  它只给「哪一步 + 什么错」，给不了「哪个路径、哪个 fd」——业务上下文要自己带

=== 附：glibc 的 %m 扩展（等价于 strerror(errno)，但不用另起参数）===
  printf 里的 %m 直接展开：errno=13 就是 "Permission denied"
  ↑ 这是 glibc 私有扩展，可移植代码里别用
```

（该程序在 stderr 上还有一行 `c3_5: No such file or directory`，那是误用 6 里 `perror("c3_5")` 的真实输出。）

### 逐条解读

| 误用 | 实测证据 | 正确做法 |
|------|----------|----------|
| 1 | 「失败一次再成功一次」之后 `errno` 还是 2 | **判返回值**（`fd == -1`），`errno` 只在失败路径上有意义 |
| 2 | `getenv` 返回 `NULL` 且 `errno = 0` | 先读 man 的 NOTES：哪些返回值算「失败」 |
| 3 | 主线程 `errno = 7`，线程里给它设 `EACCES(13)`，主线程纹丝不动 | 别用 `errno` 传值；它每线程一份（与规则 4 是同一个事实的两个方向） |
| 4 | **同一地址** `0x7ac7f39cb77a` 第三次出现 | `strerror` 返回静态缓冲，**保存指针等于保存最后一次**；要留就 `strcpy`/`strdup`，或用 `strerror_r` |
| 5 | 线程算的指针被主线程读出来是 "Permission denied" | 多线程必须 `strerror_r(errnum, buf, len)`，各自传自己的缓冲 |
| 6 | `perror` 输出到 **stderr**：`c3_5: No such file or directory` | `perror` 只给「哪一步 + 什么错」。哪个路径、哪个 fd、哪次重试——业务上下文要自己带 |

> **误用 4 和 5 是同一个坑的两种表现**：`strerror` 用一块**全局静态缓冲**（因此非线程安全），第一次和第三次返回的是**完全相同的地址**——这不是巧合，是同一块内存被反复覆写。HFT 里做高频日志时，把 `strerror(errno)` 的结果直接存进日志结构体，等同于存了「最后一次错误」。

## 4. 代码示例 C：把 `EFAULT` 具体化

源码：[../code/c3_13_efault.c](../code/c3_13_efault.c)

```c
/* TLPI 第 03 章 §3.4（+ §3.1 的「参数怎么传进内核」）—— EFAULT：把非法指针交给内核会怎样
 *
 * 内核**不能信任**用户指针：它可能指向内核地址、指向别的进程、或根本没映射。
 * 所以每个带指针参数的系统调用都要先 access_ok() 校验、再 copy_from_user() 拷贝。
 * 校验失败时系统调用返回 -1 + EFAULT(14)（裸 syscall 拿到的是 -14）。
 *
 * 本 demo 逐种「坏指针」实测，并把 errno 与裸 syscall 的返回值并排打印，
 * 顺带把 EFAULT 与其它「看着像但完全不同」的错误码分开（EFAULT vs EBADF vs EINVAL）。
 *
 * 编译：gcc -O0 -Wall -Wextra -o c3_13 c3_13_efault.c
 */
#define _GNU_SOURCE
#include <errno.h>
#include <stdio.h>
#include <string.h>
#include <sys/mman.h>
#include <sys/syscall.h>
#include <unistd.h>

/* printf 的 %-34s 是按**字节**补齐的，而一个汉字 3 字节、显示只占 2 列 →
 * 直接用会参差不齐。这里自己数显示宽度：ASCII 记 1 列，非 ASCII 记 2 列。 */
static int disp_width(const char *s)
{
    int w = 0;
    for (; *s; s++) {
        unsigned char c = (unsigned char) *s;
        if (c < 0x80) {
            w += 1;
        } else if ((c & 0xC0) != 0x80) {   /* UTF-8 续字节不重复计数 */
            w += 2;
        }
    }
    return w;
}

static void pad(const char *s, int width)
{
    fputs(s, stdout);
    for (int i = disp_width(s); i < width; i++) {
        putchar(' ');
    }
}

static void probe(const char *tag, const void *p, size_t n)
{
    /* ① glibc 包装：-1 + errno */
    errno = 0;
    ssize_t r = write(STDOUT_FILENO, p, n);
    int e1 = errno;

    /* ② 裸 syscall 指令：直接拿内核的 -errno（不经过 glibc 翻译） */
    errno = 0;
    long r2;
    __asm__ volatile ("syscall"
                      : "=a"(r2)
                      : "a"((long) SYS_write), "D"((long) STDOUT_FILENO),
                        "S"((long) p), "d"((long) n)
                      : "rcx", "r11", "memory");
    int e2 = errno;

    printf("  ");
    pad(tag, 30);
    printf("write()=%2zd errno=%-3d %-14s | raw=%4ld errno=%d\n",
           r, e1, e1 ? strerror(e1) : "(成功)", r2, e2);
}

int main(void)
{
    setvbuf(stdout, NULL, _IONBF, 0);

    char ok[] = "[3.13] 合法缓冲区，正常写出\n";
    char *unmapped = (char *) 0x1;                     /* 极低地址，必然未映射 */
    char *kernel_ish = (char *) 0xffffffff81000000ULL;  /* 看着像内核地址 */

    /* 只读映射页：先写内容，再把写权限去掉。write(2) 只需要对用户缓冲有**读**权限 */
    void *map = mmap(NULL, 4096, PROT_READ | PROT_WRITE, MAP_PRIVATE | MAP_ANONYMOUS, -1, 0);
    if (map != MAP_FAILED) {
        memcpy(map, "RO-PAGE\n", 8);
        mprotect(map, 4096, PROT_READ);
    }

    printf("=== 各种指针喂给 write(1, p, n) 的结果 ===\n");
    probe("合法栈缓冲区", ok, strlen(ok));
    probe("NULL（n=10）", NULL, 10);
    probe("NULL（n=0）", NULL, 0);            /* n=0 时内核对 buf 不做检查 */
    probe("(char*)0x1（未映射）", unmapped, 10);
    probe("(char*)0x1（n=0）", unmapped, 0);
    probe("0xffffffff81000000（越界）", kernel_ish, 10);
    probe("只读映射页（无写权限）", map, 8);   /* 只能读的页，仍然能作为 write 的源 */

    printf("\n=== 逐条结论 ===\n");
    printf("  1. NULL 与野指针都得到 EFAULT(14)，**不是** SIGSEGV —— 内核在拷贝前就拦下了\n");
    printf("     这一点很重要：用户态传坏指针不会把内核搞崩，只会拿到一个错误码\n");
    printf("  2. n=0 是特例：没有任何字节要拷，内核通常不再校验 buf（Linux 上 write(fd,NULL,0)=0）\n");
    printf("     所以「n=0 时指针可以随便传」是**依赖实现**的行为，别写进代码\n");
    printf("  3. raw 那一列拿到的是 -14，而 glibc 那列是 -1 + errno=14\n");
    printf("     同一件事的两种表示，正是 §3.1 讲的「内核用 [-4095,-1] 表示错误」\n");
    printf("  4. 只读映射页这一行说明：write(2) 只**读**你的缓冲，不写它。\n");
    printf("     所以 mmap(PROT_READ) 的内存可以直接作为 write/send 的源\n");
    printf("  5. EFAULT ≠ EBADF ≠ EINVAL：\n");
    printf("     EFAULT = 指针/地址不合法（内存 bug，先查指针生命周期）\n");
    printf("     EBADF  = fd 不是有效的打开文件描述符（fd 管理 bug）\n");
    printf("     EINVAL = 参数取值不在允许范围（调用方逻辑 bug）\n");

    if (map != MAP_FAILED) {
        munmap(map, 4096);
    }
    printf("\n=== 为什么内核必须拷贝：本节的机制落点 ===\n");
    printf("  内核拿到用户指针后不能直接解引用，必须先把数据 copy_from_user 进内核缓冲；\n");
    printf("  拷贝那一刻用户态若改了这块内存，内核用的仍是已拷贝的那份副本 → 无竞争。\n");
    printf("  代价就是要付一次内存拷贝：这是「大缓冲 write 有开销」的来源之一，\n");
    printf("  也是零拷贝方案（mmap / sendfile / splice）存在的理由。\n");
    return 0;
}
```

## 5. 常用错误码速查（HFT 高频）

| errno | 值 | 含义 | 典型场景 |
|-------|-----|------|----------|
| `EPERM` | 1 | 权限不足（无 capability） | 绑低端口、改系统参数 |
| `ENOENT` | 2 | 文件/目录不存在 | 配置路径写错 |
| `EINTR` | 4 | 被信号打断 | `read`/`epoll_wait` 被信号中断 |
| `EAGAIN`/`EWOULDBLOCK` | 11 | 非阻塞操作暂无数据 | 非阻塞 fd 读空 |
| `ENOMEM` | 12 | 内存不足 | 分配失败 |
| `EACCES` | 13 | 权限拒绝 | 打开无权限文件 |
| `EFAULT` | 14 | 传给内核的指针非法 | 野指针传给 syscall（本节 C 段） |
| `EBUSY` | 16 | 资源忙 | 文件锁冲突、设备占用 |
| `EINVAL` | 22 | 参数无效 | flags 传错 |
| `EMFILE` | 24 | 进程 fd 数达上限 | fd 泄漏 |
| `ENOSPC` | 28 | 空间不足 | 写盘失败 |
| `EPIPE` | 32 | 管道读端已关 | 写已关闭的 socket（配 `SIGPIPE`，见 [3.1](3.1-system-calls.md)） |
| `ERANGE` | 34 | 数值结果超范围 | `strtod("1e9999")`（本节 A 段实测） |

> **`EINTR` 是系统编程最常被忽略的错误码**：它是「正常情况」不是「失败」，必须重试而不是报错退出。见 Ch21 信号、Ch63 epoll。

## 6. 打印 / 退出工具

| 函数 | 作用 | 注意 |
|------|------|------|
| `perror(msg)` | 打印 `msg: strerror(errno)` 到 stderr | 用当前 `errno`，最简单 |
| `strerror(errnum)` | 错误码 → 字符串 | **非线程安全**（静态缓冲，本节 B 段误用 4/5） |
| `strerror_r(errnum, buf, len)` | 线程安全版 | glibc 下**两种签名**：`_GNU_SOURCE` 时返回 `char *`，严格 POSIX 时返回 `int`（见 [3.6.1](3.6-portability.md)） |
| `%m`（glibc 扩展） | `printf` 里直接展开 `strerror(errno)` | 非标准，可移植代码别用 |
| 原书 `errExit(msg)` | 打印 `prog: msg: strerror(errno)` 后 `exit(EXIT_FAILURE)` | 见 [3.5.2](3.5-example-programs.md) |
| 原书 `err_exit(msg)` | 同上，但用 `_exit()`（**不 flush stdio**） | 崩溃路径上会丢缓冲里的日志 |
| 原书 `errExitEN(errnum, msg)` | 用**显式**错误码而非当前 `errno` | 用于 `pthread_*` 这类「失败码是返回值」的 API |
| 原书 `errMsg(msg)` | 只打印不退出 | 可继续执行的错误 |

<summary>代码自测（Q&A）</summary>

**Q1：为什么「成功不会清零 `errno`」？会导致什么 bug？**
A：因为成功时内核/glibc 不去碰 `errno`（省一次写）。它保留的是**上一次失败**留下的旧值。所以 `if (errno != 0)` 判断成败是错的：本 demo 实测「失败一次（`errno=2`）再成功一次」之后 `errno` 仍是 2。正确做法是**先看返回值**（`fd == -1`），失败后才读 `errno`。

**Q2：系统调用失败为什么「返回 -1」，而具体原因在 `errno`？**
A：内核实际返回 `-errno`（如 `-2` = `-ENOENT`，落在 `[-4095,-1]`，`MAX_ERRNO=4095`）。glibc 包装判断返回值是否在这个范围：是则 `errno = -返回值`、返回 `-1`，否则当合法值返回。所以直接发 `syscall` 指令拿到的是 `-2` 而不是 `-1`。

**Q3：`errno` 是线程安全的吗？能不能跨线程用它传值？**
A：它是**每线程一份**的 TLS 变量（本 demo 实测主线程与子线程的 `&errno` 地址不同：`0x7eae35ea86c8` vs `0x7eae35bff648`），所以线程内读写是安全的，但**不能用它做线程间通信**——别的线程永远看不到你写的值。

**Q4：为什么不建议长期保存 `strerror()` 返回的指针？**
A：`strerror` 返回的是**同一块全局静态缓冲**的地址。本 demo 实测：`strerror(ENOENT)` → `0x7ac7f39cb77a`，`strerror(EACCES)` → `0x7ac7f39cb850`，第三次 `strerror(ENOENT)` → **又是** `0x7ac7f39cb77a`。所以保存指针 = 保存「最后一次」的结果，且多线程下是数据竞争。要留就立刻 `strcpy`/`strdup`，或改用 `strerror_r`。

**Q5：`perror("open")` 打印的是 `fd` 的错还是 `errno` 的错？**
A：是 `errno` 的错。`perror(msg)` 等价于 `fprintf(stderr, "%s: %s\n", msg, strerror(errno))`，用**当前** `errno`。所以它必须在「失败分支里、紧接着失败调用」使用；中间插了别的调用就可能打出别人的错。

**Q6：`EFAULT` 和 `EBADF`、`EINVAL` 分别指向哪类 bug？**
A：`EFAULT(14)` = 指针/地址不合法 → **内存 bug**（野指针、悬空指针、越界），先查指针生命周期；`EBADF(9)` = fd 无效 → **fd 管理 bug**（未打开、已关闭、写只读 fd）；`EINVAL(22)` = 参数取值不在允许范围 → **调用方逻辑 bug**（`flags` 组合非法、`count` 超限）。三者混起来查会走很多弯路。
