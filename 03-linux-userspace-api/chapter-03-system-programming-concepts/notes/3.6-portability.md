## 本节讲什么

3.6 分三个子节，回答三类「同一份代码换平台就不一样」的问题：

| 小节 | 管什么 | demo |
|------|--------|------|
| **3.6.1** Feature Test Macros | **API 可见性**：同一个头文件里的同一个函数，能不能被声明 | `c3_9_ftm.c`（5 组旗标） |
| **3.6.2** System Data Types | **类型宽度**：`off_t`/`pid_t`/`size_t` 到底几字节 | `c3_10_types.c`（2 组设定） |
| **3.6.3** Miscellaneous Portability Issues | **语义细节**：字节序、`char` 符号性、负数右移、结构体对齐 | `c3_11_portability.c` |

三件事其实是一件事的三个面：**C 语言把大量行为留给了「实现定义」（implementation-defined）**，而 Linux 又在其上叠了一层「用宏选择方言」的机制。

| 障碍 | 例子 | 后果 |
|------|------|------|
| **API 存在性** | `epoll` 只有 Linux；`kqueue` 只有 BSD | 直接调用 → 别的平台编译不过 |
| **类型宽度** | `long` 在 LP64 是 8 字节、ILP32 是 4 字节 | 文件偏移 / ID 溢出，ABI 不匹配 |
| **语义细节** | `strerror_r` 在 glibc 是 `char *`、musl 是 `int` | 同一函数不同 C 库行为不同 |

## 1. §3.6.1 功能测试宏：glibc 的「方言开关」

背景事实：glibc 的同一个头文件里同时放着 ISO-C 的、POSIX 的、X/Open 的、GNU 私有的函数声明。**默认只暴露最保守的一批**。要解锁更多，得在 `#include` **之前**声明「我要用哪个标准」——这就是功能测试宏（Feature Test Macro, FTM）。

| 宏 | 取值示例 | 解锁什么 |
|----|----------|----------|
| `_POSIX_C_SOURCE` | `200809L` | POSIX.1-2008 标准接口 |
| `_XOPEN_SOURCE` | `700` | SUSv4（X/Open，POSIX 超集） |
| `_GNU_SOURCE` | （有定义即可） | 全部 + Linux/GNU 扩展（`epoll`、GNU 版 `strerror_r`） |
| `_DEFAULT_SOURCE` | （有定义即可） | glibc 默认暴露的杂项 BSD/Linux 函数（`memmem` 等） |
| `_FILE_OFFSET_BITS` | `64` | 把 `off_t` 换成 64 位（见 §3.6.2） |

### 机制：`features.h` 把 FTM 翻译成 `__USE_*`

```
#include <unistd.h>          （任何 glibc 标准头）
      │  开头 #include <features.h>
      ▼
features.h 读 _GNU_SOURCE / _POSIX_C_SOURCE / _XOPEN_SOURCE / _DEFAULT_SOURCE ...
      │  换算成 __USE_GNU / __USE_POSIX / __USE_XOPEN2K8 / __USE_MISC ... 内部开关
      ▼
各头文件按 __USE_* 决定「这条声明露不露」
   例：string.h:385  #ifdef __USE_MISC → memmem() 才声明
```

**这就是「FTM 必须在所有 `#include` 之前」的底层原因**：`<features.h>` 只被有效处理一次，先 include 了别的头，开关就已经在「默认方言」下定死了。

### 代码示例 A：五组旗标，同一个源文件五种结果

```c
/* TLPI 第 03 章 §3.6.1 —— 功能测试宏（feature test macros）到底在控制什么
 *
 * 同一个头文件里，同一个函数「可见 / 不可见」取决于你在 `#include` **之前**
 * 定义了哪些宏。glibc 的 <features.h> 把你的宏翻译成一组内部开关 __USE_*，
 * 各头文件再按这些开关决定要不要声明某个函数。
 *
 * ⚠️ 本文件列出的 __USE_* 名字与下面 ③ 段的守护条件，全部**逐字抄**自
 *    glibc 2.39 的 include/features.h、string/string.h、time/time.h：
 *      · features.h 里真实存在 25 个 __USE_*；**没有** __USE_POSIX2008 这个名字，
 *        POSIX.1-2008 在 features.h 里的体现是 __USE_XOPEN2K8
 *      · memmem() 的守护开关是 __USE_MISC（string.h:385），不是 __USE_GNU
 *      · strerror_r() 在 __USE_GNU 下是另一种签名（string.h:428 / 448）
 *
 * 本 demo 的意义在于：**同一个源码，用不同的编译参数编出来，输出完全不同**。
 * 笔记里给出 5 组参数下的实测输出对照。
 *
 * 编译（5 组，见笔记实测块）：
 *   gcc -O0 -Wall -Wextra -o c3_9 c3_9_ftm.c
 *   gcc -O0 -Wall -Wextra -D_POSIX_C_SOURCE=200809L -o c3_9 c3_9_ftm.c
 *   gcc -O0 -Wall -Wextra -D_XOPEN_SOURCE=700     -o c3_9 c3_9_ftm.c
 *   gcc -O0 -Wall -Wextra -D_GNU_SOURCE           -o c3_9 c3_9_ftm.c
 *   gcc -O0 -Wall -Wextra -std=c99                -o c3_9 c3_9_ftm.c
 */
#include <features.h>
#include <stdio.h>

static void flag(const char *name, int on)
{
    printf("  %-26s %s\n", name, on ? "ON " : "OFF");
}

int main(void)
{
    printf("=== ① 我定义了什么（编译参数 + glibc 的自动补全）===\n");
#ifdef _GNU_SOURCE
    printf("  _GNU_SOURCE        = %ld\n", (long) _GNU_SOURCE);
#else
    printf("  _GNU_SOURCE        未定义\n");
#endif
#ifdef _POSIX_C_SOURCE
    printf("  _POSIX_C_SOURCE    = %ldL\n", (long) _POSIX_C_SOURCE);
#else
    printf("  _POSIX_C_SOURCE    未定义\n");
#endif
#ifdef _XOPEN_SOURCE
    printf("  _XOPEN_SOURCE      = %ld\n", (long) _XOPEN_SOURCE);
#else
    printf("  _XOPEN_SOURCE      未定义\n");
#endif
#ifdef _DEFAULT_SOURCE
    printf("  _DEFAULT_SOURCE    = %ld  （没指定别的 FTM、又不是严格 ANSI 时 glibc 自己给的）\n",
           (long) _DEFAULT_SOURCE);
#else
    printf("  _DEFAULT_SOURCE    未定义\n");
#endif
#ifdef __STRICT_ANSI__
    printf("  __STRICT_ANSI__    = %d  （-std=c99 这类「严格标准」模式才会置上）\n",
           __STRICT_ANSI__);
#else
    printf("  __STRICT_ANSI__    未定义\n");
#endif
    printf("  __STDC_VERSION__   = %ldL\n", (long) __STDC_VERSION__);

    printf("\n=== ② glibc 把它翻译成的内部开关 __USE_* ===\n");
#ifdef __USE_ISOC99
    flag("__USE_ISOC99", 1);
#else
    flag("__USE_ISOC99", 0);
#endif
#ifdef __USE_ISOC11
    flag("__USE_ISOC11", 1);
#else
    flag("__USE_ISOC11", 0);
#endif
#ifdef __USE_POSIX_IMPLICITLY
    flag("__USE_POSIX_IMPLICITLY", 1);      /* 用户没点 POSIX，glibc 替他点了 */
#else
    flag("__USE_POSIX_IMPLICITLY", 0);
#endif
#ifdef __USE_POSIX
    flag("__USE_POSIX", 1);
#else
    flag("__USE_POSIX", 0);
#endif
#ifdef __USE_POSIX199309
    flag("__USE_POSIX199309", 1);           /* 决定 struct timespec / clock_gettime */
#else
    flag("__USE_POSIX199309", 0);
#endif
#ifdef __USE_POSIX199506
    flag("__USE_POSIX199506", 1);           /* 线程相关声明的门槛 */
#else
    flag("__USE_POSIX199506", 0);
#endif
#ifdef __USE_XOPEN
    flag("__USE_XOPEN", 1);
#else
    flag("__USE_XOPEN", 0);
#endif
#ifdef __USE_XOPEN_EXTENDED
    flag("__USE_XOPEN_EXTENDED", 1);
#else
    flag("__USE_XOPEN_EXTENDED", 0);
#endif
#ifdef __USE_UNIX98
    flag("__USE_UNIX98", 1);
#else
    flag("__USE_UNIX98", 0);
#endif
#ifdef __USE_XOPEN2K
    flag("__USE_XOPEN2K", 1);
#else
    flag("__USE_XOPEN2K", 0);
#endif
#ifdef __USE_XOPEN2K8
    flag("__USE_XOPEN2K8", 1);              /* ←「POSIX.1-2008」在 glibc 里的真名 */
#else
    flag("__USE_XOPEN2K8", 0);
#endif
#ifdef __USE_XOPEN2K8XSI
    flag("__USE_XOPEN2K8XSI", 1);
#else
    flag("__USE_XOPEN2K8XSI", 0);
#endif
#ifdef __USE_LARGEFILE
    flag("__USE_LARGEFILE", 1);
#else
    flag("__USE_LARGEFILE", 0);
#endif
#ifdef __USE_LARGEFILE64
    flag("__USE_LARGEFILE64", 1);
#else
    flag("__USE_LARGEFILE64", 0);
#endif
#ifdef __USE_FILE_OFFSET64
    flag("__USE_FILE_OFFSET64", 1);
#else
    flag("__USE_FILE_OFFSET64", 0);
#endif
#ifdef __USE_MISC
    flag("__USE_MISC", 1);                  /* BSD/SVID 兼容物 + memmem */
#else
    flag("__USE_MISC", 0);
#endif
#ifdef __USE_ATFILE
    flag("__USE_ATFILE", 1);                /* openat/fstatat 一族 */
#else
    flag("__USE_ATFILE", 0);
#endif
#ifdef __USE_GNU
    flag("__USE_GNU", 1);                   /* GNU 扩展 */
#else
    flag("__USE_GNU", 0);
#endif

    printf("\n=== ③ 这些开关真的决定声明在不在（守护条件照抄 glibc 头文件）===\n");
#if (defined __USE_XOPEN_EXTENDED || defined __USE_XOPEN2K8 || __GLIBC_USE (LIB_EXT2) || __GLIBC_USE (ISOC2X))
    printf("  strdup()              ：可见     ← string.h:184 的 #if 条件（照抄）\n");
#else
    printf("  strdup()              ：**不可见**   ← string.h:184 的 #if 条件（照抄）\n");
#endif
#ifdef __USE_POSIX199309
    printf("  struct timespec / clock_gettime() / nanosleep()：可见   ← time.h:41, 276\n");
#else
    printf("  struct timespec / clock_gettime() / nanosleep()：**不可见**   ← time.h:41, 276\n");
#endif
#ifdef __USE_MISC
    printf("  memmem()              ：可见     ← string.h:385 守的是 __USE_MISC，不是 __USE_GNU\n");
#else
    printf("  memmem()              ：**不可见**   ← string.h:385 守的是 __USE_MISC，不是 __USE_GNU\n");
#endif
#ifdef __USE_XOPEN2K8
    printf("  strsignal()           ：可见     ← string.h:476\n");
#else
    printf("  strsignal()           ：**不可见**   ← string.h:476\n");
#endif
#ifdef __USE_GNU
    printf("  strerror_r()          ：GNU 版签名（返回 char *，缓冲由 glibc 管）   ← string.h:448\n");
#else
    printf("  strerror_r()          ：POSIX 版签名（返回 int，写进你给的 buf）      ← string.h:428\n");
#endif
    printf("    ↑ 最后一个最值得注意：**同一个函数名，两种 FTM 下签名都不同**。\n"
           "      换旗标不只是「能不能用」，还可能改变函数的 ABI。\n");

    printf("\n=== ④ 四条实践规则 ===\n");
    printf("  1. FTM 必须写在**所有 #include 之前**（<features.h> 被谁先拉进来就定了）\n");
    printf("  2. 要「严格 POSIX + 可移植」→ 定义 _POSIX_C_SOURCE；要 GNU 扩展 → _GNU_SOURCE\n");
    printf("  3. 别混着定义互相矛盾的 FTM；glibc 会按固定优先级归并，结果常出乎意料\n");
    printf("  4. **加旗标不一定只增不减**：-std=c99 会带出 __STRICT_ANSI__，\n"
           "     于是 glibc 不再自动给 _DEFAULT_SOURCE/_POSIX_C_SOURCE，\n"
           "     连 memmem（靠 _DEFAULT_SOURCE）都会跟着消失\n");
    return 0;
}
```

### 逐条解读

| 现象 | 说明 |
|------|------|
| `default` 组：一个 FTM 都没定义，但 `_POSIX_C_SOURCE = 200809L`、`_DEFAULT_SOURCE = 1` | **glibc 自动补的**。`features.h:231-239`：没有 FTM 且不是 `__STRICT_ANSI__` → 自动给 `_DEFAULT_SOURCE=1`；`features.h:285-293`：`_DEFAULT_SOURCE` 下若没指定 `_POSIX_C_SOURCE` 就补 `200809L`。所以「什么都不写」不等于「最保守」 |
| `xopen700` 组：只定义了 `_XOPEN_SOURCE=700`，却出现了 `_POSIX_C_SOURCE = 200809L` | `features.h:295-309` 的**推断链**：`_XOPEN_SOURCE >= 700` → 推出 `_POSIX_C_SOURCE=200809L`。给了 SUS 就自动带上对应的 POSIX |
| `gnu` 组：`_GNU_SOURCE = 1` 换来 `_XOPEN_SOURCE = 700` + `_DEFAULT_SOURCE = 1` | `features.h:202-222`：`_GNU_SOURCE` 会**改写**（不是追加）成 `_POSIX_C_SOURCE=200809L`、`_XOPEN_SOURCE=700`、`_DEFAULT_SOURCE=1`。所以 `_GNU_SOURCE` 是「上面全部 + `__USE_GNU`」 |
| `memmem` 在 `posix2008` / `xopen700` 下**不可见**，在 `default` / `gnu` 下可见 | **`memmem` 守的是 `__USE_MISC`（`string.h:385`），不是 `__USE_GNU`**。它属于 glibc 默认暴露的 BSD 杂项，所以严格 POSIX 反而把它锁掉了——这是最容易记错的守护条件 |
| `strerror_r` 在 `gnu` 下变成 **GNU 版签名** | 同一个函数名，**两种 FTM 下签名不同**：`string.h:428` 是 POSIX 版（`int strerror_r(int, char*, size_t)`），`string.h:448` 是 GNU 版（`char *strerror_r(int, char*, size_t)`）。换旗标不只是「能不能用」，还可能改变 **ABI** |
| **`stdc99` 组所有 POSIX 声明全部消失** | ⚠️ 本节最重要的一条：**加旗标不一定只增不减**。`-std=c99` → `__STRICT_ANSI__=1` → glibc **不再自动补** `_DEFAULT_SOURCE`/`_POSIX_C_SOURCE` → 连 `strdup`、`clock_gettime`、`strsignal` 这些常用件都跟着消失。这是「`-std=c99` 编不过」类报错的真正原因 |
| `__USE_ISOC11` 在 `stdc99` 下 OFF | 它由 `__STDC_VERSION__ >= 201112L` 触发；`-std=c99` 下 `__STDC_VERSION__ = 199901L`，所以 OFF |
| `__USE_FILE_OFFSET64` 五组全 OFF | 它只受 `_FILE_OFFSET_BITS=64` 控制（见 §3.6.2），跟上面这些 FTM 无关 |

> **`__USE_POSIX2008` 这个宏不存在**——demo 的第一版曾打印它，是凭印象写的虚构名字。实测办法：让**编译器自己吐宏表**（`gcc -dM -E -include features.h - < /dev/null`），筛出 `__USE_` 前缀，只有 25 个（`__USE_ISOC11/ISOC99/ISOC95`、`__USE_POSIX_IMPLICITLY`、`__USE_POSIX`/`POSIX2`/`POSIX199309`/`POSIX199506`、`__USE_XOPEN`/`XOPEN_EXTENDED`/`UNIX98`/`XOPEN2K`/`XOPEN2K8`/`XOPEN2K8XSI`、`__USE_LARGEFILE`/`LARGEFILE64`/`FILE_OFFSET64`、`__USE_MISC`/`ATFILE`/`DYNAMIC_STACK_SIZE`/`GNU`/`FORTIFY_LEVEL`/`EXTERN_INLINES`）。「POSIX.1-2008」在 glibc 里的真名是 **`__USE_XOPEN2K8`**。

## 2. §3.6.2 系统数据类型：别猜宽度

TLPI 的要点：`int`/`long` 的宽度随平台变，但**系统调用的接口类型**（`pid_t`/`uid_t`/`off_t`/`size_t`/`ssize_t`…）是实现定义好的类型。用它们而不是裸 `int`/`long`，宽度问题就交给头文件。

| 类型 | 用途 | 定义处（glibc） |
|------|------|-----------------|
| `pid_t` | 进程 ID | `<bits/types.h>` → `__pid_t` |
| `off_t` | 文件偏移 | `<bits/types.h>` → `__off_t` |
| `size_t` / `ssize_t` | 无符号 / 有符号长度 | `<stddef.h>` / `<sys/types.h>` |
| `uid_t` / `gid_t` | 用户 / 组 ID | `<bits/types.h>` |
| `mode_t` | 文件权限位 | `<bits/types.h>` |
| `dev_t` / `ino_t` | 设备号 / inode 号 | `<bits/types.h>` |

**最经典的坑是 `off_t` 与大文件**：32 位平台上 `off_t` 默认 32 位，`lseek` 处理不了 >2GB 的偏移。解法是定义 `_FILE_OFFSET_BITS=64`，让 `off_t` 变 64 位——代价是所有相关函数的 ABI 换一套（glibc 里是 `open64`/`lseek64` 一族）。

### 代码示例 B：两种 `_FILE_OFFSET_BITS` 设定

源码：[../code/c3_10_types.c](../code/c3_10_types.c)

```c
/* TLPI 第 03 章 §3.6.2 —— 标准系统数据类型：别猜宽度，用 sizeof 问出来
 *
 * TLPI 专门强调：`int` / `long` 的宽度随平台变，但**系统调用的接口类型**
 * （pid_t、uid_t、off_t、size_t、ssize_t…）是由实现定义好的类型。
 * 想写出可移植的 printf，就必须用 <inttypes.h> 的 PRI* 宏。
 *
 * 本 demo 用两种 OFF_T 设定各编一次，看 off_t 是否变化：
 *   gcc -O0 -Wall -Wextra -o c3_10 c3_10_types.c
 *   gcc -O0 -Wall -Wextra -D_FILE_OFFSET_BITS=64 -o c3_10 c3_10_types.c
 */
#define _GNU_SOURCE
#include <inttypes.h>
#include <stddef.h>
#include <stdio.h>
#include <stdint.h>
#include <sys/types.h>
#include <unistd.h>

/* 用泛型「打印类型宽度」的宏，避免一行行重复 */
#define W(t) printf("  %-22s sizeof = %2zu 字节   %s\n", #t, sizeof(t), kind(sizeof(t)))

static const char *kind(size_t n)
{
    switch (n) {
    case 1: return "1B";
    case 2: return "2B";
    case 4: return "4B";
    case 8: return "8B";
    case 16: return "16B";
    default: return "?";
    }
}

int main(void)
{
    printf("=== ① 基础 C 类型：这就是「数据模型」===\n");
    W(char); W(short); W(int); W(long); W(long long);
    W(float); W(double); W(long double);
    W(void *); W(size_t); W(ptrdiff_t);
    printf("  → 指针 %zu 字节 + long %zu 字节 ⇒ 数据模型 %s\n",
           sizeof(void *), sizeof(long),
           (sizeof(void *) == 8 && sizeof(int) == 4) ? "LP64（x86-64 / aarch64 用户态）" : "其它");

    printf("\n=== ② 系统调用接口类型（POSIX 只规定「够用」，不规定具体宽度）===\n");
    W(pid_t); W(uid_t); W(gid_t); W(mode_t); W(dev_t);
    W(off_t); W(ssize_t); W(time_t);
#ifdef __USE_MISC
    W(socklen_t); W(useconds_t);
#endif

    printf("\n=== ③ _FILE_OFFSET_BITS=64 的作用 ===\n");
#ifdef _FILE_OFFSET_BITS
    printf("  _FILE_OFFSET_BITS = %d\n", _FILE_OFFSET_BITS);
#else
    printf("  _FILE_OFFSET_BITS 未定义\n");
#endif
    printf("  sizeof(off_t) = %zu\n", sizeof(off_t));
    printf("  在 x86-64/aarch64 上 off_t 本来就是 64 位，这个宏**没有影响**；\n");
    printf("  它真正的用武之地是 32 位平台：把 off_t 从 32 位换成 64 位，从而能操作 >2GB 文件。\n");
    printf("  代价是所有相关函数的 ABI 都换一套（glibc 里叫 open64/lseek64）。\n");

    printf("\n=== ④ 为什么必须有 PRI* 宏：同一份代码在不同平台的可移植打印 ===\n");
    int32_t  i32 = -123456;
    uint32_t u32 = 4000000000u;
    int64_t  i64 = -1234567890123456789LL;
    uint64_t u64 = 18446744073709551615ULL;
    size_t   sz  = sizeof(int64_t);
    ssize_t  ssz = -1;
    pid_t    pid = getpid();
    off_t    off = 1 << 20;

    printf("  int32_t  : %" PRId32 "\n", i32);
    printf("  uint32_t : %" PRIu32 "\n", u32);
    printf("  int64_t  : %" PRId64 "\n", i64);
    printf("  uint64_t : %" PRIu64 "\n", u64);
    printf("  size_t   : %zu\n", sz);            /* 用 %zu 而不是 %lu */
    printf("  ssize_t  : %zd\n", ssz);           /* 用 %zd 而不是 %ld */
    printf("  pid_t    : %d（按 %zu 字节的类型打印，编译期由 glibc 保证匹配）\n",
           (int) pid, sizeof(pid_t));
    printf("  off_t    : %jd（转型到 intmax_t 最保险）\n", (intmax_t) off);

    printf("\n=== ⑤ 踩坑清单 ===\n");
    printf("  ✗ printf(\"%%d\", sizeof(x))        → size_t 是 64 位，%%d 只读 32 位，栈错位\n");
    printf("  ✗ printf(\"%%ld\", ssize_t 值)      → 在 Windows/32 位下不对，用 %%zd\n");
    printf("  ✗ 把 pid_t 当 int 传给变参函数     → 用 (int) 显式转，或 %%jd\n");
    printf("  ✗ 假设 long 是 32 位               → LP64 下是 64 位，ILP32 下才是 32 位\n");
    printf("  ✓ 需要「恰好 N 位」时用 <stdint.h> 的 intN_t/uintN_t，别用 int/long\n");
    return 0;
}
```

### 逐条解读

| 段 | 读数 | 说明 |
|----|------|------|
| ① | 指针 8、`long` 8、`int` 4 → **LP64** | `long` 在 LP64 下是 **8 字节**（不是 32 位！）。很多人从 Windows（LLP64，`long` = 4）转过来会踩这个 |
| ① | `long double` = **16** 字节 | x86-64 的 `long double` 是 80 位扩展精度 + 6 字节填充 = 16。**不能跨平台假设它等于 `double`** |
| ② | `pid_t`/`uid_t`/`gid_t`/`mode_t`/`socklen_t`/`useconds_t` = 4，`dev_t`/`off_t`/`ssize_t`/`time_t` = 8 | POSIX **只规定「够用」，不规定具体宽度**——这组数字是 glibc 在 x86-64 上的选择，不是标准保证 |
| ③ | `_FILE_OFFSET_BITS` 定义与否，`sizeof(off_t)` 都是 8 | 在 64 位平台上这个宏**没有影响**（`off_t` 本来就是 64 位）。它是 32 位平台的救星——这是「读书时要分清哪条是针对哪种平台」的典型例 |
| ④ | `size_t` 用 `%zu`、`ssize_t` 用 `%zd`、定长类型用 `PRI*`、`intmax_t` 用 `%jd` | 可移植的打印方式：**不要**用 `%d`/`%ld` 硬套 |

> **为什么必须有 `PRI*` 宏**：`int64_t` 在有的平台是 `long`、有的是 `long long`，写死 `%ld` 或 `%lld` 总有一半平台是错的。`<inttypes.h>` 的 `PRId64` 会被展开成该平台正确的长度修饰符，所以写 `printf("%" PRId64, x)`（字符串字面量拼接）才真正可移植。

## 3. §3.6.3 杂项可移植性

这一节列的坑都有一个共同特征：**在 x86 上跑得好好的，交叉编到 ARM 就换了一套结果**——静默 bug。

### 代码示例 C：六类「实现定义」行为一次测完

源码：[../code/c3_11_portability.c](../code/c3_11_portability.c)

```c
/* TLPI 第 03 章 §3.6.3 —— 杂项可移植性：编译器/平台宏、字节序、有符号性、右移
 *
 * 这些「不定行为」是嵌入式/HFT 里最常见的静默 bug 来源：在 x86 上跑得好好的，
 * 交叉编到 ARM 就换了一套结果。全部用编译期宏 + 实测把它钉死。
 *
 * 编译：gcc -O0 -Wall -Wextra -o c3_11 c3_11_portability.c
 */
#define _GNU_SOURCE
#include <stddef.h>
#include <stdio.h>
#include <stdint.h>
#include <string.h>

/* 一个有「洞」的结构体，用来量对齐填充 */
struct padded {
    char a;
    int  b;
    char c;
};

static void flag(const char *name, int on, const char *note)
{
    printf("  %-22s %-4s %s\n", name, on ? "YES" : "NO", note);
}

int main(void)
{
    printf("=== ① 平台/编译器宏（条件编译的判据）===\n");
#if defined(__linux__)
    flag("__linux__", 1, "= Linux 内核 ABI（不是「有 /proc」之类的功能判断）");
#else
    flag("__linux__", 0, "");
#endif
#if defined(__unix__) || defined(__unix)
    flag("__unix__", 1, "= 类 UNIX 系统");
#else
    flag("__unix__", 0, "");
#endif
#if defined(__x86_64__)
    flag("__x86_64__", 1, "64 位 x86");
#else
    flag("__x86_64__", 0, "");
#endif
#if defined(__aarch64__)
    flag("__aarch64__", 1, "64 位 ARM（嵌入式目标常见）");
#else
    flag("__aarch64__", 0, "");
#endif
#if defined(__ARM_EABI__)
    flag("__ARM_EABI__", 1, "32 位 ARM EABI");
#else
    flag("__ARM_EABI__", 0, "");
#endif
#if defined(__GNUC__) && !defined(__clang__)
    flag("__GNUC__", 1, "真 GCC（clang 也会定义 __GNUC__！要额外排除 __clang__）");
#else
    flag("__GNUC__", 1, "clang 伪装成的 GCC");
#endif
#if defined(__SIZEOF_POINTER__)
    printf("  __SIZEOF_POINTER__     %zu 字节\n", (size_t) __SIZEOF_POINTER__);
#endif
#if defined(__SIZEOF_LONG__)
    printf("  __SIZEOF_LONG__        %zu 字节\n", (size_t) __SIZEOF_LONG__);
#endif
#if defined(__BYTE_ORDER__)
    printf("  __BYTE_ORDER__         %s\n",
           __BYTE_ORDER__ == __ORDER_LITTLE_ENDIAN__ ? "LITTLE_ENDIAN（小端）" :
           __BYTE_ORDER__ == __ORDER_BIG_ENDIAN__ ? "BIG_ENDIAN（大端）" : "PDP/未知");
#endif
#if defined(__ORDER_BIG_ENDIAN__)
    printf("  __ORDER_BIG_ENDIAN__   = %d\n", __ORDER_BIG_ENDIAN__);
    printf("  __ORDER_LITTLE_ENDIAN__= %d\n", __ORDER_LITTLE_ENDIAN__);
#endif
#if defined(__FLOAT_WORD_ORDER__)
    printf("  __FLOAT_WORD_ORDER__   %s（浮点的字节序可与整数不同！）\n",
           __FLOAT_WORD_ORDER__ == __ORDER_LITTLE_ENDIAN__ ? "LITTLE_ENDIAN" : "BIG_ENDIAN");
#endif

    printf("\n=== ② 运行期验证字节序（宏之外还得看真实内存布局）===\n");
    uint32_t v = 0x01020304u;
    unsigned char b[4];
    memcpy(b, &v, 4);
    printf("  uint32_t v = 0x01020304，逐字节 = %02x %02x %02x %02x → %s端\n",
           b[0], b[1], b[2], b[3], (b[0] == 0x04) ? "小" : "大");
    printf("  ↑ 网络字节序固定是「大端」，所以 htonl()/ntohl() 在小端机上真的会翻字节\n");

    printf("\n=== ③ char 到底有没有符号：这是可移植性最阴的坑 ===\n");
    char c = 0xFF;
    unsigned char uc = 0xFF;
    printf("  (char)0xFF 转 int = %d   → %s\n", (int) c,
           (int) c < 0 ? "char 有符号（x86/aarch64 Linux 默认）" : "char 无符号");
    printf("  (unsigned char)0xFF 转 int = %d\n", (int) uc);
    printf("  危害：char c = getchar(); if (c == 0xFF) ... 在无符号平台永远不成立；\n");
    printf("        而 if (c == EOF) 在有符号平台可能把合法的 0xFF 字节当成 EOF。\n");
    printf("  正确：getchar 的返回值必须装进 int；只处理字节时用 uint8_t / unsigned char\n");

    printf("\n=== ④ 负数右移与整数除法：实现定义 vs 未定义 ===\n");
    int neg = -9;
    printf("  -9 / 2  = %d   （C99 起规定「向零截断」，所以是 -4，不是 -5）\n", neg / 2);
    printf("  -9 %% 2  = %d   （余数符号跟随被除数，所以是 -1）\n", neg % 2);
    printf("  -9 >> 1 = %d   （有符号右移是实现定义：算术移位给 -5，逻辑移位给一个正数）\n",
           neg >> 1);
    printf("  ↑ x86/ARM 的算术移位给 -5；写代码时别依赖它，要么用除法，要么保证操作数无符号\n");

    printf("\n=== ⑤ 结构体内存布局：别假设「成员依次紧排」===\n");
    printf("  struct{char;int;char} sizeof = %zu（不是 6：int 要 4 字节对齐 → 中间补 3、尾部补 3）\n",
           sizeof(struct padded));
    printf("  a 偏移 %zu, b 偏移 %zu, c 偏移 %zu\n",
           offsetof(struct padded, a), offsetof(struct padded, b),
           offsetof(struct padded, c));
    printf("  ↑ 跨平台传结构体（网络包、共享内存、驱动 ioctl）必须显式定序 + 对齐：\n");
    printf("    用 uint8_t/uint32_t、按大到小排成员、必要时 __attribute__((packed))\n");
    return 0;
}
```

```text
=== ⑤ 结构体内存布局：别假设「成员依次紧排」===
  struct{char;int;char} sizeof = 12（不是 6：int 要 4 字节对齐 → 中间补 3、尾部补 3）
  a 偏移 0, b 偏移 4, c 偏移 8
  ↑ 跨平台传结构体（网络包、共享内存、驱动 ioctl）必须显式定序 + 对齐：
    用 uint8_t/uint32_t、按大到小排成员、必要时 __attribute__((packed))
```

### 逐条解读

| 段 | 读数 | 说明 |
|----|------|------|
| ① | `__x86_64__` YES / `__aarch64__` NO | 条件编译的判据是**平台宏**，不是「有没有某个头」。嵌入式的常见分支就是 `#if defined(__aarch64__) \|\| defined(__ARM_EABI__)` |
| ① | `__GNUC__` YES 但 demo 里额外排除了 `__clang__` | **clang 也会定义 `__GNUC__`**（伪装成 GCC 以兼容大量代码）。想精确判断编译器必须同时看 `__clang__` |
| ① | `__ORDER_BIG_ENDIAN__ = 4321` / `__ORDER_LITTLE_ENDIAN__ = 1234` | 这两个数是 GCC 约定的「字节序编号」（写成 `0x1234`/`0x4321` 好记），不是地址 |
| ① | `__FLOAT_WORD_ORDER__` 单独存在 | 浮点的字节序**可以与整数不同**（历史上有混合端平台），所以 GNU 单独给了一个宏 |
| ② | `0x01020304` 逐字节 `04 03 02 01` | **宏之外还要看真实内存布局**。网络字节序固定是「大端」，所以小端机上 `htonl()`/`ntohl()` 真的会翻字节 |
| ③ | `(char)0xFF` → `-1` | `char` 的符号性是**实现定义**的：x86/aarch64 Linux 上默认有符号（`-fsigned-char`），ARM 某些工具链默认无符号。危害：`char c = getchar(); if (c == 0xFF)` 在无符号平台永不成立；`if (c == EOF)` 在有符号平台可能把合法的 `0xFF` 字节当成 EOF |
| ③ | 正确做法 | `getchar()` 的返回值**必须装进 `int`**（这样才能区分 `EOF`）；只当字节用时用 `uint8_t` / `unsigned char` |
| ④ | `-9 / 2 = -4` | C99 起规定**向零截断**，所以是 `-4` 不是 `-5`（C89 是实现定义，曾有平台给 `-5`） |
| ④ | `-9 % 2 = -1` | 余数符号**跟随被除数** |
| ④ | `-9 >> 1 = -5` | 有符号右移是**实现定义**：算术移位给 `-5`，逻辑移位给一个正数。x86/ARM 都是算术移位，但**别依赖它** |
| ⑤ | `struct{char;int;char}` sizeof = **12** | 不是 6：`int` 要 4 字节对齐 → 中间补 3 字节、尾部补 3 字节。偏移是 0 / 4 / **8**（不是 0/1/5） |
| ⑤ | 正确做法 | 跨平台传结构体（网络包、共享内存、驱动 ioctl）必须**显式定序 + 对齐**：用 `uint8_t`/`uint32_t`、成员按「大到小」排可减少填充、必要时 `__attribute__((packed))` |

> 结构体那条与第 4 本书的 `4.13 packed 实践` 是同一个知识点，那边有完整的 ioctl/协议头案例，此处不重复展开。

## 4. SUSv3 / POSIX 标准演进

| 年份 | 标准 | 说明 |
|------|------|------|
| 1988 | POSIX.1-1988 | 第一版，系统接口 + shell |
| 1990 | POSIX.1-1990 (ISO 9945-1) | 成为 ISO 标准 |
| 1996 | POSIX.1-1996 | 实时扩展（信号量、时钟、调度） |
| 2001 | **POSIX.1-2001 = SUSv3** | 合并 X/Open，TLPI 全书基线 |
| 2008 | **POSIX.1-2008 = SUSv4** | 当前主流，对应 `_POSIX_C_SOURCE=200809L` |

TLPI 全书以 **SUSv3** 为基线，并把 Linux 扩展单独标注。读 TLPI 时遇到：
- 「SUSv3 规定……」→ 这是 POSIX 保证的接口，任何合规 Unix 都有
- 「Linux 特有」→ 换平台要自己找替代（如 `epoll` ↔ `kqueue`）

## 5. HFT / 嵌入式关联

| 现象 | 本节内容的兑现 |
|------|----------------|
| 静态可移植二进制 | 用 musl + 严格 POSIX（`_POSIX_C_SOURCE`）编译，摆脱 glibc 方言依赖（见 [3.3](3.3-glibc.md)） |
| `-std=c99` 突然编不过 | `__STRICT_ANSI__` 把 glibc 的自动补全关掉 → `strdup`/`clock_gettime` 全部不可见（本节实测）。加旗标**不一定只增不减** |
| `memmem` 只在默认/GNU 下可见 | 它守的是 `__USE_MISC`。写了 `-D_POSIX_C_SOURCE` 反而锁掉它——查「函数为什么没声明」时**必须查守护条件是哪个 `__USE_*`** |
| 大文件 / 大偏移 | 行情回放、日志文件 >2GB 时，32 位平台必须 `_FILE_OFFSET_BITS=64`，否则 `lseek` 溢出 |
| 锁死 GNU 扩展 | 用 `epoll`/`io_uring` 时需 `_GNU_SOURCE`；这是「只在 Linux 跑」的显式声明 |
| 目标板是 ARM | 交叉编译前先确认 `__aarch64__` / `__ARM_EABI__` 分支；`char` 符号性、有符号右移都可能与 x86 不同 |
| 类型宽度敏感 | 时间戳/序号用 `int64_t`，别用 `long`（LP64 是 8 字节、ILP32 是 4 字节）；打印用 `PRI*` 宏 |
| 跨子系统传结构体 | 网络包、共享内存、`ioctl` 必须显式定序 + 对齐（本节 ⑤ 实测 sizeof = 12） |

<summary>代码自测（Q&A）</summary>

**Q1：功能测试宏为什么必须放在所有 `#include` 之前？**
A：因为 glibc 的所有标准头文件开头都会 `#include <features.h>`，它读取 FTM 并**一次性**换算成 `__USE_*` 内部开关。如果你先 `#include` 了别的头，`features.h` 已经在「默认方言」下把开关定死了，之后再 `#define _GNU_SOURCE` 也不生效。所以宏必须在最前面，或编译期用 `-D` 传入。

**Q2：`_GNU_SOURCE`、`_POSIX_C_SOURCE`、`_XOPEN_SOURCE` 分别解锁什么？**
A：`_POSIX_C_SOURCE`（如 `200809L`）解锁 POSIX.1-2008 标准接口；`_XOPEN_SOURCE`（如 `700`）解锁 SUSv4（POSIX 超集，含 X/Open 扩展）；`_GNU_SOURCE` 解锁全部 + Linux/GNU 扩展。实测 `_GNU_SOURCE=1` 时 glibc 会**改写**成 `_POSIX_C_SOURCE=200809L` + `_XOPEN_SOURCE=700` + `_DEFAULT_SOURCE=1`（`features.h:202-222`），所以它是「上面全部 + `__USE_GNU`」。代价是用了 GNU 扩展的代码换到非 glibc 环境可能编译不过。

**Q3：为什么「一个 FTM 都不定义」不等于「最保守」？**
A：因为 glibc 会**自动补全**。实测 `default` 组（只给 `-O0 -Wall -Wextra`）里 `_POSIX_C_SOURCE = 200809L`、`_DEFAULT_SOURCE = 1` 都是 glibc 自己给的：`features.h:231-239`（没有 FTM 且非 `__STRICT_ANSI__` → 给 `_DEFAULT_SOURCE`）、`features.h:285-293`（`_DEFAULT_SOURCE` 下补 `_POSIX_C_SOURCE=200809L`）。同理只给 `_XOPEN_SOURCE=700` 时，`features.h:295-309` 的推断链会补上 `_POSIX_C_SOURCE=200809L`。

**Q4：`memmem()` 的守护开关是 `__USE_GNU` 吗？**
A：**不是**，是 `__USE_MISC`（glibc `string.h:385`）。这导致一个反直觉的实测结果：`default` 和 `gnu` 下 `memmem` 可见，而**严格 POSIX 的 `-D_POSIX_C_SOURCE=200809L` 和 `-D_XOPEN_SOURCE=700` 反而让它不可见**（因为这两组下 `__USE_MISC` 是 OFF）。查「函数为什么没声明」时必须查它的守护条件是哪个开关。

**Q5：为什么 `-std=c99` 会让一堆 POSIX 函数消失？**
A：因为 `-std=c99`（以及 `-std=c11` 等）会置上 `__STRICT_ANSI__=1`，glibc 此时**不再自动补** `_DEFAULT_SOURCE` / `_POSIX_C_SOURCE`（`features.h:231-239` 的条件不满足）。结果是所有 `__USE_POSIX*`/`__USE_XOPEN*`/`__USE_MISC`/`__USE_ATFILE` 全部 OFF，连 `strdup`、`clock_gettime`、`struct timespec`、`strsignal` 都不可见（本节实测）。**加旗标不一定只增不减**——这是「`-std=c99` 编不过」类报错的真正原因。

**Q6：`off_t` 为什么不能写死成 `long`？`_FILE_OFFSET_BITS=64` 干嘛的？**
A：`long` 的宽度跟平台走（LP64 是 8 字节、ILP32 是 4 字节），而 `off_t` 的宽度由 `_FILE_OFFSET_BITS` 决定。32 位平台上 `off_t` 默认 32 位，无法处理 >2GB 的文件偏移；定义 `_FILE_OFFSET_BITS=64` 后变 64 位（代价是 ABI 换成 `open64`/`lseek64` 一族）。本 demo 实测：**在 x86-64 上这个宏没有影响**，`sizeof(off_t)` 两种设定都是 8——它是给 32 位平台用的。

**Q7：`__USE_POSIX2008` 这个宏存在吗？**
A：**不存在**。demo 的第一版凭印象打印了这个名字，核对 glibc 2.39 的 `features.h`（以及让编译器用 `-dM -E` 吐宏表）后确认：`features.h` 里真实存在 25 个 `__USE_*`，**没有 `__USE_POSIX2008`**。POSIX.1-2008 在 glibc 里的体现是 **`__USE_XOPEN2K8`**。教训：写「某个宏/某个行号」之前必须核源码，不能凭印象。

**Q8：`char` 有没有符号？为什么它是「最阴的坑」？**
A：`char` 的符号性是**实现定义**的：x86/aarch64 Linux 默认**有符号**（实测 `(char)0xFF` 转 `int` = `-1`），ARM 某些工具链默认无符号。危害有两个方向——`char c = getchar(); if (c == 0xFF)` 在无符号平台永不成立；而 `if (c == EOF)` 在有符号平台可能把合法的 `0xFF` 字节当成 EOF。正确做法：`getchar()` 的返回值必须装进 `int`；只当字节用时用 `uint8_t` / `unsigned char`。

**Q9：`struct{char;int;char}` 在 x86-64 上是几字节？成员偏移是多少？**
A：**12 字节**，偏移 `0 / 4 / 8`（不是 6 字节、偏移 0/1/5）。因为 `int` 需要 4 字节对齐，成员 `b` 前面要补 3 字节，整个结构体又要按最宽成员对齐，尾部再补 3 字节。跨平台传结构体（网络包、共享内存、驱动 `ioctl`）必须显式定序 + 对齐。
