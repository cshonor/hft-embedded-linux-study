## 练习题

### 题 1：文件复制（基础）

编写程序 `./copy source dest`，用 `open`/`read`/`write`/`close` 复制文件，要求：

1. 检查所有系统调用返回值
2. 用 `perror` 报告错误
3. 用标准 typedef（`ssize_t`/`mode_t`），不写死 `int`/`long`

<details>
<summary>参考答案</summary>

```c
#include <fcntl.h>
#include <unistd.h>
#include <stdio.h>
#include <stdlib.h>
#include <sys/types.h>

int main(int argc, char *argv[]) {
    if (argc != 3) {
        fprintf(stderr, "Usage: %s source dest\n", argv[0]);
        exit(EXIT_FAILURE);
    }

    int src = open(argv[1], O_RDONLY);
    if (src == -1) { perror("open source"); exit(EXIT_FAILURE); }

    int dst = open(argv[2], O_WRONLY | O_CREAT | O_TRUNC, 0644);
    if (dst == -1) { perror("open dest"); exit(EXIT_FAILURE); }

    char buf[4096];
    ssize_t n;
    while ((n = read(src, buf, sizeof(buf))) > 0) {
        if (write(dst, buf, n) != n) {   /* 短写处理：要求写满 n 字节 */
            perror("write"); exit(EXIT_FAILURE);
        }
    }
    if (n == -1) { perror("read"); exit(EXIT_FAILURE); }

    if (close(src) == -1) perror("close src");
    if (close(dst) == -1) perror("close dst");
    return 0;
}
```

</details>

### 题 2：EINTR 重试（错误处理）

上面的 `read` 没有处理 `EINTR`。改写循环，让 `read` 被信号打断时自动重试，而不是当作错误退出。

<details>
<summary>参考答案</summary>

```c
#include <errno.h>   /* errno, EINTR */

ssize_t n;
do {
    n = read(src, buf, sizeof(buf));
} while (n == -1 && errno == EINTR);   /* 被信号打断 → 重试 */

if (n == -1) { perror("read"); exit(EXIT_FAILURE); }
/* n == 0 表示读到 EOF，正常退出循环 */
```

要点：`EINTR` 是「被信号打断」的正常现象（见错误处理节），不是 I/O 失败。忽略它会导致热路径偶发漏读。

</details>

### 题 3：直接 syscall（绕过 glibc）

不调用 `write()`，用 `syscall(SYS_write, ...)` 直接写 `"raw\n"` 到标准输出，并解释为什么失败时返回值是负错误码而不是 `-1`。

<details>
<summary>参考答案</summary>

```c
#include <stdio.h>
#include <unistd.h>
#include <string.h>
#include <sys/syscall.h>

int main(void) {
    long ret = syscall(SYS_write, STDOUT_FILENO, "raw\n", 4);
    if (ret < 0 && ret >= -4095) {   /* 负错误码，需自己还原 errno */
        int e = -(int)ret;
        fprintf(stderr, "errno=%d (%s)\n", e, strerror(e));
    }
    return 0;
}
```

要点：`syscall()` 绕过 glibc 的 `MAX_ERRNO` 错误翻译层（见 glibc 节 / 错误处理节），失败时返回的是 `-errno`（如 `-2`=`-ENOENT`），不是 `-1`。要自己判断 `[-4095,-1]` 并还原 `errno`。

</details>

### 题 4：可移植性（功能测试宏）

下面代码用到了 GNU 扩展 `strerror_r` 返回 `char*` 的语义。说明如何用功能测试宏声明这一方言，以及换 musl 后为什么行为会变。

<details>
<summary>参考答案</summary>

```c
#define _GNU_SOURCE          /* 声明用 GNU 方言：strerror_r 返回 char* */
#include <string.h>
#include <stdio.h>

int main(void) {
    char buf[128];
    char *p = strerror_r(ENOENT, buf, sizeof(buf));  /* GNU：返回 char* */
    printf("%s\n", p);
    return 0;
}
```

要点：`strerror_r` 在 glibc 下默认是 GNU 语义（返回 `char*`），在 musl 下是 POSIX 语义（返回 `int`）。换 musl 后 `char *p = strerror_r(...)` 会类型不匹配——这就是「可移植性」的典型坑：同一个函数，不同 C 库语义不同（见 glibc 节 / 可移植节）。严格 POSIX 下应写成 `int r = strerror_r(...); if (r == 0) ...`。

</details>
