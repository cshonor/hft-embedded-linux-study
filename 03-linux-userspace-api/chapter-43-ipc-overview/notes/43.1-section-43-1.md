## 本节讲什么

写 → 内核缓冲 → 读；通常 **两次用户↔内核拷贝**。 字节流：pipe、FIFO、流式 socket。 消息边界：SysV/POSIX 消息队列、数据报 socket。

## 要点

| 类 | 作用 |
|----|------|
| **通信** | 交换数据 |
| **同步** | 互斥、次序、消竞态 |
| **信号** | 异步事件；数据极少；实时信号可带少量 payload |

### 通信 · 数据传输型

写 → 内核缓冲 → 读；通常 **两次用户↔内核拷贝**。  
字节流：pipe、FIFO、流式 socket。  
消息边界：SysV/POSIX 消息队列、数据报 socket。

### 通信 · 共享内存

多进程映射同一物理页；**无内核拷贝，最快**。  
SysV shm · POSIX shm · `mmap`（匿名/文件）。  
⚠️ **本身无同步** → 必须配信号量/文件锁等。

### 同步

SysV 信号量 · POSIX 信号量（有名/无名）· `flock` / `fcntl` 记录锁。

## 与 C 语言学习的关系

`mmap` 是 C 语言高级内存操作。理解 `mmap` 需要 C 语言指针、内存对齐、页概念的知识。`mmap` 返回 `void*`（不是 NULL）失败是 C 语言中不同于 `malloc` 的一个细节。

## 常见陷阱

1. **fd 标志 vs 文件状态标志混淆**

```c
/* 错误：F_SETFL 改不了访问模式 */
fcntl(fd, F_SETFL, O_WRONLY);  /* 无效 */
```

F_SETFL 只能改 O_APPEND/O_NONBLOCK 等，不能改 O_RDONLY/O_WRONLY/O_RDWR。访问模式在 open 时确定。

2. **F_GETFL 解析访问模式**

```c
int flags = fcntl(fd, F_GETFL);
int acc = flags & O_ACCMODE;  /* O_RDONLY/O_WRONLY/O_RDWR */
```

不能直接用 `flags & O_WRONLY` 判断，因为 O_RDONLY 通常是 0。必须用 O_ACCMODE 掩码。

3. **FD_CLOEXEC 竞态**

```c
int fd = open(...);
fcntl(fd, F_SETFD, FD_CLOEXEC);  /* open 和 fcntl 之间有间隙 */
/* 多线程中 exec 可能在此间隙发生 */
```

open + fcntl(F_SETFD) 之间存在竞态窗口。用 O_CLOEXEC 标志一步到位。

## 自测题

**题目 1（选择）：** `fcntl(fd, F_SETFL, flags)` 可以改变以下哪个标志？
A. O_RDONLY
B. O_WRONLY
C. O_NONBLOCK
D. O_CREAT

<details>
<summary>参考答案</summary>

C。F_SETFL 只能改 O_APPEND、O_NONBLOCK、O_ASYNC 等状态标志，不能改访问模式（O_RDONLY 等）。

</details>

**题目 2（判断）：** `FD_CLOEXEC` 是文件状态标志，存在打开文件描述中。

<details>
<summary>参考答案</summary>

错误。FD_CLOEXEC 是 fd 标志，存在进程 fd 表中，每个 fd 私有。文件状态标志（如 O_APPEND）才在打开文件描述中。

</details>

**题目 3（踩坑）：** 以下代码试图将文件改为非阻塞，有什么问题？
```c
fcntl(fd, F_SETFL, O_NONBLOCK);
```

<details>
<summary>参考答案</summary>

问题：F_SETFL 会覆盖所有状态标志。应该先 F_GETFL 取回当前标志，再 OR 上 O_NONBLOCK：
`fcntl(fd, F_SETFL, fcntl(fd, F_GETFL) | O_NONBLOCK);`

</details>

**题目 4（应用）：** 写代码设置 fd 为非阻塞模式。

<details>
<summary>参考答案</summary>

```c
int flags = fcntl(fd, F_GETFL);
if (flags < 0) return -1;
return fcntl(fd, F_SETFL, flags | O_NONBLOCK);
```

</details>
