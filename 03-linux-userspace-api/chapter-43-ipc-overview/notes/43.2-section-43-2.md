## 要点

| 工具 | 跨进程识别名 | 进程内句柄 |
|------|--------------|------------|
| 匿名管道 | 无 | fd |
| FIFO | 路径名 | fd |
| UNIX / Internet socket | 路径或 IP:port | fd |
| System V IPC | `key_t` | IPC id |
| POSIX mq / 有名 sem / shm | `/` 路径名 | `mqd_t` / `sem_t*` / fd |
| POSIX 无名 sem | 无（放共享内存） | `sem_t*` |
| mmap 文件映射 | 文件路径 | fd |

痛点：SysV 独立 key/id，无标准路径名 → POSIX 用类文件名改良。

## 与 C 语言学习的关系

`mmap` 是 C 语言高级内存操作。理解 `mmap` 需要 C 语言指针、内存对齐、页概念的知识。`mmap` 返回 `void*`（不是 NULL）失败是 C 语言中不同于 `malloc` 的一个细节。

## 常见陷阱

1. **MAP_FAILED vs NULL**

```c
void *p = mmap(NULL, size, PROT_READ|PROT_WRITE,
              MAP_PRIVATE|MAP_ANONYMOUS, -1, 0);
if (p == NULL) ...  /* 错误! */
if (p == MAP_FAILED) ...  /* 正确 */
```

mmap 失败返回 MAP_FAILED ((void*)-1)，不是 NULL。检查方式与 malloc 不同。

2. **munmap 忘记调用**

```c
void *p = mmap(NULL, 4096, ...);
/* 使用 p ... */
/* 没有 munmap → 内存泄漏 */
```

mmap 分配的内存不会自动释放。必须 munmap(p, size) 显式释放。

3. **信号处理中的 SIGSEGV**

```c
mmap(NULL, size, PROT_READ, MAP_PRIVATE|MAP_ANONYMOUS, -1, 0);
/* 写只读映射 → SIGSEGV */
```

对 PROT_READ 的映射写入会触发 SIGSEGV。确保保护属性和访问操作匹配。

## 自测题

**题目 1（选择）：** `mmap` 失败时返回什么？
A. NULL
B. -1
C. MAP_FAILED
D. 0

<details>
<summary>参考答案</summary>

C。mmap 失败返回 MAP_FAILED（定义为 (void *)-1），不是 NULL。这与 malloc 不同。

</details>

**题目 2（判断）：** `mmap` 映射的内存会在进程退出时自动释放。

<details>
<summary>参考答案</summary>

正确。进程退出时所有映射自动解除。但在长时间运行的程序中仍需手动 munmap。

</details>

**题目 3（踩坑）：** 以下代码有什么问题？
```c
void *p = mmap(NULL, 4096, PROT_READ|PROT_WRITE,
               MAP_PRIVATE|MAP_ANONYMOUS, -1, 0);
memset(p, 0, 8192);
```

<details>
<summary>参考答案</summary>

写入了 8192 字节但只映射了 4096 字节。超出映射区域会触发 SIGSEGV。应确保操作不超过映射大小。

</details>

**题目 4（应用）：** 写代码用 mmap 分配匿名内存并初始化为 0。

<details>
<summary>参考答案</summary>

```c
void *p = mmap(NULL, 4096, PROT_READ|PROT_WRITE,
               MAP_PRIVATE|MAP_ANONYMOUS, -1, 0);
if (p == MAP_FAILED) { perror("mmap"); exit(1); }
memset(p, 0, 4096);
/* ... 使用 ... */
munmap(p, 4096);
```

</details>
