# 20.11 待处理信号（Pending Signals）

> 源码核验：Linux v6.6 · `kernel/signal.c`（`do_sigpending:3232` · `SYSCALL_DEFINE2(rt_sigpending):3249`）
> 本章：[TLPI 第 20 章 — Signals: Fundamental Concepts](../README.md)

## 本节讲什么

1. **未决（pending）是什么**——信号已产生但尚未递送的中间状态，内核存在哪里
2. `sigpending()` 到底返回什么——**两层 pending 的并集，再与掩码求交**
3. 为什么 `sigpending()` **查不到未被阻塞的信号**，以及这个特性该怎么用

---

## 一、两层 pending

回顾 [20.1](./20.1-concepts-and-overview.md)：未决信号存放在两个层级。

| 层级 | 位置 | 装的什么 | 谁会产生 |
|------|------|----------|----------|
| **线程私有** | `task_struct.pending` | 发给**特定线程**的信号 | `tgkill`/`pthread_kill`/`raise`（多线程）、硬件异常（`SIGSEGV`/`SIGFPE`） |
| **进程共享** | `signal_struct.shared_pending` | 发给**整个进程**的信号 | `kill`/`killpg`/终端信号，由任一线程竞争取走 |

```
   进程（线程组）
   ┌─────────────────────────────────────────┐
   │  shared_pending  { SIGTERM }            │  ← kill(pid, SIGTERM) 放这
   │                                          │
   │   线程 A               线程 B            │
   │   ┌──────────┐        ┌──────────┐      │
   │   │ pending  │        │ pending  │      │
   │   │ {SIGSEGV}│        │   { }    │      │  ← tgkill/硬件异常放这
   │   └──────────┘        └──────────┘      │
   └─────────────────────────────────────────┘
```

## 二、`sigpending()` 与 `do_sigpending()`

```c
#include <signal.h>

int sigpending(sigset_t *set);
/* 返回：成功 0，失败 -1 */
/* set 是**输出**参数：内核把当前未决集写进去 */
```

内核实现只有 6 行，却完整揭示了语义（`kernel/signal.c:3232`）：

```c
static void do_sigpending(sigset_t *set)
{
	spin_lock_irq(&current->sighand->siglock);
	sigorsets(set, &current->pending.signal,
		  &current->signal->shared_pending.signal);     // ① 私有 ∪ 共享
	spin_unlock_irq(&current->sighand->siglock);

	/* Outside the lock because only this thread touches it.  */
	sigandsets(set, &current->blocked, set);                 // ② ∩ 掩码
}
```

**完整语义**：

```
   sigpending(set)  ⟹  set = (私有 pending ∪ 共享 pending) ∩ 当前掩码
```

| 步骤 | 操作 | 含义 |
|------|------|------|
| ① | `pending.signal` **∪** `shared_pending.signal` | 把两级 pending 合起来看 |
| ② | 结果 **∩** `current->blocked` | **只保留被阻塞的那些** |

> **这是本节最反直觉的一点**：`sigpending()` 只报告**被阻塞而未递送**的信号。

原因很自然：**未被阻塞的信号会立即递送**，递送后 pending 位就被清掉了——所以它根本不会停留在 pending 集中。

```
   信号产生
     ├─ 未被阻塞 → 立即递送 → pending 清空 → sigpending 查不到 ✓（正常）
     └─ 被阻塞   → 留在 pending → sigpending 查得到 ✓
```

**实践推论**：`sigpending()` 的典型用途是检查「临界区期间有没有信号堆积」，而不是通用地"查询是否有信号"。

## 三、典型用法

```c
sigset_t pending;
sigpending(&pending);
if (sigismember(&pending, SIGINT) == 1) {   /* 注意用 == 1 比较 */
    /* SIGINT 已被阻塞并堆积在 pending 中 */
}
```

### 临界区后检查堆积

```c
sigset_t block, save, pending;
sigemptyset(&block);
sigaddset(&block, SIGTERM);
sigaddset(&block, SIGINT);

sigprocmask(SIG_BLOCK, &block, &save);      /* 进入临界区 */
/* ... 更新共享数据结构 ... */
sigpending(&pending);                       /* 检查期间有没有信号堆积 */
if (sigismember(&pending, SIGTERM) == 1)
    need_shutdown = 1;
sigprocmask(SIG_SETMASK, &save, NULL);      /* 退出临界区 → 堆积的信号补递送 */
```

> **注意顺序**：`sigpending()` 必须在**解除阻塞之前**调用。一旦 `sigprocmask(SIG_SETMASK, ...)` 恢复掩码，pending 的信号会**立即递送并被清空**，之后就查不到了。

## 四、与「不排队」的关系

标准信号**不排队**：阻塞期间同号信号到达 N 次，pending 位图中仍然只有**一个位**，解除阻塞后 handler **只执行一次**。

```c
sigprocmask(SIG_BLOCK, &mask, NULL);
raise(SIGINT); raise(SIGINT); raise(SIGINT);   /* 发了 3 次 */
sigpending(&pending);
/* sigismember(&pending, SIGINT) == 1，但无法知道是 1 次还是 3 次 */
```

这是下一节 [20.12 信号不排队](./20.12-signals-are-not-queued.md) 的主题。

## HFT / 嵌入式关联

| 路线 | 要点 |
|------|------|
| 嵌入式 | 临界区结束后检查 pending，决定是否需要特殊处理（如停机信号在临界区期间到达，出临界区后立即响应）。注意 `sigpending` 必须在恢复掩码**之前**调用，否则信号已补递送、pending 被清空 |
| HFT | 长时间阻塞后检查 pending 可辅助诊断「信号事件被合并丢失」的问题——但因为它**不排队**，只能知道「来过」，无法知道「来了几次」。HFT 中若需精确计数，应改用实时信号（可排队，见 [Ch22.8](../../chapter-22-signals-advanced/notes/22.8-realtime-signals.md)）或 signalfd（[Ch22.11](../../chapter-22-signals-advanced/notes/22.11-fetching-signals-via-a-file-descriptor.md)） |

## 代码示例

### 一、`block_pending.c`（自编 demo）

本节讲 `sigpending()` 的语义「未决 = (私有 ∪ 共享) ∩ 掩码」。`block_pending.c` 是最小验证：阻塞 `SIGINT` → 按 `Ctrl+C` → `sigpending()` 查得到 → 解除阻塞后补递送。它只观察**单个信号**的未决与递送时序，是理解 pending 概念的第一步。

完整源码（[`code/block_pending.c`](../code/block_pending.c)）：

```c
/* Block SIGINT, show pending, then unblock (delivery / default terminate).
 * cc -Wall -Wextra -o block_pending block_pending.c && ./block_pending
 *
 * While "blocked", press Ctrl+C once or twice; standard signals do not queue.
 */
#include <errno.h>
#include <signal.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <unistd.h>

static void on_int(int sig)
{
    const char msg[] = "\n[handler] SIGINT delivered\n";
    (void)sig;
    /* write is async-signal-safe */
    write(STDOUT_FILENO, msg, sizeof(msg) - 1);
}

int main(void)
{
    sigset_t block, old, pending;
    struct sigaction sa;

    memset(&sa, 0, sizeof(sa));
    sa.sa_handler = on_int;
    sigemptyset(&sa.sa_mask);
    if (sigaction(SIGINT, &sa, NULL) == -1) {
        perror("sigaction");
        return EXIT_FAILURE;
    }

    sigemptyset(&block);
    sigaddset(&block, SIGINT);
    if (sigprocmask(SIG_BLOCK, &block, &old) == -1) {
        perror("sigprocmask BLOCK");
        return EXIT_FAILURE;
    }

    printf("pid=%ld  SIGINT blocked for 8s — try Ctrl+C\n", (long)getpid());
    sleep(8);

    if (sigpending(&pending) == -1) {
        perror("sigpending");
        return EXIT_FAILURE;
    }
    printf("SIGINT pending? %s\n",
           sigismember(&pending, SIGINT) ? "YES" : "no");

    printf("unblocking SIGINT (pending one will deliver now)...\n");
    if (sigprocmask(SIG_SETMASK, &old, NULL) == -1) {
        perror("sigprocmask SETMASK");
        return EXIT_FAILURE;
    }

    /* If user never pressed Ctrl+C, just exit cleanly */
    sleep(1);
    printf("done\n");
    return 0;
}
```

编译（macOS 26.6.2 / arm64 · clang 23.1.0）：

```bash
$CC -Wall -Wextra -o block_pending block_pending.c
```

实测输出：`code/README.md` 的「实测输出」节未单独收录（输出依赖人工按 `Ctrl+C` 的次数与时序）。它验证的规则——**未决必须在解除阻塞之前查询**——在下面的 `ignore_pending_sig.c` 里有可钉死的实测文本。

**逐条解读**：

| 代码片段 | 对应本节的哪条规则 |
|----------|--------------------|
| `sigprocmask(SIG_BLOCK, &block, &old)` | 阻塞后信号留在 pending（本节第一节「阻塞 ≠ 忽略」表） |
| `sigpending(&pending)` 在 `SIG_SETMASK` **之前** | 本节第三节的「注意顺序」：解除阻塞后 pending 会被清空，必须先查 |
| `sigprocmask(SIG_SETMASK, &old, NULL)` | 用保存的 `old` 精确恢复，而不是 `SIG_UNBLOCK` |

**源码坐标**：自编 demo；未决集实现 `do_sigpending():3232`；`sigpending` 的「∪ 后 ∩ 掩码」两行见 `kernel/signal.c:3237-3245`。

### 二、`sig_receiver.c`（Listing 20-7）

`sig_receiver.c` 是官方对 pending 的**全掩码版**实验：`sigfillset()` 把所有信号都阻塞，外部程序在睡眠期发信号，醒来后用 `printSigset()` 打出 pending 集合。它的输出直接展示了「两层 pending 取并集」以及「标准信号不排队」。

完整源码（[`code/sig_receiver.c`](../code/sig_receiver.c)）：

```c
/*************************************************************************\
*                  Copyright (C) Michael Kerrisk, 2026.                   *
*                                                                         *
* This program is free software. You may use, modify, and redistribute it *
* under the terms of the GNU General Public License as published by the   *
* Free Software Foundation, either version 3 or (at your option) any      *
* later version. This program is distributed without any warranty.  See   *
* the file COPYING.gpl-v3 for details.                                    *
\*************************************************************************/

/* Listing 20-7 */

/* sig_receiver.c

   Usage: sig_receiver [block-time]

   Catch and report statistics on signals sent by sig_sender.c.

   Note that although we use signal() to establish the signal handler in this
   program, the use of sigaction() is always preferable for this task.
*/
#define _GNU_SOURCE
#include <signal.h>
#include "signal_functions.h"           /* Declaration of printSigset() */
#include "tlpi_hdr.h"

static int sigCnt[NSIG];                /* Counts deliveries of each signal */
static volatile sig_atomic_t gotSigint = 0;
                                        /* Set nonzero if SIGINT is delivered */

static void
handler(int sig)
{
    if (sig == SIGINT)
        gotSigint = 1;
    else
        sigCnt[sig]++;
}

int
main(int argc, char *argv[])
{
    int n, numSecs;
    sigset_t pendingMask, blockingMask, emptyMask;

    printf("%s: PID is %ld\n", argv[0], (long) getpid());

    /* Here we use the simpler signal() API to establish a signal handler,
       but for the reasons described in Section 22.7 of TLPI, sigaction()
       is the (strongly) preferred API for this task. */

    for (n = 1; n < NSIG; n++)          /* Same handler for all signals */
        (void) signal(n, handler);      /* Ignore errors */

    /* If a sleep time was specified, temporarily block all signals,
       sleep (while another process sends us signals), and then
       display the mask of pending signals and unblock all signals */

    if (argc > 1) {
        numSecs = getInt(argv[1], GN_GT_0, NULL);

        sigfillset(&blockingMask);
        if (sigprocmask(SIG_SETMASK, &blockingMask, NULL) == -1)
            errExit("sigprocmask");

        printf("%s: sleeping for %d seconds\n", argv[0], numSecs);
        sleep(numSecs);

        if (sigpending(&pendingMask) == -1)
            errExit("sigpending");

        printf("%s: pending signals are: \n", argv[0]);
        printSigset(stdout, "\t\t", &pendingMask);

        sigemptyset(&emptyMask);        /* Unblock all signals */
        if (sigprocmask(SIG_SETMASK, &emptyMask, NULL) == -1)
            errExit("sigprocmask");
    }

    while (!gotSigint)                  /* Loop until SIGINT caught */
        continue;

    for (n = 1; n < NSIG; n++)          /* Display number of signals received */
        if (sigCnt[n] != 0)
            printf("%s: signal %d caught %d time%s\n", argv[0], n,
                    sigCnt[n], (sigCnt[n] == 1) ? "" : "s");

    exit(EXIT_SUCCESS);
}
```

编译（macOS 26.6.2 / arm64 · clang 23.1.0）：


```text
        12 (Bad system call: 12)
sig_receiver: signal 10 caught 1 time    ← 发了 3 次，只递送 1 次
sig_receiver: signal 12 caught 1 time
```

**逐条解读**：

| 输出行 | 对应本节哪条语义 |
|--------|------------------|
| `pending signals are:` 两行 | `sigfillset` 全屏蔽期间到达的信号全部进入 pending；`printSigset()` 把集合打印出来 |
| 编号 10 / 12 | 本机 BSD 编号表：macOS 上 10=`SIGBUS`、12=`SIGSYS`。信号来自 `sig_sender` 的 `kill()`，属于**进程共享 pending**（`shared_pending`）那一层 |
| `caught 1 time` | 解除阻塞（`SIG_SETMASK` + `emptyMask`）后信号补递送；发了 3 次只递送 1 次——标准信号不排队，pending 位图只有 1 个比特，**无法从 pending 得知来了几次**（本节自测题 4） |

### 三、`ignore_pending_sig.c`（习题 20-2 官方解）

本节「阻塞 ≠ 忽略」的另一半是：**已经 pending 的信号，若处置被改成 `SIG_IGN`，会被立刻丢弃**。这道官方习题解把这个瞬间钉成了可观测输出——它先阻塞 `SIGINT`，在阻塞期产生一个 pending，然后把处置改成 `SIG_IGN`，再重新读 pending，结果为**空集**。

完整源码（[`code/ignore_pending_sig.c`](../code/ignore_pending_sig.c)）：

```c
/*************************************************************************\
*                  Copyright (C) Michael Kerrisk, 2026.                   *
*                                                                         *
* This program is free software. You may use, modify, and redistribute it *
* under the terms of the GNU General Public License as published by the   *
* Free Software Foundation, either version 3 or (at your option) any      *
* later version. This program is distributed without any warranty.  See   *
* the file COPYING.gpl-v3 for details.                                    *
\*************************************************************************/

/* Solution for Exercise 20-2 */

/* ignore_pending_sig.c

   This program demonstrates what happens if we mark a pending signal
   (i.e., one that has been sent, but is currently blocked) as ignored.

   Usage: ignore_pending_sig

   Type Control-C (^C) to generate a SIGINT signal after the program prints
   its "sleeping" message (see below).
*/
#define _GNU_SOURCE     /* Get strsignal() declaration from <string.h> */
#include <string.h>
#include <signal.h>
#include "signal_functions.h"   /* Declaration of printSigset() */
#include "tlpi_hdr.h"

static void
handler(int sig)
{
    /* UNSAFE: This handler uses non-async-signal-safe functions
       (printf(), strsignal(), fflush(); see Section 21.1.2) */

    printf("Caught signal %d (%s)\n", sig, strsignal(sig));
    fflush(NULL);
}

int
main(int argc, char *argv[])
{
    const int numSecs = 5;

    /* Set up a handler for SIGINT */

    printf("Setting up handler for SIGINT\n");

    struct sigaction sa;
    sigemptyset(&sa.sa_mask);
    sa.sa_flags = 0;
    sa.sa_handler = handler;
    if (sigaction(SIGINT, &sa, NULL) == -1)
        errExit("sigaction");

    /* Block SIGINT for a while */

    sigset_t blocked;
    sigemptyset(&blocked);
    sigaddset(&blocked, SIGINT);
    if (sigprocmask(SIG_SETMASK, &blocked, NULL) == -1)
        errExit("sigprocmask");

    printf("BLOCKING SIGINT for %d seconds\n", numSecs);
    sleep(numSecs);

    /* Display mask of pending signals */

    sigset_t pending;
    if (sigpending(&pending) == -1)
        errExit("sigpending");
    printf("PENDING signals are: \n");
    printSigset(stdout, "\t\t", &pending);

    /* Now ignore SIGINT */

    sleep(2);
    printf("Ignoring SIGINT\n");
    if (signal(SIGINT, SIG_IGN) == SIG_ERR)     errExit("signal");

    /* Redisplay mask of pending signals */

    if (sigpending(&pending) == -1)
        errExit("sigpending");
    if (sigismember(&pending, SIGINT)) {
        printf("SIGINT is now pending\n");
    } else {
        printf("PENDING signals are: \n");
        printSigset(stdout, "\t\t", &pending);
    }
    sleep(2);

    /* Reestablish SIGINT handler */

    printf("Reestablishing handler for SIGINT\n");
    sigemptyset(&sa.sa_mask);
    sa.sa_flags = 0;
    sa.sa_handler = handler;
    if (sigaction(SIGINT, &sa, NULL) == -1)
        errExit("sigaction");

    sleep(2);

    /* And unblock SIGINT */

    printf("UNBLOCKING SIGINT\n");
    sigemptyset(&blocked);
    if (sigprocmask(SIG_SETMASK, &blocked, NULL) == -1)
        errExit("sigprocmask");

    exit(EXIT_SUCCESS);
}
```

编译（macOS 26.6.2 / arm64 · clang 23.1.0）：

```bash

```

实测输出（`BLOCKING` 期间按一次 `Ctrl+C`）：

```text

BLOCKING SIGINT for 5 seconds
PENDING signals are:
        2 (Interrupt: 2)        ← 阻塞期发的 SIGINT 在 pending
Ignoring SIGINT                 ← 处置改成 SIG_IGN 的瞬间……
PENDING signals are:
        <empty signal set>      ← pending 被抹掉，永远不会再递送
```

**逐条解读**：

| 输出行 | 对应本节/ [20.3](20.3-changing-signal-dispositions-signal.md) 的哪条规则 |
|--------|--------------------------------------------------------------------------|
| `PENDING signals are: 2 (Interrupt: 2)` | 阻塞期间的 `SIGINT` 停在 pending，`sigpending()` 查得到——这是「阻塞 = 延迟递送」 |
| `Ignoring SIGINT` 之后的 `<empty signal set>` | 处置改成 `SIG_IGN` 的瞬间，内核**冲刷**该信号的 pending（POSIX 3.3.1.3；内核侧 `do_sigaction` 的第六步 `flush_sigqueue_mask`） |
| `UNBLOCKING SIGINT` 后没有任何输出 | pending 已被抹掉，解除阻塞也**什么都不会发生**——证明 `SIG_IGN` 不只是"新信号不进 pending"，连**已有的 pending 也会被丢弃** |
| 全程没有 `Caught signal 2` | 与「阻塞」形成对照：阻塞会补递送，忽略是**永不递送** |

**踩坑点**：`<empty signal set>` 这个文案来自 `signal_functions.c` 的 `printSigset()`（`cnt == 0` 分支）。能打出空集，说明 `sigpending()` 返回的确实是一个**真集合**，不是"没有输出"——这正是「阻塞 vs 忽略」最硬的区分证据。

**源码坐标**：原书 **习题 20-2 官方解**（`github.com/segarciat/TLPI`）；内核冲刷逻辑 `do_sigaction():4175-4181` 的 `flush_sigqueue_mask()`；POSIX 依据 3.3.1.3。

### 四、教学补充片段（非 `code/`，未实测）

```c
/* pendingdemo.c —— 验证 sigpending = (私有∪共享) ∩ 掩码
 * 编译: gcc -D_GNU_SOURCE -o pendingdemo pendingdemo.c */
#define _GNU_SOURCE
#include <signal.h>
#include <stdio.h>
#include <unistd.h>
#include <sys/syscall.h>

static void show(const char *tag, const sigset_t *p)
{
    printf("  %-28s SIGINT=%d SIGUSR1=%d\n", tag,
           sigismember(p, SIGINT) == 1,
           sigismember(p, SIGUSR1) == 1);
}

int main(void)
{
    sigset_t block, save, pending;

    /* 构造要阻塞的集合：SIGINT（进程级）+ SIGUSR1（本线程） */
    sigemptyset(&block);
    sigaddset(&block, SIGINT);
    sigaddset(&block, SIGUSR1);
    sigprocmask(SIG_BLOCK, &block, &save);

    /* ① 进程级：kill 放进 shared_pending */
    kill(getpid(), SIGINT);
    /* ② 线程级：tgkill 放进本线程私有 pending */
    syscall(SYS_tgkill, getpid(), syscall(SYS_gettid), SIGUSR1);

    sigpending(&pending);
    printf("阻塞期间（私有∪共享 均应可见）:\n");
    show("  sigpending()", &pending);        /* SIGINT=1 SIGUSR1=1 */

    /* ③ 不排队验证：连发多次 SIGINT */
    raise(SIGINT); raise(SIGINT); raise(SIGINT);
    sigpending(&pending);
    printf("\n连发 3 次 SIGINT 后（仍只有一份）:\n");
    show("  sigpending()", &pending);        /* SIGINT=1（无法得知次数） */

    /* ④ 解除阻塞前必须查 pending —— 之后就被清空了 */
    sigprocmask(SIG_SETMASK, &save, NULL);
    sigpending(&pending);
    printf("\n解除阻塞后（信号已补递送，pending 清空）:\n");
    show("  sigpending()", &pending);        /* 注意：SIGINT 默认终止，实际到不了这里 */

    return 0;
}
```

> **运行提示**：`SIGINT`/`SIGUSR1` 的默认动作是 terminate，所以第 ④ 步实际运行时进程会被终止。观察 ①②③ 的输出即可；若要完整跑通，请先 `sigaction` 把两者设为 `SIG_IGN` 或自定义 handler。

## 自测题

<details>
<summary><b>问 1：</b><code>sigpending()</code> 返回的到底是什么？为什么查不到未被阻塞的信号？</summary>

内核实现（`kernel/signal.c:3232`）：

```c
static void do_sigpending(sigset_t *set)
{
	spin_lock_irq(&current->sighand->siglock);
	sigorsets(set, &current->pending.signal,
		  &current->signal->shared_pending.signal);   // 私有 ∪ 共享
	spin_unlock_irq(&current->sighand->siglock);

	/* Outside the lock because only this thread touches it.  */
	sigandsets(set, &current->blocked, set);               // ∩ 掩码
}
```

**完整语义**：

```
set = (线程私有 pending ∪ 进程共享 pending) ∩ 当前掩码
```

**为什么查不到未被阻塞的信号**：

因为未被阻塞的信号**会立即递送**——递送时内核从 pending 位图里取出该信号并清除对应位。所以未阻塞的信号在 pending 里停留的时间趋近于零，`sigpending()` 自然查不到。

**实践结论**：`sigpending()` 的准确含义是「**查询当前被阻塞、堆积着等待递送的信号**」，不是通用的"有没有信号"。

</details>

<details>
<summary><b>问 2：</b>线程私有的 pending 和进程共享的 pending 各装什么信号？<code>sigpending</code> 如何兼顾？</summary>

| 层级 | 位置 | 装的什么 |
|------|------|----------|
| **线程私有** | `task_struct.pending` | 发给特定线程：`tgkill`/`pthread_kill`/glibc 的 `raise()`（多线程下），以及**硬件异常**（`SIGSEGV`/`SIGFPE`/`SIGILL` 由当前线程触发） |
| **进程共享** | `signal_struct.shared_pending` | 发给整个进程：`kill`/`killpg`/终端信号，由任一未阻塞线程竞争取走 |

**`sigpending` 兼顾方式**：`do_sigpending` 第 ① 步就做了 `sigorsets(set, &current->pending.signal, &current->signal->shared_pending.signal)`，把两级**取并集**，所以调用方看到的是合并后的视图，无需关心信号来自哪一级。

**推论**：用 `kill()` 给多线程进程发信号，handler 由**任意一个**未阻塞该信号的线程执行——正因为信号放在 `shared_pending` 里，谁先被调度到谁取走。

</details>

<details>
<summary><b>问 3：</b>为什么必须在解除阻塞<b>之前</b>调用 <code>sigpending()</code>？</summary>

因为一旦解除阻塞，pending 的信号会**立即递送并从位图中清除**，`sigpending()` 就查不到了。

时间线：

```
sigprocmask(SIG_BLOCK, &mask, &save);
    ↓ 信号堆积在 pending
sigpending(&pending);              ← ✅ 此时能查到
    ↓
sigprocmask(SIG_SETMASK, &save, NULL);   ← 解除阻塞
    ↓ 内核立即递送 pending 信号，清除位图
sigpending(&pending);              ← ❌ 已被清空，查不到了
```

**正确模式**：

```c
sigprocmask(SIG_BLOCK, &block, &save);       /* 进入临界区 */
/* ... 更新共享数据 ... */
sigpending(&pending);                        /* 先查堆积 */
if (sigismember(&pending, SIGTERM) == 1)
    need_shutdown = 1;                       /* 记录意图 */
sigprocmask(SIG_SETMASK, &save, NULL);       /* 后解除阻塞 */
```

**更优雅的替代**：如果目的只是「不错过停机信号」，用 `sigwaitinfo()` 同步取信号（[Ch22.10](../../chapter-22-signals-advanced/notes/22.10-synchronously-waiting-for-a-signal.md)）比「阻塞 + 查 pending + 解除」干净得多。

</details>

<details>
<summary><b>问 4：</b>阻塞期间同号信号来了 5 次，<code>sigpending</code> 能查出来是 5 次吗？</summary>

**不能**。标准信号**不排队**，pending 位图里只有**一个位**，只能表示"来过 / 没来过"，无法表示次数。

```c
sigprocmask(SIG_BLOCK, &mask, NULL);
raise(SIGINT); raise(SIGINT); raise(SIGINT);  /* 发 5 次 */
sigpending(&pending);
/* sigismember(&pending, SIGINT) == 1  ← 只知道"来过" */
sigprocmask(SIG_SETMASK, &save, NULL);
/* handler 只执行 1 次，不是 5 次 ❌ */
```

**如果需要精确计数**，三个方向：

1. **实时信号**——可排队，`sigqueue()` 可携带数据（[Ch22.8](../../chapter-22-signals-advanced/notes/22.8-realtime-signals.md)）
2. **`signalfd`**——把信号变成文件描述符事件，可 `read()` 出每一次（[Ch22.11](../../chapter-22-signals-advanced/notes/22.11-fetching-signals-via-a-file-descriptor.md)）
3. **不用信号**——HFT 内部通知应走 eventfd / 共享内存原子计数器，天然支持计数

详见下一节 [20.12 信号不排队](./20.12-signals-are-not-queued.md)。

</details>

<details>
<summary><b>问 5：</b><code>do_sigpending</code> 里 <code>sigorsets</code> 加锁而 <code>sigandsets(&current->blocked, ...)</code> 不加锁，为什么？</summary>

代码里的注释直接给出了答案：

```c
static void do_sigpending(sigset_t *set)
{
	spin_lock_irq(&current->sighand->siglock);
	sigorsets(set, &current->pending.signal,
		  &current->signal->shared_pending.signal);
	spin_unlock_irq(&current->sighand->siglock);

	/* Outside the lock because only this thread touches it.  */
	sigandsets(set, &current->blocked, set);
}
```

**原因分析**：

| 数据 | 谁会修改 | 是否需要锁 |
|------|----------|-----------|
| `current->pending.signal` | **其他线程**可以往里写（用 `tgkill` 给本线程发信号） | ✅ 需要 `sighand->siglock` |
| `current->signal->shared_pending.signal` | **其他线程**竞争取走 | ✅ 需要同一把锁 |
| `current->blocked` | **只有本线程自己**能改（`sigprocmask` 只改 `current`） | ❌ 不需要锁 |

关键在注释那句 *"Outside the lock because only this thread touches it"*——`blocked` 是线程私有字段，且内核保证只有 `current` 自己会改它（源码里 `sigprocmask` 开头也有类似注释：`/* Lockless, only current can change ->blocked, never from irq */`）。

**这是一个典型的内核无锁编程模式**：通过「数据归属唯一」来消除加锁需求，而非盲目加锁。

</details>
