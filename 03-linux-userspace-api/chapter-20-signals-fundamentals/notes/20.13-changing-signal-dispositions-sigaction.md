## 本节讲什么

1. `sigaction()` 相比 `signal()` **多了什么**——`sa_mask`、`sa_flags`、`SA_SIGINFO` 三件事
2. `struct sigaction` 每个字段的确切语义（尤其是 `sa_handler` 与 `sa_sigaction` 的**共用存储**陷阱）
3. `sa_flags` 常用值怎么选，以及内核在哪一层做校验

## 一、接口与结构体

```c
#include <signal.h>

int sigaction(int sig, const struct sigaction *act, struct sigaction *oldact);
/* 返回：成功 0，失败 -1 */
/* act 为 NULL 时只读取当前处置到 oldact，不修改 */
```

```c
struct sigaction {
    union {
        void (*sa_handler)(int);                        /* 简单处理器 */
        void (*sa_sigaction)(int, siginfo_t *, void *); /* 扩展处理器（SA_SIGINFO 时用） */
    } __sigaction_handler;
    sigset_t   sa_mask;    /* handler 执行期间**额外**阻塞的信号集 */
    int        sa_flags;   /* 行为控制位 */
    void     (*sa_restorer)(void);   /* 仅供内核内部使用，不要设置！ */
};

#define sa_handler    __sigaction_handler.sa_handler
#define sa_sigaction  __sigaction_handler.sa_sigaction
```

> **⚠️ 关键陷阱**：`sa_handler` 和 `sa_sigaction` 在 Linux/glibc 上是 **union 的同一块内存**——**绝不能同时设置**！
>
> ```c
> sa.sa_handler = handler;
> sa.sa_sigaction = handler_info;   /* ❌ 覆盖了上一行，行为未定义 */
> ```
>
> 用哪个取决于 `sa_flags` 里有没有设 `SA_SIGINFO`：
> - 无 `SA_SIGINFO` → 用 `sa_handler`（`void(int)`）
> - 有 `SA_SIGINFO` → 用 `sa_sigaction`（`void(int, siginfo_t*, void*)`）

**另一个陷阱**：`sa_restorer` 是内核与 libc 之间的内部约定字段，**用户代码绝对不要设置它**，也不要依赖它的值。初始化结构体时用 `memset(&sa, 0, sizeof sa)` 清零即可。

## 二、`sa_mask`：handler 期间的额外屏蔽

`sa_mask` 里的信号会在 handler 执行期间**临时加入**当前掩码，handler 返回后由 `sigreturn` 自动恢复（见 [20.4](./20.4-introduction-to-signal-handlers.md)）。

```
   handler 执行期间的实际掩码 = 调用前掩码 ∪ sa_mask ∪ {本信号}
                                    ↑          ↑          ↑
                                  继承        sa_mask    除非 SA_NODEFER
```

**典型用途**：防止 handler 被其他 handler 打断造成嵌套：

```c
struct sigaction sa = {0};
sa.sa_handler = handler;
sigemptyset(&sa.sa_mask);
sigaddset(&sa.sa_mask, SIGTERM);     /* 处理 SIGINT 时，连 SIGTERM 一起屏蔽 */
sigaddset(&sa.sa_mask, SIGUSR1);
sa.sa_flags = SA_RESTART;
sigaction(SIGINT, &sa, NULL);
```

> **内核强制约束**：`do_sigaction()` 会执行 `sigdelsetmask(&act->sa.sa_mask, sigmask(SIGKILL)|sigmask(SIGSTOP))`（`kernel/signal.c:4161`），把 `SIGKILL`/`SIGSTOP` 从 `sa_mask` 中**静默剔除**。所以无法在 handler 期间屏蔽这两个信号。

## 三、`sa_flags` 完整表

| flag | 含义 | 备注 |
|------|------|------|
| `0` | 使用 `sa_handler`，默认语义 | handler 期间自动阻塞本信号 |
| **`SA_RESTART`** | 被信号中断的**慢系统调用自动重启** | 最常用；避免手写 `EINTR` 重试循环 |
| **`SA_SIGINFO`** | 使用 `sa_sigaction`，可获取 `siginfo_t` | 能拿到发送者 PID、UID、附加数据 |
| `SA_NOCLDSTOP` | `SIGCHLD` 仅在子进程**终止**时产生 | 子进程停止/继续时不再通知 |
| `SA_NOCLDWAIT` | 子进程退出**不产生僵尸** | 无法再 `wait()` 获取退出状态 |
| `SA_RESETHAND` | 递送后自动复位为 `SIG_DFL`（一次性） | 相当于 `signal()` 的 `SA_ONESHOT` |
| `SA_NODEFER` | handler 期间**不**自动阻塞本信号 | 允许自我重入，默认不建议 |
| `SA_ONSTACK` | 在 `sigaltstack()` 备用栈上执行 handler | 处理 `SIGSEGV` 栈溢出必需 |
| `SA_NOMASK` | `SA_NODEFER` 的历史别名 | 已废弃，勿用 |

### 内核侧的 flag 处理

`do_sigaction()` 会做一次**掩码过滤**（`kernel/signal.c:4153-4156`）：

```c
	if (act)
		act->sa.sa_flags &= UAPI_SA_FLAGS;
	if (oact)
		oact->sa.sa_flags &= UAPI_SA_FLAGS;
```

含义：内核**不认识**的 flag 位会被**静默清除，且不报错**。

> **实践推论**：想确认某个 flag 是否真的被内核支持（尤其是较新的 flag），正确做法不是看 `sigaction()` 的返回值，而是**设置后读回比对**：
> ```c
> struct sigaction want = {0}, got;
> want.sa_handler = handler;
> want.sa_flags = SA_RESTART | SOME_NEW_FLAG;
> sigaction(SIGINT, &want, NULL);
> sigaction(SIGINT, NULL, &got);         /* 读回内核实际保存的值 */
> if ((got.sa_flags & SOME_NEW_FLAG) == 0)
>     fprintf(stderr, "内核不支持该 flag，已静默丢弃\n");
> ```

## 四、内核校验链回顾

`sigaction()` 全部校验都在 `do_sigaction()`（`kernel/signal.c:4123`）里完成，完整拆解见 [20.3](./20.3-changing-signal-dispositions-signal.md)。这里只列要点：

| # | 行号 | 检查 |
|---|------|------|
| ① | `:4129` | `sig_kernel_only(sig)` → `SIGKILL`/`SIGSTOP` 拒绝，`-EINVAL` |
| ② | `:4132` | 处置存在 `sighand->action[]`，**线程组共享** |
| ③ | `:4135` | `SA_IMMUTABLE` 锁定的信号不可改 |
| ④ | `:4154` | 未知 flag 位被清除（不报错） |
| ⑤ | `:4161` | `sa_mask` 中的 `SIGKILL`/`SIGSTOP` 被剔除 |
| ⑥ | `:4175` | 新处置等于「忽略」时，冲刷所有 pending |

## 五、`sigaction()` vs `signal()`

| 能力 | `signal()` | `sigaction()` |
|------|-----------|---------------|
| 可移植性 | ❌ 行为不一致（BSD vs SysV） | ✅ POSIX 标准 |
| 控制 `SA_RESTART` | ❌ | ✅ |
| 设置 `sa_mask` | ❌ 内核硬编码为空 | ✅ |
| 获取 `siginfo_t` | ❌ | ✅ `SA_SIGINFO` |
| 指定备用栈 `SA_ONSTACK` | ❌ | ✅ |
| 一次性 `SA_RESETHAND` | ❌ 由实现决定 | ✅ 显式 |
| **结论** | **不要用**（仅 demo 或 `SIG_IGN`） | **永远用** |

> 回顾 [20.3](./20.3-changing-signal-dispositions-signal.md)：裸 `sys_signal` 在内核里硬编码 `SA_ONESHOT | SA_NOMASK`（`kernel/signal.c:4628`）——既会一次性复位，又不阻塞自身，两个都是危险语义。

## 六、标准用法模板

```c
struct sigaction sa;
memset(&sa, 0, sizeof sa);            /* ① 必须清零（或用 = {0}） */
sa.sa_handler = handler;              /* ② 与 sa_sigaction 二选一 */
sigemptyset(&sa.sa_mask);             /* ③ 必须初始化 sa_mask */
/* sigaddset(&sa.sa_mask, ...);         按需额外屏蔽 */
sa.sa_flags = SA_RESTART;             /* ④ 显式声明行为 */
/* ⑤ 不要碰 sa_restorer */

if (sigaction(SIGINT, &sa, NULL) == -1) {
    perror("sigaction");
    return 1;
}
```

**三个必须**：

| # | 要点 | 原因 |
|---|------|------|
| ① | 清零结构体 | `sa_flags`/`sa_restorer` 是垃圾值会导致未定义行为 |
| ③ | `sigemptyset(&sa.sa_mask)` | 未初始化的 `sa_mask` 会**随机屏蔽信号** |
| ④ | 显式设 `sa_flags` | 依赖默认值的代码意图不清，且平台间有差异 |

---

## HFT / 嵌入式关联

| 路线 | 要点 |
|------|------|
| 嵌入式 | `SA_RESTART` 避免信号中断 `read`/`write` 后手写 `EINTR` 重试循环，减少嵌入式代码体积与出错面。处理 `SIGSEGV` 做故障诊断时必须配 `SA_ONSTACK` + `sigaltstack()`，否则栈溢出时无栈可用。注意 `SA_NOCLDWAIT` 能避免僵尸，但会失去子进程退出状态，故障排查变困难 |
| HFT | `SA_SIGINFO` 可获取信号来源 PID/UID，用于审计（谁发的停机信号）。`SA_RESTART` 让被中断的 `recv()` 自动重启，避免手写重试引入延迟抖动。但更根本的：HFT 关键路径应**全程屏蔽**无关信号，控制类信号走 signalfd 进事件循环，handler 只作为最后兜底 |

## 代码示例

### 一、`intquit.c`（Listing 20-2）

本节的主角是 `sigaction()`，而 TLPI 用 `intquit.c` 演示「一个 handler 同时接管两个信号」：`SIGINT` 只计数后返回，`SIGQUIT` 直接 `exit()`。它虽然是 `signal()` 版本（原书刻意保留以对照），但 `sa_mask`、`sa_flags` 的等价写法正是本节自测题 1 讨论的模板。

完整源码（[`code/intquit.c`](../code/intquit.c)）：

```c
/*************************************************************************\
*                  Copyright (C) Michael Kerrisk, 2026.                   *
*                                                                         *
* This program is free software. You may use, modify, and redistribute it *
* under the terms of the GNU General Public License as published by the   *
* Free Software Foundation, either version 3 or (at your option) any      *
* later version. This program is distributed without any warranty.  See   *
* the file COPYING.gpl-v3 for details.                                    *
\*************************************************************************/

/* Listing 20-2 */

/* intquit.c

   Catch the SIGINT and SIGQUIT signals, which are normally generated
   by the control-C (^C) and control-\ (^\) keys respectively.

   Note that although we use signal() to establish signal handlers in this
   program, the use of sigaction() is always preferable for this task.
*/
#include <signal.h>
#include "tlpi_hdr.h"

static void
sigHandler(int sig)
{
    static int count = 0;

    /* UNSAFE: This handler uses non-async-signal-safe functions
       (printf(), exit(); see Section 21.1.2) */

    if (sig == SIGINT) {
        count++;
        printf("Caught SIGINT (%d)\n", count);
        return;                 /* Resume execution at point of interruption */
    }

    /* Must be SIGQUIT - print a message and terminate the process */

    printf("Caught SIGQUIT - that's all folks!\n");
    exit(EXIT_SUCCESS);
}

int
main(int argc, char *argv[])
{
    /* Establish same handler for SIGINT and SIGQUIT. Here we use the
       simpler signal() API to establish a signal handler, but for the
       reasons described in Section 22.7 of TLPI, sigaction() is the
       (strongly) preferred API for this task. */

    if (signal(SIGINT, sigHandler) == SIG_ERR)
        errExit("signal");
    if (signal(SIGQUIT, sigHandler) == SIG_ERR)
        errExit("signal");

    for (;;)                    /* Loop forever, waiting for signals */
        pause();                /* Block until a signal is caught */
}
```

编译（macOS 26.6.2 / arm64 · clang 23.1.0）：

```bash
$CC $D -Wall -Wextra -o intquit    intquit.c         get_num.c signal_functions.c
```

实测输出（先 `kill -INT`，再 `kill -QUIT`）：

```text
$ intquit：kill -INT; kill -QUIT
Caught SIGINT (1)
Caught SIGQUIT - that's all folks!    ← QUIT handler 里 exit()，第二次 INT 发不进（进程已亡）
```

**逐条解读**：

| 输出行 | 对应本节的哪个字段/行为 |
|--------|------------------------|
| `Caught SIGINT (1)` | 同一个 handler 被两个信号复用，靠 `sig == SIGINT` 分支区分。`count` 是 `static` 局部变量——handler **不是新线程**，所以它的状态在两次调用间保留（[20.4](20.4-introduction-to-signal-handlers.md)） |
| `Caught SIGQUIT - that's all folks!` | `SIGQUIT` 分支调 `exit()` 结束进程。源码注释标了 `UNSAFE`——`exit()` 会冲刷 stdio、跑 `atexit`，在 handler 里是禁忌（正确做法是 `_exit()`） |
| 之后的「第二次 INT 发不进」 | 进程已退出，后续 `kill` 找不到目标 |

**与 `sigaction()` 的等价改写**：把 `signal(SIGINT, sigHandler)` 换成本节第六节的标准模板即可——`memset(&sa,0,...)`、`sa.sa_handler = sigHandler`、`sigemptyset(&sa.sa_mask)`、`sa.sa_flags = SA_RESTART`，再 `sigaction(SIGINT, &sa, NULL)`。区别在于 `sigaction` 还能顺带控制 `sa_mask`（例如让 handler 期间连 `SIGQUIT` 一起屏蔽）。

**源码坐标**：原书 **Listing 20-2**；`do_sigaction():4123` 的六道校验见 [20.3](20.3-changing-signal-dispositions-signal.md)；`sa_mask` 剔除 `SIGKILL`/`SIGSTOP` 见 `:4161`。

### 二、`siginterrupt.c`（习题 20-4 官方解）

本节表格里 `SA_RESTART` 是重点：它决定被信号中断的慢系统调用**自动重启**还是返回 `EINTR`。`siginterrupt.c` 是官方习题 20-4 的答案——用 `sigaction()` 实现历史上的 `siginterrupt(3)` 库函数，把「读回当前 flags → 按 flag 增删 `SA_RESTART` → 写回」三步完整展示出来，是本节「读回校验」模式的最小范例。

完整源码（[`code/siginterrupt.c`](../code/siginterrupt.c)）：

```c
/*************************************************************************\
*                  Copyright (C) Michael Kerrisk, 2026.                   *
*                                                                         *
* This program is free software. You may use, modify, and redistribute it *
* under the terms of the GNU General Public License as published by the   *
* Free Software Foundation, either version 3 or (at your option) any      *
* later version. This program is distributed without any warranty.  See   *
* the file COPYING.gpl-v3 for details.                                    *
\*************************************************************************/

/* Solution for Exercise 20-4 */

/* siginterrupt.c

   An implementation of the siginterrupt(3) library function.
*/
#include <stdio.h>
#include <signal.h>

int
siginterrupt(int sig, int flag)
{
    int status;
    struct sigaction act;

    status = sigaction(sig, NULL, &act);
    if (status == -1)
        return -1;

    if (flag)
        act.sa_flags &= ~SA_RESTART;
    else
        act.sa_flags |= SA_RESTART;

    return sigaction(sig, &act, NULL);
}
```

编译（macOS 26.6.2 / arm64 · clang 23.1.0，库文件无 `main`，只编译不链接）：

```bash
$CC $D -Wall -Wextra -c siginterrupt.c   # 库文件（无 main），习题 20-4
```

实测输出：该文件**无 `main`、不产生运行输出**（`-c` 只生成目标文件），`code/README.md` 也未收录其输出。它的价值在于源码本身。

**逐条解读**：

| 代码 | 含义 |
|------|------|
| `sigaction(sig, NULL, &act)` | **先读回**当前处置到 `act`（`act = NULL` 时是"只读"语义）——这就是本节「想确认 flag 是否生效必须读回」的同一手法 |
| `if (flag) act.sa_flags &= ~SA_RESTART;` | `siginterrupt(sig, 1)` 表示"要中断"，即**清掉** `SA_RESTART`：被信号打断的慢系统调用返回 `EINTR` |
| `else act.sa_flags |= SA_RESTART;` | `siginterrupt(sig, 0)` 表示"自动重启"，即**加上** `SA_RESTART` |
| `return sigaction(sig, &act, NULL);` | 把改好的 `act` 写回内核 |

**踩坑点**：这个实现**保留了 `act` 里的其他字段**（`sa_handler`、`sa_mask`、其余 flags），只动 `SA_RESTART` 一位——这正是先读回再局部修改的意义。若直接 `memset` 一个新 `struct sigaction` 再写回，会把用户原有的 handler 和掩码全冲掉。另外注意：`SA_RESTART` 只对**可重启的慢系统调用**有效，`select`/`poll`/`epoll_wait`/`connect` 等即使带上它也仍会返回 `EINTR`（见本节自测题 5）。

**源码坐标**：原书 **习题 20-4 官方解**；`SA_RESTART` 语义见 `man 2 sigaction`、`man 7 signal`；内核 flag 过滤 `do_sigaction():4153-4156` 的 `UAPI_SA_FLAGS`。

### 三、教学补充片段（非 `code/`，未实测）

```c
/* sigactiondemo.c —— sa_handler / SA_SIGINFO / 读回验证 flag
 * 编译: gcc -o sigactiondemo sigactiondemo.c */
#define _GNU_SOURCE
#include <signal.h>
#include <stdio.h>
#include <string.h>
#include <unistd.h>

/* ① 简单处理器 */
static void simple_handler(int sig)
{
    const char m[] = "  [simple] caught SIGUSR1\n";
    write(STDOUT_FILENO, m, sizeof m - 1);      /* 用 write，不用 printf */
}

/* ② 带 siginfo 的处理器 */
static void info_handler(int sig, siginfo_t *si, void *ctx)
{
    (void)ctx;
    char buf[128];
    int n = snprintf(buf, sizeof buf,
                     "  [siginfo] signo=%d si_code=%d si_pid=%d si_uid=%d\n",
                     sig, si->si_code, si->si_pid, si->si_uid);
    /* 严格来说 snprintf 不是 async-signal-safe，此处仅作演示 */
    write(STDOUT_FILENO, buf, n);
}

int main(void)
{
    struct sigaction sa;

    /* ① sa_handler + SA_RESTART */
    memset(&sa, 0, sizeof sa);
    sa.sa_handler = simple_handler;
    sigemptyset(&sa.sa_mask);
    sa.sa_flags = SA_RESTART;
    sigaction(SIGUSR1, &sa, NULL);

    /* ② sa_sigaction + SA_SIGINFO（与 sa_handler 互斥！） */
    memset(&sa, 0, sizeof sa);
    sa.sa_sigaction = info_handler;              /* ← 用 sa_sigaction */
    sigemptyset(&sa.sa_mask);
    sa.sa_flags = SA_SIGINFO | SA_RESTART;
    sigaction(SIGUSR2, &sa, NULL);

    raise(SIGUSR1);
    raise(SIGUSR2);

    /* ③ 读回验证：内核是否保留了我们的 flag */
    struct sigaction got;
    sigaction(SIGUSR1, NULL, &got);
    printf("\n读回 SIGUSR1 的 sa_flags=0x%x，SA_RESTART %s\n",
           got.sa_flags, (got.sa_flags & SA_RESTART) ? "已生效" : "丢失");

    /* ④ 验证 sa_mask 里的 SIGKILL 被内核剔除 */
    struct sigaction killmask, verify;
    memset(&killmask, 0, sizeof killmask);
    killmask.sa_handler = simple_handler;
    sigemptyset(&killmask.sa_mask);
    sigaddset(&killmask.sa_mask, SIGKILL);       /* 试图屏蔽 SIGKILL */
    sigaction(SIGTERM, &killmask, NULL);
    sigaction(SIGTERM, NULL, &verify);
    printf("sa_mask 中 SIGKILL %s（被 do_sigaction:4161 静默剔除）\n",
           sigismember(&verify.sa_mask, SIGKILL) ? "存在" : "已剔除");

    return 0;
}
```

## 自测题

<details>
<summary><b>问 1：</b><code>sa_handler</code> 和 <code>sa_sigaction</code> 能同时设置吗？</summary>

**不能**。在 Linux/glibc 上它们是一个 **union** 的两个成员，共用同一块内存：

```c
struct sigaction {
    union {
        void (*sa_handler)(int);
        void (*sa_sigaction)(int, siginfo_t *, void *);
    } __sigaction_handler;
    ...
};
#define sa_handler    __sigaction_handler.sa_handler
#define sa_sigaction  __sigaction_handler.sa_sigaction
```

同时赋值时**后写的覆盖先写的**，行为未定义：

```c
sa.sa_handler = handler;
sa.sa_sigaction = handler_info;   /* ❌ 覆盖了上一行 */
```

**用哪个取决于 `sa_flags`**：

| `sa_flags` | 使用的成员 | 内核调用的函数签名 |
|-----------|-----------|-------------------|
| 无 `SA_SIGINFO` | `sa_handler` | `void handler(int sig)` |
| 有 `SA_SIGINFO` | `sa_sigaction` | `void handler(int sig, siginfo_t *info, void *ucontext)` |

**注意**：POSIX 并不要求它们是 union——某些实现上是独立字段（可共存）。所以「同时设置」的代码**在 Linux 上是 bug，在其他系统上可能"正常"**——这类代码移植时会暴露问题。

</details>

<details>
<summary><b>问 2：</b>初始化 <code>struct sigaction</code> 时有哪些必须做的事？</summary>

**三个必须**：

| # | 必须做的事 | 原因 |
|---|-----------|------|
| ① | **清零结构体**（`memset(&sa, 0, sizeof sa)` 或 `= {0}`） | `sa_flags`、`sa_restorer` 若是垃圾值会导致未定义行为；`sa_restorer` 尤其危险 |
| ② | **`sigemptyset(&sa.sa_mask)`** | `sa_mask` 未初始化会**随机屏蔽信号**，表现为偶发丢信号，极难排查 |
| ③ | **显式设置 `sa_flags`** | 依赖默认值意图不清，且平台间有差异 |

**一个禁止**：

- **不要设置 `sa_restorer`**——它是内核与 libc 之间的内部约定字段，用于 `sigreturn` 蹦床。用户代码设置它会破坏 handler 返回流程。

**标准模板**：

```c
struct sigaction sa = {0};              /* ① 清零（含 sa_restorer） */
sa.sa_handler = handler;                /* 或 sa_sigaction，二选一 */
sigemptyset(&sa.sa_mask);               /* ② 初始化掩码 */
/* sigaddset(&sa.sa_mask, SIGTERM);        按需额外屏蔽 */
sa.sa_flags = SA_RESTART;               /* ③ 显式声明 */
/* 不动 sa_restorer */
sigaction(SIGINT, &sa, NULL);
```

</details>

<details>
<summary><b>问 3：</b>我想确认内核是否支持某个 flag，<code>sigaction()</code> 返回 0 就说明生效了吗？</summary>

**不能这么判断**。`do_sigaction()` 会**静默清除**内核不认识的 flag 位，**不返回错误**：

```c
// kernel/signal.c:4153-4156
	if (act)
		act->sa.sa_flags &= UAPI_SA_FLAGS;      // 未知位被清除
	if (oact)
		oact->sa.sa_flags &= UAPI_SA_FLAGS;
```

`act->sa.sa_flags &= UAPI_SA_FLAGS` 只保留内核识别的位，其余一律抹掉，然后正常返回 0。

**可靠的验证方法**：设置后**读回**内核实际保存的值并比对：

```c
struct sigaction want = {0}, got;
want.sa_handler = handler;
want.sa_flags = SA_RESTART | SOME_NEW_FLAG;
sigaction(SIGINT, &want, NULL);

sigaction(SIGINT, NULL, &got);                  /* 读回 */
if ((got.sa_flags & SOME_NEW_FLAG) == 0)
    fprintf(stderr, "内核不支持 SOME_NEW_FLAG，已被静默丢弃\n");
```

**实践意义**：在需要兼容老内核的程序里，用这个技巧做**运行时特性探测**——比检查内核版本号可靠得多。内核版本号只能说明"理论上支持"，而读回比对说明的是"实际生效了"。

</details>

<details>
<summary><b>问 4：</b><code>sa_mask</code> 里加了 <code>SIGKILL</code> 会怎样？为什么？</summary>

会被**静默剔除，不报错**——handler 执行期间 `SIGKILL` 仍然有效。

`do_sigaction()` 里做了强制过滤（`kernel/signal.c:4161`）：

```c
	if (act) {
		sigdelsetmask(&act->sa.sa_mask,
			      sigmask(SIGKILL) | sigmask(SIGSTOP));
		*k = *act;
		...
	}
```

同样地：

- `sigprocmask()` 也会剔除（通过 `set_current_blocked()`，`:3066`）
- 对 `SIGKILL`/`SIGSTOP` 设置处置会返回 `-EINVAL`（`:4129`，`sig_kernel_only`）

**设计意图**：保证 `kill -9` 与 `kill -STOP` 永远是有效的最后手段。无论进程怎么写（屏蔽全部信号、注册全部 handler），管理员和 watchdog 都能收场。

**三道防线总结**：

| 层 | 行号 | 行为 |
|---|------|------|
| 改处置 | `do_sigaction:4129` | 返回 `-EINVAL` |
| 阻塞（掩码） | `set_current_blocked:3066` | 静默剔除 |
| handler 期间屏蔽 | `do_sigaction:4161` | 静默剔除 |

</details>

<details>
<summary><b>问 5：</b><code>SA_RESTART</code> 是做什么的？所有被信号中断的系统调用都会重启吗？</summary>

`SA_RESTART` 让被信号中断的**慢系统调用自动重启**，用户态看不到 `EINTR`，无需手写重试循环。

**但并非所有系统调用都会重启**——即便设了 `SA_RESTART`，以下情况仍会返回 `EINTR`：

| 类别 | 例子 | 是否重启 |
|------|------|----------|
| **慢系统调用**（可无限期阻塞） | `read` 终端/管道/socket、`write` 管道、`wait`、`pause`、`select`、`poll`、`epoll_wait` | ✅ 重启（设 `SA_RESTART` 后） |
| **带超时的调用** | `select`/`poll`/`epoll_wait` 有 timeout、`sigtimedwait` | ❌ 返回 `EINTR`（超时语义无法自动重启） |
| **`connect`** | `connect()` | ❌ 返回 `EINTR`（即使有 `SA_RESTART`） |
| **`recvmsg`/`sendmsg` 的部分 I/O** | 已传输部分数据 | ❌ 返回已传输字节数 |

**实践规则**：

```c
/* 设了 SA_RESTART 仍要处理 EINTR 的场景 */
ssize_t n;
do {
    n = read(fd, buf, sizeof buf);
} while (n == -1 && errno == EINTR);      /* 防御性写法，永远正确 */
```

**Linux 特有的例外**：`epoll_wait`、`select`、`poll` 即使在 `SA_RESTART` 下也可能返回 `EINTR`，因为它们的 timeout 语义。所以**I/O 多路复用的代码应当总是处理 `EINTR`**。

详见 [Ch21.4 `EINTR` 与 `SA_RESTART`](../../chapter-21-signal-handlers/notes/21.4-the-sa-siginfo-flag.md)。

</details>
