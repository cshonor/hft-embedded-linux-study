# 20.5 发送信号：`kill()`

> 源码核验：Linux v6.6 · `kernel/signal.c`（`SYSCALL_DEFINE2(kill):3807` · `kill_something_info:1604` · `group_send_sig_info:1451` · `kill_pid_info:1486`）

## 本节讲什么

1. `kill()` 的 `pid` 参数有**四种语义**——指定进程、同进程组、广播、指定组 ID，内核怎么区分
2. 为什么 `kill()` **不意味着"杀死"**——它只是发信号，`kill(pid, 0)` 的探测用法
3. 发送信号需要**什么权限**，以及相关接口（`raise`、`killpg`、`tgkill`、`pidfd_send_signal`）该选哪个

---

## 一、接口与 `pid` 的四种语义

```c
#include <signal.h>

int kill(pid_t pid, int sig);
/* 返回：成功 0，失败 -1（并设置 errno） */
```

`pid` 的取值决定了发给谁，这是 `kill()` 最容易用错的地方：

| `pid` | 发给谁 | 内核实现 |
|-------|--------|----------|
| `> 0` | **指定的那个进程**（`pid`） | `kill_proc_info()`（`:1609`） |
| `= 0` | **调用者所在的整个进程组** | `__kill_pgrp_info(..., task_pgrp(current))`（`:1618`） |
| `= -1` | **广播**：除 init（pid 1）和自身外的所有有权限进程 | `for_each_process` 循环（`:1623-1632`） |
| `< -1` | **进程组 `|pid|`** | `__kill_pgrp_info(..., find_vpid(-pid))`（`:1618`） |
| `= INT_MIN` | 未定义，直接 `-ESRCH` | 边界保护（`:1612-1613`，避免 UBSAN 警告） |

内核实现一览（`kernel/signal.c:1604`）：

```c
static int kill_something_info(int sig, struct kernel_siginfo *info, pid_t pid)
{
	int ret;

	if (pid > 0)
		return kill_proc_info(sig, info, pid);        // ①

	/* -INT_MIN is undefined.  Exclude this case to avoid a UBSAN warning */
	if (pid == INT_MIN)
		return -ESRCH;

	read_lock(&tasklist_lock);
	if (pid != -1) {
		ret = __kill_pgrp_info(sig, info,
				pid ? find_vpid(-pid) : task_pgrp(current));   // ②③
	} else {
		int retval = 0, count = 0;
		struct task_struct * p;

		for_each_process(p) {
			if (task_pid_vnr(p) > 1 &&                   // 排除 init(pid 1)
					!same_thread_group(p, current)) {    // 排除自己
				int err = group_send_sig_info(sig, info, p, PIDTYPE_MAX);
				++count;
				if (err != -EPERM)
					retval = err;
			}
		}
		ret = count ? retval : -ESRCH;                   // ④
	}
	read_unlock(&tasklist_lock);

	return ret;
}
```

> **两个容易被忽略的细节**：
> 1. `pid == -1` 广播时**排除了 init（pid 1）和自己**（`task_pid_vnr(p) > 1 && !same_thread_group(p, current)`）——否则一条 `kill(-1, SIGTERM)` 就能把整台机器（包括 init 和你自己的 shell）干掉。
> 2. 广播时如果**至少发给一个进程成功**就返回 0；`-EPERM`（权限不足）会被容忍，只有没有任何目标可发时才返回 `-ESRCH`。

## 二、`kill()` 不等于"杀死"

`kill()` 的准确含义是「**发送信号**」，发送什么信号由 `sig` 决定：

| 写法 | 实际效果 |
|------|----------|
| `kill(pid, SIGTERM)` | 请求优雅终止（默认可被捕获、可忽略）|
| `kill(pid, SIGKILL)` | 强制终止（不可捕获/忽略/阻塞）|
| `kill(pid, SIGUSR1)` | 用户自定义通知——**完全不终止进程** |
| `kill(pid, 0)` | **不发送任何信号**，只做存在性与权限检查 |

### `kill(pid, 0)`：零副作用探针

这是守护进程做健康探测的经典技巧：

```c
if (kill(pid, 0) == -1) {
    if (errno == ESRCH)      /* 进程不存在 */
        printf("进程已退出\n");
    else if (errno == EPERM) /* 进程存在，但无权发信号 */
        printf("进程存在但无权限\n");
    else
        perror("kill");
} else {
    printf("进程存在且有权限\n");
}
```

| `errno` | 含义 |
|---------|------|
| `ESRCH` | 目标进程（或进程组）不存在 |
| `EPERM` | 进程**存在**，但调用者无权向它发信号 |
| `EINVAL` | 信号编号非法 |

> **坑**：`kill(pid, 0)` 有 **PID 复用（PID reuse）** 风险——目标进程退出后 PID 可能被新进程回收，探测会误判为"存活"。可靠的做法是配合 `pidfd`（见下方 `pidfd_send_signal`）。

详见 [20.6 检查进程是否存在](20.6-checking-for-the-existence-of-a-process.md)。

## 三、权限：谁能给谁发信号

内核在 `group_send_sig_info()`（`:1451`）→ `do_send_sig_info()`（`:1304`）链路中做权限校验。规则是：

| 条件 | 可否发送 |
|------|----------|
| 发送者是 root（`CAP_KILL`） | ✅ 任意进程 |
| 发送者的 **real/effective UID == 目标的 real/saved UID** | ✅ |
| Linux 上发送者与目标同属一个进程且目标启用了 `PR_SET_PDEATHSIG` 之类 | 视具体情况 |
| 其他 | ❌ `-EPERM` |

> **规则本质**：普通用户只能给**自己的**进程发信号。这条限制是 Unix 安全模型的基础——否则任何用户都能 `kill -9` 别人的进程。

## 四、相关接口怎么选

| 接口 | 原型 | 用途 | 备注 |
|------|------|------|------|
| `raise()` | `int raise(int sig)` | 发信号给**自己** | 单线程进程 ≈ `kill(getpid(), sig)`；**多线程下只保证发给调用线程**（glibc 用 `tgkill` 实现） |
| `killpg()` | `int killpg(pid_t pgrp, int sig)` | 发给**进程组** | 等价于 `kill(-pgrp, sig)` |
| `tgkill()` | `int tgkill(pid_t tgid, pid_t tid, int sig)` | 发给**指定线程** | `SYSCALL_DEFINE3(tgkill):3988`；需要 tgid+tid 两个 ID |
| `pthread_kill()` | `int pthread_kill(pthread_t t, int sig)` | 发给**本进程内的线程** | POSIX 接口，内部用 `tgkill` |
| `pidfd_send_signal()` | `int pidfd_send_signal(int pidfd, int sig, siginfo_t *info, unsigned flags)` | 经 **pidfd** 发信号 | `SYSCALL_DEFINE4:3882`；**无 PID 复用问题**，容器/守护进程首选 |
| `sigqueue()` | `int sigqueue(pid_t pid, int sig, const union sigval value)` | 发信号**并携带数据** | 仅对实时信号有意义，见 [Ch22.8](../../chapter-22-signals-advanced/notes/22.8-realtime-signals.md) |

### `raise()` 多线程语义（易错）

```c
/* 单线程进程：两者等价 */
kill(getpid(), sig);
raise(sig);

/* 多线程进程：不等价！ */
kill(getpid(), sig);   /* 发给进程，由任一未阻塞线程处理 */
raise(sig);            /* 只保证发给调用线程自己 */
```

glibc 的 `raise()` 用 `tgkill(getpid(), gettid(), sig)` 实现，所以**只发给调用线程**。这在处理多线程同步时是重要区别。

## HFT / 嵌入式关联

| 路线 | 要点 |
|------|------|
| 嵌入式 | `kill(pid, 0)` 不投递只测「进程是否存在/有权限」，是守护进程健康探针的零副作用手段；`killpg` 用于终止整个进程组（如一键清理派生的 worker 子进程）；`kill -TERM` 是嵌入式服务优雅停机的标准入口，配合 handler 做资源释放 |
| HFT | `kill()` 本质是系统调用，有固定开销（~1μs 量级）；HFT 内部线程/进程通知**不应**走信号，应走共享内存原子变量或 eventfd。信号只留给外部运维控制（启停）。另注意：不要用 `kill(pid, 0)` 做高频存活探测——PID 复用会导致误判，应用 pidfd |

## 代码示例：`kill()` 四种 pid 语义 + 零信号探测

```c
/* killdemo.c —— 演示 kill 的 pid 语义与 kill(pid,0) 探测
 * 编译: gcc -o killdemo killdemo.c */
#define _GNU_SOURCE
#include <signal.h>
#include <stdio.h>
#include <unistd.h>
#include <errno.h>
#include <sys/wait.h>

static volatile sig_atomic_t got = 0;
static void handler(int sig) { got = sig; }

/* 用 kill(pid, 0) 探测进程状态 */
static void probe(pid_t pid)
{
    if (kill(pid, 0) == 0) {
        printf("  kill(%d, 0) -> 进程存在且有权限\n", pid);
    } else {
        printf("  kill(%d, 0) -> %s\n", pid,
               errno == ESRCH ? "ESRCH 进程不存在" :
               errno == EPERM ? "EPERM 存在但无权限" : "其他错误");
    }
}

int main(void)
{
    struct sigaction sa = {0};
    sa.sa_handler = handler;
    sigemptyset(&sa.sa_mask);
    sa.sa_flags = SA_RESTART;
    sigaction(SIGUSR1, &sa, NULL);

    /* ① pid > 0：发给自己 */
    kill(getpid(), SIGUSR1);
    printf("1) kill(getpid(), SIGUSR1) -> got=%d\n", got);

    /* ② raise() 等价于发给自己 */
    got = 0;
    raise(SIGUSR1);
    printf("2) raise(SIGUSR1) -> got=%d\n", got);

    /* ③ 零信号探测 */
    printf("3) 零信号探测:\n");
    probe(getpid());                      /* 存在 */
    probe(999999);                        /* 几乎必然不存在 → ESRCH */

    /* ④ pid = 0：发给同进程组（含自己） */
    got = 0;
    kill(0, SIGUSR1);
    printf("4) kill(0, SIGUSR1) 同进程组 -> got=%d\n", got);

    /* ⑤ pid < -1：发给指定进程组 */
    pid_t pgid = getpgrp();
    got = 0;
    kill(-pgid, SIGUSR1);
    printf("5) kill(-%d, SIGUSR1) 进程组 -> got=%d\n", pgid, got);

    /* ⑥ 子进程退出后探测：演示 PID 复用风险 */
    pid_t cpid = fork();
    if (cpid == 0) { _exit(0); }
    waitpid(cpid, NULL, 0);
    printf("6) 子进程 %d 已 wait 回收，探测: ", cpid);
    probe(cpid);

    return 0;
}
```

## 自测题

<details>
<summary><b>问 1：</b><code>kill()</code> 的 <code>pid</code> 四种取值分别发给谁？内核在什么位置实现这个分派？</summary>

| `pid` | 发给谁 |
|-------|--------|
| `> 0` | 指定的那个进程 |
| `= 0` | 调用者所在的**整个进程组** |
| `= -1` | **广播**：除 init（pid 1）和自身外的所有有权限进程 |
| `< -1` | 进程组 `|pid|` |

内核实现在 `kill_something_info()`（`kernel/signal.c:1604`），由 `SYSCALL_DEFINE2(kill)`（`:3807`）调用：

```c
if (pid > 0)
    return kill_proc_info(sig, info, pid);
...
if (pid != -1) {
    ret = __kill_pgrp_info(sig, info, pid ? find_vpid(-pid) : task_pgrp(current));
} else {
    for_each_process(p) { ... }          /* 广播 */
}
```

注意 `pid ? find_vpid(-pid) : task_pgrp(current)` 这一行用三元表达式同时处理了 `= 0` 和 `< -1` 两种情况。

</details>

<details>
<summary><b>问 2：</b><code>kill(-1, SIGTERM)</code> 会把 init 进程和自己杀掉吗？为什么？</summary>

**都不会**，内核显式排除了这两类目标：

```c
for_each_process(p) {
    if (task_pid_vnr(p) > 1 &&                  // 排除 init（pid 1）
            !same_thread_group(p, current)) {   // 排除自己
        int err = group_send_sig_info(sig, info, p, PIDTYPE_MAX);
        ...
    }
}
```

（`kernel/signal.c:1623-1632`）

- **`task_pid_vnr(p) > 1`**：跳过 pid 1（init/systemd）。如果连 init 都能杀，一条命令就能让系统崩溃。
- **`!same_thread_group(p, current)`**：跳过调用者自己的线程组。否则 `kill(-1, SIGTERM)` 的第一个受害者就是发信号的 shell 自己，命令永远执行不完。

**所以普通用户执行 `kill -TERM -1` 只会杀掉自己有权限的那些进程**——仍然很危险（会杀掉自己的所有登录会话和图形界面），但不至于让系统立即崩溃。

</details>

<details>
<summary><b>问 3：</b><code>kill(pid, 0)</code> 发送了什么？怎么用它区分「进程不存在」和「无权限」？</summary>

**什么都没发送**——信号 0 是空信号，内核只做查找和权限检查，不投递任何东西。

区分方法看 `errno`：

```c
if (kill(pid, 0) == -1) {
    if (errno == ESRCH)       /* 进程不存在 */
        ...
    else if (errno == EPERM)  /* 进程存在，但无权发信号 */
        ...
}
```

- `ESRCH` → 目标不存在
- `EPERM` → **目标存在**（这一点很关键，说明进程活着，只是你无权给它发信号）

**主要缺陷**：**PID 复用**——目标进程退出后，其 PID 可能被新进程回收重用，此时 `kill(pid, 0)` 会返回成功，误判为"原进程还活着"。

**可靠替代**：用 `pidfd_open(pid)` 拿到 pidfd，再用 `pidfd_send_signal(pidfd, 0, NULL, 0)` 探测。pidfd 是对进程对象的**稳定引用**，不受 PID 复用影响。

</details>

<details>
<summary><b>问 4：</b>多线程进程里，<code>raise(sig)</code> 和 <code>kill(getpid(), sig)</code> 有什么区别？</summary>

| 调用 | 语义 |
|------|------|
| `raise(sig)` | 只保证发给**调用线程自己**（glibc 用 `tgkill(getpid(), gettid(), sig)` 实现） |
| `kill(getpid(), sig)` | 发给**整个进程**，由**任意一个**未阻塞该信号的线程执行 handler |

**在单线程进程里两者等价**（进程只有一个线程，发给谁都一样）。

**在多线程进程里差异明显**：`kill(getpid(), sig)` 可能由完全不相关的线程执行 handler，执行的上下文（栈、TLS、锁状态）不可控。

**实践建议**：
- 想让**特定线程**处理信号 → 用 `pthread_kill(thread, sig)` 或 `tgkill(tgid, tid, sig)`
- 想让**整个进程**收到一次通知 → 用 `kill(getpid(), sig)`，但要注意 handler 由哪个线程跑是不确定的
- 最稳妥的多线程方案：主线程屏蔽所有关心的信号，起一个专用线程用 `sigwaitinfo()` 同步消费（[Ch22.10](../../chapter-22-signals-advanced/notes/22.10-synchronously-waiting-for-a-signal.md)）

</details>

<details>
<summary><b>问 5：</b>为什么容器/守护进程里推荐用 <code>pidfd_send_signal()</code> 而不是 <code>kill()</code>？</summary>

核心原因是 **`kill()` 存在 PID 复用（PID reuse）竞态**：

```
时间线：
  t0: 监控进程读取子进程 PID = 1234
  t1: 子进程 1234 退出
  t2: 内核回收 PID 1234，分配给一个完全无关的新进程
  t3: 监控进程调用 kill(1234, SIGTERM)  → 杀错了进程！
```

PID 是**复用资源**（默认上限 `/proc/sys/kernel/pid_max`，通常 32768 或更大，回绕很快），用它做长期身份标识本质上不安全。

`pidfd` 是对**进程对象**的文件描述符引用，只要 fd 不关，内核就持有该 `struct pid` 的引用，不会被复用：

```c
int pidfd = pidfd_open(pid, 0);              /* 获取稳定引用 */
...
pidfd_send_signal(pidfd, SIGTERM, NULL, 0);  /* 绝不会杀错 */
/* 还可以 poll(pidfd) 等待进程退出 */
```

内核实现在 `SYSCALL_DEFINE4(pidfd_send_signal)`（`kernel/signal.c:3882`）。

**适用场景**：容器 runtime（runc、containerd）、systemd、进程监控/supervisor、任何需要长期持有子进程引用的守护程序。

</details>
