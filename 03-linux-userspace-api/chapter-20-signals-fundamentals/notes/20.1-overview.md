## 本节讲什么

信号 = 内核发给进程的**异步通知**。处置： **例外：** `SIGKILL`、`SIGSTOP` — 不能捕获、忽略、阻塞。 终端（`SIGINT`/`SIGTSTP`）· 内核异常（`SIGSEGV`/`SIGFPE`/`SIGPIPE`）· `kill`/`raise`/`sigqueue` · 定时器（`SIGALRM`）等。

---

## 要点

信号 = 内核发给进程的**异步通知**。处置：

| 处置 | 行为 |
|------|------|
| 默认 | 终止 / core / 停止 / 继续 / 忽略（因信号而异） |
| 忽略 | 丢弃 |
| 捕获 | 调自定义 handler |

**例外：** `SIGKILL`、`SIGSTOP` — 不能捕获、忽略、阻塞。

### 来源

终端（`SIGINT`/`SIGTSTP`）· 内核异常（`SIGSEGV`/`SIGFPE`/`SIGPIPE`）· `kill`/`raise`/`sigqueue` · 定时器（`SIGALRM`）等。

## 与 C 语言学习的关系

`kill` 发送信号看似简单，但涉及 C 语言的进程权限模型。`kill(pid, 0)` 的探测用法需要理解 C 语言的返回值约定（0 成功，-1 失败）和 errno 机制。

## 常见陷阱

1. **kill 不等于杀死**

```c
kill(pid, SIGTERM);  /* 发送 SIGTERM，不是杀死 */
```

kill 是"发送信号"，不是"杀死进程"。SIGTERM 可以被捕获和处理。只有 SIGKILL 才强制杀死。

2. **权限不足**

```c
kill(other_pid, SIGTERM);  /* EPERM if not owner */
```

只能给自己同 UID 的进程发信号（root 除外）。权限不足返回 -1，errno=EPERM。

3. **pid 参数含义**

```c
kill(0, sig);   /* 发给同进程组 */
kill(-1, sig);  /* 发给所有有权限的 */
kill(-pgid, sig); /* 发给进程组 */
```

pid 的正/负/零含义不同。用错可能误发信号给不该收的进程。

## 自测题

**题目 1（选择）：** `kill(pid, 0)` 的作用是？
A. 杀死进程
B. 发送信号 0
C. 检查进程是否存在/是否有权限
D. 无操作

<details>
<summary>参考答案</summary>

C。信号 0 不实际发送信号，但会进行权限检查。返回 0 表示进程存在且有权限，-1 表示不存在或无权限。

</details>

**题目 2（判断）：** `kill(getpid(), SIGKILL)` 等价于 `exit()`。

<details>
<summary>参考答案</summary>

错误。SIGKILL 不会执行 atexit 处理器、不会 flush stdio 缓冲、不会做资源清理。exit() 会执行清理。

</details>

**题目 3（踩坑）：** 以下代码有什么风险？
```c
pid_t pid = fork();
if (pid == 0) {
    /* child */
    sleep(100);
}
kill(pid, SIGTERM);  /* 父进程发信号 */
```

<details>
<summary>参考答案</summary>

如果 fork 失败（返回 -1），pid=-1，kill(-1, SIGTERM) 会给所有有权限的进程发信号！必须先检查 fork 返回值。

</details>

**题目 4（应用）：** 写代码：给指定进程发 SIGTERM，等 1 秒后如果还没退出则发 SIGKILL。

<details>
<summary>参考答案</summary>

```c
kill(pid, SIGTERM);
sleep(1);
if (waitpid(pid, NULL, WNOHANG) == 0) {
    kill(pid, SIGKILL);
    waitpid(pid, NULL, 0);
}
```

</details>
