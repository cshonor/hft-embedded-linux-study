## 练习 1：写一个「正确」的 `sigaction` 安装函数

要求：显式 `sa_flags`、显式初始化 `sa_mask`、**安装后读回校验**。

<details>
<summary>参考答案</summary>

```c
#include <signal.h>
#include <string.h>
#include <stdio.h>

/* 返回 0 成功 / -1 失败。flags 必须【显式】传入，不接受"默认" */
int install_handler(int sig, void (*h)(int), int flags)
{
    struct sigaction sa, verify;

    /* ① 清零：栈上 struct sigaction 未初始化时 sa_mask 是垃圾位 */
    memset(&sa, 0, sizeof(sa));

    sa.sa_handler = h;              /* 注意：与 sa_sigaction 是 union，不能同时赋值 */
    sigemptyset(&sa.sa_mask);       /* ② 显式初始化，双保险 */
    sa.sa_flags   = flags;          /* ③ 显式，不依赖默认值 */

    if (sigaction(sig, &sa, NULL) == -1)
        return -1;

    /* ④ 读回校验 —— 内核会【静默清除】未识别的 flag 而不报错
     *    (do_sigaction():4153-4156)，唯一可靠的验证手段就是读回比对 */
    if (sigaction(sig, NULL, &verify) == -1)
        return -1;

    if (verify.sa_handler != h)
        return -1;                                    /* 被别人覆盖了 */
    if ((verify.sa_flags & flags) != (unsigned)flags)
        return -1;                                    /* flag 被内核吞了 */

    return 0;
}
```

**四个必做动作的理由**：

| # | 动作 | 漏了会怎样 |
|---|------|-----------|
| ① | `memset(&sa, 0, sizeof(sa))` | `sa_mask` 是栈垃圾 → 随机阻塞一堆信号，表现为「程序偶发卡死」 |
| ② | `sigemptyset(&sa.sa_mask)` | 同上（双保险：即使换了编译器/结构体布局也安全） |
| ③ | 显式传 `flags` | POSIX 默认**不**自动重启系统调用；BSD 老代码假定会自动重启 → 迁移时漏 `SA_RESTART` 会偶发 `EINTR` |
| ④ | 读回校验 | 内核静默吞 flag（`:4153-4156`）；第三方库可能在构造函数里覆盖你的处置 |

**`SA_RESTART` 要不要给？** 取决于你的调用类型：

| 调用 | `SA_RESTART` 有效？ | 说明 |
|------|---------------------|------|
| `read` / `write` / `recv` / `send`（阻塞 fd） | ✅ | 自动重启 |
| `open` / `fcntl` / `ioctl` | ✅ | 自动重启 |
| `wait` / `waitpid` | ✅ | 自动重启 |
| `select` / `poll` / `epoll_wait` | ❌ | 内核层面就不重启，必返 `EINTR` |
| `nanosleep` / `clock_nanosleep` | ❌ | 返 `EINTR`，需用 `rem` 续睡 |
| `connect` | ❌ | 返 `EINTR`（且不能重启连接） |
| `close` | ⚠️ **特例** | Linux 上返 `EINTR` 时 **fd 已关闭，绝不能重试** |

详见 [Ch21.5](../../chapter-21-signal-handlers/notes/21.5-interruption-and-restarting-of-system-ca.md)。

</details>

## 练习 2：`kill(pid, 0)` 探测进程存在的三个陷阱

`kill(pid, 0)` 常被用来判断「某进程是否还活着」。写出它失效的三种场景，并给出更可靠的方案。

<details>
<summary>参考答案</summary>

`kill(pid, 0)` 是**零信号探针**：发信号编号 0，内核走完权限检查就把信号丢弃，不实际递送。

```c
/* kernel/signal.c:3807 → kill_something_info():1604 → kill_pid_info():1486 */
static int kill_pid_info(int sig, struct kernel_siginfo *info, pid_t pid)
{
	...
	p = pid_task(pid, PIDTYPE_PID);        /* ← 只查 PID 哈希表 */
	if (!p)
		return -ESRCH;                 /* ← 唯一的"不存在"判据 */
	...
}
```

**陷阱一：僵尸进程返回「成功」**

`pid_task()` 只查 PID 哈希表，**不看进程状态**。子进程 `exit()` 后、父进程 `wait()` 之前，它的 `task_struct` 还在表里：

```
  子进程 exit()
      ↓
  变僵尸（task_struct 仍在 PID 哈希表）
      ↓
  父进程 kill(pid, 0) → 返回 0「活着」  ← 假阳性！
      ↓
  父进程 wait() → task_struct 释放 → 之后才返回 -ESRCH
```

**陷阱二：PID 复用**

```
  时刻 t0:  PID 1234 = 目标进程
  时刻 t1:  目标进程退出，PID 1234 释放
  时刻 t2:  新进程被分配到 PID 1234
  时刻 t3:  kill(1234, 0) → 返回 0「活着」—— 但已不是原来那个
```

如果探测是为了「决定是否给它发控制信号」，这两步之间的间隙足以让你**把信号发给错误的进程**。

**陷阱三：权限不足也返回 `-ESRCH`**

`kill()` 对「存在但无权发信号」的进程返回 **`-EPERM`**，但对某些跨命名空间/隐藏进程的情况会返回 `-ESRCH`。反过来，容器里 PID 命名空间会让 PID 语义被翻译（`task_pid_vnr()` 返回调用者可见的 PID）。所以 `errno` 必须严格区分：

```c
int proc_alive(pid_t pid)
{
    if (kill(pid, 0) == 0)
        return 1;                    /* 存在（可能是僵尸）*/
    switch (errno) {
    case ESRCH: return 0;            /* 确实不存在 */
    case EPERM: return 1;            /* 存在，只是你没权限 */
    default:    return -1;           /* 其他错误 */
    }
}
```

**更可靠的方案对比**：

| 方案 | 能识别僵尸？ | 能防 PID 复用？ | 备注 |
|------|-------------|-----------------|------|
| `kill(pid, 0)` | ❌ | ❌ | 最快，适合「尽力而为」的场景 |
| 读 `/proc/PID/stat` 第 3 字段状态字符 | ✅（`Z` = 僵尸） | ❌ | 需要 `/proc`；`state` 字段含空格要按 `)` 后取 |
| **`pidfd_open(pid)` + `pidfd_send_signal()`** | ✅ | ✅ | **首选**。Linux 5.1+；fd 持有 `task_struct` 引用，PID 循环复用也不会串 |
| `prctl(PR_SET_PDEATHSIG, sig)` | — | — | 反向：让**父进程死时**子进程自动收信号，防孤儿 |

```c
/* pidfd 方案（推荐）*/
int pfd = pidfd_open(pid, 0);
if (pfd == -1)
    return (errno == ESRCH) ? 0 : -1;      /* 真不存在 or 出错 */

/* 之后所有操作都用 pfd，不用 pid：
 *   pidfd_send_signal(pfd, SIGTERM, NULL, 0) —— 绝不会发给复用的新进程
 *   poll(pfd, POLLIN)                        —— 进程退出时 fd 可读，可直接进 epoll
 */
close(pfd);
```

**`PR_SET_PDEATHSIG` 的竞态**：它只盯「调用瞬间的父进程」。如果父进程在你调 `prctl` 之前就死了，`prctl` 不会补发信号——所以正确顺序是「先 `prctl`，再检查 `getppid()`」：

```c
prctl(PR_SET_PDEATHSIG, SIGTERM);
if (getppid() != original_parent_pid)     /* 父进程已经死了 */
    raise(SIGTERM);                       /* 自己补上 */
```

详见 [Ch20.6](./20.6-checking-for-the-existence-of-a-process.md)。

</details>

## 练习 3：写一个程序验证「标准信号不排队」

<details>
<summary>参考答案</summary>

```c
/* nostack_queue.c —— 验证标准信号 vs 实时信号的排队差异
 * 编译: gcc -Wall -Wextra -O2 -o noqueue noqueue.c
 * 运行: ./noqueue
 */
#define _GNU_SOURCE
#include <stdio.h>
#include <stdlib.h>
#include <signal.h>
#include <unistd.h>
#include <errno.h>
#include <string.h>

static volatile sig_atomic_t std_count  = 0;
static volatile sig_atomic_t rt_count   = 0;

static void on_std(int sig) { (void)sig; std_count++; }
static void on_rt (int sig) { (void)sig; rt_count++;  }

int main(void)
{
    struct sigaction sa;
    sigset_t set;

    memset(&sa, 0, sizeof(sa));
    sa.sa_handler = on_std;
    sigemptyset(&sa.sa_mask);
    sa.sa_flags = 0;
    sigaction(SIGUSR1, &sa, NULL);          /* 标准信号 */

    memset(&sa, 0, sizeof(sa));
    sa.sa_handler = on_rt;
    sigemptyset(&sa.sa_mask);
    sa.sa_flags = 0;
    sigaction(SIGRTMIN, &sa, NULL);         /* 实时信号（Linux 上 = 34）*/

    /* ① 阻塞两者，攒 5 个 */
    sigemptyset(&set);
    sigaddset(&set, SIGUSR1);
    sigaddset(&set, SIGRTMIN);
    sigprocmask(SIG_BLOCK, &set, NULL);

    for (int i = 0; i < 5; i++) {
        kill(getpid(), SIGUSR1);            /* 标准：位图，只留 1 个 */
        kill(getpid(), SIGRTMIN);           /* 实时：队列，留 5 个   */
    }

    /* ② 看看 pending 里到底有几个 */
    sigset_t pend;
    sigpending(&pend);
    printf("阻塞期间: SIGUSR1 pending=%d, SIGRTMIN pending=%d\n",
           sigismember(&pend, SIGUSR1), sigismember(&pend, SIGRTMIN));
    printf("  → 标准信号是【位图】，pending 只能看出"有/无"，看不出几个\n");

    /* ③ 解除阻塞，数 handler 被调了几次 */
    sigprocmask(SIG_UNBLOCK, &set, NULL);

    printf("解除阻塞后: SIGUSR1 handler 跑 %d 次, SIGRTMIN handler 跑 %d 次\n",
           std_count, rt_count);
    printf("  → 标准信号 5 次只递送 1 次；实时信号 5 次递送 5 次\n");

    return 0;
}
```

**预期输出**：

```
阻塞期间: SIGUSR1 pending=1, SIGRTMIN pending=1
  → 标准信号是【位图】，pending 只能看出"有/无"，看不出几个
解除阻塞后: SIGUSR1 handler 跑 1 次, SIGRTMIN handler 跑 5 次
  → 标准信号 5 次只递送 1 次；实时信号 5 次递送 5 次
```

**根源是三行代码**（`kernel/signal.c:1079`）：

```c
static bool legacy_queue(struct sigpending *signals, int sig)
{
	return (sig < SIGRTMIN) && sigismember(&signals->signal, sig);
	/*      ^^^^^^^^^^^^^^^^   ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^ */
	/*      只有标准信号才检查    位图里已经有了 → 返回 true → 丢弃 */
}
```

```
  标准信号 pending = 位图        实时信号 pending = 链表队列
  ┌──────────────────┐          ┌────┐  ┌────┐  ┌────┐
  │ bit 10 (SIGUSR1) │ = 1      │#1  │→ │#2  │→ │#3  │→ ...
  │ bit 15 (SIGTERM) │ = 0      └────┘  └────┘  └────┘
  │ ...              │           每个带自己的 siginfo（含 sigqueue 的载荷）
  └──────────────────┘
   一个 bit 只能记"有/无"          可以排 N 个（受 RLIMIT_SIGPENDING 限制）
```

**最经典的后果——`SIGCHLD` 漏收**：

```c
/* ✗ 错：三个子进程同时退出只递送一次 → 剩下两个永久僵尸 */
static void on_child(int sig) { waitpid(-1, NULL, WNOHANG); }

/* ✓ 对：循环回收 */
static void on_child(int sig)
{
    int saved = errno;
    (void)sig;
    while (waitpid(-1, NULL, WNOHANG) > 0)
        ;
    errno = saved;                 /* handler 必须保护 errno */
}
```

</details>

## 练习 4：用实验区分「阻塞」与「忽略」

<details>
<summary>参考答案</summary>

```c
/* block_vs_ignore.c —— 阻塞 vs 忽略的可观测差异
 * 编译: gcc -Wall -Wextra -O2 -o bvi bvi.c
 * 运行: ./bvi ; 在 5 秒窗口内按 Ctrl-C（或另开终端 kill -INT <pid>）
 */
#define _GNU_SOURCE
#include <stdio.h>
#include <signal.h>
#include <unistd.h>
#include <string.h>

static volatile sig_atomic_t got = 0;
static void on_int(int sig) { (void)sig; got = 1; }

int main(void)
{
    struct sigaction sa;
    sigset_t block, pend, orig;

    memset(&sa, 0, sizeof(sa));
    sa.sa_handler = on_int;
    sigemptyset(&sa.sa_mask);
    sa.sa_flags = 0;
    sigaction(SIGINT, &sa, NULL);

    /* ===== 实验 A：阻塞 ===== */
    printf("=== A. 阻塞 SIGINT 5 秒（现在是按 Ctrl-C 的窗口）===\n");
    fflush(stdout);

    sigemptyset(&block);
    sigaddset(&block, SIGINT);
    sigprocmask(SIG_BLOCK, &block, &orig);        /* 阻塞 */

    for (int i = 5; i > 0; i--) {
        printf("  %d...\n", i); fflush(stdout);
        sleep(1);
    }

    sigpending(&pend);                            /* ← 关键：能查到！*/
    printf("  sigpending(SIGINT) = %d   ← 信号【留在 pending 队列里】\n",
           sigismember(&pend, SIGINT));

    sigprocmask(SIG_SETMASK, &orig, NULL);        /* 解除阻塞 → 立即递送 */
    printf("  解除阻塞后 got=%d  ← 信号现在才递送，handler 才跑\n", got);

    /* ===== 实验 B：忽略 ===== */
    printf("\n=== B. 忽略 SIGINT 5 秒（再按 Ctrl-C）===\n");
    fflush(stdout);

    got = 0;
    memset(&sa, 0, sizeof(sa));
    sa.sa_handler = SIG_IGN;                      /* ← 忽略 */
    sigemptyset(&sa.sa_mask);
    sa.sa_flags = 0;
    sigaction(SIGINT, &sa, NULL);

    for (int i = 5; i > 0; i--) {
        printf("  %d...\n", i); fflush(stdout);
        sleep(1);
    }

    sigpending(&pend);
    printf("  sigpending(SIGINT) = %d   ← 信号被【直接丢弃】，查不到\n",
           sigismember(&pend, SIGINT));
    printf("  got=%d  ← handler 永远不会跑\n", got);

    return 0;
}
```

**预期输出（A 段按了 Ctrl-C）**：

```
=== A. 阻塞 SIGINT 5 秒 ===
  5...  ← 此处按 Ctrl-C
  4... 3... 2... 1...
  sigpending(SIGINT) = 1   ← 信号【留在 pending 队列里】
  解除阻塞后 got=1          ← 信号现在才递送

=== B. 忽略 SIGINT 5 秒 ===
  ...（按 Ctrl-C 毫无反应）
  sigpending(SIGINT) = 0   ← 直接丢弃
  got=0
```

**对照表**：

| | 阻塞（`sigprocmask`） | 忽略（`SIG_IGN`） |
|---|---|---|
| 信号去了哪 | 进 pending 队列 | **直接丢弃** |
| `sigpending()` 能看到 | ✅ | ❌ |
| 解除后 | 立即递送 | 永远不会递送 |
| 存储位置 | `task_struct.blocked` 位图（**线程私有**） | `sighand->action[].sa_handler`（**进程共享**） |
| 内核判据 | `sig_task_ignored():81` 先看 blocked | 再看 `sig_handler_ignored():74` |

```c
/* kernel/signal.c:81 */
static bool sig_task_ignored(struct task_struct *t, int sig, bool force)
{
	if (sigismember(&t->blocked, sig) || sigismember(&t->real_blocked, sig))
		return false;               /* 阻塞的：不算"忽略"，留着等解除 */

	if (t->ptrace && sig != SIGKILL)
		return true;

	return sig_handler_ignored(sig_handler(t, sig), sig, force);
	/*                          ^^^^^^^^^^^^^^^^^^^^ SIG_IGN → 真忽略 */
}
```

**作用域差异也很关键**（这是最容易搞混的一点）：

| | 作用域 | 存储 |
|---|---|---|
| 掩码（阻塞） | **线程私有** | `task_struct.blocked` |
| 处置（handler / 忽略） | **进程共享** | `sighand->action[]`（所有线程同一份） |
| 备用栈 | **线程私有** | `task_struct.sas_ss_*` |

所以「主线程设 `SIG_IGN`，worker 线程的信号也被忽略」，但「主线程阻塞 SIGINT，worker 线程照样收到 SIGINT」。

## 练习 5：为什么 `volatile sig_atomic_t` 两个限定符缺一不可

<details>
<summary>参考答案</summary>

`volatile` 和 `sig_atomic_t` 解决的**是两个完全不同的问题**：

| 限定符 | 解决什么 | 不解决什么 |
|--------|----------|-----------|
| `sig_atomic_t` | **原子性**：读写不会被信号打断成"半写状态" | 不阻止编译器优化 |
| `volatile` | **可见性**：阻止编译器把值缓存在寄存器里 | 不保证原子性 |

### 少了 `volatile`：主循环永远看不到变化

```c
static sig_atomic_t flag = 0;        /* ← 没有 volatile */

static void handler(int sig) { flag = 1; }

int main(void)
{
    signal(SIGINT, handler);
    while (!flag) {                  /* ← 编译器认为 flag 在本循环里没人改 */
        do_work();                   /*    于是优化成：读一次到寄存器，之后永不重读 */
    }                                /*    → 死循环，信号永远"收不到" */
    return 0;
}
```

编译器生成的等价代码：

```c
    int r = flag;            /* 只读一次内存 */
    while (!r) {             /* 之后只读寄存器 */
        do_work();
    }                        /* handler 改的是内存，寄存器里的 r 永远是 0 */
```

### 少了 `sig_atomic_t`：读到"半写状态"

如果用一个 8 字节的 `long long`（在 32 位平台上），写操作不是原子的：

```
  信号在"写了一半"时到达：

  flag = 0x00000000_FFFFFFFF   ← 想写这个值
         ↓
  步骤 1: 写低 32 位 → 0x00000000_FFFFFFFF (低半已更新)
         ↓  ← 信号在这里到达，handler 读了 flag
  步骤 2: 写高 32 位 → 0x00000000_FFFFFFFF (高半已更新)

  handler 读到的是：0x00000000_FFFFFFFF  ✗ 既不是旧值也不是新值
```

`sig_atomic_t` 的保证是：**对该类型的读写不会被信号打断**。在 Linux 上它就是 `int`（4 字节对齐，单条指令完成）。

> ⚠️ `sig_atomic_t` 只保证**读写本身**原子，**不**保证 `flag++` 这种读-改-写序列原子。
> handler 里只能做「赋一个常量值」，不能做 `++`、不能做复合判断。

### 正确写法

```c
static volatile sig_atomic_t flag = 0;      /* ← 两个都要 */

static void handler(int sig)
{
    (void)sig;
    flag = 1;                               /* 只赋值，不 ++ */
}

int main(void)
{
    struct sigaction sa = {0};
    sa.sa_handler = handler;
    sigemptyset(&sa.sa_mask);
    sa.sa_flags = 0;
    sigaction(SIGINT, &sa, NULL);

    while (!flag)
        do_work();

    printf("收到停止请求\n");
    return 0;
}
```

### 多线程场景要升级

`volatile sig_atomic_t` **只对「单线程 + 信号 handler」有效**。多线程下要用 C11 原子：

```c
#include <stdatomic.h>
static atomic_int flag = 0;                 /* 或 atomic_flag */

static void handler(int sig) { (void)sig; atomic_store(&flag, 1); }
/* 主循环： while (atomic_load(&flag) == 0) do_work(); */
```

不过更推荐的架构是**根本不让 worker 线程收信号**——main 里阻塞全部，起一个专用线程 `sigwaitinfo`（见 [Ch22.10](../../chapter-22-signals-advanced/notes/22.10-synchronously-waiting-for-a-signal.md)），那就完全不需要考虑原子性了。

</details>

## 练习 6：为什么 handler 里加锁会自我死锁

<details>
<summary>参考答案</summary>

**根本原因：信号 handler 不是新线程，它在被中断线程的【同一个栈】上执行，与主流程共享全部状态。**

```
  正常的线程死锁（需要两个线程）：
      线程 A 持有锁 L ──→ 等线程 B
      线程 B 等锁 L   ──→ 等线程 A
      
  信号的自我死锁（【一个线程】就够）：
      线程 A 主流程：lock(L) ... 临界区 ... unlock(L)
                        │
                        ├─ 信号在【持有 L 期间】到达
                        ▼
                     handler 跑起来（同一个线程、同一个栈）
                        │
                        └─ handler 调 lock(L) ──→ L 已经被"自己"持有
                                                  → 永远等不到
```

关键：**线程不会因为在自己栈上跑 handler 而"变成另一个执行实体"**。`pthread_mutex_lock()` 检查的是「owner 是不是我」——而 owner 就是我，但非递归锁不管这个，它只看「锁是否被持有」，于是自己等自己。

### 复现代码

```c
/* self_deadlock.c —— 演示 handler 加锁导致的自我死锁
 * 编译: gcc -Wall -Wextra -O2 -pthread -o self_deadlock self_deadlock.c
 * 运行: timeout 10 ./self_deadlock ; echo "exit=$? (124=超时=死锁)"
 */
#define _GNU_SOURCE
#include <stdio.h>
#include <signal.h>
#include <pthread.h>
#include <unistd.h>
#include <string.h>

static pthread_mutex_t g_lock = PTHREAD_MUTEX_INITIALIZER;
static volatile sig_atomic_t counter = 0;

static void handler(int sig)
{
    (void)sig;
    /* ✗ 致命：主流程可能正持有 g_lock */
    pthread_mutex_lock(&g_lock);      /* ← 自己等自己 */
    counter++;
    pthread_mutex_unlock(&g_lock);
}

int main(void)
{
    struct sigaction sa;
    memset(&sa, 0, sizeof(sa));
    sa.sa_handler = handler;
    sigemptyset(&sa.sa_mask);
    sa.sa_flags = 0;
    sigaction(SIGUSR1, &sa, NULL);

    printf("pid=%d\n", (int)getpid());

    for (;;) {
        pthread_mutex_lock(&g_lock);
        /* 临界区里【故意停留】，让信号有充分的到达窗口 */
        for (volatile long i = 0; i < 20000000L; i++)
            ;
        pthread_mutex_unlock(&g_lock);
        printf("  counter=%d\n", counter); fflush(stdout);
    }
    return 0;
}
```

运行后另开终端 `kill -USR1 <pid>`，主循环会**永久卡住**（`timeout 10` 退出码 124）。

### 三种修法

```c
/* 方案 A（最常用）：handler 什么都不锁，只置标志 */
static volatile sig_atomic_t need_work = 0;
static void handler(int sig) { (void)sig; need_work = 1; }
/* 主循环在【安全点】检查 need_work，在锁外处理 */

/* 方案 B：阻塞信号进入临界区（sigprocmask / pthread_sigmask）*/
static void critical_section(void)
{
    sigset_t block, old;
    sigemptyset(&block);
    sigaddset(&block, SIGUSR1);
    pthread_sigmask(SIG_BLOCK, &block, &old);     /* 进临界区前阻塞 */

    pthread_mutex_lock(&g_lock);
    /* ... 临界区 ... */
    pthread_mutex_unlock(&g_lock);

    pthread_sigmask(SIG_SETMASK, &old, NULL);     /* 恢复 */
}

/* 方案 C（架构级，推荐）：根本不让 worker 收信号 */
/*   main:        pthread_sigmask(SIG_BLOCK, {全部})
 *   sigwaitinfo 线程: 同步取信号 → 普通同步代码，可随便加锁
 *   worker 线程:      继承阻塞掩码，天然不受打扰  */
```

**方案 C 是 HFT 系统的标准做法**（见 [Ch22.10](../../chapter-22-signals-advanced/notes/22.10-synchronously-waiting-for-a-signal.md)）：worker 线程永远不会被信号打断，延迟分布干净，且信号线程里是**普通同步代码**，可以随意加锁、调库、用 `printf`。

**异步信号安全函数的完整清单**：`man 7 signal-safety`。简单记忆规则——只有「底层 syscall 的直接包装」才安全（`write` / `read` / `_exit` / `kill` / `sigprocmask`），任何带内部状态/锁/缓冲区的（`printf` / `malloc` / `free` / `exit` / 大部分 `str*`）都不安全。

</details>

## 练习 7：验证 `SIGKILL` / `SIGSTOP` 的三道防线

`SIGKILL` 和 `SIGSTOP` 无法被捕获、忽略、阻塞。写出验证程序，并说明内核的三道防线分别在哪。

<details>
<summary>参考答案</summary>

```c
/* kill_stop_proof.c —— 验证 SIGKILL/SIGSTOP 的三道防线
 * 编译: gcc -Wall -Wextra -O2 -o ksp ksp.c
 * 运行: ./ksp
 */
#define _GNU_SOURCE
#include <stdio.h>
#include <signal.h>
#include <unistd.h>
#include <errno.h>
#include <string.h>

static void handler(int sig) { (void)sig; }

static void try_action(int sig, const char *name)
{
    struct sigaction sa, verify;
    memset(&sa, 0, sizeof(sa));
    sa.sa_handler = handler;
    sigemptyset(&sa.sa_mask);
    sa.sa_flags = 0;

    errno = 0;
    int rc = sigaction(sig, &sa, NULL);
    printf("① 改处置 %-9s: rc=%d errno=%d (%s)\n",
           name, rc, errno, rc == -1 ? strerror(errno) : "成功");

    /* 读回看内核到底存了什么 */
    sigaction(sig, NULL, &verify);
    printf("     读回: handler=%s\n",
           verify.sa_handler == SIG_DFL ? "SIG_DFL（没改成）" : "已改（普通信号）");
}

static void try_block(int sig, const char *name)
{
    sigset_t set, check;
    sigemptyset(&set);
    sigaddset(&set, sig);
    sigprocmask(SIG_BLOCK, &set, NULL);

    sigprocmask(SIG_BLOCK, NULL, &check);      /* 读回实际掩码 */
    printf("② 阻塞   %-9s: blocked=%d  ← %s\n",
           name, sigismember(&check, sig),
           sigismember(&check, sig) ? "阻塞成功（普通信号）" : "被内核静默剔除");
}

int main(void)
{
    printf("--- 防线 ①：改处置 ---\n");
    try_action(SIGTERM, "SIGTERM");            /* 普通信号：应该成功 */
    try_action(SIGKILL, "SIGKILL");            /* 应该 EINVAL */
    try_action(SIGSTOP, "SIGSTOP");            /* 应该 EINVAL */

    printf("\n--- 防线 ②：阻塞 ---\n");
    try_block(SIGTERM, "SIGTERM");             /* 应该成功 */
    try_block(SIGKILL, "SIGKILL");             /* 静默剔除 */
    try_block(SIGSTOP, "SIGSTOP");             /* 静默剔除 */

    printf("\n--- 防线 ③：handler 期间屏蔽（sa_mask）---\n");
    {
        struct sigaction sa, verify;
        memset(&sa, 0, sizeof(sa));
        sa.sa_handler = handler;
        sigemptyset(&sa.sa_mask);
        sigaddset(&sa.sa_mask, SIGKILL);       /* 试图在 handler 期间屏蔽 SIGKILL */
        sigaddset(&sa.sa_mask, SIGTERM);       /* 对照组 */
        sa.sa_flags = 0;
        sigaction(SIGTERM, &sa, NULL);

        sigaction(SIGTERM, NULL, &verify);
        printf("   sa_mask 里放 SIGKILL → 读回 blocked=%d  ← 静默剔除\n",
               sigismember(&verify.sa_mask, SIGKILL));
        printf("   sa_mask 里放 SIGTERM → 读回 blocked=%d  ← 保留（对照组）\n",
               sigismember(&verify.sa_mask, SIGTERM));
    }

    printf("\n结论：SIGKILL/SIGSTOP 既不能改处置、也不能阻塞、也不能在 handler 期间屏蔽。\n");
    printf("      前两道【静默】生效（不报错），只有第一道会返 -EINVAL。\n");
    return 0;
}
```

**预期输出**：

```
--- 防线 ①：改处置 ---
① 改处置 SIGTERM  : rc=0 errno=0 (成功)
     读回: handler=已改（普通信号）
① 改处置 SIGKILL  : rc=-1 errno=22 (Invalid argument)
     读回: handler=SIG_DFL（没改成）
① 改处置 SIGSTOP  : rc=-1 errno=22 (Invalid argument)
     读回: handler=SIG_DFL（没改成）

--- 防线 ②：阻塞 ---
② 阻塞   SIGTERM  : blocked=1  ← 阻塞成功（普通信号）
② 阻塞   SIGKILL  : blocked=0  ← 被内核静默剔除
② 阻塞   SIGSTOP  : blocked=0  ← 被内核静默剔除

--- 防线 ③：handler 期间屏蔽（sa_mask）---
   sa_mask 里放 SIGKILL → 读回 blocked=0  ← 静默剔除
   sa_mask 里放 SIGTERM → 读回 blocked=1  ← 保留（对照组）
```

### 三道防线的内核位置

| 防线 | 内核位置 | 行为 |
|------|----------|------|
| ① 改处置 | `do_sigaction():4129` | `if (sig_kernel_only(sig)) return -EINVAL;` **报错** |
| ② 阻塞 | `sigprocmask():3094` → `set_current_blocked():3064` | `sigdelsetmask(&new_blocked, sigmask(SIGKILL)\|sigmask(SIGSTOP));` **静默剔除** |
| ③ handler 期间屏蔽 | `do_sigaction():4161` | `sigdelsetmask(&act->sa.sa_mask, ...)` **静默剔除** |

```c
/* ① do_sigaction:4129 —— 唯一会报错的一道 */
	if (!valid_signal(act->sa_flags & SA_SIGINFO ? sig : sig) || ...)
		return -EINVAL;
	if (sig_kernel_only(sig))          /* ← SIGKILL / SIGSTOP */
		return -EINVAL;

/* ② set_current_blocked:3064 —— 静默剔除 */
static int set_current_blocked(sigset_t *newset)
{
	sigdelsetmask(newset, sigmask(SIGKILL) | sigmask(SIGSTOP));
	/* ^^^^^^^^^^^^^^^^ 你传了也白传，内核直接删掉 */
	return __set_current_blocked(newset);
}

/* ③ do_sigaction:4161 —— sa_mask 同样剔除 */
	sigdelsetmask(&act->sa.sa_mask, sigmask(SIGKILL) | sigmask(SIGSTOP));
```

**判据宏**（`include/linux/signal.h`）：

```c
#define SIG_KERNEL_ONLY_MASK (\
	rt_sigmask(SIGKILL) | rt_sigmask(SIGSTOP))          /* :418 */

#define sig_kernel_only(sig)		sigmask_kernel(sig, SIG_KERNEL_ONLY_MASK)  /* :444 */
```

### ⚠️ 一个反例：内核线程可以阻塞 SIGKILL

用户进程**不可**，但内核线程可以（`kernel/signal.c:3086-3093` 的注释明确说明）。原因是内核线程没有用户态返回路径，不会被信号"递送"，阻塞只是让 `signal_pending()` 查询返回假。这也是为什么你可以用 `kthread_should_stop()` 而不是信号来控制内核线程的生命周期。

### 实践含义

- **运维层面**：`kill -9` 是最后手段，程序**没有任何办法**拦住它——所以关键状态必须在收到 `SIGTERM` 时就落盘
- **设计层面**：不要试图"保护"进程不被杀。正确的做法是设计**幂等的启动恢复流程**（重启后从 WAL/检查点恢复）
- **HFT 场景**：`kill -9` 意味着**未成交、未撤单的持仓无人接管**。生产系统的做法是 `PR_SET_PDEATHSIG` + 独立的看门狗进程，父进程一死立刻被感知并触发撤退流程，而不是等运维发现

</details>

## 综合题：生产级 daemon 骨架

**要求**：写一个可以直接用的 daemon 骨架，满足：

1. **double-fork 脱离终端**（并说明为什么是**两次** fork）
2. **`SIGHUP` 重载配置**（不重启进程）
3. **`SIGTERM` 优雅退出**（落盘、撤单、关连接后再退；第二次 `SIGTERM` 强制退）
4. **`SIGCHLD` 循环回收**（防止僵尸堆积）
5. **信号安全日志**（handler 里不能 `printf`）
6. **PID 文件 + `PR_SET_PDEATHSIG`**（防孤儿）

<details>
<summary>参考实现</summary>

```c
/* daemon_skel.c —— 生产级 daemon 骨架（信号部分完整）
 *
 * 编译: gcc -Wall -Wextra -O2 -o daemon_skel daemon_skel.c
 * 用法: ./daemon_skel            → daemon 化，日志到 syslog
 *       ./daemon_skel -f         → 前台运行，日志到 stderr
 * 停止: kill -TERM $(cat /tmp/daemon_skel.pid)
 * 重载: kill -HUP  $(cat /tmp/daemon_skel.pid)
 */
#define _GNU_SOURCE
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <signal.h>
#include <unistd.h>
#include <errno.h>
#include <fcntl.h>
#include <time.h>
#include <stdarg.h>
#include <sys/stat.h>
#include <sys/types.h>
#include <sys/wait.h>
#include <sys/syslog.h>
#include <sys/prctl.h>

#define PID_FILE    "/tmp/daemon_skel.pid"
#define CONF_FILE   "/tmp/daemon_skel.conf"

/* ─────────── 全局状态（都只在主循环里读，handler 只置位）─────────── */

static volatile sig_atomic_t g_reload   = 0;   /* SIGHUP  → 重载配置 */
static volatile sig_atomic_t g_stop     = 0;   /* SIGTERM → 优雅退出 */
static volatile sig_atomic_t g_term_cnt = 0;   /* SIGTERM 次数 */
static int g_foreground = 0;
static int g_log_fd     = STDERR_FILENO;

/* ─────────── 信号安全日志 ───────────
 * 关键：handler 里用它，所以【只能】用 async-signal-safe 函数：
 *   write / snprintf(技术上也非标准安全，但不分配内存、不持锁，实践中可接受)
 * 生产环境更稳的做法是 handler 只置标志，日志全在主循环写。
 * 这里给出 handler 直接写的版本，用于崩溃前的最后一句话。 */

static void safe_log(const char *fmt, ...)
{
    char buf[512];
    va_list ap;
    va_start(ap, fmt);
    int n = vsnprintf(buf, sizeof(buf), fmt, ap);
    va_end(ap);
    if (n < 0) return;
    if ((size_t)n >= sizeof(buf)) n = (int)sizeof(buf) - 1;

    /* 加时间戳 */
    char out[600];
    time_t t = time(NULL);
    struct tm tm;
    localtime_r(&t, &tm);
    int h = snprintf(out, sizeof(out), "[%02d:%02d:%02d] %.*s\n",
                     tm.tm_hour, tm.tm_min, tm.tm_sec, n, buf);
    if (h <= 0) return;

    /* write 是 async-signal-safe；一次写不完就循环 */
    const char *p = out;
    size_t left = (size_t)h;
    while (left > 0) {
        ssize_t w = write(g_log_fd, p, left);
        if (w <= 0) {
            if (w == -1 && errno == EINTR) continue;
            break;
        }
        p += w; left -= (size_t)w;
    }
}

/* ─────────── handlers（全部只置标志）─────────── */

static void on_hup(int sig)
{
    (void)sig;
    g_reload = 1;                      /* 主循环在安全点处理 */
}

static void on_term(int sig)
{
    (void)sig;
    int saved = errno;
    g_term_cnt++;
    if (g_term_cnt >= 2) {
        /* 第二次 → 强制退出（优雅关闭可能卡住）*/
        safe_log("第二次 SIGTERM → 强制退出");
        _exit(128 + sig);              /* 用 _exit 不用 exit：不跑 atexit、不冲 stdio */
    }
    g_stop = 1;
    safe_log("收到 SIGTERM，开始优雅关闭（再发一次强制退出）");
    errno = saved;                     /* handler 必须保护 errno */
}

static void on_child(int sig)
{
    int saved = errno;
    (void)sig;
    /* SIGCHLD 不排队：N 个子进程同时退出只递送一次 → 必须循环回收 */
    while (waitpid(-1, NULL, WNOHANG) > 0)
        ;
    errno = saved;
}

/* ─────────── 安装（统一走 install()，含读回校验）─────────── */

static int install(int sig, void (*h)(int), int flags)
{
    struct sigaction sa, verify;
    memset(&sa, 0, sizeof(sa));
    sa.sa_handler = h;
    sigemptyset(&sa.sa_mask);
    sa.sa_flags = flags;
    if (sigaction(sig, &sa, NULL) == -1)
        return -1;
    sigaction(sig, NULL, &verify);
    if (verify.sa_handler != h || (verify.sa_flags & flags) != (unsigned)flags)
        return -1;
    return 0;
}

static int install_all(void)
{
    /* SA_RESTART：让 read/recv 等自动重启，避免偶发 EINTR
     * SA_NOCLDSTOP：子进程【停止/恢复】时不发 SIGCHLD，只关心退出 */
    if (install(SIGHUP,  on_hup,   SA_RESTART) == -1) return -1;
    if (install(SIGTERM, on_term,  SA_RESTART) == -1) return -1;
    if (install(SIGINT,  on_term,  SA_RESTART) == -1) return -1;
    if (install(SIGCHLD, on_child, SA_RESTART | SA_NOCLDSTOP) == -1) return -1;

    /* SIGPIPE 忽略：写已关闭的 socket 时不至于被杀 */
    struct sigaction ign;
    memset(&ign, 0, sizeof(ign));
    ign.sa_handler = SIG_IGN;
    sigemptyset(&ign.sa_mask);
    ign.sa_flags = 0;
    if (sigaction(SIGPIPE, &ign, NULL) == -1) return -1;

    return 0;
}

/* ─────────── daemon 化 ─────────── */

static int daemonize(void)
{
    pid_t pid;

    /* 【第一次 fork】脱离调用者 shell 的会话 */
    pid = fork();
    if (pid == -1) return -1;
    if (pid != 0)
        _exit(0);                       /* 父进程退出 → shell 认为命令已结束 */

    /* setsid：创建新会话，成为会话首进程 + 进程组组长，【脱离控制终端】 */
    if (setsid() == -1) return -1;

    /* 【第二次 fork】—— 关键：防止重新获得控制终端
     *
     *   第一次 fork 后的子进程是【会话首进程】，它如果去 open 一个终端设备，
     *   该终端会成为它的控制终端（因为没有控制终端的会话首进程 open tty 时
     *   内核会分配）。
     *
     *   第二次 fork 后，新的子进程【不是】会话首进程（父进程才是），
     *   而非会话首进程 open tty 时【不会】获得控制终端。
     *
     *   → 彻底杜绝 daemon 重新"粘上"终端、收到终端产生的信号
     *     （SIGHUP/SIGINT/SIGTSTP/...）
     */
    pid = fork();
    if (pid == -1) return -1;
    if (pid != 0)
        _exit(0);                       /* 中间进程退出 → 最终的 daemon 被 init 收养 */

    /* 切根目录，避免占用可卸载的挂载点 */
    if (chdir("/") == -1) return -1;

    /* 清掉继承来的文件创建掩码 */
    umask(0);

    /* 重定向 0/1/2 到 /dev/null —— 否则 printf 会写到已消失的终端 */
    int fd = open("/dev/null", O_RDWR);
    if (fd == -1) return -1;
    dup2(fd, STDIN_FILENO);
    dup2(fd, STDOUT_FILENO);
    dup2(fd, STDERR_FILENO);
    if (fd > STDERR_FILENO) close(fd);

    return 0;
}

/* ─────────── PID 文件 ─────────── */

static int write_pidfile(const char *path)
{
    char buf[32];
    int n = snprintf(buf, sizeof(buf), "%ld\n", (long)getpid());
    if (n <= 0) return -1;

    int fd = open(path, O_RDWR | O_CREAT | O_TRUNC, 0644);
    if (fd == -1) return -1;

    /* 加写锁：防止两个实例同时启动 */
    struct flock fl = { .l_type = F_WRLCK, .l_whence = SEEK_SET, .l_start = 0, .l_len = 0 };
    if (fcntl(fd, F_SETLK, &fl) == -1) {
        close(fd);
        return -1;                      /* 已有实例在跑 */
    }

    if (write(fd, buf, (size_t)n) != n) { close(fd); return -1; }
    /* 故意【不 close】：进程存活期间一直持有锁；退出时内核自动释放 */
    return 0;
}

/* ─────────── 业务逻辑桩 ─────────── */

static void load_config(void)   { safe_log("配置已重载"); }
static void persist_state(void) { safe_log("状态已落盘"); }
static void cancel_orders(void) { safe_log("未成交单已撤销"); }
static void do_work(void)       { usleep(200000); }

/* ─────────── main ─────────── */

int main(int argc, char **argv)
{
    g_foreground = (argc > 1 && strcmp(argv[1], "-f") == 0);

    /* ① prctl 要在【任何 fork 之前】调用，且之后要校验父进程是否还活着
     *   （PR_SET_PDEATHSIG 只盯调用瞬间的父进程，有竞态）*/
    pid_t original_ppid = getppid();
    prctl(PR_SET_PDEATHSIG, SIGTERM);
    if (getppid() != original_ppid) {
        /* 父进程已经死了，prctl 不会补发 → 自己补上 */
        raise(SIGTERM);
    }

    /* ② daemon 化（前台模式跳过）*/
    if (!g_foreground && daemonize() == -1) {
        perror("daemonize");
        return 1;
    }

    /* ③ 信号处置（double-fork 之后装，避免继承中间状态）*/
    if (install_all() == -1) {
        safe_log("install_all 失败");
        return 1;
    }

    /* ④ PID 文件 */
    if (write_pidfile(PID_FILE) == -1)
        safe_log("警告: PID 文件写入失败（可能已有实例在跑）");
    else
        safe_log("已启动 pid=%ld", (long)getpid());

    /* ⑤ 初始化 */
    load_config();

    /* ⑥ 主循环 —— 所有实际动作都在【安全点】做，handler 只置标志 */
    while (!g_stop) {
        if (g_reload) {
            g_reload = 0;
            load_config();              /* 普通上下文：可以随便加锁、malloc、读文件 */
        }
        do_work();
    }

    /* ⑦ 优雅关闭（在普通上下文里做，不在 handler 里！）*/
    safe_log("开始优雅关闭...");
    cancel_orders();
    persist_state();
    unlink(PID_FILE);
    safe_log("已退出");

    return 0;
}
```

### 设计要点回顾

| 要点 | 为什么 |
|------|--------|
| **double-fork** | 第一次脱离 shell；**第二次**才是关键——让最终 daemon **不是会话首进程**，从而 open tty 时不会重新获得控制终端，彻底避免收到终端产生的 SIGHUP/SIGINT/SIGTSTP |
| **handler 只置标志** | `printf`/`malloc`/锁/`exit` 在 handler 里全不安全；实际动作放到主循环的安全点 |
| **`SA_NOCLDSTOP`** | 子进程停止/恢复默认也发 SIGCHLD，只关心退出时应过滤，减少无谓 handler 调用 |
| **`SIGCHLD` 循环 `waitpid`** | 标准信号不排队，一次信号可能对应多个已退出子进程 |
| **`_exit()` 不用 `exit()`** | `exit()` 会跑 atexit 处理器并冲刷 stdio；若 stdio 锁正被持有 → 死锁 |
| **保护 `errno`** | handler 里的函数调用可能修改 `errno`，覆盖被中断主流程的值 |
| **`PR_SET_PDEATHSIG` + `getppid()` 校验** | prctl 只盯调用瞬间的父进程；父进程若已死，prctl 不会补发信号 → 必须自己检查补发 |
| **PID 文件加 `flock`** | 防止两个实例同时启动（用 `F_SETLK` 非阻塞，失败即说明已有实例） |
| **PID 文件 fd 故意不关** | 进程存活期间持续持有锁；进程退出时内核自动释放 |
| **第二次 SIGTERM 强制退出** | 优雅关闭可能卡在撤单/落盘，运维需要一条强制通路 |

### 测试清单

### 与 Ch22.10 多线程模型的关系

这个骨架是**单线程 + handler 标志**模型，适合简单 daemon。如果是 HFT 交易进程（多线程、对抖动敏感），应升级为：

```
main()
  ├─ pthread_sigmask(SIG_BLOCK, {全部})     ← 必须在 pthread_create 之前
  ├─ 崩溃兜底：sigaltstack + SA_ONSTACK + SA_SIGINFO（SIGSEGV/BUS/FPE/ILL）
  ├─ 信号线程：for(;;) sig = sigwaitinfo(&set, &info); handle(sig, &info);
  └─ worker 线程：继承阻塞掩码，永不被信号打断
```

<details>
<summary><b>问 1：</b>综合题里为什么 handler 用 <code>_exit()</code> 而不是 <code>exit()</code>？</summary>

`exit()` 会做三件在 handler 上下文里**致命**的事：

1. 调用所有 `atexit()` / `on_exit()` 注册的处理器——这些是用户代码，可能加锁、可能非 async-signal-safe
2. 冲刷并关闭所有 stdio 流
3. 删除 `tmpfile()` 创建的临时文件

其中第 2 条是死锁的直接来源：

```
  主流程: printf(...)                    handler: exit()
     ↓                                      ↓
  fprintf 内部持有 stdout 的 FILE 锁        试图 fflush(stdout)
     ↓                                      ↓
  ←── 信号在此到达 ────────────────────→  要拿同一把锁 → 永远等不到
```

`_exit()`（以及同义的 `_Exit()`）直接进内核 `exit_group()`，**跳过** atexit 处理器和 stdio 冲刷，只做：关闭 fd（不冲刷）、通知父进程、释放资源。

```c
#include <unistd.h>
void _exit(int status);        /* POSIX.1，直接 syscall */

#include <stdlib.h>
void _Exit(int status);        /* C99，等价于 _exit */
void exit(int status);         /* 跑 atexit + 冲刷 stdio ← handler 里禁用 */
void abort(void);              /* 发 SIGABRT，可被 handler 捕获；handler 返回后仍终止 */
```

**一个简单的记忆规则**：

| 场景 | 用什么 |
|------|--------|
| handler 里正常终止 | `_exit()` |
| 主流程正常终止 | `exit()` 或 `return` from main |
| handler 里想"按默认方式死"（让内核产生 core） | 恢复 `SIG_DFL` 后 `raise(sig)`，再 `_exit(128+sig)` 兜底 |
| 断言失败 | `abort()`（会产生 core，前提 core 开关已开） |

详见 [Ch21.2](../../chapter-21-signal-handlers/notes/21.2-other-methods-of-terminating-a-signal-ha.md)。

<summary><b>问 2：</b>综合题的 double-fork 里，第二次 fork 到底防的是什么？只 fork 一次够不够？</summary>

**不够。** 只 fork 一次 + `setsid()` 会让 daemon 成为**会话首进程**，而会话首进程有一个特殊能力：**没有控制终端的会话首进程 open 一个 tty 设备时，内核会把该 tty 分配为它的控制终端**。

```
  只 fork 一次的方案：
     父 ──fork──> 子 ──setsid()──> daemon（【是】会话首进程）
                                     │
                                     └─ 某天 open("/dev/ttyS0")
                                            ↓
                                        内核分配控制终端！
                                            ↓
                                        此后该终端上的 Ctrl-C / 断开
                                        会给 daemon 发 SIGINT/SIGHUP
```

这就是第二次 fork 存在的唯一理由：

```
  double-fork 方案：
     父 ─fork→ 子1 ─setsid()→ 会话首进程 ─fork→ 子2 = daemon
                                  │                   │
                              是会话首进程         【不是】会话首进程
                                  │                   │
                              _exit(0)           open tty 时【不会】
                                                  获得控制终端 ✅
```

规则很直接：**只有会话首进程能获得控制终端**。第二次 fork 后的 daemon 不是会话首进程（它的父进程才是），所以永远不会被分配控制终端，`open()` 一个 tty 也只是普通的文件打开。

配套的还有三件事，缺一不可：

```c
pid = fork();  if (pid != 0) _exit(0);     /* ① 脱离 shell */
setsid();                                   /* ② 新会话 + 新进程组，无控制终端 */
pid = fork();  if (pid != 0) _exit(0);      /* ③ 不是会话首进程 → 永不获控制终端 */
chdir("/");                                 /* ④ 不占用可卸载挂载点 */
umask(0);                                   /* ⑤ 清掉继承的 umask */
fd = open("/dev/null", O_RDWR);             /* ⑥ 重定向 0/1/2 */
dup2(fd, 0); dup2(fd, 1); dup2(fd, 2);
```

第 ⑥ 条也常被忘：不重定向的话，`printf` 写的是一个已经"消失"的终端 fd，会收到 `SIGHUP` 或 `EIO`。

**现代替代方案**：如果用 systemd 管理，根本不需要自己 daemon 化——写个 `Type=simple` 的 service，把程序当普通前台进程跑就行。systemd 已经帮你做好了进程组隔离、日志收集（journald）、重启策略、cgroup 资源限制。

详见 [Ch37 Daemon](../../chapter-37-daemons/README.md) 与 [Ch34 进程组与会话](../../chapter-34-process-groups-sessions/README.md)。

<summary><b>问 3：</b>为什么 <code>PR_SET_PDEATHSIG</code> 之后还要再检查一次 <code>getppid()</code>？</summary>

因为 `prctl(PR_SET_PDEATHSIG, sig)` 有**固有的竞态**：它记录的是「调用这一刻的父进程」，如果父进程在 `prctl` 之前就死了，这个设置永远不会生效（没有"补发"机制）。

```
  危险窗口：

    fork()
      ↓
    ┌─────────────────────────────────────┐
    │ 父进程在此刻死亡（或先于子进程调度）  │
    └─────────────────────────────────────┘
      ↓
    prctl(PR_SET_PDEATHSIG, SIGTERM)   ← 设了个"已经死了的父进程"
      ↓
    （永远等不到信号 → 子进程变孤儿，继续跑）
```

虽然这个窗口很窄，但在负载高的机器上完全可能命中，而且一旦命中就是**永久孤儿**——daemon 化的程序会一直跑下去，谁也杀不掉。

修法是「设完立即校验」：

```c
pid_t original_ppid = getppid();          /* ① 先记下 */
prctl(PR_SET_PDEATHSIG, SIGTERM);         /* ② 再设置 */
if (getppid() != original_ppid)           /* ③ 校验：父进程变了吗？*/
    raise(SIGTERM);                       /*    变了 → 说明它已经死了/换了，补上 */
```

**为什么 `getppid()` 变化就说明父进程死了？** 父进程死亡后，子进程会被 reparent 到 init（PID 1）或最近的 subreaper。所以 `getppid()` 会变成 1 或 subreaper 的 PID，与 `original_ppid` 不同。

**三个必须知道的边界**：

| 边界 | 说明 |
|------|------|
| 只盯**直接**父进程 | 父进程的父进程死了不管 |
| **线程粒度** | `PR_SET_PDEATHSIG` 是**每线程**设置（不是进程级）。多线程程序里，只有调用它的那个线程会在父死时收信号；而且要在**每个线程**里调，或者用 `PR_SET_PDEATHSIG` 后由收到信号的线程广播 |
| **fork 后失效** | 子进程 `fork()` 后，孙进程的 PDEATHSIG **不会被继承**（`fork` 会清除该标志，因为孙进程的父进程是子进程而非原父进程）。所以 daemon 化程序要在 **fork 之后**重新设置 |

**更可靠的替代**：`pidfd_open(parent_pid)` + `poll(pidfd, POLLIN)`——fd 持有 `task_struct` 引用，父进程一退出 fd 立即就绪，且**没有竞态窗口**（在 `pidfd_open` 成功的那一刻，引用已经建立了）。还能直接进 epoll 事件循环。Linux 5.1+。

```c
int pfd = pidfd_open(original_ppid, 0);
/* 把 pfd 加进 epoll；POLLIN 就绪 = 父进程已退出 */
```

<summary><b>问 4：</b>综合题里 <code>SIGCHLD</code> 装了 <code>SA_NOCLDSTOP</code>，如果不加会怎样？</summary>

子进程**被停止**（收到 `SIGSTOP`/`SIGTSTP`/`SIGTTIN`/`SIGTTOU`）或**被恢复**（`SIGCONT`）时，也会给父进程发 `SIGCHLD`。

```c
/* kernel/signal.c 的 do_notify_parent_cldstop() */
	info.si_code = why;          /* CLD_STOPPED / CLD_CONTINUED / ... */
	...
	__send_signal(sig, &info, ...);
```

不加 `SA_NOCLDSTOP` 的后果：

| 场景 | 后果 |
|------|------|
| 用 `SIGTSTP`（Ctrl-Z）挂起子进程 | 父进程收到 SIGCHLD，handler 跑一次，`waitpid(WNOHANG)` 返回 0（没退出） → **白跑一趟** |
| 用 `SIGCONT` 恢复 | 又发一次 SIGCHLD → 又白跑一趟 |
| 作业控制型 shell | 这是**必需的**（要跟踪子进程停止/恢复状态） |
| 普通 daemon（只关心子进程退出） | **纯噪音**，尤其高频 fork 的服务里浪费 CPU |

**注意 `waitpid()` 的 flag 也有对应关系**：

```c
waitpid(-1, &status, WNOHANG);              /* 只回收"已退出"的 */
waitpid(-1, &status, WUNTRACED);            /* 也报告"已停止"的 */
waitpid(-1, &status, WCONTINUED);           /* 也报告"已恢复"的 */
```

`SA_NOCLDSTOP` 管的是**信号**，上面三个 flag 管的是 `waitpid()` 的**返回条件**，两者是独立的开关。

**另一个相关选项 `SA_NOCLDWAIT`**：

```c
sa.sa_flags |= SA_NOCLDWAIT;
```

效果是「子进程退出时**不产生僵尸**」，父进程也就不能 `wait()` 了（`wait()` 会阻塞到所有子进程退出后返回 `-1/ECHILD`）。

| | `SA_NOCLDWAIT` | `SIGCHLD` 设 `SIG_IGN` |
|---|---|---|
| 不产生僵尸 | ✅ | ✅ |
| 能 `wait()` 拿退出状态 | ❌（返回 -1/ECHILD） | ❌ |
| POSIX 可移植 | ✅（POSIX.1-2001） | ⚠️ Linux/SysV 可行，BSD 历史上不行 |

两者的实际区别在 `SIG_IGN` 时**已退出的子进程会被立即回收，但已经在等待中的僵尸会被丢弃**——如果你先 `wait()` 了一半再设 `SIG_IGN`，那些已存在的僵尸会被清掉。

实践建议：只关心"别留僵尸" → `SA_NOCLDWAIT` 或 `SIG_IGN`；需要退出码 → 装 handler + 循环 `waitpid(..., WNOHANG)` + `SA_NOCLDSTOP`。

</details>

<details>
<summary><b>问 5：</b>综合题的骨架在什么情况下会失效？怎么升级？</summary>

这个「单线程 + handler 置标志」模型在四种情况下会出问题：

**① 多线程程序 —— 信号落在哪个线程不确定**

进程级信号（`kill()` 来的）会被内核投递给**任意一个没有阻塞该信号的线程**。所以：

```c
/* 线程 A 注册了 handler，但信号可能被线程 B 收到 */
/* 而且哪个线程收到是不可预测的 → 抖动不可控 */
```

升级方案（[Ch22.10](../../chapter-22-signals-advanced/notes/22.10-synchronously-waiting-for-a-signal.md)）：

```c
/* main 里，必须在 pthread_create 之前 */
sigset_t all;
sigfillset(&all);
pthread_sigmask(SIG_BLOCK, &all, NULL);      /* 阻塞全部 */

/* 所有后续 pthread_create 的线程【继承】这个掩码 → 天然不受打扰 */

/* 专用信号线程 */
static void *sig_thread(void *arg) {
    (void)arg;
    sigset_t set;
    sigemptyset(&set);
    sigaddset(&set, SIGTERM);
    sigaddset(&set, SIGHUP);
    sigaddset(&set, SIGCHLD);
    for (;;) {
        siginfo_t info;
        int sig = sigwaitinfo(&set, &info);
        if (sig > 0) handle(sig, &info);     /* 普通同步代码，可加锁可 printf */
    }
}
```

三个决定性优势：worker 永不被打断（抖动可控）、无 async-signal-safe 约束、信号自动串行化。

**② 需要统一事件循环（socket + timer + 信号）**

handler 标志模型下，主循环要定期检查标志 → 有轮询延迟，也破坏 `epoll_wait` 的阻塞语义。

升级方案：`signalfd` 把信号变成 fd，直接进 epoll（[Ch22.11](../../chapter-22-signals-advanced/notes/22.11-fetching-signals-via-a-file-descriptor.md)）：

```c
sigset_t mask;
sigemptyset(&mask);
sigaddset(&mask, SIGTERM);
sigaddset(&mask, SIGHUP);
sigprocmask(SIG_BLOCK, &mask, NULL);          /* ① 必须先阻塞 */
int sfd = signalfd(-1, &mask, SFD_NONBLOCK);  /* ② 建 fd */
epoll_ctl(epfd, EPOLL_CTL_ADD, sfd, &ev);     /* ③ 进 epoll */
/* ④ read 时缓冲区必须 ≥ sizeof(struct signalfd_siginfo)，否则 -EINVAL */
```

**⚠️ 但 signalfd 抓不到 `SIGSEGV`/`SIGBUS`/`SIGFPE`/`SIGILL`**——同步故障信号走 `force_sig_info_to_task():1336` 线程定向直投（内核会撤销 `SIG_IGN`、解除阻塞），压根不进 pending 队列。崩溃兜底**只能**用 handler。

**③ 对抖动极其敏感（HFT 主链路）**

即使是 `sigwaitinfo` 模型，信号线程被唤醒也会占用一个物理核、污染 cache。

进一步方案：
- 把信号线程**绑到隔离核**（`pthread_setaffinity_np` + 内核 `isolcpus`）
- 或者干脆**不用信号**——用 `eventfd` / UNIX socket 做进程内通知，信号只留崩溃兜底
- 关键：**控制平面（信号）与数据平面（交易）物理隔离**

**④ 需要区分"哪个子进程退出"或"信号携带数据"**

标准信号不排队且无载荷。升级到实时信号 + `sigqueue`：

```c
/* 发送 */
union sigval sv = { .sival_int = order_id };
sigqueue(pid, SIGRTMIN + 0, sv);

/* 接收：必须 SA_SIGINFO */
static void h(int sig, siginfo_t *si, void *ctx) {
    (void)sig; (void)ctx;
    int order_id = si->si_value.sival_int;    /* 拿到数据 */
}
```

⚠️ 但**跨进程传指针（`sival_ptr`）是致命错误**——虚拟地址空间不同，解引用直接段错误。跨进程只能用 `sival_int`，或改走共享内存（见 [Ch22.12](../../chapter-22-signals-advanced/notes/22.12-interprocess-communication-with-signals.md)）。

**升级路线总结**：

| 场景 | 推荐模型 |
|------|----------|
| 单线程简单 daemon | handler 置标志（本骨架） |
| 多线程服务 | main 阻塞全部 + 专用 `sigwaitinfo` 线程 |
| 有 epoll 主循环 | `signalfd` 统一纳管 |
| HFT 主链路 | 信号线程绑隔离核 / 改用 eventfd；信号只做崩溃兜底 |
