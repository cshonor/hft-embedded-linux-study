## 本节讲什么

1. `sigset_t` 是什么——为什么信号集合用一个「位图」而不是数组或链表
2. 五个操作函数怎么用，以及**必须先初始化**这个铁律的原因
3. `sigset_t` 在内核里长什么样——位下标与信号编号的**偏移关系**

---

## 一、数据类型：一个位图

```c
typedef struct { /* 实现定义，通常是一个 unsigned long 数组，当位图用 */ } sigset_t;
```

设计成位图的原因很直接：信号总数固定（64 个以内），需要的是 O(1) 的「在/不在」查询和集合运算，位图是最紧凑、最快的选择。

- 信号编号 `1`~`64`
- 位图只需 `_NSIG_WORDS` 个 `unsigned long`（64 位系统上 64 个信号只需 **1 个** `unsigned long`）
- 集合运算（并/交/差）直接对应 `|`、`&`、`&~`

### 内核里的实现

内核自己的 `sigset_t` 位图原语（`include/linux/signal.h:64-89`）：

```c
static inline void sigaddset(sigset_t *set, int _sig)
{
	unsigned long sig = _sig - 1;                     // ← 编号转下标
	if (_NSIG_WORDS == 1)
		set->sig[0] |= 1UL << sig;
	else
		set->sig[sig / _NSIG_BPW] |= 1UL << (sig % _NSIG_BPW);
}

static inline void sigdelset(sigset_t *set, int _sig)
{
	unsigned long sig = _sig - 1;
	if (_NSIG_WORDS == 1)
		set->sig[0] &= ~(1UL << sig);
	else
		set->sig[sig / _NSIG_BPW] &= ~(1UL << (sig % _NSIG_BPW));
}

static inline int sigismember(sigset_t *set, int _sig)
{
	unsigned long sig = _sig - 1;
	if (_NSIG_WORDS == 1)
		return 1 & (set->sig[0] >> sig);
	else
		return 1 & (set->sig[sig / _NSIG_BPW] >> (sig % _NSIG_BPW));
}
```

> **关键细节**：`unsigned long sig = _sig - 1;` —— 信号编号从 **1** 开始（`SIGHUP` = 1），而位下标从 **0** 开始，所以必须减 1。这就是「不存在信号 0」的原因：编号 0 会被换算成下标 `-1`，越界。

## 二、五个操作函数

```c
#include <signal.h>

int sigemptyset(sigset_t *set);              /* 清空：所有位 = 0 */
int sigfillset(sigset_t *set);               /* 填满：所有位 = 1 */
int sigaddset(sigset_t *set, int sig);       /* 添加 sig */
int sigdelset(sigset_t *set, int sig);       /* 移除 sig */
int sigismember(const sigset_t *set, int sig);/* 查询：1 在 / 0 不在 / -1 错误 */
```

| 函数 | 作用 | 返回 |
|------|------|------|
| `sigemptyset(&set)` | 清空（所有 bit = 0） | 0 / -1 |
| `sigfillset(&set)` | 填满（所有 bit = 1） | 0 / -1 |
| `sigaddset(&set, sig)` | 添加信号 `sig` | 0 / -1 |
| `sigdelset(&set, sig)` | 移除信号 `sig` | 0 / -1 |
| `sigismember(&set, sig)` | 查询 `sig` 是否在集合中 | **1** 在 / **0** 不在 / **-1** 错误 |

> **注意 `sigismember` 的返回值语义**：它返回的是「真假值」而不是标准成功/失败码。`1` 表示在集合里，`0` 表示不在。所以判断要写 `if (sigismember(&set, sig) == 1)`，而不是 `if (sigismember(...))` 时把 `-1`（错误）当成真。

### GNU 扩展：集合运算

glibc（启用 `_GNU_SOURCE`）还提供三个集合运算：

```c
#define _GNU_SOURCE
int sigandset(sigset_t *dest, const sigset_t *left, const sigset_t *right);   /* 交 */
int sigorset (sigset_t *dest, const sigset_t *left, const sigset_t *right);   /* 并 */
int sigisemptyset(const sigset_t *set);                                       /* 是否为空 */
```

这些不是 POSIX 标准，可移植性差，但在 Linux 专用代码里很方便。内核侧对应的是 `sigandsets`/`sigorsets`/`sigandnsets`（`include/linux/signal.h`）。

## 三、铁律：必须先初始化

```c
sigset_t set;
sigaddset(&set, SIGINT);       /* ❌ 未定义行为：set 是栈上的随机值 */
```

**必须**先 `sigemptyset()` 或 `sigfillset()`：

```c
sigset_t set;
sigemptyset(&set);             /* ✅ 先清零 */
sigaddset(&set, SIGINT);
sigaddset(&set, SIGTERM);
```

**原因**：`sigset_t` 是一个 POD 结构体，声明在栈上时内容是**未初始化的垃圾数据**。`sigaddset` 只做 `|=` 置位，不会清除其他位——于是那些随机置位的信号会**意外地被阻塞**（或意外地出现在 `sa_mask` 里），表现为「莫名其妙某个信号收不到」，极难排查。

> **实战建议**：始终用初始化器 `sigset_t set = {0};` 或显式 `sigemptyset()` 起步，二者等价，但前者在声明处就能看出已初始化。

## 四、典型用法

`sigset_t` 本身只是一个容器，真正的作用体现在三处：

| 用途 | 接口 | 说明 |
|------|------|------|
| **阻塞信号** | `sigprocmask()` | 把集合作为「要阻塞/解除阻塞/替换」的掩码，见 [20.10](./20.10-the-signal-mask-blocking-signal-delivery.md) |
| **handler 期间额外屏蔽** | `sigaction` 的 `sa_mask` | handler 执行期间临时加入掩码，见 [20.13](./20.13-changing-signal-dispositions-sigaction.md) |
| **查询未决集** | `sigpending()` | 内核把当前未决信号写入集合，见 [20.11](./20.11-pending-signals.md) |

```c
/* ① 用于 sigprocmask：批量阻塞 */
sigset_t block;
sigemptyset(&block);
sigaddset(&block, SIGINT);
sigaddset(&block, SIGTERM);
sigprocmask(SIG_BLOCK, &block, NULL);

/* ② 用于 sa_mask：handler 期间额外屏蔽 SIGUSR1 */
struct sigaction sa = {0};
sa.sa_handler = handler;
sigemptyset(&sa.sa_mask);
sigaddset(&sa.sa_mask, SIGUSR1);
sigaction(SIGINT, &sa, NULL);

/* ③ 用于 sigpending：读出未决集 */
sigset_t pending;
sigemptyset(&pending);
sigpending(&pending);
if (sigismember(&pending, SIGINT) == 1) { /* SIGINT 未决 */ }
```

> **陷阱**：内核会把 `sa_mask` 和 `sigprocmask` 参数里的 `SIGKILL`/`SIGSTOP` **静默剔除**（`do_sigaction` 的 `sigdelsetmask`，`kernel/signal.c:4161`；`sigprocmask` 的 `sigdelsetmask`，`:3094` 附近）。所以即使你 `sigaddset(&set, SIGKILL)`，也不会生效，且**没有任何报错**。

## HFT / 嵌入式关联

| 路线 | 要点 |
|------|------|
| 嵌入式 | 信号集是信号管理的基石。嵌入式上常见做法是启动时一次性构造好「要屏蔽的信号集」，用 `sigprocmask(SIG_SETMASK, &mask, NULL)` 整体设置，避免热路径里反复增删。注意 `sigset_t` 未初始化的坑——嵌入式工具链往往不做栈清零，未初始化的 `sigset_t` 会随机屏蔽信号，表现为偶发丢信号，极难定位 |
| HFT | 临界区前用 `sigset_t` 批量阻塞信号、事后恢复，保证原子性。但注意：`sigprocmask` 是**系统调用**，热路径频繁进出会带来固定开销（~1μs 量级）。HFT 的做法是**启动时一次性 `SIG_SETMASK` 屏蔽**，之后不再改动，用 signalfd 或 `sigwaitinfo` 在专用线程消费，把信号从异步抢占变成同步事件 |

## 代码示例

```c
/* sigsetdemo.c —— 信号集操作与「必须先初始化」的对比
 * 编译: gcc -D_GNU_SOURCE -o sigsetdemo sigsetdemo.c */
#define _GNU_SOURCE
#include <signal.h>
#include <stdio.h>
#include <string.h>

static void dump(const char *tag, const sigset_t *set)
{
    printf("%-16s: SIGINT=%d SIGTERM=%d SIGUSR1=%d SIGKILL=%d\n", tag,
           sigismember(set, SIGINT),
           sigismember(set, SIGTERM),
           sigismember(set, SIGUSR1),
           sigismember(set, SIGKILL));
}

int main(void)
{
    sigset_t set;

    /* ① 正确：先清空再添加 */
    sigemptyset(&set);
    dump("empty", &set);

    sigaddset(&set, SIGINT);
    sigaddset(&set, SIGTERM);
    sigaddset(&set, SIGUSR1);
    dump("+INT+TERM+USR1", &set);

    sigdelset(&set, SIGUSR1);
    dump("-USR1", &set);

    sigfillset(&set);
    dump("fillset", &set);

    /* ② 集合运算（GNU 扩展） */
    sigset_t a, b, r;
    sigemptyset(&a); sigaddset(&a, SIGINT);  sigaddset(&a, SIGTERM);
    sigemptyset(&b); sigaddset(&b, SIGTERM); sigaddset(&b, SIGUSR2);
    sigorset(&r, &a, &b);   printf("\na | b (并集): TERM=%d USR2=%d\n",
                                   sigismember(&r, SIGTERM), sigismember(&r, SIGUSR2));
    sigandset(&r, &a, &b);  printf("a & b (交集): INT=%d TERM=%d\n",
                                   sigismember(&r, SIGINT), sigismember(&r, SIGTERM));

    /* ③ 演示 SIGKILL 被内核静默剔除 */
    sigset_t k;
    sigemptyset(&k);
    sigaddset(&k, SIGKILL);
    sigprocmask(SIG_BLOCK, &k, NULL);
    sigset_t cur;
    sigemptyset(&cur);
    sigprocmask(SIG_BLOCK, NULL, &cur);
    printf("\n试图阻塞 SIGKILL -> 实际掩码中 SIGKILL=%d (被内核剔除)\n",
           sigismember(&cur, SIGKILL));

    return 0;
}
```

## 自测题

<details>
<summary><b>问 1：</b>为什么说「必须先 <code>sigemptyset</code> 再 <code>sigaddset</code>」？不初始化会怎样？</summary>

`sigset_t` 是一个 POD 结构体（本质是 `unsigned long` 数组）。声明在栈上时，其内容是**未初始化的垃圾数据**。

而 `sigaddset()` 只做置位操作（`set->sig[i] |= 1UL << bit`），**不会清除其他位**。所以：

```c
sigset_t set;                  /* 栈上随机值，可能已有一堆位被置 1 */
sigaddset(&set, SIGINT);       /* 只加了 SIGINT，垃圾位仍在 */
sigprocmask(SIG_BLOCK, &set, NULL);   /* 那些垃圾位对应的信号被意外阻塞 ❌ */
```

**后果**：随机地、不可复现地丢信号——某些信号莫名收不到，且每次运行行为可能不同（取决于栈内容）。这是极难排查的一类 bug。

**正确做法**（三选一）：

```c
sigset_t set;  sigemptyset(&set);         /* ① 标准做法 */
sigset_t set = {0};                       /* ② 初始化器，等价 */
/* ③ 需要"全部屏蔽"时 */
sigset_t set;  sigfillset(&set);
```

</details>

<details>
<summary><b>问 2：</b><code>sigismember()</code> 的返回值有什么特殊之处？</summary>

它返回的是**真假值**而非标准成功/失败码：

| 返回值 | 含义 |
|--------|------|
| `1` | 信号**在**集合中 |
| `0` | 信号**不在**集合中 |
| `-1` | 出错（如信号编号非法） |

**陷阱**：如果写成 `if (sigismember(&set, sig))`，那么 `-1`（错误）也会被视为「真」，与 `1`（在集合中）无法区分。

**正确写法**：

```c
if (sigismember(&set, sig) == 1)      /* 明确比较 */
    ...
/* 或 */
int r = sigismember(&set, sig);
if (r < 0)      /* 处理错误 */
else if (r)     /* 在集合中 */
else            /* 不在 */
```

</details>

<details>
<summary><b>问 3：</b>内核里 <code>sigaddset</code> 为什么写 <code>unsigned long sig = _sig - 1;</code>？</summary>

因为**信号编号从 1 开始，而位下标从 0 开始**。

```c
// include/linux/signal.h:64
static inline void sigaddset(sigset_t *set, int _sig)
{
	unsigned long sig = _sig - 1;             // ← 编号 → 下标
	if (_NSIG_WORDS == 1)
		set->sig[0] |= 1UL << sig;
	else
		set->sig[sig / _NSIG_BPW] |= 1UL << (sig % _NSIG_BPW);
}
```

- `SIGHUP` = 1 → 下标 0
- `SIGINT` = 2 → 下标 1
- `SIGKILL` = 9 → 下标 8

**推论**：这也解释了**为什么不存在「信号 0」**——如果 `_sig == 0`，则 `sig = -1`，`1UL << -1` 是未定义行为。

所以 `kill(pid, 0)` 里的 `0` 不是「0 号信号」，而是**空信号**（不发送，只检查），这是纯粹的接口约定，与位图无关。

</details>

<details>
<summary><b>问 4：</b><code>sigaddset(&set, SIGKILL)</code> 然后 <code>sigprocmask(SIG_BLOCK, &set, NULL)</code> 能阻塞 <code>SIGKILL</code> 吗？</summary>

**不能**，而且**不会报错**——内核会静默剔除。

`sigprocmask()` 内部（`kernel/signal.c:3094` 附近）做了：

```c
sigdelsetmask(&newset, sigmask(SIGKILL) | sigmask(SIGSTOP));
```

`do_sigaction()` 里也有同样的处理（`kernel/signal.c:4161`），把 `sa_mask` 里的 `SIGKILL`/`SIGSTOP` 剔除。

**这意味着**：

1. 无法用 `sigprocmask` 阻塞 `SIGKILL`/`SIGSTOP`
2. 无法用 `sa_mask` 在 handler 期间屏蔽它们
3. 无法用 `sigaction` 改变它们的处置（`do_sigaction` `:4129` 返回 `-EINVAL`）
4. 且上述所有失败都是**静默的**（不返回错误）

**设计意图**：保证 `kill -9` 和 `kill -STOP` 永远是有效的最后手段——无论进程怎么写，管理员和 watchdog 都能收场。

</details>

<details>
<summary><b>问 5：</b><code>sigset_t</code> 有哪三个主要用途？</summary>

| 用途 | 接口 | 语义 |
|------|------|------|
| **阻塞/解除阻塞信号** | `sigprocmask(how, &set, &old)` | `set` = 要改变的信号集，`how` 决定是并集、差集还是替换 |
| **handler 期间额外屏蔽** | `sigaction` 的 `sa_mask` 字段 | handler 执行期间，这些信号**临时加入**当前掩码（返回后自动恢复） |
| **读出未决信号** | `sigpending(&set)` | 内核把当前未决的信号**写入** `set`（输出参数，非输入） |

注意第三点是**输出**语义——`sigpending` 会覆盖 `set` 的内容，调用前无需 `sigemptyset`（但初始化仍是好习惯）。

补充：`sigsuspend(&mask)` 和 `sigwaitinfo(&set, ...)` 也用 `sigset_t`，见 [Ch22.9](../../chapter-22-signals-advanced/notes/22.9-waiting-for-a-signal-using-a-mask-sigsus.md) 与 [Ch22.10](../../chapter-22-signals-advanced/notes/22.10-synchronously-waiting-for-a-signal.md)。

</details>
