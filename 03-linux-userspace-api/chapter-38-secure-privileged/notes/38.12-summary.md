# 38.12 Summary

> 本章：[TLPI 第 38 章](./README.md)

## 本节讲什么

第 38 章总结了编写安全特权程序的核心原则，涵盖信息泄露防护、权限限制、竞态条件避免、文件操作安全、输入验证、缓冲区溢出防御、DoS 防护和错误处理。

## 要点

### 安全原则速查表

| 原则 | 关键 API/技术 |
|------|--------------|
| 最小权限 | `setuid`/`setgid`/`setgroups`/capabilities |
| 权限及时丢弃 | 特权操作完成后立即 `setuid` |
| 信息不泄露 | `unsetenv`/`explicit_bzero`/禁 core dump |
| 环境隔离 | `chroot` + 丢权限 |
| 信号安全 | `sigprocmask` 屏蔽 + 异步信号安全函数 |
| 文件安全 | `O_NOFOLLOW`/`O_EXCL`/`fstat` 检查 |
| 输入验证 | 长度/格式/范围校验 + 路径净化 |
| 缓冲区安全 | `snprintf`/`strncpy` + `-D_FORTIFY_SOURCE` |
| 资源限制 | `setrlimit` 限制 CPU/内存/FD/进程 |
| Fail-safe | 检查所有返回值，失败即退出 |

### 特权程序初始化检查清单

```
[ ] 1. 清理环境变量（clearenv + 白名单）
[ ] 2. 禁用 core dump（setrlimit RLIMIT_CORE = 0）
[ ] 3. 设置资源限制（CPU/内存/FD/进程数）
[ ] 4. 打开特权资源（端口 < 1024 等）
[ ] 5. chroot 到受限目录（如果需要）
[ ] 6. setgroups(0, NULL) 清除补充组
[ ] 7. setgid() 丢弃组权限
[ ] 8. setuid() 丢弃用户权限
[ ] 9. 验证权限已丢弃（setuid(0) 应失败）
[ ] 10. 进入主循环
```

### 安全编码编译选项

```makefile
CFLAGS = -O2 -Wall -Wextra -Werror \
         -D_FORTIFY_SOURCE=2 \
         -fstack-protector-strong \
         -fPIE -pie \
         -Wl,-z,relro,-z,now \
         -Wl,-z,noexecstack
```

## 代码自测

<details>
<summary>特权程序初始化时，为什么要按"chroot → setgroups → setgid → setuid"的顺序？</summary>

1. **chroot 在 setuid 之前**：`chroot` 需要 root 权限。丢弃权限后无法再 chroot。
2. **setgroups 在 setgid 之前**：`setgroups` 需要 root 权限。如果先 setgid 丢弃 root，setgroups 会失败，旧的补充组（可能包含 root 组）不会清除。
3. **setgid 在 setuid 之前**：setuid 后程序不再是 root，setgid 可能失败（虽然有些实现允许 setgid 到自己的组）。
4. **setuid 最后**：这是不可逆的权限丢弃，之后所有操作以非特权身份执行。

</details>

<details>
<summary>`-fstack-protector-strong` 和 `-fstack-protector` 有什么区别？</summary>

`-fstack-protector` 只在有 `char` 数组的函数中插入 canary 保护。`-fstack-protector-strong` 扩大了保护范围，对所有有局部数组（任何类型）的函数、取地址局部变量的函数都插入 canary。`-fstack-protector-all` 对所有函数都插入（性能开销大）。推荐使用 `-fstack-protector-strong`，在安全性和性能之间取得平衡。

</details>
