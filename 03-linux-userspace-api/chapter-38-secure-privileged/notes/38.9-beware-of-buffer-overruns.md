# 38.9 Beware of Buffer Overruns

> 本章：[TLPI 第 38 章](../README.md)

## 本节讲什么

缓冲区溢出是特权程序中最严重的安全漏洞之一。攻击者通过精心构造的输入覆盖内存，可能执行任意代码。本节介绍溢出原理和防御措施。

## 要点

### 危险函数与安全替代

| 危险函数 | 风险 | 安全替代 |
|---------|------|---------|
| `gets` | 无长度限制 | `fgets` |
| `strcpy` | 无边界检查 | `strncpy`/`strlcpy` |
| `strcat` | 无边界检查 | `strncat`/`strlcat` |
| `sprintf` | 无边界检查 | `snprintf` |
| `vsprintf` | 无边界检查 | `vsnprintf` |
| `scanf("%s")` | 无长度限制 | `scanf("%99s")` 或 `fgets` |

### 防御层次

| 层次 | 技术 | 效果 |
|------|------|------|
| 编译期 | `-D_FORTIFY_SOURCE=2` | 编译器插入边界检查 |
| 编译期 | `-fstack-protector-strong` | 栈 canary 保护 |
| 链接期 | `-Wl,-z,relro,-z,now` | GOT 只读 |
| 运行期 | ASLR（内核默认开启） | 地址随机化 |
| 运行期 | NX bit（`-z noexecstack`） | 栈不可执行 |
| 编码 | `snprintf` 替代 `sprintf` | 源头防御 |

### 常见溢出模式

1. **栈溢出**：局部数组写入超长数据 → 覆盖返回地址
2. **堆溢出**：堆缓冲区越界 → 破坏堆元数据
3. **整数溢出**：`size_t len = a + b` 溢出 → 分配小缓冲区 → 后续写入溢出
4. **off-by-one**：循环条件 `<` 写成 `<=` → 写入一个额外字节

## HFT / 嵌入式关联

- 行情解析：二进制协议解析必须校验长度字段，防止恶意包导致溢出
- 嵌入式设备资源受限，可能缺少 ASLR/stack-protector，编码安全更重要
- 交易协议解码器应使用 `memcpy_s` 或显式长度检查

## 代码示例

```c
#include <stdio.h>
#include <string.h>
#include <stdlib.h>

/* 错误示例：整数溢出导致小分配 */
void dangerous_alloc(size_t count, const char *data)
{
    /* 如果 count 很大，count * sizeof(char) 可能溢出为小值 */
    char *buf = malloc(count);  /* 可能分配很小的缓冲区 */
    if (buf) {
        memcpy(buf, data, count);  /* 写入溢出！ */
        free(buf);
    }
}

/* 正确示例：溢出检查 */
int safe_alloc_copy(size_t count, const char *data, size_t data_len)
{
    /* 检查乘法溢出（虽然 char 大小为 1，但养成习惯） */
    if (count > SIZE_MAX) return -1;

    /* 确保不超过源数据长度 */
    if (count > data_len) count = data_len;

    char *buf = malloc(count + 1);  /* +1 给终止符 */
    if (!buf) return -1;

    memcpy(buf, data, count);
    buf[count] = '\0';
    free(buf);
    return 0;
}

/* 安全的字符串拼接 */
int safe_concat(char *dst, size_t dstsize, const char *src)
{
    size_t dlen = strnlen(dst, dstsize);
    if (dlen >= dstsize) return -1;  /* dst 未终止 */

    /* snprintf 返回需要的长度，截断后安全终止 */
    int n = snprintf(dst + dlen, dstsize - dlen, "%s", src);
    if (n < 0 || (size_t)n >= dstsize - dlen) return -1;  /* 截断 */
    return 0;
}
```

## 代码自测

<details>
<summary>什么是 off-by-one 错误？举例说明。</summary>

Off-by-one 是指循环或索引多访问了一个元素。例如：`char buf[8]; for (i = 0; i <= 8; i++) buf[i] = ...;` —— 循环条件应该是 `i < 8`。这个多余的一个字节可能覆盖栈上相邻的关键数据（如保存的帧指针低位），在某些架构上可被利用。

</details>

<details>
<summary>`-D_FORTIFY_SOURCE=2` 如何工作？</summary>

编译器在编译期分析缓冲区大小（对已知大小的栈/静态数组），在运行时插入边界检查。例如 `strcpy(dst, src)` 被替换为 `__strcpy_chk(dst, src, __bos(dst))`，如果 `src` 长度超过 `dst` 大小，调用 `__chk_fail()` 终止程序。级别 2 比级别 1 多检查了 `snprintf` 返回值等更多场景。

</details>
