# 38.6 Beware of Signals and Race Conditions

> 本章：[TLPI 第 38 章](../README.md)

## 本节讲什么

特权程序中信号处理与系统调用之间存在竞态条件。攻击者可在特权操作的窗口期发送信号，干扰程序执行流。关键是理解信号何时可中断系统调用、何时产生竞争窗口。

## 要点

### 竞态场景

| 场目 | 竞态窗口 | 后果 |
|------|---------|------|
| `setuid` + `open` | 检查 UID → 打开文件 | TOCTOU：文件被替换 |
| 信号中断 `open` | `open` 返回 `EINTR` | 特权未丢弃时继续执行 |
| `access` + `open` | access 检查 → open 打开 | 符号链接替换攻击 |
| 信号处理中调用非异步信号安全函数 | handler 执行期间 | 死锁/内存损坏 |

### 防御措施

1. **屏蔽信号**：在特权操作期间屏蔽所有信号
   ```c
   sigset_t mask, oldmask;
   sigfillset(&mask);
   sigprocmask(SIG_BLOCK, &mask, &oldmask);
   /* 特权操作 */
   sigprocmask(SIG_SETMASK, &oldmask, NULL);
   ```

2. **避免 TOCTOU**：不用 `access()` + `open()`，改用 `open()` + `fstat()`

3. **信号处理只设标志**：handler 中只设置 `volatile sig_atomic_t` 标志，主循环检查

4. **`SA_RESTART`**：让被中断的系统调用自动重启

## HFT / 嵌入式关联

- 交易系统中，订单提交路径必须屏蔽信号，防止关键操作被中断
- 嵌入式设备升级程序在写固件时需屏蔽信号，防止半完成状态
- 行情处理进程的信号 handler 只设标志，主 epoll 循环统一处理

## 代码示例

```c
#include <signal.h>
#include <fcntl.h>
#include <unistd.h>
#include <sys/stat.h>

/* 安全打开文件：屏蔽信号 + 避免 TOCTOU */
int safe_open(const char *path, int flags, mode_t mode)
{
    sigset_t mask, oldmask;
    int fd;
    struct stat st;

    /* 屏蔽所有信号 */
    sigfillset(&mask);
    sigprocmask(SIG_BLOCK, &mask, &oldmask);

    /* 打开文件（不依赖之前的 access 检查） */
    fd = open(path, flags | O_NOFOLLOW, mode);  /* O_NOFOLLOW 防符号链接 */
    if (fd == -1) {
        sigprocmask(SIG_SETMASK, &oldmask, NULL);
        return -1;
    }

    /* 用 fstat 而非 stat 检查文件属性（避免 TOCTOU） */
    if (fstat(fd, &st) == -1) {
        close(fd);
        sigprocmask(SIG_SETMASK, &oldmask, NULL);
        return -1;
    }

    /* 验证文件不是符号链接、属主正确 */
    if (!S_ISREG(st.st_mode) || (st.st_mode & S_IWOTH)) {
        close(fd);
        sigprocmask(SIG_SETMASK, &oldmask, NULL);
        return -1;
    }

    /* 恢复信号 */
    sigprocmask(SIG_SETMASK, &oldmask, NULL);
    return fd;
}
```

## 代码自测

<details>
<summary>为什么 `access()` + `open()` 模式不安全？</summary>

`access()` 检查的是真实 UID/GID 的权限，而 `open()` 使用有效 UID/GID。在特权程序中（setuid），两者不同。更重要的是，在 `access()` 和 `open()` 之间，攻击者可以替换文件（如用符号链接指向另一个文件），这就是 TOCTOU（Time-of-Check to Time-of-Use）攻击。正确做法是直接 `open()` 后用 `fstat()` 检查。

</details>

<details>
<summary>信号处理函数中为什么不能调用 `printf`？</summary>

`printf` 不是异步信号安全函数。它内部使用 `malloc`/`stdio` 缓冲区等非可重入资源。如果在信号处理期间主程序正在使用这些资源，会导致缓冲区损坏或死锁。信号处理函数只应调用异步信号安全函数（如 `write`），或仅设置 `volatile sig_atomic_t` 标志。

</details>
