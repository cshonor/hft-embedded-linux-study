# 38.4 Avoid Exposing Sensitive Information

> 本章：[TLPI 第 38 章](./README.md)

## 本节讲什么

特权程序必须避免向非特权用户泄露敏感信息。泄露途径包括：环境变量传递、命令行参数可见性、核心转储、临时文件残留、错误信息过度暴露等。

## 要点

### 常见泄露途径与对策

| 泄露途径 | 风险 | 对策 |
|---------|------|------|
| 命令行参数 | `ps`/`top` 可见 | 用文件/管道传密码，不直接传 `argv` |
| 环境变量 | 子进程继承 | 敏感数据不存 env，或用后 `unsetenv` |
| 临时文件 | `/tmp` 可读 | `O_CREAT\|O_EXCL` + `0600` 权限 |
| 核心转储 | 含内存数据 | `setrlimit(RLIMIT_CORE, 0)` |
| 错误信息 | 泄露路径/结构 | 只向日志写细节，用户看通用消息 |
| `argv[0]` 伪装 | `ps` 中暴露 | `prctl(PR_SET_NAME)` 改进程名 |

### 关键原则

- **最小暴露面**：只输出用户需要知道的信息
- **日志分级**：详细错误写 syslog，用户看到的是通用提示
- **内存清理**：用完敏感数据后 `memset`/`explicit_bzero` 清零
- **避免核心转储**：特权程序应禁用 core dump

## HFT / 嵌入式关联

- 嵌入式设备中，固件更新程序常以 root 运行，需避免在日志中暴露密钥
- HFT 交易系统的 API key/证书路径不应出现在命令行参数中
- 量化回测框架的数据库连接串应从受保护配置文件读取，而非环境变量

## 代码示例

```c
#include <sys/resource.h>
#include <string.h>
#include <errno.h>

void secure_init(void)
{
    /* 禁用 core dump，防止内存中的敏感数据被提取 */
    struct rlimit rl = { 0, 0 };
    setrlimit(RLIMIT_CORE, &rl);

    /* 清除可能继承的敏感环境变量 */
    unsetenv("DB_PASSWORD");
    unsetenv("API_SECRET_KEY");
}

/* 安全地清除内存中的敏感数据（防止编译器优化掉 memset） */
void secure_bzero(void *ptr, size_t len)
{
    /* explicit_bzero 是 POSIX.1-2008 标准，不会被优化掉 */
    explicit_bzero(ptr, len);
}

/* 安全的错误报告：用户看通用消息，细节写 syslog */
void report_error(const char *user_msg, const char *detail)
{
    /* syslog 写详细信息 */
    syslog(LOG_ERR, "Error: %s (errno=%d: %s)", detail, errno, strerror(errno));
    /* 用户只看到通用提示 */
    fprintf(stderr, "%s\n", user_msg);
}
```

## 代码自测

<details>
<summary>为什么 `memset(ptr, 0, len)` 可能不安全？</summary>

编译器在优化时，如果看到 `memset` 之后该内存不再被使用，可能会将 `memset` 调用完全删除（死代码消除）。这会导致敏感数据残留在内存中。应使用 `explicit_bzero()` 或 `memset_s()`（C11 Annex K），它们保证不被优化掉。

</details>

<details>
<summary>特权程序为什么要禁用 core dump？</summary>

Core dump 包含进程内存的完整映像，可能包含密码、密钥、令牌等敏感数据。如果特权程序崩溃，任何能读取 core 文件的用户都能提取这些信息。通过 `setrlimit(RLIMIT_CORE, 0)` 禁用 core dump 是防御措施之一。

</details>
