# 38.10 Beware of Denial-of-Service Attacks

> 本章：[TLPI 第 38 章](./README.md)

## 本节讲什么

特权程序可能成为拒绝服务攻击的目标。攻击者通过耗尽资源（CPU、内存、文件描述符、磁盘空间）或触发无限循环来使程序不可用。

## 要点

### DoS 攻击向量与防御

| 攻击向量 | 说明 | 防御 |
|---------|------|------|
| 内存耗尽 | 大量分配不释放 | `setrlimit(RLIMIT_AS)` 限制 |
| FD 耗尽 | 打开大量连接 | `setrlimit(RLIMIT_NOFILE)` + 连接数限制 |
| CPU 耗尽 | 正则/计算无限循环 | `setrlimit(RLIMIT_CPU)` + 超时 |
| 磁盘耗尽 | 日志/临时文件写满 | 磁盘配额 + 日志轮转 |
| Fork 炸弹 | 无限创建子进程 | `setrlimit(RLIMIT_NPROC)` |
| 文件锁 | 持有锁不释放 | 锁超时机制 |
| `alarm` 信号 | 长时间操作 | `alarm(timeout)` 中断 |

### 资源限制设置

```c
struct rlimit rl;

/* 限制 CPU 时间：30 秒 */
rl.rlim_cur = 30; rl.rlim_max = 30;
setrlimit(RLIMIT_CPU, &rl);

/* 限制文件大小：10 MB */
rl.rlim_cur = 10 * 1024 * 1024; rl.rlim_max = rl.rlim_cur;
setrlimit(RLIMIT_FSIZE, &rl);

/* 限制进程数 */
rl.rlim_cur = 100; rl.rlim_max = 100;
setrlimit(RLIMIT_NPROC, &rl);
```

### 网络服务防御

- **连接超时**：`setsockopt(SO_RCVTIMEO/SO_SNDTIMEO)`
- **速率限制**：令牌桶算法控制请求频率
- **最大连接数**：epoll 事件循环中限制活跃连接
- **请求大小限制**：先读长度头，拒绝超大请求

## HFT / 嵌入式关联

- 行情网关必须设置 FD 和内存限制，防止恶意连接耗尽资源
- 交易系统用 `alarm()` 为每个订单操作设置超时，防止阻塞
- 嵌入式设备内存有限，需严格控制每个连接的缓冲区大小

## 代码示例

```c
#include <sys/resource.h>
#include <signal.h>
#include <unistd.h>
#include <stdio.h>

/* 为特权程序设置资源限制 */
void set_resource_limits(void)
{
    struct rlimit rl;

    /* 限制 CPU 时间 30 秒 */
    rl.rlim_cur = 30; rl.rlim_max = 30;
    setrlimit(RLIMIT_CPU, &rl);

    /* 限制虚拟内存 256 MB */
    rl.rlim_cur = 256L * 1024 * 1024;
    rl.rlim_max = rl.rlim_cur;
    setrlimit(RLIMIT_AS, &rl);

    /* 限制文件描述符数 64 */
    rl.rlim_cur = 64; rl.rlim_max = 64;
    setrlimit(RLIMIT_NOFILE, &rl);

    /* 限制文件大小 1 MB（防止日志写满磁盘） */
    rl.rlim_cur = 1024 * 1024; rl.rlim_max = rl.rlim_cur;
    setrlimit(RLIMIT_FSIZE, &rl);

    /* 限制 fork 进程数 0（不需要子进程） */
    rl.rlim_cur = 0; rl.rlim_max = 0;
    setrlimit(RLIMIT_NPROC, &rl);
}

/* 操作超时模式 */
void timed_operation(void)
{
    /* 设置 10 秒 alarm */
    alarm(10);
    /* 执行可能阻塞的操作... */
    do_blocking_work();
    /* 取消 alarm */
    alarm(0);
}

/* SIGALRM 处理：操作超时 */
static volatile sig_atomic_t timed_out = 0;
void alarm_handler(int sig) { timed_out = 1; }
```

## 代码自测

<details>
<summary>为什么 `RLIMIT_NPROC` 设为 0 可以防止 fork 炸弹？</summary>

`RLIMIT_NPROC` 限制用户可创建的进程数。设为 0 意味着该用户不能创建任何新进程（`fork()` 返回 `EAGAIN`）。如果特权程序不需要创建子进程，将其设为 0 可以彻底防止 fork 炸弹攻击。注意此限制针对用户 ID，不是单个进程。

</details>

<details>
<summary>网络服务中为什么需要同时设置连接超时和请求大小限制？</summary>

连接超时（如 30 秒）防止慢速攻击（slowloris），攻击者发送极慢的数据保持连接不释放。请求大小限制防止攻击者发送超大请求体耗尽内存。两者互补：超时解决"慢"的问题，大小限制解决"大"的问题。缺少任何一个都可能被利用。

</details>
