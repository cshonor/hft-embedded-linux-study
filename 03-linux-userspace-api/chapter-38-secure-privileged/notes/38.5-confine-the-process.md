# 38.5 Confine the Process

> 本章：[TLPI 第 38 章](./README.md)

## 本节讲什么

限制特权进程的运行环境，减少被利用后的影响范围。核心思路：在完成特权操作后立即丢弃权限、使用 `chroot` 改变文件系统根目录、使用最小权限原则。

## 要点

### 权限丢弃策略

| 策略 | API | 说明 |
|------|-----|------|
| 永久丢弃 UID | `setuid(getuid())` | 切换回调用者 UID，不可恢复 |
| 永久丢弃 GID | `setgid(getgid())` | 同上，针对组 |
| 临时切换 | `seteuid()`/`setegid()` | 可恢复，但需谨慎 |
| 清除补充组 | `setgroups(0, NULL)` | 必须在 setgid 之前调用 |

### chroot 限制

```c
chroot("/safe/chroot");   /* 改变文件系统根 */
chdir("/");               /* 必须立即 chdir，否则旧根仍可访问 */
```

- `chroot` 不是安全沙箱：root 用户可以逃逸（如通过 `chroot(".")` 再次改变根）
- 必须先 `chroot`，再丢弃 root 权限
- chroot 环境需要包含必要的库文件和设备节点

### 最小权限操作顺序

```
1. 打开特权资源（绑定端口 < 1024 等）
2. chroot 到受限目录（如果使用）
3. setgroups(0, NULL)  清除补充组
4. setgid()            设置真实 GID
5. setuid()            设置真实 UID（最后一步，不可逆）
6. 继续非特权操作
```

## HFT / 嵌入式关联

- 交易网关：绑定 443 端口后立即 `setuid` 到专用交易用户
- 嵌入式 Web 服务器：初始化后丢弃 root，仅保留 `CAP_NET_BIND_SERVICE`
- 策略引擎沙箱：用 `chroot` 将策略进程限制在数据目录中

## 代码示例

```c
#include <unistd.h>
#include <sys/types.h>
#include <grp.h>
#include <stdio.h>

/* 权限丢弃的典型模式 */
int drop_privileges(const char *chroot_dir)
{
    uid_t ruid = getuid();  /* 真实用户 ID */
    gid_t rgid = getgid();  /* 真实组 ID */

    /* 1. 如果需要 chroot，在丢权限前做 */
    if (chroot_dir != NULL) {
        if (chroot(chroot_dir) == -1) {
            perror("chroot");
            return -1;
        }
        if (chdir("/") == -1) {  /* 必须立即 chdir */
            perror("chdir");
            return -1;
        }
    }

    /* 2. 清除补充组（必须在 setgid 前） */
    if (setgroups(0, NULL) == -1) {
        perror("setgroups");
        return -1;
    }

    /* 3. 设置 GID */
    if (setgid(rgid) == -1) {
        perror("setgid");
        return -1;
    }

    /* 4. 设置 UID（最后一步，不可逆） */
    if (setuid(ruid) == -1) {
        perror("setuid");
        return -1;
    }

    /* 验证权限已丢弃 */
    if (setuid(0) != -1) {
        fprintf(stderr, "Failed to drop root privileges!\n");
        return -1;
    }
    return 0;
}
```

## 代码自测

<details>
<summary>为什么 `setgroups(0, NULL)` 必须在 `setgid()` 之前调用？</summary>

`setgroups()` 需要 root 权限才能修改补充组列表。如果先执行 `setgid()` 丢弃了 root 权限，后续的 `setgroups()` 调用会失败，导致旧的补充组（可能包含 root 组）仍然保留，造成权限泄露。

</details>

<details>
<summary>为什么 `chroot` 不能作为安全沙箱？</summary>

`chroot` 仅改变文件系统根目录，但不改变进程的 root 权限。拥有 root 权限的进程可以通过多种方式逃逸 chroot：使用 `chroot(".")` 创建新的 chroot、通过文件描述符访问旧根、利用 `mknod` 创建设备文件等。正确做法是先 `chroot`，再丢弃 root 权限。

</details>
