# 47.7 Handling of Multiple Blocked Semaphore Operations

> 本章：[TLPI 第 47 章](./README.md)

## 本节讲什么

当 `semop()` 的操作数组中部分操作可执行、部分需阻塞时的内核处理策略，以及死锁检测和取消行为。

## 要点

### 原子性规则

`semop()` 操作数组的**所有操作是原子的**：
- 要么全部立即执行
- 要么全部阻塞等待
- 不会部分执行

### 内核处理流程

```
1. 检查所有 sops 的 sem_op 能否满足
   - sem_op > 0: 总能满足
   - sem_op = 0: 需要值 == 0
   - sem_op < 0: 需要值 >= |sem_op|

2. 如果全部可满足 → 全部执行 → 返回 0

3. 如果任一不满足:
   a. 无 IPC_NOWAIT → 阻塞等待
   b. 有 IPC_NOWAIT → 立即返回 EAGAIN
```

### 阻塞时的唤醒策略

当信号量值变化，内核按 FIFO 顺序检查阻塞队列中的等待者：

```
等待者队列: [A: sem[0] -= 1] [B: sem[1] = 0] [C: sem[0] -= 2]
sem[0] 变为 3:
  → 尝试 A: 3 >= 1 → 执行 → sem[0] = 2
  → 尝试 B: sem[1] 未变 → 不满足
  → 尝试 C: 2 >= 2 → 执行 → sem[0] = 0
```

### 唤醒的不确定性

- **不保证公平性**：唤醒顺序由内核策略决定
- **饥饿可能**：低优先级等待者可能被反复跳过
- **批量唤醒**：一个 V 操作可能唤醒多个等待者

### 死锁风险

```
进程 A: semop(semid, [{0, -1}, {1, +1}])  // 等 sem[0]
进程 B: semop(semid, [{1, -1}, {0, +1}])  // 等 sem[1]
→ A 持有 sem[0] 等 sem[1]，B 持有 sem[1] 等 sem[0]
→ 经典死锁！
```

### 信号中断处理

```c
/* semop 被信号中断时返回 -1, errno = EINTR */
struct sigaction sa = {.sa_handler = handler};
sigaction(SIGINT, &sa, NULL);

int ret;
do {
    ret = semop(semid, &op, 1);
} while (ret == -1 && errno == EINTR);
/* 自动重启（Linux 默认不自动重启 semop） */
```

### semop 与信号交互

| 场景 | 行为 |
|------|------|
| 信号中断 | 返回 -1, errno = EINTR |
| SA_RESTART | semop **不**自动重启（与 read 不同） |
| 信号处理 + semop | 需手动重试 |

## HFT / 嵌入式关联

- HFT 进程间同步避免使用 SysV 信号量（死锁风险高）
- 必须使用时：确保操作顺序一致，避免交叉等待
- `semtimedop` 限制等待时间，降低死锁影响
- 嵌入式系统使用信号量保护共享硬件资源

## 代码示例

```c
#include <sys/sem.h>
#include <stdio.h>
#include <errno.h>
#include <string.h>
#include <time.h>

/* 安全的 semop：处理 EINTR */
int safe_semop(int semid, struct sembuf *ops, size_t nops) {
    int ret;
    do {
        ret = semop(semid, ops, nops);
    } while (ret == -1 && errno == EINTR);
    return ret;
}

/* 带超时和 EINTR 处理 */
int safe_semop_timeout(int semid, struct sembuf *ops, size_t nops,
                        int timeout_sec) {
    int ret;
    struct timespec ts = {.tv_sec = timeout_sec};
    do {
        ret = semtimedop(semid, ops, nops, &ts);
        /* 超时后重置 timeout（已消耗的时间需要重新计算） */
    } while (ret == -1 && errno == EINTR);
    return ret;
}

/* 避免死锁的资源获取：按固定顺序 */
int acquire_two_semaphores(int semid) {
    /* 总是先 sem[0] 再 sem[1]，避免交叉死锁 */
    struct sembuf ops[2] = {
        {0, -1, SEM_UNDO},  /* 先获取 sem[0] */
        {1, -1, SEM_UNDO},  /* 再获取 sem[1] */
    };
    /* 原子执行：如果 sem[0] 够但 sem[1] 不够，全部阻塞 */
    return safe_semop_timeout(semid, ops, 2, 5);
}
```

## 代码自测

<details>
<summary>semop 操作数组中一个操作需要阻塞，其他操作可以立即执行，内核如何处理？</summary>

内核不会部分执行操作数组。如果任何一个操作不满足（需阻塞），整个操作数组都不会执行，进程阻塞直到所有操作都能满足。这保证了原子性：不会出现"执行了前半部分但后半部分阻塞"的中间状态。如果设置了 `IPC_NOWAIT`，任一操作不满足就立即返回 EAGAIN，不执行任何操作。

</details>
