# 47.12 Summary

> 本章：[TLPI 第 47 章](./README.md)

## 本节讲什么

第 47 章总结：System V 信号量的完整 API、操作模式和设计缺陷。

## 要点

### API 总览

| API | 用途 |
|-----|------|
| `ftok()` | 生成 IPC key |
| `semget()` | 创建/打开信号量集 |
| `semop()` | 原子操作（P/V/等待零） |
| `semtimedop()` | 带超时的 semop |
| `semctl(IPC_RMID)` | 删除信号量集 |
| `semctl(SETVAL/SETALL)` | 设置初始值 |
| `semctl(IPC_STAT)` | 获取信息 |
| `ipcs -s` | 查看系统信号量 |
| `ipcrm -s` | 删除信号量 |

### 操作模式

| 操作 | sem_op | 效果 |
|------|--------|------|
| P (获取锁) | -1 | 值减1，不足则阻塞 |
| V (释放锁) | +1 | 值加1，唤醒等待者 |
| 等待零 | 0 | 阻塞到值=0 |

### 关键标志

| 标志 | 用途 |
|------|------|
| `IPC_CREAT` | 创建信号量 |
| `IPC_EXCL` | 独占创建 |
| `SEM_UNDO` | 进程退出自动撤销 |
| `IPC_NOWAIT` | 非阻塞模式 |

### 信号量集 vs 单信号量

SysV 信号量操作的是**集合**（多个信号量值），而非单个。`semop` 可以原子操作集合中的多个信号量。

### 生命周期

```
semget(IPC_CREAT) → 创建（值为0）
  ↓
semctl(SETVAL) → 初始化
  ↓
semop() → P/V 操作
  ↓
semctl(IPC_RMID) → 显式删除
```

**注意**：进程退出后信号量仍存在，直到 IPC_RMID 或系统重启。

### 主要缺点

1. 创建+初始化非原子
2. semop 不自动重启
3. 内核限制多
4. IPC 资源泄漏
5. API 复杂

### 现代 API 推荐

| 场景 | 推荐 |
|------|------|
| 进程间互斥 | POSIX 信号量 |
| 线程同步 | pthread 互斥 |
| 超时等待 | `sem_timedwait()` |
| 文件锁 | `fcntl(F_SETLK)` |

## HFT / 嵌入式关联

- HFT 新开发优先使用 POSIX 信号量或 pthread 互斥锁
- SysV 信号量维护遗留系统：用 `ipcs -s` 监控，`ipcrm -s` 清理
- `SEM_UNDO` 防止崩溃死锁（但 POSIX 互斥不提供等价机制）

## 代码自测

<details>
<summary>SEM_UNDO 在什么场景下特别重要？为什么 POSIX 信号量没有等价机制？</summary>

`SEM_UNDO` 在进程可能崩溃的锁场景下重要：进程获取锁后崩溃，内核自动回滚（释放锁），其他进程不会被永久阻塞。POSIX 命名信号量和互斥锁在进程崩溃时**不会**自动释放（`sem_post` 不会被调用），其他等待者会永久阻塞。POSIX 的 `robust mutex`（`pthread_mutexattr_setrobust`）提供了类似功能：持有者崩溃时，下一个获取者会得到 `EOWNERDEAD`，需调用 `pthread_mutex_consistent` 恢复。

</details>
