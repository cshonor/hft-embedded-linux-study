# 47.6 Semaphore Operations: semop()

> 本章：[TLPI 第 47 章](./README.md)

## 本节讲什么

`semop()` 是 System V 信号量的核心操作函数，执行原子性的信号量增减和等待操作。支持操作数组、非阻塞和撤销操作。

## 要点

### semop() 函数

```c
#include <sys/sem.h>
int semop(int semid, struct sembuf *sops, size_t nsops);
// 返回：0 成功，-1 失败
```

### struct sembuf

```c
struct sembuf {
    unsigned short sem_num;  /* 信号量编号（0-based） */
    short          sem_op;   /* 操作值 */
    short          sem_flg;  /* 标志 */
};
```

### sem_op 含义

| sem_op | 行为 |
|--------|------|
| > 0 | V 操作：值增加 sem_op，唤醒等待者 |
| = 0 | 等待：阻塞直到值变为 0 |
| < 0 | P 操作：若值 ≥ |sem_op| 则减；否则阻塞等待 |

### sem_flg 标志

| 标志 | 效果 |
|------|------|
| 0 | 阻塞等待 |
| `IPC_NOWAIT` | 不阻塞，条件不满足时返回 EAGAIN |
| `SEM_UNDO` | 进程退出时自动撤销操作 |

### 原子操作数组

```c
struct sembuf ops[2] = {
    {0, -1, SEM_UNDO},  /* P 操作 sem[0] */
    {1, +1, SEM_UNDO},  /* V 操作 sem[1] */
};
semop(semid, ops, 2);  /* 原子执行两个操作 */
```

所有操作**要么全部成功，要么全部不执行**。

### SEM_UNDO 机制

内核维护每个进程的 semadj（调整值）：
- `SEM_UNDO` 操作记录在 semadj 中
- 进程正常/异常退出时，内核自动回滚 semadj 记录的操作
- 防止进程崩溃时持有锁导致死锁

### 常见操作模式

| 模式 | sem_op | sem_flg | 用途 |
|------|--------|---------|------|
| 获取锁 | -1 | SEM_UNDO | P 操作 |
| 释放锁 | +1 | SEM_UNDO | V 操作 |
| 等待零 | 0 | 0 | 阻塞到归零 |
| 非阻塞尝试 | -1 | IPC_NOWAIT | 条件获取 |

### 超时控制

`semtimedop()` (Linux 扩展) 支持超时：

```c
#include <time.h>
struct timespec timeout = {.tv_sec = 5};
int ret = semtimedop(semid, ops, nops, &timeout);
// 超时返回 -1，errno = EAGAIN
```

## HFT / 嵌入式关联

- SysV 信号量做进程间互斥（多策略进程共享资源）
- `SEM_UNDO` 防止进程崩溃导致死锁
- `semtedop` 超时避免无限等待
- 现代更推荐 POSIX 信号量/pthread 互斥

## 代码示例

```c
#include <sys/sem.h>
#include <stdio.h>
#include <time.h>

union semun { int val; struct semid_ds *buf; unsigned short *array; };

/* 获取信号量锁 */
int sem_lock(int semid, int semnum) {
    struct sembuf op = {
        .sem_num = semnum,
        .sem_op = -1,
        .sem_flg = SEM_UNDO,
    };
    return semop(semid, &op, 1);
}

/* 释放信号量锁 */
int sem_unlock(int semid, int semnum) {
    struct sembuf op = {
        .sem_num = semnum,
        .sem_op = +1,
        .sem_flg = SEM_UNDO,
    };
    return semop(semid, &op, 1);
}

/* 带超时的获取 */
int sem_lock_timeout(int semid, int semnum, int sec) {
    struct sembuf op = {
        .sem_num = semnum,
        .sem_op = -1,
        .sem_flg = SEM_UNDO,
    };
    struct timespec ts = {.tv_sec = sec};
    return semtimedop(semid, &op, 1, &ts);
}

/* 原子操作：获取一个释放另一个 */
int sem_transfer(int semid, int acquire, int release) {
    struct sembuf ops[2] = {
        {acquire,  -1, SEM_UNDO},
        {release,  +1, SEM_UNDO},
    };
    return semop(semid, ops, 2);
}
```

## 代码自测

<details>
<summary>SEM_UNDO 的原理和限制是什么？</summary>

**原理**：内核为每个进程-信号量对维护一个 semadj（调整计数器）。`SEM_UNDO` 标志的 `semop` 会累加 semadj（P 操作记负，V 操作记正）。进程退出时内核自动用 semadj 的反值恢复信号量值，释放可能持有的锁。

**限制**：(1) semadj 是 int，可能溢出；(2) 进程被 SIGKILL 杀死时 SEM_UNDO 仍然生效（内核处理）；(3) 多线程中 semadj 是进程级共享的，不是线程级；(4) 只对单个信号量值回滚，无法处理复杂的操作序列。

</details>
