# 6.4 虚拟内存管理：地址是假的，物理页是欠着的

> 源码核验：Linux v6.6 · `mm/memory.c:4067`（`do_anonymous_page`）· `:164`（`zero_pfn`）· 详见 [06-linux-mm](../../../06-linux-mm/README.md) 与 [Ch49.7 匿名映射](../../chapter-49-memory-mappings/notes/49.7-anonymous-mappings.md)

## 本节讲什么

6.3 说的是"地址排布"，这一节说的是**这套地址是假的**：你拿到的每一条虚拟地址都要经过页表翻译才落到物理页，而**物理页是等到你第一次碰它才分配的**（按需分页 / demand paging）。

这一节只钉一件事，但它是后续全部性能讨论的地基：

> **`malloc` 返回成功 ≠ 拿到物理内存。** 地址空间是"记账"，物理页是"欠着"，首次访问才真的付。

---

## 要点

### 三件套：页表、MMU、缺页

| 概念 | 一句话 |
|------|--------|
| 虚拟地址 | 进程看到并使用的地址，每个进程独立 |
| 页表 | 内核为每个进程维护的"虚拟页 → 物理页帧"映射表 |
| MMU | CPU 里的硬件，负责查页表做翻译 |
| 缺页异常（page fault） | 访问的页**还没装进页表**时触发，内核介入补上再重试指令 |
| 按需分页 | 页的物理分配**推迟到首次访问**，不是 `mmap`/`malloc` 时 |
| 全局零页 | 内核里一个共享的只读全零物理页；读没写过的匿名页时**大家指同一页**，不占各自 RSS |
| swap | 内存紧张时把页换到磁盘；被换出的页访问时再换入 |

### 关键区分：地址空间 ≠ 物理内存

| 动作 | 做了什么 | RSS 变吗 |
|------|---------|---------|
| `malloc(128MB)` | glibc 用 mmap 登记一段 VMA（只记地址范围） | **不变** |
| 读这段内存 | 每次读缺页都挂到**全局零页** | **基本不变** |
| 写这段内存 | 首写才分配清零物理页 | **按写入量涨** |
| `mlock()` | 强制把页装进来并锁定 | 立刻涨 |

## 代码

完整程序见 [`../code/c6_4_vm_demand.c`](../code/c6_4_vm_demand.c)：申请 128MB，然后在"未触碰 / 全量读 / 写一半"三个阶段分别查 `/proc/self/statm` 的常驻集。

```c
/* c6_4_vm_demand.c — 6.4 虚拟内存：按需分页 / 零页 / RSS 只统计真碰过的页
 * 编译: gcc -O2 -Wall -Wextra -o c6_4_vm_demand c6_4_vm_demand.c
 */
#define _GNU_SOURCE
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <unistd.h>
#include <fcntl.h>

#define MB (1024UL * 1024)

/* 用 /proc/self/statm 第 2 列拿常驻集（单位：页） */
static long rss_pages(void)
{
    int fd = open("/proc/self/statm", O_RDONLY);
    if (fd < 0) return -1;
    char b[128];
    ssize_t n = read(fd, b, sizeof b - 1);
    close(fd);
    if (n <= 0) return -1;
    b[n] = 0;
    long size = 0, resident = 0;
    sscanf(b, "%ld %ld", &size, &resident);
    return resident;
}

static void report(const char *tag, long base, long ps)
{
    long r = rss_pages();
    printf("  %-26s RSS = %6.1f MB  (%+.1f MB)\n",
           tag, (double)r * ps / MB, (double)(r - base) * ps / MB);
}

int main(void)
{
    long ps = sysconf(_SC_PAGESIZE);
    printf("页大小 = %ld B\n", ps);

    /* 1. malloc 128MB：只是登记 VMA，一个物理页都没给 */
    size_t sz = 128 * MB;
    char *p = malloc(sz);
    if (!p) { perror("malloc"); return 1; }
    long base = rss_pages();
    report("malloc(128MB) 后", base, ps);

    /* 2. 只读一遍：读缺页挂全局零页，RSS 纹丝不动 */
    long sum = 0;
    for (size_t i = 0; i < sz; i += (size_t)ps)
        sum += p[i];
    report("全量读一遍后", base, ps);

    /* 3. 写一半：首写才分配清零实页 */
    memset(p, 0x5A, sz / 2);
    report("写前一半后", base, ps);

    printf("  (读到的字节和 = %ld，证明页确实被访问过)\n", sum);
    free(p);
    return 0;
}
```

编译与运行：

```bash
gcc -O2 -Wall -Wextra -o c6_4_vm_demand c6_4_vm_demand.c && ./c6_4_vm_demand
```

实测输出（另在 Compiler Explorer 复核，gcc 13.3，4KB 页）：

```text
页大小 = 4096 B
  malloc(128MB) 后          RSS =    1.6 MB  (+0.1 MB)
  全量读一遍后         RSS =    1.6 MB  (+0.2 MB)
  写前一半后            RSS =   65.6 MB  (+64.2 MB)
  (读到的字节和 = 0，证明页确实被访问过)
```

**解读**：

- **+0.1 MB**：`malloc` 128 MB 后 RSS 几乎没动。内核只登记了一段 VMA，物理账上一页未付。
- **+0.2 MB**：把 128 MB **逐页读了一遍**（32768 次缺页！），RSS 仍然没涨。因为读缺页由内核用 `do_anonymous_page()`（`mm/memory.c:4067`）的零页分支满足——**只装 PTE，指向那个全局只读零页**（`zero_pfn`，`:164`）。零页不属于任何进程，连 RSS 都不计。
- **+64.2 MB**：写前一半（64 MB）→ 恰好涨 64 MB。这才是真正分配：每个首写页分到一个**清零的新物理页**。
- **`读到的字节和 = 0` 不是 bug**：这 128 MB 从没写过，读出来当然全 0——正好反证"读的是零页"。

⚠️ 一个比"COW 复制零页"更精确的说法：首写匿名私有页时内核调的是 `vma_alloc_zeroed_movable_folio()` **直接分配清零页**，并没有发生"从零页 memcpy"（目标本来就是全 0，清零更便宜）。"复制零页"只出现在 fork 之后的 `wp_page_copy()` 特判里。完整辨析见 [Ch49.7](../../chapter-49-memory-mappings/notes/49.7-anonymous-mappings.md)。

## HFT / 嵌入式关联

| 路线 | 要点 |
|------|------|
| 嵌入式 | 没有 swap、没有 overcommit 的裸机/RTOS 上，"申请即分配"是常态。从 Linux 移植过去时，凡依赖"按需分配"的内存估算都要重算 |
| HFT | **懒分配是确定性延迟的敌人**：热路径上的首次访问会触发缺页 + 清零（还可能触发内存回收），延迟从 ns 级跳到 μs 级。标准做法是启动时 `mlockall(MCL_CURRENT\|MCL_FUTURE)` + 把热区**全量触碰一遍**（预热），把毛刺挤到开盘前 |
| HFT | 反过来，"申请 1TB 成功"和"物理耗尽 OOM"可以相隔任意久——overcommit 让 `malloc` 的返回值**不能用作"内存够不够"的判据**。要做容量规划必须看 `/proc/meminfo` 的 `Committed_AS` 与 `MemAvailable` |
| HFT | 大页（huge pages）减少 TLB miss，但**大页不享受零页优化**（必须立刻分配），预热成本更高 |

## 自测题

**题目 1：** `mmap` 返回成功、也读到了全 0，物理内存分配了吗？

<details>
<summary>参考答案</summary>

对"被读过的那批页"来说没有。读路径的缺页由 `do_anonymous_page():4086` 用零页满足：只装 PTE，不分配物理页。零页是内核全局共享的只读页，连 RSS 都不计入（实测 A2 阶段 +0.2 MB 就是证据）。真正的物理分配推迟到**首写**。

</details>

**题目 2：** 上面实测中「全量读一遍 128MB」触发了 32768 次缺页，为什么 RSS 只涨了 0.2 MB？

<details>
<summary>参考答案</summary>

因为读缺页只需要装一条 PTE 指向全局零页，不需要分配物理页。涨的 0.2 MB 是零散的页表页（页表本身也要内存）和少量噪声，不是 128 MB 的数据页。这也是「缺页次数多 ≠ 内存占用高」的最好例证。

</details>

**题目 3：** 为什么说 `malloc` 成功不能作为"内存够用"的判据？

<details>
<summary>参考答案</summary>

因为默认的 overcommit 策略（heuristic）允许已登记的 VMA 总量超过 RAM + swap，分配只记账不付物理页。所以"申请 1TB 返回成功"和之后"写满时 OOM 被 kill"可以相隔任意久。要判断真实余量得看 `/proc/meminfo` 的 `Committed_AS`（已承诺量）与 `MemAvailable`（可用量），而不是看 `malloc` 的返回值。

</details>
