# 6.2 PID 与 PPID：两个 PID，和孤儿是怎么被收养的

> 源码核验：Linux v6.6 · `kernel/sys.c:958`（`SYSCALL_DEFINE0(getpid)`）· `:964`（`gettid`）· `:975`（`SYSCALL_DEFINE0(getppid)`）· `include/linux/sched.h:1584`（`task_pid_vnr`）· `:1636`（`task_tgid_vnr`）
> 本章：[TLPI 第 06 章 — Processes](../README.md)
> - 上一节：[6.1 进程基本概念](./6.1-basic-concepts-process.md)

## 本节讲什么

进程的第一个身份标识是 **PID**，第二个是 **PPID**（父进程 PID）。这一节要钉死三件事：

1. **内核里其实有两个"PID"**：`task_struct.pid`（线程号）和 `task_struct.tgid`（进程号）。`getpid()` 返回的是 **tgid**，不是 pid。
2. **`getpid` / `getppid` 永不失败**——源码里连 `-1` 都没有，不需要判错。
3. **父进程先退出，子进程的 PPID 会被内核改写**（"孤儿收养"），这是可观测的。

---

## 要点

### API 与返回值

```c
#include <unistd.h>
pid_t getpid(void);    /* 返回 TGID（线程组 ID）；绝不失败 */
pid_t getppid(void);   /* 返回父进程的 TGID；绝不失败 */
pid_t gettid(void);    /* Linux 专有：返回内核内部线程号（task_struct.pid） */
```

### 内核源码：两个 PID 到底差在哪

```c
/* kernel/sys.c (v6.6) —— 注释原文："SMP safe as current->tgid does not change" */
SYSCALL_DEFINE0(getpid)                        /* :958 */
{
	return task_tgid_vnr(current);         /* :960  -> 返回 TGID */
}

/* Thread ID - the internal kernel "pid" */
SYSCALL_DEFINE0(gettid)                        /* :964 */
{
	return task_pid_vnr(current);          /* :966  -> 返回 task_struct.pid */
}

SYSCALL_DEFINE0(getppid)                       /* :975 */
{
	int pid;

	rcu_read_lock();                       /* :979 */
	pid = task_tgid_vnr(rcu_dereference(current->real_parent));   /* :980 */
	rcu_read_unlock();                     /* :981 */

	return pid;
}
```

| 名字 | 取的字段 | 相同进程内多线程时 |
|------|---------|-------------------|
| `getpid()` / `task_tgid_vnr()` | `task_struct.tgid` | **所有线程相同** |
| `gettid()` / `task_pid_vnr()` | `task_struct.pid` | 每个线程不同 |
| `getppid()` | `real_parent` 的 tgid | 所有线程相同 |

⚠️ `getppid` 这里有个容易忽略的点：源码注释（`:969-973`）明确写着 `->real_parent` 的读取不是 SMP 安全的，必须用 `rcu_read_lock()` 包着、且**只能接受"可能过期"的值**。这解释了为什么 6.2 结尾的现象是"父进程刚退出时 `getppid()` 可能还返回旧值一瞬"——不是 bug，是内核刻意的取舍。

### PPID 的四种取值

| 场景 | `getppid()` 得到什么 |
|------|---------------------|
| 常规 | 创建它的那个进程的 TGID |
| 父进程已退出（孤儿） | **1**（被 init/systemd 收养），现代发行版也可能是某个 `subreaper` |
| 调用者是 init/systemd（PID 1） | 0（它没有父） |
| 容器里 | 还是容器 PID 命名空间内的号，不是宿主机的号 |

### 进程组的两个配套函数

`getpgrp()` / `getsid(0)` 分别返回**进程组 ID** 和**会话 ID**——它们不是新概念，而是内核把"若干进程"分组管理用的 ID，详见 [Ch34 进程组、会话与控制终端](../../chapter-34-process-groups-sessions/notes)。

## 代码

完整程序见 [`../code/c6_2_pid_orphan.c`](../code/c6_2_pid_orphan.c)，分两段：A 段看正常父子，B 段人为造一个孤儿。

```c
/* c6_2_pid_orphan.c — 6.2 PID/PPID、子进程回收、孤儿进程（PPID 被改写）
 * 编译: gcc -O2 -Wall -Wextra -o c6_2_pid_orphan c6_2_pid_orphan.c
 */
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
#include <sys/wait.h>

static void say(const char *tag)
{
    printf("  [%-10s] pid=%-6d ppid=%-4d\n", tag, (int)getpid(), (int)getppid());
    fflush(stdout);   /* ⚠️ 子进程随后 _exit()，不 flush 的话这段输出会丢 */
}

int main(void)
{
    say("main");

    /* ---- A. 正常父子：子进程打印时父还活着 ---- */
    printf("--- A. fork 后父子各自的身份 ---\n");
    pid_t c = fork();
    if (c < 0) { perror("fork"); return 1; }
    if (c == 0) { say("child"); _exit(0); }

    int st = 0;
    pid_t w = wait(&st);
    printf("  wait 返回 %d（就是子进程 PID）；WIFEXITED=%d WEXITSTATUS=%d\n",
           (int)w, WIFEXITED(st), WEXITSTATUS(st));

    /* ---- B. 孤儿：让「中间父」先退，孙子的 PPID 被内核改写 ---- */
    printf("--- B. 中间父退出 -> 孙子变孤儿，PPID 被改写 ---\n");
    c = fork();
    if (c < 0) { perror("fork"); return 1; }
    if (c == 0) {
        pid_t g = fork();
        if (g < 0) _exit(1);
        if (g == 0) {                     /* 孙子 */
            sleep(1);                     /* 等中间父退出 */
            say("grandchild");
            printf("             ↑ 中间父已退出，PPID 不再是它，而是被 1 号进程收养\n");
            fflush(stdout);
            _exit(0);
        }
        _exit(0);                          /* 中间父立刻退出 -> 孙子成孤儿 */
    }
    wait(NULL);                            /* 只收得到中间父 */

    /* main 自己多活一会儿，等孙子把话说完（CE 沙箱里 main 一退就收走全部子进程） */
    sleep(2);
    printf("  [main      ] 收工（pid=%d）\n", (int)getpid());
    return 0;
}
```

编译与运行：

```bash
gcc -O2 -Wall -Wextra -o c6_2_pid_orphan c6_2_pid_orphan.c && ./c6_2_pid_orphan
```

实测输出（另在 Compiler Explorer 复核，gcc 13.3，容器环境）：

```text
  [main      ] pid=2      ppid=1
--- A. fork 后父子各自的身份 ---
  [child     ] pid=3      ppid=2
--- A. fork 后父子各自的身份 ---          ← ⚠️ 这一行出现了两次，见下面解读
  wait 返回 3（就是子进程 PID）；WIFEXITED=1 WEXITSTATUS=0
--- B. 中间父退出 -> 孙子变孤儿，PPID 被改写 ---
  [grandchild] pid=5      ppid=1          ← 中间父（pid=4）已退出，PPID 被改成 1
             ↑ 中间父已退出，PPID 不再是它，而是被 1 号进程收养
--- A. fork 后父子各自的身份 ---
  wait 返回 3（就是子进程 PID）；WIFEXITED=1 WEXITSTATUS=0
--- B. 中间父退出 -> 孙子变孤儿，PPID 被改写 ---
  [main      ] 收工（pid=2）
```

**解读（三个都值得记）**：

1. **孤儿收养的证据链**：`child` 打印时 `ppid=2`（父活着，指 main）；`grandchild` 打印时 `ppid=1`——它的直接父（pid=4，那个"中间父"）已经退出，内核把它**改挂到 1 号进程**名下。这就是 `getppid` 源码里 `rcu_dereference(current->real_parent)` 读到的字段被改写的结果。
2. **`wait()` 只等得到直接子进程**：`wait` 返回 3（A 段那个子进程），而对孙子完全无能为力——孙子不是 main 的孩子。这也是为什么"孤儿"在实现上没问题：它本来就不归你管了。
3. **⚠️ 输出里 `--- A. ---` 出现了两次，不是打印错了**：`printf` 的 stdout 在管道里是**全缓冲**的，`fork()` 会把**尚未 flush 的缓冲区一并复制**给子进程。子进程 `fflush` 时把自己那份（含父进程留下的 `--- A. ---`）刷了出来，父进程最后退出时又刷了一遍。这是 `fork` + `stdio` 最经典的坑，规避办法是 **`fork` 前 `fflush(NULL)`**，或子进程统一用 `_exit` + 显式 `write(2)`。

## HFT / 嵌入式关联

| 路线 | 要点 |
|------|------|
| 嵌入式 | PID 1 不一定是 systemd：BusyBox init、`tini`、或容器里的自己都是。写"孤儿会被 PID 1 收养"的代码时别假设 PID 1 一定是 systemd |
| HFT | 父子进程守护模型（父进程监控、崩溃重拉）里，子进程必须能检测"父没了"：常用手法是 `prctl(PR_SET_PDEATHSIG, SIGTERM)`，或用 `getppid() != 原值` 轮询（注意上面那条 RCU 注释，值可能短暂滞后） |
| HFT | 用 `gettid()` 而不是 `getpid()` 给线程命名/绑核：`taskset -p`、`sched_setaffinity`、perf 的线程标记都认 **tid** |

## 自测题

**题目 1：** 一个进程里三个线程各自调用 `getpid()`，返回值一样吗？`gettid()` 呢？

<details>
<summary>参考答案</summary>

`getpid()` 三个都一样——它是 `task_tgid_vnr(current)`（`kernel/sys.c:960`），读的是 **tgid**，同一线程组共享。`gettid()` 三个都不同——它是 `task_pid_vnr(current)`（`:966`），读的是 `task_struct.pid`，每个任务唯一。注意"线程"在 Linux 内核眼里就是一个 `task_struct`，所以有独立的 pid。

</details>

**题目 2：** 为什么 `getpid()` 永远不用检查返回值是不是 -1？

<details>
<summary>参考答案</summary>

因为它只是从 `current`（当前 task_struct）里读一个字段再换个命名空间，没有任何可能失败的操作——源码 `kernel/sys.c:958-961` 就是一行 `return task_tgid_vnr(current);`，没有错误分支。凡是没有失败路径的 syscall，包一层判 `-1` 是纯浪费。

</details>

**题目 3：** fork 之后子进程 `printf` 的内容有时会「重复打印两遍」，为什么？怎么避免？

<details>
<summary>参考答案</summary>

子进程 `_exit()` 不会 flush stdio 缓冲，而 `fork()` 会把父进程**尚未 flush 的缓冲区内容复制一份**给子进程。于是子进程刷一次、父进程退出时又刷一次，同一段文字出现两遍。避免办法：`fork()` 之前调用 `fflush(NULL)` 清空所有流；或者子进程里只用 `write(2)`（无缓冲）输出；或者子进程正常 `exit()`（会 flush，但可能把父进程的内容也带出来——所以首选 `fflush(NULL)`）。上面实测输出里 `--- A. ---` 出现两次就是这个现象。

</details>
