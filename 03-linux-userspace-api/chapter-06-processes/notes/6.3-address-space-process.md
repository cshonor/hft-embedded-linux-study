## 要点

用户空间（低 → 高，示意）：

```
高地址  ┌─────────────────────┐
        │  内核空间（用户不可访） │
        ├─────────────────────┤
        │  栈 Stack ↓         │  局部变量、参数、返回地址；ulimit -s
        ├─────────────────────┤
        │  mmap / 共享库 …    │
        ├─────────────────────┤
        │  堆 Heap ↑          │  malloc；边界 = program break（Ch7）
        ├─────────────────────┤
        │  BSS（未初始化数据）  │  加载时清零；磁盘映像几乎不占空间
        ├─────────────────────┤
        │  Data（已初始化数据） │  显式初始化的全局/静态
        ├─────────────────────┤
低地址  │  Text（代码段，只读） │  指令；同程序多进程可共享
        └─────────────────────┘
```

### 变量落点示例

```c
const char *s = "hello";  /* s：数据段；字面量：只读（常在 text/rodata） */
static int x;             /* BSS */
static int y = 5;         /* Data */
int main(void) {
    int z;                /* 栈 */
    int *p = malloc(4);   /* p 在栈；*p 在堆 */
}
```

## 常见陷阱

1. **返回值未检查**

```c
int *p = malloc(sizeof(int) * 1000);
p[0] = 42;  /* malloc 失败 → NULL → 段错误 */
```

malloc 失败返回 NULL。不检查直接用会导致段错误。Linux 上可能 OOM killer 先杀进程。

2. **use-after-free**

```c
free(p);
p[0] = 42;  /* UB! */
```

free 后访问已释放内存是未定义行为。free 后应立即置 NULL：`free(p); p = NULL;`。

3. **realloc 指针失效**

```c
int *p = malloc(100);
int *q = realloc(p, 200);
/* p 可能已失效，不能再用 */
```

realloc 可能返回新地址并释放旧地址。realloc 后不能再用旧指针。应 `p = realloc(p, size);`。

## 自测题

**题目 1（选择）：** `malloc(0)` 的返回值是？
A. NULL
B. 非 NULL 或 NULL（实现定义）
C. 一定非 NULL
D. 未定义行为

<details>
<summary>参考答案</summary>

B。malloc(0) 的行为是实现定义的：可能返回 NULL，也可能返回一个非 NULL 但不可解引用的指针。

</details>

**题目 2（判断）：** `free(NULL)` 是未定义行为。

<details>
<summary>参考答案</summary>

错误。free(NULL) 是安全的，什么都不做。C 标准明确允许。

</details>

**题目 3（踩坑）：** 以下代码有什么问题？
```c
char *p = malloc(10);
strcpy(p, "Hello, World!");
```

<details>
<summary>参考答案</summary>

缓冲区溢出。"Hello, World!" 是 13 字节（含 \0），但只分配了 10 字节。应该 malloc(strlen(s)+1)。

</details>

**题目 4（应用）：** 写一个安全的字符串复制函数。

<details>
<summary>参考答案</summary>

```c
char *safe_strdup(const char *s) {
    char *p = malloc(strlen(s) + 1);
    if (p) strcpy(p, s);
    return p;
}
```

</details>
