# 6.1 进程基本概念：程序、进程与内核的两块账本

## 本节讲什么

程序（program）是磁盘上的**静态可执行文件**；进程（process）是它被加载进内存、**正在执行的动态实例**。同一个程序可以有好几个进程，彼此互不影响。

内核眼里的一个进程 = **两块账本**：

1. **用户空间内存**：代码、已初始化数据、未初始化数据、堆、栈（下一节 6.3 逐段拆）；
2. **内核态描述符 PCB**：Linux 里就是 `struct task_struct`——PID、父指针、fd 表、信号掩码、资源限制、调度信息全在里面。

进程不是"程序在跑"这么模糊的说法，而是**内核用 task_struct 记账、用一块独立地址空间当沙盒**的一个对象。

---

## 要点

| | 程序 | 进程 |
|--|------|------|
| 存在形态 | 磁盘上的 ELF 文件（静态） | 内存中的执行实例（动态） |
| 数量关系 | 一份 | 可同时有多份（各自独立） |
| 内核里的对应物 | 无 | `struct task_struct` |
| 生命周期 | 直到被删除 | `fork` 诞生 → 退出回收 |

### 内核为进程记的账（挑几个字段对应成你能验证的东西）

| task_struct / mm 里的东西 | 用户态怎么看到 |
|---|---|
| `pid` / `tgid` | `getpid()`、`/proc/[pid]` |
| `real_parent` | `getppid()` |
| `files_struct`（fd 表） | `0/1/2`、`/proc/[pid]/fd/` |
| `signal_struct`（信号处置/掩码） | `/proc/[pid]/status` 的 `Sig*` 行 |
| `mm_struct`（地址空间） | `/proc/[pid]/maps` |
| `signal->rlim[]`（资源限制） | `getrlimit()`、`ulimit -a` |

一句话：**你在用户态敲的每个 `getpid()` / `getrlimit()`，本质都是从 `task_struct` 里读一个字段。**

## 代码

完整程序见 [`../code/c6_1_process_ctx.c`](../code/c6_1_process_ctx.c)，它把上面那张表逐行打出来：

```c
/* c6_1_process_ctx.c — 6.1 进程 = 内核管理的执行上下文（资源容器视角）
 * 编译: gcc -O2 -Wall -Wextra -o c6_1_process_ctx c6_1_process_ctx.c
 */
#define _GNU_SOURCE
#include <stdio.h>
#include <unistd.h>
#include <sys/resource.h>

int main(void)
{
    /* 身份：内核 task_struct 里的第一组字段 */
    printf("PID  = %d\n", (int)getpid());
    printf("PPID = %d\n", (int)getppid());
    printf("PGID = %d   (进程组)\n", (int)getpgrp());
    printf("SID  = %d   (会话)\n", (int)getsid(0));
    printf("UID=%d EUID=%d  GID=%d EGID=%d\n",
           (int)getuid(), (int)geteuid(), (int)getgid(), (int)getegid());

    /* 资源二：fd 表（内核替你维护的打开文件表） */
    printf("fd 表: stdin=%d stdout=%d stderr=%d\n",
           STDIN_FILENO, STDOUT_FILENO, STDERR_FILENO);

    /* 资源三：资源限制（rlimit，进程属性） */
    struct rlimit rl;
    if (getrlimit(RLIMIT_NOFILE, &rl) == 0)
        printf("RLIMIT_NOFILE: cur=%lu  max=%lu\n",
               (unsigned long)rl.rlim_cur, (unsigned long)rl.rlim_max);
    if (getrlimit(RLIMIT_STACK, &rl) == 0)
        printf("RLIMIT_STACK : cur=%lu MB\n",
               (unsigned long)(rl.rlim_cur / 1024 / 1024));
    return 0;
}
```

编译与运行：

```bash
gcc -O2 -Wall -Wextra -o c6_1_process_ctx c6_1_process_ctx.c && ./c6_1_process_ctx
```

实测输出（另在 Compiler Explorer 复核，gcc 13.3，容器环境）：

```text
PID  = 2
PPID = 1
PGID = 2   (进程组)
SID  = 2   (会话)
UID=0 EUID=0  GID=0 EGID=0
fd 表: stdin=0 stdout=1 stderr=2
RLIMIT_NOFILE: cur=100  max=100
RLIMIT_STACK : cur=8 MB
```

**解读**：

- `stdin/stdout/stderr = 0/1/2` 不是规定死的，而是**约定**——进程一诞生，内核就替它打开这三个 fd。这也是为什么 6.1 说"fd 表是进程的私有资源"：换一个进程，012 背后可能是完全不同的文件。
- `RLIMIT_NOFILE = 100` 是容器给的值，你本机跑大概率是 1024 或 1048576。**这正是"限制不能硬编码"的现场证据**（Ch11 会专门讲怎么查）。
- `RLIMIT_STACK = 8 MB` 与 6.5 爆栈深度直接挂钩（8 MB ÷ 每帧字节数）。
- 沙箱里 `PID=2 / PPID=1` 是容器 PID 命名空间造成的，**不要把它当成"PID 从 2 开始"的规律**；本机跑通常是几百到几万。

## HFT / 嵌入式关联

| 路线 | 要点 |
|------|------|
| 嵌入式 | 没有 MMU 的 RTOS 里"进程"这个抽象很薄，往往只有一个地址空间；Linux 上则是靠 `mm_struct` 硬隔离。移植代码时，凡是依赖"每个进程独立 fd 表"的假设都要先确认目标平台 |
| HFT | 关键组件（行情接入 / 策略 / 风控）常拆成**多进程**而非多线程：地址空间互不可见，一方越界或崩溃不拖累另一方；代价是跨进程通信只能走共享内存 / Unix socket，比线程间传指针贵 |
| HFT | `RLIMIT_NOFILE` 决定你能同时开多少行情连接；上线前必须显式 `setrlimit` + 留够余量，别用默认值 |

## 自测题

**题目 1：** `getpid()` 返回的到底是什么？多线程程序里它和安全意义上的"线程 ID"是一回事吗？

<details>
<summary>参考答案</summary>

不是。glibc 的 `getpid()` 走内核 `SYSCALL_DEFINE0(getpid)`（`kernel/sys.c:958`），返回 `task_tgid_vnr(current)` —— **TGID，即线程组 ID**。同一进程的所有线程 `getpid()` 返回同一个值（因为 tgid 相同）。要拿内核内部意义上的线程号，得用 `gettid()`（`:964`，返回 `task_pid_vnr(current)`，即 `task_struct.pid`）。6.2 会展开这张"两个 PID"的对照表。

</details>

**题目 2：** 为什么说"程序是静态的，进程是动态的"？磁盘上的 ELF 里有 `task_struct` 吗？

<details>
<summary>参考答案</summary>

ELF 里只有代码、数据、符号表等**内容**，没有任何运行时状态；`task_struct` 是内核在 `fork` 时分配、在运行过程中不断变化的**运行时数据结构**。同一个 ELF 被加载两次就是两个互不相干的进程，各自有独立的 PID、fd 表、地址空间。

</details>

**题目 3：** 上面实测里 `RLIMIT_NOFILE = 100`，如果程序要开 200 个行情连接，会发生什么？怎么提前发现？

<details>
<summary>参考答案</summary>

第 101 个 `socket()` / `open()` 会返回 `-1` 并置 `errno = EMFILE`（进程级 fd 用尽；若是系统级则 `ENFILE`）。提前发现的办法就是在启动时 `getrlimit(RLIMIT_NOFILE, ...)` 读一次并与需求比对，或直接 `setrlimit` 抬高上限（上限不超过 `rlim_max`）。Ch11 专门讲这套查询 API，Ch36 讲 `rlimit` 的修改。

</details>
