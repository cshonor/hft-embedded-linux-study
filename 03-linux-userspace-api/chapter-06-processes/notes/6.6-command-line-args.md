# 6.6 命令行参数 `argv`：`argv[0]` 可以是任何字符串

> 源码核验：Linux v6.6 · `include/linux/mm_types.h:807`（`arg_lock`）· `:811`（`arg_start/arg_end`）· `fs/proc/base.c:358`（`proc_pid_cmdline_read`）· `:369`（`get_task_cmdline`）
> 本章：[TLPI 第 06 章 — Processes](../README.md)
> - 上一节：[6.5 栈与栈帧](./6.5-stack-frames.md)
> - 下一节：[6.7 环境列表](./6.7-environment-list.md)

## 本节讲什么

`int main(int argc, char *argv[])` 人人都写过，但有三点常被忽略：

1. **`argv[0]` 可以不是程序名**——它是调用者随便指定的字符串，甚至可以是 `"改名了"`。
2. **`argv[argc]` 一定是 `NULL`**，这是 C 标准保证的哨兵，不需要传长度。
3. **argv 的来源是 `execve`**，内核把字符串存在进程地址空间的栈顶区，`mm_struct` 里用 `arg_start/arg_end` 记住范围，`/proc/[pid]/cmdline` 读的就是这段。

---

## 要点

### 布局（都在栈顶区，紧挨着）

```text
高地址  ┌──────────────────┐
        │  environ 字符串…  │ ← env_start / env_end
        ├──────────────────┤
        │ argv 字符串…      │ ← arg_start / arg_end
        ├──────────────────┤
        │ NULL             │ ← argv[argc]
        ├──────────────────┤
        │ &argv[argc-1]    │
        │ …                │   argv[] 指针数组本身
        │ &argv[0]         │
        ├──────────────────┤
        │ argc             │
        └──────────────────┘  start_stack 附近
```

### 内核对 argv 的记账

```c
/* include/linux/mm_types.h (v6.6) */
spinlock_t arg_lock; /* protect the below fields */            /* :807 */
unsigned long arg_start, arg_end, env_start, env_end;          /* :811 */
```

`arg_lock` 为什么必须存在？因为 **`execve()` 换程序时会改写这四个指针**（旧程序的 argv 被丢弃、新程序的接上），而 `/proc/[pid]/cmdline` 的读取是**另一个上下文**——不加锁就会读到"半个旧 argv + 半个新 argv"。

```c
/* fs/proc/base.c (v6.6) —— /proc/[pid]/cmdline 的 read 实现 */
static ssize_t proc_pid_cmdline_read(struct file *file, char __user *buf,   /* :358 */
				     size_t count, loff_t *pos)
{
	struct task_struct *tsk;
	ssize_t ret;

	BUG_ON(*pos < 0);

	tsk = get_proc_task(file_inode(file));
	if (!tsk)
		return -ESRCH;
	ret = get_task_cmdline(tsk, buf, count, pos);      /* :369 读 arg_start..arg_end */
	put_task_struct(tsk);
	if (ret > 0)
		*pos += ret;
	return ret;
}
```

### 三条容易错的语义

| 说法 | 真相 |
|------|------|
| `argv[0]` 是程序名 | **不是**。它只是调用者传的第一个字符串。`execve(path, argv, envp)` 里 `argv[0]` 与 `path` 完全独立 |
| 可以用 `argv[argc]` 之前不知道长度 | 对——`argv[argc] ≡ NULL`，所以 `while (*argv)` 也能遍历 |
| 改 `argv[i]` 的内容 | 可以，那块内存属于本进程。但**别改 `argv` 指针数组本身的结构**（某些实现依赖它连续、以 NULL 结尾） |
| `/proc/[pid]/cmdline` 分隔符 | 不是空格，是 **NUL**（`\0`）；所以 `cat` 出来看着是连在一起的 |

## 代码

完整程序见 [`../code/c6_6_argv.c`](../code/c6_6_argv.c)：打印自己的 argv，再用 `fork + execv` **给另一个进程指定一个假的 `argv[0]`**。

```c
/* c6_6_argv.c — 6.6 命令行参数：argc/argv 布局 + argv[argc]==NULL + 来源(fork+execv)
 * 编译: gcc -O2 -Wall -Wextra -o c6_6_argv c6_6_argv.c
 * 用法: ./c6_6_argv -a hello --flag
 */
#define _GNU_SOURCE
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <unistd.h>
#include <sys/wait.h>

static void dump_argv(int argc, char **argv)
{
    printf("  argc = %d\n", argc);
    for (int i = 0; i <= argc; i++) {
        if (i == argc)
            printf("  argv[%d] = %-12s  <- C 标准保证的 NULL 哨兵\n",
                   i, argv[i] ? "(非NULL!)" : "NULL");
        else
            printf("  argv[%d] = %-12s (@%p)\n", i, argv[i], (void *)argv[i]);
    }
}

int main(int argc, char **argv)
{
    printf("=== A. 本进程的 argv ===\n");
    dump_argv(argc, argv);

    printf("=== B. /proc/self/cmdline（内核存的原始副本，NUL 分隔）===\n");
    FILE *f = fopen("/proc/self/cmdline", "rb");
    if (f) {
        char buf[512];
        size_t n = fread(buf, 1, sizeof buf, f);
        for (size_t i = 0; i < n; i++)
            putchar(buf[i] == '\0' ? '|' : buf[i]);
        putchar('\n');
        fclose(f);
    }

    /* 防无限递归：execv 起来的那个进程 argv[1] 是 「first」，直接收工 */
    if (argc > 1 && strcmp(argv[1], "first") == 0) {
        printf("=== C. 我是被 execv 起来的，argv 由父进程指定，不再自我重启 ===\n");
        return 0;
    }

    printf("=== C. 用 fork + execv 给另一个进程指定 argv ===\n");
    char self[512];
    ssize_t k = readlink("/proc/self/exe", self, sizeof self - 1);
    if (k <= 0) { printf("  readlink(/proc/self/exe) 失败\n"); return 0; }
    self[k] = 0;
    printf("  可执行文件真实路径 = %s\n", self);

    pid_t pid = fork();
    if (pid == 0) {
        /* argv[0] 可以是任意字符串，与真实程序名无关 —— 观察 A 段会打印 「改名了」 */
        char *newargv[] = { (char *)"改名了", (char *)"first", (char *)"-x", NULL };
        execv(self, newargv);
        perror("execv");
        _exit(127);                 /* 只有 execv 失败才会到这 */
    }
    wait(NULL);
    return 0;
}
```

编译与运行：

```bash
gcc -O2 -Wall -Wextra -o c6_6_argv c6_6_argv.c && ./c6_6_argv -a hello --flag
```

实测输出（另在 Compiler Explorer 复核，gcc 13.3）：

```text
=== A. 本进程的 argv ===
  argc = 3
  argv[0] = 改名了    (@0x7ffd7de01ed8)
  argv[1] = first        (@0x7ffd7de01ee2)
  argv[2] = -x           (@0x7ffd7de01ee8)
  argv[3] = NULL          <- C 标准保证的 NULL 哨兵
=== B. /proc/self/cmdline（内核存的原始副本，NUL 分隔）===
改名了|first|-x|
=== C. 我是被 execv 起来的，argv 由父进程指定，不再自我重启 ===
=== A. 本进程的 argv ===
  argc = 1
  argv[0] = ./output.s   (@0x7ffc032b7ee3)
  argv[1] = NULL          <- C 标准保证的 NULL 哨兵
=== B. /proc/self/cmdline（内核存的原始副本，NUL 分隔）===
./output.s|
=== C. 用 fork + execv 给另一个进程指定 argv ===
  可执行文件真实路径 = /app/output.s
```

**解读**：

1. **`argv[0] = 改名了` 是全节最硬的证据**：程序的可执行文件真实路径是 `/app/output.s`（C 段用 `readlink("/proc/self/exe")` 打出来了），但 `argv[0]` 显示的是父进程随便写的 `"改名了"`。**`argv[0]` 与程序名没有任何绑定关系。** 这也是为什么不能用 `argv[0]` 做安全判断（比如"以 root 身份调用自己"那种把戏）。
2. **两次运行的对比**说明 argv 完全由调用者决定：同一份二进制，先以 `argc=1, argv[0]="./output.s"` 跑（沙箱默认），再被 `execv` 以 `argc=3, argv[0]="改名了"` 拉起。
3. **`argv[3] = NULL` 每次都出现**，且循环条件是 `i <= argc`（多打印一个），直接看到哨兵。
4. **`/proc/self/cmdline` 用 `|` 替换 `\0` 后是 `改名了|first|-x|`** —— 印证了内核存的是 **NUL 分隔**的原始副本，且**末尾也有一个 NUL**。
5. **输出顺序**：先打印"被 execv 起来的"那次（子进程），再打印原始那次。这是 stdio 全缓冲 + 父进程等待造成的，不是逻辑错。

## HFT / 嵌入式关联

| 路线 | 要点 |
|------|------|
| 嵌入式 | BusyBox 风格的"多合一"二进制全靠 `argv[0]` 分派（`ln -s busybox ls; ./ls`）；但反过来，**不要用 `argv[0]` 做权限判断** |
| HFT | 配置参数（连接地址、席位 ID）常用 `argv` 传，启动脚本里能看清。但敏感信息（密码、密钥）**不要放 argv**——`/proc/[pid]/cmdline` 同机任何用户都能读（无 ptrace 限制时） |
| HFT | 用 `execv` 而非 `system()` 重启进程：`argv` 完全可控，且不额外 fork 一层 shell（`system` 会引入 `/bin/sh` 的启动开销与信号语义问题） |

## 自测题

**题目 1：** 一个程序打印 `argv[0]`，结果不是它自己的文件名，可能吗？为什么？

<details>
<summary>参考答案</summary>

完全可能，而且这就是标准行为。`argv[0]` 由调用者在 `execve(path, argv, envp)` 里指定，与 `path`（真正的可执行文件）是两个独立参数。上面实测里可执行文件是 `/app/output.s`，但 `argv[0]` 是父进程写的 `"改名了"`。所以任何"靠 `argv[0]` 判断我是谁/是否被合法调用"的安全逻辑都是错的。

</details>

**题目 2：** 为什么 `argv[argc]` 一定是 `NULL`，这个保证有什么实用价值？

<details>
<summary>参考答案</summary>

C 标准（C99 §5.1.2.2.1）要求 `argv[argc]` 是空指针，这样接收方即使不知道 `argc` 也能遍历：`for (char **p = argv; *p; p++)`。很多库的 API（如 `execv` 自己）就依赖这个哨兵来知道数组到哪结束。

</details>

**题目 3：** `/proc/[pid]/cmdline` 里参数之间是什么分隔符？读的时候要注意什么？

<details>
<summary>参考答案</summary>

是 **NUL（`\0`）**，不是空格。所以直接 `cat` 会看到参数连成一片。程序里要用 `\0` 切分（上面 demo 是把它换成 `|` 才好读）。另外注意末尾也有一个 `\0`，且这个文件由内核从 `mm->arg_start..arg_end` 复制出来（`fs/proc/base.c:358` 的 `proc_pid_cmdline_read` → `get_task_cmdline`），受 `arg_lock` 保护。

</details>
