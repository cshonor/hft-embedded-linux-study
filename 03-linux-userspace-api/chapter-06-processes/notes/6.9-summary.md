### 内存布局

```
高地址  ┌─────────────┐ ← argv, environ
        │  栈 (stack)  │ ↓ 向下增长
        │      ↓       │
        │  (free)      │
        │      ↑       │
        │  堆 (heap)   │ ↑ 向上增长 (brk/sbrk/mmap)
        ├─────────────┤
        │  bss (未初始化)│
        │  data (已初始化)│
        │  text (代码)  │
低地址  └─────────────┘
```

### setjmp/longjmp 语义

```c
jmp_buf env;
int r = setjmp(env);  /* 第一次返回 0，longjmp 后返回非 0 */
if (r == 0) {
    /* 正常路径 */
    do_something();   /* 如果出错，调用 longjmp(env, val) */
} else {
    /* 错误恢复路径，r = longjmp 的 val */
}
```

| 注意点 | 说明 |
|--------|------|
| 寄存器变量 | `volatile` 修饰的变量在 longjmp 后保持正确值 |
| 栈帧有效 | longjmp 的目标函数必须仍在调用栈中（未返回） |
| 信号安全 | 信号处理器中用 `sigsetjmp`/`siglongjmp` 保存/恢复信号掩码 |

## HFT / 嵌入式关联

- **进程隔离**：HFT 通常多进程隔离关键组件（行情/策略/风控独立进程）
- **内存布局优化**：`text` 段只读共享（多进程 fork 后 COW）
- **环境变量**：配置传递（`LD_PRELOAD`、`HOME`、`PATH`），HFT 可能用环境变量传配置
- **嵌入式**：精简进程通常无 fork，单进程裸机或 RTOS
- **栈大小**：嵌入式需手动设置栈大小（`ulimit -s` 或 `pthread_attr_setstacksize`）

## 代码自测

<details>
<summary>1. setjmp 返回值什么时候是 0？什么时候不是？</summary>

直接调用 `setjmp(env)` 时返回 0。当后续调用 `longjmp(env, val)` 时，执行流跳回 setjmp 的位置，此时返回值为 `val`（如果 val 为 0，会被强制改为 1）。
</details>

<details>
<summary>2. 为什么在信号处理器中用 longjmp 是危险的？</summary>

1. 信号可能在 longjmp 的目标函数正在执行时中断
2. longjmp 不恢复信号掩码，其他信号被屏蔽后无法恢复
3. 如果使用非异步信号安全的函数（如 malloc），可能导致死锁
4. 应使用 `sigsetjmp`/`siglongjmp` 替代，它们保存和恢复信号掩码
</details>

<details>
<summary>3. getenv 返回的指针可以修改吗？</summary>

技术上可以，但不应该。`getenv` 返回的是 environ 数组中指向字符串的指针，修改它会改变环境变量。正确做法是 `setenv`/`putenv`。返回的指针在下次调用 `setenv`/`putenv` 后可能失效。
</details>
