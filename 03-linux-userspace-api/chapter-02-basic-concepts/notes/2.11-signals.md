## 本节讲什么

信号是内核向进程投递的**异步通知**（软件中断）。本节回答三个问题：

1. 信号在内核里怎么表示？（`sighand_struct`）
2. `kill` 和 `tgkill` 有什么区别？（进程级 vs 线程级）
3. 为什么 HFT 热路径要小心信号？

完整展开在 [Ch20](../../chapter-20-signals-fundamentals/README.md)-[22](../../chapter-22-signals-advanced/README.md)，这里先建立「信号 = 异步抢占」的核心心智。

本节要补的是**两个只能靠实跑区分的概念**：**「屏蔽」不等于「忽略」**（屏蔽的信号进 pending，解除后立刻送达）、以及 **`EINTR` 到底是什么值、怎么写才对**。

---

## 要点

### 一、信号的本质与内核表示

信号不是「数据通道」，而是**一个编号 + 一个待处理标志**。标准信号（1-31）**不排队**——同一信号连发多次，进程可能只看到一次（实时信号 34-64 才排队，见 [Ch22](../../chapter-22-signals-advanced/README.md)）。

内核侧，每个进程的 `task_struct` 挂一个 `sighand_struct`：

```c
struct sighand_struct {              /* include/linux/sched/signal.h:20 */
    ...
    struct k_sigaction action[_NSIG];  /* 每个信号一个处理动作 */
};
```

`action[SIGINT]` 存的就是「SIGINT 该怎么处理」：默认动作 / 忽略 / 自定义处理器（`sigaction` 注册的那个）。

### 二、三个概念必须分清：默认动作 / 忽略 / 屏蔽

| 概念 | 怎么设置 | 信号送来时 | 信号丢了吗 |
|------|----------|-----------|-----------|
| **默认动作** | 什么都不做 | 按内核规定（终止/忽略/停止/继续） | — |
| **忽略（`SIG_IGN`）** | `sigaction(sig, {.sa_handler = SIG_IGN})` | 丢弃 | ✅ **丢了** |
| **屏蔽（block）** | `sigprocmask(SIG_BLOCK, ...)` | 进 **pending** 集合 | ❌ **没丢**，解除屏蔽后立刻送达 |

> **「屏蔽」和「忽略」是最容易混的一对。** 屏蔽是「先扣着」，忽略是「直接扔」。本节 demo 段 ② 用 `sigpending()` 实测了这个区别。

### 三、发送信号的三个系统调用

```c
SYSCALL_DEFINE2(kill,  pid_t, pid, int, sig)                       /* kernel/signal.c:3807 */
SYSCALL_DEFINE3(tgkill, pid_t, tgid, pid_t, pid, int, sig)         /* 线程级 */
SYSCALL_DEFINE2(tkill, pid_t, pid, int, sig)                       /* 线程级(旧) */
```

| 调用 | 目标 | 说明 |
|------|------|------|
| `kill(pid, sig)` | **整个进程组** | `pid>0` 发该进程；`pid==0` 发同进程组；`pid==-1` 发所有（有权限的） |
| `tgkill(tgid, pid, sig)` | **指定线程** | `tgid` 是进程（线程组），`pid` 是具体线程（tid） |
| `tkill(pid, sig)` | 指定线程 | 老接口，等价 `tgkill` 但少了线程组校验，已不推荐 |

> 多线程进程里，`kill` 投递的信号由**任意一个未屏蔽该信号的线程**处理（内核挑一个）；`tgkill` 才能精确投给某个 tid。这正是「要定向通知某个工作线程」时必须用 `tgkill` 的原因。

### 四、信号生命周期

```
发送方: kill(pid, sig) ──► 内核: 置目标 pending 标志
                                    │ 目标阻塞该信号？ ──是──► 挂起，等解除阻塞
                                    │否
                                    ▼
                         目标进程: 从内核态返回用户态时，检查 pending
                                    │ 有自定义 handler
                                    ▼
                         切换到用户态 handler 执行 → 返回中断点继续
```

**关键**：信号的**处理时机**是「目标进程下一次从内核态返回用户态」——不是发送那一刻立即执行。所以：

- 一个正在「纯用户态死循环」的进程，能收到信号（因为时钟中断会周期性把它拉进内核再返回）；
- 一个卡在 D 状态（不可中断睡眠）的进程，`kill -9` 也打不断（信号投递被推迟到 I/O 返回）。

### 五、`EINTR`：慢系统调用被信号打断

如果信号处理器的 handler 执行期间**没有** `SA_RESTART`，一些「慢系统调用」（可阻塞的 `read`/`write`/`accept`/`select` 等）会**提前返回 -1 并把 `errno` 设为 `EINTR`**。

**正确写法**（本节 demo 段 ④ 实测 `errno=4`）：

```c
do {
    n = read(fd, buf, sizeof buf);
} while (n < 0 && errno == EINTR);
```

或者给 `sigaction` 加 `SA_RESTART`，让内核**自动重启**这个调用。两者的差别：

| 做法 | 行为 | 适用 |
|------|------|------|
| `SA_RESTART` | 内核透明重启，调用者看不到 | 大多数场景「省事」 |
| 手工循环判 `EINTR` | 调用者能看到「被打断过」 | 需要在信号后立刻做别的事 |

### 六、异步信号安全：handler 里什么能调

**handler 运行在「可能打断任何用户态代码」的上下文里**，所以只能调**可重入（异步信号安全）**的函数：

| 可以调（async-signal-safe） | 绝对不能调 |
|------------------------------|-----------|
| `write` / `read` / `open` / `close` | `printf` / `fprintf` |
| `_exit`（**不是** `exit`） | `malloc` / `free` |
| `kill` / `sigprocmask` | `strerror` / `syslog` |
| `waitpid` / `fcntl` | 任何用 stdio 或堆的函数 |

原因：它们**不可重入**。主流程可能正好在 `printf` 内部改着 stdio 的缓冲区，handler 插进来再调一次 → 数据错乱或死锁。`signal-safety(7)` 有完整清单。本节 demo 的 handler **只用 `write()`**，就是为了守这条规矩。

## 代码

### c2_11 sigaction / 屏蔽≠忽略 / SIGCHLD / EINTR / 异步安全

[`../code/c2_11_signal.c`](../code/c2_11_signal.c) 分六段：

| 段 | 做什么 | 钉死什么 |
|----|--------|----------|
| ① | `install()` 注册 SIGUSR1 的 handler，然后 `kill(getpid(), SIGUSR1)` | handler 真的被调用；handler 里只用 `write()` |
| ② | 先 `sigprocmask` **屏蔽** SIGUSR2，发一次，用 `sigpending()` 查，再解除屏蔽 | **屏蔽 ≠ 忽略**——信号进了 pending，解除后立刻执行 |
| ③ | 注册 SIGCHLD handler，`fork` 一个子进程 | 子进程状态变化会通知父进程；竞态提醒 |
| ④ | 注册 SIGALRM（**故意不给 `SA_RESTART`**），用 `setitimer` 打断阻塞的 `read` | `errno=4 (EINTR)` 的真实值 |
| ⑤ | 打印「能调 / 不能调」清单 | 异步信号安全 |
| ⑥ | 8 个常用信号表 | 编号 + 默认动作 |

```c
/* TLPI 第 2 章 §2.11 —— 信号：异步通知、屏蔽与挂起、EINTR
 *
 * 编译：gcc -O0 -Wall -Wextra c2_11_signal.c -o c2_11
 * 运行：./c2_11        （约 0.15 秒）
 *
 * 本节要钉死的事实：
 *   ① 信号是「软件中断」：内核在合适的时机把控制流抢过来，跳到 handler。
 *   ② 用 sigaction() 而不是 signal()：语义明确、可移植。
 *   ③ 屏蔽（block）不等于忽略（ignore）：被屏蔽的信号进入 pending，解除屏蔽后才执行。
 *   ④ handler 里只能调「异步信号安全」函数 —— write() 安全，printf() 不安全。
 *   ⑤ 没有 SA_RESTART 时，慢系统调用被信号打断会返回 -1 / EINTR，调用方必须重试。
 */
#define _GNU_SOURCE
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <errno.h>
#include <unistd.h>
#include <signal.h>
#include <sys/wait.h>
#include <sys/time.h>
#include <sys/types.h>

static volatile sig_atomic_t g_count;
static volatile sig_atomic_t g_last;

/* handler 里只用 write()：它是异步信号安全的；printf() 不是 */
static void handler(int sig)
{
    g_count++;
    g_last = sig;
    const char *m = "  [handler] 在信号处理器里跑，只调用 write()\n";
    if (write(STDOUT_FILENO, m, strlen(m)) < 0) { /* 忽略 */ }
}

static void on_alarm(int sig) { (void)sig; }

static void on_chld(int sig)
{
    (void)sig;
    const char *m = "  [handler] 收到 SIGCHLD：有子进程状态变了\n";
    if (write(STDOUT_FILENO, m, strlen(m)) < 0) { /* 忽略 */ }
}

/* 安装 handler 的样板：sigaction + sigemptyset + flags */
static int install(int sig, void (*fn)(int), int flags)
{
    struct sigaction sa;
    memset(&sa, 0, sizeof(sa));
    sa.sa_handler = fn;
    sigemptyset(&sa.sa_mask);
    sa.sa_flags = flags;
    return sigaction(sig, &sa, NULL);
}

int main(void)
{
    printf("=== ① sigaction 注册，然后 kill 自己 ===\n");
    if (install(SIGUSR1, handler, SA_RESTART) < 0) { perror("sigaction"); return 1; }
    printf("  已注册 SIGUSR1(%d) -> handler\n", SIGUSR1);
    fflush(NULL);
    if (kill(getpid(), SIGUSR1) < 0) perror("kill");
    printf("  handler 调用次数 = %d，最后一次 sig = %d\n", (int)g_count, (int)g_last);
    printf("  -> 信号是异步的：kill() 立刻返回，handler 在内核选定的时机跑。\n");

    printf("\n=== ② 屏蔽 ≠ 忽略：屏蔽会进 pending，解除后立刻执行 ===\n");
    if (install(SIGUSR2, handler, SA_RESTART) < 0) { perror("sigaction"); return 1; }

    sigset_t block, pend;
    sigemptyset(&block);
    sigaddset(&block, SIGUSR2);
    if (sigprocmask(SIG_BLOCK, &block, NULL) < 0) perror("sigprocmask");
    printf("  已屏蔽 SIGUSR2(%d)，handler 次数停在 %d\n", SIGUSR2, (int)g_count);

    fflush(NULL);
    kill(getpid(), SIGUSR2);
    printf("  发了 SIGUSR2，但被屏蔽 → handler 没跑（次数仍 = %d）\n", (int)g_count);

    if (sigpending(&pend) == 0)
        printf("  sigpending(): SIGUSR2 在挂起集合里？%s\n",
               sigismember(&pend, SIGUSR2) ? "YES" : "no");

    printf("  解除屏蔽 ...\n");
    fflush(NULL);
    sigprocmask(SIG_UNBLOCK, &block, NULL);      /* 一解除，pending 的信号立刻送达 */
    printf("  handler 次数 = %d，最后一次 sig = %d\n", (int)g_count, (int)g_last);
    printf("  -> 信号没丢，只是被「扣押」了。SIG_IGN 才是彻底丢弃。\n");

    printf("\n=== ③ SIGCHLD：子进程状态变化的通知 ===\n");
    install(SIGCHLD, on_chld, SA_RESTART | SA_NOCLDSTOP);
    fflush(NULL);
    pid_t pid = fork();
    if (pid == 0) _exit(0);
    int st; waitpid(pid, &st, 0);
    printf("  父进程 waitpid 已回收子进程 %d\n", (int)pid);
    printf("  -> 注意竞态：SIGCHLD 可能在 waitpid 之前/之后到，\n");
    printf("     handler 里不该假设子进程一定还活着。\n");

    printf("\n=== ④ 慢系统调用被信号打断：EINTR ===\n");
    if (install(SIGALRM, on_alarm, 0) < 0) { perror("sigaction SIGALRM"); return 1; }
    printf("  注册 SIGALRM，flags 里**故意不给** SA_RESTART\n");

    int pp[2];
    if (pipe(pp) < 0) { perror("pipe"); return 1; }
    /* 保留写端不写：read() 会一直阻塞（这就是「慢系统调用」） */
    struct itimerval it;
    it.it_value.tv_sec = 0;  it.it_value.tv_usec = 100000;        /* 100ms 后响 */
    it.it_interval.tv_sec = 0; it.it_interval.tv_usec = 100000;
    if (setitimer(ITIMER_REAL, &it, NULL) < 0) perror("setitimer");

    char c;
    errno = 0;
    ssize_t n = read(pp[0], &c, 1);
    printf("  阻塞中的 read() 返回 %zd，errno=%d (%s)\n", n, errno, strerror(errno));
    printf("  -> EINTR(%d) = Interrupted system call：不是错误，是「被打断了，重试」\n", EINTR);
    printf("  -> 正确写法：do { n = read(...); } while (n < 0 && errno == EINTR);\n");
    printf("  -> 或者给 sigaction 加 SA_RESTART，让内核自动重启这个调用\n");
    errno = 0;
    close(pp[0]); close(pp[1]);

    printf("\n=== ⑤ 处理器里什么能调、什么不能调 ===\n");
    printf("  异步信号安全（可以调）：write / read / open / close / _exit /\n");
    printf("                          kill / sigprocmask / waitpid / fcntl\n");
    printf("  不安全（别调）：printf / malloc / free / strerror / syslog\n");
    printf("  原因：它们是**不可重入**的。主流程可能正好在 printf 内部改着\n");
    printf("        stdio 的缓冲区，handler 插进来再调一次 → 数据错乱或死锁。\n");
    printf("  本 demo 的 handler 只用 write()，就是为了守这条规矩。\n");

    printf("\n=== ⑥ 常用信号一览 ===\n");
    printf("  SIGINT(%2d)   Ctrl+C          默认终止\n", SIGINT);
    printf("  SIGQUIT(%2d)  Ctrl+\\          默认终止 + core\n", SIGQUIT);
    printf("  SIGTERM(%2d)  kill 默认       默认终止（可捕获，礼貌退出）\n", SIGTERM);
    printf("  SIGKILL(%2d)  杀无赦          不可捕获/屏蔽/忽略 —— 唯一杀不死进程的兜底\n", SIGKILL);
    printf("  SIGSTOP(%2d)  Ctrl+Z 的硬版   不可捕获，暂停\n", SIGSTOP);
    printf("  SIGCHLD(%2d)  子进程状态变化\n", SIGCHLD);
    printf("  SIGPIPE(%2d)  写一个读端已关的管道 —— 默认终止（网络服务常见坑）\n", SIGPIPE);
    printf("  SIGHUP(%2d)   控制终端断开 —— 传统上用来让 daemon 重读配置\n", SIGHUP);
    return 0;
}
```

**解读**

1. **段 ② 是全节的核心，也是「屏蔽 ≠ 忽略」唯一的实证**。三行输出把过程切成了三段：
   ```text
   已屏蔽 SIGUSR2(12)，handler 次数停在 1
   发了 SIGUSR2，但被屏蔽 → handler 没跑（次数仍 = 1）
   sigpending(): SIGUSR2 在挂起集合里？YES
   解除屏蔽 ...
   handler 次数 = 2，最后一次 sig = 12
   ```
   关键在第三行：**`sigpending()` 明确说 SIGUSR2 在挂起集合里**——信号**没有丢**。解除屏蔽后 handler 立刻执行（`sig 12`，次数从 1 变 2）。如果 SIGUSR2 是 `SIG_IGN`，`sigpending()` 就不会有它，次数也不会变。
2. **段 ④ 的 `errno=4` 是一个必须记住的数字**。`EINTR` 不是「调用出错」，而是「调用被打断了，请重试」。**把它当错误处理是常见 bug**——比如 `accept` 返回 -1 就退出服务循环，结果一个 `SIGCHLD` 就能把服务器打挂。两个正确写法：
   - 手工循环：`do { ... } while (n < 0 && errno == EINTR);`
   - 或者 `SA_RESTART`，让内核透明重启。
   demo **故意不设 `SA_RESTART`**，就是为了让 `EINTR` 显形。
3. **段 ③ 的竞态提醒值一整段**：`SIGCHLD` 可能在 `waitpid` **之前或之后**到达。所以 handler 里**不能**假设「子进程一定还活着可以 wait」，正确做法是在 handler 里循环 `waitpid(-1, ..., WNOHANG)` 直到没有更多可回收的，或者干脆用 `signalfd`/`sigwaitinfo` 同步处理（[Ch22](../../chapter-22-signals-advanced/README.md)）。
4. **段 ⑤ 的清单是编译期无法强制、只能靠纪律守住的**。特别注意两处最容易犯的：
   - **`exit()` 不安全，`_exit()` 才安全**（`exit` 会跑 `atexit` + flush stdio，与主流程的 stdio 状态冲突——这和 [2.7](./2.7-processes.md) 段 ④ 的 `_exit` 不 flush 是**同一个 stdio 状态**问题）；
   - **`printf` 不安全但极常用**。本 demo 的 handler **只用 `write()`**，所以它能安全地在 handler 里输出——段 ①② 的那两行 `[handler] ...` 就是 `write` 出来的。
5. **段 ⑥ 的 `SIGKILL(9)`/`SIGSTOP(19)` 那一列**是内核的「保底」设计：必须保证任何进程都能被无条件杀死/停止，否则一个故意屏蔽所有信号的进程就杀不掉了。注意 `SIGPIPE(13)` 那条——**默认动作是终止进程**，这是网络服务最常见的「被一个异常客户端打挂」的原因（见 [2.17](./2.17-client-server.md)）。

## HFT / 嵌入式关联

| 现象 | 本节机制的兑现 |
|------|----------------|
| 信号造成延迟毛刺 | 信号是**异步抢占**——handler 执行时打断主循环，热路径应 `pthread_sigmask` 屏蔽，让信号只在专用线程处理 |
| 优雅停机 | `SIGTERM` handler 置「停止」标志，主循环看到后刷缓冲、释放资源再退出（比 `kill -9` 安全） |
| 段错误溯源 | `SIGSEGV` 默认 dump core，配合 03.6 模块的 coredump 分析定位崩溃点 |
| 处理信号首选 | HFT 用 `sigwaitinfo`（同步等信号，无 handler 抢占）而非异步 handler（见 [Ch22](../../chapter-22-signals-advanced/README.md)） |
| **段 ② 的「屏蔽」是热路径保护伞** | 交易主循环开始前 `sigprocmask` 屏蔽所有信号，只在专用线程用 `sigwaitinfo` 接——**主循环里永远不会被 handler 打断**。段 ② 还证明了被屏蔽的信号**不会丢**，解除后照常送达 |
| **`EINTR` 是嵌入式长跑进程的头号坑** | 段 ④ 实测 `errno=4`。`accept`/`recv`/`select`/`nanosleep` 都会被它打断。**`nanosleep` 尤其阴险**：它返回 `EINTR` 时剩余时间在 `rem` 参数里，不处理就像「睡少了」——精确定时循环必须 `while (nanosleep(&req, &req) == -1 && errno == EINTR);` |
| **`SIGPIPE` 的默认动作是终止进程** | 段 ⑥ 列了出来。服务器若在客户端断开后还 `write`，进程直接死。标准做法是 `signal(SIGPIPE, SIG_IGN)` + 看 `write` 返回值，或 `send(..., MSG_NOSIGNAL)`（见 [2.17](./2.17-client-server.md)） |
| **`SIGHUP` 是 daemon 重载配置的传统信号** | 段 ⑥ 最后一行。嵌入式服务收到 `SIGHUP` 时重读配置，比 `kill + 重启` 平滑得多——**但注意它也是「控制终端断开」的默认信号**，未做 `setsid` 的进程会直接被杀（见 [2.14](./2.14-sessions.md)） |
| **handler 里 `printf` 会死锁而不是「输出乱码」** | 段 ⑤ 的机制：主流程正持着 stdio 锁，handler 再取同一把锁 → 死锁。嵌入式里表现为「进程挂了，栈在 `_IO_flockfile`」——看到这个栈直接找 handler 里的 `printf` |

## 自测题

<details>
<summary>1. 信号是同步还是异步的？</summary>

**异步**。发送方 `kill` 立即返回，信号由内核「稍后」投递——具体是目标进程下一次从内核态返回用户态时。发送方和目标进程的执行时间线是解耦的。

本节段 ① 的实测把这个时序摊开了：

```text
  已注册 SIGUSR1(10) -> handler
  [handler] 在信号处理器里跑，只调用 write()
  handler 调用次数 = 1，最后一次 sig = 10
  -> 信号是异步的：kill() 立刻返回，handler 在内核选定的时机跑。
```

对比 [2.10](./2.10-ipc.md) 的管道：`read` 会**阻塞等数据**（同步）。`sigwaitinfo` 也是同步的——它主动「等」信号，此时不需要 handler。
</details>

<details>
<summary>2. 「屏蔽信号」和「忽略信号」有什么区别？</summary>

| | 屏蔽（block） | 忽略（`SIG_IGN`） |
|---|--------------|-------------------|
| 设置方式 | `sigprocmask(SIG_BLOCK, ...)` | `sigaction(sig, {.sa_handler = SIG_IGN})` |
| 信号送来时 | 进 **pending** 集合 | **丢弃** |
| 解除后 | **立刻送达** | 永远不来（那个信号已经在 pending 里也没有） |

本节段 ② 实测（这是**唯一**能证明这个区别的实验）：

```text
  已屏蔽 SIGUSR2(12)，handler 次数停在 1
  发了 SIGUSR2，但被屏蔽 → handler 没跑（次数仍 = 1）
  sigpending(): SIGUSR2 在挂起集合里？YES      ← 关键：没丢
  解除屏蔽 ...
  handler 次数 = 2，最后一次 sig = 12          ← 解除后立刻执行
```

`sigpending()` 返回 YES 就是「扣着」；如果是 `SIG_IGN`，它连 pending 都进不去。
</details>

<details>
<summary>3. <code>read</code> 返回 -1 且 <code>errno=4</code>，是出错了吗？</summary>

**不是「出错」，是「被打断了，请重试」。** `errno=4` 是 `EINTR`（Interrupted system call）。

本节段 ④ 实测：

```text
  注册 SIGALRM，flags 里**故意不给** SA_RESTART
  阻塞中的 read() 返回 -1，errno=4 (Interrupted system call)
```

`read(2)` ERRORS 里对 `EINTR` 的定义："The call was interrupted by a signal before any data was read"。

**两个正确写法**：

```c
/* 写法一：手工重试 */
do {
    n = read(fd, buf, sizeof buf);
} while (n < 0 && errno == EINTR);

/* 写法二：注册时加 SA_RESTART，让内核透明重启 */
sa.sa_flags |= SA_RESTART;
```

⚠️ **把它当错误处理是常见 bug**：`accept` 返回 -1 就退出服务循环，结果一个 `SIGCHLD` 就能把服务器打挂。
</details>

<details>
<summary>4. <code>kill</code> 和 <code>tgkill</code> 有什么区别？什么时候必须用 <code>tgkill</code>？</summary>

- `kill` 以「进程（线程组）」为粒度，信号由内核挑**任意一个未屏蔽该信号的线程**处理；
- `tgkill(tgid, tid, sig)` 以「具体线程（tid）」为粒度，精确投递。

多线程程序要通知**特定工作线程**时，`kill` 做不到定向，必须 `tgkill`。

本节段 ① 用的是 `kill(getpid(), SIGUSR1)`——单线程进程里够用（只有主线程会处理）。到了 [2.12](./2.12-threads.md) 的多线程场景，段 ④ 的 4 条线程各有自己的 `tid`（`4/5/6/7`），这时候要定向就得 `tgkill`。
</details>

<details>
<summary>5. 为什么 SIGKILL 和 SIGSTOP 不能被捕获或阻塞？</summary>

这是内核的「**保底**」设计——必须保证「任何进程都能被无条件杀死/停止」，否则一个故意屏蔽/捕获所有信号的进程会变成无法杀死的僵尸。

`sigaction(2)` 原文："The **signals SIGKILL and SIGSTOP cannot be caught, blocked, or ignored**."

本节段 ⑥ 的表里这两行标注得很清楚：`SIGKILL(9) 杀无赦 不可捕获/屏蔽/忽略`、`SIGSTOP(19) 不可捕获`。记住这一对，就知道「为什么 `Ctrl+Z` 的 `SIGTSTP` 能被程序捕获，而 `SIGSTOP` 不能」。
</details>

<details>
<summary>6. 标准信号「不排队」是什么意思？会造成什么问题？</summary>

连发 3 次 SIGINT，进程可能只处理 1 次（内核只记一个 **pending 位**，不记次数）。所以标准信号**不能用来计数**。

要可靠计数用**实时信号**（`SIGRTMIN`+，排队投递，`sigqueue` 还能携带 `si_value`），或改用 `eventfd`/管道。

本节段 ② 的 `sigpending()` 返回的是一个**集合**（`sigset_t`）而不是计数——这从数据结构上就说明了「一个信号只有一位」。同一段里 handler 次数的变化（1 → 2）也是因为那是**两个不同信号**（SIGUSR1 和 SIGUSR2），而不是同一个信号发了两次。
</details>

<details>
<summary>7. 进程卡在 D 状态时 <code>kill -9</code> 为什么无效？</summary>

D = `TASK_UNINTERRUPTIBLE`，进程在内核态等 I/O 完成。信号只是置 pending 标志，真正处理要等进程**从内核态返回用户态**。D 状态的进程不返回用户态（一直睡在内核里等 I/O），所以信号永远没机会处理。只有 I/O 完成（或驱动超时）进程醒来，信号才生效。

这与本节「要点四」的生命周期图完全一致：**信号的处理点在「从内核态返回用户态」那一跳上**。参照 [2.7](./2.7-processes.md) 的状态表，D 是唯一「信号打不进去」的常规状态（内核还提供了 `TASK_KILLABLE` 作为「可被致命信号杀死」的变体）。
</details>

<details>
<summary>8. 信号处理器里为什么不能调 <code>printf</code>？</summary>

因为 `printf` **不可重入**：它要用 stdio 的全局缓冲区与锁。主流程可能正好在 `printf` 内部**持着那把锁**，此时信号到来、handler 插进来再调一次 `printf` → 要么**死锁**，要么数据错乱。

本节段 ⑤ 实测打印的清单里明确列了：

```text
  异步信号安全（可以调）：write / read / open / close / _exit /
                          kill / sigprocmask / waitpid / fcntl
  不安全（别调）：printf / malloc / free / strerror / syslog
```

**注意 `exit` 和 `_exit` 的差别**：`exit()` **不安全**（要跑 `atexit` + flush stdio，正撞在同一个 stdio 状态上），`_exit()` **安全**（直接进内核）。这与 [2.7](./2.7-processes.md) 段 ④ 的 `_exit` 不 flush 是**同一个 stdio 状态**的两面。

完整清单看 `signal-safety(7)`。本 demo 的 handler **只用 `write()`**——段 ①②③ 里那些 `[handler] ...` 行都是 `write` 输出的。
</details>
