## 本节讲什么

Linux 只有**一棵**目录树，所有文件和文件系统都挂在这棵树的某个节点下。本节回答三个问题：

1. 「单根目录树」是什么意思？不同的磁盘分区怎么变成 `/` 下的目录？
2. 硬链接和软链接的本质区别是什么？分别调哪个系统调用？
3. Linux 的 7 种文件类型分别是什么？

## 1. 单根目录树与挂载

Linux **只有一个根目录 `/`**，所有文件系统（磁盘分区、U 盘、网络盘）都「挂载（mount）」到 `/` 树的某个节点上，形成一棵统一的大树：

```
/                          ← 根文件系统（rootfs）
├── /bin                    ← 用户命令（常软链到 /usr/bin）
├── /dev                    ← devtmpfs：设备文件
├── /proc                   ← procfs：内核信息（见 2.19）
├── /sys                    ← sysfs：设备/驱动信息
├── /mnt/data               ← 挂载点：另一块磁盘分区挂在这
└── /home                   ← 用户家目录（可能是独立分区）
```

这和 Windows 的「每个盘符一棵树」（`C:\`、`D:\`）完全不同。Linux 里你**感觉不到**「换了块盘」——挂载点对上层完全透明，`/mnt/data/foo` 就是普通路径。

## 2. 目录、路径与 inode

| 概念 | 说明 |
|------|------|
| **绝对路径** | 从 `/` 开始：`/home/user/file` |
| **相对路径** | 相对当前工作目录：`../etc/passwd` |
| `.` / `..` | 当前目录 / 父目录（目录里的两个硬链接） |
| **inode** | 文件的「身份证」，存权限/大小/数据块指针，**不含文件名** |

**关键认知**：文件名**不在 inode 里**，而是存在**目录的数据块**里——目录本质是一张「文件名 → inode 号」的映射表。所以「删除文件」其实是删除目录里的映射项（`unlink`），当 inode 的链接计数（`i_nlink`）降到 0 才真正释放数据块。

## 3. 硬链接 vs 软链接

| 特性 | 硬链接（hard link） | 软链接（symlink） |
|------|--------------------|-------------------|
| 本质 | 同一 inode 的**另一个名字** | 存**路径字符串**的特殊文件 |
| 跨文件系统 | ❌（inode 号只在单个 FS 内唯一） | ✅（只存路径文本） |
| 指向目录 | ❌（避免环，通常禁止） | ✅ |
| 删原文件 | 不影响（inode 引用计数 >0 仍可访问） | 悬空（dangling，指向不存在的路径） |
| 创建系统调用 | `link()` | `symlink()` |
| 内核实现 | 目录项 +1 到同一 inode | 新建 inode，内容 = 路径串 |

```
硬链接：  /a/hard  ──┐
                   ├──→ inode 123（数据块）   链接计数 = 2
          /b/orig ──┘

软链接：  /a/sym ──→ 存 "/b/orig" 字符串 ──→ 解析后找到 /b/orig 的 inode
```

系统调用都落在 `fs/namei.c`：

```c
SYSCALL_DEFINE2(link, ...)      /* fs/namei.c:4708  建硬链接 */
SYSCALL_DEFINE2(symlink, ...)   /* fs/namei.c:4526  建软链接 */
SYSCALL_DEFINE1(unlink, ...)    /* fs/namei.c:4445  删名字（计数-1） */
SYSCALL_DEFINE2(mkdir, ...)     /* fs/namei.c:4162  建目录 */
SYSCALL_DEFINE2(rename, ...)    /* fs/namei.c:5057  改名（同 FS 原子） */
```

## 4. 7 种文件类型

`ls -l` 的第一个字符标识类型（`stat` 的 `st_mode` 用 `S_IS*` 宏判断）：

| 类型 | `ls` 标志 | 说明 | 例子 |
|------|-----------|------|------|
| 普通文件 | `-` | 文本/二进制 | 源码、可执行文件 |
| 目录 | `d` | 存「文件名→inode」映射 | `/etc` |
| 符号链接 | `l` | 存路径字符串 | `/bin/sh → dash` |
| 字符设备 | `c` | 按字节流访问 | `/dev/null`、`/dev/tty` |
| 块设备 | `b` | 按块访问（可随机寻址） | `/dev/sda` |
| FIFO | `p` | 命名管道（见 2.10） | `mkfifo` 创建 |
| 套接字 | `s` | Unix domain socket（见 2.10） | `/tmp/app.sock` |

「一切皆文件」的体现：设备、管道、socket 都是文件树上的一个节点，用统一的 `open`/`read`/`write` 操作（设备特殊文件见 2.5）。

## 5. HFT / 嵌入式关联

| 现象 | 本节机制的兑现 |
|------|----------------|
| 配置文件热更新 | 软链接做版本切换：`config → config.v2` 原子换链接（`symlink` + `rename`） |
| 崩溃安全的配置替换 | 临时文件 + `fsync` + `rename`（同 FS 原子替换，见 Ch18） |
| 数据分区隔离 | 把日志/行情数据挂到独立分区，避免写满根分区拖垮系统 |
| 跨文件系统限制 | 硬链接不能跨 FS，软链接可以——日志归档跨盘用软链接 |
| `/dev/shm` 共享内存 | tmpfs 挂载，POSIX 共享内存的物理载体（见 Ch54） |

## 6. 代码示例

```c
#include <stdio.h>
#include <unistd.h>
#include <sys/stat.h>
#include <sys/types.h>

int main(void) {
    /* 硬链接：同一 inode 两个名字 */
    if (link("orig.txt", "hard.txt") == -1) perror("link");

    /* 软链接：存路径字符串 */
    if (symlink("orig.txt", "sym.txt") == -1) perror("symlink");

    struct stat st1, st2;
    stat("orig.txt", &st1);
    stat("hard.txt", &st2);
    printf("orig  inode=%ld  nlink=%ld\n", (long)st1.st_ino, (long)st1.st_nlink);
    printf("hard  inode=%ld  nlink=%ld\n", (long)st2.st_ino, (long)st2.st_nlink);

    /* 硬链接：inode 相同、nlink=2；软链接则是不同 inode */
    struct stat st3;
    lstat("sym.txt", &st3);        /* lstat 不追符号链接本身 */
    printf("sym   inode=%ld (type=%s)\n", (long)st3.st_ino,
           S_ISLNK(st3.st_mode) ? "symlink" : "other");

    unlink("hard.txt"); unlink("sym.txt");
    return 0;
}
```

运行：`orig.txt` 和 `hard.txt` 的 inode 号相同、`nlink=2`（两个名字指向同一 inode）；`sym.txt` 是独立 inode、类型是 symlink。

<summary>代码自测（Q&A）</summary>

**Q1：硬链接和软链接的本质区别是什么？**
A：硬链接是**同一 inode 的另一个名字**——目录里多个名字映射到同一个 inode，链接计数（`nlink`）增加；软链接是**存路径字符串的特殊文件**，本身有独立 inode，内容是目标路径。所以硬链接删原文件不影响（inode 还在），软链接删原文件就悬空（dangling）。

**Q2：为什么硬链接不能跨文件系统？**
A：因为硬链接的本质是「多个目录项指向同一 inode 号」，而 **inode 号只在单个文件系统内唯一**（`/dev/sda1` 和 `/dev/sdb1` 都可能有自己的 inode #123）。跨文件系统无法用 inode 号唯一定位目标，所以 `link()` 跨 FS 会返回 `EXDEV`。软链接只存路径字符串，天然可跨 FS。

**Q3：Linux 的 7 种文件类型是什么？怎么在代码里判断？**
A：普通文件 `-`、目录 `d`、符号链接 `l`、字符设备 `c`、块设备 `b`、FIFO `p`、套接字 `s`。代码里用 `stat`/`lstat` 取 `st_mode`，配合 `S_ISREG`/`S_ISDIR`/`S_ISLNK`/`S_ISCHR`/`S_ISBLK`/`S_ISFIFO`/`S_ISSOCK` 宏判断。注意 `stat` 会**跟随**符号链接（返回目标类型），`lstat` 不跟随（返回符号链接本身）。

**Q4：文件名存在哪里？为什么「删除文件」不是删数据？**
A：文件名**不在 inode 里**，而是存在**目录的数据块**（目录 = 「文件名 → inode 号」映射表）。`unlink` 只删除目录里的这个映射项，inode 的链接计数（`i_nlink`）减 1；当计数降到 0（没有任何名字指向它）且没有进程打开它，内核才真正释放数据块。所以「文件被删但进程还开着」时数据仍在（打开的文件持有引用），进程关闭后才会真正释放。

**Q5：`rename()` 为什么能实现「崩溃安全的文件替换」？**
A：`rename` 在**同一文件系统内是原子的**（`fs/namei.c:5057` 的 `SYSCALL_DEFINE2(rename)`）：要么新名字完全生效，要么完全不变，不会出现中间态。所以「写临时文件 → `fsync` → `rename` 覆盖目标」是配置文件/数据文件安全替换的标准套路——即使中途崩溃，要么是旧文件、要么是新文件，不会出现写了一半的损坏文件。
