## 本节讲什么

Linux 只有**一棵**目录树，所有文件和文件系统都挂在这棵树的某个节点下。本节回答三个问题：

1. 「单根目录树」是什么意思？不同的磁盘分区怎么变成 `/` 下的目录？
2. 硬链接和软链接的本质区别是什么？分别调哪个系统调用？
3. Linux 的 7 种文件类型分别是什么？

完整 API 在 [Ch18](../../chapter-18-directories-links/README.md)，这里建立「目录树 + inode + 链接」的核心心智。

本节要补的是**表格里看不出来的那几条**：删了原文件之后硬链接和软链接**分别会怎样**、`EXDEV` 到底长什么样、以及「7 种文件类型」在一个只有 9 个 `/dev` 节点的容器里**凑不齐哪几种**。

## 要点

### 一、单根目录树与挂载

Linux **只有一个根目录 `/`**，所有文件系统（磁盘分区、U 盘、网络盘）都「挂载（mount）」到 `/` 树的某个节点上，形成一棵统一的大树：

```
/                          ← 根文件系统（rootfs）
├── /bin                    ← 用户命令（常软链到 /usr/bin）
├── /dev                    ← devtmpfs：设备文件
├── /proc                   ← procfs：内核信息（见 2.19）
├── /sys                    ← sysfs：设备/驱动信息
├── /mnt/data               ← 挂载点：另一块磁盘分区挂在这
└── /home                   ← 用户家目录（可能是独立分区）
```

这和 Windows 的「每个盘符一棵树」（`C:\`、`D:\`）完全不同。Linux 里你**感觉不到**「换了块盘」——挂载点对上层完全透明，`/mnt/data/foo` 就是普通路径。

### 二、目录、路径与 inode

| 概念 | 说明 |
|------|------|
| **绝对路径** | 从 `/` 开始：`/home/user/file` |
| **相对路径** | 相对当前工作目录：`../etc/passwd` |
| **`.` / `..`** | 当前目录 / 父目录（目录里的两个硬链接） |
| **inode** | 文件的「身份证」，存权限/大小/数据块指针，**不含文件名** |

**关键认知**：文件名**不在 inode 里**，而是存在**目录的数据块**里——目录本质是一张「文件名 → inode 号」的映射表。所以「删除文件」其实是删除目录里的映射项（`unlink`），当 inode 的链接计数（`i_nlink`）降到 0 才真正释放数据块。

### 三、硬链接 vs 软链接

| 特性 | 硬链接（hard link） | 软链接（symlink） |
|------|--------------------|-------------------|
| 本质 | 同一 inode 的**另一个名字** | 存**路径字符串**的特殊文件 |
| 跨文件系统 | ❌（inode 号只在单个 FS 内唯一） | ✅（只存路径文本） |
| 指向目录 | ❌（避免环，通常禁止） | ✅ |
| 删原文件 | 不影响（inode 引用计数 >0 仍可访问） | 悬空（dangling，指向不存在的路径） |
| 创建系统调用 | `link()` | `symlink()` |
| 内核实现 | 目录项 +1 到同一 inode | 新建 inode，内容 = 路径串 |
| `st_size` | 与目标相同（同一 inode） | **等于路径串长度** |
| `stat` vs `lstat` | 两者一样 | `stat` 跟随、`lstat` 看自己 |

```
硬链接：  /a/hard  ──┐
                   ├──→ inode 123（数据块）   链接计数 = 2
          /b/orig ──┘

软链接：  /a/sym ──→ 存 "/b/orig" 字符串 ──→ 解析后找到 /b/orig 的 inode
```

`st_size` 那一行是**一眼分辨软链接的快捷方式**：软链接自己的 `st_size` 就是它存的那个路径串有多长。

系统调用都落在 `fs/namei.c`：

```c
SYSCALL_DEFINE2(link, ...)      /* fs/namei.c:4708  建硬链接 */
SYSCALL_DEFINE2(symlink, ...)   /* fs/namei.c:4526  建软链接 */
SYSCALL_DEFINE1(unlink, ...)    /* fs/namei.c:4445  删名字（计数-1） */
SYSCALL_DEFINE2(mkdir, ...)     /* fs/namei.c:4162  建目录 */
SYSCALL_DEFINE2(rename, ...)    /* fs/namei.c:5057  改名（同 FS 原子） */
```

### 四、7 种文件类型

`ls -l` 的第一个字符标识类型（`stat` 的 `st_mode` 用 `S_IS*` 宏判断）：

| 类型 | `ls` 标志 | 说明 | 例子 |
|------|-----------|------|------|
| 普通文件 | `-` | 文本/二进制 | 源码、可执行文件 |
| 目录 | `d` | 存「文件名→inode」映射 | `/etc` |
| 符号链接 | `l` | 存路径字符串 | `/bin/sh → dash` |
| 字符设备 | `c` | 按字节流访问 | `/dev/null`、`/dev/tty` |
| 块设备 | `b` | 按块访问（可随机寻址） | `/dev/sda` |
| FIFO | `p` | 命名管道（见 [2.10](./2.10-ipc.md)） | `mkfifo` 创建 |
| 套接字 | `s` | Unix domain socket（见 [2.10](./2.10-ipc.md)） | `/tmp/app.sock` |

「一切皆文件」的体现：设备、管道、socket 都是文件树上的一个节点，用统一的 `open`/`read`/`write` 操作（设备特殊文件见 [2.5](./2.5-file-io-model.md)）。

## 代码

### c2_4 inode / nlink / 两种链接 / `EXDEV` / 7 种类型

[`../code/c2_4_links.c`](../code/c2_4_links.c) 分六段：

1. **建三种名字** —— `open`+`write` 建原文件，`link()` 建硬链接，`symlink()` 建软链接。
2. **inode 号与链接计数** —— 用 `stat` 分别看三者，**硬链与原文件 `st_ino` 相同、`st_nlink=2`；软链是独立 inode、`st_nlink=1`、`st_size == 路径长度`**。
3. **`stat` vs `lstat`** —— 同一个软链接，`stat` 跟随落到目标、`lstat` 停在链接自己。
4. **删掉原文件之后** —— `unlink(orig)` 后，硬链接**数据还活着**（`nlink` 从 2 降到 1），软链接**悬空**（`stat` 报 `ENOENT`）但 `lstat` 仍成功。
5. **硬链接不能跨文件系统** —— 实测 `link("/tmp/...", "/app/...")` 的 `EXDEV(18)`。
6. **7 种文件类型一次认全** —— 逐个 `stat` 并打印 `S_IS*` 判定结果。

```c
/* TLPI 第 2 章 §2.4 —— 单根目录树：硬链接 vs 软链接，7 种文件类型
 *
 * 编译：gcc -O0 -Wall -Wextra c2_4_links.c -o c2_4
 * 运行：./c2_4
 *
 * 本节要钉死的事实：
 *   ① 文件名不在 inode 里，存在「目录的数据块」= 一张「名字 → inode 号」映射表。
 *   ② 硬链接 = 同一 inode 的另一个名字（nlink 加一）；软链接 = 独立 inode，内容是路径串。
 *   ③ 删掉原文件：硬链接仍可访问（inode 引用计数 > 0），软链接悬空（dangling）。
 *   ④ 硬链接不能跨文件系统（EXDEV），软链接可以。
 *   ⑤ Linux 的 7 种文件类型用 stat 的 st_mode 配合 S_IS* 宏判断。
 */
#define _GNU_SOURCE
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <errno.h>
#include <unistd.h>
#include <fcntl.h>
#include <sys/stat.h>
#include <sys/types.h>
#include <sys/socket.h>
#include <sys/un.h>

#define DIR  "/tmp/c2_4"

static void jb(const char *label, int cond, const char *true_s, const char *false_s)
{
    printf("  %-46s %s\n", label, cond ? true_s : false_s);
}

/* 给一个路径判类型（stat 跟随符号链接，lstat 不跟随） */
static char type_char(mode_t m)
{
    if (S_ISREG(m))  return '-';
    if (S_ISDIR(m))  return 'd';
    if (S_ISLNK(m))  return 'l';
    if (S_ISCHR(m))  return 'c';
    if (S_ISBLK(m))  return 'b';
    if (S_ISFIFO(m)) return 'p';
    if (S_ISSOCK(m)) return 's';
    return '?';
}

static const char *type_name(mode_t m)
{
    if (S_ISREG(m))  return "普通文件";
    if (S_ISDIR(m))  return "目录";
    if (S_ISLNK(m))  return "符号链接";
    if (S_ISCHR(m))  return "字符设备";
    if (S_ISBLK(m))  return "块设备";
    if (S_ISFIFO(m)) return "FIFO(命名管道)";
    if (S_ISSOCK(m)) return "套接字";
    return "未知";
}

int main(void)
{
    char orig[128], hard[128], sym[128];
    snprintf(orig, sizeof(orig), "%s/orig.txt", DIR);
    snprintf(hard, sizeof(hard), "%s/hard.txt", DIR);
    snprintf(sym,  sizeof(sym),  "%s/sym.txt",  DIR);

    /* 干净起步 */
    unlink(hard); unlink(sym); unlink(orig);
    mkdir(DIR, 0755);

    printf("=== ① 建三种名字 ===\n");
    int fd = open(orig, O_RDWR | O_CREAT | O_TRUNC, 0644);
    if (fd < 0) { perror("open orig"); return 1; }
    if (write(fd, "hello inode\n", 12) != 12) perror("write");
    close(fd);
    printf("  open+write 建好了 %s\n", orig);

    if (link(orig, hard) == 0)       printf("  link(\"%s\", \"%s\") 成功\n", orig, hard);
    else                             printf("  link 失败 errno=%d(%s)\n", errno, strerror(errno));
    if (symlink(orig, sym) == 0)     printf("  symlink(\"%s\", \"%s\") 成功（存的是路径串）\n", orig, sym);
    else                             printf("  symlink 失败 errno=%d(%s)\n", errno, strerror(errno));
    errno = 0;

    printf("\n=== ② inode 号与链接计数（stat 跟随 / lstat 不跟随）===\n");
    struct stat a, h, l;
    if (stat(orig, &a) != 0) { perror("stat orig"); return 1; }
    if (stat(hard, &h) != 0) { perror("stat hard"); return 1; }
    if (lstat(sym, &l) != 0) { perror("lstat sym"); return 1; }

    printf("  %-12s st_ino=%-10ld st_nlink=%ld  type=%c(%s)\n",
           "orig.txt", (long)a.st_ino, (long)a.st_nlink, type_char(a.st_mode), type_name(a.st_mode));
    printf("  %-12s st_ino=%-10ld st_nlink=%ld  type=%c(%s)\n",
           "hard.txt", (long)h.st_ino, (long)h.st_nlink, type_char(h.st_mode), type_name(h.st_mode));
    printf("  %-12s st_ino=%-10ld st_nlink=%ld  type=%c(%s)  size=%ld\n",
           "sym.txt", (long)l.st_ino, (long)l.st_nlink, type_char(l.st_mode),
           type_name(l.st_mode), (long)l.st_size);

    printf("\n  关系判定（这部分每次跑都一样）：\n");
    jb("硬链接与原文件 inode 相同？", a.st_ino == h.st_ino, "SAME（同一 inode）", "DIFFERENT");
    jb("软链接与原文件 inode 相同？", l.st_ino != a.st_ino, "DIFFERENT（独立 inode）", "SAME");
    jb("硬链接使 nlink 增到 2？", a.st_nlink == 2 && h.st_nlink == 2, "YES nlink=2", "NO");
    jb("软链接的 st_size == 原路径长度？",
       (long)l.st_size == (long)strlen(orig), "YES（内容就是路径串）", "NO");

    printf("\n=== ③ 软链接与硬链接的「追不动」实验 ===\n");
    printf("  stat(\"sym.txt\") 跟随链接 -> 落在目标 orig.txt 上：\n");
    struct stat s2;
    if (stat(sym, &s2) == 0)
        printf("    stat  ok  st_ino=%ld  type=%c(%s)\n",
               (long)s2.st_ino, type_char(s2.st_mode), type_name(s2.st_mode));
    printf("  lstat(\"sym.txt\") 不跟随 -> 看到链接自己：\n");
    if (lstat(sym, &s2) == 0)
        printf("    lstat ok  st_ino=%ld  type=%c(%s)\n",
               (long)s2.st_ino, type_char(s2.st_mode), type_name(s2.st_mode));

    printf("\n=== ④ 删掉原文件之后 ===\n");
    printf("  unlink(\"%s\")\n", orig);
    unlink(orig);
    struct stat h2;
    errno = 0;
    if (stat(hard, &h2) == 0)
        printf("  硬链接 hard.txt 仍可 stat：st_ino=%ld nlink=%ld  -> 数据还活着\n",
               (long)h2.st_ino, (long)h2.st_nlink);
    else
        printf("  硬链接 stat 失败 errno=%d(%s)\n", errno, strerror(errno));
    errno = 0;
    if (stat(sym, &s2) == 0)
        printf("  软链接 stat 竟然成功（不该发生）\n");
    else
        printf("  软链接 stat 失败 errno=%d(%s)  -> 悬空(dangling)\n",
               errno, strerror(errno));
    errno = 0;
    if (lstat(sym, &s2) == 0)
        printf("  但 lstat(sym) 仍成功：链接文件本体现在还在，type=%c\n",
               type_char(s2.st_mode));
    printf("  把 nlink 归零后 inode 才真正释放：\n");
    unlink(hard);
    printf("    unlink(hard.txt) 之后，这个 inode 的引用计数归零\n");

    printf("\n=== ⑤ 硬链接不能跨文件系统 ===\n");
    errno = 0;
    if (link(sym, "/app/c2_4_xlink") == 0) {
        printf("  link(/tmp/... -> /app/...) 竟然成功 -> 说明 /tmp 与 /app 同一个 FS\n");
        unlink("/app/c2_4_xlink");
    } else {
        printf("  link(/tmp/... -> /app/...) 失败 errno=%d(%s)\n", errno, strerror(errno));
        printf("  EEXIST(%d)=目标已存在  EXDEV(%d)=跨文件系统\n", EEXIST, EXDEV);
    }
    errno = 0;

    printf("\n=== ⑥ 7 种文件类型一次认全 ===\n");
    /* 造一个 FIFO 和一个已绑定的 UNIX 套接字 */
    char fifo[128], sockp[128];
    snprintf(fifo, sizeof(fifo), "%s/pipe.fifo", DIR);
    snprintf(sockp, sizeof(sockp), "%s/app.sock", DIR);
    unlink(fifo); unlink(sockp);
    mkfifo(fifo, 0644);
    int sfd = socket(AF_UNIX, SOCK_STREAM, 0);
    struct sockaddr_un sa; memset(&sa, 0, sizeof(sa));
    sa.sun_family = AF_UNIX;
    strncpy(sa.sun_path, sockp, sizeof(sa.sun_path) - 1);
    if (sfd >= 0) bind(sfd, (struct sockaddr *)&sa, sizeof(sa));

    struct { const char *p; } cand[] = {
        { "/proc/self/exe" }, { DIR }, { sym }, { "/dev/null" },
        { "/dev/zero" }, { fifo }, { sockp }, { "/dev" },
    };
    printf("  %-24s %-4s %-14s %s\n", "路径", "类型", "S_ISxx", "说明");
    printf("  %-24s %-4s %-14s %s\n", "----------------------", "---",
           "------------", "----");
    for (unsigned i = 0; i < sizeof(cand) / sizeof(cand[0]); i++) {
        struct stat st;
        if (lstat(cand[i].p, &st) != 0) {
            printf("  %-24s %-4s %-14s (lstat 失败 errno=%d)\n",
                   cand[i].p, "?", "-", errno);
            errno = 0;
            continue;
        }
        const char *macro = S_ISREG(st.st_mode)  ? "S_ISREG"
                          : S_ISDIR(st.st_mode)  ? "S_ISDIR"
                          : S_ISLNK(st.st_mode)  ? "S_ISLNK"
                          : S_ISCHR(st.st_mode)  ? "S_ISCHR"
                          : S_ISBLK(st.st_mode)  ? "S_ISBLK"
                          : S_ISFIFO(st.st_mode) ? "S_ISFIFO"
                          : S_ISSOCK(st.st_mode) ? "S_ISSOCK" : "?";
        printf("  %-24s %-4c %-14s %s\n", cand[i].p, type_char(st.st_mode),
               macro, type_name(st.st_mode));
    }
    printf("  块设备(b)本环境没有；容器里 /dev 只映射了 null/zero/random/urandom。\n");

    if (sfd >= 0) close(sfd);
    unlink(sockp); unlink(fifo);
    return 0;
}
```

**解读**

1. **段 ② 的两行 `st_ino=3` 是硬链接定义本身**。`orig.txt` 与 `hard.txt` 的 inode 号**相同**、`st_nlink=2` —— 这就是「一个 inode，两个名字」。而 `sym.txt` 是 `st_ino=4`，一个**全新的 inode**，`st_size = 18` 正是 `"/tmp/c2_4/orig.txt"` 这个字符串的长度（18 个字符）。**用 `st_size` 就能一眼认出软链接。**
2. **段 ③ 是「跟随 vs 不跟随」的对照**：同一个 `sym.txt`，`stat()` 返回 `st_ino=3`（跳到目标 `orig.txt` 上），`lstat()` 返回 `st_ino=4`（停在链接自己）。**做「判断某个路径是不是软链接」时必须用 `lstat`**，用 `stat` 永远看不到链接本身。
3. **段 ④ 是全节最有价值的一段**，因为它把「删原文件」这一个动作的两种后果并排了：
   - **硬链接 `hard.txt`：`st_ino=3 nlink=1`，数据还活着**。原名字没了，但 inode 的引用计数还剩 1，所以内容一个字节都没丢——这就是「Linux 里删文件其实只是删名字」的直接证据。
   - **软链接：`stat` 报 `errno=2`（`ENOENT`），悬空**。因为它存的只是一串路径文本，目标没了它也没了。
   - 但**`lstat(sym)` 仍然成功，`type=l`** —— 软链接这个「文件实体」还在，只是它指向的东西不在了。这三行的区别把「路径 → inode → 数据」三层彻底分开了。
4. **段 ⑤ 的 `EXDEV(18)` 是内核级的硬约束**。`link(/tmp/... → /app/...)` 失败，因为 `/tmp` 和 `/app` 是两个不同的挂载点（不同文件系统），**inode 号只在单个文件系统内唯一**——`/tmp` 里的 inode 3 和 `/app` 里的 inode 3 是两回事，跨过去就无法唯一定位。顺带记一对易混错误码：**`EEXIST(17)` = 目标已存在，`EXDEV(18)` = 跨文件系统**。
5. **段 ⑥ 诚实报告了环境缺什么**：7 种类型里凑齐了 **6 种**（`l`/`d`/`c`/`p`/`s`），**块设备 `b` 一个都没有**——因为容器里 `/dev` 只映射了 `null`/`zero`/`random`/`urandom` 这 9 个节点，没有真实的磁盘。这不是 demo 写漏了，是容器的事实；在真机上 `stat("/dev/sda")` 就会看到 `S_ISBLK`。本仓库的约定是**做不成的实验写清楚做不成，不打印假输出**。

## 自测题

<details>
<summary>1. 硬链接和软链接的本质区别是什么？</summary>

硬链接是**同一 inode 的另一个名字**——目录里多个名字映射到同一个 inode，链接计数（`nlink`）增加；软链接是**存路径字符串的特殊文件**，本身有独立 inode，内容是目标路径。

本节实测的三行是最直接的证据：

```text
  orig.txt     st_ino=3          st_nlink=2  type=-(普通文件)
  hard.txt     st_ino=3          st_nlink=2  type=-(普通文件)
  sym.txt      st_ino=4          st_nlink=1  type=l(符号链接)  size=18
```

所以硬链接删原文件不影响（inode 还在），软链接删原文件就悬空（dangling）。另外**软链接自己的 `st_size` 等于路径串长度**（这里是 18）——这是一眼认出它的快捷方式。
</details>

<details>
<summary>2. 为什么硬链接不能跨文件系统？</summary>

因为硬链接的本质是「多个目录项指向同一 inode 号」，而 **inode 号只在单个文件系统内唯一**（`/dev/sda1` 和 `/dev/sdb1` 都可能有自己的 inode #3）。跨文件系统无法用 inode 号唯一定位目标，所以 `link()` 跨 FS 返回 **`EXDEV`**。

本节实测：

```text
=== ⑤ 硬链接不能跨文件系统 ===
  link(/tmp/... -> /app/...) 失败 errno=18(Invalid cross-device link)
  EEXIST(17)=目标已存在  EXDEV(18)=跨文件系统
```

软链接只存路径字符串，天然可跨 FS。
</details>

<details>
<summary>3. Linux 的 7 种文件类型是什么？怎么在代码里判断？</summary>

普通文件 `-`、目录 `d`、符号链接 `l`、字符设备 `c`、块设备 `b`、FIFO `p`、套接字 `s`。

代码里用 `stat`/`lstat` 取 `st_mode`，配合 `S_ISREG`/`S_ISDIR`/`S_ISLNK`/`S_ISCHR`/`S_ISBLK`/`S_ISFIFO`/`S_ISSOCK` 宏判断。

⚠️ **`stat` 会跟随符号链接**（返回目标类型），**`lstat` 不跟随**（返回符号链接本身）。本节实测这个差别：

```text
    stat  ok  st_ino=3  type=-(普通文件)      ← stat 跟随链接：落在目标 orig.txt 上
    lstat ok  st_ino=4  type=l(符号链接)      ← lstat 不跟随：看到链接自己
```

本节段 ⑥ 实测凑齐了 **6 种**（`l`/`d`/`c`/`p`/`s`），**块设备 `b` 在容器里不存在**——`/dev` 只映射了 `null`/`zero`/`random`/`urandom`，没有真实磁盘。
</details>

<details>
<summary>4. 文件名存在哪里？为什么「删除文件」不是删数据？</summary>

文件名**不在 inode 里**，而是存在**目录的数据块**（目录 = 「文件名 → inode 号」映射表）。

`unlink` 只删除目录里的这个映射项，inode 的链接计数（`i_nlink`）减 1；当计数降到 0（没有任何名字指向它）**且没有进程打开它**，内核才真正释放数据块。

本节实测把这个过程走了一遍：

```text
  unlink("/tmp/c2_4/orig.txt")
  硬链接 hard.txt 仍可 stat：st_ino=3 nlink=1  -> 数据还活着
  软链接 stat 失败 errno=2(No such file or directory)  -> 悬空(dangling)
  但 lstat(sym) 仍成功：链接文件本体现在还在，type=l
```

所以「文件被删但进程还开着」时数据仍在（打开的文件持有引用），进程关闭后才会真正释放。
</details>

<details>
<summary>5. <code>rename()</code> 为什么能实现「崩溃安全的文件替换」？</summary>

`rename` 在**同一文件系统内是原子的**（`fs/namei.c:5057` 的 `SYSCALL_DEFINE2(rename)`）：要么新名字完全生效，要么完全不变，不会出现中间态。

所以「写临时文件 → `fsync` → `rename` 覆盖目标」是配置文件/数据文件安全替换的标准套路——即使中途崩溃，要么是旧文件、要么是新文件，不会出现写了一半的损坏文件。

⚠️ 前提是**同一文件系统**（`/tmp` 和 `/app` 之间 `rename` 会 `EXDEV`）——本节段 ⑤ 的实测就是同一个约束。
</details>

<details>
<summary>6. 一个软链接的目标文件被删了，<code>lstat</code> 还能成功吗？</summary>

**能。** 这是「路径 → inode → 数据」三层分离的关键证据。

本节段 ④ 实测：

```text
  软链接 stat 失败 errno=2(No such file or directory)  -> 悬空(dangling)
  但 lstat(sym) 仍成功：链接文件本体现在还在，type=l
```

`stat()` 要跟随链接去拿目标，目标没了就 `ENOENT`；`lstat()` 只看链接这个文件**自己**，而它的实体（存着那串路径文本的 inode）还在，所以成功。

工程后果：**清理「悬空链接」的脚本必须用 `lstat` + 试 `stat` 两步**——只 `stat` 会把所有软链接都判成「不存在」。
</details>
