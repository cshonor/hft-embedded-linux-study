## 本节讲什么

进程组是「一组相关进程」的集合，shell 用它实现作业控制（`Ctrl+C`/`Ctrl+Z`/`fg`/`bg`）。本节回答三个问题：

1. 进程组是什么？PGID 怎么定？
2. 为什么 `Ctrl+C` 能一次杀掉一整个「管道命令」？
3. 内核里进程组存在哪？

完整机制在 Ch34，这里建立「组 = 信号广播单位」的核心心智。

---

## 1. 进程组的基本概念

| 概念 | 说明 |
|------|------|
| PGID | 进程组 ID，= 组长（第一个进程）的 PID |
| 组长 | 创建进程组的进程，`PGID == 组长 PID` |
| 归属 | 每个进程都属于一个进程组，可 `setpgid()` 迁移 |

```c
pid_t getpgrp(void);                     /* 取本进程组 ID */
int   setpgid(pid_t pid, pid_t pgid);    /* 设置进程组 */
```

内核侧，进程组 ID 通过 `task_struct` 关联的 `pid` 结构获取：

```c
static inline pid_t task_pgrp_nr(struct task_struct *tsk)   /* linux/sched.h:1659 */
{ return task_pgrp_nr_ns(tsk, &init_pid_ns); }
```

## 2. 作业控制：信号按「组」广播

shell 跑 `ls | grep foo | wc` 是一条**管道**，三个进程组成**一个进程组**（PGID = `ls` 的 PID）。终端信号按组发送：

| 操作 | 信号 | 发给谁 |
|------|------|--------|
| `Ctrl+C` | SIGINT | **整个前台进程组**（三个进程全收） |
| `Ctrl+Z` | SIGTSTP | 整个前台进程组（暂停） |
| `fg` / `bg` | SIGCONT | 恢复指定作业 |

**关键**：终端驱动（或 shell）把 `Ctrl+C` 变成 SIGINT 后，发给的是**前台进程组**，不是单个进程。这就是「`kill -INT -pgid`」能一次停掉整条交易管线的原因——负号表示「进程组」。

## 3. 进程组、会话、终端的关系

```
会话 (session)
 ├── 前台进程组  ←─ 接收终端输入（Ctrl+C 等信号）
 ├── 后台进程组 1
 └── 后台进程组 2
```

- **前台进程组**：唯一能读终端输入、接收终端信号的组
- **后台进程组**：读终端会触发 `SIGTTIN`，写触发 `SIGTTOU`（默认暂停）

## 4. HFT / 嵌入式关联

| 现象 | 本节机制的兑现 |
|------|----------------|
| 一次停掉整条交易管线 | `kill(-pgid, SIGTERM)` 按组广播，feed → 策略 → 下单全链路优雅退出 |
| 交易进程 daemon 化 | `setsid()` 脱离控制终端（见 2.14），避免误按 `Ctrl+Z` 挂起主循环 |
| 后台读终端被暂停 | 后台进程读 stdin 触发 SIGTTIN 默认挂起——headless 交易机 stdout 非 tty 无此问题 |

## 5. 代码示例

```c
#include <stdio.h>
#include <unistd.h>
#include <signal.h>
#include <sys/wait.h>
/* kill(-pgid, sig)：给整个进程组发信号 */
int main(void) {
    pid_t pgid = getpgrp();
    printf("my pgid = %d\n", pgid);

    if (fork() == 0) {
        setpgid(0, 0);               /* 子进程自成一组（组长） */
        for (;;) pause();            /* 挂起等信号 */
    }
    /* 父进程给「负 pgid」发信号 = 广播到整组 */
    kill(-pgid, SIGTERM);
    wait(NULL);
    return 0;
}
```

<details>
<summary>代码自测（Q&A）</summary>

**Q1：PGID 和组长的关系是什么？**
A：进程组 ID（PGID）等于**组长进程的 PID**。组长是第一个创建该组的进程。组长退出后进程组仍可存在（组内其他进程还在），此时 PGID 不再对应任何存活进程，但组 ID 仍有效。

**Q2：`kill(pid, sig)` 里的 `pid` 传负数是什么意思？**
A：传 `-pgid` 表示「给整个进程组 pgid 发信号」。`kill` 的 `pid` 参数语义：`>0` 发该进程、`==0` 发同进程组、`==-1` 发所有有权限的进程、`<-1` 发进程组 `-pid`。所以 `kill(-123, SIGTERM)` 是「停掉整个进程组 123」。

**Q3：为什么 `Ctrl+C` 能一次杀掉 `ls | grep | wc` 整条管道？**
A：shell 把管道里的进程放进**同一个进程组**，终端驱动收到 `Ctrl+C` 后产生 SIGINT 发给**前台进程组**（整组）。所以三个进程同时收到 SIGINT。这依赖「组」作为信号广播单位——若各自独立进程组，就得逐个 kill。

**Q4：后台进程读终端会发生什么？**
A：后台进程组读终端（stdin）时，终端驱动发 `SIGTTIN`，默认动作是**暂停**（stop）该进程，直到被 `fg` 调到前台并继续。写终端同理触发 `SIGTTOU`。这是作业控制保证「只有前台进程能跟终端交互」的机制。

**Q5：交易进程为什么要 `setsid()` 脱离控制终端？**
A：控制终端是「会话」的属性，挂着一个会话会收到终端的 SIGHUP（终端关闭时）和 SIGINT/SIGTSTP（按键时）。交易服务要长期后台运行，必须脱离控制终端，否则运维人员误按 `Ctrl+C`/`Ctrl+Z` 会直接打断交易主循环。`setsid` 新建会话、脱离旧终端（见 2.14、Ch37）。

</details>
