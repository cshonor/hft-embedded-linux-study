## 本节讲什么

进程组是「一组相关进程」的集合，shell 用它实现作业控制（`Ctrl+C` / `Ctrl+Z` / `fg` / `bg`）。本节回答三个问题：

1. 进程组是什么？PGID 怎么定？
2. 为什么 `Ctrl+C` 能一次杀掉一整个「管道命令」？
3. 内核里进程组存在哪？

完整机制在 [Ch34](../../chapter-34-process-groups-sessions/README.md)，这里建立「**组 = 信号广播单位**」的核心心智。

本节要补的是**广播语义的实测证据**：`setpgid(0,0)` 让子进程 `pgid` 从 `2` 变成 `3`，随后 `kill(-3, SIGTERM)` 一条语句就把子进程打死——**负号那个「-」就是整节的全部内容**。

## 要点

### 一、进程组：PGID == 组长的 PID

| 概念 | 说明 |
|------|------|
| PGID | 进程组 ID，**= 组长（第一个创建该组的进程）的 PID** |
| 组长（leader） | 创建进程组的进程，满足 `PGID == 自己的 PID` |
| 归属 | 每个进程**必须**属于一个进程组；`fork` 出的子进程**默认继承父进程的组** |
| 迁移 | `setpgid()` 可以搬组，或自成一组 |

```c
pid_t getpgrp(void);                     /* 取本进程组 ID，等价 getpgid(0) */
int   setpgid(pid_t pid, pid_t pgid);    /* 把 pid 放进 pgid 组 */
```

`setpgid(0, 0)` 是**自成一组**的惯用法：`pid=0` 表示「我自己」，`pgid=0` 表示「组号取我自己的 PID」——于是本进程既是成员又是组长。

内核侧，进程组 ID 通过 `task_struct` 上挂的 `signal_struct` 取，v6.6 的取值函数：

```c
static inline pid_t task_pgrp_nr(struct task_struct *tsk)   /* include/linux/sched.h:1659 */
{
	return task_pgrp_nr_ns(tsk, &init_pid_ns);
}
```

> 注意：进程组**没有自己的 `task_struct`**——它是挂在 `signal_struct->pids[PIDTYPE_PGID]` 上的一个 `struct pid`。这就是为什么「组长退出后进程组仍存在」：只要组内还有进程，那个 `struct pid` 就被引用着。

### 二、`kill()` 的 `pid` 参数是「有符号」的——负数 = 广播

这是本节最值钱的一条：`kill(2)` 的 `pid` 参数**不是「进程 ID」，而是一个选择器**。

| `pid` 取值 | 含义 | 典型用法 |
|-----------|------|----------|
| `pid > 0` | 发给**单个进程** `pid` | `kill(1234, SIGTERM)` |
| `pid == 0` | 发给**调用者所在的进程组**的每个进程 | 向同组伙伴广播 |
| `pid == -1` | 发给**所有有权限发信号的进程**（init 除外） | `killall` 类工具的底层 |
| `pid < -1` | 发给**进程组 `|pid|` 的所有成员** | `kill(-1234, SIGTERM)` |

所以 `kill(-1234, SIGTERM)` 读作「**给进程组 1234 广播 SIGTERM**」——那三个进程一起死。**负号不是「反向」，是「组」**。

⚠️ 使用前必须确认目标组**不含自己**（本节 demo 就是这个防御：`if (cpgid != getpgrp())`）。否则 `kill(-我的组, SIGTERM)` 会把自己也杀掉，程序在下一行之前就没了。

### 三、作业控制：终端信号按「前台进程组」发送

shell 跑 `ls | grep foo | wc` 时，三个进程被放进**同一个进程组**（PGID = `ls` 的 PID），并把它设为终端的**前台进程组**。

| 按键 | 终端驱动产生 | 发给谁 |
|------|-------------|--------|
| `Ctrl+C` | SIGINT | **整个前台进程组**（等价 `kill(-pgid, SIGINT)`） |
| `Ctrl+Z` | SIGTSTP | 整个前台进程组（**暂停**，不是杀死） |
| `Ctrl+\` | SIGQUIT | 整个前台进程组（默认 core dump） |

`fg` / `bg` 时 shell 调 `tcsetpgrp()` 切换前台组 + 发 `SIGCONT` 恢复。

**关键**：终端驱动不知道「管道」是什么，它只知道「前台进程组」。进程组是终端与「一组进程」之间的**唯一接口**。

### 四、「作业」不是一个内核概念

`jobs` 打印的 `[1]`、`[2]` 是 **shell 自己维护的表**（job → 进程组），内核里没有「作业」这个东西。所以：

- 「作业」= shell 数据结构 + 一个进程组 + 一组状态；
- 换一种 shell（`bash` → `zsh`），作业编号规则可能不同，但**进程组语义完全相同**；
- 会话首领（见 [2.14](./2.14-sessions.md)）→ 若干进程组 → 每组若干进程，这才是内核的三层结构。

## 代码

### c2_13 进程组：从 `pid == pgid` 到 `kill(-pgid)` 广播

[`../code/c2_13_pgroup.c`](../code/c2_13_pgroup.c) 分五段：

| 段 | 做什么 | 钉死什么 |
|----|--------|----------|
| ① | 打印 `getpid()` / `getpgrp()` / `getpgid(0)` / `getppid()` | `pid == pgid` ⇒ 本进程是**组长** |
| ② | `fork` 子进程，先看默认 `pgid`，再 `setpgid(0,0)` 重看 | 子进程**默认继承父的组**；`setpgid(0,0)` 后**自成一组** |
| ③ | 用 `pipe` 做「子进程就绪」同步，然后 `kill(-cpgid, SIGTERM)` | **负号 = 广播**：一条语句打死子进程 |
| ④ | ASCII 讲 `Ctrl+C` 的完整链路 | 终端 → 前台进程组 → 三个进程 |
| ⑤ | 6 个进程组相关调用一览表 | 记住接口形状 |

```c
/* TLPI 第 2 章 §2.13 —— 进程组与作业控制：kill(-pgid) 的广播语义
 *
 * 编译：gcc -O0 -Wall -Wextra c2_13_pgroup.c -o c2_13
 * 运行：./c2_13
 *
 * 本节要钉死的事实：
 *   ① 进程组是「一组进程的集合」，pgid == 组长的 pid。fork 出的子进程默认同组。
 *   ② setpgid(0, 0) 让调用者自成一组（自己当组长）。
 *   ③ kill() 的 pid 参数为**负数**时表示「发给 |pid| 这个进程组的所有成员」。
 *   ④ 这正是 shell 的 Ctrl+C / Ctrl+Z 能一次性作用到整条管道的原因 ——
 *      终端驱动把信号发给「前台进程组」，不是发给某个进程。
 */
#define _GNU_SOURCE
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <errno.h>
#include <unistd.h>
#include <signal.h>
#include <sys/wait.h>
#include <sys/types.h>

static void report_status(const char *tag, int status)
{
    if (WIFEXITED(status))
        printf("  %s: 正常退出 code=%d\n", tag, WEXITSTATUS(status));
    else if (WIFSIGNALED(status))
        printf("  %s: 被信号 %d (%s) 杀死\n", tag, WTERMSIG(status),
               strsignal(WTERMSIG(status)));
    else
        printf("  %s: status=0x%x\n", tag, status);
}

int main(void)
{
    printf("=== ① 我自己的进程组 ===\n");
    printf("  getpid()      = %d\n", (int)getpid());
    printf("  getpgrp()     = %d\n", (int)getpgrp());
    printf("  getpgid(0)    = %d\n", (int)getpgid(0));
    printf("  getppid()     = %d\n", (int)getppid());
    printf("  -> pid == pgid，说明本进程是进程组的**组长（leader）**\n");

    printf("\n=== ② fork 出的子进程默认在同一个组 ===\n");
    int ready[2];
    if (pipe(ready) < 0) { perror("pipe"); return 1; }

    fflush(NULL);
    pid_t pid = fork();
    if (pid < 0) { perror("fork"); return 1; }

    if (pid == 0) {
        /* ---------------- 子进程 ---------------- */
        close(ready[0]);
        printf("  [child] 刚 fork 出来：pid=%d  pgid=%d  （pgid 就是父的 pid）\n",
               (int)getpid(), (int)getpgrp());

        if (setpgid(0, 0) < 0)                  /* 0,0 = 以自己为组长新建一组 */
            printf("  [child] setpgid(0,0) 失败 errno=%d (%s)\n", errno, strerror(errno));
        else
            printf("  [child] setpgid(0,0) 后：pid=%d  pgid=%d  （自成一组了）\n",
                   (int)getpid(), (int)getpgrp());
        fflush(NULL);

        char b = 'x';
        if (write(ready[1], &b, 1) < 0) { /* 告诉父进程「我准备好了」 */ }
        close(ready[1]);

        pause();                                /* 挂着等信号 */
        fflush(NULL);
        _exit(0);                               /* SIGTERM 默认会直接终止，走不到这 */
    }

    /* ---------------- 父进程 ---------------- */
    close(ready[1]);
    char b;
    if (read(ready[0], &b, 1) < 0) { /* 等子进程就绪 */ }
    close(ready[0]);

    pid_t cpgid = getpgid(pid);
    printf("  父进程验证：子进程 %d 现在属于进程组 %d\n", (int)pid, (int)cpgid);
    printf("  父进程自己在进程组 %d\n", (int)getpgrp());

    printf("\n=== ③ kill(-pgid, sig)：给整组广播 ===\n");
    if (cpgid != getpgrp()) {
        printf("  安全前提成立（子进程的组 != 父的组），广播不会伤到自己\n");
        printf("  kill(%d, SIGTERM)  <- 负号 = 发给整个进程组\n", -(int)cpgid);
        if (kill(-cpgid, SIGTERM) < 0) perror("kill(-pgid)");
    } else {
        printf("  ⚠️ 子进程还在父进程的组里 —— 广播会连本进程一起杀\n");
        printf("     所以这里退化成给单个进程发：kill(%d, SIGTERM)\n", (int)pid);
        if (kill(pid, SIGTERM) < 0) perror("kill(pid)");
    }

    int st = 0;
    if (waitpid(pid, &st, 0) < 0) perror("waitpid");
    else report_status("child", st);

    printf("\n=== ④ 为什么 Ctrl+C 能杀掉整条管道 ===\n");
    printf("  shell 把 `ls | grep | wc` 里的三个进程放进**同一个进程组**，\n");
    printf("  并把它设为终端的「前台进程组」。你按 Ctrl+C 时：\n");
    printf("    终端驱动 → 给前台进程组发 SIGINT（等价 kill(-pgid, SIGINT)）\n");
    printf("    → 三个进程一起收到，一起结束\n");
    printf("  Ctrl+Z 同理，发的是 SIGTSTP；shell 收到状态变化后打印 [1]+ Stopped，\n");
    printf("  fg/bg 时再调 tcsetpgrp() 切换前台组 + 发 SIGCONT。\n");
    printf("  → 作业控制不是 shell 的魔法，是「进程组 + 会话」两套内核机制的编排。\n");

    printf("\n=== ⑤ 与进程组相关的常用调用 ===\n");
    printf("  %-26s %s\n", "getpgrp()", "取本进程的 pgid（= getpgid(0)）");
    printf("  %-26s %s\n", "getpgid(pid)", "取指定进程的 pgid");
    printf("  %-26s %s\n", "setpgid(pid, pgid)", "把 pid 放进 pgid 组；setpgid(0,0) = 自成一组");
    printf("  %-26s %s\n", "kill(-pgid, sig)", "给整个组广播信号");
    printf("  %-26s %s\n", "waitpid(-pgid, ...)", "等整个组里的任意子进程（pid 也可以给负数）");
    printf("  %-26s %s\n", "tcsetpgrp(fd, pgid)", "把某个进程组设为终端的前台组（作业控制核心）");
    return 0;
}
```

```bash
gcc -O0 -Wall -Wextra -o c2_13 c2_13_pgroup.c && ./c2_13
```

实测输出（另在 Compiler Explorer 复核，gcc 13.3.0 / x86-64 / Ubuntu 24.04 容器）：

```text
=== ① 我自己的进程组 ===
  getpid()      = 2
  getpgrp()     = 2
  getpgid(0)    = 2
  getppid()     = 1
  -> pid == pgid，说明本进程是进程组的**组长（leader）**

=== ② fork 出的子进程默认在同一个组 ===
  [child] 刚 fork 出来：pid=3  pgid=2  （pgid 就是父的 pid）
  [child] setpgid(0,0) 后：pid=3  pgid=3  （自成一组了）
  父进程验证：子进程 3 现在属于进程组 3
  父进程自己在进程组 2

=== ③ kill(-pgid, sig)：给整组广播 ===
  安全前提成立（子进程的组 != 父的组），广播不会伤到自己
  kill(-3, SIGTERM)  <- 负号 = 发给整个进程组
  child: 被信号 15 (Terminated) 杀死

=== ④ 为什么 Ctrl+C 能杀掉整条管道 ===
  shell 把 `ls | grep | wc` 里的三个进程放进**同一个进程组**，
  并把它设为终端的「前台进程组」。你按 Ctrl+C 时：
    终端驱动 → 给前台进程组发 SIGINT（等价 kill(-pgid, SIGINT)）
    → 三个进程一起收到，一起结束
  Ctrl+Z 同理，发的是 SIGTSTP；shell 收到状态变化后打印 [1]+ Stopped，
  fg/bg 时再调 tcsetpgrp() 切换前台组 + 发 SIGCONT。
  → 作业控制不是 shell 的魔法，是「进程组 + 会话」两套内核机制的编排。

=== ⑤ 与进程组相关的常用调用 ===
  getpgrp()                  取本进程的 pgid（= getpgid(0)）
  getpgid(pid)               取指定进程的 pgid
  setpgid(pid, pgid)         把 pid 放进 pgid 组；setpgid(0,0) = 自成一组
  kill(-pgid, sig)           给整个组广播信号
  waitpid(-pgid, ...)        等整个组里的任意子进程（pid 也可以给负数）
  tcsetpgrp(fd, pgid)        把某个进程组设为终端的前台组（作业控制核心）
```

**解读**

1. **段 ① 的 `getppid() = 1` 说明了 CE 容器的进程树**：本程序是 PID 2，父进程是 PID 1（容器里的 init/PID-namespace 首领）。所以「`pid == pgid == 2`」是**偶然也是必然**——PID 1 建的进程组 1，而 PID 2 是被 PID 1 直接 `fork` 出来的，默认继承组 1？不，实测是组 2。原因是容器里 PID 2 自己**被 `setsid()` 过**（或由 `exec` 前的 shell 建过新组），所以它成了新组的组长。**读到这里的正确姿势**：不要背「PID 2 一定是组长」，要记住**判据是 `pid == pgid`**，它只是恰好成立。

2. **段 ② 是本节最重要的一组数字，两个 `pgid` 的对比就是全部结论**：

   | 时刻 | pid | pgid | 含义 |
   |------|-----|------|------|
   | 刚 `fork` 完 | 3 | **2** | 继承父的组（`2` 是父的 PID） |
   | `setpgid(0,0)` 后 | 3 | **3** | 自成一组，`pgid == 自己的 pid` ⇒ 自己是**组长** |

   `fork` 的「继承」不是复制数值那么简单——内核把子进程挂到**同一个 `struct pid`**（`PIDTYPE_PGID`）上，所以父子 `pgid` 天然一致。`setpgid(0,0)` 则是把它从旧组摘下来、挂到自己新建的组上。

3. **段 ③ 的 `kill(-3, SIGTERM)` 与 `waitpid` 的配合值得记住**：`waitpid` 报告的是 `被信号 15 (Terminated) 杀死`（`WIFSIGNALED` 分支），而**不是**「正常退出」。这正是 `report_status()` 里写两个分支的原因——被信号杀死的进程**没有退出码**，`WEXITSTATUS(st)` 取出来是垃圾值。**判断子进程死因必须用 `WIFSIGNALED` + `WTERMSIG`**，对照 [2.7](./2.7-processes.md) 段 ⑥ 的 wait 宏。

4. **`if (cpgid != getpgrp())` 这个防御分支是本 demo 的设计要点**：真实代码里如果子进程没成功 `setpgid`（比如它已经 `exec` 成别的程序了，或权限不足），它就会留在父进程的组里，此时 `kill(-父pgid)` 会把父进程**自己也打死**。所以广播前**必须**验证目标组不含自己。这是最容易出「程序莫名其妙自杀」的一类 bug。

5. **段 ④ 那段文字里的 `tcsetpgrp()` 才是作业控制的真正核心**：它把某个进程组设为终端的**前台组**。shell 拿到 `Ctrl+Z` 之后，做的是「用 `tcsetpgrp` 把前台组切回自己 + `SIGCONT` 目标组」给 `bg`；`fg` 则反过来。**终端只认「前台组」这一个概念**——本节和 [2.14 会话](./2.14-sessions.md) 合起来才是完整的作业控制。

## HFT / 嵌入式关联

| 现象 | 本节机制的兑现 |
|------|----------------|
| 一次停掉整条交易管线 | `kill(-pgid, SIGTERM)` 按组广播，feed → 策略 → 下单全链路**同时**收到信号，一起做优雅退出 |
| 交易进程 daemon 化 | 必先 `setsid()` 脱离控制终端（见 [2.14](./2.14-sessions.md)），否则运维误按 `Ctrl+C`/`Ctrl+Z` 会直接打断主循环 |
| **广播前必须验「不含自己」** | 段 ③ 的 `if (cpgid != getpgrp())`。**线上事故经典形态**：`kill(0, SIGTERM)` 或误算的负 pgid 把 orchestrator 自己干掉 |
| 后台进程读终端被暂停 | 后台组 `read(stdin)` 触发 `SIGTTIN`，**默认是暂停**（不是报错）。headless 交易机 stdin 是 `/dev/null` 或套接字，`isatty=0` 故无此问题——但一旦有人 `ssh` 上去跑就中招 |
| 容器里 PID 1 处理信号特殊 | 容器的 PID 1 默认**忽略**未注册的信号，且**不 reap 僵尸**。若把交易程序当 PID 1 跑，`kill(-1, SIGTERM)` 行为与常规 shell 环境不同——用 `tini`/`--init` 更稳 |
| **不要用 `killall <名字>` 收交易进程** | `killall` 匹配的是**进程名**（`comm`，15 字符截断），匹配面不可控；**用进程组广播或 PID 文件**才是确定性的 |
| 嵌入式启动脚本里 `&` 起的后台组 | init 脚本里 `server &` 起在**同一个组**，`Ctrl+C`（若还有控制终端）会连带杀掉启动脚本；应显式 `setsid` 或 `setpgid` |

## 自测题

<details>
<summary>1. PGID 和组长的关系是什么？组长退出后进程组还在吗？</summary>

进程组 ID（PGID）**等于组长进程的 PID**。组长是第一个创建该组的进程（满足 `pid == pgid`）。

**组长退出后组仍然存在**——只要组内还有其他进程，内核里那个代表组的 `struct pid`（挂在 `signal_struct->pids[PIDTYPE_PGID]`）就被引用着，不会消失。此时 PGID 不再对应任何存活进程，但这个组号**依然有效**（还能 `kill(-pgid)`、还能 `waitpid(-pgid)`）。

本文要点一末尾的注意块就是这条：**进程组不是 `task_struct`，是一个 `struct pid`**——所以它不随组长死亡而消失。

⚠️ 这与「会话首领」不同：会话首领退出会向**整个会话**发 `SIGHUP`（见 [2.14](./2.14-sessions.md)）。
</details>

<details>
<summary>2. <code>kill(pid, sig)</code> 里的 <code>pid</code> 传负数是什么意思？四种取值分别代表什么？</summary>

| `pid` 取值 | 发给谁 |
|-----------|--------|
| `> 0` | 单个进程 `pid` |
| `== 0` | 调用者**所在的整个进程组** |
| `== -1` | 所有**有权限发信号**的进程（init 除外） |
| `< -1` | 进程组 `\|pid\|` 的**所有成员** |

所以 `kill(-123, SIGTERM)` = 「停掉整个进程组 123」。**负号表示「进程组」不是「反向」**。

本节段 ③ 实测 `kill(-3, SIGTERM)` → `child: 被信号 15 (Terminated) 杀死`。

⚠️ 用负 `pid` 广播前**必须**确认目标组不含自己，否则会把自己杀掉（demo 里的 `if (cpgid != getpgrp())` 就是这个防御）。
</details>

<details>
<summary>3. 为什么 <code>Ctrl+C</code> 能一次杀掉 <code>ls | grep | wc</code> 整条管道？</summary>

因为 shell 把管道里的进程放进**同一个进程组**，并把它设为终端的**前台进程组**。终端驱动收到 `Ctrl+C` 后产生 SIGINT，发给的是「**前台进程组**」而不是某个进程——等价于 `kill(-pgid, SIGINT)`，三个进程同时收到。

这依赖「组 = 信号广播单位」。若三个进程各自独立成组，shell 就得逐个 `kill`。

本文要点三的三行表（`Ctrl+C`→SIGINT / `Ctrl+Z`→SIGTSTP / `Ctrl+\`→SIGQUIT）说明：**终端驱动不知道「管道」存在，它只认「前台进程组」**。进程组是终端与「一组进程」之间的唯一接口。
</details>

<details>
<summary>4. 后台进程读终端会发生什么？默认动作是什么？</summary>

后台进程组读终端（stdin）时，终端驱动发 **`SIGTTIN`**，**默认动作是暂停（stop）该进程**，不是报错、也不是杀死——直到被 `fg` 调到前台并 `SIGCONT` 才继续。写终端同理触发 **`SIGTTOU`**。

这是作业控制保证「只有前台进程能跟终端交互」的机制。

⚠️ 两个坑：**①** 后台进程**看起来卡住不动**，新手常误判成死锁；**②** 用 `stty tostop` 可以让后台写终端也触发 SIGTTOU。headless 环境（stdin 不是 tty，`isatty=0`）不会触发这套机制。
</details>

<details>
<summary>5. 「作业（job）」是内核概念吗？</summary>

**不是。** `jobs` 打印的 `[1]`、`[2]` 是 **shell 自己维护的表**（job 编号 → 进程组），内核里根本没有「作业」这个数据结构。

内核只有三层结构：

```
会话（session）
 └── 进程组（process group）   ← 本节
      └── 进程（process）
```

所以「作业」= shell 数据结构 + 一个进程组 + 一组状态。换 shell（`bash` → `zsh`）作业编号规则可能变，但**进程组语义完全相同**。

本文要点四就是这条。
</details>

<details>
<summary>6. 交易进程为什么要 <code>setsid()</code> 脱离控制终端？广播信号还要注意什么？</summary>

**为什么要 `setsid()`：** 控制终端是「会话」的属性。挂在一个会话上，就会收到终端的 `SIGHUP`（终端关闭时）和 `SIGINT`/`SIGTSTP`（按键时）。交易服务要长期后台跑，必须脱离控制终端，否则运维误按 `Ctrl+C`/`Ctrl+Z` 会直接打断交易主循环。`setsid` 新建会话、脱离旧终端（见 [2.14](./2.14-sessions.md)、[Ch37](../../chapter-37-daemons/README.md)）。

**广播信号的两条纪律：**

1. **广播前验「不含自己」**——段 ③ 的 `if (cpgid != getpgrp())`。线上事故经典形态是误算负 pgid 把 orchestrator 自己干掉（HFT 表里有这一行）。
2. **别用 `killall <名字>` 收交易进程**——`killall` 匹配的是 **`comm`（进程名，15 字符截断）**，匹配面不可控（可能杀掉同名监控、同名测试进程）；**进程组广播或 PID 文件才是确定性的**。
</details>
