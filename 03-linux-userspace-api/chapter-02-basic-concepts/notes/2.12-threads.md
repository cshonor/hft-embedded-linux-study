## 本节讲什么

线程是进程内的执行单元。本节回答三个问题：

1. 线程和进程在内核里到底有什么区别？
2. `pthread_create` 底层走的是哪个系统调用、传了什么标志？
3. 为什么 `getpid()` 在线程里返回的都是同一个值？

这是后面 [Ch29](../../chapter-29-threads-intro/README.md)-[33](../../chapter-32-thread-cancellation/README.md) 线程系列（创建/同步/线程安全/取消）的入口。

本节要补的是**共享与私有边界的实测**：全局变量改了主线程**立刻看得见**（对照 [2.7](./2.7-processes.md) 的 fork 看不见），而每个线程的**栈地址各不相同**。

---

## 要点

### 一、内核真相：线程 = 共享更多资源的 task

Linux 内核里**没有独立的「线程」结构体**——线程和进程都是 `task_struct`，区别只在**共享粒度**：

```c
struct task_struct {                 /* include/linux/sched.h */
    pid_t pid;                       /* :967 线程 ID（tid，内核唯一） */
    pid_t tgid;                      /* :968 线程组 ID（= 主线程的 pid） */
};
```

```
进程（单线程）:  task_struct A（pid=100, tgid=100）
线程组:          task_struct A（pid=100, tgid=100）   ← 主线程
                 task_struct B（pid=101, tgid=100）   ← 同组线程
                 task_struct C（pid=102, tgid=100）
                        ↑ tgid 相同 = 同一进程
```

- **用户态 `getpid()`** 返回的是 **tgid**（线程组 ID）→ 同一进程所有线程返回相同值
- **`gettid()`** 返回的是 **pid**（内核唯一 tid）→ 每个线程不同
- `ps -L` / `top -H` 看到的每个「线程」就是 `task_struct->pid`

### 二、`pthread_create` 底层：`clone` 传共享标志

```c
pthread_create(&tid, NULL, start, arg)
        │
        ▼
clone(CLONE_VM | CLONE_FS | CLONE_FILES | CLONE_SIGHAND | CLONE_THREAD, 新栈顶)
        │        │         │             │                └─ 加入同一线程组(共享 tgid)
        │        │         │             └─ 共享信号处理表(sighand_struct)
        │        │         └─ 共享 fd 表(files_struct)
        │        └─ 共享根目录/工作目录
        └─ 共享地址空间(页表，mm_struct)
```

源码里这些标志的判定（`kernel/fork.c`）：

| 标志 | 语义 | 行号 |
|------|------|------|
| `CLONE_VM` | 共享地址空间（不复制页表） | `:1731` |
| `CLONE_FILES` | 共享 fd 表 | `:1784` |
| `CLONE_SIGHAND` | 共享信号处理表 | `:1803` |
| `CLONE_THREAD` | 加入同一线程组（共享 tgid） | `:1852` |

**对照**：`fork` 只设 `exit_signal=SIGCHLD`，这些标志全不传 → 页表/文件表/信号表各自复制。所以「进程」和「线程」是同一机制（`clone`）的**两个参数组合**，不是两套代码。

### 三、线程共享 vs 私有

| 共享（全线程可见） | 私有（每线程独立） |
|--------------------|--------------------|
| 地址空间（Text/Data/Heap） | 栈（stack） |
| fd 表 | 寄存器（含 PC/SP） |
| 信号处理表（sighand） | 线程 ID（tid） |
| 工作目录、根目录 | **errno** |
| 全局变量 | 信号掩码（`pthread_sigmask` 可设线程级） |

> **errno 是线程私有**的——每个线程有独立 errno，所以多线程里「检查 errno」不会互相串。但**共享全局变量**正是数据竞争的温床，必须加锁或用原子操作（见 [Ch30](../../chapter-30-thread-synchronization/README.md)、03.6 模块 Ch4）。

### 四、一个常被忽略的连带后果：fd 是进程级的

因为 `CLONE_FILES` 让所有线程共享**同一份 `files_struct`**，所以：

- 线程 A `close(3)` → 线程 B 的 `read(3)` **立刻失败**；
- 线程 A 改了文件偏移（`lseek`）→ 线程 B 看到的偏移也变了；
- 线程 A 把 `O_NONBLOCK` 设上 → **所有线程**都受影响。

这是「线程间共享 fd 表」的直接后果，也是多线程编程里比数据竞争更容易被忽视的一类 bug（因为它看起来「不是共享数据」）。

## 代码

### c2_12 pthread 创建 / 共享 vs 私有 / tid 与栈地址

[`../code/c2_12_thread.c`](../code/c2_12_thread.c) 分五段：

| 段 | 做什么 | 钉死什么 |
|----|--------|----------|
| ① | 主线程打印 `getpid()`/`gettid()` 和局部变量地址 | 主线程也有自己的 tid |
| ② | `pthread_create` + `pthread_join`，打印创建返回值、线程的 `pid`/`tid`/栈地址、`join` 拿到的返回值 | `pthread_t` 是**不透明句柄**，不是数字 |
| ③ | 线程改全局 `g_shared`，主线程 `join` 之后读 | **主线程看得见**（对照 [2.7](./2.7-processes.md) fork 看不见） |
| ④ | 一次创建 4 条线程并发跑 | 4 个 tid 互不相同，4 个栈地址也互不相同 |
| ⑤ | 线程 vs 进程的 ASCII 对照表 | 怎么选 |

```c
/* TLPI 第 2 章 §2.12 —— 线程：同一进程里共享地址空间的多条执行流
 *
 * 编译：gcc -O0 -Wall -Wextra -pthread c2_12_thread.c -o c2_12
 * 运行：./c2_12
 *
 * 本节要钉死的事实：
 *   ① 线程 = 同一进程内的多条执行流：共享地址空间、fd 表、信号处置；
 *      各自有独立的栈、寄存器、tid、errno。
 *   ② 对比 §2.7：fork 出的进程改全局变量互相看不见；线程改的立刻互相可见。
 *   ③ pthread_create 的第 4 个参数是 void*，返回值也走 pthread_join 的出口参数。
 *   ④ 编译要带 -pthread（既开宏，也把 libpthread 链进来；新版 glibc 已并入 libc）。
 */
#define _GNU_SOURCE
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <errno.h>
#include <unistd.h>
#include <pthread.h>
#include <sys/syscall.h>

static int g_shared = 0;                 /* 全局变量：所有线程共享 */
static int g_from_thread = -1;

/* 线程函数的入口签名是固定的：void *(*)(void *) */
static void *worker(void *arg)
{
    int local_in_thread = 42;            /* 局部变量：在**线程自己的栈**上 */
    printf("  [thread] pid=%d  tid=%ld  arg=\"%s\"\n",
           (int)getpid(), (long)gettid(), (const char *)arg);
    printf("  [thread] &local_in_thread = %p   （线程自己的栈）\n",
           (void *)&local_in_thread);

    g_shared = 999;                      /* 改全局变量 */
    g_from_thread = (int)(long)gettid();

    /* 通过 return 把结果交回 pthread_join 的第二个参数 */
    return (void *)(long)(local_in_thread + 1);
}

int main(void)
{
    int local_in_main = 7;

    printf("=== ① 线程与进程：pid 相同、tid 不同 ===\n");
    printf("  [main]   pid=%d  tid=%ld  &local_in_main = %p\n",
           (int)getpid(), (long)gettid(), (void *)&local_in_main);
    printf("  -> 同一个 getpid()，但 gettid() 不一样：内核视角里线程是独立调度实体\n");

    printf("\n=== ② pthread_create / pthread_join ===\n");
    printf("  创建前 g_shared = %d\n", g_shared);

    pthread_t tid;
    fflush(NULL);                        /* 多线程下更要养成清缓冲的习惯 */
    int rc = pthread_create(&tid, NULL, worker, (void *)"argument-from-main");
    if (rc != 0) {
        /* ⚠️ pthread 系列**不走 errno**，错误码直接 return */
        printf("  pthread_create 失败：%d (%s)\n", rc, strerror(rc));
        return 1;
    }
    printf("  pthread_create 返回 %d，tid（不透明句柄）= %lu\n", rc, (unsigned long)tid);

    void *ret = NULL;
    rc = pthread_join(tid, &ret);        /* 等线程结束，并取它的返回值 */
    printf("  pthread_join 返回 %d，线程返回值 = %ld\n", rc, (long)ret);

    printf("\n=== ③ 共享 vs 私有 ===\n");
    printf("  g_shared      现在 = %d   <- 线程改的，主线程直接看得见\n", g_shared);
    printf("  g_from_thread 现在 = %d   (线程的 tid)\n", g_from_thread);
    printf("  -> 对比 §2.7 的 c2_7_fork.c：fork 出的子进程改全局变量，\n");
    printf("     父进程完全看不到。这就是「线程共享地址空间」最直接的证据。\n");

    printf("\n=== ④ 四线程并发：看 tid 与栈地址 ===\n");
    pthread_t ts[4];
    for (long i = 0; i < 4; i++) {
        rc = pthread_create(&ts[i], NULL, worker, (void *)"concurrent");
        if (rc != 0) { printf("  创建第 %ld 个失败：%s\n", i, strerror(rc)); continue; }
    }
    for (int i = 0; i < 4; i++) pthread_join(ts[i], NULL);
    printf("  -> 4 条线程的 tid 互不相同，但 getpid() 全都一样。\n");

    printf("\n=== ⑤ 线程 vs 进程 对照 ===\n");
    printf("  %-22s %-28s %s\n", "resource", "thread (in one process)", "separate process");
    printf("  %-22s %-28s %s\n", "----------------------",
           "----------------------------", "----------------------------");
    printf("  %-22s %-28s %s\n", "address space", "SHARED", "separate (COW after fork)");
    printf("  %-22s %-28s %s\n", "stack", "one per thread", "one per process");
    printf("  %-22s %-28s %s\n", "file descriptor table", "SHARED", "inherited copy");
    printf("  %-22s %-28s %s\n", "signal disposition", "SHARED", "inherited copy");
    printf("  %-22s %-28s %s\n", "creation cost", "low (no new address space)", "higher (page tables etc.)");
    printf("  %-22s %-28s %s\n", "who is scheduled", "each thread is", "each process is");
    printf("  %-22s %-28s %s\n", "crash blast radius", "kills the whole process", "kills only that process");
    printf("\n  HFT 读法：线程省掉了地址空间切换，但共享状态就要同步；\n");
    printf("  「一个进程一个核 + 无锁环形队列」往往是比多线程更稳的路径。\n");
    return 0;
}
```

编译与运行（**注意 `-pthread`**）：

```bash
gcc -O0 -Wall -Wextra -pthread -o c2_12_thread c2_12_thread.c && ./c2_12_thread
```

实测输出（另在 Compiler Explorer 复核，gcc 13.3.0 / x86-64 / Ubuntu 24.04 容器）：

```text

  [main]   pid=2  tid=2  &local_in_main = 0x7fff92f240fc
  -> 同一个 getpid()，但 gettid() 不一样：内核视角里线程是独立调度实体

=== ② pthread_create / pthread_join ===
  创建前 g_shared = 0
  pthread_create 返回 0，tid（不透明句柄）= 130235288778432
  [thread] pid=2  tid=3  arg="argument-from-main"
  [thread] &local_in_thread = 0x7672c41feeac   （线程自己的栈）
  pthread_join 返回 0，线程返回值 = 43

=== ③ 共享 vs 私有 ===
  g_shared      现在 = 999   <- 线程改的，主线程直接看得见
  g_from_thread 现在 = 3   (线程的 tid)
  -> 对比 §2.7 的 c2_7_fork.c：fork 出的子进程改全局变量，
     父进程完全看不到。这就是「线程共享地址空间」最直接的证据。

=== ④ 四线程并发：看 tid 与栈地址 ===
  [thread] pid=2  tid=4  arg="concurrent"
  [thread] &local_in_thread = 0x7672c41feeac   （线程自己的栈）
  [thread] pid=2  tid=5  arg="concurrent"
  [thread] &local_in_thread = 0x7672c39fdeac   （线程自己的栈）
  [thread] pid=2  tid=6  arg="concurrent"
  [thread] &local_in_thread = 0x7672c31fceac   （线程自己的栈）
  [thread] pid=2  tid=7  arg="concurrent"
  [thread] &local_in_thread = 0x7672c29fbeac   （线程自己的栈）
  -> 4 条线程的 tid 互不相同，但 getpid() 全都一样。

=== ⑤ 线程 vs 进程 对照 ===
  resource               thread (in one process)      separate process
  ---------------------- ---------------------------- ----------------------------
  address space          SHARED                       separate (COW after fork)
  stack                  one per thread               one per process
  file descriptor table  SHARED                       inherited copy
  signal disposition     SHARED                       inherited copy
  creation cost          low (no new address space)   higher (page tables etc.)
  who is scheduled       each thread is               each process is
  crash blast radius     kills the whole process      kills only that process

  HFT 读法：线程省掉了地址空间切换，但共享状态就要同步；
  「一个进程一个核 + 无锁环形队列」往往是比多线程更稳的路径。
```

**解读**

1. **段 ③ 是「线程共享地址空间」最直接的证据，而且必须和 [2.7](./2.7-processes.md) 段 ② 对着看**：
   | | 改全局变量后，调用方看得到吗 |
   |---|---|
   | `fork`（[2.7](./2.7-processes.md)） | ❌ 看不到（`g_counter` 父进程仍是 100） |
   | `pthread_create`（本节） | ✅ **看得到**（`g_shared = 999`） |

   两条实测合起来才把「线程 vs 进程」从定义变成了可观测的事实——**差别不在 API，在 `clone` 有没有传 `CLONE_VM`**。
2. **段 ② 的 `tid（不透明句柄）= 130235288778432`** 值得停一下：`pthread_t` **不是数字**，在 glibc/x86-64 上它是一个指向线程控制块的指针。所以「打印 `pthread_t`」和「打印 `gettid()`」是两回事——前者给出的是 12 位的大数，后者是 `3` 这种小整数。**比较线程要用 `pthread_equal()`**，不能 `==`（可移植性）。
3. **段 ④ 的四个栈地址是「每个线程独立栈」的实证**，而且数值很规整：
   ```text
   0x7672c41feeac
   0x7672c39fdeac     差值 = 0x800000 = 8MB
   0x7672c31fceac     差值 = 0x800000
   0x7672c29fbeac     差值 = 0x800000
   ```
   相邻线程栈地址**正好相差 8MB**——这正是 glibc 默认的线程栈大小（`PTHREAD_STACK_MIN` 到 `ulimit -s` 之间，默认取 8MB）。这个 8MB 是**虚拟空间**（按需提交），所以起 100 条线程**不会真的占 800MB 物理内存**——但**地址空间会被切掉 800MB**，32 位系统上起不了几条。
4. **段 ⑤ 的 `crash blast radius` 那一行是架构决策的依据**：`thread → kills the whole process`，`separate process → kills only that process`。所以 HFT 里的常见折中是「**关键模块用多进程隔离**（行情/策略/下单分开，一个崩了能重启），**进程内部用多线程**共享数据」。这条在后面 [2.17](./2.17-client-server.md) 的服务器形态表里会再次出现。
5. **`pthread_join` 拿到 `43` 是「线程有返回值」的证据**——线程的入口函数返回 `void *`，`pthread_join` 的第二个参数就是接它的。对照 [2.7](./2.7-processes.md) 用 `waitpid` 拿退出码：**线程用 join 拿指针，进程用 wait 拿 8 位退出码**，两套机制。

## HFT / 嵌入式关联

| 现象 | 本节机制的兑现 |
|------|----------------|
| 线程比进程省创建开销 | `clone(CLONE_VM)` 不复制页表，创建仅「分配栈 + task_struct」，微秒级；进程要复制页表，毫秒级 |
| 共享内存通信零开销 | 线程共享地址空间，直接用共享变量通信，无需 IPC |
| 数据竞争风险 | 共享变量无锁写是竞态，需锁/原子/TSan 检测（见 03.6 Ch4） |
| 线程崩溃拖垮全进程 | 共享地址空间，一个线程段错误 → 整个进程崩溃 |
| **8MB 栈 × N 线程 = 地址空间快速耗尽** | 段 ④ 实测栈间距正好 `0x800000`。起几百条线程时 `ulimit -s` 要调小（或 `pthread_attr_setstacksize`），否则 32 位设备直接 `ENOMEM` |
| **fd 是进程级的，不是线程级的** | 段 ⑤ 的 `file descriptor table: SHARED`。**一个线程 `close` 会打掉其他线程正在用的 fd**——比数据竞争更隐蔽的一类 bug |
| **errno 是线程私有的（唯一例外）** | 段 ⑤ 的表里没列，但 `pthreads(7)` 明确：每个线程有自己的 errno。所以「多线程里检查 errno」是安全的；**但不要用 `perror` 之外的全局变量存错误** |
| **`pthread_t` 不可当整数用** | 段 ② 实测 `130235288778432`。把 `pthread_t` 直接 `printf("%d")` 或用 `==` 比较，在别的平台会出错——用 `pthread_equal` |
| **「一个进程一个核 + 无锁环形队列」往往比多线程更稳** | 段 ⑤ 末尾的结论。线程省了地址空间切换，但共享状态必须同步；**隔离性买不到**。嵌入式实时系统常按「一核一进程」划分 |
| **`-pthread` 不只是链接 libpthread** | 它还定义了 `_REENTRANT`，改变 glibc 若干头文件的声明（如 `errno` 的实现方式）。**忘了 `-pthread` 可能出现「编译通过但行为诡异」**，而不只是「链接报错」 |

<details>
<summary>1. 为什么说「Linux 没有真正的线程，只有 task_struct」？</summary>

因为内核只有一种调度实体 `task_struct`。线程和进程都用它表示，区别只是 `clone` 时传的共享标志——传 `CLONE_VM|CLONE_FILES|...` 就是线程（共享资源），不传就是进程（各自复制）。内核调度器一视同仁，按 `task_struct` 调度。

本节段 ⑤ 的表格里 `who is scheduled: each thread is` / `each process is`——**两者都被调度**，因为两者都是 `task_struct`。
</details>

<details>
<summary>2. <code>getpid()</code> 和 <code>gettid()</code> 分别返回 <code>task_struct</code> 的哪个字段？多线程里它们相等吗？</summary>

- `getpid()` 返回 **`tgid`**（线程组 ID），**同一进程所有线程相同**；
- `gettid()` 返回 **`pid`**（内核唯一 tid），**每个线程不同**。

本节段 ①④ 实测：

```text
  [main]   pid=2  tid=2
  [thread] pid=2  tid=3
  ...
  [thread] pid=2  tid=4      ← pid 全是 2
  [thread] pid=2  tid=5
  [thread] pid=2  tid=6
  [thread] pid=2  tid=7      ← tid 各不相同
```

所以 `ps -L` 看到的每个「线程」就是那些 `tid`（`task_struct->pid`）。
</details>

<details>
<summary>3. 一个线程 <code>close(fd)</code> 会影响同进程其他线程吗？</summary>

**会。** 因为 `CLONE_FILES` 让线程共享同一份 `files_struct`（fd 表），**fd 是进程级资源**。线程 A `close(3)` 后，线程 B 的 `read(3)` 立刻失败。

本节段 ⑤ 的表里 `file descriptor table: SHARED` 就是这一条。同样的连带后果还有：

- 一个线程 `lseek` 改了偏移 → 所有线程看到的偏移都变了；
- 一个线程设了 `O_NONBLOCK` → 所有线程都受影响。

**这是比数据竞争更隐蔽的一类 bug**——因为它看起来「不是共享数据」。fp [2.5](./2.5-file-io-model.md) 的 fd 三层结构解释了机制：`fdtable` 挂在 `files_struct` 上，而 `files_struct` 被 `CLONE_FILES` 共享了。
</details>

<details>
<summary>4. 线程有自己的栈吗？栈放哪里？</summary>

有，每个线程独立栈。`pthread_create` 时 glibc 用 `mmap` 分配一块区域（默认 8MB 虚拟空间，按需提交）作为线程栈，`clone` 时把新栈顶指针传进去。主线程用进程的初始栈。

本节段 ④ 的四个栈地址是**最直观的证明**：

```text
  0x7672c41feeac
  0x7672c39fdeac     ← 相差 0x800000 = 8MB
  0x7672c31fceac     ← 相差 0x800000 = 8MB
  0x7672c29fbeac     ← 相差 0x800000 = 8MB
```

相邻线程栈**正好差 8MB**——就是 glibc 的默认线程栈大小。

⚠️ 两个推论：**①** 8MB 是虚拟空间，起 100 条线程不会真占 800MB 物理内存，但会切掉 800MB 地址空间（32 位设备上很快就 `ENOMEM`）；**②** 栈溢出可能破坏相邻线程栈的 guard page，触发段错误。
</details>

<details>
<summary>5. 线程和进程的「崩溃隔离」差异，对 HFT 意味着什么？</summary>

- **进程隔离**：一个进程崩溃不影响其他进程，但通信要 IPC、创建开销大；
- **线程共享**：一个线程段错误整个进程都挂，但共享内存通信零开销。

HFT 常见折中：**关键模块用多进程隔离**（行情/策略/下单分开，一个崩了能重启），**进程内部用多线程**共享数据。这是「进程为界、线程为内」的架构原则。

本节段 ⑤ 的 `crash blast radius: kills the whole process` / `kills only that process` 就是这条原则的依据。段 ⑤ 末尾还有一句值得记住的：**「一个进程一个核 + 无锁环形队列」往往比多线程更稳**——因为隔离性买不到。
</details>

<details>
<summary>6. 为什么编译多线程程序要加 <code>-pthread</code>？不加会怎样？</summary>

**不只是「链接 libpthread」。** `-pthread` 还会定义 `_REENTRANT` 宏，改变 glibc 若干头文件的声明（典型是 `errno` 的实现方式、以及某些 `stdio` 的锁粒度）。

所以忘了 `-pthread` 的后果可能是：

| 情形 | 症状 |
|------|------|
| 没链接 libpthread | 链接期报 undefined reference（**最容易发现**） |
| 没定义 `_REENTRANT` | **编译通过、运行行为诡异**——比如 `errno` 不是线程私有的、`stdio` 锁不对 |

第二种才是坑。所以**不要**用 `-lpthread` 代替 `-pthread`（老写法只链接、不定义宏），统一用 `-pthread`。

本节 demo 的编译命令就是 `gcc -O0 -Wall -Wextra -pthread ...`。
</details>
