## 本节讲什么

线程是进程内的执行单元。本节回答三个问题：

1. 线程和进程在内核里到底有什么区别？

3. 为什么 `getpid()` 在线程里返回的都是同一个值？

## 1. 内核真相：线程 = 共享更多资源的 task

Linux 内核里**没有独立的「线程」结构体**——线程和进程都是 `task_struct`，区别只在**共享粒度**：

```c
struct task_struct {                 /* include/linux/sched.h */
    pid_t pid;                       /* :967 线程 ID（tid，内核唯一） */
    pid_t tgid;                      /* :968 线程组 ID（= 主线程的 pid） */
};
```

```
进程（单线程）:  task_struct A（pid=100, tgid=100）
线程组:          task_struct A（pid=100, tgid=100）   ← 主线程
                 task_struct B（pid=101, tgid=100）   ← 同组线程
                 task_struct C（pid=102, tgid=100）
                        ↑ tgid 相同 = 同一进程
```

- **用户态 `getpid()`** 返回的是 **tgid**（线程组 ID）→ 同一进程所有线程返回相同值
- **`gettid()`** 返回的是 **pid**（内核唯一 tid）→ 每个线程不同
- `ps -L` / `top -H` 看到的每个「线程」就是 `task_struct->pid`

## 2. `pthread_create` 底层：`clone` 传共享标志

```c
pthread_create(&tid, NULL, start, arg)
        │
        ▼
clone(CLONE_VM | CLONE_FS | CLONE_FILES | CLONE_SIGHAND | CLONE_THREAD, 新栈顶)
        │        │         │             │                └─ 加入同一线程组(共享 tgid)
        │        │         │             └─ 共享信号处理表(sighand_struct)
        │        │         └─ 共享 fd 表(files_struct)
        │        └─ 共享根目录/工作目录
        └─ 共享地址空间(页表，mm_struct)
```

源码里这些标志的判定（`kernel/fork.c`）：

| 标志 | 语义 | 行号 |
|------|------|------|
| `CLONE_VM` | 共享地址空间（不复制页表） | :1731 |
| `CLONE_FILES` | 共享 fd 表 | :1784 |
| `CLONE_SIGHAND` | 共享信号处理表 | :1803 |
| `CLONE_THREAD` | 加入同一线程组（共享 tgid） | :1852 |

**对照**：`fork` 只设 `exit_signal=SIGCHLD`，这些标志全不传 → 页表/文件表/信号表各自复制。所以「进程」和「线程」是同一机制（`clone`）的**两个参数组合**，不是两套代码。

## 3. 线程共享 vs 私有

| 共享（全线程可见） | 私有（每线程独立） |
|--------------------|--------------------|
| 地址空间（Text/Data/Heap） | 栈（stack） |
| fd 表 | 寄存器（含 PC/SP） |
| 信号处理表（sighand） | 线程 ID（tid） |
| 工作目录、根目录 | errno |
| 全局变量 | 信号掩码（`pthread_sigmask` 可设线程级） |

> **errno 是线程私有**的——每个线程有独立 errno，所以多线程里「检查 errno」不会互相串。但**共享全局变量**正是数据竞争的温床，必须加锁或用原子操作（见 Ch30、03.6 模块 Ch4）。

## 4. HFT / 嵌入式关联

| 现象 | 本节机制的兑现 |
|------|----------------|
| 线程比进程省创建开销 | `clone(CLONE_VM)` 不复制页表，创建仅「分配栈 + task_struct」，微秒级；进程要复制页表，毫秒级 |
| 共享内存通信零开销 | 线程共享地址空间，直接用共享变量通信，无需 IPC |
| 数据竞争风险 | 共享变量无锁写是竞态，需锁/原子/TSan 检测（见 03.6 Ch4） |
| 线程崩溃拖垮全进程 | 共享地址空间，一个线程段错误 → 整个进程崩溃（进程隔离则只挂一个） |

## 5. 代码示例

```c
#include <stdio.h>
#include <pthread.h>
#include <unistd.h>
/* 线程：共享全局变量，各有独立栈 */
static int shared = 0;

static void *worker(void *arg) {
    printf("thread: pid=%d tid=%ld\n", getpid(), (long)gettid());
    shared++;                          /* 共享变量（此处单线程无竞争） */
    return NULL;
}

int main(void) {
    pthread_t tid;
    pthread_create(&tid, NULL, worker, NULL);
    pthread_join(tid, NULL);
    printf("main:   pid=%d, shared=%d\n", getpid(), shared);
    return 0;
}
/* 编译：gcc -pthread demo.c */
```

<details>
<summary>代码自测（Q&A）</summary>

**Q1：为什么说「Linux 没有真正的线程，只有 task_struct」？**
A：因为内核只有一种调度实体 `task_struct`。线程和进程都用它表示，区别只是 `clone` 时传的共享标志——传 `CLONE_VM|CLONE_FILES|...` 就是线程（共享资源），不传就是进程（各自复制）。内核调度器一视同仁，按 `task_struct` 调度。

**Q2：`getpid()` 和 `gettid()` 分别返回 `task_struct` 的哪个字段？多线程里它们相等吗？**
A：`getpid()` 返回 `tgid`（线程组 ID，`task_tgid_nr()` 直接返回 `tsk->tgid`），同一进程所有线程相同；`gettid()` 返回 `pid`（内核唯一 tid），每个线程不同。多线程里 `getpid()` 恒等、`gettid()` 各不相同。

**Q3：一个线程 `close(fd)` 会影响同进程其他线程吗？**
A：会。因为 `CLONE_FILES` 让线程共享同一份 `files_struct`（fd 表），fd 是**进程级**资源。线程 A `close(3)` 后，线程 B 的 `read(3)` 立刻失败。这是「fd 表共享」的直接后果，也是线程编程的常见坑。

**Q4：线程有自己的栈吗？栈放哪里？**
A：有，每个线程独立栈。`pthread_create` 时 glibc 用 `mmap` 分配一块区域（默认 8MB 虚拟空间，按需提交）作为线程栈，`clone` 时把新栈顶指针传进去。主线程用进程的初始栈，其余线程各有一块独立栈。栈溢出时可能破坏相邻线程栈的「保护页」（guard page），触发段错误。

**Q5：线程和进程的「崩溃隔离」差异，对 HFT 意味着什么？**
A：进程隔离——一个进程崩溃不影响其他进程，但通信要 IPC、创建开销大；线程共享——一个线程段错误整个进程都挂，但共享内存通信零开销。HFT 常见折中：**关键模块用多进程隔离**（行情/策略/下单分开，一个崩了能重启），**进程内部用多线程**共享数据。这是「进程为界、线程为内」的架构原则。

</details>
