## 本节讲什么

进程是「程序运行的实例」。本节回答三个问题：

1. 进程的基本身份是什么？PID/PPID 从哪来？
2. 进程怎么被创建？`fork()` 在内核里走的是怎样一条链路？
3. 进程有哪些状态（内核视角的 `TASK_*`），内存布局长什么样？

原书以「概念」为主；本节补上内核侧的实现坐标，把「进程」这个抽象落到 `task_struct` 上，为后面 [Ch24](../../chapter-24-process-creation/README.md)（`fork` 深入）、[Ch6](../../chapter-06-processes/README.md)（进程详解）打底。

本节还要把两个**只在实跑里才会显形**的坑钉死：**僵尸进程真的长什么样**（`/proc/<pid>/stat` 的第 3 字段是 `'Z'`）、以及 **`fork` 前不 `fflush` 会让同一行打印两遍**。

## 要点

### 一、进程的基本属性

| 属性 | 含义 | 内核来源 |
|------|------|----------|
| **PID** | 进程唯一标识 | `kernel_clone()` 里 `pid_vnr(pid)` 取回（`kernel/fork.c:2922`） |
| **PPID** | 父进程 ID | 复制自父进程 `task_struct` 的 `real_parent` |
| **TGID** | 线程组 ID（主线程 PID） | 同一进程的所有线程共享 TGID |
| **状态** | `TASK_RUNNING` / `TASK_INTERRUPTIBLE` 等 | `task_struct->__state`（`include/linux/sched.h:86`） |

每个进程（`init`/`systemd` 的 PID=1 除外）都由父进程通过 `fork()` 创建。PID 1 是系统启动后第一个用户态进程；PID 0 是内核的 idle 进程（swapper），不参与用户态调度。

### 二、进程创建：`fork()` 的完整链路

`fork()` 不是「凭空造一个进程」，而是**复制当前进程**。内核侧的真实链路是：

```
用户态 fork()                    (glibc 封装)
      │
      ▼
SYSCALL_DEFINE0(fork)            kernel/fork.c:2991
      │  args.exit_signal = SIGCHLD
      ▼
kernel_clone(args)               kernel/fork.c:2868
      │  copy_process(...)
      ▼
copy_process()                   kernel/fork.c:2240
      │  复制 task_struct / 信号 / 文件表 / 内存描述符(mm)
      ├─→ dup_task_struct      复制 task_struct + 内核栈
      ├─→ copy_mm              COW 复制页表（不复制物理页）
      ├─→ copy_files           fd 表（fork 默认共享表项、各持引用计数）
      └─→ copy_sighand         信号处理表
      ▼
返回 pid：父进程拿「子进程 PID」，子进程拿 0
```

**关键源码**（`kernel/fork.c:2991`）：

```c
SYSCALL_DEFINE0(fork)
{
#ifdef CONFIG_MMU
	struct kernel_clone_args args = {
		.exit_signal = SIGCHLD,   /* 子进程退出时给父进程发 SIGCHLD */
	};
	return kernel_clone(&args);
#else
	/* can not support in nommu mode */
	return -EINVAL;
#endif
}
```

`fork` 本质是 `clone` 的特例——`fork` 只设了 `exit_signal=SIGCHLD`，共享粒度（内存/文件表）由内核默认；`clone(SIGCHLD, 0, ...)` 等价于 `fork`。`pthread_create` 则走 `clone` 传 `CLONE_VM|CLONE_FS|CLONE_FILES|CLONE_SIGHAND` 实现**线程**（见 [2.12](./2.12-threads.md)）。

### 三、进程状态机（内核视角）

内核用 `task_struct->__state` 的一个**位掩码**表示状态（`include/linux/sched.h:86`），`ps`/`top` 看到的单字母是它的投影：

| 内核宏 | 值 | `ps` 标志 | 含义 | HFT 场景 |
|--------|-----|-----------|------|----------|
| `TASK_RUNNING` | `0x00000000` | R | 正在运行或就绪排队 | 交易主循环占满 CPU |
| `TASK_INTERRUPTIBLE` | `0x00000001` | S | 可中断睡眠，等事件 | `recv` 等行情（可被信号打断） |
| `TASK_UNINTERRUPTIBLE` | `0x00000002` | D | 不可中断睡眠（通常等 I/O） | 等磁盘/网络驱动返回，**信号无法打断** |
| `__TASK_STOPPED` | `0x00000004` | T | 被 `SIGSTOP`/`SIGTSTP` 停止 | `Ctrl+Z` 挂起调试 |
| `__TASK_TRACED` | `0x00000008` | t | 被 ptrace 跟踪（gdb） | 调试器单步 |
| `EXIT_ZOMBIE` | `0x00000020` | **Z** | 已终止、父进程未 `wait` 收尸 | 僵尸堆积耗尽 PID |
| `EXIT_DEAD` | `0x00000010` | — | 已 `wait`、资源释放前最后态 | — |

**两个组合态**（源码里是位运算拼出来的）：

```c
#define TASK_KILLABLE  (TASK_WAKEKILL | TASK_UNINTERRUPTIBLE)   /* :116 可被致命信号杀死 */
#define TASK_STOPPED   (TASK_WAKEKILL | __TASK_STOPPED)          /* :117 */
```

> **D 状态是 HFT 排查重点**：进程卡在 D（`TASK_UNINTERRUPTIBLE`）时，连 `kill -9` 都打不断——它在等一个**内核侧**的 I/O 完成。交易机若发现 worker 卡 D 且 `ps` 的 `WCHAN` 指向磁盘/网络驱动，通常是存储或网卡驱动卡死，而非业务逻辑死锁。

### 四、进程内存布局

一个进程的虚拟地址空间，从低到高：

```
高地址 ┌──────────────────────┐
       │      Stack（栈）      │  局部变量、函数帧，向下增长
       │        ...           │  （运行时动态）
       ├──────────────────────┤
       │        ↕             │  ← 中间留空，可 mmap
       ├──────────────────────┤
       │      Heap（堆）       │  malloc 分配，向上增长（brk/mmap）
       ├──────────────────────┤
       │   BSS（未初始化全局）  │  零填充，不占磁盘
       ├──────────────────────┤
       │   Data（已初始化全局） │  占磁盘、加载时拷贝进内存
       ├──────────────────────┤
       │   Text（代码，只读）   │  可共享、只读
低地址 └──────────────────────┘
```

| 段 | 内容 | 来源 | 共享性 |
|----|------|------|--------|
| Text | 机器指令 | 可执行文件 `.text` | 同一程序多进程共享（只读） |
| Data | 已初始化全局/静态变量 | `.data` | 每进程私有 |
| BSS | 未初始化全局/静态变量 | `.bss`（零填充） | 每进程私有 |
| Heap | `malloc` 分配 | `brk`/`mmap` 动态 | 每进程私有 |
| Stack | 局部变量、函数帧 | 内核启动时分配 | 每进程私有（线程各自独立栈） |

`fork` 后父子进程的 Text/Data/BSS 页**暂时共享**（COW），直到某一方写入才真正复制——所以「`fork` 复制整个内存」是**误区**，实际只复制页表。

## 代码

### c2_7 fork 两次返回 / 独立地址空间 / 僵尸 / `_exit` 与缓冲

[`../code/c2_7_fork.c`](../code/c2_7_fork.c) 分六段，**每一段都对准一个只在实跑里才显形的现象**：

| 段 | 做什么 | 钉死什么 |
|----|--------|----------|
| ① | `fork` 后父子各自打印 `fork()` 的返回值与自己的 pid | 「一次调用、两次返回」 |
| ② | 父子都改全局 `g_counter`，父进程**等子进程退出后**再打印 | 地址相同、值独立 → 两份内存 |
| ③ | 子进程 `_exit(5)` 后父进程**故意不 wait**，去读 `/proc/<pid>/stat` 第 3 字段 | 拿到 `'Z'` = 僵尸；`waitpid` 后变成 `'?'` |
| ④ | 两个子进程分别用 `_exit(0)` 和 `exit(0)` 收尾 | `_exit` 不 flush → 它的 printf 全丢 |
| ⑤ | fork **之前不** `fflush(NULL)`，看 `[B]` 出现几次 | 缓冲被复制 → `[B]` 打印**两遍** |
| ⑥ | 打印 wait 宏清单 | 宏 vs 函数的区别 |

```c
/* TLPI 第 2 章 §2.7 —— 进程：fork 的返回值、独立地址空间、僵尸进程
 *
 * 编译：gcc -O0 -Wall -Wextra c2_7_fork.c -o c2_7
 * 运行：./c2_7
 *
 * 本节要钉死的事实：
 *   ① fork() 一次调用、两次返回：父进程拿到子 PID，子进程拿到 0，失败返回 -1。
 *   ② 父子各有独立虚拟地址空间 —— 全局变量的修改互不影响（写时复制）。
 *      「虚拟地址相同」不等于「同一块物理内存」。
 *   ③ 子进程退出但父进程没 wait，子进程就停在 Z（zombie）状态占着 PID。
 *   ④ _exit() 不 flush stdio；exit() 会。混用 printf + _exit 会丢输出。
 */
#define _GNU_SOURCE
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <errno.h>
#include <unistd.h>
#include <fcntl.h>
#include <time.h>
#include <sys/wait.h>
#include <sys/types.h>

static int g_counter = 100;             /* 全局变量：放进数据段 */

/* 读 /proc/<pid>/stat 的第 3 个字段（进程状态字符） */
static char proc_state(pid_t pid)
{
    char path[64], buf[512];
    snprintf(path, sizeof(path), "/proc/%d/stat", (int)pid);
    int fd = open(path, O_RDONLY);
    if (fd < 0) return '?';
    ssize_t n = read(fd, buf, sizeof(buf) - 1);
    close(fd);
    if (n <= 0) return '?';
    buf[n] = '\0';
    /* 格式：pid (comm) state ...  —— comm 里可能有空格和括号，从右括号后面找 */
    char *rp = strrchr(buf, ')');
    if (!rp || rp[1] == '\0') return '?';
    return rp[2];                        /* ')' 后面是空格，再后面是状态字符 */
}

static const char *state_name(char c)
{
    switch (c) {
    case 'R': return "Running";
    case 'S': return "Sleeping";
    case 'D': return "Uninterruptible sleep";
    case 'T': return "Stopped";
    case 'Z': return "Zombie";
    case 'X': return "Dead";
    default:  return "?";
    }
}

int main(void)
{
    printf("=== ① fork 一次调用、两次返回 ===\n");
    printf("  fork 之前：只有父进程，pid=%d\n", (int)getpid());
    fflush(NULL);

    pid_t pid = fork();
    if (pid < 0) { perror("fork"); return 1; }

    if (pid == 0) {
        printf("  子进程：fork() 返回 0        → 我用它判断「我是孩子」\n");
        printf("          我的 pid=%d  ppid=%d\n", (int)getpid(), (int)getppid());
        return 0;
    } else {
        printf("  父进程：fork() 返回 %d  → 这就是子进程的 PID\n", (int)pid);
        printf("          我的 pid=%d\n", (int)getpid());
        int st; waitpid(pid, &st, 0);
        printf("  父进程：子进程退出码 = %d\n", WEXITSTATUS(st));
    }

    printf("\n=== ② 独立地址空间（写时复制）===\n");
    printf("  fork 之前 g_counter = %d，&g_counter = %p\n", g_counter, (void *)&g_counter);
    fflush(NULL);

    pid_t p2 = fork();
    if (p2 == 0) {
        printf("  [child]  进来时  g_counter = %d  &g_counter = %p\n",
               g_counter, (void *)&g_counter);
        g_counter = 999;
        printf("  [child]  改成 999 后 g_counter = %d\n", g_counter);
        fflush(NULL);                    /* 必须先 flush：_exit() 不会替你清 stdio */
        _exit(0);
    }
    int st2; waitpid(p2, &st2, 0);
    printf("  [parent] 子进程改完退出后，g_counter = %d  &g_counter = %p\n",
           g_counter, (void *)&g_counter);
    printf("  → 父进程看到的还是 %d：两个进程的 g_counter 是两份独立的内存。\n",
           100);
    printf("  → 若两行的 &g_counter 地址相同，说明「虚拟地址一样」也**不代表**\n");
    printf("     同一块物理内存 —— 页表把它们映射到了不同的物理页（写时复制）。\n");

    printf("\n=== ③ 僵尸进程：退出但不被收尸 ===\n");
    fflush(NULL);
    pid_t p3 = fork();
    if (p3 == 0) _exit(5);               /* 子进程立刻退出 */

    /* 父进程故意先不 wait，让子进程停在 Z 状态 */
    struct timespec tv = { 0, 50000000L };   /* 50ms，给它时间变成僵尸 */
    nanosleep(&tv, NULL);
    char c = proc_state(p3);
    printf("  子进程 %d 已 _exit(5)，父进程还没 wait\n", (int)p3);
    printf("  /proc/%d/stat 的状态字段 = '%c' (%s)\n", (int)p3, c, state_name(c));
    if (c == 'Z')
        printf("  → 确认是僵尸：进程的「遗体」还占着一个 PID，等父进程收尸\n");

    int st3 = 0;
    pid_t got = waitpid(p3, &st3, 0);
    printf("  waitpid(%d) 返回 %d，WIFEXITED=%d WEXITSTATUS=%d  → 收尸完成\n",
           (int)p3, (int)got, WIFEXITED(st3), WEXITSTATUS(st3));
    errno = 0;
    printf("  收尸后再读 /proc/%d/stat：", (int)p3);
    char c2 = proc_state(p3);
    printf(" 状态='%c'\n", c2);
    printf("  → 变成 '?'（文件已消失，open 返回 ENOENT）说明进程表项真的释放了\n");

    printf("\n=== ④ _exit() 不 flush stdio ===\n");
    fflush(NULL);
    pid_t p4 = fork();
    if (p4 == 0) {
        printf("  [子A] 这行用 printf 写入缓冲，然后调 _exit(0) → 应该看不到\n");
        _exit(0);
    }
    waitpid(p4, NULL, 0);
    pid_t p5 = fork();
    if (p5 == 0) {
        printf("  [子B] 这行用 printf 写入缓冲，然后调 exit(0)  → 应该看得到\n");
        exit(0);
    }
    waitpid(p5, NULL, 0);
    fflush(NULL);
    printf("  → 上面只看到子B，证明 _exit() 绕过 stdio 清理直接进内核。\n");
    printf("  → 所以在 fork 前要 fflush(NULL)，在子进程里该用 _exit 就用 _exit，\n");
    printf("     否则同一条缓冲会被父、子各输出一遍（经典重复打印 bug）。\n");

    printf("\n=== ⑤ fork 前不 fflush：同一行会被打印两遍 ===\n");
    printf("  [A] 这行先 fflush 出去，作为对照组\n");
    fflush(NULL);
    printf("  [B] 这行留在缓冲里，然后**故意不 flush** 就 fork\n");
    pid_t p6 = fork();
    if (p6 == 0) {
        exit(0);                         /* exit() 会 flush：子进程把继承来的 [B] 印一遍 */
    }
    waitpid(p6, NULL, 0);
    fflush(NULL);                        /* 父进程再印一遍自己的 [B] */
    printf("  -> 若 [B] 出现了两次，就是「fork 复制了未 flush 的缓冲」在起作用。\n");
    printf("  -> 修法只有一个字：fork 之前 fflush(NULL)。\n");
    printf("  -> 反过来说，_exit() 不 flush，所以子进程自己的 printf 会**全丢**：\n");
    printf("     要输出就先 fflush(NULL) 再 _exit()，或者干脆用 exit()。\n");

    printf("\n=== ⑥ 退出码与 wait 宏 ===\n");
    printf("  WIFEXITED/WEXITSTATUS/WIFSIGNALED/WTERMSIG/WCOREDUMP 是宏，\n");
    printf("  不是函数 —— 它们直接对 wait status 整数做位运算，零开销。\n");
    return 0;
}
```

**解读**

1. **段 ② 是本节的硬证据，而且它的说服力来自「地址相同」这个反直觉细节**：
   ```text
   fork 之前 g_counter = 100，&g_counter = 0x404098
   [child]  改成 999 后 g_counter = 999
   [parent] 子进程改完退出后，g_counter = 100  &g_counter = 0x404098
   ```
   **同一个虚拟地址 `0x404098`，父子看到的值却不同**（子 = 999，父 = 100）。这说明「虚拟地址一样」**不等于**「同一块物理内存」——写时复制让两个进程的页表把同一个虚拟地址映射到了**不同的物理页**。如果只看地址就断言「共享了」，就会得出完全错误的结论。
2. **段 ③ 把「僵尸」从一个概念变成了一个可读的文件内容**：子进程 `_exit(5)` 之后、父进程 `wait` 之前，读 `/proc/5/stat` 的**第 3 个字段**（`state`）拿到 **`'Z'`**。`waitpid(5)` 之后**再读同一个文件**，状态变成 **`'?'`** —— demo 用 `'?'` 表示「文件已不存在」（`open` 返回 `ENOENT`）。**这一前一后两个字符，证明的是「进程表项真的被释放了」**，而不只是「状态变了」。
3. **段 ④ 和段 ⑤ 是同一个 stdio 缓冲问题的两面**，而且都是**真实踩出来的坑**（本 demo 的上一版就在这两处栽过）：
   - **段 ④：`_exit()` 不 flush** → 用 `_exit(0)` 收尾的子进程，它的 `printf` 内容**一个字都没出来**。因为 `_exit()` 直接进内核，不跑 stdio 的清理。反过来说 `exit(0)` 会 flush，所以 `[子B]` 那行看得见。
   - **段 ⑤：fork 前不 `fflush`** → `[B]` 出现**两次**。原因是 `[B]` 还躺在父进程的 stdio 缓冲里，`fork` 把**整个地址空间**（含 stdio 缓冲）复制了一份，父子各自在退出时把同一段缓冲刷出去。
   - **两条合起来只有一句口诀**：**`fork` 之前 `fflush(NULL)`；`exec`/`_exit` 之前也要 flush（或用 `exit`）**。这是 C 程序在 fork 环境里最经典的一类「输出重复/丢失」bug，本 demo 提供了可复现的证据。
4. **段 ① 的一个副产品**：父进程 `fork()` 返回 `3`（子进程 PID），子进程返回 `0`。这个「0」不是巧合——`copy_process()` 复制出的子进程，返回路径是 `ret_from_fork`，内核在那里把返回值清成 0。所以「靠返回值判断我是谁」是内核**有意提供**的接口，不是约定。
5. **段 ⑥ 提醒 wait 宏的代价**：`WIFEXITED`/`WEXITSTATUS`/`WIFSIGNALED`/`WTERMSIG`/`WCOREDUMP` 全是**宏**，直接对 `wait` status 整数做位运算，**零函数调用开销**。HFT 里父进程收子进程状态是热路径上可能发生的事，用这些宏比调 `strerror` 便宜得多。

## HFT / 嵌入式关联

| 现象 | 本节机制的兑现 |
|------|----------------|
| 进程创建是启动延迟预算 | `fork` 要 `dup_task_struct`+`copy_mm` 复制页表，毫秒级；热路径应线程池预创建、避免运行时 fork |
| COW 首写触发缺页毛刺 | `fork` 后第一次写共享页触发 page fault + 物理页复制，是「父子都活」场景的隐藏延迟 |
| 僵尸进程耗尽 PID | 长期运行进程不 `wait` 收尸 → 僵尸堆积 → `pid_max` 耗尽 → 无法新建进程 |
| 卡 D 状态 | worker 卡 `TASK_UNINTERRUPTIBLE` 等 I/O，`kill -9` 无效，须查 `WCHAN` 定位驱动 |
| 多线程 = 共享地址空间 | `clone(CLONE_VM)` 让线程共享页表，省内存但引入数据竞争（见 [2.12](./2.12-threads.md)） |
| **僵尸的零成本检测法** | 段 ③ 的手法可以直接搬到生产：**读 `/proc/<pid>/stat` 第 3 字段看是不是 `'Z'`**，不用 `ps aux | grep`。交易系统的守护进程应该定期扫自己孩子的这个字段 |
| **`fork` 前 `fflush` 是嵌入式日志的必修课** | 段 ④⑤ 实测：不 flush 会**丢日志**（`_exit`）或**重复日志**（fork 复制缓冲）。嵌入式常把日志重定向到串口（全缓冲），这个坑复现率极高 |
| **COW 的隐藏延迟落在首写** | 段 ② 的 `g_counter` 首写就是一次 COW 缺页。HFT 里「fork 出子进程后马上要更新大块数据结构」的场景，第一次写会成批触发缺页——**预热（先写一遍再开始计时）是标准做法** |
| **`ret_from_fork` 的 0 不能靠猜** | 段 ① 的「子进程拿到 0」是内核在返回路径上强制的。自己写 `clone` 包装（如某些嵌入式 RTOS 适配层）时要清楚这一点，否则会写出「子进程也以为自己拿到 PID」的错误判断 |

## 自测题

<details>
<summary>1. <code>fork()</code> 之后，父子进程谁先执行？为什么不能假设顺序？</summary>

两者先后由调度器决定，**不可预测**。内核在 `kernel_clone()` 里 `wake_up_new_task()` 唤醒子进程后，父子都可能先被调度。依赖「父先执行」是经典竞态 bug——需要同步时用 `wait`/管道/信号显式约定。

本节 demo 的输出顺序（父的「fork 之前」→ 子的两行 → 父的两行）**只是这一次运行的结果**，多跑几次就可能不同。所以任何「先打印 A 再打印 B 就能保证顺序」的推断都是错的。
</details>

<details>
<summary>2. <code>fork()</code> 返回两次，父进程拿到 PID、子进程拿到 0，这个「0」是怎么来的？</summary>

`copy_process()` 复制出的子进程，其返回路径（`ret_from_fork`）会强制让 `fork` 在子进程里返回 0。这是内核故意设计的「同一段代码、两个返回值」——父进程走 `kernel_clone` 的 `return nr`（子 PID），子进程首次被调度时从 `ret_from_fork` 起步、返回值清 0。

本节实测：

```text
  子进程：fork() 返回 0        → 我用它判断「我是孩子」
          我的 pid=3  ppid=2
  父进程：fork() 返回 3  → 这就是子进程的 PID
```

所以「靠返回值判断我是谁」是内核**有意提供**的接口。
</details>

<details>
<summary>3. 为什么说「<code>fork</code> 复制整个内存」是错的？</summary>

`copy_mm` 只复制页表（`dup_mm`→`dup_mmap`），父子共享物理页，页表项标只读。任一进程写入时触发写保护缺页（COW），内核才分配新物理页 + 复制内容。所以 `fork` 成本与「内存大小」无关，只与「页表项数量」相关。

本节段 ② 给了一个**反直觉但决定性**的证据：

```text
  fork 之前 g_counter = 100，&g_counter = 0x404098
  [child]  改成 999 后 g_counter = 999
  [parent] 子进程改完退出后，g_counter = 100  &g_counter = 0x404098
```

**虚拟地址相同（`0x404098`）、值却不同**——说明两个进程的同一个虚拟地址映射到了**不同的物理页**。只看地址就断定「共享了」，结论会完全错。
</details>

<details>
<summary>4. 进程和线程在内核里到底有什么区别？</summary>

几乎只有「共享粒度」的区别——`fork` 默认共享最少，`pthread_create` 用 `clone(CLONE_VM|CLONE_FS|CLONE_FILES|CLONE_SIGHAND|CLONE_THREAD)` 让新 task 与父共享地址空间/文件表/信号表，此时它没有独立 PID（共享 TGID），就是一个线程。

内核里两者都是 `task_struct`，**没有独立的「线程」结构体**。所以本节段 ② 的「独立地址空间」到了 [2.12](./2.12-threads.md) 就变成「`g_shared` 改了主线程直接看得见」——差别只在 `COPY_MM` 有没有发生。
</details>

<details>
<summary>5. 一个进程卡在 <code>ps</code> 的 D 状态，<code>kill -9</code> 也杀不掉，为什么？</summary>

D = `TASK_UNINTERRUPTIBLE`，进程在等内核态 I/O 完成（磁盘/网络驱动），信号投递被**延迟到 I/O 返回之后**。`kill -9` 只是置一个 pending 信号，进程从 D 转回 R 之前不会处理。

排查：`ps -o pid,stat,wchan` 看 `WCHAN` 指向哪个驱动，通常是存储或网卡问题，而非进程本身。

⚠️ 内核为此提供了 `TASK_KILLABLE`（`include/linux/sched.h:116`）= `TASK_WAKEKILL | TASK_UNINTERRUPTIBLE`——**「等 I/O 但可被致命信号杀死」**。NFS/网络文件系统就用它来避免「永久 D 状态」。
</details>

<details>
<summary>6. 我 <code>fork()</code> 之前 <code>printf</code> 了一行没换行的内容，为什么屏幕上出现了两遍？</summary>

因为 **`fork` 复制了整个地址空间，包括 stdio 缓冲**。

本节段 ⑤ 的实测（这是本 demo 里最常被踩的一处）：

```text
  [A] 这行先 fflush 出去，作为对照组
  [B] 这行留在缓冲里，然后**故意不 flush** 就 fork
  [B] 这行留在缓冲里，然后**故意不 flush** 就 fork
```

`[A]` 因为 `fflush` 过、已经进了内核，只出现一次；`[B]` 还躺在用户态缓冲里，`fork` 把缓冲复制了一份，父子各自退出时把同一段缓冲刷出去 → **两次**。

**修法**：`fork` 之前 `fflush(NULL)`。

对称的另一个坑在段 ④：**`_exit()` 不 flush**，所以用 `_exit()` 收尾的子进程，它的 `printf` 内容**一个字都不会出来**。两个坑合起来的口诀：

> **`fork` 之前 `fflush(NULL)`；想保留输出就用 `exit()`，用 `_exit()` 就必须先 flush。**
</details>

<details>
<summary>7. 怎么用一条命令判断某个 PID 是不是僵尸？</summary>

读 `/proc/<pid>/stat` 的**第 3 个字段**（`state`），看是不是 `Z`：

```bash
awk '{print $3}' /proc/<pid>/stat      # 输出 Z 就是僵尸
```

本节 demo 段 ③ 就是这么做的，而且做了前后对照：

```text
  子进程 5 已 _exit(5)，父进程还没 wait
  /proc/5/stat 的状态字段 = 'Z' (Zombie)
  ...
  waitpid(5) 返回 5，WIFEXITED=1 WEXITSTATUS=5  → 收尸完成
  收尸后再读 /proc/5/stat： 状态='?'
```

`'?'` 是 demo 对「文件已消失（`open` 返回 `ENOENT`）」的标记——**说明进程表项真的被释放了**，而不只是状态字段变了。

比 `ps aux | grep defunct` 更省资源：不用起新进程，直接读一个文件。
</details>
