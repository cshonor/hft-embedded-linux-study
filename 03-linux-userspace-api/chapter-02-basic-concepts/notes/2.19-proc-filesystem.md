## 本节讲什么

`/proc` 是内核暴露给用户态的一个**虚拟文件系统（procfs）**，是「读文件 = 查内核、写文件 = 改内核」的统一接口。本节回答三个问题：

1. `/proc` 为什么「不占磁盘」，读它的瞬间发生了什么？
2. 内核里 `/proc/[pid]/status` 这种文件是怎么「凭空」长出来的？
3. HFT 排查为什么离不开 `/proc/[pid]/maps`、`/proc/interrupts`、`/proc/softirqs`？

完整机制在 Ch12，这里建立「procfs = 内核信息的文件视图」的核心心智。

## 1. `/proc` 是什么

`/proc` 挂载的是 **procfs**，一个**伪文件系统**——它的 inode 和内容都在内存里，由内核在**读取时动态生成**，不落磁盘：

| 特性 | 说明 |
|------|------|
| 零磁盘占用 | 文件内容实时生成，`ls -l` 看到的大小多为 0 或虚值 |
| 读 = 查询 | `read()` 触发内核的 show 函数，现场拼字符串返回 |
| 写 = 配置 | 写 `/proc/sys/...` 即调内核参数（`sysctl`） |
| 目录 = 数据视图 | `/proc/[pid]` 每个目录对应一个进程 |

```bash
$ ls -l /proc/$$/status /proc/meminfo
-r--r--r-- 1 root root 0 ... /proc/$$/status    # 大小显示 0，但 cat 有内容
-r--r--r-- 1 root root 0 ... /proc/meminfo
```

## 2. 内核实现：`ONE` 宏 + `tgid_base_stuff[]` 表

`/proc/[pid]/` 下的每个文件，都是内核用宏**注册一个 show 函数**生成的：

```c
/* fs/proc/base.c:145 —— 注册「单个 show 函数」的文件 */
#define ONE(NAME, MODE, show)				\
	NOD(NAME, (S_IFREG|(MODE)),			\
		NULL, &proc_single_file_operations,	\
		{ .proc_show = show } )
```

进程目录的文件清单来自 `tgid_base_stuff[]` 表（`fs/proc/base.c:3241`）：

```c
static const struct pid_entry tgid_base_stuff[] = {
	ONE("status",     S_IRUGO, proc_pid_status),       /* :3252 */
	ONE("limits",	  S_IRUGO, proc_pid_limits),       /* :3254 */
	ONE("stat",       S_IRUGO, proc_tgid_stat),        /* :3269 */
	ONE("wchan",      S_IRUGO, proc_pid_wchan),        /* :3292 */
	ONE("schedstat",  S_IRUGO, proc_pid_schedstat),    /* :3298 */
	ONE("oom_score",  S_IRUGO, proc_oom_score),        /* :3312 */
	...
};
```

`ONE("status", S_IRUGO, proc_pid_status)` 的含义是：当用户 `cat /proc/123/status` 时，内核调 `proc_pid_status()` 现场生成该进程的状态文本。系统级文件同理，例如 `/proc/meminfo`：

```c
/* fs/proc/meminfo.c:34 */
static int meminfo_proc_show(struct seq_file *m, void *v)
{
	struct sysinfo i;
	si_meminfo(&i);                 /* :44 取内核内存统计 */
	show_val_kb(m, "MemTotal:      ", i.totalram);
	...
}

/* fs/proc/meminfo.c:178 */
proc_create_single("meminfo", 0, NULL, meminfo_proc_show);
```

## 3. 常用 `/proc` 文件全景

| 类别 | 路径 | 内容 | 用途 |
|------|------|------|------|
| **系统级** | `/proc/cpuinfo` | CPU 型号/核数/缓存/特性位 | 判断 CPU 拓扑、`siblings`/`cpu cores` |
| | `/proc/meminfo` | 内存统计（`MemTotal`/`MemAvailable`/`Cached`） | 内存压力排查 |
| | `/proc/loadavg` | 1/5/15 分钟负载 + 运行/总任务数 | 负载告警 |
| | `/proc/uptime` | 系统运行秒数 + 空闲秒数 | 计算 CPU 空闲率 |
| | `/proc/interrupts` | 每 CPU 的硬中断计数 | 网卡/磁盘中断分布 |
| | `/proc/softirqs` | 每 CPU 的软中断计数 | 网络软中断热点 |
| **进程级** | `/proc/[pid]/status` | 进程状态/内存/VmRSS/线程数 | 快速看进程健康 |
| | `/proc/[pid]/maps` | 虚拟内存映射（VMA 列表） | 看 mmap 布局、共享库 |
| | `/proc/[pid]/fd/` | 打开的文件描述符 | 查 fd 泄漏 |
| | `/proc/[pid]/stat` | 进程统计（状态/CPU 时间） | `ps` 的数据源 |
| | `/proc/[pid]/wchan` | 进程在内核态的阻塞点 | 查 D 状态卡在哪 |
| **参数** | `/proc/sys/` | 可调内核参数（`sysctl`） | 运行时改内核行为 |

## 4. `/proc/[pid]` 详解：一个进程的全息档案

```
/proc/[pid]/
 ├── status    # 人类可读：State、Threads、VmRSS、voluntary_ctxt_switches
 ├── maps      # VMA 列表：地址范围 + 权限 + 映射文件（2.8 的落地视图）
 ├── fd/       # 每个 fd 一个符号链接，指向打开的文件
 ├── stat      # 机器可读：状态码 + CPU 时间（ps 直接读它）
 ├── task/     # 线程子目录（task/[tid]/ 每个线程一份）
 └── wchan     # 阻塞时在内核里的函数名（D 状态排查关键）
```

**`/proc/[pid]/maps` 是 VMA 的直接投影**（对应 2.8 的 `vm_area_struct` 链表），一行一个 VMA：

```
7f3a00000000-7f3a00021000 r-xp 00000000 08:01 12345   /usr/lib/libc.so.6
地址范围            权限   偏移  设备  inode   映射文件
```

HFT 排查内存映射、确认共享库是否被 `LD_PRELOAD` 注入、检查 `mmap` 的大页（`hugepage`）都靠它。

## 5. HFT / 嵌入式关联

| 现象 | 本节机制的兑现 |
|------|----------------|
| 排查 D 状态卡死 | `cat /proc/[pid]/wchan` 看阻塞点 + `/proc/[pid]/status` 的 State 字段 |
| 查 fd 泄漏 | `ls /proc/[pid]/fd | wc -l` 数 fd，对比 `/proc/[pid]/limits` 的 `Max open files` |
| 确认 CPU 亲和 | `/proc/[pid]/status` 的 `Cpus_allowed_list` 看绑核结果 |
| 内存压力 | `/proc/meminfo` 的 `MemAvailable` + `/proc/[pid]/status` 的 `VmRSS` 定位大户 |
| 网络软中断热点 | `/proc/softirqs` 的 `NET_RX` 计数判断是否需 `RPS`/网卡多队列 |
| 运行时调参 | `echo 1 > /proc/sys/net/ipv4/tcp_low_latency` 类开关（sysctl） |

## 6. 代码示例

```c
#include <stdio.h>
#include <string.h>

/* 从 /proc/[pid]/status 解析 VmRSS（进程物理内存占用） */
int main(int argc, char **argv) {
    char path[64], line[256];
    snprintf(path, sizeof(path), "/proc/%s/status",
             argc > 1 ? argv[1] : "self");
    FILE *f = fopen(path, "r");
    if (!f) { perror("fopen"); return 1; }

    while (fgets(line, sizeof(line), f)) {
        if (strncmp(line, "VmRSS:", 6) == 0) {
            printf("%s", line);   /* VmRSS: 常驻物理内存 */
            break;
        }
    }
    fclose(f);
    return 0;
}
```

编译运行：`gcc -o rss rss.c && ./rss`（读自己）、`./rss 1234`（读 PID 1234）。这就是 `top`/`htop` 取内存数据的同一路径——它们本质都是解析 `/proc` 下的文本。

<summary>代码自测（Q&A）</summary>

**Q1：`/proc` 为什么 `ls -l` 显示文件大小是 0，`cat` 却有内容？**
A：因为 procfs 是**伪文件系统**，内容不落磁盘、由内核在 `read()` 时现场生成。常规文件的 `st_size` 是「已存储的字节数」，procfs 文件没有「已存储」，所以 size 报 0（或一个虚值）。真正的内容是 show 函数（如 `proc_pid_status`）临时拼出的字符串。

**Q2：内核是怎么「凭空」造出 `/proc/[pid]/status` 这种文件的？**
A：不是逐个真实创建，而是**注册表驱动**。`tgid_base_stuff[]` 表里每项是 `{名字, 权限, show 函数}`，进程目录初始化时遍历这张表，把每项挂成一个 procfs 目录项。`cat` 时 procfs 的 `read` 回调转发到对应的 `proc_pid_status()`，由它现场生成文本。`ONE` 宏（`fs/proc/base.c:145`）就是这种「一个 show 函数」文件的注册糖。

**Q3：如何通过 `/proc` 查看一个进程打开了哪些文件？**
A：`ls -l /proc/[pid]/fd/`——每个文件描述符是一个符号链接，指向它打开的实际文件（管道、socket、普通文件、设备等）。`fd` 号就是链接名，`readlink` 可得真实路径。查 fd 泄漏时用它 `ls /proc/[pid]/fd | wc -l` 数个数，再对比 `cat /proc/[pid]/limits` 里的 `Max open files`。

**Q4：`/proc/[pid]/maps` 和 `/proc/[pid]/status` 分别看什么？**
A：`maps` 是**虚拟内存映射列表**（VMA 的投影），每行一个地址区间 + 权限 + 映射文件，看进程的代码段/堆/栈/共享库/匿名映射布局；`status` 是**进程状态汇总**（人类可读），看 State、线程数、`VmRSS`（常驻物理内存）、`Cpus_allowed_list`（CPU 亲和）、上下文切换计数等。一个偏「地址空间」，一个偏「运行状态」。

**Q5：`/proc/sys/` 和普通 `/proc` 文件有什么区别？**
A：`/proc/sys/` 是 **sysctl 接口**，专用于**可写的内核参数**（读 = 查参数，写 = 改参数，如 `net/ipv4/ip_forward`）。普通 `/proc` 文件大多是只读信息（`cpuinfo`、`meminfo`、`[pid]/status`），部分 `/proc/[pid]/` 文件也可写（如 `oom_score_adj`）。`/proc/sys/` 的写操作会触发内核的参数校验和热更新，是「运行时调内核」的标准通道。

</details>
