## 本节讲什么

操作系统的核心——内核。Linux 采用宏内核架构，所有驱动、调度器、内存管理都运行在同一个特权地址空间里。理解内核的存在和边界，是后续所有系统调用学习的前提。

---

## 要点

### 内核是什么

内核是操作系统中**始终驻留内存**的核心部分，负责管理全部硬件资源：

| 职责 | 说明 |
|------|------|
| CPU 调度 | 决定哪个进程/线程占用 CPU，上下文切换 |
| 内存管理 | 虚拟地址空间、页表、换页、mmap |
| 文件系统 | VFS 抽象层，对接 ext4/btrfs/proc 等 |
| 设备驱动 | 磁盘、网卡、USB、串口…… |
| 网络 | 协议栈（TCP/IP），socket 层 |
| 安全 | 权限检查、capabilities、namespace |

### 宏内核 vs 微内核

| 架构 | 特点 | 代表 |
|------|------|------|
| **宏内核** | 驱动、调度、FS 都在内核态；性能高 | **Linux** |
| 微内核 | 内核只留 IPC/调度；驱动在用户态；更安全但慢 | QNX、MINIX |
| 混合内核 | 折中 | Windows NT、macOS XNU |

Linux 选择宏内核是为了**性能**——系统调用直接陷入内核处理，没有额外的进程间通信开销。驱动可以编译进内核（`vmlinux`），也可以动态加载（`.ko` 模块）。

### 内核态 vs 用户态

```
用户态 (User Space)     ← 应用程序、glibc
    |  系统调用 (syscall)
内核态 (Kernel Space)   ← 内核代码、驱动
```

- **用户态**：权限受限，不能直接访问硬件、不能随意读写内存
- **内核态**：CPU 处于特权模式，可以执行任何指令、访问任何内存
- **切换**：用户程序通过系统调用（`syscall` 指令）主动进入内核态；中断/异常也会切换

### 和 C 语言的关系

C 语言本身没有"内核"概念——K&R 的 C 只关心用户态的 `printf`/`fopen`。但在 Linux 上：

- 你写的 C 程序运行在**用户态**
- 调用 `open()`/`read()` 等函数时，glibc 封装会触发**系统调用**，CPU 切到内核态执行内核代码
- 内核处理完返回用户态，你的 C 程序继续执行

```c
/* 这行 C 代码背后：glibc → syscall 指令 → 内核态 sys_write → 返回 */
write(1, "hello\n", 6);
```

### HFT / 嵌入式关联

- **嵌入式**：内核可裁剪（`make menuconfig`），只保留需要的驱动和子系统；`/dev` 下的设备文件是用户态操作硬件的唯一入口
- **HFT**：每次系统调用都有陷入开销（~1μs），热路径要尽量减少 syscall 数量；理解内核态/用户态边界是性能优化的基础

## 代码示例

```c
#include <stdio.h>
#include <unistd.h>
/* 内核态 vs 用户态 */
int main(void) {
    /* printf 在用户态执行 */
    printf("User space: printf\n");
    /* write 触发系统调用, 切到内核态 */
    write(STDOUT_FILENO, "Kernel space: write syscall\n", 28);
    return 0;
}
```
