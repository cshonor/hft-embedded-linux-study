## 本节讲什么

内存映射（mmap）：把文件或设备「映射」进进程地址空间，之后用**内存访问**代替 `read`/`write`。本节回答三个问题：

1. mmap 在内核里留下什么数据结构？（`vm_area_struct`）
2. 文件映射 vs 匿名映射有什么区别？
3. mmap 什么时候比 `read`/`write` 快？代价是什么？

这是 HFT 里「零拷贝」「共享内存」两大性能手段的共同地基（[Ch49](../../chapter-49-memory-mappings/README.md) 完整展开）。

本节要补的是**三类映射行为差异的实测**：`MAP_PRIVATE` 改了半天文件居然没变、`MAP_SHARED` 改一个字节文件就变了、以及**同一文件的两个 `MAP_SHARED` 映射会互相看见**（这是「共享内存」三个字的真正含义）。

## 要点

### 一、内核表示：`vm_area_struct`（VMA）

`mmap()` 的实质，是在进程的地址空间里**登记一块区域**（VMA），记录「这段虚拟地址对应什么」：

```c
SYSCALL_DEFINE6(mmap_pgoff, unsigned long, addr, unsigned long, len, ...)  /* mm/mmap.c:1427 */
```

```c
struct vm_area_struct {              /* include/linux/mm_types.h:565 */
    unsigned long vm_start;          /* 区域起始地址（含） */
    unsigned long vm_end;            /* 区域结束地址（不含，[start,end)） */
    struct file  *vm_file;           /* 映射的文件，匿名映射为 NULL */
    unsigned long vm_pgoff;          /* 文件内偏移（页为单位） */
    pgprot_t      vm_page_prot;      /* 访问权限（读/写/执行） */
    vm_flags_t    vm_flags;          /* 标志：MAP_SHARED/PRIVATE/ANON... */
};
```

```
进程地址空间 = 一串 VMA 链表（task_struct->mm->mmap）
┌──────┬──────────────┬──────────┬────────┬──────┐
│ Text │ Data/Heap    │  mmap 区  │ libc.so │ Stack│   ← 每段一个 VMA
└──────┴──────────────┴──────────┴────────┴──────┘
```

`cat /proc/pid/maps` 就是**遍历这个 VMA 链表**打印出来的——每一行是一个 `vm_area_struct`。

### 二、三种映射类型

| 类型 | 关键标志 | 后端 | 用途 |
|------|---------|------|------|
| **共享文件映射** | `MAP_SHARED` + fd | 磁盘文件的页缓存（**改动会落回文件**） | 零拷贝读文件、多进程共享文件内容 |
| **私有文件映射** | `MAP_PRIVATE` + fd | 页缓存 + **COW**（改动不落回） | 只读加载（可执行文件、`.so`）、调试器 |
| **匿名映射** | `MAP_ANONYMOUS`，无 fd | 物理页（零填充） | `malloc` 大块内存、父子进程共享内存 |

```
共享文件映射： 虚拟地址 ──缺页──► 页缓存 ──► 磁盘文件        （写：直接改页缓存）
私有文件映射： 虚拟地址 ──缺页──► 页缓存 ──写──► COW 复制私有页（文件不动）
匿名映射：     虚拟地址 ──缺页──► 分配零填充物理页（无文件后端）
```

**访问机制**：mmap 后访问映射区，第一次触发**缺页中断**（page fault），内核才把文件页读进页缓存、建页表映射。之后就是纯内存访问，**不再有系统调用**——这就是它比 `read`/`write` 快的本质。

### 三、mmap vs read/write

| 维度 | `read`/`write` | `mmap` |
|------|----------------|--------|
| 数据路径 | 内核页缓存 → 用户缓冲区（**一次拷贝**） | 页缓存直接映射进用户地址（**零拷贝**） |
| 系统调用 | 每次读写都 syscall | 仅 `mmap`/`munmap` 两次 |
| 页错误 | 无 | 首次访问每页一次缺页 |
| 适用 | 顺序读一次、小文件 | 随机访问、大文件、共享 |

> **不是永远快**：小文件或顺序读一次，`mmap` 的缺页 + TLB 开销可能反超 `read`。mmap 的优势在「随机访问大文件」「反复访问」「跨进程共享」场景。`read` 还有一个 mmap 没有的性质：**`read` 会真的把数据搬到你指定的缓冲区**，而 mmap 的「读」只是一次缺页——所以 `read` 对「文件在读取过程中被截断」的处理更可预期。

## 代码

### c2_8 `MAP_PRIVATE` vs `MAP_SHARED` vs 匿名映射

[`../code/c2_8_mmap.c`](../code/c2_8_mmap.c) 分五段，每段都是「改内存 → 看文件」，把三种映射的差别用**文件内容的变化**区分开：

| 段 | 做什么 | 钉死什么 |
|----|--------|----------|
| ① | `MAP_PRIVATE` 映射一个内容为 `"AAAA"` 的文件，把第 1 字节改成 `'X'`，`munmap` 后读文件 | 文件仍是 `"AAAA"` → **改动被 COW 拦在内存里** |
| ② | `MAP_SHARED` 做同样的操作，改成 `'Y'` | 文件变成 `"YAAA"` → **改动直接进了页缓存** |
| ③ | **同一文件建两个 `MAP_SHARED` 映射 A 和 B**，只通过 A 改成 `'9'`，然后立刻读 B | A 和 B 都变成 `"9234"` → **两个虚拟地址映射同一组物理页** |
| ④ | `MAP_PRIVATE\|MAP_ANONYMOUS` 映射 4096 字节，写入再读回，`mprotect` 改成只读，`munmap` 后再查 maps | 无文件后端的可读写内存；`munmap` 后确实消失 |
| ⑤ | 三种标志的 ASCII 对照表 | 怎么选 |

```c
/* TLPI 第 2 章 §2.8 —— 内存映射：MAP_PRIVATE vs MAP_SHARED 的可见性差异
 *
 * 编译：gcc -O0 -Wall -Wextra c2_8_mmap.c -o c2_8
 * 运行：./c2_8
 *
 * 本节要钉死的事实：
 *   ① mmap 把文件/设备映射进用户地址空间，之后读写直接访存，不再有 read/write syscall。
 *   ② MAP_PRIVATE = 写时复制（COW）：改动只在本进程可见，不落回文件。
 *   ③ MAP_SHARED  = 改动直接写进页缓存，对**所有**映射同一文件的进程可见，
 *      也最终会落到文件（msync 只是强制刷盘，不是「让改动可见」的前提）。
 *   ④ MAP_ANONYMOUS 不要文件，就是一块匿名内存（malloc 大块时的底层手段）。
 */
#define _GNU_SOURCE
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <errno.h>
#include <unistd.h>
#include <fcntl.h>
#include <sys/mman.h>
#include <sys/stat.h>
#include <sys/types.h>

#define MMDIR "/tmp/c2_8"

static void write_file(const char *path, const char *content)
{
    int fd = open(path, O_WRONLY | O_CREAT | O_TRUNC, 0644);
    if (fd < 0) { perror("open"); return; }
    if (write(fd, content, strlen(content)) < 0) perror("write");
    close(fd);
}

static void read_file(const char *path, char *buf, size_t sz)
{
    int fd = open(path, O_RDONLY);
    if (fd < 0) { snprintf(buf, sz, "(打不开: %s)", strerror(errno)); return; }
    ssize_t n = read(fd, buf, sz - 1);
    close(fd);
    buf[n < 0 ? 0 : n] = '\0';
}

/* 在 /proc/self/maps 里找某个地址属于哪一段 */
static void find_mapping(const void *addr, char *out, size_t osz)
{
    FILE *f = fopen("/proc/self/maps", "r");
    if (!f) { snprintf(out, osz, "(读不到 maps)"); return; }
    char line[512];
    unsigned long lo, hi;
    unsigned long a = (unsigned long)addr;
    while (fgets(line, sizeof(line), f)) {
        if (sscanf(line, "%lx-%lx", &lo, &hi) == 2 && a >= lo && a < hi) {
            line[strcspn(line, "\n")] = '\0';
            snprintf(out, osz, "%s", line);
            fclose(f);
            return;
        }
    }
    fclose(f);
    snprintf(out, osz, "(没找到)");
}

int main(void)
{
    char path[128];
    snprintf(path, sizeof(path), "%s/data.txt", MMDIR);
    mkdir(MMDIR, 0755);
    char buf[256], mapinfo[512];

    /* ================= ① MAP_PRIVATE ================= */
    printf("=== ① MAP_PRIVATE：写时复制，改动不落回文件 ===\n");
    write_file(path, "AAAA");
    read_file(path, buf, sizeof(buf));
    printf("  映射前文件内容 = \"%s\"\n", buf);

    int fd = open(path, O_RDWR);
    if (fd < 0) { perror("open"); return 1; }
    struct stat st;
    if (fstat(fd, &st) < 0) { perror("fstat"); return 1; }
    printf("  fstat: st_size=%ld  st_ino=%ld   （st_size 就是要传给 mmap 的长度）\n",
           (long)st.st_size, (long)st.st_ino);

    char *p = mmap(NULL, (size_t)st.st_size, PROT_READ | PROT_WRITE,
                   MAP_PRIVATE, fd, 0);
    if (p == MAP_FAILED) { perror("mmap MAP_PRIVATE"); return 1; }
    printf("  mmap(MAP_PRIVATE) 返回地址 = %p\n", (void *)p);
    find_mapping(p, mapinfo, sizeof(mapinfo));
    printf("  /proc/self/maps 里这一段 = %s\n", mapinfo);

    printf("  映射里第 1 个字节 = '%c'\n", p[0]);
    p[0] = 'X';                          /* 只改内存，不调 write */
    printf("  把它改成 'X'（只碰内存，没调 write）\n");
    msync(p, (size_t)st.st_size, MS_SYNC);
    munmap(p, (size_t)st.st_size);

    read_file(path, buf, sizeof(buf));
    printf("  munmap 之后读文件 = \"%s\"\n", buf);
    printf("  -> 文件里还是 AAAA：MAP_PRIVATE 的改动被 COW 拦在了内存里。\n");

    /* ================= ② MAP_SHARED ================= */
    printf("\n=== ② MAP_SHARED：改动直接进页缓存，会落到文件 ===\n");
    write_file(path, "AAAA");
    char *q = mmap(NULL, 4, PROT_READ | PROT_WRITE, MAP_SHARED, fd, 0);
    if (q == MAP_FAILED) { perror("mmap MAP_SHARED"); return 1; }
    printf("  映射前文件 = \"AAAA\"\n");
    q[0] = 'Y';
    printf("  在映射里把第 1 字节改成 'Y'\n");
    msync(q, 4, MS_SYNC);
    munmap(q, 4);
    read_file(path, buf, sizeof(buf));
    printf("  munmap 之后读文件 = \"%s\"\n", buf);
    printf("  -> 变成 YAAA：MAP_SHARED 的写直接改了页缓存里的那份数据。\n");

    /* ================= ③ 两个 SHARED 映射互相可见 ================= */
    printf("\n=== ③ 同一文件的两个 MAP_SHARED 映射，互相能看见吗？ ===\n");
    write_file(path, "1234");
    char *a = mmap(NULL, 4, PROT_READ | PROT_WRITE, MAP_SHARED, fd, 0);
    char *b = mmap(NULL, 4, PROT_READ | PROT_WRITE, MAP_SHARED, fd, 0);
    if (a == MAP_FAILED || b == MAP_FAILED) { perror("mmap x2"); return 1; }
    printf("  映射 A 地址=%p  内容=\"%.4s\"\n", (void *)a, a);
    printf("  映射 B 地址=%p  内容=\"%.4s\"\n", (void *)b, b);
    printf("  两个虚拟地址不同，但底层是同一组物理页。\n");
    a[0] = '9';
    printf("  只通过 A 改成 '9'，然后立刻读 B（不调 msync）：\n");
    printf("    A = \"%.4s\"\n", a);
    printf("    B = \"%.4s\"   <- B 也变了，这就是「共享」\n", b);
    printf("  -> 对照 ①：MAP_PRIVATE 时两个映射互不可见。\n");
    munmap(a, 4); munmap(b, 4);
    close(fd);

    /* ================= ④ 匿名映射 ================= */
    printf("\n=== ④ MAP_ANONYMOUS：不要文件的匿名内存 ===\n");
    size_t len = 4096;
    char *anon = mmap(NULL, len, PROT_READ | PROT_WRITE,
                      MAP_PRIVATE | MAP_ANONYMOUS, -1, 0);
    if (anon == MAP_FAILED) { perror("mmap ANONYMOUS"); return 1; }
    printf("  mmap(NULL, %zu, ..., MAP_PRIVATE|MAP_ANONYMOUS, -1, 0) = %p\n",
           len, (void *)anon);
    find_mapping(anon, mapinfo, sizeof(mapinfo));
    printf("  maps 里这一段 = %s\n", mapinfo);

    strcpy(anon, "anonymous page");
    printf("  往里写字符串再读回：\"%s\"\n", anon);

    if (mprotect(anon, len, PROT_READ) == 0)
        printf("  mprotect(只读) 成功：再往这里写就会 SIGSEGV（本 demo 不真写）\n");
    munmap(anon, len);
    find_mapping(anon, mapinfo, sizeof(mapinfo));
    printf("  munmap 之后再查 maps = %s\n", mapinfo);

    printf("\n=== ⑤ 一张对照表 ===\n");
    printf("  %-26s %-28s %s\n", "flag", "visible to others?", "written back?");
    printf("  %-26s %-28s %s\n", "--------------------------",
           "----------------------------", "----------------------------");
    printf("  %-26s %-28s %s\n", "MAP_PRIVATE", "no  (copy-on-write)", "no");
    printf("  %-26s %-28s %s\n", "MAP_SHARED", "yes (same physical pages)",
           "yes (msync only flushes)");
    printf("  %-26s %-28s %s\n", "MAP_PRIVATE|MAP_ANONYMOUS",
           "no other process at all", "no file at all");
    printf("\n  怎么选：\n");
    printf("    · 改了别人要看得见、还要落盘   -> MAP_SHARED\n");
    printf("    · 随便改，千万别动文件         -> MAP_PRIVATE\n");
    printf("    · 只是要一块内存               -> MAP_PRIVATE|MAP_ANONYMOUS\n");
    return 0;
}
```


**解读**

1. **段 ① 和段 ② 是一组完美对照，只差一个字面量**（`X` vs `Y`，`PRIVATE` vs `SHARED`），后果却相反：`"AAAA"` 与 `"YAAA"`。**`MAP_PRIVATE` 的写不会回到文件**——内核在第一次写时触发 COW，把那一页复制一份私有的。这解释了为什么 `.so`/可执行文件可以用 `MAP_PRIVATE` 加载：**多个进程共享同一份代码页，但谁也不会污染磁盘上的文件**。
2. **段 ③ 是「共享内存」四个字的机械定义**。两个 `MAP_SHARED` 映射的**虚拟地址不同**（`0x7e643a0fc000` 和 `0x7e643a0fb000`，差了正好一页 4096），但只通过 A 改成 `'9'`，**B 立刻也变成 `"9234"`**，而且**没调 `msync`**。这说明两者底层指向**同一组物理页**——「跨进程共享内存」就是靠这个机制实现的（进程间共享时，两个进程各自 `mmap` 同一文件即可）。
3. **段 ③ 和段 ① 必须对比着读**：同样的「两个映射 + 只改一个」，`MAP_SHARED` 时互相可见，`MAP_PRIVATE` 时互不可见。**这条差异决定了你是能拿它做 IPC，还是只能拿它做只读加速。**
4. **段 ④ 的 `00:00 0` 和「没找到」值得注意**。匿名映射在 `/proc/self/maps` 里那一行的**设备号和 inode 都是 0**（`00:00 0`），而段 ① 的文件映射是 `00:47 3`（inode 3）——**这是「有没有文件后端」在 maps 里的可视化区别**。另外 `mprotect(只读)` 成功意味着后续写入会 `SIGSEGV`（demo 故意不真写），这是内存保护的基本手段。
5. **一个常被忽略的约束**：`mmap` 的长度参数**必须是页大小的整数倍**（内核会自动向上取整）。段 ④ 里传的 `4096` 正好是一页；段 ① 传的 `st_size=4`（4 字节）内核会按一页处理——**`/proc/self/maps` 里显示的范围是 `7e643a0fc000-7e643a0fd000`，正好 `0x1000` = 4096 字节**，比文件本身的 4 字节大得多。这就是「映射大文件很快，但触碰才慢」的另一面：**映射的空间是按页算的**。

| `mprotect(2)` | 改 VMA 保护位；违反时投递 `SIGSEGV` |
| `munmap(2)` | 解除映射；**匿名页的内容随之丢弃**，不落盘 |
| `proc(5)` | `/proc/pid/maps` —— 每行一个 VMA（含 `start-end perm offset dev inode pathname`） |

> `mm/mmap.c:1427`、`include/linux/mm_types.h:565` 均用 Linux **v6.6** 源码逐行核对（脚本 `verify_ksrc.py`）。

## HFT / 嵌入式关联

| 现象 | 本节机制的兑现 |
|------|----------------|
| 零拷贝行情分发 | 文件映射让数据从页缓存直达用户态，省一次内核拷贝 |
| 跨进程共享内存 | `MAP_SHARED` + 同一文件（或 `MAP_ANONYMOUS` + fork）实现进程间共享，无 IPC 序列化开销 |
| 缺页毛刺 | mmap 后首次 touch 每页都触发 page fault，热路径要 `madvise(MADV_WILLNEED)` 或 `MAP_POPULATE` 预取 |
| 观测映射布局 | `/proc/pid/maps` = VMA 链表 dump，排查「地址被映射到哪」的第一工具 |
| **段 ③ 就是 SHM 的实现机制** | 「两个映射看见彼此」是共享内存的**全部魔法**。HFT 里行情快照/订单簿用文件+`MAP_SHARED`，读者进程零拷贝直读（[Ch49](../../chapter-49-memory-mappings/README.md)/[Ch54](../../chapter-54-posix-shared-memory/README.md)） |
| **`MAP_SHARED` 的写没有 `msync` 也可能落盘，但时机不定** | 段 ③ 实测「不调 `msync`，B 就看见了」——因为都在**页缓存**里。但**页缓存 → 磁盘**这一步由内核回写策略决定。要「一定落盘」就必须 `msync(MS_SYNC)`；要「一定不落盘」就该用 `MAP_PRIVATE` |
| **`MAP_PRIVATE` 是「安全的只读加速」** | 段 ① 实测文件没被改。嵌入式里把只读资源（字库、模型文件、固件 blob）用 `MAP_PRIVATE` 映射，**内存里改了不会破坏存储** |
| **`mprotect` 是运行期加固手段** | 段 ④ 用它把内存改成只读。典型的嵌入式用法：初始化完的配置表调 `mprotect(PROT_READ)`，**之后任何误写立刻 `SIGSEGV` 而不是静默损坏**——比看半天日志有效 |
| **匿名映射是 `malloc` 的大块路径** | 段 ④ 的 `MAP_PRIVATE\|MAP_ANONYMOUS` 正是 `malloc` 超过 `MMAP_THRESHOLD`（默认 128KB）时走的路径。**频繁申请/释放大块会反复 `mmap`/`munmap` → 大量缺页**，所以 `glibc` 的 `mallopt(M_MMAP_THRESHOLD, ...)` 在延迟敏感场景常被调 |

## 自测题

<details>
<summary>1. <code>mmap</code> 之后马上能读到文件内容吗？为什么？</summary>

能读到，但**不是「立刻全量读入」**。首次访问某页时触发缺页，内核才把那一页从磁盘读进页缓存并映射。所以 `mmap` 是**惰性**的——只有 touch 到的页才真正 I/O。

本节段 ① 的一段输出顺便证明了「映射的空间按页算」：

```text
  fstat: st_size=4
  /proc/self/maps 里这一段 = 7e643a0fc000-7e643a0fd000 rw-p ...
```

文件只有 4 字节，但 VMA 范围是 `0x1000` = **一页（4096 字节）**。这就是「映射大文件很快，但遍历它才慢」的原因：登记 VMA 几乎不花时间，触发缺页才花。
</details>

<details>
<summary>2. <code>MAP_PRIVATE</code> 和 <code>MAP_SHARED</code> 的区别？</summary>

- `MAP_SHARED` 的修改**写回文件**、其他映射同一文件的进程**可见**；
- `MAP_PRIVATE` 的修改**不写回**文件，写时触发 **COW** 复制一份私有页（类似 fork 的 COW）。

本节用一组只差一个字面量的对照实验钉死了这一点：

```text
=== ① MAP_PRIVATE ===
  映射前文件内容 = "AAAA"
  把它改成 'X'（只碰内存，没调 write）
  munmap 之后读文件 = "AAAA"     ← 文件没变

=== ② MAP_SHARED ===
  映射前文件 = "AAAA"
  在映射里把第 1 字节改成 'Y'
  munmap 之后读文件 = "YAAA"     ← 文件变了
```

调试器常用 `MAP_PRIVATE` 读文件，避免意外改文件；`.so`/可执行文件加载也用 `MAP_PRIVATE`。
</details>

<details>
<summary>3. 同一个文件开两个 <code>MAP_SHARED</code> 映射，一个改了另一个能看见吗？</summary>

**能，而且这是「共享内存」的全部魔法。**

本节段 ③ 实测：

```text
  映射 A 地址=0x7e643a0fc000  内容="1234"
  映射 B 地址=0x7e643a0fb000  内容="1234"
  两个虚拟地址不同，但底层是同一组物理页。
  只通过 A 改成 '9'，然后立刻读 B（不调 msync）：
    A = "9234"
    B = "9234"   <- B 也变了，这就是「共享」
```

两个虚拟地址相差正好一页（`0x1000`），但**底层指向同一组物理页**——所以改一个，另一个立刻看到，连 `msync` 都不用调（因为两者都在页缓存里）。

**对照段 ①**：`MAP_PRIVATE` 时两个映射互不可见。**这条差异决定了你是能拿它做 IPC，还是只能拿它做只读加速。**
</details>

<details>
<summary>4. 匿名映射的「匿名」是什么意思？它映射到哪里？</summary>

「匿名」= **没有文件后端**（`vm_file == NULL`）。缺页时内核直接分配**零填充物理页**，不涉及磁盘。

本节段 ④ 实测里，匿名映射在 `/proc/self/maps` 里的样子和文件映射**明显不同**：

```text
  maps 里这一段 = 7e643a0fc000-7e643a102000 rw-p 00000000 00:00 0 
```

**设备号和 inode 都是 0**（`00:00 0`）；而段 ① 的文件映射是 `00:47 3`（inode 3）。**这就是「有没有文件后端」在 maps 里的可视化区别。**

`malloc` 分配大块（超过 `MMAP_THRESHOLD`，默认 128KB）走的就是匿名 mmap；`fork` 后的共享内存也常基于匿名映射（`MAP_SHARED|MAP_ANONYMOUS`）。
</details>

<details>
<summary>5. 为什么说 mmap 是「零拷贝」而 read 不是？</summary>

`read` 的数据路径是「磁盘 → 页缓存 → 用户缓冲区」，其中「页缓存 → 用户缓冲区」是**一次 CPU 拷贝**。mmap 让用户地址**直接映射到页缓存那一页**，读取时 CPU 直接访问页缓存，省掉那次拷贝。

注意「零拷贝」指的是**省掉 CPU 拷贝**，**磁盘 I/O 本身省不掉**（首次访问还是要缺页读盘）。所以：

- **顺序读一次小文件** → `read` 更划算（没有缺页 + TLB 开销）；
- **随机访问大文件 / 反复访问 / 跨进程共享** → mmap 更划算。
</details>

<details>
<summary>6. <code>vm_start</code> 和 <code>vm_end</code> 是左闭右开区间 <code>[start, end)</code>，这有什么好处？</summary>

相邻 VMA 能**无缝拼接**——一个的 `vm_end` 就是下一个的 `vm_start`，遍历时无重叠、无空洞歧义。

这也是 `mmap` 返回地址**按页对齐**的原因：`vm_end - vm_start` 恒为页大小整数倍。本节段 ①④ 的实测数值就能对上：`0x7e643a0fc000` 到 `0x7e643a0fd000` 正好 `0x1000`；段 ④ 从 `0x7e643a0fc000` 到 `0x7e643a102000` 正好 6 页（`0x6000`）。
</details>

<details>
<summary>7. 我改了 <code>MAP_SHARED</code> 映射的内容，什么时候真正落盘？</summary>

**不一定马上，且时机由内核的回写策略决定。**

本节段 ③ 实测「不调 `msync`，另一个映射就看见了」——这说明改动**已经在页缓存里**。但「页缓存 → 磁盘」这一步是内核按脏页回写策略（`dirty_ratio`/`dirty_expire_centisecs` 等）批量做的，你无法从代码里保证它何时发生。

所以：

| 需求 | 做法 |
|------|------|
| 一定要落盘（持久化） | `msync(addr, len, MS_SYNC)` |
| 可以让内核慢慢刷 | 什么都不做（默认） |
| 一定不要落盘 | 用 `MAP_PRIVATE`（段 ① 实测文件没变） |
| 只是跨进程共享、不需要持久 | 用 `MAP_SHARED\|MAP_ANONYMOUS` + `fork` |

HFT 里做「进程间共享的行情快照」时，**最后这一行往往才是对的**——不需要落盘，只想要共享的物理页。
</details>
