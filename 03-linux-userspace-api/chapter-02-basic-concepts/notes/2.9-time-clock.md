# 2.9 时间（两类时钟）

> 本章：[TLPI 第 02 章 — Fundamental Concepts](./README.md)

## 本节讲什么

Linux 有两类时钟：墙上时钟（real time，日历时间）和单调时钟（monotonic，单调递增）。选错时钟是性能测量中的经典错误。本节建立基本概念，后续章节展开具体 API。

---

## 要点

### 两类时钟

| 时钟 | C 类型 | 特点 | 适用场景 |
|------|--------|------|----------|
| **墙上时钟** (CLOCK_REALTIME) | `time_t`, `struct timeval` | 表示日历时间；可被 NTP/手动调整 | 日志时间戳、定时器 |
| **单调时钟** (CLOCK_MONOTONIC) | `struct timespec` | 从系统启动开始单调递增；**不被调整** | **测量时间间隔** |
| CPU 时间 | `clock_t` | 进程占用 CPU 的时间 | 性能分析 |

### 为什么测量耗时不能用墙上时钟

```c
/* 错误：用墙上时钟测间隔 */
struct timeval start, end;
gettimeofday(&start, NULL);
do_work();
gettimeofday(&end, NULL);
/* 如果 NTP 在期间把时钟回调了 2 秒 */
/* end - start 可能是负数！ */
```

墙上时钟可能被 NTP 回调或跳跃。如果在回调前后分别取时间戳，计算出的间隔可能是**负数**或**巨大跳变**。

### 正确做法：CLOCK_MONOTONIC

```c
/* 正确：用单调时钟测间隔 */
struct timespec start, end;
clock_gettime(CLOCK_MONOTONIC, &start);
do_work();
clock_gettime(CLOCK_MONOTONIC, &end);
long ns = (end.tv_sec - start.tv_sec) * 1000000000L
         + (end.tv_nsec - start.tv_nsec);
printf("elapsed: %ld ns\n", ns);
```

`CLOCK_MONOTONIC` 保证单调递增，不受 NTP 跳变影响（但会被 NTP 的 adjtime 微调频率）。

### 常用时间 API 速查

| API | 时钟类型 | 精度 | 说明 |
|-----|----------|------|------|
| `time()` | 墙上 | 秒 | 最简单，K&R 会讲 |
| `gettimeofday()` | 墙上 | 微秒 | 已过时，用 `clock_gettime` 替代 |
| `clock_gettime()` | 可选 | 纳秒 | **推荐**，可指定 CLOCK_MONOTONIC |
| `time(NULL)` | 墙上 | 秒 | 返回 time_t，用于日志时间戳 |

### time_t 和 2038 问题

```c
time_t t = time(NULL);
printf("%ld\n", (long)t);  /* Unix 时间戳：从 1970-01-01 到现在的秒数 */
```

- `time_t` 的底层类型是实现定义的——在 32 位系统上通常是 32 位有符号整数
- 32 位 `time_t` 在 **2038-01-19 03:14:07 UTC** 溢出（Y2038 问题）
- 64 位系统上 `time_t` 是 64 位，没有此问题
- 不要假设 `time_t` 是 `long`——用 `time_t` 类型本身，打印时用 `<inttypes.h>` 的宏

### 和 C 语言的关系

- K&R 第 8 章提到 `time()`/`clock()`，但没有深入时区、精度、单调时钟等概念
- `struct tm`（本地时间分解）和 `time_t`（时间戳）是 C 标准库的一部分（`<time.h>`）
- `clock()` 是 C 标准的 CPU 时间接口，但精度低（`CLOCKS_PER_SEC`）；POSIX 的 `clock_gettime` 更精确

### HFT / 嵌入式关联

- **嵌入式**：嵌入式系统可能没有 RTC（实时时钟），启动后从 1970 开始；需要 NTP 或 GPS 对时
- **HFT**：延迟测量必须用 `CLOCK_MONOTONIC`（纳秒精度）；`rdtsc`（x86）或 `cntvct_el0`（ARM）可在用户态直接读硬件计数器，比 `clock_gettime` 更快（~20ns vs ~1μs）；但需处理频率漂移和核心间同步
