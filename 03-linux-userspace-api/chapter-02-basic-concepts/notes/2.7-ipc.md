## 本节讲什么

进程之间内存隔离，不能直接读写对方的数据。IPC（Inter-Process Communication）是内核提供的一组机制，让进程之间能交换数据和同步。本节是后续 20+ 章节的概述。

---

## 要点

### 为什么需要 IPC

每个进程有独立的虚拟地址空间——进程 A 的指针 `0x400000` 和进程 B 的 `0x400000` 指向不同的物理内存。要交换数据，必须通过**内核中转**。

### IPC 机制全览

| 机制 | 特点 | 数据方向 | 典型场景 |
|------|------|----------|----------|
| **管道 (pipe)** | 父子进程间；半双工 | 单向 | `ls \| grep` |
| **FIFO (命名管道)** | 任意进程；文件系统中有路径 | 单向 | 两个独立程序通信 |
| **信号 (signal)** | 异步通知；只传信号编号 | 单向 | `kill -TERM` |
| **共享内存 (shm)** | 最快；零拷贝 | 双向 | 大数据量、高频通信 |
| **消息队列** | 带类型的消息 | 双向 | 解耦的生产-消费 |
| **信号量 (semaphore)** | 同步原语；不传数据 | N/A | 控制对共享资源的访问 |
| **Socket** | 最通用；可跨网络 | 双向 | 网络服务、本地 IPC |

### System V IPC vs POSIX IPC

Linux 有两套 IPC API：

| | System V IPC | POSIX IPC |
|--|---------------|-----------|
| 历史 | 更老，Unix 传统 | 较新，POSIX 标准 |
| 标识 | `key_t` → `int id` | 名称字符串 → `mqd_t`/`sem_t*` |
| API 复杂度 | 高（`semget`/`semop`/`semctl`） | 低（`sem_wait`/`sem_post`） |
| 持久性 | 内核持久（需手动删除） | 进程或内核持久 |
| 章节 | Ch45-48 | Ch51-54 |

### 共享内存：最快的 IPC

```c
/* 进程 A */
int shmid = shmget(key, 4096, IPC_CREAT|0666);
char *p = shmat(shmid, NULL, 0);
strcpy(p, "hello");

/* 进程 B */
char *p = shmat(shmid, NULL, 0);
printf("%s\n", p);  /* "hello" —— 直接读，没有内核拷贝 */
```

共享内存之所以最快：数据直接映射到两个进程的虚拟地址空间，读写不需要系统调用（除了初始的 `shmat`）。但需要信号量来同步访问。

### 和 C 语言的关系

- IPC API 全是 C 函数接口，需要理解 struct、指针、错误处理
- 共享内存用到 C 的指针和内存模型概念——两个进程的指针指向同一物理页
- 信号处理用到 C 函数指针（`signal(SIGINT, handler)` 中的 `handler`）

### HFT / 嵌入式关联

- **嵌入式**：管道用于 shell 命令组合；共享内存用于驱动和应用之间的大数据传输
- **HFT**：共享内存是策略进程↔交易进程的首选 IPC（最低延迟）；信号量保护订单簿的并发访问；Socket 用于行情分发
