## 本节讲什么

「程序」和「进程」是两个常被混用的概念。本节回答三个问题：

1. 程序（磁盘上的文件）和进程（运行中的实例）到底差在哪？
2. 可执行文件（ELF）里装了什么？
3. `execve` 怎么把「程序」变成「进程」？

这是理解「为什么一个程序能同时跑成多个进程」的前提，也为 Ch27（exec 家族）铺路。

---

## 1. 程序 vs 进程

| 维度 | 程序（Program） | 进程（Process） |
|------|----------------|----------------|
| 本质 | 磁盘上的可执行文件（ELF） | 程序在内存中的运行实例 |
| 生命周期 | 持久（直到删除文件） | 临时（从 exec 到 exit） |
| 资源 | 无（静态数据） | 有 PID、地址空间、fd、栈 |
| 数量 | 一个文件 | 同一文件可同时跑 N 个进程 |

> 一句话：**程序是「菜谱」，进程是「正在做的那道菜」**。同一份菜谱（程序文件）可以同时炒出多盘菜（多个进程），每盘菜各有自己的锅（内存）和进度（PC 寄存器）。

## 2. ELF：可执行文件的内部结构

Linux 可执行文件是 **ELF**（Executable and Linkable Format），分为「给链接器看」和「给加载器看」两套视图：

```
ELF Header（魔数 \x7fELF + 架构 + 入口地址）
├── Program Headers（段表，供「加载器」用，决定映射到内存哪些段）
│     └── PT_LOAD 段 → Text / Data 映射
└── Section Headers（节表，供「链接器/调试器」用）
      ├── .text  代码
      ├── .data  已初始化全局变量
      ├── .bss   未初始化（零填充，不占文件空间）
      ├── .rodata 只读数据（字符串字面量）
      ├── .symtab 符号表（函数/变量名）
      └── .debug  调试信息（-g 生成，见 03.6 Ch1）
```

工具：`readelf -l a.out` 看段（加载视角）、`readelf -S a.out` 看节（链接视角）、`file a.out` 识别 ELF。

## 3. `execve`：把程序变成进程

`execve` 是**唯一**能加载新程序的系统调用（`execl`/`execv` 等都是它的 glibc 封装）：

```
execve(path, argv, envp)
   │
   ▼
内核：读 ELF → 映射 Text/Data 段 → 建新栈 → 跳转到入口地址
   │
   ▼
进程「脱胎换骨」：代码/数据/栈全换，但 PID 不变
```

**关键特性**：`execve` **不创建新进程**——它替换当前进程的镜像。所以「`fork` + `exec`」才是标准的「创建进程跑新程序」套路：`fork` 造壳（新 PID），`exec` 换瓤（新代码）。fd 是否继承由 `O_CLOEXEC` 决定（见 2.5）。

## 4. HFT / 嵌入式关联

| 现象 | 本节机制的兑现 |
|------|----------------|
| 启动延迟 | `execve` 要读 ELF + 动态链接（若 .so）+ 缺页加载，毫秒级；热路径进程应预启动常驻，避免运行时 `fork`+`exec` |
| 程序升级 | `execve` 替换镜像 = 优雅热升级（先准备新进程，再 exec 切换，旧进程收尾退出） |
| 符号表影响 | `.symtab` 供调试/`nm` 溯源；发布时可用 `strip` 去掉符号减小体积（但 crash 时无符号难定位） |

## 5. 代码示例

```c
#include <stdio.h>
#include <unistd.h>
/* fork + exec：创建新进程并替换成新程序 */
int main(void) {
    pid_t pid = fork();
    if (pid == 0) {
        /* 子进程：用 execve 把自身替换成 /bin/ls */
        char *argv[] = { "ls", "-l", NULL };
        char *envp[] = { NULL };
        execve("/bin/ls", argv, envp);
        perror("execve");        /* execve 成功就不会走到这 */
        return 1;
    }
    /* 父进程：等待子进程 */
    wait(NULL);
    printf("parent done\n");
    return 0;
}
```

<details>
<summary>代码自测（Q&A）</summary>

**Q1：一个程序文件能同时运行成多个进程吗？它们共享内存吗？**
A：能。每个 `fork`+`exec` 都产生独立进程，各自有独立地址空间。Text 段（只读代码）在内存里**物理共享**（同一程序的多个进程映射同一份代码页），但 Data/BSS/栈/堆各进程私有（COW）。所以「代码共享、数据隔离」。

**Q2：`execve` 之后，原来的 PID 变了吗？**
A：不变。`execve` 只替换进程的代码/数据/栈镜像，`task_struct` 和 PID 原样保留。这就是为什么 `fork` 后子进程 PID 已经确定，`exec` 只是「换程序」，进程身份（PID、fd、信号掩码）延续。

**Q3：`.bss` 段为什么不占文件空间？**
A：`.bss` 存的是未初始化（或初始化为 0）的全局变量，它们的值全是 0，没必要在文件里存一长串 0。ELF 里 `.bss` 只记录「大小」，加载时内核分配对应大小的**零填充内存**即可。所以「全局变量没初始化」不增大可执行文件，但运行时占内存。

**Q4：`strip` 掉符号表（`.symtab`）有什么利弊？**
A：利：文件变小、加载稍快、也隐藏内部符号名（一定程度的反逆向）。弊：崩溃时 core 里只剩地址没有函数名，`gdb`/`addr2line` 无法还原调用栈。所以**发布版可 strip，但要保留一份带符号的 debug 版用于事后回溯**（成对归档，见 03.6 Ch3）。

**Q5：`fork` + `exec` 中间，fd 为什么会「泄漏」给新程序？**
A：`execve` 默认**保留**所有打开的 fd（除非 `O_CLOEXEC` 或 `FD_CLOEXEC` 标记）。如果 `fork` 后 `exec` 前没有关掉临时 fd，新程序就继承了这些它不知道的 fd，长期累积导致「Too many open files」。服务进程所有 fd 都应设 `O_CLOEXEC`。

</details>
