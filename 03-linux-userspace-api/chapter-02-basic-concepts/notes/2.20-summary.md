<summary>章节自测（Q&A）</summary>

**Q1：Ch2 讲了 19 个概念，它们可以归成哪几条主线？**
A：① 内核与边界（内核/系统调用/Shell）；② 权限与文件（用户组/目录树/文件 I/O/proc）；③ 程序与进程（程序/进程/进程组/会话）；④ 内存与库（内存映射/共享库）；⑤ 并发与通信（IPC/信号/线程/C-S）；⑥ 时间与实时（时间/实时）；⑦ 终端（伪终端）。七块构成后续全部章节的地基。

**Q2：Ch2 里哪些概念最贴近 HFT？为什么？**
A：文件 I/O（fd 模型）、内存映射（零拷贝）、信号（异步抢占）、线程（并发）、IPC（跨进程通信）、实时（`SCHED_FIFO`+`mlockall` 低延迟）、时间（`CLOCK_MONOTONIC` 测延迟）、/proc（排查）。它们直接对应 HFT 的「低延迟 + 高并发 + 可靠通信」三大诉求，所以是 OUTLINE「HFT 最短路径」的起点。

**Q3：为什么说「进程 = task_struct，线程 = clone 传共享标志」是 Ch2 最重要的心智之一？**
A：因为它统一了「进程/线程」这对看似不同的概念——内核里两者都是 `task_struct`，区别只是 `clone` 传的共享标志（`CLONE_VM`/`CLONE_FILES` 等）。`fork` 是 `clone` 只设 `exit_signal=SIGCHLD` 的特例，`pthread_create` 是传共享标志实现线程。这个认知贯穿 Ch24-26（进程）、Ch28-33（线程）全部内容。

**Q4：Ch2 的「权限」「内存」「信号」分别对应内核里的什么结构体？**
A：权限 → 进程凭证（`uid_t`/`gid_t` + effective UID，权限检查在 `generic_permission`）；内存 → `vm_area_struct`（VMA，mmap 的实质）；信号 → `signal_struct`/`sighand_struct`（信号表 + 处理函数）。这些结构体是 05-linux-kernel / 06-linux-mm 模块追源码的核心对象。

**Q5：学完 Ch2，下一步按什么顺序推进最高效？**
A：按 HFT 最短路径：Ch3（系统编程概念）→ Ch4-5（文件 I/O）→ Ch20-22（信号）→ Ch29-30（线程）→ Ch35（实时调度）→ Ch49-50（mmap/mlock）→ Ch56-61（socket）→ Ch63（epoll）。这条路径优先覆盖 HFT 最需要的系统调用能力，其余章节（文件系统、终端、安全）按需再补。
