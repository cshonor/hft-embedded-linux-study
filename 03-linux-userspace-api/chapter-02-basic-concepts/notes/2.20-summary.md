## 本章回顾

第 2 章是全书的基础概念地图，19 个小节覆盖了 Linux 系统编程的所有核心概念。它们可以归成几条主线：

```
Linux 系统编程核心概念（Ch2 全景）
├── 内核与边界     → 2.1 内核 / 2.1 系统调用 / 2.2 Shell
├── 权限与文件     → 2.3 用户与组 / 2.4 目录树 / 2.5 文件 I/O / 2.19 /proc
├── 程序与进程     → 2.6 程序 / 2.7 进程 / 2.13 进程组 / 2.14 会话
├── 内存与库       → 2.8 内存映射 / 2.9 共享库
├── 并发与通信     → 2.10 IPC / 2.11 信号 / 2.12 线程 / 2.17 客户端服务器
├── 时间与实时     → 2.16 时间 / 2.18 实时
└── 终端           → 2.15 伪终端
```

**本章的代码化改造**（2026-09-14 完成）：原笔记只有「概念 + 片段」，现在**每节都配一个可编译、已实跑的 demo**，共 **19 个 C 源码 / 约 130 KB**，全部进 `code/` 目录并给出「编译命令 → 实测输出 → 逐条解读 → 源码坐标 → HFT 关联」的完整链路。**笔记里的 `c` 代码块与 `code/*.c` 逐字一致**（由脚本校验），引用引号（`<source>:33` 这类）读者能直接对上。

## 本环境的实测边界（**跨节共用**，读各节实测输出时的前提）

本节记录的全部实测都跑在 **CE 的 Ubuntu 24.04 容器**里。它与普通 Linux 有几处关键差异——**很多「意外」结论其实是这些差异造成的**：

| 事实 | 实测值 | 影响哪几节 |
|------|--------|-----------|
| **`uid=euid=gid=egid=0`，但 `CapEff = 0x0`** | 没有任何 capability | [2.3](./2.3-users-and-groups.md)（`EACCES`）、[2.18](./2.18-realtime.md)（`EPERM`） |
| **没有 `/bin` 目录**（`/usr/bin` 只有 `stdbuf`） | `system()` 必返回 `32512` | [2.2](./2.2-shell.md) |
| **没有 `/dev/ptmx`、`/dev/pts`、`/dev/tty`、`/dev/shm`、`/dev/full`** | 相关调用全 `ENOENT` | [2.14](./2.14-sessions.md)、[2.15](./2.15-pseudoterminals.md) |
| **`/dev` 只有 `null`/`zero`/`random`/`urandom`/`nvidia*`** | 无其他设备节点 | [2.5](./2.5-file-io-model.md)、[2.15](./2.15-pseudoterminals.md) |
| **0/1/2 都是 socket**（`isatty = 0`） | stdio **全缓冲**（`BUFSIZ = 8192`） | [2.1](./2.1-kernel.md)、[2.14](./2.14-sessions.md)、[2.19](./2.19-proc-filesystem.md) |
| **`/` 只读**（`EROFS(30)`）；`/tmp`（1777）与 `/app` 可写 | `O_CREAT` 到 `/` 报 `EROFS` | [2.3](./2.3-users-and-groups.md)、[2.4](./2.4-directory-hierarchy.md) |
| **`ncpu = 2`** | 亲和集 `0 1` | [2.18](./2.18-realtime.md) |
| **`RLIMIT_NOFILE = 100`** | 可撞 `EMFILE(24)` | [2.5](./2.5-file-io-model.md) |
| **`RLIMIT_MEMLOCK ≈ 2 GB`**（`1996169216`） | **无 capability 也能 `mlockall`** | [2.18](./2.18-realtime.md) |
| **`pid_max = 4194304`，但只见 2 个进程** | PID namespace 隔离 | [2.19](./2.19-proc-filesystem.md) |
| 核 `7.0.0-1012-aws`，**`PREEMPT`** | 非 `PREEMPT_RT` | [2.19](./2.19-proc-filesystem.md) |
| `argv[0] = "./output.s"`、`comm = "output.s"` | CE 产物名 | [2.19](./2.19-proc-filesystem.md) |

**怎么用这张表**：读到任何一条实测输出时，先查这里——**如果结论依赖某个容器特性，本节都标注了前提**（例如 [2.14](./2.14-sessions.md) 段 ③ 的 `EPERM` 依赖「本进程是组长」）。**「实测」只对行为有效，不对版本号有效**——CE 的 `7.0.0` 内核比你本地的可能新，所以笔记里的源码坐标**统一以 v6.6 为准**。

| 内存映射（[2.8](./2.8-memory-mappings.md)） | 零拷贝 | `MAP_SHARED` 映射互相可见 → 订单簿共享 |
| 信号（[2.11](./2.11-signals.md)） | 异步事件 | `EINTR` 必须 `do/while` 或 `SA_RESTART` |
| 线程（[2.12](./2.12-threads.md)） | 并发 | 共享地址空间但**隔离性买不到** |
| 进程组/会话（[2.13](./2.13-process-groups.md)/[2.14](./2.14-sessions.md)） | 优雅停机 | `kill(-pgid)` 一次停整条管线；`setsid` 防误按 `Ctrl+C` |
| C/S（[2.17](./2.17-client-server.md)） | 可靠通信 | 同机改 `AF_UNIX`，业务代码一行不改 |
| 实时（[2.18](./2.18-realtime.md)） | 确定性 | **只看 p99/max，不看平均**——「把长尾砍掉」 |
| 时间（[2.16](./2.16-date-time.md)） | 延迟测量 | 测间隔必须 `CLOCK_MONOTONIC` |
| /proc（[2.19](./2.19-proc-filesystem.md)） | 排查 | 自监控零依赖，读文本就够 |
| **Shell（[2.2](./2.2-shell.md)）** | 启动脚本 | `exec "$@"` 保证信号直达 |

它们直接对应 HFT 的「**低延迟 + 高并发 + 可靠通信 + 可排查**」四大诉求。
</details>

<details>
<summary>3. 为什么说「进程 = task_struct，线程 = clone 传共享标志」是 Ch2 最重要的心智之一？</summary>

因为它把「进程 / 线程」这对看似无关的概念**统一成了一个机制的两个参数组合**：

```
task_struct  ← 唯一的调度实体（内核里没有独立的「线程结构体」）
    │
    ├─ fork()            只设 exit_signal=SIGCHLD → 各自复制（进程）
    └─ pthread_create()  clone(CLONE_VM|CLONE_FILES|CLONE_SIGHAND|CLONE_THREAD) → 共享（线程）
```

**本节有实测对照**（这是「被证实」而非「被告知」）：

| | 改全局变量后，调用方看得到吗 |
|---|---|
| `fork`（[2.7](./2.7-processes.md)） | ❌ 看不到 |
| `pthread_create`（[2.12](./2.12-threads.md)） | ✅ **看得到**（`g_shared = 999`） |

**这个认知贯穿**：[Ch24](../../chapter-24-process-creation/README.md)-26（进程）、[Ch28](../../chapter-28-process-creation-exec-detail/README.md)-[33](../../chapter-32-thread-cancellation/README.md)（线程）全部内容都建立在此之上。它还直接推出三条实战结论：

1. **`gettid()` ≠ `getpid()`**（前者是 `pid`，后者是 `tgid`）；
2. **fd 是进程级的**——`CLONE_FILES` 让一个线程 `close` 打掉别的线程的 fd（[2.12](./2.12-threads.md) 要点四）；
3. **`errno` 是线程私有的**（唯一的例外，`pthreads(7)`）。
</details>

<summary>4. Ch2 的「权限」「内存」「信号」分别对应内核里的什么结构体？</summary>

| 概念 | 内核结构 / 函数 | 权威坐标 | 本节 demo |
|------|----------------|----------|----------|
| **权限** | `kuid_t` / `kgid_t`（凭证）+ `generic_permission()` | `include/linux/uidgid.h:21-28`、`fs/namei.c:400` | [2.3](./2.3-users-and-groups.md) `c2_3_cred.c` |
| **内存** | `vm_area_struct`（VMA） | `include/linux/mm_types.h:565`、`mm/mmap.c:1427` | [2.8](./2.8-memory-mappings.md) `c2_8_mmap.c` |
| **信号** | `signal_struct` / `sighand_struct` + `task->signal->pids[]` | `include/linux/sched/signal.h:692/697`、`kernel/signal.c:3807` | [2.11](./2.11-signals.md) `c2_11_signal.c` |

**几处已修正 / 已核实的坐标**（脚本逐行核对 v6.6）：

- ✅ **`kuid_t`/`kgid_t` 在 `include/linux/uidgid.h:21-28`**——**不在** `include/linux/types.h:37-38`（那两行是 `uid_t`/`gid_t`）。这是本轮核对发现的**唯一真错**；
- ✅ `fs/namei.c:400` = `generic_permission()`；
- ✅ `include/linux/mm_types.h:565` = `vm_area_struct` 相关定义；`mm/mmap.c:1427` = `SYSCALL_DEFINE6(mmap_pgoff, ...)`；
- ✅ `include/linux/sched/signal.h:692` = `task_pgrp()`、`:697` = `task_session()`。

这些结构体是 `05-linux-kernel` 与内存管理模块追源码的核心对象。
</details>

<summary>5. 学完 Ch2，下一步按什么顺序推进最高效？</summary>

按 **HFT 最短路径**：

```
Ch3（系统编程概念：errno 与可移植性）
 → Ch4-5（文件 I/O：fd 模型、缓冲、原子性）
 → Ch20-22（信号：异步事件、实时信号）
 → Ch24-26（进程：创建、终止、监控子进程）
 → Ch29-30（线程：创建、同步）
 → Ch35（实时调度：SCHED_FIFO 与优先级）
 → Ch49-50（mmap / mlock：零拷贝与大页）
 → Ch56-61（socket：TCP_NODELAY、SO_REUSEPORT）
 → Ch63（epoll：事件驱动服务器）
```

这条路径优先覆盖 HFT 最需要的系统调用能力。其余章节（文件系统、终端、安全）**按需再补**——例如需要处理 `pty` 时再看 [Ch64](../../chapter-64-pseudoterminals/README.md)。

**本章已完成的工作可以当模板复用**：每个 demo 都遵循「编译命令 → CE 实测输出 → 逐条解读 → 源码坐标 → HFT 关联 → 自测题」的结构，且**笔记内联代码与 `code/*.c` 逐字一致**（脚本 `cmp_note_code.py` 校验）、**引用的实测输出能在 CE 日志里找到**（脚本 `verify_note_outputs.py` 校验）。后续章节照这个结构补，质量可预期。
</details>
