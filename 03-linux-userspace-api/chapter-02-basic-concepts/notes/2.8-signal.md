## 本节讲什么

信号是 Linux 中最原始的进程间通信机制——内核或其他进程发给目标进程的异步通知。信号本身只携带一个编号，不传数据。理解信号是编写健壮 Linux 程序的基本要求。

---

## 要点

### 信号是什么

信号是一种**软件中断**：内核在任意时刻打断目标进程的正常执行流，转而运行信号处理函数。

```
进程正在执行代码
    ↓
内核：收到 SIGINT（用户按了 Ctrl+C）
    ↓
暂停当前执行 → 调用信号处理函数 → 返回继续执行
```

### 常见信号

| 信号 | 编号 | 触发方式 | 默认行为 |
|------|------|----------|----------|
| `SIGINT` | 2 | Ctrl+C | 终止进程 |
| `SIGKILL` | 9 | `kill -9` | 终止进程（**不可捕获**） |
| `SIGTERM` | 15 | `kill`（默认） | 终止进程 |
| `SIGSEGV` | 11 | 非法内存访问 | 终止 + core dump |
| `SIGPIPE` | 13 | 向已关闭的 socket 写 | 终止进程 |
| `SIGCHLD` | 17 | 子进程退出 | 忽略 |
| `SIGSTOP` | 19 | Ctrl+Z | 暂停进程（**不可捕获**） |

`SIGKILL` 和 `SIGSTOP` 是仅有的两个**不可被捕获或忽略**的信号——这是内核保留的"最终手段"。

### 发送和处理信号

```c
/* 发送信号 */
kill(pid, SIGTERM);         /* 给指定进程发信号 */
raise(SIGTERM);             /* 给自己发信号 */

/* 注册信号处理函数 */
void handler(int sig) {
    printf("caught signal %d\n", sig);
}
signal(SIGINT, handler);    /* 简单但不推荐（行为不统一） */
sigaction(SIGINT, &sa, NULL); /* 推荐：行为确定 */
```

### 信号的核心问题：异步性

信号处理函数可能在**任意时刻**被调用——你的程序正在执行 `printf` 的中途、正在 `malloc` 分配内存时、甚至正在修改一个全局变量时。

```c
/* 危险：信号处理函数中调用非可重入函数 */
void handler(int sig) {
    printf("interrupted!\n");  /* printf 有缓冲区，可能死锁 */
    malloc(100);               /* malloc 有锁，可能死锁 */
}
```

**信号处理函数的规则**：只调用**异步信号安全**（async-signal-safe）函数。安全的做法是只设置一个 `volatile sig_atomic_t` 标志，在主循环中检查。

### 和 C 语言的关系

- 信号处理函数的注册需要 C 函数指针——`signal(SIGINT, handler)` 中的 `handler` 就是指向函数的指针
- `volatile sig_atomic_t` 是 C 标准定义的关键字组合：`volatile` 防止编译器优化，`sig_atomic_t` 保证读写的原子性
- 信号是 C 程序中少见的"并发"机制——即使单线程程序也要处理信号带来的重入问题

### HFT / 嵌入式关联

- **嵌入式**：信号用于处理硬件异常（SIGSEGV/SIGBUS）；后台服务用 SIGHUP 重新加载配置
- **HFT**：热路径必须屏蔽信号（`sigprocmask`），防止交易逻辑被异步打断；SIGPIPE 是网络编程的经典陷阱——向已关闭连接的 socket 写数据会触发 SIGPIPE 杀死进程，需用 `MSG_NOSIGNAL` 或忽略 SIGPIPE
