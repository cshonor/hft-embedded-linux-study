## 本节讲什么

Linux 的核心设计哲学："一切皆文件"。磁盘文件、管道、socket、设备节点都通过统一的文件描述符（fd）接口操作。fd 是用户程序与内核 I/O 子系统之间的桥梁。

---

## 要点

### 一切皆文件

Unix 设计的核心抽象：用同一套 `open`/`read`/`write`/`close` 接口操作所有 I/O 资源。

| 资源 | 路径示例 | 操作 |
|------|----------|------|
| 普通文件 | `/home/user/a.txt` | open → read/write → close |
| 管道 | `pipe()` 创建 | read/write |
| socket | `socket()` 创建 | send/recv（或 read/write） |
| 设备节点 | `/dev/tty`, `/dev/null` | open → read/write → close |
| procfs | `/proc/cpuinfo` | open → read → close |

统一的接口意味着：你学会操作文件，就学会了操作几乎所有 I/O。

### 文件描述符 (fd) 是什么

fd 是一个**非负整数**，是进程内打开文件表的索引：

```c
int fd = open("/tmp/data.txt", O_RDONLY);
//  fd = 3  ← 这就是文件描述符
read(fd, buf, 1024);
close(fd);
```

内核为每个进程维护一张打开文件表（`files_struct`），fd 就是这张表的**下标**：

```
fd = 0  →  stdin  (标准输入)
fd = 1  →  stdout (标准输出)
fd = 2  →  stderr (标准错误)
fd = 3  →  你打开的第一个文件
fd = 4  →  你打开的第二个文件
...
```

### fd 的关键规则

| 规则 | 说明 |
|------|------|
| **最小可用** | `open()` 总是返回最小的可用 fd 号 |
| **fork 继承** | 子进程继承父进程的 fd 表副本 |
| **close-on-fork** | `FD_CLOEXEC` 标志可在 `exec` 时自动关闭 |
| **上限** | 默认 1024（`ulimit -n`），可调高 |
| **0/1/2 保留** | POSIX 约定 stdin/stdout/stderr |

### fork 后的 fd 共享

```c
int fd = open("shared.txt", O_RDWR);
pid_t pid = fork();
/* 父子进程的 fd 指向同一个内核打开文件对象（共享文件偏移量！） */
```

`fork()` 后，父子进程的 fd 副本指向**同一个**内核文件对象。这意味着：
- 父进程 `read(fd)` 会移动文件偏移量，子进程看到的偏移量也变了
- 这是管道通信的基础（父子进程通过共享的 pipe fd 传递数据）

### 和 C 语言的关系

C 标准库（`fopen`/`fread`/`fprintf`）用的是 `FILE*` 指针，底层封装了 fd：

| C 标准库 | POSIX 系统调用 | 区别 |
|----------|----------------|------|
| `FILE *fp = fopen(...)` | `int fd = open(...)` | FILE* 有用户态缓冲 |
| `fread(buf, 1, n, fp)` | `read(fd, buf, n)` | fread 可能不触发 syscall |
| `fprintf(fp, ...)` | `write(fd, ...)` | fprintf 有格式化+缓冲 |
| `fclose(fp)` | `close(fd)` | fclose 先 flush 再 close |

K&R 教的是 `FILE*` 接口；本模块教的是 `fd` 接口——后者更底层、更强大、无缓冲。

### HFT / 嵌入式关联

- **嵌入式**：通过 `/dev/mem` 或 `/dev/i2c-0` 等设备文件操作硬件
- **HFT**：fd 是 epoll/io_uring 的操作对象；减少 fd 数量可降低内核管理开销；`O_DIRECT` 绕过页缓存直接 I/O
