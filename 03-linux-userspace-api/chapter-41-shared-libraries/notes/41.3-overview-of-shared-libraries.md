# 41.3 Overview of Shared Libraries

> 本章：[TLPI 第 41 章](../README.md)

## 本节讲什么

共享库（`.so`）在运行时动态加载，多个进程共享同一份代码。本节介绍共享库的工作原理：地址无关代码（PIC）、动态链接器、符号解析和共享库的优势。

## 要点

### 共享库 vs 静态库

| 特性 | 共享库 (.so) | 静态库 (.a) |
|------|-------------|------------|
| 链接时机 | 运行时 | 编译时 |
| 代码共享 | 多进程共享一份 | 每程序各一份 |
| 内存占用 | 低 | 高 |
| 磁盘占用 | 低（一份） | 高（每程序含副本） |
| 升级 | 替换 .so 即生效 | 需重新链接 |
| 启动开销 | 需动态链接 | 无 |
| 版本管理 | 需 SONAME | 不涉及 |

### 地址无关代码（PIC）

PIC 让共享库代码段可在任意虚拟地址加载，无需重定位：

| 代码段 | 数据段 | 技术 |
|--------|--------|------|
| 可共享（只读） | 每进程独立副本 | GOT/PLL |
| 通过 GOT 间接访问全局变量 | GOT 记录实际地址 | 延迟绑定 |

### 动态链接过程

```
1. 加载可执行文件 → 发现 PT_INTERP (ld-linux.so)
2. ld-linux.so 加载 → 读取 DT_NEEDED 递归加载依赖库
3. 符号解析 → GOT/PLT 绑定（可延迟到首次调用）
4. 运行 → 程序入口 _start → main()
```

### 创建共享库

```bash
# -fPIC: 生成地址无关代码
gcc -fPIC -c foo.c bar.c

# -shared: 创建共享库
gcc -shared -o libmylib.so foo.o bar.o

# -Wl,-soname: 设置 SONAME
gcc -shared -Wl,-soname,libmylib.so.1 -o libmylib.so.1.0.0 foo.o bar.o
```

### 共享库命名约定

| 文件名 | 用途 | 示例 |
|--------|------|------|
| `libfoo.so` | 链接器搜索名（开发用） | `-lfoo` |
| `libfoo.so.1` | SONAME（运行时加载名） | 记录在 ELF DT_SONAME |
| `libfoo.so.1.0.0` | real name（实际文件） | 包含完整版本号 |

## HFT / 嵌入式关联

- 策略引擎作为 .so 动态加载，支持热更新无需重启交易进程
- 多个交易进程共享同一份行情解析库代码段，节省内存
- 嵌入式设备 OTA 升级只需替换 .so 文件

## 代码示例

```bash
#!/bin/bash
# 完整共享库创建和使用

# 1. 创建源文件
cat > greet.c << 'EOF'
#include <stdio.h>
void greet(const char *name) {
    printf("Hello from .so, %s!\n", name);
}
EOF

# 2. 编译为 PIC 目标文件
gcc -fPIC -c greet.c

# 3. 创建共享库（带 SONAME）
gcc -shared -Wl,-soname,libgreet.so.1 -o libgreet.so.1.0 greet.o

# 4. 创建符号链接
ln -sf libgreet.so.1.0 libgreet.so.1
ln -sf libgreet.so.1   libgreet.so

# 5. 链接使用
cat > main.c << 'EOF'
void greet(const char *);
int main() {
    greet("HFT");
    return 0;
}
EOF
gcc -o app main.c -L. -lgreet
export LD_LIBRARY_PATH=.
./app

# 6. 查看依赖
ldd app
```

## 代码自测

<details>
<summary>为什么共享库需要 -fPIC（地址无关代码）？</summary>

共享库代码段被多个进程映射到不同的虚拟地址。如果代码段中包含绝对地址引用，每个进程都需要不同的重定位，导致代码段无法共享（每个进程各一份 COW 副本）。PIC 通过 GOT（全局偏移表）间接引用，使代码段完全只读可共享，只有数据段（GOT 本身）需要每进程独立。这大幅减少了共享库的内存占用。

</details>
