# 41.14 Summary

> 本章：[TLPI 第 41 章](../README.md)

## 本节讲什么

第 41 章总结：共享库和静态库的创建、安装、链接、版本管理和运行时加载。

## 要点

### 库类型对比

| 特性 | 静态库 (.a) | 共享库 (.so) |
|------|------------|-------------|
| 创建 | `ar rcs` | `gcc -shared -fPIC` |
| 链接时机 | 编译时 | 运行时 |
| 代码共享 | 否 | 是 |
| 内存效率 | 低 | 高 |
| 升级 | 重新编译 | 替换 .so |
| 版本管理 | 无 | SONAME + real name |
| 运行时依赖 | 无 | 有 |

### 共享库命名体系

```
libfoo.so        ← 链接器名（-lfoo）
libfoo.so.1      ← SONAME（ELF DT_SONAME）
libfoo.so.1.0.0  ← real name（实际文件）
```

### 关键工具

| 工具 | 用途 |
|------|------|
| `ar` | 创建/管理静态库 |
| `gcc -shared -fPIC` | 创建共享库 |
| `ldconfig` | 更新库缓存 + 修复符号链接 |
| `ldd` | 查看可执行文件依赖的共享库 |
| `readelf -d` | 查看 ELF 动态段（RPATH, NEEDED 等） |
| `objdump -T` | 查看导出/导入符号 |
| `nm` | 查看符号表 |
| `dlopen`/`dlsym` | 运行时加载共享库 |

### 版本兼容规则

| 变更类型 | 主版本号 | 旧程序兼容 |
|----------|---------|-----------|
| bug 修复 | 不变 | 是 |
| 新增接口 | 不变 | 是 |
| 删除接口 | +1 | 否 |
| 修改接口签名 | +1 | 否 |
| 修改 struct 布局 | +1 | 否 |

### 运行时查找顺序

1. DT_RPATH（已废弃）
2. LD_LIBRARY_PATH
3. DT_RUNPATH（推荐）
4. ld.so.cache
5. 默认路径 (/lib, /usr/lib)

## HFT / 嵌入式关联

- 核心库：静态链接消除启动开销和依赖
- 策略插件：共享库 + dlopen 实现热更新
- 部署：`$ORIGIN` RPATH 实现自包含
- 版本管理：符号版本控制支持多版本共存

<summary>共享库的 SONAME 有什么作用？</summary>

SONAME 记录在 ELF 文件的 `DT_SONAME` 字段中。当链接器链接共享库时，会将 SONAME（而非文件名）记录在可执行文件的 `DT_NEEDED` 字段中。运行时，动态链接器根据 `DT_NEEDED` 中的 SONAME 查找库文件，而非原始文件名。这使得 `libfoo.so.1.0.0` 和 `libfoo.so.1.1.0` 都可以被 SONAME 为 `libfoo.so.1` 的程序使用，实现兼容升级。

</details>
