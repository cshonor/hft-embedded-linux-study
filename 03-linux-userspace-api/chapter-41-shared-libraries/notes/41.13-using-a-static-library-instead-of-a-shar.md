# 41.13 Using a Static Library Instead of a Shared Library

> 本章：[TLPI 第 41 章](../README.md)

## 本节讲什么

何时选择静态库而非共享库，以及静态链接的特殊场景：全静态链接（`-static`）、部分静态链接（`-Bstatic`）、glibc 的静态链接警告。

## 要点

### 全静态 vs 动态链接

| 特性 | 全静态 (`-static`) | 动态链接 |
|------|-------------------|---------|
| 可执行文件大小 | 大（含所有库代码） | 小 |
| 运行时依赖 | 无 | 需要共享库存在 |
| 启动速度 | 快（无需动态链接） | 稍慢 |
| 库升级 | 需重新编译 | 替换 .so 即可 |
| NSS 服务 | **不工作** | 正常 |
| 内存占用 | 每进程各一份 | 共享 |
| 兼容性 | 好（不依赖系统库版本） | 需匹配库版本 |

### 部分静态链接

```bash
# 仅 libfoo 静态链接，其余动态
gcc -o app app.o -L. -Wl,-Bstatic -lfoo -Wl,-Bdynamic -lm

# 或指定直接使用 .a 文件
gcc -o app app.o /path/to/libfoo.a -lm
```

### glibc 静态链接警告

```
warning: Using 'dlopen' in statically linked applications ...
warning: Using 'getaddrinfo' in statically linked applications ...
warning: Using 'getpwuid' in statically linked applications ...
```

glibc 的 NSS（Name Service Switch）机制依赖 `dlopen` 动态加载 `/lib/libnss_*.so`。全静态链接时这些功能不可用，`getpwuid`/`gethostbyname` 等函数会失败或退化。

### 选择指南

| 场景 | 推荐 | 原因 |
|------|------|------|
| 容器/嵌入式 | 全静态 | 无依赖，自包含 |
| 系统工具 | 全静态 | 救援模式下可用 |
| 库代码需更新 | 共享 | 替换 .so 即可 |
| HFT 核心路径 | 静态 | 减少动态链接开销 |
| HFT 辅助工具 | 共享 | 便于升级 |
| 多程序共享大库 | 共享 | 节省内存 |

### 静态链接的安全优势

- 无 `LD_PRELOAD` 注入风险
- 无 `LD_LIBRARY_PATH` 劫持
- 无库路径篡改
- 无动态链接器漏洞

## HFT / 嵌入式关联

- HFT 核心交易引擎全静态链接，消除启动延迟和库依赖
- 交易策略插件保持动态链接（需热更新）
- 嵌入式设备固件全静态，减少 OTA 包大小
- 安全敏感组件静态链接，防止库替换攻击

## 代码示例

```bash
#!/bin/bash
# 静态链接示例

# 1. 全静态链接
gcc -static -o app_static app.c -lm
# 验证无动态依赖
ldd app_static  # "not a dynamic executable"

# 2. 检查文件类型
file app_static
# app_static: ELF 64-bit LSB executable, x86-64, statically linked

# 3. 部分静态链接
gcc -o app_mixed app.c \
    -L./lib -Wl,-Bstatic -lstrategy -Wl,-Bdynamic -lm -lpthread

# 4. 体积对比
echo "Static:  $(stat -c%s app_static) bytes"
echo "Dynamic: $(stat -c%s app_dynamic) bytes"
```

## 代码自测

<details>
<summary>全静态链接 glibc 程序中 getpwuid() 为什么可能失败？</summary>

`getpwuid()` 通过 NSS（Name Service Switch）机制查找用户信息。glibc 的 NSS 实现使用 `dlopen` 动态加载 `/lib/libnss_files.so`（或 `libnss_ldap.so` 等）。全静态链接的程序无法调用 `dlopen`（没有动态链接器），因此 NSS 功能不工作，`getpwuid` 无法获取 `/etc/passwd` 中的信息，只能返回硬编码的默认值。

</details>
