# 41.9 Upgrading Shared Libraries

> 本章：[TLPI 第 41 章](../README.md)

## 本节讲什么

共享库升级的两种方式：兼容升级（替换 .so 文件）和不兼容升级（共存多个版本）。如何安全地在生产环境中升级。

## 要点

### 兼容升级流程

```
旧: libfoo.so.1.0.0 ← libfoo.so.1
新: libfoo.so.1.1.0 ← libfoo.so.1 (更新符号链接)
```

1. 安装新 real name 文件
2. 更新 SONAME 符号链接指向新文件
3. 运行 `ldconfig`
4. 正在运行的进程不受影响（旧 inode 仍存活）
5. 新进程启动自动使用新版本

### 不兼容升级流程

```
旧: libfoo.so.1.0.0 ← libfoo.so.1   (保留)
新: libfoo.so.2.0.0 ← libfoo.so.2   (新增)
```

1. 安装新主版本文件
2. 创建新 SONAME 符号链接
3. 旧 SONAME 保留（兼容旧程序）
4. 链接器名 `libfoo.so` 指向新版本
5. 新程序编译时用新版本，旧程序运行时用旧版本

### 升级安全性

| 场景 | 处理 |
|------|------|
| 文件正在被使用 | Linux 下可直接替换（旧 inode 存活） |
| 正在执行 | 新进程用新版，旧进程不变 |
| 即时生效 | 需重启进程 |
| 回滚 | 保留旧版本文件，更新符号链接 |

### 热升级模式

```bash
# 1. 安装新版本（不删除旧版本）
install -m 755 libfoo.so.1.1.0 /usr/local/lib/
ldconfig  # SONAME 指向新版本

# 2. 重启使用该库的服务
systemctl restart hft-engine

# 3. 确认无误后清理旧版本（可选）
rm /usr/local/lib/libfoo.so.1.0.0
```

### 进程级热加载（dlopen）

```c
/* 运行时加载新版本，不重启进程 */
void *handle = dlopen("libfoo.so.1.1", RTLD_NOW);
void (*new_func)(void) = dlsym(handle, "new_api");
```

## HFT / 嵌入式关联

- 交易系统零停机升级：`dlopen` 加载新策略库，切换后卸载旧库
- 行情解析库兼容升级：安装新 .so，重启子进程
- 嵌入式 OTA：新固件验证通过后替换库，失败回滚

## 代码示例

```bash
#!/bin/bash
# 兼容升级示例

OLD_VER=1.0.0
NEW_VER=1.1.0
SONAME=libhft.so.1

echo "=== 升级前 ==="
ls -la /usr/local/lib/libhft.so*

# 安装新版本
install -m 755 libhft.so.${NEW_VER} /usr/local/lib/
ldconfig

echo "=== 升级后 ==="
ls -la /usr/local/lib/libhft.so*

# 验证符号链接指向新版本
readlink /usr/local/lib/${SONAME}

# 检查正在使用旧版本的进程
echo "=== 使用旧版本的进程 ==="
lsof | grep libhft.so.${OLD_VER}
```

## 代码自测

<details>
<summary>升级共享库时正在运行的进程会受影响吗？</summary>

不会。Linux 允许替换正在使用的文件：旧 inode 保持存活直到所有引用关闭，新进程打开文件时看到新版本。运行中的进程代码段仍映射在旧 inode 上，不受影响。但新启动的进程会使用新版本。要让运行中的进程使用新版本，需要重启进程或用 `dlopen` 动态加载。

</details>
