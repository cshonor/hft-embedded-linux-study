# 12.3 Summary

> 本章：[TLPI 第 12 章 — System and Process Information](../README.md)

## 本章回顾

### 信息来源一览

| 来源 | API | 用途 | 特点 |
|------|-----|------|------|
| `/proc` | 文件读取 | 进程/系统信息 | 虚拟文件系统，实时更新 |
| `uname()` | 系统调用 | 内核版本/架构 | `struct utsname` |
| `sysinfo()` | 系统调用 | 内存/负载/uptime | 简化版系统统计 |

### /proc 关键路径

| 路径 | 内容 |
|------|------|
| `/proc/1/` | PID 1 进程信息 |
| `/proc/self/` | 当前进程（等价 `/proc/getpid()/`） |
| `/proc/cpuinfo` | CPU 信息 |
| `/proc/meminfo` | 内存信息 |
| `/proc/loadavg` | 系统负载 |
| `/proc/uptime` | 系统运行时间 |
| `/proc/version` | 内核版本 |
| `/proc/[pid]/status` | 进程状态摘要 |
| `/proc/[pid]/stat` | 进程统计（单行） |
| `/proc/[pid]/maps` | 内存映射 |
| `/proc/[pid]/cmdline` | 命令行参数 |
| `/proc/[pid]/environ` | 环境变量 |
| `/proc/[pid]/fd/` | 文件描述符 |
| `/proc/[pid]/cgroup` | cgroup 信息 |

### uname API

```c
struct utsname {
    char sysname[];    /* "Linux" */
    char nodename[];   /* 主机名 */
    char release[];    /* "5.15.0-25-generic" */
    char version[];    /* "#25-Ubuntu SMP ..." */
    char machine[];    /* "x86_64" */
    char domainname[]; /* NIS 域名 */
};
int uname(struct utsname *buf);
```

### sysinfo API

```c
struct sysinfo {
    long uptime;          /* 秒 */
    unsigned long loads[3]; /* 1/5/15 分钟负载 */
    unsigned long totalram;  /* 总内存 */
    unsigned long freeram;   /* 空闲内存 */
    unsigned long sharedram;
    unsigned long bufferram;
    unsigned long totalswap;
    unsigned long freeswap;
    unsigned short procs;  /* 进程数 */
    unsigned long totalhigh;
    unsigned long freehigh;
    unsigned int mem_unit;
};
int sysinfo(struct sysinfo *info);
```

### /proc/[pid]/status 关键字段

| 字段 | 含义 |
|------|------|
| `Name` | 进程名 |
| `Pid` | PID |
| `PPid` | 父 PID |
| `Uid` | real/effective/saved UID |
| `VmRSS` | 驻留内存（KB） |
| `VmSize` | 虚拟内存（KB） |
| `Threads` | 线程数 |
| `State` | 进程状态（R/S/D/Z/T） |

## HFT / 嵌入式关联

- **进程监控**：HFT 看板读取 `/proc/[pid]/stat` 获取 CPU、RSS、状态
- **内存监控**：`/proc/meminfo` 判断系统内存压力，触发告警
- **CPU 亲和性**：`/proc/[pid]/stat` 第 39 字段是 CPU 编号（最后运行在哪个核心）
- **嵌入式**：精简系统 `/proc` 可能被裁剪，`sysinfo` 和 `uname` 更可靠
- **性能分析**：`/proc/[pid]/maps` 分析内存映射，发现共享库占用

## 衔接

- **Ch06** 进程 — PID/PPID/内存布局
- **Ch15** 文件属性 — stat() 获取文件信息

## 代码自测

<details>
<summary>1. /proc/self 是什么？和 /proc/getpid() 有什么区别？</summary>

`/proc/self` 是一个特殊的符号链接，始终指向当前进程的 `/proc/[pid]` 目录。它和 `/proc/getpid()` 指向同一目录，但 `/proc/self` 不需要先调用 `getpid()`，且在多线程程序中始终指向当前线程组。实际上 `/proc/self` 是一个内核生成的虚拟符号链接。
</details>

<details>
<summary>2. /proc/[pid]/maps 每行包含哪些信息？</summary>

格式：`address perms offset dev inode pathname`

```
00400000-00401000 r-xp 00000000 fd:00 12345  /usr/bin/myapp
00600000-00601000 r--p 00000000 fd:00 12345  /usr/bin/myapp
00601000-00602000 rw-p 00001000 fd:00 12345  /usr/bin/myapp
7f1234000000-7f1234021000 r-xp 00000000 fd:00 67890  /usr/lib/libc.so.6
```

- address：虚拟地址范围
- perms：r/w/x/p（p=private, s=shared）
- offset：文件内偏移
- dev：设备号
- inode：inode 号
- pathname：映射文件（或 [heap]/[stack]/[anon]）
</details>

<details>
<summary>3. sysinfo() 和读取 /proc/meminfo 哪个更好？</summary>

各有适用场景：
- `sysinfo()`：一次系统调用获取结构化数据，开销小，适合程序内部监控
- `/proc/meminfo`：信息更详细（包含 Cached、Buffers、Slab 等细分项），适合需要精细分析
- HFT 监控通常用 `sysinfo()` 减少文件 I/O 开销；运维分析用 `/proc/meminfo`
</details>
