## 本节讲什么

这一节是全章**唯一**讲可移植接口的地方：`/proc` 是 Linux 专有，`sysinfo()` / `get_nprocs()` 是 Linux+GNU 专有，只有 `uname()` 和 `gethostname()` 是 POSIX 通行的。本节回答三个问题：

1. `struct utsname` 到底有几个字段？为什么**是六个而不是五个**？
2. `uname()` 在 Linux 上是个什么函数——libc 自己算出来的，还是直接问内核？
3. `gethostname(name, len)` 缓冲不够时会怎样？**截断返回 0**，还是**报错**？

## 1. 六个字段，每个 65 字节

```c
#include <sys/utsname.h>

int uname(struct utsname *buf);
```

`struct utsname` 的成员在内核头 `include/uapi/linux/utsname.h:25-32` 里定义（`struct new_utsname`）：

```c
struct new_utsname {
	char sysname[__NEW_UTS_LEN + 1];
	char nodename[__NEW_UTS_LEN + 1];
	char release[__NEW_UTS_LEN + 1];
	char version[__NEW_UTS_LEN + 1];
	char machine[__NEW_UTS_LEN + 1];
	char domainname[__NEW_UTS_LEN + 1];
};
```

`__NEW_UTS_LEN` 在 `include/uapi/linux/utsname.h:15` 定义为 **64**，所以每个字段是 `char[65]`（64 个有效字符 + 1 个 NUL）。**六个字段全是定长数组，不是指针**——于是整个结构体是 390 字节的平凡数据，可以直接 `memcpy`、可以直接塞进日志，没有生命周期问题。

| 字段 | 含义 | 本容器实测 | 谁在管 |
|------|------|-----------|--------|
| `sysname` | 操作系统名 | `Linux`（Linux 上**恒为** `Linux`，`include/linux/uts.h:8` 的 `UTS_SYSNAME`） | 编译期常量 |
| `nodename` | 主机名 | `ce` | `sethostname(2)`，需 `CAP_SYS_ADMIN` |
| `release` | 内核发布号 | `7.0.0-1012-aws` | 编译期 `Makefile` 的版本串 |
| `version` | 构建信息 | `#12~24.04.1-Ubuntu SMP PREEMPT Wed Aug 12 14:00:57 UTC 2026` | 编译时间与配置 |
| `machine` | 硬件架构 | `x86_64` | 编译期 |
| `domainname` | NIS 域名 | `(none)` | `setdomainname(2)`，需 `CAP_SYS_ADMIN`；**GNU 扩展** |

> `domainname` 是**非标准**字段：`man 2 uname` 的 NOTES 明说它是 GNU 扩展，并且**只有在 `_GNU_SOURCE` 定义时**才会出现在 `struct utsname` 里。原书 Listing 12-2（`t_uname.c`）就是拿 `#ifdef _GNU_SOURCE` 把它包起来的——不定义那个宏，代码里写 `uts.domainname` 直接编译不过。

完整源码 [`code/c12_2_uname.c`](../code/c12_2_uname.c)：

```c
/* c12_2_uname.c — Ch12 §12.2：uname() 是本章唯一「POSIX 可移植」的接口
 *
 * TLPI §12.2 只有一页多，但有几个必须钉住的点：
 *   ① `struct utsname` 有**六个**字段，不是五个 —— 第六个是 GNU 扩展 domainname；
 *   ② 每个字段只有 **65 字节**（`__NEW_UTS_LEN` = 64，再留一个 NUL），
 *      所以 version 这类长串**一定**会被截断，别拿它当完整信息；
 *   ③ 在 Linux 上 `uname()` 就是**裸的 `uname(2)` 系统调用**（本程序与
 *      `syscall(SYS_uname, ...)` 逐字段对拍证明）。glibc 里 `posix/uname.c`
 *      那份「用编译期常量 + gethostname 拼出来」的实现**不是 Linux 用的**；
 *   ④ `nodename` 与 `gethostname()` 必然一致 —— 因为 glibc 的 `gethostname()`
 *      正是**建在 uname() 之上**的（`sysdeps/posix/gethostname.c:32` 里调
 *      `__uname()`），两者读的是同一个内核字段，不是巧合；
 *   ⑤ 由此推出一条反直觉的 API 语义：`gethostname(name, len)` 在 `len` 不够时
 *      **返回 -1 / ENAMETOOLONG，而且**留在缓冲里的是**没有 NUL 终止**的前缀
 *      —— 这里不能当字符串用；
 *   ⑥ `domainname` 的默认值字面量是 "(none)"，看起来像「没设置」，其实它就是
 *      内核给初值（`include/linux/uts.h` 的 `UTS_DOMAINNAME`）；
 *   ⑦ uname() 拿不到 CPU 数、内存量、进程列表 —— 那些必须走 /proc 或 sysinfo。
 *
 * 编译： gcc -O0 -Wall -Wextra -o c12_2_uname c12_2_uname.c
 * 取材： man-pages 6.19 uname(2)（"returns a string identifying the kernel"、EFAULT）
 *                      gethostname(2) 的 ERRORS（ENAMETOOLONG）
 *       Linux v6.6 include/uapi/linux/utsname.h:15（__NEW_UTS_LEN = 64）
 *                      include/uapi/linux/utsname.h:25-32（struct new_utsname = 6×65）
 *                      include/linux/uts.h:16-18（UTS_DOMAINNAME "(none)"）
 *                      kernel/sys.c:1306-1321（SYSCALL_DEFINE1(newuname)：memcpy 整个
 *                       390 字节结构体 + copy_to_user，无 NULL 检查 → EFAULT）
 *                      kernel/sys.c:1374-1426（sethostname/gethostname 的 CAP_SYS_ADMIN）
 *       glibc 2.39 sysdeps/unix/syscalls.list:88（"uname - uname i:p __uname uname"
 *                       —— uname 是**自动生成的 syscall 包装**）
 *                      sysdeps/posix/gethostname.c:26-46（gethostname 建在 __uname 上）
 *                      posix/uname.c:28-62（通用实现，Linux 不用它）
 */
#define _GNU_SOURCE
#include <errno.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <sys/syscall.h>
#include <sys/utsname.h>
#include <unistd.h>

static void hexdump(const char *tag, const unsigned char *b, int n)
{
    printf("  %s =", tag);
    for (int i = 0; i < n; i++)
        printf(" %02x", b[i]);
    printf("\n");
}

int main(void)
{
    /* ---------- ① 六个字段 ---------- */
    printf("== ① uname() 的六个字段 ==\n");
    struct utsname u;
    errno = 0;
    if (uname(&u) == -1) {
        printf("  uname 失败 errno=%d(%s)\n", errno, strerror(errno));
        return EXIT_FAILURE;
    }
    printf("  sysname    = [%s]  （OS 名，Linux 上恒为 \"Linux\"）\n", u.sysname);
    printf("  nodename   = [%s]  （即主机名）\n", u.nodename);
    printf("  release    = [%s]  （内核版本号，脚本里最常被解析的一项）\n", u.release);
    printf("  version    = [%s]\n", u.version);
    printf("  machine    = [%s]  （硬件架构，交叉编译/移植判断用这个）\n", u.machine);
    printf("  domainname = [%s]  （GNU 扩展，注意它的值）\n", u.domainname);
    printf("  各字段 strlen: sysname=%d nodename=%d release=%d version=%d machine=%d domain=%d\n",
           (int) strlen(u.sysname), (int) strlen(u.nodename), (int) strlen(u.release),
           (int) strlen(u.version), (int) strlen(u.machine), (int) strlen(u.domainname));
    printf("\n");

    /* ---------- ② 字段有多宽 ---------- */
    printf("== ② 每个字段只有 65 字节，结构体没有填充 ==\n");
    printf("  sizeof(struct utsname) = %zu 字节\n", sizeof(struct utsname));
    printf("  %zu / 6 = %zu 字节/字段  ⇒  `__NEW_UTS_LEN` = 64，再留 1 个 NUL\n",
           sizeof(struct utsname), sizeof(struct utsname) / 6);
    printf("  6 x 65 = %zu，与 sizeof 之差 = %zu（uname(2) 的载荷就是这 390 字节）\n",
           (size_t) 6 * 65, sizeof(struct utsname) - (size_t) 6 * 65);
    printf("  ⚠️ 字段是**定长数组**（char[65]），不是指针；所以整个结构体是 %zu 字节的\n",
           sizeof(struct utsname));
    printf("     平凡数据，可以直接 memcpy / 存进日志，没有生命周期问题。\n");
    printf("  ⚠️ version 最长只能装 64 个字符，本例已用 %d 个 —— 内核写入时就按\n",
           (int) strlen(u.version));
    printf("     `__NEW_UTS_LEN` 截断了，uname() 拿到的已是截断后的结果，\n");
    printf("     读的人无从知道原文更长。\n\n");

    /* ---------- ③ 它就是系统调用 ---------- */
    printf("== ③ 在 Linux 上 uname() 就是裸的 uname(2) 系统调用 ==\n");
    struct utsname raw;
    memset(&raw, 'X', sizeof(raw));     /* 先用 'X' 灌满，看内核写了哪些字节 */
    errno = 0;
    long sr = syscall(SYS_uname, &raw);
    int sre = errno;
    printf("  syscall(SYS_uname, &raw) = %ld errno=%d(%s)\n", sr, sre, strerror(sre));
    printf("  六字段逐一对拍（uname() / 原始系统调用）:\n");
    printf("    sysname    same=%d\n", strcmp(u.sysname, raw.sysname) == 0);
    printf("    nodename   same=%d\n", strcmp(u.nodename, raw.nodename) == 0);
    printf("    release    same=%d\n", strcmp(u.release, raw.release) == 0);
    printf("    version    same=%d\n", strcmp(u.version, raw.version) == 0);
    printf("    machine    same=%d\n", strcmp(u.machine, raw.machine) == 0);
    printf("    domainname same=%d\n", strcmp(u.domainname, raw.domainname) == 0);
    int xleft = 0;
    const unsigned char *pb = (const unsigned char *) &raw;
    for (size_t i = 0; i < sizeof(raw); i++)
        if (pb[i] == 'X')
            xleft++;
    printf("  内核回来之后缓冲里剩余的 'X' 字节数 = %d / %zu（0 = 内核写满了整份载荷）\n",
           xleft, sizeof(raw));
    printf("  ⚠️ 所以「nodename 是内核当场给的、不是 glibc 从别处拼的」这一点可以确认。\n");
    printf("     对照 /proc/sys/kernel/osrelease = ");
    {
        FILE *fp = fopen("/proc/sys/kernel/osrelease", "r");
        char b[128] = "";
        if (fp) { if (fgets(b, sizeof b, fp)) { char *nl = strchr(b, '\n'); if (nl) *nl = '\0'; } fclose(fp); }
        printf("[%s]  == uname.release? %d\n", b, strcmp(b, u.release) == 0);
    }
    printf("  ⚠️ 带 NULL 指针：syscall(SYS_uname, NULL) = ");
    errno = 0;
    long nul = syscall(SYS_uname, NULL);
    printf("%ld errno=%d(%s) —— 内核在 copy_to_user 处把 NULL 挡成 EFAULT\n\n",
           nul, errno, strerror(errno));

    /* ---------- ④ nodename ≡ gethostname() 的机制 ---------- */
    printf("== ④ nodename 与 gethostname() 必然一致，且原因是「同一条路」 ==\n");
    char host[256];
    errno = 0;
    if (gethostname(host, sizeof(host)) == -1) {
        printf("  gethostname 失败 errno=%d(%s)\n", errno, strerror(errno));
    } else {
        printf("  uname().nodename      = [%s]\n", u.nodename);
        printf("  gethostname(host,256) = [%s]\n", host);
        printf("  → %s\n", strcmp(u.nodename, host) == 0 ? "一致" : "不一致");
    }
    printf("  机制：glibc 的 gethostname() **不是**独立系统调用，它内部先调 __uname()\n");
    printf("        再把结果里的 nodename 段 memcpy 出来（sysdeps/posix/gethostname.c）。\n");
    printf("        所以两者不可能不一致 —— 这是实现决定的，不是巧合。\n");
    printf("  ⚠️ 但可移植性不同：`gethostname()` 是 POSIX，`domainname` 字段是 GNU 扩展。\n\n");

    /* ---------- ⑤ gethostname 缓冲太小时的**真实**行为 ---------- */
    printf("== ⑤ gethostname(name, len) 当 len 不够：-1/ENAMETOOLONG 且缓冲不终止 ==\n");
    printf("  主机名 = \"%s\"，strlen+1 = %d 字节，所以 len < %d 就一定不够。\n",
           u.nodename, (int) strlen(u.nodename) + 1, (int) strlen(u.nodename) + 1);
    for (int len = 1; len <= 5; len++) {
        unsigned char buf[8];
        memset(buf, 'Z', sizeof(buf));      /* 'Z' = 0x5a，便于看出哪些字节被覆盖 */
        errno = 0;
        int r = gethostname((char *) buf, (size_t) len);
        int e = errno;
        printf("  len=%d -> ret=%d errno=%d(%s)\n", len, r, e, strerror(e));
        char tag[32];
        snprintf(tag, sizeof(tag), "byte[0..7]");
        hexdump(tag, buf, 8);
    }
    printf("  → len=1/2 都返回 -1（ENAMETOOLONG = 36），**而且缓冲里只有前缀、没有 NUL**：\n");
    printf("     len=2 时留下的是 \"%c%c\" 两个裸字节，后头还是原来的 'Z'。\n",
           u.nodename[0], u.nodename[1]);
    printf("     ⚠️ 这时**绝不能**把缓冲当 C 字符串 printf 出去 —— 会一路读到 'Z' 之后。\n");
    printf("     len >= %d 才返回 0 并写好终止符。\n", (int) strlen(u.nodename) + 1);
    printf("  sysconf(_SC_HOST_NAME_MAX) = %ld（= __NEW_UTS_LEN，缓冲给这么多就永远够）\n",
           sysconf(_SC_HOST_NAME_MAX));
    printf("  ⚠️ POSIX 允许「截断并返回 0」，也允许「报 ENAMETOOLONG」；glibc 选后者。\n");
    printf("     所以**不能靠返回值判断有没有截断** —— 要么给足 64 字节，要么自己查 errno。\n\n");

    /* ---------- ⑥ domainname 为什么是 "(none)" ---------- */
    printf("== ⑥ domainname = \"(none)\" 不是「没设置」，是内核给的初值 ==\n");
    printf("  当前值 = [%s]\n", u.domainname);
    printf("  内核侧：include/linux/uts.h:16-18 里 `#define UTS_DOMAINNAME \"(none)\"`，\n");
    printf("          init_uts_ns 初始化时就把这个字面量填进 name.domainname；\n");
    printf("          改它走 `setdomainname(2)`（kernel/sys.c:1428），要 CAP_SYS_ADMIN。\n");
    printf("  ⚠️ 这个字段是 **GNU 扩展**：是否定义 `_GNU_SOURCE` 决定 `struct utsname`\n");
    printf("     里有没有 `domainname` 成员 —— 原书 Listing 12-2 就是拿\n");
    printf("     `#ifdef _GNU_SOURCE` 把它包起来的（见本目录 t_uname.c）。\n\n");

    /* ---------- ⑦ 它拿不到什么 ---------- */
    printf("== ⑦ uname() 拿不到的三样东西 ==\n");
    printf("  CPU 数：uname() 只说 machine=\"%s\"，不说有几个核\n", u.machine);
    printf("          → 要 get_nprocs() / sysconf(_SC_NPROCESSORS_ONLN)（见 c12_nprocs.c）\n");
    printf("  内存量：uname() 完全不给\n");
    printf("          → 要 /proc/meminfo / sysinfo() / sysconf(_SC_PHYS_PAGES)（见 c12_sysinfo.c）\n");
    printf("  进程列表：uname() 完全不给\n");
    printf("          → 要遍历 /proc/[0-9]*（见 ex12_1_proc_walk.c）\n\n");

    /* ---------- ⑧ 工程用法 ---------- */
    printf("== ⑧ 工程用法：启动时把 uname() 落进日志 ==\n");
    printf("  机器可读的启动横幅（版本漂移排查的第一手证据）：\n");
    printf("    BUILD %s %s %s [%s]\n", u.sysname, u.release, u.machine, u.nodename);
    printf("  ⚠️ 但**别**用 uname().release 做「功能是否可用」的判据：\n");
    printf("     发行版会回填补丁、容器会伪装内核版本（本机 release=%s，\n", u.release);
    printf("     而 /proc/version 里同一份信息还裹着编译器串）。\n");
    printf("     正确做法是「试一下」—— 直接调那个 API 看 errno，而不是比版本号。\n");
    return EXIT_SUCCESS;
}
```

CE 实测（第 ①② 段）：

```text
== ① uname() 的六个字段 ==
  sysname    = [Linux]  （OS 名，Linux 上恒为 "Linux"）
  nodename   = [ce]  （即主机名）
  release    = [7.0.0-1012-aws]  （内核版本号，脚本里最常被解析的一项）
  version    = [#12~24.04.1-Ubuntu SMP PREEMPT Wed Aug 12 14:00:57 UTC 2026]
  machine    = [x86_64]  （硬件架构，交叉编译/移植判断用这个）
  domainname = [(none)]  （GNU 扩展，注意它的值）
  各字段 strlen: sysname=5 nodename=2 release=14 version=59 machine=6 domain=6

== ② 每个字段只有 65 字节，结构体没有填充 ==
  sizeof(struct utsname) = 390 字节
  390 / 6 = 65 字节/字段  ⇒  `__NEW_UTS_LEN` = 64，再留 1 个 NUL
  6 x 65 = 390，与 sizeof 之差 = 0（uname(2) 的载荷就是这 390 字节）
  ⚠️ 字段是**定长数组**（char[65]），不是指针；所以整个结构体是 390 字节的
     平凡数据，可以直接 memcpy / 存进日志，没有生命周期问题。
  ⚠️ version 最长只能装 64 个字符，本例已用 59 个 —— 内核写入时就按
     `__NEW_UTS_LEN` 截断了，uname() 拿到的已是截断后的结果，
     读的人无从知道原文更长。
```

**`version` 字段的截断是本节最容易忽视的一点**：`/proc/version` 里同一个字符串还裹着编译器信息（见 [12.1](12.1-proc-filesystem.md) 实测，那里完整 219 字节），而 `uname().version` 只有 59 个字符——因为内核在写入时就按 64 字节上限裁过了。**读的人完全无法知道原文更长**，所以别拿 `uname().version` 当「完整的构建信息」。

## 2. 在 Linux 上，`uname()` 就是裸的 `uname(2)` 系统调用

这是本节最值得钉住的一条实现事实。

glibc 源码树里有两份 `uname` 实现：

| 文件 | 内容 | **Linux 上用哪份？** |
|------|------|-------------------|
| `posix/uname.c:28-62` | 一份「通用实现」：先用编译期常量填 `sysname`，再调 `gethostname()` 补 `nodename` | **不用** |
| `sysdeps/unix/syscalls.list:88` | 一行生成规则：`uname		-	uname		i:p	__uname		uname` | **用这份**（自动生成的 syscall 包装） |

也就是说 Linux 上 `uname()` 是一层**自动生成的系统调用包装**，直接把 390 字节的内核结果拷回来，**没有任何 libc 侧加工**。`c12_2_uname.c` 的第 ③ 段用它做对拍证明：

```text
== ③ 在 Linux 上 uname() 就是裸的 uname(2) 系统调用 ==
  syscall(SYS_uname, &raw) = 0 errno=0(Success)
  六字段逐一对拍（uname() / 原始系统调用）:
    sysname    same=1
    nodename   same=1
    release    same=1
    version    same=1
    machine    same=1
    domainname same=1
  内核回来之后缓冲里剩余的 'X' 字节数 = 0 / 390（0 = 内核写满了整份载荷）
  ⚠️ 所以「nodename 是内核当场给的、不是 glibc 从别处拼的」这一点可以确认。
     对照 /proc/sys/kernel/osrelease = [7.0.0-1012-aws]  == uname.release? 1
  ⚠️ 带 NULL 指针：syscall(SYS_uname, NULL) = -1 errno=14(Bad address) —— 内核在 copy_to_user 处把 NULL 挡成 EFAULT
```

`'X'` 填充探测的用意：先把整个结构体灌成 `'X'`，调用之后数还剩多少个 `'X'`。结果是 **0 / 390**——内核写满了整份载荷，没有一处留给 libc 去补。这就是「它是裸系统调用」的直接证据。

内核侧的对应代码是 `kernel/sys.c:1306-1321`：

```c
SYSCALL_DEFINE1(newuname, struct new_utsname __user *, name)
{
	struct new_utsname tmp;

	down_read(&uts_sem);
	memcpy(&tmp, utsname(), sizeof(tmp));
	up_read(&uts_sem);
	if (copy_to_user(name, &tmp, sizeof(tmp)))
		return -EFAULT;

	return 0;
}
```

注意它**没有 `if (!name) return -EFAULT;`**——NULL 是靠 `copy_to_user` 挡下来的（实测 `errno=14 EFAULT`）。对比 `kernel/sys.c:1331` 的 `uname` / `olduname` 才是显式判 NULL 的。

> **顺带一个「实现决定行为」的例子**：因为 `uname()` 是纯系统调用包装，它对 `buf` 是 `__user` 指针、要整份 390 字节都写成功才返回 0。所以传一个**只读映射**、或者跨页边界只映射了一半的缓冲进去，会得到 `EFAULT` 而不是部分成功。

## 3. `nodename` 与 `gethostname()` **必然**一致——而且原因不是巧合

```text
== ④ nodename 与 gethostname() 必然一致，且原因是「同一条路」 ==
  uname().nodename      = [ce]
  gethostname(host,256) = [ce]
  → 一致
  机制：glibc 的 gethostname() **不是**独立系统调用，它内部先调 __uname()
        再把结果里的 nodename 段 memcpy 出来（sysdeps/posix/gethostname.c）。
        所以两者不可能不一致 —— 这是实现决定的，不是巧合。
  ⚠️ 但可移植性不同：`gethostname()` 是 POSIX，`domainname` 字段是 GNU 扩展。
```

`sysdeps/posix/gethostname.c:26-46` 的整个实现只有十来行：

```c
int
__gethostname (char *name, size_t len)
{
  struct utsname buf;
  size_t node_len;

  if (__uname (&buf))
    /* Can't get hostname.  */
    return -1;

  node_len = strlen (buf.nodename) + 1;
  memcpy (name, buf.nodename, len < node_len ? len : node_len);

  if (node_len > len)
    {
      __set_errno (ENAMETOOLONG);
      return -1;
    }

  return 0;
}
```

所以 `gethostname()` 读的**就是** `uname().nodename` 那一段内存的来源（内核的 `uts_ns`）。这也解释了一条容易踩的语义（见下一节）：**缓冲不够时它返回 `-1`，而不是截断后返回 0**。

## 4. `gethostname()` 缓冲不够时的真实行为

这是本仓库在实测中**纠正过的一次判断**。直觉上「`gethostname` 会把名字截断放进缓冲、返回 0」很常见（很多老文档这么写），但 glibc 的代码不是这样——上面那段 `if (node_len > len) { __set_errno(ENAMETOOLONG); return -1; }` 就是判据。

实测（主机名 `"ce"`，`strlen+1 = 3`，所以 `len < 3` 一定不够）：

```text
== ⑤ gethostname(name, len) 当 len 不够：-1/ENAMETOOLONG 且缓冲不终止 ==
  主机名 = "ce"，strlen+1 = 3 字节，所以 len < 3 就一定不够。
  len=1 -> ret=-1 errno=36(File name too long)
  byte[0..7] = 63 5a 5a 5a 5a 5a 5a 5a
  len=2 -> ret=-1 errno=36(File name too long)
  byte[0..7] = 63 65 5a 5a 5a 5a 5a 5a
  len=3 -> ret=0 errno=0(Success)
  byte[0..7] = 63 65 00 5a 5a 5a 5a 5a
  len=4 -> ret=0 errno=0(Success)
  byte[0..7] = 63 65 00 5a 5a 5a 5a 5a
  len=5 -> ret=0 errno=0(Success)
  byte[0..7] = 63 65 00 5a 5a 5a 5a 5a
  → len=1/2 都返回 -1（ENAMETOOLONG = 36），**而且缓冲里只有前缀、没有 NUL**：
     len=2 时留下的是 "ce" 两个裸字节，后头还是原来的 'Z'。
     ⚠️ 这时**绝不能**把缓冲当 C 字符串 printf 出去 —— 会一路读到 'Z' 之后。
     len >= 3 才返回 0 并写好终止符。
  sysconf(_SC_HOST_NAME_MAX) = 64（= __NEW_UTS_LEN，缓冲给这么多就永远够）
  ⚠️ POSIX 允许「截断并返回 0」，也允许「报 ENAMETOOLONG」；glibc 选后者。
     所以**不能靠返回值判断有没有截断** —— 要么给足 64 字节，要么自己查 errno。
```

三件必须记住的事：

| 事实 | 实测证据 | 后果 |
|------|---------|------|
| `len` 不够时返回 **`-1` / `ENAMETOOLONG(36)`** | `len=1 -> ret=-1 errno=36`、`len=2 -> ret=-1 errno=36` | 返回值**必须查**；不查就会拿一段没终止的字节当字符串 |
| 失败时**缓冲里没有 NUL 终止符** | `len=2` 的 hexdump 是 `63 65 5a 5a…`（`'c' 'e' 'Z' 'Z'…`） | 失败之后**绝不能** `printf("%s", name)` |
| 给 `sysconf(_SC_HOST_NAME_MAX) = 64` 字节就永远够 | `len=3` 起就 `ret=0` 且 `byte[2]=00` | 实用写法：`char host[64];` 或 `char host[_SC_HOST_NAME_MAX + 1]` |

> **POSIX 在这里留了口子**：`gethostname(2)` 的 ERRORS 段只说可以报 `ENAMETOOLONG`，没说必须报。所以**同一个程序在别的 libc 上真的可能截断返回 0**。要写跨平台代码，唯一稳的办法是「给足 64 字节」+「检查返回值」两件事都做。

## 5. `domainname = "(none)"` 的来由

`(none)` 看起来像「没设置」，其实它就是**内核给的初值字面量**：

```text
== ⑥ domainname = "(none)" 不是「没设置」，是内核给的初值 ==
  当前值 = [(none)]
  内核侧：include/linux/uts.h:16-18 里 `#define UTS_DOMAINNAME "(none)"`，
          init_uts_ns 初始化时就把这个字面量填进 name.domainname；
          改它走 `setdomainname(2)`（kernel/sys.c:1428），要 CAP_SYS_ADMIN。
  ⚠️ 这个字段是 **GNU 扩展**：是否定义 `_GNU_SOURCE` 决定 `struct utsname`
     里有没有 `domainname` 成员 —— 原书 Listing 12-2 就是拿
     `#ifdef _GNU_SOURCE` 把它包起来的（见本目录 t_uname.c）。
```

`include/linux/uts.h:16-18` 原文：

```c
#define UTS_SYSNAME "Linux"
#define UTS_NODENAME CONFIG_DEFAULT_HOSTNAME /* set by sethostname() */
#define UTS_DOMAINNAME "(none)"	/* set by setdomainname() */
```

`domainname` 是 **NIS（Yellow Pages）时代**的概念：网络里的一堆主机共属一个域名，`domainname` 就是那个域（与 DNS 域名**无关**）。`getdomainname(2)` / `setdomainname(2)` 是它的一对反向操作，另有文本接口 `/proc/sys/kernel/domainname`。现代系统大多不用 NIS，于是永远是 `(none)`。

## 6. `uname()` 拿不到的三样东西

```text
== ⑦ uname() 拿不到的三样东西 ==
  CPU 数：uname() 只说 machine="x86_64"，不说有几个核
          → 要 get_nprocs() / sysconf(_SC_NPROCESSORS_ONLN)（见 c12_nprocs.c）
  内存量：uname() 完全不给
          → 要 /proc/meminfo / sysinfo() / sysconf(_SC_PHYS_PAGES)（见 c12_sysinfo.c）
  进程列表：uname() 完全不给
          → 要遍历 /proc/[0-9]*（见 ex12_1_proc_walk.c）
```

这一条把本章三节的**分工**钉死了：`uname()` 只给「这台机器**是什么**」（名称、版本、架构），不给「这台机器**现在怎么样**」（资源、负载、进程）。后者全在 `/proc` / `sysinfo()`。

顺带一个工程用法（第 ⑧ 段）：

```text
== ⑧ 工程用法：启动时把 uname() 落进日志 ==
  机器可读的启动横幅（版本漂移排查的第一手证据）：
    BUILD Linux 7.0.0-1012-aws x86_64 [ce]
  ⚠️ 但**别**用 uname().release 做「功能是否可用」的判据：
     发行版会回填补丁、容器会伪装内核版本（本机 release=7.0.0-1012-aws，
     而 /proc/version 里同一份信息还裹着编译器串）。
     正确做法是「试一下」—— 直接调那个 API 看 errno，而不是比版本号。
```

```c

/* t_uname.c

   Demonstrate the use of the uname() system call, which returns various
   identifying information about the system.

#endif
#include <sys/utsname.h>
#include "tlpi_hdr.h"

main(int argc, char *argv[])

    struct utsname uts;

    if (uname(&uts) == -1)
        errExit("uname");

    printf("Node name:   %s\n", uts.nodename);
    printf("System name: %s\n", uts.sysname);
    printf("Release:     %s\n", uts.release);
    printf("Version:     %s\n", uts.version);
    printf("Machine:     %s\n", uts.machine);
#ifdef _GNU_SOURCE
    printf("Domain name: %s\n", uts.domainname);
#endif
    exit(EXIT_SUCCESS);
}
```

CE 实测：

```text
Node name:   ce
System name: Linux
Release:     7.0.0-1012-aws
Version:     #12~24.04.1-Ubuntu SMP PREEMPT Wed Aug 12 14:00:57 UTC 2026
Machine:     x86_64
Domain name: (none)
```

原书这个程序只有 39 行，但有两处值得看的设计：

| 写法 | 为什么这么写 |
|------|-------------|
| `#ifdef __linux__` 包住 `#define _GNU_SOURCE` | `domainname` 是 Linux/GNU 扩展，只在 Linux 上开启这个宏 |
| 输出处再套一层 `#ifdef _GNU_SOURCE` | 在别的平台（如 macOS）上 `uts.domainname` 不存在，代码要能编译过 |

这两个 `#ifdef` 连在一起的效果是：**同一份源码，在有 `domainname` 的系统上多打一行，在没有的系统上少打一行**，而不用改任何一行逻辑。

## 常见坑

| 坑 | 正解 |
|----|------|
| 只准备 5 个字段 | 是**六个**。第六个 `domainname` 是 GNU 扩展，靠 `_GNU_SOURCE` 开关；不定义这个宏，代码里写 `uts.domainname` **编译不过** |
| 拿 `uname().version` 当完整构建信息 | 它被裁到 64 字符（实测 59）。完整信息在 `/proc/version` |
| 以为 `uname()` 是 libc 拼的 | Linux 上它就是裸的 `uname(2)`（`sysdeps/unix/syscalls.list:88` 自动生成）。用 `'X'` 灌满缓冲 + `syscall(SYS_uname)` 对拍可以证明 |
| `char host[32]; gethostname(host, 32);` 不查返回值 | `len` 不够时返回 `-1` / `ENAMETOOLONG`，**且缓冲里没有 NUL**。直接 `printf("%s")` 会读到栈上残留 |
| 用 `uname().release` 做特性判据 | 发行版回填补丁、容器伪装版本，比版本号不可靠。「试一下那个 API，看 `errno`」才是正解 |
| 认为 `domainname == "(none)"` 表示「未初始化/读取失败」 | 它是内核的字面量初值（`UTS_DOMAINNAME`）。读取是成功的 |
| 用 `sizeof(struct utsname)` 当「有效载荷」 | 是 **390**，且 `sizeof` 是最可靠的写法；**不要**自己写 `6 * 65`，跨平台（BSD 的字段布局不同）会错 |

|------|----------------|

<summary>代码自测（Q&A）</summary>

**Q1：`struct utsname` 有几个字段？第六个是什么？**
A：**六个**。前五个是 POSIX 的 `sysname` / `nodename` / `release` / `version` / `machine`，第六个 `domainname` 是 **GNU 扩展**（NIS 域名），只在定义了 `_GNU_SOURCE` 时存在。实测 `sizeof(struct utsname) = 390 = 6 × 65`，**没有填充**。

**Q2：为什么每个字段是 65 字节？**
A：内核头 `include/uapi/linux/utsname.h:15` 定义 `__NEW_UTS_LEN = 64`，字段声明是 `char x[__NEW_UTS_LEN + 1]`——64 个有效字符加一个 NUL。所以 `version` 这类长串**一定**会被截断，且读的人无从知道原文更长（本容器实测 `version` 用了 59 个字符）。

**Q3：`uname()` 在 Linux 上到底是 libc 函数还是系统调用？**
A：**就是裸的系统调用**。glibc 用 `sysdeps/unix/syscalls.list:88` 自动生成了一个包装（`uname -> __uname`），没有额外加工。`posix/uname.c` 里那份「用编译期常量 + `gethostname()` 拼出来」的通用实现是给**别的**平台用的，Linux 目录里根本没有它。实测证据：先用 `'X'` 灌满整个结构体，再 `syscall(SYS_uname, &raw)`，回来之后剩余的 `'X'` 字节数是 **0 / 390**。

**Q4：`uname()` 传 NULL 会怎样？内核在哪里挡下来？**
A：返回 `-1`、`errno = EFAULT(14)`。有趣的是 `SYSCALL_DEFINE1(newuname, ...)` **不做 NULL 检查**，是 `copy_to_user(name, &tmp, sizeof(tmp))` 失败后 `return -EFAULT` 挡下来的（`kernel/sys.c:1306-1321`）。同文件 `:1331` 的 `uname` / `olduname` 才是显式判 NULL 的版本。

**Q5：`uname().nodename` 和 `gethostname()` 会不会不一致？**
A：**不可能不一致**——因为 glibc 的 `gethostname()` 就是先调 `__uname()`，再从结果里 `memcpy` 出 `nodename` 段（`sysdeps/posix/gethostname.c:26-46`）。这是**实现决定**的，不是巧合。两者差别在可移植性：`gethostname()` 是 POSIX，`uts.domainname` 是 GNU 扩展。

**Q6：`gethostname(name, 2)` 会截断成 `"ce"` 并返回 0 吗？**
A：**不会**。实测返回 `-1`、`errno = ENAMETOOLONG(36)`，而且缓冲里留下的是**没有 NUL 终止**的两个裸字节 `63 65`（`'c' 'e'`），后面还是缓冲原有的 `'Z'` 填充。此时把它当 C 字符串 `printf` 出去会一路读过界。给 `len >= 3` 才返回 0 并写好终止符。

**Q7：那我要写跨平台的代码，`gethostname` 缓冲该给多大？**
A：给 `sysconf(_SC_HOST_NAME_MAX)` 字节，本机实测是 **64**（正好等于 `__NEW_UTS_LEN`）。然后**仍然检查返回值**——因为 POSIX 允许某些实现「截断并返回 0」，那时返回值查不出问题，只有「给足 64」这一条能保底。

**Q8：为什么 `domainname` 是 `"(none)"`？是读失败了吗？**
A：不是。`include/linux/uts.h:17` 里有 `#define UTS_DOMAINNAME "(none)"`，`init_uts_ns` 初始化时就把这个字面量填进去了。它是 **NIS 时代**的遗留概念（与 DNS 域名无关），现代系统不用 NIS，所以一直是初值。改它要 `setdomainname(2)` + `CAP_SYS_ADMIN`。

**Q9：启动日志里该不该用 `uname().release` 判断某个新 API 可不可用？**
A：**不该**。发行版会把补丁回填进旧版本号、容器可以伪装 `release`（`unshare -u` + `sethostname`），比版本号本身就不可靠。正确做法是**直接试**——调用那个 API，看 `errno` 是不是 `ENOSYS`。
