# 34.2 Process Groups

> 本章：[TLPI 第 34 章 — Process Groups and Sessions](./README.md)

## 本节讲什么

介绍进程组（Process Group）概念：一组相关进程的集合，用于信号投递和作业控制。涵盖 `setpgid()`/`getpgid()`/`getpgrp()` API。

## 要点

### 进程组概念

| 概念 | 说明 |
|------|------|
| **进程组** | 一组相关进程的集合，有一个 PGID（= 组长 PID） |
| **组长** | PID == PGID 的进程 |
| **生命周期** | 从创建到组内最后一个进程终止（组长不必最后退出） |
| **用途** | 信号投递（`killpg`）、作业控制、控制终端管理 |

### 核心 API

| 函数 | 原型 | 说明 |
|------|------|------|
| `setpgid(pid, pgid)` | `int setpgid(pid_t pid, pid_t pgid)` | 设置进程的 PGID |
| `getpgid(pid)` | `pid_t getpgid(pid_t pid)` | 获取进程的 PGID |
| `getpgrp()` | `pid_t getpgrp(void)` | 获取当前进程组 ID |
| `killpg(pgid, sig)` | `int killpg(pid_t pgid, int sig)` | 向进程组发信号 |

### setpgid 规则

```c
setpgid(pid, pgid);
```

| 场景 | 行为 |
|------|------|
| pid=0 | 作用于调用者自身 |
| pgid=0 | 将 PGID 设为 pid（创建新组，自身为组长） |
| pid != 调用者 | 只能设置子进程的 PGID，且子进程未 exec |
| 已是会话组长 | EPERM |
| 已 exec 的子进程 | EACCES |

### 典型用法：Shell 作业控制

```c
/* Shell 为每个命令创建进程组 */
pid_t pid = fork();
if (pid == 0) {
    /* 子进程：将自己放入新进程组 */
    setpgid(0, 0);  /* PGID = PID */
    execvp(cmd, argv);
    _exit(127);
}
/* 父进程（Shell）也设置子进程的 PGID */
setpgid(pid, pid);  /* 避免竞态：父子都设置 */
```

### 信号投递到进程组

```c
/* 向整个进程组发信号 */
killpg(pgid, SIGTERM);
/* 等价于 */
kill(-pgid, SIGTERM);
```

## HFT / 嵌入式关联

- **进程管理**：HFT 多进程部署用进程组统一启停（killpg 发 SIGTERM 优雅关闭）
- **服务化**：systemd 用 cgroup + 进程组管理服务进程
- **嵌入式**：较少使用进程组，通常单进程或固定父子结构
- **信号投递**：Ctrl-C 发送给前台进程组的所有进程

## 代码示例

```c
#include "tlpi_hdr.h"
#include <signal.h>

int main(void) {
    pid_t pid = fork();
    if (pid == 0) {
        /* 子进程创建新进程组 */
        setpgid(0, 0);
        printf("child: pid=%d pgid=%d\n", (int)getpid(), (int)getpgrp());
        sleep(5);
        _exit(0);
    }
    /* 父进程也设置（竞态防护） */
    setpgid(pid, pid);
    printf("parent: pid=%d pgid=%d\n", (int)getpid(), (int)getpgrp());
    printf("child pgid=%d\n", (int)pid);

    sleep(2);
    /* 向子进程组发信号 */
    killpg(pid, SIGTERM);
    wait(NULL);
    return 0;
}
```

## 代码自测

<details>
<summary>1. 为什么父进程和子进程都要调用 setpgid？</summary>

`fork()` 后父子进程执行顺序不确定。如果只有子进程调用 `setpgid`，父进程在子进程执行 `setpgid` 之前就访问了子进程的 PGID，可能得到旧的值。父子都调用 `setpgid(pid, pid)` 是幂等的——无论谁先执行，结果都是子进程在新进程组中。这是竞态防护的标准模式。
</details>

<details>
<summary>2. 进程组组长退出后，进程组还存在吗？</summary>

是的。进程组在组内最后一个进程退出后才消失。组长退出不影响其他组成员。组长只是 PID == PGID 的进程，不承担特殊管理职责。
</details>
