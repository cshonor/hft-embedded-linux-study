# 34.8 Summary

> 本章：[TLPI 第 34 章 — Process Groups and Sessions](./README.md)

## 本章回顾

### 概念层次

```
会话 (Session)
 └─ 进程组 (Process Group)
     └─ 进程 (Process)
```

### API 速查

| 函数 | 功能 |
|------|------|
| `setpgid(pid, pgid)` | 设置进程组 |
| `getpgid(pid)` / `getpgrp()` | 获取进程组 |
| `setsid()` | 创建新会话（脱离控制终端） |
| `getsid(pid)` | 获取会话 ID |
| `killpg(pgid, sig)` / `kill(-pgid, sig)` | 向进程组发信号 |
| `tcgetpgrp(fd)` / `tcsetpgrp(fd, pgid)` | 获取/设置前台进程组 |
| `tcgetsid(fd)` | 获取控制终端的会话 ID |

### 会话与控制终端

| 概念 | 说明 |
|------|------|
| **会话** | 一组进程组的集合 |
| **会话首进程** | 调用 `setsid()` 的进程 |
| **控制终端** | 会话首进程打开的第一个终端设备 |
| **前台进程组** | 接收终端输入的进程组 |
| **后台进程组** | 不接收终端输入的进程组 |
| **SIGHUP** | 控制终端断开时发给会话首进程或前台进程组 |

### setsid 行为

```c
pid_t sid = setsid();
```

| 行为 | 说明 |
|------|------|
| 新会话 | 调用者成为会话首进程 |
| 新进程组 | 调用者成为进程组长 |
| 脱离控制终端 | 不再有关联终端 |
| 失败条件 | 调用者是进程组长 → EPERM |

### 信号与终端

| 事件 | 信号 | 目标 |
|------|------|------|
| Ctrl-C | SIGINT | 前台进程组所有进程 |
| Ctrl-Z | SIGTSTP | 前台进程组所有进程 |
| Ctrl-\ | SIGQUIT | 前台进程组所有进程 |
| 终端断开 | SIGHUP | 会话首进程或前台进程组 |
| 后台进程读终端 | SIGTTIN | 读终端的后台进程 |
| 后台进程写终端 | SIGTTOU | 写终端的后台进程（若设了 TOSTOP） |

### daemon 化流程（Ch37）

```
1. fork() → 父进程 exit（脱离 shell）
2. setsid()（创建新会话）
3. fork() → 父进程 exit（不再是会话首，不能再获终端）
4. chdir("/")（避免占用目录）
5. umask(0)
6. 关闭所有 fd（或重定向到 /dev/null）
```

## HFT / 嵌入式关联

- **服务进程管理**：HFT 服务用 `setsid()` 脱离终端成为 daemon
- **进程组启停**：运维脚本用 `killpg` 统一关闭一组 HFT 进程
- **systemd**：现代 Linux 用 systemd 管理服务，自动处理会话/进程组/cgroup
- **嵌入式**：裸机无进程组概念；嵌入式 Linux 服务可用 `setsid()` daemon 化

## 代码自测

<details>
<summary>1. setsid 为什么不能在进程组长中调用？</summary>

`setsid` 的目的是创建新会话并脱离控制终端。进程组长已经是一个进程组的组长，如果允许它创建新会话，会导致同一进程组跨越两个会话，违反进程组从属于会话的层级规则。因此 POSIX 规定进程组长调用 setsid 返回 EPERM。标准 daemon 化先 fork，确保子进程不是组长。
</details>

<details>
<summary>2. SIGHUP 在什么情况下发送？</summary>

1. **控制终端断开**：如关闭终端窗口或 SSH 断开，内核向会话首进程或前台进程组发 SIGHUP
2. **会话首进程退出**：内核向前台进程组发 SIGHUP

daemon 脱离控制终端后不会收到 SIGHUP，这也是 daemon 化的目的之一。许多服务用 SIGHUP 作为"重新加载配置"信号，因为正常运行中不会收到它。
</details>
