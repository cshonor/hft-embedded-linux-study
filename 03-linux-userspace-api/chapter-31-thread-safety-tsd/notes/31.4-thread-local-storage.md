## 本节讲什么

1. **`__thread` 用法与限制**——一条关键字把全局/静态变量变成"每线程一份"；只能修饰编译期已知、可用常量初始化的变量。
2. **它为什么快**——x86-64 上 TLS 变量通过 **FS 段基址**寻址（一条 mov 搞定，可内联），对比 TSD 的函数调用查表；本节有实测反汇编和实测计时。
3. **内核在哪参与**——内核不实现 TLS API，但 `clone(CLONE_SETTLS)` 为每个新线程设置 FS base；本节把 glibc → 系统调用 → `wrmsr/wrfsbase` 的完整链路核到 v6.6 源码。

## 一、用法与限制

```c
__thread int x;                       /* GCC 扩展（TLS 诞生于此）*/
_Thread_local int y;                  /* C11 标准（等价，优先用于新代码）*/
static __thread char buf[256];        /* static 也可以 */
__thread struct ctx *g_ctx = NULL;    /* 指针可以（NULL 是常量）*/
```

四条硬限制：

| # | 限制 | 原因 |
|---|------|------|
| 1 | 只能修饰**全局或静态**变量（块内 auto 不行）| TLS 模型要求变量在链接期就分配进每线程镜像 |
| 2 | 初始化必须是**编译期常量**（或默认零）| 模板在创建线程时 memcpy，没有"跑代码"的机会 |
| 3 | C 的 `__thread` 变量**没有析构器**（与 TSD 最大差别）| 退出时模板怎么来的怎么丢；堆指针要自己收（C++ 的 thread_local 有动态初始化和析构）|
| 4 | 取地址 `&x` 合法——地址**每线程不同**，但只在取它的线程生命周期内有效 | 传给别的线程 = 传了一个悬挂语义的指针（数据是那线程的副本，但它退出后失效）|

初始化限制的破解法：`__thread struct ctx *ctx;` + 惰性 `if (!ctx) ctx = init();`——指针本身零初始化，指向的对象按需构造（这就是"TLS 放指针、堆放本体"的 HFT 标准姿势，也顺带绕开限制 2 和 3）。

## 二、为什么快：FS 段基址寻址

### 2.1 原理图

x86-64 上，每个线程有一个专属的 **FS 基址**（FSB ASE 寄存器，多数实现走 MSR 或 `wrfsbase` 指令），指向本线程的 TCB（Thread Control Block，glibc 的 `struct pthread`，见 29.8：它就在线程栈底）。TLS 变量的地址 = **FS 基址 + 编译期偏移**：

```
   线程 A                                线程 B
   FS base ──┐                           FS base ──┐
             ▼                                      ▼
   ┌─────────────────┐                 ┌─────────────────┐
   │ struct pthread   │                 │ struct pthread   │
   │ (TCB)            │                 │ (TCB)            │
   ├─────────────────┤                 ├─────────────────┤
   │ TLS 模板副本      │                 │ TLS 模板副本      │
   │  my_counter @-8  │◄── 偏移固定      │  my_counter @-8  │
   │  err_buf  @-264 │                 │  err_buf  @-264 │
   └─────────────────┘                 └─────────────────┘
   访问 my_counter：                    访问 my_counter：
   mov %fs:-8, %eax                     mov %fs:-8, %eax
   （同一条指令，不同线程的 FS → 不同内存）
```

**同一条指令，因 FS 不同而落到不同内存**——这就是"零运行时查找成本"的全部秘密：偏移在链接期定死，基址在硬件里。

### 2.2 实测反汇编

源码：

```c
int global_counter;              /* 外部链接：gcc 不能折叠加载 */
__thread int tls_counter;

int read_global(void){ return global_counter; }
int read_tls   (void){ return tls_counter;   }
```

`gcc -O2 -S` 实测输出（WSL gcc）：

```asm
read_global:
        movl    global_counter(%rip), %eax     ; RIP 相对寻址：普通全局，所有线程同一地址
        ret

read_tls:
        movl    %fs:tls_counter@tpoff, %eax    ; ⭐ FS 段前缀 + 链接期偏移：每线程不同地址
        ret
```

`%fs:` 前缀 + `@tpoff`（thread pointer offset）就是 TLS 的机器级形态。

顺带解剖 `errno` 的两层：

```asm
;; 你的代码里：errno 宏展开成一次函数调用（errno 在 libc 的 TU 里，跨 TU 看不见）
        call    __errno_location@PLT
        movl    (%rax), %eax
;; libc 自己的 TU 里（模拟同 TU 编译 __errno_location）：
        movq    __libc_errno@gottpoff(%rip), %rax   ; GOT 里取偏移（initial-exec 模型）
        addq    %fs:0, %rax                          ; + FS 基址 → 本线程的 errno 地址
```

所以准确说法是：**errno 的实际存储访问（在 libc 内部）是 `%fs` 段寻址；你的代码经过一次 PLT 调用拿到地址**。这也解释了为什么频繁读 errno 的热路径可以先把 `errno` 存进局部变量——省掉的是 PLT 调用那层，而不是 TLS 本身（TLS 那层本来就免费）。

### 2.3 实测计时：TLS vs TSD vs 全局

| 访问方式 | 实测（每线程 1 亿次读，ns/次）| 机制 |
|----------|------|------|
| 普通全局 | ~0.4 | RIP 相对寻址（还能被缓存进寄存器）|
| `__thread` TLS | ~0.5 | `%fs:偏移` 寻址，可内联可缓存 |
| `pthread_getspecific` | ~2.0 | 函数调用 + 二级数组查表 |
| `pthread_getspecific` + once | ~2.0 | once 完成态只多一条原子读 |

（量级参考：TLS 与普通全局几乎同价，TSD 慢约一个函数调用——**热路径上 TLS 免费原则成立**。）

### 2.4 TLS 四种链接模型（链接器自动选择，读 ELF 时会遇见）

| 模型 | 场景 | 成本 |
|------|------|------|
| local-exec | 可执行文件自己的变量 | 最快：`%fs:偏移` 一条指令 |
| initial-exec | 主程序加载时就确定（含启动期加载的 .so）| 快：GOT 里一次间接 |
| local-dynamic | 同一 .so 内多个变量共享一个偏移块 | 中：调 `__tls_get_addr` |
| global-dynamic | dlopen 运行时才加载的 .so 里的 TLS | 最慢：每次 `__tls_get_addr` 查 DTV |

工程含义：**dlopen 一个大量使用 TLS 的 .so，不仅它的 TLS 访问走最慢模型，还要消耗"静态 TLS 剩余额度"**——额度耗尽时 dlopen 直接失败（`cannot allocate memory in static TLS block`）。这是动态加载策略插件的 HFT 系统踩过的真实坑：插件要么少用 `__thread`，要么编译时 `-ftls-model=global-dynamic` 显式走慢路径换取可加载性。

## 三、内核侧链路（v6.6 核验）

内核不认识 `__thread`——TLS 的**创建**由 glibc 与内核协作完成：

```
pthread_create
  └─ glibc: 分配线程栈 + TLS 模板副本 + TCB(struct pthread)
  └─ clone(CLONE_VM|CLONE_THREAD|...|CLONE_SETTLS, tls=TCB地址)
       └─ kernel/fork.c: kernel_clone()
            └─ copy_process()
                 └─ arch/x86/kernel/process.c: copy_thread():159
                      · :184  p->thread.fsbase = current->thread.fsbase  ← 先继承父线程
                      · :254  if (clone_flags & CLONE_SETTLS)
                                 ret = set_new_tls(p, tls);               ← 再被新值覆盖
                           set_new_tls():130
                            └─ do_set_thread_area_64(p, ARCH_SET_FS, tls):137
                                 └─ x86_fsbase_write_task(p, tls)  ← 写进新任务的 thread 结构
  （新线程第一次被调度上 CPU 时，switch_to 会装载它的 FS base）
  （运行时改 FS base 的通用入口：arch_prctl(ARCH_SET_FS) → process_64.c:828，
   preempt_disable → selector 清 0 → wrfsbase/wrmsrl → preempt_enable）
```

两个细节：

1. **`copy_thread():184` 先继承 fsbase、`:254` 再被 CLONE_SETTLS 覆盖**——没传 SETTLS 的 clone（比如普通 fork）子进程继承父的 FS base 值，但注意 fork 出的新进程有自己的 mm 和新的 TLS 块，这个继承值在单线程子进程里语义无害；真正的每线程差异完全由 SETTLS 路径决定。
2. **`ARCH_SET_FS:828` 里的 `preempt_disable()`**：改段寄存器/FSB ASE 必须在不可抢占区完成（防止改到一半被切走，别的代码用错基址）；`selector 清 0` 是 FSGSBASE 时代的规范做法（基址全权交给 fsbase，段选择器退位）。

### 3.1 TLS 变量的初始化时机（把三条链拼起来）

1. 程序启动：动态链接器把所有 TLS 变量收进**模板**（.tdata 有初值 / .tbss 零值）；
2. `pthread_create`：glibc 为新线程栈分配 TLS 块，`memcpy` 模板（这一步在用户态完成，"每线程一份初值"由此而来）；
3. `clone(CLONE_SETTLS)`：内核把 FS base 指向它；
4. 此后该线程的每一次 `my_var` 访问 = `%fs:偏移`。

主线程的 TLS 块在程序加载时由动态链接器静态安置（栈头附近），不走 clone。

## 四、TSD vs TLS 终极对比表（本章收口）

| 维度 | TSD（`pthread_key_*`）| TLS（`__thread`/`_Thread_local`）|
|------|----------------------|----------------------------------|
| 声明方式 | 运行时 create | 编译期关键字 |
| 数据类型 | 只能放 `void*` | 任意类型 |
| 初始化 | 运行时惰性（getspecific==NULL 判据）| 仅编译期常量（指针+惰性构造绕行）|
| 析构 | destructor 原生支持（4 轮上限）| C：无；C++：thread_local 有 |
| 数量上限 | 1024 keys | 链接期 TLS 块大小（远大于实际需要）|
| 访问成本 | 函数调用查表（~2 ns）| 一条段寻址（~0.5 ns，可内联）|
| dlopen 兼容 | 完全兼容 | initial-exec 额度可能耗尽 → 加载失败 |
| 谁在内核 | 无（纯用户态）| clone(CLONE_SETTLS) + FS base |
| 典型场景 | 老接口改造（strerror 范式）| 新代码的每线程上下文（HFT 默认）|

---

## HFT / 嵌入式关联

| 路线 | 要点 |
|------|------|
| HFT · 标准姿势 | `static __thread struct engine_ctx *ctx;`——TLS 放指针（零初始化免费），堆放本体（启动时构造）；热路径访问 `ctx->field` 全部内联成一条 FS 寻址 + 一次间接寻址 |
| HFT · 一核一线程 | 每线程上下文（订单簿视图、内存池、统计槽）全进 TLS，跨线程零共享 = 零锁零伪共享；再把线程钉核（29.8），上下文永驻该核 L1/L2 |
| HFT · 插件 | dlopen 型策略插件的 `__thread` 用量要审计（§2.4 静态 TLS 额度问题）；或插件接口显式传 ctx 指针，不用 TLS |
| 嵌入式 · 工具链 | `__thread` 需要 TLS 重定位 + 运行时支持：Linux 用户态齐全；裸机（无 MMU/no libc）看工具链（GCC 支持 emutls 软件模拟，但慢且占 ROM）；RTOS 上 pthread 库（如 Zephyr/FreeRTOS+POSIX 层）通常同时提供 TSD 与 TLS |
| 嵌入式 · 每中断一份 | 中断上下文也可以借 TLS 思想：每 IRQ 一块静态上下文 + 索引寻址，与线程上下文物理隔离（数据竞争设计的"空间换同步"通用套路）|

## 代码示例

`tls_demo.c`（gcc -O2 -Wall -Wextra 零告警编译通过）：

```c
/* tls_demo.c — Ch31.4：每线程地址不同、TLS vs TSD 计时、TLS 放指针范式
 * 编译：gcc -O2 -Wall -Wextra -o tls_demo tls_demo.c -pthread
 */
#define _GNU_SOURCE
#include <stdio.h>
#include <stdlib.h>
#include <pthread.h>
#include <time.h>
#include <stdint.h>

static double now_ns(void){struct timespec t;clock_gettime(CLOCK_MONOTONIC,&t);
    return t.tv_sec*1e9+t.tv_nsec;}

/* ---------- 演示 1：地址每线程不同 ---------- */
static __thread int tls_counter = 100;          /* 带初值：每线程都从 100 开始 */
static int global_counter = 100;                /* 对照：全进程共享 */

static void *addr_worker(void *a){
    (void)a;
    tls_counter += (int)(intptr_t)a;            /* 只改自己那份 */
    printf("[demo1] 线程%ld: &tls_counter=%p tls_counter=%d | "
           "&global_counter=%p global_counter=%d\n",
           (long)(intptr_t)a, (void*)&tls_counter, tls_counter,
           (void*)&global_counter, global_counter);
    return NULL;}

static void demo_addr(void){
    pthread_t t1, t2;
    pthread_create(&t1, NULL, addr_worker, (void*)(intptr_t)1);
    pthread_join(t1, NULL);
    pthread_create(&t2, NULL, addr_worker, (void*)(intptr_t)2);
    pthread_join(t2, NULL);
    printf("[demo1] 主线程: tls_counter=%d（仍是初值 100）| "
           "global_counter=%d\n", tls_counter, global_counter);
}

/* ---------- 演示 2：TLS 放指针（绕开"仅常量初始化"限制）---------- */
typedef struct { long id; char pad[64]; } engine_ctx;   /* 大块头上下文 */
static __thread engine_ctx *ctx = NULL;         /* 零初始化 ✓ */

static void *ctx_worker(void *a){
    if (!ctx) {                                  /* 惰性构造：每线程一次 */
        ctx = malloc(sizeof *ctx);
        ctx->id = (long)(intptr_t)a;
    }
    printf("[demo2] 线程%ld 的 ctx=%p（堆本体，每线程一个）\n", ctx->id, (void*)ctx);
    free(ctx);                                   /* C 的 __thread 无析构，自己收 */
    return NULL;}

/* ---------- 演示 3：TLS vs TSD 计时 ---------- */
static __thread int tls_hot;
static pthread_key_t tsd_key;

#define LOOPS 100000000L
static void *bench_worker(void *a){(void)a;
    /* ⭐ TSD 是每线程的：必须在 worker 自己的格子里设值。
     * 若在 main 里 setspecific，worker 的 getspecific 拿到的是 NULL（空指针解引用）。 */
    pthread_setspecific(tsd_key, &tls_hot);
    volatile int sink = 0;
    double t0 = now_ns();
    for (long i = 0; i < LOOPS; i++) sink += tls_hot;
    double t1 = now_ns();
    for (long i = 0; i < LOOPS; i++) sink += *(int*)pthread_getspecific(tsd_key);
    double t2 = now_ns();
    printf("[demo3] %ld 次读取：TLS %6.2f ns/次 | TSD(getspecific) %6.2f ns/次 | "
           "比 %.1fx\n", LOOPS, (t1-t0)/LOOPS, (t2-t1)/LOOPS,
           (t2-t1)/(t1-t0));
    (void)sink;
    return NULL;}

int main(void){
    printf("==== 演示 1：地址每线程不同 ====\n");
    demo_addr();
    printf("==== 演示 2：TLS 放指针 ====\n");
    pthread_t t2; pthread_create(&t2, NULL, ctx_worker, (void*)(intptr_t)7);
    pthread_join(t2, NULL);
    printf("==== 演示 3：TLS vs TSD 计时 ====\n");
    pthread_key_create(&tsd_key, NULL);
    pthread_t t3; pthread_create(&t3, NULL, bench_worker, NULL);
    pthread_join(t3, NULL);
    pthread_key_delete(tsd_key);
    return 0;
}
```

实测输出（WSL2 / 12 核；地址与耗时随机器浮动）：

```text
==== 演示 1：地址每线程不同 ====
[demo1] 线程1: &tls_counter=0x76df061ff6a8 tls_counter=101 | &global_counter=0x61d248f4b010 global_counter=100
[demo1] 线程2: &tls_counter=0x76df061ff6a8 tls_counter=102 | &global_counter=0x61d248f4b010 global_counter=100
[demo1] 主线程: tls_counter=100（仍是初值 100）| global_counter=100
==== 演示 2：TLS 放指针 ====
[demo2] 线程7 的 ctx=0x76df00000b70（堆本体，每线程一个）
==== 演示 3：TLS vs TSD 计时 ====
[demo3] 100000000 次读取：TLS   0.52 ns/次 | TSD(getspecific)   2.14 ns/次 | 比 4.1x
```

四点解读：

1. demo1：`&global_counter` 全进程同一个地址；两线程的 `tls_counter` **值互不影响**（101 和 102，主线程仍是初值 100）——每线程一份的语义成立。
2. demo1 细节（关键）：两个线程的 `&tls_counter` **地址完全相同**（0x76df061ff6a8）！因为线程 1 先 join 退出，线程 2 创建时 glibc 复用了同一块缓存栈（29.8 的 `alloc_thread_stack_node` 缓存复用），TLS 块就在栈里，自然同一地址——**TLS 地址 = 线程生命周期，不是全局唯一 ID**，跨线程传 `&tls_var` 必悬挂（29.5 的 `pthread_t` 复用同源）。
3. demo2：`__thread` 指针零初始化 + 惰性 malloc——绕开"仅常量初始化"限制的标准姿势；C 的 TLS 无析构，自己 free。
4. demo3：TLS 读取 0.52 ns（可被循环流水化）vs getspecific 2.14 ns（函数调用不可内联）——**热路径选 TLS 的量化依据**（~4 倍）。
