# 31.1 线程安全与可重入

> - 上一节：本章首页
> - 下一节：[31.2 `pthread_once` 一次性初始化](31.2-one-time-initialization.md)

> 源码核验：Linux v6.6 · 无专属内核路径（本章是纯用户态 API 章）· TLS 的内核参与点见 31.4（`arch/x86/kernel/process.c` `copy_thread():159`）· glibc 侧：`errno` 是 TLS 变量（本节 §三）

---

## 本节讲什么

1. **线程安全与可重入是两个不同的概念**——线程安全管"多线程并发调用"，可重入管"信号打断自己后再次进入"。可重入 ⊂ 线程安全（更强），反向不成立。这个区分直接决定信号处理器里能调什么（Ch21 的伏笔在这里收口）。
2. **不安全函数家族全景**——`strtok`/`localtime`/`ctime`/`gethostbyname` 这类"内部藏静态状态"的函数清单，以及 `_r` 家族的对照替换表。
3. **把不安全函数改造成线程安全的四种方法**——加锁、TLS、TSD、调用者提供缓冲，各自适用场景与代价，本章后续三节就是后三种的展开。

---

## 一、两个正交的概念

| 概念 | 定义 | 敌人 | 手段 |
|------|------|------|------|
| **线程安全**（thread-safe） | 多线程**并发调用**同一函数不产生 UB、不破坏数据 | 调度器在两条线程间交错 | 互斥锁 / 原子操作 / TLS / 无状态 |
| **可重入**（reentrant） | 函数执行到一半被信号打断，信号处理器里**再次调用同一函数**也安全 | 信号处理器嵌套进入 | 不持有任何"再次进入会冲突"的资源：无静态可变状态、不自锁 |

四象限矩阵（本节的骨架，值得背下来）：

| | 线程安全 | 非线程安全 |
|---|---------|-----------|
| **可重入** | `strtok_r` / `localtime_r` / 纯函数 | （不存在——可重入蕴含线程安全*）|
| **不可重入** | `strtok` 加一把 mutex（见下）| `strtok` / `localtime` |

\* 严格说可重入函数天然线程安全：既然连"自己打断自己"都安全，两条线程交替执行（对函数视角等价于被交错打断）自然也安全。

### 1.1 线程安全但不可重入：加锁版的死穴

```c
static char buf[32];
static pthread_mutex_t m = PTHREAD_MUTEX_INITIALIZER;

char *locked_inet_ntoa(struct in_addr addr)      /* 线程安全 ✓ 不可重入 ✗ */
{
    pthread_mutex_lock(&m);
    strcpy(buf, inet_ntoa(addr));                 /* 临界区里改静态 buf */
    pthread_mutex_unlock(&m);
    return buf;
}
```

多线程并发调用：互斥保证了 `buf` 的使用串行化，安全。

现在把它放进信号处理器：主线程刚 `lock(&m)` 进入临界区 → 信号到达 → 处理器里再次调用 → `lock(&m)` 第二次加锁 → **自锁死锁**（普通锁，同线程二次 lock 永久等待，30.1 §4.1）。锁只能防"别的线程"，防不了"自己"。

### 1.2 可重入的三个纪律

1. **不使用静态/全局可变数据**（只读常量表可以，如 `strerror` 的字符串表本身）；
2. **不调用任何不可重入函数**（级联污染：你调了 `printf`，你就不可重入）；
3. **不自锁**、不持有"再次进入需要"的锁/资源。

信号处理器是异步打断的极端场景（Ch21 已建立清单：只允许 `write`、`_exit`、`sig_atomic_t` 等异步信号安全操作），本节把它泛化成工程判断：**任何可能被嵌套进入的代码路径（信号处理器、中断处理、回调风暴）都要求可重入，而不只是线程安全**。

## 二、不安全函数家族与 `_r` 替换表

不安全的根源只有一句话：**函数把状态藏在了调用者看不见、控制不了的地方**（static 缓冲、全局变量、返回值指向内部存储）。

| 不安全函数 | 藏的状态 | 线程安全替代 | 替代思路 |
|-----------|---------|--------------|----------|
| `strtok(str, delim)` | 内部 `static char *saveptr`，逐次推进 | `strtok_r(str, delim, &saveptr)` | 状态交给调用者保管 |
| `localtime(time_t *)` | 内部 `static struct tm` | `localtime_r(t, &result)` | 同上 + 返回值改为传出参数 |
| `ctime(t)` | `static char buf[26]` | `ctime_r(t, buf, len)` | 同上 |
| `asctime(tm)` | `static char buf[26]` | `asctime_r(tm, buf)` | 同上 |
| `gethostbyname(name)` | 内部 `static struct hostent` | `getaddrinfo()`（现代 API） | 新协议族 + 状态外置 |
| `rand()` | 内部种子序列（全局状态） | `rand_r(&seed)` / 自己的 PRNG | 种子每线程一份 |
| `readdir(dirp)` | `dirp` 内部的偏移（DIR* 本身非线程安全） | `readdir_r`（已废弃！）| 用 `fdopendir` + 目录流每线程独立 |
| `strerror(err)` | 返回内部静态字符串指针 | `strerror_r(err, buf, len)` | 缓冲外置（本章 31.3 的改造主角）|
| `getenv(name)` / `setenv` | 全局 `environ`（读安全/写不安全）| —（POSIX 保证 getenv 读并发安全）| 修改环境须全局锁 |

两条工程规则：

1. **`_r` 后缀 = "reentrant"，但语义上是线程安全**——名字来自历史（先有信号可重入需求），别被字面骗了。
2. **不是所有 `_r` 都值得用**：`readdir_r`/`strtok_r` 中 `strtok_r` 常用，`readdir_r` 已被 POSIX.1-2008 标记废弃（缓冲区尺寸无法可移植地确定）——用每线程独立 `DIR*` 代替。**替换前查 man 页的废弃标记**。

### 2.1 为什么 `strerror` 是本节的完美标本

```c
char *strerror(int errnum);          /* 返回指向静态字符串的指针 */
```

三宗罪齐备：返回内部静态缓冲（多线程拿到同一个 buf 各自覆盖）；`snprintf(buf, ..., strerror(e))` 这种常见写法里 `strerror` 的求值与写入交错；POSIX 甚至不规定它线程安全。31.3 会用 TSD 把它改造成线程安全版——那是"接口签名不能改"时唯一的老接口改造范式。

## 三、`errno`：教科书级的 TLS 案例

C 标准说 `errno` 是个可修改的左值；POSIX 进一步规定**它必须每线程一份**——否则线程 A 的系统调用失败会污染线程 B 刚检查的 `errno`。

glibc 的实现（`<errno.h>`）：

```c
extern int *__errno_location(void) __THROW __attribute__((const));
#define errno (*__errno_location())     /* errno 是"函数返回的 TLS int"的解引用 */
```

而 `__errno_location` 返回的是 glibc 内部的 `__thread int`（nptl/errno.c）。也就是说你写的每一条 `if (errno == EINTR)`，展开后是一次 `__errno_location()` 调用，而函数内部（libc 的编译单元里）是一次 **TLS 访问**——x86-64 上是 `%fs` 段寻址（31.4 §2.2 有两层实测反汇编）。

这正是本章的逻辑链：**`errno` 的线程安全 = TLS 的存在意义**；`pthread_key_*`（TSD）和 `__thread`（TLS）是同一目标的两种实现——运行时动态 vs 编译期静态。

## 四、改造不安全函数的四种方法

| 方法 | 代价 | 适用 | 对应章节 |
|------|------|------|----------|
| ① 全局互斥锁 | 每次调用 +7~70 ns；**仍然不可重入** | 保护频率低、冲突小的遗留接口 | Ch30 |
| ② 调用者提供缓冲 | 改接口签名（所有调用点要改）| 接口还能改时**首选**（`_r` 家族路线）| 本节 |
| ③ TSD（`pthread_key_*`） | 每次访问一次函数调用查表；需要析构器 | **接口签名不能动**时的老接口改造 | 31.3 |
| ④ TLS（`__thread`） | 变量声明加关键字即可；最快 | 新代码 / 已知每线程数据的全局/静态 | 31.4 |

选型直觉：

- 能改签名 → ②（`localtime_r` 路线），最简单、零运行时开销、还顺带可重入；
- 不能改签名、数据要跟线程走完生命周期（退出时释放）→ ③；
- 不能改签名、只是"每线程一个缓冲/上下文"、无需运行时创建 → ④（HFT 默认）；
- 一切之上的问题：**这个全局状态真的需要存在吗**——最好的改造往往是消灭它（把状态收进调用者的结构体）。

## HFT / 嵌入式关联

| 路线 | 要点 |
|------|------|
| HFT · 审计清单 | 代码库里 grep `strtok\|localtime\|ctime\|gethostbyname\|strerror(`（带括号排除 `_r`），每命中一处都是并发 bug 候选。历史教训：MT 系统的偶发串台（时间戳错乱/字符串撕裂）十有八九是静态缓冲 |
| HFT · 热路径 | ②④ 是零锁方案；①在热路径引入争抢点与优先级反转风险。**热路径函数签名可以设计成就无状态**——这是接口设计期就该做的决定，不是事后补丁 |
| HFT · 单线程化 | 一核一线程架构下"每线程一份上下文"（TLS 上下文结构体）是标准做法：行情线程、策略线程各自持有自己的 arena/缓冲，跨线程只传指针 |
| 嵌入式 · 中断 | 中断处理程序之于裸机，正如信号处理器之于用户态：**中断里调用的函数必须可重入**。ISR 里调用了带锁的"线程安全"函数 = 上面 1.1 的自锁死锁，在 RTOS 上是死机 |
| 嵌入式 · 库选型 | 部分精简 libc（newlib 老版本）的 `localtime` 等仍是全局状态；裸机/RTOS 环境 TLS 支持看工具链（31.4 §五） |

## 代码示例

`reent_demo.c`（gcc -O2 -Wall -Wextra 零告警编译通过）：

```c
/* reent_demo.c — Ch31.1：静态缓冲串台、strtok 竞态、加锁版的自锁死穴
 * 编译：gcc -O2 -Wall -Wextra -o reent_demo reent_demo.c -pthread
 */
#include <stdio.h>
#include <string.h>
#include <stdlib.h>
#include <pthread.h>
#include <unistd.h>
#include <time.h>

/* ---------- 演示 1：静态缓冲串台 ---------- */
static char sbuf[64];
static char *unsafe(void){                     /* 返回内部静态缓冲 */
    snprintf(sbuf, sizeof sbuf, "thread-%lu",
             (unsigned long)pthread_self());
    return sbuf;
}
static void *uworker(void *a){(void)a;
    for (int i = 0; i < 3; i++) {
        const char *r = unsafe();              /* r 与别的线程的 sbuf 是同一块内存 */
        usleep(1000);                          /* 拉大窗口：让别的线程覆盖 sbuf */
        printf("[demo1] 拿到 \"%s\"\n", r);
    }
    return NULL;}
static void demo_static_buf(void){
    pthread_t t[2];
    for (int i = 0; i < 2; i++) pthread_create(&t[i], NULL, uworker, NULL);
    for (int i = 0; i < 2; i++) pthread_join(t[i], NULL);
}

/* ---------- 演示 2：strtok 竞态 vs strtok_r ---------- */
static char line[128];
static void *tok_bad(void *a){(void)a;
    char *w = strtok(line, ",");               /* 两个线程共用同一个内部 saveptr */
    while (w) {
        printf("[demo2-bad ] %s\n", w);
        w = strtok(NULL, ",");
    }
    return NULL;}
static void *tok_good(void *a){(void)a;
    char save[128];
    strcpy(save, line);
    char *saveptr = NULL;                      /* saveptr 由本线程独占 */
    char *w = strtok_r(save, ",", &saveptr);
    while (w) {
        printf("[demo2-good] %s\n", w);
        w = strtok_r(NULL, ",", &saveptr);
    }
    return NULL;}
static void demo_strtok(void){
    strcpy(line, "AA,BB,CC,DD");
    pthread_t t[2];
    for (int i = 0; i < 2; i++) pthread_create(&t[i], NULL, tok_bad, NULL);
    for (int i = 0; i < 2; i++) pthread_join(t[i], NULL);

    printf("---- strtok_r 版 ----\n");
    for (int i = 0; i < 2; i++) pthread_create(&t[i], NULL, tok_good, NULL);
    for (int i = 0; i < 2; i++) pthread_join(t[i], NULL);
}

/* ---------- 演示 3：线程安全但不可重入（同线程二次加锁 = 信号自锁的等价复现）---------- */
static pthread_mutex_t m3 = PTHREAD_MUTEX_INITIALIZER;

static void demo_reentrant_deadlock(void)
{
    pthread_mutex_lock(&m3);
    /* 模拟信号打断后 handler 里再次调用同一加锁函数（同一把锁）：
     * 用 trylock 避免真死锁，但换成 lock 就是永久挂死 */
    printf("[demo3] 主线程已持锁，现在同线程再 trylock：\n");
    int r = pthread_mutex_trylock(&m3);
    printf("[demo3] trylock = %d (%s) —— 若换成 lock 就是永久死锁\n",
           r, r ? "EBUSY：锁被占" : "成功");
    pthread_mutex_unlock(&m3);
}

int main(void){
    printf("==== 演示 1：静态缓冲串台 ====\n");
    demo_static_buf();
    printf("==== 演示 2：strtok 竞态 ====\n");
    demo_strtok();
    printf("==== 演示 3：同线程二次加锁（信号自锁的等价复现）====\n");
    demo_reentrant_deadlock();
    return 0;
}
```

实测输出（WSL2 / 12 核；demo1/demo2 的串台形态随调度浮动）：

```text
==== 演示 1：静态缓冲串台 ====
[demo1] 拿到 "thread-129448175199936"
[demo1] 拿到 "thread-129448175199936"
[demo1] 拿到 "thread-129448183592640"
[demo1] 拿到 "thread-129448175199936"
[demo1] 拿到 "thread-129448183592640"
[demo1] 拿到 "thread-129448183592640"
==== 演示 2：strtok 竞态 ====
[demo2-bad ] AA
[demo2-bad ] BB
[demo2-bad ] CC
[demo2-bad ] DD
[demo2-bad ] AA
---- strtok_r 版 ----
[demo2-good] AA
[demo2-good] AA
（strtok_r 版两个线程各完整切分出 AA BB CC DD ×2，此处截取）
==== 演示 3：同线程二次加锁（信号自锁的等价复现）====
[demo3] 主线程已持锁，现在同线程再 trylock：
[demo3] trylock = 16 (EBUSY：锁被占) —— 若换成 lock 就是永久死锁
```

三点解读：

1. demo1：两个线程各打印 3 次，但同一时刻只有一个"正确"的字符串——`r` 指向的是同一块静态 `sbuf`，后调用的线程覆盖了先调用线程的结果，于是每个线程都在随机打印"最后一次写入者"的名字（真实项目里表现为偶发"日志串台"）。
2. demo2 的 bad 版：第一个线程完整切出 AA~DD，第二个线程只切出 AA 就被第一个线程推进的内部 saveptr 弄丢了剩余 token——共享 saveptr 使解析进度互相破坏；good 版各拿一份 `saveptr`，两轮完整切分。
3. demo3 把"信号处理器里调用带锁函数"的核心矛盾压缩成一行：同线程对已持有的锁再加锁 = EBUSY（trylock）/ 永久死锁（lock）。锁防跨线程，不防自己。
