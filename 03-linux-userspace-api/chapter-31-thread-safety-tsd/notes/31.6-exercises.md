## 练习题

### 练习 1：静态缓冲串台复现与修复

写 `unsafe_version()`（返回内部 static buf）和 `safe_version()`（调用者传 buf），两个线程各调 10 万次，统计"返回后被覆盖"的次数。再回答：为什么 `printf("%s", unsafe())` 这种单行写法也会串台？（提示：`unsafe()` 返回后、`printf` 读它之前，另一个线程可以跑完一整轮）

### 练习 2：`_r` 家族替换审计

给一份代码片段清单，找出全部非线程安全调用并给出替换：`strtok`、`localtime`、`ctime`、`asctime`、`gethostbyname`、`rand`、`strerror`、`readdir`（注意最后两个的替换不是简单加 `_r`）。

### 练习 3：`pthread_once` 的失败语义

`init_routine` 无参无返回。设计一个方案让 `pthread_once` 支持失败的初始化：调用方能区分"成功完成 / 初始化失败 / 尚未初始化"三态，且失败后允许重试（提示：失败时把 once 状态重置回未初始化——查 man 确认这是否合法，以及合法的实现手段）。

### 练习 4：TSD 版 `strerror` 完整落地

把 31.3 的四步范式写完整（含 `(unknown error)` 兜底与真错误消息），然后做两个破坏性实验：① 故意不配 destructor，跑 100 万个短命线程观察内存增长；② destructor 里再 setspecific，验证 4 轮上限。

### 练习 5：TLS 放指针的完整模式

实现"每线程一个 4KB 缓冲池"：`static __thread arena_t *arena;`，惰性分配，线程退出前归还（自注册 pthread_cleanup_push 或 worker 显式清理）。对比直接 `__thread arena_t arena;`（编译期就要 4KB×线程数的 TLS 块）的取舍。

### 练习 6：TLS vs TSD 基准

对 `__thread int` / `pthread_getspecific` / 普通全局各做 1 亿次读取基准（注意 volatile sink 防优化），解释三者差距的机器级原因（RIP 相对寻址 / FS 段寻址 / 函数调用查表）。

### 练习 7：`errno` 的解剖

写一个程序证明 `errno` 是每线程一份的（线程 A 设 EINTR，线程 B 读到 0）。再用 `objdump` 或 `gcc -S` 找到 `errno` 访问的 `%fs:` 指令，把 31.1 §三的结论亲手验一遍。

## 综合题：线程安全的错误报告模块（完整可运行）

需求：`const char *errfmt(int code)` 返回格式化错误串（线程安全、每线程缓冲、支持嵌套调用 `errfmt(errfmt(...))` 场景的安全分析）。参考实现：

```c
/* errfmt.c — Ch31.6 综合题：TSD+once 惰性缓冲 + 嵌套安全性分析
 * 编译：gcc -O2 -Wall -Wextra -o errfmt errfmt.c -pthread
 */
#define _GNU_SOURCE
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <stdint.h>             /* intptr_t */
#include <pthread.h>

#define EBUF_LEN 128
#define NBUF 4                      /* 每线程 4 个缓冲轮转：支持 4 层嵌套 */

static pthread_key_t ekey;
static pthread_once_t eonce = PTHREAD_ONCE_INIT;

typedef struct {
    char bufs[NBUF][EBUF_LEN];
    int  next;
} errpool_t;

static void epool_dtor(void *p){ free(p); }

static void ekey_create(void){
    pthread_key_create(&ekey, epool_dtor);        /* key 全局恰好一次 */
}

static errpool_t *my_pool(void){
    errpool_t *p = pthread_getspecific(ekey);
    if (p == NULL) {                              /* 本线程首次：惰性分配 */
        p = calloc(1, sizeof *p);
        pthread_setspecific(ekey, p);
    }
    return p;
}

/* 线程安全 + 支持最多 NBUF 层嵌套（轮转缓冲） */
const char *errfmt(int code)
{
    pthread_once(&eonce, ekey_create);
    errpool_t *p = my_pool();
    char *buf = p->bufs[p->next];
    p->next = (p->next + 1) % NBUF;               /* 下次嵌套调用用下一块 */
    snprintf(buf, EBUF_LEN, "[err %d] %s", code, strerror(code));
    return buf;
}

static void *worker(void *a){
    long id = (long)(intptr_t)a;
    /* 嵌套调用：外层 errfmt 的结果被内层 errfmt 安全地拼进 printf */
    printf("[T%ld] 嵌套：%s / 单层：%s\n",
           id, errfmt((int)id), errfmt(100 + (int)id));
    return NULL;   /* 退出 → epool_dtor 整池回收 */
}

int main(void){
    pthread_t t[3];
    for (long i = 0; i < 3; i++)
        pthread_create(&t[i], NULL, worker, (void*)(intptr_t)(i+1));
    for (int i = 0; i < 3; i++) pthread_join(t[i], NULL);
    printf("主线程直接调用：%s\n", errfmt(42));
    pthread_key_delete(ekey);      /* 演示用：进程退出前 delete（值已全空/析构过）*/
    return 0;
}
```

实测输出（WSL2 / 12 核）：

```text
[T3] 嵌套：[err 3] No such process / 单层：[err 103] Software caused connection abort
[T2] 嵌套：[err 2] No such file or directory / 单层：[err 102] Network dropped connection on reset
[T1] 嵌套：[err 1] Operation not permitted / 单层：[err 101] Network is unreachable
主线程直接调用：[err 42] No message of desired type
```

思考点（做完题再看）：

1. **为什么 NBUF=4 而不是 1**：`printf("%s", errfmt(x))` 单次调用只需要 1 块；但 `snprintf(buf, n, "%s-%s", errfmt(a), errfmt(b))` 里两个 errfmt 求值先后未知，1 块缓冲会互相覆盖（第二个覆盖第一个）。轮转缓冲让嵌套/多重求值各自拿不同块——glibc 老式 `strerror` 连这层保护都没有。
2. **轮转的边界**：超过 NBUF 层嵌套仍会覆盖最旧的——工程上按实际嵌套深度设 NBUF，或接口文档明示"返回值有效期到下一次第 N 次调用"。
3. **key_delete 放在最后**只是演示：所有线程已 join、值已析构，此时 delete 不泄漏（31.3 §2.4 的正确用法）。

## HFT / 嵌入式关联

| 路线 | 要点 |
|----|------|
| HFT | 综合题的 errpool 就是日志/风控消息格式化的标准形态：热路径禁 printf（锁 + 系统调用），先 errfmt 进 TLS/TSD 缓冲，批量刷；轮转缓冲深度 = 日志宏的最大嵌套层数（通常 2~4）|
| HFT · 嵌套陷阱 | `snprintf(buf, n, "%s: %s", my_strerror(a), my_strerror(b))` 是生产事故常客——单缓冲版两个实参共享同一块，输出只剩后者。题 1/综合题都在钉这一点 |
| 嵌入式 | 练习 5 的"TLS 放指针"在嵌入式还有一层意义：静态 TLS 块越大，每线程创建成本越高（模板 memcpy）+ ROM/内存占用线性涨；指针 + 池化是资源受限环境的常态 |
