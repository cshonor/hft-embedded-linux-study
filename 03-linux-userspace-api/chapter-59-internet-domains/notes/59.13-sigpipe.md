## 与 C 语言学习的关系

本节的 `write()` 对应 K&R 8.2 节。K&R 的 copy.c 用 `write(1, buf, n)` 输出到 stdout。注意 `write` 与 `printf`/`fprintf` 的区别：`write` 是无格式化的字节流输出，`printf` 有格式化和缓冲。HFT 场景中 `write` 比 `printf` 更可控。

## 常见陷阱

1. **fd 方向搞反**

```c
int fds[2];
pipe(fds);
write(fds[0], buf, n);  /* 错! fds[0] 是读端 */
write(fds[1], buf, n);  /* 正确 */
```

pipe 返回的 fd[0] 是读端，fd[1] 是写端。搞反会返回 EBADF。

2. **SIGPIPE**

```c
/* 读端已关闭 */
close(fds[0]);
write(fds[1], buf, n);  /* SIGPIPE → 进程被杀 */
```

写已关闭的管道会触发 SIGPIPE。应忽略 SIGPIPE 或用 send 的 MSG_NOSIGNAL。

3. **管道容量有限**

```c
/* 写满管道后 write 阻塞 */
write(fds[1], big_buf, 65536);  /* PIPE_BUF 通常 4096-65536 */
```

管道容量有限（通常 64KB）。写满后 write 阻塞。PIPE_BUF 以内的写是原子的。

## 自测题

**题目 1（选择）：** `pipe(fds)` 中 `fds[0]` 和 `fds[1]` 分别是？
A. 都是读端
B. fds[0] 写端, fds[1] 读端
C. fds[0] 读端, fds[1] 写端
D. 都是写端

<details>
<summary>参考答案</summary>

C。fds[0] 是读端，fds[1] 是写端。记忆法：0 像 O_RDONLY，1 像 O_WRONLY。

</details>

**题目 2（判断）：** 管道的写端关闭后，读端 read 会返回 0。

<details>
<summary>参考答案</summary>

正确。所有写端关闭后，read 返回 0（EOF）。这是管道通信结束的标志。

</details>

**题目 3（踩坑）：** 以下代码有什么问题？
```c
int fds[2];
pipe(fds);
if (fork() == 0) {
    close(fds[0]);
    write(fds[1], "hello", 5);
}
```

<details>
<summary>参考答案</summary>

子进程关闭了读端，但父进程没有关闭写端。父进程的写端不关，子进程的 read 永远不会收到 EOF。需要在父子进程各自关闭不用的端。

</details>

**题目 4（应用）：** 写代码：父子进程通过管道通信，子进程发消息给父进程。

<details>
<summary>参考答案</summary>

```c
int fds[2];
pipe(fds);
if (fork() == 0) {
    close(fds[0]);
    write(fds[1], "hello", 5);
    close(fds[1]);
} else {
    close(fds[1]);
    char buf[16];
    read(fds[0], buf, 16);
    printf("got: %s\n", buf);
}
```

</details>
