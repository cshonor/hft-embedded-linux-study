# 64.2 Unix 98 Pseudoterminals

> 本章：[TLPI 第 64 章](./README.md)

## 本节讲什么

Unix 98 标准伪终端（PTY）接口：`posix_openpt()` 创建主设备，`grantpt()`/`unlockpt()`/`ptsname()` 准备从设备，`fork` + `setsid` 建立伪终端会话。

## 要点

### PTY 架构

```
┌───────────┐           ┌───────────┐
│ Master PTY │ ←数据流→  │ Slave PTY  │
│ (pty master)│          │ (pts/N)    │
└─────┬─────┘           └─────┬─────┘
      │                        │
  应用程序                  子进程（如 shell）
  写 master → 从 slave 读    读写 slave
```

### Unix 98 PTY API

```c
#include <stdlib.h>
int posix_openpt(int flags);         /* 打开主设备 */
int grantpt(int fd);                  /* 设置从设备权限 */
int unlockpt(int fd);                 /* 解锁从设备 */
char *ptsname(int fd);                /* 获取从设备路径 */
```

### 完整流程

```c
/* 1. 打开主设备 */
int masterfd = posix_openpt(O_RDWR | O_NOCTTY);

/* 2. 设置从设备权限 */
grantpt(masterfd);

/* 3. 解锁从设备 */
unlockpt(masterfd);

/* 4. 获取从设备名 */
char *slavename = ptsname(masterfd);

/* 5. fork，子进程打开从设备 */
pid_t pid = fork();
if (pid == 0) {
    setsid();                    /* 新会话 */
    int slavefd = open(slavename, O_RDWR);
    dup2(slavefd, STDIN_FILENO);
    dup2(slavefd, STDOUT_FILENO);
    dup2(slavefd, STDERR_FILENO);
    close(slavefd);
    close(masterfd);
    execlp("bash", "bash", NULL);
}

/* 6. 父进程通过 masterfd 与子进程通信 */
```

### grantpt 替代

| 方式 | 说明 |
|------|------|
| `grantpt(fd)` | 标准方式，修改从设备属主和权限 |
| 手动 `chown`/`chmod` | 非标准，不推荐 |

现代 Linux 上 `posix_openpt` 已设置适当权限，`grantpt` 通常是无操作。

### openpty() 便捷函数

```c
#include <pty.h>
int masterfd, slavefd;
char name[256];
openpty(&masterfd, &slavefd, name, NULL, NULL);
/* 一步完成 master+slave 创建和打开 */
```

## HFT / 嵌入式关联

- 交易系统远程管理：通过 PTY 提供交互式 shell
- 嵌入式设备调试终端：通过串口+PTY 桥接
- 自动化测试：PTY 模拟终端交互
- 终端录制/回放：捕获 PTY 数据流

## 代码示例

```c
#include <stdlib.h>
#include <unistd.h>
#include <fcntl.h>
#include <stdio.h>
#include <string.h>

/* 创建 PTY 并启动子进程 */
int pty_fork(int *masterfd) {
    /* 1. 打开主设备 */
    *masterfd = posix_openpt(O_RDWR | O_NOCTTY);
    if (*masterfd < 0) return -1;

    /* 2. 准备从设备 */
    if (grantpt(*masterfd) < 0 ||
        unlockpt(*masterfd) < 0) {
        close(*masterfd);
        return -1;
    }

    char *slavename = ptsname(*masterfd);
    if (!slavename) { close(*masterfd); return -1; }

    /* 3. fork */
    pid_t pid = fork();
    if (pid < 0) { close(*masterfd); return -1; }

    if (pid == 0) {
        /* 子进程 */
        close(*masterfd);
        setsid();

        int slavefd = open(slavename, O_RDWR);
        if (slavefd < 0) _exit(1);

        dup2(slavefd, STDIN_FILENO);
        dup2(slavefd, STDOUT_FILENO);
        dup2(slavefd, STDERR_FILENO);
        close(slavefd);

        return 0;  /* 子进程返回 0 */
    }

    /* 父进程 */
    return pid;
}

int main() {
    int masterfd;
    pid_t pid = pty_fork(&masterfd);

    if (pid == 0) {
        execlp("bash", "bash", "--norc", NULL);
        _exit(1);
    }

    /* 父进程：读写 masterfd 与子进程通信 */
    char buf[4096];
    ssize_t n;
    while ((n = read(masterfd, buf, sizeof(buf))) > 0) {
        write(STDOUT_FILENO, buf, n);  /* 转发输出 */
    }
    close(masterfd);
    return 0;
}
```

## 代码自测

<details>
<summary>为什么子进程需要调用 setsid()？</summary>

`setsid()` 创建新会话，使子进程脱离控制终端。然后打开从设备作为新会话的控制终端。如果不调用 `setsid()`，子进程仍属于父进程的会话组，从设备不会成为控制终端，终端相关的功能（如 Ctrl+C 产生 SIGINT）不会正常工作。`setsid()` 还使子进程成为新会话的首进程和新进程组的组长，避免被父进程的作业控制干扰。

</details>
