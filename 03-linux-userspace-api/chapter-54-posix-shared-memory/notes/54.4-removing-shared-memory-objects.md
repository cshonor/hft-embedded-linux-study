# 54.4 Removing Shared Memory Objects

> 本章：[TLPI 第 54 章 — POSIX Shared Memory](../README.md)

## 本节讲什么

介绍如何正确删除 POSIX 共享内存对象：`shm_unlink()` 的语义、延迟删除行为和清理策略。

## 要点

### shm_unlink 语义

```c
int shm_unlink(const char *name);
```

| 行为 | 说明 |
|------|------|
| 从 `/dev/shm` 删除名字 | 新进程无法通过名字打开 |
| 已有 fd/mapping 不受影响 | 正在使用的进程不受影响 |
| 最后一个映射解除后释放内存 | 引用计数为 0 时回收 |
| 返回值 | 0 成功，-1 失败 |

### 延迟删除模型

```
进程 A: shm_open("/hft_data", O_CREAT, 0644)
进程 A: mmap(...) → refcount = 1
进程 B: shm_open("/hft_data", 0) → fd
进程 B: mmap(...) → refcount = 2

进程 A: shm_unlink("/hft_data")  → 名字删除，但内存还在
进程 B: 仍可正常访问 → refcount = 2

进程 A: munmap() → refcount = 1
进程 B: munmap() + close() → refcount = 0 → 内存释放
```

### 清理策略

| 策略 | 说明 | 适用 |
|------|------|------|
| 创建者 unlink | 创建后立即 unlink | 临时共享（无需其他进程通过名字访问） |
| 最后使用者 unlink | 使用完成后 unlink | 长期共享 |
| 启动时清理 | 程序启动时 unlink 残留 | 防崩溃残留 |
| 系统重启 | tmpfs 重启清空 | 终极清理 |

### 常见问题

| 问题 | 原因 | 解决 |
|------|------|------|
| `shm_open` EEXIST | 对象已存在且用了 O_EXCL | 先 unlink 或不用 O_EXCL |
| 泄漏 | 创建但未 unlink | 定期清理 `/dev/shm` |
| 权限错误 | 权限不匹配 | `fchmod` 修改 |
| 大小为 0 | 忘记 ftruncate | 创建后立即 ftruncate |

### 命令行管理

```bash
# 查看
ls -l /dev/shm/
df -h /dev/shm

# 删除
rm /dev/shm/hft_data    # 等价 shm_unlink
# 或
python3 -c "import posix_ipc; posix_ipc.unlink_shared_memory('hft_data')"

# 批量清理
rm /dev/shm/hft_*       # 谨慎！
```

## HFT / 嵌入式关联

- **启动清理**：HFT 服务启动时先 `shm_unlink` 可能残留的旧对象
- **立即 unlink**：创建后立即 `shm_unlink`（fd 已持有），防止崩溃残留
- **大小监控**：`df -h /dev/shm` 监控共享内存总量
- **嵌入式**：`/dev/shm` 空间有限，需严格管理

## 代码示例

```c
#include <sys/mman.h>
#include <fcntl.h>
#include <stdio.h>

/* 安全创建模式：创建后立即 unlink */
void *create_temp_shm(const char *name, size_t size) {
    int fd = shm_open(name, O_CREAT | O_RDWR | O_EXCL, 0600);
    if (fd == -1) {
        /* 可能上次崩溃残留，清理后重试 */
        shm_unlink(name);
        fd = shm_open(name, O_CREAT | O_RDWR, 0600);
        if (fd == -1) return NULL;
    }
    ftruncate(fd, size);
    void *p = mmap(NULL, size, PROT_READ|PROT_WRITE, MAP_SHARED, fd, 0);
    close(fd);
    shm_unlink(name);   /* 立即 unlink，fd 仍有效 */
    return p;
}

/* 正常创建模式：使用者负责清理 */
void *create_persistent_shm(const char *name, size_t size) {
    int fd = shm_open(name, O_CREAT | O_RDWR, 0644);
    if (fd == -1) return NULL;
    ftruncate(fd, size);
    void *p = mmap(NULL, size, PROT_READ|PROT_WRITE, MAP_SHARED, fd, 0);
    close(fd);
    /* 不 unlink，其他进程可通过名字访问 */
    return p;
}
```

## 代码自测

<details>
<summary>1. shm_unlink 后正在使用的进程会怎样？</summary>

不受影响。`shm_unlink` 只删除名字，不影响已打开的 fd 和已映射的内存。正在使用的进程可以继续读写。只有当所有 fd 关闭且所有 mmap 解除后，内存才被真正回收。这是"延迟删除"设计。
</details>

<details>
<summary>2. 什么时候应该立即 unlink？</summary>

如果共享内存只用于已知的固定进程组（不通过名字被新进程发现），可以在所有使用者打开 fd 后立即 `shm_unlink`。好处：(1) 程序崩溃不留残留；(2) 不占用 `/dev/shm` 名字空间。fd 仍然有效直到 `close` + `munmap`。
</details>
