# 54.3 Using Shared Memory Objects

> 本章：[TLPI 第 54 章 — POSIX Shared Memory](./README.md)

## 本节讲什么

介绍 POSIX 共享内存对象的使用流程：`shm_open()` 创建/打开 → `ftruncate()` 设置大小 → `mmap()` 映射 → 读写 → `munmap()` 解除。

## 要点

### POSIX 共享内存 API

| 函数 | 说明 |
|------|------|
| `shm_open(name, oflag, mode)` | 创建/打开共享内存对象（类似 open） |
| `shm_unlink(name)` | 删除共享内存对象 |
| `ftruncate(fd, size)` | 设置对象大小 |
| `mmap(addr, len, prot, flags, fd, 0)` | 映射到进程地址空间 |
| `fstat(fd, &sb)` | 查看对象信息（大小等） |
| `fchmod(fd, mode)` | 修改权限 |
| `close(fd)` | 关闭 fd（对象仍存在） |

### 使用流程

```
1. shm_open("/hft_data", O_CREAT|O_RDWR, 0644)  → fd
2. ftruncate(fd, 1024*1024)                      → 设置 1MB 大小
3. mmap(NULL, 1024*1024, PROT_READ|PROT_WRITE, MAP_SHARED, fd, 0)  → ptr
4. 读写 ptr 指向的内存
5. munmap(ptr, 1024*1024)                        → 解除映射
6. close(fd)                                      → 关闭 fd
7. shm_unlink("/hft_data")                        → 删除对象
```

### shm_open flags

| flag | 说明 |
|------|------|
| `O_CREAT` | 不存在则创建 |
| `O_EXCL` | 配合 O_CREAT，存在则失败 |
| `O_RDWR` | 读写 |
| `O_RDONLY` | 只读 |
| `O_TRUNC` | 截断为 0 |

### 与 SysV 共享内存对比

| 特性 | POSIX `shm_open` | SysV `shmget` |
|------|-----------------|---------------|
| 接口 | 文件式（open/ftruncate/mmap） | 系统调用式 |
| 位置 | `/dev/shm/` | 内核匿名 |
| 管理工具 | `ls /dev/shm/` | `ipcs -m` |
| 大小控制 | `ftruncate` | 创建时指定 |
| 权限 | 文件权限 | ipc_perm |
| 可移植性 | POSIX | SysV |

### mmap 选项

```c
/* POSIX 共享内存的标准 mmap 用法 */
void *p = mmap(NULL, size,
               PROT_READ | PROT_WRITE,
               MAP_SHARED | MAP_HASSEMICOLON,
               fd, 0);

/* 常用 flags 组合 */
MAP_SHARED          /* 共享映射（多进程可见） */
MAP_SHARED | MAP_LOCKED       /* 锁定在内存中 */
MAP_SHARED | MAP_HUGETLB      /* 使用大页 */
MAP_SHARED | MAP_POPULATE     /* 预填充页表 */
```

### /dev/shm 文件系统

```
$ ls -l /dev/shm/
total 1024
-rw-r--r-- 1 hft hft 1048576 Aug 12 19:00 hft_data
```

- POSIX 共享内存对象以文件形式存在于 `/dev/shm`（tmpfs）
- `df -h /dev/shm` 查看可用空间
- 可用 `ls`/`rm` 管理（但推荐用 `shm_unlink`）

## HFT / 嵌入式关联

- **行情共享**：HFT 行情进程创建共享内存对象，策略进程 mmap 读取
- **MAP_LOCKED**：锁定页面防止换页延迟
- **MAP_HUGETLB**：使用 2MB 大页减少 TLB miss
- **MAP_POPULATE**：启动时预填充页表，避免运行时缺页
- **NUMA**：`mbind` 绑定共享内存到特定 NUMA 节点
- **嵌入式**：`/dev/shm` 可能需要手动挂载或增大

## 代码示例

```c
#include <sys/mman.h>
#include <fcntl.h>
#include <stdio.h>
#include <unistd.h>

#define SHM_NAME "/hft_market_data"
#define SHM_SIZE (64 * 1024 * 1024)  /* 64MB */

int main(void) {
    /* 创建共享内存对象 */
    int fd = shm_open(SHM_NAME, O_CREAT | O_RDWR, 0644);
    if (fd == -1) { perror("shm_open"); return 1; }

    /* 设置大小 */
    if (ftruncate(fd, SHM_SIZE) == -1) { perror("ftruncate"); return 1; }

    /* 映射 */
    void *ptr = mmap(NULL, SHM_SIZE,
                     PROT_READ | PROT_WRITE,
                     MAP_SHARED | MAP_LOCKED,
                     fd, 0);
    if (ptr == MAP_FAILED) { perror("mmap"); return 1; }

    /* 写入数据 */
    memset(ptr, 0, SHM_SIZE);
    printf("shared memory ready: %p (%d MB)\n", ptr, SHM_SIZE/(1024*1024));

    /* 另一个进程可以 shm_open + mmap 访问同一内存 */

    /* 清理 */
    munmap(ptr, SHM_SIZE);
    close(fd);
    shm_unlink(SHM_NAME);
    return 0;
}
```

## 代码自测

<details>
<summary>1. shm_open 后为什么需要 ftruncate？</summary>

`shm_open` 创建的对象初始大小为 0 字节。如果直接 `mmap` 一个大小为 0 的对象，mmap 会失败（ EINVAL）。`ftruncate` 将对象扩展到所需大小，之后 mmap 才能映射。这是 POSIX 共享内存的标准流程。
</details>

<details>
<summary>2. close(fd) 后共享内存还有效吗？</summary>

是的。`close(fd)` 只关闭文件描述符，共享内存对象仍然存在于 `/dev/shm` 中，其他已 mmap 的进程仍然可以访问。对象在 `shm_unlink` 被调用且所有映射解除后才真正释放。
</details>
