## 练习 11-1：在另一个 UNIX 实现上跑 Listing 11-1

### 任务

把 Listing 11-1（`t_sysconf.c`，page 216）拿到**另一个 UNIX 实现**上运行，比较输出。

**难点**：本仓库拿不到第二个 UNIX 实现（只有 Linux 容器）。所以解答做两件能真正落地的事：

1. 先把 Listing 11-1 的 6 项**原样打一遍**（方便与手边的其他实现逐行对照）；
2. 给出一张宽表：每项的**实测值 + POSIX 保证下限 + glibc 里的取值路径**。第三列才是本题的正解——它说明「在别的 UNIX 上，哪些项允许不一样、允许差到多少」。

### 实现

完整源码 [`code/ex11_1_sysconf_wide.c`](../code/ex11_1_sysconf_wide.c)：

```c
/* ex11_1_sysconf_wide.c — 原书习题 11-1 解答
 *
 * 【任务】（对应原书 Ch11 Exercises 11-1）把 Listing 11-1 拿到**另一个 UNIX 实现**
 *   上跑一遍、对比结果。
 *   ⚠️ 原书习题文字的公开原文未能核验（man7 只分发源码、不放习题文字），
 *      所以这里只写任务要求，不做逐字引用。
 *
 * 【本题的困难】本仓库只有 Linux（Compiler Explorer 的 Ubuntu 24.04 容器），
 *   拿不到第二个 UNIX 实现。所以这里做两件能真正落地的事：
 *
 *   ① 把 Listing 11-1 的 6 项**原样先打一遍**（方便和原书输出逐行对照）；
 *   ② 给出一张「宽表」：每项的值 + glibc 2.39 里的取值路径 + POSIX 只保证的
 *      下限。第三列才是本题的真正答案 —— 它解释了「在别的 UNIX 上，哪些
 *      项允许不一样、允许差到多少」。
 *
 * 编译： gcc -O0 -Wall -Wextra -o ex11_1_sysconf_wide ex11_1_sysconf_wide.c
 * 取材： 原书 Listing 11-1 = syslim/t_sysconf.c（page 216），本目录 t_sysconf.c 为其逐字镜像
 *       glibc 2.39 sysdeps/posix/sysconf.c:68-93 / :265-267 / :1113 / :1123
 *       glibc 2.39 sysdeps/unix/sysv/linux/sysconf.c:56-67 / :69-73
 *       glibc 2.39 sysdeps/unix/sysv/linux/x86/sysconf.c:33-36（只多管 CPU cache）
 *       man-pages 6.19 sysconf(3)：每一项的 _POSIX_* 下限
 */
#define _GNU_SOURCE
#include <errno.h>
#include <limits.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <unistd.h>

static void orig(const char *msg, int name)
{
    errno = 0;
    long lim = sysconf(name);
    if (lim != -1)
        printf("%s %ld\n", msg, lim);
    else if (errno == 0)
        printf("%s (indeterminate)\n", msg);
    else
        printf("%s ERROR: %s\n", msg, strerror(errno));
}

struct row { int name; const char *lbl; long floor; const char *src; };

int main(void)
{
    printf("=== ① 原样重跑 Listing 11-1（page 216）的 6 项 ===\n");
    orig("_SC_ARG_MAX:        ", _SC_ARG_MAX);
    orig("_SC_LOGIN_NAME_MAX: ", _SC_LOGIN_NAME_MAX);
    orig("_SC_OPEN_MAX:       ", _SC_OPEN_MAX);
    orig("_SC_NGROUPS_MAX:    ", _SC_NGROUPS_MAX);
    orig("_SC_PAGESIZE:       ", _SC_PAGESIZE);
    orig("_SC_RTSIG_MAX:      ", _SC_RTSIG_MAX);

    printf("\n=== ② 宽表：值 / POSIX 保证下限 / glibc 里的取值路径 ===\n");
    const struct row T[] = {
        { _SC_ARG_MAX, "_SC_ARG_MAX", _POSIX_ARG_MAX,
          "sysdeps/unix/sysv/linux/sysconf.c:56-67  min(max(131072, RLIMIT_STACK/4), 6MiB)" },
        { _SC_LOGIN_NAME_MAX, "_SC_LOGIN_NAME_MAX", _POSIX_LOGIN_NAME_MAX,
          "sysdeps/unix/sysv/linux/bits/local_lim.h:90  LOGIN_NAME_MAX 256" },
        { _SC_OPEN_MAX, "_SC_OPEN_MAX", _POSIX_OPEN_MAX,
          "sysdeps/posix/sysconf.c:92 -> getdtsz.c:32  getrlimit(RLIMIT_NOFILE).rlim_cur" },
        { _SC_NGROUPS_MAX, "_SC_NGROUPS_MAX", _POSIX_NGROUPS_MAX,
          "linux/sysconf.c:69-73  读 /proc/sys/kernel/ngroups_max" },
        { _SC_PAGESIZE, "_SC_PAGESIZE", 1,
          "sysdeps/posix/sysconf.c:220  _SC_PAGESIZE -> __getpagesize()" },
        { _SC_RTSIG_MAX, "_SC_RTSIG_MAX", _POSIX_RTSIG_MAX,
          "sysdeps/posix/sysconf.c:265-267 -> RTSIG_MAX（<linux/limits.h>:19 的 32）" },
    };
    printf("  %-22s %-12s %-10s %s\n", "name", "实测", "下限", "POSIX 只保证 / 差值意味着什么");
    for (size_t i = 0; i < sizeof(T) / sizeof(T[0]); i++) {
        errno = 0;
        long v = sysconf(T[i].name);
        char vi[16];
        if (v == -1) snprintf(vi, sizeof vi, "(-1)");
        else snprintf(vi, sizeof vi, "%ld", v);
        printf("  %-22s %-12s %-10ld %s\n", T[i].lbl, vi, T[i].floor,
               (T[i].floor > 0 && v > 0 && v != T[i].floor) ? "** 比下限大 **" : "");
    }
    printf("\n  每项的完整来源：\n");
    for (size_t i = 0; i < sizeof(T) / sizeof(T[0]); i++)
        printf("    %-22s %s\n", T[i].lbl, T[i].src);

    printf("\n=== ③ 这就是「在别的 UNIX 上会不一样」的答案 ===\n");
    printf("  POSIX 对每一项只给「不低于」的下限，所以另一台 UNIX 上合法的最小值是：\n");
    printf("    _SC_ARG_MAX        >= %d      （本机 %ld）\n", _POSIX_ARG_MAX, sysconf(_SC_ARG_MAX));
    printf("    _SC_LOGIN_NAME_MAX >= %d       （本机 %ld）\n", _POSIX_LOGIN_NAME_MAX,
           sysconf(_SC_LOGIN_NAME_MAX));
    printf("    _SC_OPEN_MAX       >= %d      （本机 %ld）\n", _POSIX_OPEN_MAX, sysconf(_SC_OPEN_MAX));
    printf("    _SC_NGROUPS_MAX    >= %d       （本机 %ld）\n", _POSIX_NGROUPS_MAX,
           sysconf(_SC_NGROUPS_MAX));
    printf("    _SC_PAGESIZE       >= %d       （本机 %ld）\n", 1, sysconf(_SC_PAGESIZE));
    printf("    _SC_RTSIG_MAX      >= %d       （本机 %ld）\n", _POSIX_RTSIG_MAX,
           sysconf(_SC_RTSIG_MAX));
    printf("  也就是说：_SC_OPEN_MAX 在另一台机器上可能是 20，_SC_NGROUPS_MAX 可能是 8，\n");
    printf("  _SC_ARG_MAX 可能是 4096 —— 全都合法。写 `char buf[1024]` 赌「路径够短」或者\n");
    printf("  `#define MAX_FD 1024` 就是踩这个坑。\n");

    printf("\n=== ④ 本机这几个值的稳定性（同一进程内查两次）===\n");
    long a1 = sysconf(_SC_OPEN_MAX), a2 = sysconf(_SC_OPEN_MAX);
    long b1 = sysconf(_SC_CLK_TCK), b2 = sysconf(_SC_CLK_TCK);
    printf("  _SC_OPEN_MAX 两次: %ld / %ld -> %s\n", a1, a2, a1 == a2 ? "一致" : "不一致");
    printf("  _SC_CLK_TCK  两次: %ld / %ld -> %s\n", b1, b2, b1 == b2 ? "一致" : "不一致");
    printf("  sysconf(3) 原文：「The values obtained from these functions are system\n");
    printf("  configuration constants.  They do not change during the lifetime of a process.」\n");
    printf("  ——但 _SC_OPEN_MAX 会跟着 setrlimit 变，所以「一生不变」这句对限制类并不成立，\n");
    printf("     见 §11.1 的 c11_1_three_kinds.c。\n");
    return 0;
}
```

编译运行：

```bash
gcc -O0 -Wall -Wextra -o ex11_1_sysconf_wide ex11_1_sysconf_wide.c && ./ex11_1_sysconf_wide
```


逐项看「在别的 UNIX 上会怎么变」：

| 项 | 本机 | POSIX 下限 | 换一台机器会怎样 | 为什么 |
|----|------|-----------|----------------|-------|
| `_SC_ARG_MAX` | 2097152 | 4096（`_POSIX_ARG_MAX`） | 可能是 **4096**，也可能更大 | glibc 自己算的 `min(max(131072, RLIMIT_STACK/4), 6MiB)`；别的实现可能直接返回内核 `ARG_MAX = 131072` |
| `_SC_LOGIN_NAME_MAX` | 256 | 9 | 合法值可能只有 **9** | 只要 `utmp` 结构够放 8 字符 + `\0` 就合规 |
| `_SC_OPEN_MAX` | 100 | 20 | 可能是 **20** | 本机等于 `RLIMIT_NOFILE.rlim_cur`；别的实现可能是硬上限或固定常量 |
| `_SC_NGROUPS_MAX` | 65536 | 8 | 可能是 **8** | 本机读 `/proc/sys/kernel/ngroups_max`；别的实现返回编译期常量 |
| `_SC_PAGESIZE` | 4096 | 1 | 可能是 **8192 / 16384 / 65536** | ARM64 常见 4K/16K/64K 三种页大小 |
| `_SC_RTSIG_MAX` | 32 | 8 | 可能是 **8** | 本机来自内核 uapi 的 `RTSIG_MAX 32` |

> **本题的真正教训**：Listing 11-1 在另一台机器上不会「报错」，它会**安静地给你另一组数**。所以任何 `#define MAX_FD 1024` 或 `char buf[256]` 式的硬编码，都会在别人的机器上以「偶尔截断 / 偶尔 EMFILE」的形式暴露出来。
>
> ④ 段还顺手戳破一句 man-pages 原文：「The values obtained from these functions are system configuration constants. They do not change during the lifetime of a process.」——对 `_SC_OPEN_MAX` **不成立**（[11.1](11.1-system-limits.md) 实测：改 `RLIMIT_NOFILE` 后它从 100 变 50）。

## 练习 11-2：在别的文件系统上跑 Listing 11-2

### 任务

把 Listing 11-2（`t_fpathconf.c`，page 218）拿到**别的文件系统**上运行，比较输出。

Listing 11-2 只对 `STDIN_FILENO` 问三个 `_PC_*`。要「跑到别的文件系统上」其实不需要第二台机器——**一台 Linux 上就挂着十几种文件系统**。所以解答改成：

1. 遍历 `/proc/mounts`，对每个挂载点问同一组 `_PC_*`；
2. 按 `(NAME_MAX, LINK_MAX, FILESIZEBITS)` **去重**后再打印（CE 容器里 `/cefs` 下挂着几十个带哈希路径的 `autofs`/`squashfs` 子挂载点，全打出来既长又不可复现）；
3. 顺手打 `statfs().f_type` 与 `statvfs().f_namemax`，说明「为什么同一个内核上会有不同答案」。

### 实现

完整源码 [`code/ex11_2_fs_sweep.c`](../code/ex11_2_fs_sweep.c)：

```c
/* ex11_2_fs_sweep.c — 原书习题 11-2 解答
 *
 * 【任务】（对应原书 Ch11 Exercises 11-2）把 Listing 11-2 拿到**别的文件系统**
 *   上跑一遍、对比结果。
 *   ⚠️ 原书习题文字的公开原文未能核验（man7 只分发源码、不放习题文字），
 *      所以这里只写任务要求，不做逐字引用。
 *
 * 【本题的可做性】Listing 11-2（= 本目录 t_fpathconf.c，page 218）只对
 *   STDIN_FILENO 问三个 _PC_*。要「跑到别的文件系统上」，不需要第二台机器 ——
 *   Linux 一台机器上就挂着十几种文件系统。本解答改成：
 *
 *   ① 遍历 /proc/mounts，对每个挂载点问同一组 _PC_*；
 *   ② 按 (NAME_MAX, LINK_MAX, FILESIZEBITS) **去重**后再打印，
 *      否则几十个挂载点会把结论淹没；
 *   ③ 顺手把 statfs().f_type 与 statvfs().f_namemax 打出来，
 *      说明「为什么同一个内核上会有不同答案」。
 *
 * 【为什么要去重而不是全打印】CE 容器里 /cefs 下面挂了几十个 autofs/squashfs
 *   子挂载点，路径名里还带不同的哈希（每次运行都不一样），全打出来既长又不
 *   可复现。去重后只剩三行，正好是三份答案。
 *
 * 编译： gcc -O0 -Wall -Wextra -o ex11_2_fs_sweep ex11_2_fs_sweep.c
 * 取材： glibc 2.39 sysdeps/unix/sysv/linux/pathconf.c:133-192（__statfs_link_max，按 f_type 查表）
 *       glibc 2.39 sysdeps/unix/sysv/linux/pathconf.c:197-240（__statfs_filesize_max，按 f_type 查表）
 *       glibc 2.39 sysdeps/posix/pathconf.c:65-86（_PC_NAME_MAX -> statvfs.f_namemax）
 *       glibc 2.39 sysdeps/unix/sysv/linux/linux_fsinfo.h:255-268（各 fs 的 LINK_MAX 常量）
 */
#define _GNU_SOURCE
#include <errno.h>
#include <limits.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <sys/statfs.h>
#include <sys/statvfs.h>
#include <unistd.h>

#define MAXK 64

struct key { long nm, lk, fb; char ftype[24]; unsigned long ftype_hex; int hits; };

static struct key keys[MAXK];
static int nkeys;

static void note(long nm, long lk, long fb, const char *ftype, unsigned long hex)
{
    for (int i = 0; i < nkeys; i++)
        if (keys[i].nm == nm && keys[i].lk == lk && keys[i].fb == fb) {
            keys[i].hits++;
            return;
        }
    if (nkeys >= MAXK) return;
    keys[nkeys].nm = nm; keys[nkeys].lk = lk; keys[nkeys].fb = fb;
    keys[nkeys].ftype_hex = hex; keys[nkeys].hits = 1;
    snprintf(keys[nkeys].ftype, sizeof keys[0].ftype, "%s", ftype);
    nkeys++;
}

int main(void)
{
    FILE *f = fopen("/proc/mounts", "r");
    if (!f) { perror("/proc/mounts"); return 1; }

    printf("=== ① 遍历 /proc/mounts，问同一组 _PC_* ===\n");
    long nm = pathconf("/", _PC_NAME_MAX);
    long lk = pathconf("/", _PC_LINK_MAX);
    long fb = pathconf("/", _PC_FILESIZEBITS);
    printf("  先在 / 上取一组基线: NAME_MAX=%ld LINK_MAX=%ld FILESIZEBITS=%ld\n", nm, lk, fb);

    char dev[128], mnt[128], type[32];
    int scanned = 0;
    while (fscanf(f, "%127s %127s %31s %*s %*s %*s", dev, mnt, type) == 3) {
        struct statfs sf;
        if (statfs(mnt, &sf) != 0)
            continue;
        errno = 0;
        long a = pathconf(mnt, _PC_NAME_MAX);
        if (a == -1) continue;
        long b = pathconf(mnt, _PC_LINK_MAX);
        long c = pathconf(mnt, _PC_FILESIZEBITS);
        scanned++;
        note(a, b, c, type, (unsigned long)sf.f_type);
    }
    fclose(f);

    printf("\n=== ② 去重后的答案（扫了 %d 个挂载点，共 %d 种结果）===\n", scanned, nkeys);
    printf("  %-9s %-10s %-15s %-12s %s\n", "NAME_MAX", "LINK_MAX", "FILESIZEBITS",
           "f_type", "代表文件系统");
    for (int i = 0; i < nkeys; i++)
        printf("  %-9ld %-10ld %-15ld 0x%-9lx %s（%d 个挂载点）\n",
               keys[i].nm, keys[i].lk, keys[i].fb, keys[i].ftype_hex,
               keys[i].ftype, keys[i].hits);

    printf("\n=== ③ 为什么会有不同答案 ===\n");
    printf("  _PC_LINK_MAX      -> glibc 按 statfs().f_type 查表：\n");
    printf("                       ext4 -> EXT4_LINK_MAX 65000；其余多数 -> LINUX_LINK_MAX 127\n");
    printf("                       （linux_fsinfo.h:256 / :268；ext4 还要特判，见 pathconf.c:63-128）\n");
    printf("  _PC_FILESIZEBITS  -> 同样查表：ext4 64；tmpfs/proc/squashfs 走 default 32\n");
    printf("  _PC_NAME_MAX      -> statvfs().f_namemax，由**超级块**报上来，所以能不是 255\n");
    printf("                       （本机 squashfs 就报了 256）\n");
    printf("  _PC_PATH_MAX      -> 这几行里它**没有任何变化**：glibc 直接 return PATH_MAX(%d)，\n",
           PATH_MAX);
    printf("                       与文件系统无关。\n");
    printf("  _PC_PIPE_BUF      -> 同理，直接 return PIPE_BUF(%d)。\n", PIPE_BUF);

    printf("\n=== ④ 与 Listing 11-2 原始行为对照 ===\n");
    printf("  原书 Listing 11-2 对 STDIN_FILENO 问三项，本机结果：\n");
    errno = 0;
    printf("    _PC_NAME_MAX = %ld\n", fpathconf(STDIN_FILENO, _PC_NAME_MAX));
    printf("    _PC_PATH_MAX = %ld\n", fpathconf(STDIN_FILENO, _PC_PATH_MAX));
    printf("    _PC_PIPE_BUF = %ld\n", fpathconf(STDIN_FILENO, _PC_PIPE_BUF));
    printf("  —— 与在 / 上问的结果完全一样。原因是这三项在 glibc 里都不看 fd 指向的类型\n");
    printf("     （_PC_NAME_MAX 走 statvfs，管道/终端 fd 也能 statvfs 成功并报 255）。\n");
    printf("  所以「换文件系统」这个实验真正会变的只有 LINK_MAX / FILESIZEBITS / NAME_MAX。\n");
    return 0;
}
```

CE（gcc 13.3.0 / x86-64 / Ubuntu 24.04）实测：

```text
=== ① 遍历 /proc/mounts，问同一组 _PC_* ===
  先在 / 上取一组基线: NAME_MAX=255 LINK_MAX=127 FILESIZEBITS=32

=== ② 去重后的答案（扫了 60 个挂载点，共 3 种结果）===
  NAME_MAX  LINK_MAX   FILESIZEBITS    f_type       代表文件系统
  255       127        32              0x1021994   tmpfs（31 个挂载点）
  255       65000      64              0xef53      ext4（10 个挂载点）
  256       127        32              0x73717368  squashfs（19 个挂载点）

=== ④ 与 Listing 11-2 原始行为对照 ===
  原书 Listing 11-2 对 STDIN_FILENO 问三项，本机结果：
    _PC_NAME_MAX = 255
    _PC_PATH_MAX = 4096
    _PC_PIPE_BUF = 4096
```

逐项看：

| 观察 | 说明 |
|------|------|
| 扫了 **60 个挂载点**，去重后只剩 **3 种** `(NAME_MAX, LINK_MAX, FILESIZEBITS)` 组合 | 绝大多数挂载点共享同样的三元组，去重才看得清结论 |
| `tmpfs`（31 个）：`255 / 127 / 32` | `/`、`/tmp`、`/dev`、`/etc/passwd`、`/etc/shadow` 等都是 tmpfs（`f_type=0x1021994`）。`LINK_MAX` 走 `default` → `LINUX_LINK_MAX 127` |
| `ext4`（10 个）：`255 / 65000 / 64` | `/lib`、`/usr/lib`、`/lib64`、`/app`、`/usr/local/bin/dumb-init` 等。`EXT4_LINK_MAX 65000`（`linux_fsinfo.h:256`）、`FILESIZEBITS 64` |
| `squashfs`（19 个）：`256 / 127 / 32` | `/cefs/**` 下的只读镜像。**`NAME_MAX` 是 256，不是 255** —— 这一格是本题最有价值的一行 |
| `_PC_NAME_MAX = 256` 意味着什么 | `char name[256]` 恰好装不下「256 个字符 + 结尾 `\0`」。文件名长度上限来自**超级块上报的 `f_namemax`**，不是内核 uapi 里写死的 `NAME_MAX 255` |
| ④ 段三项与 `/` 上完全一样 | 因为 glibc 对 `_PC_NAME_MAX`（走 `statvfs`）、`_PC_PATH_MAX`（`return PATH_MAX`）、`_PC_PIPE_BUF`（`return PIPE_BUF`）**都不看 fd 指向的类型** |
| 所以「换文件系统」真正会变的只有三项 | `LINK_MAX` / `FILESIZEBITS`（按 `f_type` 查表）与 `NAME_MAX`（`f_namemax`） |

> **和 [11.3](11.3-file-related-limits.md) A 段的差别**：A 段用固定两列（`/` vs `/lib`）做对照，本习题改成**全量扫描 + 去重**，于是额外暴露出 squashfs 的 `f_namemax = 256`——这正是「`NAME_MAX` 是每目录、每文件系统的事」最有说服力的证据。

## HFT / 嵌入式关联

| 场景 | 这两道习题带来的直接结论 |
|------|----------------------|
| 「在我机器上是好的」不算通过 | 11-1 的宽表说明：同类值在不同实现上合法区间差 1 个数量级以上（`_SC_ARG_MAX` 4096 ↔ 2097152）。性能调优前先在这些项上打启动日志 |
| 路径/文件名缓冲 | 11-2 的 squashfs `NAME_MAX = 256` 是最实用的那一条：`char name[256]` 在只读镜像上会少一个字节。规范做法是 `pathconf(dir, _PC_NAME_MAX) + 1` |
| 容器存储驱动 | 同一个容器里 `tmpfs` 与 `ext4` 混挂很常见。`LINK_MAX` 在两者上差 **512 倍**（127 vs 65000），把「硬链接上限」写死的代码换存储驱动就可能失效 |
| 交叉编译 + 目标板 | 11-1 的逻辑应该反向用一遍：**编译期拿到的 `<limits.h>` 是工具链的，不是目标板的**。要用宽表的第三列（`_POSIX_*` 下限）作为「最低可依赖值」 |
| IPC 与管道 | `_PC_PIPE_BUF` 在扫描结果里**从头到尾没出现过**（它不随文件系统变，恒 4096）。跨进程消息协议按 4096 设计，别按管道容量 65536 |
| 自动化自检 | `ex11_2_fs_sweep.c` 去重打印的思路可以直接搬进启动自检：扫一遍关键挂载点，把三元组打进日志——环境变化时这是最快的定位线索 |

<summary>代码自测（Q&A）</summary>

**Q1：习题 11-1 要求「在别的 UNIX 上跑」，拿不到第二个 UNIX 怎么办？**
A：把问题改成「**别的 UNIX 上允许差多少**」。POSIX 对每个限制只给「不低于」的下限（`_POSIX_*`），所以只要列出「本机实测值 + 该下限」，就能算出合法区间。`ex11_1_sysconf_wide.c` 的 ②/③ 段就是这张表：`_SC_ARG_MAX` 合法区间 `>= 4096`、`_SC_NGROUPS_MAX` `>= 8`、`_SC_OPEN_MAX` `>= 20`……本机全在区间的上端。

**Q2：`_SC_ARG_MAX` 的「合法最小值 4096」和「本机 2097152」差 512 倍，代码该怎么写？**
A：运行时查、运行时定缓冲，或按「下限 + 动态扩容」写。**绝对不能**拿 2097152 当常量（别的机器可能是 4096），也不能拿 4096 当预算（本机会浪费 511/512 的空间）。

**Q3：习题 11-2 里 `_PC_NAME_MAX` 在 squashfs 上是 256，这有什么实际影响？**
A：`pathconf(dir, _PC_NAME_MAX)` 返回的是**名字本身**的最大字符数，不含结尾 `\0`。所以缓冲要按「返回值 + 1」分配。`char name[256]` 在这个文件系统上能装的名字比合法上限少一个字符，而且在 `NAME_MAX` 语义下最容易被忽略——因为多数文件系统报 255，正好装下。

**Q4：既然一台机器上就挂着多种文件系统，为什么 Listing 11-2 只问 `STDIN_FILENO`？**
A：原书那个程序是**最小示例**，目的是演示 `fpathconf()` 的用法（用 fd 而不是路径）。但它也会误导：实测 ④ 段说明这三项在 glibc 里**根本不看 fd 类型**，所以 Listing 11-2 的输出在任何文件系统上都一样——**它演示不了「换文件系统会不一样」**。习题 11-2 的价值就在这里：要真正看到差异，必须用 `pathconf(路径, …)` 并换路径。

**Q5：`_PC_FILESIZEBITS = 32`（tmpfs）和 `64`（ext4）差别意味着什么？**
A：这是「文件大小需要用多少位表示」——32 位意味着该文件系统上单文件最大 4 GiB 级别的寻址。tmpfs 报 32 不代表真的只能用 32 位偏移（本机 `off_t` 是 64 位、`_PC_FILESIZEBITS` 由 `f_type` 查表），但**跨文件系统拷贝大文件时这是要看的项**（[Ch5 大文件 LFS](../../chapter-05-file-io-further/notes/5.10-large-files.md)）。

**Q6：为什么两个解答都要去重/克制输出？**
A：因为「结论的稳定性」比「输出的完整性」重要。CE 容器里 `/cefs` 下有几十个**路径带构建哈希**的 `squashfs` 挂载点（每次运行路径都不同），全量打印会让结论无法核对。`ex11_2_fs_sweep.c` 按值三元组去重后只剩 3 行，**每行都代表「一个可解释的答案」**；同时把「有多少个挂载点共享这个答案」也打出来（31 / 10 / 19）——这既保留了信息量，又不引入不可复现的噪声。
