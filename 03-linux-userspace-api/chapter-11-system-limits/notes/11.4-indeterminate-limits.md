# 11.4 Indeterminate Limits 不确定的限制

> 本章：[TLPI 第 11 章 — System Limits and Options](../README.md)
> 源码核验：glibc **2.39**（`sysdeps/posix/sysconf.c`、`sysdeps/posix/pathconf.c`）+ POSIX.1-2017（`<limits.h>` 的 `_POSIX_*` 下限表）+ man-pages **6.19** `sysconf(3)` / `fpathconf(3)` + CE 实测（gcc 13.3.0 / x86-64 / Ubuntu 24.04）
> - 上一节：[11.3 Retrieving File-Related Limits (and Options) at Run Time 文件相关限制](11.3-file-related-limits.md)
> - 下一节：[11.5 System Options 系统选项](11.5-system-options.md)

---

## 本节讲什么

「不确定」是一种**标准允许的合法状态**：实现可以说「这个限制我有，但我不告诉你确切值」。此时 `sysconf`/`pathconf` 返回 `-1` 且 **`errno` 不变**。本节的三个问题：

1. 本机上**哪些** name 真的 indeterminate？
2. 一个能分清「确定值 / 不确定 / 出错」的封装长什么样？
3. 查不到的时候，程序该退到哪一级？（降级阶梯）

外加一个反方向的坑：**有些结果「看起来有值」其实毫无意义**，比 `-1` 更危险。

---

## 1. 什么叫 indeterminate

man-pages 6.19 `sysconf(3)` 的 RETURN VALUE 段（逐字）：

> If `name` corresponds to a maximum or minimum limit, and that limit is **indeterminate**, -1 is returned and `errno` is **not changed**. (To distinguish an indeterminate limit from an error, set `errno` to zero before the call, and then check whether `errno` is nonzero when -1 is returned.)

`fpathconf(3)` 的 RETURN VALUE 段有对应的一句（把 `name` 换成 `_PC_*`）。要点：

| 想表达 | 返回值 | `errno` | 调用者该做什么 |
|-------|-------|--------|--------------|
| 确定值 | 具体数 | 不变 | 直接用 |
| **indeterminate** | `-1` | **不变**（清零后仍为 0） | **走保守回退**，不是报错 |
| 真错误 | `-1` | 被设（`EINVAL`/`EBADF`/`ENOENT`…） | 报错（这是 bug） |

所以 indeterminate 不是「不支持」，而是「**这个实现不回答**」。前者是你问了一个它没有的功能，后者是它有、但拒绝给数。

## 2. 本机的 indeterminate 清单

完整源码 [`code/c11_4_indeterminate.c`](../code/c11_4_indeterminate.c)：

```c
/* c11_4_indeterminate.c — Ch11 §11.4：indeterminate 限制与「查不到怎么办」
 *
 * §11.4 讲的是这样一类限制：标准允许系统**不告诉你确切值**。此时
 * sysconf/pathconf 返回 -1 且 errno 不变。问题在于：
 *
 *   ① 哪些 name 会 indeterminate？（本机实测清单）
 *   ② 一个安全的封装长什么样？
 *   ③ 查不到时程序该退到哪一级？（降级阶梯：sysconf -> pathconf -> 编译期宏 -> 保守常量）
 *
 * 编译： gcc -O0 -Wall -Wextra -o c11_4_indeterminate c11_4_indeterminate.c
 * 取材： sysconf(3) / fpathconf(3) RETURN VALUE 段（man-pages 6.19）；
 *       glibc 2.39 sysdeps/posix/sysconf.c:102-103（_SC_TZNAME_MAX 恒 -1）
 *       glibc 2.39 sysdeps/posix/pathconf.c:44-62（LINK_MAX/MAX_CANON/MAX_INPUT 可 -1）
 *       POSIX.1-2017 <limits.h>：_POSIX_* 是「保证下限」，实现可以更大
 */
#define _GNU_SOURCE
#include <errno.h>
#include <limits.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <unistd.h>

/* ---------- ① 扫一遍，只打印真的 indeterminate 的 ---------- */
static void sweep(void)
{
    static const struct { int name; const char *lbl; } N[] = {
        { _SC_ARG_MAX, "_SC_ARG_MAX" }, { _SC_CHILD_MAX, "_SC_CHILD_MAX" },
        { _SC_OPEN_MAX, "_SC_OPEN_MAX" }, { _SC_STREAM_MAX, "_SC_STREAM_MAX" },
        { _SC_NGROUPS_MAX, "_SC_NGROUPS_MAX" }, { _SC_HOST_NAME_MAX, "_SC_HOST_NAME_MAX" },
        { _SC_LOGIN_NAME_MAX, "_SC_LOGIN_NAME_MAX" }, { _SC_TTY_NAME_MAX, "_SC_TTY_NAME_MAX" },
        { _SC_TZNAME_MAX, "_SC_TZNAME_MAX" }, { _SC_SYMLOOP_MAX, "_SC_SYMLOOP_MAX" },
        { _SC_RE_DUP_MAX, "_SC_RE_DUP_MAX" }, { _SC_IOV_MAX, "_SC_IOV_MAX" },
        { _SC_MQ_OPEN_MAX, "_SC_MQ_OPEN_MAX" }, { _SC_MQ_PRIO_MAX, "_SC_MQ_PRIO_MAX" },
        { _SC_SEM_NSEMS_MAX, "_SC_SEM_NSEMS_MAX" }, { _SC_SEM_VALUE_MAX, "_SC_SEM_VALUE_MAX" },
        { _SC_DELAYTIMER_MAX, "_SC_DELAYTIMER_MAX" }, { _SC_SIGQUEUE_MAX, "_SC_SIGQUEUE_MAX" },
    };
    int n = 0;
    printf("### ① 本机的 indeterminate 清单（-1 且 errno==0）\n");
    for (size_t i = 0; i < sizeof(N) / sizeof(N[0]); i++) {
        errno = 0;
        long v = sysconf(N[i].name);
        if (v == -1 && errno == 0) {
            printf("  %-22s = -1  (indeterminate)\n", N[i].lbl);
            n++;
        }
    }
    printf("  共 %d 项 indeterminate。它们不是「不支持」，而是「这个实现不回答」。\n", n);

    static const struct { int name; const char *lbl; } P[] = {
        { _PC_NAME_MAX, "_PC_NAME_MAX" }, { _PC_LINK_MAX, "_PC_LINK_MAX" },
        { _PC_PATH_MAX, "_PC_PATH_MAX" }, { _PC_PIPE_BUF, "_PC_PIPE_BUF" },
        { _PC_MAX_CANON, "_PC_MAX_CANON" }, { _PC_MAX_INPUT, "_PC_MAX_INPUT" },
        { _PC_ASYNC_IO, "_PC_ASYNC_IO" }, { _PC_SYNC_IO, "_PC_SYNC_IO" },
        { _PC_PRIO_IO, "_PC_PRIO_IO" }, { _PC_FILESIZEBITS, "_PC_FILESIZEBITS" },
        { _PC_2_SYMLINKS, "_PC_2_SYMLINKS" },
    };
    printf("\n  pathconf(\"/\") 侧：\n");
    for (size_t i = 0; i < sizeof(P) / sizeof(P[0]); i++) {
        errno = 0;
        long v = pathconf("/", P[i].name);
        if (v == -1 && errno == 0)
            printf("  %-22s = -1  (indeterminate)\n", P[i].lbl);
    }
    printf("  （_PC_ASYNC_IO/_PC_SYNC_IO/_PC_PRIO_IO 在 glibc 里只在「问了普通文件」时才有答案，\n");
    printf("    问目录一律返回 -1。见 sysdeps/posix/pathconf.c:128-148 的 S_ISREG 判断。）\n");
}

/* ---------- ② 安全封装：把「限制值」和「状态」分开 ---------- */
enum qstat { Q_OK, Q_INDETERMINATE, Q_ERROR };

static long query_sysconf(int name, enum qstat *st)
{
    errno = 0;
    long v = sysconf(name);
    if (v != -1) { *st = Q_OK; return v; }
    if (errno == 0) { *st = Q_INDETERMINATE; return -1; }
    *st = Q_ERROR;
    return -1;
}

static const char *qname(enum qstat s)
{
    switch (s) {
    case Q_OK:            return "OK";
    case Q_INDETERMINATE: return "INDETERMINATE";
    default:              return "ERROR";
    }
}

/* ---------- ③ 降级阶梯：查不到时退到哪一级 ---------- */

/* 目标：拿一个「安全的文件名长度上限」。三级退让：
 *   一级  sysconf(_SC_NAME_MAX)? 不存在 —— NAME_MAX 是路径相关的，只能 pathconf
 *   二级  pathconf(path, _PC_NAME_MAX)
 *   三级  编译期 NAME_MAX（<limits.h>，本机 255）—— 但它也可能没定义
 *   四级  _POSIX_NAME_MAX（保证下限，永远有）—— 但可能小到没法用（14）
 */
static long name_max_ladder(const char *path, const char **how)
{
    if (path) {
        errno = 0;
        long v = pathconf(path, _PC_NAME_MAX);
        if (v != -1) { *how = "pathconf(_PC_NAME_MAX)"; return v; }
    }
#ifdef NAME_MAX
    *how = "<limits.h> NAME_MAX";
    return NAME_MAX;
#else
    *how = "_POSIX_NAME_MAX（保证下限）";
    return _POSIX_NAME_MAX;
#endif
}

int main(void)
{
    sweep();

    printf("\n### ② 安全封装的三种结果\n");
    static const struct { int name; const char *lbl; } T[] = {
        { _SC_OPEN_MAX, "_SC_OPEN_MAX" },
        { _SC_TZNAME_MAX, "_SC_TZNAME_MAX" },
        { 9999, "9999（非法 name）" },
    };
    for (size_t i = 0; i < sizeof(T) / sizeof(T[0]); i++) {
        enum qstat st;
        long v = query_sysconf(T[i].name, &st);
        printf("  %-22s -> status=%-14s value=%ld\n", T[i].lbl, qname(st), v);
    }

    printf("\n### ③ 降级阶梯：要一个文件名长度上限\n");
    const char *how = "?";
    long nm = name_max_ladder("/tmp", &how);
    printf("  pathconf(\"/tmp\") 成功 -> %ld  （来源：%s）\n", nm, how);
    how = "?";
    nm = name_max_ladder("/no/such/dir", &how);
    printf("  pathconf(\"/no/such/dir\") 失败 -> %ld （来源：%s）\n", nm, how);
    printf("  阶梯的含义：能用运行时查询就用；查不到就退到编译期宏；宏也没有就退到\n");
    printf("  POSIX 保证下限（本机 _POSIX_NAME_MAX=%d），并按这个值把缓冲区放大一点。\n",
           _POSIX_NAME_MAX);

    printf("\n### ④ 两个容易踩的「假 indeterminate」\n");
    errno = 0;
    long x = pathconf("/", _PC_MAX_CANON);
    printf("  pathconf(\"/\", _PC_MAX_CANON) = %ld, errno=%d  —— 问的不是终端，语义上无意义\n",
           x, errno);
    errno = 0;
    long y = pathconf("/", _PC_VDISABLE);
    printf("  pathconf(\"/\", _PC_VDISABLE)  = %ld, errno=%d  —— glibc 直接返回 _POSIX_VDISABLE，\n",
           y, errno);
    printf("     连「这是不是终端」都不检查（sysdeps/posix/pathconf.c:115-119）。\n");
    printf("  这两类「看起来有值、其实没意义」的结果，比 -1 更危险。\n");
    return 0;
}
```

编译运行：

```bash
gcc -O0 -Wall -Wextra -o c11_4_indeterminate c11_4_indeterminate.c && ./c11_4_indeterminate
```

逐段看：

| 段 | 观察 | 说明 |
|----|------|------|
| ① | `sysconf` 侧**只有 4 项**：`_SC_TZNAME_MAX` / `_SC_SYMLOOP_MAX` / `_SC_MQ_OPEN_MAX` / `_SC_SEM_NSEMS_MAX` | 其余 14 项限制类都能给出数（见 [11.2](11.2-runtime-limits.md) ②） |
| ① | `pathconf("/")` 侧 3 项 `_PC_ASYNC_IO` / `_PC_SYNC_IO` / `_PC_PRIO_IO` | 它们**不是真的 indeterminate**，而是「问目录没意义」：glibc 对这三个做了 `S_ISREG \|\| S_ISBLK` 判断（`sysdeps/posix/pathconf.c:128-148`），不满足就 `return -1` 且不设 `errno`——**与真 indeterminate 同形** |
| ② | 三种状态被 `enum qstat` 明确分开 | 关键设计：**值（`long`）与状态（`enum`）分开返回**，不再靠 `-1` 兼当哨兵 |
| ② | `_SC_OPEN_MAX → OK 100`、`_SC_TZNAME_MAX → INDETERMINATE -1`、`9999 → ERROR -1` | 后两者返回值**一模一样**，只有状态不同。这就是为什么必须封装 |
| ③ | `pathconf("/tmp")` → 255（来源 `pathconf`）；`pathconf("/no/such/dir")` → 255（来源 **`<limits.h> NAME_MAX`**） | 同一条降级函数，两条不同来源——**调用者拿到的 255 是从哪来的，被显式写回 `how`** |
| ④ | `pathconf("/", _PC_MAX_CANON) = 255, errno=0`；`_PC_VDISABLE = 0, errno=0` | glibc **不检查「是不是终端」**：`_PC_MAX_CANON` → `return MAX_CANON;`（255）、`_PC_VDISABLE` → `return _POSIX_VDISABLE;`（0）。man-pages 明写这两项「`path` must refer to a terminal」，但实现不验 |

### 2.1 为什么 `_SC_TZNAME_MAX` 恒为 `-1`

glibc 的实现就是一行（`sysdeps/posix/sysconf.c:102-103`）：

```c
    case _SC_TZNAME_MAX:
      return -1;
```

**没有 `#ifdef`、没有读文件、没有 `__set_errno`。** 它和 `default:` 分支（`:64-66`，会设 `EINVAL`）的区别就是**不碰 `errno`**——这正是「indeterminate」的实现方式。

对比 `_SC_NGROUPS_MAX`（`:85-90`）用的是另一套手法：

```c
    case _SC_NGROUPS_MAX:
#ifdef	NGROUPS_MAX
      return NGROUPS_MAX;
#else
      return -1;
#endif
```

## 3. 查不到时的降级阶梯

TLPI 在 §11.4 给的建议是「用特别的手段（ad hoc techniques）决定一个程序可以依赖的限制」。整理成四级：

| 级别 | 手段 | 优点 | 缺点 | 本仓库的例子 |
|------|------|------|------|------------|
| 1 | `pathconf(path, _PC_NAME_MAX)` | 最准，随文件系统 | 可能 `-1`；要能访问那个目录 | `name_max_ladder("/tmp", …)` → 255 |
| 2 | `<limits.h>` 的 `NAME_MAX` | 无系统调用 | glibc **可能 `#undef` 掉**（`OPEN_MAX`/`ARG_MAX`/`LINK_MAX` 就是这样） | 回退到 255 |
| 3 | `_POSIX_NAME_MAX` | **永远有**（只要有 `<unistd.h>`） | 只是保底值，可能小到不可用（14） | 回退到 14 |
| 4 | 动态扩容 | 不依赖任何上限 | 要自己管内存 / 多次系统调用 | 路径解析、`readline` 类场景 |

代码骨架（`c11_4_indeterminate.c` 的 `name_max_ladder()`）：

```c
static long name_max_ladder(const char *path, const char **how)
{
    if (path) {
        errno = 0;
        long v = pathconf(path, _PC_NAME_MAX);
        if (v != -1) { *how = "pathconf(_PC_NAME_MAX)"; return v; }
    }
#ifdef NAME_MAX
    *how = "<limits.h> NAME_MAX";
    return NAME_MAX;
#else
    *how = "_POSIX_NAME_MAX（保证下限）";
    return _POSIX_NAME_MAX;
#endif
}
```

> 第 2 级的 `#ifdef` 是**必须的**：glibc 的 `bits/local_lim.h` 在 `#include <linux/limits.h>` 之后会主动 `#undef NR_OPEN / LINK_MAX / OPEN_MAX / ARG_MAX`，注释里解释了理由——「the limit can be changed at runtime and therefore the macro must not be defined」。所以同一个体系里，有的宏在、有的宏不在。

## 4. 常见坑

| 坑 | 说明 |
|----|------|
| 把 `-1` 当「不支持」/「没有限制」 | 三种情况共用 `-1`：indeterminate、选项不支持、真错误。一律要先 `errno = 0` 再判 |
| 不封装，直接 `if (v == -1) use_default;` | 会把 `EINVAL`（name 写错，真 bug）也静默降级掉。真错误必须崩 |
| 忘了 `errno = 0` 只清一次 | 见 [11.2](11.2-runtime-limits.md) ⑥：会把 indeterminate 误报成错误 |
| 只判 `ENOENT` / 只看返回值 | `pathconf` 侧还有 `ENOTDIR`(20)、`EBADF`(9)、`EACCES`、`ELOOP`、`ENAMETOOLONG`（[11.3](11.3-file-related-limits.md) C 段实测） |
| 拿 `_PC_MAX_CANON` / `_PC_VDISABLE` 问目录 | glibc 不检查终端就返回值（④ 段）。**「有值」不等于「有意义」** |
| 用 `_POSIX_NAME_MAX`(14) 当实际缓冲 | 那是保底值；按它分配会白白截断合法文件名 |
| 假定「本机的 indeterminate 清单」跨平台不变 | 本机 4 项，别的 libc/内核可能更多或更少。**清单要实测，不能背** |

## 5. HFT / 嵌入式关联

| 场景 | 本节机制怎么兑现 |
|------|----------------|
| 路径解析缓冲 | 别写 `char path[PATH_MAX]`（`PATH_MAX` 还可能没定义）。要么按 `pathconf` 结果分配，要么用 `asprintf`/realloc 走第 4 级动态扩容 |
| 启动自检日志 | 把「本机 indeterminate 清单」在启动时打一遍（① 段就是模板）：换容器/换 libc 后，同一份配置为什么走了不同分支，这份日志能直接回答 |
| 嵌入式 BusyBox rootfs | 越裁剪的实现越多 indeterminate。程序不能假设「查得到」，必须真有一个回退路径 |
| IPC 队列/信号量 | `_SC_MQ_OPEN_MAX` / `_SC_SEM_NSEMS_MAX` 在本机就是 indeterminate（4 项里的两项）。要开 POSIX 消息队列/信号量时**不能靠 `sysconf` 定容量**，得按 `_POSIX_MQ_OPEN_MAX`(8) / `_POSIX_SEM_NSEMS_MAX`(256) 保底 + 运行时试错 |
| 终端相关代码 | 判「是不是 tty」用 `isatty(fd)`，**不要**用 `pathconf(fd, _PC_MAX_CANON)` 是否有值来判——它永远有值（④ 段） |
| 配置校验 | `_PC_SYNC_IO` / `_PC_ASYNC_IO` / `_PC_PRIO_IO` 这三个在「普通文件」和「目录/管道」上答案不同；配置文件里按对象类型分别处理 |

<summary>代码自测（Q&A）</summary>

**Q1：什么叫 indeterminate？它和「不支持」有什么区别？**
A：「不支持」是**选项**没有实现（[11.5](11.5-system-options.md)），「indeterminate」是**限制**存在但实现不告诉你确切值。二者在返回值上都是 `-1`，且都不改动 `errno`——**完全同形**。区别只在于你问的 `name` 属于限制类还是选项类。

**Q2：本机哪些 `_SC_*` 是 indeterminate？**
A：4 项：`_SC_TZNAME_MAX`、`_SC_SYMLOOP_MAX`、`_SC_MQ_OPEN_MAX`、`_SC_SEM_NSEMS_MAX`。其中 `_SC_TZNAME_MAX` 在 glibc 里就是一行 `case _SC_TZNAME_MAX: return -1;`（`sysdeps/posix/sysconf.c:102-103`），连 `errno` 都不碰。

**Q3：为什么说 `_PC_ASYNC_IO` 在目录上的 `-1` 不是「真 indeterminate」？**
A：因为 glibc 是**主动拒绝回答**：`sysdeps/posix/pathconf.c:128-141` 里 `_PC_ASYNC_IO` 先 `stat`，然后 `if (!S_ISREG(st.st_mode) && !S_ISBLK(st.st_mode)) return -1;`。对目录不满足条件 → 返回 `-1` 不设 `errno`。语义上是「问错了对象」，形式上却与 indeterminate 一致。换成普通文件 fd 就得到 `1`（[11.3](11.3-file-related-limits.md) B 段实测）。

**Q4：安全封装为什么要把「状态」和「值」分开返回？**
A：因为 `-1` 是合法值也是错误标志，一个 `long` 放不下两种信息。`c11_4_indeterminate.c` 用 `enum qstat { Q_OK, Q_INDETERMINATE, Q_ERROR }` 作输出参数，调用点写 `if (st == Q_OK) use(v); else fallback();`——**真错误（`Q_ERROR`）必须崩**，不能静默降级，否则 `sysconf(9999)` 这种拼错常量的 bug 会一直藏下去。

**Q5：查不到 `_PC_NAME_MAX` 时，退到 `NAME_MAX` 还是 `_POSIX_NAME_MAX`？**
A：先 `NAME_MAX`（本机 255），**它可能不存在**（glibc 会 `#undef` 一部分限制宏），所以外面要套 `#ifdef`；再退 `_POSIX_NAME_MAX`（永远有，但只有 14）。实测两条路径：`pathconf("/tmp")` 成功给 255；`pathconf("/no/such/dir")` 失败后退到 `NAME_MAX` 也是 255——**同值不同源，所以 demo 里把来源字符串一起返回**。

**Q6：④ 段那两个「假 indeterminate」危险在哪？**
A：`pathconf("/", _PC_MAX_CANON) = 255`、`pathconf("/", _PC_VDISABLE) = 0`，两个都 `errno=0`，看起来完全正常。但 man-pages 明写这两项「`fd` or `path` must refer to a terminal」——glibc 不检查（`sysdeps/posix/pathconf.c:51-55` / `:115-119` 直接 `return MAX_CANON;` / `return _POSIX_VDISABLE;`）。**「返回了值」被误当成「问了一个有效的对象」**，这类错误比 `-1` 难查得多。判终端要用 `isatty()`。

**Q7：为什么「本机 indeterminate 清单」不能背下来用？**
A：它是**实现选择**，不是标准规定。标准只说「允许 indeterminate」，没说哪些必须 indeterminate。本机 glibc 2.39 是 4 + 3 项，换 musl / 换嵌入式 libc / 换个内核版本都可能不同。所以清单只能在目标环境上实测（① 段那段 sweep 代码就是要抄到自检里去的）。

</details>
