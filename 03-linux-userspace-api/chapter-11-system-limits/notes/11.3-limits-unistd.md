## 要点

| 头文件 | 内容 |
|--------|------|
| `<limits.h>` | `_POSIX_*_MAX` 标准最低下限；部分系统还有实现定义的 `NAME_MAX` 等 |
| `<unistd.h>` | 特性宏：`_POSIX_THREADS`、`_POSIX_REALTIME_SIGNALS` 等 |

> 宏只代表**编译期声明**；裁剪内核 / 容器可能关掉功能 → **可靠做法仍是 `sysconf` 运行时校验**。

## 与 C 语言学习的关系

系统限制和信息 API 涉及 C 语言的可移植性编程。`sysconf`/`pathconf` 返回 `long`，需要检查返回值和 errno。这部分内容训练 C 程序员不硬编码系统参数（如 `OPEN_MAX`、`PAGE_SIZE`），而是运行时查询——这是可移植 C 编程的基本素养。

## 常见陷阱

1. **硬编码系统限制**

```c
#define MAX_FD 256  /* 错误假设 */
long max_fd = sysconf(_SC_OPEN_MAX);  /* 运行时查询 */
```

系统限制值因平台和配置而异。硬编码会导致程序在新环境上失败。应用 sysconf/pathconf 运行时查询。

2. **sysconf 返回值未检查**

```c
long val = sysconf(_SC_OPEN_MAX);
/* val 可能是 -1（无限制或出错） */
```

sysconf 返回 -1 可能表示"无限制"或"出错"。需要检查 errno 来区分：先清除 errno，调用后检查。

3. **uname 结构体字段假设**

```c
struct utsname buf;
uname(&buf);
printf("%s", buf.release);  /* 字段长度有限! */
```

utsname 各字段长度有限（通常 65 字节）。过长的字段会被截断。不要假设完整信息。

## 自测题

**题目 1（选择）：** 获取系统最大打开文件数，应该用？
A. 宏 OPEN_MAX
B. sysconf(_SC_OPEN_MAX)
C. getrlimit(RLIMIT_NOFILE)
D. B 或 C

<details>
<summary>参考答案</summary>

D。sysconf 返回系统默认值，getrlimit 返回当前进程的限制。两者都可，但 getrlimit 更精确。硬编码 OPEN_MAX 宏不可移植。

</details>

**题目 2（判断）：** `sysconf(_SC_OPEN_MAX)` 返回 -1 一定表示出错。

<details>
<summary>参考答案</summary>

错误。返回 -1 可能表示"无限制"或"出错"。需要先清除 errno，调用后检查 errno 是否被设置来区分。

</details>

**题目 3（踩坑）：** 以下代码有什么问题？
```c
long page_size = 4096;  /* 硬编码 */
void *p = mmap(NULL, page_size, ...);
```

<details>
<summary>参考答案</summary>

页面大小因平台而异（x86=4KB, ARM64 可能=16KB/64KB）。应运行时查询：`long page_size = sysconf(_SC_PAGESIZE);`

</details>

**题目 4（应用）：** 写代码获取当前进程的文件描述符限制并打印。

<details>
<summary>参考答案</summary>

```c
struct rlimit rl;
if (getrlimit(RLIMIT_NOFILE, &rl) == 0) {
    printf("soft: %lu, hard: %lu
",
           (unsigned long)rl.rlim_cur,
           (unsigned long)rl.rlim_max);
}
```

</details>
