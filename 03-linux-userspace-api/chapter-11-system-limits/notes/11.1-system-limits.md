# 11.1 System Limits 系统限制

> 本章：[TLPI 第 11 章 — System Limits and Options](../README.md)

## 本节讲什么

本章要解决的是**可移植性**问题：同一个程序在别人的机器上为什么读写文件会失败、`exec` 会报错、管道里的消息会撕裂。根源是「上限」不是常量——它随内核配置、`rlimit`、文件系统、容器裁剪而变。

本节只回答三个问题（其余小节展开）：

1. **limit 和 option 是两回事**吗？为什么 man-pages 要把它们写成两段？
2. SUSv3 把限制分成**哪三类**？为什么这个分类决定了你该用哪个查询函数？
3. `<limits.h>` 里那个 `_POSIX_NAME_MAX = 14` 是「实际值」还是「最低承诺」？

---

## 1. 术语：limit 与 option 是两类问题

man-pages 6.19 `sysconf(3)` 的 DESCRIPTION 把它们分开写，原文：

> At compile time this is done by including `<unistd.h>` and/or `<limits.h>` and testing the value of certain macros.
>
> At run time, one can ask for numerical values using the present function `sysconf()`. One can ask for numerical values that may depend on the filesystem in which a file resides using `fpathconf(3)` and `pathconf(3)`. One can ask for string values using `confstr(3)`.

| 概念 | 问的是什么 | 答案的形状 | 例子 |
|------|-----------|-----------|------|
| **Limit（限制）** | 某个资源的**上限/下限** | 一个数（可能 indeterminate） | `ARG_MAX`、`OPEN_MAX`、`NAME_MAX`、`PATH_MAX`、`PIPE_BUF` |
| **Option（选项）** | 某个可选特性**有没有实现** | 支持 / 不支持（三态，见 [11.5](11.5-system-options.md)） | `_POSIX_THREADS`、`_POSIX_REALTIME_SIGNALS`、`_POSIX_BARRIERS` |

两者**答案的形态完全不同**，但查询入口共用同一个 `sysconf()`、返回值也共用同一个 `-1`。这是本章最大的坑的来源：[11.2](11.2-runtime-limits.md) 会看到「限制 indeterminate」和「选项不支持」在 `-1` + `errno` 上**完全无法区分**。

---

## 2. SUSv3 的三类限制（决定用哪个查询函数）

| 类 | 名字 | 特征 | 查询入口 | 本章例子 |
|----|------|------|---------|---------|
| **1** | 运行时恒定 | 进程生命期内不变；`<limits.h>` 里可能根本没定义 | `sysconf()` | `_SC_CLK_TCK`、`_SC_PAGESIZE`、`_SC_VERSION` |
| **2** | 路径名相关 | **依赖具体文件系统 / 挂载点**，同一台机器上两个目录答案可以不同 | `pathconf()` / `fpathconf()` | `_PC_NAME_MAX`、`_PC_LINK_MAX`、`_PC_FILESIZEBITS` |
| **3** | 运行时可增 | 标准只保证「不低于下限」，运行时**可以改大** | `sysconf()` + `rlimit` | `_SC_OPEN_MAX` ↔ `RLIMIT_NOFILE` |

类 3 是最容易误判的一类。TLPI 的说法是「值可以增加」——而 Linux 上它压根**不是一个上限**，只是 `getrlimit(RLIMIT_NOFILE).rlim_cur` 的当前快照。看第 4 节的实测：

```
--- 改 rlimit 之前 ---
  _SC_OPEN_MAX     = 100
setrlimit(soft -> 50) 成功
--- 改 rlimit 之后 ---
  _SC_OPEN_MAX     = 50
```

`sysconf(_SC_OPEN_MAX)` 自己**会变**。所以 man-pages 那句「The values obtained from these functions are system configuration constants. They do not change during the lifetime of a process.」对类 3 是**不成立**的（[11.7 习题 11-1](11.7-exercises.md) 会把这个矛盾单独拎出来）。

---

## 3. 下限宏：`_POSIX_*` 是「保证」不是「实际」

man-pages `sysconf(3)` 原文：

> If the constant is defined, it gives a guaranteed value, and a greater value might actually be supported.

所以 `_POSIX_NAME_MAX` 是 **14** 不代表文件名只能 14 个字符，而是「**POSIX 承诺至少 14**——一个只支持 14 字符的实现也合法」。本机 255，是「更大」的那一侧。

| 宏 | POSIX 保证的下限 | 本机实测 | 差多少 |
|----|----------------|---------|-------|
| `_POSIX_ARG_MAX` | 4096 | 2097152（`_SC_ARG_MAX`） | 512× |
| `_POSIX_CHILD_MAX` | 25 | 54956（`_SC_CHILD_MAX`） | 2198× |
| `_POSIX_NGROUPS_MAX` | 8 | 65536（`_SC_NGROUPS_MAX`） | 8192× |
| `_POSIX_OPEN_MAX` | 20 | 100（`_SC_OPEN_MAX`） | 5× |
| `_POSIX_STREAM_MAX` | 8 | 16（`_SC_STREAM_MAX`） | 2× |
| `_POSIX_LOGIN_NAME_MAX` | 9 | 256（`_SC_LOGIN_NAME_MAX`） | 28× |
| `_POSIX_TTY_NAME_MAX` | 9 | 32（`_SC_TTY_NAME_MAX`） | 3.6× |
| `_POSIX_NAME_MAX` | 14 | 255（`NAME_MAX`） | 18× |
| `_POSIX_PATH_MAX` | 256 | 4096（`PATH_MAX`） | 16× |
| `_POSIX_PIPE_BUF` | 512 | 4096（`PIPE_BUF`） | 8× |

一旦按「保证下限」去分配缓冲区，就会在**真实机器上偏小**；一旦按「本机实测」写死，就会在**别的机器上偏大或偏小**。两条路都不通，所以要用运行时查询（[11.2](11.2-runtime-limits.md)）。

> **诚实说明**：上表「本机实测」一列来自第 4 节的同一次运行。其中 `_SC_CHILD_MAX`（跟 `RLIMIT_NPROC` 走）在容器里会随宿主机负载变化——重跑一次就可能是另一个数（本仓库两次运行分别拿到 54956 与 56783）。**只有 `_SC_ARG_MAX` / `_SC_OPEN_MAX` / `_SC_PAGESIZE` 这类由固定 rlimit 或编译期常量决定的项是稳定的。**

## 4. 代码：三类限制的现场对照

完整源码 [`code/c11_1_three_kinds.c`](../code/c11_1_three_kinds.c)：

```c
/* c11_1_three_kinds.c — Ch11 §11.1：三类限制的现场对照
 *
 * TLPI 把 SUSv3 的限制分三类，本节只用一次实验把「类 1 恒定」和
 * 「类 3 运行时可改」摆在一起：
 *
 *   实验：先查四个 _SC_*，再把 RLIMIT_NOFILE 的 soft 减半，再查同样的四项。
 *         _SC_CLK_TCK / _SC_PAGESIZE / _SC_VERSION 一位不变（类 1）；
 *         _SC_OPEN_MAX 跟着 RLIMIT_NOFILE 走（类 3 —— 它甚至不是「上限」，
 *         只是一个当前值）。
 *
 * 类 2（路径相关）需要另一个文件系统才能看出差别，放到 §11.3 / 习题 11-2。
 *
 * 编译： gcc -O0 -Wall -Wextra -o c11_1_three_kinds c11_1_three_kinds.c
 * 取材： sysconf(3) 的 RETURN VALUE 段（man-pages 6.19）
 *        glibc 2.39 sysdeps/posix/sysconf.c:82-83（_SC_CLK_TCK -> __getclktck()）
 *                              :92-93（_SC_OPEN_MAX -> __getdtablesize()）
 *                  sysdeps/posix/getdtsz.c:32（= getrlimit(RLIMIT_NOFILE).rlim_cur）
 *                  sysdeps/unix/sysv/linux/getclktck.c:22-23（SYSTEM_CLK_TCK 兜底 100）
 *        Linux v6.6 include/uapi/asm-generic/resource.h:30-31（RLIMIT_NOFILE = 7）
 */
#define _GNU_SOURCE
#include <errno.h>
#include <limits.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <sys/resource.h>
#include <unistd.h>

static long sc(int name)
{
    errno = 0;
    return sysconf(name);
}

static const struct { int name; const char *lbl; } FOUR[] = {
    { _SC_CLK_TCK,      "_SC_CLK_TCK" },
    { _SC_PAGESIZE,     "_SC_PAGESIZE" },
    { _SC_VERSION,      "_SC_VERSION" },
    { _SC_OPEN_MAX,     "_SC_OPEN_MAX" },
};

static void dump_four(const char *when)
{
    printf("--- %s ---\n", when);
    for (size_t i = 0; i < sizeof(FOUR) / sizeof(FOUR[0]); i++)
        printf("  %-16s = %ld\n", FOUR[i].lbl, sc(FOUR[i].name));
}

int main(void)
{
    printf("### 一次实验：把 RLIMIT_NOFILE 的 soft 减半，再看这四项\n");
    dump_four("改 rlimit 之前");

    struct rlimit r;
    if (getrlimit(RLIMIT_NOFILE, &r) != 0) {
        perror("getrlimit");
        return 1;
    }
    printf("\nRLIMIT_NOFILE: soft=%lu hard=%lu\n",
           (unsigned long)r.rlim_cur, (unsigned long)r.rlim_max);

    struct rlimit low = r;
    low.rlim_cur = (r.rlim_max >= 10) ? r.rlim_max / 2 : r.rlim_max;   /* 只降不升 */
    if (setrlimit(RLIMIT_NOFILE, &low) != 0) {
        printf("setrlimit 失败: %s\n", strerror(errno));
        return 1;
    }
    printf("setrlimit(soft -> %lu) 成功\n\n", (unsigned long)low.rlim_cur);

    dump_four("改 rlimit 之后");

    printf("\n结论：前三项与环境无关（类 1 运行时恒定）；\n");
    printf("      _SC_OPEN_MAX 只是「RLIMIT_NOFILE 的当前值」，改了它就变（类 3）。\n");
    printf("      glibc 的实现是一行：return __getrlimit(RLIMIT_NOFILE,&ru)<0 ? OPEN_MAX : ru.rlim_cur;\n");

    printf("\n### SUSv3 保证的只是「不低于这个下限」（<limits.h> / <unistd.h>）\n");
    printf("  %-22s %-10s %s\n", "保证下限宏", "值", "本机实测（未改 rlimit 时）");
    printf("  %-22s %-10s %ld\n", "(CLK_TCK：无下限宏)", "--", sc(_SC_CLK_TCK));
    printf("  %-22s %-10d %ld\n", "_POSIX_OPEN_MAX", _POSIX_OPEN_MAX,
           (long)r.rlim_max);
    printf("  %-22s %-10d %ld\n", "_POSIX_CHILD_MAX", _POSIX_CHILD_MAX, sc(_SC_CHILD_MAX));
    printf("  %-22s %-10d %ld\n", "_POSIX_NGROUPS_MAX", _POSIX_NGROUPS_MAX, sc(_SC_NGROUPS_MAX));
    printf("  %-22s %-10d %ld\n", "_POSIX_STREAM_MAX", _POSIX_STREAM_MAX, sc(_SC_STREAM_MAX));
    printf("  %-22s %-10d %ld\n", "_POSIX_LOGIN_NAME_MAX", _POSIX_LOGIN_NAME_MAX,
           sc(_SC_LOGIN_NAME_MAX));
    printf("  %-22s %-10d %ld\n", "_POSIX_TTY_NAME_MAX", _POSIX_TTY_NAME_MAX, sc(_SC_TTY_NAME_MAX));
    printf("  %-22s %-10d %ld\n", "_POSIX_NAME_MAX", _POSIX_NAME_MAX, (long)NAME_MAX);
    printf("  %-22s %-10d %ld\n", "_POSIX_PATH_MAX", _POSIX_PATH_MAX, (long)PATH_MAX);
    printf("  %-22s %-10d %ld\n", "_POSIX_PIPE_BUF", _POSIX_PIPE_BUF, (long)PIPE_BUF);

    printf("\n注意四件事：\n");
    printf("  1) 下限宏是「保证」，不是「实际」。_POSIX_NAME_MAX=14 看着很荒唐，\n");
    printf("     但 POSIX 只承诺 14 —— 它允许一个文件系统只支持 14 字符文件名。\n");
    printf("  2) <limits.h> 里 NAME_MAX/PATH_MAX/PIPE_BUF 有定义，ARG_MAX/OPEN_MAX/LINK_MAX\n");
    printf("     却被 glibc 主动 #undef 掉了（见 §11.3 的源码）。用它们之前先 #ifdef。\n");
    printf("  3) _SC_CLK_TCK 不等于内核的 HZ：它是「times() 的节拍频率」，\n");
    printf("     本机是 %ld，而内核 HZ 是内核编译期常量，两者不必相同。\n", sc(_SC_CLK_TCK));
    printf("  4) 第一行连下限宏都没有：全库找不到 _POSIX_CLK_TCK。POSIX.1-2017\n");
    printf("     <limits.h>/<sysconf> 原文只说「The symbol CLK_TCK is obsolescent\n");
    printf("     and removed.」—— 它只保证 _SC_CLK_TCK 查得到，不承诺任何下限。\n");
    return 0;
}
```

编译运行：

```bash
gcc -O0 -Wall -Wextra -o c11_1_three_kinds c11_1_three_kinds.c && ./c11_1_three_kinds
```

CE（gcc 13.3.0 / x86-64 / Ubuntu 24.04）实测：

```text

--- 改 rlimit 之前 ---
  _SC_CLK_TCK      = 100
  _SC_PAGESIZE     = 4096
  _SC_VERSION      = 200809
  _SC_OPEN_MAX     = 100

RLIMIT_NOFILE: soft=100 hard=100
setrlimit(soft -> 50) 成功

--- 改 rlimit 之后 ---
  _SC_CLK_TCK      = 100
  _SC_PAGESIZE     = 4096
  _SC_VERSION      = 200809
  _SC_OPEN_MAX     = 50

结论：前三项与环境无关（类 1 运行时恒定）；
      _SC_OPEN_MAX 只是「RLIMIT_NOFILE 的当前值」，改了它就变（类 3）。
      glibc 的实现是一行：return __getrlimit(RLIMIT_NOFILE,&ru)<0 ? OPEN_MAX : ru.rlim_cur;

### SUSv3 保证的只是「不低于这个下限」（<limits.h> / <unistd.h>）
  保证下限宏        值        本机实测（未改 rlimit 时）
  (CLK_TCK：无下限宏) --         100
  _POSIX_OPEN_MAX        20         100
  _POSIX_CHILD_MAX       25         54956
  _POSIX_NGROUPS_MAX     8          65536
  _POSIX_STREAM_MAX      8          16
  _POSIX_LOGIN_NAME_MAX  9          256
  _POSIX_TTY_NAME_MAX    9          32
  _POSIX_NAME_MAX        14         255
  _POSIX_PATH_MAX        256        4096
  _POSIX_PIPE_BUF        512        4096

注意四件事：
  1) 下限宏是「保证」，不是「实际」。_POSIX_NAME_MAX=14 看着很荒唐，
     但 POSIX 只承诺 14 —— 它允许一个文件系统只支持 14 字符文件名。
  2) <limits.h> 里 NAME_MAX/PATH_MAX/PIPE_BUF 有定义，ARG_MAX/OPEN_MAX/LINK_MAX
     却被 glibc 主动 #undef 掉了（见 §11.3 的源码）。用它们之前先 #ifdef。
  3) _SC_CLK_TCK 不等于内核的 HZ：它是「times() 的节拍频率」，
     本机是 100，而内核 HZ 是内核编译期常量，两者不必相同。
  4) 第一行连下限宏都没有：全库找不到 _POSIX_CLK_TCK。POSIX.1-2017
     <limits.h>/<sysconf> 原文只说「The symbol CLK_TCK is obsolescent
     and removed.」—— 它只保证 _SC_CLK_TCK 查得到，不承诺任何下限。
```

逐条看：

| 观察 | 说明 |
|------|------|
| 改 `rlimit` 前三项 `_SC_CLK_TCK=100` / `_SC_PAGESIZE=4096` / `_SC_VERSION=200809`，改后**一字不变** | 类 1：与进程环境无关 |
| `_SC_OPEN_MAX` 从 **100** → **50** | 类 3：它就是 `RLIMIT_NOFILE.rlim_cur` |
| `_SC_VERSION = 200809` 而不是「版本号 3」 | POSIX 用**修订版年月**表示：2008 年 9 月 = POSIX.1-2008 |
| `_POSIX_NAME_MAX=14` vs 实测 `NAME_MAX=255` | 18 倍差距，说明下限宏与实现值的量级没关系 |
| `(CLK_TCK：无下限宏) -- 100` | 全库（POSIX `<limits.h>` / `<unistd.h>` / glibc `posix1_lim.h`）都搜不到 `_POSIX_CLK_TCK`。POSIX.1-2017 只说「The symbol **CLK_TCK** is obsolescent and removed. It is replaced with the phrase "clock ticks per second".」——它保证 `_SC_CLK_TCK` 查得到，**不承诺任何下限** |

### 4.1 glibc 是怎么实现的（两个函数九行）

`_SC_OPEN_MAX` 走到 `sysdeps/posix/sysconf.c:92-93`：

```c
    case _SC_OPEN_MAX:
      return __getdtablesize ();
```

而 `__getdtablesize` 的整个函数体（`sysdeps/posix/getdtsz.c:25-33`）是：

```c
int
__getdtablesize (void)
{
  struct rlimit ru;

  /* This should even work if `getrlimit' is not implemented.  POSIX.1
     does not define this function but we will generate a stub which
     returns -1.  */
  return __getrlimit (RLIMIT_NOFILE, &ru) < 0 ? OPEN_MAX : ru.rlim_cur;
}
```

> **「`_SC_OPEN_MAX` 会变」不是行为怪异，就是字面上一行 `return ... ru.rlim_cur`。** 失败时兜底用的 `OPEN_MAX` 是 **256**（`sysdeps/unix/sysv/linux/getdtsz.c:19`，注释写着 `/* This comes from the Linux kernel header. */`），不是 POSIX 的 `_POSIX_OPEN_MAX=20`。

`_SC_CLK_TCK` 走 `:82-83` → `__getclktck()`（`sysdeps/unix/sysv/linux/getclktck.c:22-31`）：

```c
#ifndef SYSTEM_CLK_TCK
# define SYSTEM_CLK_TCK	100
#endif

/* Return frequency of times().  */
int
__getclktck (void)
{
  return GLRO(dl_clktck) ?: SYSTEM_CLK_TCK;
}
```

内核的 `HZ`（编译期常量，常见 250 / 1000）与它**没有关系**——`times()` 的节拍频率是内核通过 `AT_CLKTCK` 辅助向量（auxv）告诉用户态的，本机就是 100。

## 5. 常见坑

| 坑 | 说明 |
|----|------|
| `#define MAX_PATH 256` / `char buf[256]` 装路径 | POSIX 只保证 256，本机 4096。反之在嵌入式裁剪内核上可能真的只有 256 |
| 用 `_POSIX_NAME_MAX`（14）去分配文件名缓冲 | 只是保底值，会造成不必要的截断；用 `pathconf(path, _PC_NAME_MAX)`（[11.3](11.3-file-related-limits.md)） |
| 以为 `<limits.h>` 一定有 `OPEN_MAX` / `ARG_MAX` | glibc 在 `bits/local_lim.h` 里**主动 `#undef`** 了 `NR_OPEN` / `LINK_MAX` / `OPEN_MAX` / `ARG_MAX`；不加 `#ifdef` 直接 `printf("%d", OPEN_MAX)` 是**编译错误**（本仓库实测：`error: 'OPEN_MAX' undeclared`），不是 0 |
| 把 `_SC_CLK_TCK` 当成内核 `HZ` | 两者不同源；`HZ` 变化不影响 `sysconf(_SC_CLK_TCK)` |
| 把「类 3」当常量缓存 | 缓存 `_SC_OPEN_MAX` 之后 `setrlimit()` 抬高上限，缓存就过期了；要么重查，要么自己记住「它 = rlimit」 |
| 跨机器对比数值 | `_SC_CHILD_MAX` 跟 `RLIMIT_NPROC` 走，容器里由宿主机决定，**同一台机器两次运行都可能不同** |

## 6. HFT / 嵌入式关联

| 场景 | 本节机制怎么兑现 |
|------|----------------|
| 嵌入式裁剪内核 | BusyBox/自建 rootfs 常把 `NR_OPEN` 调小、把 `NAME_MAX` 之外的东西砍掉；只信编译期宏的代码在这种镜像上直接崩 |
| 路径拼接缓冲 | 不要 `char path[256]`。用 `pathconf(dir, _PC_PATH_MAX)` 拿**该目录**的相对路径上限，或干脆动态扩容（[11.4](11.4-indeterminate-limits.md) 的降级阶梯） |
| fd 上限与行情连接数 | 一个 HFT 网关卡要开几百上千个 fd；`_SC_OPEN_MAX` 只是当前 rlimit，**先 `setrlimit` 再 `sysconf` 复验**，别在启动日志里报一个没抬过的数 |
| 时间换算 | 用 `times()` 拿到的 tick 除以 `sysconf(_SC_CLK_TCK)` 得秒；**不要**除以 `HZ`，也不要拿 `CLOCKS_PER_SEC`（那是 `clock()` 的，恒为 1000000） |
| 启动自检 | 把本节这几项在进程启动时打一遍并落日志：容器/嵌入式环境一变，同样的二进制行为会变，日志是唯一线索 |
| 限流与背压 | `ARG_MAX` 决定单次 `exec` 能传多少参数——用 `find ... -exec` 批量处理时会在别的机器上莫名 `E2BIG`（[11.2](11.2-runtime-limits.md) 有更狠的：真正卡住的是 `MAX_ARG_STRLEN`） |

<summary>代码自测（Q&A）</summary>

**Q1：`limit` 和 `option` 有什么区别？为什么要分开讲？**
A：limit 的答案是**一个数**，option 的答案是**支持/不支持**。两者都通过 `sysconf()` 查询、失败都返回 `-1`，所以 man-pages 的 RETURN VALUE 段把它们拆成两条来写：限制那条说「indeterminate 时 `-1` 且 **errno 不变**」，选项那条说「不支持时 `-1`」。**返回值形态一样，语义完全不同**——这就是 `c11_2_sysconf_table.c` 要在同一张表里同时打 `errno` 的原因。

**Q2：SUSv3 的三类限制分别是什么？为什么分类重要？**
A：① 运行时恒定（`sysconf`）；② 路径名相关、随文件系统变（`pathconf`/`fpathconf`）；③ 运行时可增（`sysconf` + `rlimit`）。分类重要是因为它**直接决定用哪个函数**：问 `NAME_MAX` 用 `sysconf` 根本查不到（没有 `_SC_NAME_MAX`），必须 `pathconf`；而问 `_SC_OPEN_MAX` 用 `pathconf` 也没意义，它是进程级的。

**Q3：实测中 `_SC_OPEN_MAX` 从 100 变成 50，这违反「值在进程生命期内不变」吗？**
A：**违反**。man-pages 那句 "They do not change during the lifetime of a process." 只对类 1/类 2 成立。`_SC_OPEN_MAX` 在 glibc 里就是 `__getrlimit(RLIMIT_NOFILE, &ru) < 0 ? OPEN_MAX : ru.rlim_cur`（`sysdeps/posix/getdtsz.c:32`），`rlim_cur` 一变它就变。程序里 `setrlimit(RLIMIT_NOFILE, &low)` 把 soft 从 100 降到 50 之后立刻重查，得到 50。

**Q4：`_POSIX_ARG_MAX = 4096`，本机 `_SC_ARG_MAX = 2097152`，那我能不能按 4096 分配参数缓冲？**
A：不能按它去**分配**（太小），但也不能按 2097152 去写死（别的机器可以是 4096）。正确做法是运行时查。另外要注意 `_SC_ARG_MAX` 只是「理论值」：本仓库在 CE 上实测 `execve` 传 128 KiB 的单个参数就 `E2BIG`，真正卡住的是 `MAX_ARG_STRLEN = PAGE_SIZE*32 = 131072`（见 [11.2](11.2-runtime-limits.md) 与 [11.3](11.3-file-related-limits.md) 的实测）。

**Q5：为什么 `_POSIX_CLK_TCK` 查不到？**
A：因为 **POSIX 从来没定义过它**。本仓库把 POSIX.1-2017 的 `<limits.h>` / `<unistd.h>` / `<sysconf>` 全文抓下来 grep，没有 `_POSIX_CLK_TCK`；`<sysconf>` 原文只说 "The symbol `CLK_TCK` is obsolescent and removed. It is replaced with the phrase "clock ticks per second"." 所以这一项只有 `_SC_CLK_TCK` 可查，没有下限宏。这也是第 3 节表格第一行写 `--` 的原因。

**Q6：`_SC_CLK_TCK` 和内核对 `HZ` 是什么关系？**
A：没有直接关系。`_SC_CLK_TCK` 是内核在启动时通过 `auxv` 的 `AT_CLKTCK` 传给 libc 的（glibc 存进 `GLRO(dl_clktck)`），`__getclktck()` 优先用它，缺省才退回编译期的 `SYSTEM_CLK_TCK=100`。它决定的是 `times()` 的返回值怎么换算成秒，与内核内部调度节拍 `HZ` 是两个独立的东西。

**Q7：`<limits.h>` 里到底哪些宏能直接用？**
A：实测结论：`NAME_MAX`(255) / `PATH_MAX`(4096) / `PIPE_BUF`(4096) 有定义；`ARG_MAX` / `OPEN_MAX` / `LINK_MAX` / `NR_OPEN` 被 glibc **主动 `#undef`**（原因写在 `bits/local_lim.h` 的注释里：这些值运行时可变，宏会误导）。所以用之前一律先 `#ifdef`，不要以为「未定义就是 0」。
