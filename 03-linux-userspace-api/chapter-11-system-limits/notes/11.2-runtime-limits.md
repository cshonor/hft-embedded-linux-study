## 本节讲什么

本节把「运行时查询」这件事做到底：`sysconf()` 的返回值**只有 `-1` 一种失败信号**，但它有**三种完全不同的含义**。分清这三次是本章的核心技能。四个问题：

1. `-1` 的三义分别是什么？哪两个**在返回值 + `errno` 上完全一样**（因此不可能靠返回值区分）？
2. 「不重置 `errno`」会怎样**误报错误**？给一段现场。
3. 「值是对的」就说明这次调用干净吗？（不是）
4. `_SC_ARG_MAX` 报 2 MiB，为什么 `execve` 传 128 KiB 就 `E2BIG` 了？

## 1. 原型与命名

```c
#include <unistd.h>

long sysconf(int name);                         /* 系统级：不依赖路径/文件 */
long pathconf(const char *pathname, int name);  /* 按路径名（见 11.3） */
long fpathconf(int fd, int name);               /* 按已打开 fd（见 11.3） */
size_t confstr(int name, char *buf, size_t len);/* 查「字符串」选项（见 11.5） */
```

| API | 常量前缀 | 本节用到的 |
|-----|---------|-----------|
| `sysconf` | `_SC_*` | `_SC_ARG_MAX`、`_SC_OPEN_MAX`、`_SC_CLK_TCK`、`_SC_TZNAME_MAX`、`_SC_THREADS` … |
| `pathconf` / `fpathconf` | `_PC_*` | `_PC_NAME_MAX`、`_PC_PATH_MAX`、`_PC_PIPE_BUF` … |

Shell 侧有一个封装：`getconf`。它在容器里常常**不存在**——本仓库的 CE 沙箱实测 `getconf: command not found`（整个 `/usr/bin/getconf` 都没有），所以「用 getconf 交叉验证」这个练习在受限环境里做不了，得靠程序自己。

```bash
getconf ARG_MAX            # 等价于 sysconf(_SC_ARG_MAX)
getconf NAME_MAX /home     # 等价于 pathconf("/home", _PC_NAME_MAX)
```

## 2. `-1` 的三义（man-pages 原文）

man-pages 6.19 `sysconf(3)` 的 RETURN VALUE 段逐字：

> The return value of `sysconf()` is one of the following:
>
> - On error, -1 is returned and `errno` is set to indicate the error (for example, `EINVAL`, indicating that `name` is invalid).
> - If `name` corresponds to a maximum or minimum limit, and that limit is **indeterminate**, -1 is returned and `errno` is **not changed**. (To distinguish an indeterminate limit from an error, set `errno` to zero before the call, and then check whether `errno` is nonzero when -1 is returned.)
> - If `name` corresponds to an option, a positive value is returned if the option is supported, and -1 is returned if the option is **not supported**.

拆成表：

| # | 情况 | 返回值 | `errno` | 可区分吗 |
|---|------|-------|--------|---------|
| a | **真错误**（`name` 非法） | `-1` | `EINVAL`(22) | 可（`errno != 0`） |
| b | **限制 indeterminate** | `-1` | **不变**（调用前清零则仍是 0） | 可（`errno == 0`） |
| c | **选项不支持** | `-1` | **不变** | **不可**——与 b 一模一样 |
| d | 正常 | 具体值 | 不变 | 可 |

所以正确的判断骨架是：

```c
errno = 0;
long v = sysconf(name);
if (v == -1) {
    if (errno == 0)
        /* b 或 c：不知道确切值，或该选项不支持 —— 都要走「保守回退」 */
    else
        /* a：真错误，比如 EINVAL。这才是 bug（拼错了 name 常量） */
}
```

> **`errno = 0` 必须写在每次调用之前，而不是函数开头写一次。** 第 5 节的 ⑥ 段会把「只清一次」造成的误报现场打出来。

## 3. 原书 Listing 11-1（page 216）：`t_sysconf.c`

原书第一个示例就是「用 `errno == 0` 区分 indeterminate 与错误」。逐字镜像（本仓库 [`code/t_sysconf.c`](../code/t_sysconf.c)）：

```c
/* t_sysconf.c

   Demonstrate the use of sysconf() to retrieve system limits.
*/
#include "tlpi_hdr.h"
static void             /* Print 'msg' plus sysconf() value for 'name' */
sysconfPrint(const char *msg, int name)
{
    long lim;

    errno = 0;
    lim = sysconf(name);
    if (lim != -1) {        /* Call succeeded, limit determinate */
        printf("%s %ld\n", msg, lim);
    } else {
        if (errno == 0)     /* Call succeeded, limit indeterminate */
            printf("%s (indeterminate)\n", msg);
        else                /* Call failed */
            errExit("sysconf %s", msg);
    }
}
int
main(int argc, char *argv[])
{
    sysconfPrint("_SC_ARG_MAX:        ", _SC_ARG_MAX);
    sysconfPrint("_SC_LOGIN_NAME_MAX: ", _SC_LOGIN_NAME_MAX);
    sysconfPrint("_SC_OPEN_MAX:       ", _SC_OPEN_MAX);
    sysconfPrint("_SC_NGROUPS_MAX:    ", _SC_NGROUPS_MAX);
    sysconfPrint("_SC_PAGESIZE:       ", _SC_PAGESIZE);
    sysconfPrint("_SC_RTSIG_MAX:      ", _SC_RTSIG_MAX);
    exit(EXIT_SUCCESS);
}
```

核心就一个 `sysconfPrint()`：`errno = 0` → `lim = sysconf(name)` → 非 `-1` 就打印值；`-1` 且 `errno == 0` 就打印 `(indeterminate)`；否则 `errExit`。`main` 依次问 6 项：`_SC_ARG_MAX` / `_SC_LOGIN_NAME_MAX` / `_SC_OPEN_MAX` / `_SC_NGROUPS_MAX` / `_SC_PAGESIZE` / `_SC_RTSIG_MAX`。

编译运行（本仓库加了 `-Wno-unused-parameter`：原书 `main(argc, argv)` 不用这两个参数，而原书 Makefile 只开 `-Wall` 不开 `-Wextra`，代码逐字不改）：

```bash
gcc -O0 -Wall -Wextra -Wno-unused-parameter -o t_sysconf t_sysconf.c && ./t_sysconf
```

CE（gcc 13.3.0 / x86-64 / Ubuntu 24.04）实测：

```text
_SC_ARG_MAX:         2097152
_SC_LOGIN_NAME_MAX:  256
_SC_OPEN_MAX:        100
_SC_NGROUPS_MAX:     65536
_SC_PAGESIZE:        4096
_SC_RTSIG_MAX:       32
```

六行都拿到了确定值，没有一项 indeterminate。这六项的**出处各不相同**（下一节的自编 demo 会把来源打全）：

| 项 | 值 | 谁在回答 |
|----|----|---------|
| `_SC_ARG_MAX` | 2097152 | glibc 自己算：`min(max(131072, RLIMIT_STACK/4), 6MiB)` |
| `_SC_LOGIN_NAME_MAX` | 256 | 编译期常量 `LOGIN_NAME_MAX` |
| `_SC_OPEN_MAX` | 100 | `getrlimit(RLIMIT_NOFILE).rlim_cur` |
| `_SC_NGROUPS_MAX` | 65536 | **读文件** `/proc/sys/kernel/ngroups_max` |
| `_SC_PAGESIZE` | 4096 | `__getpagesize()` |
| `_SC_RTSIG_MAX` | 32 | 内核 uapi 常量 `RTSIG_MAX` |

## 4. 自编：`sysconf()` 全表 + `-1` 三义现场

完整源码 [`code/c11_2_sysconf_table.c`](../code/c11_2_sysconf_table.c)：

```c
/* c11_2_sysconf_table.c — Ch11 §11.2：sysconf() 全表 + 返回 -1 的三种含义
 *
 * 三件事：
 *   ① 把 sysconf 的四类 name 全查一遍（常量类 / 限制类 / 选项类 / 扩展类），
 *      每行带上「调用后 errno」——因为判断 -1 的唯一依据就是它。
 *   ② 把「-1 三义」逐个抓到现场：
 *        a. 真错误              -> errno=EINVAL（name 非法）
 *        b. 限制不确定(indeterminate) -> 返回 -1 且 errno **不变**
 *        c. 选项不支持          -> 也返回 -1，errno 也 **不变**（和 b 不可区分！）
 *   ③ 演示不重置 errno 会怎样误判：先制造 errno=22，再查一个 indeterminate，
 *      就会把一个「没问题的 -1」当成错误。
 *
 * 编译： gcc -O0 -Wall -Wextra -o c11_2_sysconf_table c11_2_sysconf_table.c
 * 取材： sysconf(3) RETURN VALUE 段（man-pages 6.19）逐字：
 *         "If name corresponds to a maximum or minimum limit, and that limit is
 *          indeterminate, -1 is returned and errno is not changed."
 *       glibc 2.39 sysdeps/posix/sysconf.c:64-66（default: __set_errno(EINVAL); return -1;）
 *       glibc 2.39 sysdeps/posix/sysconf.c:102-103（_SC_TZNAME_MAX 直接 return -1）
 *       glibc 2.39 sysdeps/unix/sysv/linux/sysconf.c:56-67（_SC_ARG_MAX 的算法）
 */
#define _GNU_SOURCE
#include <errno.h>
#include <limits.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <unistd.h>

/* errno==0 且返回 -1 => indeterminate；errno!=0 且返回 -1 => 真错误 */
static void sc(const char *lbl, int name)
{
    errno = 0;
    long v = sysconf(name);
    const char *tag = "";
    if (v == -1)
        tag = (errno == 0) ? "  <- 非错误：indeterminate / 选项不支持"
                           : "  <- 真错误";
    printf("  %-26s = %-12ld errno=%-3d%s\n", lbl, v, errno, tag);
}

static const struct { int name; const char *lbl; } CONSTS[] = {
    { _SC_VERSION,     "_SC_VERSION" },
    { _SC_2_VERSION,   "_SC_2_VERSION" },
    { _SC_CLK_TCK,     "_SC_CLK_TCK" },
    { _SC_PAGESIZE,    "_SC_PAGESIZE" },
    { _SC_PAGE_SIZE,   "_SC_PAGE_SIZE" },
    { _SC_CHAR_BIT,    "_SC_CHAR_BIT" },
    { _SC_INT_MAX,     "_SC_INT_MAX" },
    { _SC_LONG_BIT,    "_SC_LONG_BIT" },
    { _SC_WORD_BIT,    "_SC_WORD_BIT" },
    { _SC_MB_LEN_MAX,  "_SC_MB_LEN_MAX" },
    { _SC_NZERO,       "_SC_NZERO" },
    { _SC_SSIZE_MAX,   "_SC_SSIZE_MAX" },
    { _SC_ATEXIT_MAX,  "_SC_ATEXIT_MAX" },
    { _SC_PASS_MAX,    "_SC_PASS_MAX" },
};

static const struct { int name; const char *lbl; } LIMITS[] = {
    { _SC_ARG_MAX,         "_SC_ARG_MAX" },
    { _SC_CHILD_MAX,       "_SC_CHILD_MAX" },
    { _SC_OPEN_MAX,        "_SC_OPEN_MAX" },
    { _SC_STREAM_MAX,      "_SC_STREAM_MAX" },
    { _SC_NGROUPS_MAX,     "_SC_NGROUPS_MAX" },
    { _SC_LOGIN_NAME_MAX,  "_SC_LOGIN_NAME_MAX" },
    { _SC_HOST_NAME_MAX,   "_SC_HOST_NAME_MAX" },
    { _SC_TTY_NAME_MAX,    "_SC_TTY_NAME_MAX" },
    { _SC_TZNAME_MAX,      "_SC_TZNAME_MAX" },
    { _SC_SYMLOOP_MAX,     "_SC_SYMLOOP_MAX" },
    { _SC_RE_DUP_MAX,      "_SC_RE_DUP_MAX" },
    { _SC_IOV_MAX,         "_SC_IOV_MAX" },
    { _SC_SIGQUEUE_MAX,    "_SC_SIGQUEUE_MAX" },
    { _SC_MQ_OPEN_MAX,     "_SC_MQ_OPEN_MAX" },
    { _SC_MQ_PRIO_MAX,     "_SC_MQ_PRIO_MAX" },
    { _SC_DELAYTIMER_MAX,  "_SC_DELAYTIMER_MAX" },
    { _SC_SEM_NSEMS_MAX,   "_SC_SEM_NSEMS_MAX" },
    { _SC_SEM_VALUE_MAX,   "_SC_SEM_VALUE_MAX" },
};

static const struct { int name; const char *lbl; } OPTS[] = {
    { _SC_JOB_CONTROL,            "_SC_JOB_CONTROL" },
    { _SC_SAVED_IDS,              "_SC_SAVED_IDS" },
    { _SC_THREADS,                "_SC_THREADS" },
    { _SC_REALTIME_SIGNALS,       "_SC_REALTIME_SIGNALS" },
    { _SC_PRIORITY_SCHEDULING,    "_SC_PRIORITY_SCHEDULING" },
    { _SC_TIMERS,                 "_SC_TIMERS" },
    { _SC_SEMAPHORES,             "_SC_SEMAPHORES" },
    { _SC_SHARED_MEMORY_OBJECTS,  "_SC_SHARED_MEMORY_OBJECTS" },
    { _SC_MONOTONIC_CLOCK,        "_SC_MONOTONIC_CLOCK" },
    { _SC_CPUTIME,                "_SC_CPUTIME" },
    { _SC_THREAD_CPUTIME,         "_SC_THREAD_CPUTIME" },
    { _SC_BARRIERS,               "_SC_BARRIERS" },
    { _SC_READER_WRITER_LOCKS,    "_SC_READER_WRITER_LOCKS" },
    { _SC_2_C_DEV,                "_SC_2_C_DEV" },
    { _SC_2_FORT_DEV,             "_SC_2_FORT_DEV" },
    { _SC_2_LOCALEDEF,            "_SC_2_LOCALEDEF" },
    { _SC_2_SW_DEV,               "_SC_2_SW_DEV" },
    { _SC_XOPEN_VERSION,          "_SC_XOPEN_VERSION" },
};

static const struct { int name; const char *lbl; } EXTRAS[] = {
    { _SC_PHYS_PAGES,         "_SC_PHYS_PAGES" },
    { _SC_AVPHYS_PAGES,       "_SC_AVPHYS_PAGES" },
    { _SC_NPROCESSORS_CONF,   "_SC_NPROCESSORS_CONF" },
    { _SC_NPROCESSORS_ONLN,   "_SC_NPROCESSORS_ONLN" },
    { _SC_MINSIGSTKSZ,        "_SC_MINSIGSTKSZ" },
    { _SC_SIGSTKSZ,           "_SC_SIGSTKSZ" },
};

#define DUMP(arr)                                                       \
    do {                                                                \
        for (size_t i = 0; i < sizeof(arr) / sizeof((arr)[0]); i++)     \
            sc((arr)[i].lbl, (arr)[i].name);                            \
    } while (0)

int main(void)
{
    printf("### ① 常量类（与 CPU/内核无关的确定值）\n");
    DUMP(CONSTS);

    printf("\n### ② 限制类\n");
    DUMP(LIMITS);

    printf("\n### ③ 选项类（支持则返回一个 >0 的值，不支持则 -1）\n");
    DUMP(OPTS);

    printf("\n### ④ glibc/Linux 扩展\n");
    DUMP(EXTRAS);

    printf("\n### ⑤ 返回 -1 的三种含义，逐个抓现场\n");

    errno = 0;
    long v = sysconf(9999);
    printf("  a) sysconf(9999)          -> %ld errno=%d (%s)\n", v, errno, strerror(errno));
    printf("     name 非法 = 真错误。glibc 走的是 sysdeps/posix/sysconf.c:64 的 default 分支。\n");

    errno = 0;
    v = sysconf(_SC_TZNAME_MAX);
    printf("  b) sysconf(_SC_TZNAME_MAX) -> %ld errno=%d   <- indeterminate，不是错误\n", v, errno);
    printf("     glibc 里就是一行 `case _SC_TZNAME_MAX: return -1;`（sysconf.c:102-103），\n");
    printf("     压根不碰 errno，所以调用者必须自己在调用前把 errno 清零。\n");

    errno = 0;
    v = sysconf(_SC_2_FORT_DEV);
    printf("  c) sysconf(_SC_2_FORT_DEV) -> %ld errno=%d   <- 选项不支持，也是 -1\n", v, errno);
    printf("     和 b) 在「返回值 + errno」上完全一样 —— 靠返回值无法区分，\n");
    printf("     只能靠你知道这个 name 问的是「限制」还是「选项」。\n");

    printf("\n### ⑥ 不重置 errno 的经典误判\n");
    errno = 0;
    (void) sysconf(9999);                       /* 先把 errno 弄成 22，之后故意不清零 */
    printf("  上一步留下了 errno=%d (%s)\n", errno, strerror(errno));
    long w = sysconf(_SC_TZNAME_MAX);           /* 一个完全正常的 indeterminate */
    printf("  紧接着查 _SC_TZNAME_MAX -> %ld，errno=%d\n", w, errno);
    printf("  如果按「-1 && errno != 0 就是错误」去判，这里会误报错误。\n");
    printf("  正确写法：**每次调用之前** errno = 0，而不是整个函数开头清一次。\n");

    printf("\n### ⑦ 值对不代表 errno 干净\n");
    errno = 0;
    long n = sysconf(_SC_NPROCESSORS_ONLN);
    printf("  sysconf(_SC_NPROCESSORS_ONLN) = %ld，但 errno 被留成 %d (%s)\n",
           n, errno, strerror(errno));
    printf("  （glibc 的 __get_nprocs 读 /sys 时留下的 ENOENT，值本身是对的。）\n");
    return 0;
}
```

|----|------|------|
| ① | `_SC_VERSION = 200809` | 不是「版本 3」，而是 **POSIX 修订版年月**（2008-09） |
| ① | `_SC_INT_MAX = 2147483647`、`_SC_LONG_BIT = 64` | 常量类：`sysconf` 也能查 ABI 宽度，不必去 `#ifdef` 平台 |
| ② | 4 项 `-1` 且 `errno=0`：`_SC_TZNAME_MAX` / `_SC_SYMLOOP_MAX` / `_SC_MQ_OPEN_MAX` / `_SC_SEM_NSEMS_MAX` | 这就是 **indeterminate**：实现允许不回答（见 [11.4](11.4-indeterminate-limits.md)） |
| ② | `_SC_CHILD_MAX = 54956` 与 `_SC_SIGQUEUE_MAX = 54956` 同值 | 不是巧合：两者在 glibc 里分别落到 `RLIMIT_NPROC` 与 `RLIMIT_SIGPENDING`，而本沙箱把这两个 rlimit 设成了同一个值（56783 → 本次采样 54956） |
| ③ | `_SC_2_FORT_DEV = -1` | **选项**不支持。它的 `-1` 与 ② 的 indeterminate **完全同形** |
| ④ | `_SC_NPROCESSORS_CONF/ONLN = 2` 但 `errno=2` | **值对不代表干净**：glibc 为拿这个值去读 `/sys/devices/system/cpu` 相关路径，失败留下 `ENOENT`(2) |
| ⑤a | `sysconf(9999)` → `-1 errno=22` | 真错误，glibc 落到 `sysconf.c:64` 的 `default:` |
| ⑤b | `_SC_TZNAME_MAX` → `-1 errno=0` | glibc 就是一行 `case _SC_TZNAME_MAX: return -1;`（`sysdeps/posix/sysconf.c:102-103`），**不碰 `errno`** |
| ⑤c | `_SC_2_FORT_DEV` → `-1 errno=0` | 与 b 不可区分 |
| ⑥ | 先 `sysconf(9999)` 留下 `errno=22`，**不清零**再查 `_SC_TZNAME_MAX` → `-1 errno=22` | 一个完全正常的 indeterminate 被误判成错误。**「调用前清零」必须逐次执行** |
| ⑦ | `errno=2` 而值正确 | 不要用 `errno != 0` 去判「这次调用是否出错」，`errno` 只在**返回值是 `-1` 时**才有解读意义 |

### 4.1 glibc 的四级分派（`_SC_*` 到底谁在回答）

`sysconf()` 在 x86-64 glibc 2.39 里是这样一路转交下去的：

```c
/* sysdeps/unix/sysv/linux/x86/sysconf.c:31-37 —— x86 特化层 */
long int
__sysconf (int name)
{
  if (name >= _SC_LEVEL1_ICACHE_SIZE && name <= _SC_LEVEL4_CACHE_LINESIZE)
    return __cache_sysconf (name);

  return linux_sysconf (name);
}

/* Now the generic Linux version.  */
#undef __sysconf
#define __sysconf static linux_sysconf
#include "../sysconf.c"
```

```c
/* sysdeps/unix/sysv/linux/sysconf.c:51-91 —— Linux 层，只认下面这些 */
    case _SC_MONOTONIC_CLOCK:
    case _SC_CPUTIME:
    case _SC_THREAD_CPUTIME:
      return _POSIX_VERSION;

    case _SC_ARG_MAX:
      ...
	    const long int limit = MAX (legacy_ARG_MAX, rlimit.rlim_cur / 4);
	    return MIN (limit, maximum_ARG_MAX);
    case _SC_NGROUPS_MAX:
      procfname = "/proc/sys/kernel/ngroups_max";
    case _SC_SIGQUEUE_MAX:
        if (__getrlimit (RLIMIT_SIGPENDING, &rlimit) == 0)
	  return rlimit.rlim_cur;
        procfname = "/proc/sys/kernel/rtsig-max";
    case _SC_MINSIGSTKSZ:
      return GLRO(dl_minsigstacksize);
    case _SC_SIGSTKSZ:
      return sysconf_sigstksz ();
    ...
  return posix_sysconf (name);
```

四级链条：

| 层 | 文件 | 管什么 |
|----|------|-------|
| 1 | `sysdeps/unix/sysv/linux/x86/sysconf.c:33-34` | **只**管 12 个 CPU cache 项（`_SC_LEVEL1_ICACHE_SIZE` … `_SC_LEVEL4_CACHE_LINESIZE`）→ `__cache_sysconf` |
| 2 | 同上 `:36` | 其余全部转给 `linux_sysconf` |
| 3 | `sysdeps/unix/sysv/linux/sysconf.c:51-91` | Linux 特化：`_SC_ARG_MAX`（算 rlimit）、`_SC_NGROUPS_MAX`（**读 `/proc`**）、`_SC_SIGQUEUE_MAX`（读 rlimit）、`_SC_MINSIGSTKSZ`、`_SC_SIGSTKSZ`、`_SC_MONOTONIC_CLOCK`/`_SC_CPUTIME`/`_SC_THREAD_CPUTIME`（直接 `return _POSIX_VERSION`） |
| 4 | `sysdeps/posix/sysconf.c`（用 `#define __sysconf static posix_sysconf` + `#include` 变成 `posix_sysconf`） | POSIX 通用表；认不出的 `name` 落到 `:64` 的 `default: __set_errno(EINVAL); return -1;` |

这就解释了 ⑤a 的 `EINVAL` 从哪来，也解释了为什么 `_SC_TZNAME_MAX`（`:102-103`）**什么都不做就返回 `-1`**：它在 POSIX 表里就是这么一行。

> **一个反直觉的推论**：`sysconf()` 不保证「只读内存」。`_SC_NGROUPS_MAX` 会 **`open("/proc/sys/kernel/ngroups_max")` + `read` + `close`**（`linux/sysconf.c:97-118`）。在 HFT 热路径上反复调它，就是在反复做系统调用。

## 5. `_SC_ARG_MAX` 的 2 MiB 是个「名义值」

`_SC_ARG_MAX` 报 **2097152**（2 MiB）。这是 glibc 的算法（`linux/sysconf.c:34/38/56-67`）：

```c
#define legacy_ARG_MAX 131072
#define maximum_ARG_MAX (6 * 1024 * 1024)
...
    case _SC_ARG_MAX:
	{
	  struct rlimit rlimit;
	  if (__getrlimit (RLIMIT_STACK, &rlimit) == 0)
	    {
	      const long int limit = MAX (legacy_ARG_MAX, rlimit.rlim_cur / 4);
	      return MIN (limit, maximum_ARG_MAX);
	    }
	  return legacy_ARG_MAX;
	}
```

本沙箱 `RLIMIT_STACK = 8388608`（8 MiB）→ `8388608 / 4 = 2097152` → 就是实测值。

**但 2 MiB 传不进去。** 实测 `execve` 的单参数长度阶梯（本地探针输出）：

```text
  _SC_ARG_MAX            = 2097152      errno=0
  arglen=65536    OK
  arglen=131072   execve FAILED errno=7 (Argument list too long)
  arglen=131073   execve FAILED errno=7 (Argument list too long)
  arglen=131200   execve FAILED errno=7 (Argument list too long)
  arglen=262144   execve FAILED errno=7 (Argument list too long)
```

卡住的位置是 **`MAX_ARG_STRLEN = PAGE_SIZE * 32 = 128 KiB`**：

| 事实 | 位置 |
|---|---|
| `#define MAX_ARG_STRLEN (PAGE_SIZE * 32)` | `include/uapi/linux/binfmts.h:15` |
| `static bool valid_arg_len(struct linux_binprm *bprm, unsigned long len) { return len <= MAX_ARG_STRLEN; }` | `fs/exec.c:297-300` |
| `int copy_string_kernel(...) { int len = strnlen(arg, MAX_ARG_STRLEN) + 1; ... if (!valid_arg_len(bprm, len)) return -E2BIG; ... }` | `fs/exec.c:618-650` |
| `bprm_stack_limits()` 算出 `argmin`（栈最低水位），越线也报 `-E2BIG` | `fs/exec.c:477-515` |
| `if (bprm->rlim_stack.rlim_cur > _STK_LIM) bprm->rlim_stack.rlim_cur = _STK_LIM;`（`_STK_LIM = 8 MiB`） | `fs/exec.c:1347-1348`、`include/uapi/linux/resource.h:66` |

> **这才是 TLPI 那一章真正的「可移植性」教训**：`sysconf(_SC_ARG_MAX)` 给你一个**数**，但你不知道这个数怎么被用。man-pages 自己在 BUGS 里写着：「It is difficult to use `ARG_MAX` because it is not specified how much of the argument space for `exec(3)` is consumed by the user's environment variables.」「Some returned values may be huge; they are not suitable for allocating memory.」

## 6. 常见坑

| 坑 | 说明 |
|----|------|
| 只在函数开头 `errno = 0` 一次 | ⑥ 段现场：任何**前面**的失败都会污染判断，把一个 indeterminate 误报成错误 |
| 用 `errno != 0` 判「本次调用出错」 | ⑦ 段现场：`_SC_NPROCESSORS_ONLN` 值正确而 `errno=2`。`errno` 只在返回 `-1` 时有意义 |
| 用 `-1` 区分「限制不确定」和「选项不支持」 | **不可能**（⑤b vs ⑤c）。只能靠「你知道自己在问哪一类」 |
| 以为 `sysconf()` 是纯内存操作 | `_SC_NGROUPS_MAX` 读 `/proc`，`_SC_SIGQUEUE_MAX` 读 rlimit，`_SC_NPROCESSORS_*` 读 `/sys`。热路径反复调用 = 反复系统调用 |
| 把 `_SC_ARG_MAX` 当可用内存随便 `malloc` | man-pages BUGS 明说不适合用来分配；本机 2 MiB 装不进 `execve`（真实墙 128 KiB） |
| 在容器里依赖 `getconf` 交叉验证 | CE 沙箱里 `/usr/bin/getconf` 不存在（本章实测 `command not found`）；要交叉验证得自己写程序 |
| `sysconf(9999)` 之后不检查 `errno` | 这就是「真错误」那一类，代表程序写错了 `name`，必须崩掉而不是静默回退 |

<summary>代码自测（Q&A）</summary>

**Q1：`sysconf()` 返回 `-1` 有几种含义？怎么区分？**
A：三种。① 真错误（`errno` 被设，如 `EINVAL`）；② 限制 indeterminate（`errno` **不变**）；③ 选项不支持（`errno` **不变**）。**②和③无法互相区分**——它们的「返回值 + `errno`」完全一样。可区分的只有「真错误」与「非错误」：调用前 `errno = 0`，返回 `-1` 时看 `errno` 是否为 0。

**Q2：为什么 `errno = 0` 要写在每次调用之前？**
A：因为 `errno` 是**线程局部但跨调用存活**的。⑥ 段现场：先 `sysconf(9999)`（把 `errno` 置 22），**不清零**再查 `_SC_TZNAME_MAX`，得到 `-1 errno=22`——一个完全正常的 indeterminate 被误报成错误。glibc 对 `_SC_TZNAME_MAX` 的实现是 `case _SC_TZNAME_MAX: return -1;`（`sysdeps/posix/sysconf.c:102-103`），它压根不碰 `errno`。

**Q3：`_SC_NPROCESSORS_ONLN = 2` 但 `errno = 2`，这说明调用失败了吗？**
A：没有。⑦ 段就是这个现场：值 2 是**正确**的（沙箱 2 核），`errno=2`(ENOENT) 是 glibc 内部读 `/sys` 时留下的。**只要返回值不是 `-1`，`errno` 就没有解读意义**。用 `errno != 0` 判失败会在这里误报。

**Q4：`_SC_TZNAME_MAX` 为什么会 indeterminate？**
A：因为它属于「时区名长度」——glibc 不想承诺一个具体值。man-pages 的 RETURN VALUE 允许实现这样做：「If `name` corresponds to a maximum or minimum limit, and that limit is indeterminate, -1 is returned and `errno` is not changed.」本机 indeterminate 一共 4 项：`_SC_TZNAME_MAX` / `_SC_SYMLOOP_MAX` / `_SC_MQ_OPEN_MAX` / `_SC_SEM_NSEMS_MAX`。

**Q5：`_SC_ARG_MAX = 2097152` 是 `RLIMIT_STACK` 的 1/4，为什么是这个算法？**
A：glibc 的目标是「参数+环境不能把栈吃光」。`sysdeps/unix/sysv/linux/sysconf.c:56-67`：`limit = MAX(legacy_ARG_MAX, rlimit.rlim_cur / 4); return MIN(limit, maximum_ARG_MAX)`。本机 `RLIMIT_STACK = 8388608` → `8388608/4 = 2097152`；上限被夹在 6 MiB（`maximum_ARG_MAX`），下限被抬到 128 KiB（`legacy_ARG_MAX`）。

**Q6：那为什么 `execve` 传 131072 字节就失败了？**
A：因为内核另有硬约束：`MAX_ARG_STRLEN = PAGE_SIZE * 32 = 131072`（`include/uapi/linux/binfmts.h:15`），由 `valid_arg_len()`（`fs/exec.c:297-300`）在 `copy_string_kernel()`（`fs/exec.c:618-650`）里检查，越线返回 `-E2BIG`。实测 65536 OK、131072 就 `errno=7`。**`sysconf` 给的数与内核实际接受的长度是两套规则。**

**Q7：`sysconf()` 会不会做 I/O？**
A：会。`_SC_NGROUPS_MAX` 走 `/proc/sys/kernel/ngroups_max`（`sysdeps/unix/sysv/linux/sysconf.c:97-118`，`open` + `read` + `strtol` + `close`）；`_SC_SIGQUEUE_MAX` 先试 `getrlimit(RLIMIT_SIGPENDING)`、失败再读 `/proc/sys/kernel/rtsig-max`；`_SC_NPROCESSORS_*` 走 `/sys`。这也是 ⑦ 段 `errno` 被污染的原因。

**Q8：这套分派为什么要分成 x86 特化 + linux + posix 三层？**
A：为了复用。CPU cache 那 12 项需要 `cpuid`/`sysfs` 的体系结构相关代码（`__cache_sysconf`），放在 `x86/sysconf.c`；Linux 通用但非 POSIX 的部分（`/proc`、rlimit、`_POSIX_VERSION` 直返）放 `linux/sysconf.c`；纯 POSIX 表放 `sysdeps/posix/sysconf.c`，用 `#define __sysconf static posix_sysconf` + `#include` 组装。所以同一个 `sysconf(_SC_ARG_MAX)` 在三层的表现完全不同。

</details>
