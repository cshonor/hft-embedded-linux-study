## 本节讲什么

前一节讲的是**限制**（答案是数）；本节讲**选项**（答案是「有没有」）。选项的坑在于 `<unistd.h>` 里的 `_POSIX_FOO` 宏有**四种状态**，而且**编译期说「说不清」的时候，只有运行时能给你答案**。四个问题：

1. `_POSIX_FOO` 的四态分别怎么读？为什么「未定义」不等于「不支持」？
2. 编译期 `_POSIX_MONOTONIC_CLOCK = 0` 而运行时 `sysconf(_SC_MONOTONIC_CLOCK) = 200809`，该信谁？
3. `confstr()` 查的是什么？它和 `sysconf` 的失败信号有什么不同？
4. 三态判断在 C 代码里怎么写才不会**编译不过**？

---

## 1. `_POSIX_FOO` 的四态（man-pages 原文）

man-pages 6.19 `sysconf(3)` 的 DESCRIPTION 段逐字：

> For options, typically, there is a constant `_POSIX_FOO` that may be defined in `<unistd.h>`. **If it is undefined, one should ask at run time. If it is defined to -1, then the option is not supported. If it is defined to 0, then relevant functions and headers exist, but one has to ask at run time what degree of support is available.** If it is defined to a value other than -1 or 0, then the option is supported. Usually the value (such as 200112L) indicates the year and month of the POSIX revision describing the option. glibc uses the value 1 to indicate support as long as the POSIX revision has not been published yet. The `sysconf()` argument will be `_SC_FOO`. For a list of options, see `posixoptions(7)`.

| 状态 | 含义 | 该怎么办 |
|------|------|---------|
| **未定义** | 编译期不知道 | 必须运行时 `sysconf(_SC_FOO)` |
| **`-1`** | 明确**不支持** | 可以用，但没有保证；准备回退路径 |
| **`0`** | 头文件/函数**在**，但支持到什么程度说不清 | 必须运行时问 |
| **其他正值** | **支持**，值通常是 POSIX 修订版年月（如 `200809L`） | 可以直接用 |

> 只有「其他正值」是**编译期就能定**的。其余三态都要落到运行时。

## 2. 自编：三态 + 运行时对照 + `confstr`

完整源码 [`code/c11_5_options.c`](../code/c11_5_options.c)：

```c
/* c11_5_options.c — Ch11 §11.5：系统选项（System Options）的三态与两条查法
 *
 * 限制是「一个数」，选项是「支持 / 不支持」。POSIX 给选项设计了三态：
 *   _POSIX_FOO 未定义      -> 编译期不知道，必须运行时问 sysconf(_SC_FOO)
 *   _POSIX_FOO == -1       -> 明确不支持
 *   _POSIX_FOO == 0        -> 头文件/函数都在，但支持到什么程度要运行时问
 *   _POSIX_FOO == 其他正值 -> 支持，通常就是描述它的 POSIX 修订版年月（如 200809L）
 *
 * 本程序把这三态用宏判断打出来，再和运行时的 sysconf(_SC_*) 对齐，最后加一段
 * confstr() —— 它查的是**字符串**选项（路径、版本号），是 sysconf 的字面兄弟。
 *
 * 编译： gcc -O0 -Wall -Wextra -o c11_5_options c11_5_options.c
 * 取材： sysconf(3) DESCRIPTION 段（man-pages 6.19）逐字：
 *         "For options, typically, there is a constant _POSIX_FOO that may be
 *          defined in <unistd.h>.  If it is undefined, one should ask at run
 *          time.  If it is defined to -1, then the option is not supported.
 *          If it is defined to 0, then relevant functions and headers exist,
 *          but one has to ask at run time what degree of support is available."
 *       glibc 2.39 sysdeps/unix/sysv/linux/bits/posix_opt.h:23/26/32/103/106/128/131/146/152/155/164/182-183/186/192
 *       glibc 2.39 posix/confstr.c:43（_CS_PATH）/ :252（_CS_GNU_LIBC_VERSION）
 *                                 / :257（_CS_GNU_LIBPTHREAD_VERSION）；无值时 :265/:277 return 0
 */
#define _GNU_SOURCE
#include <errno.h>
#include <limits.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <unistd.h>

static void sc(const char *lbl, int name)
{
    errno = 0;
    long v = sysconf(name);
    const char *note = "";
    if (v == -1)
        note = (errno == 0) ? "  <- 不支持（或该 name 属限制类且 indeterminate）" : "  <- 真错误";
    printf("  %-28s = %-10ld%s\n", lbl, v, note);
}

int main(void)
{
    printf("### ① 编译期：_POSIX_* 的三态（本机 glibc 2.39）\n");

    printf("  -- 支持（值为 POSIX 修订年月）--\n");
    printf("  _POSIX_JOB_CONTROL=%ld _POSIX_SAVED_IDS=%ld _POSIX_THREADS=%ld\n",
           (long)_POSIX_JOB_CONTROL, (long)_POSIX_SAVED_IDS, (long)_POSIX_THREADS);
    printf("  _POSIX_REALTIME_SIGNALS=%ld _POSIX_TIMERS=%ld _POSIX_SEMAPHORES=%ld\n",
           (long)_POSIX_REALTIME_SIGNALS, (long)_POSIX_TIMERS, (long)_POSIX_SEMAPHORES);
    printf("  _POSIX_PRIORITY_SCHEDULING=%ld _POSIX_BARRIERS=%ld _POSIX_SPIN_LOCKS=%ld\n",
           (long)_POSIX_PRIORITY_SCHEDULING, (long)_POSIX_BARRIERS, (long)_POSIX_SPIN_LOCKS);

    printf("\n  -- 定义为 0（头文件在，但程度要说运行时）--\n");
    printf("  _POSIX_MONOTONIC_CLOCK=%ld  _POSIX_CPUTIME=%ld  _POSIX_THREAD_CPUTIME=%ld\n",
           (long)_POSIX_MONOTONIC_CLOCK, (long)_POSIX_CPUTIME, (long)_POSIX_THREAD_CPUTIME);

    printf("\n  -- 定义为 -1（明确不支持）--\n");
    printf("  _POSIX_SPORADIC_SERVER=%ld  _POSIX_THREAD_SPORADIC_SERVER=%ld\n",
           (long)_POSIX_SPORADIC_SERVER, (long)_POSIX_THREAD_SPORADIC_SERVER);
    printf("  _POSIX_TRACE=%ld  _POSIX_TRACE_EVENT_FILTER=%ld  _POSIX_TYPED_MEMORY_OBJECTS=%ld\n",
           (long)_POSIX_TRACE, (long)_POSIX_TRACE_EVENT_FILTER, (long)_POSIX_TYPED_MEMORY_OBJECTS);

    printf("\n### ② 运行时：同一批选项用 sysconf(_SC_*) 再问一遍\n");
    sc("_SC_JOB_CONTROL", _SC_JOB_CONTROL);
    sc("_SC_SAVED_IDS", _SC_SAVED_IDS);
    sc("_SC_THREADS", _SC_THREADS);
    sc("_SC_REALTIME_SIGNALS", _SC_REALTIME_SIGNALS);
    sc("_SC_TIMERS", _SC_TIMERS);
    sc("_SC_SEMAPHORES", _SC_SEMAPHORES);
    sc("_SC_MONOTONIC_CLOCK", _SC_MONOTONIC_CLOCK);
    sc("_SC_CPUTIME", _SC_CPUTIME);
    sc("_SC_THREAD_CPUTIME", _SC_THREAD_CPUTIME);
    sc("_SC_2_C_DEV", _SC_2_C_DEV);
    sc("_SC_2_FORT_DEV", _SC_2_FORT_DEV);
    sc("_SC_2_LOCALEDEF", _SC_2_LOCALEDEF);
    sc("_SC_XOPEN_VERSION", _SC_XOPEN_VERSION);

    printf("\n  对照要点：_POSIX_MONOTONIC_CLOCK=0（编译期「说不清」），而\n");
    printf("  sysconf(_SC_MONOTONIC_CLOCK) 给出 200809 —— 编译期含糊的，运行时才有答案。\n");

    printf("\n### ③ confstr()：查「字符串」选项（sysconf 的字面兄弟）\n");
    struct { int name; const char *lbl; } cs[] = {
        { _CS_PATH, "_CS_PATH" },
        { _CS_GNU_LIBC_VERSION, "_CS_GNU_LIBC_VERSION" },
        { _CS_GNU_LIBPTHREAD_VERSION, "_CS_GNU_LIBPTHREAD_VERSION" },
    };
    for (size_t i = 0; i < sizeof(cs) / sizeof(cs[0]); i++) {
        errno = 0;
        size_t need = confstr(cs[i].name, NULL, 0);      /* 先问需要多大 */
        if (need == 0) {
            printf("  %-28s 无值（errno=%d）\n", cs[i].lbl, errno);
            continue;
        }
        char *buf = malloc(need);
        size_t got = confstr(cs[i].name, buf, need);
        printf("  %-28s 需要 %2zu B，写入 %2zu B: \"%s\"\n", cs[i].lbl, need, got, buf);
        free(buf);
    }
    printf("  注意：与 sysconf 一样，confstr 没有值的时候返回 0（不是 -1），\n");
    printf("        且**不保证**设置 errno —— 用 (confstr(n,NULL,0)) 判空即可。\n");

    printf("\n### ④ 三态判断在代码里怎么写才不会踩坑\n");
    printf("  错的：int have = _POSIX_BARRIERS;        // 宏没定义时编不过\n");
    printf("  对的：#ifdef _POSIX_BARRIERS              // 先判有没有\n");
    printf("            #if _POSIX_BARRIERS > 0 ...      // 再判支不支持\n");
    printf("            #else ... runtime ...            // ==0 要问运行时\n");
    printf("            #endif\n");
    printf("        #else  ... runtime ...               // 未定义也要问运行时\n");
    printf("        #endif\n");
    printf("  本机实测：_POSIX_BARRIERS=%ld（正值），sysconf 也给 %ld，两边一致。\n",
           (long)_POSIX_BARRIERS, sysconf(_SC_BARRIERS));
    return 0;
}
```


逐段看：

| 段 | 观察 | 说明 |
|----|------|------|
| ① | `_POSIX_JOB_CONTROL=1`、`_POSIX_SAVED_IDS=1` | 这两项是**特例**：值 `1` 不是年月，而是「支持」（`posix_opt.h:23` / `:26`）。glibc 用 `1` 表示「标准修订版还没发布时就已经支持」 |
| ① | `_POSIX_THREADS=200809` 等一批 `200809L` | 2008-09 = POSIX.1-2008（SUSv4）。这就是「值 = 描述它的修订版年月」 |
| ① | `_POSIX_MONOTONIC_CLOCK=0` / `_POSIX_CPUTIME=0` / `_POSIX_THREAD_CPUTIME=0` | **唯一「说不清」的三项**：头文件在、函数在，但支持程度要运行时问 |
| ① | `_POSIX_SPORADIC_SERVER=-1` / `_POSIX_TRACE=-1` / `_POSIX_TYPED_MEMORY_OBJECTS=-1` | 明确不支持 |
| ② | `_SC_MONOTONIC_CLOCK = 200809` | 编译期 `0` → 运行时 `200809`。**这一对是本节最重要的对照** |
| ② | `_SC_CPUTIME` / `_SC_THREAD_CPUTIME` 也都是 `200809` | 同上，`0` 只是「编译期不下结论」 |
| ② | `_SC_2_FORT_DEV = -1` | 真的不支持。glibc 为它留了专门的 case（`sysdeps/posix/sysconf.c:486-491`）：`#ifdef _POSIX2_FORT_DEV return _POSIX2_FORT_DEV; #else return -1; #endif`——宏没定义就返回 `-1` 且**不设 `errno`**，所以形式上与 indeterminate 同形 |
| ② | `_SC_XOPEN_VERSION = 700` | X/Open 版本号是 **700**，不是年月（XPG7）。所以「值 = 年月」只是**通常**，不是铁律 |
| ③ | `_CS_PATH` 需要 **14 B**，写入 14 B（含结尾 `\0`） | `"/bin:/usr/bin"` 是 13 个字符 + `\0`。**`confstr` 的长度含结尾空字节** |
| ③ | 先用 `confstr(name, NULL, 0)` 问长度，再 `malloc` | 标准用法。失败时返回 **0**（与 `sysconf` 的 `-1` 不同），且**不保证**设 `errno` |
| ④ | `#ifdef` → `#if > 0` → `#else runtime` | 三态嵌套。直接 `int have = _POSIX_BARRIERS;` 在宏未定义时是**编译错误**（本仓库在 CE 上实测过 `error: 'OPEN_MAX' undeclared` 这类） |

### 2.1 为什么 glibc 用 `_POSIX_MONOTONIC_CLOCK = 0`

看 `posix_opt.h` 的实际内容：

| 宏 | 值 | 行 |
|----|----|----|
| `_POSIX_JOB_CONTROL` | 1 | `sysdeps/unix/sysv/linux/bits/posix_opt.h:23` |
| `_POSIX_SAVED_IDS` | 1 | `:26` |
| `_POSIX_PRIORITY_SCHEDULING` | 200809L | `:32` |
| `_POSIX_SEMAPHORES` | 200809L | `:103` |
| `_POSIX_REALTIME_SIGNALS` | 200809L | `:106` |
| `_POSIX_CPUTIME` | **0** | `:128` |
| `_POSIX_THREAD_CPUTIME` | **0** | `:131` |
| `_POSIX_SPIN_LOCKS` | 200809L | `:146` |
| `_POSIX_TIMERS` | 200809L | `:152` |
| `_POSIX_BARRIERS` | 200809L | `:155` |
| `_POSIX_MONOTONIC_CLOCK` | **0** | `:164` |
| `_POSIX_SPORADIC_SERVER` | -1 | `:182` |
| `_POSIX_THREAD_SPORADIC_SERVER` | -1 | `:183` |
| `_POSIX_TRACE` | -1 | `:186` |
| `_POSIX_TYPED_MEMORY_OBJECTS` | -1 | `:192` |

理由：**「支持」这两个字对 `_POSIX_MONOTONIC_CLOCK` 没有单一答案**——有的 CPU/内核上 `CLOCK_MONOTONIC` 可用，有的要靠回退实现。所以 glibc 不在编译期下结论，一律让运行时 `sysconf(_SC_MONOTONIC_CLOCK)` 回答。

而 `sysconf` 那边的实现是**直接返回 `_POSIX_VERSION`**（`sysdeps/unix/sysv/linux/sysconf.c:51-54`）：

```c
    case _SC_MONOTONIC_CLOCK:
    case _SC_CPUTIME:
    case _SC_THREAD_CPUTIME:
      return _POSIX_VERSION;
```

`_POSIX_VERSION` 本机 = `200809L` → 就是实测的 `200809`。**「编译期 0」+「运行时 200809」不是矛盾，是分工。**

## 3. `confstr()`：查字符串选项

`sysconf` 只能给数；有些选项的答案是**字符串**（搜索路径、版本号），那是 `confstr`：

```c
#include <unistd.h>
size_t confstr(int name, char *buf, size_t len);
/* 返回「写入的字节数（含结尾 \0）」；name 无值时返回 0 */
```

| name | 本机结果 | glibc 位置 |
|------|---------|-----------|
| `_CS_PATH` | `"/bin:/usr/bin"`（14 B 含 `\0`） | `posix/confstr.c:43` |
| `_CS_GNU_LIBC_VERSION` | `"glibc 2.39"`（11 B 含 `\0`） | `:252` |
| `_CS_GNU_LIBPTHREAD_VERSION` | `"NPTL 2.39"`（10 B 含 `\0`） | `:257` |

三个关键差异（与 `sysconf` 比）：

| | `sysconf` | `confstr` |
|---|----------|----------|
| 失败信号 | `-1`（三义，见 [11.2](11.2-runtime-limits.md)） | **`0`** |
| 是否设 `errno` | 真错误时才设 | **不保证**设 |
| 「先问长度」 | 不支持 | 支持：`confstr(name, NULL, 0)` |

标准用法（demo 里的循环）：

```c
size_t need = confstr(name, NULL, 0);   /* 先问需要多大（含结尾 \0） */
if (need == 0) { /* 无值：直接回退，别去看 errno */ }
char *buf = malloc(need);
confstr(name, buf, need);
```

退出码里 `:265` / `:277` 的 `return 0;` 就是 glibc 在「这个 `name` 没有值」时走的路——`_CS_V6_WIDTH_RESTRICTED_ENVS` 这类在当前配置下拿不到值的项。

## 4. 常见坑

| 坑 | 说明 |
|----|------|
| 直接 `int s = _POSIX_BARRIERS;` | 宏未定义时**编译不过**（不是 0）。必须先 `#ifdef` |
| 把 `_POSIX_FOO == 0` 当「不支持」 | `0` 的官方含义是「**头文件和函数在**，支持程度问运行时」。`_POSIX_MONOTONIC_CLOCK=0` 但运行时明确支持 |
| 把 `_POSIX_FOO` 的值当年月 | 多数是年月（`200809L`），但 `_POSIX_JOB_CONTROL`/`_POSIX_SAVED_IDS` 是 `1`，`_SC_XOPEN_VERSION` 是 `700`。**别做算术** |
| 只信编译期宏就下结论 | man-pages 原文第一条就是「If it is undefined, one should ask at run time」 |
| `confstr` 失败时看 `errno` | 它返回 `0` 表示「无值」，且**不保证**设 `errno`。用返回值判 |
| `confstr` 的缓冲按「字符串长度」分配 | 返回值/需求长度**含结尾 `\0`**（`"/bin:/usr/bin"` 13 字符 → 14 B） |
| 编译期 `_POSIX_VERSION` 当真 | 交叉编译时它来自工具链头文件，不是目标板；要判断目标板能力必须运行时 `sysconf` |
| 混淆 `_SC_THREADS` 与 `_POSIX_THREADS` | 一个是运行时入口、一个是编译期宏。两边都给 `200809` 不代表永远一致 |

## 5. HFT / 嵌入式关联

| 场景 | 本节机制怎么兑现 |
|------|----------------|
| 选时钟源 | `CLOCK_MONOTONIC` / `CLOCK_CPUTIME` 这类「编译期 0」的选项，**必须**在启动时 `sysconf(_SC_MONOTONIC_CLOCK)` 确认。只信 `#ifdef _POSIX_MONOTONIC_CLOCK` 会误判（它是 `0`，`#if` 判定为假） |
| 实时信号 | `_SC_REALTIME_SIGNALS = 200809` 本机支持；信号驱动 I/O 与 `sigqueue` 依赖它。启动自检里打一遍 |
| 线程与同步 | `_SC_BARRIERS` / `_SC_SPIN_LOCKS` / `_SC_READER_WRITER_LOCKS` 全 `200809`；要极致低延迟自旋锁就直接用，不必自己造 |
| POSIX 定时器 | `_SC_TIMERS` 决定能否用 `timer_create`；`_SC_CPUTIME` 决定能否用 `CLOCK_PROCESS_CPUTIME_ID` 做超时预算 |
| 嵌入式裁剪 | 越小的 rootfs 越可能把 `_POSIX_FOO` 编成 `-1` 或不定义。**功能探测要写成「宏 + 运行时双查」**（④ 段骨架），别只写一半 |
| 版本与兼容 | `_CS_GNU_LIBC_VERSION` 比 `gnu_get_libc_version()` 更通用（后者是 glibc 私有）；启动日志里打它，能直接区分「同一二进制跑在哪个 libc 上」 |
| 容器/发行版差异 | `_SC_XOPEN_VERSION = 700` 说明本机是 XPG7。跨发行版移植时这一项可以进兼容矩阵 |

<summary>代码自测（Q&A）</summary>

**Q1：`_POSIX_FOO` 有几种状态？分别怎么读？**
A：四种。① 未定义 → 编译期不知道，**运行时问**；② `-1` → 明确不支持；③ `0` → 头文件/函数在，但支持程度**运行时问**；④ 其他正值 → 支持，值通常是 POSIX 修订版年月（`200809L`）。只有第 ④ 种是编译期可定的。

**Q2：`_POSIX_MONOTONIC_CLOCK = 0` 但 `sysconf(_SC_MONOTONIC_CLOCK) = 200809`，信哪个？**
A：**信运行时**。`0` 的含义是「相关函数和头文件存在，但支持到什么程度要问运行时」（man-pages 原文）。glibc 觉得单调时钟的可用性依赖 CPU/内核，编译期不下结论；`sysconf` 那条分支（`sysdeps/unix/sysv/linux/sysconf.c:51-54`）直接 `return _POSIX_VERSION`，本机是 `200809`。

**Q3：为什么 `_POSIX_JOB_CONTROL` 是 `1` 而不是 `200809L`？**
A：man-pages 解释了：「glibc uses the value `1` to indicate support as long as the POSIX revision has not been published yet.」`_POSIX_JOB_CONTROL` / `_POSIX_SAVED_IDS` 在 `posix_opt.h:23` / `:26` 就是 `1`。所以**不要对 `_POSIX_*` 的值做算术**，只能判「>0 / ==0 / ==-1」。

**Q4：`confstr` 和 `sysconf` 的失败信号有什么不同？**
A：`sysconf` 失败返回 `-1`（且要配 `errno` 判真错误）；`confstr` 在「该 name 无值」时返回 **`0`**，并且**不保证设置 `errno`**。另外 `confstr` 的**返回值含结尾 `\0`**：实测 `_CS_PATH` 返回 14（`"/bin:/usr/bin"` 是 13 个字符）。

**Q5：`confstr` 的正确调用姿势是什么？**
A：先用 `confstr(name, NULL, 0)` 问需要多大，再 `malloc(need)` + `confstr(name, buf, need)`。demo 的 ③ 段就是这么写的。注意 `size_t` 参数与返回值都别和 `int` 混。

**Q6：为什么 `#ifdef` 不能省？**
A：因为**未定义的宏不是 0**。写 `int have = _POSIX_BARRIERS;` 在未定义时是编译错误；写 `#if _POSIX_BARRIERS` 在未定义时被当作 0（**等于把「不知道」误当成「不支持」**）。正确姿势是 `#ifdef` 先确定「有没有这个宏」，再 `#if > 0` 判支持程度。

**Q7：`_SC_2_FORT_DEV` 返回 `-1`，这和 `_SC_TZNAME_MAX` 的 `-1` 一样吗？**
A：返回值与 `errno` 一模一样（都是 `-1` + `errno` 不变），但**语义不同**：前者是「选项不支持」，后者是「限制 indeterminate」。参见 [11.2](11.2-runtime-limits.md) ⑤b/⑤c 的现场。这也是本节为什么把「选项」和「限制」分成两章讲。

**Q8：`_SC_XOPEN_VERSION = 700` 说明什么？**
A：本机符合 **X/Open Portability Guide 第 7 版（XPG7）**。这里暴露一个事实：选项返回值**不都是年月**（`700` 是版本号）。要判断具体能力还是得查 `posixoptions(7)` 的对照表。
