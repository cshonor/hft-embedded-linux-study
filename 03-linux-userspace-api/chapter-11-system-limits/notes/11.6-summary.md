## 本章回顾：一条主线，五个分叉

本章从头到尾只在回答一个问题：**「这个上限/特性，我能不能写死？」** 答案统一是「不能」，但**不能的理由和应对手段**按分叉各不相同：

| 节 | 分叉 | 一句话 |
|----|------|-------|
| [11.1](11.1-system-limits.md) | 术语与分类 | limit ≠ option；三类限制决定用哪个查询函数 |
| [11.2](11.2-runtime-limits.md) | `sysconf` | 一个 `-1` 三种含义，其中两种**不可区分** |
| [11.3](11.3-file-related-limits.md) | `pathconf` / `fpathconf` | 只有 3~5 个 `_PC_*` 真的问文件系统，其余是常量转发 |
| [11.4](11.4-indeterminate-limits.md) | indeterminate | 「不回答」是合法状态；查不到就走降级阶梯 |
| [11.5](11.5-system-options.md) | option 四态 | 编译期只有「正值」一态可定，其余全要运行时确认 |

## 决策表：要查什么 → 用哪个入口

| 想查的东西 | 入口 | 常量形态 | 记得判 |
|-----------|------|---------|-------|
| 进程级上限（fd 数、参数长度、子进程数） | `sysconf` | `_SC_*` | `-1` 三义（`errno`） |
| 路径/目录/文件系统相关上限 | `pathconf(path,…)` | `_PC_*` | `-1` 三义 + `ENOTDIR` 等 |
| 已打开对象相关上限 | `fpathconf(fd,…)` | `_PC_*` | 同上，另加 `EBADF` |
| 字符串选项（搜索路径、版本号） | `confstr` | `_CS_*` | 返回值 **0** 表示无值 |
| 编译期已知的支持情况 | `<limits.h>` / `<unistd.h>` 宏 | `_POSIX_*` | 先 `#ifdef` 再 `#if > 0` |
| Shell 一侧 | `getconf` | 同名 | 容器里可能**没有** `getconf` |

### 关键「名义值 vs 真实值」

| 项 | 名义 | 真实墙 |
|----|------|-------|
| 参数长度 | `_SC_ARG_MAX = 2097152` | `MAX_ARG_STRLEN = PAGE_SIZE*32 = 131072`（131072 时即 `E2BIG`） |
| 管道原子写 | `PIPE_BUF = 4096` | 与管道容量（默认 65536）无关 |
| fd 上限 | `_SC_OPEN_MAX = 100` | soft 用满时**第 48 个**就 `EMFILE`（soft=50 时只能开 47 个） |

## 「反直觉」清单

1. **`sysconf(_SC_OPEN_MAX)` 会变** —— 它不是上限，是 `RLIMIT_NOFILE.rlim_cur` 的快照；man-pages 说「进程生命期内不变」这句对限制类不成立。
2. **「限制 indeterminate」和「选项不支持」不可区分** —— 都是 `-1` 且 `errno` 不变。只能靠「你知道自己在问哪一类」。
3. **`errno != 0` 不代表这次调用失败** —— `_SC_NPROCESSORS_ONLN` 值正确、`errno` 却是 `ENOENT`；`pathconf("/lib", _PC_LINK_MAX)` 值正确、`errno` 却是 `ENOENT`。**只在返回 `-1` 时看 `errno`**。
4. **`pathconf` 大多数项不查文件系统** —— `_PC_PATH_MAX` / `_PC_PIPE_BUF` 在 glibc 里就是 `return 一个宏`。
5. **`_PC_NAME_MAX` 能不是 255** —— squashfs 报 256（来自超级块的 `f_namemax`）。
6. **`pathconf` 不检查「是不是终端」** —— `_PC_MAX_CANON` 对目录也返回 255、`_PC_VDISABLE` 返回 0。「有值」≠「有意义」。
7. **`pathconf("")` 是 `ENOENT` 而不是 `EINVAL`** —— glibc 专门加了空串前置判断。
8. **`confstr` 失败返回 0 而不是 -1** —— 而且**不保证**设 `errno`。
9. **`_POSIX_MONOTONIC_CLOCK = 0` 但运行时 `200809`** —— `0` 不是「不支持」，是「编译期不下结论」。
10. **`getconf` 在容器里可能不存在** —— CE 沙箱里没有 `/usr/bin/getconf`，交叉验证得自己写程序。
11. **glibc 主动 `#undef` 了部分限制宏** —— `OPEN_MAX` / `ARG_MAX` / `LINK_MAX` / `NR_OPEN` 用之前必须 `#ifdef`，否则编译不过。
12. **`_POSIX_CLK_TCK` 根本不存在** —— POSIX 只说 `CLK_TCK` 这符号已废弃删除，不承诺任何下限。

## 常见错误码（本章实测到的）

| 调用 | 条件 | `errno` | 值 |
|------|------|--------|----|
| `sysconf(9999)` | `name` 非法 | `EINVAL`(22) | -1 |
| `sysconf(_SC_TZNAME_MAX)` | indeterminate | 0（不变） | -1 |
| `pathconf("")` | 空路径 | `ENOENT`(2) | -1 |
| `pathconf("/no/such/dir/xyz")` | 路径不存在 | `ENOENT`(2) | -1 |
| `pathconf("/proc/version/inside")` | 中间不是目录 | `ENOTDIR`(20) | -1 |
| `pathconf("/", 9999)` | `name` 非法 | `EINVAL`(22) | -1 |
| `fpathconf(9999, …)` | fd 无效 | `EBADF`(9) | -1 |
| `fpathconf(STDIN_FILENO, 9999)` | `name` 非法 | `EINVAL`(22) | -1 |
| `execve` 参数 131072 字节 | 超 `MAX_ARG_STRLEN` | `E2BIG`(7) | 失败 |
| 开第 48 个 fd（soft=50） | 用满 | `EMFILE`(24) | 失败 |
| `setrlimit` 抬 soft 到 hard+1 | 超硬上限 | `EINVAL`(22) | rc=-1 |

## 沙箱环境限制表（CE 实测）

摸底记录（`_ch11_probe2.txt`）：

```text
  _SC_CHILD_MAX          = 56783        errno=0
  RLIMIT_NOFILE    soft=100          hard=100
  RLIMIT_NPROC     soft=56783        hard=56783
  RLIMIT_STACK     soft=8388608      hard=8388608
```

改 rlimit 与用满 fd：

```text
  尝试把 soft 抬到 hard+1: rc=-1 errno=22 (Invalid argument)
  把 soft 降到 50:          rc=0 errno=0 (Success)
    _SC_OPEN_MAX (now)   = 50           errno=0
  成功开到 47 个 fd，第 48 个失败：errno=24 (Too many open files)
```

| 事实 | 值 |
|------|----|
| `RLIMIT_NOFILE` | soft = hard = **100**（`getdtablesize()` 同为 100） |
| `RLIMIT_NPROC` / `RLIMIT_SIGPENDING` | 同值（56783），所以 `_SC_CHILD_MAX` = `_SC_SIGQUEUE_MAX` |
| `RLIMIT_STACK` | 8388608（8 MiB）→ 决定 `_SC_ARG_MAX` |
| `/bin/sh`、`/usr/bin/getconf`、`/dev/fd` | **不存在** |
| `/dev/shm` | **不存在**（`pathconf` 对它的 `_PC_LINK_MAX` 等全部 `ENOENT`） |
| 主要挂载点 | `/`、`/tmp`、`/dev` = tmpfs；`/lib`、`/usr/lib`、`/app` = ext4；`/opt/compiler-explorer` = nfs4；`/cefs/**` = autofs + squashfs |

> ⚠️ **可复现性说明**：本表里 `_SC_CHILD_MAX`（56783 ↔ 54956）、`_SC_AVPHYS_PAGES`、`_SC_MINSIGSTKSZ` / `_SC_SIGSTKSZ`、`_SC_PHYS_PAGES` 属于「随宿主机状态变化」的项，重跑一次就会不同；`_SC_ARG_MAX` / `_SC_OPEN_MAX` / `_SC_PAGESIZE` / `_SC_CLK_TCK` / 各 `_POSIX_*` 下限则稳定。写笔记引用数字时必须注明是哪一次运行。

## HFT / 嵌入式关联

| 场景 | 本章结论怎么用 |
|------|--------------|
| 启动自检 | 把 `_SC_ARG_MAX` / `_SC_OPEN_MAX` / `_SC_CLK_TCK` / `_SC_PAGESIZE` / 关键目录的 `_PC_NAME_MAX` 全部落日志。容器的存储驱动、rlimit、页大小一变，同样的二进制行为就变 |
| fd 上限 | 先 `setrlimit(RLIMIT_NOFILE)` 再 `sysconf(_SC_OPEN_MAX)` 复验——不要在没抬过的状态下把值写进监控 |
| 跨进程消息 | 单次 `write` ≤ `PIPE_BUF`（4096）才保证不交错；管道容量（65536）是另一回事 |
| 批量 `exec` | 参数上限按内核 `MAX_ARG_STRLEN = 128 KiB` 算，不是 `_SC_ARG_MAX` 的 2 MiB |
| 文件名/路径缓冲 | `pathconf(dir, _PC_NAME_MAX) + 1`；只在「cwd 相对路径」语义下 `_PC_PATH_MAX` 才有意义，绝对路径要动态扩容 |
| 特性探测 | 用「`#ifdef` + `#if > 0` + 运行时 `sysconf`」三态骨架；`_POSIX_MONOTONIC_CLOCK = 0` 是真会出现的中间态 |
| 嵌入式裁剪 | 越裁剪的实现越多 indeterminate。程序必须有回退路径（降级阶梯），不能假设「查得到」 |

<summary>本章自测（Q&A）</summary>

**Q1：一句话概括本章的核心技能。**
A：**分清三个 `-1`**：`errno != 0` 是真错误；`errno == 0` 可能是「限制 indeterminate」也可能是「选项不支持」（不可区分）；而返回值不是 `-1` 时 `errno` 无意义。剩下的一切（三类限制、四个查询入口、四态选项宏）都是围绕这件事展开的。

**Q2：本章 7 个自编 demo 各自解决什么问题？**
A：`c11_1_three_kinds.c` 一次实验分清类 1 与类 3；`c11_2_sysconf_table.c` 全表 + `-1` 三义 + 两种误判；`c11_3_pathconf_matrix.c` 文件系统 × fd 类型 × 错误码三个矩阵；`c11_4_indeterminate.c` indeterminate 清单 + 安全封装 + 降级阶梯；`c11_5_options.c` 选项四态 + `confstr`；`ex11_1_sysconf_wide.c` 习题 11-1；`ex11_2_fs_sweep.c` 习题 11-2。

**Q3：如果要写一个「生产可用」的限制查询库，必备哪几件事？**
A：① 每个查询都 `errno = 0` 前置清零、只在 `-1` 时读 `errno`；② 状态与值分开返回（`enum` + `long`）；③ 真错误直接暴露（不静默降级）；④ indeterminate 走显式降级阶梯并把「来源」一起返回；⑤ 对会因为 `#undef` 而不存在的宏套 `#ifdef`；⑥ 对会漂移的项（`_SC_CHILD_MAX` 等）不做跨进程缓存。

**Q4：本章哪些实测数字是「一次运行有效」，哪些是「环境常量」？**
A：稳定：`_SC_ARG_MAX`(2097152)、`_SC_OPEN_MAX`(100)、`_SC_PAGESIZE`(4096)、`_SC_CLK_TCK`(100)、`_SC_VERSION`(200809)、各 `_POSIX_*` 下限、`pathconf` 的 `LINK_MAX`/`FILESIZEBITS`/`NAME_MAX`。会漂移：`_SC_CHILD_MAX`、`_SC_SIGQUEUE_MAX`、`_SC_PHYS_PAGES`、`_SC_AVPHYS_PAGES`、`_SC_MINSIGSTKSZ`、`_SC_SIGSTKSZ`、ex11_2 的挂载点计数。引用前者的数字可以直接抄，引用后者必须注明是哪一次运行。

**Q5：为什么本章要专门写一节的「沙箱环境限制表」？**
A：因为本章所有结论都依赖「跑在什么环境里」。CE 容器把 `RLIMIT_NOFILE` 设成 100（不是常见的 1024/1048576），没有 `getconf`、没有 `/dev/shm`，`/tmp` 是 tmpfs——这些前提不写清，读者会以为「`_SC_OPEN_MAX` 就是 100」或「`pathconf` 问 `/tmp` 一定成功」。
