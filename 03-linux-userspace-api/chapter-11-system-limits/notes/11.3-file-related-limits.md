# 11.3 Retrieving File-Related Limits (and Options) at Run Time 文件相关限制

## 本节讲什么

本节是「类 2 限制」的实现细节。它的核心结论有点反直觉：

> **`pathconf()` 里只有 4 个 `_PC_*` 真的去问了文件系统。** 其余大多数是把编译期常量原样返回。

所以本节要回答：

1. 哪些 `_PC_*` **真的**随文件系统变？哪些只是「穿着 `pathconf` 外衣的 `#define`」？
2. 同一组问题问 `/`（tmpfs）和 `/lib`（ext4），哪些格子会变？变多少？
3. `_PC_PIPE_BUF` 是「这个管道的容量」吗？（不是）
4. 空串、不存在的路径、路径中间不是目录，`errno` 分别是多少？

---

## 1. 原型

```c
#include <unistd.h>

long fpathconf(int fd, int name);
long pathconf(const char *path, int name);
/* 成功返回该配置项的值；-1 的三义与 sysconf() 完全一致（见 11.2） */
```

man-pages 6.19 `fpathconf(3)` 对两者的区别只有一句：

> `fpathconf()` gets a value for the configuration option `name` for the open file descriptor `fd`.
>
> `pathconf()` gets a value for configuration option `name` for the filename `path`.

以及一句容易被忽略的：

> The corresponding macros defined in `<unistd.h>` are minimum values; if an application wants to take advantage of values which may change, a call to `fpathconf()` or `pathconf()` can be made, **which may yield more liberal results**.

### ERRORS（man-pages 原文列出，本仓库实测逐条验证）

| `errno` | 何时 | 本仓库实测（见第 4 节 C 段） |
|---------|------|--------------------------|
| `EACCES` | `path` 的某个前缀目录没有搜索权限 | 未构造（CE 沙箱是 root） |
| `EBADF` | `fd` 不是有效 fd（仅 `fpathconf`） | `fpathconf(9999, …)` → `errno=9` |
| `EINVAL` | `name` 非法，**或该实现不支持把 `name` 关联到这个文件** | `pathconf("/", 9999)` → `errno=22` |
| `ELOOP` | 解析 `path` 时符号链接层数过多 | 未构造 |
| `ENAMETOOLONG` | `path` 太长 | 未构造 |
| `ENOENT` | `path` 的某一段不存在 | `pathconf("/no/such/dir/xyz", …)` → `errno=2` |
| `ENOTDIR` | `path` 的某一段不是目录 | `pathconf("/proc/version/inside", …)` → `errno=20` |

## 2. `_PC_*` 的真实分工

| `_PC_*` | man-pages 语义 | glibc 2.39 的实际实现 | 会随文件系统变吗 |
|---------|---------------|---------------------|----------------|
| `_PC_LINK_MAX` | 文件最大硬链接数（对目录＝该目录内） | `__statfs_link_max()`：按 `statfs().f_type` **查表** | **会**（ext4 65000 / 其余 127） |
| `_PC_FILESIZEBITS` | 文件大小所需位数 | `__statfs_filesize_max()`：按 `f_type` **查表** | **会**（ext4 64 / 其余 32） |
| `_PC_NAME_MAX` | 该目录里允许创建的文件名最大长度 | `statvfs().f_namemax`（**超级块上报**） | **会**（squashfs 报 256） |
| `_PC_PATH_MAX` | **相对路径**最大长度（当 `path`/`fd` 是当前工作目录时） | **直接 `return PATH_MAX;`** | 不会（恒 4096） |
| `_PC_PIPE_BUF` | 能**原子写入**管道/FIFO 的最大字节数 | **直接 `return PIPE_BUF;`** | 不会（恒 4096） |
| `_PC_CHOWN_RESTRICTED` | `chown` 是否受限 | `return _POSIX_CHOWN_RESTRICTED;` | 不会 |
| `_PC_NO_TRUNC` | 超长文件名是否报错（而非截断） | `return _POSIX_NO_TRUNC;` | 不会 |
| `_PC_VDISABLE` | 终端「禁用字符」的值 | `return _POSIX_VDISABLE;`（**不检查是不是终端**） | 不会 |
| `_PC_ASYNC_IO` | 是否支持异步 I/O | `S_ISREG(mode) \|\| S_ISBLK(mode)` 才 `1`，否则 `-1` | 看**对象类型**，不看文件系统 |

> **结论：把 `pathconf()` 当成「问文件系统」的万能入口是错的。** 真正落到文件系统的只有前 3 项（加上 4 个 statfs 项里的 `_PC_2_SYMLINKS` / `_PC_CHOWN_RESTRICTED`），其余是常量转发。

## 3. 原书 Listing 11-2（page 218）：`t_fpathconf.c`

原书示例对 `STDIN_FILENO` 问三项。逐字镜像（本仓库 [`code/t_fpathconf.c`](../code/t_fpathconf.c)）：

```c
/* t_fpathconf.c

   Demonstrate the use of fpathconf() to retrieve the values of
   pathname-related limits.
*/
#include "tlpi_hdr.h"
static void             /* Print 'msg' plus value of fpathconf(fd, name) */
fpathconfPrint(const char *msg, int fd, int name)
{
    long lim;

    errno = 0;
    lim = fpathconf(fd, name);
    if (lim != -1) {        /* Call succeeded, limit determinate */
        printf("%s %ld\n", msg, lim);
    } else {
        if (errno == 0)     /* Call succeeded, limit indeterminate */
            printf("%s (indeterminate)\n", msg);
        else                /* Call failed */
            errExit("fpathconf %s", msg);
    }
}
int
main(int argc, char *argv[])
{
    fpathconfPrint("_PC_NAME_MAX: ", STDIN_FILENO, _PC_NAME_MAX);
    fpathconfPrint("_PC_PATH_MAX: ", STDIN_FILENO, _PC_PATH_MAX);
    fpathconfPrint("_PC_PIPE_BUF: ", STDIN_FILENO, _PC_PIPE_BUF);
    exit(EXIT_SUCCESS);
}
```

结构与 Listing 11-1 同构：`errno = 0` → `fpathconfPrint()` → 非 `-1` 打印值 / `errno == 0` 打 `(indeterminate)` / 否则 `errExit`。

编译运行：

```bash
gcc -O0 -Wall -Wextra -Wno-unused-parameter -o t_fpathconf t_fpathconf.c && ./t_fpathconf
```

CE（gcc 13.3.0 / x86-64 / Ubuntu 24.04）实测：

```text
_PC_NAME_MAX:  255
_PC_PATH_MAX:  4096
_PC_PIPE_BUF:  4096
```

三项都拿到了值。注意这里 `STDIN_FILENO` 在沙箱里是**管道**（不是终端），但三项照样有答案——因为 glibc 的这三项**不看 fd 指向什么**（`_PC_NAME_MAX` 走 `statvfs`，管道 fd 也能 `statvfs` 成功）。

## 4. 自编：三种维度的矩阵

`t_fpathconf` 只问了一个 fd、三项；本 demo 把「换文件系统」「换 fd 类型」「换错误条件」三个维度都拉开。

完整源码 [`code/c11_3_pathconf_matrix.c`](../code/c11_3_pathconf_matrix.c)：

```c
/* c11_3_pathconf_matrix.c — Ch11 §11.3：pathconf() / fpathconf() 到底查了什么
 *
 * §11.3 的核心不是「会调用这两个函数」，而是搞清哪些 _PC_* 真的会去问文件
 * 系统、哪些其实只是把编译期常量原样返回。本程序用一个矩阵把它分开：
 *
 *   A. 同一组问题，问两个**不同文件系统**上的路径（/ 是 tmpfs，/lib 是 ext4）。
 *      只有 _PC_LINK_MAX / _PC_FILESIZEBITS 变了 —— 它们是按 statfs().f_type
 *      分派的；_PC_NAME_MAX 来自 statvfs().f_namemax；而 _PC_PATH_MAX 与
 *      _PC_PIPE_BUF 无论问谁都是同一个编译期常量。
 *
 *   B. 同一组问题，问四种**不同 fd 类型**。_PC_ASYNC_IO 会分叉（普通文件 1，
 *      管道/字符设备 -1），其余照旧。
 *
 *   C. 错误码矩阵：空串、不存在的路径、路径中间不是目录、非法 name、非法 fd。
 *
 * 编译： gcc -O0 -Wall -Wextra -o c11_3_pathconf_matrix c11_3_pathconf_matrix.c
 * 取材： glibc 2.39 sysdeps/unix/sysv/linux/pathconf.c:45-55（按 statfs 分派四项）
 *        glibc 2.39 sysdeps/unix/sysv/linux/pathconf.c:63-128（distinguish_extX：/sys/dev/block -> /proc/mounts）
 *        glibc 2.39 sysdeps/posix/pathconf.c:32-36（空串 -> ENOENT）
 *        glibc 2.39 sysdeps/posix/pathconf.c:40-42（default -> EINVAL）
 *        glibc 2.39 sysdeps/posix/pathconf.c:65-86（_PC_NAME_MAX -> statvfs.f_namemax）
 *        glibc 2.39 sysdeps/posix/pathconf.c:89-93（_PC_PATH_MAX -> PATH_MAX 常量）
 *        glibc 2.39 sysdeps/posix/pathconf.c:96-100（_PC_PIPE_BUF -> PIPE_BUF 常量）
 *        glibc 2.39 sysdeps/unix/sysv/linux/linux_fsinfo.h:256 EXT4_LINK_MAX=65000
 *        glibc 2.39 sysdeps/unix/sysv/linux/linux_fsinfo.h:268 LINUX_LINK_MAX=127
 *        Linux v6.6 include/uapi/linux/limits.h:13-14 PATH_MAX/PIPE_BUF
 */
#define _GNU_SOURCE
#include <errno.h>
#include <fcntl.h>
#include <limits.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <sys/statfs.h>
#include <sys/statvfs.h>
#include <unistd.h>

struct item { int name; const char *lbl; };

static const struct item PC[] = {
    { _PC_NAME_MAX,  "_PC_NAME_MAX" },
    { _PC_LINK_MAX,  "_PC_LINK_MAX" },
    { _PC_FILESIZEBITS, "_PC_FILESIZEBITS" },
    { _PC_PATH_MAX,  "_PC_PATH_MAX" },
    { _PC_PIPE_BUF,  "_PC_PIPE_BUF" },
    { _PC_NO_TRUNC,  "_PC_NO_TRUNC" },
    { _PC_CHOWN_RESTRICTED, "_PC_CHOWN_RESTRICTED" },
    { _PC_ASYNC_IO,  "_PC_ASYNC_IO" },
};

/* 两列对照打印：值 + errno + 是否不同 */
static void row(const char *what, long a, int ea, long b, int eb)
{
    printf("  %-20s %-8ld (errno %d)   %-8ld (errno %d)   %s\n",
           what, a, ea, b, eb, (a != b) ? "** 不同 **" : "相同");
}

static void matrix_paths(void)
{
    const char *p1 = "/";       /* CE 沙箱里是 tmpfs */
    const char *p2 = "/lib";    /* 绑定挂载的 ext4 */
    FILE *f;
    char dev[128], mnt[128], type[32];

    printf("### A. 同一组问题问两个文件系统\n");
    printf("  %-20s %-19s %-19s %s\n", "", p1, p2, "");
    for (size_t i = 0; i < sizeof(PC) / sizeof(PC[0]); i++) {
        errno = 0; long a = pathconf(p1, PC[i].name); int ea = errno;
        errno = 0; long b = pathconf(p2, PC[i].name); int eb = errno;
        row(PC[i].lbl, a, ea, b, eb);
    }

    printf("\n  两者的身份（读 /proc/mounts + statfs）：\n");
    for (int k = 0; k < 2; k++) {
        const char *p = k ? p2 : p1;
        struct statfs sf;
        if (statfs(p, &sf) != 0) { printf("    statfs(%s) 失败\n", p); continue; }
        struct statvfs sv;
        long nm = statvfs(p, &sv) == 0 ? (long)sv.f_namemax : -1;
        printf("    %-6s f_type=0x%-8lx f_namemax=%-4ld", p, (unsigned long)sf.f_type, nm);
        f = fopen("/proc/mounts", "r");
        if (f) {
            while (fscanf(f, "%127s %127s %31s %*s %*s %*s", dev, mnt, type) == 3)
                if (strcmp(mnt, p) == 0) break;
            fclose(f);
            printf(" 挂载类型=%s\n", type);
        } else {
            printf("\n");
        }
    }
    printf("\n  glibc 的分工（源码）：_PC_LINK_MAX/_PC_FILESIZEBITS 按 statfs().f_type 查表；\n");
    printf("  _PC_NAME_MAX 取 statvfs().f_namemax；_PC_PATH_MAX 直接 return PATH_MAX；\n");
    printf("  _PC_PIPE_BUF 直接 return PIPE_BUF。后两个与文件系统无关。\n");
    printf("  （A 段 _PC_LINK_MAX 问 /lib 那一格带着 errno=2：glibc 区分 ext2/3/4 时要先\n");
    printf("    readlink /sys/dev/block/MAJ:MIN，失败再退到 /proc/mounts；失败那一次把\n");
    printf("    ENOENT 留在了 errno 里。值是对的，errno 脏了。）\n");
}

static void matrix_fds(void)
{
    int pipefd[2];
    if (pipe(pipefd) != 0) { perror("pipe"); return; }
    const char *regpath = "/etc/hostname";
    int reg = open(regpath, O_RDONLY);
    if (reg < 0) { regpath = "/proc/version"; reg = open(regpath, O_RDONLY); }
    int nul = open("/dev/null", O_RDONLY);

    struct { const char *lbl; int fd; } fds[] = {
        { "STDIN_FILENO", STDIN_FILENO },
        { "pipe read end", pipefd[0] },
        { "regular file",  reg },
        { "/dev/null",     nul },
    };

    printf("\n### B. 同一组问题问四种 fd\n");
    printf("  %-20s %-12s %-12s %-12s %-12s\n", "", fds[0].lbl, fds[1].lbl,
           fds[2].lbl, fds[3].lbl);
    for (size_t i = 0; i < sizeof(PC) / sizeof(PC[0]); i++) {
        long v[4]; int e[4];
        printf("  %-20s", PC[i].lbl);
        for (int k = 0; k < 4; k++) {
            errno = 0;
            v[k] = (fds[k].fd < 0) ? -1 : fpathconf(fds[k].fd, PC[i].name);
            e[k] = errno;
            if (v[k] == -1 && e[k] == 0) printf(" %-12s", "-1(indet)");
            else if (v[k] == -1)         printf(" %-12s", "ERR");
            else                          printf(" %-12ld", v[k]);
        }
        printf("\n");
    }
    printf("  说明：_PC_PIPE_BUF 对任何 fd 都返回 4096（编译期常量，不是「这个管道的容量」）；\n");
    printf("        _PC_ASYNC_IO 只在普通文件/块设备上是 1（glibc 对 path 做 S_ISREG||S_ISBLK 判断）。\n");
    printf("        B 段「regular file」这一列实际打开的是 %s。\n", regpath);

    if (reg >= 0) close(reg);
    if (nul >= 0) close(nul);
    close(pipefd[0]);
    close(pipefd[1]);
}

static void err_matrix(void)
{
    printf("\n### C. 错误码矩阵\n");
#define E(call, expect)                                                  \
    do {                                                                 \
        errno = 0;                                                       \
        long r = (call);                                                 \
        printf("  %-46s -> %-4ld errno=%-2d %-22s %s\n", #call, r,       \
               errno, strerror(errno),                                   \
               (errno == (expect)) ? "" : "<- 与预期不符");              \
    } while (0)

    E(pathconf("", _PC_NAME_MAX),            ENOENT);
    E(pathconf("/no/such/dir/xyz", _PC_NAME_MAX), ENOENT);
    E(pathconf("/proc/version/inside", _PC_NAME_MAX), ENOTDIR);
    E(pathconf("/", 9999),                   EINVAL);
    E(fpathconf(9999, _PC_NAME_MAX),         EBADF);
    E(fpathconf(STDIN_FILENO, 9999),         EINVAL);
#undef E
    printf("  三点注意：\n");
    printf("  1) pathconf(\"\") 不是 EINVAL 而是 ENOENT —— glibc 在 sysdeps/posix/pathconf.c:32-36\n");
    printf("     专门为它加了一个前置判断（空串在 open 语义里就等于「没给路径」）。\n");
    printf("  2) 「路径里某一段不存在」和「路径中间那一段不是目录」是两个不同的 errno：\n");
    printf("     第 2 行 ENOENT / 第 3 行 ENOTDIR。写重试逻辑时不能只判 ENOENT。\n");
    printf("  3) 非法的 name 与「本实现不支持把 name 关联到这个文件」共用 EINVAL，\n");
    printf("     和 sysconf 一样：-1 + errno 分不清「问错了」还是「不回答」。\n");
}

int main(void)
{
    matrix_paths();
    matrix_fds();
    err_matrix();

    printf("\n### D. 这三个值在别处也见得到，别混为一谈\n");
    printf("  <limits.h> 的 PATH_MAX   = %d  (= <linux/limits.h> 里的 #define PATH_MAX 4096)\n",
           PATH_MAX);
    printf("  <limits.h> 的 PIPE_BUF   = %d  (决定 write(2) 的原子上界，不是管道容量)\n",
           PIPE_BUF);
    printf("  <limits.h> 的 NAME_MAX   = %d  (内核 uapi 里写死的，而 pathconf 会按 fs 回话)\n",
           NAME_MAX);
    printf("  管道容量是另一回事：本机 pipe() 出来默认 65536，可用 fcntl(F_SETPIPE_SZ) 改。\n");
    return 0;
}
```

编译运行：

```bash

### D. 这三个值在别处也见得到，别混为一谈
  <limits.h> 的 PATH_MAX   = 4096  (= <linux/limits.h> 里的 #define PATH_MAX 4096)
  <limits.h> 的 PIPE_BUF   = 4096  (决定 write(2) 的原子上界，不是管道容量)
  <limits.h> 的 NAME_MAX   = 255  (内核 uapi 里写死的，而 pathconf 会按 fs 回话)
  管道容量是另一回事：本机 pipe() 出来默认 65536，可用 fcntl(F_SETPIPE_SZ) 改。
```

逐段看：

| 段 | 观察 | 说明 |
|----|------|------|
| A | `/` 是 `f_type=0x1021994` **tmpfs**；`/lib` 是 `0xef53` **ext4** | 用 `statfs()` 拿 `f_type`、`statvfs()` 拿 `f_namemax`、`/proc/mounts` 拿类型名——三者互相对上 |
| A | 只有 `_PC_LINK_MAX`（127→65000）与 `_PC_FILESIZEBITS`（32→64）**变了** | 这两项按 `f_type` 查表 |
| A | `_PC_NAME_MAX` 两列都是 255，但**它确实来自文件系统** | 因为 tmpfs 和 ext4 恰巧都报 255；换 squashfs 就变成 256（[11.7 习题 11-2](11.7-exercises.md) 的实测里能看到） |
| A | `_PC_PATH_MAX` / `_PC_PIPE_BUF` 两列相同 | 它们在 glibc 里**就是 `return PATH_MAX;` / `return PIPE_BUF;`**，与文件系统无关 |
| A | `/lib` 那格 `_PC_LINK_MAX = 65000` 却带 `errno=2` | glibc 要先区分 ext2/3/4：`readlink("/sys/dev/block/MAJ:MIN")` 失败 → 退到 `/proc/mounts`；**失败那一次的 `ENOENT` 留在了 `errno` 里**。值正确、`errno` 脏 |
| B | `_PC_PIPE_BUF` 对**四种 fd** 都是 4096 | 不是「这个管道的容量」。管道容量是另一回事：内核 `pipe_max_size = 1048576`、默认 65536（`fs/pipe.c:54`），可用 `fcntl(F_SETPIPE_SZ)` 改 |
| B | `_PC_ASYNC_IO` 只有普通文件是 `1`，管道/`/dev/null`/stdin 是 `-1` | glibc 做的是 `S_ISREG(mode) \|\| S_ISBLK(mode)`（`sysdeps/posix/pathconf.c:135`），字符设备（`/dev/null`）不满足 |
| C | `pathconf("")` → **ENOENT(2)** 而不是 `EINVAL` | glibc 在 `sysdeps/posix/pathconf.c:32-36` 有前置判断：`if (path[0] == '\0') { __set_errno(ENOENT); return -1; }` |
| C | `/no/such/dir/xyz` → `ENOENT(2)`；`/proc/version/inside` → **`ENOTDIR(20)`** | 两个不同的 `errno`，写重试/降级逻辑时不能只判 `ENOENT` |
| C | `fpathconf(9999, …)` → **`EBADF(9)`** 而不是 `EINVAL` | `fpathconf` 会先校验 fd；`pathconf` 没有这一步 |
| D | `<limits.h>` 的 `NAME_MAX=255` 与 `pathconf` 的 255 **来源不同** | 前者是内核 uapi 写死的常量（`include/uapi/linux/limits.h:12`），后者是超级块上报的 `f_namemax`。两者可以不等 |

### 4.1 glibc 的分工（源码）

`pathconf()` 在 Linux 上先按 `name` 分流，只有 4 项走文件系统专属路径（`sysdeps/unix/sysv/linux/pathconf.c:38-59`）：

```c
long int
__pathconf (const char *file, int name)
{
  struct statfs fsbuf;

  switch (name)
    {
    case _PC_LINK_MAX:
      return __statfs_link_max (__statfs (file, &fsbuf), &fsbuf, file, -1);

    case _PC_FILESIZEBITS:
      return __statfs_filesize_max (__statfs (file, &fsbuf), &fsbuf);

    case _PC_2_SYMLINKS:
      return __statfs_symlinks (__statfs (file, &fsbuf), &fsbuf);

    case _PC_CHOWN_RESTRICTED:
      return __statfs_chown_restricted (__statfs (file, &fsbuf), &fsbuf);

    default:
      return posix_pathconf (file, name);
    }
}
```

`fpathconf()` 结构相同（`sysdeps/unix/sysv/linux/fpathconf.c:29-52`），把 `__statfs(file, …)` 换成 `__fstatfs(fd, …)`，其余落 `posix_fpathconf`。

而「按 `f_type` 查表」的细节在 `linux_fsinfo.h`：

| 宏 | 值 | 行 |
|----|----|----|
| `EXT2_LINK_MAX` | 32000 | `sysdeps/unix/sysv/linux/linux_fsinfo.h:255` |
| `EXT4_LINK_MAX` | 65000 | `:256` |
| `F2FS_LINK_MAX` | 32000 | `:257` |
| `XFS_LINK_MAX` | 2147483647 | `:265` |
| `LINUX_LINK_MAX` | 127 | `:268` |

`__statfs_link_max()`（`linux/pathconf.c:133-192`）的骨架是 `switch (fsbuf->f_type)`：EXT2 走 `distinguish_extX()`（`:63-128`，因为它要区分 ext2/3 与 ext4）、F2FS → `F2FS_LINK_MAX`、XFS → `XFS_LINK_MAX`、`default` → `LINUX_LINK_MAX`。

`distinguish_extX()` 的分辨办法很土但有效：`snprintf("/sys/dev/block/%u:%u")` → `readlink` → 如果落在 `/sys/fs/ext4/<base>` 就 `access()` 一下——**存在就是 ext4，不存在就是 ext2/3**（`:76-86`）。读不到 `/sys` 就退到遍历 `/proc/mounts`（`:92`）。

## 5. `PIPE_BUF` 不是管道容量

这是本节最容易混的一个点，三个数各自不同：

| 名字 | 值 | 含义 | 出处 |
|------|----|------|------|
| `_PC_PIPE_BUF` / `PIPE_BUF` | 4096 | `write()` 到管道的**原子性上界**：≤4096 的写不会与其他写者交错 | `include/uapi/linux/limits.h:14`；`pathconf` 直接返回这个宏 |
| 管道容量（默认） | 65536 | 管道缓冲区能存多少字节 | `fs/pipe.c`（`pipe_max_size = 1048576`，`fs/pipe.c:54`），可 `fcntl(F_SETPIPE_SZ)` 改 |
| `/proc/sys/fs/pipe-max-size` | 1048576 | 单次可设的最大容量 | 同上 |

所以「用 `pathconf(fd, _PC_PIPE_BUF)` 查管道容量」是错的——查出来的永远是 4096。要查容量得用 `fcntl(fd, F_GETPIPE_SZ)`。

> 相关：小写入合并的行为在 `fs/pipe.c:463-464`——`if ((buf->flags & PIPE_BUF_FLAG_CAN_MERGE) && offset + chars <= PAGE_SIZE)`，这是「多个小 `write` 落进同一页」的条件，与 `PIPE_BUF` 的原子性保证是两件事。

## 6. 常见坑

| 坑 | 说明 |
|----|------|
| 用 `pathconf()` 查 `_PC_PIPE_BUF` 想知道管道容量 | 恒 4096。容量用 `fcntl(F_GETPIPE_SZ)` |
| 以为 `pathconf("/", _PC_PATH_MAX)` 是「绝对路径上限」 | man-pages 原文：**relative pathname when path is the current working directory**。拼绝对路径时预算要按「各级 NAME_MAX 之和」算，不能拿 4096 当万能缓冲 |
| 用 `pathconf()` 的 `-1` 当「文件不存在」 | `-1` 可能来自 `errno=0` 的 indeterminate；必须配 `errno` 判（同 [11.2](11.2-runtime-limits.md)） |
| 认为「`errno == 0` 就代表这次调用干净」 | A 段 `/lib` 的 `_PC_LINK_MAX` 值是**对的**，`errno` 却是 `ENOENT(2)`（glibc 内部探 `/sys` 留下的）。**只在返回 `-1` 时看 `errno`** |
| 只判 `ENOENT` 就以为覆盖了所有「路径有问题」 | `ENOTDIR`(20) 是另一种。`EACCES` / `ELOOP` / `ENAMETOOLONG` 还在后面 |
| 拿 `pathconf()` 去查目录的 `_PC_MAX_CANON` / `_PC_VDISABLE` | glibc **不检查是不是终端**就返回值（`_PC_VDISABLE` 返回 0，`_PC_MAX_CANON` 返回 255）——「看起来有值、其实没意义」，见 [11.4](11.4-indeterminate-limits.md) ④ |
| `fpathconf` 前不检查 fd | `fpathconf(9999, …)` 是 `EBADF` 而非 `EINVAL`；`fd` 是 `-1` 时更要先拦 |

## 7. HFT / 嵌入式关联

| 场景 | 本节机制怎么兑现 |
|------|----------------|
| 落盘目录选型 | 高频写盘（订单日志/快照）要 `_PC_LINK_MAX`、`_PC_FILESIZEBITS` 时**必须对目标目录问**，ext4 与 tmpfs 的答案差一截；容器里 `/tmp` 常是 tmpfs，行为与 `/data`（ext4）不同 |
| 原子写边界 | 跨进程/跨线程往同一管道写消息，单次 `write` ≤ `_PC_PIPE_BUF`（4096）才保证不交错。这是 IPC 协议头设计参数，**不能按管道容量 65536 设计** |
| 嵌入式只读 rootfs | squashfs/UBIFS 会报**非 255** 的 `f_namemax`（本仓库实测 squashfs 报 256）；用 `char name[256]` 的代码在 `f_namemax=256` 上可能少一个字节（要含结尾 `\0` 就是 257） |
| 路径拼接 | `_PC_PATH_MAX` 只在「`path` 是 cwd」的语义下成立；拼接绝对路径要用动态扩容（[11.4](11.4-indeterminate-limits.md) 的降级阶梯） |
| 分布式/网络文件系统 | `/opt` 之类 NFS 挂载点上 `f_type` 是 `0x6969`，`_PC_LINK_MAX` 走 `default` → 127；不要把「本机一定是 65000」写死 |
| 启动自检 | 把「关键目录的 `_PC_NAME_MAX`/`_PC_LINK_MAX`/`_PC_PIPE_BUF`」在启动日志里打一遍：容器编排换了存储驱动（overlayfs → tmpfs）时，这是最快的定位手段 |

<summary>代码自测（Q&A）</summary>

**Q1：`pathconf()` 里哪些 `_PC_*` 真的会随文件系统变？**
A：只有 `_PC_LINK_MAX`、`_PC_FILESIZEBITS`（按 `statfs().f_type` 查表）、`_PC_NAME_MAX`（`statvfs().f_namemax`），加上 4 个 statfs 分派项里的 `_PC_2_SYMLINKS`、`_PC_CHOWN_RESTRICTED`。`_PC_PATH_MAX` / `_PC_PIPE_BUF` / `_PC_NO_TRUNC` / `_PC_VDISABLE` 在 glibc 里是**直接 `return` 一个宏**，问谁都一样。

**Q2：实测中 `_PC_LINK_MAX` 在 `/` 上是 127、在 `/lib` 上是 65000，为什么？**
A：`/` 是 tmpfs（`f_type=0x1021994`），走 `default` → `LINUX_LINK_MAX = 127`；`/lib` 是 ext4（`0xef53`）→ `EXT4_LINK_MAX = 65000`（`linux_fsinfo.h:268` / `:256`）。另外 `/lib` 那格还带 `errno=2`——glibc 区分 ext2/3/4 时先 `readlink("/sys/dev/block/MAJ:MIN")` 失败，留下了 `ENOENT`。

**Q3：`_PC_PIPE_BUF = 4096` 是「这个管道能存 4096 字节」吗？**
A：不是。它是 `write()` 到管道/FIFO 的**原子性上界**（≤ 它的一次写不会被其他写者打断）。管道容量另算：本机默认 65536，上限 1048576（`fs/pipe.c:54` 的 `pipe_max_size`），可用 `fcntl(fd, F_SETPIPE_SZ)` 改、用 `F_GETPIPE_SZ` 查。而在 glibc 里 `_PC_PIPE_BUF` 干脆是 `return PIPE_BUF;`——与具体管道无关。

**Q4：`pathconf("", _PC_NAME_MAX)` 为什么是 `ENOENT` 不是 `EINVAL`？**
A：glibc 在 `sysdeps/posix/pathconf.c:32-36` 专门加了一个前置判断：`if (path[0] == '\0') { __set_errno (ENOENT); return -1; }`。理由在 `open` 语义里，空串等于「没给路径」而不是「路径非法」。所以它进不了 `default:`（那才是 `EINVAL`）。

**Q5：`_PC_PATH_MAX` 的语义到底是什么？能当绝对路径缓冲上限吗？**
A：man-pages 原文：「The maximum length of a **relative pathname** when `path` or `fd` is the current working directory.」所以它是「从 cwd 出发的相对路径」上限，不是绝对路径上限。绝对路径理论最大是「各级目录 `NAME_MAX` 之和 + 分隔符 + 结尾 `\0`」，可能超过 4096——所以拼绝对路径要动态扩容。

**Q6：`_PC_ASYNC_IO` 为什么要看对象类型？**
A：因为「异步 I/O」显然只对随机访问对象有意义。glibc 的实现（`sysdeps/posix/pathconf.c:128-141`）是：拿不到 `stat` 就 `-1`；`S_ISREG(mode) || S_ISBLK(mode)` 才 `return 1`，否则 `return -1`。所以同一个 `pathconf("/", …)` 对目录返回 `-1`，对普通文件返回 `1`。

**Q7：`fpathconf` 比 `pathconf` 好在哪？**
A：两点：① **无 TOCTOU**——`pathconf(path)` 要重新解析路径，`fpathconf(fd)` 用的是已打开的对象，目录被换掉也不会查错；② **能问只有 fd 的对象**——管道、socket、字符设备可能压根没有可用路径（或路径不可访问）。原书 Listing 11-2 就是用 `STDIN_FILENO` 演示这一点。本仓库在 `c11_4_indeterminate.c` 的降级阶梯里优先用 `pathconf`，是因为要问的是「某个目录」而不是「某个已打开对象」。

</details>
