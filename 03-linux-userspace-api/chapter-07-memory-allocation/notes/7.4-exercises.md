## 练习 1：用 `sbrk` + 空闲链表实现 `my_malloc` / `my_free`

**题目**：用 `sbrk` 维护一个空闲链表，实现简化版 `my_malloc` 和 `my_free`。要求：

- 空闲块按大小组织成链表；
- `my_malloc(size)` 遍历链表找到足够大的块，必要时**分割**；
- `my_free(ptr)` 把块标记为空闲，并**合并相邻的空闲块**。

### 先把两个数字算清楚

设计一个块，头部需要存 `size` / `free` / `next`：

```c
typedef struct block {
    size_t size;            /* 8 字节 */
    int free;               /* 4 字节 */
    /* +4 字节 padding：让 next 对齐到 8 */
    struct block *next;     /* 8 字节 */
} block_t;
```

| 量 | 值 | 怎么来的 |
|----|----|---------|
| `sizeof(block_t)` | **24** | 8 + 4 + 4(padding) + 8 |
| 头部对齐后 `META` | **32** | `ALIGN_UP(24)` —— **头部也必须对齐到 16**，否则每个块一错位，后面全歪 |
| `ALIGN_UP(100)` | **112** | `(100 + 15) & ~15` |
| `ALIGN_UP(200)` | **208** | `(200 + 15) & ~15` |

于是 `my_malloc(200)` 与 `my_malloc(100)` 的**地址差应该是 32 + 208 = 240**，而 `my_malloc(100)` 和它前面那块的差是 **32 + 112 = 144**。这两个数字下面有实测核对。

> ⚠️ 第一版草稿最容易错的地方就是**忘了把 `META` 也对齐**：`sizeof(block_t) = 24` 不是 16 的倍数，直接用它做步长，第二块的地址就不再是 16 对齐了，后面 `malloc` 出来的指针一用 SIMD 就崩。

### 完整实现

完整程序见 [`../code/ex7_1_simple_malloc.c`](../code/ex7_1_simple_malloc.c)。

```c
/* TLPI Ch7 练习 1 参考实现：用 sbrk + 空闲链表做 my_malloc / my_free
 * 编译: gcc -O2 -Wall -Wextra -o ex7_1 ex7_1_simple_malloc.c
 */
#include <stdio.h>
#include <unistd.h>
#include <stdint.h>

typedef struct block {
    size_t size;                /* 数据区大小（字节） */
    int free;                   /* 是否空闲 */
    struct block *next;         /* 下一个块（含已分配的，方便遍历） */
} block_t;

#define ALIGN       16
#define ALIGN_UP(x) (((x) + (ALIGN - 1)) & ~((size_t) ALIGN - 1))
#define META        ALIGN_UP(sizeof(block_t))   /* 头部也要对齐到 16 */

static block_t *g_head;

void *my_malloc(size_t size)
{
    size = ALIGN_UP(size);
    if (size == 0) size = ALIGN;

    /* 第一遍：在链表里找一块够大且空闲的 */
    for (block_t *b = g_head; b != NULL; b = b->next) {
        if (!b->free || b->size < size) continue;

        /* 剩得够多就切开，后半段变成新的空闲块 */
        if (b->size >= size + META + ALIGN) {
            block_t *split = (block_t *) ((char *) b + META + size);
            split->size = b->size - size - META;
            split->free = 1;
            split->next = b->next;
            b->next = split;
            b->size = size;
        }
        b->free = 0;
        return (char *) b + META;
    }

    /* 第二遍：没有合适的，直接向内核要 */
    block_t *b = (block_t *) sbrk(0);
    if (sbrk((intptr_t) (META + size)) == (void *) -1)
        return NULL;

    b->size = size;
    b->free = 0;
    b->next = g_head;           /* 头插，省事 */
    g_head  = b;
    return (char *) b + META;
}

void my_free(void *ptr)
{
    if (ptr == NULL) return;

    block_t *b = (block_t *) ((char *) ptr - META);
    b->free = 1;

    /* 合并「当前块 + 紧邻的下一块」这一种情况，够用了 */
    if (b->next != NULL && b->next->free
        && (char *) b + META + b->size == (char *) b->next) {
        b->size += META + b->next->size;
        b->next = b->next->next;
    }
}

int main(void)
{
    char *a = my_malloc(100);
    char *b = my_malloc(200);
    char *c = my_malloc(100);

    printf("a=%p  b=%p  c=%p\n", (void *) a, (void *) b, (void *) c);
    printf("b - a = %ld   (期望 32 + 112 = 144)\n", (long) (b - a));
    printf("c - b = %ld   (期望 32 + 208 = 240)\n", (long) (c - b));

    for (int i = 0; i < 100; i++) a[i] = 'a';
    for (int i = 0; i < 200; i++) b[i] = 'b';
    for (int i = 0; i < 100; i++) c[i] = 'c';

    my_free(b);                     /* 中间那块先还 */
    char *d = my_malloc(200);       /* 应该原地复用 b */
    printf("my_free(b) 后 my_malloc(200) = %p  （复用 b = %s）\n",
           (void *) d, d == b ? "是" : "否");

    printf("邻居没被踩坏: a[0]=%c a[99]=%c  c[0]=%c c[99]=%c  d[0]=%c\n",
           a[0], a[99], c[0], c[99], d[0]);

    my_free(a); my_free(c); my_free(d);
    printf("收尾 sbrk(0) = %p\n", sbrk(0));
    return 0;
}
```

编译与运行：

```bash
gcc -O2 -Wall -Wextra -o ex7_1 ex7_1_simple_malloc.c && ./ex7_1
```

实测输出（另在 Compiler Explorer 复核，gcc 13.3）：

```text
a=0x3eeba020  b=0x3eeba0b0  c=0x3eeba1a0
b - a = 144   (期望 32 + 112 = 144)
c - b = 240   (期望 32 + 208 = 240)
my_free(b) 后 my_malloc(200) = 0x3eeba0b0  （复用 b = 是）
邻居没被踩坏: a[0]=a a[99]=a  c[0]=c c[99]=c  d[0]=b
收尾 sbrk(0) = 0x3eedc000
```

**四个核对点**

1. **地址差与理论值精确吻合**：`b − a = 144 = 32 + 112`，`c − b = 240 = 32 + 208`。这同时验证了「头部 32 字节」和「16 字节对齐」两件事。
2. **`free` 之后能原地复用**：`my_free(b)` 把中间那块还回链表，紧接着 `my_malloc(200)` 返回的正是 `b` 的地址 `0x3eeba0b0`。—— 这正是 glibc 的真实行为（[c7_2](./7.1-heap-allocation.md#c7_2-free-不一定下调-breaktlpi-listing-7-1-精神) 里 free 后 break 不降）。
3. **切分逻辑没把邻居踩坏**：`a[0]/a[99]/c[0]/c[99]` 全是自己写进去的值，`d[0] = 'b'` 说明 `b` 那块的内容还在（`my_free` 不擦数据）。
4. **`sbrk(0)` 收尾值 `0x3eedc000` 比首块地址高得多**，因为这个简化实现**从不归还内存** —— 它只做「复用 + 合并」，不调 `sbrk(-n)`。真实分配器才有 `trim` 逻辑。

**这个练习为什么值得做**：做完它，`malloc` 就不再是黑盒了。你会发现 glibc 里那些看起来很绕的东西 —— chunk 头、bin 链表、对齐要求、`trim` 阈值 —— 全都是为了解决这里已经露头的两个问题：**碎片**（切分后剩下的零头怎么办）和**寻址**（怎么快速找到够大的块）。生产级实现无非是把「线性找」换成「按 size 分桶」（fastbin / smallbin / largebin），把「只合并 next」换成「双向合并」。

## 练习 2：`calloc` 与 `malloc` + `memset` 的区别

从**安全性**、**性能**、**实现**三个角度分析。

| 角度 | `calloc(n, s)` | `malloc(n*s)` + `memset` |
|------|---------------|--------------------------|
| **安全性** | 内部检查 `n × s` **整数溢出**，溢出时返回 `NULL` | `n*s` 在 `size_t` 上回绕成小值，会「分配成功」，随后按原尺寸写就越界 |
| **性能** | 大块走 `mmap` 时，内核给的**匿名页本来就是清零的**，可省掉 `memset` | 必须实打实写一遍 ·n×s· 字节（还要多吃一次页错误） |
| **实现** | 走 glibc 的 `calloc` → 小块走 `_int_malloc` + 置零，大块直接 `mmap` | 两次函数调用，中间还有一个**指针已分配但未初始化**的窗口 |
| **语义** | 一次调用，语义完整 | 两步之间若被信号打断/长跳转，会留下未初始化的敏感数据 |

**实测支撑**（见 [c7_4](./7.1-heap-allocation.md#c7_4-malloc-家族语义实测)）：`calloc(SIZE_MAX, 2)` 返回 `(nil)` —— 溢出被拦下。同样尺寸若写 `malloc(SIZE_MAX * 2)`，`SIZE_MAX * 2` 会回绕成 `SIZE_MAX - 1`，看起来「成功」。

**结论**：要清零就用 `calloc`，不要手写 `malloc + memset` —— 前者免费拿到了溢出检查和（大块时）内核零页的优惠。

## 练习 3：为什么 `realloc(ptr, 0)` 的行为不统一？

### 标准怎么说的

| 标准 | 规定 |
|------|------|
| C89 / C99 / C11 | **实现定义**：要么返回 `NULL`，要么返回一个**不能用于访问对象**的非空指针 |
| C17 | 同上，且标记为 **deprecated**（C DR 400） |
| **C23** | **未定义行为**（undefined behavior） |

C17 §7.22.3.5 的原文：

> If size is zero and memory for the new object is not allocated, it is implementation-defined whether the old object is deallocated. If the old object is not deallocated, its value shall be unchanged.

**为什么会这样**：`realloc` 的语义是「**调整**一块已有对象的大小」，它的返回值契约是「指向新对象的指针」。大小为 0 时，「新对象」是什么？—— 既可以说「没有对象，返回 `NULL`」，也可以说「有一个 0 字节对象，返回它的地址」。标准当初（C89）为了照顾下面这种写法才允许 0 长度：

```c
OBJ *p = calloc(0, sizeof(OBJ));    /* "零长度占位符" */
while (1) {
    p = realloc(p, c * sizeof(OBJ));  /* 反复调整直到尺寸稳定 */
    /* 中间可能改 c 或 break */
}
```

结果两种解释都活了下来，行为就分裂了。

### 各家实测/实测来源

| 实现 | `realloc(p, 0)` 的行为 |
|------|----------------------|
| **glibc**（Linux） | **释放 `p` 并返回 `NULL`** —— 本章 [c7_4 实测](./7.1-heap-allocation.md#c7_4-malloc-家族语义实测)确认，输出 `7) realloc(p, 0) = (nil)` |
| BSD / macOS | 释放 `p`，但可能返回一个**指向最小分配块的非空指针** |
| 一些嵌入式 libc | 可能什么都不做并返回 `NULL`（此时 `p` 仍然有效 → 直接泄漏） |

### 结论

**永远不要写 `realloc(ptr, 0)`。** 想释放就写：

```c
free(ptr);
ptr = NULL;         /* 顺手防悬垂 */
```

这样语义在**所有**实现上都确定，也不会在「返回非空」的实现上悄悄泄漏一个最小块。

## 收尾自测

<details>
<summary>1. 为什么练习 1 里的 <code>META</code> 要做 <code>ALIGN_UP</code>，直接用 <code>sizeof(block_t)</code> 不行吗？</summary>

不行。`sizeof(block_t) = 24`，不是 16 的倍数。如果直接用 24 做步长，第二块的起始地址 = 第一块 + 24 + size（size 已按 16 对齐）→ **偏移 24，不是 16 的倍数**，用户拿到的指针就此失去 16 字节对齐。

后果不是立刻崩溃，而是：`double` / SIMD 类型的访问可能触发未对齐访问的惩罚甚至 `SIGBUS`（某些架构上），而且 `free` 之后所有块的地址全歪 —— 这类 bug 排查起来极痛。

对齐到 32 之后，每块步长 = 32 + 16k，永远是 16 的倍数。这也是 glibc 里 `chunk` 大小永远 16 字节对齐的原因。
</details>

<details>
<summary>2. 练习 1 的实现从不归还内存，为什么还能叫「malloc」？</summary>

因为 **「归还」不是 `malloc` 的契约**。`malloc` 的契约是「给我一块至少 size 字节的、可写的内存，或者告诉我失败」。复用空闲块完全满足这个契约，而且比每次都找内核更快。

glibc 也是这么想的：它只在「堆顶出现一大段连续空闲」时才考虑 `sbrk(-n)` 归回（[c7_2](./7.1-heap-allocation.md#c7_2-free-不一定下调-breaktlpi-listing-7-1-精神) 里 `free` 掉 1000 个块后，break 仍留着 140 KB）。

真正要「把这些页还给内核」的场景，用的是 `mmap` + `munmap`（[c7_3](./7.1-heap-allocation.md#c7_3-两条路径heap-台阶式长还是新开匿名段) 的 B 段：256 KB 的块 free 时直接 `munmap`）。
</details>
