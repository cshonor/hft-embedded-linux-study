## 本章回顾

| 分配方式 | 接口 | 位置 | 释放 | 特点 |
|---------|------|------|------|------|
| 堆分配 | `malloc` / `calloc` / `realloc` | 堆 | `free` | 最常用；需手动管理 |
| 栈分配 | `alloca`（非标准）/ C99 VLA | 栈 | 函数返回自动 | 极快；不可跨函数；无错误检查 |
| 系统调用 | `brk` / `sbrk` | 堆顶 | `sbrk(-n)` / `brk(addr)` | `malloc` 的底层之一；**业务代码禁用** |
| 内存映射 | `mmap` / `munmap` | 任意虚拟地址 | `munmap` | 大块；可共享；`free` 时真还内核 |
| 对齐分配 | `posix_memalign` / `aligned_alloc` | 堆 | `free` | SIMD / DMA / 缓存行 |

**一句话把两条路径记住**：小块（更准确地说：**现有空闲空间能满足、或 `nb` 不到阈值**）扩主堆 `[heap]`；大块新开一段匿名映射，`free` 时直接还给内核。判据在 `malloc/malloc.c:2564`。

## malloc 家族速查

| 函数 | 原型 | 说明 |
|------|------|------|
| `malloc` | `void *malloc(size_t size)` | 内容**未初始化**；失败返回 `NULL` 并设 `errno` |
| `calloc` | `void *calloc(size_t n, size_t sz)` | 分配 `n×sz` 并**清零**；**检查整数溢出** |
| `realloc` | `void *realloc(void *ptr, size_t sz)` | 调整大小，**可能移动**；旧指针一律视为失效 |
| `free` | `void free(void *ptr)` | `ptr` 可为 `NULL`（空操作）；**不清零** |
| `aligned_alloc` | C11，`size` 须为 `align` 倍数 | 对齐分配 |
| `posix_memalign` | `int posix_memalign(void **p, size_t align, size_t sz)` | 用**返回值**报错（不设 `errno`），非法对齐给 `EINVAL` |
| `strdup` | POSIX | `malloc` + `strcpy` 的封装 |

## `realloc` 的四种情形（全部实测过）

| 场景 | 行为 | 实测 |
|------|------|------|
| `realloc(NULL, n)` | ≡ `malloc(n)` | ✅ 返回非空 |
| `realloc(p, smaller)` | 通常原地缩减 | ✅ 指针不变 |
| `realloc(p, bigger)` | 可能搬移（新块 + 拷贝 + 释放旧块） | ✅ 指针从堆跳到 mmap 区，旧数据完整 |
| `realloc(p, 0)` | 实现定义 → C23 起 UB | ✅ glibc：释放 `p`，返回 `NULL` |
| `realloc` 失败 | **旧块不动**，返回 `NULL` | 标准保证 |

⚠️ 唯一必须背下来的写法：

```c
void *np = realloc(ptr, newsize);
if (np == NULL) { /* 失败：ptr 仍有效，自己决定 */ }
else            { ptr = np; }          /* 成功：旧 ptr 立即失效 */
```

## 分配器实现（拓展）

| 分配器 | 特点 | 常见场景 |
|--------|------|---------|
| ptmalloc（glibc） | 按 arena / bin（fastbin / smallbin / largebin / unsorted）分区；**tcache 每线程缓存** | 通用默认 |
| tcmalloc（Google） | 线程缓存 + 中央堆，减少锁竞争 | 多线程服务 |
| jemalloc（FreeBSD/NetBSD 起步） | size class 分区，碎片少 | 大内存 / 多线程 |
| mimalloc（Microsoft） | 分段 + 自由链表分片 | 通用高性能 |

本节讲的所有细节（chunk 头、tcache、mmap 阈值）都是 **ptmalloc** 的行为 —— 换分配器结论就变，别把它们当 C 语言语义。

## 错误与陷阱

| 问题 | 说明 | 怎么防 |
|------|------|--------|
| 内存泄漏 | `malloc` 后丢指针 | ASan / valgrind；RAII 风格封装 |
| `realloc` 后旧指针 | 搬移后旧地址失效 | 用临时变量接返回值 |
| 重复释放 | tcache 时代常**不立刻崩** | 释放后 `p = NULL` |
| 越界写 | 踩到 chunk 头或 redzone | ASan；`_FORTIFY_SOURCE` |
| use-after-free | 释放后继续访问 | `p = NULL`；ASan |
| 未检查返回值 | `malloc` 返回 `NULL` 还被解引用 | 一律检查 |
| `malloc(0)` 当失败判据 | glibc 返回非空 | 用 `errno` / 显式尺寸检查 |

## HFT / 嵌入式关联

- **热路径零 `malloc`**：分配器最坏情况含链表搜索 + `sbrk` / `mmap` 系统调用，延迟不可控。启动时预分配 arena / 固定大小对象池。
- **大页与 TLB**：HFT 关键结构用 `mmap(MAP_HUGETLB)` / `madvise(MADV_HUGEPAGE)`，降低 TLB miss（Ch49–50）。
- **对齐就是性能**：缓存行 64 字节对齐防 false sharing；SIMD 要 64；`O_DIRECT` 要页对齐 4096。
- **嵌入式**：无 MMU 平台没有 `brk`，只能 `mmap` 或静态池；长时间运行的小内存设备通常**直接禁用 `malloc`**（碎片无解）。
- **跨平台雷区**：`malloc(0)` / `realloc(p, 0)` 标准不统一，一律用显式 `free` + `malloc` 表达。

## 衔接

- **Ch49 内存映射**：`mmap` 的另一半 —— 文件映射、共享映射、`MAP_*` 标志
- **Ch50 虚拟内存操作**：`mprotect` / `mlock` / `madvise` / `mincore`
- **Ch61 高级文件 I/O**：`sendfile` / `splice` / `tee`（真正的零拷贝）
- **Ch24 fork**：堆随地址空间被 COW（写时复制），大堆会影响 `fork` 代价
- **Ch63 替代 I/O 模型**：`select` / `poll` / `epoll`（与内存分配无直接关系，别混）

## 自测题

<details>
<summary>1. `calloc(n, sz)` 和 `malloc(n*sz)` + `memset` 的区别？</summary>

- **安全性**：`calloc` 会检查 `n × sz` 的**整数溢出**（实测 `calloc(SIZE_MAX, 2)` 返回 `NULL`）；`malloc(n*sz)` 会回绕成一个小值然后「分配成功」，随后按原尺寸写就越界。
- **性能**：大块 `calloc` 走 `mmap` 时，内核给的**匿名页本来就是清零的**（见 6.4 的零页机制），glibc 可以省掉实际的 `memset`。
- **语义**：一次调用 vs 两次调用，后者在中间窗口里指针未初始化。
</details>

<details>
<summary>2. `realloc` 搬移内存后，原指针是什么状态？</summary>

**失效**（dangling）。只要 `realloc` 返回了一个**新地址**，旧块就已经被自动释放，旧指针不可再解引用 —— 标准里连"访问旧指针"都算 UB，即使这次刚好原地没搬。

如果 `realloc` 失败（返回 `NULL`），**原内存仍然有效**，需要你自己 `free`。

实测（c7_4 第 6 条）：`realloc(16 → 1MB)` 把指针从堆区的 `0x1c6b8330` 换成 mmap 区的 `0x7c5874aff010`，旧数据 `1 2 3 4` 完整带了过去。
</details>

<details>
<summary>3. `alloca` 的优势和硬限制？</summary>

**优势**：只挪一下 `sp`（一条指令），比 `malloc` 快一个数量级；函数返回自动回收，不可能泄漏。

**硬限制**（三条都是实测确认的）：

1. **没有错误检查** —— 不像 `malloc` 返回 `NULL`，栈不够时直接 `SIGSEGV`（实测 `alloca(16MB)` 在 8MB 栈上被信号 11 杀死）。
2. **不能跨函数** —— 返回指向栈的指针，调用者一用就踩别人的栈帧。
3. **循环里不回收** —— 回收粒度是**函数返回**，不是作用域结束。实测循环 5 次 `alloca(4096)`，地址每次固定下移 4112 字节，一路涨不回头。

另外它是**非标准**扩展（POSIX 也没有）；GCC 下 glibc 把它映射到 `__builtin_alloca`（`stdlib/alloca.h:35`）。
</details>

<details>
<summary>4. 为什么「大块走 mmap」这句话不严谨？</summary>

因为 mmap 判据在 `sysmalloc()` 里（`malloc/malloc.c:2564`），**只有现有 bin 和 top chunk 都满足不了时才会被走到**；而且比的是 **`nb`（chunk 大小）**，不是请求的 size，阈值还会被 `free()` 大块时动态调高。

所以一个 200 KB 的请求，如果 top chunk 里正好有地方，它会直接从 top 切 —— 既不动 `[heap]` 的系统调用，也不开匿名映射。

实测（c7_3）：16 KB × 10 全都从 `[heap]` 里切（`[heap]` 只在 top 用尽时台阶式跳两级）；256 KB × 4 每次都走 mmap，因为 `nb ≈ 262176` 远比 `[heap]` 里剩下的可用空间大。
</details>
