## 本节讲什么

堆是地址空间里**唯一能在运行期自由伸缩**的那一段。把它弄清楚，只需要回答四个问题：

1. 堆的上界在哪，谁在动它？—— **program break**，入口只有 `brk` / `sbrk`。
2. 日常写的 `malloc` 到底做了什么？—— 它是**库函数**，在「扩主堆」和「新开 mmap」之间自己挑。
3. 为什么 `free` 之后 `sbrk(0)` 常常一动不动？—— 小块留在空闲链表里等着被复用。
4. 写错了会怎样？—— 五类典型错误，用 ASan 抓现场。

## 要点

### 一、program break 与两个入口

**program break** = 进程堆的当前上边界（书里叫「program break」，内核侧就是 `mm->brk`）。

| 动作 | 效果 |
|------|------|
| 上移 break | 扩大堆，拿到更多**虚拟**地址 |
| 下移 break | 缩小堆，把虚拟地址还给内核 |

```c
#include <unistd.h>
int   brk(void *end_data_segment);   /* 设成绝对地址：成功 0，失败 -1 */
void *sbrk(intptr_t increment);      /* 相对移动；成功返回「调整前」的 break */
```

| 规则 | 说明 |
|------|------|
| `sbrk(0)` | **不移动**断点，只返回当前值 —— 用户态唯一的「查看」手段 |
| `sbrk(n) > 0` | 抬高 n 字节，返回值 = 抬高**前**的断点（也就是新区域的起点） |
| 失败 | 返回 `(void *) -1`，并设 `errno = ENOMEM` |
| 抬高 ≠ 占物理页 | 只改虚拟地址；首次访问才通过缺页分配物理页（见 6.4） |
| 下移过猛 | 把断点压到「glibc 已经用过的堆」下面 → 直接 `SIGSEGV`（下面有实测） |
| 业务代码 | **禁止**直接用 `brk` / `sbrk` —— 堆是 glibc 的地盘，不是你的 |

最后一条不是教条，是**实测出来的**：glibc 自己的 stdio 缓冲区就住在堆上，你把 break 降回去，等于把它的数据还给了内核。见 [c7_1 的 B 段](#c7_1-归位可以降过头就崩)。

### 二、malloc / free 的语义

```c
#include <stdlib.h>
void *malloc(size_t size);   /* 未初始化；失败返回 NULL 并设 errno */
void  free(void *ptr);
```

**用户拿到的指针不含分配器头部**，元数据躺在用户区**前方**：

```text
低地址 ┌──────────────────┐
       │ chunk 头（size/   │  ← 分配器私有：大小、bin 链表指针、标志位
       │  bin 指针、标志） │     你越界写这里 → free 时直接崩
       ├──────────────────┤ ← malloc 返回的指针从这里开始
       │ 用户数据          │
       ├──────────────────┤
       │ 对齐填充          │
       └──────────────────┘ 高地址
```

`free` 的四条事实：

| 事实 | 说明 |
|------|------|
| `ptr` 必须来自 `malloc`/`calloc`/`realloc` | 否则 UB；`free` 栈地址会被 glibc 的检查拦下（实测见 [c7_6](#c7_6-五类典型堆错误asan-抓现行)） |
| `free(NULL)` | 安全，空操作 |
| **不保证下调 break** | 小块进空闲链表等着复用；只有堆顶那一大段连续空闲才可能触发 `sbrk(-n)` |
| **不清零** | 内容原样留着（信息残留面）；但 glibc 的 tcache 会覆写头部 16 字节，见 [c7_4](#c7_4-malloc-家族语义实测) |

### 三、calloc / realloc

| 函数 | 语义 | 要点 |
|------|------|------|
| `calloc(n, s)` | 分配 `n × s` 并**清零** | 会检查 `n × s` **整数溢出** —— 这是它比 `malloc + memset` 真正强的地方 |
| `realloc(p, n)` | 调整大小 | 可能原地，也可能「新块 + 拷贝 + 释放旧块」；**旧指针一律视为失效** |
| `realloc(NULL, n)` | ≡ `malloc(n)` | 实测确认 |
| `realloc(p, 0)` | **不要用** | C17 及以前是实现定义、C23 起是未定义行为；glibc 上等于 `free(p)` 并返回 NULL |

```c
/* ❌ 失败时原指针丢失 → 泄漏 */
ptr = realloc(ptr, newsize);

/* ✅ 用临时变量接 */
void *np = realloc(ptr, newsize);
if (np == NULL) { /* ptr 仍然有效，自己决定继续用还是 free */ }
else            { ptr = np; }
```

### 四、malloc(0)

POSIX 允许返回 `NULL` **或** 一个可 `free` 的非空指针。**glibc 返回非空**，所以：

```c
void *p = malloc(0);
free(p);                        /* 必须 free，不能当失败处理 */
/* 但绝不可解引用：请求 0 字节，访问就是 UB */
```

判断「分配是否失败」的正确姿势是**看 `errno` 或统一判 `NULL` 并保证 `size > 0`**，而不是拿 `malloc(0)` 的返回值当信号。

### 五、两条路径：`sbrk` 还是 `mmap`（源码级判据）

glibc 的 malloc 有两条完全不同的取内存路径：

| 路径 | 触发时机 | 特征 |
|------|----------|------|
| **扩主堆**（`sbrk`） | 请求能从现有 bin / top chunk 满足，或 `sysmalloc` 判定 `nb < mmap_threshold` | 动 `[heap]`，`free` 后常留在空闲链表 |
| **新开 mmap** | `sysmalloc` 走到 mmap 分支 | 多一段**匿名映射**，`free` 时 `munmap` 直接还给内核 |

判据就一句（glibc 2.39 `malloc/malloc.c:2564-2565`，位于 `sysmalloc()` 内）：

```c
if ((unsigned long) (nb) >= (unsigned long) (mp_.mmap_threshold)
    && (mp_.n_mmaps < mp_.n_mmaps_max))
```

这句话有三个**必须注意**的细节，缺一个就会得出错误结论：

1. **比的是 `nb`（chunk 大小），不是请求的 `size`** —— `nb = (size + 8 + 15) & ~15`（`request2size`，`malloc.c:1314`：含 8 字节头，再按 16 对齐）。代入阈值 131072 反推：请求 **131049** 字节时 `nb` 恰好够上阈值，**131048** 的 `nb` 只有 131056 —— 所以 128 KB 从来不是「请求字节数」的分界线。（这两个数字是**按公式推算**的，不是观测值；真要观测还得先把 top chunk 耗掉，见 [c7_3](#c7_3-两条路径heap-台阶式长还是新开匿名段)。）
2. **它只在 `sysmalloc()` 里** —— 也就是说，**只有现有 bin 和 top chunk 都满足不了时才会被走到**。这才是「为什么 16 KB 的分配从来没走 mmap」的真正原因：top 够。
3. **阈值默认 128 KB**（`DEFAULT_MMAP_THRESHOLD_MIN`，`malloc.c:946`），且 `free()` 一个大块时会**动态调高**它（`malloc.c:3380-3384`）。要复现实验就必须先 `mallopt(M_MMAP_THRESHOLD, 128*1024)` 钉死 —— 该调用同时把 `mp_.no_dyn_threshold` 置 1（`malloc.c:5442-5447`）。

> ⚠️ 所以「大块走 mmap」这句简化说法**不完整**。准确的表述是：**当现有空闲空间不够时，看 `nb` 和 `mmap_threshold` 谁大**。一个 200 KB 的请求也可能先从 top chunk 里切出来。

### 六、对齐

| 接口 | 保证的对齐 | 备注 |
|------|-----------|------|
| `malloc` / `calloc` / `realloc` | `_Alignof(max_align_t)`，x86-64 上 = **16** | 够放任何标量类型 |
| `posix_memalign(&p, align, size)` | `align`（必须是 2 的幂且是 `sizeof(void*)` 的倍数） | 成功返回 0，非法对齐返回 **`EINVAL`**（不是崩溃） |
| `aligned_alloc(align, size)`（C11） | `align` | 要求 `size` 是 `align` 的整数倍，否则 UB |

为什么要更严格的对齐？**SIMD**（AVX-512 要 64 字节）、**DMA / O_DIRECT**（要页对齐 4096）、**缓存行**（要 64 字节，防 false sharing）。

### c7_1 归位可以，降过头就崩

完整程序见 [`../code/c7_1_program_break.c`](../code/c7_1_program_break.c)：先演示 `sbrk` / `brk` 的正常语义，再把「break 降过头」放进子进程看后果。

```c
/* Ch7 §7.1 — program break 的查询与调整（brk / sbrk）
 * 编译: gcc -O2 -Wall -Wextra -o c7_1_program_break c7_1_program_break.c
 */
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
#include <sys/wait.h>

#define PAGE 4096

/* ── A. 安全用法：只在「当前 break 之上」要内存，并只归还到自己的出发点 ── */
static void safe_use(void)
{
    /* 先输出一次，让 stdio 的缓冲区落到堆上。
     * 若把首次输出留到后面，归还 break 时会把 glibc 尚未分配的堆一并砍掉。 */
    printf("A. 安全用法\n");

    char *base = (char *) sbrk(0);      /* 此刻的 break 已包含 stdio 缓冲 */
    printf("   起始 break            = %p\n", (void *) base);

    /* sbrk(+n)：相对移动，成功时返回「调整前」的断点 */
    char *old = (char *) sbrk(16 * PAGE);
    if (old == (char *) -1) { perror("sbrk"); return; }
    printf("   sbrk(+%ld) 返回旧断点 = %p\n", 16L * PAGE, (void *) old);
    printf("   抬高后 break          = %p\n", sbrk(0));
    printf("   返回值 == 旧断点吗    = %s\n", old == base ? "是" : "否");

    /* 新区域可以随意读写：虚拟地址已到手，物理页还没分配 */
    old[0] = 'A';
    old[16 * PAGE - 1] = 'Z';
    printf("   首尾各写一字节        = %c ... %c\n", old[0], old[16 * PAGE - 1]);

    /* 归还：只回到 base（自己的出发点），一字节都不多降 */
    if (brk(base) != 0) { perror("brk"); return; }
    printf("   brk(起始) 后 break    = %p  ← 回到出发点\n\n", sbrk(0));
}

/* ── B. 危险用法：把 break 降到程序启动时的位置，会砍掉 glibc 自己的堆 ── */
static char *g_earliest;        /* main 第一行读到的 break：那时 stdio 缓冲还没分配 */

static void reckless_use(void)
{
    printf("B. 危险用法：把 break 降回「还没用到 stdio」时的位置\n");
    fflush(stdout);
    brk(g_earliest);            /* 连 glibc 的 stdio 缓冲区一起还给内核 */
    printf("   这一行若能看到，说明缓冲区恰好没被砍到\n");
}

int main(void)
{
    g_earliest = (char *) sbrk(0);

    safe_use();

    fflush(stdout);
    pid_t pid = fork();
    if (pid == 0) { reckless_use(); return 0; }

    int st = 0;
    waitpid(pid, &st, 0);
    if (WIFSIGNALED(st))
        printf("B. 子进程被信号 %d 杀死。用户态的 stdio 缓冲区也住在堆上，\n"
               "   把 break 降过头 = 把 glibc 自己的数据也还给了内核。\n"
               "   这正是「业务代码禁止直接 brk/sbrk」最硬的理由。\n",
               WTERMSIG(st));
    else
        printf("B. 子进程 exit = %d（这次没崩）\n", WEXITSTATUS(st));
    return 0;
}
```

编译与运行：

```bash
gcc -O2 -Wall -Wextra -o c7_1_program_break c7_1_program_break.c && ./c7_1_program_break
```

实测输出（另在 Compiler Explorer 复核，gcc 13.3）：

```text
A. 安全用法
   起始 break            = 0x1913000
   sbrk(+65536) 返回旧断点 = 0x1913000
   抬高后 break          = 0x1923000
   返回值 == 旧断点吗    = 是
   首尾各写一字节        = A ... Z
   brk(起始) 后 break    = 0x1913000  ← 回到出发点

B. 危险用法：把 break 降回「还没用到 stdio」时的位置
B. 子进程被信号 11 杀死。用户态的 stdio 缓冲区也住在堆上，
   把 break 降过头 = 把 glibc 自己的数据也还给了内核。
   这正是「业务代码禁止直接 brk/sbrk」最硬的理由。
```

**解读**

1. `sbrk(+65536)` 的返回值 `0x1913000` **等于**调用前的 break —— 这不是巧合，是 `sbrk` 的契约：**返回新区域的起始地址**。
2. `0x1913000 → 0x1923000` 正好差 `0x10000` = 65536，`sbrk` 按字节数精确移动。
3. A 段能安全归位，是因为 `base` 是在**首次 `printf` 之后**读的 —— 那时 stdio 的缓冲区（`malloc` 出来的，就在堆上）已经在 `base` 以下了。
4. B 段故意的：`g_earliest` 在 `main` 第一行读，**那时 stdio 缓冲还没分配**；再 `brk(g_earliest)` 就把 glibc 后来分配的东西全砍了。子进程 `SIGSEGV(11)` 就是证据。**这就是「破坏性使用 `brk`」的真实代价**，比任何警告都有说服力。

### c7_2 free 不一定下调 break（TLPI Listing 7-1 精神）

完整程序见 [`../code/c7_2_free_and_sbrk.c`](../code/c7_2_free_and_sbrk.c)：分两阶段 —— 1000 个 1 KB 小块、1 个 256 KB 大块，各自看 break 怎么动。

```c
/* Ch7 §7.1 — free() 不一定下调 program break（TLPI Listing 7-1 精神）
 * 编译: gcc -O2 -Wall -Wextra -o c7_2_free_and_sbrk c7_2_free_and_sbrk.c
 */
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>

#define N 1000

static char *g_base;

static void show(const char *tag)
{
    char *now = (char *) sbrk(0);
    printf("%-30s break = %p   (较起点 %+8ld B)\n",
           tag, (void *) now, (long) (now - g_base));
}

int main(void)
{
    static char *ptr[N];

    g_base = (char *) sbrk(0);
    show("启动");

    /* 阶段 1：大量小块 —— 走主堆 */
    for (int i = 0; i < N; i++) {
        ptr[i] = malloc(1024);
        if (ptr[i] == NULL) { perror("malloc"); return 1; }
        ptr[i][0] = 'x';            /* 触碰一下，确保真的占了页 */
    }
    show("malloc(1000 x 1KB) 之后");

    for (int i = 0; i < N; i++)
        free(ptr[i]);
    show("全部 free 之后");

    /* 阶段 2：一个大块 —— 走 mmap，与 program break 无关 */
    char *big = malloc(256 * 1024);
    if (big == NULL) { perror("malloc"); return 1; }
    big[0] = 'y';
    show("malloc(256KB) 之后");

    free(big);
    show("free(256KB) 之后");
    return 0;
}
```

编译与运行：

```bash
gcc -O2 -Wall -Wextra -o c7_2_free_and_sbrk c7_2_free_and_sbrk.c && ./c7_2_free_and_sbrk
```

实测输出（另在 Compiler Explorer 复核，gcc 13.3）：

```text
启动                         break = 0x2e999000   (较起点       +0 B)
malloc(1000 x 1KB) 之后      break = 0x2eaa1000   (较起点 +1081344 B)
全部 free 之后               break = 0x2e9bc000   (较起点  +143360 B)
malloc(256KB) 之后           break = 0x2e9bc000   (较起点  +143360 B)
free(256KB) 之后             break = 0x2e9bc000   (较起点  +143360 B)
```

**解读**

1. 1000 × 1 KB = 1024000 字节，实际抬高 **1081344** 字节 —— 多出来的 57344 是头部开销 + 对齐取整。
2. **全部 `free` 之后，break 只降了 937984 字节，还留着 143360 字节（140 KB）不还。** 这 140 KB 就是 glibc 留着复用的空闲块 —— 省下的正是下一次 `malloc` 的系统调用。
3. `malloc(256KB)` **一字节都没动 break** —— 它走的是 mmap，和 program break 完全无关。
4. 结论：**`sbrk(0)` 不能当内存占用的仪表**。要看真实占用得读 `/proc/self/status` 的 `VmRSS`（见 6.4）。

同一结论在原书 Listing 7-1 的复刻上更干净（`code/free_and_sbrk.c`，100 个 1 KB 块全 free）：

```text
initial program break:           0xb6d8000
allocating 100*1024 bytes
program break after malloc:      0xb6f9000
freeing blocks from 1 to 100 in steps of 1
program break after free():      0xb6f9000
```

**free 前后 break 一个字节都没变。**

### c7_3 两条路径：`[heap]` 台阶式长，还是新开匿名段

完整程序见 [`../code/c7_3_two_paths.c`](../code/c7_3_two_paths.c)：A 段连续分配 16 KB × 10，B 段连续分配 256 KB × 4，全程记录 `break`、`[heap]` 段、匿名段三个量。

```c
/* Ch7 §7.1 — malloc 的两条路：扩主堆 [heap]，还是新开一段 mmap
 * 编译: gcc -O2 -Wall -Wextra -o c7_3_two_paths c7_3_two_paths.c
 */
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <unistd.h>
#include <fcntl.h>

/* 直接 open/read 读 /proc/self/maps。
 * 不用 fopen —— 它自己会 malloc 一块缓冲，反而污染我们要观测的堆。 */
static long maps_kb(int which)          /* which: 0 = 匿名段, 1 = [heap] */
{
    int fd = open("/proc/self/maps", O_RDONLY);
    if (fd < 0) return -1;

    static char buf[65536];             /* 静态区，不占堆 */
    ssize_t n = read(fd, buf, sizeof buf - 1);
    close(fd);
    if (n <= 0) return -1;
    buf[n] = '\0';

    long kb = 0;
    char *line = buf;
    while (line != NULL && *line != '\0') {
        char *nl = strchr(line, '\n');
        if (nl != NULL) *nl = '\0';

        unsigned long a = 0, b = 0;
        if (sscanf(line, "%lx-%lx", &a, &b) == 2) {
            long size = (long) ((b - a) / 1024);
            if (which == 1) {
                if (strstr(line, "[heap]") != NULL) kb += size;
            } else {
                char *last = strrchr(line, ' ');
                if (last == NULL || *(last + 1) == '\0')
                    kb += size;         /* 没有名字 = 匿名映射 */
            }
        }
        line = (nl != NULL) ? nl + 1 : NULL;
    }
    return kb;
}

int main(void)
{
    printf("初始    break=%p   [heap]=%5ld KB   匿名段=%5ld KB\n\n",
           sbrk(0), maps_kb(1), maps_kb(0));

    /* A. 连续小块：主堆一台阶一台阶地长 */
    puts("A. malloc(16KB) x 10，都不 free：");
    for (int i = 0; i < 10; i++) {
        char *p = malloc(16 * 1024);
        if (p == NULL) { perror("malloc"); return 1; }
        memset(p, 'a', 16 * 1024);
        printf("   #%-2d   break=%p   [heap]=%5ld KB   匿名段=%5ld KB\n",
               i + 1, sbrk(0), maps_kb(1), maps_kb(0));
    }

    /* B. 大块：每次都在别处新开一段匿名映射，主堆纹丝不动 */
    puts("\nB. malloc(256KB) x 4，都不 free：");
    for (int i = 0; i < 4; i++) {
        char *p = malloc(256 * 1024);
        if (p == NULL) { perror("malloc"); return 1; }
        memset(p, 'b', 256 * 1024);
        printf("   #%-2d   break=%p   [heap]=%5ld KB   匿名段=%5ld KB\n",
               i + 1, sbrk(0), maps_kb(1), maps_kb(0));
    }
    return 0;
}
```


**解读**

1. **A 段是台阶式的**：#1 首次分配触发 glibc 建主堆（`[heap]` 0 → 132 KB）；#2–#7 直接从 top chunk 里切，`break` **一步不动**；#8 top 用尽，再 `sbrk` 一次（132 → 264 KB）。这就是「**malloc 不是每次都找内核**」的字面证据。
2. **B 段每次都在别处新开一段**：`[heap]` 纹丝不动，匿名段每次 **+260 KB**（256 KB 请求 + 头部 + 页对齐 = 266240 字节 = 260 KB）。`free` 时这些段会 `munmap` 直接还给内核 —— 这就是「大块分配不造成堆碎片」的原因。
3. **两条路径不是由「请求大小」单独决定的**：A 段的 16 KB 请求，如果 top 不够，`sysmalloc` 会先看 `nb` 是否 ≥ 阈值；B 段的 256 KB 的 `nb ≈ 262176` 比 `[heap]` 里剩下的可用空间大得多（初始映射才 132 KB），所以每次都走出 mmap。准确判据见[要点五的源码](#五两条路径sbrk-还是-mmap源码级判据)。
4. 想自己复现这个实验，**务必先 `mallopt(M_MMAP_THRESHOLD, 128*1024)`**，否则 glibc 的动态阈值会让结果飘。

### c7_4 malloc 家族语义实测

完整程序见 [`../code/c7_4_malloc_family.c`](../code/c7_4_malloc_family.c)：8 个小实验，把 `malloc(0)`、不清零、`calloc` 溢出保护、`realloc` 的四种情形一次测完。

```c
/* Ch7 §7.1 — malloc / calloc / realloc / malloc(0) 的语义实测
 * 编译: gcc -O2 -Wall -Wextra -o c7_4_malloc_family c7_4_malloc_family.c
 */
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <stdint.h>

int main(void)
{
    /* 1) malloc(0)：glibc 返回可 free 的非空指针，不能当失败处理 */
    void *z = malloc(0);
    printf("1) malloc(0) = %p (%s)\n", z,
           z ? "非 NULL，必须 free" : "NULL");
    free(z);

    /* 2) malloc 不清零 —— 但 glibc 的 tcache 会覆写块的头部 16 字节 */
    char *a = malloc(32);
    memcpy(a, "SECRET-TOKEN-1234", 17);
    memcpy(a + 16, "LEFTOVER!", 9);     /* 放到 tcache 元数据之后 */
    printf("2) free 后重新 malloc：a = %p\n", (void *) a);
    free(a);
    char *b = malloc(32);               /* 大概率拿到同一个块 */
    printf("   b = %p  (与 a 同址 = %s)\n", (void *) b, a == b ? "是" : "否");
    printf("   b 的前 32 字节:");
    for (int i = 0; i < 32; i++)
        printf(" %02x", (unsigned char) b[i]);
    printf("\n");
    printf("   b[16] 起的字符串 = %.8s   <- 残留未被清零\n", b + 16);
    free(b);

    /* 3a) calloc 清零 */
    int *arr = calloc(8, sizeof(int));
    printf("3a) calloc(8, 4) 全零 = %s\n",
           (arr[0] | arr[7]) == 0 ? "是" : "否");
    free(arr);

    /* 3b) calloc 的溢出保护：n*s 回绕时返回 NULL，而不是「成功」一个小块。
     * 用非 const 变量传参，绕开编译器的静态检查，让行为在运行期体现。 */
    volatile size_t nmemb = SIZE_MAX, elem = 2;
    void *ovf = calloc(nmemb, elem);
    printf("3b) calloc(SIZE_MAX, 2) = %p (%s)\n", ovf,
           ovf == NULL ? "溢出被拦下" : "竟然成功 → 危险");
    free(ovf);

    /* 4) realloc(NULL, n) 等价 malloc(n) */
    int *p = realloc(NULL, 64);
    printf("4) realloc(NULL, 64) = %p (%s)\n", (void *) p,
           p ? "等价 malloc" : "失败");
    p[0] = 7;

    /* 5) realloc 缩容：通常原地，指针不变。
     * 旧地址先存成整数；返回值另起一个变量接，
     * 免得编译器把「realloc 之后还碰旧指针」判成 use-after-free。 */
    uintptr_t b5 = (uintptr_t) p;
    int *q5 = realloc(p, 16);
    if (q5 == NULL) { perror("realloc"); return 1; }
    printf("5) realloc(64->16) 指针%s: %p -> %p\n",
           ((uintptr_t) q5 == b5) ? "不变" : "改变",
           (void *) b5, (void *) q5);
    p = q5;

    /* 6) realloc 扩容：旧数据保留，指针通常变（跨区搬移） */
    for (int i = 0; i < 4; i++) p[i] = i + 1;
    uintptr_t b6 = (uintptr_t) p;
    int *q6 = realloc(p, 1024 * 1024);
    if (q6 == NULL) { perror("realloc"); return 1; }
    printf("6) realloc(16->1MB) 指针%s: %p -> %p; 旧数据 = %d %d %d %d\n",
           ((uintptr_t) q6 == b6) ? "不变" : "改变",
           (void *) b6, (void *) q6, q6[0], q6[1], q6[2], q6[3]);
    p = q6;
    free(p);

    /* 7) realloc(p, 0)：glibc 释放 p 并返回 NULL（此后 p 已成悬垂） */
    void *q = malloc(128);
    void *r = realloc(q, 0);
    printf("7) realloc(p, 0) = %p (%s)\n", r,
           r == NULL ? "glibc：已释放并返回 NULL" : "返回了非 NULL 指针");
    if (r != NULL) free(r);             /* 非 glibc 实现下才需要 */

    /* 8) free(NULL) 是空操作 */
    free(NULL);
    printf("8) free(NULL) 未崩溃\n");
    return 0;
}
```

```bash

```

实测输出（另在 Compiler Explorer 复核，gcc 13.3）：

```text
1) malloc(0) = 0x1c6b72a0 (非 NULL，必须 free)
2) free 后重新 malloc：a = 0x1c6b82d0
   b = 0x1c6b82d0  (与 a 同址 = 是)
   b 的前 32 字节: b8 c6 01 00 00 00 00 00 00 00 00 00 00 00 00 00 4c 45 46 54 4f 56 45 52 21 00 00 00 00 00 00 00
   b[16] 起的字符串 = LEFTOVER   <- 残留未被清零

6) realloc(16->1MB) 指针改变: 0x1c6b8330 -> 0x7c5874aff010; 旧数据 = 1 2 3 4
7) realloc(p, 0) = (nil) (glibc：已释放并返回 NULL)
8) free(NULL) 未崩溃
```

**解读**

1. **第 2 条是本节最有价值的一段**。十六进制 dump 把两件事同时坐实：
   - 偏移 `0x00-0x07` 是 `b8 c6 01 00 00 00 00 00` —— **tcache 的 `next` 指针**（`tcache_put` 写入，`malloc.c:3157-3163`）；
   - 偏移 `0x08-0x0f` 全是 `00` —— `tcache_get` 把 `e->key` 清成了 0（`malloc.c:3191`）；
   - 偏移 `0x10` 起是 `4c 45 46 54 4f 56 45 52 21` = **`LEFTOVER!`** —— **原样残留，malloc 确实不清零**。
   
   所以「malloc 不清零」这句话要修正得更精确：**用户区头部 16 字节会被 glibc 自己覆写，16 字节之后才是原样残留**。安全上是坏事（信息泄漏面），调试时是好事（能看出这块内存的上一个住户）。
2. **第 3b 条是 `calloc` 存在的真正理由**：`SIZE_MAX × 2` 回绕后是 `SIZE_MAX - 1`，一个天真的实现会「成功」返回一个巨块 —— `calloc` 内部做了溢出检查，直接返回 `NULL`。`malloc(n*s) + memset` 没有这层保护。
3. 第 5 / 6 条的对照说明 **`realloc` 的行为不统一**：缩容原地（指针不变），扩容跨区搬移（指针从 `0x1c6b8330` 跳到 mmap 区的 `0x7c5874aff010`，旧数据 `1 2 3 4` 完整带过去）。所以**旧指针必须视为失效**。
4. 第 7 条实测确认 glibc 的 `realloc(p, 0)` = `free(p)` + 返回 `NULL`。
5. ⚠️ 这份源码在 `-O2 -Wall -Wextra` 下会报 2 条 **`-Wuse-after-free`**（"pointer 'p'/'q5' may be used after 'realloc'"）。它不是代码写错 —— 我们只是把 `realloc` **前后**的地址都拿去打印，而 GCC 的指针分析无法区分「打印地址值」和「解引用」。**但这条警告指向的规则是真的**：`realloc` 之后旧指针失效。生产代码里如果它真的报了，请当成真 bug 查。

### c7_5 对齐

完整程序见 [`../code/c7_5_memalign.c`](../code/c7_5_memalign.c)。

```c
/* Ch7 §7.1 — 对齐分配：malloc 的默认对齐 vs posix_memalign / aligned_alloc
 * 编译: gcc -O2 -Wall -Wextra -o c7_5_memalign c7_5_memalign.c
 */
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <stddef.h>
#include <stdint.h>

int main(void)
{
    /* malloc 保证的对齐 = max_align_t 的对齐（x86-64 上为 16） */
    printf("_Alignof(max_align_t) = %zu\n\n", _Alignof(max_align_t));

    /* 连续 8 次 malloc(1)，看地址低 4 位 */
    printf("malloc(1) 连续 8 次的地址（低 4 位应恒为 0）:\n");
    void *ps[8];
    for (int i = 0; i < 8; i++) {
        ps[i] = malloc(1);
        printf("   %p   低4位 = %zu\n", ps[i], (uintptr_t) ps[i] & 0xf);
    }
    for (int i = 0; i < 8; i++) free(ps[i]);

    /* posix_memalign：成功返回 0，失败返回 errno 值（不是设 errno） */
    size_t align = 4096;
    void *pg = NULL;
    int rc = posix_memalign(&pg, align, 100);
    if (rc != 0) { fprintf(stderr, "posix_memalign: %s\n", strerror(rc)); return 1; }
    printf("\nposix_memalign(4096, 100) = %p,  %% 4096 = %zu\n",
           pg, (uintptr_t) pg % align);
    free(pg);

    /* 非法对齐（不是 2 的幂）→ 返回 EINVAL，不是崩溃 */
    void *bad = NULL;
    rc = posix_memalign(&bad, 100, 64);
    printf("posix_memalign(100, 64) rc = %d (%s)\n", rc,
           rc ? "EINVAL，被拒绝" : "竟然成功");
    free(bad);

    /* aligned_alloc (C11)：要求 size 是 align 的整数倍 */
    void *av = aligned_alloc(64, 64 * 4);
    printf("aligned_alloc(64, 256) = %p,  %% 64 = %zu\n",
           av, (uintptr_t) av % 64);
    free(av);
    return 0;
}
```

编译与运行：

```bash
gcc -O2 -Wall -Wextra -o c7_5_memalign c7_5_memalign.c && ./c7_5_memalign
```

实测输出（另在 Compiler Explorer 复核，gcc 13.3）：

```text
_Alignof(max_align_t) = 16

malloc(1) 连续 8 次的地址（低 4 位应恒为 0）:
   0x347cb2b0   低4位 = 0
   0x347cb2d0   低4位 = 0
   0x347cb2f0   低4位 = 0
   0x347cb310   低4位 = 0
   0x347cb330   低4位 = 0
   0x347cb350   低4位 = 0
   0x347cb370   低4位 = 0
   0x347cb390   低4位 = 0

posix_memalign(4096, 100) = 0x347cc000,  % 4096 = 0
posix_memalign(100, 64) rc = 22 (EINVAL，被拒绝)
aligned_alloc(64, 256) = 0x347cb3c0,  % 64 = 0
```

**解读**

1. 8 次 `malloc(1)` 的地址低 4 位**恒为 0** —— 这就是「`malloc` 保证 16 字节对齐」的实测形态（间隔恰好 0x20 = 32，因为最小 chunk 是 32）。
2. `posix_memalign(4096, 100)` 返回的地址 `% 4096 == 0`，直接拿到页对齐 —— 这正是 `O_DIRECT` 和 DMA 需要的那种指针。
3. **非法对齐（100 不是 2 的幂）返回 `rc = 22`，也就是 `EINVAL`**，不是崩溃、也不是 `NULL`。`posix_memalign` 用返回值报错，**不设 `errno`**，这点和 `malloc` 不同。
4. 想要 16 以上的对齐，**别自己加 padding**（那是内存浪费 + 易错）：`posix_memalign` / `aligned_alloc` 就是干这个的。

### c7_6 五类典型堆错误：ASan 抓现行

完整程序见 [`../code/c7_6_heap_errors.c`](../code/c7_6_heap_errors.c)：五个 case 各是一个小函数，由 `-DCASE=n` 在编译期选定。

```c
/* Ch7 §7.1 — 五类典型堆错误，用 ASan 抓现行
 * 每次只编一种（CASE 由编译期决定），这样每个 case 都在干净的进程里跑：
 *
 *   for n in 1 2 3 4 5; do
 *       gcc -O1 -g -fsanitize=address -DCASE=$n -Wall -Wextra \
 *           -o c7_6_case$n c7_6_heap_errors.c
 *       ./c7_6_case$n
 *   done
 */
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <unistd.h>

#ifdef __SANITIZE_ADDRESS__
#include <sanitizer/lsan_interface.h>
#endif

#ifndef CASE
#define CASE 1
#endif

/* 1. 堆越界写：踩到分配器元数据 / ASan 的 redzone */
static void case_oob(void)
{
    char *raw = malloc(8);
    volatile char *p = raw;
    p[16] = 'x';                        /* 越界 8 字节，落在 ASan 的 redzone 里 */
    free(raw);
}

/* 2. use-after-free */
static void case_uaf(void)
{
    char *p = malloc(32);
    free(p);
    printf("     (uaf) 释放后读到的字节 = %d\n", p[0]);
}

/* 3. double free */
static void case_double_free(void)
{
    char *p = malloc(32);
    printf("     (df) 第一块 %p\n", (void *) p);
    free(p);
    free(p);
}

/* 4. 内存泄漏：
 *    大多数 ASan 环境在进程退出时由 LSan 汇报泄漏，但有些容器里
detect_leaks 默认是关的（实测 Compiler Explorer 就是）。
 *    所以这里换成不依赖工具的观测法：看 RSS 涨不涨。 */
static long rss_kb(void)
{
    FILE *f = fopen("/proc/self/statm", "r");
    if (f == NULL) return -1;
    long total = 0, resident = 0;
    if (fscanf(f, "%ld %ld", &total, &resident) != 2) resident = -1;
    fclose(f);
    return resident * (sysconf(_SC_PAGESIZE) / 1024);
}

static void case_leak(void)
{
    long before = rss_kb();
    for (int i = 0; i < 1000; i++) {
        void *p = malloc(4096);         /* 指针当场丢失 */
        if (p != NULL) memset(p, 1, 4096);  /* 真碰，否则物理页不会到手 */
    }
    printf("     (leak) 1000 x 4KB 分配后不释放：RSS %+ld KB\n",
           rss_kb() - before);
    fflush(stdout);                     /* LSan 报错后直接 _exit，缓冲会丢 */
#ifdef __SANITIZE_ADDRESS__
    __lsan_do_leak_check();             /* 环境若开了 LSan，这里会额外报一份 */
#endif
}

/* 5. free 一个非堆指针（这里是栈地址） */
static void case_invalid(void)
{
    int on_stack = 42;
    free(&on_stack);
}

static const struct { const char *name; void (*fn)(void); } CASES[] = {
    { "(无)",                            NULL },
    { "越界写     heap-buffer-overflow",  case_oob },
    { "释放后使用 heap-use-after-free",   case_uaf },
    { "重复释放   double-free",           case_double_free },
    { "内存泄漏   leak",                  case_leak },
    { "free 非堆  bad-free",              case_invalid },
};

int main(void)
{
    printf("CASE %d: %s\n", CASE, CASES[CASE].name);
    fflush(stdout);
    CASES[CASE].fn();
    return 0;
}
```

每个 case 单独编译（`-DCASE=n`），保证在**干净的进程**里触发：

```bash

    gcc -O1 -g -fsanitize=address -DCASE=$n -Wall -Wextra -o c7_6_case$n c7_6_heap_errors.c
    ./c7_6_case$n
done
```

**解读**

1. 五类错误里，**glibc 自己能立刻拦下的只有 double-free 和 bad-free** —— 它检查 tcache key、检查指针是否真的有 chunk 头，不合法就直接 `abort`。而**越界写和 use-after-free 在默认配置下可以悄无声息地活很久**（碰坏了邻居的 chunk 头，往往到下一次 `free` 才炸）；泄漏则永远不报。ASan 的价值就是把其中 4 类提前到现场。
2. 每一类都给了**从分配到出错**的完整调用栈（上面省略了中间的 frame）：`allocated by` → `freed by` → `READ of size 1`。这是 ASan 相对 valgrind 的优势（不用跑两遍、报告更短）。
3. **踩到的坑**：Compiler Explorer 上 ASan 的 `detect_leaks` **默认是关的** —— 程序正常退出时不会报泄漏。解法是**显式调用 `__lsan_do_leak_check()`**（`<sanitizer/lsan_interface.h>`，用 `#ifdef __SANITIZE_ADDRESS__` 包起来）。实测这样就能拿到 `4096000 byte(s) in 1000 object(s)` 的精确报告。
4. 另一个坑：**ASan 报错后直接 `_exit`，不 flush stdio** —— 前面 `printf` 的内容会全部丢失。所以 CASE 4 里在 `__lsan_do_leak_check()` 之前加了 `fflush(stdout)`。（[c7_1 的 B 段](#c7_1-归位可以降过头就崩)也是另一种「输出突然没了」，但那里的机制是缓冲区**被 unmap 掉**，不是没 flush —— 两个坑别混。）
5. 泄漏还有个不依赖任何工具的证据：**RSS 涨了 5796 KB**（1000 × 4 KB = 4096 KB 用户数据，其余是 ASan 的 redzone / 影子内存 / 分配器元数据等开销）。`泄漏` 的本质就是「这些页一直占着不还」。

## HFT / 嵌入式关联

- **热路径上不要有 `malloc`**。分配器最坏情况是 O(链长) 的搜索 + 不可预测的 `sbrk` / `mmap` 系统调用 —— 后者在 HFT 里就是几十微秒的抖动。做法是预分配 arena / 固定大小对象池，启动时一次性拿到。
- **想避免碎片就绕开主堆**：大于阈值的分配直接走去 `mmap`（`free` 时完整归还内核），这也是 `jemalloc` / `tcmalloc` 按 size class 切分的思路。
- **大页**：HFT 的关键数据结构用 `mmap(MAP_HUGETLB)` 或 `madvise(MADV_HUGEPAGE)`，直接降低 TLB miss —— 那是 [Ch49](../../chapter-49-memory-mappings/README.md) / Ch50 的地盘。
- **嵌入式**：无 MMU 的平台（uClinux）**没有 `brk`**，heap 只能靠 `mmap` 或静态池。堆上还有一个隐形代价 —— **碎片**在长时间运行的小内存设备上是致命伤，通常直接禁用 `malloc`。
- **`malloc(0)` / `realloc(p, 0)` 这类边角在跨平台代码里是雷**：标准不统一，glibc / BSD 行为不同。写法上统一成显式 `free` + `malloc` 最省心。
- **ASan 要进 CI**：本节五类错误里有三类在默认 glibc 下不会立刻报错，靠人眼 review 是抓不住的。

## 自测题

<details>
<summary>1. `free(p)` 之后 `sbrk(0)` 完全没变，说明内存没被释放吗？</summary>

**不是。** `free` 把一个块标记为空闲并交回 glibc 的空闲链表，**只改分配器自己的数据结构，不碰 program break**。只有「堆顶那一段连续空闲」大到值得归回时，glibc 才可能调 `sbrk(-n)`。

实测（c7_2）：`malloc(1000 × 1KB)` 把 break 抬高 1081344 字节，全部 `free` 之后只降到 +143360 字节 —— 还留着 140 KB 在链表里复用。这正是「分配器用空间换系统调用」的策略。

要判断内存是否真被释放，看 `free` 之后**能不能被下一次 `malloc` 复用**，或者读 `/proc/self/status` 的 `VmRSS`。
</details>

<details>
<summary>2. 一个 200 KB 的 `malloc`，一定会走 `mmap` 吗？</summary>

**不一定。** 判据不是「请求大小 vs 128 KB」，而是（`malloc.c:2564`）：

```c
if ((unsigned long)(nb) >= (unsigned long)(mp_.mmap_threshold) && ...)
```

三处关键：
1. 比的是 **`nb`（chunk 大小，含 8 字节头部并向上取整 16）**，不是请求的 `size`；
2. 这句话**只在 `sysmalloc()` 里**，也就是**只有现有 bin 和 top chunk 都满足不了时才会被走到**；
3. 阈值还会被 `free()` 大块时的动态调整改掉（`malloc.c:3380`）。

所以如果进程的 top chunk 里恰好有 200 KB 空闲，这个请求会**直接从 top 切**，两条系统调用路径都不走。实测中 256 KB 的请求每次都走 mmap，是因为 `nb ≈ 262176` 比 `[heap]` 里**剩余**的可用空间大得多（初始 `[heap]` 映射 132 KB，A 段再消耗 160 KB 之后更少）。
</details>

<details>
<summary>3. `calloc(n, s)` 和 `malloc(n*s)` + `memset` 相比，安全性上强在哪？</summary>

**整数溢出检查。**

`n * s` 在 `size_t` 上回绕后可能变成一个小数字。天真的实现 `malloc(n*s)` 会「成功」返回一个远小于预期的块，随后按原尺寸写就越界 —— 这是一类经典的可利用漏洞。

实测（c7_4 第 3b 条）：`calloc(SIZE_MAX, 2)` 返回 `NULL`（溢出被拦下），而不是返回一个回绕后的小块。

性能上还有个附带好处：大块 `calloc` 走 `mmap` 时，内核给的**匿名页本来就是清零的**，glibc 可以省掉 `memset`。
</details>

<details>
<summary>4. 为什么说「业务代码禁止直接调用 `brk` / `sbrk`」？</summary>

因为**堆不是你一个人的**。glibc 的分配器在你的进程里维护着一整套状态（top chunk、各个 bin、tcache），stdio 的缓冲区、`fopen` 的 `FILE` 结构等全都在堆上。

你要是直接把 break 降回去，就等于把它们脚下的虚拟地址还给了内核。实测（c7_1 B 段）：子进程在 `brk(最早记录的值)` 之后 **被信号 11 杀死** —— 它连一行 `printf` 都写不出来了。

要拿更多内存，用 `malloc`；要拿一段独立的大内存，用 `mmap`。`brk` / `sbrk` 只在**读**（`sbrk(0)` 看边界、理解 `malloc` 行为）时才有用。
</details>
