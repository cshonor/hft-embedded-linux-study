# 37.6 Summary

> 本章：[TLPI 第 37 章 — Daemons](./README.md)

## 本章回顾

### Daemon 化流程

```
1. fork() + 父 exit      ← 脱离 shell
2. setsid()               ← 新会话 + 新进程组 + 脱离控制终端
3. fork() + 父 exit       ← 不再是会话首，不能再获得终端
4. chdir("/")              ← 不占用目录
5. umask(0)                ← 文件权限不受继承 umask 影响
6. close all fd / dup→null ← 关闭继承的 fd
7. open syslog             ← 日志重定向
```

### Daemon 相关 API

| 函数 | 用途 |
|------|------|
| `setsid()` | 创建新会话 |
| `fork()` × 2 | 脱离 shell 和会话首 |
| `chdir("/")` | 切换工作目录 |
| `umask(0)` | 清除 umask |
| `open("/dev/null")` + `dup2` | 重定向 stdio |
| `openlog()`/`syslog()` | 系统日志 |
| `umask()` | 设置 umask |

### 日志系统

```c
openlog("my_daemon", LOG_PID | LOG_NDELAY, LOG_DAEMON);
syslog(LOG_INFO, "started, pid=%d", getpid());
syslog(LOG_ERR, "error: %s", strerror(errno));
closelog();
```

| facility | 说明 |
|----------|------|
| `LOG_DAEMON` | 系统服务（默认） |
| `LOG_LOCAL0`~`LOG_LOCAL7` | 自定义 |

| priority | 级别 |
|----------|------|
| `LOG_EMERG` | 紧急 |
| `LOG_ALERT` | 警报 |
| `LOG_CRIT` | 严重 |
| `LOG_ERR` | 错误 |
| `LOG_WARNING` | 警告 |
| `LOG_NOTICE` | 通知 |
| `LOG_INFO` | 信息 |
| `LOG_DEBUG` | 调试 |

### SIGHUP 处理

Daemon 脱离控制终端后不会收到 SIGHUP，因此常用作"重新加载配置"信号：

```c
void sighup_handler(int sig) {
    reload_config();
}

signal(SIGHUP, sighup_handler);
```

## HFT / 嵌入式关联

- **HFT 服务 daemon 化**：行情/策略/风控进程都需 daemon 化
- **日志**：用 `syslog` 或自定义日志框架（HFT 通常用自建日志，syslog 延迟不可控）
- **systemd 替代**：现代 Linux 用 systemd 管理服务，`Type=forking` 或 `Type=simple`，自动处理 daemon 化
- **嵌入式**：BusyBox 的 start-stop-daemon 管理 daemon 生命周期
- **PID 文件**：在 `/var/run/myapp.pid` 写入 PID，供运维脚本管理

## 代码自测

<details>
<summary>1. 为什么 daemon 需要两次 fork？</summary>

第一次 fork 脱离 shell。setsid 后成为会话首进程，但会话首进程可能重新获得控制终端（通过打开终端设备）。第二次 fork 后子进程不是会话首进程，不会再获得控制终端。这确保 daemon 永远脱离终端控制。
</details>

<details>
<summary>2. systemd Type=simple 和 Type=forking 的区别？</summary>

- **Type=simple**：进程不 daemon 化，systemd 认为主进程是服务进程。简单直接，stdout/stderr 自动被 journald 捕获。
- **Type=forkting**：传统 daemon 模式，主进程 fork 子进程后退出。systemd 需指定 `PIDFile` 追踪子进程。复杂但兼容传统 daemon。

现代推荐 `Type=simple`（或 `Type=exec`），不需要程序自己做 daemon 化——systemd 接管。
</details>

<details>
<summary>3. 为什么 daemon 要关闭所有 fd？</summary>

1. **释放资源**：从父进程继承的 fd（如终端、管道）可能不再需要
2. **防止干扰**：继承的终端 fd 可能影响终端操作
3. **文件描述符泄漏**：未关闭的 fd 占用资源
4. **安全**：防止通过继承的 fd 访问不应访问的文件

重定向 stdin/stdout/stderr 到 `/dev/null` 确保标准 I/O 操作不失败。
</details>
