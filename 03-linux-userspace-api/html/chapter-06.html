章节目标

建立进程基础模型：虚拟地址空间布局、命令行参数、环境变量、PID/PPID；掌握非局部跳转 setjmp/longjmp，为后续 fork、exec、信号、多进程铺路。

易错清单

  1. BSS 在磁盘可执行文件几乎不占空间；加载后分配并清零。
  2. 代码段 / 字符串字面量只读；改写 → 常 SIGSEGV。
  3. getenv 指针勿 free。
  4. putenv 传入局部栈缓冲 → 野指针风险。
  5. 信号处理里 longjmp 有额外限制（Ch21）。
  6. 用 environ，勿依赖非标准 envp。
  7. 本章 没有 fork/exec；别和 Ch24–27 混章。

Ch5  fd / 打开描述（stdin/out/err 已在进程里）

  → Ch8  UID/GID
  → Ch24 fork：复制地址空间、环境、fd 表（本章直接落地）

代码示例

#include <stdio.h>
#include <unistd.h>
#include <sys/types.h>
#include <sys/wait.h>

/* Ch6 进程 — 演示 fork/wait/getpid 基本进程操作。
 * fork() 创建子进程；wait() 等待子进程结束。
 * 编译: gcc -o ch6_demo ch6_demo.c */

int main(void) {
    pid_t pid = fork();
    if (pid < 0) {
        perror("fork");
        return 1;
    }

    if (pid == 0) {
        /* 子进程 */
        printf("Child: pid=%d, parent pid=%d\n",
               (int)getpid(), (int)getppid());
        _exit(42);
    } else {
        /* 父进程 */
        printf("Parent: pid=%d, child pid=%d\n",
               (int)getpid(), (int)pid);
        int status;
        waitpid(pid, &status, 0);
        if (WIFEXITED(status))
            printf("Child exited with %d\n", WEXITSTATUS(status));
    }
    return 0;
}

6.1

进程基本概念

本章：TLPI 第 06 章 — Processes - 上一节：本章首页 - 下一节：6.2 PID 与 PPID

本节讲什么

进程 = 内核管理的执行上下文；内核为其分配资源以运行程序。 内核视角两大块： 1. 用户空间内存：代码、数据、栈、堆等

要点
程序（program） 磁盘上的静态可执行文件
进程（process） 加载进内存、正在执行的动态实例

进程 = 内核管理的执行上下文；内核为其分配资源以运行程序。

内核视角两大块：

  1. 用户空间内存：代码、数据、栈、堆等
  2. 内核 PCB（Linux：task_struct）：状态、PID、fd 表、信号掩码、资源限制等

代码示例

#include <unistd.h>
#include <stdio.h>
#include <sys/types.h>

int main(void) {
    /* 进程 = 内核管理的执行上下文 */
    printf("PID = %d\n", getpid());
    printf("PPID = %d (父进程)\n", getppid());

    /* 进程有自己的地址空间 */
    int x = 42;  /* x 在栈上 */
    printf("x 的地址: %p (栈区)\n", (void *)&x);

    /* 进程有自己的 fd 表 */
    printf("stdin fd = %d, stdout fd = %d\n", STDIN_FILENO, STDOUT_FILENO);

    /* 查看进程的内存映射（内核视角的进程资源） */
    printf("查看 /proc/%d/maps 可了解进程地址空间\n", getpid());
    return 0;
}

6.2

PID 与 PPID

本章：TLPI 第 06 章 — Processes - 上一节：6.1 进程基本概念 - 下一节：6.3 进程虚拟地址空间（本章核心）

本节讲什么

include pid_t getpid(void); / 当前 PID；永不失败 / pid_t getppid(void); / 父进程 PID /

要点

#include <unistd.h>
pid_t getpid(void);   /* 当前 PID；永不失败 */
pid_t getppid(void);  /* 父进程 PID */
点
PID 正整数；历史上常见上限 32767，见 /proc/sys/kernel/pid_max（现代可更大）
PID 1 init / systemd，系统初代进程
孤儿进程 父先退出 → 被 PID 1 收养 → getppid() 常为 1
错误处理 getpid/getppid 不会失败，不必查 -1

代码示例

#include <unistd.h>
#include <stdio.h>
#include <sys/types.h>

int main(void) {
    pid_t pid = getpid();     /* 当前 PID，永不失败 */
    pid_t ppid = getppid();   /* 父进程 PID */

    printf("PID  = %d\n", pid);
    printf("PPID = %d\n", ppid);

    /* 孤儿进程：父进程先退出 → 被 PID 1 收养 */
    pid_t child = fork();
    if (child == 0) {
        /* 子进程 */
        sleep(1);  /* 等父进程先退出 */
        printf("子进程: PID=%d, PPID=%d\n", getpid(), getppid());
        /* 如果父进程已退出，PPID 会变成 1（被 init 收养） */
        _exit(0);
    } else if (child > 0) {
        printf("父进程: PID=%d, 子PID=%d\n", pid, child);
        /* 父进程立即退出，子进程变孤儿 */
    } else {
        perror("fork");
        return 1;
    }
    return 0;
}

6.3

进程虚拟地址空间（本章核心）

本章：TLPI 第 06 章 — Processes - 上一节：6.2 PID 与 PPID - 下一节：6.4 命令行参数 argv

本节讲什么

用户空间（低 → 高，示意）： 高地址 ┌─────────────────────┐ │ 内核空间（用户不可访） │

要点

用户空间（低 → 高，示意）：

高地址  ┌─────────────────────┐
        │  内核空间（用户不可访） │
        ├─────────────────────┤
        │  栈 Stack ↓         │  局部变量、参数、返回地址；ulimit -s
        ├─────────────────────┤
        │  mmap / 共享库 …    │
        ├─────────────────────┤
        │  堆 Heap ↑          │  malloc；边界 = program break（Ch7）
        ├─────────────────────┤
        │  BSS（未初始化数据）  │  加载时清零；磁盘映像几乎不占空间
        ├─────────────────────┤
        │  Data（已初始化数据） │  显式初始化的全局/静态
        ├─────────────────────┤
低地址  │  Text（代码段，只读） │  指令；同程序多进程可共享
        └─────────────────────┘

变量落点示例

const char *s = "hello";  /* s：数据段；字面量：只读（常在 text/rodata） */
static int x;             /* BSS */
static int y = 5;         /* Data */
int main(void) {
    int z;                /* 栈 */
    int *p = malloc(4);   /* p 在栈；*p 在堆 */
}

Demo：code/mem_segments.c

代码示例

#include <stdio.h>
#include <stdlib.h>

/* 不同段的全局/静态变量 */
const char *ro_str = "hello";   /* 字面量在只读段 */
static int bss_var;             /* BSS（未初始化 → 清零） */
static int data_var = 100;      /* Data（已初始化） */
int global_var = 7;             /* Data */

int main(void) {
    int stack_var = 42;                   /* 栈 */
    int *heap_var = malloc(sizeof(int));  /* 堆 */
    *heap_var = 99;

    printf("=== 进程地址空间 ===\n");
    printf("只读字面量  ro_str   = %p\n", (void *)ro_str);
    printf("Text/代码段  main    = %p\n", (void *)main);
    printf("Data 段     data_var = %p\n", (void *)&data_var);
    printf("Data 段     global   = %p\n", (void *)&global_var);
    printf("BSS 段      bss_var  = %p (值=%d, 清零)\n", (void *)&bss_var, bss_var);
    printf("栈          stack    = %p\n", (void *)&stack_var);
    printf("堆          heap     = %p (值=%d)\n", (void *)heap_var, *heap_var);

    printf("\n地址从低到高: Text → Data → BSS → Heap → ... → Stack → Kernel\n");
    free(heap_var);
    return 0;
}

6.4

Virtual Memory Management

本章：TLPI 第 6 章

本节讲什么

Linux 采用虚拟内存管理：每个进程有独立的虚拟地址空间，通过页表映射到物理内存。

核心概念

  • 虚拟页 → 物理页帧：MMU 通过页表转换
  • 缺页中断：访问未映射的页时，内核分配物理页
  • 按需分页（demand paging）：页在首次访问时才加载
  • 交换（swap）：内存不足时将页写到交换分区

虚拟内存区域（VMA）

内核为每个进程维护 VMA 列表，记录各段（text/data/heap/stack/mapping）的属性。 - /proc/[pid]/maps 查看进程的 VMA 布局 - /proc/[pid]/smaps 更详细，含 RSS/PSS

HFT 关注点

  • mlockall() 锁定内存，防止换页导致延迟尖峰
  • 大页（huge pages）减少 TLB miss

6.5

The Stack and Stack Frames

本章：TLPI 第 6 章

本节讲什么

每次函数调用在栈上创建一个栈帧（stack frame），包含局部变量、参数、返回地址。

栈帧结构

高地址 │ 返回地址     │
       │ 旧 rbp       │ ← rbp 指向这里
       │ 局部变量     │
       │ 保存的寄存器 │
低地址 │ ...          │ ← rsp 指向栈顶

栈的特性

  • 自动管理：函数返回时栈帧自动释放
  • 方向：x86-64 上栈向低地址增长
  • 大小：默认 8MB（ulimit -s），超限 → SIGSEGV
  • 栈溢出常见原因：递归太深、大数组局部变量

栈 vs 堆

特性 栈 堆
分配速度 极快（移动 sp） 慢（malloc 搜索空闲块）
生命周期 函数返回自动释放 手动 free
大小 有限（默认 8MB） 大（受虚拟地址空间限制）

6.4

命令行参数 `argv`

本章：TLPI 第 06 章 — Processes - 上一节：6.3 进程虚拟地址空间（本章核心） - 下一节：6.5 环境变量

本节讲什么

int main(int argc, char *argv[]) ---

要点

int main(int argc, char *argv[])
argc 参数个数
argv[0] 程序名（可为任意字符串；POSIX 允许与真实路径不一致）
argv[argc] NULL
来源 父进程 fork+exec 传入
可改性 可改字符串内容；勿随意改 argv 指针数组语义

代码示例

#include <stdio.h>

int main(int argc, char *argv[]) {
    printf("argc = %d\n", argc);

    /* argv[0] 是程序名（可能是路径） */
    printf("argv[0] = %s\n", argv[0]);

    /* 打印所有参数 */
    for (int i = 1; i < argc; i++) {
        printf("argv[%d] = %s\n", i, argv[i]);
    }

    /* argv[argc] == NULL（C 标准保证） */
    printf("argv[%d] = %s\n", argc, argv[argc] ? "非NULL" : "NULL");

    /* 简单参数解析示例 */
    if (argc > 1 && argv[1][0] == '-') {
        printf("检测到选项: %s\n", argv[1]);
    }
    return 0;
}

6.5

环境变量

本章：TLPI 第 06 章 — Processes - 上一节：6.4 命令行参数 argv - 下一节：6.6 非局部跳转 setjmp / longjmp

本节讲什么

extern char environ; / NAME=VALUE 字符串数组，NULL 结尾 / #include char getenv(const char name);

要点

extern char **environ;   /* NAME=VALUE 字符串数组，NULL 结尾 */

API

#include <stdlib.h>
char *getenv(const char *name);
int putenv(char *string);                                      /* 持有传入缓冲，慎用 */
int setenv(const char *name, const char *value, int overwrite); /* 推荐 */
int unsetenv(const char *name);
int clearenv(void);
要点
继承 子进程默认继承父环境（fork 复制）
作用域 进程内修改只影响自己及之后创建的子进程；不影响父进程/外层 shell
setenv vs putenv setenv 复制字符串；putenv 直接用传入缓冲 → 局部数组会变野指针
getenv 返回指向环境区的指针；不要 free
main 第三参 envp 非标准扩展，不推荐；用 environ

典型用途：PATH、LC_*、LD_LIBRARY_PATH、配置传递。

Demo：code/t_getenv.c

代码示例

#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
extern char **environ;
/* 环境变量: getenv/setenv/unsetenv + environ */
int main(void) {
    /* getenv: 查询 */
    char *path = getenv("PATH");
    printf("PATH = %.40s...\n", path ? path : "(null)");

    /* setenv: 设置 (overwrite=1) */
    setenv("MY_VAR", "hello", 1);
    printf("MY_VAR = %s\n", getenv("MY_VAR"));

    /* unsetenv: 删除 */
    unsetenv("MY_VAR");
    printf("after unset: %s\n", getenv("MY_VAR") ? "exists" : "gone");

    /* environ: 遍历所有环境变量 */
    printf("\nFirst 3 env vars:\n");
    for (int i = 0; i < 3 && environ[i]; i++)
        printf("  %s\n", environ[i]);
    return 0;
}

6.6

非局部跳转 `setjmp` / `longjmp`

本章：TLPI 第 06 章 — Processes - 上一节：6.5 环境变量 - 下一节：下一章+1:02d}-*/notes.md)

本节讲什么

include int setjmp(jmp_buf env); / 直接调用返回 0；保存栈上下文 / void longjmp(jmp_buf env, int val); / 回到 setjmp；表现为返回 val（0→1） /

要点

#include <setjmp.h>
int setjmp(jmp_buf env);           /* 直接调用返回 0；保存栈上下文 */
void longjmp(jmp_buf env, int val); /* 回到 setjmp；表现为返回 val（0→1） */
  • 普通 goto：函数内。
  • setjmp/longjmp：跨函数非局部跳转。

易踩坑：优化变量

setjmp 与 longjmp 之间被修改的局部变量，若放在寄存器里，恢复后可能「回滚」：

volatile int flag;  /* 强制走内存，禁止只放寄存器 */

典型场景：深层错误跳出、简易异常路径（信号处理里的用法见 Ch21，限制更多）。

Demo：code/setjmp_vars.c

代码示例

#include <stdio.h>
#include <setjmp.h>
#include <stdlib.h>
/* setjmp/longjmp: 非局部跳转 (类似 goto 但可跨函数) */
static jmp_buf env;

void do_error(void) {
    printf("Error occurred, jumping back...\n");
    longjmp(env, 1);  /* 跳回 setjmp, 返回值=1 */
}

int main(void) {
    int ret = setjmp(env);
    if (ret == 0) {
        printf("Normal path\n");
        do_error();  /* 模拟出错 */
        printf("This line never executes\n");
    } else {
        printf("Error recovery path (ret=%d)\n", ret);
    }
    printf("Continuing after error recovery\n");
    return 0;
}

setjmp/longjmp 语义

jmp_buf env;
int r = setjmp(env);  /* 第一次返回 0，longjmp 后返回非 0 */
if (r == 0) {
    /* 正常路径 */
    do_something();   /* 如果出错，调用 longjmp(env, val) */
} else {
    /* 错误恢复路径，r = longjmp 的 val */
}
注意点 说明
寄存器变量 volatile 修饰的变量在 longjmp 后保持正确值
栈帧有效 longjmp 的目标函数必须仍在调用栈中（未返回）

代码自测

1. setjmp 返回值什么时候是 0？什么时候不是？

直接调用 setjmp(env) 时返回 0。当后续调用 longjmp(env, val) 时，执行流跳回 setjmp 的位置，此时返回值为 val（如果 val 为 0，会被强制改为 1）。

2. 为什么在信号处理器中用 longjmp 是危险的？
  1. 信号可能在 longjmp 的目标函数正在执行时中断
  2. longjmp 不恢复信号掩码，其他信号被屏蔽后无法恢复
  3. 如果使用非异步信号安全的函数（如 malloc），可能导致死锁
  4. 应使用 sigsetjmp/siglongjmp 替代，它们保存和恢复信号掩码
3. getenv 返回的指针可以修改吗？

技术上可以，但不应该。getenv 返回的是 environ 数组中指向字符串的指针，修改它会改变环境变量。正确做法是 setenv/putenv。返回的指针在下次调用 setenv/putenv 后可能失效。

练习 2 参考代码

#include "tlpi_hdr.h"
#include <setjmp.h>

static jmp_buf err_env;
static int err_code;

/* 模拟深层调用链 */
void level3(int fail) {
    if (fail) {
        err_code = 42;
        longjmp(err_env, err_code);
    }
    printf("level3: success\n");
}

void level2(int fail) { level3(fail); }
void level1(int fail) { level2(fail); }

int main(void) {
    int r = setjmp(err_env);
    if (r == 0) {
        printf("第一次调用（正常路径）\n");
        level1(0);       /* 不出错 */
        level1(1);       /* 出错 → longjmp */
        printf("这行不会执行\n");
    } else {
        printf("错误恢复：err_code=%d\n", r);
    }
    return 0;
}

练习 3 答案

危险性： 1. 信号掩码未恢复：longjmp 不恢复信号掩码，处理器期间被屏蔽的信号不会被重新启用 2. 非异步信号安全函数：如果信号打断 malloc 等，longjmp 跳过释放步骤，导致堆损坏或死锁 3. 栈帧可能无效：如果信号打断的函数已返回，目标栈帧可能已销毁

安全替代：

#include <signal.h>
#include <setjmp.h>

static sigjmp_buf sig_env;

void handler(int sig) {
    siglongjmp(sig_env, 1);  /* 保存/恢复信号掩码 */
}

/* 使用 */
if (sigsetjmp(sig_env, 1) == 0) {
    signal(SIGINT, handler);
    /* 危险操作... */
} else {
    printf("被信号中断\n");
}

sigsetjmp(buf, savesigs) 的第二个参数为 1 表示保存信号掩码。siglongjmp 会恢复掩码。
