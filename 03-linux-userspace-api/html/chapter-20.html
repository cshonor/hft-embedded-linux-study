章节目标

20.8 易错清单

  1. SIGKILL/SIGSTOP 不可捕/忽/阻
  2. 标准信号不排队；实时信号可排队
  3. 掩码是线程属性
  4. 阻塞 ≠ 忽略（pending 待递送 vs 直接丢）

代码示例

#include <stdio.h>
#include <signal.h>
#include <unistd.h>

/* Ch20 信号基础 — signal/kill/raise + 信号概念。
 * 演示注册信号处理器 + 自发信号。
 * 编译: gcc -o ch20_demo ch20_demo.c */

static volatile sig_atomic_t got_signal = 0;

void handler(int sig) {
    got_signal = sig;
}

int main(void) {
    /* 注册 SIGUSR1 处理器 */
    signal(SIGUSR1, handler);

    /* 给自己发信号 */
    printf("Sending SIGUSR1 to self...\n");
    raise(SIGUSR1);

    /* 检查是否收到 */
    if (got_signal == SIGUSR1)
        printf("Caught SIGUSR1!\n");
    else
        printf("No signal caught\n");

    /* kill() 也可以给自己发信号 */
    printf("Sending SIGUSR1 via kill()...\n");
    kill(getpid(), SIGUSR1);

    if (got_signal == SIGUSR1)
        printf("Caught again!\n");

    /* SIGKILL (9) 和 SIGSTOP (19) 不能被捕获/忽略/阻塞 */
    printf("\nSIGKILL and SIGSTOP cannot be caught or ignored\n");
    return 0;
}

20.3

生命周期

本章：TLPI 第 20 章 — Signals: Fundamental Concepts - 上一节：20.2 编号与分类 - 下一节：20.4 信号掩码与未决集

本节讲什么

  1. 产生 — 内核标记目标 2. 未决（pending） — 已产生但被阻塞，暂不递送 3. 递送 — 中断用户流，执行默认动作或 handler

要点

  1. 产生 — 内核标记目标
  2. 未决（pending） — 已产生但被阻塞，暂不递送
  3. 递送 — 中断用户流，执行默认动作或 handler

递送点：进程从内核态返回用户态前（典型）。不是任意用户指令中间插入。

HFT / 嵌入式关联

路线 要点
嵌入式 生命周期 在嵌入式系统的应用场景
HFT 生命周期 对低延迟和性能的影响

代码示例

#include <signal.h>
#include <unistd.h>
#include <stdio.h>
/* 信号生命周期: 产生 → 未决(pending) → 传递(delivery) → 处理 */
void handler(int sig) { printf("处理信号 %d\n", sig); }
int main(void) {
    sigset_t mask;
    sigemptyset(&mask);
    sigaddset(&mask, SIGINT);
    sigprocmask(SIG_BLOCK, &mask, NULL);  /* 阻塞 SIGINT */
    printf("SIGINT 已阻塞, 发送后处于 pending 状态\n");
    raise(SIGINT);  /* 产生但未传递 (被阻塞) */
    /* 检查是否 pending */
    sigset_t pending;
    sigpending(&pending);
    printf("SIGINT pending: %s\n", sigismember(&pending, SIGINT) ? "YES" : "NO");
    signal(SIGINT, handler);
    printf("解除阻塞 → 信号传递\n");
    sigprocmask(SIG_UNBLOCK, &mask, NULL);  /* 传递 → handler 执行 */
    return 0;
}

20.4

信号掩码与未决集

本章：TLPI 第 20 章 — Signals: Fundamental Concepts - 上一节：20.3 生命周期 - 下一节：20.5 signal() 缺陷（警示）

本节讲什么

掩码中的信号 = 阻塞 → 抵达后进 pending，解除后才递送。 掩码是线程属性；多线程下 sigprocmask 影响当前线程。 int sigemptyset(sigset_t *set);

要点

掩码中的信号 = 阻塞 → 抵达后进 pending，解除后才递送。
掩码是线程属性；多线程下 sigprocmask 影响当前线程。

int sigemptyset(sigset_t *set);
int sigfillset(sigset_t *set);
int sigaddset(sigset_t *set, int sig);
int sigdelset(sigset_t *set, int sig);
int sigismember(const sigset_t *set, int sig);

int sigprocmask(int how, const sigset_t *set, sigset_t *oldset);
/* SIG_BLOCK | SIG_UNBLOCK | SIG_SETMASK */

int sigpending(sigset_t *set);   /* 当前线程未决集 */

sigprocmask how

how 行为
SIG_BLOCK 新掩码 = 旧 ∪ set
SIG_UNBLOCK 新掩码 = 旧 − set
SIG_SETMASK 新掩码 = set

Demo：code/block_pending.c

HFT / 嵌入式关联

路线 要点
嵌入式 信号掩码与未决集 在嵌入式系统的应用场景
HFT 信号掩码与未决集 对低延迟和性能的影响

代码示例

#include <stdio.h>
#include <signal.h>
#include <unistd.h>
/* 信号掩码: 阻塞信号使其变为"待决" */
void handler(int sig) {
    const char *m = "caught!\n";
    write(1, m, 8);
}

int main(void) {
    signal(SIGINT, handler);

    /* 阻塞 SIGINT */
    sigset_t mask, old;
    sigemptyset(&mask);
    sigaddset(&mask, SIGINT);
    sigprocmask(SIG_BLOCK, &mask, &old);
    printf("SIGINT blocked for 3s, try Ctrl+C...\n");

    sleep(3);

    /* 检查待决信号 */
    sigset_t pending;
    sigpending(&pending);
    printf("SIGINT pending: %s\n",
           sigismember(&pending, SIGINT) ? "yes" : "no");

    /* 解除阻塞: 待决信号立即递送 */
    printf("Unblocking...\n");
    sigprocmask(SIG_SETMASK, &old, NULL);
    sleep(1);
    return 0;
}

20.5

`signal()` 缺陷（警示）

本章：TLPI 第 20 章 — Signals: Fundamental Concepts - 上一节：20.4 信号掩码与未决集 - 下一节：20.6 发送信号

本节讲什么

sighandler_t signal(int sig, sighandler_t handler); 跨系统：是否自动复位默认、handler 期间是否阻塞自身等不一致；无附加数据。 ✅ 生产统一 sigaction()（Ch21）。

要点

sighandler_t signal(int sig, sighandler_t handler);

跨系统：是否自动复位默认、handler 期间是否阻塞自身等不一致；无附加数据。
✅ 生产统一 sigaction()（Ch21）。

HFT / 嵌入式关联

路线 要点
嵌入式 signal() 缺陷（警示） 在嵌入式系统的应用场景
HFT signal() 缺陷（警示） 对低延迟和性能的影响

常见陷阱

  1. signal() 不可移植
signal(SIGINT, handler);  /* 行为不一致 */

signal() 在不同系统上行为不一致（是否自动恢复默认、handler 期间是否阻塞自身）。生产代码用 sigaction()。

  1. handler 中调用不安全函数
void handler(int sig) {
    printf("got signal\n");  /* printf 不安全! */
}

printf/malloc 等不是异步信号安全函数。handler 中只能调用异步信号安全函数（如 write）。

  1. 信号竞态
/* 检查标志后处理，但信号可能在此间到达 */
if (flag) { ... }  /* TOCTOU */

信号可能在检查和处理之间到达。需要用 sigprocmask 阻塞信号或用 volatile sig_atomic_t。

自测题

题目 1（选择）： SIGKILL 和 SIGSTOP 的共同特点是？ A. 可以被捕获 B. 可以被忽略 C. 可以被阻塞 D. 都不能被捕获/忽略/阻塞

参考答案

D。SIGKILL 和 SIGSTOP 不能被捕获、忽略或阻塞。这是设计上的保证。

题目 2（判断）： 可以在信号处理函数中安全地调用 printf。

参考答案

错误。printf 不是异步信号安全函数。它使用 stdio 缓冲区和 malloc，在信号处理函数中调用可能导致死锁或数据损坏。用 write 代替。

题目 3（踩坑）： 以下代码有什么问题？

volatile int flag = 0;
void handler(int sig) { flag = 1; }
int main() {
    signal(SIGINT, handler);
    while (!flag) { /* busy wait */ }
    printf("done\n");
}
参考答案

1) signal() 不可移植，应用 sigaction；2) busy wait 浪费 CPU，应用 pause() 或 sigsuspend()；3) printf 在信号后的主循环中调用是安全的，但如果信号在 printf 执行中到来则不安全。

题目 4（应用）： 写代码用 sigaction 捕获 SIGINT 并设置标志。

参考答案 
volatile sig_atomic_t flag = 0;
void handler(int sig) { flag = 1; }
struct sigaction sa = {0};
sa.sa_handler = handler;
sigemptyset(&sa.sa_mask);
sa.sa_flags = SA_RESTART;
sigaction(SIGINT, &sa, NULL);

代码示例

#include <stdio.h>
#include <signal.h>
#include <unistd.h>
/* signal(): 简单但不可移植, 推荐用 sigaction */
static volatile sig_atomic_t flag = 0;

void old_handler(int sig) {
    flag = 1;
}

int main(void) {
    /* signal: 旧接口, 行为因平台而异 */
    void (*old)(int) = signal(SIGUSR1, old_handler);
    printf("old handler was: %p\n", (void *)old);

    raise(SIGUSR1);
    printf("flag = %d\n", flag);

    /* 恢复默认行为 */
    signal(SIGUSR1, SIG_DFL);
    /* 忽略信号 */
    signal(SIGUSR2, SIG_IGN);
    raise(SIGUSR2);  /* 被忽略 */
    printf("SIGUSR2 was ignored\n");
    return 0;
}

#include <unistd.h>

    return 0;
}

20.9

信号集（Signal Sets）

本章：TLPI 第 20 章 — 信号 - 上一节：20.8 显示信号描述 - 下一节：20.10 信号掩码

本节讲什么

sigset_t 类型及 5 个操作函数，用于批量管理信号集合。

要点

数据类型

typedef struct { /* 实现定义，通常 long[] 位图 */ } sigset_t;

操作函数

函数 作用
sigemptyset(&set) 清空（所有 bit = 0）
sigfillset(&set) 填满（所有 bit = 1）
sigaddset(&set, sig) 添加信号 sig
sigdelset(&set, sig) 移除信号 sig
sigismember(&set, sig) 查询 sig 是否在集合中（1/0）

关键约束

  • 必须先 sigemptyset 或 sigfillset 初始化，不能直接 sigaddset
  • sigismember 返回 1（在集合中）/ 0（不在）/ -1（错误）

典型用法

sigset_t set;
sigemptyset(&set);
sigaddset(&set, SIGINT);
sigaddset(&set, SIGTERM);
// 后续用于 sigprocmask() 或 sigaction.sa_mask

HFT / 嵌入式关联

路线 要点
嵌入式 信号集是信号管理的基石，sigprocmask 批量阻塞避免竞态
HFT 临界区前用 sigset_t 批量阻塞信号，事后恢复，保证原子性

代码示例

#include <stdio.h>
#include <signal.h>
/* 信号集操作: sigemptyset/sigaddset/sigismember */
int main(void) {
    sigset_t set;
    sigemptyset(&set);
    sigaddset(&set, SIGINT);
    sigaddset(&set, SIGTERM);
    sigaddset(&set, SIGUSR1);

    printf("SIGINT in set: %d\n", sigismember(&set, SIGINT));   /* 1 */
    printf("SIGKILL in set: %d\n", sigismember(&set, SIGKILL)); /* 0 */

    sigdelset(&set, SIGUSR1);
    printf("SIGUSR1 in set: %d\n", sigismember(&set, SIGUSR1)); /* 0 */

    sigfillset(&set);
    printf("SIGKILL in full set: %d\n", sigismember(&set, SIGKILL)); /* 1 */
    return 0;
}

20.10

信号掩码（阻塞信号传递）

本章：TLPI 第 20 章 — 信号 - 上一节：20.9 信号集 - 下一节：20.11 待处理信号

本节讲什么

sigprocmask() — 阻塞（延迟）信号传递，控制何时处理信号而非是否处理。

要点

核心概念

  • 信号掩码 = 内核为每个进程维护的"被阻塞信号集合"
  • 被阻塞的信号 不会丢失，标记为 pending，解除阻塞后传递
  • SIGKILL 和 SIGSTOP 无法阻塞

sigprocmask API

int sigprocmask(int how, const sigset_t *set, sigset_t *oldset);
how 语义
SIG_BLOCK 掩码 = 旧掩码 ∪ set（添加阻塞）
SIG_UNBLOCK 掩码 = 旧掩码 \ set（解除阻塞）
SIG_SETMASK 掩码 = set（直接替换）

关键模式：临界区保护

sigset_t oldmask, blockset;
sigemptyset(&blockset);
sigaddset(&blockset, SIGINT);
sigprocmask(SIG_BLOCK, &blockset, &oldmask);  /* 进入临界区 */
/* ... 临界区代码 ... */
sigprocmask(SIG_SETMASK, &oldmask, NULL);     /* 退出临界区 */

常见误区

  • 阻塞 ≠ 忽略：阻塞延迟传递，忽略直接丢弃
  • 多线程用 pthread_sigmask，不用 sigprocmask

HFT / 嵌入式关联

路线 要点
嵌入式 临界区保护数据结构一致性，避免信号处理函数重入导致竞态
HFT 订单簿更新期间阻塞 SIGINT，防止处理函数中断热路径

代码示例

#include <stdio.h>
#include <signal.h>
#include <unistd.h>
/* sigprocmask: 阻塞 SIGINT 3 秒后解除 */
int main(void) {
    sigset_t blockset, oldmask;
    sigemptyset(&blockset);
    sigaddset(&blockset, SIGINT);

    sigprocmask(SIG_BLOCK, &blockset, &oldmask);
    printf("SIGINT blocked for 3s, try Ctrl+C...\n");
    sleep(3);

    printf("unblocking SIGINT...\n");
    sigprocmask(SIG_SETMASK, &oldmask, NULL);
    printf("done\n");
    return 0;
}

20.11

待处理信号（Pending Signals）

本章：TLPI 第 20 章 — 信号 - 上一节：20.10 信号掩码 - 下一节：20.12 信号不排队

本节讲什么

sigpending() — 查询哪些信号已被产生但因阻塞而尚未传递。

要点

API

int sigpending(sigset_t *set);
  • 返回当前进程的 pending 信号集（已产生但被阻塞的信号）
  • 仅查询，不修改信号状态

核心行为

  1. 信号产生 → 检查掩码 → 被阻塞 → 标记 pending
  2. 解除阻塞 → pending 信号立即传递
  3. 同类型多次产生 → pending 中只标记一次（标准信号不排队）

典型用法

sigset_t pending;
sigpending(&pending);
if (sigismember(&pending, SIGINT)) {
    printf("SIGINT is pending!\n");
}

HFT / 嵌入式关联

路线 要点
嵌入式 临界区结束后检查 pending，决定是否需要特殊处理
HFT 长时间阻塞后检查 pending 可辅助诊断"丢失"的信号事件

代码示例

#include <stdio.h>
#include <signal.h>
#include <unistd.h>
/* sigpending: 查询被阻塞的待处理信号 */
int main(void) {
    sigset_t blockset, oldmask, pending;
    sigemptyset(&blockset);
    sigaddset(&blockset, SIGUSR1);

    sigprocmask(SIG_BLOCK, &blockset, &oldmask);
    raise(SIGUSR1);  /* 被阻塞, 标记 pending */

    sigpending(&pending);
    if (sigismember(&pending, SIGUSR1)) {
        printf("SIGUSR1 is pending (blocked)\n");
    }

    signal(SIGUSR1, SIG_IGN);  /* 改成忽略避免退出 */
    sigprocmask(SIG_SETMASK, &oldmask, NULL);
    printf("unblocked, SIGUSR1 delivered (ignored)\n");
    return 0;
}

20.12

信号不排队

本章：TLPI 第 20 章 — 信号 - 上一节：20.11 待处理信号 - 下一节：20.13 改变信号处置：sigaction

本节讲什么

标准信号的核心限制：同类型信号多次产生只传递一次。

要点

核心事实

  • 标准信号（1-31）：不排队，pending 集合中每个信号只有一个 bit
  • 实时信号（SIGRTMIN-SIGRTMAX）：可排队，但 API 更复杂
  • 多次发送同一标准信号 → 至少传递一次，不保证次数

后果

场景 行为
阻塞期间收到 3 次 SIGINT 解除后只传递 1 次
多个子进程退出 → SIGCHLD 只处理 1 次 → 可能漏收
用信号做事件计数 不可靠，会丢事件

解决方案

  1. SIGCHLD → waitpid(-1, &st, WNOHANG) 循环回收
  2. 事件计数 → 管道/eventfd，不用信号
  3. 实时信号 + sigqueue → 可排队

典型陷阱

/* 错误: 依赖信号计数 */
void handler(int sig) { child_count++; }  /* 可能丢失! */

/* 正确: handler 中循环 waitpid */
void handler(int sig) {
    while (waitpid(-1, NULL, WNOHANG) > 0) { }
}

HFT / 嵌入式关联

路线 要点
嵌入式 子进程管理必须用 waitpid 循环，不能靠信号计数
HFT 绝不用信号传递行情事件（会丢），用共享内存/管道/eventfd

代码示例

#include <stdio.h>
#include <signal.h>
#include <string.h>
/* 信号不排队: 多次发送只收到一次 */
volatile sig_atomic_t count = 0;
void handler(int sig) { count++; }

int main(void) {
    struct sigaction sa;
    memset(&sa, 0, sizeof(sa));
    sa.sa_handler = handler;
    sigaction(SIGUSR1, &sa, NULL);

    sigset_t blockset, oldmask;
    sigemptyset(&blockset);
    sigaddset(&blockset, SIGUSR1);
    sigprocmask(SIG_BLOCK, &blockset, &oldmask);

    for (int i = 0; i < 5; i++) raise(SIGUSR1);

    sigprocmask(SIG_SETMASK, &oldmask, NULL);
    printf("sent 5 signals, received %d\n", count); /* count == 1 */
    return 0;
}

20.13

改变信号处置：sigaction()

本章：TLPI 第 20 章 — 信号 - 上一节：20.12 信号不排队 - 下一节：20.14 等待信号：pause

本节讲什么

sigaction() — POSIX 标准的信号处置设置接口，替代不可移植的 signal()。

要点

结构体

struct sigaction {
    void     (*sa_handler)(int);          /* 简单处理函数 */
    void     (*sa_sigaction)(int, siginfo_t *, void *);  /* 扩展处理函数 */
    sigset_t   sa_mask;    /* 处理期间额外阻塞的信号集 */
    int        sa_flags;   /* 控制行为 */
};

sa_flags 常用值

flag 含义
0 使用 sa_handler，默认语义
SA_RESTART 被信号中断的系统调用自动重启
SA_SIGINFO 使用 sa_sigaction（带 siginfo_t 详情）
SA_NOCLDSTOP SIGCHLD 仅在子进程终止时发
SA_RESETHAND 信号传递后重置为 SIG_DFL（一次性）

sigaction vs signal

signal() sigaction()
可移植性 行为不一致（BSD vs SysV） POSIX 标准
SA_RESTART 不支持 支持
sa_mask 不支持 支持
SA_SIGINFO 不支持 支持
结论 不要用 永远用 sigaction

典型用法

struct sigaction sa;
memset(&sa, 0, sizeof(sa));
sa.sa_handler = handler;
sigemptyset(&sa.sa_mask);
sa.sa_flags = SA_RESTART;
sigaction(SIGINT, &sa, NULL);

HFT / 嵌入式关联

路线 要点
嵌入式 SA_RESTART 避免信号中断 read/write 后手动重试
HFT SA_SIGINFO 可获取信号来源 PID，用于审计

代码示例

#include <stdio.h>
#include <signal.h>
#include <string.h>
#include <unistd.h>
/* sigaction: 三种处置方式 */
void handler(int sig) { printf("caught SIGUSR1\n"); }
void handler_info(int sig, siginfo_t *si, void *ctx) {
    printf("caught %d from pid=%d\n", sig, si->si_pid);
}

int main(void) {
    struct sigaction sa;

    /* 1. 简单 handler + SA_RESTART */
    memset(&sa, 0, sizeof(sa));
    sa.sa_handler = handler;
    sigemptyset(&sa.sa_mask);
    sa.sa_flags = SA_RESTART;
    sigaction(SIGUSR1, &sa, NULL);

    /* 2. SA_SIGINFO: 获取发送者信息 */
    memset(&sa, 0, sizeof(sa));
    sa.sa_sigaction = handler_info;
    sigemptyset(&sa.sa_mask);
    sa.sa_flags = SA_SIGINFO;
    sigaction(SIGUSR2, &sa, NULL);

    raise(SIGUSR1);
    raise(SIGUSR2);
    printf("handlers done\n");
    return 0;
}

20.14

等待信号：pause()

本章：TLPI 第 20 章 — 信号 - 上一节：20.13 改变信号处置：sigaction - 下一节：20.15 总结

本节讲什么

pause() — 最简单的"等待信号"原语，以及它固有的竞态问题。

要点

pause() 行为

int pause(void);  /* 总是返回 -1, errno = EINTR */
  • 挂起进程直到被信号中断
  • 信号被忽略或被掩码阻塞时，pause 不会被唤醒

竞态条件（核心问题）

/* 有 bug 的代码 */
if (ready == 0) {
    /* 如果在 if 和 pause 之间信号到达并处理了,
       ready 变为 1, 但 pause 仍然会永远阻塞! */
    pause();  /* ← 竞态! */
}

正确的替代方案

方案 函数 优势
sigsuspend sigsuspend(&mask) 原子地"解除阻塞 + 等待"
ppoll/pselect ppoll(..., &sigmask) 带超时的原子等待
sigwaitinfo sigwaitinfo(&set, &info) 同步等待，不跑 handler

关键结论

  • 生产代码不要用 pause()，用 sigsuspend() 替代（见 22.9 节）

HFT / 嵌入式关联

路线 要点
嵌入式 简单等待场景可用 pause，但生产代码用 sigsuspend
HFT 绝不用 pause — 竞态不可接受，用 sigwaitinfo 或 self-pipe

代码示例

#include <stdio.h>
#include <signal.h>
#include <unistd.h>
/* pause: 等待信号（演示，生产代码用 sigsuspend） */
volatile sig_atomic_t got_signal = 0;
void handler(int sig) { got_signal = 1; }

int main(void) {
    struct sigaction sa;
    sa.sa_handler = handler;
    sigemptyset(&sa.sa_mask);
    sa.sa_flags = 0;
    sigaction(SIGINT, &sa, NULL);

    printf("waiting for Ctrl+C...\n");
    if (!got_signal) {
        pause();  /* 等待信号 */
    }
    printf("signal received, got_signal=%d\n", got_signal);
    return 0;
}
/* 注意: 有竞态 — SIGINT 在 if 和 pause 之间到达,
   pause 会永远阻塞。正确做法见 22.9 sigsuspend。 */

代码自测

1. 为什么 signal() 不如 sigaction() 安全？

signal() 的行为在不同 UNIX 实现中不一致：BSD 语义会自动重置处置，SysV 语义不会。sigaction() 是 POSIX 标准，行为一致，且支持 SA_RESTART、sa_mask 等高级功能。

2. 标准信号不排队有什么实际后果？

阻塞期间多次发送同一信号，解除后只传递一次。SIGCHLD 场景下可能漏收子进程退出状态，必须在 handler 中用 while (waitpid(-1, &st, WNOHANG) > 0) 循环回收。

练习题

本章：TLPI 第 20 章 — 信号

本节讲什么

原书第 20 章练习题要点。

1. 实现 sigHandler 包装函数，在调用真实 handler 前保存/恢复 errno 
void sigHandlerWrapper(int sig, void (*realHandler)(int)) {
    int saved_errno = errno;
    realHandler(sig);
    errno = saved_errno;
}

原因：信号处理函数中调用函数可能修改 errno，覆盖被中断代码的 errno 值。

2. 为什么不能用 printf 在信号处理函数中输出？

printf 是非异步信号安全函数：它使用内部缓冲区和锁，如果信号中断了主线程的 printf，handler 中再调 printf 会导致死锁或缓冲区损坏。替代方案：write(STDOUT_FILENO, ...) + 预格式化字符串。

3. 实现一个安全的 sleep 函数，使用 nanosleep 并处理信号中断 
int safe_sleep(unsigned int seconds) {
    struct timespec req = { .tv_sec = seconds, .tv_nsec = 0 };
    struct timespec rem;
    while (nanosleep(&req, &rem) == -1 && errno == EINTR) {
        req = rem;  /* 被信号中断，继续睡剩余时间 */
    }
    return 0;
}
