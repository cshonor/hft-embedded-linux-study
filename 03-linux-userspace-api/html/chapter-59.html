59.2

网络字节序

本章：TLPI 第 59 章 — Internet 域 Socket - 上一节：59.1 Internet 域 Socket 概述 - 下一节：59.3 数据表示

本节讲什么

网络字节序（大端）与主机字节序的转换。

要点

字节序

字节序 说明 典型架构
大端 (Big-endian) 高位字节在低地址 网络协议、SPARC、Motorola
小端 (Little-endian) 低位字节在低地址 x86/x64、ARM (默认)

转换函数

函数 作用
htonl(uint32_t) 主机 → 网络 (32 位)
htons(uint16_t) 主机 → 网络 (16 位)
ntohl(uint32_t) 网络 → 主机 (32 位)
ntohs(uint16_t) 网络 → 主机 (16 位)

核心规则

  • 网络传输的所有多字节整数必须用网络字节序（大端）
  • IP 地址、端口号都需要转换
  • h = host, n = network, l = long (32-bit), s = short (16-bit)

HFT / 嵌入式关联

路线 要点
嵌入式 ARM 可配置大小端，跨平台代码必须用 htons/htonl
HFT x86 上 htonl 无指令开销（编译器优化为 bswap）

代码示例

#include <stdio.h>
#include <arpa/inet.h>
/* 网络字节序转换 */
int main(void) {
    uint16_t port = 0x1234;
    uint32_t addr = 0x12345678;

    printf("host:     port=0x%04x, addr=0x%08x\n", port, addr);
    printf("network:  port=0x%04x, addr=0x%08x\n",
           htons(port), htonl(addr));
    printf("back:     port=0x%04x, addr=0x%08x\n",
           ntohs(htons(port)), ntohl(htonl(addr)));

    /* 大端机器上 htons 返回值不变 */
    /* 小端机器上 htons 交换字节 */
    return 0;
}

59.3

数据表示

本章：TLPI 第 59 章 — Internet 域 Socket - 上一节：59.2 网络字节序 - 下一节：59.4 sockaddr_in 结构

本节讲什么

跨平台网络数据传输的表示问题：不同架构的整数大小、对齐、浮点格式差异。

要点

问题来源

差异 例子
整数大小 int 在 ILP32 是 32 位，LP64 是 64 位
字节序 x86 小端，SPARC 大端
结构体对齐 #pragma pack 不同
浮点 几乎都是 IEEE 754，但非保证

解决方案

方案 适用场景
文本协议 (HTTP, SMTP) 通用、可调试，但解析慢
固定宽度整数 (uint32_t) 二进制协议标准做法
序列化框架 (protobuf) 复杂结构
TLV (Type-Length-Value) 灵活可扩展

二进制协议最佳实践

/* 用固定宽度类型, 明确字节序 */
struct msg {
    uint32_t magic;      /* 固定 magic number */
    uint16_t version;    /* 协议版本 */
    uint16_t type;       /* 消息类型 */
    uint32_t length;     /* payload 长度 */
    /* payload follows */
};
/* 所有字段用 htonl/htons 转换后发送 */

常见陷阱

  • 不要直接 send(struct, sizeof(struct)) — 对齐和字节序不可控
  • 不要用 int/long — 用 uint32_t/uint64_t
  • 浮点数用文本传输或自定义编码

HFT / 嵌入式关联

路线 要点
嵌入式 ARM + x86 混合通信必须统一二进制格式
HFT 二进制协议 + 固定宽度类型 + 零拷贝解析，延迟最低

代码示例

#include <stdio.h>
#include <stdint.h>
#include <string.h>
#include <arpa/inet.h>
/* 二进制数据表示: 固定宽度 + 网络字节序 */
struct msg_hdr {
    uint32_t magic;
    uint16_t version;
    uint16_t type;
    uint32_t length;
};

int main(void) {
    /* 构造消息头 */
    struct msg_hdr hdr = {
        .magic = 0x4D474348,  /* "MGCH" */
        .version = 1,
        .type = 2,
        .length = 100
    };

    /* 序列化: 转为网络字节序 */
    uint32_t net_magic = htonl(hdr.magic);
    uint16_t net_ver = htons(hdr.version);
    uint16_t net_type = htons(hdr.type);
    uint32_t net_len = htonl(hdr.length);

    /* 发送时直接 send(&net_xxx, sizeof) */
    printf("serialized: magic=0x%08x ver=%d type=%d len=%d\n",
           net_magic, net_ver, net_type, net_len);

    /* 接收端反序列化 */
    hdr.magic = ntohl(net_magic);
    hdr.version = ntohs(net_ver);
    hdr.type = ntohs(net_type);
    hdr.length = ntohl(net_len);
    printf("deserialized: magic=0x%08x ver=%d type=%d len=%d\n",
           hdr.magic, hdr.version, hdr.type, hdr.length);
    return 0;
}

59.5

主机与服务转换概览

本章：TLPI 第 59 章 — Internet 域 Socket - 上一节：59.4 sockaddr_in 结构 - 下一节：59.6 inet_pton/inet_ntop

本节讲什么

主机名 ↔ IP 地址、服务名 ↔ 端口号的转换 API 概览。

要点

两类转换

转换 新 API 旧 API
主机名 ↔ IP getaddrinfo / getnameinfo gethostbyname / gethostbyaddr
服务名 ↔ 端口 getaddrinfo / getnameinfo getservbyname / getservbyport

旧 API 的问题

旧 API 问题
gethostbyname 不支持 IPv6
gethostbyaddr 不可重入（静态缓冲区）
getservbyname 不可重入

新 API: getaddrinfo / getnameinfo

特性 优势
IPv4 + IPv6 协议无关
可重入 线程安全
替代多个旧函数 一个函数搞定

getaddrinfo 流程

主机名 + 服务名 → getaddrinfo → sockaddr 结构链表

getnameinfo 流程

sockaddr 结构 → getnameinfo → 主机名 + 服务名字符串

HFT / 嵌入式关联

路线 要点
嵌入式 getaddrinfo 可重入，适合多线程环境
HFT 启动时解析地址一次，运行时直接用 sockaddr，避免 DNS 查询延迟

代码示例

#include <stdio.h>
#include <netdb.h>
#include <string.h>
/* getaddrinfo: 主机名+服务名 → sockaddr */
int main(void) {
    struct addrinfo hints, *res;
    memset(&hints, 0, sizeof(hints));
    hints.ai_family = AF_UNSPEC;      /* IPv4 或 IPv6 */
    hints.ai_socktype = SOCK_STREAM;  /* TCP */

    int err = getaddrinfo("localhost", "80", &hints, &res);
    if (err) {
        fprintf(stderr, "getaddrinfo: %s\n", gai_strerror(err));
        return 1;
    }

    /* 遍历所有结果 */
    for (struct addrinfo *p = res; p; p = p->ai_next) {
        char host[NI_MAXHOST], serv[NI_MAXSERV];
        getnameinfo(p->ai_addr, p->ai_addrlen,
                    host, sizeof(host),
                    serv, sizeof(serv),
                    NI_NUMERICHOST | NI_NUMERICSERV);
        printf("addr: %s:%s (family=%d)\n", host, serv, p->ai_family);
    }

    freeaddrinfo(res);
    return 0;
}

59.6

inet_pton() 和 inet_ntop()

本章：TLPI 第 59 章 — Internet 域 Socket - 上一节：59.5 主机与服务转换概览 - 下一节：59.7 getaddrinfo

本节讲什么

inet_pton() / inet_ntop() — IP 地址的点分字符串与二进制格式互转。

要点

API

/* 字符串 → 二进制 */
int inet_pton(int af, const char *src, void *dst);
/* 成功返回 1, src 格式错误返回 0, 错误返回 -1 */

/* 二进制 → 字符串 */
const char *inet_ntop(int af, const void *src, char *dst, socklen_t size);
/* 成功返回 dst 指针, 错误返回 NULL */

与旧函数的对比

旧 API 新 API
IPv4 inet_addr, inet_ntoa inet_pton(AF_INET), inet_ntop(AF_INET)
IPv6 不支持 inet_pton(AF_INET6), inet_ntop(AF_INET6)
线程安全 inet_ntoa 不安全 安全（调用者提供缓冲区）

使用场景

场景 函数
命令行输入 IP → sockaddr inet_pton
sockaddr → 打印 IP inet_ntop
主机名解析 getaddrinfo（非 inet_pton）

注意事项

  • inet_pton 不做 DNS 查询，只解析点分 IP 字符串
  • inet_ntop 的 dst 缓冲区需足够大：IPv4 ≥ 16 字节，IPv6 ≥ 46 字节
  • inet_addr 已废弃（不支持 IPv6 + 返回 INADDR_NONE 有歧义）

HFT / 嵌入式关联

路线 要点
嵌入式 inet_pton 简单高效，无 DNS 查询开销
HFT 启动时用 inet_pton 解析配置 IP，运行时直接用二进制格式

代码示例

#include <stdio.h>
#include <arpa/inet.h>
/* inet_pton / inet_ntop: IP 地址字符串与二进制互转 */
int main(void) {
    /* IPv4 */
    struct in_addr addr4;
    if (inet_pton(AF_INET, "192.168.1.1", &addr4) == 1) {
        printf("IPv4 binary: 0x%08x\n", ntohl(addr4.s_addr));
        char str[INET_ADDRSTRLEN];
        inet_ntop(AF_INET, &addr4, str, sizeof(str));
        printf("IPv4 string: %s\n", str);
    }

    /* IPv6 */
    struct in6_addr addr6;
    if (inet_pton(AF_INET6, "::1", &addr6) == 1) {
        char str6[INET6_ADDRSTRLEN];
        inet_ntop(AF_INET6, &addr6, str6, sizeof(str6));
        printf("IPv6 string: %s\n", str6);
    }

    /* 错误格式 */
    if (inet_pton(AF_INET, "999.999.999.999", &addr4) == 0) {
        printf("invalid address format\n");
    }
    return 0;
}

59.9

/etc/services 文件

本章：TLPI 第 59 章 — Internet 域 Socket - 上一节：59.8 getnameinfo - 下一节：59.10 协议无关转换

本节讲什么

/etc/services — 服务名与端口号的映射文件。

要点

文件格式

# 服务名    端口/协议    别名
http        80/tcp       www www-http
https       443/tcp
ssh         22/tcp
domain      53/tcp       nameserver
domain      53/udp

查询方式

方式 函数
服务名 → 端口 getservbyname("http", "tcp")
端口 → 服务名 getservbyport(80, "tcp")
getaddrinfo getaddrinfo(host, "http", ...) 内部查询

注意事项

  • /etc/services 是本地文件，可能过时或不完整
  • 新服务（如自定义端口）需手动添加
  • 生产环境建议直接用端口号，不依赖此文件
  • getservbyname 不可重入（有 _r 版本）

HFT / 嵌入式关联

路线 要点
嵌入式 嵌入式系统可能没有 /etc/services，直接用端口号
HFT 直接用数字端口号，避免文件查询开销

代码示例

#include <stdio.h>
#include <netdb.h>
/* /etc/services 查询: getservbyname / getservbyport */
int main(void) {
    /* 服务名 → 端口 */
    struct servent *s = getservbyname("http", "tcp");
    if (s) {
        printf("http/tcp: port %d\n", ntohs(s->s_port));
    }

    s = getservbyname("ssh", "tcp");
    if (s) {
        printf("ssh/tcp: port %d\n", ntohs(s->s_port));
    }

    /* 端口 → 服务名 */
    s = getservbyport(htons(443), "tcp");
    if (s) {
        printf("port 443/tcp: %s\n", s->s_name);
    }
    return 0;
}

59.10

协议无关的主机与服务转换

本章：TLPI 第 59 章 — Internet 域 Socket - 上一节：59.9 /etc/services - 下一节：59.11 客户端-服务端示例

本节讲什么

getaddrinfo + getnameinfo 实现协议无关（IPv4/IPv6）的网络编程。

要点

协议无关的核心思想

  • 代码不硬编码 IPv4 (sockaddr_in) 或 IPv6 (sockaddr_in6)
  • 用 sockaddr_storage 通用结构存储地址
  • getaddrinfo 返回的 addrinfo 链表可遍历尝试

getaddrinfo hints 设置

hints 字段 推荐值 含义
ai_family AF_UNSPEC IPv4 或 IPv6 都行
ai_socktype SOCK_STREAM TCP
ai_flags AI_PASSIVE 服务端 bind 用（host=NULL 时）

服务端绑定模式

struct addrinfo hints = {
    .ai_family = AF_UNSPEC,
    .ai_socktype = SOCK_STREAM,
    .ai_flags = AI_PASSIVE,
};
struct addrinfo *res;
getaddrinfo(NULL, "8080", &hints, &res);

for (struct addrinfo *p = res; p; p = p->ai_next) {
    int fd = socket(p->ai_family, p->ai_socktype, p->ai_protocol);
    if (bind(fd, p->ai_addr, p->ai_addrlen) == 0) {
        listen(fd, 5);
        break;  /* 成功绑定 */
    }
    close(fd);
}

客户端连接模式

struct addrinfo hints = {
    .ai_family = AF_UNSPEC,
    .ai_socktype = SOCK_STREAM,
};
struct addrinfo *res;
getaddrinfo("example.com", "80", &hints, &res);

for (struct addrinfo *p = res; p; p = p->ai_next) {
    int fd = socket(p->ai_family, p->ai_socktype, p->ai_protocol);
    if (connect(fd, p->ai_addr, p->ai_addrlen) == 0) break;
    close(fd);
}

HFT / 嵌入式关联

路线 要点
嵌入式 AF_UNSPEC 让代码同时支持 IPv4/IPv6，面向未来
HFT 启动时解析一次，选择最优地址（IPv6 优先或延迟最低）

代码示例

#include <stdio.h>
#include <netdb.h>
#include <string.h>
#include <sys/socket.h>
#include <unistd.h>
/* 协议无关: getaddrinfo 遍历 IPv4+IPv6 */
int main(void) {
    struct addrinfo hints, *res;
    memset(&hints, 0, sizeof(hints));
    hints.ai_family = AF_UNSPEC;
    hints.ai_socktype = SOCK_STREAM;

    int err = getaddrinfo("localhost", "daytime", &hints, &res);
    if (err) { fprintf(stderr, "%s\n", gai_strerror(err)); return 1; }

    for (struct addrinfo *p = res; p; p = p->ai_next) {
        char host[NI_MAXHOST], serv[NI_MAXSERV];
        getnameinfo(p->ai_addr, p->ai_addrlen,
                    host, sizeof(host), serv, sizeof(serv),
                    NI_NUMERICHOST | NI_NUMERICSERV);
        printf("family=%d, %s:%s\n", p->ai_family, host, serv);

        /* 尝试连接 */
        int fd = socket(p->ai_family, p->ai_socktype, p->ai_protocol);
        if (connect(fd, p->ai_addr, p->ai_addrlen) == 0) {
            char buf[256];
            ssize_t n = read(fd, buf, sizeof(buf)-1);
            if (n > 0) { buf[n] = 0; printf("  → %s", buf); }
            close(fd);
            break;
        }
        close(fd);
    }
    freeaddrinfo(res);
    return 0;
}

59.11

流式 Socket 客户端-服务端示例

本章：TLPI 第 59 章 — Internet 域 Socket - 上一节：59.10 协议无关转换 - 下一节：59.12 Internet Socket 库

本节讲什么

一个完整的 TCP 客户端-服务端示例，展示 Internet 域 socket 的完整流程。

要点

服务端流程

socket → bind → listen → accept → read/write → close

客户端流程

socket → connect → read/write → close

关键 API 串联

步骤 服务端 客户端
创建 socket(AF_INET, SOCK_STREAM, 0) 同左
地址 bind(fd, &addr, len) connect(fd, &addr, len)
监听 listen(fd, backlog) —
接受 accept(fd, &cli, &len) —
通信 read/write read/write

常见错误

错误 原因
bind EADDRINUSE 端口被占用（加 SO_REUSEADDR）
connect ECONNREFUSED 服务端未运行
accept EINTR 被信号中断（SA_RESTART 或手动重试）

HFT / 嵌入式关联

路线 要点
嵌入式 TCP 保证可靠传输，适合嵌入式远程管理
HFT TCP 有 Nagle 延迟，设 TCP_NODELAY；或用 UDP/共享内存

代码示例

#include <stdio.h>
#include <string.h>
#include <unistd.h>
#include <arpa/inet.h>
#include <sys/socket.h>
#include <sys/wait.h>
/* TCP echo 服务端 + 客户端 */
#define PORT 9999

int main(void) {
    pid_t pid = fork();
    if (pid == 0) {
        /* 服务端 */
        int sfd = socket(AF_INET, SOCK_STREAM, 0);
        struct sockaddr_in addr = {
            .sin_family = AF_INET,
            .sin_port = htons(PORT),
            .sin_addr.s_addr = INADDR_ANY,
        };
        int opt = 1;
        setsockopt(sfd, SOL_SOCKET, SO_REUSEADDR, &opt, sizeof(opt));
        bind(sfd, (struct sockaddr *)&addr, sizeof(addr));
        listen(sfd, 5);

        struct sockaddr_in cli;
        socklen_t clen = sizeof(cli);
        int cfd = accept(sfd, (struct sockaddr *)&cli, &clen);
        char buf[64];
        ssize_t n = read(cfd, buf, sizeof(buf)-1);
        if (n > 0) { buf[n] = 0; printf("server recv: %s\n", buf); }
        write(cfd, "ack", 3);
        close(cfd); close(sfd);
        _exit(0);
    }

    sleep(1);  /* 等服务端启动 */
    /* 客户端 */
    int fd = socket(AF_INET, SOCK_STREAM, 0);
    struct sockaddr_in addr = {
        .sin_family = AF_INET,
        .sin_port = htons(PORT),
    };
    inet_pton(AF_INET, "127.0.0.1", &addr.sin_addr);
    connect(fd, (struct sockaddr *)&addr, sizeof(addr));
    write(fd, "hello", 5);

    char buf[64] = {0};
    read(fd, buf, sizeof(buf));
    printf("client recv: %s\n", buf);
    close(fd);
    wait(NULL);
    return 0;
}

Internet 域 Socket 库

本章：TLPI 第 59 章 — Internet 域 Socket - 上一节：59.11 客户端-服务端示例 - 下一节：59.13 并发服务端

本节讲什么

封装 Internet 域 socket 的常用函数库，简化服务端/客户端代码。

要点

设计目标

  • 封装 getaddrinfo + socket + bind/connect 流程
  • 协议无关（IPv4/IPv6 自动适配）
  • 错误处理统一

典型封装函数

函数 作用
inetListen(port, backlog, &addr) 服务端: socket+bind+listen
inetConnect(host, port, type) 客户端: socket+connect
inetBind(port, type, &addr) UDP: socket+bind

封装优势

  • 消除重复代码（每次写 getaddrinfo 链很繁琐）
  • 统一错误处理
  • 协议无关，自动适配

使用示例

/* 服务端 */
int lfd = inetListen("8080", 5, NULL);
int cfd = accept(lfd, NULL, NULL);

/* 客户端 */
int fd = inetConnect("localhost", "8080", SOCK_STREAM);

HFT / 嵌入式关联

路线 要点
嵌入式 封装库减少重复代码，适合资源有限的团队
HFT 封装需注意避免隐藏选项（如 TCP_NODELAY），保留 setsockopt 接口

代码示例

#include <stdio.h>
#include <string.h>
#include <netdb.h>
#include <unistd.h>
#include <sys/socket.h>
/* 简化版 inetListen + inetConnect 封装 */
int inetListen(const char *port, int backlog) {
    struct addrinfo hints, *res;
    memset(&hints, 0, sizeof(hints));
    hints.ai_family = AF_UNSPEC;
    hints.ai_socktype = SOCK_STREAM;
    hints.ai_flags = AI_PASSIVE;

    if (getaddrinfo(NULL, port, &hints, &res)) return -1;

    int fd = -1;
    for (struct addrinfo *p = res; p; p = p->ai_next) {
        fd = socket(p->ai_family, p->ai_socktype, p->ai_protocol);
        if (fd < 0) continue;
        int opt = 1;
        setsockopt(fd, SOL_SOCKET, SO_REUSEADDR, &opt, sizeof(opt));
        if (bind(fd, p->ai_addr, p->ai_addrlen) == 0 &&
            listen(fd, backlog) == 0) break;
        close(fd); fd = -1;
    }
    freeaddrinfo(res);
    return fd;
}

int inetConnect(const char *host, const char *port) {
    struct addrinfo hints, *res;
    memset(&hints, 0, sizeof(hints));
    hints.ai_family = AF_UNSPEC;
    hints.ai_socktype = SOCK_STREAM;

    if (getaddrinfo(host, port, &hints, &res)) return -1;

    int fd = -1;
    for (struct addrinfo *p = res; p; p = p->ai_next) {
        fd = socket(p->ai_family, p->ai_socktype, p->ai_protocol);
        if (fd < 0) continue;
        if (connect(fd, p->ai_addr, p->ai_addrlen) == 0) break;
        close(fd); fd = -1;
    }
    freeaddrinfo(res);
    return fd;
}

UNIX 域 vs Internet 域 Socket

本章：TLPI 第 59 章 — Internet 域 Socket - 上一节：59.13 并发服务端 - 下一节：59.15 进一步信息

本节讲什么

UNIX 域 socket 与 Internet 域 socket 的对比和选型。

要点

对比表

维度 UNIX 域 (AF_UNIX) Internet 域 (AF_INET)
范围 本机 跨主机
地址 文件路径 IP + 端口
性能 更快（无网络栈） 较慢（TCP/IP 栈）
权限 文件系统权限 无内置权限控制
连接管理 无 TIME_WAIT 有 TIME_WAIT
数据拷贝 可零拷贝（SCM_RIGHTS） 需拷贝

性能差异

  • UNIX 域 socket 比 TCP 快 2-3 倍（无网络栈开销）
  • 大块数据传输差异更明显
  • UNIX 域 socket 支持 SCM_RIGHTS 传递 fd（零拷贝）

何时用 UNIX 域

  • 本机进程间通信（如 Docker daemon, X11）
  • 需要文件系统权限控制
  • 性能敏感场景
  • 需要传递 fd

何时用 Internet 域

  • 跨主机通信
  • 客户端分布在不同机器
  • 需要标准网络协议

HFT / 嵌入式关联

路线 要点
嵌入式 本机组件间通信用 UNIX 域更快更安全
HFT 行情网关用 TCP 接收，内部组件间用 UNIX 域或共享内存

代码示例

#include <stdio.h>
#include <string.h>
#include <unistd.h>
#include <sys/socket.h>
#include <sys/un.h>
#include <sys/wait.h>
/* UNIX 域 socket echo */
#define PATH "/tmp/test_unix_sock"

int main(void) {
    pid_t pid = fork();
    if (pid == 0) {
        /* 服务端 */
        int sfd = socket(AF_UNIX, SOCK_STREAM, 0);
        struct sockaddr_un addr = { .sun_family = AF_UNIX };
        strcpy(addr.sun_path, PATH);
        unlink(PATH);
        bind(sfd, (struct sockaddr *)&addr, sizeof(addr));
        listen(sfd, 5);
        int cfd = accept(sfd, NULL, NULL);
        char buf[64];
        ssize_t n = read(cfd, buf, sizeof(buf)-1);
        if (n > 0) { buf[n] = 0; printf("server: %s\n", buf); }
        close(cfd); close(sfd); unlink(PATH);
        _exit(0);
    }

    usleep(100000);
    /* 客户端 */
    int fd = socket(AF_UNIX, SOCK_STREAM, 0);
    struct sockaddr_un addr = { .sun_family = AF_UNIX };
    strcpy(addr.sun_path, PATH);
    connect(fd, (struct sockaddr *)&addr, sizeof(addr));
    write(fd, "hello unix", 10);
    close(fd);
    wait(NULL);
    return 0;
}

代码自测

1. 为什么 getaddrinfo 比 gethostbyname 好？

getaddrinfo 支持 IPv6、线程安全（可重入）、一个函数替代多个旧函数（gethostbyname + getservbyname）。gethostbyname 只支持 IPv4 且使用静态缓冲区，不可重入。

2. inet_pton 和 getaddrinfo 的区别？

inet_pton 只将点分 IP 字符串转为二进制，不做 DNS 查询。getaddrinfo 解析主机名（可触发 DNS 查询）并返回完整的 sockaddr 结构链表，支持服务名到端口的转换。

练习题

本章：TLPI 第 59 章 — Internet 域 Socket

本节讲什么

原书第 59 章练习题要点。

1. 为什么 bind 失败时应该设 SO_REUSEADDR？

TCP 连接关闭后，端口进入 TIME_WAIT 状态（持续 2*MSL ≈ 60 秒）。在此期间 bind 同一端口会失败（EADDRINUSE）。SO_REUSEADDR 允许绑定处于 TIME_WAIT 的端口，使服务端能快速重启。

2. 如何让代码同时支持 IPv4 和 IPv6？
  1. 用 getaddrinfo + AF_UNSPEC 获取所有地址
  2. 遍历结果链表，尝试 socket + bind/connect
  3. 用 sockaddr_storage 通用结构存储地址
  4. 不硬编码 sockaddr_in，用 sockaddr * 通用指针
3. connect 失败时应该怎么处理？

遍历 getaddrinfo 返回的链表，对每个地址尝试 socket + connect，成功则停止。一个主机可能有多个 IP（如 IPv4 + IPv6），某个 IP 连接失败不代表全部失败。
