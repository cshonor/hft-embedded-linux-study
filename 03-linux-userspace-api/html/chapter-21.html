导读

章节目标

用 sigaction 注册处理器；理解 sa_mask 与 SA_*；严守 async-signal-safe；处理 EINTR / SA_RESTART；安全处理 SIGCHLD。

21.8 易错清单

  1. sa_mask 叠加，不替换；退出即撤
  2. SA_NODEFER → 易递归
  3. EINTR 合法，别当致命
  4. 标志用 volatile sig_atomic_t
  5. handler 禁 printf/malloc
  6. 实时信号 + sigqueue 需 SA_SIGINFO
  7. 多线程：信号交给未阻塞该信号的某线程

练习

  1. sigaction + sa_mask
  2. 开关 SA_RESTART 看 read/EINTR
  3. SA_SIGINFO 打印发送者 pid
  4. sig_atomic_t 主循环范式
  5. SIGCHLD 循环 waitpid

背诵卡

# 要点
1 用 sigaction，不用 signal
2 handler 期间：自动阻本信号 + sa_mask
3 只设 volatile sig_atomic_t；禁非 async-safe
4 处理 EINTR；SA_RESTART 非万能
5 SIGCHLD：循环 WNOHANG 或 SA_NOCLDWAIT
6 SA_SIGINFO 才拿得到 siginfo_t / 队列数据

参考

  • Kerrisk · TLPI Ch21
  • man 2 sigaction · man 7 signal-safety · man 2 waitpid

代码示例

#include <stdio.h>
#include <signal.h>
#include <string.h>
#include <unistd.h>

/* Ch21 信号处理器 — sigaction（替代可移植性差的 signal）。
 * 演示 sigaction 注册 + 信号信息获取。
 * 编译: gcc -o ch21_demo ch21_demo.c */

static volatile sig_atomic_t count = 0;

void handler(int sig, siginfo_t *info, void *ctx) {
    count++;
    /* 注意: printf 不是异步信号安全函数，这里仅做演示 */
    const char *msg = "caught SIGINT\n";
    write(STDOUT_FILENO, msg, strlen(msg));
}

int main(void) {
    struct sigaction sa;
    memset(&sa, 0, sizeof(sa));
    sa.sa_sigaction = handler;
    sa.sa_flags = SA_SIGINFO;
    sigemptyset(&sa.sa_mask);

    /* sigaction 比 signal 更可移植、更强大 */
    if (sigaction(SIGINT, &sa, NULL) < 0) {
        perror("sigaction");
        return 1;
    }

    printf("Press Ctrl+C to test (will catch 3 times then exit)\n");
    printf("Or run: kill -INT %d\n", (int)getpid());

    while (count < 3) {
        pause();  /* 等待信号 */
    }
    printf("Caught %d signals, exiting.\n", count);
    return 0;
}

21.1

`sigaction()`

本章：TLPI 第 21 章 — Signals: Signal Handlers - 上一节：本章首页 - 下一节：21.2 sa_mask（临时叠加）

本节讲什么

include int sigaction(int sig, const struct sigaction act, struct sigaction oldact); 不能用于 SIGKILL / SIGSTOP。act/oldact 可为 NULL。

要点

#include <signal.h>
int sigaction(int sig, const struct sigaction *act, struct sigaction *oldact);

不能用于 SIGKILL / SIGSTOP。act/oldact 可为 NULL。

struct sigaction {
    void (*sa_handler)(int);                          /* 或 */
    void (*sa_sigaction)(int, siginfo_t *, void *); /* 需 SA_SIGINFO */
    sigset_t sa_mask;
    int sa_flags;
};
形式 用途
sa_handler 仅信号编号；可赋 SIG_DFL / SIG_IGN
sa_sigaction + SA_SIGINFO siginfo_t（pid/uid/来源/si_value 等）；sigqueue 传值必备

Demo：code/flag_handler.c · code/siginfo_demo.c

HFT / 嵌入式关联

路线 要点
嵌入式 sigaction 是唯一可移植的注册方式，且能显式设 sa_mask/flags；SA_SIGINFO 让 handler 拿到 si_pid/si_uid/si_value，嵌入式调试时可溯源信号来源
HFT 一次性把 SIGTERM/SIGINT/SIGSEGV 注册到位、flags 显式 SA_RESTART，避免运行时反复 syscall 注册；handler 越薄越好（只置标志），重活留给主循环

代码示例

#include <stdio.h>
#include <signal.h>
#include <string.h>
#include <unistd.h>
/* sigaction: 可移植的信号注册 (替代 signal) */
void handler(int sig, siginfo_t *info, void *ucontext) {
    /* siginfo_t 包含详细信息 */
    char buf[128];
    int n = snprintf(buf, sizeof(buf),
        "signal=%d, si_code=%d, si_pid=%d, si_uid=%d\n",
        sig, info->si_code, info->si_pid, info->si_uid);
    write(STDOUT_FILENO, buf, n);
}

int main(void) {
    struct sigaction sa;
    memset(&sa, 0, sizeof(sa));
    sa.sa_sigaction = handler;
    sa.sa_flags = SA_SIGINFO | SA_RESTART;  /* SA_RESTART: 自动重启被中断的系统调用 */
    sigemptyset(&sa.sa_mask);

    /* 注册 SIGUSR1 处理器 */
    if (sigaction(SIGUSR1, &sa, NULL) < 0)
        perror("sigaction");

    /* 自发信号 */
    raise(SIGUSR1);

    /* 从另一个进程发信号 */
    if (fork() == 0) {
        kill(getppid(), SIGUSR1);
        _exit(0);
    }
    wait(NULL);
    return 0;
}

21.2

`sa_mask`（临时叠加）

本章：TLPI 第 21 章 — Signals: Signal Handlers - 上一节：21.1 sigaction() - 下一节：21.3 常用 sa_flags

本节讲什么

handler 运行期间： 1. 默认自动阻塞正在处理的那个信号（防递归） 2. 额外阻塞 sa_mask

要点

handler 运行期间：

  1. 默认自动阻塞正在处理的那个信号（防递归）
  2. 额外阻塞 sa_mask
  3. handler 返回后恢复原线程掩码
sigprocmask sa_mask
时效 长期（直到再改） 仅 handler 期间
作用 改线程掩码 临时追加阻塞

HFT / 嵌入式关联

路线 要点
嵌入式 handler 期间默认阻塞本信号防重入，配合 sa_mask 可临时阻塞相关信号，保证嵌入式时序敏感的 handler「执行完前不被同族打断」
HFT sa_mask 的阻塞只持续 handler 生命周期，不改长期掩码；HFT 信号 handler 应短到微秒级，阻塞窗口越小对延迟影响越小，别在 handler 里做重活

代码示例

#include <signal.h>
#include <unistd.h>
#include <stdio.h>
void handler(int sig) {
    printf("handler: sig=%d\n", sig);
}
int main(void) {
    struct sigaction sa = {0};
    sa.sa_handler = handler;
    sigemptyset(&sa.sa_mask);
    sigaddset(&sa.sa_mask, SIGQUIT);  /* handler 期间阻塞 SIGQUIT */
    sa.sa_flags = SA_RESTART;
    sigaction(SIGINT, &sa, NULL);
    printf("Ctrl+C → handler 执行期间 SIGQUIT 被阻塞\n");
    for (;;) pause();
    return 0;
}

21.3

常用 `sa_flags`

本章：TLPI 第 21 章 — Signals: Signal Handlers - 上一节：21.2 sa_mask（临时叠加） - 下一节：21.4 EINTR 与 SA_RESTART

本节讲什么

要点

标志 含义
SA_SIGINFO 用 sa_sigaction
SA_RESTART 多数慢调用被中断后自动重启（否则常 EINTR）
SA_NODEFER 不自动阻塞本信号（易重入，慎用）
SA_RESETHAND 一次后复位 SIG_DFL（老 signal 味）
SA_NOCLDSTOP SIGCHLD：子停/续不通知
SA_NOCLDWAIT SIGCHLD：子退出不留僵尸

HFT / 嵌入式关联

路线 要点
嵌入式 SA_NOCLDWAIT 让子进程退出不留僵尸、免去手动 waitpid，嵌入式多进程服务省心；SA_RESETHAND 复刻老 signal 一次性语义，需复位场景可用
HFT SA_RESTART 决定慢 syscall 被打断后是否自动重启，HFT 阻塞式 I/O 设上它可减少 EINTR 分支；SA_NODEFER 会开放重入，性能敏感但易踩雷，慎用

代码示例

#include <signal.h>
#include <stdio.h>
void handler(int sig) { printf("got %d\n", sig); }
int main(void) {
    struct sigaction sa = {0};
    sa.sa_handler = handler;
    /* SA_RESTART: 被信号中断的系统调用自动重启 */
    sa.sa_flags = SA_RESTART;
    /* SA_NOCLDSTOP: 子进程暂停不产生 SIGCHLD */
    /* SA_NODEFER: handler 期间不自动阻塞自身信号 */
    sigaction(SIGINT, &sa, NULL);
    printf("SA_RESTART: read 被 SIGINT 中断后自动重启\n");
    return 0;
}

21.4

`EINTR` 与 `SA_RESTART`

本章：TLPI 第 21 章 — Signals: Signal Handlers - 上一节：21.3 常用 sa_flags - 下一节：21.5 Async-Signal-Safe（最重要）

本节讲什么

阻塞在慢系统调用时递送信号 → 跑完 handler 后： - 默认：调用失败，errno == EINTR - SA_RESTART：许多调用自动重启

要点

阻塞在慢系统调用时递送信号 → 跑完 handler 后：

  • 默认：调用失败，errno == EINTR
  • SA_RESTART：许多调用自动重启

⚠️ 并非所有调用都可重启（epoll_wait、部分 accept/sleep 等因平台而异）。
业务应统一处理 EINTR（重试或显式退出）。

Demo：code/eintr_read.c

HFT / 嵌入式关联

路线 要点
嵌入式 慢设备 I/O（串口/网络）易被信号打断，嵌入式代码对 read/write 必须处理 EINTR 重试，否则偶发中断会静默丢数据
HFT EINTR 是延迟抖动来源之一——阻塞中的 recv/epoll_wait 被打断后返回，若未重试会漏事件；统一 while(ret<0 && errno==EINTR) 重试，保证关键路径不被信号偷走时间片

代码示例

#include <signal.h>
#include <unistd.h>
#include <stdio.h>
void handler(int sig) { printf("handler: %d\n", sig); }
int main(void) {
    struct sigaction sa = {0};
    sa.sa_handler = handler;
    sa.sa_flags = 0;  /* 不设 SA_RESTART → read 返回 EINTR */
    sigaction(SIGUSR1, &sa, NULL);

    /* 对比: 设 SA_RESTART 后 read 自动重启 */
    printf("不设 SA_RESTART: read 被 SIGUSR1 中断 → 返回 -1 errno=EINTR\n");
    printf("设 SA_RESTART: read 自动重启\n");
    raise(SIGUSR1);
    return 0;
}

21.5

Async-Signal-Safe（最重要）

本章：TLPI 第 21 章 — Signals: Signal Handlers - 上一节：21.4 EINTR 与 SA_RESTART - 下一节：21.6 SIGCHLD

本节讲什么

handler 可随时打断用户态代码 → 禁止非异步信号安全函数。 推荐范式： volatile sig_atomic_t got_sigint = 0;

要点

handler 可随时打断用户态代码 → 禁止非异步信号安全函数。

✅ 常见允许 ❌ 严禁
write、_exit、sigaction、sigprocmask、sigpending、…（见 POSIX 列表） printf、malloc/free、stdio、多数锁、C++/库随意调用

推荐范式：

volatile sig_atomic_t got_sigint = 0;
void handler(int sig) { (void)sig; got_sigint = 1; }

sig_atomic_t：读写在实现上视为原子，避免撕裂。

HFT / 嵌入式关联

路线 要点
嵌入式 handler 里 malloc/printf 可能死锁（打断正持锁的代码），嵌入式资源受限下锁竞争更常见；只用 write/_exit/sig_atomic_t 置标志，逻辑回主循环
HFT handler 里任何 malloc/加锁都可能引入微秒级不可预测延迟甚至死锁；HFT 的 handler 只做 sig_atomic_t 置位，让主循环在稳定上下文中处理，杜绝延迟毛刺

代码示例

#include <signal.h>
#include <unistd.h>
#include <stdio.h>
#include <string.h>
/* 异步信号安全函数: 可在 handler 中安全调用 */
void handler(int sig) {
    /* 安全: write 是 async-signal-safe */
    const char *msg = "signal!\n";
    write(STDOUT_FILENO, msg, strlen(msg));
    /* 不安全: printf/malloc/free 都不能在 handler 中调用! */
}
int main(void) {
    struct sigaction sa = {0};
    sa.sa_handler = handler;
    sigaction(SIGUSR1, &sa, NULL);
    printf("handler 中只能用 write, 不能用 printf\n");
    raise(SIGUSR1);
    return 0;
}

21.6

`SIGCHLD`

本章：TLPI 第 21 章 — Signals: Signal Handlers - 上一节：21.5 Async-Signal-Safe（最重要） - 下一节：21.7 signal() vs sigaction()

本节讲什么

子进程退出 → 父收 SIGCHLD。 Demo：code/sigchld_reap.c ---

要点

子进程退出 → 父收 SIGCHLD。

做法
handler 里 循环 waitpid(-1, …, WNOHANG) 收尸（标准信号不排队，一次可能对应多个子）
SA_NOCLDWAIT 内核自动收，不留僵尸

Demo：code/sigchld_reap.c

HFT / 嵌入式关联

路线 要点
嵌入式 标准信号不排队，一次 SIGCHLD 可能对应多个子进程，嵌入式多进程服务必须 while(waitpid(-1,WNOHANG)) 收净，否则留僵尸
HFT HFT 极少 fork 子进程（fork 有写时复制抖动），若用则 SA_NOCLDWAIT 让内核自动收尸、省去 handler；子进程只做隔离性重活，别在关键路径 fork

代码示例

#include <signal.h>
#include <unistd.h>
#include <stdio.h>
#include <sys/wait.h>
/* SIGCHLD: 子进程状态变化时发给父进程 */
void handler(int sig) {
    int status;
    pid_t pid = waitpid(-1, &status, WNOHANG);
    if (pid > 0) {
        char buf[64];
        int n = snprintf(buf, sizeof(buf), "子进程 %d 退出\n", pid);
        write(STDOUT_FILENO, buf, n);
    }
}
int main(void) {
    struct sigaction sa = {0};
    sa.sa_handler = handler;
    sa.sa_flags = SA_RESTART | SA_NOCLDSTOP;
    sigaction(SIGCHLD, &sa, NULL);

    pid_t pid = fork();
    if (pid == 0) { _exit(0); }
    printf("父进程: 子PID=%d, 等待 SIGCHLD\n", pid);
    sleep(2);
    return 0;
}

21.7

`signal()` vs `sigaction()`

本章：TLPI 第 21 章 — Signals: Signal Handlers - 上一节：21.6 SIGCHLD - 下一节：下一章+1:02d}-*/notes.md)

本节讲什么

要点

signal() sigaction()
sa_mask / flags ❌ / 不一致 ✅
SA_SIGINFO ❌ ✅
SA_RESTART 实现不一 可显式设
生产 弃用 首选

HFT / 嵌入式关联

路线 要点
嵌入式 signal() 在各 libc 间语义漂移（是否复位、是否阻塞自身），交叉编译平台各异；sigaction 显式声明 mask/flags，是嵌入式可移植代码的唯一选择
HFT 用 signal() 等于把 handler 语义交给平台决定，竞态难复现；HFT 生产统一 sigaction，行为确定、延迟可测，这是低延迟系统的底线

代码示例

#include <signal.h>
#include <stdio.h>
void handler(int sig) { printf("sig=%d\n", sig); }
int main(void) {
    /* signal(): 行为不一致, 不推荐 */
    /* signal(SIGINT, handler); */

    /* sigaction(): 行为确定, 推荐 */
    struct sigaction sa = {0};
    sa.sa_handler = handler;
    sigemptyset(&sa.sa_mask);
    sa.sa_flags = SA_RESTART;
    sigaction(SIGINT, &sa, NULL);

    printf("sigaction vs signal:\n");
    printf("  signal: 不确定是否自动复位、是否阻塞自身\n");
    printf("  sigaction: 行为明确, 可设 mask/flags\n");
    return 0;
}
