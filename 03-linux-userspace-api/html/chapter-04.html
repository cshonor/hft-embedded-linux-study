导读

章节定位

UNIX「一切皆文件」的操作根基：同一套 4 个系统调用 操作普通文件、终端、管道、socket、设备文件。

open() → read() / write() → close()
（+ lseek / ioctl 视对象而定）

示例：通用拷贝（Listing 4-1 精神）

见 code/copy.c（不依赖书中 tlpi_hdr.h）。

cc -Wall -o copy code/copy.c
./copy a.txt b.txt          # 文件 → 文件
./copy a.txt /dev/tty       # 文件 → 终端
./copy /dev/tty log.txt     # 键盘 → 文件（Ctrl+D 结束）

易错清单

  1. fd 在进程 fd 表；偏移 在打开文件描述（open file description）— Ch5 三层结构。
  2. close(fd) 释放槽位；进程退出自动关全部 fd。
  3. 管道/socket 不要假设可 lseek。
  4. 短读、部分写是 正常现象，必须处理。
  5. umask 影响新建权限；mode 仅配合 O_CREAT。
  6. write 成功 ≠ 落盘。

双线提示

路线 带走
嵌入式 /dev 设备也走同一套 open/read/write；专属控制靠 ioctl
HFT 短读/部分写；热路径少 syscall；落盘语义与缓冲要清楚

代码示例

#include <stdio.h>
#include <fcntl.h>
#include <unistd.h>
#include <string.h>

/* Ch4 通用 I/O 模型 — open/read/write/close 四件套。
 * 所有文件类型（普通文件/设备/proc）统一用这套接口。
 * 编译: gcc -o ch4_demo ch4_demo.c */

int main(void) {
    int fd = open("/tmp/ch4_test.txt", O_WRONLY | O_CREAT | O_TRUNC, 0644);
    if (fd < 0) { perror("open"); return 1; }

    const char *msg = "Hello, Universal I/O!\n";
    write(fd, msg, strlen(msg));
    close(fd);

    /* 重新打开读取 */
    fd = open("/tmp/ch4_test.txt", O_RDONLY);
    if (fd < 0) { perror("open read"); return 1; }

    char buf[256];
    ssize_t n = read(fd, buf, sizeof(buf) - 1);
    if (n > 0) {
        buf[n] = '\0';
        printf("read back: %s", buf);
    }
    close(fd);
    return 0;
}

4.1

Overview

本章：TLPI 第 04 章 — File I/O: The Universal I/O Model

本节讲什么

Linux I/O 的核心模型：打开文件得到 fd，通过 fd 读写，最后关闭。本章介绍 5 个核心系统调用。

要点

万物皆文件

Linux 用统一的 I/O 接口操作所有资源——普通文件、设备、管道、套接字都通过 fd 访问。

五个核心系统调用

操作 系统调用 原型
打开 open() int open(const char *pathname, int flags, ...);
读 read() ssize_t read(int fd, void *buf, size_t count);
写 write() ssize_t write(int fd, const void *buf, size_t count);
关闭 close() int close(int fd);
定位 lseek() off_t lseek(int fd, off_t offset, int whence);

文件描述符 (FD)

→ 内核三层（fd 表 / open file description / inode）见书内 Ch5 · LKD §3.8 ---

要点
定义 非负整数；进程内引用 已打开文件
默认 0 STDIN_FILENO · 1 STDOUT_FILENO · 2 STDERR_FILENO（<unistd.h>）
私有 fd 是 进程私有；两进程同数字 fd 通常指向 不同 打开实例

→ 内核三层（fd 表 / open file description / inode）见书内 Ch5 · LKD §3.8

代码示例

#include <fcntl.h>
#include <unistd.h>
#include <stdio.h>

int main(void) {
    /* 0/1/2 默认打开：STDIN/STDOUT/STDERR */
    printf("STDIN_FILENO = %d\n", STDIN_FILENO);   /* 0 */
    printf("STDOUT_FILENO = %d\n", STDOUT_FILENO); /* 1 */
    printf("STDERR_FILENO = %d\n", STDERR_FILENO); /* 2 */

    /* 新 fd 从最小可用数字开始分配 */
    int fd1 = open("/tmp/a.txt", O_CREAT | O_RDWR, 0644);  /* 期望 3 */
    int fd2 = open("/tmp/b.txt", O_CREAT | O_RDWR, 0644);  /* 期望 4 */
    printf("fd1 = %d, fd2 = %d\n", fd1, fd2);

    /* 关闭 fd1 后，3 被回收，下次 open 复用 */
    close(fd1);
    int fd3 = open("/tmp/c.txt", O_CREAT | O_RDWR, 0644);  /* 期望 3 */
    printf("fd3 = %d (复用最小可用)\n", fd3);

    close(fd2);
    close(fd3);
    return 0;
}

4.2

通用 I/O 模型（核心思想）

本章：TLPI 第 04 章 — File I/O: The Universal I/O Model - 上一节：本章首页 - 下一节：4.3 文件描述符 FD

本节讲什么

要点

点 说明
同一套 API 拷贝磁盘文件与读写 /dev/tty 可用同一段代码
差异在哪 设备/文件系统逻辑在 内核驱动；应用层无感
通用不够时 设备专属控制用 ioctl()

代码示例

#include <fcntl.h>
#include <unistd.h>
#include <stdio.h>

/* 同一套 open/read/write/close 适用于所有文件类型 */
int main(void) {
    /* 操作普通文件 */
    int fd = open("/tmp/demo.txt", O_WRONLY | O_CREAT | O_TRUNC, 0644);
    if (fd < 0) { perror("open file"); return 1; }
    write(fd, "hello\n", 6);
    close(fd);

    /* 操作设备文件 /dev/null — 同一套 API */
    int dev = open("/dev/null", O_WRONLY);
    if (dev < 0) { perror("open /dev/null"); return 1; }
    write(dev, "anything", 8);  /* 数据被丢弃，但调用成功 */
    close(dev);

    /* 读 /proc/version — 还是同一套 API */
    int proc = open("/proc/version", O_RDONLY);
    if (proc < 0) { perror("open /proc"); return 1; }
    char buf[256];
    ssize_t n = read(proc, buf, sizeof(buf) - 1);
    if (n > 0) { buf[n] = '\0'; printf("%s", buf); }
    close(proc);
    return 0;
}

4.4

`open()`

本章：TLPI 第 04 章 — File I/O: The Universal I/O Model - 上一节：4.3 文件描述符 FD - 下一节：4.5 read()

本节讲什么

include int open(const char pathname, int flags, / mode_t mode /); flags（位掩码；访问模式三选一）*

要点

#include <fcntl.h>
int open(const char *pathname, int flags, /* mode_t mode */);
成功 返回 fd
失败 -1

flags（位掩码；访问模式三选一）

标志 含义
O_RDONLY / O_WRONLY / O_RDWR 只读 / 只写 / 读写
O_CREAT 不存在则创建；须给 mode
O_TRUNC 存在则截断为 0
O_APPEND 追加（原子性详 Ch5）
O_NONBLOCK 非阻塞打开
O_NOFOLLOW 不跟随符号链接

mode： 新建权限，受 umask 屏蔽：最终权限 ≈ mode & ~umask。
默认 open 跟随 符号链接。

与 C 语言学习的关系

open() 是 POSIX 系统调用（内核接口），直接向 Linux 内核发起服务，不是 C 语言标准库函数。

int open(const char *pathname, int flags, mode_t mode);  // POSIX 系统调用
FILE *fopen(const char *path, const char *mode);          // C 标准库（libc 封装）

fopen() 是 C 标准库函数，内部底层会调用 open() 系统调用，并额外带上用户态缓冲区。K&R 第 8 章讲解的正是这套文件系统接口。

fopen 模式 → open flags 映射：

fopen 模式 open 对应 flags 说明
"r" O_RDONLY 只读
"w" O_WRONLY \| O_CREAT \| O_TRUNC 只写、创建、截断清空旧文件
"a" O_WRONLY \| O_CREAT \| O_APPEND 追加写

关键区别： fopen 在用户态带缓冲区（FILE 结构体内部 buffer）；open 没有用户态缓冲，读写直接进入内核。

HFT / 嵌入式关联

UNIX 文件 I/O 分两层：用户态 libc 库层 ↔ 内核系统调用层。

路线 要点
嵌入式 Linux 可选 libc 封装（fopen，自带缓冲，简单）；也可直接调用 open 系统调用做裸文件操作，适合资源受限场景。/dev 设备也走同一套 open/read/write；专属控制靠 ioctl
HFT 低延迟 fopen/fread/fwrite：libc 自带用户层缓冲区，多一层拷贝，带来微小额外延迟。直接 open/read/write：绕开 libc 用户缓冲，但系统调用本身陷入内核也有开销。工程上要权衡：什么时候用库缓冲、什么时候直接系统调用，mmap 也经常登场
通用 短读/部分写；热路径少 syscall；落盘语义与缓冲要清楚

补充区分重点（面试 / 考试高频）

fopen / fread / fwrite open / read / write
返回值 FILE * 指针 int fd（内核整数句柄）
层级 C 标准库（libc） POSIX 系统调用（内核接口）
缓冲 用户态带缓冲区 无用户态缓冲
关闭 fclose() → 内部调用 close() close(fd)
可移植 C 标准，跨平台 POSIX，Unix/Linux 限定

常见陷阱

  1. O_CREAT 忘传 mode
/* mode 参数丢失，权限不确定 */
fd = open("f.txt", O_WRONLY | O_CREAT);
/* 必须给 mode */
fd = open("f.txt", O_WRONLY | O_CREAT, 0644);

O_CREAT 时第三个参数 mode 是新文件权限，受 umask 影响。漏传会导致权限不确定（取决于栈上残留值）。

  1. 返回值未检查
int fd = open(path, O_RDONLY);
read(fd, buf, n);  /* fd=-1 → EBADF */

open 失败返回 -1。不检查直接用 fd 会导致后续操作全部失败。必须 if ((fd = open(...)) < 0) { perror; exit; }。

  1. O_TRUNC 意外截断
/* 想追加写，却加了 O_TRUNC */
fd = open("log.txt", O_WRONLY | O_TRUNC);  /* 清空了! */
fd = open("log.txt", O_WRONLY | O_APPEND);  /* 正确 */

O_TRUNC 在文件存在时截断为 0。追加写场景误加 O_TRUNC 会丢失数据。

自测题

题目 1（选择）： open("f.txt", O_CREAT) 缺少什么参数？ A. flags 不对 B. mode 参数 C. pathname D. 返回值

参考答案

B。O_CREAT 时必须提供 mode（如 0644），受 umask 影响。漏传会使用栈上不确定的值。

题目 2（判断）： open 失败时返回 0。

参考答案

错误。open 失败返回 -1 并设置 errno。fd=0 是 stdin，open 正常时可能返回 0（如果 stdin 被关闭）。

题目 3（踩坑）： 以下代码有什么问题？

int fd = open("/etc/passwd", O_WRONLY|O_CREAT|O_TRUNC, 0644);
参考答案

对 /etc/passwd 用 O_WRONLY|O_TRUNC 会截断系统密码文件！想读文件应用 O_RDONLY。这是非常危险的操作。

题目 4（应用）： 写代码：以读写方式打开文件，不存在则创建（权限 0644），存在则追加。

参考答案 
int fd = open("data.txt", O_RDWR|O_CREAT|O_APPEND, 0644);
if (fd < 0) { perror("open"); exit(1); }

代码示例

#include <stdio.h>
#include <fcntl.h>
#include <unistd.h>
/* open(): flags = O_RDONLY / O_WRONLY / O_RDWR + O_CREAT/O_TRUNC/O_APPEND */
int main(void) {
    int fd = open("/tmp/ch4_open.txt", O_WRONLY | O_CREAT | O_TRUNC, 0644);
    if (fd < 0) { perror("open"); return 1; }
    write(fd, "test", 4);
    close(fd);

    fd = open("/tmp/ch4_open.txt", O_RDONLY);
    char buf[8];
    read(fd, buf, 4);
    buf[4] = '\0';
    printf("read: %s\n", buf);
    close(fd);
    return 0;
}

思考题

HFT 热路径写日志，用 fprintf（fopen），还是 open + write？各自优缺点是什么？

参考思路
  • fprintf（fopen）：libc 缓冲减少 syscall 次数（批量 flush），但多一次用户态拷贝；格式化方便；缓冲区 flush 时机不可控
  • open + write：无 libc 缓冲层，延迟更低更可控；但每次 write 都陷入内核，频繁写时 syscall 开销大
  • HFT 实践：热路径日志常用自定义 ring buffer + 批量 write，或 mmap + 定期刷盘，兼顾低延迟和少 syscall
4.5

`read()`

本章：TLPI 第 04 章 — File I/O: The Universal I/O Model - 上一节：4.4 open() - 下一节：4.6 write()

本节讲什么

ssize_t read(int fd, void buffer, size_t count); 普通文件到尾部常返回 0；管道 / socket / 终端更易短读 → 网络编程必须循环读*。 ---

要点

ssize_t read(int fd, void *buffer, size_t count);
返回 含义
>0 读到的字节数；可小于 count（短读 short read）
0 EOF
-1 出错

普通文件到尾部常返回 0；管道 / socket / 终端更易短读 → 网络编程必须循环读。

常见陷阱

  1. 短读未处理
/* 假设一次读完 */
ssize_t n = read(fd, buf, 1024);
/* n 可能 < 1024 */

read 返回值可能小于请求字节数（short read）。网络和管道尤其常见，必须循环读。

  1. EINTR 未处理
/* 信号中断后 read 返回 -1, errno=EINTR */
/* 不是错误，应重试 */

信号中断系统调用时返回 -1 且 errno=EINTR。应该重试，或用 SA_RESTART 自动重启。

  1. EOF 判断错误
/* 用 feof 预判 EOF → 多读一次 */
while (!feof(fp)) { fgets(...); }
/* 正确：检查返回值 */
while (fgets(buf, sz, fp) != NULL) { ... }

read 返回 0 表示 EOF。不要用 feof 预判（feof 只在读取越过后才为真）。

自测题

题目 1（选择）： read() 返回 0 表示什么？ A. 出错 B. EOF C. 没有数据 D. 需要重试

参考答案

B。返回 0 表示已到达文件末尾（EOF）。返回 -1 表示出错，返回 >0 表示读到的字节数。

题目 2（判断）： read 一定会读满请求的字节数。

参考答案

错误。read 可能返回少于请求的字节数（short read），尤其在管道、socket、终端上。必须循环读。

题目 3（踩坑）： 以下代码有什么问题？

char buf[1024];
read(fd, buf, sizeof(buf));
buf[strlen(buf)] = '\0';
参考答案

1) read 不保证以 null 结尾；2) 没检查返回值；3) strlen 在未终止的 buf 上越界。应检查返回值并手动加 \0。

题目 4（应用）： 写一个安全的 readall 函数，确保读满 n 字节或遇到 EOF。

参考答案 
ssize_t readall(int fd, void *buf, size_t n) {
    size_t total = 0;
    while (total < n) {
        ssize_t r = read(fd, (char*)buf+total, n-total);
        if (r < 0 && errno == EINTR) continue;
        if (r < 0) return -1;
        if (r == 0) break; /* EOF */
        total += r;
    }
    return total;
}

代码示例

#include <stdio.h>
#include <fcntl.h>
#include <unistd.h>
/* read(): 返回读取字节数, 0=EOF, -1=错误 */
int main(void) {
    int fd = open("/etc/hostname", O_RDONLY);
    char buf[256];
    ssize_t n;
    while ((n = read(fd, buf, sizeof(buf))) > 0)
        write(STDOUT_FILENO, buf, n);
    printf("\nlast read returned %zd\n", n);
    close(fd);
    return 0;
}

4.6

`write()`

本章：TLPI 第 04 章 — File I/O: The Universal I/O Model - 上一节：4.5 read() - 下一节：4.7 lseek()

本节讲什么

ssize_t write(int fd, const void *buffer, size_t count); ---

要点

ssize_t write(int fd, const void *buffer, size_t count);
点
返回 实际写入字节；允许 部分写 partial write
落盘 成功 ≠ 已持久化；常先入页缓存（缓冲详后续章）；强制刷盘用 fsync/fdatasync

常见陷阱

  1. 部分写未处理
/* 假设一次写完 */
write(fd, buf, 1024);
/* 可能只写了 512 */

write 返回值可能小于请求字节数（partial write）。必须循环写直到全部写出。

  1. write 成功 ≠ 落盘
write(fd, data, size);  /* 数据在页缓存 */
fsync(fd);  /* 强制落盘 */

write 成功只表示数据到了内核页缓存。需要 fsync/fdatasync 确保持久化。

  1. SIGPIPE 导致进程退出
write(pipe_fd, buf, n);  /* 对端关闭 → SIGPIPE */
signal(SIGPIPE, SIG_IGN);  /* 忽略 */

向已关闭的管道/socket 写数据触发 SIGPIPE，默认终止进程。应忽略 SIGPIPE。

自测题

题目 1（选择）： write() 返回值小于请求字节数时应该？ A. 报错退出 B. 重试写剩余部分 C. 忽略 D. 关闭文件

参考答案

B。这是部分写（partial write），是正常现象。应该循环写剩余部分直到全部写出。

题目 2（判断）： write 成功返回后数据已经写入磁盘。

参考答案

错误。write 成功只表示数据到了内核页缓存。断电仍会丢失。需要 fsync 确保落盘。

题目 3（踩坑）： 以下代码有什么问题？

int fd = open("log.txt", O_WRONLY);
write(fd, "hello", 5);
close(fd);
参考答案

1) 没检查 open 返回值；2) 没检查 write 返回值（可能部分写）；3) 没检查 close 返回值（NFS 上 close 可能报延迟错误）。

题目 4（应用）： 写一个安全的 writeall 函数。

参考答案 
ssize_t writeall(int fd, const void *buf, size_t n) {
    size_t total = 0;
    while (total < n) {
        ssize_t w = write(fd, (char*)buf+total, n-total);
        if (w < 0 && errno == EINTR) continue;
        if (w < 0) return -1;
        total += w;
    }
    return total;
}

代码示例

#include <stdio.h>
#include <fcntl.h>
#include <unistd.h>
#include <string.h>
/* write(): 可能部分写入, 需循环保证写完 */
int main(void) {
    int fd = open("/tmp/ch4_write.txt", O_WRONLY | O_CREAT | O_TRUNC, 0644);
    const char *msg = "hello write\n";
    size_t total = strlen(msg);
    ssize_t written = 0;
    while (written < (ssize_t)total) {
        ssize_t n = write(fd, msg + written, total - written);
        if (n < 0) { perror("write"); break; }
        written += n;
    }
    printf("wrote %zd bytes\n", written);
    close(fd);
    return 0;
}

4.6

Closing a File: close()

本章：TLPI 第 04 章 — File I/O: The Universal I/O Model

本节讲什么

close() 释放文件描述符，使其可被重用。

要点

close() 原型

int close(int fd);
  • 成功返回 0，失败返回 -1
  • 释放 fd，使其可被后续 open() 复用
  • 进程终止时内核自动关闭所有打开的 fd

close() 做了什么

  1. 释放 fd（使其可重用）
  2. 释放打开文件表中的条目（引用计数减 1）
  3. 如果是最后一个引用，释放内存中的文件描述
  4. 对于管道/套接字，close 可能触发特殊行为（如关闭管道写端使读端收到 EOF）

应该检查 close() 的返回值吗

  • 普通文件：通常不检查（最佳实践是检查）
  • 网络文件系统（NFS）：必须检查（可能延迟写入失败）
  • 带缓冲的文件：close 前应先 fflush/fsync

常见误区

误区 纠正
close 保证数据写到磁盘 不保证，需要 fsync()
忘记 close 只泄漏 fd 还可能阻止文件被删除（若持有写锁）

4.7

`lseek()`

本章：TLPI 第 04 章 — File I/O: The Universal I/O Model - 上一节：4.6 write() - 下一节：4.8 ioctl()

本节讲什么

off_t lseek(int fd, off_t offset, int whence); ---

要点

off_t lseek(int fd, off_t offset, int whence);
whence 基准
SEEK_SET 文件起始
SEEK_CUR 当前偏移
SEEK_END 文件末尾
特性
只改偏移 改的是 打开文件描述 内的 offset；本身不产生 I/O
文件空洞 跳过尾部再 write，中间可不占磁盘块；读空洞区得 0
不可 seek 管道、socket、终端 → -1，errno=ESPIPE

常见陷阱

  1. 管道上 lseek 失败
lseek(pipe_fd, 0, SEEK_SET);  /* ESPIPE */

管道、socket、终端不支持 seek。lseek 返回 -1，errno=ESPIPE。

  1. 空洞文件浪费磁盘
lseek(fd, 1024*1024, SEEK_SET);
write(fd, "x", 1);  /* 中间是空洞 */

lseek 超过文件末尾再 write 会产生空洞。空洞在读时返回 0，但不一定占磁盘块。

  1. lseek 返回值未检查
lseek(fd, offset, SEEK_SET);
read(fd, buf, n);  /* 偏移可能没变 */

lseek 返回新的文件偏移。不检查返回值可能导致后续读写位置错误。

自测题

题目 1（选择）： lseek(fd, 0, SEEK_CUR) 的作用是？ A. 跳到开头 B. 跳到末尾 C. 获取当前偏移 D. 重置偏移

参考答案

C。SEEK_CUR 从当前位置偏移 0 字节，相当于获取当前文件偏移量而不移动。

题目 2（判断）： 所有文件类型都支持 lseek。

参考答案

错误。管道、socket、终端不支持 lseek，返回 -1 且 errno=ESPIPE。

题目 3（踩坑）： 以下代码试图在管道上随机访问，会怎样？

int fd = open("pipe", O_RDWR);
lseek(fd, 100, SEEK_SET);
参考答案

如果 fd 是管道，lseek 返回 -1 且 errno=ESPIPE。管道是流式数据，不支持随机访问。

题目 4（应用）： 写代码获取文件大小（不用 stat）。

参考答案 
off_t cur = lseek(fd, 0, SEEK_CUR);
off_t size = lseek(fd, 0, SEEK_END);
lseek(fd, cur, SEEK_SET);  /* 恢复 */

代码示例

#include <stdio.h>
#include <fcntl.h>
#include <unistd.h>
/* lseek(): 调整文件偏移量 SEEK_SET/SEEK_CUR/SEEK_END */
int main(void) {
    int fd = open("/tmp/ch4_lseek.txt", O_RDWR | O_CREAT | O_TRUNC, 0644);
    write(fd, "ABCDEFGHIJ", 10);

    lseek(fd, 3, SEEK_SET);   /* 移到偏移 3 */
    char c;
    read(fd, &c, 1);
    printf("byte at offset 3: %c\n", c);

    off_t pos = lseek(fd, 0, SEEK_CUR);  /* 当前位置 */
    printf("current offset: %ld\n", (long)pos);

    lseek(fd, -1, SEEK_END);  /* 从末尾回退1 */
    read(fd, &c, 1);
    printf("last byte: %c\n", c);
    close(fd);
    return 0;
}

Summary

本章回顾

五个核心系统调用

调用 函数原型 功能 关键点
open() int open(const char *path, int flags, ...) 打开/创建文件 flags: O_RDONLY/O_WRONLY/O_RDWR/O_CREAT/O_TRUNC/O_APPEND
read() ssize_t read(int fd, void *buf, size_t count) 读数据 返回实际读取字节数，0 表示 EOF，-1 表示错误
write() ssize_t write(int fd, const void *buf, size_t count) 写数据 返回实际写入字节数，可能 < count
close() int close(int fd) 关闭文件 释放 fd，flush 内核缓冲

open() 常用 flags

flag 含义 说明
O_RDONLY 只读 0
O_WRONLY 只写 1
O_RDWR 读写 2
O_CREAT 不存在则创建 需提供 mode 参数
O_TRUNC 截断已有文件为 0 需有写权限
O_APPEND 每次写追加到末尾 原子操作
O_EXCL 与 O_CREAT 配合 文件已存在则失败
O_CLOEXEC exec 时自动关闭 防止 fd 泄漏

关键概念

  • fd（文件描述符）：进程级文件句柄（整数），指向内核打开文件表项
  • 一切皆文件：统一 read/write 接口操作普通文件、设备、管道、套接字
  • 偏移量：每个 fd 独立维护读写位置（fork 后父子共享偏移量）
  • O_APPEND：内核在每次 write 前原子设置偏移量到文件末尾，多进程安全追加
  • short read/write：read/write 返回值可能小于请求值，必须循环处理
  • EOF：read 返回 0 表示文件末尾，不是错误

fd 范围与限制

项 说明
0 (STDIN) 标准输入
1 (STDOUT) 标准输出
2 (STDERR) 标准错误
3+ 用户可用 fd
ulimit -n 查看/设置进程最大 fd 数（默认 1024）

常见错误码

errno 含义 场景
EBADF fd 无效 未打开或已关闭
EFAULT buf 地址非法 传入空指针或坏地址
EINTR 被信号中断 read/write 被信号打断，应重试
ENOSPC 空间不足 write 时磁盘满
EAGAIN 非阻塞模式无数据 O_NONBLOCK + 无可读数据

HFT / 嵌入式关联

  • 行情数据落盘：O_APPEND | O_CREAT | O_WRONLY 追加写行情日志，原子安全
  • DMA 直通：嵌入式场景可能直接 read() /dev/mem 或自定义字符设备
  • 零拷贝：通用 I/O 模型是基础，后续 sendfile / splice / mmap 是优化方向
  • fd 泄漏防护：关键路径必须 close()，或使用 O_CLOEXEC

代码自测

1. 为什么 read/write 可能返回小于请求的字节数？
  • read：到达 EOF、管道/套接字缓冲区只有部分数据、被信号中断、从终端读取遇到换行符
  • write：磁盘空间不足、写入管道且缓冲区部分满、被信号中断
  • 正确做法：循环调用直到完成全部数据传输（参见练习 1）
2. fork() 后父子进程共享文件偏移量吗？

是。fork() 复制 fd 表，但指向相同的内核打开文件表项。父子进程共享偏移量和状态标志。这是一个重要的并发问题——多进程操作同一文件需用 O_APPEND 或文件锁。

3. O_APPEND 为什么能保证多进程写入不交错？

内核在执行 write() 时，先原子地将偏移量设为文件末尾，再执行写入。这个"设偏移量+写"操作是不可分割的原子步骤。没有 O_APPEND 时，lseek(SEEK_END) + write() 是两步，存在 TOCTOU 竞争窗口。

练习 1 参考代码

#include "tlpi_hdr.h"
#include <fcntl.h>

int main(int argc, char *argv[]) {
    if (argc != 3)
        usageErr("usage: %s src dst\n", argv[0]);

    int srcfd = open(argv[1], O_RDONLY);
    if (srcfd == -1) errExit("open src");

    int dstfd = open(argv[2], O_WRONLY | O_CREAT | O_TRUNC, 0644);
    if (dstfd == -1) errExit("open dst");

    char buf[8192];
    ssize_t n;
    while ((n = read(srcfd, buf, sizeof(buf))) > 0) {
        ssize_t written = 0;
        while (written < n) {           /* 处理 short write */
            ssize_t w = write(dstfd, buf + written, n - written);
            if (w == -1) errExit("write");
            written += w;
        }
    }
    if (n == -1) errExit("read");

    if (close(srcfd) == -1) errExit("close src");
    if (close(dstfd) == -1) errExit("close dst");
    return 0;
}

练习 2 参考代码

#include "tlpi_hdr.h"
#include <fcntl.h>

int main(int argc, char *argv[]) {
    int fd = open(argv[1], O_RDONLY);
    if (fd == -1) errExit("open");

    off_t size = lseek(fd, 0, SEEK_END);
    if (size == -1) errExit("lseek SEEK_END");

    for (off_t pos = size - 1; pos >= 0; pos--) {
        lseek(fd, pos, SEEK_SET);
        char c;
        if (read(fd, &c, 1) == 1)
            write(STDOUT_FILENO, &c, 1);
    }
    close(fd);
    return 0;
}

练习 3 答案

  1. 管道/FIFO 缓冲区不足：PIPE_BUF 大小限制，write 写入部分数据后返回
  2. 信号中断：EINTR，部分数据已写入
  3. 磁盘空间不足：ENOSPC，仅写入剩余空间对应的数据
  4. 网络套接字：TCP 发送缓冲区部分填满

练习 4 答案

  • 有 O_APPEND：不会交错。内核在每次 write 前原子地将偏移量设为文件末尾，整个"设偏移量+写"是不可分割的。
  • 无 O_APPEND：会交错。lseek(SEEK_END) + write() 是两步操作，进程 A 的 lseek 和 write 之间可能被进程 B 的 lseek+write 插入，导致覆盖或交错。

HFT / 嵌入式关联

  • 可靠文件拷贝：HFT 日志归档场景下需要处理 short write
  • 嵌入式 OTA：固件烧写场景下确保完整写入
  • 原子追加：多进程行情日志统一用 O_APPEND
