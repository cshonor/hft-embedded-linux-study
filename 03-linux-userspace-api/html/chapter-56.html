导读

章节目标

socket/bind/listen/accept/connect；地址结构；读写与关闭；STREAM vs DGRAM；UNIX vs INET。

UNIX vs Internet（导论）

AF_UNIX AF_INET(6)
范围 本机 跨机
地址 路径 / 抽象名 IP:port
DGRAM 可靠 UDP 可丢
权限 文件权限 应用层
特色 可传 fd/凭证 协议栈

本机优先 UNIX；要远程用 Internet。

陷阱

  1. STREAM 无消息边界
  2. 勿关 listener；关的是 conn fd
  3. UNIX DGRAM ≠ UDP 可靠性
  4. fork 复制 fd → close≠断连
  5. backlog≠最大客户端数
  6. addrlen 类型用 socklen_t

背诵卡

# 要点
1 socket→bind→listen→accept / connect
2 STREAM 字节流；DGRAM 有边界
3 accept 新 fd；listener 常留
4 shutdown 半关闭；close 看引用
5 UNIX DGRAM 可靠；UDP 不
6 本机 UNIX；跨机 INET

代码示例

#include <stdio.h>
#include <sys/socket.h>
#include <sys/un.h>
#include <unistd.h>
#include <string.h>

/* Ch56 套接字入门 — socket/bind/listen/accept/connect。
 * 演示 AF_UNIX 面向连接的服务器端基本流程。
 * 编译: gcc -o ch56_demo ch56_demo.c */

#define SOCK_PATH "/tmp/ch56_sock"

int main(void) {
    /* 创建套接字: AF_UNIX + SOCK_STREAM */
    int sfd = socket(AF_UNIX, SOCK_STREAM, 0);
    if (sfd < 0) { perror("socket"); return 1; }

    /* 绑定地址 */
    struct sockaddr_un addr;
    memset(&addr, 0, sizeof(addr));
    addr.sun_family = AF_UNIX;
    strncpy(addr.sun_path, SOCK_PATH, sizeof(addr.sun_path) - 1);

    unlink(SOCK_PATH);  /* 确保路径不存在 */
    if (bind(sfd, (struct sockaddr *)&addr, sizeof(addr)) < 0) {
        perror("bind"); return 1;
    }

    /* 监听, backlog=5 */
    if (listen(sfd, 5) < 0) { perror("listen"); return 1; }
    printf("Server listening on %s\n", SOCK_PATH);

    /* fork 子进程作为客户端 */
    pid_t pid = fork();
    if (pid == 0) {
        int cfd = socket(AF_UNIX, SOCK_STREAM, 0);
        connect(cfd, (struct sockaddr *)&addr, sizeof(addr));
        write(cfd, "hello socket", 12);
        char buf[64];
        int n = read(cfd, buf, sizeof(buf));
        if (n > 0) { buf[n] = '\0'; printf("Client: got '%s'\n", buf); }
        close(cfd);
        _exit(0);
    }

    /* 服务器: accept + 读写 */
    int cfd = accept(sfd, NULL, NULL);
    if (cfd >= 0) {
        char buf[64];
        int n = read(cfd, buf, sizeof(buf));
        if (n > 0) { buf[n] = '\0'; printf("Server: got '%s'\n", buf); }
        write(cfd, "reply from server", 17);
        close(cfd);
    }

    waitpid(pid, NULL, 0);
    close(sfd);
    unlink(SOCK_PATH);
    return 0;
}

56.1

概念

本章：TLPI 第 56 章 — Sockets: Introduction - 上一节：本章首页 - 下一节：56.2 –56.4 创建与地址

本节讲什么

C/S：服务器 socket→bind→listen→accept；客户端 socket→connect（通常不 bind）。 ---

要点

域 用途
AF_UNIX 本机 IPC
AF_INET / AF_INET6 网络
类型
SOCK_STREAM 连接、可靠、双向字节流、有序无重复
SOCK_DGRAM 无连接、保留边界；INET 不可靠；UNIX 可靠

C/S：服务器 socket→bind→listen→accept；客户端 socket→connect（通常不 bind）。

HFT / 嵌入式关联

路线 要点
嵌入式 AF_UNIX 本机 IPC 零网络栈开销，嵌入式多进程/多线程服务首选；SOCK_DGRAM 在 UNIX 域可靠，省去自建重传
HFT 域与类型决定协议栈开销——AF_UNIX 直通内核无 IP/TCP 头，延迟远低于 AF_INET；同机行情分发/风控走 AF_UNIX，跨机才走 INET

代码示例


/* socket 通信域与类型 */
#include <stdio.h>
#include <stdlib.h>
#include <sys/socket.h>
#include <unistd.h>

int main(void) {
    /* AF_UNIX: 本地通信，SOCK_STREAM: 面向连接 */
    int fd1 = socket(AF_UNIX, SOCK_STREAM, 0);
    printf("AF_UNIX SOCK_STREAM: fd=%d\n", fd1);

    /* AF_UNIX, SOCK_DGRAM: 无连接数据报 */
    int fd2 = socket(AF_UNIX, SOCK_DGRAM, 0);
    printf("AF_UNIX SOCK_DGRAM:  fd=%d\n", fd2);

    /* AF_INET, SOCK_STREAM: TCP */
    int fd3 = socket(AF_INET, SOCK_STREAM, 0);
    printf("AF_INET SOCK_STREAM: fd=%d (TCP)\n", fd3);

    /* AF_INET, SOCK_DGRAM: UDP */
    int fd4 = socket(AF_INET, SOCK_DGRAM, 0);
    printf("AF_INET SOCK_DGRAM:  fd=%d (UDP)\n", fd4);

    /* SOCK_NONBLOCK: 非阻塞 */
    int fd5 = socket(AF_UNIX, SOCK_STREAM | SOCK_NONBLOCK, 0);
    printf("SOCK_NONBLOCK:       fd=%d\n", fd5);

    /* SOCK_CLOEXEC: exec 时自动关闭 */
    int fd6 = socket(AF_UNIX, SOCK_STREAM | SOCK_CLOEXEC, 0);
    printf("SOCK_CLOEXEC:        fd=%d\n", fd6);

    close(fd1); close(fd2); close(fd3); close(fd4); close(fd5); close(fd6);
    return 0;
}

56.2

–56.4 创建与地址

本章：TLPI 第 56 章 — Sockets: Introduction - 上一节：56.1 概念 - 下一节：56.5 面向连接 API

本节讲什么

int socket(int domain, int type, int protocol); / protocol 常 0 / int bind(int sockfd, const struct sockaddr *addr, socklen_t addrlen); 统一入口 struct sockaddr；实际用 sockaddr_un / _in / _in6。

要点

int socket(int domain, int type, int protocol);  /* protocol 常 0 */
int bind(int sockfd, const struct sockaddr *addr, socklen_t addrlen);

统一入口 struct sockaddr；实际用 sockaddr_un / _in / _in6。
addrlen 用 socklen_t。代码用 AF_*（与 PF_* 同值）。

HFT / 嵌入式关联

路线 要点
嵌入式 sockaddr 统一入口 + sockaddr_un/_in/_in6 家族，写双栈服务用 sockaddr_storage 兼容 v4/v6；bind 定本端地址是服务端第一课
HFT socket() 本身轻量，但地址解析不该在热路径重复做；启动期一次性 bind/connect 到位，热路径只做 send/recv，避免每次系统调用

代码示例


/* socket() 创建 + 协议自动选择 */
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <sys/socket.h>
#include <unistd.h>

int main(void) {
    /* protocol=0 表示自动选择默认协议 */
    int tcp_fd = socket(AF_INET, SOCK_STREAM, 0);
    /* 等价于 socket(AF_INET, SOCK_STREAM, IPPROTO_TCP) */
    printf("SOCK_STREAM + proto 0: fd=%d (TCP selected automatically)\n", tcp_fd);

    int udp_fd = socket(AF_INET, SOCK_DGRAM, 0);
    /* 等价于 socket(AF_INET, SOCK_DGRAM, IPPROTO_UDP) */
    printf("SOCK_DGRAM  + proto 0: fd=%d (UDP selected automatically)\n", udp_fd);

    /* 显式指定协议 */
    int raw_fd = socket(AF_INET, SOCK_RAW, IPPROTO_ICMP);
    if (raw_fd >= 0) {
        printf("SOCK_RAW + IPPROTO_ICMP: fd=%d (needs root)\n", raw_fd);
        close(raw_fd);
    } else {
        printf("SOCK_RAW failed (needs CAP_NET_RAW)\n");
    }

    close(tcp_fd);
    close(udp_fd);
    return 0;
}

56.3

Binding a Socket to an Address: bind()

本章：TLPI 第 56 章 — Sockets: Introduction

本节讲什么

介绍 bind() 系统调用：将套接字绑定到指定地址和端口。涵盖服务器端绑定流程、INADDR_ANY 通配地址、端口冲突处理。

要点

bind 函数

int bind(int sockfd, const struct sockaddr *addr, socklen_t addrlen);
参数 说明
sockfd socket() 返回的 fd
addr 指向 sockaddr 的指针（实际为 sockaddr_in/sockaddr_in6/sockaddr_un）
addrlen addr 结构大小
返回值 0 成功，-1 失败

服务器端标准流程

1. socket(AF_INET, SOCK_STREAM, 0)  → sockfd
2. bind(sockfd, &addr, sizeof(addr))  → 绑定地址+端口
3. listen(sockfd, backlog)           → 开始监听
4. accept(sockfd, &client_addr, &len) → 接受连接

IPv4 绑定示例

struct sockaddr_in addr;
memset(&addr, 0, sizeof(addr));
addr.sin_family = AF_INET;
addr.sin_port = htons(8080);        /* 网络字节序 */
addr.sin_addr.s_addr = htonl(INADDR_ANY);  /* 0.0.0.0 所有接口 */
bind(sockfd, (struct sockaddr *)&addr, sizeof(addr));

常用地址

地址 含义
INADDR_ANY (0.0.0.0) 所有 IPv4 接口
in6addr_any (::) 所有 IPv6 接口
127.0.0.1 仅本地回环
具体 IP 仅该接口

bind 常见错误

errno 含义 原因
EADDRINUSE 地址已使用 端口被占用，或未设 SO_REUSEADDR
EACCES 权限不足 绑定 1024 以下端口需 root
EADDRNOTAVAIL 地址不可用 指定了不存在的本地 IP
EINVAL 参数错误 sockfd 未 socket 创建或已绑定

SO_REUSEADDR

int opt = 1;
setsockopt(sockfd, SOL_SOCKET, SO_REUSEADDR, &opt, sizeof(opt));
bind(sockfd, ...);
场景 无 SO_REUSEADDR 有 SO_REUSEADDR
重启绑定 TIME_WAIT 端口 EADDRINUSE 成功
绑定同端口不同 IP EADDRINUSE 成功

HFT / 嵌入式关联

  • 端口绑定：HFT 服务绑定特定端口接收行情/订单
  • SO_REUSEADDR：HFT 服务重启时避免等待 TIME_WAIT（2MSL 约 60s）
  • INADDR_ANY：多网卡服务器绑定所有接口
  • 嵌入式：绑定到特定网卡接口 IP，避免外部访问

代码示例

#include "tlpi_hdr.h"
#include <netinet/in.h>

int create_server(int port) {
    int sockfd = socket(AF_INET, SOCK_STREAM, 0);
    if (sockfd == -1) errExit("socket");

    /* SO_REUSEADDR 避免重启时 EADDRINUSE */
    int opt = 1;
    setsockopt(sockfd, SOL_SOCKET, SO_REUSEADDR, &opt, sizeof(opt));

    struct sockaddr_in addr;
    memset(&addr, 0, sizeof(addr));
    addr.sin_family = AF_INET;
    addr.sin_port = htons(port);
    addr.sin_addr.s_addr = htonl(INADDR_ANY);

    if (bind(sockfd, (struct sockaddr *)&addr, sizeof(addr)) == -1)
        errExit("bind");

    if (listen(sockfd, 128) == -1) errExit("listen");

    return sockfd;
}

代码自测

1. 为什么绑定 1024 以下端口需要 root 权限？

Linux 规定 1-1023 端口为特权端口（reserved ports），只有 effective UID=0 的进程或具有 CAP_NET_BIND_SERVICE 能力的进程才能绑定。这是历史安全设计——客户端连接特权端口时信任服务器是 root 运行的可信服务。HFT 服务通常绑定高位端口（如 8080/9090）避免权限问题，或用 capabilities。

2. INADDR_ANY 和绑定具体 IP 的区别？

INADDR_ANY(0.0.0.0) 绑定所有网络接口，接受发往任何本地 IP 的连接。绑定具体 IP 只接受发往该 IP 的连接。多网卡服务器如果只希望外部访问用外部 IP、内部访问用内部 IP，可以分别绑定不同 IP 的同端口。

56.4

Generic Socket Address Structures: struct sockaddr

本章：TLPI 第 56 章 — Sockets: Introduction

本节讲什么

介绍通用套接字地址结构 struct sockaddr 和各协议族的具体地址结构（sockaddr_in/sockaddr_in6/sockaddr_un），以及它们之间的类型转换。

要点

通用地址结构

struct sockaddr {
    sa_family_t sa_family;   /* 地址族: AF_INET/AF_INET6/AF_UNIX */
    char        sa_data[14]; /* 地址数据 */
};
  • 所有套接字 API（bind/connect/accept）接受 struct sockaddr *
  • 实际传入的是具体协议族的结构，强制转换

IPv4 地址结构

struct sockaddr_in {
    sa_family_t    sin_family;     /* AF_INET */
    in_port_t      sin_port;       /* 端口（网络字节序） */
    struct in_addr sin_addr;      /* IPv4 地址 */
    unsigned char  sin_zero[8];    /* 填充，使大小=16 */
};

struct in_addr {
    in_addr_t s_addr;              /* 32位 IPv4 地址（网络字节序） */
};

IPv6 地址结构

struct sockaddr_in6 {
    sa_family_t     sin6_family;   /* AF_INET6 */
    in_port_t       sin6_port;     /* 端口 */
    uint32_t        sin6_flowinfo; /* 流信息 */
    struct in6_addr sin6_addr;     /* IPv6 地址 */
    uint32_t        sin6_scope_id; /* 作用域 */
};

struct in6_addr {
    uint8_t s6_addr[16];           /* 128位 IPv6 地址 */
};

Unix 域地址结构

struct sockaddr_un {
    sa_family_t sun_family;       /* AF_UNIX */
    char        sun_path[108];   /* 路径名 */
};

大小对比

结构 大小 地址族
sockaddr 16 通用
sockaddr_in 16 AF_INET
sockaddr_in6 28 AF_INET6
sockaddr_un 110 AF_UNIX
sockaddr_storage 128 通用大容量

sockaddr_storage

struct sockaddr_storage ss;
/* 足够大，可以容纳任何协议族的地址结构 */
/* 适合 accept 等需要存储未知类型地址的场景 */

类型转换模式

struct sockaddr_in addr;
memset(&addr, 0, sizeof(addr));
addr.sin_family = AF_INET;
addr.sin_port = htons(8080);
addr.sin_addr.s_addr = htonl(INADDR_ANY);

/* 强制转换为通用类型 */
bind(sockfd, (struct sockaddr *)&addr, sizeof(addr));

字节序转换

函数 说明
htons(port) 主机→网络 short（端口）
htonl(addr) 主机→网络 long（地址）
ntohs(port) 网络→主机 short
ntohl(addr) 网络→主机 long

地址转换函数

函数 说明
inet_pton(af, str, &addr) 文本→二进制（推荐）
inet_ntop(af, &addr, str, size) 二进制→文本（推荐）
inet_addr(str) 文本→long（已废弃）
inet_ntoa(addr) 二进制→文本（已废弃，非线程安全） 
/* 推荐用法 */
struct sockaddr_in addr;
inet_pton(AF_INET, "192.168.1.100", &addr.sin_addr);

char str[INET_ADDRSTRLEN];
inet_ntop(AF_INET, &addr.sin_addr, str, sizeof(str));

HFT / 嵌入式关联

  • sockaddr_storage：HFT 服务器用 sockaddr_storage 存储客户端地址，兼容 IPv4/IPv6
  • inet_pton/inet_ntop：线程安全，HFT 必须用这两个替代废弃函数
  • 字节序：HFT 网络代码必须正确处理字节序，用 htons/htonl
  • 嵌入式：精简系统可能只有 IPv4，sockaddr_in 足够

代码示例

#include <netinet/in.h>
#include <arpa/inet.h>
#include <string.h>
#include <stdio.h>

/* 统一地址处理（支持 IPv4 和 IPv6） */
void print_peer(int sockfd) {
    struct sockaddr_storage ss;
    socklen_t len = sizeof(ss);
    getpeername(sockfd, (struct sockaddr *)&ss, &len);

    char host[NI_MAXHOST], port[NI_MAXSERV];
    getnameinfo((struct sockaddr *)&ss, len,
                host, sizeof(host), port, sizeof(port),
                NI_NUMERICHOST | NI_NUMERICSERV);
    printf("peer: %s:%s\n", host, port);
}

/* IPv4 绑定 */
int bind_ipv4(int sockfd, const char *ip, int port) {
    struct sockaddr_in addr;
    memset(&addr, 0, sizeof(addr));
    addr.sin_family = AF_INET;
    addr.sin_port = htons(port);
    if (inet_pton(AF_INET, ip, &addr.sin_addr) != 1) return -1;
    return bind(sockfd, (struct sockaddr *)&addr, sizeof(addr));
}

代码自测

1. 为什么需要 sockaddr 通用结构？

C 语言没有函数重载或多态。套接字 API（bind/connect/accept）需要接受任何协议族的地址。struct sockaddr 作为通用"基类"，具体协议族的结构（sockaddr_in/sockaddr_un）作为"子类"，通过强制类型转换传入。sa_family 字段让内核知道实际类型。

2. sockaddr_storage 比 sockaddr 好在哪里？

sockaddr 只有 16 字节，无法容纳 IPv6 的 sockaddr_in6（28 字节）。sockaddr_storage 有 128 字节，足够容纳任何地址族。且它有对齐保证，可以安全地 cast 为具体类型。在需要存储未知类型地址（如 accept 的客户端地址）时应该用 sockaddr_storage。

面向连接 API

本章：TLPI 第 56 章 — Sockets: Introduction - 上一节：56.2 –56.4 创建与地址 - 下一节：56.6 –56.8 I/O 与关闭

本节讲什么

Demo：code/（UNIX 流式极简 C/S） ---

要点

调用
listen(fd, backlog) 仅 STREAM；backlog≈未完成+已完成队列上限，≠最大并发
accept 阻塞等连接；返回新 conn fd；可取对端地址
connect STREAM：三次握手；DGRAM：只记默认对端

Demo：code/（UNIX 流式极简 C/S）

HFT / 嵌入式关联

路线 要点
嵌入式 listen backlog 是未完成+已完成队列上限≠最大并发，资源受限设备要控制 backlog 防 SYN 洪泛；accept 阻塞等连接，非阻塞配 epoll
HFT connect 三次握手 + accept 各是系统调用，HFT 连接建立只在启动期，热路径零握手；backlog 要够大，避免高并发下连接建立排队延迟

代码示例


/* socket 通信 API 全流程：bind → listen → accept → connect */
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <unistd.h>
#include <sys/socket.h>
#include <sys/un.h>

int main(void) {
    const char *sock_path = "/tmp/ch56_api.sock";
    unlink(sock_path);

    /* --- 服务器端 --- */
    int sfd = socket(AF_UNIX, SOCK_STREAM, 0);
    struct sockaddr_un saddr = { .sun_family = AF_UNIX };
    strncpy(saddr.sun_path, sock_path, sizeof(saddr.sun_path) - 1);

    bind(sfd, (struct sockaddr *)&saddr, sizeof(saddr));
    listen(sfd, 1);
    printf("server: listening on %s\n", sock_path);

    /* fork 子进程做客户端 */
    pid_t pid = fork();
    if (pid == 0) {
        int cfd = socket(AF_UNIX, SOCK_STREAM, 0);
        struct sockaddr_un caddr = { .sun_family = AF_UNIX };
        strncpy(caddr.sun_path, sock_path, sizeof(caddr.sun_path) - 1);

        /* connect 主动连接 */
        if (connect(cfd, (struct sockaddr *)&caddr, sizeof(caddr)) == 0) {
            printf("client: connected\n");
            send(cfd, "hello server", 13, 0);

            char buf[64];
            ssize_t n = recv(cfd, buf, sizeof(buf) - 1, 0);
            if (n > 0) { buf[n] = '\0'; printf("client: echo='%s'\n", buf); }
        }
        close(cfd);
        _exit(0);
    }

    /* accept 接收连接 */
    int afd = accept(sfd, NULL, NULL);
    if (afd >= 0) {
        char buf[64];
        ssize_t n = recv(afd, buf, sizeof(buf) - 1, 0);
        if (n > 0) { buf[n] = '\0'; printf("server: received='%s'\n", buf); }
        send(afd, "hello client", 13, 0);
        close(afd);
    }

    wait(NULL);
    close(sfd);
    unlink(sock_path);
    return 0;
}

要点

read/write 可用；send/recv 带 flags（MSG_PEEK 等）。
STREAM 无边界 → 应用层分包。

close shutdown(how)
语义 fd 引用 −1；归零才断 直接关通道；SHUT_RD/WR/RDWR
半关闭 难 SHUT_WR 发 FIN，仍可读
fork 后 一方 close 未必断 TCP 推荐显式 shutdown

默认阻塞；O_NONBLOCK → EAGAIN/EWOULDBLOCK（配 epoll 等）。

HFT / 嵌入式关联

路线 要点
嵌入式 close 是引用计数归零才断，fork 后须双方关无用端否则连接不真正关闭；shutdown SHUT_WR 发 FIN 半关闭，协议优雅断开
HFT 默认阻塞 I/O 会卡死关键路径，HFT 一律 O_NONBLOCK + epoll；shutdown 比 close 更可控（半关闭发 FIN），避免 TIME_WAIT 与 SIGPIPE 坑

代码示例


/* socket close 与 shutdown 的区别 */
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <unistd.h>
#include <sys/socket.h>
#include <sys/un.h>

int main(void) {
    /* shutdown 可以只关闭一个方向，close 完全关闭 */
    int fd = socket(AF_UNIX, SOCK_STREAM, 0);
    printf("socket created: fd=%d\n", fd);

    /* shutdown(SHUT_WR): 关闭写方向，仍可读 */
    shutdown(fd, SHUT_WR);
    printf("shutdown(SHUT_WR): write end closed, read still open\n");

    /* shutdown(SHUT_RDWR): 双向关闭 */
    shutdown(fd, SHUT_RDWR);
    printf("shutdown(SHUT_RDWR): both directions closed\n");

    /* close: 释放 fd（引用计数归零才真正关闭） */
    close(fd);
    printf("close(fd): fd released\n");

    printf("\n区别:\n");
    printf("  close: 释放 fd，如果还有 dup 的副本则不真正关闭\n");
    printf("  shutdown: 立即影响所有副本，可只关一个方向\n");
    return 0;
}

socket 用 fd 还是 FILE*？——用 fd

socket() 返回 int fd，所有 socket 操作只认 fd：

int sockfd = socket(AF_INET, SOCK_STREAM, 0);  // 返回 fd
bind(sockfd, ...);  listen(sockfd, 5);  accept(sockfd, ...);
send(sockfd, buf, n, 0);  recv(sockfd, buf, n, 0);  close(sockfd);

不用 FILE* 的三个原因：

原因 解释
双向通信 TCP 全双工，FILE* 缓冲区对双向 I/O 不友好——fputs 的数据还在缓冲区里，对端 recv 不到
事件驱动 select/poll/epoll 只认 int fd，不认 FILE*
非阻塞 I/O socket 常用 O_NONBLOCK，FILE* 的用户缓冲会与 EAGAIN 冲突——缓冲区有旧数据但 recv 返回 EAGAIN，行为未定义 
文件 I/O:  fprintf(fp,...) → [stdio buf] → write(fd) → [page cache] → 磁盘
socket:    send(sockfd,...) → [内核 socket buffer] → 网卡    ← 没有用户缓冲

唯一例外：简单同步行协议客户端（HTTP/1.0、SMTP）可用 fdopen(sockfd, "r+") 包成 FILE*，方便 fprintf/fgets 行读写。但必须 fflush(fp) 后对端才能收到，且不能与 epoll/O_NONBLOCK 共用。

fd (int) FILE*
socket/bind/listen/accept ✅ ❌
send/recv ✅ ❌
select/poll/epoll ✅ ❌
O_NONBLOCK ✅ ❌
fdopen 包装后 — ✅（仅同步阻塞+行协议）
正常网络编程 用 fd 不用

HFT / 嵌入式关联

  • TCP：HFT 订单/控制消息使用 TCP（可靠传输）
  • UDP：HFT 行情数据使用 UDP（低延迟，可丢包）
  • Unix 域套接字：同机进程间通信，比 TCP 快 2-5 倍
  • 非阻塞 + epoll：所有套接字用 O_NONBLOCK + epoll 管理多路复用
  • 嵌入式：lwIP 等轻量 TCP/IP 栈

代码自测

1. SOCK_STREAM 和 SOCK_DGRAM 的区别？
  • SOCK_STREAM：面向连接，可靠传输（TCP），保证顺序和不丢失，有流量控制
  • SOCK_DGRAM：无连接，不可靠传输（UDP），不保证顺序，可能丢包，无流量控制

HFT 选择：订单用 TCP（可靠），行情用 UDP（低延迟）。

2. 为什么需要 htons？

x86 CPU 使用小端字节序（低字节在低地址），网络协议使用大端字节序（高字节在低地址）。htons 将端口号从主机字节序转为网络字节序，确保不同架构的机器发送的数据格式一致。不转换可能导致连接到错误端口。
