章节目标

掌握 ACE 标签、最小/扩展 ACL、ACL_MASK、Access vs Default ACL；会用 libacl（-lacl）；理清内核判定顺序与 chmod/umask/ls -l 交互陷阱。

17.7 速查：Access vs Default · chmod 影响

Access ACL Default ACL
对象 文件/目录 仅目录
控制本对象访问？ 是 否
继承 — 新建文件/子目录
对扩展 ACL 做 chmod 效果
改「属组」那三位（ls 上的 group） 实际改的是 MASK，不是 GROUP_OBJ
最小 ACL 与传统一致，改 GROUP_OBJ
备份
默认 cp 易丢 ACL（同 xattr）
保留 cp --preserve=xattr / rsync -A（及 xattr 相关选项）

17.8 易错清单

  1. 备份丢 ACL → 权限「突然不对」
  2. chmod + 扩展 ACL → 动的是 MASK；ls group 列是 MASK
  3. 有 Default ACL 时 umask 行为改变
  4. 硬链接共享 ACL；软链接无自身 ACL（跟目标）
  5. NFS ACL 兼容性慎用
  6. libacl 不可移植到典型 BSD/macOS 同一套 API

练习

  1. 遍历打印 Access ACE（简易 getfacl）
  2. 写扩展 ACL：命名用户 + MASK，再 getfacl/ls -l+
  3. 目录 Default ACL → 新建文件是否继承
  4. 带 ACL 文件 chmod，观察 group 列变 MASK

背诵卡

# 要点
1 ACL = ACE 列表；扩展 ACL 必须有 MASK
2 有效权限 = ACE & MASK
3 ls -l 有 + 时 group 列常是 MASK
4 Default ACL 只影响新建；目录专属
5 存于 system.posix_acl_* xattr
6 chmod 扩展 ACL 时改 MASK，勿当 GROUP_OBJ

代码示例

#include <stdio.h>
#include <sys/acl.h>
#include <errno.h>

/* Ch17 访问控制列表 (ACL) — acl_get_file/acl_set_file。
 * ACL 比传统 rwx 更细粒度：可给特定用户/组单独授权。
 * 编译: gcc -o ch17_demo ch17_demo.c -lacl
 * 需要安装: apt install libacl1-dev */

int main(void) {
    const char *path = "/tmp/ch17_test.txt";
    FILE *fp = fopen(path, "w");
    if (!fp) { perror("fopen"); return 1; }
    fprintf(fp, "test\n");
    fclose(fp);

    /* 获取文件 ACL */
    acl_t acl = acl_get_file(path, ACL_TYPE_ACCESS);
    if (acl == NULL) {
        perror("acl_get_file (need libacl)");
        remove(path);
        return 1;
    }

    /* 打印 ACL 文本形式 */
    char *text = acl_to_text(acl, NULL);
    if (text) {
        printf("Current ACL:\n%s\n", text);
        acl_free(text);
    }
    acl_free(acl);

    /* 创建新 ACL 条目: 给 uid 1000 读写权限 */
    acl = acl_from_text("u::rw,g::r,o::r,u:1000:rw,m::rw");
    if (acl) {
        if (acl_set_file(path, ACL_TYPE_ACCESS, acl) == 0)
            printf("ACL updated: uid 1000 gets rw\n");
        else
            perror("acl_set_file");
        acl_free(acl);
    }

    remove(path);
    return 0;
}

17.1

基础概念

本章：TLPI 第 17 章 — Access Control Lists - 上一节：本章首页 - 下一节：17.2 ACL_MASK（核心坑）

本节讲什么

ACL = 多条 ACE：tag + [qualifier uid/gid] + 权限(rwx)。 ---

要点

ACL = 多条 ACE：tag + [qualifier uid/gid] + 权限(rwx)。

六种 Tag

常量 文本 说明
ACL_USER_OBJ user:: 所有者（固定 1）
ACL_USER user:uid: 命名用户（可多条）
ACL_GROUP_OBJ group:: 属组（固定 1）
ACL_GROUP group:gid: 命名组（可多条）
ACL_MASK mask:: 有效权限上限（扩展 ACL 必需）
ACL_OTHER other:: 其他人（固定 1）

两类 ACL

类型 作用 xattr
Access ACL 控制该对象访问 system.posix_acl_access
Default ACL 仅目录；不控制本目录访问，供新建子对象继承 system.posix_acl_default

最小 vs 扩展

组成 MASK
最小 ACL USER_OBJ + GROUP_OBJ + OTHER 不需要（≈ 传统 mode）
扩展 ACL 另有 ACL_USER / ACL_GROUP 必须有 ACL_MASK

HFT / 嵌入式关联

路线 要点
嵌入式 ACL 六种 tag（USER_OBJ/USER/GROUP_OBJ/GROUP/MASK/OTHER），Access ACL 控访问 / Default ACL 仅目录供继承
HFT 多用户/多进程部署用 ACL 精细授权（风控用户只读、交易用户读写），比传统 rwx 更细粒度

代码示例

#include <sys/acl.h>
#include <stdio.h>

/* ACL (访问控制列表): 比 rwx 更细粒度的权限控制
 * 标准 POSIX 权限: 属主/组/其他 各 rwx
 * ACL: 可以给特定用户/组单独授权
 *
 * 需要 libacl: gcc -lacl
 */
int main(void) {
    /* 获取文件的 ACL */
    acl_t acl = acl_get_file("/tmp", ACL_TYPE_ACCESS);
    if (acl == NULL) {
        perror("acl_get_file");
        printf("(可能不支持 ACL 或未安装 libacl)\n");
        return 1;
    }

    /* 转为文本格式 */
    char *text = acl_to_text(acl, NULL);
    if (text) {
        printf("ACL:\n%s\n", text);
        acl_free(text);
    }
    acl_free(acl);
    return 0;
}

17.2

`ACL_MASK`（核心坑）

本章：TLPI 第 17 章 — Access Control Lists - 上一节：17.1 基础概念 - 下一节：17.3 内核判定顺序（示意）

本节讲什么

MASK 限制：命名用户、命名组、GROUP_OBJ 的有效权限上限。 有效权限 = ACE 权限 & MASK 例：user:alice:rwx + mask::r-- → alice 实际只有 r--。

要点

MASK 限制：命名用户、命名组、GROUP_OBJ 的有效权限上限。

有效权限 = ACE 权限 & MASK

例：user:alice:rwx + mask::r-- → alice 实际只有 r--。

ls -l 现象： 存在扩展 ACL 时，group 列显示的是 MASK，不是 GROUP_OBJ；行末常有 +。

HFT / 嵌入式关联

路线 要点
嵌入式 MASK 是命名用户/组/GROUP_OBJ 的有效权限上限，有效权限 = ACE 权限 & MASK
HFT ls -l 的 group 列显示的是 MASK 不是 GROUP_OBJ，审计权限时别误读；MASK 设错会静默削减授权

代码示例

#include <sys/acl.h>
#include <stdio.h>

/* ACL mask: 限制所有 ACL 条目的最大权限 (除 user:: 和 other::)
 * 类似于一个"权限上限过滤器"
 */
int main(void) {
    /* 示例 ACL:
     * user::rw-          (属主: 不受 mask 影响)
     * user:alice:rwx     (alice: 被 mask 过滤)
     * group::r--         (组: 被 mask 过滤)
     * mask::rw-          (最大有效权限: rw-)
     * other::r--         (其他: 不受 mask 影响)
     *
     * alice 的有效权限 = rwx & rw- = rw-
     */

    acl_t acl = acl_get_file("/tmp", ACL_TYPE_ACCESS);
    if (acl == NULL) { perror("acl_get_file"); return 1; }

    char *text = acl_to_text(acl, NULL);
    if (text) {
        /* 查找 mask 行 */
        char *mask = strstr(text, "mask::");
        if (mask) {
            printf("ACL mask: %.6s\n", mask);
        } else {
            printf("无 mask 条目 (仅有基本权限)\n");
        }
        acl_free(text);
    }
    acl_free(acl);
    return 0;
}

17.3

内核判定顺序（示意）

本章：TLPI 第 17 章 — Access Control Lists - 上一节：17.2 ACL_MASK（核心坑） - 下一节：17.4 Default ACL 继承

本节讲什么

  1. root → 放行（执行还需有 x，细节见手册） 2. EUID == 所有者 → USER_OBJ 3. 匹配某 ACL_USER → 权限 & MASK

要点

  1. root → 放行（执行还需有 x，细节见手册）
  2. EUID == 所有者 → USER_OBJ
  3. 匹配某 ACL_USER → 权限 & MASK
  4. EGID/附加组匹配 ACL_GROUP / GROUP_OBJ → & MASK
  5. → ACL_OTHER
  6. 否则拒绝

HFT / 嵌入式关联

路线 要点
嵌入式 内核按 owner→ACL_USER→GROUP_OBJ/ACL_GROUP→OTHER 顺序判定，先匹配先生效
HFT 理解判定顺序才能预测多规则冲突时的实际授权，避免权限配置出现意外放行/拒绝

代码示例

#include <sys/acl.h>
#include <stdio.h>

/* ACL 条目类型:
 * ACL_USER_OBJ  - 属主权限 (对应传统 owner rwx)
 * ACL_USER      - 指定用户权限
 * ACL_GROUP_OBJ - 属组权限 (对应传统 group rwx)
 * ACL_GROUP     - 指定组权限
 * ACL_MASK      - 最大有效权限过滤器
 * ACL_OTHER     - 其他用户 (对应传统 other rwx)
 */
int main(void) {
    acl_t acl = acl_get_file("/tmp", ACL_TYPE_ACCESS);
    if (acl == NULL) { perror("acl_get_file"); return 1; }

    acl_entry_t entry;
    acl_tag_t tag;
    int entry_id = ACL_FIRST_ENTRY;

    printf("=== ACL 条目 ===\n");
    while (acl_get_entry(acl, entry_id, &entry) == 1) {
        entry_id = ACL_NEXT_ENTRY;
        acl_get_tag_type(entry, &tag);
        switch (tag) {
            case ACL_USER_OBJ:  printf("user::"); break;
            case ACL_USER:      printf("user:uid:"); break;
            case ACL_GROUP_OBJ: printf("group::"); break;
            case ACL_GROUP:     printf("group:gid:"); break;
            case ACL_MASK:      printf("mask::"); break;
            case ACL_OTHER:     printf("other::"); break;
            default: printf("unknown:"); break;
        }
        printf("rwx\n");
    }
    acl_free(acl);
    return 0;
}

17.4

Default ACL 继承

本章：TLPI 第 17 章 — Access Control Lists - 上一节：17.3 内核判定顺序（示意） - 下一节：17.5 libacl API（链接 -lacl）

本节讲什么

父目录设 Default ACL 后： ---

要点

父目录设 Default ACL 后：

新建对象 行为
普通文件 Default → 自身 Access ACL；创建 mode 仍约束；umask 通常不再按传统方式生效
子目录 Access + 自己的 Default 都从父 Default 继承（可继续向下传）

Default 不改目录里已有文件，只影响之后新建的对象。

HFT / 嵌入式关联

路线 要点
嵌入式 父目录 Default ACL 只影响新建对象（文件→Access ACL，子目录→Access+Default 继续下传），不改已有文件
HFT 用目录 Default ACL 让新生成的日志/配置文件自动带上正确权限，免逐个 chmod

代码示例

#include <sys/acl.h>
#include <stdio.h>

/* Default ACL: 仅对目录有效
 * 新创建的文件/子目录自动继承目录的 default ACL
 */
int main(void) {
    /* 获取目录的 default ACL */
    acl_t def_acl = acl_get_file("/tmp", ACL_TYPE_DEFAULT);
    if (def_acl == NULL) {
        printf("/tmp 无 default ACL (常见)\n");
    } else {
        char *text = acl_to_text(def_acl, NULL);
        if (text) {
            printf("Default ACL:\n%s\n", text);
            acl_free(text);
        }
        acl_free(def_acl);
    }

    /* 设置 default ACL:
     * acl_t acl = acl_from_text("u::rwx,g::rwx,o::rwx");
     * acl_set_file("/tmp/mydir", ACL_TYPE_DEFAULT, acl);
     */
    return 0;
}

17.5

libacl API（链接 `-lacl`）

本章：TLPI 第 17 章 — Access Control Lists - 上一节：17.4 Default ACL 继承 - 下一节：17.6 命令行

本节讲什么

include #include / 视发行版；部分声明在 sys/acl.h / acl_t acl_get_file(const char *path, acl_type_t type);

要点

#include <sys/acl.h>
#include <acl/libacl.h>   /* 视发行版；部分声明在 sys/acl.h */

acl_t acl_get_file(const char *path, acl_type_t type);
int   acl_set_file(const char *path, acl_type_t type, acl_t acl);
/* type: ACL_TYPE_ACCESS / ACL_TYPE_DEFAULT */

int acl_get_entry(acl_t acl, int entry_id, acl_entry_t *entry_p);
int acl_create_entry(acl_t *acl_p, acl_entry_t *entry_p);
int acl_set_tag_type(acl_entry_t entry_d, acl_tag_t tag_type);
int acl_set_qualifier(acl_entry_t entry_d, const void *qualifier_p);
int acl_set_permset(acl_entry_t entry_d, acl_permset_t permset_d);

int acl_valid(acl_t acl);
void acl_free(void *obj_p);

编程要点：

  1. 扩展 ACL 手写 MASK
  2. 写入前 acl_valid()
  3. 用完 acl_free()
  4. FS 需支持 ACL（现代 ext4 等通常默认可用）

Demo：code/print_acl.c · code/set_named_user_acl.c

HFT / 嵌入式关联

路线 要点
嵌入式 acl_get_file/acl_set_file + acl_valid() 校验 + acl_free() 释放；扩展 ACL 须手写 MASK
HFT 程序化设置 ACL 须 acl_valid() 前置校验，避免写入无效 ACL 导致权限异常

代码示例

#include <stdio.h>
#include <sys/acl.h>
/* libacl API: acl_get_entry/acl_get_tag_type/acl_create_entry */
int main(void) {
    const char *path = "/tmp/acl_api_test.txt";
    FILE *fp = fopen(path, "w"); fclose(fp);

    /* 获取 ACL */
    acl_t acl = acl_get_file(path, ACL_TYPE_ACCESS);
    if (!acl) { perror("acl_get_file"); return 1; }

    /* 遍历 ACL 条目 */
    acl_entry_t entry;
    int entry_id = ACL_FIRST_ENTRY;
    printf("ACL entries:\n");
    while (acl_get_entry(acl, entry_id, &entry) == 1) {
        acl_tag_t tag;
        acl_get_tag_type(entry, &tag);
        const char *type = (tag == ACL_USER_OBJ) ? "user_obj" :
                           (tag == ACL_GROUP_OBJ) ? "group_obj" :
                           (tag == ACL_OTHER) ? "other" :
                           (tag == ACL_USER) ? "user" : "group";
        printf("  tag: %s\n", type);
        entry_id = ACL_NEXT_ENTRY;
    }

    /* 创建新 ACL */
    acl_t new_acl = acl_from_text("u::rw,g::r,o::r,u:1000:rw,m::rw");
    if (new_acl) {
        acl_set_file(path, ACL_TYPE_ACCESS, new_acl);
        printf("ACL updated (uid 1000 gets rw)\n");
        acl_free(new_acl);
    }
    acl_free(acl);
    remove(path);
    return 0;
}

17.7

ACL Implementation Limits

本节讲什么

ACL（访问控制列表）的实现限制：每文件最大 ACE 数量、ACL 大小限制、文件系统支持差异。

要点

系统限制

限制 典型值 来源
每文件最大 ACE 25 ext2/ext3
每文件最大 ACE 无限（动态） ext4/xfs/btrfs
ACL 总大小 32KB 内核
命名空间数 1-3 user/group/other

文件系统支持

文件系统 ACL 支持 需挂载选项
ext4 是 默认开启
xfs 是 默认开启
btrfs 是 默认开启
ext2/3 是 acl 挂载选项
tmpfs 是 acl 选项
FAT/NTFS 模拟 不原生
NFS v4 是 协议级

ACE（Access Control Entry）结构

user::rw-          # 文件属主
user:hft:rwx       # 特定用户
group::r--         # 文件属组
group:traders:rw- # 特定组
mask::rwx          # 最大有效权限掩码
other::r--         # 其他用户

mask 的作用

mask 限制 named user 和 named group 的最大有效权限：

user:hft:rwx  # 请求 rwx
mask::r-x     # mask 只允许 r-x
→ hft 实际权限 = rwx & r-x = r-x

查看和设置

getfacl file           # 查看 ACL
setfacl -m u:hft:rwx file   # 设置用户权限
setfacl -m g:traders:rw file # 设置组权限
setfacl -m m::rwx file      # 设置 mask
setfacl -b file            # 删除所有 ACL

HFT / 嵌入式关联

  • 交易系统文件权限精细控制：不同策略组访问不同数据
  • 嵌入式多用户场景：限制配置文件访问
  • 注意文件系统是否原生支持 ACL

代码示例

#!/bin/bash
# 设置 HFT 目录 ACL

# 策略组可读写行情数据
setfacl -R -m g:strategy:rw /data/market/

# 风控组只读

# 验证

代码自测

mask 在 ACL 中起什么作用？

mask 限定了所有 named user 和 named group ACE 的最大有效权限。实际有效权限 = ACE 权限 ∩ mask 权限。例如用户 ACE 设为 rwx 但 mask 为 r-x，则实际有效权限为 r-x。mask 的作用是集中控制所有额外用户的权限上限，无需逐个修改。

17.8

The ACL API

本章：TLPI 第 17 章 — Access Control Lists

本节讲什么

介绍 Linux ACL（POSIX 1003.1e）的编程接口：acl_get_file()、acl_set_file()、acl_get_entry()、acl_get_tagtype()、acl_set_qualifier() 等 libacl 函数族，以及如何用程序方式读取和修改文件的 ACL。

要点

libacl 核心函数

函数 功能 说明
acl_get_file(path, type) 获取 ACL type: ACL_TYPE_ACCESS / ACL_TYPE_DEFAULT
acl_set_file(path, type, acl) 设置 ACL 需先 acl_valid() 校验
acl_get_entry(acl, entry_id, *entry_p) 遍历 ACL 条目 ACL_FIRST_ENTRY / ACL_NEXT_ENTRY
acl_get_tagtype(entry, *tag) 获取条目类型 ACL_USER_OBJ / ACL_USER / ACL_GROUP_OBJ / ACL_GROUP / ACL_MASK / ACL_OTHER
acl_get_qualifier(entry) 获取限定符 UID（ACL_USER）或 GID（ACL_GROUP）
acl_get_permset(entry, *permset) 获取权限集 返回 acl_permset_t
acl_get_perm(permset, perm) 查询权限 perm: ACL_READ / ACL_WRITE / ACL_EXECUTE
acl_create_entry(*acl, *entry) 创建新条目 插入到 ACL 末尾
acl_set_tagtype(entry, tag) 设置条目类型 配合 acl_create_entry
acl_set_qualifier(entry, uid/gid) 设置限定符 指向 UID/GID
acl_set_permset(entry, permset) 设置权限集 需先 acl_get_permset 获取
acl_add_perm(permset, perm) 添加权限 —
acl_delete_perm(permset, perm) 删除权限 —
acl_valid(acl) 校验 ACL 合法性 修改后必须校验
acl_free(obj) 释放 ACL 对象 所有 acl_get 返回的对象都需释放

ACL 条目类型

标签 含义 对应传统权限位
ACL_USER_OBJ 文件属主 owner r/w/x
ACL_USER 指定用户 额外用户权限
ACL_GROUP_OBJ 文件属组 group r/w/x
ACL_GROUP 指定组 额外组权限
ACL_MASK 最大有效权限掩码 限制 ACL_USER/ACL_GROUP/ACL_GROUP_OBJ
ACL_OTHER 其他用户 other r/w/x

access ACL vs default ACL

类型 对象 作用
ACL_TYPE_ACCESS 文件 & 目录 决定当前对象的访问权限
ACL_TYPE_DEFAULT 仅目录 新建子文件/子目录继承的 ACL 模板

修改 ACL 的典型流程

1. acl_get_file(path, ACL_TYPE_ACCESS) → 获取当前 ACL
2. acl_create_entry(&acl, &entry)       → 创建新条目
3. acl_set_tagtype(entry, ACL_USER)     → 设为指定用户
4. acl_set_qualifier(entry, &uid)       → 设置 UID
5. acl_get_permset(entry, &permset)     → 获取权限集
6. acl_add_perm(permset, ACL_READ)     → 添加读权限
7. acl_valid(acl)                       → 校验合法性
8. acl_set_file(path, ACL_TYPE_ACCESS, acl) → 写回
9. acl_free(acl)                         → 释放

HFT / 嵌入式关联

  • 多用户共享行情数据：ACL 可授权特定用户读取行情数据目录，而无需修改属组
  • 嵌入式：libacl 通常不预装在精简嵌入式系统上；若需 ACL 支持需交叉编译 libacl + 依赖 libattr

代码示例

#include <sys/acl.h>
#include <stdio.h>
#include <stdlib.h>

int show_acl(const char *path) {
    acl_t acl = acl_get_file(path, ACL_TYPE_ACCESS);
    if (acl == NULL) { perror("acl_get_file"); return -1; }

    acl_entry_t entry;
    acl_tag_t tag;
    uid_t *uid_p;
    acl_permset_t permset;
    int entry_id = ACL_FIRST_ENTRY;

    while (acl_get_entry(acl, entry_id, &entry) == 1) {
        entry_id = ACL_NEXT_ENTRY;
        acl_get_tagtype(entry, &tag);

        char *tag_str;
        switch (tag) {
            case ACL_USER_OBJ:  tag_str = "USER_OBJ"; break;
            case ACL_USER:      tag_str = "USER"; break;
            case ACL_GROUP_OBJ: tag_str = "GROUP_OBJ"; break;
            case ACL_GROUP:     tag_str = "GROUP"; break;
            case ACL_MASK:      tag_str = "MASK"; break;
            case ACL_OTHER:     tag_str = "OTHER"; break;
            default:            tag_str = "?"; break;
        }

        acl_get_permset(entry, &permset);
        int r = acl_get_perm(permset, ACL_READ);
        int w = acl_get_perm(permset, ACL_WRITE);
        int x = acl_get_perm(permset, ACL_EXECUTE);

        if (tag == ACL_USER || tag == ACL_GROUP) {
            uid_p = acl_get_qualifier(entry);
            printf("%s:%u  %c%c%c\n", tag_str, *uid_p,
                   r ? 'r':'-', w?'w':'-', x?'x':'-');
        } else {
            printf("%-10s  %c%c%c\n", tag_str,
                   r?'r':'-', w?'w':'-', x?'x':'-');
        }
    }
    acl_free(acl);
    return 0;
}

/* 给指定用户添加读权限 */
int grant_read(const char *path, uid_t uid) {
    acl_t acl = acl_get_file(path, ACL_TYPE_ACCESS);
    if (!acl) { perror("acl_get_file"); return -1; }

    acl_entry_t entry;
    acl_create_entry(&acl, &entry);
    acl_set_tagtype(entry, ACL_USER);
    acl_set_qualifier(entry, &uid);

    acl_permset_t permset;
    acl_get_permset(entry, &permset);
    acl_add_perm(permset, ACL_READ);

    if (acl_valid(acl) != 0) {
        fprintf(stderr, "ACL invalid after modification\n");
        acl_free(acl);
        return -1;
    }

    if (acl_set_file(path, ACL_TYPE_ACCESS, acl) != 0) {
        perror("acl_set_file");
        acl_free(acl);
        return -1;
    }
    acl_free(acl);
    return 0;
}

代码自测

1. ACL_MASK 的作用是什么？如果不设置会怎样？

ACL_MASK 是最大有效权限掩码，限制了 ACL_USER、ACL_GROUP、ACL_GROUP_OBJ 条目的有效权限。当 ACL 中存在 ACL_USER 或 ACL_GROUP 条目时，内核自动添加 ACL_MASK。如果不显式设置，acl_valid() 可能失败；即使通过，实际有效权限会被掩码截断。

例如：ACL_USER:1000 rwx + ACL_MASK: r-- → 用户 1000 的有效权限只有 r。

2. 如何为目录设置 default ACL，使新文件自动继承权限？

使用 acl_get_file(dir, ACL_TYPE_DEFAULT) 获取默认 ACL，修改后用 acl_set_file(dir, ACL_TYPE_DEFAULT, acl) 写回。新建在目录中的文件会继承 default access ACL（经过掩码后的副本），新建子目录会同时继承 default ACL 本身。

3. acl_valid() 校验失败可能有哪些原因？
  • 缺少必需条目：必须恰好有一个 ACL_USER_OBJ、ACL_GROUP_OBJ、ACL_OTHER
  • 有 ACL_USER 或 ACL_GROUP 条目但没有 ACL_MASK
  • ACL_USER 条目的限定符（UID）重复
  • 权限集包含非法值

代码自测

1. minimum ACL 和 extended ACL 的区别？
  • minimum ACL：仅含 ACL_USER_OBJ + ACL_GROUP_OBJ + ACL_OTHER，完全等价于传统的 9 位权限模式（rwxrwxrwx）
  • extended ACL：添加了 ACL_USER / ACL_GROUP / ACL_MASK 条目，突破传统模型，允许为额外用户/组单独设置权限
2. getfacl 输出中 #effective: 标记是什么含义？

当存在 ACL_MASK 时，getfacl 显示每个受掩码影响的条目的名义权限和有效权限。#effective: 后面是经过掩码 AND 运算后的实际有效权限。例如：

group:dev:rw-    #effective:r--     ← MASK 只有 r

表示 dev 组的名义权限是 rw-，但因 MASK 限制实际只有 r--。

练习 1 参考框架

#include <sys/acl.h>
#include <pwd.h>
#include <grp.h>
#include <stdio.h>

void print_perm(acl_permset_t p) {
    printf("%c%c%c",
        acl_get_perm(p, ACL_READ) ? 'r' : '-',
        acl_get_perm(p, ACL_WRITE) ? 'w' : '-',
        acl_get_perm(p, ACL_EXECUTE) ? 'x' : '-');
}

void show_acl(const char *path, acl_type_t type) {
    acl_t acl = acl_get_file(path, type);
    if (!acl) return;

    /* 获取 mask 用于 effective 计算 */
    acl_entry_t e;
    acl_permset_t mask_perm = NULL;
    int id = ACL_FIRST_ENTRY;
    while (acl_get_entry(acl, id, &e) == 1) {
        id = ACL_NEXT_ENTRY;
        acl_tag_t tag;
        acl_get_tagtype(e, &tag);
        if (tag == ACL_MASK) {
            acl_get_permset(e, &mask_perm);
            break;
        }
    }

    /* 第二遍：打印 */
    id = ACL_FIRST_ENTRY;
    while (acl_get_entry(acl, id, &e) == 1) {
        id = ACL_NEXT_ENTRY;
        acl_tag_t tag;
        acl_get_tagtype(e, &tag);
        acl_permset_t ps;
        acl_get_permset(e, &ps);

        switch (tag) {
        case ACL_USER_OBJ: printf("user:");  print_perm(ps); break;
        case ACL_USER: {
            uid_t *u = acl_get_qualifier(e);
            struct passwd *pw = getpwuid(*u);
            printf("user:%s", pw ? pw->pw_name : "???");
            print_perm(ps);
            if (mask_perm) { printf("\t\t#effective:"); print_perm(ps & *(acl_permset_t*)mask_perm); }
            break;
        }
        case ACL_GROUP_OBJ: printf("group:"); print_perm(ps); break;
        case ACL_GROUP: {
            gid_t *g = acl_get_qualifier(e);
            struct group *gr = getgrgid(*g);
            printf("group:%s", gr ? gr->gr_name : "???");
            print_perm(ps);
            break;
        }
        case ACL_MASK: printf("mask:"); print_perm(ps); break;
        case ACL_OTHER: printf("other:"); print_perm(ps); break;
        }
        printf("\n");
    }
    acl_free(acl);
}

练习 3 答案

继承规则： - 新文件继承目录的 default ACL 作为 access ACL - 但新建普通文件的 ACL_EXECUTE 杁会被清除（umask 不影响 ACL 继承，但执行位继承有限制） - 新建子目录继承 default ACL 作为自己的 default ACL（递归继承） - 具体行为：acl_create_entry 时内核根据对象类型自动过滤
