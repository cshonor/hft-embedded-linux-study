章节目标

理解分区与传统 FS 布局（以 ext2 为范例）、inode 与路径解析；掌握 VFS 抽象；区分磁盘 FS / tmpfs / 日志 FS；会 mount/umount 与 statvfs；打通硬件 ↔ VFS ↔ 应用。

14.10 速查：statfs vs statvfs · 挂载标志

statfs statvfs
可移植 Linux 等扩展 POSIX/SUSv3
结构体 struct statfs struct statvfs
建议 Linux 专用够用 跨平台首选
flag 作用一句话
MS_RDONLY 只读挂载
MS_NOEXEC 不能在此执行程序
MS_NOSUID setuid 位无效
MS_REMOUNT 原地改选项
MS_BIND 绑定镜像目录树
MNT_DETACH 懒卸载
MNT_FORCE 强制卸载（危险）

14.11 易错清单

  1. inode 号仅在同一 FS 内可比；硬链接不能跨 FS
  2. unlink：链接计数→0 且无打开者 → 才真正释放数据块
  3. 挂载遮盖：别把重要目录当挂载点却忘了「底下有东西」
  4. tmpfs 吃内存/swap，不占普通磁盘配额语义
  5. dentry 是内核缓存，不落盘
  6. 日志 ≠ 用户数据已持久化；关键写仍要 fsync/fdatasync
  7. 可移植：statvfs；挂载信息可解析 /proc/mounts

练习

  1. statvfs 简易 df
  2. root 下 MS_BIND 绑定挂载再卸载
  3. 同分区硬链接 inode 相同；跨分区对比 inode
  4. （选）MS_RDONLY / MS_NOEXEC 行为
  5. 解析 /proc/mounts

背诵卡

# 要点
1 文件名在目录块；元数据在 inode
2 inode# 仅同 FS 有效；硬链接不跨分区
3 VFS：super_block / inode / dentry / file
4 单一目录树 + 挂载点（遮盖原内容）
5 可移植查容量用 statvfs；df 同源
6 日志保元数据恢复速度；数据落盘仍靠 fsync

代码示例

#include <stdio.h>
#include <sys/statfs.h>
#include <sys/vfs.h>
#include <dirent.h>
#include <string.h>

/* Ch14 文件系统 — statfs 获取文件系统信息 + 遍历目录。
 * 编译: gcc -o ch14_demo ch14_demo.c */

int main(void) {
    /* statfs: 文件系统整体信息 */
    struct statfs fs;
    if (statfs("/", &fs) == 0) {
        printf("Filesystem on /:\n");
        printf("  type:        %x\n", (unsigned)fs.f_type);
        printf("  block size:  %ld\n", (long)fs.f_bsize);
        printf("  total:       %ld blocks\n", (long)fs.f_blocks);
        printf("  free:        %ld blocks\n", (long)fs.f_bfree);
        printf("  available:   %ld blocks\n", (long)fs.f_bavail);
        printf("  max files:   %ld\n", (long)fs.f_files);
    }

    /* opendir/readdir: 遍历目录 */
    DIR *dir = opendir("/tmp");
    if (dir) {
        struct dirent *ent;
        printf("\nEntries in /tmp:\n");
        while ((ent = readdir(dir)) != NULL) {
            if (ent->d_name[0] != '.')
                printf("  %s (type=%d)\n", ent->d_name, ent->d_type);
        }
        closedir(dir);
    }
    return 0;
}

14.1

设备特殊文件

本章：TLPI 第 14 章 — File Systems - 上一节：本章首页 - 下一节：14.2 磁盘与分区

本节讲什么

/dev 下节点代表设备；内容不在该「文件」里，内核用主/次设备号找驱动。 ---

要点

/dev 下节点代表设备；内容不在该「文件」里，内核用主/次设备号找驱动。

类型 访问方式 例子
块设备 可随机、按块、可经页缓存 /dev/sda1、NVMe 分区
字符设备 流式、通常无块缓冲语义 /dev/tty、串口

HFT / 嵌入式关联

路线 要点
嵌入式 /dev 下字符/块设备节点让用户态统一 open 设备；mknod 创建设备文件是嵌入式固件定制常用手段
HFT 设备文件统一抽象，访问特殊设备（FPGA/网卡寄存器）走同一套 read/write 接口，无需专用 API

代码示例

#include <sys/statfs.h>
#include <stdio.h>

int main(void) {
    /* 查看文件系统信息 */
    struct statfs fs;
    if (statfs("/", &fs) != 0) { perror("statfs"); return 1; }

    printf("文件系统类型 magic = 0x%lx\n", fs.f_type);
    printf("块大小       = %ld\n", fs.f_bsize);
    printf("总块数       = %ld\n", fs.f_blocks);
    printf("空闲块数     = %ld\n", fs.f_bfree);
    printf("可用块数     = %ld\n", fs.f_bavail);
    printf("总 inode     = %ld\n", fs.f_files);
    printf("空闲 inode   = %ld\n", fs.f_ffree);

    /* 常见 f_type:
     * 0xEF53 → ext2/ext3/ext4
     * 0x58465342 → XFS
     * 0x9123683E → Btrfs
     */
    return 0;
}

14.2

磁盘与分区

本章：TLPI 第 14 章 — File Systems - 上一节：14.1 设备特殊文件 - 下一节：14.3 传统布局（ext2 范例）

本节讲什么

一块盘可多分区；一分区上 mkfs 出一个独立文件系统。 Linux 单一目录树：各 FS 通过挂载接到树上，应用只见路径。 ---

要点

一块盘可多分区；一分区上 mkfs 出一个独立文件系统。
Linux 单一目录树：各 FS 通过挂载接到树上，应用只见路径。

HFT / 嵌入式关联

路线 要点
嵌入式 分区表决定根文件系统布局，eMMC/SD 分区策略影响启动速度与磨损均衡
HFT 盘分区与挂载布局决定 I/O 隔离（日志/数据分盘），避免相互争抢 IOPS 拖慢交易

代码示例

#include <sys/stat.h>
#include <fcntl.h>
#include <unistd.h>
#include <stdio.h>

int main(void) {
    /* 设备文件: 块设备 vs 字符设备 */
    struct stat sb;

    /* 查看根分区设备 */
    if (stat("/", &sb) == 0) {
        printf("/ 的设备: major=%u minor=%u\n",
               major(sb.st_dev), minor(sb.st_dev));
        printf("/ 的类型: %s\n",
               S_ISDIR(sb.st_mode) ? "目录" : "其他");
    }

    /* /dev/null 是字符设备 */
    if (stat("/dev/null", &sb) == 0) {
        printf("/dev/null: %s (major=%u minor=%u)\n",
               S_ISCHR(sb.st_mode) ? "字符设备" : "其他",
               major(sb.st_rdev), minor(sb.st_rdev));
    }

    /* /dev/sda 是块设备 */
    if (stat("/dev/sda", &sb) == 0) {
        printf("/dev/sda: %s\n",
               S_ISBLK(sb.st_mode) ? "块设备" : "其他");
    }
    return 0;
}

14.3

传统布局（ext2 范例）

本章：TLPI 第 14 章 — File Systems - 上一节：14.2 磁盘与分区 - 下一节：14.4 i-node（核心）

本节讲什么

要点

区域 作用
Boot block 引导；首块常保留
Superblock 全局元数据：块数、inode 数、块大小、空闲量、类型/挂载状态；ext2 多处备份
inode table 所有 inode
Data blocks 文件内容、目录条目

文件名不在 inode 里，在目录的数据块：(name → inode#)。

HFT / 嵌入式关联

路线 要点
嵌入式 ext2 无日志，掉电后需 fsck，适合只读 rootfs；读写频繁场景用带日志 FS 换取掉电一致性
HFT 理解块组/超级块布局可定制块大小、inode 数等参数，减少元数据开销、优化顺序写吞吐

代码示例

#include <sys/statfs.h>
#include <stdio.h>

/* ext2/ext3/ext4 文件系统结构概念演示 */
int main(void) {
    struct statfs fs;
    if (statfs("/", &fs) != 0) { perror("statfs"); return 1; }

    /* ext 系列的 magic number */
    if (fs.f_type == 0xEF53) {
        printf("文件系统: ext2/ext3/ext4\n");
    } else {
        printf("文件系统 magic: 0x%lx (非 ext)\n", fs.f_type);
    }

    /* ext 文件系统结构:
     * - 引导块 (boot block)
     * - 块组 (block group): 超级块 + 组描述符 + 块位图 + inode位图 + inode表 + 数据块
     * - inode: 存文件元数据 (大小/权限/时间/数据块指针)
     * - 目录: 特殊文件, 内容是 entry 列表 (文件名→inode)
     */
    printf("块大小: %ld\n", fs.f_bsize);
    printf("每组 inode 数: %ld\n", fs.f_files);
    return 0;
}

14.4

i-node（核心）

本章：TLPI 第 14 章 — File Systems - 上一节：14.3 传统布局（ext2 范例） - 下一节：14.5 VFS（Virtual File System）

本节讲什么

同一 文件系统内 inode 号唯一；跨 FS 比较 inode 无意义。硬链接不能跨分区。 inode 常含：类型与权限、UID/GID、硬链接计数、大小、atime/mtime/ctime、数据块指针（直接/一二级间接等）。 目录 = 特殊文件，数据块存名字映射。

要点

同一 文件系统内 inode 号唯一；跨 FS 比较 inode 无意义。硬链接不能跨分区。

inode 常含：类型与权限、UID/GID、硬链接计数、大小、atime/mtime/ctime、数据块指针（直接/一二级间接等）。

是 否
元数据 + 块指针 文件名

目录 = 特殊文件，数据块存名字映射。

路径解析 /home/xxx/file.txt（示意）

根 inode → 找 home → xxx → file.txt 的 inode → 按块指针读数据。

Demo：code/print_inode.c

HFT / 嵌入式关联

路线 要点
嵌入式 inode 存元数据不含文件名（文件名在目录数据块），硬链接共享同一 inode，链接计数归零才释放
HFT stat 开销走 inode 缓存；理解 inode 与目录项分离，可优化海量小文件的元数据密集操作

代码示例

#include <sys/stat.h>
#include <stdio.h>

int main(void) {
    struct stat sb;

    /* stat 获取 inode 信息 */
    if (stat("/etc/passwd", &sb) != 0) { perror("stat"); return 1; }

    printf("inode 号: %lu\n", sb.st_ino);
    printf("硬链接数: %lu\n", sb.st_nlink);
    printf("文件大小: %ld\n", sb.st_size);
    printf("块大小:   %ld\n", sb.st_blksize);
    printf("分配块数: %ld\n", sb.st_blocks);

    /* 两个不同路径指向同一 inode → 硬链接 */
    struct stat sb2;
    if (stat("/etc/alternatives/editor", &sb2) == 0) {
        if (sb.st_ino == sb2.st_ino) {
            printf("同一 inode (硬链接)\n");
        }
    }
    return 0;
}

14.5

VFS（Virtual File System）

本章：TLPI 第 14 章 — File Systems - 上一节：14.4 i-node（核心） - 下一节：14.6 日志 FS 与内存 FS

本节讲什么

统一 open/read/write；下层可以是 ext4 / xfs / tmpfs / nfs… ---

要点

统一 open/read/write；下层可以是 ext4 / xfs / tmpfs / nfs…

对象 角色
super_block 一次挂载实例
inode FS 内对象
dentry 名字 ↔ inode 缓存（内存，加速查找）
file 打开文件上下文（与 fd 对应）

HFT / 嵌入式关联

路线 要点
嵌入式 VFS 用 super_block/inode/dentry/file 四对象统一不同 FS，让所有 FS 共用同一套系统调用
HFT VFS 层 dentry 缓存命中与否决定 open/stat 延迟；冷路径 open 会触发磁盘元数据读，需预热

代码示例

#include <stdio.h>
#include <fcntl.h>
#include <unistd.h>
/* VFS: 虚拟文件系统, 统一接口访问不同文件系统 */
int main(void) {
    /* 同样的 open/read/write 接口:
     * 普通文件 (ext4), 设备文件 (/dev/null), proc (/proc/version) */
    int fd1 = open("/etc/hostname", O_RDONLY);
    int fd2 = open("/dev/null", O_WRONLY);
    int fd3 = open("/proc/version", O_RDONLY);

    char buf[256];
    if (fd1 >= 0) { read(fd1, buf, 20); buf[20]='\0'; printf("file: %s", buf); close(fd1); }
    if (fd3 >= 0) { read(fd3, buf, 50); buf[50]='\0'; printf("proc: %.50s...\n", buf); close(fd3); }
    if (fd2 >= 0) { write(fd2, "anything", 8); close(fd2); }
    return 0;
}

14.6

日志 FS 与内存 FS

本章：TLPI 第 14 章 — File Systems - 上一节：14.5 VFS（Virtual File System） - 下一节：14.7 挂载点与单一目录树

本节讲什么

日志模式（概念）： 常见：ext3/4、XFS、Btrfs… tmpfs：全在内存（+可 swap）；断电丢；/dev/shm 常为 tmpfs。

要点
ext2（无日志） 崩溃后常需全盘 fsck，大盘极慢
日志 FS 先记事务再改正式结构；崩溃后重放日志

日志模式（概念）：

模式 要点
Journal 元数据+数据都进日志（最稳、最慢）
Ordered（ext4 常见默认） 先写数据，再记元数据日志
Writeback 主要保证元数据；数据顺序弱、更快、风险大

常见：ext3/4、XFS、Btrfs…
tmpfs：全在内存（+可 swap）；断电丢；/dev/shm 常为 tmpfs。

日志默认不替代用户数据 fsync；元数据恢复 ≠ 「你的 write 已落盘」。见 Ch13。

HFT / 嵌入式关联

路线 要点
嵌入式 tmpfs 常驻 RAM 掉电即失适合临时文件；日志 FS（ext4）掉电更稳但有写放大，按数据重要性选型
HFT 行情/订单等热数据放 tmpfs/ramfs 拿零磁盘延迟；持久数据用 ordered 日志模式平衡一致性

代码示例

#include <sys/mount.h>
#include <sys/statfs.h>
#include <stdio.h>

int main(void) {
    /* 挂载信息在 /proc/mounts */
    FILE *fp = fopen("/proc/mounts", "r");
    if (!fp) { perror("fopen"); return 1; }

    char line[512];
    printf("=== 挂载的文件系统 (前10行) ===\n");
    for (int i = 0; i < 10 && fgets(line, sizeof(line), fp); i++) {
        printf("%s", line);
    }
    fclose(fp);

    /* statfs 查看特定挂载点 */
    struct statfs fs;
    if (statfs("/tmp", &fs) == 0) {
        printf("\n/tmp: type=0x%lx, bsize=%ld\n", fs.f_type, fs.f_bsize);
    }
    return 0;
}

14.7

挂载点与单一目录树

本章：TLPI 第 14 章 — File Systems - 上一节：14.6 日志 FS 与内存 FS - 下一节：14.8 mount / umount（需特权，如 CAP_SYS_ADMIN）

本节讲什么

分区 FS 必须挂到某目录（挂载点）才可访问。 挂载后：挂载点原内容被遮住；卸载后恢复。 - 同一 FS 可挂到多处

要点

分区 FS 必须挂到某目录（挂载点）才可访问。
挂载后：挂载点原内容被遮住；卸载后恢复。

  • 同一 FS 可挂到多处
  • 可在已有树上再叠一层挂载

HFT / 嵌入式关联

路线 要点
嵌入式 统一目录树把不同分区挂到单一命名空间；/proc、/sys 伪 FS 提供运行时内核信息
HFT 高频读写目录挂 tmpfs、低频持久目录挂磁盘，用挂载点做存储分层，隔离冷热 I/O

代码示例

#include <dirent.h>
#include <sys/stat.h>
#include <stdio.h>

int main(void) {
    /* 目录的本质: 存储文件名→inode 映射表 */
    DIR *dir = opendir("/tmp");
    if (!dir) { perror("opendir"); return 1; }

    struct dirent *entry;
    while ((entry = readdir(dir)) != NULL) {
        /* 跳过 . 和 .. */
        if (entry->d_name[0] == '.' && entry->d_name[1] == '\0') continue;
        if (entry->d_name[0] == '.' && entry->d_name[1] == '.') continue;

        /* d_type: 文件类型 */
        const char *type;
        switch (entry->d_type) {
            case DT_REG:  type = "文件"; break;
            case DT_DIR:  type = "目录"; break;
            case DT_LNK:  type = "链接"; break;
            case DT_CHR:  type = "字符设备"; break;
            case DT_BLK:  type = "块设备"; break;
            default:      type = "其他"; break;
        }
        printf("%-20s inode=%-10lu %s\n", entry->d_name, entry->d_ino, type);
    }
    closedir(dir);
    return 0;
}

14.10

A Virtual Memory File System: tmpfs

本章：TLPI 第 14 章 — File Systems

本节讲什么

介绍 tmpfs——Linux 基于内存的虚拟文件系统。文件数据完全驻留在页缓存中，不写磁盘，重启后数据丢失。

要点

tmpfs 特性

特性 说明
存储介质 内存（RAM）+ swap（可能换出）
持久性 无（重启丢失）
速度 接近内存读写速度
大小限制 挂载时指定 size=，默认为 RAM 的 50%
特殊用途 /tmp、/dev/shm、/run、/sys/fs/cgroup

tmpfs vs ramfs vs 磁盘文件系统

特性 tmpfs ramfs ext4
存储 RAM + swap RAM only 磁盘
大小限制 有（size=） 无（可能 OOM） 磁盘大小
Swap 支持 不支持 —
持久性 无 无 有
用途 /tmp, /dev/shm 内核内部 通用

挂载选项

# 基本挂载
mount -t tmpfs -o size=1G tmpfs /mnt/tmp

# 常见选项
mount -t tmpfs -o size=512M,mode=1777,uid=1000,gid=1000 tmpfs /mnt/tmp
选项 默认 说明
size=N RAM 50% 最大容量
nr_blocks=N — 最大块数
nr_inodes=N — 最大 inode 数
mode=NNN 1777 权限
uid=N 0 属主 UID
gid=N 0 属组 GID
mpol=... — NUMA 策略

系统默认 tmpfs 挂载

挂载点 用途 典型大小
/dev/shm POSIX 共享内存 RAM 的 50%
/run 运行时文件（PID 等） RAM 的 5-10%
/tmp 临时文件（部分发行版） RAM 的 50%
/sys/fs/cgroup cgroup2 小

tmpfs 内存使用

写入 1GB 文件到 tmpfs:
  → 页缓存分配 1GB（匿名页）
  → 如果 RAM 不足 → 换出到 swap
  → 读取时从 swap 换回 RAM
  → umount / 删除 → 立即释放
  • tmpfs 页面标记为匿名页（anonymous page），可被换出
  • free -m 中的 shared 列包含 tmpfs 占用
  • df 命令显示 tmpfs 使用量

HFT / 嵌入式关联

  • 共享内存：/dev/shm 是 POSIX shm_open 的默认路径，HFT 进程间共享行情数据
  • 临时数据：HFT 回测中间结果放 /tmp（tmpfs），避免磁盘 I/O
  • NUMA：mpol=bind:0 绑定 tmpfs 到特定 NUMA 节点，减少跨节点访问延迟
  • 嵌入式：无磁盘的嵌入式系统用 tmpfs 作为可写文件系统
  • 启动加速：init 脚本 tmp 文件放 tmpfs，启动更快
  • 容量控制：HFT 场景下 tmpfs size 不可过大，防止挤压行情数据

# 检查 tmpfs 使用情况
df -h /dev/shm /tmp /run

# 挂载 tmpfs
sudo mount -t tmpfs -o size=2G,mode=1777 tmpfs /mnt/hft_shm

# /etc/fstab 永久挂载

代码自测

1. tmpfs 和 ramfs 的区别？为什么 tmpfs 更常用？
  • ramfs：纯内存，无大小限制，可能导致 OOM（持续分配直到耗尽 RAM，无法回收）
  • tmpfs：有大小限制（size=），支持 swap 换出，可控制用量

tmpfs 更常用因为：(1) 有大小限制防止 OOM；(2) 支持 swap，内存压力时可以换出；(3) 内核维护统计信息；(4) 是 tmpfs 而非 ramfs 被用于 /tmp//dev/shm//run。

2. tmpfs 中的文件被 swap out 后，性能有什么影响？

tmpfs 页面被换出后，读取需要从 swap 空间换回 RAM，产生磁盘 I/O 延迟（如果 swap 在 SSD 上约 50-100μs，HDD 上约 5-10ms）。对于 HFT 场景，这可能导致微秒级操作突然变成毫秒级延迟。因此 HFT 系统：(1) 关闭 swap（swapoff -a）；(2) 限制 tmpfs 大小；(3) 用 mlock 锁定关键共享内存。

3. 如何限制 tmpfs 的 inode 数量？为什么需要限制？

mount -t tmpfs -o nr_inodes=10000 tmpfs /mnt/tmp。限制 inode 防止大量小文件耗尽内存（每个 inode 占用约 320 字节内核内存）。恶意程序可以创建大量小文件消耗系统内存，限制 inode 数量是一种防护。

练习 1 参考代码

#include "tlpi_hdr.h"
#include <sys/statvfs.h>

int main(int argc, char *argv[]) {
    if (argc != 2) usageErr("usage: %s <path>\n", argv[0]);

    struct statvfs buf;
    if (statvfs(argv[1], &buf) != 0) errExit("statvfs");

    unsigned long block_size = buf.f_frsize;
    unsigned long total = buf.f_blocks * block_size;
    unsigned long free = buf.f_bfree * block_size;
    unsigned long avail = buf.f_bavail * block_size;
    unsigned long used = total - free;

    printf("File system: %s\n", argv[1]);
    printf("Block size    : %lu bytes\n", block_size);
    printf("Total size    : %.2f GB\n", (double)total / (1<<30));
    printf("Used          : %.2f GB (%.1f%%)\n",
           (double)used / (1<<30), 100.0 * used / total);
    printf("Available     : %.2f GB\n", (double)avail / (1<<30));
    printf("Total inodes  : %lu\n", buf.f_files);
    printf("Free inodes   : %lu\n", buf.f_ffree);
    printf("Max name len  : %lu\n", buf.f_namemax);
    return 0;
}

#include <stdio.h>
#include <fcntl.h>
#include <time.h>
#include <unistd.h>
#include <string.h>

#define SIZE (100 * 1024 * 1024)  /* 100MB */
#define BUF_SIZE 4096

void bench_write(const char *path) {
    int fd = open(path, O_WRONLY | O_CREAT | O_TRUNC, 0644);
    char buf[BUF_SIZE];
    memset(buf, 'x', sizeof(buf));

    struct timespec start, end;
    clock_gettime(CLOCK_MONOTONIC, &start);
    for (int i = 0; i < SIZE / BUF_SIZE; i++)
        write(fd, buf, sizeof(buf));
    fsync(fd);
    clock_gettime(CLOCK_MONOTONIC, &end);
    close(fd);

    long long ns = (end.tv_sec - start.tv_sec) * 1000000000LL
                 + (end.tv_nsec - start.tv_nsec);
    printf("%-20s write: %lld ms (%.1f MB/s)\n", path,
           ns / 1000000, (double)SIZE / (ns / 1000) * 1000 / (1<<20));
    unlink(path);
}

int main(void) {
    bench_write("/dev/shm/tmpfs_test");
    bench_write("./disk_test");
    return 0;
}
