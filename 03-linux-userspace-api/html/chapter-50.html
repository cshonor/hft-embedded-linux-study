对比速记

调用 作用 权限 关键实测结论
mprotect 改 r/w/x 不超 fd 模式（EACCES） 违例 SIGSEGV；W^X 加固
mlock* 禁 swap RLIMIT_MEMLOCK / CAP_IPC_LOCK 超限 ENOMEM（非 EPERM）；MS_INVALIDATE→EBUSY
mincore 驻留快照 无权限文件映射静默 0 零页 mincore=1 但 Rss=0
madvise 访问提示 advice 合法即可 DONTNEED：匿名→0，文件 PRIVATE→原内容

易错清单

  1. mlock 超限返回 ENOMEM，不是 EPERM（EPERM 只在「限额 0 且无 CAP_IPC_LOCK」）
  2. mincore 对无权限文件映射静默返回全 0（v6.6 can_do_mincore() 防侧信道），不是「真的不在内存」
  3. 零页：mincore 说驻留、Rss 不计——两个口径不同
  4. MADV_DONTNEED 匿名映射读回 0；文件 PRIVATE 读回文件内容——不是同一件事
  5. MADV_FREE 是 lazyfree（内存压力前数据还在），不能当确定性清零用
  6. MCL_FUTURE 让后续 mmap/malloc 静默受限额约束——错误会在离 mlockall 很远的地方爆
  7. mincore 是瞬时快照，不能做同步条件
  8. mprotect 的 addr 必须页对齐（EINVAL），length 内核取整
  9. W^X：同页避免 W+X；JIT 写完改 R|X（ARM64 还需 __clear_cache 同步 I-cache）

50.1

修改内存保护：mprotect()

源码核验：Linux v6.6 · mm/mprotect.c（do_mprotect_pkey():690 · change_protection():513 · change_protection_range():483 · change_pte_range():83） 本章：TLPI 第 50 章 — Virtual Memory Operations - 上一节：本章首页 - 下一节：50.2 mlock / mlockall

本节讲什么

mprotect() 修改已有映射（mmap 区 / 堆 / 栈均可）的保护属性。三个灵魂问题：

  1. 改保护 = 改什么？（PTE 的 rwx 位，不是重新分配内存）
  2. 什么能改、什么不能改？（不能超过映射后备的权限——只读 fd 映射不可加 PROT_WRITE）
  3. 违反保护会怎样？（CPU 陷阱 → SIGSEGV，不是返回错误）
#include <sys/mman.h>
int mprotect(void *addr, size_t length, int prot);
/* 返回 0 成功；-1 失败（errno: EACCES/EINVAL/ENOMEM/ENOTSUP） */

要点

参数规则

规则 说明
addr 必须页对齐 否则 EINVAL（内核不做静默取整，munmap 同理）
length 内核向上取整到页 与 mmap 一致
作用于任何已有 VMA mmap 区、brk 堆、栈、vDSO——只要在进程地址空间内
可跨多个 VMA 一次调用覆盖的区间里夹着别的映射也照改（按 VMA 逐个处理）

prot 四位组合

prot 读 写 执行 典型用途
PROT_NONE ❌ ❌ ❌ guard 页、延迟分配区
PROT_READ ✅ ❌ ❌ 只读配置、字符串常量区
PROT_READ\|PROT_WRITE ✅ ✅ ❌ 普通数据
PROT_READ\|PROT_EXEC ✅ ❌ ✅ 代码段（text）
PROT_READ\|PROT_WRITE\|PROT_EXEC ✅ ✅ ✅ JIT 生成期（现代系统尽量回避）

权限天花板：不能超过后备权限

  • 文件映射：prot 不得超过 open() 时的模式——O_RDONLY 打开的 fd，mprotect 加 PROT_WRITE → EACCES
  • 匿名映射：天花板就是 mmap 时的 prot——匿名区无后备文件，但 mmap 后可以放宽或收紧吗？可以：匿名私有映射 mprotect 加 PROT_EXEC 通常成功（除非 SELinux/mmap_min_addr 等 LSM 限制）
  • W^X 原则（现代内核加固）：同一页尽量避免同时 Write+Execute——写完代码改 R|X，见下方 JIT 用法

内核路径（v6.6 实测核验）

mprotect(2)
 └─ do_mprotect_pkey()              mm/mprotect.c:690
     ├─ 遍历 [start,end) 内每个 VMA（vma_iterator）
     ├─ 权限校验：prot & ~旧 vma 可写位？→ 文件映射查 MAY_WRITE → EACCES
     └─ mprotect_fixup() → change_protection()      mm/mprotect.c:513
         └─ change_protection_range()                mm/mprotect.c:483
             └─ change_pte_range()                   mm/mprotect.c:83
                 ├─ 逐 PTE 改 prot 位（pte_modify）
                 ├─ 脏页记账：VM_SHARED 可写映射改只读时标记 dirty_accountable
                 └─ TLB flush：change_protection_end() → flush_tlb_range()

关键细节：change_pte_range() 只改已建立的 PTE；尚未缺页的地址在下次缺页时按新 vm_page_prot 建立。所以 mprotect 是「改 VMA 属性 + 顺手改现存 PTE + 刷 TLB」三件事。

错误码速查

errno 触发条件
EINVAL addr 未页对齐 / prot 非法 / 区间不在任何映射内（部分实现）
EACCES 要求的权限超过 fd 打开模式（文件映射）
ENOMEM 内核内部结构分配失败 / 区间不是进程映射
ENOTSUP 文件系统不支持（个别 fs）

HFT / 嵌入式关联

路线 要点
嵌入式 JIT 固件：PROT_READ\|PROT_WRITE 写码 → mprotect 改 PROT_READ\|PROT_EXEC 执行，现代强制 W^X 防注入；只读配置区 PROT_READ 防误写（违例立刻 SIGSEGV 而不是悄悄破坏）
HFT 订单簿共享区在「快照读」阶段设 PROT_READ，防策略代码误写关键数据；热路径代码段 PROT_READ\|PROT_EXEC + W^X 加固；PROT_NONE guard 页夹住热缓冲，越界访问第一时间报 SIGSEGV 而不是踩坏邻居

代码示例


/* mprotect 三段式：PROT_NONE 触发 SIGSEGV → 恢复 RW 写入成功
 * 实测（WSL Ubuntu，gcc -O2 -Wall -Wextra，2026-09-05）：
 *   步骤1 PROT_NONE 写访问……捕获 SIGSEGV ✓
 *        mprotect 恢复 RW 后写入成功 p[0]=3
 */
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <signal.h>
#include <setjmp.h>
#include <errno.h>
#include <sys/mman.h>
#include <unistd.h>

static sigjmp_buf jb;
static void segv_handler(int sig) { (void)sig; siglongjmp(jb, 1); }

int main(void)
{
    long pagesz = sysconf(_SC_PAGESIZE);
    char *p = mmap(NULL, (size_t)pagesz, PROT_READ | PROT_WRITE,
                   MAP_PRIVATE | MAP_ANONYMOUS, -1, 0);
    if (p == MAP_FAILED) { perror("mmap"); return 1; }
    p[0] = 1;                                  /* 先写一次（触发缺页分配） */

    signal(SIGSEGV, segv_handler);
    if (mprotect(p, (size_t)pagesz, PROT_NONE) != 0) {
        perror("mprotect NONE"); return 1;
    }
    printf("步骤1 PROT_NONE 写访问……");
    fflush(stdout);
    if (sigsetjmp(jb, 1) == 0) {
        p[0] = 2;                              /* 违反 PROT_NONE → SIGSEGV */
        printf("写入成功（异常！）\n");
    } else {
        printf("捕获 SIGSEGV ✓\n");
    }

    if (mprotect(p, (size_t)pagesz, PROT_READ | PROT_WRITE) != 0) {
        perror("mprotect RW"); return 1;
    }
    p[0] = 3;                                  /* 恢复后写入正常 */
    printf("     mprotect 恢复 RW 后写入成功 p[0]=%d\n", p[0]);

    munmap(p, (size_t)pagesz);
    return 0;
}

为什么用 sigsetjmp 而不是 setjmp：SIGSEGV 是同步信号，handler 里 siglongjmp 跳出后内核已把栈上的信号帧清理；sigsetjmp(…, 1) 同时保存被阻塞的信号掩码，防止 SIGSEGV 在 handler 期间被屏蔽后不再递送。

自测题

题目 1（选择）： mprotect(p, len, PROT_READ) 对一个 MAP_SHARED 可写映射调用后，已写的脏页会怎样？

参考答案

脏页记账被保留。change_pte_range()（mm/mprotect.c:83）处理 VM_SHARED 可写映射降权时会标记 dirty_accountable，把「PTE 曾可写期间产生的脏」正确传给反向映射，保证后续回写不丢数据。

题目 2（判断）： 匿名映射 mmap 时只给了 PROT_READ，之后可以用 mprotect 加上 PROT_WRITE。

参考答案

可以。匿名映射没有后备文件，不存在「超过 fd 打开模式」的天花板；mprotect 直接改 VMA 属性。但文件映射不行——O_RDONLY 的 fd 映射加写权限返回 EACCES。

题目 3（踩坑）： 以下代码在 ARM64 嵌入式 Linux 上运行，为什么可能直接崩溃？

void *code = mmap(NULL, 4096, PROT_WRITE, MAP_PRIVATE|MAP_ANONYMOUS, -1, 0);
memcpy(code, trampoline, sizeof(trampoline));
((void(*)(void))code)();
参考答案

映射只有 PROT_WRITE 没有 PROT_EXEC，跳转执行触发 SIGSEGV。修正：写完代码后 mprotect(code, 4096, PROT_READ|PROT_EXEC) 再执行（W^X 模式）。另外 ARM64 指令缓存与数据缓存不连贯（VIPT），JIT 还需要缓存同步（用户态通常由 __builtin___clear_cache 处理），这是嵌入式与 x86 的显著差异。

50.2

内存锁定：mlock() 与 mlockall()

源码核验：Linux v6.6 · mm/mlock.c（can_do_mlock():40 · __mlock_posix_error_return():566 · do_mlock():575 · SYSCALL_DEFINE2(mlock):622 · SYSCALL_DEFINE1(mlockall):705） 本章：TLPI 第 50 章 — Virtual Memory Operations - 上一节：50.1 mprotect - 下一节：50.3 驻留查询 mincore

本节讲什么

mlock 家族把页钉在物理内存（页标记 Mlocked，从 LRU 链表摘除），换出器永不回收。三个灵魂问题：

  1. 为什么要锁？（缺页/换入换出是毫秒级延迟毛刺的根源——HFT 大忌）
  2. 谁有资格锁？（RLIMIT_MEMLOCK 限额，超限返回什么？——ENOMEM，不是 EPERM，经典面试题）
  3. 锁住了什么？（只锁当前已驻留的页 + 顺带预填充；MCL_FUTURE 锁未来）
#include <sys/mman.h>
int mlock(const void *addr, size_t length);
int munlock(const void *addr, size_t length);
int mlock2(const void *addr, size_t length, int flags);   /* Linux 扩展 */
int mlockall(int flags);    /* MCL_CURRENT | MCL_FUTURE | MCL_ONFAULT(2) */
int munlockall(void);

要点

语义规则

规则 说明
mlock 立即预填充 do_mlock() 末尾 __mm_populate()：把区间内所有页当场缺页进来（不是等访问）
多次 mlock 不叠加 同区 mlock 两次，一次 munlock 即解除（无计数语义，与 fcntl 记录锁不同）
addr 页对齐，length 向上取整 与 mprotect 一致
fork：子进程继承锁 页在父子间 COW；VM_LOCKED 标志遗传给子 VMA
exec：全部解锁 新程序映像替换整个地址空间
munmap 自动解除该区锁定 生命周期跟随 VMA

权限模型（v6.6 can_do_mlock():40 逐行核验）

bool can_do_mlock(void)
{
    if (rlimit(RLIMIT_MEMLOCK) != 0)   /* 限额非零（哪怕 4KB）→ 有资格 */
        return true;
    if (capable(CAP_IPC_LOCK))         /* 或持有 CAP_IPC_LOCK */
        return true;
    return false;                      /* 否则 EPERM——限额为 0 且无特权 */
}

do_mlock():575 的限额检查（简化）：

locked = len >> PAGE_SHIFT;                     /* 本次请求页数 */
locked += current->mm->locked_vm;               /* 加已锁总数 */
if ((locked > lock_limit) && (!capable(CAP_IPC_LOCK)))
    /* error 保持初值 -ENOMEM → 返回 ENOMEM */

⭐ 错误码分界： - 限额为 0 且无 CAP_IPC_LOCK → EPERM（连资格都没有） - 有资格但超量 → ENOMEM（不是 EPERM！）——TLPI 与 man page 都强调这一点 - 另有 __mlock_posix_error_return():566：GUP 层的 -EFAULT→-ENOMEM、-ENOMEM→-EAGAIN（POSIX 规定的换算）

与 msync 的联动（实测验证）

msync(MS_INVALIDATE) 作用到带 VM_LOCKED 的区域 → EBUSY（mm/msync.c 的显式检查：if ((flags & MS_INVALIDATE) && (vma->vm_flags & VM_LOCKED)) error = -EBUSY）。锁定的页不允许从进程地址空间「作废」。

MCL_FUTURE 的坑

mlockall(MCL_CURRENT|MCL_FUTURE) 之后每次 mmap/malloc/栈增长都要过限额检查——超限时 mmap 返回 ENOMEM，malloc 返回 NULL。程序会以「莫名其妙的内存分配失败」形式死亡，而不是死在 mlock 调用点。

实测数据（WSL Ubuntu，2026-09-05）

RLIMIT_MEMLOCK soft=65536 kB hard=65536 kB     ← WSL Ubuntu 默认 64MB
mlock(128MB) = -1 errno=12(Cannot allocate memory)   ← 超限走 ENOMEM ✓
mlock(1 页) = 0 成功

注意 WSL 的默认限额（64MB）与桌面 Ubuntu 22.04（8MB）不同，脚本化部署时必须显式 ulimit -l / systemd LimitMEMLOCK。

HFT / 嵌入式关联

路线 要点
嵌入式 无 swap 的系统 mlock 几乎无意义（没地方换出），但预填充语义仍有价值——启动时把关键页摸一遍，避免运行时首次缺页抖动；RAM 紧张时锁多了直接挤爆伙伴系统（mlock 的页不参与回收 → 别人 OOM）
HFT mlockall(MCL_CURRENT\|MCL_FUTURE) 是行业标配：预热阶段把行情缓冲/策略热数据全部驻留，消除两类毛刺——缺页（µs 级）与换入换出（ms 级）；配套动作：① setrlimit/systemd LimitMEMLOCK=infinity（或 CAP_IPC_LOCK）② 预分配所有缓冲再 MCL_CURRENT ③ 慎用 MCL_FUTURE——它会掩盖「忘了锁哪块」的 bug，让 malloc 在意想不到的地方失败

实测经验：单纯 mlockall 不够——从未触碰过的页不在 MCL_CURRENT 的填充范围……不对，v6.6 的 mlockall→do_mlockall→apply_vma_lock_flags + __mm_populate 会主动填充全部当前 VMA；真正的坑是 MAP_NORESERVE 大映射 + mlockall 会把整个稀疏区灌满物理页。锁之前先想清楚区间的真实工作集大小。

代码示例


/* mlock 限额实测：超限 ENOMEM（非 EPERM）+ 小块成功
 * 实测（WSL Ubuntu，gcc -O2 -Wall -Wextra，2026-09-05）：
 *   RLIMIT_MEMLOCK soft=65536 kB hard=65536 kB
 *   mlock(128MB) = -1 errno=12(Cannot allocate memory)   ← 超限 ENOMEM
 *   mlock(1 页) = 0 成功
 */
#define _GNU_SOURCE
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <errno.h>
#include <sys/mman.h>
#include <sys/resource.h>
#include <unistd.h>

int main(void)
{
    long pagesz = sysconf(_SC_PAGESIZE);

    struct rlimit rl;
    if (getrlimit(RLIMIT_MEMLOCK, &rl) != 0) { perror("getrlimit"); return 1; }
    printf("RLIMIT_MEMLOCK soft=%lu kB hard=%lu kB\n",
           (unsigned long)rl.rlim_cur / 1024, (unsigned long)rl.rlim_max / 1024);

    char *p = mmap(NULL, (size_t)pagesz, PROT_READ | PROT_WRITE,
                   MAP_PRIVATE | MAP_ANONYMOUS, -1, 0);
    if (p == MAP_FAILED) { perror("mmap"); return 1; }

    /* 超限请求：按实测限额动态取 2 倍，保证真的超 */
    size_t big_len = 64UL << 20;
    if (big_len <= rl.rlim_cur) big_len = rl.rlim_cur * 2;
    char *big = mmap(NULL, big_len, PROT_READ | PROT_WRITE,
                     MAP_PRIVATE | MAP_ANONYMOUS, -1, 0);
    if (big == MAP_FAILED) { perror("mmap big"); return 1; }
    errno = 0;
    int r = mlock(big, big_len);
    printf("mlock(%zuMB) = %d", big_len >> 20, r);
    if (r != 0)
        printf(" errno=%d(%s)  ← 超限是 ENOMEM 不是 EPERM\n",
               errno, strerror(errno));
    munmap(big, big_len);

    errno = 0;
    r = mlock(p, (size_t)pagesz);
    printf("mlock(1 页) = %d %s\n", r, r ? strerror(errno) : "成功");

    munlock(p, (size_t)pagesz);
    munmap(p, (size_t)pagesz);
    return 0;
}

超限请求是安全的：do_mlock() 在限额检查不通过时不会执行填充（apply_vma_lock_flags 被跳过），64MB 只是虚拟区，一页物理内存都不会消耗。

参考答案

错误。mlock 无计数语义（与 fcntl 记录锁不同）：VMA 的 VM_LOCKED 是布尔标志，同区重复 mlock 幂等，一次 munlock 全解。跨进程各自 mlock 同一共享区时，页在所有引用者的 VMA 都解锁后才真正回到可换出状态。

50.3

驻留查询：mincore()

源码核验：Linux v6.6 · mm/mincore.c（mincore_pte_range():100 · can_do_mincore():158 · do_mincore():187 · SYSCALL_DEFINE3(mincore):232） 本章：TLPI 第 50 章 — Virtual Memory Operations - 上一节：50.2 mlock / mlockall - 下一节：50.4 访问提示 madvise

本节讲什么

mincore（MINimal CORE，名字来自「minimal information about core/residency」）查询区间内哪些页当前在物理内存。三个灵魂问题：

  1. 返回的 vec[i] & 1 到底是什么？（PTE present 位的快照——页表里有映射）
  2. 它能当同步条件吗？（不能——瞬时、非原子，查完的瞬间内核可能就把页回收了）
  3. 零页算驻留吗？（算！mincore 说 resident，RSS 却不计——两者口径不同）
#include <sys/mman.h>
int mincore(void *addr, size_t length, unsigned char *vec);
/* vec[i] & 1 == 1：第 i 页（从 addr 页对齐起点数）当前驻留 */

要点

三种 PTE 状态的处理（mincore_pte_range():100 逐行核验）

PTE 状态 vec 值 说明
pte_present(pte) 1 真页或零页（零页是 present+special 的特殊 PTE）——mincore 区分不了
空映射（pte_none） 0 还没缺页过
swap 项 mincore_page(swap cache) 查交换缓存 换出的页若还在 swap cache 里算 1
migration/hwpoison 项 1 迁移中的页视为驻留
透明大页（THP） memset(vec, 1, nr) 整块全 1 2MB 大页一次标满

⭐ 零页语义：mincore 与 RSS 的口径差（实测验证）

匿名私有映射只读触碰的页，内核映射零页（do_anonymous_page 只读分支，见 49.7）：

实测（WSL Ubuntu，2026-09-05）：
  4 页匿名映射：页 0 写触碰、页 1 读触碰、页 2/3 不碰
  mincore = [1,1,0,0]     ← 零页 present，mincore 说驻留
  同区 Rss = 4 kB         ← RSS 只算页 0 的真页（vm_normal_page 对零页返回 NULL）

一页内存，两个口径打架——mincore 回答「PTE 能直接翻译吗」，RSS 回答「这个进程独占多少真物理页」。

⭐ 无权限文件映射：静默返回 0（防侧信道，v6.6 新增语义）

can_do_mincore():158：对文件映射，仅当调用者能写该文件（或拥有 inode）才返回真实驻留信息；否则 do_mincore() 把整个 vec 填 0——不报错，就是不给真话：

static inline bool can_do_mincore(struct vm_area_struct *vma)
{
    if (vma_is_anonymous(vma)) return true;
    if (!vma->vm_file) return false;
    /* 只对「能以写模式打开对应文件」的映射泄露 page cache 驻留信息，
       否则构成侧信道（探测别的进程读了什么文件页） */
    return inode_owner_or_capable(...) || file_permission(vma->vm_file, MAY_WRITE) == 0;
}

这是 Spectre/Meltdown 时代加固的一部分：驻留模式本身是信息（能推断「谁在预读什么文件」）。

瞬时性与「非原子」

walk_page_range 逐页读 PTE 时只持该页表的 spinlock，页与页之间不连贯；返回用户态的过程中任何页都可能被回收/换出/换入。正确用法：诊断（启动后验证 mlock 生效、观察 MADV_DONTNEED 效果），不是同步原语。

错误码

errno 条件
EINVAL addr 未页对齐 / length ≥ UINTPTR_MAX/pagesize
ENOMEM 区间不在任何映射内（含未映射空洞）
EAGAIN（少见） 页表遍历时 PTE 竞态（ACTION_AGAIN）

HFT / 嵌入式关联

路线 要点
嵌入式 启动自检：预填充（mlock/MAP_POPULATE）后 mincore 全 1 即「热身完成」的可验证标准；XIP（eXecute In Place）场景 mincore 恒 1（NOR flash 直接映射）——用它区分「真 RAM 驻留」还是「flash 就地执行」时要小心口径
HFT mlockall 之后的验收步骤：对热缓冲 mincore 全 1 才能宣告「无缺页风险」；监控线程周期性采样非锁定区的驻留率，驻留率骤降 = 内存压力前兆（比等 swap 毛刺打在延迟分布上早得多）；注意对共享行情文件映射若无写权限，mincore 全 0 是假象（can_do_mincore 防侧信道分支）

/* mincore 零页口径差实测：mincore 说驻留，RSS 不认账
 * 实测（WSL Ubuntu，gcc -O2 -Wall -Wextra，2026-09-05）：
 *   mincore = [1,1,0,0]（预期 [1,1,0,0]：零页也算 resident）
 *   同区 Rss = 4 kB（预期 4：零页 present 却不计入 RSS）
 */
#define _GNU_SOURCE
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <sys/mman.h>
#include <unistd.h>

int main(void)
{
    long pagesz = sysconf(_SC_PAGESIZE);
    size_t P = (size_t)pagesz;

    char *q = mmap(NULL, 4 * P, PROT_READ | PROT_WRITE,
                   MAP_PRIVATE | MAP_ANONYMOUS, -1, 0);
    if (q == MAP_FAILED) { perror("mmap"); return 1; }

    q[0] = 1;                        /* 页 0：写触碰 → 分配真页 */
    volatile char c = q[P]; (void)c; /* 页 1：读触碰 → 映射零页 */
                                     /* 页 2/3：不触碰 */

    unsigned char vec[4];
    if (mincore(q, 4 * P, vec) != 0) { perror("mincore"); return 1; }
    printf("mincore = [%d,%d,%d,%d]（页0=写触碰 页1=读触碰零页）\n",
           vec[0] & 1, vec[1] & 1, vec[2] & 1, vec[3] & 1);
    printf("页 1 的零页：mincore 说 resident，但它是全局唯一共享页\n");
    return 0;
}

题目 1（选择）： 一个普通用户对别人拥有的文件的只读映射调用 mincore，返回的 vec 里全是 0，最可能的原因？

A. 文件页都不在内存　B. can_do_mincore 防侧信道拒绝泄露　C. 映射坏了　D. mincore 失败了

参考答案

B。v6.6 起 can_do_mincore():158 只对「能写该文件/拥有 inode」的映射返回真实驻留，否则静默填 0（不报错）。这是防侧信道加固——驻留模式能推断其他进程的文件访问行为。

题目 2（判断）： mincore 返回全 1 之后，程序可以放心访问整段区间而不会发生任何缺页。

参考答案

错误。mincore 是瞬时快照，无任何原子性保证——返回用户态的微秒级窗口里内核完全可以把页回收（尤其无 mlock 的普通匿名页）。要保证不缺页必须 mlock；mincore 只能做诊断/验收，不能做同步条件。

题目 3（应用）： 为什么页 1 读触碰后 mincore=1 而 Rss 不增加？写出两者的统计口径。

参考答案

读触碰的匿名私有页映射零页（全局唯一物理页，zero_pfn）。mincore 的口径是 PTE present（mincore_pte_range 里 pte_present(pte) → *vec = 1），零页 PTE 是 present+special，所以算 1；RSS 的口径是进程独占的真物理页（vm_normal_page() 对 special PTE 返回 NULL，跳过统计），零页全系统共享一份，不计入任何进程的 RSS。一句话：mincore 看「有没有映射」，RSS 看「占了多少真页」。

50.4

访问模式提示：madvise()

源码核验：Linux v6.6 · mm/madvise.c（madvise_need_mmap_write():50 · madvise_free_pte_range():625 · zap_page_range_single() 调用 :825 · madvise_dontneed_free():859 · do_madvise():1407 · SYSCALL_DEFINE3(madvise):1461） 本章：TLPI 第 50 章 — Virtual Memory Operations - 上一节：50.3 驻留查询 mincore - 下一节：50.5 总结

本节讲什么

madvise 向内核描述未来的访问模式，内核据此调整预读/回收/布局策略。三个灵魂问题：

  1. 提示的约束力？（内核可忽略——这不是命令，是 advice；只有 MADV_DONTNEED 等少数几个有确定语义）
  2. 最危险也最有用的是哪个？（MADV_DONTNEED：匿名映射的数据直接丢弃，读回全 0）
  3. MADV_FREE 和 MADV_DONTNEED 什么区别？（FREE 是「可反悔的丢弃」，内核保留内容直到内存紧张才真丢）
#include <sys/mman.h>
int madvise(void *addr, size_t length, int advice);
/* addr 页对齐；length 向上取整；作用于 [addr, addr+len) 覆盖的映射 */

要点

advice 全表（POSIX + Linux 扩展）

advice 语义 约束力
MADV_NORMAL 默认行为（恢复） 弱
MADV_RANDOM 关闭/减弱预读（随机访问，预读是浪费） 弱（改 readahead 窗口）
MADV_SEQUENTIAL 加倍预读 + 读完即回收 弱
MADV_WILLNEED 立即预读到 page cache（异步启动读） 弱
MADV_DONTNEED 丢弃页（语义见下表，确定行为） 强
MADV_FREE（Linux） 标记可丢弃：内容保留到内存紧张才真丢；期间再写则取消标记 中
MADV_DONTDUMP/DO_DUMP 从 core dump 排除/包含 强
MADV_HUGEPAGE/NOHUGEPAGE（Linux） 对区间启用/禁用 THP 中
MADV_REMOVE（Linux） 共享内存/tmpfs：截断「洞」 强
MADV_POPULATE_READ/WRITE（5.14+） 主动预填充（等价触碰但不真的写数据） 强

⭐ MADV_DONTNEED 三种映射的确切语义（实测验证）

映射类型 DONTNEED 之后 再读的内容
匿名 PRIVATE 私有数据永久丢弃，页释放，PTE 清空 全 0（重新缺页→零页）
文件 PRIVATE 私有修改丢弃，页释放，PTE 指回…不，PTE 清空 文件当前内容（重新缺页从 page cache 读）
文件 SHARED 脏页按正常路径回写后页可回收，PTE 清空 文件内容（重读 page cache/磁盘）

实测证据（WSL Ubuntu，2026-09-05，gcc -O2 -Wall -Wextra 零告警）：

匿名：全写后 mincore = [1,1,1,1]
      MADV_DONTNEED 后 mincore = [0,0,0,0]，q[0]=0x00          ← 数据消失 ✓
文件 PRIVATE：改 'Z' 后 f[0]='Z'
      DONTNEED 后 f[0]='O'                                      ← 私有修改丢弃 ✓

内核路径（v6.6 实测核验）

madvise(2)
 └─ do_madvise()                          mm/madvise.c:1407
     ├─ madvise_need_mmap_write():50      多数 advice 只需 read_lock，DONTNEED 等才升级写锁
     └─ 按 advice 分发：
         ├─ MADV_DONTNEED → madvise_dontneed_free():859
         │     └─ zap_page_range_single():825   ← 真正拆 PTE、释放页
         ├─ MADV_FREE → madvise_free_single_vma():768

MADV_FREE vs MADV_DONTNEED（Linux 面试高频）

维度 MADV_FREE MADV_DONTNEED
立即效果 PTE 清脏标记，页标记可回收 PTE 立即拆除，页立即释放
读回内容 旧数据（若还没被回收） 全 0 / 文件原内容（确定）

常见错误

  • advice 非法（如 99）→ EINVAL（实测验证 ✓）
  • 区间内含未映射空洞 → ENOMEM（与 munlock 的「跳过空洞」不同，madvise 默认严格；只有部分 advice 用 process_madvise 风格的宽松遍历）
  • 对 MAP_LOCKED 区间 MADV_DONTNEED：v6.6 引入 MADV_DONTNEED_LOCKED（允许拆锁页），普通 DONTNEED 对锁页直接拒绝

HFT / 嵌入式关联

路线 要点
嵌入式 MADV_RANDOM 关预读：flash 随机读场景避免无谓的读放大（NAND 页 4-16KB，预读一次就是一次真消耗）；MADV_DONTNEED 主动归还大缓冲省 RAM（比 munmap 温和——地址空间保留，随时可复用）
HFT 行情缓冲复用三板斧：madvise(MADV_DONTNEED) 重置（下个周期读到的保证是零/新数据，防「脏数据残留」型策略 bug）；MADV_HUGEPAGE 对热大缓冲开 THP（2MB 页 → TLB miss 率骤降，见 06.7 BPF 章 的性能观测）；MADV_SEQUENTIAL 用于顺序落盘的审计日志区

实测警示：MADV_DONTNEED 重置的匿名页读回 0——如果策略代码假设「重置后数据不变」，生产上会出现只在内存压力下复现的灵异 bug（FREE 才有「暂时保留」语义）。

/* MADV_DONTNEED 双语义实测：匿名归零 + 文件 PRIVATE 丢弃修改
 * 实测（WSL Ubuntu，gcc -O2 -Wall -Wextra，2026-09-05）：
 *   全写后 mincore = [1,1,1,1]
 *   MADV_DONTNEED 后 mincore = [0,0,0,0]，q[0]=0x00
 *   文件 PRIVATE 改 'Z' 后 f[0]='Z'；DONTNEED 后 f[0]='O'
 *   madvise(99) = -1 errno=22(Invalid argument)
 */
#define _GNU_SOURCE
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <fcntl.h>
#include <errno.h>
#include <sys/mman.h>
#include <unistd.h>

int main(void)
{
    long pagesz = sysconf(_SC_PAGESIZE);
    size_t P = (size_t)pagesz;

    /* 匿名映射：DONTNEED 归零 */
    char *q = mmap(NULL, 4 * P, PROT_READ | PROT_WRITE,
                   MAP_PRIVATE | MAP_ANONYMOUS, -1, 0);
    if (q == MAP_FAILED) { perror("mmap q"); return 1; }
    memset(q, 0x5A, 4 * P);
    unsigned char vec[4];
    mincore(q, 4 * P, vec);
    printf("全写后 mincore = [%d,%d,%d,%d]\n",
           vec[0]&1, vec[1]&1, vec[2]&1, vec[3]&1);

    if (madvise(q, 4 * P, MADV_DONTNEED) != 0) { perror("madvise"); return 1; }
    mincore(q, 4 * P, vec);
    printf("DONTNEED 后 mincore = [%d,%d,%d,%d]，q[0]=0x%02x（预期 0x00）\n",
           vec[0]&1, vec[1]&1, vec[2]&1, vec[3]&1, (unsigned char)q[0]);

    /* 文件 PRIVATE：DONTNEED 丢弃私有修改 */
    int fd = open("/tmp/ch50_adv.dat", O_RDWR | O_CREAT | O_TRUNC, 0644);
    if (fd < 0) { perror("open"); return 1; }
    if (write(fd, "ORIG", 4) != 4) { perror("write"); return 1; }
    char *f = mmap(NULL, 4, PROT_READ | PROT_WRITE, MAP_PRIVATE, fd, 0);
    if (f == MAP_FAILED) { perror("mmap f"); return 1; }
    f[0] = 'Z';
    printf("文件 PRIVATE 改 'Z' 后 f[0]='%c'；", f[0]);
    if (madvise(f, 4, MADV_DONTNEED) != 0) { perror("madvise f"); return 1; }
    printf("DONTNEED 后 f[0]='%c'（预期 O：私有修改丢弃）\n", f[0]);

    /* 非法 advice */
    errno = 0;
    int r = madvise(q, P, 99);
    printf("madvise(99) = %d errno=%d(%s)，预期 -1/EINVAL\n",
           r, errno, r ? strerror(errno) : "OK");

    munmap(q, 4 * P);
    munmap(f, 4);
    close(fd);
    unlink("/tmp/ch50_adv.dat");
    return 0;
}

自测题

题目 1（选择）： MAP_PRIVATE 文件映射，写脏了 3 页，madvise(MADV_DONTNEED) 后再读，内容是？

A. 修改后的数据　B. 全 0　C. 文件当前内容　D. 未定义

参考答案

C。DONTNEED 拆掉 COW 副本页的 PTE 并释放页，再读触发缺页从 page cache 读文件当前内容——不是 0（0 是匿名映射的语义），也不是「未定义」。实测：改 'Z' → DONTNEED → 读回 'O'（文件原字面）。

题目 2（判断）： MADV_FREE 之后立刻读这段内存，内容必然是 0。

参考答案

错误。MADV_FREE 是 lazyfree：PTE 标记可回收但内容保留，在页真正被回收（内存压力）之前读到的仍是旧数据；期间任何写会取消标记。必然读 0 的是 MADV_DONTNEED。

题目 3（应用）： 行情处理进程每周期用 64MB 缓冲，周期结束想「清零重置」，工程师 A 提议 memset(buf, 0, 64MB)，B 提议 madvise(buf, 64MB, MADV_DONTNEED)，怎么选？

参考答案

DONTNEED 更优（三点）：① memset 要写 64MB（16384 次缺页 + 全部脏页进回写路径），DONTNEED 只是拆 PTE（µs 级批量操作）；② DONTNEED 立刻释放 16384 个物理页给系统，内存压力友好；③ 读回语义明确为 0。代价：下周期首次访问每页一次缺页（~µs × 页数）。若缓冲已 mlock，注意 v6.6 普通参数的 DONTNEED 会被拒绝（需 MADV_DONTNEED_LOCKED）；若不想付缺页代价且缓冲必须常驻，memset 仍是兜底——HFT 实务常在预热阶段两者都做（DONTNEED + 重新 populate + mlock）。

四组调用速览表（含 v6.6 实测要点）

调用 作用 权限/限额 关键实测结论（v6.6）
mprotect 改 PTE 的 rwx 不许超 fd 打开模式（EACCES） 违例 = SIGSEGV（同步信号，可 sigsetjmp 捕获）
mlock/mlockall 禁换出 + 立即预填充 RLIMIT_MEMLOCK / CAP_IPC_LOCK 超限返回 ENOMEM 不是 EPERM；fork 继承、exec 解锁；mlock 区 msync(MS_INVALIDATE)→EBUSY

反直觉真相（易错点 TOP 4）

  1. mlock 超限是 ENOMEM——can_do_mlock 拒绝才是 EPERM；两个错误码对应「无资格」和「超量」两道不同的关。
  2. 零页口径打架——mincore 说驻留（present），Rss 不认账（零页全系统共享一份）；「读触碰的匿名页」两个指标必然不一致。
  3. MADV_DONTNEED 匿名≠文件——匿名丢成 0，文件 PRIVATE 丢成文件原内容（COW 副本没了）；把两者混为一谈会在「重置缓冲」场景写出让策略读到脏数据的 bug。
  4. MADV_FREE 不丢数据——lazyfree 只在内存压力时真丢；需要确定性清零只能 DONTNEED。

#include <sys/mman.h>
#include <time.h>
#include <stdio.h>
#include <stdlib.h>

#define SIZE (1UL << 30)  /* 1GB */
#define ITERATIONS 1000

/* 随机偏移写一次，测单次访问延迟 */
static void bench_access(char *buf, const char *label)
{
    struct timespec start, end;
    long long max_ns = 0, min_ns = 1LL << 62, total_ns = 0;
    unsigned int seed = 42;

    for (int i = 0; i < ITERATIONS; i++) {
        size_t offset = ((size_t)rand_r(&seed) * 4096) % SIZE;
        clock_gettime(CLOCK_MONOTONIC, &start);
        buf[offset] = 'x';      /* 未驻留的页在此触发缺页 */
        clock_gettime(CLOCK_MONOTONIC, &end);

        long long ns = (end.tv_sec - start.tv_sec) * 1000000000LL
                     + (end.tv_nsec - start.tv_nsec);
        if (ns > max_ns) max_ns = ns;
        if (ns < min_ns) min_ns = ns;
        total_ns += ns;
    }
    printf("%s: avg=%lldns min=%lldns max=%lldns\n",
           label, total_ns / ITERATIONS, min_ns, max_ns);
}

int main(void)
{
    char *buf = mmap(NULL, SIZE, PROT_READ | PROT_WRITE,
                     MAP_PRIVATE | MAP_ANONYMOUS, -1, 0);
    if (buf == MAP_FAILED) { perror("mmap"); return 1; }

    /* 注意：bench 本身会逐步触碰页——先「冷测」再 mlockall 后「热测」
       严格冷测应 fork 子进程跑第一轮，父进程 mlock 后再测 */
    bench_access(buf, "before mlockall");

    if (mlockall(MCL_CURRENT | MCL_FUTURE) != 0) {
        /* 失败本身即 50.2 的语义演示：非特权进程受 RLIMIT_MEMLOCK 约束，
           超限部分锁不住，errno=ENOMEM（do_mlock 超限路径保持初值） */
        perror("mlockall（超限 ENOMEM，见 50.2）");
        return 0;   /* 演示目的已达成：失败路径本身就是结果 */
    }
    bench_access(buf, "after  mlockall");

    munmap(buf, SIZE);
    return 0;
}

预期：mlockall 前 max 延迟可能达毫秒级（硬缺页：分配页 + 清零 + 建映射），mlockall 后所有页驻留（do_mlock 的 __mm_populate 已预填充），max 降到微秒级（缓存 miss 而非缺页）。

实测（WSL Ubuntu，非 root，RLIMIT_MEMLOCK 默认限额，2026-09-05）：

before mlockall: avg=1687ns min=17ns max=39278ns
mlockall（超限 ENOMEM，见 50.2）: Cannot allocate memory

1GB 远超限额 → 失败路径触发，失败本身就是 50.2 的语义演示：can_do_mlock 放行（限额非零即有资格）但 do_mlock 超限拒绝，errno 是 ENOMEM 而非 EPERM（超限路径保持初值 ENOMEM，EPERM 只在 can_do_mlock 拒绝时出现）。root 下 ulimit -l unlimited 后可跑出完整的前后对比。before 行的 max≈39µs 即硬缺页成本（分配+清零+建映射）；min=17ns 是 THP 大页摊薄后的热页写。

/* mincore 零页口径差 + MADV_DONTNEED 双语义
 * 实测输出：
 *   mincore = [1,1,0,0]（页0=写触碰 页1=读触碰零页）
 *   同区 Rss = 4 kB（预期 4：零页 present 却不计入 RSS）
 *   全写后 mincore = [1,1,1,1]
 *   MADV_DONTNEED 后 mincore = [0,0,0,0]，q[0]=0x00
 *   文件 PRIVATE 改 'Z' 后 f[0]='Z'；DONTNEED 后 f[0]='O'
 *   madvise(99) = -1 errno=22(Invalid argument)
 */
#define _GNU_SOURCE
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <fcntl.h>
#include <errno.h>
#include <sys/mman.h>
#include <unistd.h>

/* /proc/self/smaps 中包含 addr 的 VMA 的 Rss(kB) */
static long smaps_rss(void *addr)
{
    FILE *fp = fopen("/proc/self/smaps", "r");
    if (!fp) return -1;
    char line[300];
    unsigned long lo, hi, a = (unsigned long)addr;
    long rss = -1;
    int in_target = 0;
    while (fgets(line, sizeof line, fp)) {
        if (sscanf(line, "%lx-%lx", &lo, &hi) == 2)
            in_target = (a >= lo && a < hi);
        else if (in_target && strncmp(line, "Rss:", 4) == 0) {
            sscanf(line + 4, "%ld", &rss);
            break;
        }
    }
    fclose(fp);
    return rss;
}

int main(void)
{
    long pagesz = sysconf(_SC_PAGESIZE);
    size_t P = (size_t)pagesz;

    char *q = mmap(NULL, 4 * P, PROT_READ | PROT_WRITE,
                   MAP_PRIVATE | MAP_ANONYMOUS, -1, 0);
    if (q == MAP_FAILED) { perror("mmap"); return 1; }
    q[0] = 1;                        /* 页 0：写触碰（真页） */
    volatile char c = q[P]; (void)c; /* 页 1：读触碰（零页） */

    unsigned char vec[4];
    if (mincore(q, 4 * P, vec) != 0) { perror("mincore"); return 1; }
    printf("mincore = [%d,%d,%d,%d]（页0=写触碰 页1=读触碰零页）\n",
           vec[0] & 1, vec[1] & 1, vec[2] & 1, vec[3] & 1);
    printf("同区 Rss = %ld kB（预期 4：零页 present 却不计入 RSS）\n",
           smaps_rss(q));

    memset(q, 0x5A, 4 * P);
    mincore(q, 4 * P, vec);
    printf("全写后 mincore = [%d,%d,%d,%d]\n",
           vec[0] & 1, vec[1] & 1, vec[2] & 1, vec[3] & 1);
    if (madvise(q, 4 * P, MADV_DONTNEED) != 0) { perror("madvise"); return 1; }
    mincore(q, 4 * P, vec);
    printf("MADV_DONTNEED 后 mincore = [%d,%d,%d,%d]，q[0]=0x%02x（预期 0x00）\n",
           vec[0] & 1, vec[1] & 1, vec[2] & 1, vec[3] & 1, (unsigned char)q[0]);

    int fd = open("/tmp/ch50_d.dat", O_RDWR | O_CREAT | O_TRUNC, 0644);
    if (fd < 0) { perror("open"); return 1; }
    if (write(fd, "ORIG", 4) != 4) { perror("write"); return 1; }
    char *f = mmap(NULL, 4, PROT_READ | PROT_WRITE, MAP_PRIVATE, fd, 0);
    if (f == MAP_FAILED) { perror("mmap f"); return 1; }
    f[0] = 'Z';
    printf("文件 PRIVATE 改 'Z' 后 f[0]='%c'；", f[0]);
    if (madvise(f, 4, MADV_DONTNEED) != 0) { perror("madvise f"); return 1; }
    printf("DONTNEED 后 f[0]='%c'（预期 O：私有修改丢弃）\n", f[0]);

    errno = 0;
    int r = madvise(q, P, 99);
    printf("madvise(99) = %d errno=%d(%s)，预期 -1/EINVAL\n",
           r, errno, r ? strerror(errno) : "OK");

    munmap(q, 4 * P);
    munmap(f, 4);
    close(fd);
    unlink("/tmp/ch50_d.dat");
    return 0;
}

解读三连： 1. mincore=[1,1,0,0] 但 Rss=4kB——页 1 读触碰映射零页：PTE present（mincore 认）+ 全系统共享（RSS 不认）。 2. MADV_DONTNEED 后 mincore 全 0 且读回 0x00——匿名页的确定性丢弃。 3. 文件 PRIVATE 读回 'O'——丢的是 COW 副本，page cache 原页完好（对照 49.4 的可见性规则）。
