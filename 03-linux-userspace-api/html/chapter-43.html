思考题（43.6）

  1. 匿名管道无路径名，只能靠继承 fd → 仅相关进程。
  2. 进程持久 vs 内核持久；SysV 忘删 → 泄漏。
  3. 共享内存可见同一数据，无原子/序保证 → 需同步。
  4. 无名 sem 无名字可打开，须放在双方都能看见的共享区。

背诵卡

# 要点
1 通信 / 同步 / 信号 三类
2 拷贝型 vs 共享内存（最快且须同步）
3 命名：路径·fd vs SysV key·id
4 持久：进程 / 内核 / 文件系统
5 跨机只用 Internet socket
6 内核持久记得 unlink/显式删

代码示例

#include <stdio.h>
#include <unistd.h>
#include <string.h>
#include <sys/wait.h>

/* Ch43 IPC 概述 — 用管道演示最简单的进程间通信。
 * IPC 三大类: 数据传输(pipe/FIFO/msgq) / 共享内存 / 同步(信号量)。
 * 编译: gcc -o ch43_demo ch43_demo.c */

int main(void) {
    int pipefd[2];
    if (pipe(pipefd) < 0) { perror("pipe"); return 1; }

    pid_t pid = fork();
    if (pid < 0) { perror("fork"); return 1; }

    if (pid == 0) {
        /* 子进程: 写端 */
        close(pipefd[0]);  /* 关闭读端 */
        const char *msg = "Hello from child via pipe!\n";
        write(pipefd[1], msg, strlen(msg));
        close(pipefd[1]);
        _exit(0);
    }

    /* 父进程: 读端 */
    close(pipefd[1]);  /* 关闭写端 */
    char buf[256];
    ssize_t n = read(pipefd[0], buf, sizeof(buf) - 1);
    if (n > 0) {
        buf[n] = '\0';
        printf("Parent received: %s", buf);
    }
    close(pipefd[0]);
    waitpid(pid, NULL, 0);

    printf("\nIPC options:\n");
    printf("  pipe/FIFO: simple, parent-child or same-origin\n");
    printf("  SysV IPC: msgq/sem/shm (key-based, kernel-persistent)\n");
    printf("  POSIX IPC: mq_open/sem_open/shm_open (name-based)\n");
    printf("  sockets: cross-machine, most flexible\n");
    return 0;
}

43.1

IPC 分类法（A Taxonomy of IPC Facilities）

本章：TLPI 第 43 章 — Interprocess Communication Overview - 上一节：本章首页 - 下一节：43.2 通信设施

本节讲什么

IPC 三大类（通信 / 同步 / 信号），以及两个关键维度：命名与句柄（Table 43-1）、可访问范围与持久性（Table 43-2）。

要点

三大类

类 作用
通信 交换数据
同步 互斥、次序、消竞态
信号 异步事件；数据极少；实时信号可带少量 payload

通信 · 数据传输型

写 → 内核缓冲 → 读；通常 两次用户↔内核拷贝。 字节流：pipe、FIFO、流式 socket。 消息边界：SysV/POSIX 消息队列、数据报 socket。

通信 · 共享内存

多进程映射同一物理页；无内核拷贝，最快。 SysV shm · POSIX shm · mmap（匿名/文件）。 ⚠️ 本身无同步 → 必须配信号量/文件锁等。

同步

SysV 信号量 · POSIX 信号量（有名/无名）· flock / fcntl 记录锁。

命名与句柄（Table 43-1）

工具 跨进程识别名 进程内句柄
匿名管道 无 fd
FIFO 路径名 fd
UNIX / Internet socket 路径或 IP:port fd
System V IPC key_t IPC id
POSIX mq / 有名 sem / shm / 路径名 mqd_t / sem_t* / fd
POSIX 无名 sem 无（放共享内存） sem_t*
mmap 文件映射 文件路径 fd

痛点：SysV 独立 key/id，无标准路径名 → POSIX 用类文件名改良。

可访问范围（Table 43-2）

范围 例子
仅相关进程 匿名 pipe、匿名 POSIX sem
本机任意（权限掩码） FIFO、Unix socket、SysV/POSIX IPC、文件锁
跨主机 Internet socket

持久性（生命周期）

级别 含义 代表
进程持久 最后一方关句柄即毁 pipe、FIFO、socket
内核持久 须显式删或重启；进程全退仍在 SysV IPC、POSIX 有名 mq/sem/shm
文件系统持久 落盘，重启仍在 基于文件的 mmap

坑：内核持久对象忘记 *_unlink / ipcrm → 资源泄漏、占满限额。

HFT / 嵌入式关联

路线 要点
嵌入式 资源受限环境优先选进程持久 IPC（pipe/FIFO），避免内核持久对象泄漏
HFT 共享内存最快（零拷贝），但必须配同步原语；持久性影响重启恢复策略

代码示例

#include <stdio.h>
#include <unistd.h>
#include <string.h>
#include <sys/mman.h>
#include <sys/wait.h>
/* IPC 分类法: 数据传输/共享内存/同步 + 命名/持久性 */
int main(void) {
    /* 数据传输: pipe (拷贝型, 进程持久) */
    int fd[2]; pipe(fd);
    if (fork() == 0) { close(fd[0]); write(fd[1], "data", 4); _exit(0); }
    close(fd[1]); char buf[4]; read(fd[0], buf, 4);
    printf("pipe (data transfer): %s\n", buf);
    wait(NULL);

    /* 共享内存: mmap MAP_SHARED (共享型, 进程持久) */
    int *shared = mmap(NULL, sizeof(int), PROT_READ|PROT_WRITE,
                       MAP_SHARED|MAP_ANONYMOUS, -1, 0);
    *shared = 42;
    printf("shared mmap: %d (zero-copy)\n", *shared);
    munmap(shared, sizeof(int));

    /* 内核持久: SysV IPC (需要 ipcrm 显式删除) */
    printf("kernel-persistent: SysV IPC (need ipcrm)\n");
    return 0;
}

43.2

通信设施（Communication Facilities）

本章：TLPI 第 43 章 — Interprocess Communication Overview - 上一节：43.1 IPC 分类法 - 下一节：43.3 同步设施

本节讲什么

逐一介绍各种 通信型 IPC 设施的特点与适用场景：数据传输型（pipe、FIFO、socket、消息队列）与共享内存型。

要点

数据传输型（拷贝型）

设施 边界 范围 持久性 备注
pipe 字节流 仅相关进程 进程持久 最简单，父子进程单向通信
FIFO 字节流 本机任意 进程持久 命名管道，mkfifo() 创建
UNIX socket 流/数据报 本机任意 进程持久 比 FIFO 更灵活，双工
Internet socket 流/数据报 跨主机 进程持久 网络通信唯一选择
SysV 消息队列 消息边界 本机任意 内核持久 key/id 命名，需 ipcrm 清理
POSIX 消息队列 消息边界+优先级 本机任意 内核持久 /name 命名，可接 mq_notify

共享内存型（零拷贝）

设施 范围 持久性 备注
SysV shm 本机任意 内核持久 shmget/shmat/shmdt/shmctl
POSIX shm 本机任意 内核持久 shm_open/ftruncate/mmap
mmap 匿名 仅相关进程 进程持久 MAP_SHARED|MAP_ANONYMOUS
mmap 文件 本机任意 文件系统持久 落盘，重启仍在

⚠️ 共享内存 本身无同步，必须配信号量或文件锁。

关键区分

  • 字节流 vs 消息边界：pipe/FIFO 是字节流（无边界），消息队列有边界
  • 拷贝型 vs 共享型：数据传输型需两次内核拷贝，共享内存型零拷贝但需同步
  • 进程持久 vs 内核持久：内核持久对象忘记清理 → 资源泄漏

HFT / 嵌入式关联

路线 要点
嵌入式 资源受限优先 pipe/FIFO；避免 SysV IPC（内核持久易泄漏）
HFT 共享内存零拷贝最快，配 futex/信号量同步；消息队列优先选 POSIX mq

代码示例

#include <stdio.h>
#include <unistd.h>
#include <string.h>
#include <sys/mman.h>
#include <sys/wait.h>
/* 通信设施对比: pipe(拷贝) vs mmap(共享) */
int main(void) {
    /* 1. pipe: 字节流, 两次拷贝, 进程持久 */
    int fd[2]; pipe(fd);
    if (fork() == 0) {
        close(fd[0]);
        write(fd[1], "pipe-data", 9);
        _exit(0);
    }
    close(fd[1]);
    char buf[16] = {0};
    read(fd[0], buf, 9);
    printf("pipe (copy): %s\n", buf);
    wait(NULL);

    /* 2. mmap 共享内存: 零拷贝, 进程持久, 需自行同步 */
    int *shared = mmap(NULL, sizeof(int), PROT_READ|PROT_WRITE,
                       MAP_SHARED|MAP_ANONYMOUS, -1, 0);
    *shared = 0;
    if (fork() == 0) {
        *shared = 99;  /* 子进程写 */
        _exit(0);
    }
    wait(NULL);
    printf("mmap (zero-copy): %d\n", *shared);  /* 父进程读 */
    munmap(shared, sizeof(int));
    return 0;
}

43.3

同步设施（Synchronization Facilities）

本章：TLPI 第 43 章 — Interprocess Communication Overview - 上一节：43.2 通信设施 - 下一节：43.4 IPC 设施比较

本节讲什么

逐一介绍各种 同步型 IPC 设施：信号量（SysV / POSIX 有名 / POSIX 无名）与文件锁（flock / fcntl 记录锁）。

要点

信号量

设施 命名 范围 持久性 备注
SysV 信号量 key/id 本机任意 内核持久 复杂 API，支持信号量集
POSIX 有名信号量 /name 本机任意 内核持久 sem_open/sem_wait/sem_post
POSIX 无名信号量 无（放共享内存） 仅相关进程 随共享内存 sem_init/sem_wait/sem_post

文件锁

设施 粒度 备注
flock 整个文件 BSD 风格，仅咨询锁
fcntl 记录锁 字节范围 POSIX 标准， advisory + mandatory

SysV vs POSIX 信号量

System V POSIX
时代 80 年代 SysV 后标准化
命名 key + id /name 类路径
句柄 IPC id sem_t*
持久 内核持久 有名对象内核持久
清理 易忘显式删 有 open/close/unlink 语义
I/O 多路复用 弱 更易接 poll/epoll（视实现）

细读：Ch45–48（SysV）· Ch51–54（POSIX）。

HFT / 嵌入式关联

路线 要点
嵌入式 POSIX 无名信号量 + 匿名共享内存最轻量；避免 SysV 复杂 API
HFT futex-based 用户态自旋优先；信号量仅作 fallback（内核态切换开销大）

代码示例

#include <stdio.h>
#include <semaphore.h>
#include <sys/mman.h>
#include <sys/wait.h>
#include <unistd.h>
/* 同步设施: POSIX 无名信号量 (放共享内存) */
int main(void) {
    /* 在共享内存中创建无名信号量 */
    sem_t *sem = mmap(NULL, sizeof(sem_t), PROT_READ|PROT_WRITE,
                      MAP_SHARED|MAP_ANONYMOUS, -1, 0);
    sem_init(sem, 1, 0);  /* pshared=1, 初始值=0 */

    if (fork() == 0) {
        printf("child: working...\n");
        sleep(1);
        sem_post(sem);  /* 子进程通知 */
        _exit(0);
    }
    sem_wait(sem);  /* 父进程等待 */
    printf("parent: child signaled\n");
    wait(NULL);
    sem_destroy(sem);
    munmap(sem, sizeof(sem_t));
    return 0;
}

43.4

IPC 设施比较（Comparing IPC Facilities）

本章：TLPI 第 43 章 — Interprocess Communication Overview - 上一节：43.3 同步设施 - 下一节：43.5 总结

本节讲什么

从多个维度横向比较各种 IPC 设施，给出选型原则。

要点

选型决策树

  1. 大批量高吞吐 → 共享内存 + 同步
  2. 亲缘进程简单单向 → pipe
  3. 无关本地字节流 → FIFO / UNIX 流 socket
  4. 消息边界 / 优先级 → POSIX mq（通常优于 SysV mq）
  5. 跨主机 → Internet socket
  6. 互斥/条件等待 → POSIX 信号量（或 futex 上层封装）
  7. 极老 UNIX 兼容 → 慎用/备选 SysV

性能比较

维度 pipe/FIFO socket 消息队列 共享内存
拷贝次数 2 2 2 0
消息边界 无 可选 有 无
同步内置 无 无 无 无
跨主机 否 是 否 否
持久性 进程 进程 内核 进程/内核/文件

性能：拷贝型有内核缓冲开销；关键路径务必实测。

POSIX vs SysV 总结

System V IPC POSIX IPC
API 复杂度 高（信号量集等） 低（简洁语义）
命名 ftok → key → id /name 路径
可移植性 广泛（老系统） 较新（Linux 2.6+）
推荐 遗留系统兼容 新项目首选

HFT / 嵌入式关联

路线 要点
嵌入式 pipe + FIFO 覆盖 90% 场景；共享内存仅在高吞吐需求时引入
HFT 共享内存 + futex 自旋为黄金组合；消息队列延迟过高不用

代码示例

#include <stdio.h>
#include <unistd.h>
/* IPC 选型原则演示 */
int main(void) {
    printf("IPC selection guide:\n");
    printf("  Parent-child only:     pipe (simplest)\n");
    printf("  Same machine, unrelated: FIFO or Unix socket\n");
    printf("  Cross-machine:         Internet socket (TCP/UDP)\n");
    printf("  High throughput:       shared memory + semaphore\n");
    printf("  Message queue:         POSIX mq (better than SysV)\n");
    printf("  Need persistence:      file-backed (FIFO/mmap)\n");

    /* 管道是最简单的选择 */
    int fd[2];
    pipe(fd);
    printf("\npipe() is the simplest IPC for parent-child\n");
    return 0;
}

需求 推荐

机制 延迟 带宽 复制次数

TCP socket 10-50μs 中 2+（网络栈）

POSIX 消息队列 5-15μs 中 2

IPC 持久性

类型 生命周期
pipe/FIFO 进程终止
SysV IPC 直到显式删除或系统重启
POSIX IPC (named) 直到显式删除
mmap munmap 或进程终止
socket close 或进程终止

HFT / 嵌入式关联

  • 共享内存：HFT 行情数据分发首选——零拷贝、纳秒级延迟
  • Unix socket：HFT 控制消息（策略↔风控）
  • 信号量：共享内存同步保护
  • 管道：简单进程间通信（如策略进程的 stdout 给监控进程）
  • 嵌入式：通常用管道或共享内存；精简系统可能不支持 SysV IPC
  • 无锁设计：HFT 用 SPSC 无锁环形缓冲 + 共享内存替代信号量

代码自测

1. 为什么共享内存是最快的 IPC？

共享内存映射到多个进程的虚拟地址空间，访问共享数据如同访问本地内存——无需内核中转，无需数据拷贝。其他 IPC（管道/socket/消息队列）每次通信都需要系统调用 + 数据从用户空间到内核再到另一个进程的两次拷贝。共享内存只需一次映射，后续访问是普通内存读写。

2. SysV IPC 和 POSIX IPC 的区别？

文件系统接口 无（用 key/id） 有（/dev/shm）

练习 2 答案

1. 父进程向子进程传递配置参数 → 管道：简单，父子关系天然存在。fork 后子进程继承管道读端。

2. HFT 行情进程向策略进程分发 1MB 行情快照 → 共享内存：零拷贝，纳秒级延迟。行情进程写入共享内存，策略进程直接读取。配合信号量或无锁环形缓冲同步。管道/socket 需要两次内核拷贝 1MB 数据，延迟毫秒级。

3. 多个客户端向服务器发送短请求 → Unix socket：支持多路复用（epoll），多客户端各自连接，服务器统一管理。命名简单（路径），权限可控。

4. 两个进程需要同步访问共享文件 → 文件锁（fcntl F_SETLK）：专为文件设计，字节范围锁，自动释放。信号量也行但文件锁更自然。

HFT / 嵌入式关联

  • 共享内存 + 无锁队列：HFT 标准行情分发方案
  • Unix socket：控制平面通信
  • 嵌入式：管道最简单可靠；共享内存需硬件支持
