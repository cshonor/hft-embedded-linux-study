导读

章节目标

建立 Pthreads 模型；分清共享/私有资源；掌握 create / join / detach / pthread_exit；认识竞争条件，为互斥锁铺垫。

29.3 核心 API

创建

int pthread_create(pthread_t *thread, const pthread_attr_t *attr,
                   void *(*start_routine)(void *), void *arg);

attr==NULL → 默认可接合。新线程可能在 create 返回前已跑。自身 ID：pthread_self()。

终止

方式
start 函数 return
pthread_exit(retval)
pthread_cancel Ch32

❌ 线程内 exit() → 整个进程没。
⚠️ 主线程从 main return ≈ exit() → 其它线程一并死；要等子线程时主线程用 pthread_join 或 pthread_exit。

join / detach

int pthread_join(pthread_t thread, void **retval);
int pthread_detach(pthread_t thread);
joinable detached
回收 须 pthread_join 终止后自动回收
返回值 可取 不可 join

同一线程只能 join 一次。可接合退出无人 join → 僵尸线程。

属性（略）

pthread_attr_init / destroy；可设栈大小、分离状态等。

Demo：code/simple_thread.c · code/thread_exit_retval.c · code/detached_thread.c · code/thread_race.c

29.5 易错清单

  1. 线程里 exit()
  2. 主线程 return 拖死其它线程
  3. 把即将失效的栈地址传给新线程
  4. 无同步读写共享变量 → 竞争（Ch30）
  5. 混淆 PID 与 pthread_t
  6. 忘 join → 僵尸线程
  7. 多线程 fork：子进程只留调用线程（Ch28）

实验清单

  1. create + join
  2. 独立 errno / 共享全局
  3. joinable vs detached
  4. （选）主线程 exit 拖死线程
  5. （选）栈指针传参野指针

背诵卡

# 要点

2 -pthread；成功返回 0

代码示例

#include <stdio.h>
#include <pthread.h>
#include <unistd.h>
#include <string.h>

/* Ch29 线程入门 — pthread_create/pthread_join。
 * 线程共享地址空间，比 fork 轻量。
 * 编译: gcc -o ch29_demo ch29_demo.c -lpthread */

static int shared_counter = 0;  /* 线程间共享 */

void *worker(void *arg) {
    int id = *(int *)arg;
    for (int i = 0; i < 5; i++) {
        shared_counter++;
        printf("Thread %d: counter=%d\n", id, shared_counter);
        usleep(100000);  /* 100ms */
    }
    return NULL;
}

int main(void) {
    pthread_t t1, t2;
    int id1 = 1, id2 = 2;

    pthread_create(&t1, NULL, worker, &id1);
    pthread_create(&t2, NULL, worker, &id2);

    pthread_join(t1, NULL);
    pthread_join(t2, NULL);

    printf("Final counter: %d (expected 10)\n", shared_counter);
    return 0;
}

29.1

概念

本章：TLPI 第 29 章 — Threads: Introduction - 上一节：本章首页 - 下一节：29.2 Pthreads 规范

本节讲什么

线程 = 进程内执行流；至少有主线程。共享虚拟地址空间；每线程独立栈。 同进程线程切换无需换页表/刷 TLB，通常比进程切换便宜。 ---

要点

线程 = 进程内执行流；至少有主线程。共享虚拟地址空间；每线程独立栈。

✅ 共享 ❌ 私有
代码/全局/堆、库 pthread_t、线程栈
PID/PPID/PGID/SID、终端 线程信号掩码
fd 表、文件锁、cwd、umask 每线程 errno
信号 handler、rlimit、定时器 浮点上下文、调度属性等
UID/GID 凭证

同进程线程切换无需换页表/刷 TLB，通常比进程切换便宜。

HFT / 嵌入式关联

路线 要点
嵌入式 线程切换无需换页表/刷 TLB、比进程切换便宜；嵌入式多任务用线程共享内存通信，省掉进程间 IPC 开销
HFT HFT 用多线程共享内存（行情/订单/策略线程直接读写全局、堆），省掉进程间 IPC 拷贝；每线程独立栈 + 共享 fd 表是低延迟架构的地基

代码示例

#include <pthread.h>
#include <stdio.h>
void *worker(void *arg) { printf("线程: %s\n", (char *)arg); return NULL; }
int main(void) {
    pthread_t tid;
    pthread_create(&tid, NULL, worker, "hello");
    pthread_join(tid, NULL);
    printf("主线程: 线程已结束\n");
    return 0;
}

29.2

Pthreads 规范

本章：TLPI 第 29 章 — Threads: Introduction - 上一节：29.1 概念 - 下一节：29.4 线程 vs 进程

本节讲什么

  • #include <pthread.h>，链接 -pthread - 成功返回 0；失败返回正错误码（一般不设 errno） - pthread_t 不透明 → 用 pthread_equal

要点

  • #include <pthread.h>，链接 -pthread
  • 成功返回 0；失败返回正错误码（一般不设 errno）
  • pthread_t 不透明 → 用 pthread_equal
  • Linux：基于 clone(CLONE_VM|CLONE_FILES|CLONE_SIGHAND,…)

HFT / 嵌入式关联

路线 要点
嵌入式 基于 clone(CLONE_VM\|CLONE_FILES\|...) 共享资源、创建开销低于 fork；嵌入式常驻服务用线程池复用线程
HFT pthread 返回错误码不设 errno——HFT 关键路径要显式检查返回码；线程创建有开销，用线程池预分配避免运行时创建带来的延迟抖动

常见陷阱

  1. 返回值 vs errno
if (pthread_create(&t, NULL, func, arg) < 0)  /* 错误! */
    perror("pthread_create");
/* 正确：返回错误码，不是 -1 */
if ((err = pthread_create(&t, NULL, func, arg)) != 0)
    strerror(err);

Pthreads 函数返回错误码而不是设置 errno。不能用 perror，要用 strerror(err)。

  1. 忘记 join 或 detach
pthread_create(&t, NULL, func, arg);
/* 不 join 也不 detach → 资源泄漏 */

线程结束后如果不 join 或 detach，资源不会回收。必须 join 或 detach。

  1. mutex 忘记 unlock
pthread_mutex_lock(&m);
if (error) return;  /* 没 unlock! */
pthread_mutex_unlock(&m);

mutex lock 后在所有路径都必须 unlock。用 goto cleanup 或 pthread_mutex_trylock + cleanup。

自测题

题目 1（选择）： pthread_create 失败时返回什么？ A. -1 B. 0 C. 错误码（正整数） D. NULL

参考答案

C。Pthreads 函数返回错误码（如 EAGAIN）而不是 -1，也不设置 errno。用 strerror(err) 获取描述。

题目 2（判断）： 主线程退出时其他线程会继续运行。

参考答案

错误。主线程调用 exit() 或从 main() 返回时，所有线程都会被终止。只有 pthread_exit 才允许其他线程继续。

题目 3（踩坑）： 以下代码有什么问题？

void *thread_func(void *arg) {
    int x = *(int*)arg;
    return NULL;
}
int val = 42;
pthread_create(&t, NULL, thread_func, &val);
参考答案

如果 thread_func 在 val 被修改后才执行，会读到错误的值。应确保 arg 的生命周期覆盖线程执行期，或动态分配。

题目 4（应用）： 写代码创建线程、等待线程结束并获取返回值。

参考答案 
void *func(void *arg) { return (void*)42; }
pthread_t t;
pthread_create(&t, NULL, func, NULL);
void *retval;
pthread_join(t, &retval);
printf("result: %ld\n", (long)retval);

代码示例

#include <stdio.h>
#include <pthread.h>
#include <unistd.h>
#include <string.h>
/* pthread 基础: create/join/exit/self */
void *worker(void *arg) {
    int id = *(int *)arg;
    printf("Thread %d: tid=%lu, pid=%d\n",
           id, (unsigned long)pthread_self(), (int)getpid());
    /* pthread_exit: 线程退出, 可返回值 */
    int *result = malloc(sizeof(int));
    *result = id * 100;
    pthread_exit(result);
}

int main(void) {
    pthread_t t1, t2;
    int id1 = 1, id2 = 2;

    pthread_create(&t1, NULL, worker, &id1);
    pthread_create(&t2, NULL, worker, &id2);

    /* join: 等待线程结束并获取返回值 */
    void *r1, *r2;
    pthread_join(t1, &r1);
    pthread_join(t2, &r2);

    printf("Thread 1 returned: %d\n", *(int *)r1);
    printf("Thread 2 returned: %d\n", *(int *)r2);
    free(r1);
    free(r2);
    return 0;
}

29.3

线程创建

本章：TLPI 第 29 章 — 线程 - 上一节：29.2 Pthreads API 概览 - 下一节：29.4 线程终止

本节讲什么

pthread_create() — 创建新线程，指定启动函数和参数。

要点

API

int pthread_create(pthread_t *thread, const pthread_attr_t *attr,
                   void *(*start)(void *), void *arg);
  • thread：返回线程 ID
  • attr：线程属性（NULL = 默认）
  • start：线程入口函数
  • arg：传递给 start 的参数
  • 成功返回 0，失败返回错误号（不设 errno）

关键行为

行为 说明
共享地址空间 所有线程共享堆、全局变量、文件描述符
独立栈 每个线程有独立栈（默认 8MB）
独立 TID pthread_t 是进程内标识
调度 新线程立即或稍后运行（不保证顺序）

错误处理

int ret = pthread_create(&tid, NULL, start_routine, arg);
if (ret != 0) {
    fprintf(stderr, "pthread_create: %s\n", strerror(ret));
    exit(1);
}

注意事项

  • 返回值是错误号，不是 -1，不能用 perror
  • 新线程继承调用者的信号掩码，但 pending 信号只给创建者
  • 新线程继承调用者的备用信号栈（如果有的话）

HFT / 嵌入式关联

路线 要点
嵌入式 线程比进程轻量（无 fork 拷贝），适合嵌入式资源受限场景
HFT 线程创建有开销（~10-50μs），热路径中预创建所有线程

代码示例

#include <stdio.h>
#include <pthread.h>
#include <string.h>
#include <unistd.h>
/* pthread_create: 创建线程 */
void *worker(void *arg) {
    int id = *(int *)arg;
    printf("thread %d: running (tid=%lu)\n", id, (unsigned long)pthread_self());
    return (void *)(long)(id * 100);
}

int main(void) {
    pthread_t t1, t2;
    int arg1 = 1, arg2 = 2;

    int ret1 = pthread_create(&t1, NULL, worker, &arg1);
    if (ret1) { fprintf(stderr, "create t1: %s\n", strerror(ret1)); return 1; }

    int ret2 = pthread_create(&t2, NULL, worker, &arg2);
    if (ret2) { fprintf(stderr, "create t2: %s\n", strerror(ret2)); return 1; }

    void *res1, *res2;
    pthread_join(t1, &res1);
    pthread_join(t2, &res2);
    printf("t1 returned %ld, t2 returned %ld\n",
           (long)res1, (long)res2);
    return 0;
}

29.4

线程 vs 进程

本章：TLPI 第 29 章 — Threads: Introduction - 上一节：29.2 Pthreads 规范 - 下一节：下一章+1:02d}-*/notes.md)

本节讲什么

要点

进程 fork 线程 pthread
地址空间 独立（COW） 共享
创建开销 更高 更低
共享数据 IPC 直接全局/堆
exit 只杀本进程 杀全部线程
回收 waitpid join / detach

HFT / 嵌入式关联

路线 要点
嵌入式 线程共享地址空间省 IPC；进程隔离更安全（一个进程崩不拖累其他）——嵌入式看实时性选线程、看可靠性选进程
HFT HFT 关键路径用线程共享内存（零拷贝共享行情/订单簿），但隔离性差——一个线程 segfault 杀全进程；对稳定性要求高的组件改用进程 + 共享内存隔离

代码示例

#include <pthread.h>
#include <unistd.h>
#include <stdio.h>
void *worker(void *arg) {
    printf("线程 PID=%d TID=%lu\n", getpid(), (unsigned long)pthread_self());
    return NULL;
}
int main(void) {
    pthread_t t1, t2;
    pthread_create(&t1, NULL, worker, NULL);
    pthread_create(&t2, NULL, worker, NULL);
    pthread_join(t1, NULL); pthread_join(t2, NULL);
    printf("主线程 PID=%d (同进程共享 PID)\n", getpid());
    return 0;
}

29.5

线程 ID

本章：TLPI 第 29 章 — 线程 - 上一节：29.4 线程终止 - 下一节：29.6 加入线程

本节讲什么

pthread_t 类型、pthread_self() 和 pthread_equal() — 线程标识的获取与比较。

要点

API

函数 作用
pthread_self() 返回当前线程的 pthread_t
pthread_equal(t1, t2) 比较两个线程 ID（返回非 0 = 相等）

pthread_t 的不确定性

  • pthread_t 的类型由实现定义（可能是 unsigned long、结构体等）
  • 不能直接用 == 比较，必须用 pthread_equal
  • 不能直接 printf 打印（可移植性差）
  • 不同实现可能有不同的内部表示

与 PID 的区别

getpid() pthread_self()
标识 进程 线程
类型 pid_t（int） pthread_t（实现定义）
内核可见 是 否（glibc 维护）
比较 == pthread_equal
获取内核 TID gettid() N/A

gettid() vs pthread_self()

  • gettid() 返回内核级线程 ID（Linux 特有，pid_t）
  • pthread_self() 返回 POSIX 线程 ID（pthread_t）
  • 两者没有简单的转换关系
  • gettid() 需 syscall(SYS_gettid)（glibc 2.30+ 有包装）

HFT / 嵌入式关联

路线 要点
嵌入式 线程 ID 用于日志区分，pthread_self 够用
HFT gettid() 可用于 /proc/self/task/ 绑核和性能分析

代码示例

#include <stdio.h>
#include <pthread.h>
#include <unistd.h>
#include <sys/syscall.h>
/* 线程 ID: pthread_self vs gettid */
void *worker(void *arg) {
    pthread_t tid = pthread_self();
    pid_t ktid = syscall(SYS_gettid);
    printf("thread: pthread_t=%lu, kernel tid=%d\n",
           (unsigned long)tid, ktid);
    return NULL;
}

int main(void) {
    pthread_t main_tid = pthread_self();
    printf("main: pthread_t=%lu, kernel tid=%d\n",
           (unsigned long)main_tid, (int)getpid());

    pthread_t t;
    pthread_create(&t, NULL, worker, NULL);
    pthread_join(t, NULL);

    /* pthread_equal 比较 */
    if (pthread_equal(main_tid, pthread_self())) {
        printf("still in main thread\n");
    }
    return 0;
}

29.6

加入线程（pthread_join）

本章：TLPI 第 29 章 — 线程 - 上一节：29.5 线程 ID - 下一节：29.7 分离线程

本节讲什么

pthread_join() — 等待指定线程终止并回收资源，类似 waitpid 对进程的作用。

要点

API

int pthread_join(pthread_t thread, void **retval);
  • 阻塞直到 thread 终止
  • retval 接收线程返回值（pthread_exit 的参数或 return 的值）
  • 成功返回 0，失败返回错误号

核心行为

行为 说明
阻塞等待 调用者阻塞直到目标线程终止
资源回收 回收线程栈等资源
获取返回值 通过 retval 接收 void*
一次性 同一线程只能被 join 一次

与 waitpid 的对比

waitpid pthread_join
对象 子进程 线程
选择性 可等任意子进程 (-1) 必须指定具体线程
非阻塞 WNOHANG 无（用 pthread_tryjoin_np GNU 扩展）
状态 int *status void **retval

注意事项

  • 不能 join 自己（死锁，返回 EDEADLK）
  • 不能 join 已 detached 的线程（返回 EINVAL）
  • 不 join 也不 detach 的线程 → 资源泄漏（变成 zombie thread）
  • 目标线程被 cancel 时，retval 设为 PTHREAD_CANCELED

典型模式

void *result;
pthread_join(worker_tid, &result);
if (result == PTHREAD_CANCELED) {
    printf("thread was canceled\n");
} else {
    printf("thread returned %ld\n", (long)result);
}

HFT / 嵌入式关联

路线 要点
嵌入式 join 是线程资源回收的标准方式，避免内存泄漏
HFT 热路径不 join（阻塞），用线程池 + 无锁队列回收结果

代码示例

#include <stdio.h>
#include <pthread.h>
#include <string.h>
/* pthread_join: 等待线程终止并获取返回值 */
void *compute(void *arg) {
    int n = *(int *)arg;
    long sum = 0;
    for (int i = 1; i <= n; i++) sum += i;
    return (void *)sum;
}

int main(void) {
    pthread_t t1, t2;
    int n1 = 100, n2 = 1000;

    pthread_create(&t1, NULL, compute, &n1);
    pthread_create(&t2, NULL, compute, &n2);

    void *r1, *r2;
    pthread_join(t1, &r1);
    pthread_join(t2, &r2);
    printf("sum(1..100) = %ld\n", (long)r1);   /* 5050 */
    printf("sum(1..1000) = %ld\n", (long)r2);  /* 500500 */
    return 0;
}

29.7

分离线程（pthread_detach）

本章：TLPI 第 29 章 — 线程 - 上一节：29.6 加入线程 - 下一节：29.8 线程属性

本节讲什么

pthread_detach() — 将线程标记为分离状态，终止时自动回收资源，无需 join。

要点

API

int pthread_detach(pthread_t thread);
  • 将 thread 标记为 detached
  • 线程终止时自动回收资源
  • 之后不能 pthread_join（返回 EINVAL）

两种线程状态

状态 行为 资源回收
joinable (默认) 终止后等待 join 需要 pthread_join
detached 终止后自动回收 内核自动回收

何时用 detach

  • 不需要返回值 → detach
  • 不想阻塞等待 → detach
  • 线程生命周期不确定 → detach
  • 需要返回值 → join（不 detach）

设置方式

/* 方式1: 创建后 detach */
pthread_t tid;
pthread_create(&tid, NULL, worker, arg);
pthread_detach(tid);

/* 方式2: 线程内自己 detach */
void *worker(void *arg) {
    pthread_detach(pthread_self());
    /* ... */
    return NULL;
}

/* 方式3: 创建时通过属性 detach */
pthread_attr_t attr;
pthread_attr_init(&attr);
pthread_attr_setdetachstate(&attr, PTHREAD_CREATE_DETACHED);
pthread_create(&tid, &attr, worker, arg);
pthread_attr_destroy(&attr);

注意事项

  • detach 后无法获取返回值
  • detach 后无法知道线程何时终止
  • 每个线程必须被 join 或 detach，否则资源泄漏

HFT / 嵌入式关联

路线 要点
嵌入式 短生命周期后台任务用 detach，避免泄漏
HFT 线程池中的工作线程不用 detach（需复用），独立监控线程可 detach

代码示例

#include <stdio.h>
#include <pthread.h>
#include <unistd.h>
/* pthread_detach: 分离线程, 自动回收 */
void *logger(void *arg) {
    /* 自己 detach */
    pthread_detach(pthread_self());
    for (int i = 0; i < 3; i++) {
        printf("logger: tick %d\n", i);
        sleep(1);
    }
    return NULL;  /* 自动回收, 无需 join */
}

int main(void) {
    pthread_t tid;
    pthread_create(&tid, NULL, logger, NULL);

    /* 主线程不等 logger, 自己做别的事 */
    sleep(2);
    printf("main: doing other work\n");

    sleep(2);  /* 等 logger 跑完 */
    printf("main: exiting\n");
    return 0;
}

29.8

线程属性

本章：TLPI 第 29 章 — 线程 - 上一节：29.7 分离线程 - 下一节：29.9 线程 vs 进程

本节讲什么

pthread_attr_t — 在创建线程时设置属性（分离状态、栈大小、栈地址、调度参数等）。

要点

使用模式

pthread_attr_t attr;
pthread_attr_init(&attr);                  /* 初始化为默认值 */
pthread_attr_setdetachstate(&attr, ...);   /* 设置属性 */
pthread_create(&tid, &attr, func, arg);    /* 用属性创建 */
pthread_attr_destroy(&attr);               /* 销毁 */

可设置属性

属性 设置函数 说明
分离状态 setdetachstate JOINABLE (默认) / DETACHED
栈大小 setstacksize 默认 8MB，可缩小
栈地址 setstackaddr 自定义栈位置（少用）
栈溢出保护区 setguardsize 栈溢出保护页大小
调度策略 setschedpolicy SCHED_OTHER/FIFO/RR
调度参数 setschedparam 优先级
继承调度 setinheritsched PTHREAD_INHERIT/EXPLICIT

常用场景

1. 减小栈大小（嵌入式/大量线程）

pthread_attr_t attr;
pthread_attr_init(&attr);
pthread_attr_setstacksize(&attr, 64 * 1024);  /* 64KB 栈 */
pthread_create(&tid, &attr, worker, arg);

2. 创建即分离

pthread_attr_setdetachstate(&attr, PTHREAD_CREATE_DETACHED);

栈大小选择

场景 推荐栈大小
默认 8MB
大量线程（1000+） 64-128KB
嵌入式 4-32KB
深递归 保持 8MB 或更大

注意事项

  • pthread_attr_init 后必须 pthread_attr_destroy
  • 栈太小可能导致段错误（栈溢出）
  • 调度属性需要特权（SCHED_FIFO/SCHED_RR）

HFT / 嵌入式关联

路线 要点
嵌入式 小栈 + detached 适合嵌入式大量轻量线程
HFT 固定栈大小避免动态扩展延迟；调度策略用 SCHED_FIFO

代码示例

#include <stdio.h>
#include <pthread.h>
#include <string.h>
/* 线程属性: 栈大小 + 分离状态 */
void *worker(void *arg) {
    int size = *(int *)arg;
    printf("worker: stack request was %d KB\n", size / 1024);
    return NULL;
}

int main(void) {
    pthread_attr_t attr;
    pthread_attr_init(&attr);

    /* 设置 256KB 栈 */
    size_t stacksize = 256 * 1024;
    pthread_attr_setstacksize(&attr, stacksize);

    /* 设置分离状态 */
    pthread_attr_setdetachstate(&attr, PTHREAD_CREATE_JOINABLE);

    pthread_t tid;
    int arg = 256 * 1024;
    int ret = pthread_create(&tid, &attr, worker, &arg);
    if (ret) { fprintf(stderr, "%s\n", strerror(ret)); return 1; }

    pthread_join(tid, NULL);
    pthread_attr_destroy(&attr);

    /* 查询默认栈大小 */
    pthread_attr_init(&attr);
    size_t defsize;
    pthread_attr_getstacksize(&attr, &defsize);
    printf("default stack: %lu KB\n", (unsigned long)(defsize / 1024));
    pthread_attr_destroy(&attr);
    return 0;
}

29.9

线程 vs 进程

本章：TLPI 第 29 章 — 线程 - 上一节：29.8 线程属性 - 下一节：29.10 总结

本节讲什么

线程和进程的优劣对比，何时用线程、何时用进程。

要点

对比表

维度 线程 进程
创建开销 ~10-50μs ~100-1000μs（fork 拷贝页表）
上下文切换 ~1-10μs ~5-50μs
地址空间 共享 独立
数据共享 直接访问全局变量 需 IPC（管道/共享内存）
隔离性 差（一个崩溃全挂） 好（独立地址空间）
同步开销 低（互斥锁） 高（IPC）
调试 难（竞态条件） 相对容易

何时用线程

  • 需要大量数据共享（如图像处理、矩阵运算）
  • 低延迟通信（共享变量 vs IPC）
  • I/O 并行（一个线程阻塞不影响其他）
  • 资源受限（线程比进程轻量）

何时用进程

  • 需要隔离（一个崩溃不能拖垮其他）
  • 安全性要求高（权限分离）
  • 可用性优先（子进程崩溃可重启）
  • 避免锁竞争（Chrome/Nginx 多进程模型）

混合模型

模型 例子
多进程 Nginx（master + workers）
多线程 数据库（一个连接一个线程）
多进程 + 多线程 Chrome（每 tab 一个进程，每进程多线程）
事件驱动 Redis/Node.js（单线程 + epoll）

HFT 场景选择

场景 推荐 原因
行情处理 + 策略 多线程 共享内存零拷贝
风控独立 多进程 隔离性，风控崩不拖垮交易
回测引擎 多进程 可并行多个回测任务

HFT / 嵌入式关联

路线 要点
嵌入式 资源受限优先线程，但关键模块用进程隔离
HFT 线程共享内存零延迟，但风控/日志用独立进程保证隔离

代码示例

#include <stdio.h>
#include <pthread.h>
#include <unistd.h>
#include <sys/wait.h>
#include <string.h>
/* 线程 vs 进程: 创建开销对比 */
void *thread_worker(void *arg) { return NULL; }

int main(void) {
    /* 线程创建: 共享地址空间 */
    pthread_t tid;
    int shared_var = 42;
    pthread_create(&tid, NULL, thread_worker, NULL);
    /* 线程可直接访问 shared_var */
    printf("thread: shared_var = %d (same address space)\n", shared_var);
    pthread_join(tid, NULL);

    /* 进程创建: 独立地址空间 */
    pid_t pid = fork();
    if (pid == 0) {
        /* 子进程有自己的副本, 修改不影响父进程 */
        shared_var = 99;
        printf("child: shared_var = %d (own copy)\n", shared_var);
        _exit(0);
    }
    wait(NULL);
    printf("parent: shared_var = %d (unchanged)\n", shared_var);
    return 0;
}

代码自测

1. joinable 和 detached 线程有什么区别？

joinable 线程终止后资源不回收，需 pthread_join 回收并获取返回值。detached 线程终止时自动回收资源，无法 join 也无法获取返回值。每个线程必须二选一，否则资源泄漏。

2. 为什么不能直接用 == 比较 pthread_t？

pthread_t 的类型由实现定义，可能是整数、结构体或指针。不同平台类型不同，直接用 == 不可移植。POSIX 要求用 pthread_equal() 比较。

29.11

练习题

本章：TLPI 第 29 章 — 线程

本节讲什么

原书第 29 章练习题要点。

1. 除了 return，线程还有哪些终止方式？
  1. pthread_exit(void *retval) — 显式退出，可返回值
  2. 从 start 函数 return — 等价于 pthread_exit
  3. 被其他线程 pthread_cancel — 异步取消
  4. 任意线程调用 exit — 整个进程退出（所有线程终止）
  5. 主线程从 main return — 等价于 exit，所有线程终止

注意：主线程从 main return 会导致所有线程终止，即使它们还没跑完。

2. 如果线程既没有被 join 也没有被 detach 会怎样？

线程终止后变成 zombie thread，资源（栈、线程描述符）不被回收，导致内存泄漏。这类似于进程不被 waitpid 回收变成 zombie 进程。每个 joinable 线程必须最终被 join。

3. fork 之后，子进程中有几个线程？

子进程只有调用 fork 的那个线程。其他线程不会复制。但子进程继承了父进程的互斥锁状态（锁可能在其他线程手中持有），这通常导致死锁。所以多线程程序中 fork 是危险的，应尽量避免。
