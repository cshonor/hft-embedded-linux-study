15.1

Retrieving File Information: `stat()` 文件属性读取

本章：TLPI 第 15 章 — File Attributes 实测环境：macOS 26.6.2 (arm64 / Darwin) · clang 23.1.0（本目录代码全部实测；Linux 专有项单独标注） 源码核验：man-pages 6.19 stat(2) + Linux v6.6 include/uapi/asm-generic/stat.h + TLPI dist files/ 原书镜像 - 上一节：本章首页 - 下一节：15.2 File Timestamps 文件时间戳

本节讲什么

一句话：struct stat 是内核 inode 的用户态快照，本节回答四个问题：

  1. stat() / lstat() / fstat() 三个入口，对同一个符号链接返回的为什么是两个 inode 的信息？
  2. fstat() 凭什么能躲开路径竞态（TOCTOU）？
  3. st_size、st_blocks、st_blksize 三个"大小"各说各的，谁该信谁？
  4. 三个时间戳的现代接口为什么必须带纳秒？

要点：三个调用一张表

#include <sys/stat.h>

int  stat(const char *pathname, struct stat *buf);   /* 跟随符号链接 */
int lstat(const char *pathname, struct stat *buf);   /* 链接自身 */
int fstat(int fd, struct stat *buf);                 /* 已打开的 fd */
调用 符号链接 TOCTOU 典型场景
stat 跟到目标 有（路径解析发生在调用时） 一般查询
lstat 得到链接 inode（S_ISLNK） 有 ls -l、递归遍历
fstat fd 打开那一刻已定 无 安全检查、fd 复用

fstat 的价值（自编 demo 实测）：先 open 再 fstat，之后就算路径被 rename / 被换指向，fstat(fd) 看到的永远是打开那一刻的对象——路径解析只在 open 发生一次，这是躲开 TOCTOU 的正解。

实测：stat 与 lstat 对同一个链接返回两个 inode

完整源码 code/c15_1_stat_family.c（关键段节选）：

symlink(target, linkpath);          /* target.txt 与 link.lnk 两个 inode */
stat(linkpath, &sb_t);
lstat(linkpath, &sb_l);
/* stat  → regular,  st_size=16  （目标文件的）
   lstat → symlink,  st_size=26  （链接里存的路径串长度） */

实测（macOS / APFS）：

== ① stat() 跟随链接，lstat() 看链接自身 ==
  stat(链接)     st_ino=2274505  type=regular st_size=16
  lstat(链接)    st_ino=2274506  type=symlink st_size=26
  链接的 st_size=26 恰好等于它装的目标路径 "/tmp/tlpi_c15_1/target.txt"（26 字节）
  ⚠️ 符号链接的 st_size 不是文件内容长度，是「链接里存的路径串长度」。

符号链接的 st_size = 目标路径串的字节数，这是大多数人第一次被 struct stat 打脸的地方。

实测：fstat 认 fd 不认路径

== ② fstat() 认 fd 不认路径：rename 之后照样看老对象 ==
  fstat(fd) 的 st_ino = 2274505
  rename(target → linkpath) 后：路径 linkpath 已是普通文件
  stat(linkpath) st_ino = 2274505（路径是新的，对象还是老 inode——同目录 rename 不换 inode）
  fstat(fd)     st_ino = 2274505（还是打开时的老 inode！与 rename 前一致）
  ⚠️ 这就是「先 open 再 fstat」能躲开 TOCTOU 的原因：
     路径解析只发生在 open 那一刻，之后对手怎么改路径都碰不到它。

实测：三个"大小"的分工

== ③ st_size / st_blocks / st_blksize 三个数各说各的 ==
  稀疏文件：st_size=1048577 B, st_blocks=8 (×512B = 4096 B)
  → 逻辑大小 1 MiB+1，实际磁盘占用只有 8 块（4096 字节）
  ⚠️ 判断「文件多大」用 st_size，判断「占多少磁盘」用 st_blocks×512。
  st_blksize = 4096（优选 IO 块；HFT 日志 IO 按它的倍数对齐最省 syscall）

st_blocks 的单位是 512 字节块（历史包袱，不是 st_blksize）——内核 include/uapi/asm-generic/stat.h 里写死的约定。

struct stat 核心字段速查

字段 含义 实测备注
st_dev / st_ino 所在设备 + inode 号 同一文件系统内 (dev, ino) 才唯一
st_mode 类型 + 权限 + 特殊位 类型用 S_IS*() 宏判，别裸与 S_IFMT
st_nlink 硬链接计数 目录最低 2（. + 父目录项），见 Ch18
st_uid / st_gid 属主 / 属组 数字；转名字要查 passwd/group（Ch8）
st_rdev 设备文件的 major/minor 只有 S_ISCHR/S_ISBLK 有意义；用 major()/minor() 拆
st_size 逻辑字节数 符号链接=路径串长
st_blksize 优选 IO 块 实测 4096
st_blocks 512B 块数 稀疏文件可远小于 st_size/512
st_atim/mtim/ctim 三个时间戳（timespec） macOS 叫 st_atimespec 等，见 15.2

设备号实测：/dev/zero 的 st_rdev=50331651 拆开是 major=3 minor=3。

/* Listing 15-1 */

/* t_stat.c

   A program that displays the information returned by the stat()/lstat()
   system calls.

   Usage: t_stat [-l] file

   The '-l' option indicates that lstat() rather than stat() should be used.
*/
#include <sys/sysmacros.h>
#if defined(_AIX)
#define _BSD
#endif
#if defined(__sgi) || defined(__sun)            /* Some systems need this */
#include <sys/mkdev.h>                          /* To get major() and minor() */
#endif
#if defined(__hpux)                             /* Other systems need this */
#include <sys/mknod.h>
#endif
#include <sys/stat.h>
#include <time.h>
#include "file_perms.h"
#include "tlpi_hdr.h"

static void
displayStatInfo(const struct stat *sb)
{
    printf("File type:                ");

    switch (sb->st_mode & S_IFMT) {
    case S_IFREG:  printf("regular file\n");            break;
    case S_IFDIR:  printf("directory\n");               break;
    case S_IFCHR:  printf("character device\n");        break;
    case S_IFBLK:  printf("block device\n");            break;
    case S_IFLNK:  printf("symbolic (soft) link\n");    break;
    case S_IFIFO:  printf("FIFO or pipe\n");            break;
    case S_IFSOCK: printf("socket\n");                  break;
    default:       printf("unknown file type?\n");      break;
    }

    printf("Device containing i-node: major=%ld   minor=%ld\n",
                (long) major(sb->st_dev), (long) minor(sb->st_dev));

    printf("I-node number:            %ld\n", (long) sb->st_ino);

    printf("Mode:                     %lo (%s)\n",
            (unsigned long) sb->st_mode, filePermStr(sb->st_mode, 0));

    if (sb->st_mode & (S_ISUID | S_ISGID | S_ISVTX))
        printf("    special bits set:     %s%s%s\n",
                (sb->st_mode & S_ISUID) ? "set-UID " : "",
                (sb->st_mode & S_ISGID) ? "set-GID " : "",
                (sb->st_mode & S_ISVTX) ? "sticky " : "");

    printf("Number of (hard) links:   %ld\n", (long) sb->st_nlink);

    printf("Ownership:                UID=%ld   GID=%ld\n",
            (long) sb->st_uid, (long) sb->st_gid);

    if (S_ISCHR(sb->st_mode) || S_ISBLK(sb->st_mode))
        printf("Device number (st_rdev):  major=%ld; minor=%ld\n",
                (long) major(sb->st_rdev), (long) minor(sb->st_rdev));

    printf("File size:                %lld bytes\n", (long long) sb->st_size);
    printf("Optimal I/O block size:   %ld bytes\n", (long) sb->st_blksize);
    printf("512B blocks allocated:    %lld\n", (long long) sb->st_blocks);

    printf("Last file access:         %s", ctime(&sb->st_atime));
    printf("Last file modification:   %s", ctime(&sb->st_mtime));
    printf("Last status change:       %s", ctime(&sb->st_ctime));
}

int
main(int argc, char *argv[])
{
    struct stat sb;
    Boolean statLink;           /* True if "-l" specified (i.e., use lstat) */
    int fname;                  /* Location of filename argument in argv[] */

    statLink = (argc > 1) && strcmp(argv[1], "-l") == 0;
                                /* Simple parsing for "-l" */
    fname = statLink ? 2 : 1;

    if (fname >= argc || (argc > 1 && strcmp(argv[1], "--help") == 0))
        usageErr("%s [-l] file\n"
                "        -l = use lstat() instead of stat()\n", argv[0]);

    if (statLink) {
        if (lstat(argv[fname], &sb) == -1)
            errExit("lstat");
    } else {
        if (stat(argv[fname], &sb) == -1)
            errExit("stat");
    }

    displayStatInfo(&sb);

    exit(EXIT_SUCCESS);
}

代码自测（Q&A）

Q1：stat() 和 lstat() 对符号链接返回不同的 st_ino，哪一个是"链接文件"的？ A：lstat() 返回链接自身的（实测 2274506 vs 目标 2274505）。链接是一个真实 inode，类型位是 S_IFLNK，内容就是目标路径串——所以它的 st_size 等于路径串长度。

Q2：为什么"先 open 再 fstat"没有 TOCTOU？ A：路径解析（目录项逐级查找 + 权限检查）只发生在 open() 那一刻，之后内核操作的是 inode/fd。实测把路径 rename 到另一个对象上，fstat(fd) 的 st_ino 纹丝不动。

Q3：st_blocks 的单位是什么？为什么不是 st_blksize？ A：512 字节（内核 asm-generic/stat.h 的历史约定）。st_blksize 是"一次 IO 多大最划算"（实测 4096），两者无关。

Q4：稀疏文件 st_size=1048577、st_blocks=8，du 和 ls -l 分别显示什么？ A：ls -l 显示 st_size（1 MiB+1），du 显示 st_blocks×512（4096B，向上取整到块）。哪个"对"取决于你问的是逻辑还是物理。

Q5：怎么不用 root 也能证明 fstat 免疫路径替换？ A：demo 里 rename(target, linkpath) 把符号链接整个覆盖成普通文件后，stat(linkpath) 与 fstat(fd) 的 st_ino 相同且等于打开时的 inode——路径已经指向"另一个名字"，fd 还认得老对象。

Q6：major()/minor() 从哪来？ A：Linux 在 <sys/sysmacros.h>，macOS 直接在 <sys/types.h>。本目录用空壳 shim 让原书 t_stat.c 在 macOS 零改动编译。

Q7：struct stat 的三个时间戳字段，Linux 和 macOS 的名字差在哪？ A：Linux st_atim / st_mtim / st_ctim（struct timespec），macOS 是 st_atimespec / st_mtimespec / st_ctimespec。跨平台代码用宏抹平（c15_1 的做法），别用秒级字段。

本节讲什么

三个时间戳 atime / mtime / ctime 是审计的骨架，本节回答：

  1. 哪些操作动哪个戳？（一张实测表）
  2. utime() / utimes()（§15.2.1）与 utimensat() / futimens()（§15.2.2）两代接口差在哪？
  3. 为什么 mtime 可以伪造到未来，ctime 永远不能？

代码自测（Q&A）

Q1：ctime 到底记什么？ A：inode 状态变更——权限、属主、链接数、大小（隐含内容变更）任一变动都会动它。它是内核盖的章，utimensat 也伪造不了。

Q2：utime(NULL) 和 utime(&buf) 的权限要求差在哪？ A：NULL（设为现在）：属主或有写权即可；非 NULL（设任意值）：仅属主或 CAP_FOWNER。"能写"不等于"能改成任意时间"。

Q3：为什么 ctime 在"显式设成旧值"时也动？ A：内核判据是"inode 是否经历了一次状态变更操作"，不是"值是否变化"。实测 mtime 完全没变、ctime 精确到 ns 动了。

Q4：改符号链接自身的时间戳怎么办？ A：utimensat(AT_FDCWD, link, times, AT_SYMLINK_NOFOLLOW)——唯一入口。实测把链接 mtime 改到 2000-01-01 成功。老接口 utime/utimes 一律跟随链接。

Q5：futimens 相比 utimensat 的优势？ A：走 fd：一是配合 open 后的校验无路径竞态，二是 O_PATH 打开的对象也能改；三是接口对称（fd 版无需 dirfd 组合）。

Q6：mtime 在未来会导致什么？ A：合法但危险——make/备份的 mtime 比较会错乱。实测 mtime = now + 3600s 一次调用即成功。清理时 touch 或 futimens(UTIME_NOW) 归位。

Q7：UTIME_OMIT 的值为什么长得那么怪（1,111,111,111 ns）？ A：它是人工挑的"不可能误当真实纳秒偏移"的哨兵值；macOS 头文件不提供该宏，本目录 demo 里按 Linux 同值自定义。

目录三权的实测（本节最反直觉的一段）

== ④ 目录的 r=「列名字」 x=「穿越/打开」 ==

  dir=r-- 时 open(dir):             OK                  ← 列目录（读目录数据）可以
  dir=-wx 时 open(dir/file):        OK                  ← 有 x 没 r，知道名字就能开
  → 只有 x 没有 r：摸得到里面的文件，但 ls 列不出目录内容

代码自测（Q&A）

Q1：mode=0077 的文件，属主为什么读不了？ A：判定算法先看 euid==属主 → 选属主三元组 --- → 拒。其他位的 rwx 对属主永远不生效——switch 语义。

Q2：access(F_OK) 在 mode=0000 时为什么还允许？ A：F_OK 只问"路径可达 + 存在"，不涉及权限位。四连测实测 F_OK=0、R/W/X 全拒。

Q3：umask 022 下 chmod(0666) 为什么结果是 0666？ A：umask 只参与创建（open/mkdir 的 mode 参数），chmod 是事后绝对赋值，满额通过。实测两者差异清晰可见。

Q4：SUID 程序里 access(R_OK) 和 open(O_RDONLY) 为什么可能给出相反答案？ A：access 按 real ID（发起者），open 按有效 ID（SUID 后的 euid）。两者回答的是两个不同的问题——这正是 access 存在的理由。

Q5：目录 sticky 位 1777 意味着什么？ A：任何人可创建/删除自己的文件，但不能删别人的（/tmp 就是它）。sticky 对普通文件在现代系统只是历史语义。

Q6：chmod(2) 为什么没有 a+rX？ A：它只有绝对赋值。符号模式是 chmod(1) 在用户态解析的；X 语义（目录或有任一 x 才加 x）需要先 stat 再算，ex15_6 给出了完整实现。

Q7：怎么安全地"看一眼"umask？ A：单线程：umask(0) 后立即恢复；多线程：fork 子进程探测或读 /proc/self/status 的 Umask 行（Linux 4.7+）。umask(0)+恢复在多线程下有真实竞态窗口。

I-node Flags（ext2 Extended File Attributes）i-node 标志

本章：TLPI 第 15 章 — File Attributes ⚠️ Linux 专有（ext 系列/部分 FS 的 inode 标志，ioctl 接口）；macOS 无对应机制，本节源码核验、未实测——诚实标注，Pi（aarch64 / ext4）上是复测平台 源码核验：man-pages 6.19 ioctl_fs(2) / chattr(1) + Linux v6.6 include/uapi/linux/fs.h + TLPI dist files/chiflag.c - 上一节：15.4 File Permissions - 下一节：15.6 Summary

本节讲什么

权限位管"谁能做什么"，i-node 标志管"这个文件在 FS 层有什么行为"（追加只写、不可改、不 dump……）。与 xattr（Ch16）不同：这些标志由文件系统解释、只对 superuser 或文件属主开放修改、且有独立的 ioctl 接口 FS_IOC_GETFLAGS / FS_IOC_SETFLAGS。

要点：常用标志表

标志定义在内核 include/uapi/linux/fs.h（v6.6，坐标实测核对）：

标志 常量 作用
Append-only FS_APPEND_FL 写只能追加（O_APPEND 强制），root 也删不掉（先清标志）
Immutable FS_IMMUTABLE_FL 内容/元数据/链接数全冻结，root 也要先清标志
No dump FS_NODUMP_FL dump(8) 忽略
No access time FS_NOATIME_FL 读不更新 atime（比 relatime 更狠，单文件粒度）
Compressed FS_COMPR_FL 透明压缩（ext2/4 未合入，btrfs 等）
Secure deletion FS_SECRM_FL 删除时覆写（现代 SSID/trims 下基本失效）

为什么 Append-only 是审计/安全基石：攻击者拿到 root 也无法篡改 append-only 的日志文件——只能追加。HFT 主机与交易所审计都要求交易日志 +a。代价：日志轮转必须"改名重建"而不是原地截断。

修改接口与特权

#include <sys/ioctl.h>
#include <linux/fs.h>
int fd = open(path, O_RDONLY);          /* 只读打开即可改标志 */
ioctl(fd, FS_IOC_GETFLAGS, &flags);     /* 读 */
flags |= FS_APPEND_FL;
ioctl(fd, FS_IOC_SETFLAGS, &flags);     /* 写（需 CAP_LINUX_IMMUTABLE 级特权） */
  • 修改者必须是文件属主或 CAP_FOWNER；FS_IMMUTABLE_FL/FS_APPEND_FL 的设置/清除还需 CAP_LINUX_IMMUTABLE；
  • 清 immutable 标志本身是 root 的两步操作：先 FS_IOC_SETFLAGS 去标志，再改/删——渗透测试与加固的熟客。
