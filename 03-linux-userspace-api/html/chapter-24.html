✅ 大致继承 / 共享语义

代码示例

#include <stdio.h>
#include <unistd.h>
#include <sys/types.h>
#include <sys/wait.h>
#include <string.h>

/* Ch24 进程创建 — fork/COW/vfork。
 * fork() 后子进程获得父进程数据的副本（写时复制）。
 * 编译: gcc -o ch24_demo ch24_demo.c */

static int global_var = 100;  /* 全局变量：fork 后各自独立 */

int main(void) {
    int local_var = 200;

    printf("Before fork: global=%d, local=%d\n", global_var, local_var);

    pid_t pid = fork();
    if (pid < 0) {
        perror("fork");
        return 1;
    }

    if (pid == 0) {
        /* 子进程: 修改变量，不影响父进程（COW） */
        global_var = 999;
        local_var = 888;
        printf("Child (pid=%d): global=%d, local=%d\n",
               (int)getpid(), global_var, local_var);
        _exit(0);
    } else {
        /* 父进程 */
        waitpid(pid, NULL, 0);
        printf("Parent (pid=%d): global=%d, local=%d (unchanged by child)\n",
               (int)getpid(), global_var, local_var);
    }

    /* vfork: 子进程共享父进程内存，不写时复制 */
    printf("\nvfork demo:\n");
    pid = vfork();
    if (pid == 0) {
        global_var = 555;  /* 直接修改父进程内存! */
        _exit(0);          /* vfork 子进程必须 _exit，不能 return */
    }
    waitpid(pid, NULL, 0);
    printf("After vfork: global=%d (modified by vfork child!)\n", global_var);
    return 0;
}

`fork()`

本章：TLPI 第 24 章 — Process Creation - 上一节：本章首页 - 下一节：24.2 Copy-On-Write（COW）

本节讲什么

include pid_t fork(void); Demo：code/fork_basic.c

要点

#include <unistd.h>
pid_t fork(void);
返回 含义
> 0 父进程：子 PID
0 子进程
-1 失败

Demo：code/fork_basic.c

HFT / 嵌入式关联

路线 要点
嵌入式 fork 复制出子进程（watchdog/守护），父子按返回值三态分流
HFT fork 页表复制开销是启动延迟预算大头；热路径避免频繁 fork、改用线程池

代码示例

#include <unistd.h>
#include <stdio.h>
int main(void) {
    pid_t pid = fork();
    if (pid < 0) { perror("fork"); return 1; }
    if (pid == 0) {
        printf("子进程: PID=%d, PPID=%d\n", getpid(), getppid());
        _exit(0);
    } else {
        printf("父进程: PID=%d, 子PID=%d\n", getpid(), pid);
        wait(NULL);
    }
    return 0;
}

24.2

Copy-On-Write（COW）

本章：TLPI 第 24 章 — Process Creation - 上一节：24.1 fork() - 下一节：24.4 文件描述符

本节讲什么

fork 瞬间共享页（标只读）；一方写入 → 缺页 → 内核复制该页。 逻辑上地址空间独立；COW 只是加速。 ---

要点

fork 瞬间共享页（标只读）；一方写入 → 缺页 → 内核复制该页。
逻辑上地址空间独立；COW 只是加速。

HFT / 嵌入式关联

路线 要点
嵌入式 COW 让 fork 只标共享页不立即复制，省 RAM（嵌入式内存紧）
HFT COW 使 fork 成本极低；但首写触发缺页复制，需预热避免首次写入毛刺

代码示例

#include <unistd.h>
#include <stdio.h>
int global = 100;  /* 全局变量, fork 后共享页 (COW) */
int main(void) {
    pid_t pid = fork();
    if (pid == 0) {
        global = 200;  /* 子进程写入 → 触发 COW → 复制该页 */
        printf("子: global=%d\n", global);  /* 200 */
        _exit(0);
    } else {
        wait(NULL);
        printf("父: global=%d (不受子修改影响)\n", global);  /* 100 */
    }
    return 0;
}

24.3

The vfork() System Call

本章：TLPI 第 24 章 — Process Creation

本节讲什么

介绍 vfork() 系统调用：一种优化版 fork()，不复制父进程地址空间，子进程直接共享父进程内存，直到调用 exec() 或 _exit()。

要点

vfork vs fork vs clone

特性 fork() vfork() clone()
地址空间 复制（COW） 不复制，共享 可选
父子关系 独立运行 父阻塞等待 独立
子进程限制 无 只能 _exit() 或 exec() 无
性能 中等（COW） 最快（无复制） 最灵活
POSIX 标准 已废弃 Linux 特有
现代推荐 是 否 是（用于线程）

vfork 语义

vfork() 调用后：
1. 子进程在父进程的地址空间中运行
2. 父进程被挂起（阻塞），直到子进程：
   a) 调用 _exit()  → 父进程恢复
   b) 调用 exec()   → 父进程恢复
3. 子进程绝对不能：
   - 修改任何变量（共享父进程内存！）
   - 使用 return（而不是 _exit）
   - 调用其他修改内存的函数

vfork 的限制

禁止操作 后果
return 栈帧问题，破坏父进程栈
exit() 调用 atexit 处理器和 stdio flush，破坏父进程数据
修改变量 直接修改父进程变量
malloc 修改堆状态，破坏父进程

vfork 的设计意图

  • BSD 时代：fork 需要复制全部页面（无 COW），开销大
  • vfork 专为"fork+exec"模式优化：子进程立即 exec，无需复制地址空间
  • 现代系统：fork 已使用 COW（Copy-On-Write），开销很小
  • vfork 的性能优势微乎其微，且语义危险

现代 Linux 的 fork 性能

fork+exec 性能（典型 x86_64）：
  fork():  ~50-100μs（COW，仅复制页表）
  vfork(): ~20-30μs（无页表复制）
  clone(): ~20-30μs（可控制共享项）

差异在大多数应用中可忽略，但 HFT 高频创建子进程场景可能敏感。

HFT / 嵌入式关联

  • HFT 不使用 vfork：语义危险，收益微小
  • 现代替代：用 posix_spawn() 或 clone() + exec()
  • 嵌入式：uClinux（无 MMU）不支持 COW fork，旧版可能需 vfork；现代嵌入式 Linux 有 MMU，用标准 fork
  • 性能分析：如果 fork+exec 是瓶颈，优化方式：(1) 减少子进程创建频率；(2) 用线程替代进程

代码示例

/* vfork 的正确（但已不推荐）用法 */
#include "tlpi_hdr.h"
#include <unistd.h>

int main(void) {
    pid_t pid = vfork();    /* 不推荐使用！ */
    if (pid == -1) errExit("vfork");

    if (pid == 0) {        /* 子进程 */
        /* 只能做两件事：exec 或 _exit */
        execlp("ls", "ls", "-l", NULL);
        /* 如果 exec 失败 */
        _exit(EXIT_FAILURE);  /* 必须 _exit，不能 exit/return */
    }
    /* 父进程在此恢复，子进程已 exec 或 _exit */
    printf("child finished\n");
    return 0;
}

/* 现代替代方案：posix_spawn */
#include <spawn.h>

int modern_fork_exec(void) {
    pid_t pid;
    char *argv[] = {"ls", "-l", NULL};
    char *envp[] = {NULL};
    /* posix_spawn 内部优化了 fork+exec */
    int ret = posix_spawnp(&pid, "ls", NULL, NULL, argv, envp);
    return ret;
}

代码自测

1. vfork 后子进程为什么不能用 return？

vfork 不创建新的地址空间和栈，子进程与父进程共享同一个栈。如果子进程 return，函数返回会修改共享栈的返回地址和局部变量，父进程恢复执行时栈状态已被破坏，可能导致崩溃或未定义行为。必须用 _exit() 正确退出子进程。

2. 现代 Linux 还需要 vfork 吗？

几乎不需要。现代 fork() 使用 COW（Copy-On-Write），只复制页表（不复制物理页），开销已经很低。vfork 的性能优势很小，但语义危险（子进程不能修改内存、不能用 exit/return）。

替代方案： 1. posix_spawn() — POSIX 标准的 fork+exec 替代 2. clone(CLONE_VM | CLONE_VFORK, ...) — Linux 特有，更灵活 3. 直接 fork() + exec() — COW 已经足够快

3. vfork 和 clone 的关系？

Linux 中 vfork() 内部实现为 clone(CLONE_VM | CLONE_VFORK | SIGCHLD, ...)： - CLONE_VM：共享地址空间 - CLONE_VFORK：父进程挂起直到子进程 exec/exit - SIGCHLD：子进程退出时发 SIGCHLD

clone() 是更通用的原语，fork()/vfork()/pthread_create() 都基于 clone() 实现。

24.4

文件描述符

本章：TLPI 第 24 章 — Process Creation - 上一节：24.2 Copy-On-Write（COW） - 下一节：24.5 stdio 缓冲陷阱

本节讲什么

父子指向同一打开文件描述 → 共享文件偏移与状态标志。 策略：用完 close；FD_CLOEXEC 只在 exec 时关，fork 不会因它关 fd。 Demo：code/fork_fd_offset.c

要点

父子指向同一打开文件描述 → 共享文件偏移与状态标志。
策略：用完 close；FD_CLOEXEC 只在 exec 时关，fork 不会因它关 fd。

Demo：code/fork_fd_offset.c

HFT / 嵌入式关联

路线 要点
嵌入式 父子共享 fd 偏移，多进程写同一文件需同步或各自 close
HFT fork 后父子共享 socket 偏移会竞态，立即 exec 或明确分工规避

代码示例

#include <unistd.h>
#include <fcntl.h>
#include <stdio.h>
int main(void) {
    int fd = open("/tmp/fork_fd.txt", O_CREAT | O_RDWR, 0644);
    write(fd, "before", 6);

    pid_t pid = fork();
    if (pid == 0) {
        /* 子进程继承 fd, 指向同一个打开文件描述 (共享偏移) */
        write(fd, "_child", 6);
        printf("子: fd=%d\n", fd);
        close(fd);
        _exit(0);
    }
    wait(NULL);
    write(fd, "_parent", 7);
    printf("父: fd=%d (与子共享偏移)\n", fd);
    close(fd);
    return 0;
}

24.5

stdio 缓冲陷阱

本章：TLPI 第 24 章 — Process Creation - 上一节：24.4 文件描述符 - 下一节：24.6 多线程 + fork（重难点）

本节讲什么

printf 无 \n（全缓冲时）→ 用户缓冲未刷 → fork 复制缓冲 → 父子各打一份。 fork 前 fflush(NULL) / fflush(stdout)。 Demo：code/fork_stdio_buf.c

要点

printf 无 \n（全缓冲时）→ 用户缓冲未刷 → fork 复制缓冲 → 父子各打一份。
fork 前 fflush(NULL) / fflush(stdout)。

Demo：code/fork_stdio_buf.c

HFT / 嵌入式关联

路线 要点
嵌入式 fork 前 fflush，否则缓冲复制导致重复输出
HFT fork 前 fflush 避免日志重复/污染，HFT 日志完整性关键

代码示例

#include <unistd.h>
#include <stdio.h>
int main(void) {
    printf("before fork (未 flush)");
    pid_t pid = fork();
    if (pid == 0) {
        printf("child\n");
        _exit(0);
    }
    wait(NULL);
    printf("parent\n");
    fflush(stdout);
    /* 问题: fork 时 stdout 缓冲区被复制
     * "before fork" 可能被输出两次!
     * 解决: fork 前 fflush(stdout) */
    return 0;
}

24.6

多线程 + `fork`（重难点）

本章：TLPI 第 24 章 — Process Creation - 上一节：24.5 stdio 缓冲陷阱 - 下一节：24.7 典型范式

本节讲什么

子进程只保留 fork 那条线程；其它线程不跑清理 → 锁可能永久锁死、堆状态撕裂。 ---

要点

子进程只保留 fork 那条线程；其它线程不跑清理 → 锁可能永久锁死、堆状态撕裂。

做法
✅ 多线程里尽量只 fork 后立刻 exec
⚠️ pthread_atfork 只能缓解
❌ fork 后子进程继续跑复杂多线程逻辑

HFT / 嵌入式关联

路线 要点
嵌入式 多线程进程 fork 只保留调用线程，其它线程锁可能永久锁死
HFT 多线程热路径进程慎 fork；要 fork 就立刻 exec（pthread_atfork 只缓解）

代码示例

#include <unistd.h>
#include <stdio.h>
#include <sys/wait.h>
int main(void) {
    /* fork 常见用法: 父进程继续服务, 子进程处理请求 */
    for (int i = 0; i < 3; i++) {
        pid_t pid = fork();
        if (pid == 0) {
            printf("子进程 %d (PID=%d)\n", i, getpid());
            _exit(i);
        }
    }
    /* 父进程等所有子进程 */
    int status;
    while (wait(&status) > 0) {
        printf("子进程退出: code=%d\n", WEXITSTATUS(status));
    }
    return 0;
}

24.7

典型范式

本章：TLPI 第 24 章 — Process Creation - 上一节：24.6 多线程 + fork（重难点） - 下一节：24.8 vfork（了解即可）

本节讲什么

fork + exec（shell / 起外部程序）：子进程关多余 fd、重定向，再 exec*；失败 _exit(127)。 fork 后分叉业务（多进程服务）：父子各跑逻辑；父须 wait* 防僵尸（Ch26）。 ---

要点

fork + exec（shell / 起外部程序）：子进程关多余 fd、重定向，再 exec*；失败 _exit(127)。
fork 后分叉业务（多进程服务）：父子各跑逻辑；父须 wait* 防僵尸（Ch26）。

HFT / 嵌入式关联

路线 要点
嵌入式 fork+exec（起程序）/ fork 分叉（多进程服务）两大范式
HFT 父监控子执行 + wait 防僵尸，是 HFT 进程监控与崩溃重启的基础范式

代码示例

#include <unistd.h>
#include <stdio.h>
/* fork 速查:
 * - 返回: 父=子PID, 子=0, 错=-1
 * - 继承: fd/内存/信号掩码 (COW)
 * - 不继承: 锁/定时器值(只继承剩余时间)
 * - stdio 缓冲区: fork 前 fflush!
 */
int main(void) {
    fflush(stdout);
    pid_t pid = fork();
    if (pid == 0) { printf("子 PID=%d\n", getpid()); _exit(0); }
    wait(NULL);
    printf("父 PID=%d\n", getpid());
    return 0;
}
