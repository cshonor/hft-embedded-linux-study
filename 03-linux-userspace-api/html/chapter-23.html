章节目标

区分休眠 / 间隔定时器 / POSIX 定时器；认清 SIGALRM 冲突；掌握 CLOCK_REALTIME vs CLOCK_MONOTONIC；会处理休眠被信号打断（EINTR）。

23.6 选型速查

API 粒度 靠信号？ 多实例 场景
sleep 秒 常 SIGALRM ❌ 尽量不用
nanosleep 纳秒 否 ✅ 短休眠首选
setitimer 微秒 是 每 which 一个 遗留
timer_create 纳秒 可选 ✅ 周期/多定时器
clock_nanosleep 纳秒 否 ✅ 绝对时间 / 单调钟

23.7 易错清单

  1. alarm/sleep/ITIMER_REAL 冲突
  2. 墙钟做定时 → NTP 回拨/快进灾难
  3. SIGEV_SIGNAL + 标准信号仍可能丢事件；高频用线程通知慎开销
  4. 定时器非硬实时，有调度延迟
  5. fork/exec 对定时器继承/清除有特殊规则（见手册）

练习

  1. nanosleep + EINTR 重试
  2. （选）setitimer 周期 SIGALRM
  3. timer_create + CLOCK_MONOTONIC + SIGEV_THREAD
  4. （选）对比 REALTIME / MONOTONIC 在时间跳变下行为

背诵卡

# 要点
1 休眠用 nanosleep，勿混 alarm/sleep
2 定时用 timer_create；多实例 + 可选线程通知
3 超时用 CLOCK_MONOTONIC
4 EINTR 用 rem 重试相对休眠
5 ITIMER_* 每类全局一个，靠信号
6 定时器不保证硬准时

代码示例

#include <stdio.h>
#include <signal.h>
#include <time.h>
#include <unistd.h>
#include <string.h>

/* Ch23 定时器与睡眠 — alarm/timer_create/nanosleep。
 * 演示 alarm 定时 + nanosleep 精确睡眠。
 * 编译: gcc -o ch23_demo ch23_demo.c */

static volatile sig_atomic_t alarm_fired = 0;

void alarm_handler(int sig) {
    alarm_fired = 1;
}

void sigusr1_handler(int sig) {
    alarm_fired++;
}

int main(void) {
    /* alarm: 秒级定时器 */
    signal(SIGALRM, alarm_handler);
    alarm(2);
    printf("alarm set for 2 seconds, waiting...\n");
    pause();
    printf("alarm fired!\n");

    /* nanosleep: 纳秒级睡眠 */
    struct timespec req = {1, 500 * 1000 * 1000};  /* 1.5 秒 */
    struct timespec rem;
    printf("nanosleep(1.5s)...\n");
    nanosleep(&req, &rem);

    /* timer_create: POSIX 定时器（更精确） */
    timer_t timerid;
    struct sigevent sev;
    sev.sigev_notify = SIGEV_SIGNAL;
    sev.sigev_signo = SIGUSR1;
    signal(SIGUSR1, sigusr1_handler);

    timer_create(CLOCK_MONOTONIC, &sev, &timerid);
    struct itimerspec its = {
        .it_interval = {0, 0},         /* 不重复 */
        .it_value = {1, 0}             /* 1秒后触发 */
    };
    timer_settime(timerid, 0, &its, NULL);
    printf("POSIX timer set for 1 second...\n");
    pause();
    printf("POSIX timer fired!\n");
    timer_delete(timerid);
    return 0;
}

23.1

休眠接口

本章：TLPI 第 23 章 — Timers and Sleeping - 上一节：本章首页 - 下一节：23.2 setitimer / alarm

本节讲什么

int nanosleep(const struct timespec req, struct timespec rem); - 不占 SIGALRM - 中断：-1/EINTR，rem 剩余时间可重试

要点

sleep / usleep（少用）

API 问题
sleep 内部常走 alarm+SIGALRM，与其它 alarm 冲突；打断返回剩余秒数
usleep 已废弃；新代码用 nanosleep

nanosleep（推荐短休眠）

int nanosleep(const struct timespec *req, struct timespec *rem);
  • 不占 SIGALRM
  • 中断：-1/EINTR，rem 剩余时间可重试
  • 线程友好

Demo：code/nanosleep_retry.c

clock_nanosleep

int clock_nanosleep(clockid_t clock_id, int flags,
                    const struct timespec *req, struct timespec *rem);
flags 含义
0 相对休眠（≈ nanosleep，常等价 CLOCK_REALTIME 相对）
TIMER_ABSTIME 等到绝对时刻

定时/超时逻辑优先 CLOCK_MONOTONIC（不受墙钟跳变影响）。

HFT / 嵌入式关联

路线 要点
嵌入式 nanosleep 不占 SIGALRM、不与 alarm 冲突，适合做传感器采样间隔/轮询节流的短休眠；clock_nanosleep 可选单调钟防墙钟跳变
HFT HFT 关键路径基本不用 sleep（休眠有调度延迟、不确定）；要用也只是微秒级 nanosleep 做退避；计时/超时一律 CLOCK_MONOTONIC，墙钟跳变会破坏间隔测量

代码示例

#include <time.h>
#include <stdio.h>
int main(void) {
    struct timespec ts;
    clock_gettime(CLOCK_REALTIME, &ts);
    printf("CLOCK_REALTIME: %ld.%09ld\n", ts.tv_sec, ts.tv_nsec);

    clock_gettime(CLOCK_MONOTONIC, &ts);
    printf("CLOCK_MONOTONIC: %ld.%09ld\n", ts.tv_sec, ts.tv_nsec);

    /* nanosleep: 高精度睡眠 */
    struct timespec req = {.tv_sec = 0, .tv_nsec = 500 * 1000 * 1000};
    printf("nanosleep 500ms...\n");
    nanosleep(&req, NULL);
    printf("done\n");
    return 0;
}

23.2

`setitimer` / `alarm`

本章：TLPI 第 23 章 — Timers and Sleeping - 上一节：23.1 休眠接口 - 下一节：23.3 POSIX 定时器 timer_create

本节讲什么

int setitimer(int which, const struct itimerval new_val, struct itimerval old_val); unsigned int alarm(unsigned int seconds); / 简化版 ITIMER_REAL /

要点

int setitimer(int which, const struct itimerval *new_val,
              struct itimerval *old_val);
unsigned int alarm(unsigned int seconds);  /* 简化版 ITIMER_REAL */
which 计时 信号
ITIMER_REAL 墙钟 SIGALRM
ITIMER_VIRTUAL 用户态 CPU SIGVTALRM
ITIMER_PROF 用户+内核 CPU SIGPROF

it_value 启动/停止；it_interval 为 0 则单次。
每类 which 全局一个；依赖信号、标准信号不排队 → 新代码优先 POSIX 定时器。

HFT / 嵌入式关联

路线 要点
嵌入式 ITIMER_PROF 测任务 CPU 占用（profiling）；ITIMER_REAL 做周期心跳/看门狗；三类 which 每类全局一个，多任务需各自管理
HFT 标准信号不排队、每类全局一个，HFT 高精度周期任务应改用 POSIX 定时器；alarm/setitimer 精度止于微秒且走异步信号上下文，不适合低延迟关键路径

代码示例

#include <sys/time.h>
#include <signal.h>
#include <unistd.h>
#include <stdio.h>
void handler(int sig) {
    static int count = 0;
    printf("定时器触发 #%d\n", ++count);
    if (count >= 3) _exit(0);
}
int main(void) {
    signal(SIGALRM, handler);
    struct itimerval it = {
        .it_interval = {.tv_sec = 1, .tv_usec = 0},  /* 每 1 秒 */
        .it_value    = {.tv_sec = 1, .tv_usec = 0},  /* 首次 1 秒后 */
    };
    setitimer(ITIMER_REAL, &it, NULL);
    printf("setitimer: 每 1 秒触发 SIGALRM\n");
    for (;;) pause();
    return 0;
}

23.3

POSIX 定时器 `timer_create`

本章：TLPI 第 23 章 — Timers and Sleeping - 上一节：23.2 setitimer / alarm - 下一节：23.4 时钟类型

本节讲什么

int timer_create(clockid_t clockid, struct sigevent sevp, timer_t timerid); int timer_settime(timer_t timerid, int flags, const struct itimerspec new_val, struct itimerspec old_val);

要点

int timer_create(clockid_t clockid, struct sigevent *sevp, timer_t *timerid);
int timer_settime(timer_t timerid, int flags,
                  const struct itimerspec *new_val, struct itimerspec *old_val);
int timer_delete(timer_t timerid);

sigevent 通知

方式 要点
SIGEV_SIGNAL 指定信号 + 可带数据；多定时器可并存，但仍受信号排队限制
SIGEV_THREAD 到期调线程回调，无 async-safe 限制
SIGEV_NONE 只计数

优势：多实例、可选单调钟、纳秒 itimerspec。
链接：老 glibc 可能需 -lrt。

Demo：code/posix_timer_thread.c

HFT / 嵌入式关联

路线 要点
嵌入式 多实例定时器 + 纳秒精度，做周期控制/采样；SIGEV_THREAD 回调无 async-safe 限制，可跑复杂周期任务
HFT timer_create(CLOCK_MONOTONIC, ...) 纳秒精度做周期采样/心跳；SIGEV_SIGNAL 带 siginfo 数据可区分多定时器；但信号上下文仍不适合关键路径——HFT 更常用 epoll 超时 + CLOCK_MONOTONIC 计时

代码示例

#include <stdio.h>
#include <signal.h>
#include <time.h>
#include <unistd.h>
#include <string.h>
/* timer_create: POSIX 定时器 (比 alarm 更精确) */
static volatile sig_atomic_t tick = 0;

void timer_handler(int sig, siginfo_t *si, void *uc) {
    tick++;
}

int main(void) {
    /* 注册信号处理器 */
    struct sigaction sa;
    memset(&sa, 0, sizeof(sa));
    sa.sa_sigaction = timer_handler;
    sa.sa_flags = SA_SIGINFO;
    sigaction(SIGRTMIN, &sa, NULL);

    /* 创建定时器 */
    timer_t timerid;
    struct sigevent sev;
    memset(&sev, 0, sizeof(sev));
    sev.sigev_notify = SIGEV_SIGNAL;
    sev.sigev_signo = SIGRTMIN;

    timer_create(CLOCK_MONOTONIC, &sev, &timerid);

    /* 设置: 1秒后首次, 之后每0.5秒 */
    struct itimerspec its;
    its.it_value.tv_sec = 1;
    its.it_value.tv_nsec = 0;
    its.it_interval.tv_sec = 0;
    its.it_interval.tv_nsec = 500 * 1000 * 1000;
    timer_settime(timerid, 0, &its, NULL);

    printf("Timer started, waiting 3 seconds...\n");
    sleep(3);

    /* 获取剩余时间 */
    struct itimerspec curr;
    timer_gettime(timerid, &curr);
    printf("Timer interval: %ld.%09ld sec\n",
           (long)curr.it_interval.tv_sec,
           (long)curr.it_interval.tv_nsec);
    printf("Ticks received: %d\n", tick);

    timer_delete(timerid);
    return 0;
}

23.4

时钟类型

本章：TLPI 第 23 章 — Timers and Sleeping - 上一节：23.3 POSIX 定时器 timer_create - 下一节：23.5 休眠与 EINTR

本节讲什么

要点

时钟 用途
CLOCK_REALTIME 墙钟；NTP 可跳；不宜做间隔超时
CLOCK_MONOTONIC 单调递增；定时/超时首选
*_CPUTIME_ID CPU 时间；不是墙钟延时

HFT / 嵌入式关联

路线 要点
嵌入式 CLOCK_MONOTONIC 做看门狗超时（防墙钟/NTP 跳变）；*_CPUTIME_ID 测单个任务 CPU 占用做负载均衡
HFT CLOCK_MONOTONIC/CLOCK_MONOTONIC_RAW 是 HFT 计时首选——CLOCK_REALTIME 会被 NTP 跳变破坏间隔测量；测延迟用 MONOTONIC_RAW（不受 NTP/adjtime 影响），是「裸硬件计数」

代码示例

#include <time.h>
#include <stdio.h>
int main(void) {
    struct timespec ts;
    /* CLOCK_REALTIME: 墙上时间 (可被 NTP 调整) */
    clock_gettime(CLOCK_REALTIME, &ts);
    printf("REALTIME:    %ld.%09ld\n", ts.tv_sec, ts.tv_nsec);

    /* CLOCK_MONOTONIC: 单调递增 (不受 NTP 影响, HFT 首选) */
    clock_gettime(CLOCK_MONOTONIC, &ts);
    printf("MONOTONIC:   %ld.%09ld\n", ts.tv_sec, ts.tv_nsec);

    /* CLOCK_MONOTONIC_RAW: 纯硬件, 不受 NTP/adjtime 影响 */
    clock_gettime(CLOCK_MONOTONIC_RAW, &ts);
    printf("MONO_RAW:    %ld.%09ld\n", ts.tv_sec, ts.tv_nsec);

    /* CLOCK_PROCESS_CPUTIME_ID: 进程 CPU 时间 */
    clock_gettime(CLOCK_PROCESS_CPUTIME_ID, &ts);
    printf("PROC_CPU:    %ld.%09ld\n", ts.tv_sec, ts.tv_nsec);
    return 0;
}

23.5

休眠与 `EINTR`

本章：TLPI 第 23 章 — Timers and Sleeping - 上一节：23.4 时钟类型 - 下一节：下一章+1:02d}-*/notes.md)

本节讲什么

相对休眠被信号打断 → EINTR；nanosleep 用 rem 重试： while (nanosleep(&req, &req) == -1 && errno == EINTR) ;

要点

相对休眠被信号打断 → EINTR；nanosleep 用 rem 重试：

while (nanosleep(&req, &req) == -1 && errno == EINTR)
    ;

TIMER_ABSTIME：打断后通常重算绝对时间，不是简单用 rem。

HFT / 嵌入式关联

路线 要点
嵌入式 信号打断阻塞调用返回 EINTR，嵌入式服务用 while 循环重试，避免被信号提前打断导致控制时序错乱
HFT HFT 里阻塞调用被信号打断必须正确处理 EINTR，否则超时/休眠提前返回破坏时序；TIMER_ABSTIME 打断后重算绝对时间，不累积漂移

代码示例

#include <time.h>
#include <unistd.h>
#include <signal.h>
#include <stdio.h>
void handler(int sig) { printf("handler\n"); }
int main(void) {
    signal(SIGUSR1, handler);
    /* nanosleep 被信号中断后, remaining 返回剩余时间 */
    struct timespec req = {.tv_sec = 5, .tv_nsec = 0}, rem;
    raise(SIGUSR1);
    int ret = nanosleep(&req, &rem);
    if (ret < 0) {
        printf("nanosleep 被中断, 剩余 %ld.%09ld\n", rem.tv_sec, rem.tv_nsec);
    }
    return 0;
}

23.6

POSIX 间隔定时器

本章：TLPI 第 23 章 — 定时器 - 上一节：23.5 间隔定时器 setitimer - 下一节：23.7 通过文件描述符通知的定时器

本节讲什么

POSIX timer_create() 系列 API — 比 setitimer 更灵活：可指定信号、可携带数据、可多实例。

要点

API 总览

函数 作用
timer_create(clockid, &evp, &timerid) 创建定时器
timer_settime(timerid, flags, &its, &old_its) 启动/停止
timer_gettime(timerid, &its) 查询剩余时间
timer_getoverrun(timerid) 查询溢出次数
timer_delete(timerid) 删除定时器

与 setitimer 的对比

setitimer POSIX timer_create
实例数 每进程 3 个（ITIMER_REAL/VT/PROF） 无限制
信号 固定（SIGALRM/SIGVTALRM/SIGPROF） 可指定
数据携带 无 可通过 sigevent 携带 sigval
通知方式 仅信号 信号 / 线程 / sigqueue
精度 微秒 纳秒

sigevent 结构（通知方式）

struct sigevent {
    int sigev_notify;          /* SIGEV_SIGNAL / SIGEV_THREAD / SIGEV_NONE */
    int sigev_signo;           /* 信号编号 (SIGEV_SIGNAL 时) */
    union sigval sigev_value;  /* 携带的数据 */
    /* SIGEV_THREAD 时: 新线程调用 sigev_notify_function */
};

通知方式

方式 行为
SIGEV_SIGNAL 发送指定信号（可携带 sigval）
SIGEV_THREAD 创建新线程调用回调函数
SIGEV_NONE 仅计时，不通知（用 timer_gettime 轮询）
SIGEV_THREAD_ID Linux 扩展，发信号到指定线程

溢出（overrun）

  • 标准信号不排队 → 多次超时可能只通知一次
  • timer_getoverrun() 返回丢失的超时次数
  • 实时信号可减少溢出，但仍需检查

时钟类型

clockid 含义
CLOCK_REALTIME 墙上时间（可被 NTP 调整）
CLOCK_MONOTONIC 单调递增（不受 NTP 影响，推荐）
CLOCK_PROCESS_CPUTIME_ID 进程 CPU 时间
CLOCK_THREAD_CPUTIME_ID 线程 CPU 时间

HFT / 嵌入式关联

路线 要点
嵌入式 CLOCK_MONOTONIC 避免墙上时间跳变导致定时器异常
HFT SIGEV_THREAD_ID 定向通知到指定线程，避免打断热路径线程

代码示例

#include <stdio.h>
#include <signal.h>
#include <time.h>
#include <string.h>
#include <unistd.h>
/* POSIX timer: CLOCK_MONOTONIC + SIGEV_SIGNAL */
volatile sig_atomic_t tick = 0;
void handler(int sig, siginfo_t *si, void *ctx) {
    tick++;
}

int main(void) {
    /* 注册信号处理 */
    struct sigaction sa;
    memset(&sa, 0, sizeof(sa));
    sa.sa_sigaction = handler;
    sa.sa_flags = SA_SIGINFO;
    sigaction(SIGRTMIN, &sa, NULL);

    /* 创建定时器 */
    timer_t timerid;
    struct sigevent sev;
    memset(&sev, 0, sizeof(sev));
    sev.sigev_notify = SIGEV_SIGNAL;
    sev.sigev_signo = SIGRTMIN;
    sev.sigev_value.sival_ptr = &timerid;
    timer_create(CLOCK_MONOTONIC, &sev, &timerid);

    /* 启动: 首次 0.5s, 之后每 0.5s */
    struct itimerspec its;
    its.it_value.tv_sec = 0;
    its.it_value.tv_nsec = 500000000;
    its.it_interval = its.it_value;
    timer_settime(timerid, 0, &its, NULL);

    /* 等 2 秒 */
    sleep(2);
    printf("ticks: %d (expected ~4)\n", tick);

    timer_delete(timerid);
    return 0;
}

23.7

通过文件描述符通知的定时器

本章：TLPI 第 23 章 — 定时器 - 上一节：23.6 POSIX 间隔定时器 - 下一节：23.8 总结

本节讲什么

timerfd 系列 API — Linux 特有，将定时器事件变为可从文件描述符读取的事件，融入 epoll。

要点

API

函数 作用
timerfd_create(clockid, flags) 创建 timerfd
timerfd_settime(fd, flags, &its, &old_its) 启动/停止
timerfd_gettime(fd, &its) 查询剩余时间

核心行为

  1. 定时器超时时，内核向 fd 写入 uint64_t（超时次数）
  2. read(fd, &expirations, 8) 读取并清零计数
  3. 可设 TFD_NONBLOCK / TFD_CLOEXEC

与其他定时器 API 的对比

alarm setitimer POSIX timer_create timerfd
实例数 1 3 无限 无限
通知 信号 信号 信号/线程 fd (epoll)
融入 epoll 否 否 否 是
精度 秒 微秒 纳秒 纳秒
可携带数据 否 否 是 否（仅计数）

优势

  • 统一事件循环：定时器 + I/O + 信号全在 epoll 中处理
  • 无信号处理函数，纯同步
  • 多个 timerfd 可融入同一个 epoll 实例

典型用法

int tfd = timerfd_create(CLOCK_MONOTONIC, TFD_NONBLOCK | TFD_CLOEXEC);
struct itimerspec its = {
    .it_interval = { .tv_sec = 1, .tv_nsec = 0 },
    .it_value = { .tv_sec = 1, .tv_nsec = 0 },
};
timerfd_settime(tfd, 0, &its, NULL);
/* 将 tfd 加入 epoll，epoll_wait 返回后 read(tfd, &count, 8) */

HFT / 嵌入式关联

路线 要点
嵌入式 timerfd + epoll 统一事件循环，替代信号+回调的复杂架构
HFT 心跳/超时检测用 timerfd 融入 epoll，避免信号中断热路径

代码示例

#include <stdio.h>
#include <sys/timerfd.h>
#include <unistd.h>
#include <time.h>
#include <string.h>
/* timerfd: 通过文件描述符读取定时器事件 */
int main(void) {
    int tfd = timerfd_create(CLOCK_MONOTONIC, 0);
    if (tfd < 0) { perror("timerfd_create"); return 1; }

    /* 每 0.5 秒触发一次 */
    struct itimerspec its;
    memset(&its, 0, sizeof(its));
    its.it_value.tv_nsec = 500000000;
    its.it_interval.tv_nsec = 500000000;
    timerfd_settime(tfd, 0, &its, NULL);

    /* 读取 4 次超时 */
    for (int i = 0; i < 4; i++) {
        uint64_t expirations;
        read(tfd, &expirations, sizeof(expirations));
        printf("tick %d: %lu expiration(s)\n",
               i + 1, (unsigned long)expirations);
    }

    close(tfd);
    return 0;
}

代码自测

1. 为什么推荐 CLOCK_MONOTONIC 而非 CLOCK_REALTIME？

CLOCK_REALTIME 反映墙上时间，可被 NTP 或管理员调整（向前跳或向后跳），导致定时器行为异常。CLOCK_MONOTONIC 单调递增，不受调整影响，适合定时器。

2. timerfd 相比 POSIX timer 的最大优势是什么？

timerfd 是文件描述符，可融入 epoll/poll 事件循环，与 I/O 事件统一处理。POSIX timer 通过信号通知，需要 handler 或 sigwaitinfo，难以与 I/O 事件统一。

原书第 23 章练习题要点。

1. 实现 buftimedread 函数：在指定时间内从 stdin 读取一行，超时返回 
ssize_t buftimedread(char *buf, size_t len, struct timespec *timeout) {
    fd_set rfds;
    FD_ZERO(&rfds);
    FD_SET(STDIN_FILENO, &rfds);

    int ret = pselect(STDIN_FILENO + 1, &rfds, NULL, NULL, timeout, NULL);
    if (ret <= 0) return -1;  /* 超时或错误 */

    return read(STDIN_FILENO, buf, len);
}

用 pselect 而非 select + alarm，避免信号竞态。

2. setitimer 和 timer_create 各能创建多少个定时器？

setitimer 每进程只有 3 个（ITIMER_REAL、ITIMER_VIRTUAL、ITIMER_PROF），因为它们是固定编号的全局资源。timer_create 可创建无限多个（受系统资源限制），每个返回独立的 timer_t。

3. timer_getoverrun 返回什么？什么时候需要检查它？

返回自上次通知以来"丢失"的超时次数。当使用 SIGEV_SIGNAL 通知标准信号时，信号不排队，多次超时可能只通知一次。在 handler 中调用 timer_getoverrun 获取丢失次数，以修正时间计算。
