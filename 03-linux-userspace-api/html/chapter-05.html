章节目标

揭示 Linux 内核 三层文件结构，理解：fd 复制、原子操作、pread/pwrite、fcntl、非阻塞 I/O、大文件支持。
Ch4 会用 open/read/write/lseek，只认识 fd 数字
Ch5 看透三层结构；解释偏移共享、多进程写覆盖、fd 重定向
Ch13 页缓存、write 缓冲、fsync（「write 成功 ≠ 已落盘」）

易错清单

  1. 偏移在 打开文件描述；dup 共享，独立 open 独立。
  2. FD_CLOEXEC = fd 标志；O_APPEND/O_NONBLOCK = 文件状态标志。
  3. pread ≠ lseek+read（原子性 + 不改全局偏移）。
  4. O_EXCL 须配 O_CREAT。
  5. fcntl(F_SETFL) 改不了 读写模式。
  6. O_NONBLOCK 对普通磁盘文件通常无效。

Ch4 vs Ch5 速查

Ch4 Universal I/O Ch5 Further Details
焦点 同一套 API 操作万物 内核三层 + 进阶语义
API open/read/write/close/lseek dup*、pread*、fcntl、原子标志
偏移 「有个游标」 游标在 打开描述；谁共享谁独立
非阻塞 少提 O_NONBLOCK 适用对象与语义
落盘 未深入 → Ch13 缓冲 / fsync

章节链路

Ch4 会用 fd 数字
  → Ch5 三层结构解释「怪现象」
  → Ch6 进程环境
  → Ch13 缓冲：write 成功 ≠ 落盘（fsync）

双线提示

路线
嵌入式 dup2 重定向；O_CLOEXEC 防 exec 泄漏；设备 fd 的 fcntl
HFT pread/pwrite 并发；少 lseek 竞态；非阻塞多用于 socket/管道

代码示例

#include <stdio.h>
#include <fcntl.h>
#include <unistd.h>
#include <string.h>

/* Ch5 深入文件 I/O — dup/dup2/fcntl/lseek/pread/pwrite。
 * 演示 dup2 重定向 + lseek 随机访问。
 * 编译: gcc -o ch5_demo ch5_demo.c */

int main(void) {
    int fd = open("/tmp/ch5_test.txt", O_RDWR | O_CREAT | O_TRUNC, 0644);
    if (fd < 0) { perror("open"); return 1; }

    /* 写入数据 */
    const char *data = "ABCDEFGHIJ";
    write(fd, data, 10);

    /* lseek 到开头，用 pread 读特定位置（不影响文件偏移量） */
    char buf[4];
    pread(fd, buf, 3, 5);  /* 从偏移5读3字节 */
    buf[3] = '\0';
    printf("pread at offset 5: %s\n", buf);

    /* dup2: 将 fd 复制到 STDOUT_FILENO，重定向输出 */
    lseek(fd, 0, SEEK_SET);
    dup2(fd, STDOUT_FILENO);
    close(fd);

    /* printf 现在写入文件而不是终端 */
    printf("This goes to the file via dup2!\n");
    fflush(stdout);
    return 0;
}

5.1

内核三层结构（本章核心 · 必考）

本章：TLPI 第 05 章 — File I/O: Further Details - 上一节：本章首页 - 下一节：5.2 dup / dup2 / dup3

本节讲什么

进程内相关的三层，厘清无数文件 I/O 疑难： → lseek 改的是 打开文件描述里的偏移，不是「fd 数字本身」。 ---

要点

进程内相关的三层，厘清无数文件 I/O 疑难：

层 谁有 存什么
1. 进程 fd 表 每进程独有 指向「打开文件描述」的指针 + fd 标志（主要是 FD_CLOEXEC）
2. 打开文件描述（open file description） 内核全局，可被多 fd 共享 文件偏移（lseek 改的就是它）、状态标志（O_APPEND/O_NONBLOCK…）、指向 inode
3. inode 磁盘上真实文件 大小、权限、磁盘块位置、链接计数等

关键推论（高频面试点）

操作 打开文件描述 偏移
两次独立 open() 同一路径 两个 各自独立
dup / dup2 / fcntl(F_DUPFD) 同一个 共享
fork 继承 通常 共享 父打开描述 共享（见 LKD §3.8）
O_APPEND write 前内核 原子 移到 EOF 再写 —

→ lseek 改的是 打开文件描述里的偏移，不是「fd 数字本身」。

代码示例

#include <fcntl.h>
#include <unistd.h>
#include <stdio.h>

/* 演示内核三层结构：dup 共享打开文件描述（含偏移） */
int main(void) {
    int fd = open("/tmp/sparse.txt", O_RDWR | O_CREAT, 0644);
    write(fd, "ABCDE", 5);

    /* dup 后 fd 和 fd2 指向同一个打开文件描述 → 共享偏移 */
    int fd2 = dup(fd);
    printf("fd=%d, fd2=%d\n", fd, fd2);

    /* 通过 fd 读 2 字节 → 偏移变到 2 */
    char buf[3];
    lseek(fd, 0, SEEK_SET);
    read(fd, buf, 2);
    printf("fd 读 2 字节后偏移: %ld\n", lseek(fd, 0, SEEK_CUR));  /* 2 */

    /* fd2 的偏移也是 2（共享） */
    printf("fd2 偏移: %ld (共享)\n", lseek(fd2, 0, SEEK_CUR));    /* 2 */

    /* 对比：两次独立 open → 各自独立偏移 */
    int fd3 = open("/tmp/sparse.txt", O_RDONLY);
    printf("fd3 偏移: %ld (独立)\n", lseek(fd3, 0, SEEK_CUR));    /* 0 */

    close(fd); close(fd2); close(fd3);
    return 0;
}

5.5

`fcntl` — 文件控制

本章：TLPI 第 05 章 — File I/O: Further Details - 上一节：5.4 原子操作 - 下一节：5.6 打开标志补充（扩展 Ch4）

本节讲什么

int fcntl(int fd, int cmd, ...); FD_CLOEXEC：exec 时自动关该 fd，防泄漏。 Demo：code/fcntl_nonblock.c（管道上设 O_NONBLOCK）

要点

int fcntl(int fd, int cmd, ...);
cmd 作用
F_DUPFD 复制 fd（类似 dup）
F_GETFD / F_SETFD fd 标志（进程 fd 表）：主要 FD_CLOEXEC
F_GETFL / F_SETFL 文件状态标志（打开描述）：可改 O_APPEND、O_NONBLOCK；不能改 O_RDONLY/O_WRONLY/O_RDWR

两组标志勿混

存在哪 例子 共享？
fd 标志 进程 fd 表项 FD_CLOEXEC 每个 fd 私有
文件状态标志 打开文件描述 O_APPEND、O_NONBLOCK dup 的 fd 共享

FD_CLOEXEC：exec 时自动关该 fd，防泄漏。
Demo：code/fcntl_nonblock.c（管道上设 O_NONBLOCK）

常见陷阱

  1. fd 标志 vs 文件状态标志混淆
/* 错误：F_SETFL 改不了访问模式 */
fcntl(fd, F_SETFL, O_WRONLY);  /* 无效 */

F_SETFL 只能改 O_APPEND/O_NONBLOCK 等，不能改 O_RDONLY/O_WRONLY/O_RDWR。访问模式在 open 时确定。

  1. F_GETFL 解析访问模式
int flags = fcntl(fd, F_GETFL);
int acc = flags & O_ACCMODE;  /* O_RDONLY/O_WRONLY/O_RDWR */

不能直接用 flags & O_WRONLY 判断，因为 O_RDONLY 通常是 0。必须用 O_ACCMODE 掩码。

  1. FD_CLOEXEC 竞态
int fd = open(...);
fcntl(fd, F_SETFD, FD_CLOEXEC);  /* open 和 fcntl 之间有间隙 */
/* 多线程中 exec 可能在此间隙发生 */

open + fcntl(F_SETFD) 之间存在竞态窗口。用 O_CLOEXEC 标志一步到位。

自测题

题目 1（选择）： fcntl(fd, F_SETFL, flags) 可以改变以下哪个标志？ A. O_RDONLY B. O_WRONLY C. O_NONBLOCK D. O_CREAT

参考答案

C。F_SETFL 只能改 O_APPEND、O_NONBLOCK、O_ASYNC 等状态标志，不能改访问模式（O_RDONLY 等）。

题目 2（判断）： FD_CLOEXEC 是文件状态标志，存在打开文件描述中。

参考答案

错误。FD_CLOEXEC 是 fd 标志，存在进程 fd 表中，每个 fd 私有。文件状态标志（如 O_APPEND）才在打开文件描述中。

题目 3（踩坑）： 以下代码试图将文件改为非阻塞，有什么问题？

fcntl(fd, F_SETFL, O_NONBLOCK);
参考答案

问题：F_SETFL 会覆盖所有状态标志。应该先 F_GETFL 取回当前标志，再 OR 上 O_NONBLOCK： fcntl(fd, F_SETFL, fcntl(fd, F_GETFL) | O_NONBLOCK);

题目 4（应用）： 写代码设置 fd 为非阻塞模式。

参考答案 
int flags = fcntl(fd, F_GETFL);
if (flags < 0) return -1;
return fcntl(fd, F_SETFL, flags | O_NONBLOCK);

代码示例

#include <stdio.h>
#include <fcntl.h>
#include <unistd.h>
/* fcntl: 获取/设置文件描述符属性 */
int main(void) {
    int fd = open("/tmp/fcntl_test.txt", O_RDWR | O_CREAT, 0644);

    /* 获取文件状态标志 */
    int flags = fcntl(fd, F_GETFL);
    printf("access mode: %s\n",
           (flags & O_ACCMODE) == O_RDONLY ? "RDONLY" :
           (flags & O_ACCMODE) == O_WRONLY ? "WRONLY" : "RDWR");

    /* 设置 O_NONBLOCK */
    fcntl(fd, F_SETFL, flags | O_NONBLOCK);
    flags = fcntl(fd, F_GETFL);
    printf("O_NONBLOCK set: %s\n", (flags & O_NONBLOCK) ? "yes" : "no");

    /* 获取文件描述符标志 */
    int fdflags = fcntl(fd, F_GETFD);
    printf("FD_CLOEXEC: %s\n", (fdflags & FD_CLOEXEC) ? "yes" : "no");

    close(fd);
    return 0;
}

5.3

Open File Status Flags

本章：TLPI 第 05 章 — File I/O: Further Details

本节讲什么

fcntl() 的 F_GETFL/F_SETFL 可以获取和设置文件状态标志（O_APPEND/O_NONBLOCK/O_ASYNC 等）。

要点

获取文件状态标志

int flags = fcntl(fd, F_GETFL);
if (flags & O_APPEND)    /* 追加模式 */
if (flags & O_NONBLOCK)  /* 非阻塞模式 */

设置文件状态标志

int flags = fcntl(fd, F_GETFL);
flags |= O_NONBLOCK;
fcntl(fd, F_SETFL, flags);

可修改 vs 不可修改的标志

可修改 (F_SETFL) 不可修改（只能在 open 时设置）
O_APPEND O_RDONLY / O_WRONLY / O_RDWR
O_NONBLOCK O_CREAT
O_ASYNC O_TRUNC
O_DIRECT O_EXCL

常见误区

误区 纠正
可以用 F_SETFL 改读写模式 不可以，访问模式只能 open 时设定

自测要点

  • 如何用 fcntl 获取和设置 O_NONBLOCK？
  • 哪些标志可以用 F_SETFL 修改，哪些不能？

5.4

Relationship Between File Descriptors and Open Files

本章：TLPI 第 05 章 — File I/O: Further Details

本节讲什么

fd 和打开文件的关系：多个 fd 可以指向同一个打开文件，共享偏移量和状态标志。

要点

三层结构

进程级 fd 表          系统级打开文件表       inode 表
[fd 0] ──────────→ [打开文件描述] ──────→ [inode]
[fd 1] ──────────→ [打开文件描述] ──────→ [inode]
[fd 3] ──────────→ [打开文件描述] ──────→ [inode]

共享场景

场景 结果
同一进程两次 open() 同一文件 两个 fd，两个打开文件描述，各自独立偏移量
fork() 后子进程继承 fd 父子共享同一打开文件描述，共享偏移量
dup()/dup2() 两个 fd 指向同一打开文件描述，共享偏移量

打开文件描述 (open file description) 包含

  • 文件偏移量 (offset)
  • 文件状态标志 (O_APPEND, O_NONBLOCK...)
  • 访问模式 (O_RDONLY...)
  • 引用计数

常见误区

误区 纠正
两次 open 同一文件共享偏移量 不共享，各自独立
fork 后父子进程有独立的偏移量 共享，fork 复制 fd 表但不复制打开文件描述

自测要点

  • fd 表、打开文件表、inode 表三层结构是什么？
  • fork 后父子进程的 fd 是否共享偏移量？
  • dup() 后两个 fd 是否共享偏移量？

5.2

`dup` / `dup2` / `dup3`

本章：TLPI 第 05 章 — File I/O: Further Details - 上一节：5.1 内核三层结构（本章核心 · 必考） - 下一节：5.3 pread / pwrite

本节讲什么

include int dup(int oldfd); / 最小可用编号，同一打开描述 / int dup2(int oldfd, int newfd); / newfd 已开则先 close；再复制 /

要点

#include <unistd.h>
int dup(int oldfd);                        /* 最小可用编号，同一打开描述 */
int dup2(int oldfd, int newfd);            /* newfd 已开则先 close；再复制 */
int dup3(int oldfd, int newfd, int flags); /* Linux；可带 O_CLOEXEC */

典型用途：重定向 stdin/stdout（shell 管道、exec 前重定向）。
Demo：code/dup_share_offset.c

常见陷阱

  1. dup2 的 close-on-exec
dup2(oldfd, newfd);  /* newfd 没有 CLOEXEC */

dup2 复制的 fd 不继承 close-on-exec 标志。exec 前需要手动设置，或用 dup3(fd, newfd, O_CLOEXEC)。

  1. dup2 目标已打开
dup2(oldfd, newfd);  /* 如果 newfd 已打开，先关闭 */

dup2 如果 newfd 已打开，会先关闭再复制。如果不希望这样，应先检查。

  1. 共享偏移的意外
int fd2 = dup(fd1);
/* fd1 和 fd2 共享文件偏移 */
lseek(fd1, 0, SEEK_SET);  /* fd2 的偏移也变了! */

dup 复制的 fd 共享同一个打开文件描述（包括偏移）。lseek 通过一个 fd 会影响另一个。

自测题

题目 1（选择）： dup2(oldfd, newfd) 和 dup(oldfd) 的区别？ A. 没有区别 B. dup2 可以指定目标 fd 编号 C. dup2 更快 D. dup 只能复制到 0

参考答案

B。dup 返回最小可用 fd，dup2 可以指定目标 fd 编号 newfd。

题目 2（判断）： dup 复制的 fd 有独立的文件偏移。

参考答案

错误。dup 复制的 fd 共享同一个打开文件描述，包括文件偏移和状态标志。

题目 3（踩坑）： 以下代码在 exec 后会发生什么？

int fd = open("f.txt", O_RDONLY);
dup2(fd, STDIN_FILENO);
execvp("cat", argv);
参考答案

dup2 复制的 fd 默认没有 FD_CLOEXEC，所以 exec 后 stdin 仍然指向 f.txt。这正是 shell 重定向的原理。

题目 4（应用）： 写代码实现 shell 的输出重定向 cmd > file.txt。

参考答案 
int fd = open("file.txt", O_WRONLY|O_CREAT|O_TRUNC, 0644);
dup2(fd, STDOUT_FILENO);
close(fd);
execvp(cmd, argv);

代码示例

#include <stdio.h>
#include <fcntl.h>
#include <unistd.h>
/* dup/dup2/dup3: 复制文件描述符 */
int main(void) {
    int fd = open("/dev/null", O_WRONLY);
    int new_fd = dup(fd);          /* 返回最小可用 fd */
    int fd10 = dup2(fd, 10);       /* 复制到 fd=10 */
    printf("dup: %d, dup2(fd,10): %d\n", new_fd, fd10);
    close(fd); close(new_fd); close(fd10);
    return 0;
}

5.3

`pread` / `pwrite`

本章：TLPI 第 05 章 — File I/O: Further Details - 上一节：5.2 dup / dup2 / dup3 - 下一节：5.4 原子操作

本节讲什么

ssize_t pread(int fd, void buf, size_t count, off_t offset); ssize_t pwrite(int fd, const void buf, size_t count, off_t offset); Demo：code/pread_demo.c

要点

ssize_t pread(int fd, void *buf, size_t count, off_t offset);
ssize_t pwrite(int fd, const void *buf, size_t count, off_t offset);
特性
偏移 用参数 offset；不改 当前文件偏移
原子性 单次调用原子；lseek+read 组合非原子（多线程会乱）
场景 多线程随机读写、DB 引擎
限制 不可用于管道/socket 等不可 seek 对象

Demo：code/pread_demo.c

常见陷阱

  1. 短读未处理
/* 假设一次读完 */
ssize_t n = read(fd, buf, 1024);
/* n 可能 < 1024 */

read 返回值可能小于请求字节数（short read）。网络和管道尤其常见，必须循环读。

  1. EINTR 未处理
/* 信号中断后 read 返回 -1, errno=EINTR */
/* 不是错误，应重试 */

信号中断系统调用时返回 -1 且 errno=EINTR。应该重试，或用 SA_RESTART 自动重启。

  1. EOF 判断错误
/* 用 feof 预判 EOF → 多读一次 */
while (!feof(fp)) { fgets(...); }
/* 正确：检查返回值 */
while (fgets(buf, sz, fp) != NULL) { ... }

read 返回 0 表示 EOF。不要用 feof 预判（feof 只在读取越过后才为真）。

自测题

题目 1（选择）： read() 返回 0 表示什么？ A. 出错 B. EOF C. 没有数据 D. 需要重试

参考答案

B。返回 0 表示已到达文件末尾（EOF）。返回 -1 表示出错，返回 >0 表示读到的字节数。

题目 2（判断）： read 一定会读满请求的字节数。

参考答案

错误。read 可能返回少于请求的字节数（short read），尤其在管道、socket、终端上。必须循环读。

题目 3（踩坑）： 以下代码有什么问题？

char buf[1024];
read(fd, buf, sizeof(buf));
buf[strlen(buf)] = '\0';
参考答案

1) read 不保证以 null 结尾；2) 没检查返回值；3) strlen 在未终止的 buf 上越界。应检查返回值并手动加 \0。

题目 4（应用）： 写一个安全的 readall 函数，确保读满 n 字节或遇到 EOF。

参考答案 
ssize_t readall(int fd, void *buf, size_t n) {
    size_t total = 0;
    while (total < n) {
        ssize_t r = read(fd, (char*)buf+total, n-total);
        if (r < 0 && errno == EINTR) continue;
        if (r < 0) return -1;
        if (r == 0) break; /* EOF */
        total += r;
    }
    return total;
}

代码示例

#include <stdio.h>
#include <fcntl.h>
#include <unistd.h>
#include <string.h>
/* pread/pwrite: 在指定偏移读写, 不改变文件偏移量 */
int main(void) {
    int fd = open("/tmp/pread_test.txt", O_RDWR | O_CREAT | O_TRUNC, 0644);
    write(fd, "0123456789ABCDEF", 16);

    /* pread 从偏移5读, 不改变当前偏移 */
    char buf[4];
    pread(fd, buf, 3, 5);
    buf[3] = '\0';
    printf("pread(5,3): %s\n", buf);

    /* 当前偏移仍在16 */

    printf("offset after pread: %ld (unchanged)\n", (long)pos);

    /* pwrite 在指定偏移写 */

    pread(fd, buf, 3, 10);
    buf[3] = '\0';
    printf("pwrite(10,XYZ): %s\n", buf);
    close(fd);
    return 0;
}

5.7

非阻塞 `O_NONBLOCK`

本章：TLPI 第 05 章 — File I/O: Further Details - 上一节：5.6 打开标志补充（扩展 Ch4） - 下一节：5.8 大文件 LFS

本节讲什么

要点

对象 行为
普通磁盘文件 通常 无效果（读盘一般不靠这个变「非阻塞」）
管道 / FIFO / socket / 终端 无数据时 read 立即 -1，errno=EAGAIN/EWOULDBLOCK

O_NONBLOCK ≠ 异步 AIO；只是「不睡、立刻返回」的轮询式语义。

代码示例

#include <fcntl.h>
#include <unistd.h>
#include <errno.h>
#include <stdio.h>
#include <string.h>

int main(void) {
    int pipefd[2];
    if (pipe(pipefd) < 0) { perror("pipe"); return 1; }

    /* 把读端设为非阻塞 */
    int flags = fcntl(pipefd[0], F_GETFL);
    fcntl(pipefd[0], F_SETFL, flags | O_NONBLOCK);

    /* 管道里没数据 → read 立即返回 -1, errno=EAGAIN */
    char buf[64];
    ssize_t n = read(pipefd[0], buf, sizeof(buf));
    if (n < 0) {
        if (errno == EAGAIN || errno == EWOULDBLOCK) {
            printf("read 返回 -1, errno=EAGAIN (无数据可读)\n");
        } else {
            perror("read");
        }
    } else if (n == 0) {
        printf("EOF\n");
    } else {
        printf("读到 %zd 字节\n", n);
    }

    /* 写入数据后非阻塞读就能拿到 */
    write(pipefd[1], "hi", 2);
    n = read(pipefd[0], buf, sizeof(buf));
    printf("第二次 read: %zd 字节: %.*s\n", n, (int)n, buf);

    close(pipefd[0]);
    close(pipefd[1]);
    return 0;
}

代码示例

#include <fcntl.h>
#include <unistd.h>
#include <stdio.h>

/* 加了 _FILE_OFFSET_BITS=64 后 off_t 自动变 64 位 */
int main(void) {

    /* 创建一个大文件（用 lseek 跳到 5GB 处写 1 字节） */
    int fd = open("/tmp/bigfile.dat", O_WRONLY | O_CREAT, 0644);
    if (fd < 0) { perror("open"); return 1; }

    off_t target = (off_t)5 * 1024 * 1024 * 1024;  /* 5 GB */

    printf("文件大小: %lld bytes (%.1f GB)\n",
           (long long)size, (double)size / (1024.0 * 1024 * 1024));

    close(fd);
    return 0;
}

代码自测

1. dup2(fd, 2) 和 close(2); fcntl(fd, F_DUPFD, 2) 的区别？

dup2(fd, 2) 原子地关闭 fd 2 并将 fd 复制到 2。close(2); fcntl(fd, F_DUPFD, 2) 分两步，中间可能被信号中断或另一线程抢占 fd 2。在多线程或信号处理程序中应使用 dup2 或 F_DUPFD_CLOEXEC。

2. F_GETFL 返回的 access mode 怎么判断？

不能直接 & O_RDONLY（O_RDONLY 是 0）。需用 mask = result & O_ACCMODE，然后判断 mask 是 O_RDONLY(0)、O_WRONLY(1) 还是 O_RDWR(2)。

3. readv 如何实现一次读取头部+数据体？ 
struct iovec iov[2];
iov[0].iov_base = &header;  iov[0].iov_len = sizeof(header);
iov[1].iov_base = body_buf; iov[1].iov_len = body_len;
ssize_t n = readv(fd, iov, 2);

一次系统调用完成两个不连续缓冲区的读取，比分两次 read 更高效。

特性 dup2(fd, 2) close(2); fcntl(fd, F_DUPFD, 2)

练习 2 答案

线程 A: lseek(fd, 100, SEEK_SET)  → 偏移量=100
线程 B: lseek(fd, 500, SEEK_SET)  → 偏移量=500
线程 A: read(fd, buf, 10)         → 从 500 开始读！错误

pread(fd, buf, 10, 100) 不修改偏移量，多线程调用互不干扰。

练习 3 参考代码

struct msg_header {
    uint32_t magic;
    uint32_t body_len;
};

ssize_t read_message(int fd, struct msg_header *hdr, char *body, size_t body_cap) {
    /* 先读头部 */
    ssize_t n = read(fd, hdr, sizeof(*hdr));
    if (n != sizeof(*hdr)) return -1;
    if (hdr->body_len > body_cap) return -1;

    /* 用 readv 一次读取头部+数据体（演示 readv 用法） */
    struct iovec iov[2];
    iov[0].iov_base = hdr;
    iov[0].iov_len = sizeof(*hdr);
    iov[1].iov_base = body;
    iov[1].iov_len = hdr->body_len;

    /* 注意：需要先 lseek 回退头部位置 */
    lseek(fd, -sizeof(*hdr), SEEK_CUR);
    return readv(fd, iov, 2);
}

练习 4 答案

场景 read 返回值 errno
无写端打开 0 (EOF) —
有写端但无数据 -1 EAGAIN
有写端且有数据 实际字节数 —
所有写端关闭后 0 (EOF) —

关键区别：O_NONBLOCK 下，FIFO 有写端但无数据返回 -1/EAGAIN；无写端返回 0/EOF。阻塞模式下，无数据会阻塞等待，无写端返回 0/EOF。
