导读

优先级：🟡→🔴（可移植性 / 路径长度 / 管道原子写边界；Ch15 / Ch36 / Ch44 都要回头看这一章） 前置：Ch3（syscall 与 errno 范式——本章所有「-1 到底是哪个意思」全靠这个）· Ch10（_SC_CLK_TCK ↔ times()） 后置：Ch12 系统与进程信息（/proc、uname——限制信息的另一来源）· Ch15 文件属性（NAME_MAX / PATH_MAX 的实际使用）· Ch36 进程资源（RLIMIT_*）· Ch44 管道与 FIFO（_PC_PIPE_BUF）

章节目标

  • 分清三个入口：编译期宏 / 运行时全局查询 / 运行时路径查询。问错了入口，答案本身就是错的（问 NAME_MAX 用 sysconf() 根本查不到——没有 _SC_NAME_MAX 这个常量）
  • -1 有三义：① 调用失败（errno 被设）② 限制不确定（errno 不变）③ 选项不支持（-1 就是答案）。同一个返回值，三种处置
  • limit 与 option 是两类问题：limit 的答案是「一个数」，option 的答案是「支持 / 不支持」。man-pages 把 RETURN VALUE 拆成两条写，正是因为它们共用了 -1
  • 诚实：本仓库把 man-pages 6.19、POSIX.1-2017、glibc 2.39、Linux v6.6 的相关段落全部抓下来逐字核对，发现书上的若干说法需要修正（_SC_ARG_MAX 的 2 MiB 只是「名义值」；_PC_PATH_MAX 压根不问文件系统）
  • 溯源：本章 7 篇笔记里的每一行实测输出都能在 CE 日志 tlpi-ch11-final.txt 里定位；每一处 glibc / 内核坐标都实读核准

一条主线：四级分派

sysconf() 不是「查表」，而是一层层往下问，最后落到一个「查不到就报错」的兜底：

级 谁 在哪 管什么
① __sysconf（x86 特化） sysdeps/unix/sysv/linux/x86/sysconf.c:31-37 只拦 8 个 _SC_LEVEL*_CACHE_*，转给 __cache_sysconf，其余全丢给下一级
② linux_sysconf sysdeps/unix/sysv/linux/sysconf.c + linux/sysconf.c Linux 专属项：_SC_NGROUPS_MAX 读 /proc/sys/kernel/ngroups_max、_SC_ARG_MAX 算 rlim_stack/4、_SC_SIGQUEUE_MAX 取 RLIMIT_SIGPENDING …
③ posix_sysconf sysdeps/posix/sysconf.c POSIX 通项：_SC_CLK_TCK → __getclktck()、_SC_OPEN_MAX → __getdtablesize()、一堆 #ifdef ... return ...
④ default: sysdeps/posix/sysconf.c:64-66 __set_errno(EINVAL); return -1; —— 这才是「真错误」的唯一出处

同一套四级结构在 pathconf() 上重复一遍（x86 无特化，从 linux 起算），只是第 ① 级换成了「只有 4 个 _PC_* 真的去问文件系统」：

真的问文件系统（走 statfs） 直接返回编译期常量
_PC_LINK_MAX、_PC_FILESIZEBITS、_PC_2_SYMLINKS、_PC_CHOWN_RESTRICTED _PC_PATH_MAX → PATH_MAX(4096)、_PC_PIPE_BUF → PIPE_BUF(4096)、_PC_MAX_CANON / _PC_MAX_INPUT / _PC_VDISABLE → 常量

一句话：「文件相关的限制」里只有一半真的跟文件有关。

与 Ch10 / Ch12 边界（防混淆）

章 主题 内容
Ch10 Time 读 / 写 / 量时间。sysconf(_SC_CLK_TCK) 只是它顺手用过的一个常量
Ch11 System Limits and Options 问系统「能到什么程度」：数（limit）与布尔（option），三个入口（宏 / sysconf / pathconf），以及 -1 三种含义
Ch12 System and Process Information /proc、uname、sysinfo —— 另一种拿同样信息的方式，往往比 sysconf 更直接（例如 /proc/meminfo vs _SC_PHYS_PAGES）

Ch11 与 Ch12 是同一批数据的两个入口：Ch11 是 POSIX 可移植接口，Ch12 是 Linux 专有的「直接看内核」。移植优先 Ch11，刨根问底用 Ch12。

两个容易踩的坑：

容易踩的坑 正解
把 errno = 0 省掉 不能省。-1 到底是「错误」还是「不确定」，唯一判据就是 errno 是否被改动；不预先清零，你读到的是上一次调用留下的陈年 errno
以为 -1 一定是「失败」 -1 也可能是正确答案：选项不支持时就是 -1，而限制不确定时也是 -1（但 errno == 0）

易错清单

  1. _1 的三义必须靠 errno 拆开 —— ① 错误（errno != 0）② indeterminate（errno == 0）③ 选项不支持（-1 是答案，errno 也不变）。先把 errno = 0，再判断。
  2. sysconf() 对「不认识的常量」报 EINVAL —— 实测 sysconf(9999) → errno=22、返回 -1。唯一出处是 sysdeps/posix/sysconf.c:64-66。
  3. _SC_TZNAME_MAX 在本机恒为 -1 且 errno 不变 —— 它是恒 indeterminate，不是坏了（sysdeps/posix/sysconf.c:102-103 直接 return -1，不 set_errno）。同理 _SC_SYMLOOP_MAX、_SC_MQ_OPEN_MAX、_SC_SEM_NSEMS_MAX 也是（共 4 项）。
  4. _SC_OPEN_MAX 不是常量，它等于 getrlimit(RLIMIT_NOFILE).rlim_cur —— glibc 走 __getdtablesize()（sysdeps/posix/getdtsz.c:32）。实测：soft 从 100 降到 50 后，_SC_OPEN_MAX 立刻变成 50。man-pages 那句「值在进程生命期内不变」对它是不成立的。
  5. _SC_CLK_TCK 恒为 100，与 CONFIG_HZ 无关 —— 它是内核经 auxv 的 AT_CLKTCK 传进来的 USER_HZ；glibc 侧 __getclktck() 是 GLRO(dl_clktck) ?: SYSTEM_CLK_TCK，兜底值写死 100（sysdeps/unix/sysv/linux/getclktck.c:22-31）。
  6. _SC_ARG_MAX 的 2 MiB 是「名义值」 —— 实测本机 _SC_ARG_MAX = 2097152（= RLIMIT_STACK(8 MiB)/4，glibc linux/sysconf.c:56-67），但同一台机器上 execve 传 65536 字节 OK / 131072 字节 E2BIG(7)。真正卡住的是 MAX_ARG_STRLEN = PAGE_SIZE*32 = 131072（include/uapi/linux/binfmts.h:16）。
  7. ARG_MAX 本身「难以使用」是官方承认的 —— man-pages BUGS 段原话：「It is difficult to use ARG_MAX because it is not specified how much of the argument space for exec(3) is consumed by the user's environment variables.」另外还有一条：「Some returned values may be huge; they are not suitable for allocating memory.」
  8. pathconf 的返回值可能带「脏 errno」 —— 实测 pathconf("/lib", _PC_LINK_MAX) 返回正确的 65000，但 errno 被留成 2（ENOENT）。原因是 glibc 区分 ext2/3/4 时先 readlink /sys/dev/block/MAJ:MIN，失败退到 /proc/mounts，失败那次把 ENOENT 留在了 errno（sysdeps/unix/sysv/linux/pathconf.c:63-128 的 distinguish_extX）。返回值对 ≠ errno 干净。
  9. _PC_PATH_MAX 不查文件系统 —— 它直接 return PATH_MAX（sysdeps/posix/pathconf.c:89-93）。所以本仓库扫 60 个挂载点，_PC_PATH_MAX 一律 4096，不管底层是 tmpfs 还是 nfs。
  10. _PC_PIPE_BUF 也不查文件系统 —— 直接 return PIPE_BUF（sysdeps/posix/pathconf.c:96-100），实测恒 4096。
  11. _PC_LINK_MAX 才会随文件系统变，而且值很分散 —— 实测：tmpfs 127、ext4 65000、squashfs 127。glibc 的常量表（linux_fsinfo.h:255-268）里 ext2/3 = 32000、ext4 = 65000、XFS = 2147483647、F2FS = 32000、未知 = 127。用 127 当「硬上限」会浪费 500 倍空间。
  12. pathconf("") 是 ENOENT，不是 EINVAL —— 实测 errno=2。空路径在 sysdeps/posix/pathconf.c:32-36 就被挡掉了（if (path[0] == '\0')）。
  13. pathconf 的错误码要分类读 —— 实测：9999 → EINVAL(22)；"" → ENOENT(2)；不存在的目录 → ENOENT(2)；/proc/version/inside（中间是普通文件）→ ENOTDIR(20)。
  14. fpathconf 的第一参数是 fd，所以失败是 EBADF 不是 ENOENT —— 实测 fpathconf(9999, _PC_NAME_MAX) → EBADF(9)；fpathconf(STDIN_FILENO, 9999) → EINVAL(22)。
  15. _PC_ASYNC_IO 在 glibc 里其实是返回 -1（indeterminate） —— sysdeps/posix/pathconf.c:128-141 有 S_ISREG/S_ISBLK 判断，但对普通文件返回 1、其它返回 -1 且不设 errno。实测 pathconf("/") 上 _PC_ASYNC_IO / _PC_SYNC_IO / _PC_PRIO_IO 三项都是 indeterminate。
  16. _PC_VDISABLE 不检查「这是不是终端」 —— 它直接返回 _POSIX_VDISABLE（sysdeps/posix/pathconf.c:115-119）。而 _PC_MAX_CANON / _PC_MAX_INPUT 在规范上要求 fd/path 必须是终端（man-pages 原文 "where fd or path must refer to a terminal"）—— 两者行为不一致。
  17. _POSIX_FOO 有四态，不是三态 —— 未定义 → 运行时问；-1 → 不支持；0 → 函数和头文件存在，但支持程度要运行时问；其它值（如 200809L）→ 支持，数字表示 POSIX 修订年月。glibc 还有个特例：修订版尚未发布时用 1 表示支持。
  18. _POSIX_MONOTONIC_CLOCK / _POSIX_CPUTIME / _POSIX_THREAD_CPUTIME 在 glibc 里都是 0 —— 不是「不支持」，是「存在但支持度要问」。所以 sysconf(_SC_MONOTONIC_CLOCK) 走的是 linux/sysconf.c:51-54 的 return _POSIX_VERSION（返回 200809），不等于宏的值 0。
  19. confstr() 和 sysconf() 不是同一回事 —— confstr() 返回字符串（_CS_PATH、_CS_GNU_LIBC_VERSION…），要靠返回值判长度：返回 0 表示「没有这个值」，返回 >n 表示缓冲区太小、需要多大就给你多大。实测 _CS_PATH 需 14 B → "/bin:/usr/bin"；_CS_GNU_LIBC_VERSION 11 B → "glibc 2.39"。
  20. getconf 命令是验证手段，但精简系统里常常没有 —— CE 沙箱里既无 getconf 也无 /bin/sh，所以本仓库的交叉验证一律靠自编程序里打两遍，不靠外部命令。
  21. fd 用满是 EMFILE，且硬上限抬不动 —— 实测 soft=50 时只能开到 47 个（0/1/2 已占），第 48 个 errno=24 EMFILE；setrlimit 把 soft 抬到 hard+1 → EINVAL(22)。所以「_SC_OPEN_MAX 报 100 就敢开 100 个 fd」是错的。
  22. _SC_NPROCESSORS_CONF 会留下脏 errno —— 实测它返回 2 但 errno 被留成 2（ENOENT），跟第 8 条同源。判断「是不是错误」不能只看 errno != 0，必须先 errno = 0 再调。

双线提示

路线
HFT 路径缓冲区永远不要按 PATH_MAX 写死——它只是「相对路径的最大长度」，拼接后的绝对路径可以远超；_PC_PIPE_BUF 实测恒 4096，也就是说管道上超过 4 KiB 的一次 write 不保证原子，多线程写同一条管道必须先自己分片；_SC_OPEN_MAX 要在改过 RLIMIT_NOFILE 之后重查（它不是常量），行情网关进程开几万个连接前先 setrlimit 再 sysconf 复核；_SC_ARG_MAX 报 2 MiB 而 execve 实际 128 KiB 就 E2BIG，热重启子进程时把大配置塞进 argv 会炸，改用 stdin / 临时文件；_POSIX_MONOTONIC_CLOCK == 0 别误读成「不支持 MONOTONIC 时钟」——要 sysconf(_SC_MONOTONIC_CLOCK) 看 _POSIX_VERSION
嵌入式 交叉编译时 _SC_* / _PC_* 的运行时值才是真的，宿主机上查到的数字一个都不能带到板子上；只读根文件系统 + tmpfs /tmp 的组合会让 pathconf 在同一台设备上按路径给出不同答案（这正是 11-2 习题的考点）；BusyBox 精简系统里没有 getconf，程序里要么自带 sysconf 探测、要么读 /proc；老 uClibc / musl 对 _SC_* 的覆盖面比 glibc 小得多，遇到 EINVAL 要能降级到编译期宏；_POSIX_VDISABLE 在串口控制台上的行为跟 PC 终端不一样，写 TTY 初始化代码前先 pathconf 确认
两条线共同的坑 「未定义就当成 0」——<limits.h> 里 ARG_MAX / OPEN_MAX / LINK_MAX / NR_OPEN 都被 glibc 主动 #undef（注释写在 bits/local_lim.h：这些值运行时可变，给个宏会误导）。用之前一律 #ifdef，并且不要把「未定义」当「不支持」

几条实测结论（都是本仓库跑出来的，不是书上抄的）：

  • _SC_OPEN_MAX 会跟着 rlimit 变：RLIMIT_NOFILE soft=hard=100 时 _SC_OPEN_MAX = 100；把 soft 降到 50 之后立刻变 50 —— 「值在进程生命期内不变」对它不成立
  • _SC_ARG_MAX = 2097152（名义）vs execve 128 KiB 就 E2BIG：65536 字节 OK，131072 字节 errno=7。差 16 倍
  • _SC_CLK_TCK = 100、_SC_PAGESIZE = 4096、_SC_VERSION = 200809，改 rlimit 前后一字不变
  • 下限宏 vs 实测：_POSIX_OPEN_MAX 20 → 100、_POSIX_CHILD_MAX 25 → 54956、_POSIX_GROUPS_MAX 8 → 65536、_POSIX_STREAM_MAX 8 → 16、_POSIX_LOGIN_NAME_MAX 9 → 256、_POSIX_TTY_NAME_MAX 9 → 32、_POSIX_NAME_MAX 14 → 255、_POSIX_PATH_MAX 256 → 4096、_POSIX_PIPE_BUF 512 → 4096 —— 标准给的是「保证」，实际常常宽 2000 倍
  • indeterminate 实测清单：sysconf 侧 4 项 _SC_TZNAME_MAX / _SC_SYMLOOP_MAX / _SC_MQ_OPEN_MAX / _SC_SEM_NSEMS_MAX；pathconf("/") 侧 3 项 _PC_ASYNC_IO / _PC_SYNC_IO / _PC_PRIO_IO
  • _PC_LINK_MAX 按文件系统分三档：tmpfs 127 / ext4 65000 / squashfs 127；_PC_NAME_MAX 是 tmpfs 255 / ext4 255 / squashfs 256
  • _PC_PATH_MAX 恒 4096、_PC_PIPE_BUF 恒 4096，跨 60 个挂载点无一例外 —— 因为它们是编译期常量，不查文件系统
  • 错误码实测：sysconf(9999) → EINVAL(22)；pathconf("/", 9999) → EINVAL(22)；pathconf("") → ENOENT(2)；pathconf("/proc/version/inside") → ENOTDIR(20)；fpathconf(9999, …) → EBADF(9)
  • confstr 三连：_CS_PATH 需 14 B → "/bin:/usr/bin"；_CS_GNU_LIBC_VERSION 11 B → "glibc 2.39"；_CS_GNU_LIBPTHREAD_VERSION 10 B → "NPTL 2.39"
  • _SC_2_FORT_DEV = -1（不支持），而 _SC_2_VERSION = 200809、_SC_XOPEN_VERSION = 700
  • fd 用满：soft=50 时只能开 47 个（0/1/2 已占），第 48 个 EMFILE(24)；把 soft 抬到 hard+1 → EINVAL(22)

11.1

System Limits 系统限制

本章：TLPI 第 11 章 — System Limits and Options 源码核验：glibc 2.39（sysdeps/posix/sysconf.c、sysdeps/posix/getdtsz.c、sysdeps/unix/sysv/linux/getclktck.c、posix/bits/posix1_lim.h）+ Linux v6.6（include/uapi/linux/limits.h、include/uapi/asm-generic/resource.h）+ man-pages 6.19 sysconf(3) + CE 实测（gcc 13.3.0 / x86-64 / Ubuntu 24.04） - 上一节：本章首页 - 下一节：11.2 Retrieving System Limits (and Options) at Run Time 运行时查询

本节讲什么

本章要解决的是可移植性问题：同一个程序在别人的机器上为什么读写文件会失败、exec 会报错、管道里的消息会撕裂。根源是「上限」不是常量——它随内核配置、rlimit、文件系统、容器裁剪而变。

本节只回答三个问题（其余小节展开）：

  1. limit 和 option 是两回事吗？为什么 man-pages 要把它们写成两段？
  2. SUSv3 把限制分成哪三类？为什么这个分类决定了你该用哪个查询函数？
  3. <limits.h> 里那个 _POSIX_NAME_MAX = 14 是「实际值」还是「最低承诺」？

1. 术语：limit 与 option 是两类问题

man-pages 6.19 sysconf(3) 的 DESCRIPTION 把它们分开写，原文：

At compile time this is done by including <unistd.h> and/or <limits.h> and testing the value of certain macros.

At run time, one can ask for numerical values using the present function sysconf(). One can ask for numerical values that may depend on the filesystem in which a file resides using fpathconf(3) and pathconf(3). One can ask for string values using confstr(3).

概念 问的是什么 答案的形状 例子
Limit（限制） 某个资源的上限/下限 一个数（可能 indeterminate） ARG_MAX、OPEN_MAX、NAME_MAX、PATH_MAX、PIPE_BUF
Option（选项） 某个可选特性有没有实现 支持 / 不支持（三态，见 11.5） _POSIX_THREADS、_POSIX_REALTIME_SIGNALS、_POSIX_BARRIERS

两者答案的形态完全不同，但查询入口共用同一个 sysconf()、返回值也共用同一个 -1。这是本章最大的坑的来源：11.2 会看到「限制 indeterminate」和「选项不支持」在 -1 + errno 上完全无法区分。

2. SUSv3 的三类限制（决定用哪个查询函数）

类 名字 特征 查询入口 本章例子
1 运行时恒定 进程生命期内不变；<limits.h> 里可能根本没定义 sysconf() _SC_CLK_TCK、_SC_PAGESIZE、_SC_VERSION
2 路径名相关 依赖具体文件系统 / 挂载点，同一台机器上两个目录答案可以不同 pathconf() / fpathconf() _PC_NAME_MAX、_PC_LINK_MAX、_PC_FILESIZEBITS
3 运行时可增 标准只保证「不低于下限」，运行时可以改大 sysconf() + rlimit _SC_OPEN_MAX ↔ RLIMIT_NOFILE

类 3 是最容易误判的一类。TLPI 的说法是「值可以增加」——而 Linux 上它压根不是一个上限，只是 getrlimit(RLIMIT_NOFILE).rlim_cur 的当前快照。看第 4 节的实测：

--- 改 rlimit 之前 ---
  _SC_OPEN_MAX     = 100
setrlimit(soft -> 50) 成功
--- 改 rlimit 之后 ---
  _SC_OPEN_MAX     = 50

sysconf(_SC_OPEN_MAX) 自己会变。所以 man-pages 那句「The values obtained from these functions are system configuration constants. They do not change during the lifetime of a process.」对类 3 是不成立的（11.7 习题 11-1 会把这个矛盾单独拎出来）。

3. 下限宏：_POSIX_* 是「保证」不是「实际」

man-pages sysconf(3) 原文：

If the constant is defined, it gives a guaranteed value, and a greater value might actually be supported.

所以 _POSIX_NAME_MAX 是 14 不代表文件名只能 14 个字符，而是「POSIX 承诺至少 14——一个只支持 14 字符的实现也合法」。本机 255，是「更大」的那一侧。

宏 POSIX 保证的下限 本机实测 差多少
_POSIX_ARG_MAX 4096 2097152（_SC_ARG_MAX） 512×
_POSIX_CHILD_MAX 25 54956（_SC_CHILD_MAX） 2198×
_POSIX_NGROUPS_MAX 8 65536（_SC_NGROUPS_MAX） 8192×
_POSIX_OPEN_MAX 20 100（_SC_OPEN_MAX） 5×
_POSIX_STREAM_MAX 8 16（_SC_STREAM_MAX） 2×
_POSIX_LOGIN_NAME_MAX 9 256（_SC_LOGIN_NAME_MAX） 28×
_POSIX_TTY_NAME_MAX 9 32（_SC_TTY_NAME_MAX） 3.6×
_POSIX_NAME_MAX 14 255（NAME_MAX） 18×
_POSIX_PATH_MAX 256 4096（PATH_MAX） 16×
_POSIX_PIPE_BUF 512 4096（PIPE_BUF） 8×

一旦按「保证下限」去分配缓冲区，就会在真实机器上偏小；一旦按「本机实测」写死，就会在别的机器上偏大或偏小。两条路都不通，所以要用运行时查询（11.2）。

诚实说明：上表「本机实测」一列来自第 4 节的同一次运行。其中 _SC_CHILD_MAX（跟 RLIMIT_NPROC 走）在容器里会随宿主机负载变化——重跑一次就可能是另一个数（本仓库两次运行分别拿到 54956 与 56783）。只有 _SC_ARG_MAX / _SC_OPEN_MAX / _SC_PAGESIZE 这类由固定 rlimit 或编译期常量决定的项是稳定的。

4. 代码：三类限制的现场对照

完整源码 code/c11_1_three_kinds.c：

/* c11_1_three_kinds.c — Ch11 §11.1：三类限制的现场对照
 *
 * TLPI 把 SUSv3 的限制分三类，本节只用一次实验把「类 1 恒定」和
 * 「类 3 运行时可改」摆在一起：
 *
 *   实验：先查四个 _SC_*，再把 RLIMIT_NOFILE 的 soft 减半，再查同样的四项。
 *         _SC_CLK_TCK / _SC_PAGESIZE / _SC_VERSION 一位不变（类 1）；
 *         _SC_OPEN_MAX 跟着 RLIMIT_NOFILE 走（类 3 —— 它甚至不是「上限」，
 *         只是一个当前值）。
 *
 * 类 2（路径相关）需要另一个文件系统才能看出差别，放到 §11.3 / 习题 11-2。
 *
 * 编译： gcc -O0 -Wall -Wextra -o c11_1_three_kinds c11_1_three_kinds.c
 * 取材： sysconf(3) 的 RETURN VALUE 段（man-pages 6.19）
 *        glibc 2.39 sysdeps/posix/sysconf.c:82-83（_SC_CLK_TCK -> __getclktck()）
 *                              :92-93（_SC_OPEN_MAX -> __getdtablesize()）
 *                  sysdeps/posix/getdtsz.c:32（= getrlimit(RLIMIT_NOFILE).rlim_cur）
 *                  sysdeps/unix/sysv/linux/getclktck.c:22-23（SYSTEM_CLK_TCK 兜底 100）
 *        Linux v6.6 include/uapi/asm-generic/resource.h:30-31（RLIMIT_NOFILE = 7）
 */
#define _GNU_SOURCE
#include <errno.h>
#include <limits.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <sys/resource.h>
#include <unistd.h>

static long sc(int name)
{
    errno = 0;
    return sysconf(name);
}

static const struct { int name; const char *lbl; } FOUR[] = {
    { _SC_CLK_TCK,      "_SC_CLK_TCK" },
    { _SC_PAGESIZE,     "_SC_PAGESIZE" },
    { _SC_VERSION,      "_SC_VERSION" },
    { _SC_OPEN_MAX,     "_SC_OPEN_MAX" },
};

static void dump_four(const char *when)
{
    printf("--- %s ---\n", when);
    for (size_t i = 0; i < sizeof(FOUR) / sizeof(FOUR[0]); i++)
        printf("  %-16s = %ld\n", FOUR[i].lbl, sc(FOUR[i].name));
}

int main(void)
{
    printf("### 一次实验：把 RLIMIT_NOFILE 的 soft 减半，再看这四项\n");
    dump_four("改 rlimit 之前");

    struct rlimit r;
    if (getrlimit(RLIMIT_NOFILE, &r) != 0) {
        perror("getrlimit");
        return 1;
    }
    printf("\nRLIMIT_NOFILE: soft=%lu hard=%lu\n",
           (unsigned long)r.rlim_cur, (unsigned long)r.rlim_max);

    struct rlimit low = r;
    low.rlim_cur = (r.rlim_max >= 10) ? r.rlim_max / 2 : r.rlim_max;   /* 只降不升 */
    if (setrlimit(RLIMIT_NOFILE, &low) != 0) {
        printf("setrlimit 失败: %s\n", strerror(errno));
        return 1;
    }
    printf("setrlimit(soft -> %lu) 成功\n\n", (unsigned long)low.rlim_cur);

    dump_four("改 rlimit 之后");

    printf("\n结论：前三项与环境无关（类 1 运行时恒定）；\n");
    printf("      _SC_OPEN_MAX 只是「RLIMIT_NOFILE 的当前值」，改了它就变（类 3）。\n");
    printf("      glibc 的实现是一行：return __getrlimit(RLIMIT_NOFILE,&ru)<0 ? OPEN_MAX : ru.rlim_cur;\n");

    printf("\n### SUSv3 保证的只是「不低于这个下限」（<limits.h> / <unistd.h>）\n");
    printf("  %-22s %-10s %s\n", "保证下限宏", "值", "本机实测（未改 rlimit 时）");
    printf("  %-22s %-10s %ld\n", "(CLK_TCK：无下限宏)", "--", sc(_SC_CLK_TCK));
    printf("  %-22s %-10d %ld\n", "_POSIX_OPEN_MAX", _POSIX_OPEN_MAX,
           (long)r.rlim_max);
    printf("  %-22s %-10d %ld\n", "_POSIX_CHILD_MAX", _POSIX_CHILD_MAX, sc(_SC_CHILD_MAX));
    printf("  %-22s %-10d %ld\n", "_POSIX_NGROUPS_MAX", _POSIX_NGROUPS_MAX, sc(_SC_NGROUPS_MAX));
    printf("  %-22s %-10d %ld\n", "_POSIX_STREAM_MAX", _POSIX_STREAM_MAX, sc(_SC_STREAM_MAX));
    printf("  %-22s %-10d %ld\n", "_POSIX_LOGIN_NAME_MAX", _POSIX_LOGIN_NAME_MAX,
           sc(_SC_LOGIN_NAME_MAX));
    printf("  %-22s %-10d %ld\n", "_POSIX_TTY_NAME_MAX", _POSIX_TTY_NAME_MAX, sc(_SC_TTY_NAME_MAX));
    printf("  %-22s %-10d %ld\n", "_POSIX_NAME_MAX", _POSIX_NAME_MAX, (long)NAME_MAX);
    printf("  %-22s %-10d %ld\n", "_POSIX_PATH_MAX", _POSIX_PATH_MAX, (long)PATH_MAX);
    printf("  %-22s %-10d %ld\n", "_POSIX_PIPE_BUF", _POSIX_PIPE_BUF, (long)PIPE_BUF);

    printf("\n注意四件事：\n");
    printf("  1) 下限宏是「保证」，不是「实际」。_POSIX_NAME_MAX=14 看着很荒唐，\n");
    printf("     但 POSIX 只承诺 14 —— 它允许一个文件系统只支持 14 字符文件名。\n");
    printf("  2) <limits.h> 里 NAME_MAX/PATH_MAX/PIPE_BUF 有定义，ARG_MAX/OPEN_MAX/LINK_MAX\n");
    printf("     却被 glibc 主动 #undef 掉了（见 §11.3 的源码）。用它们之前先 #ifdef。\n");
    printf("  3) _SC_CLK_TCK 不等于内核的 HZ：它是「times() 的节拍频率」，\n");
    printf("     本机是 %ld，而内核 HZ 是内核编译期常量，两者不必相同。\n", sc(_SC_CLK_TCK));
    printf("  4) 第一行连下限宏都没有：全库找不到 _POSIX_CLK_TCK。POSIX.1-2017\n");
    printf("     <limits.h>/<sysconf> 原文只说「The symbol CLK_TCK is obsolescent\n");
    printf("     and removed.」—— 它只保证 _SC_CLK_TCK 查得到，不承诺任何下限。\n");

}

  3) _SC_CLK_TCK 不等于内核的 HZ：它是「times() 的节拍频率」，
     本机是 100，而内核 HZ 是内核编译期常量，两者不必相同。
  4) 第一行连下限宏都没有：全库找不到 _POSIX_CLK_TCK。POSIX.1-2017
     <limits.h>/<sysconf> 原文只说「The symbol CLK_TCK is obsolescent
     and removed.」—— 它只保证 _SC_CLK_TCK 查得到，不承诺任何下限。

4.1 glibc 是怎么实现的（两个函数九行）

_SC_OPEN_MAX 走到 sysdeps/posix/sysconf.c:92-93：

    case _SC_OPEN_MAX:
      return __getdtablesize ();

而 __getdtablesize 的整个函数体（sysdeps/posix/getdtsz.c:25-33）是：

int
__getdtablesize (void)
{
  struct rlimit ru;

  /* This should even work if `getrlimit' is not implemented.  POSIX.1
     does not define this function but we will generate a stub which
     returns -1.  */
  return __getrlimit (RLIMIT_NOFILE, &ru) < 0 ? OPEN_MAX : ru.rlim_cur;
}

「_SC_OPEN_MAX 会变」不是行为怪异，就是字面上一行 return ... ru.rlim_cur。 失败时兜底用的 OPEN_MAX 是 256（sysdeps/unix/sysv/linux/getdtsz.c:19，注释写着 /* This comes from the Linux kernel header. */），不是 POSIX 的 _POSIX_OPEN_MAX=20。

_SC_CLK_TCK 走 :82-83 → __getclktck()（sysdeps/unix/sysv/linux/getclktck.c:22-31）：

#ifndef SYSTEM_CLK_TCK
# define SYSTEM_CLK_TCK 100
#endif

/* Return frequency of times().  */
int
__getclktck (void)
{
  return GLRO(dl_clktck) ?: SYSTEM_CLK_TCK;
}

内核的 HZ（编译期常量，常见 250 / 1000）与它没有关系——times() 的节拍频率是内核通过 AT_CLKTCK 辅助向量（auxv）告诉用户态的，本机就是 100。

坑 说明

代码自测（Q&A）

Q1：limit 和 option 有什么区别？为什么要分开讲？ A：limit 的答案是一个数，option 的答案是支持/不支持。两者都通过 sysconf() 查询、失败都返回 -1，所以 man-pages 的 RETURN VALUE 段把它们拆成两条来写：限制那条说「indeterminate 时 -1 且 errno 不变」，选项那条说「不支持时 -1」。返回值形态一样，语义完全不同——这就是 c11_2_sysconf_table.c 要在同一张表里同时打 errno 的原因。

Q2：SUSv3 的三类限制分别是什么？为什么分类重要？ A：① 运行时恒定（sysconf）；② 路径名相关、随文件系统变（pathconf/fpathconf）；③ 运行时可增（sysconf + rlimit）。分类重要是因为它直接决定用哪个函数：问 NAME_MAX 用 sysconf 根本查不到（没有 _SC_NAME_MAX），必须 pathconf；而问 _SC_OPEN_MAX 用 pathconf 也没意义，它是进程级的。

Q3：实测中 _SC_OPEN_MAX 从 100 变成 50，这违反「值在进程生命期内不变」吗？ A：违反。man-pages 那句 "They do not change during the lifetime of a process." 只对类 1/类 2 成立。_SC_OPEN_MAX 在 glibc 里就是 __getrlimit(RLIMIT_NOFILE, &ru) < 0 ? OPEN_MAX : ru.rlim_cur（sysdeps/posix/getdtsz.c:32），rlim_cur 一变它就变。程序里 setrlimit(RLIMIT_NOFILE, &low) 把 soft 从 100 降到 50 之后立刻重查，得到 50。

Q4：_POSIX_ARG_MAX = 4096，本机 _SC_ARG_MAX = 2097152，那我能不能按 4096 分配参数缓冲？ A：不能按它去分配（太小），但也不能按 2097152 去写死（别的机器可以是 4096）。正确做法是运行时查。另外要注意 _SC_ARG_MAX 只是「理论值」：本仓库在 CE 上实测 execve 传 128 KiB 的单个参数就 E2BIG，真正卡住的是 MAX_ARG_STRLEN = PAGE_SIZE*32 = 131072（见 11.2 与 11.3 的实测）。

Q5：为什么 _POSIX_CLK_TCK 查不到？ A：因为 POSIX 从来没定义过它。本仓库把 POSIX.1-2017 的 <limits.h> / <unistd.h> / <sysconf> 全文抓下来 grep，没有 _POSIX_CLK_TCK；<sysconf> 原文只说 "The symbol CLK_TCK is obsolescent and removed. It is replaced with the phrase "clock ticks per second"." 所以这一项只有 _SC_CLK_TCK 可查，没有下限宏。这也是第 3 节表格第一行写 -- 的原因。

Q6：_SC_CLK_TCK 和内核对 HZ 是什么关系？ A：没有直接关系。_SC_CLK_TCK 是内核在启动时通过 auxv 的 AT_CLKTCK 传给 libc 的（glibc 存进 GLRO(dl_clktck)），__getclktck() 优先用它，缺省才退回编译期的 SYSTEM_CLK_TCK=100。它决定的是 times() 的返回值怎么换算成秒，与内核内部调度节拍 HZ 是两个独立的东西。

Q7：<limits.h> 里到底哪些宏能直接用？ A：实测结论：NAME_MAX(255) / PATH_MAX(4096) / PIPE_BUF(4096) 有定义；ARG_MAX / OPEN_MAX / LINK_MAX / NR_OPEN 被 glibc 主动 #undef（原因写在 bits/local_lim.h 的注释里：这些值运行时可变，宏会误导）。所以用之前一律先 #ifdef，不要以为「未定义就是 0」。

本节讲什么

本节把「运行时查询」这件事做到底：sysconf() 的返回值只有 -1 一种失败信号，但它有三种完全不同的含义。分清这三次是本章的核心技能。四个问题：

  1. -1 的三义分别是什么？哪两个在返回值 + errno 上完全一样（因此不可能靠返回值区分）？
  2. 「不重置 errno」会怎样误报错误？给一段现场。
  3. 「值是对的」就说明这次调用干净吗？（不是）
  4. _SC_ARG_MAX 报 2 MiB，为什么 execve 传 128 KiB 就 E2BIG 了？

2. -1 的三义（man-pages 原文）

man-pages 6.19 sysconf(3) 的 RETURN VALUE 段逐字：

The return value of sysconf() is one of the following:

  • On error, -1 is returned and errno is set to indicate the error (for example, EINVAL, indicating that name is invalid).
  • If name corresponds to a maximum or minimum limit, and that limit is indeterminate, -1 is returned and errno is not changed. (To distinguish an indeterminate limit from an error, set errno to zero before the call, and then check whether errno is nonzero when -1 is returned.)
  • If name corresponds to an option, a positive value is returned if the option is supported, and -1 is returned if the option is not supported.

拆成表：

# 情况 返回值 errno 可区分吗
a 真错误（name 非法） -1 EINVAL(22) 可（errno != 0）
b 限制 indeterminate -1 不变（调用前清零则仍是 0） 可（errno == 0）
c 选项不支持 -1 不变 不可——与 b 一模一样
d 正常 具体值 不变 可

所以正确的判断骨架是：

errno = 0;
long v = sysconf(name);
if (v == -1) {
    if (errno == 0)
        /* b 或 c：不知道确切值，或该选项不支持 —— 都要走「保守回退」 */
    else
        /* a：真错误，比如 EINVAL。这才是 bug（拼错了 name 常量） */
}

errno = 0 必须写在每次调用之前，而不是函数开头写一次。 第 5 节的 ⑥ 段会把「只清一次」造成的误报现场打出来。

3. 原书 Listing 11-1（page 216）：t_sysconf.c

原书第一个示例就是「用 errno == 0 区分 indeterminate 与错误」。逐字镜像（本仓库 code/t_sysconf.c）：

/* t_sysconf.c

   Demonstrate the use of sysconf() to retrieve system limits.
*/
#include "tlpi_hdr.h"
static void             /* Print 'msg' plus sysconf() value for 'name' */
sysconfPrint(const char *msg, int name)
{
    long lim;

    errno = 0;
    lim = sysconf(name);
    if (lim != -1) {        /* Call succeeded, limit determinate */
        printf("%s %ld\n", msg, lim);
    } else {
        if (errno == 0)     /* Call succeeded, limit indeterminate */
            printf("%s (indeterminate)\n", msg);
        else                /* Call failed */
            errExit("sysconf %s", msg);
    }
}
int

{

坑 说明
只在函数开头 errno = 0 一次 ⑥ 段现场：任何前面的失败都会污染判断，把一个 indeterminate 误报成错误

代码自测（Q&A）

Q1：sysconf() 返回 -1 有几种含义？怎么区分？ A：三种。① 真错误（errno 被设，如 EINVAL）；② 限制 indeterminate（errno 不变）；③ 选项不支持（errno 不变）。②和③无法互相区分——它们的「返回值 + errno」完全一样。可区分的只有「真错误」与「非错误」：调用前 errno = 0，返回 -1 时看 errno 是否为 0。

Q2：为什么 errno = 0 要写在每次调用之前？ A：因为 errno 是线程局部但跨调用存活的。⑥ 段现场：先 sysconf(9999)（把 errno 置 22），不清零再查 _SC_TZNAME_MAX，得到 -1 errno=22——一个完全正常的 indeterminate 被误报成错误。glibc 对 _SC_TZNAME_MAX 的实现是 case _SC_TZNAME_MAX: return -1;（sysdeps/posix/sysconf.c:102-103），它压根不碰 errno。

Q3：_SC_NPROCESSORS_ONLN = 2 但 errno = 2，这说明调用失败了吗？ A：没有。⑦ 段就是这个现场：值 2 是正确的（沙箱 2 核），errno=2(ENOENT) 是 glibc 内部读 /sys 时留下的。只要返回值不是 -1，errno 就没有解读意义。用 errno != 0 判失败会在这里误报。

Q4：_SC_TZNAME_MAX 为什么会 indeterminate？ A：因为它属于「时区名长度」——glibc 不想承诺一个具体值。man-pages 的 RETURN VALUE 允许实现这样做：「If name corresponds to a maximum or minimum limit, and that limit is indeterminate, -1 is returned and errno is not changed.」本机 indeterminate 一共 4 项：_SC_TZNAME_MAX / _SC_SYMLOOP_MAX / _SC_MQ_OPEN_MAX / _SC_SEM_NSEMS_MAX。

Q5：_SC_ARG_MAX = 2097152 是 RLIMIT_STACK 的 1/4，为什么是这个算法？ A：glibc 的目标是「参数+环境不能把栈吃光」。sysdeps/unix/sysv/linux/sysconf.c:56-67：limit = MAX(legacy_ARG_MAX, rlimit.rlim_cur / 4); return MIN(limit, maximum_ARG_MAX)。本机 RLIMIT_STACK = 8388608 → 8388608/4 = 2097152；上限被夹在 6 MiB（maximum_ARG_MAX），下限被抬到 128 KiB（legacy_ARG_MAX）。

Q6：那为什么 execve 传 131072 字节就失败了？ A：因为内核另有硬约束：MAX_ARG_STRLEN = PAGE_SIZE * 32 = 131072（include/uapi/linux/binfmts.h:15），由 valid_arg_len()（fs/exec.c:297-300）在 copy_string_kernel()（fs/exec.c:618-650）里检查，越线返回 -E2BIG。实测 65536 OK、131072 就 errno=7。sysconf 给的数与内核实际接受的长度是两套规则。

Q7：sysconf() 会不会做 I/O？ A：会。_SC_NGROUPS_MAX 走 /proc/sys/kernel/ngroups_max（sysdeps/unix/sysv/linux/sysconf.c:97-118，open + read + strtol + close）；_SC_SIGQUEUE_MAX 先试 getrlimit(RLIMIT_SIGPENDING)、失败再读 /proc/sys/kernel/rtsig-max；_SC_NPROCESSORS_* 走 /sys。这也是 ⑦ 段 errno 被污染的原因。

Q8：这套分派为什么要分成 x86 特化 + linux + posix 三层？ A：为了复用。CPU cache 那 12 项需要 cpuid/sysfs 的体系结构相关代码（__cache_sysconf），放在 x86/sysconf.c；Linux 通用但非 POSIX 的部分（/proc、rlimit、_POSIX_VERSION 直返）放 linux/sysconf.c；纯 POSIX 表放 sysdeps/posix/sysconf.c，用 #define __sysconf static posix_sysconf + #include 组装。所以同一个 sysconf(_SC_ARG_MAX) 在三层的表现完全不同。

Retrieving File-Related Limits (and Options) at Run Time 文件相关限制

本章：TLPI 第 11 章 — System Limits and Options 源码核验：glibc 2.39（sysdeps/unix/sysv/linux/pathconf.c、sysdeps/unix/sysv/linux/fpathconf.c、sysdeps/posix/pathconf.c、sysdeps/unix/sysv/linux/linux_fsinfo.h）+ Linux v6.6（include/uapi/linux/limits.h、fs/pipe.c）+ man-pages 6.19 fpathconf(3) + CE 实测（gcc 13.3.0 / x86-64 / Ubuntu 24.04） - 上一节：11.2 Retrieving System Limits (and Options) at Run Time 运行时查询 - 下一节：11.4 Indeterminate Limits 不确定的限制

本节讲什么

本节是「类 2 限制」的实现细节。它的核心结论有点反直觉：

pathconf() 里只有 4 个 _PC_* 真的去问了文件系统。 其余大多数是把编译期常量原样返回。

所以本节要回答：

  1. 哪些 _PC_* 真的随文件系统变？哪些只是「穿着 pathconf 外衣的 #define」？
  2. 同一组问题问 /（tmpfs）和 /lib（ext4），哪些格子会变？变多少？
  3. _PC_PIPE_BUF 是「这个管道的容量」吗？（不是）
  4. 空串、不存在的路径、路径中间不是目录，errno 分别是多少？

1. 原型

#include <unistd.h>

long fpathconf(int fd, int name);
long pathconf(const char *path, int name);
/* 成功返回该配置项的值；-1 的三义与 sysconf() 完全一致（见 11.2） */

man-pages 6.19 fpathconf(3) 对两者的区别只有一句：

fpathconf() gets a value for the configuration option name for the open file descriptor fd.

pathconf() gets a value for configuration option name for the filename path.

以及一句容易被忽略的：

The corresponding macros defined in <unistd.h> are minimum values; if an application wants to take advantage of values which may change, a call to fpathconf() or pathconf() can be made, which may yield more liberal results.

ERRORS（man-pages 原文列出，本仓库实测逐条验证）

errno 何时 本仓库实测（见第 4 节 C 段）
EACCES path 的某个前缀目录没有搜索权限 未构造（CE 沙箱是 root）
EBADF fd 不是有效 fd（仅 fpathconf） fpathconf(9999, …) → errno=9
EINVAL name 非法，或该实现不支持把 name 关联到这个文件 pathconf("/", 9999) → errno=22
ELOOP 解析 path 时符号链接层数过多 未构造
ENAMETOOLONG path 太长 未构造
ENOENT path 的某一段不存在 pathconf("/no/such/dir/xyz", …) → errno=2
ENOTDIR path 的某一段不是目录 pathconf("/proc/version/inside", …) → errno=20

2. _PC_* 的真实分工

_PC_* man-pages 语义 glibc 2.39 的实际实现 会随文件系统变吗
_PC_LINK_MAX 文件最大硬链接数（对目录＝该目录内） __statfs_link_max()：按 statfs().f_type 查表 会（ext4 65000 / 其余 127）
_PC_FILESIZEBITS 文件大小所需位数 __statfs_filesize_max()：按 f_type 查表 会（ext4 64 / 其余 32）
_PC_NAME_MAX 该目录里允许创建的文件名最大长度 statvfs().f_namemax（超级块上报） 会（squashfs 报 256）
_PC_PATH_MAX 相对路径最大长度（当 path/fd 是当前工作目录时） 直接 return PATH_MAX; 不会（恒 4096）
_PC_PIPE_BUF 能原子写入管道/FIFO 的最大字节数 直接 return PIPE_BUF; 不会（恒 4096）
_PC_CHOWN_RESTRICTED chown 是否受限 return _POSIX_CHOWN_RESTRICTED; 不会
_PC_NO_TRUNC 超长文件名是否报错（而非截断） return _POSIX_NO_TRUNC; 不会
_PC_VDISABLE 终端「禁用字符」的值 return _POSIX_VDISABLE;（不检查是不是终端） 不会
_PC_ASYNC_IO 是否支持异步 I/O S_ISREG(mode) \|\| S_ISBLK(mode) 才 1，否则 -1 看对象类型，不看文件系统

结论：把 pathconf() 当成「问文件系统」的万能入口是错的。 真正落到文件系统的只有前 3 项（加上 4 个 statfs 项里的 _PC_2_SYMLINKS / _PC_CHOWN_RESTRICTED），其余是常量转发。

3. 原书 Listing 11-2（page 218）：t_fpathconf.c

原书示例对 STDIN_FILENO 问三项。逐字镜像（本仓库 code/t_fpathconf.c）：

/* t_fpathconf.c

   Demonstrate the use of fpathconf() to retrieve the values of
   pathname-related limits.
*/
#include "tlpi_hdr.h"
static void             /* Print 'msg' plus value of fpathconf(fd, name) */
fpathconfPrint(const char *msg, int fd, int name)
{
    long lim;

    errno = 0;
    lim = fpathconf(fd, name);
    if (lim != -1) {        /* Call succeeded, limit determinate */
        printf("%s %ld\n", msg, lim);
    } else {
        if (errno == 0)     /* Call succeeded, limit indeterminate */
            printf("%s (indeterminate)\n", msg);
        else                /* Call failed */
            errExit("fpathconf %s", msg);
    }
}
int
main(int argc, char *argv[])
{
    fpathconfPrint("_PC_NAME_MAX: ", STDIN_FILENO, _PC_NAME_MAX);
    fpathconfPrint("_PC_PATH_MAX: ", STDIN_FILENO, _PC_PATH_MAX);
    fpathconfPrint("_PC_PIPE_BUF: ", STDIN_FILENO, _PC_PIPE_BUF);
    exit(EXIT_SUCCESS);
}

结构与 Listing 11-1 同构：errno = 0 → fpathconfPrint() → 非 -1 打印值 / errno == 0 打 (indeterminate) / 否则 errExit。

编译运行：

gcc -O0 -Wall -Wextra -Wno-unused-parameter -o t_fpathconf t_fpathconf.c && ./t_fpathconf

CE（gcc 13.3.0 / x86-64 / Ubuntu 24.04）实测：

_PC_NAME_MAX:  255
_PC_PATH_MAX:  4096

三项都拿到了值。注意这里 STDIN_FILENO 在沙箱里是管道（不是终端），但三项照样有答案——因为 glibc 的这三项不看 fd 指向什么（_PC_NAME_MAX 走 statvfs，管道 fd 也能 statvfs 成功）。

4. 自编：三种维度的矩阵

t_fpathconf 只问了一个 fd、三项；本 demo 把「换文件系统」「换 fd 类型」「换错误条件」三个维度都拉开。

完整源码 code/c11_3_pathconf_matrix.c：

/* c11_3_pathconf_matrix.c — Ch11 §11.3：pathconf() / fpathconf() 到底查了什么
 *
 * §11.3 的核心不是「会调用这两个函数」，而是搞清哪些 _PC_* 真的会去问文件
 * 系统、哪些其实只是把编译期常量原样返回。本程序用一个矩阵把它分开：
 *
 *   A. 同一组问题，问两个**不同文件系统**上的路径（/ 是 tmpfs，/lib 是 ext4）。
 *      只有 _PC_LINK_MAX / _PC_FILESIZEBITS 变了 —— 它们是按 statfs().f_type
 *      分派的；_PC_NAME_MAX 来自 statvfs().f_namemax；而 _PC_PATH_MAX 与
 *      _PC_PIPE_BUF 无论问谁都是同一个编译期常量。
 *
 *   B. 同一组问题，问四种**不同 fd 类型**。_PC_ASYNC_IO 会分叉（普通文件 1，
 *      管道/字符设备 -1），其余照旧。
 *
 *   C. 错误码矩阵：空串、不存在的路径、路径中间不是目录、非法 name、非法 fd。
 *
 * 编译： gcc -O0 -Wall -Wextra -o c11_3_pathconf_matrix c11_3_pathconf_matrix.c
 * 取材： glibc 2.39 sysdeps/unix/sysv/linux/pathconf.c:45-55（按 statfs 分派四项）
 *        glibc 2.39 sysdeps/unix/sysv/linux/pathconf.c:63-128（distinguish_extX：/sys/dev/block -> /proc/mounts）
 *        glibc 2.39 sysdeps/posix/pathconf.c:32-36（空串 -> ENOENT）
 *        glibc 2.39 sysdeps/posix/pathconf.c:40-42（default -> EINVAL）
 *        glibc 2.39 sysdeps/posix/pathconf.c:65-86（_PC_NAME_MAX -> statvfs.f_namemax）
 *        glibc 2.39 sysdeps/posix/pathconf.c:89-93（_PC_PATH_MAX -> PATH_MAX 常量）
 *        glibc 2.39 sysdeps/posix/pathconf.c:96-100（_PC_PIPE_BUF -> PIPE_BUF 常量）
 *        glibc 2.39 sysdeps/unix/sysv/linux/linux_fsinfo.h:256 EXT4_LINK_MAX=65000
 *        glibc 2.39 sysdeps/unix/sysv/linux/linux_fsinfo.h:268 LINUX_LINK_MAX=127
 *        Linux v6.6 include/uapi/linux/limits.h:13-14 PATH_MAX/PIPE_BUF
 */
#define _GNU_SOURCE
#include <errno.h>
#include <fcntl.h>
#include <limits.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <sys/statfs.h>
#include <sys/statvfs.h>
#include <unistd.h>

struct item { int name; const char *lbl; };

static const struct item PC[] = {
    { _PC_NAME_MAX,  "_PC_NAME_MAX" },
    { _PC_LINK_MAX,  "_PC_LINK_MAX" },
    { _PC_FILESIZEBITS, "_PC_FILESIZEBITS" },
    { _PC_PATH_MAX,  "_PC_PATH_MAX" },
    { _PC_PIPE_BUF,  "_PC_PIPE_BUF" },
    { _PC_NO_TRUNC,  "_PC_NO_TRUNC" },
    { _PC_CHOWN_RESTRICTED, "_PC_CHOWN_RESTRICTED" },
    { _PC_ASYNC_IO,  "_PC_ASYNC_IO" },
};

/* 两列对照打印：值 + errno + 是否不同 */
static void row(const char *what, long a, int ea, long b, int eb)
{
    printf("  %-20s %-8ld (errno %d)   %-8ld (errno %d)   %s\n",
           what, a, ea, b, eb, (a != b) ? "** 不同 **" : "相同");
}

static void matrix_paths(void)
{
    const char *p1 = "/";       /* CE 沙箱里是 tmpfs */
    const char *p2 = "/lib";    /* 绑定挂载的 ext4 */
    FILE *f;
    char dev[128], mnt[128], type[32];

    printf("### A. 同一组问题问两个文件系统\n");
    printf("  %-20s %-19s %-19s %s\n", "", p1, p2, "");
    for (size_t i = 0; i < sizeof(PC) / sizeof(PC[0]); i++) {
        errno = 0; long a = pathconf(p1, PC[i].name); int ea = errno;
        errno = 0; long b = pathconf(p2, PC[i].name); int eb = errno;
        row(PC[i].lbl, a, ea, b, eb);
    }

    printf("\n  两者的身份（读 /proc/mounts + statfs）：\n");
    for (int k = 0; k < 2; k++) {
        const char *p = k ? p2 : p1;
        struct statfs sf;
        if (statfs(p, &sf) != 0) { printf("    statfs(%s) 失败\n", p); continue; }
        struct statvfs sv;
        long nm = statvfs(p, &sv) == 0 ? (long)sv.f_namemax : -1;
        printf("    %-6s f_type=0x%-8lx f_namemax=%-4ld", p, (unsigned long)sf.f_type, nm);
        f = fopen("/proc/mounts", "r");
        if (f) {
            while (fscanf(f, "%127s %127s %31s %*s %*s %*s", dev, mnt, type) == 3)
                if (strcmp(mnt, p) == 0) break;
            fclose(f);
            printf(" 挂载类型=%s\n", type);
        } else {
            printf("\n");
        }
    }
    printf("\n  glibc 的分工（源码）：_PC_LINK_MAX/_PC_FILESIZEBITS 按 statfs().f_type 查表；\n");
    printf("  _PC_NAME_MAX 取 statvfs().f_namemax；_PC_PATH_MAX 直接 return PATH_MAX；\n");
    printf("  _PC_PIPE_BUF 直接 return PIPE_BUF。后两个与文件系统无关。\n");
    printf("  （A 段 _PC_LINK_MAX 问 /lib 那一格带着 errno=2：glibc 区分 ext2/3/4 时要先\n");
    printf("    readlink /sys/dev/block/MAJ:MIN，失败再退到 /proc/mounts；失败那一次把\n");
    printf("    ENOENT 留在了 errno 里。值是对的，errno 脏了。）\n");
}

static void matrix_fds(void)
{
    int pipefd[2];
    if (pipe(pipefd) != 0) { perror("pipe"); return; }
    const char *regpath = "/etc/hostname";
    int reg = open(regpath, O_RDONLY);
    if (reg < 0) { regpath = "/proc/version"; reg = open(regpath, O_RDONLY); }
    int nul = open("/dev/null", O_RDONLY);

    struct { const char *lbl; int fd; } fds[] = {
        { "STDIN_FILENO", STDIN_FILENO },
        { "pipe read end", pipefd[0] },
        { "regular file",  reg },
        { "/dev/null",     nul },
    };

    printf("\n### B. 同一组问题问四种 fd\n");
    printf("  %-20s %-12s %-12s %-12s %-12s\n", "", fds[0].lbl, fds[1].lbl,
           fds[2].lbl, fds[3].lbl);
    for (size_t i = 0; i < sizeof(PC) / sizeof(PC[0]); i++) {
        long v[4]; int e[4];
        printf("  %-20s", PC[i].lbl);
        for (int k = 0; k < 4; k++) {
            errno = 0;
            v[k] = (fds[k].fd < 0) ? -1 : fpathconf(fds[k].fd, PC[i].name);
            e[k] = errno;
            if (v[k] == -1 && e[k] == 0) printf(" %-12s", "-1(indet)");
            else if (v[k] == -1)         printf(" %-12s", "ERR");
            else                          printf(" %-12ld", v[k]);
        }
        printf("\n");
    }
    printf("  说明：_PC_PIPE_BUF 对任何 fd 都返回 4096（编译期常量，不是「这个管道的容量」）；\n");
    printf("        _PC_ASYNC_IO 只在普通文件/块设备上是 1（glibc 对 path 做 S_ISREG||S_ISBLK 判断）。\n");
    printf("        B 段「regular file」这一列实际打开的是 %s。\n", regpath);

    if (reg >= 0) close(reg);
    if (nul >= 0) close(nul);
    close(pipefd[0]);
    close(pipefd[1]);
}

static void err_matrix(void)
{
    printf("\n### C. 错误码矩阵\n");
#define E(call, expect)                                                  \
    do {                                                                 \
        errno = 0;                                                       \
        long r = (call);                                                 \
        printf("  %-46s -> %-4ld errno=%-2d %-22s %s\n", #call, r,       \
               errno, strerror(errno),                                   \
               (errno == (expect)) ? "" : "<- 与预期不符");              \
    } while (0)

    E(pathconf("", _PC_NAME_MAX),            ENOENT);
    E(pathconf("/no/such/dir/xyz", _PC_NAME_MAX), ENOENT);
    E(pathconf("/proc/version/inside", _PC_NAME_MAX), ENOTDIR);
    E(pathconf("/", 9999),                   EINVAL);
    E(fpathconf(9999, _PC_NAME_MAX),         EBADF);
    E(fpathconf(STDIN_FILENO, 9999),         EINVAL);
#undef E
    printf("  三点注意：\n");
    printf("  1) pathconf(\"\") 不是 EINVAL 而是 ENOENT —— glibc 在 sysdeps/posix/pathconf.c:32-36\n");
    printf("     专门为它加了一个前置判断（空串在 open 语义里就等于「没给路径」）。\n");
    printf("  2) 「路径里某一段不存在」和「路径中间那一段不是目录」是两个不同的 errno：\n");
    printf("     第 2 行 ENOENT / 第 3 行 ENOTDIR。写重试逻辑时不能只判 ENOENT。\n");
    printf("  3) 非法的 name 与「本实现不支持把 name 关联到这个文件」共用 EINVAL，\n");
    printf("     和 sysconf 一样：-1 + errno 分不清「问错了」还是「不回答」。\n");
}

int main(void)
{
    matrix_paths();
    matrix_fds();
    err_matrix();

    printf("\n### D. 这三个值在别处也见得到，别混为一谈\n");
    printf("  <limits.h> 的 PATH_MAX   = %d  (= <linux/limits.h> 里的 #define PATH_MAX 4096)\n",
           PATH_MAX);
    printf("  <limits.h> 的 PIPE_BUF   = %d  (决定 write(2) 的原子上界，不是管道容量)\n",
           PIPE_BUF);
    printf("  <limits.h> 的 NAME_MAX   = %d  (内核 uapi 里写死的，而 pathconf 会按 fs 回话)\n",
           NAME_MAX);
    printf("  管道容量是另一回事：本机 pipe() 出来默认 65536，可用 fcntl(F_SETPIPE_SZ) 改。\n");
    return 0;
}

A _PC_PATH_MAX / _PC_PIPE_BUF 两列相同 它们在 glibc 里就是 return PATH_MAX; / return PIPE_BUF;，与文件系统无关
A /lib 那格 _PC_LINK_MAX = 65000 却带 errno=2 glibc 要先区分 ext2/3/4：readlink("/sys/dev/block/MAJ:MIN") 失败 → 退到 /proc/mounts；失败那一次的 ENOENT 留在了 errno 里。值正确、errno 脏
B _PC_PIPE_BUF 对四种 fd 都是 4096 不是「这个管道的容量」。管道容量是另一回事：内核 pipe_max_size = 1048576、默认 65536（fs/pipe.c:54），可用 fcntl(F_SETPIPE_SZ) 改
B _PC_ASYNC_IO 只有普通文件是 1，管道//dev/null/stdin 是 -1 glibc 做的是 S_ISREG(mode) \|\| S_ISBLK(mode)（sysdeps/posix/pathconf.c:135），字符设备（/dev/null）不满足
C pathconf("") → ENOENT(2) 而不是 EINVAL glibc 在 sysdeps/posix/pathconf.c:32-36 有前置判断：if (path[0] == '\0') { __set_errno(ENOENT); return -1; }
C /no/such/dir/xyz → ENOENT(2)；/proc/version/inside → ENOTDIR(20) 两个不同的 errno，写重试/降级逻辑时不能只判 ENOENT
C fpathconf(9999, …) → EBADF(9) 而不是 EINVAL fpathconf 会先校验 fd；pathconf 没有这一步
D <limits.h> 的 NAME_MAX=255 与 pathconf 的 255 来源不同 前者是内核 uapi 写死的常量（include/uapi/linux/limits.h:12），后者是超级块上报的 f_namemax。两者可以不等

4.1 glibc 的分工（源码）

pathconf() 在 Linux 上先按 name 分流，只有 4 项走文件系统专属路径（sysdeps/unix/sysv/linux/pathconf.c:38-59）：

long int
__pathconf (const char *file, int name)
{
  struct statfs fsbuf;

  switch (name)
    {
    case _PC_LINK_MAX:
      return __statfs_link_max (__statfs (file, &fsbuf), &fsbuf, file, -1);

    case _PC_FILESIZEBITS:
      return __statfs_filesize_max (__statfs (file, &fsbuf), &fsbuf);

    case _PC_2_SYMLINKS:
      return __statfs_symlinks (__statfs (file, &fsbuf), &fsbuf);

    case _PC_CHOWN_RESTRICTED:
      return __statfs_chown_restricted (__statfs (file, &fsbuf), &fsbuf);

    default:
      return posix_pathconf (file, name);
    }
}

fpathconf() 结构相同（sysdeps/unix/sysv/linux/fpathconf.c:29-52），把 __statfs(file, …) 换成 __fstatfs(fd, …)，其余落 posix_fpathconf。

而「按 f_type 查表」的细节在 linux_fsinfo.h：

宏 值 行
EXT2_LINK_MAX 32000 sysdeps/unix/sysv/linux/linux_fsinfo.h:255
EXT4_LINK_MAX 65000 :256
F2FS_LINK_MAX 32000 :257
XFS_LINK_MAX 2147483647 :265
LINUX_LINK_MAX 127 :268

__statfs_link_max()（linux/pathconf.c:133-192）的骨架是 switch (fsbuf->f_type)：EXT2 走 distinguish_extX()（:63-128，因为它要区分 ext2/3 与 ext4）、F2FS → F2FS_LINK_MAX、XFS → XFS_LINK_MAX、default → LINUX_LINK_MAX。

distinguish_extX() 的分辨办法很土但有效：snprintf("/sys/dev/block/%u:%u") → readlink → 如果落在 /sys/fs/ext4/<base> 就 access() 一下——存在就是 ext4，不存在就是 ext2/3（:76-86）。读不到 /sys 就退到遍历 /proc/mounts（:92）。

5. PIPE_BUF 不是管道容量

这是本节最容易混的一个点，三个数各自不同：

名字 值 含义 出处
_PC_PIPE_BUF / PIPE_BUF 4096 write() 到管道的原子性上界：≤4096 的写不会与其他写者交错 include/uapi/linux/limits.h:14；pathconf 直接返回这个宏
管道容量（默认） 65536 管道缓冲区能存多少字节 fs/pipe.c（pipe_max_size = 1048576，fs/pipe.c:54），可 fcntl(F_SETPIPE_SZ) 改
/proc/sys/fs/pipe-max-size 1048576 单次可设的最大容量 同上

所以「用 pathconf(fd, _PC_PIPE_BUF) 查管道容量」是错的——查出来的永远是 4096。要查容量得用 fcntl(fd, F_GETPIPE_SZ)。

相关：小写入合并的行为在 fs/pipe.c:463-464——if ((buf->flags & PIPE_BUF_FLAG_CAN_MERGE) && offset + chars <= PAGE_SIZE)，这是「多个小 write 落进同一页」的条件，与 PIPE_BUF 的原子性保证是两件事。

6. 常见坑

坑 说明
用 pathconf() 查 _PC_PIPE_BUF 想知道管道容量 恒 4096。容量用 fcntl(F_GETPIPE_SZ)
以为 pathconf("/", _PC_PATH_MAX) 是「绝对路径上限」 man-pages 原文：relative pathname when path is the current working directory。拼绝对路径时预算要按「各级 NAME_MAX 之和」算，不能拿 4096 当万能缓冲
用 pathconf() 的 -1 当「文件不存在」 -1 可能来自 errno=0 的 indeterminate；必须配 errno 判（同 11.2）
认为「errno == 0 就代表这次调用干净」 A 段 /lib 的 _PC_LINK_MAX 值是对的，errno 却是 ENOENT(2)（glibc 内部探 /sys 留下的）。只在返回 -1 时看 errno
只判 ENOENT 就以为覆盖了所有「路径有问题」 ENOTDIR(20) 是另一种。EACCES / ELOOP / ENAMETOOLONG 还在后面
拿 pathconf() 去查目录的 _PC_MAX_CANON / _PC_VDISABLE glibc 不检查是不是终端就返回值（_PC_VDISABLE 返回 0，_PC_MAX_CANON 返回 255）——「看起来有值、其实没意义」，见 11.4 ④
fpathconf 前不检查 fd fpathconf(9999, …) 是 EBADF 而非 EINVAL；fd 是 -1 时更要先拦

代码自测（Q&A）

Q1：pathconf() 里哪些 _PC_* 真的会随文件系统变？ A：只有 _PC_LINK_MAX、_PC_FILESIZEBITS（按 statfs().f_type 查表）、_PC_NAME_MAX（statvfs().f_namemax），加上 4 个 statfs 分派项里的 _PC_2_SYMLINKS、_PC_CHOWN_RESTRICTED。_PC_PATH_MAX / _PC_PIPE_BUF / _PC_NO_TRUNC / _PC_VDISABLE 在 glibc 里是直接 return 一个宏，问谁都一样。

Q2：实测中 _PC_LINK_MAX 在 / 上是 127、在 /lib 上是 65000，为什么？ A：/ 是 tmpfs（f_type=0x1021994），走 default → LINUX_LINK_MAX = 127；/lib 是 ext4（0xef53）→ EXT4_LINK_MAX = 65000（linux_fsinfo.h:268 / :256）。另外 /lib 那格还带 errno=2——glibc 区分 ext2/3/4 时先 readlink("/sys/dev/block/MAJ:MIN") 失败，留下了 ENOENT。

Q3：_PC_PIPE_BUF = 4096 是「这个管道能存 4096 字节」吗？ A：不是。它是 write() 到管道/FIFO 的原子性上界（≤ 它的一次写不会被其他写者打断）。管道容量另算：本机默认 65536，上限 1048576（fs/pipe.c:54 的 pipe_max_size），可用 fcntl(fd, F_SETPIPE_SZ) 改、用 F_GETPIPE_SZ 查。而在 glibc 里 _PC_PIPE_BUF 干脆是 return PIPE_BUF;——与具体管道无关。

Q4：pathconf("", _PC_NAME_MAX) 为什么是 ENOENT 不是 EINVAL？ A：glibc 在 sysdeps/posix/pathconf.c:32-36 专门加了一个前置判断：if (path[0] == '\0') { __set_errno (ENOENT); return -1; }。理由在 open 语义里，空串等于「没给路径」而不是「路径非法」。所以它进不了 default:（那才是 EINVAL）。

Q5：_PC_PATH_MAX 的语义到底是什么？能当绝对路径缓冲上限吗？ A：man-pages 原文：「The maximum length of a relative pathname when path or fd is the current working directory.」所以它是「从 cwd 出发的相对路径」上限，不是绝对路径上限。绝对路径理论最大是「各级目录 NAME_MAX 之和 + 分隔符 + 结尾 \0」，可能超过 4096——所以拼绝对路径要动态扩容。

Q6：_PC_ASYNC_IO 为什么要看对象类型？ A：因为「异步 I/O」显然只对随机访问对象有意义。glibc 的实现（sysdeps/posix/pathconf.c:128-141）是：拿不到 stat 就 -1；S_ISREG(mode) || S_ISBLK(mode) 才 return 1，否则 return -1。所以同一个 pathconf("/", …) 对目录返回 -1，对普通文件返回 1。

Q7：fpathconf 比 pathconf 好在哪？ A：两点：① 无 TOCTOU——pathconf(path) 要重新解析路径，fpathconf(fd) 用的是已打开的对象，目录被换掉也不会查错；② 能问只有 fd 的对象——管道、socket、字符设备可能压根没有可用路径（或路径不可访问）。原书 Listing 11-2 就是用 STDIN_FILENO 演示这一点。本仓库在 c11_4_indeterminate.c 的降级阶梯里优先用 pathconf，是因为要问的是「某个目录」而不是「某个已打开对象」。

11.4

Indeterminate Limits 不确定的限制

本章：TLPI 第 11 章 — System Limits and Options 源码核验：glibc 2.39（sysdeps/posix/sysconf.c、sysdeps/posix/pathconf.c）+ POSIX.1-2017（<limits.h> 的 _POSIX_* 下限表）+ man-pages 6.19 sysconf(3) / fpathconf(3) + CE 实测（gcc 13.3.0 / x86-64 / Ubuntu 24.04） - 上一节：11.3 Retrieving File-Related Limits (and Options) at Run Time 文件相关限制 - 下一节：11.5 System Options 系统选项

本节讲什么

「不确定」是一种标准允许的合法状态：实现可以说「这个限制我有，但我不告诉你确切值」。此时 sysconf/pathconf 返回 -1 且 errno 不变。本节的三个问题：

  1. 本机上哪些 name 真的 indeterminate？
  2. 一个能分清「确定值 / 不确定 / 出错」的封装长什么样？
  3. 查不到的时候，程序该退到哪一级？（降级阶梯）

外加一个反方向的坑：有些结果「看起来有值」其实毫无意义，比 -1 更危险。

1. 什么叫 indeterminate

man-pages 6.19 sysconf(3) 的 RETURN VALUE 段（逐字）：

If name corresponds to a maximum or minimum limit, and that limit is indeterminate, -1 is returned and errno is not changed. (To distinguish an indeterminate limit from an error, set errno to zero before the call, and then check whether errno is nonzero when -1 is returned.)

fpathconf(3) 的 RETURN VALUE 段有对应的一句（把 name 换成 _PC_*）。要点：

想表达 返回值 errno 调用者该做什么
确定值 具体数 不变 直接用
indeterminate -1 不变（清零后仍为 0） 走保守回退，不是报错
真错误 -1 被设（EINVAL/EBADF/ENOENT…） 报错（这是 bug）

所以 indeterminate 不是「不支持」，而是「这个实现不回答」。前者是你问了一个它没有的功能，后者是它有、但拒绝给数。

2. 本机的 indeterminate 清单

完整源码 code/c11_4_indeterminate.c：

/* c11_4_indeterminate.c — Ch11 §11.4：indeterminate 限制与「查不到怎么办」
 *
 * §11.4 讲的是这样一类限制：标准允许系统**不告诉你确切值**。此时
 * sysconf/pathconf 返回 -1 且 errno 不变。问题在于：
 *
 *   ① 哪些 name 会 indeterminate？（本机实测清单）
 *   ② 一个安全的封装长什么样？
 *   ③ 查不到时程序该退到哪一级？（降级阶梯：sysconf -> pathconf -> 编译期宏 -> 保守常量）
 *
 * 编译： gcc -O0 -Wall -Wextra -o c11_4_indeterminate c11_4_indeterminate.c
 * 取材： sysconf(3) / fpathconf(3) RETURN VALUE 段（man-pages 6.19）；
 *       glibc 2.39 sysdeps/posix/sysconf.c:102-103（_SC_TZNAME_MAX 恒 -1）
 *       glibc 2.39 sysdeps/posix/pathconf.c:44-62（LINK_MAX/MAX_CANON/MAX_INPUT 可 -1）
 *       POSIX.1-2017 <limits.h>：_POSIX_* 是「保证下限」，实现可以更大

        { _SC_LOGIN_NAME_MAX, "_SC_LOGIN_NAME_MAX" }, { _SC_TTY_NAME_MAX, "_SC_TTY_NAME_MAX" },
        { _SC_TZNAME_MAX, "_SC_TZNAME_MAX" }, { _SC_SYMLOOP_MAX, "_SC_SYMLOOP_MAX" },

/* ---------- ② 安全封装：把「限制值」和「状态」分开 ---------- */
enum qstat { Q_OK, Q_INDETERMINATE, Q_ERROR };

static long query_sysconf(int name, enum qstat *st)
{
    errno = 0;
    long v = sysconf(name);
    if (v != -1) { *st = Q_OK; return v; }
    if (errno == 0) { *st = Q_INDETERMINATE; return -1; }
    *st = Q_ERROR;
    return -1;
}

static const char *qname(enum qstat s)
{
    switch (s) {
    case Q_OK:            return "OK";
    case Q_INDETERMINATE: return "INDETERMINATE";
    default:              return "ERROR";
    }
}

/* ---------- ③ 降级阶梯：查不到时退到哪一级 ---------- */

/* 目标：拿一个「安全的文件名长度上限」。三级退让：
 *   一级  sysconf(_SC_NAME_MAX)? 不存在 —— NAME_MAX 是路径相关的，只能 pathconf
 *   二级  pathconf(path, _PC_NAME_MAX)
 *   三级  编译期 NAME_MAX（<limits.h>，本机 255）—— 但它也可能没定义
 *   四级  _POSIX_NAME_MAX（保证下限，永远有）—— 但可能小到没法用（14）
 */
static long name_max_ladder(const char *path, const char **how)
{
    if (path) {
        errno = 0;
        long v = pathconf(path, _PC_NAME_MAX);
        if (v != -1) { *how = "pathconf(_PC_NAME_MAX)"; return v; }
    }
#ifdef NAME_MAX
    *how = "<limits.h> NAME_MAX";
    return NAME_MAX;
#else
    *how = "_POSIX_NAME_MAX（保证下限）";
    return _POSIX_NAME_MAX;
#endif
}

int main(void)
{
    sweep();

    printf("\n### ② 安全封装的三种结果\n");
    static const struct { int name; const char *lbl; } T[] = {
        { _SC_OPEN_MAX, "_SC_OPEN_MAX" },
        { _SC_TZNAME_MAX, "_SC_TZNAME_MAX" },
        { 9999, "9999（非法 name）" },
    };
    for (size_t i = 0; i < sizeof(T) / sizeof(T[0]); i++) {
        enum qstat st;
        long v = query_sysconf(T[i].name, &st);
        printf("  %-22s -> status=%-14s value=%ld\n", T[i].lbl, qname(st), v);
    }

    printf("\n### ③ 降级阶梯：要一个文件名长度上限\n");
    const char *how = "?";
    long nm = name_max_ladder("/tmp", &how);
    printf("  pathconf(\"/tmp\") 成功 -> %ld  （来源：%s）\n", nm, how);
    how = "?";
    nm = name_max_ladder("/no/such/dir", &how);
    printf("  pathconf(\"/no/such/dir\") 失败 -> %ld （来源：%s）\n", nm, how);
    printf("  阶梯的含义：能用运行时查询就用；查不到就退到编译期宏；宏也没有就退到\n");
    printf("  POSIX 保证下限（本机 _POSIX_NAME_MAX=%d），并按这个值把缓冲区放大一点。\n",
           _POSIX_NAME_MAX);

    printf("\n### ④ 两个容易踩的「假 indeterminate」\n");
    errno = 0;
    long x = pathconf("/", _PC_MAX_CANON);
    printf("  pathconf(\"/\", _PC_MAX_CANON) = %ld, errno=%d  —— 问的不是终端，语义上无意义\n",
           x, errno);
    errno = 0;
    long y = pathconf("/", _PC_VDISABLE);
    printf("  pathconf(\"/\", _PC_VDISABLE)  = %ld, errno=%d  —— glibc 直接返回 _POSIX_VDISABLE，\n",
           y, errno);
    printf("     连「这是不是终端」都不检查（sysdeps/posix/pathconf.c:115-119）。\n");
    printf("  这两类「看起来有值、其实没意义」的结果，比 -1 更危险。\n");
    return 0;
}

  _PC_SYNC_IO            = -1  (indeterminate)
  _PC_PRIO_IO            = -1  (indeterminate)
  （_PC_ASYNC_IO/_PC_SYNC_IO/_PC_PRIO_IO 在 glibc 里只在「问了普通文件」时才有答案，
    问目录一律返回 -1。见 sysdeps/posix/pathconf.c:128-148 的 S_ISREG 判断。）

### ② 安全封装的三种结果
  _SC_OPEN_MAX           -> status=OK             value=100
  _SC_TZNAME_MAX         -> status=INDETERMINATE  value=-1
  9999（非法 name）  -> status=ERROR          value=-1

### ③ 降级阶梯：要一个文件名长度上限
  pathconf("/tmp") 成功 -> 255  （来源：pathconf(_PC_NAME_MAX)）
  pathconf("/no/such/dir") 失败 -> 255 （来源：<limits.h> NAME_MAX）
  阶梯的含义：能用运行时查询就用；查不到就退到编译期宏；宏也没有就退到
  POSIX 保证下限（本机 _POSIX_NAME_MAX=14），并按这个值把缓冲区放大一点。

### ④ 两个容易踩的「假 indeterminate」
  pathconf("/", _PC_MAX_CANON) = 255, errno=0  —— 问的不是终端，语义上无意义
  pathconf("/", _PC_VDISABLE)  = 0, errno=0  —— glibc 直接返回 _POSIX_VDISABLE，
     连「这是不是终端」都不检查（sysdeps/posix/pathconf.c:115-119）。
  这两类「看起来有值、其实没意义」的结果，比 -1 更危险。

逐段看：

段 观察 说明
① sysconf 侧只有 4 项：_SC_TZNAME_MAX / _SC_SYMLOOP_MAX / _SC_MQ_OPEN_MAX / _SC_SEM_NSEMS_MAX 其余 14 项限制类都能给出数（见 11.2 ②）
① pathconf("/") 侧 3 项 _PC_ASYNC_IO / _PC_SYNC_IO / _PC_PRIO_IO 它们不是真的 indeterminate，而是「问目录没意义」：glibc 对这三个做了 S_ISREG \|\| S_ISBLK 判断（sysdeps/posix/pathconf.c:128-148），不满足就 return -1 且不设 errno——与真 indeterminate 同形
② 三种状态被 enum qstat 明确分开 关键设计：值（long）与状态（enum）分开返回，不再靠 -1 兼当哨兵
② _SC_OPEN_MAX → OK 100、_SC_TZNAME_MAX → INDETERMINATE -1、9999 → ERROR -1 后两者返回值一模一样，只有状态不同。这就是为什么必须封装
③ pathconf("/tmp") → 255（来源 pathconf）；pathconf("/no/such/dir") → 255（来源 <limits.h> NAME_MAX） 同一条降级函数，两条不同来源——调用者拿到的 255 是从哪来的，被显式写回 how
④ pathconf("/", _PC_MAX_CANON) = 255, errno=0；_PC_VDISABLE = 0, errno=0 glibc 不检查「是不是终端」：_PC_MAX_CANON → return MAX_CANON;（255）、_PC_VDISABLE → return _POSIX_VDISABLE;（0）。man-pages 明写这两项「path must refer to a terminal」，但实现不验

2.1 为什么 _SC_TZNAME_MAX 恒为 -1

glibc 的实现就是一行（sysdeps/posix/sysconf.c:102-103）：

    case _SC_TZNAME_MAX:
      return -1;

没有 #ifdef、没有读文件、没有 __set_errno。 它和 default: 分支（:64-66，会设 EINVAL）的区别就是不碰 errno——这正是「indeterminate」的实现方式。

对比 _SC_NGROUPS_MAX（:85-90）用的是另一套手法：

    case _SC_NGROUPS_MAX:
#ifdef  NGROUPS_MAX
      return NGROUPS_MAX;
#else
      return -1;
#endif

3. 查不到时的降级阶梯

TLPI 在 §11.4 给的建议是「用特别的手段（ad hoc techniques）决定一个程序可以依赖的限制」。整理成四级：

级别 手段 优点 缺点 本仓库的例子
1 pathconf(path, _PC_NAME_MAX) 最准，随文件系统 可能 -1；要能访问那个目录 name_max_ladder("/tmp", …) → 255
2 <limits.h> 的 NAME_MAX 无系统调用 glibc 可能 #undef 掉（OPEN_MAX/ARG_MAX/LINK_MAX 就是这样） 回退到 255
3 _POSIX_NAME_MAX 永远有（只要有 <unistd.h>） 只是保底值，可能小到不可用（14） 回退到 14

static long name_max_ladder(const char *path, const char **how)
{
    if (path) {
        errno = 0;
        long v = pathconf(path, _PC_NAME_MAX);
        if (v != -1) { *how = "pathconf(_PC_NAME_MAX)"; return v; }
    }
#ifdef NAME_MAX
    *how = "<limits.h> NAME_MAX";
    return NAME_MAX;
#else
    *how = "_POSIX_NAME_MAX（保证下限）";
    return _POSIX_NAME_MAX;
#endif
}

第 2 级的 #ifdef 是必须的：glibc 的 bits/local_lim.h 在 #include <linux/limits.h> 之后会主动 #undef NR_OPEN / LINK_MAX / OPEN_MAX / ARG_MAX，注释里解释了理由——「the limit can be changed at runtime and therefore the macro must not be defined」。所以同一个体系里，有的宏在、有的宏不在。

4. 常见坑

坑 说明
把 -1 当「不支持」/「没有限制」 三种情况共用 -1：indeterminate、选项不支持、真错误。一律要先 errno = 0 再判
不封装，直接 if (v == -1) use_default; 会把 EINVAL（name 写错，真 bug）也静默降级掉。真错误必须崩
忘了 errno = 0 只清一次 见 11.2 ⑥：会把 indeterminate 误报成错误
只判 ENOENT / 只看返回值 pathconf 侧还有 ENOTDIR(20)、EBADF(9)、EACCES、ELOOP、ENAMETOOLONG（11.3 C 段实测）
拿 _PC_MAX_CANON / _PC_VDISABLE 问目录 glibc 不检查终端就返回值（④ 段）。「有值」不等于「有意义」
用 _POSIX_NAME_MAX(14) 当实际缓冲 那是保底值；按它分配会白白截断合法文件名
假定「本机的 indeterminate 清单」跨平台不变 本机 4 项，别的 libc/内核可能更多或更少。清单要实测，不能背

代码自测（Q&A）

Q1：什么叫 indeterminate？它和「不支持」有什么区别？ A：「不支持」是选项没有实现（11.5），「indeterminate」是限制存在但实现不告诉你确切值。二者在返回值上都是 -1，且都不改动 errno——完全同形。区别只在于你问的 name 属于限制类还是选项类。

Q2：本机哪些 _SC_* 是 indeterminate？ A：4 项：_SC_TZNAME_MAX、_SC_SYMLOOP_MAX、_SC_MQ_OPEN_MAX、_SC_SEM_NSEMS_MAX。其中 _SC_TZNAME_MAX 在 glibc 里就是一行 case _SC_TZNAME_MAX: return -1;（sysdeps/posix/sysconf.c:102-103），连 errno 都不碰。

Q3：为什么说 _PC_ASYNC_IO 在目录上的 -1 不是「真 indeterminate」？ A：因为 glibc 是主动拒绝回答：sysdeps/posix/pathconf.c:128-141 里 _PC_ASYNC_IO 先 stat，然后 if (!S_ISREG(st.st_mode) && !S_ISBLK(st.st_mode)) return -1;。对目录不满足条件 → 返回 -1 不设 errno。语义上是「问错了对象」，形式上却与 indeterminate 一致。换成普通文件 fd 就得到 1（11.3 B 段实测）。

Q4：安全封装为什么要把「状态」和「值」分开返回？ A：因为 -1 是合法值也是错误标志，一个 long 放不下两种信息。c11_4_indeterminate.c 用 enum qstat { Q_OK, Q_INDETERMINATE, Q_ERROR } 作输出参数，调用点写 if (st == Q_OK) use(v); else fallback();——真错误（Q_ERROR）必须崩，不能静默降级，否则 sysconf(9999) 这种拼错常量的 bug 会一直藏下去。

Q5：查不到 _PC_NAME_MAX 时，退到 NAME_MAX 还是 _POSIX_NAME_MAX？ A：先 NAME_MAX（本机 255），它可能不存在（glibc 会 #undef 一部分限制宏），所以外面要套 #ifdef；再退 _POSIX_NAME_MAX（永远有，但只有 14）。实测两条路径：pathconf("/tmp") 成功给 255；pathconf("/no/such/dir") 失败后退到 NAME_MAX 也是 255——同值不同源，所以 demo 里把来源字符串一起返回。

Q6：④ 段那两个「假 indeterminate」危险在哪？ A：pathconf("/", _PC_MAX_CANON) = 255、pathconf("/", _PC_VDISABLE) = 0，两个都 errno=0，看起来完全正常。但 man-pages 明写这两项「fd or path must refer to a terminal」——glibc 不检查（sysdeps/posix/pathconf.c:51-55 / :115-119 直接 return MAX_CANON; / return _POSIX_VDISABLE;）。「返回了值」被误当成「问了一个有效的对象」，这类错误比 -1 难查得多。判终端要用 isatty()。

Q7：为什么「本机 indeterminate 清单」不能背下来用？ A：它是实现选择，不是标准规定。标准只说「允许 indeterminate」，没说哪些必须 indeterminate。本机 glibc 2.39 是 4 + 3 项，换 musl / 换嵌入式 libc / 换个内核版本都可能不同。所以清单只能在目标环境上实测（① 段那段 sweep 代码就是要抄到自检里去的）。

System Options 系统选项

本章：TLPI 第 11 章 — System Limits and Options 源码核验：glibc 2.39（sysdeps/unix/sysv/linux/bits/posix_opt.h、posix/bits/posix1_lim.h、posix/confstr.c、sysdeps/unix/sysv/linux/x86/sysconf.c）+ man-pages 6.19 sysconf(3) / posixoptions(7) + CE 实测（gcc 13.3.0 / x86-64 / Ubuntu 24.04） - 上一节：11.4 Indeterminate Limits 不确定的限制 - 下一节：11.6 Summary 本章总结

本节讲什么

前一节讲的是限制（答案是数）；本节讲选项（答案是「有没有」）。选项的坑在于 <unistd.h> 里的 _POSIX_FOO 宏有四种状态，而且编译期说「说不清」的时候，只有运行时能给你答案。四个问题：

  1. _POSIX_FOO 的四态分别怎么读？为什么「未定义」不等于「不支持」？
  2. 编译期 _POSIX_MONOTONIC_CLOCK = 0 而运行时 sysconf(_SC_MONOTONIC_CLOCK) = 200809，该信谁？
  3. confstr() 查的是什么？它和 sysconf 的失败信号有什么不同？
  4. 三态判断在 C 代码里怎么写才不会编译不过？

1. _POSIX_FOO 的四态（man-pages 原文）

man-pages 6.19 sysconf(3) 的 DESCRIPTION 段逐字：

For options, typically, there is a constant _POSIX_FOO that may be defined in <unistd.h>. If it is undefined, one should ask at run time. If it is defined to -1, then the option is not supported. If it is defined to 0, then relevant functions and headers exist, but one has to ask at run time what degree of support is available. If it is defined to a value other than -1 or 0, then the option is supported. Usually the value (such as 200112L) indicates the year and month of the POSIX revision describing the option. glibc uses the value 1 to indicate support as long as the POSIX revision has not been published yet. The sysconf() argument will be _SC_FOO. For a list of options, see posixoptions(7).

状态 含义 该怎么办
未定义 编译期不知道 必须运行时 sysconf(_SC_FOO)
-1 明确不支持 可以用，但没有保证；准备回退路径
0 头文件/函数在，但支持到什么程度说不清 必须运行时问
其他正值 支持，值通常是 POSIX 修订版年月（如 200809L） 可以直接用

只有「其他正值」是编译期就能定的。其余三态都要落到运行时。

2. 自编：三态 + 运行时对照 + confstr

完整源码 code/c11_5_options.c：

/* c11_5_options.c — Ch11 §11.5：系统选项（System Options）的三态与两条查法
 *
 * 限制是「一个数」，选项是「支持 / 不支持」。POSIX 给选项设计了三态：
 *   _POSIX_FOO 未定义      -> 编译期不知道，必须运行时问 sysconf(_SC_FOO)
 *   _POSIX_FOO == -1       -> 明确不支持
 *   _POSIX_FOO == 0        -> 头文件/函数都在，但支持到什么程度要运行时问
 *   _POSIX_FOO == 其他正值 -> 支持，通常就是描述它的 POSIX 修订版年月（如 200809L）
 *
 * 本程序把这三态用宏判断打出来，再和运行时的 sysconf(_SC_*) 对齐，最后加一段
 * confstr() —— 它查的是**字符串**选项（路径、版本号），是 sysconf 的字面兄弟。
 *
 * 编译： gcc -O0 -Wall -Wextra -o c11_5_options c11_5_options.c
 * 取材： sysconf(3) DESCRIPTION 段（man-pages 6.19）逐字：
 *         "For options, typically, there is a constant _POSIX_FOO that may be
 *          defined in <unistd.h>.  If it is undefined, one should ask at run
 *          time.  If it is defined to -1, then the option is not supported.
 *          If it is defined to 0, then relevant functions and headers exist,
 *          but one has to ask at run time what degree of support is available."
 *       glibc 2.39 sysdeps/unix/sysv/linux/bits/posix_opt.h:23/26/32/103/106/128/131/146/152/155/164/182-183/186/192
 *       glibc 2.39 posix/confstr.c:43（_CS_PATH）/ :252（_CS_GNU_LIBC_VERSION）
 *                                 / :257（_CS_GNU_LIBPTHREAD_VERSION）；无值时 :265/:277 return 0
 */
#define _GNU_SOURCE
#include <errno.h>
#include <limits.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <unistd.h>

static void sc(const char *lbl, int name)
{
    errno = 0;
    long v = sysconf(name);
    const char *note = "";
    if (v == -1)
        note = (errno == 0) ? "  <- 不支持（或该 name 属限制类且 indeterminate）" : "  <- 真错误";
    printf("  %-28s = %-10ld%s\n", lbl, v, note);
}

int main(void)
{
    printf("### ① 编译期：_POSIX_* 的三态（本机 glibc 2.39）\n");

    printf("  -- 支持（值为 POSIX 修订年月）--\n");
    printf("  _POSIX_JOB_CONTROL=%ld _POSIX_SAVED_IDS=%ld _POSIX_THREADS=%ld\n",
           (long)_POSIX_JOB_CONTROL, (long)_POSIX_SAVED_IDS, (long)_POSIX_THREADS);
    printf("  _POSIX_REALTIME_SIGNALS=%ld _POSIX_TIMERS=%ld _POSIX_SEMAPHORES=%ld\n",
           (long)_POSIX_REALTIME_SIGNALS, (long)_POSIX_TIMERS, (long)_POSIX_SEMAPHORES);
    printf("  _POSIX_PRIORITY_SCHEDULING=%ld _POSIX_BARRIERS=%ld _POSIX_SPIN_LOCKS=%ld\n",
           (long)_POSIX_PRIORITY_SCHEDULING, (long)_POSIX_BARRIERS, (long)_POSIX_SPIN_LOCKS);

    printf("\n  -- 定义为 0（头文件在，但程度要说运行时）--\n");
    printf("  _POSIX_MONOTONIC_CLOCK=%ld  _POSIX_CPUTIME=%ld  _POSIX_THREAD_CPUTIME=%ld\n",
           (long)_POSIX_MONOTONIC_CLOCK, (long)_POSIX_CPUTIME, (long)_POSIX_THREAD_CPUTIME);

    printf("\n  -- 定义为 -1（明确不支持）--\n");
    printf("  _POSIX_SPORADIC_SERVER=%ld  _POSIX_THREAD_SPORADIC_SERVER=%ld\n",
           (long)_POSIX_SPORADIC_SERVER, (long)_POSIX_THREAD_SPORADIC_SERVER);
    printf("  _POSIX_TRACE=%ld  _POSIX_TRACE_EVENT_FILTER=%ld  _POSIX_TYPED_MEMORY_OBJECTS=%ld\n",
           (long)_POSIX_TRACE, (long)_POSIX_TRACE_EVENT_FILTER, (long)_POSIX_TYPED_MEMORY_OBJECTS);

    printf("\n### ② 运行时：同一批选项用 sysconf(_SC_*) 再问一遍\n");
    sc("_SC_JOB_CONTROL", _SC_JOB_CONTROL);
    sc("_SC_SAVED_IDS", _SC_SAVED_IDS);
    sc("_SC_THREADS", _SC_THREADS);
    sc("_SC_REALTIME_SIGNALS", _SC_REALTIME_SIGNALS);
    sc("_SC_TIMERS", _SC_TIMERS);
    sc("_SC_SEMAPHORES", _SC_SEMAPHORES);
    sc("_SC_MONOTONIC_CLOCK", _SC_MONOTONIC_CLOCK);
    sc("_SC_CPUTIME", _SC_CPUTIME);
    sc("_SC_THREAD_CPUTIME", _SC_THREAD_CPUTIME);
    sc("_SC_2_C_DEV", _SC_2_C_DEV);
    sc("_SC_2_FORT_DEV", _SC_2_FORT_DEV);
    sc("_SC_2_LOCALEDEF", _SC_2_LOCALEDEF);
    sc("_SC_XOPEN_VERSION", _SC_XOPEN_VERSION);

    printf("\n  对照要点：_POSIX_MONOTONIC_CLOCK=0（编译期「说不清」），而\n");
    printf("  sysconf(_SC_MONOTONIC_CLOCK) 给出 200809 —— 编译期含糊的，运行时才有答案。\n");

    printf("\n### ③ confstr()：查「字符串」选项（sysconf 的字面兄弟）\n");
    struct { int name; const char *lbl; } cs[] = {
        { _CS_PATH, "_CS_PATH" },
        { _CS_GNU_LIBC_VERSION, "_CS_GNU_LIBC_VERSION" },
        { _CS_GNU_LIBPTHREAD_VERSION, "_CS_GNU_LIBPTHREAD_VERSION" },
    };
    for (size_t i = 0; i < sizeof(cs) / sizeof(cs[0]); i++) {
        errno = 0;
        size_t need = confstr(cs[i].name, NULL, 0);      /* 先问需要多大 */
        if (need == 0) {
            printf("  %-28s 无值（errno=%d）\n", cs[i].lbl, errno);
            continue;
        }
        char *buf = malloc(need);
        size_t got = confstr(cs[i].name, buf, need);
        printf("  %-28s 需要 %2zu B，写入 %2zu B: \"%s\"\n", cs[i].lbl, need, got, buf);
        free(buf);
    }
    printf("  注意：与 sysconf 一样，confstr 没有值的时候返回 0（不是 -1），\n");
    printf("        且**不保证**设置 errno —— 用 (confstr(n,NULL,0)) 判空即可。\n");

    printf("\n### ④ 三态判断在代码里怎么写才不会踩坑\n");
    printf("  错的：int have = _POSIX_BARRIERS;        // 宏没定义时编不过\n");
    printf("  对的：#ifdef _POSIX_BARRIERS              // 先判有没有\n");
    printf("            #if _POSIX_BARRIERS > 0 ...      // 再判支不支持\n");
    printf("            #else ... runtime ...            // ==0 要问运行时\n");
    printf("            #endif\n");
    printf("        #else  ... runtime ...               // 未定义也要问运行时\n");
    printf("        #endif\n");
    printf("  本机实测：_POSIX_BARRIERS=%ld（正值），sysconf 也给 %ld，两边一致。\n",
           (long)_POSIX_BARRIERS, sysconf(_SC_BARRIERS));
    return 0;
}

    case _SC_THREAD_CPUTIME:

_POSIX_VERSION 本机 = 200809L → 就是实测的 200809。「编译期 0」+「运行时 200809」不是矛盾，是分工。

代码自测（Q&A）

Q1：_POSIX_FOO 有几种状态？分别怎么读？ A：四种。① 未定义 → 编译期不知道，运行时问；② -1 → 明确不支持；③ 0 → 头文件/函数在，但支持程度运行时问；④ 其他正值 → 支持，值通常是 POSIX 修订版年月（200809L）。只有第 ④ 种是编译期可定的。

Q2：_POSIX_MONOTONIC_CLOCK = 0 但 sysconf(_SC_MONOTONIC_CLOCK) = 200809，信哪个？ A：信运行时。0 的含义是「相关函数和头文件存在，但支持到什么程度要问运行时」（man-pages 原文）。glibc 觉得单调时钟的可用性依赖 CPU/内核，编译期不下结论；sysconf 那条分支（sysdeps/unix/sysv/linux/sysconf.c:51-54）直接 return _POSIX_VERSION，本机是 200809。

Q3：为什么 _POSIX_JOB_CONTROL 是 1 而不是 200809L？ A：man-pages 解释了：「glibc uses the value 1 to indicate support as long as the POSIX revision has not been published yet.」_POSIX_JOB_CONTROL / _POSIX_SAVED_IDS 在 posix_opt.h:23 / :26 就是 1。所以不要对 _POSIX_* 的值做算术，只能判「>0 / ==0 / ==-1」。

Q4：confstr 和 sysconf 的失败信号有什么不同？ A：sysconf 失败返回 -1（且要配 errno 判真错误）；confstr 在「该 name 无值」时返回 0，并且不保证设置 errno。另外 confstr 的返回值含结尾 \0：实测 _CS_PATH 返回 14（"/bin:/usr/bin" 是 13 个字符）。

Q5：confstr 的正确调用姿势是什么？ A：先用 confstr(name, NULL, 0) 问需要多大，再 malloc(need) + confstr(name, buf, need)。demo 的 ③ 段就是这么写的。注意 size_t 参数与返回值都别和 int 混。

Q6：为什么 #ifdef 不能省？ A：因为未定义的宏不是 0。写 int have = _POSIX_BARRIERS; 在未定义时是编译错误；写 #if _POSIX_BARRIERS 在未定义时被当作 0（等于把「不知道」误当成「不支持」）。正确姿势是 #ifdef 先确定「有没有这个宏」，再 #if > 0 判支持程度。

Q7：_SC_2_FORT_DEV 返回 -1，这和 _SC_TZNAME_MAX 的 -1 一样吗？ A：返回值与 errno 一模一样（都是 -1 + errno 不变），但语义不同：前者是「选项不支持」，后者是「限制 indeterminate」。参见 11.2 ⑤b/⑤c 的现场。这也是本节为什么把「选项」和「限制」分成两章讲。

Q8：_SC_XOPEN_VERSION = 700 说明什么？ A：本机符合 X/Open Portability Guide 第 7 版（XPG7）。这里暴露一个事实：选项返回值不都是年月（700 是版本号）。要判断具体能力还是得查 posixoptions(7) 的对照表。

「反直觉」清单

  1. sysconf(_SC_OPEN_MAX) 会变 —— 它不是上限，是 RLIMIT_NOFILE.rlim_cur 的快照；man-pages 说「进程生命期内不变」这句对限制类不成立。
  2. 「限制 indeterminate」和「选项不支持」不可区分 —— 都是 -1 且 errno 不变。只能靠「你知道自己在问哪一类」。
  3. errno != 0 不代表这次调用失败 —— _SC_NPROCESSORS_ONLN 值正确、errno 却是 ENOENT；pathconf("/lib", _PC_LINK_MAX) 值正确、errno 却是 ENOENT。只在返回 -1 时看 errno。
  4. pathconf 大多数项不查文件系统 —— _PC_PATH_MAX / _PC_PIPE_BUF 在 glibc 里就是 return 一个宏。
  5. _PC_NAME_MAX 能不是 255 —— squashfs 报 256（来自超级块的 f_namemax）。
  6. pathconf 不检查「是不是终端」 —— _PC_MAX_CANON 对目录也返回 255、_PC_VDISABLE 返回 0。「有值」≠「有意义」。
  7. pathconf("") 是 ENOENT 而不是 EINVAL —— glibc 专门加了空串前置判断。
  8. confstr 失败返回 0 而不是 -1 —— 而且不保证设 errno。
  9. _POSIX_MONOTONIC_CLOCK = 0 但运行时 200809 —— 0 不是「不支持」，是「编译期不下结论」。
  10. getconf 在容器里可能不存在 —— CE 沙箱里没有 /usr/bin/getconf，交叉验证得自己写程序。
  11. glibc 主动 #undef 了部分限制宏 —— OPEN_MAX / ARG_MAX / LINK_MAX / NR_OPEN 用之前必须 #ifdef，否则编译不过。
  12. _POSIX_CLK_TCK 根本不存在 —— POSIX 只说 CLK_TCK 这符号已废弃删除，不承诺任何下限。

本章自测（Q&A）

Q1：一句话概括本章的核心技能。 A：分清三个 -1：errno != 0 是真错误；errno == 0 可能是「限制 indeterminate」也可能是「选项不支持」（不可区分）；而返回值不是 -1 时 errno 无意义。剩下的一切（三类限制、四个查询入口、四态选项宏）都是围绕这件事展开的。

Q3：如果要写一个「生产可用」的限制查询库，必备哪几件事？ A：① 每个查询都 errno = 0 前置清零、只在 -1 时读 errno；② 状态与值分开返回（enum + long）；③ 真错误直接暴露（不静默降级）；④ indeterminate 走显式降级阶梯并把「来源」一起返回；⑤ 对会因为 #undef 而不存在的宏套 #ifdef；⑥ 对会漂移的项（_SC_CHILD_MAX 等）不做跨进程缓存。

Q4：本章哪些实测数字是「一次运行有效」，哪些是「环境常量」？ A：稳定：_SC_ARG_MAX(2097152)、_SC_OPEN_MAX(100)、_SC_PAGESIZE(4096)、_SC_CLK_TCK(100)、_SC_VERSION(200809)、各 _POSIX_* 下限、pathconf 的 LINK_MAX/FILESIZEBITS/NAME_MAX。会漂移：_SC_CHILD_MAX、_SC_SIGQUEUE_MAX、_SC_PHYS_PAGES、_SC_AVPHYS_PAGES、_SC_MINSIGSTKSZ、_SC_SIGSTKSZ、ex11_2 的挂载点计数。引用前者的数字可以直接抄，引用后者必须注明是哪一次运行。

Q5：为什么本章要专门写一节的「沙箱环境限制表」？ A：因为本章所有结论都依赖「跑在什么环境里」。CE 容器把 RLIMIT_NOFILE 设成 100（不是常见的 1024/1048576），没有 getconf、没有 /dev/shm，/tmp 是 tmpfs——这些前提不写清，读者会以为「_SC_OPEN_MAX 就是 100」或「pathconf 问 /tmp 一定成功」。

 *   子挂载点，路径名里还带不同的哈希（每次运行都不一样），全打出来既长又不
 *   可复现。去重后只剩三行，正好是三份答案。

#define _GNU_SOURCE
#include <errno.h>
#include <limits.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <sys/statfs.h>
#include <sys/statvfs.h>
#include <unistd.h>

#define MAXK 64

struct key { long nm, lk, fb; char ftype[24]; unsigned long ftype_hex; int hits; };

static struct key keys[MAXK];
static int nkeys;

static void note(long nm, long lk, long fb, const char *ftype, unsigned long hex)
{
    for (int i = 0; i < nkeys; i++)
        if (keys[i].nm == nm && keys[i].lk == lk && keys[i].fb == fb) {
            keys[i].hits++;
            return;
        }
    if (nkeys >= MAXK) return;
    keys[nkeys].nm = nm; keys[nkeys].lk = lk; keys[nkeys].fb = fb;
    keys[nkeys].ftype_hex = hex; keys[nkeys].hits = 1;
    snprintf(keys[nkeys].ftype, sizeof keys[0].ftype, "%s", ftype);
    nkeys++;
}

int main(void)
{
    FILE *f = fopen("/proc/mounts", "r");
    if (!f) { perror("/proc/mounts"); return 1; }

    printf("=== ① 遍历 /proc/mounts，问同一组 _PC_* ===\n");
    long nm = pathconf("/", _PC_NAME_MAX);
    long lk = pathconf("/", _PC_LINK_MAX);
    long fb = pathconf("/", _PC_FILESIZEBITS);
    printf("  先在 / 上取一组基线: NAME_MAX=%ld LINK_MAX=%ld FILESIZEBITS=%ld\n", nm, lk, fb);

    char dev[128], mnt[128], type[32];
    int scanned = 0;
    while (fscanf(f, "%127s %127s %31s %*s %*s %*s", dev, mnt, type) == 3) {
        struct statfs sf;
        if (statfs(mnt, &sf) != 0)
            continue;
        errno = 0;
        long a = pathconf(mnt, _PC_NAME_MAX);
        if (a == -1) continue;
        long b = pathconf(mnt, _PC_LINK_MAX);
        long c = pathconf(mnt, _PC_FILESIZEBITS);
        scanned++;
        note(a, b, c, type, (unsigned long)sf.f_type);
    }
    fclose(f);

    printf("\n=== ② 去重后的答案（扫了 %d 个挂载点，共 %d 种结果）===\n", scanned, nkeys);
    printf("  %-9s %-10s %-15s %-12s %s\n", "NAME_MAX", "LINK_MAX", "FILESIZEBITS",
           "f_type", "代表文件系统");
    for (int i = 0; i < nkeys; i++)
        printf("  %-9ld %-10ld %-15ld 0x%-9lx %s（%d 个挂载点）\n",
               keys[i].nm, keys[i].lk, keys[i].fb, keys[i].ftype_hex,
               keys[i].ftype, keys[i].hits);

    printf("\n=== ③ 为什么会有不同答案 ===\n");
    printf("  _PC_LINK_MAX      -> glibc 按 statfs().f_type 查表：\n");
    printf("                       ext4 -> EXT4_LINK_MAX 65000；其余多数 -> LINUX_LINK_MAX 127\n");
    printf("                       （linux_fsinfo.h:256 / :268；ext4 还要特判，见 pathconf.c:63-128）\n");
    printf("  _PC_FILESIZEBITS  -> 同样查表：ext4 64；tmpfs/proc/squashfs 走 default 32\n");
    printf("  _PC_NAME_MAX      -> statvfs().f_namemax，由**超级块**报上来，所以能不是 255\n");
    printf("                       （本机 squashfs 就报了 256）\n");
    printf("  _PC_PATH_MAX      -> 这几行里它**没有任何变化**：glibc 直接 return PATH_MAX(%d)，\n",
           PATH_MAX);
    printf("                       与文件系统无关。\n");
    printf("  _PC_PIPE_BUF      -> 同理，直接 return PIPE_BUF(%d)。\n", PIPE_BUF);

    printf("\n=== ④ 与 Listing 11-2 原始行为对照 ===\n");
    printf("  原书 Listing 11-2 对 STDIN_FILENO 问三项，本机结果：\n");
    errno = 0;
    printf("    _PC_NAME_MAX = %ld\n", fpathconf(STDIN_FILENO, _PC_NAME_MAX));
    printf("    _PC_PATH_MAX = %ld\n", fpathconf(STDIN_FILENO, _PC_PATH_MAX));
    printf("    _PC_PIPE_BUF = %ld\n", fpathconf(STDIN_FILENO, _PC_PIPE_BUF));
    printf("  —— 与在 / 上问的结果完全一样。原因是这三项在 glibc 里都不看 fd 指向的类型\n");
    printf("     （_PC_NAME_MAX 走 statvfs，管道/终端 fd 也能 statvfs 成功并报 255）。\n");
    printf("  所以「换文件系统」这个实验真正会变的只有 LINK_MAX / FILESIZEBITS / NAME_MAX。\n");
    return 0;
}

观察 说明
扫了 60 个挂载点，去重后只剩 3 种 (NAME_MAX, LINK_MAX, FILESIZEBITS) 组合 绝大多数挂载点共享同样的三元组，去重才看得清结论
tmpfs（31 个）：255 / 127 / 32 /、/tmp、/dev、/etc/passwd、/etc/shadow 等都是 tmpfs（f_type=0x1021994）。LINK_MAX 走 default → LINUX_LINK_MAX 127
ext4（10 个）：255 / 65000 / 64 /lib、/usr/lib、/lib64、/app、/usr/local/bin/dumb-init 等。EXT4_LINK_MAX 65000（linux_fsinfo.h:256）、FILESIZEBITS 64
squashfs（19 个）：256 / 127 / 32 /cefs/** 下的只读镜像。NAME_MAX 是 256，不是 255 —— 这一格是本题最有价值的一行
_PC_NAME_MAX = 256 意味着什么 char name[256] 恰好装不下「256 个字符 + 结尾 \0」。文件名长度上限来自超级块上报的 f_namemax，不是内核 uapi 里写死的 NAME_MAX 255
④ 段三项与 / 上完全一样 因为 glibc 对 _PC_NAME_MAX（走 statvfs）、_PC_PATH_MAX（return PATH_MAX）、_PC_PIPE_BUF（return PIPE_BUF）都不看 fd 指向的类型
所以「换文件系统」真正会变的只有三项 LINK_MAX / FILESIZEBITS（按 f_type 查表）与 NAME_MAX（f_namemax）

代码自测（Q&A）

Q1：习题 11-1 要求「在别的 UNIX 上跑」，拿不到第二个 UNIX 怎么办？ A：把问题改成「别的 UNIX 上允许差多少」。POSIX 对每个限制只给「不低于」的下限（_POSIX_*），所以只要列出「本机实测值 + 该下限」，就能算出合法区间。ex11_1_sysconf_wide.c 的 ②/③ 段就是这张表：_SC_ARG_MAX 合法区间 >= 4096、_SC_NGROUPS_MAX >= 8、_SC_OPEN_MAX >= 20……本机全在区间的上端。

Q2：_SC_ARG_MAX 的「合法最小值 4096」和「本机 2097152」差 512 倍，代码该怎么写？ A：运行时查、运行时定缓冲，或按「下限 + 动态扩容」写。绝对不能拿 2097152 当常量（别的机器可能是 4096），也不能拿 4096 当预算（本机会浪费 511/512 的空间）。

Q3：习题 11-2 里 _PC_NAME_MAX 在 squashfs 上是 256，这有什么实际影响？ A：pathconf(dir, _PC_NAME_MAX) 返回的是名字本身的最大字符数，不含结尾 \0。所以缓冲要按「返回值 + 1」分配。char name[256] 在这个文件系统上能装的名字比合法上限少一个字符，而且在 NAME_MAX 语义下最容易被忽略——因为多数文件系统报 255，正好装下。

Q4：既然一台机器上就挂着多种文件系统，为什么 Listing 11-2 只问 STDIN_FILENO？ A：原书那个程序是最小示例，目的是演示 fpathconf() 的用法（用 fd 而不是路径）。但它也会误导：实测 ④ 段说明这三项在 glibc 里根本不看 fd 类型，所以 Listing 11-2 的输出在任何文件系统上都一样——它演示不了「换文件系统会不一样」。习题 11-2 的价值就在这里：要真正看到差异，必须用 pathconf(路径, …) 并换路径。

Q5：_PC_FILESIZEBITS = 32（tmpfs）和 64（ext4）差别意味着什么？ A：这是「文件大小需要用多少位表示」——32 位意味着该文件系统上单文件最大 4 GiB 级别的寻址。tmpfs 报 32 不代表真的只能用 32 位偏移（本机 off_t 是 64 位、_PC_FILESIZEBITS 由 f_type 查表），但跨文件系统拷贝大文件时这是要看的项（Ch5 大文件 LFS）。

Q6：为什么两个解答都要去重/克制输出？ A：因为「结论的稳定性」比「输出的完整性」重要。CE 容器里 /cefs 下有几十个路径带构建哈希的 squashfs 挂载点（每次运行路径都不同），全量打印会让结论无法核对。ex11_2_fs_sweep.c 按值三元组去重后只剩 3 行，每行都代表「一个可解释的答案」；同时把「有多少个挂载点共享这个答案」也打出来（31 / 10 / 19）——这既保留了信息量，又不引入不可复现的噪声。
