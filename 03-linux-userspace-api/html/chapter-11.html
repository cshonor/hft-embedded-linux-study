章节目标

解决可移植性：不要写死 MAX_PATH 之类；掌握 SUSv3 限制与 POSIX 可选特性；会用 sysconf / pathconf / fpathconf；分清三类限制与「错误 vs 不确定」；为文件、管道、IPC 写健壮代码。

章 关联

Ch12 /proc、硬件信息 — 限制信息的另一来源

管道 / FIFO _PC_PIPE_BUF 原子写边界
Ch36 RLIMIT_NOFILE ↔ _SC_OPEN_MAX

练习

  1. 封装安全 sysconf：区分错误 / indeterminate；批量打印常用限制
  2. 对不同目录 pathconf(_PC_NAME_MAX)（如 / vs /tmp）
  3. 静态 PATH_MAX vs 动态扩容
  4. getconf 与程序结果交叉验证

背诵卡

# 要点
1 三类限制：恒定 / 路径相关 / 可增
2 全局 → sysconf；文件系统 → fpathconf 优先
3 -1：先清 errno，再分错误 vs indeterminate
4 _SC_* / _PC_* 命名
5 _SC_CLK_TCK ≠ HZ；PIPE_BUF 跟文件系统走
6 编译期宏不够，运行时再查

#include <stdio.h>
#include <unistd.h>

    printf("_SC_OPEN_MAX (max fd per process): %ld\n", sysconf(_SC_OPEN_MAX));
    printf("_SC_CLK_TCK (clock ticks/sec):     %ld\n", sysconf(_SC_CLK_TCK));
    printf("_SC_PAGESIZE:                      %ld\n", sysconf(_SC_PAGESIZE));

    /* 编译期常量 */

    printf("LONG_MAX = %ld\n", LONG_MAX);

11.1

基础概念

本章：TLPI 第 11 章 — System Limits and Options - 上一节：本章首页 - 下一节：11.2 三大查询 API

本节讲什么

❌ #define MAX_PATH 256 — 各系统、各文件系统不一致 ✅ 运行时查询上限 SUSv3：每个限制有最低强制下限，在 <limits.h>，前缀 _POSIX_

要点

概念 含义
Limits 资源 / 路径 / 进程能力上限
Options 标准可选特性（系统可实现或不实现）

❌ #define MAX_PATH 256 — 各系统、各文件系统不一致
✅ 运行时查询上限

SUSv3：每个限制有最低强制下限，在 <limits.h>，前缀 _POSIX_
例：_POSIX_ARG_MAX = 4096 → 所有 POSIX 系统至少这么多，实际往往更大。

三类限制（核心）

类 特征 查询 例
1. 运行时恒定 进程生命期内不变；<limits.h> 可能未定义 sysconf _SC_OPEN_MAX、_SC_PAGESIZE
2. 路径名相关 依赖文件系统 / 挂载点 pathconf / fpathconf NAME_MAX、PATH_MAX、PIPE_BUF
3. 运行时可增 保证 ≥ 下限，运行中可上调 多为 sysconf + 资源限制 与 Ch36 rlimit 相关

HFT / 嵌入式关联

路线 要点
嵌入式 裁剪内核/容器里限制会变，别硬编码 MAX_PATH=256；用 sysconf/pathconf 运行时查询，POSIX 只保证 POSIX 最低下限
HFT 热路径缓冲大小（路径、fd 数）依赖系统限制，启动时 sysconf 查一次并缓存，避免运行时反复系统调用；误设上限会导致丢数据或浪费内存

代码示例

#include <unistd.h>
#include <stdio.h>

int main(void) {
    /* sysconf: 查询运行时限制 */
    long clk = sysconf(_SC_CLK_TCK);
    long max_fd = sysconf(_SC_OPEN_MAX);
    long child_max = sysconf(_SC_CHILD_MAX);

    printf("clock ticks/sec = %ld\n", clk);
    printf("max open files  = %ld\n", max_fd);
    printf("max child procs = %ld\n", child_max);

    /* pathconf: 查询文件/路径相关限制 */
    long name_max = pathconf("/", _PC_NAME_MAX);
    long path_max = pathconf("/", _PC_PATH_MAX);
    printf("max filename    = %ld\n", name_max);
    printf("max path length = %ld\n", path_max);
    return 0;
}

11.2

三大查询 API

本章：TLPI 第 11 章 — System Limits and Options - 上一节：11.1 基础概念 - 下一节：11.3 编译期：<limits.h> / <unistd.h>

本节讲什么

include long sysconf(int name); / 系统级，不依赖路径 / long pathconf(const char pathname, int name); / 按路径 */

要点

#include <unistd.h>

long sysconf(int name);                         /* 系统级，不依赖路径 */
long pathconf(const char *pathname, int name);  /* 按路径 */
long fpathconf(int fd, int name);               /* 按 fd，优先 */

返回值陷阱（必记）

返回 -1 有两种含义：

条件 含义
errno != 0 真正出错（如 EINVAL：name 非法）
errno == 0 限制 indeterminate（不确定），不是错误 
errno = 0;
long v = sysconf(name);
if (v == -1) {
    if (errno == 0)
        /* indeterminate */;
    else
        /* error */;
}

常量命名

API 前缀 例
sysconf _SC_* _SC_ARG_MAX、_SC_OPEN_MAX、_SC_PAGESIZE、_SC_CLK_TCK
pathconf/fpathconf _PC_* _PC_NAME_MAX、_PC_PATH_MAX、_PC_PIPE_BUF

Shell：getconf（封装同类查询）

getconf ARG_MAX
getconf NAME_MAX /home

Demo：code/print_limits.c

HFT / 嵌入式关联

路线 要点
嵌入式 返回 -1 分两种情况（errno!=0 真错 / errno==0 indeterminate），先 errno=0 再调；fpathconf(fd) 比 pathconf(path) 优先避免 TOCTOU
HFT 查询限制是低频操作，用 fpathconf(fd) 对已打开 fd 查询更安全高效；启动时一次性缓存结果，热路径不重复查

代码示例

#include <stdio.h>
#include <unistd.h>
#include <limits.h>
/* sysconf/pathconf/confstr 运行时查询系统限制 */
int main(void) {
    printf("_SC_OPEN_MAX = %ld\n", sysconf(_SC_OPEN_MAX));
    printf("_SC_CLK_TCK = %ld\n", sysconf(_SC_CLK_TCK));
    printf("_SC_ARG_MAX = %ld\n", sysconf(_SC_ARG_MAX));
    printf("_PC_PATH_MAX(/tmp) = %ld\n", pathconf("/tmp", _PC_PATH_MAX));

    char buf[256];
    confstr(_CS_GNU_LIBC_VERSION, buf, sizeof(buf));
    printf("glibc version: %s\n", buf);
    return 0;
}

11.3

编译期：`<limits.h>` / `<unistd.h>`

本章：TLPI 第 11 章 — System Limits and Options - 上一节：11.2 三大查询 API - 下一节：11.4 常用限制速览

本节讲什么

要点

头文件 内容
<limits.h> _POSIX_*_MAX 标准最低下限；部分系统还有实现定义的 NAME_MAX 等
<unistd.h> 特性宏：_POSIX_THREADS、_POSIX_REALTIME_SIGNALS 等

宏只代表编译期声明；裁剪内核 / 容器可能关掉功能 → 可靠做法仍是 sysconf 运行时校验。

HFT / 嵌入式关联

路线 要点
嵌入式 宏只代表编译期声明，裁剪内核/容器可能关掉功能；可靠做法仍 sysconf 运行时校验； 的特性宏（_POSIX_THREADS 等）同理
HFT 编译期宏是最低保证值、实际更大；配置缓冲按运行时 sysconf 结果分配，避免按 POSIX 下限分配过小导致截断

代码示例

#include <unistd.h>
#include <stdio.h>

int main(void) {
    /* <unistd.h> 中的 _POSIX_* 编译时常量 */
    printf("_POSIX_OPEN_MAX  = %d\n", _POSIX_OPEN_MAX);
    printf("_POSIX_CHILD_MAX = %d\n", _POSIX_CHILD_MAX);
    printf("_POSIX_PATH_MAX  = %d\n", _POSIX_PATH_MAX);
    printf("_POSIX_NAME_MAX  = %d\n", _POSIX_NAME_MAX);

    /* 编译时常量是最小保证值, 运行时实际可能更大 */
    long actual = sysconf(_SC_OPEN_MAX);
    printf("\n运行时实际 max fd = %ld (>= %d)\n", actual, _POSIX_OPEN_MAX);
    return 0;
}

11.4

常用限制速览

本章：TLPI 第 11 章 — System Limits and Options - 上一节：11.3 编译期：<limits.h> / <unistd.h> - 下一节：11.5 Indeterminate：工程策略

本节讲什么

要点

sysconf(_SC_*)

常量 含义
_SC_ARG_MAX exec 参数 + 环境变量总字节上限
_SC_OPEN_MAX 进程最大打开 fd 数（Linux 上常对应软限制，见 Ch36）
_SC_PAGESIZE / _SC_PAGE_SIZE 页大小
_SC_CLK_TCK times() 时钟节拍（≠ 内核 HZ）
_SC_NGROUPS_MAX 补充组最大个数
_SC_LOGIN_NAME_MAX 登录名最大长度
_SC_THREADS 等 运行时选项检测（是否支持某特性）

pathconf / fpathconf(_PC_*)

常量 含义
_PC_NAME_MAX 单组件文件名最大长度
_PC_PATH_MAX 相对路径最大长度（注意：绝对路径缓冲不能想当然）
_PC_PIPE_BUF 管道原子写最大字节
_PC_NO_TRUNC 文件名超长是否报错（非截断）

HFT / 嵌入式关联

路线 要点
嵌入式 _SC_OPEN_MAX（最大 fd）与 _PC_PIPE_BUF（管道原子写）是嵌入式 IPC 关键；_SC_CLK_TCK 是 times() 换算秒的依据，≠内核 HZ
HFT _PC_PIPE_BUF 决定管道原子写上限，跨进程日志/信号管道按它设计避免写撕裂；_SC_OPEN_MAX 影响 fd 复用与连接上限，需配合 rlimit 抬高

代码示例

#include <unistd.h>
#include <stdio.h>

int main(void) {
    /* sysconf 查询各种系统限制 */
    struct { int constant; const char *name; } items[] = {
        { _SC_ARG_MAX,       "ARG_MAX" },
        { _SC_OPEN_MAX,      "OPEN_MAX" },
        { _SC_CHILD_MAX,     "CHILD_MAX" },
        { _SC_STREAM_MAX,    "STREAM_MAX" },
        { _SC_NGROUPS_MAX,   "NGROUPS_MAX" },
        { _SC_CLK_TCK,       "CLK_TCK" },
    };

    for (int i = 0; i < 6; i++) {
        long val = sysconf(items[i].constant);
        printf("%-15s = %ld%s\n", items[i].name, val,
               val == -1 ? " (无限制/不确定)" : "");
    }
    return 0;
}

11.5

Indeterminate：工程策略

本章：TLPI 第 11 章 — System Limits and Options - 上一节：11.4 常用限制速览 - 下一节：11.6 选项检测（Feature Options）

本节讲什么

当 -1 且 errno==0： 1. 用 _POSIX_* 最小值保守分配 2. 启发式固定缓冲（如 4096）— 权宜

要点

当 -1 且 errno==0：

  1. 用 _POSIX_* 最小值保守分配
  2. 启发式固定缓冲（如 4096）— 权宜
  3. 动态扩容（推荐：路径解析、readline 一类）

典型坑：PATH_MAX 在部分系统未定义；静态大数组仍可能不够或浪费。

HFT / 嵌入式关联

路线 要点
嵌入式 PATH_MAX 部分系统未定义，静态大数组可能不够或浪费；indeterminate 时用 POSIX 最小值保守分配或动态扩容（路径解析、readline 类）
HFT 热路径缓冲 indeterminate 时用动态扩容而非静态大数组，避免浪费内存与二次拷贝；固定缓冲只在性能敏感的已知上限场景使用

代码示例

#include <unistd.h>
#include <stdio.h>
#include <limits.h>

int main(void) {
    /* 某些限制"不确定" → sysconf 返回 -1 且 errno 不设 */
    errno = 0;
    long val = sysconf(_SC_RE_DUP_MAX);
    if (val == -1) {
        if (errno == 0) {
            printf("RE_DUP_MAX: 不确定 (无限制)\n");
        } else {
            perror("sysconf");
        }
    } else {
        printf("RE_DUP_MAX = %ld\n", val);
    }

    /* 管道缓冲区大小: fpathconf */
    int pipefd[2];
    pipe(pipefd);
    long pipe_buf = fpathconf(pipefd[0], _PC_PIPE_BUF);
    printf("PIPE_BUF = %ld\n", pipe_buf);
    close(pipefd[0]);
    close(pipefd[1]);
    return 0;
}

11.6

选项检测（Feature Options）

本章：TLPI 第 11 章 — System Limits and Options - 上一节：11.5 Indeterminate：工程策略 - 下一节：11.7 高频易错

本节讲什么

两者不一致时以运行时为准。 ---

要点

时机 方式
编译期 <unistd.h> 的 _POSIX_*
运行期 sysconf(_SC_*)（如 _SC_THREADS）

两者不一致时以运行时为准。

HFT / 嵌入式关联

路线 要点
嵌入式 特性宏 ≠ 运行时一定可用，容器/裁剪内核要再查；两者不一致以运行时 sysconf 为准（如 _SC_THREADS）
HFT 交易程序依赖某特性（实时信号、POSIX 定时器等）时，启动时 sysconf 检测并以运行时为准，避免编译期宏误判导致运行期崩溃

代码示例

#include <unistd.h>
#include <stdio.h>

int main(void) {
    /* 检查系统是否支持某特性 (_SC_*_C89 / _SC_*_200112) */
    struct { int constant; const char *name; } opts[] = {
        { _SC_FSYNC,           "FSYNC" },
        { _SC_MAPPED_FILES,    "MAPPED_FILES" },
        { _SC_MEMORY_PROTECTION, "MEMORY_PROTECTION" },
        { _SC_THREADS,         "THREADS" },
        { _SC_TIMERS,          "TIMERS" },
        { _SC_ASYNCHRONOUS_IO, "ASYNC_IO" },
    };

    for (int i = 0; i < 6; i++) {
        long val = sysconf(opts[i].constant);
        printf("%-25s = %s\n", opts[i].name,
               val > 0 ? "支持" : "不支持");
    }

    /* 编译时用 #if _POSIX_* 检查, 运行时用 sysconf */
    return 0;
}

高频易错

本章：TLPI 第 11 章 — System Limits and Options - 上一节：11.6 选项检测（Feature Options） - 下一节：下一章+1:02d}-*/notes.md)

本节讲什么

  1. _SC_CLK_TCK ≠ 内核 HZ；times() 换算秒必须用它；别和 clock() 混用。 2. PATH_MAX 语义是相对路径一类上限；拼绝对路径勿直接当万能缓冲。 3. PIPE_BUF 随文件系统变 → 用 fpathconf(fd, _PC_PIPE_BUF)。

要点

  1. _SC_CLK_TCK ≠ 内核 HZ；times() 换算秒必须用它；别和 clock() 混用。
  2. PATH_MAX 语义是相对路径一类上限；拼绝对路径勿直接当万能缓冲。
  3. PIPE_BUF 随文件系统变 → 用 fpathconf(fd, _PC_PIPE_BUF)。
  4. 先 errno=0 再调；勿见 -1 就当错误。
  5. Linux：sysconf(_SC_OPEN_MAX) 常反映软限制，可用 getrlimit/setrlimit（Ch36）。
  6. 特性宏 ≠ 运行时一定可用 → 容器 / 裁剪内核要再查。

HFT / 嵌入式关联

路线 要点
嵌入式 _SC_CLK_TCK≠内核 HZ，times() 换算秒必须用它；PIPE_BUF 随文件系统变用 fpathconf；先 errno=0 再调，勿见 -1 当错误
HFT sysconf(_SC_OPEN_MAX) 常反映软限制，配合 setrlimit 抬高才能加大 fd 上限；特性宏≠运行时可用，容器环境要再查避免误判

代码示例

#include <unistd.h>
#include <stdio.h>

/* 系统限制查询三板斧:
 * 1. <limits.h> / <unistd.h> 编译时常量 (_POSIX_*)
 * 2. sysconf() / pathconf() 运行时查询
 * 3. 返回 -1 且 errno==0 → 不确定 (无限制)
 */
int main(void) {
    printf("=== 系统限制速查 ===\n");
    printf("OPEN_MAX  = %ld\n", sysconf(_SC_OPEN_MAX));
    printf("ARG_MAX   = %ld\n", sysconf(_SC_ARG_MAX));
    printf("CHILD_MAX = %ld\n", sysconf(_SC_CHILD_MAX));
    printf("CLK_TCK   = %ld\n", sysconf(_SC_CLK_TCK));

    printf("\n文件相关:\n");
    printf("NAME_MAX  = %ld (路径 /)\n", pathconf("/", _PC_NAME_MAX));
    printf("PATH_MAX  = %ld (路径 /)\n", pathconf("/", _PC_PATH_MAX));
    printf("PIPE_BUF  = %ld (路径 /)\n", pathconf("/", _PC_PIPE_BUF));
    return 0;
}
