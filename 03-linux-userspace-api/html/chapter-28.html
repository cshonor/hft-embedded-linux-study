章节目标

深挖 COW 与继承清单；多线程 fork / pthread_atfork；vfork/clone；exec 资源细则与 fork/exec 信号对比表；O_CLOEXEC；规范 fork+exec。

28.9 易错清单

  1. fork：掩码继承、pending 清；exec：handler→DFL、掩码保留
  2. 多线程 fork → 立刻 exec
  3. 勿用 vfork
  4. CLOEXEC 只对 exec
  5. exec 成功不返回；失败 _exit
  6. clone 是 fork/线程共同底座

实验清单

  1. COW：改全局变量互不影响（见 Ch24 fork_basic）
  2. （选）多线程 fork 风险
  3. CLOEXEC（Ch27）
  4. fork+exec 重定向模板
  5. fork/exec 信号状态对比（本目录 demo）

背诵卡

# 要点
1 fork 掩码✓ pending✗；exec 掩码✓ handler→DFL
2 多线程 fork 只留一线程 → 立刻 exec
3 vfork 共享地址空间，新代码禁用
4 fork/线程 ⊂ clone(flags)
5 CLOEXEC：fork 不关、exec 关
6 子失败 _exit，防 atexit 双跑

代码示例

#include <stdio.h>
#include <unistd.h>
#include <sys/wait.h>
#include <fcntl.h>
#include <string.h>

/* Ch28 进程创建与执行细节 — fork+exec 实现简易 shell。
 * 演示 fd 在 fork/exec 间的继承 + FD_CLOEXEC。
 * 编译: gcc -o ch28_demo ch28_demo.c */

int run_command(char **args) {
    pid_t pid = fork();
    if (pid < 0) return -1;
    if (pid == 0) {
        execvp(args[0], args);
        perror("execvp");
        _exit(127);
    }
    int status;
    waitpid(pid, &status, 0);
    return WIFEXITED(status) ? WEXITSTATUS(status) : -1;
}

int main(void) {
    /* 演示 fd 继承: 打开一个文件描述符 */
    int fd = open("/tmp/ch28_test.txt", O_WRONLY | O_CREAT | O_TRUNC, 0644);
    write(fd, "written by parent before fork\n", 30);

    /* 子进程继承 fd */
    pid_t pid = fork();
    if (pid == 0) {
        /* fd 在子进程中仍然有效 */
        write(fd, "written by child after fork\n", 28);

        /* 设置 FD_CLOEXEC: exec 后自动关闭 */
        int flags = fcntl(fd, F_GETFD);
        fcntl(fd, F_SETFD, flags | FD_CLOEXEC);

        char *args[] = {"ls", "-l", "/proc/self/fd", NULL};
        printf("Child fd before exec:\n");
        run_command(args);

        /* exec 后 fd 应该被关闭（但这里已经 exec 了不会执行） */
        _exit(0);
    }
    waitpid(pid, NULL, 0);
    write(fd, "written by parent after child exit\n", 35);
    close(fd);

    /* 简易 shell 循环 */
    printf("\nMini shell demo:\n");
    char *cmd1[] = {"echo", "hello", NULL};
    char *cmd2[] = {"pwd", NULL};
    char *cmd3[] = {"ls", "/tmp", NULL};
    run_command(cmd1);
    run_command(cmd2);
    run_command(cmd3);
    return 0;
}

28.1

fork 再深入

本章：TLPI 第 28 章 — Process Creation and Program Execution in More Detail - 上一节：本章首页 - 下一节：28.2 多线程 + fork

本节讲什么

fork 复制页表、页标只读；写时缺页再拷贝物理页。现代 Linux fork 开销低；逻辑上地址空间仍独立。 Demo：code/fork_signal_state.c ---

要点

COW

fork 复制页表、页标只读；写时缺页再拷贝物理页。现代 Linux fork 开销低；逻辑上地址空间仍独立。

继承 vs 不继承（精要）

✅ 继承 ❌ 不继承
地址空间（COW）、fd 表（共享 struct file/偏移） 新 PID/PPID
信号 handler、信号 掩码 pending 清空
凭证、cwd、umask、rlimit、PGID/SID… 其它线程（只留调用线程）
文件锁、部分定时器/AIO/inotify 等

掩码继承；pending 清空。

Demo：code/fork_signal_state.c

HFT / 嵌入式关联

路线 要点
嵌入式 fork 复制页表标只读，写时缺页再拷贝，省 RAM
HFT COW 使 fork 开销低；继承/不继承清单是 fork 子进程环境控制的依据

代码示例

#include <unistd.h>
#include <sys/wait.h>
#include <stdio.h>
/* fork 内核细节:
 * - 分配新 task_struct, 新 PID
 * - 复制父进程的 mm_struct (COW)
 * - 复制 fd 表 (共享打开文件描述)
 * - 复制信号处理器和掩码
 */
int main(void) {
    pid_t pid = fork();
    if (pid == 0) { printf("子: PID=%d\n", getpid()); _exit(0); }
    wait(NULL);
    printf("父: PID=%d\n", getpid());
    return 0;
}

28.2

多线程 + fork

本章：TLPI 第 28 章 — Process Creation and Program Execution in More Detail - 上一节：28.1 fork 再深入 - 下一节：28.3 vfork

本节讲什么

POSIX：子进程只保留发起 fork 的线程；其它线程不跑清理 → 锁/堆状态危险。 ---

要点

POSIX：子进程只保留发起 fork 的线程；其它线程不跑清理 → 锁/堆状态危险。

方案
最优 fork 后立刻 exec
缓解 pthread_atfork(prepare, parent, child) 统一加解锁
避免 fork 后子进程继续跑复杂多线程逻辑

HFT / 嵌入式关联

路线 要点
嵌入式 子进程只留发起 fork 的线程，锁/堆状态危险
HFT 多线程进程 fork 后立即 exec；pthread_atfork 只缓解，热路径慎 fork

代码示例

#include <unistd.h>
#include <stdio.h>
int main(void) {
    /* fork 后父子执行顺序不确定!
     * 不要依赖执行顺序, 用同步机制 (wait/pipe/signal) */
    pid_t pid = fork();
    if (pid == 0) { printf("子进程\n"); _exit(0); }
    /* 不保证子先还是父先执行 */
    wait(NULL);
    printf("父进程\n");
    return 0;
}

28.3

`vfork`

本章：TLPI 第 28 章 — Process Creation and Program Execution in More Detail - 上一节：28.2 多线程 + fork - 下一节：28.4 clone（Linux）

本节讲什么

共享地址空间；父阻塞至子 _exit/exec；子勿乱改内存。新代码用 fork+COW，禁用 vfork。 ---

要点

共享地址空间；父阻塞至子 _exit/exec；子勿乱改内存。新代码用 fork+COW，禁用 vfork。

HFT / 嵌入式关联

路线 要点
嵌入式 vfork 共享地址空间父阻塞，子勿改内存
HFT vfork+exec 省页表复制，但已被 fork+COW 取代，新代码禁用

代码示例

#include <unistd.h>
#include <stdio.h>
/* vfork:
 * - 子进程借用父进程地址空间 (不 COW)
 * - 父进程阻塞直到子进程 _exit/exec
 * - 子进程不能 return, 不能修改变量
 * - 现代: 用 posix_spawn 或 fork+exec 替代
 */
int main(void) {
    pid_t pid = vfork();
    if (pid == 0) {
        char *args[] = {"echo", "vfork+exec", NULL};
        execvp("echo", args);
        _exit(1);  /* 必须 _exit */
    }
    wait(NULL);
    return 0;
}

28.4

`clone`（Linux）

本章：TLPI 第 28 章 — Process Creation and Program Execution in More Detail - 上一节：28.3 vfork - 下一节：28.5 exec 资源细则（承 Ch27）

本节讲什么

fork / pthread_create 均基于 clone 标志组合： fork ≈ 不共享上述、并带 SIGCHLD 的 clone 特例。 ---

要点

fork / pthread_create 均基于 clone 标志组合：

标志例 含义
CLONE_VM 共享地址空间（线程）
CLONE_FILES 共享 fd 表
CLONE_SIGHAND 共享信号处置

fork ≈ 不共享上述、并带 SIGCHLD 的 clone 特例。

HFT / 嵌入式关联

路线 要点
嵌入式 clone 标志控制共享粒度（VM/files/sighand）
HFT clone 是 fork/pthread_create 底层，理解共享粒度是隔离/共享决策基础

代码示例

#include <sched.h>
#include <unistd.h>
#include <sys/wait.h>
#include <stdio.h>
/* clone: Linux 特有, 比 fork 更灵活
 * 可控制: 共享地址空间/fd表/信号处理器/...
 * 线程本质就是 clone(CLONE_VM | CLONE_FILES | ...)
 */
static int child_fn(void *arg) {
    printf("clone 子: PID=%d\n", getpid());
    return 0;
}
int main(void) {
    char stack[65536];
    int flags = CLONE_VM | SIGCHLD;  /* 共享地址空间 */
    pid_t pid = clone(child_fn, stack + sizeof(stack), flags, NULL);
    if (pid < 0) { perror("clone"); return 1; }
    waitpid(pid, NULL, 0);
    printf("clone 完成 (共享 VM = 线程)\n");
    return 0;
}

28.5

exec 资源细则（承 Ch27）

本章：TLPI 第 28 章 — Process Creation and Program Execution in More Detail - 上一节：28.4 clone（Linux） - 下一节：28.6 FD_CLOEXEC / O_CLOEXEC

本节讲什么

要点

✅ 保留 ❌ 销毁/重置
PID/PGID/SID、cwd、umask 整块用户地址空间
信号掩码 handler → SIG_DFL
未 CLOEXEC 的 fd pending 清空、atexit 丢弃
rlimit… 其它线程、多数锁/定时器/AIO…

超级对比表

操作 信号掩码 handler pending
fork 继承 继承 清空
exec 继承 → SIG_DFL 清空

HFT / 嵌入式关联

路线 要点
嵌入式 exec 保留信号掩码/cwd/fd，重置 handler→SIG_DFL
HFT exec 后 handler 重置、掩码保留，worker 需按需重装 handler

代码示例

#include <unistd.h>
#include <stdio.h>
/* exec 内核细节:
 * 1. 检查文件格式 (ELF? shebang?)
 * 2. 分配新地址空间, 丢弃旧的
 * 3. 加载代码/数据段
 * 4. PID 不变, fd 默认保留 (除 FD_CLOEXEC)
 * 5. 信号处理器重置 (忽略/默认保留, 自定义的改为默认)
 */
int main(void) {
    pid_t pid = fork();
    if (pid == 0) {
        char *args[] = {"ps", NULL};
        execvp("ps", args);
        _exit(1);
    }
    wait(NULL);
    printf("exec: PID 不变, 映像替换\n");
    return 0;
}

28.6

`FD_CLOEXEC` / `O_CLOEXEC`

本章：TLPI 第 28 章 — Process Creation and Program Execution in More Detail - 上一节：28.5 exec 资源细则（承 Ch27） - 下一节：28.7 fork + exec 规范

本节讲什么

打开即 O_CLOEXEC，避免 fork 与 exec 之间的竞态。见 Ch27 cloexec demo。 ---

要点

fork exec
CLOEXEC fd 不关（标记可复制） 关掉

打开即 O_CLOEXEC，避免 fork 与 exec 之间的竞态。见 Ch27 cloexec demo。

HFT / 嵌入式关联

路线 要点
嵌入式 O_CLOEXEC 原子设置，避免 fork/exec 间竞态
HFT O_CLOEXEC 是防 fd 泄漏到 worker 的最佳实践（原子无竞态）

代码示例

#include <fcntl.h>
#include <unistd.h>
#include <stdio.h>
int main(void) {
    /* 对比: open(O_CLOEXEC) vs fcntl(FD_CLOEXEC) */
    /* O_CLOEXEC: 原子操作, 无竞态 */
    int fd1 = open("/tmp/a.txt", O_CREAT | O_CLOEXEC, 0644);

    /* fcntl: open + fcntl 之间有竞态 (多线程 exec) */
    int fd2 = open("/tmp/b.txt", O_CREAT, 0644);
    fcntl(fd2, F_SETFD, FD_CLOEXEC);  /* 有间隙! */

    printf("O_CLOEXEC (原子) > open+fcntl (有竞态)\n");
    close(fd1); close(fd2);
    return 0;
}
