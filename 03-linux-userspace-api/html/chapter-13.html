导读

章节目标

厘清两层缓冲与延迟写；掌握 fsync/fdatasync/O_SYNC；会控 stdio 缓冲与 fflush；严禁无保护地混用 stdio 与原生 read/write；了解 posix_fadvise / O_DIRECT。

13.7 速查：持久化相关标志/调用

机制 作用范围 等不等落盘 备注
write → 页缓存 否 成功 ≠ 落盘
fsync 一文件数据+元数据 是 最稳、最贵
fdatasync 优先数据 是 常够用
sync 全局 不定 业务禁用狂调
O_SYNC 每次 write≈fsync 是 极慢
O_DSYNC 每次 write≈fdatasync 是
O_DIRECT 绕过页缓存 否 仍要 fsync 才谈持久化
fflush 仅 stdio 用户缓冲 否 不刷磁盘

13.8 易错清单

  1. write 成功 ≠ 落盘
  2. 只要数据、不要改大小/mtime → 优先 fdatasync
  3. stdout→文件/管道：全缓冲，无 \n/fflush 看不见输出
  4. O_SYNC 管的是 write，管不住未 fflush 的 stdio
  5. O_DIRECT 对齐失败 → EINVAL；用 posix_memalign
  6. 崩溃丢：用户态 stdio + 内核脏页；已刷盘的安全

练习

  1. 终端 vs 重定向：stdout 行缓冲/全缓冲 + fflush
  2. 小循环多次 write vs 加大缓冲/批写
  3. 复现 printf+write 乱序，用 fflush 修
  4. O_DIRECT 故意不对齐 → EINVAL
  5. （选）posix_fadvise 顺序读提示

背诵卡

# 要点
1 两层：内核页缓存 + stdio 用户缓冲
2 write ≠ 落盘；要持久化用 fsync/fdatasync
3 混用 stdio 与 read/write 前必须 fflush
4 重定向后 stdout 常变全缓冲
5 O_DIRECT 绕缓存≠持久化；要对齐
6 fdatasync 通常够；sync() 勿滥用

代码示例

#include <stdio.h>
#include <unistd.h>
#include <fcntl.h>
#include <string.h>

/* Ch13 文件 I/O 缓冲 — stdio 缓冲 vs 内核缓冲 vs 无缓冲。
 * 演示 setvbuf 控制用户态缓冲 + O_DIRECT 绕过内核缓冲。
 * 编译: gcc -o ch13_demo ch13_demo.c */

int main(void) {
    /* 行缓冲: 遇到 \n 才 flush */
    char line_buf[1024];
    setvbuf(stdout, line_buf, _IOLBF, sizeof(line_buf));

    printf("This is line-buffered");  /* 无 \n，暂不输出 */
    fflush(stdout);                    /* 手动 flush */
    printf(" - now flushed\n");

    /* 全缓冲 vs 无缓冲对比 */
    FILE *fp = fopen("/tmp/ch13_test.txt", "w");
    setvbuf(fp, NULL, _IOFBF, 8192);  /* 全缓冲 8KB */
    fprintf(fp, "fully buffered\n");
    fclose(fp);  /* close 时 flush */

    /* 内核缓冲: write() 先进内核 page cache，不保证落盘 */
    int fd = open("/tmp/ch13_test2.txt", O_WRONLY | O_CREAT | O_TRUNC, 0644);
    write(fd, "kernel buffered\n", 16);
    fsync(fd);   /* 强制刷盘，绕过内核缓冲延迟 */
    close(fd);

    printf("stdio buffer -> kernel buffer -> disk (fsync)\n");
    return 0;
}

13.1

内核缓冲（Buffer / Page Cache）

本章：TLPI 第 13 章 — File I/O Buffering - 上一节：本章首页 - 下一节：13.2 stdio 用户态缓冲（FILE*）

本节讲什么

read() / write() 不直接对磁盘做同步块传输，而是在用户缓冲 ↔ 内核页缓存之间拷贝。 后台 flusher 周期性刷脏页；参数见 /proc/sys/vm/dirty_*。 #include

要点

read() / write() 不直接对磁盘做同步块传输，而是在用户缓冲 ↔ 内核页缓存之间拷贝。

延迟写（Delayed Write）
write() 成功返回 ≠ 已落盘；数据多在脏页里
好处 合并小写、少寻道、吞吐高
风险 崩溃/断电 → 脏页丢失

后台 flusher 周期性刷脏页；参数见 /proc/sys/vm/dirty_*。

强制落盘

#include <unistd.h>
void sync(void);          /* 全局刷脏；标准允许不等待完成；业务勿狂调 */
int fsync(int fd);        /* 该文件：数据 + 元数据；等到设备完成 */
int fdatasync(int fd);    /* 优先刷数据；元数据按需；通常比 fsync 轻 */

open 同步标志

标志 近似语义
O_SYNC 每次 write ≈ fsync（数据+元数据）
O_DSYNC 每次 write ≈ fdatasync

同步 IO 极慢；事务/关键日志按需用。
若前面还有 stdio，必须先 fflush 再依赖 O_SYNC/write。

HFT / 嵌入式关联

路线 要点
嵌入式 write() 只把数据写进 page cache 脏页，返回≠落盘；掉电/崩溃会丢失未 fsync 的数据，嵌入式掉电保护须对关键数据 fdatasync
HFT 交易日志/订单 write() 返回只是进了脏页，落盘前崩溃=丢单；关键路径显式 fsync/fdatasync 保证持久性，代价是同步写延迟

代码示例

#include <stdio.h>
#include <fcntl.h>
#include <unistd.h>
#include <string.h>
/* 三层缓冲: stdio buffer -> kernel page cache -> disk */
int main(void) {
    /* stdio buffer: 用户态, setvbuf 控制 */
    FILE *fp = fopen("/tmp/buffer_test.txt", "w");
    setvbuf(fp, NULL, _IOFBF, 4096);  /* 全缓冲 4KB */
    fprintf(fp, "in stdio buffer (not on disk yet)\n");
    /* fflush: stdio -> kernel page cache */
    fflush(fp);
    fclose(fp);

    /* kernel page cache: write() 先进 cache */
    int fd = open("/tmp/buffer_test.txt", O_WRONLY | O_APPEND);
    write(fd, "in page cache\n", 14);
    /* fsync: page cache -> disk */
    fsync(fd);
    close(fd);

    printf("Data path: stdio buffer -> page cache -> disk\n");
    return 0;
}

13.2

stdio 用户态缓冲（`FILE*`）

本章：TLPI 第 13 章 — File I/O Buffering - 上一节：13.1 内核缓冲（Buffer / Page Cache） - 下一节：13.3 【致命】混用 FILE* 与 read/write(fd)

本节讲什么

printf / fwrite / fgets 先打用户缓冲；满或刷新时才 read/write。 int setvbuf(FILE stream, char buf, int mode, size_t size); int fflush(FILE stream); / NULL = 刷新所有输出流 */

要点

printf / fwrite / fgets 先打用户缓冲；满或刷新时才 read/write。

setvbuf 三种模式

int setvbuf(FILE *stream, char *buf, int mode, size_t size);
mode 行为 典型默认
_IOFBF 全缓冲：满才刷 普通磁盘文件
_IOLBF 行缓冲：\n 或满 终端上的 stdout
_IONBF 无缓冲 stderr

刷新

int fflush(FILE *stream);   /* NULL = 刷新所有输出流 */

自动刷新：fclose、正常退出。

不要依赖 fflush 丢弃输入缓冲（未标准化）。

重定向坑： stdout 接到管道/文件时，常从行缓冲变成全缓冲 → 无 \n/fflush 时日志「卡住」。

Demo：code/stdio_buffering.c

fileno() — FILE* 与 fd 的桥梁

#include <stdio.h>
int   fileno(FILE *stream);              /* FILE* → int fd（向下拆箱） */
FILE *fdopen(int fd, const char *mode);  /* int fd → FILE*（向上装箱） */
fileno(fp) fdopen(fd, mode)
方向 FILE* → fd fd → FILE*
缓冲 不改变现有缓冲 新建一个用户缓冲区
所有权 fclose(fp) 会关闭 fd fclose(fp) 会关闭 fd
典型用途 对 stdio 流调系统调用 给 open() 的 fd 加缓冲

三个标准流：fileno(stdin)→0、fileno(stdout)→1、fileno(stderr)→2。

系统调用只认 fd，不认 FILE*——需要 fileno 的场景：

场景 代码
强制落盘 fsync(fileno(fp))
设非阻塞 fcntl(fileno(fp), F_SETFL, O_NONBLOCK)
内存映射 mmap(NULL, len, PROT_READ, MAP_SHARED, fileno(fp), 0)
判断终端 isatty(fileno(stdout))
取文件属性 fstat(fileno(fp), &sb)

混用规则：fprintf 走用户缓冲，write(fileno(fp)) 直接进内核，两者各走各的。混用前必须 fflush(fp) 同步，否则数据顺序错乱（详见 13.3 节）。

FILE *fp = fopen("log.txt", "w");
fprintf(fp, "AAA");            /* 还在用户 buf */
fflush(fp);                    /* 刷干净 */
write(fileno(fp), "BBB", 3);  /* 现在顺序正确 */

POSIX.1-2008 要求 fileno() 不加锁（只读 FILE 结构的 _fileno 字段），线程安全；但拿到 fd 后的操作不一定线程安全。

HFT / 嵌入式关联

路线 要点
嵌入式 stdio 缓冲策略随输出目标变（终端行缓冲/文件全缓冲），日志重定向到文件后行缓冲变全缓冲，嵌入式可能"看不到实时日志"
HFT 热路径日志走 printf 会卡在用户态缓冲延迟输出；追求低延迟直接 write() 绕开 stdio，或 setvbuf 关缓冲

代码示例

#include <stdio.h>
#include <unistd.h>

int main(void) {
    /* stdio 缓冲 vs 内核缓冲 */
    FILE *fp = fopen("/tmp/bufdemo.txt", "w");

    /* 行缓冲: 遇到 \n 才 flush */
    fprintf(fp, "这行在缓冲区");
    fprintf(fp, "还没写入\n");  /* \n 触发 flush (行缓冲模式) */

    /* 手动 flush */
    fprintf(fp, "手动flush前");
    fflush(fp);  /* 强制写入内核 */

    /* setvbuf 设置缓冲模式 */
    setvbuf(fp, NULL, _IOFBF, 8192);  /* 全缓冲, 8KB */
    fprintf(fp, "全缓冲模式\n");

    fclose(fp);  /* fclose 自动 flush */

    /* 对比: write() 无用户缓冲, 直接进内核 */
    int fd = fileno(fp);
    write(fd, "直接写fd\n", 10);
    return 0;
}

13.3

Controlling Kernel Buffering of File I/O

本章：TLPI 第 13 章

本节讲什么

控制内核页缓存的刷写行为。

API

  • fsync(fd) — 同步文件数据和元数据
  • fdatasync(fd) — 只同步数据（不更新 mtime 等）
  • sync() — 刷写所有脏页
  • O_SYNC (open flag) — 每次 write 自动同步
  • O_DSYNC — 只同步数据
  • O_FSYNC = O_SYNC

fcntl F_SETFL

int flags = fcntl(fd, F_GETFL);
flags |= O_SYNC;
fcntl(fd, F_SETFL, flags);

性能影响

方式 数据安全 性能
默认（延迟写） 低（可能丢失） 高
fdatasync 中 中
fsync 高 低
O_SYNC 最高 最低

13.4

`posix_fadvise` — 访问模式提示

本章：TLPI 第 13 章 — File I/O Buffering - 上一节：13.3 【致命】混用 FILE* 与 read/write(fd) - 下一节：13.5 Direct I/O（O_DIRECT）

本节讲什么

int posix_fadvise(int fd, off_t offset, off_t len, int advice); 仅建议内核；常用： ---

要点

int posix_fadvise(int fd, off_t offset, off_t len, int advice);

仅建议内核；常用：

advice 含义
POSIX_FADV_NORMAL 默认
POSIX_FADV_SEQUENTIAL 顺序 → 加大预读
POSIX_FADV_RANDOM 随机 → 少预读
POSIX_FADV_DONTNEED 短期不用 → 可回收缓存
POSIX_FADV_WILLNEED 即将用 → 预加载

HFT / 嵌入式关联

路线 要点
嵌入式 闪存随机读慢，fadvise(WILLNEED) 预取整文件进 page cache，提升启动/加载速度，规避按需读的延迟
HFT 开盘前 posix_fadvise(fd, WILLNEED) 预热行情/静态数据文件，把 I/O 挪到盘前；顺序日志给 SEQUENTIAL 提示

代码示例

#include <fcntl.h>
#include <unistd.h>
#include <stdio.h>

int main(void) {
    int fd = open("/tmp/fadvise_demo.txt", O_RDONLY);
    if (fd < 0) { perror("open"); return 1; }

    /* 告诉内核: 我要顺序读, 预读有帮助 */
    if (posix_fadvise(fd, 0, 0, POSIX_FADV_SEQUENTIAL) != 0) {
        perror("posix_fadvise SEQUENTIAL");
    }
    printf("提示: 顺序读 (内核会预读)\n");

    /* 告诉内核: 这段数据不会再用了, 可丢弃缓存 */
    if (posix_fadvise(fd, 0, 4096, POSIX_FADV_DONTNEED) != 0) {
        perror("posix_fadvise DONTNEED");
    }
    printf("提示: 丢弃前4KB缓存\n");

    /* 预取: 数据马上要用, 提前加载到缓存 */
    if (posix_fadvise(fd, 4096, 8192, POSIX_FADV_WILLNEED) != 0) {
        perror("posix_fadvise WILLNEED");
    }
    printf("提示: 预取4KB-12KB\n");

    close(fd);
    return 0;
}

13.5

Direct I/O（`O_DIRECT`）

本章：TLPI 第 13 章 — File I/O Buffering - 上一节：13.4 posix_fadvise — 访问模式提示 - 下一节：13.6 两层数据流

本节讲什么

open(path, O_RDWR | O_DIRECT)：绕过页缓存，应用与块设备更直接传数据。 缓冲区地址、文件偏移、传输长度须为逻辑块大小（常见 512/4096）整数倍。 缓冲分配：posix_memalign()。

要点

open(path, O_RDWR | O_DIRECT)：绕过页缓存，应用与块设备更直接传数据。

对齐（硬约束）

缓冲区地址、文件偏移、传输长度须为逻辑块大小（常见 512/4096）整数倍。
缓冲分配：posix_memalign()。

适用 自带缓存的 DB 等，不想占系统 page cache
缺点 小 IO 很惨；不能替代 fsync 持久化

O_DIRECT ≠ O_SYNC：前者绕过页缓存；设备本身可能有缓存，落盘仍要 fsync/fdatasync。

Demo：code/odirect_align.c

HFT / 嵌入式关联

路线 要点
嵌入式 O_DIRECT 绕过 page cache 减少内存占用与双重拷贝，适合自带缓存的应用（数据库）；需对齐且不能替代 fsync
HFT 自带用户态缓存的系统用 O_DIRECT 避免内核 page cache 二次拷贝与缓存污染，降低大块读写的延迟与 CPU 开销

代码示例

#include <fcntl.h>
#include <unistd.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

int main(void) {
    /* O_DIRECT: 绕过内核页缓存, 直接读写磁盘 */
    /* 要求: 缓冲区、偏移、长度都必须对齐到块大小 */

    int fd = open("/tmp/odirect_demo.txt", O_RDWR | O_CREAT | O_DIRECT, 0644);
    if (fd < 0) { perror("open O_DIRECT"); return 1; }

    /* 分配对齐的缓冲区 (512 或 4096 对齐) */
    void *buf;
    if (posix_memalign(&buf, 512, 512) != 0) {
        perror("posix_memalign");
        return 1;
    }
    memset(buf, 'A', 512);

    /* 直接写磁盘, 不经过页缓存 */
    ssize_t n = write(fd, buf, 512);
    if (n < 0) { perror("write"); free(buf); return 1; }
    printf("O_DIRECT write: %zd 字节 (绕过页缓存)\n", n);

    /* O_DIRECT 适合: 数据库、HFT 日志等不想要缓存污染的场景 */
    free(buf);
    close(fd);
    return 0;
}

13.3

【致命】混用 `FILE*` 与 `read`/`write`(fd)

本章：TLPI 第 13 章 — File I/O Buffering - 上一节：13.2 stdio 用户态缓冲（FILE*） - 下一节：13.4 posix_fadvise — 访问模式提示

本节讲什么

两套缓冲互不可见： - stdio 有自己的用户缓冲 - read/write 直达内核缓存，绕过 stdio

要点

两套缓冲互不可见：

  • stdio 有自己的用户缓冲
  • read/write 直达内核缓存，绕过 stdio

→ 乱序、丢数据。

做法
✅ 全程只用一套接口
✅ 必须混用：切换前对输出流 fflush
❌ printf 完直接对同一 fd write（未 fflush）

Demo：code/mix_stdio_write.c

HFT / 嵌入式关联

路线 要点
嵌入式 同一 fd 上混用 FILE* 与 read/write，两层缓冲各自独立会乱序/丢数据，混用前必须 fflush 同步
HFT 日志线程 printf 完直接 write 同一 fd 会数据乱序丢失；混用前必须 fflush，热路径干脆统一走 syscall

常见陷阱

  1. 短读未处理
/* 假设一次读完 */
ssize_t n = read(fd, buf, 1024);
/* n 可能 < 1024 */

read 返回值可能小于请求字节数（short read）。网络和管道尤其常见，必须循环读。

  1. EINTR 未处理
/* 信号中断后 read 返回 -1, errno=EINTR */
/* 不是错误，应重试 */

信号中断系统调用时返回 -1 且 errno=EINTR。应该重试，或用 SA_RESTART 自动重启。

  1. EOF 判断错误
/* 用 feof 预判 EOF → 多读一次 */
while (!feof(fp)) { fgets(...); }
/* 正确：检查返回值 */
while (fgets(buf, sz, fp) != NULL) { ... }

read 返回 0 表示 EOF。不要用 feof 预判（feof 只在读取越过后才为真）。

自测题

题目 1（选择）： read() 返回 0 表示什么？ A. 出错 B. EOF C. 没有数据 D. 需要重试

参考答案

B。返回 0 表示已到达文件末尾（EOF）。返回 -1 表示出错，返回 >0 表示读到的字节数。

题目 2（判断）： read 一定会读满请求的字节数。

参考答案

错误。read 可能返回少于请求的字节数（short read），尤其在管道、socket、终端上。必须循环读。

题目 3（踩坑）： 以下代码有什么问题？

char buf[1024];
read(fd, buf, sizeof(buf));
buf[strlen(buf)] = '\0';
参考答案

1) read 不保证以 null 结尾；2) 没检查返回值；3) strlen 在未终止的 buf 上越界。应检查返回值并手动加 \0。

题目 4（应用）： 写一个安全的 readall 函数，确保读满 n 字节或遇到 EOF。

参考答案 
ssize_t readall(int fd, void *buf, size_t n) {
    size_t total = 0;
    while (total < n) {
        ssize_t r = read(fd, (char*)buf+total, n-total);
        if (r < 0 && errno == EINTR) continue;
        if (r < 0) return -1;
        if (r == 0) break; /* EOF */
        total += r;
    }
    return total;
}

代码示例

#include <stdio.h>
#include <fcntl.h>
#include <unistd.h>
#include <string.h>
/* read/write vs fread/fwrite: 直接系统调用 vs stdio */
int main(void) {
    /* write: 直接进 kernel page cache */
    int fd = open("/tmp/rw_test.txt", O_WRONLY | O_CREAT | O_TRUNC, 0644);
    write(fd, "via write()\n", 12);
    close(fd);

    /* fwrite: 经 stdio 缓冲, flush 时才调 write */
    FILE *fp = fopen("/tmp/rw_test.txt", "a");
    fwrite("via fwrite()\n", 13, 1, fp);
    fclose(fp);  /* fclose 自动 flush */

    /* posix_fadvise: 给内核预读/丢弃提示 */
    fd = open("/tmp/rw_test.txt", O_RDONLY);
    posix_fadvise(fd, 0, 0, POSIX_FADV_SEQUENTIAL);  /* 顺序读 */
    char buf[64];
    read(fd, buf, sizeof(buf));
    printf("content: %s", buf);
    close(fd);
    return 0;
}

13.6

两层数据流

本章：TLPI 第 13 章 — File I/O Buffering - 上一节：13.5 Direct I/O（O_DIRECT） - 下一节：下一章+1:02d}-*/notes.md)

本节讲什么

写： 应用 → stdio 用户缓冲 →（fflush）→ write → 内核脏页 →（fsync/flusher）→ 磁盘 读： 磁盘 → 页缓存 → read → stdio 缓冲 → fgets/… → 应用 ---

要点

写： 应用 → stdio 用户缓冲 →（fflush）→ write → 内核脏页 →（fsync/flusher）→ 磁盘

读： 磁盘 → 页缓存 → read → stdio 缓冲 → fgets/… → 应用

HFT / 嵌入式关联

路线 要点
嵌入式 两层缓冲（用户态 stdio + 内核 page cache）必须分清数据流时点，才能正确控制落盘与内存占用
HFT 延迟敏感路径尽量压成一层（直接 write 或 O_DIRECT），减少缓冲层数与数据拷贝次数

代码示例

#include <stdio.h>
#include <fcntl.h>
#include <unistd.h>

/* 缓冲层次总结:
 * 1. stdio 缓冲 (用户空间): setvbuf/fflush 控制
 * 2. 内核页缓存: posix_fadvise 提示, O_DIRECT 绕过
 * 3. fsync/fdatasync: 强制刷盘
 */
int main(void) {
    FILE *fp = fopen("/tmp/buf_summary.txt", "w");
    fprintf(fp, "hello");
    /* 数据在 stdio 缓冲 → fflush 后进内核页缓存 */
    fflush(fp);
    /* 内核页缓存 → fsync 后才真正落盘 */
    int fd = fileno(fp);
    fsync(fd);
    printf("数据已落盘 (stdio → 内核 → 磁盘)\n");
    fclose(fp);

    /* 总结:
     * write() → 内核页缓存 (不落盘)
     * fsync() → 强制页缓存写入磁盘
     * O_DIRECT → 绕过页缓存 (直接磁盘 I/O)
     * posix_fadvise → 给内核缓存提示
     */
    return 0;
}

练习题

练习 1：fsync vs fdatasync

解释 fsync(fd) 和 fdatasync(fd) 的区别，在什么场景下应该用哪个？

练习 2：stdio 与系统调用混用

为什么混用 FILE*（如 fprintf/fread）和文件描述符 I/O（如 write(fd, ...)）会导致数据不一致？如何避免？

练习 3：缓冲模式对比

编写程序对比 stdio 三种缓冲模式（_IOFBF/_IOLBF/_IONBF）对写入性能的影响。

参考答案

练习 1 答案

特性 fsync(fd) fdatasync(fd)
同步内容 数据 + 元数据 仅数据（最小元数据）
元数据 mtime、ctime、inode 大小等 仅必要元数据（如文件大小）
性能 较慢（更多 I/O） 较快（减少元数据写入）
POSIX 标准要求 标准要求

场景选择： - fsync：数据库事务日志、关键文件持久化（需确保 mtime 正确） - fdatasync：HFT 日志、高性能写入场景（只要数据安全，不关心 mtime）

注意：fdatasync 可能在某些文件系统（如 ext4 with data=journal）上等价于 fsync。

练习 2 答案

数据不一致原因：

stdio 缓冲区: [aaaa|bbbb]    write(fd, "cccc") → 直接写内核
                      ↑                          ↑
              fflush 前 stdio 缓冲区           内核缓冲区
  • fprintf(fp, "aaaa") → 数据在 stdio 缓冲区（用户空间），未到达内核
  • write(fd, "bbbb") → 数据直接进入内核缓冲区
  • 读取顺序可能错乱：内核中的 "bbbb" 先落盘，stdio 中的 "aaaa" 后 flush
  • 多个缓冲区各自有偏移量，可能覆盖或交错

避免方法： 1. 不混用：只用 stdio 或只用系统调用 2. fflush(fp) 强制刷新 stdio 缓冲区后再用 write(fd) 3. fileno(fp) 获取 fd 后统一使用 write，但需先 setbuf(fp, NULL) 关闭缓冲

练习 3 参考代码

#include <stdio.h>
#include <time.h>
#include <string.h>

#define LINES 100000
#define LINE "Hello, World!\n"

void bench(int mode, const char *name) {
    FILE *f = tmpfile();
    setvbuf(f, NULL, mode, 0);

    struct timespec start, end;
    clock_gettime(CLOCK_MONOTONIC, &start);

    for (int i = 0; i < LINES; i++)
        fputs(LINE, f);

    fflush(f);
    clock_gettime(CLOCK_MONOTONIC, &end);

    long long ns = (end.tv_sec - start.tv_sec) * 1000000000LL
                 + (end.tv_nsec - start.tv_nsec);
    printf("%-8s: %lld.%09lld s (%d lines)\n", name,
           ns / 1000000000LL, ns % 1000000000LL, LINES);
    fclose(f);
}

int main(void) {
    bench(_IOFBF, "FULLBUF");
    bench(_IOLBF, "LINEBUF");
    bench(_IONBF, "NOBUF");
    return 0;
}

预期结果： - _IOFBF（全缓冲）：最快，系统调用最少 - _IOLBF（行缓冲）：较慢，每行触发一次系统调用 - _IONBF（无缓冲）：最慢，每次 fputs 一次系统调用

HFT / 嵌入式关联

  • HFT 日志：用 O_DIRECT + write 绕过页缓存，或 fdatasync 确保持久化
  • 延迟优先：HFT 热路径避免 stdio 缓冲，用 write(fd, buf, n) 直接系统调用
  • 嵌入式：嵌入式文件系统可能不支持 fdatasync（回退到 fsync）
  • O_SYNC：打开时用 O_SYNC 或 O_DSYNC 替代手动 fsync
