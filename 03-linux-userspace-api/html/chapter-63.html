63.3

信号驱动 I/O

本章：TLPI 第 63 章 — 备用 I/O 模型 - 上一节：63.2 I/O 多路复用 select/poll - 下一节：63.4 epoll API

本节讲什么

信号驱动 I/O — 内核在 fd 可读/可写时发 SIGIO 信号，进程异步处理。

要点

工作流程

  1. 设 fd 属主：fcntl(fd, F_SETOWN, getpid())
  2. 启用非阻塞：fcntl(fd, F_SETFL, O_NONBLOCK)
  3. 启用异步通知：fcntl(fd, F_SETFL, O_ASYNC)
  4. 注册 SIGIO handler
  5. fd 可读/可写时内核发 SIGIO

优缺点

优势 劣势
无需轮询 信号开销大（内核→用户态切换）
不阻塞 标准 SIGIO 不携带 fd 信息
简单 竞态条件（信号与读取之间状态变化）

实际应用

  • 主要用于 UDP socket（TCP 的信号过于频繁）
  • 被 epoll 完全取代 — 现代 Linux 不推荐使用
  • 历史价值大于实用价值

与 epoll 的对比

信号驱动 I/O epoll
通知方式 信号 (SIGIO) epoll_wait 返回事件
fd 信息 不携带（需查询） 携带（epoll_data_t）
性能 差（信号开销） 好（共享内存事件表）
扩展性 差 好（O(1) 复杂度）
推荐 不推荐 强烈推荐

HFT / 嵌入式关联

路线 要点
嵌入式 旧嵌入式系统可能用信号驱动 I/O，新系统应迁移到 epoll
HFT 不用信号驱动 I/O — 信号中断热路径有延迟抖动，用 epoll

代码示例

#include <stdio.h>
#include <fcntl.h>
#include <signal.h>
#include <unistd.h>
/* 信号驱动 I/O: SIGIO 通知 fd 可读 */
volatile sig_atomic_t data_ready = 0;
void handler(int sig) { data_ready = 1; }

int main(void) {
    int fd = open("/dev/null", O_RDONLY | O_NONBLOCK);

    /* 设属主 + 启用异步通知 */
    fcntl(fd, F_SETOWN, getpid());
    fcntl(fd, F_SETFL, O_ASYNC | O_NONBLOCK);

    /* 注册 SIGIO handler */
    signal(SIGIO, handler);

    /* 实际使用: 等待 data_ready, 然后 read(fd) */
    printf("signal-driven I/O setup complete\n");
    printf("(use epoll instead in production)\n");

    close(fd);
    return 0;
}

63.4

epoll API

本章：TLPI 第 63 章 — 备用 I/O 模型 - 上一节：63.3 信号驱动 I/O - 下一节：63.5 同时等待信号和 fd

本节讲什么

epoll — Linux 高性能 I/O 多路复用，O(1) 复杂度，适合大量连接。

要点

API 三件套

函数 作用
epoll_create1(flags) 创建 epoll 实例，返回 fd
epoll_ctl(epfd, op, fd, &event) 添加/修改/删除监听 fd
epoll_wait(epfd, events, maxevents, timeout) 等待事件

epoll_ctl 的 op

op 作用
EPOLL_CTL_ADD 添加 fd
EPOLL_CTL_MOD 修改监听事件
EPOLL_CTL_DEL 删除 fd

事件类型

事件 含义
EPOLLIN 可读
EPOLLOUT 可写
EPOLLET 边沿触发（只通知一次）
EPOLLONESHOT 通知一次后需重新 armed

两种触发模式

模式 行为 推荐
水平触发 (LT, 默认) fd 可读就一直通知 简单，但可能多余通知
边沿触发 (ET) 状态变化时通知一次 高性能，需非阻塞 + 读到 EAGAIN

与 select/poll 的对比

select poll epoll
fd 上限 1024 (FD_SETSIZE) 无限制 无限制
复杂度 O(n) O(n) O(1)
返回方式 全量遍历检查 全量遍历检查 只返回就绪的
内核维护 每次拷贝 fd_set 每次拷贝 pollfd 内核维护红黑树
大量连接 慢 慢 快

epoll_event 结构

struct epoll_event {
    uint32_t events;       /* EPOLLIN | EPOLLOUT | ... */
    epoll_data_t data;     /* fd / ptr / u32 / u64 */
};

边沿触发 (ET) 模式要点

/* ET 模式必须循环读到 EAGAIN */
while (1) {
    ssize_t n = read(fd, buf, sizeof(buf));
    if (n == -1 && errno == EAGAIN) break;  /* 读完了 */
    if (n <= 0) break;  /* EOF 或错误 */
    /* 处理 buf */
}

HFT / 嵌入式关联

路线 要点
嵌入式 epoll 是 Linux 高并发服务端的标准方案
HFT ET 模式 + 非阻塞 fd + 批量 read 是最低延迟方案

代码示例

#include <stdio.h>
#include <sys/epoll.h>
#include <unistd.h>
#include <fcntl.h>
#include <string.h>
/* epoll: 监听 stdin + 定时器 fd */
int main(void) {
    int epfd = epoll_create1(0);

    /* 添加 stdin (ET 模式) */
    struct epoll_event ev;
    ev.events = EPOLLIN | EPOLLET;
    ev.data.fd = STDIN_FILENO;
    fcntl(STDIN_FILENO, F_SETFL, O_NONBLOCK);
    epoll_ctl(epfd, EPOLL_CTL_ADD, STDIN_FILENO, &ev);

    /* 事件循环 */
    struct epoll_event events[10];
    printf("type something (Ctrl+D to exit):\n");
    while (1) {
        int n = epoll_wait(epfd, events, 10, -1);  /* 无限等待 */
        for (int i = 0; i < n; i++) {
            if (events[i].data.fd == STDIN_FILENO) {
                char buf[256];
                /* ET 模式: 循环读到 EAGAIN */
                while (1) {
                    ssize_t r = read(STDIN_FILENO, buf, sizeof(buf)-1);
                    if (r <= 0) break;
                    buf[r] = 0;
                    printf("read: %s", buf);
                }
                if (r == 0) goto done;  /* EOF */
            }
        }
    }
done:
    close(epfd);
    return 0;
}

63.5

同时等待信号和文件描述符

本章：TLPI 第 63 章 — 备用 I/O 模型 - 上一节：63.4 epoll API - 下一节：63.6 总结

本节讲什么

pselect() / ppoll() / epoll_pwait() — 原子地等待信号和 fd，消除竞态。

要点

问题：信号与 I/O 的竞态

/* 竞态: 信号在 sigprocmask 和 select 之间到达 */
sigprocmask(SIG_UNBLOCK, &sigset, NULL);  /* 解除阻塞 */
select(...);  /* 如果信号在此行之前到达, select 永远不醒 */

解决方案：原子"解除阻塞 + 等待"

函数 替代 优势
pselect select 原子解除信号阻塞 + 等待 fd
ppoll poll 同上
epoll_pwait epoll_wait 同上

pselect 签名

int pselect(int nfds, fd_set *rfds, fd_set *wfds, fd_set *efds,
            const struct timespec *timeout, const sigset_t *sigmask);
  • sigmask：等待期间临时替换信号掩码（原子操作）
  • 返回后信号掩码恢复原值

signalfd + epoll 方案

/* 更优雅的方案: signalfd 融入 epoll */
int sfd = signalfd(-1, &sigmask, 0);
epoll_ctl(epfd, EPOLL_CTL_ADD, sfd, &ev);
/* epoll_wait 同时返回 fd 事件和信号事件 */

三种方案对比

方案 优势 劣势
pselect/ppoll POSIX 标准化 仍需 handler
epoll_pwait Linux 高效 Linux 专有
signalfd + epoll 统一事件循环，无 handler Linux 专有

HFT / 嵌入式关联

路线 要点
嵌入式 ppoll 是可移植的方案，适合嵌入式
HFT signalfd + epoll 统一事件循环，零信号中断延迟

代码示例

#include <stdio.h>
#include <signal.h>
#include <poll.h>
#include <unistd.h>
#include <sys/signalfd.h>
/* 方案: signalfd + poll 统一等待信号和 fd */
int main(void) {
    /* 阻塞 SIGINT */
    sigset_t mask;
    sigemptyset(&mask);
    sigaddset(&mask, SIGINT);
    sigprocmask(SIG_BLOCK, &mask, NULL);

    /* 创建 signalfd */
    int sfd = signalfd(-1, &mask, 0);

    /* poll 同时等 stdin 和 signalfd */
    struct pollfd fds[2];
    fds[0].fd = STDIN_FILENO;  fds[0].events = POLLIN;
    fds[1].fd = sfd;            fds[1].events = POLLIN;

    printf("type input or Ctrl+C (5s timeout):\n");
    int n = poll(fds, 2, 5000);
    if (n == 0) {
        printf("timeout\n");
    } else {
        if (fds[0].revents & POLLIN) {
            char buf[64];
            fgets(buf, sizeof(buf), stdin);
            printf("stdin: %s", buf);
        }
        if (fds[1].revents & POLLIN) {
            struct signalfd_siginfo si;
            read(sfd, &si, sizeof(si));
            printf("signal: %d\n", si.ssi_signo);
        }
    }
    close(sfd);
    return 0;
}

I/O 模型选型决策

需求 推荐
少量 fd, 简单 阻塞 I/O
少量 fd, 需超时 select
中等 fd, 可移植 poll

核心要点

  1. epoll 是 Linux 高并发标准方案 — O(1) 复杂度
  2. ET 模式必须非阻塞 fd + 循环读到 EAGAIN
  3. signalfd + epoll 统一事件循环 — 消除信号竞态
  4. 信号驱动 I/O 已被 epoll 取代，不用
  5. io_uring 是 Linux 最新异步 I/O 框架（超出 TLPI 范围）

代码自测

1. epoll 的 ET 模式为什么必须用非阻塞 fd？

ET 模式只在状态变化时通知一次。如果用阻塞 fd，read/recv 在缓冲区数据读完后会阻塞，导致无法返回事件循环处理其他 fd。非阻塞 fd 读到 EAGAIN 表示数据读完，可以安全返回等待下一个事件。

2. select 和 epoll 的核心区别？

select 每次调用需要拷贝 fd_set 到内核，返回后全量遍历检查每个 fd，复杂度 O(n)，且 fd 数量受 FD_SETSIZE (1024) 限制。epoll 在内核维护红黑树，只返回就绪的 fd，复杂度 O(1)，无数量限制。

练习题

本章：TLPI 第 63 章 — 备用 I/O 模型

本节讲什么

原书第 63 章练习题要点。

1. 用 epoll 实现一个 echo 服务端，支持多客户端并发 
int epfd = epoll_create1(0);
struct epoll_event ev = { .events = EPOLLIN, .data.fd = listen_fd };
epoll_ctl(epfd, EPOLL_CTL_ADD, listen_fd, &ev);

struct epoll_event events[64];
while (1) {
    int n = epoll_wait(epfd, events, 64, -1);
    for (int i = 0; i < n; i++) {
        if (events[i].data.fd == listen_fd) {
            int cfd = accept(listen_fd, NULL, NULL);
            fcntl(cfd, F_SETFL, O_NONBLOCK);
            ev.events = EPOLLIN | EPOLLET;
            ev.data.fd = cfd;
            epoll_ctl(epfd, EPOLL_CTL_ADD, cfd, &ev);
        } else {
            /* echo: 读到 EAGAIN 为止, 原样写回 */
            char buf[4096];
            while (1) {
                ssize_t r = read(events[i].data.fd, buf, sizeof(buf));
                if (r <= 0) break;
                write(events[i].data.fd, buf, r);
            }
        }
    }
}
2. 为什么 pselect 需要额外的 sigmask 参数？

pselect 原子地"用 sigmask 替换信号掩码 + 等待 fd"，返回后恢复原掩码。这消除了"解除信号阻塞"和"进入等待"之间的竞态窗口，确保不会错过信号。如果分两步做（sigprocmask + select），信号可能在两步之间到达，select 会永远阻塞。

3. signalfd + epoll 相比 pselect 有什么优势？

signalfd 将信号变成普通 fd 事件，融入 epoll 事件循环。优势：(1) 统一处理 fd 和信号，无需 handler；(2) 没有 handler 的异步中断，代码全同步；(3) 可与大量 fd 一起高效管理；(4) 线程安全，可指定接收信号的线程。
