横向对比

read/write mmap 文件
拷贝 用户↔页缓存两次 直接碰页缓存，少一次

易错清单

  1. mmap 失败返回 MAP_FAILED（(void*)-1），不是 NULL
  2. offset 必须页对齐（EINVAL）；length 内核向上取整
  3. PRIVATE 未写过的页跟随 page cache——不是快照（实测三连，copy-on-write 非 copy-on-access）
  4. 写页内 1 字节 = 整页 COW 定格（粒度是页）
  5. 越过文件尾访问映射 → SIGBUS（不是 SIGSEGV——VMA 合法但无后备）
  6. msync 只对 SHARED 文件映射有意义；MS_ASYNC 是 no-op（2.6.19+）
  7. MS_INVALIDATE 遇 mlock 区 → EBUSY
  8. munmap 的 addr 必须页对齐（EINVAL）；区间内空洞静默忽略
  9. munmap 中间一页 → VMA 分裂（maps 1→2）；相邻同 flags 分配又会 merge
  10. mremap 无 MAYMOVE 被挡 → ENOMEM；搬家是页表级零拷贝
  11. MREMAP_DONTUNMAP 旧地址读回零（不是旧数据）；仅匿名映射
  12. MAP_FIXED 静默覆盖已有映射（先 munmap 再建）；NOREPLACE 被占→EEXIST
  13. remap_file_pages v6.6 纯 emulation（dmesg 警告 + mmap 绕路）
  14. overcommit=2 严格模式下 MAP_NORESERVE 被忽略（照样记账）

49.1

四大组合

源码核验：Linux v6.6 · mm/mmap.c（do_mmap():1203 · get_unmapped_area():1801 · mmap_region():2662）· include/linux/mm_types.h（struct vm_area_struct :565） 本章：TLPI 第 49 章 — Memory Mappings - 上一节：本章首页 - 下一节：49.2 创建映射 mmap

本节讲什么

mmap 的本质：只在进程虚拟地址空间「画一块区域」，建立映射关系，不立刻把数据搬进内存。 访问这块虚拟地址才会触发缺页中断，由内核把磁盘/设备数据填进物理页。所以第一件事是分清三样东西：

概念 是什么 谁触发
mmap 用户态「画一块虚拟区间」，建立 虚址 ↔ 文件/设备/匿名页 的映射 进程主动调用
缺页中断（page fault） CPU 内存管理机制：访问未映射/未加载地址时陷入内核填页 CPU 硬件，不等于 mmap
共享 / 私有 mmap 的 flags 控制多进程是否共用同一物理页 MAP_SHARED / MAP_PRIVATE

一句话：mmap 给进程虚拟地址画一块区域，可以映射到同一份物理内存实现多进程共享；但设备能不能让你映射，由设备驱动说了算——独占访问靠驱动锁，不是 mmap 自带能力。

生命周期：fork 继承映射；exec / 退出 销毁全部映射。

内核三步走（v6.6 坐标）

mmap(2)
 └─ ksys_mmap_pgoff():1382        fd → struct file（fd 不合法直接 EBADF）
     └─ do_mmap():1203             计算 vm_flags（SHARED→VM_SHARED、prot→vm_page_prot…）
         ├─ get_unmapped_area():1801   选地址：top-down 从 mmap_base 往下找空洞
         └─ mmap_region():2662         【画区】
             ├─ do_vmi_munmap():2693   （仅 MAP_FIXED）先拆旧映射
             ├─ vma_merge 尝试         与相邻 VMA 属性相同 → 合并（不新建）

注意：mmap 只到「画区」为止——物理页一颗都没分配（除非 MAP_POPULATE）。填页是首次访问时缺页中断的事。这就是「先画区后填页」。

要点

mmap 的三类映射对象

对象 fd / offset 缺页时内核从哪填 典型场景
磁盘文件 fd + 页对齐 offset 页缓存（page cache） 文件共享、加载 text 段
设备 DMA 缓冲区 设备 fd 驱动提供的内存页（remap_pfn_range / dma_mmap_*） 网卡/采集卡零拷贝、帧缓冲
匿名内存 MAP_ANONYMOUS、fd=-1 零页 + 首写 COW 分配 malloc 一类、父子共享

四大组合

MAP_PRIVATE MAP_SHARED
文件 COW；改不回文件；加载 text/只读文件 改可见且可回盘；无关进程 IPC
匿名 私有堆式分配（malloc 一类） 仅亲缘（fork 继承）IPC

共享型设备 vs 独占型设备

设备类型 例子 mmap 的用法
共享型 共享文件、共享设备缓冲区 多进程 MAP_SHARED 映射同一份物理内存，一个改、其他进程都看得见
独占型 麦克风、独占采集卡 ❌ 不是给每个进程各做一份 mmap；✅ 设备驱动里做独占锁，同一时刻只允许一个进程 mmap 成功，别的进程调用 mmap 失败/阻塞

关键：互斥逻辑写在设备驱动里，mmap 只是驱动对外暴露缓冲区的手段，本身不提供任何互斥。

生命周期：fork 继承映射；exec / 退出 销毁全部映射。

HFT / 嵌入式关联

路线 要点
嵌入式 设备 DMA 缓冲区 mmap：/dev/mem、帧缓冲（framebuffer）、网卡/采集卡寄存器——用户态直接读写设备内存，省掉 read/write 的 syscall + 一次拷贝
HFT 低延迟零拷贝：把网卡（DPDK 大页 + mmap）的 DMA 环形缓冲区映射进用户态，报文「网卡 DMA 直写用户态页」，不经过内核协议栈拷贝；共享型设备多进程 MAP_SHARED 看同一份行情

独占设备在 HFT 里同样成立：锁在驱动。例：一个采集卡同一时刻只让一个进程 mmap，驱动用 mutex/原子变量守卫 fops->mmap，抢不到就返回 -EBUSY。

代码示例


/* 四大映射组合演示：MAP_PRIVATE vs MAP_SHARED × 文件 vs 匿名 */
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <fcntl.h>
#include <sys/mman.h>
#include <sys/wait.h>
#include <unistd.h>

int main(void) {
    /* 1) MAP_PRIVATE 文件映射 — COW，修改不回盘 */
    int fd = open("/tmp/ch49_demo.txt", O_RDWR | O_CREAT | O_TRUNC, 0644);
    if (fd < 0) { perror("open"); return 1; }
    if (write(fd, "original", 8) != 8) { perror("write"); return 1; }
    char *priv = mmap(NULL, 8, PROT_READ | PROT_WRITE, MAP_PRIVATE, fd, 0);
    priv[0] = 'X';  /* 写入触发 COW，不影响文件 */
    printf("MAP_PRIVATE after write: %.8s\n", priv);

    /* 2) MAP_SHARED 文件映射 — 修改可回盘 */
    char *shared = mmap(NULL, 8, PROT_READ | PROT_WRITE, MAP_SHARED, fd, 0);
    shared[0] = 'S';  /* msync 后写回文件 */
    msync(shared, 8, MS_SYNC);

    /* 3) MAP_SHARED|MAP_ANONYMOUS — 父子 IPC */
    char *anon = mmap(NULL, 64, PROT_READ | PROT_WRITE,
                      MAP_SHARED | MAP_ANONYMOUS, -1, 0);
    strcpy(anon, "fork-ipc");
    pid_t pid = fork();
    if (pid == 0) { printf("child: %s\n", anon); _exit(0); }
    wait(NULL);

    /* 4) MAP_PRIVATE|MAP_ANONYMOUS — 私有堆式分配 */
    char *heap_like = mmap(NULL, 64, PROT_READ | PROT_WRITE,
                           MAP_PRIVATE | MAP_ANONYMOUS, -1, 0);
    strcpy(heap_like, "private anon");

    munmap(priv, 8); munmap(shared, 8); munmap(anon, 64); munmap(heap_like, 64);
    close(fd);
    return 0;
}

设备独占：锁在驱动（伪代码）

/* 驱动侧：独占设备同一时刻只允许一个进程 mmap */
static int mic_mmap(struct file *filp, struct vm_area_struct *vma)
{
    /* 原子变量实现「拿得到才映射」的独占锁 */
    if (!atomic_add_unless(&mic_open, 1, 1))
        return -EBUSY;             /* 已被别的进程独占 → mmap 失败 */

    /* 把设备 DMA 缓冲区物理页映射进用户态虚拟地址 */
    return remap_pfn_range(vma, vma->vm_start,
                           mic_dma_paddr >> PAGE_SHIFT,
                           vma->vm_end - vma->vm_start,
                           vma->vm_page_prot);
}

static int mic_release(struct inode *i, struct file *filp)
{
    atomic_set(&mic_open, 0);      /* 释放独占 */
    return 0;
}

注意：互斥逻辑完全在驱动（atomic_add_unless + -EBUSY），mmap 系统调用本身不提供「独占」能力——它只是把驱动暴露的缓冲区挂到进程虚拟地址上。

创建映射：mmap()

源码核验：Linux v6.6 · mm/mmap.c（ksys_mmap_pgoff():1382 · do_mmap():1203 · generic_get_unmapped_area():1691 · arch_get_unmapped_area():1726 · get_unmapped_area():1801 · mmap_region():2662 · vma_link():395 · vma_merge():863）· include/linux/mm_types.h（struct vm_area_struct :565） 本章：TLPI 第 49 章 — Memory Mappings - 上一节：49.1 四大组合 - 下一节：49.3 解除映射 munmap

本节讲什么

mmap 在进程虚拟地址空间画一块区域（建立一个 VMA），建立「虚址区间 ↔ 文件/匿名后备」的映射关系。三个灵魂问题：

  1. 画区时发生了什么？（选地址 → 建 VMA → 挂树——一颗物理页都不分配）
  2. 六个参数各自的坑？（offset 必须页对齐；prot 不能超 fd 模式；flags 必须含 SHARED/PRIVATE 之一）
  3. 失败返回什么？（MAP_FAILED = (void*)-1，不是 NULL——与 malloc 的最大差异）
#include <sys/mman.h>
void *mmap(void *addr, size_t length, int prot, int flags,
           int fd, off_t offset);
/* 成功返回映射起始地址（内核选）；失败返回 MAP_FAILED 并设 errno */

要点

参数六元组精讲

参数 规则 坑
addr NULL 推荐（内核自选）；非 NULL 非固定时只是提示，内核可挪走 期望返回 addr 而没用 MAP_FIXED → 地址几乎必然不同
length 向上取整到页边界（映射尾页部分可用） 写越 length（但同页内）不报错——最后一页是整页
prot PROT_NONE/READ/WRITE/EXEC 组合 不得超过 fd 的 open 模式（O_RDONLY + PROT_WRITE → EACCES）
flags 必须含 MAP_SHARED 或 MAP_PRIVATE 之一（两者语义互斥） 缺了或都给 → EINVAL
fd 文件映射必填；MAP_ANONYMOUS 时被忽略（惯例传 -1） 匿名时内核根本不碰 fd（传啥都行，但 -1 是可读性惯例）
offset 必须页对齐（EINVAL） 想映射「文件第 100 字节起」？先算 offset=100&~(pagesize-1)，指针再偏移 100

返回值：MAP_FAILED 不是 NULL

void *p = mmap(NULL, len, PROT_READ|PROT_WRITE, MAP_PRIVATE|MAP_ANONYMOUS, -1, 0);
if (p == NULL)   ...   /* 错：mmap 不返回 NULL */
if (p == MAP_FAILED) { perror("mmap"); exit(1); }   /* 对 */

MAP_FAILED 定义为 ((void *) -1)。内核选地址永远避开 0 和 -1 附近的页，NULL 恒不可能。

addr 非 NULL 时的三种命运

flags 内核行为
无 MAP_FIXED addr 是 hint：以 addr 为起点向上找空洞（arch_get_unmapped_area():1726，bottom-up）；拿不到就别处返回
MAP_FIXED 精确落在 addr，静默覆盖已有映射（见 49.10）
MAP_FIXED_NOREPLACE 精确落 addr；被占 → EEXIST（不覆盖，4.17+）

内核路径：从 syscall 到 VMA 挂树（v6.6 坐标）

mmap(2)
 └─ ksys_mmap_pgoff():1382
     ├─ fd 合法性：fdget()，失败 EBADF
     └─ vm_mmap_pgoff → do_mmap():1203
         ├─ length==0 → EINVAL；溢出检查
         ├─ flags 校验（_MAP_VALIDATE；SHARED/PRIVATE 二选一）
         ├─ 计算 vm_flags：prot + flags 翻译成内核位图
         │    （VM_SHARED/VM_MAYWRITE/VM_GROWSDOWN…，mmap_min_addr 检查）
         ├─ 文件：security_mmap_file(LSM)、mapping 预检查
         └─ get_unmapped_area():1801
             └─ arch_get_unmapped_area():1726（bottom-up）/ topdown 变体
                 从 hint/上次 mmap 地址附近找第一个够大的空洞
         mmap_region():2662【画区】
         ├─（MAP_FIXED）先 do_vmi_munmap():2693 拆旧映射
         ├─ accountable_mapping：私有可写 → 记账 swap 预留（VM_ACCOUNT，
         │    可被 MAP_NORESERVE 关闭，见 49.9）
         ├─ vma_merge():863 尝试：与 prev/next VMA 属性相同且紧贴 → 合并进现有 VMA
         ├─（合并失败）vm_area_alloc：从 slab 分配 vm_area_struct
         ├─ vma_link():395
         │    ├─ maple tree 插入（v6.6 起 VMA 用 maple tree 组织，旧版红黑树）
         │    └─ 文件映射：挂进 mapping->i_mmap（反向映射）
         └─ MAP_POPULATE → 立即 populate（预缺页）

vm_area_struct（include/linux/mm_types.h:565）——一个 VMA 的身份证

字段 含义
vm_start / vm_end 虚拟区间 [start, end)，页对齐
vm_page_prot 缺页时建立 PTE 用的保护位（prot 翻译而来）
vm_flags VM_SHARED/VM_MAYREAD/VM_LOCKED/VM_ACCOUNT…（内核内部位图，与 mmap flags 不同）
vm_file / vm_pgoff 后备文件（持引用计数）与文件内页偏移
vm_ops 文件映射的缺页回调（fault→filemap_fault 等）
anon_vma 匿名页的反向映射锚点（COW/父子链）

一个 VMA 管一段属性完全相同的连续虚址——这就是为什么 munmap 中间一页会把 VMA 分裂成两个（见 49.3 实测）。

fd 的生命周期独立于映射

mmap 后 close(fd) 映射依然有效——vm_area_struct.vm_file 持有 struct file 的引用计数，close 只减你自己那份。实测验证（49.3 实验）。

/* mmap 生命周期实测：画区≠填页（maps/smaps 双口径）
 * 实测（WSL Ubuntu，gcc -O2 -Wall -Wextra，2026-09-05）：
 *   步骤1 mmap p=0x7ef676812000（未触碰，两侧 guard 为 PROT_NONE）
 *     [未触碰] VMA条数=1  Rss=0 kB          ← 画区完成，零物理页
 *   步骤2 读触碰第 0 页（do_anonymous_page 走零页分支）
 *     [读触碰] VMA条数=1  Rss=0 kB          ← 零页 present 但不计 RSS
 *   步骤3 写触碰第 0 页（分配私有物理页）
 *     [写触碰] VMA条数=1  Rss=4 kB          ← COW 真页才进 RSS
 *   步骤5 close(fd) 后读文件映射："FDLIFE"  ← fd 关了映射还活着
 */
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <fcntl.h>
#include <errno.h>
#include <sys/mman.h>
#include <unistd.h>

static long smaps_rss(void *addr)
{
    FILE *fp = fopen("/proc/self/smaps", "r");
    if (!fp) return -1;
    char line[300];
    unsigned long lo, hi, a = (unsigned long)addr;
    long rss = -1;
    int in_target = 0;
    while (fgets(line, sizeof line, fp)) {
        if (sscanf(line, "%lx-%lx", &lo, &hi) == 2)
            in_target = (a >= lo && a < hi);
        else if (in_target && strncmp(line, "Rss:", 4) == 0) {
            sscanf(line + 4, "%ld", &rss);
            break;
        }
    }
    fclose(fp);
    return rss;
}

int main(void)
{
    long pagesz = sysconf(_SC_PAGESIZE);
    size_t P = (size_t)pagesz;

    /* PROT_NONE guard 包夹观察区：防观察区的 VMA 被相邻分配 merge 吞并
     * （v1 实测教训：fopen(/proc/self/smaps) 自身 malloc→mmap，
     *  与观察区紧贴且 flags 相同 → vma_merge 吞掉边界，VMA 条数错乱） */
    char *raw = mmap(NULL, 5 * P, PROT_NONE, MAP_PRIVATE | MAP_ANONYMOUS, -1, 0);
    if (raw == MAP_FAILED) { perror("mmap raw"); return 1; }
    char *p = mmap(raw + P, 3 * P, PROT_READ | PROT_WRITE,
                   MAP_PRIVATE | MAP_ANONYMOUS | MAP_FIXED, -1, 0);
    if (p == MAP_FAILED) { perror("mmap"); return 1; }

    printf("mmap p=%p（未触碰）Rss=%ld kB ← 画区完成，物理页为 0\n",
           (void *)p, smaps_rss(p));

    volatile char c = p[0]; (void)c;    /* 读触碰：映射零页 */
    printf("读触碰后 Rss=%ld kB ← 零页不计入 RSS\n", smaps_rss(p));

    p[0] = 1;                           /* 写触碰：分配真页 */
    printf("写触碰后 Rss=%ld kB ← COW 真页进 RSS\n", smaps_rss(p));

    /* close(fd) 后映射存活 */
    int fd = open("/tmp/ch49_a.dat", O_RDWR | O_CREAT | O_TRUNC, 0644);
    if (fd < 0) { perror("open"); return 1; }
    if (write(fd, "FDLIFE", 6) != 6) { perror("write"); return 1; }
    char *f = mmap(NULL, 6, PROT_READ, MAP_PRIVATE, fd, 0);
    if (f == MAP_FAILED) { perror("mmap file"); return 1; }
    close(fd);
    printf("close(fd) 后读文件映射：\"%.6s\" ← vma->vm_file 持引用\n", f);

    munmap(p, 3 * P);
    munmap(raw, 5 * P);
    munmap(f, 6);
    unlink("/tmp/ch49_a.dat");
    return 0;
}

题目 1（选择）： mmap(NULL, 4096, PROT_READ, MAP_PRIVATE, fd, 100) 返回什么错误？fd 打开模式为 O_RDONLY。

A. 成功　B. EINVAL　C. EACCES　D. EBADF

参考答案

B（EINVAL）——offset=100 未页对齐。prot=PROT_READ 没超过 O_RDONLY 模式（不触发 EACCES）。页对齐是 offset 参数自己的硬性要求，与 prot 无关。

题目 2（判断）： mmap 成功返回时，length 字节的物理内存已经分配好了。

参考答案

错误。mmap 只建 VMA（画区），一颗物理页都没有——实测 mmap 后 Rss=0 kB。物理页在首次访问时按缺页中断逐页分配（匿名走 do_anonymous_page，文件走 filemap_fault）。例外：MAP_POPULATE 标志强制立即预填充。

题目 3（应用）： 为什么实验程序要用 PROT_NONE 页包夹观察区？

参考答案

两个原因：① vma_merge()（mm/mmap.c:863）会把属性相同且地址紧贴的相邻 VMA 合并成一个——观察工具自身的 fopen（内部 malloc→mmap 一个新 VMA）如果恰好紧贴观察区且 flags 相同，观察区的边界就被吞掉，maps 里的条数失真（实测踩过：VMA 条数=0）；② guard 的 PROT_NONE 与观察区的 RW flags 不同，merge 必然拒绝，观察窗口的边界被钉死。这本身就是 vma_merge 语义的活体演示。

49.3

解除映射：munmap()

源码核验：Linux v6.6 · mm/mmap.c（do_vmi_align_munmap():2452 · do_vmi_munmap():2618 · unmap_region 调用 :2575 · __vm_munmap():2918）· mm/memory.c（unmap_region():2322 同名内部声明 :79） 本章：TLPI 第 49 章 — Memory Mappings - 上一节：49.2 创建映射 mmap - 下一节：49.4 文件映射

本节讲什么

munmap 从进程地址空间删除一段 VMA 区间，顺带释放区间内该进程私有的物理页与页表项。三个灵魂问题：

  1. 删掉的是什么？（VMA 区间 + PTE + 私有页的引用——不是「擦除内存」）
  2. 域内的脏页去哪了？（MAP_SHARED 的脏页由内核回写机制异步落盘，munmap 不等待；要保证先 msync）
  3. 部分解除会发生什么？（VMA 分裂——一个 VMA 变两个，实测可见）
#include <sys/mman.h>
int munmap(void *addr, size_t length);
/* 返回 0 成功；-1 失败（EINVAL：addr 未页对齐） */

要点

行为规则

规则 说明
addr 必须页对齐 否则 EINVAL（内核不取整、不静默修正）
length 向上取整 同 mmap
区间内未映射的空洞 静默忽略——munmap 允许覆盖空洞+映射混合区间，全部拆掉
MAP_PRIVATE 修改 随私有页释放而丢弃（本来就不回文件）
MAP_SHARED 脏页 留在 page cache，回写线程异步落盘——munmap 返回 ≠ 数据在磁盘
访问已解除区 缺页 → SIGSEGV（该虚址已无 VMA 覆盖）
进程退出/exec 全部映射自动解除（mm_struct 销毁路径批量做）

⭐ VMA 分裂：munmap 中间一页的实测

映射 3 页 → munmap(p + pagesize, pagesize)（只拆中间页）：

实测（WSL Ubuntu，2026-09-05）：
  munmap 前 maps 条数=1
  munmap 后 maps 条数=2      ← [p, p+P) 和 [p+2P, p+3P) 两个独立 VMA
  Rss=4 kB                   ← 第 0 页写过仍驻留；中间页被释放

do_vmi_align_munmap():2452 的处理：区间两端若切在 VMA 中间，先 split 出「被删部分」——VMA 从 1 个变 3 个，中间的标记 detach 后销毁，剩下 2 个。map_count 也会随之变化（大量分裂受 vm.max_map_count 默认 65530 限制）。

内核路径（v6.6 坐标）

munmap(2)
 └─ __vm_munmap():2918
     └─ do_vmi_munmap():2618
         └─ do_vmi_align_munmap():2452
             ├─ vma 找齐：mas_walk 定位 start/end 所在 VMA
             ├─ 两端切割：start 落在 VMA 内部 → vma_split（VMA 分裂的来源）
             ├─ 摘除：受影响 VMA 标记 detached，从 maple tree 批量移除
             │    （mmap_write_lock 全程持有——munmap 是重操作）
             └─ unmap_region():2575
                 ├─ unmap_vmas：逐 PTE 拆映射
                 │    └─ zap_pte_range：清 PTE，私有页引用--（归零则释放回 buddy）
                 │       文件页：从 page cache 摘除引用（页本身通常留在 cache）
                 ├─ free_pgtables：整段页表页（PTE 页本身）释放
                 └─ tlb_finish_mmu：批量刷 TLB（惰性批次化，减少 IPI 次数）

TLB shootdown：munmap 拆掉 PTE 后，别的 CPU 核上可能还缓存着旧翻译——必须发 IPI 让所有核的 TLB 作废该区间。多核服务器上大区间 munmap 的开销主要在这批 IPI（这也是 THP 存在的理由之一：一个 2MB 页一条 TLB 项，shootdown 对象少 512 倍）。

msync 与 munmap 的先后

「保证 SHARED 脏页落盘再解除」的正确顺序：

msync(p, len, MS_SYNC);   /* 阻塞到磁盘写完 */
munmap(p, len);           /* 之后解除才安全 */

munmap 自身不提供任何落盘保证（脏页留在 page cache 交给回写线程）。崩溃窗口 = munmap 后、回写完成前。

HFT / 嵌入式关联

路线 要点
嵌入式 NOMMU 体系 munmap 粒度受限（只能整段、地址必须与原 mmap 完全一致）；RAM 紧张设备上「及时 munmap 大映射」比「等退出」更能压住碎片
HFT 行情缓冲换版时 munmap+重建会引发：①TLB shootdown IPI（打断其他忙轮询核！）；②新映射首触缺页——替代方案是 MADV_DONTNEED（只清页保 VMA，见 50.4）。换缓冲尽量避免 munmap

 *     [分裂后] VMA条数=2  Rss=4 kB

#include <stdio.h>
#include <stdlib.h>
#include <fcntl.h>
#include <sys/mman.h>
#include <unistd.h>

/* 统计 maps 中完全落在 [start,start+len) 内的 VMA 条数 */
static int maps_count(void *start, size_t len)
{
    FILE *fp = fopen("/proc/self/maps", "r");
    if (!fp) return -1;
    char line[300];
    unsigned long lo, hi, s = (unsigned long)start, e = s + (unsigned long)len;
    int n = 0;
    while (fgets(line, sizeof line, fp))
        if (sscanf(line, "%lx-%lx", &lo, &hi) == 2 && lo >= s && hi <= e)
            n++;
    fclose(fp);
    return n;
}

int main(void)
{
    long pagesz = sysconf(_SC_PAGESIZE);
    size_t P = (size_t)pagesz;

    /* PROT_NONE guard 包夹，防观察区被相邻 vma_merge 吞并 */
    char *raw = mmap(NULL, 5 * P, PROT_NONE, MAP_PRIVATE | MAP_ANONYMOUS, -1, 0);
    if (raw == MAP_FAILED) { perror("mmap raw"); return 1; }
    char *p = mmap(raw + P, 3 * P, PROT_READ | PROT_WRITE,
                   MAP_PRIVATE | MAP_ANONYMOUS | MAP_FIXED, -1, 0);
    if (p == MAP_FAILED) { perror("mmap"); return 1; }
    p[0] = 1;                                  /* 第 0 页驻留 */

    printf("munmap 前 VMA 条数=%d\n", maps_count(p, 3 * P));

    if (munmap(p + P, P) != 0) { perror("munmap"); return 1; }
    printf("munmap 中间页后 VMA 条数=%d（预期 2：VMA 分裂）\n",
           maps_count(p, 3 * P));

    /* 访问已解除的中间页 → SIGSEGV（此处不演示崩溃，只验证两端仍可访问） */
    p[0] = 2;
    p[2 * P] = 3;
    printf("两端页仍可访问：p[0]=%d p[2P]=%d\n", p[0], p[2 * (int)P]);

    munmap(p, P);
    munmap(p + 2 * P, P);
    munmap(raw, 5 * P);
    return 0;
}

题目 1（选择）： munmap(p + 100, 8192) 其中 p 页对齐、4KB 页。结果？

A. 成功，从 p+100 拆 8192 字节　B. EINVAL　C. 成功，但 addr 未对齐被静默取整　D. ENOMEM

题目 2（判断）： munmap 一段含未映射空洞的区间会失败。

参考答案

错误。munmap 对区间内的空洞静默忽略，只拆除实际存在的映射部分（成功返回 0）。这与 mlock（跳过空洞）宽松、与 msync（空洞导致最终返回 ENOMEM）严格的行为形成三方对比——同族 API 对空洞的策略并不统一，记忆点：munmap 最宽容。

题目 3（应用）： 为什么说「在忙轮询的多核交易机上，大区间 munmap 是全局税」？

参考答案

munmap 拆 PTE 后必须作废所有 CPU 上缓存的旧翻译（TLB shootdown）——内核向每个可能持有该区间翻译的核发 IPI，中断信号会打断那些核上正在跑的忙轮询线程（哪怕它们根本不碰这块内存），造成几十微秒的抖动，摊到所有核上。规避：① 用 MADV_DONTNEED 替代（清页但保 VMA，同样有 shootdown 但页数可控）；② 用 THP 减少 TLB 项数量；③ 在 RCU 风格的「换代窗口」（交易间隙）集中做地址空间手术。

49.4

文件映射

源码核验：Linux v6.6 · mm/memory.c（do_wp_page():3338 · wp_page_copy():3053 · wp_page_shared():3276 · copy_present_pte():923）· mm/filemap.c（page cache 查找 filemap_fault） 本章：TLPI 第 49 章 — Memory Mappings - 上一节：49.3 解除映射 munmap - 下一节：49.5 msync

本节讲什么

文件映射把页缓存（page cache）按需挂进进程虚址。三个灵魂问题：

  1. PRIVATE 读的是什么？（page cache 原页——私有只承诺写之后；实测 v1 曾在此翻车）
  2. 越过文件尾访问映射会怎样？（SIGBUS——映射合法（VMA 覆盖）但页无后备，与 SIGSEGV 的分界线）
  3. 修改对别人可见吗？（SHARED 立即可见：写的就是 page cache；PRIVATE 永不可见：COW 副本）

要点

PRIVATE vs SHARED 文件映射：内核路径速查

环节 MAP_PRIVATE 文件 MAP_SHARED 文件
读 缺页把 page cache 页直接映射进来（不复制！多进程读同一物理页） 同左——共享同一 page cache 页
首写 do_wp_page():3338 → 私有分支 → wp_page_copy():3053：复制 page cache 页内容到私有匿名页，此后与文件脱钩 do_wp_page():3369 → wp_page_shared():3276：原地改 PTE 可写 + 页标脏，写的直接就是 page cache 页
其他进程可见？ ❌（各写各的副本） ✅（page cache 即唯一真相）
写回磁盘？ ❌ 永不 ✅ 脏页由回写线程异步落盘（msync 可强制立即）
零页参与？ 仅"映区超出文件尾"的空白部分读挂零页 ❌

⭐ 可见性规则的精确表述（实测三连验证）

MAP_PRIVATE 是 copy-on-WRITE，不是 copy-on-ACCESS。

页的状态 别人改 page cache 后，我读到什么
我从未写过这页 别人的修改（我的 PTE 还指着 page cache 原页！）
我写过这页（任意一字节） 我的快照（整页已 COW，写一个字节就定格整页） 
实测（WSL Ubuntu，2026-09-05，v1→v2→v3 三版连环）：
  v1：fork 后子写 shar[0]='S'，父读 priv[0] → 'S'（不是预写的 'O'！）
      ← 推翻「PRIVATE=快照」的直觉：未写过的页跟随 page cache
  v2：父在 fork 前写 priv[1]='K'，fork 后子改 shar，父读 priv[0] → 'O'
      ← 意外：写 priv[1]（同页）把 priv[0] 也定格了——COW 粒度是页
  v3：对照组放不同页（页 0 不写 / 页 1 写 'K'）：
      priv[0]='S'（跟随）  priv[4096]='K'（快照）  ← 双双命中

越界访问的两种死法

信号 含义 触发条件
SIGSEGV 虚址无 VMA 覆盖（映射之外） 访问未映射区/已 munmap 区/prot 禁止的操作
SIGBUS 虚址有 VMA 但无后备页 文件映射越过 EOF（文件被 truncate）/ 磁盘坏块 / 稀疏洞未分配

实测：映射 2 页文件 → ftruncate 缩到 1 页 → 访问第 2 页 shar[4096] → 捕获 SIGBUS（缺页处理走到 filemap_fault 发现 offset ≥ i_size）。

fd 关闭与映射生命周期

mmap 后 close(fd) 映射仍有效（vm_area_struct.vm_file 持引用，实测验证见 49.2）。文件被删（unlink）也一样——页缓存与 inode 的引用还活着。杀掉映射的只有三件事：munmap / 进程退出 / exec。

HFT / 嵌入式关联

路线 要点
嵌入式 SHARED 只读映射共享固件/ROMFS 镜像省 RAM；fork 后 PRIVATE 首写 COW 共享只读段零拷贝（busybox 型多进程布局）
HFT SHARED 映射跨进程共享订单簿/行情零拷贝（写=写 page cache，无 syscall、无拷贝）；读多写少场景用 PRIVATE 借 COW 省内存——但记住可见性规则：策略进程「以为的快照」若从未写過，行情写入端一改它就读到新值——需要真快照时必须自己先触碰一页定格

代码示例


/* PRIVATE vs SHARED 可见性 + SIGBUS 实测（v3 最终版）
 * 实测（WSL Ubuntu，gcc -O2 -Wall -Wextra，2026-09-05）：
 *   步骤2 fork 后父观察:
 *     priv[0]='S'（页 0 未写→跟随 page cache）
 *     priv[4096]='K'（页 1 写过→整页 COW 快照）
 *     shar[0]='S' shar[4096]='T'（SHARED 全局可见）
 *   步骤3 文件截断到 1 页，访问映射第 2 页 shar[4096]……捕获 SIGBUS ✓
 */
#define _GNU_SOURCE
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <fcntl.h>
#include <errno.h>
#include <signal.h>
#include <setjmp.h>
#include <sys/mman.h>
#include <sys/wait.h>
#include <unistd.h>

static sigjmp_buf jb;
static void bus_handler(int sig) { (void)sig; siglongjmp(jb, 1); }

int main(void)
{
    long pagesz = sysconf(_SC_PAGESIZE);
    size_t P = (size_t)pagesz;
    size_t len = 2 * P;                    /* 映射 2 页 */

    int fd = open("/tmp/ch49_b.dat", O_RDWR | O_CREAT | O_TRUNC, 0644);
    if (fd < 0) { perror("open"); return 1; }
    if (write(fd, "ORIGORIG", 8) != 8) { perror("write"); return 1; }
    if (ftruncate(fd, (off_t)len) != 0) { perror("ftruncate"); return 1; }

    char *priv = mmap(NULL, len, PROT_READ | PROT_WRITE, MAP_PRIVATE, fd, 0);
    char *shar = mmap(NULL, len, PROT_READ | PROT_WRITE, MAP_SHARED,  fd, 0);
    if (priv == MAP_FAILED || shar == MAP_FAILED) { perror("mmap"); return 1; }

    /* 对照组放不同页：页 1 父 fork 前写 'K'（整页 COW 定格）；页 0 不写（跟随） */
    priv[P] = 'K';
    pid_t pid = fork();
    if (pid == 0) {
        priv[0] = 'P';                     /* 子 COW：只影响子进程副本 */
        shar[0] = 'S';                     /* 直接写 page cache：全局可见 */
        shar[P] = 'T';
        _exit(0);
    }
    wait(NULL);
    printf("fork 后父观察:\n");
    printf("  priv[0]='%c'（页 0 未写→跟随 page cache）\n", priv[0]);
    printf("  priv[%ld]='%c'（页 1 写过→整页 COW 快照）\n", (long)P, priv[P]);
    printf("  shar[0]='%c' shar[%ld]='%c'（SHARED 全局可见）\n",
           shar[0], (long)P, shar[P]);

    /* SIGBUS：文件截断到 1 页，访问第 2 页（越过 EOF 无后备） */
    if (ftruncate(fd, (off_t)P) != 0) { perror("ftruncate 2"); return 1; }
    signal(SIGBUS, bus_handler);
    printf("文件截断到 1 页，访问映射第 2 页……");
    fflush(stdout);
    if (sigsetjmp(jb, 1) == 0) {
        volatile char c = shar[P]; (void)c;
        printf("读取成功（异常！）\n");
    } else {
        printf("捕获 SIGBUS ✓（映射合法但页无后备）\n");
    }

    munmap(priv, len);
    munmap(shar, len);
    close(fd);
    unlink("/tmp/ch49_b.dat");
    return 0;
}

自测题

题目 1（选择）： 进程 A 以 MAP_PRIVATE 映射文件，从未写入页 0。进程 B 以 MAP_SHARED 映射同一文件并修改了文件页 0。A 读页 0 得到？

A. 文件原内容　B. B 修改后的内容　C. 全 0　D. 未定义

参考答案

B。A 的 PTE 仍指向 page cache 原页（从未 COW），B 的修改直接写在 page cache 页上，A 读到修改。MAP_PRIVATE 只在自己写的那一刻才定格快照。实测三连（v1）正是这个结论的出处。

题目 2（判断）： 文件映射越界访问（文件 4KB、映射 8KB、访问 offset 6KB）触发 SIGSEGV。

参考答案

错误，是 SIGBUS。虚址在 VMA 内（映射合法），但后备文件不够——缺页处理发现 offset ≥ i_size，无法提供数据页，发 SIGBUS。SIGSEGV 是「VMA 都不存在」，两者的判定层次不同（内存管理子系统 vs 文件层后备）。实测验证：截断到 1 页后访问第 2 页捕获 SIGBUS。

题目 3（应用）： 写一个「行情快照」策略进程，要求行情写入进程落盘的更新不影响已读到的行情，怎么设计？

参考答案

用 MAP_PRIVATE 映射，启动后先逐页写一遍（例如 memset 或拷贝到本地）把整段定格成 COW 快照——此后的读与 page cache 脱钩。注意 COW 粒度是页：只写过页内 1 字节，整页（4KB）都定格。代价：每页多一份物理内存拷贝。若嫌贵：只定格真正要读的页区间（稀疏触碰），或者用 msync+独立文件做版本化快照。

49.5

同步映射区：msync()

源码核验：Linux v6.6 · mm/msync.c（SYSCALL_DEFINE3(msync):32 · vfs_fsync_range() 调用 :96）· mm/page-writeback.c（脏页回写） 本章：TLPI 第 49 章 — Memory Mappings - 上一节：49.4 文件映射 - 下一节：49.6 mmap flags 补充细节

本节讲什么

msync 把 MAP_SHARED 映射的脏页刷回磁盘。三个灵魂问题：

  1. 三种模式差在哪？（MS_SYNC 阻塞落盘；MS_ASYNC 现代 Linux 里是 no-op；MS_INVALIDATE 丢干净页缓存）
  2. 什么时候真的需要它？（担心崩溃丢失时——别的进程的可见性从来不靠 msync，page cache 本来就是全局的）
  3. 它和 mlock 什么关系？（MS_INVALIDATE 作用在锁定区 → EBUSY，实测验证）
#include <sys/mman.h>
int msync(void *addr, size_t length, int flags);
/* flags: MS_SYNC | MS_ASYNC | MS_INVALIDATE（前两者互斥） */

要点

三种模式（含现代内核的真实行为）

flags POSIX 语义 Linux v6.6 真实行为（msync.c:32 逐行核验）
MS_SYNC 阻塞直到脏页写到磁盘 逐 VMA 调 vfs_fsync_range(file, fstart, fend, 1)（:96）——真同步
MS_ASYNC 调度后台回写，立即返回 no-op！内核 2.6.19 起自带脏页追踪，page cache 的脏页由回写线程自动管理，无需「提醒」
MS_INVALIDATE 丢弃 page cache 中的干净页 对 VM_LOCKED（mlock）区直接 EBUSY（:81-84）

⭐ MS_ASYNC 的历史：TLPI 写作年代（2010）MS_ASYNC 确实有「启动回写」语义；现代 man page 明确注明 "Since Linux 2.6.19, MS_ASYNC is in fact a no-op"。老代码里的 msync(p, len, MS_ASYNC) 现在只是心理安慰。

msync 真正解决什么

需求 靠什么
别的进程立刻读到我的修改 什么都不用做——SHARED 写的就是 page cache，天然全局可见
崩溃后数据还在磁盘 msync(MS_SYNC)——唯一保证
内存占用太大想丢干净页 msync(MS_INVALIDATE)（罕见）

内核路径（v6.6 实测核验）

msync(2) → SYSCALL_DEFINE3(msync)            mm/msync.c:32
 ├─ flags 校验（:39-46）：
 │    未知标志 → EINVAL；MS_SYNC+MS_ASYNC 同传 → EINVAL；addr 未页对齐 → EINVAL
 ├─ 遍历 [start,end) 的每个 VMA：
 │    ├─ 空洞区间：跳过，但记 unmapped_error（最终返回 ENOMEM）
 │    ├─ MS_INVALIDATE && VM_LOCKED → EBUSY（:81-84，实测验证）
 │    └─ MS_SYNC && file && VM_SHARED：
 │         vfs_fsync_range(file, fstart, fend, 1)   :96
 │         （同步等磁盘——所以 MS_SYNC 的延迟≈磁盘 fsync）
 └─ MAP_PRIVATE 映射：循环体里 file 分支不满足 → 直接滑过（无操作）

要点：PRIVATE 映射调 msync 无任何效果（不报错，白调）——msync 只对 VM_SHARED + vm_file 的 VMA 有意义。

错误码速查

errno 条件 实测
EINVAL flags 非法 / SYNC+ASYNC 同传 / addr 未对齐 ✓（22）
ENOMEM 区间含未映射空洞（结束后统一返回） —
EBUSY MS_INVALIDATE 遇 mlock 区 ✓（16）

HFT / 嵌入式关联

路线 要点
嵌入式 掉电保护：关键配置/日志写 SHARED 映射后 MS_SYNC 强制落 flash（eMMC/NAND 的 fsync 含 FTL 层刷写，毫秒级，别放热路径）；MS_INVALIDATE 做外设缓存一致性冲洗（罕见但嵌入式 debug 用过）
HFT 热路径永不碰 MS_SYNC（一次 = 一次真 fsync，毫秒级）；审计日志缓冲用单独线程攒批刷；可见性需求是伪需求（page cache 天然共享），只有崩溃持久性才需要 msync——分清两者能省掉一半无谓调用

代码示例


/* msync 语义实测：EINVAL / EBUSY 两个错误码（完整可跑版）
 * 实测（WSL Ubuntu，gcc -O2 -Wall -Wextra，2026-09-05）：
 *   步骤4 msync(MS_SYNC|MS_ASYNC) = -1 errno=22(Invalid argument)
 *   步骤5 mlock 区上 msync(MS_INVALIDATE) = -1 errno=16(Device or resource busy)
 */
#define _GNU_SOURCE
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <fcntl.h>
#include <errno.h>
#include <sys/mman.h>
#include <unistd.h>

int main(void)
{
    long pagesz = sysconf(_SC_PAGESIZE);
    size_t P = (size_t)pagesz;

    int fd = open("/tmp/ch49_sync.dat", O_RDWR | O_CREAT | O_TRUNC, 0644);
    if (fd < 0) { perror("open"); return 1; }
    if (ftruncate(fd, (off_t)P) != 0) { perror("ftruncate"); return 1; }

    char *shar = mmap(NULL, P, PROT_READ | PROT_WRITE, MAP_SHARED, fd, 0);
    if (shar == MAP_FAILED) { perror("mmap"); return 1; }
    strcpy(shar, "dirty data");

    /* 1. MS_SYNC：真同步落盘（阻塞到磁盘完成） */
    if (msync(shar, P, MS_SYNC) != 0) perror("msync MS_SYNC");
    printf("MS_SYNC 完成：脏页已落盘\n");

    /* 2. 互斥标志 → EINVAL */
    errno = 0;
    int r = msync(shar, P, MS_SYNC | MS_ASYNC);
    printf("msync(MS_SYNC|MS_ASYNC) = %d errno=%d(%s)，预期 EINVAL\n",
           r, errno, r ? strerror(errno) : "OK");

    /* 3. mlock 区 + MS_INVALIDATE → EBUSY */
    char *lk = mmap(NULL, P, PROT_READ | PROT_WRITE,
                    MAP_SHARED | MAP_ANONYMOUS, -1, 0);
    if (lk == MAP_FAILED) { perror("mmap lk"); return 1; }
    lk[0] = 1;
    if (mlock(lk, P) != 0) { perror("mlock"); return 1; }
    errno = 0;
    r = msync(lk, P, MS_INVALIDATE);
    printf("mlock 区上 msync(MS_INVALIDATE) = %d errno=%d(%s)，预期 EBUSY\n",
           r, errno, r ? strerror(errno) : "OK");

    munlock(lk, P);
    munmap(lk, P);
    munmap(shar, P);
    close(fd);
    unlink("/tmp/ch49_sync.dat");
    return 0;
}

题目 1（选择）： 进程 A MAP_SHARED 映射写入后没有调用任何 msync，进程 B 映射同一文件读，能看到修改吗？

A. 不能，必须先 msync　B. 能，立即看到　C. 能，但延迟不定　D. 只有 MS_ASYNC 后能看到

参考答案

错误。自 2.6.19 起 MS_ASYNC 是 no-op——内核的脏页追踪 + 平衡回写线程已全自动，MS_ASYNC 的「提醒」职责被彻底取代。man 2 msync 的 NOTES 明确写了这一点。需要确定性落盘只有 MS_SYNC。

题目 3（应用）： 交易程序把成交记录写进 MAP_SHARED 映射的日志文件，要求「进程崩溃不丢、机器断电最多丢 1 秒」，怎么设计刷盘节奏？

参考答案

独立刷盘线程每 ≤1s 调一次 msync(区间, MS_SYNC)（对增量区间，避免整段重扫）；写线程永不阻塞在 fsync。注意三点：① MS_SYNC 的延迟 ≈ 磁盘 fsync（HDD 毫秒级/NVMe 几十 µs~百 µs），必须在旁路线程；② 关键字段用定长记录 + 序号，崩溃恢复时容忍半条记录；③ 别忘了 fsync 日志文件本身的新增块（ftruncate/pwrite 的元数据也走 fsync 路径，vfs_fsync_range 已覆盖）。

49.6

mmap() flags 参数补充细节

源码核验：Linux v6.6 · uapi/asm-generic/mman-common.h（MAP_SHARED:0x01 · MAP_PRIVATE:0x02 · MAP_FIXED:0x10 · MAP_FIXED_NOREPLACE:0x100000:31）· mm/mmap.c（do_mmap():1203 flags 校验分支） 本章：TLPI 第 49 章 — Memory Mappings - 上一节：49.5 msync - 下一节：49.7 匿名映射

本节讲什么

flags 参数的正式语义细节：SHARED/PRIVATE 的修改可见性矩阵（SUSv3 规定 + 实测验证）、MAP_TYPE 位域结构、fork 的继承规则。三个灵魂问题：

  1. 「PRIVATE = 私有」到底私有什么？（只私有自己的写——读跟随后备，实测三连见 49.4）
  2. SHARED/PRIVATE 在 flags 里占什么位置？（低 4 位 MAP_TYPE 掩码，其余标志在上层位叠加）
  3. fork 之后呢？（两类映射都继承，语义原样传递——这是父子 IPC 的根基）

要点

修改可见性矩阵（SUSv3 规定 + v6.6 实测）

映射类型 修改者 谁能看到修改 修改是否到达底层文件
MAP_SHARED 文件 本进程 所有映射同一文件区域的进程 + read() 读者 ✅（异步回写 / msync 强制）
MAP_PRIVATE 文件 本进程 只有自己（写过之后，COW 页） ❌ 永不
MAP_SHARED 文件 其他进程（经 SHARED 映射） 本进程能看到（即使本进程是 PRIVATE 映射——但仅限未写过的页） —
MAP_SHARED 文件 其他进程（经 write()） 同上——未写过的 PRIVATE 页能读到 —

⭐ 加粗行的矩阵正是 49.4 实测三连 的结论：PRIVATE 是 copy-on-write，未写过的页始终跟随 page cache。SUSv3 只规定了行为，实测给出了机制层面的原因（PTE 仍指向共享页）。

MAP_TYPE：flags 的位域结构

/* uapi/asm-generic/mman-common.h */
#define MAP_SHARED    0x01     /* 低 4 位是「映射类型」域 */
#define MAP_PRIVATE   0x02
#define MAP_TYPE      0x0f     /* 掩码：flags & MAP_TYPE 取类型 */
/* 高层位是行为修饰（可叠加）： */
#define MAP_FIXED         0x10
#define MAP_ANONYMOUS    0x20
#define MAP_GROWSDOWN    0x0100
#define MAP_DENYWRITE    0x0800
#define MAP_EXECUTABLE  0x1000
#define MAP_LOCKED      0x2000
#define MAP_NORESERVE   0x4000
#define MAP_POPULATE   0x008000     /* :26 */
#define MAP_STACK      0x020000     /* :28 */
#define MAP_HUGETLB    0x040000     /* :29 */
#define MAP_FIXED_NOREPLACE 0x100000  /* :31 */

类型域与修饰域正交：MAP_SHARED|MAP_ANONYMOUS|MAP_POPULATE = 类型(01) + 修饰(20|8000)。flags 校验顺序：do_mmap():1203 先取 flags & MAP_TYPE 判断 SHARED/PRIVATE（既无 SHARED 也无 PRIVATE → EINVAL），再逐个处理修饰标志。

各修饰标志一句话

标志 语义 详见
MAP_FIXED / MAP_FIXED_NOREPLACE 固定地址（覆盖/拒绝覆盖） 49.10
MAP_ANONYMOUS 无后备文件，缺页走零页/COW 49.7
MAP_NORESERVE 不预留 swap（overcommit） 49.9
MAP_LOCKED 映射即锁定（等价 mmap+mlock 一步） 50.2
MAP_POPULATE 映射即预缺页（读写前页表已建好） 本节下方
MAP_STACK 告诉内核「这是栈」（仅影响布局启发，不做强制） —
MAP_HUGETLB 用预留大页池（hugetlbfs） 06-linux-mm

MAP_POPULATE：预缺页的两种姿势

/* 姿势 1：mmap 时带标志 */
p = mmap(NULL, len, RW, MAP_PRIVATE|MAP_ANONYMOUS|MAP_POPULATE, -1, 0);
/* 姿势 2：mmap 后 madvise（等价） */
p = mmap(NULL, len, RW, MAP_PRIVATE|MAP_ANONYMOUS, -1, 0);
madvise(p, len, MADV_POPULATE_WRITE);      /* 5.14+，读用 POPULATE_READ */

把「N 页 × 首触缺页（各 µs 级）」从运行时挪到启动时。注意 POPULATE 不等于 mlock：页填了但不锁，内存压力下照样被换出——延迟敏感场景 POPULATE+mlock 配套用。

fork 的继承规则

映射 fork 后子进程 写的语义
MAP_PRIVATE（任意） 继承同一映射 父子各自 COW（同 49.4 矩阵）
MAP_SHARED 文件 继承，与父（及所有映射者）共享 page cache 立即互相可见
MAP_SHARED MAP_ANONYMOUS 继承，父子共享同一物理页

exec 则相反：所有映射销毁（新程序映像重建地址空间）。

HFT / 嵌入式关联

路线 要点
嵌入式 MAP_POPULATE 消除上电后首触抖动（工控响应时间预算友好）；MAP_STACK 对自定义线程栈布局是「礼貌提示」——NOMMU 上才真正影响分配
HFT 启动序标配 MAP_POPULATE（或 mlockall 顺带的填充）——把 16384 页 × 1µs 的首触税从交易时段挪到 init；MAP_LOCKED=mmap+mlock 原子化（免两步间隙的窗口）；可见性矩阵提醒：策略读行情用 SHARED 映射（实时跟随）或主动触碰过的 PRIVATE（确定性快照），别用「未写过的 PRIVATE」——那是最阴险的中间态：测试环境像快照（没人并发写），生产环境像实时（行情不断改）

代码示例


/* MAP_POPULATE vs 惰性映射：首触缺页对比
 * 实测（WSL Ubuntu，gcc -O2 -Wall -Wextra，2026-09-05）：
 *   lazy     映射后：Rss=0 kB（画区不填页）
 *   populate 映射后：Rss=16384 kB（16MB 全部预填）
 *   lazy     区 memset 首触 15 ms（含 4096 次缺页）
 *   populate 区 memset      1 ms（无缺页，纯写内存）——15 倍差
 */
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <sys/mman.h>
#include <time.h>
#include <unistd.h>

static long smaps_rss(void *addr)
{
    FILE *fp = fopen("/proc/self/smaps", "r");
    if (!fp) return -1;
    char line[300];
    unsigned long lo, hi, a = (unsigned long)addr;
    long rss = -1;
    int in_target = 0;
    while (fgets(line, sizeof line, fp)) {
        if (sscanf(line, "%lx-%lx", &lo, &hi) == 2)
            in_target = (a >= lo && a < hi);
        else if (in_target && strncmp(line, "Rss:", 4) == 0) {
            sscanf(line + 4, "%ld", &rss);
            break;
        }
    }
    fclose(fp);
    return rss;
}

int main(void)
{
    size_t len = 16UL << 20;                 /* 16MB = 4096 页 */

    char *lazy = mmap(NULL, len, PROT_READ | PROT_WRITE,
                      MAP_PRIVATE | MAP_ANONYMOUS, -1, 0);
    if (lazy == MAP_FAILED) { perror("mmap lazy"); return 1; }
    printf("lazy     映射后 Rss=%ld kB（画区，0 物理页）\n", smaps_rss(lazy));

    char *pop = mmap(NULL, len, PROT_READ | PROT_WRITE,
                     MAP_PRIVATE | MAP_ANONYMOUS | MAP_POPULATE, -1, 0);
    if (pop == MAP_FAILED) { perror("mmap populate"); return 1; }
    printf("populate 映射后 Rss=%ld kB（全部预填，写脏即真页）\n",
           smaps_rss(pop));

    /* 用时间对比首触：lazy 区首次 memset 才付税 */
    struct timespec t0, t1;
    clock_gettime(CLOCK_MONOTONIC, &t0);
    memset(lazy, 1, len);
    clock_gettime(CLOCK_MONOTONIC, &t1);
    printf("lazy 区 memset 首触耗时 %ld ms（含 4096 次缺页）\n",
           (t1.tv_sec - t0.tv_sec) * 1000 + (t1.tv_nsec - t0.tv_nsec) / 1000000);

    clock_gettime(CLOCK_MONOTONIC, &t0);
    memset(pop, 1, len);
    clock_gettime(CLOCK_MONOTONIC, &t1);
    printf("populate 区 memset 耗时 %ld ms（无缺页，纯写内存）\n",
           (t1.tv_sec - t0.tv_sec) * 1000 + (t1.tv_nsec - t0.tv_nsec) / 1000000);

    munmap(lazy, len);
    munmap(pop, len);
    return 0;
}

题目 1（选择）： flags & MAP_TYPE 的作用？

A. 取出 SHARED/PRIVATE 类型位　B. 校验 flags 合法性　C. 清除修饰标志　D. 区分匿名/文件映射

参考答案

A。MAP_TYPE=0x0f 掩出低 4 位的映射类型域（SHARED=0x01/PRIVATE=0x02）；匿名与否由 MAP_ANONYMOUS（0x20）单独表达，与类型域正交——四种组合（文件/匿名 × SHARED/PRIVATE）就是 49.1 四大组合。

题目 2（判断）： MAP_POPULATE 之后这些页被锁定，不会被换出。

参考答案

错误。POPULATE 只做预缺页（当下把页表建满、页填进来），不设 VM_LOCKED——内存压力下页照样进入回收/换出路径。要「永不换出」必须 mlock/MAP_LOCKED。两者是正交维度：POPULATE 管「现在有没有」，LOCKED 管「将来走不走」。

题目 3（应用）： 策略进程用 MAP_PRIVATE 映射行情文件，测试回测全对、实盘偶发「读到未来数据」式异常，从本节矩阵出发定位问题。

参考答案

回测时无并发写入者，PRIVATE 未写过的页读到的永远是「当前值」= 事实快照，行为正确；实盘行情进程持续改 page cache，策略的 PRIVATE 页未写过的部分跟随实时变化——同一个虚址两次读可能不同，回测里不存在这种竞态。修复：① 改用 SHARED 映射 + 显式双缓冲版本号（承认实时性，用序号 fence 一致性）；② 或初始化时主动触碰整段（memset 定格 COW 快照）+ 定期显式刷新重定格。根源是误把 copy-on-write 当 copy-on-access。

匿名映射

源码核验：Linux v6.6 · mm/memory.c（do_anonymous_page():4067 · zero_pfn:164 · wp_page_copy():3053 · do_wp_page():3338 · copy_present_pte():923）· mm/shmem.c（SGP_READ hole 语义 :1993 · 零页映射 :2906）深挖见 06-linux-mm 本章：TLPI 第 49 章 — 内存映射 - 上一节：49.6 其他 mmap 标志 - 下一节：49.8 mremap

本节讲什么

  1. 匿名映射怎么用（MAP_ANONYMOUS vs /dev/zero，PRIVATE vs SHARED）？

*shared = 0;
if (fork() == 0) {
    *shared = 42;  /* 子进程写 */
    _exit(0);
}

零页与 COW 的内核真相

零页是什么

属性 值
本体 ZERO_PAGE(0)——内核镜像里一个特殊只读物理页，内容全 0
符号 zero_pfn（mm/memory.c:164），init_zero_pfn():172 在启动早期把它的 PFN 存进全局变量
磁盘后备 无。开机就在内存，永不换出
共享范围 全局所有进程——谁的匿名私有页没被写过，PTE 就指它
归属 不属于任何进程：RSS 都不计入它（后面实测验证）

读路径：挂零页

do_anonymous_page()（mm/memory.c:4067）对「读触发的缺页」：

/* Use the zero-page for reads */
if (!(vmf->flags & FAULT_FLAG_WRITE) &&
        !mm_forbids_zeropage(vma->vm_mm)) {          // :4086
        entry = pte_mkspecial(pfn_pte(my_zero_pfn(vmf->address),
                        vma->vm_page_prot));          // :4088  ← PTE 指向零页
        ...
        goto setpte;                                  // 只装 PTE，不分配任何页
}

关键：分配的只有页表项，一页物理内存都没给你。之后读这页永远读零页的 0，MMU 不报错——PTE 存在、有映射，只是指向只读共享页。pte_mkspecial 标记它"特殊"，vm_normal_page() 会跳过它（rmap/回收不认识零页）。

顺带：mm_forbids_zeropage() 为真的场景是 KVM 等——虚拟机脏页追踪要求每页可追踪，零页共享会破坏语义，此时读也实分页。

写路径：直接分配清零新页（⚠ 精确说法）

写触发的缺页不走上面那个 if，直接（:4102-4104）：

/* Allocate our own private page. */
if (unlikely(anon_vma_prepare(vma))) ...
folio = vma_alloc_zeroed_movable_folio(vma, vmf->address);   // :4104
...
entry = mk_pte(&folio->page, vma->vm_page_prot);
if (vma->vm_flags & VM_WRITE)
        entry = pte_mkwrite(pte_mkdirty(entry), vma);        // :4121 可写+脏

所以「COW 复制零页」的精确版本是：

首写匿名私有页：分配一个全新清零物理页（无 memcpy），把 PTE 从零页改指它。逻辑上是"写时复制"，物理上零页根本没被复制——目标本来就是全 0，分配清零页等价且更省（清零有硬件优化的 clear_page，比拷贝快）。

真发生"从零页复制"判定的是 wp_page_copy():3072——但那是 fork 之后的场景：父子共指零页 + 双方 PTE 均被写保护，一方写时 is_zero_pfn(pte_pfn(vmf->orig_pte)) 命中，同样跳过拷贝直接清零新页。

fork 的 COW：copy_present_pte 双向写保护

fork 复制页表时（copy_present_pte():923）：

/*
 * If it's a COW mapping, write protect it both
 * in the parent and the child
 */
if (is_cow_mapping(vm_flags) && pte_write(pte)) {      // :960
        ptep_set_wrprotect(src_mm, addr, src_pte);     // 父也写保护！
        pte = pte_wrprotect(pte);                      // 子写保护
}

三个要点：

  1. 父进程的 PTE 也被写成只读——COW 是父子双方同时进入只读态，谁先写谁触发 do_wp_page()。
  2. is_cow_mapping() 即 !(flags & (VM_SHARED | VM_MAYSHARE))——MAP_SHARED 映射完全绕过 COW：父子直接共指同一物理页，谁写都不复制（这正是"共享"语义的内核实现，也解释了上面对比表最后一列）。
  3. 写触发后的分流在 do_wp_page():3338： - :3369 VM_SHARED|VM_MAYSHARE → wp_page_shared():3276——原地改 PTE 可写 + 标脏，不复制； - 私有映射 → 若该页确认独占（fork 后对方已写走/未共享）→ wp_page_reuse():3009 原地复用；真共享着 → wp_page_copy():3053 分配新页 + 复制内容（源是零页则免拷贝）。

匿名 SHARED：读 hole 也有零页捷径，写才实分页

do_anonymous_page():4076 开头一行挡死零页捷径：

if (vma->vm_flags & VM_SHARED)
        return VM_FAULT_SIGBUS;    // 匿名共享映射不走这条路径

匿名 MAP_SHARED 的 VMA 由 shmem（tmpfs）接管。但「共享必须实分页」只对了一半——shmem 对读 hole 同样有零页捷径（mm/shmem.c:1993 注释原文）：

/*
 * SGP_READ: succeed on hole, with NULL folio, letting caller zero.
 * SGP_NOALLOC: fail on hole, with NULL folio, letting caller fail.
 */

读 fault 拿到 NULL folio 后映射全局零页（shmem.c:2906 .page = ZERO_PAGE(0)）。这在语义上完全成立：hole 里还没人写过，读出来必然全 0，指零页和指一个清零页无法区分。一旦有任何一方写（SGP_WRITE），shmem 才分配真页放进 page cache——此后所有进程的读 fault 都命中真页，共享语义由此建立。

所以精确结论是：零页优化覆盖到 shmem 读 hole；共享的“实分页”门槛只卡在写上。下面 demo 的 B 段实测验证：SHARED 匿名全量读 RSS 不涨，写一半 RSS +128MB。

malloc 与 overcommit 的会计真相

  • malloc 大块（glibc 阈值默认 128KB）→ mmap(MAP_PRIVATE|MAP_ANONYMOUS) → 仅仅登记了 VMA，物理账上一页未付；
  • RSS 不涨、/proc/meminfo 的 Committed_AS 也不按全量记（默认 overcommit heuristic 只对"明显超过 RAM+swap"说不）；
  • 物理页分配被推迟到每次首写的那一下缺页——所以"申请 1TB 成功"和"物理内存耗尽 OOM"可以相隔任意久。

HFT / 嵌入式关联

路线 要点
嵌入式 匿名共享映射是父子进程 IPC 最简单方式；只读大数组让零页兜底，省下整个数组的 RAM
HFT MAP_SHARED\|MAP_ANONYMOUS 用于父子共享行情数据，零拷贝；预分配 arena 但只写热区——冷区一直由零页"免费"占位，RSS 反映真实热区
HFT 懒分配=确定性敌人：首写延迟里藏着缺页+清零+可能的内存回收，热路径上要么启动时 mlock+全量触碰，要么接受首次访问的毛刺

代码示例

/* zero_page_demo.c — Ch49.7：零页 vs 实分页的 RSS 实测
 * A. MAP_PRIVATE 匿名：映射后 / 全量读后 / 写一半后 三阶段观测
 * B. MAP_SHARED 匿名（shmem）：读不占 RSS（SGP_READ hole 零页）vs 写才实分页
 * 编译：gcc -O2 -Wall -Wextra -o zero_page_demo zero_page_demo.c
 */
#define _GNU_SOURCE
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <sys/mman.h>
#include <unistd.h>

#define MB (1024UL * 1024)
#define SIZE (256UL * MB)          /* 256MB，页大小 4KB → 65536 页 */

/* /proc/self/statm 第 2 列 = resident（单位：页） */
static long rss_pages(void)
{
    long size, resident;
    FILE *f = fopen("/proc/self/statm", "r");
    if (!f) return -1;
    if (fscanf(f, "%ld %ld", &size, &resident) != 2) resident = -1;
    fclose(f);
    return resident;
}

static void report(const char *tag, long base)
{
    long r = rss_pages();
    long ps = sysconf(_SC_PAGESIZE);
    printf("  %-28s RSS = %7.1f MB（相对 %+.1f MB）\n",
           tag, (double)r * ps / MB, (double)(r - base) * ps / MB);
}

int main(void)
{
    long ps = sysconf(_SC_PAGESIZE);
    printf("页大小 %ld B，映射 %lu MB\n", ps, SIZE / MB);

    /* ========== A. MAP_PRIVATE 匿名：零页三阶段 ========== */
    char *p = mmap(NULL, SIZE, PROT_READ | PROT_WRITE,
                   MAP_PRIVATE | MAP_ANONYMOUS, -1, 0);
    if (p == MAP_FAILED) { perror("mmap"); return 1; }
    long base = rss_pages();
    report("A1 映射完成（未触碰）", base);

    /* 全量只读扫描：每页都读 1 字节 → 65536 次读缺页全挂零页 */
    for (size_t i = 0; i < SIZE; i += (size_t)ps)
        if (p[i] != 0) { printf("非零?! 破坏假设\n"); return 1; }
    report("A2 全量读一遍后", base);

    /* 写前一半：32768 次写缺页 → 32768 个清零实页 */
    memset(p, 0x5A, SIZE / 2);
    report("A3 写前一半后", base);

    printf("  解读：读 256MB → RSS 纹丝不动（零页共享不计入）；"
           "写 128MB → RSS 恰好 +128MB\n");
    munmap(p, SIZE);

    /* ========== B. MAP_SHARED 匿名：shmem 对照组 ========== */
    char *s = mmap(NULL, SIZE, PROT_READ | PROT_WRITE,
                   MAP_SHARED | MAP_ANONYMOUS, -1, 0);
    if (s == MAP_FAILED) { perror("mmap shared"); return 1; }
    long base2 = rss_pages();
    for (size_t i = 0; i < SIZE; i += (size_t)ps)
        (void)s[i];               /* 只读不写 */
    report("B1 SHARED 全量读一遍后", base2);
    memset(s, 0x5A, SIZE / 2);    /* 写前一半：shmem 实分页 */
    report("B2 SHARED 写前一半后", base2);
    munmap(s, SIZE);
    return 0;
}

页大小 4096 B，映射 256 MB
  A1 映射完成（未触碰）        RSS =     1.4 MB（相对 +0.1 MB）
  A2 全量读一遍后              RSS =     1.4 MB（相对 +0.1 MB）
  A3 写前一半后                RSS =   129.4 MB（相对 +128.1 MB）
  解读：读 256MB → RSS 纹丝不动（零页共享不计入）；写 128MB → RSS 恰好 +128MB

自测题

题目 1（概念）： mmap 返回成功、也读到了全 0，物理内存分配了吗？

参考答案

没有（就这批被读过的页而言）。读路径的缺页由 do_anonymous_page():4086 用零页满足：只装 PTE，不分配物理页。零页是内核全局共享的只读页，连 RSS 都不计入。真正的物理页分配推迟到首写。

题目 2（精确辨析）： 「首写匿名私有页时，内核分配新页并复制零页内容」——这句话哪里不精确？

参考答案

do_anonymous_page() 写路径（:4104）直接调 vma_alloc_zeroed_movable_folio() 分配清零新页，没有发生"从零页复制"的 memcpy——目标本来就是全 0，清零等价且更快。"从零页复制"的判定只出现在 fork 之后的 wp_page_copy():3072（is_zero_pfn 特判），且那里同样跳过拷贝。逻辑上叫 COW，物理上是"换页+清零"。

题目 3（fork）： fork 后父子对匿名私有页各写一次，物理页从 1 页变成几页？谁的 PTE 先失去写权限？

参考答案

2 页。copy_present_pte():960 在 fork 复制页表时就把父子双方的 PTE 都写保护（ptep_set_wrprotect 父 + pte_wrprotect 子）；先写的一方走 wp_page_copy() 分配自己的新页，后写的一方此时独占原页，走 wp_page_reuse() 原地改回可写——所以是 1(共享) → 2(各一份)。

题目 4（对比）： 匿名 MAP_SHARED 映射首读分配物理页吗？什么时候才分配？

参考答案

首读不分配。do_anonymous_page():4076 开头 VM_SHARED → SIGBUS 挡死零页捷径，匿名共享 VMA 由 shmem 接管；但 shmem 对读 hole 也有零页捷径（shmem.c:1993「SGP_READ: succeed on hole, with NULL folio, letting caller zero」）——读 fault 拿到 NULL folio 后映射全局零页。写 fault（SGP_WRITE）才分配真页放进 page cache，此后所有映射者的读都命中真页，共享语义建立。demo 实测：SHARED 匿名全量读 RSS +0.0MB，写一半后 +128.0MB。

题目 5（面试高频）： 「malloc 很大内存返回成功但物理内存没分配」完整链条是什么？三个环节各对应哪个内核机制？

参考答案

① glibc 大块（≥128KB）走 mmap(MAP_PRIVATE|MAP_ANONYMOUS)——只登记 VMA；② 读触发的缺页由零页满足（do_anonymous_page 读路径）——RSS 不涨；③ 首写才分配清零实页（写路径）。overcommit 默认策略（heuristic）允许 VMA 总量超 RAM+swap，所以"申请成功"与"物理耗尽 OOM"可以相隔任意久。

49.8

重新映射：mremap()

源码核验：Linux v6.6 · mm/mremap.c（take_rmap_locks():105 · move_vma():583 · vma_to_resize():746 · mremap_to():800 · SYSCALL_DEFINE5(mremap):908 · MREMAP_DONTUNMAP 处理 :609/:770/:857） 本章：TLPI 第 49 章 — Memory Mappings - 上一节：49.7 匿名映射 - 下一节：49.9 MAP_NORESERVE 与 overcommit

本节讲什么

mremap 是 Linux 特有的「映射版 realloc」：原地扩/缩映射，必要时整段搬家。三个灵魂问题：

  1. 原地扩展的条件？（紧邻高地址方向有够大的空洞——没空洞时无 MREMAP_MAYMOVE 直接 ENOMEM）
  2. 搬家时数据怎么办？（PTE 级搬家：物理页不动，只把页表项搬到新虚址——比 memcpy 快一个数量级）
  3. MREMAP_DONTUNMAP 是什么？（5.13+ 新玩具：搬走 PTE 但旧虚址留空壳，读回零页）
#define _GNU_SOURCE
#include <sys/mman.h>
void *mremap(void *old_address, size_t old_size, size_t new_size,
             int flags, /* void *new_address (MREMAP_FIXED 时) */);
/* flags: MREMAP_MAYMOVE | MREMAP_FIXED | MREMAP_DONTUNMAP(4, Linux 5.13+) */

要点

三种操作语义

操作 条件 结果
原地扩展 [old_end, old_end + (new-old)) 是空洞 地址不变，VMA 长大
搬家扩展 原地不行 + 带 MREMAP_MAYMOVE 新地址（move_vma():583：PTE 搬迁），数据逻辑保留
收缩 new < old 地址不变，尾部 munmap（脏 SHARED 页照常回写）
DONTUNMAP 匿名映射 + MAYMOVE + new==old 新地址得 PTE，旧地址 VMA 保留但读回零页

原地失败且无 MAYMOVE → MAP_FAILED + ENOMEM（实测验证：紧贴阻挡下 errno=12）。

错误码表（vma_to_resize():746 分支对照）

errno 分支（v6.6 坐标）
EFAULT old 区间不在任何 VMA 内 / old_len 超出 VMA 尾（:754/:775）
EINVAL DONTUNMAP 用在 VM_DONTEXPAND/VM_PFNMAP 上（:770）等
EAGAIN 扩张会超 RLIMIT_MEMLOCK（mlock_future_ok :790）
ENOMEM 无 MAYMOVE 且原地不行 / map_count 超限 / swap 预留不足（VM_ACCOUNT :793）

⭐ 内核路径：PTE 级搬家（为什么快）

mremap(2) → SYSCALL_DEFINE5(mremap)         mm/mremap.c:908
 ├─ vma_to_resize():746                     定位并校验 old VMA
 ├─ new == old：收缩路径 → vma_shrink（尾部 munmap）
 └─ mremap_to():800
     └─ move_vma():583
         ├─ take_rmap_locks():105           锁 anon_vma/i_mmap（反向映射一致性）
         ├─ move_page_tables                【核心】逐 PMD 批量把 PTE 从旧虚址
         │    摘下挂到新虚址——物理页不动！
         ├─ 旧 VMA 区间 munmap
         └─ （DONTUNMAP）旧 VMA 保留、PTE 不搬走的部分清空 → 零页

物理页一个都没动，动的只是页表。4KB 页的 PTE 搬运是内存内的位操作；这正是 realloc 大块内部走 mremap 的原因——扩 128MB→256MB 若靠 memcpy 要搬 128GB/s 级带宽好几毫秒，mremap 原地扩展是零拷贝。

MREMAP_DONTUNMAP 的语义（实测验证）

实测（WSL Ubuntu，2026-09-05）：
  DONTUNMAP: 旧 0x75800c513000 → 新 0x75800c511000
    新地址 data="DATA"           ← PTE 搬到新地址，内容完整
    旧地址 d[0]=0x00             ← 旧地址变空壳，读回零填充

用途：无锁迁移缓冲（读者还握着旧指针的窗口期内旧地址合法可读——只是读到 0）、构建 userspace 双视图。限制：仅匿名映射（文件映射/PFNMAP 拒绝）、必须 MAYMOVE、new_size 必须 == old_size。

与 glibc realloc 的关系

glibc 对大块（≥ mmap 阈值，默认 128KB，动态调整）的 malloc 走 mmap；对应 realloc 走 mremap(MREMAP_MAYMOVE)——这是「realloc 大块几乎免费」的底层真相。小块在堆内（brk 区）realloc 仍可能 memcpy。

HFT / 嵌入式关联

路线 要点
嵌入式 环形缓冲按流量扩容：mremap 原地扩（PTE 级）避免复制吞吐缓冲；NOMMU 无 mremap（无页表可搬）
HFT 订单池动态扩容用 mremap(MREMAP_MAYMOVE)——迁移是页表操作不是数据拷贝，128MB 池扩容在 µs 量级；坑：搬家后地址变了，所有缓存了旧指针的代码（对象池 freelist、硬件 DMA 描述符）必须失效重建——所以宁可 mmap 预留大虚拟区 + MAP_NORESERVE + 按需 populate，也不让地址漂移

代码示例


/* mremap 原地/受阻/搬家/收缩/DONTUNMAP 全景实测
 * 实测（WSL Ubuntu，gcc -O2 -Wall -Wextra，2026-09-05）：
 *   步骤1 原地扩展 1→2 页: 0x...515000 → 0x...515000（地址不变）data="hello"
 *   步骤2 vic=0x...514000 blk=0x...517000（vic 上方紧贴 blk）
 *     mremap 无 MAYMOVE 被挡: Cannot allocate memory（errno=12 预期 ENOMEM）
 *     mremap MAYMOVE 成功: 0x...514000 → 0x...512000（地址改变）data="VICTIM"
 *   步骤3 收缩 2→1 页: 0x...512000 → 0x...512000（地址不变）data="VICTIM"
 *   步骤4 MAP_FIXED_NOREPLACE 覆盖: EEXIST（见 49.10）
 *   步骤5 DONTUNMAP: 旧 0x...513000 → 新 0x...511000
 *     新地址 data="DATA" / 旧地址 d[0]=0x00（零填充）
 */
#define _GNU_SOURCE
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <errno.h>
#include <sys/mman.h>
#include <unistd.h>

#ifndef MREMAP_DONTUNMAP
#define MREMAP_DONTUNMAP 4
#endif

int main(void)
{
    long pagesz = sysconf(_SC_PAGESIZE);
    size_t P = (size_t)pagesz;

    /* 1. 自造空洞：mmap 3 页 → munmap 上 2 页 → 剩 1 页且上方空洞 */
    char *big = mmap(NULL, 3 * P, PROT_READ | PROT_WRITE,
                     MAP_PRIVATE | MAP_ANONYMOUS, -1, 0);
    if (big == MAP_FAILED) { perror("mmap big"); return 1; }
    if (munmap(big + P, 2 * P) != 0) { perror("munmap hole"); return 1; }
    strcpy(big, "hello");
    char *m1 = mremap(big, P, 2 * P, 0);       /* 无 MAYMOVE，上方空洞 */
    if (m1 == MAP_FAILED) perror("原地扩展");
    else printf("原地扩展 1→2 页: %p → %p data=\"%s\"\n",
                (void *)big, (void *)m1, m1);

    /* 2. 紧贴阻挡（top-down 分配器让 vic 紧贴 blk 下方） */
    char *blk = mmap(NULL, P, PROT_READ | PROT_WRITE,
                     MAP_PRIVATE | MAP_ANONYMOUS, -1, 0);
    char *vic = mmap(NULL, P, PROT_READ | PROT_WRITE,
                     MAP_PRIVATE | MAP_ANONYMOUS, -1, 0);
    if (blk == MAP_FAILED || vic == MAP_FAILED) { perror("mmap blk/vic"); return 1; }
    strcpy(vic, "VICTIM");

    errno = 0;
    char *blocked = mremap(vic, P, 2 * P, 0);  /* 无 MAYMOVE，上方被挡 */
    printf("受阻+无MAYMOVE: %s(errno=%d 预期 %d)\n",
           blocked == MAP_FAILED ? "MAP_FAILED" : "意外成功",
           errno, ENOMEM);

    errno = 0;
    char *moved = mremap(vic, P, 2 * P, MREMAP_MAYMOVE);
    if (moved == MAP_FAILED) perror("MAYMOVE");
    else printf("MAYMOVE 搬家: %p → %p data=\"%s\"\n",
                (void *)vic, (void *)moved, moved);

    /* 3. 收缩 */
    char *shr = mremap(moved, 2 * P, P, 0);
    if (shr != MAP_FAILED)
        printf("收缩 2→1 页: %p → %p data=\"%s\"\n",
               (void *)moved, (void *)shr, shr);

    /* 5. MREMAP_DONTUNMAP：新旧并存，旧地址零填充 */
    char *d = mmap(NULL, P, PROT_READ | PROT_WRITE,
                   MAP_PRIVATE | MAP_ANONYMOUS, -1, 0);
    strcpy(d, "DATA");
    char *d2 = mremap(d, P, P, MREMAP_MAYMOVE | MREMAP_DONTUNMAP);
    if (d2 == MAP_FAILED) {
        perror("DONTUNMAP（内核 < 5.13 或限制）");
    } else {
        printf("DONTUNMAP: 旧 %p → 新 %p\n", (void *)d, (void *)d2);
        printf("  新地址 data=\"%s\" / 旧地址 d[0]=0x%02x（零填充）\n",
               d2, (unsigned char)d[0]);
    }
    return 0;
}

题目 1（选择）： mremap(p, 4096, 8192, 0) 时 p 上方紧贴另一个映射，返回？

题目 2（判断）： mremap 搬家时要复制所有数据到新物理页。

参考答案

错误。move_page_tables 搬的是页表项（PTE 从旧虚址摘下挂到新虚址），物理页纹丝不动——这就是 mremap 快的本质。代价：TLB shootdown（旧翻译全部作废，IPI 广播）+ rmap 锁（take_rmap_locks():105，反向映射一致性）。

题目 3（应用）： 用 MREMAP_DONTUNMAP 设计「策略热切换」：新策略引擎就绪前旧引擎继续服务。

参考答案

49.9

MAP_NORESERVE 与 swap space overcommit

源码核验：Linux v6.6 · mm/mmap.c（accountable_mapping 记账 · security_vm_enough_memory_mm 检查 · mmap_region():2662 内 charged 分支）· mm/util.c（vm_commit_limit / __vm_enough_memory overcommit 判定） 本章：TLPI 第 49 章 — Memory Mappings - 上一节：49.8 mremap - 下一节：49.10 MAP_FIXED

本节讲什么

私有可写映射默认要预留 swap（承诺「你最坏情况全写满也放得下」）；MAP_NORESERVE 放弃这个承诺。三个灵魂问题：

  1. 预留的是什么？（swap 空间的记账数字，不是真实分配——commit 只动计数器）
  2. 三种 overcommit 模式怎么选？（0 启发式 / 1 全放行 / 2 按公式严格）
  3. 什么时候会死？（写爆 commit → OOM killer，按 oom_score 挑受害者）

要点

预留机制：VM_ACCOUNT

mmap_region() 对私有可写映射走 accountable_mapping：commit 字节数进 mm->committed_vm，全局对照 CommitLimit（/proc/meminfo）。预留失败 → mmap 返回 ENOMEM。MAP_NORESERVE 跳过整个记账（v6.6 中该标志本身已在多数模式被弱化，见下表）。

三种 overcommit 模式（/proc/sys/vm/overcommit_memory）

模式 语义 MAP_NORESERVE 的效果
0（默认）: 启发式 明显离谱的请求拒绝（单次 > RAM+swap），合理的放行 基本等效（启发式本来就宽松）
1: 总是允许 不检查，来者不拒 无差别
2: 严格模式 总 commit ≤ swap + RAM × overcommit_ratio 被忽略——严格模式下人人都必须记账

严格模式的公式（vm_commit_limit()）：

CommitLimit = SwapTotal + (RAMTotal - RAMKernelReserved) × overcommit_ratio/100

死亡路径：写爆 commit

承诺了 8GB（committed） ← mmap 时只记数字，没占真内存
   ↓ 进程真写满
物理内存 + swap 全线耗尽
   ↓
page fault 分配不出页 → out_of_memory() → OOM killer
   ↓ 按 oom_score（RSS、nice、运行时间…）选牺牲品 → SIGKILL

被杀的不一定是肇事进程——oom_score 偏向大 RSS，谁胖谁死。生产事故经典形态：「稀疏大映射的进程活得好好的，隔壁无辜的数据库被 OOM 了」。

何时用 MAP_NORESERVE

场景 判断
稀疏数组（大部分页永不写） ✅ 用——不写就不占真内存，预留是浪费
预留大虚拟区 + 按需 populate（HFT 常见） ✅ 用
共享内存大块 ⚠️ 谨慎——SHARED 映射本身不记账（无 swap 可换），但真写满照样挤爆 RAM
正常分配 ❌ 不用——默认记账是免费保险
要可靠的 OOM 行为 ❌ 不用

观测工具

grep -i commit /proc/meminfo    # CommitLimit / Committed_AS（承诺 vs 上限）
cat /proc/<pid>/status | grep VmSize   # 虚拟 vs RSS：稀疏映射的差值就是「画而未用」

HFT / 嵌入式关联

路线 要点
嵌入式 无 swap 设备时 CommitLimit ≈ RAM×ratio——严格模式直接把多数大 mmap 拒掉；嵌入式常开 overcommit=1（反正没有 swap 可承诺，记账是自欺）
HFT 预留超大虚拟区（如 64GB 订单池地址空间）+ MAP_NORESERVE + 按需 mlock/populate——虚拟区白拿，物理页按工作集付账；但必须配监控：Committed_AS 贴近 CommitLimit = 全系统 OOM 前兆，比等毛刺可靠

代码示例


/* MAP_NORESERVE：稀疏大映射的「画而不占」
 * 实测（WSL Ubuntu，gcc -O2 -Wall -Wextra，2026-09-05）：
 *   mapped 1GB with MAP_NORESERVE
 *   Rss=0 kB（只写 2 页前）→ 写 2 页后 Rss=8 kB
 */
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <sys/mman.h>
#include <unistd.h>

static long smaps_rss(void *addr)
{
    FILE *fp = fopen("/proc/self/smaps", "r");
    if (!fp) return -1;
    char line[300];
    unsigned long lo, hi, a = (unsigned long)addr;
    long rss = -1;
    int in_target = 0;
    while (fgets(line, sizeof line, fp)) {
        if (sscanf(line, "%lx-%lx", &lo, &hi) == 2)
            in_target = (a >= lo && a < hi);
        else if (in_target && strncmp(line, "Rss:", 4) == 0) {
            sscanf(line + 4, "%ld", &rss);
            break;
        }
    }
    fclose(fp);
    return rss;
}

int main(void)
{
    size_t size = 1UL << 30;                  /* 1GB 虚拟 */
    char *p = mmap(NULL, size, PROT_READ | PROT_WRITE,
                   MAP_PRIVATE | MAP_ANONYMOUS | MAP_NORESERVE, -1, 0);
    if (p == MAP_FAILED) { perror("mmap"); return 1; }
    printf("mapped 1GB MAP_NORESERVE at %p, Rss=%ld kB（画而不占）\n",
           (void *)p, smaps_rss(p));

    p[0] = 'x';
    p[4096] = 'y';                            /* 只碰 2 页 */
    printf("写 2 页后 Rss=%ld kB（只有真写的页进物理内存）\n", smaps_rss(p));
    /* 注意：若写满 1GB 且系统无余量 → OOM killer 可能杀掉本进程或邻居 */

    munmap(p, size);
    return 0;
}

自测题

题目 1（选择）： overcommit_memory=2（严格模式）下，MAP_NORESERVE 的效果？

A. 完全跳过记账　B. 被忽略，照样记账　C. mmap 必定失败　D. 只影响 RSS

参考答案

B。严格模式的语义就是「人人都记账、总承诺不超公式」——MAP_NORESERVE 在此模式下形同虚设。反过来在模式 1（总是允许）下记账本来就不查，NORESERVE 也无意义。该标志只在默认启发式模式下有实际差别。

题目 2（判断）： Committed_AS 是当前真实占用的内存量。

参考答案

错误。Committed_AS 是承诺总量——所有进程「最坏情况全写满」的加总（虚拟内存记账），真实占用看 RSS/MemAvailable。Committed_AS 完全可以远超 RAM（overcommit 0/1 下常态），它逼近 CommitLimit 才是危险信号。

题目 3（应用）： 8GB RAM + 4GB swap 的机器，进程 A 按默认模式 mmap 12GB 私有匿名映射，会发生什么？overcommit_memory 分别为 0/1/2 时？

参考答案
  • 模式 0（启发式）：单次请求 12GB > RAM+swap=12GB 的边界判定（「明显过度」），大概率 ENOMEM；若分成多次小块 mmap 则各块都能过（启发式只看单次）。
  • 模式 1：mmap 成功（不检查）；写满时物理耗尽 → OOM killer 开杀。
  • 模式 2：记账 12GB > CommitLimit（=swap 4GB + RAM×ratio），ENOMEM——在 mmap 调用点就失败，不拖到写的时候。这是三种模式的责任分界：2 = 当场拒绝，1 = 事后偿命（OOM），0 = 介于中间。
49.10

MAP_FIXED 标志

源码核验：Linux v6.6 · mm/mmap.c（mmap_region():2662 内 do_vmi_munmap():2693 先拆旧映射分支）· uapi/asm-generic/mman-common.h（MAP_FIXED:0x10 · MAP_FIXED_NOREPLACE:0x100000:31） 本章：TLPI 第 49 章 — Memory Mappings - 上一节：49.9 MAP_NORESERVE - 下一节：49.11 非线性映射

本节讲什么

MAP_FIXED 要求内核精确映射到 addr（不再是提示）。三个灵魂问题：

  1. 覆盖已有映射时会发生什么？（静默 munmap 再 mmap——不询问、不报错、不留全尸）
  2. 现代替代品？（MAP_FIXED_NOREPLACE：被占则 EEXIST，4.17+）
  3. 谁真的需要它？（动态链接器、自实现分配器/栈布局、实验 A 的 guard 技术）

要点

行为规则

规则 说明
返回值 = addr 成功时精确等于 addr（这也是验证成功的唯一方式）
addr 必须页对齐 EINVAL
静默覆盖 [addr, addr+length) 内已有映射（含代码段/栈！）→ 先 do_vmi_munmap():2693 拆掉再建新映射
length 向上取整 同普通 mmap

覆盖的破坏性（v6.6 路径）

mmap_region():2662
 └─ if (flags & MAP_FIXED) → do_vmi_munmap():2693   ← 覆盖区的旧 VMA 无条件拆除

覆盖自己正在执行的代码段 = 下一条指令取指就崩；覆盖栈 = 返回地址蒸发。传统 32 位时代 MAP_FIXED 最大的坑：mmap(NULL, ...) 返回 0 附近地址（低地址映射被拒 mmap_min_addr 前的行为）——现代内核已防护，但「覆盖自己」的自杀式用法依然是未定义行为重灾区。

MAP_FIXED_NOREPLACE（Linux 4.17+，实测验证）

void *p = mmap(hint, len, prot, MAP_FIXED_NOREPLACE | ..., fd, off);
/* 目标区已映射 → MAP_FAILED + EEXIST（errno=17）；否则精确落 hint */

实测（WSL Ubuntu，2026-09-05）：
  MAP_FIXED_NOREPLACE 覆盖 0x...69d000: MAP_FAILED（errno=17 预期 EEXIST=17）
  同地址仅作 hint: 成功 y=0x...69f000（内核挪到空洞）

三种 addr 语义对照

flags addr 含义 被占时
无 FIXED hint（从 hint 向上找空洞） 自动挪走
MAP_FIXED 精确落点 覆盖
MAP_FIXED_NOREPLACE 精确落点 EEXIST 拒绝

何时使用

场景 用途
动态链接器（ld.so） 把共享库 ELF 段装配到 vaddr 指定位置（PIE 之前的时代；现在仍用于 fixed-address 链接的二进制）
自定义内存布局 线程栈、arena 分配器的地址规划
测试/实验技术 guard 页包夹观察区（本仓库实验 A 的标准手法：PROT_NONE guard 阻止 vma_merge 吞并观察窗口）
遗留兼容 需要 32 位兼容地址的老程序

默认规则：业务代码不用 MAP_FIXED。要「尽量靠近某地址」用 hint；要「必须精确且安全」用 NOREPLACE。

HFT / 嵌入式关联

路线 要点
嵌入式 /dev/mem + MAP_FIXED 把外设寄存器映射到固定虚址（驱动/裸机代码假设的地址）；NOMMU 体系 mmap 本身就近似 fixed（物理连续性约束）
HFT 大页/NUMA 亲和的地址布局规划；MAP_FIXED_NOREPLACE 做启动自检——规划好的地址被谁占了立刻发现（EEXIST 而不是静默漂移）；永远别在运行期用裸 MAP_FIXED 改地址空间（静默覆盖 + TLB shootdown 双重风险）

代码示例


/* MAP_FIXED vs FIXED_NOREPLACE vs hint 三态实测
 * 实测（WSL Ubuntu，gcc -O2 -Wall -Wextra，2026-09-05）：
 *   MAP_FIXED_NOREPLACE 覆盖 0x...69d000: MAP_FAILED（errno=17 预期 EEXIST）
 *   同地址仅作 hint: 成功 y=0x...69f000（预期 y != 占用地址）
 */
#define _GNU_SOURCE
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <errno.h>
#include <sys/mman.h>
#include <unistd.h>

int main(void)
{
    long pagesz = sysconf(_SC_PAGESIZE);
    size_t P = (size_t)pagesz;

    char *occupied = mmap(NULL, P, PROT_READ | PROT_WRITE,
                          MAP_PRIVATE | MAP_ANONYMOUS, -1, 0);
    if (occupied == MAP_FAILED) { perror("mmap"); return 1; }
    strcpy(occupied, "OCCUPIED");
    printf("占用区: %p（内容 \"%s\"）\n", (void *)occupied, occupied);

    /* 1. NOREPLACE：精确落点，被占拒绝 */
    errno = 0;
    void *x = mmap(occupied, P, PROT_READ | PROT_WRITE,
                   MAP_PRIVATE | MAP_ANONYMOUS | MAP_FIXED_NOREPLACE, -1, 0);
    printf("MAP_FIXED_NOREPLACE 覆盖: %s（errno=%d 预期 EEXIST=%d）\n",
           x == MAP_FAILED ? "MAP_FAILED" : "成功(异常!)",
           errno, EEXIST);

    /* 2. 同地址仅 hint：内核挪走 */
    errno = 0;
    void *y = mmap(occupied, P, PROT_READ | PROT_WRITE,
                   MAP_PRIVATE | MAP_ANONYMOUS, -1, 0);
    printf("同地址仅作 hint: %s y=%p（预期成功且 y != %p）\n",
           y == MAP_FAILED ? "MAP_FAILED" : "成功", y, (void *)occupied);

    /* 3. 裸 MAP_FIXED 覆盖（危险演示）：内容被替换 */
    void *z = mmap(occupied, P, PROT_READ | PROT_WRITE,
                   MAP_PRIVATE | MAP_ANONYMOUS | MAP_FIXED, -1, 0);
    if (z == MAP_FAILED) { perror("MAP_FIXED"); return 1; }
    printf("裸 MAP_FIXED 覆盖: z=%p（== occupied），旧内容 \"%s\" 消失"
           "（静默拆掉了原 VMA）\n",
           z, ((char *)z)[0] ? "?" : "已零填充");

    munmap(y, P);
    munmap(z, P);       /* z == occupied，同一页 */
    return 0;
}

题目 1（选择）： mmap(p, len, ..., MAP_FIXED|MAP_ANONYMOUS, -1, 0) 成功后，p 处原来的栈映射会怎样？

A. 报错拒绝　B. 与新映射共存　C. 被静默拆除　D. 栈迁移到别处

参考答案

C。mmap_region() 对 MAP_FIXED 第一步就是 do_vmi_munmap():2693 拆掉区间内所有旧 VMA——无条件、静默。覆盖栈 = 返回地址蒸发 = 崩溃；这是 MAP_FIXED 危险性的本质：它拥有「不经询问删除映射」的权限。

题目 2（判断）： MAP_FIXED_NOREPLACE 成功时返回的地址可能与传入的 addr 不同。

参考答案

错误。NOREPLACE 的语义是「要么精确落 addr，要么 EEXIST 失败」——成功必 == addr（实测验证）。会挪地址的是不带任何 FIXED 的 hint 模式。

题目 3（应用）： 实验程序想观察一块 mmap 区的 VMA 行为，为什么用 PROT_NONE 页 + MAP_FIXED 包夹它？

参考答案

① 先 mmap(NULL, 5P, PROT_NONE, ...) 拿连续 5 页 guard 区；② mmap(guard+P, 3P, RW, MAP_FIXED, ...) 把中间 3 页升级成观察区。guard 的 PROT_NONE 与观察区 RW flags 不同 → vma_merge 拒绝合并——观察区边界被两侧 guard 钉死，任何后续分配（包括 fopen 内部的 malloc→mmap）都无法把观察区吞并变形。没有 guard 时实测出现过 VMA 条数错乱（相邻同 flags 分配把边界 merge 掉）。这是「用 mprotect 的 flags 差异当合并绝缘体」的标准技术。

49.11

非线性映射：remap_file_pages()

源码核验：Linux v6.6 · mm/mmap.c（emulation 层 SYSCALL_DEFINE5(remap_file_pages):2952 · pr_warn_once:2962 注释 "Emulation of deprecated remap_file_pages() syscall"） 本章：TLPI 第 49 章 — Memory Mappings - 上一节：49.10 MAP_FIXED - 下一节：49.12 总结

本节讲什么

remap_file_pages() 允许「一个 VMA 的不同虚页指向文件的不同页」——打破线性对应。三个灵魂问题：

  1. 为什么需要非线性？（数据库/索引引擎想让「虚拟连续的 B 树区」对应「文件里散乱的页」）
  2. 它现在是什么状态？（v6.6 只剩 emulation：内核收到调用就打 dmesg 警告，然后用 munmap+mmap+MAP_FIXED 重建——原始实现 3.16 就删了）
  3. 现在怎么实现同样需求？（多个小 VMA 拼接，或干脆别用 mmap）

要点

概念：线性 vs 非线性

普通（线性）映射:  虚页 0 → 文件页 0
                  虚页 1 → 文件页 1
                  虚页 2 → 文件页 2

非线性映射:        虚页 0 → 文件页 4096
                  虚页 1 → 文件页 0
                  虚页 2 → 文件页 8192

历史与现状

时点 状态
2.6 内核早期 原生实现：VMA 带 VM_NONLINEAR 标志，页表随意指——复杂度炸弹（与反碎片、KSM、THP 全都打架）
Linux 3.16（2014） 原生实现删除
v6.6（本文核验） 纯 emulation：mm/mmap.c:2952 的 SYSCALL_DEFINE5 收到调用后：① pr_warn_once() 在 dmesg 记录 "uses deprecated remap_file_pages() syscall"（:2962）② 内部等价于 munmap 目标区间 + mmap(...MAP_FIXED) 重建 
SYSCALL_DEFINE5(remap_file_pages, ...)          mm/mmap.c:2952
 ├─ pr_warn_once("... deprecated ...")          :2962  ← dmesg 可见指纹
 └─ has_pending_nonlinear_op → munmap + 重建（本质是普通 mmap 的包装）

现代调用 remap_file_pages = 慢速绕路的 mmap，没有任何性能优势，只留兼容。

为什么被删（架构教训）

非线性 VMA 打破了「一个 VMA ↔ 一段连续文件区间」的核心不变量： - 反向映射（rmap）复杂化：同一 VMA 的页指向文件各处，优先级搜索树退化 - 与 THP/KSM/compaction 的交互全是特判 - 收益人口极窄（数据库大多早有自己的 buffer pool，不走 mmap）

这是「通用机制里塞特例」最终被偿还的经典案例——内核设计里不变量的价值高于单点性能。

替代方案

/* 需求：把文件第 2 页映射到虚址 p，第 0 页到 p+4096（自定义排列） */
mmap(p,      4096, PROT_READ|PROT_WRITE, MAP_SHARED|MAP_FIXED, fd, 8192);
mmap(p+4096, 4096, PROT_READ|PROT_WRITE, MAP_SHARED|MAP_FIXED, fd, 0);

代价：每段一个 VMA（map_count 消耗，上限 vm.max_map_count 默认 65530）；TLB/缺页行为不变（反正都是按页缺的）。更现代的选择：别映射——数据库用 pread/pwrite + 自管 buffer pool（PostgreSQL 的决策路径正是如此）。

HFT / 嵌入式关联

路线 要点
嵌入式 老代码移植时若见到 remap_file_pages：expect dmesg 警告 + 性能退化（绕路 mmap），规划迁移到多 mmap 或 read/write 模型
HFT 现代引擎无使用场景。教训级价值：「通用路径塞特例」的架构债——自己写撮合引擎/行情总线时，同样警惕「给某个策略开特殊通道」型需求，特例会指数级腐蚀不变量

代码示例


/* 非线性映射的现代实现：多 mmap + MAP_FIXED 拼接
 * 实测（WSL Ubuntu，gcc -O2 -Wall -Wextra，2026-09-05）：
 *   page 0 (file page 2): PAGE2    ← 虚页 0 指向文件第 2 页
 *   page 1 (file page 1): PAGE1    ← 虚页 1 保持原位
 */
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <fcntl.h>
#include <unistd.h>
#include <sys/mman.h>

int main(void)
{
    long pagesz = sysconf(_SC_PAGESIZE);
    size_t P = (size_t)pagesz;

    int fd = open("/tmp/ch49_nonlin.dat", O_RDWR | O_CREAT | O_TRUNC, 0644);
    if (fd < 0) { perror("open"); return 1; }
    if (ftruncate(fd, (off_t)(3 * P)) != 0) { perror("ftruncate"); return 1; }

    /* 写 3 页标记：PAGE0/PAGE1/PAGE2 */
    char tmp[16];
    for (int i = 0; i < 3; i++) {
        snprintf(tmp, sizeof tmp, "PAGE%d", i);
        if (pwrite(fd, tmp, strlen(tmp), (off_t)(i * P)) < 0) { perror("pwrite"); return 1; }
    }

    char *p = mmap(NULL, 3 * P, PROT_READ | PROT_WRITE, MAP_SHARED, fd, 0);
    if (p == MAP_FAILED) { perror("mmap"); return 1; }

    /* 非线性重排：虚页 0 改指文件页 2（remap_file_pages 的现代等价物） */
    void *r = mmap(p, P, PROT_READ | PROT_WRITE,
                   MAP_SHARED | MAP_FIXED, fd, (off_t)(2 * P));
    if (r == MAP_FAILED) { perror("mmap FIXED"); return 1; }

    printf("page 0 (file page 2): %.6s\n", p);          /* PAGE2 */
    printf("page 1 (file page 1): %.6s\n", p + P);      /* PAGE1 */
    printf("page 2 (file page 2): %.6s\n", p + 2 * P);  /* PAGE2（同页双视图！） */

    munmap(p, 3 * P);
    close(fd);
    unlink("/tmp/ch49_nonlin.dat");
    return 0;
}

注意第三个输出：虚页 0 与虚页 2 现在指向同一个文件页——多 mmap 天然支持「一页多视图」，这本来就是非线性映射的能力子集。

练习题

练习 1：共享内存计数器（fork IPC）

用 MAP_SHARED|MAP_ANONYMOUS 实现父子计数器，各加 10000 次，观察竞态。

练习 2：解释计数器为什么不是 20000

(*counter)++ 非原子——丢失更新。

练习 3：mmap 映射的文件被 truncate 会怎样？

访问被截掉的部分触发 SIGBUS（映射合法但页无后备）。

实验 4（实测）：mmap 生命周期三态 + VMA 分裂

mmap 3 页 → 未触碰/读触碰/写触碰三态的 Rss 演化；munmap 中间页观察 maps 条数 1→2。

实验 5（实测）：PRIVATE vs SHARED 可见性三连

对照页设计（页 0 不写 / 页 1 预写 'K'）：fork 后子改 SHARED，父读 PRIVATE——页 0 跟随 page cache、页 1 COW 快照定格。

实验 6（实测）：mremap 全景 + MAP_FIXED_NOREPLACE

自造空洞原地扩展 / 紧贴阻挡 ENOMEM / MAYMOVE 搬家 / 收缩 / DONTUNMAP 旧址零填充 / NOREPLACE EEXIST。

实验 7（实测）：MAP_POPULATE 预填充对比

lazy 与 populate 各 16MB：Rss 0 vs 16384 kB；memset 首触 15ms vs 1ms。

练习 1 参考代码

#include <stdio.h>
#include <stdlib.h>
#include <sys/mman.h>
#include <sys/wait.h>
#include <unistd.h>

int main(void)
{
    int *counter = mmap(NULL, sizeof(int), PROT_READ | PROT_WRITE,
                        MAP_SHARED | MAP_ANONYMOUS, -1, 0);
    if (counter == MAP_FAILED) { perror("mmap"); return 1; }
    *counter = 0;

    pid_t pid = fork();
    if (pid == 0) {
        for (int i = 0; i < 10000; i++) (*counter)++;
        _exit(0);
    }
    for (int i = 0; i < 10000; i++) (*counter)++;
    wait(NULL);
    /* 注意: 结果可能不是 20000, 因为 ++ 不是原子操作 */
    printf("counter: %d (race condition: not 20000)\n", *counter);
    return 0;
}

练习 2 答案

(*counter)++ 是读-改-写三步操作，非原子。父子进程可能同时读到相同值，各自加 1 后写回，导致丢失更新。修复：信号量（Ch53）/文件锁（Ch55）/__sync_fetch_and_add 原子操作/带 mutex 的 pthread 共享（Ch30）。

练习 3 答案

访问被截断的部分触发 SIGBUS：虚址在 VMA 内（映射合法），但缺页处理发现 offset ≥ i_size（无后备数据页），发 SIGBUS。与 SIGSEGV（VMA 不存在）是两个不同层次的死法。防护：访问前对 fstat 的大小做区间校验，或捕获 SIGBUS（sigsetjmp 方案，见 49.4 实测）。

实验 7 参考代码（实测：2026-09-05）


/* MAP_POPULATE vs 惰性映射：Rss 与首触耗时
 * 实测（WSL Ubuntu，gcc -O2 -Wall -Wextra，2026-09-05）：
 *   lazy     mmap 后 Rss=0 kB
 *   populate mmap 后 Rss=16384 kB
 *   lazy     区 memset 首触 15 ms（4096 次缺页）
 *   populate 区 memset      1 ms（纯写内存）——15 倍差
 */
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <time.h>
#include <sys/mman.h>
#include <unistd.h>

int main(void)
{
    size_t len = 16UL << 20;                 /* 16MB = 4096 页 */

    char *lazy = mmap(NULL, len, PROT_READ | PROT_WRITE,
                      MAP_PRIVATE | MAP_ANONYMOUS, -1, 0);
    char *pop  = mmap(NULL, len, PROT_READ | PROT_WRITE,
                      MAP_PRIVATE | MAP_ANONYMOUS | MAP_POPULATE, -1, 0);
    if (lazy == MAP_FAILED || pop == MAP_FAILED) { perror("mmap"); return 1; }

    struct timespec t0, t1;
    clock_gettime(CLOCK_MONOTONIC, &t0);
    memset(lazy, 1, len);                    /* 首触：4096 次缺页 */
    clock_gettime(CLOCK_MONOTONIC, &t1);
    printf("lazy     memset %ld ms\n",
           (t1.tv_sec - t0.tv_sec) * 1000 + (t1.tv_nsec - t0.tv_nsec) / 1000000);

    clock_gettime(CLOCK_MONOTONIC, &t0);
    memset(pop, 1, len);                     /* 无缺页 */
    clock_gettime(CLOCK_MONOTONIC, &t1);
    printf("populate memset %ld ms\n",
           (t1.tv_sec - t0.tv_sec) * 1000 + (t1.tv_nsec - t0.tv_nsec) / 1000000);

    munmap(lazy, len);
    munmap(pop, len);
    return 0;
}
