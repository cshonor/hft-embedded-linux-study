导读

章节目标

mmap/munmap/msync；四大组合；PRIVATE vs SHARED；SIGBUS；匿名映射；与 read/SysV shm 对比。

横向对比

read/write mmap 文件
拷贝 用户↔页缓存两次 直接碰页缓存，少一次
代价 系统调用 缺页；小顺序 IO 未必更快
共享匿名 mmap SysV shm 共享文件 mmap
进程 仅亲缘 任意本机 任意本机（同文件）
持久 末 munmap 毁 内核持久+RMID 可回盘

共享区同样：勿存裸指针，用 offset。

陷阱清单

  1. offset 未页对齐 → 失败
  2. SHARED 越过 EOF → SIGBUS
  3. PRIVATE 改文件「不生效」
  4. munmap ≠ msync
  5. 匿名 SHARED 不能给无关进程
  6. prot > open 权限
  7. 共享区裸指针

背诵卡

# 要点
1 PRIVATE=COW 不回盘；SHARED=可见可回盘
2 四组合：私匿/私文/共匿/共文
3 fork 继承；exec 全毁
4 EOF 越界 SHARED → SIGBUS
5 落盘用 msync；匿名 fd=-1
6 mmap 大文件随机访问常更省拷贝
7 mmap 只画区不搬数据，访问才缺页填页；设备独占靠驱动锁（非 mmap 能力）

代码示例

#include <stdio.h>
#include <sys/mman.h>
#include <fcntl.h>
#include <unistd.h>
#include <string.h>
#include <sys/wait.h>

/* Ch49 内存映射 — mmap/munmap/msync/mremap。
 * mmap 可以映射文件/匿名内存, 父子进程可共享。
 * 编译: gcc -o ch49_demo ch49_demo.c */

int main(void) {
    /* === 匿名共享映射 (父子进程共享) === */
    int *shared = mmap(NULL, sizeof(int),
                       PROT_READ | PROT_WRITE,
                       MAP_SHARED | MAP_ANONYMOUS,
                       -1, 0);
    if (shared == MAP_FAILED) { perror("mmap"); return 1; }

    *shared = 0;
    printf("Initial value: %d\n", *shared);

    pid_t pid = fork();
    if (pid == 0) {
        /* 子进程: 修改共享映射 */
        for (int i = 0; i < 5; i++) {
            (*shared)++;
            printf("Child: value=%d\n", *shared);
            usleep(100000);
        }
        _exit(0);
    }

    /* 父进程: 也能看到变化 */
    for (int i = 0; i < 5; i++) {
        usleep(100000);
        printf("Parent sees: value=%d\n", *shared);
    }
    waitpid(pid, NULL, 0);

    printf("Final value: %d\n", *shared);

    /* === 文件映射 === */
    int fd = open("/tmp/ch49_mmap.txt", O_RDWR | O_CREAT | O_TRUNC, 0644);
    write(fd, "Hello, mmap!", 12);

    char *fmap = mmap(NULL, 12, PROT_READ | PROT_WRITE, MAP_SHARED, fd, 0);
    if (fmap != MAP_FAILED) {
        /* 通过内存修改文件内容 */
        fmap[0] = 'J';  /* Hello -> Jello */
        msync(fmap, 12, MS_SYNC);  /* 同步到文件 */
        printf("File content after mmap modify: %.12s\n", fmap);
        munmap(fmap, 12);
    }
    close(fd);
    remove("/tmp/ch49_mmap.txt");

    munmap(shared, sizeof(int));
    return 0;
}

49.1

四大组合

本章：TLPI 第 49 章 — Memory Mappings - 上一节：本章首页 - 下一节：49.2 –49.3 mmap / munmap

本节讲什么

mmap 的本质：只在进程虚拟地址空间「画一块区域」，建立映射关系，不立刻把数据搬进内存。 访问这块虚拟地址才会触发缺页中断，由内核把磁盘/设备数据填进物理页。所以第一件事是分清三样东西：

概念 是什么 谁触发
mmap 用户态「画一块虚拟区间」，建立 虚址 ↔ 文件/设备/匿名页 的映射 进程主动调用
缺页中断（page fault） CPU 内存管理机制：访问未映射/未加载地址时陷入内核填页 CPU 硬件，不等于 mmap
共享 / 私有 mmap 的 flags 控制多进程是否共用同一物理页 MAP_SHARED / MAP_PRIVATE

一句话：mmap 给进程虚拟地址画一块区域，可以映射到同一份物理内存实现多进程共享；但设备能不能让你映射，由设备驱动说了算——独占访问靠驱动锁，不是 mmap 自带能力。

生命周期：fork 继承映射；exec / 退出 销毁全部映射。

要点

mmap 的三类映射对象

对象 fd / offset 缺页时内核从哪填 典型场景
磁盘文件 fd + 页对齐 offset 页缓存（page cache） 文件共享、加载 text 段
设备 DMA 缓冲区 设备 fd 驱动提供的内存页（remap_pfn_range / dma_mmap_*） 网卡/采集卡零拷贝、帧缓冲
匿名内存 MAP_ANONYMOUS、fd=-1 零页 + 首写 COW 分配 malloc 一类、父子共享

四大组合

MAP_PRIVATE MAP_SHARED
文件 COW；改不回文件；加载 text/只读文件 改可见且可回盘；无关进程 IPC
匿名 私有堆式分配（malloc 一类） 仅亲缘（fork 继承）IPC

共享型设备 vs 独占型设备

设备类型 例子 mmap 的用法
共享型 共享文件、共享设备缓冲区 多进程 MAP_SHARED 映射同一份物理内存，一个改、其他进程都看得见
独占型 麦克风、独占采集卡 ❌ 不是给每个进程各做一份 mmap；✅ 设备驱动里做独占锁，同一时刻只允许一个进程 mmap 成功，别的进程调用 mmap 失败/阻塞

关键：互斥逻辑写在设备驱动里，mmap 只是驱动对外暴露缓冲区的手段，本身不提供任何互斥。

生命周期：fork 继承映射；exec / 退出 销毁全部映射。

HFT / 嵌入式关联

路线 要点
嵌入式 设备 DMA 缓冲区 mmap：/dev/mem、帧缓冲（framebuffer）、网卡/采集卡寄存器——用户态直接读写设备内存，省掉 read/write 的 syscall + 一次拷贝
HFT 低延迟零拷贝：把网卡（DPDK 大页 + mmap）的 DMA 环形缓冲区映射进用户态，报文「网卡 DMA 直写用户态页」，不经过内核协议栈拷贝；共享型设备多进程 MAP_SHARED 看同一份行情

独占设备在 HFT 里同样成立：锁在驱动。例：一个采集卡同一时刻只让一个进程 mmap，驱动用 mutex/原子变量守卫 fops->mmap，抢不到就返回 -EBUSY。

代码示例


/* 四大映射组合演示：MAP_PRIVATE vs MAP_SHARED × 文件 vs 匿名 */
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <fcntl.h>
#include <sys/mman.h>
#include <sys/wait.h>
#include <unistd.h>

int main(void) {
    /* 1) MAP_PRIVATE 文件映射 — COW，修改不回盘 */
    int fd = open("/tmp/ch49_demo.txt", O_RDWR | O_CREAT | O_TRUNC, 0644);
    write(fd, "original", 8);
    char *priv = mmap(NULL, 8, PROT_READ | PROT_WRITE, MAP_PRIVATE, fd, 0);
    priv[0] = 'X';  /* 写入触发 COW，不影响文件 */
    printf("MAP_PRIVATE after write: %.8s\n", priv);

    /* 2) MAP_SHARED 文件映射 — 修改可回盘 */
    char *shared = mmap(NULL, 8, PROT_READ | PROT_WRITE, MAP_SHARED, fd, 0);
    shared[0] = 'S';  /* msync 后写回文件 */
    msync(shared, 8, MS_SYNC);

    /* 3) MAP_SHARED|MAP_ANONYMOUS — 父子 IPC */
    char *anon = mmap(NULL, 64, PROT_READ | PROT_WRITE,
                      MAP_SHARED | MAP_ANONYMOUS, -1, 0);
    strcpy(anon, "fork-ipc");
    pid_t pid = fork();
    if (pid == 0) { printf("child: %s\n", anon); _exit(0); }
    wait(NULL);

    /* 4) MAP_PRIVATE|MAP_ANONYMOUS — 私有堆式分配 */
    char *heap_like = mmap(NULL, 64, PROT_READ | PROT_WRITE,
                           MAP_PRIVATE | MAP_ANONYMOUS, -1, 0);
    strcpy(heap_like, "private anon");

    munmap(priv, 8); munmap(shared, 8); munmap(anon, 64); munmap(heap_like, 64);
    close(fd);
    return 0;
}

设备独占：锁在驱动（伪代码）

/* 驱动侧：独占设备同一时刻只允许一个进程 mmap */
static int mic_mmap(struct file *filp, struct vm_area_struct *vma)
{
    /* 原子变量实现「拿得到才映射」的独占锁 */
    if (!atomic_add_unless(&mic_open, 1, 1))
        return -EBUSY;             /* 已被别的进程独占 → mmap 失败 */

    /* 把设备 DMA 缓冲区物理页映射进用户态虚拟地址 */
    return remap_pfn_range(vma, vma->vm_start,
                           mic_dma_paddr >> PAGE_SHIFT,
                           vma->vm_end - vma->vm_start,
                           vma->vm_page_prot);
}

static int mic_release(struct inode *i, struct file *filp)
{
    atomic_set(&mic_open, 0);      /* 释放独占 */
    return 0;
}

注意：互斥逻辑完全在驱动（atomic_add_unless + -EBUSY），mmap 系统调用本身不提供「独占」能力——它只是把驱动暴露的缓冲区挂到进程虚拟地址上。

49.2

–49.3 `mmap` / `munmap`

本章：TLPI 第 49 章 — Memory Mappings - 上一节：49.1 四大组合 - 下一节：49.4 文件映射

本节讲什么

void mmap(void addr, size_t length, int prot, int flags, int fd, off_t offset); int munmap(void *addr, size_t length); - addr=NULL 推荐；length 上对齐页

要点

void *mmap(void *addr, size_t length, int prot, int flags, int fd, off_t offset);
int munmap(void *addr, size_t length);
  • addr=NULL 推荐；length 上对齐页
  • prot：NONE/READ/WRITE/EXEC；不得超过文件 open 权限
  • flags：必须 SHARED 或 PRIVATE 二选一
  • 文件：fd+页对齐 offset；匿名：MAP_ANONYMOUS，fd=-1，offset=0
  • 失败：MAP_FAILED
  • munmap 不自动刷盘 → 共享映射要落盘用 msync

HFT / 嵌入式关联

路线 要点
嵌入式 匿名映射替代 malloc 分配页对齐缓冲（DMA/裸金属缓存）；映射设备寄存器/MMIO 到用户态直读
HFT MAP_SHARED 文件/匿名映射做零拷贝共享行情缓冲；匿名映射省 malloc 元数据开销、页对齐利于大页/TLB

常见陷阱

  1. MAP_FAILED vs NULL
void *p = mmap(NULL, size, PROT_READ|PROT_WRITE,
              MAP_PRIVATE|MAP_ANONYMOUS, -1, 0);
if (p == NULL) ...  /* 错误! */
if (p == MAP_FAILED) ...  /* 正确 */

mmap 失败返回 MAP_FAILED ((void*)-1)，不是 NULL。检查方式与 malloc 不同。

  1. munmap 忘记调用
void *p = mmap(NULL, 4096, ...);
/* 使用 p ... */
/* 没有 munmap → 内存泄漏 */

mmap 分配的内存不会自动释放。必须 munmap(p, size) 显式释放。

  1. 信号处理中的 SIGSEGV
mmap(NULL, size, PROT_READ, MAP_PRIVATE|MAP_ANONYMOUS, -1, 0);
/* 写只读映射 → SIGSEGV */

对 PROT_READ 的映射写入会触发 SIGSEGV。确保保护属性和访问操作匹配。

自测题

题目 1（选择）： mmap 失败时返回什么？ A. NULL B. -1 C. MAP_FAILED D. 0

参考答案

C。mmap 失败返回 MAP_FAILED（定义为 (void *)-1），不是 NULL。这与 malloc 不同。

题目 2（判断）： mmap 映射的内存会在进程退出时自动释放。

参考答案

正确。进程退出时所有映射自动解除。但在长时间运行的程序中仍需手动 munmap。

题目 3（踩坑）： 以下代码有什么问题？

void *p = mmap(NULL, 4096, PROT_READ|PROT_WRITE,
               MAP_PRIVATE|MAP_ANONYMOUS, -1, 0);
memset(p, 0, 8192);
参考答案

写入了 8192 字节但只映射了 4096 字节。超出映射区域会触发 SIGSEGV。应确保操作不超过映射大小。

题目 4（应用）： 写代码用 mmap 分配匿名内存并初始化为 0。

参考答案 
void *p = mmap(NULL, 4096, PROT_READ|PROT_WRITE,
               MAP_PRIVATE|MAP_ANONYMOUS, -1, 0);
if (p == MAP_FAILED) { perror("mmap"); exit(1); }
memset(p, 0, 4096);
/* ... 使用 ... */
munmap(p, 4096);

代码示例


/* mmap / munmap 完整用法：匿名映射 + 文件映射 + 错误处理 */
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <fcntl.h>
#include <sys/stat.h>
#include <sys/mman.h>
#include <unistd.h>

int main(void) {
    /* --- 匿名映射 --- */
    size_t len = 4096;
    void *p = mmap(NULL, len, PROT_READ | PROT_WRITE,
                   MAP_PRIVATE | MAP_ANONYMOUS, -1, 0);
    if (p == MAP_FAILED) { perror("mmap anon"); exit(1); }
    memset(p, 0xAB, len);
    printf("anon mapped %zu bytes at %p\n", len, p);
    munmap(p, len);

    /* --- 文件映射 --- */
    int fd = open("/tmp/ch49_file.dat", O_RDWR | O_CREAT | O_TRUNC, 0644);
    if (fd < 0) { perror("open"); exit(1); }
    ftruncate(fd, (off_t)len);  /* 必须先设置文件大小 */

    char *fm = mmap(NULL, len, PROT_READ | PROT_WRITE, MAP_SHARED, fd, 0);
    if (fm == MAP_FAILED) { perror("mmap file"); exit(1); }
    strcpy(fm, "mapped file content");
    printf("file mapped: %s\n", fm);

    munmap(fm, len);
    close(fd);
    return 0;
}

49.3

解除映射：munmap()

本章：TLPI 第 49 章 — 内存映射 - 上一节：49.2 mmap - 下一节：49.4 内存映射一致性

本节讲什么

munmap() — 解除内存映射，释放虚拟地址空间。

要点

API

int munmap(void *addr, size_t length);
  • 解除从 addr 开始、长度 length 的映射
  • addr 必须页对齐
  • length 自动向上取整到页边界
  • 成功返回 0，失败返回 -1

核心行为

行为 说明
解除映射 虚拟地址空间不再有效
丢弃修改 MAP_PRIVATE 的修改被丢弃
写回文件 MAP_SHARED 的脏页写回文件（异步）
部分解除 可以只解除部分区域
进程退出 自动 munmap 所有映射

部分解除

/* 映射 4 页 */
char *p = mmap(NULL, 4096*4, PROT_READ|PROT_WRITE, MAP_SHARED, fd, 0);

/* 解除中间 2 页 */
munmap(p + 4096, 4096*2);
/* 现在: p[0..4095] 映射, p[4096..8191] 解除, p[8192..12287] 映射 */

注意事项

  • munmap 不会立即写回脏页（MAP_SHARED），需要 msync 确保落盘
  • munmap 后访问该区域 → SIGSEGV
  • addr 不对齐 → 失败，errno = EINVAL
  • 可以 munmap 一段未映射的区域（静默成功）

HFT / 嵌入式关联

路线 要点
嵌入式 及时 munmap 释放虚拟地址空间，避免耗尽
HFT mmap 共享内存区域在生命周期结束时立即 munmap，防止悬空引用

代码示例

#include <stdio.h>
#include <sys/mman.h>
#include <fcntl.h>
#include <unistd.h>
#include <string.h>
/* munmap: 解除内存映射 */
int main(void) {
    int fd = open("/tmp/test_mmap", O_RDWR|O_CREAT|O_TRUNC, 0644);
    write(fd, "hello mmap", 10);

    /* 映射 */
    char *p = mmap(NULL, 4096, PROT_READ|PROT_WRITE, MAP_SHARED, fd, 0);
    if (p == MAP_FAILED) { perror("mmap"); return 1; }
    printf("mapped: %.10s\n", p);

    /* 修改 */
    memcpy(p, "HELLO", 5);

    /* 解除映射 */
    if (munmap(p, 4096) == 0) {
        printf("munmap: success\n");
    }

    /* p 不再有效, 访问会 SIGSEGV */
    close(fd);
    unlink("/tmp/test_mmap");
    return 0;
}

49.4

文件映射

本章：TLPI 第 49 章 — Memory Mappings - 上一节：49.2 –49.3 mmap / munmap - 下一节：49.5 msync

本节讲什么

PRIVATE：首写 COW，仅本进程可见，永不写回文件。 SHARED：同页共享；改对其它映射者可见；内核异步回盘。 SIGSEGV = 非法虚址；SIGBUS = 映射合法但无后备。

要点

PRIVATE：首写 COW，仅本进程可见，永不写回文件。
SHARED：同页共享；改对其它映射者可见；内核异步回盘。

越界 PRIVATE SHARED
映区大于文件 零页；写不扩文件 越过 EOF → SIGBUS

SIGSEGV = 非法虚址；SIGBUS = 映射合法但无后备。

HFT / 嵌入式关联

路线 要点
嵌入式 SHARED 只读映射共享固件/ROMFS 镜像省 RAM；fork 后 PRIVATE 首写 COW 共享只读段零拷贝
HFT SHARED 映射跨进程共享订单簿/行情零拷贝；PRIVATE 读多写少用 COW 避免写放大、省内存

代码示例


/* MAP_FIXED 映射到固定地址（危险，仅演示） */
#include <stdio.h>
#include <stdlib.h>
#include <sys/mman.h>
#include <unistd.h>

int main(void) {
    /* 先用一个普通映射拿到一段虚拟地址 */
    void *hint = mmap(NULL, 4096, PROT_READ | PROT_WRITE,
                      MAP_PRIVATE | MAP_ANONYMOUS, -1, 0);
    if (hint == MAP_FAILED) { perror("mmap hint"); exit(1); }
    printf("hint address: %p\n", hint);
    munmap(hint, 4096);

    /* MAP_FIXED 要求内核精确映射到指定地址，覆盖已有映射 */
    /* 实际开发中几乎不用，这里仅演示参数 */
    void *fixed = mmap(hint, 4096, PROT_READ | PROT_WRITE,
                       MAP_PRIVATE | MAP_ANONYMOUS | MAP_FIXED, -1, 0);
    if (fixed == MAP_FAILED) { perror("mmap fixed"); exit(1); }
    printf("fixed mapped at: %p (same as hint)\n", fixed);
    munmap(fixed, 4096);
    return 0;
}

`msync`

本章：TLPI 第 49 章 — Memory Mappings - 上一节：49.4 文件映射 - 下一节：49.6 –49.8 Flags · mremap

本节讲什么

int msync(void addr, size_t length, int flags); MS_SYNC 阻塞落盘 · MS_ASYNC 后台 · MS_INVALIDATE 作废缓存。 仅对 SHARED* 有意义。

要点

int msync(void *addr, size_t length, int flags);

MS_SYNC 阻塞落盘 · MS_ASYNC 后台 · MS_INVALIDATE 作废缓存。
仅对 SHARED 有意义。

HFT / 嵌入式关联

路线 要点
嵌入式 掉电保护：关键配置/日志 MS_SYNC 强制落 flash；MS_INVALIDATE 同步外设缓存一致性
HFT 热路径不碰 msync；审计/持久化日志用 MS_ASYNC 后台刷盘，避免阻塞引入延迟毛刺

代码示例


/* msync 三种模式：MS_SYNC / MS_ASYNC / MS_INVALIDATE */
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <fcntl.h>
#include <sys/mman.h>
#include <unistd.h>

int main(void) {
    int fd = open("/tmp/ch49_msync.txt", O_RDWR | O_CREAT | O_TRUNC, 0644);
    ftruncate(fd, 4096);
    char *m = mmap(NULL, 4096, PROT_READ | PROT_WRITE, MAP_SHARED, fd, 0);
    if (m == MAP_FAILED) { perror("mmap"); exit(1); }

    strcpy(m, "msync demo data");

    /* MS_SYNC：同步刷盘，阻塞直到写回完成 */
    if (msync(m, 4096, MS_SYNC) < 0) perror("msync MS_SYNC");
    printf("MS_SYNC done — data flushed to disk\n");

    /* MS_ASYNC：异步刷盘，立即返回 */
    strcpy(m, "async update");
    if (msync(m, 4096, MS_ASYNC) < 0) perror("msync MS_ASYNC");
    printf("MS_ASYNC submitted\n");

    munmap(m, 4096);
    close(fd);
    return 0;
}

49.7

匿名映射

本章：TLPI 第 49 章 — 内存映射 - 上一节：49.6 共享文件映射 - 下一节：49.8 mremap

本节讲什么

匿名映射 — 不关联任何文件的内存映射，用于分配初始化为零的内存或进程间共享内存。

要点

两种匿名映射方式

方式 flags 可移植性
MAP_ANONYMOUS MAP_SHARED\|MAP_ANONYMOUS, fd=-1 Linux/BSD（非 POSIX）
/dev/zero 映射 /dev/zero 文件 POSIX 可移植

MAP_SHARED vs MAP_PRIVATE 匿名映射

MAP_SHARED\|MAP_ANONYMOUS MAP_PRIVATE\|MAP_ANONYMOUS
用途 父子进程共享内存 分配零初始化内存
fork 后 子进程共享同一映射 子进程获得 COW 副本
等价于 共享内存 IPC 类似 malloc（但无 free）

典型用法：父子进程共享内存

/* MAP_ANONYMOUS | MAP_SHARED: fork 后父子共享 */
int *shared = mmap(NULL, sizeof(int), PROT_READ|PROT_WRITE,
                   MAP_SHARED|MAP_ANONYMOUS, -1, 0);
*shared = 0;
if (fork() == 0) {
    *shared = 42;  /* 子进程写 */
    _exit(0);
}
wait(NULL);
printf("parent sees: %d\n", *shared);  /* 42 */

与 malloc 的区别

malloc mmap(MAP_ANONYMOUS)
可 free 是 否（需 munmap）
粒度 任意大小 页对齐（4KB）
共享 否 可（MAP_SHARED）
初始化 不保证 零初始化

HFT / 嵌入式关联

路线 要点
嵌入式 匿名共享映射是父子进程 IPC 最简单方式
HFT MAP_SHARED\|MAP_ANONYMOUS 用于父子进程共享行情数据，零拷贝

代码示例

#include <stdio.h>
#include <sys/mman.h>
#include <unistd.h>
#include <sys/wait.h>
/* 匿名共享映射: 父子进程通信 */
int main(void) {
    /* 分配共享内存 */
    int *shared = mmap(NULL, sizeof(int), PROT_READ|PROT_WRITE,
                       MAP_SHARED|MAP_ANONYMOUS, -1, 0);
    if (shared == MAP_FAILED) { perror("mmap"); return 1; }
    *shared = 100;

    pid_t pid = fork();
    if (pid == 0) {
        /* 子进程: 修改共享内存 */
        *shared += 50;
        printf("child: shared = %d\n", *shared);
        _exit(0);
    }
    wait(NULL);
    printf("parent: shared = %d\n", *shared);  /* 150 */

    munmap(shared, sizeof(int));
    return 0;
}

49.8

重新映射：mremap()

本章：TLPI 第 49 章 — 内存映射 - 上一节：49.7 匿名映射 - 下一节：49.9 MAP_NORESERVE 与 overcommit

本节讲什么

mremap() — Linux 特有，调整已映射区域的大小或位置（类似 realloc 对 mmap）。

要点

API

void *mremap(void *old_address, size_t old_size, size_t new_size, int flags, ...);
  • 调整 old_address 处 old_size 的映射为 new_size
  • flags: MREMAP_MAYMOVE（允许移动地址）
  • 返回新地址（可能与旧地址不同）

核心行为

操作 行为
扩大 在原地址扩展（空间足够）或移动到新位置
缩小 截断，多余部分被 munmap
移动 如果 MREMAP_MAYMOVE 且原位置空间不足

与 realloc 的关系

glibc 的 realloc 对大块内存（>128KB）内部使用 mremap： - malloc 大块 → mmap - realloc 大块 → mremap - free 大块 → munmap

注意事项

  • Linux 特有，不可移植
  • 只能 remap 匿名映射（不能 remap 文件映射的大小）
  • 不指定 MREMAP_MAYMOVE 且空间不足 → 返回 MAP_FAILED
  • 缩小时，被截断区域的脏页（MAP_SHARED）会写回文件

性能优势

  • 扩大映射时不需要拷贝数据（如果原地扩展）
  • 比 malloc+memcpy+free 快得多

HFT / 嵌入式关联

路线 要点
嵌入式 mremap 扩展共享内存避免拷贝，性能优于重新 mmap
HFT 大块内存重分配用 mremap 避免数据拷贝

代码示例

#include <stdio.h>
#include <sys/mman.h>
#include <string.h>
/* mremap: 调整映射大小 */
int main(void) {
    /* 初始映射 1 页 */
    size_t old_size = 4096;
    char *p = mmap(NULL, old_size, PROT_READ|PROT_WRITE,
                   MAP_PRIVATE|MAP_ANONYMOUS, -1, 0);
    if (p == MAP_FAILED) { perror("mmap"); return 1; }
    strcpy(p, "hello");

    /* 扩大到 4 页 */
    size_t new_size = 4096 * 4;
    char *new_p = mremap(p, old_size, new_size, MREMAP_MAYMOVE);
    if (new_p == MAP_FAILED) {
        perror("mremap");
        munmap(p, old_size);
        return 1;
    }

    printf("old: %p, new: %p\n", p, new_p);
    printf("data preserved: %s\n", new_p);  /* "hello" */

    /* 写入更大范围 */
    memset(new_p + old_size, 'x', new_size - old_size);
    printf("expanded region filled\n");

    munmap(new_p, new_size);
    return 0;
}

49.9

MAP_NORESERVE 与 swap space overcommit

本章：TLPI 第 49 章 — 内存映射 - 上一节：49.8 mremap - 下一节：49.10 MAP_FIXED

本节讲什么

MAP_NORESERVE 标志和 Linux 的 overcommit 机制 — 映射时不预留 swap 空间。

要点

背景：swap 预留

  • 默认情况下，mmap 分配私有匿名映射时，内核预留等量 swap 空间
  • 如果 swap 不足，mmap 失败（ENOMEM）
  • 这保证了内存总能写入 swap

MAP_NORESERVE

mmap(NULL, size, PROT_READ|PROT_WRITE,
     MAP_PRIVATE|MAP_ANONYMOUS|MAP_NORESERVE, -1, 0);
  • 不预留 swap 空间
  • 允许分配超过 swap+RAM 的虚拟内存
  • 实际使用时如果物理内存+swap 耗尽 → OOM killer

Overcommit 模式

/* /proc/sys/vm/overcommit_memory */
0  /* 启发式（默认）: 不允许明显过度的分配 */
1  /* 总是允许: 不检查 */
2  /* 严格: 不允许超过 swap + RAM * ratio */
模式 MAP_NORESERVE 效果
0 (启发式) 可能允许
1 (总是允许) 总是允许
2 (严格) 忽略 MAP_NORESERVE

风险

  • OOM Killer: 内存耗尽时内核随机杀进程
  • 不可预测 — 哪个进程被杀取决于 oom_score
  • 适合 "分配多但实际用少" 的场景（如稀疏数组）

何时用 MAP_NORESERVE

场景 是否使用
稀疏数组（大部分不写） 用
共享内存大块 谨慎
正常内存分配 不用
需要可靠 OOM 处理 不用

HFT / 嵌入式关联

路线 要点
嵌入式 无 swap 环境 overcommit 行为不同，需测试
HFT 不用 MAP_NORESERVE — 交易系统不能冒 OOM 风险，预分配固定大小

代码示例

#include <stdio.h>
#include <sys/mman.h>
/* MAP_NORESERVE: 不预留 swap */
int main(void) {
    /* 分配 1GB 虚拟内存, 不预留 swap */
    size_t size = 1UL << 30;  /* 1 GB */
    char *p = mmap(NULL, size, PROT_READ|PROT_WRITE,
                   MAP_PRIVATE|MAP_ANONYMOUS|MAP_NORESERVE, -1, 0);
    if (p == MAP_FAILED) {
        perror("mmap MAP_NORESERVE");
        return 1;
    }
    printf("mapped 1GB with MAP_NORESERVE at %p\n", p);

    /* 只写一小部分 — 不会 OOM */
    p[0] = 'x';
    p[4096] = 'y';
    printf("wrote 2 bytes, only 2 pages actually used\n");

    /* 如果写满 1GB → 可能触发 OOM killer */
    munmap(p, size);
    return 0;
}

49.10

MAP_FIXED 标志

本章：TLPI 第 49 章 — 内存映射 - 上一节：49.9 MAP_NORESERVE - 下一节：49.11 非线性映射

本节讲什么

MAP_FIXED — 强制 mmap 在指定地址创建映射，覆盖已有映射。

要点

行为

void *p = mmap(addr, length, prot, flags|MAP_FIXED, fd, offset);
  • addr 必须页对齐
  • 如果 [addr, addr+length) 已有映射 → 静默覆盖
  • 返回值等于 addr（成功）或 MAP_FAILED（失败）

危险性

  • 覆盖已有映射（包括栈、代码段等）→ 段错误
  • 必须确保 addr 区域空闲
  • 可移植性差：不同 UNIX 行为不一致

何时使用

场景 用途
动态链接器 在固定地址加载共享库
自定义内存布局 线程栈、自定义分配器
兼容旧代码 需要固定地址的遗留程序

推荐做法

  • 不要直接用 MAP_FIXED — 太危险
  • 用 mmap(NULL, ...) 获取地址，再检查是否在期望范围
  • Linux 4.17+ 提供 MAP_FIXED_NOREPLACE：不覆盖已有映射

MAP_FIXED_NOREPLACE (Linux 4.17+)

/* 如果地址已被占用, 失败而非覆盖 */
p = mmap(hint_addr, length, prot, MAP_FIXED_NOREPLACE|flags, fd, offset);

HFT / 嵌入式关联

路线 要点
嵌入式 固定地址映射用于访问硬件寄存器（如 /dev/mem）
HFT 不常用，固定地址映射可移植性差

代码示例

#include <stdio.h>
#include <sys/mman.h>
#include <string.h>
/* MAP_FIXED: 在指定地址创建映射 (危险!) */
int main(void) {
    /* 先正常映射一块内存 */
    char *p = mmap(NULL, 4096, PROT_READ|PROT_WRITE,
                   MAP_PRIVATE|MAP_ANONYMOUS, -1, 0);
    strcpy(p, "original");

    /* 用 MAP_FIXED 在同一地址重新映射 */
    char *q = mmap(p, 4096, PROT_READ|PROT_WRITE,
                   MAP_PRIVATE|MAP_ANONYMOUS|MAP_FIXED, -1, 0);
    if (q == MAP_FAILED) { perror("mmap FIXED"); return 1; }

    printf("p=%p, q=%p (same address)\n", p, q);
    /* 原内容被覆盖 */
    printf("content after MAP_FIXED: '%s' (empty = overwritten)\n", q);

    munmap(q, 4096);
    return 0;
}

49.11

非线性映射：remap_file_pages()

本章：TLPI 第 49 章 — 内存映射 - 上一节：49.10 MAP_FIXED - 下一节：49.12 总结

本节讲什么

remap_file_pages() — 将文件的不同部分映射到同一虚拟内存区域的不同页面（非线性映射）。

要点

概念

普通文件映射是线性的：虚拟地址 offset 对应文件 offset。非线性映射允许自定义这个映射关系：

虚拟页 0 → 文件 offset 4096
虚拟页 1 → 文件 offset 0
虚拟页 2 → 文件 offset 8192

API

int remap_file_pages(void *addr, size_t len, int prot,
                     size_t pgoff, int flags);
  • addr：已映射区域内的地址
  • pgoff：文件内的页偏移
  • 将 [addr, addr+len) 重新映射到文件的 pgoff 处

已废弃

  • Linux 3.16 起标记为废弃
  • 内核内部改用多次 mmap + MAP_FIXED 实现
  • 新代码不应使用

替代方案

/* 替代: 多次 mmap + MAP_FIXED */
/* 映射文件的第 1 页到地址 p */
mmap(p, 4096, PROT_READ|PROT_WRITE, MAP_SHARED|MAP_FIXED, fd, 4096);
/* 映射文件的第 0 页到地址 p+4096 */
mmap(p+4096, 4096, PROT_READ|PROT_WRITE, MAP_SHARED|MAP_FIXED, fd, 0);

历史用途

  • 数据库引擎需要将文件的某些页映射到特定虚拟地址
  • 减少使用多个映射区域（每个映射区域有内核开销）
  • 现在用多个 mmap 替代

HFT / 嵌入式关联

路线 要点
嵌入式 已废弃，不用
HFT 已废弃，不用。如果需要非线性映射，用多次 mmap + MAP_FIXED

代码示例

#include <stdio.h>
#include <sys/mman.h>
#include <fcntl.h>
#include <unistd.h>
#include <string.h>
/* 非线性映射替代方案: 多次 mmap + MAP_FIXED */
int main(void) {
    int fd = open("/tmp/test_nonlinear", O_RDWR|O_CREAT|O_TRUNC, 0644);
    /* 写 3 页数据 */
    write(fd, "PAGE0", 5); lseek(fd, 4096, SEEK_SET);
    write(fd, "PAGE1", 5); lseek(fd, 8192, SEEK_SET);
    write(fd, "PAGE2", 5);

    /* 先映射足够大的区域 */
    char *p = mmap(NULL, 4096*3, PROT_READ|PROT_WRITE, MAP_SHARED, fd, 0);

    /* 重新映射第 1 页为文件第 2 页 (非线性) */
    mmap(p, 4096, PROT_READ|PROT_WRITE, MAP_SHARED|MAP_FIXED, fd, 8192);
    /* 现在虚拟页 0 → 文件页 2 */

    printf("page 0 (should be PAGE2): %.5s\n", p);
    printf("page 1 (should be PAGE1): %.5s\n", p + 4096);

    munmap(p, 4096*3);
    close(fd);
    unlink("/tmp/test_nonlinear");
    return 0;
}

代码自测

1. MAP_SHARED 和 MAP_PRIVATE 的区别？

MAP_SHARED：多个进程映射同一文件区域时共享同一物理页，写入对其他进程可见且写回文件。MAP_PRIVATE：写入触发 COW（copy-on-write），每个进程有独立副本，修改不影响其他进程和文件。

2. 匿名共享映射如何实现父子进程通信？

父进程用 mmap(NULL, size, PROT_READ|PROT_WRITE, MAP_SHARED|MAP_ANONYMOUS, -1, 0) 创建共享映射，fork 后子进程继承同一映射，父子共享同一物理内存，写入互相可见。

本节讲什么

原书第 49 章练习题要点。

1. 用 mmap 实现一个简单的共享内存计数器，父子进程各加 10000 次 
int *counter = mmap(NULL, sizeof(int), PROT_READ|PROT_WRITE,
                    MAP_SHARED|MAP_ANONYMOUS, -1, 0);
*counter = 0;
if (fork() == 0) {
    for (int i = 0; i < 10000; i++) (*counter)++;
    _exit(0);
}
for (int i = 0; i < 10000; i++) (*counter)++;
wait(NULL);
/* 注意: 结果可能不是 20000, 因为 ++ 不是原子操作 */
printf("counter: %d (race condition: not 20000)\n", *counter);
2. 为什么上述计数器结果可能不正确？

(*counter)++ 是读-改-写三步操作，非原子。父子进程可能同时读到相同值，各自加 1 后写回，导致丢失更新。需要用信号量或原子操作（__sync_fetch_and_add）保证原子性。

3. mmap 映射文件后，文件被 truncate 会怎样？

访问被截断的部分会触发 SIGBUS 信号。因为文件实际大小不够，内核无法提供数据页。解决方法：在访问映射区域前检查文件大小，或注册 SIGBUS 信号处理函数。
