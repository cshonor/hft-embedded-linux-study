代码示例

#include <stdio.h>
#include <pthread.h>
#include <unistd.h>
#include <string.h>

/* Ch32 线程取消 — pthread_cancel/cleanup_push/cleanup_pop。
 * 演示取消线程 + 清理函数执行。
 * 编译: gcc -o ch32_demo ch32_demo.c -lpthread */

static int fd = -1;

void cleanup_handler(void *arg) {
    printf("Cleanup: %s\n", (char *)arg);
    if (fd >= 0) {
        close(fd);
        printf("Cleanup: fd closed\n");
    }
}

void *worker(void *arg) {
    /* 注册清理函数（LIFO 顺序执行） */
    pthread_cleanup_push(cleanup_handler, "step 1");
    pthread_cleanup_push(cleanup_handler, "step 2");

    fd = open("/tmp/ch32_test.txt", O_WRONLY | O_CREAT, 0644);
    printf("Worker: opened fd=%d, entering loop...\n", fd);

    /* 默认延迟取消点: sleep 是取消点 */
    while (1) {
        printf("Worker: working...\n");
        sleep(1);  /* 取消点: 如果被取消，在此触发 */
    }

    /* cleanup_push 和 cleanup_pop 必须配对 */
    pthread_cleanup_pop(0);
    pthread_cleanup_pop(0);
    return NULL;
}

int main(void) {
    pthread_t tid;
    pthread_create(&tid, NULL, worker, NULL);

    sleep(3);
    printf("Main: cancelling worker thread...\n");
    pthread_cancel(tid);
    pthread_join(tid, NULL);
    printf("Main: worker joined after cancellation\n");

    if (fd >= 0) close(fd);
    return 0;
}

32.2

Cancellation State and Type

本章：TLPI 第 32 章 — Thread Cancellation

本节讲什么

介绍线程取消的状态和类型控制：PTHREAD_CANCEL_ENABLE/DISABLE 和 PTHREAD_CANCEL_DEFERRED/ASYNCHRONOUS，以及 pthread_setcancelstate()/pthread_setcanceltype() API。

要点

取消状态 (State)

状态 说明
PTHREAD_CANCEL_ENABLE 接受取消请求（默认）
PTHREAD_CANCEL_DISABLE 暂不接受取消请求，请求挂起待恢复后处理

取消类型 (Type)

类型 说明
PTHREAD_CANCEL_DEFERRED 延迟取消，到取消点才检查（默认）
PTHREAD_CANCEL_ASYNCHRONOUS 异步取消，任意时刻可被取消

核心 API

函数 原型 说明
pthread_setcancelstate(state, *oldstate) 设置取消状态 ENABLE/DISABLE
pthread_setcanceltype(type, *oldtype) 设置取消类型 DEFERRED/ASYNCHRONOUS
pthread_cancel(thread) 请求取消 发送取消请求
pthread_testcancel() 显式取消点 检查是否有挂起的取消请求

取消点 (Cancellation Points)

POSIX 定义了一组取消点函数，调用这些函数时会检查是否有挂起的取消请求：

取消点函数 说明
read(), write() I/O 操作
sleep(), nanosleep() 定时
waitpid() 等待子进程
pthread_cond_wait() 等待条件
select(), pselect() I/O 多路复用
accept(), connect() 网络
recv(), send() 网络
fopen(), fclose() stdio

非取消点：malloc()、free()、memcpy()、printf()、sin() 等纯计算函数。

异步取消的风险

PTHREAD_CANCEL_ASYNCHRONOUS:
  → 任意指令处可能被取消
  → 如果正在 malloc（持有堆锁）→ 死锁
  → 如果正在修改链表 → 数据结构损坏
  → 如果已锁 mutex 但未解锁 → 死锁

建议：除非确定线程在纯计算循环中等待取消，否则使用 DEFERRED。

禁用取消的典型场景

/* 临界区中禁止取消 */
int oldstate;
pthread_setcancelstate(PTHREAD_CANCEL_DISABLE, &oldstate);
/* 临界区操作（加锁、修改共享数据等） */
pthread_mutex_lock(&mutex);
shared_data = new_value;
pthread_mutex_unlock(&mutex);
pthread_setcancelstate(oldstate, NULL);  /* 恢复 */

HFT / 嵌入式关联

  • HFT 不用取消：HFT 线程通常用协作式退出（设置退出标志，线程自行检查）
  • 异步取消危险：可能导致锁未释放、内存泄漏、数据不一致
  • 嵌入式：RTOS 通常无取消机制，用任务删除 + 清理回调
  • 优雅关闭：HFT 策略线程收到关闭信号后完成当前订单再退出，不用 pthread_cancel

代码示例

#include <pthread.h>
#include <stdio.h>

void *worker(void *arg) {
    /* 默认 DEFERRED + ENABLE */
    while (1) {
        /* 在安全点检查取消 */
        pthread_testcancel();

        /* 临界区禁用取消 */
        int oldstate;
        pthread_setcancelstate(PTHREAD_CANCEL_DISABLE, &oldstate);
        /* 操作共享资源 */
        pthread_setcancelstate(oldstate, NULL);

        /* I/O 操作是取消点，可以安全取消 */
        char buf[256];
        read(fd, buf, sizeof(buf));   /* 取消点 */
    }
    return NULL;
}

/* 异步取消示例（仅用于纯计算线程） */
void *cpu_worker(void *arg) {
    int oldtype;
    pthread_setcanceltype(PTHREAD_CANCEL_ASYNCHRONOUS, &oldtype);
    while (1) {
        compute();  /* 纯计算，无锁无 I/O */
    }
    return NULL;
}

代码自测

1. DEFERRED 和 ASYNCHRONOUS 取消的区别？
  • DEFERRED（默认）：取消请求被挂起，直到线程到达取消点（如 read/write/pthread_cond_wait）才执行。保证在安全点取消。
  • ASYNCHRONOUS：取消请求可以在线程执行任意指令时生效。可能导致中途释放锁、损坏数据结构。除非纯计算线程，不建议使用。
2. 为什么在临界区要 DISABLE 取消？

如果线程在持有 mutex 时被取消，mutex 不会被自动释放（除非用 pthread_cleanup_push 注册清理函数），导致死锁。禁用取消确保临界区完整执行。恢复取消后，挂起的请求在下一个取消点生效。

3. pthread_testcancel() 做了什么？

检查当前线程是否有挂起的取消请求。如果有，立即执行取消（调用已注册的清理函数，然后线程退出）。如果没有，直接返回。它是一个显式创建的取消点，用于在不调用标准取消点函数的计算循环中提供取消机会。

32.7

Summary

本章：TLPI 第 32 章 — Thread Cancellation

本章回顾

取消 API 速查

函数 功能
pthread_cancel(thread) 请求取消线程
pthread_setcancelstate(state, *old) ENABLE / DISABLE
pthread_setcanceltype(type, *old) DEFERRED / ASYNCHRONOUS
pthread_testcancel() 显式取消点
pthread_cleanup_push(routine, arg) 注册清理函数
pthread_cleanup_pop(execute) 弹出并可选执行清理函数

取消流程

pthread_cancel(thread)
    │
    ▼
线程收到取消请求（挂起或立即）
    │
    ├─ DISABLE → 请求挂起，等恢复后处理
    ├─ DEFERRED → 到取消点执行
    └─ ASYNCHRONOUS → 任意时刻执行
    │
    ▼
执行清理函数栈（LIFO 顺序）
    │
    ▼
pthread_exit(PTHREAD_CANCELED)

清理函数

pthread_cleanup_push(cleanup_func, arg);
/* ... 代码 ... */
pthread_cleanup_pop(0);  /* 0=不执行，非0=执行 */
触发清理函数的情况 说明
pthread_cancel() 成功 DEFERRED 在取消点，ASYNCHRONOUS 任意时刻
pthread_exit() 线程主动退出
pthread_cleanup_pop(非0) 手动执行

不触发：return 不会执行清理函数（这是常见陷阱）

取消状态/类型组合

State Type 行为
ENABLE DEFERRED 到取消点才取消（最安全，默认）
ENABLE ASYNCHRONOUS 任意时刻取消（危险）
DISABLE 任意 请求挂起，不取消

HFT / 嵌入式关联

  • HFT 不用 pthread_cancel：用协作式退出（atomic flag + 循环检查）
  • 嵌入式：RTOS 用任务删除 + cleanup callback
  • 清理函数：用于释放锁/内存，但 return 不触发，必须用 pthread_exit

1. 为什么 return 不会触发清理函数？

POSIX 规定 pthread_cleanup_push/pop 必须在同一函数中成对出现（宏实现）。return 跳过了 pthread_cleanup_pop，清理函数不被执行。只有 pthread_exit() 或被取消时才触发。这是一个常见的内存/锁泄漏陷阱——应确保退出路径经过 pthread_exit 或显式 pop(1)。

2. 异步取消为什么几乎总是危险的？
  1. 可能在持有 mutex 时被取消 → 死锁
  2. 可能在 malloc 中间被取消 → 堆损坏
  3. 可能在修改数据结构中间被取消 → 数据不一致
  4. 清理函数本身可能也需要取消点，但异步取消下不安全
  5. 任何库函数内部状态可能不一致
