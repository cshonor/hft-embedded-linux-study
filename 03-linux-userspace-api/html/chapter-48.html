导读

章节目标

shmget/shmat/shmdt/shmctl；延迟 IPC_RMID；指针陷阱；shm+sem 模型；限额与对比。

优缺点

✅ 无拷贝、多进程同区。
❌ 非 fd、无 epoll「数据就绪」、须自管同步、内核持久易漏、API 老。
→ 新项目常选 POSIX shm + mmap。

拷贝对比：pipe/mq ≈ 两次拷贝；shm ≈ 零业务拷贝（仍有页表建立成本）。

SysV IPC 速记（四章收束）

mq sem shm
句柄 非 fd 非 fd 非 fd
持久 内核 内核 内核
RMID 立即标记 立即标记 等 nattch=0
角色 消息 同步 数据

思考题要点

  1. RMID 延迟到 nattch=0。
  2. attach/detach；exec 全 detach。
  3. 虚址不同 → offset。
  4. 无同步 → 竞态。
  5. attach++ / detach--；nattch=0 + DEST → 回收。
  6. pipe/mq 拷贝 vs shm 共享页。

背诵卡

# 要点
1 同物理页；无拷贝；须同步
2 shmat(NULL)；exec 自动 detach
3 RMID 延迟；看 shm_nattch
4 段内只用 offset
5 shm + sem 经典配对
6 新项目可 POSIX shm

代码示例

#include <stdio.h>
#include <sys/types.h>
#include <sys/ipc.h>
#include <sys/shm.h>
#include <string.h>
#include <unistd.h>
#include <sys/wait.h>

/* Ch48 SysV 共享内存 — shmget/shmat/shmdt。
 * 共享内存是最快的 IPC: 进程直接读写同一物理内存。
 * 编译: gcc -o ch48_demo ch48_demo.c */

#define SHM_SIZE 4096

int main(void) {
    /* 创建共享内存段 */
    int shmid = shmget(IPC_PRIVATE, SHM_SIZE, IPC_CREAT | 0666);
    if (shmid < 0) { perror("shmget"); return 1; }

    /* 父进程映射共享内存 */
    char *shm = shmat(shmid, NULL, 0);
    if (shm == (void *)-1) { perror("shmat"); return 1; }

    /* 写入初始数据 */
    strcpy(shm, "Hello from parent!");

    pid_t pid = fork();
    if (pid == 0) {
        /* 子进程: 映射同一共享内存段 */
        char *child_shm = shmat(shmid, NULL, 0);
        if (child_shm == (void *)-1) { perror("shmat child"); _exit(1); }

        printf("Child reads: %s\n", child_shm);

        /* 修改共享内存 */
        strcpy(child_shm, "Hello from child!");

        shmdt(child_shm);
        _exit(0);
    }

    waitpid(pid, NULL, 0);

    /* 父进程看到子进程的修改 */
    printf("Parent reads after child: %s\n", shm);

    /* 清理 */
    shmdt(shm);
    shmctl(shmid, IPC_RMID, NULL);
    return 0;
}

48.1

原理

本章：TLPI 第 48 章 — System V Shared Memory - 上一节：本章首页 - 下一节：48.2 –48.3 · 48.7 API

本节讲什么

多进程映射同一物理页 → 无用户↔内核数据拷贝。 本身不同步 → 须信号量/文件锁。 内核持久；detach ≠ 销毁。

要点

多进程映射同一物理页 → 无用户↔内核数据拷贝。
本身不同步 → 须信号量/文件锁。
内核持久；detach ≠ 销毁。
术语：SysV 说 attach/detach；mmap 说 map — 思想近、API 不同。

HFT / 嵌入式关联

路线 要点
嵌入式 多进程映射同一物理页，无用户↔内核拷贝
HFT 零拷贝共享行情/订单簿（无 memcpy），但需信号量同步；内核持久需清理

代码示例

#include <stdio.h>
#include <sys/shm.h>
#include <string.h>
#include <unistd.h>
#include <sys/wait.h>
/* 共享内存原理: 多个进程映射同一物理内存页 */
int main(void) {
    /* shmget: 在内核中分配共享内存段 */
    int shmid = shmget(IPC_PRIVATE, 4096, IPC_CREAT | 0666);
    printf("Shared memory segment: id=%d, size=4096\n", shmid);

    /* shmat: 将段映射到进程地址空间 */
    char *shm = shmat(shmid, NULL, 0);
    printf("Attached at: %p\n", (void *)shm);

    /* 父进程写入 */
    strcpy(shm, "Hello from parent!");

    pid_t pid = fork();
    if (pid == 0) {
        /* 子进程映射同一段, 看到相同数据 */
        char *child_shm = shmat(shmid, NULL, 0);
        printf("Child sees: %s\n", child_shm);
        strcpy(child_shm, "Modified by child!");
        shmdt(child_shm);
        _exit(0);
    }

    waitpid(pid, NULL, 0);
    printf("Parent sees: %s\n", shm);

    /* shmdt: 解除映射 (段仍然存在于内核中) */
    shmdt(shm);

    /* shmctl(IPC_RMID): 删除段 (标记删除, 引用计数归零时真正释放) */
    shmctl(shmid, IPC_RMID, NULL);
    return 0;
}

48.2

–48.3 · 48.7 API

本章：TLPI 第 48 章 — System V Shared Memory - 上一节：48.1 原理 - 下一节：48.6 陷阱：段内勿存指针

本节讲什么

size 向上对齐页；新建清零。返回 shmid。 - shmaddr=NULL：推荐（内核选址） - SHM_RDONLY：只读

要点

shmget(key, size, shmflg)

size 向上对齐页；新建清零。返回 shmid。

shmat(shmid, shmaddr, shmflg)

  • shmaddr=NULL：推荐（内核选址）
  • SHM_RDONLY：只读
  • 成功：起始虚址；失败：(void*)-1
  • fork 继承映射；exec 全部自动 detach

shmdt(addr)

解除本进程映射；不销毁内核段。进程退出时内核自动 detach。

shmctl · IPC_RMID（高频）

对象 IPC_RMID
mq / sem 立即标记删；新 get 失败
shm 仅 SHM_DEST；全部 shmdt（nattch=0）后才释放

IPC_STAT/IPC_SET：属性；关注 shm_nattch、shm_segsz。

Demo：code/

HFT / 嵌入式关联

路线 要点
嵌入式 shmget 向上对齐页新建清零；shmat NULL 推荐内核选址；exec 自动 detach
HFT shmat 映射共享段到地址空间；exec 自动 detach 防泄漏；IPC_RMID 需 nattch=0 才释放

代码示例

#include <stdio.h>
#include <sys/shm.h>
#include <string.h>
#include <time.h>
/* 共享内存 API: shmget/shmat/shmdt/shmctl */
int main(void) {
    /* shmget: 创建/获取共享内存段 */
    int shmid = shmget(IPC_PRIVATE, 4096, IPC_CREAT | 0666);
    printf("shmget: id=%d\n", shmid);

    /* shmat: 映射到地址空间
     * addr=NULL: 内核选择地址
     * shmflg: SHM_RDONLY (只读), SHM_RND (对齐)
     */
    char *shm1 = shmat(shmid, NULL, 0);
    char *shm2 = shmat(shmid, NULL, SHM_RDONLY);
    printf("shmat RW:  %p\n", (void *)shm1);
    printf("shmat RO:  %p\n", (void *)shm2);

    /* 写入数据 (通过 RW 映射) */
    strcpy(shm1, "API demo");

    /* shmctl: 控制 */
    struct shmid_ds ds;
    shmctl(shmid, IPC_STAT, &ds);
    printf("\nshmctl(IPC_STAT):\n");
    printf("  size:      %lu\n", (unsigned long)ds.shm_segsz);
    printf("  attaches:  %lu\n", (unsigned long)ds.shm_nattch);
    printf("  cpid:      %d (creator)\n", ds.shm_cpid);
    printf("  lpid:      %d (last op)\n", ds.shm_lpid);
    printf("  atime:     %s", ctime(&ds.shm_atime));

    /* shmdt: 解除映射 */
    shmdt(shm1);
    shmdt(shm2);

    /* IPC_RMID: 标记删除 (所有映射解除后才真正释放) */
    shmctl(shmid, IPC_RMID, NULL);
    printf("Marked for deletion\n");
    return 0;
}

48.3

Using Shared Memory

本章：TLPI 第 48 章

本节讲什么

shmat() 将共享内存段映射到进程虚拟地址空间，shmdt() 解除映射。映射后的内存区域可被多个进程直接读写，是最快的 IPC 方式。

要点

核心 API

#include <sys/shm.h>
void *shmat(int shmid, const void *shmaddr, int shmflg);
int shmdt(const void *shmaddr);

shmat() 参数

参数 含义
shmid shmget() 返回的共享内存 ID
shmaddr 期望映射地址（NULL 为自动选择）
shmflg SHM_RDONLY 只读 / 0 读写

映射地址选择

shmaddr shmflg 行为
NULL 任意 内核自动选择地址（推荐）
非 NULL 无 SHM_RND 尝试精确映射到指定地址
非 NULL SHM_RND 向下对齐到 SHMLBA

推荐使用 NULL：让内核选择可用地址，避免地址冲突。

使用流程

/* 1. 创建/获取共享内存 */
int shmid = shmget(key, size, IPC_CREAT | 0666);

/* 2. 映射到进程地址空间 */
void *addr = shmat(shmid, NULL, 0);
/* addr 现在指向共享内存 */

/* 3. 直接读写共享内存 */
memset(addr, 0, size);

/* 4. 解除映射 */
shmdt(addr);

/* 5. 删除共享内存 */
shmctl(shmid, IPC_RMID, NULL);

注意事项

问题 说明
非自动删除 shmdt 只是解除映射，段仍存在
删除时机 IPC_RMID 不立即删除，等所有映射解除后才回收
写入后再读取 需要内存屏障或同步机制保证可见性
多进程地址不同 不同进程映射到不同虚拟地址，用指针需用偏移
fork 继承 子进程继承映射

共享内存中的指针问题

/* 错误：指针在另一个进程中无效 */
struct shared_data {
    int count;
    char *name;  /* 在进程 A 中的地址，进程 B 无法使用 */
};

/* 正确：使用偏移量 */
struct shared_data {
    int count;
    size_t name_offset;  /* 相对于共享内存基址的偏移 */
};
/* 访问：base + name_offset */

同步需求

共享内存本身没有同步机制，必须配合： - 信号量（SysV 或 POSIX） - pthread 互斥锁（多进程共享需设置 PTHREAD_PROCESS_SHARED） - 原子操作（简单的 flag/counter）

HFT / 嵌入式关联

  • HFT 最快 IPC：行情数据通过共享内存传递，纳秒级延迟
  • 多策略进程共享行情快照：只读映射，避免拷贝
  • 嵌入式多进程共享配置/状态数据
  • 必须配合同步机制防止竞争

代码示例

#include <sys/shm.h>
#include <sys/ipc.h>
#include <string.h>
#include <stdio.h>

typedef struct {
    int seq;
    int valid;
    char data[4096];
} shared_state_t;

int main() {
    /* 创建共享内存 */
    int shmid = shmget(IPC_PRIVATE, sizeof(shared_state_t),
                       IPC_CREAT | 0666);
    if (shmid == -1) { perror("shmget"); return 1; }

    /* 父进程映射 */
    shared_state_t *state = shmat(shmid, NULL, 0);
    if (state == (void*)-1) { perror("shmat"); return 1; }

    /* 初始化 */
    memset(state, 0, sizeof(*state));

    /* fork 子进程 */
    pid_t pid = fork();
    if (pid == 0) {
        /* 子进程映射（fork 自动继承，也可手动 shmat） */
        /* state 已继承 */
        for (int i = 0; i < 10; i++) {
            while (!state->valid);  /* 忙等（简化，实际需锁） */
            printf("Child read: seq=%d\n", state->seq);
            state->valid = 0;
        }
        shmdt(state);
        _exit(0);
    }

    /* 父进程写入 */
    for (int i = 0; i < 10; i++) {
        state->seq = i;
        snprintf(state->data, sizeof(state->data), "msg-%d", i);
        state->valid = 1;
        usleep(10000);  /* 等子进程读取 */
    }

    waitpid(pid, NULL, 0);

    shmdt(state);
    shmctl(shmid, IPC_RMID, NULL);
    return 0;
}

代码自测

shmdt() 后共享内存段会被删除吗？

不会。shmdt() 只是解除当前进程的映射，共享内存段仍然存在。即使调用了 shmctl(shmid, IPC_RMID, NULL)，段也不会立即删除——它被标记为"待删除"，直到所有进程都调用 shmdt 解除映射后才真正回收。这个设计确保正在使用共享内存的进程不会被中断。

48.4

工程模型

本章：TLPI 第 48 章 — System V Shared Memory - 上一节：48.6 陷阱：段内勿存指针 - 下一节：48.9 限额 · 运维

本节讲什么

SysV sem（互斥/握手）+ SysV shm（大数据） → 一方 IPC_RMID 打标 → 各方 shmdt → 回收。 ---

要点

SysV sem（互斥/握手）+ SysV shm（大数据） → 一方 IPC_RMID 打标 → 各方 shmdt → 回收。

HFT / 嵌入式关联

路线 要点
嵌入式 SysV sem（互斥/握手）+ SysV shm（大数据）经典组合
HFT 信号量保护共享内存是跨进程 IPC 经典模型；一方 IPC_RMID 打标，各方 shmdt 回收

代码示例

#include <stdio.h>
#include <sys/shm.h>
#include <sys/sem.h>
#include <string.h>
#include <unistd.h>
#include <sys/wait.h>
/* 共享内存 + 信号量: 经典 IPC 模型 */
union semun { int val; };

int main(void) {
    /* 创建共享内存 + 信号量 */
    int shmid = shmget(IPC_PRIVATE, 256, IPC_CREAT | 0666);
    int semid = semget(IPC_PRIVATE, 1, IPC_CREAT | 0666);

    /* 信号量初始化为 1 (mutex) */
    union semun arg = {.val = 1};
    semctl(semid, 0, SETVAL, arg.val);

    /* 映射共享内存 */
    char *shm = shmat(shmid, NULL, 0);
    shm[0] = '\0';  /* 初始为空字符串 */

    pid_t pid = fork();
    if (pid == 0) {
        char *child_shm = shmat(shmid, NULL, 0);
        struct sembuf lock = {0, -1, 0};
        struct sembuf unlock = {0, 1, 0};

        /* 获取锁 -> 写数据 -> 释放锁 */
        semop(semid, &lock, 1);
        strcat(child_shm, "child wrote; ");
        semop(semid, &unlock, 1);

        shmdt(child_shm);
        _exit(0);
    }

    /* 父进程也写 */
    struct sembuf lock = {0, -1, 0};
    struct sembuf unlock = {0, 1, 0};
    semop(semid, &lock, 1);
    strcat(shm, "parent wrote; ");
    semop(semid, &unlock, 1);

    waitpid(pid, NULL, 0);
    printf("Shared content: %s\n", shm);

    shmdt(shm);
    shmctl(shmid, IPC_RMID, NULL);
    semctl(semid, 0, IPC_RMID);
    return 0;
}

48.5

Location of Shared Memory in Virtual Memory

本章：TLPI 第 48 章

本节讲什么

shmat() 返回的虚拟地址由内核选择。了解共享内存的映射位置规则、SHMLBA 对齐要求，以及不指定地址时的风险和限制。

要点

虚拟地址空间布局

高地址 ┌──────────────────────┐
       │ 内核空间                │
       ├──────────────────────┤
       │ 栈 ↓                   │
       │                       │
       │ 共享内存映射区           │ ← shmat 返回地址
       │                       │
       │ 堆 ↑                   │
       ├──────────────────────┤
       │ BSS/Data/Text          │
低地址 └──────────────────────┘

SHMLBA 对齐

#define SHMLBA 0x40000  /* 256KB (页面大小 × 倍数) */
情况 要求
shmaddr=NULL 内核自动选择，总是对齐
shmaddr 非 NULL, 无 SHM_RND 必须页对齐（4KB）
shmaddr 非 NULL, 有 SHM_RND 向下对齐到 SHMLBA

不同进程地址不同

进程 A 进程 B
0x7f1234560000 0x7f4567890000
不同的虚拟地址 指向同一物理内存

结论：共享内存中的指针在不同进程间无效，必须使用相对偏移。

地址选择策略

方法 优点 缺点
shmat(shmid, NULL, 0) 简单安全 各进程地址不同
指定固定地址 各进程地址一致 地址冲突风险
mmap(MAP_SHARED) 替代 更灵活 非 SysV API

/proc/sysvipc/shm

# key shmid perms size cpid lpid natt uid gid

shmaddr 固定地址的风险

/* 危险：固定地址可能与已有映射冲突 */
void *addr = shmat(shmid, (void*)0x10000000, 0);
/* 如果 0x10000000 已被使用，返回 -1 errno=EINVAL */

/* 更安全：使用 NULL */
void *addr = shmat(shmid, NULL, 0);
/* 内核选择可用地址 */

使用 mmap 替代

/* POSIX mmap 方式（更推荐） */
void *addr = mmap(NULL, size, PROT_READ | PROT_WRITE,
                  MAP_SHARED | MAP_ANONYMOUS, -1, 0);
/* 或基于文件 */
int fd = shm_open("/myshm", O_CREAT | O_RDWR, 0666);
ftruncate(fd, size);
void *addr = mmap(NULL, size, PROT_READ | PROT_WRITE,
                  MAP_SHARED, fd, 0);

HFT / 嵌入式关联

  • HFT 共享内存不指定地址（NULL），避免冲突
  • 多进程共享行情数据时使用偏移量而非绝对指针
  • 嵌入式固定地址映射需确保地址空间不冲突
  • 现代推荐使用 mmap + shm_open 替代 SysV 共享内存

代码示例

#include <sys/shm.h>
#include <stdio.h>
#include <string.h>

/* 安全的共享内存使用模式 */
void *safe_shmat(int shmid) {
    void *addr = shmat(shmid, NULL, 0);
    if (addr == (void*)-1) return NULL;
    return addr;
}

/* 使用偏移量而非指针的共享结构 */
typedef struct {
    int seq;
    size_t name_offset;  /* 偏移而非指针 */
    char pool[4096];    /* 字符串存储池 */
} shared_data_t;

/* 在共享内存中存储字符串，返回偏移量 */
size_t shared_strdup(shared_data_t *s, const char *str) {
    size_t off = s->name_offset;
    strncpy(s->pool + off, str, 4096 - off - 1);
    s->name_offset += strlen(str) + 1;
    return off;
}

/* 从偏移量读取字符串 */
const char *shared_getstr(shared_data_t *s, size_t off) {
    return s->pool + off;
}

代码自测

为什么不同进程 shmat 返回的地址可能不同？

每个进程有自己的虚拟地址空间，内核为每个进程独立选择映射地址。同一个物理内存页可以映射到不同进程的不同虚拟地址。内核选择映射地址时会避开已有的映射区域（代码段、堆、栈、其他共享内存等），因此不同进程的虚拟地址空间布局不同，导致同一个共享内存段映射到不同地址。

48.6

陷阱：段内勿存指针

本章：TLPI 第 48 章 — System V Shared Memory - 上一节：48.2 –48.3 · 48.7 API - 下一节：48.4 工程模型

本节讲什么

各进程映射虚址可能不同 → 绝对指针在对方无效 → SIGSEGV。 ✅ 只存相对段基址的 offset（或固定布局 struct，无堆指针）。 ---

要点

各进程映射虚址可能不同 → 绝对指针在对方无效 → SIGSEGV。
✅ 只存相对段基址的 offset（或固定布局 struct，无堆指针）。

HFT / 嵌入式关联

路线 要点
嵌入式 跨进程/跨核共享段虚址不同，只存 offset + 固定布局 POD struct，杜绝绝对指针失效
HFT 订单簿/行情环形缓冲按 offset 寻址，多进程读写同一段无 SIGSEGV，免指针解引用

代码示例

#include <stdio.h>
#include <sys/shm.h>
#include <string.h>
/* 共享内存中的指针陷阱: 不能存指针! */
typedef struct {
    int count;
    char name[64];
    /* 不要在这里放指针! */
    /* char *ptr;  // 错误: 指针在不同进程中地址不同 */
} shared_data_t;

int main(void) {
    int shmid = shmget(IPC_PRIVATE, sizeof(shared_data_t),
                       IPC_CREAT | 0666);
    shared_data_t *data = shmat(shmid, NULL, 0);

    /* 正确: 使用偏移量或内联数据 */
    data->count = 42;
    strcpy(data->name, "inline data (OK)");

    printf("count=%d name=%s\n", data->count, data->name);

    /* 陷阱: 如果在共享内存中存了指针, 指针值在另一个进程中无效 */
    /* 因为不同进程的地址空间布局不同 */
    printf("\nPointer pitfall: pointers in shared memory are INVALID\n");
    printf("  Use offsets or inline data instead\n");

    shmdt(data);
    shmctl(shmid, IPC_RMID, NULL);
    return 0;
}

48.7

Shared Memory Control Operations

本章：TLPI 第 48 章

本节讲什么

shmctl() 是 System V 共享内存的控制接口，用于获取/设置属性、删除共享内存段等操作。

要点

shmctl() 函数

#include <sys/shm.h>
int shmctl(int shmid, int cmd, struct shmid_ds *buf);

命令一览

cmd 说明 需要 buf
IPC_RMID 标记删除（等所有 detatch 后回收） 否
IPC_STAT 获取 shmid_ds 是
IPC_SET 修改权限 是
SHM_LOCK 锁定在物理内存（禁止换出） 否
SHM_UNLOCK 解锁（允许换出） 否
SHM_INFO 系统级统计信息 是
SHM_STAT 类似 IPC_STAT（用 shmid 作索引） 是

SHM_LOCK / SHM_UNLOCK

/* 锁定共享内存，防止换出到 swap */
shmctl(shmid, SHM_LOCK, NULL);
/* 这等效于对每个映射进程的 mlockall */
/* 但只锁定该段，不影响其他内存 */
操作 效果 权限
SHM_LOCK 禁止换出，保证访问不产生缺页 root 或 CAP_IPC_LOCK
SHM_UNLOCK 允许换出 root 或 CAP_IPC_LOCK

删除时机

shmctl(shmid, IPC_RMID, NULL);
  ↓
标记为"待删除"
  ↓
等待所有进程 shmdt()
  ↓
最后进程 shmdt 后，内核回收物理内存

重要：即使标记删除后，仍可通过 shmat 映射（不推荐）。

#include <sys/shm.h>
#include <stdio.h>
#include <time.h>

void lock_shared_memory(int shmid) {
    if (shmctl(shmid, SHM_LOCK, NULL) == -1) {
        perror("shmctl SHM_LOCK");
    } else {
        printf("Shared memory %d locked in RAM\n", shmid);
    }
}

void monitor_shm(int shmid) {
    struct shmid_ds ds;
    if (shmctl(shmid, IPC_STAT, &ds) == -1) {
        perror("shmctl IPC_STAT");
        return;
    }

    time_t now = time(NULL);
    printf("=== Shared Memory Segment %d ===\n", shmid);
    printf("Size:          %zu bytes\n", ds.shm_segsz);
    printf("Attaches:      %lu\n", ds.shm_nattch);
    printf("Creator PID:   %d\n", ds.shm_cpid);
    printf("Last op PID:   %d\n", ds.shm_lpid);
    if (ds.shm_atime)
        printf("Last attach:   %ld sec ago\n", now - ds.shm_atime);
    if (ds.shm_dtime)
        printf("Last detach:   %ld sec ago\n", now - ds.shm_dtime);
    printf("Last change:   %ld sec ago\n", now - ds.shm_ctime);
    printf("Permissions:   %04o\n", ds.shm_perm.mode);

    if (ds.shm_nattch == 0)
        printf("WARNING: 0 attaches - can be safely removed\n");
}

/* 安全删除：等待所有进程 detach */
void safe_remove(int shmid) {
    /* 标记删除 */
    if (shmctl(shmid, IPC_RMID, NULL) == -1) {
        perror("shmctl IPC_RMID");
        return;
    }

    /* 等待 nattch 变为 0（实际中可能需要超时） */
    struct shmid_ds ds;
    do {
        usleep(100000);
        if (shmctl(shmid, IPC_STAT, &ds) == -1) break;
    } while (ds.shm_nattch > 0);

    printf("Shared memory %d fully removed\n", shmid);
}

代码自测

IPC_RMID 后共享内存段是否立即消失？如果还有进程映射着会怎样？

不立即消失。IPC_RMID 只是给段标记"待删除"标志。此时新的 shmat 调用会失败（EIDRM），但已经映射的进程仍能正常访问。段会在最后一个映射进程调用 shmdt 后才真正被回收物理内存。这个设计保证了正在使用共享内存的进程不会被中断。可以通过 ipcs -m 的 status 列看到 dest 标记。

shm_nattch 为 0 但段仍然存在，这是什么情况？

shm_nattch 为 0 表示没有进程映射该段，但段尚未被 IPC_RMID 删除。SysV 共享内存是内核持久的——即使没有使用者，段也保留在内核中直到显式删除。这是 SysV IPC 的设计缺陷：进程崩溃后不会自动清理，导致资源泄漏。需要用 ipcrm -m <shmid> 手动清理。

代码自测

为什么共享内存需要同步机制？没有同步会怎样？

共享内存允许多个进程同时读写同一块物理内存，但内核不提供任何同步保证。如果两个进程同时修改同一数据结构（如链表、计数器），会产生数据竞争：读写交错导致数据损坏、计数错误、链表断裂等问题。必须使用信号量、互斥锁或原子操作确保关键区的互斥访问。这是共享内存作为最快 IPC 的代价：性能最高，但同步责任完全由程序员承担。

练习 1：共享内存 + 信号量

题目：使用 SysV 共享内存和信号量实现多进程共享计数器。多个进程并发递增共享计数器，确保原子性。

参考答案 
#include <sys/shm.h>
#include <sys/sem.h>
#include <unistd.h>
#include <stdio.h>

union semun { int val; struct semid_ds *buf; unsigned short *array; };

typedef struct {
    int semid;
    int shmid;
    volatile int counter;
} shared_counter_t;

shared_counter_t *sc_create(int initial) {
    int shmid = shmget(IPC_PRIVATE, sizeof(shared_counter_t),
                       IPC_CREAT | 0666);
    int semid = semget(IPC_PRIVATE, 1, IPC_CREAT | 0666);

    shared_counter_t *sc = shmat(shmid, NULL, 0);
    sc->shmid = shmid;
    sc->semid = semid;
    sc->counter = initial;

    /* 初始化信号量为 1（互斥锁） */
    union semun arg = {.val = 1};
    semctl(semid, 0, SETVAL, arg);
    return sc;
}

void sc_increment(shared_counter_t *sc) {
    struct sembuf op = {.sem_num = 0, .sem_op = -1, .sem_flg = SEM_UNDO};
    semop(sc->semid, &op, 1);    /* P */
    sc->counter++;                /* 临界区 */
    op.sem_op = 1;
    semop(sc->semid, &op, 1);    /* V */
}

int sc_read(shared_counter_t *sc) {
    struct sembuf op = {.sem_num = 0, .sem_op = -1, .sem_flg = SEM_UNDO};
    semop(sc->semid, &op, 1);
    int val = sc->counter;
    op.sem_op = 1;
    semop(sc->semid, &op, 1);
    return val;
}

void sc_destroy(shared_counter_t *sc) {
    int shmid = sc->shmid, semid = sc->semid;
    shmdt(sc);
    shmctl(shmid, IPC_RMID, NULL);
    semctl(semid, 0, IPC_RMID);
}

练习 2：共享内存中的环形缓冲区

题目：在共享内存中实现无锁单生产者单消费者环形缓冲区。

参考答案 
#include <sys/shm.h>
#include <stdatomic.h>

#define BUF_SIZE 4096  /* 2 的幂，方便取模 */

typedef struct {
    atomic_uint head;  /* 生产者写位置 */
    atomic_uint tail;  /* 消费者读位置 */
    char data[BUF_SIZE];
} ringbuf_t;

ringbuf_t *rb_create(void) {
    int shmid = shmget(IPC_PRIVATE, sizeof(ringbuf_t),
                       IPC_CREAT | 0666);
    ringbuf_t *rb = shmat(shmid, NULL, 0);
    atomic_store(&rb->head, 0);
    atomic_store(&rb->tail, 0);
    return rb;
}

/* 生产者写入（单线程） */
int rb_write(ringbuf_t *rb, const char *src, size_t len) {
    unsigned head = atomic_load_explicit(&rb->head,
                                          memory_order_relaxed);
    unsigned tail = atomic_load_explicit(&rb->tail,
                                          memory_order_acquire);
    size_t free = BUF_SIZE - (head - tail);
    if (len > free) return -1;  /* 满了 */

    for (size_t i = 0; i < len; i++)
        rb->data[(head + i) % BUF_SIZE] = src[i];

    atomic_store_explicit(&rb->head, head + len,
                           memory_order_release);
    return len;
}

/* 消费者读取（单线程） */
int rb_read(ringbuf_t *rb, char *dst, size_t len) {
    unsigned tail = atomic_load_explicit(&rb->tail,
                                          memory_order_relaxed);
    unsigned head = atomic_load_explicit(&rb->head,
                                          memory_order_acquire);
    size_t avail = head - tail;
    if (avail == 0) return -1;  /* 空了 */
    size_t n = (len < avail) ? len : avail;

    for (size_t i = 0; i < n; i++)
        dst[i] = rb->data[(tail + i) % BUF_SIZE];

    atomic_store_explicit(&rb->tail, tail + n,
                           memory_order_release);
    return n;
}

练习 3：共享内存泄漏

题目：一个程序创建了共享内存但未调用 IPC_RMID 就退出了。如何发现并清理？

参考答案 
# 1. 查看系统所有共享内存段
ipcs -m

# 输出示例:
# key       shmid owner perms bytes nattch status
# 0xabcd1234 0     hft   660   4096  0

# 2. nattch=0 且 status 为空 → 残留段
# 3. 删除
ipcrm -m 0

# 或用 key 删除
ipcrm -M 0xabcd1234

# 4. 验证
ipcs -m

残留段的特征：nattch=0（无进程映射），status 列为空（非 dest）。这些段占用物理内存直到系统重启或手动删除。嵌入式系统应在启动脚本中清理。
