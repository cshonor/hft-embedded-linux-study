## 要点

```c
#include <sys/acl.h>
#include <acl/libacl.h>   /* 视发行版；部分声明在 sys/acl.h */

acl_t acl_get_file(const char *path, acl_type_t type);
int   acl_set_file(const char *path, acl_type_t type, acl_t acl);
/* type: ACL_TYPE_ACCESS / ACL_TYPE_DEFAULT */

int acl_get_entry(acl_t acl, int entry_id, acl_entry_t *entry_p);
int acl_create_entry(acl_t *acl_p, acl_entry_t *entry_p);
int acl_set_tag_type(acl_entry_t entry_d, acl_tag_t tag_type);
int acl_set_qualifier(acl_entry_t entry_d, const void *qualifier_p);
int acl_set_permset(acl_entry_t entry_d, acl_permset_t permset_d);

int acl_valid(acl_t acl);
void acl_free(void *obj_p);
```

编程要点：

1. 扩展 ACL **手写 MASK**  
2. 写入前 `acl_valid()`  
3. 用完 `acl_free()`  
4. FS 需支持 ACL（现代 ext4 等通常默认可用）  

Demo：[`code/print_acl.c`](./code/print_acl.c) · [`code/set_named_user_acl.c`](./code/set_named_user_acl.c)

## 与 C 语言学习的关系

权限与凭证管理是 Unix 系统编程的重要主题。C 语言中 `uid_t`/`gid_t` 是整数类型，理解 setuid 程序的 real/effective/saved UID 切换需要扎实的 C 语言基础。这部分内容对应 K&R 中文件权限的基础概念，并在 HFT 场景中涉及特权端口的绑定和权限降级。

## 常见陷阱

1. **TOCTOU 竞态**

```c
if (access("f.txt", R_OK) == 0) {
    /* 攻击者在此期间替换文件 */
    fd = open("f.txt", O_RDONLY);
}
```

access() 和 open() 之间文件可能被替换（TOCTOU）。应直接 open 并检查错误，或用 fstat 验证已打开的 fd。

2. **setuid 程序未降权**

```c
/* setuid root 程序 */
fd = open("/etc/shadow", O_RDONLY);
/* ... 处理 ... */
/* 忘记降权就执行用户代码 → 提权! */
```

setuid 程序应在完成特权操作后立即降权（seteuid(getuid())），遵循最小权限原则。

3. **混淆 real UID 和 effective UID**

```c
/* real UID: 启动进程的用户 */
/* effective UID: 当前有效权限 */
/* setuid 程序中两者不同! */
```

real UID 是登录用户，effective UID 决定当前权限。setuid 程序中 effective UID 变为文件属主。

## 自测题

**题目 1（选择）：** setuid 程序执行时，哪个 UID 会改变？
A. real UID
B. effective UID
C. saved set-user-ID
D. 所有 UID

<details>
<summary>参考答案</summary>

B。setuid 程序执行时 effective UID 变为文件属主的 UID。real UID 不变。saved set-user-ID 也被设为 effective UID。

</details>

**题目 2（判断）：** `access()` 和 `open()` 组合使用是安全的权限检查方式。

<details>
<summary>参考答案</summary>

错误。access() 基于 real UID 检查，open() 基于 effective UID。而且两者之间有 TOCTOU 竞态。应直接 open 并检查。

</details>

**题目 3（踩坑）：** 以下 setuid root 程序有什么安全隐患？
```c
int main() {
    system("ls /root");
}
```

<details>
<summary>参考答案</summary>

system() 调用 shell，shell 会解析 PATH 环境变量。攻击者可以修改 PATH 让恶意程序替代 ls。setuid 程序应直接用 execve 指定完整路径。

</details>

**题目 4（应用）：** 写代码：setuid 程序先打开特权文件，然后降权到普通用户。

<details>
<summary>参考答案</summary>

```c
int fd = open("/etc/shadow", O_RDONLY);
if (fd < 0) { perror("open"); exit(1); }
/* 立即降权 */
seteuid(getuid());
/* 现在以普通用户身份运行 */
```

</details>
