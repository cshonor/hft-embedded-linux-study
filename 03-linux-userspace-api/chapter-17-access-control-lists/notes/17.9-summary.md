# 17.9 Summary

> 本章：[TLPI 第 17 章 — Access Control Lists](../README.md)

## 本章回顾

### ACL 核心概念

| 概念 | 说明 |
|------|------|
| ACL | 扩展文件权限，突破传统 owner/group/other 三级模型 |
| POSIX 1003.1e draft 17 | Linux 实现的 ACL 标准（libacl） |
| minimum ACL | 仅含 USER_OBJ + GROUP_OBJ + OTHER（等价传统权限） |
| extended ACL | 含 ACL_USER / ACL_GROUP / ACL_MASK，超出传统模型 |

### ACL 条目类型一览

| 条目 | 含义 | 传统对应 |
|------|------|---------|
| `ACL_USER_OBJ` | 属主权限 | owner |
| `ACL_USER` | 额外用户权限 | 无 |
| `ACL_GROUP_OBJ` | 属组权限 | group |
| `ACL_GROUP` | 额外组权限 | 无 |
| `ACL_MASK` | 有效权限上限 | 无（当有 extended 条目时自动出现） |
| `ACL_OTHER` | 其他用户 | other |

### access ACL vs default ACL

| 类型 | 适用对象 | 用途 |
|------|---------|------|
| `ACL_TYPE_ACCESS` | 文件 + 目录 | 当前对象的实际权限 |
| `ACL_TYPE_DEFAULT` | 仅目录 | 新建子项继承的模板 |

### 命令行工具

| 命令 | 功能 |
|------|------|
| `getfacl file` | 查看 ACL |
| `setfacl -m u:alice:rw file` | 修改 ACL |
| `setfacl -x u:alice file` | 删除条目 |
| `setfacl -b file` | 移除所有 extended ACL |
| `setfacl -d -m g:dev:rwx dir` | 设置 default ACL |
| `setfacl --set u::rwx,g::rx,o::r file` | 覆盖整个 ACL |

### libacl API 汇总

| 操作 | 函数 |
|------|------|
| 获取 | `acl_get_file()`, `acl_get_fd()` |
| 设置 | `acl_set_file()`, `acl_set_fd()` |
| 遍历 | `acl_get_entry()` |
| 读取 | `acl_get_tagtype()`, `acl_get_qualifier()`, `acl_get_permset()`, `acl_get_perm()` |
| 修改 | `acl_create_entry()`, `acl_set_tagtype()`, `acl_set_qualifier()`, `acl_set_permset()`, `acl_add_perm()`, `acl_delete_perm()` |
| 校验 | `acl_valid()` |
| 释放 | `acl_free()` |
| 文本转换 | `acl_to_text()`, `acl_from_text()` |

### 权限检查流程（内核视角）

```
进程访问文件 →
1. 是属主？ → 查 ACL_USER_OBJ
2. 匹配 ACL_USER？ → 查该条目 & ACL_MASK
3. 是属组或匹配 ACL_GROUP？ → 查该条目 & ACL_MASK
4. 其他 → 查 ACL_OTHER
```

```bash
gcc -o acl_demo acl_demo.c -lacl
```

## HFT / 嵌入式关联

- HFT 系统通常以单一服务用户运行，ACL 使用较少，但在多团队共享数据目录场景下有用
- 嵌入式：libacl 依赖 libattr，精简 rootfs 可能不含；`busybox` 的 `setfacl`/`getfacl` 是简化版

## 代码自测

<details>
<summary>1. minimum ACL 和 extended ACL 的区别？</summary>

- **minimum ACL**：仅含 `ACL_USER_OBJ` + `ACL_GROUP_OBJ` + `ACL_OTHER`，完全等价于传统的 9 位权限模式（rwxrwxrwx）
- **extended ACL**：添加了 `ACL_USER` / `ACL_GROUP` / `ACL_MASK` 条目，突破传统模型，允许为额外用户/组单独设置权限
</details>

<details>
<summary>2. `getfacl` 输出中 `#effective:` 标记是什么含义？</summary>

当存在 `ACL_MASK` 时，`getfacl` 显示每个受掩码影响的条目的名义权限和有效权限。`#effective:` 后面是经过掩码 AND 运算后的实际有效权限。例如：

```
group:dev:rw-    #effective:r--     ← MASK 只有 r
```

表示 dev 组的名义权限是 `rw-`，但因 MASK 限制实际只有 `r--`。
</details>
