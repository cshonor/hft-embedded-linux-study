## 算法本体（switch 语义，与 15.4.3 一脉相承）

```
① euid == 文件属主            → ACL_USER_OBJ，结束（mask 不参与）
② euid 命中某条 ACL_USER      → 该条 AND mask（若有），结束
③ egid==属组 或 补充组命中
   ACL_GROUP_OBJ / ACL_GROUP  → 命中可能多条（OR：交完 mask 后任一允许即允许），结束
④ 都没命中                    → ACL_OTHER，结束（mask 不参与）
```

三条铁律（每条都有实测输出对应）：
1. **属主只看 USER_OBJ**——named user 给属主更大权限也没用；
2. **mask 只约束②③两类条目**，对 owner / other 无效；
3. **组类命中是 OR**：多条命中时一条允许就允许（15.4.3 的"属组不叠加"在 ACL 里反而变成 OR）。

## 实测（c17_1，全部与书上的算法一致）

```text
== ACL: user::rw- user:1001:r-- group::r-- group:1002:-wx mask::rw- other::r-- ==
== 文件属主=1000，属组=1003 ==

  uid=1000 属主         求 r → 允许  [① euid==属主 → ACL_USER_OBJ（mask 不参与）]
  uid=1001 named user   求 r → 允许  [② 命中 named user → 该条 AND mask]
  uid=1001 named user   求 w → 拒绝  [② 命中 named user → 该条 AND mask]
  uid=1002 ∈组1002      求 w → 允许  [③④ 组类命中 → 该条 AND mask（多条 OR）]
  uid=1002 ∈组1002      求 x → 拒绝  [③④ 组类命中 → 该条 AND mask（多条 OR）]
  uid=2000 ∈组1003      求 r → 允许  [③④ 组类命中 → 该条 AND mask（多条 OR）]
  uid=2000 路人         求 r → 允许  [④ 未命中 → ACL_OTHER（mask 不参与）]

== mask 清零：named/组全灭，属主与 other 不受影响 ==
  属主 1000 求 r  → 允许（mask 对 owner 无效，仍走 rw-）
  named 1001 求 r → 拒绝（mask 生效，r-- 交 0 = 0）
  路人 2000 求 r  → 允许（mask 对 other 无效，仍走 r--）
```

注意 `uid=1002 求 x`：named group 明明给了 `-wx`，但 mask 是 `rw-`——交完只剩 `-w-`，x 拒绝。**这一单条就是 mask 的全部意义**。

## 常见坑

| 坑 | 正解 |
|----|------|
| 给属主加 named user 条目想放大属主权限 | 无效：属主判定永远走 USER_OBJ |
| mask 被自动改小后"权限莫名其妙没了" | named/group 条目受 mask 约束；`setfacl -m m::rwx` 手动放开 |
| 认为组类条目要全部满足 | OR 不是 AND；一条交完 mask 后允许即允许 |
| 把 15.4 的"属组不叠加"直接搬到 ACL | 传统权限里"选中即定"，ACL 组类是多条 OR——两处语义不同 |

## HFT / 嵌入式关联

| 场景 | 本节机制怎么兑现 |
|------|----------------|
| 权限排查 | 先确定身份命中哪一类（①→④），再看该类的"原始 AND mask"——定位路径固定 |
| 工具轮换 | 服务账户的补充组变化会静默改变命中路径——变更管理要把"组身份"当配置 |
| 复现/单测 | 判定算法是纯逻辑（本 demo），可以把生产 ACL 抽出来做离线单测 |

<details>
<summary>代码自测（Q&A）</summary>

**Q1：mask 清零后为什么属主还能写？**
A：算法①里属主只看 USER_OBJ，mask 不参与——实测允许。named user 同样的 r-- 交 0 直接拒绝。

**Q2：named group 给 -wx、mask 是 rw-，组内成员能执行吗？**
A：不能。-wx AND rw- = -w-。实测"uid=1002 求 x → 拒绝"。

**Q3：多个组条目同时命中，一个 rwx 一个 ---，怎么算？**
A：逐条与 mask 求交后 **OR**：rwx 那条允许即允许。

**Q4：named user 条目命中后还需要查组吗？**
A：不需要——②命中即结束（无论结果允许/拒绝）。这就是"switch 语义"。

</details>
