## 本节讲什么

传统 9 位权限只能表达「属主 / 属组 / 其他」三个身份的 rwx。ACL（访问控制列表）在这之上加**任意多条**的"指定用户/指定组"条目——精确到人的授权。本节钉住：

1. ACL 条目的 6 种 tag 与"最小 ACL / 扩展 ACL"的分界；
2. ACL 存在哪：`system.posix_acl_access` xattr（Ch16 的直接应用）；
3. 为什么 `ls -l` 会多出一个 `+`。

---

## 要点：6 种条目

| tag | 文本形式 | 数量 | 语义 |
|-----|---------|------|------|
| ACL_USER_OBJ | `user::rwx` | 恰 1 | 文件属主的权限 |
| ACL_USER | `user:1001:r--` | 0..n | 指定 uid 的权限 |
| ACL_GROUP_OBJ | `group::r-x` | 恰 1 | 文件属组的权限 |
| ACL_GROUP | `group:devs:rwx` | 0..n | 指定 gid 的权限 |
| ACL_MASK | `mask::rwx` | 0/1 | named/group 类的**上限**（17.4） |
| ACL_OTHER | `other::r--` | 恰 1 | 其他人的权限 |

**最小 ACL** = USER_OBJ + GROUP_OBJ + OTHER 三条（正好映射传统 9 位权限）。
**扩展 ACL** = 上述 + 任意 named 条目；一旦有 named 条目，**mask 变成必选**（内核自动生成/维护）。

## ACL 落在哪

```
system.posix_acl_access   ← 文件的 ACL（Ch16 xattr 的直接应用）
system.posix_acl_default  ← 目录的 default ACL（17.6）
```

权限语义：与文件本身绑定（读写 ACL = 读写文件的属主/特权）。

**`ls -l` 的 `+`**：扩展 ACL 存在时 `ls -l` 尾部显示 `+`，且 group 位显示的实际是 **mask**（不是 GROUP_OBJ）——这是最经典的混淆点（17.4 展开）。

## 平台现实（诚实标注）

| 平台 | POSIX draft ACL | 备注 |
|------|----------------|------|
| Linux + ext4/xfs | ✅ 完整 | 本章的"真机"；`getfacl/setfacl` 可用 |
| Linux + tmpfs | ✅ | 支持（实测平台候选） |
| macOS (APFS) | ❌ draft 无 | 只有 NFSv4 风格 ACL，API/语义完全不同 |
| 本机复现方式 | — | 判定算法纯逻辑复现（c17_1，实测通过） |

## HFT / 嵌入式关联

| 场景 | 本节机制怎么兑现 |
