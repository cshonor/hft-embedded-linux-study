## setfacl 四种用法（-m/-x/-b/--restore）

```bash
setfacl -m u:1001:rx,g:devs:rwx file     # 修改/添加条目（-m）
setfacl -x u:1001 file                    # 删除指定条目（-x）
setfacl -b file                           # 清掉全部扩展 ACL（回到最小 ACL）
setfacl -m m::rx file                     # 手动设 mask（n 选项可禁自动重算）
setfacl -M acl.txt file                   # 从文件批量导入（-m 的文件版）
setfacl --restore=acl.txt                 # getfacl 快照的整体恢复（含目录递归）
```

## getfacl 常用姿势

```bash
getfacl file                    # 长形式全量输出（#effective 注释带 mask 计算结果）
getfacl -R /srv/share > acl.txt # 目录树快照 → 进 git
getfacl file | setfacl --set-file=- otherfile   # 克隆 ACL
```

## 与 chmod 的关系（协议总结）

| 操作 | 生效位置 |
|------|---------|
| `chmod u±r` | USER_OBJ |
| `chmod g±r` | **mask**（有扩展 ACL 时）/ GROUP_OBJ（最小 ACL） |
| `chmod o±r` | OTHER |
| `setfacl -m u::…` | USER_OBJ（等价 chmod u 的精细版） |
| `setfacl -m m::…` | mask |

两个工具是**同一存储的两种视图**——它们的组合行为在 17.4 已钉死。

## 常见坑

| 坑 | 正解 |
|----|------|
| `setfacl -x g:devs` 后权限没变 | 删的是条目；mask 若仍在，剩余组类仍被压；必要时 `-x m::` 一并删 |
| `-b` 想当然"清 named 保留 mask" | -b 清**全部**扩展条目（含 mask），回到最小 ACL |
| 快照只存 stat | stat 丢 ACL；必须 getfacl 文本 |

## HFT / 嵌入式关联

| 场景 | 本节机制怎么兑现 |
|------|----------------|
