## 本节讲什么

信号驱动 I/O — 内核在 fd 可读/可写时发 `SIGIO` 信号，进程异步处理。

---

## 要点

### 工作流程

1. 设 fd 属主：`fcntl(fd, F_SETOWN, getpid())`
2. 启用非阻塞：`fcntl(fd, F_SETFL, O_NONBLOCK)`
3. 启用异步通知：`fcntl(fd, F_SETFL, O_ASYNC)`
4. 注册 `SIGIO` handler
5. fd 可读/可写时内核发 `SIGIO`

### 优缺点

| 优势 | 劣势 |
|------|------|
| 无需轮询 | 信号开销大（内核→用户态切换） |
| 不阻塞 | 标准 SIGIO 不携带 fd 信息 |
| 简单 | 竞态条件（信号与读取之间状态变化） |

### 实际应用

- 主要用于 UDP socket（TCP 的信号过于频繁）
- 被 `epoll` 完全取代 — 现代 Linux 不推荐使用
- 历史价值大于实用价值

### 与 epoll 的对比

| | 信号驱动 I/O | epoll |
|--|-------------|-------|
| 通知方式 | 信号 (SIGIO) | epoll_wait 返回事件 |
| fd 信息 | 不携带（需查询） | 携带（epoll_data_t） |
| 性能 | 差（信号开销） | 好（共享内存事件表） |
| 扩展性 | 差 | 好（O(1) 复杂度） |
| 推荐 | 不推荐 | 强烈推荐 |

---

## HFT / 嵌入式关联

| 路线 | 要点 |
|------|------|
| 嵌入式 | 旧嵌入式系统可能用信号驱动 I/O，新系统应迁移到 epoll |
| HFT | 不用信号驱动 I/O — 信号中断热路径有延迟抖动，用 epoll |

## 代码示例

```c
#include <stdio.h>
#include <fcntl.h>
#include <signal.h>
#include <unistd.h>
/* 信号驱动 I/O: SIGIO 通知 fd 可读 */
volatile sig_atomic_t data_ready = 0;
void handler(int sig) { data_ready = 1; }

int main(void) {
    int fd = open("/dev/null", O_RDONLY | O_NONBLOCK);

    /* 设属主 + 启用异步通知 */
    fcntl(fd, F_SETOWN, getpid());
    fcntl(fd, F_SETFL, O_ASYNC | O_NONBLOCK);

    /* 注册 SIGIO handler */
    signal(SIGIO, handler);

    /* 实际使用: 等待 data_ready, 然后 read(fd) */
    printf("signal-driven I/O setup complete\n");
    printf("(use epoll instead in production)\n");

    close(fd);
    return 0;
}
```
