### I/O 模型选型决策

| 需求 | 推荐 |
|------|------|
| 少量 fd, 简单 | 阻塞 I/O |
| 少量 fd, 需超时 | select |
| 中等 fd, 可移植 | poll |
| 大量 fd, 高性能 | **epoll (ET 模式)** |
| 信号 + fd 混合等待 | **signalfd + epoll** |
| 异步 I/O (Linux 5.1+) | io_uring |

### 核心要点

1. **epoll 是 Linux 高并发标准方案** — O(1) 复杂度
2. **ET 模式必须非阻塞 fd + 循环读到 EAGAIN**
3. **signalfd + epoll 统一事件循环** — 消除信号竞态
4. 信号驱动 I/O 已被 epoll 取代，不用
5. io_uring 是 Linux 最新异步 I/O 框架（超出 TLPI 范围）

## 代码自测

<details>
<summary>1. epoll 的 ET 模式为什么必须用非阻塞 fd？</summary>

ET 模式只在状态变化时通知一次。如果用阻塞 fd，read/recv 在缓冲区数据读完后会阻塞，导致无法返回事件循环处理其他 fd。非阻塞 fd 读到 EAGAIN 表示数据读完，可以安全返回等待下一个事件。
</details>

<details>
<summary>2. select 和 epoll 的核心区别？</summary>

select 每次调用需要拷贝 fd_set 到内核，返回后全量遍历检查每个 fd，复杂度 O(n)，且 fd 数量受 FD_SETSIZE (1024) 限制。epoll 在内核维护红黑树，只返回就绪的 fd，复杂度 O(1)，无数量限制。
</details>
