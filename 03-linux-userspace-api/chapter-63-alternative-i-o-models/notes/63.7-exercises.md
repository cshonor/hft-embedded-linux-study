<details>
<summary>1. 用 epoll 实现一个 echo 服务端，支持多客户端并发</summary>

```c
int epfd = epoll_create1(0);
struct epoll_event ev = { .events = EPOLLIN, .data.fd = listen_fd };
epoll_ctl(epfd, EPOLL_CTL_ADD, listen_fd, &ev);

struct epoll_event events[64];
while (1) {
    int n = epoll_wait(epfd, events, 64, -1);
    for (int i = 0; i < n; i++) {
        if (events[i].data.fd == listen_fd) {
            int cfd = accept(listen_fd, NULL, NULL);
            fcntl(cfd, F_SETFL, O_NONBLOCK);
            ev.events = EPOLLIN | EPOLLET;
            ev.data.fd = cfd;
            epoll_ctl(epfd, EPOLL_CTL_ADD, cfd, &ev);
        } else {
            /* echo: 读到 EAGAIN 为止, 原样写回 */
            char buf[4096];
            while (1) {
                ssize_t r = read(events[i].data.fd, buf, sizeof(buf));
                if (r <= 0) break;
                write(events[i].data.fd, buf, r);
            }
        }
    }
}
```
</details>

<details>
<summary>2. 为什么 pselect 需要额外的 sigmask 参数？</summary>

pselect 原子地"用 sigmask 替换信号掩码 + 等待 fd"，返回后恢复原掩码。这消除了"解除信号阻塞"和"进入等待"之间的竞态窗口，确保不会错过信号。如果分两步做（sigprocmask + select），信号可能在两步之间到达，select 会永远阻塞。
</details>

<details>
<summary>3. signalfd + epoll 相比 pselect 有什么优势？</summary>

signalfd 将信号变成普通 fd 事件，融入 epoll 事件循环。优势：(1) 统一处理 fd 和信号，无需 handler；(2) 没有 handler 的异步中断，代码全同步；(3) 可与大量 fd 一起高效管理；(4) 线程安全，可指定接收信号的线程。
</details>
