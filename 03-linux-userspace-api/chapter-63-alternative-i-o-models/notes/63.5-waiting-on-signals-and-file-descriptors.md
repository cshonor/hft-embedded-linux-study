## 本节讲什么

一个进程既要等 fd（网络包、管道、终端），又要等信号（`SIGTERM` 停机、`SIGCHLD` 收尸、
`SIGIO` 通知），而这两件事**原本属于两套完全不同的等待机制**。把它们拼在一起，
就撞上了一道经典竞态。本节按四层展开：

1. **问题层**：竞态的精确形态是什么？为什么"先检查标志再等 fd"必然有洞？
2. **方案层**：`pselect()` / `ppoll()` / `epoll_pwait()` 如何把"解除阻塞 + 等待"**压进一次系统调用**？
3. **内核层**：`set_user_sigmask()` / `restore_saved_sigmask_unless()` / `poll_select_finish()`
   三个函数怎么配合？—— 这里藏着本节**最有实践价值的一个坑**（timeout 被悄悄改写）
4. **终局层**：`signalfd()` 换了个思路 —— 干脆把信号变成字节流，让竞态**根本不存在**

> 🔗 **分工**：`pselect`/`ppoll` 的可移植语义主场在
> [TLPI Ch20 信号：基本概念](../../chapter-20-signals-fundamentals/)；
> epoll 的机制主场在 [63.4 epoll API](./63.4-the-epoll-api.md)；
> 信号驱动 I/O（`SIGIO`）主场在 [63.3 信号驱动 I/O](./63.3-signal-driven-i-o.md)；
> `io_uring` 作为终极替代主场在 [12.5 现代网络](../../../12.5-modern-networking/)。

## 要点

### 1. 竞态的精确形态 —— 不是一个窗口，是"检查"与"等待"之间的整段

教科书常把这段竞态画成"信号恰好落在两个系统调用中间"，听起来概率极低、不值得防。
**这个印象是错的。** 真正的洞不在两个系统调用之间，而在**用户态的"检查标志"动作**
与**内核的"进入等待"动作**之间 —— 这一段的长度是一个完整的用户态指令序列，
而且**只要信号在你检查之后到达，你就永远看不到它了**。

精确的时间线（错误写法）：

```
用户态                                       内核 / 信号
─────────────────────────────────────────────────────────
if (!got_sig) {          ← ① 读到 0
                                             ② 信号到达，pending
  sigprocmask(SIG_SETMASK, &unblocked);
                                             ③ 返回用户态 → handler 跑 → got_sig = 1
  select(nfds, ..., NULL);        ← ④ 但 got_sig 已经读过了！
                                             ⑤ select 睡死
}
```

关键在于 **③ 发生在 ④ 之前**：`sigprocmask()` 一解除阻塞，pending 的信号会在
**该系统调用返回用户态之前**立刻投递、handler 立刻跑完。等你执行到 ④ 的 `select()`，
`got_sig` 已经是 1 了，可你早就用 ① 的旧值做了分支判断。

这跟"概率"无关 —— 只要信号在 ① 之后到达，**100% 丢**。
[示例 1](#示例-1确定性复现竞态-race-democ) 给出了一个 100% 可复现的构造。

> 📌 这也是为什么 `SA_RESTART` 帮不上忙：`SA_RESTART` 管的是"等待中被信号打断后要不要重启"，
> 而这里的信号**根本没有打断任何等待** —— 它是在等待开始之前到达的。

### 2. ⭐ `pselect()` 的 timeout 陷阱 —— 手册说的和内核做的不是一回事

这是本节最值得记住的一条。

几乎所有资料（包括 TLPI）都写："`pselect()` 不修改它的 `timeout` 参数，这一点与
`select()` 不同"。**这句话只对你通过 glibc 调用 `pselect()` 时成立。**
man7 `select(2)` 的 NOTES 节把这事说得很清楚：

> The `pselect()` interface described in this page is implemented by glibc.
> The underlying Linux system call is named **`pselect6()`**.
> This system call has **somewhat different behavior** from the glibc wrapper function.
>
> **The Linux `pselect6()` system call modifies its `timeout` argument.**
> However, the glibc wrapper function hides this behavior by using a local variable
> for the timeout argument that is passed to the system call. Thus, the glibc
> `pselect()` function does not modify its `timeout` argument;
> this is the behavior required by POSIX.1-2001.

也就是说：

| 你调用的是 | timeout 会不会被改 | 谁在替你兜底 |
|-----------|------------------|-------------|
| glibc `pselect()` | **不会** | glibc 把 timeout **拷到局部变量**再传给 syscall，你传入的对象原封不动 |
| 内核 `pselect6()`（裸 `syscall()`、汇编、`io_uring` 等路径） | **会** | 没人兜底 |
| glibc `ppoll()` | **不会**（同一套手法） | glibc |
| 内核 `ppoll`（裸 `syscall()`） | **会** | 没人兜底 |
| `select()` | **会**（glibc 不隐藏） | POSIX 允许两种行为之一 |

而且还有更狠的一条，在 BUGS 节：

> On Linux, `select()` **also modifies `timeout` if the call is interrupted by a
> signal handler** (i.e., the `EINTR` error return). This is not permitted by POSIX.1.

**被信号打断时也改** —— 而 POSIX 明确规定 `EINTR` 返回时 timeout 不该动。
这正是 [示例 2](#示例-2观测-timeout-被改写-ppoll_timeout_probec) 要实测的东西。

#### 内核里的作案现场

`fs/select.c` 的 `poll_select_finish()` 是唯一的收尾出口，`pselect6` 和 `ppoll`
都从这里返回：

```c
/* fs/select.c:298-321 */
static int poll_select_finish(struct timespec64 *end_time,
			      void __user *p,
			      enum poll_time_type pt_type, int ret)
{
	struct timespec64 rts;

	restore_saved_sigmask_unless(ret == -ERESTARTNOHAND);

	if (!p)
		return ret;                          /* timeout 为 NULL → 不写回 */

	if (current->personality & STICKY_TIMEOUTS)
		goto sticky;

	/* No update for zero timeout */
	if (!end_time->tv_sec && !end_time->tv_nsec)
		return ret;                          /* 传进来的 timeout 是 0 → 不写回 */

	ktime_get_ts64(&rts);
	rts = timespec64_sub(*end_time, rts);         /* 剩余时间 = 到期时刻 - 现在 */
	if (rts.tv_sec < 0)
		rts.tv_sec = rts.tv_nsec = 0;

	switch (pt_type) {
	...
	case PT_TIMESPEC:
		if (!put_timespec64(&rts, p))            /* ← 写回用户态 */
			return ret;
		break;
```

注意 `restore_saved_sigmask_unless()` 在**第一行**，写回 timeout 在后面 ——
**无论返回原因是超时、有 fd 就绪、还是被信号打断，只要 `p` 非空且原 timeout 非零，
写回都会发生**。这就是"EINTR 时也改 timeout"的源码依据。

三个不写回的例外，值得单独记住：

| 情形 | 后果 |
|------|------|
| `timeout == NULL` | 不写回（无对象可写）—— `pselect` 的"死等"模式完全免疫此坑 |
| 原 timeout 为 `{0, 0}` | 不写回（源码显式跳过）—— 纯轮询模式也免疫 |
| `personality & STICKY_TIMEOUTS` | 跳到 `sticky:`，不写回（兼容老 Unix 行为） |

#### 为什么 glibc 的做法算是"正确的"

POSIX.1-2001 要求 `pselect()` 的 timeout 是 `const struct timespec *`：

```c
int pselect(int nfds, fd_set *readfds, fd_set *writefds, fd_set *exceptfds,
            const struct timespec *timeout,   /* ← const */
            const sigset_t *sigmask);         /* ← const */
```

`const` 就意味着"我不改你"。对照 `select()`：

```c
int select(int nfds, fd_set *readfds, fd_set *writefds, fd_set *exceptfds,
           struct timeval *timeout);          /* ← 非 const */
```

签名上的这个 `const` 差异，就是 glibc 必须拷一份局部变量的原因 ——
**内核 syscall 的 ABI 里没有 const 这个概念，它只有一个可写的用户态指针。**

> 🔑 **元教训（第 3 次应验）**：**man page 描述的是 glibc 封装的契约，不是内核 syscall 的行为。**
> 前两次是 `epoll_create(size)` 的 size 被忽略（见 [63.4](./63.4-the-epoll-api.md)），
> 这次是 `pselect6()` 改 timeout。凡是手册里出现
> "The X interface described in this page is implemented by glibc / The underlying
> Linux system call has somewhat different behavior" 这类字眼，
> 内核行为就要单独查源码。

### 3. 内核实现（上）：`set_user_sigmask()` 的三连

`pselect` / `ppoll` / `epoll_pwait` 三家共用同一个入口函数：

```c
/* kernel/signal.c:3122-3147 */
/*
 * The api helps set app-provided sigmasks.
 *
 * This is useful for syscalls such as ppoll, pselect, io_pgetevents and
 * epoll_pwait where a new sigmask is passed from userland for the syscalls.
 *
 * Note that it does set_restore_sigmask() in advance, so it must be always
 * paired with restore_saved_sigmask_unless() before return from syscall.
 */
int set_user_sigmask(const sigset_t __user *umask, size_t sigsetsize)
{
	sigset_t kmask;

	if (!umask)
		return 0;                                        /* ① 快路径 */
	if (sigsetsize != sizeof(sigset_t))
		return -EINVAL;
	if (copy_from_user(&kmask, umask, sizeof(sigset_t)))
		return -EFAULT;

	set_restore_sigmask();                               /* ② 打标记 */
	current->saved_sigmask = current->blocked;           /* ③ 存旧值 */
	set_current_blocked(&kmask);                         /* ④ 换新值 */

	return 0;
}
```

四个要点，逐个都有实际后果：

**① `sigmask == NULL` 时直接返回 0，什么都不做。**
所以 `pselect(..., NULL)` 严格等价于 `select(...)`，`ppoll(..., NULL)` 严格等价于 `poll(...)`。
手册也印证："If `sigmask` is NULL, the signal mask is not modified during the `pselect()` call."

**② `set_restore_sigmask()` 只是设一个 thread flag：**

```c
/* include/linux/sched/signal.h:488-491 */
static inline void set_restore_sigmask(void)
{
	set_thread_flag(TIF_RESTORE_SIGMASK);
}
```

它**不**改任何掩码，只在 task 上插一面旗子，告诉"即将返回用户态的那段 arch 代码"：
记得先把掩码还原。注释里解释了为什么还要顺带设 `TIF_SIGPENDING`：

> We set `TIF_SIGPENDING` here to ensure that the arch signal code always gets run
> when `TIF_RESTORE_SIGMASK` is set.

**③ `saved_sigmask` 存的是"调用前的 blocked"，也就是要还原回去的值。**

**④ `set_current_blocked()` 会强行剔除 `SIGKILL` / `SIGSTOP`：**

```c
/* kernel/signal.c:3064-3068 */
void set_current_blocked(sigset_t *newset)
{
	sigdelsetmask(newset, sigmask(SIGKILL) | sigmask(SIGSTOP));
	__set_current_blocked(newset);
}
```

所以你就算在 `sigmask` 里"解除阻塞 SIGKILL"，内核也不理 —— 这跟
[63.3](./63.3-signal-driven-i-o.md) 里 `do_signalfd4()` 的 `sigdelsetmask()` 是同一套保险。

⚠️ 对比一下 `__set_current_blocked()`：它**不**做这个剔除。注释写得很直白：

> NOTE! Unlike the user-mode `sys_sigprocmask()`, the kernel interface happily
> blocks "unblockable" signals like SIGKILL and friends.

**内核内部 API 和 syscall 包装的语义不一样** —— 又一处"同名不同义"。

### 4. ⭐ 内核实现（下）：`restore_saved_sigmask_unless()` —— 两家的判定条件不一样

这是本节一个容易看漏的细节。同一个 helper，在 `select.c` 和 `eventpoll.c` 里
传进去的**条件表达式不同**：

| 调用点 | 源码 | 判定条件 |
|--------|------|---------|
| `pselect6` / `ppoll` | `fs/select.c:304` | `restore_saved_sigmask_unless(ret == -ERESTARTNOHAND)` |
| `epoll_pwait` / `epoll_pwait2` | `fs/eventpoll.c:2354` | `restore_saved_sigmask_unless(error == -EINTR)` |

helper 本身只有三行：

```c
/* include/linux/sched/signal.h:555-561 */
static inline void restore_saved_sigmask_unless(bool interrupted)
{
	if (interrupted)
		WARN_ON(!signal_pending(current));
	else
		restore_saved_sigmask();
}

/* :547-551 */
static inline void restore_saved_sigmask(void)
{
	if (test_and_clear_restore_sigmask())
		__set_current_blocked(&current->saved_sigmask);
}
```

**语义**：`interrupted == true` 时不在这里还原掩码，只断言"确实有信号 pending"；
留给返回用户态前的 arch 信号代码（它看到 `TIF_RESTORE_SIGMASK` 就会还原）。
`interrupted == false` 时立刻就地还原。

#### 为什么非要分叉？

因为**"被信号打断"这件事，在两条路径上的表示方式不同**：

```
fs/select.c:686      ret = -ERESTARTNOHAND;      ← do_select() 的中断返回码
fs/select.c:939      count = -ERESTARTNOHAND;    ← do_poll() 的中断返回码
fs/eventpoll.c:1877  return -EINTR;              ← ep_poll() 的中断返回码
```

`do_select()` / `do_poll()` 返回的是**内部错误码** `-ERESTARTNOHAND`
（含义：有 handler 就不重启、直接给 userspace `-EINTR`），
它在 `poll_select_finish()` 里还没被翻译成 `-EINTR`（只有在 `sticky` 分支才翻译）。
而 `ep_poll()` 直接返回 `-EINTR`。

所以：**两处条件看似不一致，实则都在判断同一件事 —— "这次返回是被信号打断的吗"**，
只是要在各自的代码点上用当时那个返回值的表示形式去比。

#### 被打断时的完整时序

```
pselect(..., &empty_mask)                      信号在等待期间到达
  │
  ├─ set_user_sigmask()     blocked := empty（解除阻塞），TIF_RESTORE_SIGMASK := 1
  │
  ├─ core_sys_select()      ← 阻塞中
  │      ↑ 信号到达，进程被唤醒
  │
  ├─ do_select() 返回 -ERESTARTNOHAND
  │
  ├─ poll_select_finish()
  │     ├─ restore_saved_sigmask_unless(true)   → 只 WARN_ON，**不还原**
  │     └─ put_timespec64() 写回剩余 timeout
  │
  └─ 返回用户态前（arch 代码）：
        ├─ handler 用【解除阻塞后的掩码】跑           ← 关键
        └─ restore_saved_sigmask()  blocked := saved（原掩码） ← 然后才还原
        → 用户看到 errno == EINTR
```

**"handler 跑完之后才还原掩码"** 这一点很重要：如果你的 handler 里又触发了新的等待，
那次等待看到的还是临时掩码，不是原掩码。这也是 `set_user_sigmask()` 注释强调
"must be always paired with `restore_saved_sigmask_unless()` before return from syscall" 的原因 ——
两行代码必须成对，漏了就会把掩码永久改掉。

### 5. `poll_select_finish()`：谁写回 timeout —— 一张表终结混乱

把 `fs/select.c` 和 `fs/eventpoll.c` 并排看，会得出一个很干净的结论：

| 接口 | timeout 类型 | 内核是否写回 | 依据 |
|------|-------------|------------|------|
| `select()` | `struct timeval *`（非 const） | ✅ 写回 | `select.c:723` → `poll_select_finish(..., PT_TIMEVAL, ret)` |
| `pselect6()`（内核） | `struct __kernel_timespec *` | ✅ 写回 | `select.c:764` → `poll_select_finish(..., type, ret)` |
| `ppoll`（内核） | `struct __kernel_timespec *` | ✅ 写回 | `select.c:1122` → `poll_select_finish(..., PT_TIMESPEC, ret)` |
| glibc `pselect()` / `ppoll()` | `const struct timespec *` | ❌ 不改 | glibc 拷局部变量后传给内核 |
| `epoll_pwait()` | `int timeout`（**按值**） | ❌ 无从写起 | `eventpoll.c:2359-2368` |
| `epoll_pwait2()` | `const struct __kernel_timespec *` | ❌ 不写回 | `eventpoll.c:2370-2386`，走完即止 |

`epoll_pwait2` 的源码很直白 —— 它甚至**没有** `poll_select_finish` 的对应物：

```c
/* fs/eventpoll.c:2370-2386 */
SYSCALL_DEFINE6(epoll_pwait2, int, epfd, struct epoll_event __user *, events,
		int, maxevents, const struct __kernel_timespec __user *, timeout,
		const sigset_t __user *, sigmask, size_t, sigsetsize)
{
	struct timespec64 ts, *to = NULL;

	if (timeout) {
		if (get_timespec64(&ts, timeout))
			return -EFAULT;
		to = &ts;
		if (poll_select_set_timeout(to, ts.tv_sec, ts.tv_nsec))
			return -EINVAL;
	}

	return do_epoll_pwait(epfd, events, maxevents, to, sigmask, sigsetsize);
}
```

`to = &ts` 指向的是**栈上的局部变量**，`do_epoll_wait` 用完之后就丢了，
从来没有人 `copy_to_user` 回 `timeout`。所以 `epoll_pwait2()` 是这堆接口里
**唯一既支持纳秒精度、又不改 timeout** 的一个 —— 如果你在写自己的事件循环，
这是个被低估的选择。

`epoll_pwait` 的 `int timeout` 是按值传的，更是天然不可能被改。

> 📌 **顺带一个常规做法**：`ppoll(NULL, 0, &ts, &sigmask)` 是一个被广泛使用的
> "带信号掩码的 nanosleep"。`do_sys_poll()` 里 `nfds == 0` 时循环立刻退出
> （`len = min_t(unsigned int, 0, N_STACK_PPS) = 0` → `break`），
> `do_poll()` 直接落到 `if (!count) { count = wait->error; if (signal_pending) count = -ERESTARTNOHAND; }`，
> 于是它就是一个纯睡眠 + 原子换掩码。同理 `ppoll` 里传 `pollfd.fd = -1`
> 也只会被 `do_pollfd()` 忽略（`mask` 保持 0，不会置 `POLLNVAL`）。

### 6. `pselect6` 为什么是 6 个参数 —— `struct sigset_argpack`

`pselect()` 逻辑上有 7 个参数：`nfds, readfds, writefds, exceptfds, timeout, sigmask, sigsetsize`。
但内核头里它是 `SYSCALL_DEFINE6`。多出来的那个去哪了？

```c
/* fs/select.c:767-805 */
/*
 * Most architectures can't handle 7-argument syscalls. So we provide a
 * 6-argument version where the sixth argument is a pointer to a structure
 * which has a pointer to the sigset_t itself followed by a size_t containing
 * the sigset size.
 */
struct sigset_argpack {
	sigset_t __user *p;
	size_t size;
};

static inline int get_sigset_argpack(struct sigset_argpack *to,
				     struct sigset_argpack __user *from)
{
	// the path is hot enough for overhead of copy_from_user() to matter
	if (from) {
		if (!user_read_access_begin(from, sizeof(*from)))
			return -EFAULT;
		unsafe_get_user(to->p, &from->p, Efault);
		unsafe_get_user(to->size, &from->size, Efault);
		user_read_access_end();
	}
	return 0;
Efault:
	user_access_end();
	return -EFAULT;
}

SYSCALL_DEFINE6(pselect6, int, n, fd_set __user *, inp, fd_set __user *, outp,
		fd_set __user *, exp, struct __kernel_timespec __user *, tsp,
		void __user *, sig)
{
	struct sigset_argpack x = {NULL, 0};

	if (get_sigset_argpack(&x, sig))
		return -EFAULT;

	return do_pselect(n, inp, outp, exp, tsp, x.p, x.size, PT_TIMESPEC);
}
```

两个细节：

1. **"多数架构处理不了 7 参数 syscall"** —— 这是 ABI 硬约束。syscall 参数通过寄存器传，
   通用寄存器就那么几个。源码注释和 man7 是同一句话：
   "most architectures support a maximum of 6 arguments to a system call."
2. `get_sigset_argpack()` 没用 `copy_from_user()`，而是用了
   `user_read_access_begin()` + `unsafe_get_user()`。注释点明原因：
   **"the path is hot enough for overhead of copy_from_user() to matter"** ——
   `pselect` 在高频事件循环里会被疯狂调用，连 `copy_from_user` 的开销都要省。
   （`copy_from_user()` 有 `might_fault()` / 各种检查，`unsafe_get_user` 在
   `user_access_begin/end` 保护下省掉这些。）

man7 给的结构体名字不同（`ss` / `ss_len`），但布局一致：

```c
struct {
    const kernel_sigset_t *ss;   /* Pointer to signal set */
    size_t ss_len;               /* Size (in bytes) of object pointed to by 'ss' */
};
```

> ⚠️ 手册里这个 `kernel_sigset_t` 是**内核**的 `sigset_t`（8 字节 / 64 位），
> 不是 glibc 的 `sigset_t`（128 字节 / 1024 位）。这正是必须把 size 一起传进来的原因 ——
> 内核要检查 `sigsetsize != sizeof(sigset_t)` 再决定接受还是 `-EINVAL`。

顺带把 `enum poll_time_type` 也列一下，它决定了 timeout 的编解码方式：

```c
/* fs/select.c:291-296 */
enum poll_time_type {
	PT_TIMEVAL = 0,        /* struct __kernel_old_timeval   —— select()        */
	PT_OLD_TIMEVAL = 1,    /* struct old_timeval32          —— compat select() */
	PT_TIMESPEC = 2,       /* struct __kernel_timespec      —— pselect6/ppoll  */
	PT_OLD_TIMESPEC = 3,   /* struct old_timespec32         —— 32 位 time_t    */
};
```

`do_pselect()` 只接受 `PT_TIMESPEC` / `PT_OLD_TIMESPEC`，其他值直接 `BUG()`
（`select.c:750-751`）—— 这是内核内部的"不可能发生"断言。

### 7. signalfd —— 换个思路：把信号变成字节流

前三节的方案都在"怎么让信号和 fd 安全地一起等"。`signalfd()` 的思路完全不同：

> **不要让信号去打断等待 —— 让信号本身变成一个可读的 fd。**

一旦信号变成 fd，它就和 socket / pipe / timerfd 完全同构了，
可以进 `epoll` 监听，竞态**从根上消失**（信号全程阻塞，永远不会"打断"任何东西）。

#### 7.1 `struct signalfd_ctx` —— 只有一个字段，而且存的是**反码**

```c
/* fs/signalfd.c:41-43 */
struct signalfd_ctx {
	sigset_t sigmask;
};
```

就这么一个字段。但它的**语义是反的** —— 存的是"**不要**通过 signalfd 递送的信号集合"，
而不是"要递送的集合"。原因在 `do_signalfd4()`：

```c
/* fs/signalfd.c:253-272 */
static int do_signalfd4(int ufd, sigset_t *mask, int flags)
{
	struct signalfd_ctx *ctx;

	/* Check the SFD_* constants for consistency.  */
	BUILD_BUG_ON(SFD_CLOEXEC != O_CLOEXEC);
	BUILD_BUG_ON(SFD_NONBLOCK != O_NONBLOCK);

	if (flags & ~(SFD_CLOEXEC | SFD_NONBLOCK))
		return -EINVAL;

	sigdelsetmask(mask, sigmask(SIGKILL) | sigmask(SIGSTOP));   /* ① 剔除不可拦信号 */
	signotset(mask);                                            /* ② 取反 */

	if (ufd == -1) {
		ctx = kmalloc(sizeof(*ctx), GFP_KERNEL);
		if (!ctx)
			return -ENOMEM;

		ctx->sigmask = *mask;                                   /* ③ 存反码 */
		...
		ufd = anon_inode_getfd("[signalfd]", &signalfd_fops, ctx,
				       O_RDWR | (flags & (O_CLOEXEC | O_NONBLOCK)));
```

三步：

- **① `sigdelsetmask(mask, SIGKILL|SIGSTOP)`** —— 先把这两个不可拦的信号从
  "用户想接收的集合"里剔除。man7 印证：
  > "It is not possible to receive SIGKILL or SIGSTOP signals via a signalfd file
  > descriptor; these signals are **silently ignored** if specified in mask."
  ⚠️ **静默忽略** —— 不报错、不返回 `-EINVAL`，你只是永远读不到它们。
  这已经是本批笔记里第 4 次遇到"静默"行为了
  （前三次见 [63.3](./63.3-signal-driven-i-o.md) 的元教训）。
- **② `signotset(mask)`** —— 取反。
- **③** 存进 ctx。

为什么要反？因为下游用的是 `dequeue_signal(current, &ctx->sigmask, info, &type)`，
而 `dequeue_signal()` 的第二个参数是"**要跳过**的信号集合"。
所以存反码正好可以直接喂给它。

> 📌 `/proc/pid/fdinfo` 里看到的 `sigmask:` 是**再取反一次**之后的（即用户原始语义）：
> ```c
> /* fs/signalfd.c:232-240 */
> sigmask = ctx->sigmask;
> signotset(&sigmask);
> render_sigset_t(m, "sigmask:\t", &sigmask);
> ```

#### 7.2 `signalfd_read()` —— 批量读，但只有第一次可能阻塞

```c
/* fs/signalfd.c:202-229 */
static ssize_t signalfd_read(struct file *file, char __user *buf, size_t count,
			     loff_t *ppos)
{
	struct signalfd_ctx *ctx = file->private_data;
	struct signalfd_siginfo __user *siginfo;
	int nonblock = file->f_flags & O_NONBLOCK;
	ssize_t ret, total = 0;
	kernel_siginfo_t info;

	count /= sizeof(struct signalfd_siginfo);          /* ① 向下取整到"能装几个" */
	if (!count)
		return -EINVAL;                                /* ② 缓冲区 < 128 字节 */

	siginfo = (struct signalfd_siginfo __user *) buf;
	do {
		ret = signalfd_dequeue(ctx, &info, nonblock);
		if (unlikely(ret <= 0))
			break;
		ret = signalfd_copyinfo(siginfo, &info);
		if (ret < 0)
			break;
		siginfo++;
		total += ret;
		nonblock = 1;                                  /* ③ 之后一律非阻塞 */
	} while (--count);

	return total ? total: ret;
}
```

三个要点：

**① `count /= sizeof(...)`** —— 你传的字节数被换算成"能装几个 siginfo"。
多出来的零头直接扔掉，`read(sfd, buf, 200)` 和 `read(sfd, buf, 128)` 效果一样（都只装 1 个）。

**② ⚠️ 缓冲区小于 128 字节 → `-EINVAL`。**
man7 只在正文写了一句 "The buffer must be at least `sizeof(struct signalfd_siginfo)` bytes."，
但 **ERRORS 小节里根本没有这一条** —— 那里只列了两条 `EINVAL`（fd 不是 signalfd / flags 非法）。
也就是说，**这个错误码只能靠读源码知道**。实测见
[示例 3](#示例-3signalfd-的-read-语义-sfd_read_semanticsc)。

**③ `nonblock = 1`** —— 第一次成功取到信号之后，循环里的后续取信号一律非阻塞。
语义是：**"要么立刻给我一个，要么就去等（但只等第一次）"**。
这样一次 `read()` 能批量取走多个 pending 信号，又不会在最后卡住。

#### 7.3 `signalfd_dequeue()` —— 真的是"摘走"，不是"窥视"

```c
/* fs/signalfd.c:155-195 */
static ssize_t signalfd_dequeue(struct signalfd_ctx *ctx, kernel_siginfo_t *info,
				int nonblock)
{
	enum pid_type type;
	ssize_t ret;
	DECLARE_WAITQUEUE(wait, current);

	spin_lock_irq(&current->sighand->siglock);
	ret = dequeue_signal(current, &ctx->sigmask, info, &type);   /* ← 真摘 */
	switch (ret) {
	case 0:
		if (!nonblock)
			break;
		ret = -EAGAIN;
		fallthrough;
	default:
		spin_unlock_irq(&current->sighand->siglock);
		return ret;
	}

	add_wait_queue(&current->sighand->signalfd_wqh, &wait);      /* ← 挂在 sighand 上 */
	for (;;) {
		set_current_state(TASK_INTERRUPTIBLE);
		ret = dequeue_signal(current, &ctx->sigmask, info, &type);
		if (ret != 0)
			break;
		if (signal_pending(current)) {
			ret = -ERESTARTSYS;                                  /* ← 注意这个码 */
			break;
		}
		spin_unlock_irq(&current->sighand->siglock);
		schedule();
		spin_lock_irq(&current->sighand->siglock);
	}
	spin_unlock_irq(&current->sighand->siglock);

	remove_wait_queue(&current->sighand->signalfd_wqh, &wait);
	__set_current_state(TASK_RUNNING);

	return ret;
}
```

- `dequeue_signal()` 是真的把信号从 pending 队列里摘下来。man7：
  > "As a consequence of the `read(2)`, the signals are **consumed**, so that they are
  > no longer pending for the process (i.e., will not be caught by signal handlers,
  > and cannot be accepted using `sigwaitinfo(2)`)."
- 等待队列是 `current->sighand->signalfd_wqh` —— 挂在 **sighand** 上，
  信号到达时由 `signalfd_notify()` 一类的路径 `wake_up`。
- 阻塞时若被**非 signalfd 集合内**的信号打断，返回 `-ERESTARTSYS`
  （注意：跟前面 `select`/`poll` 的 `-ERESTARTNOHAND` 不是一个码 ——
  `-ERESTARTSYS` 意味着**装了 `SA_RESTART` 的 handler 会自动重启这次 `read`**）。

#### 7.4 `signalfd_poll()` —— 查两个队列

```c
/* fs/signalfd.c:51-66 */
static __poll_t signalfd_poll(struct file *file, poll_table *wait)
{
	struct signalfd_ctx *ctx = file->private_data;
	__poll_t events = 0;

	poll_wait(file, &current->sighand->signalfd_wqh, wait);

	spin_lock_irq(&current->sighand->siglock);
	if (next_signal(&current->pending, &ctx->sigmask) ||
	    next_signal(&current->signal->shared_pending,
			&ctx->sigmask))
		events |= EPOLLIN;
	spin_unlock_irq(&current->sighand->siglock);

	return events;
}
```

查的是**两个**队列：

| 队列 | 含义 | 谁来填 |
|------|------|--------|
| `current->pending` | **线程私有** pending | `pthread_kill()` / `tgkill()` / 同步故障（SIGSEGV 等） |
| `current->signal->shared_pending` | **进程（线程组）共享** pending | `kill()` / `sigqueue()` / 终端信号 / `SIGCHLD` |

**注意这里用的是 `current`** —— 不是创建 signalfd 的那个 task，而是**正在 `poll`/`read` 的那个线程**。
这直接引出下一节那个最容易踩的坑。

#### 7.5 `signalfd_copyinfo()` —— 128 字节的硬约束与 `SIL_*` 分派

```c
/* fs/signalfd.c:71-90 */
static int signalfd_copyinfo(struct signalfd_siginfo __user *uinfo,
			     kernel_siginfo_t const *kinfo)
{
	struct signalfd_siginfo new;

	BUILD_BUG_ON(sizeof(struct signalfd_siginfo) != 128);   /* ← 编译期断言 */
	...
	memset(&new, 0, sizeof(new));

	new.ssi_signo = kinfo->si_signo;
	new.ssi_errno = kinfo->si_errno;
	new.ssi_code  = kinfo->si_code;
	switch (siginfo_layout(kinfo->si_signo, kinfo->si_code)) {
	case SIL_KILL:  ...  break;
	case SIL_TIMER: ...  break;
	case SIL_POLL:  ...  break;
	...
```

`BUILD_BUG_ON(sizeof != 128)` 是个编译期断言 —— 结构体大小一旦不是 128 字节，
内核**编译不过**。uapi 头文件里把理由写得很清楚：

```c
/* include/uapi/linux/signalfd.h:43-52 */
	/*
	 * Pad strcture to 128 bytes. Remember to update the
	 * pad size when you add new members. We use a fixed
	 * size structure to avoid compatibility problems with
	 * future versions, and we leave extra space for additional
	 * members. We use fixed size members because this strcture
	 * comes out of a read(2) and we really don't want to have
	 * a compat on read(2).
	 */
	__u8 __pad[28];
```

（顺带一提：内核源码里这里有个 typo —— "strcture"，两处。原样保留。）

128 字节可以这样验算：

| 字段 | 大小 | 累计 |
|------|------|------|
| `ssi_signo` / `ssi_errno` / `ssi_code` | 4×3 | 12 |
| `ssi_pid` / `ssi_uid` / `ssi_fd` / `ssi_tid` / `ssi_band` / `ssi_overrun` / `ssi_trapno` / `ssi_status` / `ssi_int` | 4×9 | 48 |
| `ssi_ptr` / `ssi_utime` / `ssi_stime` / `ssi_addr` | 8×4 | 80 |
| `ssi_addr_lsb` / `__pad2` | 2×2 | 84 |
| `ssi_syscall` | 4 | 88 |
| `ssi_call_addr` | 8 | 96 |
| `ssi_arch` | 4 | 100 |
| `__pad[28]` | 28 | **128** ✓ |

⚠️ **一个常见误解：`ssi_overrun` 不是"信号队列溢出计数"。** 看分派表：

```c
/* fs/signalfd.c:95-104 */
	case SIL_TIMER:
		new.ssi_tid     = kinfo->si_tid;
		new.ssi_overrun = kinfo->si_overrun;      /* ← 只有这里填 */
		new.ssi_ptr     = (long) kinfo->si_ptr;
		new.ssi_int     = kinfo->si_int;
		break;
	case SIL_POLL:
		new.ssi_band = kinfo->si_band;
		new.ssi_fd   = kinfo->si_fd;              /* ← 与 63.3 的 si_fd 呼应 */
		break;
```

`ssi_overrun` 是 **`timer_create()` 超期次数**，来自 `struct siginfo` 的 `si_overrun`，
只在 `SIL_TIMER` 分支填。其他分支下它维持 `memset` 的 0。
（同理 `ssi_fd` / `ssi_band` 只在 `SIL_POLL` 分支填 ——
这正是 [63.3 信号驱动 I/O](./63.3-signal-driven-i-o.md) 里 `F_SETSIG` + `si_fd` 那一套的落点。）

### 8. ⭐⭐ signalfd 的线程语义 —— 它读的是"**当前**线程"的信号

这是 signalfd 在多线程程序里最容易踩的坑，而且**内核源码和 man7 的说法完全一致**，
可以放心当作硬事实。

先把源码依据摆出来（重复一次 7.4 的关键行）：

```c
	if (next_signal(&current->pending, &ctx->sigmask) ||        /* 当前线程的私有队列 */
	    next_signal(&current->signal->shared_pending,           /* 进程级共享队列    */
			&ctx->sigmask))
		events |= EPOLLIN;
```

man7 `signalfd(2)` 的 Thread semantics 小节：

> "when a thread reads from a signalfd file descriptor, it will read the signals that
> are directed to the thread itself and the signals that are directed to the process
> (i.e., the entire thread group). **(A thread will not be able to read signals that
> are directed to other threads in the process.)**"

翻译成一张表：

| 信号来源 | 落在哪个队列 | 线程 A 的 signalfd 能读到吗？ |
|---------|-------------|---------------------------|
| `kill(pid, sig)`（发给进程） | `shared_pending` | ✅ 任何线程都能读 |
| `sigqueue(pid, sig, ...)` | `shared_pending` | ✅ 任何线程都能读 |
| 终端 `Ctrl+C` → `SIGINT` | `shared_pending` | ✅ |
| 子进程退出 → `SIGCHLD` | `shared_pending` | ✅ |
| `pthread_kill(A, sig)`（定向到 A） | `A.pending` | ✅ **只有 A 自己**能读 |
| `tgkill(pid, tid_A, sig)` | `A.pending` | ✅ **只有 A 自己**能读 |
| 线程 A 访问非法地址 → `SIGSEGV` | `A.pending` | ⚠️ 见下（同步信号本来就不能用 signalfd） |

**实践结论**：

> 在多线程程序里，**不要让"事件循环线程"替其他线程读 signalfd**。
> 如果工作线程用 `pthread_kill()` 给自己发了个信号，主循环线程的 signalfd
> **永远读不到它** —— 不会报错，就是永远不就绪。

对 HFT 的直接影响：常见的"一个 pin 住的低延迟线程跑事件循环 + 若干工作线程"布局下，
如果你的停机/重配置信号是用 `pthread_kill()` 定向到工作线程的，
那 signalfd 方案就废了 —— 必须改成 `kill(getpid(), sig)`（进程级），
或者让**每个线程自己建一个 signalfd**。

> 📌 **fork 的语义**（man7）：
> "After a `fork(2)`, the child inherits a copy of the signalfd file descriptor.
> A `read(2)` from the file descriptor in the child will return information about
> signals queued to the child."
> ⚠️ 还有一个更阴的：**如果父进程把 signalfd 加进了 epoll 实例，`fork` 后子进程
> `epoll_wait()` 不会把这个继承来的 fd 报成就绪**。变通办法是子进程关掉继承的 fd、
> 重建 signalfd、再重新加进 epoll。

### 9. signalfd 的三个硬限制

#### 限制一：收不到同步生成的信号

man7 Limitations：

> "The signalfd mechanism can't be used to receive signals that are **synchronously
> generated**, such as the `SIGSEGV` signal that results from accessing an invalid
> memory address or the `SIGFPE` signal that results from an arithmetic error.
> Such signals can be caught only via signal handler."

原因不复杂：同步信号是**在故障指令的上下文里直接投递**的（`force_sig_fault()` 一类路径），
它们根本不进"等待被摘取"的 pending 队列模型 —— 内核必须在返回用户态前处理掉，
否则就会回到同一条出错指令上死循环。

> 对 HFT 的含义：**栈溢出 / 非法访问的兜底 handler 不能用 signalfd 实现**，
> 只能是传统 handler（而且还得配 `sigaltstack()`）。

#### 限制二：`SIGKILL` / `SIGSTOP` 被静默忽略

已在 7.1 讲过 —— `sigdelsetmask()` 在 `do_signalfd4()` 里直接剔除，不报错。

#### 限制三：非实时信号不排队

```c
/* kernel/signal.c:1079-1082 */
static inline bool legacy_queue(struct sigpending *signals, int sig)
{
	return (sig < SIGRTMIN) && sigismember(&signals->signal, sig);
}

/* :1104-1106 */
	if (legacy_queue(pending, sig))
		goto ret;      /* 已有同号 pending → 不再排队 */
```

标准信号（`SIGINT` / `SIGTERM` / `SIGHUP` / `SIGCHLD` …）在 pending 时**只记一个位**，
不排队。所以：**三个 `SIGTERM` 连发，你 `read()` 只能拿到一个。**

对"停机"语义无所谓（一个就够了），但如果你的 signalfd 承担了
"统计信号次数"的职责，就必须改用 `SIGRTMIN..SIGRTMAX`（实时信号，真排队）。

| 信号类型 | 排队？ | 典型用途 |
|---------|-------|---------|
| 标准信号（`SIGTERM` / `SIGINT` / `SIGCHLD`） | ❌ 合并为 1 | 停机、重载、收尸 |
| 实时信号（`SIGRTMIN`+，配合 `sigqueue()`） | ✅ 真排队 | 需要计数/携带数据的场景 |

man7 还有一条相关的：

> "If a signal appears in the mask of more than one of the file descriptors, then
> occurrences of that signal can be read (**once**) from any one of the file descriptors."

即：**一个进程可以有多个 signalfd，同一信号出现在多个 fd 的 mask 里时，
它只会被读走一次，不是每个 fd 各读一份。**

#### （附）一个容易忽略的顺序要求

> "Normally, the set of signals to be received via the file descriptor should be
> **blocked** using `sigprocmask(2)`, to prevent the signals being handled according
> to their default dispositions."

**必须先 `sigprocmask(SIG_BLOCK, ...)` 再 `signalfd()`。** 顺序反了的话，
在 signalfd 建好之前到达的信号会走默认动作（比如 `SIGTERM` 直接杀进程），
signalfd 根本来不及接。

还有 execve 的连带问题：

> "If spawning a child process to execute a helper program (that does not need the
> signalfd file descriptor), then, after the call to `fork(2)`, you will normally
> want to **unblock those signals before calling `execve(2)`** … Be aware, however,
> that this won't be possible in the case of a helper program spawned behind the
> scenes by any library function that the program may call. In such cases, one must
> fall back to using a traditional signal handler that writes to a file descriptor
> monitored by `select(2)`, `poll(2)`, or `epoll(7)`."

**"信号被阻塞"这个状态会跨 `execve` 继承下去** —— 所以你 fork 出去的 helper 程序
会莫名其妙收不到它期待的信号。这条在写守护进程时经常坑人。

### 10. ⭐ 五种方案决策矩阵（修正版）

原笔记只对比了 3 种。把 `epoll_pwait2` 和 self-pipe 也放进来，并按
"是否需要 handler"、"timeout 是否被改"、"多线程安全性"三个新维度展开：

| 方案 | 解决竞态的方式 | 需要 handler? | timeout 被改? | 信号排队? | 多线程 | 可移植性 |
|------|--------------|--------------|--------------|----------|--------|---------|
| `select` + 全局标志 | ❌ 不解决 | 是 | ✅ 会被改（含 EINTR） | 靠自己写 pipe | 每线程自管 | POSIX |
| `pselect` / `ppoll` + self-pipe | 原子换掩码 + 等待 | 是（写 pipe） | glibc 不改 / 裸 syscall 改 | pipe 本身排队 | 每线程自管 | POSIX |
| `epoll_pwait` + self-pipe | 原子换掩码 + 等待 | 是（写 pipe） | ❌ 不改 | pipe 本身排队 | 每线程自管 | Linux |
| **`signalfd` + `epoll`** | **竞态不存在** | **否** | N/A（走 epoll 语义） | 内核队列（非 RT 合并） | ⚠️ 只读本线程+进程级 | Linux |
| `signalfd` + `epoll_pwait2` | 竞态不存在 + 纳秒精度 | **否** | ❌ 不改 | 同上 | 同上 | Linux 5.11+ |

**怎么选**：

```
需要跨 UNIX 移植？
├─ 是 → pselect/ppoll + self-pipe
└─ 否（Linux 专有可接受）
   ├─ 信号种类少、只需要"停机/重载" → signalfd + epoll   ★ 推荐
   ├─ 还要纳秒级 timeout 且不想被改 → signalfd + epoll_pwait2
   └─ 必须处理 SIGSEGV/SIGFPE 兜底 → signalfd + 传统 handler(sigaltstack) 混用
```

**最重要的一句话**：

> 一旦用了 signalfd，信号全程阻塞，**`pselect`/`ppoll`/`epoll_pwait` 全都不需要了** ——
> 竞态的前提（"信号在等待开始前到达"）消失了，普通 `epoll_wait()` 就够了。
> 本节的三个"p 系列"API 和 signalfd 是**互斥的两条路线**，不是叠加关系。

### 11. 修正原笔记的几处

| 原笔记的说法 | 判定 | 依据 |
|-------------|------|------|
| "`pselect` / `ppoll` 仍需 handler" | ✅ 对（但没说清"为什么"） | 它们只是原子地换掩码+等待，信号仍由 handler 处理 |
| "`epoll_pwait` Linux 专有" | ✅ 对 | — |
| "`signalfd` + epoll：统一事件循环，无 handler" | ✅ 对，但**不完整** | 补三条硬限制：同步信号收不到、SIGKILL/SIGSTOP 静默忽略、非 RT 信号不排队 |
| "`signalfd` 融入 epoll 后 `epoll_wait` 同时返回 fd 事件和信号事件" | ⚠️ **需要加限定** | 只在单线程、或信号是**进程级**（`kill`/`sigqueue`）时成立。`pthread_kill()` 定向到别的线程的信号，你的 signalfd 读不到 |
| "HFT：signalfd + epoll 统一事件循环，零信号中断延迟" | ⚠️ 措辞过头 | "零中断延迟"不准确。`read()` 阻塞路径被非 mask 内信号打断时返回 `-ERESTARTSYS`；且 `epoll_wait` 仍可能被**非** signalfd 集合内的信号打断返回 `EINTR`。准确说法是"**信号不再打断业务等待**" |
| 示例用 `signalfd(-1, &mask, 0)` 后直接 `poll()` | ✅ 可用，但应加 `SFD_NONBLOCK` | 阻塞 signalfd 在 epoll 边缘触发（EPOLLET）下会卡死；`SFD_NONBLOCK` 是默认该带的 |

> 📌 关于"零信号中断延迟"这条，值得单独说一句：
> signalfd 真正消灭的是 **EINTR 重试循环** 和 **竞态窗口**，
> 不是"信号处理的延迟"。信号仍然要经历完整的 `sighand->siglock` 加锁、
> pending 入队、唤醒 `signalfd_wqh`、`epoll_wait` 返回、`read()` 系统调用这一串。
> 它的价值是**代码结构变简单 + 行为可预测**，不是延迟变低。
> 真要压延迟，方向是 [12.5 现代网络](../../../12.5-modern-networking/) 的 `io_uring`。

## HFT / 嵌入式关联

| 路线 | 要点 | 内核依据 |
|------|------|---------|
| **HFT · 停机路径** | `signalfd(SIGINT\|SIGTERM\|SIGHUP)` 进主 epoll，停机不需要 `EINTR` 重试循环，事件循环主体保持无分支 | 信号全程阻塞 → `epoll_wait` 不会被业务信号打断 |
| **HFT · 别用 signalfd 收高频事件** | signalfd 的价值是**结构简化**，不是延迟降低。信号仍要过 `sighand->siglock` + pending 入队 + 唤醒 + `read()` 一整串 | `signalfd_dequeue` 全程持 `sighand->siglock` 自旋锁 |
| **HFT · 多线程布局** | "主循环线程读 signalfd" 只能收**进程级**信号。工作线程自发的 `pthread_kill()` 信号主循环读不到 —— 要么改 `kill(getpid(), ...)`，要么每线程自建 signalfd | `signalfd_poll` 用 `current->pending` |
| **HFT · 要计数就用实时信号** | 标准信号不排队（3 个 `SIGTERM` 只读到 1 个）。需要区分/计数时改用 `SIGRTMIN+n` + `sigqueue()` | `legacy_queue()` `signal.c:1079` |
| **HFT · 兜底 handler 不能省** | `SIGSEGV` / `SIGFPE` 收不到，栈溢出兜底仍需传统 handler + `sigaltstack()` | man7 Limitations |
| **HFT · timeout 复用** | 在循环里复用同一个 `struct timespec` 时，**裸 syscall 的 ppoll 会把它改掉**。glibc 封装不会 —— 但如果你走 `syscall()` / 手写 asm / `io_uring` 路径就会中招 | 第 71 条 |
| **HFT · 纳秒级超时** | `epoll_pwait2()` 是唯一"纳秒精度 + 不改 timeout"的选择 | `eventpoll.c:2370`，`const` 参数 + 无写回 |
| **嵌入式 · 可移植性** | 需要跨 UNIX 时只能用 `pselect`/`ppoll` + self-pipe。signalfd 是 Linux 专有 | — |
| **嵌入式 · 省一个 fd** | self-pipe 方案要 2 个 fd（读端+写端）；signalfd 只要 1 个。fd 紧张的嵌入式环境这是实打实的差别 | `anon_inode_getfd()` |
| **通用 · execve 传染** | 用 signalfd 阻塞掉的信号会跨 `execve` 继承给 helper 程序。fork 后 exec 前记得解除阻塞 | man7 NOTES |

### 示例 1：确定性复现竞态（`race_demo.c`）

原笔记里那段"信号在 `sigprocmask` 和 `select` 之间到达"的伪码没法稳定复现。
下面这个版本是 **100% 确定性**的 —— 用"先阻塞再 `raise()`"造出一个已 pending 的信号，
然后走一遍错误写法。

```c
/* race_demo.c —— 确定性复现「检查标志 → 等待」竞态
 * 构建: gcc -O0 -o race_demo race_demo.c
 * 用法: ./race_demo            (错误写法，会挂住，请用 timeout 5 ./race_demo)
 *       ./race_demo pselect    (正确写法，立刻返回)
 */
#define _GNU_SOURCE
#include <signal.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <unistd.h>
#include <errno.h>
#include <sys/select.h>

static volatile sig_atomic_t got;

static void handler(int s) { (void)s; got = 1; }

int main(int argc, char **argv)
{
    int use_pselect = (argc > 1 && !strcmp(argv[1], "pselect"));

    struct sigaction sa = {0};
    sa.sa_handler = handler;
    sigemptyset(&sa.sa_mask);
    sigaction(SIGUSR1, &sa, NULL);

    sigset_t blocked, empty;
    sigemptyset(&blocked); sigaddset(&blocked, SIGUSR1);
    sigemptyset(&empty);

    /* 全程阻塞 SIGUSR1，然后造一个「已经 pending、handler 还没跑」的信号 */
    sigprocmask(SIG_BLOCK, &blocked, NULL);
    raise(SIGUSR1);
    printf("[%s] SIGUSR1 已 pending, got=%d\n",
           use_pselect ? "pselect" : "select ", (int)got);

    if (!got) {                                  /* ← ① 读到 0 */
        if (use_pselect) {
            /* 正确：解除阻塞 + 等待 压进【一个】系统调用。
               pending 的信号在等待期间投递 → pselect 立刻返回 -1/EINTR */
            struct timespec ts = { .tv_sec = 2, .tv_nsec = 0 };
            errno = 0;
            int r = pselect(0, NULL, NULL, NULL, &ts, &empty);
            printf("  pselect -> %d (errno=%s), got=%d\n",
                   r, strerror(errno), (int)got);
        } else {
            /* 错误：两步走。
               sigprocmask 一返回用户态，pending 信号立刻投递、handler 立刻跑完，
               但 got 已经在 ① 被读成 0 了 —— select 睡死。 */
            sigprocmask(SIG_SETMASK, &empty, NULL);
            printf("  解除阻塞后 got=%d，即将 select(NULL timeout) …\n", (int)got);
            select(0, NULL, NULL, NULL, NULL);
            printf("  select 返回了（正常情况看不到这行）\n");
        }
    }
    return 0;
}
```

**预期输出**：

```
$ timeout 5 ./race_demo pselect
[pselect] SIGUSR1 已 pending, got=0
  pselect -> -1 (errno=Interrupted system call), got=1

$ timeout 5 ./race_demo
[select ] SIGUSR1 已 pending, got=0
  解除阻塞后 got=1，即将 select(NULL timeout) …
$ echo $?
124          ← timeout(1) 的退出码：进程被杀，说明 select 真的睡死了
```

`got=1` 那行是关键证据：handler **确实跑了**，只是跑在 ① 之后，
分支判断用的是旧值。

### 示例 2：观测 timeout 被改写（`ppoll_timeout_probe.c`）

直接对比"裸 syscall `ppoll`"和"glibc `ppoll()`"对同一个 `struct timespec` 的处理。

```c
/* ppoll_timeout_probe.c —— 实测第 71/72 条
 * 构建: gcc -O0 -o ppoll_timeout_probe ppoll_timeout_probe.c
 * 需要: Linux（SYS_ppoll）
 */
#define _GNU_SOURCE
#include <errno.h>
#include <poll.h>
#include <signal.h>
#include <stdio.h>
#include <string.h>
#include <sys/syscall.h>
#include <unistd.h>

static volatile sig_atomic_t alarms;
static void on_alarm(int s) { (void)s; alarms++; }

static void show(const char *tag, const struct timespec *ts)
{
    printf("    %-26s { tv_sec=%ld, tv_nsec=%09ld }\n",
           tag, (long)ts->tv_sec, ts->tv_nsec);
}

int main(void)
{
    struct sigaction sa = {0};
    sa.sa_handler = on_alarm;
    sigemptyset(&sa.sa_mask);
    sa.sa_flags = 0;                        /* 故意不加 SA_RESTART */
    sigaction(SIGALRM, &sa, NULL);

    /* pollfd.fd = -1 → do_pollfd() 直接忽略（mask 保持 0，不置 POLLNVAL），
       于是 ppoll 退化成「可换掩码的 nanosleep」 */
    struct pollfd pfd = { .fd = -1, .events = 0 };

    /* ---- A: 裸 syscall，绕过 glibc 的局部变量拷贝 ---- */
    struct timespec a = { .tv_sec = 5, .tv_nsec = 0 };
    printf("A) 裸 syscall(SYS_ppoll)，timeout=5s，1 秒后 SIGALRM 打断\n");
    show("调用前", &a);
    alarm(1);
    errno = 0;
    long ra = syscall(SYS_ppoll, &pfd, 1, &a, (void *)0, (size_t)8);
    printf("   ret=%ld errno=%d(%s) alarms=%d\n", ra, errno, strerror(errno), (int)alarms);
    show("调用后", &a);                     /* ← 被改成了剩余时间 ≈ 4s */

    /* ---- B: glibc ppoll()，glibc 帮你拷了局部变量 ---- */
    struct timespec b = { .tv_sec = 5, .tv_nsec = 0 };
    printf("\nB) glibc ppoll()，timeout=5s，1 秒后 SIGALRM 打断\n");
    show("调用前", &b);
    alarm(1);
    errno = 0;
    long rb = ppoll(&pfd, 1, &b, NULL);
    printf("   ret=%ld errno=%d(%s) alarms=%d\n", rb, errno, strerror(errno), (int)alarms);
    show("调用后", &b);                     /* ← 原封不动 {5, 0} */

    /* ---- C: 超时到期（非 EINTR）路径，裸 syscall 同样会改 ---- */
    struct timespec c = { .tv_sec = 1, .tv_nsec = 0 };
    printf("\nC) 裸 syscall(SYS_ppoll)，timeout=1s，让它正常超时到期\n");
    show("调用前", &c);
    errno = 0;
    long rc = syscall(SYS_ppoll, &pfd, 1, &c, (void *)0, (size_t)8);
    printf("   ret=%ld errno=%d(%s)\n", rc, errno, strerror(errno));
    show("调用后", &c);                     /* ← 归零 {0, 0} */

    return 0;
}
```

**预期输出**（数值有小幅抖动）：

```
A) 裸 syscall(SYS_ppoll)，timeout=5s，1 秒后 SIGALRM 打断
    调用前                      { tv_sec=5, tv_nsec=000000000 }
   ret=-1 errno=4(Interrupted system call) alarms=1
    调用后                      { tv_sec=3, tv_nsec=998xxx000 }   ← 【被改了】

B) glibc ppoll()，timeout=5s，1 秒后 SIGALRM 打断
    调用前                      { tv_sec=5, tv_nsec=000000000 }
   ret=-1 errno=4(Interrupted system call) alarms=2
    调用后                      { tv_sec=5, tv_nsec=000000000 }   ← 【没改】

C) 裸 syscall(SYS_ppoll)，timeout=1s，让它正常超时到期
    调用前                      { tv_sec=1, tv_nsec=000000000 }
   ret=0 errno=0(Success)
    调用后                      { tv_sec=0, tv_nsec=000000000 }   ← 【归零】
```

A 这一行就是 man7 BUGS 那条的行为 —— **`EINTR` 返回时 timeout 也被改了**。

> 📌 注意 A 里 `sigsetsize` 传的是 `8`（内核 `sigset_t` 的大小），不是 glibc 的 `128`。
> 因为 `sigmask` 是 NULL，`set_user_sigmask()` 会在 `if (!umask) return 0;`
> 直接返回，根本不检查 size —— 传什么都行。

### 示例 3：signalfd 的 `read()` 语义（`sfd_read_semantics.c`）

实测第 79 条（缓冲区 < 128 → `-EINVAL`）和批量读取（7.2 的 `nonblock = 1`）。

```c
/* sfd_read_semantics.c —— 实测 signalfd 的 read 语义
 * 构建: gcc -O0 -o sfd_read_semantics sfd_read_semantics.c
 */
#define _GNU_SOURCE
#include <errno.h>
#include <signal.h>
#include <stdio.h>
#include <string.h>
#include <sys/signalfd.h>
#include <unistd.h>

int main(void)
{
    sigset_t mask;
    sigemptyset(&mask);
    sigaddset(&mask, SIGRTMIN);
    sigprocmask(SIG_BLOCK, &mask, NULL);        /* ① 必须先阻塞，顺序不能反 */

    int sfd = signalfd(-1, &mask, SFD_NONBLOCK);
    if (sfd < 0) { perror("signalfd"); return 1; }

    /* 灌 3 个排队信号（实时信号才排队） */
    union sigval sv;
    for (int i = 0; i < 3; i++) {
        sv.sival_int = 100 + i;
        sigqueue(getpid(), SIGRTMIN, sv);
    }
    printf("已 sigqueue 3 个 SIGRTMIN\n");

    /* (a) 缓冲区 64 字节 < 128 → -EINVAL，而且不消耗任何信号 */
    char small[64];
    errno = 0;
    ssize_t r1 = read(sfd, small, sizeof small);
    printf("(a) read(64)      -> %zd  errno=%d(%s)\n",
           r1, errno, strerror(errno));

    /* (b) 缓冲区够大 → 一次 read 批量取走 3 个（nonblock=1 让循环不卡住） */
    struct signalfd_siginfo buf[8];
    errno = 0;
    ssize_t r2 = read(sfd, buf, sizeof buf);
    int n = (int)(r2 / (ssize_t)sizeof(buf[0]));
    printf("(b) read(%zu)   -> %zd  (= %d 个 siginfo)\n", sizeof buf, r2, n);
    for (int i = 0; i < n; i++)
        printf("      [%d] signo=%u si_code=%d si_int=%d\n",
               i, buf[i].ssi_signo, buf[i].ssi_code, buf[i].ssi_int);

    /* (c) 再读一次 → 队列已空，SFD_NONBLOCK → EAGAIN */
    errno = 0;
    ssize_t r3 = read(sfd, buf, sizeof buf);
    printf("(c) read again    -> %zd  errno=%d(%s)\n",
           r3, errno, strerror(errno));

    /* (d) 换成标准信号，验证「不排队」 */
    sigset_t m2; sigemptyset(&m2); sigaddset(&m2, SIGUSR1);
    sigprocmask(SIG_BLOCK, &m2, NULL);
    int sfd2 = signalfd(-1, &m2, SFD_NONBLOCK);
    for (int i = 0; i < 3; i++) raise(SIGUSR1);
    errno = 0;
    ssize_t r4 = read(sfd2, buf, sizeof buf);
    printf("(d) 3 个 SIGUSR1，read -> %zd (= %d 个，标准信号被合并)\n",
           r4, (int)(r4 > 0 ? r4 / (ssize_t)sizeof(buf[0]) : 0));

    close(sfd); close(sfd2);
    return 0;
}
```

**预期输出**：

```
已 sigqueue 3 个 SIGRTMIN
(a) read(64)      -> -1  errno=22(Invalid argument)
(b) read(1024)   -> 384  (= 3 个 siginfo)
      [0] signo=34 si_code=-1 si_int=100
      [1] signo=34 si_code=-1 si_int=101
      [2] signo=34 si_code=-1 si_int=102
(c) read again    -> -1  errno=11(Resource temporarily unavailable)
(d) 3 个 SIGUSR1，read -> 128 (= 1 个，标准信号被合并)
```

- **(a)** 印证第 79 条：`-EINVAL`，且 **(b) 仍能读到 3 个** →
  说明失败的 `read` **没有消耗信号**。
- **(b)** 印证 7.2 的 `nonblock = 1`：一次 `read` 取走 3 个，第 4 次尝试时非阻塞返回，
  循环立刻结束，不会卡住。
- **(c)** 印证 `SFD_NONBLOCK` → `-EAGAIN`。
- **(d)** 印证 `legacy_queue()`：3 个标准信号合并成 1 个。

### 示例 4：生产骨架 —— signalfd 并进 epoll（`sfd_epoll_loop.c`）

这是本节的**推荐形态**。注意它用的是普通 `epoll_wait()`，不是 `epoll_pwait()`
—— 因为信号全程阻塞，竞态不存在。

```c
/* sfd_epoll_loop.c —— signalfd + epoll 统一事件循环
 * 构建: gcc -O2 -Wall -o sfd_epoll_loop sfd_epoll_loop.c
 */
#define _GNU_SOURCE
#include <errno.h>
#include <signal.h>
#include <stdio.h>
#include <string.h>
#include <sys/epoll.h>
#include <sys/signalfd.h>
#include <unistd.h>

#define MAXEV 64

int main(void)
{
    /* ① 先阻塞，再建 signalfd —— 顺序反了会漏信号 */
    sigset_t mask;
    sigemptyset(&mask);
    sigaddset(&mask, SIGINT);
    sigaddset(&mask, SIGTERM);
    sigaddset(&mask, SIGHUP);
    sigaddset(&mask, SIGCHLD);
    sigprocmask(SIG_BLOCK, &mask, NULL);

    /* ② 建 signalfd。SFD_NONBLOCK 必带：EPOLLET 下阻塞 fd 会卡死 */
    int sfd = signalfd(-1, &mask, SFD_NONBLOCK | SFD_CLOEXEC);
    if (sfd < 0) { perror("signalfd"); return 1; }

    /* ③ 建 epoll，把 signalfd 当普通 fd 加进去 */
    int ep = epoll_create1(EPOLL_CLOEXEC);
    if (ep < 0) { perror("epoll_create1"); return 1; }

    struct epoll_event ev = { .events = EPOLLIN, .data.fd = sfd };
    if (epoll_ctl(ep, EPOLL_CTL_ADD, sfd, &ev) < 0) {
        perror("epoll_ctl(sfd)"); return 1;
    }
    /* 业务 fd 照常加：epoll_ctl(ep, EPOLL_CTL_ADD, sock, ...); */

    printf("pid=%ld 运行中。Ctrl+C / kill -TERM / kill -HUP %ld\n",
           (long)getpid(), (long)getpid());

    struct epoll_event evs[MAXEV];
    struct signalfd_siginfo si;
    int quit = 0;

    while (!quit) {
        /* ④ 用普通 epoll_wait —— 不需要 epoll_pwait。
           信号已全程阻塞，不可能在「检查→等待」之间溜进来。 */
        int n = epoll_wait(ep, evs, MAXEV, -1);
        if (n < 0) {
            /* mask 之外的信号（比如 SIGSEGV）仍可能打断，理论上要处理 */
            if (errno == EINTR) continue;
            perror("epoll_wait");
            break;
        }

        for (int i = 0; i < n; i++) {
            if (evs[i].data.fd != sfd) {
                /* 业务 fd 就绪 —— 正常处理 */
                continue;
            }

            /* ⑤ signalfd 就绪：循环读到 EAGAIN 为止，尽量批量取走 */
            for (;;) {
                ssize_t r = read(sfd, &si, sizeof si);
                if (r != (ssize_t)sizeof si)
                    break;                      /* EAGAIN 或出错 → 下一轮 epoll */

                switch (si.ssi_signo) {
                case SIGINT:
                    printf("SIGINT  (from pid %u) → 退出\n", si.ssi_pid);
                    quit = 1;
                    break;
                case SIGTERM:
                    printf("SIGTERM (from pid %u) → 退出\n", si.ssi_pid);
                    quit = 1;
                    break;
                case SIGHUP:
                    printf("SIGHUP  → 重载配置\n");
                    break;
                case SIGCHLD:
                    printf("SIGCHLD pid=%u status=%d\n",
                           si.ssi_pid, si.ssi_status);
                    break;
                }
                if (quit) break;
            }
            if (quit) break;
        }
    }

    close(ep);
    close(sfd);
    return 0;
}
```

**为什么这么写**：

| 决定 | 理由 |
|------|------|
| `sigprocmask` 在 `signalfd` **之前** | man7 明确要求；反了会漏掉建立期间到达的信号 |
| `SFD_NONBLOCK` 必带 | 若将来改成 `EPOLLET`，阻塞 fd 会漏事件并卡死；带了就两种触发模式都安全 |
| `SFD_CLOEXEC` 建议带 | `BUILD_BUG_ON(SFD_CLOEXEC != O_CLOEXEC)`，与 `O_CLOEXEC` 同值 |
| 用 `epoll_wait` 而非 `epoll_pwait` | signalfd 让竞态不存在，`epoll_pwait` 是多余开销 |
| `read` 循环到 `EAGAIN` | `signalfd_read` 的 `nonblock = 1` 语义：一次 `epoll_wait` 可能对应多个信号 |
| `if (errno == EINTR) continue` 仍保留 | mask **之外**的信号（如 `SIGSEGV`）照样能打断 `epoll_wait` |

> ⚠️ **如果是多线程程序**：把 signalfd 的创建和 `read` 都放在**同一个线程**里，
> 并确保你要收的信号是**进程级**的（`kill(getpid(), ...)` / 终端 / `SIGCHLD`）。
> 见第 8 节。

**Q1.** `pselect()` 到底会不会修改它的 `timeout` 参数？

<details>
<summary>答案</summary>

**取决于你调的是 glibc 封装还是内核 syscall。**

- **glibc `pselect()`**：**不会**。glibc 把 timeout 拷到一个局部变量再传给内核，
  你传入的对象原封不动。
- **内核 `pselect6()`**：**会**。

man7 `select(2)` NOTES 原文：

> **The Linux `pselect6()` system call modifies its `timeout` argument.**
> However, the glibc wrapper function hides this behavior by using a local variable
> for the timeout argument that is passed to the system call. Thus, the glibc
> `pselect()` function does not modify its `timeout` argument;
> this is the behavior required by POSIX.1-2001.

**为什么 glibc 非要多拷一次？** 因为 POSIX.1-2001 把 `pselect()` 的 timeout 声明成
`const struct timespec *`：

```c
int pselect(..., const struct timespec *timeout, const sigset_t *sigmask);
                 ^^^^^
```

对比 `select()` 的 `struct timeval *timeout` 没有 const。
**内核 syscall 的 ABI 里没有 const 的概念**——它拿到的就是一个可写的用户态指针，
`poll_select_finish()` 会用 `put_timespec64()` 把剩余时间写回去（`fs/select.c:346`）。
glibc 的局部变量拷贝是为了让**用户可见的行为**符合那个 `const`。

**实践影响**：只要你走 `syscall(SYS_ppoll, ...)`、手写汇编、
或者任何绕过 glibc 封装的路径，timeout 就会被改。
在循环里复用同一个 `struct timespec` 时会静默出错。
</details>
</details>

**Q2.** `select()` 在被信号打断（`EINTR`）返回时，会不会修改 `timeout`？POSIX 怎么说？

<details>
<summary>答案</summary>

**会改，而 POSIX 不允许。**

man7 `select(2)` BUGS 节原文：

> On Linux, `select()` **also modifies `timeout` if the call is interrupted by a
> signal handler** (i.e., the `EINTR` error return).
> **This is not permitted by POSIX.1.**

源码层面：`poll_select_finish()` 里 `restore_saved_sigmask_unless()` 是第一行
（`fs/select.c:304`），写回 timeout 在它后面 —— **两者之间没有按返回原因分叉**。
只要满足三个条件就写回：

| 条件 | 说明 |
|------|------|
| `p != NULL` | 用户传了非 NULL 的 timeout |
| `!(personality & STICKY_TIMEOUTS)` | 没设 sticky timeout personality |
| `end_time` 非全零 | 传入的 timeout 不是 `{0, 0}` |

跟"是不是 `EINTR` 返回"完全无关。

顺带说清楚 `select()` 的**超时返回**也改 timeout，这个是 POSIX 允许的：

> On Linux, `select()` modifies `timeout` to reflect the amount of time not slept;
> most other implementations do not do this. (**POSIX.1 permits either behavior.**)

所以 Linux 上 `select()` 的 timeout 无论怎么返回都该当成**未定义**：
> "Consider `timeout` to be undefined after `select()` returns."
</details>
</details>

	len = min_t(unsigned int, nfds, N_STACK_PPS);

		walk->next = NULL;
		walk->len = len;

			break;                              /* len = 0 → 立刻退出 */
		...
```

		if (!count) {
			count = wait->error;
			if (signal_pending(current))
				count = -ERESTARTNOHAND;
		}
```

纯睡眠 + 原子换掩码。同理，传 `pollfd.fd = -1` 也可以 ——
`do_pollfd()` 对 `fd < 0` 直接返回 0（不置 `POLLNVAL`）。
</details>
</details>

**Q4.** 为什么 `pselect`/`ppoll` 里是 `restore_saved_sigmask_unless(ret == -ERESTARTNOHAND)`，
而 `epoll_pwait` 里是 `restore_saved_sigmask_unless(error == -EINTR)`？哪个写错了？

<details>
<summary>答案</summary>

**都没写错。两处判断的是同一件事，只是"被信号打断"在两个子系统里的表示方式不同。**

```c
/* fs/select.c:304 */
	restore_saved_sigmask_unless(ret == -ERESTARTNOHAND);

/* fs/eventpoll.c:2354 */
	restore_saved_sigmask_unless(error == -EINTR);
```

看各自的中断返回码：

| 等待函数 | 源码行 | 中断返回码 |
|---------|-------|-----------|
| `do_select()` | `select.c:686` | `ret = -ERESTARTNOHAND;` |
| `do_poll()` | `select.c:939` | `count = -ERESTARTNOHAND;` |
| `ep_poll()` | `eventpoll.c:1877` | `return -EINTR;` |

`select`/`poll` 这一支返回的是**内核内部错误码** `-ERESTARTNOHAND`
（含义："如果装了 handler 就不重启，直接给用户态 `-EINTR`"；
在 `poll_select_finish()` 里它还没被翻译 —— 只有走到 `sticky:` 标签才会
`if (ret == -ERESTARTNOHAND) ret = -EINTR;`）。

`epoll` 这一支直接返回 `-EINTR`。

所以两处条件都必须匹配**自己那个子系统当时用的表示形式**。

---

**helper 本身的语义**：

```c
/* include/linux/sched/signal.h:555-561 */
static inline void restore_saved_sigmask_unless(bool interrupted)
{
	if (interrupted)
		WARN_ON(!signal_pending(current));
	else
		restore_saved_sigmask();
}
```

`interrupted == true` → **不在这里还原**，只断言"确实有信号 pending"，
把还原工作留给返回用户态前的 arch 信号代码（它看到 `TIF_RESTORE_SIGMASK` 就会处理）。

**为什么要留到那时候？** 因为顺序很重要：

```
handler 用【临时的、已解除阻塞的】掩码跑
    ↓
handler 返回后，arch 代码看到 TIF_RESTORE_SIGMASK
    ↓
restore_saved_sigmask() → blocked := saved_sigmask
    ↓
用户看到 errno == EINTR，且掩码已还原
```

如果在这里就地还原，handler 就会在**原掩码**（信号全阻塞）下运行，
那 `pselect` 传进来的 `sigmask` 就白传了。

`kernel/signal.c:3128` 的注释把这条约束写成了硬性要求：
> "Note that it does `set_restore_sigmask()` in advance, so it must be always
> paired with `restore_saved_sigmask_unless()` before return from syscall."
</details>
</details>

**Q5.** `epoll_pwait2()` 会像 `ppoll()` 那样把剩余时间写回 `timeout` 吗？

<details>
<summary>答案</summary>

**不会。** 它是这一堆接口里唯一"纳秒精度 + 不改 timeout"的。

```c
/* fs/eventpoll.c:2370-2386 */
SYSCALL_DEFINE6(epoll_pwait2, int, epfd, struct epoll_event __user *, events,
		int, maxevents, const struct __kernel_timespec __user *, timeout,
		const sigset_t __user *, sigmask, size_t, sigsetsize)
{
	struct timespec64 ts, *to = NULL;

	if (timeout) {
		if (get_timespec64(&ts, timeout))
			return -EFAULT;
		to = &ts;                            /* ← 指向【栈上局部变量】 */
		if (poll_select_set_timeout(to, ts.tv_sec, ts.tv_nsec))
			return -EINVAL;
	}

	return do_epoll_pwait(epfd, events, maxevents, to, sigmask, sigsetsize);
}
```

`to = &ts` 指向栈变量，`do_epoll_wait()` 用完之后就随栈帧一起消失 ——
**从来没有任何 `copy_to_user` 把它写回 `timeout`**。
（对比 `ppoll` 有 `poll_select_finish(&end_time, tsp, PT_TIMESPEC, ret)`，
里面就是 `put_timespec64(&rts, p)`。）

完整对照表：

| 接口 | timeout 形参 | 内核写回? |
|------|-------------|----------|
| `select()` | `struct __kernel_old_timeval *` | ✅ |
| `pselect6()` | `struct __kernel_timespec *` | ✅ |
| `ppoll` | `struct __kernel_timespec *` | ✅ |
| `epoll_pwait()` | `int timeout`（**按值**） | ❌ 无从写起 |
| **`epoll_pwait2()`** | `const struct __kernel_timespec *` | **❌** |

> 📌 `epoll_pwait()` 的 `int timeout` 是按值传的（毫秒精度），
> 物理上不可能被写回。这既是它的缺点（只有 ms 精度），也是它的优点（天然免疫此坑）。
</details>
</details>

**Q6.** `struct signalfd_ctx` 里存的 `sigmask` 是"我想接收的信号集"吗？`SIGKILL` 放进 mask 会怎样？

<details>
<summary>答案</summary>

**不是。存的是取反后的（"要跳过"的）集合。**

```c
/* fs/signalfd.c:41-43 —— 只有一个字段 */
struct signalfd_ctx {
	sigset_t sigmask;
};

/* fs/signalfd.c:263-272 */
	if (flags & ~(SFD_CLOEXEC | SFD_NONBLOCK))
		return -EINVAL;

	sigdelsetmask(mask, sigmask(SIGKILL) | sigmask(SIGSTOP));   /* ① */
	signotset(mask);                                            /* ② 取反 */

	if (ufd == -1) {
		ctx = kmalloc(sizeof(*ctx), GFP_KERNEL);
		if (!ctx)
			return -ENOMEM;

		ctx->sigmask = *mask;                                   /* ③ 存反码 */
```

**为什么要存反码？** 因为下游直接用它调 `dequeue_signal()`，
而 `dequeue_signal()` 的第二个参数语义是"**要跳过**的信号集合"：

```c
/* fs/signalfd.c:163 */
	ret = dequeue_signal(current, &ctx->sigmask, info, &type);
```

存反码正好可以直接喂进去，省掉每次取反。

---

**`SIGKILL` / `SIGSTOP` 放进 mask 会怎样？—— 静默忽略。**

`①` 那行在**取反之前**就把它们从"用户想接收的集合"里删掉了，
所以取反之后它们落在"要跳过"的那一侧 —— 你永远读不到。

man7 印证（两次强调）：

> "It is not possible to receive SIGKILL or SIGSTOP signals via a signalfd file
> descriptor; these signals are **silently ignored** if specified in mask."

> "Attempts to include SIGKILL and SIGSTOP in mask are **silently ignored**."

⚠️ 注意"**silently**"：不返回 `-EINVAL`，不打日志，man7 也只是陈述事实。
这已经是本批笔记里第 4 次遇到内核的"静默"行为了
（前三次见 [63.3](./63.3-signal-driven-i-o.md)：`f_op->fasync == NULL` 时
`fcntl(O_ASYNC)` 返回 0、`F_SETOWN` 未设时静默丢通知、`epoll_create(size)` 忽略 size）。

> 📌 顺带：`/proc/pid/fdinfo` 里看到的 `sigmask:` 是**再取反一次**的结果，
> 也就是用户的原始语义，方便人读：
> ```c
> /* fs/signalfd.c:237-239 */
> sigmask = ctx->sigmask;
> signotset(&sigmask);
> render_sigset_t(m, "sigmask:\t", &sigmask);
> ```
</details>
</details>

**Q7.** `read(sfd, buf, 64)`（缓冲区小于 128 字节）会发生什么？

<details>
<summary>答案</summary>

**返回 `-1`，`errno == EINVAL`。一个字节都不读，也不消耗任何信号。**

```c
/* fs/signalfd.c:211-213 */
	count /= sizeof(struct signalfd_siginfo);      /* 64 / 128 = 0 */
	if (!count)
		return -EINVAL;                            /* ← 直接返回 */
```

---

**⚠️ 这里是文档缺口**：man7 `signalfd(2)` 只在正文里写了一句

> "The buffer must be at least `sizeof(struct signalfd_siginfo)` bytes."

但 **ERRORS 小节里列的两条 `EINVAL` 都不包含这条**：

```
EINVAL fd is not a valid signalfd file descriptor.
EINVAL flags is invalid; or, in Linux 2.6.26 or earlier, flags is nonzero.
```

也就是说，**这个错误码只能靠读源码（或亲自踩）才知道。**
这跟第 71 条是同一族的问题：手册记录的是"应该怎么用"，不是"用错了会发生什么"。

---

**另外两个相关语义**：

1. **零头被丢弃**：`count /= sizeof(...)` 是整数除法。
   `read(sfd, buf, 200)` 和 `read(sfd, buf, 128)` 等效（都只装 1 个）。

2. **批量读取，但只有第一次可能阻塞**：
   ```c
   /* fs/signalfd.c:216-226 */
   	do {
   		ret = signalfd_dequeue(ctx, &info, nonblock);
   		if (unlikely(ret <= 0))
   			break;
   		ret = signalfd_copyinfo(siginfo, &info);
   		if (ret < 0)
   			break;
   		siginfo++;
   		total += ret;
   		nonblock = 1;                        /* ← 第一次成功后一律非阻塞 */
   	} while (--count);
   ```
   `nonblock = 1` 保证：一次 `read` 能把当前 pending 的信号**批量取走**，
   但绝不会在取完最后一个之后卡住等新信号。
</details>

**Q8.** 多线程程序里，主线程建了 signalfd 并 `epoll_wait`，工作线程用
`pthread_kill(worker_tid, SIGUSR1)` 给自己发信号。主线程的 signalfd 能读到吗？

<details>
<summary>答案</summary>

**读不到。永远读不到，而且不会有任何错误提示。**

源码依据 —— `signalfd_poll()` 查的是两个队列：

```c
/* fs/signalfd.c:58-62 */
	spin_lock_irq(&current->sighand->siglock);
	if (next_signal(&current->pending, &ctx->sigmask) ||          /* ① 当前线程私有 */
	    next_signal(&current->signal->shared_pending,             /* ② 进程级共享 */
			&ctx->sigmask))
		events |= EPOLLIN;
	spin_unlock_irq(&current->sighand->siglock);
```

关键在于 **`current`** —— 是"**正在 `poll`/`read` 的那个线程**"，
不是"创建 signalfd 的那个线程"。

`pthread_kill(worker_tid, ...)` 产生的信号进的是 **worker 的私有 pending 队列**，
主线程（= `current`）的 `current->pending` 里没有它。

man7 说得更直白：

> "when a thread reads from a signalfd file descriptor, it will read the signals that
> are directed to the thread itself and the signals that are directed to the process
> (i.e., the entire thread group).
> **(A thread will not be able to read signals that are directed to other threads
> in the process.)**"

---

**对照表**：

| 来源 | 落在哪个队列 | 主线程 signalfd |
|------|-------------|---------------|
| `kill(getpid(), sig)` | `shared_pending` | ✅ 读得到 |
| `sigqueue(getpid(), sig, ...)` | `shared_pending` | ✅ 读得到 |
| 终端 `Ctrl+C` → `SIGINT` | `shared_pending` | ✅ 读得到 |
| 子进程退出 → `SIGCHLD` | `shared_pending` | ✅ 读得到 |
| `pthread_kill(worker_tid, sig)` | `worker.pending` | ❌ **读不到** |
| `tgkill(pid, worker_tid, sig)` | `worker.pending` | ❌ **读不到** |
| worker 自己的 `SIGSEGV` | `worker.pending` | ❌（且同步信号本来就不能用 signalfd） |

**怎么办（三选一）**：

1. 改成**进程级**发送：`kill(getpid(), sig)` / `sigqueue(getpid(), ...)`。
2. 让**每个线程自己建一个 signalfd**，各自 `read`。
3. **由需要收信号的那个线程自己去 `read` 这个 signalfd**（signalfd fd 是共享的，
   谁 `read` 就查谁的队列）。

---

**对 HFT 的直接影响**：常见的"一个 pin 核线程跑事件循环 + 若干工作线程"布局下，
如果停机/重配置信号是工作线程用 `pthread_kill()` 自发自收的，
那"主线程统一 signalfd"的方案**从设计上就不成立**。这是必须在架构阶段就想清楚的。

> 📌 相关的 fork 语义（man7）：
> "After a `fork(2)`, the child inherits a copy of the signalfd file descriptor.
> A `read(2)` from the file descriptor in the child will return information about
> signals queued to the child."
> ⚠️ 更阴的一点：如果父进程把 signalfd 加进了 epoll 实例，
> **`fork` 后子进程的 `epoll_wait()` 不会把这个继承来的 fd 报成就绪**。
> 变通办法：子进程关掉继承的 fd，重建 signalfd，重新加进 epoll。
</details>
</details>

<details>
<summary>自测题 9（点击展开）</summary>

**Q9.** 连发 3 个 `SIGTERM`（进程已用 `sigprocmask` 阻塞），然后 `read()` signalfd，能读到几个？

<details>
<summary>答案</summary>

**1 个。** 标准信号不排队，pending 状态只记一个位。

```c
/* kernel/signal.c:1079-1082 */
static inline bool legacy_queue(struct sigpending *signals, int sig)
{
	return (sig < SIGRTMIN) && sigismember(&signals->signal, sig);
}

/* :1104-1106 —— 在 __send_signal_locked() 里 */
	if (legacy_queue(pending, sig))
		goto ret;                    /* 已有同号 pending → 不再排队 */
```

`legacy_queue()` 返回 true 的条件是"**`sig < SIGRTMIN` 且已经在 pending 集合里**" ——
两个条件都满足就跳过排队，直接返回。

---

| 信号类型 | 排队? | 3 连发能读到 |
|---------|-------|-------------|
| 标准信号（`SIGTERM`/`SIGINT`/`SIGHUP`/`SIGCHLD`，1–31） | ❌ 合并为 1 | 1 个 |
| 实时信号（`SIGRTMIN`+，配合 `sigqueue()`） | ✅ 真排队 | 3 个 |

**实践判断**：

- **停机/重载语义**下无所谓 —— 一个就够了，多余的是噪音。
- **需要计数或携带不同数据**时必须用 `SIGRTMIN..SIGRTMAX` + `sigqueue()`。
  实时信号的 pending 用的是**链表**（不是位图），所以真的会排队。

man7 还补充了一条多 fd 的情形：

> "If a signal appears in the mask of more than one of the file descriptors, then
> occurrences of that signal can be read (**once**) from any one of the file descriptors."

即：一个进程建了多个 signalfd、同一个信号在多个 fd 的 mask 里时，
**它只会被读走一次**，不是每个 fd 各一份。
</details>
</details>

<details>
<summary>自测题 10（点击展开）</summary>

**Q10.** 判断下列说法对错，并给出依据：

① 用了 signalfd 之后，还需要 `epoll_pwait()` 来保证不丢信号。
② signalfd 可以替代所有 signal handler，包括 `SIGSEGV` 的兜底。
③ `epoll_pwait()` 的 `timeout` 参数和 `ppoll()` 一样，返回时会被改成剩余时间。
④ `pselect6` 的第 6 个参数是 `sigset_t *`。
⑤ `set_current_blocked()` 会按你给的掩码原样设置。

<details>
<summary>答案</summary>

**全部为错。**

| # | 判定 | 依据 |
|---|------|------|
| ① 还需 `epoll_pwait` | ❌ | **恰恰相反 —— 不需要了。** signalfd 方案里信号全程被 `sigprocmask` 阻塞，永远不会"打断"任何等待；竞态的前提（"信号在等待开始前到达"）**根本不成立**。用普通 `epoll_wait()` 就够。见 `sfd_epoll_loop.c` |
| ② 能替代所有 handler | ❌ | **同步生成的信号收不到。** man7 Limitations 原文："The signalfd mechanism can't be used to receive signals that are **synchronously generated**, such as the `SIGSEGV` signal that results from accessing an invalid memory address or the `SIGFPE` signal that results from an arithmetic error. Such signals can be caught only via signal handler." 栈溢出兜底仍需传统 handler + `sigaltstack()` |
| ③ `epoll_pwait` 改 timeout | ❌ | **`epoll_pwait()` 的 timeout 是 `int`（按值传、毫秒精度），物理上无从写起。** 即便是纳秒精度的 `epoll_pwait2()`，**也不写回** —— `to = &ts` 指向栈变量，用后即弃（`eventpoll.c:2374-2386`）。改 timeout 的是 `ppoll`/`pselect6`/`select` |
| ④ 第 6 参是 `sigset_t *` | ❌ | 是 **`struct sigset_argpack { sigset_t __user *p; size_t size; }`**（`select.c:773-776`）。原因写在注释里："Most architectures can't handle 7-argument syscalls. So we provide a 6-argument version where the sixth argument is a pointer to a structure which has a pointer to the `sigset_t` itself followed by a `size_t` containing the sigset size." |
| ⑤ 原样设置 | ❌ | **会强行剔除 `SIGKILL`/`SIGSTOP`：<br>`void set_current_blocked(sigset_t *newset) { sigdelsetmask(newset, sigmask(SIGKILL) \| sigmask(SIGSTOP)); __set_current_blocked(newset); }`（`signal.c:3064-3068`）。**<br>而 `__set_current_blocked()`（多两个下划线）**不**剔除 —— 注释："NOTE! Unlike the user-mode `sys_sigprocmask()`, the kernel interface happily blocks 'unblockable' signals like SIGKILL and friends." |

**最容易凭直觉答对的是 ③ 和 ⑤** —— 尤其是 ⑤，
`set_current_blocked()` 和 `__set_current_blocked()` 只差两个下划线，
语义却差了一道保险。内核里这种"同名近似 API 语义不同"的情况要格外小心
（参见 [63.4](./63.4-the-epoll-api.md) 里 `epoll_create` / `epoll_create1` 的对比）。

> 📌 关于 ①，补一句**常见误解**：signalfd 消灭的是 **EINTR 重试循环**和**竞态窗口**，
> 不是"信号处理的延迟"。信号仍要完整走一遍
> `sighand->siglock` 加锁 → pending 入队 → 唤醒 `signalfd_wqh` →
> `epoll_wait` 返回 → `read()` 系统调用。
> 它的价值是**代码结构简单、行为可预测**，不是延迟更低。
> 真要压延迟，方向是 [12.5 现代网络](../../../12.5-modern-networking/) 的 `io_uring`。
</details>
