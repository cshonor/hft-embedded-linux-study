# 4.5 `write()`

## 本节讲什么

`write()` 把字节写进 fd。本节回答三个问题：

1. `write()` 在内核里怎么校验、怎么落到页缓存？
2. 「部分写（partial write）」为什么是正常现象，怎么处理？
3. 为什么「`write` 成功 ≠ 数据已落盘」？`SIGPIPE` 又是什么？

本节有一条**反直觉**的实测结论：`write` 返回 0 竟然是合法的。还有一条**能救命**的：写管道时进程会莫名死掉，是 `SIGPIPE` 干的。

---

## 1. 原型与内核链路

```c
#include <unistd.h>
ssize_t write(int fd, const void *buffer, size_t count);
/* >0 实际写入字节（可能 < count）；-1 = 出错 */
```

```
用户态 write(fd, buf, count)
      ▼
SYSCALL_DEFINE3(write)        fs/read_write.c:646
      ▼
ksys_write()                  fs/read_write.c:626
      ├─→ fdget_pos(fd)      ← 取 struct file（流式对象 f_pos 为 NULL）
      ├─→ vfs_write()        ← 通用校验 + 分派（见下）
      └─→ 成功回写 f_pos，fdput_pos(f)
```

`vfs_write()` 的**逐字全文**（`fs/read_write.c:564-594`，v6.6）——和 `vfs_read` 完全对称：

```c
ssize_t vfs_write(struct file *file, const char __user *buf, size_t count, loff_t *pos)
{
	ssize_t ret;

	if (!(file->f_mode & FMODE_WRITE))
		return -EBADF;
	if (!(file->f_mode & FMODE_CAN_WRITE))
		return -EINVAL;
	if (unlikely(!access_ok(buf, count)))
		return -EFAULT;

	ret = rw_verify_area(WRITE, file, pos, count);
	if (ret)
		return ret;
	if (count > MAX_RW_COUNT)
		count =  MAX_RW_COUNT;
	file_start_write(file);
	if (file->f_op->write)
		ret = file->f_op->write(file, buf, count, pos);
	else if (file->f_op->write_iter)
		ret = new_sync_write(file, buf, count, pos);
	else
		ret = -EINVAL;
	if (ret > 0) {
		fsnotify_modify(file);
		add_wchar(current, ret);
	}
	inc_syscw(current);
	file_end_write(file);
	return ret;
}
```

## 2. 偏移是从哪回写的？—— 看 `ksys_read`

`vfs_read`/`vfs_write` 里那个 `loff_t *pos` 参数到底指向谁？`ksys_read`（`:602-618`）给出了答案，逐字：

```c
ssize_t ksys_read(unsigned int fd, char __user *buf, size_t count)
{
	struct fd f = fdget_pos(fd);
	ssize_t ret = -EBADF;

	if (f.file) {
		loff_t pos, *ppos = file_ppos(f.file);
		if (ppos) {
			pos = *ppos;
			ppos = &pos;
		}
		ret = vfs_read(f.file, buf, count, ppos);
		if (ret >= 0 && ppos)
			f.file->f_pos = pos;
		fdput_pos(f);
	}
	return ret;
}
```

而 `file_ppos`（`:597-600`）：

```c
/* file_ppos returns &file->f_pos or NULL if file is stream */
static inline loff_t *file_ppos(struct file *file)
{
	return file->f_mode & FMODE_STREAM ? NULL : &file->f_pos;
}
```

三件事一次说清：

1. **普通文件**：`ppos` 指向 `struct file::f_pos`，`vfs_read` 直接改它；
2. 但代码还是**先拷到局部 `pos` 再传出去**，读完才 `f.file->f_pos = pos` 回写——这样「读失败」时偏移不会被改动一半；
3. **流式对象**（socket/pipe 设了 `FMODE_STREAM`）`ppos == NULL`，`vfs_read` 收到 `NULL` 也不回写——**这就是它们没有"当前位置"、`lseek` 返回 `ESPIPE` 的同一根源**。

## 3. 部分写（partial write）：必须循环

和 `read` 的短读一样，`write` **可以**只写一部分就返回：

| 部分写原因 | 场景 |
|-----------|------|
| 管道/FIFO 缓冲不足 | `PIPE_BUF` 限制，只写满缓冲区就返回 |
| 磁盘空间不足 | `ENOSPC`，只写入剩余空间能容纳的部分 |
| socket 发送缓冲部分满 | TCP 发送缓冲区只有这么多空闲 |
| 信号中断 | `EINTR`，部分数据已写出 |

标准封装 `writeall`：

```c
ssize_t writeall(int fd, const void *buf, size_t n)
{
    size_t total = 0;

    while (total < n) {
        ssize_t w = write(fd, (char *) buf + total, n - total);
        if (w < 0 && errno == EINTR)
            continue;                       /* 信号中断：重试 */
        if (w < 0)
            return -1;
        total += (size_t) w;
    }
    return (ssize_t) total;
}
```

> **原书 Listing 4-1（`copy.c`）用的是 `if (write(...) != numRead) fatal(...)`**——它敢这么写，因为只拷普通文件。一旦换成管道/socket，"部分写"就是常态，`!=` 直接报错等于把「可恢复的慢」当成「不可恢复的错」。手工制造一次部分写见 [练习 4-3](4.10-exercises.md)。

## 4. 代码：六组实测，包括三次"以为会怎样、实际不是"

完整源码 [`code/c4_5_write.c`](../code/c4_5_write.c)：

```c
/* c4_5_write.c — write() 的返回值、部分写、以及「成功 ≠ 落盘」
 *
 * 演示六件事：
 *   1) write 返回实际写入字节数；写入普通文件通常一次写满
 *   2) count == 0 时 write 返回 0（合法，不是错误）
 *   3) /dev/full：写永远报 ENOSPC（磁盘满是什么样）
 *   4) SIGPIPE：写「读端已关闭」的管道——不忽略会被信号杀掉
 *   5) 忽略 SIGPIPE 后，同样的操作变成 -1 + EPIPE
 *   6) write 成功只到页缓存；fsync 才是落盘
 *
 * 编译: gcc -O0 -Wall -o c4_5_write c4_5_write.c
 */
#include <fcntl.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <unistd.h>
#include <signal.h>
#include <errno.h>
#include <sys/wait.h>

/* 往「读端已关闭」的管道写，在 SIGPIPE 默认动作下的下场 */
static void default_sigpipe_child(void)
{
    int p[2];
    pipe(p);
    close(p[0]);                        /* 读端关掉：已经没人听了 */
    printf("  [子进程] 读端已关闭，现在 write(p[1], ...) ...\n");
    fflush(stdout);
    ssize_t n = write(p[1], "x", 1);    /* 这一步会触发 SIGPIPE */
    printf("  [子进程] write 返回 %zd （走不到这里）\n", n);
    _exit(0);                           /* 不用 exit()，它会刷 stdio */
}

int main(void)
{
    char big[4096];
    memset(big, 'A', sizeof big);
    ssize_t n;

    printf("== 1. 正常写：普通文件一次写满 ==\n");
    const char *path = "/tmp/c4_write.txt";
    int fd = open(path, O_WRONLY | O_CREAT | O_TRUNC, 0644);
    n = write(fd, big, sizeof big);
    printf("  write(4096) -> %zd  （普通文件通常一次写完）\n", n);

    printf("\n== 2. count = 0：合法返回 0 ==\n");
    errno = 0;
    n = write(fd, big, 0);
    printf("  write(fd, buf, 0) -> %zd  errno=%d  （0 不是错误，是「写了 0 个字节」）\n", n, errno);
    close(fd);

    printf("\n== 3. /dev/full：永远 ENOSPC，模拟磁盘满 ==\n");
    int full = open("/dev/full", O_WRONLY);
    if (full >= 0) {
        errno = 0;
        n = write(full, big, sizeof big);
        printf("  write(/dev/full, 4096) -> %zd  errno=%d (%s)\n",
               n, errno, strerror(errno));
        close(full);
    } else {
        printf("  （本环境没有 /dev/full）\n");
    }

    printf("\n== 4. SIGPIPE 的默认动作：直接杀进程 ==\n");
    /* ⚠️ fork 之前必须 flush：stdout 被重定向时是全缓冲，缓冲区内容会被
       子进程一起继承，父子各刷一遍 → 前面的输出重复两遍。 */
    fflush(stdout);
    pid_t pid = fork();
    if (pid == 0) {
        default_sigpipe_child();
        _exit(0);
    }
    int status;
    waitpid(pid, &status, 0);
    if (WIFSIGNALED(status)) {
        printf("  [父进程] 子进程被信号杀死：signal = %d", WTERMSIG(status));
        if (WTERMSIG(status) == SIGPIPE) printf(" = SIGPIPE");
        printf("\n  → 服务器写 socket 前不忽略它，一个断连就能带走整个进程。\n");
    } else {
        printf("  [父进程] 子进程正常退出 status=%d\n", WEXITSTATUS(status));
    }

    printf("\n== 5. 忽略 SIGPIPE：变成可处理的 EPIPE ==\n");
    signal(SIGPIPE, SIG_IGN);
    int p[2];
    pipe(p);
    close(p[0]);
    errno = 0;
    n = write(p[1], "x", 1);
    printf("  signal(SIGPIPE, SIG_IGN) 后 write -> %zd  errno=%d (%s)\n",
           n, errno, strerror(errno));
    printf("  → 进程活着，错误变成可判断、可恢复的返回值。这是网络服务的标准做法。\n");
    close(p[1]);

    printf("\n== 6. write 成功 ≠ 落盘 ==\n");
    fd = open(path, O_WRONLY | O_CREAT | O_TRUNC, 0644);
    n = write(fd, "durable?", 8);
    printf("  write 返回 %zd —— 数据此刻在页缓存（脏页）里，还没进磁盘\n", n);
    int rc = fsync(fd);
    printf("  fsync 返回 %d —— 到这里才算真正刷到存储设备\n", rc);
#ifdef __linux__
    rc = fdatasync(fd);
    printf("  fdatasync 返回 %d —— 只保证数据部分，不保证元数据\n", rc);
#endif
    printf("  → 断电测试：write 之后立刻拔电，数据可能丢；fsync 之后拔电才安全。\n");
    close(fd);
    unlink(path);
    return 0;
}
```

编译运行：

```bash
gcc -O0 -Wall -Wextra -o c4_5_write c4_5_write.c && ./c4_5_write
```

CE（gcc 13.3.0 / x86-64 / Ubuntu 24.04）实测：

```text
== 1. 正常写：普通文件一次写满 ==
  write(4096) -> 4096  （普通文件通常一次写完）

== 2. count = 0：合法返回 0 ==
  write(fd, buf, 0) -> 0  errno=0  （0 不是错误，是「写了 0 个字节」）

== 3. /dev/full：永远 ENOSPC，模拟磁盘满 ==
  （本环境没有 /dev/full）

== 4. SIGPIPE 的默认动作：直接杀进程 ==
  [子进程] 读端已关闭，现在 write(p[1], ...) ...
  [父进程] 子进程被信号杀死：signal = 13 = SIGPIPE
  → 服务器写 socket 前不忽略它，一个断连就能带走整个进程。

== 5. 忽略 SIGPIPE：变成可处理的 EPIPE ==
  signal(SIGPIPE, SIG_IGN) 后 write -> -1  errno=32 (Broken pipe)
  → 进程活着，错误变成可判断、可恢复的返回值。这是网络服务的标准做法。

== 6. write 成功 ≠ 落盘 ==
  write 返回 8 —— 数据此刻在页缓存（脏页）里，还没进磁盘
  fsync 返回 0 —— 到这里才算真正刷到存储设备
  fdatasync 返回 0 —— 只保证数据部分，不保证元数据
  → 断电测试：write 之后立刻拔电，数据可能丢；fsync 之后拔电才安全。
```

逐条看：

| 观察 | 说明 |
|------|------|
| `write(4096)` 返回 4096 | 普通文件上「一次写完」是常态，但这是**行为**不是**保证** |
| **`write(fd, buf, 0)` 返回 0、`errno=0`** | 反直觉但正确：写入 0 个字节是一次成功的操作。**所以 `w == 0` 不能当"写完了"的信号，只有 `-1` 才是错** |
| `/dev/full` 不存在 | CE 沙箱（容器）没建这个设备节点。它的语义是「写永远报 `ENOSPC`」，用来测"磁盘满"分支——本环境只能跳过（代码里已优雅降级） |
| 子进程被 `signal 13 = SIGPIPE` 杀死 | **这是本节最实用的一条**。向"读端已关闭"的管道写数据，内核发给写进程 `SIGPIPE`，默认动作是**终止进程**。服务器写 socket 时对端随时可能断开——不处理就是"一个断连干掉整个服务" |
| 忽略后变成 `-1 errno=32 EPIPE` | `signal(SIGPIPE, SIG_IGN)` 之后，同一个操作变成**可判断、可恢复**的错误码。网络服务的标准做法 |
| `fsync` 返回 0 才算落盘 | `write` 返回 8 时数据在页缓存（脏页）里。**断电就丢**。`fsync`（数据+元数据）/ `fdatasync`（只数据）才是持久化边界，详见 Ch13 |

> 第 4 条的实测里有个细节：子进程是在 `printf` 一句之后、`write` 那一刻被杀的，所以父进程 `waitpid` 拿到的是 `WIFSIGNALED` 而非退出码。血统纯正的 `SIGPIPE` 事故就长这样——**程序没有任何错误日志，直接消失**。

## 5. SIGPIPE：写已关闭的管道会杀进程

向「读端已关闭」的管道/socket 写数据时，内核会向写进程发送 `SIGPIPE` 信号；该信号默认动作是**终止进程**：

```c
write(pipe_fd, buf, n);   /* 对端已 close → 进程被 SIGPIPE 杀死 */
signal(SIGPIPE, SIG_IGN); /* 忽略后，write 返回 -1，errno=EPIPE */
```

服务器写 socket 时对端可能随时断开，因此**必须先忽略 `SIGPIPE`**，否则一个断连就能让整个服务崩溃。忽略后 `write` 返回 `-1` + `EPIPE`（实测 `errno=32`），程序自己处理。

## 6. 成功 ≠ 落盘：数据先入页缓存

`write` 返回成功，只表示数据**拷进了内核页缓存**（page cache），**尚未**写进物理磁盘：

```
write(fd, data, size)
   │  copy_from_user → 页缓存（脏页）
   │  返回成功！但数据还在内存里
   ▼
fsync(fd) / fdatasync(fd)   ← 强制把脏页刷到磁盘
```

断电、内核崩溃时，页缓存里尚未刷盘的脏页会**丢失**。要保证持久化必须显式 `fsync`/`fdatasync`（Ch13）。嵌入式/HFT 落盘场景尤其要分清「写进内核」和「写进磁盘」的边界。

## 7. HFT / 嵌入式关联

| 现象 | 本节机制的兑现 |
|------|----------------|
| 行情日志落盘 | `write` 成功不代表安全，崩溃可能丢最近几秒日志；关键数据要 `fdatasync`，但 `fdatasync` 会阻塞，需权衡 |
| 多进程追加 | `O_APPEND` 让每次 `write` 原子地追加到末尾，避免部分写交错（Ch5） |
| 服务器防崩 | 写 socket 前忽略 `SIGPIPE`，否则对端断连直接杀进程（实测 `signal 13`） |
| 少 syscall | 批量 `write`（大缓冲）比多次小 `write` 省 syscall（`vfs_write` 末尾 `inc_syscw` 在计数），但大缓冲也意味着延迟数据攒满才写 |
| `w == 0` 不是完成信号 | 只有 `-1` 才是错误。写循环的退出条件是 `total == n`，不是 `w == 0` |

<summary>代码自测（Q&A）</summary>

**Q1：`write()` 返回值小于请求字节数时该怎么办？**
A：这是「部分写」，正常现象，不能当错误。应循环写剩余部分直到全部写完（见 `writeall`）。不处理会导致数据静默丢失——尤其管道、socket、磁盘快满时。

**Q2：`write` 成功返回后，数据一定在磁盘上了吗？**
A：不一定。`write` 成功只表示数据进了**内核页缓存**（脏页），断电/崩溃会丢。要保证持久化必须 `fsync`（连元数据一起刷）或 `fdatasync`（只刷数据）。这正是「成功 ≠ 落盘」的含义。

**Q3：向对端已关闭的管道写数据，进程为什么可能「莫名退出」？**
A：内核会向写进程发 `SIGPIPE`（实测信号号 13），默认动作是终止进程——所以程序**没有任何错误日志就直接消失**。服务器写 socket 时对端随时可能断开，所以要先 `signal(SIGPIPE, SIG_IGN)` 忽略它，这样 `write` 会返回 `-1` + `EPIPE`（实测 `errno=32`），由程序自己处理断连。

**Q4：`write` 的 `-EBADF` 和 `-EFAULT` 分别查什么？**
A：`EBADF` 查 **fd**——无效或没以写方式打开（`vfs_write` 里 `!(f_mode & FMODE_WRITE)`）。`EFAULT` 查 **buf**——用户态缓冲区地址非法（`access_ok` 失败），`buf` 可能是野指针或 `count` 越界。

**Q5：流式对象（socket/pipe）为什么没有「文件偏移」？**
A：看 `file_ppos()`（`fs/read_write.c:597-600`）：`file->f_mode & FMODE_STREAM ? NULL : &file->f_pos`。socket/pipe 是**流**，数据读走即消失、没有「当前位置」概念，所以 `f_pos` 为 `NULL`，`ksys_write` 也就不回写偏移（`if (ret >= 0 && ppos)` 里 `ppos` 为空）。这也是它们不支持 `lseek`（`ESPIPE`）的同一根源。

**Q6：`write(fd, buf, 0)` 返回 0，这是错误吗？**
A：不是。实测 `errno=0`（成功）。写入 0 个字节是一次合法的"空操作"。**但要小心**：这意味着 `while ((w = write(...)) > 0)` 这种循环写法在 `w == 0` 时会退出——如果你的 `count` 因为某种原因算成了 0，循环会静默结束且什么都没写。`writeall` 用的是 `total < n` 作条件，不会踩这个坑。

**Q7：为什么 `ksys_read` 要多一次 `pos` 的拷贝，而不让 `vfs_read` 直接改 `f_pos`？**
A：为了**失败时不留半个偏移**。看 `ksys_read`：`pos` 是局部变量，`vfs_read` 改的是 `&pos`；只有 `ret >= 0` 才写回 `f.file->f_pos = pos`。如果直接传 `&f->f_pos`，一次失败的部分读也可能把偏移推走，后续重试就对不上了。

</details>
