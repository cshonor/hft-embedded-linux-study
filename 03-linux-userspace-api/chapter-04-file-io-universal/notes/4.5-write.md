## 本节讲什么

`write()` 把字节写进 fd。本节回答三个问题：

1. `write()` 在内核里怎么校验、怎么落到页缓存？
2. 「部分写（partial write）」为什么是正常现象，怎么处理？
3. 为什么「`write` 成功 ≠ 数据已落盘」？`SIGPIPE` 又是什么？

---

## 1. 原型与内核链路

```c
#include <unistd.h>
ssize_t write(int fd, const void *buffer, size_t count);
/* >0 实际写入字节（可能 < count）；-1 = 出错 */
```

```
用户态 write(fd, buf, count)
      ▼
SYSCALL_DEFINE3(write)        fs/read_write.c:646
      ▼
ksys_write()                  fs/read_write.c:626
      ├─→ fdget_pos(fd)      ← 取 struct file（流式对象 f_pos 为 NULL）
      ├─→ vfs_write()        ← 通用校验 + 分派（见下）
      └─→ 成功回写 f_pos，fdput_pos(f)
```

`vfs_write()` 校验链与 `vfs_read` 完全对称（`fs/read_write.c:564-583`）：

```c
ssize_t vfs_write(struct file *file, const char __user *buf, size_t count, loff_t *pos)
{
	if (!(file->f_mode & FMODE_WRITE))       return -EBADF;
	if (!(file->f_mode & FMODE_CAN_WRITE))   return -EINVAL;
	if (unlikely(!access_ok(buf, count)))    return -EFAULT;
	ret = rw_verify_area(WRITE, file, pos, count);
	if (count > MAX_RW_COUNT) count = MAX_RW_COUNT;
	file_start_write(file);
	if (file->f_op->write)        ret = file->f_op->write(file, buf, count, pos);
	else if (file->f_op->write_iter) ret = new_sync_write(file, buf, count, pos);
	else                          ret = -EINVAL;
	...
	file_end_write(file);
	return ret;
}
```

## 2. 部分写（partial write）：必须循环

和 `read` 的短读一样，`write` **可以**只写一部分就返回：

| 部分写原因 | 场景 |
|-----------|------|
| 管道/FIFO 缓冲不足 | `PIPE_BUF` 限制，只写满缓冲区就返回 |
| 磁盘空间不足 | `ENOSPC`，只写入剩余空间能容纳的部分 |
| socket 发送缓冲部分满 | TCP 发送缓冲区只有这么多空闲 |
| 信号中断 | `EINTR`，部分数据已写出 |

标准封装 `writeall`：

```c
ssize_t writeall(int fd, const void *buf, size_t n) {
    size_t total = 0;
    while (total < n) {
        ssize_t w = write(fd, (char*)buf + total, n - total);
        if (w < 0 && errno == EINTR) continue;   /* 信号中断，重试 */
        if (w < 0) return -1;
        total += w;
    }
    return total;
}
```

## 3. 成功 ≠ 落盘：数据先入页缓存

`write` 返回成功，只表示数据**拷进了内核页缓存**（page cache），**尚未**写进物理磁盘：

```
write(fd, data, size)
   │  copy_from_user → 页缓存（脏页）
   │  返回成功！但数据还在内存里
   ▼
fsync(fd) / fdatasync(fd)   ← 强制把脏页刷到磁盘
```

断电、内核崩溃时，页缓存里尚未刷盘的脏页会**丢失**。要保证持久化必须显式 `fsync`/`fdatasync`（Ch13）。嵌入式/HFT 落盘场景尤其要分清「写进内核」和「写进磁盘」的边界。

## 4. SIGPIPE：写已关闭的管道会杀进程

向「读端已关闭」的管道/socket 写数据时，内核会向写进程发送 `SIGPIPE` 信号；该信号默认动作是**终止进程**：

```c
write(pipe_fd, buf, n);   /* 对端已 close → 进程被 SIGPIPE 杀死 */
signal(SIGPIPE, SIG_IGN); /* 忽略后，write 返回 -1，errno=EPIPE */
```

服务器写 socket 时对端可能随时断开，因此**必须先忽略 `SIGPIPE`**，否则一个断连就能让整个服务崩溃。忽略后 `write` 返回 `-1` + `EPIPE`，程序自己处理。

## 5. HFT / 嵌入式关联

| 现象 | 本节机制的兑现 |
|------|----------------|
| 行情日志落盘 | `write` 成功不代表安全，崩溃可能丢最近几秒日志；关键数据要 `fdatasync`，但 `fdatasync` 会阻塞，需权衡 |
| 多进程追加 | `O_APPEND` 让每次 `write` 原子地追加到末尾，避免部分写交错（Ch5） |
| 服务器防崩 | 写 socket 前忽略 `SIGPIPE`，否则对端断连直接杀进程 |
| 少 syscall | 批量 `write`（大缓冲）比多次小 `write` 省 syscall，但大缓冲也意味着延迟数据攒满才写 |

## 6. 代码示例

```c
#include <stdio.h>
#include <fcntl.h>
#include <unistd.h>
#include <string.h>

/* write(): 可能部分写入, 需循环保证写完 */
int main(void) {
    int fd = open("/tmp/ch4_write.txt", O_WRONLY|O_CREAT|O_TRUNC, 0644);
    if (fd < 0) { perror("open"); return 1; }
    const char *msg = "hello write\n";
    size_t total = strlen(msg), written = 0;
    while (written < total) {
        ssize_t n = write(fd, msg + written, total - written);
        if (n < 0) { perror("write"); break; }
        written += n;
    }
    printf("wrote %zu bytes\n", written);
    close(fd);
    return 0;
}
```

<details>
<summary>代码自测（Q&A）</summary>

**Q1：`write()` 返回值小于请求字节数时该怎么办？**
A：这是「部分写」，正常现象，不能当错误。应循环写剩余部分直到全部写完（见 `writeall`）。不处理会导致数据静默丢失——尤其管道、socket、磁盘快满时。

**Q2：`write` 成功返回后，数据一定在磁盘上了吗？**
A：不一定。`write` 成功只表示数据进了**内核页缓存**（脏页），断电/崩溃会丢。要保证持久化必须 `fsync`（连元数据一起刷）或 `fdatasync`（只刷数据）。这正是「成功 ≠ 落盘」的含义。

**Q3：向对端已关闭的管道写数据，进程为什么可能「莫名退出」？**
A：内核会向写进程发 `SIGPIPE`，默认动作是终止进程。服务器写 socket 时对端随时可能断开，所以要先 `signal(SIGPIPE, SIG_IGN)` 忽略它，这样 `write` 会返回 `-1` + `EPIPE`，由程序自己处理断连。

**Q4：`write` 的 `-EBADF` 和 `-EFAULT` 分别查什么？**
A：`EBADF` 查 **fd**——无效或没以写方式打开（`vfs_write` 里 `!(f_mode & FMODE_WRITE)`）。`EFAULT` 查 **buf**——用户态缓冲区地址非法（`access_ok` 失败），`buf` 可能是野指针或 `count` 越界。

**Q5：流式对象（socket/pipe）为什么没有「文件偏移」？**
A：看 `file_ppos()`（`fs/read_write.c:597`）：`file->f_mode & FMODE_STREAM ? NULL : &file->f_pos`。socket/pipe 是**流**，数据读走即消失、没有「当前位置」概念，所以 `f_pos` 为 `NULL`，`ksys_write` 也就不回写偏移。这也是它们不支持 `lseek`（`ESPIPE`）的同一根源。

</details>
