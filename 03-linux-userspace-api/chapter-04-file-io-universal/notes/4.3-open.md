## 本节讲什么

`open()` 把「路径名」变成「fd」，是万能 I/O 模型的第一步。本节回答三个问题：

1. `open()` 在内核里走的是怎样一条链路（从路径字符串到 fd 槽位）？
2. `flags` 和 `mode` 两个参数各自控制什么？`umask` 怎么参与？
3. `open()`（系统调用）和 `fopen()`（C 库函数）差在哪？

本节把「权限是算出来的」和「fd 标志 vs 文件状态标志分属两层」这两件事**跑到屏幕上**——尤其是第二件，它直接决定 Ch5 讲 `dup` 时哪些东西会被共享。

---

## 1. 原型与内核链路

```c
#include <fcntl.h>
int open(const char *pathname, int flags, /* mode_t mode */);
/* 成功返回 fd；失败返回 -1 并设 errno */
```

`open` 是**变参**函数——只有 `flags` 含 `O_CREAT`（或 `O_TMPFILE`）时才需要第三个参数 `mode`。内核侧完整链路（v6.6）：

```
用户态 open(path, flags, mode)
      │
      ▼
SYSCALL_DEFINE3(open)                    fs/open.c:1441
      │  if (force_o_largefile()) flags |= O_LARGEFILE;   ← fs/open.c:1443-1444
      ▼
do_sys_open(AT_FDCWD, ...)               fs/open.c:1434
      ▼
do_sys_openat2()                         fs/open.c:1406
      ├─→ build_open_flags()  解析 flags/mode 成 struct open_flags
      ├─→ getname()           从用户态拷贝路径字符串（copy_from_user）
      ├─→ get_unused_fd_flags()  ← 分配「最小可用」fd
      ├─→ do_filp_open()      真正打开：路径解析 + 调用 f_op->open
      │                        （这里才做权限检查、创建文件、挂 inode）
      └─→ fd_install(fd, f)   把 struct file 装进 fd 表的 fd 槽位
```

> 关键：fd 的分配（`get_unused_fd_flags`）发生在**真正打开之前**——先占坑，`do_filp_open` 失败再 `put_unused_fd` 还回去。`open` 默认相对 `AT_FDCWD`（当前工作目录）；`openat`/`openat2` 可指定 `dfd` 做相对路径（用于防 TOCTOU，见 Ch18）。
>
> `fs/open.c:1443-1444` 那两行是**实测发现的**：`F_GETFL` 返回的 flags 比你传进去的多一位 `O_LARGEFILE`（见第 4 节）。

## 2. flags：位掩码，访问模式三选一

| 标志 | 含义 |
|------|------|
| `O_RDONLY` / `O_WRONLY` / `O_RDWR` | 只读 / 只写 / 读写（**三者必选其一**，占 `O_ACCMODE` 掩码 `0x3`） |
| `O_CREAT` | 不存在则创建；此时**必须给 mode** |
| `O_EXCL` | 与 `O_CREAT` 配合：文件已存在则失败（原子「排他创建」） |
| `O_TRUNC` | 存在则截断为 0（需写权限） |
| `O_APPEND` | 每次写前原子地把偏移设到末尾（详 Ch5） |
| `O_NONBLOCK` | 非阻塞打开（对管道/FIFO/设备有意义） |
| `O_CLOEXEC` | `exec` 时自动关闭，防 fd 泄漏给子程序 |
| `O_NOFOLLOW` | 不跟随符号链接 |
| `O_SYNC` / `O_DSYNC` | 写以同步方式完成（每次 write 落盘，Ch13） |

## 3. mode 与 umask

`mode` 只在新文件被 `O_CREAT` 创建时生效，指定的是**请求的权限**；最终权限还要被进程的 `umask` 屏蔽：

```
最终权限 = mode & ~umask
例如 mode=0666, umask=022 → 0644 (rw-r--r--)
     mode=0666, umask=002 → 0664 (rw-rw-r--)
```

`umask` 是进程级属性（`umask()` 系统调用可改），默认 `022`。它只**屏蔽**（清除）权限位，不能「新增」`mode` 里没有的位。

## 4. 代码：四组实测验证 flags 与 mode

完整源码 [`code/c4_3_open.c`](../code/c4_3_open.c)：

```c
/* c4_3_open.c — open() 的 flags 与 mode：权限到底怎么算出来的
 *
 * 演示四件事：
 *   1) 最终权限 = mode & ~umask，用三组 umask 实测
 *   2) O_EXCL + O_CREAT = 原子排他创建（第二次必失败 EEXIST）
 *   3) O_TRUNC 清空 / O_APPEND 追加，同一个文件两种命运
 *   4) O_CLOEXEC 落在「fd 标志位」里，不在文件状态标志里
 *
 * 编译: gcc -O0 -Wall -o c4_3_open c4_3_open.c
 */
#include <fcntl.h>
#include <stdio.h>
#include <string.h>
#include <unistd.h>
#include <errno.h>
#include <sys/stat.h>

static void show(const char *tag, const char *path)
{
    struct stat st;
    if (stat(path, &st) < 0) { printf("  %s: stat 失败\n", tag); return; }
    printf("  %-28s 权限 = %04o (%s%s%s%s%s%s%s%s%s)  大小 = %lld\n",
           tag, st.st_mode & 07777,
           (st.st_mode & S_IRUSR) ? "r" : "-", (st.st_mode & S_IWUSR) ? "w" : "-",
           (st.st_mode & S_IXUSR) ? "x" : "-", (st.st_mode & S_IRGRP) ? "r" : "-",
           (st.st_mode & S_IWGRP) ? "w" : "-", (st.st_mode & S_IXGRP) ? "x" : "-",
           (st.st_mode & S_IROTH) ? "r" : "-", (st.st_mode & S_IWOTH) ? "w" : "-",
           (st.st_mode & S_IXOTH) ? "x" : "-",
           (long long) st.st_size);
}

int main(void)
{
    const mode_t MODE = 0666;               /* 请求的权限：rw-rw-rw- */
    const char *path = "/tmp/c4_open.txt";

    printf("== 1. 最终权限 = mode & ~umask  （本节核心）==\n");
    printf("  请求 mode = %04o (rw-rw-rw-)\n\n", MODE);

    mode_t masks[] = { 0000, 0022, 0077, 0027 };
    for (unsigned i = 0; i < sizeof masks / sizeof masks[0]; i++) {
        unlink(path);                        /* 先删掉，确保每次都是新建 */
        mode_t old = umask(masks[i]);
        int fd = open(path, O_WRONLY | O_CREAT, MODE);
        umask(old);                          /* 恢复，别影响后面 */
        close(fd);
        printf("  umask = %04o  ->  mode & ~umask = %04o & %04o = %04o\n",
               masks[i], (unsigned) MODE, (unsigned) (~masks[i] & 07777),
               (unsigned) (MODE & ~masks[i]));
        show("          实测", path);
    }
    printf("\n  结论：umask 只能「减」不能「加」。mode 里没有的位，umask 造不出来。\n");

    printf("\n== 2. O_EXCL + O_CREAT：原子的「不存在才创建」==\n");
    unlink(path);
    int fd = open(path, O_WRONLY | O_CREAT | O_EXCL, 0644);
    printf("  第一次 open(O_CREAT|O_EXCL) -> %d  （成功）\n", fd);
    close(fd);

    errno = 0;
    int fd2 = open(path, O_WRONLY | O_CREAT | O_EXCL, 0644);
    printf("  第二次 open(O_CREAT|O_EXCL) -> %d  errno=%d (%s)\n",
           fd2, errno, strerror(errno));
    printf("  → 两次 open 之间没有「先 stat 再 create」的窗口，这就是它防 TOCTOU 的意义。\n");

    printf("\n== 3. O_TRUNC 清空 vs O_APPEND 追加 ==\n");
    unlink(path);
    fd = open(path, O_WRONLY | O_CREAT, 0644);
    write(fd, "AAAA", 4);
    close(fd);
    show("写入 AAAA 后", path);

    fd = open(path, O_WRONLY | O_TRUNC);     /* 打开就截断成 0 */
    close(fd);
    show("O_TRUNC 打开一次后", path);

    fd = open(path, O_WRONLY | O_APPEND);
    write(fd, "BBBB", 4);
    close(fd);
    fd = open(path, O_WRONLY | O_APPEND);
    write(fd, "CCCC", 4);
    close(fd);
    show("O_APPEND 两次写 BBBB+CCCC", path);
    printf("  → O_TRUNC 只要「打开」就把数据清零，连 write 都不需要。\n");

    printf("\n== 4. O_CLOEXEC 存在哪：fd 标志 vs 文件状态标志 ==\n");
    int e1 = open("/dev/null", O_RDONLY | O_CLOEXEC);
    int e2 = open("/dev/null", O_RDONLY);
    int f1 = fcntl(e1, F_GETFD);             /* fd 标志：FD_CLOEXEC 在这 */
    int f2 = fcntl(e1, F_GETFL);             /* 文件状态标志：O_* 在这 */
    printf("  O_CLOEXEC 打开后  F_GETFD = 0x%x  (FD_CLOEXEC=0x%x → %s)\n",
           f1, FD_CLOEXEC, (f1 & FD_CLOEXEC) ? "已设" : "未设");
    printf("                    F_GETFL = 0x%x\n", f2);
    printf("      O_ACCMODE(0x%x) 取出的访问模式 = %d → %s\n",
           O_ACCMODE, f2 & O_ACCMODE,
           (f2 & O_ACCMODE) == O_RDONLY ? "只读" :
           (f2 & O_ACCMODE) == O_WRONLY ? "只写" : "读写");
    printf("      O_CLOEXEC 这一位在 F_GETFL 里吗？0x%x & 0x%x = 0x%x → %s\n",
           f2, O_CLOEXEC, f2 & O_CLOEXEC,
           (f2 & O_CLOEXEC) ? "在" : "不在（它属于 F_GETFD）");
    printf("      F_GETFL 里多出来的 0x8000：内核在 open 时会按平台附加 O_LARGEFILE\n");
    printf("        （fs/open.c:1443-1444: if (force_o_largefile()) flags |= O_LARGEFILE;）。\n");
    printf("        它不是你传的 —— 所以「F_GETFL 的返回值 ≠ 你传给 open 的 flags」。\n");
    printf("  没加的对照组       F_GETFD = 0x%x\n", fcntl(e2, F_GETFD));
    printf("  → FD_CLOEXEC 是「这个 fd 的」，dup 不会带走；O_* 状态标志是「打开描述」的。\n");
    close(e1);
    close(e2);
    unlink(path);
    return 0;
}
```

编译运行：

```bash
gcc -O0 -Wall -Wextra -o c4_3_open c4_3_open.c && ./c4_3_open
```

CE（gcc 13.3.0 / x86-64 / Ubuntu 24.04）实测：

```text
== 1. 最终权限 = mode & ~umask  （本节核心）==
  请求 mode = 0666 (rw-rw-rw-)

  umask = 0000  ->  mode & ~umask = 0666 & 7777 = 0666
            实测             权限 = 0666 (rw-rw-rw-)  大小 = 0
  umask = 0022  ->  mode & ~umask = 0666 & 7755 = 0644
            实测             权限 = 0644 (rw-r--r--)  大小 = 0
  umask = 0077  ->  mode & ~umask = 0666 & 7700 = 0600
            实测             权限 = 0600 (rw-------)  大小 = 0
  umask = 0027  ->  mode & ~umask = 0666 & 7750 = 0640
            实测             权限 = 0640 (rw-r-----)  大小 = 0

  结论：umask 只能「减」不能「加」。mode 里没有的位，umask 造不出来。

== 2. O_EXCL + O_CREAT：原子的「不存在才创建」==
  第一次 open(O_CREAT|O_EXCL) -> 3  （成功）
  第二次 open(O_CREAT|O_EXCL) -> -1  errno=17 (File exists)
  → 两次 open 之间没有「先 stat 再 create」的窗口，这就是它防 TOCTOU 的意义。

== 3. O_TRUNC 清空 vs O_APPEND 追加 ==
  写入 AAAA 后              权限 = 0644 (rw-r--r--)  大小 = 4
  O_TRUNC 打开一次后      权限 = 0644 (rw-r--r--)  大小 = 0
  O_APPEND 两次写 BBBB+CCCC 权限 = 0644 (rw-r--r--)  大小 = 8
  → O_TRUNC 只要「打开」就把数据清零，连 write 都不需要。

== 4. O_CLOEXEC 存在哪：fd 标志 vs 文件状态标志 ==
  O_CLOEXEC 打开后  F_GETFD = 0x1  (FD_CLOEXEC=0x1 → 已设)
                    F_GETFL = 0x8000
      O_ACCMODE(0x3) 取出的访问模式 = 0 → 只读
      O_CLOEXEC 这一位在 F_GETFL 里吗？0x8000 & 0x80000 = 0x0 → 不在（它属于 F_GETFD）
      F_GETFL 里多出来的 0x8000：内核在 open 时会按平台附加 O_LARGEFILE
        （fs/open.c:1443-1444: if (force_o_largefile()) flags |= O_LARGEFILE;）。
        它不是你传的 —— 所以「F_GETFL 的返回值 ≠ 你传给 open 的 flags」。
  没加的对照组       F_GETFD = 0x0
  → FD_CLOEXEC 是「这个 fd 的」，dup 不会带走；O_* 状态标志是「打开描述」的。
```

逐条看：

| 观察 | 说明 |
|------|------|
| 四组 `umask` 的实测权限与手算**完全一致** | `0000→0666`（`~0` 的 4 位八进制是 `7777`）、`0022→0644`、`0077→0600`、`0027→0640`。这说明 `mode & ~umask` 不是比喻，就是内核那行代码 |
| `O_EXCL` 第二次返回 `-1 errno=17` | `EEXIST`。**注意它是「原子失败」**：如果先 `stat` 再 `open`，两个进程会同时通过 `stat` 检查，然后都去创建——中间那个窗口就是 TOCTOU |
| `O_TRUNC` 只「打开」就把 4 字节变 0 | 一行 `open(path, O_WRONLY|O_TRUNC)` 后面**连 `write` 都没有**，文件就空了。这是「误加 `O_TRUNC` 导致日志清空」事故的机制 |
| `O_APPEND` 两次写累计到 8 字节 | `O_APPEND` 的语义是「每次 `write` 前原子定位到末尾」，所以两次独立的 `open`+`write` 也能正确接续 |
| `O_CLOEXEC` 只出现在 `F_GETFD = 0x1` | **本节最重要的一条**：`FD_CLOEXEC` 是**进程 fd 表项**上的标志位，用 `fcntl(fd, F_GETFD)` 读；它**不在** `F_GETFL` 里 |
| `F_GETFL = 0x8000` 而我只传了 `O_RDONLY`（=0） | `0x8000` 是内核在 `open` 系统调用入口按平台条件补的 `O_LARGEFILE`（`fs/open.c:1443-1444`）。所以**`F_GETFL` 的返回值 ≠ 你的入参**——想判断访问模式要用 `O_ACCMODE` 掩码去取，别直接比整数 |

> 为什么这条要专门强调？因为 Ch5 讲 `dup` 时会问「哪些东西被共享」。答案是：**打开描述上的东西（`f_flags` 里的 `O_APPEND`/`O_NONBLOCK`）被共享，fd 表项上的东西（`FD_CLOEXEC`）不被共享**。这一节先把「两组标志分属两层」这件事用实测钉死。

## 5. `open()` vs `fopen()`：系统调用 vs C 库

```c
int   open(const char *pathname, int flags, mode_t mode);  // POSIX 系统调用
FILE *fopen(const char *path, const char *mode);           // C 标准库封装
```

| | `open` / `read` / `write` | `fopen` / `fread` / `fwrite` |
|---|---|---|
| 返回值 | `int fd`（内核整数句柄） | `FILE *` 指针 |
| 层级 | POSIX 系统调用（直接进内核） | C 标准库（libc，内部调 `open`） |
| 缓冲 | **无**用户态缓冲 | **有**用户态缓冲（`FILE` 内部 buffer） |
| 关闭 | `close(fd)` | `fclose()` → 内部 `close()` |
| 可移植 | Unix/Linux 限定 | C 标准，跨平台 |

`fopen` 的「r/w/a」模式到 `open` flags 的映射：

| fopen 模式 | open 对应 flags |
|---|---|
| `"r"` | `O_RDONLY` |
| `"w"` | `O_WRONLY \| O_CREAT \| O_TRUNC` |
| `"a"` | `O_WRONLY \| O_CREAT \| O_APPEND` |

## 6. HFT / 嵌入式关联

| 路线 | 要点 |
|------|------|
| **嵌入式 Linux** | 资源受限场景可直接 `open` 裸文件操作（免 libc 缓冲层）；`/dev` 设备走同一套 `open`；专属控制靠 `ioctl` |
| **HFT 低延迟** | `fopen` 多一层用户态拷贝；直接 `open/write` 少一层但每次 syscall 都陷内核。热路径常权衡：批量写 or `mmap` or `io_uring` |
| **多进程日志** | `O_APPEND` 保证多进程追加不交错（原子设偏移+写）；`O_CLOEXEC` 防 `exec` 后 fd 泄漏 |
| **权限要显式给足** | 服务创建数据文件要小心：`mode` 给 `0640` + `umask 027` 是常见的「组内可读、外人不可见」组合（实测 `0027 → 0640`） |

<summary>代码自测（Q&A）</summary>

**Q1：`open("f.txt", O_CREAT)` 少了什么参数？为什么危险？**
A：少了 `mode`。`open` 是变参函数，只有 `flags` 含 `O_CREAT` 时才读第三个参数；漏传时内核会读栈上的残留值当 `mode`，导致新文件权限随机。正确写法 `open("f.txt", O_CREAT, 0644)`（再受 `umask` 屏蔽）。

**Q2：`open` 失败时返回 0 吗？**
A：不。失败返回 `-1` 并设 `errno`。`0` 是合法 fd（stdin），只有 `0` 号槽位空闲时才可能返回 0——这本身不是错误。判断成功与否只能用 `fd == -1`。实测里 `close(0)` 之后 `open` 就拿到了 0（见 4.1）。

**Q3：`O_EXCL | O_CREAT` 组合有什么用途？**
A：原子地「仅当文件不存在时创建」。两个进程同时用这个组合创建同名文件，内核保证只有一个成功、另一个得到 `-EEXIST`（实测 `errno=17`）——这是「用文件当锁」或「原子生成临时文件」的经典手段，避免 `open` 后再 `stat` 的 TOCTOU 竞争窗口。

**Q4：为什么 `umask` 只能「屏蔽」权限，不能「添加」权限？**
A：内核里的计算是 `mode & ~umask`——`umask` 只把某些位清零。`mode` 里本就没有的位，`umask` 造不出来。实测四组对照（`0000/0022/0077/0027`）都严格符合这个式子。

**Q5：`fopen("a")` 和 `open(..., O_APPEND)` 在「追加」语义上等价吗？**
A：等价，且底层是同一个机制。`fopen("a")` 内部就是 `open(path, O_WRONLY|O_CREAT|O_APPEND, ...)`，`O_APPEND` 让内核在每次 `write` 前原子地把偏移设到文件末尾，多进程追加不会交错。区别只在 `fopen` 多了用户态缓冲，`fclose` 时才真正 flush + `close`。

**Q6：`FD_CLOEXEC` 和 `O_CLOEXEC` 有什么区别？**
A：`O_CLOEXEC` 是**传给 `open` 的入参**，`FD_CLOEXEC` 是**读出来的 fd 标志位**（`fcntl(fd, F_GETFD)`）。实测：`open(path, O_RDONLY|O_CLOEXEC)` 之后 `F_GETFD = 0x1`，即 `FD_CLOEXEC` 已设。已打开的 fd 也可以用 `fcntl(fd, F_SETFD, FD_CLOEXEC)` 补设——这正是 `O_CLOEXEC` 出现之前的老做法。

**Q7：为什么说「`F_GETFL` 的返回值不等于你传的 flags」？**
A：实测 `open("/dev/null", O_RDONLY|O_CLOEXEC)` 之后 `F_GETFL = 0x8000`，而 `O_RDONLY` 是 0——多出来的 `0x8000` 是内核在 `open` 入口按平台条件补的 `O_LARGEFILE`（`fs/open.c:1443-1444`）。所以判断访问模式必须用 `O_ACCMODE` 掩码取低 2 位，不能拿整数直接比。
