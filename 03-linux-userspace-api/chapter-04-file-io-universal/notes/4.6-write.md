## 要点

```c
ssize_t write(int fd, const void *buffer, size_t count);
```

| 点 | |
|----|--|
| 返回 | 实际写入字节；允许 **部分写 partial write** |
| 落盘 | **成功 ≠ 已持久化**；常先入页缓存（缓冲详后续章）；强制刷盘用 `fsync`/`fdatasync` |

---

## 与 C 语言学习的关系

文件 I/O 是 C 语言系统编程的基础。K&R 第 8 章（8.1-8.4）讲解了低级 I/O（open/read/write/close/lseek），与本模块的 POSIX 接口直接对应。注意 C 标准库的 `fopen/fread/fwrite`（带缓冲）与系统调用的 `open/read/write`（无用户态缓冲）的区别——理解缓冲层次是 HFT 低延迟编程的关键。

| 路线 | 带走 |
|------|------|
| 嵌入式 | `/dev` 设备也走同一套 open/read/write；专属控制靠 ioctl |
| HFT | 短读/部分写；热路径少 syscall；落盘语义与缓冲要清楚 |

## 常见陷阱

1. **部分写未处理**

```c
/* 假设一次写完 */
write(fd, buf, 1024);
/* 可能只写了 512 */
```

write 返回值可能小于请求字节数（partial write）。必须循环写直到全部写出。

2. **write 成功 ≠ 落盘**

```c
write(fd, data, size);  /* 数据在页缓存 */
fsync(fd);  /* 强制落盘 */
```

write 成功只表示数据到了内核页缓存。需要 fsync/fdatasync 确保持久化。

3. **SIGPIPE 导致进程退出**

```c
write(pipe_fd, buf, n);  /* 对端关闭 → SIGPIPE */
signal(SIGPIPE, SIG_IGN);  /* 忽略 */
```

向已关闭的管道/socket 写数据触发 SIGPIPE，默认终止进程。应忽略 SIGPIPE。

## 自测题

**题目 1（选择）：** `write()` 返回值小于请求字节数时应该？
A. 报错退出
B. 重试写剩余部分
C. 忽略
D. 关闭文件

<details>
<summary>参考答案</summary>

B。这是部分写（partial write），是正常现象。应该循环写剩余部分直到全部写出。

</details>

**题目 2（判断）：** `write` 成功返回后数据已经写入磁盘。

<details>
<summary>参考答案</summary>

错误。write 成功只表示数据到了内核页缓存。断电仍会丢失。需要 fsync 确保落盘。

</details>

**题目 3（踩坑）：** 以下代码有什么问题？
```c
int fd = open("log.txt", O_WRONLY);
write(fd, "hello", 5);
close(fd);
```

<details>
<summary>参考答案</summary>

1) 没检查 open 返回值；2) 没检查 write 返回值（可能部分写）；3) 没检查 close 返回值（NFS 上 close 可能报延迟错误）。

</details>

**题目 4（应用）：** 写一个安全的 writeall 函数。

<details>
<summary>参考答案</summary>

```c
ssize_t writeall(int fd, const void *buf, size_t n) {
    size_t total = 0;
    while (total < n) {
        ssize_t w = write(fd, (char*)buf+total, n-total);
        if (w < 0 && errno == EINTR) continue;
        if (w < 0) return -1;
        total += w;
    }
    return total;
}
```

</details>
