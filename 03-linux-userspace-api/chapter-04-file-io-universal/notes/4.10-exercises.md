## 练习题

### 练习 1：实现简化版 `cp` 命令

使用 `open`/`read`/`write`/`close` 实现文件拷贝。

**要求**：
- 源文件用 `O_RDONLY` 打开
- 目标文件用 `O_WRONLY | O_CREAT | O_TRUNC`，权限 0644
- 循环 read 直到 EOF
- 处理 short write（write 返回值 < 请求值）
- 错误处理：检查所有系统调用的返回值

### 练习 2：文件内容倒序输出

使用 `lseek` 从文件末尾向前逐字节读取，倒序输出到 stdout。

**提示**：
- 先 `lseek(fd, 0, SEEK_END)` 获取文件大小
- 从末尾开始 `lseek(fd, -1, SEEK_END)` 然后 `lseek(fd, -2, SEEK_CUR)` 逐字节

### 练习 3：解释 short write

为什么 `write()` 的返回值可能小于请求的字节数？列举至少 3 种场景。

### 练习 4：O_APPEND 的原子性

使用 `O_APPEND` 模式，多进程同时写同一文件，数据会交错吗？为什么？如果不使用 `O_APPEND` 呢？

## 参考答案

### 练习 1 参考代码

```c
#include "tlpi_hdr.h"
#include <fcntl.h>

int main(int argc, char *argv[]) {
    if (argc != 3)
        usageErr("usage: %s src dst\n", argv[0]);

    int srcfd = open(argv[1], O_RDONLY);
    if (srcfd == -1) errExit("open src");

    int dstfd = open(argv[2], O_WRONLY | O_CREAT | O_TRUNC, 0644);
    if (dstfd == -1) errExit("open dst");

    char buf[8192];
    ssize_t n;
    while ((n = read(srcfd, buf, sizeof(buf))) > 0) {
        ssize_t written = 0;
        while (written < n) {           /* 处理 short write */
            ssize_t w = write(dstfd, buf + written, n - written);
            if (w == -1) errExit("write");
            written += w;
        }
    }
    if (n == -1) errExit("read");

    if (close(srcfd) == -1) errExit("close src");
    if (close(dstfd) == -1) errExit("close dst");
    return 0;
}
```

### 练习 2 参考代码

```c
#include "tlpi_hdr.h"
#include <fcntl.h>

int main(int argc, char *argv[]) {
    int fd = open(argv[1], O_RDONLY);
    if (fd == -1) errExit("open");

    off_t size = lseek(fd, 0, SEEK_END);
    if (size == -1) errExit("lseek SEEK_END");

    for (off_t pos = size - 1; pos >= 0; pos--) {
        lseek(fd, pos, SEEK_SET);
        char c;
        if (read(fd, &c, 1) == 1)
            write(STDOUT_FILENO, &c, 1);
    }
    close(fd);
    return 0;
}
```

### 练习 3 答案

1. **管道/FIFO 缓冲区不足**：`PIPE_BUF` 大小限制，write 写入部分数据后返回
2. **信号中断**：`EINTR`，部分数据已写入
3. **磁盘空间不足**：`ENOSPC`，仅写入剩余空间对应的数据
4. **网络套接字**：TCP 发送缓冲区部分填满

### 练习 4 答案

- **有 O_APPEND**：不会交错。内核在每次 write 前原子地将偏移量设为文件末尾，整个"设偏移量+写"是不可分割的。
- **无 O_APPEND**：会交错。`lseek(SEEK_END)` + `write()` 是两步操作，进程 A 的 lseek 和 write 之间可能被进程 B 的 lseek+write 插入，导致覆盖或交错。

## HFT / 嵌入式关联

- **可靠文件拷贝**：HFT 日志归档场景下需要处理 short write
- **嵌入式 OTA**：固件烧写场景下确保完整写入
- **原子追加**：多进程行情日志统一用 `O_APPEND`
