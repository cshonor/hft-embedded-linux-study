## 练习 4-1：用 I/O 系统调用实现 `tee`

### 题干（原书 Exercise 4-1，逐字）

> The `tee` command reads its standard input until end-of-file, writing a copy of the input to standard output and to the file named in its command-line argument. Implement `tee` using I/O system calls. By default, `tee` overwrites any existing file with the given name. Implement the `-a` command-line option (`tee -a file`), which causes `tee` to append text to the end of a file if it already exists.

**要点拆解**：

| 要求 | 实现手段 |
|------|---------|
| 读 stdin 直到 EOF | `while ((n = read(STDIN_FILENO, buf, sizeof buf)) > 0)`，`n == 0` 就是 EOF |
| 同时写两处 | 每轮把同一份 `buf` 写 `fd`（文件）和 `STDOUT_FILENO`（屏幕） |
| 默认覆盖 | `O_WRONLY \| O_CREAT \| O_TRUNC` |
| `-a` 追加 | 把 `O_TRUNC` 换成 `O_APPEND` |

### 实现

完整源码 [`code/ex4_1_tee.c`](../code/ex4_1_tee.c)：

```c
/* ex4_1_tee.c — TLPI 练习 4-1：用 I/O 系统调用实现 tee
 *
 * 【题干（原书 Exercise 4-1，逐字）】
 *   The tee command reads its standard input until end-of-file, writing a
 *   copy of the input to standard output and to the file named in its
 *   command-line argument.  Implement tee using I/O system calls.  By
 *   default, tee overwites any existing file with the given name.
 *   Implement the -a command-line option (tee -a file), which casuses tee
 *   to append text to the end of a file if it already exists.
 *
 * 【实现要点】
 *   - 一份输入，两处输出：stdout 一份、文件一份
 *   - 循环 read 到 0（EOF）；每轮把读到的 n 字节写两处
 *   - -a：打开文件时加 O_APPEND（而不是 O_TRUNC）
 *   - getopt(3) 解析选项；用完记得检查 optind == argc - 1（恰好一个文件参数）
 *
 * 【踩坑提示】写 stdout 也可能发生部分写（stdout 可能是管道且缓冲区满），
 *   所以两处都要用 writeAll 循环，不能只 `write(...)` 一下就走。
 *
 * 编译: gcc -O0 -Wall -o ex4_1_tee ex4_1_tee.c
 * 用法: echo hello | ./ex4_1_tee out.txt
 *       echo world | ./ex4_1_tee -a out.txt
 */
#include <fcntl.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <unistd.h>
#include <errno.h>

#define BUF_SIZE 1024

/* 把 buf 里 len 字节完整写到 fd：处理部分写和 EINTR */
static ssize_t writeAll(int fd, const char *buf, size_t len)
{
    size_t written = 0;

    while (written < len) {
        ssize_t n = write(fd, buf + written, len - written);
        if (n < 0) {
            if (errno == EINTR)
                continue;               /* 被信号打断：数据没写、不是错误，重试 */
            return -1;                  /* 真错误 */
        }
        written += (size_t) n;
    }
    return (ssize_t) written;
}

int main(int argc, char *argv[])
{
    int append = 0;
    int opt;

    while ((opt = getopt(argc, argv, "a")) != -1) {
        switch (opt) {
        case 'a': append = 1;  break;
        default:
            fprintf(stderr, "Usage: %s [-a] file\n", argv[0]);
            return 1;
        }
    }

    if (optind != argc - 1) {
        fprintf(stderr, "Usage: %s [-a] file\n", argv[0]);
        return 1;
    }
    const char *path = argv[optind];

    int flags = O_WRONLY | O_CREAT | (append ? O_APPEND : O_TRUNC);
    int fd = open(path, flags, 0644);
    if (fd < 0) {
        fprintf(stderr, "open %s: %s\n", path, strerror(errno));
        return 1;
    }

    char buf[BUF_SIZE];
    ssize_t n;
    int rounds = 0;

    while ((n = read(STDIN_FILENO, buf, sizeof buf)) > 0) {
        rounds++;
        if (writeAll(fd, buf, (size_t) n) < 0) {   /* 去处一：文件 */
            fprintf(stderr, "write %s: %s\n", path, strerror(errno));
            return 1;
        }
        if (writeAll(STDOUT_FILENO, buf, (size_t) n) < 0) {  /* 去处二：屏幕 */
            fprintf(stderr, "write stdout: %s\n", strerror(errno));
            return 1;
        }
    }
    if (n < 0) {
        fprintf(stderr, "read: %s\n", strerror(errno));
        return 1;
    }

    fprintf(stderr, "[ex4_1_tee] 读了 %d 轮，模式 = %s\n",
            rounds, append ? "append (-a)" : "overwrite (默认 O_TRUNC)");
    close(fd);
    return 0;
}
```

两处细节值得单独点出来：

1. **写 stdout 也必须循环**。stdout 被重定向到管道时，缓冲区满会部分写——和写文件一样要用 `writeAll`。只对文件循环、对 stdout 直接 `write()` 一下，是这道题最常见的半对答案。
2. **`getopt` 之后要检查 `optind == argc - 1`**。否则 `./tee a b`（两个文件参数）会被当成合法输入，静默忽略 `b`。`optind` 是「第一个非选项参数的下标」。

### 实测（CE）

```bash
gcc -O0 -Wall -Wextra -o ex4_1_tee ex4_1_tee.c
printf 'hello tee\nsecond line\n' | ./ex4_1_tee /tmp/tee_out.txt
```

```text
hello tee
second line
```

stderr 侧：

```text
  [ex4_1_tee] 读了 1 轮，模式 = overwrite (默认 O_TRUNC)
```

**解读**：

| 观察 | 说明 |
|------|------|
| stdout 打出两行 | 一份去了屏幕 |
| `/tmp/tee_out.txt` 内容相同 | 另一份去了文件（demo 里用 `writeAll` 写文件侧） |
| 「读了 1 轮」 | 24 字节一次性读完——`read` 一次就能拿完，说明**短读不是必现的**，但必须能处理 |
| 模式 = `overwrite` | 没传 `-a`，走 `O_TRUNC`。传 `-a` 则这次输出应变成 `append (-a)`，且**旧内容保留** |

> 想亲眼验证 `-a`：先 `printf 'first\n' > f`，再 `printf 'second\n' | ./ex4_1_tee f`（内容变成只有 `second`），对比 `printf 'second\n' | ./ex4_1_tee -a f`（`first` 还在）。差别就是 `O_TRUNC` 与 `O_APPEND` 一个标志位。

### 与「标准 tee」的差距

| 项 | 本题实现 | GNU `tee` |
|----|---------|-----------|
| `-a` | ✓ | ✓ |
| 写多个文件 | ✗（只支持一个） | ✓ `tee f1 f2 f3` |
| `SIGINT`/`SIGPIPE` 处理 | ✗ | ✓（收到 `SIGINT` 先 flush） |
| 写 stdout 失败后继续写文件 | ✗（直接返回 1） | ✓（`-p` 选项） |

原书只要求最基本的形态，上面这张表是「如果你想把它做成能用的命令，还差什么」。

## 练习 4-2：写一个保留空洞的 `cp`

### 题干（原书 Exercise 4-2，逐字）

> Write a program like `cp` that, when used to copy a regular file that contains holes (sequences of null bytes), also creates corresponding holes in the target file.

### 朴素做法错在哪

教科书式的拷贝循环：

```c
while ((n = read(in, buf, sizeof buf)) > 0)
    write(out, buf, n);
```

读空洞区时，**内核交给你的是真实的 0 字节**（[4.7](4.7-lseek.md) 实测：空洞读出来全是 0）。这些 0 被老老实实写进目标文件，目标文件就**真的分配了磁盘块**——空洞被「灌实」了。

一个 1 MB 逻辑大小、实际只占 12 KB 的稀疏文件，拷完变成实打实 1 MB。**逻辑内容一样，物理占用暴涨 80 倍。**

### 正确做法

用 `SEEK_DATA` / `SEEK_HOLE` 问文件系统「这段是数据还是洞」，只把**数据段**搬过去；洞段在目标文件里用 `lseek` **跳过去**（不写）。目标文件的洞是「跳出来的」，不是「写零写出来的」。

```
源文件:  [数据 4K][    洞 500K    ][数据 4K][      洞 1.5M      ][数据 5B]
            ↓ 读+写    ↓ lseek 跳过    ↓ 读+写    ↓ lseek 跳过     ↓ 读+写
目标文件:[数据 4K][    洞 500K    ][数据 4K][      洞 1.5M      ][数据 5B]
                                            ↑ 最后由 ftruncate 补齐逻辑长度
```

完整源码 [`code/ex4_2_cpholes.c`](../code/ex4_2_cpholes.c)：

```c
/* ex4_2_cpholes.c — TLPI 练习 4-2：像 cp 一样拷贝，但保留源文件的「空洞」
 *
 * 【题干（原书 Exercise 4-2，逐字）】
 *   Write a program like cp that, when used to copy a regular file that
 *   contains holes (sequences of null bytes), also creates correspdonding
 *   holes in the target file.
 *
 * 【朴素做法错在哪】
 *   普通 copy 用 `while (read(...) > 0) write(...)`，读到空洞区会拿到一堆
 *   真实的 0 字节，然后老老实实写进目标文件 —— 空洞被「灌实」了，
 *   目标文件物理占用暴涨。源文件 4 KB、目标文件 1 MB 的荒唐结果从此而来。
 *
 * 【正确做法】
 *   用 lseek(fd, off, SEEK_DATA) / SEEK_HOLE 问文件系统「哪里有数据、
 *   哪里有洞」，把有数据的段读出来写过去，洞则在目标文件里用 lseek
 *   跳过去（不写）。目标文件的洞是「跳出来」的，不是「写零写出来」的。
 *
 * 【注意】SEEK_HOLE/SEEK_DATA 需要文件系统支持（ext4/xfs/btrfs 都支持，
 *   某些陈旧 FS 或 overlayfs 可能不支持，会返回 EINVAL）。
 *
 * 编译: gcc -O0 -Wall -o ex4_2_cpholes ex4_2_cpholes.c
 * 用法: ./ex4_2_cpholes src dst
 */
#define _GNU_SOURCE
#include <fcntl.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <unistd.h>
#include <errno.h>
#include <sys/stat.h>

#define BUF_SIZE 4096

static ssize_t writeAll(int fd, const char *buf, size_t len)
{
    size_t written = 0;
    while (written < len) {
        ssize_t n = write(fd, buf + written, len - written);
        if (n < 0) {
            if (errno == EINTR) continue;
            return -1;
        }
        written += (size_t) n;
    }
    return (ssize_t) written;
}

static void report(const char *tag, const char *path)
{
    struct stat st;
    if (stat(path, &st) < 0) return;
    printf("  %-14s st_size = %8lld B   st_blocks*512 = %8lld B   块数 = %lld\n",
           tag, (long long) st.st_size, (long long) st.st_blocks * 512,
           (long long) st.st_blocks);
}

int main(int argc, char *argv[])
{
    const char *src, *dst;

    if (argc == 3) {
        src = argv[1];
        dst = argv[2];
    } else if (argc == 1) {
        /* 无参数模式：自己造一个带洞的源文件再拷它 —— 便于在无预置数据的
           环境（如 Compiler Explorer 沙箱）里自测。 */
        src = "/tmp/c4_holes_src.bin";
        dst = "/tmp/c4_holes_dst.bin";
        printf("== 0. 先造一个带洞的源文件 ==\n");
        int f = open(src, O_RDWR | O_CREAT | O_TRUNC, 0644);
        if (f < 0) { perror("open src"); return 1; }
        write(f, "HEAD-", 5);                        /* 数据段 1 */
        lseek(f, 512 * 1024, SEEK_SET);              /* 洞 1：跳 500 KB */
        write(f, "MIDDLE", 6);                       /* 数据段 2 */
        lseek(f, 2 * 1024 * 1024, SEEK_SET);         /* 洞 2：再跳 1.5 MB */
        write(f, "TAIL!", 5);                        /* 数据段 3 */
        /* 洞 3（**尾部洞**）：只把长度撑到 3 MiB，不写任何数据。
           这一段专门用来把「尾部是洞」这个场景造出来 —— 它同时逼出
           拷贝循环里的 ENXIO 分支和收尾的 ftruncate()。 */
        ftruncate(f, 3 * 1024 * 1024);
        close(f);
        report("造好的源文件", src);
        printf("\n== 开始拷贝 ==\n");
    } else {
        fprintf(stderr, "Usage: %s [src dst]\n", argv[0]);
        return 1;
    }

    int in = open(src, O_RDONLY);
    if (in < 0) { fprintf(stderr, "open %s: %s\n", src, strerror(errno)); return 1; }

    int out = open(dst, O_WRONLY | O_CREAT | O_TRUNC, 0644);
    if (out < 0) { fprintf(stderr, "open %s: %s\n", dst, strerror(errno)); return 1; }

    struct stat st;
    fstat(in, &st);
    off_t size = st.st_size;
    printf("  源文件 %s: st_size = %lld B, st_blocks*512 = %lld B\n",
           src, (long long) st.st_size, (long long) st.st_blocks * 512);

    off_t pos = 0;
    int holes = 0, data_segs = 0;
    char buf[BUF_SIZE];

    while (pos < size) {
        /* 从 pos 找下一段数据；没有数据就是纯洞，直接收尾 */
        off_t data = lseek(in, pos, SEEK_DATA);
        if (data < 0) {
            if (errno == ENXIO) {            /* 后面全是洞 */
                printf("  从偏移 %lld 起到文件末尾：全是洞，目标文件直接 lseek 跳过\n",
                       (long long) pos);
                holes++;
                break;
            }
            fprintf(stderr, "SEEK_DATA(%lld): %s\n", (long long) pos, strerror(errno));
            return 1;
        }

        if (data > pos) {                    /* [pos, data) 是一段洞 */
            printf("  洞   : 偏移 %8lld .. %8lld  （%lld 字节）\n",
                   (long long) pos, (long long) data, (long long) (data - pos));
            holes++;
            if (lseek(out, data, SEEK_SET) < 0) {   /* 目标文件也跳过这段 */
                fprintf(stderr, "lseek out: %s\n", strerror(errno));
                return 1;
            }
        }

        /* 从 data 找下一个洞 → [data, hole) 是有数据的段 */
        off_t hole = lseek(in, data, SEEK_HOLE);
        if (hole < 0) hole = size;           /* 文件系统不报洞就一路拷到底 */
        printf("  数据 : 偏移 %8lld .. %8lld  （%lld 字节）\n",
               (long long) data, (long long) hole, (long long) (hole - data));
        data_segs++;

        if (lseek(in, data, SEEK_SET) < 0) return 1;
        if (lseek(out, data, SEEK_SET) < 0) return 1;
        off_t remaining = hole - data;
        while (remaining > 0) {
            size_t want = remaining < (off_t) sizeof buf ? (size_t) remaining
                                                         : sizeof buf;
            ssize_t n = read(in, buf, want);
            if (n < 0) { if (errno == EINTR) continue;
                         fprintf(stderr, "read: %s\n", strerror(errno)); return 1; }
            if (n == 0) break;
            if (writeAll(out, buf, (size_t) n) < 0) {
                fprintf(stderr, "write: %s\n", strerror(errno)); return 1;
            }
            remaining -= n;
        }
        pos = hole;
    }

    /* 关键一步：把目标文件「撑」到和源文件一样的逻辑大小。
       本轮源文件以一段尾部洞收尾（循环是靠 ENXIO 退出的），所以最后那个
       数据段之后什么都没有写 —— 不执行这一句，目标文件就比源文件短。
       ftruncate 扩出来的区域不分配磁盘块，所以洞依然保留。 */
    if (ftruncate(out, size) < 0)
        fprintf(stderr, "ftruncate: %s\n", strerror(errno));

    printf("  共 %d 段数据、%d 处洞\n", data_segs, holes);
    close(in);
    close(out);

    printf("\n== 结果对比 ==\n");
    report(src, src);
    report(dst, dst);
    printf("  → 两者 st_size 一样（逻辑内容相同），st_blocks 也接近（洞被保留）。\n");
    printf("    若用朴素 read/write 拷贝，目标 st_blocks 会被灌到跟 st_size 一个量级。\n");
    return 0;
}
```

三个关键点：

| 点 | 代码 | 为什么 |
|----|------|--------|
| 找下一段数据 | `lseek(in, pos, SEEK_DATA)` | 返回 `pos` 之后第一个**数据**字节的偏移；没有数据则 `errno == ENXIO` |
| 找下一个洞 | `lseek(in, data, SEEK_HOLE)` | 返回 `data` 之后第一个**洞**；失败就退化成「一路拷到底」（`hole = size`） |
| 补齐尾部洞 | `ftruncate(out, size)` | **漏了这句，跳过尾部洞的文件会比源文件短** |

`ftruncate` 这一步最容易忘：循环结束时 `out` 的偏移停在最后一个数据段的末尾，后面那一大段尾部洞没有「写」过，所以文件逻辑长度不够。`ftruncate` 把它撑到 `size`，而这个扩展出来的区域**天然就是洞**（不分配块）。

### 实测（CE）

无参数运行会让程序自造一个带洞的源文件（沙箱里没有预置数据可用）：


```text
== 0. 先造一个带洞的源文件 ==
  造好的源文件 st_size =  3145728 B   st_blocks*512 =    12288 B   块数 = 24

== 开始拷贝 ==
  源文件 /tmp/c4_holes_src.bin: st_size = 3145728 B, st_blocks*512 = 12288 B
  数据 : 偏移        0 ..     4096  （4096 字节）
  洞   : 偏移     4096 ..   524288  （520192 字节）
  数据 : 偏移   524288 ..   528384  （4096 字节）
  洞   : 偏移   528384 ..  2097152  （1568768 字节）
  数据 : 偏移  2097152 ..  2101248  （4096 字节）
  从偏移 2101248 起到文件末尾：全是洞，目标文件直接 lseek 跳过
  共 3 段数据、3 处洞

== 结果对比 ==
  /tmp/c4_holes_src.bin st_size =  3145728 B   st_blocks*512 =    12288 B   块数 = 24
  /tmp/c4_holes_dst.bin st_size =  3145728 B   st_blocks*512 =    12288 B   块数 = 24
  → 两者 st_size 一样（逻辑内容相同），st_blocks 也接近（洞被保留）。
    若用朴素 read/write 拷贝，目标 st_blocks 会被灌到跟 st_size 一个量级。
```

**解读**：

| 观察 | 说明 |
|------|------|
| 源 `st_size = 3145728`（3 MiB），`st_blocks*512 = 12288`（12 KiB） | 逻辑 3 MiB、物理 12 KiB，**差了 256 倍**——这就是稀疏文件 |
| 扫出 **3 段数据 + 3 处洞** | 交错分布。最后那段洞是**尾部洞**：循环是靠 `SEEK_DATA` 返回 `ENXIO` 退出的，不是靠 `pos < size` 走完 |
| 第三段报 `4096` 字节，可源文件里只写了 5 字节 | 段边界按**文件系统块**报，不是按写入字节数报（这 4096 字节里有 4091 个「块内补零」） |
| 洞的边界 `4096` / `524288` / `528384` / `2097152` / `2101248` | 全是 4 KiB 的整数倍——粒度是块，不是字节 |
| 目标 `st_size` **完全相同** | 逻辑内容一致。**这一轮靠的正是末尾那句 `ftruncate(out, size)`**：最后一个数据段之后什么都没写，`out` 本来只有 2101248 字节，是 `ftruncate` 把它撑到 3145728 |
| 目标 `st_blocks` **也完全相同**（12288 B / 24 块） | 洞被真正保留了——**连 `ftruncate` 撑出来的尾部洞也是洞**（扩展区不分配块）。**这就是本题的全部意义** |

### 一个副产品：段边界「块对齐，但被 `i_size` 截断」

注意第三段数据报的是 `4096` 字节，而源文件里明明只写了 5 字节。这不是 bug——把这个 demo 的**前一版**（源文件以数据段结尾，`i_size = 2097157`）的输出放在一起看，规律就出来了：

| 版本 | 最后一段数据写了几字节 | `i_size` | FS 报的段尾 |
|------|---------------------|---------|------------|
| 前一版（无尾部洞） | 5 | 2097157 | **2097157**（正好是 `i_size`） |
| 本版（有尾部洞） | 5 | 3145728 | **2101248**（`2097152 + 4096`，块对齐） |

两版唯一的差别是 `i_size`：段边界按**块**算，但**会被 `i_size` 截断**。所以：

- 数据段恰好顶到文件末尾时，报的是 `i_size`（看起来像「字节级精确」）
- 数据段后面还有洞时，报的就是**块边界**（露出 4091 个零填充字节）

这和 [4.7](4.7-lseek.md) 里 `lseek(4, SEEK_HOLE) → 4096` 是同一个机制。**结论**：拿 `SEEK_DATA`/`SEEK_HOLE` 做逻辑时，一律按块对齐去理解，别假设字节级精度。

> 对比一下：把 `SEEK_DATA`/`SEEK_HOLE` 换成朴素循环，目标 `st_blocks*512` 会从 12288 涨到约 3145728（3 MiB）——逻辑大小一样，物理占用 **256 倍**。

### 一个可移植性坑

`SEEK_DATA`/`SEEK_HOLE` **不是所有文件系统都支持**。ext4/xfs/btrfs 支持，某些文件系统会返回 `EINVAL`。而且前面 [4.7](4.7-lseek.md) 已经挖出过：内核通用兜底 `default_llseek` 对这两个 whence 的实现是**「文件末尾是唯一的洞」**——在不支持洞检测的 FS 上，这份代码会退化成「一路拷到底」，**洞静默失效**。所以程序里那句 `if (hole < 0) hole = size;` 既是容错，也藏着「优化可能悄悄不生效」的风险。

## 练习 4-3（自编）：制造一次真实的部分写

[4.5 `write()`](4.5-write.md) 里说「部分写是合法结果」。但**用普通文件很难制造出来**——你也看到了，原书 Listing 4-1 干脆写了 `fatal("write() returned error or partial write occurred")`，因为「往普通文件写一小段」这个受控场景下部分写确实不该出现。

想亲眼看一次，得找一个**有容量上限**的对象。管道正好：它有一个固定容量的环形缓冲区。

完整源码 [`code/ex4_3_partial_write.c`](../code/ex4_3_partial_write.c)：

```c
/* ex4_3_partial_write.c — 亲手制造一次「部分写」，看 writeAll 怎么救回来
 *
 * 【为什么需要这个 demo】
 *   原书 Listing 4-1（copy.c）写的是：
 *        if (write(outputFd, buf, numRead) != numRead)
 *            fatal("write() returned error or partial write occurred");
 *   它敢这么写，是因为它只拷普通文件——普通文件上部分写几乎不出现。
 *   但只要换成管道/socket/磁盘快满，部分写就是**常态**，`!=` 直接报错
 *   就等于把「可恢复的慢」当成「不可恢复的错」。
 *
 *   这个 demo 用 pipe + 缩小管道缓冲 + 非阻塞，强制内核只写一部分，
 *   让「部分写」从书本概念变成屏幕上看得见的数字。
 *
 * 编译: gcc -O0 -Wall -o ex4_3_partial_write ex4_3_partial_write.c
 */
#define _GNU_SOURCE
#include <fcntl.h>
#include <stdio.h>
#include <string.h>
#include <unistd.h>
#include <errno.h>
#include <fcntl.h>

/* 通用写法：循环直到写完（处理部分写 + EINTR） */
static ssize_t writeAll(int fd, const char *buf, size_t len)
{
    size_t written = 0;
    while (written < len) {
        ssize_t n = write(fd, buf + written, len - written);
        if (n < 0) {
            if (errno == EINTR)    continue;   /* 被打断：重试 */
            if (errno == EAGAIN)   break;      /* 非阻塞且缓冲满：先收工，稍后再来 */
            return -1;
        }
        written += (size_t) n;
    }
    return (ssize_t) written;
}

int main(void)
{
    char buf[8192];
    memset(buf, 'Z', sizeof buf);

    printf("== 1. 造一个「容量很小」的管道 ==\n");
    int p[2];
    if (pipe(p) < 0) { perror("pipe"); return 1; }

    int defsz = fcntl(p[1], F_GETPIPE_SZ);
    printf("  默认管道容量 F_GETPIPE_SZ = %d 字节\n", defsz);

    /* 调小到一页，便于观察「写不下」 */
    int want = 4096;
    if (fcntl(p[1], F_SETPIPE_SZ, want) < 0)
        printf("  F_SETPIPE_SZ(%d) 失败: %s（继续用默认容量）\n", want, strerror(errno));
    int nowsz = fcntl(p[1], F_GETPIPE_SZ);
    printf("  现在容量 F_GETPIPE_SZ = %d 字节\n", nowsz);

    printf("\n== 2. 非阻塞写「远超容量」的数据 → 必然部分写 ==\n");
    int fl = fcntl(p[1], F_GETFL);
    fcntl(p[1], F_SETFL, fl | O_NONBLOCK);       /* 不阻塞，写不下就立刻返回 */

    size_t want_write = sizeof buf;              /* 8192 字节 */
    errno = 0;
    ssize_t n = write(p[1], buf, want_write);    /* 先来一次「裸 write」 */
    printf("  裸 write(p[1], buf, %zu) -> %zd 字节", want_write, n);
    if (n < (ssize_t) want_write)
        printf("   ← 部分写！请求 %zu，只写了 %zd\n", want_write, n);
    else
        printf("\n");

    printf("\n== 3. 同一件事：writeAll 循环版，把剩余的都补上 ==\n");
    /* 先把管道清空，重新来过。
       注意：读端也要设非阻塞，否则「读空管道」会一直阻塞下去
       （这就是本 demo 第一版在 CE 上跑满 20 秒被 kill 的原因）。 */
    fcntl(p[0], F_SETFL, fcntl(p[0], F_GETFL) | O_NONBLOCK);
    { char drain[8192]; while (read(p[0], drain, sizeof drain) > 0) ; }

    size_t total = 0;
    for (int spins = 0; spins < 100 && total < want_write; spins++) {
        ssize_t w = writeAll(p[1], buf + total, want_write - total);
        if (w < 0) { perror("writeAll"); break; }
        total += (size_t) w;
        printf("  writeAll 一轮写出 %zd 字节，累计 %zu / %zu\n", w, total, want_write);
        if (total < want_write) {
            char drain[8192];                      /* 缓冲满了：真实程序此时该等「可写事件」 */
            ssize_t got = read(p[0], drain, sizeof drain);
            printf("    管道满，读端消费 %zd 字节后继续\n", got);
            if (got <= 0) break;                   /* 真读不到就收手，别空转 */
        }
    }
    printf("  writeAll 最终写出 %zu 字节（请求 %zu）\n", total, want_write);

    printf("\n== 4. 结论 ==\n");
    printf("  同一份数据、同一次请求，内核可以只写一部分就返回。\n");
    printf("  所以：write 的返回值必须用，且要用循环；`!= count 就报错` 只适用于\n");
    printf("  「只写普通文件」这种受控场景（原书 Listing 4-1 正是这个场景）。\n");
    close(p[0]);
    close(p[1]);
    return 0;
}
```

思路：
1. `fcntl(p[1], F_SETPIPE_SZ, 4096)` 把管道容量压到 4096 字节
2. 读端也设 `O_NONBLOCK`（否则写满后 drain 会死锁）
3. 非阻塞 `write(p[1], buf, 8192)` → 内核装不下 8192，**只写 4096 就返回**
4. 再用 `writeAll` 循环版：写一轮、读端消费一轮、再写一轮，最终写满 8192

### 实测（CE）

```bash
gcc -O0 -Wall -Wextra -o ex4_3_partial_write ex4_3_partial_write.c
./ex4_3_partial_write
```

```text
== 1. 造一个「容量很小」的管道 ==
  默认管道容量 F_GETPIPE_SZ = 65536 字节
  现在容量 F_GETPIPE_SZ = 4096 字节

== 2. 非阻塞写「远超容量」的数据 → 必然部分写 ==
  裸 write(p[1], buf, 8192) -> 4096 字节   ← 部分写！请求 8192，只写了 4096

== 3. 同一件事：writeAll 循环版，把剩余的都补上 ==
  writeAll 一轮写出 4096 字节，累计 4096 / 8192
    管道满，读端消费 4096 字节后继续
  writeAll 一轮写出 4096 字节，累计 8192 / 8192
  writeAll 最终写出 8192 字节（请求 8192）

== 4. 结论 ==
  同一份数据、同一次请求，内核可以只写一部分就返回。
  所以：write 的返回值必须用，且要用循环；`!= count 就报错` 只适用于
  「只写普通文件」这种受控场景（原书 Listing 4-1 正是这个场景）。
```

**解读**：

| 观察 | 说明 |
|------|------|
| 默认管道容量 `65536` | Linux 默认 64 KiB（内核 `fs/pipe.c` 的初始容量上限）。`F_SETPIPE_SZ` 可以调，上限受 `/proc/sys/fs/pipe-max-size` 约束 |
| 裸 `write(8192)` → **返回 4096** | 请求 8192，实际只写 4096。**没有报错，`errno` 干净**——这正是「部分写必须处理」的原因 |
| `writeAll` 两轮补齐 | 第一轮撞满管道 → 让读端消费 → 第二轮补齐。循环的本质就是「写多少、扣多少、继续」 |
| 结论与 Listing 4-1 的对比 | 原书那个 `fatal(...)` 在「只写普通文件」时是安全的（普通文件几乎不会部分写）；一旦对象换成管道/socket，**同一句判断就会误杀** |

> 这也解释了为什么 [4.5](4.5-write.md) 的 demo 里 `write(4096)` 一次就返回 4096：目标是普通文件，没有容量天花板。**对象决定行为**——这就是通用 I/O 模型的另一面：接口统一，但底下的容量特性千差万别。

## 补充练习（自编，巩固机制）

原书只有上面两道，下面两道不要写代码，但值得想清楚：

### 补充 1：`short write` 的至少 3 种成因

1. **管道/FIFO 缓冲区只剩一部分空间**：内核能装多少装多少（本页练习 4-3 实测）。
2. **被信号中断（`EINTR`）**：部分数据已写入后被打断。正确处理是**重试**而不是报错。
3. **磁盘/配额空间不足（`ENOSPC` / `EDQUOT`）**：只写入剩余空间能容纳的部分。
4. **socket 发送缓冲区部分填满**：TCP 只拷了能放下的字节。

对应内核机制：`vfs_write` 不做「保证写满」的承诺（`fs/read_write.c:564`），实际写入量由 `f_op->write` / `f_op->write_iter` 决定。`vfs_read` 同理（`:450`）。

### 补充 2：`O_APPEND` 的原子性

**有 `O_APPEND`**：不交错。内核在 `vfs_write` 内部把「定位到末尾 + 写」做成**一个不可分割的动作**——注意它是内核代码里的原子性，不是用户态两次 syscall 的巧合。

**无 `O_APPEND`**：会交错。`lseek(SEEK_END)` + `write()` 是**两步**，进程 A 的两步之间可能插入进程 B，两者都从同一个「旧末尾」开始写，导致互相覆盖。

这是经典的 TOCTOU 竞争窗口。**用户态代码无法复刻 `O_APPEND` 的同等原子性**——这是本章唯一一个「必须有内核配合才能做对」的机制。

<summary>代码自测（Q&A）</summary>

**Q1：`tee` 为什么必须对 stdout 也用循环写？**
A：因为 stdout 可能是管道（`| grep`、`| tee`）。管道有容量上限，写超过剩余空间就会部分写——和写文件一样。只对文件循环、对 stdout 单次 `write()`，在本地终端下**测不出问题**（tty 慢且通常能收下），一旦被管道接管就会丢数据。这正是练习 4-3 实测的那个现象。

**Q2：`tee -a` 和默认行为在内核里差什么？**
A：只差一个标志位：默认 `O_TRUNC`（打开时把文件截断为 0），`-a` 用 `O_APPEND`（每次写前原子地定位到末尾）。`O_TRUNC` 发生在 `open` 时，`O_APPEND` 发生在**每次 `write` 时**——所以 `-a` 在多进程并发下也是安全的，`O_TRUNC` 语义上就是「清空重来」。

**Q3：为什么朴素 `read/write` 拷贝会把空洞灌实？**
A：因为**内核对空洞区的读返回真实的 0 字节**（[4.7](4.7-lseek.md) 实测：8 字节全是 0），而 `read` 不告诉你「这段原本是洞」。用户态只看到「一堆 0」，就会把它们写进目标文件，目标文件于是真的分配块、真的存了 0。要区分「洞」和「真数据里的 0」，**只能反过来问文件系统**——这就是 `SEEK_DATA`/`SEEK_HOLE` 存在的理由。

**Q4：练习 4-2 里 `ftruncate(out, size)` 那句能不能省？**
A：不能省。循环只写到最后一个**数据段**的末尾。本 demo 的源文件是以**尾部洞**收尾的（循环靠 `SEEK_DATA` 返回 `ENXIO` 退出），最后一个数据段只到 `2101248`，而 `i_size` 是 `3145728`——**不 `ftruncate`，目标文件就比源文件短 1 MB**。实测两份 `st_size` 完全相同，这一句正是原因。
有意思的是，这个 demo 的**前一版**源文件以数据段结尾（`i_size = 2097157`，最后一段写到 `2097157`），那时 `ftruncate` 恰好是**空操作**——看不出来它有没有用。**这正是它危险的地方：一行看起来可有可无的代码，只在特定输入下才暴露必要性。**
`ftruncate` 扩展出来的区域**不分配磁盘块**（实测尾部洞撑到 3 MiB 后 `st_blocks` 仍是 24 块），所以补长度的同时洞依然保留。

**Q5：`SEEK_DATA`/`SEEK_HOLE` 在所有文件系统上都能用吗？**
A：不能。内核通用兜底 `default_llseek`（`fs/read_write.c:230-278`）对这两个 whence 的实现是「**文件末尾是唯一的洞**」——在不支持真实洞检测的 FS 上，`SEEK_DATA` 直接返回 `offset`（当成全是数据）、`SEEK_HOLE` 返回 `i_size`。所以这份代码在不支持的 FS 上会**静默地退化成朴素拷贝**：结果正确，优化失效。程序里 `if (hole < 0) hole = size;` 是容错，但要意识到它也有「悄悄不优化」的一面。

**Q6：练习 4-3 里为什么读端也要设 `O_NONBLOCK`？**
A：因为要**边写边读**：管道写满 → 必须让读端消费 → 才能继续写。如果读端是阻塞的，主循环里那一步 drain 会在「管道里暂时没数据」时**永久阻塞**，程序卡死。实测：最初版本就是阻塞读的 drain 循环，在 CE 里跑满 20 秒被 kill（`exit code = 143`）；改成两端都非阻塞、用有界循环配 `EAGAIN` 才修好。

**Q7：为什么 `write` 部分写的时候 `errno` 还是干净的？**
A：因为部分写**不是错误**。`write` 返回一个小于 `count` 的正数，语义是「我只写了这么多」。`errno` 只在返回 `-1` 时才有意义。所以正确写法是：

```c
ssize_t n = write(fd, buf, len);
if (n < 0) {
    if (errno == EINTR) continue;   /* 被打断，重试 */
    /* 真错误 */
} else {
    /* n 可能是 1..len 之间的任何值，扣掉 n 继续 */
}
```

把 `n < len` 当成错误（原书 Listing 4-1 的 `fatal(...)`）只在「只写普通文件」这种受控场景成立。
