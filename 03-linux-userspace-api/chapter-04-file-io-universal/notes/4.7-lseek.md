## 本节讲什么

`lseek()` 调整文件偏移。本节回答四个问题：

1. `lseek` 在内核里怎么改 `f_pos`？`SEEK_END` 的「末尾」从哪来？
2. 为什么管道/socket 上 `lseek` 返回 `ESPIPE`？
3. 「文件空洞」是怎么来的？读空洞区得到什么？
4. 原书那个交互式演示器 `seek_io`（Listing 4-3）怎么用？（见 §5 原书 Listing 4-3）

本节还有一个**源码层面的发现**：`SEEK_HOLE`/`SEEK_DATA` 在内核里有两套实现——通用兜底的那套**假设文件没有洞**，真正的洞检测是具体文件系统提供的。实测输出（`4096` 而不是 `i_size`）证明跑的是后者。

---

## 1. 原型与内核链路

```c
#include <unistd.h>
off_t lseek(int fd, off_t offset, int whence);
/* 成功返回新偏移；失败 -1（ESPIPE / EBADF / EINVAL） */
```

| `whence` | 基准 | 语义 |
|----------|------|------|
| `SEEK_SET` | 文件起始 | 偏移 = `offset` |
| `SEEK_CUR` | 当前偏移 | 偏移 = `f_pos + offset`（且 `offset==0` 时**只查不改**） |
| `SEEK_END` | 文件末尾 | 偏移 = `i_size + offset` |
| `SEEK_DATA` / `SEEK_HOLE` | — | 定位到下一个数据/空洞区（**需文件系统支持**） |

```
用户态 lseek(fd, offset, whence)
      ▼
SYSCALL_DEFINE3(lseek)         fs/read_write.c:311
      ▼
ksys_lseek()                   fs/read_write.c:293
      ├─→ fdget_pos(fd)       ← 取 struct file，fd 无效 → -EBADF
      ├─→ vfs_llseek()        ← 见下
      └─→ fdput_pos(f)
```

`vfs_llseek()` 先做「可 seek 性」检查（`fs/read_write.c:285-291`，逐字）：

```c
loff_t vfs_llseek(struct file *file, loff_t offset, int whence)
{
	if (!(file->f_mode & FMODE_LSEEK))
		return -ESPIPE;
	return file->f_op->llseek(file, offset, whence);
}
EXPORT_SYMBOL(vfs_llseek);
```

`FMODE_LSEEK` 值是 `0x4`（`include/linux/fs.h:115`）——管道/socket/终端不设这位，所以直接被挡在 `-ESPIPE`。

## 2. `default_llseek`：通用兜底实现

普通文件通常不自己实现 `llseek`，走内核的默认实现。**逐字全文**（`fs/read_write.c:230-278`，v6.6）：

```c
loff_t default_llseek(struct file *file, loff_t offset, int whence)
{
	struct inode *inode = file_inode(file);
	loff_t retval;

	inode_lock(inode);
	switch (whence) {
		case SEEK_END:
			offset += i_size_read(inode);
			break;
		case SEEK_CUR:
			if (offset == 0) {
				retval = file->f_pos;
				goto out;
			}
			offset += file->f_pos;
			break;
		case SEEK_DATA:
			/*
			 * In the generic case the entire file is data, so as
			 * long as offset isn't at the end of the file then the
			 * offset is data.
			 */
			if (offset >= inode->i_size) {
				retval = -ENXIO;
				goto out;
			}
			break;
		case SEEK_HOLE:
			/*
			 * There is a virtual hole at the end of the file, so
			 * as long as offset isn't i_size or larger, return
			 * i_size.
			 */
			if (offset >= inode->i_size) {
				retval = -ENXIO;
				goto out;
			}
			offset = inode->i_size;
			break;
	}
	retval = -EINVAL;
	if (offset >= 0 || unsigned_offsets(file)) {
		if (offset != file->f_pos) {
			file->f_pos = offset;
			file->f_version = 0;
		}
		retval = offset;
	}
out:
	inode_unlock(inode);
	return retval;
}
```

三个必须看清的点：

| 点 | 说明 |
|----|------|
| `SEEK_CUR` + `offset == 0` → `retval = file->f_pos; goto out;` | 这是「**查当前位置**」的专用快捷路径：`lseek(fd, 0, SEEK_CUR)` 不改任何东西，只把当前偏移返回给你 |
| `SEEK_END` 的「末尾」= `i_size_read(inode)` | 文件大小的权威来源是 **inode 的 `i_size`**，不是「实际扫到 EOF」。所以它不需要读一个字节就能算出末尾 |
| `if (offset != file->f_pos)` 才写回，并清 `f_version` | 偏移没变就不碰 `f_pos`；一旦改动还会清 `f_version`（供 NFS/缓存一致性用） |

### 一个源码层面的发现：`default_llseek` 假设「文件没有洞」

看 `SEEK_HOLE` 分支的注释和代码：

```c
		case SEEK_HOLE:
			/*
			 * There is a virtual hole at the end of the file, so
			 * as long as offset isn't i_size or larger, return
			 * i_size.
			 */
			...
			offset = inode->i_size;
```

它的语义是「**文件末尾是唯一的洞**」——不管 `offset` 在哪，只要没超出文件末尾，就告诉你「下一个洞在 `i_size` 处」。

**但实测 `lseek(4, SEEK_HOLE)` 返回的是 `4096`，不是 `i_size`（1048580）。** 说明真正管事的不是这个通用兜底，而是**文件系统自己实现的 `llseek`**（ext4 / overlayfs 会真实遍历 extent 树报告洞的位置）。

这解释了一个容易踩的坑：**同样的代码在不同文件系统上行为不同**。在不支持洞检测的 FS 上，`SEEK_HOLE` 会退化成「洞 = 文件末尾」，你的稀疏文件优化逻辑就静默失效了。

## 3. 文件空洞（sparse file）

```c
lseek(fd, 1024*1024, SEEK_SET);   /* 跳到 1MB 处 */
write(fd, "x", 1);                /* 中间 1MB 是空洞 */
```

产生一个「逻辑大小 1MB+1，物理只占几 KB」的稀疏文件：

- 空洞区**不分配磁盘块**（`ls -lh` 显示逻辑大小，`du -h` 显示真实占用）
- 读空洞区返回 **0**（内核在页缓存里「现场造零」）
- 拷贝稀疏文件若用普通 `read/write` 循环，会把空洞「读成真的 0 字节」写满目标——`cp` 默认能识别稀疏（`cp --sparse=auto`），自己写拷贝工具要注意（正确做法见 [练习 4-2](4.10-exercises.md)）

## 4. 代码：六组实测

完整源码 [`code/c4_7_lseek.c`](../code/c4_7_lseek.c)：

```c
/* c4_7_lseek.c — lseek()：只改偏移、不碰磁盘；越尾写就造出空洞
 *
 * 演示六件事：
 *   1) SEEK_SET / SEEK_CUR / SEEK_END 三种基准
 *   2) lseek(fd, 0, SEEK_CUR) 是「查当前偏移」的惯用法
 *   3) lseek 不改数据：同一偏移重复读，内容一样
 *   4) 越尾写造空洞：st_size 大、st_blocks 小（逻辑大小 ≠ 物理占用）
 *   5) 空洞区读出来是 0
 *   6) 管道上 lseek -> ESPIPE
 *
 * 编译: gcc -O0 -Wall -o c4_7_lseek c4_7_lseek.c
 */
#define _GNU_SOURCE     /* 必须在所有 include 之前：SEEK_HOLE / SEEK_DATA 靠它才可见 */
#include <fcntl.h>
#include <stdio.h>
#include <string.h>
#include <unistd.h>
#include <errno.h>
#include <sys/stat.h>

static void report_size(const char *tag, const char *path)
{
    struct stat st;
    if (stat(path, &st) < 0) return;
    printf("  %-22s st_size = %8lld 字节   st_blocks = %6lld 块  →  物理占用 ≈ %lld 字节\n",
           tag, (long long) st.st_size, (long long) st.st_blocks,
           (long long) st.st_blocks * 512);
}

int main(void)
{
    char c;
    const char *path = "/tmp/c4_lseek.txt";

    printf("== 1. 三种基准 ==\n");
    int fd = open(path, O_RDWR | O_CREAT | O_TRUNC, 0644);
    write(fd, "ABCDEFGHIJ", 10);             /* 10 字节 */
    printf("  文件内容 \"ABCDEFGHIJ\"（10 字节），写完偏移 = %ld\n",
           (long) lseek(fd, 0, SEEK_CUR));

    lseek(fd, 3, SEEK_SET);
    read(fd, &c, 1);
    printf("  SEEK_SET 到 3 再读 1 字节 -> '%c'   新偏移 = %ld\n",
           c, (long) lseek(fd, 0, SEEK_CUR));

    lseek(fd, -2, SEEK_CUR);
    read(fd, &c, 1);
    printf("  SEEK_CUR 回退 2 再读 1 字节 -> '%c'  新偏移 = %ld\n",
           c, (long) lseek(fd, 0, SEEK_CUR));

    lseek(fd, -1, SEEK_END);
    read(fd, &c, 1);
    printf("  SEEK_END 回退 1 再读 1 字节 -> '%c'  新偏移 = %ld\n",
           c, (long) lseek(fd, 0, SEEK_CUR));

    printf("\n== 2. lseek 只改偏移，不改数据 ==\n");
    lseek(fd, 0, SEEK_SET);
    read(fd, &c, 1);
    printf("  偏移 0 读到 '%c'\n", c);
    lseek(fd, 0, SEEK_SET);
    read(fd, &c, 1);
    printf("  再回偏移 0 读到 '%c'  ← 数据没被动过，动的只是游标\n", c);

    printf("\n== 3. 越尾写 = 文件空洞（sparse file）==\n");
    close(fd);
    unlink(path);
    fd = open(path, O_RDWR | O_CREAT | O_TRUNC, 0644);
    write(fd, "HEAD", 4);                     /* 真实数据 4 字节 */
    report_size("只写 4 字节", path);

    off_t at = lseek(fd, 1024 * 1024, SEEK_SET);   /* 跳到 1 MiB 处 */
    printf("  lseek 到 1 MiB -> %ld\n", (long) at);
    write(fd, "TAIL", 4);
    report_size("越尾写 4 字节后", path);
    printf("  → 逻辑大小 ≈ 1 MiB + 4，物理占用只有几 KB。中间是空洞。\n");

    printf("\n== 4. 空洞区读出来是 0 ==\n");
    lseek(fd, 4096, SEEK_SET);                /* 跳进空洞中间 */
    char zbuf[8];
    ssize_t n = read(fd, zbuf, sizeof zbuf);
    printf("  从空洞里读 %zd 字节，全部是零？%s\n", n,
           (n == 8 && zbuf[0] == 0 && zbuf[7] == 0) ? "是" : "否");
    printf("  → 没有磁盘块存在，内核在页缓存里「现场造零」。\n");

    printf("\n== 5. SEEK_HOLE / SEEK_DATA：问文件系统「哪里有洞」==\n");
#ifdef SEEK_HOLE
    lseek(fd, 0, SEEK_SET);
    off_t d = lseek(fd, 0, SEEK_DATA);
    printf("  lseek(0, SEEK_DATA) -> %lld   （0：开头就是数据）\n", (long long) d);
    off_t h = lseek(fd, 4, SEEK_HOLE);
    printf("  lseek(4, SEEK_HOLE) -> %lld   ← 不是 4！文件系统按**块**报边界\n",
           (long long) h);
    if (h > 0) {
        d = lseek(fd, h, SEEK_DATA);
        printf("  lseek(%lld, SEEK_DATA) -> %lld   （下一个数据段的起点）\n",
               (long long) h, (long long) d);
    }
    printf("  → 粒度是文件系统块（这里 4096 字节），不是字节。所以洞的范围会被\n");
    printf("    向上取整到块边界；别拿它做逐字节的精确判断。\n");
#else
    printf("  （本平台没定义 SEEK_HOLE；需要 _GNU_SOURCE + 支持该特性的文件系统）\n");
#endif
    close(fd);

    printf("\n== 6. 管道上 lseek：ESPIPE ==\n");
    int p[2];
    pipe(p);
    errno = 0;
    off_t r = lseek(p[0], 0, SEEK_CUR);
    printf("  lseek(pipe, 0, SEEK_CUR) -> %ld  errno=%d (%s)\n",
           (long) r, errno, strerror(errno));
    printf("  → 管道是流，数据读走即消失，根本没有「当前位置」这个概念。\n");
    close(p[0]);
    close(p[1]);
    unlink(path);
    return 0;
}
```

```text
== 1. 三种基准 ==
  文件内容 "ABCDEFGHIJ"（10 字节），写完偏移 = 10
  SEEK_SET 到 3 再读 1 字节 -> 'D'   新偏移 = 4
  SEEK_CUR 回退 2 再读 1 字节 -> 'C'  新偏移 = 3
  SEEK_END 回退 1 再读 1 字节 -> 'J'  新偏移 = 10

== 2. lseek 只改偏移，不改数据 ==
  偏移 0 读到 'A'
  再回偏移 0 读到 'A'  ← 数据没被动过，动的只是游标

== 3. 越尾写 = 文件空洞（sparse file）==
  只写 4 字节        st_size =        4 字节   st_blocks =      8 块  →  物理占用 ≈ 4096 字节
  lseek 到 1 MiB -> 1048576
  越尾写 4 字节后  st_size =  1048580 字节   st_blocks =     16 块  →  物理占用 ≈ 8192 字节
  → 逻辑大小 ≈ 1 MiB + 4，物理占用只有几 KB。中间是空洞。

== 4. 空洞区读出来是 0 ==
  从空洞里读 8 字节，全部是零？是
  → 没有磁盘块存在，内核在页缓存里「现场造零」。

== 5. SEEK_HOLE / SEEK_DATA：问文件系统「哪里有洞」==
  lseek(0, SEEK_DATA) -> 0   （0：开头就是数据）
  lseek(4, SEEK_HOLE) -> 4096   ← 不是 4！文件系统按**块**报边界
  lseek(4096, SEEK_DATA) -> 1048576   （下一个数据段的起点）
  → 粒度是文件系统块（这里 4096 字节），不是字节。所以洞的范围会被
    向上取整到块边界；别拿它做逐字节的精确判断。

== 6. 管道上 lseek：ESPIPE ==
  lseek(pipe, 0, SEEK_CUR) -> -1  errno=29 (Illegal seek)
  → 管道是流，数据读走即消失，根本没有「当前位置」这个概念。
```

逐条看：

| 观察 | 说明 |
|------|------|
| `SEEK_SET 3` → 读到 `'D'`，偏移 4 | `SEEK_SET` 是绝对定位（0-based，第 4 个字符是 `'D'`） |
| `SEEK_CUR -2` → 从 4 退到 2，读到 `'C'`，偏移 3 | 相对定位。**注意 `SEEK_CUR` 的基准是当前偏移，不是"上次结果"** |
| `SEEK_END -1` → 读到 `'J'`（最后一个字符） | `SEEK_END` 基于 `i_size`，所以 `-1` 正好落在最后一字节 |
| 同一偏移重复读，结果相同 | `lseek` **完全不碰数据**，只移动游标 |
| 4 字节 → 越尾写 → `st_size` 暴增到 1048580，`st_blocks` 只从 8 涨到 16 | `1048580/512 ≈ 2048` 块，实际只有 16 块（8192 字节）。**逻辑大小和物理占用是两回事** |
| 空洞里读出来全是 0 | 那些 0 **不是磁盘上的数据**，是内核在页缓存里生成后交给你 |
| `SEEK_HOLE` 报 `4096` 而不是 `4` | 洞的边界按**文件系统块**（4 KiB）对齐。`HEAD-` 只有 5 字节，但它所在的整个块都算「有数据」 |
| 管道 `lseek` → `ESPIPE` | 流式对象没有「位置」概念，`FMODE_LSEEK` 未设，`vfs_llseek` 第一行就返回错误 |

```c
/* seek_io.c  —— TLPI Listing 4-3（逐字镜像，未改动） */

/* seek_io.c

   Demonstrate the use of lseek() and file I/O system calls.

   Usage: seek_io file {r<length>|R<length>|w<string>|s<offset>}...

   This program opens the file named on its command line, and then performs
   the file I/O operations specified by its remaining command-line arguments:

           r<length>    Read 'length' bytes from the file at current
                        file offset, displaying them as text.

           R<length>    Read 'length' bytes from the file at current
                        file offset, displaying them in hex.

           w<string>    Write 'string' at current file offset.

           s<offset>    Set the file offset to 'offset'.

   Example:

        seek_io myfile wxyz s1 r2
*/
#include <sys/stat.h>
#include <fcntl.h>
#include <ctype.h>
#include "tlpi_hdr.h"

int
main(int argc, char *argv[])
{
    size_t len;
    off_t offset;
    int fd, ap, j;
    unsigned char *buf;
    ssize_t numRead, numWritten;

    if (argc < 3 || strcmp(argv[1], "--help") == 0)
        usageErr("%s file {r<length>|R<length>|w<string>|s<offset>}...\n",
                 argv[0]);

    fd = open(argv[1], O_RDWR | O_CREAT,
                S_IRUSR | S_IWUSR | S_IRGRP | S_IWGRP |
                S_IROTH | S_IWOTH);                     /* rw-rw-rw- */
    if (fd == -1)
        errExit("open");

    for (ap = 2; ap < argc; ap++) {
        switch (argv[ap][0]) {
        case 'r':   /* Display bytes at current offset, as text */
        case 'R':   /* Display bytes at current offset, in hex */
            len = getLong(&argv[ap][1], GN_ANY_BASE, argv[ap]);

            buf = malloc(len);
            if (buf == NULL)
                errExit("malloc");

            numRead = read(fd, buf, len);
            if (numRead == -1)
                errExit("read");

            if (numRead == 0) {
                printf("%s: end-of-file\n", argv[ap]);
            } else {
                printf("%s: ", argv[ap]);
                for (j = 0; j < numRead; j++) {
                    if (argv[ap][0] == 'r')
                        printf("%c", isprint(buf[j]) ?  buf[j] : '?');
                    else
                        printf("%02x ", buf[j]);
                }
                printf("\n");
            }

            free(buf);
            break;

        case 'w':   /* Write string at current offset */
            numWritten = write(fd, &argv[ap][1], strlen(&argv[ap][1]));
            if (numWritten == -1)
                errExit("write");
            printf("%s: wrote %ld bytes\n", argv[ap], (long) numWritten);
            break;

        case 's':   /* Change file offset */
            offset = getLong(&argv[ap][1], GN_ANY_BASE, argv[ap]);
            if (lseek(fd, offset, SEEK_SET) == -1)
                errExit("lseek");
            printf("%s: seek succeeded\n", argv[ap]);
            break;

        default:
            cmdLineErr("Argument must start with [rRws]: %s\n", argv[ap]);
        }
    }

    if (close(fd) == -1)
        errExit("close");

    exit(EXIT_SUCCESS);
}
```

用法（每个参数是一个操作，按顺序执行）：

```
seek_io file {r<length>|R<length>|w<string>|s<offset>}...
```

| 操作 | 含义 |
|------|------|
| `r<length>` | 从**当前偏移**读 `length` 字节，按**文本**打印（不可打印字符打成 `?`） |
| `R<length>` | 同上，但按**十六进制**打印（`%02x `） |
| `w<string>` | 在**当前偏移**写字符串 |
| `s<offset>` | 把偏移设为 `offset`（`SEEK_SET`） |

它把三种调用串在一条命令里，正好是「`lseek` 只是移动游标、搬数据的另有其人」的最好注脚：

```bash
gcc -O0 -Wall -Wextra -o seek_io tlpi_hdr.h seek_io.c

./seek_io /tmp/seek_io_demo.txt \
    wABCDEFGHIJ s4 r3 s0 R10 s20 wXYZ s20 r3
```

| 操作 | 观察 | 说明 |
|------|------|------|
| `wABCDEFGHIJ` | `wrote 10 bytes` | 在偏移 0 写 10 字节，写完偏移自动变成 **10** |
| `s4` | `seek succeeded` | 只改游标，数据没动 |
| `r3` | `EFG` | 偏移 4 开始的 3 个字符 = `E`/`F`/`G`（`A` 是第 0 个）。**注意 `lseek` 是 0-based 的** |
| `s0` | `seek succeeded` | 跳回开头 |
| `R10` | `41 42 43 44 45 46 47 48 49 4a` | 同一段数据换成十六进制看。`41` = `'A'`…`4a` = `'J'`——**`r` 和 `R` 读的是同一份字节，只是打印方式不同** |
| `s20` | `seek succeeded` | 跳到文件末尾之后（文件当时只有 10 字节）→ 造洞 |
| `wXYZ` | `wrote 3 bytes` | 在 20 处写 3 字节。偏移 10..20 变成**空洞**（10 字节），文件逻辑长度变成 23 |
| `s20` `r3` | `XYZ` | 跳回去读，拿到刚写的 3 字节。**中间那 10 字节的洞没有读出来**（它不在读取范围里） |

### 两个使用注意

1. **`open` 用的是 `O_RDWR | O_CREAT`，没有 `O_TRUNC`**（`seek_io.c:54-56`）。所以对**同一个文件**重复运行，新写的字符会**盖在旧内容上**，读出来的东西和上一次有关。CE 每次是干净沙箱所以看不出来；本地反复跑请换文件名或先删。
2. **`r` 模式把不可打印字符打成 `?`**（`seek_io.c:80`：`isprint(buf[j]) ? buf[j] : '?'`）。所以想看清二进制内容要用 `R`（hex）。想看「洞里的 0」用 `R` 才能看到 `00`。

> 与自编 `c4_7_lseek.c` 的分工：`seek_io` 是**原书原物**、可交互组合，适合手动玩；`c4_7_lseek.c` 是**定点验证**，覆盖了 `SEEK_CUR`/`SEEK_END`/`SEEK_HOLE`/`SEEK_DATA` 和 `st_size` vs `st_blocks` 这些原书没有的实测点。两者互补。

## 6. HFT / 嵌入式关联

| 现象 | 本节机制的兑现 |
|------|----------------|
| 日志文件大小 | `lseek(fd, 0, SEEK_END)` 是「不用 `stat` 拿文件大小」的快捷方式（但要恢复原偏移）；更稳的是 `fstat` |
| 稀疏文件省盘 | 预分配大文件（如行情回放文件）用 `lseek` + 写尾，逻辑大小大、物理占用小。实测 1 MiB 逻辑只占 8 KiB |
| 洞检测要挑文件系统 | `SEEK_HOLE` 在支持它的 FS 上给精确边界，在不支持的 FS 上退化成 `default_llseek` 的「洞=文件末尾」——**同一份代码两种行为** |
| 管道不可 seek | 从管道/socket 读流时不能回退/跳转，只能顺序消费——行情流天然是「只前进」的 |
| 偏移是共享状态 | `f_pos` 在 `struct file` 里，`dup`/`fork` 共享；多进程随机读写要各自独立 `open` |

<summary>代码自测（Q&A）</summary>

**Q1：`lseek(fd, 0, SEEK_CUR)` 的作用是什么？**
A：从当前位置偏移 0 字节，即「查询当前偏移而不移动」。`default_llseek` 里有专门的快捷分支：`case SEEK_CUR: if (offset == 0) { retval = file->f_pos; goto out; }`——直接返回，连锁里的 `switch` 都不走完。

**Q2：所有文件类型都支持 `lseek` 吗？**
A：不。管道、socket、终端没有 `FMODE_LSEEK`（`fs.h:115`，值 `0x4`）标志，`vfs_llseek` 第一行就 `return -ESPIPE`。实测管道上 `errno=29`。它们是流式对象，数据读走即消失，没有「位置」概念。

**Q3：`lseek` 越尾再写会怎样？为什么「中间不占磁盘」？**
A：产生文件空洞。`lseek` 只改 `f_pos` 不写数据，中间的偏移区间没有对应磁盘块；只有后来 `write` 的尾部字节真正分配块。读空洞区时内核返回 0（页缓存现场造零）。实测：逻辑 1048580 字节、物理 8192 字节。

**Q4：用「`lseek(SEEK_END)` 拿文件大小」有什么要注意的？**
A：`SEEK_END` 会**移动** `f_pos` 到末尾。若之后还要在原位置读写，必须先 `SEEK_CUR` 记住原偏移、查完再 `SEEK_SET` 恢复。更稳妥的是用 `fstat`/`stat` 直接读 `st_size`，不碰偏移。

**Q5：`lseek` 会不会触发磁盘 I/O？**
A：不会。它只改内存里的 `struct file::f_pos`（`include/linux/fs.h:1007`），不读数据、不分配块（除非后续 `write` 到空洞区才分配）。这也是「`lseek` 极快」的原因。

**Q6：`SEEK_HOLE` 在所有文件系统上都返回真实洞位置吗？**
A：不一定。`default_llseek` 的 `SEEK_HOLE` 分支写死了「文件末尾是唯一的洞」（注释：`There is a virtual hole at the end of the file`），会直接返回 `i_size`。只有文件系统自己实现了 `llseek` 才会报告真实洞位置。实测在 overlayfs 上 `lseek(4, SEEK_HOLE)` 返回 `4096`（真实边界），说明走的是文件系统实现——**所以这段代码的可移植性取决于底层 FS**。

**Q7：为什么 `SEEK_HOLE` 报的洞起点是 4096 而不是 5？**
A：因为洞检测的粒度是**文件系统块**（这里 4 KiB），不是字节。前 5 字节 `HEAD-` 落在第 0 号块里，整个块就被视为「有数据」，所以下一个洞从块边界 4096 开始。做稀疏拷贝优化时要按块处理，不要假设字节级精度。
