## 实验 1：FIFO 99 满负荷 vs SCHED_OTHER 饿死

**问题**：核 11 上一个 FIFO 99 任务满负荷跑 2 秒，同核的 SCHED_OTHER 任务每 100ms 醒来记一次心跳，能记几次？实验用 `busy_done` 原子信号对齐双方时间窗，**心跳全部落在 FIFO 占核期内**，排除收尾自由段的干扰。

```c
/* fifo_starve.c — FIFO 满负荷 vs OTHER 饿死 (root, 绑核 11, 全程 ~2.5s)
 * 编译: gcc -O2 -Wall -Wextra -o fifo_starve fifo_starve.c -pthread
 */
#define _GNU_SOURCE
#include <errno.h>
#include <pthread.h>
#include <sched.h>
#include <stdatomic.h>
#include <stdio.h>
#include <string.h>
#include <time.h>
#include <unistd.h>

static double now_s(void)
{
    struct timespec ts;
    clock_gettime(CLOCK_MONOTONIC, &ts);
    return ts.tv_sec + ts.tv_nsec / 1e9;
}

static double cpu_s(void)
{
    struct timespec ts;
    clock_gettime(CLOCK_THREAD_CPUTIME_ID, &ts);
    return ts.tv_sec + ts.tv_nsec / 1e9;
}

static atomic_int busy_done;

static void *worker(void *arg)
{
    long *beats = arg;
    const struct timespec nap = {.tv_sec = 0, .tv_nsec = 100000000};
    while (!atomic_load(&busy_done)) {
        nanosleep(&nap, NULL);
        (*beats)++;                 /* 醒得来 + 拿得到 CPU 才有心跳 */
    }
    return NULL;
}

int main(void)
{
    setvbuf(stdout, NULL, _IOLBF, 0);

    cpu_set_t set;
    CPU_ZERO(&set);
    CPU_SET(11, &set);
    if (sched_setaffinity(0, sizeof set, &set) == -1) {
        perror("setaffinity(cpu11)");
        return 1;
    }

    long beats = 0;
    pthread_t tid;
    pthread_create(&tid, NULL, worker, &beats);

    struct sched_param sp = {.sched_priority = 99};
    if (sched_setscheduler(0, SCHED_FIFO, &sp) == -1) {
        fprintf(stderr, "sched_setscheduler(FIFO,99): %s (需要 root)\n",
                strerror(errno));
        atomic_store(&busy_done, 1);
        pthread_join(tid, NULL);
        return 1;
    }

    double t0 = now_s(), c0 = cpu_s();
    while (now_s() - t0 < 2.0)
        ;                            /* FIFO 99 满负荷自旋 2s */
    double wall = now_s() - t0, cpu = cpu_s() - c0;

    atomic_store(&busy_done, 1);    /* 先停表, 再恢复 OTHER */
    sp.sched_priority = 0;
    sched_setscheduler(0, SCHED_OTHER, &sp);
    pthread_join(tid, NULL);

    printf("FIFO 线程: 墙钟 %.2fs, 获得 CPU %.2fs (%.0f%%)\n",
           wall, cpu, 100 * cpu / wall);
    printf("OTHER 线程: FIFO 占核 2s 内心跳 %ld 次"
           " (无限流理想 OTHER 应 20 次; FIFO 无限流则趋 0)\n", beats);
    return 0;
}
```

实测输出（root · 核 11）：

```
# ./fifo_starve
FIFO 线程: 墙钟 2.00s, 获得 CPU 1.90s (95%)
OTHER 线程: FIFO 占核 2s 内心跳 4 次
```

**观察点**：
- FIFO 拿到 95% 而非 100%——**RT throttling**（950ms/1s，35.2 节六）在两秒内切出了约 100ms 的非 RT 窗口；
- OTHER 心跳 4 次 ≈ 每个周期 50ms 窗口里挤进 2 次——**饿死不是绝对的，throttling 是 OTHER 的活命通道**。把 `sched_rt_runtime_us` 设为 -1 关闭限流再跑，心跳将归零（读者自证）；
- `dmesg | grep throttling` 可见 `sched: RT throttling activated`（rt.c:1022）——本实验在 dmesg 里留下了它。

## 实验 2：RR 时间片轮转 vs FIFO 独占

**问题**：同优先级两个任务绑同一核，RR 和 FIFO 各是什么命运？
设计要点：worker 各自上报 TID，**主线程通过 TID 跨线程设置两个 worker 的策略**（演示 35.3 的「pid 参数是 TID」），再统一放行——避免"先升级者满核压制后升级者"的起跑线污染。

```c
/* rr_alt.c — 同优先级双子对比: ./rr_alt rr|fifo (root, worker 绑核 11)
 * 编译: gcc -O2 -Wall -Wextra -o rr_alt rr_alt.c -pthread
 */
#define _GNU_SOURCE
#include <errno.h>
#include <pthread.h>
#include <sched.h>
#include <stdatomic.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <sys/syscall.h>
#include <time.h>
#include <unistd.h>

static double now_s(void)
{
    struct timespec ts;
    clock_gettime(CLOCK_MONOTONIC, &ts);
    return ts.tv_sec + ts.tv_nsec / 1e9;
}

static atomic_int ready, start;
static pid_t g_tids[2];
static long cnt1, cnt2;
static int g_policy;

static void *spin(void *arg)
{
    long idx = (long)arg;
    long *cnt = idx ? &cnt2 : &cnt1;
    g_tids[idx] = syscall(SYS_gettid);      /* 上报 TID */
    atomic_fetch_add(&ready, 1);
    while (!atomic_load(&start))
        ;                                   /* 策略由主线程经 TID 设置 */
    double end = now_s() + 2.0;
    while (now_s() < end)
        (*cnt)++;
    return NULL;
}

int main(int argc, char **argv)
{
    setvbuf(stdout, NULL, _IOLBF, 0);
    g_policy = (argc > 1 && strcmp(argv[1], "fifo") == 0)
               ? SCHED_FIFO : SCHED_RR;

    cpu_set_t set;
    CPU_ZERO(&set);
    CPU_SET(11, &set);                      /* worker: 核 11 */
    pthread_attr_t attr;
    pthread_attr_init(&attr);
    pthread_attr_setaffinity_np(&attr, sizeof set, &set);

    pthread_t t1, t2;
    pthread_create(&t1, &attr, spin, (void *)0);
    pthread_create(&t2, &attr, spin, (void *)1);

    CPU_ZERO(&set);
    CPU_SET(10, &set);                      /* 主线程: 核 10 */
    sched_setaffinity(0, sizeof set, &set);
    while (atomic_load(&ready) < 2)
        usleep(1000);

    /* 跨线程设置: sched_setscheduler 的 pid 参数传 TID (35.3 节) */
    struct sched_param sp = {.sched_priority = 50};
    if (sched_setscheduler(g_tids[0], g_policy, &sp) == -1 ||
        sched_setscheduler(g_tids[1], g_policy, &sp) == -1) {
        perror("sched_setscheduler(worker)");
        return 1;
    }
    printf("T1(tid=%d) T2(tid=%d) 已设为 %s/50, 同时起跑\n",
           g_tids[0], g_tids[1],
           g_policy == SCHED_FIFO ? "FIFO" : "RR");
    atomic_store(&start, 1);

    for (int s = 1; s <= 2; s++) {
        sleep(1);
        printf("t=%ds  cnt1=%-12ld cnt2=%-12ld\n", s, cnt1, cnt2);
    }
    pthread_join(t1, NULL);
    pthread_join(t2, NULL);
    printf("policy=%s: cnt1=%ld cnt2=%ld\n",
           g_policy == SCHED_FIFO ? "SCHED_FIFO" : "SCHED_RR",
           cnt1, cnt2);
    return 0;
}
```

实测输出（root · worker 核 11 / 采样核 10）：

```
# ./rr_alt rr
T1(tid=7413) T2(tid=7414) 已设为 RR/50, 同时起跑
t=1s  cnt1=33223410     cnt2=33230171
t=2s  cnt1=66377555     cnt2=66431802
policy=SCHED_RR: cnt1=66377555 cnt2=66431802     ← 严格平分

# ./rr_alt fifo
T1(tid=7421) T2(tid=7422) 已设为 FIFO/50, 同时起跑
t=1s  cnt1=67668599     cnt2=1254
t=2s  cnt1=135437204    cnt2=1254
policy=SCHED_FIFO: cnt1=135437204 cnt2=1254       ← T2 基本饿死
```

**解读**：
- RR：两计数器每一秒都几乎相等——`task_tick_rt` 每 100ms（`RR_TIMESLICE`，rt.h:57）requeue 轮转（rt.c:2655-2667），双子平分秋色；
- FIFO：cnt2 ≈ 0 恒定——tick 对 FIFO 直接 return（rt.c:2652），同级无轮转。cnt2 的非零余量（1254 次 ≈ 微秒级）来自**设置成功到 T1 独占之间的毫秒级空隙**，之后彻底归零；
- 两组的 cnt 绝对值差 ≈ 2 倍：RR 版每个任务只拿到一半核时间——**轮转的"税"直接可见**（135M vs 66M）。

## 实验 3：RT throttling 直击（改配额 → 观察 → 恢复）

**问题**：把 `sched_rt_runtime_us` 从 950000 改成 100000（100ms/1s），FIFO 99 满负荷 2 秒能拿到多少 CPU？
设计要点：**先改配额再切 FIFO**（消除设置间隙的积累），并**跨周期边界 sleep 2 秒**（让核 11 的 rt_time 被 period timer 清零，排除上一实验残留）。

```c
/* rt_throttle.c — RT throttling 配额实验 (root, 绑核 11, 自动恢复 sysctl)
 * 编译: gcc -O2 -Wall -Wextra -o rt_throttle rt_throttle.c -pthread
 */
#define _GNU_SOURCE
#include <errno.h>
#include <sched.h>
#include <stdio.h>
#include <string.h>
#include <time.h>
#include <unistd.h>

static double now_s(void)
{
    struct timespec ts;
    clock_gettime(CLOCK_MONOTONIC, &ts);
    return ts.tv_sec + ts.tv_nsec / 1e9;
}

static double cpu_s(void)
{
    struct timespec ts;
    clock_gettime(CLOCK_THREAD_CPUTIME_ID, &ts);
    return ts.tv_sec + ts.tv_nsec / 1e9;
}

static int write_sysctl(const char *val)
{
    FILE *f = fopen("/proc/sys/kernel/sched_rt_runtime_us", "w");
    if (!f)
        return -1;
    int r = fputs(val, f) == EOF ? -1 : 0;
    fclose(f);
    return r;
}

int main(void)
{
    setvbuf(stdout, NULL, _IOLBF, 0);

    char orig[32] = "?";
    FILE *f = fopen("/proc/sys/kernel/sched_rt_runtime_us", "r");
    if (!f || !fgets(orig, sizeof orig, f)) {
        perror("读 sched_rt_runtime_us");
        return 1;
    }
    fclose(f);
    orig[strcspn(orig, "\n")] = 0;
    printf("当前配额: runtime=%s / period=1000000 (µs)\n", orig);

    /* 先改配额, 再切 FIFO: 消除切换间隙的 rt_time 积累 */
    if (write_sysctl("100000") == -1) {
        perror("写 sysctl");
        return 1;
    }
    printf("配额改为 100000 (100ms/1s)\n");

    cpu_set_t set;
    CPU_ZERO(&set);
    CPU_SET(11, &set);
    sched_setaffinity(0, sizeof set, &set);

    /* 跨周期边界: 清掉本核 rt_time 的历史残留 (前一实验的 FIFO 留下的账) */
    sleep(2);

    struct sched_param sp = {.sched_priority = 99};
    if (sched_setscheduler(0, SCHED_FIFO, &sp) == -1) {
        perror("sched_setscheduler(FIFO,99)");
        write_sysctl(orig);
        return 1;
    }
    printf("FIFO 99 满负荷 2s...\n");

    double t0 = now_s(), c0 = cpu_s();
    while (now_s() - t0 < 2.0)
        ;
    double wall = now_s() - t0, cpu = cpu_s() - c0;

    write_sysctl(orig);                      /* 无论结果如何都恢复 */
    printf("结果: 墙钟 %.2fs, 获得 CPU %.2fs (%.0f%%)\n",
           wall, cpu, 100 * cpu / wall);
    printf("已恢复 runtime=%s (验证: cat /proc/sys/kernel/sched_rt_runtime_us)\n",
           orig);
    return 0;
}
```

实测输出（root · 核 11）：

```
# ./rt_throttle
当前配额: runtime=950000 / period=1000000 (µs)
配额改为 100000 (100ms/1s)
FIFO 99 满负荷 2s...
结果: 墙钟 2.03s, 获得 CPU 0.20s (10%)
已恢复 runtime=950000 (验证: cat /proc/sys/kernel/sched_rt_runtime_us)
```

**解读**：2.03s 墙钟只拿到 0.20s——**恰好 = 2 个周期 × 100ms 配额**。`rt_time` 一超 100ms（`sched_rt_runtime_exceeded` rt.c:1013），整队下架冻结到周期起点（hrtimer `sched_rt_period_timer` 补给，rt.c:66/:901）。这就是 35.2 那张限流图的数值版。

紧随其后抓 dmesg（生产排障的指纹采集）：

```
$ dmesg | grep -i throttling
[  239.912405] sched: RT throttling activated          ← rt.c:1022 printk
```

> **相位噪声警告**：同一程序重跑一次得到的是 `墙钟 2.14s / CPU 0.30s (14%)` 而非 0.20s——任务起点与 period hrtimer 的相位关系决定了第一段配额窗口的可用长度（起点恰在周期边界后 vs 边界临近，第一段能差出约一个配额）。**做 throttling 实验看数量级（约 2×runtime），别较真个位数百分比**。

> **实验教训（第一版踩坑记）**：本实验第一版把"切 FIFO"放在"改配额"之前，且没有跨周期 sleep——实测得到 `墙钟 8.06s / CPU 0.00s` 的诡异数据：**上一实验（rr_alt fifo）留在核 11 的 rt_time 残余**让本任务上线即超限，几乎没跑就被冻结；随后 hypervisor 层的 vCPU 唤醒延迟让每次解冻都迟到，形成"冻结 900ms→解冻跑几微秒→再冻结"的循环，墙钟膨胀 4 倍。两处顺序修正（先改配额、跨周期清账）之后数据立即回到理论值。**rt_rq 的账本是每 CPU 持久的，做 throttling 实验必须先"清账"**。

## 实验 4：CFS 权重比——nice 0 vs nice 5 同核对撞（预写→实测）

**问题**：35.1 说"nice 差 5 ≈ 1.25⁵ ≈ 3.06 : 1 的 CPU 时间比"。同核上真跑出来是多少？
设计要点：两个 worker **绑同一核**（核 11，主线程躲核 10），各自 `setpriority(PRIO_PROCESS, 0, n)` 给**自己**设 nice（顺带验证 pid 参数的 TID 粒度），atomic 发令对齐起跑，各跑 4s 墙钟后报告 `CLOCK_THREAD_CPUTIME_ID`。

```c
/* nice_race.c — CFS 权重比实测: 同核 nice 0 vs nice 5
 * 预写结论: CPU 时间比 ≈ 1024:335 ≈ 3.06:1 (1.25^5)
 * 关键设计: worker 各自 setpriority(PRIO_PROCESS, 0, n) 作用于自身线程
 *           —— PRIO_PROCESS 的 pid 参数是 TID 粒度 (sys.c:219 task_pid_vnr(current))
 * 编译: gcc -O2 -Wall -Wextra -o nice_race nice_race.c -pthread
 */
#define _GNU_SOURCE
#include <errno.h>
#include <pthread.h>
#include <sched.h>
#include <stdatomic.h>
#include <stdio.h>
#include <string.h>
#include <sys/resource.h>
#include <time.h>
#include <unistd.h>

static double now_s(void)
{
    struct timespec ts;
    clock_gettime(CLOCK_MONOTONIC, &ts);
    return ts.tv_sec + ts.tv_nsec / 1e9;
}

static double cpu_s(void)
{
    struct timespec ts;
    clock_gettime(CLOCK_THREAD_CPUTIME_ID, &ts);
    return ts.tv_sec + ts.tv_nsec / 1e9;
}

static atomic_int go;
static double cpu0, cpu5;

static void *spin_target(void *arg)
{
    long want_nice = (long)arg;
    /* nice 对自身线程设置: PRIO_PROCESS + who=0 → 调用线程自己 */
    if (setpriority(PRIO_PROCESS, 0, (int)want_nice) == -1) {
        fprintf(stderr, "worker(nice %ld) setpriority: %s\n",
                want_nice, strerror(errno));
        return NULL;
    }
    errno = 0;
    int got = getpriority(PRIO_PROCESS, 0);
    printf("  worker: 请求 nice %ld, 读回 nice %d\n", want_nice, got);

    while (!atomic_load(&go))
        ;                        /* 等发令 */
    double end = now_s() + 4.0;  /* 各自跑 4s 墙钟 */
    double c0 = cpu_s();
    while (now_s() < end)
        ;
    double used = cpu_s() - c0;
    if (want_nice == 0)
        cpu0 = used;
    else
        cpu5 = used;
    return NULL;
}

int main(void)
{
    setvbuf(stdout, NULL, _IOLBF, 0);
    printf("[nice_race] 预写: nice0/nice5 CPU 比 ≈ 1024/335 = %.3f\n",
           1024.0 / 335.0);

    cpu_set_t wset, mset;
    CPU_ZERO(&wset);
    CPU_SET(11, &wset);          /* worker: 核 11 */
    CPU_ZERO(&mset);
    CPU_SET(10, &mset);          /* 主线程: 核 10 */

    pthread_attr_t attr;
    pthread_attr_init(&attr);
    pthread_attr_setaffinity_np(&attr, sizeof wset, &wset);

    pthread_t t0, t5;
    pthread_create(&t0, &attr, spin_target, (void *)0);
    pthread_create(&t5, &attr, spin_target, (void *)5);

    if (sched_setaffinity(0, sizeof mset, &mset) == -1) {
        perror("主线程 setaffinity(核10)");
        return 1;
    }
    usleep(100000);              /* 等 worker 报告 nice 读回 */
    atomic_store(&go, 1);

    pthread_join(t0, NULL);
    pthread_join(t5, NULL);

    printf("实测: nice0 = %.2fs, nice5 = %.2fs, 比值 = %.2f : 1\n",
           cpu0, cpu5, cpu0 / cpu5);
    printf("偏差: 实测 %.2f vs 理论 3.06 (%.1f%%)\n",
           cpu0 / cpu5, 100.0 * (cpu0 / cpu5) / 3.057 - 100.0);
    return 0;
}
```

实测输出（普通用户即够——nice 调大是降权，免特权）：

```
$ ./nice_race
[nice_race] 预写: nice0/nice5 CPU 比 ≈ 1024/335 = 3.057
  worker: 请求 nice 0, 读回 nice 0
  worker: 请求 nice 5, 读回 nice 5
实测: nice0 = 3.06s, nice5 = 1.01s, 比值 = 3.03 : 1
偏差: 实测 3.03 vs 理论 3.06 (-0.8%)

# root 重跑 (对照): 比值 = 3.03 : 1, nice0=3.03s, nice5=1.00s —— 一致
```

**解读**：
- **预写命中**：3.03 vs 理论 3.057，偏差 -0.8%——`sched_prio_to_weight` 的"每级 ×1.25"设计（core.c:11531 注释）在实测中兑现到 1% 以内。CFS 的 vruntime 分蛋糕就是严格按权重比执行，"nice 是比例调节"不是近似说法；
- 两次读回（`请求 nice 5, 读回 nice 5`）证明 **worker 线程各自独立设置了 nice 且互不影响**——`setpriority(PRIO_PROCESS, 0, …)` 的作用域是调用线程（TID），不是进程（TGID）。多线程程序里"给整个进程降权"必须逐线程设；
- 剩余 ~2% 偏差的来源：worker 起跑前的 `usleep(100000)` 窗口里 nice0 线程可能已抢跑、`CLOCK_THREAD_CPUTIME_ID` 的精度粒度、核 11 上偶发的外来任务。**微基准三诫第一条：只报比值不报绝对值**。

## 实验 5：SCHED_IDLE 两面观——单向门 + 权重比（预写→实测）

**问题 A**：普通用户能把自己切进 SCHED_IDLE 吗？切进去还能出来吗？
**问题 B**：SCHED_IDLE 的权重（3）与 nice 19 的权重（15）相比，CPU 时间比是 5:1 吗？

```c
/* idle_weight.c — SCHED_IDLE vs nice 19 的 CFS 权重比 + "单向门"验证
 * 预写 A: nice19(权重15) / SCHED_IDLE(权重3) CPU 比 ≈ 5:1
 *         (sched.h:2179 WEIGHT_IDLEPRIO=3, core.c:11542 nice19=15)
 * 预写 B: 普通用户能自降 SCHED_IDLE (切 IDLE 免特权), 但切回
 *         SCHED_OTHER 被拒 EPERM —— 按 "nice 20 提权" 审查 (core.c:7598)
 * 用法: ./idle_weight          (任何用户: 单向门验证)
 *       ./idle_weight weigh    (root: 权重比实测)
 * 编译: gcc -O2 -Wall -Wextra -o idle_weight idle_weight.c -pthread
 */
#define _GNU_SOURCE
#include <errno.h>
#include <pthread.h>
#include <sched.h>
#include <stdatomic.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <sys/resource.h>
#include <time.h>
#include <unistd.h>

static double now_s(void)
{
    struct timespec ts;
    clock_gettime(CLOCK_MONOTONIC, &ts);
    return ts.tv_sec + ts.tv_nsec / 1e9;
}

static double cpu_s(void)
{
    struct timespec ts;
    clock_gettime(CLOCK_THREAD_CPUTIME_ID, &ts);
    return ts.tv_sec + ts.tv_nsec / 1e9;
}

static const char *polname(int p)
{
    return p == SCHED_OTHER ? "SCHED_OTHER" :
           p == SCHED_FIFO  ? "SCHED_FIFO"  :
           p == SCHED_RR    ? "SCHED_RR"    :
           p == SCHED_BATCH ? "SCHED_BATCH" :
           p == SCHED_IDLE  ? "SCHED_IDLE"  : "other";
}

static void dump_policy(void)
{
    printf("  当前 policy=%s (euid=%d)\n", polname(sched_getscheduler(0)),
           geteuid());
}

/* ---------- 模式 1: 单向门 (任何用户) ---------- */
static int door_test(void)
{
    struct sched_param sp = {.sched_priority = 0};
    struct rlimit rl;
    getrlimit(RLIMIT_NICE, &rl);
    printf("[单向门] RLIMIT_NICE={soft=%lu, hard=%lu}\n",
           (unsigned long)rl.rlim_cur, (unsigned long)rl.rlim_max);
    dump_policy();

    printf("[1] 切入 SCHED_IDLE (预写: 免特权成功)...\n");
    if (sched_setscheduler(0, SCHED_IDLE, &sp) == -1) {
        printf("    切入失败: %s\n", strerror(errno));
        return 1;
    }
    dump_policy();

    printf("[2] 切回 SCHED_OTHER (预写: 非特权 EPERM, root 成功)...\n");
    if (sched_setscheduler(0, SCHED_OTHER, &sp) == -1) {
        printf("    切回失败: %s (EPERM=%d) —— 单向门!\n",
               strerror(errno), errno == EPERM);
        printf("    [3] 改用 nice 验证仍可读: nice=%d (nice 操作不受影响)\n",
               getpriority(PRIO_PROCESS, 0));
        return 0;                /* 停在 IDLE 是预期结果 */
    }
    dump_policy();
    printf("    切回成功 (本进程持有 CAP_SYS_NICE)\n");
    return 0;
}

/* ---------- 模式 2: 权重比 (root) ---------- */
static atomic_int go;
static double cpu_19, cpu_idle;

static void *spin19(void *arg)
{
    (void)arg;
    setpriority(PRIO_PROCESS, 0, 19);   /* 自身线程 nice 19 */
    while (!atomic_load(&go))
        ;
    double end = now_s() + 4.0, c0 = cpu_s();
    while (now_s() < end)
        ;
    cpu_19 = cpu_s() - c0;
    return NULL;
}

static void *spin_idle(void *arg)
{
    (void)arg;
    struct sched_param sp = {.sched_priority = 0};
    if (sched_setscheduler(0, SCHED_IDLE, &sp) == -1) {
        printf("  idle worker: 切 SCHED_IDLE 失败: %s\n", strerror(errno));
        return NULL;
    }
    while (!atomic_load(&go))
        ;
    double end = now_s() + 4.0, c0 = cpu_s();
    while (now_s() < end)
        ;
    cpu_idle = cpu_s() - c0;
    return NULL;
}

static int weigh_test(void)
{
    printf("[idle_weight weigh] 预写: nice19/SCHED_IDLE CPU 比 ≈ 15/3 = 5:1\n");
    cpu_set_t wset, mset;
    CPU_ZERO(&wset);
    CPU_SET(11, &wset);
    CPU_ZERO(&mset);
    CPU_SET(10, &mset);
    pthread_attr_t attr;
    pthread_attr_init(&attr);
    pthread_attr_setaffinity_np(&attr, sizeof wset, &wset);

    pthread_t ta, tb;
    pthread_create(&ta, &attr, spin19, NULL);
    pthread_create(&tb, &attr, spin_idle, NULL);
    sched_setaffinity(0, sizeof mset, &mset);
    usleep(200000);              /* 等 worker 就位 */
    atomic_store(&go, 1);

    pthread_join(ta, NULL);
    pthread_join(tb, NULL);

    printf("实测: nice19 = %.2fs, SCHED_IDLE = %.2fs, 比值 = %.2f : 1\n",
           cpu_19, cpu_idle, cpu_19 / cpu_idle);
    return 0;
}

int main(int argc, char **argv)
{
    setvbuf(stdout, NULL, _IOLBF, 0);
    if (argc > 1 && strcmp(argv[1], "weigh") == 0)
        return weigh_test();
    return door_test();
}
```

实测输出（两个身份各跑一次）：

```
$ ./idle_weight                        # 普通用户 (uid=1000)
[单向门] RLIMIT_NICE={soft=0, hard=0}
  当前 policy=SCHED_OTHER (euid=1000)
[1] 切入 SCHED_IDLE (预写: 免特权成功)...
  当前 policy=SCHED_IDLE (euid=1000)
[2] 切回 SCHED_OTHER (预写: 非特权 EPERM)...
    切回失败: Operation not permitted (EPERM=1) —— 单向门!
    [3] nice 仍可读: nice=0

# ./idle_weight weigh                   # root, 核 11 对撞
[idle_weight weigh] 预写: nice19/SCHED_IDLE CPU 比 ≈ 15/3 = 5:1
实测: nice19 = 3.37s, SCHED_IDLE = 0.68s, 比值 = 4.93 : 1
```

**解读**：
- **单向门确认**（问题 A）：切入免特权（user_check 的 fair 分支 :7566 只拦 nice 降低，切 IDLE 不带 nice 变更一路放行）；切回命中 :7598 专门分支——内核把"IDLE → 非 IDLE"等价于"从 nice 20 提升"，RLIMIT_NICE=0 必然不够 → EPERM。**普通用户可以自沉、不能自救**（详见 35.3 第五节）；
- **权重比命中**（问题 B）：4.93 vs 理论 5.00（偏差 -1.4%）——`WEIGHT_IDLEPRIO = 3`（sched.h:2179）不是注释里的装饰品，CFS 真拿它分蛋糕。注意 SCHED_IDLE 的"低一档"是**连续谱**（3/15 = 0.2 倍于 nice 19）而非"另一个世界"——它与 CFS 任务仍然同在一个 fair 队列里竞争，任何就绪 RT 任务照样把它俩一起踩；
- 与实验 4 合起来看：两个实验共用同一套骨架（双 worker 绑同核 + atomic 发令 + `CLOCK_THREAD_CPUTIME_ID` 计时），只换"策略/优先级"一个变量——这就是内核权重类实验的可复用模板。

## 实验 6：RESET_ON_FORK 隔代验证（预写→实测）

**问题**：flag "只管一代"到底是什么意思——孙进程会怎样？
预写：子进程被重置（OTHER/0，ROF 位清零）；子进程若重设 FIFO **不带 ROF**，孙进程应**原样继承 FIFO 40**（不再有重置发生）。

```c
/* rof_grand.c — SCHED_RESET_ON_FORK 隔代验证 (root)
 * 预写: flag 只管一代 (core.c:4763 子进程出生时清零)
 *   子进程: policy=OTHER, rt_priority=0, 无 ROF 位 (被重置)
 *   孙进程: 继承子进程的 FIFO 40 原样 (无重置) —— 重置不是遗传病
 * 编译: gcc -O2 -Wall -Wextra -o rof_grand rof_grand.c
 */
#define _GNU_SOURCE
#include <errno.h>
#include <sched.h>
#include <stdio.h>
#include <string.h>
#include <sys/wait.h>
#include <unistd.h>

static const char *polname(int p)
{
    int reset = p & SCHED_RESET_ON_FORK;
    p &= ~SCHED_RESET_ON_FORK;
    static char buf[32];
    const char *base =
        p == SCHED_OTHER ? "SCHED_OTHER" :
        p == SCHED_FIFO  ? "SCHED_FIFO"  :
        p == SCHED_RR    ? "SCHED_RR"    : "other";
    snprintf(buf, sizeof buf, "%s%s", base, reset ? "+ROF" : "");
    return buf;
}

static void dump(const char *who)
{
    struct sched_param sp = {0};
    sched_getparam(0, &sp);
    printf("  %-8s pid=%-6d policy=%-16s rt_priority=%d\n",
           who, getpid(), polname(sched_getscheduler(0)), sp.sched_priority);
}

int main(void)
{
    setvbuf(stdout, NULL, _IOLBF, 0);
    printf("[rof_grand] 预写: ROF 位只管一代, 孙进程不再带位\n");

    /* 父: FIFO 50 + RESET_ON_FORK */
    struct sched_param sp = {.sched_priority = 50};
    if (sched_setscheduler(0, SCHED_FIFO | SCHED_RESET_ON_FORK, &sp) == -1) {
        printf("需要 root: %s\n", strerror(errno));
        return 1;
    }
    dump("父(设置后)");

    pid_t child = fork();
    if (child == 0) {
        dump("子");              /* 预写: OTHER/0, 无 ROF 位 (被重置) */

        /* 子进程自行重设 FIFO 40 —— 注意不带 ROF 位。
         * 孙进程将原样继承 FIFO 40 (无重置) —— 这才是
         * "flag 不遗传"的直接证据: 重置只发生在父带位的那一次 fork */
        struct sched_param sp2 = {.sched_priority = 40};
        if (sched_setscheduler(0, SCHED_FIFO, &sp2) == 0) {
            printf("  子进程自行设 FIFO 40 (无ROF): OK\n");
            dump("子(重设后)");
        }

        pid_t grand = fork();
        if (grand == 0) {
            dump("孙");          /* 预写: FIFO/40 原样继承, 无 ROF 位 */
            _exit(0);
        }
        waitpid(grand, NULL, 0);
        sched_setscheduler(0, SCHED_OTHER, &(struct sched_param){0});
        _exit(0);
    }
    waitpid(child, NULL, 0);
    dump("父(最终)");            /* 预写: FIFO+ROF, 50 不变 */
    return 0;
}
```

实测输出（root）：

```
# ./rof_grand
[rof_grand] 预写: ROF 位只管一代, 孙进程不再带位
  父(设置后) pid=384    policy=SCHED_FIFO+ROF   rt_priority=50
  子      pid=385    policy=SCHED_OTHER      rt_priority=0
  子进程自行设 FIFO 40 (无ROF): OK
  子(重设后) pid=385    policy=SCHED_FIFO       rt_priority=40
  孙      pid=386    policy=SCHED_FIFO       rt_priority=40
  父(最终) pid=384    policy=SCHED_FIFO+ROF   rt_priority=50
```

**解读**：
- **预写命中**：五条记录构成"只管一代"的完整证据链——
  1. 父带位 → 子出生即重置（OTHER/0），`sched_reset_on_fork` 位同步清零（core.c:4763）；
  2. 子重设 FIFO 40（无 ROF）→ 孙**原样继承 FIFO 40**——如果 flag 会遗传，孙也该被重置成 OTHER，实测否决；
- ROF 的本质是**出生时的一次性产钳**，不是写进基因的遗传病——每一次 fork 是否重置，只看**父进程此刻**有没有带位；
- 注意 `sched_getscheduler` 返回值的坑（35.3）：父显示 `SCHED_FIFO+ROF` 是 Linux 2.6.39+ 的扩展行为（返回值带 flag 位），`polname()` 里的 `p &= ~SCHED_RESET_ON_FORK` 先剥位再判断才是可移植写法。

## 习题 7：推演——为什么 nice -20 救不了"必须先跑"

某同学把策略线程设为 `SCHED_OTHER` + nice -20，理由是"已经是普通进程最高优先级"。

<details>
<summary>参考答案</summary>

两个世界：策略线程的内核 prio = NICE_TO_PRIO(-20) = **100**；而任何就绪 RT 任务 prio ≤ 98。调度类层面 fair 整体被 rt 压制（sched.h:2323 类链从高往低扫），数值层面 100 > 98 恒成立。机器上任何一个失控的 SCHED_FIFO 1（哪怕 nice -20 的 CFS 负载为零）都能把它踩进土里。**"必须先跑"只有 RT 策略能承诺，nice 的极限只是"其他 CFS 任务让着我"。**
</details>

## 习题 8：设计——RT 服务的 fork 边界

一个 FIFO 90 的数据采集守护进程（root 运行）需要在收到外部指令时 fork/exec 执行 `/usr/local/bin/reload.sh`。给出三道防线防止调度属性泄漏到脚本。

<details>
<summary>参考答案</summary>

1. **`SCHED_RESET_ON_FORK`**：主服务 `sched_setscheduler(0, SCHED_FIFO|SCHED_RESET_ON_FORK, &sp)`——fork 出的子进程 policy→SCHED_NORMAL、nice→0、rt_priority→0（core.c:4750-4752），连负 nice 也一并归零（:4753-4754）。注意 flag 只管一代、且普通用户不能取消它（:7607-7609）；
2. **exec 前显式降级**：fork 后、exec 前在子进程里 `sched_setscheduler(0, SCHED_OTHER, &{0})`——RT 任务降优先级/降级是无特权自由（core.c:7557），双保险；
3. **能力最小化**：整个服务只给 `cap_sys_nice`（setcap）而非裸 root；脚本以专用低权账号跑——就算属性泄漏，泄漏的 FIFO 90 也撞不上任何别的破坏面。

风险点：巡检时注意 `sched_getscheduler` 返回值会带回 RESET_ON_FORK 位（2.6.39+ 扩展，35.3 实验 3 实测），先剥位再判断。
</details>

## 习题 9：综合设计——trader 双线程启动序列

行情线程（必须微秒级响应）+ 落盘线程（可拖延）。写出两个线程各自的调度配置与完整启动序列，并说明每一步为什么在这个次序。

<details>
<summary>参考答案</summary>

**配置**：行情线程 = SCHED_FIFO 85 + 绑隔离核 4 + mlockall；落盘线程 = SCHED_OTHER + nice 15 + 绑核 8（杂务核）。

**序列与理由**：

| 步 | 操作 | 为什么必须在此时 |
|----|------|------------------|
| 1 | `mlockall(MCL_CURRENT\|MCL_FUTURE)` | 趁代码还在 CFS 下、页错误还廉价时锁页；RT 之后一次缺页 = 微秒级悬崖 |
| 2 | 预触/预热所有热路径内存 + cache | 同上，且绑核后的迁移会冷 cache，预热应在最终绑核后补一轮 |
| 3 | `sched_setaffinity` 绑核 | 策略切换前先定"在哪跑"，避免切 FIFO 后任务先在错核上抢到 CPU |
| 4 | 行情线程 `sched_setscheduler(0, SCHED_FIFO, 85)` | 即时生效（switched_to_rt → resched_curr，rt.c:2557）；之后才允许开始热路径 |
| 5 | 落盘线程 `setpriority(PRIO_PROCESS, tid, 15)` | 最后降权——它不抢即可，顺序无碍 |
| 6 | 行情线程设 RLIMIT_RTTIME 兜底 | 防 bug 自旋烧配额触发 throttling 连累全核（35.2 节六） |

**为什么行情线程 85 而不是 99**：内核线程（ksoftirqd 等）在 99 附近有关键活动；网络收包链路若被自家线程踩住，延迟反而恶化。留头部余量是工程纪律（同 35.2 关联表）。
</details>
