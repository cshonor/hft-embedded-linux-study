# 35.2 Overview of Realtime Process Scheduling

> 本章：[TLPI 第 35 章 — Process Priorities and Scheduling](../README.md)

## 本节讲什么

介绍 Linux 实时调度策略：`SCHED_FIFO`（先进先出）、`SCHED_RR`（轮转）和 `SCHED_OTHER`（普通），以及优先级范围、调度行为和 API 概览。

## 要点

### 调度策略对比

| 策略 | 类型 | 优先级 | 行为 | 适用 |
|------|------|--------|------|------|
| `SCHED_OTHER` | 普通调度 | nice 值（-20~19） | CFS 公平调度 | 通用 |
| `SCHED_FIFO` | 实时 | 1-99 | 运行直到被抢占或让出 | 实时 |
| `SCHED_RR` | 实时 | 1-99 | 轮转，有时间片 | 实时 |
| `SCHED_BATCH` | 普通 | nice | 批处理优化 | 计算 |
| `SCHED_IDLE` | 最低 | — | 仅在空闲时运行 | 后台 |
| `SCHED_DEADLINE` | 实时 | EDF | 最早截止期限 | Linux 3.14+ |

### 优先级层次

```
实时优先级（1-99，越大越高）
  SCHED_FIFO / SCHED_RR
  ↑
  99 ← 最高
  ...
  1  ← 最低实时
─────────────────
  -20 ← 最高普通
  ...
  19  ← 最低普通
  SCHED_OTHER（nice 值）
```

**实时优先级高于所有普通进程**：一个 SCHED_FIFO 优先级 1 的进程比 SCHED_OTHER nice -20 的进程优先级高。

### SCHED_FIFO 行为

```
SCHED_FIFO 优先级 50 运行中:
  → 持续运行，直到：
    a) 主动 sched_yield() / 阻塞
    b) 更高优先级实时进程就绪
    c) 被信号中断
  → 不会被同优先级或更低优先级打断
  → 醒来后恢复运行（如果仍是最高）
```

### SCHED_RR 行为

```
SCHED_RR 优先级 50 运行中:
  → 运行一个时间片（默认 100ms，可查 sched_rr_get_interval）
  → 时间片用完 → 排到同优先级队列尾部
  → 轮到下一个同优先级 SCHED_RR 线程
```

### 核心 API

| 函数 | 说明 |
|------|------|
| `sched_setscheduler(pid, policy, param)` | 设置策略和优先级 |
| `sched_getscheduler(pid)` | 获取策略 |
| `sched_setparam(pid, param)` | 设置优先级 |
| `sched_getparam(pid, param)` | 获取优先级 |
| `sched_get_priority_max(policy)` | 最大优先级（99） |
| `sched_get_priority_min(policy)` | 最小优先级（1） |
| `sched_rr_get_interval(pid, &ts)` | SCHED_RR 时间片 |
| `nice(inc)` | 调整 nice 值（SCHED_OTHER） |
| `setpriority(PRIO_PROCESS, 0, nice)` | 设置 nice 值 |
| `sched_yield()` | 主动让出 CPU |

### 权限要求

| 操作 | 权限 |
|------|------|
| 设置实时策略 | `CAP_SYS_NICE` 或 RLIMIT_RTPRIO |
| 提高优先级 | `CAP_SYS_NICE` |
| 设置 nice < 0 | `CAP_SYS_NICE` |
| 设置 nice >= 0 | 普通用户可设 |

## HFT / 嵌入式关联

- **SCHED_FIFO + CPU 隔离**：HFT 标准配置——策略线程 SCHED_FIFO 优先级 99，绑定到隔离核心（`isolcpus`）
- **mlockall**：配合 `mlockall(MCL_CURRENT | MCL_FUTURE)` 防止页面换出导致延迟抖动
- **PREEMPT_RT**：实时内核补丁，减少调度延迟到微秒级
- **嵌入式 RTOS**：FreeRTOS/VxWorks 有固定优先级抢占调度，类似 SCHED_FIFO
- **避免 SCHED_RR**：HFT 不用轮转，策略线程独占核心

## 代码示例

```c
#include <sched.h>
#include <stdio.h>
#include <sys/mman.h>

void setup_realtime(int priority) {
    /* 锁定内存，防止换页 */
    mlockall(MCL_CURRENT | MCL_FUTURE);

    /* 设置 SCHED_FIFO + 优先级 */
    struct sched_param param;
    param.sched_priority = priority;  /* 1-99 */
    if (sched_setscheduler(0, SCHED_FIFO, &param) != 0) {
        perror("sched_setscheduler");
    }

    /* 查询 RR 时间片 */
    struct timespec ts;
    sched_rr_get_interval(0, &ts);
    printf("RR timeslice: %ld ms\n", ts.tv_nsec / 1000000);
}

/* 绑定 CPU（需 sched_setaffinity） */
void pin_cpu(int cpu) {
    cpu_set_t cpuset;
    CPU_ZERO(&cpuset);
    CPU_SET(cpu, &cpuset);
    sched_setaffinity(0, sizeof(cpuset), &cpuset);
}
```

## 代码自测

<details>
<summary>1. SCHED_FIFO 和 SCHED_RR 的区别？HFT 用哪个？</summary>

- **SCHED_FIFO**：同优先级线程按 FIFO 运行，不被同优先级打断（除非主动让出）
- **SCHED_RR**：同优先级线程轮转，每个线程有时间片限制

HFT 用 SCHED_FIFO：策略线程独占 CPU 核心，不被同优先级线程打断，保证最低延迟。配合 `isolcpus` 隔离核心，策略线程是唯一可运行线程。
</details>

<details>
<summary>2. 普通进程可以设置 SCHED_FIFO 吗？</summary>

默认不行。设置实时调度策略需要 `CAP_SYS_NICE` 能力（通常是 root 或通过 capabilities 授权）。也可以通过 `RLIMIT_RTPRIO` 限制非 root 用户设置实时优先级的上限。现代 Linux 还支持 `systemd` 的 `LimitRTPRIO` 指令。
</details>

<details>
<summary>3. SCHED_FIFO 优先级 1 和 nice -20 哪个优先级高？</summary>

SCHED_FIFO 优先级 1 更高。实时调度策略（SCHED_FIFO/SCHED_RR）的优先级范围（1-99）始终高于普通调度策略（SCHED_OTHER）的 nice 值。即使 nice -20（最高普通优先级），也会被最低实时优先级（1）的 SCHED_FIFO 进程抢占。
</details>
