## 本节讲什么

四组调用作用于**已有映射**（mmap / 堆 / 栈均可）：改保护、锁 RAM、查驻留、给访问提示。通用约束：`addr` 页对齐、`length` 向上取整。

---

## 要点

### 四组调用速览表（含 v6.6 实测要点）

| 调用 | 作用 | 权限/限额 | 关键实测结论（v6.6） |
|------|------|-----------|---------------------|
| `mprotect` | 改 PTE 的 rwx | 不许超 fd 打开模式（`EACCES`） | 违例 = SIGSEGV（同步信号，可 sigsetjmp 捕获） |
| `mlock`/`mlockall` | 禁换出 + 立即预填充 | `RLIMIT_MEMLOCK` / `CAP_IPC_LOCK` | **超限返回 `ENOMEM` 不是 `EPERM`**；fork 继承、exec 解锁；mlock 区 `msync(MS_INVALIDATE)`→`EBUSY` |
| `mincore` | 驻留快照（PTE present 口径） | 无权限文件映射**静默返回 0**（防侧信道） | 零页 mincore=1 但 **Rss=0**（口径差）；瞬时非原子，只能诊断 |
| `madvise` | 访问模式提示 | 多数可忽略；DONTNEED 确定语义 | 匿名 DONTNEED **读回 0**；文件 PRIVATE DONTNEED **读回文件内容**（丢弃 COW 修改） |

### 反直觉真相（易错点 TOP 4）

1. **`mlock` 超限是 `ENOMEM`**——`can_do_mlock` 拒绝才是 `EPERM`；两个错误码对应「无资格」和「超量」两道不同的关。
2. **零页口径打架**——`mincore` 说驻留（present），`Rss` 不认账（零页全系统共享一份）；「读触碰的匿名页」两个指标必然不一致。
3. **`MADV_DONTNEED` 匿名≠文件**——匿名丢成 0，文件 PRIVATE 丢成文件原内容（COW 副本没了）；把两者混为一谈会在「重置缓冲」场景写出让策略读到脏数据的 bug。
4. **`MADV_FREE` 不丢数据**——lazyfree 只在内存压力时真丢；需要确定性清零只能 DONTNEED。

### Ch50 × Ch49 联动关系图

```
mmap(2) 建立映射（Ch49）
   │
   ├── mprotect ──→ 改 rwx（guard 页 / W^X / JIT）
   ├── mlock     ──→ 钉住物理页（HFT 延迟治理第 1 步）
   ├── mincore   ──→ 验收「真的驻留了吗」
   ├── madvise   ──→ 预读开关 / THP / DONTNEED 重置
   └── msync(Ch49.5) ←─ mlock 联动：MS_INVALIDATE 遇 VM_LOCKED = EBUSY
```

## HFT / 嵌入式关联

| 路线 | 工具链组合 |
|------|-----------|
| 嵌入式 | `MAP_POPULATE`(Ch49) 预填充 → `mincore` 验收 → `PROT_READ` 固化配置区；RAM 紧张时 `madvise(DONTNEED)` 归还大缓冲 |
| HFT | 启动序：`mlockall(MCL_CURRENT\|MCL_FUTURE)` + `madvise(MADV_HUGEPAGE)` 热缓冲 → `mincore` 全 1 验收 → 运行期 `PROT_NONE` guard + 每周期 `MADV_DONTNEED` 重置 |

## 自测题

**题目（综合）：** 用一章四组调用设计「HFT 热缓冲上线检查清单」。

<details>
<summary>参考答案</summary>

① `mlockall(MCL_CURRENT|MCL_FUTURE)`（或对缓冲逐区 `mlock`）——消除换出毛刺；② `madvise(MADV_HUGEPAGE)` 候选 THP（配合内核 `madvise` 模式）；③ 遍历缓冲 `mincore` 断言全 1——验收驻留；④ 缓冲边界外放 `PROT_NONE` guard 页（`mprotect`）——越界秒杀；⑤ 周期重置用 `madvise(MADV_DONTNEED)` + 重新 populate（注意锁页需 `MADV_DONTNEED_LOCKED`）；⑥ 监控线：驻留率下降或 `msync(MS_INVALIDATE)` 突然 `EBUSY` 变化 = 内存布局被动过的信号。

</details>
