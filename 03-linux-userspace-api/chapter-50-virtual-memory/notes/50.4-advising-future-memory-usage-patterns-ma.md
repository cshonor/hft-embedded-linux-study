## 本节讲什么

`madvise` 向内核**描述未来的访问模式**，内核据此调整预读/回收/布局策略。三个灵魂问题：

1. 提示的约束力？（**内核可忽略**——这不是命令，是 advice；只有 `MADV_DONTNEED` 等少数几个有确定语义）
2. 最危险也最有用的是哪个？（`MADV_DONTNEED`：匿名映射的**数据直接丢弃**，读回全 0）
3. `MADV_FREE` 和 `MADV_DONTNEED` 什么区别？（FREE 是「可反悔的丢弃」，内核保留内容直到内存紧张才真丢）

```c
#include <sys/mman.h>
int madvise(void *addr, size_t length, int advice);
/* addr 页对齐；length 向上取整；作用于 [addr, addr+len) 覆盖的映射 */
```

## 要点

### advice 全表（POSIX + Linux 扩展）

| advice | 语义 | 约束力 |
|--------|------|--------|
| `MADV_NORMAL` | 默认行为（恢复） | 弱 |
| `MADV_RANDOM` | 关闭/减弱预读（随机访问，预读是浪费） | 弱（改 readahead 窗口） |
| `MADV_SEQUENTIAL` | 加倍预读 + 读完即回收 | 弱 |
| `MADV_WILLNEED` | 立即预读到 page cache（异步启动读） | 弱 |
| `MADV_DONTNEED` | **丢弃页**（语义见下表，确定行为） | **强** |
| `MADV_FREE`（Linux） | 标记可丢弃：内容保留到内存紧张才真丢；期间再写则取消标记 | 中 |
| `MADV_DONTDUMP`/`DO_DUMP` | 从 core dump 排除/包含 | 强 |
| `MADV_HUGEPAGE`/`NOHUGEPAGE`（Linux） | 对区间启用/禁用 THP | 中 |
| `MADV_REMOVE`（Linux） | 共享内存/tmpfs：截断「洞」 | 强 |
| `MADV_POPULATE_READ/WRITE`（5.14+） | 主动预填充（等价触碰但不真的写数据） | 强 |

### ⭐ MADV_DONTNEED 三种映射的确切语义（实测验证）

| 映射类型 | DONTNEED 之后 | 再读的内容 |
|----------|---------------|------------|
| 匿名 PRIVATE | **私有数据永久丢弃**，页释放，PTE 清空 | **全 0**（重新缺页→零页） |
| 文件 PRIVATE | **私有修改丢弃**，页释放，PTE 指回…不，PTE 清空 | **文件当前内容**（重新缺页从 page cache 读） |
| 文件 SHARED | 脏页按正常路径回写后页可回收，PTE 清空 | 文件内容（重读 page cache/磁盘） |

实测证据（WSL Ubuntu，2026-09-05，`gcc -O2 -Wall -Wextra` 零告警）：

```
匿名：全写后 mincore = [1,1,1,1]
      MADV_DONTNEED 后 mincore = [0,0,0,0]，q[0]=0x00          ← 数据消失 ✓
文件 PRIVATE：改 'Z' 后 f[0]='Z'
      DONTNEED 后 f[0]='O'                                      ← 私有修改丢弃 ✓
```

### 内核路径（v6.6 实测核验）

```
madvise(2)
 └─ do_madvise()                          mm/madvise.c:1407
     ├─ madvise_need_mmap_write():50      多数 advice 只需 read_lock，DONTNEED 等才升级写锁
     └─ 按 advice 分发：
         ├─ MADV_DONTNEED → madvise_dontneed_free():859
         │     └─ zap_page_range_single():825   ← 真正拆 PTE、释放页
         ├─ MADV_FREE → madvise_free_single_vma():768
         │     └─ madvise_free_pte_range():625  ← PTE 标记 lazyfree（页进 inactive list 等淘汰）
         ├─ MADV_WILLNEED → filemap 预读调度
         └─ MADV_HUGEPAGE → khugepaged 登记区间
```

### MADV_FREE vs MADV_DONTNEED（Linux 面试高频）

| 维度 | `MADV_FREE` | `MADV_DONTNEED` |
|------|-------------|-----------------|
| 立即效果 | PTE 清脏标记，页标记可回收 | PTE 立即拆除，页立即释放 |
| 读回内容 | **旧数据**（若还没被回收） | **全 0 / 文件原内容**（确定） |
| 内存紧张时 | 真丢弃（丢的是真页） | 已经丢了 |
| 再写入 | 清除 lazyfree 标记，继续用 | 正常缺页分配新页 |
| 典型场景 | malloc 实现归还堆（glibc tcache→arena→FREE） | 明确放弃（重置大缓冲、状态机清零） |

### 常见错误

- `advice` 非法（如 99）→ `EINVAL`（实测验证 ✓）
- 区间内含**未映射空洞** → `ENOMEM`（与 `munlock` 的「跳过空洞」不同，madvise 默认严格；只有部分 advice 用 `process_madvise` 风格的宽松遍历）
- 对 `MAP_LOCKED` 区间 `MADV_DONTNEED`：v6.6 引入 `MADV_DONTNEED_LOCKED`（允许拆锁页），普通 `DONTNEED` 对锁页直接拒绝

## HFT / 嵌入式关联

| 路线 | 要点 |
|------|------|
| 嵌入式 | `MADV_RANDOM` 关预读：flash 随机读场景避免无谓的读放大（NAND 页 4-16KB，预读一次就是一次真消耗）；`MADV_DONTNEED` 主动归还大缓冲省 RAM（比 munmap 温和——地址空间保留，随时可复用） |
| HFT | 行情缓冲复用三板斧：`madvise(MADV_DONTNEED)` 重置（下个周期读到的保证是零/新数据，防「脏数据残留」型策略 bug）；`MADV_HUGEPAGE` 对热大缓冲开 THP（2MB 页 → TLB miss 率骤降，见 [06.7 BPF 章](../../../06.7-bpf-observability/README.md) 的性能观测）；`MADV_SEQUENTIAL` 用于顺序落盘的审计日志区 |

**实测警示**：`MADV_DONTNEED` 重置的匿名页**读回 0**——如果策略代码假设「重置后数据不变」，生产上会出现只在内存压力下复现的灵异 bug（FREE 才有「暂时保留」语义）。

## 代码示例

```c

/* MADV_DONTNEED 双语义实测：匿名归零 + 文件 PRIVATE 丢弃修改
 * 实测（WSL Ubuntu，gcc -O2 -Wall -Wextra，2026-09-05）：
 *   全写后 mincore = [1,1,1,1]
 *   MADV_DONTNEED 后 mincore = [0,0,0,0]，q[0]=0x00
 *   文件 PRIVATE 改 'Z' 后 f[0]='Z'；DONTNEED 后 f[0]='O'
 *   madvise(99) = -1 errno=22(Invalid argument)
 */
#define _GNU_SOURCE
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <fcntl.h>
#include <errno.h>
#include <sys/mman.h>
#include <unistd.h>

int main(void)
{
    long pagesz = sysconf(_SC_PAGESIZE);
    size_t P = (size_t)pagesz;

    /* 匿名映射：DONTNEED 归零 */
    char *q = mmap(NULL, 4 * P, PROT_READ | PROT_WRITE,
                   MAP_PRIVATE | MAP_ANONYMOUS, -1, 0);
    if (q == MAP_FAILED) { perror("mmap q"); return 1; }
    memset(q, 0x5A, 4 * P);
    unsigned char vec[4];
    mincore(q, 4 * P, vec);
    printf("全写后 mincore = [%d,%d,%d,%d]\n",
           vec[0]&1, vec[1]&1, vec[2]&1, vec[3]&1);

    if (madvise(q, 4 * P, MADV_DONTNEED) != 0) { perror("madvise"); return 1; }
    mincore(q, 4 * P, vec);
    printf("DONTNEED 后 mincore = [%d,%d,%d,%d]，q[0]=0x%02x（预期 0x00）\n",
           vec[0]&1, vec[1]&1, vec[2]&1, vec[3]&1, (unsigned char)q[0]);

    /* 文件 PRIVATE：DONTNEED 丢弃私有修改 */
    int fd = open("/tmp/ch50_adv.dat", O_RDWR | O_CREAT | O_TRUNC, 0644);
    if (fd < 0) { perror("open"); return 1; }
    if (write(fd, "ORIG", 4) != 4) { perror("write"); return 1; }
    char *f = mmap(NULL, 4, PROT_READ | PROT_WRITE, MAP_PRIVATE, fd, 0);
    if (f == MAP_FAILED) { perror("mmap f"); return 1; }
    f[0] = 'Z';
    printf("文件 PRIVATE 改 'Z' 后 f[0]='%c'；", f[0]);
    if (madvise(f, 4, MADV_DONTNEED) != 0) { perror("madvise f"); return 1; }
    printf("DONTNEED 后 f[0]='%c'（预期 O：私有修改丢弃）\n", f[0]);

    /* 非法 advice */
    errno = 0;
    int r = madvise(q, P, 99);
    printf("madvise(99) = %d errno=%d(%s)，预期 -1/EINVAL\n",
           r, errno, r ? strerror(errno) : "OK");

    munmap(q, 4 * P);
    munmap(f, 4);
    close(fd);
    unlink("/tmp/ch50_adv.dat");
    return 0;
}
```

## 自测题

**题目 1（选择）：** `MAP_PRIVATE` 文件映射，写脏了 3 页，`madvise(MADV_DONTNEED)` 后再读，内容是？

A. 修改后的数据　B. 全 0　C. 文件当前内容　D. 未定义

<details>
<summary>参考答案</summary>

**C**。DONTNEED 拆掉 COW 副本页的 PTE 并释放页，再读触发缺页从 page cache 读**文件当前内容**——不是 0（0 是匿名映射的语义），也不是「未定义」。实测：改 'Z' → DONTNEED → 读回 'O'（文件原字面）。

</details>

**题目 2（判断）：** `MADV_FREE` 之后立刻读这段内存，内容必然是 0。

<details>
<summary>参考答案</summary>

错误。`MADV_FREE` 是 lazyfree：PTE 标记可回收但**内容保留**，在页真正被回收（内存压力）之前读到的仍是旧数据；期间任何写会取消标记。必然读 0 的是 `MADV_DONTNEED`。

</details>

**题目 3（应用）：** 行情处理进程每周期用 64MB 缓冲，周期结束想「清零重置」，工程师 A 提议 `memset(buf, 0, 64MB)`，B 提议 `madvise(buf, 64MB, MADV_DONTNEED)`，怎么选？

<details>
<summary>参考答案</summary>

DONTNEED 更优（三点）：① `memset` 要**写 64MB**（16384 次缺页 + 全部脏页进回写路径），DONTNEED 只是拆 PTE（µs 级批量操作）；② DONTNEED 立刻释放 16384 个物理页给系统，内存压力友好；③ 读回语义明确为 0。代价：下周期首次访问每页一次缺页（~µs × 页数）。若缓冲已 `mlock`，注意 v6.6 普通参数的 DONTNEED 会被拒绝（需 `MADV_DONTNEED_LOCKED`）；若不想付缺页代价且缓冲必须常驻，memset 仍是兜底——HFT 实务常在预热阶段两者都做（DONTNEED + 重新 populate + mlock）。

</details>
