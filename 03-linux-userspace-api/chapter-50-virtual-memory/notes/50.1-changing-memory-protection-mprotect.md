# 50.1 修改内存保护：mprotect()

> 源码核验：Linux v6.6 · `mm/mprotect.c`（`do_mprotect_pkey():690` · `change_protection():513` · `change_protection_range():483` · `change_pte_range():83`）

## 本节讲什么

`mprotect()` 修改**已有映射**（mmap 区 / 堆 / 栈均可）的保护属性。三个灵魂问题：

1. 改保护 = 改什么？（PTE 的 rwx 位，**不是**重新分配内存）
2. 什么能改、什么不能改？（不能超过映射后备的权限——只读 fd 映射不可加 `PROT_WRITE`）
3. 违反保护会怎样？（CPU 陷阱 → **SIGSEGV**，不是返回错误）

```c
#include <sys/mman.h>
int mprotect(void *addr, size_t length, int prot);
/* 返回 0 成功；-1 失败（errno: EACCES/EINVAL/ENOMEM/ENOTSUP） */
```

---

## 要点

### 参数规则

| 规则 | 说明 |
|------|------|
| `addr` **必须页对齐** | 否则 `EINVAL`（内核不做静默取整，munmap 同理） |
| `length` 内核向上取整到页 | 与 mmap 一致 |
| 作用于**任何已有 VMA** | mmap 区、`brk` 堆、栈、vDSO——只要在进程地址空间内 |
| 可跨多个 VMA | 一次调用覆盖的区间里夹着别的映射也照改（按 VMA 逐个处理） |

### prot 四位组合

| prot | 读 | 写 | 执行 | 典型用途 |
|------|----|----|------|----------|
| `PROT_NONE` | ❌ | ❌ | ❌ | guard 页、延迟分配区 |
| `PROT_READ` | ✅ | ❌ | ❌ | 只读配置、字符串常量区 |
| `PROT_READ\|PROT_WRITE` | ✅ | ✅ | ❌ | 普通数据 |
| `PROT_READ\|PROT_EXEC` | ✅ | ❌ | ✅ | 代码段（text） |
| `PROT_READ\|PROT_WRITE\|PROT_EXEC` | ✅ | ✅ | ✅ | JIT 生成期（现代系统尽量回避） |

### 权限天花板：不能超过后备权限

- 文件映射：`prot` 不得超过 `open()` 时的模式——`O_RDONLY` 打开的 fd，`mprotect` 加 `PROT_WRITE` → **`EACCES`**
- 匿名映射：天花板就是 `mmap` 时的 `prot`——匿名区无后备文件，但 mmap 后可以**放宽或收紧**吗？可以：匿名私有映射 `mprotect` 加 `PROT_EXEC` 通常成功（除非 SELinux/`mmap_min_addr` 等 LSM 限制）
- **W^X 原则**（现代内核加固）：同一页尽量避免同时 Write+Execute——写完代码改 `R|X`，见下方 JIT 用法

### 内核路径（v6.6 实测核验）

```
mprotect(2)
 └─ do_mprotect_pkey()              mm/mprotect.c:690
     ├─ 遍历 [start,end) 内每个 VMA（vma_iterator）
     ├─ 权限校验：prot & ~旧 vma 可写位？→ 文件映射查 MAY_WRITE → EACCES
     └─ mprotect_fixup() → change_protection()      mm/mprotect.c:513
         └─ change_protection_range()                mm/mprotect.c:483
             └─ change_pte_range()                   mm/mprotect.c:83
                 ├─ 逐 PTE 改 prot 位（pte_modify）
                 ├─ 脏页记账：VM_SHARED 可写映射改只读时标记 dirty_accountable
                 └─ TLB flush：change_protection_end() → flush_tlb_range()
```

关键细节：`change_pte_range()` 只改**已建立的 PTE**；尚未缺页的地址在下次缺页时按新 `vm_page_prot` 建立。所以 `mprotect` 是「改 VMA 属性 + 顺手改现存 PTE + 刷 TLB」三件事。

### 错误码速查

| errno | 触发条件 |
|-------|----------|
| `EINVAL` | addr 未页对齐 / prot 非法 / 区间不在任何映射内（部分实现） |
| `EACCES` | 要求的权限超过 fd 打开模式（文件映射） |
| `ENOMEM` | 内核内部结构分配失败 / 区间不是进程映射 |
| `ENOTSUP` | 文件系统不支持（个别 fs） |

---

## HFT / 嵌入式关联

| 路线 | 要点 |
|------|------|
| 嵌入式 | JIT 固件：`PROT_READ\|PROT_WRITE` 写码 → `mprotect` 改 `PROT_READ\|PROT_EXEC` 执行，现代强制 **W^X** 防注入；只读配置区 `PROT_READ` 防误写（违例立刻 SIGSEGV 而不是悄悄破坏） |
| HFT | 订单簿共享区在「快照读」阶段设 `PROT_READ`，防策略代码误写关键数据；热路径代码段 `PROT_READ\|PROT_EXEC` + W^X 加固；`PROT_NONE` guard 页夹住热缓冲，越界访问**第一时间**报 SIGSEGV 而不是踩坏邻居 |

## 代码示例

```c

/* mprotect 三段式：PROT_NONE 触发 SIGSEGV → 恢复 RW 写入成功
 * 实测（WSL Ubuntu，gcc -O2 -Wall -Wextra，2026-09-05）：
 *   步骤1 PROT_NONE 写访问……捕获 SIGSEGV ✓
 *        mprotect 恢复 RW 后写入成功 p[0]=3
 */
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <signal.h>
#include <setjmp.h>
#include <errno.h>
#include <sys/mman.h>
#include <unistd.h>

static sigjmp_buf jb;
static void segv_handler(int sig) { (void)sig; siglongjmp(jb, 1); }

int main(void)
{
    long pagesz = sysconf(_SC_PAGESIZE);
    char *p = mmap(NULL, (size_t)pagesz, PROT_READ | PROT_WRITE,
                   MAP_PRIVATE | MAP_ANONYMOUS, -1, 0);
    if (p == MAP_FAILED) { perror("mmap"); return 1; }
    p[0] = 1;                                  /* 先写一次（触发缺页分配） */

    signal(SIGSEGV, segv_handler);
    if (mprotect(p, (size_t)pagesz, PROT_NONE) != 0) {
        perror("mprotect NONE"); return 1;
    }
    printf("步骤1 PROT_NONE 写访问……");
    fflush(stdout);
    if (sigsetjmp(jb, 1) == 0) {
        p[0] = 2;                              /* 违反 PROT_NONE → SIGSEGV */
        printf("写入成功（异常！）\n");
    } else {
        printf("捕获 SIGSEGV ✓\n");
    }

    if (mprotect(p, (size_t)pagesz, PROT_READ | PROT_WRITE) != 0) {
        perror("mprotect RW"); return 1;
    }
    p[0] = 3;                                  /* 恢复后写入正常 */
    printf("     mprotect 恢复 RW 后写入成功 p[0]=%d\n", p[0]);

    munmap(p, (size_t)pagesz);
    return 0;
}
```

**为什么用 `sigsetjmp` 而不是 `setjmp`**：SIGSEGV 是同步信号，handler 里 `siglongjmp` 跳出后内核已把栈上的信号帧清理；`sigsetjmp(…, 1)` 同时保存被阻塞的信号掩码，防止 SIGSEGV 在 handler 期间被屏蔽后不再递送。

## 自测题

**题目 1（选择）：** `mprotect(p, len, PROT_READ)` 对一个 `MAP_SHARED` 可写映射调用后，已写的脏页会怎样？

<details>
<summary>参考答案</summary>

脏页记账被保留。`change_pte_range()`（mm/mprotect.c:83）处理 VM_SHARED 可写映射降权时会标记 `dirty_accountable`，把「PTE 曾可写期间产生的脏」正确传给反向映射，保证后续回写不丢数据。

</details>

**题目 2（判断）：** 匿名映射 `mmap` 时只给了 `PROT_READ`，之后可以用 `mprotect` 加上 `PROT_WRITE`。

<details>
<summary>参考答案</summary>

可以。匿名映射没有后备文件，不存在「超过 fd 打开模式」的天花板；`mprotect` 直接改 VMA 属性。但文件映射不行——`O_RDONLY` 的 fd 映射加写权限返回 `EACCES`。

</details>

**题目 3（踩坑）：** 以下代码在 ARM64 嵌入式 Linux 上运行，为什么可能直接崩溃？

```c
void *code = mmap(NULL, 4096, PROT_WRITE, MAP_PRIVATE|MAP_ANONYMOUS, -1, 0);
memcpy(code, trampoline, sizeof(trampoline));
((void(*)(void))code)();
```

<details>
<summary>参考答案</summary>

映射只有 `PROT_WRITE` 没有 `PROT_EXEC`，跳转执行触发 SIGSEGV。修正：写完代码后 `mprotect(code, 4096, PROT_READ|PROT_EXEC)` 再执行（W^X 模式）。另外 ARM64 指令缓存与数据缓存不连贯（VIPT），JIT 还需要缓存同步（用户态通常由 `__builtin___clear_cache` 处理），这是嵌入式与 x86 的显著差异。

</details>
