# 55.4 Mandatory Locking

> 本章：[TLPI 第 55 章](../README.md)

## 本节讲什么

强制锁（mandatory locking）是 Linux 的一种文件锁机制，通过设置 setgid 位且清除执行位来启用。与建议锁不同，强制锁会阻止其他进程的 `open()`/`read()`/`write()` 操作。

## 要点

### 启用强制锁

```bash
# 文件设置 setgid + 无组执行位
chmod g+s,g-x file
# ls -l 显示: -rw-r-Sr--
# ^^^ 大写 S 表示 setgid 但无执行位 = 强制锁启用
```

### 强制锁 vs 建议锁

| 特性 | 建议锁 (advisory) | 强制锁 (mandatory) |
|------|------------------|---------------------|
| 获取方式 | `fcntl(F_SETLK)` | `fcntl(F_SETLK)` |
| 启用条件 | 无 | setgid+无组执行 |
| 阻止 open() | 否 | 是 |
| 阻止 read/write | 否（仅锁本身） | 是 |
| 端口性 | POSIX 标准 | Linux 特有 |
| 推荐 | 是 | 不推荐 |

### 强制锁行为

```
进程 A: flock(F_SETLK, 写锁)  ← 获取写锁
进程 B: open(file, O_WRONLY) ← 被阻塞（强制锁）
进程 C: read(fd, ...)         ← 被阻塞（强制锁）
进程 A: flock(F_UNLCK)        ← 释放
进程 B/C: 继续执行
```

### 限制与问题

1. **竞态条件**：在 open 和 lock 之间可能被其他进程操作
2. **死锁风险**：多个进程互相等待锁释放
3. **性能影响**：每次 I/O 都检查锁
4. **非标准**：部分文件系统不支持
5. **已不推荐**：现代使用文件租约（lease）或 `O_NONBLOCK`

## HFT / 嵌入式关联

- HFT 不推荐使用强制锁（性能差，死锁风险）
- 嵌入式场景如需强制保护，用 `O_EXCL` 或 `flock` 建议锁替代
- 了解强制锁原理有助于调试遗留系统

## 代码示例

```c
#include <fcntl.h>
#include <sys/file.h>
#include <unistd.h>
#include <stdio.h>

int main(int argc, char *argv[]) {
    int fd = open(argv[1], O_RDWR);
    /* 获取写锁（如果是强制锁文件则阻塞其他 I/O） */
    struct flock fl = {
        .l_type = F_WRLCK,
        .l_whence = SEEK_SET,
        .l_start = 0,
        .l_len = 0,  /* 0 = 到文件尾 */
    };
    fcntl(fd, F_SETLKW, &fl);
    printf("Locked %s\n", argv[1]);
    sleep(10);
    fl.l_type = F_UNLCK;
    fcntl(fd, F_SETLK, &fl);
    close(fd);
    return 0;
}
```

## 代码自测

<details>
<summary>为什么强制锁已不推荐使用？</summary>

强制锁存在多个问题：(1) open 和 lock 之间的竞态；(2) 可能导致死锁；(3) 性能开销大（每次 I/O 检查锁）；(4) 非标准，移植性差；(5) 某些文件系统不支持。现代替代方案包括文件租约（`F_SETLEASE`）、`O_NONBLOCK` + 轮询、或使用建议锁 + 应用层协调。

</details>
