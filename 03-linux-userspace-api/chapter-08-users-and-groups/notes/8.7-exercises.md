## 练习 1：UID → 用户信息（含三类失败的分辨）

编写程序，接受一个 UID 参数，打印**用户名、主组名**和该进程当前持有的**附属组数量**。要求：

- 使用 `getpwuid()` 查用户信息；
- 使用 `getgrgid()` 查主组名；
- **`/etc/group` 里查不到该 GID 时，程序不能当成"失败"退出**；
- UID 在 `/etc/passwd` 里没有记录时，同样不能当成"失败"退出。

> 提示：本节真正要练的不是 API 调用，而是**把三种情况分开**——① 记录不存在（不是错误）；② 组数据库不可用（也不是"这条不存在"）；③ 真正的系统错误。

### 参考实现

完整代码见 [`../code/ex8_1_uid_info.c`](../code/ex8_1_uid_info.c)：

```c
/* ex8_1_uid_info.c —— Ch08 自测题 1 参考实现
 *
 * 给定一个 UID，打印：用户名、主组名、以及该进程当前持有的附属组。
 *
 * 关键点在于「三种失败要分开」：
 *   - UID 在 /etc/passwd 里没有记录  -> getpwuid 返回 NULL，errno 不变
 *   - /etc/group 里没有该 GID        -> getgrgid 返回 NULL，errno 不变
 *   - 真正的系统错误                 -> errno 被设成非 0
 * 把第一种当成「失败」退出是本类程序最常见的 bug。
 *
 * 编译：cc -Wall -Wextra -o ex8_1_uid_info ex8_1_uid_info.c
 * 运行：./ex8_1_uid_info [uid]        （不带参数则查当前进程的 uid）
 */
#define _DEFAULT_SOURCE
#include <errno.h>
#include <grp.h>
#include <pwd.h>
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>

int main(int argc, char *argv[])
{
    uid_t uid = (argc > 1) ? (uid_t) strtol(argv[1], NULL, 10) : getuid();

    /* ---- 第 1 步：查用户（errno 必须自己清零） ---- */
    errno = 0;
    struct passwd *pw = getpwuid(uid);
    if (pw == NULL) {
        if (errno == 0) {
            printf("UID %ld：/etc/passwd 里没有这条记录（这不算出错）\n",
                   (long) uid);
        } else {
            perror("getpwuid");
        }
        return 0;       /* 「查不到」不是程序失败，正常退出 */
    }

    printf("UID %ld -> 用户名 %s\n", (long) uid, pw->pw_name);
    printf("            注释   %s\n", pw->pw_gecos);
    printf("            家目录 %s\n", pw->pw_dir);
    printf("            壳     %s\n", pw->pw_shell);

    /* ---- 第 2 步：主组。来自 passwd 的 gid 字段 ---- */
    errno = 0;
    struct group *gr = getgrgid(pw->pw_gid);
    if (gr != NULL)
        printf("主组   %s(%ld)\n", gr->gr_name, (long) gr->gr_gid);
    else
        printf("主组   (%ld) —— /etc/group 里查不到该 GID（errno=%d）\n",
               (long) pw->pw_gid, errno);

    /* ---- 第 3 步：附属组。来自进程凭证，与上面的文件无关 ---- */
    int n = getgroups(0, NULL);
    if (n < 0) {
        perror("getgroups");
        return 1;
    }

    printf("附属组 %d 个", n);
    if (n > 0) {
        gid_t *gs = malloc((size_t) n * sizeof(gid_t));
        if (gs == NULL) {
            perror("malloc");
            return 1;
        }
        if (getgroups(n, gs) != n) {    /* 两次调用之间组数可能变，以第二次为准 */
            perror("getgroups");
            free(gs);
            return 1;
        }
        for (int i = 0; i < n; i++) {
            struct group *g = getgrgid(gs[i]);      /* 结果立即用掉，不留指针 */
            if (g != NULL)
                printf(" %s(%ld)", g->gr_name, (long) gs[i]);
            else
                printf(" ?(%ld)", (long) gs[i]);
        }
        free(gs);
    }
    putchar('\n');

    printf("主组 %ld 是否也在附属组里：%s\n", (long) pw->pw_gid,
           (n > 0) ? "看上面列表（内核不保证互斥）" : "列表为空，无从判断");
    puts("注：附属组由进程凭证携带，内核对它一无所知地放在 /etc/passwd 里 ——");
    puts("    真正把它塞进凭证的是 setgroups() / initgroups()，属 Ch9 §9.6。");
    return 0;
}
```

编译与运行：

```bash
gcc -O0 -Wall -Wextra -o ex8_1_uid_info ex8_1_uid_info.c
./ex8_1_uid_info 10240       # 一个存在的 uid
./ex8_1_uid_info 0           # 一个在 /etc/passwd 里不存在的 uid
```

实测输出（另在 Compiler Explorer 复核，gcc 13.3）：

```text
UID 10240 -> 用户名 ce
            注释   Not a real account
            家目录 /app
            壳     /bin/bash
主组   (10240) —— /etc/group 里查不到该 GID（errno=2）
附属组 1 个 ?(0)
主组 10240 是否也在附属组里：看上面列表（内核不保证互斥）
注：附属组由进程凭证携带，内核对它一无所知地放在 /etc/passwd 里 ——
    真正把它塞进凭证的是 setgroups() / initgroups()，属 Ch9 §9.6。
```

```text
UID 0：/etc/passwd 里没有这条记录（这不算出错）
```

### 解读

1. **`UID 0` 那一次是本题的核心考点**：进程自身 `uid=0`，但 `/etc/passwd` 里只有 `ce(10240)`，`getpwuid(0)` 返回 `NULL` 且 `errno=0`。程序打印一句人话后 `return 0` —— **「查不到」不是程序失败**。任何把这种情况当错误退出的实现，在精简容器里都会立刻翻车。
2. **`主组   (10240) —— /etc/group 里查不到该 GID（errno=2）`**：注意这里 `errno` **不是 0**，而是 `ENOENT`。原因是 `/etc/group` 这个文件本身不存在，`open()` 留下的 errno 透传了出来（机制见 [8.3 第五节](./8.3-group-file.md)）。所以本题的正确做法是：**只要 `getgrgid` 返回 `NULL` 就按「没有这个组」处理**，把 `errno` 打进日志而不是拿它做分支判断。
3. **`附属组 1 个 ?(0)`** —— 这个结果很有意思：`getgroups(0, NULL)` 返回 **1**，那一个附属组的 GID 是 **0**；而 `getgrgid(0)` 同样翻不出名字（没有 `/etc/group`），所以显示 `?`。这说明**附属组来自进程凭证，与 `/etc/group` 无关** —— 文件里没记录，进程依然持有它。
4. 最后两行注释是给读者的定位指引：**附属组的 API 属于 [Ch9 §9.6](../../chapter-09-process-credentials/README.md)**，本节只是"顺手看一眼"，不作展开。
5. 程序里 `free(gs)` 之前的所有 `getgrgid()` 结果都是**立即使用**的 —— 因为在 `free` 之后，那些 `struct group *` 指向的静态缓冲随时可能被下一次调用改写（[8.4](./8.4-retrieving-info.md)）。

## 练习 2：`/etc/shadow` 的必要性

解释为什么 `/etc/shadow` 的引入是必要的。如果没有 shadow 文件，会带来什么安全问题？

### 参考答案

**没有 shadow 时**：

1. `/etc/passwd` **必须全局可读** —— `passwd(5)`："It should have read permission allowed for all users (many utilities, like `ls(1)` use it to map user IDs to usernames), but write access only for the superuser."。`ls -l` 要把 `uid` 显示成名字，映射表就躲不开人人可读。
2. 密文因此落在**任何用户都能读**的文件里 → 可以**离线**做字典 / 彩虹表攻击。攻击者不需要任何权限，也不受登录失败次数限制。
3. 无法表达口令生命周期策略。`passwd(5)` 只有 7 个字段，没有"上次修改日期""最长有效天数""过期前警告""账号过期日"的位置 —— 这正是 `shadow(5)` 需要有 **9 个字段**的原因。
4. `passwd(5)` 自己回顾了历史："In the good old days there was no great problem with this general read permission. Everybody could read the encrypted passwords, but **the hardware was too slow to crack a well-chosen password**, and moreover the basic assumption used to be that of a friendly user-community." —— 随着 CPU 变快、社区变大，这个假设两边都塌了。

**shadow 之后**：

1. 哈希只对 root（以及 `shadow` 组成员）可读。`shadow(5)`："This file **must not be readable by regular users** if password security is to be maintained." —— 注意这是**命令式**的要求，不是"建议"。
2. 策略字段齐备（第 3–8 字段）。
3. 即便 `/etc/passwd` 被读到，也只是用户名和 uid，没有可爆破的目标。

**⚠️ 但要注意一个常见误解**：**本容器（以及很多容器镜像）的 `/etc/shadow` 是 `0644`**（[8.2](./8.2-shadow-file.md) 实测）。这种情况下「引入 shadow」的安全收益**是零** —— 只是把密文从一个全局可读的文件搬到了另一个全局可读的文件。所以正确的表述是：**shadow 的安全性来自「权限位」，不是来自「文件叫什么名字」**。

## 练习 3：遍历所有用户

编写程序遍历 `/etc/passwd`，打印所有用户的 UID 和用户名。

### 参考答案

8.4 已经实测过原书配套程序 `t_getpwent.c`（输出只有一行 `ce       10240`，因为该文件只有 1 条记录；见 [8.4](./8.4-retrieving-info.md)）。在它基础上加一个过滤条件即可：

```c
/* 在 t_getpwent.c 的基础上加一个 uid 过滤（原书的 while 循环一字未改） */
#include <pwd.h>
#include <stdio.h>
#include <stdlib.h>

int main(int argc, char *argv[])
{
    uid_t floor = (argc > 1) ? (uid_t) strtol(argv[1], NULL, 10) : 0;
    struct passwd *pwd;

    while ((pwd = getpwent()) != NULL) {          /* 原书原样 */
        if (pwd->pw_uid < floor)
            continue;                              /* 常见的"只看普通用户"过滤 */
        printf("%-8s %5ld\n", pwd->pw_name, (long) pwd->pw_uid);   /* 原书原样 */
    }
    endpwent();
    exit(EXIT_SUCCESS);
}
```

> 这段**没有单独实跑**（它只是给已实测的 `t_getpwent.c` 加了一个 `if`），所以不带实测输出。要真跑，把 `t_getpwent.c` 的 `main` 换成上面这段即可。

### 要点

1. **`getpwent()` 是"顺序遍历"，必须配对 `endpwent()`**（`getpwent(3)`：遍历完应调用 `endpwent()` 以释放资源）。忘了它 = 一直持有一个打开的 `FILE *`。
2. **不要用循环里的 `getpwnam()` 代替 `getpwent()`**。`getpwnam()` 每次调用都要重新 `fopen` + 从文件头线性扫描（`nss/files-XXX.c` 的 `DB_LOOKUP` 宏）；`getpwent()` 保持流打开，是**唯一**适合"扫全表"的接口。
3. **`pwd->pw_name` 不能存**。它指向静态缓冲，下一次 `getpwent()` 就会把它改写。要留着就必须 `strdup`。
4. `%-8s %5ld` 这个格式来自原书，不是随手排的：名字左对齐 8 列、uid 右对齐 5 列。跟原书输出对齐时别改它。
5. 「只看普通用户」的常见判据是 `pw_uid >= 1000`（或 `>/etc/login.defs` 里的 `UID_MIN`）。**但这是发行版约定，不是内核或 libc 的约定** —— 为了可移植性，最好从 `login.defs` 读，或者干脆别过滤。

## 练习 4：复现并修复 `crypt()` 的别名漏洞

下面的认证函数「看起来和教科书一样」，但它有一个可被利用的漏洞。请说明漏洞的触发条件、复现它，并写出安全版本。

```c
static int verify(const char *password, const char *stored)
{
    return strcmp(crypt(password, stored), stored) == 0;
}
```

### 参考答案（含实测复现）

**触发条件不是"口令错"，而是「`stored` 与 `crypt()` 的返回值是同一块内存」。**

完整复现程序见 [`../code/c8_8_crypt_traps.c`](../code/c8_8_crypt_traps.c)：

```c
/* c8_8_crypt_traps.c —— 8.5：crypt() 的三个坑，其中一个是安全漏洞
 *
 * 坑 1：crypt() 和 getpwnam() 一样返回静态缓冲 —— 前一次的结果会被后一次改写
 * 坑 2：把 crypt() 自己返回的指针当「盐」再喂回去，crypt() 会失败返回 "*1"
 * 坑 3：此时 strcmp(返回值, stored) 两边指向同一块内存 → 恒等 → 任何口令都"通过"
 *
 * 编译：cc -Wall -Wextra -o c8_8_crypt_traps c8_8_crypt_traps.c -lcrypt
 */
#define _DEFAULT_SOURCE
#include <crypt.h>
#include <stdio.h>
#include <string.h>

/* ❌ 看起来和原书 Listing 8-2 一模一样，但存的是 crypt() 自己的返回值时就废了 */
static int bad_verify(const char *password, const char *stored)
{
    return strcmp(crypt(password, stored), stored) == 0;
}

/* ✅ 正确写法：盐拷成副本、先挡锁定账号、再挡 *0 与 *1 这两个失败哨兵 */
static int good_verify(const char *password, const char *stored)
{
    char salt[256];

    if (password == NULL || stored == NULL)
        return 0;
    if (snprintf(salt, sizeof salt, "%s", stored) >= (int) sizeof salt)
        return 0;                       /* 密文长得离谱，直接拒绝 */
    if (salt[0] == '!' || salt[0] == '*')
        return 0;                       /* 锁定 / 无口令 */

    char *got = crypt(password, salt);
    if (got == NULL)
        return 0;
    if (got[0] == '*')
        return 0;                       /* crypt 失败（*0 / *1），绝不当成匹配 */

    return strcmp(got, salt) == 0;
}

int main(void)
{
    /* ---- 坑 1：静态缓冲 ---- */
    char *h1 = crypt("pw-one", "$6$saltAAAA");
    char keep1[256];
    snprintf(keep1, sizeof keep1, "%s", h1);    /* 先拷一份 */

    char *h2 = crypt("pw-two", "$6$saltBBBB");
    printf("h1=%p  h2=%p  (%s)\n", (void *) h1, (void *) h2,
           h1 == h2 ? "同一块内存" : "不同内存");
    printf("h1 现在指向的内容 = %.22s...\n", h1);
    printf("调用前拷下来的 keep1 = %.22s...\n", keep1);

    /* ---- 坑 2 + 坑 3：别名导致「任何口令都通过」 ---- */
    char *stored_ptr = crypt("secret123", "$6$rounds=5000$abc");
    char stored_copy[256];
    snprintf(stored_copy, sizeof stored_copy, "%s", stored_ptr);

    printf("\nstored_ptr（crypt 静态缓冲）= %.30s...\n", stored_ptr);
    printf("stored_copy（副本）          = %.30s...\n", stored_copy);

    printf("\n[❌ bad_verify] 直接把 crypt 的返回值当 stored\n");
    printf("bad_verify(\"definitely-wrong\", stored_ptr) = %d   <- 错口令本该返回 0\n",
           bad_verify("definitely-wrong", stored_ptr));
    printf("此刻 stored_ptr 的内容变成了 = %s\n", stored_ptr);

    printf("\n[✅ good_verify] 用副本，且检查哨兵\n");
    printf("good_verify(\"secret123\", stored_copy)        = %d\n",
           good_verify("secret123", stored_copy));
    printf("good_verify(\"definitely-wrong\", stored_copy) = %d\n",
           good_verify("definitely-wrong", stored_copy));
    printf("good_verify(\"x\", \"!\")   （锁定账号）          = %d\n",
           good_verify("x", "!"));
    printf("good_verify(\"x\", \"*\")   （无口令）            = %d\n",
           good_verify("x", "*"));

    puts("\n一句话：认证代码里绝不能把 crypt() 的返回值再当盐喂回去；");
    puts("        也不能只看 strcmp 的结果，必须先排除 *0/*1 与 !/* 这两类哨兵。");
    return 0;
}
```

实测输出（另在 Compiler Explorer 复核，gcc 13.3）：

```text
h1=0x7009aa8ea0e0  h2=0x7009aa8ea0e0  (同一块内存)
h1 现在指向的内容 = $6$saltBBBB$NOcDoe/sX....
调用前拷下来的 keep1 = $6$saltAAAA$NZDX0Mh.I2...

stored_ptr（crypt 静态缓冲）= $6$rounds=5000$abc$yBlE3WPe8QG...
stored_copy（副本）          = $6$rounds=5000$abc$yBlE3WPe8QG...

[❌ bad_verify] 直接把 crypt 的返回值当 stored
bad_verify("definitely-wrong", stored_ptr) = 1   <- 错口令本该返回 0
此刻 stored_ptr 的内容变成了 = *1

[✅ good_verify] 用副本，且检查哨兵
good_verify("secret123", stored_copy)        = 1
good_verify("definitely-wrong", stored_copy) = 0
good_verify("x", "!")   （锁定账号）          = 0
good_verify("x", "*")   （无口令）            = 0
```

**失效链条**（`bad_verify("definitely-wrong", stored_ptr) = 1` 是怎么来的）：

1. `crypt()` 的返回值指向**静态缓冲**（`crypt(3)`："The return value points to **static data whose content is overwritten by each call**."），而 `stored_ptr` 恰好就是上一次 `crypt()` 的返回值 → **两者是同一块内存**；
2. 本次调用把 `stored_ptr` 当**盐**，但它不是合法盐格式 → libxcrypt 返回失败哨兵 **`*0`**，并**就地覆写**那块缓冲；
3. 若那块内存里原本就是 `*0`，libxcrypt 的 `make_failure_token()` 会返回 **`*1`**（源码：`if (setting && setting[0] == '*' && setting[1] == '0') output[1] = '1';`）；
4. `strcmp(返回的指针, stored)` —— 两边**指向同一块内存**，`strcmp(x, x) == 0` 恒真 → **返回 1**。

实测第 4 行 `此刻 stored_ptr 的内容变成了 = *1` 补上了最后一环。

**安全版本**必须四步俱全：

```c
static int good_verify(const char *password, const char *stored)
{
    char salt[256];

    if (password == NULL || stored == NULL)
        return 0;
    if (snprintf(salt, sizeof salt, "%s", stored) >= (int) sizeof salt)
        return 0;                       /* ① 密文长得离谱，拒绝 */
    if (salt[0] == '!' || salt[0] == '*')
        return 0;                       /* ② 先挡锁定 / 无口令 */

    char *got = crypt(password, salt);  /* ③ 用副本作盐，切断别名 */
    if (got == NULL)
        return 0;                       /* man 所述的失败 */
    if (got[0] == '*')
        return 0;                       /* ④ 再挡 *0 / *1 */

    return strcmp(got, salt) == 0;      /* 此时两边是两块不同的内存 */
}
```

实测四行结果：`1` / `0` / `0` / `0` —— 正确口令通过，错口令、锁定账号、无口令账号全部拒绝。

### 延伸

这道题背后是**三个独立的坑叠加**：

| # | 坑 | 单独出现的后果 |
|---|----|----------------|
| 1 | `crypt()` 返回静态缓冲 | 数据被改写（和 `getpwnam()` 一样） |
| 2 | 失败返回 `*0` 而非 `NULL`（与 man 不一致） | 只判 `NULL` 的实现会漏掉 |
| 3 | `*1` 是"输入已是 `*0`"的回环标记 | 与 ① 叠加 → **认证被绕过** |

任何一个单独都不致命，**叠起来就是一个安全漏洞**。所以最终写法要"四道闸门全关"，不能依赖对某个实现的观察。
