# 8.2 The Shadow Password File：`/etc/shadow`

## 本节讲什么

8.1 的结论是「`/etc/passwd` 必须全局可读」。那么密文放哪？这一节回答：

1. `/etc/shadow` 的**唯一硬要求**是什么（一句话）？
2. 9 个字段各管什么？
3. 第 2 字段的 5 种形态 —— `!` 和 `*` 到底差在哪？
4. 为什么实测里空字段读回来是 `-1` 而不是 `0`？
5. 本容器的 `/etc/shadow` 是 **0644** —— 这算什么？

## 要点

### 一、唯一的硬要求：一句话

`shadow(5)` DESCRIPTION 原文：

> `shadow` is a file which contains the password information for the system's accounts and optional aging information.
>
> **This file must not be readable by regular users if password security is to be maintained.**

来历见 `getspnam(3)` DESCRIPTION：

> Long ago it was considered safe to have encrypted passwords openly visible in the password file. When computers got faster and people got more security-conscious, this was no longer acceptable. Julianne Frances Haugh implemented the **shadow password suite** that keeps the encrypted passwords in the shadow password database (e.g., the local shadow password file `/etc/shadow`, NIS, and LDAP), **readable only by root**.

所以正确说法不是「`/etc/shadow` 通常只有 root 能读」，而是**「只有 root 能读」是它成立的前提**。权限一旦放宽，这个文件就退化成了一个「名字更长的 `/etc/passwd`」。

### 二、九个字段

`shadow(5)`："Each line of this file contains **9 fields**, separated by colons ("`:`")"。

| # | 字段 | `shadow(5)` 原文要点 |
|---|------|----------------------|
| 1 | `login name` | "It must be a valid account name, which exists on the system." |
| 2 | `encrypted password` | 见下一节（5 种形态） |
| 3 | `date of last password change` | "expressed as the number of days since 1970-01-01 00:00:00 UTC"；"**The value 0 indicates that the user must change their password the next time they log in**"；"An empty field means that password aging features are disabled." |
| 4 | `minimum password age` | "the number of days the user must wait before they can change their password again"；"An empty field and value 0 mean that there is no minimum password age." |
| 5 | `maximum password age` | "the number of days after which the user must change their password" |
| 6 | `password warning period` | "The number of days before a password expires ... during which the user is warned." |
| 7 | `password inactivity period` | 口令过期后**仍接受**的天数，之后必须找管理员 |
| 8 | `account expiration date` | "The date when the account expires"；"**account expiration differs from password expiration**: Account expiration prevents the user from logging in, whereas password expiration only prevents users from logging in with their password." |
| 9 | `reserved field` | "This field is reserved for future use."（`struct spwd` 里就是 `sp_flag`） |

> ⚠️ 第 3 字段的 `0` 是个陷阱："The value 0 **should not be used**"（第 8 字段）—— 在不同工具眼里它既可能表示「永不过期」也可能表示「1970-01-01 就过期了」。

### 三、第 2 字段的四种形态（`!` 是最需要记住的）

`shadow(5)` 原文逐条：

| 形态 | 含义 | 原文 |
|------|------|------|
| **空串** | **允许无口令登录** | "If the password field is empty, the user can log in without a password. However, some applications that read the `/etc/shadow` file might block access if the password field is empty." |
| 合法 `crypt()` 结果 | 正常口令 | "Refer to `crypt(3)` for details on how this string is interpreted." |
| **`!` 开头** | **账号被锁定**，且**原密文还留在后面** | "If the password field begins with an exclamation mark `!`, the password is locked. **The remaining characters on the line represent the password field before the password was locked.**" |
| 其它非法串（如 `*`） | 不能用 UNIX 口令登录 | "If the password field contains a string that is **not a valid result of `crypt(3)`**, for instance `!` or `*`, the user cannot use a UNIX password to log in. However, the user may log in the system by other means." |

第三行是本文件里信息量最大的一句：

- **锁定 = 在密文前面插一个 `!`**，所以 `usermod -L` / `passwd -l` 是**可逆**的，`-U` 把 `!` 删掉就恢复；
- **「锁定」这个状态里带着原密文**。于是如果 `/etc/shadow` 被普通用户读到，泄露的不只是"有人被锁了"，还有**他能解开的那份哈希**；
- 第四行的 "may log in by other means" 也很要紧 —— 锁的是**口令**这条路，不是账号本身（SSH key、`su`、`rsh` 都可能照常）。`passwd(5)` NOTES 说同一件事："the user will be unable to login using `login(1)`, but may still login using `rlogin(1)`, run existing processes and initiate new ones through `rsh(1)`, `cron(8)`, `at(1)`, or mail filters, etc."

### 四、`struct spwd` 与「空字段 = `-1`」

`getspnam(3)` 给的 `<shadow.h>` 定义：

```c
struct spwd {
    char          *sp_namp;   /* Login name */
    char          *sp_pwdp;   /* Encrypted password */
    long           sp_lstchg; /* Date of last change (days since 1970-01-01 UTC) */
    long           sp_min;    /* Min # of days between changes */
    long           sp_max;    /* Max # of days between changes */
    long           sp_warn;   /* # of days before password expires */
    long           sp_inact;  /* # of days after password expires until disabled */
    long           sp_expire; /* Date when account expires (days since 1970-01-01 UTC) */
    unsigned long  sp_flag;   /* Reserved */
};
```

**9 个字段一一对应**。而空字段在内存里是什么，`getspnam(3)` DESCRIPTION 里 `putspent()` 那句给了权威答案：

> The `putspent()` function writes the contents of the supplied `struct spwd *p` as a text line in the shadow password file format to stream. **String entries with value NULL and numerical entries with value `-1` are written as an empty string.**

**`-1` 就是「这个字段没写」的内存表示。** 所以判断策略时不能只看有没有 `0`：

```c
/* ✗ 错：把 -1 当成「0 天」→ 会算出「口令立刻过期」 */
if (sp->sp_max == 0) { /* 永不过期 */ }

/* ✓ 对：先分「没写」再分「写了 0」 */
if (sp->sp_max < 0)      { /* 字段为空：不检查 */ }
else if (sp->sp_max == 0) { /* 显式写了 0：由策略决定语义，别自己猜 */ }
```

### 五、API 家族与权限墙

| 函数 | 作用 | 备注 |
|------|------|------|
| `getspnam(name)` | 按名查一条 | 非 `_r` 版本 "may point to **static area**"（`getspnam(3)` RETURN VALUE） |
| `getspent()` / `setspent()` / `endspent()` | 顺序遍历 | `getspent(3)` 走 `setspent()` 隐式打开的文件 |
| `fgetspent(FILE *)` | 从**你给的**流读一条 | ← 测试时唯一能用的入口（和 8.1 的 `fgetpwent` 对应） |
| `sgetspent(const char *)` | 解析**一个字符串** | 连文件都不需要 |
| `putspent(const struct spwd *, FILE *)` | 反向往出写 | 就是上面那句 `-1` ↔ 空串规则的实现者 |
| `lckpwdf()` / `ulckpwdf()` | 加锁 / 解锁 | 15 秒拿不到就返回 -1 |
| `getspnam_r()` / `getspent_r()` / `fgetspent_r()` / `sgetspent_r()` | 可重入版 | glibc 2.19 起要 `_DEFAULT_SOURCE` |

错误码只有两个（`getspnam(3)` ERRORS）：

| errno | 含义 |
|-------|------|
| `EACCES` | "The caller does not have permission to access the shadow password file." |
| `ERANGE` | "Supplied buffer is too small." |

**关于 `lckpwdf()` 的局限，`getspnam(3)` 自己说得很直白：**

> Note that there is **no protection against direct access** of the shadow password file. **Only programs that use `lckpwdf()` will notice the lock.**

这句话解释了「权限位」为什么不可替代：锁是**协作式**的，`fopen("/etc/shadow")` 完全不理会它。既然锁拦不住人，那就只能靠「不是 root 根本打不开」。

## 代码

### c8_2 权限位、降权实验与 `!` / `*` 语义

完整程序见 [`../code/c8_2_shadow_file.c`](../code/c8_2_shadow_file.c)：先 `stat()` 看权限位；再 `fork()` 出子进程降权复现「普通用户视角」；最后用 `fgetspent()` 解析一份合成 shadow，把 `!` / `*` 的语义跑出来。

```c
/* c8_2_shadow_file.c —— 8.2：为什么密文要搬到 /etc/shadow
 *
 * 三件事一起做：
 *   1. stat() 看 /etc/shadow 的权限位（密文只给 root + shadow 组）
 *   2. 以 root 读一次；再 fork 出子进程 setuid() 降权到普通账号读一次，
 *      把「普通用户读不到」从书上的一句话变成可复现的实验
 *   3. fgetspent() 解析一份合成 shadow，看字段含义与 ! / * 的锁定语义
 *
 * 编译：cc -Wall -Wextra -o c8_2_shadow_file c8_2_shadow_file.c
 */
#define _DEFAULT_SOURCE
#include <errno.h>
#include <pwd.h>
#include <shadow.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <sys/stat.h>
#include <sys/wait.h>
#include <unistd.h>

static void try_shadow(const char *who)
{
    errno = 0;
    FILE *fp = fopen("/etc/shadow", "r");
    printf("[%s] fopen(/etc/shadow) -> %s  errno=%d(%s)\n",
           who, fp ? "ok" : "NULL", errno, strerror(errno));
    if (fp != NULL)
        fclose(fp);

    errno = 0;
    struct spwd *sp = getspnam("ce");
    printf("[%s] getspnam(\"ce\")   -> %s  errno=%d(%s)\n",
           who, sp ? "non-NULL" : "NULL", errno, strerror(errno));
    if (sp != NULL)
        printf("[%s]     sp_pwdp=%s lstchg=%ld min=%ld max=%ld warn=%ld\n",
               who, sp->sp_pwdp, sp->sp_lstchg, sp->sp_min, sp->sp_max, sp->sp_warn);
}

int main(void)
{
    struct stat st;
    if (stat("/etc/shadow", &st) == 0) {
        printf("/etc/shadow mode=%04o uid=%ld gid=%ld size=%ld\n",
               (unsigned) (st.st_mode & 07777), (long) st.st_uid,
               (long) st.st_gid, (long) st.st_size);
    } else {
        perror("stat /etc/shadow");
    }

    try_shadow("root");

    struct passwd *pw = getpwnam("ce");
    if (pw == NULL) {
        puts("找不到 ce 账号，跳过降权实验");
        return 0;
    }

    printf("\n尝试降权到 %s(%ld) 复现「普通用户视角」…\n",
           pw->pw_name, (long) pw->pw_uid);

    fflush(stdout);                     /* fork 前刷缓冲，否则子进程会复制一份未 flush 的输出 */
    pid_t pid = fork();
    if (pid == 0) {
        if (setgid(pw->pw_gid) != 0 || setuid(pw->pw_uid) != 0) {
            printf("[child] setuid(%ld) 失败：errno=%d(%s)\n",
                   (long) pw->pw_uid, errno, strerror(errno));
            puts("[child] 评测容器跑在 user namespace 里，只映射了 uid 0，");
            puts("[child] 所以 setuid 到别的 uid 直接 EINVAL —— 这条实验在这里做不成。");
            puts("[child] 「普通用户读不到 shadow」的结论改由文件权限位 + man 5 shadow 说明。");
            fflush(stdout);             /* _exit 不 flush stdio */
            _exit(0);
        }
        printf("[child] 降权后 uid=%ld\n", (long) getuid());
        try_shadow("ce");
        fflush(stdout);
        _exit(0);
    }
    wait(NULL);

    /* ---- 合成一份 shadow，看字段与锁定语义 ---- */
    const char *sf = "/tmp/c8_shadow_demo";
    FILE *w = fopen(sf, "w");
    if (w != NULL) {
        fputs("alice:$6$abcdefgh$abc:19000:0:99999:7:14:20000\n"
              "bob:!:19000:0:99999:7:::\n"
              "carol:*:19000:0:99999:7:::\n", w);
        fclose(w);
    }

    puts("\n-- fgetspent() 解析合成 shadow --");
    FILE *f = fopen(sf, "r");
    struct spwd *sp;
    while (f != NULL && (sp = fgetspent(f)) != NULL) {
        const char *verdict = "正常";
        if (sp->sp_pwdp[0] == '!')
            verdict = "已锁定（! 开头）";
        else if (sp->sp_pwdp[0] == '*')
            verdict = "禁用（* 开头，无口令）";
        printf("%-6s pwdp=%-24s lstchg=%-6ld max=%-6ld inact=%-4ld expire=%-6ld %s\n",
               sp->sp_namp, sp->sp_pwdp, sp->sp_lstchg, sp->sp_max,
               sp->sp_inact, sp->sp_expire, verdict);
    }
    if (f != NULL)
        fclose(f);

    return 0;
}
```

编译与运行：

```bash
gcc -O0 -Wall -Wextra -o c8_2_shadow_file c8_2_shadow_file.c && ./c8_2_shadow_file
```

实测输出（另在 Compiler Explorer 复核，gcc 13.3）：

```text
/etc/shadow mode=0644 uid=0 gid=0 size=55
[root] fopen(/etc/shadow) -> ok  errno=0(Success)
[root] getspnam("ce")   -> non-NULL  errno=0(Success)
[root]     sp_pwdp=$1$rockyou$hty8SH9lK4mcCQXKENxaa1 lstchg=18723 min=0 max=99999 warn=7

尝试降权到 ce(10240) 复现「普通用户视角」…
[child] setuid(10240) 失败：errno=22(Invalid argument)
[child] 评测容器跑在 user namespace 里，只映射了 uid 0，
[child] 所以 setuid 到别的 uid 直接 EINVAL —— 这条实验在这里做不成。
[child] 「普通用户读不到 shadow」的结论改由文件权限位 + man 5 shadow 说明。

-- fgetspent() 解析合成 shadow --
alice  pwdp=$6$abcdefgh$abc          lstchg=19000  max=99999  inact=14   expire=20000  正常
bob    pwdp=!                        lstchg=19000  max=99999  inact=-1   expire=-1     已锁定（! 开头）
carol  pwdp=*                        lstchg=19000  max=99999  inact=-1   expire=-1     禁用（* 开头，无口令）
```

**解读**

1. `mode=0644` —— **这是确凿的配置错误**。`shadow(5)` 的要求是 "must not be readable by regular users"，而 0644 意味着任何用户都能读到 `$1$rockyou$hty8SH9lK4mcCQXKENxaa1`。这台机器的等价安全等级 = **完全没有 shadow**。生产环境上这一条要用配置管理钉死，不能靠人工 `chmod`。
2. `size=55` 与这条记录的字符数**正好相等**：`ce`(2) + `$1$rockyou$hty8SH9lK4mcCQXKENxaa1`(33) + `18723`(5) + `0`(1) + `99999`(5) + `7`(1) = 47，再加 8 个字段分隔冒号 = **55**。也就是说这份 `/etc/shadow` 的单行记录**末尾同样没有换行符**（和 8.1 的 `/etc/passwd` 一样）。解析器必须两种都吃。
3. `sp_pwdp = $1$rockyou$hty8SH9lK4mcCQXKENxaa1` —— 前缀 `$1$` 是 **MD5-crypt**，本容器上单核能跑 8910 次/秒（8.5 的实测表）。盐还被起名叫 `rockyou`（经典口令字典），基本等于明示「这份哈希是拿字典跑出来的」。这行输出就是我们把 0644 列为"确凿错误"的实证理由。
4. 降权实验**在这台机器上做不成**，输出如实报告了原因：`setuid(10240)` 返回 `EINVAL(22)`。原因是评测容器跑在 **user namespace** 里，只映射了 uid 0，内核不允许切到一个未映射的 uid。所以「普通用户读不到 shadow」这个结论**不能靠这段代码证明**，只能靠：① 文件权限位（第 1 行）；② `shadow(5)` 原文；③ `getspnam(3)` 的 `EACCES` 条款。**把做不成的实验如实写出来，比编一个漂亮输出有用得多。**
5. `bob` / `carol` 两行是本节的关键对照：`!` 和 `*` 都被 `fgetspent()` 原样读进 `sp_pwdp`，程序按首字符判定为「已锁定 / 禁用」。
6. 注意 `inact=-1  expire=-1` —— 这两个字段在文件里**是空的**（`bob:!:19000:0:99999:7:::`），读回来就是 `-1`，正是第四节那句 `putspent()` 规则的镜像。**空字段 ≠ 0 天。**

## HFT / 嵌入式关联

- **权限就是全部**。`lckpwdf()` 是协作式锁，`fopen()` 不认；所以 `/etc/shadow` 的防线只有文件权限位和「谁能当 root」。审计一件部署时，`stat -c %a /etc/shadow` 应该出现在 checklist 里，和「服务不能以 root 跑」并列。
- **`0644` 的 shadow 在容器镜像里非常常见**。基础镜像构建脚本用 `chmod -R 644`、或者把宿主机的 `/etc` 整个 COPY 进去，都会造成这个状态。**CI 里加一条断言成本极低**：
  ```bash
  # 非 root 组可读即视为错误
  [ "$(stat -c %a /etc/shadow)" = "640" ] || [ "$(stat -c %a /etc/shadow)" = "600" ]
  ```
- **`!` 是运维最爱的"临时停用"手段，但它不是禁用账号**。`shadow(5)` 和 `passwd(5)` 都说被锁的用户仍可能从其它路径进来。要真断掉，得同时处理 shell、SSH key、`/etc/securetty`、PAM 的 `account` 栈。
- **嵌入式**：BusyBox 的 `passwd`/`login` 可以走 `CONFIG_USE_BB_SHADOW`，也可以完全不用 shadow（密文留在 `/etc/passwd`）。读这类镜像时**先判断用的是哪套**：`/etc/shadow` 存在但只有 `root:x` 这种占位行时，真密文可能还在 `/etc/passwd` 里。
- **不要自己解析 `/etc/shadow`**。字段语义（尤其是 `-1` ↔ 空串、`0` 对第 3/第 8 字段含义不同）在 `getspnam(3)` 里，不在文件格式里；用 `fgetspent()` / `sgetspent()` 解析字符串是更省事的路径，而且 `putspent()` 能把结果原样写回去。
- **HFT 场景下大概率根本不该有 shadow**：交易节点用固定服务账号 + SSH key + 一次性镜像，口令登录通常直接关掉。此时正确的加固是**让 `/etc/shadow` 里没有任何合法 `crypt()` 结果**（全 `!` 或 `*`），而不是留一堆能登的账号。

## 自测题

<details>
<summary>1. <code>/etc/shadow</code> 是 <code>0644</code>，这算"宽松"还是"错误"？</summary>

**是错误，不是宽松。**

`shadow(5)` 的措辞是命令式的："This file **must not be readable by regular users** if password security is to be maintained." 换句话说，**「普通用户读不到」是这个文件能成立的先决条件**，不是一个可调的强度档位。

`0644` 的等价后果是本容器实测到的状态：任何一个能起进程的账号都能 `cat /etc/shadow`，把 `$1$rockyou$hty8SH9lK4mcCQXKENxaa1` 拿到手里做离线爆破（MD5-crypt 单核 8910 次/秒，见 [8.5](./8.5-password-encryption.md)）。此时引入 shadow 的全部安全收益归零 —— 只是把密文从一个全局可读的文件搬到了另一个全局可读的文件。

正确值：`600`（root:root）或 `640`（root:shadow，配合 `shadow` 组成员）。
</details>

<details>
<summary>2. 一个账号的密文是 <code>!$6$abc$...</code>，这个账号到底能不能登录？</summary>

**取决于登录路径，不是一个简单的"能/不能"。**

`shadow(5)` 对 `!` 的定义是："the password is **locked**. The remaining characters on the line represent the password field **before the password was locked**."

- **口令这条路：不能。** `!$6$...` 整体不是合法的 `crypt()` 结果，`crypt()` 会返回失败哨兵（8.5 实测为 `*0`），`strcmp` 永远不会相等。
- **其它路径：可能能。** `shadow(5)` 自己写了："the user **may log in the system by other means**"，`passwd(5)` NOTES 列了 `rlogin(1)` / `rsh(1)` / `cron(8)` / `at(1)` / mail filters，以及已有的进程。

实践结论：`!` 是**停用口令**，不是停用账号。要停用账号，改 shell + 清理 authorized_keys + 上 PAM `account` 策略。
</details>

<details>
<summary>3. <code>fgetspent()</code> 读回来 <code>sp_max == -1</code>，和 <code>sp_max == 0</code> 有什么不一样？</summary>

**`-1` 是"字段没写"，`0` 是"写了 0"。**

`getspnam(3)` 里 `putspent()` 的说明给出对应关系："numerical entries with value **`-1` are written as an empty string**"。所以 `-1` 是 libc 表示「文件里这段是空的」的内部约定。

`shadow(5)` 对 `maximum password age`（第 5 字段）说的是："**An empty field means that there are no maximum password age, no password warning period, and no password inactivity period**."

本容器实测就出现了这个值：`bob` 那行是 `bob:!:19000:0:99999:7:::`，两个空字段读回来 `inact=-1  expire=-1`。

写法上的直接影响：`if (sp->sp_max == 0) { /* 永不过期 */ }` 是错的 —— 它把「字段为空」误当成「0 天」。正确做法是先判 `< 0`。
</details>
