# 8.6 Summary

> 本章：[TLPI 第 08 章 — Users and Groups](./README.md)

## 本章回顾

### 密码数据库文件

| 文件 | 用途 | 权限 | 结构 |
|------|------|------|------|
| `/etc/passwd` | 用户基本信息 | 全局可读 | `name:passwd:uid:gid:comment:home:shell` |
| `/etc/shadow` | 密码哈希 | 仅 root | `name:hash:changed:min:max:warn:inactive:expire` |
| `/etc/group` | 组基本信息 | 全局可读 | `name:passwd:gid:member_list` |
| `/etc/gshadow` | 组密码 | 仅 root | 组密码哈希 |

### /etc/passwd 字段

```
root:x:0:0:root:/root:/bin/bash
 └─┘└┘└─┘└─┘└──────┘└──────┘└────────┘
  1  2   3   4    5       6        7

1. 用户名
2. 密码占位符（x → 实际在 /etc/shadow）
3. UID
4. GID（主组）
5. 备注（GECOS）
6. 主目录
7. 登录 shell
```

### /etc/shadow 字段

```
root:$6$xxx:19000:0:99999:7:::
 └─┘└──┘└────┘└─┘└────┘└┘
  1    2     3    4    5  6

1. 用户名
2. 密码哈希（$id$salt$hash，$6$=SHA-512）
3. 上次修改日期（距 1970-01-01 的天数）
4. 最小修改间隔天数
5. 最大有效天数
6. 过期前警告天数
7. 密码过期后宽限天数
8. 账号过期日期
```

### 密码哈希算法

| ID 前缀 | 算法 | 说明 |
|---------|------|------|
| `$1$` | MD5 | 过时，不安全 |
| `$5$` | SHA-256 | 可用 |
| `$6$` | SHA-512 | 推荐 |
| `$y$` | yescrypt | 现代推荐 |
| `$2b$` | bcrypt | 跨平台推荐 |

### 用户/组信息查询 API

| 函数 | 原型 | 说明 |
|------|------|------|
| `getpwuid(uid)` | `struct passwd *getpwuid(uid_t uid)` | 按 UID 查用户 |
| `getpwnam(name)` | `struct passwd *getpwnam(const char *name)` | 按用户名查 |
| `getpwuid_r` | 可重入版本 | 线程安全 |
| `getgrgid(gid)` | `struct group *getgrgid(gid_t gid)` | 按 GID 查组 |
| `getgrnam(name)` | `struct group *getgrnam(const char *name)` | 按组名查 |
| `getgrgid_r` | 可重入版本 | 线程安全 |
| `getgroups(size, list)` | 获取附属组列表 | 返回 GID 数组 |
| `setpwent()`/`getpwent()`/`endpwent()` | 遍历 /etc/passwd | 顺序扫描 |

### struct passwd

```c
struct passwd {
    char  *pw_name;    /* 用户名 */
    uid_t  pw_uid;     /* UID */
    gid_t  pw_gid;     /* 主 GID */
    char  *pw_gecos;   /* 备注 */
    char  *pw_dir;     /* 主目录 */
    char  *pw_shell;   /* 登录 shell */
    char  *pw_passwd;  /* 密码（通常为 "x"） */
};
```

### struct group

```c
struct group {
    char   *gr_name;   /* 组名 */
    gid_t   gr_gid;    /* GID */
    char  **gr_mem;    /* 成员用户名列表 */
    char   *gr_passwd; /* 组密码 */
};
```

## HFT / 嵌入式关联

- **权限分离**：HFT 系统不同组件用不同用户运行（行情用户/策略用户/风控用户），最小权限原则
- **嵌入式**：精简系统可能用 BusyBox 的简化 passwd/shadow，甚至硬编码用户
- **审计**：日志记录操作者 UID，通过 `getpwuid` 转换为用户名

## 衔接

- **Ch09** 进程凭证 — `setuid`/`setgid` 修改运行时 UID/GID
- **Ch40** 登录记账 — utmp/wtmp 记录用户登录
- **Ch38** 安全/特权程序 — 权限分离设计

## 代码自测

<details>
<summary>1. 为什么引入 /etc/shadow？</summary>

1. **安全性**：`/etc/passwd` 必须全局可读（很多程序需要查 UID→用户名），如果把密码哈希放在里面，任何用户都能获取哈希进行离线破解
2. **密码策略**：shadow 文件支持过期、警告、锁定等策略字段，passwd 无法表达
3. **引入时机**：早期 Unix 密码直接在 passwd 第二字段；随着 CPU 增强，离线破解变得可行，引入 shadow 将哈希隔离到仅 root 可读
</details>

<details>
<summary>2. getpwuid 返回的指针需要 free 吗？</summary>

不需要。`getpwuid` 返回的是静态分配的 `struct passwd` 指针，下次调用同一函数会被覆盖。因此**不是线程安全**的——多线程同时调用会导致竞争。线程安全版本是 `getpwuid_r`，需调用者提供缓冲区。
</details>

<details>
<summary>3. 附属组（supplementary groups）的作用？</summary>

一个用户可以属于多个组。主组在 `/etc/passwd` 的 GID 字段，附属组在 `/etc/group` 的成员列表中。进程启动时加载所有组到 supplementary groups 列表，用于权限检查。这样用户无需切换组即可访问多个组的资源。
</details>
