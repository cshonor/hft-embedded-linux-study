## 本章回顾

Linux 的「用户与组」被拆成**三个文本文件 + 两套查询 API + 一个哈希函数**：

```
        ┌──────────────────────────────────────────────┐
        │  文件（权威数据）                              │
        │  /etc/passwd   name:x:uid:gid:gecos:dir:sh   │
        │  /etc/group    grp:x:gid:m1,m2               │
        │  /etc/shadow   name:$id$salt$hash:...        │
        └──────────────────────────────────────────────┘
                          ↑↓ 查询 / 遍历 / 可重入
        ┌──────────────────────────────────────────────┐
        │  API（libc 的 NSS 层）                        │
        │  getpwnam/getpwuid/getpwent  + _r 版本        │
        │  getgrnam/getgrgid/getgrent  + _r 版本        │
        │  getspnam/getspent           + _r 版本        │
        └──────────────────────────────────────────────┘
                          ↑↓ 认证
        ┌──────────────────────────────────────────────┐
        │  crypt(key, salt) → $id$salt$hashed           │
        │  盐 = 算法标识 + 轮数 + 随机前缀               │
        └──────────────────────────────────────────────┘
```

**一句话主线**：`/etc/passwd` 必须全局可读（`ls -l` 要翻译 uid）→ 所以密文搬到 `/etc/shadow`（只 root 可读）→ 校验靠 `crypt(口令, 盐)` 与密文比对 → 运行时切换身份是 **Ch9** 的事，不是本章。

## 三个数据文件的字段

### `/etc/passwd` —— 7 字段

```
ce:x:10240:10240:Not a real account:/app:/bin/bash
 └┘└┘└───┘└───┘└────────────────┘└──┘└───────┘
 1  2   3    4          5          6      7
```

| # | 字段 | 含义 |
|---|------|------|
| 1 | `name` | 登录名 |
| 2 | `password` | `x`（密文在 shadow）/ `*`（禁止口令登录）/ `*NP*`（NIS+）/ **空串（无口令直接登录）** |
| 3 | `UID` | **0 = root** |
| 4 | `GID` | **主组**（附属组在 `/etc/group`） |
| 5 | `GECOS` | 纯注释，不参与认证 |
| 6 | `directory` | 用于初始化 `HOME` |
| 7 | `shell` | 用于初始化 `SHELL`；空则 `/bin/sh` |

### `/etc/group` —— 4 字段

```
rocket:x:500:alice,bob
 └───┘└┘└─┘└────────┘
   1   2  3     4
```

| # | 字段 | 含义 |
|---|------|------|
| 1 | `group_name` | 组名 |
| 2 | `password` | 组密码，基本恒为 `x` / `*` |
| 3 | `GID` | 组 ID |
| 4 | `user_list` | **附属组成员名单**，逗号分隔 |

> ⚠️ `group(5)` BUGS：引自 4.2BSD 的 "**no one seems to keep `/etc/group` up-to-date**"。第 4 字段是冗余信息，别当权威。

### `/etc/shadow` —— **9 字段**

```
ce:$1$rockyou$hty8SH9lK4mcCQXKENxaa1:18723:0:99999:7:::
└┘└──────────────────────────────┘└───┘└┘└───┘└┘└───────┘
 1                 2                 3   4   5   6    7 8 9
```

| # | 字段 | 含义 |
|---|------|------|
| 1 | `login name` | 必须是与 `/etc/passwd` 一致的有效账号名 |
| 2 | `encrypted password` | `$id$salt$hash` / `!` 前缀 = 锁定 / `*` = 无口令 / 空串 = 无口令可登 |
| 3 | `date of last password change` | 距 1970-01-01 的天数；**0 = 下次登录必须改** |
| 4 | `minimum password age` | 两次改口令的最小间隔 |
| 5 | `maximum password age` | 口令最长有效天数 |
| 6 | `password warning period` | 过期前提前警告天数 |
| 7 | `password inactivity period` | 过期后仍接受的宽限天数 |
| 8 | `account expiration date` | **账号**过期日（≠ 口令过期） |
| 9 | `reserved field` | `struct spwd` 里是 `sp_flag` |

> ⭐ **空数字字段读回来是 `-1`，不是 `0`**。依据 `getspnam(3)` 对 `putspent()` 的说明："numerical entries with value **-1 are written as an empty string**"。

**三个文件的关键对照**：

| | 权限 | 含密文 | 判定「不存在」的唯一依据 |
|---|------|--------|--------------------------|
| `/etc/passwd` | **644（必须全局可读）** | ❌ 只有 `x` 占位 | 该文件 |
| `/etc/group` | 644 | ❌ | 该文件（`passwd` 里的 gid 不算数） |
| `/etc/shadow` | **600 / 640（必须非 root 不可读）** | ✅ | 该文件 |

## 三个结构体

```c
/* <pwd.h>（getpwnam(3)） */
struct passwd {
    char  *pw_name;    /* username */
    char  *pw_passwd;  /* user password（shadow 系统里是 "x"） */
    uid_t  pw_uid;     /* user ID */
    gid_t  pw_gid;     /* group ID（主组） */
    char  *pw_gecos;   /* user information（注释，POSIX 未规定） */
    char  *pw_dir;     /* home directory */
    char  *pw_shell;   /* shell program */
};

/* <grp.h>（getgrnam(3)） */
struct group {
    char   *gr_name;   /* group name */
    char   *gr_passwd; /* group password */
    gid_t   gr_gid;    /* group ID */
    char  **gr_mem;    /* NULL-terminated array of pointers to names of members */
};

/* <shadow.h>（getspnam(3)） */
struct spwd {
    char          *sp_namp;   /* Login name */
    char          *sp_pwdp;   /* Encrypted password */
    long           sp_lstchg; /* 上次修改日（距 1970-01-01 的天数） */
    long           sp_min;    /* 最小改密间隔 */
    long           sp_max;    /* 最大有效天数 */
    long           sp_warn;   /* 过期前警告天数 */
    long           sp_inact;  /* 过期后宽限天数 */
    long           sp_expire; /* 账号过期日 */
    unsigned long  sp_flag;   /* Reserved */
};
```

三处必须记住的细节：

| 细节 | 说明 |
|------|------|
| `gr_mem` 是 **NULL 结尾数组** | 空组的 `gr_mem` 非 NULL，而是 `gr_mem[0] == NULL` |
| `sp_*` 的 **`-1` = 空字段** | 别把「没写」当成「0 天」 |
| `pw_gecos` **不在 POSIX** | 可移植性打折 |

## API 速查

| 需求 | passwd | group | shadow |
|------|--------|-------|--------|
| 按名字查 | `getpwnam()` | `getgrnam()` | `getspnam()` |
| 按 ID 查 | `getpwuid()` | `getgrgid()` | — |
| 顺序遍历 | `setpwent()` / `getpwent()` / `endpwent()` | `setgrent()` / `getgrent()` / `endgrent()` | `setspent()` / `getspent()` / `endspent()` |
| 从任意流读 | `fgetpwent(FILE *)` | `fgetgrent(FILE *)` | `fgetspent(FILE *)` |
| 从字符串读 | — | — | `sgetspent(const char *)` |
| 可重入版 | `getpwnam_r` / `getpwuid_r` / `getpwent_r` | `getgrnam_r` / `getgrgid_r` / `getgrent_r` | `getspnam_r` / `getspent_r` / `fgetspent_r` |
| 反向写出 | — | — | `putspent()` |

**返回值四条铁律**：

| # | 规则 | 依据 |
|---|------|------|
| 1 | 非 `_r` 版本返回**静态缓冲**，下一次同类调用即覆写，**不要 `free`、不要存** | `getpwnam(3)` RETURN VALUE；实测三个指针同地址 |
| 2 | 非 `_r` 版本「没找到」= `NULL` + `errno`；**调前必须先 `errno = 0`**；但 `errno` 取值标准未规定，可能是 `0` / `ENOENT` / `EBADF` / `ESRCH` / `EPERM` … | `getpwnam(3)` NOTES + ERRORS |
| 3 | `_r` 版本**返回错误号**，「不存在」= `s == 0` **且** `*result == NULL` | `getpwnam(3)` RETURN VALUE |
| 4 | `_r` 版本的 `ERANGE` 要**自己翻倍重试**；`sysconf(_SC_GETPW_R_SIZE_MAX)` 只是"建议值"，返回 -1 时**不改 `errno`** | `getpwnam(3)` DESCRIPTION；glibc `nss/getXXbyYY.c:139-158` |

## `crypt()` 速查

```c
#define _DEFAULT_SOURCE                 /* glibc ≥ 2.28；≤ 2.27 才用 _XOPEN_SOURCE */
#include <unistd.h>
#include <crypt.h>                      /* libxcrypt 下必须 */
char *crypt(const char *key, const char *salt);   /* 编译要 -lcrypt */
```

| 盐形态 | 算法 | 密文长度 | 摘要长度 |
|--------|------|----------|----------|
| `ab`（2 字符） | DES-crypt | **13** | — |
| `$1$…` | MD5-crypt | 29 | 22 |
| `$5$…` | SHA-256-crypt | 50 | 43 |
| `$6$…` | SHA-512-crypt | 93 | 86 |
| `$6$rounds=N$…` | SHA-512-crypt（自定义轮数） | 93 + 12 | 86 |
| `$2b$NN$…` | bcrypt（libxcrypt 扩展） | 60 | 31 |
| `$y$…` | yescrypt（libxcrypt 扩展） | 视实现 | 视实现 |

默认轮数 **5000**，clamp 到 **1000 … 999999999**（`crypt(3)` NOTES）。

**三种返回值**：

| 返回值 | 含义 | 处理 |
|--------|------|------|
| 正常密文 | 算出来了 | 与 `stored` 比较 |
| `NULL` | man 所述错误 | 判失败 |
| **`*0` / `*1`** | libxcrypt 的失败哨兵（`*0` = 盐无效；`*1` = 输入已是 `*0`） | **必须判失败** |

## 易错清单

本批全部有实测支撑：

1. **`/etc/passwd` 是 644 不是"配置不严"**，是设计使然（`ls -l` 要翻译 uid）；反过来 **`/etc/shadow` 是 644 就是确凿错误**。
2. **`pw_passwd` 是占位符 `x`**，拿它直接 `crypt()` 会得到 `*0`。认证前**必须**用 `sp_pwdp` 覆盖。
3. **非 `_r` 版本返回静态缓冲**，`getpwent` / `getpwnam` / `getpwuid` 共用同一块；「读一批存数组」直接是 bug。
4. **地址不可假设**：`fgetpwent` 连续三次同址，但 `getpwnam` 与 `getpwuid` 查同一用户却**不同址**。
5. **空数字字段 = `-1`**（不是 `0`）；`sp_max == 0` 与 `sp_max < 0` 语义完全不同。
6. **空组的 `gr_mem` 不是 NULL**，而是首元素为 NULL 的数组。写 `if (gr->gr_mem != NULL)` 会走错分支。
7. **`errno` 范式有条件**：后端起不开时（`/etc/group` 不存在）`errno` 会是 `ENOENT`，无法与「真的出错」区分。man 明确列了 `0 / ENOENT / EBADF / ESRCH / EPERM` 都可能。
8. **`_r` 版「不存在」= `s == 0` 且 `*result == NULL`**，只看 `s` 不够；且 `_r` **不动 `errno`**。
9. **`crypt()` 失败可能返回 `*0` 而不是 `NULL`**（libxcrypt），必须同时处理；`crypt()` 的返回值**绝不能当盐再喂回去**（会得到 `*1`，导致任何口令"通过"）。
10. **`userIdFromName("1000")` 不查库**；失败返回 `(uid_t)-1`（打印为 `4294967295`），而 `groupNameFromId` 失败返回 `NULL` —— 两个方向约定不同。
11. **DES 只吃口令前 8 字符**（不足补 0），盐只有 2 字符 / 4096 种 —— 这两个限制合起来判了 DES-crypt 的死刑。
12. **本章不涉及 RUID/EUID/SUID 与 `setuid()`** —— 那是 [Ch9](../../chapter-09-process-credentials/README.md)；**附属组的 API（`getgroups`/`setgroups`）也不在本章**，在 Ch9 §9.6。
13. **glibc ≥ 2.28 用 `_DEFAULT_SOURCE`**，不是老教程里的 `_XOPEN_SOURCE`；glibc 2.39 本身不带 `crypt()`，靠 libxcrypt，**要链 `-lcrypt`**。

## HFT / 嵌入式关联

| 场景 | 要点 |
|------|------|
| **热路径** | 绝不查账户库。`getpwuid` 是 O(n) 文件扫描，接 LDAP/SSSD 后是**网络往返**。日志里记**数字 uid**，翻译结果缓存 |
| **审计** | 「写日志时翻译成名字」会把 I/O 带进热路径；反过来翻译要用缓存 + 失效策略 |
| **权限排查** | 先问内核（`id` / `getgroups`），再看文件。`group(5)` BUGS 已经承认文件常年过期 |
| **HFT 加固** | 交易节点通常关掉口令登录；此时正确做法是让 `/etc/shadow` 里**没有任何合法 `crypt()` 结果**（全 `!` / `*`），而不是留一堆能登的账号 |
| **算法迁移** | `$1$` 一律当已泄露处理（8910 次/秒）；用 `pam_unix` 的 `sha512`/yescrypt + 下次登录重算 |
| **CI 断言** | `stat -c %a /etc/shadow` ∈ {600, 640}；第 2 字段非空；`/etc/passwd` 无空密码字段。三条都是低成本高收益 |
| **嵌入式** | BusyBox 的 `crypt` 支持面远小于 libxcrypt（常只有 DES / MD5）。构建机生成的 `$6$` 密文到板上可能直接 `*0` —— **统一算法或统一 libxcrypt** |
| **嵌入式精简** | 很多镜像根本没有 `/etc/group`，甚至没有 `/etc/shadow`。所有「gid → 组名」「uid → 用户名」的代码**必须能接受 NULL** |
| **FIPS** | `/proc/sys/crypto/fips_enabled` 非 0 时 DES-crypt 直接 `EPERM`；老系统切 FIPS 会导致**所有登录失败而报错只是"口令错"** |

## 自测题

<details>
<summary>1. 为什么引入 <code>/etc/shadow</code>？</summary>

**因为 `/etc/passwd` 必须全局可读。**

`passwd(5)` 原文："It should have read permission allowed for all users (many utilities, like `ls(1)` use it to map user IDs to usernames), but write access only for the superuser." —— `ls -l` 要把 `uid` 显示成名字，映射表就得人人可读。

于是：

1. **安全**：密文如果留在 `/etc/passwd`，任何用户都能拿到哈希做**离线**字典攻击（本容器 `$1$` 单核 8910 次/秒）。
2. **策略**：shadow 多了有效期/警告/宽限/锁定等字段（9 个字段），`passwd` 的 7 个字段表达不了。
3. **历史**：`passwd(5)` 自己回顾了原因 —— "In the good old days ... the hardware was too slow to crack a well-chosen password ... These days many people run some version of the shadow password suite, where `/etc/passwd` has an 'x' character in the password field, and the encrypted passwords are in `/etc/shadow`, which is readable by the superuser only."

详细推导见 [8.1](./8.1-passwd-file.md) 与 [8.2](./8.2-shadow-file.md)。
</details>

<details>
<summary>2. <code>getpwuid()</code> 返回的指针需要 <code>free</code> 吗？能存起来吗？</summary>

**不需要 `free`，也绝对不能存。**

`getpwnam(3)` RETURN VALUE："The return value may point to a **static area**, and may be overwritten by subsequent calls to `getpwent(3)`, `getpwnam()`, or `getpwuid()`. (**Do not pass the returned pointer to `free(3)`.**)"

实测证据（[8.4](./8.4-retrieving-info.md) `c8_4`）：`fgetpwent()` 三次返回**同一个地址** `0x7da0e6211240`，而且用第 1 个指针 `p1` 去读，读到的是第 2 条记录的 `"bob"`。

坑比"同一个指针"更深一层：`struct passwd` 里的 `char *` 字段也指向同一块静态内存，所以**即使按值拷贝结构体**，里面的指针仍会被下一次调用改掉。

要留住内容：立刻 `strdup` 需要的字段，或者改用 `getpwnam_r()`（多线程下也是必须的）。
</details>

<details>
<summary>3. 附属组（supplementary groups）怎么查？</summary>

**文件侧**：附属组是 `/etc/group` 第 4 字段 `user_list` 里的名字列表（`group(5)`："a list of the usernames that are members of this group, separated by commas"）。一个用户**可以出现在多行**。主组则是 `/etc/passwd` 第 4 字段，每人恰好一个。

**但「这个进程此刻持有哪些组」不是文件能回答的** —— 那是**进程凭证**。要问内核：

```c
#include <grp.h>
int n = getgroups(0, NULL);         /* 先问有几个 */
gid_t list[n];
getgroups(n, list);                 /* 再取出来 */
```

推进凭证的是 `setgroups()`（特权操作）和 `initgroups()`（按 `/etc/group` 把用户的全部组一次装好）。

⚠️ **这套 API 属于 [Ch9 §9.6 附属组 ID](../../chapter-09-process-credentials/README.md)**，本章只讲文件侧。另外 `group(5)` 的 BUGS 段提醒：文件里的名单常年过期，**判断"用户是否在某组"要以 `getgroups()` 的输出为准**。

<summary>4. 认证代码里比较密文时，最容易犯的两个错是什么？</summary>

**① 把 `crypt()` 的返回值当盐再喂回去；② 只判 `NULL` 不判 `*0` / `*1`。**

第 ① 个会造出真实漏洞（[8.5](./8.5-password-encryption.md) `c8_8` 实测）：

```c
/* ❌ 错口令 bad_verify("definitely-wrong", stored_ptr) 返回 1 —— 认证被绕过 */
return strcmp(crypt(password, stored), stored) == 0;
```

链条：`crypt()` 返回静态缓冲 → 本次调用把 `stored` 当盐、盐非法 → 返回 `*0` → **但若这块内存里原本就是 `*0`，libxcrypt 返回 `*1` 并就地覆写** → `strcmp` 两边同一块内存 → 恒等成立。

第 ② 个：`crypt(3)` 的 man 说 "On error, NULL is returned"，但实测（libxcrypt）返回的是字符串 `*0`。

正确的 `verify` 要四步俱全：

```c
if (password == NULL || stored == NULL) return 0;                 /* 空指针 */
if (snprintf(salt, sizeof salt, "%s", stored) >= (int) sizeof salt) return 0;  /* 超长 */
if (salt[0] == '!' || salt[0] == '*') return 0;                   /* 锁定 / 无口令 */
char *got = crypt(password, salt);                                /* 用副本作盐 */
if (got == NULL) return 0;                                        /* man 的失败 */
if (got[0] == '*') return 0;                                      /* 实测的 *0 / *1 */
return strcmp(got, salt) == 0;
```
</details>
