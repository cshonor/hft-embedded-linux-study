## 本节讲什么

前三节讲的是**文件**，这一节讲**接口**。同一个「查账号」需求，libc 给了三层能力：

1. **单条查**（`getpwnam` / `getpwuid` / `getgrnam` / `getgrgid`）—— 返回值语义怎么读？
2. **顺序遍历**（`setpwent` / `getpwent` / `endpwent` 家族）—— 怎么从头扫到尾？
3. **可重入版**（`getpwnam_r` 家族）—— 多线程、以及一个全新的错误：`ERANGE`。

再加两个只在「测试/迁移」时用得到的入口：`fgetpwent(FILE *)` / `fgetgrent(FILE *)`。

## 要点

### 一、`errno` 范式：怎么读，以及它什么时候失效

`getpwnam(3)` RETURN VALUE 原文：

> The `getpwnam()` and `getpwuid()` functions return a pointer to a `passwd` structure, or **NULL if the matching entry is not found or an error occurs**. **If an error occurs, errno is set to indicate the error. If one wants to check errno after the call, it should be set to zero before the call.**

于是有了这个范式：

```c
errno = 0;                          /* ← 必须先清零，否则读到的是上一次的残留 */
struct passwd *pw = getpwnam("nobody");
if (pw == NULL) {
    if (errno == 0)   /* 确实"没有这条记录" */;
    else              /* 出错了 */;
}
```

**但它有一个真实的失效点**：`errno` 在「没找到」时的取值**标准根本没有规定**。`getpwnam(3)` NOTES 原文：

> It does not call "not found" an error, and hence **does not specify what value errno might have in this situation**. But that makes it impossible to recognize errors. One might argue that according to POSIX errno should be left unchanged if an entry is not found. **Experiments on various UNIX-like systems show that lots of different values occur in this situation: 0, ENOENT, EBADF, ESRCH, EWOULDBLOCK, EPERM, and probably others.**

`getgrnam(3)` ERRORS 索性把 `ENOENT` 直接列进了「没找到」的取值：

> **0 or ENOENT or ESRCH or EBADF or EPERM or ...**
> The given name or gid was not found.

所以这条范式的适用边界是：**当后端数据库文件本身能正常打开时**，它是可靠的（本节实测中 `/etc/passwd` 存在，`getpwnam("nosuchuser")` 就是干净的 `errno=0`）；**当后端文件缺失/不可读时**（`/etc/group` 不存在的情况），`errno` 会被 `open()` 的 `ENOENT` 污染。机制见 [8.3 第五节](./8.3-group-file.md)。

### 二、静态缓冲：指针「有效到下一次同类调用为止」

`getpwnam(3)` RETURN VALUE 原文：

> **The return value may point to a static area, and may be overwritten by subsequent calls to `getpwent(3)`, `getpwnam()`, or `getpwuid()`.** (Do not pass the returned pointer to `free(3)`.)

三件事要分清楚：

| 事实 | 说明 |
|------|------|
| **不要 `free`** | 它不是 `malloc` 出来的 |
| **不要存** | 「下一次**同类**调用」就会覆写 —— 这个「同类」比想象中宽：`getpwent` / `getpwnam` / `getpwuid` 共用同一块 |
| **不要跨线程** | `getpwnam(3)` ATTRIBUTES 明确标 `MT-Unsafe race:pwnam locale` |

实现就在 `nss/getXXbyYY.c:93`：一个模块级 `static char *buffer;`，首次调用时懒分配（`:123-126`），所有非 `_r` 版本的 `getpwnam` / `getpwuid` / `getgrnam` / `getgrgid` 都从同一个转换单元生成。

> ⚠️ 地址**不可假设**。本节实测里 `fgetpwent()` 三次拿到的是**同一个地址**，但 `getpwnam("ce")` 和 `getpwuid(10240)`（同一个用户！）拿到的是**两个不同地址**。所以正确结论是「指针的有效期到下一次同类调用为止」，而**不是**「同一个账户总是同一块内存」。

### 三、三层 API 对照

| 层 | passwd 侧 | group 侧 | 返回值 | 线程安全 |
|----|-----------|----------|--------|----------|
| **单条查** | `getpwnam(name)` / `getpwuid(uid)` | `getgrnam(name)` / `getgrgid(gid)` | `struct passwd *` / `struct group *` | `MT-Unsafe` |
| **顺序遍历** | `setpwent()` / `getpwent()` / `endpwent()` | `setgrent()` / `getgrent()` / `endgrent()` | 同上，`NULL` = 到头 | `MT-Unsafe race:getpwent` |
| **可重入** | `getpwnam_r` / `getpwuid_r` / `getpwent_r` | `getgrnam_r` / `getgrgid_r` / `getgrent_r` | **`int`（错误号）** | `MT-Safe locale` |
| **从任意流读** | `fgetpwent(FILE *)` / `fgetpwent_r` | `fgetgrent(FILE *)` / `fgetgrent_r` | 同单条查 | 看版本 |

`fgetpwent(FILE *)` 这一层很关键：因为 `getpwnam()` 的路径是**编译期写死**的（`nss/files-XXX.c:42` 的 `#define DATAFILE "/etc/" DATABASE`），**想读自己造的测试文件，这是唯一的正规入口**。本节四个演示里就有三个用了它。

### 四、`_r` 版本的语义变化：三个必须记住的点

`getpwnam(3)` RETURN VALUE 对 `_r` 版本的定义：

> On success, `getpwnam_r()` and `getpwuid_r()` **return zero**, and set `*result` to `pwd`. **If no matching password record was found, these functions return 0 and store NULL in `*result`.** In case of error, **an error number is returned**, and NULL is stored in `*result`.

| # | 变化 | 后果 |
|---|------|------|
| 1 | **返回错误号，不是 `-1`** | 不要再对它用 `errno` 范式；`s == ERANGE` 而不是 `s == -1 && errno == ERANGE` |
| 2 | **「不存在」= `s == 0` 且 `res == NULL`** | **只看 `s` 是不够的** —— 成功和"没找到"都返回 0 |
| 3 | **多了一种全新错误 `ERANGE`** | 你给的缓冲太小 → 必须自己加大重试 |

缓冲怎么定大小？`getpwnam(3)` DESCRIPTION：

> The call `sysconf(_SC_GETPW_R_SIZE_MAX)` returns either **-1, without changing errno**, or an initial suggested size for `buf`. (**If this size is too small, the call fails with `ERANGE`**, in which case the caller can retry with a larger buffer.)

注意两个细节：`sysconf` 返回 `-1` 时**不能**去看 `errno`（man 明说 "without changing errno"），要自己给个兜底值（`man 3 getpwnam` 的 EXAMPLES 用的是 `16384`）；以及那个「建议值」**只是建议**，`ERANGE` 重试不是可选项。非 `_r` 版本则由 libc 自己干这件事（`nss/getXXbyYY.c:139-158`：`while (... == ERANGE) { buffer_size *= 2; realloc(...); }`）。

## 代码

### c8_4 返回值语义：`errno` 范式 vs 静态缓冲

完整程序见 [`../code/c8_4_lookup_api.c`](../code/c8_4_lookup_api.c)：先演示 `errno` 范式，再用 `fgetpwent()` 读三条合成记录，把「指针被覆写」这件事打印成**地址证据**。

```c
/* c8_4_lookup_api.c —— 8.4：查询 API 的返回值语义
 *
 * 三个必须记住的点，全部实测：
 *   1. 「查不到」= 返回 NULL 且 errno 不变（要把 errno 先清零才能区分）
 *   2. 返回的指针指向静态缓冲，下一次调用就把它改写掉
 *   3. 静态缓冲的地址由 libc 决定，两次调用可能不同
 *
 * 编译：cc -Wall -Wextra -o c8_4_lookup_api c8_4_lookup_api.c
 */
#define _DEFAULT_SOURCE
#include <errno.h>
#include <grp.h>
#include <pwd.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

int main(void)
{
    /* ---- 1. errno 范式 ---- */
    errno = 0;
    struct passwd *pw = getpwnam("nosuchuser");
    printf("errno=0; getpwnam(\"nosuchuser\") -> %s  errno=%d  => %s\n",
           pw ? "non-NULL" : "NULL", errno,
           (pw == NULL && errno == 0) ? "「用户不存在」" : "「系统错误」");

    errno = 0;
    pw = getpwuid(0);
    printf("errno=0; getpwuid(0)              -> %s  errno=%d  => %s\n",
           pw ? pw->pw_name : "NULL", errno,
           (pw == NULL && errno == 0) ? "「无此 UID 的记录」" : "「系统错误」");

    errno = 0;
    pw = getpwnam("ce");
    if (pw != NULL)
        printf("errno=0; getpwnam(\"ce\")           -> uid=%ld gid=%ld gecos=%s\n",
               (long) pw->pw_uid, (long) pw->pw_gid, pw->pw_gecos);

    /* ---- 2. 静态缓冲：连续读两条记录，前一个指针的内容被改写 ---- */
    const char *pf = "/tmp/c8_passwd_demo";
    FILE *w = fopen(pf, "w");
    if (w == NULL) {
        perror("fopen for write");
        return 1;
    }
    fputs("alice:x:1001:1001:Alice:/home/alice:/bin/bash\n"
          "bob:x:1002:1002:Bob:/home/bob:/bin/sh\n"
          "carol:x:1003:1003:Carol:/home/carol:/sbin/nologin\n", w);
    fclose(w);

    puts("\n-- 静态缓冲实测：fgetpwent() 读三条记录 --");
    FILE *f = fopen(pf, "r");
    struct passwd *p1 = fgetpwent(f);
    printf("第 1 条: p1=%p p1->pw_name=\"%s\"\n", (void *) p1, p1->pw_name);

    struct passwd *p2 = fgetpwent(f);
    printf("第 2 条: p2=%p p2->pw_name=\"%s\"\n", (void *) p2, p2->pw_name);
    printf("        此刻再用 p1 读 -> p1->pw_name=\"%s\"  (p1==p2? %s)\n",
           p1->pw_name, p1 == p2 ? "是" : "否");

    struct passwd *p3 = fgetpwent(f);
    printf("第 3 条: p3=%p p3->pw_name=\"%s\"\n", (void *) p3, p3->pw_name);
    printf("        此刻 p1->pw_name=\"%s\"，p2->pw_name=\"%s\" —— 三个指针是同一块内存\n",
           p1->pw_name, p2->pw_name);
    fclose(f);

    /* ---- 3. 地址由 libc 决定，别做任何假设 ---- */
    struct passwd *a = getpwnam("ce");
    struct passwd *b = getpwuid(10240);
    printf("\ngetpwnam(\"ce\")=%p  getpwuid(10240)=%p  (同一用户，地址%s)\n",
           (void *) a, (void *) b, a == b ? "相同" : "不同");

    puts("\n结论：返回的指针「有效到下一次同类调用为止」，要留住内容就得自己拷一份；");
    puts("      多线程里必须换 _r 版本（见 c8_5_lookup_r.c）。");
    return 0;
}
```

编译与运行：

```bash
gcc -O0 -Wall -Wextra -o c8_4_lookup_api c8_4_lookup_api.c && ./c8_4_lookup_api
```

实测输出（另在 Compiler Explorer 复核，gcc 13.3）：

```text
errno=0; getpwnam("nosuchuser") -> NULL  errno=0  => 「用户不存在」
errno=0; getpwuid(0)              -> NULL  errno=0  => 「无此 UID 的记录」
errno=0; getpwnam("ce")           -> uid=10240 gid=10240 gecos=Not a real account

-- 静态缓冲实测：fgetpwent() 读三条记录 --
第 1 条: p1=0x7da0e6211240 p1->pw_name="alice"
第 2 条: p2=0x7da0e6211240 p2->pw_name="bob"
        此刻再用 p1 读 -> p1->pw_name="bob"  (p1==p2? 是)
第 3 条: p3=0x7da0e6211240 p3->pw_name="carol"
        此刻 p1->pw_name="carol"，p2->pw_name="carol" —— 三个指针是同一块内存

getpwnam("ce")=0x7da0e6211320  getpwuid(10240)=0x7da0e6211380  (同一用户，地址不同)

结论：返回的指针「有效到下一次同类调用为止」，要留住内容就得自己拷一份；
      多线程里必须换 _r 版本（见 c8_5_lookup_r.c）。
```

**解读**

1. **`errno` 范式在本容器上是可用的**（前两行）：`/etc/passwd` 存在，所以「没找到」走的是「文件打开、扫完没匹配」那条路，`internal_getent()` 在 `nss/files-XXX.c:130` 用 `__set_errno(saved_errno)` 把调用前设的 0 **还了回来** → `errno=0` 干净地表示"不存在"。**这个干净是有条件的**：换成 `/etc/group`（文件不存在）就不是这样了，见 [8.3](./8.3-group-file.md)。
2. **`getpwuid(0)` 又一次返回 NULL**：进程 `uid=0`，`/etc/passwd` 里没有 0 号记录。这不是错误，`errno=0` 说得很清楚。
3. **三行地址完全相同（`0x7da0e6211240`）**，这是「静态缓冲」最硬的证据。注意第 2 条那行：**用 `p1` 去读，读到的是 `"bob"`** —— `p1`、`p2`、`p3` 指向同一块内存，后一次调用把前一次的字段全改写了。所以「读一批记录存进数组」的写法在这种 API 上**直接是 bug**，必须 `strdup` 或者换成 `_r` 版本。
4. **最后一行才是最容易踩的**：`getpwnam("ce")` 与 `getpwuid(10240)` 查的是**同一个用户**，地址却**不同**（`0x...320` vs `0x...380`）。所以「同一个账户 = 同一个指针」不成立；唯一能依赖的契约是 man 的那句「下一次同类调用就会覆写」。**任何基于地址相等的缓存都会在某些 libc / NSS 后端上翻车。**

### c8_5 `_r` 版本：错误号、`*result` 与 `ERANGE` 重试

完整程序见 [`../code/c8_5_lookup_r.c`](../code/c8_5_lookup_r.c)：成功路径、「不存在」的两种表达、以及缓冲从 8 字节指数增长到 64 字节才成功的全过程。

```c
/* c8_5_lookup_r.c —— 8.4：_r 版本（可重入）与 ERANGE 重试
 *
 * 非 _r 版本把结果放在静态缓冲里；_r 版本由调用者提供 struct 与缓冲，
 * 因此线程安全。代价是要自己处理「缓冲不够」这一种全新的错误。
 *
 * 编译：cc -Wall -Wextra -o c8_5_lookup_r c8_5_lookup_r.c
 */
#define _DEFAULT_SOURCE
#include <errno.h>
#include <grp.h>
#include <pwd.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <unistd.h>

int main(void)
{
    long pw_max = sysconf(_SC_GETPW_R_SIZE_MAX);
    long gr_max = sysconf(_SC_GETGR_R_SIZE_MAX);
    printf("_SC_GETPW_R_SIZE_MAX=%ld  _SC_GETGR_R_SIZE_MAX=%ld\n", pw_max, gr_max);

    struct passwd pw, *res = NULL;
    char *buf = malloc((size_t) pw_max);

    /* ---- 成功路径 ---- */
    int s = getpwnam_r("ce", &pw, buf, (size_t) pw_max, &res);
    printf("getpwnam_r(\"ce\", bufsize=%ld) -> s=%d res=%s", pw_max, s,
           res ? "non-NULL" : "NULL");
    if (res != NULL)
        printf("  pw_name=%s pw_uid=%ld pw_gecos=%s", pw.pw_name,
               (long) pw.pw_uid, pw.pw_gecos);
    else if (s == ENOENT || s == ESRCH)
        printf("  （errno 风格：s=ENOENT 表示不存在）");
    putchar('\n');

    /* ---- 「不存在」在 _r 里的表达方式变了 ---- */
    res = (struct passwd *) 0x1;        /* 故意塞个非 NULL，看库里会不会改它 */
    s = getpwnam_r("nosuchuser", &pw, buf, (size_t) pw_max, &res);
    printf("getpwnam_r(\"nosuchuser\")     -> s=%d res=%s"
           "   （s==0 且 res==NULL 才是「不存在」；只看 s 是不够的）\n",
           s, res ? "non-NULL" : "NULL");
    free(buf);

    /* ---- 缓冲太小：ERANGE，指数增长重试 ---- */
    puts("\n-- 缓冲从小往大试，直到不再 ERANGE --");
    size_t sz = 8;
    while (sz <= 8192) {
        char *b = malloc(sz);
        if (b == NULL)
            break;
        res = NULL;
        s = getpwnam_r("ce", &pw, b, sz, &res);
        printf("bufsize=%-5zu -> s=%-3d %-28s res=%s\n", sz, s,
               s == ERANGE ? "ERANGE（缓冲不够）" : strerror(s),
               res ? "non-NULL" : "NULL");
        free(b);
        if (s != ERANGE)
            break;
        sz *= 2;
    }

    puts("\n注意：_r 版本失败时返回的是「错误号」，不是 -1；");
    puts("      它不会去动 errno —— 所以不要再对它用 errno 范式。");
    return 0;
}
```

编译与运行：

```bash
gcc -O0 -Wall -Wextra -o c8_5_lookup_r c8_5_lookup_r.c && ./c8_5_lookup_r
```

实测输出（另在 Compiler Explorer 复核，gcc 13.3）：

```text
_SC_GETPW_R_SIZE_MAX=1024  _SC_GETGR_R_SIZE_MAX=1024
getpwnam_r("ce", bufsize=1024) -> s=0 res=non-NULL  pw_name=ce pw_uid=10240 pw_gecos=Not a real account
getpwnam_r("nosuchuser")     -> s=0 res=NULL   （s==0 且 res==NULL 才是「不存在」；只看 s 是不够的）

-- 缓冲从小往大试，直到不再 ERANGE --
bufsize=8     -> s=34  ERANGE（缓冲不够）     res=NULL
bufsize=16    -> s=34  ERANGE（缓冲不够）     res=NULL
bufsize=32    -> s=34  ERANGE（缓冲不够）     res=NULL
bufsize=64    -> s=0   Success                      res=non-NULL

注意：_r 版本失败时返回的是「错误号」，不是 -1；
      它不会去动 errno —— 所以不要再对它用 errno 范式。
```

**解读**

1. **`s = 0` 不代表成功**。第二行是关键：`getpwnam_r("nosuchuser")` 返回 `s=0`（不是错误号！），但 `res=NULL`。程序里为了证明这一点，**先故意把 `res` 塞成 `(struct passwd *)0x1`**，库里照样把它改成 `NULL` —— 说明这个出参**每次都被写**，不能靠"初始化过"来判断。
2. **`ERANGE` 是有真实下界的**：`bufsize = 8 / 16 / 32` 全部 `s=34`（`ERANGE` 的数值就是 34），到 **64** 才成功。注意 `sysconf` 给的"建议值"是 **1024** —— 比实际需要大得多。man 只说它是 "an initial suggested size"，不是保证值；反过来，**比建议值小也可能成功**。所以正确写法是「从建议值开始，失败就翻倍重试」，而不是"必须给 1024"。
3. **`_r` 版本不动 `errno`**（第五行注释）。所以 `if (errno == 0) 不存在` 这类写法在 `_r` 上完全无效，必须看返回值 `s` 和出参 `res` 的组合。
4. 常见误写是把 `ERANGE` 重试写成「给个更大的固定值再来一次」。真到临界点上，一次可能还是不够；`nss/getXXbyYY.c:139-158` 里 libc 自己的做法就是 **`while` 循环 + `buffer_size *= 2` + `realloc`**，照抄这个形状。

### Listing 8-1：`ugid_functions.c` 的四个助手

这是 TLPI 后面十几章都在复用的公共件（Ch9/12/15/34/38/39/40…）—— 把 uid/gid 和名字互相翻译。完整程序见 [`../code/ugid_functions.c`](../code/ugid_functions.c)；原书官方说明里它是 **Listing 8-1, page 159**，而配套头文件 `ugid_functions.h` **没有印进书里**（原文："This file is not printed in the book; it is the header file for `ugid_functions.c` (Listing 8-1, page 159)"）。

```c
/* ugid_functions.c —— 原书 Listing 8-1（p.159）复刻版
 *
 * 四个「名字 ↔ 数字 ID」的转换助手。TLPI 后面几乎所有例子都用它们把
 * uid/gid 翻译成人能读的名字（第 9/12/15/34/38/39/40 章…）。
 *
 * 与原书的差别：只把 #include "tlpi_hdr.h" 去掉（改由 ugid_functions.h
 * 提供 uid_t/gid_t），并补上原书靠 tlpi_hdr.h 间接引入的 <stdlib.h>
 * （strtol 的声明）。函数体逐行保持原样。
 *
 * 编译：cc -Wall -Wextra -c ugid_functions.c
 */
#include <ctype.h>
#include <grp.h>
#include <pwd.h>
#include <stdlib.h>
#include "ugid_functions.h"

char *          /* Return name corresponding to 'uid', or NULL on error */
userNameFromId(uid_t uid)
{
    struct passwd *pwd;

    pwd = getpwuid(uid);
    return (pwd == NULL) ? NULL : pwd->pw_name;
}

uid_t           /* Return UID corresponding to 'name', or -1 on error */
userIdFromName(const char *name)
{
    struct passwd *pwd;
    uid_t u;
    char *endptr;

    if (name == NULL || *name == '\0')  /* On NULL or empty string */
        return -1;                      /* return an error */

    u = strtol(name, &endptr, 10);      /* As a convenience to caller */
    if (*endptr == '\0')                /* allow a numeric string */
        return u;

    pwd = getpwnam(name);
    if (pwd == NULL)
        return -1;

    return pwd->pw_uid;
}

char *          /* Return name corresponding to 'gid', or NULL on error */
groupNameFromId(gid_t gid)
{
    struct group *grp;

    grp = getgrgid(gid);
    return (grp == NULL) ? NULL : grp->gr_name;
}

gid_t           /* Return GID corresponding to 'name', or -1 on error */
groupIdFromName(const char *name)
{
    struct group *grp;
    gid_t g;
    char *endptr;

    if (name == NULL || *name == '\0')  /* On NULL or empty string */
        return -1;                      /* return an error */

    g = strtol(name, &endptr, 10);      /* As a convenience to caller */
    if (*endptr == '\0')                /* allow a numeric string */
        return g;

    grp = getgrnam(name);
    if (grp == NULL)
        return -1;

    return grp->gr_gid;
}
```

验收驱动见 [`../code/t_ugid.c`](../code/t_ugid.c)：把 `"ce"` / `"1000"` / `"0"` / `"nosuchuser"` / `""` 分别喂给四个函数，把边界一次跑完。

```c
/* t_ugid.c —— 验收原书 Listing 8-1 的四个助手函数
 *
 * 这四个函数（userNameFromId / userIdFromName / groupNameFromId /
 * groupIdFromName）是 TLPI 后面十几章都在用的公共件，所以单独验一遍：
 *   - 数字字符串走「快捷路径」，不查数据库
 *   - 查不到时返回 NULL / (uid_t)-1
 *   - 主机上没有的目标（比如没有 /etc/group 的容器）必须能安全返回
 *
 * 编译（三个文件一起）：
 *   cc -Wall -Wextra -o t_ugid t_ugid.c ugid_functions.c
 */
#include <stdio.h>
#include <stdlib.h>

#include "ugid_functions.h"

int main(void)
{
    const char *names[] = { "ce", "1000", "0", "nosuchuser", "" };
    for (size_t i = 0; i < sizeof names / sizeof names[0]; i++) {
        uid_t u = userIdFromName(names[i]);
        gid_t g = groupIdFromName(names[i]);
        char *un = userNameFromId(u);
        char *gn = groupNameFromId(g);
        printf("userIdFromName(\"%s\") = %-6ld  userNameFromId -> %s\n",
               names[i], (long) u, un ? un : "(NULL)");
        printf("          groupIdFromName = %-6ld  groupNameFromId -> %s\n",
               (long) g, gn ? gn : "(NULL)");
    }

    /* 边界：NULL 指针与「UID 存在但没有对应记录」 */
    printf("\nuserIdFromName(NULL) = %ld\n", (long) userIdFromName(NULL));
    printf("groupNameFromId(10240) = %s\n",
           groupNameFromId(10240) ? groupNameFromId(10240) : "(NULL)");
    return 0;
}
```

实测输出（另在 Compiler Explorer 复核，gcc 13.3）：

```text
userIdFromName("ce") = 10240   userNameFromId -> ce
          groupIdFromName = 4294967295  groupNameFromId -> (NULL)
userIdFromName("1000") = 1000    userNameFromId -> (NULL)
          groupIdFromName = 1000    groupNameFromId -> (NULL)
userIdFromName("0") = 0       userNameFromId -> (NULL)
          groupIdFromName = 0       groupNameFromId -> (NULL)
userIdFromName("nosuchuser") = 4294967295  userNameFromId -> (NULL)
          groupIdFromName = 4294967295  groupNameFromId -> (NULL)
userIdFromName("") = 4294967295  userNameFromId -> (NULL)
          groupIdFromName = 4294967295  groupNameFromId -> (NULL)

userIdFromName(NULL) = 4294967295
groupNameFromId(10240) = (NULL)
```

**解读**

1. **`userIdFromName("1000") = 1000` —— 这个 1000 根本没查数据库。** 函数体里有一句 `u = strtol(name, &endptr, 10); if (*endptr == '\0') return u;`（原书注释写得很清楚："As a convenience to caller ... allow a numeric string"）。**只要整串都是数字就直接返回**，哪怕系统里没有 1000 号用户（本容器确实没有）。这是有意的便利设计，但也意味着 `userIdFromName("0")` **永远返回 0**，即使 0 号记录不存在 —— 输出里 `userIdFromName("0") = 0` 与 `userNameFromId(0) -> (NULL)` 并存，正是这个语义。
2. **`-1` 打印出来是 `4294967295`**。函数失败返回 `(uid_t) -1`，而 `uid_t` 是**无符号**的，`printf("%ld", (long) u)` 就把 32 位的 `0xFFFFFFFF` 显示成 `4294967295`。判断失败必须写 `if (u == (uid_t) -1)`，**不能**写 `if (u == -1)`（虽然等价，但读代码的人会以为 `uid_t` 是有符号的），更不能用 `> 0` 之类的关系判断。
3. **`""` 和 `NULL` 都返回 `(uid_t) -1`**，不打数据库 —— 函数开头的 `if (name == NULL || *name == '\0') return -1;` 拦住了。这是好设计：调用方不用自己判空。
4. **`groupNameFromId(10240) -> (NULL)`**：本容器没有 `/etc/group`，所以任何 gid 都翻不出名字（[8.3](./8.3-group-file.md)）。注意它返回 `NULL` 而不是 `(gid_t) -1` —— **「名字→ID」失败返回 -1，「ID→名字」失败返回 NULL**，两个方向的约定不同，写调用方代码时最容易搞混的就是这里。
5. `userIdFromName("ce") = 10240` 走的是**真正查库**那条路（`"ce"` 不是纯数字），说明两条路径都工作。

/* t_getpwent.c —— 原书 Ch08 配套程序复刻版
 *
 * 演示用 getpwent() 顺序遍历系统密码文件。
 * 原书依赖 tlpi_hdr.h（取 EXIT_SUCCESS 等），此处只补 <stdlib.h>，其余逐行原样。

 * 编译：cc -Wall -Wextra -o t_getpwent t_getpwent.c

#include <stdio.h>
#include <stdlib.h>

int
main(int argc, char *argv[])
{

    while ((pwd = getpwent()) != NULL)

    endpwent();
    exit(EXIT_SUCCESS);
}

/* t_getpwnam_r.c —— 原书 Ch08 配套程序复刻版
 *
 * 原书说明：This file is not printed in the book; it is a supplementary file
 * for Chapter 8.（即它不是 Listing，只是随章发布的示例。）
 *
 * 演示 getpwnam_r()：可重入版本，结果写进调用者提供的 struct passwd 与缓冲。
 * 原书依赖 tlpi_hdr.h（取 usageErr/errExitEN/malloc 包装），此处内联最小实现，
 * 主流程逐行保持原样。
 *
 * 注意原书这一行打印的是 pw_gecos（注释字段），不是 pw_name：
 *     printf("Name: %s\n", pwd.pw_gecos);
 * 已核对 man7.org 上的官方源码，确实如此；man 3 getpwnam 的 EXAMPLES 里
 * 也是 "Name: %s" 配 pwd.pw_gecos。对本容器的 ce 账号，pw_gecos =
 * "Not a real account" —— 输出看着像出错，其实标签与字段本来就不对应。
 * 详见 notes/8.4-retrieving-info.md。
 *
 * 编译：cc -Wall -Wextra -o t_getpwnam_r t_getpwnam_r.c
 */
#define _DEFAULT_SOURCE
#include <pwd.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <unistd.h>

int
main(int argc, char *argv[])
{
    if (argc != 2 || strcmp(argv[1], "--help") == 0) {
        fprintf(stderr, "Usage: %s username\n", argv[0]);
        exit(EXIT_FAILURE);
    }

    size_t bufSize = sysconf(_SC_GETPW_R_SIZE_MAX);
    char *buf = malloc(bufSize);
    if (buf == NULL) {
        fprintf(stderr, "malloc %zu failed\n", bufSize);
        exit(EXIT_FAILURE);
    }

    struct passwd *result;
    struct passwd pwd;

    int s = getpwnam_r(argv[1], &pwd, buf, bufSize, &result);
    if (s != 0) {
        fprintf(stderr, "getpwnam_r: %s\n", strerror(s));
        exit(EXIT_FAILURE);
    }

    if (result != NULL)
        printf("Name: %s\n", pwd.pw_gecos);
    else
        printf("Not found\n");

    exit(EXIT_SUCCESS);
}

## HFT / 嵌入式关联

- **`getXXbyYY` 系列一律不可以在热路径上调用**。不仅是 O(n) 文件扫描：接了 SSSD/LDAP 之后它就是**一次网络往返**（可能几百毫秒）。行情/风控线程里一次 `getpwuid` 足以造成可观测的抖动。
- **「一次读一批」必须自己拷**。非 `_r` 版本的返回值是同一块静态内存，`struct passwd` 里的 `char *` 也指向那块内存里的字符串。要留住就必须 **`strdup` 每个字段**（或整块 memcpy），否则整批记录会退化成"最后一条复制 N 遍"。这是这类 API 最经典的 bug。
- **多线程服务启动时用 `_r` 版**，并且**按 `nss/getXXbyYY.c` 的形状写重试**（`while (ERANGE) buffer_size *= 2`）。给个固定 1024 在接了 LDAP 的机器上会被打脸 —— 后端返回的 `gecos`/`dir` 可以很长。
- **`sysconf(_SC_LOGIN_NAME_MAX)` / `_SC_GETPW_R_SIZE_MAX` 都可能返回 -1**，而且 `sysconf` 在返回 -1 时**不保证设置 errno**（`getpwnam(3)` 明说 "without changing errno"）。原书 Listing 8-2 里就写了兜底值 256。别拿 `errno` 去判 `sysconf` 失败。
- **嵌入式**：uClibc/musl 的 `getpwent` 家族行为与 glibc 有差异，尤其是「`_r` 版在"没找到"时返回什么」和「静态缓冲有几块」。跨 libc 的代码**只依赖 man 里写下的契约**（返回值、`*result`、NULL 结束），不要依赖实测到的地址行为。
- **每次调用都重开文件**这一点在嵌入式上尤其贵（`/etc/passwd` 可能在只有几十 KB/s 的 jffs2/squashfs 上）。枚举用户的代码应该 `setpwent()` 打开一次、`endpwent()` 关掉，而不是循环里 `getpwnam`。

## 自测题

<details>
<summary>1. 把 <code>getpwnam()</code> 返回的指针存进数组，循环读 100 个用户，会得到什么？</summary>

**会得到「100 份最后一条记录」。**

`getpwnam(3)` RETURN VALUE："The return value **may point to a static area, and may be overwritten by subsequent calls** to `getpwent(3)`, `getpwnam()`, or `getpwuid()`."

本节实测把这件事打成了地址证据：`fgetpwent()` 三次返回的都是 `0x7da0e6211240`，而且**用第 1 个指针 `p1` 去读，读到的是第 2 条记录的 `"bob"`**。

注意坑比 "同一个指针" 更深一层：`struct passwd` 里的 `char *pw_name` 等字段也指向**同一块静态内存里的偏移**。所以即使你把 `struct passwd` 按值拷出来（`struct passwd copy = *p;`），里面的 `char *` 依然会被下一次调用改掉。

正确做法：
- 每条记录**立刻**把需要的字段 `strdup` / `snprintf` 存下来；
- 或者改用 `getpwnam_r()`，自己提供 `struct passwd` 和 buffer（多线程下也是必须的）。
</details>

<details>
<summary>2. <code>getpwnam_r()</code> 返回 0，是成功还是没找到？</summary>

**都可能是。必须同时看出参 `*result`。**

`getpwnam(3)` RETURN VALUE 原文把两种情形都写成返回 0：

> On success, `getpwnam_r()` and `getpwuid_r()` return **zero**, and set `*result` to `pwd`. **If no matching password record was found, these functions return 0 and store NULL in `*result`.** In case of error, an error number is returned, and NULL is stored in `*result`.

所以判定表是：

| `s` | `*result` | 含义 |
|-----|-----------|------|
| `0` | 非 NULL | ✅ 成功 |
| `0` | `NULL` | 没有这条记录 |
| 非 0（如 `ERANGE`=34） | `NULL` | 出错 |

本节实测两行正好覆盖前两种：`s=0 res=non-NULL`（成功）与 `s=0 res=NULL`（不存在）。程序里还**故意把 `res` 预置成 `(struct passwd *)0x1`** 再调第二次，结果库里把它改成了 `NULL` —— 说明这个出参每次都会被写。

另一种常见误写是拿 `_r` 版本去用 `errno` 范式：`_r` 版本**不动 `errno`**，`errno` 在这里没有任何意义。
</details>

<details>
<summary>3. <code>sysconf(_SC_GETPW_R_SIZE_MAX)</code> 返回 1024，是不是就说明 1024 一定够？给 8 / 16 / 32 / 64 会怎样？</summary>

**不是。它只是 "an initial suggested size"。**

`getpwnam(3)` DESCRIPTION："returns either -1, without changing errno, or an **initial suggested size** for `buf`. (If this size is too small, the call fails with `ERANGE`, in which case the caller can retry with a larger buffer.)"

本节实测（用同一个 `getpwnam_r("ce", ...)`）：

```text
bufsize=8     -> s=34  ERANGE（缓冲不够）     res=NULL
bufsize=16    -> s=34  ERANGE（缓冲不够）     res=NULL
bufsize=32    -> s=34  ERANGE（缓冲不够）     res=NULL
bufsize=64    -> s=0   Success                      res=non-NULL
```

两个反直觉点：

1. **`s` 是 34**，不是 `-1` —— `_r` 版本返回的是**错误号本身**（`ERANGE` 的数值就是 34）。
2. **64 就够了**，比建议值 1024 小得多。说明建议值是**偏保守的上界**（`struct pwent_data` 预留给最长行），不是"必须给这么多"。

正确写法照抄 glibc 自己（`nss/getXXbyYY.c:139-158`）：从建议值开始，`ERANGE` 就 `buffer_size *= 2` 重试。另外 `sysconf` 返回 -1 时**不要看 `errno`** —— man 明说 "without changing errno"，要自己给兜底值。
</details>

<details>
<summary>4. <code>userIdFromName("1000")</code> 返回 1000 —— 它查库了吗？</summary>

**没有。这是函数里特意留的「数字快捷路径」。**

原书 `ugid_functions.c` 的函数体：

```c
u = strtol(name, &endptr, 10);      /* As a convenience to caller */
if (*endptr == '\0')                /* allow a numeric string */
    return u;

pwd = getpwnam(name);               /* 只有不是纯数字才走到这里 */
```

`strtol` 把整串都吃掉（`*endptr == '\0'`）就直接返回，**完全不碰数据库**。所以本容器里（根本没有 1000 号用户）`userIdFromName("1000")` 照样返回 1000。

三条推论：

- `userIdFromName("0")` **永远返回 0**，即使 0 号记录不存在（实测里 `userNameFromId(0) -> (NULL)` 与它并存）。
- 想区分「这个数字真的对应一个用户的 uid」和「只是个数字」，得另调一次 `getpwuid()` 验证。
- 这也是这类 helper 的常见取舍：方便调用方写 `./tool 1000` 和 `./tool wzp` 都行，代价是**丢失了一次存在性校验**。
</details>

<details>
<summary>5. 为什么 <code>t_getpwnam_r ce</code> 打出的是 <code>Name: Not a real account</code>？</summary>

**因为那一行打的是 `pw_gecos`（注释字段），不是 `pw_name`。**

原书 `t_getpwnam_r.c` 的源码：

```c
if (result != NULL)
    printf("Name: %s\n", pwd.pw_gecos);     /* ← 字段名是 _gecos */
else
    printf("Not found\n");
```

`pw_gecos` 对应 `/etc/passwd` 的**第 5 字段**（`passwd(5)` 称它为 "comment field ... used only for informational purposes"）。本容器的 `/etc/passwd` 里 `ce` 的 gecos 就是 `Not a real account`，所以输出看着像报错，实际只是**标签写的是 Name、值来自注释字段**。

这一点已核对上游：man7.org 上 TLPI 官方源码里确实是 `pwd.pw_gecos`；`man 3 getpwnam` 的 EXAMPLES 里也是同样的 `printf("Name: %s\n", pwd.pw_gecos)`。**这是上游一路传下来的写法**，不是本仓库抄错。

顺带它可以当 `_r` 的调用骨架模板：`sysconf` 拿建议大小 → `malloc` → `getpwnam_r(name, &pwd, buf, bufSize, &result)` → 判 `s != 0`（错误）/ 判 `result != NULL`（找到）。
</details>
