## 本节讲什么

前三节把「密文放在哪」说完了，这一节说「密文怎么算、怎么比」：

1. `crypt()` 的接口契约 —— 尤其是**现代 glibc 要哪个 feature test macro**（很多资料还停留在旧写法）。
2. 盐不是随机数，而是「**算法标识 + 轮数 + 随机前缀**」的打包串。`$1$` … `$6$` 各是什么，密文多长。
3. **`crypt()` 的失败返回值不是 `NULL`** —— 实测拿到的是字符串 `*0`。这个字符串会造出一个真实的安全漏洞。
4. 各种算法的**单核成本**实测：为什么 `$1$`（MD5）必须淘汰。
5. 把整章串成一条认证流水线（原书 Listing 8-2 + 可自动化版本）。

## 要点

### 一、接口与那个过时的宏

`crypt(3)` SYNOPSIS 与 Feature Test Macro 原文：

```c
#include <unistd.h>

char *crypt(const char *key, const char *salt);

#include <crypt.h>

char *crypt_r(const char *key, const char *salt, struct crypt_data *restrict data);
```

> Feature Test Macro Requirements for glibc (see `feature_test_macros(7)`):
>
> `crypt()`:
> **Since glibc 2.28: `_DEFAULT_SOURCE`**
> glibc 2.27 and earlier: `_XOPEN_SOURCE`
>
> `crypt_r()`: `_GNU_SOURCE`

**这就是「老教程为什么不能用」的典型**：网上大量示例（以及原书 Listing 8-2）写的是 `#define _XOPEN_SOURCE`，那是 **glibc 2.27 及更早**的要求。在 glibc ≥ 2.28 上要用 `_DEFAULT_SOURCE`。

还有一层容易忽略的：**glibc 自己已经不提供 `crypt()` 了**。`crypt(3)` HISTORY 段原文：

> The `crypt()`, `encrypt(3)`, and `setkey(3)` functions are part of the POSIX.1-2008 XSI Options Group for Encryption and are **optional**. If the interfaces are not available, then the symbolic constant `_XOPEN_CRYPT` is either not defined, or it is defined to -1 and availability can be checked at run time with `sysconf(3)`. **This may be the case if the downstream distribution has switched from glibc crypt to libxcrypt.** When recompiling applications in such distributions, the programmer must detect if `_XOPEN_CRYPT` is not available and **include `<crypt.h>`** for the function prototypes; otherwise **libxcrypt is an ABI-compatible drop-in replacement**.

本容器就是这条路径：`LIBRARY` 段写的是 "Password hashing library (**libcrypt, -lcrypt**)"，所以编译要加 `-lcrypt`。（`-lcrypt` 在 Debian/Ubuntu 上是必需的，glibc 2.39 已经不再带这个库。）

### 二、盐 = 算法标识 + 轮数 + 随机前缀

盐看着像「一串随机字符」，实际是**带格式的**。`crypt(3)` NOTES 原文：

> If `salt` is a character string starting with the characters `"$id$"` followed by a string optionally terminated by `"$"`, then the result has the form:
>
> ```
> $id$salt$hashed
> ```
>
> `id` identifies the hashing method used instead of DES ... The following values of `id` are supported:
>
> | ID | Method |
> |----|--------|
> | `1` | MD5 |
> | `2a` | Blowfish (not in mainline glibc; added in some Linux distributions) |
> | `5` | SHA-256 (since glibc 2.7) |
> | `6` | SHA-512 (since glibc 2.7) |

「hashed 部分长度是固定的」也有原文：

> "salt" stands for the **up to 16 characters** following `"$id$"` in the salt. The "hashed" part of the password string is the actual computed password. **The size of this string is fixed**:
> MD5 **22** characters
> SHA-256 **43** characters
> SHA-512 **86** characters

轮数可调（自 glibc 2.7）：

> the SHA-256 and SHA-512 implementations support a user-supplied number of hashing rounds, **defaulting to 5000**. If the `"$id$"` characters in the salt are followed by `"rounds=xxx$"` ... the result has the form `$id$rounds=yyy$salt$hashed` ... The number of rounds actually used is **1000 if xxx is less than 1000, 999999999 if xxx is greater than 999999999**, and is equal to xxx otherwise.

这些长度和实测完全对得上（见下文 `c8_6` 的输出）：

| 盐 | 实测密文长度 | 拆解 | man 里的固定长度 |
|----|--------------|------|------------------|
| `ab` | **13** | DES 全串 13 字符，前 2 字符就是盐 | "a series of **13** printable ASCII characters (the first two characters represent the salt itself)" |
| `$1$abc` | **29** | `$1$`(3) + `abc`(3) + `$`(1) + **22** | MD5 **22** |
| `$5$abc` | **50** | `$5$`(3) + `abc`(3) + `$`(1) + **43** | SHA-256 **43** |
| `$6$abc` | **93** | `$6$`(3) + `abc`(3) + `$`(1) + **86** | SHA-512 **86** |
| `$6$rounds=1000$abc` | **105** | 3 + `rounds=1000$`(12) + 3 + 1 + 86 | 差的正是那 12 个字符 |
| `$2b$08$abcdefghijklmnopqrstuv` | **60** | `$2b$08$`(7) + 22 字符盐 + 31 字符哈希 | bcrypt 是 libxcrypt 扩展，glibc man 未定义 |

> `$5$` 与 `$6$` 差的 43 字符不是「加密更强」，是**摘要更长**而已 —— 后面成本表会说明「长度 ≠ 慢」。

### 三、DES 的三个硬限制

`crypt(3)` DESCRIPTION 原文：

> **`salt` is a two-character string chosen from the set `[a-zA-Z0-9./]`.** This string is used to perturb the algorithm in **one of 4096 different ways**.
>
> By taking the **lowest 7 bits of each of the first eight characters of the key, a 56-bit key is obtained**. ... The returned value points to the hashed password, a series of 13 printable ASCII characters ...
>
> Warning: the key space consists of **2\*\*56 equal 7.2e16 possible values**. Exhaustive searches of this key space are possible using **massively parallel computers**.

三个直接后果：

| 限制 | 数值 | 后果 |
|------|------|------|
| 盐只有 2 字符、字符集 64 个 | 64² = **4096** 种（12 bit） | 彩虹表 / 预计算完全可行 |
| 口令只用前 8 个字符 | 「第 9 个字符起完全不影响结果」 | 长口令白设 |
| 密钥空间 2^56 | ≈ 7.2×10¹⁶ | 今天的专用硬件能穷举 |

`crypt(3)` 还专门警告不要拿它做别的密码学用途：

> The DES algorithm itself has a few quirks which make the use of the `crypt()` interface a **very poor choice for anything other than password authentication**. If you are planning on using the `crypt()` interface for a cryptography project, **don't do it**.

### 四、⭐ 失败返回值不是 `NULL` —— 以及由此产生的漏洞

`crypt(3)` RETURN VALUE 只说：

> On success, a pointer to the hashed password is returned. **On error, NULL is returned.**

**但实测不是这样。** 本容器（libxcrypt）在盐无法识别时返回的是**字符串 `*0`**（`c8_6` 输出里 `$y$` 那一行，长度 2）。源码层面的确切实现是 libxcrypt 4.4.36 `lib/util-make-failure-token.c`：

```c
void
make_failure_token (const char *setting, char *output, int size)
{
  if (size >= 3)
    {
      output[0] = '*';
      output[1] = '0';
      output[2] = '\0';

      if (setting && setting[0] == '*' && setting[1] == '0')
        output[1] = '1';
    }

  /* If there's not enough space for the full failure token, do the
     best we can.  */
  else if (size == 2)
    {
      output[0] = '*';
      output[1] = '\0';
    }
  else if (size == 1)
    {
      output[0] = '\0';
    }
}
```

两个哨兵的分工很明确：

| 返回值 | 含义 |
|--------|------|
| `*0` | **盐无效 / 算法无法识别** → 算不出来 |
| **`*1`** | **输入本身就是 `*0`** → 连'"试算"都拒绝（防止拿失败结果再喂回来） |

**`*1` 这条分支就是漏洞的入口。** `crypt()` 和 `getpwnam()` 一样返回**静态缓冲**（`crypt(3)`："The return value points to **static data whose content is overwritten by each call**."），于是下面这种「看起来和教科书一样」的认证函数会被绕过：

```c
/* ❌ 只要 stored 恰好指向 crypt() 自己的静态缓冲，任何口令都"通过" */
static int bad_verify(const char *password, const char *stored)
{
    return strcmp(crypt(password, stored), stored) == 0;
}
```

失效链条，三步：

1. `stored` 是上一次 `crypt()` 的返回值（同一块静态缓冲）；
2. 本次 `crypt(password, stored)` 检测到 `stored` 以 `*0` 开头 → 返回 **`*1`**，**并且这块内存上原来那串密文被覆写成了 `*1`**；
3. `strcmp("*1", stored)` 两边**指向同一块内存** → 恒等 → **返回 1（通过）**。

本节实测把这条链完整跑出来了：`bad_verify("definitely-wrong", stored_ptr) = 1`，而且紧接着打印 `stored_ptr` 的内容，它已经变成 `*1`。

安全的写法必须做四件事（`c8_8` 的 `good_verify`）：

```c
static int good_verify(const char *password, const char *stored)
{
    char salt[256];

    if (password == NULL || stored == NULL)
        return 0;
    if (snprintf(salt, sizeof salt, "%s", stored) >= (int) sizeof salt)
        return 0;                       /* ① 密文长得离谱，直接拒绝 */
    if (salt[0] == '!' || salt[0] == '*')
        return 0;                       /* ② 先挡锁定 / 无口令 */

    char *got = crypt(password, salt);  /* ③ 用副本作盐，不用原缓冲 */
    if (got == NULL)
        return 0;
    if (got[0] == '*')
        return 0;                       /* ④ 再挡 *0 / *1，绝不当成匹配 */

    return strcmp(got, salt) == 0;      /* 此时两边是两块不同的内存 */
}
```

> ① 是 `snprintf` 的溢出防护；② 是 `shadow(5)` 的 `!` / `*` 语义；③ 是切断别名；④ 是 `make_failure_token` 对应的哨兵检查。**少任何一条都有洞**：只做 ③ 不做 ④，`crypt()` 返回 `*0` 时和 `stored` 的比较仍然是"两块不同内存"，能挡住，但如果 `stored` 本身就是 `*0`（某些工具留下的占位），`strcmp("*0","*0")==0` 又成立了。

### 五、成本：为什么 `$1$` 必须淘汰

`shadow(5)` 与 `passwd(5)` 只规定格式，不规定强度。强度体现在**每次验证要花多少 CPU** —— 因为攻击者拿到盐之后只能逐词试（彩虹表被随机盐废掉了，但「同盐同口令必然同结果」这一点也说明盐只挡预计算，不挡字典）。

本节 `c8_7` 用 `CLOCK_MONOTONIC` 实测了单核吞吐（同一个口令换不同算法，各跑约 300 ms），详见下文代码段的输出。结论一句话：

> **MD5-crypt 比 SHA-512-crypt 便宜约 14 倍，比 bcrypt(cost=8) 便宜约 534 倍。**

而且 `$2b$`（bcrypt）的 cost 是**每 +1 翻一倍**，所以 cost=12 又比 cost=8 慢 16 倍 —— 一千万词字典从「6.94 天」变成「110.97 天」。这就是「成本可调」的意义：**同样的代码，在不同年代的机器上自动保持相同的破解难度**。

`crypt(3)` ERRORS 里还有一条与部署相关的：

| errno | 含义 |
|-------|------|
| `EINVAL` | "salt has the wrong format." |
| `ENOSYS` | "The `crypt()` function was not implemented, probably because of **U.S.A. export restrictions**." |
| `EPERM` | "`/proc/sys/crypto/fips_enabled` has a nonzero value, and an attempt was made to use a **weak hashing type, such as DES**." |

最后一条在 FIPS 合规的环境下会真出现：开了 FIPS 模式之后 DES-crypt 直接 `EPERM`。

### c8_6 盐决定算法：7 组对比 + DES 截断 + 锁定哨兵

完整程序见 [`../code/c8_6_crypt_schemes.c`](../code/c8_6_crypt_schemes.c)：从密文前缀反推算法的 `algo_of()`、7 种盐的长度对比、DES 只吃前 8 字符、以及 `!` / `*` 四种锁定哨兵。

```c
/* c8_6_crypt_schemes.c —— 8.5：crypt() 的算法由盐决定
 *
 * 同一个口令配不同的盐，输出长度、前缀、算法全都不一样。
 * 盐不是「随机数」，它是「算法标识 + 轮数参数 + 随机前缀」的打包串。
 *
 * 编译：cc -Wall -Wextra -o c8_6_crypt_schemes c8_6_crypt_schemes.c -lcrypt
 */
#define _DEFAULT_SOURCE
#include <crypt.h>
#include <stdio.h>
#include <string.h>

/* 从密文前缀反推算法 —— 认证程序要干的第一件事 */
static const char *algo_of(const char *h)
{
    if (h == NULL)
        return "NULL（crypt 失败）";
    if (h[0] == '*')
        return "失败哨兵 *0 / *1";
    if (h[0] != '$')
        return "DES-crypt（13 字符、无前缀）";
    if (strncmp(h, "$1$", 3) == 0)
        return "MD5-crypt";
    if (strncmp(h, "$5$", 3) == 0)
        return "SHA-256-crypt";
    if (strncmp(h, "$6$", 3) == 0)
        return "SHA-512-crypt";
    if (strncmp(h, "$2", 2) == 0)
        return "bcrypt";
    if (strncmp(h, "$y$", 3) == 0)
        return "yescrypt";
    return "未知";
}

int main(void)
{
    const char *salt[] = {
        "ab",                            /* 经典 DES：2 字符盐 */
        "$1$abc",                        /* MD5 */
        "$5$abc",                        /* SHA-256，默认 5000 轮 */
        "$6$abc",                        /* SHA-512，默认 5000 轮 */
        "$6$rounds=1000$abc",            /* 显式指定轮数 */
        "$2b$08$abcdefghijklmnopqrstuv", /* bcrypt cost=8 */
        "$y$j9T$abcdefghij",             /* yescrypt（新发行版默认） */
    };

    for (size_t i = 0; i < sizeof salt / sizeof salt[0]; i++) {
        char *h = crypt("secret123", salt[i]);
        printf("\n盐 %-32s\n  密文 %s\n  长度 %zu  算法 %s\n",
               salt[i], h ? h : "NULL", h ? strlen(h) : 0, algo_of(h));
    }

    /* ---- 盐相同 → 结果必然相同（这就是不能只靠加密防彩虹表的原因） ---- */
    char d1[256], d2[256];
    snprintf(d1, sizeof d1, "%s", crypt("secret123", "$6$fixedsalt"));
    snprintf(d2, sizeof d2, "%s", crypt("secret123", "$6$fixedsalt"));
    printf("\n同一口令 + 同一盐两次：%s\n", strcmp(d1, d2) == 0 ? "完全相同" : "不同");

    snprintf(d1, sizeof d1, "%s", crypt("secret123", "$6$fixedsalt"));
    snprintf(d2, sizeof d2, "%s", crypt("secret123", "$6$otherslat"));
    printf("同一口令 + 不同盐：  %s\n", strcmp(d1, d2) == 0 ? "相同" : "不同");

    /* ---- DES 只吃口令的前 8 个字符 ---- */
    char e1[64], e2[64], e3[64];
    snprintf(e1, sizeof e1, "%s", crypt("12345678AAA", "ab"));
    snprintf(e2, sizeof e2, "%s", crypt("12345678ZZZ", "ab"));
    snprintf(e3, sizeof e3, "%s", crypt("1234567", "ab"));
    printf("\nDES \"12345678AAA\" -> %s\n", e1);
    printf("DES \"12345678ZZZ\" -> %s  %s\n", e2,
           strcmp(e1, e2) == 0 ? "（一模一样：第 9 个字符根本没进算法）" : "（不同）");
    printf("DES \"1234567\"     -> %s  %s\n", e3,
           strcmp(e1, e3) == 0 ? "（也一模一样：不足 8 字符按 0 补齐）" : "（不同）");

    /* ---- 锁定账号：密文以 ! 或 * 开头 ---- */
    puts("\n-- 锁定 / 禁用账号的哨兵 --");
    const char *lock[] = { "!", "!!", "*", "!$6$abc" };
    for (size_t i = 0; i < sizeof lock / sizeof lock[0]; i++) {
        char *h = crypt("anything", lock[i]);
        printf("stored=\"%-8s\" -> crypt() 返回 \"%s\"  %s\n", lock[i],
               h ? h : "NULL", algo_of(h));
    }
    puts("（*0 永远不可能等于 stored 的密文，所以认证必然失败 —— 这就是锁定的实现方式）");
    return 0;
}
```

**解读**

1. **密文长度是「格式自带」的**，不是随机。13 / 29 / 50 / 93 / 105 —— 后四个都能用 `$id$`(3) + 盐(3) + `$`(1) + 固定摘要长（22 / 43 / 86 / 86）算出来，和 `crypt(3)` NOTES 里那句 "The size of this string is fixed" 完全一致。**`$6$rounds=1000$` 比 `$6$` 多出的 12 字符，就是 `rounds=1000$` 这 12 个字符本身**（105 − 93 = 12），摘要长度没变。
2. **`$y$`（yescrypt）在本容器上直接失败**，返回 `*0`。原因是 `crypt(3)` NOTES 那张 id 表只列了 `1` / `2a` / `5` / `6`（**glibc 的视角**），而 `$y$` 是 **libxcrypt** 新增的；本容器的 libxcrypt 构建没启用 yescrypt。这正好演示了「**man 与实现不同源**」：man 是 man-pages 项目的，实现是 libxcrypt 的，两者的能力集可以不重合。
3. **注意这里的返回是 `*0` 而不是 `NULL`** —— 与 man 的 "On error, NULL is returned" 不一致。所以**认证代码必须同时处理 `NULL` 和 `*` 开头**（第二节的 `good_verify` 就是按这个写的）。
4. **DES 那三行是本节最直观的一击**：`"12345678AAA"` 与 `"12345678ZZZ"` 密文**完全相同**，因为 DES-crypt 只看前 8 个字符。而 `"1234567"`（7 个字符）结果**不同** —— 说明不足 8 字符是按 0 补齐，不是直接截断。这两个现象合起来能推出完整语义：**取前 8 个字符，不足补 0，第 9 字符起丢弃**。
5. 「同一口令 + 同一盐两次：完全相同 / 不同盐：不同」这两行在说清盐的作用边界：**盐不是密钥，它挡的是预计算（彩虹表），挡不住「拿到盐之后逐词试」**。逐词试只能靠「每次验证更贵」拖，见 `c8_7`。
6. **最后四行是锁定机制的实现原理**：无论 `stored` 是 `!`、`!!`、`*` 还是 `!$6$abc`，`crypt()` 一律返回 `*0`。而 `*0` 这个 2 字符串**永远不可能等于 `stored` 那串密文**（长度都对不上），所以 `strcmp` 必然不等 → 认证必然失败。**「锁定」不需要在 `crypt()` 里做任何特殊分支，它只是「让比较必然失败」。**
7. ⚠️ 但第 6 点有个前提：比较的**两边必须是两块不同的内存**。一旦 `stored` 就是 `crypt()` 的返回值（第三节那个别名陷阱），`*0` 会被就地改写成 `*1`，恒等成立 —— **同样的哨兵机制从「必然拒绝」翻转成「必然通过」**。

### c8_7 单核成本实测：把「安全强度」量化

完整程序见 [`../code/c8_7_crypt_cost.c`](../code/c8_7_crypt_cost.c)：各算法跑约 300 ms 数吞吐，再用**同一次运行实测到的速率**推算一千万词字典的耗时。

```c
/* c8_7_crypt_cost.c —— 8.5：crypt() 的计算成本，就是离线爆破的成本
 *
 * 单核吞吐实测：同一个口令，换不同算法各跑 0.3 秒，换算成「次/秒」。
 * 第二张表由**同一次运行实测到的速率**推算（不是抄来的常数），
 * 回答「为什么 $1$（MD5）必须淘汰、为什么现代发行版默认 $y$」。
 *
 * 编译：cc -O2 -Wall -Wextra -o c8_7_crypt_cost c8_7_crypt_cost.c -lcrypt
 */
#define _DEFAULT_SOURCE
#include <crypt.h>
#include <stdio.h>
#include <time.h>

#define NSCHEME 4

static double now_ms(void)
{
    struct timespec ts;
    clock_gettime(CLOCK_MONOTONIC, &ts);
    return ts.tv_sec * 1000.0 + ts.tv_nsec / 1e6;
}

int main(void)
{
    const char *schemes[NSCHEME] = {
        "$1$abcdefgh",                   /* MD5-crypt */
        "$5$abcdefgh",                   /* SHA-256-crypt, 5000 轮 */
        "$6$abcdefgh",                   /* SHA-512-crypt, 5000 轮 */
        "$2b$08$abcdefghijklmnopqrstuv", /* bcrypt cost=8 */
    };
    const char *names[NSCHEME] = {
        "$1$（MD5-crypt）", "$5$（SHA-256-crypt）",
        "$6$（SHA-512-crypt）", "$2b$（bcrypt cost=8）",
    };
    double rate[NSCHEME];
    const double budget_ms = 300.0;
    const double wordlist = 1e7;         /* 一千万词的字典，只用于「换算」 */

    puts("算法                            口令数   总耗时      每次耗时     次/秒");
    for (int i = 0; i < NSCHEME; i++) {
        int n = 0;
        double t0 = now_ms();
        while (now_ms() - t0 < budget_ms) {
            crypt("benchmark-pw", schemes[i]);
            n++;
        }
        double dt = now_ms() - t0;
        rate[i] = n * 1000.0 / dt;
        printf("%-30s %-8d %8.1fms %10.1f us %9.0f\n",
               schemes[i], n, dt, dt * 1000.0 / n, rate[i]);
    }

    printf("\n把上面的速率换算成「跑完一千万词字典要多久」（单核，纯算术推算）：\n");
    for (int i = 0; i < NSCHEME; i++) {
        double sec = wordlist / rate[i];
        printf("  %-26s %8.0f 次/秒 -> %10.0f 秒 = %6.2f 小时 = %6.2f 天\n",
               names[i], rate[i], sec, sec / 3600, sec / 86400);
    }

    /* bcrypt 的特点是「成本可调」：每 +1 就翻一倍 */
    double bc12 = rate[3] / 16.0;
    double sec12 = wordlist / bc12;
    printf("  %-26s %8.2f 次/秒 -> %10.0f 秒 = %6.2f 小时 = %6.2f 天\n",
           "$2b$（bcrypt cost=12）", bc12, sec12, sec12 / 3600, sec12 / 86400);

    printf("\n结论：同一份口令字典，MD5-crypt 比 SHA-512-crypt 便宜约 %.0f 倍，\n",
           rate[0] / rate[2]);
    printf("      比 bcrypt(cost=8) 便宜约 %.0f 倍。加一个随机盐只挡预计算（彩虹表），\n",
           rate[0] / rate[3]);
    puts("      挡不住「拿到盐之后逐词试」—— 后者只能靠「每次验证更贵」来拖。");
    puts("      注意 $5$（SHA-256）在本容器上反而比 $6$（SHA-512）慢，");
    puts("      这是 libxcrypt 实现细节，别把「位数越大越慢」当成定律。");
    return 0;
}
```

编译与运行（必须开 `-O2`，否则测的是没优化的库绑定开销；不过 `crypt()` 本体在 libcrypt 里，主要影响是调用序列）：


```text
$6$abcdefgh                    197         300.4ms     1525.1 us       656

把上面的速率换算成「跑完一千万词字典要多久」（单核，纯算术推算）：
```

**解读**

1. **`$1$` 是 8910 次/秒**。这个数字直接判了 MD5-crypt 的死刑：一千万词的字典 0.31 小时跑完，也就是**半天不到就能试掉一部中等字典**。而 `/etc/shadow` 是不是 0644（[8.2](./8.2-shadow-file.md) 实测这台机器就是 0644）决定攻击者**能不能开始** —— 权限和算法是两道独立的门。
2. **`$5$`（SHA-256）比 `$6$`（SHA-512）还慢**（405 vs 656 次/秒）。这**违反直觉**，所以程序特意把它写成结论的一部分：`$6$` 摘要更长却更快，是 libxcrypt 的具体实现所致（轮函数结构不同）。**不要把「位数越大/摘要越长越慢」当定律** —— 强度只能实测，不能靠命名推。
3. **`$2b$08` 那一行只有 11 次、耗时 659 ms**，超过了 300 ms 的预算。原因很直接：单次耗时 ≈ 60 ms，循环体每次执行后才检查时间，所以最后一次必然冲出去。**这也说明 bcrypt 比两个 SHA 变种贵得多**（60 ms vs 1.5–2.5 ms），这正是它作为口令哈希的设计目标。
4. **第二张表是「纯算术推算」**，程序里写得很清楚：用的是**同一次运行实测到的 `rate[]`**，不是抄来的常数。第一版曾经用手抄常数导致与本次实测不符（差近一倍），改成同批数据推算之后才自洽 —— **笔记里凡是有"换算"的地方，都要指明分子分母是不是同一次测量**。
5. **`$2b$` 的 cost 每 +1 翻倍**：`cost=12 = rate[3] / 16`，于是从 6.94 天变成 110.97 天。这是 bcrypt/yescrypt 相对 MD5/SHA 家族的**结构性优势** —— 可以用一个参数把成本跟着硬件一起涨，而 `$1$`/`$5$`/`$6$` 只有 5000 轮这个几乎固定的值。

### c8_8 三个 `crypt()` 陷阱（含一个真实的安全漏洞）

完整程序见 [`../code/c8_8_crypt_traps.c`](../code/c8_8_crypt_traps.c)：静态缓冲、`*1` 哨兵、以及「错误口令也认证通过」的复现，最后给出正确的 `good_verify()`。

```c
/* c8_8_crypt_traps.c —— 8.5：crypt() 的三个坑，其中一个是安全漏洞
 *
 * 坑 1：crypt() 和 getpwnam() 一样返回静态缓冲 —— 前一次的结果会被后一次改写
 * 坑 2：把 crypt() 自己返回的指针当「盐」再喂回去，crypt() 会失败返回 "*1"
 * 坑 3：此时 strcmp(返回值, stored) 两边指向同一块内存 → 恒等 → 任何口令都"通过"
 *
 * 编译：cc -Wall -Wextra -o c8_8_crypt_traps c8_8_crypt_traps.c -lcrypt
 */
#define _DEFAULT_SOURCE
#include <crypt.h>
#include <stdio.h>
#include <string.h>

/* ❌ 看起来和原书 Listing 8-2 一模一样，但存的是 crypt() 自己的返回值时就废了 */
static int bad_verify(const char *password, const char *stored)
{
    return strcmp(crypt(password, stored), stored) == 0;
}

/* ✅ 正确写法：盐拷成副本、先挡锁定账号、再挡 *0 与 *1 这两个失败哨兵 */
static int good_verify(const char *password, const char *stored)
{
    char salt[256];

    if (password == NULL || stored == NULL)
        return 0;
    if (snprintf(salt, sizeof salt, "%s", stored) >= (int) sizeof salt)
        return 0;                       /* 密文长得离谱，直接拒绝 */
    if (salt[0] == '!' || salt[0] == '*')
        return 0;                       /* 锁定 / 无口令 */

    char *got = crypt(password, salt);
    if (got == NULL)
        return 0;
    if (got[0] == '*')
        return 0;                       /* crypt 失败（*0 / *1），绝不当成匹配 */

    return strcmp(got, salt) == 0;
}

int main(void)
{
    /* ---- 坑 1：静态缓冲 ---- */
    char *h1 = crypt("pw-one", "$6$saltAAAA");
    char keep1[256];
    snprintf(keep1, sizeof keep1, "%s", h1);    /* 先拷一份 */

    char *h2 = crypt("pw-two", "$6$saltBBBB");
    printf("h1=%p  h2=%p  (%s)\n", (void *) h1, (void *) h2,
           h1 == h2 ? "同一块内存" : "不同内存");
    printf("h1 现在指向的内容 = %.22s...\n", h1);
    printf("调用前拷下来的 keep1 = %.22s...\n", keep1);

    /* ---- 坑 2 + 坑 3：别名导致「任何口令都通过」 ---- */
    char *stored_ptr = crypt("secret123", "$6$rounds=5000$abc");
    char stored_copy[256];
    snprintf(stored_copy, sizeof stored_copy, "%s", stored_ptr);

    printf("\nstored_ptr（crypt 静态缓冲）= %.30s...\n", stored_ptr);
    printf("stored_copy（副本）          = %.30s...\n", stored_copy);

    printf("\n[❌ bad_verify] 直接把 crypt 的返回值当 stored\n");
    printf("bad_verify(\"definitely-wrong\", stored_ptr) = %d   <- 错口令本该返回 0\n",
           bad_verify("definitely-wrong", stored_ptr));
    printf("此刻 stored_ptr 的内容变成了 = %s\n", stored_ptr);

    printf("\n[✅ good_verify] 用副本，且检查哨兵\n");
    printf("good_verify(\"secret123\", stored_copy)        = %d\n",
           good_verify("secret123", stored_copy));
    printf("good_verify(\"definitely-wrong\", stored_copy) = %d\n",
           good_verify("definitely-wrong", stored_copy));
    printf("good_verify(\"x\", \"!\")   （锁定账号）          = %d\n",
           good_verify("x", "!"));
    printf("good_verify(\"x\", \"*\")   （无口令）            = %d\n",
           good_verify("x", "*"));

    puts("\n一句话：认证代码里绝不能把 crypt() 的返回值再当盐喂回去；");
    puts("        也不能只看 strcmp 的结果，必须先排除 *0/*1 与 !/* 这两类哨兵。");
    return 0;
}
```

编译与运行：

```bash

```

实测输出（另在 Compiler Explorer 复核，gcc 13.3）：

```text

h1 现在指向的内容 = $6$saltBBBB$NOcDoe/sX....
调用前拷下来的 keep1 = $6$saltAAAA$NZDX0Mh.I2...

stored_ptr（crypt 静态缓冲）= $6$rounds=5000$abc$yBlE3WPe8QG...
stored_copy（副本）          = $6$rounds=5000$abc$yBlE3WPe8QG...

[❌ bad_verify] 直接把 crypt 的返回值当 stored
bad_verify("definitely-wrong", stored_ptr) = 1   <- 错口令本该返回 0
此刻 stored_ptr 的内容变成了 = *1

[✅ good_verify] 用副本，且检查哨兵
good_verify("secret123", stored_copy)        = 1
good_verify("definitely-wrong", stored_copy) = 0
good_verify("x", "!")   （锁定账号）          = 0
good_verify("x", "*")   （无口令）            = 0

一句话：认证代码里绝不能把 crypt() 的返回值再当盐喂回去；
        也不能只看 strcmp 的结果，必须先排除 *0/*1 与 !/* 这两类哨兵。
```

**解读**

1. **前两行是坑 1 的证据**：`h1 == h2`（`0x7009aa8ea0e0`）。而且注意 `h1 现在指向的内容` 已经变成 `h2` 那次的 SHA-512 结果（`$6$saltBBBB$...`），只有**调用前拷下来的 `keep1`** 还留着 `$6$saltAAAA$...`。**`crypt()` 的返回值和 `getpwnam()` 一样是静态缓冲**（`crypt(3)`："The return value points to static data whose content is overwritten by each call."）。
2. **`bad_verify("definitely-wrong", stored_ptr) = 1`** —— 错误口令返回了「通过」。这是**功能级的安全漏洞**，不是理论风险。和 [8.4](./8.4-retrieving-info.md) 里 `getpwnam` 的静态缓冲是同一个根因，但后果严重得多：那边是数据被改写，这边是**认证被绕过**。
3. **`此刻 stored_ptr 的内容变成了 = *1`** 这一行补上了因果链的最后一环：`crypt()` 检测到输入以 `*0` 开头，于是**就地**把这块内存写成了 `*1`（`lib/util-make-failure-token.c` 里 `if (setting && setting[0] == '*' && setting[1] == '0') output[1] = '1';`）。于是 `strcmp` 的两边指向同一块内存，恒等成立。
   - 注意一个反直觉点：这里第一步的 `*0` **不是**因为口令错，而是因为 `stored` 是别的密文时 `crypt()` 把它当成了**盐**，而它不是合法盐格式 → 返回 `*0`。也就是说**漏洞的触发条件与口令内容无关**，只看「`stored` 和 `crypt()` 返回值是否同一块内存」。
4. **`good_verify` 四行全对**（1 / 0 / 0 / 0），其中后两行说明它也顺手挡住了 `shadow(5)` 的两种哨兵：`!`（锁定）和 `*`（无口令）。这是**纵深防御**：即使 `stored` 被污染成了 `!` 或 `*`，也不会出现「比较两边恰好相等」。
5. 一句话总结：**「先拷贝再比较」和「先排除哨兵再比较」两件事都要做**。只做前者，`stored` 是 `*0`（合法占位场景）时仍会 `*0 == *0`；只做后者，别名问题还在。

### c8_9 把整章串成一条认证流水线

完整程序见 [`../code/c8_9_auth_pipeline.c`](../code/c8_9_auth_pipeline.c)：原书 Listing 8-2 需要交互输入，**跑不了自动化测试**，所以这是它的可自动化等价物 —— 现算一份合成 shadow，再走 `fgetspent()` 读回来逐条验证。

```c
/* c8_9_auth_pipeline.c —— 8.5：把整章串成一条可自动跑的认证流水线
 *
 * 原书 Listing 8-2 需要交互输入，无法在评测环境里跑；本程序是它的
 * 可自动化等价物：自己造一份合成 shadow，再走 getspnam()/fgetspent()
 * 把记录读回来，逐条验证候选口令。
 *
 * 编译：cc -Wall -Wextra -o c8_9_auth_pipeline c8_9_auth_pipeline.c -lcrypt
 */
#define _DEFAULT_SOURCE
#include <crypt.h>
#include <pwd.h>
#include <shadow.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <time.h>

/* 安全版校验：副本作盐 + 排除锁定账号 + 排除 *0 与 *1 哨兵（同 c8_8_crypt_traps.c） */
static int verify(const char *password, const char *stored)
{
    char salt[256];

    if (password == NULL || stored == NULL)
        return 0;
    if (snprintf(salt, sizeof salt, "%s", stored) >= (int) sizeof salt)
        return 0;
    if (salt[0] == '!' || salt[0] == '*')
        return 0;

    char *got = crypt(password, salt);
    if (got == NULL || got[0] == '*')
        return 0;

    return strcmp(got, salt) == 0;
}

static int days_since_epoch(void)
{
    return (int) (time(NULL) / 86400);
}

int main(void)
{
    /* ---- 1. 造一份合成 shadow（alice 的密文现算） ---- */
    char alice_hash[256];
    snprintf(alice_hash, sizeof alice_hash, "%s", crypt("hunter2", "$6$tlpidemo$"));

    const char *sf = "/tmp/c8_shadow_pipeline";
    FILE *w = fopen(sf, "w");
    if (w == NULL) {
        perror("fopen for write");
        return 1;
    }
    fprintf(w, "alice:%s:%d:0:99999:7:14:21000\n", alice_hash, days_since_epoch());
    fputs("bob:!:19500:0:99999:7:::\n", w);         /* 锁定 */
    fputs("carol:*:19500:0:99999:7:::\n", w);       /* 无口令 */
    fclose(w);

    printf("今天距 1970-01-01 = %d 天\n", days_since_epoch());
    printf("alice 的密文（$6$ 前缀 = SHA-512-crypt）= %s\n\n", alice_hash);

    /* ---- 2. 走 shadow 查询路径读回来，逐条验证 ---- */
    struct { const char *user, *pw; } attempts[] = {
        { "alice", "hunter2" },     /* 正确 */
        { "alice", "Hunter2" },     /* 大小写不同 */
        { "alice", "" },            /* 空口令 */
        { "bob",   "hunter2" },     /* 账号被 ! 锁定 */
        { "carol", "hunter2" },     /* 账号被 * 禁用 */
    };

    FILE *f = fopen(sf, "r");
    struct spwd *sp;
    while (f != NULL && (sp = fgetspent(f)) != NULL) {
        int cnt = sp->sp_max;
        const char *policy = (cnt == 0 || cnt >= 99999)
                                 ? "永不过期（0 或 99999 都表示不检查）"
                                 : "有最长有效期";
        printf("账号 %-6s 密文前缀=%-4.4s 最长有效=%ld 天（%s）\n",
               sp->sp_namp, sp->sp_pwdp, sp->sp_max, policy);

        for (size_t i = 0; i < sizeof attempts / sizeof attempts[0]; i++) {
            if (strcmp(attempts[i].user, sp->sp_namp) != 0)
                continue;
            printf("   口令 \"%s\" -> %s\n", attempts[i].pw,
                   verify(attempts[i].pw, sp->sp_pwdp) ? "✅ 认证通过" : "❌ 拒绝");
        }
    }
    if (f != NULL)
        fclose(f);

    /* ---- 3. 真实环境对照：本容器以 root 运行，能读到真的 shadow ---- */
    puts("\n-- 真实 shadow（本容器） --");
    struct passwd *pw = getpwnam("ce");
    if (pw == NULL) {
        puts("getpwnam(\"ce\") 失败，跳过");
        return 0;
    }
    struct spwd *real = getspnam(pw->pw_name);
    if (real == NULL) {
        printf("getspnam(\"%s\") = NULL —— 普通用户读 shadow 会 errno=EACCES\n",
               pw->pw_name);
    } else {
        printf("%s 的密文 = %s\n", real->sp_namp, real->sp_pwdp);
        printf("前缀 $1$ = MD5-crypt。它的验证速度比 $6$ 快一个数量级（见 c8_7_crypt_cost.c\n");
        printf("里的同机实测表），所以这种哈希在字典攻击面前最脆弱 ——\n");
        printf("这正是现代发行版把默认算法换成 $6$/$y$ 的原因。\n");
        printf("账号未锁定：%s\n", verify("wrong-password", real->sp_pwdp) ? "错误口令也通过了（！）"
                                                                          : "错误口令被正确拒绝");
    }
    return 0;
}
```

编译与运行：

**解读**

1. **`alice` 的密文是现算的**：`crypt("hunter2", "$6$tlpidemo$")`。所以那串 `$6$tlpidemo$SHcfts...` 可以被任何人在任何机器上复现（盐是固定的 `tlpidemo`）—— 这也顺便印证了「**同盐同口令必然同结果**」，即「盐不等于密钥」。
2. **`"hunter2"` 通过、`"Hunter2"` 拒绝、`""` 拒绝**。第三行值得注意：**空口令不是"跳过验证"**，它会走完整的 `crypt("", salt)` 再比较 —— 因为 `alice` 的密文不是空串，必然不相等。反过来说，**如果 shadow 里那格是空的（`shadow(5)`："the user can log in without a password"），结论就完全相反**。空口令的安全性完全取决于文件里那一格，不取决于认证代码。
3. **`bob`（`!` 锁定）和 `carol`（`*` 无口令）都被拒绝**，走的是 `good_verify` 里的哨兵检查（第 ② 步），**根本不需要调用 `crypt()`**。这比"算了再比"更快也更安全。
4. **`最长有效=99999 天`** 是程序对 `sp_max` 的解读。注意这句注释里的坑：「0 或 99999 都表示不检查」。而 [8.2](./8.2-shadow-file.md) 说过空字段读回来是 **`-1`** —— 三种取值（`-1` / `0` / `99999`）语义各不相同，程序里只处理了后两种，属于**有意简化**，生产代码不能这么写。
5. **最后一段是真实环境对照**：`ce` 的密文是 `$1$rockyou$hty8SH9lK4mcCQXKENxaa1`。盐被起名叫 `rockyou`（经典口令字典名）基本等于明示「这份哈希是拿字典跑出来的」，而 `$1$`（MD5-crypt）在本容器上是 8910 次/秒（`c8_7`）。**「格式合法」和「安全」是两件事**：这行输出就是最好的例子。
6. 注意程序里 `verify("wrong-password", real->sp_pwdp)` 返回 0，打印「错误口令被正确拒绝」—— 说明 `ce` **没有被锁定**，`$1$...` 是真实可验证的密文，不是 `!` 占位。

### Listing 8-2：`check_password.c`（原书 p.164）

完整程序见 [`../code/check_password.c`](../code/check_password.c)。原书官方说明里它是 **Listing 8-2, page 164**，编译要 `-lcrypt`。

```c
/* check_password.c —— 原书 Listing 8-2（p.164）复刻版
 *
 * 读一个用户名 + 口令，与 /etc/shadow 里的密文比对。
 * 编译：cc -Wall -Wextra -o check_password check_password.c -lcrypt
 *
 * 与原书的差别（三处，主流程逐行保持原样）：
 *   1. 原书 #include "tlpi_hdr.h" 取 errExit()/fatal()/Boolean —— 本文件内联了
 *      最小等价实现（见文末），并显式补上原书由 tlpi_hdr.h 间接引入的
 *      <errno.h>/<stdio.h>/<stdlib.h>/<string.h>。
 *   2. 原书的宏块用 _BSD_SOURCE 取 getpass(3) 声明、_XOPEN_SOURCE 取 crypt()
 *      声明。glibc 2.20 起 _BSD_SOURCE 已废弃；按 man 3 crypt 的 Feature Test
 *      Macro 表，crypt() 自 glibc 2.28 起只需 _DEFAULT_SOURCE。
 *   3. Boolean authOk 改成 int authOk（省掉书中定义的 Boolean）。
 *
 * 注意：本程序必须交互输入（stdin 读到 EOF 即退出）。可自动化的等价物
 * 见 c8_9_auth_pipeline.c。
 */
/* Compile with -lcrypt */
#if ! defined(__sun)
#define _DEFAULT_SOURCE /* 原书用 _BSD_SOURCE + _XOPEN_SOURCE（均已过时） */
#endif
#include <unistd.h>
#include <limits.h>
#include <pwd.h>
#include <shadow.h>
#include <crypt.h>
#include <errno.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

static void errExit(const char *msg);
static void fatal(const char *msg);

int
main(int argc, char *argv[])
{
    char *username, *password, *encrypted, *p;
    struct passwd *pwd;
    struct spwd *spwd;
    int authOk;
    size_t len;
    long lnmax;

    /* Determine size of buffer required for a username, and allocate it */

    lnmax = sysconf(_SC_LOGIN_NAME_MAX);
    if (lnmax == -1)                    /* If limit is indeterminate */
        lnmax = 256;                    /* make a guess */

    username = malloc(lnmax);
    if (username == NULL)
        errExit("malloc");

    printf("Username: ");
    fflush(stdout);
    if (fgets(username, lnmax, stdin) == NULL)
        exit(EXIT_FAILURE);             /* Exit on EOF */

    len = strlen(username);
    if (username[len - 1] == '\n')
        username[len - 1] = '\0';       /* Remove trailing '\n' */

    /* Look up password and shadow password records for username */

    pwd = getpwnam(username);
    if (pwd == NULL)
        fatal("couldn't get password record");
    spwd = getspnam(username);
    if (spwd == NULL && errno == EACCES)
        fatal("no permission to read shadow password file");

    if (spwd != NULL)           /* If there is a shadow password record */
        pwd->pw_passwd = spwd->sp_pwdp;     /* Use the shadow password */

    password = getpass("Password: ");

    /* Encrypt password and erase cleartext version immediately */

    encrypted = crypt(password, pwd->pw_passwd);
    for (p = password; *p != '\0'; )
        *p++ = '\0';

    if (encrypted == NULL)
        errExit("crypt");

    authOk = strcmp(encrypted, pwd->pw_passwd) == 0;
    if (!authOk) {
        printf("Incorrect password\n");
        exit(EXIT_FAILURE);
    }

    printf("Successfully authenticated: UID=%ld\n", (long) pwd->pw_uid);

    /* Now do authenticated work... */

    exit(EXIT_SUCCESS);
}

/* ---- 以下是原书 tlpi_hdr.h 提供、本文件内联的最小等价实现 ---- */

static void
errExit(const char *msg)
{
    perror(msg);
    exit(EXIT_FAILURE);
}

static void
fatal(const char *msg)
{
    fprintf(stderr, "ERROR: %s\n", msg);
    exit(EXIT_FAILURE);
}
```

**与原书的三处差别**（主流程逐行保持原样）：

| # | 原书 | 本仓库 | 原因 |
|---|------|--------|------|
| 1 | `#include "tlpi_hdr.h"`（取 `errExit` / `fatal` / `Boolean`） | 内联最小等价实现，显式补 `<errno.h>` / `<stdio.h>` / `<stdlib.h>` / `<string.h>` | 书自带的公共头不在本仓库；行为等价 |
| 2 | `#define _BSD_SOURCE` + `#define _XOPEN_SOURCE`（`#if !defined(__sun)` 包着） | `#define _DEFAULT_SOURCE` | glibc 2.20 起 `_BSD_SOURCE` 已废弃；按 `crypt(3)` 的 Feature Test Macro 表，glibc ≥ 2.28 只需 `_DEFAULT_SOURCE` |
| 3 | `Boolean authOk;` | `int authOk;` | 省掉书里定义的 `Boolean`（本质就是 `int`） |

主流程一字未动，特别是这三处教学要点：

```c
spwd = getspnam(username);
if (spwd == NULL && errno == EACCES)
    fatal("no permission to read shadow password file");

if (spwd != NULL)                           /* If there is a shadow password record */
    pwd->pw_passwd = spwd->sp_pwdp;         /* Use the shadow password */

password = getpass("Password: ");

encrypted = crypt(password, pwd->pw_passwd);
for (p = password; *p != '\0'; )            /* 用完立刻抹掉明文 */
    *p++ = '\0';
```

三件事：① `getspnam` 失败要先看 `errno == EACCES`（对应 `getspnam(3)` ERRORS）；② **必须用 `sp_pwdp` 覆盖 `pw_passwd`** —— 否则拿到的是 8.1 里那个占位符 `"x"`，`crypt()` 会返回 `*0`；③ **比较完立刻把明文口令缓冲清零**（`getpass()` 返回的是静态缓冲，不清就会一直留在进程内存里）。

实测输出（另在 Compiler Explorer 复核，gcc 13.3，stdin 喂 `ce` + 错误口令；另一次喂 `nosuchuser`）：

```text
Username: Incorrect password
```

```text
Username: 
ERROR: couldn't get password record
```

两次运行都 `exit code = 1`，覆盖了两条失败路径：

- 第一次：`getpwnam`/`getspnam` 都成功（说明本容器**以 root 跑**，能读 0644 的 shadow），`crypt` 算出来不匹配 → `Incorrect password`。口令是从 stdin 读的（`getpass()` 在没有 tty 时回落到 stdin），所以 `Password:` 提示出现在 stderr。
- 第二次：`getpwnam("nosuchuser")` 返回 NULL → 走 `fatal()` → `ERROR: couldn't get password record`。注意 `fatal()` 用的是 `fprintf(stderr, ...)`，而 `errExit()` 用 `perror()` —— **这两个函数的区别就是"有没有 errno 可讲"**，原书的设计在这里体现得很清楚。

## HFT / 嵌入式关联

- **认证路径上不要用 `crypt()` 家族**。想自建校验，用 libsodium 的 `crypto_pwhash`（Argon2id）或至少 `crypt_r()` + yescrypt/bcrypt。`crypt()` 的接口契约本身就容易用错（静态缓冲 + `*0`/`*1`），错误代价是**整个认证被绕过**。
- **`$1$` 一律当"已经泄露"处理**。8910 次/秒意味着 8 位以内的小写字母+数字口令能在小时级被穷举。迁移方案是 `authconfig` / `pam_unix` 的 `sha512`（或 yescrypt）配合**下次登录时重算密文**，而不是全量重置口令。
- **空口令那格是运维红线**：`shadow(5)` 明说空串允许无口令登录，`passwd(5)` 说 `/etc/passwd` 里空串也一样。**CI 里加一条断言扫 `/etc/shadow` / `/etc/passwd` 第 2 字段是否为空**，成本很低，拦住的是一类极严重的配置事故。
- **FIPS 环境**：开了 `/proc/sys/crypto/fips_enabled` 之后 DES-crypt 直接 `EPERM`（`crypt(3)` ERRORS）。老系统升级到 FIPS 模式时，`/etc/shadow` 里的 `$1$` 甚至无前缀的密文会导致**所有登录失败**，而错误信息只是「口令错」。迁移前先统计算法分布。
- **嵌入式**：BusyBox 的 `crypt` 支持面比 libxcrypt 小得多（常见只有 DES 和 MD5）。在交叉编译环境里用 `$6$` 生成的密文，到板上可能直接 `*0`。**要么板上也用同一套 libxcrypt，要么统一算法**，别在构建机和目标机之间赌兼容性。
- **成本参数要跟着硬件走**。bcrypt 的 cost / yescrypt 的 `N/r/p` 应该按「单次验证 ≈ 50–100 ms」来定；本容器实测 bcrypt cost=8 已经 ~60 ms，cost=12 就是 ~960 ms —— 在同一台机器上给登录接口加 1 秒延迟，用户是能感觉到的。**安全参数和体验参数是同一个旋钮**。
- **`getpass()` 只能算"够用"**。它返回静态缓冲（原书那段清零 `for` 循环就是在处理这个），且不处理超长输入。生产代码用 `readpassphrase()` 或 `termios` 自己关回显。

## 自测题

<details>
<summary>1. 现代 glibc（≥ 2.28）上编译用 <code>crypt()</code> 的程序，该写哪个 feature test macro？</summary>

**`_DEFAULT_SOURCE`。**

`crypt(3)` 的 Feature Test Macro 原文：

> `crypt()`:
> **Since glibc 2.28: `_DEFAULT_SOURCE`**
> glibc 2.27 and earlier: `_XOPEN_SOURCE`

网上大量示例（以及 TLPI 原书 Listing 8-2）写的是 `_XOPEN_SOURCE`，那是 ≤ 2.27 的要求。在 glibc ≥ 2.28 上虽然还能编过，但已经**不是推荐写法**。

另外两件容易漏的：

- **glibc 2.39 已经不带 `crypt()` 实现**，改成依赖 libxcrypt（`crypt(3)` LIBRARY 段写的是 "Password hashing library (libcrypt, **-lcrypt**)"）。所以**必须链 `-lcrypt`**，并且要 `#include <crypt.h>` 拿原型 —— `crypt(3)` HISTORY 段明确要求「检测 `_XOPEN_CRYPT` 不可用时改用 `<crypt.h>`」。
- `crypt_r()` 要的是 `_GNU_SOURCE`，比 `crypt()` 的宏更严格。
</details>

<details>
<summary>2. <code>crypt()</code> 失败时一定返回 <code>NULL</code> 吗？</summary>

**不一定 —— 本容器实测返回的是字符串 `*0`。**

`crypt(3)` RETURN VALUE 确实写着 "On error, NULL is returned"，但那是 man-pages 项目的描述，**实际实现是 libxcrypt**。libxcrypt 4.4.36 `lib/util-make-failure-token.c` 里：

```c
output[0] = '*';
output[1] = '0';
output[2] = '\0';

if (setting && setting[0] == '*' && setting[1] == '0')
    output[1] = '1';
```

本节 `c8_6` 的实测印证了这一点：`$y$`（本容器的 libxcrypt 没启用 yescrypt）那一行返回 `密文 *0`、`长度 2`，**不是 NULL**。

所以认证代码的正确形态是**三种都挡**：

```c
char *got = crypt(password, salt);
if (got == NULL)    return 0;   /* man 说的那种失败 */
if (got[0] == '*')  return 0;   /* 实测到的 *0 / *1 */
```

只看 `NULL` 会在 libxcrypt 上放过 `*0`，而 `*0` 一旦和同样是 `*0` 的 `stored` 比较就成立了。
</details>

<details>
<summary>3. 这段代码有什么问题？<code>return strcmp(crypt(password, stored), stored) == 0;</code></summary>

**它会在特定条件下让任何口令都通过。**

这是本节 `c8_8` 复现的漏洞。触发条件不是「口令错」，而是 **`stored` 与 `crypt()` 的返回值是同一块内存**（`crypt()` 返回静态缓冲）：

1. `crypt(password, stored)` 把 `stored` 当**盐**。如果它不是合法盐格式（比如它本身是另一串 `$6$...` 之外的产物），libxcrypt 返回 **`*0`**，并**就地覆写**那块静态缓冲；
2. 但在此之前，如果静态缓冲里本来就存着 `*0`，`make_failure_token` 会返回 **`*1`**（`if (setting[0]=='*' && setting[1]=='0') output[1]='1';`）；
3. `strcmp(返回的指针, stored)` —— 两边**指向同一块内存**，`strcmp(x, x) == 0` 恒真 → 返回 1。

实测：`bad_verify("definitely-wrong", stored_ptr) = 1`（本该是 0），且随后 `stored_ptr` 的内容打印为 `*1`。

正确写法要同时做四件事（`good_verify`）：
1. 用 `snprintf` 把 `stored` **拷成副本**再当盐（切断别名）；
2. 先挡 `!` / `*` 开头（`shadow(5)` 的锁定 / 无口令语义）；
3. `got == NULL` 判失败；
4. **`got[0] == '*'` 判失败**（`*0` / `*1` 绝不能当成匹配）。
</details>

<details>
<summary>4. <code>$5$</code>（SHA-256）和 <code>$6$</code>（SHA-512）哪个更慢？</summary>

**按本容器实测：`$5$` 更慢，而且是明显更慢。**

```text
$5$abcdefgh                    122         301.5ms     2471.6 us       405
$6$abcdefgh                    197         300.4ms     1525.1 us       656
```

`$5$` 405 次/秒，`$6$` 656 次/秒 —— **摘要更长的 `$6$` 反而快约 60%**。这是 libxcrypt 的具体实现差异（SHA-256 与 SHA-512 的轮函数结构、以及 libxcrypt 对两者的展开方式不同），不是「位数越大越慢」的反例那么简单。

启示有两条：

- **强度只能实测，不能靠命名或长度推**。文档里能确定的只有格式（摘要 43 vs 86 字符）和默认轮数（都是 5000）。
- 但**这也不构成"选 `$5$` 更好"**：`$6$` 更快意味着攻击者也更快，同时它的摘要更长、抗碰撞余量更大。选型看的是「**验证成本**」这个可调量（轮数 / bcrypt cost），而不是摘要长度。
</details>

<details>
<summary>5. 为什么原书 Listing 8-2 要写 <code>pwd->pw_passwd = spwd->sp_pwdp;</code> 这一句？</summary>

**因为不写就会拿到占位符 `"x"`，`crypt()` 必然失败。**

`getpwnam()` 返回的 `struct passwd.pw_passwd` 来自 `/etc/passwd` 的第 2 字段。在用了 shadow 的系统上那格是 `x`（`passwd(5)`："This is either the encrypted user password, an asterisk (`*`), or the letter 'x'."），**真密文在 `/etc/shadow` 的 `sp_pwdp`**。

[8.1](./8.1-passwd-file.md) 的实测直接给出了这个值：`pw_passwd=x`。

原书那句的上下文是：

```c
spwd = getspnam(username);
if (spwd == NULL && errno == EACCES)
    fatal("no permission to read shadow password file");

if (spwd != NULL)                                /* If there is a shadow password record */
    pwd->pw_passwd = spwd->sp_pwdp;              /* Use the shadow password */
```

三个细节：

1. **是 `pwd->pw_passwd = ...`，不是修改 `spwd`** —— 往 `struct passwd` 里塞密文，后面 `crypt(password, pwd->pw_passwd)` 才拿到正确的盐。这也顺便绕开了「`getpwnam` 和 `getspnam` 各自有静态缓冲」的问题，因为之后只用一个指针。
2. **`spwd == NULL` 且 `errno == EACCES`** 才是「没权限读 shadow」；其他情况（比如用户根本没有 shadow 记录）不算致命，代码会继续用 `/etc/passwd` 里那一格。这个区分对应 `getspnam(3)` ERRORS 的 `EACCES` 条目。
3. 本容器的 shadow 是 **0644**（[8.2](./8.2-shadow-file.md)），所以以 root 跑时 `getspnam` 一定成功 —— 这条 `EACCES` 分支在评测环境里**走不到**。这提醒我们：**能跑通不等于分支被覆盖过**。
</details>
