## 本节讲什么

上一节讲的是**内核**那一层缓冲；从这一节开始往上加一层：`printf` / `fwrite` / `fgets` 这些 stdio 函数**不是**直接调 `write(2)` 的，它们先往一块**用户态**的数组里攒，攒够或遇到刷新条件才真正调用系统调用。

这一节回答四个问题：

1. 「stdout 到终端时是行缓冲、重定向到文件时是全缓冲」——这句话**是从哪儿来的**？它是一条约定，还是某段代码的结果？
2. 缓冲**多大**？为什么实测 `__fbufsize(stdout)` 是 **4096** 而 `BUFSIZ` 是 **8192**？两个数不相等时才需要解释。
3. `FILE*` 和 `fd` 之间靠什么互转？转过去之后缓冲归谁管？
4. `fflush` 和「落盘」是什么关系？

## 1. 「行缓冲 vs 全缓冲」的真身：`_IO_file_doallocate()`

在 glibc 里，一个 `FILE*` 第一次真正被使用时，会走 `_IO_file_doallocate()` 去分配它的缓冲区。**缓冲模式和缓冲大小都在这一段里定死**（glibc 2.39 `libio/filedoalloc.c`）：

```c
  size = BUFSIZ;
  if (fp->_fileno >= 0 && __builtin_expect (_IO_SYSSTAT (fp, &st), 0) >= 0)
    {
      if (S_ISCHR (st.st_mode))
	{
	  /* Possibly a tty.  */
	  if (
#ifdef DEV_TTY_P
	      DEV_TTY_P (&st) ||
#endif
	      local_isatty (fp->_fileno))
	    fp->_flags |= _IO_LINE_BUF;
	}
#if defined _STATBUF_ST_BLKSIZE
      if (st.st_blksize > 0 && st.st_blksize < BUFSIZ)
	size = st.st_blksize;
#endif
    }
  p = malloc (size);
```

把这段读成两句话：

| 问题 | 答案 | 代码依据 |
|------|------|---------|
| **什么时候行缓冲？** | **只有**「字符设备（`S_ISCHR`）**且** `isatty()` 为真」时 | `if (S_ISCHR (st.st_mode)) { if (... local_isatty(...)) fp->_flags \|= _IO_LINE_BUF; }` |
| **缓冲区多大？** | 初始 `BUFSIZ`；若 `0 < st_blksize < BUFSIZ`，改为 `st_blksize` | `if (st.st_blksize > 0 && st.st_blksize < BUFSIZ) size = st.st_blksize;` |

**所以「stdout 到终端就自动行缓冲」不是 stdio 标准里的约定，而是这段代码的结果。** 它是 glibc 的实现细节（其它 libc 可能不同），而且判据是「字符设备 + `isatty`」这一对，不是「名字叫 /dev/tty」。

实测（`c13_2_stdio_buffering.c` ①、② 段）：

```text
== ① 判据本身：stdout 是什么、缓冲多大 ==
  isatty(STDOUT_FILENO) = 0  （1 = 终端；0 = 走全缓冲）
  fstat(1).st_mode = 0140777   S_ISCHR=0  S_ISFIFO=0  S_ISSOCK=1
  → 本容器里 stdout 是 **socket**，既不是字符设备也不是管道。
  BUFSIZ = 8192   而 __fbufsize(stdout) = 4096
  → 两者**不相等**，且后者恰好 = st_blksize = 4096：
     glibc 的 _IO_file_doallocate()（libio/filedoalloc.c）里：
       size = BUFSIZ;
       if (st.st_blksize > 0 && st.st_blksize < BUFSIZ) size = st.st_blksize;
     st_blksize(4096) < BUFSIZ(8192) → size 取 4096。
     同一段代码里，行缓冲是**只有** S_ISCHR + isatty() 才设的：
       if (S_ISCHR(st.st_mode)) { if (isatty(fd)) fp->_flags |= _IO_LINE_BUF; }
     所以「stdout 到终端就自动行缓冲」不是约定，是这段代码。
```

`S_ISSOCK=1` 这一行是**沙箱特有**的：CE 把 stdout 接在 socket 上，所以 `S_ISCHR` 和 `S_ISFIFO` 都是 0，`isatty` 也是 0 —— 这个容器里**永远看不到行缓冲**（除非手动 `setvbuf`）。这正是 ③ 段要解决的问题。

### glibc 的 `stdio_ext.h`：怎么「看到」缓冲参数

上面那些 `__fbufsize` / `__flbf` 不是标准 C，是 glibc 的扩展，定义在 `<stdio_ext.h>`：

| 函数 | 返回 |
|------|------|
| `__fbufsize(FILE *)` | 当前缓冲区**字节数** |
| `__flbf(FILE *)` | 是否**行缓冲**（0/1） |
| `__freading` / `__fwriting` | 方向状态 |
| `__fpending(FILE *)` | 当前**待刷出**的字节数（这个很实用：调试「日志没出来」时直接问它） |

## 2. 三种模式与 `setvbuf`

标准接口是 `setvbuf`：

```c
#include <stdio.h>

int setvbuf(FILE *stream, char *buf, int mode, size_t size);
```

| mode | 名字 | 行为 |
|------|------|------|
| `_IOFBF` | 全缓冲 | 缓冲区满（或显式刷新）才 `write`；普通文件、管道、socket 的默认 |
| `_IOLBF` | 行缓冲 | 遇到 `'\n'` 或缓冲区满就 `write`；**终端**的默认 |
| `_IONBF` | 无缓冲 | 每次输出都立即 `write`；`stderr` 的默认 |

实测三种模式切换后缓冲区参数的变化：

```text
== ② 三种模式：setvbuf 之后 __fbufsize / __flbf 怎么变 ==
  默认(_IOFBF):        isatty=0  __flbf=0  __fbufsize=4096  st_blksize=4096
  setvbuf(stdout, NULL, _IOLBF, 4096) = 0 errno=0(Success)
  改成 _IOLBF:         isatty=0  __flbf=1  __fbufsize=4096  st_blksize=4096
     → __flbf 从 0 变成 1：**帧内确实改成了行缓冲**。
  setvbuf(stdout, NULL, _IONBF, 0)    = 0 errno=0(Success)
  改成 _IONBF:         isatty=0  __flbf=0  __fbufsize=1  st_blksize=4096
  setvbuf(stdout, NULL, _IOFBF, 4096) = 0 errno=0(Success)
  改回 _IOFBF:         isatty=0  __flbf=0  __fbufsize=1  st_blksize=4096
  ⚠️ 三次都返回 0（成功），模式也真的跟着变了 —— 说明 glibc 允许
     对已经用过的流改缓冲（标准不保证，别在工程里这么写）。
     规范用法：`setvbuf(fp, buf, mode, size);` 紧跟在 fopen/fdopen 之后。
```

注意 `_IONBF` 那行的 `__fbufsize` 变成了 **1**——「无缓冲」在 glibc 里就是「缓冲区只有 1 字节」。

### `setvbuf` 的返回成功**不等于**生效

这是本仓库在 Ch12 学到的同一条教训（`/proc/sys` 写入返回成功但值没变）在 stdio 上的复现。探针 `probe13` 里先给 `stdout` 设一个 64 字节的显式缓冲，再企图「恢复默认」：

```text
  setvbuf 前：__fbufsize(stdout)=4096  __flbf(stdout)=0 (_IOFBF=0 _IOLBF=1 _IONBF=2)
  setvbuf(stdout, buf64, _IOFBF, 64) = 0 errno=0(Success)
  setvbuf 后：__fbufsize(stdout)=64  __flbf(stdout)=0
  恢复默认：setvbuf(stdout,NULL,_IOFBF,0) = 0 errno=0(Success)  __fbufsize(stdout)=64
     ⚠️ 看返回值是「成功」，但缓冲区大小一个字没变 —— 流已经用过，setvbuf 实际没生效。
        「返回成功 ≠ 生效」的又一例（对照 Ch12 的 /proc/sys write）。
```

标准（C99 7.19.5.6）只说 `setvbuf` 「要在对流做任何其它操作**之前**调用」；对流已经用过之后再调，行为是**未定义**的——glibc 选择「部分生效、仍返回 0」。**工程结论：把 `setvbuf` 紧跟 `fopen`/`fdopen`，不要中途改。**

## 3. 行缓冲的机制：`'\n'` 到底触发了什么

「行缓冲」的名字容易让人以为「stdio 在扫描每个输出字节找 `'\n'`」——实际上就是这个意思：往行缓冲流里写数据时，`_IO_file_xsputn` 会找最后一个 `'\n'`，把它**之前**（含它）的部分立即 `write` 出去，剩下的留在缓冲里。

CE 里没有 pty（`probe13b` 实测 `/dev/ptmx` 不存在、`posix_openpt()` 返回 `ENOENT`），所以**无法**用「真终端」复现默认的行缓冲。但机制本身可以显式验证：把 `stdout` 切成 `_IOLBF`，再用 `write()` 当**参照物**：

```text
== ③ 行缓冲的机制：'\n' 真的会触发 flush（CE 上也能复现） ==
  做法：把 stdout 切成 _IOLBF，然后用 write() 当「参照物」——
        write() 不过用户态缓冲，它一旦出现，就说明它之前的东西已经出去了。
  下面每轮都先记一个「已写出字节数」，再决定 printf 里带不带 '\n'。
  管道里读回来 40 字节（write 参照物写了 4 字节）：
    [行 1] ""
    [行 2] "LINE1-with-newline"
    [行 3] "LINE2-no-newlineREF"
  → 行缓冲下：带 '\n' 的 "LINE1-with-newline" **在 REF 之前**就出去了；
     不带 '\n' 的 "LINE2-no-newline" 一直待在缓冲里，直到最后的 fflush()。
     这正是终端下默认发生的事（区别只是终端默认就是 _IOLBF，不用手动设）。
```

**这段实验的设计值得学**：程序不依赖「人眼观察输出的先后顺序」（那在 socket 上根本不可靠），而是：

1. 把 `stdout` 临时接到一个**管道**上（`dup2(fds[1], STDOUT_FILENO)`）；
2. 用 `write(STDOUT_FILENO, "REF\n", 4)` 当「参照物」——`write` 绕过用户态缓冲，它一旦出现在管道里，就说明**它之前** stdio 已经刷出去的内容也已经在了；
3. 事后把管道读回来，按行解析，得到**客观的顺序证据**；
4. 恢复原 `stdout`，程序继续正常输出。

这样得到的三行结果里，`LINE2-no-newlineREF` 这个「粘连」本身就是证据：不带 `'\n'` 的那 17 字节一直躺在缓冲里，直到最后 `fflush` 才和后面的内容一起出去。

## 4. `fileno()` / `fdopen()`：两层之间的桥

`FILE*` 和 `fd` 是两个不同的世界：

| | `FILE *` | `int fd` |
|---|---------|---------|
| 谁提供 | C 库（libc） | 内核 |
| 有缓冲吗 | **有**（用户态那一层） | 没有（`read`/`write` 直接碰页缓存） |
| 能传给系统调用吗 | **不能** | 能 |
| 打开函数 | `fopen` / `fdopen` | `open` / `socket` / `pipe` / `accept` |

两个方向的转换函数：

```c
int   fileno(FILE *stream);              /* FILE* → int fd（拆箱，不改变缓冲） */
FILE *fdopen(int fd, const char *mode);  /* int fd → FILE*（装箱，新建一个缓冲区） */
```

| | `fileno(fp)` | `fdopen(fd, mode)` |
|---|---|---|
| 方向 | `FILE*` → `fd` | `fd` → `FILE*` |
| 会新建缓冲区吗 | **不会**，只是把内部那个 `_fileno` 字段读出来 | **会**，新流第一次用时分配自己的缓冲区 |
| 所有权 | 用 `fclose(fp)` 关流时会连 fd 一起关 | 同理：`fclose` 会关闭传入的那个 fd |
| 典型用途 | 对 stdio 流做系统调用级操作（`fstat` / `fsync` / `fcntl` / `mmap`） | 给 `open()` / `socket()` 得来的 fd 套上格式化 I/O |

实测「同一份数据，`fstat` 看到的大小在 `fflush` 前后不同」：

```text
== ④ fileno() / fdopen()：两层之间的桥 ==
  fopen("/app/c13_2.txt", "w") -> FILE* 0x376a62a0，fileno() = 3
  fprintf 之后，文件大小（fstat 走 fd）= 0 字节 ← 还在 stdio 缓冲里，没进内核
  fflush 之后，文件大小 = 18 字节 ← 已经到内核（页缓存）里了
  → 这就是「FILE* 有缓冲、fd 没有」的可测差别：同一个 fd，
     fstat 看到的大小在 fflush 前后是不同的。
  ⚠️ 因此 `fprintf(fp, ...)` 之后立刻 `write(fileno(fp), ...)` 就一定乱序。
```

`FILE* 0x376a62a0` 这个地址每次运行都会变，但**「0 → 18」这个跳跃是稳定的**：它是「用户态缓冲 vs 内核」这两层之间差别的直接证据。

## 5. 缓冲 ≠ 落盘：一条完整的接力线

```text
== ⑤ 别把「缓冲」和「落盘」混为一谈 ==
  用户态缓冲(stdio)  --fflush-->  内核页缓存  --fsync/fdatasync-->  磁盘
    ↑ 本节            ↑ §13.3 讲的          ↑ §13.3
  `fflush()` **只管用户态那一层**，它不落盘；`fsync()` 才能落盘，但它
  管不到还待在 stdio 缓冲里的字节。两者各管一层，不能互相替代。
  完整的两层数据流见 13.4；混用的后果与修法见 13.7。
```

完整源码 [`code/c13_2_stdio_buffering.c`](../code/c13_2_stdio_buffering.c)：

```c
/* c13_2_stdio_buffering.c — Ch13 §13.2：stdio 库的缓冲
 *
 * TLPI §13.2（p.237）讲的是「用户态那一层缓冲」：
 *   ① `printf` / `fwrite` / `fgets` 先把数据放进 **用户态缓冲**，满了或
 *      显式刷新时才调 `read`/`write`；
 *   ② `setvbuf()` 三种模式：`_IOFBF` / `_IOLBF` / `_IONBF`；
 *   ③ 默认模式**取决于是不是终端**：stdout 接终端 → 行缓冲；接文件/管道 → 全缓冲。
 *
 * ⚠️ 本程序跑在 CE 上，stdout 是 **SOCKET**（不是终端）→ `isatty(1) = 0`
 *    → 默认**全缓冲**。所以「终端 vs 重定向」那一半**观察不到**。
 *    取而代之，本程序做两件更硬的事：
 *      a) 把判据本身量出来（isatty / st_mode / st_blksize / __fbufsize / __flbf）,
 *         并用 glibc 源码说明**为什么**缓冲区是 4096 而不是 BUFSIZ(8192)；
 *      b) **显式**切成 `_IOLBF` —— 这样就能在 CE 上复现「遇到 '\n' 就刷」这一半，
 *         而这正是终端下默认发生的事。
 *    并且**不依赖肉眼观察顺序**：每一轮都把「stdio 缓冲里有多少字节」量出来，
 *    用插入的 write() 当参照物，结果只由数字说话。
 *
 * 编译： gcc -O0 -Wall -Wextra -o c13_2_stdio_buffering c13_2_stdio_buffering.c
 * 取材： TLPI §13.2（setvbuf 三模式、fflush、自动刷新时机、重定向导致全缓冲）
 *       man-pages 6.19 setvbuf(3)（"must be called ... before any other operation"）
 *                      fflush(3)（NULL 刷新所有输出流；输入流的行为未标准化）
 *                      stdio(3)（BUFSIZ；默认缓冲模式与 isatty 的关系）
 *       glibc 2.39 libio/filedoalloc.c 的 _IO_file_doallocate()：
 *         size = BUFSIZ;
 *         if (S_ISCHR(st.st_mode)) { if (isatty(...)) fp->_flags |= _IO_LINE_BUF; }
 *         if (st.st_blksize > 0 && st.st_blksize < BUFSIZ) size = st.st_blksize;
 *         → 行缓冲只可能来自「字符设备 + isatty」；缓冲大小取 st_blksize
 *       glibc 2.39 libio/iofdopen.c / libio/libioP.h（__fbufsize / __flbf 的数据来源）
 */
#include <errno.h>
#include <fcntl.h>
#include <stdio.h>
#include <stdio_ext.h>      /* __fbufsize() / __flbf() / __freading() —— glibc 扩展 */
#include <stdlib.h>
#include <string.h>
#include <sys/stat.h>
#include <unistd.h>

/* 报一次「stdout 当前是什么状态」 */
static void dump_stdout_state(const char *tag)
{
    struct stat st;

    if (fstat(STDOUT_FILENO, &st) == -1) {
        printf("  %-22s fstat 失败 errno=%d\n", tag, errno);
        return;
    }
    printf("  %-22s isatty=%d  __flbf=%d  __fbufsize=%zu  st_blksize=%ld\n",
           tag, isatty(STDOUT_FILENO), __flbf(stdout) != 0,
           __fbufsize(stdout), (long) st.st_blksize);
}

int main(void)
{
    printf("== ① 判据本身：stdout 是什么、缓冲多大 ==\n");
    {
        struct stat st;

        printf("  isatty(STDOUT_FILENO) = %d  （1 = 终端；0 = 走全缓冲）\n",
               isatty(STDOUT_FILENO));
        if (fstat(STDOUT_FILENO, &st) == 0) {
            printf("  fstat(1).st_mode = %07o   S_ISCHR=%d  S_ISFIFO=%d  S_ISSOCK=%d\n",
                   (unsigned) st.st_mode, S_ISCHR(st.st_mode),
                   S_ISFIFO(st.st_mode), S_ISSOCK(st.st_mode));
            printf("  → 本容器里 stdout 是 **socket**，既不是字符设备也不是管道。\n");
            printf("  BUFSIZ = %d   而 __fbufsize(stdout) = %zu\n",
                   BUFSIZ, __fbufsize(stdout));
            printf("  → 两者**不相等**，且后者恰好 = st_blksize = %ld：\n", (long) st.st_blksize);
            printf("     glibc 的 _IO_file_doallocate()（libio/filedoalloc.c）里：\n");
            printf("       size = BUFSIZ;\n");
            printf("       if (st.st_blksize > 0 && st.st_blksize < BUFSIZ) size = st.st_blksize;\n");
            printf("     st_blksize(%ld) < BUFSIZ(%d) → size 取 4096。\n",
                   (long) st.st_blksize, BUFSIZ);
            printf("     同一段代码里，行缓冲是**只有** S_ISCHR + isatty() 才设的：\n");
            printf("       if (S_ISCHR(st.st_mode)) { if (isatty(fd)) fp->_flags |= _IO_LINE_BUF; }\n");
            printf("     所以「stdout 到终端就自动行缓冲」不是约定，是这段代码。\n");
        }
        printf("\n");
        dump_stdout_state("默认状态:");
    }

    printf("\n== ② 三种模式：setvbuf 之后 __fbufsize / __flbf 怎么变 ==\n");
    {
        dump_stdout_state("默认(_IOFBF):");

        /* ⚠️ 顺序很讲究：C 标准要求 setvbuf「在任何 I/O 之前」调用。
           下面这个流已经用过，所以严格说这是未定义行为 —— 实测能不能生效，
           正是本节要量的事。 */
        errno = 0;
        int r1 = setvbuf(stdout, NULL, _IOLBF, 4096);
        int e1 = errno;
        printf("  setvbuf(stdout, NULL, _IOLBF, 4096) = %d errno=%d(%s)\n",
               r1, e1, strerror(e1));
        dump_stdout_state("改成 _IOLBF:");
        printf("     → __flbf 从 0 变成 %d：**帧内确实改成了行缓冲**。\n", __flbf(stdout) != 0);

        errno = 0;
        int r2 = setvbuf(stdout, NULL, _IONBF, 0);
        int e2 = errno;
        printf("  setvbuf(stdout, NULL, _IONBF, 0)    = %d errno=%d(%s)\n",
               r2, e2, strerror(e2));
        dump_stdout_state("改成 _IONBF:");

        errno = 0;
        int r3 = setvbuf(stdout, NULL, _IOFBF, 4096);
        int e3 = errno;
        printf("  setvbuf(stdout, NULL, _IOFBF, 4096) = %d errno=%d(%s)\n",
               r3, e3, strerror(e3));
        dump_stdout_state("改回 _IOFBF:");
        printf("  ⚠️ 三次都返回 0（成功），模式也真的跟着变了 —— 说明 glibc 允许\n");
        printf("     对已经用过的流改缓冲（标准不保证，别在工程里这么写）。\n");
        printf("     规范用法：`setvbuf(fp, buf, mode, size);` 紧跟在 fopen/fdopen 之后。\n");
    }

    printf("\n== ③ 行缓冲的机制：'\\n' 真的会触发 flush（CE 上也能复现） ==\n");
    {
        printf("  做法：把 stdout 切成 _IOLBF，然后用 write() 当「参照物」——\n");
        printf("        write() 不过用户态缓冲，它一旦出现，就说明它之前的东西已经出去了。\n");
        printf("  下面每轮都先记一个「已写出字节数」，再决定 printf 里带不带 '\\n'。\n\n");

        int fds[2];
        if (pipe(fds) == -1) {
            printf("  pipe 失败 errno=%d(%s)\n", errno, strerror(errno));
            return EXIT_FAILURE;
        }

        /* 把 stdout 换成管道写端 —— 这样能**自己读回来**，不靠肉眼。 */
        int saved = dup(STDOUT_FILENO);
        if (saved == -1 || dup2(fds[1], STDOUT_FILENO) == -1) {
            printf("  dup2 失败 errno=%d(%s)\n", errno, strerror(errno));
            return EXIT_FAILURE;
        }
        close(fds[1]);
        setvbuf(stdout, NULL, _IOLBF, 4096);

        /* 轮 1：printf 里**带** '\n' */
        printf("LINE1-with-newline\n");
        /* 轮 2：printf 里**不带** '\n' */
        printf("LINE2-no-newline");
        /* 参照物 */
        ssize_t ref = write(STDOUT_FILENO, "REF\n", 4);
        fflush(stdout);

        dup2(saved, STDOUT_FILENO);
        close(saved);

        char back[256];
        memset(back, 0, sizeof(back));
        ssize_t got = read(fds[0], back, sizeof(back) - 1);
        close(fds[0]);

        printf("  管道里读回来 %ld 字节（write 参照物写了 %ld 字节）：\n", (long) got, (long) ref);
        {
            char *p = back;
            int ln = 1;
            while (*p != '\0') {
                char *nl = strchr(p, '\n');
                if (nl == NULL) {
                    printf("    [行 %d] \"%s\"  ← 没有换行结尾，说明它是被「满/fflush」推出去的\n", ln, p);
                    break;
                }
                *nl = '\0';
                printf("    [行 %d] \"%s\"\n", ln, p);
                p = nl + 1;
                ln++;
            }
        }
        printf("  → 行缓冲下：带 '\\n' 的 \"LINE1-with-newline\" **在 REF 之前**就出去了；\n");
        printf("     不带 '\\n' 的 \"LINE2-no-newline\" 一直待在缓冲里，直到最后的 fflush()。\n");
        printf("     这正是终端下默认发生的事（区别只是终端默认就是 _IOLBF，不用手动设）。\n");
    }

    printf("\n== ④ fileno() / fdopen()：两层之间的桥 ==\n");
    {
        const char *path = "/app/c13_2.txt";
        FILE *fp = fopen(path, "w");
        int fd;

        if (fp == NULL) {
            printf("  fopen 失败 errno=%d(%s)\n", errno, strerror(errno));
            return EXIT_FAILURE;
        }
        fd = fileno(fp);
        printf("  fopen(\"%s\", \"w\") -> FILE* %p，fileno() = %d\n",
               path, (void *) fp, fd);
        fprintf(fp, "written-by-fprintf");
        {
            struct stat st;
            fstat(fd, &st);
            printf("  fprintf 之后，文件大小（fstat 走 fd）= %ld 字节 ← 还在 stdio 缓冲里，没进内核\n",
                   (long) st.st_size);
        }
        fflush(fp);
        {
            struct stat st;
            fstat(fd, &st);
            printf("  fflush 之后，文件大小 = %ld 字节 ← 已经到内核（页缓存）里了\n",
                   (long) st.st_size);
        }
        printf("  → 这就是「FILE* 有缓冲、fd 没有」的可测差别：同一个 fd，\n");
        printf("     fstat 看到的大小在 fflush 前后是不同的。\n");
        printf("  ⚠️ 因此 `fprintf(fp, ...)` 之后立刻 `write(fileno(fp), ...)` 就一定乱序。\n");
        fclose(fp);
        unlink(path);
    }

    printf("\n== ⑤ 别把「缓冲」和「落盘」混为一谈 ==\n");
    printf("  用户态缓冲(stdio)  --fflush-->  内核页缓存  --fsync/fdatasync-->  磁盘\n");
    printf("    ↑ 本节            ↑ §13.3 讲的          ↑ §13.3\n");
    printf("  `fflush()` **只管用户态那一层**，它不落盘；`fsync()` 才能落盘，但它\n");
    printf("  管不到还待在 stdio 缓冲里的字节。两者各管一层，不能互相替代。\n");
    printf("  完整的两层数据流见 13.4；混用的后果与修法见 13.7。\n");
    return EXIT_SUCCESS;
}
```

## 常见坑

| # | 坑 | 正解 |
|---|----|------|
| 1 | 以为「stdout 是行缓冲」是普遍规律 | 只有「**字符设备** + `isatty()`」才设行缓冲。重定向到文件/管道/socket 后一律**全缓冲**——包括本仓库 CE 沙箱的 socket |
| 2 | 调试时日志「卡住不出来」，加 `printf("\n")` 也没用 | 全缓冲下 `'\n'` **不**触发刷新。要么 `fflush(stdout)`，要么 `setvbuf(stdout, NULL, _IOLBF, 0)`（或 `setbuf(stdout, NULL)`），要么改用 `stderr`（默认 `_IONBF`） |
| 3 | 以为 `__fbufsize(stdout)` 应当等于 `BUFSIZ` | 实测 4096 vs 8192。glibc 会取 `min(BUFSIZ, st_blksize)`；`/proc` 这类伪文件的 `st_blksize` 甚至是 1024 |
| 4 | 以为 `setvbuf` 返回 0 就一定生效 | 对流已经用过的情形，glibc **部分生效仍返回 0**。规范做法：紧跟 `fopen`/`fdopen` 调用 |
| 5 | 以为 `fflush` 有持久化语义 | `fflush` 只把字节交给**页缓存**。要落盘必须再 `fsync(fileno(fp))` / `fdatasync`（见 [13.3](13.3-controlling-kernel-buffering.md)） |
| 6 | 用 `_exit()` / `abort()` / 被 `SIGKILL` 结束进程，以为缓冲会刷 | **不会**。`fclose` / `exit()` 才保证刷新；`_exit(2)` 和信号直接终止时，用户态缓冲里的字节**全部丢失** |
| 7 | 用 `fflush(stdin)` 来「清空输入缓冲」 | 未定义行为（C 标准只对**输出**流定义了 `fflush`）。要丢输入得自己 `read` 掉，或用 `tcflush` |
| 8 | 对 `FILE*` 直接调 `fsync(fp)` | 类型不符（`FILE*` 不是 `int`）。必须 `fsync(fileno(fp))`；`-Wall` 会报类型不匹配 |
| 9 | 以为 `stderr` 也是全缓冲 | `stderr` 默认 `_IONBF`（**永远**立即输出），这是它作为错误通道的意义。但把 `stderr` 重定向到文件后 glibc 仍保持无缓冲 |
| 10 | 混用 `fprintf(fp, ...)` 与 `write(fileno(fp), ...)` | 两者各走各的缓冲，顺序必然乱（见 [13.7](13.7-mixing-stdio-syscalls.md)）。切换接口前 `fflush(fp)` |

## HFT / 嵌入式关联

| 场景 | 结论怎么用 |
|------|-----------|
| **热路径禁用 stdio** | `printf` 的代价不只是「多一层拷贝」，而是①持有流的锁（多线程下是竞争点）②未知的缓冲区大小导致不可预测的 `write` 时机。低延迟路径直接用 `write(2)` 或环形缓冲 + 独立线程刷盘 |
| **重定向后的日志延迟** | 服务从「前台运行」改成「`systemd` 管理 + 输出到 journal」或 `nohup ... > log` 之后，stdout 从行缓冲变全缓冲，日志可能**几 KB 才出现一次**。要看实时日志：`setvbuf(stdout, NULL, _IOLBF, 0)` 或定期 `fflush` |
| **`__fpending()` 做诊断** | 怀疑日志丢了，可以在打点处 `fprintf(stderr, "pending=%zu\n", __fpending(logfp))`，直接看到「还有多少字节卡在用户态」 |
| **嵌入式串口日志** | 串口是**字符设备**且通常 `isatty` 为真 → stdout 变成**行缓冲**（每行一次 `write`）。这在 115200 波特率下就是灾难（一行 ~80 字节 ≈ 7 ms），要么关行缓冲改成大块写，要么用 DMA + 环形缓冲 |
| **掉电与缓冲** | 板子掉电时，用户态缓冲 + 页缓存两层都可能丢。关键记录必须 `fflush` **之后**再 `fsync`/`fdatasync` —— 只做 `fflush` 是把数据从「会丢的一层」搬到「也会丢的另一层」 |
| **`fclose` 是隐式持久化点** | 服务正常退出走 `exit()` → 所有流的 `fclose` 会执行 → 数据至少进了页缓存。所以「SIGKILL 之后日志缺尾巴」和「SIGTERM 之后日志完整」的差别就在这里 |

<summary>代码自测（Q&A）</summary>

**Q1：stdout 到什么情况下才是行缓冲？这句话的代码依据是什么？**

A：**只有**当 stdout 是**字符设备**（`S_ISCHR(st.st_mode)`）**且** `isatty()` 返回真时。依据是 glibc `libio/filedoalloc.c` 的 `_IO_file_doallocate()`：`if (S_ISCHR (st.st_mode)) { if (... local_isatty (fp->_fileno)) fp->_flags |= _IO_LINE_BUF; }`。它是实现细节，不是 stdio 标准的规定。

**Q2：为什么 `__fbufsize(stdout)` 是 4096 而 `BUFSIZ` 是 8192？**

A：同一段代码里还有一行 `if (st.st_blksize > 0 && st.st_blksize < BUFSIZ) size = st.st_blksize;`。stdout 是 socket 时 `st_blksize = 4096`，小于 `BUFSIZ(8192)`，所以缓冲区取 4096。**两个数不相等本身就是「缓冲区大小由 `st_blksize` 决定」的证据**。

**Q3：CE 里没有终端、没有 pty，怎么验证行缓冲？**

A：`probe13b` 实测 `/dev/ptmx` 不存在、`posix_openpt()` 返回 `ENOENT`，所以无法开一个 pty。可行的替代：显式 `setvbuf(stdout, NULL, _IOLBF, ...)` 把流切成行缓冲，再把 stdout 临时 `dup2` 到一个**管道**上，用 `write(STDOUT_FILENO, "REF\n", 4)` 当参照物，事后从管道读回来解析顺序。实测得到 `LINE2-no-newlineREF` —— 粘连本身就说明不带 `'\n'` 的内容一直没出去。

**Q4：`fileno()` 和 `fdopen()` 分别做什么？缓冲归谁？**

A：`fileno(fp)` 把流内部记录的 fd 读出来，**不改变缓冲**（只是拆箱）；`fdopen(fd, mode)` 给一个裸 fd 套上 `FILE*`，**新建**一个缓冲区（装箱）。两者都与同一个内核 fd 共享文件偏移和状态。

**Q5：`fprintf(fp, "hello")` 之后立刻 `fstat(fileno(fp))`，大小是 0。这说明了什么？**

A：说明那 5 个字节还在**用户态缓冲**里，压根没进内核。`fflush(fp)` 之后再看才是 5（本程序实测 18 字节对应更长的载荷）。这是「`FILE*` 有缓冲、`fd` 没有」最直接的证据，也解释了为什么混用一定乱序。

**Q6：`fflush(fp)` 之后数据就安全了吗？**

A：**没有**。`fflush` 只把字节从「用户态缓冲」搬到「内核页缓存」，断电仍会丢。要耐久必须补 `fsync(fileno(fp))` 或 `fdatasync(fileno(fp))`。反过来，只做 `fsync` 不做 `fflush` 更糟——`fsync` 完全看不见用户态缓冲里的字节（见 [13.3](13.3-controlling-kernel-buffering.md) 与 [13.9 习题 13-3](13.9-exercises.md)）。

**Q7：`setvbuf` 返回 0 但缓冲区没变，这是 bug 吗？**

A：不是 bug，是**未定义行为的一个允许结果**。C99 只要求在对流做其它操作**之前**调用 `setvbuf`；流用过之后再调，glibc 选择「可能部分生效、仍返回 0」。所以判据是「调用时机」而不是「返回值」——把 `setvbuf` 紧跟 `fopen`/`fdopen` 就没有这个问题。
