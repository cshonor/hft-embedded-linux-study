## 本节讲什么

前三节分别讲了「内核那一层」「用户态那一层」「怎么把数据推下去」。这一节把它们**合起来**，回答一个操作性问题：

> **给定一个时刻，我怎么知道数据在哪一层？** 以及**怎么用程序把这件事量出来**？

原书这一段是全章的枢纽：它把「两层缓冲 + 若干刷新点」整理成一条统一的数据流，之后 13.5（访问模式提示）和 13.6（Direct I/O）都是在这条线上做文章。

## 1. 全章唯一的「层」模型

```text
                应用代码
                   │
    ┌──────────────┴───────────────┐
    │  stdio 函数（fprintf/fwrite）│       ← 13.2
    │  用户态缓冲（FILE* 内）      │
    └──────────────┬───────────────┘
                   │ fflush()        ← 13.2
    ┌──────────────┴───────────────┐
    │  read(2) / write(2)          │       ← 13.1
    │  内核页缓存（page cache）    │
    └──────────────┬───────────────┘
                   │ fsync() / fdatasync() / sync() / O_SYNC   ← 13.3
              [ 块设备 / 介质 ]
                   ▲
                   └── O_DIRECT（绕过整条上层）  ← 13.6
```

把这张图记成三个「接口」和三个「刷新点」：

| 接口 | 在哪两层之间 | 谁调用 |
|------|-------------|--------|
| `fprintf` / `fwrite` / `fgets` | 应用 ↔ **用户态缓冲** | 你的代码 |
| `read(2)` / `write(2)` | 用户态缓冲 ↔ **内核页缓存** | 你的代码**或** stdio 内部 |
| 设备写回（writeback） | 内核页缓存 ↔ **介质** | 内核（flusher 或限流触发） |

| 刷新点 | 跨越哪一层 | 由谁发起 |
|--------|-----------|---------|
| `fflush(fp)` | 用户态缓冲 → 页缓存 | 你（或 `fclose` / `exit`） |
| `fsync(fd)` / `fdatasync(fd)` | 页缓存 → 介质 | 你 |
| `fclose(fp)` | **隐式 `fflush`**（**不** `fsync`） | 你（或 `exit`） |

> **`fclose` 只做前一层。** 这是最常见的误解：以为「文件关了所以数据安全了」。实际上 `fclose` 之后数据通常只在页缓存里。

## 2. 用程序把「数据在哪一层」量出来

「数据在哪一层」是一个**可以客观测量**的量。判据不是「我看没看见」，而是**另一个进程/另一个 fd 能不能看见**：

- 字节还在**用户态缓冲**里 → 别的 fd 看不到（`st_size` 还是 0）；
- 字节到了**页缓存** → 别的 fd 立刻看得到（`st_size` 变了）；
- 字节到了**介质** → 别的 fd 看到的**没有变化**（因为页缓存不清）。

`c13_4_two_layers.c` 就用这个判据走了一遍五级阶梯（载荷 16 字节）：

```text
== 用「另一个 fd 能看见多少」来定位数据在哪一层 ==
  载荷 = "0123456789ABCDEF"（16 字节）
  列的含义：'别处可见' = 另开 O_RDONLY fd 实际读到的字节数；
            '文件大小' = 另开 fd 的 st_size；'nr_dirty' = 整机脏页数

  0. 文件还不存在              别处可见 -1 字节  文件大小 -1  nr_dirty=14
                                       ↳ 数据在：——
  已 fopen("/app/c13_4.txt", "w")，fileno(fp)=3

  1. fprintf 之后（未 fflush）  别处可见  0 字节  文件大小  0  nr_dirty=14
                                       ↳ 数据在：**用户态 stdio 缓冲**里
  2. fflush 之后                   别处可见 16 字节  文件大小 16  nr_dirty=14
                                       ↳ 内容是 [0123456789ABCDEF]
                                       ↳ 数据在：**内核页缓存**里（stdio 缓冲已空）

  fsync(fileno(fp)) = 0 errno=0(Success)
  3. fsync 之后                    别处可见 16 字节  文件大小 16  nr_dirty=14
                                       ↳ 内容是 [0123456789ABCDEF]
                                       ↳ 数据在：页缓存 **和** 磁盘上都有（页缓存不清）
  4. fclose 之后（它会隐式 fflush） 别处可见 16 字节  文件大小 16  nr_dirty=14
                                       ↳ 内容是 [0123456789ABCDEF]
                                       ↳ 数据在：页缓存 + 磁盘（同上）
```

读出这五级的三条结论：

```text
== 这张阶梯说明了什么 ==
  ┌ 第 0 级 → 1 级：fprintf 只是把字节拷进用户态数组，**外部完全看不见**
  ├ 第 1 级 → 2 级：fflush 把字节交给内核，**外部立刻可见**（这就是页缓存）
  ├ 第 2 级 → 3 级：fsync 让数据到达设备；但「外部可见性」**不再变化**
  │   → 所以「看得见」只能证明「至少到了页缓存」，**证明不了已落盘**：
  │     要判落盘只能看 nr_dirty / Dirty 这类**内核侧计数器**，或者换台机器验。
  └ 第 3 级 → 4 级：fclose 会隐式 fflush（标准规定），所以不 fflush 也不 fclose
     就该怀疑丢数据 —— 那正是「进程被 SIGKILL 掉」时的情形。

  ⚠️ 每一级的 nr_dirty 都可能被别的进程干扰（整机口径），
     而且 16 字节远小于一页，脏页计数在这么小的量上**看不出变化**。
     这里诚实地记下来：小 IO 下 nr_dirty 不是有效指标，用 st_size 与可见性判断。
```

> ⚠️ **这里的 `nr_dirty=14` 全程不变，是刻意的诚实**：16 字节远小于一页（4096 字节），脏页计数在这个量级上无法分辨。**这一节用错指标就会得出错误结论**——正确的判据是「另一个 fd 的 `st_size` 与内容」。而在 [13.1](13.1-buffer-page-cache.md) 的 16 MiB 实验里，`nr_dirty` 才是有效指标。**同一组计数器，用在不同量级的 I/O 上要换判据。**

## 3. 两条链路的完整写法

```text
== 两条链路的完整写法 ==
  写：fprintf -> [stdio buf] -fflush-> [page cache] -fsync-> disk
  读：read    <- [page cache] <- 设备      （stdio 侧：fgets <- [stdio buf] <- read）
  ⚠️ 读方向有个容易漏的点：stdio 的读缓冲是**预读**的。
     你对一个 FILE* 调 fread(buf, 1, 1, fp)，内核那边可能被要求读了
     一整个 st_blksize（本机 4096）—— 所以「读了多少」在两层里是不同的数。
     要看这种差异就得用 `read(fileno(fp), ...)` 绕开 stdio，或者用 strace。
```

把「写」方向的每一段对应到具体调用：

| 位置 | 数据在哪 | 怎么把它推进下一层 |
|------|---------|-------------------|
| `fprintf` 返回后 | 用户态缓冲 | `fflush(fp)` |
| `fflush` 返回后 | 页缓存 | `fsync(fd)` / `fdatasync(fd)` |
| `fsync` 返回后 | 介质（也仍在页缓存里） | —— 已到底 |

「读」方向多一个容易漏的点：**stdio 读缓冲是预读的**。`fgets` / `fread` 会向内核请求「一整块」（通常是 `st_blksize`），所以「应用请求的字节数」和「内核实际读的字节数」不相等。这就是为什么 `fread(fp, 1, 1, fp)` 在 `strace` 下看着像读了一大片。

## 4. 一张判定表：我该调什么

| 我想达到的效果 | 该调的 | 不该调的 |
|---------------|-------|---------|
| 让别的进程**看到**我写的数据（共享日志、跨进程通知） | `fflush(fp)` | `fsync`（更慢且没必要） |
| 让数据在**断电后**还在 | `fflush(fp)` **然后** `fsync(fileno(fp))` | 只 `fflush`、只 `fsync`（前者丢在页缓存，后者看不见用户态） |
| 只刷数据、不关心时间戳 | `fdatasync(fileno(fp))` | —— |
| 让**每一次** `write` 都落盘 | 打开时 `O_SYNC` / `O_DSYNC`，并且**加大块** | 事后只 `fcntl` 加 `O_SYNC` 而不管 stdio 缓冲 |
| 提高吞吐（可容忍少量丢失） | 加大块、让内核延迟写 | 无脑挂 `O_SYNC` |
| 把数据从用户态直接交给设备、不进页缓存 | `O_DIRECT`（见 [13.6](13.6-direct-io.md)）+ 对齐 | —— |
| 给内核一个访问模式的提示 | `posix_fadvise()`（见 [13.5](13.5-advising-kernel.md)） | 把它当命令使（它只是建议，也可能返回 0 而不生效） |

完整源码 [`code/c13_4_two_layers.c`](../code/c13_4_two_layers.c)：

```c
/* c13_4_two_layers.c — Ch13 §13.4：I/O 缓冲总结（两层数据流，逐级量出来）
 *
 * TLPI §13.4（p.243）把前面三节合成一张图：
 *
 *   写：应用 → [stdio 缓冲] --fflush--> [内核页缓存] --fsync/fdatasync--> 磁盘
 *   读：磁盘 → [内核页缓存] --read----> [stdio 缓冲] --fgets/fread------> 应用
 *
 * 这张图人人都能背，但「某一刻数据到底在哪一层」很少被真量过。
 * 本程序用**外部探针**逐级问同一个问题：
 *   「另开一个 fd 去看这个文件，能看见多少字节？」
 * 因为 stdio 的缓冲、内核的页缓存、磁盘三者对外部观察者的可见性**层层不同**，
 * 所以这个探针能把「数据在哪一层」一格一格地量出来。
 *
 * 每一级同时记录 /proc/vmstat 的 nr_dirty（整机脏页数），
 * 用来区分「进了页缓存」与「落到磁盘」。
 *
 * 编译： gcc -O0 -Wall -Wextra -o c13_4_two_layers c13_4_two_layers.c
 * 取材： TLPI §13.4（Figure 13-2 / 13-3 的两层数据流）
 *       man-pages 6.19 fflush(3)（只刷 stdio 缓冲，不落盘）
 *                      fsync(2)（把 in-core 数据交给存储设备）
 *       Linux v6.6 fs/sync.c:180-190（vfs_fsync_range）
 *                      mm/page-writeback.c（nr_dirty 的维护与 writeback 触发）
 */
#define _GNU_SOURCE
#include <errno.h>
#include <fcntl.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <sys/stat.h>
#include <unistd.h>

#define F1 "/app/c13_4.txt"
#define PAYLOAD "0123456789ABCDEF"

static long vmstat_val(const char *key)
{
    FILE *fp = fopen("/proc/vmstat", "r");
    char line[256];
    long v = -1;

    if (fp == NULL)
        return -1;
    while (fgets(line, sizeof(line), fp) != NULL) {
        if (strncmp(line, key, strlen(key)) == 0) {
            if (sscanf(line + strlen(key), " %ld", &v) != 1)
                v = -2;
            break;
        }
    }
    fclose(fp);
    return v;
}

/* 外部探针：另开一个 fd 读文件，返回实际能读到的字节数（并回填内容） */
static long probe_seen_by_other_fd(char *out, size_t cap)
{
    int fd = open(F1, O_RDONLY);
    ssize_t n;

    if (fd == -1)
        return -1;
    memset(out, 0, cap);
    n = read(fd, out, cap - 1);
    close(fd);
    return n < 0 ? -1 : (long) n;
}

/* 外部探针 2：另开一个 fd 看 st_size（不用 close 写端，看的是页缓存的元数据） */
static long probe_size_by_other_fd(void)
{
    struct stat st;
    int fd = open(F1, O_RDONLY);
    long sz;

    if (fd == -1)
        return -1;
    if (fstat(fd, &st) == -1)
        sz = -1;
    else
        sz = (long) st.st_size;
    close(fd);
    return sz;
}

static void report(const char *stage, const char *where)
{
    char seen[64];
    long n = probe_seen_by_other_fd(seen, sizeof(seen));

    printf("  %-34s 别处可见 %2ld 字节  文件大小 %2ld  nr_dirty=%ld\n",
           stage, n, probe_size_by_other_fd(), vmstat_val("nr_dirty"));
    if (n > 0)
        printf("  %-34s   ↳ 内容是 [%s]\n", "", seen);
    printf("  %-34s   ↳ 数据在：%s\n", "", where);
}

int main(void)
{
    const size_t LEN = strlen(PAYLOAD);

    printf("== 用「另一个 fd 能看见多少」来定位数据在哪一层 ==\n");
    printf("  载荷 = \"%s\"（%zu 字节）\n", PAYLOAD, LEN);
    printf("  列的含义：'别处可见' = 另开 O_RDONLY fd 实际读到的字节数；\n");
    printf("            '文件大小' = 另开 fd 的 st_size；'nr_dirty' = 整机脏页数\n\n");

    unlink(F1);
    report("0. 文件还不存在", "——");

    FILE *fp = fopen(F1, "w");
    int fd;
    if (fp == NULL) {
        printf("  fopen 失败 errno=%d(%s)\n", errno, strerror(errno));
        return EXIT_FAILURE;
    }
    fd = fileno(fp);
    printf("  已 fopen(\"%s\", \"w\")，fileno(fp)=%d\n\n", F1, fd);

    fprintf(fp, "%s", PAYLOAD);
    report("1. fprintf 之后（未 fflush）", "**用户态 stdio 缓冲**里");

    fflush(fp);
    report("2. fflush 之后", "**内核页缓存**里（stdio 缓冲已空）");

    errno = 0;
    int fr = fsync(fd);
    printf("\n  fsync(fileno(fp)) = %d errno=%d(%s)\n", fr, errno, strerror(errno));
    report("3. fsync 之后", "页缓存 **和** 磁盘上都有（页缓存不清）");

    fclose(fp);
    report("4. fclose 之后（它会隐式 fflush）", "页缓存 + 磁盘（同上）");

    printf("\n== 这张阶梯说明了什么 ==\n");
    printf("  ┌ 第 0 级 → 1 级：fprintf 只是把字节拷进用户态数组，**外部完全看不见**\n");
    printf("  ├ 第 1 级 → 2 级：fflush 把字节交给内核，**外部立刻可见**（这就是页缓存）\n");
    printf("  ├ 第 2 级 → 3 级：fsync 让数据到达设备；但「外部可见性」**不再变化**\n");
    printf("  │   → 所以「看得见」只能证明「至少到了页缓存」，**证明不了已落盘**：\n");
    printf("  │     要判落盘只能看 nr_dirty / Dirty 这类**内核侧计数器**，或者换台机器验。\n");
    printf("  └ 第 3 级 → 4 级：fclose 会隐式 fflush（标准规定），所以不 fflush 也不 fclose\n");
    printf("     就该怀疑丢数据 —— 那正是「进程被 SIGKILL 掉」时的情形。\n");
    printf("\n  ⚠️ 每一级的 nr_dirty 都可能被别的进程干扰（整机口径），\n");
    printf("     而且 16 字节远小于一页，脏页计数在这么小的量上**看不出变化**。\n");
    printf("     这里诚实地记下来：小 IO 下 nr_dirty 不是有效指标，用 st_size 与可见性判断。\n");

    printf("\n== 两条链路的完整写法 ==\n");
    printf("  写：fprintf -> [stdio buf] -fflush-> [page cache] -fsync-> disk\n");
    printf("  读：read    <- [page cache] <- 设备      （stdio 侧：fgets <- [stdio buf] <- read）\n");
    printf("  ⚠️ 读方向有个容易漏的点：stdio 的读缓冲是**预读**的。\n");
    printf("     你对一个 FILE* 调 fread(buf, 1, 1, fp)，内核那边可能被要求读了\n");
    printf("     一整个 st_blksize（本机 4096）—— 所以「读了多少」在两层里是不同的数。\n");
    printf("     要看这种差异就得用 `read(fileno(fp), ...)` 绕开 stdio，或者用 strace。\n");

    unlink(F1);
    return EXIT_SUCCESS;
}
```

## 常见坑

| # | 坑 | 正解 |
|---|----|------|
| 1 | 以为「文件关了」就等于「数据安全了」 | `fclose` 只做隐式 `fflush`（→ 页缓存），**不** `fsync`。要耐久必须显式 `fsync` |
| 2 | 用「另一个 fd 能读到」当落盘证据 | 看到的只是**页缓存**。落盘是不可见的（第 2 级 → 第 3 级外部表现零变化） |
| 3 | 在小 IO 上用脏页计数器判断 | 16 字节远小于一页，`nr_dirty` 看不出变化（本节实测全程 14）。小 IO 用 `st_size` / 可见性；大 IO 才用计数器 |
| 4 | 把 `errno` 当 `fflush` / `fsync` 的唯一判据 | 两者都要看**返回值**：`fflush` 返回 `EOF` 才是失败；`fsync` 返回 `-1` 才是失败。而 [`posix_fadvise`](13.5-advising-kernel.md) 连 `errno` 都不设 |
| 5 | 以为读方向「请求多少就读多少」 | stdio 读缓冲会预读整块（本机 `st_blksize = 4096`）。`fread` 1 字节 → 内核侧看到的是 4096 字节 |
| 6 | 用 `_exit()` / 被 `SIGKILL` 结束进程，指望缓冲刷出 | 用户态缓冲**直接丢失**。`exit()` / 正常 `return` 才会跑 `fclose` 那一轮 |
| 7 | 以为「两层缓冲」只是多一次拷贝 | 两层的**语义不同**：一层管「攒大小块」，一层管「合并磁盘写」；两层的**刷新点分属不同接口**，搞混就会写出「`fflush` 了但没落盘」这类代码 |

## HFT / 嵌入式关联

| 场景 | 结论怎么用 |
|------|-----------|
| **「数据到哪一层」是排查第一问** | 日志丢了/重复了，先问「在哪一层丢的」：用户态（进程被杀、没 `fflush`）、页缓存（断电、没 `fsync`）、介质（设备缓存、没 flush）——三层三套修法 |
| **跨进程可见 vs 持久化** | 同一个进程组内通知用 `fflush` 就够（对方看页缓存）；要过掉电就必须 `fsync`。把这两件事分开，能省掉大量无谓的 `fsync` |
| **读写缓冲不对称** | 写方向你控制块大小；读方向 stdio 会**预读**。做「按需读大文件」的程序时，stdio 的预读可能带来意想不到的 I/O 放大（尤其随机读场景），这时用 `posix_fadvise(POSIX_FADV_RANDOM)` 或绕开 stdio |
| **嵌入式 flash** | 两层缓冲都是为了「合并小写」；对 flash 来说合并能显著减少擦写。所以嵌入式上应该**加大**缓冲而不是关掉 —— 除非是掉电关键数据 |
| **`fclose` 与 `exit()`** | 服务优雅退出走 `exit()` → `fclose` → 至少进页缓存；`SIGKILL` 走 `_exit` 路径 → 用户态缓冲全丢。运维上「重启丢日志尾巴」和「kill -9 丢日志尾巴」的差别就在这里 |
| **量化指标** | `__fpending(fp)` 看用户态还剩多少；`/proc/vmstat` 的 `nr_dirty` 看内核里还剩多少。两个数字一起看，就是「这层链路当前积压在哪」 |

<summary>代码自测（Q&A）</summary>

**Q1：这一节的核心判据是什么？**

A：「**另一个 fd 能不能看见**」。字节在用户态缓冲时，别的 fd 的 `st_size` 还是 0；`fflush` 之后立刻变成实际长度；再 `fsync` 之后**外部表现不变**。所以「可见」⇔「至少到了页缓存」，而「落盘」是不可见的。

**Q2：为什么这一节的 `nr_dirty` 全程都是 14，和 13.1 的「涨了 4092」不一样？**

A：量级不同。本节载荷只有 16 字节，远小于一页（4096 字节），脏页计数在这个尺度上**分辨不出来**。13.1 写 16 MiB（4096 页），增量才明显。**同一组计数器要用在匹配的量级上**——这是本仓库刻意保留的一条诚实标注。

**Q3：`fclose` 之后数据落盘了吗？**

A：**没有**。`fclose` 只做隐式 `fflush`，把字节从用户态缓冲送到页缓存。要落盘必须再 `fsync` / `fdatasync`（而且要**在 `fclose` 之前**用 `fileno(fp)` 拿到 fd，或者 `fclose` 之后重新 `open` 再 `fsync`）。

**Q4：写出「持久化一行日志」的正确调用序列。**

A：`fprintf(fp, ...); fflush(fp); fsync(fileno(fp));` —— 三件事对应三层。如果只用 `write(2)`：`write(fd, ...); fsync(fd);`。

**Q5：读方向的缓冲有什么特别之处？**

A：stdio 的**读**缓冲会预读整块。你调 `fread(buf, 1, 1, fp)`，内核侧可能被要求读一整个 `st_blksize`（本机 4096）。所以「应用请求的字节数」和「内核实际读的字节数」不相等——要看这种差异得绕开 stdio 或上 `strace`。

**Q6：如果我只想「让另一个进程立刻看到我的输出」，最少要做什么？**

A：`fflush(fp)` 就够了。`fsync` 是多余的（它保证的是掉电存活，而跨进程可见只需到页缓存）。反过来，如果对端要以「文件大小变化」来判断新内容，那 `fflush` 也是**必需**的——否则 `st_size` 一直不动，对端永远收不到通知。
