## 本节讲什么

[13.5](13.5-advising-kernel.md) 是「建议内核怎么用缓存」；这一节是更激烈的一步：**整个绕过页缓存**。

```c
fd = open(path, O_RDWR | O_DIRECT);   /* 数据在用户缓冲与设备之间直接搬，不进页缓存 */
```

这一节回答四个问题：

1. `O_DIRECT` 要求「对齐」——**对齐什么**？对到什么值？书上说「缓冲区地址、文件偏移、传输长度都要按逻辑块大小对齐」，这句话准确吗？
2. 内核到底是**哪两处代码**在检查对齐？为什么必须看两处？
3. 为什么同一段代码在 `tmpfs` 上「跑得通」、在 `ext4` 上「报 `EINVAL`」？
4. `O_DIRECT` 能替代 `fsync` 吗？

---

## 1. 先在**目标文件系统**上确认环境

`O_DIRECT` 的行为**依文件系统而变**（见 §3），所以第一步是先看清自己在哪台文件系统上：

```text
== ① 先看清是在哪台文件系统上试 ==
  /app/c13_6.bin -> ext4(0xef53)
  /tmp/c13_6.bin -> tmpfs(0x1021994)
  → 两个路径**不是**同一台文件系统，所以下面的结论必须分开说。
```

`f_type` 的判据（`statfs`）：**`0xef53` = ext4**、**`0x1021994` = tmpfs**、`0x9fa0` = proc。三者用同一段代码得到完全不同的结果，所以「`O_DIRECT` 能不能用」这个问题**必须带文件系统限定语**才成立。

---

## 2. 先问内核：`statx(STATX_DIOALIGN)`

Linux 6.1 起提供了一个正式接口，让应用**问**内核「这个文件的 direct I/O 对齐要求是多少」，而不用靠猜：

```c
struct statx stx;
statx(AT_FDCWD, path, 0, STATX_DIOALIGN, &stx);
/* stx.stx_dio_mem_align    —— 缓冲区地址的对齐要求 */
/* stx.stx_dio_offset_align —— 偏移与长度的对齐要求 */
```

实测（CE 上这套机制**没有生效**，值得如实记录）：

```text
== ② 问内核：O_DIRECT 的对齐要求到底是多少 ==
  （statx(2) 的 STATX_DIOALIGN，Linux 6.1 起可用）
  对 /app/c13_6.bin：
    statx 成功但未返回 DIOALIGN（stx_mask=0x173f）→ 该文件系统不支持上报
  对 /tmp/c13_6.bin：
    statx 成功但未返回 DIOALIGN（stx_mask=0x173f）→ 该文件系统不支持上报
```

`stx_mask` 是「内核**实际填了**哪些字段」的位图。`0x173f` 里**不含** `STATX_DIOALIGN`（`0x800`）这一位，所以那两个字段是 0、不可用。**这意味着不能指望它，必须 fallback**：要么保守按 4096 对齐，要么用 §3 的「试错法」实测。

失败时的标准退化路径（`c13_6_direct_io.c` 的做法）：把 `stx_dio_mem_align` / `stx_dio_offset_align` 当成「未知」，改用「已知的安全值 + 逐项试错」来确定边界。所以在下面这段实测里看到的每个 `EINVAL`，都是**现场测出来的**，不是猜的。

## 3. 偏移 / 长度 vs 缓冲区地址：**两套不同的对齐值**

这是本节最值钱的一段。先把结果摆出来：

```text
== ③ 偏移 / 长度 / 缓冲区地址：逐项试错 ==
  在 /app/c13_6.bin（ext4(0xef53)）上：
    offset/len 都对齐           buf%64= 0 off=0      len=512    -> read=512    errno=0(Success)
    len=100 非对齐              buf%64= 0 off=0      len=100    -> read=-1     errno=22(Invalid argument)
    off=1 非对齐                buf%64= 0 off=1      len=512    -> read=-1     errno=22(Invalid argument)
    off=4096 len=1024              buf%64= 0 off=4096   len=1024   -> read=1024   errno=0(Success)
  在 /tmp/c13_6.bin（tmpfs(0x1021994)）上：
    offset/len 都对齐           buf%64= 0 off=0      len=512    -> read=512    errno=0(Success)
    len=100 非对齐              buf%64= 0 off=0      len=100    -> read=100    errno=0(Success)
    off=1 非对齐                buf%64= 0 off=1      len=512    -> read=512    errno=0(Success)

  → 缓冲区地址的对齐下界（用起始偏移造出 1/2/4/.../512 对齐的 buf）：
    buf 对齐 = 1 字节          buf%64= 1 off=0      len=512    -> read=512    errno=0(Success)
    buf 对齐 = 2 字节          buf%64= 2 off=0      len=512    -> read=512    errno=0(Success)
    buf 对齐 = 4 字节          buf%64= 4 off=0      len=512    -> read=512    errno=0(Success)
    buf 对齐 = 8 字节          buf%64= 8 off=0      len=512    -> read=512    errno=0(Success)
    buf 对齐 = 16 字节         buf%64=16 off=0      len=512    -> read=512    errno=0(Success)
    buf 对齐 = 64 字节         buf%64= 0 off=0      len=512    -> read=512    errno=0(Success)
    buf 对齐 = 256 字节        buf%64= 0 off=0      len=512    -> read=512    errno=0(Success)
    buf 对齐 = 512 字节        buf%64= 0 off=0      len=512    -> read=512    errno=0(Success)
```

三组对照，各说一件事：

| 观察 | 说明 |
|------|------|
| **ext4**：`len=100` → `EINVAL`、`off=1` → `EINVAL` | 偏移与长度**被强制**对齐（本机是 512 的倍数） |
| **tmpfs**：`len=100` / `off=1` 都成功 | tmpfs **没有实现** direct I/O，`O_DIRECT` 被当成普通 I/O 静默忽略 —— 这就是「同一段代码在 tmpfs 上跑得通、在 ext4 上报错」的根因 |
| **ext4**：缓冲区地址从 1 字节对齐到 512 字节对齐**全部成功** | **缓冲区地址的对齐在 ext4 上没有被强制** —— 这与「三样都要按逻辑块大小对齐」的流行说法**不一致** |

**为什么会这样？** 因为内核里是**两处**代码在管这件事，用的是**两个不同的对齐值**：

```text
  → 内核判据（Linux v6.6，两处，别只看一处）：
     (a) fs/iomap/direct-io.c:291-293 —— 偏移与长度：
           if ((pos | length) & (bdev_logical_block_size(iomap->bdev) - 1) ||
               !bdev_iter_is_aligned(iomap->bdev, dio->submit.iter))
                   return -EINVAL;
     (b) include/linux/blkdev.h:1320-1325 —— 缓冲区地址用的是**另一个**值：
           return iov_iter_is_aligned(iter, bdev_dma_alignment(bdev),
                                      bdev_logical_block_size(bdev) - 1);
         而 lib/iov_iter.c:866-875 里 addr_mask 管**地址**、len_mask 管**长度**。
         所以：偏移/长度 ← bdev_logical_block_size
               缓冲区地址 ← bdev_dma_alignment + 1
         这两个数**都随底层设备（队列参数）变**，不是常数。
```

把两处放在一起看：

| 要对齐的东西 | 内核用的值 | 出处 |
|-------------|-----------|------|
| **偏移 `pos`、长度 `length`** | `bdev_logical_block_size(iomap->bdev)` | `fs/iomap/direct-io.c:291` |
| **`iov_iter` 的地址** | `bdev_dma_alignment(bdev)`（作为 `addr_mask`） | `include/linux/blkdev.h:1320-1325` → `lib/iov_iter.c:866-875` |
| **`iov_iter` 的长度** | `bdev_logical_block_size(bdev) - 1`（作为 `len_mask`） | 同上 |

```c
static inline unsigned int bdev_dma_alignment(struct block_device *bdev)
{
	return queue_dma_alignment(bdev_get_queue(bdev));
}

static inline bool bdev_iter_is_aligned(struct block_device *bdev,
					struct iov_iter *iter)
{
	return iov_iter_is_aligned(iter, bdev_dma_alignment(bdev),
				   bdev_logical_block_size(bdev) - 1);
}
```

`iov_iter_is_aligned(iter, addr_mask, len_mask)` 的语义是「地址满足 `addr_mask`、长度满足 `len_mask`」——**两个 mask 分开传**，这就从代码结构上说明了「地址和长度是两套要求」。

**本机为什么地址对齐「没有强制」？** 因为 ext4 走 `iomap` 路径时，`bdev_dma_alignment()` 返回的是**队列的 DMA 对齐要求**（很多设备上是 0 或 1，即不要求），而 `bdev_logical_block_size()` 是 512。所以：

- 长度与偏移按 **512** 检查 → `len=100` / `off=1` 被拒；
- 地址按 **DMA 对齐（≈ 1）** 检查 → 1 字节对齐也能通过。

**这也解释了为什么 `STATX_DIOALIGN` 要分成 `stx_dio_mem_align` 和 `stx_dio_offset_align` 两个字段**（`block/bdev.c:1046-1047`）——它们本来就是**两个不同的值**，不是一个：

```c
	stat->dio_mem_align = bdev_dma_alignment(bdev) + 1;
	stat->dio_offset_align = bdev_logical_block_size(bdev);
```

| `statx` 字段 | 来自 | 管什么 |
|-------------|------|-------|
| `stx_dio_mem_align` | `bdev_dma_alignment(bdev) + 1` | **缓冲区地址** |
| `stx_dio_offset_align` | `bdev_logical_block_size(bdev)` | **偏移与长度** |

> ⚠️ **对书上说法的修正**：TLPI（以及很多网上的总结）把三者笼统说成「都要按逻辑块大小对齐」。**在 Linux v6.6 + ext4 的实测中，地址那一项并没有被强制**。工程上仍建议按 4096 对齐（跨设备安全），但要知道：**判据是两套值，且地址那一套通常比长度那一套松**。

## 4. `O_DIRECT` ≠ `O_SYNC`：绕过缓存**不等于**落盘

```text
== ④ O_DIRECT ≠ O_SYNC：绕过缓存不等于落盘 ==
  write(O_DIRECT, 4096) = 4096 errno=0(Success)
  紧接着 fsync(fd) = 0 errno=0(Success)
  → O_DIRECT 打开的 fd 上 **fsync 依然返回 0**：绕过页缓存只是
     「不经过内核这块内存」，设备自己的写缓存还在，要不要落盘是另一回事。
     所以两者要**叠加**用：O_DIRECT 省拷贝/省缓存污染，fsync/O_SYNC 管持久化。
```

这是两个**正交**的维度：

| | 经过页缓存？ | 等设备确认？ |
|---|---|---|
| 普通 `write` | 是 | 否 |
| `write` + `fsync` | 是 | 是 |
| `O_SYNC` 的 `write` | 是 | 是（每次） |
| `O_DIRECT` 的 `write` | **否** | 否 |
| `O_DIRECT` + `fsync` | **否** | 是 |

`O_DIRECT` 只是把「内核这块内存」从链路上拿掉，**设备自己的写缓存**依然存在。要真正确保持久，仍然要 `fsync` / `fdatasync`（或给 `O_DIRECT` 再叠 `O_SYNC`）。

## 5. 不是所有文件都能 `O_DIRECT`

```text
== ⑤ 不是所有文件都能 O_DIRECT ==
  open(/dev/zero       , O_RDONLY|O_DIRECT) = -1  errno=22(Invalid argument)
  open(/etc/passwd     , O_RDONLY|O_DIRECT) = 3   errno=0(Success)
  open(/proc/version   , O_RDONLY|O_DIRECT) = -1  errno=22(Invalid argument)
  → `/dev/zero` 之所以失败，是因为它没有块设备的 direct I/O 能力；
     而 `/etc/passwd` 在本容器里位于 tmpfs 上，虽然能打开，
     但那个 O_DIRECT **是假的**（实测 ③ 里 tmpfs 从不对齐检查）。
```

三种结果，三种含义：

| 对象 | `open` 结果 | 含义 |
|------|-----------|------|
| `/dev/zero` | `-1` / `EINVAL` | 字符设备没有 direct I/O 能力，**在 `open` 时就被拒** |
| `/etc/passwd`（tmpfs） | 成功 | 但 `O_DIRECT` **被静默忽略**（§3 的 tmpfs 行为），是「假 DIO」 |
| `/proc/version` | `-1` / `EINVAL` | 伪文件没有块设备后端 |

**「`open` 成功」不等于「DIO 生效」**——这是本条最危险的地方：在 tmpfs 上你永远不会收到 `EINVAL`，也就永远不会发现自己的对齐逻辑是错的，直到代码跑到 ext4 上。

`probe13` 的 D 段（同一份代码分别在 tmpfs 与 ext4 上跑）也复现了这一点：

```text
  D1 造文件 /tmp/c13probe.bin      write=8192 errno=0
  D2 open(/tmp/c13probe.bin     , O_RDONLY|O_DIRECT) = 3 errno=0(Success)
  D3 三样对齐（buf%512=0, off=0, len=512）：read=512 errno=0(Success)
  D4 len=100（非 512 倍数）：read=100 errno=0(Success)
  D5 off=1（非 512 倍数）：read=512 errno=0(Success)
  D6 buf 只 512 对齐（不是 4096）：read=512 errno=0(Success)
  D7 buf 来自 malloc（16 字节对齐）：read=512 errno=0(Success)
  D8 off=8192（正好 EOF）：read=0 errno=0(Success)
  D1 造文件 /app/c13probe.bin      write=8192 errno=0
  D2 open(/app/c13probe.bin     , O_RDONLY|O_DIRECT) = 3 errno=0(Success)
  D3 三样对齐（buf%512=0, off=0, len=512）：read=512 errno=0(Success)
  D4 len=100（非 512 倍数）：read=-1 errno=22(Invalid argument)
  D5 off=1（非 512 倍数）：read=-1 errno=22(Invalid argument)
  D6 buf 只 512 对齐（不是 4096）：read=512 errno=0(Success)
  D7 buf 来自 malloc（16 字节对齐）：read=512 errno=0(Success)
  D8 off=8192（正好 EOF）：read=0 errno=0(Success)
  D9 open(/dev/zero, O_RDONLY|O_DIRECT) = -1 errno=22(Invalid argument)
  D10 open(/etc/passwd, O_RDONLY|O_DIRECT) = 3 errno=0(Success)
```

`D6` / `D7` 两行是「地址对齐没被强制」的又一次复现：512 对齐可以，**`malloc` 的 16 字节对齐也可以**。

## 6. 原书程序：`direct_read.c`（Listing 13-1，p.247）

原书本章只印了**一个** Listing，就是它 —— 全书讲 `O_DIRECT` 的样板代码。它把本节讲的两件事都做全了：

| 要点 | 代码 |
|------|------|
| 用 `O_DIRECT` 打开 | `fd = open(argv[1], O_RDONLY \| O_DIRECT);` |
| 用 `memalign` 造「奇倍数对齐」的缓冲 | `buf = memalign(alignment * 2, length + alignment); buf += alignment;` |
| 对齐值可作参数覆盖（默认 4096） | `alignment = (argc > 4) ? getLong(argv[4], GN_ANY_BASE, "alignment") : 4096;` |

那个 `memalign(alignment * 2, ...)` 再 `buf += alignment` 的技巧值得学：它保证 `buf` 落在 `alignment` 的**奇倍数**上，于是「按 256 字节对齐」的测试不会**意外**同时满足「512 字节对齐」——否则那些试错实验就得不出结论。本仓库 `c13_6_direct_io.c` 里用 `base + offs[i]` 手工造不同对齐，是同一个思路。

用法（`--help` 时走 `usageErr`，输出到 **stderr** 并 `exit(1)`）：

```text
  Usage: ./output.s file length [offset [alignment]]
```

实际跑一次 `direct_read /etc/passwd 512 0 512`：

```text
Read 50 bytes
```

这一行值得看一眼：请求读 **512** 字节，实际读到 **50** 字节。原因不是 `O_DIRECT` 的问题，而是**本容器的 `/etc/passwd` 只有 50 字节**（见 [`code/README.md`](../code/README.md) 的沙箱说明）；而且它位于 tmpfs 上——所以这次 `O_DIRECT` 其实是**假的**（§3 的 tmpfs 行为）。

完整源码 [`code/direct_read.c`](../code/direct_read.c)：

```c
/*************************************************************************\
*                  Copyright (C) Michael Kerrisk, 2026.                   *
*                                                                         *
* This program is free software. You may use, modify, and redistribute it *
* under the terms of the GNU General Public License as published by the   *
* Free Software Foundation, either version 3 or (at your option) any      *
* later version. This program is distributed without any warranty.  See   *
* the file COPYING.gpl-v3 for details.                                    *
\*************************************************************************/

/* direct_read.c

   Demonstrate the use of O_DIRECT to perform I/O bypassing the buffer cache
   ("direct I/O").

   Usage: direct_read file length [offset [alignment]]

   This program is Linux-specific.
*/
#define _GNU_SOURCE     /* Obtain O_DIRECT definition from <fcntl.h> */
#include <fcntl.h>
#include <malloc.h>
#include "tlpi_hdr.h"

int
main(int argc, char *argv[])
{
    int fd;
    ssize_t numRead;
    size_t length, alignment;
    off_t offset;
    char *buf;

    if (argc < 3 || strcmp(argv[1], "--help") == 0)
        usageErr("%s file length [offset [alignment]]\n", argv[0]);

    length = getLong(argv[2], GN_ANY_BASE, "length");
    offset = (argc > 3) ? getLong(argv[3], GN_ANY_BASE, "offset") : 0;
    alignment = (argc > 4) ? getLong(argv[4], GN_ANY_BASE, "alignment") : 4096;

    fd = open(argv[1], O_RDONLY | O_DIRECT);
    if (fd == -1)
        errExit("open");

    /* memalign() allocates a block of memory aligned on an address that
       is a multiple of its first argument. By specifying this argument as
       2 * 'alignment' and then adding 'alignment' to the returned pointer,
       we ensure that 'buf' is aligned on an odd multiple of
       'alignment'. We do this to ensure that if, for example, we ask
       for a 256-byte aligned buffer, we don't accidentally get
       a buffer that is also aligned on a 512-byte boundary. */

    buf = memalign(alignment * 2, length + alignment);
    if (buf == NULL)
        errExit("memalign");

    buf += alignment;

    if (lseek(fd, offset, SEEK_SET) == -1)
        errExit("lseek");

    numRead = read(fd, buf, length);
    if (numRead == -1)
        errExit("read");
    printf("Read %ld bytes\n", (long) numRead);

    exit(EXIT_SUCCESS);
}
```

## 7. 什么时候该用 `O_DIRECT`

```text
== ⑥ 什么时候该用 O_DIRECT ==
  适合：自带缓存层的大型 DB / 存储引擎（自己管得比内核好，不想双重缓存）
  不适合：小 IO 频繁的场景（每次都是整块设备往返，代价极高）
  工程要点：
    1) 别写死对齐值 —— 用 statx(STATX_DIOALIGN) 问，或按 4096 保守给；
    2) 用 posix_memalign/对齐分配，别用 malloc 硬赌；
    3) 记住它**不解决持久化**，该 fsync 还得 fsync；
    4) 一定要在**目标文件系统**上验过 —— 同一段代码在 tmpfs 上
       「跑得通」不代表在 ext4 上能跑通（本程序的 ③ 就是这个陷阱的现场）。
```

原则一句话：**`O_DIRECT` 是给「自己已经有缓存」的应用用的**（数据库缓冲池、HFT 的自管行情缓存），目的是避免**双重缓存**（内核页缓存 + 应用缓存）与多余拷贝。它牺牲的是「内核帮你合并小写」的能力，所以只适合**大块、对齐、批量**的 I/O。

完整源码 [`code/c13_6_direct_io.c`](../code/c13_6_direct_io.c)：

```c
/* c13_6_direct_io.c — Ch13 §13.6：绕过缓冲区高速缓存（O_DIRECT）
 *
 * TLPI §13.6（p.246）讲 `O_DIRECT`：让应用与块设备之间**直接**传数据，
 * 绕开内核页缓存。原书配的程序是 Listing 13-1（`filebuff/direct_read.c`，p.247），
 * 已逐字镜像在本目录下。
 *
 * 书上对对齐要求的说法是「缓冲区地址、文件偏移、传输长度**三样**都要是
 * 逻辑块大小的整数倍」。本节把这句话**量准**：
 *   ① 两种文件系统上的行为完全不同：ext4 会硬性检查，tmpfs **完全不检查**
 *      （因为 tmpfs 根本没实现 direct I/O，这个标志被静默忽略）；
 *   ② 偏移与长度的对齐要求来自 `bdev_logical_block_size`；
 *   ③ 缓冲区地址的对齐要求来自 **另一个** 值：`bdev_dma_alignment + 1`；
 *      两者**都随底层设备变**，不是常数 —— 用 `statx(2)` 的 `STATX_DIOALIGN`
 *      可以直接问内核要准确值（v6.1+）；
 *   ④ `O_DIRECT` **不等于** `O_SYNC`：绕过缓存 ≠ 落盘。
 *
 * 编译： gcc -O0 -Wall -Wextra -o c13_6_direct_io c13_6_direct_io.c
 * 取材： TLPI §13.6（O_DIRECT 的语义、对齐要求、posix_memalign）
 *       man-pages 6.19 open(2) 的 O_DIRECT（"alignment restrictions ... vary
 *         across filesystems and kernel versions"；"differs from O_SYNC"）
 *                      statx(2) 的 STATX_DIOALIGN（dio_mem_align / dio_offset_align）
 *       Linux v6.6 fs/iomap/direct-io.c:291-293（iomap_dio_bio_iter 的对齐检查）
 *                      include/linux/blkdev.h:1315-1325（bdev_dma_alignment /
 *                        bdev_iter_is_aligned）
 *                      lib/iov_iter.c:866-875（iov_iter_is_aligned：addr_mask 管地址、
 *                        len_mask 管长度）
 *                      block/bdev.c:1046-1047（STATX_DIOALIGN 的两个字段从哪来）
 *                      fs/open.c（O_DIRECT 的合法性检查）
 *       glibc 2.39 sysdeps/unix/sysv/linux/statx.c（statx 的 syscall 包装）
 */
#define _GNU_SOURCE
#include <errno.h>
#include <fcntl.h>
#include <malloc.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <sys/stat.h>
#include <sys/statfs.h>
#include <unistd.h>

#ifndef STATX_DIOALIGN
#define STATX_DIOALIGN 0x00000800
#endif
#ifndef STX_DIO_ALIGN
#define STX_DIO_ALIGN 0x00004000
#endif

#define EXT4_PATH "/app/c13_6.bin"
#define TMPFS_PATH "/tmp/c13_6.bin"

static void fs_name(const char *path, char *out, size_t cap)
{
    struct statfs sf;

    if (statfs(path, &sf) == -1) {
        snprintf(out, cap, "(statfs 失败 errno=%d)", errno);
        return;
    }
    switch ((unsigned long) sf.f_type) {
    case 0xef53:     snprintf(out, cap, "ext4(0xef53)");          break;
    case 0x01021994: snprintf(out, cap, "tmpfs(0x1021994)");      break;
    case 0x9fa0:     snprintf(out, cap, "proc(0x9fa0)");          break;
    case 0x6969:     snprintf(out, cap, "nfs(0x6969)");           break;
    case 0x58465342: snprintf(out, cap, "xfs(0x58465342)");       break;
    case 0x794c7630: snprintf(out, cap, "overlayfs(0x794c7630)"); break;
    default:         snprintf(out, cap, "未知(0x%lx)", (unsigned long) sf.f_type); break;
    }
}

/* 向内核要 O_DIRECT 的对齐要求（STATX_DIOALIGN，Linux 6.1+） */
static void ask_dio_align(const char *path)
{
    struct statx stx;
    int r;

    memset(&stx, 0, sizeof(stx));
    errno = 0;
    r = statx(AT_FDCWD, path, 0, STATX_DIOALIGN, &stx);
    if (r == -1) {
        printf("    statx(%s, STATX_DIOALIGN) 失败 errno=%d(%s)\n", path, errno, strerror(errno));
        return;
    }
    if (!(stx.stx_mask & STATX_DIOALIGN) || !(stx.stx_attributes_mask & STX_DIO_ALIGN)) {
        printf("    statx 成功但未返回 DIOALIGN（stx_mask=0x%x）→ 该文件系统不支持上报\n",
               stx.stx_mask);
        return;
    }
    printf("    statx: stx_dio_mem_align    = %u   ← 缓冲区地址要按它对齐\n", stx.stx_dio_mem_align);
    printf("           stx_dio_offset_align = %u   ← 偏移/长度要按它对齐\n", stx.stx_dio_offset_align);
}

/* 造一个 length 字节的文件（普通写） */
static int make_file(const char *path, size_t length)
{
    char *b = malloc(length);
    int fd;

    if (b == NULL)
        return -1;
    memset(b, 'E', length);
    fd = open(path, O_CREAT | O_WRONLY | O_TRUNC, 0644);
    if (fd == -1) {
        free(b);
        return -1;
    }
    if (write(fd, b, length) != (ssize_t) length) {
        close(fd);
        free(b);
        return -1;
    }
    close(fd);
    free(b);
    return 0;
}

/* 一次 O_DIRECT 读尝试：len/off 可调，buf 用大块里的不同偏移造出不同对齐 */
static void try_read(const char *path, size_t len, off_t off, char *buf, const char *tag)
{
    int fd;
    ssize_t n;

    fd = open(path, O_RDONLY | O_DIRECT);
    if (fd == -1) {
        printf("    %-30s open 失败 errno=%d(%s)\n", tag, errno, strerror(errno));
        return;
    }
    if (lseek(fd, off, SEEK_SET) == -1) {
        printf("    %-30s lseek 失败 errno=%d(%s)\n", tag, errno, strerror(errno));
        close(fd);
        return;
    }
    errno = 0;
    n = read(fd, buf, len);
    printf("    %-30s buf%%64=%2zu off=%-6ld len=%-6zu -> read=%-6ld errno=%d(%s)\n",
           tag, (size_t) ((unsigned long) buf % 64), (long) off, len,
           (long) n, errno, strerror(errno));
    close(fd);
}

int main(void)
{
    char n1[64], n2[64];

    /* 先让两个路径**存在**，否则 statfs() 只会拿到 ENOENT，
       报出来的文件系统类型就无从谈起（fs_name 会打出「statfs 失败」）。 */
    (void) make_file(EXT4_PATH, 8192);
    (void) make_file(TMPFS_PATH, 8192);

    fs_name(EXT4_PATH, n1, sizeof(n1));
    fs_name(TMPFS_PATH, n2, sizeof(n2));
    printf("== ① 先看清是在哪台文件系统上试 ==\n");
    printf("  %-14s -> %s\n", EXT4_PATH, n1);
    printf("  %-14s -> %s\n", TMPFS_PATH, n2);
    printf("  → 两个路径**不是**同一台文件系统，所以下面的结论必须分开说。\n");

    printf("\n== ② 问内核：O_DIRECT 的对齐要求到底是多少 ==\n");
    printf("  （statx(2) 的 STATX_DIOALIGN，Linux 6.1 起可用）\n");
    printf("  对 %s：\n", EXT4_PATH);
    ask_dio_align("/app");
    printf("  对 %s：\n", TMPFS_PATH);
    ask_dio_align("/tmp");

    printf("\n== ③ 偏移 / 长度 / 缓冲区地址：逐项试错 ==\n");
    {
        const size_t FILELEN = 8192;
        /* 用一块足够大的缓冲，通过不同起始偏移构造不同对齐的 buf */
        char *base = NULL;
        size_t total = FILELEN + 4096;

        if (posix_memalign((void **) &base, 4096, total + 4096) != 0) {
            printf("  posix_memalign 失败\n");
            return EXIT_FAILURE;
        }

        if (make_file(EXT4_PATH, FILELEN) == -1 || make_file(TMPFS_PATH, FILELEN) == -1) {
            printf("  造文件失败 errno=%d(%s)\n", errno, strerror(errno));
            return EXIT_FAILURE;
        }

        printf("  在 %s（%s）上：\n", EXT4_PATH, n1);
        try_read(EXT4_PATH, 512, 0,   base,        "offset/len 都对齐");
        try_read(EXT4_PATH, 100, 0,   base,        "len=100 非对齐");
        try_read(EXT4_PATH, 512, 1,   base,        "off=1 非对齐");
        try_read(EXT4_PATH, 1024, 4096, base,      "off=4096 len=1024");

        printf("  在 %s（%s）上：\n", TMPFS_PATH, n2);
        try_read(TMPFS_PATH, 512, 0,  base,        "offset/len 都对齐");
        try_read(TMPFS_PATH, 100, 0,  base,        "len=100 非对齐");
        try_read(TMPFS_PATH, 512, 1,  base,        "off=1 非对齐");

        printf("\n  → 缓冲区地址的对齐下界（用起始偏移造出 1/2/4/.../512 对齐的 buf）：\n");
        {
            const size_t offs[] = {1, 2, 4, 8, 16, 64, 256, 512};
            for (size_t i = 0; i < sizeof(offs) / sizeof(offs[0]); i++) {
                char tag[64];
                snprintf(tag, sizeof(tag), "buf 对齐 = %zu 字节", offs[i]);
                try_read(EXT4_PATH, 512, 0, base + offs[i], tag);
            }
        }

        printf("\n  → 内核判据（Linux v6.6，两处，别只看一处）：\n");
        printf("     (a) fs/iomap/direct-io.c:291-293 —— 偏移与长度：\n");
        printf("           if ((pos | length) & (bdev_logical_block_size(iomap->bdev) - 1) ||\n");
        printf("               !bdev_iter_is_aligned(iomap->bdev, dio->submit.iter))\n");
        printf("                   return -EINVAL;\n");
        printf("     (b) include/linux/blkdev.h:1320-1325 —— 缓冲区地址用的是**另一个**值：\n");
        printf("           return iov_iter_is_aligned(iter, bdev_dma_alignment(bdev),\n");
        printf("                                      bdev_logical_block_size(bdev) - 1);\n");
        printf("         而 lib/iov_iter.c:866-875 里 addr_mask 管**地址**、len_mask 管**长度**。\n");
        printf("         所以：偏移/长度 ← bdev_logical_block_size\n");
        printf("               缓冲区地址 ← bdev_dma_alignment + 1\n");
        printf("         这两个数**都随底层设备（队列参数）变**，不是常数。\n");

        free(base);
        unlink(EXT4_PATH);
        unlink(TMPFS_PATH);
    }

    printf("\n== ④ O_DIRECT ≠ O_SYNC：绕过缓存不等于落盘 ==\n");
    {
        int fd = open(EXT4_PATH, O_CREAT | O_RDWR | O_TRUNC | O_DIRECT, 0644);
        char *b = NULL;

        if (fd == -1) {
            printf("  open 失败 errno=%d(%s)\n", errno, strerror(errno));
            return EXIT_FAILURE;
        }
        if (posix_memalign((void **) &b, 4096, 4096) != 0) {
            printf("  posix_memalign 失败\n");
            close(fd);
            return EXIT_FAILURE;
        }
        memset(b, 'X', 4096);
        errno = 0;
        ssize_t w = write(fd, b, 4096);
        printf("  write(O_DIRECT, 4096) = %ld errno=%d(%s)\n", (long) w, errno, strerror(errno));
        errno = 0;
        int r = fsync(fd);
        printf("  紧接着 fsync(fd) = %d errno=%d(%s)\n", r, errno, strerror(errno));
        printf("  → O_DIRECT 打开的 fd 上 **fsync 依然返回 0**：绕过页缓存只是\n");
        printf("     「不经过内核这块内存」，设备自己的写缓存还在，要不要落盘是另一回事。\n");
        printf("     所以两者要**叠加**用：O_DIRECT 省拷贝/省缓存污染，fsync/O_SYNC 管持久化。\n");
        free(b);
        close(fd);
    }

    printf("\n== ⑤ 不是所有文件都能 O_DIRECT ==\n");
    {
        const char *paths[] = {"/dev/zero", "/etc/passwd", "/proc/version", NULL};
        for (int i = 0; paths[i] != NULL; i++) {
            errno = 0;
            int fd = open(paths[i], O_RDONLY | O_DIRECT);
            int e = errno;
            printf("  open(%-16s, O_RDONLY|O_DIRECT) = %-3d errno=%d(%s)\n",
                   paths[i], fd, e, strerror(e));
            if (fd >= 0)
                close(fd);
        }
        printf("  → `/dev/zero` 之所以失败，是因为它没有块设备的 direct I/O 能力；\n");
        printf("     而 `/etc/passwd` 在本容器里位于 tmpfs 上，虽然能打开，\n");
        printf("     但那个 O_DIRECT **是假的**（实测 ③ 里 tmpfs 从不对齐检查）。\n");
    }

    printf("\n== ⑥ 什么时候该用 O_DIRECT ==\n");
    printf("  适合：自带缓存层的大型 DB / 存储引擎（自己管得比内核好，不想双重缓存）\n");
    printf("  不适合：小 IO 频繁的场景（每次都是整块设备往返，代价极高）\n");
    printf("  工程要点：\n");
    printf("    1) 别写死对齐值 —— 用 statx(STATX_DIOALIGN) 问，或按 4096 保守给；\n");
    printf("    2) 用 posix_memalign/对齐分配，别用 malloc 硬赌；\n");
    printf("    3) 记住它**不解决持久化**，该 fsync 还得 fsync；\n");
    printf("    4) 一定要在**目标文件系统**上验过 —— 同一段代码在 tmpfs 上\n");
    printf("       「跑得通」不代表在 ext4 上能跑通（本程序的 ③ 就是这个陷阱的现场）。\n");
    return EXIT_SUCCESS;
}
```

## 常见坑

| # | 坑 | 正解 |
|---|----|------|
| 1 | 把「三样对齐」当成同一个值 | 内核里是**两套值**：偏移/长度用 `bdev_logical_block_size`，缓冲区地址用 `bdev_dma_alignment`。本机 ext4 实测地址那套**没有被强制** |
| 2 | 在 tmpfs 上测通了就以为代码对了 | tmpfs **忽略** `O_DIRECT`（`len=100`、`off=1` 全成功）。必须在**目标文件系统**上验 |
| 3 | 以为 `O_DIRECT` 打开了就一定生效 | `/etc/passwd`（tmpfs）上 `open` 成功但 DIO 是假的；只有**写/读时报错**才是真检查 |
| 4 | 用 `malloc` 分配 `O_DIRECT` 缓冲区 | 只对齐 16 字节。用 `posix_memalign()` 或 `aligned_alloc()`，并且**按 4096 保守对齐**（虽然本机 ext4 上更松，但跨设备安全） |
| 5 | 以为 `O_DIRECT` 能替代 `fsync` | 只绕过「内核页缓存」，**设备写缓存还在**。要持久化仍要 `fsync` / `fdatasync` |
| 6 | `O_DIRECT` 配小块写 | 每次都变成整块设备往返，小 IO 下代价极高。`O_DIRECT` 只适合大块批量 |
| 7 | 忘了 `O_DIRECT` 的 `read` 也可能 short read | 即使对齐正确，`read` 也可能返回小于请求的长度（尤其跨设备/尾块）。必须循环读 |
| 8 | 对字符设备（`/dev/zero`）用 `O_DIRECT` | `open` 就返回 `EINVAL`。它在 `open` 阶段检查，不是 `read` 阶段 |
| 9 | 写死 512 对齐值 | 对齐要求随**底层设备队列参数**变化（`bdev_logical_block_size` / `bdev_dma_alignment` 都不是常数）。优先 `statx(STATX_DIOALIGN)`，拿不到再保守给 4096 |

## HFT / 嵌入式关联

| 场景 | 结论怎么用 |
|------|-----------|
| **自带缓存的存储引擎** | 行情历史库/订单库若自己有 page 管理，用 `O_DIRECT` 避免同一份数据在内核页缓存和应用缓存里各放一份（内存翻倍 + 拷贝翻倍） |
| **低延迟读盘的确定性** | `O_DIRECT` 让「一次 `read` = 一次设备 I/O」，延迟可预测；而走页缓存的读会遇到「命中就极快、不命中就极慢」的双峰。对尾延迟敏感的场景，确定性比平均更快更重要 |
| **持久化的正确组合** | `open(O_DIRECT)` + `write` + `fsync`（或 `O_DIRECT|O_SYNC`）。单靠 `O_DIRECT` 会给出「我已经直连设备了」的错觉，而设备写缓存仍在 |
| **对齐分配是工程成本** | 应用里所有 I/O 缓冲都要 `posix_memalign` 对齐，且要**回退**——不同设备要求不同（本机 ext4 地址要求极松，别的设备可能是 512/4096）。建议实现一个「按 4096 对齐 + 长度按设备扇区补齐」的小分配器 |
| **嵌入式 flash** | 很多嵌入式存储（eMMC/SD/NAND 控制器）的 DMA 对齐要求比服务器盘更严；`O_DIRECT` 若对齐不对，表现为 `EINVAL` 或性能暴跌。**先在目标板上实测一遍对齐下界** |
| **tmpfs 陷阱** | 调试期把数据目录放在 `/tmp`（tmpfs）上，`O_DIRECT` 的 bug 全部隐形；上线换成 ext4/eMMC 后集中爆发。CI 里应当**至少有一个非 tmpfs 的挂载点**做验证 |
| **不要用 `O_DIRECT` 读小配置** | 读一个几十字节的配置文件用 `O_DIRECT`，会把「一次页缓存命中」变成「一次设备往返 + 对齐补齐」。这类 I/O 交给页缓存反而更快 |

<summary>代码自测（Q&A）</summary>

**Q1：`O_DIRECT` 要求对齐，到底要对齐哪几样？**

A：**两套要求**。① 偏移与长度：按 `bdev_logical_block_size`（本机 512）；② 缓冲区**地址**：按 `bdev_dma_alignment`。内核在 `fs/iomap/direct-io.c:291-293` 检查前者、`include/linux/blkdev.h:1320-1325`（`bdev_iter_is_aligned`）检查后者。

**Q2：书上说「三样都要按逻辑块大小对齐」，实测符合吗？**

A：**不完全符合**。本机 ext4 实测：`len=100` → `EINVAL`、`off=1` → `EINVAL`（这两项确实被强制），但**缓冲区地址从 1 字节对齐到 512 字节对齐全部成功** —— 地址那一套用的是 DMA 对齐值，比逻辑块大小松得多。`statx` 分成 `stx_dio_mem_align` / `stx_dio_offset_align` 两个字段，正说明它们是两个不同的值。

**Q3：为什么同一段代码在 tmpfs 上成功、在 ext4 上 `EINVAL`？**

A：tmpfs **没有实现 direct I/O**，`O_DIRECT` 被静默忽略，所以 `len=100`、`off=1` 都不报错。ext4 走 `iomap` 路径，会真的检查偏移/长度的对齐。**这是「在错误的环境上验证代码」的典型案例。**

**Q4：`O_DIRECT` 能替代 `fsync` 吗？**

A：**不能**。实测 `O_DIRECT` 打开的 fd 上 `fsync` 依然返回 0 —— 说明两者是**正交**的：`O_DIRECT` 管「不经内核页缓存」，`fsync` / `O_SYNC` 管「等设备确认」。要持久化必须叠加。

**Q5：怎么在代码里拿到真正的对齐要求？**

A：优先 `statx(AT_FDCWD, path, 0, STATX_DIOALIGN, &stx)`（Linux 6.1+）读 `stx_dio_mem_align` / `stx_dio_offset_align`。**但本机 CE 实测它没返回**（`stx_mask=0x173f`，不含 `STATX_DIOALIGN`），所以要能 fallback：保守按 4096 对齐，或做一次「试错探测」。

**Q6：`open(/etc/passwd, O_RDONLY|O_DIRECT)` 成功了，说明 DIO 可用吗？**

A：**不能说明**。`/etc/passwd` 在本容器里位于 tmpfs，`open` 成功但 DIO 被忽略。只有「在不支持的文件系统上 `open` 会失败」这一条不成立——字符设备（`/dev/zero`）才在 `open` 阶段返回 `EINVAL`。

**Q7：`O_DIRECT` 最适合什么场景？最不适合什么？**

A：最适合「应用自带缓存、做大块顺序/批量 I/O、想避免双重缓存」的场景（数据库、存储引擎）。最不适合「小 IO 频繁」的场景——每次 `read`/`write` 都会变成一次整块设备往返，还会因为对齐要求把缓冲放大。
