## 本节讲什么

`read()` / `write()` **不直接对磁盘**做同步块传输——它们把数据在**用户缓冲**和**内核页缓存**之间拷来拷去，真正的设备传输由内核在「以后某个时刻」批量做。这一节回答三个问题：

1. `write()` 返回的时候，数据到底在**哪儿**？为什么对别的 fd 立刻可见、却仍可能没落盘？
2. 「延迟写」的收益从哪儿来——为什么它能同时提高吞吐、又降低延迟？代价是什么？
3. **块大小**为什么是这一章最重要的旋钮？它和系统调用次数的关系是线性的还是别的？

这三个问题在 `c13_1_buffer_cache.c` 里各有一段可运行的验证。

## 1. 数据路径：两层缓冲里的「下面那一层」

文件 I/O 的完整链路上有**两处**缓冲，本章 13.1 讲的是下面那一处：

```
应用代码
  |  （stdio 函数，见 13.2）
  v
[用户态 stdio 缓冲]  ---- fflush() ---->   （这一层归 libc 管）
  |
  v
read(2) / write(2)          ← 本节讲的就是这两个调用的语义
  |
  v
[内核页缓存 page cache]  ---- writeback ---->  [块设备]
  |                                                ^
  +-------------------- fsync() -------------------+
```

**关键点是那个「双层」结构**：`read()` / `write()` 这一层的语义是「和内核的页缓存交换数据」，**不是**「和磁盘交换数据」。因此：

| 调用 | 实际做了什么 | **没有**做什么 |
|------|-------------|---------------|
| `write(fd, buf, n)` | 把 `n` 字节从用户空间**拷进**内核页缓存里对应文件的页，返回 `n` | 没有等设备写完；甚至可能还没决定什么时候写 |
| `read(fd, buf, n)` | 若目标页已在页缓存里，**直接拷贝**；否则先发起一次设备读、把读到的页留在缓存里 | 不保证读到你「刚写完但还没落盘」的内容——不过**本机**能读到，因为大家都看同一份缓存 |

> 为什么这个区别重要：它意味着 `write()` 的**返回延迟**主要由「内存拷贝速度」决定，而不是磁盘速度。这正是下一节 §2 实测里那 16 MiB 只用毫秒级写进去的原因。

## 2. 延迟写：`write()` 返回 ≠ 已落盘

内核收集起这些被改过、但还没写到设备的页，给它们一个名字：**脏页（dirty page）**。回写由两条路触发：

| 触发者 | 机制 | 本容器实测参数（`/proc/sys/vm/`） |
|--------|------|-----------------------------------|
| 后台 flusher 线程 | 周期性扫描，把「脏了超过一定时间」的页写回 | `dirty_writeback_centisecs = 500`（每 5 秒扫一次）、`dirty_expire_centisecs = 3000`（脏超过 30 秒必须写） |
| 阈值限流 | 脏页占比太高时，**写操作自己**被迫开始回写（这是写突刺时的卡顿来源） | `dirty_background_ratio = 10`（超过 10% 后台开始写）、`dirty_ratio = 20`（超过 20% 前台进程必须自己写） |

「延迟写」让吞吐变好（合并小写、少寻道）、让 `write()` 延迟变低（只等内存拷贝）。**代价**是：从 `write()` 返回到数据真正落盘之间存在一个窗口，这个窗口里断电 / 崩溃 / 内核 panic，数据就没了。

### 怎么**量出**「数据还在页缓存里」

不能靠「读回来能不能看见」判断——页缓存对所有进程是同一份，别的 fd 当然看得见。要看的是**内核侧的计数器**：`/proc/vmstat` 的 `nr_dirty`（当前脏页数，单位**页**）与 `/proc/meminfo` 的 `Dirty`（单位 **kB**）。程序里这么读：

```c
static long meminfo_kb(const char *key);   /* 从 /proc/meminfo 取 "Dirty:  1234 kB" */
static long vmstat_val(const char *key);   /* 从 /proc/vmstat 取 "nr_dirty 459" */
```

然后「写 16 MiB → 看 `nr_dirty` 涨了多少 → `fsync` → 再看它落回去」：

```text
== ② 脏页计数器：write 之后涨，fsync 之后落 ==
  写之前      : Dirty=1836      kB  Writeback=0        kB  nr_dirty=459       nr_writeback=0
  写 16 MiB 后 : Dirty=18204     kB  Writeback=0        kB  nr_dirty=4551      nr_writeback=0
  → nr_dirty 的增量 = 4092 页；而 16 MiB / 4096 字节页 = 4096 页
     两者对得上 ⟹ 这 16 MiB 一个字都没上磁盘，全在页缓存里等着。
     另外 nr_dirty(页) x 4 = Dirty(kB) 恒成立：4551 x 4 = 18204
  fsync(fd) = 0 errno=0(Success)
  fsync 之后  : Dirty=1948      kB  Writeback=0        kB  nr_dirty=487       nr_writeback=0
  → nr_dirty 从 4551 落回 487，就是 fsync 把脏页推下去的。
  ⚠️ 这两个计数器是**整机（宿主）**口径，不是本进程的：
     别的容器、别的进程也在写盘，所以绝对值**必然漂移**；
     但上面那句「增量 == 页数」是**当次运行内**成立的，可以当场验。
```

这段实验的设计要点值得单独说，因为它是**可以当场对账**的：

| 设计 | 为什么这么定 |
|------|-------------|
| 写入量取 **16 MiB** | 它 `= 4096 × 4096` 字节，正好 4096 页；`nr_dirty` 的增量应当**恰好**是这个数，多一页少一页都能看出来 |
| 取 16 MiB 而不是 1 GiB | CE 容器的 `RLIMIT_FSIZE` 恰好是 **16777216**（16 MiB，`probe13c` 实测）。写 32 MiB 会被 `SIGXFSZ(25)` 杀掉，而且**信号不会刷 stdio 缓冲**，输出会整段丢失 |
| 同时打 `nr_dirty` 与 `Dirty` | 两者单位不同（页 / kB），`nr_dirty × 4 = Dirty` 这条恒等式是**交叉校验**：任一读取路径写错都会暴露 |
| 两次采样之间不 `sleep` | 增量是「当次运行内」的差值，不依赖绝对值的稳定性 |

> ⚠️ **诚实标注**：`nr_dirty` 是**整机**（宿主）计数器，不区分进程、也不区分容器。上面「增量 = 4092 页」而不是精确的 4096，就是因为采样的几毫秒里宿主别的地方也在写盘、也有回写。**结论成立**（同一数量级、严格对应），但别把差值当成精确值。

## 3. 块大小：这一章最重要的旋钮

`write()` 的次数只由「总字节数 / 每次写的块大小」决定——这是**算出来的**，与机器无关。程序里固定总量 1 MiB、只改 `buf-size`：

```text
== ③ 总字节数不变，只改块大小：系统调用次数差 4 个数量级 ==
  目标：每档都写 1048576 字节，只改 write() 的 buf-size
    buf-size   write() 次数 耗时(s) 
    1          1048576        0.3089
    16         65536          0.0200
    256        4096           0.0015
    4096       256            0.0003
    65536      16             0.0002
  → 总字节一样，buf-size 从 1 加到 65536，write() 次数从 1048576 降到 16
     （差 65536 倍 ≈ 4.8 个数量级），耗时跟着掉。
  ⚠️ CE 上测到的**耗时是另一台机器**的值，只能看趋势；
     但「次数」是算出来的（TOTAL / buf-size），绝对可靠。
```

读这张表有个方法论上的要点：**先看「次数」这一列，再看「耗时」**。因为耗时在 CE 上属于「另一台宿主机」的数字，而次数是 `1048576 / buf-size` 的结果，在任何机器上都一样。把可移植的那一列当结论、把不可移植的那一列当佐证，是本仓库对所有性能类实测的统一处理方式。

为什么减少系统调用次数就能提速？因为每次系统调用都要走一遍「用户态 → 内核态 → 用户态」的完整切换（保存/恢复寄存器、切换栈、可能的 TLB/缓存扰动）。对 1 MiB 数据：

- `buf-size = 1`：1048576 次切换，光切换开销就压过了一切；
- `buf-size = 65536`：16 次切换，切换开销可以忽略。

> 这也解释了为什么 `stdio` 要存在（见 [13.2](13.2-stdio-file.md)）：它的全部价值就是**替你把小块攒成大块**，从而把系统调用次数降下来。

## 4. 本节结论

```text
== ④ 本节结论：两层缓冲里的「下面那一层」 ==
  read()/write()  <-copy->  内核页缓存  <-writeback->  磁盘
  ① 证明「返回时数据在内核」；② 证明「此时还没落盘」；③ 证明「块大小决定系统调用次数」
  要把它推进磁盘：fsync()/fdatasync()/sync() 或 O_SYNC（见 13.3）
```

完整源码 [`code/c13_1_buffer_cache.c`](../code/c13_1_buffer_cache.c)：

```c
/* c13_1_buffer_cache.c — Ch13 §13.1：内核缓冲（Buffer Cache / Page Cache）
 *
 * TLPI §13.1（p.233）的核心断言只有一句话：
 *   `read()` / `write()` **不直接对磁盘**做传输，而是在「用户缓冲」与
 *   「内核缓冲区高速缓存（buffer cache / page cache）」之间复制数据。
 * 本程序把这句话拆成三件**可以量出来**的事：
 *   ① write() 返回后，数据立刻对另一个 fd 可见 —— 因为它在内核里，不在磁盘上；
 *   ② 写完一大批数据，/proc/meminfo 的 Dirty 与 /proc/vmstat 的 nr_dirty 会涨；
 *      fsync() 之后会落回去 —— 这就是「延迟写」的直接证据；
 *   ③ 总字节数不变，只改 write() 的块大小，**系统调用次数**会差 4 个数量级，
 *      耗时跟着走 —— 这才是「缓冲影响性能」的机制。
 *
 * 编译： gcc -O0 -Wall -Wextra -o c13_1_buffer_cache c13_1_buffer_cache.c
 * 取材： TLPI §13.1（buffer cache 的定义、块大小对性能的影响、Table 13-1/13-2）
 *       man-pages 6.19 write(2) NOTES（"a successful return from write() does not
 *         make any guarantee that data has been committed to disk"）
 *                      fsync(2)（"The fsync() call ... transfers all modified
 *         in-core data ... to the storage device"）
 *       Linux v6.6 mm/page-writeback.c（dirty 计数器 / flusher 线程）
 *                      include/linux/writeback.h（DIRTY_* 阈值）
 *       TLPI Ch12 §12.1.2（/proc/meminfo、/proc/vmstat 的读法）
 */
#include <errno.h>
#include <fcntl.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <time.h>
#include <unistd.h>

/* ---------- 小工具：从 /proc/meminfo 取一个 kB 字段 ---------- */
static long meminfo_kb(const char *key)
{
    FILE *fp = fopen("/proc/meminfo", "r");
    char line[256];
    long v = -1;

    if (fp == NULL)
        return -1;
    while (fgets(line, sizeof(line), fp) != NULL) {
        if (strncmp(line, key, strlen(key)) == 0) {
            if (sscanf(line + strlen(key), " : %ld", &v) != 1)
                v = -2;
            break;
        }
    }
    fclose(fp);
    return v;
}

/* ---------- 小工具：从 /proc/vmstat 取一个计数器 ---------- */
static long vmstat_val(const char *key)
{
    FILE *fp = fopen("/proc/vmstat", "r");
    char line[256];
    long v = -1;

    if (fp == NULL)
        return -1;
    while (fgets(line, sizeof(line), fp) != NULL) {
        if (strncmp(line, key, strlen(key)) == 0) {
            if (sscanf(line + strlen(key), " %ld", &v) != 1)
                v = -2;
            break;
        }
    }
    fclose(fp);
    return v;
}

/* ---------- 小工具：单调时钟，返回秒（double） ---------- */
static double now_sec(void)
{
    struct timespec ts;

    clock_gettime(CLOCK_MONOTONIC, &ts);
    return (double) ts.tv_sec + (double) ts.tv_nsec / 1e9;
}

#define TMPFILE "/app/c13_1.bin"

int main(void)
{
    printf("== ① write() 返回后，数据已经在内核里（对别的 fd 立刻可见） ==\n");
    {
        const char *msg = "hello-page-cache";
        int fd = open(TMPFILE, O_CREAT | O_WRONLY | O_TRUNC, 0644);
        if (fd == -1) {
            printf("  open 失败 errno=%d(%s)\n", errno, strerror(errno));
            return EXIT_FAILURE;
        }
        errno = 0;
        ssize_t w = write(fd, msg, strlen(msg));
        int we = errno;
        printf("  write(fd, \"%s\", %d) = %ld errno=%d(%s)\n",
               msg, (int) strlen(msg), (long) w, we, strerror(we));
        /* 刻意**不** fsync、也不 close 写端，直接另开一个 fd 去读 */
        int rfd = open(TMPFILE, O_RDONLY);
        char buf[64];
        memset(buf, 0, sizeof(buf));
        errno = 0;
        ssize_t r = read(rfd, buf, sizeof(buf) - 1);
        printf("  另开 fd 立刻 read() = %ld 字节，内容 = [%s]\n", (long) r, buf);
        printf("  → 此刻数据在**内核页缓存**里：写端还在、也没 fsync，磁盘上那份未必更新\n");
        printf("     （能读到 ⟸ 说明 write 拷进的是内核；**不**说明它已经落盘，见 ②）\n");
        close(rfd);
        close(fd);
    }

    printf("\n== ② 脏页计数器：write 之后涨，fsync 之后落 ==\n");
    {
        const size_t CHUNK = 1u << 20;      /* 1 MiB */
        /* 共 16 MiB —— 正好等于 CE 的 RLIMIT_FSIZE 上限（probe13c 实测 16777216）。
           挑这个数是因为：16 MiB = 4096 页，nr_dirty 应该恰好 +4096，可以**当场对账**。 */
        const int NCHUNK = 16;
        char *buf = malloc(CHUNK);
        long d0, d1, d2;

        if (buf == NULL) {
            printf("  malloc 失败\n");
            return EXIT_FAILURE;
        }
        memset(buf, 'D', CHUNK);

        d0 = vmstat_val("nr_dirty");
        printf("  写之前      : Dirty=%-9ld kB  Writeback=%-8ld kB  nr_dirty=%-8ld  nr_writeback=%ld\n",
               meminfo_kb("Dirty"), meminfo_kb("Writeback"), d0, vmstat_val("nr_writeback"));

        int fd = open(TMPFILE, O_WRONLY | O_TRUNC);
        if (fd == -1) {
            printf("  open 失败 errno=%d(%s)\n", errno, strerror(errno));
            free(buf);
            return EXIT_FAILURE;
        }
        for (int i = 0; i < NCHUNK; i++) {
            if (write(fd, buf, CHUNK) != (ssize_t) CHUNK) {
                printf("  write 失败 errno=%d(%s)\n", errno, strerror(errno));
                break;
            }
        }
        d1 = vmstat_val("nr_dirty");
        printf("  写 %d MiB 后 : Dirty=%-9ld kB  Writeback=%-8ld kB  nr_dirty=%-8ld  nr_writeback=%ld\n",
               NCHUNK, meminfo_kb("Dirty"), meminfo_kb("Writeback"),
               d1, vmstat_val("nr_writeback"));
        printf("  → nr_dirty 的增量 = %ld 页；而 %d MiB / %ld 字节页 = %ld 页\n",
               d1 - d0, NCHUNK, (long) sysconf(_SC_PAGESIZE),
               (long) (NCHUNK * CHUNK / (size_t) sysconf(_SC_PAGESIZE)));
        printf("     两者对得上 ⟹ 这 16 MiB 一个字都没上磁盘，全在页缓存里等着。\n");
        printf("     另外 nr_dirty(页) x 4 = Dirty(kB) 恒成立：%ld x 4 = %ld\n",
               d1, d1 * 4);

        errno = 0;
        int fr = fsync(fd);
        int fe = errno;
        printf("  fsync(fd) = %d errno=%d(%s)\n", fr, fe, strerror(fe));
        d2 = vmstat_val("nr_dirty");
        printf("  fsync 之后  : Dirty=%-9ld kB  Writeback=%-8ld kB  nr_dirty=%-8ld  nr_writeback=%ld\n",
               meminfo_kb("Dirty"), meminfo_kb("Writeback"),
               d2, vmstat_val("nr_writeback"));
        printf("  → nr_dirty 从 %ld 落回 %ld，就是 fsync 把脏页推下去的。\n", d1, d2);

        printf("  ⚠️ 这两个计数器是**整机（宿主）**口径，不是本进程的：\n");
        printf("     别的容器、别的进程也在写盘，所以绝对值**必然漂移**；\n");
        printf("     但上面那句「增量 == 页数」是**当次运行内**成立的，可以当场验。\n");
        printf("  ⚠️ 反过来看时间：write() 把 16 MiB 拷进内核只花了毫秒级 ——\n");
        printf("     这不是磁盘的速度，是**内存拷贝**的速度，收益全在延迟写上。\n");
        close(fd);
        free(buf);
    }

    printf("\n== ③ 总字节数不变，只改块大小：系统调用次数差 4 个数量级 ==\n");
    {
        const size_t TOTAL = 1u << 20;      /* 每档都写 1 MiB */
        const size_t sizes[] = {1, 16, 256, 4096, 65536};
        char *big = malloc(65536);

        if (big == NULL) {
            printf("  malloc 失败\n");
            return EXIT_FAILURE;
        }
        memset(big, 'B', 65536);
        printf("  目标：每档都写 %zu 字节，只改 write() 的 buf-size\n", TOTAL);
        printf("    %-10s %-14s %-10s\n", "buf-size", "write() 次数", "耗时(s)");
        for (size_t k = 0; k < sizeof(sizes) / sizeof(sizes[0]); k++) {
            size_t bs = sizes[k];
            int fd = open(TMPFILE, O_WRONLY | O_TRUNC);
            double t0, t1;
            size_t calls = 0, done = 0;

            if (fd == -1) {
                printf("  open 失败 errno=%d(%s)\n", errno, strerror(errno));
                break;
            }
            t0 = now_sec();
            while (done < TOTAL) {
                size_t n = (TOTAL - done < bs) ? (TOTAL - done) : bs;
                if (write(fd, big, n) != (ssize_t) n)
                    break;
                done += n;
                calls++;
            }
            t1 = now_sec();
            close(fd);
            printf("    %-10zu %-14zu %.4f\n", bs, calls, t1 - t0);
        }
        printf("  → 总字节一样，buf-size 从 1 加到 65536，write() 次数从 1048576 降到 16\n");
        printf("     （差 65536 倍 ≈ 4.8 个数量级），耗时跟着掉。\n");
        printf("  ⚠️ CE 上测到的**耗时是另一台机器**的值，只能看趋势；\n");
        printf("     但「次数」是算出来的（TOTAL / buf-size），绝对可靠。\n");
        free(big);
    }

    printf("\n== ④ 本节结论：两层缓冲里的「下面那一层」 ==\n");
    printf("  read()/write()  <-copy->  内核页缓存  <-writeback->  磁盘\n");
    printf("  ① 证明「返回时数据在内核」；② 证明「此时还没落盘」；③ 证明「块大小决定系统调用次数」\n");
    printf("  要把它推进磁盘：fsync()/fdatasync()/sync() 或 O_SYNC（见 13.3）\n");

    unlink(TMPFILE);
    return EXIT_SUCCESS;
}
```

## 常见坑

| # | 坑 | 正解 |
|---|----|------|
| 1 | 以为 `write()` 返回就成了「数据已保存」 | 它只保证「字节进了页缓存」。要持久化必须 `fsync` / `fdatasync` / `sync` / `O_SYNC`（见 [13.3](13.3-controlling-kernel-buffering.md)） |
| 2 | 用「另一个 fd 能读到」来证明「落盘了」 | 页缓存是**全系统共享**的，所有 fd 都看得见同一份。可见性只能证明「至少到了页缓存」 |
| 3 | 用 `nr_dirty` 的绝对值判断本进程写了多少 | `nr_dirty` / `Dirty` 都是**整机**口径。只有「同一次运行内的增量」可用，且仍有其他进程干扰 |
| 4 | 认为「延迟写」是纯粹的延迟 | 它是**吞吐换延迟**：`write()` 快了，但数据在窗口期（默认最长 30 秒）内有丢失风险 |
| 5 | 把 `dirty_ratio` 触发的回写当成「磁盘慢」 | 脏页超过 `dirty_ratio`（本机 20%）时，**写操作自己**会被迫参与回写，于是「写变慢」——这是内核限流，不是设备问题 |
| 6 | 小块 `write()` 后再抱怨吞吐低 | 先看「系统调用次数」这一列：`buf-size = 1` 时 1 MiB 要 1048576 次调用，开销全在切换上 |
| 7 | 拿 `st_size` 当「数据已写出」的证据 | `st_size` 反映的是**内核里**的 inode 大小（`i_size`），同样不代表落盘 |
| 8 | 在 CE 里写超过 16 MiB 的文件 | 会收到 `SIGXFSZ(25)`，而且**该信号不刷 stdio 缓冲**，程序的输出会整段消失（`probe13b` 首跑实测，exit code 153）。看到「程序莫名没有输出」先怀疑它 |

## HFT / 嵌入式关联

| 场景 | 结论怎么用 |
|------|-----------|
| **成交回报 / 订单日志** | `write()` 返回只代表字节进了页缓存。对「不可丢」的记录（成交、报单确认），必须在语义边界上显式 `fsync()` / `fdatasync()`；对可重放的行情快照，则宁可批量写、让内核延迟写把小块攒大 —— 这是吞吐与持久性的取舍点 |
| **延迟分布** | 页缓存把「磁盘延迟」从写路径上挪走了，但**没消除**：脏页超过 `dirty_ratio` 之后，回写压力会**反压到写调用自己**，表现为尾延迟尖刺。监控 `nr_dirty` / `Dirty` 就是提前看到这堵墙 |
| **块大小调优** | 这是最直接的旋钮：把行情入库的 `write()` 从 64 B 提到 64 KiB，系统调用次数从「每条一次」变成「每千条一次」。在 CE 上实测同一份 1 MiB 数据，次数差 65536 倍 |
| **嵌入式掉电保护** | 板子没有 UPS，掉电就等于拔电。页缓存里未回写的脏页**全部丢失**，且 `ext4` 默认 `data=ordered` 只能保证「不含新数据的旧内容」而不保证新数据可达。关键数据用 `fdatasync()`（比 `fsync` 省一次元数据同步） |
| **flash 寿命** | 延迟写会把多个小写合并成一次设备写 —— 对 NAND 是好事（少一次擦写周期）。反过来，无脑 `O_SYNC` 会把每次 `write` 都变成一次设备往返，flash 磨损与延迟双双恶化 |
| **`/proc/vmstat` 就是监控接口** | `nr_dirty` / `nr_writeback` / `pgwriteback` 这些计数器是自监控的**低成本**来源（一次 `read()` 一个文件），比调 `sysinfo()` 更细。但注意它是**整机口径**，容器里读不到「本容器自己的」脏页量 |

<summary>代码自测（Q&A）</summary>

**Q1：`write()` 返回之后，数据可能在哪几个位置？**

A：三个层次，从近到远：① 可能还在 **stdio 用户态缓冲**里（如果用的是 `fprintf`/`fwrite` 且没 `fflush`，见 [13.2](13.2-stdio-file.md)）；② 一定已经到了 **内核页缓存**（`write(2)` 返回就意味着这次拷贝完成了）；③ **不保证**在磁盘上。本节 ① 段证明的是 ②，② 段证明的是 ③ 不成立。

**Q2：怎么用可观测的数据证明「数据还在页缓存里」？**

A：看内核计数器：`/proc/vmstat` 的 `nr_dirty`（单位：页）和 `/proc/meminfo` 的 `Dirty`（单位：kB）。本节写入 16 MiB（= 4096 页）前 `nr_dirty = 459`、写后 `4551`（增量 4092），`fsync` 后落回 `487`。两条交叉校验：增量应与页数同量级，且 `nr_dirty × 4 = Dirty`（4551 × 4 = 18204 ✓）。

**Q3：为什么增量是 4092 而不是恰好 4096？这算实验失败吗？**

A：不算。`nr_dirty` 是**整机（宿主）**计数器，采样之间的几毫秒里其他进程也在制造/回写脏页。判定标准是「同一数量级、方向正确、能落回」——而不是逐页精确。要更干净的对账只能在没有其他负载的机器上做一次。

**Q4：1 MiB 数据，`buf-size` 从 1 改到 65536，系统调用次数怎么变？哪个数字与机器无关？**

A：次数从 1048576 降到 16（差 65536 倍）。**次数**与机器无关（它是 `总计 / buf-size` 算出来的），**耗时**在 CE 上属于另一台宿主机、只能看趋势。这也是为什么本节的原则是「先用次数下结论、再用耗时佐证」。

**Q5：`dirty_ratio` 与 `dirty_background_ratio` 有什么区别？**

A：本机分别是 **10%** 和 **20%**（`probe13b` 实测）。`dirty_background_ratio` 是「后台 flusher 开始干活的线」；`dirty_ratio` 是「前台进程被迫自己回写的线」。后者被触发时，业务看到的是**写延迟突然变大**——那不是设备慢，是内核在限流。

**Q6：为什么 CE 里的程序写超过 16 MiB 会「没有任何输出」？**

A：容器的 `RLIMIT_FSIZE = 16777216`（`probe13c` 实测）。超限时进程收到 `SIGXFSZ(25)` 并被终止，而**信号不会触发 stdio 缓冲的刷新**，所以此前 `printf` 的内容（还全在 socket 的发送缓冲里）一起丢掉，只留下一个非零 exit code（`probe13b` 首跑是 153 = 128 + 25）。这是一种「看起来像程序没跑」的失败，排查时先看 exit code 里的信号位。
