## 1. 五个手段与它们的作用域

```c
#include <unistd.h>

int fsync(int fd);        /* 该文件的数据 + 元数据，等到设备完成 */
int fdatasync(int fd);    /* 该文件的数据（+ 读回数据所必需的元数据） */
void sync(void);          /* 全系统所有脏页，不等待设备确认 */
```

| 手段 | 作用域 | 等设备确认？ | 备注 |
|------|--------|-------------|------|
| `sync()` | **全系统**所有脏页、所有文件系统 | **不等**（标准允许「只排队就返回」） | 古老接口；业务里几乎不该用 |
| `fsync(fd)` | **这一个文件**：数据 + 全部元数据 | 等 | 最贵，最保险 |
| `fdatasync(fd)` | **这一个文件**：数据 + 影响数据可达性的元数据 | 等 | 通常比 `fsync` 便宜 |
| `O_SYNC`（`open` 标志） | **每一次** `write()` 都走同步语义 | 等 | 内建在 `write` 上，改不了 |
| `O_DSYNC`（`open` 标志） | 同上，但语义对齐 `fdatasync` | 等 | 每次 `write` 都同步 |

实测常量值（`c13_3_sync_calls.c` ① 段）：

```text
== ① 三个刷盘调用 & 四个打开标志 ==
  sync()       刷**全局**所有脏页（不区分文件、不等待设备确认）
  fsync(fd)    刷**这一个文件**的数据 + 元数据，等到设备完成
  fdatasync(fd) 刷数据（+ 读回数据所必需的元数据），通常比 fsync 轻

  O_SYNC   = 04010000
  O_DSYNC  = 010000
  O_RSYNC  = 04010000
  O_DIRECT = 040000
  O_RSYNC == O_SYNC ? 1   （Linux 上这两者是同一个值：只同步写，不同步读）
  ⚠️ SUSv3 本来给 O_RSYNC 定义了「读也同步」的语义，Linux 没有实现，
     直接把它定义成 O_SYNC 的同义词 —— 这是「标准说要、实现不做」的经典例子。
```

「`O_RSYNC == O_SYNC`」这条**是 Linux 特有的**：SUSv3 给了 `O_RSYNC` 一个独立语义（「读操作也要同步」），Linux 没实现它，直接在 `bits/fcntl-linux.h` 里 `#define O_RSYNC O_SYNC`。所以**别写依赖 `O_RSYNC` 做读同步的代码**——在 Linux 上它不会有任何效果。

> Linux 还额外提供 `sync_file_range(2)`（可以只刷文件的某个区间、且**不保证**元数据落盘），但它不在本章的讨论范围里；要用得先读 man page 的 CAVEATS 一节。

## 2. 哪些 `fd` 上 `fsync` 会失败——以及为什么是 `EINVAL` 不是 `ESPIPE`

实测：

```text
== ② fsync 在哪些 fd 上失败，错误码是什么 ==
  普通文件(O_RDWR)   fsync=0   errno=0  (Success          )  fdatasync=0   errno=0  (Success)
  普通文件(O_RDONLY) fsync=0   errno=0  (Success          )  fdatasync=0   errno=0  (Success)
  /proc/version          fsync=-1  errno=22 (Invalid argument )  fdatasync=-1  errno=22 (Invalid argument)
  /dev/null              fsync=-1  errno=22 (Invalid argument )  fdatasync=-1  errno=22 (Invalid argument)
  管道读端           fsync=-1  errno=22 (Invalid argument )  fdatasync=-1  errno=22 (Invalid argument)
  管道写端           fsync=-1  errno=22 (Invalid argument )  fdatasync=-1  errno=22 (Invalid argument)

  → 失败的一律是 errno=22(EINVAL)，**不是 ESPIPE(29)**：
     内核判据在 fs/sync.c:180-190 的 vfs_fsync_range()：
       if (!file->f_op->fsync)
           return -EINVAL;
     /proc 的伪文件、/dev/null、管道，它们的 file_operations 里
     **根本没有 .fsync 这个回调**，于是走不到「设备不支持」那一步，
     直接在 VFS 层被判 EINVAL。
  → 「只读 fd 上 fsync 也返回 0」也不是巧合：
     do_fsync() 只做 fdget() + vfs_fsync()，**完全不看打开模式**。
     所以 `fsync(open(path, O_RDONLY))` 是合法的（虽然没什么用）。
```

两个「反直觉」点值得展开：

| 反直觉 | 为什么 | 工程含义 |
|--------|-------|---------|
| 管道 / `/dev/null` 上 `fsync` 是 **`EINVAL`** 而不是 **`ESPIPE`** | `ESPIPE` 是 `lseek` 类操作对「不可定位」对象的判据（管道会返回它）。而 `fsync` 的第一道关是 VFS 层的「这个 `file_operations` 有没有 `.fsync` 回调」——没有就直接 `EINVAL`，**根本走不到「设备/对象不支持」那一步** | 代码里对不认识的对象统一处理 `fsync` 失败时，**按 `EINVAL` 兜底比按 `ESPIPE` 更实际**。判错了会漏掉 `/dev/null`、`/proc` 这类 fd |
| 只读打开的 fd 上 `fsync` 也返回 **0** | `do_fsync()` 只做 `fdget()` + `vfs_fsync()`，**完全不检查 `O_RDONLY`** | 所以「`fsync` 失败 ⇒ 数据没落盘」这个推理**不成立**：反方向也不成立（`fsync` 成功 ⇒ 这次 `write` 的数据落盘了）——它只保证「**这个文件**当前所有脏页都被推下去了」。这是 `fsync` 语义容易被误用的地方 |

## 3. `fsync` 与 `fdatasync` 在内核里的差别只有三行

```text
== ③ fsync 与 fdatasync 在内核里的唯一差别 ==
  fs/sync.c:180-190 的 vfs_fsync_range()：
    if (!file->f_op->fsync) return -EINVAL;
    if (!datasync && (inode->i_state & I_DIRTY_TIME))
        mark_inode_dirty_sync(inode);
    return file->f_op->fsync(file, start, end, datasync);
  → 差别只在中间那三行：**fsync 会把「只有时间戳脏」的 inode
     提升成真正需要同步的 inode**，fdatasync 不会。
     换句话说：纯粹只改了 mtime/atime 时，fdatasync 可以合法地什么都不写。
  → 所以「fdatasync 更快」只在你**不在乎时间戳**的时候成立；
     而且注意它是**量级上的差别**，不是「fdatasync = fsync / 2」。
```

把它们连起来看，`vfs_fsync_range()` 就是**唯一**的业务判据所在：

```c
int vfs_fsync_range(struct file *file, loff_t start, loff_t end, int datasync)
{
	struct inode *inode = file->f_mapping->host;

	if (!file->f_op->fsync)
		return -EINVAL;
	if (!datasync && (inode->i_state & I_DIRTY_TIME))
		mark_inode_dirty_sync(inode);
	return file->f_op->fsync(file, start, end, datasync);
}
```

`I_DIRTY_TIME` 是「**只有**时间戳需要更新」这个状态的标志位（`sb`/`inode` 层面的延迟时间戳更新，由 `CONFIG_*` 与挂载选项影响）。`fsync` 遇到它就 `mark_inode_dirty_sync()` 把 inode 提升成「真脏」，再往下走；`fdatasync` 直接跳过——于是文件系统有机会只写数据块、不写 inode。

**所以「`fdatasync` 比 `fsync` 快多少」是一个依文件系统/挂载选项而变的量**，不是一个固定比例。想知道在**你的**文件系统上是多少，只能测（见 [13.9 习题 13-2](13.9-exercises.md)）。

## 4. `O_SYNC` 的代价

```text
== ④ O_SYNC 的代价：写 1 MiB 对比 ==
  固定 buf-size = 4096，写 1048576 字节（256 次 write）
    普通 O_WRONLY    耗时 0.0007 s
    O_WRONLY|O_SYNC    耗时 0.7527 s
  → O_SYNC 让每次 write 都等到设备确认，代价可能是**几十到上千倍**。
  ⚠️ CE 的绝对耗时不能当本机数据；请只看**两个模式之间的比值**。
```

**这里最该记住的是「乘起来」这件事**：`O_SYNC` 的代价是**每次 `write`** 一次，所以总代价 ≈ 「单次同步成本 × `write` 次数」。而 `write` 次数又由块大小决定（[13.1 §3](13.1-buffer-page-cache.md)）——于是「`O_SYNC` + 小块」是最坏的组合：

| 组合 | 同步次数 | 后果 |
|------|---------|------|
| `O_SYNC` + 1 字节缓冲 | 1048576 次设备往返 | 原书 Table 13-3 里这个组合要 **1030 秒**（写 1 MB） |
| `O_SYNC` + 4 KiB 缓冲 | 256 次 | 本机实测 0.75 秒 |
| 无 `O_SYNC` + 4 KiB | 0 次同步（由内核延迟写） | 0.0007 秒 |

所以原书的建议是：**不要为了「保险」全局挂 `O_SYNC`**。要持久化就在真正需要的那几个点上显式 `fsync` / `fdatasync`；要吞吐就加大块、让内核延迟写。

## 5. 最容易漏的一条：`O_SYNC` 管不到 stdio 缓冲

`O_SYNC` 是 `open(2)` 的标志，它改的是**内核侧**这个 fd 的行为——可它管不到**上游**的用户态缓冲：

```text
== ⑤ O_SYNC 管的是 write()，管不到 stdio 缓冲 ==
  fcntl(fd, F_GETFL) = 0100001，O_SYNC 位 = 0
  fcntl(fd, F_SETFL, flags|O_SYNC) = 0 errno=0(Success)
  fprintf 之后立刻 fstat(fd).st_size = 0  ← 一个字都还没进内核
  fflush 之后 st_size = 51  ← 这才进了页缓存（O_SYNC 才有机会介入）
  → 结论：`O_SYNC` 是给 `write(2)` 的语义，**stdio 缓冲在它上游**。
     FILE* 上不 fflush，O_SYNC 一点用都没有 —— 这是本章最实用的一条。
```

`fcntl(fd, F_SETFL, ...)` 只输出 `0100001` 里的低位标志（`O_RDWR|O_CREAT|...`），而 `O_SYNC` 位是 0 —— 也就是说可以**事后**给一个已打开的 fd 加上 `O_SYNC`（`F_SETFL` 允许改的标志里包含 `O_SYNC`）。加了之后：

- 效果生效点仍然是 `write(2)`；
- `fprintf` 仍然把字节攒在用户态缓冲里，`fstat(fd).st_size` 仍然是 **0**；
- 只有 `fflush` 之后那 51 字节进了页缓存，`O_SYNC` 才有机会介入。

**工程结论**：在 `FILE*` 上谈 `O_SYNC` 是无效的。要用就必须 `fflush` 之后再谈持久化，或者干脆别用 stdio（直接 `write`）。

完整源码 [`code/c13_3_sync_calls.c`](../code/c13_3_sync_calls.c)：

```c
/* c13_3_sync_calls.c — Ch13 §13.3：控制文件 I/O 的内核缓冲
 *
 * TLPI §13.3（p.239）给了两套手段：
 *   ① 用 `fsync()` / `fdatasync()` / `sync()` **在需要的时候**主动刷；
 *   ② 用 `O_SYNC` / `O_DSYNC` 在 `open()` 时声明「以后每次 write 都同步」。
 * 本程序把 §13.3 里那些「课上讲了但没人量过」的边界钉住：
 *   ① 三个调用的作用域；`O_SYNC` / `O_DSYNC` / `O_RSYNC` 的实际数值与等价关系；
 *   ② `fsync` 在哪些 fd 上会失败、**错误码是 EINVAL 而不是 ESPIPE**，为什么；
 *   ③ **只读 fd 上 fsync 也返回 0**（内核不看打开模式）；
 *   ④ `fsync` 与 `fdatasync` 在内核里的**唯一**语义差别（时间戳）；
 *   ⑤ `O_SYNC` 的代价有多大（1 MiB 写，比普通写慢几个数量级）；
 *   ⑥ `O_SYNC` **管不到**还待在 stdio 缓冲里的字节 —— 这是本节最实用的坑。
 *
 * 编译： gcc -O0 -Wall -Wextra -o c13_3_sync_calls c13_3_sync_calls.c
 * 取材： TLPI §13.3（同步 I/O 的定义、O_SYNC/O_DSYNC/O_RSYNC、Table 13-3 的开销对比）
 *       man-pages 6.19 fsync(2)（EINVAL/EBADF；fdatasync 不刷不影响读回数据的元数据）
 *                      sync(2)（"the kernel may still be writing"）
 *                      open(2) 的 O_SYNC / O_DSYNC / O_RSYNC
 *       Linux v6.6 fs/sync.c:111（SYSCALL_DEFINE0(sync)）
 *                      fs/sync.c:180-190（vfs_fsync_range：`if (!file->f_op->fsync)
 *                        return -EINVAL;` —— EINVAL 的唯一来源）
 *                      fs/sync.c:185-186（`if (!datasync && (inode->i_state &
 *                        I_DIRTY_TIME)) mark_inode_dirty_sync(inode);` —— fsync 与
 *                        fdatasync 在内核里的唯一语义差别）
 *                      fs/sync.c:205-226（do_fsync / SYSCALL_DEFINE1(fsync|fdatasync)）
 */
#define _GNU_SOURCE
#include <errno.h>
#include <fcntl.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <sys/stat.h>
#include <time.h>
#include <unistd.h>

#define F1 "/app/c13_3.bin"

static double now_sec(void)
{
    struct timespec ts;

    clock_gettime(CLOCK_MONOTONIC, &ts);
    return (double) ts.tv_sec + (double) ts.tv_nsec / 1e9;
}

/* 对一个 fd 试 fsync + fdatasync，把结果打出来 */
static void try_sync_pair(const char *tag, int fd)
{
    int e1, e2;

    errno = 0;
    int r1 = fsync(fd);
    e1 = errno;
    errno = 0;
    int r2 = fdatasync(fd);
    e2 = errno;

    printf("  %-22s fsync=%-3d errno=%-3d(%-17s)  fdatasync=%-3d errno=%-3d(%s)\n",
           tag, r1, e1, strerror(e1), r2, e2, strerror(e2));
}

int main(void)
{
    printf("== ① 三个刷盘调用 & 四个打开标志 ==\n");
    {
        printf("  sync()       刷**全局**所有脏页（不区分文件、不等待设备确认）\n");
        printf("  fsync(fd)    刷**这一个文件**的数据 + 元数据，等到设备完成\n");
        printf("  fdatasync(fd) 刷数据（+ 读回数据所必需的元数据），通常比 fsync 轻\n\n");
        printf("  O_SYNC   = 0%o\n", (unsigned) O_SYNC);
        printf("  O_DSYNC  = 0%o\n", (unsigned) O_DSYNC);
        printf("  O_RSYNC  = 0%o\n", (unsigned) O_RSYNC);
        printf("  O_DIRECT = 0%o\n", (unsigned) O_DIRECT);
        printf("  O_RSYNC == O_SYNC ? %d   （Linux 上这两者是同一个值：只同步写，不同步读）\n",
               O_RSYNC == O_SYNC);
        printf("  ⚠️ SUSv3 本来给 O_RSYNC 定义了「读也同步」的语义，Linux 没有实现，\n");
        printf("     直接把它定义成 O_SYNC 的同义词 —— 这是「标准说要、实现不做」的经典例子。\n");
    }

    printf("\n== ② fsync 在哪些 fd 上失败，错误码是什么 ==\n");
    {
        int fd;
        int pfd[2];

        fd = open(F1, O_CREAT | O_RDWR | O_TRUNC, 0644);
        if (fd == -1) {
            printf("  open 失败 errno=%d(%s)\n", errno, strerror(errno));
            return EXIT_FAILURE;
        }
        if (write(fd, "x", 1) != 1)
            printf("  write 失败 errno=%d\n", errno);
        try_sync_pair("普通文件(O_RDWR)", fd);

        /* 关键对照：同一个文件用**只读**打开 */
        {
            int rfd = open(F1, O_RDONLY);
            try_sync_pair("普通文件(O_RDONLY)", rfd);
            close(rfd);
        }
        close(fd);

        fd = open("/proc/version", O_RDONLY);
        try_sync_pair("/proc/version", fd);
        close(fd);

        fd = open("/dev/null", O_WRONLY);
        try_sync_pair("/dev/null", fd);
        close(fd);

        if (pipe(pfd) == 0) {
            try_sync_pair("管道读端", pfd[0]);
            try_sync_pair("管道写端", pfd[1]);
            close(pfd[0]);
            close(pfd[1]);
        }

        printf("\n  → 失败的一律是 errno=22(EINVAL)，**不是 ESPIPE(29)**：\n");
        printf("     内核判据在 fs/sync.c:180-190 的 vfs_fsync_range()：\n");
        printf("       if (!file->f_op->fsync)\n");
        printf("           return -EINVAL;\n");
        printf("     /proc 的伪文件、/dev/null、管道，它们的 file_operations 里\n");
        printf("     **根本没有 .fsync 这个回调**，于是走不到「设备不支持」那一步，\n");
        printf("     直接在 VFS 层被判 EINVAL。\n");
        printf("  → 「只读 fd 上 fsync 也返回 0」也不是巧合：\n");
        printf("     do_fsync() 只做 fdget() + vfs_fsync()，**完全不看打开模式**。\n");
        printf("     所以 `fsync(open(path, O_RDONLY))` 是合法的（虽然没什么用）。\n");
    }

    printf("\n== ③ fsync 与 fdatasync 在内核里的唯一差别 ==\n");
    printf("  fs/sync.c:180-190 的 vfs_fsync_range()：\n");
    printf("    if (!file->f_op->fsync) return -EINVAL;\n");
    printf("    if (!datasync && (inode->i_state & I_DIRTY_TIME))\n");
    printf("        mark_inode_dirty_sync(inode);\n");
    printf("    return file->f_op->fsync(file, start, end, datasync);\n");
    printf("  → 差别只在中间那三行：**fsync 会把「只有时间戳脏」的 inode\n");
    printf("     提升成真正需要同步的 inode**，fdatasync 不会。\n");
    printf("     换句话说：纯粹只改了 mtime/atime 时，fdatasync 可以合法地什么都不写。\n");
    printf("  → 所以「fdatasync 更快」只在你**不在乎时间戳**的时候成立；\n");
    printf("     而且注意它是**量级上的差别**，不是「fdatasync = fsync / 2」。\n");

    printf("\n== ④ O_SYNC 的代价：写 1 MiB 对比 ==\n");
    {
        const size_t TOTAL = 1u << 20;
        const size_t BS = 4096;
        char *buf = malloc(BS);
        int modes[2] = {0, 1};
        const char *names[2] = {"普通 O_WRONLY", "O_WRONLY|O_SYNC"};

        if (buf == NULL) {
            printf("  malloc 失败\n");
            return EXIT_FAILURE;
        }
        memset(buf, 'S', BS);
        printf("  固定 buf-size = %zu，写 %zu 字节（%zu 次 write）\n",
               BS, TOTAL, TOTAL / BS);
        for (int k = 0; k < 2; k++) {
            int flags = O_CREAT | O_WRONLY | O_TRUNC;
            size_t done = 0;
            double t0, t1;

            if (modes[k])
                flags |= O_SYNC;
            int fd = open(F1, flags, 0644);
            if (fd == -1) {
                printf("  open 失败 errno=%d(%s)\n", errno, strerror(errno));
                break;
            }
            t0 = now_sec();
            while (done < TOTAL) {
                if (write(fd, buf, BS) != (ssize_t) BS)
                    break;
                done += BS;
            }
            t1 = now_sec();
            close(fd);
            printf("    %-18s 耗时 %.4f s\n", names[k], t1 - t0);
        }
        printf("  → O_SYNC 让每次 write 都等到设备确认，代价可能是**几十到上千倍**。\n");
        printf("  ⚠️ CE 的绝对耗时不能当本机数据；请只看**两个模式之间的比值**。\n");
        printf("  ⚠️ 书上（Table 13-3）的结论值得记：**不要**为了「保险」全局挂 O_SYNC，\n");
        printf("     要么把 write 的块加大，要么在真正需要的点上显式 fsync/fdatasync。\n");
        printf("     而且记住 O_SYNC 是**每次 write** 都同步 —— 块越小越惨。\n");
        free(buf);
    }

    printf("\n== ⑤ O_SYNC 管的是 write()，管不到 stdio 缓冲 ==\n");
    {
        FILE *fp = fopen(F1, "w");
        int fd;
        struct stat st;

        if (fp == NULL) {
            printf("  fopen 失败 errno=%d(%s)\n", errno, strerror(errno));
            return EXIT_FAILURE;
        }
        fd = fileno(fp);
        /* 用 fcntl 把这个 fd 的 O_SYNC 打开（模拟另一种设置方式） */
        {
            int fl = fcntl(fd, F_GETFL);
            printf("  fcntl(fd, F_GETFL) = 0%o，O_SYNC 位 = %d\n",
                   (unsigned) fl, (fl & O_SYNC) != 0);
            errno = 0;
            int r = fcntl(fd, F_SETFL, fl | O_SYNC);
            printf("  fcntl(fd, F_SETFL, flags|O_SYNC) = %d errno=%d(%s)\n",
                   r, errno, strerror(errno));
        }
        fprintf(fp, "%s", "以 O_SYNC 打开，但这行还在 stdio 缓冲里");
        fstat(fd, &st);
        printf("  fprintf 之后立刻 fstat(fd).st_size = %ld  ← 一个字都还没进内核\n",
               (long) st.st_size);
        fflush(fp);
        fstat(fd, &st);
        printf("  fflush 之后 st_size = %ld  ← 这才进了页缓存（O_SYNC 才有机会介入）\n",
               (long) st.st_size);
        fclose(fp);
        printf("  → 结论：`O_SYNC` 是给 `write(2)` 的语义，**stdio 缓冲在它上游**。\n");
        printf("     FILE* 上不 fflush，O_SYNC 一点用都没有 —— 这是本章最实用的一条。\n");
    }

    unlink(F1);
    return EXIT_SUCCESS;
}
```

## 常见坑

| # | 坑 | 正解 |
|---|----|------|
| 1 | 用 `sync()` 来「保证我的文件写好」 | `sync()` 是**全局**的，且标准允许它不等待设备确认。要保证自己的文件就 `fsync(fd)` |
| 2 | 以为 `fsync` 失败一定是 `ESPIPE` | 管道/`/dev/null`/`/proc` 上都是 **`EINVAL(22)`**——因为它们的 `file_operations` 里没有 `.fsync` 回调 |
| 3 | 以为 `fsync` 会检查 fd 是不是可写 | `do_fsync()` **不看打开模式**，`O_RDONLY` 的 fd 上 `fsync` 照样返回 0 |
| 4 | 以为 `fdatasync` 总是比 `fsync` 快一个固定比例 | 差别只在「是否把 `I_DIRTY_TIME` 的 inode 提升为真脏」。差多少取决于文件系统与挂载选项，必须实测 |
| 5 | 全局给日志 fd 挂 `O_SYNC` | 代价是「每次 `write` 一次设备往返」，与 `write` 次数**相乘**。小缓冲下能慢 4 个数量级 |
| 6 | 在 `FILE*` 上依赖 `O_SYNC` | `O_SYNC` 作用在 `write(2)` 上，而 stdio 缓冲在它**上游**。不 `fflush` 时 `st_size` 仍是 0，`O_SYNC` 完全没机会生效 |
| 7 | 用 `O_RSYNC` 期望「读也同步」 | Linux 上 `O_RSYNC == O_SYNC`，**没有**读同步语义（SUSv3 要求了、Linux 没实现） |
| 8 | 反复 `fflush` 当「多刷几次保险」 | 第二次开始是空操作。真正的成本在 `fsync`，重复刷只会白烧 I/O |
| 9 | 忘了「`fflush` + `fsync` 是接力，不是二选一」 | 少 `fflush` → 数据还在用户态，`fsync` 看不见；少 `fsync` → 数据只在页缓存，断电就丢。见 [13.9 习题 13-3](13.9-exercises.md) |

## HFT / 嵌入式关联

| 场景 | 结论怎么用 |
|------|-----------|
| **写订单日志的持久化点** | 用 `fdatasync(fd)` 而不是 `fsync(fd)`：不需要「mtime 精确到最后一次写」这类元数据，省掉一次 inode 同步。但要注意：如果业务依赖「文件大小（inode 元数据）」来判定日志完整，那 `fdatasync` 也会带上它（因为大小关系到数据可达性） |
| **批量提交 vs 逐条提交** | 逐条 `fdatasync` = 逐条设备往返；把 N 条日志攒成一块、在**语义边界**（一批委托全部写完）做一次同步，可以把同步次数降低 N 倍。这是 HFT 日志最常见的做法 |
| **`O_SYNC` 的正确用法** | 只在「这条 fd 上的每次 `write` 都必须落盘」时才挂（例如单笔风控事件），并且**同时**保证块足够大。千万别给行情入库那种高频小块写的 fd 挂 |
| **嵌入式掉电** | 板子掉电 = 拔电。要落盘必须走到设备：`fsync`/`fdatasync`。而且注意很多 eMMC/SD 卡**自带写缓存**，`fsync` 返回不保证介质上真的写完了——要更强保证得看设备是否支持 `FUA`/`cache flush`（`fsync` 会尽量下发 flush） |
| **`/proc` 与 `/sys` 上的 fsync** | 都会返回 `EINVAL`。参数下发脚本里如果统一 `fsync` 一遍，会遇到莫名其妙的失败——按 `EINVAL` 白名单处理即可 |
| **调试「数据为什么丢」** | 排查顺序：① 用的是 stdio 吗 → 有没有 `fflush`；② 有没有 `fsync`；③ `fsync` 的返回值与 `errno` 是什么（可能是 `EINVAL`，说明这个 fd 压根不支持）；④ 设备的写缓存有没有关掉 |

<summary>代码自测（Q&A）</summary>

**Q1：`sync()` / `fsync()` / `fdatasync()` 的作用域各是什么？**

A：`sync()` = **全系统**所有脏页，且**不等待**设备确认；`fsync(fd)` = 这一个文件的**数据 + 全部元数据**，等设备完成；`fdatasync(fd)` = 这一个文件的**数据 + 可达性所需的最小元数据**，等设备完成。

**Q2：对管道调 `fsync` 得到什么错误码？为什么？**

A：`-1` / `EINVAL(22)`，**不是** `ESPIPE(29)`。因为 `vfs_fsync_range()` 的第一道判据是 `if (!file->f_op->fsync) return -EINVAL;`——管道的 `file_operations` 里根本没有 `.fsync` 回调，VFS 层直接拒掉，走不到「对象不可定位」那一步。`/dev/null`、`/proc` 文件同理。

**Q3：`fsync` 和 `fdatasync` 在内核里的差别是哪几行？**

A：`fs/sync.c` 的 `vfs_fsync_range()` 中间那三行：`if (!datasync && (inode->i_state & I_DIRTY_TIME)) mark_inode_dirty_sync(inode);`。`fsync` 会把「**只有**时间戳脏」的 inode 提升为真脏再去同步；`fdatasync` 跳过这一步，于是文件系统可以只写数据块。

**Q4：`fcntl(fd, F_SETFL, flags | O_SYNC)` 之后，`fprintf` 的输出会落盘吗？**

A：**不会**。实测：`F_SETFL` 返回 0（成功），但 `fprintf` 之后 `fstat(fd).st_size = 0` —— 字节还在**用户态缓冲**里。`fflush` 之后 `st_size` 才变成 51。`O_SYNC` 的语义挂在 `write(2)` 上，stdio 缓冲在它上游，不 `fflush` 就完全没有机会介入。

**Q5：`O_RSYNC` 在 Linux 上是什么？**

A：与 `O_SYNC` **同值**（本机实测 `O_RSYNC = O_SYNC = 04010000`）。SUSv3 要求它表达「读操作也同步」，Linux 没有实现这个语义，直接把它定义成 `O_SYNC` 的别名。所以不要写依赖 `O_RSYNC` 做读同步的代码。

**Q6：`fsync(open(path, O_RDONLY))` 合法吗？**

A：合法，返回 0。`do_fsync()` 只做 `fdget()` + `vfs_fsync()`，**完全不检查打开模式**。虽然「只读 fd 上同步」看不出有什么用，但在「统一遍历一批 fd 做 `fsync`」的代码里，它不会因为 `O_RDONLY` 而失败。

**Q7：为什么说「`O_SYNC` + 小块写」是最坏组合？**

A：因为 `O_SYNC` 的代价是**每次 `write`** 一次设备往返，而小块写让 `write` 次数暴增，两者相乘。原书 Table 13-3 里 `BUF_SIZE=1` 且带 `O_SYNC` 的组合（写 1 MB）要 **1030 秒**；本节实测 4 KiB 块带 `O_SYNC` 写 1 MiB 是 **0.7527 秒**，而不带 `O_SYNC` 只要 **0.0007 秒**。
