## 本节讲什么

前面几节讲的都是「**命令**内核做某件事」（`write` / `fsync` / `O_SYNC`）。这一节是本章唯一一个「**建议**内核」的接口：

```c
#include <fcntl.h>

int posix_fadvise(int fd, off_t offset, off_t len, int advice);
```

它不改变任何 I/O 的结果，只影响内核的**预读策略**和**缓存保留策略**。这一节回答四个问题：

1. 六个 `advice` 值各是什么，什么时候用哪个？
2. 为什么 `posix_fadvise` **不返回 `-1`**，也不设 `errno`？这与 `errno` 范式（[Ch03](../../chapter-03-system-programming-concepts/README.md)）冲突，怎么解释？
3. 各类 `fd` 上分别返回什么？（管道、坏 fd、已 `close` 的 fd、`/proc` 伪文件）
4. 「返回 0」是否意味着「内核照做了」？

> ℹ️ **关于本节标题**：`blog.man7.org` 上**早期**的章节表把 13.5 写作 "Giving the Kernel Hints about I/O Patterns: `posix_fadvise()`"，成书后的正式目录是 **"Advising the Kernel About I/O Patterns"**。本仓库以**成书版**为准（文件名与官方节号一一对应）。

## 1. 六个 `advice` 值

| `advice` | 常量值（实测） | 语义 | 典型用法 |
|----------|--------------|------|---------|
| `POSIX_FADV_NORMAL` | **0** | 恢复系统默认的预读窗口 | 模式切换后的复位 |
| `POSIX_FADV_SEQUENTIAL` | **1** | 顺序访问 → 大幅加大预读 | 从头到尾扫一遍的大文件（日志回放、离线分析） |
| `POSIX_FADV_RANDOM` | **2** | 随机访问 → 关掉预读 | 数据库的随机索引查找、B 树遍历 |
| `POSIX_FADV_WILLNEED` | **3** | 马上要用 → 现在就预取进页缓存 | 开盘前预热行情文件；启动时预读配置 |
| `POSIX_FADV_DONTNEED` | **4** | 短期不再用 → 允许立刻回收这批页缓存 | 一次性扫描完大文件后主动交还内存 |
| `POSIX_FADV_NOREUSE` | **5** | 只用一次（Linux 上基本是空操作） | 语义上等价于「DONTNEED 得早一点」，但 Linux 没实现差别 |

`offset` 与 `len` 圈定作用区间；`len == 0` 表示「从 `offset` 到文件尾」。

**预读（readahead）是这里所有语义的背景**：内核在你**还没读**的时候就先把后面的数据读进页缓存。预读窗口太小时顺序读会因「每次都等 I/O」而慢；窗口太大时随机读会浪费带宽和缓存。`advice` 就是在告诉内核「我这一批访问属于哪一类」。

> Linux 还额外提供 `readahead(2)`（直接命令内核「预取这一段」，语义比 `WILLNEED` 更直接），它是 Linux 专有接口，不在本节讨论范围。

## 2. 返回值约定：它就是错误码，**不是 `-1`**

这是本节最容易踩的一条。对普通文件逐个 `advice` 调用，实测：

```text
== ① 返回值约定：它就是错误码，不是 -1 ==
  对普通文件 /app/c13_5.bin（fd=3）逐个 advice 调用：
    POSIX_FADV_NORMAL        (常量 0) -> 返回 0   errno=0(Success)
    POSIX_FADV_RANDOM        (常量 1) -> 返回 0   errno=0(Success)
    POSIX_FADV_SEQUENTIAL    (常量 2) -> 返回 0   errno=0(Success)
    POSIX_FADV_WILLNEED      (常量 3) -> 返回 0   errno=0(Success)
    POSIX_FADV_DONTNEED      (常量 4) -> 返回 0   errno=0(Success)
    POSIX_FADV_NOREUSE       (常量 5) -> 返回 0   errno=0(Success)
    advice 乱填            (  9999) -> 返回 22  errno=0(Success)  ← 非法 advice
  → 六种合法 advice 都返回 0；非法 advice 返回 **22**（不是 -1）。
  → 从始至终 errno 都是 0 —— `perror()` 在这里**什么都打不出来**。
```

**为什么这样设计？** 因为 `errno` 是**进程级**的全局变量（线程私有实现，但语义上属「上一次失败的调用」）。而 `posix_fadvise` 被设计成**线程安全**接口，它选择用**返回值**携带错误码，避免依赖 `errno`。glibc 的实现是直接的（`sysdeps/unix/sysv/linux/posix_fadvise.c`）：

```c
int
posix_fadvise (int fd, off_t offset, off_t len, int advise)
{
  /* The system call does not support 64-bit offsets on all architectures;
     ... */
  int ret = INTERNAL_SYSCALL_CALL (fadvise64_64, fd, offset, len, advise);
  if (INTERNAL_SYSCALL_ERROR_P (ret))
    return INTERNAL_SYSCALL_ERRNO (ret);
  return 0;
}
```

`INTERNAL_SYSCALL_ERRNO(ret)` 就是把内核返回的 `-Exxx` 取出绝对值（例如内核返回 `-22` → 函数返回 `22`）。所以**返回值直接是 `errno` 风格的错误码**，而 `errno` 变量**从来没被碰过**。

同一个家族里还有 `pthread_*` 系列（`pthread_create` 等也是返回错误码，不设 `errno`）。**记忆法：把 `errno` 留给「进程级的最后一次失败」，需要线程安全的接口就改用返回值。**

## 3. 各类 `fd` 上的失败码

```text
== ② 各类 fd 上的失败码 ==
  管道读端             -> 29  errno=0(Success)  ← 期望 ESPIPE(29)
  管道写端             -> 29  errno=0(Success)
  fd = 9999（根本不存在）-> 9   errno=0(Success)  ← 期望 EBADF(9)
  合法 fd 但已 close     -> 9   errno=0(Success)
  （关闭前同一数值）      -> 0  
  /proc/version（伪文件）-> 0   errno=0(Success)  ← 连 /proc 都不报错

  → 三种失败、三种错误码，**errno 全是 0**：
     非法 advice  → EINVAL(22)
     管道         → ESPIPE(29)
     fd 不存在    → EBADF(9)
     这正是 glibc 那段代码的直接后果：
       if (INTERNAL_SYSCALL_ERROR_P (ret))
           return INTERNAL_SYSCALL_ERRNO (ret);
       return 0;
```

| 对象 | 返回 | 错误码 | 说明 |
|------|------|-------|------|
| 普通文件 | 0 | — | 六种 `advice` 都接受 |
| 非法 `advice`（9999） | **22** | `EINVAL` | 内核 `mm/fadvise.c` 在 `switch` 的 `default` 分支返回 `-EINVAL` |
| 管道（读端/写端） | **29** | `ESPIPE` | 不可定位的对象 |
| `fd = 9999` | **9** | `EBADF` | `fdget()` 失败 |
| 已 `close` 的合法 fd 编号 | **9** | `EBADF` | 同上；**关掉之后连编号都会被回收给别人**，是最难查的一类 bug |
| `/proc/version` | **0** | — | 伪文件也照收不误——因为 `advice` 只影响**页缓存**策略，而 `/proc` 根本没走页缓存 |

> `/proc` 返回 0 这件事本身就是「**返回成功 ≠ 有效果**」的最好证据：这个文件上根本不存在「页缓存」这个概念，`advice` 无从生效，但内核仍然返回成功。

## 4. 正确写法

```text
== ③ 正确写法 ==
  ❌ 错的：
       if (posix_fadvise(fd, 0, 0, POSIX_FADV_WILLNEED) == -1)
           perror("posix_fadvise");     /* 永远不成立，而且 perror 读的是旧 errno */
  ✅ 对的：
       int ret = posix_fadvise(fd, 0, 0, POSIX_FADV_WILLNEED);
       if (ret != 0)
       fprintf(stderr, "posix_fadvise: %s\n", strerror(ret));
  同类约定的还有 `pthread_*` 系列和 `statx()` 的部分返回 ——
  记法：**「线程安全」的接口常常用返回值传错误码**，因为 errno 是进程级的。
```

**错在哪**：`posix_fadvise` 永远不返回 `-1`，所以 `== -1` 这个判断**永远不成立**——错误被静默忽略；而 `perror()` 读的是**进程里上一次失败调用**留下的 `errno`，与本次调用无关，**打出来的是别人的错误**。这种「双重错误」在排查时会消耗大量时间。

## 5. `advice` 的语义与两个误解

```text
== ④ 六个 advice 的语义与典型用法 ==
  advice                   语义 / 什么时候用
  POSIX_FADV_NORMAL        默认，恢复系统推断的预读窗口
  POSIX_FADV_SEQUENTIAL    顺序访问 → 大幅加大预读
  POSIX_FADV_RANDOM        随机访问 → 关掉预读（省带宽/省缓存）
  POSIX_FADV_WILLNEED      马上要用 → 现在就预取进页缓存
  POSIX_FADV_DONTNEED      短期不再用 → 允许立刻回收这批缓存
  POSIX_FADV_NOREUSE       只用一次（Linux 上基本是空操作）

  ⚠️ 两点容易误解：
     1) 它只是**建议**：内核可以完全忽略，返回值 0 **不代表**内核照做了。
        （和 Ch12 的 `/proc/sys` 写入一个道理：返回成功 ≠ 效果发生）
     2) `DONTNEED` 只影响**页缓存**，它**不是** `fsync` 的替代品，
        也不会把脏页丢掉 —— 对脏页调 DONTNEED，内核会先把它们写回。
  → 真正可测的效果差异在性能上（命中率、预读字节数），
     本程序不装作量到了 —— 要看去 /proc/vmstat 的
     `readahead_*` / `pgscan_*` 计数在调用前后的变化。
```

两个误解展开：

| 误解 | 事实 | 后果 |
|------|------|------|
| 「返回 0 说明内核照做了」 | 内核**可以完全忽略**任何 `advice`。它只是一个 hint | 把 `DONTNEED` 当「释放内存」的保证来用，会在内存紧张时发现缓存并没有按预期回收 |
| 「`DONTNEED` 可以替代 `fsync`，或者会把脏页丢掉」 | `DONTNEED` 作用在**页缓存**上；遇到**脏页**时内核**先把它们写回**，再回收 | 在写路径后面调 `DONTNEED` 会**额外制造一次设备写**——它不是「反方向的 `fsync`」，而是「让内核有机会提前回收」 |

**那么怎么验证 `advice` 真的有效？** 只能看**副作用指标**：`/proc/vmstat` 里的 `readahead_*` 系列计数器在调用前后的变化，或者用 `mincore(2)` 看某个区间是否已被缓存。`c13_5_fadvise.c` 有意**不假装量到了**这些——它只验证返回值和错误码，把「效果验证」留给读者在真机上做。

完整源码 [`code/c13_5_fadvise.c`](../code/c13_5_fadvise.c)：

```c
/* c13_5_fadvise.c — Ch13 §13.5：给内核的 I/O 模式提示 posix_fadvise()
 *
 * TLPI §13.5（p.244）介绍 `posix_fadvise()`：给内核一个**建议**，
 * 让页缓存的预读/回收策略贴合应用的访问模式。
 *
 * 这一节最容易写错的地方**不是** advice 的语义，而是**返回值约定**：
 *   `posix_fadvise()` 失败时**不返回 -1、也不设置 errno**，
 *   它**直接把错误码当返回值**返回。
 * 本程序把这一点量出来，并把六个 advice 值、以及「哪些 fd 上会失败、失败码是什么」
 * 一起钉住。
 *
 * 编译： gcc -O0 -Wall -Wextra -o c13_5_fadvise c13_5_fadvise.c
 * 取材： TLPI §13.5（六个 advice 常量、只对文件的后半部分给建议的用法）
 *       man-pages 6.19 posix_fadvise(2)（"returns an error number ... instead of
 *         setting errno"；EBADF / EINVAL / ESPIPE）
 *       glibc 2.39 sysdeps/unix/sysv/linux/posix_fadvise.c:
 *           if (INTERNAL_SYSCALL_ERROR_P (ret))
 *             return INTERNAL_SYSCALL_ERRNO (ret);
 *           return 0;
 *         —— 「返回错误码」这条约定的出处；全程不碰 errno
 *       Linux v6.6 mm/fadvise.c（ksys_fadvise64_64 / generic_fadvise 的 EINVAL、ESPIPE）
 */
#define _GNU_SOURCE
#include <errno.h>
#include <fcntl.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <unistd.h>

#define F1 "/app/c13_5.bin"

int main(void)
{
    printf("== ① 返回值约定：它就是错误码，不是 -1 ==\n");
    {
        int fd = open(F1, O_CREAT | O_RDWR | O_TRUNC, 0644);
        struct {
            const char *name;
            int advice;
        } tab[] = {
            {"POSIX_FADV_NORMAL",     POSIX_FADV_NORMAL},
            {"POSIX_FADV_RANDOM",     POSIX_FADV_RANDOM},
            {"POSIX_FADV_SEQUENTIAL", POSIX_FADV_SEQUENTIAL},
            {"POSIX_FADV_WILLNEED",   POSIX_FADV_WILLNEED},
            {"POSIX_FADV_DONTNEED",   POSIX_FADV_DONTNEED},
            {"POSIX_FADV_NOREUSE",    POSIX_FADV_NOREUSE},
        };

        if (fd == -1) {
            printf("  open 失败 errno=%d(%s)\n", errno, strerror(errno));
            return EXIT_FAILURE;
        }
        if (write(fd, "0123456789", 10) != 10)
            printf("  write 失败 errno=%d\n", errno);

        printf("  对普通文件 %s（fd=%d）逐个 advice 调用：\n", F1, fd);
        for (size_t i = 0; i < sizeof(tab) / sizeof(tab[0]); i++) {
            errno = 0;
            int r = posix_fadvise(fd, 0, 0, tab[i].advice);
            int e = errno;
            printf("    %-24s (常量 %d) -> 返回 %-3d errno=%d(%s)\n",
                   tab[i].name, tab[i].advice, r, e, strerror(e));
        }

        errno = 0;
        int r = posix_fadvise(fd, 0, 0, 9999);
        printf("    %-24s (  9999) -> 返回 %-3d errno=%d(%s)  ← 非法 advice\n",
               "advice 乱填", r, errno, strerror(errno));
        close(fd);
        printf("  → 六种合法 advice 都返回 0；非法 advice 返回 **22**（不是 -1）。\n");
        printf("  → 从始至终 errno 都是 0 —— `perror()` 在这里**什么都打不出来**。\n");
    }

    printf("\n== ② 各类 fd 上的失败码 ==\n");
    {
        int pfd[2];

        if (pipe(pfd) == 0) {
            errno = 0;
            int r1 = posix_fadvise(pfd[0], 0, 0, POSIX_FADV_NORMAL);
            printf("  管道读端             -> %-3d errno=%d(%s)  ← 期望 ESPIPE(29)\n",
                   r1, errno, strerror(errno));
            errno = 0;
            int r2 = posix_fadvise(pfd[1], 0, 0, POSIX_FADV_NORMAL);
            printf("  管道写端             -> %-3d errno=%d(%s)\n",
                   r2, errno, strerror(errno));
            close(pfd[0]);
            close(pfd[1]);
        }

        errno = 0;
        int r3 = posix_fadvise(9999, 0, 0, POSIX_FADV_NORMAL);
        printf("  fd = 9999（根本不存在）-> %-3d errno=%d(%s)  ← 期望 EBADF(9)\n",
               r3, errno, strerror(errno));

        {
            int fd = open(F1, O_RDONLY);
            errno = 0;
            int r4 = posix_fadvise(fd, 0, 0, POSIX_FADV_NORMAL);
            close(fd);
            errno = 0;
            int r5 = posix_fadvise(fd, 0, 0, POSIX_FADV_NORMAL);   /* 已关闭的 fd */
            printf("  合法 fd 但已 close     -> %-3d errno=%d(%s)\n",
                   r5, errno, strerror(errno));
            printf("  （关闭前同一数值）      -> %-3d\n", r4);
        }

        {
            int fd = open("/proc/version", O_RDONLY);
            errno = 0;
            int r6 = posix_fadvise(fd, 0, 0, POSIX_FADV_NORMAL);
            printf("  /proc/version（伪文件）-> %-3d errno=%d(%s)  ← 连 /proc 都不报错\n",
                   r6, errno, strerror(errno));
            close(fd);
        }

        printf("\n  → 三种失败、三种错误码，**errno 全是 0**：\n");
        printf("     非法 advice  → EINVAL(22)\n");
        printf("     管道         → ESPIPE(29)\n");
        printf("     fd 不存在    → EBADF(9)\n");
        printf("     这正是 glibc 那段代码的直接后果：\n");
        printf("       if (INTERNAL_SYSCALL_ERROR_P (ret))\n");
        printf("           return INTERNAL_SYSCALL_ERRNO (ret);\n");
        printf("       return 0;\n");
    }

    printf("\n== ③ 正确写法 ==\n");
    printf("  ❌ 错的：\n");
    printf("       if (posix_fadvise(fd, 0, 0, POSIX_FADV_WILLNEED) == -1)\n");
    printf("           perror(\"posix_fadvise\");     /* 永远不成立，而且 perror 读的是旧 errno */\n");
    printf("  ✅ 对的：\n");
    printf("       int ret = posix_fadvise(fd, 0, 0, POSIX_FADV_WILLNEED);\n");
    printf("       if (ret != 0)\n");
    printf("       fprintf(stderr, \"posix_fadvise: %%s\\n\", strerror(ret));\n");
    printf("  同类约定的还有 `pthread_*` 系列和 `statx()` 的部分返回 ——\n");
    printf("  记法：**「线程安全」的接口常常用返回值传错误码**，因为 errno 是进程级的。\n");

    printf("\n== ④ 六个 advice 的语义与典型用法 ==\n");
    printf("  %-24s %s\n", "advice", "语义 / 什么时候用");
    printf("  %-24s %s\n", "POSIX_FADV_NORMAL", "默认，恢复系统推断的预读窗口");
    printf("  %-24s %s\n", "POSIX_FADV_SEQUENTIAL", "顺序访问 → 大幅加大预读");

    printf("  %-24s %s\n", "POSIX_FADV_DONTNEED", "短期不再用 → 允许立刻回收这批缓存");
    printf("  %-24s %s\n", "POSIX_FADV_NOREUSE", "只用一次（Linux 上基本是空操作）\n");
    printf("  ⚠️ 两点容易误解：\n");
    printf("     1) 它只是**建议**：内核可以完全忽略，返回值 0 **不代表**内核照做了。\n");
    printf("        （和 Ch12 的 `/proc/sys` 写入一个道理：返回成功 ≠ 效果发生）\n");
```

## 常见坑

| # | 坑 | 正解 |
|---|----|------|
| 1 | `if (posix_fadvise(...) == -1) perror(...)` | 它**永远不返回 `-1`**。正确判据是 `ret != 0`，用 `strerror(ret)` 解释。`perror` 在这里读的是别人的 `errno` |
| 2 | 以为「返回 0」= 「内核照做了」 | 它只是**建议**。`/proc/version` 上返回 0 但根本没有页缓存可作用 |
| 3 | 用 `POSIX_FADV_DONTNEED` 当 `fsync` 的替代品 | `DONTNEED` 只碰页缓存；对脏页它反而**先触发回写**。持久化只能靠 `fsync` / `fdatasync` |
| 4 | 对管道调 `posix_fadvise` 并期望 `EINVAL` | 管道上返回 **`ESPIPE(29)`**（不可定位），与 `fsync` 的 `EINVAL` 不同——两套判据 |
| 5 | 对已 `close` 的 fd 继续调 | 返回 `EBADF(9)`。而且关掉之后**编号可能已被别的 `open` 复用**，于是错误会「变成对另一个文件的操作」——这类 bug 静默且危险 |
| 6 | 以为 `POSIX_FADV_NOREUSE` 有特殊效果 | Linux 上它基本是空操作（内核只把它当作「可能再也不用」的弱提示） |
| 7 | 用 `advice` 期望立即提速 | 效果体现在**预读窗口**和**缓存保留**上，属于「长期行为调整」，不是「立刻变快」。要立刻预取就用 `WILLNEED` 或 `readahead(2)` |

## HFT / 嵌入式关联

| 场景 | 结论怎么用 |
|------|-----------|
| **开盘前预热行情/静态文件** | `posix_fadvise(fd, 0, 0, POSIX_FADV_WILLNEED)` 把文件拉进页缓存，把磁盘延迟从「撮合路径上」挪到「开盘前」。这是本章最直接的落地用法 |
| **顺序回放 vs 随机查表** | 交易日内的行情/成交回放是**顺序**的 → `SEQUENTIAL` 加大预读；订单簿的快照查表是**随机**的 → `RANDOM` 关掉预读，避免用一次读污染一整窗缓存 |
| **一次性扫描后交还内存** | 收盘后的批处理扫完大文件，用 `DONTNEED` 让内核回收这批页缓存，避免占用（尤其是小内存容器/嵌入式设备上）。注意：**如果文件是脏的，这会先触发一次回写** |
| **`errno` 判据的统一处理** | 代码里对 `posix_fadvise` 必须用返回值判断。工具函数里若混用「`errno` 派」和「返回值派」两套接口，最容易写出「错误被静默吞掉」的代码 |
| **嵌入式预读** | flash 的随机读代价高，启动时用 `WILLNEED` 把整个可执行文件/资源文件预取进来，可以显著降低首帧/首次访问延迟。但要算好内存：预取的是**整段文件**，小内存设备上要控制范围 |
| **`ram` 受限设备** | `POSIX_FADV_DONTNEED` 是嵌入式里少见的「主动交还页缓存」的手段（另一个是 `echo 3 > /proc/sys/vm/drop_caches`，但那是全局的） |

<summary>代码自测（Q&A）</summary>

**Q1：`posix_fadvise` 的错误码怎么拿？**

A：**看返回值**。它返回 `0` 表示成功，返回**正数错误码**（如 `22` = `EINVAL`、`29` = `ESPIPE`、`9` = `EBADF`）表示失败。`errno` **始终不被设置**——实测六种合法 `advice` 与三种失败情形下 `errno` 全是 0。

**Q2：为什么它不遵循 `errno` 范式？**

A：因为它被设计成**线程安全**接口。`errno` 语义上是「最近一次失败调用」的全局状态，多个线程会互相覆盖。glibc 的实现把它转成「返回值携带错误码」（`return INTERNAL_SYSCALL_ERRNO (ret);`），`pthread_*` 系列同理。

**Q3：对管道调 `posix_fadvise` 返回什么？**

A：**29（`ESPIPE`）**。注意这和 `fsync` 在管道上的结果（`EINVAL`）**不一样**——`fadvise` 走的是「不可定位」判据，`fsync` 走的是「没有 `.fsync` 回调」判据。

**Q4：`POSIX_FADV_DONTNEED` 能当 `fsync` 使吗？**

A：**不能**，而且方向相反。`DONTNEED` 是「允许回收这批页缓存」；遇到**脏页**时内核**先回写再回收**，所以它在写路径之后调反而会多一次设备写。持久化只有 `fsync` / `fdatasync` / `sync` / `O_SYNC` 这几条路。

**Q5：`/proc/version` 上 `posix_fadvise` 为什么返回 0？**

A：因为 `advice` 只影响**页缓存**策略，而 `/proc` 的内容是 `read` 时现算的（见 [Ch12 §12.1](../../chapter-12-system-process-info/notes/12.1-proc-filesystem.md)），没有页缓存可作用。内核不认为这是错误，于是返回成功。这正是「返回成功 ≠ 效果发生」的干净例证。

**Q6：`offset`/`len` 的「`len == 0`」是什么含义？**

A：「从 `offset` 到文件末尾」。想作用整文件就写 `posix_fadvise(fd, 0, 0, advice)`。

**Q7：怎么验证 `advice` 真的生效了？**

A：看**副作用**指标：`/proc/vmstat` 的 `readahead_*` 系列计数器在调用前后的变化；或用 `mincore(2)` 检查某个地址区间是否已被缓存。这不是一个「调用即刻可断言」的接口——这一点必须诚实承认。
