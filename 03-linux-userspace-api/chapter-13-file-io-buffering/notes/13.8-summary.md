## 本章回顾：一条链路上的两层缓冲

本章从头到尾只讲一条链路，和一个核心区分：

```text
应用代码
   │  fprintf / fwrite / fgets                    ← §13.2 管这一层
   ▼
[用户态 stdio 缓冲]  ──── fflush() ────┐
   │                                   │
   │  read(2) / write(2)               │          ← §13.1 管这一层
   ▼                                   │
[内核页缓存 page cache]  ──── writeback ────► [块设备]
   ▲                                   │
   └── fsync / fdatasync / O_SYNC ─────┘          ← §13.3 管这一层
   └── posix_fadvise（只是建议）                   ← §13.5
   └── O_DIRECT（整个绕过这一层）                  ← §13.6
```

**一句话总结**：数据可能停在三层里的任意一层，每层有**各自的**刷新接口，且**接口不通用**：

| 层 | 数据在哪 | 推进到下一层的接口 | 常见误解 |
|----|---------|------------------|---------|
| 用户态缓冲 | `FILE*` 内部数组 | `fflush(fp)`（或 `fclose` / `exit`） | 以为 `\n` 总会触发刷新（只有行缓冲时才） |
| 内核页缓存 | 内存里的页 | `fsync(fd)` / `fdatasync(fd)` / `sync()` / `O_SYNC` | 以为 `write` 返回就安全了 |
| 介质 | 设备 | —— | 以为 `fsync` 一定意味着「介质上写完了」（设备写缓存还没算） |

**这一章所有反直觉行为都能用这一张表解释。**

## 决策表：我该调什么

| 我想达到的效果 | 该调的 | 不该调的／注意 |
|---------------|-------|--------------|
| 让**别的进程**看到我写的数据 | `fflush(fp)` | 不需要 `fsync` |
| 让数据**掉电后还在** | `fflush(fp)` **然后** `fsync(fileno(fp))` | 只做其中一个都不够 |
| 只刷数据、不在乎时间戳 | `fdatasync(fileno(fp))` | —— |
| 每次 `write` 都落盘 | `O_SYNC` / `O_DSYNC`（**并加大块**） | 小块 + `O_SYNC` 是最坏组合 |
| 提高吞吐 | 加大块、让内核延迟写 | 无脑 `O_SYNC` |
| 绕过页缓存 | `O_DIRECT` + 对齐 + `posix_memalign` | 它**不**解决持久化 |
| 给内核访问模式提示 | `posix_fadvise()` | 判据是**返回值**，不是 `errno` |
| 顺序扫描大文件 | `POSIX_FADV_SEQUENTIAL` / `WILLNEED` | —— |
| 随机查表 | `POSIX_FADV_RANDOM` | 别用 `SEQUENTIAL`（会把缓存冲掉） |
| 用完交还页缓存 | `POSIX_FADV_DONTNEED` | **不是** `fsync` 的替代；对脏页会先触发回写 |

## 反直觉清单

1. **`write()` 返回 ≠ 落盘** —— 它只保证字节进了页缓存（13.1 实测 `nr_dirty` 涨了 4092 页）。
2. **「另一个 fd 能读到」证明不了落盘** —— 页缓存是共享的；`fsync` 之后外部可见性**毫无变化**（13.4 的 2→3 级）。
3. **`__fbufsize(stdout)` 不等于 `BUFSIZ`** —— 实测 4096 vs 8192，因为 glibc 取 `min(BUFSIZ, st_blksize)`。
4. **「stdout 到终端是行缓冲」不是约定，是代码** —— `_IO_file_doallocate()` 里 `S_ISCHR + isatty` 才设 `_IO_LINE_BUF`。
5. **`setvbuf` 返回 0 不一定生效** —— 对流已经用过的情形，glibc 部分生效仍返回 0（与 Ch12 的 `/proc/sys` 写入同型）。
6. **`setvbuf(_IONBF)` 之后 `__fbufsize` 是 1，不是 0** —— 「无缓冲」在 glibc 里就是一个 1 字节缓冲。
7. **`fsync` 在管道上返回 `EINVAL` 而不是 `ESPIPE`** —— 判据是「`file_operations` 有没有 `.fsync`」，与「能不能定位」无关。
8. **只读 fd 上 `fsync` 返回 0** —— `do_fsync()` **不看打开模式**。
9. **`fsync` 与 `fdatasync` 的差别只有三行** —— 是否把 `I_DIRTY_TIME` 的 inode 提升为真脏（`fs/sync.c`）。
10. **`O_RSYNC == O_SYNC`** —— SUSv3 要求「读也同步」，Linux 没实现，直接给了同一个值。
11. **`O_SYNC` 管不到 stdio 缓冲** —— `fcntl(F_SETFL, O_SYNC)` 之后 `fprintf`，`st_size` 仍是 **0**。
12. **`posix_fadvise` 永远不返回 `-1`，也不设 `errno`** —— 返回值就是错误码（`22` / `29` / `9`）。
13. **`posix_fadvise` 在 `/proc/version` 上返回 0** —— 那里根本没有页缓存可作用，「成功 ≠ 有效果」。
14. **`O_DIRECT` 的两套对齐值不是同一个数** —— 偏移/长度按 `bdev_logical_block_size`（512），缓冲地址按 `bdev_dma_alignment`（本机实测极松，1 字节对齐都行）。
15. **`O_DIRECT` 在 tmpfs 上是假的** —— `len=100`、`off=1` 全部成功，因为 tmpfs 没实现 direct I/O。
16. **`O_DIRECT` 不等于 `O_SYNC`** —— 两者正交，`O_DIRECT` 打开的 fd 上 `fsync` 照样返回 0。
17. **`fprintf` + `write` 混用一定乱序** —— 而且顺序错的内容**长度往往是对的**，测试容易漏过。
18. **`dup` 救不了混用** —— `dup` 出来的 fd 与原 fd 共享 `struct file`（因此共享 `f_pos`）。
19. **外部 `lseek` 会把 stdio 的写入带到新位置** —— 实测造成 104 字节文件、前 100 字节是 NUL 空洞。
20. **`fclose` 只做隐式 `fflush`，不 `fsync`** —— 「文件关了所以数据安全了」是错的。
21. **`_exit()` / 被信号杀死，用户态缓冲直接丢** —— 只有 `exit()` / 正常返回才跑 `fclose`。
22. **CE 里写超过 16 MiB 会「没有输出」** —— `SIGXFSZ(25)` 终止进程，且该信号**不刷 stdio 缓冲**。

| 事实 | 值 | 影响 |
|------|----|------|

## HFT / 嵌入式关联

| 场景 | 本章结论怎么用 |
|------|--------------|
| **「数据到哪一层」是排查第一问** | 日志丢了/重复了，先分层定位：用户态（进程被杀、没 `fflush`）、页缓存（断电、没 `fsync`）、介质（设备缓存）——三层三套修法 |
| **持久化三件套** | `fflush` + `fsync`/`fdatasync`（或 `O_SYNC`/`O_DSYNC`）+ **加大块**。少任何一件都会在某个场景丢数据 |
| **延迟与吞吐的取舍点** | 延迟写把磁盘延迟挪出写路径，但脏页超阈值后会**反压**到写调用（`dirty_ratio = 20`）。监控 `nr_dirty` 提前看到这堵墙 |
| **块大小是最大的旋钮** | 1 MiB 数据从 1 字节块改到 64 KiB 块，系统调用从 1048576 次降到 16 次。热路径上这一项比任何微优化都有效 |
| **stdio 在生产日志里的陷阱** | 重定向到文件/journal 后全缓冲，日志可能几 KB 才出现一次；串口（字符设备）反而是行缓冲，每行一次 `write` —— 两个极端都要显式设计缓冲策略 |
| **`O_DIRECT` 的适用边界** | 只给「自带缓存 + 大块批量」的场景；且必须**在目标文件系统上**验证对齐（tmpfs 上永远不报错，是最大的坑） |
| **`posix_fadvise` 预热** | 开盘前 `WILLNEED` 把行情/静态数据拉进页缓存，把磁盘延迟挪到盘前；批处理扫描完用 `DONTNEED` 交还内存（但它**不是** `fsync`） |
| **嵌入式掉电** | 板子掉电 = 拔电。两层缓冲都可能丢，且很多 eMMC/SD 自带写缓存 —— `fsync` 返回不保证介质写完。关键数据要么 `fdatasync`，要么用带掉电保护的存储 |
| **flash 寿命** | 合并小写对 NAND 是好事（少擦写周期），所以嵌入式上一般应**加大**缓冲；无脑 `O_SYNC` 会同时恶化延迟与磨损 |

<summary>本章自测（Q&A）</summary>

**Q1：一句话概括本章的核心技能。**

A：**分清「数据现在在哪一层」，并知道把每一层推进到下一层的接口**。三层（用户态缓冲 / 页缓存 / 介质）× 各自的刷新接口（`fflush` / `fsync`·`fdatasync`·`O_SYNC` / 设备自身）= 本章全部内容。任何「数据丢了/顺序错了/没落盘」的问题，都能在这张表上定位。

**Q2：为什么 13.1 里 `nr_dirty` 涨了 4092，而 13.4 里全程都是 14？**

A：I/O 量级不同。13.1 写 16 MiB（4096 页），计数器变化明显；13.4 载荷 16 字节，远小于一页，计数器分辨不出来。**同一组计数器要用在匹配的量级上**——小 I/O 用 `st_size` / 可见性判断，大 I/O 才用计数器。

**Q3：写「一行业务日志」，写出完整的持久化调用序列。**

A：`fprintf(fp, ...)` → `fflush(fp)` → `fsync(fileno(fp))`。三件事对应三层。若走裸 syscall 则是：`write(fd, ...)` → `fsync(fd)`（`fdatasync` 如果不在乎时间戳）。

**Q4：为什么「`dup` 一个 fd 来避开 stdio 缓冲」行不通？**

A：`dup` 复制的是 fd 编号，**指向同一个 `struct file`**，因此共享 `f_pos`（内核文件偏移）与状态标志。乱序的根因是「用户态缓冲 vs 内核可见性」与「共享偏移」，换 fd 两个都没解决。要独立偏移必须**重新 `open`**。

**Q5：`fsync` 和 `fdatasync` 的差别，用一句话说清。**

A：`fsync` 会把「只有时间戳脏」的 inode 提升为真脏再去同步，`fdatasync` 不会。依据是 `fs/sync.c` 的 `vfs_fsync_range()` 里那三行。**差多少依文件系统与挂载选项而定**，不是固定比例。

**Q6：`O_DIRECT` 要求对齐的三样东西，实测都对到什么值？**

A：**两套值**。偏移与长度：`bdev_logical_block_size`（本机 512，实测 `len=100`/`off=1` 都被拒）；缓冲区地址：`bdev_dma_alignment`（本机 ext4 上极松，**1 字节到 512 字节对齐全部成功**）。所以「三样都按逻辑块大小对齐」这个流行说法**不准确**。`statx` 把它们分成 `stx_dio_mem_align` / `stx_dio_offset_align` 两个字段，正说明是两个值。

**Q7：怎么判断一段「混用 stdio 与 syscall」的代码是对是错？**

A：**判顺序，不只判内容**。本仓库实测五种写法的结果分别是 `[BBBBAAAA]` / `[AAAABBBB]` / `[AAAABBBB]` / `[BBBBAAAA]` / `[~100~AAAA]`（空洞）——内容长度往往都对，只有顺序（和是否产生空洞）能区分对错。

**Q8：本章哪些数字是「一次运行有效」，哪些是环境常量？**

A：稳定：`BUFSIZ(8192)`、普通文件的 `st_blksize(4096)`、`_IO*` 常量、`O_*` 标志值、`PIPE_BUF(4096)`、`RLIMIT_FSIZE(16 MiB)`、`statfs` 的 `f_type`、各错误码。会漂移：`nr_dirty`/`Dirty` 绝对值、所有耗时、`statvfs` 可用空间、`FILE*` 地址、`MemTotal`（CE 会换宿主机）。引用后者必须注明是哪一次运行。
