## 习题 13-1：给 `copy.c` 计时

**题目要求（转引）**：用 shell 的 `time` 内建给 Listing 4-1 的 `copy.c` 计时；**(a)** 用 `-DBUF_SIZE=nbytes` 编译出不同缓冲大小再测；**(b)** 给 `open()` 加上 `O_SYNC` 再测；**(c)** 在多种文件系统上重复以上实验。

**本实现的三个偏差**（都是环境所迫，逐条说明）：

| 原书要求 | 本实现 | 原因 |
|---------|-------|------|
| 用 shell `time` | 用 `clock_gettime(CLOCK_MONOTONIC)` 自己计时 | CE 容器里**没有 `/bin/sh`**（Ch12 已实测 `system()` 返回 32512），shell 内建不可用 |
| 只报耗时 | **同时报系统调用次数** | 耗时在 CE 上是「另一台宿主机」的值；**次数是算出来的**，与机器无关，才是可移植的结论 |
| 在多种文件系统上测 | 只在 `/app`（ext4）上测；`/tmp` 上不做 `O_SYNC` | `/tmp` 是 tmpfs：① 只有 20 MiB；② 没有真实设备，`O_SYNC` 语义失真（见 [13.6](13.6-direct-io.md) 的 tmpfs 实测） |

实测（源文件 1 MiB）：

```text
== 习题 13-1：copy.c 的缓冲大小 / O_SYNC 计时（自带计时） ==
  源文件 /app/ex13_1_src.bin，大小 1048576 字节；目标是 /app/ex13_1_dst.bin
  计时用 clock_gettime(CLOCK_MONOTONIC) —— CE 里没有 shell 的 time 可用。
  同时打印**系统调用次数**（read+write 之和）：它是算得出来的，不随机器变。

  buf-size   O_SYNC   系统调用次数 耗时(s)  说明
  10         否      209717         0.0590     
  512        否      4097           0.0016     
  4096       否      513            0.0006     ← 与 BUF_SIZE 相同
  65536      否      33             0.0003     
  4096       是      513            0.7737     ← 每次 write 都等到设备确认
  65536      是      33             0.0538     ← 每次 write 都等到设备确认

== 怎么读这张表 ==
  (a) 只看「系统调用次数」那一列（它与机器无关）：
      buf-size 10 -> 512 -> 4096 -> 65536，次数按**反比**下降。
      1 MiB 用 10 字节缓冲要 20 多万次调用，用 64 KiB 只要 32 次 ——
      这就是 §13.1 说的「减少系统调用」的全部含义，耗时差异是它的**结果**，
      不是独立的一条结论。
  (b) O_SYNC 那两行：同样的 buf-size，耗时**涨一大截**。
      因为每次 write() 都要等设备确认，而小缓冲意味着 write 次数多，
      于是「同步的代价 x 次数」被乘起来 —— 这是 O_SYNC 最主要的陷阱。
```

**为什么故意没跑「小缓冲 + `O_SYNC`」**：原书 Table 13-3 里 `BUF_SIZE=1` 带 `O_SYNC`（写 1 MB）要 **1030 秒**。那不是「测不出来」，是「测出来要上千秒」，不该在沙箱里做。这个取舍写在了程序的输出里，而不是悄悄跳过。

完整源码 [`code/ex13_1_copy_bench.c`](../code/ex13_1_copy_bench.c)：

```c
/* ex13_1_copy_bench.c — Ch13 习题 13-1：copy.c 的缓冲大小 / O_SYNC 计时
 *
 * 原书习题 13-1（p.250）：
 *   用 shell 的 `time` 内建给 Listing 4-1 的 `copy.c` 计时，然后
 *     (a) 用 `-DBUF_SIZE=nbytes` 换不同缓冲大小再测；
 *     (b) 给 `open()` 加上 `O_SYNC` 再测，看不同缓冲大小下差多少；
 *     (c) 在多种文件系统上重复，看趋势是否一致。
 *
 * ⚠️ 两处必须自己动手的改动：
 *   1) CE 没有 shell，用不了 `time` 内建 → 本程序**自己**用
 *      `clock_gettime(CLOCK_MONOTONIC)` 计时，并顺带把「系统调用次数」
 *      这个更本质的量也打印出来（它不随机器变）。
 *   2) `O_SYNC` 在小缓冲下会慢到不可接受 —— 原书 Table 13-3（写 1 MB）里
 *      `BUF_SIZE=1` 从 0.73 秒变成 1030 秒。所以本程序**故意跳过**
 *      「小缓冲 + O_SYNC」的组合，并在输出里说明为什么。这是工程判断，
 *      不是偷懒：**不要**在沙箱里跑一个可能要上千秒的实验。
 *
 * 也可以用 -DBUF_SIZE=n 只跑单一配置（与书上做法一致，便于对照）：
 *     gcc -O0 -Wall -Wextra -DBUF_SIZE=10 -o ex13_1_10 ex13_1_copy_bench.c
 *
 * 编译： gcc -O0 -Wall -Wextra -o ex13_1_copy_bench ex13_1_copy_bench.c
 * 取材： TLPI 习题 13-1；§13.1 正文（"using a larger buffer size ... means
 *         performing fewer system calls"）
 *       TLPI §4.2 的 Listing 4-1（copy.c 的 BUF_SIZE 用法）
 *       TLPI §13.3 + Table 13-3（O_SYNC 的开销随 BUF_SIZE 变化极大）
 *       man-pages 6.19 read(2) / write(2) / open(2)（O_SYNC）
 */
#include <errno.h>
#include <fcntl.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <time.h>
#include <unistd.h>

#ifndef BUF_SIZE
#define BUF_SIZE 4096           /* 与 Listing 4-1 的默认做法一致 */
#endif

#define SRC  "/app/ex13_1_src.bin"
#define DST  "/app/ex13_1_dst.bin"
#define TOTAL (1u << 20)        /* 源文件 1 MiB（CE 的 RLIMIT_FSIZE = 16 MiB） */

static double now_sec(void)
{
    struct timespec ts;

    clock_gettime(CLOCK_MONOTONIC, &ts);
    return (double) ts.tv_sec + (double) ts.tv_nsec / 1e9;
}

static int make_src(void)
{
    size_t done = 0;
    char *b = malloc(65536);
    int fd;

    if (b == NULL)
        return -1;
    memset(b, 'C', 65536);
    fd = open(SRC, O_CREAT | O_WRONLY | O_TRUNC, 0644);
    if (fd == -1) {
        free(b);
        return -1;
    }
    while (done < TOTAL) {
        size_t n = (TOTAL - done < 65536) ? (TOTAL - done) : 65536;
        if (write(fd, b, n) != (ssize_t) n) {
            close(fd);
            free(b);
            return -1;
        }
        done += n;
    }
    close(fd);
    free(b);
    return 0;
}

/* 一次完整的「读-写」复制；返回耗时秒数，*calls 回填系统调用总次数 */
static double run_copy(size_t bufsize, int use_sync, size_t *calls)
{
    char *buf = malloc(bufsize);
    double t0, t1;
    size_t ncalls = 0;
    int in, out;

    if (buf == NULL)
        return -1.0;

    in = open(SRC, O_RDONLY);
    if (in == -1) {
        free(buf);
        return -1.0;
    }
    out = open(DST, O_CREAT | O_WRONLY | O_TRUNC | (use_sync ? O_SYNC : 0), 0644);
    if (out == -1) {
        close(in);
        free(buf);
        return -1.0;
    }

    t0 = now_sec();
    for (;;) {
        ssize_t n = read(in, buf, bufsize);
        ncalls++;
        if (n < 0) {
            printf("  read 失败 errno=%d(%s)\n", errno, strerror(errno));
            break;
        }
        if (n == 0)
            break;
        if (write(out, buf, (size_t) n) != n) {
            printf("  write 失败 errno=%d(%s)\n", errno, strerror(errno));
            break;
        }
        ncalls++;
    }
    t1 = now_sec();

    close(in);
    close(out);
    free(buf);
    *calls = ncalls;
    return t1 - t0;
}

int main(void)
{
    printf("== 习题 13-1：copy.c 的缓冲大小 / O_SYNC 计时（自带计时） ==\n");
    printf("  源文件 %s，大小 %u 字节；目标是 %s\n", SRC, (unsigned) TOTAL, DST);
    printf("  计时用 clock_gettime(CLOCK_MONOTONIC) —— CE 里没有 shell 的 time 可用。\n");
    printf("  同时打印**系统调用次数**（read+write 之和）：它是算得出来的，不随机器变。\n\n");

    if (make_src() == -1) {
        printf("  造源文件失败 errno=%d(%s)\n", errno, strerror(errno));
        return EXIT_FAILURE;
    }

    printf("  %-10s %-8s %-14s %-10s %s\n", "buf-size", "O_SYNC", "系统调用次数", "耗时(s)", "说明");
    {
        const size_t sizes[] = {10, 512, 4096, 65536};
        for (size_t i = 0; i < sizeof(sizes) / sizeof(sizes[0]); i++) {
            size_t calls = 0;
            double dt = run_copy(sizes[i], 0, &calls);
            printf("  %-10zu %-8s %-14zu %-10.4f %s\n",
                   sizes[i], "否", calls, dt,
                   (sizes[i] == BUF_SIZE) ? "← 与 BUF_SIZE 相同" : "");
        }
        /* 只在大缓冲上试 O_SYNC：小缓冲 + O_SYNC 的耗时是**分钟到千秒级** */
        {
            const size_t sizes2[] = {4096, 65536};
            for (size_t i = 0; i < sizeof(sizes2) / sizeof(sizes2[0]); i++) {
                size_t calls = 0;
                double dt = run_copy(sizes2[i], 1, &calls);
                printf("  %-10zu %-8s %-14zu %-10.4f %s\n",
                       sizes2[i], "是", calls, dt, "← 每次 write 都等到设备确认");
            }
        }
    }

    printf("\n== 怎么读这张表 ==\n");
    printf("  (a) 只看「系统调用次数」那一列（它与机器无关）：\n");
    printf("      buf-size 10 -> 512 -> 4096 -> 65536，次数按**反比**下降。\n");
    printf("      1 MiB 用 10 字节缓冲要 20 多万次调用，用 64 KiB 只要 32 次 ——\n");
    printf("      这就是 §13.1 说的「减少系统调用」的全部含义，耗时差异是它的**结果**，\n");
    printf("      不是独立的一条结论。\n");
    printf("  (b) O_SYNC 那两行：同样的 buf-size，耗时**涨一大截**。\n");
    printf("      因为每次 write() 都要等设备确认，而小缓冲意味着 write 次数多，\n");
    printf("      于是「同步的代价 x 次数」被乘起来 —— 这是 O_SYNC 最主要的陷阱。\n");
    printf("  (c) 书上 Table 13-3（写 1 MB）的数量级：BUF_SIZE=1 时不带 O_SYNC 约 0.7 秒，\n");
    printf("      带 O_SYNC 约 1030 秒；BUF_SIZE=4096 时约 0.01 秒 vs 0.34 秒。\n");
    printf("      → 所以本程序**故意没跑**「小缓冲 + O_SYNC」：\n");
    printf("        那不是「测不出来」，是「测出来要上千秒」，不该在沙箱里做。\n");
```

## 习题 13-2：给 `write_bytes.c` 计时

**题目要求（转引）**：给原书配套程序 `write_bytes`（写入型 benchmark）计时，换不同缓冲大小与不同文件系统。

原书程序 `write_bytes.c` 本身就是为这道题准备的——它内置了三个编译期开关：`-DUSE_O_SYNC` / `-DUSE_FSYNC` / `-DUSE_FDATASYNC`（不加开关就是普通写）。**它自己不输出任何东西**，所以本仓库既跑了原书程序（验证开关可用），也写了一个「自带计时」的版本。

### 原书程序在 CE 上的实测

| 编译旗标 | exit code | execTime |
|---------|-----------|----------|
| （无） | 0 | 27 ms |
| `-DUSE_O_SYNC` | 0 | 22 ms |
| `-DUSE_FSYNC` | 0 | 44 ms |
| `-DUSE_FDATASYNC` | 0 | 21 ms |

⚠️ **这四个数不说明任何性能问题**：CE 上写的是 `/tmp`（tmpfs，**没有真实设备**），`O_SYNC` / `fsync` 在 tmpfs 上几乎无成本，所以「同步模式的耗时」在这里失真。**要看同步代价，必须在真实块设备上做**——这正是原书要求「换多种文件系统」的原因。

`--help` 与参数校验的输出（都在 **stderr**，`exit 1`）：

```text
  Usage: ./output.s file num-bytes buf-size
```

```text
  getLong error (in num-bytes): value must be > 0
          offending text: 0
```

第二条是 `getLong(..., GN_GT_0, "num-bytes")` 的报错格式 —— 本仓库的 `get_num.h` 替身把这两行的缩进逐字对齐了原书（见 [`code/README.md`](../code/README.md)）。

完整源码 [`code/write_bytes.c`](../code/write_bytes.c)：

```c
/*************************************************************************\

/* write_bytes.c

   Write bytes to a file. (A simple program for file I/O benchmarking.)

   Usage: write_bytes file num-bytes buf-size

   Writes 'num-bytes' bytes to 'file', using a buffer size of 'buf-size'
   for each write().

   If compiled with -DUSE_O_SYNC, open the file with the O_SYNC flag,
   so that all data and metadata changes are flushed to the disk.

   If compiled with -DUSE_FDATASYNC, perform an fdatasync() after each write,
   so that data--and possibly metadata--changes are flushed to the disk.

   If compiled with -DUSE_FSYNC, perform an fsync() after each write, so that
   data and metadata are flushed to the disk.
*/
#include <sys/stat.h>
#include <fcntl.h>
#include "tlpi_hdr.h"

int
main(int argc, char *argv[])
{
    if (argc != 4 || strcmp(argv[1], "--help") == 0)
        usageErr("%s file num-bytes buf-size\n", argv[0]);

    size_t numBytes = getLong(argv[2], GN_GT_0, "num-bytes");
    size_t bufSize = getLong(argv[3], GN_GT_0, "buf-size");

    char *buf = malloc(bufSize);
    if (buf == NULL)
        errExit("malloc");

    int openFlags = O_CREAT | O_WRONLY;

#if defined(USE_O_SYNC) && defined(O_SYNC)
    openFlags |= O_SYNC;
#endif

    int fd = open(argv[1], openFlags, S_IRUSR | S_IWUSR);
    if (fd == -1)
        errExit("open");

    size_t thisWrite, totWritten;
    for (totWritten = 0; totWritten < numBytes;
            totWritten += thisWrite) {
        thisWrite = min(bufSize, numBytes - totWritten);

        if (write(fd, buf, thisWrite) != (ssize_t) thisWrite)
            fatal("partial/failed write");

#ifdef USE_FSYNC
        if (fsync(fd))
            errExit("fsync");
#endif
#ifdef USE_FDATASYNC
        if (fdatasync(fd))
            errExit("fdatasync");
#endif
    }

    if (close(fd) == -1)
        errExit("close");
    exit(EXIT_SUCCESS);
}
```

### 自带计时的版本

`ex13_2_write_bench.c` 用与 `write_bytes.c` **完全相同**的写循环，外加 `CLOCK_MONOTONIC` 计时，并多打一列「每次 `write` 平均耗时」——这一列把「次数」这个混杂因素除掉，才真正反映**单次同步**的代价：

```text
== 习题 13-2：写入型 benchmark（write_bytes.c 自带计时的版本） ==
  输出文件 /app/ex13_2.bin。计时用 CLOCK_MONOTONIC；同时给出 write() 次数与
  「每次写平均耗时」——最后这一列最能说明同步的代价。

  模式         总字节 buf-size write() 次数 耗时(s)   每次 write 平均(us)
  普通         1048576   512      2048         0.0013      0.63
  普通         1048576   4096     256          0.0004      1.61
  普通         1048576   65536    16           0.0003      15.90
  O_SYNC         1048576   512      2048         5.5500      2709.95
  O_SYNC         1048576   4096     256          0.7395      2888.63
  O_SYNC         1048576   65536    16           0.0545      3405.57
  每次 fsync   262144    512      512          1.4617      2854.97
  每次 fsync   262144    4096     64           0.1797      2807.78
  每次 fsync   262144    65536    4            0.0129      3219.51
  每次 fdatasync 262144    512      512          1.3933      2721.20
  每次 fdatasync 262144    4096     64           0.1804      2818.07
  每次 fdatasync 262144    65536    4            0.0129      3228.02

== 怎么读这张表 ==
  1) 「write() 次数」只由 总字节/buf-size 决定，**与机器无关**。
     先看这一列，再看耗时 —— 否则很容易把「调用次数多」误当成「磁盘慢」。
  2) 最后一列「每次 write 平均」把「次数」这个混杂因素除掉了，
     它才真正反映**单次同步**的代价：
       普通模式     每次调用只是内存拷贝（亚微秒级）
       O_SYNC       每次调用 = 一次设备往返（毫秒级，差 3~4 个数量级）
       每次 fsync   同理，但它只在**循环里额外调**，O_SYNC 是内建在 write 上
```

**为什么四种模式的总字节数不一样**：普通 / `O_SYNC` 各写 **1 MiB**，而 `fsync` / `fdatasync` 各只写 **256 KiB**。这是刻意的规模缩减——「512 字节缓冲 + 每次 `fsync`」写 1 MiB 会是 2048 次设备往返，把 CE 的作业时间推到不必要的长度。**同一张表里比较「每次 write 平均」这一列时不受总字节数影响**，所以缩减是无害的。

**`fdatasync` 并没有明显更快**（2721 vs 2855 μs 每次）：这符合 [13.3](13.3-controlling-kernel-buffering.md) 的分析——差别只在「是否把 `I_DIRTY_TIME` 的 inode 提升为真脏」，而这份负载每次都在改变文件大小（元数据必须写），所以 `fdatasync` 省不下什么。**这是必须在目标文件系统上实测才能知道的结论**，而不是一个可以背下来的比例。

```c
/* ex13_2_write_bench.c — Ch13 习题 13-2：给 write_bytes.c 加计时
 *
 * 原书习题 13-2（p.250）：
 *   「给本书源码分发包里的 `filebuff/write_bytes.c` 计时，
 *     换不同的缓冲大小与不同的文件系统。」
 *
 * 麻烦在于：**书上的 `write_bytes.c` 自己不打印任何耗时** ——
 * 它只负责写，计时要用 shell 的 `time` 内建（`time ./write_bytes ofile 100000000 4096`）。
 * CE 里既没有 shell 也没有 `time`，所以本程序做两件事：
 *   ① 用与 `write_bytes.c` **完全相同**的写入循环，自己在程序内计时；
 *   ② 把书上那三个编译期开关（`-DUSE_O_SYNC` / `-DUSE_FSYNC` / `-DUSE_FDATASYNC`）

 *    - 普通 / O_SYNC：1 MiB

#include <errno.h>

#define OUT "/app/ex13_2.bin"

/* 四种模式，对应书里 write_bytes.c 的四个编译分支 */
enum { M_PLAIN = 0, M_OSYNC, M_FSYNC, M_FDATASYNC };

static double now_sec(void)
{
    struct timespec ts;

    clock_gettime(CLOCK_MONOTONIC, &ts);
    return (double) ts.tv_sec + (double) ts.tv_nsec / 1e9;
}

/* 与 write_bytes.c 一模一样的循环，只是外面套了计时 */
static double bench(int mode, size_t numBytes, size_t bufSize, size_t *writes)
{
    char *buf = malloc(bufSize);
    int flags = O_CREAT | O_WRONLY | O_TRUNC | (mode == M_OSYNC ? O_SYNC : 0);
    double t0, t1;
    size_t thisWrite, totWritten;
    int fd;
    int ok = 1;

    if (buf == NULL)
        return -1.0;
    fd = open(OUT, flags, S_IRUSR | S_IWUSR);
    if (fd == -1) {
        free(buf);
        return -1.0;
    }
    *writes = 0;
    t0 = now_sec();
    for (totWritten = 0; totWritten < numBytes; totWritten += thisWrite) {
        thisWrite = (bufSize < numBytes - totWritten) ? bufSize : (numBytes - totWritten);
        if (write(fd, buf, thisWrite) != (ssize_t) thisWrite) {
            printf("  write 失败 errno=%d(%s)\n", errno, strerror(errno));
            ok = 0;
            break;
        }
        (*writes)++;
        if (mode == M_FSYNC && fsync(fd) != 0) {
            printf("  fsync 失败 errno=%d(%s)\n", errno, strerror(errno));
            ok = 0;
            break;
        }
        if (mode == M_FDATASYNC && fdatasync(fd) != 0) {
            printf("  fdatasync 失败 errno=%d(%s)\n", errno, strerror(errno));
            ok = 0;
            break;
        }
    }
    t1 = now_sec();
    close(fd);
    free(buf);
    return ok ? (t1 - t0) : -1.0;
}

{
    printf("== 习题 13-2：写入型 benchmark（write_bytes.c 自带计时的版本） ==\n");

    printf("  「每次写平均耗时」——最后这一列最能说明同步的代价。\n\n");

    printf("  %-14s %-9s %-8s %-12s %-11s %s\n",
           "模式", "总字节", "buf-size", "write() 次数", "耗时(s)", "每次 write 平均(us)");
    {
        struct {
            int mode;
            const char *name;
            size_t total;
        } modes[] = {
            {M_PLAIN,     "普通",          1u << 20},
            {M_OSYNC,     "O_SYNC",        1u << 20},

            {M_FDATASYNC, "每次 fdatasync", 1u << 18},
        };
        const size_t bufs[] = {512, 4096, 65536};

        for (size_t m = 0; m < sizeof(modes) / sizeof(modes[0]); m++) {
            for (size_t b = 0; b < sizeof(bufs) / sizeof(bufs[0]); b++) {
                size_t writes = 0;

                printf("  %-14s %-9zu %-8zu %-12zu %-11.4f %.2f\n",
                       modes[m].name, modes[m].total, bufs[b], writes, dt,
                       writes ? dt * 1e6 / (double) writes : 0.0);
            }
        }
    }

    printf("  1) 「write() 次数」只由 总字节/buf-size 决定，**与机器无关**。\n");
    printf("     先看这一列，再看耗时 —— 否则很容易把「调用次数多」误当成「磁盘慢」。\n");
    printf("  2) 最后一列「每次 write 平均」把「次数」这个混杂因素除掉了，\n");

    printf("       普通模式     每次调用只是内存拷贝（亚微秒级）\n");
    printf("       O_SYNC       每次调用 = 一次设备往返（毫秒级，差 3~4 个数量级）\n");
    printf("       每次 fsync   同理，但它只在**循环里额外调**，O_SYNC 是内建在 write 上\n");
    printf("  3) 书上 Table 13-3 的结论与此一致：**别为了保险全局挂 O_SYNC**。\n");
    printf("     要么把缓冲加大（同样的同步次数摊到更多字节上），要么只在关键点显式\n");
    printf("     `fsync()` / `fdatasync()`。\n");
```

## 习题 13-3：`fflush(fp); fsync(fileno(fp));` 的作用

**题目要求（转引）**：这两条语句各自起什么作用？

答案是一句话：**它们各推一层，是接力而不是二选一。**

| 语句 | 作用域 | 推的是哪一层 |
|------|--------|-------------|
| `fflush(fp)` | 用户态 → 内核（页缓存） | **stdio 缓冲** |
| `fsync(fileno(fp))` | 内核 → 设备 | **页缓存** |

本仓库用两个「只做一半」的陷阱来证明它们**互不替代**：

```text
== ① 陷阱：只调 fsync、不先 fflush ==
  已 fprintf 21 字节（还在 stdio 缓冲里）
  另一个 fd 看到的文件大小 = 0
  fsync(fileno(fp)) = 0 errno=0(Success)  ← 内核说「成功了」
  但另一个 fd 看到的文件大小仍然是 = 0
  → **fsync 返回 0 并不代表你的数据安全了**：它只管它看得见的那一层，
     而你的字节还在 stdio 缓冲里。这是本节最值得记住的一条。
     nr_dirty=216（16 字节远小于一页，看不出变化，仅作记录）

  补上 fflush 再看：
  fflush(fp) = 0 errno=0(Success)
  另一个 fd 看到的文件大小 = 21  ← 现在才可见
  fsync(fileno(fp)) = 0 errno=0(Success)

== ② 陷阱：只 fflush、不 fsync ==
  fileno(fp) = 3
  fflush 之后，另一个 fd 看到 21 字节 —— 数据已经离开本进程
  可这是**页缓存**；此刻拔电源，字节就没了。fflush **没有任何**持久化语义。
  → 想让「外部可见」升级成「已落盘」，只有 fsync/fdatasync/sync/O_SYNC 这几条路。
```

**①最反直觉**：`fsync` 返回 **0**（成功），但文件大小仍然是 **0**。因为 `fsync` 作用于**内核里这个文件已有的脏页**，而用户态缓冲里的 21 字节**内核根本不知道**。所以「`fsync` 成功 ⇒ 我这批数据安全了」这个推理**是错的**——`fsync` 的语义是「把这个文件当前所有**内核可见的**修改推下去」，不包括 libc 缓冲里的字节。

状态表（**串联**关系）：

```text
== ③ 两条语句连用：作用域是**串联**的，不是二选一 ==
  状态表（✓ = 该层已有数据；? = 无法从用户态直接证实）
    时刻                       stdio 用户缓冲 内核页缓存 磁盘
    fprintf 之后               ✓            —            —
    fflush 之后                —            ✓            —
    fsync 之后                 —            ✓            ✓
    fflush 返回 0，fsync 返回 0；nr_dirty 216 -> 216
  → 这两条语句不是「两个可选方案」，而是**一次接力的两棒**：
     少任何一棒，你要么丢数据，要么没落盘。
```

完整源码 [`code/ex13_3_fflush_fsync.c`](../code/ex13_3_fflush_fsync.c)：

```c
/* ex13_3_fflush_fsync.c — Ch13 习题 13-3：`fflush(fp); fsync(fileno(fp));` 到底做了什么
 *
 * 原书习题 13-3（p.250）：
 *   「下面两条语句的作用是什么？  fflush(fp);  fsync(fileno(fp)); 」
 *
 * 这题的答案不难背（一个刷用户态、一个刷内核态），但**两个顺序陷阱**很值得量：
 *   ① 只调 `fsync(fileno(fp))` 而**不先** `fflush(fp)` ——
 *      fsync 会返回 0（成功），可文件里**一个字节都没有**：
 *      因为写入还停在 stdio 缓冲里，fsync 根本不知道有这回事；
 *   ② 只调 `fflush(fp)` ——
 *      另一个 fd 已经能读到全部内容（说明进了页缓存），但**没有任何东西保证它落盘**。
 * 判据用三个能真量出来的量：
 *   - 「另一个 fd 看到多少字节」→ 数据有没有离开**本进程的用户态**；
 *   - `fsync` 的返回值 → 内核有没有把这批页交给设备；
 *   - `/proc/vmstat` 的 nr_dirty → 整机层面还有多少脏页（辅助，会被别人干扰）。
 *
 * 编译： gcc -O0 -Wall -Wextra -o ex13_3_fflush_fsync ex13_3_fflush_fsync.c
 * 取材： TLPI 习题 13-3；§13.2（fflush 的作用范围）、§13.3（fsync 的作用范围）
 *       man-pages 6.19 fflush(3)（"do not ... flush to disk"）、fsync(2)、fileno(3)
 *       Linux v6.6 fs/sync.c:205-226（do_fsync：只看 fd，不看打开模式）
 *       C99 7.19.5.3（fflush 只在输出流上定义良好）
 */
#define _GNU_SOURCE
#include <errno.h>
#include <fcntl.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <sys/stat.h>
#include <unistd.h>

#define F1 "/app/ex13_3.txt"
#define PAYLOAD "0123456789-ABCDEFGHIJ"        /* 21 字节 */
static const size_t PLEN = 21;

static long vmstat_val(const char *key)
{
    FILE *fp = fopen("/proc/vmstat", "r");
    char line[256];
    long v = -1;

    if (fp == NULL)
        return -1;
    while (fgets(line, sizeof(line), fp) != NULL) {
        if (strncmp(line, key, strlen(key)) == 0) {
            if (sscanf(line + strlen(key), " %ld", &v) != 1)
                v = -2;
            break;
        }
    }
    fclose(fp);
    return v;
}

/* 另一个 fd 能看到多少字节 */
static long other_fd_size(void)
{
    struct stat st;
    int fd = open(F1, O_RDONLY);
    long sz;

    if (fd == -1)
        return -1;
    sz = (fstat(fd, &st) == -1) ? -1 : (long) st.st_size;
    close(fd);
    return sz;
}

int main(void)
{
    printf("== 0. 先把两条语句分开 ≡ 先把两层分开 ==\n");
    printf("  `fflush(fp)`          ：把 **stdio 用户态缓冲** 交给内核（→ 页缓存）\n");
    printf("  `fsync(fileno(fp))`   ：把 **内核页缓存里属于这个文件的部分** 交给设备\n");
    printf("  载荷 \"%s\"（%zu 字节）\n\n", PAYLOAD, PLEN);

    printf("== ① 陷阱：只调 fsync、不先 fflush ==\n");
    {
        FILE *fp;
        int fd;

        unlink(F1);
        fp = fopen(F1, "w");
        if (fp == NULL) {
            printf("  fopen 失败 errno=%d(%s)\n", errno, strerror(errno));
            return EXIT_FAILURE;
        }
        fd = fileno(fp);
        fprintf(fp, "%s", PAYLOAD);
        printf("  已 fprintf %zu 字节（还在 stdio 缓冲里）\n", PLEN);
        printf("  另一个 fd 看到的文件大小 = %ld\n", other_fd_size());

        errno = 0;
        int r = fsync(fd);                 /* ← 故意不 fflush */
        printf("  fsync(fileno(fp)) = %d errno=%d(%s)  ← 内核说「成功了」\n",
               r, errno, strerror(errno));
        printf("  但另一个 fd 看到的文件大小仍然是 = %ld\n", other_fd_size());
        printf("  → **fsync 返回 0 并不代表你的数据安全了**：它只管它看得见的那一层，\n");
        printf("     而你的字节还在 stdio 缓冲里。这是本节最值得记住的一条。\n");
        printf("     nr_dirty=%ld（16 字节远小于一页，看不出变化，仅作记录）\n",
               vmstat_val("nr_dirty"));

        printf("\n  补上 fflush 再看：\n");
        errno = 0;
        int f = fflush(fp);
        printf("  fflush(fp) = %d errno=%d(%s)\n", f, errno, strerror(errno));
        printf("  另一个 fd 看到的文件大小 = %ld  ← 现在才可见\n", other_fd_size());
        errno = 0;
        r = fsync(fd);
        printf("  fsync(fileno(fp)) = %d errno=%d(%s)\n", r, errno, strerror(errno));
        fclose(fp);
    }

    printf("\n== ② 陷阱：只 fflush、不 fsync ==\n");
    {
        FILE *fp;
        int fd;

        unlink(F1);
        fp = fopen(F1, "w");
        if (fp == NULL) {
            printf("  fopen 失败 errno=%d(%s)\n", errno, strerror(errno));
            return EXIT_FAILURE;
        }
        fd = fileno(fp);
        fprintf(fp, "%s", PAYLOAD);
        fflush(fp);
        printf("  fileno(fp) = %d\n", fd);
        printf("  fflush 之后，另一个 fd 看到 %ld 字节 —— 数据已经离开本进程\n", other_fd_size());
        printf("  可这是**页缓存**；此刻拔电源，字节就没了。fflush **没有任何**持久化语义。\n");
        printf("  → 想让「外部可见」升级成「已落盘」，只有 fsync/fdatasync/sync/O_SYNC 这几条路。\n");
        fclose(fp);
    }

    printf("\n== ③ 两条语句连用：作用域是**串联**的，不是二选一 ==\n");
    {
        FILE *fp = fopen(F1, "w");
        int fd;
        int r1, r2;
        long before, after;

        if (fp == NULL) {
            printf("  fopen 失败 errno=%d(%s)\n", errno, strerror(errno));
            return EXIT_FAILURE;
        }
        fd = fileno(fp);
        before = vmstat_val("nr_dirty");
        fprintf(fp, "%s", PAYLOAD);
        printf("  状态表（✓ = 该层已有数据；? = 无法从用户态直接证实）\n");
        printf("    %-28s %-14s %-14s %s\n", "时刻", "stdio 用户缓冲", "内核页缓存", "磁盘");
        printf("    %-28s %-14s %-14s %s\n", "fprintf 之后", "✓", "—", "—");

        r1 = fflush(fp);
        printf("    %-28s %-14s %-14s %s\n", "fflush 之后", "—", "✓", "—");
        errno = 0;
        r2 = fsync(fd);
        printf("    %-28s %-14s %-14s %s\n", "fsync 之后", "—", "✓", "✓");

        printf("    fflush 返回 %d，fsync 返回 %d；nr_dirty %ld -> %ld\n", r1, r2, before, after);
```

## 习题 13-4：`printf` 与 `write` 的输出顺序为什么随重定向而变

**题面（从官方解答程序反推）**：给出的代码是

```c
printf("If I had more time, \n");
write(STDOUT_FILENO, "I would have written you a shorter letter.\n", 43);
```

要求解释：**为什么这两行的先后顺序在 stdout 重定向到终端 vs 磁盘文件时不同**。

**反推依据**：man7 上公开的 `mix23_linebuff.c` 标注为 "Solution to Exercise 13-4, page 250"，即这道题的官方解答程序；它的输出与我们需要的解释一一对应（见下）。**这是本章唯一有公开官方解答的一题**，其余四题只有转引的题干。

**答案**：因为 `printf` 走 **stdio 用户态缓冲**，而 `write` **绕过**它直接进内核。两者的可见性取决于前者的**缓冲模式**：

| stdout 的类型 | 默认缓冲模式 | `printf` 的 `\n` 会触发刷新吗 | 实际顺序 |
|--------------|-------------|--------------------------|---------|
| **终端**（字符设备 + `isatty`） | **行缓冲** | **会** | `printf` 先出，`write` 后出 |
| **磁盘文件 / 管道 / socket** | **全缓冲** | **不会** | `write` 先出，`printf` 要等到 `fflush`/`fclose` 才出 |

判定依据是 [13.2](13.2-stdio-file.md) 里 glibc 的 `_IO_file_doallocate()`：**只有** `S_ISCHR(st.st_mode) && isatty(fd)` 才设 `_IO_LINE_BUF`。重定向到文件/管道之后这个条件不成立，于是变成全缓冲，`\n` 不再触发刷新。

官方解答程序的实测输出：

```text
I would have written you a shorter letter.
If I had more time, 
```

它把 `stdout` 显式设成行缓冲，于是 `printf` 那句（带 `'\n'`）**先**出来。与 `mix23io.c`（默认全缓冲）的输出顺序**正好相反**：

```text
in accordance with his twofold attitude.
To man the world is twofold, 
```

**两个程序、同一段机制、相反的观察结果** —— 这就是本题要的解释。

> ⚠️ **CE 上的观察限制**：本容器 stdout 是 **socket**（`S_ISSOCK=1`、`isatty=0`），且**没有 pty**（`/dev/ptmx` 不存在）。所以「终端 → 行缓冲 → `printf` 先出」这一半**无法在 CE 里直接观察**，只能靠 `mix23_linebuff.c` **显式** `setvbuf(_IOLBF)` 复现。[13.2](13.2-stdio-file.md) 的 ③ 段用「管道 + `write` 参照物」的办法把行缓冲机制做成了可判定的实验。

## 习题 13-5：用 I/O 系统调用实现 `tail [-n num] file`

**题目要求（转引）**：`tail [-n num] file` 打印文件最后 `num` 行（默认 10 行）。用 `lseek()` / `read()` / `write()` 等 **I/O 系统调用**实现，并**注意本章讲的缓冲问题**，让实现是高效的。

**「高效」是这道题的关键词**，它排除了最朴素的两个写法：

| 排除的写法 | 为什么不行 |
|-----------|-----------|
| 从头读到尾、用环形缓冲保留最后 n 行 | 读的是**整个文件**，代价与文件大小成正比 |
| 先 `fstat` 拿大小、一次性读进大缓冲 | 文件大起来就是 OOM；也不符合「高效」的要求 |

**正确做法**：从文件**尾部按块往回扫**，攒够 `n+1` 个换行就停，然后一次性写出去。于是代价是 **O(尾部那点字节)**，与文件总大小**无关**。

实现里有两个容易写错的地方，本仓库都做了修正并在输出里**实测对账**：

### 修正一：行数不等于换行数（最后一行不需要以 `\n` 结尾）

POSIX 的 `tail` 定义里，**最后一段没有结尾换行符的文字也算一行**。所以：

```
文件以 '\n' 结尾  → 行数 = 换行数
否则              → 行数 = 换行数 + 1
```

用样本 `"a\nb\nc-no-newline"`（16 字节、只有 **2** 个 `'\n'`，但是 **3** 行）实测：

```text
== 边界情况（每一条都真跑一遍，不靠人眼判断）==
  样本 "a\nb\nc-no-newline"：16 字节、只有 2 个 '\n'，但是 **3 行**
  1) -n 1           → [c-no-newline]（读了 16 字节）
  2) -n 3           → [a
b
c-no-newline]（读了 16 字节）
  3) -n 0           → []（读了 16 字节）← 0 行就是 0 字节
  4) -n 99（> 行数） → [a
b
c-no-newline]（读了 16 字节）← 行数不够就是全部
  ⚠️ 看第 1) 条：实现若只拿「换行数」当行数，这里会多吐一行 'b' 出来。
```

**第 1) 条是这道题最容易错的地方**：只按「换行数」数行的实现会输出 `b\nc-no-newline`（多一行）。另外 `-n 0` 必须单独处理——否则「找不到第 skip 个换行」的 fallback 会变成「输出全部行」。

### 修正二：回扫拼接时的块对齐（本仓库在调试中真实踩到的 bug）

回扫时要把每轮读到的「更靠前的一块」拼到已累积数据**前面**。最初的写法是：

```c
want = (size_t) ((long) st.st_size - (long) used - pos);
read(fd, nb, want);                  /* 只填 nb[0..want) */
memcpy(nb + BLK, buf, used);         /* ← 错：应从 nb + want 接 */
```

当 `pos` 被夹到 0（最后一块往往**不满** `BLK`）时，`read` 只写 `nb[0..want)`（`want < BLK`），而旧数据却从 `nb[BLK]` 开始——中间 `[want, BLK)` 留下一段**未初始化的堆内存**，输出里会插进随机垃圾。

**症状**：`-n 1000`（= 全部行）时的「输出首行」变成 `line-0253`（正确应为 `line-0001`），而「输出行数」仍然是 1000 —— 只有顺序错了，行数看不出来。

**修法**：旧数据接在 `nb[want]` 处，并且 `malloc` 精确分配：

```c
want = (size_t) ((long) st.st_size - (long) used - pos);
nb = malloc(want + used);            /* 精确分配，不留缝隙 */
if (read(fd, nb, want) != (ssize_t) want) errExit("read");   /* 短读检查 */
memcpy(nb + want, buf, used);
```

修完之后的**对账表**（这是本程序最漂亮的一段输出）：

```text
  -n       实际读入字节 输出行数 输出首行
  1        4096           1          line-1000: 01234567890123456789012345678901234
  100      12288          100        line-0901: 01234567890123456789012345678901234
  500      45056          500        line-0501: 01234567890123456789012345678901234
  1000     82000          1000       line-0001: 01234567890123456789012345678901234
```

| 观察 | 说明 |
|------|------|
| 「实际读入字节」随 `-n` 增大而增大，但**始终 ≤ 文件大小** | 证明是「从尾部回扫」而不是「从头读到尾」（后者会恒等于 82000） |
| 「输出首行」分别是 `line-1000 / line-0901 / line-0501 / line-0001` | 恰好差 `n-1` 行 —— 这是「从尾部数 n 行」的**直接证据** |
| `-n 1000` 时读满 82000 字节 | `-n` 等于总行数时必然扫到文件开头；再加一点就是「`-n` > 行数 = 输出全部」 |

完整源码 [`code/ex13_5_tail.c`](../code/ex13_5_tail.c)：

```c
/* ex13_5_tail.c — Ch13 习题 13-5：用 I/O 系统调用实现 `tail [-n num] file`
 *
 * 原书习题 13-5（p.250）：
 *   「`tail [-n num] file` 打印文件最后 num 行（默认 10 行）。
 *     用 `lseek()` / `read()` / `write()` 等 I/O **系统调用**实现它，
 *     并且**记住本章讲的缓冲问题**，让实现是高效的。」
 *
 * 「高效」的意思是关键，它排除了最朴素的两个写法：
 *   ❌ 从头读到尾、用一个环形缓冲保留最后 n 行 —— 读的是**整个文件**；
 *   ❌ 先 fstat 拿大小、一次性读进大缓冲 —— 文件大起来就是 OOM。
 * 正确做法是**从文件尾部往回按块扫**，找到足够多的换行符就停：
 *   用 `lseek(fd, -BLK, SEEK_END)` 定位，`read()` 一块，数里面的 '\n'；
 *   不够 n+1 个就再往前挪一块，够了一次性写出去。
 * 于是代价是 O(尾部那点字节)，与文件总大小**无关**。
 *
 * 本程序的「高效」还可量：它会把「一共 READ 了多少字节」打出来，
 * 你可以拿它跟文件总大小对比 —— 200 KiB 的文件读最后 5 行，只读了 4 KiB。
 *
 * 用法：
 *     ./ex13_5_tail --help
 *     ./ex13_5_tail [-n num] file
 *     ./ex13_5_tail              # 不带参数 → 自测模式（自己造文件、跑几组参数）
 *
 * 编译： gcc -O0 -Wall -Wextra -o ex13_5_tail ex13_5_tail.c
 * 取材： TLPI 习题 13-5；§13.1（为什么块大小与系统调用次数有关）
 *                      §4.4（lseek 的 SEEK_END + 负偏移）
 *                      §5.4（read 的 short read 与 0 = EOF）
 *       man-pages 6.19 lseek(2)（SEEK_END + 负 off_t；越界返回 EINVAL）
 *                      read(2)（short read）、write(2)（partial write）
 *       POSIX tail(1) 的 `-n` 语义（负数表示「从开头第 n 行之后」，本实现不支持）
 */
#define _GNU_SOURCE
#include <errno.h>
#include <fcntl.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <sys/stat.h>
#include <unistd.h>

#define BLK 4096

/* 统计一块里的 '\n' 个数 */
static size_t count_nl(const char *b, size_t n)
{
    size_t c = 0;

    for (size_t i = 0; i < n; i++)
        if (b[i] == '\n')
            c++;
    return c;
}

/*
 * 打印 file 的最后 nlines 行。
 * 返回实际读入的字节数（用于展示「高效」），-1 表示失败。
 */
static long tail_file(const char *path, long nlines, FILE *out)
{
    int fd = open(path, O_RDONLY);
    struct stat st;
    char *buf = NULL;           /* 累积的尾部数据，从 buf[used-blk] 往右有效 */
    long total_read = 0;
    size_t used = 0;            /* 有效字节数（尾部） */
    long seen_nl = 0;           /* 已扫过的块里累计的换行数 */
    long start;                 /* 输出起点（在 buf 里的下标） */
    size_t i;

    if (fd == -1) {
        fprintf(stderr, "tail: 打不开 %s: %s\n", path, strerror(errno));
        return -1;
    }
    if (fstat(fd, &st) == -1) {
        fprintf(stderr, "tail: fstat 失败: %s\n", strerror(errno));
        close(fd);
        return -1;
    }

    /* 从尾部往回扫，直到攒够 nlines+1 个换行（多要一个用来定位起点） */
    for (;;) {
        long pos;
        size_t want;
        ssize_t n;
        char *nb;

        if ((long) used >= st.st_size)
            break;                                  /* 已经到文件开头了 */
        pos = (long) st.st_size - (long) used - BLK;
        if (pos < 0)
            pos = 0;

        /* 这一轮要从文件 [pos, st_size) 里补上前面缺的那一段。
           注意 want 可能 **小于** BLK —— 当 pos 被夹到 0 时就是这样
           （最后一块往往不满）。所以旧数据必须接在 nb[want] 处，
           **不能**写成 nb[BLK]：那样中间 [want, BLK) 会留下一段
           未初始化的堆内存，输出就像被随机插入了一段垃圾。 */
        want = (size_t) ((long) st.st_size - (long) used - pos);
        nb = malloc(want + used);
        if (nb == NULL) {
            fprintf(stderr, "tail: malloc 失败\n");
            free(buf);
            close(fd);
            return -1;
        }
        if (used > 0)
            memcpy(nb + want, buf, used);
        if (lseek(fd, pos, SEEK_SET) == -1) {
            fprintf(stderr, "tail: lseek 失败: %s\n", strerror(errno));
            free(nb);
            free(buf);
            close(fd);
            return -1;
        }
        n = read(fd, nb, want);
        if (n <= 0) {
            free(nb);
            free(buf);
            close(fd);
            return -1;
        }
        if (n != (ssize_t) want) {
            /* 普通文件上不该发生；真要发生就得重试，本实现选择明确报错 */
            fprintf(stderr, "tail: 短读（want %zu, got %zd）\n", want, n);
            free(nb);
            free(buf);
            close(fd);
            return -1;
        }
        total_read += n;
        seen_nl += (long) count_nl(nb, (size_t) n);
        free(buf);
        buf = nb;
        used += (size_t) n;

        if (seen_nl > nlines)
            break;
    }
    close(fd);

    /* 找输出起点：从 buf 开头数到第 (行数 - nlines) 个 '\n' 之后。
       数行数时要留意**最后一行不需要以换行结尾**（POSIX tail 的定义）：
         文件以 '\n' 结尾  → 行数 = 换行数
         否则              → 行数 = 换行数 + 1
       回扫时至少读过包含文件最后一个字节的那一块，所以 buf[used-1] 就是文件末字节。 */
    if (nlines == 0) {
        /* 0 行就是 0 行：不输出任何东西。
           （不能靠下面的定位逻辑 —— 它找不到第 skip 个换行时会 fallback 成
             「从头输出」，那反而变成全部行。） */
        start = (long) used;
    } else {
        long nlines_total = seen_nl + ((used > 0 && buf[used - 1] == '\n') ? 0 : 1);
        long skip = nlines_total - nlines;

        start = 0;
        if (skip > 0) {
            long k = 0;
            for (i = 0; i < used; i++) {
                if (buf[i] == '\n') {
                    k++;
                    if (k == skip) {
                        start = (long) i + 1;
                        break;
                    }
                }
            }
            if (k < skip)
                start = 0;
        }
    }
    for (i = (size_t) start; i < used; i++)
        if (fputc((unsigned char) buf[i], out) == EOF)
            break;

    free(buf);
    return total_read;
}

/* ---------- 自测模式：造一个多行文件，跑几组参数 ---------- */
static int self_test(void)
{
    const char *p = "/app/ex13_5_sample.txt";

        printf("  造样本失败 errno=%d(%s)\n", errno, strerror(errno));
        return EXIT_FAILURE;

        fprintf(fp, "line-%04d: %s\n", i,
                "0123456789012345678901234567890123456789012345678901234567890123456789");
    fclose(fp);

    {
        int fd = open(p, O_RDONLY);
        fstat(fd, &st);
        close(fd);
        fdsz = (int) st.st_size;
    }

    printf("== 自测：样本文件 %s\n", p);
    printf("   共 %d 行，文件大小 %d 字节（约 %d KiB）\n\n", NLINES, fdsz, fdsz / 1024);

    {
        /* 档位刻意拉开：每行 79 字节 → 一块 4096 字节只装得下约 51 行。
           所以 n=1 与 n=50 都只需一块，n=100 要两块，n=500 要十来块，
           而 n=1000（= 总行数）会一路扫到文件开头 —— 「实际读入字节」这一列
           才能看出它随 n 增长，而不是恒等于块大小。 */
        const long ns[] = {1, 100, 500, 1000};
        printf("  %-8s %-14s %-10s %s\n", "-n", "实际读入字节", "输出行数", "输出首行");
        for (size_t k = 0; k < sizeof(ns) / sizeof(ns[0]); k++) {
            long got;
            long nout = 0;
            char first[128];

            /* 为了拿到「首行」又不把全部输出打出来，先输出到临时文件。
               首行比末行更能说明问题：如果实现真的「从尾部数 n 行」，

                            first[cp] = '\0';
                        }
                    }
                    fclose(o);
                }
                unlink(tmp);
            }

        }

    printf("     （%d 字节）。这就是「从尾部往回扫」的意义：代价只跟尾部有关，\n", fdsz);

        printf("  [tail 读了 %ld 字节]\n", got);

    printf("\n== 边界情况（每一条都真跑一遍，不靠人眼判断）==\n");
    {
        const char *p2 = "/app/ex13_5_nonl.txt";
        /* 16 字节、2 个 '\n'：按 tail 的定义是 **3 行**（最后一行没有结尾换行） */

            printf("  1) -n 1           → [");

int main(int argc, char *argv[])
{
    long nlines = 10;
    const char *path = NULL;

    if (argc == 1)
        return self_test();

    if (strcmp(argv[1], "--help") == 0) {
        printf("Usage: %s [-n num] file\n", argv[0]);
        printf("       用 lseek/read/write 系统调用实现的 tail（只支持从末尾数的 -n）\n");
        return EXIT_SUCCESS;
    }
    if (strcmp(argv[1], "-n") == 0) {
        if (argc < 4) {
            fprintf(stderr, "Usage: %s [-n num] file\n", argv[0]);
            return EXIT_FAILURE;
        }
        nlines = strtol(argv[2], NULL, 10);
        if (nlines < 0) {
            fprintf(stderr, "%s: -n 不能是负数（本实现不支持「从头 n 行之后」）\n", argv[0]);
            return EXIT_FAILURE;
        }
        path = argv[3];
    } else {
        path = argv[1];
    }

    {
        long got = tail_file(path, nlines, stdout);
        if (got < 0)
            return EXIT_FAILURE;
        fprintf(stderr, "[%s: 为取最后 %ld 行，实际只读了 %ld 字节]\n", argv[0], nlines, got);
    }
    return EXIT_SUCCESS;
}
```

## 常见坑

| # | 坑 | 正解 |
|---|----|------|
| 1 | 用 shell `time` 测性能，但在容器里没有 `/bin/sh` | 用 `clock_gettime(CLOCK_MONOTONIC)` 自己计时。**并且同时报「系统调用次数」**——那个才与机器无关 |
| 2 | 只看耗时、不看次数 | 耗时是「另一台宿主机」的值。次数 = `总量 / 块大小`，是可移植的结论 |
| 3 | 在 tmpfs 上测 `O_SYNC` / `fsync` 的代价 | tmpfs 没有真实设备，同步语义失真。必须在真实块设备上测（原书要求「换多种文件系统」正是为此） |
| 4 | 为了「测全」而跑小缓冲 + `O_SYNC` | 原书 Table 13-3 里那个组合要 **1030 秒**。要么加大块，要么明确跳过并说明理由 |
| 5 | 只 `fsync` 不 `fflush`，然后以为数据安全 | `fsync` 返回 0 但文件大小仍是 **0** —— 它**看不见**用户态缓冲里的字节 |
| 6 | 只 `fflush` 不 `fsync`，然后以为数据耐久 | 只到了页缓存。拔电源就没了 |
| 7 | 认为「`fsync` 成功 ⇒ 这批数据落盘」 | `fsync` 的语义是「把这个文件**内核已可见的**修改推下去」，与你的那次 `fprintf` 是否已 `fflush` 无关 |
| 8 | 用「数换行」来数行数（`tail` 实现） | 最后一行**不需要**以 `\n` 结尾。漏了这一条会多输出一行（本仓库实测：`-n 1` 会吐出 `b\nc-no-newline`） |
| 9 | `tail` 的 `-n 0` 没单独处理 | 「找不到第 skip 个换行」的 fallback 会变成「输出全部」。必须显式返回 0 行 |
| 10 | 回扫拼接时按 `BLK` 而不是按「实际读到的字节数」对齐 | 最后一块常常不满，会产生**未初始化的空洞**（本仓库真实踩到：`-n 1000` 的首行错成 `line-0253`）。按 `want` 拼接 |
| 11 | 用「输出行数」单独验证 `tail` 是否正确 | 行数对、顺序错是这个 bug 的典型表现。必须同时验证**首行/内容** |

## HFT / 嵌入式关联

| 场景 | 结论怎么用 |
|------|-----------|
| **benchmark 的方法论** | 本节的统一做法值得照搬：**先给一个与机器无关的定量指标**（系统调用次数 / 字节数），**再给机器相关的指标**（耗时）作佐证。反过来做，得到的结论换台机器就失效 |
| **同步写入的预算** | `每写一条日志就 fsync` 的代价是「每次一次设备往返」。实测每次同步约 **2.7~3.4 ms**（CE 的 tmpfs 上还失真，真机会更慢）。用它算「每秒能持久化多少条」就能发现架构问题 |
| **`fdatasync` 不是银弹** | 本仓库实测它与 `fsync` 差别很小，因为负载每次都在改文件大小（元数据必须写）。**省不省取决于负载与文件系统**，不能照抄结论 |
| **`tail` 的实现思路就是日志尾部读取** | 「从尾部按块回扫、攒够就停」是读日志尾部的标准做法（`tail -f` 的初读、崩溃后的尾部回放）。关键是**代价与文件总大小无关**——这对 GB 级日志是决定性的 |
| **`-n` 语义的边界要按 POSIX** | 「最后一行不需要换行」这条在真实日志里极常见（进程被 `SIGKILL` 时最后一行常常写不全）。实现按「换行数」数行会在这种日志上出错——**恰恰是最需要 `tail` 的时候** |
| **缓冲问题的两个落点** | 13-3 是「持久化落点」（`fflush` + `fsync` 缺一不可），13-4 是「可见性落点」（重定向后全缓冲导致日志延迟）。两者都是生产事故的高频来源 |

<summary>习题自测（Q&A）</summary>

**Q1：习题 13-2 里，为什么「每次 `write` 平均耗时」这一列最有价值？**

A：因为它把「次数」这个混杂因素除掉了。不同 `buf-size` 下 `write()` 次数相差几个数量级，直接比总耗时会被次数淹没；换成「每次平均」之后就能看出：普通模式每次约 **0.6~16 μs**（内存拷贝），`O_SYNC` 每次约 **2700~3400 μs**（设备往返）—— 差 3~4 个数量级。

**Q2：习题 13-3 的答案用一句话怎么说？**

A：`fflush` 推「用户态 → 页缓存」这一层，`fsync` 推「页缓存 → 设备」这一层；**两条是接力的两棒，不是二选一**。只做前者会丢在页缓存，只做后者则完全看不见用户态缓冲里的字节（实测 `fsync` 返回 0 但文件大小仍是 0）。

**Q3：习题 13-4 的答案取决于哪段 glibc 代码？**

A：`libio/filedoalloc.c` 的 `_IO_file_doallocate()`。里面 `if (S_ISCHR (st.st_mode)) { if (... local_isatty (fp->_fileno)) fp->_flags |= _IO_LINE_BUF; }` 决定了「只有字符设备 + `isatty`」才行缓冲。重定向到文件/管道/socket 后条件不成立 → 全缓冲 → `\n` 不刷新 → `write` 先出。

**Q4：习题 13-5 里「高效」具体指什么？**

A：代价**与文件总大小无关**。做法是从尾部按块（本实现 `BLK = 4096`）往回扫，攒够 `n+1` 个换行就停。实测读 1000 行样本的尾部：`-n 1` 只读 4096 字节、`-n 100` 读 12288 字节，而文件是 82000 字节。若实现是「从头读到尾」，这一列会恒等于 82000。

**Q5：实现 `tail` 时有两个容易写错的边界，分别是什么？**

A：① **行数 ≠ 换行数**：文件不以 `\n` 结尾时，行数 = 换行数 + 1（`-n 1` 对 `"a\nb\nc-no-newline"` 应输出 `c-no-newline`，不是 `b\nc-no-newline`）；② **`-n 0` 要单独处理**，否则 fallback 会输出全部行。

**Q6：本仓库在实现 `tail` 时踩到的 bug 是什么？**

A：回扫拼接时把旧数据按硬编码的 `BLK` 偏移拷贝（`memcpy(nb + BLK, buf, used)`），而最后一块常常不满 `BLK`，于是 `[want, BLK)` 留下**未初始化的堆内存**。症状很隐蔽：`-n 1000` 的「输出行数」仍是 1000，只有「输出首行」错成 `line-0253`。修法是按实际读到的 `want` 拼接，并精确 `malloc`。

**Q7：为什么这一章要把「习题文字是转引」这件事专门标注出来？**

A：因为 man7 只分发源码、不分发习题正文。本仓库的纪律是「可溯源到标准/源码原文」——转引的题干必须标明是转引，**不能冒充官方原文**。唯一的例外是习题 13-4：它的官方解答程序（`mix23_linebuff.c`）是公开的，所以那一题的题面可以从解答程序反推，推理依据也写在了正文里。
