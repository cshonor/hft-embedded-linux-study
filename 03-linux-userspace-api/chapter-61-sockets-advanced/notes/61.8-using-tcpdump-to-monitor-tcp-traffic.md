# 61.8 Using tcpdump to Monitor TCP Traffic

> 本章：[TLPI 第 61 章](./README.md)

## 本节讲什么

`tcpdump` 是网络抓包和协议分析的必备工具。本节介绍如何使用 tcpdump 监控 TCP 流量、过滤特定连接、分析三次握手和数据传输。

## 要点

### tcpdump 基本用法

```bash
# 监听特定接口
tcpdump -i eth0

# 不解析主机名/端口名，加速输出
tcpdump -n -i eth0

# 详细输出（-v/-vv/-vvv）
tcpdump -vvv -i eth0

# 抓取 ASCII 内容
tcpdump -A -i eth0

# 写入文件供后续分析
tcpdump -w capture.pcap -i eth0
tcpdump -r capture.pcap
```

### 常用过滤器

| 过滤器 | 说明 |
|--------|------|
| `tcp` | 仅 TCP 包 |
| `udp` | 仅 UDP 包 |
| `port 8080` | 端口 8080 |
| `host 192.168.1.1` | 特定主机 |
| `src host 10.0.0.1` | 源 IP |
| `dst port 443` | 目的端口 |
| `tcp[tcpflags] & tcp-syn != 0` | SYN 包 |
| `tcp[tcpflags] & tcp-ack != 0` | ACK 包 |
| `not port 22` | 排除 SSH |

### TCP 三次握手抓取

```bash
# 抓取 SYN/SYN-ACK/ACK
tcpdump -n -i eth0 'tcp[tcpflags] & tcp-syn != 0 or tcp[tcpflags] & tcp-ack != 0 and port 8080'
```

```
1. SYN     client > server  seq=0
2. SYN-ACK server > client seq=0 ack=1
3. ACK     client > server seq=1 ack=1
```

### TCP 数据传输分析

```bash
# 抓取完整 TCP 流
tcpdump -n -S -i eth0 'port 8080'

# -S: 绝对序列号（默认相对）
# 输出: client > server: seq 1:1001 ack 1 win 65535
```

### 常见 TCP 标志

| 标志 | 含义 |
|------|------|
| `S` | SYN |
| `.` | ACK |
| `F` | FIN |
| `R` | RST |
| `P` | PSH |
| `U` | URG |

## HFT / 嵌入式关联

- HFT 交易链路调试：抓取 TCP 延迟和重传
- 策略服务器通信分析：验证协议正确性
- 嵌入式设备网络问题排查

## 代码示例

```bash
#!/bin/bash
# HFT 交易链路抓包

# 1. 抓取交易服务器所有流量
tcpdump -n -i eth0 -w hft_$(date +%s).pcap 'host 10.0.0.100 and port 9999'

# 2. 实时分析
tcpdump -n -tttt -i eth0 'host 10.0.0.100 and port 9999'
# -tttt: 时间戳精确到微秒

# 3. 只看 TCP 异常
tcpdump -n -i eth0 'host 10.0.0.100 and (tcp[tcpflags] & tcp-rst != 0 or tcp[tcpflags] & tcp-fin != 0)'

# 4. 统计重传
tcpdump -n -r capture.pcap | grep -c 'tcp retransmission'
```

## 代码自测

<details>
<summary>tcpdump -S 选项的作用是什么？为什么 HFT 场景需要使用？</summary>

`-S` 打印绝对 TCP 序列号，而非默认的相对序列号（从 0 开始）。相对序列号便于人眼阅读，但无法检测序列号回绕（PAWS）和精确计算数据量。HFT 场景需要精确分析协议交互、检测重传和乱序，绝对序列号必不可少。

</details>
