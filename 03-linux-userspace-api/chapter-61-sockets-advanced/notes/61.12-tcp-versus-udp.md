# 61.12 TCP versus UDP

> 本章：[TLPI 第 61 章](../README.md)

## 本节讲什么

TCP 和 UDP 的本质区别、适用场景选择，以及在高级应用中如何根据需求选择传输协议。

## 要点

### TCP vs UDP 对比

| 特性 | TCP | UDP |
|------|-----|-----|
| 连接 | 面向连接 | 无连接 |
| 可靠性 | 保证交付 | 不保证 |
| 顺序 | 有序到达 | 可能乱序 |
| 流控 | 有（滑动窗口） | 无 |
| 拥塞控制 | 有 | 无 |
| 延迟 | 较高（握手+ACK） | 低（直接发送） |
| 开销 | 大（头部20+字节） | 小（头部8字节） |
| 多播 | 不支持 | 支持 |
| 分片 | 无（MSS 协商） | 有（IP 层分片） |
| 适用 | 命令/交易/文件 | 行情/视频/DNS |

### TCP 适用场景

- 需要可靠交付的数据传输
- 请求-响应模式
- 文件传输
- 交易指令（HFT 订单）

### UDP 适用场景

- 实时行情广播（允许丢包，不能等待）
- 多媒体流
- DNS 查询
- 组播/广播通信
- 高频小消息（减少 TCP 握手开销）

### HFT 中的协议选择

| 场景 | 协议 | 原因 |
|------|------|------|
| 交易所订单 | TCP | 订单必须可靠到达 |
| 市场行情 | UDP 多播 | 多个订阅者，允许丢包 |
| 策略间通信 | TCP | 本机可靠通信 |
| 风控消息 | TCP | 必须可靠 |
| 日志传输 | UDP | 允许丢失，低延迟 |

### UDP 可靠性补充

在 UDP 上自行实现可靠性：

| 特性 | 实现方式 |
|------|---------|
| 序列号 | 检测丢包和乱序 |
| ACK/NACK | 确认收到 |
| 超时重传 | 保障交付 |
| 拥塞控制 | 避免网络过载 |

常见框架：Aeron (低延迟 UDP 多播), OpenMDD (行情分发)

### TCP 延迟优化

| 优化 | 效果 |
|------|------|
| `TCP_NODELAY` | 禁用 Nagle，减少小包延迟 |
| `TCP_QUICKACK` | 禁用延迟 ACK |
| `TCP_FASTOPEN` | 省去一个 RTT（TFO） |
| 增大缓冲区 | 减少因窗口满等待 |
| 持久连接 | 避免重新握手 |

## HFT / 嵌入式关联

- 订单通道：TCP + `TCP_NODELAY` + 持久连接
- 行情通道：UDP 多播，容忍丢包但不能等
- 嵌入式传感器：UDP 广播低延迟数据
- 风控系统：TCP 保障指令可靠传输

## 代码示例

```c
/* HFT 多通道设计 */

/* 1. 订单通道：TCP */
int order_fd = socket(AF_INET, SOCK_STREAM, 0);
int opt = 1;
setsockopt(order_fd, IPPROTO_TCP, TCP_NODELAY, &opt, sizeof(opt));
connect(order_fd, (struct sockaddr*)&order_addr, sizeof(order_addr));

/* 2. 行情通道：UDP 多播 */
int mcast_fd = socket(AF_INET, SOCK_DGRAM, 0);
struct ip_mreqn mreq;
mreq.imr_multiaddr = mcast_addr;
mreq.imr_ifindex = ifindex;
setsockopt(mcast_fd, IPPROTO_IP, IP_ADD_MEMBERSHIP, &mreq, sizeof(mreq));

/* 3. 多路复用 */
struct epoll_event ev;
int epfd = epoll_create1(0);
ev.events = EPOLLIN;
ev.data.fd = order_fd;  epoll_ctl(epfd, EPOLL_CTL_ADD, order_fd, &ev);
ev.data.fd = mcast_fd;  epoll_ctl(epfd, EPOLL_CTL_ADD, mcast_fd, &ev);

/* 订单可靠，行情低延迟，各取所长 */
```

## 代码自测

<details>
<summary>为什么 HFT 市场行情通常使用 UDP 多播而不是 TCP？</summary>

1. **低延迟**：UDP 无握手、无 ACK、无拥塞控制，数据直接发送
2. **一对多**：多播一次发送多个订阅者接收，无需 N 次复制
3. **容忍丢包**：行情数据实时性强，丢一帧可等下一帧，不能等重传
4. **无队头阻塞**：一个包丢失不阻塞后续包（TCP 会等重传）
5. **带宽效率**：多播共享一条流，而非 N 条 TCP 连接

</details>
