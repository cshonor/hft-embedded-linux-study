# 61.11 Inheritance of Flags and Options across accept() and Other Operations

> 本章：[TLPI 第 61 章](../README.md)

## 本节讲什么

`accept()` 返回的新套接字继承了监听套接字的哪些属性：选项、标志、信号处理等。了解哪些继承哪些不继承，避免意外行为。

## 要点

### accept() 继承规则

| 属性 | 是否继承 | 说明 |
|------|---------|------|
| `SO_REUSEADDR` | 是 | 选项继承 |
| `SO_KEEPALIVE` | 是 | 选项继承 |
| `SO_RCVBUF`/`SO_SNDBUF` | 否 | 使用系统默认值 |
| `SO_OOBINLINE` | 是 | 选项继承 |
| `TCP_NODELAY` | 否 | 新连接默认 Nagle on |
| `TCP_CORK` | 否 | 新连接默认 Cork off |
| `SO_LINGER` | 否 | 使用系统默认 |
| FD flags (O_NONBLOCK) | 否 | accept 返回阻塞 fd |
| `SO_DOMAIN`/`SO_TYPE` | 是 | 协议和类型相同 |
| signal disposition | N/A | 进程级，非 fd |

### 设置继承选项的正确时机

```c
/* 错误：在 accept 后设置每个新连接 */
int connfd = accept(lfd, NULL, NULL);
setsockopt(connfd, IPPROTO_TCP, TCP_NODELAY, &opt, sizeof(opt));
/* 高并发下每个连接都设置，开销大 */

/* 正确：在 listen 前设置监听 fd，继承到 accept */
setsockopt(lfd, IPPROTO_TCP, TCP_NODELAY, &opt, sizeof(opt));
int connfd = accept(lfd, NULL, NULL);  /* 继承 TCP_NODELAY */
```

### 不继承的选项需单独设置

```c
/* 缓冲区大小不继承，需在每个新连接设置 */
int connfd = accept(lfd, NULL, NULL);
int bufsz = 4 * 1024 * 1024;
setsockopt(connfd, SOL_SOCKET, SO_RCVBUF, &bufsz, sizeof(bufsz));
setsockopt(connfd, SOL_SOCKET, SO_SNDBUF, &bufsz, sizeof(bufsz));
```

### 非阻塞模式继承

```c
/* 方法1：accept 前设置监听 fd 非阻塞 */
int flags = fcntl(lfd, F_GETFL);
fcntl(lfd, F_SETFL, flags | O_NONBLOCK);
/* accept4 返回的 fd 也是非阻塞（Linux 扩展） */

/* 方法2：使用 accept4 直接设置 */
int connfd = accept4(lfd, NULL, NULL, SOCK_NONBLOCK | SOCK_CLOEXEC);
```

### accept4 flags (Linux 2.6.28+)

| flag | 说明 |
|------|------|
| `SOCK_NONBLOCK` | 新 fd 非阻塞 |
| `SOCK_CLOEXEC` | 新 fd close-on-exec |

## HFT / 嵌入式关联

- HFT 服务器在 listen 前统一设置选项，减少每连接开销
- 使用 `accept4(SOCK_NONBLOCK | SOCK_CLOEXEC)` 原子设置
- 确保所有交易连接的 `TCP_NODELAY` 统一

## 代码示例

```c
#include <sys/socket.h>
#include <netinet/tcp.h>
#include <fcntl.h>

void setup_listen_socket(int lfd) {
    int opt = 1;

    /* 在 listen 前设置可继承选项 */
    setsockopt(lfd, SOL_SOCKET, SO_REUSEADDR, &opt, sizeof(opt));
    setsockopt(lfd, IPPROTO_TCP, TCP_NODELAY, &opt, sizeof(opt));

    /* 注意：SO_RCVBUF/SO_SNDBUF 不继承到 accept */
    /* 需在每个新连接单独设置 */

    /* 监听 fd 设为非阻塞（accept4 也继承非阻塞） */
    int flags = fcntl(lfd, F_GETFL);
    fcntl(lfd, F_SETFL, flags | O_NONBLOCK);
}

int accept_conn(int lfd) {
    /* accept4 原子设置 NONBLOCK + CLOEXEC */
    int connfd = accept4(lfd, NULL, NULL,
                         SOCK_NONBLOCK | SOCK_CLOEXEC);

    /* 设置不继承的选项 */
    int bufsz = 4 * 1024 * 1024;
    setsockopt(connfd, SOL_SOCKET, SO_RCVBUF, &bufsz, sizeof(bufsz));
    setsockopt(connfd, SOL_SOCKET, SO_SNDBUF, &bufsz, sizeof(bufsz));

    /* 快速 ACK（不继承） */
    int opt = 1;
    setsockopt(connfd, IPPROTO_TCP, TCP_QUICKACK, &opt, sizeof(opt));

    return connfd;
}
```

## 代码自测

<details>
<summary>为什么建议使用 accept4 而不是 accept + fcntl？</summary>

`accept4(lfd, NULL, NULL, SOCK_NONBLOCK | SOCK_CLOEXEC)` 在一次系统调用中同时完成 accept 和设置标志，避免了 accept + fcntl 的两步操作。两步操作之间存在竞争窗口：在 accept 返回和 fcntl 设置之间，fd 已经存在但未设置 CLOEXEC，如果此时其他线程执行 `exec()`，fd 会泄漏到新进程。`accept4` 是原子的，消除竞争窗口，性能也更好（一次系统调用）。

</details>
