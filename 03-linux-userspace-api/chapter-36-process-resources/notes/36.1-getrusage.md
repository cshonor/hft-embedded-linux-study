## 要点

```c
int getrusage(int who, struct rusage *usage);
```

| who | 含义 |
|-----|------|
| `RUSAGE_SELF` | 本进程 |
| `RUSAGE_CHILDREN` | **已 wait 回收**的子进程汇总（未 wait 不计） |
| `RUSAGE_THREAD` | 当前线程（Linux） |

常用字段：`ru_utime` / `ru_stime` · `ru_maxrss`（峰值 KB，**非累加**）· `ru_minflt`/`ru_majflt` · `ru_nvcsw`/`ru_nivcsw`。

Demo：[`code/rusage_demo.c`](./code/rusage_demo.c)

## 与 C 语言学习的关系

`fork()`/`exec()`/`wait()` 是 Unix 进程模型的核心，也是 C 语言系统编程的基础。C 语言没有内置的并发原语——`fork` 是 Unix 创建进程的方式。理解 `fork` 的返回值（父返回子 PID，子返回 0）需要扎实的 C 语言指针和返回值概念。对照 K&R 8.3 节学习进程创建与文件描述符的关系。

## 常见陷阱

1. **fork 返回值未区分**

```c
pid_t pid = fork();
/* 父子都执行同一代码 → 必须区分 */
```

fork 返回三次：父进程返回子 PID，子进程返回 0，失败返回 -1。必须区分三个分支。

2. **fork 前缓冲区未 flush**

```c
printf("hello");  /* 在缓冲区 */
fork();  /* 子进程也会输出 hello */
```

fork 前如果 stdio 缓冲区有数据，子进程会复制并重复输出。fork 前应 fflush 或用 write。

3. **子进程未回收 → 僵尸**

```c
fork();
/* 父进程不 wait → 子进程变僵尸 */
```

子进程退出后如果父进程不 wait，子进程变成僵尸（Z 状态），占用 PID 和少量内存。

## 自测题

**题目 1（选择）：** `fork()` 在子进程中返回什么？
A. 子进程 PID
B. 0
C. -1
D. 父进程 PID

<details>
<summary>参考答案</summary>

B。子进程中 fork 返回 0，父进程中返回子进程 PID，失败返回 -1。

</details>

**题目 2（判断）：** `fork` 后子进程和父进程的执行顺序是确定的。

<details>
<summary>参考答案</summary>

错误。fork 后父子进程的执行顺序不确定，取决于调度器。不能用 sleep 来保证顺序。

</details>

**题目 3（踩坑）：** 以下代码有什么问题？
```c
printf("before fork
");
fork();
printf("after fork
");
```

<details>
<summary>参考答案</summary>

如果 stdout 是全缓冲（管道/文件），缓冲区被复制，子进程也会输出 "before fork"。fork 前应 fflush(stdout)。

</details>

**题目 4（应用）：** 写代码：fork 一个子进程，父进程打印子 PID，子进程打印自己的 PID。

<details>
<summary>参考答案</summary>

```c
pid_t pid = fork();
if (pid < 0) { perror("fork"); exit(1); }
if (pid == 0) {
    printf("child: %d
", getpid());
} else {
    printf("parent: child=%d
", pid);
}
```

</details>
