# 36.3 Details of Specific Resource Limits

> 本章：[TLPI 第 36 章 — Process Resources](../README.md)

## 本节讲什么

详细介绍每个 `RLIMIT_*` 资源限制的含义、默认值和实际影响。

## 要点

### 资源限制一览

| 限制 | 含义 | 典型默认 | HFT 关注 |
|------|------|---------|---------|
| `RLIMIT_AS` | 虚拟内存上限 | 无限 | 防止 OOM |
| `RLIMIT_CORE` | core 文件大小 | 0 | 调试时设大 |
| `RLIMIT_CPU` | CPU 时间（秒） | 无限 | 防 CPU 飙升 |
| `RLIMIT_DATA` | 数据段大小 | 无限 | — |
| `RLIMIT_FSIZE` | 文件大小 | 无限 | 日志大小 |
| `RLIMIT_NOFILE` | 最大 fd 数 | 1024 | HFT 需调高 |
| `RLIMIT_NPROC` | 最大进程/线程数 | 无限 | 线程池控制 |
| `RLIMIT_RSS` | 驻留内存 | 无限 | — |
| `RLIMIT_STACK` | 栈大小 | 8MB | 线程栈 |
| `RLIMIT_MEMLOCK` | mlock 锁定上限 | 64KB | HFT 需调大 |
| `RLIMIT_RTPRIO` | 实时优先级上限 | 0 | HFT 需要 |
| `RLIMIT_RTTIME` | 实时 CPU 时间 | 无限 | 防死循环 |
| `RLIMIT_SIGPENDING` | 挂起信号数 | 无限 | — |

### 重要限制详解

**RLIMIT_NOFILE（最大 fd 数）**：
```
默认 1024 → HFT 需要大量 fd（网络连接、文件、epoll）
调整：ulimit -n 1000000 或 setrlimit(RLIMIT_NOFILE, ...)
systemd: LimitNOFILE=1000000
```

**RLIMIT_MEMLOCK（mlock 上限）**：
```
默认 64KB → HFT mlockall 锁定全部内存会失败
调整：ulimit -l unlimited
systemd: LimitMEMLOCK=infinity
```

**RLIMIT_NPROC（进程/线程数）**：
```
限制用户能创建的进程+线程总数
HFT 线程池场景需调高
systemd: LimitNPROC=10000
```

**RLIMIT_CPU（CPU 秒数）**：
```
超过限制 → SIGXCPU 信号
继续超 → SIGKILL
HFT 不设此限制（可能误杀长时间运行的回测）
```

**RLIMIT_CORE（core 文件大小）**：
```
0 = 不生成 core 文件
unlimited = 完整 core
HFT 调试时设为 unlimited
```

**RLIMIT_RTTIME（实时 CPU 时间，微秒）**：
```
SCHED_FIFO/RR 线程连续运行超过限制 → SIGXCPU
设计目的是防止实时线程死循环冻系统
HFT 策略线程需注意：长时间纯计算可能触发
```

### setrlimit / getrlimit API

```c
struct rlimit {
    rlim_t rlim_cur;  /* 软限制（当前值） */
    rlim_t rlim_max;  /* 硬限制（上限） */
};

int getrlimit(int resource, struct rlimit *rlim);
int setrlimit(int resource, const struct rlimit *rlim);
```

| 规则 | 说明 |
|------|------|
| `rlim_cur <= rlim_max` | 软限制不超过硬限制 |
| 非 root 可降低 rlim_max | 但不可升高（不可逆） |
| root 可调高 rlim_max | 需 CAP_SYS_RESOURCE |
| `RLIM_INFINITY` | 无限制 |

### prlimit 系统调用

```c
int prlimit(pid_t pid, int resource,
            const struct rlimit *new_limit,
            struct rlimit *old_limit);
```

优势：可设置其他进程的限制，且原子地获取旧值并设置新值。

## HFT / 嵌入式关联

- **NOFILE 调高**：HFT 可能需要数万 fd（交易所连接 + 行情订阅 + 日志）
- **MEMLOCK 调大**：HFT 用 `mlockall` 锁定所有内存防止换页
- **RTPRIO 调高**：HFT 策略线程需要 SCHED_FIFO 实时优先级
- **RTTIME 注意**：长时间纯计算策略可能触发 SIGXCPU，需设置足够大或改用非实时策略
- **嵌入式**：资源受限系统设置严格 RLIMIT 防止失控

## 代码示例

```c
#include <sys/resource.h>
#include <stdio.h>

void setup_hft_limits(void) {
    struct rlimit rl;

    /* 最大 fd 数 */
    rl.rlim_cur = 1000000;
    rl.rlim_max = 1000000;
    if (setrlimit(RLIMIT_NOFILE, &rl) != 0) perror("NOFILE");

    /* mlock 上限 */
    rl.rlim_cur = RLIM_INFINITY;
    rl.rlim_max = RLIM_INFINITY;
    if (setrlimit(RLIMIT_MEMLOCK, &rl) != 0) perror("MEMLOCK");

    /* core 文件 */
    rl.rlim_cur = RLIM_INFINITY;
    rl.rlim_max = RLIM_INFINITY;
    if (setrlimit(RLIMIT_CORE, &rl) != 0) perror("CORE");

    /* 实时优先级 */
    rl.rlim_cur = 99;
    rl.rlim_max = 99;
    if (setrlimit(RLIMIT_RTPRIO, &rl) != 0) perror("RTPRIO");
}

void show_limits(void) {
    struct rlimit rl;
    const char *names[] = {"CPU", "FSIZE", "DATA", "STACK", "CORE",
                           "RSS", "NPROC", "NOFILE", "MEMLOCK",
                           "AS", "LOCKS", "SIGPENDING", "RTPRIO"};
    int resources[] = {RLIMIT_CPU, RLIMIT_FSIZE, RLIMIT_DATA, RLIMIT_STACK,
                       RLIMIT_CORE, RLIMIT_RSS, RLIMIT_NPROC, RLIMIT_NOFILE,
                       RLIMIT_MEMLOCK, RLIMIT_AS, RLIMIT_LOCKS,
                       RLIMIT_SIGPENDING, RLIMIT_RTPRIO};
    for (int i = 0; i < 13; i++) {
        getrlimit(resources[i], &rl);
        printf("%-12s: soft=%ld hard=%ld\n", names[i],
               (long)rl.rlim_cur, (long)rl.rlim_max);
    }
}
```

## 代码自测

<details>
<summary>1. 软限制和硬限制的区别？</summary>

- **软限制（rlim_cur）**：当前生效的限制值，进程可以自由地在 0~硬限制之间调整
- **硬限制（rlim_max）**：软限制的上限。非特权进程只能降低硬限制（不可逆），不能升高。root 可以升高。
- 系统管理员通过 `/etc/security/limits.conf` 或 systemd 设置硬限制
</details>

<details>
<summary>2. RLIMIT_CPU 超限后会发生什么？</summary>

进程 CPU 累计时间超过软限制时，内核发送 SIGXCPU 信号。如果进程忽略或捕获 SIGXCPU 继续运行，每秒再发一次。超过硬限制时，发送 SIGKILL。SIGXCPU 的默认行为是终止进程并生成 core 文件。
</details>

<details>
<summary>3. 为什么 HFT 需要调高 RLIMIT_MEMLOCK？</summary>

HFT 用 `mlockall(MCL_CURRENT | MCL_FUTURE)` 锁定所有内存页，防止被换出到 swap。如果页被换出，访问时会触发缺页中断从磁盘读回，延迟从纳秒跳到毫秒级。默认 MEMLOCK 限制只有 64KB，mlockall 会失败。需要设为 unlimited 或足够大。
</details>
