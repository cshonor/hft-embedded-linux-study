# 9.8 Summary

> 本章：[TLPI 第 09 章 — Process Credentials](./README.md)

## 本章回顾

### 进程凭证一览

| 凭证 | 用途 | 修改 API | 非 root 限制 |
|------|------|---------|-------------|
| **Real UID/GID** | 标识启动用户 | `setuid()`/`setgid()` | 只能设为 real 或 saved 中的值 |
| **Effective UID/GID** | 权限检查依据 | `seteuid()`/`setegid()` | 只能设为 real 或 saved 中的值 |
| **Saved set-UID/GID** | exec 时保存的 effective | `setresuid()` | 只能设为 real 或 effective |
| **FS UID/GID** | Linux 特有（已废弃） | `setfsuid()`/`setfsgid()` | 始终跟随 effective |
| **Supplementary groups** | 附属组 | `setgroups()` | 需要 CAP_SETGID |

### setuid/seteuid/setresuid 行为对比

| 操作 | root (euid=0) | 非特权进程 |
|------|---------------|-----------|
| `setuid(x)` | 同时设 real=effective=saved=x | 只设 effective=x（等于 seteuid） |
| `seteuid(x)` | 设 effective=x | 设 effective=real 或 saved 之一 |
| `setresuid(r,e,s)` | 同时设 real/eff/saved | 三个中每个必须是 real/eff/saved 之一 |

### 凭证在 fork/exec 时的传递

| 事件 | Real | Effective | Saved |
|------|------|-----------|-------|
| `fork()` | 继承父 | 继承父 | 继承父 |
| `exec()`（无 setuid 位） | 不变 | 不变 = effective | 设为 effective |
| `exec()`（有 setuid 位） | 不变 | 设为文件 owner | 设为 effective |

### set-user-ID 程序工作流程

```
1. 程序文件 setuid 位 + owner=root
2. exec → effective UID = root, saved UID = root
3. 程序以 root 身份执行特权操作
4. 完成后 seteuid(real_uid) → 临时降权
5. 需要时 seteuid(saved_uid=0) → 恢复特权
6. 最终 setuid(real_uid) → 永久降权（不可逆）
```

### 凭证相关 API 汇总

| 函数 | 功能 |
|------|------|
| `getuid()`/`getgid()` | 获取 real UID/GID |
| `geteuid()`/`getegid()` | 获取 effective UID/GID |
| `getresuid()`/`getresgid()` | 获取 real/eff/saved 三者 |
| `setuid()`/`setgid()` | 设置（root 全设，非 root 仅 effective） |
| `seteuid()`/`setegid()` | 仅设置 effective |
| `setresuid()`/`setresgid()` | 精确设置三者 |
| `setreuid()`/`setregid()` | 交换 real/effective（BSD 风格） |
| `setfsuid()`/`setfsgid()` | 设置 FS UID/GID（仅 Linux，已废弃） |
| `getgroups()` | 获取附属组 |
| `setgroups()` | 设置附属组（需特权） |
| `initgroups()` | 从 /etc/group 加载附属组 |

## HFT / 嵌入式关联

- **降权运行**：HFT 服务以 root 启动（绑定 1024 以下端口），绑定后 `setuid` 降为普通用户
- **安全审计**：凭证日志记录 effective UID 变化轨迹，用于合规审计
- **嵌入式**：通常全程 root 运行，凭证管理较少使用
- **容器化**：容器内用户映射（`/etc/subuid`），与宿主用户隔离

## 代码自测

<details>
<summary>1. setuid 程序如何安全地临时降权和恢复特权？</summary>

```c
uid_t real = getuid();     /* 启动用户 */
uid_t saved = geteuid();   /* exec 后 saved = effective = root */

/* 临时降权 */
seteuid(real);             /* effective = real, saved 不变 */

/* 恢复特权 */
seteuid(saved);            /* effective = saved = root */

/* 永久降权 */
setuid(real);              /* real=eff=saved = real, 不可逆 */
```

关键：`saved` 保存了 exec 时的 effective UID，即使临时降权也能恢复。永久降权用 `setuid` 而非 `seteuid`。
</details>

<details>
<summary>2. fork 后子进程的凭证是什么？</summary>

fork 后子进程继承父进程的所有凭证：real UID/GID、effective UID/GID、saved set-UID/GID、附属组列表。父子进程凭证相同。但父子进程是独立的进程，之后各自修改自己的凭证互不影响。
</details>

<details>
<summary>3. 为什么 drop privilege 必须按 setgroups → setgid → setuid 顺序？</summary>

- `setgroups` 需要 root 权限。如果先 `setuid`（降为普通用户），`setgroups` 返回 EPERM
- 结果：主 GID 改了但附属组列表仍包含 root 组，权限未完全放下
- 正确顺序：先 `setgroups(0, NULL)` 清空，再 `setgid`，最后 `setuid`
- `setuid` 从 root→普通用户是不可逆的（无法回到 root）
</details>
