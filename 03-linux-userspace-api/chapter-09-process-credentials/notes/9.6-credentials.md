## 本节讲什么

`setgid` / `setegid` / `setregid` / `setresgid` 与上表对称（UID→GID）。 历史：BSD → SUSv3 → Linux 扩展；能力递增，旧接口保留兼容。 新代码在 Linux 上若需精细控制：优先想清要不要 **`seteuid`（临时）** 还是 **`setresuid`（一次钉死 R/E/S）**。

---

## 要点

> **特权进程 = EUID==0**（不是 RUID==0）。  
> 参数 **`-1`** = 该项不改（`setreuid` / `setresuid` 系）。

### 对比总表

| 调用 | 改什么 | 特权进程 (EUID=0) | 非特权（含 setuid 程序） |
|------|--------|-------------------|--------------------------|
| `setuid(uid)` | 视情况 | **R+E+S 全改为 uid** | 仅能改 **EUID** → `uid` 须为 RUID 或 Saved-UID |
| `seteuid(e)` | 仅 EUID | 任意合法 uid | 仅能设为 **RUID 或 Saved-UID** |
| `setreuid(r,e)` | R 与/或 E | 能力更宽（见 man） | 受 R/Saved 约束；规则细看 `man 2 setreuid` |
| `setresuid(r,e,s)` | R/E/S 各独立 | 任意组合（`-1` 跳过） | 每项只能是当前 R/E/S 之一等（见 man）；**Linux 扩展** |
| `setfsuid` / `setfsgid` | FUID/FGID | 见 man | 几乎不用 |
| `setgroups` | 补充组列表 | 可改 | **失败**（需特权） |

`setgid` / `setegid` / `setregid` / `setresgid` 与上表对称（UID→GID）。

### 为何有这么多接口？

历史：BSD → SUSv3 → Linux 扩展；能力递增，旧接口保留兼容。  
新代码在 Linux 上若需精细控制：优先想清要不要 **`seteuid`（临时）** 还是 **`setresuid`（一次钉死 R/E/S）**。

Demo：[`code/seteuid_drop_restore.c`](./code/seteuid_drop_restore.c)（需自行 `chmod u+s` + 属主 root 才能看全路径）

## 常见陷阱

1. **TOCTOU 竞态**

```c
if (access("f.txt", R_OK) == 0) {
    /* 攻击者在此期间替换文件 */
    fd = open("f.txt", O_RDONLY);
}
```

access() 和 open() 之间文件可能被替换（TOCTOU）。应直接 open 并检查错误，或用 fstat 验证已打开的 fd。

2. **setuid 程序未降权**

```c
/* setuid root 程序 */
fd = open("/etc/shadow", O_RDONLY);
/* ... 处理 ... */
/* 忘记降权就执行用户代码 → 提权! */
```

setuid 程序应在完成特权操作后立即降权（seteuid(getuid())），遵循最小权限原则。

3. **混淆 real UID 和 effective UID**

```c
/* real UID: 启动进程的用户 */
/* effective UID: 当前有效权限 */
/* setuid 程序中两者不同! */
```

real UID 是登录用户，effective UID 决定当前权限。setuid 程序中 effective UID 变为文件属主。

## 自测题

**题目 1（选择）：** setuid 程序执行时，哪个 UID 会改变？
A. real UID
B. effective UID
C. saved set-user-ID
D. 所有 UID

<details>
<summary>参考答案</summary>

B。setuid 程序执行时 effective UID 变为文件属主的 UID。real UID 不变。saved set-user-ID 也被设为 effective UID。

</details>

**题目 2（判断）：** `access()` 和 `open()` 组合使用是安全的权限检查方式。

<details>
<summary>参考答案</summary>

错误。access() 基于 real UID 检查，open() 基于 effective UID。而且两者之间有 TOCTOU 竞态。应直接 open 并检查。

</details>

**题目 3（踩坑）：** 以下 setuid root 程序有什么安全隐患？
```c
int main() {
    system("ls /root");
}
```

<details>
<summary>参考答案</summary>

system() 调用 shell，shell 会解析 PATH 环境变量。攻击者可以修改 PATH 让恶意程序替代 ls。setuid 程序应直接用 execve 指定完整路径。

</details>

**题目 4（应用）：** 写代码：setuid 程序先打开特权文件，然后降权到普通用户。

<details>
<summary>参考答案</summary>

```c
int fd = open("/etc/shadow", O_RDONLY);
if (fd < 0) { perror("open"); exit(1); }
/* 立即降权 */
seteuid(getuid());
/* 现在以普通用户身份运行 */
```

</details>
