# 58.3 The Data-Link Layer

> 本章：[TLPI 第 58 章 — TCP/IP Fundamentals](../README.md)

## 本节讲什么

介绍 TCP/IP 协议栈的数据链路层（Data-Link Layer）：以太网帧格式、MAC 地址、ARP 协议、以及链路层在 TCP/IP 协议栈中的角色。

## 要点

### TCP/IP 协议栈层次

```
应用层     HTTP, DNS, SIP, custom
           ↓
传输层     TCP / UDP
           ↓
网络层     IP (IPv4/IPv6), ICMP
           ↓
数据链路层  Ethernet, Wi-Fi, PPP
           ↓
物理层     光纤, 双绞线, 无线电波
```

### 数据链路层职责

| 职责 | 说明 |
|------|------|
| 帧封装 | 将 IP 数据报封装为以太网帧 |
| MAC 地址 | 48 位硬件地址，标识网卡接口 |
| ARP | 将 IP 地址解析为 MAC 地址 |
| MTU | 最大传输单元（以太网 1500 字节） |
| 错误检测 | CRC32 帧校验 |

### 以太网帧格式

```
┌───────────┬───────────┬─────┬───────────┬──────────┐
│ 目标 MAC   │ 源 MAC    │类型 │  数据       │  CRC     │
│ 6 字节     │ 6 字节     │2字节│ 46-1500   │ 4 字节   │
└───────────┴───────────┴─────┴───────────┴──────────┘
                           ↑
                    0x0800 = IPv4
                    0x86DD = IPv6
                    0x0806 = ARP
                    0x8100 = VLAN tag
```

### MAC 地址

| 概念 | 说明 |
|------|------|
| 长度 | 48 位（6 字节） |
| 格式 | XX:XX:XX:XX:XX:XX |
| 厂商 OUI | 前 24 位 |
| 设备标识 | 后 24 位 |
| 广播地址 | FF:FF:FF:FF:FF:FF |
| 组播 | 第一字节最低位为 1 |
| 本地管理 | 第二位为 1（本地分配） |

### ARP 协议

```
进程 A (192.168.1.10) → 通信 192.168.1.20

1. 查 ARP 缓存: 192.168.1.20 → ? (无缓存)
2. 广播 ARP 请求: "谁有 192.168.1.20?"
3. 192.168.1.20 单播回复: "我是 192.168.1.20, MAC=xx:xx:xx:xx:xx:xx"
4. A 更新 ARP 缓存
5. A 发送以太网帧到目标 MAC
```

### ARP 命令

```bash
# 查看 ARP 缓存
arp -a
ip neigh

# 静态 ARP 条目（防止 ARP 欺骗）
arp -s 192.168.1.1 00:11:22:33:44:55
```

### MTU

| 链路类型 | MTU |
|---------|-----|
| 以太网 | 1500 字节 |
| 以太网 Jumbo Frame | 9000 字节 |
| PPP | 1500 字节 |
| GRE 隧道 | 1476 字节 |
| IPv6 | 1280 字节（最小） |

**MTU 对 TCP 的影响**：MSS = MTU - IP头(20) - TCP头(20) = 1460 字节

## HFT / 嵌入式关联

- **组播**：HFT 行情数据使用 IP 组播，链路层映射为以太网组播帧
- **Jumbo Frame**：HFT 专用网络启用 9000 字节 Jumbo Frame，减少帧头开销
- **ARP 缓存**：HFT 服务器对关键网关和行情源设静态 ARP（防欺骗）
- **网卡亲和性**：多队列网卡 RSS，每个队列绑定到不同 CPU 核心
- **DPDK**：绕过内核网络栈，用户态直接从网卡 DMA 读取以太网帧
- **嵌入式**：嵌入式以太网通常 MTU 1500，支持 IEEE 1588 PTP

## 代码示例

```bash
# 查看接口 MTU
ip link show eth0

# 修改 MTU（需 root）
ip link set eth0 mtu 9000

# 查看 ARP 缓存
ip neigh show

# 抓取以太网帧（链路层）
tcpdump -i eth0 -e -XX
```

```c
/* 获取接口 MAC 地址 */
#include <net/if.h>
#include <sys/ioctl.h>
#include <linux/if.h>

int get_mac(const char *ifname, unsigned char *mac) {
    int fd = socket(AF_INET, SOCK_DGRAM, 0);
    struct ifreq ifr;
    strncpy(ifr.ifr_name, ifname, IFNAMSIZ);
    ioctl(fd, SIOCGIFHWADDR, &ifr);
    memcpy(mac, ifr.ifr_hwaddr.sa_data, 6);
    close(fd);
    return 0;
}
```

## 代码自测

<details>
<summary>1. MTU 和 MSS 的关系？</summary>

MSS（Maximum Segment Size）是 TCP 数据段的最大数据部分大小。MSS = MTU - IP头(20字节) - TCP头(20字节)。以太网 MTU=1500 → MSS=1460。Jumbo Frame MTU=9000 → MSS=8960。HFT 网络用 Jumbo Frame 减少大消息的分片。
</details>

<details>
<summary>2. 为什么 HFT 网络要用 Jumbo Frame？</summary>

1. **减少帧头开销**：每个以太网帧有 38 字节开销（帧头+CRC+间隙），1500 字节帧开销比例 2.5%，9000 字节帧仅 0.4%
2. **减少中断次数**：大消息分片更少，网卡中断更少
3. **减少 CPU 开销**：处理更少的帧，帧处理开销降低
4. **提升吞吐**：尤其适合大块数据传输（行情快照）
</details>

<details>
<summary>3. ARP 欺骗是什么？如何防御？</summary>

ARP 欺骗：攻击者发送伪造的 ARP 回复，将自己的 MAC 与网关 IP 关联，使受害者的流量经过攻击者。防御：(1) 静态 ARP 条目（`arp -s`）；(2) 动态 ARP 检测（交换机层）；(3) 网络隔离（专用 VLAN）；(4) HFT 专用网络通常与办公网络物理隔离。
</details>
