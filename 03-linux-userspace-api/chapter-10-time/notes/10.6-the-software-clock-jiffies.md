# 10.6 The Software Clock (Jiffies)

> 本章：[TLPI 第 10 章 — Time](./README.md)

## 本节讲什么

介绍 Linux 内核软件时钟的概念：jiffies（时钟中断滴答）、HZ 配置、分辨率限制，以及 `clock_getres()` 如何查询时钟精度。

## 要点

### jiffies 概念

| 概念 | 说明 |
|------|------|
| **jiffies** | 内核全局计数器，每次时钟中断 +1 |
| **HZ** | 时钟中断频率（每秒中断次数），编译时配置 |
| **jiffy** | 一个时钟滴答的时长 = 1/HZ 秒 |
| **分辨率** | 软件时钟的最小可分辨时间间隔 |

### HZ 配置值

| HZ | jiffy | 内核版本 | 典型场景 |
|----|-------|---------|---------|
| 100 | 10ms | 2.4 及更早 | 桌面/服务器 |
| 250 | 4ms | 2.6 默认 | 通用服务器 |
| 300 | 3.33ms | 某些发行版 | 桌面/服务器 |
| 1000 | 1ms | 2.6 可选 | 低延迟/桌面 |

### HZ 对系统的影响

| 高 HZ（1000） | 低 HZ（100） |
|---------------|-------------|
| 计时更精确 | 计时粗糙 |
| 定时器精度更高 | 定时器精度低 |
| 中断开销更大 | 中断开销小 |
| 上下文切换更频繁 | CPU 利用率更高 |
| 低延迟应用受益 | 吞吐量应用受益 |
| 功耗更高 | 笔记本省电 |

### 查询分辨率

```c
struct timespec res;
clock_getres(CLOCK_REALTIME, &res);
/* res.tv_sec = 0, res.tv_nsec = 4000000 (4ms) 当 HZ=250 */
```

| clockid | 典型分辨率 | 说明 |
|---------|-----------|------|
| `CLOCK_REALTIME` | 1/HZ | 墙上时钟 |
| `CLOCK_MONOTONIC` | 1/HZ | 单调时钟 |
| `CLOCK_MONOTONIC_RAW` | 硬件精度 | 不受 NTP 调整 |
| `CLOCK_MONOTONIC_COARSE` | 1/HZ | 快速但粗糙 |
| `CLOCK_REALTIME_COARSE` | 1/HZ | 快速但粗糙 |

### clock_getres API

```c
int clock_getres(clockid_t clk_id, struct timespec *res);
/* 返回 0 成功，res 填入分辨率 */
```

### 高分辨率定时器（hrtimer）

Linux 2.6.21+ 引入高分辨率定时器：
- 不依赖 jiffies，直接使用硬件时钟源（TSC/HPET）
- 支持纳秒级定时器
- `clock_nanosleep()` / `timer_settime()` 可达纳秒精度
- 前提：内核 `CONFIG_HIGH_RES_TIMERS=y`

| 定时器类型 | 分辨率 | 依赖 |
|-----------|--------|------|
| 传统定时器 | jiffies（4ms） | HZ |
| hrtimer | 纳秒 | 硬件时钟源 |
| `CLOCK_MONOTONIC_RAW` | 硬件精度 | TSC |

## HFT / 嵌入式关联

- **HFT 时钟需求**：微秒级时间戳，必须用 hrtimer + `CLOCK_MONOTONIC`
- **TSC（Time Stamp Counter）**：x86 CPU 硬件计数器，纳秒精度，HFT 首选时钟源
- `rdtsc` 指令直接读 TSC，无需系统调用
- **嵌入式**：ARM 的 Generic Timer（如 aarch64 的 CNTVCT）替代 jiffies 做高精度计时
- **内核编译**：HFT 专用内核通常 `CONFIG_HZ_1000=y` + `CONFIG_HIGH_RES_TIMERS=y` + `CONFIG_PREEMPT_RT=y`
- **时钟源选择**：`/sys/devices/system/clocksource/clocksource0/current_clocksource` 查看当前时钟源

## 代码示例

```c
#include <time.h>
#include <stdio.h>

void show_clock_resolutions(void) {
    clockid_t clocks[] = {
        CLOCK_REALTIME, CLOCK_MONOTONIC,
        CLOCK_MONOTONIC_RAW, CLOCK_REALTIME_COARSE,
        CLOCK_MONOTONIC_COARSE
    };
    const char *names[] = {
        "REALTIME", "MONOTONIC",
        "MONOTONIC_RAW", "REALTIME_COARSE",
        "MONOTONIC_COARSE"
    };
    struct timespec res;
    for (int i = 0; i < 5; i++) {
        clock_getres(clocks[i], &res);
        printf("%-20s: %ld.%09ld s (%ld ns)\n", names[i],
               (long)res.tv_sec, res.tv_nsec,
               res.tv_sec * 1000000000L + res.tv_nsec);
    }
}

/* 使用 rdtsc 直接读 TSC（x86） */
#ifdef __x86_64__
#include <stdint.h>
static inline uint64_t rdtsc(void) {
    uint32_t lo, hi;
    __asm__ __volatile__ ("rdtsc" : "=a"(lo), "=d"(hi));
    return ((uint64_t)hi << 32) | lo;
}
#endif
```

## 代码自测

<details>
<summary>1. HZ=250 时，clock_gettime(CLOCK_MONOTONIC) 返回的时间精度是多少？</summary>

理论上分辨率为 4ms（1/250 秒），但实际精度取决于实现：
- 如果使用 hrtimer（高分辨率定时器），`CLOCK_MONOTONIC` 可达纳秒精度，不受 HZ 限制
- 如果未启用 hrtimer，精度为 4ms
- 现代内核默认启用 hrtimer，所以 `clock_gettime` 通常为纳秒精度
- `clock_getres` 可以查询实际分辨率
</details>

<details>
<summary>2. CLOCK_MONOTONIC_COARSE 为什么比 CLOCK_MONOTONIC 快？</summary>

`CLOCK_MONOTONIC_COARSE` 是 Linux 特有时钟，它直接读取内核的 jiffies 计数器（`jiffies` 全局变量），**不陷入硬件时钟源查询**，开销极低。但精度只有 1/HZ（通常 4ms）。适用于不需要高精度但需要频繁获取时间戳的场景（如日志记录、统计计数）。`CLOCK_MONOTONIC` 则通过硬件时钟源（TSC/HPET）获取纳秒级时间，开销较高。
</details>

<details>
<summary>3. 为什么 HFT 场景通常编译 HZ=1000？</summary>

1. 更高的 HZ 意味着更频繁的调度检查，减少调度延迟
2. 定时器精度更高（1ms vs 4ms）
3. `CLOCK_MONOTONIC` 在无 hrtimer 时精度更高
4. HFT 对延迟敏感，中断开销可接受
5. 现代 HFT 系统通常还启用 `CONFIG_PREEMPT_RT`（实时抢占），配合高 HZ 实现可预测的延迟
</details>
