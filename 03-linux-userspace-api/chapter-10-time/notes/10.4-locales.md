> - 上一节：[10.3 Timezones 时区](10.3-timezones.md)

## 本节讲什么

[10.3](10.3-timezones.md) 管的是**偏移**（几点了），本节管的是**语言和格式**（怎么写成字）。两者正交：

| 维度 | 由谁决定 | 例子 |
|------|---------|------|
| 时间点 → UTC 秒数 | 内核 + `TZ` | `1700000000` |
| UTC 秒数 → 数字/字符串 | **locale** | `11/14/23` vs `14.11.2023` vs `2023年11月14日` |

一条最重要的前置事实：

> **C 程序的 locale 永远是 `"C"`，除非你自己调 `setlocale()`。** 环境变量 `LANG` / `LC_ALL` / `LC_TIME` **不会自动生效**。

这条跟大多数人的直觉相反（shell 里 `LANG=zh_CN.UTF-8` 明明生效了）——因为 shell 自己调了 `setlocale`，你的 C 程序没有。

本节 demo：`c10_4_locale.c`，五段——装了哪些 locale / `LC_TIME` 怎么改 `strftime` / `nl_langinfo` / `LC_NUMERIC` 与 `printf` / **`strftime` 返回 0 的坑**。

## 1. 进程级全局状态：`setlocale()` 的两种调用是两件事

源码：[../code/c10_4_locale.c](../code/c10_4_locale.c)

```c
/* TLPI 第 10 章 §10.4 Locales
 * locale 的粒度（LC_ALL vs LC_TIME vs LC_NUMERIC）、这台机器装了哪些 locale、
 * LC_TIME 怎么改 strftime、nl_langinfo / localeconv 取本地化字符串
 *
 * 编译: gcc -O0 -Wall -Wextra -o c10_4_locale c10_4_locale.c
 * 运行: ./c10_4_locale                        (无需参数、无需权限)
 *
 * 用固定时间戳，只让 locale 变 → 输出可复现。
 * ⚠️ locale 是**进程级全局状态**，不是线程级的；setlocale 是少数必须
 *    「在程序开头调一次」的函数。
 */
#define _GNU_SOURCE
#include <langinfo.h>
#include <locale.h>
#include <stdio.h>
#include <string.h>
#include <time.h>

#define FIXED 1700000000L   /* 2023-11-14 22:13:20 UTC */

/* 五个字段的复合格式串。单独拎出来是为了把它**连同展开结果一起打印**——
   下面第 2 节的日志里会先出现这一行原文，读者才知道每行五列各是什么。 */
#define FMT "%A %d %B %Y  |  %c  |  %p  |  %x  |  %X"

static const char *try_list[] = {
    "", "C", "POSIX", "C.UTF-8", "en_US.UTF-8", "en_US.utf8",
    "zh_CN.UTF-8", "zh_CN.utf8", "de_DE.UTF-8", "ja_JP.UTF-8",
    "fr_FR.UTF-8", "lt_LT.UTF-8", NULL
};

static void show_available(void)
{
    printf("== 1. 默认 locale 与这台机器上装了哪些 ==\n");
    printf("setlocale(LC_ALL, NULL) 初始 = \"%s\"\n", setlocale(LC_ALL, NULL));
    printf("（C 程序启动时永远是 \"C\"，除非自己调 setlocale —— "
           "环境变量 LANG/LC_* 不会自动生效）\n\n");

    for (int i = 0; try_list[i] != NULL; i++) {
        char *got;

        setlocale(LC_ALL, "C");                  /* 每次从干净状态试 */
        got = setlocale(LC_ALL, try_list[i]);
        printf("  setlocale(LC_ALL, %-12s) -> %s\n",
               try_list[i][0] ? try_list[i] : "\"\"",
               got ? got : "NULL（这台机器没装）");
        setlocale(LC_ALL, "C");
    }
    printf("\n");
}

static void show_lc_time(void)
{
    struct tm tm;
    time_t t = (time_t) FIXED;
    /* ⚠️ 这个 200 不是随手写的：zh_CN 的 "%A %d %B %Y  |  %c  |  %p  |  %x  |  %X"
       拼起来要 128 字节 —— 原来写 120，strftime 直接返回 0，
       而**返回 0 时缓冲区内容是不确定的**，于是打出 `@??z` 这种垃圾。
       这就是下面第 5 小节要专门演示的坑。 */
    char buf[200];

    printf("== 2. LC_TIME 影响 strftime 的哪些格式符 ==\n");
    printf("  格式串: \"%s\"\n", FMT);
    localtime_r(&t, &tm);

    for (int i = 0; try_list[i] != NULL; i++) {
        char *got;
        size_t n;

        setlocale(LC_ALL, "C");
        got = setlocale(LC_TIME, try_list[i]);
        if (got == NULL)
            continue;                            /* 没装的跳过 */

        n = strftime(buf, sizeof buf, FMT, &tm);
        printf("  LC_TIME=%-12s %s%s\n", try_list[i][0] ? try_list[i] : "\"\"", buf,
               (n == 0) ? "   <-- 返回 0：缓冲区不够！" : "");
    }
    setlocale(LC_ALL, "C");
    printf("\n");
}

/* strftime 唯一的失败信号就是「返回 0」—— 它不会告诉你需要多大，
   而且失败时缓冲区内容**未定义**。这是 C 标准库里少见的「无信息失败」。 */
static void show_ret0_trap(void)
{
    struct tm tm;
    time_t t = (time_t) FIXED;
    char big[512], small[64];

    printf("== 5. 掉一次 strftime 返回 0 的坑 ==\n");
    if (setlocale(LC_ALL, "zh_CN.UTF-8") == NULL) {
        printf("  （这台机器没装 zh_CN.UTF-8，跳过）\n\n");
        setlocale(LC_ALL, "C");
        return;
    }
    localtime_r(&t, &tm);
    {
        size_t need = strftime(big, sizeof big, "%c", &tm);
        size_t n;

        /* 故意先填满，再看 strftime 失败时到底动没动这块内存 */
        memset(small, '#', sizeof small);
        n = strftime(small, 20, "%c", &tm);

        printf("  LC_TIME=zh_CN.UTF-8，格式 \"%%c\"，时间戳 %ld\n", (long) FIXED);
        printf("    完整内容占 %zu 字节（不含结尾 \\0）：\"%s\"\n", need, big);
        printf("    只给 20 字节 -> 返回 %zu  %s\n", n, (n == 0) ? "（0 = 失败）" : "");
        printf("    此时 small = \"%.*s\"\n", 19, small);
        printf("    → 返回 0 时缓冲区内容未定义，**绝不能**再当字符串用；\n");
        printf("      要拿到「需要多大」只能先给个够大的缓冲区试一次。\n\n");
    }
    setlocale(LC_ALL, "C");
}

static void show_langinfo(void)
{
    static const nl_item items[] = {
        CODESET, D_T_FMT, D_FMT, T_FMT, AM_STR, PM_STR,
        RADIXCHAR, THOUSEP, CRNCYSTR
    };
    static const char *names[] = {
        "CODESET", "D_T_FMT", "D_FMT", "T_FMT", "AM_STR", "PM_STR",
        "RADIXCHAR", "THOUSEP", "CRNCYSTR"
    };

    printf("== 3. nl_langinfo()：locale 里的字符串 ==\n");
    for (int pass = 0; pass < 2; pass++) {
        const char *loc = (pass == 0) ? "C" : "de_DE.UTF-8";

        if (setlocale(LC_ALL, loc) == NULL) {
            printf("  （%s 没装，跳过）\n", loc);
            continue;
        }
        printf("  --- locale = %s ---\n", loc);
        for (size_t i = 0; i < sizeof items / sizeof items[0]; i++) {
            const char *v = nl_langinfo(items[i]);
            char e[80];
            size_t j = 0;
            for (size_t k = 0; v[k] != '\0' && j + 2 < sizeof e; k++) {
                if (v[k] == '\n') { e[j++] = '\\'; e[j++] = 'n'; }
                else              { e[j++] = v[k]; }
            }
            e[j] = '\0';
            printf("    %-10s = \"%s\"\n", names[i], e);
        }
    }
    setlocale(LC_ALL, "C");
    printf("\n");
}

static void show_numeric(void)
{
    struct lconv *lc;
    static const int ival = 1234567;
    static const double dval = 1234567.891;

    printf("== 4. LC_NUMERIC 与 printf：小数点是唯一被 printf 认的 ==\n");
    for (int pass = 0; pass < 2; pass++) {
        const char *loc = (pass == 0) ? "C" : "de_DE.UTF-8";

        if (setlocale(LC_ALL, loc) == NULL) {
            printf("  （%s 没装，跳过）\n", loc);
            continue;
        }
        lc = localeconv();
        printf("  --- locale = %s ---\n", loc);
        printf("    localeconv: decimal_point=\"%s\"  thousands_sep=\"%s\"  "
               "currency_symbol=\"%s\"\n",
               lc->decimal_point, lc->thousands_sep, lc->currency_symbol);
        printf("    printf(\"%%f\")      = %f\n", dval);
        printf("    printf(\"%%'d\")     = %'d     <- 千分位要靠 ' 旗标\n", ival);
    }
    setlocale(LC_ALL, "C");
    printf("\n");
}

int main(void)
{
    show_available();
    show_lc_time();
    show_langinfo();
    show_numeric();
    show_ret0_trap();

    printf("四个必须记住的点：\n");
    printf("  1) locale 是**进程级全局**的，C 程序不调 setlocale 永远跑在 \"C\" 上；\n");
    printf("  2) setlocale(LC_ALL, \"\") 才是「按环境变量来」，传 NULL 是「查询」；\n");
    printf("  3) printf 只认 LC_NUMERIC 的小数点；千分位分隔符要显式写 %%'d；\n");
    printf("  4) strftime 失败时**只返回 0**，不给需要的长度，缓冲区内容也不确定\n");
    printf("     —— 这就是 locale=zh_CN 时最容易被咬一口的地方（见第 5 段）。\n");
    return 0;
}
```

编译 + 运行：

```bash
gcc -O0 -Wall -Wextra -o c10_4_locale c10_4_locale.c
./c10_4_locale
```

实测（CE，gcc 13.3.0）第 1 段：

```text
== 1. 默认 locale 与这台机器上装了哪些 ==
setlocale(LC_ALL, NULL) 初始 = "C"
（C 程序启动时永远是 "C"，除非自己调 setlocale —— 环境变量 LANG/LC_* 不会自动生效）

  setlocale(LC_ALL, ""          ) -> C
  setlocale(LC_ALL, C           ) -> C
  setlocale(LC_ALL, POSIX       ) -> C
  setlocale(LC_ALL, C.UTF-8     ) -> C.UTF-8
  setlocale(LC_ALL, en_US.UTF-8 ) -> en_US.UTF-8
  setlocale(LC_ALL, en_US.utf8  ) -> en_US.utf8
  setlocale(LC_ALL, zh_CN.UTF-8 ) -> zh_CN.UTF-8
  setlocale(LC_ALL, zh_CN.utf8  ) -> zh_CN.utf8
  setlocale(LC_ALL, de_DE.UTF-8 ) -> de_DE.UTF-8
  setlocale(LC_ALL, ja_JP.UTF-8 ) -> ja_JP.UTF-8
  setlocale(LC_ALL, fr_FR.UTF-8 ) -> NULL（这台机器没装）
  setlocale(LC_ALL, lt_LT.UTF-8 ) -> lt_LT.UTF-8
```

### 第二参数有两种完全不同的含义

| 第二个参数 | 含义 | 返回值 |
|-----------|------|--------|
| `NULL` | **查询**当前设置 | 当前 locale 名（如 `"C"`） |
| `""` | **按环境变量设**（读 `LC_ALL` / `LC_*` / `LANG`） | 设置后的名字 |
| `"C"` / `"zh_CN.UTF-8"` ... | 显式按名字设 | 成功返回名字，**失败返回 `NULL`** |

这是 `setlocale` 唯一能告诉你「成功没有」的方式：**返回 `NULL` 就是没装上**。本机 `fr_FR.UTF-8` 返回 `NULL`——不是代码写错了，是这台机器确实没装这个 locale。

### `${LANG}` 那套的解析优先级

`setlocale(LC_ALL, "")` 里的空串触发下面这套查找（glibc，由高到低）：

| 顺序 | 环境变量 |
|------|---------|
| 1 | `LC_ALL` |
| 2 | `LC_<类别>`（如 `LC_TIME`、`LC_NUMERIC`） |
| 3 | `LANG` |
| 4 | 都没设 → 保持 `"C"` |

本机这些都没设，所以 `setlocale(LC_ALL, "")` 得到 `"C"`（实测第 2 行）。

### locale 名字的两种拼法

实测里同时列出了 `zh_CN.UTF-8` 和 `zh_CN.utf8`，**两个都能装上**：

| 写法 | 说明 |
|------|------|
| `en_US.UTF-8` | 规范写法（IETF 风格），现代 glibc 常见 |
| `en_US.utf8` | **历史别名**，glibc 也认。因为这个历史原因，写跨平台代码时优先用 `utf8` 拼法更兼容 |

### `LC_ALL` 是覆盖一切的，但它本身也属于「全局」

`setlocale(LC_ALL, "zh_CN.UTF-8")` 一次改掉**所有**类别。日常更该用的是**单类别**设置：

```c
setlocale(LC_TIME, "zh_CN.UTF-8");     /* 只改日期格式，不动小数点 */
setlocale(LC_NUMERIC, "C");            /* 数字格式保持 C，避免 printf 输出逗号 */
```

**「只改 `LC_TIME`，把 `LC_NUMERIC` 固定成 `C`」是工程上的标准做法**，原因见第 4 段。

## 2. `LC_TIME` 影响 `strftime` 的哪些格式符

```text
== 2. LC_TIME 影响 strftime 的哪些格式符 ==
  格式串: "%A %d %B %Y  |  %c  |  %p  |  %x  |  %X"
  LC_TIME=""           Tuesday 14 November 2023  |  Tue Nov 14 22:13:20 2023  |  PM  |  11/14/23  |  22:13:20
  LC_TIME=C            Tuesday 14 November 2023  |  Tue Nov 14 22:13:20 2023  |  PM  |  11/14/23  |  22:13:20
  LC_TIME=POSIX        Tuesday 14 November 2023  |  Tue Nov 14 22:13:20 2023  |  PM  |  11/14/23  |  22:13:20
  LC_TIME=C.UTF-8      Tuesday 14 November 2023  |  Tue Nov 14 22:13:20 2023  |  PM  |  11/14/23  |  22:13:20
  LC_TIME=en_US.UTF-8  Tuesday 14 November 2023  |  Tue 14 Nov 2023 10:13:20 PM UTC  |  PM  |  11/14/2023  |  10:13:20 PM
  LC_TIME=en_US.utf8   Tuesday 14 November 2023  |  Tue 14 Nov 2023 10:13:20 PM UTC  |  PM  |  11/14/2023  |  10:13:20 PM
  LC_TIME=zh_CN.UTF-8  星期二 14 十一月 2023  |  2023年11月14日 星期二 22时13分20秒  |  下午  |  2023年11月14日  |  22时13分20秒
  LC_TIME=zh_CN.utf8   星期二 14 十一月 2023  |  2023年11月14日 星期二 22时13分20秒  |  下午  |  2023年11月14日  |  22时13分20秒
  LC_TIME=de_DE.UTF-8  Dienstag 14 November 2023  |  Di 14 Nov 2023 22:13:20 UTC  |    |  14.11.2023  |  22:13:20
  LC_TIME=ja_JP.UTF-8  火曜日 14 11月 2023  |  2023年11月14日 22時13分20秒  |  午後  |  2023年11月14日  |  22時13分20秒
  LC_TIME=lt_LT.UTF-8  Antradienis 14 lapkričio 2023  |  2023 m. lapkričio 14 d. 22:13:20  |    |  2023-11-14  |  22:13:20
```

每行五个字段，对应同一个格式串 `"%A %d %B %Y  |  %c  |  %p  |  %x  |  %X"`——demo 里用 `#define FMT` 把它拎出来，所以日志会连原文带展开结果一起打（源码见 `code/c10_4_locale.c`）。

实测暴露一件很关键的事：**`%A` / `%B` 在所有 locale 下都变了，但 `%d` / `%Y` 的不变**。把格式符按「认不认 locale」分成两类：

| 类别 | 格式符 | 行为 |
|------|--------|------|
| **表示「文字」的** | `%a` `%A` `%b` `%B` `%h` `%p` | **跟随 locale**（`Tuesday` → `星期二`） |
| **表示「组合格式」的** | `%c` `%x` `%X` `%r` | **跟随 locale，而且整个格式都变**（`%X` 从 `22:13:20` 变成 `10:13:20 PM`） |
| **表示「数字」的** | `%Y` `%m` `%d` `%H` `%M` `%S` `%j` `%U` `%W` | **不跟随 locale**（数字还是阿拉伯数字） |
| **固定 ISO 风格** | `%F` `%T` `%R` `%D` | **不跟随 locale**（这是它们存在的意义） |

看 `de_DE` 那一行的对比最清楚：`%A %d %B %Y` 变成了 `Dienstag 14 November 2023`（`%d` 仍是 `14`），但 `%x` 从 `11/14/23` 变成了 `14.11.2023`（因为 `D_FMT` 是 `%d.%m.%Y`）。

> ⚠️ **`%p` 在 `de_DE` 下是空串**（实测那一列是空的）。德语里没有 AM/PM 缩写。如果你的输出靠 `%p` 区分上下午，德语文档里会**直接丢掉这个信息**。

### 为什么这行「修过一次」

这一节的 demo 原来给 `strftime` 的缓冲区是 **120 字节**，结果 `zh_CN.UTF-8` 那一行打出乱码 `@??z`。追下去发现：那个格式串在中文下拼起来要 **128 字节** → `strftime` 返回 0 → **缓冲区内容未定义**。

修法是：缓冲区扩到 200，并在每一行都检查返回值是否为 0（实测输出里若出现「`<-- 返回 0：缓冲区不够！`」就是踩了）。这个坑值得单独演示，所以加了第 5 段（见下）。

## 3. `nl_langinfo()`：把 locale 里的字符串取出来

```text
== 3. nl_langinfo()：locale 里的字符串 ==
  --- locale = C ---
    CODESET    = "ANSI_X3.4-1968"
    D_T_FMT    = "%a %b %e %H:%M:%S %Y"
    D_FMT      = "%m/%d/%y"
    T_FMT      = "%H:%M:%S"
    AM_STR     = "AM"
    PM_STR     = "PM"
    RADIXCHAR  = "."
    THOUSEP    = ""
    CRNCYSTR   = "-"
  --- locale = de_DE.UTF-8 ---
    CODESET    = "UTF-8"
    D_T_FMT    = "%a %d %b %Y %T %Z"
    D_FMT      = "%d.%m.%Y"
    T_FMT      = "%T"
    AM_STR     = ""
    PM_STR     = ""
    RADIXCHAR  = ","
    THOUSEP    = "."
    CRNCYSTR   = "+€"
```

`nl_langinfo(item)` 是「反着用 locale」的接口：`strftime` 是「格式符 → 字符串」，`nl_langinfo` 是「**直接问 locale 里某个字段的字符串**」。

| `nl_item` | 含义 | 用途 |
|-----------|------|------|
| `CODESET` | 字符集名 | **这是判断编码的正确方式**（不要靠 `MB_CUR_MAX` 猜） |
| `D_T_FMT` / `D_FMT` / `T_FMT` | 日期时间/日期/时间的**格式串** | 用来构造 `strftime` 的格式 |
| `AM_STR` / `PM_STR` | 上午/下午的字符串 | 德语下是空串 |
| `RADIXCHAR` | **小数点字符** | `C` 是 `.`，德语是 `,` |
| `THOUSEP` | 千分位分隔符 | `C` 是空串，德语是 `.` |
| `CRNCYSTR` | 货币符号 | 德语是 `"+€"`（前面那个 `+` 表示「符号在前」） |

**`CODESET` 那条最实用**：`"ANSI_X3.4-1968"` 就是 ASCII 的正式名。程序的启动自检里经常写「如果 `CODESET` 不是 `UTF-8` 就告警」，比猜 locale 名字可靠得多。

`CRNCYSTR` 那个前导 `+` 是 POSIX 规定的「符号位置」编码（`+` 在前 / `-` 在后），不是「正号」。

## 4. `LC_NUMERIC` 与 `printf`：小数点是唯一被认的

```text
== 4. LC_NUMERIC 与 printf：小数点是唯一被 printf 认的 ==
  --- locale = C ---
    localeconv: decimal_point="."  thousands_sep=""  currency_symbol=""
    printf("%f")      = 1234567.891000
    printf("%'d")     = 1234567     <- 千分位要靠 ' 旗标
  --- locale = de_DE.UTF-8 ---
    localeconv: decimal_point=","  thousands_sep="."  currency_symbol="€"
    printf("%f")      = 1234567,891000
    printf("%'d")     = 1.234.567     <- 千分位要靠 ' 旗标
```

这一段是全篇最实用的一节。三条结论：

| 结论 | 说明 |
|------|------|
| **`printf` 只认 `LC_NUMERIC` 小数点** | `%f` 输出 `1234567,891000`——**逗号**。如果你在解析自己的日志，`sscanf("%f")` 换 locale 后就会解析失败 |
| **千分位分隔符不会自动加** | 必须写 `%'d`（那个 `'` 是 POSIX 扩展旗标）。光设 locale 不出分隔符 |
| `localeconv()` 是**结构体版**的 `nl_langinfo` | `struct lconv *`，一次拿到所有数字/货币相关字段 |

### 为什么「只改 `LC_TIME`，把 `LC_NUMERIC` 锁成 `C`」是标准做法

看第 2 段的实测：把 `LC_ALL` 设成 `de_DE.UTF-8` 之后，**`%f` 的输出就带逗号了**。这会连锁引发：

| 受影响的地方 | 后果 |
|-------------|------|
| `printf("%f")` | 输出逗号 → 日志/CSV 不再能用 `.` 解析 |
| `scanf` / `sscanf` / `strtod` / `atof` | **反向也受影响**：德语 locale 下 `strtod("1.5")` 会在 `1` 处停下，返回 `1.0` |
| 自己写的 JSON / 协议序列化 | 出来的不是合法 JSON（JSON 规定小数点必须是 `.`） |

所以 `setlocale(LC_ALL, "")` 在**服务端代码里是个陷阱**。正确姿势：

```c
setlocale(LC_TIME, "zh_CN.UTF-8");   /* 只要中文日期格式 */
setlocale(LC_NUMERIC, "C");          /* 数字格式必须锁死 */
```

> 顺带：`printf` 的 `%'d` 旗标**只影响输出**，不影响输入函数。而 `strtod` 的行为**由 `LC_NUMERIC` 决定**——这是「同一个 locale 改了之后，输入和输出一起变」的少数例子之一，务必小心。

## 5. 掉一次 `strftime` 返回 0 的坑

```text
== 5. 掉一次 strftime 返回 0 的坑 ==
  LC_TIME=zh_CN.UTF-8，格式 "%c"，时间戳 1700000000
    完整内容占 43 字节（不含结尾 \0）："2023年11月14日 星期二 22时13分20秒"
    只给 20 字节 -> 返回 0  （0 = 失败）
    此时 small = "###################"
    → 返回 0 时缓冲区内容未定义，**绝不能**再当字符串用；
      要拿到「需要多大」只能先给个够大的缓冲区试一次。
```

`strftime()` 的失败契约是 C 标准库里少见的「**无信息失败**」：

| 问题 | 答案 |
|------|------|
| 怎么知道失败了？ | 返回 `0` |
| 失败了怎么知道需要多大？ | **不知道**（标准没给任何途径） |
| 失败时缓冲区里是什么？ | **未定义**（demo 里先 `memset` 成 `#`，实测原封不动，但**不能依赖这个行为**） |
| 成功但输出恰好是空串怎么办？ | 也返回 `0`（区分不了！不过正常的格式符不会产生空输出） |

### 实践建议

| 做法 | 说明 |
|------|------|
| 缓冲区给足 | 经验值：`%c` + 中文 locale ≤ 64 字节；自己拼多个格式符时按「字符数 × `MB_CUR_MAX`」估 |
| **每次调用都检查返回值** | 返回 0 就报错/降级，绝不用那个缓冲区 |
| 需要精确长度时**先用大缓冲区探一次** | `size_t need = strftime(big, sizeof big, fmt, &tm);` 再按需分配。没有更好的办法 |
| 别用 `strlen(buf)` 当长度 | 失败时 `buf` 可能没有 `\0` |

这与「`snprintf` 返回**需要的长度**」形成鲜明对比——`snprintf` 你可以在下界估算后重试一次拿到正确结果，`strftime` 不行。

## HFT / 嵌入式关联

| 场景 | 结论 |
|------|------|
| **协议/序列化** | `LC_NUMERIC` 必须锁 `"C"`。否则德语环境下输出的 JSON 里 `1,5` 不是合法 JSON |
| **时间戳格式** | 固定用 `%F %T` / `%Y-%m-%dT%H:%M:%S`，**不要**用 `%c`/`%x`/`%X`——它们的输出随机器变，日志就没法用脚本统一解析 |
| **热路径** | `setlocale()` 会重建整个 locale 表（要读 `.mo` / locale archive），**绝不能在热路径反复调**。正确做法是进程启动时调一次 |
| **多线程** | `setlocale()` 改的是**进程级**全局状态，且 glibc 的 locale 对象本身不是线程安全切换的。多线程程序里**不要**在中途改 locale |
| **嵌入式（musl / BusyBox）** | 常见情况是**一个 locale 都没装**，`setlocale(LC_ALL, "")` 直接返回 `NULL`，程序沉默地跑在 `"C"` 上。凡是依赖 locale 的输出都不要进协议 |
| **中文日志** | `CODESET` 必须是 `UTF-8`。启动自检里查这一项，比查 `LANG` 可靠 |
| **货币/金额** | `CRNCYSTR` / `THOUSEP` 在不同 locale 下差异极大（德语 `1.234,56 €`）。**金额一律用整数最小单位（分）存储和传输**，格式化只在前端做 |

## 代码自测

<details>
<summary>1. 进程启动时 `setlocale(LC_ALL, NULL)` 返回 `"C"`，但环境变量里明明有 `LANG=zh_CN.UTF-8`。为什么？</summary>

**因为 C 程序不会自动读环境变量**。`LANG` / `LC_ALL` / `LC_*` 只在**你显式调** `setlocale(LC_ALL, "")`（注意：第二个参数是**空串**，不是 `NULL`）时才被读取。

对比三种调用：

| 调用 | 行为 | 本机实测返回 |
|------|------|-------------|
| `setlocale(LC_ALL, NULL)` | **查询**，不改任何东西 | `"C"` |
| `setlocale(LC_ALL, "")` | 按环境变量设置（`LC_ALL` → `LC_*` → `LANG`） | `"C"`（本机环境变量没设） |
| `setlocale(LC_ALL, "zh_CN.UTF-8")` | 显式按名字设 | `"zh_CN.UTF-8"` |

这是「C 标准库不做任何你没让它做的事」的典型体现，也是老 C 程序里中文输出乱码的第一大原因。

</details>

<details>
<summary>2. `setlocale(LC_ALL, "")` 之后 `printf("%f")` 输出变成了逗号。这是 bug 吗？怎么修？</summary>

**不是 bug，是 POSIX 规定的行为**。`%f` 的小数点字符由 `LC_NUMERIC` 的 `decimal_point` 决定（`nl_langinfo(RADIXCHAR)` / `localeconv()->decimal_point`）。

德语 locale 下实测：`printf("%f", 1234567.891)` → `1234567,891000`。

修法（按推荐度）：

| 修法 | 说明 |
|------|------|
| `setlocale(LC_ALL, ""); setlocale(LC_NUMERIC, "C");` | **最推荐**：只解锁语言/日期本地化，数字格式锁死 |
| 干脆不用 `LC_ALL`，只调 `setlocale(LC_TIME, "")` | 你多半只是想要本地化的日期 |
| 自己格式化数字 | 只在确实需要本地化展示时才用 locale |

⚠️ 反向的坑同样存在：`strtod("1.5")` / `sscanf("%f")` 在德语 locale 下只解析到 `1`。**输入和输出都被 `LC_NUMERIC` 影响**。

</details>

<details>
<summary>3. `strftime()` 返回 0 表示什么？为什么说它比 `snprintf` 难用？</summary>

返回 `0` 表示**失败**（缓冲区不够）。但：

| 对比项 | `snprintf` | `strftime` |
|--------|-----------|-----------|
| 失败信号 | 返回值 ≥ `size`（**返回的是需要的长度**） | 返回 `0`（**不告诉你需要多大**） |
| 能否「先问长度再分配」 | 能：`n = snprintf(NULL, 0, fmt, ...)` | **不能**（没有对应机制） |
| 失败时缓冲区内容 | 保证 `\0` 结尾（截断） | **未定义** |
| 截断时的行为 | 输出被截断但仍是合法字符串 | 返回 0，内容不可用 |

所以 `strftime` 的唯一安全用法是「**给足够大的缓冲区 + 每次检查返回值**」。如果确实需要精确长度，只能先给一个大缓冲区调一次拿到长度，再按需分配——多一次调用。

本 demo 的第 2 段和第 5 段就是这件事的两面：前者因为缓冲区太小而失败（一行乱码），后者把失败过程显式演示出来。

</details>

<details>
<summary>4. 为什么说「依赖 locale 的输出不要写进协议」？</summary>

因为同一份数据在不同机器上会变成**不同的字节**，而且这种差异**不报错、不告警**：

| 维度 | 变化示例（本 demo 实测） |
|------|------------------------|
| 小数点 | `.`（C） vs `,`（de_DE） |
| 日期格式 | `11/14/23`（C） vs `14.11.2023`（de_DE） vs `2023年11月14日`（zh_CN） |
| AM/PM | `PM`（C） vs **空串**（de_DE，德语没有） |
| 时区名 | `GMT` / `CST` / `+0545`（内容长度都不固定） |
| 字符集 | `ANSI_X3.4-1968`（C） vs `UTF-8`（其它） |

后果很具体：

1. 一台德国服务器写出的日志，你的解析脚本按 `%m/%d/%y` 去读会**全部读错**。
2. 用 `%c` 生成的字符串含中文，长度按**字符**算和按**字节**算差 3 倍。
3. 序列化成 JSON 时 `1,5` 不是合法 JSON 数字，接收端**解析失败但不是协议错误**（很难查到根因）。

所以工程约定是：**「机器读的」一律用固定格式（`%Y-%m-%dT%H:%M:%S`、`LC_NUMERIC=C`、UTF-8），「人读的」才用 locale**。

</details>
