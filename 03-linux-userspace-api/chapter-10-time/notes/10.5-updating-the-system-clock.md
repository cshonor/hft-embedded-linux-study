# 10.5 Updating the System Clock 修改系统时钟

> 本章：[TLPI 第 10 章 — Time](../README.md)
> 源码核验：Linux **v6.6**（`kernel/time/time.c`、`kernel/time/timekeeping.c`、`kernel/time/ntp.c`、`include/uapi/linux/timex.h` 逐行核对）+ CE 实测（gcc 13.3.0 / x86-64 / Ubuntu 24.04）
> - 上一节：[10.4 Locales 本地化](10.4-locales.md)
> - 下一节：[10.6 The Software Clock (Jiffies) 软件时钟](10.6-the-software-clock-jiffies.md)

---

## 本节讲什么

前面四节全是「读」。本节讲「**写**」——把系统时钟改成另一个值。

| 接口 | 精度 | 行为 | 权限 |
|------|------|------|------|
| `settimeofday(tv, tz)` | μs | **跳变** | `CAP_SYS_TIME` |
| `clock_settime(CLOCK_REALTIME, ts)` | ns | **跳变** | `CAP_SYS_TIME` |
| `adjtime(delta, olddelta)` | μs | **平滑**（每秒最多约 500 μs） | `CAP_SYS_TIME` |
| `clock_adjtime(REALTIME, tx)` | ns | 同时调 `freq`/`offset`/`tick`/`status` | `CAP_SYS_TIME`（只读不需要） |

本节的 demo 做一件很「诚实」的事：**在非特权容器里把每一路都试一遍，看它到底返回什么**。做不成的实验就如实打印 `EPERM`，不假装成功——这是本仓库 demo 的统一约定。

## 0. 先确认自己有没有资格

源码：[../code/c10_5_setclock.c](../code/c10_5_setclock.c)

```c
/* TLPI 第 10 章 §10.5 Updating the System Clock
 * 改系统时钟的四个接口在**非特权**进程下分别怎么失败；只读接口怎么读；
 * CAP_SYS_TIME 到底有没有
 *
 * 编译: gcc -O0 -Wall -Wextra -o c10_5_setclock c10_5_setclock.c
 * 运行: ./c10_5_setclock                      (无需参数；本容器非 root)
 *
 * 原书 §10.5 讲了三条改时钟的路（settimeofday / clock_settime / adjtime）
 * 和 NTP 的渐进校正。本 demo 只做一件事：**在容器里把每一路都试一遍，
 * 看它到底返回什么**。做不成的实验就如实打印「EPERM」，不假装成功
 * —— 这是本仓库 demo 的统一约定。
 *
 * 预期（非特权容器）：4 个写接口全部 -1/EPERM，2 个只读接口成功。
 */
#define _GNU_SOURCE
#include <errno.h>
#include <stdio.h>
#include <string.h>
#include <sys/time.h>
#include <sys/timex.h>
#include <time.h>
#include <unistd.h>

/* CAP_SYS_TIME 在 capability 位图里的位号（include/uapi/linux/capability.h） */
#define CAP_SYS_TIME_BIT 25

static int read_cap_sys_time(void)
{
    FILE *f = fopen("/proc/self/status", "r");
    char line[512];
    unsigned long long eff = 0;

    if (f == NULL)
        return -1;
    while (fgets(line, sizeof line, f) != NULL) {
        if (strncmp(line, "CapEff:", 7) == 0) {
            sscanf(line + 7, "%llx", &eff);
            break;
        }
    }
    fclose(f);
    return (int) ((eff >> CAP_SYS_TIME_BIT) & 1ULL);
}

static void show_identity(void)
{
    int cap = read_cap_sys_time();

    printf("== 0. 先看有没有资格改时钟 ==\n");
    printf("uid=%ld  euid=%ld  egid=%ld\n",
           (long) getuid(), (long) geteuid(), (long) getegid());
    printf("CapEff 里 CAP_SYS_TIME(bit %d) = %s\n",
           CAP_SYS_TIME_BIT,
           cap < 0 ? "读不到 /proc/self/status"
                   : (cap ? "1 —— 有资格" : "0 —— 没资格，下面的写操作必然 EPERM"));
    printf("\n");
}

static void probe_writes(void)
{
    struct timespec ts = { 0, 0 };
    struct timeval tv = { 0, 0 };
    struct timeval delta = { 0, 1000 };     /* 想往前拨 1000 微秒 */
    struct timeval old = { 0, 0 };
    struct timex tx;
    int rc;

    printf("== 1. 四个「改时钟」接口逐个试 ==\n");

    errno = 0;
    ts.tv_sec = (time_t) 0;                 /* 想把时钟设成 1970-01-01 */
    rc = clock_settime(CLOCK_REALTIME, &ts);
    printf("  clock_settime(CLOCK_REALTIME, 1970-01-01) -> %d  errno=%d (%s)\n",
           rc, errno, strerror(errno));

    errno = 0;
    rc = settimeofday(&tv, NULL);
    printf("  settimeofday(&{0,0}, NULL)                  -> %d  errno=%d (%s)\n",
           rc, errno, strerror(errno));

    errno = 0;
    rc = adjtime(&delta, &old);
    printf("  adjtime(+1000us, &old)                      -> %d  errno=%d (%s)\n",
           rc, errno, strerror(errno));

    memset(&tx, 0, sizeof tx);
    tx.modes = ADJ_FREQUENCY;
    tx.freq = 100;
    errno = 0;
    rc = clock_adjtime(CLOCK_REALTIME, &tx);
    printf("  clock_adjtime(REALTIME, modes=ADJ_FREQUENCY) -> %d  errno=%d (%s)\n",
           rc, errno, strerror(errno));
    printf("（这四条在非特权进程下都必须是 EPERM —— 内核用\n"
           "  capable(CAP_SYS_TIME) 在真正动时钟之前就挡掉了）\n\n");
}

static void probe_reads(void)
{
    struct timeval old = { 0, 0 };
    struct timex tx;
    int rc;

    printf("== 2. 两个「只读」接口是允许的 ==\n");

    errno = 0;
    rc = adjtime(NULL, &old);
    printf("  adjtime(NULL, &old) 读待校正量 -> %d  剩余 %ld.%06ld s  errno=%d (%s)\n",
           rc, (long) old.tv_sec, (long) old.tv_usec, errno, strerror(errno));

    memset(&tx, 0, sizeof tx);
    errno = 0;
    rc = clock_adjtime(CLOCK_REALTIME, &tx);
    if (rc < 0) {
        printf("  clock_adjtime(REALTIME, modes=0) 只读 -> %d  errno=%d (%s)\n",
               rc, errno, strerror(errno));
    } else {
        printf("  clock_adjtime(REALTIME, modes=0) 只读 -> %d  (返回值即 status)\n", rc);
        printf("    freq      = %ld  (每 2^16 单位 = 1 ppm)\n", tx.freq);
        printf("    offset    = %ld us\n", tx.offset);
        printf("    esterror  = %ld us\n", tx.esterror);
        printf("    maxerror  = %ld us\n", tx.maxerror);
        printf("    status    = 0x%x  (STA_PLL=%d STA_UNSYNC=%d STA_NANO=%d)\n",
               tx.status, !!(tx.status & STA_PLL), !!(tx.status & STA_UNSYNC),
               !!(tx.status & STA_NANO));
        printf("    tai       = %d  (TAI - UTC 的闰秒补偿)\n", (int) tx.tai);
        /* tick 就是内核的 tick_usec：USER_HZ 一个 tick 的微秒数。
           它不是 2^-16 定标量（freq 才是）。见 kernel/time/ntp.c:816
           `txc->tick = tick_usec;` + :34 `tick_usec = USER_TICK_USEC`。 */
        printf("    tick      = %ld  (USER_HZ 下一个 tick 的微秒数 = 10 ms)\n", tx.tick);
    }
    printf("\n");
}

static void show_gettimeofday_timezone(void)
{
    struct timeval tv;
    struct timezone tz;
    int rc;

    printf("== 3. gettimeofday 的第二个参数（struct timezone） ==\n");
    memset(&tz, 0xAA, sizeof tz);           /* 先填成 0xAA，看内核会不会改写 */
    errno = 0;
    rc = gettimeofday(&tv, &tz);
    printf("  gettimeofday(&tv, &tz) -> %d  errno=%d (%s)\n",
           rc, errno, strerror(errno));
    printf("  tv = %ld.%06ld\n", (long) tv.tv_sec, (long) tv.tv_usec);
    printf("  tz = { tz_minuteswest=%d, tz_dsttime=%d }\n",
           tz.tz_minuteswest, tz.tz_dsttime);
    printf("  tz 仍是 0xAA 模式? %s   <- glibc 根本不填它\n",
           (tz.tz_minuteswest == (int) 0xAAAAAAAA) ? "是" : "否");
    printf("（POSIX 早就把 timezone 参数标成废弃：Linux 里时区完全由用户态\n"
           "  glibc + /etc/localtime 决定，内核手上没有时区信息）\n");
}

int main(void)
{
    show_identity();
    probe_writes();
    probe_reads();
    show_gettimeofday_timezone();

    printf("\n原书 §10.5 的要点，在这台机器上的对照：\n");
    printf("  settimeofday()  —— 废弃；要 CAP_SYS_TIME；精度只到微秒\n");
    printf("  clock_settime() —— 推荐替代；同样要 CAP_SYS_TIME；精度到纳秒；**会跳变**\n");
    printf("  adjtime()       —— 平滑推进：内核对 delta 按每秒约 %d us 的速率摊开\n",
           500);
    printf("  clock_adjtime() —— adjtimex(2) 的 POSIX 门面，能同时调 freq/offset/tick\n");
    return 0;
}
```

编译 + 运行：

```bash
gcc -O0 -Wall -Wextra -o c10_5_setclock c10_5_setclock.c
./c10_5_setclock
```

实测（CE，gcc 13.3.0）：

```text
== 0. 先看有没有资格改时钟 ==
uid=0  euid=0  egid=0
CapEff 里 CAP_SYS_TIME(bit 25) = 0 —— 没资格，下面的写操作必然 EPERM
```

**这里有一个非常重要的教学点**：`uid` / `euid` 都是 **0**，但**依然没有权限**。

| 概念 | 说明 |
|------|------|
| `uid=0` | 只是「root 用户」这个**身份** |
| `CapEff`（Effective capability set） | **真正决定能不能做**的东西 |
| `CAP_SYS_TIME` | capability 位图里的**第 25 位**（`include/uapi/linux/capability.h`） |

容器运行时（Docker 默认）**会把 capability 集合裁掉**，只保留一小部分——所以「容器里是 root」≠「容器里什么都能干」。这也是「宿主机上 `date -s` 能跑、容器里报 `Operation not permitted`」的根因。

demo 里读 `CapEff` 的方式是直接解析 `/proc/self/status`：

```c
while (fgets(line, sizeof line, f) != NULL) {
    if (strncmp(line, "CapEff:", 7) == 0) {
        sscanf(line + 7, "%llx", &eff);
        break;
    }
}
```

`CapEff` 是**十六进制位图**，所以判断第 25 位就是 `(eff >> 25) & 1`。

## 1. 四个「改时钟」接口逐个试：全部 EPERM

```text
== 1. 四个「改时钟」接口逐个试 ==
  clock_settime(CLOCK_REALTIME, 1970-01-01) -> -1  errno=1 (Operation not permitted)
  settimeofday(&{0,0}, NULL)                  -> -1  errno=1 (Operation not permitted)
  adjtime(+1000us, &old)                      -> -1  errno=1 (Operation not permitted)
  clock_adjtime(REALTIME, modes=ADJ_FREQUENCY) -> -1  errno=1 (Operation not permitted)
（这四条在非特权进程下都必须是 EPERM —— 内核用
  capable(CAP_SYS_TIME) 在真正动时钟之前就挡掉了）
```

四条全部 `-1 / errno=1 (EPERM)`。内核里的拦截点：

| 接口 | 内核里的权限检查 | 位置（v6.6） |
|------|-----------------|-------------|
| `settimeofday()` / `clock_settime()`（都走 `do_sys_settimeofday64`） | `security_settime64(tv, tz)` → LSM（`commoncap` 的 `cap_settime()` → `capable(CAP_SYS_TIME)`） | `kernel/time/time.c:177` |
| `adjtime()` / `clock_adjtime()`（都走 `__do_adjtimex`） | `!capable(CAP_SYS_TIME)` | `kernel/time/timekeeping.c:2349` / `:2353` / `:2367` |

`clock_settime` 的 syscall 定义在 `kernel/time/posix-timers.c:1113`，`CLOCK_REALTIME` 的实现在同一文件 `:1515` 的 `[CLOCK_REALTIME] = &clock_realtime` 表里——**它最终还是调 `do_sys_settimeofday64()`**，跟 `settimeofday` 走同一条路。

> **为什么「权限检查必须在动时钟之前」很关键**：时钟一旦被改，所有基于时间戳的排序、超时、日志都会错乱。所以这个检查必须是**第一道**（在任何状态被修改之前），不能放在 `if (tz)` 那种分支里。看 `do_sys_settimeofday64()` 的代码顺序就很清楚：第 174 行先校验 `timespec` 合法性，第 177 行就检查权限，第 181 行之后才碰 `sys_tz` 和时钟。

## 2. 两个「只读」接口是允许的

```text
== 2. 两个「只读」接口是允许的 ==
  adjtime(NULL, &old) 读待校正量 -> 0  剩余 0.000000 s  errno=0 (Success)
  clock_adjtime(REALTIME, modes=0) 只读 -> 0  (返回值即 status)
    freq      = -904454  (每 2^16 单位 = 1 ppm)
    offset    = 0 us
    esterror  = 2 us
    maxerror  = 4976 us
    status    = 0x2000  (STA_PLL=0 STA_UNSYNC=0 STA_NANO=1)
    tai       = 37  (TAI - UTC 的闰秒补偿)
    tick      = 10000  (USER_HZ 下一个 tick 的微秒数 = 10 ms)
```

这是本节信息量最大的一段。逐个字段拆：

| 字段 | 实测值 | 含义 | 来源 |
|------|--------|------|------|
| `freq` | `-904454` | **频率偏移**，单位是「**2⁻¹⁶ 定标的 ppm**」→ 实际 = `−904454 / 65536 ≈ −13.8 ppm` | `include/uapi/linux/timex.h:68` 注释写着 `frequency offset (scaled ppm)` |
| `offset` | `0 us` | 待施加的时间偏移量（只读时为 0） | — |
| `esterror` | `2 us` | **估算误差**（NTP 自己报的） | `:70` `estimated error (usec)` |
| `maxerror` | `4976 us` | **最大误差**，会随时间线性增长（不跟 NTP 同步就越来越大） | `:69` `maximum error (usec)` |
| `status` | `0x2000` | 状态位图，见下表 | `:71` `clock command/status` |
| `tai` | `37` | **TAI − UTC 的闰秒差**（写这段代码时是 37 秒） | `:89` `TAI offset (ro)` |
| `tick` | `10000` | **USER_HZ 一个 tick 的微秒数** = `10 ms`（不是 2⁻¹⁶ 定标量！见下） | `:78` `tick; /* (modified) usecs between clock ticks */` |

### `status = 0x2000` 拆位

| 位 | 名称 | 实测 | 含义 |
|----|------|------|------|
| `0x0001` | `STA_PLL` | 0 | PLL 更新已**关闭** |
| `0x0040` | `STA_UNSYNC` | 0 | 时钟**已同步**（这个 0 是好事） |
| `0x2000` | `STA_NANO` | **1** | 分辨率是**纳秒**（0 = 微秒） |

位定义取自 `include/uapi/linux/timex.h:171`（`STA_PLL`）、`:178`（`STA_UNSYNC`）、`:187`（`STA_NANO`）。

`STA_NANO=1` 这一位很实用：它决定了 `offset` 字段的单位是 ns 还是 µs。解析 `struct timex` 之前**必须**先看这一位。

### `tick = 10000` 是怎么来的（一条完整的证据链）

这条链把 10.6 的主题提前串起来了：

| 步骤 | 位置 | 内容 |
|------|------|------|
| ① 内核给 `struct timex` 填 `tick` | `kernel/time/ntp.c:816` | `txc->tick = tick_usec;` |
| ② `tick_usec` 的初值 | `kernel/time/ntp.c:34` | `unsigned long tick_usec = USER_TICK_USEC;` |
| ③ `USER_TICK_USEC` 的定义 | `include/linux/jiffies.h:68` | `#define USER_TICK_USEC ((1000000UL + USER_HZ/2) / USER_HZ)` |
| ④ `USER_HZ` 的值 | `include/asm-generic/param.h:9` | `# define USER_HZ 100` |

代进公式：`(1000000 + 50) / 100 = 10000` ✔ 与实测一致。

注意第 ④ 步——**又是 `USER_HZ`（写死的 100），不是 `CONFIG_HZ`**。这一节和 [10.6](10.6-the-software-clock-jiffies.md) 会各撞一次这个坑，所以值得在这里先立住。

### `adjtime(NULL, &olddelta)` 是一个「查询」

`adjtime(3)` 的第一个参数为 `NULL` 时**不修改任何东西**，只把「当前还没做完的平滑调整量」写进第二个参数（实测 `0.000000 s`，因为时钟本来就准）。

这跟 [10.1](10.1-calendar-time.md) 讨论的 `time()` 一样，是「用 `NULL` 表示只读」的经典接口设计。POSIX 里它对应的内核接口是 `ADJ_OFFSET_SS_READ`（`include/uapi/linux/timex.h:153`，注释就写着 `read-only adjtime`）。

## 3. `gettimeofday` 的第二个参数：内核根本不填它

```text
== 3. gettimeofday 的第二个参数（struct timezone） ==
  gettimeofday(&tv, &tz) -> 0  errno=0 (Success)
  tv = 1789376722.928727
  tz = { tz_minuteswest=0, tz_dsttime=0 }
  tz 仍是 0xAA 模式? 否   <- glibc 根本不填它
（POSIX 早就把 timezone 参数标成废弃：Linux 里时区完全由用户态
  glibc + /etc/localtime 决定，内核手上没有时区信息）
```

demo 的技巧：调用前先把 `struct timezone` **整块 `memset` 成 `0xAA`**，然后看内核有没有改写它。

| 观察 | 结论 |
|------|------|
| `tz = { 0, 0 }` | 是 `0xAAAAAAAA` 模式被清掉了吗？**不是**——`memset` 成 `0xAA` 之后 `tz_minuteswest` 应该是 `0xAAAAAAAA`，实测是 `0` |
| `tz 仍是 0xAA 模式? 否` | 所以 glibc **真的写了** `{0, 0}` 进去——但写的是「零」，不是真实时区 |

> 这里有个容易搞反的地方，值得写清楚：**「不被填写」和「被填成 0」在这个实验里是不好区分的**。要区分得看反汇编或者读源码。demo 的措辞是「glibc 根本不填它」——更准确的说法是 **glibc 把它清零，从不给真实值**（因为 Linux 内核没有时区信息可给）。
>
> 所以这个参数的正确用法是：**永远传 `NULL`**。

### 为什么 `settimeofday` 的 `tz` 参数被废弃

看内核代码就明白了（`kernel/time/time.c:181-193`）：

```c
	if (tz) {
		/* Verify we're within the +-15 hrs range */
		if (tz->tz_minuteswest > 15*60 || tz->tz_minuteswest < -15*60)
			return -EINVAL;

		sys_tz = *tz;
		update_vsyscall_tz();
		...
	}
```

内核只接受这个值、校验范围（±15 小时）、存进一个 `sys_tz` 变量，然后——**几乎没人用它**。真正的时区换算全在 glibc 里做（[10.3](10.3-timezones.md)）。这个「历史遗留的 write-only 参数」就是 POSIX 把它标成 `obsolescent` 的原因。

## 4. 四种改时钟方式的行为差异

```text
原书 §10.5 的要点，在这台机器上的对照：
  settimeofday()  —— 废弃；要 CAP_SYS_TIME；精度只到微秒
  clock_settime() —— 推荐替代；同样要 CAP_SYS_TIME；精度到纳秒；**会跳变**
  adjtime()       —— 平滑推进：内核对 delta 按每秒约 500 us 的速率摊开
  clock_adjtime() —— adjtimex(2) 的 POSIX 门面，能同时调 freq/offset/tick
```

### 「跳变」为什么是问题

`clock_settime()` 把时钟**直接设成新值**，于是：

| 受害对象 | 后果 |
|---------|------|
| 基于「绝对时刻」的定时器（`timer_settime` 用 `TIMER_ABSTIME`） | 可能**立刻触发**，也可能**永远不触发** |
| 单调性假设 | 时间戳出现「倒流」，日志按时间排序会乱 |
| 性能测量 | 测出来的耗时可能是负数 |
| 分布式系统 | 各节点的时间顺序（Lamport / 向量钟）被破坏 |

### `adjtime()` 的平滑机制：一条具体的源码证据

`adjtime(+1000us)` 想「往前拨 1000 µs」，但**不是立刻拨**，而是让内核在若干个 tick 里一点点加进去。

内核里的常数就在 `kernel/time/ntp.c:43`：

```c
#define MAX_TICKADJ		500LL		/* usecs */
```

以及它在 `second_overflow()` 里的用法（`:477`）：

```c
	if (time_adjust > MAX_TICKADJ) {
		time_adjust -= MAX_TICKADJ;
		tick_length += MAX_TICKADJ_SCALED;
	} else if (time_adjust < -MAX_TICKADJ) {
		...
```

也就是**每个 tick 最多补偿 500 µs**，对应到「每秒约 500 µs/s」这个经典数字：想补完 1000 µs 大约要 **2 秒**。

推论（很实用）：

| delta | 大致需要的时间 |
|-------|--------------|
| 1 ms | ~2 秒 |
| 128 ms | ~256 秒（≈ 4.3 分钟） |
| 1 s | ~2000 秒（≈ 33 分钟） |

所以 `adjtime()` **只适合微调**。偏差大到秒级时，要么忍受很长的收敛时间，要么明确接受一次 `clock_settime()` 跳变（运维上需要公告）。这正是 `ntpd` 早期「偏差 < 128 ms 用 slew，> 128 ms 用 step」那条业界约定的由来。

### `clock_adjtime()` 是 `adjtimex(2)` 的 POSIX 门面

| 对比 | `adjtime()` | `clock_adjtime()` |
|------|-------------|-------------------|
| 能调什么 | 只有「时间偏移」（且只能平滑） | **`freq` / `offset` / `tick` / `status` / `time`** 全都能调 |
| 参数 | 两个 `struct timeval` | 一个 `struct timex`（`include/uapi/linux/timex.h:65`） |
| 底层 | `ADJ_OFFSET_SINGLESHOT`（`:152`，注释 `old-fashioned adjtime`） | `__do_adjtimex()`（`kernel/time/ntp.c:762`） |
| 谁在用 | 老代码 | **chronyd / ntpd 的现代路径** |

Ch10 里本节的 demo 只演示「非特权下必然失败」和「只读能拿到什么」。真正的 `freq`/`offset` 调优属于时间同步子系统的范畴，Ch10 不展开。

> **一个并发细节**：`adjtime()` 是「单次」语义——新的 `adjtime()` 调用会**取消**上一次还没做完的调整，并把它剩下的量通过 `olddelta` 返回（`kernel/time/ntp.c:1011` 的注释 `/* cancel running adjtime() */`）。所以「用 `olddelta` 累积」这种做法是不存在的：你只会拿到「被取消时还剩多少」。

## HFT / 嵌入式关联

| 场景 | 结论 |
|------|------|
| **HFT 绝对不能跳变** | 所有校时走 `adjtime`/`clock_adjtime`，`clock_settime` 只在冷启动时用一次 |
| **PTP（IEEE 1588）** | 纳秒级同步，走的就是 `clock_adjtime` 那套（硬件打时间戳 + `freq`/`offset` 微调）。比 NTP 高 3 个数量级 |
| **chrony 优于 ntpd** | `chrony` 在虚拟化/间歇联网环境下收敛更快，也是现代发行版默认 |
| **只读探测成本极低** | `clock_adjtime(REALTIME, modes=0)` **不需要特权**，可以健康检查里定期读 `maxerror`——它一直涨就说明时间同步没工作 |
| **`STA_UNSYNC` 是告警信号** | 这一位（`0x0040`）为 1 表示时钟未同步。HFT 程序启动自检里应该查它 |
| **`tai = 37` 的意义** | 闰秒差是 37 秒，且**会变**（每次闰秒 +1）。如果你的系统需要严格的连续时间轴，用 `CLOCK_TAI` 而不是 `CLOCK_REALTIME`（见 [10.8](10.8-summary.md)） |
| **嵌入式无 RTC** | 上电后时钟从 0 或固定值起步，必须从 NTP/PTP 或者 RTC 芯片 `clock_settime` 设一次。**这一次跳变**要挑在系统启动早期（服务还没起来）做 |
| **容器环境** | 容器默认**没有** `CAP_SYS_TIME`（本 demo 实测就是），所以容器里的一切校时都只能靠宿主机或 `--cap-add=SYS_TIME` |
| **安全提醒** | 「能改时钟」等价于「能伪造日志时间戳 / 绕过证书有效期 / 破坏审计」。所以 `CAP_SYS_TIME` 是不该随手授予的高危 capability |

## 代码自测

<details>
<summary>1. 容器里 `uid=0`，为什么 `clock_settime` 仍然返回 EPERM？</summary>

因为权限判断走的是 **capability**，不是 uid。`uid=0` 只是身份；真正决定「能不能改时钟」的是**有效能力集**（`CapEff`）里的 `CAP_SYS_TIME` 位（位号 **25**）。

Docker 默认的 capability 白名单里**没有** `CAP_SYS_TIME`，所以即便进程 euid=0 也一样被拒。本 demo 实测 `CapEff 里 CAP_SYS_TIME(bit 25) = 0`，然后四条写接口全部 `errno=1 (EPERM)`。

这也解释了为什么：

| 现象 | 原因 |
|------|------|
| 宿主机上 `date -s` 能跑 | 宿主机的 root 有完整 capability 集 |
| 容器里同样的命令报 `Operation not permitted` | `CapEff` 被裁掉了 |
| `--privileged` 之后就能跑了 | `--privileged` 会放开（几乎）全部 capability |

**修法**：`docker run --cap-add=SYS_TIME`。但要先想清楚——给容器改时钟的权限，等于给它伪造任何时间戳的权限。

</details>

<details>
<summary>2. `adjtime(+1000us)` 想拨 1 毫秒，为什么要花约 2 秒？</summary>

因为 `adjtime()` 的设计是**平滑**（slew）而不是跳变。内核限制每次补偿的上限：

```c
/* kernel/time/ntp.c:43 */
#define MAX_TICKADJ		500LL		/* usecs */
```

每个 tick 最多补 500 µs，折算下来是「约 500 µs/秒」的速率。所以 1000 µs ÷ 500 µs/s ≈ **2 秒**。

这个设计的好处是时钟**单调**（不会倒退、不会跳），代价是**收敛慢**：

| 需要补的量 | 大致耗时 |
|-----------|---------|
| 1 ms | ~2 s |
| 128 ms | ~256 s（4.3 分钟） |
| 1 s | ~2000 s（33 分钟） |

所以时间同步守护进程通常有个「阈值」：小偏差用 slew（`adjtime`），大偏差才 step（`clock_settime`）。这正是「HFT 系统里 33 分钟的偏差修复窗口不可接受」的原因——真实部署必须让偏差一直保持在小量级。

</details>

<details>
<summary>3. `struct timex` 里的 `tick = 10000` 是什么意思？为什么不是 2⁻¹⁶ 定标的？</summary>

`tick` 是「**一个 tick 有多少微秒**」，`10000 µs = 10 ms`，因为它是按 `USER_HZ = 100` 算的：

```
tick_usec = USER_TICK_USEC
          = ((1000000UL + USER_HZ/2) / USER_HZ)     /* include/linux/jiffies.h:68 */
          = (1000000 + 50) / 100
          = 10000
```

三项证据：

| 步骤 | 位置 |
|------|------|
| `txc->tick = tick_usec;` | `kernel/time/ntp.c:816` |
| `tick_usec = USER_TICK_USEC;` | `kernel/time/ntp.c:34` |
| `struct timex` 里 `tick` 的注释是 `usecs between clock ticks` | `include/uapi/linux/timex.h:78` |

**不要和 `freq` 搞混**：`freq` 才是 2⁻¹⁶ 定标的（`scaled ppm`）——实测 `freq = -904454` 表示 `−904454/65536 ≈ −13.8 ppm`。`offset` / `esterror` / `maxerror` 都是**微秒**（除非 `STA_NANO` 为 1，那时 `offset` 变成纳秒）。

顺带注意 `USER_HZ` 又是那个写死的 100——**和容器的实际 `CONFIG_HZ=1000` 差 10 倍**。这个坑在 [10.6](10.6-the-software-clock-jiffies.md) 会正面撞上。

</details>

<details>
<summary>4. `gettimeofday(&tv, &tz)` 的 `tz` 参数被内核填了什么？为什么该传 NULL？</summary>

**内核不提供有意义的时区信息**。实测（先把整块 `memset` 成 `0xAA` 再调用）：

```text
  tz = { tz_minuteswest=0, tz_dsttime=0 }
  tz 仍是 0xAA 模式? 否   <- glibc 根本不填它
```

所以 glibc 是把它**清零**了，而不是填入真实时区。原因很简单——Linux 内核**没有时区概念**（[10.3](10.3-timezones.md)）：时区完全是用户态 glibc 读 `TZ` / `/etc/localtime` 得到的。

`settimeofday()` 的 `tz` 参数在内核里（`kernel/time/time.c:181-193`）也只是被校验范围（±15 小时）后存进一个几乎没人用的 `sys_tz`。这就是 POSIX 把它标记为 **obsolescent** 的原因。

**结论**：`gettimeofday` / `settimeofday` 的第二个参数一律传 `NULL`。要时区？用 `localtime()` + `tm_gmtoff`。

</details>

<details>
<summary>5. 怎么判断这台机器的时间同步在工作？</summary>

读 `struct timex`，看这三个字段（**只读，不需要特权**）：

| 字段 | 健康状态 | 本 demo 实测 |
|------|---------|-------------|
| `status` 的 `STA_UNSYNC`（`0x0040`） | 必须是 **0** | `status = 0x2000` → `STA_UNSYNC=0` ✔ 已同步 |
| `maxerror` | 应该稳定在小量级（µs~ms 级）；**持续线性增长**说明同步没工作 | `4976 us` |
| `esterror` | NTP 自报的估算误差，也是越小越好 | `2 us` |

再加上 `STA_NANO`（`0x2000`）判断 `offset` 的单位是 ns 还是 µs。

一段可用的健康检查：

```c
struct timex tx = { 0 };
if (clock_adjtime(CLOCK_REALTIME, &tx) >= 0) {
    if (tx.status & STA_UNSYNC)
        warn("clock not synchronized");
    if (tx.maxerror > 100000)          /* > 100 ms 视为异常 */
        warn("maxerror too large: %ld us", tx.maxerror);
}
```

注意 `clock_adjtime()` 的**返回值就是 `status`**（不是 0/1），实测 `-> 0`。所以判断成功要用 `>= 0`，而不是 `== 0`。

</details>
