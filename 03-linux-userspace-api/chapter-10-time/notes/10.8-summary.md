## 本章回顾：一条主线，三个维度

10.1 – 10.7 看似在讲七个不相干的主题，其实是**同一个问题的三个维度**：

| 维度 | 问题 | 涉及节 |
|------|------|--------|
| **读**（怎么拿时间） | 内核给了哪些时钟？各是什么语义？ | 10.1 / 10.2 / 10.3 / 10.4（怎么把它写成人看的）/ 10.6 / 10.8 |
| **写**（怎么改时间） | 谁能改、怎么改、跳变还是平滑 | 10.5 |
| **量**（这个进程花了多少） | CPU 时间与墙上时间是两套账 | 10.7 |

一条贯穿全章的主线是：

> **「时钟」不是一个东西，是十一个不同的东西。**
> 同一句 `clock_gettime(id, &ts)`，喂不同的 `id` 进去，拿到的是**语义完全不同**的数字 —— 有的是 Epoch 秒数、有的是开机以来的秒数、有的是 CPU 纳秒数、有的是 1 ms 粒度的缓存值。

本节用一个 demo 把这十一个时钟一次性摆齐。

## 0. 十一个 `CLOCK_*` 的实测全景

源码：[../code/c10_8_clockids.c](../code/c10_8_clockids.c)

```c
/* TLPI 第 10 章 §10.8（时钟全景）+ §10.6 补充
 * 把 Linux 上所有 CLOCK_* 摆在一起：数值 / 分辨率 / 当前读数 / 会不会失败
 *
 * 编译: gcc -O0 -Wall -Wextra -o c10_8_clockids c10_8_clockids.c
 * 运行: ./c10_8_clockids                        (无需参数、无需权限)
 *
 * 这张表是 §10.6 的收束：同一个 clock_gettime 接口，喂不同的 clockid
 * 拿到的是完全不同的东西 —— 墙上时间 / 单调时间 / CPU 时间 / 粗粒度缓存值。
 * 后面 §10.8 的选型表就是按这张实测表写的。
 */
#define _GNU_SOURCE
#include <errno.h>
#include <stdio.h>
#include <string.h>
#include <time.h>

static const struct {
    clockid_t id;
    const char *name;
    const char *kind;
} ids[] = {
    { CLOCK_REALTIME,             "CLOCK_REALTIME",             "墙上时间" },
    { CLOCK_MONOTONIC,            "CLOCK_MONOTONIC",            "单调" },
    { CLOCK_MONOTONIC_RAW,        "CLOCK_MONOTONIC_RAW",        "单调(不校正)" },
    { CLOCK_BOOTTIME,             "CLOCK_BOOTTIME",             "单调(含挂起)" },
    { CLOCK_REALTIME_COARSE,      "CLOCK_REALTIME_COARSE",      "粗粒度" },
    { CLOCK_MONOTONIC_COARSE,     "CLOCK_MONOTONIC_COARSE",     "粗粒度" },
    { CLOCK_PROCESS_CPUTIME_ID,   "CLOCK_PROCESS_CPUTIME_ID",   "进程 CPU" },
    { CLOCK_THREAD_CPUTIME_ID,    "CLOCK_THREAD_CPUTIME_ID",    "线程 CPU" },
    { CLOCK_REALTIME_ALARM,       "CLOCK_REALTIME_ALARM",       "闹钟" },
    { CLOCK_BOOTTIME_ALARM,       "CLOCK_BOOTTIME_ALARM",       "闹钟" },
    { CLOCK_TAI,                  "CLOCK_TAI",                  "国际原子时" },
};

static void one(clockid_t id, const char *name, const char *kind)
{
    struct timespec res, now;
    int rr, nr;

    errno = 0;
    rr = clock_getres(id, &res);
    errno = 0;
    nr = clock_gettime(id, &now);

    printf("  %-24s id=0x%08x  %-12s ", name, (unsigned) id, kind);

    if (rr == 0)
        printf("res=%9ld ns  ", (long) res.tv_sec * 1000000000L + res.tv_nsec);
    else
        printf("res=%-12s ", "ERR");

    if (nr == 0)
        printf("now=%12ld.%09ld\n", (long) now.tv_sec, (long) now.tv_nsec);
    else
        printf("now 失败 errno=%d (%s)\n", errno, strerror(errno));
}

int main(void)
{
    struct timespec rt, mono, raw, boot, tai;

    printf("== 1. 所有 CLOCK_* 逐个试 ==\n");
    for (size_t i = 0; i < sizeof ids / sizeof ids[0]; i++)
        one(ids[i].id, ids[i].name, ids[i].kind);
    printf("\n");

    printf("== 2. 把几个关键时钟放在一起比 ==\n");
    clock_gettime(CLOCK_REALTIME, &rt);
    clock_gettime(CLOCK_MONOTONIC, &mono);
    clock_gettime(CLOCK_MONOTONIC_RAW, &raw);
    clock_gettime(CLOCK_BOOTTIME, &boot);
    clock_gettime(CLOCK_TAI, &tai);

    printf("  REALTIME     = %ld.%09ld   Epoch 起算（可被 NTP 改）\n",
           (long) rt.tv_sec, (long) rt.tv_nsec);
    printf("  MONOTONIC    = %ld.%09ld   开机起算，被 NTP 用 slewing 慢慢拉\n",
           (long) mono.tv_sec, (long) mono.tv_nsec);
    printf("  MONOTONIC_RAW= %ld.%09ld   硬件时间源直接换算，NTP 完全碰不到\n",
           (long) raw.tv_sec, (long) raw.tv_nsec);
    printf("  BOOTTIME     = %ld.%09ld   比 MONOTONIC 多算挂起时间\n",
           (long) boot.tv_sec, (long) boot.tv_nsec);
    printf("  TAI          = %ld.%09ld   原子时\n", (long) tai.tv_sec, (long) tai.tv_nsec);
    printf("\n");
    printf("  RAW - MONO         = %+ld ns    ← NTP 累计 slew 掉的量\n",
           (long) ((raw.tv_sec - mono.tv_sec) * 1000000000L + (raw.tv_nsec - mono.tv_nsec)));
    printf("  BOOTTIME - MONO    = %+ld ns    ← 容器里没挂起过，所以是 0\n",
           (long) ((boot.tv_sec - mono.tv_sec) * 1000000000L + (boot.tv_nsec - mono.tv_nsec)));
    printf("  TAI - REALTIME     = %+ld ns    ← 闰秒补偿；内核没加载闰秒表时是 0\n",
           (long) ((tai.tv_sec - rt.tv_sec) * 1000000000L + (tai.tv_nsec - rt.tv_nsec)));
    printf("  REALTIME - MONO    = %+ld ns    ← 两个起点不同，这个差值没有意义\n",
           (long) ((rt.tv_sec - mono.tv_sec) * 1000000000L + (rt.tv_nsec - mono.tv_nsec)));
    printf("     （但它的**变化率**有意义：如果它突然变大/变小，说明 REALTIME 被调了）\n\n");

    printf("== 3. 两个 ALARM 时钟：读得到，但「定定时器」要额外能力 ==\n");
    {
        struct timespec ts;

        errno = 0;
        if (clock_gettime(CLOCK_REALTIME_ALARM, &ts) == 0)
            printf("  clock_gettime(CLOCK_REALTIME_ALARM) 成功 —— 读不需要特权\n");
        else
            printf("  clock_gettime(CLOCK_REALTIME_ALARM) 失败 errno=%d (%s)\n",
                   errno, strerror(errno));
        printf("  但用 timer_create() 挂到 ALARM 时钟上就需要 CAP_WAKE_ALARM，\n");
        printf("  目的只有一个：让系统从 suspend 里被唤醒（Ch23 会实测）。\n");
    }
    printf("\n");

    printf("== 4. 选型口径（§10.8 那张表的实测依据） ==\n");
    printf("  要人可读日期时间        -> CLOCK_REALTIME\n");
    printf("  要测间隔/延迟/超时      -> CLOCK_MONOTONIC（绝不用 REALTIME）\n");
    printf("  要基准测试、排除 NTP    -> CLOCK_MONOTONIC_RAW\n");
    printf("  高频打时间戳、容忍粗粒度-> CLOCK_MONOTONIC_COARSE（最便宜）\n");
    printf("  要算「这函数花了多少 CPU」-> CLOCK_PROCESS_CPUTIME_ID / THREAD\n");
    printf("  要含休眠时长            -> CLOCK_BOOTTIME\n");
    return 0;
}
```

### 读这张表的三条线索

**① `id` 值不是连续的，中间有两个空位。**

把表按 `id` 排一下：

| `id` | 时钟 | 备注 |
|------|------|------|
| `0` | `CLOCK_REALTIME` | |
| `1` | `CLOCK_MONOTONIC` | |
| `2` | `CLOCK_PROCESS_CPUTIME_ID` | 这两个是**负数编码**的前缀，POSIX 里被映射成正数 |
| `3` | `CLOCK_THREAD_CPUTIME_ID` | |
| `4` | `CLOCK_MONOTONIC_RAW` | Linux 扩展 |
| `5` | `CLOCK_REALTIME_COARSE` | Linux 扩展 |
| `6` | `CLOCK_MONOTONIC_COARSE` | Linux 扩展 |
| `7` | `CLOCK_BOOTTIME` | Linux 扩展 |
| `8` | `CLOCK_REALTIME_ALARM` | Linux 扩展，需 `CAP_WAKE_ALARM` 才能**设定时器** |
| `9` | `CLOCK_BOOTTIME_ALARM` | 同上 |
| — | *（没有 10）* | `CLOCK_TAI` 前留了一个空位 |
| `11` | `CLOCK_TAI` | Linux 扩展 |

定义在 `include/uapi/linux/time.h:49-64`：`CLOCK_REALTIME 0`（`:49`）、`CLOCK_MONOTONIC 1`（`:50`）、`CLOCK_REALTIME_COARSE 5`（`:54`）、`CLOCK_REALTIME_ALARM 8`（`:57`）、`CLOCK_BOOTTIME_ALARM 9`（`:58`）、`CLOCK_TAI 11`（`:64`）。

> **`id` 里那个空位（没有 10）不是笔误**：`10` 曾短暂分配给 `CLOCK_TAI` 的前身，后来改到 `11` 并保留空洞，避免和已经发布出去的 ABI 冲突。**内核 ABI 的编号一旦发出去就不能回收。**

**② 「分辨率」一列全是 `1 ns`，除了两个 COARSE。**

这一列就是 [10.6](10.6-the-software-clock-jiffies.md) 的结论复用：走 hrtimer 的报 `HIGH_RES_NSEC = 1`，走 jiffy 的报 `TICK_NSEC = 1/CONFIG_HZ = 1000000`。

**③ `now` 一列里的数字量级差了几十个数量级，这不是 bug。**

| 时钟 | `now` 量级 | 起点 |
|------|-----------|------|
| `CLOCK_REALTIME` / `TAI` | `1789371108`（≈ 1.79e9） | Epoch（1970-01-01） |
| `CLOCK_MONOTONIC*` / `BOOTTIME` | `4038`（≈ 4e3） | **开机时刻**（本容器开机约 67 分钟） |
| `CLOCK_*_CPUTIME_ID` | `0.00049`（≈ 5e-4） | **进程/线程启动时刻** |

**三个不同量级 = 三个不同起点。** 这也是为什么**绝对不能把两个不同时钟的读数相减**（见下一节）。

## 1. 让几个时钟互相「对账」

```text
== 2. 把几个关键时钟放在一起比 ==
  REALTIME     = 1789371108.831768747   Epoch 起算（可被 NTP 改）
  MONOTONIC    = 4038.158705009   开机起算，被 NTP 用 slewing 慢慢拉
  MONOTONIC_RAW= 4038.126118820   硬件时间源直接换算，NTP 完全碰不到
  BOOTTIME     = 4038.158705077   比 MONOTONIC 多算挂起时间
  TAI          = 1789371145.831768881   原子时

  RAW - MONO         = -32586189 ns    ← NTP 累计 slew 掉的量
  BOOTTIME - MONO    = +68 ns    ← 容器里没挂起过，所以是 0
  TAI - REALTIME     = +37000000134 ns    ← 闰秒补偿；内核没加载闰秒表时是 0
  REALTIME - MONO    = +1789367070673063738 ns    ← 两个起点不同，这个差值没有意义
```

四个差值，四种含义：

| 差值 | 实测量 | 有没有意义 | 说明 |
|------|--------|-----------|------|
| `RAW − MONO` | `−32.586189 ms` | ✅ **很有意义** | `MONOTONIC_RAW` 完全不校正，`MONOTONIC` 会被 NTP 用 slewing 慢慢拉 → 差值就是**累计被校正掉的量**。这是检验「NTP 正在工作」的直接证据 |
| `BOOTTIME − MONO` | `+68 ns` | ✅ 有意义 | `BOOTTIME` 会额外累加 suspend 期间的时间。容器里从没挂起过 → 差值≈0。**在笔记本上挂起一次再跑，这个差值就会变成几分钟** |
| `TAI − REALTIME` | `+37.000000134 s` | ✅ 很有意义 | 就是**闰秒差**（TAI − UTC = 37 s）。`+134 ns` 是两次读取的时间差。内核没加载闰秒表时这个差值会变成 0 |
| `REALTIME − MONO` | `1.789e18 ns` | ❌ **没有意义** | 两个时钟起点不同，相减只是「两个绝对值之差」，不含任何信息 |

### 但 `REALTIME − MONO` 的**变化率**有意义

demo 在输出里专门注了一句：

```text
     （但它的**变化率**有意义：如果它突然变大/变小，说明 REALTIME 被调了）
```

这是一个非常实用的**时间跳变探测器**：

```c
/* 记录基线，之后定期比较 */
static struct timespec base;
static time_t base_diff;

/* 首次调用：记下 REALTIME - MONOTONIC */
clock_gettime(CLOCK_REALTIME, &rt);
clock_gettime(CLOCK_MONOTONIC, &mo);
base_diff = rt.tv_sec - mo.tv_sec;

/* 之后每次都检查：差值应该以「每秒≈1 秒」的速率缓慢变化 */
...
if (labs(now_diff - base_diff) > 1)
    warn("CLOCK_REALTIME was stepped by %ld s", now_diff - base_diff);
```

| 现象 | 结论 |
|------|------|
| 差值**缓慢**变化（几 ppm 量级） | 正常的 NTP slewing（[10.5](10.5-updating-the-system-clock.md) 的平滑校时） |
| 差值**瞬间跳变** | 有人执行了 `clock_settime()` —— HFT 里这是**事故信号**，因为所有基于绝对时刻的定时器都可能失效 |

> **这是 §10.5 讲「跳变是问题」之后，本节给出的「怎么检测跳变」的答案。** 三行代码就能做一个生产级的时钟监控。

## 2. 两个 ALARM 时钟：读得到，但用起来要能力

```text
== 3. 两个 ALARM 时钟：读得到，但「定定时器」要额外能力 ==
  clock_gettime(CLOCK_REALTIME_ALARM) 成功 —— 读不需要特权
```

`CLOCK_REALTIME_ALARM` / `CLOCK_BOOTTIME_ALARM` 与普通版本**唯一**的区别是：

| 用途 | 权限要求 |
|------|---------|
| `clock_gettime(CLOCK_REALTIME_ALARM, ...)` | **无需特权**（实测成功） |
| `timer_create(CLOCK_REALTIME_ALARM, ...)` | 需要 **`CAP_WAKE_ALARM`** |

它们存在的唯一目的：**让系统从 suspend（挂起）状态被唤醒**。普通定时器在系统挂起时不会触发（因为 CPU 停了），ALARM 定时器会去配置 RTC，让 RTC 在到点时把机器叫醒。

> 这个能力之所以要单独限制，是因为「能让机器从休眠中醒来」= 「能持续耗电」。恶意程序拿到它就能让笔记本永远不进低功耗状态（电池耗尽）。Ch23 会实测。

## 3. 选型总表（每一行都有实测支撑）

| 你要做什么 | 用哪个时钟 | 实测依据 |
|-----------|-----------|---------|
| 给日志/消息打**人可读**时间戳 | `CLOCK_REALTIME` | §10.1 三种读法同秒 |
| 测**延迟 / 超时 / 间隔** | `CLOCK_MONOTONIC` | §10.8 `RAW−MONO` 证明 REALTIME 会被校时动 |
| **基准测试**，要排除 NTP 干扰 | `CLOCK_MONOTONIC_RAW` | 同上，`−32.6 ms` 的累计校正量 |
| **高频**打时间戳，1 ms 粒度够用 | `CLOCK_MONOTONIC_COARSE` | §10.6 `4.9 ns/call` vs `18.9 ns/call` |
| 算**这段代码花了多少 CPU** | `CLOCK_PROCESS_CPUTIME_ID` | §10.7 实测与 `clock()` 完全一致 |
| 算**某个线程**花了多少 CPU | `CLOCK_THREAD_CPUTIME_ID` | §10.7 单线程下两者相差 918 ns |
| 要含**系统休眠**的时长 | `CLOCK_BOOTTIME` | §10.8 `BOOTTIME−MONO = +68 ns` |
| 要**不受闰秒**影响的连续时间轴 | `CLOCK_TAI` | §10.8 `TAI−REALTIME = +37 s` |
| 定时唤醒机器 | `CLOCK_*_ALARM` + `CAP_WAKE_ALARM` | §10.8 第 3 段 |
| 要 **user / sys 拆分** | `times()` / `getrusage()` | §10.7 `utime` / `stime` 分列 |
| 要**缺页/上下文切换/IO** 计数 | `getrusage()` | §10.7 §5 字段表 |
| **跨进程 / 跨机器**可比的时间 | `CLOCK_REALTIME`（配 PTP）或 `CLOCK_TAI` | — |

## 4. 本章 API 全表

### 4.1 取时间

| 函数 | 精度 | 头文件 | 备注 |
|------|------|--------|------|
| `time(&t)` | 秒 | `<time.h>` | vDSO，实测 `2.9 ns/call` |
| `gettimeofday(&tv, NULL)` | μs | `<sys/time.h>` | **废弃**；第二个参数永远传 `NULL` |
| `clock_gettime(id, &ts)` | ns | `<time.h>` | 推荐；`-lrt` 在 glibc 2.17+ 不再需要 |
| `times(&tms)` | 1/USER_HZ | `<sys/times.h>` | 返回值是**开机 tick 数** |
| `clock()` | 1/`CLOCKS_PER_SEC` | `<time.h>` | Linux 上 = `CLOCK_PROCESS_CPUTIME_ID` |
| `getrusage(who, &ru)` | μs | `<sys/resource.h>` | 附带缺页/切换/IO |
| `gettimeofday()` 的 `tz` | — | — | **废弃，永远传 NULL** |

### 4.2 分解 / 格式化

| 函数 | 方向 | 备注 |
|------|------|------|
| `gmtime()` / `localtime()` | `time_t` → `struct tm` | **共用静态缓冲区**，用 `_r` 版 |
| `mktime()` | `struct tm` → `time_t`（本地时区） | 会**顺带规范化** `tm` 字段 |
| `timegm()` | `struct tm` → `time_t`（UTC） | Linux/GNU 扩展 |
| `asctime()` / `ctime()` | → 字符串 | 共用静态缓冲区，末尾带 `\n` |
| `strftime()` | `struct tm` → 格式化字符串 | 失败**只返回 0**，缓冲区内容未定义 |
| `strptime()` | 字符串 → `struct tm` | 不设 `tm_isdst`（保持 -1） |

### 4.3 改时间 / 校时

| 函数 | 行为 | 权限 |
|------|------|------|
| `settimeofday()` | 跳变 | `CAP_SYS_TIME` |
| `clock_settime(CLOCK_REALTIME, ...)` | 跳变 | `CAP_SYS_TIME` |
| `adjtime()` | 平滑，每秒约 500 µs | `CAP_SYS_TIME` |
| `clock_adjtime()` | 调 freq/offset/tick/status | 写要 `CAP_SYS_TIME`，**读不要** |

### 4.4 时区 / locale

| 函数 / 变量 | 作用 |
|------------|------|
| `tzset()` | 重读 `TZ` / `/etc/localtime`，刷新下面三个 |
| `tzname[0]` / `tzname[1]` | 标准时 / 夏令时的名字 |
| `timezone` | 本地时区相对 UTC 的偏移（秒，**UTC 以西为正**） |
| `daylight` | 该时区是否有 DST |
| `tm_gmtoff` / `tm_zone` | `struct tm` 里的扩展字段，**取偏移的正确位置** |
| `setlocale(LC_ALL, "")` | 按环境变量初始化 locale（不调就永远是 `"C"`） |
| `nl_langinfo()` | 取 locale 里的格式串（`D_T_FMT` / `RADIXCHAR`…） |

## 5. 时间类型与精度对照

| 类型 | 字段 | 单位 | 谁在用 |
|------|------|------|--------|
| `time_t` | 单个整数 | 秒 | `time()` / `mktime()` |
| `struct timeval` | `tv_sec` + `tv_usec` | μs | `gettimeofday()` / `select()` |
| `struct timespec` | `tv_sec` + `tv_nsec` | ns | `clock_gettime()` / `nanosleep()` / `pselect()` |
| `struct tm` | 9 + 2 个字段 | 各字段单位不同 | `localtime()` 等 |
| `clock_t` | 单个整数 | **不固定**（见下） | `clock()` / `times()` |
| `struct tms` | 4 个 `clock_t` | `1/USER_HZ` | `times()` |

### `clock_t` 是最容易搞错的类型

| 事实 | 实测 / 出处 |
|------|------------|
| 本机 `sizeof(clock_t) = 8` | §10.7 实测 |
| `times()` 里单位是 `1/USER_HZ`（= 10 ms） | `sysconf(_SC_CLK_TCK) = 100` |
| `clock()` 里单位是 `1/CLOCKS_PER_SEC`（= 1 µs） | `CLOCKS_PER_SEC = 1000000` |
| **同一个类型，两个函数两个单位** | 见 [10.7 §0](10.7-process-time.md) |

所以 `clock_t` 这个类型名是**误导性的**：它本身不带单位，单位由**调用它的函数**决定。

## HFT / 嵌入式关联（本章收束）

| 主题 | 结论 |
|------|------|
| **打时间戳** | `CLOCK_MONOTONIC`（19 ns）→ 量大就用 `COARSE`（4.9 ns）→ 极致就用 `rdtsc`（10.5 ns）+ 硬件时间戳 |
| **绝不用 `CLOCK_REALTIME` 测间隔** | 它会被 `clock_settime` 跳变、被 NTP slew。用 §10.8 的 `REALTIME − MONOTONIC` 差值监控跳变 |
| **校时策略** | 冷启动 `clock_settime` 一次；之后一律 `adjtime` / `clock_adjtime`（每秒 ~500 µs 收敛） |
| **闰秒** | 需要连续时间轴就用 `CLOCK_TAI`；依赖 UTC 就提前处理闰秒表 |
| **CPU 时间** | 用 `CLOCK_THREAD_CPUTIME_ID`（线程钉核后最干净）；`ru_nivcsw` / `ru_minflt` 是抖动诊断核心指标 |
| **locale 陷阱** | HFT 程序启动后**只设 `LC_TIME`**，`LC_NUMERIC` 必须保持 `"C"`，否则 `printf("%f")` 的小数点会变成 `,`（见 [10.4](10.4-locales.md)） |
| **时区** | 服务器一律 `TZ=UTC`（或用 `CLOCK_TAI`），跨时区日志才有可比性；偏移**永远从 `tm_gmtoff` 取**，不硬编码 |
| **容器** | 默认**没有** `CAP_SYS_TIME`；`CLOCK_BOOTTIME` 在容器里等于 `MONOTONIC`（宿主机的 suspend 容器看不到） |
| **嵌入式（ARM）** | `CNTVCT_EL0` 等价 TSC；`CNTFRQ_EL0` 常是假值需校正。无 RTC 的板子上 `CLOCK_REALTIME` 上电即为垃圾数据 |
| **`CONFIG_HZ`** | 现代内核它**不再限制定时器精度**（hrtimer 接管），只影响 COARSE 时钟与 `USER_HZ` 统计接口 |

## 代码自测

<details>
<summary>1. 为什么 `REALTIME − MONOTONIC` 的绝对值没有意义，但它的变化率很有意义？</summary>

**绝对值没有意义**：两个时钟**起点不同**。

| 时钟 | 起点 | 实测读数 |
|------|------|---------|
| `CLOCK_REALTIME` | Epoch（1970-01-01 UTC） | `1789371108.831...` |
| `CLOCK_MONOTONIC` | **未定义**（通常开机） | `4038.158...` |

相减得到 `1789367070673063738 ns` —— 这个数字只说明「系统从 1970 年到开机之间过了大约 56.7 年」，**和任何延迟/性能都无关**。

**变化率有意义**：`REALTIME` 和 `MONOTONIC` 都以「每秒 1 秒」的速率前进，所以它们之差的**变化**只能来自两件事：

| 变化来源 | 速率 | 检测方法 |
|---------|------|---------|
| NTP slewing（正常） | 几 ppm，即每秒差几十 ns | `RAW − MONO` 那种量级的缓慢变化 |
| `clock_settime()` 跳变（事故） | **瞬间几十毫秒到几秒** | 差值突然变化 > 1 秒 |

所以一段「时钟跳变监控」只要三行判断：

```c
long diff = rt.tv_sec - mo.tv_sec;
if (labs(diff - base_diff) > 1)
    warn("CLOCK_REALTIME stepped by %ld s", diff - base_diff);
```

**为什么这在 HFT 里重要**：`clock_settime()` 会让所有 `TIMER_ABSTIME` 定时器行为不可预测（可能立刻触发、可能永远不触发），也会让日志时间戳倒流。有一个独立监控能第一时间发现「有人动了时钟」。

</details>

<details>
<summary>2. `CLOCK_TAI − CLOCK_REALTIME = 37 s` 是什么意思？该用哪个？</summary>

**37 秒是 TAI 与 UTC 之间的闰秒累计差**（截至写这段代码时）。

| 时间标准 | 定义 | 是否插入闰秒 |
|---------|------|-------------|
| **TAI**（国际原子时） | 纯原子钟，**均匀流逝** | ❌ 不插 |
| **UTC** | TAI 减掉闰秒，贴近地球自转 | ✅ 插（所以 UTC 有 23:59:60） |
| **`CLOCK_REALTIME`** | 近似 UTC 的**日历时间** | ✅ 会受闰秒影响 |
| **`CLOCK_TAI`** | 内核维护的原子时 | ❌ 不受影响 |

实测：

```text
  TAI - REALTIME     = +37000000134 ns    ← 闰秒补偿；内核没加载闰秒表时是 0
```

`+37 s` 是闰秒差，后面 `134 ns` 是两次读取之间的间隔。

**该用哪个**：

| 需求 | 用 |
|------|-----|
| 日志要人看得懂的日期时间 | `CLOCK_REALTIME` |
| 要**严格单调、均匀流逝**的绝对时间轴（金融交易时间戳、审计） | `CLOCK_TAI` |
| 只是测间隔 | `CLOCK_MONOTONIC`（根本不需要绝对时间） |

**注意两个坑**：

1. **`CLOCK_TAI` 在闰秒表没加载时等于 `CLOCK_REALTIME`**——内核对它需要一份闰秒表（`adjtimex` 的 `ADJ_STATUS` + `STA_INS`），通常由 NTP 守护进程灌进去。所以 `TAI−REALTIME = 0` 不代表「闰秒差是 0」，而代表「这台机器还不知道闰秒」。
2. **不要自己加减 37**：闰秒差是**会变**的（历史上每 1~2 年可能 +1）。硬编码 37 的代码在未来会静默错 1 秒。

</details>

<details>
<summary>3. 十一个 `CLOCK_*` 里，哪几个是 POSIX 标准，哪几个是 Linux 扩展？</summary>

| 时钟 | 标准 | 引入 |
|------|------|------|
| `CLOCK_REALTIME` | ✅ **POSIX.1-2001** | 最早 |
| `CLOCK_MONOTONIC` | ✅ **POSIX.1-2001** | 最早 |
| `CLOCK_PROCESS_CPUTIME_ID` | ✅ POSIX（`clock_getcpuclockid()`） | 最早 |
| `CLOCK_THREAD_CPUTIME_ID` | ✅ POSIX | 最早 |
| `CLOCK_MONOTONIC_RAW` | ❌ **Linux 扩展** | 2.6.28 |
| `CLOCK_REALTIME_COARSE` | ❌ Linux 扩展 | 2.6.32 |
| `CLOCK_MONOTONIC_COARSE` | ❌ Linux 扩展 | 2.6.32 |
| `CLOCK_BOOTTIME` | ❌ Linux 扩展 | 2.6.39 |
| `CLOCK_REALTIME_ALARM` | ❌ Linux 扩展 | 3.0 |
| `CLOCK_BOOTTIME_ALARM` | ❌ Linux 扩展 | 3.3 |
| `CLOCK_TAI` | ❌ Linux 扩展 | 3.10 |

**四个标准 + 七个扩展。**

**移植性上的实际影响**：

| 用到了 | 后果 |
|-------|------|
| `CLOCK_MONOTONIC` / `CLOCK_REALTIME` / `*_CPUTIME_ID` | 到处能编译（macOS / BSD 都有） |
| `*_COARSE` | macOS 没有 → 需要 `#ifdef CLOCK_MONOTONIC_COARSE`；性能优化要有 `CLOCK_MONOTONIC` 兜底 |
| `CLOCK_BOOTTIME` | macOS 没有 → 用 `mach_absolute_time()` 或 `CLOCK_MONOTONIC` 兜底 |
| `CLOCK_TAI` / `*_ALARM` | 基本只有 Linux 有 |

所以 HFT 代码里常见的写法是：

```c
#ifdef CLOCK_MONOTONIC_COARSE
#  define FAST_CLOCK CLOCK_MONOTONIC_COARSE
#else
#  define FAST_CLOCK CLOCK_MONOTONIC
#endif
```

**注意 `CLOCK_MONOTONIC_RAW` 的坑**：它**完全不受 NTP 校正**，所以：

- 测**短期**延迟 → ✅ 更好（不受 NTP 抖动影响）；
- 测**长期**间隔（几分钟以上）→ ❌ 它的速率可能和真实时间有偏差（因为没被校正），会累积误差。

这也是 §10.8 里 `RAW − MONO = −32.6 ms` 的含义：本机的 NTP 已经累计把 `MONOTONIC` 拉慢了 32.6 ms。

</details>

<details>
<summary>4. 本章哪个"书上的结论"已经被现代内核推翻了？还有哪些需要打折扣？</summary>

| 原书说法（2010，2.6 内核） | 今天（v6.6）的实测 | 状态 |
|--------------------------|-------------------|------|
| 「`CLOCK_REALTIME` / `CLOCK_MONOTONIC` 的分辨率 = 1/HZ」 | 实测 **1 ns**；只有 `*_COARSE` 还是 1/HZ | ❌ **已变**（前提变了：hrtimer 成为默认） |
| 「软件时钟粒度限制一切定时器」 | 只有 jiffies 路径受限；`nanosleep` / `timer_settime` 走 hrtimer | ❌ **已变**（`ex10_3` 请求 1 µs 能醒来） |
| 「`gettimeofday` 已废弃」 | 仍成立 | ✅ 成立 |
| 「`settimeofday` 的 `tz` 参数废弃」 | 仍成立（内核仍只是存进没人用的 `sys_tz`） | ✅ 成立 |
| 「`HZ` 是 250 或 1000，影响定时器精度」 | Kconfig 默认仍是 `HZ_250`，但**定时器精度不再由它决定** | ⚠️ **要打折扣** |
| 「`sysconf(_SC_CLK_TCK)` 就是 HZ」 | 恒为 **100**（`USER_HZ`），与实际 `CONFIG_HZ=1000` 差 10 倍 | ❌ **书没这么说，但流传很广；实测证伪** |
| 「`clock()` 是 `times()` 的便捷版」 | Linux 上 glibc 的 `clock()` 走 `CLOCK_PROCESS_CPUTIME_ID`，**根本不调 `times()`** | ⚠️ **要打折扣** |
| 「`CLOCK_PROCESS_CPUTIME_ID` 分辨率是 1/HZ」 | 实测 **1 ns**（`CPUCLOCK_SCHED` 分支把 `tv_nsec` 改写成 1） | ⚠️ 要打折扣 |

**贯穿全章的方法论**：原书讲的是**机制**，机制没变；变的是**默认配置**和**实现路径**。所以：

> **读机制 → 查源码确认当前实现 → 用实测验证行为。三步都不能省。**

这一章十四篇笔记（含本节）里，**有 6 处「书上的数值/说法」被实测修正**——这就是「对着源码 + 实测读」的价值。
</details>
