## 本章回顾

### 时间 API 速查

| 类别 | API | 精度 | 说明 |
|------|-----|------|------|
| 获取墙上时间 | `time(NULL)` | 秒 | 简单但不精确 |
| 获取墙上时间 | `gettimeofday(&tv, NULL)` | 微秒 | 已废弃，用 clock_gettime 替代 |
| 获取墙上时间 | `clock_gettime(CLOCK_REALTIME, &ts)` | 纳秒 | 推荐 |
| 获取单调时间 | `clock_gettime(CLOCK_MONOTONIC, &ts)` | 纳秒 | 不受 NTP 跳变，测量间隔首选 |
| 快速单调时间 | `clock_gettime(CLOCK_MONOTONIC_COARSE, &ts)` | jiffies | 低开销，适合频繁调用 |
| 设置时钟 | `clock_settime(CLOCK_REALTIME, &ts)` | 纳秒 | 需 CAP_SYS_TIME |
| 微调时钟 | `adjtime(&delta, NULL)` | 微秒 | NTP 平滑校正 |
| 查询分辨率 | `clock_getres(clk, &res)` | — | 查看时钟精度 |
| 时间格式化 | `ctime()` / `strftime()` | — | 人可读格式 |
| 时间分解 | `localtime()` / `gmtime()` | — | tm 结构 |
| 进程时间 | `times(&buf)` | 时钟滴答 | 用户/系统 CPU 时间 |
| 进程时间 | `clock()` | 时钟滴答 | 精度低（CLOCKS_PER_SEC） |

### 时间类型

| 类型 | 说明 |
|------|------|
| `time_t` | 秒数（自 1970-01-01 UTC） |
| `struct timeval` | `{tv_sec, tv_usec}` 微秒精度 |
| `struct timespec` | `{tv_sec, tv_nsec}` 纳秒精度 |
| `struct tm` | 分解时间 {年月日时分秒} |
| `clockid_t` | 时钟标识（CLOCK_REALTIME / CLOCK_MONOTONIC 等） |

### 时钟 ID 对比

| clockid | 是否单调 | 是否受 NTP 调整 | 精度 | 适用场景 |
|---------|---------|----------------|------|---------|
| `CLOCK_REALTIME` | 否 | 是 | 纳秒 | 当前日期时间 |
| `CLOCK_MONOTONIC` | 是 | 受平滑调整 | 纳秒 | 测量间隔 |
| `CLOCK_MONOTONIC_RAW` | 是 | 否 | 硬件精度 | 基准测试 |
| `CLOCK_MONOTONIC_COARSE` | 是 | 受平滑调整 | jiffies | 高频低精度 |
| `CLOCK_REALTIME_COARSE` | 否 | 是 | jiffies | 高频低精度 |
| `CLOCK_BOOTTIME` | 是 | — | 纳秒 | 包含挂起时间 |
| `CLOCK_PROCESS_CPUTIME_ID` | — | — | 纳秒 | 本进程 CPU 时间 |
| `CLOCK_THREAD_CPUTIME_ID` | — | — | 纳秒 | 本线程 CPU 时间 |

### 时间格式化 API

| 函数 | 原型 | 说明 |
|------|------|------|
| `ctime(&t)` | `char *ctime(const time_t *t)` | "Wed Aug 12 19:00:00 2026\n" |
| `gmtime(&t)` | `struct tm *gmtime(const time_t *t)` | UTC 分解时间 |
| `localtime(&t)` | `struct tm *localtime(const time_t *t)` | 本地时区分解时间 |

| `strftime(buf, n, fmt, &tm)` | `size_t strftime(...)` | 自定义格式 |

## HFT / 嵌入式关联

- **时间戳**：HFT 所有日志和消息必须带纳秒时间戳，用 `CLOCK_MONOTONIC`
- **延迟测量**：`clock_gettime(CLOCK_MONOTONIC, &before); ...; clock_gettime(CLOCK_MONOTONIC, &after)`
- **TSC**：x86 上直接用 `rdtsc` 指令，避免系统调用开销
- **PTP**：纳秒级时钟同步（IEEE 1588），比 NTP 精确 3 个数量级
- **嵌入式**：ARM 上用 Generic Timer（`CNTVCT_EL0`）替代 `rdtsc`
- **避免 jiffies**：所有热路径使用 hrtimer 支持的时钟

## 代码自测

<details>
<summary>1. CLOCK_REALTIME 和 CLOCK_MONOTONIC 的区别？HFT 应该用哪个？</summary>

- `CLOCK_REALTIME`：墙上时钟，表示实际日期时间，受 NTP/管理员修改，可能跳变
- `CLOCK_MONOTONIC`：单调时钟，从某个未定义起点递增，不受 settimeofday 影响，但受 NTP 平滑调整

**HFT 应用**：
- 测量间隔、延迟 → `CLOCK_MONOTONIC`（必须）
- 时间戳日志（需人可读日期） → `CLOCK_REALTIME`
- 最好同时记录两者：REALTIME 用于人可读时间，MONOTONIC 用于间隔计算
</details>

<details>
<summary>2. 为什么 gettimeofday 被废弃？</summary>

1. `clock_gettime` 提供纳秒精度（`timespec`），而 `gettimeofday` 只有微秒（`timeval`）
2. `gettimeofday` 的 timezone 参数无意义
3. POSIX.1-2008 标记为废弃
4. `clock_gettime` 支持多种时钟（MONOTONIC 等），更灵活
5. 现代 glibc 中 `gettimeofday` 内部调用 `clock_gettime`，但接口不够好
</details>

<details>
<summary>3. 如何测量一段代码的纳秒级执行时间？</summary>

```c
struct timespec start, end;
clock_gettime(CLOCK_MONOTONIC, &start);
/* 待测代码 */
clock_gettime(CLOCK_MONOTONIC, &end);
long long ns = (end.tv_sec - start.tv_sec) * 1000000000LL
              + (end.tv_nsec - start.tv_nsec);
printf("耗时: %lld ns\n", ns);
```

如果需要更低开销，用 x86 的 `rdtsc` 指令直接读 TSC，配合 CPU 频率换算。
</details>
