## 本节讲什么

[10.1](10.1-calendar-time.md) 把时间读成了一个 `time_t`（一串秒数）。本节解决「**从秒数到人**」的整条链条。

| 步骤 | 函数 | 输入 → 输出 |
|------|------|-------------|
| ① 秒数 → 分解时间（UTC） | `gmtime()` / `gmtime_r()` | `time_t` → `struct tm` |
| ② 秒数 → 分解时间（本地） | `localtime()` / `localtime_r()` | `time_t` → `struct tm` |
| ③ 分解时间 → 秒数 | `mktime()` / `timegm()` | `struct tm` → `time_t` |
| ④ 分解时间 → 字符串 | `asctime()` / `strftime()` | `struct tm` → `char[]` |
| ⑤ 秒数 → 字符串（一步到位） | `ctime()` | `time_t` → `char[]` |
| ⑥ 字符串 → 分解时间（反向） | `strptime()` | `char[]` → `struct tm` |

`ctime()` 内部**就是** `localtime()` + `asctime()`；`asctime()` 内部就是按 `%a %b %e %H:%M:%S %Y` 调 `strftime()`（等价，不是同一次调用）。记住这条链，可重入性一节就自然懂了。

| 本节的 demo | 演示什么 |
|-------------|----------|
| `c10_2_strftime.c` | `struct tm` 字段语义 + **38 个格式符全表** + 往返回 |
| `c10_2_reentrant.c` | 四个函数共用静态缓冲区，现场抓地址看覆盖 |
| `c10_2_curr_time_demo.c` + `curr_time.c` | 原书 **Listing 10-2**（p.194）的 `currTime()`，并验证它的 `static` 缓冲区 |
| `strtime.c` | 原书 **Listing 10-3**（p.197），`strptime` 的主线 |
| `show_time.c` | 原书 **Listing 10-4**（p.199），`ctime` / `asctime` / `strftime` 三连 |

## 1. `struct tm` 的字段没有一个是「直觉值」

### 代码示例 A

源码：[../code/c10_2_strftime.c](../code/c10_2_strftime.c)

```c
/* TLPI 第 10 章 §10.2 Time-Conversion Functions
 * strftime() 格式符全表 + struct tm 字段语义 + 往返回
 *
 * 编译: gcc -O0 -Wall -Wextra -o c10_2_strftime c10_2_strftime.c
 * 运行: ./c10_2_strftime                    (无需参数、无需权限)
 *
 * ⚠️ 本 demo 故意用**固定时间戳** 1700000000（= 2023-11-14 22:13:20 UTC），
 *    不用 time(NULL)。这样笔记里的实测输出才能逐字复现、不随运行时刻漂移。
 *    （这是本仓库写「会被抄进笔记的输出」的统一约定。）
 *
 * 三个必须现场看到的点：
 *   1. struct tm 的 tm_year 是「年 - 1900」、tm_mon 是 0..11 —— 字符串里看到的
 *      年份不是字段里的数值；
 *   2. 同一时间戳喂给 gmtime() 与 localtime()，得到两个 struct tm；
 *   3. %s 不是 C 标准（C99 没有它），是 POSIX/glibc 扩展 —— 用 gcc -std=c99
 *      加 -pedantic 会告警，但这里不告警是因为默认是 gnu 模式。
 */
#define _GNU_SOURCE
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <time.h>

#define FIXED_EPOCH 1700000000L

/* 把不可见字符转义后再打印，否则 %n / %t 会把输出表格冲乱 */
static void esc(const char *s, char *out, size_t n)
{
    size_t j = 0;

    for (size_t i = 0; s[i] != '\0' && j + 2 < n; i++) {
        if (s[i] == '\n')      { out[j++] = '\\'; out[j++] = 'n'; }
        else if (s[i] == '\t') { out[j++] = '\\'; out[j++] = 't'; }
        else                   { out[j++] = s[i]; }
    }
    out[j] = '\0';
}

static void show_struct_tm(void)
{
    time_t t = (time_t) FIXED_EPOCH;
    struct tm g;

    gmtime_r(&t, &g);
    printf("== 1. struct tm 的字段就是内核/库给你的原始数值 ==\n");
    printf("tm_sec   = %2d      tm_min  = %2d      tm_hour = %2d\n",
           g.tm_sec, g.tm_min, g.tm_hour);
    printf("tm_mday  = %2d      tm_mon  = %2d   <- 0..11，不是 1..12\n",
           g.tm_mday, g.tm_mon);
    printf("tm_year  = %2d   <- 年 - 1900，所以真实年份 = %d\n",
           g.tm_year, g.tm_year + 1900);
    printf("tm_wday  = %2d   <- 0=Sunday\n", g.tm_wday);
    printf("tm_yday  = %2d   <- 0..365，不是 1..366\n", g.tm_yday);
    printf("tm_isdst = %2d   <- gmtime 恒为 0\n\n", g.tm_isdst);
}

static void show_formats(void)
{
    static const char *fmts[] = {
        "%a", "%A", "%b", "%B", "%c", "%C", "%d", "%D", "%e", "%F",
        "%g", "%G", "%h", "%H", "%I", "%j", "%m", "%M", "%n", "%p",
        "%r", "%R", "%s", "%S", "%t", "%T", "%u", "%U", "%V", "%w",
        "%W", "%x", "%X", "%y", "%Y", "%z", "%Z", "%%", NULL
    };
    time_t t = (time_t) FIXED_EPOCH;
    struct tm g;

    gmtime_r(&t, &g);
    printf("== 2. strftime 格式符全表（固定时间戳 1700000000，用 gmtime） ==\n");
    for (int i = 0; fmts[i] != NULL; i++) {
        char buf[200], e[210];
        size_t n = strftime(buf, sizeof buf, fmts[i], &g);
        esc(buf, e, sizeof e);
        printf("  %-4s -> \"%s\"%s\n", fmts[i], e, (n == 0) ? "   <-- 返回 0！" : "");
    }
    printf("\n");
}

static void show_gm_vs_local(void)
{
    time_t t = (time_t) FIXED_EPOCH;
    struct tm g, l;
    char bg[80], bl[80];

    gmtime_r(&t, &g);
    localtime_r(&t, &l);
    /* %Z 在 gmtime 下由 glibc 填 "GMT"；localtime 下取 tzname[] */
    strftime(bg, sizeof bg, "%F %T %Z (%z)", &g);
    strftime(bl, sizeof bl, "%F %T %Z (%z)", &l);

    printf("== 3. 同一时间戳，两条分解路径 ==\n");
    printf("gmtime()    -> %s\n", bg);
    printf("localtime() -> %s\n", bl);
    printf("容器的 TZ     = %s\n",
           getenv("TZ") ? getenv("TZ") : "(未设置，glibc 回退读 /etc/localtime)");
    printf("两者相同?     %s   <- 容器默认 UTC 时二者必然相同\n\n",
           (l.tm_hour == g.tm_hour && l.tm_min == g.tm_min) ? "是" : "否（容器非 UTC）");
}

static void show_round_trip(void)
{
    /* strftime 出去，strptime 回来，mktime 归一 —— 原书 Listing 10-3 的主线 */
    const char *in = "2023-11-14 22:13:20";
    const char *infmt = "%Y-%m-%d %H:%M:%S";
    struct tm tm;
    char out[80];

    memset(&tm, 0, sizeof tm);
    if (strptime(in, infmt, &tm) == NULL) {
        printf("strptime 失败\n");
        return;
    }
    tm.tm_isdst = -1;   /* strptime 不设这个字段，交给 mktime 自己判定 */

    printf("== 4. strftime / strptime / mktime 往返回 ==\n");
    printf("输入字符串      = \"%s\"   格式 %s\n", in, infmt);
    printf("strptime 后 tm  = year=%d mon=%d mday=%d %02d:%02d:%02d\n",
           tm.tm_year, tm.tm_mon, tm.tm_mday, tm.tm_hour, tm.tm_min, tm.tm_sec);
    printf("mktime 还原的秒 = %ld   <- strptime 之后 tm_isdst 仍是 %d\n",
           (long) mktime(&tm), tm.tm_isdst);
    strftime(out, sizeof out, "%A, %d %B %Y %H:%M:%S %Z", &tm);
    printf("再 strftime     = %s\n", out);
    printf("和原时间戳相等? %s\n", (mktime(&tm) == (time_t) FIXED_EPOCH) ? "是" : "否");
}

int main(void)
{
    show_struct_tm();
    show_formats();
    show_gm_vs_local();
    show_round_trip();
    return 0;
}
```

编译 + 运行：

```bash
gcc -O0 -Wall -Wextra -o c10_2_strftime c10_2_strftime.c
./c10_2_strftime
```

> 本 demo 用**固定时间戳** `1700000000`（= 2023-11-14 22:13:20 UTC），不用 `time(NULL)`——这样笔记里的实测输出才能逐字复现、不随运行时刻漂移。这是本仓库「会被抄进笔记的输出」的统一约定。

实测（CE，gcc 13.3.0）第 1 段：

```text
== 1. struct tm 的字段就是内核/库给你的原始数值 ==
tm_sec   = 20      tm_min  = 13      tm_hour = 22
tm_mday  = 14      tm_mon  = 10   <- 0..11，不是 1..12
tm_year  = 123   <- 年 - 1900，所以真实年份 = 2023
tm_wday  =  2   <- 0=Sunday
tm_yday  = 317   <- 0..365，不是 1..366
tm_isdst =  0   <- gmtime 恒为 0
```

四个「不是直觉值」的字段：

| 字段 | 值 | 换算 | 常见错误 |
|------|----|------|----------|
| `tm_year` | `123` | **+ 1900** = 2023 | 直接当 2023 用 → 差 1900 年 |
| `tm_mon` | `10` | **+ 1** = 11 月 | 当 10 月用 → 差一个月 |
| `tm_mday` | `14` | 直接用 | 这个字段**是** 1..31，别再 +1 |
| `tm_wday` | `2` | 0 = **星期日** | 当成星期一（`1=Sun` 的 ISO 约定）→ 差一天 |
| `tm_yday` | `317` | **+ 1** = 第 318 天 | 当第 317 天用 → 差一天 |

> 记住一句话就够：**`tm` 里凡是「范围从 0 开始」的字段（`mon`/`wday`/`yday`）都要 +1 才能当人话；`year` 要 +1900；`mday`/`hour`/`min`/`sec` 是正常的。**

`tm_isdst` 有三态，这点最常被忽略：

| 值 | 含义 |
|----|------|
| `> 0` | 该时刻处于夏令时 |
| `0` | 该时刻不处于夏令时 |
| `-1` | **不知道**——由 `mktime()` 自己判定（`gmtime()` 永远给 0；`strptime()` 不设这个字段，所以它保持调用方给的值） |

## 2. `strftime` 格式符全表（38 个，实测）

```text
== 2. strftime 格式符全表（固定时间戳 1700000000，用 gmtime） ==
  %a   -> "Tue"
  %A   -> "Tuesday"
  %b   -> "Nov"
  %B   -> "November"
  %c   -> "Tue Nov 14 22:13:20 2023"
  %C   -> "20"
  %d   -> "14"
  %D   -> "11/14/23"
  %e   -> "14"
  %F   -> "2023-11-14"
  %g   -> "23"
  %G   -> "2023"
  %h   -> "Nov"
  %H   -> "22"
  %I   -> "10"
  %j   -> "318"
  %m   -> "11"
  %M   -> "13"
  %n   -> "\n"
  %p   -> "PM"
  %r   -> "10:13:20 PM"
  %R   -> "22:13"
  %s   -> "1700000000"
  %S   -> "20"
  %t   -> "\t"
  %T   -> "22:13:20"
  %u   -> "2"
  %U   -> "46"
  %V   -> "46"
  %w   -> "2"
  %W   -> "46"
  %x   -> "11/14/23"
  %X   -> "22:13:20"
  %y   -> "23"
  %Y   -> "2023"
  %z   -> "+0000"
  %Z   -> "GMT"
  %%   -> "%"
```

按用途归类（把 38 个压成 8 组）：

| 组 | 格式符 | 备注 |
|----|--------|------|
| 年 | `%Y` `%y` `%C` `%G` `%g` | `%G`/`%g` 是 **ISO 8601 周历**的年（和 `%V` 配套），不是日历年 |
| 月 | `%m` `%b` `%B` `%h` | `%h` 是 `%b` 的同义词（历史遗留） |
| 日 | `%d` `%e` `%j` | `%e` 是**空格填充**，`%d` 是零填充；`%j` 是年内第几天（**1..366**，注意这里 +1 了） |
| 时 | `%H` `%I` `%k` `%l` | `%k`/`%l` 是 **GNU 扩展**（空格填充的 24/12 小时制） |
| 分/秒 | `%M` `%S` | **只到秒**，亚秒要自己拼（见 [10.9](10.9-exercise.md) 练习 2） |
| 时分秒组合 | `%T` `%R` `%r` `%X` | `%X` 是 **locale 相关**的（换 `de_DE` 会变），`%T`/`%R` 是固定格式 |
| 日期组合 | `%F` `%D` `%x` `%c` | `%x`/`%c` 是 **locale 相关**；`%F` = `%Y-%m-%d`、`%D` = `%m/%d/%y` 是固定的 |
| 时区/杂项 | `%z` `%Z` `%s` `%n` `%t` `%%` `%u` `%w` `%U` `%V` `%W` `%p` | `%s` 是 **POSIX/GNU 扩展**（C99 里没有它） |

### 两个「看着像错的」输出

| 输出 | 解释 |
|------|------|
| `%s -> "1700000000"` | 把时间戳**原样回打**。这不是 C 标准格式符，是 POSIX/glibc 扩展——用 `gcc -std=c99 -pedantic` 会告警（本 demo 默认 gnu 模式所以不报） |
| `%n -> "\n"`、`%t -> "\t"` | 真的输出换行/制表符。demo 里专门写了 `esc()` 把它们转义成 `\n`/`\t` 显示，**否则输出表格会被冲乱**——这也是写「会打印不可见字符」的 demo 时该有的习惯 |
| `%j -> "318"` 但 `tm_yday = 317` | `%j` 是**人的计数**（1..366），`tm_yday` 是**程序计数**（0..365）。差的就是那个 +1 |

### `strftime` 唯一的失败信号：返回 0

`strftime()` 成功时返回**写入的字节数**（不含结尾 `\0`），失败时返回 **0**。它**不会**告诉你「需要多大」。

这个坑在 locale 切换到中文时最容易踩——见 [10.4 Locales](10.4-locales.md) 第 5 段的现场实测：`LC_TIME=zh_CN.UTF-8` 下格式 `%c` 需要 43 字节，只给 20 字节时返回 0，而缓冲区内容**未定义**。

## 3. 同一时间戳，两条分解路径

```text
== 3. 同一时间戳，两条分解路径 ==
gmtime()    -> 2023-11-14 22:13:20 GMT (+0000)
localtime() -> 2023-11-14 22:13:20 UTC (+0000)
容器的 TZ     = (未设置，glibc 回退读 /etc/localtime)
两者相同?     是   <- 容器默认 UTC 时二者必然相同
```

要注意这里的 `%Z` 两条路径来源不同：

| 路径 | `%z` / `%Z` 从哪来 |
|------|-------------------|
| `gmtime()` | `tm_zone` 由 glibc 填成 `"GMT"`，`tm_gmtoff` 填 0。**不读 TZ** |
| `localtime()` | 从 `TZ` 环境变量（或 `/etc/localtime`）解析出来 |

所以在这台容器上两者恰好都是 `+0000`，**换到 `TZ=Asia/Shanghai` 就会分叉**——那时 `gmtime` 仍是 `GMT +0000`，`localtime` 变成 `CST +0800`。这正是 [10.3](10.3-timezones.md) 要展开的东西。

## 4. 往返回：`strftime` → `strptime` → `mktime`

```text
== 4. strftime / strptime / mktime 往返回 ==
输入字符串      = "2023-11-14 22:13:20"   格式 %Y-%m-%d %H:%M:%S
strptime 后 tm  = year=123 mon=10 mday=14 22:13:20
mktime 还原的秒 = 1700000000   <- strptime 之后 tm_isdst 仍是 -1
再 strftime     = Tuesday, 14 November 2023 22:13:20 UTC
和原时间戳相等? 是
```

三件事：

| 现象 | 说明 |
|------|------|
| `strptime` 返回的不是 `time_t` | 它填的是 `struct tm`，**必须**再调 `mktime()` 才得到秒数 |
| `strptime()` **不碰 `tm_isdst`** | 所以 demo 里先 `memset(&tm, 0, ...)` 再显式写 `tm.tm_isdst = -1`，让 `mktime()` 自己判定。**忘记这一步**会让 `mktime` 按「不是夏令时」算 → 在 DST 边界上差一小时 |
| 往返能回到原值 | 说明格式串和输入串是「互逆」的。但这是**巧合性的成立**：`mktime` 会把 `tm` 里越界的字段「归一化」（如 `tm_mon = 12` → 下一年 1 月），所以往返测试**不能**证明解析正确 |

> `strptime()` 是 X/Open（SUSv3）函数，不是 C 标准。这就是原书 `strtime.c` 要写 `#define _XOPEN_SOURCE` 的原因——而**不给值的 `_XOPEN_SOURCE` 在现代 glibc 上不再解锁任何东西**，必须给 `700`（见下面第 7 段）。

## 5. 可重入性：四个函数共用同一块静态内存

这是本节最该带走的一条。`gmtime()` / `localtime()` / `asctime()` / `ctime()` **都返回静态缓冲区的指针**——两次调用会互相覆盖。

### 代码示例 B

源码：[../code/c10_2_reentrant.c](../code/c10_2_reentrant.c)

```c
/* TLPI 第 10 章 §10.2 Time-Conversion Functions（可重入性）
 * gmtime()/localtime()/asctime()/ctime() 返回的都是**静态缓冲区**，
 * 两次调用会互相覆盖 —— 现场抓地址 + 现场看数据被改掉。
 *
 * 编译: gcc -O0 -Wall -Wextra -o c10_2_reentrant c10_2_reentrant.c
 * 运行: ./c10_2_reentrant                    (无需参数、无需权限)
 *
 * 输出里的地址每次运行不同（ASLR + 库加载基址），要看的是：
 *   * 两次调用返回的**指针是否相同**；
 *   * 第一个结果里的数据是不是**被第二次调用改掉了**。
 */
#define _GNU_SOURCE
#include <stdio.h>
#include <time.h>

#define T1 1700000000L   /* 2023-11-14 22:13:20 UTC */
#define T2 0L            /* 1970-01-01 00:00:00 UTC */

static void show_tm_clobber(void)
{
    time_t a = (time_t) T1, b = (time_t) T2;
    struct tm *p1, *p2;

    printf("== 1. gmtime() / localtime() 共用同一个静态 struct tm ==\n");
    p1 = gmtime(&a);
    p2 = gmtime(&b);
    printf("p1 = gmtime(&%ld) -> %p\n", (long) a, (void *) p1);
    printf("p2 = gmtime(&%ld) -> %p\n", (long) b, (void *) p2);
    printf("两个指针相同? %s\n", (p1 == p2) ? "是 —— 同一个缓冲区" : "否");
    printf("通过 p1 读出的年份 = %d   <- 期望 %d，实际是 %d\n",
           p1->tm_year + 1900, 1900 + 123, p1->tm_year + 1900);
    printf("（p1 看到的是第二次调用的结果，第一次的结果已经没了）\n\n");

    p1 = gmtime(&a);
    p2 = localtime(&a);
    printf("gmtime() 与 localtime() 也是同一个缓冲区? %s\n\n",
           (p1 == p2) ? "是" : "否");
}

static void show_tm_reentrant(void)
{
    time_t a = (time_t) T1, b = (time_t) T2;
    struct tm ta, tb;
    struct tm *r1, *r2;

    printf("== 2. _r 版本：调用者自己给缓冲区 ==\n");
    r1 = gmtime_r(&a, &ta);
    r2 = gmtime_r(&b, &tb);
    printf("gmtime_r(&%ld) -> %p   ta.tm_year=%d\n", (long) a, (void *) r1, ta.tm_year + 1900);
    printf("gmtime_r(&%ld) -> %p   tb.tm_year=%d\n", (long) b, (void *) r2, tb.tm_year + 1900);
    printf("两个缓冲区相同? %s\n", (r1 == r2) ? "是" : "否 —— 各自独立");
    printf("ta 里还是第一次的结果? %s\n\n",
           (ta.tm_year + 1900 == 2023 && tb.tm_year + 1900 == 1970) ? "是" : "否");
}

static void show_str_clobber(void)
{
    time_t a = (time_t) T1, b = (time_t) T2;
    struct tm ga, gb;
    char *s1, *s2;
    char ba[64], bb[64];

    printf("== 3. asctime() 共用同一个静态字符数组 ==\n");
    gmtime_r(&a, &ga);
    gmtime_r(&b, &gb);

    s1 = asctime(&ga);
    printf("第 1 次 asctime(&ga) -> %p  内容: %s", (void *) s1, s1);
    s2 = asctime(&gb);
    printf("第 2 次 asctime(&gb) -> %p  内容: %s", (void *) s2, s2);
    printf("两个指针相同? %s\n", (s1 == s2) ? "是 —— 同一个缓冲区" : "否");
    printf("现在拿第 1 次的指针 s1 再读一次: %s", s1);
    printf("  ^^ 第 1 次的结果已被第 2 次覆盖\n\n");

    printf("== 4. ctime() 同样共用缓冲区（它就是 localtime + asctime） ==\n");
    s1 = ctime(&a);
    printf("第 1 次 ctime(&%ld) -> %p  内容: %s", (long) a, (void *) s1, s1);
    s2 = ctime(&b);
    printf("第 2 次 ctime(&%ld) -> %p  内容: %s", (long) b, (void *) s2, s2);
    printf("两个指针相同? %s\n\n", (s1 == s2) ? "是" : "否");

    printf("== 5. _r 版本：调用者自己给缓冲区 ==\n");
    printf("asctime_r(&ga, ba) -> %s", asctime_r(&ga, ba));
    printf("asctime_r(&gb, bb) -> %s", asctime_r(&gb, bb));
    printf("两个缓冲区互不影响：ba=\"%s\"  bb=\"%s\"\n",
           ba, bb);
    ctime_r(&a, ba);
    printf("ctime_r(&%ld, ba)  -> %s", (long) a, ba);
    printf("此时 bb 仍是: %s", bb);
}

int main(void)
{
    show_tm_clobber();
    show_tm_reentrant();
    show_str_clobber();
    printf("\n结论：主线程里单次用没问题；一旦要同时持有两个分解时间，"
           "或者多线程/信号处理器里也要转时间，就必须用 _r 版本。\n");
    return 0;
}
```

### 逐条解读

| 现象 | 说明 |
|------|------|
| `gmtime()` 两次返回**同一个地址** `0x715d2ac0a320` | 这个地址在库的 `.bss` 段（一堆 `0x715d...` 是 libc 的映射基址）。它**每次运行都不一样**（ASLR），所以笔记里唯一有意义的是「两次是否相同」 |
| `gmtime()` 与 `localtime()` **也是同一个** | 两个函数共用同一个 `struct tm`，所以混着用更危险 |
| `通过 p1 读出的年份 = 1970` | 这不是「p1 失效了」，而是 p1 **指向的那块内存被第二次调用改写了**。经典的「先存指针后使用」bug |
| `_r` 版本地址不同（`0x7ffee9adcc50` / `0x7ffee9adcc10` 在栈上） | `_r` 版由**调用方**给缓冲区，所以天然隔离。注意这两个地址在**栈**上，与前面 `.bss` 的地址段完全不同 |
| `asctime()` 的静态**字符数组**地址与 `struct tm` 的**不同**（`...a2a0` vs `...a320`） | 是两块**独立**的静态内存。所以「同时持有 `struct tm*` 和 `char*`」在单线程里**是安全的**——危险的是持有两个 `char*` |
| `ba="..."` 的引号里有个换行 | `asctime()` 的输出自带 `\n`，字符串本身没坏 |

### 什么时候必须用 `_r` 版

| 场景 | 为什么 |
|------|--------|
| **多线程** | `_r` 版不带静态状态；`gmtime`/`localtime`/`ctime` 都是 MT-Unsafe |
| **信号处理器** | 信号处理器里调 `localtime()` 会改掉主流程正在用的那块缓冲区。`localtime_r` 虽然也不是异步信号安全的，但至少不共享内存 |
| **同时持有两个分解时间** | 最直接的动机：本 demo 第 1 段就是 |
| **要 `tm_zone` 指向稳定字符串** | `tm_zone` 在 `struct tm` 里是 `const char *`，`localtime()` 给它的是一块会被刷新的静态区（`_r` 版里由 glibc 保证生命周期更长，但换 TZ 后仍可能失效） |

/* curr_time.c

   Implement our currTime() function.
*/
#include <time.h>
#include "curr_time.h"          /* Declares function defined here */

#define BUF_SIZE 1000

/* Return a string containing the current time formatted according to
   the specification in 'format' (see strftime(3) for specifiers).
   If 'format' is NULL, we use "%c" as a specifier (which gives the'
   date and time as for ctime(3), but without the trailing newline).
   Returns NULL on error. */

char *
currTime(const char *format)
{
    static char buf[BUF_SIZE];  /* Nonreentrant */
    time_t t;
    size_t s;
    struct tm *tm;

    t = time(NULL);
    tm = localtime(&t);
    if (tm == NULL)
        return NULL;

    s = strftime(buf, BUF_SIZE, (format != NULL) ? format : "%c", tm);

    return (s == 0) ? NULL : buf;
}

    p2 = currTime("%F");
    printf("第二次 currTime(\"%%F\") 返回 %p  内容: %s\n", (void *) p2, p2);
    printf("两个指针相同? %s\n", (p1 == p2) ? "是 —— 同一个 static 缓冲区" : "否");

三个要点：

| 要点 | 说明 |
|------|------|
| `currTime(NULL)` → 走 `%c` | 源码里 `format == NULL` 时换成 `%c`，然后**把末尾 `\n` 去掉**（`%c` 不带换行，但原书为了通用还是查了一遍），这就是输出里没有空行的原因 |

## 7. 原书 Listing 10-3：`strtime.c` 与那个「不给值的 `_XOPEN_SOURCE`」

```c
/*************************************************************************\
*                  Copyright (C) Michael Kerrisk, 2026.                   *
*                                                                         *

\*************************************************************************/

/* strtime.c

   Demonstrate the use of strptime() and strftime().

   Calls strptime() using the given "format" to process the "input-date+time".
   The conversion is then reversed by calling strftime() with the given
   "out-format" (or a default format if this argument is omitted).
*/
#if ! defined(__sun)
#ifndef _XOPEN_SOURCE
#define _XOPEN_SOURCE
#endif
#endif
#include <time.h>
#include <locale.h>
#include "tlpi_hdr.h"

#define SBUF_SIZE 1000

int
main(int argc, char *argv[])
{
    struct tm tm;
    char sbuf[SBUF_SIZE];
    char *ofmt;

    if (argc < 3 || strcmp(argv[1], "--help") == 0)
        usageErr("%s input-date-time in-format [out-format]\n", argv[0]);

    if (setlocale(LC_ALL, "") == NULL)
        errExit("setlocale");   /* Use locale settings in conversions */

    memset(&tm, 0, sizeof(struct tm));          /* Initialize 'tm' */
    if (strptime(argv[1], argv[2], &tm) == NULL)
        fatal("strptime");

    tm.tm_isdst = -1;           /* Not set by strptime(); tells mktime()
                                   to determine if DST is in effect */
    printf("calendar time (seconds since Epoch): %ld\n", (long) mktime(&tm));

    ofmt = (argc > 3) ? argv[3] : "%H:%M:%S %A, %d %B %Y %Z";
    if (strftime(sbuf, SBUF_SIZE, ofmt, &tm) == 0)
        fatal("strftime returned 0");
    printf("strftime() yields: %s\n", sbuf);

    exit(EXIT_SUCCESS);
}
```

```bash

./strtime '2023-11-14 22:13:20|%Y-%m-%d %H:%M:%S'
```

```text

strftime() yields: 22:13:20 Tuesday, 14 November 2023 UTC
```

### 编译参数上的那处「让步」是一条真结论

原书源码第一行是：

```c
#define _XOPEN_SOURCE
```

**不给值**。2010 年的 glibc 看到这个会解锁 SUSv2 的一套接口（包括 `strptime`）；现代 glibc **不认**这种写法——它要求 `_XOPEN_SOURCE >= 500`，否则 `#error` 或者干脆不声明 `strptime`。

这就是本仓库坚持「原书源码零改动、只动编译参数」的价值：`-D_XOPEN_SOURCE=700` 不是偷懒，而是**把「书是 2010 年写的」这件事显式地留在命令行上**，读者一看就知道这里有个时间差。

| 写法 | 现代 glibc 2.39 下的结果 |
|------|--------------------------|
| `#define _XOPEN_SOURCE`（不给值） | 不给 `__USE_XOPEN2K8`，`strptime` 的声明不可见 |
| `-D_XOPEN_SOURCE=700` | 等价于 SUSv4，`strptime` 可见 |
| `#define _GNU_SOURCE` | 也可见（GNU 是超集） |

（这套「用宏选方言」的机制在 [Ch03 §3.6.1](../../chapter-03-system-programming-concepts/notes/3.6-portability.md) 已经完整拆过，这里只做对照。）

## 8. 原书 Listing 10-4：`show_time.c` 三连打

源码：[../code/show_time.c](../code/show_time.c)

```c
/*************************************************************************\
*                  Copyright (C) Michael Kerrisk, 2026.                   *
*                                                                         *
* This program is free software. You may use, modify, and redistribute it *
* under the terms of the GNU General Public License as published by the   *
* Free Software Foundation, either version 3 or (at your option) any      *

/* show_time.c

   A short program that allows us to see the effects of locale and timezone
   on some of the functions that deal with time.

   Try running this program with command lines such as the following:

        ./show_time
        TZ=":Pacific/Auckland" ./show_time
        TZ=":US/Central" ./show_time
        TZ=":CET" ./show_time
*/
#include <time.h>
#include <locale.h>
#include "tlpi_hdr.h"

#define BUF_SIZE 200

int
main(int argc, char *argv[])
{
    time_t t;
    struct tm *loc;
    char buf[BUF_SIZE];

    if (setlocale(LC_ALL, "") == NULL)
        errExit("setlocale");   /* Use locale settings in conversions */

    t = time(NULL);

    printf("ctime() of time() value is:  %s", ctime(&t));

    loc = localtime(&t);
    if (loc == NULL)
        errExit("localtime");

    printf("asctime() of local time is:  %s", asctime(loc));

    if (strftime(buf, BUF_SIZE, "%A, %d %B %Y, %H:%M:%S %Z", loc) == 0)
        fatal("strftime returned 0");
    printf("strftime() of local time is: %s\n", buf);

    exit(EXIT_SUCCESS);
}
```

编译 + 运行：

```bash
gcc -O0 -Wall -Wextra -Wno-unused-parameter -o show_time show_time.c
./show_time
```

实测（CE，gcc 13.3.0）：

```text
ctime() of time() value is:  Mon Sep 14 08:43:42 2026
asctime() of local time is:  Mon Sep 14 08:43:42 2026
strftime() of local time is: Monday, 14 September 2026, 08:43:42 UTC
```

三行的差别就是「三条链」的差别：

| 输出行 | 走的路 |
|--------|--------|
| `ctime() of time() value` | `time()` → `ctime()`（内部 = `localtime` + `asctime`） |
| `asctime() of local time` | `time()` → `localtime()` → `asctime()` |
| `strftime() of local time` | `time()` → `localtime()` → `strftime("%A, %d %B %Y, %H:%M:%S %Z")` |

注意后两者虽然都是「local」，**格式却不一样**（`%c` vs 自定义串）——因为 `asctime` 用的是固定的 `%c`，`strftime` 用的是源码里写的格式串。这也是为什么新代码应该一律用 `strftime`：格式可控，而且不受 locale 的 `D_T_FMT` 影响。

## HFT / 嵌入式关联

| 场景 | 结论 |
|------|------|
| **日志时间戳** | 用 `strftime("%Y-%m-%d %H:%M:%S")` + 自己拼纳秒。**不要**用 `ctime`/`asctime`（带 `\n`、不能选格式、locale 一变就变） |
| **热路径** | 一次 `strftime` 是 **µs 量级**（要解析格式串 + 查 locale 表），比 `clock_gettime` 贵 2~3 个数量级。打时间戳请存 `timespec`，格式化放到离线分析里做 |
| **多线程 / 多核** | `gmtime`/`localtime`/`ctime`/`asctime` 全部 MT-Unsafe → 一律用 `_r` 版 |
| **格式化缓冲区的长度** | 别猜。中文 locale 下 `%c` 要 43 字节，`lt_LT` 更长。给 128 起步，并且**必须检查返回值是否为 0** |
| **嵌入式（无 locale 数据）** | BusyBox / musl 环境下 `setlocale(LC_ALL, "zh_CN.UTF-8")` 会直接返回 `NULL`，`%c`/`%x` 永远走 `"C"`。**依赖 locale 的输出不要写进协议** |
| **跨机器对齐** | 「同一时间戳 → 字符串」这件事**必须**显式带时区，否则两台机器日志对不上。用 ISO 8601 带偏移的形式（见 [10.9](10.9-exercise.md) 练习 2） |

```c
struct tm *p = gmtime(&t1);          /* t1 = 1700000000 → 2023-11-14 */
struct tm *q = gmtime(&t2);          /* t2 = 0          → 1970-01-01 */
printf("%d\n", p->tm_year + 1900);   /* 打印 1970，不是 2023 */
```

因为 `gmtime()` **两次返回同一个静态 `struct tm` 的地址**（本 demo 实测 `p1 == p2`）。`q` 的那次调用把 `p` 指向的那块内存改写了，所以 `p->tm_year` 读出来的是第二次的结果。

修法三选一：

| 修法 | 代码 |
|------|------|
| 用完立刻取值（最省） | `struct tm a = *gmtime(&t1);` —— 注意这是**拷贝一份**，不是存指针 |
| 用 `_r` 版 | `struct tm a, b; gmtime_r(&t1, &a); gmtime_r(&t2, &b);` |
| 只要字符串 | 直接 `strftime` 到自己的缓冲区 |

</details>

<details>
<summary>2. `asctime()` 和 `ctime()` 共用缓冲区吗？`struct tm` 和字符串的缓冲区是同一块吗？</summary>

**`asctime` 与 `ctime` 共用**（本 demo 实测两者返回 `0x715d2ac0a2a0`），因为 `ctime` 内部就是 `localtime` + `asctime`。

**但与 `struct tm` 的缓冲区不是同一块**——实测一个是 `...a320`、一个是 `...a2a0`，相差 `0x80 = 128` 字节，是两块独立的静态内存。

所以推论是：

| 持有的东西 | 单线程下是否安全 |
|-----------|-----------------|
| 一个 `struct tm*` + 一个 `char*` | **安全**（不同缓冲区） |
| 两个 `char*` | **不安全**（后一次覆盖前一次） |
| 两个 `struct tm*` | **不安全** |
| 任何组合 + 多线程 | **不安全** |

</details>

<details>
<summary>3. 为什么 `strptime()` 之后一定要写 `tm.tm_isdst = -1`？</summary>

`strptime()` **完全不碰 `tm_isdst`**（本 demo 实测：解析完仍是 `-1`，因为 demo 里显式设过；如果不 memset 又不设，它会是你栈上的垃圾值）。

而 `mktime()` 对 `tm_isdst` 的解释是三态的：

| `tm_isdst` | `mktime` 的行为 |
|-----------|-----------------|
| `1` | 按**处于夏令时**解释，`tm_gmtoff` 用 DST 偏移 |
| `0` | 按**不处于夏令时**解释 |
| `-1` | 让 `mktime` 自己根据时区规则**判定** |

所以如果残留 `0`，而目标时刻其实在夏令时内，`mktime` 算出来会**差 3600 秒**。这不是理论问题——美国/欧洲都有真实的 DST 边界。

另外 `strptime` 还有两个容易忽略的行为：它**只解析格式串里出现的字段**（`tm_hour` 等未出现的字段保持原样），并且**不校验日期合法性**（`2023-02-30` 会原样填进 `tm_mday`，交给 `mktime` 去归一化成 3 月 2 日）。

</details>

<details>
<summary>4. `%s` 能拿到时间戳，为什么不干脆只用 `%s`？</summary>

三个理由：

1. **`%s` 是扩展，不是 C 标准**（C99 的 `strftime` 格式符表里没有它）。用 `gcc -std=c99 -pedantic` 编译会告警，换 libc（如 musl）也可能不认。
2. **它绕了一圈**：你本来手里就有 `time_t`，`strftime("%s")` 是「`time_t` → 字符串 → 再解析回 `time_t`」，纯属浪费。
3. **它不解决亚秒**：`%s` 只到秒，纳秒仍然要单独拼。

正确的用法是：**存 `time_t`/`timespec` 做计算，只在输出给人看的那一刻才格式化。**

</details>
