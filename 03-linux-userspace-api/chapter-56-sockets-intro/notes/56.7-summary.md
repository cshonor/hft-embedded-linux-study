## 本章回顾

### 套接字 API 速查

| 函数 | 说明 |
|------|------|
| `socket(domain, type, protocol)` | 创建套接字 |
| `bind(sockfd, addr, len)` | 绑定地址 |
| `listen(sockfd, backlog)` | 开始监听（服务器） |
| `accept(sockfd, addr, &len)` | 接受连接 |
| `connect(sockfd, addr, len)` | 连接服务器（客户端） |
| `send(sockfd, buf, len, flags)` | 发送数据 |
| `recv(sockfd, buf, len, flags)` | 接收数据 |
| `close(sockfd)` | 关闭套接字 |
| `shutdown(sockfd, how)` | 关闭一个方向 |
| `getsockname(sockfd, addr, &len)` | 获取本地地址 |
| `getpeername(sockfd, addr, &len)` | 获取对端地址 |
| `setsockopt/getsockopt` | 套接字选项 |

### 地址族和类型

| domain | 说明 |
|--------|------|
| `AF_INET` | IPv4 |
| `AF_INET6` | IPv6 |
| `AF_UNIX` | Unix 域 |

| type | 说明 |
|------|------|
| `SOCK_STREAM` | 面向连接（TCP） |
| `SOCK_DGRAM` | 无连接（UDP） |
| `SOCK_RAW` | 原始套接字 |

### 服务器 vs 客户端流程

```
服务器:                      客户端:
socket()                    socket()
  ↓                           ↓
bind()                     connect()
  ↓
listen()
  ↓
accept() ←── 建立连接 ←──
  ↓
recv()/send()             send()/recv()
  ↓
close()                    close()
```

### 字节序函数

| 函数 | 说明 |
|------|------|
| `htons()` | 主机→网络 short（端口） |
| `htonl()` | 主机→网络 long（地址） |
| `ntohs()` | 网络→主机 short |
| `ntohl()` | 网络→主机 long |

### 地址转换

| 函数 | 说明 |
|------|------|
| `inet_pton(af, str, &addr)` | 文本→二进制 |
| `inet_ntop(af, &addr, str, size)` | 二进制→文本 |

## HFT / 嵌入式关联

- **TCP**：HFT 订单/控制消息使用 TCP（可靠传输）
- **UDP**：HFT 行情数据使用 UDP（低延迟，可丢包）
- **Unix 域套接字**：同机进程间通信，比 TCP 快 2-5 倍
- **非阻塞 + epoll**：所有套接字用 `O_NONBLOCK` + `epoll` 管理多路复用
- **嵌入式**：lwIP 等轻量 TCP/IP 栈

## 代码自测

<details>
<summary>1. SOCK_STREAM 和 SOCK_DGRAM 的区别？</summary>

- `SOCK_STREAM`：面向连接，可靠传输（TCP），保证顺序和不丢失，有流量控制
- `SOCK_DGRAM`：无连接，不可靠传输（UDP），不保证顺序，可能丢包，无流量控制

HFT 选择：订单用 TCP（可靠），行情用 UDP（低延迟）。
</details>

<details>
<summary>2. 为什么需要 htons？</summary>

x86 CPU 使用小端字节序（低字节在低地址），网络协议使用大端字节序（高字节在低地址）。`htons` 将端口号从主机字节序转为网络字节序，确保不同架构的机器发送的数据格式一致。不转换可能导致连接到错误端口。
</details>
