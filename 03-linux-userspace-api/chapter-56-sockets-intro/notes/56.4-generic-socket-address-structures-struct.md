# 56.4 Generic Socket Address Structures: struct sockaddr

> 本章：[TLPI 第 56 章 — Sockets: Introduction](./README.md)

## 本节讲什么

介绍通用套接字地址结构 `struct sockaddr` 和各协议族的具体地址结构（`sockaddr_in`/`sockaddr_in6`/`sockaddr_un`），以及它们之间的类型转换。

## 要点

### 通用地址结构

```c
struct sockaddr {
    sa_family_t sa_family;   /* 地址族: AF_INET/AF_INET6/AF_UNIX */
    char        sa_data[14]; /* 地址数据 */
};
```

- 所有套接字 API（`bind`/`connect`/`accept`）接受 `struct sockaddr *`
- 实际传入的是具体协议族的结构，强制转换

### IPv4 地址结构

```c
struct sockaddr_in {
    sa_family_t    sin_family;     /* AF_INET */
    in_port_t      sin_port;       /* 端口（网络字节序） */
    struct in_addr sin_addr;      /* IPv4 地址 */
    unsigned char  sin_zero[8];    /* 填充，使大小=16 */
};

struct in_addr {
    in_addr_t s_addr;              /* 32位 IPv4 地址（网络字节序） */
};
```

### IPv6 地址结构

```c
struct sockaddr_in6 {
    sa_family_t     sin6_family;   /* AF_INET6 */
    in_port_t       sin6_port;     /* 端口 */
    uint32_t        sin6_flowinfo; /* 流信息 */
    struct in6_addr sin6_addr;     /* IPv6 地址 */
    uint32_t        sin6_scope_id; /* 作用域 */
};

struct in6_addr {
    uint8_t s6_addr[16];           /* 128位 IPv6 地址 */
};
```

### Unix 域地址结构

```c
struct sockaddr_un {
    sa_family_t sun_family;       /* AF_UNIX */
    char        sun_path[108];   /* 路径名 */
};
```

### 大小对比

| 结构 | 大小 | 地址族 |
|------|------|--------|
| `sockaddr` | 16 | 通用 |
| `sockaddr_in` | 16 | AF_INET |
| `sockaddr_in6` | 28 | AF_INET6 |
| `sockaddr_un` | 110 | AF_UNIX |
| `sockaddr_storage` | 128 | 通用大容量 |

### sockaddr_storage

```c
struct sockaddr_storage ss;
/* 足够大，可以容纳任何协议族的地址结构 */
/* 适合 accept 等需要存储未知类型地址的场景 */
```

### 类型转换模式

```c
struct sockaddr_in addr;
memset(&addr, 0, sizeof(addr));
addr.sin_family = AF_INET;
addr.sin_port = htons(8080);
addr.sin_addr.s_addr = htonl(INADDR_ANY);

/* 强制转换为通用类型 */
bind(sockfd, (struct sockaddr *)&addr, sizeof(addr));
```

### 字节序转换

| 函数 | 说明 |
|------|------|
| `htons(port)` | 主机→网络 short（端口） |
| `htonl(addr)` | 主机→网络 long（地址） |
| `ntohs(port)` | 网络→主机 short |
| `ntohl(addr)` | 网络→主机 long |

### 地址转换函数

| 函数 | 说明 |
|------|------|
| `inet_pton(af, str, &addr)` | 文本→二进制（推荐） |
| `inet_ntop(af, &addr, str, size)` | 二进制→文本（推荐） |
| `inet_addr(str)` | 文本→long（已废弃） |
| `inet_ntoa(addr)` | 二进制→文本（已废弃，非线程安全） |

```c
/* 推荐用法 */
struct sockaddr_in addr;
inet_pton(AF_INET, "192.168.1.100", &addr.sin_addr);

char str[INET_ADDRSTRLEN];
inet_ntop(AF_INET, &addr.sin_addr, str, sizeof(str));
```

## HFT / 嵌入式关联

- **sockaddr_storage**：HFT 服务器用 `sockaddr_storage` 存储客户端地址，兼容 IPv4/IPv6
- `inet_pton`/`inet_ntop`：线程安全，HFT 必须用这两个替代废弃函数
- **字节序**：HFT 网络代码必须正确处理字节序，用 `htons`/`htonl`
- **嵌入式**：精简系统可能只有 IPv4，`sockaddr_in` 足够

## 代码示例

```c
#include <netinet/in.h>
#include <arpa/inet.h>
#include <string.h>
#include <stdio.h>

/* 统一地址处理（支持 IPv4 和 IPv6） */
void print_peer(int sockfd) {
    struct sockaddr_storage ss;
    socklen_t len = sizeof(ss);
    getpeername(sockfd, (struct sockaddr *)&ss, &len);

    char host[NI_MAXHOST], port[NI_MAXSERV];
    getnameinfo((struct sockaddr *)&ss, len,
                host, sizeof(host), port, sizeof(port),
                NI_NUMERICHOST | NI_NUMERICSERV);
    printf("peer: %s:%s\n", host, port);
}

/* IPv4 绑定 */
int bind_ipv4(int sockfd, const char *ip, int port) {
    struct sockaddr_in addr;
    memset(&addr, 0, sizeof(addr));
    addr.sin_family = AF_INET;
    addr.sin_port = htons(port);
    if (inet_pton(AF_INET, ip, &addr.sin_addr) != 1) return -1;
    return bind(sockfd, (struct sockaddr *)&addr, sizeof(addr));
}
```

## 代码自测

<details>
<summary>1. 为什么需要 sockaddr 通用结构？</summary>

C 语言没有函数重载或多态。套接字 API（bind/connect/accept）需要接受任何协议族的地址。`struct sockaddr` 作为通用"基类"，具体协议族的结构（`sockaddr_in`/`sockaddr_un`）作为"子类"，通过强制类型转换传入。`sa_family` 字段让内核知道实际类型。
</details>

<details>
<summary>2. sockaddr_storage 比 sockaddr 好在哪里？</summary>

`sockaddr` 只有 16 字节，无法容纳 IPv6 的 `sockaddr_in6`（28 字节）。`sockaddr_storage` 有 128 字节，足够容纳任何地址族。且它有对齐保证，可以安全地 cast 为具体类型。在需要存储未知类型地址（如 accept 的客户端地址）时应该用 `sockaddr_storage`。
</details>
