## 练习 1：写一个「不会骗你」的 `pthread_create` 包装

下面这段创建线程的代码在生产环境跑了半年，某天线上线程没起来但日志一片正常。找出**全部**问题并给出修正版。

```c
/* 原版（有问题） */
void spawn_worker(int id)
{
    pthread_t t;
    static int ids[8];

    if (pthread_create(&t, NULL, worker, &ids[id]) == -1)
        perror("pthread_create");

    pthread_detach(t);
}
```

<details>
<summary>参考答案</summary>

**四处错误**：

| # | 问题 | 为什么错 | 修正 |
|---|------|----------|------|
| ① | `== -1` 判断 | Pthreads **返回正错误码，不设 `errno`**（29.2）。失败时返回 `EAGAIN`(11) / `EINVAL`(22) / `EPERM`(1)，永远不等于 -1 | `if ((rc = pthread_create(...)) != 0)` |
| ② | `perror()` | 同上——`errno` 没被设置，`perror` 打印的是**上一次无关系统调用残留的** `errno`，日志完全误导 | `fprintf(stderr, "...: %s\n", strerror(rc))` |
| ③ | `pthread_t t` 是局部变量，detach 之后就没了 | 这一处其实**没问题**（detach 是快照语义），但若改成 joinable 就泄漏了 | 保持 detach，或把它存到数组里等 join |
| ④ | **没有检查 `pthread_detach` 的返回值** | `ESRCH` 说明 `pthread_t` 已失效（线程跑完了且被回收）；`EINVAL` 说明重复 detach。静默吞掉会掩盖 bug | 至少 `assert(rc == 0)` 或记日志 |

**另外两个隐患**：

- `static int ids[8]`：如果 `id >= 8` 就越界；且所有线程共享同一块 `static` 内存，若 worker 会**改写**它就会互相干扰。传只读的 id 值更安全。
- 创建即 detach 有竞态窗口（29.7 方式①）。更彻底的做法是用属性 `PTHREAD_CREATE_DETACHED`（方式③）。

**修正版**：

```c
#define _GNU_SOURCE
#include <pthread.h>
#include <stdio.h>
#include <string.h>
#include <errno.h>
#include <stdlib.h>

/* 返回 0 成功，否则返回错误码（正数） */
static int spawn_worker_detached(int id)
{
    pthread_attr_t attr;
    int rc = pthread_attr_init(&attr);
    if (rc) return rc;

    /* 创建即分离：无竞态（29.7 方式③） */
    rc = pthread_attr_setdetachstate(&attr, PTHREAD_CREATE_DETACHED);
    if (rc) { pthread_attr_destroy(&attr); return rc; }

    /* 顺便把栈调小：默认 8MB 太浪费（29.8） */
    rc = pthread_attr_setstacksize(&attr, 512 * 1024);
    if (rc) { pthread_attr_destroy(&attr); return rc; }

    /* 传值而不是传地址：用一个每个线程独立的堆块，避免共享可变对象 */
    int *arg = malloc(sizeof(int));
    if (!arg) { pthread_attr_destroy(&attr); return ENOMEM; }
    *arg = id;

    pthread_t t;                       /* 局部变量没问题：属性是快照 */
    rc = pthread_create(&t, &attr, worker, arg);
    pthread_attr_destroy(&attr);

    if (rc) {
        free(arg);
        /* ★ 用返回的错误码，不是 errno */
        fprintf(stderr, "spawn_worker(%d) 失败: %s\n", id, strerror(rc));
        return rc;
    }
    /* 注意：worker 负责 free(arg) */
    return 0;
}
```

**配套的可复用日志宏**：

```c
#define PTH_ERR(fn, rc) \
    fprintf(stderr, "[%s:%d] %s: %s\n", __func__, __LINE__, fn, strerror(rc))

/* 用法 */
if ((rc = pthread_create(&t, &attr, fn, arg)) != 0) { PTH_ERR("pthread_create", rc); ... }
```
</details>

## 练习 2：传参三大陷阱

下面程序创建 4 个线程，期望打印 `id = 0..3`。实际输出是乱的甚至崩溃。找出**三个**传参缺陷并修正。

```c
#include <pthread.h>
#include <stdio.h>

void *worker(void *arg)
{
    int id = *(int *)arg;
    printf("id = %d\n", id);
    return NULL;
}

int main(void)
{
    pthread_t t[4];
    for (int i = 0; i < 4; i++)
        pthread_create(&t[i], NULL, worker, &i);      /* ← 缺陷 A */
    for (int i = 0; i < 4; i++)
        pthread_join(t[i], NULL);
    return 0;
}
```

<details>
<summary>参考答案</summary>

**缺陷 A（致命）：传了循环变量的地址 `&i`**

`&i` 对所有 4 个线程是**同一个地址**。新线程可能在 `pthread_create` 返回前就开始执行（29.3），
等它解引用时 `i` 已经变成 1、2、3 甚至 4。典型输出：`1 2 3 3` 或 `4 4 4 4`。

> 更糟的是：`i` 是 `main` 的栈变量，`main` 若先返回，这块栈就失效了 → 未定义行为。

**缺陷 B：传了「即将失效的对象」的地址**

即使改成 `static int ids[4]`，如果 worker 会**写** `ids[id]`，4 个线程就共享一块可变内存 → 数据竞争。
传参的原则是：**要么传值，要么传指向不可变/独占对象的指针**。

**缺陷 C：没检查 `pthread_create` 返回值**

`EAGAIN` 真的会发生（线程数超限 / `RLIMIT_NPROC` / 内存不足，`kernel/fork.c:2366`）。
如果第 3 个创建失败，`t[3]` 是**未初始化的垃圾**，后面的 `pthread_join(t[3])` 是未定义行为。

**修正版（两种写法）**：

```c
/* 写法 1：把整数塞进指针（POSIX 不保证，但 Linux/glibc 上普遍可行，简单场景够用） */
#include <stdint.h>
for (int i = 0; i < 4; i++)
    pthread_create(&t[i], NULL, worker, (void *)(intptr_t)i);

void *worker(void *arg) { int id = (int)(intptr_t)arg; ... }
```

```c
/* 写法 2（推荐、可移植）：每个线程一个独立对象 */
static int ids[4];                    /* 只读，不共享可变状态 */
int created = 0;

for (int i = 0; i < 4; i++) {
    ids[i] = i;
    int rc = pthread_create(&t[i], NULL, worker, &ids[i]);
    if (rc != 0) {
        fprintf(stderr, "create %d 失败: %s\n", i, strerror(rc));
        break;                         /* 不要留着未初始化的 pthread_t */
    }
    created++;
}

/* 只 join 真正创建成功的那些 */
for (int i = 0; i < created; i++)
    pthread_join(t[i], NULL);
```

**写法 3（最健壮）**：堆上分配，每个线程独占，由 worker 释放：

```c
for (int i = 0; i < 4; i++) {
    int *p = malloc(sizeof *p);
    *p = i;
    if (pthread_create(&t[i], NULL, worker, p) != 0) {
        free(p);                       /* 创建失败要自己回收，否则泄漏 */
        break;
    }
    created++;
}

void *worker(void *arg)
{
    int id = *(int *)arg;
    free(arg);                         /* ★ 消费者负责释放 */
    ...
}
```

> **HFT 提醒**：热路径上连 `malloc` 都不要有。长驻线程应该在**启动期**建好，
> 参数用预分配的数组 slot（如 `struct worker_ctx ctx[N]`，第 i 个线程用 `&ctx[i]`），
> 运行时零分配、零释放。
</details>

## 练习 3：证伪 `pthread_t` 的稳定性

写一个程序证明：**线程终止后，`pthread_t` 值会被新线程复用**。
提示：连续创建-销毁-创建，比较前后两个 `pthread_t`。

<details>
<summary>参考答案</summary>

```c
/* tid_reuse.c — 证明 pthread_t 会被复用（29.5 / 29.6） */
#define _GNU_SOURCE
#include <stdio.h>
#include <pthread.h>
#include <unistd.h>
#include <string.h>

static void *noop(void *arg) { (void)arg; return NULL; }

static unsigned long T(pthread_t t) { return (unsigned long)t; }

int main(void)
{
    enum { N = 6 };
    pthread_t first[N], second[N];

    /* 第一轮：建 N 个，全 join 掉 */
    for (int i = 0; i < N; i++) pthread_create(&first[i], NULL, noop, NULL);
    for (int i = 0; i < N; i++) pthread_join(first[i], NULL);

    printf("第一轮 pthread_t：\n");
    for (int i = 0; i < N; i++) printf("  [%d] 0x%lx\n", i, T(first[i]));

    /* 第二轮：同样建 N 个（默认 8MB 栈，glibc 会缓存复用刚释放的栈） */
    for (int i = 0; i < N; i++) pthread_create(&second[i], NULL, noop, NULL);
    for (int i = 0; i < N; i++) pthread_join(second[i], NULL);

    printf("第二轮 pthread_t：\n");
    for (int i = 0; i < N; i++) printf("  [%d] 0x%lx\n", i, T(second[i]));

    printf("复用统计：\n");
    int reused = 0;
    for (int i = 0; i < N; i++)
        for (int j = 0; j < N; j++)
            if (pthread_equal(first[i], second[j])) { reused++; break; }
    printf("  第二轮有 %d/%d 个线程拿到了第一轮用过的 pthread_t\n", reused, N);

    return 0;
}
```

**典型输出**：第二轮几乎全部复用第一轮的 `pthread_t` 值。

**为什么？**（29.5 / 29.6）

- `pthread_t` = `struct pthread *`，也就是**线程栈区的地址**（TCB 在栈高端）
- 线程终止 + join 之后，glibc `__free_tcb()` → `munmap` 掉整块栈
- 新建线程再 `mmap` 时，内核很可能把**同一段虚拟地址**还回来（glibc 甚至有栈缓存）

**三条硬性规则**：

| # | 规则 |
|---|------|
| ① | **用 `pthread_equal()` 比较**，不用 `==`（类型不透明，不可移植） |
| ② | **线程终止后，其 `pthread_t` 立即作废**。别缓存它做长期身份标识 |
| ③ | 需要稳定 ID 就用 **`gettid()`**（内核 TID，在进程生命周期内唯一）或自己分配的 slot 下标 |

```c
/* 稳定 ID 的标准做法：启动期分配 slot，用下标做身份 */
struct worker { pthread_t tid; pid_t kernel_tid; int slot; /* ... */ };
static struct worker W[N];

void *worker_main(void *arg)
{
    struct worker *w = arg;
    w->kernel_tid = gettid();          /* glibc 2.30+；或用 syscall(SYS_gettid) */
    ...
}

/* 日志里打 kernel_tid，与 ps -eLf 的 LWP 列、perf、gdb 完全对齐（29.5） */
```

> **别混淆**：`getpid()` 返回的是 **TGID**（`kernel/sys.c:958`），所有线程相同；
> 只有 `gettid()`（`:964`）返回内核 `pid` 才每线程不同。
</details>

## 练习 4：回收契约设计

给定以下 5 类线程，为每类选择 **joinable / detached**，并说明谁负责回收、以及怎么设置最安全。

| 线程 | 职责 | 生命周期 |
|------|------|----------|
| A | 撮合引擎主循环 | 与进程等长 |
| B | 一次性配置热加载 | 几毫秒，火后即忘 |
| C | 异步日志刷盘 | 与进程等长，关闭时必须确认已落盘 |
| D | 库内部的心跳上报 | 与进程等长，调用方不感知 |
| E | 第三方行情协议解析 | 长驻，可能因为协议异常而崩溃 |

<details>
<summary>参考答案</summary>

| 线程 | 选择 | 设置方式 | 谁回收 | 理由 |
|------|------|----------|--------|------|
| **A 撮合主循环** | **joinable** | 默认（属性 `JOINABLE`） | 关闭序列 `pthread_timedjoin_np` | 需要优雅退出确认；返回值带退出原因 |
| **B 配置热加载** | **detached** | **方式③ 属性创建即分离** | glibc 自动 | 火后即忘，不需要结果也不需要同步点；方式③ 无竞态且省一次调用 |
| **C 异步日志刷盘** | **joinable** | 默认 | 关闭序列 `pthread_timedjoin_np`（带 5s 超时） | **必须确认落盘完成**——detached 丢得静悄悄（29.7） |
| **D 库内心跳** | **detached** | **方式② 线程内 `pthread_detach(pthread_self())`** | glibc 自动 | 调用方不感知也不能负责回收；自 detach 零竞态、自包含 |
| **E 第三方协议解析** | **独立进程** | — | — | 第三方代码是崩溃高发区；多线程下崩一个 = 全灭（29.9 故障域）。放到独立进程，`SIGCHLD` + 重启 |

**统一模板**：

```c
/* 需要确认的（A / C）：joinable + 带超时 join */
static int shutdown_joinable(pthread_t t, int timeout_sec)
{
    struct timespec ts;
    clock_gettime(CLOCK_REALTIME, &ts);
    ts.tv_sec += timeout_sec;

    int rc = pthread_timedjoin_np(t, NULL, &ts);
    if (rc == ETIMEDOUT) {
        fprintf(stderr, "线程未在 %d 秒内退出，放弃等待\n", timeout_sec);
        /* 可选：pthread_cancel(t); 或最后 _exit() 兜底 */
        return rc;
    }
    return rc;
}

/* 火后即忘的（B）：属性创建即分离 */
static int spawn_detached(void *(*fn)(void *), void *arg)
{
    pthread_attr_t attr;
    int rc = pthread_attr_init(&attr);
    if (rc) return rc;
    rc = pthread_attr_setdetachstate(&attr, PTHREAD_CREATE_DETACHED);
    if (rc) { pthread_attr_destroy(&attr); return rc; }

    pthread_t t;
    rc = pthread_create(&t, &attr, fn, arg);       /* t 可以立刻丢掉 */
    pthread_attr_destroy(&attr);
    return rc;
}

/* 库内部的（D）：线程第一行自 detach */
static void *heartbeat(void *arg)
{
    pthread_detach(pthread_self());     /* 零竞态：此刻本线程必然存活 */
    while (!atomic_load(&stop_hb)) { report(); sleep(30); }
    return NULL;
}
```

**三条铁律回顾**：

1. **契约必须唯一**——要么固定由 A join，要么固定由 B detach。两边都留后手会让 `pthread_detach` 静默返回 0 却什么也没做（29.7 第四节）
2. **要结果 → join；要同步点 → join；拿不准 → join**
3. **detach 之后立即作废 `pthread_t`**
</details>

## 练习 5：诊断一次栈溢出

一个多线程服务每隔几天随机 `SIGSEGV`，core 里看到的调用栈毫无意义（栈顶被破坏）。
已知每个线程默认 8MB 栈、默认 4KB guard。

**(a)** 为什么 guard page 没能及时挡住？
**(b)** 给出**四步**诊断流程。
**(c)** 给出**三条**修复措施。

<details>
<summary>参考答案</summary>

### (a) 为什么 guard page 没挡住

**guard page 只能挡「小步溢出」，挡不住「大步跨越」**（29.8 第 3.3 节）。

```
  High addr  ┌──────────────┐
             │ 已用栈        │
             │      ↓       │
             │              │
             ├──────────────┤
             │ guard 4KB    │  ← 单次写入 ≥ 4KB 就直接跳过去
  Low addr   ├──────────────┤
             │ 相邻线程栈    │  ← 落到这里：无信号、静默破坏
             └──────────────┘
```

一次写入 ≥ guardsize（默认 4KB）就会跨过保护页，写到相邻映射——而那很可能就是**另一个线程的栈**。
所以症状是「栈顶被破坏、调用栈无意义」，而不是干净的 `SIGSEGV`。

**高危写法**：

```c
char buf[64 * 1024];          /* 64KB 局部数组 */
char vla[n];                  /* VLA，n 由输入决定 */
alloca(size);                 /* 动态栈分配 */
深递归里的巨型帧
```

**另一个完全不同的原因**：新线程栈是**固定大小**的（mmap 时定死），不像主线程栈能按需扩展。
如果 `stacksize` 被调得过小，正常深度的调用链也会溢出。

### (b) 四步诊断流程

| 步 | 动作 | 命令 / 代码 |
|----|------|-------------|
| ① | **确认是不是栈溢出**：看故障地址与栈边界的距离 | gdb: `p/x $sp`，再和 `pthread_getattr_np()` 拿到的 `stackaddr` 比 |
| ② | **静态估算每个函数的栈帧** | `gcc -fstack-usage -O2 *.c` → 生成 `.su` 文件；或 `-Wstack-usage=4096` 对超阈函数报警 |
| ③ | **运行期量已用栈**：在线程入口和最深处取局部地址求差 | 见下方代码 |
| ④ | **调大 guard 再复现**：把 `guardsize` 调到 64KB，若立刻变成干净的 `SIGSEGV`，就坐实了「大步跨越」 | `pthread_attr_setguardsize(&attr, 64*1024)` |

**第 ③ 步的代码**：

```c
static __thread void *g_stack_entry;      /* 线程入口处记录（Ch31 的 __thread） */
static __thread size_t g_max_used;

static void probe(void)
{
    volatile char here;
    size_t used = (char *)g_stack_entry - (char *)&here;
    if (used > g_max_used) g_max_used = used;
}

void *worker(void *arg)
{
    volatile char entry;
    g_stack_entry = (void *)&entry;
    ...
    probe();                              /* 在关键深处调用 */
    ...
}

/* 退出前打印 */
void *worker(void *arg)
{
    ...
    size_t total, guard; void *base;
    pthread_attr_t ga; pthread_getattr_np(pthread_self(), &ga);
    pthread_attr_getstack(&ga, &base, &total);
    pthread_attr_getguardsize(&ga, &guard);
    printf("栈用量 %zu / %zu KB（guard %zu KB）→ 水位 %.1f%%\n",
           g_max_used/1024, total/1024, guard/1024,
           100.0 * g_max_used / total);
    pthread_attr_destroy(&ga);
}
```

> 水位持续 > 60% 就该扩容或重构了——留足余量给信号处理和异常路径。

**另外两个 aids**：

- `ulimit -c unlimited` + `systemd-coredump`，保证能拿到 core
- 在线程里装 `SIGSEGV` 的 `sigaltstack` + `SA_ONSTACK` handler（Ch21），栈溢出时至少能打出有意义的回溯

### (c) 三条修复措施

| # | 措施 | 说明 |
|---|------|------|
| ① | **栈上不放 > 4KB 的对象** | 大缓冲区改 `malloc`、静态池、或 `__thread` 预分配槽位。这是治本 |
| ② | **调大 `guardsize` 到 64KB~1MB** | 缓解，不是根治；代价是每线程多占虚拟内存（不占物理内存，PROT_NONE） |
| ③ | **显式设置 `stacksize` 并留 2~3 倍余量** | 别用默认的 8MB 就以为安全——如果第三方库在栈上开大数组，8MB 照样能踩穿 |
| （④） | 深递归改写为显式栈的迭代 | 协议解析 / JSON / XML 树遍历的高危模式 |

> **HFT 补充**：固定栈正是我们要的（可预测延迟，不像主线程栈会在故障路径动态扩展）。
> 代价是必须**自己把栈算清楚**：静态分析 + 运行期水位打点，两者都做。
</details>

## 练习 6：调度属性静默失效

下面代码想让 worker 跑在 `SCHED_FIFO` 优先级 50 上，运行后检查发现**仍然是 `SCHED_OTHER` 优先级 0**，
而且 `pthread_create` 返回 0，没有任何报错。**(a)** 为什么？ **(b)** 怎么修？ **(c)** 修完还是 `EPERM` 怎么办？

```c
pthread_attr_t attr;
pthread_attr_init(&attr);
pthread_attr_setschedpolicy(&attr, SCHED_FIFO);
struct sched_param sp = { .sched_priority = 50 };
pthread_attr_setschedparam(&attr, &sp);
pthread_create(&tid, &attr, worker, NULL);
```

<details>
<summary>参考答案</summary>

### (a) 为什么静默失效

**漏了 `pthread_attr_setinheritsched(&attr, PTHREAD_EXPLICIT_SCHED)`。**

`pthread_attr_t` 的 `inheritsched` 默认值是 **`PTHREAD_INHERIT_SCHED`**，含义是：
**忽略 attr 里填的 `schedpolicy` / `schedparam`，新线程直接继承创建者的调度属性。**

所以 `pthread_attr_setschedpolicy` 和 `set schedparam` 都写了，但**根本没人读**。
`pthread_create` 返回 0，线程跑得好好的，只是延迟特性完全不是你要的。

> 这个模式和 Ch22 里 `do_sigaction()` 静默吞掉未知 `sa_flags`（`kernel/signal.c:4153-4156`）
> 是同一类约定：**内核/POSIX 里静默忽略的东西，唯一对策是「写进去再读回来比对」。**

### (b) 修正版（三件套 + 读回校验）

```c
static int create_rt_thread(pthread_t *tid, int cpu, int prio,
                            void *(*fn)(void *), void *arg)
{
    pthread_attr_t attr;
    int rc = pthread_attr_init(&attr);
    if (rc) return rc;

    /* ① 策略 */
    rc = pthread_attr_setschedpolicy(&attr, SCHED_FIFO);
    if (rc) goto out;

    /* ② 优先级 */
    struct sched_param sp = { .sched_priority = prio };
    rc = pthread_attr_setschedparam(&attr, &sp);
    if (rc) goto out;

    /* ③ ★ 生效开关 —— 一行都不能少 */
    rc = pthread_attr_setinheritsched(&attr, PTHREAD_EXPLICIT_SCHED);
    if (rc) goto out;

    /* ④ 绑核 */
    cpu_set_t cs;
    CPU_ZERO(&cs);
    CPU_SET(cpu, &cs);
    rc = pthread_attr_setaffinity_np(&attr, sizeof cs, &cs);
    if (rc) goto out;

    rc = pthread_create(tid, &attr, fn, arg);

out:
    pthread_attr_destroy(&attr);
    if (rc) return rc;

    /* ⑤ ★ 读回校验 —— 唯一可靠的确认方式 */
    int pol;
    struct sched_param got;
    pthread_getschedparam(*tid, &pol, &got);
    cpu_set_t got_cs; CPU_ZERO(&got_cs);
    pthread_getaffinity_np(*tid, sizeof got_cs, &got_cs);

    fprintf(stderr, "校验: policy=%d prio=%d cpus=%d（期望 FIFO/%d/1）\n",
            pol, got.sched_priority, CPU_COUNT(&got_cs), prio);
    if (pol != SCHED_FIFO || got.sched_priority != prio)
        fprintf(stderr, "  ⚠ 调度属性未生效！\n");

    return 0;
}
```

### (c) 还是 `EPERM`：权限问题

内核判定在 **`kernel/sched/core.c:7562` 的 `user_check_sched_setscheduler()`**：

```c
if (rt_policy(policy)) {
    unsigned long rlim_rtprio = task_rlimit(p, RLIMIT_RTPRIO);      /* :7573 */
    if (policy != p->policy && !rlim_rtprio)                        /* :7576 */
        goto req_priv;
    if (attr->sched_priority > p->rt_priority &&
        attr->sched_priority > rlim_rtprio)
        goto req_priv;
}
...
req_priv:
    if (!capable(CAP_SYS_NICE)) return -EPERM;                      /* :7614 */
```

**两条路，任意一条**：

```bash
# 路径 1（推荐）：RLIMIT_RTPRIO，不需要 root，且天然是优先级上界
ulimit -r 50
./prog
# 或在代码里：
#   struct rlimit rl = { 50, 50 }; setrlimit(RLIMIT_RTPRIO, &rl);

# 路径 2：CAP_SYS_NICE，无上限
sudo setcap cap_sys_nice=ep ./prog
./prog
```

**⚠ 安全警告**：`SCHED_FIFO` 线程**没有时间片**，会一直跑到阻塞、主动 yield、或被更高优先级抢占。
一个优先级 99 的死循环会把同核所有东西饿死（sshd 无响应，只能硬重启）。

防御清单：

- RT 线程里禁止无界循环，必须有阻塞点
- 优先级从低往高调（先试 50，别一上来 99）
- 用 `RLIMIT_RTPRIO` 设硬上界
- 别随便改 `/proc/sys/kernel/sched_rt_runtime_us`（默认 950000 = 给非 RT 留 5% 兜底）
</details>

## 练习 7：线程 vs 进程选型

对下面 6 个场景给出选择（**多线程 / 多进程 / 混合**）和一句话理由。

| # | 场景 |
|---|------|
| 1 | HFT 撮合引擎：订单簿 2GB，行情线程 → 策略线程 → 风控线程，端到端预算 10μs |
| 2 | 一个占 40GB 虚拟内存的服务需要周期性执行外部脚本 |
| 3 | 用第三方闭源库解析交易所的二进制行情协议（历史上崩过） |
| 4 | 32MB 内存的嵌入式设备，需要 8 个并发传感器采集任务 |
| 5 | 需要把某个模块降权到 nobody 运行，但主程序是 root |
| 6 | Web 服务：每请求需要调用一个可能死循环的模板引擎 |

<details>
<summary>参考答案</summary>

| # | 选择 | 理由 |
|---|------|------|
| 1 | **多线程（同进程）** | 2GB 订单簿不可能通过 IPC 传（微秒级抖动）。共享 `mm_struct` 零拷贝；再配合一核一线程 + SPSC 无锁队列 + `SCHED_FIFO` 分层。线程切换不写 CR3、不跑 `cond_mitigation()`（`arch/x86/mm/tlb.c:562` vs `:612`） |
| 2 | **多进程，且绝不在热路径 fork** | `dup_mm()` 成本与虚拟内存大小成正比（`kernel/fork.c:1735`），40GB 的进程 fork 一次是毫秒级。用 `posix_spawn`（通常走 `CLONE_VM\|CLONE_VFORK` + exec），或在启动阶段 fork 好一个 worker 池 |
| 3 | **多进程隔离** | 第三方闭源库是崩溃高发区。多线程下崩一个 = 全灭（信号处理是进程级共享的）。放独立进程，用共享内存传行情，`SIGCHLD` + 自动重启 |
| 4 | **多线程 + 调小栈** | 32MB 内存下 8 个进程各 8MB 栈直接爆。用 `pthread_attr_setstacksize(16~64KB)`；注意无 MMU 平台 guardsize 无效，要靠 `-fstack-usage` |
| 5 | **多进程** | **线程不能独立降权**——`setuid` 影响的是整个进程的所有线程（凭据是进程级的）。要权限分离只能多进程，配合 `setcap` / namespace |
| 6 | **多进程 + 超时 kill** | 死循环的模板引擎在多线程里会拖死整个进程；多进程可以 `SIGKILL` 掉单个 worker 并重启。这也是 nginx / php-fpm 的经典模型 |

**一句话总结选型判据**：

```
  共享大量可变状态 + 延迟敏感  →  多线程
  需要故障隔离 / 权限分离 / 独立重启 / exec  →  多进程
  虚拟内存巨大  →  绝不 fork
  拿不准  →  先多进程（隔离性可以后加 IPC），再加多线程优化热点
```

**混合是常态**：现代系统几乎都是「进程内多线程，进程间 IPC」——
HFT 主链路多线程共享订单簿，日志/网关/风控外挂用独立进程（29.9 第七节）。
</details>

## 综合题：生产级线程池 + 优雅关闭

**要求**：

1. 固定 N 个 worker，**启动期一次性创建**，运行期零 `pthread_create`/`join`/`detach`
2. 任务队列用互斥锁 + 条件变量（Ch30 会讲，这里先用起来）
3. 支持**优雅关闭**：置 `shutdown` 标志 → 广播唤醒所有 worker → 等待在途任务完成 → 带超时 join
4. 每个 worker 可配：栈大小、绑核、调度策略（**含 `EXPLICIT_SCHED`**）
5. 统计：已提交 / 已完成 / 已拒绝 / 队列峰值
6. 提供 `dump_status()` 打印每个 worker 的内核 TID、CPU、栈水位

### 参考实现：`thread_pool.c`

```c
/* thread_pool.c — Ch29 综合题：生产级线程池 + 优雅关闭
 *
 * 编译: gcc -O2 -Wall -Wextra -o thread_pool thread_pool.c -pthread
 * 运行: ./thread_pool [worker数]
 *   需要 RT 优先级时: ulimit -r 50 && ./thread_pool
 */
#define _GNU_SOURCE
#include <stdio.h>
#include <stdlib.h>
#include <stdarg.h>
#include <string.h>
#include <errno.h>
#include <unistd.h>
#include <time.h>
#include <sched.h>
#include <pthread.h>
#include <sys/syscall.h>

/* ───────────────────────── 任务队列 ───────────────────────── */

typedef void (*task_fn)(void *arg);

struct task {
    task_fn   fn;
    void     *arg;
    struct task *next;
};

/* ───────────────────────── worker 上下文 ───────────────────────── */

struct worker {
    pthread_t      tid;         /* join 用 */
    pid_t          ktid;        /* 内核 TID，日志/调试用（29.5） */
    int            slot;        /* 稳定身份：用下标，不用 pthread_t */
    int            cpu;         /* 绑定的 CPU，-1 表示不绑 */
    void          *stack_top;   /* 栈高端地址，用于水位估算 */
    size_t         stack_size;
    unsigned long  n_done;      /* 本 worker 完成的任务数 */
    struct pool   *pool;
};

struct pool {
    /* 任务队列（Ch30 的互斥锁 + 条件变量，这里先用） */
    pthread_mutex_t q_mu;
    pthread_cond_t  q_cv;       /* 有任务来了 */
    pthread_cond_t  done_cv;    /* 有任务完成了 */
    struct task    *head, *tail;
    int             qlen;
    int             peak_qlen;

    /* 生命周期 */
    int             shutdown;   /* 1 = 不再接收新任务，处理完队列就退 */
    int             nworkers;
    struct worker  *workers;

    /* 统计 */
    unsigned long   n_submit;
    unsigned long   n_done;
    unsigned long   n_reject;
    int             max_qlen;   /* 队列上限，0 = 不限 */
};

/* ───────────────────────── 日志 ───────────────────────── */

static pthread_mutex_t log_mu = PTHREAD_MUTEX_INITIALIZER;

static void say(const char *fmt, ...)
{
    struct timespec ts;
    clock_gettime(CLOCK_MONOTONIC, &ts);
    char body[512];
    va_list ap;
    va_start(ap, fmt);
    vsnprintf(body, sizeof body, fmt, ap);
    va_end(ap);

    pthread_mutex_lock(&log_mu);
    fprintf(stderr, "[%6ld.%03ld][tid %ld] %s\n",
            (long)ts.tv_sec, ts.tv_nsec / 1000000,
            (long)syscall(SYS_gettid), body);
    pthread_mutex_unlock(&log_mu);
}

static pid_t gettid_(void) { return (pid_t)syscall(SYS_gettid); }

/* ───────────────────────── worker 主循环 ───────────────────────── */

static struct task *pop_task(struct pool *p)
{
    struct task *t = p->head;
    if (!t) return NULL;
    p->head = t->next;
    if (!p->head) p->tail = NULL;
    p->qlen--;
    return t;
}

static void *worker_main(void *arg)
{
    struct worker *w = arg;
    struct pool *p = w->pool;

    w->ktid = gettid_();

    /* 记录栈入口，用于水位估算（练习 5） */
    volatile char entry;
    w->stack_top = (void *)&entry;
    w->stack_size = 0;
    {
        pthread_attr_t ga;
        if (pthread_getattr_np(pthread_self(), &ga) == 0) {
            void *base; size_t sz;
            pthread_attr_getstack(&ga, &base, &sz);
            w->stack_size = sz;
            pthread_attr_destroy(&ga);
        }
    }
    say("worker[%d] 启动：内核 TID=%ld CPU=%d 栈=%zuKB",
        w->slot, (long)w->ktid, w->cpu, w->stack_size / 1024);

    for (;;) {
        pthread_mutex_lock(&p->q_mu);

        /* 条件变量必须用 while 循环（防虚假唤醒，Ch30） */
        while (!p->shutdown && p->qlen == 0)
            pthread_cond_wait(&p->q_cv, &p->q_mu);

        if (p->shutdown && p->qlen == 0) {
            /* 关闭 + 队列已空 → 退出 */
            pthread_mutex_unlock(&p->q_mu);
            break;
        }

        struct task *t = pop_task(p);
        pthread_mutex_unlock(&p->q_mu);

        /* 在锁外执行任务：避免串行化整个池 */
        if (t->fn)
            t->fn(t->arg);
        free(t);

        w->n_done++;

        pthread_mutex_lock(&p->q_mu);
        p->n_done++;
        pthread_cond_signal(&p->done_cv);
        pthread_mutex_unlock(&p->q_mu);
    }

    say("worker[%d] 退出，共完成 %lu 个任务", w->slot, w->n_done);
    return NULL;
}

/* ───────────────────────── 线程池 API ───────────────────────── */

static int pool_create(struct pool *p, int nworkers, int max_qlen,
                       size_t stack_kb, size_t guard_kb,
                       int use_rt, int base_prio)
{
    memset(p, 0, sizeof *p);
    pthread_mutex_init(&p->q_mu, NULL);
    pthread_cond_init(&p->q_cv, NULL);
    pthread_cond_init(&p->done_cv, NULL);
    p->nworkers = nworkers;
    p->max_qlen = max_qlen;

    p->workers = calloc(nworkers, sizeof(struct worker));
    if (!p->workers) return ENOMEM;

    int ncpu = (int)sysconf(_SC_NPROCESSORS_ONLN);
    int created = 0;

    for (int i = 0; i < nworkers; i++) {
        struct worker *w = &p->workers[i];
        w->slot = i;
        w->cpu  = (ncpu > 0) ? (i % ncpu) : -1;
        w->pool = p;

        pthread_attr_t attr;
        int rc = pthread_attr_init(&attr);
        if (rc) { say("attr_init 失败: %s", strerror(rc)); break; }

        /* ① 栈：调小 + 调大 guard（29.8） */
        if (stack_kb) {
            rc = pthread_attr_setstacksize(&attr, stack_kb * 1024);
            if (rc) say("setstacksize 失败: %s", strerror(rc));
        }
        if (guard_kb) {
            rc = pthread_attr_setguardsize(&attr, guard_kb * 1024);
            if (rc) say("setguardsize 失败: %s", strerror(rc));
        }

        /* ② 调度三件套 —— EXPLICIT 一行都不能少（练习 6） */
        if (use_rt) {
            rc = pthread_attr_setschedpolicy(&attr, SCHED_FIFO);
            if (rc) say("setschedpolicy 失败: %s", strerror(rc));

            int prio = base_prio - i;          /* 每个 worker 差一档，避免同优先级轮转 */
            if (prio < sched_get_priority_min(SCHED_FIFO))
                prio = sched_get_priority_min(SCHED_FIFO);
            struct sched_param sp = { .sched_priority = prio };
            rc = pthread_attr_setschedparam(&attr, &sp);
            if (rc) say("setschedparam 失败: %s", strerror(rc));

            rc = pthread_attr_setinheritsched(&attr, PTHREAD_EXPLICIT_SCHED);  /* ★ */
            if (rc) say("setinheritsched 失败: %s", strerror(rc));
        }

        /* ③ 绑核（glibc 扩展，29.8） */
        if (w->cpu >= 0) {
            cpu_set_t cs;
            CPU_ZERO(&cs);
            CPU_SET(w->cpu, &cs);
            rc = pthread_attr_setaffinity_np(&attr, sizeof cs, &cs);
            if (rc) say("setaffinity_np 失败: %s", strerror(rc));
        }

        /* ④ 全部 joinable：关闭时要确认（29.6 / 29.7） */
        rc = pthread_create(&w->tid, &attr, worker_main, w);
        pthread_attr_destroy(&attr);

        if (rc) {
            say("pthread_create(slot %d) 失败: %s（EAGAIN 真的会发生，kernel/fork.c:2366）",
                i, strerror(rc));
            break;
        }
        created++;

        /* ⑤ 读回校验：唯一可靠的确认方式 */
        if (use_rt) {
            int pol; struct sched_param got;
            pthread_getschedparam(w->tid, &pol, &got);
            if (pol != SCHED_FIFO)
                say("  ⚠ slot %d 调度属性未生效（policy=%d）—— 缺 RLIMIT_RTPRIO 或 CAP_SYS_NICE",
                    i, pol);
        }
    }

    if (created != nworkers) {
        say("只创建了 %d/%d 个 worker，进入降级关闭", created, nworkers);
        pthread_mutex_lock(&p->q_mu);
        p->shutdown = 1;
        pthread_cond_broadcast(&p->q_cv);
        pthread_mutex_unlock(&p->q_mu);
        for (int i = 0; i < created; i++)
            pthread_join(p->workers[i].tid, NULL);
        free(p->workers);
        p->workers = NULL;
        return EAGAIN;
    }
    return 0;
}

/* 提交任务：非阻塞；队列满则拒绝 */
static int pool_submit(struct pool *p, task_fn fn, void *arg)
{
    struct task *t = malloc(sizeof *t);
    if (!t) return ENOMEM;
    t->fn = fn; t->arg = arg; t->next = NULL;

    int rc = 0;
    pthread_mutex_lock(&p->q_mu);

    if (p->shutdown) { rc = ECANCELED; free(t); goto out; }
    if (p->max_qlen && p->qlen >= p->max_qlen) { rc = ENOBUFS; free(t); goto out; }

    if (p->tail) p->tail->next = t; else p->head = t;
    p->tail = t;
    p->qlen++;
    p->n_submit++;
    if (p->qlen > p->peak_qlen) p->peak_qlen = p->qlen;

    pthread_cond_signal(&p->q_cv);

out:
    if (rc) p->n_reject++;
    pthread_mutex_unlock(&p->q_mu);
    return rc;
}

/* 等待所有已提交任务完成 */
static void pool_drain(struct pool *p)
{
    pthread_mutex_lock(&p->q_mu);
    while (p->n_done < p->n_submit)
        pthread_cond_wait(&p->done_cv, &p->q_mu);
    pthread_mutex_unlock(&p->q_mu);
}

/* 优雅关闭：停止接收 → 广播 → 带超时 join */
static int pool_shutdown(struct pool *p, int timeout_sec)
{
    say("关闭：置 shutdown 并广播所有 worker");
    pthread_mutex_lock(&p->q_mu);
    p->shutdown = 1;
    pthread_cond_broadcast(&p->q_cv);     /* 广播，不是 signal！ */
    pthread_mutex_unlock(&p->q_mu);

    int timed_out = 0;
    for (int i = 0; i < p->nworkers; i++) {
        struct timespec ts;
        clock_gettime(CLOCK_REALTIME, &ts);
        ts.tv_sec += timeout_sec;

        int rc = pthread_timedjoin_np(p->workers[i].tid, NULL, &ts);
        if (rc == 0) {
            say("  worker[%d] 已回收", i);
        } else {
            say("  worker[%d] join 失败/超时: %s", i, strerror(rc));
            timed_out = 1;
            /* 生产兜底：pthread_cancel + 再 join；或最后 _exit() */
        }
    }
    return timed_out ? ETIMEDOUT : 0;
}

static void pool_dump(struct pool *p)
{
    say("==== 线程池状态 ====");
    say("  提交 %lu / 完成 %lu / 拒绝 %lu / 队列峰值 %d",
        p->n_submit, p->n_done, p->n_reject, p->peak_qlen);
    for (int i = 0; i < p->nworkers; i++) {
        struct worker *w = &p->workers[i];
        cpu_set_t cs; CPU_ZERO(&cs);
        pthread_getaffinity_np(w->tid, sizeof cs, &cs);
        say("  worker[%d]: TID=%ld CPU集=%d 个 完成=%lu 栈=%zuKB",
            i, (long)w->ktid, CPU_COUNT(&cs), w->n_done, w->stack_size/1024);
    }
}

static void pool_destroy(struct pool *p)
{
    pthread_mutex_destroy(&p->q_mu);
    pthread_cond_destroy(&p->q_cv);
    pthread_cond_destroy(&p->done_cv);
    free(p->workers);
    p->workers = NULL;
}

/* ───────────────────────── 演示 ───────────────────────── */

struct job { int id; int usec; };

static void job_fn(void *arg)
{
    struct job *j = arg;
    if (j->usec) usleep(j->usec);
    free(j);                            /* 任务自己释放参数 */
}

int main(int argc, char **argv)
{
    int nworkers = (argc > 1) ? atoi(argv[1]) : 4;
    int ncpu = (int)sysconf(_SC_NPROCESSORS_ONLN);
    if (nworkers > ncpu) nworkers = ncpu > 0 ? ncpu : 1;

    say("=== Ch29 综合题：线程池（%d 个 worker，在线 CPU %d）===", nworkers, ncpu);

    static struct pool P;
    int rc = pool_create(&P, nworkers,
                         /*max_qlen=*/4096,
                         /*stack_kb=*/512,       /* 默认 8MB 太浪费（29.8） */
                         /*guard_kb=*/64,        /* 默认 4KB 挡不住大帧（练习 5） */
                         /*use_rt=*/0,           /* 需要 RT 就改成 1 并 ulimit -r 50 */
                         /*base_prio=*/50);
    if (rc) { say("pool_create 失败: %s", strerror(rc)); return 1; }

    /* 提交 200 个任务 */
    enum { NJOBS = 200 };
    for (int i = 0; i < NJOBS; i++) {
        struct job *j = malloc(sizeof *j);
        j->id = i;
        j->usec = (i % 20) * 1000;      /* 0~19ms */
        if ((rc = pool_submit(&P, job_fn, j)) != 0) {
            say("提交 %d 被拒: %s", i, strerror(rc));
            free(j);
        }
    }

    pool_drain(&P);                     /* 等在途任务全部完成 */
    pool_dump(&P);

    pool_shutdown(&P, /*timeout_sec=*/5);
    pool_destroy(&P);

    say("=== 演示结束 ===");
    return 0;
}
```

<summary>1. 综合题的线程池里，为什么关闭时必须用 `pthread_cond_broadcast` 而不是 `pthread_cond_signal`？</summary>

因为**有多个 worker 睡在同一个条件变量上，`signal` 只唤醒一个**。

```c
/* worker 侧 */
while (!p->shutdown && p->qlen == 0)
    pthread_cond_wait(&p->q_cv, &p->q_mu);      /* N 个 worker 都睡在这 */
```

如果关闭时用 `signal`：

```
  shutdown = 1
  pthread_cond_signal(&q_cv)   → 只唤醒 worker[0]
      ↓
  worker[0] 发现 shutdown && qlen==0 → 退出
  worker[1..N-1] 仍然睡在 q_cv 上，永远等不到唤醒
      ↓
  pool_shutdown 的 join 全部卡死 → 超时 → 进程关不掉
```

正确做法：

```c
pthread_mutex_lock(&p->q_mu);
p->shutdown = 1;
pthread_cond_broadcast(&p->q_cv);       /* ★ 唤醒所有等待者 */
pthread_mutex_unlock(&p->q_mu);
```

**配套的两个要点**：

1. **条件变量必须用 `while` 而不是 `if`**（防虚假唤醒，Ch30）：
   ```c
   while (!p->shutdown && p->qlen == 0)      /* ✔ while */
       pthread_cond_wait(&p->q_cv, &p->q_mu);
   ```
2. **判断条件必须在锁的保护下读**。`shutdown` 和 `qlen` 都由 `q_mu` 保护，
   `pthread_cond_wait` 会在睡下前自动释放锁、醒来后自动重新获取——这是它存在的意义。

> **HFT 补充**：关闭路径的延迟不敏感，但要**可靠**。
> `pthread_timedjoin_np` 带 5 秒超时 + 兜底 `pthread_cancel` / `_exit()`，
> 保证进程一定能退干净，不会卡在关停上。
</details>

<details>
<summary>2. 为什么任务要在锁外执行？把 `t->fn(t->arg)` 放进临界区会怎样？</summary>

**放进临界区会把整个线程池串行化**——同一时刻只有一个 worker 能执行任务，N 个 worker 退化成 1 个。

```c
/* ❌ 错误：任务在锁内执行 */
pthread_mutex_lock(&p->q_mu);
while (...) pthread_cond_wait(...);
struct task *t = pop_task(p);
t->fn(t->arg);                    /* ← 持锁执行，其他 worker 全被挡在 q_mu 外 */
pthread_mutex_unlock(&p->q_mu);
```

```c
/* ✅ 正确：只保护队列本身，任务在锁外跑 */
pthread_mutex_lock(&p->q_mu);
while (...) pthread_cond_wait(...);
struct task *t = pop_task(p);
pthread_mutex_unlock(&p->q_mu);   /* ← 先放锁 */

t->fn(t->arg);                    /* ← 锁外执行，N 个 worker 真并行 */
```

**临界区的正确边界**：只保护**共享数据结构的访问**（队列的 push/pop、计数器增减），
不保护**任务本身的业务逻辑**。

**推广原则**：

| 场景 | 临界区应覆盖 |
|------|-------------|
| 队列操作 | ✔ 覆盖（head/tail/qlen 的一致性） |
| 统计计数 | ✔ 覆盖（或用 C11 `<stdatomic.h>` 的原子操作，更快） |
| 任务执行 | ✘ 不覆盖（耗时长，会串行化） |
| I/O | ✘ 不覆盖（可能阻塞，会卡死所有 worker） |

**优化**：统计计数可以改成原子操作，把锁的持有时间进一步缩短：

```c
#include <stdatomic.h>
static atomic_ulong g_done;
atomic_fetch_add_explicit(&g_done, 1, memory_order_relaxed);
```

配合无锁的 SPSC 队列（HFT 标准做法），可以做到**关键路径完全无锁**。
</details>

<details>
<summary>3. `pool_create` 里创建失败时为什么要「只 join 已创建成功的」？</summary>

因为**未初始化 / 创建失败的 `pthread_t` 是垃圾值，对它 `join` 是未定义行为**。

`pthread_create` 失败时（最常见 `EAGAIN`），它**不保证**写入 `tid` 参数。
内核侧 `EAGAIN` 的来源（`kernel/fork.c`）：

- `:2366` —— `RLIMIT_NPROC` / 线程数超过系统上限
- `dup_task_struct()` 内存不足
- 内核栈 `__vmalloc_node_range(THREAD_SIZE)` 失败（`:309`）

如果代码写成：

```c
for (i = 0; i < N; i++)
    pthread_create(&w[i].tid, ...);      /* 不检查返回值 */
...
for (i = 0; i < N; i++)
    pthread_join(w[i].tid, NULL);        /* ← 对垃圾 pthread_t 调用 join = UB */
```

后果可能是：崩溃、join 到不相干的线程（地址复用）、或者静默卡死。

**正确姿势**：

```c
int created = 0;
for (int i = 0; i < N; i++) {
    int rc = pthread_create(&w[i].tid, &attr, worker_main, &w[i]);
    if (rc) { say("create %d 失败: %s", i, strerror(rc)); break; }   /* ★ 立刻停 */
    created++;
}

if (created != N) {
    /* 降级：让已创建的 worker 优雅退出，只 join 它们 */
    pthread_mutex_lock(&p->q_mu);
    p->shutdown = 1;
    pthread_cond_broadcast(&p->q_cv);
    pthread_mutex_unlock(&p->q_mu);
    for (int i = 0; i < created; i++)          /* ★ 循环上界是 created 不是 N */
        pthread_join(w[i].tid, NULL);
    return EAGAIN;
}
```

**另外两处配套**：

1. **`break` 而不是 `continue`** —— 一个失败通常意味着资源已耗尽，继续尝试只会继续失败
2. **已经 `malloc` 的资源要回收** —— 练习 1 里 `free(arg)` 就是同样的道理（谁分配谁负责，失败路径也要走到）

> **生产提醒**：线程池创建失败通常意味着整机资源紧张。
> 宁可**启动时失败、进程退出、由 supervisor 重启**，也不要带着一个残缺的池继续跑——
> 后者会以「莫名其妙的性能下降 + 偶发超时」的形式折磨你几周。
</details>

<details>
<summary>4. 综合题里 `worker` 用 `slot` 下标而不是 `pthread_t` 做身份，为什么？还有哪些稳定 ID 方案？</summary>

**因为 `pthread_t` 在线程终止后会被复用**（练习 3 已证），而且是**不透明类型**，不可移植。

```
  pthread_t = struct pthread *  = 线程栈区高端地址（29.5）
       ↓
  线程终止 + join/detach → glibc __free_tcb() → munmap 整块栈
       ↓
  新建线程再 mmap → 内核很可能返回同一段虚拟地址
       ↓
  你手里那个旧的 pthread_t 现在指向一个完全不相干的线程
```

**四种稳定 ID 方案对比**：

| 方案 | 稳定性 | 可移植 | 与工具对齐 | 适用场景 |
|------|--------|--------|-----------|----------|
| **`slot` 下标**（本综合题） | ✔ 进程内终身唯一 | ✔ | ✘ | **首选**：固定数量 worker、日志/统计、数组索引 |
| **`gettid()` 内核 TID** | ✔ 进程生命周期内唯一 | Linux 专有 | **✔**（`ps -eLf` 的 LWP、perf、gdb） | **日志必打**：排查问题时能直接对上工具输出 |
| **`pthread_self()`** | ✘ 会复用 | ✔ | ✘ | 只用于**线程内临时**调用 `pthread_detach(self)` / `pthread_exit` |
| **`getpid()`** | ✘ **所有线程相同**（返回 TGID） | ✔ | 部分 | 判断「是否同一进程」，不能区分线程 |

**推荐组合**：`slot`（业务身份）+ `gettid()`（诊断身份），两者都打进日志：

```c
struct worker {
    int  slot;      /* 业务身份：w[3] 就是 3 号 worker */
    pid_t ktid;     /* 诊断身份：与 ps/perf/gdb 对齐 */
};

say("worker[%d] tid=%ld 处理订单 %lu", w->slot, (long)w->ktid, order_id);
```

```bash
# 日志里的 tid 可以直接对应到系统工具
ps -eLf | grep trade          # LWP 列 = ktid
top -H -p $(pidof trade)      # 按线程看 CPU
perf top -t <ktid>            # 只采这一个线程
gdb -p $(pidof trade)         # info threads / thread apply all bt
```

**获取内核 TID 的两种方式**：

```c
#define _GNU_SOURCE
#include <sys/syscall.h>
pid_t t1 = syscall(SYS_gettid);     /* 全版本可用 */

/* glibc 2.30+ */
#include <unistd.h>
pid_t t2 = gettid();                /* 需要先定义 _GNU_SOURCE */
```

**⚠ 千万别写成 `getpid()`**：

```c
/* kernel/sys.c:958 */
SYSCALL_DEFINE0(getpid) { return task_tgid_vnr(current); }   /* TGID，所有线程相同 */
/* kernel/sys.c:964 */
SYSCALL_DEFINE0(gettid) { return task_pid_vnr(current); }    /* 内核 pid，每线程不同 */
```

用 `getpid()` 打日志，所有线程的输出 ID 全一样，等于没打。
</details>

<details>
<summary>5. 把这个线程池改造成 HFT 生产级，还需要补什么？逐条给出理由。</summary>

| # | 改造项 | 理由 |
|---|--------|------|
| ① | **任务队列换成 SPSC/MPSC 无锁环形队列** | 互斥锁会让 worker 睡在 futex 上（μs 级）；无锁队列关键路径零系统调用。这是 HFT 与通用线程池最大的区别 |
| ② | **消除伪共享：每个 worker 的统计用 `alignas(64)` 填充** | 相邻 worker 的 `n_done` 落在同一 cache line 上，每次自增都会让对方的 cache line 失效（几十 ns/次，高频下累积成 μs） |
| ③ | **任务参数预分配，运行期零 `malloc`** | `malloc` 有锁竞争 + 可能触发 `mmap`/`brk` 系统调用（μs 级抖动）。用对象池 / 预分配 ring |
| ④ | **绑定物理核（不是逻辑核），并考虑 NUMA** | 超线程的两个逻辑核共享执行单元和 L1/L2；跨 NUMA 访问内存要多几十 ns。配合 `numactl --physcpubind` / `mbind` |
| ⑤ | **`SCHED_FIFO` 分层 + `RLIMIT_RTPRIO` 上界** | 行情 > 策略 > 风控 > 落盘；用 `ulimit -r` 而非 root，且天然防「写错 99 锁死机器」 |
| ⑥ | **栈调小 + guard 调大 + `-fstack-usage` 静态检查** | 8MB/线程在几十个线程时 VIRT 就到几百 MB；64KB guard 挡住常见大帧；静态分析治本 |
| ⑦ | **关停用 `timedjoin_np` + `pthread_cancel` 兜底 + 最后 `_exit()`** | 保证进程一定能退干净，不会卡在关停上 |
| ⑧ | **启动期建好所有线程，运行期零 `pthread_create`/`join`/`detach`** | 创建成本（~20-50μs）绝不能出现在关键路径 |
| ⑨ | **每 worker 记录栈水位并打点告警** | 栈溢出是「栈顶被破坏、回溯无意义」的最难查 bug（练习 5） |
| ⑩ | **日志走独立进程 + 无锁队列，绝不在关键路径 `printf`** | `printf` 有 stdio 锁 + 可能触发 `write` 系统调用（μs 级）。用异步日志线程，Critical 路径只往 ring buffer 写一条 |
| ⑪ | **禁用 `malloc` 之外的所有系统调用**：预 `mlockall(MCL_CURRENT\|MCL_FUTURE)` | 缺页（major fault）是毫秒级抖动。见 Ch50 虚拟内存 |
| ⑫ | **热路径绝不 `fork`** | `dup_mm()` 成本与虚拟内存大小成正比，几十 GB 的进程 fork 一次要毫秒级（29.9） |

**目标形态**：

```
  启动期：mlockall → 预分配所有池 → 建 N 个 worker（绑核 + FIFO + 小栈 + 大 guard）
          → 预热（跑空任务把代码/数据都拉进 cache）

  运行期：行情线程 ─[SPSC 无锁 ring]─→ 策略线程 ─[SPSC ring]─→ 风控线程
          全程零系统调用、零锁、零分配、零缺页

  关停：置 shutdown → broadcast → timedjoin(5s) → cancel 兜底 → _exit()
```

> **诚实的评估**：这套东西的复杂度比通用线程池高一个数量级，
> 只有在**端到端预算 < 10μs 且 P99.9 有硬要求**时才值得。
> 大多数场景用本综合题的版本 + 无锁队列就够了。
</details>
