# 29.6 连接已终止的线程（`pthread_join`）

## 本节讲什么

1. `pthread_join()` 做三件事：**等待结束 + 取返回值 + 回收资源**——三者是一体的
2. 它不是轮询：内核在线程退出时**自动**清 TID 并 futex-wake，`join` 只是睡在 futex 上等
3. 不 join 也不 detach 会怎样（「僵尸线程」的真相），以及为什么内核层其实很干净

---

## 一、接口与语义

```c
#include <pthread.h>

int pthread_join(pthread_t thread, void **retval);
/* 返回 0 成功；失败返回正错误码 */
```

| 参数 | 说明 |
|------|------|
| `thread` | 要连接的线程。**必须是可接合的（joinable）** |
| `retval` | 出参，接收线程的退出状态（`pthread_exit` 的返回值或 `return` 的值）。**不关心就传 `NULL`** |

**语义**：阻塞调用线程，直到 `thread` 终止；然后取回其退出状态，并**释放该线程的资源**。

```
  主线程                                    worker
  ───────                                  ──────
  pthread_join(t, &r)                      正在干活
       │                                      │
       ├─ 读 t 的 tid 字段：非 0              │
       ├─ futex_wait(&tid)  ← 睡在这里        │
       │         ⋮                            ├─ 干完了
       │         ⋮                            ├─ pthread_exit(retval)
       │         ⋮                            ↓
       │         ⋮                      内核 mm_release():
       │         ⋮                        ① put_user(0, &tid)      ← TID 清零
       │         ⋮                        ② futex_wake(&tid, 1)    ← 唤醒 joiner
       ↓         ⋮                            ↓
  被唤醒，读 tid==0                       task_struct 回收（autoreap）
       │
       ├─ 取回 retval
       ├─ 释放线程栈等 glibc 资源
       ↓
  pthread_join 返回 0，主线程继续
```

## 二、`pthread_join` 的三重身份

它一个调用干了三件事，这也是为什么**不 join 会出问题**：

| 作用 | 说明 | 不做会怎样 |
|------|------|-----------|
| **① 同步** | 阻塞等待目标线程结束 | 没法知道线程何时完成 |
| **② 取返回值** | 拿到 `pthread_exit` 的 `retval` | 拿不到退出状态/计算结果 |
| **③ 回收资源** | 释放 glibc 的线程描述符和栈 | **资源泄漏**（见下） |

### ③ 是「必须 join 或 detach」的真正原因

回顾 [29.4](29.4-thread-termination.md)：**内核层其实很干净**——
`exit_notify()` 对非线程组 leader 恒 `autoreap = true`，`task_struct` 立即释放：

```c
/* kernel/exit.c:746-751 */
	} else if (thread_group_leader(tsk)) {
		autoreap = thread_group_empty(tsk) &&
			do_notify_parent(tsk, tsk->exit_signal);
	} else {
		autoreap = true;                    /* 普通线程：直接回收 */
	}

	if (autoreap) {
		tsk->exit_state = EXIT_DEAD;        /* 不是 ZOMBIE */
		...
		release_task(p);                     /* task_struct 立即释放 */
	}
```

**泄漏的是 glibc 层的用户态资源**：

```
  可接合线程结束但没人 join：

    内核层：  task_struct 已释放 ✓          （autoreap）
    glibc 层：struct pthread + 8MB 栈【保留】✗
              （退出返回值要留给 join 来取）

  → 反复这样会持续泄漏虚拟内存，VIRT 不断上涨，
    最终 pthread_create 返回 EAGAIN
```

```
  观察方法：
    $ cat /proc/PID/status | grep VmSize     # 持续上涨
    $ top -p <pid>                            # 看 VIRT 列
```

## 三、内核机制：`CLONE_CHILD_CLEARTID` + futex

这是 `pthread_join()` 最精巧的部分——**它不需要任何额外的系统调用来"通知"等待者**。

### 第一步：创建时登记地址

`pthread_create()` 传了 `CLONE_CHILD_CLEARTID`，内核记下「线程退出时要清哪个地址」：

```c
/* kernel/fork.c:2351 */
	p->clear_child_tid = (clone_flags & CLONE_CHILD_CLEARTID) ? args->child_tid : NULL;
```

这个地址指向**线程描述符里的 `tid` 字段**（glibc 安排的）。

### 第二步：退出时内核自动清理 + 唤醒

```c
/* kernel/fork.c:1616 */
static void mm_release(struct task_struct *tsk, struct mm_struct *mm)
{
	uprobe_free_utask(tsk);

	/* Get rid of any cached register state */
	deactivate_mm(tsk, mm);

	/*
	 * Signal userspace if we're not exiting with a core dump
	 * because we want to leave the value intact for debugging
	 * purposes.
	 */
	if (tsk->clear_child_tid) {
		if (atomic_read(&mm->mm_users) > 1) {           /* ← 还有别的线程活着 */
			/*
			 * We don't check the error code - if userspace has
			 * not set up a proper pointer then tough luck.
			 */
			put_user(0, tsk->clear_child_tid);       /* ① TID 写 0 */
			do_futex(tsk->clear_child_tid, FUTEX_WAKE,
					1, NULL, NULL, 0, 0);            /* ② 唤醒 1 个等待者 */
		}
		tsk->clear_child_tid = NULL;
	}

	/* All done, finally we can wake up parent and return this mm to him. */
	if (tsk->vfork_done)
		complete_vfork_done(tsk);
}
```

**两个关键细节**：

**① `atomic_read(&mm->mm_users) > 1` 这个条件**

如果这是**最后一个线程**（整个进程要退出了），就**不做**清 TID + wake：
- 没有人在等（joiner 自己也是线程，它也退了）
- 地址空间马上要被拆除，`put_user()` 会失败

**② 注释里那句 "if userspace has not set up a proper pointer then tough luck"**

内核**不检查 `put_user()` 的返回值**——如果用户态给的地址是垃圾，内核也不会报错。
这是"用户态自己负责"的内核惯例（GIGO：garbage in, garbage out）。

### 第三步：join 侧的等待

glibc 的 `pthread_join()` 大致逻辑：

```c
/* glibc 的 pthread_join（概念版，非源码）*/
int pthread_join(pthread_t thread, void **retval)
{
    struct pthread *pd = (struct pthread *)thread;

    /* ① 已经在跑完的状态？直接回收 */
    if (pd->tid == 0)
        goto cleanup;

    /* ② 睡在 tid 字段上，直到它被内核清零 */
    while (pd->tid != 0) {
        /* futex_wait: 如果 *(&pd->tid) == pd->tid 就睡；
           内核退出路径会把它改成 0 并 FUTEX_WAKE 唤醒我们 */
        futex_wait(&pd->tid, pd->tid);
    }

cleanup:
    /* ③ 取返回值 */
    if (retval)
        *retval = pd->result;
    /* ④ 释放栈等资源 */
    free_stuff(pd);
    return 0;
}
```

**为什么用 futex 而不是轮询或信号量？**

| 方案 | 无竞争开销 | 有竞争开销 | 说明 |
|------|-----------|-----------|------|
| 轮询 `while (tid != 0)` | 0（但烧 CPU） | 极高 | 浪费一个核 |
| 信号量/条件变量 | 每次都进内核 | 进内核 | 无竞争时白付系统调用成本 |
| **futex** | **0**（纯用户态 cmpxchg） | 进内核 | **快路径不进内核** |

futex（Fast Userspace muTEX）的核心思想：**无竞争时全部在用户态用一个原子操作解决，
只有真的要睡眠/唤醒才进内核**。系统调用入口是 `SYSCALL_DEFINE6(futex)`（`kernel/futex/syscalls.c:164`）。

## 四、joinable vs detached

| | **joinable（默认）** | **detached** |
|---|---------------------|--------------|
| 创建方式 | 默认，或 `PTHREAD_CREATE_JOINABLE` | `pthread_detach()` 或属性 `PTHREAD_CREATE_DETACHED` |
| 结束后资源 | **必须 `pthread_join` 才释放** | 自动释放 |
| 能取返回值 | ✅ | ❌ |
| 能 `pthread_join` 吗 | ✅ | ❌ 返回 `EINVAL` |
| 能 `pthread_detach` 吗 | ✅（join 之前） | ❌ 返回 `EINVAL` |
| 用途 | 需要返回值 / 需要确认结束 | 后台任务、不关心结果（如日志线程） |

```
  线程的两种归宿（互斥，二选一）

  ┌──────────────┐
  │  线程创建     │
  └──────┬───────┘
         │
    ┌────┴────┐
    ▼         ▼
 joinable   detached
    │         │
    │         └─ 结束时内核+glibc 自动回收，无需干预
    │
    ├─ 有人 join → 取返回值 + 回收 ✓
    └─ 无人 join → glibc 层资源泄漏 ✗
```

**判断规则**：**需要知道线程什么时候结束、或需要它的结果 → joinable；否则 detached。**

## 五、错误码与常见误用

| 错误码 | 场景 |
|--------|------|
| `EDEADLK` (35) | **自己 join 自己**，或 A join B 同时 B join A（死锁） |
| `EINVAL` (22) | 目标线程是 **detached** 的（不能 join） |
| `ESRCH` (3) | 找不到该 `pthread_t` 对应的线程（可能已 join 过，或 `pthread_t` 失效） |
| `EDEADLK` | 某些实现上也用于「join 一个已经 join 过的线程」（glibc 通常给 `ESRCH`） |

```c
/* ✗ 自连接 */
static void *worker(void *arg)
{
    pthread_join(pthread_self(), NULL);      /* EDEADLK */
}

/* ✗ 循环等待 */
/* 线程 A: pthread_join(B, NULL);  线程 B: pthread_join(A, NULL);  → 死锁 */

/* ✗ join 一个 detached 线程 */
pthread_attr_t attr;
pthread_attr_init(&attr);
pthread_attr_setdetachstate(&attr, PTHREAD_CREATE_DETACHED);
pthread_create(&t, &attr, w, NULL);
int rc = pthread_join(t, NULL);     /* EINVAL */

/* ✗ 重复 join */
pthread_join(t, NULL);              /* 成功 */
rc = pthread_join(t, NULL);         /* ESRCH 或 EINVAL */
```

⚠️ **注意 `pthread_t` 复用带来的隐蔽错误**（见 [29.5](29.5-thread-ids.md)）：
线程结束后它的 `pthread_t` 可能被新线程复用。此时对着旧的 `pthread_t` 调 `join`，
**可能 join 到一个无关的线程**，而不是返回 `ESRCH`。这是真实存在的 bug 来源。

**防御习惯**：join 完就不再使用那个 `pthread_t`；需要长期标识用 TID。

## 六、返回值的坑

```c
int pthread_join(pthread_t thread, void **retval);
```

**`retval` 指向的内存必须在线程结束后仍有效**——
绝不能返回指向**线程自己栈**的指针（见 [29.4](29.4-thread-termination.md)）：

```c
/* ✗ 致命 */
static void *worker(void *arg)
{
    int result = 42;
    return &result;          /* 线程结束，栈释放 */
}

/* ✓ 三种正确做法 */
static void *w1(void *a) { (void)a; return (void *)(intptr_t)42; }   /* 整数编码 */
static void *w2(void *a) { (void)a; static int r = 42; return &r; }  /* 静态变量 */
static void *w3(void *a) { int *p = malloc(sizeof(int)); *p = 42; return p; }  /* 堆，调用方 free */
```

**不关心返回值就传 `NULL`**：

```c
pthread_join(t, NULL);       /* 只等待 + 回收，不取返回值 */
```

⚠️ 传 `NULL` **仍然会回收资源**——「回收」是 join 的固有职责，与取不取返回值无关。

## 七、批量 join 与线程池

```c
/* 顺序 join：等第一个结束才等第二个 —— 总耗时 = 最长的那个（其实更早结束的早就完了）*/
for (int i = 0; i < N; i++)
    pthread_join(t[i], &r[i]);
```

顺序 join 是**正确且够用**的：所有线程并行跑，join 只是依次收取结果。
如果线程 0 最后才结束，前面的 join 会先返回（因为线程 1..N 早就结束了），
所以总等待时间 = `max(各线程耗时)`，不是总和。

```
  线程0: ████████████
  线程1: ███
  线程2: ██████
           ↑
    join(0) 阻塞到 12 秒
    join(1) 立即返回（3 秒时就结束了）
    join(2) 立即返回（6 秒时就结束了）
  → 总耗时 12 秒，不是 21 秒
```

**线程池的正确形态**（反复创建销毁是反模式）：

```c
/* 启动时建好，运行时只分发任务 */
for (int i = 0; i < N; i++)
    pthread_create(&pool[i], NULL, worker_loop, &ctx[i]);

/* ... 运行 ... */

/* 关闭时：先通知，再 join */
atomic_store(&shutdown, 1);
pthread_cond_broadcast(&work_cv);
for (int i = 0; i < N; i++)
    pthread_join(pool[i], NULL);        /* 一次性回收全部 */
```

## HFT / 嵌入式关联

| 路线 | 要点 |
|------|------|
| 嵌入式 | ① **长期运行的服务漏 join 会持续泄漏 8MB/线程**，256MB 设备上几十次就撑爆 → 标准解法是「创建即 detached」或「启动建池、关闭时统一 join」。② `pthread_join` 会**阻塞调用线程**，在只有单核或核数紧张的设备上要注意别把所有线程都堵在 join 上。③ 用 `pthread_timedjoin_np()`（glibc 扩展）加超时，避免永久卡住 |
| HFT | ① **`pthread_join` 只用于启动/关闭，绝不在关键路径上调用**。无竞争时它的快路径是纯用户态（十几 ns），但**只要目标线程还没结束就要进 futex 睡眠**——唤醒是调度器级的（数 µs 起）。② **关闭序列里的 join 必须有超时预案**：某个 worker 卡在 I/O 上（D 状态）会让整个关闭流程永久阻塞。用 `pthread_timedjoin_np()` 超时后记录告警并继续，最后可 `_exit()` 兜底。③ **join 能拿到返回值 = 天然的"任务完成确认"**，比另搞一套状态标志更可靠。④ 线程池里 worker 永不退出（跑整个进程生命周期），**只在进程关闭时 join 一次**——这样 join 的开销完全不出现在关键路径上。⑤ 注意「最后一个线程退出父进程才收 `SIGCHLD`」（[29.4](29.4-thread-termination.md)），监控进程的超时判据要按这个来设 |

## 代码示例：join 的完整用法

```c
/* pthread_join_demo.c —— join 的语义、返回值、错误码与泄漏演示
 *
 * 编译: gcc -Wall -Wextra -O2 -pthread -o pjd pthread_join_demo.c
 * 运行: ./pjd
 */
#define _GNU_SOURCE
#include <stdio.h>
#include <stdlib.h>
#include <stdint.h>
#include <string.h>
#include <pthread.h>
#include <unistd.h>
#include <errno.h>
#include <sys/syscall.h>
#include <time.h>

static pid_t gettid_(void) { return (pid_t)syscall(SYS_gettid); }

static double now_s(void)
{
    struct timespec ts;
    clock_gettime(CLOCK_MONOTONIC, &ts);
    return ts.tv_sec + ts.tv_nsec / 1e9;
}

/* ── 演示 1：join 取返回值 ─────────────────────────── */
static void *compute(void *arg)
{
    long n = (long)arg;
    long result = n * n;
    printf("  [计算] 线程 %ld (tid=%d): %ld² = %ld\n", n, gettid_(), n, result);
    return (void *)result;           /* 整数编码，安全 */
}

static void demo_retval(void)
{
    pthread_t t[3];
    printf("\n【演示 1】join 取返回值\n");

    for (long i = 1; i <= 3; i++)
        pthread_create(&t[i - 1], NULL, compute, (void *)i);

    for (int i = 0; i < 3; i++) {
        void *r;
        pthread_join(t[i], &r);
        printf("  join[%d] 得到: %ld\n", i, (long)r);
    }
}

/* ── 演示 2：join 的等待时间 = max，不是 sum ───────── */
static void *sleep_worker(void *arg)
{
    int sec = (int)(intptr_t)arg;
    sleep((unsigned)sec);
    printf("  [睡眠] 睡 %d 秒的线程结束 (tid=%d)\n", sec, gettid_());
    return NULL;
}

static void demo_join_max_not_sum(void)
{
    pthread_t t[3];
    int secs[3] = { 3, 1, 2 };
    double t0;

    printf("\n【演示 2】join 总耗时 = max(各线程)，不是 sum\n");
    t0 = now_s();
    for (int i = 0; i < 3; i++)
        pthread_create(&t[i], NULL, sleep_worker, (void *)(intptr_t)secs[i]);

    for (int i = 0; i < 3; i++) {
        pthread_join(t[i], NULL);
        printf("  join[%d] 返回，已耗时 %.2f 秒\n", i, now_s() - t0);
    }
    printf("  总耗时 %.2f 秒  ← max(3,1,2)=3，不是 3+1+2=6\n", now_s() - t0);
}

/* ── 演示 3：错误码 ───────────────────────────────── */
static void *quitter(void *arg) { (void)arg; return NULL; }

static void demo_errors(void)
{
    pthread_t t;
    int rc;

    printf("\n【演示 3】join 的错误码\n");

    /* ① join detached 线程 → EINVAL */
    pthread_attr_t attr;
    pthread_attr_init(&attr);
    pthread_attr_setdetachstate(&attr, PTHREAD_CREATE_DETACHED);
    pthread_create(&t, &attr, quitter, NULL);
    sleep(1);                                  /* 让它跑完 */
    rc = pthread_join(t, NULL);
    printf("  join(detached)      → rc=%d (%s)\n", rc, strerror(rc));
    pthread_attr_destroy(&attr);

    /* ② 重复 join → ESRCH（或其他）*/
    pthread_create(&t, NULL, quitter, NULL);
    pthread_join(t, NULL);
    rc = pthread_join(t, NULL);
    printf("  第二次 join(同一个)  → rc=%d (%s)\n", rc, strerror(rc));

    /* ③ 自 join → EDEADLK */
    rc = pthread_join(pthread_self(), NULL);
    printf("  join(pthread_self)  → rc=%d (%s)\n", rc, strerror(rc));
}

/* ── 演示 4：不 join 的资源泄漏 ───────────────────── */
static unsigned long get_vmsize_kb(void)
{
    FILE *f = fopen("/proc/self/status", "r");
    char line[256];
    unsigned long v = 0;
    if (!f) return 0;
    while (fgets(line, sizeof(line), f))
        if (strncmp(line, "VmSize:", 7) == 0) { sscanf(line + 7, "%lu", &v); break; }
    fclose(f);
    return v;
}

static void *noop(void *arg) { (void)arg; return NULL; }

static void demo_leak(void)
{
    unsigned long before = get_vmsize_kb();

    printf("\n【演示 4】不 join 不 detach 的后果\n");
    printf("  创建 100 个「跑完就结束」的线程，从不回收...\n");

    for (int i = 0; i < 100; i++) {
        pthread_t t;
        pthread_create(&t, NULL, noop, NULL);
        /* 故意不 join，不 detach */
    }
    sleep(1);

    unsigned long after = get_vmsize_kb();
    printf("  VmSize: %lu KB → %lu KB  (+%lu KB，约 %.1f MB)\n",
           before, after, after - before, (after - before) / 1024.0);
    printf("  → 内核 task_struct 已回收（autoreap），泄漏的是【glibc 的线程栈】\n");
    printf("  → 反复这样最终会让 pthread_create 返回 EAGAIN\n");
}

int main(void)
{
    printf("主线程: pid=%d tid=%d\n", getpid(), gettid_());

    demo_retval();
    demo_join_max_not_sum();
    demo_errors();
    demo_leak();

    return 0;
}
```

**预期输出要点**：

```
【演示 1】join 取返回值
  [计算] 线程 1 (tid=12346): 1² = 1
  [计算] 线程 2 (tid=12347): 2² = 4
  join[0] 得到: 1
  join[1] 得到: 4
  ...

【演示 2】join 总耗时 = max，不是 sum
  join[0] 返回，已耗时 3.00 秒       ← 等的是 3 秒那个
  join[1] 返回，已耗时 3.00 秒       ← 1 秒的早就完了，立即返回
  join[2] 返回，已耗时 3.00 秒
  总耗时 3.00 秒  ← max(3,1,2)=3

【演示 3】join 的错误码
  join(detached)      → rc=22 (Invalid argument)      ← EINVAL
  第二次 join(同一个)  → rc=3 (No such process)         ← ESRCH
  join(pthread_self)  → rc=35 (Resource deadlock avoided)  ← EDEADLK

【演示 4】不 join 不 detach 的后果
  VmSize: 12345 KB → 835678 KB  (+823333 KB，约 804 MB)
  → 泄漏的是【glibc 的线程栈】
```

## 代码自测

<details>
<summary><b>问 1：</b><code>pthread_join()</code> 是怎么「感知」到线程结束的？是轮询吗？</summary>

**不是轮询，内核在线程退出的必经之路上自动完成了通知。**

三个 `CLONE_*` 标志配合，内核在两个时机操作**同一个用户态地址**
（glibc 线程描述符里的 `tid` 字段）：

### 创建时：登记地址

```c
/* kernel/fork.c:2351 */
	p->clear_child_tid = (clone_flags & CLONE_CHILD_CLEARTID) ? args->child_tid : NULL;
```

（`CLONE_CHILD_SETTID` 则在 `:2347` 记下「新线程启动时要写哪个地址」）

### 退出时：清零 + 唤醒

```c
/* kernel/fork.c:1616 */
static void mm_release(struct task_struct *tsk, struct mm_struct *mm)
{
	...
	if (tsk->clear_child_tid) {
		if (atomic_read(&mm->mm_users) > 1) {           /* 还有别的线程活着 */
			put_user(0, tsk->clear_child_tid);      /* ① TID 写 0 */
			do_futex(tsk->clear_child_tid, FUTEX_WAKE,
					1, NULL, NULL, 0, 0);           /* ② 唤醒 1 个等待者 */
		}
		tsk->clear_child_tid = NULL;
	}
	...
}
```

`mm_release()` 是**每个任务退出的必经之路**（由 `exit_mm_release()` 调用，
`kernel/fork.c:1649-1652`），所以不需要任何额外机制。

### join 侧：睡在 futex 上

```c
/* glibc pthread_join 的概念逻辑 */
while (pd->tid != 0)
    futex_wait(&pd->tid, pd->tid);      /* 值还是 tid → 睡 */
/* 内核把它改成 0 并 FUTEX_WAKE → 循环退出 */
```

futex 系统调用入口：`SYSCALL_DEFINE6(futex)`（`kernel/futex/syscalls.c:164`）。

**关键洞察**：`futex_wait(&tid, 预期值)` 是**原子地**「检查值 + 睡眠」。
如果线程在 `futex_wait` 之前就结束了（tid 已被清零），
值比较失败 → futex 立即返回 `EAGAIN` → join 立即完成。
**没有丢失唤醒的窗口**，这正是 futex 存在的意义。

### 为什么这个设计好

| 方案 | 无竞争开销 | 有竞争开销 |
|------|-----------|-----------|
| 轮询 `while (tid != 0)` | 烧 100% CPU | 极高 |
| 信号量/条件变量 | 每次进内核 | 进内核 |
| **futex** | **0**（纯用户态原子操作） | 进内核 |

futex（Fast Userspace muTEX）的核心：**无竞争时全部在用户态解决，
只有真要睡眠/唤醒才进内核**。这也是 `pthread_mutex` 的底层——
无竞争的加锁解锁完全不进内核（十几 ns）。

> ⚠️ 注意 `atomic_read(&mm->mm_users) > 1` 这个条件：如果是**最后一个**线程，
> 就不做清 TID + wake（没人在等，且地址空间马上拆除，`put_user` 会失败）。

</details>

<details>
<summary><b>问 2：</b>「僵尸线程」是什么？内核里真的有僵尸线程吗？</summary>

**内核里没有僵尸线程。** 这个说法指的是 **glibc 层的资源没释放**。

### 内核层：线程根本不进僵尸态

```c
/* kernel/exit.c:727 */
static void exit_notify(struct task_struct *tsk, int group_dead)
{
	bool autoreap;
	...
	tsk->exit_state = EXIT_ZOMBIE;              /* 先假定 */
	...
	if (unlikely(tsk->ptrace)) {
		...
	} else if (thread_group_leader(tsk)) {
		autoreap = thread_group_empty(tsk) &&   /* ① 只有最后一个线程 */
			do_notify_parent(tsk, tsk->exit_signal);
	} else {
		autoreap = true;                        /* ② 普通线程：恒 true */
	}

	if (autoreap) {
		tsk->exit_state = EXIT_DEAD;            /* ← DEAD 不是 ZOMBIE */
		list_add(&tsk->ptrace_entry, &dead);
	}
	...
	release_task(p);                            /* 立即释放 task_struct */
}
```

普通线程 = 非线程组 leader → `autoreap = true` → 直接 `EXIT_DEAD` → 立即 `release_task()`。
**内核的 `task_struct` 当场回收，不保留任何退出状态可供 `wait()`**。

配合另一条：线程退出**不发 `SIGCHLD`**（`copy_process():2632-2633` 的 `exit_signal = -1`）。

### glibc 层：栈和线程描述符留着等 join

```
  可接合线程结束，无人 join：

    内核层：  task_struct        已释放 ✓
    glibc 层：struct pthread    保留 ✗
             8MB 线程栈         保留 ✗
             （退出返回值要留给 join 来取）
```

**这才是"僵尸线程"的真实含义**——不是内核的僵尸进程，是**用户态内存泄漏**。

### 症状与诊断

```
  $ cat /proc/PID/status | grep VmSize     # 持续上涨
  $ top -p <pid>                           # VIRT 列不断变大，RSS 变化不大
```

- **VIRT 涨、RSS 不涨**：因为 8MB 栈是虚拟内存，实际只提交了用到的页
- 但**虚拟地址空间是有限资源**（32 位进程 4GB → 500 个线程就到顶）
- 最终 `pthread_create` 返回 `EAGAIN`

### 修法（二选一）

```c
/* ① 需要结果/确认结束 → join */
void *r;
pthread_join(t, &r);

/* ② 不需要 → detach（推荐：创建时就指定，无竞态窗口）*/
pthread_attr_t attr;
pthread_attr_init(&attr);
pthread_attr_setdetachstate(&attr, PTHREAD_CREATE_DETACHED);
pthread_create(&t, &attr, w, NULL);
pthread_attr_destroy(&attr);
```

> **对比真正的僵尸进程**：僵尸进程是内核保留 `task_struct` 等父进程 `wait()`，
> 占用的是**内核内存和 PID 资源**；"僵尸线程"占用的是**用户态虚拟内存**。
> 两者机制完全不同，只是症状相似（资源不释放）。

</details>

<details>
<summary><b>问 3：</b><code>pthread_join(t1)</code> → <code>pthread_join(t2)</code> 顺序等待，总耗时是两者之和吗？</summary>

**不是，是 max(两者耗时)。**

```
  线程1: ████████████ (12s)
  线程2: ███          (3s)
            ↑ 3s 时线程2 就结束了，它【保持结束状态】等 join
  join(t1) → 阻塞到 12s
  join(t2) → 立即返回（t2 早在 3s 时就结束了）
  总耗时 = 12s，不是 15s
```

**为什么？** 因为线程结束后（无人 join 时）**不会消失**——
它的 `task_struct` 被内核回收了，但 **glibc 的线程描述符和退出状态还留着**，
等 join 来取。所以后 join 的那个能立即拿到结果。

**这个性质带来的实践结论**：

```c
/* 常见的「启动 N 个并行任务，全部收工」写法是完全正确的 */
for (int i = 0; i < N; i++)
    pthread_create(&t[i], NULL, worker, &jobs[i]);
for (int i = 0; i < N; i++)
    pthread_join(t[i], &results[i]);      /* 总耗时 = 最慢的那个 */
```

不需要额外的屏障或计数——**顺序 join 就是标准的"等待全部完成"**。

```
  反过来说，如果想【尽早】知道谁先完成并立刻处理结果，
  顺序 join 做不到（它按数组顺序等）。这时要用：
    · 条件变量 + 完成队列
    · 或者让 worker 直接把结果写进自己的 slot，主线程最后统一收
```

**注意一个陷阱**：顺序 join 时，如果 `t[0]` 特别慢，而 `t[1..N]` 早就结束了，
那么 `t[1..N]` 的**资源会一直挂着**直到 main 走到它们的 join。
通常无所谓（进程要退出了），但在长期运行的服务里要注意：
**及时 join 掉的线程才会释放栈**。

**HFT 场景**：worker 线程通常跑整个进程生命周期（永不结束），
只在关闭时 join 一次。这样 join 完全不出现在关键路径上。
需要"等待某批任务完成"时用条件变量或原子计数，而不是 join。

</details>

<details>
<summary><b>问 4：</b>哪些情况 <code>pthread_join</code> 会失败？各自什么原因？</summary>

| 错误码 | 场景 | 内核/glibc 层面原因 |
|--------|------|-------------------|
| `EDEADLK` (35) | **自连接**（`pthread_join(pthread_self(), NULL)`），或 A↔B 循环等待 | glibc 检测出会死锁，直接返回而不是真卡住 |
| `EINVAL` (22) | 目标线程是 **detached** 的 | detached 线程的资源自动回收，没有"可 join 的退出状态" |
| `ESRCH` (3) | 找不到对应的线程 | 已经 join 过；或 `pthread_t` 无效 |
| `EINVAL` | 目标线程**已经被别的线程 join 了**（某些实现） | 一个线程只能被 join 一次 |

### ⚠️ 最危险的情况：`pthread_t` 复用

上面都是"明确报错"的好情况。真正危险的是**不报错但操作错对象**：

```c
pthread_t old_t;
pthread_create(&old_t, NULL, w, NULL);
pthread_join(old_t, NULL);        /* OK */

/* ... 后来又创建了一堆线程 ... */

pthread_join(old_t, NULL);        /* 可能是 ESRCH，
                                     也可能【join 到了复用了这块栈的新线程】！*/
```

原因见 [29.5](29.5-thread-ids.md)：`pthread_t` 在 glibc 上就是**线程栈的地址**，
线程结束后栈被 `munmap`（或进 glibc 的栈缓存），
新线程很可能拿到**同一块地址** → `pthread_t` 相同。

```
  线程 A: pthread_t = 0x7f8a4c000700   结束 → 栈释放
  线程 B: pthread_t = 0x7f8a4c000700   ← 复用

  对着 A 的旧 pthread_t 调 join/cancel
  → 实际操作的是 B！不报错，静默出错
```

**防御习惯**：

1. **join 完就不再使用那个 `pthread_t`**（设为 0 或移出作用域）
2. 需要长期标识线程 → 用 **TID**（`gettid()`），内核保证不与活跃线程冲突
3. 更推荐：用**自己的线程编号**（0,1,2…）做业务索引，TID 只用于和系统工具对照

### 其他要注意的

```c
/* ① join 的线程必须存在过 */
pthread_t t;                       /* 未初始化 */
pthread_join(t, NULL);             /* 未定义行为，可能崩溃 */

/* ② join 会被信号打断吗？ */
/* pthread_join 不是「慢系统调用」，它不返回 EINTR。
   被信号打断时 glibc 会内部重启（表现为 join 继续等待）。
   → 不能在 handler 里指望打断 join；要可中断的等待用
     pthread_timedjoin_np（glibc 扩展）或条件变量 */

/* ③ 带超时的 join（glibc 扩展）*/
#define _GNU_SOURCE
struct timespec ts;
clock_gettime(CLOCK_REALTIME, &ts);
ts.tv_sec += 5;
int rc = pthread_timedjoin_np(t, &r, &ts);
if (rc == ETIMEDOUT) { /* 超时，线程还没结束 */ }
```

> **HFT 实践**：关闭流程里的 join 一定要有超时预案。
> 某个 worker 卡在 D 状态（不可中断睡眠）会让 join 永久阻塞，
> `pthread_timedjoin_np` 超时后记录告警并继续，最后用 `_exit()` 兜底。

</details>

<details>
<summary><b>问 5：</b>写一个「启动 N 个 worker、跑完后收集全部结果」的标准模板。</summary>

```c
/* worker_pool.c —— 标准模板：启动 N 个 worker，收集全部结果
 *
 * 编译: gcc -Wall -Wextra -O2 -pthread -o wp worker_pool.c
 */
#define _GNU_SOURCE
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <stdint.h>
#include <pthread.h>
#include <errno.h>
#include <sys/syscall.h>

#define NWORKERS 4
#define NJOBS    100

/* ── 任务与结果 ───────────────────────────────────── */

struct job {
    int   id;
    long  input;
    long  result;        /* worker 直接写进自己的 slot —— 无需返回值传递 */
    int   rc;            /* 0 成功 */
};

static struct job jobs[NJOBS];
static _Atomic int next_job = 0;              /* 原子分发，无锁 */

/* ── worker：抢任务 → 干活 → 写自己的 slot ─────────── */

static void *worker(void *arg)
{
    long wid = (long)arg;
    long done = 0;

    printf("  worker %ld (tid=%d) 启动\n", wid, (int)syscall(SYS_gettid));

    for (;;) {
        int idx = atomic_fetch_add(&next_job, 1);     /* 原子抢一个任务 */
        if (idx >= NJOBS)
            break;

        struct job *j = &jobs[idx];

        /* 干活（这里用平方模拟）*/
        j->result = j->input * j->input;
        j->rc = 0;
        done++;
    }

    printf("  worker %ld 完成 %ld 个任务\n", wid, done);

    /* 返回值用整数编码，安全（不指向自己的栈）*/
    return (void *)done;
}

/* ── 主：建线程 → join 收结果 ───────────────────────── */

int main(void)
{
    pthread_t pool[NWORKERS];
    int       create_failed = 0;

    /* ① 初始化任务数组 */
    for (int i = 0; i < NJOBS; i++) {
        jobs[i].id    = i;
        jobs[i].input = i + 1;
        jobs[i].rc    = -1;              /* 标记未完成 */
    }

    /* ② 启动 worker（检查每一个返回值！）*/
    for (long i = 0; i < NWORKERS; i++) {
        int rc = pthread_create(&pool[i], NULL, worker, (void *)i);
        if (rc != 0) {                   /* ← 用 != 0，不是 < 0 */
            fprintf(stderr, "pthread_create(%ld) 失败: %s\n", i, strerror(rc));
            pool[i] = 0;                 /* 标记为无效 */
            create_failed++;
        }
    }

    /* ③ 顺序 join 收集结果（总耗时 = 最慢的 worker）*/
    long total = 0;
    for (int i = 0; i < NWORKERS; i++) {
        if (pool[i] == 0)                /* 跳过创建失败的 */
            continue;

        void *r = NULL;
        int rc = pthread_join(pool[i], &r);
        if (rc != 0) {
            fprintf(stderr, "pthread_join(%d) 失败: %s\n", i, strerror(rc));
            continue;
        }
        total += (long)r;
        /* join 完不再使用 pool[i] —— 防御 pthread_t 复用 */
    }

    /* ④ 校验结果 */
    int incomplete = 0;
    for (int i = 0; i < NJOBS; i++)
        if (jobs[i].rc != 0) incomplete++;

    printf("\n  共完成 %ld 个任务（期望 %d）\n", total, NJOBS);
    printf("  未完成: %d\n", incomplete);
    printf("  抽查: job[0]: %ld² = %ld\n", jobs[0].input, jobs[0].result);
    printf("        job[99]: %ld² = %ld\n", jobs[99].input, jobs[99].result);

    return (total == NJOBS) ? 0 : 1;
}
```

### 模板的六个要点

| # | 要点 | 为什么 |
|---|------|--------|
| ① | **任务分发用原子计数器** | 无锁、自动负载均衡（快手多干） |
| ② | **结果写进自己的 slot**，不用返回值 | 生命周期清晰；也支持"哪个线程干的"的追溯 |
| ③ | **检查每个 `pthread_create` 返回值** | `EAGAIN` 真的会发生；用 `!= 0` 判断 |
| ④ | **失败的线程要标记并跳过 join** | 否则 join 一个未初始化的 `pthread_t` = 未定义行为 |
| ⑤ | **顺序 join 即可** | 总耗时 = max，不是 sum（见问 3） |
| ⑥ | **join 完不再使用 `pthread_t`** | 防御栈地址复用（见问 4） |

### 变体：需要超时/可取消的关闭

```c
/* 关闭时：先通知，再带超时 join */
atomic_store(&shutdown, 1);

for (int i = 0; i < NWORKERS; i++) {
    struct timespec ts;
    clock_gettime(CLOCK_REALTIME, &ts);
    ts.tv_sec += 5;                                  /* 5 秒宽限 */

    int rc = pthread_timedjoin_np(pool[i], NULL, &ts);
    if (rc == ETIMEDOUT) {
        fprintf(stderr, "worker %d 未在 5 秒内退出，放弃等待\n", i);
        /* 可选：pthread_cancel(pool[i]); 或最后 _exit() 兜底 */
    }
}
```

> **HFT 补充**：如果 worker 是**长驻**的（跑整个进程生命周期），
> 就把 ②③④ 移到进程关闭路径上，关键路径上**完全没有 join**。
> 任务分发改用无锁队列（而不是原子计数器 + 数组），避免伪共享。

</details>
