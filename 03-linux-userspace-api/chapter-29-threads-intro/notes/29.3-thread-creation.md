## 本节讲什么

1. `pthread_create()` 的**四个参数**各自的含义，以及传参时最容易犯的三个错误
2. 新线程**可能在 `pthread_create()` 返回之前就开始运行**——这个竞态怎么防
3. 从 `pthread_create()` 到内核 `copy_process()` 的完整路径，以及线程数上限由谁决定

## 一、接口

```c
#include <pthread.h>

int pthread_create(pthread_t *thread,
                   const pthread_attr_t *attr,
                   void *(*start_routine)(void *),
                   void *arg);
/* 返回 0 成功；失败返回正错误码（不设 errno），见 29.2 */
```

| 参数 | 说明 |
|------|------|
| `thread` | 出参，接收新线程的 `pthread_t`。**必须在 `pthread_create` 返回后才有效** |
| `attr` | 线程属性；`NULL` = 默认（可接合、默认栈大小、继承调度策略） |
| `start_routine` | 新线程的入口函数，签名必须是 `void *(*)(void *)` |
| `arg` | 传给 `start_routine` 的**单个** `void *` 参数 |

**新线程从 `start_routine` 开始执行**，它返回（`return`）时线程结束，返回值即线程的退出状态
（由 `pthread_join()` 取得）。

## 二、从 `pthread_create()` 到内核

```
  用户代码                 glibc (NPTL)                   内核
  ─────────                ────────────                   ─────
  pthread_create(&t,
      NULL, worker, arg)
       │
       │                   ① 分配栈（mmap，默认 8MB
       │                      + guard page）
       │                   ② 在栈底构造 struct pthread
       │                      （线程描述符 / TCB）
       │                   ③ 计算 TLS 地址
       ↓
                           clone(CLONE_VM | CLONE_FS | CLONE_FILES
                                 | CLONE_SIGHAND | CLONE_THREAD
                                 | CLONE_SYSVSEM | CLONE_SETTLS
                                 | CLONE_PARENT_SETTID
                                 | CLONE_CHILD_CLEARTID
                                 | CLONE_CHILD_SETTID,
                                 stack_top,
                                 &parent_tid, &tls_desc, &child_tid)
                                        │
                                        ↓
                              SYSCALL_DEFINE5(clone)  fork.c:3036
                                        │  组装 struct kernel_clone_args
                                        ↓
                              kernel_clone(&args)     fork.c:2868
                                        │
                                        ↓
                              copy_process(...)       fork.c:2240
                                        ├─ dup_task_struct()       :2327
                                        ├─ copy_mm()   → 共享（CLONE_VM）
                                        ├─ copy_files() → 共享（CLONE_FILES）
                                        ├─ copy_sighand() → 共享（CLONE_SIGHAND）
                                        ├─ p->set_child_tid  = ... :2347
                                        ├─ p->clear_child_tid = ...:2351
                                        ├─ tgid/group_leader 分派   :2565
                                        └─ exit_signal = -1        :2632
                                        ↓
                              wake_up_new_task(p)   →  新线程变为可运行
```

**glibc 传的 `CLONE_*` 组合**（这就是「线程」在内核里的完整定义）：

| 标志 | 值 | 作用 |
|------|-----|------|
| `CLONE_VM` | `0x100` | 共享地址空间 |
| `CLONE_FS` | `0x200` | 共享 cwd / umask / root |
| `CLONE_FILES` | `0x400` | 共享文件描述符表 |
| `CLONE_SIGHAND` | `0x800` | 共享信号处置表 |
| `CLONE_SYSVSEM` | `0x40000` | 共享 System V `SEM_UNDO` |
| `CLONE_THREAD` | `0x10000` | **同一线程组**（tgid 相同） |
| `CLONE_SETTLS` | `0x80000` | 设置新线程的 TLS 指针 |
| `CLONE_PARENT_SETTID` | `0x100000` | 把新 TID 写进父线程指定的地址 |
| `CLONE_CHILD_CLEARTID` | `0x200000` | 线程退出时清该地址的 TID 并 futex-wake |
| `CLONE_CHILD_SETTID` | `0x1000000` | 线程启动时把 TID 写进自己指定的地址 |

> 注意 **`exit_signal` 传的是 0**（不是 `SIGCHLD`），内核在 `copy_process():2632`
> 对 `CLONE_THREAD` 强制设成 `-1`：
> ```c
> 	if (clone_flags & CLONE_THREAD)
> 		p->exit_signal = -1;      /* 线程退出不通知父进程 */
> ```
> 详见 [29.1](29.1-overview.md) 第三节。

## 三、传参的三大陷阱

`arg` 是 `void *`，只能传**一个**指针。这三个错误在真实代码里反复出现：

### 陷阱 1：传栈上局部变量的地址（循环创建线程时必踩）

```c
/* ✗ 经典错误：所有线程拿到同一个地址，内容是最后一次循环的值 */
for (int i = 0; i < N; i++) {
    pthread_create(&t[i], NULL, worker, &i);     /* ← 传了 &i！ */
    /* i 在栈上，所有线程共享同一个地址 */
}

static void *worker(void *arg)
{
    int id = *(int *)arg;      /* 读到的可能是任一时刻的 i，甚至 5（越界）*/
    ...
}
```

```
  时间线：
    i=0    create(&i)  ─┐
    i=1    create(&i)  ─┤ 三个线程都指向【同一个 &i】
    i=2    create(&i)  ─┘
                        ↓
    线程0 启动，读 *(&i) = 2   ← 期望 0，实际 2
    线程1 启动，读 *(&i) = 2   ← 期望 1，实际 2
    线程2 启动，读 *(&i) = 3   ← 循环已结束，i 变成 3
```

**三种修法**：

```c
/* 方案 A：每线程一个独立变量（数组 / 每线程 malloc）*/
static int ids[N];
for (int i = 0; i < N; i++) {
    ids[i] = i;
    pthread_create(&t[i], NULL, worker, &ids[i]);      /* 各自的地址 */
}

/* 方案 B：把整数直接编码进指针（最省事，POSIX 允许 intptr_t 往返）*/
#include <stdint.h>
for (int i = 0; i < N; i++)
    pthread_create(&t[i], NULL, worker, (void *)(intptr_t)i);

static void *worker(void *arg)
{
    int id = (int)(intptr_t)arg;      /* 直接解码，无内存访问 */
    ...
}

/* 方案 C：动态分配，线程自己 free */
for (int i = 0; i < N; i++) {
    int *p = malloc(sizeof(int));
    *p = i;
    pthread_create(&t[i], NULL, worker, p);      /* 线程负责 free */
}
static void *worker(void *arg)
{
    int id = *(int *)arg;
    free(arg);                                    /* 必须，否则泄漏 */
    ...
}
```

> 方案 C 有个隐患：如果 `pthread_create` **失败**，`malloc` 的内存没人 free。
> 要在失败分支里 `free(p)`。

### 陷阱 2：传指向「即将失效」对象的指针

```c
/* ✗ 栈帧返回后 buf 就失效了 */
void start(void)
{
    char buf[64];
    snprintf(buf, sizeof(buf), "task-%d", next_id());
    pthread_create(&t, NULL, worker, buf);      /* ← buf 是栈上数组 */
}   /* 函数返回 → buf 失效 → 新线程读到垃圾 */

/* ✗ 同理，容器扩容导致的失效（C++）*/
std::vector<Task> tasks;
tasks.push_back(t);
pthread_create(&tid, NULL, worker, &tasks[0]);   /* 下次 push_back 可能重分配 */
```

**修法**：确保被指向对象的**生命周期覆盖线程的整个执行期**。
最稳妥的做法是「动态分配 + 线程负责释放」，或者用**屏障同步**。

### 陷阱 3：多个线程共享同一个可变对象

```c
/* ✗ 两个线程共享一个 buffer，会互相覆盖 */
static char shared_buf[256];
snprintf(shared_buf, ..., "A 的参数");
pthread_create(&t1, NULL, worker, shared_buf);
snprintf(shared_buf, ..., "B 的参数");      /* ← 覆盖了 A 还没读走的参数 */
pthread_create(&t2, NULL, worker, shared_buf);
```

**修法**：同上，每线程一份。

> **统一原则**：`arg` 指向的数据要么**每线程一份**，要么**只读且生命周期足够长**。
> 传局部地址是最常见的错误，因为它"有时候能跑对"（取决于调度时机），
> 所以能通过本地测试，却在生产环境随机出错。

## 四、「新线程可能在 `pthread_create()` 返回前就开始运行」

```
  主线程                                    新线程
  ───────                                  ───────
  pthread_create(&t, NULL, w, &arg)
       │
       │  clone() 系统调用
       │  ...内核里 wake_up_new_task(p)...
       │                                    ← 此时新线程【已经可运行】
       │                                       可能立刻在另一个核上跑起来
       ↓
  pthread_create 返回，写 t
       ↓
  主线程继续执行
```

**这不是理论风险**——多核机器上新线程被调度到空闲核是很常见的。

### 后果一：不能依赖「创建顺序 = 执行顺序」

```c
pthread_create(&t1, NULL, print_one, NULL);
pthread_create(&t2, NULL, print_two, NULL);
/* 谁先打印是不确定的！可能是 "two one" */
```

需要顺序时必须**显式同步**（`pthread_join`、屏障、条件变量）。

### 后果二：`thread` 出参在新线程里不可用

```c
pthread_t t;
/* ✗ 新线程里不能用 t —— 主线程还没写它呢 */
static void *worker(void *arg)
{
    pthread_detach(t);        /* t 是全局变量，但值可能还没被填！*/
}
pthread_create(&t, NULL, worker, NULL);
```

**修法**：线程需要自己的 ID 时用 `pthread_self()`：

```c
static void *worker(void *arg)
{
    (void)arg;
    pthread_detach(pthread_self());       /* ✓ 自己拿自己的 ID */
    return NULL;
}
```

### 后果三：参数还没准备好，新线程就读了

```c
struct ctx *c = malloc(sizeof(*c));
pthread_create(&t, NULL, worker, c);
c->fd = open(...);        /* ✗ 新线程可能已经读了未初始化的 c->fd */
c->name = strdup("x");
```

**修法**：**先准备完，再创建**。这是最干净的方案，不需要额外同步：

```c
struct ctx *c = malloc(sizeof(*c));
c->fd   = open(...);          /* ① 全部初始化完 */
c->name = strdup("x");
pthread_create(&t, NULL, worker, c);   /* ② 再创建 */
```

如果必须边跑边填，用条件变量或屏障；但**首选永远是「先备后建」**。

## 五、失败原因与线程数上限

`pthread_create()` 失败时返回的错误码（**不是** `errno`）：

| 错误码 | 含义 | 常见原因 |
|--------|------|----------|
| `EAGAIN` (11) | 资源不足，无法再创建线程 | **最常见**。线程数上限、内存不足 |
| `EINVAL` (22) | 无效的 `attr` | 栈大小非法（太小 / 未对齐）、调度策略不支持 |
| `EPERM` (1) | 无权限设置指定的调度策略/优先级 | 非 root 却请求 `SCHED_FIFO` 或过高优先级 |

### 线程数的三道上限

```
  ① RLIMIT_NPROC（每用户）
     ulimit -u  →  该用户能创建的【任务总数】（含进程和线程）
     内核检查点：copy_process():2366
     ⚠️ 是对【线程】计数的，不是只对进程！

  ② /proc/sys/kernel/threads-max（系统级）
     cat /proc/sys/kernel/threads-max

  ③ 实际内存约束（最容易被忽略）
     每线程开销 = 用户栈（默认 8MB，虚拟）+ 内核栈（16KB，物理）
                 + task_struct（~8KB，物理）
     8MB 虚拟栈 × 1000 线程 = 8GB 虚拟地址空间
     → 32 位进程（4GB 地址空间）开 500 个线程就到顶了
```

内核的检查点（`kernel/fork.c:2365-2370`）：

```c
	retval = -EAGAIN;
	if (is_rlimit_overlimit(task_ucounts(p), UCOUNT_RLIMIT_NPROC, rlimit(RLIMIT_NPROC))) {
		if (p->real_cred->user != INIT_USER &&
		    !capable(CAP_SYS_RESOURCE) && !capable(CAP_SYS_ADMIN))
			goto bad_fork_cleanup_count;          /* → EAGAIN */
	}
```

注意 `task_ucounts(p)` —— 计数是**按用户（UID）**而非按进程的，
所以同一用户的**所有**进程/线程加在一起受限。

**诊断命令**：

```bash
ulimit -u                                        # RLIMIT_NPROC
cat /proc/sys/kernel/threads-max                  # 系统级上限
ps -eLf | wc -l                                   # 当前系统的任务总数
ls /proc/self/task | wc -l                        # 当前进程的线程数
cat /proc/PID/status | grep Threads               # 某进程的线程数
cat /proc/PID/limits | grep "max processes"       # 某进程的 NPROC 限制
```

## 六、栈：glibc 怎么分配线程的栈

```
  进程虚拟地址空间中的线程栈布局

   高地址 ┌─────────────────────┐
          │  struct pthread     │  ← 线程描述符（TCB），含 TLS 区，在栈底
          ├─────────────────────┤
          │  __thread 变量区     │
          ├─────────────────────┤
          │                     │
          │  栈（向低地址增长）   │  ← 局部变量、函数调用帧
          │        ↓            │
          │  ... 空闲 ...        │
          ├─────────────────────┤
          │  guard page (4KB)   │  ← PROT_NONE，栈溢出时 SIGSEGV
   低地址 └─────────────────────┘
```

| 特性 | 说明 |
|------|------|
| **分配者** | glibc（不是内核），用 `mmap(MAP_ANONYMOUS\|MAP_STACK\|MAP_NORESERVE)` |
| **默认大小** | 由 `RLIMIT_STACK`（`ulimit -s`）决定；若为 `unlimited`，则 x86-32 = 2MB，其他架构各异。**用 `pthread_attr_getstacksize()` 查实际值，别猜** |
| **guard page** | glibc 默认在栈底加一页 `PROT_NONE` 的保护页，栈溢出时触发 `SIGSEGV` 而不是踩到前一个线程的栈 |
| **内核栈** | 另有一份，16KB（`THREAD_SIZE`），物理内存，随 `dup_task_struct()` 分配 |

> ⚠️ **保护页只能拦住「跨页」的溢出**。如果一个大数组（比如 `char buf[8192]`）
> 一次性越过保护页，或者递归把栈整个写穿，保护页救不了你。
> 真正的深度递归要显式设置更大的栈。

### 显式设置栈大小

```c
pthread_attr_t attr;
size_t stacksize;

pthread_attr_init(&attr);

/* ① 先查默认值（不同系统差异大，不要硬编码）*/
pthread_attr_getstacksize(&attr, &stacksize);
printf("默认栈大小: %zu KB\n", stacksize / 1024);

/* ② 设置（不要小于 PTHREAD_STACK_MIN，通常 16KB）*/
pthread_attr_setstacksize(&attr, 256 * 1024);       /* 256 KB */

/* ③ 也可以同时设保护页大小；设为 0 表示不要保护页（省一页）*/
pthread_attr_setguardsize(&attr, 0);

pthread_create(&t, &attr, worker, NULL);
pthread_attr_destroy(&attr);        /* 必须 */
```

⚠️ **栈太小的症状**：`SIGSEGV` 且栈回溯看起来"莫名其妙"，
或者局部变量被莫名修改。这类 bug 极难查。
用 `pthread_attr_setstacksize()` 给个充裕的值（如 1MB）复测，能快速确认是不是栈的问题。

## HFT / 嵌入式关联

| 路线 | 要点 |
|------|------|
| 嵌入式 | ① **默认栈 8MB 在 256MB 内存的设备上是灾难**。虽然栈是虚拟内存、按需提交物理页，但 overcommit 关闭或 `/proc/sys/vm/overcommit_memory=2` 时 `mmap` 就会失败。务必显式 `pthread_attr_setstacksize()` 设 64KB~1MB。② **32 位设备的地址空间天花板**：8MB × 400 线程 = 3.2GB，接近 32 位的 4GB 用户空间上限 → 减小栈或减线程数。③ `RLIMIT_NPROC` 在嵌入式上常设得很低（几十），起线程池前先 `ulimit -u` 核对 |
| HFT | ① **不在关键路径上创建线程**：`pthread_create()` 约 20~30 µs（mmap + clone + 栈准备），足以毁掉一次交易机会。**启动时把线程池建好，运行时只做任务分发**。② **绑核要在创建时做**：`pthread_setaffinity_np()` 对已创建的线程生效，但线程可能先在别的核跑一段；更好的是 `pthread_attr_setaffinity_np()`（glibc 2.32+）在**创建时就绑核**，避免迁移开销与 cache 冷启动。③ **失败必须处理**：`EAGAIN` 在线程池耗尽时真的会发生；用 `if (rc != 0)` 判断（见 [29.2](29.2-background-details-of-the-pthreads-api.md)），记录并降级（同步执行或丢弃并告警）。④ 调试时遇到"莫名其妙的段错误"，第一件事是**把栈放大 10 倍复测**，能快速排除栈溢出 |

## 代码示例：线程创建的正确姿势

```c
/* thread_create_demo.c —— pthread_create 的参数传递、竞态与栈设置
 *
 * 编译: gcc -Wall -Wextra -O2 -pthread -o tcd thread_create_demo.c
 * 运行: ./tcd
 */
#define _GNU_SOURCE
#include <stdio.h>
#include <stdlib.h>
#include <stdarg.h>
#include <string.h>
#include <stdint.h>
#include <pthread.h>
#include <unistd.h>
#include <errno.h>
#include <sys/syscall.h>
#include <sys/resource.h>

#define N 4

static pid_t gettid_(void) { return (pid_t)syscall(SYS_gettid); }

static pthread_mutex_t print_lock = PTHREAD_MUTEX_INITIALIZER;
static void say(const char *fmt, ...)
{
    va_list ap;
    va_start(ap, fmt);
    pthread_mutex_lock(&print_lock);
    vprintf(fmt, ap);
    fflush(stdout);
    pthread_mutex_unlock(&print_lock);
    va_end(ap);
}

/* ── 演示 1：错误的传参（传循环变量地址）───────────────── */
static void *bad_worker(void *arg)
{
    int id = *(int *)arg;
    say("  [错误版] 线程读到 id=%d\n", id);
    return NULL;
}

static void demo_bad_arg(void)
{
    pthread_t t[N];
    say("\n【演示 1】错误的传参：&i\n");
    for (int i = 0; i < N; i++)
        pthread_create(&t[i], NULL, bad_worker, &i);     /* ← 故意的错 */
    for (int i = 0; i < N; i++)
        pthread_join(t[i], NULL);
    say("  ↑ 注意：读到的 id 不是 0,1,2,3，而是【最终值或中间值】\n");
}

/* ── 演示 2：正确的传参（整数编码进指针）─────────────── */
static void *good_worker_intptr(void *arg)
{
    int id = (int)(intptr_t)arg;
    say("  [正确版A] 线程 %d: tid=%d\n", id, gettid_());
    return NULL;
}

static void demo_good_intptr(void)
{
    pthread_t t[N];
    say("\n【演示 2】正确的传参：把整数编码进指针\n");
    for (int i = 0; i < N; i++)
        pthread_create(&t[i], NULL, good_worker_intptr, (void *)(intptr_t)i);
    for (int i = 0; i < N; i++)
        pthread_join(t[i], NULL);
}

/* ── 演示 3：正确的传参（每线程独立数组元素）──────────── */
struct task { int id; char name[32]; };

static void *good_worker_struct(void *arg)
{
    struct task *tk = arg;
    say("  [正确版B] 线程 %d (%s): tid=%d\n", tk->id, tk->name, gettid_());
    return NULL;
}

static void demo_good_struct(void)
{
    pthread_t t[N];
    struct task tasks[N];                       /* 每线程一个独立元素 */

    say("\n【演示 3】正确的传参：每线程一个结构体\n");
    for (int i = 0; i < N; i++) {
        tasks[i].id = i;                        /* ① 先初始化 */
        snprintf(tasks[i].name, sizeof(tasks[i].name), "task-%d", i);
    }
    for (int i = 0; i < N; i++)                 /* ② 再创建 */
        pthread_create(&t[i], NULL, good_worker_struct, &tasks[i]);
    for (int i = 0; i < N; i++)
        pthread_join(t[i], NULL);
}

/* ── 演示 4：新线程可能在 create 返回前就跑 ──────────── */
static void *order_worker(void *arg)
{
    int id = (int)(intptr_t)arg;
    say("  [顺序] 线程 %d 开始执行 (tid=%d)\n", id, gettid_());
    return NULL;
}

static void demo_no_order_guarantee(void)
{
    pthread_t t[N];
    say("\n【演示 4】创建顺序 ≠ 执行顺序\n");
    for (int i = 0; i < N; i++) {
        say("  主线程: create(%d)...\n", i);
        pthread_create(&t[i], NULL, order_worker, (void *)(intptr_t)i);
        /* 新线程可能在这一行之前就已经跑完了 */
    }
    for (int i = 0; i < N; i++)
        pthread_join(t[i], NULL);
    say("  ↑ 输出顺序不确定；要保证顺序必须显式同步\n");
}

/* ── 演示 5：栈大小 ─────────────────────────────────── */
static void *stack_worker(void *arg)
{
    char probe;                                 /* 用局部变量的地址代表栈位置 */
    (void)arg;
    say("  [栈] tid=%-6d 局部变量地址 ≈ %p\n", gettid_(), (void *)&probe);
    return NULL;
}

static void demo_stack(void)
{
    pthread_attr_t attr;
    size_t defsize;
    size_t guardsize;
    struct rlimit rl;

    say("\n【演示 5】栈设置\n");

    pthread_attr_init(&attr);
    pthread_attr_getstacksize(&attr, &defsize);
    pthread_attr_getguardsize(&attr, &guardsize);
    say("  默认栈大小  : %zu KB (%zu MB)\n", defsize / 1024, defsize / 1024 / 1024);
    say("  默认保护页  : %zu 字节\n", guardsize);

    if (getrlimit(RLIMIT_STACK, &rl) == 0) {
        if (rl.rlim_cur == RLIM_INFINITY)
            say("  RLIMIT_STACK: unlimited\n");
        else
            say("  RLIMIT_STACK: soft=%lu KB\n", (unsigned long)rl.rlim_cur / 1024);
    }

    /* 显式设成 256KB */
    pthread_attr_setstacksize(&attr, 256 * 1024);
    pthread_attr_getstacksize(&attr, &defsize);
    say("  设为 256KB 后实际: %zu KB\n", defsize / 1024);

    pthread_t t1, t2;
    pthread_create(&t1, NULL, stack_worker, NULL);      /* 默认栈 */
    pthread_create(&t2, &attr, stack_worker, NULL);     /* 256KB 栈 */
    pthread_join(t1, NULL);
    pthread_join(t2, NULL);
    pthread_attr_destroy(&attr);
}

/* ── 演示 6：请求过大栈 → 失败返回正数 ───────────────── */
static void demo_create_fail(void)
{
    pthread_attr_t attr;
    pthread_t t;
    int rc;

    pthread_attr_init(&attr);
    pthread_attr_setstacksize(&attr, 512UL * 1024 * 1024 * 1024);   /* 512GB */

    rc = pthread_create(&t, &attr, stack_worker, NULL);
    say("\n【演示 6】pthread_create 失败\n");
    say("  请求 512GB 栈 → 返回 %d (%s)\n", rc, strerror(rc));
    say("  ↑ 是【正数】不是 -1；正确判断是 if (rc != 0)\n");
    say("  errno 此时=%d（未被设置，perror 会误导）\n", errno);

    pthread_attr_destroy(&attr);
}

int main(void)
{
    say("主线程: pid=%d tid=%d\n", getpid(), gettid_());

    demo_bad_arg();
    demo_good_intptr();
    demo_good_struct();
    demo_no_order_guarantee();
    demo_stack();
    demo_create_fail();

    return 0;
}
```

## 代码自测

<details>
<summary><b>问 1：</b>下面这段代码有什么问题？怎么修？</summary>

```c
for (int i = 0; i < 5; i++)
    pthread_create(&t[i], NULL, worker, &i);
```

**问题：所有 5 个线程拿到的是同一个地址 `&i`。**

`i` 是 `main` 栈上的一个变量，5 次循环传的都是它的地址。而新线程**可能在
`pthread_create` 返回前就开始运行**，也可能在循环结束之后才运行——
无论哪种，它读到的 `*(&i)` 都不是"它被创建时的那个 i"。

```
  时间线：
    i=0  create(&i) ─┐
    i=1  create(&i) ─┤
    i=2  create(&i) ─┤ 5 个线程全都指向同一个 &i
    i=3  create(&i) ─┤
    i=4  create(&i) ─┘
    i=5  （循环结束）
                     ↓
    线程们陆续启动，读 *(&i) = 5   ← 全都是 5，而且越界了
```

**三种修法**：

```c
/* ① 把整数编码进指针（最省事，推荐用于只传一个 ID 的场景）*/
#include <stdint.h>
for (int i = 0; i < 5; i++)
    pthread_create(&t[i], NULL, worker, (void *)(intptr_t)i);

static void *worker(void *arg) {
    int id = (int)(intptr_t)arg;      /* 直接解码，无需内存访问 */
    ...
}

/* ② 每线程一个独立变量 */
static int ids[5];
for (int i = 0; i < 5; i++) {
    ids[i] = i;
    pthread_create(&t[i], NULL, worker, &ids[i]);
}

/* ③ 动态分配，线程自己释放 */
for (int i = 0; i < 5; i++) {
    int *p = malloc(sizeof(int));
    *p = i;
    int rc = pthread_create(&t[i], NULL, worker, p);
    if (rc != 0) { free(p); /* 处理失败 */ }    /* ← 别忘了失败分支 */
}
static void *worker(void *arg) {
    int id = *(int *)arg;
    free(arg);                        /* 线程负责释放 */
    ...
}
```

**统一原则**：`arg` 指向的数据要么**每线程一份**，要么**只读且生命周期覆盖线程的整个执行期**。

这类 bug 危险在于它"有时候能跑对"——取决于调度时机，本地测试可能一直正确，
上了多核生产机才随机出错。

</details>

<details>
<summary><b>问 2：</b>为什么不能假设「先创建的线程先执行」？需要顺序时怎么办？</summary>

因为**新线程在 `pthread_create()` 返回之前就已经可运行了**。

看内核路径：`pthread_create` → `clone()` → `kernel_clone()`（`fork.c:2868`）
→ `copy_process()`（`:2909`）→ **`wake_up_new_task(p)`**。
最后一步把新线程放进运行队列，**此时它就可以在任何空闲核上立即运行**，
而主线程还卡在从系统调用返回、写 `thread` 出参的过程中。

```
  主线程（核 0）                        新线程（核 1）
  ─────────────                        ────────────
  pthread_create(...)
       │
       ├─ clone() 陷入内核
       │      ...
       │      wake_up_new_task(p)  ───→  【开始运行】
       │      ...                         可能已经跑到 printf 了
       ├─ 返回用户态
       ├─ 写 thread 出参
       ↓
  继续执行
```

而且**多个线程的启动顺序也是不确定的**——取决于哪个核先空闲、调度器怎么选。

**需要顺序时的三种手段**：

```c
/* ① pthread_join —— 最简单，但要"等它跑完" */
pthread_create(&t1, NULL, w1, NULL);
pthread_join(t1, NULL);              /* 等 t1 结束 */
pthread_create(&t2, NULL, w2, NULL); /* 现在 t2 一定在 t1 之后 */
/* 缺点：完全串行，失去了并发 */

/* ② 屏障 pthread_barrier_t —— N 个线程互相等到齐 */
static pthread_barrier_t barrier;
pthread_barrier_init(&barrier, NULL, N);

static void *worker(void *arg) {
    prepare();                            /* 各自准备 */
    pthread_barrier_wait(&barrier);       /* 等所有人准备好 */
    do_timed_work();                      /* 一起开始 */
    return NULL;
}
/* 适合"预备 → 同时开跑"的场景（如基准测试、批处理）*/

/* ③ 条件变量 —— 最灵活，按条件推进 */
static pthread_mutex_t m = PTHREAD_MUTEX_INITIALIZER;
static pthread_cond_t  cv = PTHREAD_COND_INITIALIZER;
static int ready = 0;

static void *worker(void *arg) {
    pthread_mutex_lock(&m);
    while (!ready)                        /* 必须用 while 不是 if */
        pthread_cond_wait(&cv, &m);
    pthread_mutex_unlock(&m);
    do_work();
    return NULL;
}
/* 主线程: lock; ready = 1; pthread_cond_broadcast(&cv); unlock; */
```

**HFT 里的实际做法**：根本不依赖顺序。
线程创建后各自进入事件循环，通过**队列 + 无锁/有锁同步**传递任务，
顺序由数据流本身保证，而不是由创建顺序保证。

详见 [Ch30.2 条件变量](../../chapter-30-thread-synchronization/notes/30.2-signaling-changes-of-state-condition-var.md)。

</details>

<details>
<summary><b>问 3：</b><code>pthread_create</code> 返回 <code>EAGAIN</code> 时，可能的原因有哪些？怎么查？</summary>

`EAGAIN` 表示"资源不足，无法创建新线程"。具体是三道天花板之一：

### ① `RLIMIT_NPROC`（每用户任务数）

```c
/* kernel/fork.c:2365-2370 */
	retval = -EAGAIN;
	if (is_rlimit_overlimit(task_ucounts(p), UCOUNT_RLIMIT_NPROC, rlimit(RLIMIT_NPROC))) {
		if (p->real_cred->user != INIT_USER &&
		    !capable(CAP_SYS_RESOURCE) && !capable(CAP_SYS_ADMIN))
			goto bad_fork_cleanup_count;          /* → EAGAIN */
	}
```

⚠️ **这是按用户（UID）计数的，而且统计的是【线程】不是进程**。
同一用户跑的所有进程/线程加在一起受限。

```bash
ulimit -u                                     # 查看（unlimited 表示不限）
ps -eLf | wc -l                               # 当前系统的任务总数
cat /proc/PID/limits | grep "max processes"     # 某进程的实际限制
```

### ② 系统级 `threads-max`

```bash
cat /proc/sys/kernel/threads-max
```

### ③ 实际内存/地址空间约束（最隐蔽）

```
  每线程的开销：
    用户栈     默认 8MB（虚拟，按需提交物理页）
    内核栈     16KB（THREAD_SIZE，物理，立即分配）
    task_struct ~8KB（物理，slab）

  地址空间天花板（32 位进程）：
    4GB 用户空间 ÷ 8MB/线程 ≈ 500 线程就到顶
    → 减小栈大小或减线程数
```

`mmap` 失败会直接导致 `pthread_create` 返回 `EAGAIN`。

### 诊断清单

```bash
# 1. 当前线程数
cat /proc/self/status | grep Threads
ls /proc/self/task | wc -l

# 2. 三道上限
ulimit -u
cat /proc/sys/kernel/threads-max
free -m

# 3. 是不是内存不够
cat /proc/meminfo | grep -E "MemAvailable|Committed_AS"
cat /proc/sys/vm/overcommit_memory     # 2 = 严格模式，mmap 更容易失败

# 4. 谁在吃线程
ps -eLf --sort=-nlwp | head -20        # 按线程数排序
```

### 修法

| 原因 | 修法 |
|------|------|
| `RLIMIT_NPROC` | `ulimit -u` 调高（或 systemd 的 `TasksMax=`） |
| 栈太大 | `pthread_attr_setstacksize()` 设小（如 256KB~1MB） |
| 线程确实太多 | **改用线程池 / I/O 多路复用**（epoll 一个线程管上万连接） |
| 32 位地址空间 | 换 64 位构建，或减小栈 |

> **HFT 实践**：线程池在启动时就把线程建好，运行时**永远不创建线程**。
> 这样 `EAGAIN` 只可能在启动阶段发生（fail fast），不会在交易时段突然出现。
> 如果必须动态扩容，要**预留余量**并监控失败计数。

</details>

<details>
<summary><b>问 4：</b>线程的栈是谁分配的？默认多大？栈溢出会怎样？</summary>

**glibc 分配的，不是内核。** 内核只管内核栈（16KB），用户栈是 glibc 在
`pthread_create()` 内部用 `mmap(MAP_ANONYMOUS|MAP_STACK|MAP_NORESERVE)` 分配的。

```
  高地址 ┌─────────────────────┐
         │  struct pthread     │ ← 线程描述符 TCB（含 TLS 区）
         ├─────────────────────┤
         │  __thread 变量       │
         ├─────────────────────┤
         │  局部变量 / 调用帧    │ ← 栈向低地址增长
         │        ↓            │
         ├─────────────────────┤
         │  guard page (4KB)   │ ← PROT_NONE
  低地址 └─────────────────────┘
```

### 默认大小

**不要硬编码数字**——它由 `RLIMIT_STACK`（`ulimit -s`）决定：

- 若 `RLIMIT_STACK` 有限值 → 线程栈默认就等于它
- 若 `unlimited` → 架构相关（x86-32 = 2MB，x86-64 上通常 8MB）

查实际值：

```c
pthread_attr_t attr;
size_t sz;
pthread_attr_init(&attr);
pthread_attr_getstacksize(&attr, &sz);     /* ← 用这个，别猜 */
printf("%zu KB\n", sz / 1024);
```

或命令行：`ulimit -s`

### 栈溢出会怎样

**情况 A：小幅溢出 → 撞上 guard page → `SIGSEGV`**

这是"好"的情况。保护页是 `PROT_NONE` 的，任何访问都会段错误，
能立刻定位（配 `sigaltstack` + `SA_ONSTACK` 还能打出回溯，
见 [Ch21.3](../../chapter-21-signal-handlers/notes/21.3-handling-a-signal-on-an-alternate-stack-.md)）。

**情况 B：大步跨越保护页 → 踩到相邻内存**

```c
static void deep(void)
{
    char buf[65536];        /* 一次就跳过 16 页 */
    memset(buf, 0, sizeof(buf));   /* 可能直接越过 guard page */
}
```

单个大数组或极端递归可能**一步跨过** 4KB 保护页，落到前一个线程的栈或
其他 mmap 区域上 → **静默的数据损坏**，症状是"变量莫名被改"，极难查。

**情况 C：踩穿到 TCB/TLS 区**

栈向低地址增长，而 TCB 在**栈底（高地址）**。所以正常增长不会踩到 TCB——
除非有缓冲区**向上**溢出（如 `strcpy` 越过数组边界往高地址写），
那会直接破坏 `struct pthread`，症状是 `pthread_*` 调用莫名其妙地失败。

### 显式设置

```c
pthread_attr_t attr;
pthread_attr_init(&attr);
pthread_attr_setstacksize(&attr, 1024 * 1024);      /* 1 MB */
pthread_attr_setguardsize(&attr, 4096);             /* 也可设 0 省一页 */
pthread_create(&t, &attr, worker, NULL);
pthread_attr_destroy(&attr);
```

⚠️ 不能小于 `PTHREAD_STACK_MIN`（通常 16KB），否则 `pthread_create` 返回 `EINVAL`。

> **HFT / 嵌入式**：嵌入式上默认 8MB 栈在 256MB 内存设备上是灾难，
> 显式设 64KB~1MB；HFT 上栈太小的 `SIGSEGV` 很难查，
> 遇到"莫名其妙的段错误"第一件事是**把栈放大 10 倍复测**，能快速排除栈问题。

</details>

<details>
<summary><b>问 5：</b>新线程里想 detach 自己，为什么不能用 <code>pthread_detach(t)</code>（t 是全局的 <code>pthread_t</code>）？</summary>

因为**主线程可能还没把 `t` 填好**。

`pthread_create(&t, ...)` 的 `t` 是**出参**，在 `pthread_create` **返回之后**才有效。
但新线程可能在 `pthread_create` 返回**之前**就开始运行（见问 2）：

```
  主线程                              新线程
  ───────                            ──────
  pthread_create(&t, ...)
       │
       ├─ clone() 陷入内核
       │      wake_up_new_task(p) ──→ 【开始运行】
       │                                pthread_detach(t);   ← t 还是垃圾值！
       ├─ 返回用户态
       ├─ 写 t        ← 太晚了
```

`pthread_detach(垃圾值)` 的后果是未定义行为：可能返回 `ESRCH`（找不到线程），
更糟的是**恰好匹配到另一个线程**而把它 detach 了。

**正确做法：用 `pthread_self()`**

```c
static void *worker(void *arg)
{
    (void)arg;
    pthread_detach(pthread_self());      /* ✓ 自己拿自己的 ID，永远正确 */
    /* ... 干正事 ... */
    return NULL;
}
```

`pthread_self()` 读的是 TCB 里 glibc 在 `clone()` **之前**就填好的字段，
从新线程第一条指令起就有效。

**另外三个同类陷阱**：

```c
/* ① 新线程里不能用主线程传的 pthread_t 数组 */
pthread_t t[5];
static void *w(void *arg) { pthread_detach(t[0]); }   /* ✗ 同理 */

/* ② 主线程读新线程写的全局变量 —— 没有同步，也是竞态 */
static void *w(void *arg) { result = 42; return NULL; }  /* 主线程直接读 result ✗ */
/* 必须用 pthread_join 取返回值，或用条件变量/原子变量 */

/* ③ 创建后立刻 detach 是【安全的】 */
pthread_create(&t, NULL, w, NULL);
pthread_detach(t);
/* detach 对已结束但未 join 的线程依然有效，资源会被回收。
   反过来（先 detach 再 join）才是错误，join 会返回 EINVAL */
```

> **更推荐的做法**：如果一开始就打算 detach，用**属性**在创建时指定，
> 根本不给竞态留窗口：
> ```c
> pthread_attr_t attr;
> pthread_attr_init(&attr);
> pthread_attr_setdetachstate(&attr, PTHREAD_CREATE_DETACHED);
> pthread_create(&t, &attr, w, NULL);      /* 创建即分离 */
> pthread_attr_destroy(&attr);
> ```
> 详见 [29.7 分离线程](29.7-detaching-a-thread.md) 与 [29.8 线程属性](29.8-thread-attributes.md)。

</details>
