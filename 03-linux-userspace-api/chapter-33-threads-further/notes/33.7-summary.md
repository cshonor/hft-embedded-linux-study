## 本章回顾

### 小节速览（内核坐标版）

| 节 | 主题 | 一句话内核视角 |
|----|------|--------------|
| 33.1 线程栈 | 主线程 vs 子线程两套机制 | 子线程栈是普通 mmap **不增长**；每线程 16KB 内核栈（`THREAD_SIZE:16`）立即占物理内存 |
| 33.2 线程与信号 | 处置共享、掩码私有 | `complete_signal():1004` 从 `curr_target` 轮转选未阻塞线程；全阻塞挂共享队列 |
| 33.3 进程控制 | fork/exec/exit | `de_thread():1044` exec 杀光其他线程（非 leader 还会**窃取 leader 的 PID**） |
| 33.4 实现模型 | M:1 / 1:1 / M:N | Linux 1:1：pthread 就是 clone 出的 task_struct，阻塞/多核/观测全部免费 |
| 33.5 NPTL | LinuxThreads → NPTL | 三大内核地基：`CLONE_THREAD`（TGID）、`CLONE_CHILD_CLEARTID`（join 的 futex）、`tgkill` |
| 33.6 高级同步 | rwlock/barrier/spin/PROCESS_SHARED | 全部落 futex；PRIVATE key 快在跳过物理页反查 |

### 三个反直觉真相

1. **「线程栈」是两种东西**：主线程栈（`VM_GROWSDOWN` 可增长、进程栈区）与子线程栈（mmap 区固定、有 guard）——名字同，机制完全不同。
2. **信号没有"进程掩码"**：掩码每线程独立，`complete_signal` 只是**从上次目标轮转**找第一个未阻塞的——全员阻塞时信号安静地挂在共享队列，谁先解除谁领走（不是丢失）。
3. **exec 的 PID 窃取**：非 leader 线程 exec 后，内核让它顶替已死 leader 的 PID——`getpid()` 语义靠一个换位 hack 保住。

### 决策速查

| 场景 | 正解 | 陷阱 |
|------|------|------|
| 多线程信号处理 | 创建线程前主线程阻塞 → sigwait 专用线程 | handler 里 printf/malloc（锁+非 async-safe） |
| 多线程要 fork | fork 后**只做 async-signal-safe 事 → exec**；或 `posix_spawn` | 子进程 lock 继承的锁（持有者不存在→死锁）；atfork 只救你自己的锁 |
| 主线程退 worker 也要退 | `exit()`（触发 `exit_group` 全灭） | `return` 等价于 exit——想留 worker 得 `pthread_exit(NULL)` |
| 海量线程并发 IO | 协程（M:1 思想转世）+ 线程池铺底 | 1:1 线程扛百万连接（栈+内核栈烧爆） |
| 跨进程同步对象 | `PTHREAD_PROCESS_SHARED` + 共享内存映射 | 忘设 shared → 假同步（futex key 各自哈希） |

### 本章铁律（HFT 视角）

1. **信号线程是部署标准**，业务线程全员阻塞；
2. **多线程进程的 fork 只有一条生路：紧跟 exec**；
3. 线程预算 = 用户栈（虚拟 8MB × N）+ **内核栈 16KB × N（物理）**——内存预算按物理算；
4. `pthread_t` ≠ TID，观测用 `gettid()`；
5. 选同步原语顺序：**能不能不锁 → mutex → 特化原语**，spin/rwlock 先量后用。

## 代码自测

<details>
<summary>1. 为什么「全员阻塞 SIGUSR1 后 kill() 发 SIGUSR1」不会丢信号？</summary>

信号留在进程的**共享 pending 队列**（`shared_pending`）。`complete_signal():1004` 轮转一圈没有线程 `wants_signal()`（全 blocked）就返回——信号挂着，不丢弃。之后任何一个线程 `pthread_sigmask(SIG_UNBLOCK, ...)` 并返回用户态时，信号递送或被 `sigwait` 取走。**阻塞 ≠ 丢弃**，只有标准信号在队列里**合并**（多次投递记一次）。
</details>

<details>
<summary>2. fork 出的子进程里 printf 为什么可能死锁？和 exec 前的限制是什么关系？</summary>

stdio 流锁随地址空间 COW 继承。若父进程某线程恰好在 printf 内（持流锁）时另一线程 fork，子进程继承"锁定"的锁位，但持有者线程没被复制——子进程 printf 走到该锁即死锁。**async-signal-safe 函数清单恰好就是"不持锁"的函数清单**——信号处理器和 fork 子进程面对的是同一个世界（「别的执行流可能消失在持锁中途」），所以共享同一份白名单。exec 替换映像后锁状态清零，一切安全。
</details>

<details>
<summary>3. 四线程进程，线程 2（非 leader）执行 execve 成功。之后 getpid() 返回什么？/proc 里 task 目录少了几个？</summary>

getpid() 返回**原 leader 的 PID**——`de_thread():1044` 杀光其他 3 线程后，非 leader 调用者与已退出的 leader **换位**（接管其 PID/TGID）。`/proc/pid/task/` 从 4 项变 1 项。这就是「exec 后进程身份不变」的实现：物理上执行映像的线程换了，逻辑身份被内核手术缝合。
</details>

<details>
<summary>4. 子线程默认栈 8MB、内核栈 16KB、guard 4KB——一台 64GB 机器的理论线程数上限和实际工程预算差多少？</summary>

理论：64GB / 16KB = 4M 线程（只算内核栈物理内存；用户栈 8MB 是虚拟、按触碰收费，但 mmap 地址空间 128TB 也够）。实际工程：每线程还有 glibc `struct pthread`（TCB 等 ~数 KB 物理）、页表项、调度器开销（runqueue 负载）——实践中万级线程已是重负载（调度抖动、组唤醒风暴），千级是常见健康上限。**预算按"内核栈 16KB × N 立即物理 + 触碰到的用户页"算**。
</details>

<details>
<summary>5. 把 33.2/33.3 串起来：SIGHUP 重载配置 + SIGTERM 优雅退出 + 禁止 fork 的多线程服务，画出完整生命周期。</summary>

```text
main ─ pthread_sigmask(BLOCK {SIGHUP,SIGTERM})      ← 一切之前
    ├─ sigwait 线程：取信号 → 翻译成内部事件（管道/eventfd）
    ├─ 业务线程 × N：全员继承阻塞，永不收信号
    │     SIGHUP → 配置线程在读检查点原子换表（无锁读：双缓冲+原子指针）
    │     SIGTERM → shutdown 事件 → 各线程跑到 quiesce 点 → 退出
    └─ 主线程 pthread_exit（或 join 最后的 logger）
外部工具一律 posix_spawn；绝不 fork-worker。
```
</details>
