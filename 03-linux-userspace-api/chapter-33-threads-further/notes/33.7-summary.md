### 线程与 fork 的危险

| 问题 | 说明 |
|------|------|
| 只复制调用线程 | 其他线程消失，可能持有锁未释放 |
| 锁状态不确定 | 子进程可能继承已锁的 mutex，无持有者信息 |
| stdio 不一致 | 子进程继承 stdio 内部锁状态 |
| POSIX 建议 | fork 后子进程只调用 async-signal-safe 函数，直到 exec |

### 线程与信号

| 规则 | 说明 |
|------|------|
| 信号掩码 | 每进程一个（所有线程共享），用 `pthread_sigmask` 设置 |
| 信号投递 | 硬件信号（SIGSEGV/SIGFPE）发给触发线程 |
| 进程级信号 | SIGINT/SIGTERM 发给任意一个未屏蔽的线程 |
| `sigwait()` | 指定线程等待信号，其他线程不处理 |
| 推荐模式 | 主线程 `sigwait`，其他线程屏蔽信号 |

### 实时调度策略

| 策略 | 说明 | 适用 |
|------|------|------|
| `SCHED_OTHER` | 普通调度（CFS） | 默认 |
| `SCHED_FIFO` | 实时先进先出 | HFT/嵌入式 |
| `SCHED_RR` | 实时轮转 | 实时系统 |
| `SCHED_DEADLINE` | 最早截止期限 | Linux 特有 |

```c
struct sched_param param;
param.sched_priority = 50;  /* 1-99，越大优先级越高 */
pthread_setschedparam(thread, SCHED_FIFO, &param);
```

## HFT / 嵌入式关联

- **fork 禁忌**：HFT 多线程进程绝不 fork（锁丢失风险），用多进程或 `posix_spawn`
- **实时调度**：HFT 策略线程用 `SCHED_FIFO` + `mlockall` + CPU 隔离
- **信号处理**：用 `sigwait` 专用线程处理信号，工作线程屏蔽
- **栈大小**：HFT 线程通常减小栈（2-4MB），减少内存占用
- **嵌入式**：线程数严格控制，栈大小精确配置

## 代码自测

<details>
<summary>1. 为什么多线程程序中 fork 后只应调用 async-signal-safe 函数？</summary>

fork 只复制调用线程，其他线程消失。如果消失的线程持有 malloc 锁或 stdio 锁，子进程继承这些锁的锁定状态但无持有者。子进程调用 malloc 或 stdio 函数会死锁。async-signal-safe 函数不使用锁，是安全的。直到 exec 替换地址空间后才能安全调用其他函数。
</details>

<details>
<summary>2. 如何让信号只由一个指定线程处理？</summary>

```c
/* 所有线程屏蔽目标信号 */
sigset_t set;
sigemptyset(&set);
sigaddset(&set, SIGINT);
pthread_sigmask(SIG_BLOCK, &set, NULL);

/* 信号处理线程用 sigwait */
void *signal_thread(void *arg) {
    int sig;
    sigwait(&set, &sig);
    printf("received signal %d\n", sig);
    return NULL;
}
```

这种模式避免信号处理器中调用非异步安全函数的问题。
</details>

<details>
<summary>3. SCHED_FIFO 和 SCHED_RR 的区别？</summary>

- **SCHED_FIFO**：同优先级线程按 FIFO 顺序运行，除非主动让出（`sched_yield`）或被更高优先级抢占，否则会一直运行
- **SCHED_RR**：同优先级线程轮转，每个线程运行一个时间片（默认 100ms）后被抢占，轮到下一个同优先级线程

HFT 通常用 SCHED_FIFO（策略线程独占 CPU 核心，不被同优先级线程打断）。
</details>
