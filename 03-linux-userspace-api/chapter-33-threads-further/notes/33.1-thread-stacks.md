## 要点

### 主线程栈 vs 子线程栈：三个本质差异

这是本节最容易被忽略的认知——「线程栈」这个词掩盖了两套完全不同的机制：

| 维度 | 主线程栈 | 子线程栈 |
|------|---------|---------|
| 位置 | 进程栈区（高地址，`0x7ffc...` 附近，紧邻环境变量） | mmap 区（`0x7f...` 中段，与库/共享内存同区） |
| 分配者 | 内核 `execve` 时静态划定 | glibc 调 `mmap(MAP_STACK)` 动态分配 |
| 可增长 | ✅ `expand_downwards()` 按需向下扩展（VMA 可变） | ❌ 固定大小，溢出即玩完 |
| 默认大小 | `RLIMIT_STACK`（通常 8MB） | glibc 取 `RLIMIT_STACK`（unlimited 时退回 2MB） |
| guard 页 | 无（溢出撞到的是别的 VMA 或空洞 → SIGSEGV） | 有（默认 1 页 4KB 只读 guard） |

为什么主线程栈可以增长？它的 VMA 带 `VM_GROWSDOWN` 标志，缺页时内核检查是否向下越界、在限额内就扩。子线程栈是普通匿名映射，没有这个标志——**新线程栈不增长**。

### 栈大小的 API 层

```c
pthread_attr_setstacksize(attr, size)      /* 设大小，必须 ≥ PTHREAD_STACK_MIN */
pthread_attr_getstacksize(attr, &size)
pthread_attr_setstack(attr, addr, size)    /* 自备内存当栈（少用：需 4KB 对齐） */
pthread_attr_setguardsize(attr, size)      /* 0 = 关 guard */
sysconf(_SC_THREAD_STACK_MIN)              /* = PTHREAD_STACK_MIN，通常 16KB */
```

规则速记：

- 设小于 `PTHREAD_STACK_MIN`（16KB）→ `pthread_attr_setstacksize` 返回 `EINVAL`；
- guard 计入 mmap 总量但**不计入** `stacksize`（后者是可用区）；
- `setstack` 与 `setstacksize/guardsize` 互斥（一次设置覆盖另一侧）。

### 每线程的隐藏成本（HFT 算账用）

| 成本 | 大小 | 归属 |
|------|------|------|
| 用户态栈（虚拟） | 默认 8MB/线程 | mmap 地址空间 |
| 用户态栈（物理） | 按需，只算触碰过的页 | RSS |
| **内核栈** | **16KB/线程**（`THREAD_SIZE = PAGE_SIZE << 2`） | **物理内存立即占用，不可分页** |
| guard 页 | 4KB | 8MB 里划出（虚拟） |

1000 线程 = 16MB 内核栈物理内存 + 8GB 虚拟地址。内核栈用 `__vmalloc_node_range()` 分配（`kernel/fork.c:309`）且带缓存复用（`:303-306` 注释：线程退出后栈保留在 per-CPU 缓存，下一个新线程直接复用——省去 16KB 的分配/清零）。

### 栈溢出的三种结局

1. **越过后撞 guard 页**（小步溢出，如深递归）→ guard 页不可写 → SIGSEGV，崩溃点就在栈附近（好排查）；
2. **一步跨过 guard 页**（大缓冲区写入，如 `char buf[8192]` 溢出）→ guard 只有 4KB，直接踩进相邻 VMA → 可能不立即崩，数据悄悄坏（最难排查）；
3. **主线程栈溢出**（无 guard）→ 撞到任意映射 → SIGSEGV 或静默写坏别的数据。

## HFT / 嵌入式关联

| 路线 | 要点 |
|------|------|
| 嵌入式 | 线程数 × 栈 = 硬内存预算：内核栈 16KB/线程是**立即占用的物理内存**，512MB 板子开 5000 线程光内核栈就烧 80MB |
| HFT | 一核一线程 + 小栈（1~2MB）：既控制地址空间总量，又让所有线程常驻不同核的 cache；栈顶地址对齐到 2MB/4MB 边界可降低 TLB 压力 |
| HFT | 热路径禁深递归：每层 ~32B（实测 x86-64），1MB 栈 ≈ 3 万层余量，但递归本身是不确定延迟源 |

## 代码示例

```c
/* stack_probe.c — Ch33.1：主线程栈 vs 子线程栈的地址空间布局实测
 * 观测：三线程地址分区 / 默认栈大小 / PTHREAD_STACK_MIN / RLIMIT
 * 编译：gcc -O2 -Wall -Wextra -o stack_probe stack_probe.c -pthread
 */
#define _GNU_SOURCE
#include <stdio.h>
#include <string.h>
#include <pthread.h>
#include <unistd.h>
#include <sys/resource.h>

static void print_frame(const char *who, int depth)
{
    char pad[32];
    memset(pad, ' ', depth * 2);
    pad[depth * 2] = '\0';
    char probe[16];
    printf("%s%-10s 帧地址 %p\n", pad, who, (void *)probe);
    if (depth > 0)
        print_frame(who, depth - 1);      /* 递归 5 层，观测 SP 下移 */
}

static void *worker(void *arg)
{
    long id = (long)arg;
    char name[16];
    snprintf(name, sizeof name, "worker%ld", id);
    print_frame(name, 5);
    return NULL;
}

int main(void)
{
    printf("== 栈属性 ==\n");
    printf("PTHREAD_STACK_MIN      = %d B (%d KB)\n",
           (int)sysconf(_SC_THREAD_STACK_MIN),
           (int)(sysconf(_SC_THREAD_STACK_MIN) / 1024));

    struct rlimit rl;
    getrlimit(RLIMIT_STACK, &rl);
    printf("RLIMIT_STACK           = ");
    if (rl.rlim_cur == RLIM_INFINITY) printf("unlimited（glibc 子线程退回 2MB）\n");
    else                                printf("%llu MB\n", (unsigned long long)(rl.rlim_cur >> 20));

    pthread_attr_t attr;
    pthread_attr_init(&attr);
    size_t ss = 0, gs = 0;
    pthread_attr_getstacksize(&attr, &ss);
    pthread_attr_getguardsize(&attr, &gs);
    printf("子线程默认 stacksize   = %zu B（%zu MB）\n", ss, ss >> 20);
    printf("子线程默认 guardsize   = %zu B\n", gs);
    pthread_attr_destroy(&attr);

    printf("\n== 地址空间分区（主线程高地址 / 子线程 mmap 区）==\n");
    print_frame("main", 5);

    pthread_t t[3];
    for (long i = 0; i < 3; i++)
        pthread_create(&t[i], NULL, worker, (void *)i);
    for (int i = 0; i < 3; i++)
        pthread_join(t[i], NULL);
    return 0;
}
```

实测输出（WSL2 / 12 核，gcc -O2 零告警）：

```text
== 栈属性 ==
PTHREAD_STACK_MIN      = 16384 B (16 KB)
RLIMIT_STACK           = 8 MB
子线程默认 stacksize   = 8388608 B (8 MB)
子线程默认 guardsize   = 4096 B

== 地址空间分区（主线程高地址 / 子线程 mmap 区）==
          main 帧地址 0x7ffff1044ff0
        main 帧地址 0x7ffff1044f90
      main 帧地址 0x7ffff1044f30
    main 帧地址 0x7ffff1044ed0
  main 帧地址 0x7ffff1044e70
main 帧地址 0x7ffff1044e10
          worker0 帧地址 0x7aab3b9fee80
        worker0 帧地址 0x7aab3b9fee10
      worker0 帧地址 0x7aab3b9fedb0
    worker0 帧地址 0x7aab3b9fed50
  worker0 帧地址 0x7aab3b9fecf0
worker0 帧地址 0x7aab3b9fec90
          worker1 帧地址 0x7aab3b1fde80
...
```

三点解读：

1. **两套地址分区**：main 的帧在 `0x7ffff...`（进程栈区，紧贴高地址），三个 worker 的帧在 `0x7aab...`（mmap 区）——同一进程里「线程栈」占着两个完全不同的地址区间。
2. **每层帧 ~0x60 字节（96B）**：相邻递归层地址差 96B（-O2 含对齐与保存的帧开销），1MB 栈理论余量 1 万+ 层。
3. **worker 栈相邻间隔 = 8MB 栈 + 4KB guard**（实测 worker1/worker2 帧地址差 0x801000）——mmap 区里一列紧挨的栈+guard 序列，直接看到 guard 页就在栈底之下。

## 自测题

**题目 1（判断）：** 子线程栈默认 8MB 用完后会自动增长吗？

<details>
<summary>参考答案</summary>

不会。只有主线程栈的 VMA 带 `VM_GROWSDOWN` 标志（`expand_downwards` 按需扩展）；子线程栈是 glibc 用 `mmap` 映的普通匿名区，固定大小——**新线程栈不增长**，写越界要么撞 guard 页 SIGSEGV，要么跨过 guard 踩坏相邻 VMA。

</details>

**题目 2（计算）：** 512MB 内存的嵌入式板子，最多开多少个线程才安全（只算内核栈）？

<details>
<summary>参考答案</summary>

每线程内核栈 `THREAD_SIZE` = 16KB（`PAGE_SIZE << 2`，v6.6 x86-64 `page_64_types.h:16`）物理内存、立即占用、不可分页。512MB 全给线程栈（不现实，仅算上限）= 32768 个；实际还要留用户态物理页 + 内核其他结构，工程上按内存 5~10% 预算 → 1600~3200 线程量级。

</details>

**题目 3（概念）：** guard 页为什么只能挡「小步溢出」？

<details>
<summary>参考答案</summary>

guard 默认 1 页（4KB）且**位于栈底之下**（低地址）。递归类小步溢出每帧只向下挪几十字节，会先踩进 guard → SIGSEGV（好排查）。但单个大写入（如 `char buf[8192]` 的 memset）一步跨过 4KB guard 直接命中相邻 VMA——可能不崩，数据悄悄坏。

</details>

**题目 4（观察）：** 怎么用 `pmap` 或 `/proc/pid/maps` 区分主线程栈和子线程栈？

<details>
<summary>参考答案</summary>

主线程栈是 `[stack]` 标记的 VMA（高地址）；子线程栈无专门标记，表现为 mmap 区的匿名 VMA（`[ anon ]`，4KB/8MB 大小、前后常伴一个 `---p`（无权限）小段即 guard）。demo 里 worker 帧地址 `0x7f4f...` 与 main 的 `0x7ffc...` 分区即直接证据。

</details>
