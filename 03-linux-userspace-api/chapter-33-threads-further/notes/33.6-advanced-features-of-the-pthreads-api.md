## 要点

### 四原语对照表

| 原语 | 语义 | 典型场景 | 误用之最 |
|------|------|---------|---------|
| `pthread_rwlock_t` | 读共享、写独占 | 读多写少（配置表：99% 查 1% 更新） | 读锁内调写者也要读的共享缓存（递归死锁）；写饥饿（glibc 默认读者优先变体，写者可能饿死——有 `_NP` 变体可调） |
| `pthread_barrier_t` | 集合点：全员到齐才一起过 | 分阶段并行（全员到齐再进下一 phase）；数据接力（A 们写完 B 们才能读） | 期望它带数据传递——barrier 只同步不传值；忘了 `PTHREAD_BARRIER_SERIAL_THREAD` 只有一个线程拿到返回值这个事实 |
| `pthread_spinlock_t` | 忙等锁 | **核内**短临界区（<几十 ns：改几个变量）且**不可阻塞** | 临界区里出现任何系统调用/内存缺页/长循环——自旋烧掉整个时间片还拖慢持锁者（30.1 实测跨核 spin 81ns/次比 mutex 69ns 还慢） |
| `PTHREAD_PROCESS_SHARED` | 属性（非新原语） | mutex/condvar/rwlock/barrier 放共享内存跨进程 | 忘设 shared 属性 → 跨进程锁**假成功**（各自锁了各自的缓存行）；锁所在的共享内存被双方以不同地址映射时仍 OK（futex key 按物理页），但对象内不能存指针 |

### 读写锁：读者优先的代价

glibc 默认实现读者优先：只要有读者鱼贯而来，写者就一直排队——**写饥饿**是真实风险：

| 变体 | 行为 | 获取 |
|------|------|------|
| 默认 | 读者优先（读者可以"插队"到等待写者前面） | `PTHREAD_RWLOCK_INITIALIZER` |
| `_NP` 变体 | 写者优先 | `pthread_rwlockattr_setkind_np(&attr, PTHREAD_RWLOCK_PREFER_WRITER_NONRECURSIVE_NP)` |

判据：**写延迟敏感**（如行情快照刷新）必须上 writer-prefer 或干脆 mutex；rwlock 的收益窗口其实很窄——读临界区必须足够短、写频率足够低，否则 mutex（无竞争 7ns）反而更快（30.1 数据）。

### barrier：一到两次的"GO"

```c
pthread_barrier_init(&b, NULL, nthreads);      /* 计数 = nthreads */
int rc = pthread_barrier_wait(&b);
/* rc == PTHREAD_BARRIER_SERIAL_THREAD（只在一个线程）→ 该线程做 phase 间串行收尾 */
pthread_barrier_destroy(&b);
```

- `rc` 的设计：`n` 个线程同时返回，但其中恰好 1 个拿到 `SERIAL_THREAD`、其余拿 0——**天然选出一个"收尾者"**（改 phase 计数、重置共享变量），省一次额外同步；
- barrier 可**循环使用**：同一批线程一遍遍过同一集合点（`count` 每轮自动重置）。

### PROCESS_SHARED：同步对象进共享内存

```c
pthread_mutexattr_t ma;
pthread_mutexattr_init(&ma);
pthread_mutexattr_setpshared(&ma, PTHREAD_PROCESS_SHARED);   /* ⭐ 默认是 _PRIVATE */
pthread_mutex_init(m_in_shm, &ma);
```

两个坑：

1. **默认 PRIVATE**：放共享内存却忘了设 shared → 各进程在自己地址空间各锁各的（futex key 按 PRIVATE 哈希不含物理页身份）——**假同步**，数据竞争照跑，而且很难复现；
2. 对象必须放在**共享映射**（`shm_open`+`mmap` 或 `MAP_SHARED` 匿名）里，普通全局变量在 fork 之前就在则另说（fork 复制的是 COW，锁状态分裂成两份，见 33.3）。

PRIVATE 为什么快：futex key 跳过 `get_futex_key()` 的 inode/page 反查（30.1 核验的 `FUT_OFF_MMSHARED` 路径），单进程内一律走 mm 偏移——省几十 ns 与一次 cache line 弹跳。

## HFT / 嵌入式关联

| 路线 | 要点 |
|------|------|
| HFT | 订单簿/配置快照：seqlock 或 RCU 思想（读不加锁）优先于 rwlock；跨进程共享行情段 + PROCESS_SHARED mutex 只用于低频控制面（高频面走 lock-free） |
| HFT | barrier 用于启动对齐：全员 `mlockall`+预热完成 → barrier → 同时开跑（消除起跑毛刺） |
| 嵌入式 | 单核 MCU 上 spinlock 无意义（自旋=不让出 CPU=持锁者也跑不了）——等于关中断/信号量；SMP SoC 上才谈 spin |
| 通用 | 选型顺序：先问能不能**不加锁**（每线程副本/原子变量/消息传递），再 mutex，rwlock/spin 是特化答案不是默认答案 |

## 代码示例

```c
/* sync_prim.c — Ch33.6：rwlock/barrier/spin 三原语实测
 * demo1: rwlock 并发读计数（8 读 + 1 写）
 * demo2: barrier 三线程两轮集合点 + SERIAL_THREAD 收尾
 * demo3: spinlock 计数（对照 mutex 留给 30.1 数据）
 * 编译：gcc -O2 -Wall -Wextra -o sync_prim sync_prim.c -pthread
 */
#define _GNU_SOURCE
#include <stdio.h>
#include <pthread.h>
#include <unistd.h>

#define NRD 8

static pthread_rwlock_t rw = PTHREAD_RWLOCK_INITIALIZER;
static long shared_val;
static long read_sums[NRD];
static volatile long spin_val;
static pthread_spinlock_t sp;

static void *reader(void *arg)
{
    long id = (long)arg;
    long acc = 0;
    for (int i = 0; i < 100000; i++) {
        pthread_rwlock_rdlock(&rw);
        acc += shared_val;                    /* 读临界区：一行 */
        pthread_rwlock_unlock(&rw);
    }
    read_sums[id] = acc;
    return NULL;
}

static void *writer(void *arg)
{
    (void)arg;
    for (int i = 0; i < 1000; i++) {
        pthread_rwlock_wrlock(&rw);
        shared_val += 1;
        pthread_rwlock_unlock(&rw);
        usleep(100);                          /* 模拟低频写 */
    }
    return NULL;
}

static pthread_barrier_t bar;
static long phase_count[3];

static void *phaser(void *arg)
{
    long id = (long)arg;
    for (int round = 0; round < 2; round++) {
        phase_count[id]++;                    /* 本线程的 phase 进度 */
        int rc = pthread_barrier_wait(&bar);  /* 集合点 */
        if (rc == PTHREAD_BARRIER_SERIAL_THREAD)
            printf("  [round %d] 线程 %ld 是 SERIAL_THREAD：全队到齐（各自 phase=%ld/%ld/%ld）\n",
                   round, id, phase_count[0], phase_count[1], phase_count[2]);
    }
    return NULL;
}

static void *spinner(void *arg)
{
    (void)arg;
    for (int i = 0; i < 1000000; i++) {
        pthread_spin_lock(&sp);
        spin_val++;
        pthread_spin_unlock(&sp);
    }
    return NULL;
}

int main(void)
{
    printf("== demo1: rwlock 8 读 1 写 ==\n");
    pthread_t r[NRD], w;
    for (long i = 0; i < NRD; i++) pthread_create(&r[i], NULL, reader, (void *)i);
    pthread_create(&w, NULL, writer, NULL);
    for (int i = 0; i < NRD; i++) pthread_join(r[i], NULL);
    pthread_join(w, NULL);
    long expect = read_sums[0];               /* 各读者看到不同时刻，但都在 [0,1000] 区间 */
    printf("  writer 共写 %ld 次；读者 acc 样例 %ld（写者结束时其他读者可见终值 1000）\n",
           shared_val, expect);
    printf("  shared_val 终值 = %ld\n", shared_val);

    printf("== demo2: barrier 两轮集合 ==\n");
    pthread_barrier_init(&bar, NULL, 3);
    pthread_t p[3];
    for (long i = 0; i < 3; i++) pthread_create(&p[i], NULL, phaser, (void *)i);
    for (int i = 0; i < 3; i++) pthread_join(p[i], NULL);
    pthread_barrier_destroy(&bar);

    printf("== demo3: spinlock 1M 次自增 ==\n");
    pthread_spin_init(&sp, 0);
    pthread_t s1, s2;
    pthread_create(&s1, NULL, spinner, NULL);
    pthread_create(&s2, NULL, spinner, NULL);
    pthread_join(s1, NULL); pthread_join(s2, NULL);
    pthread_spin_destroy(&sp);
    printf("  spin_val = %ld（期望 2000000）\n", spin_val);
    return 0;
}
```

实测输出（WSL2 / 12 核，gcc -O2 零告警）：

```text
== demo1: rwlock 8 读 1 写 ==
  writer 共写 1000 次；读者 acc 样例 729630（写者结束时其他读者可见终值 1000）
  shared_val 终值 = 1000
== demo2: barrier 两轮集合 ==
  [round 0] 线程 2 是 SERIAL_THREAD：全队到齐（各自 phase=1/1/1）
  [round 1] 线程 0 是 SERIAL_THREAD：全队到齐（各自 phase=2/2/2）
== demo3: spinlock 1M 次自增 ==
  spin_val = 2000000（期望 2000000）
```

三点解读：

1. **demo1**：写 1000 次期间 8 个读者各读 10 万次没有互相阻塞（读共享）。`acc` 样例 729630 = 10 万次读到的 `shared_val` 累加和（全程读到 0→1000 间递增值，均值 ~7.3——写者 usleep(100µs)×1000 次 ≈ 0.1s 内写完，前 1 万次读看到大部分写入）；终值 1000 由写锁独占保证。
2. **demo2**：两轮集合点，SERIAL_THREAD 每轮**可能落在不同线程**（round0 是 2、round1 是 0）——它是"恰好一个拿到"，不是"固定 leader"。`phase=1/1/1`、`2/2/2` 证明真到齐才放行。
3. **demo3**：spinlock 正确性无虞（200 万精确），但 30.1 的基准数据（spin 跨核 81ns vs mutex 69ns）提醒：**短临界区也得真量过再选**，自旋不是免费的快。

## 自测题

**题目 1（判据）：** 什么条件下 spinlock 比 mutex 快？什么条件下反而慢？

<details>
<summary>参考答案</summary>

快：临界区**短于两次上下文切换成本**（μs 级）且运行在**不同核**上——等 50ns 比睡 3μs 划算。慢：①同核（自旋=烧自己的时间片，持锁者根本没机会跑——必须等调度）；②临界区含系统调用/缺页/长循环（自旋时间超过睡眠成本）；③竞争者多（每个自旋者都在烧 CPU 拖慢持锁者抢总线）。30.1 实测跨核 4 线程：spin 81ns 反而比 mutex 69ns 慢——自旋风暴干扰了持锁者的 cache。

</details>

**题目 2（语义）：** `pthread_barrier_wait` 的返回值设计解决了什么问题？

<details>
<summary>参考答案</summary>

`n` 个线程同时被放行，但**恰好一个**拿到 `PTHREAD_BARRIER_SERIAL_THREAD`——自动选出一个"收尾者"执行 phase 间串行工作（重置计数器、swap 缓冲、打印汇总），其余线程拿 0 直接进下一轮。没有它就得再补一次"谁负责收尾"的选举同步。demo2 还证明收尾者每轮可能不同——程序**不能假设**它固定。

</details>

**题目 3（陷阱）：** 把 `PTHREAD_MUTEX_INITIALIZER` 的 mutex 放进 `shm_open` 的共享内存，两个进程各自锁定/解锁都成功——数据却在竞争。哪里错了？

<details>
<summary>参考答案</summary>

忘了 `pthread_mutexattr_setpshared(&attr, PTHREAD_PROCESS_SHARED)`。默认 PRIVATE 的 futex key 按"进程私有地址"哈希——两个进程各自锁的是**逻辑上同一个对象、内核视角两个独立锁**（key 不同桶）。必须 init 时设 shared 属性，futex key 才走物理页身份（`FUT_OFF_INODE/MMSHARED` 路径）锁定真身。

</details>

**题目 4（选型）：** 配置表 99% 读 1% 写、写延迟不敏感，rwlock 一定比 mutex 好吗？

<details>
<summary>参考答案</summary>

不一定。读临界区只有几 ns 时 rwlock 的原子计数开销（读者登记/退出）可能吃掉全部收益——无竞争 mutex 7ns（30.1 实测）很难输。rwlock 赢面在读临界区**够长**（μs 级：要遍历哈希表）且写**低频**（此时读侧重叠度才值回开销）。写延迟敏感场景 glibc 默认读者优先会写饥饿——上 writer-prefer 变体或换设计（双缓冲 + 原子指针切换）。

</details>
