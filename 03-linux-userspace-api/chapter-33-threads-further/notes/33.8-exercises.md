## 练习题

### 练习 1：fork 在多线程中的问题

编写多线程程序，一个线程持有 mutex，另一个线程调用 `fork()`。子进程尝试 lock 同一个 mutex 会发生什么？

### 练习 2：信号专用线程

实现一个信号处理专用线程模式：主工作线程屏蔽 SIGINT/SIGTERM，信号线程用 `sigwait()` 接收信号并设置退出标志。

### 练习 3：实时调度测试

编写程序，创建两个线程分别用 SCHED_FIFO 和 SCHED_OTHER 调度策略，对比 CPU 占用和延迟。

## 参考答案

### 练习 1 答案

```c
pthread_mutex_t mutex = PTHREAD_MUTEX_INITIALIZER;

void *thread_a(void *arg) {
    pthread_mutex_lock(&mutex);
    sleep(5);  /* 持有锁 5 秒 */
    pthread_mutex_unlock(&mutex);
    return NULL;
}

void *thread_b(void *arg) {
    sleep(1);  /* 等 thread_a 持有锁 */
    pid_t pid = fork();
    if (pid == 0) {
        /* 子进程：只复制了 thread_b，thread_a 消失 */
        /* mutex 仍然锁定，但没有持有者 */
        pthread_mutex_lock(&mutex);  /* 死锁！ */
        printf("child got lock\n");
        pthread_mutex_unlock(&mutex);
        _exit(0);
    }
    return NULL;
}
```

子进程死锁——mutex 从父进程继承的锁定状态，但没有线程持有它。`pthread_mutex_lock` 会永远阻塞。

**解决**：用 `pthread_atfork()` 注册 handler 在子进程中重新初始化 mutex，或避免在多线程中 fork。

### 练习 2 参考代码

```c
#include <pthread.h>
#include <signal.h>
#include <stdatomic.h>
#include <stdio.h>

static atomic_int should_exit = 0;
static sigset_t signal_set;

void *signal_thread(void *arg) {
    int sig;
    while (1) {
        sigwait(&signal_set, &sig);
        printf("signal %d received\n", sig);
        if (sig == SIGINT || sig == SIGTERM) {
            atomic_store(&should_exit, 1);
            break;
        }
    }
    return NULL;
}

int main(void) {
    /* 屏蔽信号（所有线程继承） */
    sigemptyset(&signal_set);
    sigaddset(&signal_set, SIGINT);
    sigaddset(&signal_set, SIGTERM);
    pthread_sigmask(SIG_BLOCK, &signal_set, NULL);

    /* 启动信号线程 */
    pthread_t sig_tid;
    pthread_create(&sig_tid, NULL, signal_thread, NULL);

    /* 工作循环 */
    while (!atomic_load(&should_exit)) {
        /* 工作 */
    }

    pthread_join(sig_tid, NULL);
    printf("exiting gracefully\n");
    return 0;
}
```

### 练习 3 答案

SCHED_FIFO 线程优先级高于 SCHED_OTHER，会独占 CPU 直到主动让出。SCHED_OTHER 线程会被饥饿（得不到 CPU）。

```bash
# 需要 root 迈权或 CAP_SYS_NICE
sudo ./sched_test
```

预期结果：SCHED_FIFO 线程 CPU 使用率接近 100%，SCHED_OTHER 线程被挤压到接近 0%。

**注意**：测试时确保不是在唯一 CPU 核上运行，否则会冻系统。用 `taskset` 限制到特定核心。

## HFT / 嵌入式关联

- **fork 禁忌**：HFT 多线程服务用 `posix_spawn` 替代 fork+exec
- **信号线程**：HFT 标准模式——信号线程 + 工作线程屏蔽信号
- **实时调度**：HFT 策略线程 SCHED_FIFO + CPU 隔离（`isolcpus`）
- **嵌入式**：RTOS 有固定优先级调度，类似 SCHED_FIFO
