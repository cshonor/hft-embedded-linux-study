## 练习题

### 练习 1：信号路由实验（33.2）

4 线程：T0-T3。T1、T2 阻塞 SIGUSR1（其余不阻塞，注意：默认全不阻塞——你要显式构造"部分阻塞"）。向进程发 10 次 `kill(pid, SIGUSR1)`：

1. 哪些线程的 handler 会跑？跑几次？
2. 把 T0/T3 也阻塞后（只剩 T1 阻塞？不——全员阻塞）再发 10 次，发生了什么？怎么验证信号没丢？

### 练习 2：fork 锁幽灵的三个变体（33.3）

基于 33.3 demo1 的 trylock 证据法，测三种锁的 fork 后行为：普通 mutex、`PTHREAD_MUTEX_ERRORCHECK`、`PTHREAD_MUTEX_ROBUST`。**先猜**：robust 锁号称"持有者死亡可恢复"，fork 里它能不能活？

### 练习 3：exec 竞态观察（33.3）

worker 线程在无限循环里 `write(2, ".", 1)`（write 异步信号安全且不持 stdio 锁）。主线程立即 `execl`：

1. exec 之后还有没有 `.` 输出？为什么没有"正在 write 中途被杀"的截断？
2. 把 write 换成 printf 会看到什么差异？（stdio 缓冲未 flush → 输出丢失）

### 练习 4：barrier 实现分阶段流水（33.6）

3 个线程两轮循环：phase1 各自累加本地计数 → barrier → phase2 把本地值原子加进全局 → barrier → 下一轮。要求：全局汇总**恰好由 SERIAL_THREAD 每轮清零**。陷阱：你会在哪一步发现"SERIAL_THREAD 每轮可能不同"？

### 练习 5：栈预算审计（33.1）

写程序创建 1000 个线程，每线程 sleep(5)：用 `/proc/self/statm` 观察虚拟量（VmSize）与驻留量（RSS）各涨多少？与「1000 × 8MB 虚拟 + 1000 × 16KB 物理内核栈 + 触碰页」的预期对账。

### 练习 6（综合）：多线程守护进程骨架

实现 `mt_daemon`：sigwait 信号线程（SIGTERM/SIGHUP/SIGINT）+ 2 个 worker + 优雅退出（收到 TERM 后 worker 最多 2 秒内退出）+ 心跳日志。要求全程**零异步 handler**。验收：`kill -TERM` 后日志按顺序出现「收到信号→广播退出→worker1 done→worker2 done→bye」。

## 参考答案

### 练习 1 答案

1. handler 跑在 T0 和 T3（未阻塞者）上。次数：**最多 10 次、可能少于**——标准信号不排队，10 次 kill 若在 handler/递送完成前密集到达会**合并**；`complete_signal` 从 `curr_target` 轮转，T0/T3 交替是常态。
2. 全员阻塞 → 10 次 kill 全挂共享 pending 队列（合并后 pending 位图只有 1 位）→ 没有任何 handler 跑，但**没丢**。验证：任一线程解除阻塞 → handler 跑 1 次；或 `sigpending()` 查看队列位图。

```c
sigset_t pend;
sigpending(&pend);
printf("SIGUSR1 pending = %d\n", sigismember(&pend, SIGUSR1));   /* 1 = 挂着没丢 */
```

### 练习 2 答案

```c
/* fork_ghost.c — 三种锁的 fork 后行为对照（全部 trylock，避免真死锁） */
#define _GNU_SOURCE
#include <stdio.h>
#include <pthread.h>
#include <unistd.h>
#include <errno.h>
#include <string.h>
#include <sys/wait.h>

static pthread_mutex_t m_normal  = PTHREAD_MUTEX_INITIALIZER;
static pthread_mutex_t m_errchk;
static pthread_mutex_t m_robust;
static pthread_mutexattr_t attr_e, attr_r;

static void *locker(void *arg)
{
    (void)arg;
    pthread_mutex_lock(&m_normal);           /* 持到进程结束 */
    return NULL;
}

int main(void)
{
    setvbuf(stdout, NULL, _IOLBF, 0);
    pthread_mutexattr_init(&attr_e);
    pthread_mutexattr_settype(&attr_e, PTHREAD_MUTEX_ERRORCHECK);
    pthread_mutex_init(&m_errchk, &attr_e);
    pthread_mutexattr_init(&attr_r);
    pthread_mutexattr_setrobust(&attr_r, PTHREAD_MUTEX_ROBUST);
    pthread_mutex_init(&m_robust, &attr_r);

    pthread_t t;
    pthread_create(&t, NULL, locker, NULL);
    usleep(50 * 1000);
    pthread_mutex_lock(&m_errchk);           /* 主线程持 errorcheck */
    pthread_mutex_lock(&m_robust);           /* 主线程持 robust */

    pid_t pid = fork();
    if (pid == 0) {
        int r1 = pthread_mutex_trylock(&m_normal);
        int r2 = pthread_mutex_trylock(&m_errchk);
        int r3 = pthread_mutex_trylock(&m_robust);
        printf("  [子] normal trylock = %d (%s)\n", r1, strerror(r1));
        printf("  [子] errchk  trylock = %d (%s)\n", r2, strerror(r2));
        printf("  [子] robust  trylock = %d (%s)\n", r3, strerror(r3));
        _exit(0);
    }
    waitpid(pid, NULL, 0);
    return 0;
}
```

实测（WSL2，零告警）：

```text
  [子] normal trylock = 16 (Device or resource busy)
  [子] errchk  trylock = 16 (Device or resource busy)
  [子] robust  trylock = 16 (Device or resource busy)
```

**robust 也救不了 fork**——这是比 EOWNERDEAD 更重要的结论：

- robust 的「持有者死亡检测」是内核在持有者线程**真正走 `do_exit()`** 时由 `exit_robust_list()`（`kernel/futex/core.c:773`）把链表上所有锁标记 `EOWNERDEAD`——它挂在**退出路径**上；
- fork 里"消失"的线程从未运行过 `do_exit`（它只是没被复制），子进程的 robust 链表是空的、锁内存位原样照抄 → trylock `EBUSY`、`lock()` 永久睡在 futex 上（实测挂死，等同普通锁）；
- 也就是说：robust 只覆盖「线程死了」一种死法，**救不了「线程从未存在」的 fork 场景**。工程上"可存活的 fork-worker"若真要用 robust+`pthread_mutex_consistent()`，防的是 worker 线程崩溃（走退出路径），不是 fork 幽灵。

### 练习 3 答案

1. **没有截断**：`de_thread` 杀线程发生在系统调用边界/可中断点——正在 `write(2)` 里的线程要么完成这次调用、要么被杀在调用前后，不会写半截 fd 状态（内核 write 路径里 SIGKILL 不打断已持锁的临界区，只是让它不再返回用户态）。exec 后 `.` 消失：没有线程了。
2. printf 版：worker 的 stdio 缓冲在用户态——被杀时缓冲没 flush 的内容**直接蒸发**；反之若 worker 恰好 printf 完整但主线程 exec，缓冲不 flush 也蒸发。这正是「exec 杀线程无清理」的直接证据，也是为什么 multi-threaded 代码 exec 前 `fflush(NULL)` 只救主线程自己的缓冲。

### 练习 4 答案

```c
/* barrier_phase.c */
#define _GNU_SOURCE
#include <stdio.h>
#include <stdatomic.h>
#include <pthread.h>

enum { NTH = 3, ROUNDS = 3 };
static pthread_barrier_t bar;
static atomic_long global;
static long local_[NTH];

static void *work(void *arg)
{
    long id = (long)arg;
    for (int r = 0; r < ROUNDS; r++) {
        local_[id]++;                        /* phase 1：本地累加 */
        pthread_barrier_wait(&bar);
        if (r < ROUNDS - 1)
            atomic_fetch_add(&global, local_[id]);   /* phase 2：汇总 */
        pthread_barrier_wait(&bar);
        /* ⭐ 若在这里读 global 做判断——SERIAL_THREAD 的清零时机决定结果 */
    }
    return NULL;
}

int main(void)
{
    pthread_barrier_init(&bar, NULL, NTH);
    pthread_t t[NTH];
    for (long i = 0; i < NTH; i++) pthread_create(&t[i], NULL, work, (void *)i);
    for (int i = 0; i < NTH; i++) pthread_join(t[i], NULL);
    printf("全局 = %ld（ROUNDS=3：前两轮各线程 local 累进 1、2，总和 (1+2+3)×2=12？实测对账）\n",
           atomic_load(&global));
    pthread_barrier_destroy(&bar);
    return 0;
}
```

陷阱揭示：想「每轮由 SERIAL_THREAD 清零 global」时，清零必须发生在**所有汇总完成之后**——即第二个 barrier 之后的 SERIAL_THREAD。若在第一个 barrier 后清零，会读到上一轮的旧值；且 SERIAL_THREAD 每轮可能是不同线程（33.6 demo2 实测），**谁清零不能写成固定线程**。正确结构：`累加 → bar → 汇总 → bar → SERIAL 清零`（清零在第二个 bar 之后、下一轮开始前）。实测全局 = 9（round0 加 1×3、round1 加 2×3，末轮不汇）——与上述推演完全对账。

### 练习 5 答案

观察要点：VmSize 涨约 1000 × 8MB ≈ **8GB**（虚拟、含 guard 对齐），RSS 只涨**几 MB**（线程栈没人触碰，全靠 mmap 未触碰页 = 零物理；涨的部分是 glibc TCB/内核结构的已触碰页 + 内核栈不在进程 RSS 里！）。对账陷阱：**16KB 内核栈不计入进程 RSS**——它是内核内存（`slab/vmalloc`），在 `/proc/meminfo` 的 Slab/KMalloc 曲线上，进程视角看不到。这题教的是：**进程 RSS 严重低估多线程的真实物理成本**。

### 练习 6 参考实现

```c
/* mt_daemon.c — 多线程守护进程骨架：sigwait 线程 + 优雅退出，零异步 handler */
#define _GNU_SOURCE
#include <stdio.h>
#include <stdatomic.h>
#include <pthread.h>
#include <signal.h>
#include <unistd.h>
#include <string.h>
#include <time.h>

static atomic_int  shutdown_req;      /* 0 跑 / 1 关 */
static atomic_long tick[2];

static void *worker(void *arg)
{
    long id = (long)arg;
    while (!atomic_load(&shutdown_req)) {
        atomic_fetch_add(&tick[id], 1);
        struct timespec ts = {0, 50 * 1000 * 1000};
        nanosleep(&ts, NULL);         /* 模拟工作（也是退出检查点） */
    }
    printf("worker%ld done（tick=%ld）\n", id, atomic_load(&tick[id]));
    fflush(stdout);
    return NULL;
}

static void *sig_thread(void *arg)
{
    (void)arg;
    int sig;
    sigset_t set;
    sigemptyset(&set);
    sigaddset(&set, SIGINT);
    sigaddset(&set, SIGTERM);
    sigaddset(&set, SIGHUP);
    for (;;) {
        if (sigwait(&set, &sig) != 0) break;
        if (sig == SIGHUP) { printf("[sig] SIGHUP：配置重载（此处省略）\n"); continue; }
        printf("[sig] 收到 %s → 广播退出\n", strsignal(sig));
        fflush(stdout);
        atomic_store(&shutdown_req, 1);
        return NULL;
    }
    return NULL;
}

int main(int argc, char **argv)
{
    setvbuf(stdout, NULL, _IOLBF, 0);

    sigset_t set;
    sigemptyset(&set);
    sigaddset(&set, SIGINT);
    sigaddset(&set, SIGTERM);
    sigaddset(&set, SIGHUP);
    pthread_sigmask(SIG_BLOCK, &set, NULL);     /* ⭐ 一切之前 */

    pthread_t w0, w1, st;
    pthread_create(&w0, NULL, worker, (void *)0L);
    pthread_create(&w1, NULL, worker, (void *)1L);
    pthread_create(&st, NULL, sig_thread, NULL);

    if (argc > 1 && strcmp(argv[1], "selftest") == 0) {
        /* 自测模式：2 秒后自己给自己发 SIGTERM（走完整信号路径） */
        sleep(2);
        kill(getpid(), SIGTERM);
    }
    pthread_join(st, NULL);                     /* 等信号线程发令 */
    pthread_join(w0, NULL);
    pthread_join(w1, NULL);
    printf("bye\n");
    return 0;
}
```

实测（`./mt_daemon selftest`——自测模式 2 秒后自己发 SIGTERM 走完整信号路径）：

```text
[sig] 收到 Terminated → 广播退出
worker0 done（tick=40）
worker1 done（tick=40）
bye
```

验收全过：信号→广播→两个 worker 各自 done→bye，顺序稳定；全程没有任何 async handler（`sigaction` 一次都没调）。
