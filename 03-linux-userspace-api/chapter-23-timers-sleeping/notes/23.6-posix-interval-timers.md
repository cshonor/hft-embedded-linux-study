## 本节讲什么

§23.1 的 `setitimer()` 有四个硬伤。POSIX.1b 定义了一套新 API 把它们**逐个**解决，Linux 2.6 起完整实现。本节就是把这四个硬伤 ↔ 四个解法一一对上：

| `setitimer()` 的硬伤（原书原文） | POSIX 定时器的解法 |
|---|---|
| *We can set only **one timer** of each of the three types* | `timer_create()` **可以创建任意多个**定时器，每个有独立的 ID |
| *The only way of being notified of timer expiration is via delivery of a signal. Furthermore, **we can't change the signal*** | `struct sigevent` 可选：**不通知 / 指定信号 / 起线程 / 发给指定线程** |
| *If an interval timer expires multiple times while the corresponding signal is blocked, then the signal handler is called only once. In other words, **we have no way of knowing whether there was a timer overrun*** | **overrun 计数**：`timer_getoverrun()` 或 `si_overrun`（§23.6.6） |
| *Timers are limited to **microsecond resolution*** | 走 **POSIX 时钟**（纳秒表示），HRT 下精度由硬件决定（§23.5） |

外加一条本节最大的实用价值：**定时器可以拿一个文件描述符来通知** —— 不过那是 §23.7 的 `timerfd`。本节先讲信号与线程两种通知。

## 1. 生命周期：三个系统调用

原书把定时器的一生分成三步：

> - The `timer_create()` system call **creates** a new timer and defines the method by which it will notify the process when it expires.
> - The `timer_settime()` system call **arms** (starts) or **disarms** (stops) a timer.
> - The `timer_delete()` system call **deletes** a timer that is no longer required.

生命周期规则（原书逐字）：

> POSIX timers are **not inherited** by a child created by `fork()`. They are **disarmed and deleted** during an `exec()` or on process termination.

| 事件 | 对 POSIX 定时器的影响 | 对比 `setitimer` |
|------|---------------------|-----------------|
| `fork()` | **不继承**（子进程一个都没有） | `setitimer` 也不继承 |
| `exec()` | **被解除武装并删除** | `setitimer` 的定时器**跨 `exec` 保留** |
| 进程终止 | 自动删除 | —— |

> ⚠️ 最后一行那个对比很容易记反：**老的 `ITIMER_REAL` 会跨 `exec` 活下来，新的 POSIX 定时器不会。** 写「`exec` 自己重启自己」这类程序时，定时器语义会变。

> 📌 原书还说 *On Linux, programs using the POSIX timer API must be compiled with the `-lrt` option* —— 同样是时代产物。**glibc ≥ 2.17 已把 librt 并入 libc**，本仓库实测直接 `gcc -O0 -Wall -Wextra` 即可，无需 `-lrt`。

## 2. §23.6.1 创建定时器：`timer_create()`

```c
#define _POSIX_C_SOURCE 199309
#include <signal.h>
#include <time.h>

int timer_create(clockid_t clockid, struct sigevent *evp, timer_t *timerid);
```

| 参数 | 含义 |
|------|------|
| `clockid` | 用哪个时钟计时。可以填 §23.5 Table 23-1 的任一种，**也可以是 `clock_getcpuclockid()` / `pthread_getcpuclockid()` 的返回值** |
| `evp` | 到期时**怎么通知**；传 `NULL` 有明确默认（见下） |
| `timerid` | 输出参数：一个**句柄**，后续 `timer_settime`/`timer_gettime`/`timer_delete` 都用它 |

### `struct sigevent`

```c
union sigval {
    int   sival_int;              /* Integer value for accompanying data */
    void *sival_ptr;              /* Pointer value for accompanying data */
};

struct sigevent {
    int          sigev_notify;    /* Notification method */
    int          sigev_signo;     /* Timer expiration signal */
    union sigval sigev_value;     /* Value accompanying signal or
                                     passed to thread function */
    union {
        pid_t      _tid;          /* ID of thread to be signaled */
        struct {
            void (*_function) (union sigval);   /* Thread notification function */
            void  *_attribute;                  /* Really 'pthread_attr_t *' */
        } _sigev_thread;
    } _sigev_un;
};

#define sigev_notify_function    _sigev_un._sigev_thread._function
#define sigev_notify_attributes  _sigev_un._sigev_thread._attribute
#define sigev_notify_thread_id   _sigev_un._tid
```

> ⭐ 注意最后三个**宏**：`sigev_notify_function` / `sigev_notify_attributes` / `sigev_notify_thread_id` **根本不是结构体成员**，而是对那个匿名 union 里成员的重命名。所以你在代码里写 `sev.sigev_notify_function = ...` 其实是在访问 `sev._sigev_un._sigev_thread._function`。这个设计是为了**让 `union` 不暴露在 API 表面**。

### Table 23-2：`sigev_notify` 的四种取值

| `sigev_notify` 值 | 通知方式 | 是否 SUSv3 |
|-------------------|---------|-----------|
| `SIGEV_NONE` | **不通知**；用 `timer_gettime()` 自己轮询进度 | ✅ |
| `SIGEV_SIGNAL` | 给**进程**发 `sigev_signo` 信号 | ✅ |
| `SIGEV_THREAD` | 把 `sigev_notify_function` 当作**新线程的启动函数**调用 | ✅ |
| `SIGEV_THREAD_ID` | 把 `sigev_signo` 发给 `sigev_notify_thread_id` 指定的**线程** | ❌ **Linux 专有** |

四种各自的细节（原书）：

- **`SIGEV_NONE`**：*Don't provide notification of timer expiration. The process can still monitor the progress of the timer using `timer_gettime()`.*
- **`SIGEV_SIGNAL`**：*If `sigev_signo` is a **realtime signal**, then the `sigev_value` field specifies data (an integer or a pointer) to accompany the signal... This data can be retrieved via the `si_value` field of the `siginfo_t` structure that is passed to the handler... or returned by a call to `sigwaitinfo()` or `sigtimedwait()`.*
- **`SIGEV_THREAD`**：*...allows an implementation to generate the notifications for a periodic timer either by having **each notification delivered to a new unique thread** or by having the notifications **delivered in series to a single new thread**.*（SUSv3 原文是「as if」，正是为了允许这两种实现）
- **`SIGEV_THREAD_ID`**：*intended for use by **threading libraries***；它要求线程实现使用 `CLONE_THREAD`（现代 NPTL 是，老的 LinuxThreads 不是）

### ⭐ `evp == NULL` 的默认语义

原书逐字：

> The `evp` argument may be specified as `NULL`, which is equivalent to specifying `sigev_notify` as **`SIGEV_SIGNAL`**, `sigev_signo` as **`SIGALRM`** (this may be different on other systems, since SUSv3 merely says "a default signal number"), and `sigev_value.sival_int` as **the timer ID**.

三件事一起记住：

| 字段 | 默认值 |
|------|--------|
| `sigev_notify` | `SIGEV_SIGNAL` |
| `sigev_signo` | `SIGALRM`（**Linux 专有选择**，SUSv3 只说「一个默认信号号」） |
| `sigev_value.sival_int` | **定时器 ID**（注意是 `sival_**int**`，不是 `sival_ptr`！） |

本仓库用官方分发里的 `ptmr_null_evp.c`（**习题 23-3 的官方解答**）来实测这一点 —— 见下文 §23.6.5 之后的「习题 23-3」。

### ⚠️ 定时器数量受「realtime 信号队列上限」约束

原书 §23.6.1 结尾一句容易被忽略但很重要：

> As currently implemented, the kernel **preallocates one queued realtime signal structure for each POSIX timer** that is created using `timer_create()`. The intent of this preallocation is to ensure that at least one such structure is available for queuing a signal when the timer expires. This means that **the number of POSIX timers that may be created is subject to the limitations on the number of realtime signals that can be queued**.

也就是说：**每创建一个 POSIX 定时器，内核就先扣掉一个 realtime 信号的队列名额**（默认上限见 `man 7 signal` 的 `RLIMIT_SIGPENDING` 与内核 `sigqueue` 相关限制）。所以「POSIX 定时器可以无限创建」是**错的** —— 它受 realtime 信号资源限制。这条在 §23.6.6 里还会再出现一次，因为那正是 POSIX.1b 委员会放弃「用 realtime 信号排队来表达多次到期」的原因。

## ⭐ 实测：`timer_t` 到底是什么？

书里只说 `timer_t` 是 *"a data type specified by SUSv3 for representing a timer identifier"* —— 却不说是整数还是指针。本仓库用一个一次性探针（不属于章节交付物）问清楚了：

```text
sizeof(timer_t)=8  sizeof(clockid_t)=4
-- SIGEV_SIGNAL --
  handle[0] = (nil)   (long)=0
  handle[1] = 0x1   (long)=1
  handle[2] = 0x2   (long)=2
-- SIGEV_THREAD --
  handle[0] = 0x8000000005c81238   (long)=-9223372036757777864
  handle[1] = 0x8000000005c81268   (long)=-9223372036757777816
  handle[2] = 0x8000000005c81298   (long)=-9223372036757777768
-- 对照 malloc(64) 两个地址 --
  0xb902590
  0xb9025e0
```

读出来的三件事：

| 观察 | 结论 |
|------|------|
| `sizeof(timer_t) = 8`、`sizeof(clockid_t) = 4` | `timer_t` 是**指针宽度**，`clockid_t` 是 `int` 宽度 |
| `SIGEV_SIGNAL` 路径：`handle[0] = (nil)`、`handle[1] = 0x1`、`handle[2] = 0x2` | **就是内核的小整数定时器 ID**（`(timer_t)(uintptr_t)ktimerid`，从 0 开始） |
| `SIGEV_THREAD` 路径：`handle[0] = 0x8000000005c81238`、`0x8000000005c81268`、`0x8000000005c81298` | 三个句柄**等间距 0x30 = 48 字节**，且形态与 `malloc(64)` 出来的普通堆地址（`0xb902590`）**完全不同** ⇒ 这是 **glibc 自己分配的内部结构地址**，不是内核 ID |

**结论（这几行代码就是本节最实用的一条实践警告）：**

> ⭐ **`timer_t` 是不透明句柄，其数值随通知机制而变。** `SIGEV_SIGNAL` 下它是个小整数，`SIGEV_THREAD` 下它是 glibc 内部结构的地址 —— 所以：
> - **不要**把 `timer_t` 当整数打印/比较/存盘；
> - **不要**假设 `timer_t == 0` 是「失败」（本页实测里 `Timer ID: 0` 是**完全合法**的第一个定时器！）；
> - **不要**假设它能跨进程传递。
>
> 唯一的正确用法：把它当**你自己不能解释的句柄**，原样传给 `timer_settime()` / `timer_gettime()` / `timer_delete()`。

> 📌 glibc 侧的原因：`sysdeps/unix/sysv/linux/timer_create.c` 里，`SIGEV_SIGNAL` 路径直接把内核返回的 `ktimerid` 强转成 `timer_t`；`SIGEV_THREAD` 路径则 `malloc` 一个内部 `struct timer` 记录 `ktimerid` 与通知函数，返回的是**那个结构体的地址**。
>
> 📌 原书示例里 `Timer ID: 134524952` 看起来像个「正常的大数」，那是书写作年代（glibc 较老、堆地址在那个量级）的产物。**换成 `SIGEV_THREAD` 就变成另一个量级了** —— 这正是不能依赖数值形态的原因。

## 完整源码（Listing 23-6）：命令行字符串 → `itimerspec`

```c
/* itimerspec_from_str.c

   Implement our itimerspecFromStr() function.
*/
#ifndef __APPLE__       /* Mac OS X doesn't define the 'itimerspec' structure
                           (or the POSIX timer functions (timer_*()) */
#include <string.h>
#include <stdlib.h>
#include "itimerspec_from_str.h"        /* Declares function defined here */

/* Convert a string of the following form to an itimerspec structure:
   "value.sec[/value.nanosec][:interval.sec[/interval.nanosec]]".
   Optional components that are omitted cause 0 to be assigned to the
   corresponding structure fields. */

void
itimerspecFromStr(char *str, struct itimerspec *tsp)
{
    char *dupstr ,*cptr, *sptr;

    dupstr = strdup(str);

    cptr = strchr(dupstr, ':');
    if (cptr != NULL)
        *cptr = '\0';

    sptr = strchr(dupstr, '/');
    if (sptr != NULL)
        *sptr = '\0';

    tsp->it_value.tv_sec = atoi(dupstr);
    tsp->it_value.tv_nsec = (sptr != NULL) ? atoi(sptr + 1) : 0;

    if (cptr == NULL) {
        tsp->it_interval.tv_sec = 0;
        tsp->it_interval.tv_nsec = 0;
    } else {
        sptr = strchr(cptr + 1, '/');
        if (sptr != NULL)
            *sptr = '\0';
        tsp->it_interval.tv_sec = atoi(cptr + 1);
        tsp->it_interval.tv_nsec = (sptr != NULL) ? atoi(sptr + 1) : 0;
    }
    free(dupstr);
}
#endif
```

字符串语法与解析结果：

| 输入 | `it_value` | `it_interval` |
|------|-----------|---------------|
| `2:5` | 2 s | 5 s |
| `1/0:0/100000000` | 1 s | 100 ms |
| `0/500000000:0/500000000` | 500 ms | 500 ms |
| `10` | 10 s | 0（**单次**） |
| `0` | 0（**已解除武装**） | 0 |

解析逻辑三步：

1. 找 `:` ⇒ 切出「首次值」与「间隔值」两段（没有 `:` 就是单次，间隔全 0）；
2. 在每段里找 `/` ⇒ 切出「秒」与「纳秒」；
3. `atoi()` 各自转换。

> 📌 **与书里印刷版的一处差异（源码核验）**：书上 Listing 23-6 直接对**传入的字符串**动刀（`cptr = strchr(str, ':')` 然后 `*cptr = '\0'`），也就是**会修改调用者的 buffer**（实践中就是 `argv[]`）。man7 当前分发版改成了先 `dupstr = strdup(str)`，在**副本**上切分，最后 `free(dupstr)` —— 不再有副作用。**当前版更好**：不销毁 `argv`，打印用法/日志时还能正常显示原始参数。

> ⚠️ 注意这个文件顶部有 `#ifndef __APPLE__` 包住整个实现 —— 因为 **macOS 没有 `itimerspec` 结构、也没有 `timer_*()` 系列函数**。这是个跨平台可用性的真实提醒（原书是 Linux 书，但 Kerrisk 也照顾到了 macOS）。

## 3. §23.6.2 武装与解除武装：`timer_settime()`

```c
#define _POSIX_C_SOURCE 199309
#include <time.h>

int timer_settime(timer_t timerid, int flags,
                  const struct itimerspec *value,
                  struct itimerspec *old_value);

struct itimerspec {
    struct timespec it_interval;    /* Interval for periodic timer */
    struct timespec it_value;       /* First expiration */
};

struct timespec {
    time_t tv_sec;                  /* Seconds */
    long   tv_nsec;                 /* Nanoseconds */
};
```

| 字段 | 作用 | 置 0 的后果 |
|------|------|------------|
| `it_value` | **第一次**到期时刻（相对或绝对，看 `flags`） | **解除武装**（disarm） |
| `it_interval` | 每次到期后**重装**给 `it_value` 的值 | 只响**一次** |

> ⭐ 和 `struct itimerval` 一样：**`it_interval` 写在前面，`it_value` 在后面** —— 顺序反直觉，用指定初始化器（`.it_value = ...`）就不会记错。

原书原文的几条规则：

> If both subfields of `it_interval` are 0, this timer expires **just once**. If both subfields of `it_value` are 0, the timer is **disarmed**.
>
> If `flags` is specified as `0`, then `value.it_value` is interpreted **relative** to the clock value at the time of the call to `timer_settime()` (i.e., like `setitimer()`). If `flags` is specified as **`TIMER_ABSTIME`**, then `value.it_value` is interpreted as an **absolute time** (i.e., measured from the clock's zero point). **If that time has already passed on the clock, the timer expires immediately.**
>
> To disarm a timer, we make a call to `timer_settime()` specifying **both fields of `value.it_value` as 0**.

还有一条**与 `clock_settime()` 方向相反**的取整规则：

> If the timer value and interval are **not multiples of the resolution of the corresponding clock** (as returned by `clock_getres()`), these values are **rounded up** to the next multiple of the resolution.

（对比 §23.5.2：`clock_settime()` 遇到非整数倍是**向下**取整。方向相反的原因是语义目标相反 —— 详见 [23.5](23.5-posix-clocks.md) 的说明。）

`old_value` 是输出参数，拿「上一次设置的剩余时间与间隔」，不需要就传 `NULL`。它的语义与下面的 `timer_gettime()` 完全一样。

## 4. §23.6.3 / §23.6.4 查询与删除

```c
#define _POSIX_C_SOURCE 199309
#include <time.h>

int timer_gettime(timer_t timerid, struct itimerspec *curr_value);
int timer_delete(timer_t timerid);
```

`timer_gettime()` 的三条读法（原书原文）：

| 观察到的值 | 含义 |
|-----------|------|
| `curr_value.it_value` | **距下一次到期还有多久** —— *even if this timer was established as an absolute timer using `TIMER_ABSTIME`*（**绝对武装的定时器，读出来也是相对剩余！**） |
| `curr_value.it_value` 两个子字段都为 0 | 定时器当前**已解除武装** |
| `curr_value.it_interval` 两个子字段都为 0 | 定时器**只响一次**，时刻就是 `curr_value.it_value` |

`timer_delete()` 的三条要点：

- *Each POSIX timer consumes a small amount of system resources.* ⇒ 用完就删，别泄漏。
- 若删除时定时器还武装着，**先自动解除武装**再删。
- *If there is already a **pending signal** from an expiration of this timer, that signal **remains pending**.*（SUSv3 对此**未规定**，别的 UNIX 可能行为不同）
- 进程终止时定时器自动删除。

## 5. §23.6.5 通过信号通知

两种接收方式：**信号处理器** 或 **`sigwaitinfo()` / `sigtimedwait()`**。两者都能拿到 `siginfo_t`（用处理器时要先装 `SA_SIGINFO`）。`siginfo_t` 里与定时器相关的字段：

| 字段 | 值 | 是否标准 |
|------|----|---------|
| `si_signo` | 这个定时器产生的信号 | ✅ |
| `si_code` | **`SI_TIMER`**（明确告诉你「这个信号来自 POSIX 定时器到期」） | ✅ |
| `si_value` | `timer_create()` 时给的 `evp.sigev_value` | ✅ |
| `si_overrun` | overrun 计数（§23.6.6） | ❌ **Linux 扩展** |
| `si_timerid` | 内核内部用来标识定时器的 ID | ❌ **Linux 扩展**，原书原文：*It is **not useful to applications*** |

> ⭐ 关键技巧（原书原文）：*When calling `timer_create()`, `evp.sigev_value.sival_ptr` is typically assigned **the address of the `timerid` argument given in the same call** (see Listing 23-5). This allows the signal handler (or the `sigwaitinfo()` call) to obtain the **ID of the timer that generated the signal**.*
>
> 为什么要「传地址」而不是「传 ID 本身」？因为**多个定时器可以共用同一个信号**，处理器必须能分辨「这次是哪一个到期了」。用地址就能在处理器里 `*tidptr` 取回 ID，进而调 `timer_getoverrun(*tidptr)`。

```c
   arguments specifies the initial value and interval for a POSIX timer. The
   format of these arguments is defined by the function itimerspecFromStr().

   The program establishes a handler for the timer notification signal, creates
   and arms one timer for each command-line argument, and then pauses. Each
   timer expiration causes the generation of a signal, and, when invoked, the
   signal handler displays information about the timer expiration.

   Kernel support for Linux timers is provided since Linux 2.6. On older
   systems, an incomplete user-space implementation of POSIX timers
   was provided in glibc.
*/
#define _POSIX_C_SOURCE 199309
#include <signal.h>
#include <time.h>
#include "curr_time.h"                  /* Declares currTime() */
#include "itimerspec_from_str.h"        /* Declares itimerspecFromStr() */
#include "tlpi_hdr.h"

#define TIMER_SIG SIGRTMAX              /* Our timer notification signal */

static void
handler(int sig, siginfo_t *si, void *uc)
{
    timer_t *tidptr;

    tidptr = si->si_value.sival_ptr;

    /* UNSAFE: This handler uses non-async-signal-safe functions
       (printf(); see Section 21.1.2) */

    printf("[%s] Got signal %d\n", currTime("%T"), sig);
    printf("    *sival_ptr         = %ld\n", (long) *tidptr);
    printf("    timer_getoverrun() = %d\n", timer_getoverrun(*tidptr));
}

int
main(int argc, char *argv[])
{
    struct itimerspec ts;
    struct sigaction  sa;
    struct sigevent   sev;
    timer_t *tidlist;
    int j;

    if (argc < 2)
        usageErr("%s secs[/nsecs][:int-secs[/int-nsecs]]...\n", argv[0]);

    tidlist = calloc(argc - 1, sizeof(timer_t));
    if (tidlist == NULL)
        errExit("malloc");

    /* Establish handler for notification signal */

    sa.sa_flags = SA_SIGINFO;
    sa.sa_sigaction = handler;
    sigemptyset(&sa.sa_mask);
    if (sigaction(TIMER_SIG, &sa, NULL) == -1)
        errExit("sigaction");

    /* Create and start one timer for each command-line argument */

    sev.sigev_notify = SIGEV_SIGNAL;    /* Notify via signal */
    sev.sigev_signo = TIMER_SIG;        /* Notify using this signal */

    for (j = 0; j < argc - 1; j++) {
        itimerspecFromStr(argv[j + 1], &ts);

        sev.sigev_value.sival_ptr = &tidlist[j];
                /* Allows handler to get ID of this timer */

        if (timer_create(CLOCK_REALTIME, &sev, &tidlist[j]) == -1)
            errExit("timer_create");
        printf("Timer ID: %ld (%s)\n", (long) tidlist[j], argv[j + 1]);

        if (timer_settime(tidlist[j], 0, &ts, NULL) == -1)
            errExit("timer_settime");
    }

    for (;;)                            /* Wait for incoming timer signals */
        pause();
}
```

|------|------|
| `#define TIMER_SIG SIGRTMAX` | 用**最高优先级的 realtime 信号**做通知信号 —— 这样 `sigev_value` 才能随信号携带数据 |

| `for (;;) pause();` | 没有退出路径 —— 靠外部信号杀掉 |

## 6. §23.6.6 定时器 overrun

### 问题是什么

原书原文：

> Suppose that we have chosen to receive notification of timer expiration via delivery of a signal... Suppose further that the timer expires **multiple times before the associated signal is caught or accepted**. This could occur as the result of a **delay before the process is next scheduled**. Alternatively, it could occur because **delivery of the associated signal was blocked**, either explicitly via `sigprocmask()`, or **implicitly during the execution of the handler** for the signal.

### 为什么不能用 realtime 信号排队解决

这是本节最有意思的一段推理，原书逐字：

> We might suppose that using a **realtime signal** would help solve this problem, since multiple instances of a realtime signal are queued. However, this approach turns out to be **unworkable**, because **there are limits on the number of realtime signals that can be queued**. Therefore, the POSIX.1b committee decided on a different approach: if we choose to receive timer notification via a signal, then **multiple instances of the signal are never queued, even if we use a realtime signal**. Instead, after receiving the signal..., we can fetch the **timer overrun count**, which is the number of **extra** timer expirations that occurred between the time the signal was generated and the time it was received.

用「信号排队」表达「到期 N 次」的问题是**资源无界**：一个 1 ms 的定时器挂 10 秒就是 10000 个待排队信号，而 realtime 信号队列有系统级上限（回想 §23.6.1：**每个 POSIX 定时器在创建时就已经预扣一个名额**）。所以 POSIX.1b 选了**计数**方案。

### 定义与两条读法

> For example, if the timer has expired **three** times since the last signal was received, then the overrun count is **2**.

| 方法 | 说明 |
|------|------|
| `timer_getoverrun(timerid)` | **SUSv3 规定**的取法。原书特别指出它在 SUSv3 的 async-signal-safe 函数表里（原书 Table 21-1，page 426）⇒ **可以安全地在信号处理器里调用** |
| `si_overrun`（`siginfo_t` 字段） | **Linux 扩展**，省掉一次系统调用 |

> ⭐ **overrun 计数在每次收到定时器信号时被重置。** 原书原文：*The timer overrun count is **reset each time we receive the timer signal**. If the timer expired just once since the timer signal was handled or accepted, then the overrun count will be **0**.*

书里的示例（`ptmr_sigev_signal 2:5`，`Ctrl-Z` 挂起几秒再 `fg`）：

```
[15:55:34] Got signal 64
    *sival_ptr         = 134524952
    timer_getoverrun() = 5
```

> The last line of program output shows that **five timer overruns** occurred, meaning that **six** timer expirations occurred since the previous signal delivery.

### ⭐ 本仓库的补充实测：确定性地把 overrun 跑出来

原书的示例依赖**手工 `Ctrl-Z`/`fg`**，在无人值守环境里复现不了 —— 本仓库在 CE 上跑的 `ptmr_sigev_signal` 里 **overrun 全是 0**（处理器跑得够快，每次到期都被及时处理）。为了让 §23.6.6 有正例，本仓库写了一个延伸 demo：

[`code/c23_posix_timer_overrun.c`](../code/c23_posix_timer_overrun.c)

```c
/* c23_posix_timer_overrun.c

   ⚠️ 延伸 demo —— **原书没有这个程序**。
      §23.6.6 讲「定时器 overrun」，原书的示例是靠手工 `Ctrl-Z`（SIGSTOP）挂起
      进程几秒再 `fg` 来制造 overrun。这种手法在无人值守环境（CI / CE / 自动化
      回归）里无法复现，所以本节在 CE 上从来观察不到 overrun > 0 的正例。

   本程序用**确定性的手法**制造 overrun —— 不需要任何人工干预：

     1. sigprocmask(SIG_BLOCK, {SIGRTMAX})  把通知信号阻塞住
        ⇒ 定时器到期产生的信号进不了处理器。
     2. timer_create(CLOCK_REALTIME, SIGEV_SIGNAL/SIGRTMAX)
     3. timer_settime(1 ms 后首次，之后每 1 ms)
     4. nanosleep(1 s)
        ⇒ 这一秒里定时器到期约 1000 次，但内核只保留**一个** pending 信号，
          多出来的到期**不会排队**（这正是 POSIX.1b 选择「计数」而不是
          「排队 realtime 信号」的原因，见原书 §23.6.6）。
     5. sigwaitinfo() 取那唯一一个信号，读 si_overrun / timer_getoverrun()

   预期：overrun ≈ 999（到期 ~1000 次，其中 1 次「兑现」成那个信号，其余算法 overrun）。

   编译：gcc -O0 -Wall -Wextra -o c23_overrun c23_posix_timer_overrun.c
   ⚠️ 只依赖 libc，不需要 tlpi_hdr.h / get_num.c。
*/
#define _POSIX_C_SOURCE 199309
#include <signal.h>
#include <stdio.h>
#include <stdlib.h>
#include <time.h>
#include <unistd.h>

#define TIMER_SIG SIGRTMAX
#define NSEC_PER_MS 1000000L

int
main(void)
{
    timer_t tid;
    struct sigevent sev;
    struct itimerspec ts;
    struct timespec req, t0, t1;
    sigset_t blockSet;
    siginfo_t si;
    int got;

    /* ---- 时间基准用 CLOCK_MONOTONIC，避免 NTP 干扰（§23.5） ---- */

    if (clock_gettime(CLOCK_MONOTONIC, &t0) == -1) {
        perror("clock_gettime");
        exit(EXIT_FAILURE);
    }

    printf("=== POSIX 定时器 overrun 实测 ===\n");
    printf("通知信号 SIGRTMAX = %d\n", TIMER_SIG);

    /* ---- 第 1 步：先把通知信号阻塞住 ---- */

    sigemptyset(&blockSet);
    sigaddset(&blockSet, TIMER_SIG);
    if (sigprocmask(SIG_BLOCK, &blockSet, NULL) == -1) {
        perror("sigprocmask");
        exit(EXIT_FAILURE);
    }
    printf("已 sigprocmask(SIG_BLOCK) 阻塞信号 %d —— 它进不了处理器，只能被排队\n",
           TIMER_SIG);

    /* ---- 第 2 步：创建定时器，通知方式 = 信号 ---- */

    sev.sigev_notify = SIGEV_SIGNAL;
    sev.sigev_signo = TIMER_SIG;
    sev.sigev_value.sival_ptr = &tid;

    if (timer_create(CLOCK_REALTIME, &sev, &tid) == -1) {
        perror("timer_create");
        exit(EXIT_FAILURE);
    }
    printf("timer ID = %ld\n", (long) tid);

    /* ---- 第 3 步：武装 —— 1 ms 后首次，之后每 1 ms ---- */

    ts.it_value.tv_sec = 0;
    ts.it_value.tv_nsec = NSEC_PER_MS;
    ts.it_interval.tv_sec = 0;
    ts.it_interval.tv_nsec = NSEC_PER_MS;

    if (timer_settime(tid, 0, &ts, NULL) == -1) {
        perror("timer_settime");
        exit(EXIT_FAILURE);
    }

    /* ---- 第 4 步：睡 1 秒，让到期次数远远超过「能送达的信号个数」 ---- */

    req.tv_sec = 1;
    req.tv_nsec = 0;
    if (nanosleep(&req, NULL) == -1) {
        perror("nanosleep");
        exit(EXIT_FAILURE);
    }

    if (clock_gettime(CLOCK_MONOTONIC, &t1) == -1) {
        perror("clock_gettime");
        exit(EXIT_FAILURE);
    }
    printf("睡了 %.6f 秒（墙钟 MONOTONIC 口径）—— 期间定时器到期约 1000 次\n",
           (double) (t1.tv_sec - t0.tv_sec)
               + (double) (t1.tv_nsec - t0.tv_nsec) / 1000000000.0);

    /* ---- 第 5 步：取那唯一一个信号，读 overrun ---- */

    got = sigwaitinfo(&blockSet, &si);
    if (got == -1) {
        perror("sigwaitinfo");
        exit(EXIT_FAILURE);
    }
    printf("sigwaitinfo() 取到信号 %d\n", got);

#ifdef __linux__
    printf("    si_overrun         = %d      (Linux 扩展字段，省一次系统调用)\n",
           si.si_overrun);
#endif
    printf("    timer_getoverrun() = %d      (SUSv3 规定的取法)\n",
           timer_getoverrun(tid));

    /* ---- 收尾：先解除武装，再看 overrun 是不是被「收到信号」这个动作重置了 ---- */

    ts.it_value.tv_sec = 0;
    ts.it_value.tv_nsec = 0;
    ts.it_interval.tv_sec = 0;
    ts.it_interval.tv_nsec = 0;
    if (timer_settime(tid, 0, &ts, NULL) == -1) {   /* it_value 全 0 = 解除武装 */
        perror("timer_settime");
        exit(EXIT_FAILURE);
    }

    printf("解除武装后再读一次 timer_getoverrun() = %d\n", timer_getoverrun(tid));
    printf("读法：到期 N 次但只送出 1 个信号时，overrun = N - 1；\n");
    printf("      收到信号后 overrun 会被重置，所以第二次读到的是 0。\n");

    if (timer_delete(tid) == -1) {
        perror("timer_delete");
        exit(EXIT_FAILURE);
    }
    return 0;
}
```

```text

timer ID = 0
睡了 1.000128 秒（墙钟 MONOTONIC 口径）—— 期间定时器到期约 1000 次
```

| 行 | 含义 |
|----|------|
| `已 sigprocmask(SIG_BLOCK) 阻塞信号 64` | 通知信号进不了处理器（也没有处理器）—— 这正是原书说的 *delivery ... was blocked, explicitly via `sigprocmask()`* |
| `睡了 1.000128 秒` | 用 `CLOCK_MONOTONIC` 量的真实睡眠时长 |
| `si_overrun = 999` | **Linux 扩展字段**：1 秒 ÷ 1 ms = 约 1000 次到期，1 次「兑现」成那个 pending 信号，其余 **999 次**都是 overrun |
| `timer_getoverrun() = 999` | **SUSv3 规定的取法**，读出同一个数 ⇒ 两个来源一致 |
| `解除武装后再读一次 timer_getoverrun() = 0` | ⭐ **收到信号后计数被重置**（原书原文的行为），所以第二次读到 0 |

**这就是 overrun 的确切含义在数字上的体现**：`overrun = 到期次数 − 1`。如果代码忽略 overrun，它会以为「只到期了一次」，于是把一个 1 ms 的周期任务当成「1 秒一次」来处理 —— 这类 bug 在「信号被阻塞」或「处理器很慢」时才会浮现，非常难查。

> ⭐ 顺带一个对照：§23.7 的 `timerfd` 用的是**完全不同的机制** —— `read()` 直接返回「到期次数」本身（`uint64_t`），不需要 overrun 字段，也不会因为「只送一个信号」而丢信息。那个方案更干净（见 [23.7](23.7-timers-that-notify-via-file-descriptors-.md) 实测 `expirations read: 47`）。

```c
/* ptmr_sigev_thread.c

   This program demonstrates the use of threads as the notification mechanism
   for expirations of a POSIX timer. Each of the program's command-line
   arguments specifies the initial value and interval for a POSIX timer. The
   format of these arguments is defined by the function itimerspecFromStr().

   The program creates and arms one timer for each command-line argument.
   The timer notification method is specified as SIGEV_THREAD, causing the
   timer notifications to be delivered via a thread that invokes threadFunc()
   as its start function. The threadFunc() function displays information
   about the timer expiration, increments a global counter of timer expirations,
   and signals a condition variable to indicate that the counter has changed.
   In the main thread, a loop waits on the condition variable, and each time
   the condition variable is signaled, the main thread prints the value of the
   global variable that counts timer expirations.

   Kernel support for Linux timers is provided since Linux 2.6. On older
   systems, an incomplete user-space implementation of POSIX timers
   was provided in glibc.
*/
#include <signal.h>
#include <time.h>
#include <pthread.h>
#include "curr_time.h"              /* Declares currTime() */
#include "tlpi_hdr.h"
#include "itimerspec_from_str.h"    /* Declares itimerspecFromStr() */

static pthread_mutex_t mtx = PTHREAD_MUTEX_INITIALIZER;
static pthread_cond_t cond = PTHREAD_COND_INITIALIZER;

static int expireCnt = 0;           /* Number of expirations of all timers */

static void                         /* Thread notification function */
threadFunc(union sigval sv)
{
    timer_t *tidptr;
    int s;

    tidptr = sv.sival_ptr;

    printf("[%s] Thread notify\n", currTime("%T"));
    printf("    timer ID=%ld\n", (long) *tidptr);
    printf("    timer_getoverrun()=%d\n", timer_getoverrun(*tidptr));

    /* Increment counter variable shared with main thread and signal
       condition variable to notify main thread of the change. */

    s = pthread_mutex_lock(&mtx);
    if (s != 0)
        errExitEN(s, "pthread_mutex_lock");

    expireCnt += 1 + timer_getoverrun(*tidptr);

    s = pthread_mutex_unlock(&mtx);
    if (s != 0)
        errExitEN(s, "pthread_mutex_unlock");

    s = pthread_cond_signal(&cond);
    if (s != 0)
        errExitEN(s, "pthread_cond_signal");
}

int
main(int argc, char *argv[])
{
    struct sigevent sev;
    struct itimerspec ts;
    timer_t *tidlist;
    int s, j;

    if (argc < 2)
        usageErr("%s secs[/nsecs][:int-secs[/int-nsecs]]...\n", argv[0]);

    tidlist = calloc(argc - 1, sizeof(timer_t));
    if (tidlist == NULL)
        errExit("malloc");

    sev.sigev_notify = SIGEV_THREAD;            /* Notify via thread */
    sev.sigev_notify_function = threadFunc;     /* Thread start function */
    sev.sigev_notify_attributes = NULL;
            /* Could be pointer to pthread_attr_t structure */

    /* Create and start one timer for each command-line argument */

    for (j = 0; j < argc - 1; j++) {
        itimerspecFromStr(argv[j + 1], &ts);

        sev.sigev_value.sival_ptr = &tidlist[j];
                /* Passed as argument to threadFunc() */

        if (timer_create(CLOCK_REALTIME, &sev, &tidlist[j]) == -1)
            errExit("timer_create");
        printf("Timer ID: %ld (%s)\n", (long) tidlist[j], argv[j + 1]);

        if (timer_settime(tidlist[j], 0, &ts, NULL) == -1)
            errExit("timer_settime");
    }

    /* The main thread waits on a condition variable that is signaled
       on each invocation of the thread notification function. We
       print a message so that the user can see that this occurred. */

    s = pthread_mutex_lock(&mtx);
    if (s != 0)
        errExitEN(s, "pthread_mutex_lock");

    for (;;) {
        s = pthread_cond_wait(&cond, &mtx);
        if (s != 0)
            errExitEN(s, "pthread_cond_wait");
        printf("main(): expireCnt = %d\n", expireCnt);
    }
}
```

编译（`code/` 目录下，**注意要加 `-pthread`**）：

```bash

    ptmr_sigev_thread.c itimerspec_from_str.c curr_time.c get_num.c
```

程序结构（比 Listing 23-5 多了线程与条件变量）：

| 片段 | 作用 |
|------|------|
| `sev.sigev_notify = SIGEV_THREAD;`<br>`sev.sigev_notify_function = threadFunc;`<br>`sev.sigev_notify_attributes = NULL;` | 通知方式从「发信号」换成「起线程调函数」 |
| `sev.sigev_value.sival_ptr = &tidlist[j];` | 同一个地址技巧 —— 但这次它是**传给 `threadFunc()` 的唯一参数**（`union sigval`），不是通过 `siginfo_t` |
| `static int expireCnt` + `mtx`/`cond` | 全局到期计数，由 `threadFunc()` 加、由主线程打印 |
| `expireCnt += 1 + timer_getoverrun(*tidptr);` | ⭐ 原书原文：*To allow for the possibility of timer overruns, the value returned by `timer_getoverrun()` is also added to `expireCnt`* —— **SIGEV_THREAD 下同样会 overrun**，所以这里必须加上 |
| 主线程 `pthread_cond_wait(&cond, &mtx)` | 等通知函数 `signal` 条件变量后打印计数 |

> ⚠️ **`SIGEV_THREAD` 的性能代价**：SUSv3 说通知函数「as if」是新线程的启动函数，允许两种实现（每次一个新线程 / 串行送到同一个新线程）。glibc 的实现会**为每个定时器建一个辅助线程**。所以高频定时器**不要**用 `SIGEV_THREAD` —— 线程创建/调度开销远超信号。要高频就用 `SIGEV_SIGNAL`（并且处理 overrun）或 `timerfd`。

## 8. 习题 23-3 的官方解答：`evp == NULL` 等价于什么

原书习题 23-3：

> Write a program to show that if the `evp` argument to `timer_create()` is specified as `NULL`, then this is equivalent to specifying `evp` as a pointer to a `sigevent` structure with `sigev_notify` set to `SIGEV_SIGNAL`, `sigev_signo` set to `SIGALRM`, and `si_value.sival_int` set to the timer ID.

**实现**：`code/ptmr_null_evp.c`，逐行取自 man7 官方 `timers/ptmr_null_evp.c`（**习题 23-3 的官方解答**，正文未印成 Listing）。

```c
/* ptmr_null_evp.c

   A program to demonstrate POSIX timer defaults when the 'evp' argument
   of timer_create() is specified as NULL.

   Kernel support for Linux timers is provided since Linux 2.6. On older
   systems, an incomplete user-space implementation of POSIX timers
   was provided in glibc.
*/
#define _POSIX_C_SOURCE 199309
#include <signal.h>
#include <time.h>
#include "curr_time.h"          /* Declaration of currTime() */
#include "tlpi_hdr.h"

static void
handler(int sig, siginfo_t *si, void *uc)
{
    printf("[%s] Got signal %d\n", currTime("%T"), sig);
    printf("    sival_int          = %d\n", si->si_value.sival_int);
#ifdef __linux__
    printf("    si_overrun         = %d\n", si->si_overrun);
#endif
    printf("    timer_getoverrun() = %d\n",
            timer_getoverrun((timer_t) si->si_value.sival_ptr));
}

int
main(int argc, char *argv[])
{
    if (argc < 2)
        usageErr("%s secs [nsecs [int-secs [int-nsecs]]]\n", argv[0]);

    struct sigaction sa;
    sa.sa_flags = SA_SIGINFO;
    sa.sa_sigaction = handler;
    sigemptyset(&sa.sa_mask);
    if (sigaction(SIGALRM, &sa, NULL) == -1)
        errExit("sigaction");

    timer_t tid;
    if (timer_create(CLOCK_REALTIME, NULL, &tid) == -1)
        errExit("timer_create");
    printf("timer ID = %ld\n", (long) tid);

    struct itimerspec ts;
    ts.it_value.tv_sec = atoi(argv[1]);
    ts.it_value.tv_nsec = (argc > 2) ? atoi(argv[2]) : 0;
    ts.it_interval.tv_sec = (argc > 3) ? atoi(argv[3]) : 0;
    ts.it_interval.tv_nsec = (argc > 4) ? atoi(argv[4]) : 0;
    if (timer_settime(tid, 0, &ts, NULL) == -1)
        errExit("timer_settime");

    for (int j = 0; ; j++)
        pause();
}
```

编译（`code/` 目录下）：

```bash
gcc -O0 -Wall -Wextra -o ptmr_null_evp ptmr_null_evp.c curr_time.c get_num.c
```

程序的证明思路很直接：**既然默认信号是 `SIGALRM`，那就给 `SIGALRM` 装处理器（而不是像 Listing 23-5 那样装 `SIGRTMAX`）；既然默认 `sival_int` 是定时器 ID，那就把 `si_value.sival_int` 打印出来** —— 如果两者都符合，等价性就验证了。

### CE 实测：`1 0 0 50000000`（1 秒后首次，之后每 50 ms）

```text
timer ID = 0
[04:31:50] Got signal 14
    sival_int          = 0
    si_overrun         = 0
    timer_getoverrun() = 0
[04:31:50] Got signal 14
    sival_int          = 0
    si_overrun         = 0
    timer_getoverrun() = 0
```

三个字段全部对上：

| 输出 | 断言 | 结论 |
|------|------|------|
| `timer ID = 0` | `si_value.sival_int` 应该等于定时器 ID | `sival_int = 0` ✅ |
| `[04:31:50] Got signal 14` | `sigev_signo` 应该是 `SIGALRM` | 信号 **14 = `SIGALRM`** ✅ |
| 处理器能被调到 | `sigev_notify` 应该是 `SIGEV_SIGNAL` | 确实通过信号送达 ✅ |

> ⚠️ 这个程序里有个**刻意的细节**值得注意：打印 `si_overrun` 那一行被 `#ifdef __linux__` 包着（原书写法），因为 `si_overrun` 是 Linux 扩展字段。而 `timer_getoverrun((timer_t) si->si_value.sival_ptr)` 那一行直接**把 `sival_int` 强转成 `timer_t`** —— 因为默认语义下这个字段里装的就是定时器 ID。**这是全章唯一一处「把整数当 `timer_t` 用」的合法场合**，前提正是「已经证明了这个字段是 ID」。其余场合一律当不透明句柄（见前面的 `timer_t` 实测）。

## 常见坑

| # | 坑 | 正解 |
|---|----|------|
| 1 | 把 `timer_t` 当整数比较/打印/存盘 | 它是**不透明句柄**：`SIGEV_SIGNAL` 下是小整数，`SIGEV_THREAD` 下是 glibc 内部结构地址（本页实测） |
| 2 | 以为 `timer_t == 0` 表示「创建失败」 | `Timer ID: 0` 是**完全正常**的第一个定时器。失败要看 `timer_create()` 返回 `-1` |
| 3 | 以为 POSIX 定时器可以「无限创建」 | 内核**每创建一个就预分配一个 realtime 信号结构** ⇒ 数量受 realtime 信号队列上限约束（§23.6.1 原书原文） |
| 4 | `timer_gettime()` 的 `it_value` 当「绝对时刻」用 | 它返回的是**距下次到期的剩余**，即使当初用 `TIMER_ABSTIME` 武装的也一样 |
| 5 | `it_value` 置 0 但保留 `it_interval` 以为还在跑 | `it_value` 全 0 = **解除武装**，`it_interval` 写什么都没意义 |
| 6 | 忘了 `SA_SIGINFO` | 处理器拿不到 `siginfo_t`，无法分辨是哪个定时器/读 `si_value` |
| 7 | 多个定时器共用一个信号，却用 `sival_int` 传 ID | 用 `sival_ptr = &tidlist[j]` 传**地址**（原书 Listing 23-5 的做法）；`sival_int` 只有「`evp=NULL` 默认语义」下才装 ID |
| 8 | 以为 realtime 信号能「排队表达多次到期」 | POSIX.1b **明确不做**：*multiple instances of the signal are **never queued**, even if we use a realtime signal* ⇒ 必须读 overrun |
| 9 | 忽略 overrun ⇒ 把「1000 次到期」当成「1 次」 | 收到信号后**立即**调 `timer_getoverrun()`（被重置前）；`SIGEV_THREAD` 下也要加 `1 + timer_getoverrun()` |
| 10 | 在信号处理器里调 `printf()` | 不是 async-signal-safe。**`timer_getoverrun()` 是**（SUSv3 表），但 `printf` 不是 ⇒ 要么用 `write()`，要么改用 `sigwaitinfo()`（§23.9 习题 23-4） |
| 11 | 高频定时器用 `SIGEV_THREAD` | glibc 会给每个定时器建辅助线程 ⇒ 开销远超信号。高频用 `SIGEV_SIGNAL` 或 `timerfd` |
| 12 | 用 `atoi()` 解析参数却不校验 | `--help` 会被 `atoi` 当 0 —— 本页实测 `ptmr_*` 就因此把 `--help` 当成「0 时长的定时器」然后无限等待 |
| 13 | 假设 `timer_create()` 能接受任意 `clockid` | `SIGEV_THREAD` **不能**配 `CLOCK_PROCESS_CPUTIME_ID` 之类的 CPU 时钟；且用 `clock_getcpuclockid()` 得到的 ID 要保证目标进程还活着 |
| 14 | 靠 `fork()` 后子进程里的定时器 | POSIX 定时器**不继承**；子进程一个都没有 |
| 15 | 靠 `exec()` 后定时器还在 | POSIX 定时器在 `exec` 时**被解除武装并删除**（对比：`setitimer` 的会保留） |
| 16 | 忘了 `-pthread` 编 `SIGEV_THREAD` 程序 | 链接可能过但运行时崩；显式加 `-pthread` |
| 17 | 把 `timer_settime` 的取整方向记成向下 | **向上**取整到 `clock_getres()` 的整数倍（与 `clock_settime()` 相反） |

## HFT / 嵌入式关联

| 路线 | 结论怎么用 |
|------|-----------|
| **HFT** | ① **生产环境里的高频定时器一律不用 `SIGEV_SIGNAL`/`SIGEV_THREAD`，用 `timerfd`**（§23.7）—— 信号会把逻辑推进异步上下文（不能 `printf`、不能加锁），线程通知有创建开销，而 `timerfd` 能把定时变成 fd 事件、回到主循环里同步处理。② 如果确实要用 `SIGEV_SIGNAL`（比如兼容老代码），**必须处理 overrun**：100 µs 的定时器在 GC/页错误/scheduling 延迟下随时会 overrun，忽略它等于把「时间到了几次」记错。③ **别用 `SIGEV_THREAD` 做周期任务** —— glibc 每定时器一个辅助线程，线程调度抖动远大于定时器本身的抖动。④ 定时器的 `clockid` 选 `CLOCK_MONOTONIC`（`timer_create(CLOCK_MONOTONIC, ...)`），避免 NTP 阶跃导致整条周期线错位。⑤ 「定时器数量不能无限」是一条真实的容量约束 —— 设计「每个连接一个定时器」的架构时，要按 realtime 信号/`RLIMIT_SIGPENDING` 的上限做容量规划。 |
| **嵌入式** | ① `SIGEV_THREAD` 在资源紧张的板子上**优先排除**（每定时器一个线程 = 每定时器一个栈）。② 若 libc 不支持 `SIGEV_THREAD`（部分精简 libc 只实现 `SIGEV_SIGNAL`），代码要能退化 —— 这也是「用 `timerfd` 之外还要留信号路径」的原因之一。③ 定时器不跨 `fork`/`exec` 是一个**安全特性**：`exec` 后旧定时器被清除，避免了「重启后旧的看门狗定时器还在打主人」这类问题。④ 用 `CLOCK_PROCESS_CPUTIME_ID` 建定时器可以做「CPU 用量配额」的超时（进程烧满 N 秒就杀），这在嵌入式里比墙钟超时更贴合实际负载。 |

<summary>代码自测（Q&A）</summary>

**Q1：为什么 `evp->sigev_value.sival_ptr` 要传「定时器 ID 变量的地址」而不是 ID 本身？**

A：因为**多个定时器可能共用同一个信号**。处理器只能用「`siginfo_t` 里携带的数据」来分辨这次是谁到期了。如果在 `timer_create()` 时把 `tidlist[j]` 的**地址**放进去，处理器就能 `tidptr = si->si_value.sival_ptr;` 然后 `*tidptr` 取回 ID，再拿它去调 `timer_getoverrun(*tidptr)` —— 这是原书 Listing 23-5 的标准做法。（`sival_int` 装 ID 只在 `evp == NULL` 的默认语义下成立，见习题 23-3。）

**Q2：`overrun` 为什么不用 realtime 信号排队来表达？**

A：因为**资源不可控**。原书原文说得很直接：*multiple instances of a realtime signal are queued. However, this approach turns out to be unworkable, because there are **limits on the number of realtime signals that can be queued***。而且 §23.6.1 已经说明：**每创建一个 POSIX 定时器，内核就预分配一个 realtime 信号结构** —— 队列资源本来就紧张。1 ms 的定时器挂 10 秒 = 10000 次到期，任何固定队列都撑不住。所以 POSIX.1b 改成「只送一个信号 + 计数」。

**Q3：`overrun = 999`，真实到期多少次？**

A：**1000 次**。定义就是「信号产生到被接收之间**多出来**的到期次数」，所以 `到期次数 = overrun + 1`。本页 `c23_overrun` 的实测：睡了 1.000128 秒、周期 1 ms ⇒ 约 1000 次到期，`overrun = 999` ⇒ 1000 次。**书里的例子 `timer_getoverrun() = 5` ⇒ 6 次到期**，也是同一个换算。

**Q4：`overrun` 什么时候被清零？**

A：**每次收到定时器信号时**（原书原文：*The timer overrun count is **reset each time we receive the timer signal***）。所以必须在**收到信号之后立刻**读它 —— 本页 `c23_overrun` 实测就展示了这一点：`sigwaitinfo()` 之后的第一次读是 `999`，解除武装后再读一次就是 `0`。

**Q5：`SIGEV_THREAD` 和 `SIGEV_SIGNAL` 应该怎么选？**

A：看是否需要「同步上下文」。
- `SIGEV_SIGNAL`：开销小，但业务逻辑跑在**信号处理器**里 ⇒ 只能用 async-signal-safe 函数；或者先把信号 `SIG_BLOCK` 住再 `sigwaitinfo()` 同步取（§23.9 习题 23-4 的做法）。
- `SIGEV_THREAD`：业务逻辑跑在**普通线程**里 ⇒ 可以用任何函数，但 glibc 会为每个定时器建一个辅助线程，开销大（原书原文还提示：*there are limits on the number of threads*）。
- **两者的共同缺陷**：都不是 fd，没法跟 socket/管道一起进 `epoll`。**高频 + 多路复用场景直接上 `timerfd`**（§23.7）。

**Q6：`timer_create()` 返回 0 就是失败吗？**

A：不是。**返回 0 表示成功**（和 `timer_*` 系列的风格一致：成功返 0、失败返 `-1` 并设 `errno`）。而 `timerid` 输出参数里那个**句柄的值**是另一回事 —— 本页实测里第一个定时器的句柄**就是 `0`**（`SIGEV_SIGNAL` 路径下它是内核的小整数 ID），打印出来是 `Timer ID: 0`。**句柄的值没有任何约定含义**，不要用它判断成功失败。

**Q7：为什么 `timer_settime()` 的时间要「向上」取整，而 `clock_settime()` 是「向下」？**

A：语义目标相反。「设置**时钟**」是「尽量接近你要的值」⇒ 向下取整不会凭空多给时间；「武装**定时器**」是「**至少**等这么久」⇒ 必须向上取整，否则可能提前触发，违反「至少」的承诺。详见 [23.5](23.5-posix-clocks.md) 的对照表。

**Q8：本页为什么没给出 `overrun > 0` 的 `ptmr_sigev_signal` 实测？**

A：因为原书制造 overrun 的手法是**手工按 `Ctrl-Z`（SIGSTOP）挂起几秒再 `fg`**，这在无人值守环境（CI / CE）里没法自动做。本仓库在 CE 上跑的 `ptmr_sigev_signal`（100 ms 间隔、处理器只做三次 `printf`）处理器跑得够快，**每次到期都被及时处理，overrun 全是 0**。所以本节改用**主动阻塞信号**的手法写了 `c23_posix_timer_overrun.c`，拿到了 `overrun = 999` 的正例 —— 这样 §23.6.6 的核心结论就有了可复现的实测支撑。
