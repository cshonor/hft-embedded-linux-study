## 本节讲什么

前三节的定时器都建立在**一个隐含的时钟**上（`ITIMER_REAL` 用墙钟、`nanosleep` 用相对时间）。从本节开始，**时钟本身变成一个可选的参数**。

本节钉四件事：

1. **POSIX 时钟 API 只有三个系统调用**：`clock_gettime()` / `clock_getres()` / `clock_settime()`（外加 §23.5.3 的两个「取 CPU 时钟 ID」的函数）。
2. **`clockid` 决定语义**：能不能被设置、算的是墙钟还是 CPU 时间、会不会被 NTP 调整 —— 一张表全部说清。
3. **`clock_getres()` 是判断 HRT 的唯一手段**（§23.2 的结论在这里落地）。
4. ⭐ **`clock_nanosleep()` + `TIMER_ABSTIME` 是「睡眠永不漂移」的正解** —— 它一举解决了 §23.4 里 `remain` 续睡的两个问题（向上取整累积 + `remain` 语义）。

## 1. 三个系统调用

```c
#define _POSIX_C_SOURCE 199309
#include <time.h>

int clock_gettime(clockid_t clockid, struct timespec *tp);
int clock_getres(clockid_t clockid, struct timespec *res);
int clock_settime(clockid_t clockid, const struct timespec *tp);
```

| 调用 | 干什么 | 关键点 |
|------|--------|--------|
| `clock_gettime()` | 读当前时刻 | `timespec` 是纳秒精度，但**返回值粒度可能更粗**（取决于 clock 与 HRT） |
| `clock_getres()` | 读**分辨率** | 返回值是「下界」不是承诺；**判断 HRT 就看它**（§23.2） |
| `clock_settime()` | 设置时刻 | **只有 `CLOCK_REALTIME` 可设**；需要 `CAP_SYS_TIME` |

> ⚠️ 原书说「On Linux, programs using this API must be compiled with the **`-lrt`** option」—— 这是书写作年代的事。**现代 glibc（≥ 2.17）已把 librt 合并进 libc**，`gcc foo.c` 就能链接，不用 `-lrt`。本仓库的实测就是直接 `gcc -O0 -Wall -Wextra`，没有任何 `-lrt`。

### 两个方向相反的取整规则（很反直觉，务必记住）

| 场景 | 取整方向 | 出处 |
|------|---------|------|
| `clock_settime()` 传入的时刻**不是**时钟分辨率的整数倍 | **向 下**（round **downward**） | 原书 §23.5.2 逐字 |
| `timer_settime()` / `setitimer()` 的定时值**不是**分辨率的整数倍 | **向 上**（rounded **up**） | 原书 §23.6.2 逐字 |

为什么方向相反？因为语义目标不同：**设时间**是「尽可能接近你要的值」，**设定时器**是「至少等这么久」。这条对比在本章里出现两次，值得单独记一笔。

## 2. Table 23-1：POSIX 时钟类型

原书 Table 23-1（SUSv3 规定的四种）：

| Clock ID | 描述 |
|----------|------|
| `CLOCK_REALTIME` | **可设置**的系统级实时（墙钟）时钟 |
| `CLOCK_MONOTONIC` | **不可设置**的单调时钟 |
| `CLOCK_PROCESS_CPUTIME_ID` | 进程级 CPU 时间时钟（Linux 2.6.12 起） |
| `CLOCK_THREAD_CPUTIME_ID` | 线程级 CPU 时间时钟（Linux 2.6.12 起） |

原书的两句关键说明：

> `CLOCK_REALTIME` ... measures **wall-clock** time. By contrast with the `CLOCK_MONOTONIC` clock, the setting of this clock **can be changed**.
>
> SUSv3 specifies that the `CLOCK_MONOTONIC` clock measures time since some **"unspecified point in the past"** that doesn't change after system startup. This clock is useful for applications that must **not be affected by discontinuous changes to the system clock** (e.g., a manual change to the system time). On Linux, this clock measures the time since system startup.

> All of the clocks in Table 23-1 are specified in SUSv3, but **only `CLOCK_REALTIME` is mandatory** and widely supported on UNIX implementations.

### Linux 往 Table 23-1 上加的时钟

| 时钟 | 内核版本 | 特点 |
|------|---------|------|
| `CLOCK_MONOTONIC_RAW` | 2.6.28 | 类 `CLOCK_MONOTONIC`，但是**纯硬件时间**，不受 NTP 调整影响。专供时钟同步类应用 |
| `CLOCK_REALTIME_COARSE` | 2.6.32 | `CLOCK_REALTIME` 的低分辨率版：**不去访问硬件时钟**（某些硬件时钟源访问代价高），返回值分辨率就是 **jiffy** |
| `CLOCK_MONOTONIC_COARSE` | 2.6.32 | 同上，对应 `CLOCK_MONOTONIC` |
| `CLOCK_BOOTTIME` | 2.6.39 | `CLOCK_MONOTONIC` **+ 系统挂起（suspend）时间**；用来做「自开机以来真实过了多久」 |
| `CLOCK_TAI` | 3.10 | 国际原子时。**没有闰秒跳变**（`CLOCK_REALTIME` 会在闰秒时刻跳一下/停一秒） |

> 📌 **源码核验**：`CLOCK_BOOTTIME` 与 `CLOCK_TAI` **在 §23.5 正文与 Table 23-1 里都没有出现** —— 我用 `grep` 在章节原文里逐字确认过。它们出现在本节要讲的 `clock_times.c` 里，而这个程序是官方分发中**未印刷**的那一批，文件头自己写着 *A useful small program for time namespaces* —— 说明它是书出版之后为 **time namespaces** 补的。这正是本仓库拿它来「补白」的原因。
>
> 另外书里把 `CLOCK_MONOTONIC_COARSE` 印成了 `CLOCK_MONOTONIC_COARSE` → 「`CLOCK_MONOTIC_COARSE`」（少一个 `N`）。**这是原书的排版错字**，代码里正确的名字是 `CLOCK_MONOTONIC_COARSE`。

## 3. 取「某个进程/线程」的 CPU 时钟 ID

```c
#define _XOPEN_SOURCE 600
#include <time.h>
int clock_getcpuclockid(pid_t pid, clockid_t *clockid);
       /* 成功返 0，失败返**正数**错误码 */

#define _XOPEN_SOURCE 600
#include <pthread.h>
#include <time.h>
int pthread_getcpuclockid(pthread_t thread, clockid_t *clockid);
```

- `clock_getcpuclockid(0, &cid)` ⇒ 拿到**自己**的 CPU 时间时钟 ID。拿到之后可以 `clock_gettime(cid, &ts)` 读出本进程已消耗的 CPU 时间 —— 这就是 `time(1)` / `/proc/<pid>/stat` 那类工具的基础。
- 注意两者的错误返回风格：**返回正数错误码**（像 `pthread_*`），不是 `-1` + `errno`。
- 原书附了一句适用性说明：*According to SUSv3, an implementation may allow the `CLOCK_PROCESS_CPUTIME_ID` and `CLOCK_THREAD_CPUTIME_ID` clocks to be settable. At the time of writing, these clocks are **read-only on Linux**.*

```c
/*************************************************************************\

/* clock_times.c

   Display the values of the CLOCK_REALTIME, CLOCK_MONOTONIC, and
   CLOCK_BOOTTIME clocks. A useful small program for time namespaces.
*/
#define _XOPEN_SOURCE 600
#include <time.h>
#include <stdio.h>
#include <stdlib.h>
#include <stdbool.h>
#include <unistd.h>

#define SECS_IN_DAY (24 * 60 * 60)

static void
displayClock(clockid_t clock, char *name, bool showRes)
{
    struct timespec ts;

    if (clock_gettime(clock, &ts) == -1) {
        perror("clock_gettime");
        exit(EXIT_FAILURE);
    }

    printf("%-15s: %10ld.%03ld (", name,
            (long) ts.tv_sec, ts.tv_nsec / 1000000);

    long days = ts.tv_sec / SECS_IN_DAY;
    if (days > 0)
        printf("%ld days + ", days);

    printf("%2ldh %2ldm %2lds", (ts.tv_sec % SECS_IN_DAY) / 3600,
            (ts.tv_sec % 3600) / 60, ts.tv_sec % 60);
    printf(")\n");

    if (clock_getres(clock, &ts) == -1) {
        perror("clock_getres");
        exit(EXIT_FAILURE);
    }

    if (showRes)
        printf("     resolution: %10ld.%09ld\n",
                (long) ts.tv_sec, ts.tv_nsec);
}

int
main(int argc, char *argv[])
{
    bool showRes = argc > 1;

    displayClock(CLOCK_REALTIME, "CLOCK_REALTIME", showRes);
#ifdef CLOCK_TAI
    displayClock(CLOCK_TAI, "CLOCK_TAI", showRes);
#endif
    displayClock(CLOCK_MONOTONIC, "CLOCK_MONOTONIC", showRes);
#ifdef CLOCK_BOOTTIME
    displayClock(CLOCK_BOOTTIME, "CLOCK_BOOTTIME", showRes);
#endif
    exit(EXIT_SUCCESS);
}
```

编译（`code/` 目录下）：

```bash
gcc -O0 -Wall -Wextra -o clock_times clock_times.c
```

> 它**只依赖 libc**，不需要 `tlpi_hdr.h` / `get_num.c` —— 这也是它适合当「环境体检工具」的原因。

程序很短，值得逐段看：

| 片段 | 作用 |
|------|------|
| `bool showRes = argc > 1;` | **带任何一个参数**就打印分辨率（`clock_times showres` 的 `showres` 只是个占位，内容不重要） |
| `printf("%-15s: %10ld.%03ld (", ...)` | 名字左对齐 15 列、秒右对齐 10 列、**毫秒** 3 位 ⇒ 打印出来的 `1789619106.436` 是**截断到毫秒**的 |
| `days`/`h`/`m`/`s` 三行换算 | 把秒数拆成「多少天 + 时:分:秒」 |
| `if (showRes) printf("     resolution: %10ld.%09ld\n", ...)` | 分辨率按 `秒.纳秒9位` 打印 |
| `#ifdef CLOCK_TAI` / `#ifdef CLOCK_BOOTTIME` | 用条件编译兼容老内核头文件 |

> ⚠️ **`clock_getres()` 被调用是「无条件」的**（在 `if (showRes)` **之前**）。所以即使不加参数，程序也已经查过一遍分辨率，只是不打印。

## 4. `clock_getres()` 是 HRT 的判据

把 §23.2 的结论在这里落地。同一个探针（不属于章节交付物）把 Linux 上所有能拿到的时钟连分辨率一起列了出来：

```text
  CLOCK_REALTIME           value=1789620249.696493133  res=0.000000001
  CLOCK_MONOTONIC          value=16451.861264680  res=0.000000001
  CLOCK_BOOTTIME           value=16451.861266059  res=0.000000001
  CLOCK_TAI                value=1789620286.696498867  res=0.000000001
  CLOCK_MONOTONIC_RAW      value=16452.150209398  res=0.000000001
  CLOCK_REALTIME_COARSE    value=1789620249.696206129  res=0.001000000
  CLOCK_MONOTONIC_COARSE   value=16451.860974688  res=0.001000000
  CLOCK_PROCESS_CPUTIME_ID value=0.000908274  res=0.000000001
  CLOCK_THREAD_CPUTIME_ID  value=0.000910698  res=0.000000001
```

| 时钟 | `clock_getres()` | 解读 |
|------|------------------|------|
| `CLOCK_REALTIME` / `CLOCK_MONOTONIC` / `CLOCK_BOOTTIME` / `CLOCK_TAI` / `CLOCK_MONOTONIC_RAW` | `0.000000001` | **1 ns ⇒ HRT（`CONFIG_HIGH_RES_TIMERS`）已开启** |
| `CLOCK_REALTIME_COARSE` / `CLOCK_MONOTONIC_COARSE` | **`0.001000000`** | **1 ms ⇒ 这台机器的 jiffy = 1 ms（`CONFIG_HZ=1000`）** |
| `CLOCK_PROCESS_CPUTIME_ID` / `CLOCK_THREAD_CPUTIME_ID` | `0.000000001` | 1 ns |

这张表把「**HRT 的 1 ns**」和「**tick 的 1 ms**」**同时**摆出来了 —— 它们差 6 个数量级，共存于同一台机器。书里说的 *the resolution of the returned value is the jiffy* 指的就是最后那两个 `_COARSE`。

> ⭐ 顺带的实测细节：`CLOCK_MONOTONIC_RAW` = `16452.150`，比 `CLOCK_MONOTONIC` = `16451.861` **大 0.289 秒**。`RAW` 不被 NTP 调整，`MONOTONIC` 会被 **slew**（慢速调整）⇒ 这个差值就是这台宿主运行 4.57 小时里累积的调整量。**这个数随宿主与时长变化**，不作普适结论，只说明「两者确实会分开」。

## 23.5.4 `clock_nanosleep()`：睡眠问题的正解

```c
#define _XOPEN_SOURCE 600
#include <time.h>

int clock_nanosleep(clockid_t clockid, int flags,
                    const struct timespec *request,
                    struct timespec *remain);
/* 返回 0 表示睡满；返回**正数错误码**表示出错或被信号打断 */
```

原书对「为什么需要它」说得很明确：

> If we instead try retrieving the current time, calculating the difference until the desired target time, and doing a relative sleep, then there is a possibility that the process **may be preempted in the middle of these steps**, and consequently sleep for longer than desired.
>
> ...this "oversleeping" problem is particularly marked for a process that uses a loop to restart a sleep that is interrupted by a signal handler. ... We can avoid the oversleeping problem by making an initial call to `clock_gettime()` to retrieve the time, adding the desired amount to that time, and then calling `clock_nanosleep()` with the **`TIMER_ABSTIME`** flag (and restarting the system call if it is interrupted by a signal handler).

### `TIMER_ABSTIME` 为什么能解决 §23.4 的「永远睡不完」

| 维度 | `nanosleep()`（相对） | `clock_nanosleep(TIMER_ABSTIME)`（绝对） |
|------|---------------------|----------------------------------------|
| `request` 的含义 | 「**从现在起**睡这么久」 | 「睡到**这个绝对时刻**」 |
| 被打断后怎么办 | 拿 `remain` 当**新的相对请求**再睡 | **原样重复同一次调用**（`request` 不变） |
| 每次重启的误差 | 每轮都向上取整到 jiffy ⇒ **累积** | 每次都是「睡到同一个绝对时刻」⇒ **误差不累积** |
| 极端情况 | 信号比 jiffy 还密 ⇒ **永远睡不完** | 信号再密，只要有一次安静下来就立即到期 |
| `remain` 参数 | 必须传，用来续睡 | **无用**，传 `NULL`（原书原文：*the `remain` argument is unused (it is unnecessary)*） |

另外两个区别于 `nanosleep()` 的点：

1. **`clockid` 可选** —— 原书：*we can choose the clock that is used to measure the sleep interval. We specify the desired clock in `clockid`: `CLOCK_REALTIME`, `CLOCK_MONOTONIC`, or `CLOCK_PROCESS_CPUTIME_ID`.* 想睡「真实过了 1 秒」就用 `CLOCK_MONOTONIC`；`CLOCK_REALTIME` 会被 NTP 阶跃影响。
2. **错误返回风格** —— 直接返回正数错误码（不是 `-1` + `errno`）。所以**不能写** `if (clock_nanosleep(...) == -1)`。

### Listing 23-4 是一条代码片段，官方没有对应文件

⭐ **源码核验结论**：官方 Ch23 分发目录里**没有**「Listing 23-4」对应的 `.c` 文件。Listing 23-4 是 §23.5.4 正文里的一段**内联示例**，原书标题为 *Listing 23-4: Using `clock_nanosleep()`*：

```c
struct timespec request;

/* Retrieve current value of CLOCK_REALTIME clock */
if (clock_gettime(CLOCK_REALTIME, &request) == -1)
    errExit("clock_gettime");

request.tv_sec += 20;               /* Sleep for 20 seconds from now */
s = clock_nanosleep(CLOCK_REALTIME, TIMER_ABSTIME, &request, NULL);
if (s != 0) {
    if (s == EINTR)
        printf("Interrupted by signal handler\n");
    else
        errExitEN(s, "clock_nanosleep");
}
```

这段片段的三个要点，全部体现在 `t_clock_nanosleep.c` 里（见下）：

- 先 `clock_gettime()` 取**当前时刻**，再加上想要的偏移 ⇒ 得到**绝对目标时刻**；
- `TIMER_ABSTIME` 下 `remain` 传 `NULL`；
- 判断错误用 `s != 0` / `s == EINTR`，**不是** `s == -1`。

```c
/*************************************************************************\

* under the terms of the GNU General Public License as published by the   *

\*************************************************************************/

/* t_clock_nanosleep.c

   Demonstrate the use of clock_nanosleep() to sleep for an interval
   specified in nanoseconds.

   See also t_nanosleep.c.

   Linux supports clock_nanosleep() since kernel 2.6.
*/
#if ! defined(_XOPEN_SOURCE) || _XOPEN_SOURCE < 600
#define _XOPEN_SOURCE 600
#endif
#include <sys/time.h>
#include <time.h>
#include <signal.h>
#include "tlpi_hdr.h"

static void
sigintHandler(int sig)
{
    return;                             /* Just interrupt clock_nanosleep() */
}

int
main(int argc, char *argv[])
{
    if (argc < 3 || strcmp(argv[1], "--help") == 0)
        usageErr("%s secs nanosecs [a]\n", argv[0]);

    /* Allow SIGINT handler to interrupt clock_nanosleep() */

    struct sigaction sa;
    sigemptyset(&sa.sa_mask);
    sa.sa_flags = 0;
    sa.sa_handler = sigintHandler;
    if (sigaction(SIGINT, &sa, NULL) == -1)
        errExit("sigaction");

    /* If more than three command-line arguments, use TIMER_ABSTIME flag */

    int flags = (argc > 3) ? TIMER_ABSTIME : 0;

    struct timespec request;

    if (flags == TIMER_ABSTIME) {
        if (clock_gettime(CLOCK_REALTIME, &request) == -1)
            errExit("clock_gettime");
        printf("Initial CLOCK_REALTIME value: %ld.%09ld\n",
                (long) request.tv_sec, request.tv_nsec);

        request.tv_sec  += getLong(argv[1], 0, "secs");
        request.tv_nsec += getLong(argv[2], 0, "nanosecs");
        if (request.tv_nsec >= 1000000000) {
            request.tv_sec += request.tv_nsec / 1000000000;
            request.tv_nsec %= 1000000000;
        }

    } else {                    /* Relative sleep */
        request.tv_sec  = getLong(argv[1], 0, "secs");
        request.tv_nsec = getLong(argv[2], 0, "nanosecs");
    }

    struct timeval start, finish;
    if (gettimeofday(&start, NULL) == -1)
        errExit("gettimeofday");

    for (;;) {
        struct timespec remain;
        int s = clock_nanosleep(CLOCK_REALTIME, flags, &request, &remain);
        if (s != 0 && s != EINTR)
            errExitEN(s, "clock_nanosleep");

        if (s == EINTR)
            printf("Interrupted... ");

        if (gettimeofday(&finish, NULL) == -1)
            errExit("gettimeofday");
        printf("Slept: %.6f secs", finish.tv_sec - start.tv_sec +
                        (finish.tv_usec - start.tv_usec) / 1000000.0);

        if (s == 0)
            break;                      /* sleep completed */

        if (flags != TIMER_ABSTIME) {
            printf("... Remaining: %ld.%09ld",
                    (long) remain.tv_sec, remain.tv_nsec);

            request = remain;
        }

        printf("... Restarting\n");
    }

    printf("\nSleep complete\n");
    exit(EXIT_SUCCESS);
}
```

编译（`code/` 目录下）：

```bash
gcc -O0 -Wall -Wextra -o t_clock_nanosleep t_clock_nanosleep.c get_num.c
```

用法是 `secs nanosecs [a]`：**第 3 个参数存在就走 `TIMER_ABSTIME` 分支**（`flags = (argc > 3) ? TIMER_ABSTIME : 0;`）。这个设计很聪明 —— 同一个程序、同一套循环，只靠一个参数就在「相对」与「绝对」两种语义之间切换，**对照结果直接可比**。

程序里两个值得记住的写法：

```c
/* ① 绝对分支：先取当前时刻，再把「偏移」加上去 —— 注意要处理 nsec 进位 */
if (request.tv_nsec >= 1000000000) {
    request.tv_sec += request.tv_nsec / 1000000000;
    request.tv_nsec %= 1000000000;
}

/* ② 错误处理：clock_nanosleep 返回正数错误码，不是 -1 */
int s = clock_nanosleep(CLOCK_REALTIME, flags, &request, &remain);
if (s != 0 && s != EINTR)
    errExitEN(s, "clock_nanosleep");
```

## CE 实测：绝对睡眠（`1 0 a`）

```text
Initial CLOCK_REALTIME value: 1789619387.870112001
Slept: 1.000051 secs
Sleep complete
```

对比着读：

| 模式 | 命令行 | 输出 | 说明 |
|------|--------|------|------|
| 相对 | `1 0` | `Slept: 1.000071 secs` | 只打印睡眠结果，没有前置行 |
| 绝对 | `1 0 a` | 先 `Initial CLOCK_REALTIME value: 1789619387.870112001`，再 `Slept: 1.000051 secs` | **多打了一行**：`clock_gettime()` 取到的「当前绝对时刻」（秒 + 9 位纳秒） |

两点：

- **`Initial CLOCK_REALTIME value` 那一行是 `TIMER_ABSTIME` 的指纹** —— 只有走了绝对分支才会 `clock_gettime()` 并打印它。`%ld.%09ld` ⇒ 纳秒位是**打印出来的真实值**（`.870112001`），不是补零。
- **超出量 `+71 µs`（相对）与 `+51 µs`（绝对）** —— 同一量级。绝对睡眠并不「更准」，它解决的是**累积漂移**与**永不到期**，不是单次的调度延迟（§23.2）。

> ⚠️ 与 `t_nanosleep.c` 的打印格式有个小差别值得注意：`t_nanosleep` 用 `%9.6f`（**宽度 9**，所以是 ` 1.000071`），`t_clock_nanosleep` 用 `%.6f`（无宽度，`1.000071`）。这不是笔误，是原书两个程序的写法差异。

## 常见坑

| # | 坑 | 正解 |
|---|----|------|
| 1 | 用 `CLOCK_REALTIME` 做「经过了多久」的测量 | 它会被 NTP 阶跃/手动改时间影响 ⇒ 用 `CLOCK_MONOTONIC` |
| 2 | 以为 `CLOCK_MONOTONIC` 完全不受影响 | 它会被 NTP **slew**（慢速调整）。要完全不被调的是 `CLOCK_MONOTONIC_RAW` |
| 3 | 以为 `CLOCK_MONOTONIC` 是「绝对时间」 | 它是「自某个未指定的过去点起」的相对计数，**跨机不可比**；跨机对齐用 `CLOCK_REALTIME`/`CLOCK_TAI` |
| 4 | 用 `CLOCK_MONOTONIC` 存盘做时间戳 | 重启后归零，历史数据无法比较；存盘用 `CLOCK_REALTIME`（或存 UTC） |
| 5 | 闰秒时刻用 `CLOCK_REALTIME` 做周期任务 | 闰秒时 `CLOCK_REALTIME` 会跳变/停顿；**`CLOCK_TAI` 没有闰秒** |
| 6 | 以为能 `clock_settime()` 改所有时钟 | **只有 `CLOCK_REALTIME` 可设**，且需要 `CAP_SYS_TIME`；其余全只读 |
| 7 | 把 `clock_getres()` 当「精度承诺」 | 它是**下界**。实测 `clock_nanosleep(1s)` 实际 +51~71 µs |
| 8 | 在定时器里用 `CLOCK_REALTIME_COARSE` 图便宜 | 分辨率就是 **jiffy**（实测 1 ms），代价是精度 |
| 9 | 写 `if (clock_nanosleep(...) == -1)` | 它**返回正数错误码**，不是 `-1`；写 `if (s != 0)` |
| 10 | `TIMER_ABSTIME` 时还给 `remain` 传指针并读它 | 绝对模式下 `remain` **完全无用**（原书原文），传 `NULL` |
| 11 | `TIMER_ABSTIME` 时的 `request` 忘了进位 `tv_nsec` | `tv_nsec` 必须 < 1e9，否则 `EINVAL` |
| 12 | 还在 `-lrt` | glibc ≥ 2.17 已并入 libc；`-lrt` 无害但不是必需（老发行版/老交叉工具链上仍需） |
| 13 | 以为 `clock_getcpuclockid` 像 `clock_gettime` 一样返回 `-1` | 它和 `pthread_*` 一样**返回正数错误码** |
| 14 | 用 `CLOCK_PROCESS_CPUTIME_ID` 做睡眠/超时基准 | 它算的是 **CPU 时间**，进程阻塞时不动 ⇒ 永远等不到（和 `ITIMER_VIRTUAL` 同一个陷阱） |

## HFT / 嵌入式关联

| 路线 | 结论怎么用 |
|------|-----------|
| **HFT** | ① **定时基准只用 `CLOCK_MONOTONIC`**：节流窗口、重传超时、心跳间隔都用它，`CLOCK_REALTIME` 只用于「对外可见的时间戳」和日志。② 需要在**绝对时刻**动手（开盘、集合竞价结束、收盘前 N 秒平仓）就用 `clock_nanosleep(CLOCK_MONOTONIC, TIMER_ABSTIME, ...)`：它不怕信号密集，也不怕 NTP 调整，重启后剩余时间是**重算**的。③ 跨机对齐时间（多机共用一个行情源）优先 `PTP` 校准的 `CLOCK_TAI` —— **没有闰秒跳变**，避免在闰秒那一刻出现「同一秒出现两次」或「某秒消失」。④ 量「这段代码耗时」用 `CLOCK_MONOTONIC_RAW` 或 `CLOCK_MONOTONIC`，**不要**用 `CLOCK_REALTIME`（被 slew 会污染测量）。⑤ 低延迟打点用 `CLOCK_REALTIME_COARSE`：不访问硬件时钟、代价极小，代价是 1 ms 粒度 —— 适合「哪一秒发生了这事」而不适合「花了多少 ns」。 |
| **嵌入式** | ① 做「运行了多久」的计时（开机时长、保修计时）用 `CLOCK_BOOTTIME` —— 它把 suspend 时间算进去，`CLOCK_MONOTONIC` 不算。② 低功耗设备做「每 100 ms 采一次」用 `CLOCK_MONOTONIC` + `TIMER_ABSTIME`，避免每次唤醒的抖动累积成采样率漂移。③ 检查目标板有没有 HRT：跑一次 `clock_getres()`（本项目提供的 `clock_times showres` 就是为这个）。没有 HRT 时所有睡眠精度掉回 jiffy。④ `CLOCK_PROCESS_CPUTIME_ID` 是「这个进程烧了多少 CPU」的现成手段，比 `getrusage()` 更细（可到线程级用 `CLOCK_THREAD_CPUTIME_ID`）。 |

<summary>代码自测（Q&A）</summary>

**Q1：为什么 `clock_settime()` 向下取整，而定时器向上取整？**

A：因为语义目标不同。「设置时间是**尽量接近**你要的值」，而「定时器是**至少**等这么久才算数」。向上取整保证不会提前触发（提前触发会破坏「至少等 n 秒」的语义）；向下取整保证不会把时间往未来推（推了就等于凭空多了时间）。

**Q2：`CLOCK_REALTIME` 和 `CLOCK_TAI` 差 37 秒，这个数是怎么来的？**

A：`CLOCK_TAI` 是国际原子时（TAI，连续、没有闰秒），`CLOCK_REALTIME` 是 UTC（有闰秒调整）。TAI − UTC = 37 秒是 1972 年以来累积插入的闰秒总数（2017-01-01 起为 37 秒）。本页 `clock_times` 的实测正好给出 `1789619145.722 − 1789619108.722 = 37.000`。因为 `CLOCK_TAI` **不含闰秒跳变**，需要「连续、单调、又跟真实时刻对齐」的场景（如 PTP 时间戳）用它更合适。

**Q3：`CLOCK_BOOTTIME` 和 `CLOCK_MONOTONIC` 实测相等，说明什么？**

A：说明这台机器**没 suspend 过**。两者的定义差就是 suspend 时间：`CLOCK_BOOTTIME = CLOCK_MONOTONIC + suspend 时间`。笔记本合上盖子再打开、或嵌入式设备进入 `suspend-to-RAM` 唤醒后，两者就会分开 —— 这也是「运行时长统计」必须用 `CLOCK_BOOTTIME` 的原因。

**Q4：`TIMER_ABSTIME` 为什么能避免 §23.4 说的「永远睡不完」？**

A：因为请求的对象变了。相对睡眠每次重启都需要一个**新的相对量**（`remain`），而每个相对量都会被向上取整到 jiffy ⇒ 误差逐轮累积，信号够密就永远到不了 0。绝对睡眠请求的是**同一个绝对时刻**，重启用的还是**原来那个 `request`**（原书原文：*the sleep can be restarted by repeating the call with the same `request` argument*）—— 取整误差不会累积，只要有一次不受干扰就立即到期。

**Q5：我想测「这段代码跑了多久」，该用哪个时钟？**

A：用 `CLOCK_MONOTONIC`（或追求完全不受 NTP 影响时用 `CLOCK_MONOTONIC_RAW`）。**不要**用 `CLOCK_REALTIME`：一次 NTP 阶跃就能让你测出负数或一个大得离谱的数。也不要为了省事用 `CLOCK_REALTIME_COARSE` —— 它粒度是 jiffy（实测 1 ms），测微秒级耗时完全不够。

**Q6：`clock_getres()` 说 1 ns，那我用 `clock_nanosleep(0, 1)` 睡 1 纳秒行不行？**

A：语法上可以（`tv_nsec` 必须 < 1e9，1 合法），但**实际不可能**睡 1 纳秒。`clock_getres()` 给的是「时钟能表示的最小刻度」，而一次系统调用进入/退出的开销就有几十到上百纳秒，加上调度延迟（§23.2 实测 +51~71 µs）远大于 1 ns。**分辨率 ≠ 可达到的精度。**

**Q7：`clock_times.c` 为什么既没有被印成 Listing，也没在正文里提到？**

A：因为它不是书的一部分，而是**官方配套分发目录里额外提供的程序**。它的文件头写着 *A useful small program for time namespaces* —— 它是为内核 6.x 时代新增的 **time namespaces**（每个命名空间可以偏移 `CLOCK_MONOTONIC`/`CLOCK_BOOTTIME`）准备的体检工具，成书时还没有这个特性。这也是本仓库把「未印刷」的程序单独标注出来的原因：**它们是官方素材，但不是原书正文**。
