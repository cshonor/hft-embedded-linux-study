## 本节讲什么

`setitimer()` 建立的是「**间隔定时器**」：在未来某个时间点到期，并且（可选）此后每隔一段固定时间再到期一次。它有三个互不相同的「计时口径」，靠 `which` 选；`alarm()` 只是 `ITIMER_REAL` 的秒级简化版，**两者共用同一个内核定时器**。

本节钉五件事：

1. **`which` 决定「时间怎么走」**，也决定**发哪个信号**；三个信号的默认处置都是「终止进程」。
2. **`it_value` 是倒计时，`it_interval` 是重装值**：`it_value` 归零即撤销定时器，`it_interval` 为 0 则只响一次。
3. **每类 `which` 每进程只有一个** —— 第二次调用是**覆盖**，不是新建。
4. **`alarm()` / `sleep()` / `setitimer(ITIMER_REAL)` 三者共享同一个定时器**，混用必然互相踩。
5. **返回值口径不一致**：`alarm()` 在剩余 ≥ 0.5 秒时**向上取整**，而「裸 `setitimer()` + 取 `tv_sec`」是截断 —— 本节的实测把这 1 秒的差摆出来了。

## 1. `which` 的三种口径

```c
#include <sys/time.h>

int getitimer(int which, struct itimerval *curr_value);
int setitimer(int which, const struct itimerval *new_value,
              struct itimerval *old_value);
```

| `which` | 倒计时依据 | 到期的信号 | 信号默认处置 |
|---------|-----------|-----------|-------------|
| `ITIMER_REAL` | **真实时间**（墙钟） | `SIGALRM` | 终止进程 |
| `ITIMER_VIRTUAL` | **进程虚拟时间**（只算用户态 CPU） | `SIGVTALRM` | 终止进程 |
| `ITIMER_PROF` | **进程时间**（用户态 + 内核态 CPU） | `SIGPROF` | 终止进程 |

三点必须记住：

- **默认处置是终止** —— 所以「不装处理器就 `setitimer()`」等于给进程安排一次自杀。
- **`ITIMER_VIRTUAL` / `ITIMER_PROF` 不走墙钟** —— 进程被换下 CPU 时它们**暂停**。所以它们能做 profiling（「这段代码烧掉多少 CPU」），但**不能做超时**。
- `ITIMER_PROF` 比 `ITIMER_VIRTUAL` 多算了内核态（含系统调用、缺页），所以做 profiling 用它更贴近「这个进程总共占了多少 CPU」。

## 2. `struct itimerval`：两个 `timeval` 的分工

```c
struct itimerval {
    struct timeval it_interval;   /* 重装值：周期 */
    struct timeval it_value;      /* 倒计时：下一次到期还有多久 */
};

struct timeval {
    time_t      tv_sec;           /* 秒 */
    suseconds_t tv_usec;          /* 微秒 */
};
```

| 字段 | 作用 | 置 0 的后果 |
|------|------|------------|
| `it_value` | 距离**下一次**到期的延迟 | **撤销**定时器（无论 `it_interval` 是什么） |
| `it_interval` | 每次到期后**自动重装**给 `it_value` 的值 | 只响**一次**，之后定时器停 |

> ⭐ 顺序很反直觉：**`it_interval` 写在前面，`it_value` 写在后面**。书上和 man page 都按这个顺序定义，写初始化列表时别按直觉反着来。

`old_value` 是输出参数：拿「上一个设置的剩余时间」，`alarm()` 的返回值就是从它来的。不需要就传 `NULL`。

---

## 3. 「每类只有一个」这条硬约束

对**每一种** `which`，内核在进程的 `signal_struct` 里只维护**一个**定时器。所以：

| 事实 | 后果 |
|------|------|
| `setitimer(ITIMER_REAL, ...)` 第二次调用是**覆盖** | 想同时挂两个 `ITIMER_REAL` 做不到 —— 必须自己维护队列 |
| `alarm()` / `sleep()` / `setitimer(ITIMER_REAL)` 共享同一个定时器 | 三者**互相覆盖**，混用必然出错 |
| 定时器**不跨 `fork()` 继承**，但**跨 `exec()` 保留** | 子进程里 `alarm` 不响；`exec` 之后老闹钟还在 |

> ⚠️ 这是本节最重要的一条实践结论：**同一个进程里，`ITIMER_REAL` 只能有「一个主人」。** 需要多个定时器就该换 §23.6 的 POSIX 定时器（可无限多实例）。

```c
/* real_timer.c

   A demonstration of the use of (real-time) timers created using setitimer().

   Usage: real_timer [secs [usecs [int-secs [int-usecs]]]]
             Defaults: 2      0        0         0

   The command-line arguments are the second and microsecond settings for
   the timer's initial value and interval.

   The version of this code shown in the first print of the book contained
   an error in the main() function whereby 'maxSigs' was initialized before
   'itv', even though the initialization of the former variable depends on the
   initialization of the latter variable. See the erratum for page 983 to 984.
*/
#include <signal.h>
#include <sys/time.h>
#include <time.h>
#include "tlpi_hdr.h"

static volatile sig_atomic_t gotAlarm = 0;
                        /* Set nonzero on receipt of SIGALRM */

/* Retrieve and display the real time, and (if 'includeTimer' is
   TRUE) the current value and interval for the ITIMER_REAL timer */

static void
displayTimes(const char *msg, Boolean includeTimer)
{
    struct itimerval itv;
    static struct timeval start;
    struct timeval curr;
    static int callNum = 0;             /* Number of calls to this function */

    if (callNum == 0)                   /* Initialize elapsed time meter */
        if (gettimeofday(&start, NULL) == -1)
            errExit("gettimeofday");

    if (callNum % 20 == 0)              /* Print header every 20 lines */
        printf("       Elapsed   Value Interval\n");

    if (gettimeofday(&curr, NULL) == -1)
        errExit("gettimeofday");
    printf("%-7s %6.2f", msg, curr.tv_sec - start.tv_sec +
                        (curr.tv_usec - start.tv_usec) / 1000000.0);

    if (includeTimer) {
        if (getitimer(ITIMER_REAL, &itv) == -1)
            errExit("getitimer");
        printf("  %6.2f  %6.2f",
                itv.it_value.tv_sec + itv.it_value.tv_usec / 1000000.0,
                itv.it_interval.tv_sec + itv.it_interval.tv_usec / 1000000.0);
    }

    printf("\n");
    callNum++;
}

static void
sigalrmHandler(int sig)
{
    gotAlarm = 1;
}

int
main(int argc, char *argv[])
{
    struct itimerval itv;
    clock_t prevClock;
    int maxSigs;                /* Number of signals to catch before exiting */
    int sigCnt;                 /* Number of signals so far caught */
    struct sigaction sa;

    if (argc > 1 && strcmp(argv[1], "--help") == 0)
        usageErr("%s [secs [usecs [int-secs [int-usecs]]]]\n", argv[0]);

    sigemptyset(&sa.sa_mask);
    sa.sa_flags = 0;
    sa.sa_handler = sigalrmHandler;
    if (sigaction(SIGALRM, &sa, NULL) == -1)
        errExit("sigaction");

    /* Set timer from the command-line arguments */

    itv.it_value.tv_sec = (argc > 1) ? getLong(argv[1], 0, "secs") : 2;
    itv.it_value.tv_usec = (argc > 2) ? getLong(argv[2], 0, "usecs") : 0;
    itv.it_interval.tv_sec = (argc > 3) ? getLong(argv[3], 0, "int-secs") : 0;
    itv.it_interval.tv_usec = (argc > 4) ? getLong(argv[4], 0, "int-usecs") : 0;

    /* Exit after 3 signals, or on first signal if interval is 0 */

    maxSigs = (itv.it_interval.tv_sec == 0 &&
                itv.it_interval.tv_usec == 0) ? 1 : 3;

    displayTimes("START:", FALSE);
    if (setitimer(ITIMER_REAL, &itv, NULL) == -1)
        errExit("setitimer");

    prevClock = clock();
    sigCnt = 0;

    for (;;) {

        /* Inner loop consumes at least 0.5 seconds CPU time */

        while (((clock() - prevClock) * 10 / CLOCKS_PER_SEC) < 5) {
            if (gotAlarm) {                     /* Did we get a signal? */
                gotAlarm = 0;
                displayTimes("ALARM:", TRUE);

                sigCnt++;
                if (sigCnt >= maxSigs) {
                    printf("That's all folks\n");
                    exit(EXIT_SUCCESS);
                }
            }
        }

        prevClock = clock();
        displayTimes("Main: ", TRUE);
    }
}
```

## CE 实测：`1 0 1 0`（1 秒后首次，之后每 1 秒）

命令行是 `[secs [usecs [int-secs [int-usecs]]]]`，所以 `1 0 1 0` = 首次 1 秒、间隔 1 秒。`it_interval` 非 0 ⇒ 程序要收满 **3 个**信号才退出。

```text
       Elapsed   Value Interval
START:    0.00
Main:     0.51    0.49    1.00
ALARM:    1.49    0.51    1.00
Main:     1.51    0.49    1.00
ALARM:    2.00    1.00    1.00
Main:     2.51    0.49    1.00
ALARM:    3.00    1.00    1.00
That's all folks
```

逐条解读：

| 行 | 含义 |
|----|------|
| `Elapsed   Value Interval` | 每 20 行打一次的表头（`callNum % 20 == 0`）。本作业只有 9 行，所以只出现一次 |
| `START:    0.00` | `displayTimes("START:", FALSE)` —— **第三个参数是 `FALSE`**，所以这一行**不打印** `Value`/`Interval` 两栏（那时定时器还没启动） |
| `Main:     0.51    0.49    1.00` | 内层 `while` 循环烧掉 0.5 秒 CPU 后落到这一行。`Value = 0.49` 就是「距下次到期还有 0.49 秒」，`Interval = 1.00` |
| `ALARM:    1.49    0.51    1.00` | 信号已送达、`getitimer()` 读出**新**一轮的剩余 0.51 秒 ⇒ **`it_interval` 自动重装了** |
| `That's all folks` | `sigCnt >= maxSigs`（3）⇒ `exit(EXIT_SUCCESS)`，所以程序**能正常退出**（本章少数几个能自己结束的程序之一） |

要点：

- **`Elapsed` 是墙钟、`Main:` 行之间的间隔是 0.5 秒 CPU** —— 两者不是一回事。`0.51 / 1.49 / 2.00 / 2.51 / 3.00` 这套时刻说明：**到期时刻本身是准的（1.49→2.00→3.00 的间隔交替是 0.5/1.0）**，只是「打印的时刻」被 0.5 秒的 CPU 忙等量化了。
- **`ALARM:` 行看到的 `Value` 不是 0**（是 0.51/1.00）—— 因为信号送达与 `getitimer()` 之间隔了一段时间，内核已经按 `it_interval` 重装过了。
- ⭐ **间隔定时器不会「累积漂移」**：书中 §23.2 的原文是 *interval timers are not subject to creeping errors* —— 后续到期时刻按 `it_interval` 从**上次到期点**推算，不因为处理延迟而往后堆。这一点和「自己 `nanosleep()` 循环」有本质区别（见 §23.4）。

## CE 实测：`1 0`（间隔为 0 ⇒ 单次定时器）

`maxSigs` 的取值由 `it_interval` 是否为 0 决定：为 0 时 `maxSigs = 1`，所以第一个信号就退出。

```text
       Elapsed   Value Interval
START:    0.00
Main:     0.50    0.50    0.00
ALARM:    1.01    0.00    0.00
That's all folks
```

| 行 | 含义 |
|----|------|
| `START:    0.00` | 同样不打印 `Value`/`Interval`（`includeTimer == FALSE`） |
| `Main:     0.50    0.50    0.00` | `Interval = 0.00` ⇒ **单次**；`Value = 0.50` 是剩余倒计时 |
| `ALARM:    1.01    0.00    0.00` | 到期后 `Value` 归 **0.00** ⇒ 定时器已停（`it_interval == 0` 不再重装） |

**`it_value` 归零 = 定时器已撤销**，这就是 `alarm(0)` 撤销闹钟的底层机制。

## 返回值口径：`alarm()` 向上取整，裸 `setitimer()` 截断

这一点习题 23-1（「用 `setitimer()` 实现 `alarm()`」）会真正考到，本仓库的实现是 `code/ex23_1_my_alarm.c`（详见 [23.9 练习题](23.9-exercises.md)）。关键实测数据：

```text
  真 alarm(5)   -> 返回 0
  getitimer() 看到的真实剩余：4.699919 秒
  真 alarm(0)   -> 返回 5   ← 与上一行比：**向上取整**，不是截断
```

读法：真实剩余 **4.699919** 秒 ⇒ 内核的 `alarm(0)` 返回 **5**（向上取整），而「裸 `setitimer` + 取 `tv_sec`」只会返回 **4**（截断）。完整输出与解读在 [23.9](23.9-exercises.md)。

内核侧的差别在 `kernel/time/itimer.c` 的 `alarm_setitimer()`（v3.5 时该文件是 `kernel/itimer.c`）：

``` 内核原文（linux-next v3.5 镜像站，逐字）
	do_setitimer(ITIMER_REAL, &it_new, &it_old);

	/*
	 * We can't return 0 if we have an alarm pending ...  And we'd
	 * better return too much than too little anyway
	 */
	if ((!it_old.it_value.tv_sec && it_old.it_value.tv_usec) ||
	    it_old.it_value.tv_usec >= 500000)
		it_old.it_value.tv_sec++;

	return it_old.it_value.tv_sec;
```

> ⚠️ 版本说明（诚实标注）：上面这段引自 **v3.5**（`kernel/itimer.c`）。v6.6 该文件已移到 `kernel/time/itimer.c`，**本仓库没有逐字核对那一版**（在线源码站被反爬拦住）。但本节实测的 `4.699919 → 返回 5` 与这段逻辑**完全吻合**，所以行为结论是可靠的。

## 常见坑

| # | 坑 | 正解 |
|---|----|------|
| 1 | 装了 `SIGALRM` 处理器却忘了它默认是**终止进程** | 三兄弟（`SIGALRM`/`SIGVTALRM`/`SIGPROF`）默认都杀进程 |
| 2 | 以为「每类 `which` 可以有多个」 | **每进程每类只有一个**，第二次调用是覆盖 |
| 3 | 在同一个进程里混用 `alarm()` 与 `setitimer(ITIMER_REAL)` | 它们是**同一个**定时器，互相覆盖 |
| 4 | 用 `ITIMER_VIRTUAL`/`ITIMER_PROF` 做超时 | 它们走 CPU 时间，进程被换下 CPU 就暂停 ⇒ **永远等不到超时** |
| 5 | 以为 `it_interval` 置 0 是「撤销」 | 撤销要靠把 **`it_value`** 置 0；`it_interval=0` 只是「不重复」 |
| 6 | 按直觉写 `{.it_value=..., .it_interval=...}` | 用**指定初始化器**（designated initializer）就不会记错顺序 |
| 7 | 在 `fork()` 后的子进程里等闹钟 | 定时器**不继承**；要么子进程自己设，要么父进程设 |
| 8 | 拿 `setitimer()` 的返回秒数当「精确剩余」 | 是 `tv_sec` 截断值；要精确剩余得调 `getitimer()` |
| 9 | 现代内核用 `-lrt` 链 `setitimer` | `setitimer` 一直在 **libc** 里；`-lrt` 是给 POSIX 定时器用的（且 glibc ≥ 2.17 之后也不需要了） |
| 10 | 假设定时器到期就会**立刻**得到 CPU | 到期只是「信号被标记为 pending」，真正跑处理器要等调度到本进程（§23.2） |

## HFT / 嵌入式关联

| 路线 | 结论怎么用 |
|------|-----------|
| **HFT** | ① `ITIMER_REAL` 走墙钟 ⇒ 一次 NTP 阶跃就能让所有周期任务错位；周期心跳一律用 `CLOCK_MONOTONIC` 的 POSIX 定时器/timerfd。② 每类只有一个实例 ⇒ 多个策略/多个风控超时**不能**各挂一个 `ITIMER_REAL`。③ 到期时刻准但**处理器延迟不可控** ⇒ 关键路径上「定时器发信号 + 信号处理器干活」全程都在异步上下文里，不能放止损/撤单这类要审计的操作。 |
| **嵌入式** | ① `ITIMER_PROF` 是**低开销 CPU 占用率**的现成手段（不用像 `cpu_burner.c` 那样自己算）；② `ITIMER_REAL` 做**看门狗喂狗的超时**很省事，但注意它走墙钟、且与 `sleep()` 抢同一个定时器；③ uClibc/musl 上 `setitimer` 的微秒精度受 `HZ` 限制（无 `CONFIG_HIGH_RES_TIMERS` 时），设计超时必须按最坏 jiffy 留余量（§23.2）。 |

<summary>代码自测（Q&A）</summary>

**Q1：为什么说 `ITIMER_VIRTUAL` 不能用来做超时？**

A：它倒计时用的是**进程虚拟时间**（只算用户态 CPU）。进程被换下 CPU、阻塞在 I/O 上、或在等待时，这个计数**不增长** ⇒ 定时器永不到期，超时形同不存在。做超时必须用 `ITIMER_REAL`（墙钟）或 `CLOCK_MONOTONIC`。

**Q2：`it_value` 与 `it_interval` 都置 0 会怎样？**

A：定时器被**撤销**。`it_value = {0,0}` 单独就是撤销（`alarm(0)` 的底层实现），此时 `it_interval` 写什么都没意义。

**Q3：本节的 `real_timer 1 0 1 0` 里，为什么 `ALARM:` 行的 `Value` 不是 0 而是 0.51？**

A：信号送达 ≠ 立刻跑处理器。`getitimer()` 是**处理器跑起来之后**才调的，那时内核早已按 `it_interval = 1s` 重装了下一轮，所以读到的是新一轮的剩余。这也顺带说明「`it_interval` 会从上次到期点重新起算」——不是从处理器返回点起算，所以**不会累积漂移**。

**Q4：`alarm(0)` 撤销时返回 5，而我用 `setitimer` 取 `tv_sec` 只拿到 4，谁错了？**

A：都没错，**口径不同**。内核 `alarm_setitimer()` 在剩余微秒 ≥ 500000 时 `tv_sec++`（注释原话是 *we'd better return too much than too little*）；而「裸 `setitimer` + 读 `old.it_value.tv_sec`」是截断。实测：真实剩余 `4.699919` ⇒ `alarm(0)` 返回 `5`，`my_alarm()` 返回 `4`。

**Q5：为什么 `usageErr()` 的输出在 stderr 而不是 stdout？**

A：用法/错误信息走 stderr 是惯例（保证重定向 stdout 时用户仍能看到）。本仓库实测里的 `Usage: ./output.s ...` 就是它；`argv[0]` 是 `./output.s` 是 CE 执行器的产物，不影响结论。
