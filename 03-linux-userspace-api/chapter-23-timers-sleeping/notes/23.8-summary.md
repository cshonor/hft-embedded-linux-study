### 定时器选型决策

| 需求 | 推荐 |
|------|------|
| 简单延时 | `nanosleep` |
| 单次超时 | `alarm` 或 `timer_create` |
| 间隔定时（旧代码） | `setitimer` |
| 间隔定时（新代码） | POSIX `timer_create` |
| 融入 epoll 事件循环 | `timerfd` |
| 高精度 + 特定线程通知 | `timer_create` + `SIGEV_THREAD_ID` |

### 核心要点

1. 始终用 `CLOCK_MONOTONIC` 而非 `CLOCK_REALTIME`（避免 NTP 跳变）
2. `timerfd` 是 Linux 最佳实践——融入 epoll，统一事件循环
3. `setitimer` 限制多（仅 3 个实例），新代码用 POSIX timer
4. 标准信号超时不排队 → 用 `timer_getoverrun()` 检查丢失次数

## 代码自测

<details>
<summary>1. 为什么推荐 CLOCK_MONOTONIC 而非 CLOCK_REALTIME？</summary>

CLOCK_REALTIME 反映墙上时间，可被 NTP 或管理员调整（向前跳或向后跳），导致定时器行为异常。CLOCK_MONOTONIC 单调递增，不受调整影响，适合定时器。
</details>

<details>
<summary>2. timerfd 相比 POSIX timer 的最大优势是什么？</summary>

timerfd 是文件描述符，可融入 epoll/poll 事件循环，与 I/O 事件统一处理。POSIX timer 通过信号通知，需要 handler 或 sigwaitinfo，难以与 I/O 事件统一。
</details>
