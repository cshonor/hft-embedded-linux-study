## 本节讲什么

int nanosleep(const struct timespec *req, struct timespec *rem); - **不占 `SIGALRM`** - 中断：`-1`/`EINTR`，`rem` 剩余时间可重试

---

## 要点

### `sleep` / `usleep`（少用）

| API | 问题 |
|-----|------|
| `sleep` | 内部常走 `alarm`+`SIGALRM`，与其它 `alarm` 冲突；打断返回剩余秒数 |
| `usleep` | 已废弃；新代码用 `nanosleep` |

### `nanosleep`（推荐短休眠）

```c
int nanosleep(const struct timespec *req, struct timespec *rem);
```

- **不占 `SIGALRM`**  
- 中断：`-1`/`EINTR`，`rem` 剩余时间可重试  
- 线程友好  

Demo：[`code/nanosleep_retry.c`](./code/nanosleep_retry.c)

### `clock_nanosleep`

```c
int clock_nanosleep(clockid_t clock_id, int flags,
                    const struct timespec *req, struct timespec *rem);
```

| flags | 含义 |
|-------|------|
| `0` | 相对休眠（≈ `nanosleep`，常等价 `CLOCK_REALTIME` 相对） |
| `TIMER_ABSTIME` | 等到绝对时刻 |

定时/超时逻辑优先 **`CLOCK_MONOTONIC`**（不受墙钟跳变影响）。

## 与 C 语言学习的关系

时间 API 是 C 系统编程的常见需求。K&R 没有深入讲解时间 API，但 `time_t` 和 `struct tm` 是 C 标准的一部分。在 HFT 场景中，高精度时钟（`clock_gettime` + `CLOCK_MONOTONIC`）是延迟测量的基础。注意 `time_t` 的类型不要假设为 `long`——应使用 `inttypes.h` 的格式化宏。

## 常见陷阱

1. **混淆 CLOCK_REALTIME 和 CLOCK_MONOTONIC**

```c
/* CLOCK_REALTIME: 可被 NTP 调整，会跳变 */
/* CLOCK_MONOTONIC: 单调递增，不可调 */
clock_gettime(CLOCK_MONOTONIC, &ts);
```

测量时间间隔必须用 CLOCK_MONOTONIC。CLOCK_REALTIME 可能被 NTP 往回调整，导致负的时间差。

2. **time_t 类型假设**

```c
long t = time(NULL);  /* 错误假设 */
time_t t = time(NULL); /* 正确 */
```

time_t 的底层类型是实现定义的（可能是 int32_t 或 int64_t）。不要假设为 long，用 time_t 类型。

3. **sleep 被信号中断**

```c
sleep(10);  /* 被信号中断后返回，不保证睡满 */
/* 返回值 = 剩余秒数 */
```

sleep 被信号中断后返回剩余秒数。需要精确延时应检查返回值并继续 sleep 剩余时间，或用 nanosleep。

## 自测题

**题目 1（选择）：** 测量两个事件之间的时间间隔，应该用哪个时钟？
A. CLOCK_REALTIME
B. CLOCK_MONOTONIC
C. CLOCK_PROCESS_CPUTIME_ID
D. time()

<details>
<summary>参考答案</summary>

B。CLOCK_MONOTONIC 单调递增不受 NTP 影响。CLOCK_REALTIME 可能被调整导致负间隔。

</details>

**题目 2（判断）：** `time_t` 一定是 `long` 类型。

<details>
<summary>参考答案</summary>

错误。time_t 的底层类型是实现定义的。在 32 位系统上可能是 32 位整数（2038 年问题）。应直接用 time_t 类型。

</details>

**题目 3（踩坑）：** 以下代码有什么问题？
```c
struct timespec start, end;
clock_gettime(CLOCK_REALTIME, &start);
/* ... do work ... */
clock_gettime(CLOCK_REALTIME, &end);
double elapsed = (end.tv_sec - start.tv_sec) +
                 (end.tv_nsec - start.tv_nsec) / 1e9;
```

<details>
<summary>参考答案</summary>

用 CLOCK_REALTIME 测量时间间隔。如果 NTP 在期间调整了时钟，elapsed 可能为负。应改用 CLOCK_MONOTONIC。

</details>

**题目 4（应用）：** 写代码用 clock_gettime 测量函数执行时间（纳秒精度）。

<details>
<summary>参考答案</summary>

```c
struct timespec start, end;
clock_gettime(CLOCK_MONOTONIC, &start);
foo();
clock_gettime(CLOCK_MONOTONIC, &end);
long ns = (end.tv_sec - start.tv_sec) * 1000000000L
         + (end.tv_nsec - start.tv_nsec);
printf("elapsed: %ld ns
", ns);
```

</details>
