# 39.11 Summary

> 本章：[TLPI 第 39 章](./README.md)

## 本节讲什么

第 39 章总结：Linux capabilities 的核心概念、API、安全实践和与 setuid 的对比。

## 要点

### capabilities 核心概念

| 概念 | 说明 |
|------|------|
| 拆分 root 权限 | 将全能 root 拆为 40+ 个独立能力 |
| 最小权限原则 | 程序只需获取必要的 capabilities |
| 文件 capabilities | 通过 setcap 在文件上设置，替代 setuid |
| 进程 capability 集 | Effective / Permitted / Inheritable / Bounding / Ambient |

### API 总览

| API | 用途 |
|-----|------|
| `cap_get_proc()` / `cap_set_proc()` | 获取/设置进程 caps |
| `cap_get_file()` / `cap_set_file()` | 获取/设置文件 caps |
| `cap_to_text()` / `cap_from_text()` | 文本 ↔ 内部格式 |
| `cap_set_flag()` | 设置 flag |
| `cap_clear()` / `cap_clear_flag()` | 清除 caps |
| `prctl(PR_SET_KEEPCAPS)` | 旧内核 exec 后保留 caps |
| `prctl(PR_CAPBSET_DROP)` | 缩小 bounding set |
| `prctl(PR_CAP_AMBIENT)` | 设置 ambient caps (4.3+) |
| `prctl(PR_SET_SECUREBITS)` | NOROOT 等安全位 |

### 常用 capabilities 速查

| Capability | 用途 | 典型程序 |
|------------|------|---------|
| `CAP_NET_BIND_SERVICE` | 绑定 <1024 端口 | webserver |
| `CAP_NET_RAW` | 原始套接字 | ping, tcpdump |
| `CAP_IPC_LOCK` | 锁定内存 | mlock, HFT engine |
| `CAP_SYS_NICE` | 设置调度策略 | 实时进程 |
| `CAP_SYS_TIME` | 修改系统时间 | ntpd |
| `CAP_SYS_ADMIN` | 系统管理（最强） | mount |
| `CAP_CHOWN` | 修改文件属主 | chown |
| `CAP_KILL` | 发送信号 | process manager |

### 安全最佳实践

1. 优先使用文件 caps 替代 setuid root
2. 程序启动早期丢弃不必要的 caps
3. 用 Bounding Set 限制可获取的 caps 范围
4. 考虑 `SECBIT_NOROOT` 防止 root 逃逸
5. systemd 中用 `AmbientCapabilities` + `CapabilityBoundingSet`
6. 不要给程序过多 caps（特别是 `CAP_SYS_ADMIN`）

### setuid vs capabilities

| 特性 | setuid root | 文件 capabilities |
|------|------------|-------------------|
| 权限粒度 | 全有或全无 | 细粒度 |
| 安全性 | 低 | 高 |
| 可审计性 | 差 | 好 |
| 兼容性 | 所有系统 | Linux ≥ 2.6.24 |
| 推荐 | 不推荐 | 推荐 |

## HFT / 嵌入式关联

- HFT 引擎只需 `CAP_IPC_LOCK` + `CAP_NET_BIND_SERVICE` + `CAP_SYS_NICE`
- 使用 `CapabilityBoundingSet` 限制容器内进程权限
- 嵌入式设备用 caps 替代 setuid 程序
- 安全审计：定期用 `getcap -r /` 检查所有文件 caps

<summary>什么是 Bounding Set？它的作用是什么？</summary>

Bounding Set（边界集）限制了进程（及其后代）能拥有的 capabilities 上限。`exec` 时新进程的 permitted caps 会被 Bounding Set 过滤。通过 `prctl(PR_CAPBSET_DROP, cap)` 可以缩小 bounding set，且操作不可逆——一旦丢弃，该 cap 永远无法恢复。这是实现最小权限的重要工具：在程序启动初期丢弃所有不需要的 caps，防止后续代码（即使被攻击者控制）也无法获取这些权限。
