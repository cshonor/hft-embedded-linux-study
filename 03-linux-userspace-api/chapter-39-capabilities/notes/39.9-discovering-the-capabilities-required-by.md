# 39.9 Discovering the Capabilities Required by a Program

> 本章：[TLPI 第 39 章](../README.md)

## 本节讲什么

如何确定一个程序需要哪些 capabilities：使用 `capsh`、`strace`、`getcap` 等工具分析和调试 capability 需求。

## 要点

### 分析工具

| 工具 | 用途 | 命令 |
|------|------|------|
| `getcap` | 查看文件 capabilities | `getcap ./app` |
| `capsh` | 查看/设置进程 caps | `capsh --print` |
| `strace` | 跟踪权限操作 | `strace -e trace=capset ./app` |
| `ltrace` | 跟踪库调用 | `ltrace -e cap_* ./app` |
| `/proc/self/status` | 查看进程 caps | `grep Cap /proc/self/status` |

### /proc/self/status 中的 Cap 字段

```
CapInh: 0000000000000000  ← Inheritable
CapPrm: 0000000000000000  ← Permitted
CapEff: 0000000000000000  ← Effective
CapBnd: 000001ffffffffff  ← Bounding
CapAmb: 0000000000000000  ← Ambient
```

### 解析 hex capability 位掩码

```bash
# 方法1：capsh 解析
capsh --decode=000001ffffffffff
# 输出: cap_chown,cap_dac_override,...

# 方法2：位运算（脚本）
python3 -c "
mask = 0x000001ffffffffff
caps = ['CAP_CHOWN','CAP_DAC_OVERRIDE','CAP_DAC_READ_SEARCH',
        'CAP_FOWNER','CAP_FSETID','CAP_KILL','CAP_SETGID',
        'CAP_SETUID','CAP_SETPCAP','CAP_LINUX_IMMUTABLE',
        'CAP_NET_BIND_SERVICE','CAP_NET_BROADCAST','CAP_NET_ADMIN',
        'CAP_NET_RAW','CAP_IPC_LOCK','CAP_IPC_OWNER','CAP_SYS_MODULE',
        'CAP_SYS_RAWIO','CAP_SYS_CHROOT','CAP_SYS_PTRACE','CAP_SYS_PACCT',
        'CAP_SYS_ADMIN','CAP_SYS_BOOT','CAP_SYS_NICE','CAP_SYS_RESOURCE',
        'CAP_SYS_TIME','CAP_SYS_TTY_CONFIG','CAP_MKNOD','CAP_LEASE',
        'CAP_AUDIT_WRITE','CAP_AUDIT_CONTROL','CAP_SETFCAP']
for i, c in enumerate(caps):
    if mask & (1 << i):
        print(c)
"
```

### 发现程序所需 capabilities 的步骤

1. 以无 capabilities 运行程序，观察 `EPERM` 错误
2. 用 `strace` 跟踪返回 `EPERM` 的系统调用
3. 查表确定该调用需要的 capability
4. 逐步添加 caps 直到程序正常运行

### 常见系统调用 → capability 映射

| 系统调用 | 失败 errno | 所需 capability |
|---------|-----------|----------------|
| `bind(port<1024)` | `EACCES` | `CAP_NET_BIND_SERVICE` |
| `socket(SOCK_RAW)` | `EPERM` | `CAP_NET_RAW` |
| `setpriority()` | `EPERM` | `CAP_SYS_NICE` |
| `mlock()` | `EPERM` | `CAP_IPC_LOCK` |
| `settimeofday()` | `EPERM` | `CAP_SYS_TIME` |
| `mount()` | `EPERM` | `CAP_SYS_ADMIN` |
| `chroot()` | `EPERM` | `CAP_SYS_CHROOT` |
| `kill()` | `EPERM` | `CAP_KILL` |

## HFT / 嵌入式关联

- 新交易服务上线前用 `strace` 分析精确的 capability 需求
- 嵌入式固件打包时确定最小 capability 集合
- 安全审计：验证程序没有多余的 capability

## 代码示例

```bash
#!/bin/bash
# 分析程序所需 capabilities

APP=./hft_engine

echo "=== 1. 当前文件 capabilities ==="
getcap $APP || echo "(none set)"

echo "=== 2. 以无 caps 运行，收集 EPERM ==="
# 使用 capsh --drop 移除所有 caps 后运行
strace -f -e trace=%file,%network,%process $APP 2>&1 | \
    grep -E 'EPERM|EACCES' | head -20

echo "=== 3. 尝试逐步添加 caps ==="
# 先尝试 CAP_NET_BIND_SERVICE
sudo setcap cap_net_bind_service=ep $APP
$APP --test 2>&1 | grep -i 'denied\|permission' || echo "OK: bind"

# 再添加 CAP_IPC_LOCK
sudo setcap cap_net_bind_service,cap_ipc_lock=ep $APP
$APP --test 2>&1 | grep -i 'denied\|permission' || echo "OK: mlock"

echo "=== 4. 最终 caps ==="
getcap $APP
```

## 代码自测

<details>
<summary>如何在不修改程序源码的情况下确定它需要哪些 capabilities？</summary>

1. 以普通用户运行程序，观察哪些操作失败（`EPERM`/`EACCES`）
2. 用 `strace -e trace=%file,%network,%process ./app 2>&1 | grep EPERM` 跟踪失败的系统调用
3. 查阅 capabilities 手册（`man capabilities`）确定每个失败调用对应的 capability
4. 用 `setcap` 逐步添加 caps 并重新测试，直到程序正常工作
5. 最终用 `getcap` 确认设置的最小 caps 集合

</details>
