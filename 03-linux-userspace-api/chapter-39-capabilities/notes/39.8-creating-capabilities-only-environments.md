# 39.8 Creating Capabilities-Only Environments

> 本章：[TLPI 第 39 章](../README.md)

## 本节讲什么

创建不依赖 root 的纯 capability 环境：使用 `SECBIT_NOROOT` 安全位、ambient capabilities（Linux 4.3+）、以及容器/沙箱中的应用模式。

## 要点

### SECBIT_NOROOT

```c
#include <sys/prctl.h>
#define SECBIT_NOROOT 1
#define SECBIT_NOROOT_LOCKED 2

prctl(PR_SET_SECUREBITS, SECBIT_NOROOT | SECBIT_NOROOT_LOCKED);
```

| 效果 | 说明 |
|------|------|
| root 退化为普通用户 | setuid(0) 不再获得全部能力 |
| 仍可通过文件 caps 赋权 | setcap 设置的能力仍生效 |
| LOCKED 位 | 防止撤销 NOROOT 模式 |

### Ambient Capabilities (Linux 4.3+)

```c
/* 设置 ambient capability */
prctl(PR_CAP_AMBIENT, PR_CAP_AMBIENT_RAISE, CAP_NET_BIND_SERVICE, 0, 0);

/* exec 后子进程自动继承 */
execve("/path/to/child", argv, envp);
```

| 特性 | 说明 |
|------|------|
| 自动继承 | exec 时无需文件 caps 配合 |
| 无需 setuid | 非 root 进程也能传递特权 |
| Permitted + Effective | ambient 直接进入子进程 P' 和 E' |

### 纯 capability 环境模式

```
┌──────────────────────────────────┐
│  init 进程 (root)                 │
│  设置: SECBIT_NOROOT              │
│  设置: Bounding set = 需要的 caps │
│  fork + exec 子服务               │
├──────────────────────────────────┤
│  子服务 (非 root UID)              │
│  继承 ambient caps                │
│  drop 不需要的 caps                │
│  执行核心逻辑                      │
└──────────────────────────────────┘
```

### 无 setuid 的替代方案

| 传统方式 | Capability 替代 |
|---------|-----------------|
| `setuid root` + bind 80 | `setcap cap_net_bind_service=ep` |
| `setuid root` + ping | `setcap cap_net_raw=ep` |
| `setuid root` + chown | `setcap cap_chown=ep` |
| root + mount | `setcap cap_sys_admin=ep` |

### systemd 中的 capability 管理

```ini
# /etc/systemd/system/hft.service
[Service]
User=hft
AmbientCapabilities=CAP_NET_BIND_SERVICE CAP_IPC_LOCK CAP_SYS_NICE
CapabilityBoundingSet=CAP_NET_BIND_SERVICE CAP_IPC_LOCK CAP_SYS_NICE
NoNewPrivileges=yes
```

## HFT / 嵌入式关联

- HFT 交易服务用 ambient caps 传递特权，无需 setuid root
- 嵌入式 systemd 服务配置精确的 capability bounding set
- 容器化 HFT 组件用 capability 替代 root 权限

## 代码示例

```c
#include <sys/capability.h>
#include <sys/prctl.h>
#include <unistd.h>
#include <stdio.h>

/* 初始化纯 capability 环境 */
int setup_cap_environment(void) {
    /* 1. 设置 Bounding Set（限制子进程可获取的 caps） */
    cap_value_t allowed[] = {
        CAP_NET_BIND_SERVICE, CAP_IPC_LOCK, CAP_SYS_NICE
    };
    for (int i = 0; i < sizeof(allowed)/sizeof(allowed[0]); i++)
        prctl(PR_CAPBSET_DROP, allowed[i], 0, 0, 0);

    /* 2. 设置允许的 caps 为 effective+permitted */
    cap_t caps = cap_get_proc();
    cap_clear(caps);
    cap_set_flag(caps, CAP_PERMITTED, 3, allowed, CAP_SET);
    cap_set_flag(caps, CAP_EFFECTIVE, 3, allowed, CAP_SET);
    cap_set_proc(caps);
    cap_free(caps);

    /* 3. 设置 ambient caps（Linux 4.3+） */
    for (int i = 0; i < 3; i++)
        prctl(PR_CAP_AMBIENT, PR_CAP_AMBIENT_RAISE, allowed[i], 0, 0);

    /* 4. 开启 NOROOT（root 也需 caps） */
    prctl(PR_SET_SECUREBITS, 0x1 | 0x2); /* NOROOT | LOCKED */

    /* 5. 切换到非 root 用户 */
    setgid(1000);
    setuid(1000);

    return 0;
}
```

## 代码自测

<details>
<summary>Ambient capabilities 和 Inheritable capabilities 有何区别？</summary>

- **Inheritable** 需要**文件 capabilities 配合**：exec 时 `F_inheritable & P_inheritable` 才能继承，必须用 `setcap` 在目标文件上设置 inheritable flag
- **Ambient** 是**自动继承**的：exec 时直接进入子进程的 Permitted 和 Effective 集合，不需要文件 capabilities 设置，也不需要 `setcap`

Ambient capabilities 简化了非 root 程序传递特权的流程，尤其适合容器和 systemd 服务。

</details>
