## 要点

| 集合 | 作用 |
|------|------|
| **Permitted** | 可拥有的上限；可从中抬到 Effective；**删掉难自恢复**（除非再 exec 文件能力） |
| **Effective** | **内核检查用**；按需开关 |
| **Inheritable** | fork 继承；参与 exec 算新 Permitted |
| **Bounding** | exec 能拿到的全局上界；**只删不增**；容器常用 |
| **Ambient**（4.3+） | 非 root 跨 exec 传能力；root exec 时清空 |

### 文件能力（xattr）

| 项 | |
|----|--|
| File Permitted | 并入新进程 Permitted（∩ Bounding） |
| File Inheritable | 与进程 Inheritable 与后并入 |
| File Effective | **1 bit**：1 → 新 Effective=新 Permitted；0 → Effective 空（或 Ambient） |

`setcap 'cap_net_raw+ep' ./ping` · `getcap` · `/proc/$$/status` 的 `Cap*`。

## 与 C 语言学习的关系

`fork()` 是 C 语言系统编程的核心。C 语言没有内置的并发原语——`fork` 是 Unix 创建进程的唯一方式。理解 `fork` 的返回值（父返回子 PID，子返回 0）需要扎实的 C 语言指针和返回值概念。

## 常见陷阱

1. **fork 返回值未区分**

```c
pid_t pid = fork();
/* 父子都执行同一代码 */
```

fork 返回两次：父进程返回子 PID，子进程返回 0，失败返回 -1。必须区分三个分支。

2. **fd 继承导致泄漏**

```c
int fd = open(...);
fork();
/* 父子都有 fd，都不关 → 泄漏 */
```

fork 后子进程继承父的 fd 表。父子都需要 close 各自的 fd。

3. **缓冲区被复制**

```c
printf("hello");  /* 在缓冲区，未 flush */
fork();  /* 子进程也会输出 hello */
```

fork 前如果 stdio 缓冲区有数据，子进程会复制并重复输出。fork 前应 fflush 或用 write。

## 自测题

**题目 1（选择）：** `fork()` 在子进程中返回什么？
A. 子进程 PID
B. 0
C. -1
D. 父进程 PID

<details>
<summary>参考答案</summary>

B。子进程中 fork 返回 0，父进程中返回子进程 PID，失败返回 -1。

</details>

**题目 2（判断）：** `fork` 后子进程和父进程的执行顺序是确定的。

<details>
<summary>参考答案</summary>

错误。fork 后父子进程的执行顺序不确定，取决于调度器。不能用 sleep 来保证顺序。

</details>

**题目 3（踩坑）：** 以下代码有什么问题？
```c
printf("before fork\n");
fork();
printf("after fork\n");
```

<details>
<summary>参考答案</summary>

如果 stdout 是行缓冲（终端），"before fork" 会立即输出。但如果是全缓冲（管道/文件），缓冲区被复制，子进程也会输出 "before fork"。fork 前应 fflush(stdout)。

</details>

**题目 4（应用）：** 写代码：fork 一个子进程，父进程打印子 PID，子进程打印自己的 PID。

<details>
<summary>参考答案</summary>

```c
pid_t pid = fork();
if (pid < 0) { perror("fork"); exit(1); }
if (pid == 0) {
    printf("child: %d\n", getpid());
} else {
    printf("parent: child=%d\n", pid);
}
```

</details>
