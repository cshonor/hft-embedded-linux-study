# 39.4 The Modern Capabilities Implementation

> 本章：[TLPI 第 39 章](../README.md)

## 本节讲什么

Linux 2.6.24+ 引入了现代 capabilities 实现：VFS 扩展（文件 capabilities）、`libcap` 库 API、进程和文件 capability 的交互规则。

## 要点

### 进程 capability API

```c
#include <sys/capability.h>

/* 获取进程 capabilities */
cap_t cap_get_proc(void);

/* 设置进程 capabilities */
int cap_set_proc(cap_t cap_p);

/* 获取文件 capabilities */
cap_t cap_get_file(const char *fname);

/* 设置文件 capabilities */
int cap_set_file(const char *fname, cap_t cap_p);

/* 文本 ↔ 内部格式转换 */
char *cap_to_text(cap_t caps, ssize_t *length);
cap_t cap_from_text(const char *str);

/* 释放 */
int cap_free(void *ptr);
```

### libcap 操作流程

```c
/* 1. 获取当前 caps */
cap_t caps = cap_get_proc();

/* 2. 修改 flag */
cap_value_t cap_list[] = { CAP_NET_BIND_SERVICE };
cap_set_flag(caps, CAP_EFFECTIVE, 1, cap_list, CAP_SET);
cap_set_flag(caps, CAP_PERMITTED, 1, cap_list, CAP_SET);

/* 3. 应用到进程 */
cap_set_proc(caps);

/* 4. 释放 */
cap_free(caps);
```

### 文件 capabilities 格式

```bash
# setcap 语法: capability=flags
# flags: e=effective, i=inheritable, p=permitted
setcap cap_net_bind_service=ep ./server
setcap cap_net_raw,cap_net_admin=ep ./tcpdump
```

### securebits 控制

| bit | 名称 | 效果 |
|-----|------|------|
| 1 | SECBIT_NOROOT | root 也需 capabilities |
| 2 | SECBIT_NOROOT_LOCKED | 锁定 NOROOT |
| 4 | SECBIT_NO_SETUID_FIXUP | setuid 不改变 caps |
| 8 | SECBIT_NO_SETUID_FIXUP_LOCKED | 锁定 |

### exec 后 capability 规则

```
文件有 capabilities (setcap):
  P' = (F_inheritable & P_inheritable) | (F_permitted & B)
  E' = F_effective ? P' : ambient_caps
  I' = P_inheritable  (不变)

文件无 capabilities (普通文件):
  若 setuid root:
    P' = B (bounding set)
    E' = P'
    I' = P'
  若普通文件:
    P' = (P_inheritable & ambient) | ambient
    E' = ambient
```

## HFT / 嵌入式关联

- HFT 引擎用 `CAP_NET_BIND_SERVICE` 绑定 80/443 端口，非 root 运行
- 策略沙箱用 `CAP_SYS_NICE` 设置调度策略，不需要其他权限
- 嵌入式设备启动脚本用 `CAP_SYS_TIME` 校准时钟

## 代码示例

```c
#include <sys/capability.h>
#include <stdio.h>
#include <unistd.h>

/* 丢弃所有不必要的能力 */
int drop_capabilities_except(const cap_value_t *keep, int nkeep) {
    cap_t caps = cap_get_proc();
    if (!caps) return -1;

    /* 清除所有 effective 和 permitted */
    cap_clear_flag(caps, CAP_EFFECTIVE);
    cap_clear_flag(caps, CAP_PERMITTED);

    /* 只保留需要的 */
    if (nkeep > 0) {
        cap_set_flag(caps, CAP_EFFECTIVE, nkeep, keep, CAP_SET);
        cap_set_flag(caps, CAP_PERMITTED, nkeep, keep, CAP_SET);
    }

    int ret = cap_set_proc(caps);
    cap_free(caps);
    return ret;
}

int main() {
    cap_t caps = cap_get_proc();
    char *str = cap_to_text(caps, NULL);
    printf("Before: %s\n", str);
    cap_free(str);
    cap_free(caps);

    /* 只保留 NET_BIND_SERVICE */
    cap_value_t keep[] = { CAP_NET_BIND_SERVICE };
    drop_capabilities_except(keep, 1);

    caps = cap_get_proc();
    str = cap_to_text(caps, NULL);
    printf("After:  %s\n", str);
    cap_free(str);
    cap_free(caps);

    return 0;
}
```

## 代码自测

<details>
<summary>为什么建议在程序启动早期就丢弃不必要的 capabilities？</summary>

1. 减少攻击面：丢弃后即使有漏洞也无法执行需要该能力的操作（如加载内核模块）
2. 防止 fork/exec 泄漏：子进程继承 capabilities，尽早丢弃防止扩散
3. 最小权限原则：只保留必要权限，降低漏洞影响范围
4. 不可逆性：通过 Bounding set 限制后，丢弃的能力无法再获取

</details>
