## 本节讲什么

1. wait 不持锁 / 用 `if` 判条件 2. 非持有者 unlock 3. 递归锁 unlock 次数不对

---

## 要点

| 工具 | 职责 |
|------|------|
| mutex | 保护**状态读写** |
| cond | 等待**状态变化** |

1. wait 不持锁 / 用 `if` 判条件  
2. 非持有者 unlock  
3. 递归锁 unlock 次数不对  
4. 多锁无序 → 死锁  
5. 以为 cond「存信号」：wait 前乱 signal 会丢（须在持锁下改谓词再 signal）  

---

## HFT / 嵌入式关联

| 路线 | 要点 |
|------|------|
| 嵌入式 | 明确 mutex（保护状态）与 cond（等状态变化）的职责分工；持锁改谓词再 signal 防丢唤醒 |
| HFT | HFT 多线程最易踩「cond 存信号」的坑——wait 前乱 signal 会丢唤醒；关键路径保证「持锁改状态 → signal」原子性，否则延迟下偶发丢单难查 |

## 代码示例

```c
#include <pthread.h>
#include <stdio.h>
static int count = 0;
pthread_mutex_t lock = PTHREAD_MUTEX_INITIALIZER;
void *worker(void *arg) {
    for (int i = 0; i < 100000; i++) {
        pthread_mutex_lock(&lock);
        count++;
        pthread_mutex_unlock(&lock);
    }
    return NULL;
}
int main(void) {
    pthread_t t1, t2;
    pthread_create(&t1, NULL, worker, NULL);
    pthread_create(&t2, NULL, worker, NULL);
    pthread_join(t1, NULL); pthread_join(t2, NULL);
    printf("count = %d (期望 200000)\n", count);
    return 0;
}
```
