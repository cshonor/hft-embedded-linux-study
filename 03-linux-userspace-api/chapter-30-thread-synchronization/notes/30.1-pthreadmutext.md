## 本节讲什么

pthread_mutex_t mtx = PTHREAD_MUTEX_INITIALIZER;   /* 静态 */ pthread_mutex_init(&mtx, &attr);                   /* 动态 */ pthread_mutex_destroy(&mtx);                       /* 须未持锁 */

---

## 要点

| 概念 | |
|------|--|
| 竞态 | 无保护并发读写，结果依赖调度 |
| 临界区 | 须互斥执行的共享访问代码 |
| mutex | 同一时刻至多一线程进入临界区 |

### 初始化

```c
pthread_mutex_t mtx = PTHREAD_MUTEX_INITIALIZER;   /* 静态 */
pthread_mutex_init(&mtx, &attr);                   /* 动态 */
pthread_mutex_destroy(&mtx);                       /* 须未持锁 */
```

禁止拷贝 mutex；行为未定义。

### API

```c
pthread_mutex_lock / trylock / timedlock / unlock
```

`trylock` 拿不到 → `EBUSY`（正错误码，Pthreads 风格）。

### 类型（attr）

| 类型 | 要点 |
|------|------|
| `NORMAL`（常见默认） | 同线程再 lock → 死锁；乱 unlock → UB |
| `RECURSIVE` | 可嵌套；unlock 次数须匹配 |
| `ERRORCHECK` | 非法操作返回错误；调试用 |
| `ADAPTIVE_NP`（Linux） | 短自旋再睡；短临界区 |

### 死锁

1. 同线程对普通锁二次 lock  
2. 多锁**获取顺序不一致**  

→ **全局统一加锁顺序**。

Demo：[`code/thread_incr_mutex.c`](./code/thread_incr_mutex.c)（对比 Ch29 `thread_race`）

## 与 C 语言学习的关系

Pthreads 是 C 语言多线程编程的标准。`pthread_create` 接收函数指针和 `void*` 参数——这是 C 语言回调模式的核心。线程返回 `void*` 需要 C 语言指针和类型转换的知识。注意 Pthreads 函数返回错误码（而非设置 errno），不能用 perror，要用 strerror。在 HFT 场景中，线程是低延迟并发的基础。

## 常见陷阱

1. **死锁**

```c
pthread_mutex_lock(&a);
pthread_mutex_lock(&b);  /* 如果另一线程先 lock b → 死锁 */
```

多个 mutex 的加锁顺序不一致会导致死锁。所有线程必须按相同顺序加锁。

2. **忘记 unlock**

```c
pthread_mutex_lock(&m);
if (error) return;  /* 没 unlock */
pthread_mutex_unlock(&m);
```

所有代码路径都必须 unlock。用 goto cleanup 或 C++ RAII。

3. **优先级反转**

```c
/* 低优先级线程持有 mutex */
/* 高优先级线程等待 mutex → 被低优先级阻塞 */
```

低优先级线程持有锁时高优先级线程被阻塞。用 PTHREAD_PRIO_INHERIT 或避免在关键路径上加锁。

## 自测题

**题目 1（选择）：** `pthread_mutex_trylock` 返回 EBUSY 表示什么？
A. 系统繁忙
B. mutex 已被其他线程持有
C. mutex 不存在
D. 参数无效

<details>
<summary>参考答案</summary>

B。mutex 已被其他线程持有，trylock 不会阻塞而是立即返回 EBUSY。

</details>

**题目 2（判断）：** 同一个线程可以对同一个 mutex 加锁两次。

<details>
<summary>参考答案</summary>

错误（默认情况下）。普通 mutex 不可重入，同线程第二次 lock 会死锁。需要可重入 mutex 用 PTHREAD_MUTEX_RECURSIVE。

</details>

**题目 3（踩坑）：** 以下代码有什么问题？
```c
pthread_mutex_t m = PTHREAD_MUTEX_INITIALIZER;
pthread_mutex_lock(&m);
/* 处理数据 */
if (error)
    exit(1);
pthread_mutex_unlock(&m);
```

<details>
<summary>参考答案</summary>

error 时直接 exit(1)，没有 unlock mutex。虽然 exit 会终止进程（mutex 随之销毁），但如果改为 return 就会死锁。应养成所有路径都 unlock 的习惯。

</details>

**题目 4（应用）：** 写代码用 mutex 保护一个计数器。

<details>
<summary>参考答案</summary>

```c
pthread_mutex_t m = PTHREAD_MUTEX_INITIALIZER;
int counter = 0;
void increment(void) {
    pthread_mutex_lock(&m);
    counter++;
    pthread_mutex_unlock(&m);
}
```

</details>
