## 本节讲什么

1. xattr 在 inode 上**怎么存**（ext4 的 block/inode 混合布局）；
2. 大小限制到底卡在哪（单值、总量、命名空间开销）；
3. **inode 竞态**为什么同样适用于 xattr——以及 fd 版接口为什么是正解。

---

## 要点：存储布局（以 ext4 为例）

| 位置 | 条件 | 容量 |
|------|------|------|
| inode 内 | 总量小（ext4：`i_inline`/老式 `i_block[15]` 区，约 4KB 内） | 最快，随 inode 一起进 cache |
| 独立数据块 | 总量超出 inode 剩余 | 额外一次块读 |
| inode 外部块（老式 ext2/3 "outer block"） | 历史包袱 | — |

内核侧 `fs/xattr.c` 的通用路径：`setxattr()` → namespace 检查（`xattr_permission()`）→ 具体 FS 的 `->xattr handlers`。

**限制速查**（Linux，FS 相关）：

- 单名字 ≤ 255 字节；单值 ≤ 64 KiB（VFS 层上限，ext4 还受实现约束）；
- 总量 = 所在 FS 的 xattr 空间（ext4 内嵌约 4KB，超了落独立块；tmpfs/overlayfs 支持度不同）；
- 名字本身计入开销（`user.` 前缀 + NUL）。

## 实测：inode 竞态同样适用于 xattr

`stat(path)` 后再 `setxattr(path, ...)`，两次路径解析之间文件可以被换掉——**xattr 会落到对手的新文件上**。正解与 15.1 的 TOCTOU一样：**先 open 拿 fd，用 `fsetxattr(fd, ...)`**：

```text
== ③④ fsetxattr 走 fd + 权限语义（写 user.* 需要文件的写权限）==
  fsetxattr(fd, user.viafd) = 0（fd 版：stat 后文件被换也换不走）
  文件改 0444 后 setxattr(user.hack) = -1 errno=13(Permission denied)
  → user.* 的写权限 = 文件写权限，不是后门。
```

**权限语义实测**：文件 0444 后写 `user.*` → `EACCES`。读/写 xattr 复用文件的读/写权限判定——xattr 不是特权后门。

## 符号链接与 user.*

```text
== ② user.* 与符号链接 ==
  setxattr(链接, user.onlink) = 0 → 不带 follow 抑制时，落在目标文件上
  ⚠️ Linux 上 user.* 根本不允许挂到 symlink 自身（user xattr 只支持
     文件/目录）；要给链接挂东西只能用 system.* 里的个别前缀。
```

（demo 实测为 macOS 路径语义：默认跟随链接、落在目标上；Linux 上对链接设 `user.*` 直接 `EOPNOTSUPP`——两平台结论一致的是：**user.* 与 symlink 自身无缘**。）

## 常见坑

| 坑 | 正解 |
|----|------|
| 以为 xattr 免费、无限 | 单值 64KiB / 总量数 KiB 起步（ext4）；写入前按 `getxattr(NULL)` 探 |
| stat-then-setxattr | TOCTOU。open + fsetxattr |
| 在 NFS/overlayfs 上重度用 xattr | 支持度参差；部署前探测（set 后回读验证） |
| 值里塞结构体不管字节序/版本 | xattr 是裸字节；存版本号 + 定长字段，读侧自校验 |

## HFT / 嵌入式关联

| 场景 | 本节机制怎么兑现 |
|------|----------------|
| 行情数据校验 | checksum/行数存 `user.*`（≤几 KB），校验免读大文件；注意 inode 内 xattr 随 inode 常驻 cache，读开销近零 |
| fd 化管线 | 从 open 到落盘全程用 fd 系接口（fsetxattr），多进程抢文件也不写错对象 |
| 嵌入式 flash | xattr 落独立块 = 额外擦写；高频更新的属性别放 xattr，或接受写放大 |

<details>
<summary>代码自测（Q&A）</summary>

**Q1：xattr 存在哪？读它要几级 IO？**
A：ext4 上小 xattr 在 inode 内（0 额外 IO，随 inode 进 cache）；超限落独立块（+1 块 IO）。所以"小而热"的元数据放 xattr 很划算。

**Q2：写 xattr 需要什么权限？**
A：`user.*`：文件写权限（实测 0444 文件 EACCES）。`security./trusted.`：CAP_SYS_ADMIN。namespace 决定门槛。

**Q3：为什么 fd 版接口重要？**
A：路径版每次调用都重新解析路径，中间可被换（TOCTOU）；fd 版绑死打开时的 inode——与 fstat 同一个道理。

**Q4：Linux 上能给 symlink 挂 user.* 吗？**
A：不能（user xattr 仅支持普通文件/目录，内核直接拒绝）。给链接挂元数据只能走特定 system.* 前缀或换方案。

</details>
