## 本节讲什么

扩展属性（xattr / EA）= **挂在 inode 上的 name=value 键值对**。它回答传统 9 位权限位回答不了的问题：MIME 类型、来源 URL、校验和、App 签名……本节钉住：

1. **namespace 规则**——名字的前缀决定特权门槛，这是 xattr 的宪法；
2. xattr 与普通文件数据的关系（同 inode、同权限模型、**不是绕过权限的后门**）；
3. 与 i-node flags（15.5）的本质区别。

---

## 要点：namespace 规则表（xattr 的宪法）

| namespace | 读 | 写 | 用途 |
|-----------|----|----|------|
| **`user.`** | 文件读权 | 文件写权 | **唯一对非特权进程完全开放的**——应用数据的家 |
| `system.` | 实现/内核解释 | 实现定义 | ACL（`system.posix_acl_access`）、内核功能 |
| `security.` | 读 | `CAP_SYS_ADMIN` | SELinux 标签、`security.capability`（file capabilities） |
| `trusted.` | `CAP_SYS_ADMIN` | `CAP_SYS_ADMIN` | 用户态可信任元数据 |

**实测**（[`code/c16_2_namespaces.c`](../code/c16_2_namespaces.c)，非特权进程逐一试探）：

```text
== ① namespace 特权门槛（非特权进程逐一试探，如实记录）==
  setxattr(user.approved) = 0  OK
  setxattr(system.foo   ) = 0  OK    ← macOS 未强制 Linux 的特权规则
  setxattr(security.foo ) = 0  OK    ← Linux 上应为 EPERM（CAP_SYS_ADMIN）
  setxattr(trusted.foo  ) = 0  OK    ← Linux 上应为 EPERM
  ⚠️ man-pages 的规则是 Linux 的规则；本机 macOS 对这些前缀不强制
     ——namespace 特权是**实现行为**，不是可移植承诺。跨平台程序
     只依赖 user.*，且对 setxattr 的失败一律以返回码为准。
```

## 与相邻机制的区别

| 机制 | 存储粒度 | 解释者 | 典型用途 |
|------|---------|--------|---------|
| 权限位（15.4） | 12 bit | VFS | 访问控制 |
| i-node flags（15.5） | 位标志 | **文件系统** | append-only 等行为开关 |
| **xattr（本节）** | 任意 name=value | **应用** | 自由元数据 |
| 普通文件内容 | 字节流 | 应用 | 数据本体 |

一句话：**xattr 是"inode 上的小数据库"，flags 是"inode 上的行为开关"**。

---

## 常见坑

| 坑 | 正解 |
|----|------|
| 拿 xattr 当 IPC/大数据存储 | xattr 有单值大小与总量限制（§16.2，FS 相关）；大数据进文件、xattr 存指针/校验和 |
| 假设 `trusted.` 写不进去只是权限问题 | Linux 上还需 FS 支持；某些 FS（如 NFS 配置）干脆没有 |
| 用 xattr 绕过文件权限 | 写 `user.*` 就需要文件写权限（16.3 实测 0444 文件 EACCES） |

## HFT / 嵌入式关联

| 场景 | 本节机制怎么兑现 |
|------|----------------|
| 数据血缘 | 行情文件落盘时把「交易所、协议版本、采样时间」写进 `user.*`，读取侧强校验 |
| 固件管理 | 升级包的签名/版本存 `user.*`，与内容解耦、不占文件名 |
| 合规审计 | `security.*` 是 file capabilities 与 SELinux 的家——主机加固清单要盘它 |
| 缓存失效 | 配置文件的 checksum 放 `user.checksum`，避免为校验而多读一遍内容 |

<details>
<summary>代码自测（Q&A）</summary>

**Q1：`user.` namespace 为什么对应用最安全？**
A：特权门槛最低（读写只需文件对应权限）且语义稳定。其他 namespace 的解释权在内核/实现，跨平台/跨 FS 行为不可控。

**Q2：macOS 上设 `security.foo` 成功了，和 man-pages 矛盾吗？**
A：不矛盾——namespace 特权检查是 Linux 的实现行为。macOS 对这些前缀不强制（实测通过）。这正是"只依赖 user.*"的理由。

**Q3：xattr 会跟着文件内容一起被 cp 复制吗？**
A：cp 默认不复制 xattr（`--preserve=xattr` 才行）；tar/rsync 都需要显式选项。备份/迁移流程要专门验证。

</details>
