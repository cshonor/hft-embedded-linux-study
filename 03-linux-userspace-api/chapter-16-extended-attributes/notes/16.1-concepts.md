## 要点

标准 inode 字段固定；**扩展属性（EA）** 附加任意 `key → value`（多为小元数据，非大文件内容替代）。

- 对象：普通文件、目录、链接、设备、FIFO 等（视 FS）  
- 支持：ext4 / XFS / Btrfs / tmpfs 等；**不保证所有 FS** → 处理 `ENOTSUP`  
- 符号链接：默认跟随目标；操作链接本体用 `l*` 系列（FS 对 symlink EA 支持常很弱）

### 键名：`namespace.name`

| 命名空间 | 谁用 | 权限要点 |
|----------|------|----------|
| **`user.*`** | 普通自定义元数据 | 受文件 r/w 权限约束 |
| **`trusted.*`** | 管理员私有 | 仅 root（EUID） |
| **`security.*`** | SELinux、`security.capability` 等 | 多为内核/特权 |
| **`system.*`** | 内核用途；**ACL** 在此（`system.posix_acl_*`） | 普通用户一般不能乱改 |

> POSIX ACL 实质是存在 `system.*` 里的 EA → [Ch17](../chapter-17-access-control-lists/notes.md)。

## 常见陷阱

1. **返回值未检查**

```c
/* 调用后不检查返回值直接继续 */
result = some_call(...);
use(result);  /* 如果失败? */
```

系统调用和库函数的返回值必须检查。失败时通常返回 -1 或 NULL 并设置 errno。不检查会导致后续操作在错误状态下继续。

2. **资源泄漏**

```c
/* 打开资源后在错误路径未释放 */
fd = open(...);
if (error) return;  /* fd 泄漏 */
```

所有分配的资源（fd、内存、锁）在所有代码路径上都必须释放。用 goto cleanup 模式确保清理。

3. **可移植性假设**

```c
/* 假设特定平台行为 */
/* 如假设 int 是 4 字节、指针是 8 字节 */
```

不要硬编码平台相关假设。用 sizeof、stdint.h 类型（uint32_t 等）和 POSIX 宏确保可移植性。

## 自测题

**题目 1（选择）：** 系统调用失败时通常如何报告错误？
A. 打印错误信息
B. 返回 -1 并设置 errno
C. 调用 exit
D. 抛出异常

<details>
<summary>参考答案</summary>

B。系统调用失败时返回 -1 并设置 errno。用 perror 或 strerror(errno) 获取描述。Pthreads 例外，返回错误码。

</details>

**题目 2（判断）：** errno 在函数成功时会被清零。

<details>
<summary>参考答案</summary>

错误。errno 只在失败时被设置，成功时不会清零。不能通过 errno 判断是否出错，必须先检查返回值。

</details>

**题目 3（踩坑）：** 以下代码有什么问题？
```c
if (some_call() < 0) {
    printf("error: %s\n", strerror(errno));
    /* 但中间可能调用了其他函数，errno 被覆盖 */
}
```

<details>
<summary>参考答案</summary>

errno 可能在 strerror 调用前被其他函数覆盖。应该先保存 errno：`int e = errno;` 然后用 strerror(e)。或在 some_call 失败后立即处理。

</details>

**题目 4（应用）：** 写一个错误处理模板：调用系统调用，失败时打印错误并退出。

<details>
<summary>参考答案</summary>

```c
if (some_syscall(args) < 0) {
    perror("some_syscall");
    exit(EXIT_FAILURE);
}
/* 成功继续 */
```

</details>
