# 18.3 Creating and Removing (Hard) Links: link() and unlink() 创建与删除（硬）链接

## 本节讲什么

本节把 §18.1 的概念落成两个 syscall，并把「删除」的真相讲清：

1. `link()` 只是**在目录表里加一行**——所以「复制」「移动」「拷贝内容」这些词全都用错了；
2. `unlink()` 删的也是**目录表里的一行**——所以「删除文件」这个词在 inode 还被 fd 吊住时是**假的**；
3. `nlink == 0 && 没有打开的 fd` 才是真删除，这两个条件缺一不可；
4. 「先 `open` 再 `unlink`」是全 Unix 最优雅的临时文件惯用法——**竞态面为零**。

---

## 要点：两个 syscall 的契约

```c
#include <unistd.h>
int link(const char *oldpath, const char *newpath);
int linkat(int olddirfd, const char *oldpath,
           int newdirfd, const char *newpath, int flags);
int unlink(const char *pathname);
int unlinkat(int dirfd, const char *pathname, int flags);
```

| 规则 | 证据 / 错误码 |
|------|--------------|
| `oldpath` 必须**已存在** | 实测 `ENOENT`（见下） |
| `newpath` 不得存在（不存在「覆盖」语义，那要 `rename`） | `EEXIST` |
| 两者必须在**同一文件系统** | `EXDEV`（硬链接 = 同一 inode 的第二条目录项，inode 换了 FS 就无从谈起） |
| 不能 `link` 目录 | `EPERM` |
| `unlinkat(dirfd, name, AT_REMOVEDIR)` | ≈ `rmdir`（删空目录）；`flags=0` 则 ≈ `unlink` |

## 实测：link → unlink 全生命周期

**完整源码（[`code/c18_1_link_unlink.c`](../code/c18_1_link_unlink.c)）：**

```c
/* c18_1_link_unlink.c — Ch18 §18.1/§18.3：硬链接计数与 unlink 的真实语义
 *
 * 钉住的点（全部实测）：
 *   ① link() = 在目录表里加一条「名字→inode」映射，st_nlink++；
 *      两个名字完全平等，没有"原件/副本"之分；
 *   ② unlink() 删的是**目录项**；st_nlink==0 且无进程持有 fd 才真删；
 *   ③ 「打开后再 unlink」的技巧：fd 继续可读写，close 时内容蒸发
 *      ——临时文件的经典做法（竞态面为零：名字从未存在过）；
 *   ④ 目录不能被 unlink（要 rmdir），且硬链接不能跨文件系统（EXDEV）。
 *
 * 编译： cc -Wall -Wextra -o c18_1_link_unlink c18_1_link_unlink.c
 * 取材： man-pages 6.19 link(2)/unlink(2) + TLPI §18.1/§18.3（Listing 18-1 t_unlink.c）
 */
#include <errno.h>
#include <fcntl.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <sys/stat.h>
#include <unistd.h>

static void nlink_of(const char *tag, const char *path)
{
    struct stat sb;
    if (stat(path, &sb) == -1) { printf("  %-22s (不存在)\n", tag); return; }
    printf("  %-22s st_nlink=%ld\n", tag, (long) sb.st_nlink);
}

int main(void)
{
    const char *a = "/tmp/tlpi_c18_1_a.txt";
    const char *b = "/tmp/tlpi_c18_1_b.txt";
    unlink(a); unlink(b);

    /* ---------- ① 硬链接：两个平等的名字 ---------- */
    printf("== ① link(): 两个名字，一个 inode ==\n");
    int fd = open(a, O_RDWR | O_CREAT | O_EXCL, 0644);
    if (fd == -1) { perror("open"); return EXIT_FAILURE; }
    if (link(a, b) == -1) { perror("link"); return EXIT_FAILURE; }
    nlink_of(a, a);
    struct stat sa, sb;
    stat(a, &sa); stat(b, &sb);
    printf("  %s 与 %s 的 inode 相同? %d（%lu）\n", a, b,
           sa.st_ino == sb.st_ino, (unsigned long) sa.st_ino);
    if (write(fd, "via a\n", 6) != 6) { perror("write"); return EXIT_FAILURE; }
    char buf[64];
    int rfd = open(b, O_RDONLY);
    ssize_t n = read(rfd, buf, sizeof buf);
    printf("  通过 b 读到 %zd 字节（\"%.*s\"）——写 a 读 b，同一份数据\n",
           n, (int) n, buf);
    close(rfd);

    /* ---------- ②③ unlink 与 open 技巧 ---------- */
    printf("\n== ②③ unlink 后 fd 仍可读写，close 即蒸发 ==\n");
    if (unlink(a) == -1) { perror("unlink a"); return EXIT_FAILURE; }
    nlink_of("unlink a 后的 b", b);
    if (write(fd, "still writable\n", 15) != 15) { perror("write2"); return EXIT_FAILURE; }
    if (unlink(b) == -1) { perror("unlink b"); return EXIT_FAILURE; }

    errno = 0;
    int sret = stat(a, &sb);
    printf("  两个名字都没了: stat(a) = %d errno=%d(%s)\n",
           sret, errno, strerror(errno));
    if (lseek(fd, 0, SEEK_SET) == (off_t) -1) { perror("lseek"); return EXIT_FAILURE; }
    n = read(fd, buf, sizeof buf);
    printf("  但 fd 还活着: 读回 %zd 字节（\"%.*s\"）\n", n, (int) n, buf);
    printf("  ⚠️ close(fd) 后内容才真正释放——临时文件先 open 后 unlink，\n");
    printf("     名字从未暴露给其他进程，竞态面为零。\n");

    /* ---------- ④ 目录与跨文件系统 ---------- */
    printf("\n== ④ 边界行为 ==\n");
    errno = 0;
    int r = unlink("/tmp");
    printf("  unlink(/tmp) = %d errno=%d(%s)  ← 目录要走 rmdir\n",
           r, errno, strerror(errno));
    errno = 0;
    r = link("/tmp/tlpi_c18_1_a.txt", "/tmp/x");  /* 源已不存在 */
    printf("  link(不存在的名字) = %d errno=%d(%s)\n", r, errno, strerror(errno));
    printf("  ⚠️ 跨文件系统硬链接 → EXDEV（硬链接是同一 inode 的第二条目录项，\n");
    printf("     inode 换了 FS 就无从谈起）；跨设备请用 symlink（18.5）。\n");

    close(fd);
    return EXIT_SUCCESS;
}
```

实测输出：

```text
== ① link(): 两个名字，一个 inode ==
  /tmp/tlpi_c18_1_a.txt  st_nlink=2
  /tmp/tlpi_c18_1_a.txt 与 /tmp/tlpi_c18_1_b.txt 的 inode 相同? 1（2277499）
  通过 b 读到 6 字节（"via a"）——写 a 读 b，同一份数据

== ②③ unlink 后 fd 仍可读写，close 即蒸发 ==
  unlink a 后的 b      st_nlink=1
  两个名字都没了: stat(a) = -1 errno=2(No such file or directory)
  但 fd 还活着: 读回 21 字节（"via a
still writable"）
  ⚠️ close(fd) 后内容才真正释放——临时文件先 open 后 unlink，
     名字从未暴露给其他进程，竞态面为零。

== ④ 边界行为 ==
  unlink(/tmp) = -1 errno=1(Operation not permitted)  ← 目录要走 rmdir
  link(不存在的名字) = -1 errno=2(No such file or directory)
```

四个钉住的点，按 ①→④：

1. **两个名字完全平等**：`st_nlink=2`、同 inode、写 a 读 b 得到同一份数据。没有「原件/副本」的概念—— inode 才是「文件本体」，名字只是目录表里的行。
2. **`unlink(a)` 之后 `b` 的 `st_nlink` 从 2 变 1**：数据一字节没动，只是目录表少了一行。
3. **名字全没了、`fd` 还活着**：`stat(a)` 已经 `ENOENT`，但那个 fd 还能读出 21 字节（包括 unlink **之后**写入的 15 字节）。**`close(fd)` 才是数据真正蒸发的一刻。**
4. **目录不能 `unlink`**（要走 `rmdir`），且 `link()` 的源必须存在。

```c
/* t_unlink.c

    Demonstrate that, when a file is unlinked, it is not actually removed from
    the file system until after any open descriptors referring to it are closed.

    Usage: t_unlink file
*/
#include <sys/stat.h>
#include <fcntl.h>
#include "tlpi_hdr.h"

#define CMD_SIZE 200
#define BUF_SIZE 1024

int
main(int argc, char *argv[])
{
    int fd, j, numBlocks;
    char shellCmd[CMD_SIZE];            /* Command to be passed to system() */
    char buf[BUF_SIZE];                 /* Random bytes to write to file */

    if (argc < 2 || strcmp(argv[1], "--help") == 0)
        usageErr("%s temp-file [num-1kB-blocks] \n", argv[0]);

    numBlocks = (argc > 2) ? getInt(argv[2], GN_GT_0, "num-1kB-blocks")
                           : 100000;

    /* O_EXCL so that we ensure we create a new file */

    fd = open(argv[1], O_WRONLY | O_CREAT | O_EXCL, S_IRUSR | S_IWUSR);
    if (fd == -1)
        errExit("open");

    if (unlink(argv[1]) == -1)          /* Remove filename */
        errExit("unlink");

    for (j = 0; j < numBlocks; j++)     /* Write lots of junk to file */
        if (write(fd, buf, BUF_SIZE) != BUF_SIZE)
            fatal("partial/failed write");

    snprintf(shellCmd, CMD_SIZE, "df -k `dirname %s`", argv[1]);
    system(shellCmd);                   /* View space used in file system */

    if (close(fd) == -1)                /* File is now destroyed */
        errExit("close");
    printf("********** Closed file descriptor\n");

    /* See the erratum for page 348 at http://man7.org/tlpi/errata/.
       Depending on factors such as random scheduler decisions and the
       size of the file created, the 'df' command executed by the second
       system() call below does may not show a change in the amount
       of disk space consumed, because the blocks of the closed file
       have not yet been freed by the kernel. If this is the case,
       then inserting a sleep(1) call here should be sufficient to
       ensure that the the file blocks have been freed by the time
       of the second 'df' command.
    */

    system(shellCmd);                   /* Review space used in file system */
    exit(EXIT_SUCCESS);
}
```

实测输出：

```text
$ ./t_unlink bigfile 300000          # 先 open，再立刻 unlink，再写 300MB
Filesystem   1024-blocks     Used Available Capacity iused      ifree %iused  Mounted on
/dev/disk3s5   239362496 29504280 184074220    14%  568087 1840742200    0%   /System/Volumes/Data
Filesystem   1024-blocks     Used Available Capacity iused      ifree %iused  0%   /System/Volumes/Data
/dev/disk3s5   239362496 29204292 184374208    14%  568087 1843742080    0%   /System/Volumes/Data
********** Closed file descriptor
```

两次 `df` 的 **Available 从 184074220 → 184374208，释放了 299988 KB ≈ 300 MB**——而这 300 MB 是**在名字已经不存在、文件已经「删完」之后才写进去的**。这就是 `unlink` 语义最直观的证明：`unlink` 只摘名字，不摘数据。

> **顺带一个有意思的输出顺序现象**：`********** Closed file descriptor` 这行 `printf` 出现在**两次 `df` 之后**。原因是 `printf` 走 stdio 的**全缓冲**（stdout 是管道时按块缓冲，程序结束才冲刷），而 `system()` 里的 `df` 直接写到终端（无缓冲）——这不是 bug，是 [13 章 stdio 缓冲](../../chapter-13-file-io-buffering/README.md) 的活教材。

> **另一处诚实标注**：用 `./t_unlink bigfile 5`（5 KB）跑时两次 `df` 只差 8 KB，几乎看不出效果——这正是原书源码注释里那段 erratum 说的「文件太小 / 内核还没把块释放掉，`df` 未必立刻反映」。**用 300 MB 才能让效果肉眼可见。**

## 要点：「先 open 再 unlink」为什么竞态面为零

```c
int fd = open(path, O_RDWR | O_CREAT | O_EXCL, 0600);
unlink(path);            /* 名字从这一刻起不存在于任何目录表 */
/* ... 用 fd 读写 ... */
close(fd);               /* 数据真正释放 */
```

对比传统「`/tmp/myname.pid`」式临时文件：其他进程可以在你 `open` 与 `unlink` 之间**猜到那个名字**并打开/篡改（TOCTOU）。而 `open` 后立刻 `unlink`，**名字存在的窗口只有两条 syscall 之间**，且之后从未有过——攻击面为零。glibc 的 `tmpfile(3)` 内部就是这么做的；`mkstemp` + `unlink` 是它的手动版。

## 常见坑

| 坑 | 正解 |
|----|------|
| 「删除了文件但磁盘没腾出来」 | 两个条件：`nlink==0` **且**无打开 fd。常被一个忘掉的进程（日志程序、`tail -f`）吊着；`lsof +L1` 能找到 |
| 用 `unlink` 删目录 | 不行（实测 `EPERM`）；目录要用 `rmdir`，且只能删**空**目录 |
| 以为 `unlink` 能「覆盖」一个已存在的名字 | `unlink(path)` 后再 `open` 有竞态窗口；要原子替换用 `rename`（§18.4） |
| 想恢复「刚被删的文件」 | 名字没了就是没了；唯一出路是从**还开着它的进程的 fd** 里抢救（`/proc/PID/fd/N`，Linux） |
| `link(old, new)` 期望 `new` 被覆盖 | `EEXIST`；`link` 没有覆盖语义，原子替换是 `rename` 的职责 |
| 跨文件系统 `link` | `EXDEV`；要「跨设备引用」请用符号链接（§18.2 / §18.5） |

## HFT / 嵌入式关联

| 场景 | 本节机制怎么兑现 |
|------|----------------|
| 临时文件零竞态 | 行情回放、落盘中间结果的临时文件一律「`open` + `unlink`」：崩溃时内核自动回收（nlink 已 0 且无 fd），**无需清理脚本** |
| 热更新不掉数据 | 老进程被 `rename` 覆盖后继续跑老 inode（见习题 18-1，`ex18_1_txtbsy.c` 实测）——灰度发布的底层保证 |
| 日志占盘排查 | 「删了 log 磁盘没变大」= 有进程还开着它；运维三板斧 `lsof +L1` / `/proc/*/fd` / 重启该进程 |
| 嵌入式掉电安全 | `unlink` 只动目录表，掉电后 journal 回放要么「名字在」要么「不在」，不会出现半删状态 |
| 硬链接做版本池 | 多版本共享同一数据 inode，`st_nlink` 直接告诉你这份快照被几处引用，统计零成本 |

<summary>代码自测（Q&A）</summary>

**Q1：`unlink` 之后还能从 fd 读到数据吗？**
A：能，而且**能继续写**。实测：unlink 后写入 15 字节，随后从同一 fd 读回 21 字节（含 unlink 前写的 6 字节）。inode 与 fd 的绑定在打开时就定了，`unlink` 只摘目录表里的名字。

**Q2：`st_nlink` 变成 0 的瞬间数据就被释放了吗？**
A：不是。还要**没有任何打开的 fd**。内核对 inode 的引用计数（`i_count`）与链接计数（`i_nlink`）是两个独立的东西；两者都归零，inode 才被回收到空闲表。

**Q3：`link()` 为什么不能跨文件系统？**
A：硬链接的本质是「同一 inode 的第二条目录项」。inode 编号只在**单个文件系统内部**有意义——你不可能在另一个 FS 里「引用」这个 FS 的 inode。所以内核在 `vfs_link()` 里直接 `EXDEV`。

**Q4：`O_EXCL` 在这个惯用法里是必须的吗？**
A：强烈建议。没有它，如果另一个进程恰好已经 `open` 了同一路径，你的 `open` 会拿到**同一个 inode** 的另一个 fd，随后 `unlink` + 写入就把对方的数据搅了。`O_EXCL` 保证「这个 inode 是我刚建的、还没人见过」。

**Q5：怎么在 Linux 上抢救「刚被删但还有进程开着」的文件？**
A：`/proc/PID/fd/N` 是那个 fd 的符号链接，指向「inode 还活着」的对象——可以 `cp` 出来。macOS 没有等价接口（`lsof` 只能告诉你谁开着）。这也是「救援要趁早」的原因：进程一退，fd 关闭，inode 才真正释放。

**Q6：`linkat(AT_FDCWD, ..., AT_EMPTY_PATH)` 能对 fd 建链接吗？**
A：Linux 特有（需要 `CAP_DAC_READ_SEARCH` 或配合 `O_PATH` + `/proc/self/fd/N`），macOS 无此能力。它把「先 open 再 unlink」的惯用法推进到「先 open 再 link 回来」，用于实现可恢复的临时文件。Pi5 复测清单里可以补一条。

</details>
