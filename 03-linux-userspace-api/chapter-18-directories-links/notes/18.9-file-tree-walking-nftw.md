## 本节讲什么

1. `nftw()` = 递归遍历目录树的**标准接口**：递归逻辑、深度限制、先序/后序、链接策略全部由内核/libc 代理；
2. 四个 flag 里 `FTW_DEPTH`（后序）与 `FTW_PHYS`（不跟随链接）是**工程上最常用的一对**——递归删除的固定搭配；
3. 本机实测展示了「不跟随」与「跟随」的**本质区别**：默认模式下，指向目录的符号链接会让**同一棵子树被遍历两次**；
4. `nopenfd`（同时打开的目录数上限）是资源护栏，不是「越大越好」。

## 要点：接口契约

```c
#include <ftw.h>
int nftw(const char *dirpath,
         int (*fn)(const char *fpath, const struct stat *sb,
                   int typeflag, struct FTW *ftwbuf),
         int nopenfd, int flags);
/* 返回：0 = 遍历完；fn 的返回值（非0即提前终止）；-1 = nftw 自身出错 */
```

| `typeflag` | 含义 |
|-----------|------|
| `FTW_F` | 普通文件（或被跟随的链接指向的文件） |
| `FTW_D` | 目录（**先序**：子项还未处理） |
| `FTW_DP` | 目录（**后序**：子项已全部处理，需 `FTW_DEPTH`） |
| `FTW_SL` | 符号链接本身（需 `FTW_PHYS`） |
| `FTW_SLN` | **悬空**符号链接（跟随模式下 `stat` 失败时） |
| `FTW_DNR` | 目录不可读（`opendir` 失败） |
| `FTW_NS` | `stat` 失败（`FTW_NS` 时 `sb` 内容不可信） |

| flag | 效果 | 不给的后果 |
|------|------|-----------|
| `FTW_PHYS` | 不跟随符号链接 | **子树被重复遍历**（本机实测） |
| `FTW_DEPTH` | 后序遍历（目录以 `FTW_DP` 报告） | 无法做递归删除 |
| `FTW_MOUNT` | 不跨文件系统 | 会走进挂载点（如 `/proc`） |
| `FTW_CHDIR` | 进入每层目录再回调 | 路径串更长（与相对路径配合省内存） |

`struct FTW`：`base` = `fpath` 里**文件名**的起始下标；`level` = 相对起点的深度（起点为 0）。

## 实测：FTW_PHYS / FTW_DEPTH 三态对照（[`code/nftw_dir_tree.c`](../code/nftw_dir_tree.c)，Listing 18-3）

测试树：`f.txt`、`real/deep/f.txt`、`linkdir -> real`（指向**目录**的链接）、`dangling -> nowhere`。

```text
######## 默认（跟随符号链接）########
d D    2278244  .
l SLN  2278250      dangling
d D    2278245      real
d D    2278246          deep
- F    2278248              f.txt
- F    2278247      f.txt
d D    2278245      linkdir     ← inode 2278245 == real 的 inode！
d D    2278246          deep
- F    2278248              f.txt   ← 同一棵子树被遍历了第二次

######## -p（FTW_PHYS 不跟随）########
d D    2278244  .
l SL   2278250      dangling    ← 变成 SL（链接本身）
d D    2278245      real
d D    2278246          deep
- F    2278248              f.txt
- F    2278247      f.txt
l SL   2278249      linkdir     ← 自己的 inode 2278249，不再深入

######## -p -d（FTW_PHYS + FTW_DEPTH 后序）########
l SL   2278250      dangling
- F    2278248              f.txt
d DP   2278246          deep      ← 目录以 DP 报告（子项已处理完）
d DP   2278245      real
- F    2278247      f.txt
l SL   2278249      linkdir
d DP   2278244  .               ← 根最后出现
```

三个钉住的点：

1. **默认模式 = 子树被遍历两次**：`linkdir` 显示为 `d D` 且 inode 是 `real` 的 2278245，`real/deep/f.txt` 的 inode 2277248 出现两次。**这不是理论推演，是实测输出**。 implication：统计文件数/大小必须 `FTW_PHYS`，否则重复计数。
2. **`dangling` 的两种待遇**：默认模式下报 `SLN`（`stat` 失败 → 用 `lstat` 兜底识别出「这是悬空链接」）；`FTW_PHYS` 下报 `SL`（压根不 `stat`）。
3. **`FTW_DEPTH` 的后序**：所有目录以 `DP` 出现，且**出现在它所有子项之后**——这正是 `remove()` 递归删除能工作的前提（[18.7](18.7-removing-a-file-or-directory-remove.md)）。

## 实测：习题 18-7 官方解（[`code/file_type_stats.c`](../code/file_type_stats.c)）

```text
$ ./file_type_stats /etc
Total files:         262
Regular:             225   85.9%
Directory:            33   12.6%
Char device:           0    0.0%
Block device:          0    0.0%
Symbolic link:         4    1.5%
FIFO:                  0    0.0%
Socket:                0    0.0%
Non-statable:          0    0.0%
```

它用 `FTW_PHYS`（源码里就是这样），所以符号链接按自身统计（4 个，没有把链接目标重复计入）——与上面第 1 点的结论一致。

## 实测：原书镜像正常运行（[`code/nftw_dir_tree.c`](../code/nftw_dir_tree.c)）

```text
$ mkdir -p tree/sub && touch tree/f1 tree/sub/f2 && ln -sf f1 tree/lnk
$ ./nftw_dir_tree tree
d D    2277899  tree
d D    2277900      sub
- F    2277902          f2
- F    2277901      lnk        ← 没有 FTW_PHYS：链接 f1 被跟随，报成普通文件
- F    2277901      f1
```

注意 `lnk` 被报成 `F`（且 inode 与 `f1` 相同 2277901）——**再次印证**默认模式跟随链接。TLPI 在这里特意提醒：回调里的 `pathname` 可能是**任意长**的路径串（每层都拼接），别假设 `PATH_MAX` 就够。

## 要点：nftw vs 手写递归 readdir

| | `nftw` | 手写 `opendir`+`readdir` 递归 |
|--|--------|------------------------------|
| 递归/深度限制 | 内建（`nopenfd`） | 自己管（栈深度、fd 数） |
| 后序遍历 | `FTW_DEPTH` 一个 flag | 自己调两遍回调 |
| 符号链接策略 | `FTW_PHYS` 一个 flag | 自己判断 `S_ISLNK` + 决定递不递 |
| 跨挂载点 | `FTW_MOUNT` | 自己比 `st_dev` |
| 可控性（剪枝、并行） | 低（回调只能返回 0/非0） | 高 |
| 移植性 | POSIX（但 `FTW_*` 细节有平台差） | 完全可控 |

工程结论：**批量处理/统计/删除用 `nftw`；需要剪枝（按名字跳过子树）、并行、或进度上报时手写**。

## 常见坑

| 坑 | 正解 |
|----|------|
| 统计目录大小/文件数不加 `FTW_PHYS` | 指向目录的链接会让子树被算两遍（本机实测 inode 相同、条目重复） |
| 递归删除只给 `FTW_DEPTH` 忘了 `FTW_PHYS` | 链接指向**外部**文件会被误删；`FTW_DEPTH\|FTW_PHYS` 是固定搭配 |
| 假设回调里 `fpath` 长度 < `PATH_MAX` | 每层拼接，深树 + 长名字会超；需要短路径就用 `FTW_CHDIR` + `ftwbuf->base` |
| `nopenfd` 给很小就以为「省资源」 | 太小会导致 nftw 频繁关闭/重开目录（性能悬崖）；典型值 20~64 |
| 回调返回非 0 以为是「错误码」 | nftw 原样把它返回给调用者（不是 -1）；用它做「提前终止」，真错误要自己另行传递 |
| 在回调里 `chdir` 而没用 `FTW_CHDIR` | 后续回调的相对路径全部错位；要么全程用绝对路径，要么用 flag |
| `FTW_NS` 时直接用 `sb` | `stat` 失败时 `sb` 不可信；先判 `typeflag == FTW_NS` |

## HFT / 嵌入式关联

| 场景 | 本节机制怎么兑现 |
|------|----------------|
| 数据集冷数据归档 | `nftw + FTW_PHYS` 遍历 + 按 mtime 挑文件；`FTW_MOUNT` 防止走进 NFS 挂载点把扫描卡死 |
| 磁盘配额/容量监控 | `file_type_stats` 的模式（`FTW_PHYS` 统计，不重复计数）；周期任务里注意遍历本身的 I/O 开销 |
| 安全清理 | `FTW_DEPTH|FTW_PHYS` 递归删除临时目录；`FTW_PHYS` 是「不误删链接外文件」的唯一保证 |
| 嵌入式镜像打包 | 打包器遍历 rootfs 时必须 `FTW_PHYS`——否则 `/usr/lib/libx.so -> libx.so.1` 会被打包成两份内容 |
| 深目录防炸 | 回调路径串长度不可控；高扇区树（如按 tick 分文件）用 `FTW_CHDIR` + `base` 或干脆手写递归 + `openat`（§18.11） |
| 防环 | 目录树理论上无环（内核禁止目录硬链接），但**链接指向目录**的「逻辑环」由 `FTW_PHYS` 一次性解决 |

<summary>代码自测（Q&A）</summary>

**Q1：为什么默认模式会把「指向目录的链接」当目录遍历？**
A：`nftw` 内部对每个条目先 `stat`（跟随），得到的类型是目录 → 递归进去。这个行为是 POSIX 规定的，不是 bug。`FTW_PHYS` 让它改用 `lstat`，链接就报 `FTW_SL` 并停止下钻。实测 inode 相同（2278245）证明「两个名字、同一 inode」。

**Q2：`FTW_SLN` 和 `FTW_SL` 的区别？**
A：都是链接。`FTW_SL` = 不跟随模式（`FTW_PHYS`）下的链接本身；`FTW_SLN` = 跟随模式下 `stat` **失败**的链接（一般是悬空）。实测：同一棵树里 `dangling` 在默认模式下是 `SLN`，加 `-p` 后变 `SL`。

**Q3：`nopenfd` 给 1 会怎样？**
A：功能正确，但每进入一层目录就要关掉上一层的 DIR（保存位置、重开、seek 回去），性能急剧下降。它是「同时打开目录数」的护栏；给 20~64 通常既能防 fd 耗尽又不触发频繁重开。

**Q4：回调返回 3 会发生什么？nftw 返回什么？**
A：立即停止遍历（剩余子树不访问），`nftw` 把 3 原样返回给调用者。注意与 `-1`（nftw 自身出错）区分。所以「用户自定义错误码」要选非 0、非 -1 的值，或者用全局变量传递。

**Q5：遍历时目录被并发删除会怎样？**
A：`nftw` 用 `lstat`/`opendir` 逐级访问，被删的子树可能报 `FTW_NS`/`FTW_DNR`，也可能正常跳过——**没有一致性保证**。要强一致快照得靠文件系统快照，应用层只能「容忍竞态 + 按错误码分派处理」。

**Q6：`nftw` 能并行化吗？**
A：接口本身串行（一个回调、一个遍历游标）。要并行得手写递归 + 线程池（每个 worker 用 `openat` 锚定自己的子树）。这也是「需要并行就别用 nftw」的根本原因。

</details>
