## 本节讲什么

TLPI 第 18 章的「地基节」。本节回答四个问题：

1. 目录到底是不是文件？它的「内容」是什么？
2. 硬链接的本质是什么？（一句话：**同一 inode 的第二个名字**）
3. 目录的 `r / w / x` 三位为什么含义**完全不同于**普通文件？
4. `st_nlink` 从 2 开始数的是谁？（不是「被链接的次数」）

---

## 要点：目录是「名字 → inode」的映射表

| 普通文件 | 目录 |
|---------|------|
| 数据块存**内容** | 数据块存**目录项**（directory entry）：`(文件名, inode 编号)` |
| `st_size` = 内容字节数 | `st_size` 的含义**由文件系统决定**（见下） |
| `st_nlink` = 被硬链接次数 | `st_nlink` = **2 + 子目录数**（自己 + `.` + 各子目录的 `..`） |

两个方向都可以反过来说：

- **一个 inode 可以有多个名字**（硬链接），但**一个目录项只指向一个 inode**；
- `.` 和 `..` 不是「特殊语法」，它们就是**目录里实实在在的两条目录项**——所以 `..` 能用 `..` 访问，根目录的 `..` 指向自己（防止向上走到表外）。

## 实测：`st_nlink` 的真实算法

**完整源码（[`code/c18_6_mkdir_rmdir.c`](../code/c18_6_mkdir_rmdir.c)）：**

```c
/* c18_6_mkdir_rmdir.c — Ch18 §18.6：mkdir() / rmdir() 的真实语义
 *
 * 钉住的点（全部实测）：
 *   ① mkdir() 的 mode **受 umask 削减**（与 open 同一套规则），
 *      且目录必定带上 x 位才有用（没有 x 连 cd 都进不去）；
 *   ② 目录的 st_nlink 不是「被链接次数」而是 **2 + 子目录数**：
 *      自己一条、"." 一条，每个子目录的 ".." 再各算一条；
 *   ③ rmdir() 只吃**空目录**：非空 ENOTEMPTY、指向文件的 ENOTDIR、
 *      指向目录的**符号链接**也是 ENOTDIR（要用 unlink 删链接本身）；
 *   ④ rmdir(".") / rmdir("..") → EINVAL/EBUSY，内核不许把树上节点摘断；
 *   ⑤ unlinkat(dirfd, name, AT_REMOVEDIR) 是 rmdir 的 *at 版本（§18.11）。
 *
 * 编译： cc -Wall -Wextra -o c18_6_mkdir_rmdir c18_6_mkdir_rmdir.c
 * 取材： man-pages 6.19 mkdir(2)/rmdir(2) + TLPI §18.6
 */
#include <errno.h>
#include <fcntl.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <sys/stat.h>
#include <sys/types.h>
#include <unistd.h>

static void try_mkdir(const char *p, mode_t mode, const char *tag)
{
    errno = 0;
    int r = mkdir(p, mode);
    printf("  %-42s = %d %s\n", tag, r, r == 0 ? "" : strerror(errno));
}

static void try_rmdir(const char *p, const char *tag)
{
    errno = 0;
    int r = rmdir(p);
    printf("  %-42s = %d %s\n", tag, r, r == 0 ? "" : strerror(errno));
}

int main(void)
{
    const char *base = "/tmp/tlpi_c18_6";
    char d[128], sub[160], f[160], lnk[160];
    snprintf(d,   sizeof d,   "%s/d",     base);
    snprintf(sub, sizeof sub, "%s/d/sub", base);
    snprintf(f,   sizeof f,   "%s/d/f",   base);
    snprintf(lnk, sizeof lnk, "%s/d_lnk", base);
    system("rm -rf /tmp/tlpi_c18_6 && mkdir /tmp/tlpi_c18_6");

    /* ---------- ① mode & umask ---------- */
    printf("== ① mkdir 的 mode 受 umask 削减 ==\n");
    mode_t old = umask(0);                       /* 先读出当前 umask */
    umask(old);
    printf("  当前 umask = %04o\n", (unsigned) old);
    try_mkdir(d, 0777, "mkdir(d, 0777)");
    struct stat sb;
    stat(d, &sb);
    printf("  实得 mode = %04o（= 0777 & ~%04o）\n",
           (unsigned) (sb.st_mode & 07777), (unsigned) old);

    /* ---------- ② st_nlink 的算法 ---------- */
    printf("\n== ② 目录的 st_nlink = 2 + 子目录数 ==\n");
    stat(d, &sb);
    printf("  空目录 d          st_nlink = %ld   ← 自己\n",
           (long) sb.st_nlink);
    mkdir(sub, 0755);
    stat(d, &sb);
    printf("  建 d/sub 之后 d   st_nlink = %ld   ← +子目录的 \"..\"\n",
           (long) sb.st_nlink);
    printf("  ⚠️ d/sub 自己的 st_nlink = ");
    stat(sub, &sb);
    printf("%ld（新建空目录恒为 2）\n", (long) sb.st_nlink);

    /* ---------- ③ rmdir 的失败面 ---------- */
    printf("\n== ③ rmdir 只吃空目录 ==\n");
    int fd = open(f, O_WRONLY | O_CREAT | O_EXCL, 0644);
    if (fd == -1) { perror("open"); return EXIT_FAILURE; }
    close(fd);
    try_rmdir(d, "rmdir(非空 d)");
    try_rmdir(f, "rmdir(普通文件)");
    symlink(d, lnk);
    try_rmdir(lnk, "rmdir(指向目录的符号链接)");
    printf("  → 删链接本身请用 unlink；rmdir 只跟到底层对象的类型\n");

    try_rmdir(".", "rmdir(\".\")");
    try_rmdir("..", "rmdir(\"..\")");

    /* ---------- ④ *at 版本 ---------- */
    printf("\n== ④ unlinkat(AT_REMOVEDIR) == rmdir ==\n");
    int dfd = open(d, O_RDONLY | O_DIRECTORY);
    if (dfd == -1) { perror("open dir"); return EXIT_FAILURE; }
    char *slash = strrchr(f, '/');
    errno = 0;
    int r = unlinkat(dfd, slash + 1, 0);              /* 0 = 删文件 */
    printf("  unlinkat(dfd, \"%s\", 0)             = %d %s\n",
           slash + 1, r, r == 0 ? "" : strerror(errno));
    errno = 0;
    r = unlinkat(dfd, "sub", AT_REMOVEDIR);           /* 删空目录 */
    printf("  unlinkat(dfd, \"sub\", AT_REMOVEDIR)   = %d %s\n",
           r, r == 0 ? "" : strerror(errno));
    close(dfd);

    /* ---------- ⑤ mkdir 的存在/父目录检查 ---------- */
    printf("\n== ⑤ mkdir 的前置检查（都是内建原子性，不是先 stat 再建）==\n");
    try_mkdir(d, 0755, "mkdir(已存在的 d)");
    try_mkdir("/tmp/tlpi_c18_6/no/such/parent", 0755, "mkdir(父目录不存在)");

    /* 清理 */
    unlink(lnk);
    try_rmdir(d, "rmdir(空 d)  ← 现在可以了");
    rmdir(base);
    return EXIT_SUCCESS;
}
```

实测输出：

```text
== ② 目录的 st_nlink = 2 + 子目录数 ==
  空目录 d          st_nlink = 2   ← 自己
  建 d/sub 之后 d   st_nlink = 3   ← +子目录的 ".."
  ⚠️ d/sub 自己的 st_nlink = 2（新建空目录恒为 2）
```

交叉验证：本机 `stat("/tmp")` 实测 `st_nlink=61`（`/tmp` 里有 59 个子目录）——**目录的 nlink 永远能被「子目录个数」解释**，跟这个目录里有多少普通文件无关。

## 要点：目录的 `r / w / x` 是三件完全不同的事

| 位 | 普通文件 | 目录 |
|----|---------|------|
| `r` | 读内容 | **列出**目录项（见得到名字） |
| `x` | 执行 | **穿过 / 解析路径**（访问内部文件必备） |
| `w` | 写内容 | **增删改名**目录项（`mkdir` / `unlink` / `rename` 都要它） |

最反直觉的组合是「**只有 `r` 没有 `x`**」：能 `ls` 看到所有名字，却**打不开其中任何一个**（路径解析停在中间那一级）。反过来「只有 `x` 没有 `r`」：名字看不到，但**如果你已经知道确切路径**，照样能 `open` ——这正是 `chmod 711 $HOME` 的原理（别人进得来、列不出来）。

## 实测：目录 `st_size` 是「文件系统私有」的（探测程序，未入 `code/`）

```text
dir /tmp:         st_size=1952 st_nlink=61 min_bsize=4096
dir /Users/a0000: st_size=960
--- readdir on APFS (macOS) ---
  .    d_type=4  (DIR)  d_ino=2277962  d_reclen=32
  ..   d_type=4  (DIR)  d_ino=2163188  d_reclen=32
  ll   d_type=10 (LNK)  d_ino=2277965  d_reclen=32
```

**跨平台要点**：Linux 的 ext4 / tmpfs 上目录 `st_size` 总是**块大小的整数倍**（新建空目录 4096），而 APFS 实测是 1952 / 960 这类**非块对齐的真实字节数**。结论：**任何拿目录 `st_size` 做「目录内容大小」估算的代码都是错的**——跨平台更错。要真算大小只能 `nftw()` 累加（见 §18.9）。

## 常见坑

| 坑 | 正解 |
|----|------|
| 拿目录 `st_size` 当「目录内容大小」 | `st_size` 是文件系统私有实现细节（APFS 实测 1952 ≠ 4096 倍数）；要算大小用 `nftw` 累加 |
| 以为 `.` / `..` 是 shell 语法 | 它们是**目录项**；没有它们（如某些挂载选项下）`cd ..` 就走不通 |
| 给目录 `chmod 644` 以为只是「不让写」 | 去掉 `x` 后**整棵子树都访问不了**；目录权限的最低配置是 `700` / `755` |
| 以为 `st_nlink` 从 1 开始 | 目录从 **2** 开始（`.` + 自己），每多一个子目录 +1 |
| 硬链接「复制了一份文件」 | 没有复制任何数据字节——只是目录表里多了一行指向同一 inode |

## HFT / 嵌入式关联

| 场景 | 本节机制怎么兑现 |
|------|----------------|
| 目录权限即安全边界 | 行情/日志目录给 `750`：服务组能读能进，其他人**连名字都看不到**（`x` 缺失时 `ls` 报 `Permission denied`） |
| 目录项即缓存键 | 内核 `dcache` 缓存的就是「名字→inode」这条映射；海量小文件目录（如按 tick 分文件）会撑爆 dentry 缓存——**分桶目录**是标准缓解手段 |
| 硬链接省空间 | 同一批行情快照的多份视图用硬链接（同一 inode），`cp -al` 式快照零数据拷贝 |
| 嵌入式只读根 | 只读 squashfs 上目录 `st_size` 又是另一套值——任何依赖它的逻辑在固件上必翻车 |

<details>
<summary>代码自测（Q&A）</summary>

**Q1：目录和普通文件在内核层面差在哪？**
A：都是 inode + 数据块。差别在数据块的**解释方式**：目录块被内核解析成 `(文件名, inode#)` 的定长/变长记录表（ext4 用 `ext4_dir_entry_2`），而普通文件块是裸字节。`S_ISDIR(st_mode)` 只是给了你一个「该怎么解释」的提示。

**Q2：为什么目录的 `st_nlink` 最小是 2？**
A：目录自己被父目录引用一次，再被自己的 `.` 引用一次。每新增一个子目录，那个子目录的 `..` 又引用它一次，所以 +1。实测：空目录 2 → 建一个子目录变 3。

**Q3：只有 `r` 没有 `x` 的目录，到底能干什么？**
A：能 `readdir` 列出名字，不能解析路径进到里面的文件（`open` 报 `EACCES`）。所以「能看到名字」和「能访问内容」是两个独立权限。

**Q4：APFS 上目录 `st_size=1952`，Linux 上为什么总是 4096 的倍数？**
A：ext4 的目录按块组织，`i_size` 随块分配增长；APFS 的目录是 B-tree 记录，`st_size` 反映的是记录流的实际字节数。**结论别依赖**：目录大小从来不是 API 承诺过的量。

**Q5：`ls` 和 `ls -l` 对目录权限的要求一样吗？**
A：不一样。`ls` 只需 `r`（列名字）；`ls -l` 要 `r + x`（还要对每个条目 `stat`，得能穿过目录）。实测上「只有 `r`」的目录 `ls` 正常、`ls -l` 报权限错。

</details>
