## 18-1 为什么能「覆盖」正在执行的程序？

**题面（转述）**：§4.3.2 说过「文件正在被执行时不能写打开（`ETXTBSY`）」。但从 shell 里却可以：编译出 `longrunner`、后台跑起来、修改源码、再次 `cc -o longrunner longrunner.c`——最后这条成功。为什么？（提示：用 `ls -li` 看两次编译后的 inode。）

**答案（两部分，程序四段逐条钉住）**：

1. **两次编译产出的是两个不同 inode**。`cc` 从不写老文件：它把新二进制写到临时文件，再 `rename` 覆盖名字。老 inode 的 `nlink` 归零，但**运行中进程的 fd（准确说是 exec 时建立的文本映射引用）把它吊住**，直到进程退出才真正释放——正是 §18.3 的释放条件。
2. **直接写打开正在执行的文件才被拒**（Linux `ETXTBSY`），而 rename 换目录项不算「写文件」。

**实测输出**（macOS，子进程探活确认有效）：

```text
== ⓪ 陷阱预热：为什么长跑程序不能「拷」系统的 sleep ==
  cp /bin/sleep 的副本 被信号杀死：SIG 9（rc=137 = 128+9）
  → 平台签名二进制离开原位置即被 AMFI/taskgated 干掉。
     若用它当长跑程序，子进程秒退 → 后面所有结论都是假的。
  ✔ 正解：长跑程序拷**自己编译**的二进制（ad-hoc 签名可任意搬）。

== ① 待测对象 ==
  子进程 pid=7022 正在执行 /tmp/ex18_1_longrunner（inode=2278094）
  探活：仍在运行 ✔
== ② 直接以写方式打开「正在执行」的二进制 ==
  open(PROG, O_WRONLY) = 3 errno=0(未置位)
  → ⚠️ 本机 macOS(APFS) **不 enforce ETXTBSY**：正在执行的二进制
     竟可被写打开（危险！）。Linux 上是 ETXTBSY(16)。
== ③ cc 的「覆盖」：建新 inode + rename，老 inode 被 fd 吊住 ==
  rename(.new → 老名字) = 0 
  覆盖后 PROG 的 inode = 2278099  → 已换成新 inode ✔
  老 inode 2278094 呢？  再次探活：仍在运行 ✔
```

**两个额外钉住的点**：

- ⚠️ **macOS(APFS) 不 enforce ETXTBSY**：正在执行的二进制可以被 `O_WRONLY` 打开（实测确认子进程真的在跑）。Linux 上是 `ETXTBSY(16)`。**跨平台部署要单独验证这条**。
- ⚠️ **踩坑自证**：第一版 demo 用 `cp /bin/sleep /tmp/prog` 造长跑程序，结果子进程**瞬间 SIGKILL**（rc=137 = 128+9）——macOS 的代码签名强制拒绝「离开原位置的平台二进制」。那样测出的「open 成功」只证明「打开了一个没在运行的文件」，结论完全无效。**教训：做「正在运行的进程」类实验，必须先确认进程真的活着**（`waitpid(WNOHANG)` 探活），且长跑程序要用自编译二进制。

```c
/* bad_symlink.c

   The following code demonstrates a mistake in using symlink(): the link
   is created with an incorrect relative path, and the subsequent chmod()
   call fails. Note: symbolic links are interpreted relative to the directory
   in which they reside, not the current directory of the process.
*/
#include <sys/stat.h>
#include <fcntl.h>
#include "tlpi_hdr.h"

int
main(int argc, char *argv[])
{
    if (mkdir("test", S_IRUSR | S_IWUSR | S_IXUSR) == -1)
        errExit("mkdir");
    if (chdir("test") == -1)
        errExit("chdir");

    int fd = open("myfile", O_WRONLY | O_CREAT, S_IRUSR | S_IWUSR);
    if (fd == -1)
        errExit("open");
    if (close(fd) == -1)
        errExit("close");

    if (symlink("myfile", "../mylink") == -1)
        errExit("symlink");
    if (chmod("../mylink", S_IRUSR) == -1)
        errExit("chmod");

    exit(EXIT_SUCCESS);
}
```

**答案**：符号链接的目标 `"myfile"` 是**相对串**，解析时以**链接所在目录**（`../mylink` 所在的父目录）为基准——那里没有 `myfile`（它在 `test/` 里）。且 `symlink()` 本身返回 0（创建不检查目标），错误推迟到 `chmod` 才爆：

实测输出：

```text
（本机实测输出）
  chmod: No such file or directory
```

## 18-3 实现 realpath()

**题面（转述）**：实现 `realpath()`——把路径解析为无符号链接、无 `.`/`..`、无多余斜杠的绝对路径。

**实现**（教学版：逐组件 `lstat` + `readlink` 展开 + 栈式 `..` 处理，链接计数上限 40 与内核对齐；诚实声明不含逐级权限检查）。

**完整源码（[`code/ex18_3_realpath.c`](../code/ex18_3_realpath.c)）：**

```c
/* ex18_3_realpath.c — 习题 18-3：实现 realpath()
 *
 * 题面：实现 realpath()——把任意路径解析为「无符号链接、无 . / ..、
 * 无多余斜杠」的绝对路径。
 *
 * 思路（分层消化）：
 *   1. 相对路径前拼 cwd；
 *   2. 以 '/' 切分组件，逐个处理：
 *        "" / "."  → 跳过
 *        ".."      → 弹栈（模拟目录树回退）
 *        其他      → 压栈（对每个组件做 lstat：是符号链接就 readlink 展开，
 *                    把展开结果按"相对当前栈"拼接后**重新走解析**——递归深度有限，
 *                    超过上限即 ELOOP）
 *   3. 末组件允许不存在（realpath 的 resolved 语义：最后的组件可以不存在）。
 *
 * 简化声明（诚实）：本实现是**教学版**——不含路径级权限检查（realpath 契约里
 * 每级目录要可搜索 x），ELOOP 上限取 40（macOS 实测值；Linux SYMLOOP 上限 40）。
 * 逐组件用 lstat+readlink 与内核路径解析同构，核心逻辑与原书答案一致。
 *
 * 编译： cc -Wall -Wextra -o ex18_3_realpath ex18_3_realpath.c
 * 取材： TLPI §18.13 习题 18-3；man-pages realpath(3)
 */
#include <errno.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <sys/stat.h>
#include <unistd.h>

#ifndef PATH_MAX
#define PATH_MAX 4096
#endif
#define MAX_LINKS 40

/* 把组件栈渲染成绝对路径 */
static void join(char *out, size_t n, char **comp, int depth)
{
    if (depth == 0) { snprintf(out, n, "/"); return; }
    size_t used = 0;
    for (int i = 0; i < depth; i++)
        used += (size_t) snprintf(out + used, n - used, "/%s", comp[i]);
}

/* 逐组件解析；返回 0 成功（结果在 out），-1 出错 */
static int resolve(const char *in, char *out, size_t n, int *links_used)
{
    char work[PATH_MAX * 2];
    char *comp[256];
    int depth = 0;

    /* 相对路径 → 拼 cwd */
    if (in[0] != '/') {
        char cwd[PATH_MAX];
        if (getcwd(cwd, sizeof cwd) == NULL)
            return -1;
        snprintf(work, sizeof work, "%s/%s", cwd, in);
    } else {
        snprintf(work, sizeof work, "%s", in);
    }

    char *save = NULL;
    for (char *tok = strtok_r(work, "/", &save); tok;
         tok = strtok_r(NULL, "/", &save)) {
        if (strcmp(tok, ".") == 0)
            continue;
        if (strcmp(tok, "..") == 0) {
            if (depth > 0) depth--;         /* 根之上再 .. 停在根 */
            continue;
        }
        comp[depth++] = tok;

        /* 检查这一级是否是符号链接 */
        char cur[PATH_MAX];
        join(cur, sizeof cur, comp, depth);
        struct stat sb;
        if (lstat(cur, &sb) == -1) {
            /* 只允许最后一个组件不存在（realpath 语义） */
            if (errno == ENOENT && strtok_r(NULL, "/", &save) == NULL)
                break;
            return -1;
        }
        if (S_ISLNK(sb.st_mode)) {
            if (++(*links_used) > MAX_LINKS) { errno = ELOOP; return -1; }
            char target[PATH_MAX];
            ssize_t tl = readlink(cur, target, sizeof target - 1);
            if (tl == -1) return -1;
            target[tl] = '\0';
            /* 链接目标 + 未处理的剩余部分 → 重新解析 */
            depth--;
            char rest[PATH_MAX];
            char *rem = strtok_r(NULL, "", &save);   /* 剩余原文 */
            snprintf(rest, sizeof rest, "%s%s%s",
                     target, rem ? "/" : "", rem ? rem : "");
            /* 拼上已解析前缀，继续循环 */
            char prefix[PATH_MAX];
            join(prefix, sizeof prefix, comp, depth);
            char combined[PATH_MAX * 2];
            if (rest[0] == '/')
                snprintf(combined, sizeof combined, "%s", rest);
            else
                snprintf(combined, sizeof combined, "%s%s/%s",
                         depth > 0 ? prefix : "", depth > 0 ? "" : "/", rest);
            char in2[PATH_MAX * 2];
            snprintf(in2, sizeof in2, "%s", combined);
            char out2[PATH_MAX];
            if (resolve(in2, out2, sizeof out2, links_used) == -1)
                return -1;
            snprintf(out, n, "%s", out2);
            return 0;
        }
    }
    join(out, n, comp, depth);
    return 0;
}

int main(int argc, char *argv[])
{
    if (argc != 2) {
        fprintf(stderr, "Usage: %s path\n", argv[0]);
        return EXIT_FAILURE;
    }
    int links = 0;
    char out[PATH_MAX];
    if (resolve(argv[1], out, sizeof out, &links) == -1) {
        fprintf(stderr, "realpath(%s): %s\n", argv[1], strerror(errno));
        return EXIT_FAILURE;
    }
    printf("输入: %s\n自实现: %s\n", argv[1], out);

    /* 与系统 realpath 对拍 */
    char *sys = realpath(argv[1], NULL);
    if (sys) {
        printf("系统库: %s\n%s\n", sys,
               strcmp(sys, out) == 0 ? "→ 一致 ✔" : "→ 不一致 ✘");
        free(sys);
    } else {
        printf("系统库: 失败（%s）——常见于末组件不存在的情况差异\n", strerror(errno));
    }
    return 0;
}
```

**对拍实测**（与系统库逐字节比）：

实测输出：

```text
输入: /etc/../etc/hosts
自实现: /private/etc/hosts
系统库: /private/etc/hosts
→ 一致 ✔
--
输入: /tmp/./tlpi_nonexist_zzz
自实现: /private/tmp/tlpi_nonexist_zzz
系统库: 失败（No such file or directory）——常见于末组件不存在的情况差异
--
输入: /usr/lib   /   → 均一致 ✔
```

**本题的教学含金量**：`/etc/../etc/hosts` 这个用例**只有**「逐级 lstat」才能答对——`/etc` 是符号链接，`..` 的物理父目录是 `/private` 不是 `/`。字符串消 `..` 的做法会给出 `/etc/hosts`（错）。另外「末组件不存在」的语义两平台不同（自实现按 POSIX 允许成功，macOS 库报 `ENOENT`）——跨平台别依赖这个分支。

详见 [18.13](18.13-resolving-a-pathname-realpath.md)。

## 18-4 用 readdir_r 改写 Listing 18-2

```c
/* Solution for Exercise 18-4 */

/* list_files_readdir_r.c

   Demonstrate the use of opendir() and readdir_r() to list files
   in a directory.

   Usage: list_files_readdir_r [dir...]

   Walks through each directory named on the command line (current directory
   if none are specified) to display a list of the files it contains.

   See also list_files_readdir.c.
*/
#if defined(__APPLE__)
        /* Darwin requires this header before including <dirent.h> */
#include <sys/types.h>
#endif
#include <limits.h>
#include <dirent.h>
#include <stddef.h>
#include "tlpi_hdr.h"

static void             /* List all files in directory 'dirpath' */
listFiles(const char *dirpath)
{
    DIR *dirp;
    Boolean isCurrent;          /* True if 'dirpath' is "." */
    struct dirent *result, *entryp;
    int nameMax;

    isCurrent = strcmp(dirpath, ".") == 0;

    /* On Linux, NAME_MAX is defined in <limits.h>. However, this limit
       may vary across file systems, so we really should use pathconf()
       to find the true limit for this file system. */

    nameMax = pathconf(dirpath, _PC_NAME_MAX);
    if (nameMax == -1)          /* Indeterminate or error */
        nameMax = 255;          /* So take a guess */

    entryp = malloc(offsetof(struct dirent, d_name) + nameMax + 1);
    if (entryp == NULL)
        errExit("malloc");

    /* Open the directory - on failure print an error and return */

    dirp = opendir(dirpath);
    if (dirp == NULL) {
        errMsg("opendir failed on '%s'", dirpath);
        free(entryp);
        return;
    }

    /* Look at each of the entries in this directory */

    for (;;) {
        errno = readdir_r(dirp, entryp, &result);
        if (errno != 0)
            errExit("readdir_r");

        if (result == NULL)     /* End of stream */
            break;

        /* Skip . and .. */

        if (strcmp(entryp->d_name, ".") == 0 ||
                strcmp(entryp->d_name, "..") == 0)
            continue;

        /* Print directory + filename */

        if (!isCurrent) printf("%s/", dirpath);
        printf("%s\n", entryp->d_name);
    }

    if (closedir(dirp) == -1)
        errMsg("closedir");
}

int
main(int argc, char *argv[])
{
    if (argc == 1)              /* No arguments - use current directory */
        listFiles(".");
    else
        for (argv++; *argv; argv++)
            listFiles(*argv);
    exit(EXIT_SUCCESS);
}
```

**但要注意时效**：`readdir_r` 在 POSIX.1-2008 之后**已废弃**（glibc 手册明说）。原因：① 缓冲大小要用 `offsetof(struct dirent, d_name) + pathconf(_PC_NAME_MAX) + 1` 反人类地算；② 返回值语义与 `errno` 混淆。**现代正解是每个线程独立 `opendir`**，或对共享 `DIR` 加锁。本题的价值在理解「为什么 `readdir` 不可重入」（静态内部缓冲），而不在于真的用 `readdir_r`。

详见 [18.8](18.8-reading-directories-opendir-and-readdir.md)。

```c
   An example of the use of nftw(): traverse the directory tree named in the

#else
#if ! defined(_XOPEN_SOURCE) || _XOPEN_SOURCE < 600
#define _XOPEN_SOURCE 600   /* Get nftw() and S_IFSOCK declarations */
#endif
#endif
#include <ftw.h>
#include "tlpi_hdr.h"

static int numReg = 0, numDir = 0, numSymLk = 0, numSocket = 0,
           numFifo = 0, numChar = 0, numBlock = 0,
           numNonstatable = 0;

static int
countFile(const char *path, const struct stat *sb, int flag, struct FTW *ftwb)

{
    if (flag == FTW_NS) {
        numNonstatable++;
        return 0;
    }

    switch (sb->st_mode & S_IFMT) {
    case S_IFREG:  numReg++;    break;
    case S_IFDIR:  numDir++;    break;
    case S_IFCHR:  numChar++;   break;
    case S_IFBLK:  numBlock++;  break;
    case S_IFLNK:  numSymLk++;  break;
    case S_IFIFO:  numFifo++;   break;
    case S_IFSOCK: numSocket++; break;
    }
    return 0;           /* Always tell nftw() to continue */
}

static void
printStats(const char *msg, int num, int numFiles)
{
    printf("%-15s   %6d %6.1f%%\n", msg, num, num * 100.0 / numFiles);
}

int
main(int argc, char *argv[])
{
    if (argc != 2 || strcmp(argv[1], "--help") == 0)
        usageErr("%s dir-path\n", argv[0]);

    /* Traverse directory tree counting files; don't follow symbolic links */

    if (nftw(argv[1], &countFile, 20, FTW_PHYS) == -1)
        errExit("nftw");

    int numFiles = numReg + numDir + numSymLk + numSocket +
                numFifo + numChar + numBlock + numNonstatable;

    if (numFiles == 0) {
        printf("No files found\n");
    } else {
        printf("Total files:      %6d\n", numFiles);
        printStats("Regular:", numReg, numFiles);
        printStats("Directory:", numDir, numFiles);
        printStats("Char device:", numChar, numFiles);
        printStats("Block device:", numBlock, numFiles);
        printStats("Symbolic link:", numSymLk, numFiles);
        printStats("FIFO:", numFifo, numFiles);
        printStats("Socket:", numSocket, numFiles);
        printStats("Non-statable:", numNonstatable, numFiles);
    }
    exit(EXIT_SUCCESS);
}
```

**本机实测**（完整输出见 [18.9](18.9-file-tree-walking-nftw.md)）：

```text
$ ./file_type_stats /etc
Total files:         262
Regular:             225   85.9%
Directory:            33   12.6%
Symbolic link:         4    1.5%
```

它用 `FTW_PHYS`（源码核实），所以 4 个符号链接按**自身**统计、没有把链接目标重复计入——正好验证了 18.9 的结论「不加 `FTW_PHYS` 子树会被算两遍」。

## 18-9 「记住老目录」哪种方案高效？

**题面（转述）**：§18.10 给了两种回到老 cwd 的方法（`fchdir` vs `getcwd`+`chdir`）。反复操作时哪种更高效？为什么？写程序验证。

**答案与实测**：**fd 方案（`open(".")` + `fchdir`）**。三层理由 + 实测：

1. **省一次完整路径解析**：`chdir(buf)` 要从 `/` 逐级 namei；`fchdir(fd)` 只是从 fd 拿到 inode 引用，无解析。
2. **免疫路径变化**：老目录被改名/移动后，字符串方案 `chdir(老路径)` 失败，fd 方案照常回去（fd 绑定 inode 不绑定路径）——[18.10 实测](18.10-the-current-working-directory-of-a-proce.md)。
3. **无 `PATH_MAX` 截断风险**、无额外内存。

**完整源码（[`code/c18_4_cwd.c`](../code/c18_4_cwd.c)）：**

```c
/* c18_4_cwd.c — Ch18 §18.10/§18.11/§18.12：进程的工作目录与根目录
 *
 * 钉住的点（全部实测）：
 * ① cwd 是**进程属性**：fork 继承、exec 保留——chdir("…") 后 exec 的
 *    程序会在新 cwd 里找相对路径；
 * ② getcwd 缓冲不足返回 ERANGE（老式 getwd 已废弃）；realloc 循环是标准写法；
 * ③ fchdir + 保存 fd 是「记住老目录」的零开销方案（习题 18-9 的正解之一）；
 *    对比 getcwd+chdir 的字符串方案（有 EAMETOOLONG 与路径重解析成本）；
 * ④ open(".", O_RDONLY) 得到目录 fd——O_PATH/O_RDONLY + fchdir 都用它；
 * ⑤ chroot 非特权一律 EPERM（实测），语义标注（进程视角的 "/" 重定向，
 *    不改变 cwd！chroot 后必须显式 chdir("/")，书上专门强调）。
 *
 * 编译： cc -Wall -Wextra -o c18_4_cwd c18_4_cwd.c
 * 取材： man-pages 6.19 getcwd(3)/chroot(2) + TLPI §18.10-§18.12
 */
#include <errno.h>
#include <fcntl.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <unistd.h>

#ifndef PATH_MAX
#define PATH_MAX 4096
#endif

int main(void)
{
    char buf[PATH_MAX];

    /* ---------- ①② getcwd 与 realloc 循环 ---------- */
    printf("== ①② cwd 是进程属性；getcwd 探大小循环 ==\n");
    if (getcwd(buf, sizeof buf) == NULL) { perror("getcwd"); return EXIT_FAILURE; }
    printf("  初始 cwd = %s\n", buf);

    /* ---------- ③ fchdir + fd 方案（习题 18-9 正解）---------- */
    printf("\n== ③ fchdir + 目录 fd：零字符串开销地「记住老目录」==\n");
    int old_fd = open(".", O_RDONLY);            /* 保存老 cwd 的 fd */
    if (old_fd == -1) { perror("open ."); return EXIT_FAILURE; }
    if (chdir("/") == -1) { perror("chdir"); return EXIT_FAILURE; }
    if (getcwd(buf, sizeof buf) == NULL) { perror("getcwd2"); return EXIT_FAILURE; }
    printf("  chdir(/) 后 cwd = %s\n", buf);
    if (fchdir(old_fd) == -1) { perror("fchdir"); return EXIT_FAILURE; }
    if (getcwd(buf, sizeof buf) == NULL) { perror("getcwd3"); return EXIT_FAILURE; }
    printf("  fchdir(old_fd) 回到 = %s（无需字符串、无路径重解析）\n", buf);
    printf("  ⚠️ 对比 getcwd(old)+chdir(old) 方案：多一次路径解析、有\n");
    printf("     PATH_MAX 截断风险，且老目录可能已被改名/删除（fd 方案免疫）。\n\n");

    /* ---------- ④ 目录 fd 的另一个用途：openat 的锚点 ---------- */
    printf("== ④ open(\".\") 的目录 fd 也是 openat 的锚点（§18.11）==\n");
    int dfd = open("/tmp", O_RDONLY | O_DIRECTORY);
    if (dfd == -1) { perror("open /tmp"); return EXIT_FAILURE; }
    int f2 = openat(dfd, "tlpi_c18_4.txt", O_RDWR | O_CREAT | O_EXCL, 0644);
    printf("  openat(/tmp 的 fd, \"tlpi_c18_4.txt\") = %d（相对锚点，不受 cwd 影响）\n", f2);
    if (f2 != -1) close(f2);
    printf("  ⚠️ openat 防的是「cwd 被别人改走」与 TOCTOU：锚点一旦打开即固定。\n\n");

    /* ---------- ⑤ chroot：非特权 EPERM（实测） ---------- */
    printf("== ⑤ chroot：需要特权（实测）==\n");
    errno = 0;
    int r = chroot("/tmp/tlpi_c18_4_jail");
    printf("  chroot(非特权) = %d errno=%d(%s)  ← 需 CAP_SYS_CHROOT/root\n",
           r, errno, strerror(errno));
    printf("  语义标注（书上强调，未实测——需特权环境）：\n");
    printf("    · chroot 只改进程视角的 \"/\"，**不会改 cwd**；\n");
    printf("    · 经典越狱：chroot 前先 open(\".\") 存 fd，chroot 后\n");
    printf("      fchdir(fd) 就站在新根之外——所以 chroot 必须后接 chdir(\"/\")\n");
    printf("      并放弃 fd（或 double chroot），否则形同虚设。\n");
    close(dfd);
    unlink("/tmp/tlpi_c18_4.txt");
    close(old_fd);
    return EXIT_SUCCESS;
}
```

实测输出：

```text
== ③ fchdir + 目录 fd：零字符串开销地「记住老目录」==
  chdir(/) 后 cwd = /
  fchdir(old_fd) 回到 = /Users/a0000/WorkBuddy/.../chapter-18-directories-links（无需字符串、无路径重解析）
```

严格基准测试（微秒级差值）未做——本机 APFS 上差异会被符号链接解析与文件系统缓存噪声淹没；结论由「解析次数对比」这一结构性证据支撑，Pi5 复测清单可补一条 `clock_gettime` 计时版本。

<summary>代码自测（Q&A）</summary>

**Q1：18-1 里「cc 的覆盖」和「直接写打开」的本质区别是什么？**
A：前者是**目录表操作**（rename 换目录项指向新 inode），后者是**inode 写操作**（要真的改老 inode 的数据）。内核只对后者施加 ETXTBSY；目录表层面没有任何「这个文件在跑」的概念。所以 rename 永远能成功。

**Q2：为什么 macOS 的签名机制会 SIGKILL 拷贝的 /bin/sleep？**
A：`/bin/sleep` 带 Apple 平台签名（`Platform identifier=26`），系统强制它只能从受信位置运行；拷到 `/tmp` 后签名校验语境失效，AMFI 直接 SIGKILL。自己 clang 编译的是 ad-hoc 签名，无位置约束。**这是做系统实验时的 macOS 专属陷阱**，Linux 无此机制。

**Q3：18-3 的自实现与系统库最可能在哪类输入上分歧？**
A：① 末组件不存在（POSIX 允许成功、macOS 实测报 `ENOENT`）；② 路径中某级目录无 `x` 权限（教学版没做逐级权限检查）；③ 超长路径（教学版按 `PATH_MAX` 截断语义，实际 realpath 契约是报错）。教学版的边界都写在源码头注释里。

**Q4：18-7 的统计为什么必须 `FTW_PHYS`？不加会怎样？**
A：不加时指向目录的链接会被当作目录下钻，其子树的每个文件都会被**再数一次**（实测 inode 相同、条目重复）。`/etc` 这类含 `/etc/periodic -> ...` 链接的目录立刻就能看出重复计数。

**Q5：18-9 的两种方案，除了效率还有什么区别值得记？**
A：失败模式不同。字符串方案在「老目录被改名/删除」时**回不去**（`chdir` 失败）；fd 方案在同样情况下**照常回去**（fd 绑定 inode）。对一个长期运行、目录结构可能变化的服务，后者是唯一正确的选择——效率反而是次要的。

**Q6：这 9 道题里哪道最有工程价值？**
A：18-1。它把 §18.3（unlink 语义）、§18.4（rename 原子替换）和真实部署（灰度发布、热更新不掉数据）串成一条线，且顺带钉出了 macOS 签名与 ETXTBSY 两个跨平台坑。其次是 18-3（`..` 的物理语义是安全代码的地基）。
