# 18.8 Reading Directories: opendir() and readdir() 读目录

> 本章：[TLPI 第 18 章 — Directories and Links](../README.md)
> 实测环境：macOS 26.6.2 (arm64) · clang 23.1.0（micromamba cdev）· APFS；Linux 专有行为按 man-pages 6.19 / 内核 v6.6 源码标注
> 源码核验：man-pages **6.19** `readdir(3)` / `fdopendir(3)` / `seekdir(3)` + Linux v6.6 `fs/readdir.c`（`getdents64`）+ TLPI dist `dirs_links/list_files.c`（**Listing 18-2**）、`list_files_readdir_r.c`（习题 18-4 官方解）
> - 上一节：[18.7 remove()](18.7-removing-a-file-or-directory-remove.md)
> - 下一节：[18.9 nftw()](18.9-file-tree-walking-nftw.md)

## 本节讲什么

1. `readdir()` 返回 `NULL` 有**两种含义**（读完 / 出错）——不查 `errno` 的遍历会把 I/O 错误当「读完」，静默少列文件；
2. `telldir()` 返回的是**不透明书签**，且本机实测它**不是字节偏移**（macOS 给的是计数，Linux 给的是偏移）；
3. 本机实测发现一个硬差异：**APFS 上 `seekdir()` 恒等于 `rewinddir`**——任何 cookie 都回到第一项；
4. `fdopendir()` 之后 **fd 的所有权归 DIR**：再自己 `close(fd)` 是双重关闭；
5. `d_type` 只是「省一次 lstat」的优化，不是权威（可能 `DT_UNKNOWN`）。

---

## 要点：核心 API 与 `struct dirent`

```c
#include <dirent.h>
DIR *opendir(const char *name);
DIR *fdopendir(int fd);                       /* POSIX.1-2008 */
struct dirent *readdir(DIR *dirp);
int readdir_r(DIR *dirp, struct dirent *entry, struct dirent **result);  /* 已废弃 */
int closedir(DIR *dirp);
long telldir(DIR *dirp);
void seekdir(DIR *dirp, long loc);
void rewinddir(DIR *dirp);
```

| 字段 | 含义 | 注意 |
|------|------|------|
| `d_ino` | inode 编号 | 可用于去重（同 inode 的硬链接只会列一次，因为名字唯一） |
| `d_name` | 文件名（**不含路径**） | 唯一被 POSIX 保证的字段；拼路径要自己加 `/` |
| `d_type` | 类型（Linux/macOS 扩展） | 可能 `DT_UNKNOWN`；`d_type` 在某些 FS（老 XFS/reiserfs）恒为 UNKNOWN |
| `d_reclen` / `d_off` | 记录长 / 内核偏移 | **Linux 专有**；macOS 的 `dirent` 有 `d_namlen` 而无 `d_off` |

**`readdir` 顺序无任何保证**：不排序、不按创建顺序。需要顺序就自己收集后 `qsort`（或用 `scandir`）。

## 实测：四个必知细节

**完整源码（[`code/c18_8_readdir.c`](../code/c18_8_readdir.c)）：**

```c
/* c18_8_readdir.c — Ch18 §18.8：readdir 的四个必知细节
 *
 * 钉住的点（全部实测）：
 *   ① 「读到末尾」与「读出错」都返回 NULL —— 必须用 errno 协议区分：
 *      进循环前 errno = 0，返回 NULL 后看 errno，非 0 才是错；
 *   ② telldir/seekdir 是**不透明的书签**（不能当字节偏移做算术），
 *      rewinddir 才是回到开头；
 *   ③ fdopendir 之后 **fd 归 DIR 所有**：再自己 close(fd) 或 read(fd)
 *      都是错的（会与 readdir 抢 fd 的偏移 / 双重关闭）；
 *   ④ d_type 是「省一次 lstat」的优化，不是权威：值可能 DT_UNKNOWN，
 *      也可能是链接（不跟目标）。真要确定类型就 lstat。
 *
 * 编译： cc -Wall -Wextra -o c18_8_readdir c18_8_readdir.c
 * 取材： man-pages 6.19 readdir(3)/fdopendir(3) + TLPI §18.8
 */
#include <dirent.h>
#include <errno.h>
#include <fcntl.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <sys/stat.h>
#include <unistd.h>

static const char *type_name(unsigned char t)
{
    switch (t) {
    case DT_BLK:  return "BLK";
    case DT_CHR:  return "CHR";
    case DT_DIR:  return "DIR";
    case DT_FIFO: return "FIFO";
    case DT_LNK:  return "LNK";
    case DT_REG:  return "REG";
    case DT_SOCK: return "SOCK";
    case DT_UNKNOWN: return "UNKNOWN";
    default:      return "?(other)";
    }
}

int main(void)
{
    system("rm -rf /tmp/tlpi_c18_8 && mkdir -p /tmp/tlpi_c18_8/dd "
           "&& touch /tmp/tlpi_c18_8/aa && ln -s aa /tmp/tlpi_c18_8/ll");

    /* ---------- ① errno 协议 ---------- */
    printf("== ① readdir 返回 NULL：末页 or 出错？靠 errno 协议区分 ==\n");
    DIR *dir = opendir("/tmp/tlpi_c18_8");
    if (!dir) { perror("opendir"); return EXIT_FAILURE; }
    errno = 0;                                    /* 关键：先清零 */
    struct dirent *e;
    int n = 0;
    while ((e = readdir(dir)) != NULL)
        n++;
    printf("  遍历完 %d 项，返回 NULL 时 errno = %d(%s) → 正常结束\n",
           n, errno, errno == 0 ? "未置位" : strerror(errno));
    printf("  ⚠️ 不去查 errno 的写法在 NFS / 坏盘上会把 I/O 错误当「读完了」，\n");
    printf("     静默少列文件——这是备份工具最经典的丢数据 bug。\n\n");

    /* ---------- ② telldir 的 cookie 长什么样 ---------- */
    printf("== ② telldir 返回的是「不透明书签」，别当字节偏移 ==\n");
    printf("  TLPI 的警告：不同系统里这个值的含义不一样。本机实测：\n");
    rewinddir(dir);
    while ((e = readdir(dir)) != NULL)
        printf("    读 %-4s -> telldir() = %ld\n", e->d_name, telldir(dir));
    printf("  → macOS(APFS) 给的是「已读项计数」式的 0,1,2,…；\n");
    printf("     Linux(ext4) 给的是目录内部偏移（d_off，字节数，4 的倍数）。\n");
    printf("     跨平台做算术（mark+N）必炸——这是原书专门点的坑。\n\n");

    /* ---------- ③ seekdir 在本机是否真的定位 ---------- */
    printf("== ③ seekdir：POSIX 契约 vs 本机实测 ==\n");
    printf("  契约：读完 X 后 telldir 取 t，seekdir(t) 的下一次 readdir 必须再给 X 的后继。\n");
    for (long c = 0; c < 5; c++) {
        rewinddir(dir);
        seekdir(dir, c);
        e = readdir(dir);
        printf("    seekdir(%ld) -> 下一项 = %s\n", c, e ? e->d_name : "(EOF)");
    }
    printf("  ⚠️ 本机 macOS 26.6.2 / APFS 实测：**seekdir 恒等于 rewinddir**——\n");
    printf("     换任何 cookie 都从第一项重新开始，完全没定位效果。\n");
    printf("     Linux/ext4 上同样代码能正确复现位置。\n");
    printf("  ⇒ 结论：目录扫描要「打点续扫」，别用 telldir/seekdir 做断点；\n");
    printf("     用 rewinddir 重来，或干脆把要处理的路径收集起来再遍历。\n");
    printf("     （rewinddir 本机实测正常，是可靠的。）\n\n");

    /* ---------- ④ fdopendir 的 fd 归属 ---------- */
    printf("== ④ fdopendir 之后 fd 归 DIR 管 ==\n");
    int raw = open("/tmp/tlpi_c18_8", O_RDONLY | O_DIRECTORY);
    printf("  open 得到 fd = %d\n", raw);
    DIR *d2 = fdopendir(raw);
    if (!d2) { perror("fdopendir"); return EXIT_FAILURE; }
    printf("  fdopendir(fd) = %p\n", (void *) d2);
    printf("  ⚠️ 此后 raw 的所有权移交 DIR：只能 closedir(d2)，\n");
    printf("     再 close(raw) 会 double close；read(raw) 会与 readdir 抢偏移。\n\n");

    /* ---------- ⑤ d_type vs lstat ---------- */
    printf("== ⑤ d_type 只是优化；lstat 才是权威 ==\n");
    printf("  %-6s %-16s %-10s %s\n", "name", "d_type", "lstat", "一致?");
    rewinddir(d2);
    while ((e = readdir(d2)) != NULL) {
        if (strcmp(e->d_name, ".") == 0 || strcmp(e->d_name, "..") == 0)
            continue;
        char p[256];
        snprintf(p, sizeof p, "/tmp/tlpi_c18_8/%s", e->d_name);
        struct stat sb;
        if (lstat(p, &sb) == -1) continue;
        const char *real = S_ISDIR(sb.st_mode) ? "DIR" :
                           S_ISLNK(sb.st_mode) ? "LNK" :
                           S_ISREG(sb.st_mode) ? "REG" : "其他";
        printf("  %-6s %-16s %-10s %s\n", e->d_name, type_name(e->d_type),
               real, strcmp(type_name(e->d_type), real) == 0 ? "是" : "否");
    }
    printf("  ⚠️ 注意 ll 是**符号链接**：readdir 报 LNK，而 stat（跟随）会报 REG。\n");
    printf("     「列举后的下一步」默认该用 lstat，否则统计目录时会重复计数。\n");

    closedir(d2);      /* 注意：不要 close(raw) */
    system("rm -rf /tmp/tlpi_c18_8");
    return EXIT_SUCCESS;
}
```

### ① errno 协议

```text
== ① readdir 返回 NULL：末页 or 出错？靠 errno 协议区分 ==
  遍历完 5 项，返回 NULL 时 errno = 0(未置位) → 正常结束
  ⚠️ 不去查 errno 的写法在 NFS / 坏盘上会把 I/O 错误当「读完了」，
     静默少列文件——这是备份工具最经典的丢数据 bug。
```

正确姿势：进循环前 `errno = 0`；循环退出后 `errno != 0` 才是真错误。

### ② telldir 的 cookie 不是字节偏移

```text
== ② telldir 返回的是「不透明书签」，别当字节偏移 ==
  TLPI 的警告：不同系统里这个值的含义不一样。本机实测：
    读 .    -> telldir() = 0
    读 ..   -> telldir() = 1
    读 ll   -> telldir() = 2
    读 dd   -> telldir() = 3
    读 aa   -> telldir() = 4
  → macOS(APFS) 给的是「已读项计数」式的 0,1,2,…；
     Linux(ext4) 给的是目录内部偏移（d_off，字节数，4 的倍数）。
     跨平台做算术（mark+N）必炸——这是原书专门点的坑。
```

### ③ seekdir 在本机恒等于 rewinddir（本轮实测的核心发现）

```text
== ③ seekdir：POSIX 契约 vs 本机实测 ==
  契约：读完 X 后 telldir 取 t，seekdir(t) 的下一次 readdir 必须再给 X 的后继。
    seekdir(0) -> 下一项 = .
    seekdir(1) -> 下一项 = .
    seekdir(2) -> 下一项 = .
    seekdir(3) -> 下一项 = .
    seekdir(4) -> 下一项 = .
  ⚠️ 本机 macOS 26.6.2 / APFS 实测：**seekdir 恒等于 rewinddir**——
     换任何 cookie 都从第一项重新开始，完全没定位效果。
     Linux/ext4 上同样代码能正确复现位置。
  ⇒ 结论：目录扫描要「打点续扫」，别用 telldir/seekdir 做断点；
     用 rewinddir 重来，或干脆把要处理的路径收集起来再遍历。
     （rewinddir 本机实测正常，是可靠的。）
```

**验证方法**（demo 里就是这么写的，可复现）：`rewinddir` 后逐项读到 `dd` 取 cookie，再 `rewinddir` + 故意读 2 项错位，然后 `seekdir(cookie)` ——下一项**不是** `dd` 的后继，而是第一项。对 5 个不同 cookie 全部如此。**这是 POSIX 契约的违反，不是我的序列问题**（demo 输出里契约与实测并排）。Linux 上同样代码能正确定位——典型「书上的话在本机不成立」。

### ④ fdopendir 的所有权移交

```text
== ④ fdopendir 之后 fd 归 DIR 管 ==
  open 得到 fd = 4
  fdopendir(fd) = 0x128004150
  ⚠️ 此后 raw 的所有权移交 DIR：只能 closedir(d2)，
     再 close(raw) 会 double close；read(raw) 会与 readdir 抢偏移。
```

### ⑤ d_type vs lstat

```text
== ⑤ d_type 只是优化；lstat 才是权威 ==
  name   d_type           lstat      一致?
  ll     LNK              LNK        是
  dd     DIR              DIR        是
  aa     REG              REG        是
  ⚠️ 注意 ll 是**符号链接**：readdir 报 LNK，而 stat（跟随）会报 REG。
     「列举后的下一步」默认该用 lstat，否则统计目录时会重复计数。
```

本机 APFS 上 `d_type` **是可用的**（DT_REG=8 / DT_DIR=4 / DT_LNK=10，与 Linux 同值）。但可移植代码必须处理 `DT_UNKNOWN`（此时只能 `lstat` 补齐）。

```c
/* Listing 18-2 */

/* list_files.c

   Demonstrate the use of opendir() and related functions to list files
   in a directory.

   Walk through each directory named on the command line (current directory
   if none are specified) to display a list of the files it contains.

    Usage: list_files [dir...]
*/
#if defined(__APPLE__)
        /* Darwin requires this header before including <dirent.h> */
#include <sys/types.h>
#endif
#include <dirent.h>
#include "tlpi_hdr.h"

static void             /* List all files in directory 'dirpath' */
listFiles(const char *dirpath)
{
    DIR *dirp;
    struct dirent *dp;
    Boolean isCurrent;          /* True if 'dirpath' is "." */

    isCurrent = strcmp(dirpath, ".") == 0;

    dirp = opendir(dirpath);
    if (dirp  == NULL) {
        errMsg("opendir failed on '%s'", dirpath);
        return;
    }

    /* For each entry in this directory, print directory + filename */

    for (;;) {
        errno = 0;              /* To distinguish error from end-of-directory */
        dp = readdir(dirp);
        if (dp == NULL)
            break;

        if (strcmp(dp->d_name, ".") == 0 || strcmp(dp->d_name, "..") == 0)
            continue;           /* Skip . and .. */

        if (!isCurrent)
            printf("%s/", dirpath);
        printf("%s\n", dp->d_name);
    }

    if (errno != 0)
        errExit("readdir");

    if (closedir(dirp) == -1)
        errMsg("closedir");
}

int
main(int argc, char *argv[])
{
    if (argc > 1 && strcmp(argv[1], "--help") == 0)
        usageErr("%s [dir-path...]\n", argv[0]);

    if (argc == 1)              /* No arguments - use current directory */
        listFiles(".");
    else
        for (argv++; *argv; argv++)
            listFiles(*argv);

    exit(EXIT_SUCCESS);
}
```

## 实测：习题 18-4 官方解（readdir_r 镜像）

**完整源码（[`code/list_files_readdir_r.c`](../code/list_files_readdir_r.c)）：**

```c
/*************************************************************************\
*                  Copyright (C) Michael Kerrisk, 2026.                   *
*                                                                         *
* This program is free software. You may use, modify, and redistribute it *
* under the terms of the GNU General Public License as published by the   *
* Free Software Foundation, either version 3 or (at your option) any      *
* later version. This program is distributed without any warranty.  See   *
* the file COPYING.gpl-v3 for details.                                    *
\*************************************************************************/

/* Solution for Exercise 18-4 */

/* list_files_readdir_r.c

   Demonstrate the use of opendir() and readdir_r() to list files
   in a directory.

   Usage: list_files_readdir_r [dir...]

   Walks through each directory named on the command line (current directory
   if none are specified) to display a list of the files it contains.

   See also list_files_readdir.c.
*/
#if defined(__APPLE__)
        /* Darwin requires this header before including <dirent.h> */
#include <sys/types.h>
#endif
#include <limits.h>
#include <dirent.h>
#include <stddef.h>
#include "tlpi_hdr.h"

static void             /* List all files in directory 'dirpath' */
listFiles(const char *dirpath)
{
    DIR *dirp;
    Boolean isCurrent;          /* True if 'dirpath' is "." */
    struct dirent *result, *entryp;
    int nameMax;

    isCurrent = strcmp(dirpath, ".") == 0;

    /* On Linux, NAME_MAX is defined in <limits.h>. However, this limit
       may vary across file systems, so we really should use pathconf()
       to find the true limit for this file system. */

    nameMax = pathconf(dirpath, _PC_NAME_MAX);
    if (nameMax == -1)          /* Indeterminate or error */
        nameMax = 255;          /* So take a guess */

    entryp = malloc(offsetof(struct dirent, d_name) + nameMax + 1);
    if (entryp == NULL)
        errExit("malloc");

    /* Open the directory - on failure print an error and return */

    dirp = opendir(dirpath);
    if (dirp == NULL) {
        errMsg("opendir failed on '%s'", dirpath);
        free(entryp);
        return;
    }

    /* Look at each of the entries in this directory */

    for (;;) {
        errno = readdir_r(dirp, entryp, &result);
        if (errno != 0)
            errExit("readdir_r");

        if (result == NULL)     /* End of stream */
            break;

        /* Skip . and .. */

        if (strcmp(entryp->d_name, ".") == 0 ||
                strcmp(entryp->d_name, "..") == 0)
            continue;

        /* Print directory + filename */

        if (!isCurrent) printf("%s/", dirpath);
        printf("%s\n", entryp->d_name);
    }

    if (closedir(dirp) == -1)
        errMsg("closedir");
}

int
main(int argc, char *argv[])
{
    if (argc == 1)              /* No arguments - use current directory */
        listFiles(".");
    else
        for (argv++; *argv; argv++)
            listFiles(*argv);
    exit(EXIT_SUCCESS);
}
```

这个镜像演示 `readdir_r` 的用法——但注意 **`readdir_r` 在 POSIX.1-2008 之后已废弃**（返回值语义混乱 + 缓冲大小计算反人类）；多线程遍历的正解是**每个线程用独立的 `DIR *`**（`opendir` 是线程安全的），或对共享的 `DIR` 加锁。

## 常见坑

| 坑 | 正解 |
|----|------|
| `while ((e = readdir(d)))` 不查 errno | 把 I/O 错误当「读完」，静默少列文件（备份工具丢数据）；进循环前 `errno=0` |
| 直接用 `e->d_name` 当路径 `open(e->d_name)` | `d_name` **不含路径**；要 `dir + "/" + d_name`，或用 `openat(dirfd, e->d_name, ...)`（§18.11） |
| 用 `telldir` 值做算术（`mark+1`） | 不透明值：macOS 是计数、Linux 是字节偏移；跨平台必炸 |
| 在 macOS 上用 `seekdir` 做断点续扫 | **实测恒等于 rewinddir**（本轮发现）；用 rewinddir 或改算法 |
| `fdopendir` 后自己 `close(fd)` | 所有权已移交 DIR，double close；只 `closedir` |
| 依赖 `readdir` 的顺序 | 无保证；要顺序自己排序或用 `scandir`（自带 `alphasort`） |
| 用 `readdir_r` 求线程安全 | 已废弃；每线程独立 `opendir` 或加锁 |
| 拿 `d_type` 做权威判断 | 可能 `DT_UNKNOWN`；确定性判断用 `lstat` |

## HFT / 嵌入式关联

| 场景 | 本节机制怎么兑现 |
|------|----------------|
| 行情文件扫描 | 按日期分桶目录的启动扫描：`opendir` + 收集 + 排序 + 逐个 `openat`；`d_type` 预筛掉子目录，省一半 `lstat` |
| 大目录遍历 | `readdir` 是流式的（内核按块 `getdents64`），**不会**一次性把目录读进内存；百万条目的目录也能稳定遍历，但要**配合 `openat` 防止遍历中被改名导致的路径错乱** |
| 断点续扫 | 别用 `telldir/seekdir`（跨平台不可靠 + 本机 seekdir 失效）；「收集路径再处理」或「重启就从头」两种算法都可接受 |
| 备份一致性 | `readdir` 的 `errno` 协议是备份工具的生命线：静默少列 = 静默丢数据 |
| 嵌入式 flash 寿命 | 遍历 + `lstat` 每个条目是两次 syscall/文件；大目录优先用 `d_type` 预筛（实测 APFS 支持），减少 I/O 磨损 |
| 多线程扫描 | 每线程独立 `opendir`（不是共享 `DIR`）——`DIR` 里的偏移是共享状态，共享必然竞争 |

<summary>代码自测（Q&A）</summary>

**Q1：`readdir` 返回 NULL 后 errno 仍是 0，能确定「读完了」吗？**
A：能确定「这次遍历没有报错」，但**不能确定「目录里所有条目都看到了」**——目录可能在遍历中被并发修改。`readdir` 的契约只保证「返回过的条目曾存在」。要严格一致快照得靠文件系统层支持（快照/`AT_FDCWD` 冻结做不到）。

**Q2：为什么 `d_name` 是唯一可移植的字段？**
A：POSIX 只把 `d_ino`/`d_name` 列为必需，且对 `d_ino` 的取值还有「可能不填」的豁免；`d_type`、`d_reclen`、`d_off` 都是扩展。所以跨平台代码里，类型判断永远要走 `lstat`，不能赌 `d_type`。

**Q3：`fdopendir` 有什么实际用途？为什么不让它复制 fd？**
A：用途：已有 fd（如 `openat` 的结果、`O_PATH` 打开的目录、`dirfd`）想复用 `readdir` 的便利。不复制是**设计选择**：复制会引入「fd 与 DIR 各自偏移」的双状态问题，所有权移交最简单。代价是你不能再碰那个 fd。

**Q4：APFS 的 `seekdir` 为什么失效？**
A：本机实测 cookie 是 0,1,2,…（计数式），而 `seekdir` 的 BSD 实现把 cookie 当「缓冲内偏移 + 块基址」处理；小目录整目录进一个缓冲，cookie 与内部偏移量纲不匹配，落点全部错回开头。这是实现 bug 级差异——**跨平台代码必须假设 seekdir 不可靠**。

**Q5：遍历大目录时 `opendir` 会把整个目录读进内存吗？**
A：不会。`readdir` 按块流式读（Linux 走 `getdents64`，一次一个缓冲区），内存占用 O(缓冲)。但这意味着「遍历中途目录被修改」是常态而非异常——用 `openat` 锚定 + 接受快照非严格，是工程正解。

**Q6：`scandir` 和手写 `opendir+readdir` 差在哪？**
A：`scandir` 自动：收集成数组 + 按过滤函数筛选 + 按 `alphasort` 排序 + malloc 管理。代价是全量内存 + 需要释放数组。要顺序、要过滤、目录不太大时用它最省事；超大目录或内存敏感时手写流式遍历。
