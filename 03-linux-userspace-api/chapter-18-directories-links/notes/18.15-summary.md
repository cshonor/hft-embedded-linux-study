## 本章一条主线

**路径（名字）与 inode（本体）是两个层次**。整章的每个接口都在这两个层次间移动：

| 层次 | 是什么 | 本章相关接口 |
|------|--------|-------------|
| **名字层** | 目录项 `(名字, inode#)`、路径字符串 | `link`/`unlink`/`rename`/`symlink`/`mkdir`/`rmdir`/`dirname`/`basename` |
| **本体层** | inode、数据块、fd 引用 | `stat`/`lstat`/`open` 后的一切（`readlink` 是名字层的读口） |

**所有竞态与安全问题的根源都是「在名字层做多次操作」**；所有解法（`open`+`unlink`、safe-write、`*at()` 锚点、`fchdir` 恢复）都是「**尽早把名字换成引用**」。

## API 全景图（按功能分组）

### 创建与删除（目录表写操作）

| 接口 | 一句话 | 关键语义 |
|------|--------|---------|
| `link(old,new)` | 加一行名字 | 同 inode、同 FS、不覆盖（`EEXIST`） |
| `unlink(path)` | 删一行名字 | 只摘名字；`nlink==0` 且无 fd 才释放 |
| `symlink(target,path)` | 建独立 inode 存路径串 | **不检查目标**（悬空合法） |
| `mkdir(path,mode)` | 建目录 | mode 受 umask；`EEXIST` 原子检查 |
| `rmdir(path)` | 删空目录 | 「空」= 只剩 `.`/`..` |
| `remove(path)` | C 标准分派器 | 判类型 → `unlink`/`rmdir`；删链接本身 |
| `rename(old,new)` | **原子替换** | 同 FS O(1)；目录四规则 + 两条 `EINVAL` |

### 读取与遍历

| 接口 | 一句话 | 关键语义 |
|------|--------|---------|
| `opendir/readdir/closedir` | 流式读目录 | `NULL` 有两义（查 errno）；顺序无保证 |
| `telldir/seekdir/rewinddir` | 书签 | 不透明值；**本机实测 seekdir 失效** |
| `fdopendir(fd)` | fd 转 DIR | 所有权移交，不能再 close(fd) |
| `nftw(dir,fn,nopenfd,flags)` | 遍历目录树 | `FTW_DEPTH\|FTW_PHYS` 是递归删除固定搭配 |
| `readlink(path,buf,n)` | 读链接原文 | 裸字节串，**不补 NUL**，返回值是字节数 |
| `realpath(path,resolved)` | 解析到底 | 逐级 lstat；`..` 不能字符串消去 |

### 位置与边界

| 接口 | 一句话 | 关键语义 |
|------|--------|---------|
| `chdir/fchdir/getcwd` | 进程 cwd | fd 方案优于字符串方案（习题 18-9） |
| `*at()` 族 | 相对目录 fd 操作 | 消 TOCTOU + 去 cwd 全局状态 |
| `chroot(path)` | 改解析起点 | 需特权；**不改 cwd**；特权进程可逃逸 |
| `dirname/basename` | 纯字符串切分 | **会毁输入**；尾部斜杠忽略；空串给 `.` |

## 三个惯用法（背下来）

```c
/* ① 零竞态临时文件：名字从未暴露，崩溃自动回收 */
int fd = open(path, O_RDWR|O_CREAT|O_EXCL, 0600);
unlink(path);
/* ... 用 fd ... */
close(fd);                       /* 数据此刻才释放 */

/* ② safe-write：读者永远看到完整旧版或完整新版 */
write(tmp); fsync(tmp); rename(tmp, target);

/* ③ 锚点模式：把名字换成引用，消除 cwd 全局状态与 TOCTOU */
int anchor = open(root, O_RDONLY|O_DIRECTORY);
int fd = openat(anchor, rel, O_RDONLY|O_NOFOLLOW);
```

## 常见坑 Top 8（全章汇总）

1. 删了文件磁盘没腾出 → 有进程还开着它（`nlink==0` 且无 fd 才释放）
2. `readdir` 返回 `NULL` 不查 `errno` → I/O 错误被当「读完」，静默丢文件
3. 字符串消 `..` → `/link/../x` 结果错误；必须逐级 `lstat`
4. `readlink` 后不补 NUL / 不看返回值 → 截断 + 未定义行为
5. 同一 `path` 喂两次 `dirname`/`basename` → 第一次就毁了输入
6. `nftw` 递归删除忘 `FTW_PHYS` → 链接外的文件被误删
7. `chroot` 后不 `chdir("/")` 不丢特权 → 相对路径/double chroot 逃逸
8. 用 `rename` 当锁 → 它是覆盖语义；互斥要用 `link` 的 `EEXIST` 或 `O_EXCL`

<summary>代码自测（Q&A）</summary>

**Q1：本章哪几条实测结论与「书上的话」不一致，写代码时要当心？**
A：① macOS `seekdir` 恒等于 `rewinddir`（书按 POSIX 契约描述）；② macOS 不 enforce ETXTBSY（书按 Linux 描述）；③ macOS/APFS 目录 `st_size` 非块对齐（书按「块整数倍」描述）；④ macOS 链接有自己的 uid/gid/mode（书说权限被忽略）；⑤ realpath 对「末组件不存在」的实现差异。全部已在本章各节实测钉住。

**Q2：「把名字换成引用」具体指什么？为什么它消除竞态？**
A：指尽早 `open`（得到绑定 inode 的 fd），之后不再做路径操作（用 `fstat`/`fchmod`/`fchdir`/`readlinkat` 等 fd 级接口）。路径解析（TOCTOU 所在）只发生一次；fd 一旦建立，后续操作的对象固定，不存在「检查与使用之间被换掉」。

**Q3：本章哪几个接口能做「原子」互斥？为什么 rename 不行？**
A：`link()`（目标存在则 `EEXIST`）、`open(O_CREAT|O_EXCL)`、`mkdir()`（存在则 `EEXIST`）——三者都是「检查+创建」在内核一步完成。`rename` 是无条件覆盖，两个进程同时 rename 都成功，锁形同虚设。

**Q4：目录操作里最容易被忽略的性能点？**
A：路径解析。每条全路径 `open` 都要从 `/` 逐级走（namei + dcache 锁）；深目录 + 海量文件时 `openat` 锚点（只解析最后一段）是数量级差距。其次是大目录的 `readdir` 顺序（无序 → 排序成本）。

**Q5：如果要给本章画一张「安全性等级」图，怎么排？**
A：从弱到强：字符串拼路径 → 全路径 stat+open（TOCTOU）→ `O_NOFOLLOW` → `realpath` 校验 → `*at()` 锚点 → 全 fd 化（open 后只用 f 系接口）→ chroot/容器（边界隔离，但 chroot 本身可逃逸）。工程正解通常是「`*at()` 锚点 + `O_NOFOLLOW`」这一档——不需要特权，覆盖面够。

**Q6：本章与 Ch19（inotify）怎么衔接？**
A：本章所有目录操作都是「拉」模型（主动查）；Ch19 的 inotify 是「推」模型（内核主动通知目录变化）。配置热更新 = 本章的 safe-write + Ch19 的事件监听；目录监控 = Ch19 的 `IN_CREATE/IN_DELETE/IN_MOVED_FROM`。两者合起来才是完整的文件系统编程图景。
