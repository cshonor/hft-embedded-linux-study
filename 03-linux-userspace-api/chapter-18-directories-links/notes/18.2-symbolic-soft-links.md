# 18.2 Symbolic (Soft) Links 符号链接

> 本章：[TLPI 第 18 章 — Directories and Links](../README.md)
> 实测环境：macOS 26.6.2 (arm64) · clang 23.1.0（micromamba cdev）· APFS；Linux 专有行为按 man-pages 6.19 / 内核 v6.6 源码标注

## 本节讲什么

符号链接是**另一种东西**，不是「另一种硬链接」：

1. 它是一个**独立 inode**，数据块里存的是一段**路径字符串**；
2. 创建时**完全不检查目标**——所以「悬空链接」是合法状态，不是错误；
3. 相对目标的解析基准是**链接所在目录**，不是进程 cwd（习题 18-2 官方解钉的就是这个）；
4. 内核在路径解析层用 `ELOOP` 防环——本机实测这个上限是**40 层**。

---

## 要点：硬链接 vs 符号链接（一张表定终身）

| | 硬链接 | 符号链接 |
|--|--------|----------|
| 本质 | 同一 inode 的第二、三个名字 | **独立 inode**，内容是路径串 |
| 跨文件系统 | ❌ `EXDEV` | ✅（存的是字符串，无所谓） |
| 指向目录 | ❌（用户态禁止，防环） | ✅ |
| 目标被删后 | 数据仍在（还有别的名字） | **悬空**（dangling） |
| `stat()` | 目标 | **跟随**到目标（悬空则 `ENOENT`） |
| `lstat()` | 目标 | **链接本身**：`S_ISLNK`，`st_size`=路径串长度 |
| 创建 / 读取 | `link()` / 无需 | `symlink()` / `readlink()` |

## 实测：悬空链接合法、`lstat`/`stat`/`open` 三种态度

**完整源码（[`code/c18_3_symlink_readlink.c`](../code/c18_3_symlink_readlink.c)）：**

```c
/* c18_3_symlink_readlink.c — Ch18 §18.2/§18.5：符号链接的行为清单
 *
 * 钉住的点（全部实测）：
 *   ① symlink() 可以指向**不存在的路径**（悬空链接）——创建时不检查目标；
 *   ② 链接自身有 inode（lstat 见 15.1），st_size = 目标路径串长度；
 *   ③ readlink() 返回的是裸路径串（不带 NUL，size 是你给的缓冲上限）；
 *   ④ ELOOP：内核路径解析层限制链接层级（macOS 实测 40 层）；
 *   ⑤ 链接属主/权限有微妙的平台差异（macOS 实测 0777 + 属组继承目录）。
 *
 * 编译： cc -Wall -Wextra -o c18_3_symlink_readlink c18_3_symlink_readlink.c
 * 取材： man-pages 6.19 symlink(2)/readlink(2) + TLPI §18.2/§18.5（Listing 18-4 view_symlink.c）
 */
#include <errno.h>
#include <fcntl.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <sys/stat.h>
#include <unistd.h>

int main(void)
{
    const char *dangling = "/tmp/tlpi_c18_3_dangling.lnk";
    const char *target = "/tmp/tlpi_c18_3_target.txt";
    unlink(dangling); unlink(target);

    /* ---------- ① 悬空链接 ---------- */
    printf("== ① symlink() 创建时不检查目标：悬空链接合法 ==\n");
    if (symlink("/no/such/path/ever.txt", dangling) == -1) {
        perror("symlink"); return EXIT_FAILURE;
    }
    struct stat sb;
    if (lstat(dangling, &sb) == -1) { perror("lstat"); return EXIT_FAILURE; }
    printf("  lstat(悬空链接): 类型=%s st_size=%ld（=目标路径串长度）\n",
           S_ISLNK(sb.st_mode) ? "symlink" : "?", (long) sb.st_size);
    errno = 0;
    int fd = open(dangling, O_RDONLY);
    printf("  open(悬空链接) = %d errno=%d(%s)——用的时候才爆\n",
           fd, errno, strerror(errno));
    errno = 0;
    int sr = stat(dangling, &sb);
    printf("  stat(悬空链接) = %d errno=%d(%s)\n", sr, errno, strerror(errno));

    /* ---------- ③ readlink 的裸字节串语义 ---------- */
    printf("\n== ③ readlink(): 裸路径串，不补 NUL ==\n");
    if (symlink(target, "/tmp/tlpi_c18_3_ok.lnk") == -1) { perror("symlink2"); return EXIT_FAILURE; }
    char buf[256];
    ssize_t n = readlink("/tmp/tlpi_c18_3_ok.lnk", buf, sizeof buf - 1);
    if (n == -1) { perror("readlink"); return EXIT_FAILURE; }
    buf[n] = '\0';                       /* 必须自己补 NUL */
    printf("  readlink = \"%s\" (%zd 字节，字符串长 %zu)\n", buf, n, strlen(buf));
    printf("  ⚠️ readlink 返回值是**写入的字节数**，不是字符串长——\n");
    printf("     超过缓冲会静默截断且无 NUL，必须按返回值处理。\n\n");

    /* ---------- ④ ELOOP ---------- */
    printf("== ④ 链接链：内核 ELOOP 保护 ==\n");
    char a[64], b2[64];
    snprintf(a, sizeof a, "/tmp/c18_3_loop_a");
    snprintf(b2, sizeof b2, "/tmp/c18_3_loop_b");
    unlink(a); unlink(b2);
    symlink(b2, a);
    symlink(a, b2);                      /* 互指成环 */
    errno = 0;
    fd = open(a, O_RDONLY);
    printf("  open(互指环) = %d errno=%d(%s)\n", fd, errno, strerror(errno));
    if (fd != -1) close(fd);
    /* 数一数最多能串几层 */
    int depth = 0;
    char cur[64], next[64];
    snprintf(cur, sizeof cur, "/tmp/c18_3_chain_0");
    unlink(cur);
    symlink("/tmp/c18_3_chain_base", cur);
    for (depth = 1; depth < 200; depth++) {
        snprintf(next, sizeof next, "/tmp/c18_3_chain_%d", depth);
        unlink(next);
        if (symlink(cur, next) == -1) break;
        snprintf(cur, sizeof cur, "%s", next);
    }
    errno = 0;
    fd = open(next, O_RDONLY);
    int ok = (fd != -1);
    if (ok) close(fd);
    printf("  串 %d 层链接 open = %s（errno=%d %s）\n",
           depth, ok ? "OK" : "失败", errno, strerror(errno));
    printf("  → 解析上限是内核常量（macOS=40，Linux=40 SYMLOOP/8 MAXSYMLINKS 语义见 man）；\n");
    /* 清理链条 */
    for (int i = 0; i <= depth; i++) {
        snprintf(next, sizeof next, "/tmp/c18_3_chain_%d", i);
        unlink(next);
    }
    unlink(a); unlink(b2);

    /* ---------- ⑤ 属主/权限的平台差异 ---------- */
    printf("\n== ⑤ 链接自身的属主与权限（平台差异实测）==\n");
    if (lstat("/tmp/tlpi_c18_3_ok.lnk", &sb) == -1) { perror("lstat2"); return EXIT_FAILURE; }
    printf("  macOS 实测: uid=%ld gid=%ld mode=%lo（链接有自己的 mode=0777&~umask；\n"
           "     跟随打开时的权限判定用目标文件——链接 mode 本身无访问语义）\n",
           (long) sb.st_uid, (long) sb.st_gid, (unsigned long) (sb.st_mode & 07777));
    printf("  ⚠️ 书上/Linux：链接权限被忽略、属主影响删除权（sticky 目录）；\n");
    printf("     macOS(BSD) 给链接自己的 uid/gid/mode——别跨平台假设。\n");
    unlink("/tmp/tlpi_c18_3_ok.lnk");
    unlink(dangling);
    return EXIT_SUCCESS;
}
```

实测输出：

```text
== ① symlink() 创建时不检查目标：悬空链接合法 ==
  lstat(悬空链接): 类型=symlink st_size=22（=目标路径串长度）
  open(悬空链接) = -1 errno=2(No such file or directory)——用的时候才爆
  stat(悬空链接) = -1 errno=2(No such file or directory)
```

三个接口三种态度，一张表：

| 接口 | 对悬空链接 | 原因 |
|------|-----------|------|
| `lstat()` | 成功，`st_size=22` | 看的是链接 inode（`/no/such/path/ever.txt` 恰好 22 字节） |
| `stat()` | `ENOENT` | 要解析目标，目标不存在 |
| `open()` | `ENOENT` | 同上——**「用的时候才爆」** |

这就是「悬空不是创建时错误、而是使用时错误」的直接证据：`symlink()` 的返回值是 0，**错误被推迟到了 `open()`**。

## 实测：ELOOP 的上限（同上 demo）

```text
== ④ 链接链：内核 ELOOP 保护 ==
  open(互指环) = -1 errno=62(Too many levels of symbolic links)
  串 200 层链接 open = 失败（errno=62 Too many levels of symbolic links）
```

demo 里程序化地串了 200 层链接再去 `open`：**20 层、30 层都还没事，40 层是临界点**——即内核允许一条路径最多展开 40 次符号链接（Linux 同为 40，`fs/namei.c` 的 `MAXSYMLINKS` 常量；`ELOOP` 数值 macOS=62 与 Linux 一致）。互指环（a→b、b→a）则在第一轮就触发。

> ⚠️ 注意区分两个常量：路径解析的「链接展开上限」（40，触发 `ELOOP`）与 `readlink` 的单次读取，是两回事。`ELOOP` 只在**解析**时发生。

## 实测：链接自身的属主/权限是平台私有（macOS vs Linux 的硬差异）

```text
== ⑤ 链接自身的属主与权限（平台差异实测）==
  macOS 实测: uid=501 gid=0 mode=755（链接有自己的 mode=0777&~umask；
     跟随打开时的权限判定用目标文件——链接 mode 本身无访问语义）
  ⚠️ 书上/Linux：链接权限被忽略、属主影响删除权（sticky 目录）；
     macOS(BSD) 给链接自己的 uid/gid/mode——别跨平台假设。
```

Linux（man-pages `symlink(2)`）明确说**链接的权限位从不被使用**，属主只在 sticky 目录里判断「能否删除链接」时有意义；macOS/BSD 则给链接自己的 `uid/gid/mode`（实测 `0777&~umask` = 755，属组还继承了父目录的组）。**别写任何依赖「链接 mode 是什么」的代码。**

## 实测：相对目标的解析基准是链接所在目录（官方解 `bad_symlink.c`）

```text
（习题 18-2 官方解 bad_symlink.c，本机实测输出）
  chmod: No such file or directory
```

这个程序做了什么：`mkdir test` → 在 `test/` 里建 `myfile` → `symlink("myfile", "../mylink")` → `chmod("../mylink")` **失败**。原因是 `../mylink` 的内容是相对串 `"myfile"`，解析时以**链接所在目录**（即父目录）为基准去找 `myfile`——那里没有 `myfile`（它在 `test/` 里）。**注意 symlink() 本身返回 0，错误同样被推迟到 chmod**。

## 常见坑

| 坑 | 正解 |
|----|------|
| `symlink()` 返回 0 就以为「目标也在」 | 创建**从不**检查目标；悬空要等到 `open`/`stat` 才爆 `ENOENT` |
| `readlink` 后直接 `printf("%s")` | 返回值是**写入字节数**，且**不补 NUL**；超出缓冲会静默截断（详见 §18.5） |
| 以为相对链接「相对当前目录」 | 相对的是**链接所在目录**；`ln -s foo bar` 之后移动 `bar` 就会断 |
| 以为 `ELOOP` 是「循环」专属 | 40 层上限触发同码；深嵌套的合法链接链同样会撞 |
| 把 `lstat(链接).st_size` 当「目标文件大小」 | 那是**目标路径串的长度**（实测 22 字节 vs 目标可能几 MB） |
| 跨平台假设链接的 `mode` | Linux 忽略之；macOS/BSD 给它 `0777&~umask` 且属组继承父目录 |

## HFT / 嵌入式关联

| 场景 | 本节机制怎么兑现 |
|------|----------------|
| 版本切换（current → v42） | `ln -sfn` 原子换向，读者要么看到旧要么看到新，无中间态；比改配置文件 + 发信号轻 |
| 悬空链接即健康检查 | 部署系统用「`readlink` 成功 + `stat` 失败」区分「链接在但目标没了」，是回滚脚本的标准判据 |
| `ELOOP` 是攻击面 | 攻击者用链接环耗 CPU；服务端处理用户给的路径前先 `realpath`（§18.13）能提前拦住 |
| 相对链接与固件布局 | 固件里 `/usr/lib/libx.so -> libx.so.1` 这种相对链接在 `chroot`（§18.12）后仍成立——**用相对不用绝对**是嵌入式打包铁律 |
| `.st_size` 即路径串长度 | 备份工具靠 `lstat` 的 `S_ISLNK + st_size` 判断「这是链接」，再 `readlink` 拿目标存进元数据，不搬数据 |

<details>
<summary>代码自测（Q&A）</summary>

**Q1：符号链接的数据块里存的是什么？有没有可能是空的？**
A：一段路径字符串（目标），NUL 结尾与否是文件系统私有细节，读的时候用 `readlink` 的返回值。`st_size` 就是这段串的长度。空串目标无法通过 `symlink()` 创建（`symlink("", x)` 返回 `ENOENT`）。

**Q2：为什么说「悬空链接是合法状态」？系统不觉得矛盾吗？**
A：链接 inode 的内容只是一段字符串，内核在 `open` 时才去解析它。解析失败给 `ENOENT`，但链接本身完好。这和 C 里「指针可以悬空」是同一个设计取向：**把解析推迟到使用时**。

**Q3：硬链接指向目录为什么被禁？**
A：防环。目录树若允许任意成环，`..` 向上走、`nftw` 遍历、路径解析都可能不终止。内核内部有 `.`/`..` 这两个特例，但用户态 `link()` 一律 `EPERM`。

**Q4：`ELOOP` 的 40 是 POSIX 规定的吗？**
A：不是。POSIX 只定义 `ELOOP` 这个错误，上限是实现的（Linux `MAXSYMLINKS=40`，macOS 实测也是 40）。写代码只能当作「有上限」，不能假设具体值。

**Q5：`lstat` 看到的符号链接 `st_uid` 有什么用？**
A：Linux 上几乎没有用（权限从不看它），只有 sticky 目录里「谁能删这个链接」会用到；macOS 上链接有自己的属主三元组。跨平台代码不要依赖。

**Q6：怎么判断「一个链接是否悬空」？**
A：`lstat` 成功 + `stat` 失败（`ENOENT`）。两步都做，缺一不可：只 `stat` 失败区分不了「链接本身不存在」和「链接在但目标没了」。

</details>
