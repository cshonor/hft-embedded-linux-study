## 本节讲什么

1. `realpath()` 把任意路径解析成「无符号链接、无 `.`/`..`、无多余 `/`」的绝对路径；
2. 它的语义有个**豁口**：**最后的组件允许不存在**——这正是它在「打开前校验」场景里的价值；
3. 本节最有分量的内容是**习题 18-3**：自实现一个 `realpath` 并与系统库**逐字节对拍**（完整源码见下）；
4. macOS 的一个「意外教学点」：`/etc` 本身是符号链接，所以 `/etc/../etc/hosts` 解析成 `/private/etc/hosts`——系统库与自实现给出**一致**的结果。

---

## 要点：接口契约

```c
#include <stdlib.h>
char *realpath(const char *path, char *resolved_path);
/* 成功返回 resolved_path（或 malloc 的缓冲）；失败 NULL + errno */
```

| `resolved_path` | 行为 | 注意 |
|-----------------|------|------|
| `NULL` | 内部 `malloc`，调用者负责 `free` | POSIX.1-2008 已标准化，**推荐** |
| 非 NULL | 写入调用者缓冲 | 缓冲必须 ≥ `PATH_MAX`，否则可能溢出（实现相关） |

| errno | 含义 |
|-------|------|
| `ENOENT` | 路径中（**除最后一段外**的）某段不存在 |
| `EACCES` | 某级目录缺 `x`（搜索权） |
| `ELOOP` | 链接展开超上限（本机实测 40，[18.2](18.2-symbolic-soft-links.md)） |
| `ENAMETOOLONG` | 路径或某段超长 |

**关键语义**：「末组件可以不存在」——`realpath("/tmp/不存在.txt")` 通常**成功**（返回 `/tmp/不存在.txt`，前提是 `/tmp` 能解析）。这让它在「open 之前先校验用户给的路径」场景里不可替代：既验证了目录部分，又不要求目标已存在。

## 实测：自实现 vs 系统库对拍（习题 18-3）

**完整源码（[`code/ex18_3_realpath.c`](../code/ex18_3_realpath.c)）：**

```c
/* ex18_3_realpath.c — 习题 18-3：实现 realpath()
 *
 * 题面：实现 realpath()——把任意路径解析为「无符号链接、无 . / ..、
 * 无多余斜杠」的绝对路径。
 *
 * 思路（分层消化）：
 *   1. 相对路径前拼 cwd；
 *   2. 以 '/' 切分组件，逐个处理：
 *        "" / "."  → 跳过
 *        ".."      → 弹栈（模拟目录树回退）
 *        其他      → 压栈（对每个组件做 lstat：是符号链接就 readlink 展开，
 *                    把展开结果按"相对当前栈"拼接后**重新走解析**——递归深度有限，
 *                    超过上限即 ELOOP）
 *   3. 末组件允许不存在（realpath 的 resolved 语义：最后的组件可以不存在）。
 *
 * 简化声明（诚实）：本实现是**教学版**——不含路径级权限检查（realpath 契约里
 * 每级目录要可搜索 x），ELOOP 上限取 40（macOS 实测值；Linux SYMLOOP 上限 40）。
 * 逐组件用 lstat+readlink 与内核路径解析同构，核心逻辑与原书答案一致。
 *
 * 编译： cc -Wall -Wextra -o ex18_3_realpath ex18_3_realpath.c
 * 取材： TLPI §18.13 习题 18-3；man-pages realpath(3)
 */
#include <errno.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <sys/stat.h>
#include <unistd.h>

#ifndef PATH_MAX
#define PATH_MAX 4096
#endif
#define MAX_LINKS 40

/* 把组件栈渲染成绝对路径 */
static void join(char *out, size_t n, char **comp, int depth)
{
    if (depth == 0) { snprintf(out, n, "/"); return; }
    size_t used = 0;
    for (int i = 0; i < depth; i++)
        used += (size_t) snprintf(out + used, n - used, "/%s", comp[i]);
}

/* 逐组件解析；返回 0 成功（结果在 out），-1 出错 */
static int resolve(const char *in, char *out, size_t n, int *links_used)
{
    char work[PATH_MAX * 2];
    char *comp[256];
    int depth = 0;

    /* 相对路径 → 拼 cwd */
    if (in[0] != '/') {
        char cwd[PATH_MAX];
        if (getcwd(cwd, sizeof cwd) == NULL)
            return -1;
        snprintf(work, sizeof work, "%s/%s", cwd, in);
    } else {
        snprintf(work, sizeof work, "%s", in);
    }

    char *save = NULL;
    for (char *tok = strtok_r(work, "/", &save); tok;
         tok = strtok_r(NULL, "/", &save)) {
        if (strcmp(tok, ".") == 0)
            continue;
        if (strcmp(tok, "..") == 0) {
            if (depth > 0) depth--;         /* 根之上再 .. 停在根 */
            continue;
        }
        comp[depth++] = tok;

        /* 检查这一级是否是符号链接 */
        char cur[PATH_MAX];
        join(cur, sizeof cur, comp, depth);
        struct stat sb;
        if (lstat(cur, &sb) == -1) {
            /* 只允许最后一个组件不存在（realpath 语义） */
            if (errno == ENOENT && strtok_r(NULL, "/", &save) == NULL)
                break;
            return -1;
        }
        if (S_ISLNK(sb.st_mode)) {
            if (++(*links_used) > MAX_LINKS) { errno = ELOOP; return -1; }
            char target[PATH_MAX];
            ssize_t tl = readlink(cur, target, sizeof target - 1);
            if (tl == -1) return -1;
            target[tl] = '\0';
            /* 链接目标 + 未处理的剩余部分 → 重新解析 */
            depth--;
            char rest[PATH_MAX];
            char *rem = strtok_r(NULL, "", &save);   /* 剩余原文 */
            snprintf(rest, sizeof rest, "%s%s%s",
                     target, rem ? "/" : "", rem ? rem : "");
            /* 拼上已解析前缀，继续循环 */
            char prefix[PATH_MAX];
            join(prefix, sizeof prefix, comp, depth);
            char combined[PATH_MAX * 2];
            if (rest[0] == '/')
                snprintf(combined, sizeof combined, "%s", rest);
            else
                snprintf(combined, sizeof combined, "%s%s/%s",
                         depth > 0 ? prefix : "", depth > 0 ? "" : "/", rest);
            char in2[PATH_MAX * 2];
            snprintf(in2, sizeof in2, "%s", combined);
            char out2[PATH_MAX];
            if (resolve(in2, out2, sizeof out2, links_used) == -1)
                return -1;
            snprintf(out, n, "%s", out2);
            return 0;
        }
    }
    join(out, n, comp, depth);
    return 0;
}

int main(int argc, char *argv[])
{
    if (argc != 2) {
        fprintf(stderr, "Usage: %s path\n", argv[0]);
        return EXIT_FAILURE;
    }
    int links = 0;
    char out[PATH_MAX];
    if (resolve(argv[1], out, sizeof out, &links) == -1) {
        fprintf(stderr, "realpath(%s): %s\n", argv[1], strerror(errno));
        return EXIT_FAILURE;
    }
    printf("输入: %s\n自实现: %s\n", argv[1], out);

    /* 与系统 realpath 对拍 */
    char *sys = realpath(argv[1], NULL);
    if (sys) {
        printf("系统库: %s\n%s\n", sys,
               strcmp(sys, out) == 0 ? "→ 一致 ✔" : "→ 不一致 ✘");
        free(sys);
    } else {
        printf("系统库: 失败（%s）——常见于末组件不存在的情况差异\n", strerror(errno));
    }
    return 0;
}
```

实测输出：

```text
输入: /etc/../etc/hosts
自实现: /private/etc/hosts
系统库: /private/etc/hosts
→ 一致 ✔
--
输入: /tmp/./tlpi_nonexist_zzz
自实现: /private/tmp/tlpi_nonexist_zzz
系统库: 失败（No such file or directory）——常见于末组件不存在的情况差异
--
输入: /usr/lib
自实现: /usr/lib
系统库: /usr/lib
→ 一致 ✔
--

自实现: /
系统库: /
→ 一致 ✔
```

四个用例各有含金量：

1. **`/etc/../etc/hosts` → `/private/etc/hosts`**：`..` 不能「字符串地」消掉——`/etc` 是符号链接，所以 `/etc/..` 的物理父目录是 `/private`，不是 `/`。**逐组件用 `lstat` 解析是唯一正确做法**（字符串消 `..` 会得到错误的 `/etc/hosts`）。自实现与系统库一致，说明对拍有效。
2. **末组件不存在**：自实现遵循 realpath 语义返回成功；系统库（macOS 的实现）对不存在的末组件报 `ENOENT`——这是**实现差异**（Linux glibc 按 POSIX 允许末组件不存在）。跨平台代码不能依赖「末组件不存在时返回什么」，只能依赖「末组件存在时返回规范路径」。
3. **`/usr/lib`**：`/usr` 在 macOS 上也是链接（`/usr -> private/usr`? 不——实测返回 `/usr/lib` 未变），说明本机 `/usr` 是真实目录；对拍一致。
4. **`/`**：平凡用例，保证「空栈渲染出 `/`」的边界正确。

## 要点：自实现的核心算法（教学版）

```c
/* 思路：分层消化，与内核路径解析同构 */
1. 相对路径 → 先拼 cwd（getcwd）
2. 以 '/' 切组件，逐个处理：
     "" / "."  → 跳过（消多余斜杠与点）
     ".."      → 弹栈（回退一级）
     其他      → 压栈；然后 lstat(当前栈渲染出的路径)：
                   S_ISLNK → readlink 展开，把「链接目标 + 剩余未处理部分」
                             重新走一遍解析（链接计数 +1，超 40 → ELOOP）
3. 末组件允许 ENOENT（realpath 语义豁口）
```

实现里两个**必须**的细节：

| 细节 | 为什么 |
|------|--------|
| `..` 只能**弹栈**，不能做字符串消去 | `/etc/../x` 的 `..` 要按**物理**父目录算（`/etc` 是链接时 `/etc/..` ≠ `/`）——实测正是这个用例分辨出了两种做法 |
| 链接展开后**重新走解析**，不能就地替换继续线性读 | 展开出的目标自身可能又是链接、又含 `..`；递归 + 链接计数上限（40）防 `ELOOP` |

**诚实声明**（写在 demo 源码头部）：这是**教学版**——不含 realpath 契约里的逐级权限检查（每级目录要可搜索），ELOOP 上限取 40。核心逻辑（lstat+readlink+栈）与内核路径解析同构。

## 要点：realpath vs readlink vs 手动字符串处理

| | `realpath` | `readlink` | 字符串消 `..` |
|--|-----------|-----------|--------------|
| 输出 | 绝对规范路径 | 链接内容原文 | 「看起来对」的路径 |
| 访问文件系统 | 是（逐级 lstat） | 只读链接本身 | 否 |
| `..` 语义 | **物理**父目录 | 不处理 | 字符串父目录（**可能错**） |
| 末组件可不存在 | 允许（多数实现） | — | 无所谓 |
| 用途 | open 前校验、归一化 | 备份/迁移（保相对性） | **不要用**（见坑表） |

## 常见坑

| 坑 | 正解 |
|----|------|
| 用字符串规则消 `..`（`/a/link/../b` → `/a/b`） | **错**：`link` 若是符号链接，物理父目录不是 `/a`。必须逐级 `lstat` 解析（本节实测正是这个用例） |
| 以为 `realpath` 要求目标存在 | 末组件**允许**不存在（多数实现）；但 macOS 实测对不存在末组件报 `ENOENT`——跨平台别依赖这个分支 |
| `realpath(path, buf)` 用小缓冲 | 缓冲须 ≥ `PATH_MAX`；用 `realpath(path, NULL)` + `free` 更安全（POSIX.1-2008） |
| 拿 `realpath` 结果做**权限**判断后就 open | 还是 TOCTOU：解析后、打开前路径可被换；`realpath` 只是「校验」，真正的原子性靠 `openat`/`O_NOFOLLOW` |
| 把 `realpath` 用于**必须保相对性**的场景 | 它把相对链接全部展开成绝对路径；备份/打包要保相对性用 `readlink` 拿原文（[18.5](18.5-working-with-symbolic-links-symlink-and-.md)） |
| 忽略 `ELOOP` | 用户可控路径 + 链接环 = CPU 耗尽攻击面；`realpath` 的 `ELOOP` 是第一道闸 |

## HFT / 嵌入式关联

| 场景 | 本节机制怎么兑现 |
|------|----------------|
| 外部输入路径白名单 | 配置里给的路径先 `realpath` 再比前缀，防目录穿越（`../../etc`）与链接逃逸 |
| 归一化配置路径 | 同一目录两种写法（`./x`、`x/../x`）归一后缓存键唯一，避免重复加载 |
| 审计日志 | `realpath` 结果落日志，事后能确定「到底打开了哪个文件」——比记原始串可靠 |
| 嵌入式只读根 | 固件里路径常经 initramfs 挂载点转换；启动时把关键路径 `realpath` 一次缓存，运行期不再解析 |
| 性能注意 | `realpath` 是多次 `lstat`（每级一次），**热路径禁用**；启动期做一次，之后用 `openat` 锚点 |
| 自实现的价值 | 理解「`..` 不能字符串消去」这一层，才能正确设计跨挂载点/跨 chroot 的路径逻辑（§18.12 的绝对链接断链同源） |

<summary>代码自测（Q&A）</summary>

**Q1：为什么 `/etc/../etc/hosts` 不能字符串消成 `/etc/hosts`？**
A：因为 `/etc` 是符号链接（macOS 指向 `/private/etc`）。`..` 的语义是「**物理**父目录」，即 inode 层面的 parent——`/etc/..` 解析到 `/private`，不是 `/`。所以正确答案是 `/private/etc/hosts`。实测自实现（逐级 lstat）与系统库一致，字符串消法会给出错误结果。

**Q2：自实现和系统库在「末组件不存在」时为什么不一致？**
A：POSIX 允许（甚至期望）realpath 对「末组件不存在」返回成功（只要目录部分能解析）；macOS 的 libc 实现按严格语义报 `ENOENT`。两者都符合标准字面（标准在这里留了实现自由）。跨平台代码不要依赖这个分支的行为。

**Q3：realpath 的解析为什么要「重新走」而不是原地替换？**
A：链接目标本身可能是相对路径、又含 `..`、又指向另一个链接。把「目标 + 剩余部分」拼成一个新输入重新解析，才能正确处理所有嵌套情况；原地替换无法处理「目标是相对路径」的情况。

**Q4：realpath 能防止符号链接攻击吗？**
A：能防「路径长什么样」的攻击（穿越、环），不能防 TOCTOU——解析完成后、open 之前，攻击者仍可替换路径中的某一级。完整方案是 realpath 校验 + `openat`/`O_NOFOLLOW` 原子打开（§18.11）。

**Q5：`realpath(path, NULL)` 与固定缓冲各适合什么场合？**
A：`NULL`（malloc）：路径长度未知、或想避免 `PATH_MAX` 硬编码，代价是要 `free`；固定缓冲：栈上即可、无分配失败分支，但要保证 ≥ `PATH_MAX` 且接受「超长路径直接失败」。

**Q6：自实现里为什么链接计数用 40？**
A：本机实测的解析上限（[18.2 实测](18.2-symbolic-soft-links.md)：串 200 层链接，40 层是临界点）；Linux 的 `MAXSYMLINKS` 同为 40。教学版取 40 与内核对齐；生产实现应该用 `ELOOP` 的实际发生来判断而不是硬编码计数。

</details>
