## 本节讲什么

`*at()` 族是 Linux 2.6.16 引入、POSIX.1-2008 收编的一整族接口。它解决两个老接口的结构性缺陷：

1. **TOCTOU**：`chdir(dir)` 与 `open("file")` 之间，目录可以被换掉；
2. **进程级全局状态**：cwd 是进程属性，多线程共享，谁都能搅局。

`*at()` 把「基准」从进程属性（cwd）变成**一个 fd**——锚点打开即固定，之后所有操作都相对它。本节还实测 `openat` 与 cwd 的解耦。

---

## 要点：*at() 族对照表

| *at() 版本 | 老 API | flags 参数 |
|-----------|--------|-----------|
| `openat` | `open` | 无（`O_NOFOLLOW` 走 open 的 flags） |
| `fstatat` | `stat`/`lstat`/`fstat` | `AT_SYMLINK_NOFOLLOW`（= lstat）、`AT_EMPTY_PATH`（Linux，= fstat） |
| `unlinkat` | `unlink`/`rmdir` | `AT_REMOVEDIR`（= rmdir） |
| `renameat` / `renameat2` | `rename` | `renameat2`：`RENAME_EXCHANGE`/`RENAME_NOREPLACE`（Linux 专有） |
| `linkat` | `link` | `AT_SYMLINK_FOLLOW`、`AT_EMPTY_PATH`（Linux） |
| `symlinkat` / `readlinkat` | `symlink`/`readlink` | 无 |
| `mkdirat` / `mknodat` / `fchmodat` / `fchownat` / `faccessat` / `futimensat` | 同名老接口 | 各有若干 |

**`dirfd` 参数的语义**（全部 *at 共用）：

| `dirfd` | `pathname` | 行为 |
|---------|-----------|------|
| `AT_FDCWD` | 相对路径 | 相对 cwd（等价老 API） |
| `AT_FDCWD` | 绝对路径 | 忽略 dirfd |
| 有效目录 fd | 相对路径 | **相对该目录** |
| 有效目录 fd | 绝对路径 | 忽略 dirfd（绝对路径总是从 `/` 开始） |

## 实测：openat 与 cwd 解耦（[`code/c18_4_cwd.c`](../code/c18_4_cwd.c)）

```text
== ④ open(".") 的目录 fd 也是 openat 的锚点（§18.11）==
  openat(/tmp 的 fd, "tlpi_c18_4.txt") = 5（相对锚点，不受 cwd 影响）
  ⚠️ openat 防的是「cwd 被别人改走」与 TOCTOU：锚点一旦打开即固定。
```

这个 demo 的上下文：之前已经 `chdir("/")`，此时拿**早先打开的 `/tmp` 目录 fd** 去 `openat`——文件出现在 `/tmp` 里，与当前 cwd 无关。**这就是「锚点即固定」的直接证据**。

## 实测：unlinkat 的两种模式（[`code/c18_6_mkdir_rmdir.c`](../code/c18_6_mkdir_rmdir.c)）

```text
== ④ unlinkat(AT_REMOVEDIR) == rmdir ==
  unlinkat(dfd, "f", 0)             = 0 
  unlinkat(dfd, "sub", AT_REMOVEDIR)   = 0 
```

`flags=0` 删文件（等价 `unlink`），`AT_REMOVEDIR` 删空目录（等价 `rmdir`）。**一个接口覆盖了两个老接口**，且都以「目录 fd 为锚」——递归删除时再也不用拼路径串（对比 §18.9 里「回调路径串可能超长」的坑）。

## 要点：TOCTOU 的三段式与 *at() 的破法

老写法的竞态窗口：

```c
/* ✗ 三步之间，dir 可以被改名/换成符号链接 */
struct stat sb;
stat("/srv/data/config", &sb);      /* 1. 检查 */
chdir("/srv/data");                 /* 2. 进入 —— 这里 dir 可能已被换 */
int fd = open("config", O_RDONLY);  /* 3. 使用 —— 打开的可能已是别的东西 */
```

`*at()` 的破法：**把「进入」变成「持有一个引用」**。

```c
/* ✓ 锚点打开后不可替换（fd 指向 inode，不指向路径） */
int dirfd = open("/srv/data", O_RDONLY | O_DIRECTORY);   /* 唯一的路径检查点 */
struct stat sb;
fstatat(dirfd, "config", &sb, 0);
int fd = openat(dirfd, "config", O_RDONLY);
```

配合 `O_NOFOLLOW`（open 时拒绝链接）与 `fstatat(AT_SYMLINK_NOFOLLOW)`，可以把「用户可控路径」的攻击面压到只剩**一次** `open`。

> **更彻底的口诀（TLPI 反复强调）**：先 `open`（拿到 fd = 拿到 inode），再对 fd 做一切操作（`fstat`/`fchmod`/`fchown`/`futimens`）。路径解析只发生一次，后面全是 inode 级操作，无竞态可言。

## 要点：openat 的性能红利

| 场景 | 老接口 | *at() 接口 |
|------|--------|-----------|
| 深层目录批量操作 | 每个文件都要全路径解析（逐级查目录） | 锚点 fd 已在深处，只解析最后一段 |
| 遍历 + 打开 | 拼串 + 全路径 `open` | `dirfd` 从 `readdir` 的目录直接 `openat(e->d_name)` |
| 多线程 | cwd 全局竞争 | 每线程/每模块自己的锚点 fd，零竞争 |

对海量小文件（行情落盘、日志分片）的场景，`*at()` 不是「安全选配」而是**吞吐量来源**——路径解析是 `namei` 层的锁与 dcache 查找，省一次全路径就是省一串操作。

## 常见坑

| 坑 | 正解 |
|----|------|
| `openat(dirfd, "/abs/path", ...)` 期望「相对 dirfd + 绝对回退」 | 绝对路径**完全忽略** dirfd；要「回退到 cwd」语义就显式传 `AT_FDCWD` |
| 以为 `AT_FDCWD` 是「安全默认值」 | 它等价老 API，**没有任何防 TOCTOU 能力**；用它就等于没用 *at |
| `openat` 后忘了 `close(dirfd)` | 锚点 fd 泄漏；长跑进程要审计，建议用 RAII/defer 包装 |
| 用 `faccessat(AT_FDCWD, path, W_OK)` 检查再 `open` | 还是 TOCTOU（且 `access` 有 euid/ruid 混淆坑，见 [15 章](../../chapter-15-file-attributes/README.md)）；直接 `open` + 检查返回值 |
| `unlinkat` 删目录忘了 `AT_REMOVEDIR` | 报 `EISDIR`(Linux)/`EPERM`(macOS)；与「忘了 flags」的报错区分开 |
| 以为 `*at()` 在 macOS 上全有 | 核心几个有（`openat`/`fstatat`/`unlinkat`/`renameat`...），但 `renameat2`、`AT_EMPTY_PATH` 等 Linux 扩展没有；跨平台要留降级路径 |
| 用「打开目录 fd」当**锁** | 打开不互斥；互斥用 `O_CREAT\|O_EXCL` 建锁文件或 `link()` 的 `EEXIST` |

## HFT / 嵌入式关联

| 场景 | 本节机制怎么兑现 |
|------|----------------|
| 启动锚点模式 | `main` 打开业务根目录 fd（如 `/var/data/quotes`），之后全部 `openat(anchor, rel)`——运维从任何 cwd 启动行为一致 |
| 海量小文件吞吐 | 行情按 tick 分文件：`openat(dayfd, "HHMMSS.bin")` 省掉全路径解析；深层目录收益最大 |
| 多线程零竞争 | 每个模块持自己的目录 fd，cwd 从此是只读变量；`chdir` 从代码规范里整个删掉 |
| 安全网关 | 接收外部路径的入口统一「`openat(anchor, rel, O_NOFOLLOW)` → 失败即拒绝」，TOCTOU 与符号链接攻击一起挡 |
| 嵌入式递归删除 | `unlinkat(dirfd, name, AT_REMOVEDIR)` 按锚点删，不需要拼接超长路径（对比 §18.9 的 `PATH_MAX` 坑） |
| 容器/沙箱 | `openat` 配合 `O_PATH`（Linux）实现受限文件访问；macOS 无 `O_PATH`，用 `O_RDONLY|O_DIRECTORY` 等价替代 |

<details>
<summary>代码自测（Q&A）</summary>

**Q1：`openat(AT_FDCWD, "x", O_RDONLY)` 和 `open("x", O_RDONLY)` 有区别吗？**
A：没有。`AT_FDCWD` 就是「用 cwd」，两条完全等价（内核走同一条路径）。所以「为了用 *at 而用 AT_FDCWD」是自我安慰——防 TOCTOU 的前提是**传入真实的目录 fd**。

**Q2：锚点 fd 为什么「不可替换」？**
A：fd 在打开时就绑定到了具体 inode（`open` 完成解析后引用计数 +1）。之后把那个路径改名、删除、甚至换成符号链接，fd 指向的 inode 不变。这正是 §18.3「unlink 后 fd 仍可读」的同一机制。

**Q3：`fstatat(AT_SYMLINK_NOFOLLOW)` 和 `lstat` 完全等价吗？**
A：语义等价（都不跟随），但 `fstatat` 多了锚定能力：可以「相对某目录 fd 判断类型」，`lstat` 只能全路径。在遍历中配合 `readdir` 使用时，`fstatat(dirfd, name, AT_SYMLINK_NOFOLLOW)` 比「拼串 + lstat」既快又无竞态。

**Q4：`openat` 打开目录 fd 时需要什么 flags？**
A：`O_RDONLY|O_DIRECTORY` 是可移植写法（macOS 无 `O_PATH`）。Linux 上 `O_PATH|O_DIRECTORY` 更强（不做权限检查、不能 read 但能当锚点和 `fchdir`）。跨平台代码用前者。

**Q5：为什么说 *at() 族「把 cwd 从代码里删掉了」？**
A：因为所有路径操作都可以改写成 `*at(anchor, ...)` 形式，cwd 从此与逻辑无关——运维从哪个目录启动、哪个线程 chdir 了，都不影响行为。这是一种**消除全局状态**的重构，价值不亚于安全性本身。

**Q6：`AT_EMPTY_PATH` 是什么？macOS 有吗？**
A：Linux 扩展：`pathname` 传空串时操作**fd 本身**指向的对象（如 `fstatat(fd, "", &sb, AT_EMPTY_PATH)` = `fstat(fd, &sb)`）。macOS 没有。对 fd 的操作在 macOS 上要用对应的 `f` 版接口（`fstat`/`fchmod`/...）。

</details>
