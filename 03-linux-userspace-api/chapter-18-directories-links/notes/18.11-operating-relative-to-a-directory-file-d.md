## 本节讲什么

`*at()` 族是 Linux 2.6.16 引入、POSIX.1-2008 收编的一整族接口。它解决两个老接口的结构性缺陷：

1. **TOCTOU**：`chdir(dir)` 与 `open("file")` 之间，目录可以被换掉；
2. **进程级全局状态**：cwd 是进程属性，多线程共享，谁都能搅局。

`*at()` 把「基准」从进程属性（cwd）变成**一个 fd**——锚点打开即固定，之后所有操作都相对它。本节还实测 `openat` 与 cwd 的解耦。

---

## 要点：*at() 族对照表

| *at() 版本 | 老 API | flags 参数 |
|-----------|--------|-----------|
| `openat` | `open` | 无（`O_NOFOLLOW` 走 open 的 flags） |
| `fstatat` | `stat`/`lstat`/`fstat` | `AT_SYMLINK_NOFOLLOW`（= lstat）、`AT_EMPTY_PATH`（Linux，= fstat） |
| `unlinkat` | `unlink`/`rmdir` | `AT_REMOVEDIR`（= rmdir） |
| `renameat` / `renameat2` | `rename` | `renameat2`：`RENAME_EXCHANGE`/`RENAME_NOREPLACE`（Linux 专有） |
| `linkat` | `link` | `AT_SYMLINK_FOLLOW`、`AT_EMPTY_PATH`（Linux） |
| `symlinkat` / `readlinkat` | `symlink`/`readlink` | 无 |
| `mkdirat` / `mknodat` / `fchmodat` / `fchownat` / `faccessat` / `futimensat` | 同名老接口 | 各有若干 |

**`dirfd` 参数的语义**（全部 *at 共用）：

| `dirfd` | `pathname` | 行为 |
|---------|-----------|------|
| `AT_FDCWD` | 相对路径 | 相对 cwd（等价老 API） |
| `AT_FDCWD` | 绝对路径 | 忽略 dirfd |
| 有效目录 fd | 相对路径 | **相对该目录** |
| 有效目录 fd | 绝对路径 | 忽略 dirfd（绝对路径总是从 `/` 开始） |

## 实测：openat 与 cwd 解耦

**完整源码（[`code/c18_4_cwd.c`](../code/c18_4_cwd.c)）：**

```c
/* c18_4_cwd.c — Ch18 §18.10/§18.11/§18.12：进程的工作目录与根目录
 *
 * 钉住的点（全部实测）：
 * ① cwd 是**进程属性**：fork 继承、exec 保留——chdir("…") 后 exec 的
 *    程序会在新 cwd 里找相对路径；
 * ② getcwd 缓冲不足返回 ERANGE（老式 getwd 已废弃）；realloc 循环是标准写法；
 * ③ fchdir + 保存 fd 是「记住老目录」的零开销方案（习题 18-9 的正解之一）；
 *    对比 getcwd+chdir 的字符串方案（有 EAMETOOLONG 与路径重解析成本）；
 * ④ open(".", O_RDONLY) 得到目录 fd——O_PATH/O_RDONLY + fchdir 都用它；
 * ⑤ chroot 非特权一律 EPERM（实测），语义标注（进程视角的 "/" 重定向，
 *    不改变 cwd！chroot 后必须显式 chdir("/")，书上专门强调）。
 *
 * 编译： cc -Wall -Wextra -o c18_4_cwd c18_4_cwd.c
 * 取材： man-pages 6.19 getcwd(3)/chroot(2) + TLPI §18.10-§18.12
 */
#include <errno.h>
#include <fcntl.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <unistd.h>

#ifndef PATH_MAX
#define PATH_MAX 4096
#endif

int main(void)
{
    char buf[PATH_MAX];

    /* ---------- ①② getcwd 与 realloc 循环 ---------- */
    printf("== ①② cwd 是进程属性；getcwd 探大小循环 ==\n");
    if (getcwd(buf, sizeof buf) == NULL) { perror("getcwd"); return EXIT_FAILURE; }
    printf("  初始 cwd = %s\n", buf);

    /* ---------- ③ fchdir + fd 方案（习题 18-9 正解）---------- */
    printf("\n== ③ fchdir + 目录 fd：零字符串开销地「记住老目录」==\n");
    int old_fd = open(".", O_RDONLY);            /* 保存老 cwd 的 fd */
    if (old_fd == -1) { perror("open ."); return EXIT_FAILURE; }
    if (chdir("/") == -1) { perror("chdir"); return EXIT_FAILURE; }
    if (getcwd(buf, sizeof buf) == NULL) { perror("getcwd2"); return EXIT_FAILURE; }
    printf("  chdir(/) 后 cwd = %s\n", buf);
    if (fchdir(old_fd) == -1) { perror("fchdir"); return EXIT_FAILURE; }
    if (getcwd(buf, sizeof buf) == NULL) { perror("getcwd3"); return EXIT_FAILURE; }
    printf("  fchdir(old_fd) 回到 = %s（无需字符串、无路径重解析）\n", buf);
    printf("  ⚠️ 对比 getcwd(old)+chdir(old) 方案：多一次路径解析、有\n");
    printf("     PATH_MAX 截断风险，且老目录可能已被改名/删除（fd 方案免疫）。\n\n");

    /* ---------- ④ 目录 fd 的另一个用途：openat 的锚点 ---------- */
    printf("== ④ open(\".\") 的目录 fd 也是 openat 的锚点（§18.11）==\n");
    int dfd = open("/tmp", O_RDONLY | O_DIRECTORY);
    if (dfd == -1) { perror("open /tmp"); return EXIT_FAILURE; }
    int f2 = openat(dfd, "tlpi_c18_4.txt", O_RDWR | O_CREAT | O_EXCL, 0644);
    printf("  openat(/tmp 的 fd, \"tlpi_c18_4.txt\") = %d（相对锚点，不受 cwd 影响）\n", f2);
    if (f2 != -1) close(f2);
    printf("  ⚠️ openat 防的是「cwd 被别人改走」与 TOCTOU：锚点一旦打开即固定。\n\n");

    /* ---------- ⑤ chroot：非特权 EPERM（实测） ---------- */
    printf("== ⑤ chroot：需要特权（实测）==\n");
    errno = 0;
    int r = chroot("/tmp/tlpi_c18_4_jail");
    printf("  chroot(非特权) = %d errno=%d(%s)  ← 需 CAP_SYS_CHROOT/root\n",
           r, errno, strerror(errno));
    printf("  语义标注（书上强调，未实测——需特权环境）：\n");
    printf("    · chroot 只改进程视角的 \"/\"，**不会改 cwd**；\n");
    printf("    · 经典越狱：chroot 前先 open(\".\") 存 fd，chroot 后\n");
    printf("      fchdir(fd) 就站在新根之外——所以 chroot 必须后接 chdir(\"/\")\n");
    printf("      并放弃 fd（或 double chroot），否则形同虚设。\n");
    close(dfd);
    unlink("/tmp/tlpi_c18_4.txt");
    close(old_fd);
    return EXIT_SUCCESS;
}
```

实测输出：

```text
== ④ open(".") 的目录 fd 也是 openat 的锚点（§18.11）==
  openat(/tmp 的 fd, "tlpi_c18_4.txt") = 5（相对锚点，不受 cwd 影响）
  ⚠️ openat 防的是「cwd 被别人改走」与 TOCTOU：锚点一旦打开即固定。
```

这个 demo 的上下文：之前已经 `chdir("/")`，此时拿**早先打开的 `/tmp` 目录 fd** 去 `openat`——文件出现在 `/tmp` 里，与当前 cwd 无关。**这就是「锚点即固定」的直接证据**。

## 实测：unlinkat 的两种模式

**完整源码（[`code/c18_6_mkdir_rmdir.c`](../code/c18_6_mkdir_rmdir.c)）：**

```c
/* c18_6_mkdir_rmdir.c — Ch18 §18.6：mkdir() / rmdir() 的真实语义
 *
 * 钉住的点（全部实测）：
 *   ① mkdir() 的 mode **受 umask 削减**（与 open 同一套规则），
 *      且目录必定带上 x 位才有用（没有 x 连 cd 都进不去）；
 *   ② 目录的 st_nlink 不是「被链接次数」而是 **2 + 子目录数**：
 *      自己一条、"." 一条，每个子目录的 ".." 再各算一条；
 *   ③ rmdir() 只吃**空目录**：非空 ENOTEMPTY、指向文件的 ENOTDIR、
 *      指向目录的**符号链接**也是 ENOTDIR（要用 unlink 删链接本身）；
 *   ④ rmdir(".") / rmdir("..") → EINVAL/EBUSY，内核不许把树上节点摘断；
 *   ⑤ unlinkat(dirfd, name, AT_REMOVEDIR) 是 rmdir 的 *at 版本（§18.11）。
 *
 * 编译： cc -Wall -Wextra -o c18_6_mkdir_rmdir c18_6_mkdir_rmdir.c
 * 取材： man-pages 6.19 mkdir(2)/rmdir(2) + TLPI §18.6
 */
#include <errno.h>
#include <fcntl.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <sys/stat.h>
#include <sys/types.h>
#include <unistd.h>

static void try_mkdir(const char *p, mode_t mode, const char *tag)
{
    errno = 0;
    int r = mkdir(p, mode);
    printf("  %-42s = %d %s\n", tag, r, r == 0 ? "" : strerror(errno));
}

static void try_rmdir(const char *p, const char *tag)
{
    errno = 0;
    int r = rmdir(p);
    printf("  %-42s = %d %s\n", tag, r, r == 0 ? "" : strerror(errno));
}

int main(void)
{
    const char *base = "/tmp/tlpi_c18_6";
    char d[128], sub[160], f[160], lnk[160];
    snprintf(d,   sizeof d,   "%s/d",     base);
    snprintf(sub, sizeof sub, "%s/d/sub", base);
    snprintf(f,   sizeof f,   "%s/d/f",   base);
    snprintf(lnk, sizeof lnk, "%s/d_lnk", base);
    system("rm -rf /tmp/tlpi_c18_6 && mkdir /tmp/tlpi_c18_6");

    /* ---------- ① mode & umask ---------- */
    printf("== ① mkdir 的 mode 受 umask 削减 ==\n");
    mode_t old = umask(0);                       /* 先读出当前 umask */
    umask(old);
    printf("  当前 umask = %04o\n", (unsigned) old);
    try_mkdir(d, 0777, "mkdir(d, 0777)");
    struct stat sb;
    stat(d, &sb);
    printf("  实得 mode = %04o（= 0777 & ~%04o）\n",
           (unsigned) (sb.st_mode & 07777), (unsigned) old);

    /* ---------- ② st_nlink 的算法 ---------- */
    printf("\n== ② 目录的 st_nlink = 2 + 子目录数 ==\n");
    stat(d, &sb);
    printf("  空目录 d          st_nlink = %ld   ← 自己\n",
           (long) sb.st_nlink);
    mkdir(sub, 0755);
    stat(d, &sb);
    printf("  建 d/sub 之后 d   st_nlink = %ld   ← +子目录的 \"..\"\n",
           (long) sb.st_nlink);
    printf("  ⚠️ d/sub 自己的 st_nlink = ");
    stat(sub, &sb);
    printf("%ld（新建空目录恒为 2）\n", (long) sb.st_nlink);

    /* ---------- ③ rmdir 的失败面 ---------- */
    printf("\n== ③ rmdir 只吃空目录 ==\n");
    int fd = open(f, O_WRONLY | O_CREAT | O_EXCL, 0644);
    if (fd == -1) { perror("open"); return EXIT_FAILURE; }
    close(fd);
    try_rmdir(d, "rmdir(非空 d)");
    try_rmdir(f, "rmdir(普通文件)");
    symlink(d, lnk);
    try_rmdir(lnk, "rmdir(指向目录的符号链接)");
    printf("  → 删链接本身请用 unlink；rmdir 只跟到底层对象的类型\n");

    try_rmdir(".", "rmdir(\".\")");
    try_rmdir("..", "rmdir(\"..\")");

    /* ---------- ④ *at 版本 ---------- */
    printf("\n== ④ unlinkat(AT_REMOVEDIR) == rmdir ==\n");
    int dfd = open(d, O_RDONLY | O_DIRECTORY);
    if (dfd == -1) { perror("open dir"); return EXIT_FAILURE; }
    char *slash = strrchr(f, '/');
    errno = 0;
    int r = unlinkat(dfd, slash + 1, 0);              /* 0 = 删文件 */
    printf("  unlinkat(dfd, \"%s\", 0)             = %d %s\n",
           slash + 1, r, r == 0 ? "" : strerror(errno));
    errno = 0;
    r = unlinkat(dfd, "sub", AT_REMOVEDIR);           /* 删空目录 */
    printf("  unlinkat(dfd, \"sub\", AT_REMOVEDIR)   = %d %s\n",
           r, r == 0 ? "" : strerror(errno));
    close(dfd);

    /* ---------- ⑤ mkdir 的存在/父目录检查 ---------- */
    printf("\n== ⑤ mkdir 的前置检查（都是内建原子性，不是先 stat 再建）==\n");
    try_mkdir(d, 0755, "mkdir(已存在的 d)");
    try_mkdir("/tmp/tlpi_c18_6/no/such/parent", 0755, "mkdir(父目录不存在)");

    /* 清理 */
    unlink(lnk);
    try_rmdir(d, "rmdir(空 d)  ← 现在可以了");
    rmdir(base);
    return EXIT_SUCCESS;
}
```

实测输出：

```text
== ④ unlinkat(AT_REMOVEDIR) == rmdir ==
  unlinkat(dfd, "f", 0)             = 0 
  unlinkat(dfd, "sub", AT_REMOVEDIR)   = 0 
```

`flags=0` 删文件（等价 `unlink`），`AT_REMOVEDIR` 删空目录（等价 `rmdir`）。**一个接口覆盖了两个老接口**，且都以「目录 fd 为锚」——递归删除时再也不用拼路径串（对比 §18.9 里「回调路径串可能超长」的坑）。

## 要点：TOCTOU 的三段式与 *at() 的破法

老写法的竞态窗口：

```c
/* ✗ 三步之间，dir 可以被改名/换成符号链接 */
struct stat sb;
stat("/srv/data/config", &sb);      /* 1. 检查 */
chdir("/srv/data");                 /* 2. 进入 —— 这里 dir 可能已被换 */
int fd = open("config", O_RDONLY);  /* 3. 使用 —— 打开的可能已是别的东西 */
```

`*at()` 的破法：**把「进入」变成「持有一个引用」**。

```c
/* ✓ 锚点打开后不可替换（fd 指向 inode，不指向路径） */
int dirfd = open("/srv/data", O_RDONLY | O_DIRECTORY);   /* 唯一的路径检查点 */
struct stat sb;
fstatat(dirfd, "config", &sb, 0);
int fd = openat(dirfd, "config", O_RDONLY);
```

配合 `O_NOFOLLOW`（open 时拒绝链接）与 `fstatat(AT_SYMLINK_NOFOLLOW)`，可以把「用户可控路径」的攻击面压到只剩**一次** `open`。

> **更彻底的口诀（TLPI 反复强调）**：先 `open`（拿到 fd = 拿到 inode），再对 fd 做一切操作（`fstat`/`fchmod`/`fchown`/`futimens`）。路径解析只发生一次，后面全是 inode 级操作，无竞态可言。

## 要点：openat 的性能红利

| 场景 | 老接口 | *at() 接口 |
|------|--------|-----------|
| 深层目录批量操作 | 每个文件都要全路径解析（逐级查目录） | 锚点 fd 已在深处，只解析最后一段 |
| 遍历 + 打开 | 拼串 + 全路径 `open` | `dirfd` 从 `readdir` 的目录直接 `openat(e->d_name)` |
| 多线程 | cwd 全局竞争 | 每线程/每模块自己的锚点 fd，零竞争 |

对海量小文件（行情落盘、日志分片）的场景，`*at()` 不是「安全选配」而是**吞吐量来源**——路径解析是 `namei` 层的锁与 dcache 查找，省一次全路径就是省一串操作。

## 常见坑

| 坑 | 正解 |
|----|------|
| `openat(dirfd, "/abs/path", ...)` 期望「相对 dirfd + 绝对回退」 | 绝对路径**完全忽略** dirfd；要「回退到 cwd」语义就显式传 `AT_FDCWD` |
| 以为 `AT_FDCWD` 是「安全默认值」 | 它等价老 API，**没有任何防 TOCTOU 能力**；用它就等于没用 *at |
| `openat` 后忘了 `close(dirfd)` | 锚点 fd 泄漏；长跑进程要审计，建议用 RAII/defer 包装 |
| 用 `faccessat(AT_FDCWD, path, W_OK)` 检查再 `open` | 还是 TOCTOU（且 `access` 有 euid/ruid 混淆坑，见 [15 章](../../chapter-15-file-attributes/README.md)）；直接 `open` + 检查返回值 |
| `unlinkat` 删目录忘了 `AT_REMOVEDIR` | 报 `EISDIR`(Linux)/`EPERM`(macOS)；与「忘了 flags」的报错区分开 |
| 以为 `*at()` 在 macOS 上全有 | 核心几个有（`openat`/`fstatat`/`unlinkat`/`renameat`...），但 `renameat2`、`AT_EMPTY_PATH` 等 Linux 扩展没有；跨平台要留降级路径 |
| 用「打开目录 fd」当**锁** | 打开不互斥；互斥用 `O_CREAT\|O_EXCL` 建锁文件或 `link()` 的 `EEXIST` |

## HFT / 嵌入式关联

| 场景 | 本节机制怎么兑现 |
|------|----------------|
| 启动锚点模式 | `main` 打开业务根目录 fd（如 `/var/data/quotes`），之后全部 `openat(anchor, rel)`——运维从任何 cwd 启动行为一致 |
| 海量小文件吞吐 | 行情按 tick 分文件：`openat(dayfd, "HHMMSS.bin")` 省掉全路径解析；深层目录收益最大 |
| 多线程零竞争 | 每个模块持自己的目录 fd，cwd 从此是只读变量；`chdir` 从代码规范里整个删掉 |
| 安全网关 | 接收外部路径的入口统一「`openat(anchor, rel, O_NOFOLLOW)` → 失败即拒绝」，TOCTOU 与符号链接攻击一起挡 |
| 嵌入式递归删除 | `unlinkat(dirfd, name, AT_REMOVEDIR)` 按锚点删，不需要拼接超长路径（对比 §18.9 的 `PATH_MAX` 坑） |
| 容器/沙箱 | `openat` 配合 `O_PATH`（Linux）实现受限文件访问；macOS 无 `O_PATH`，用 `O_RDONLY|O_DIRECTORY` 等价替代 |

<summary>代码自测（Q&A）</summary>

**Q1：`openat(AT_FDCWD, "x", O_RDONLY)` 和 `open("x", O_RDONLY)` 有区别吗？**
A：没有。`AT_FDCWD` 就是「用 cwd」，两条完全等价（内核走同一条路径）。所以「为了用 *at 而用 AT_FDCWD」是自我安慰——防 TOCTOU 的前提是**传入真实的目录 fd**。

**Q2：锚点 fd 为什么「不可替换」？**
A：fd 在打开时就绑定到了具体 inode（`open` 完成解析后引用计数 +1）。之后把那个路径改名、删除、甚至换成符号链接，fd 指向的 inode 不变。这正是 §18.3「unlink 后 fd 仍可读」的同一机制。

**Q3：`fstatat(AT_SYMLINK_NOFOLLOW)` 和 `lstat` 完全等价吗？**
A：语义等价（都不跟随），但 `fstatat` 多了锚定能力：可以「相对某目录 fd 判断类型」，`lstat` 只能全路径。在遍历中配合 `readdir` 使用时，`fstatat(dirfd, name, AT_SYMLINK_NOFOLLOW)` 比「拼串 + lstat」既快又无竞态。

**Q4：`openat` 打开目录 fd 时需要什么 flags？**
A：`O_RDONLY|O_DIRECTORY` 是可移植写法（macOS 无 `O_PATH`）。Linux 上 `O_PATH|O_DIRECTORY` 更强（不做权限检查、不能 read 但能当锚点和 `fchdir`）。跨平台代码用前者。

**Q5：为什么说 *at() 族「把 cwd 从代码里删掉了」？**
A：因为所有路径操作都可以改写成 `*at(anchor, ...)` 形式，cwd 从此与逻辑无关——运维从哪个目录启动、哪个线程 chdir 了，都不影响行为。这是一种**消除全局状态**的重构，价值不亚于安全性本身。

**Q6：`AT_EMPTY_PATH` 是什么？macOS 有吗？**
A：Linux 扩展：`pathname` 传空串时操作**fd 本身**指向的对象（如 `fstatat(fd, "", &sb, AT_EMPTY_PATH)` = `fstat(fd, &sb)`）。macOS 没有。对 fd 的操作在 macOS 上要用对应的 `f` 版接口（`fstat`/`fchmod`/...）。

</details>
