# 18.5 Working with Symbolic Links: symlink() and readlink() 操作符号链接

## 本节讲什么

§18.2 讲了符号链接**是什么**，本节讲**怎么用**——两个接口、四个必须钉住的细节：

1. `symlink()` 创建时不检查目标（§18.2 已实测），但**检查链接名本身**（`EEXIST`）；
2. `readlink()` 返回**裸字节串**：不补 NUL、不解析、返回值是「写入的字节数」；
3. `readlink` 的语义陷阱：**静默截断**且**无 NUL**——最常见的崩溃源头；
4. 原书 Listing 18-4 (`view_symlink.c`) 把 `readlink` 与 `realpath` 并排，一眼看出「裸串」和「解析结果」的差别。

---

## 要点：两个接口的契约

```c
#include <unistd.h>
int symlink(const char *linkpath_target, const char *linkpath);
ssize_t readlink(const char *pathname, char *buf, size_t bufsiz);
ssize_t readlinkat(int dirfd, const char *pathname,
                   char *buf, size_t bufsiz);      /* POSIX.1-2008 */
```

| 项 | 规则 | 错误码（实测） |
|----|------|---------------|
| `symlink` 目标 | **不检查存在性**，任何字符串都行（悬空合法） | — |
| `symlink` 链接名 | 不得已存在 | `EEXIST` |
| `readlink` 缓冲 | 按 `bufsiz` 上限写，**不补 NUL** | 缓冲太小 → **静默截断**，返回 `bufsiz` |
| `readlink` 返回值 | **写入的字节数**（= `lstat().st_size`，若缓冲够大） | 失败 `-1` |
| `readlink` 非链接 | 报错（它不跟随） | `EINVAL` |

**`readlink` 的正确姿势**（三行，缺一不可）：

```c
char buf[PATH_MAX];
ssize_t n = readlink(path, buf, sizeof(buf) - 1);  /* 留 1 字节给 NUL */
if (n == -1) { /* 真出错：EINVAL=不是链接, ENOENT... */ }
buf[n] = '\0';                                     /* 自己补 NUL，n 是字节数不是长度 */
```

> ⚠️ 若 `n == sizeof(buf)-1` 说明**可能被截断**（目标串长度 ≥ 缓冲）。严谨实现应 `lstat` 拿 `st_size` 后分配 `st_size+1` 再读一次。

## 实测：readlink 的裸串语义

**完整源码（[`code/c18_3_symlink_readlink.c`](../code/c18_3_symlink_readlink.c)）：**

```c
/* c18_3_symlink_readlink.c — Ch18 §18.2/§18.5：符号链接的行为清单
 *
 * 钉住的点（全部实测）：
 *   ① symlink() 可以指向**不存在的路径**（悬空链接）——创建时不检查目标；
 *   ② 链接自身有 inode（lstat 见 15.1），st_size = 目标路径串长度；
 *   ③ readlink() 返回的是裸路径串（不带 NUL，size 是你给的缓冲上限）；
 *   ④ ELOOP：内核路径解析层限制链接层级（macOS 实测 40 层）；
 *   ⑤ 链接属主/权限有微妙的平台差异（macOS 实测 0777 + 属组继承目录）。
 *
 * 编译： cc -Wall -Wextra -o c18_3_symlink_readlink c18_3_symlink_readlink.c
 * 取材： man-pages 6.19 symlink(2)/readlink(2) + TLPI §18.2/§18.5（Listing 18-4 view_symlink.c）
 */
#include <errno.h>
#include <fcntl.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <sys/stat.h>
#include <unistd.h>

int main(void)
{
    const char *dangling = "/tmp/tlpi_c18_3_dangling.lnk";
    const char *target = "/tmp/tlpi_c18_3_target.txt";
    unlink(dangling); unlink(target);

    /* ---------- ① 悬空链接 ---------- */
    printf("== ① symlink() 创建时不检查目标：悬空链接合法 ==\n");
    if (symlink("/no/such/path/ever.txt", dangling) == -1) {
        perror("symlink"); return EXIT_FAILURE;
    }
    struct stat sb;
    if (lstat(dangling, &sb) == -1) { perror("lstat"); return EXIT_FAILURE; }
    printf("  lstat(悬空链接): 类型=%s st_size=%ld（=目标路径串长度）\n",
           S_ISLNK(sb.st_mode) ? "symlink" : "?", (long) sb.st_size);
    errno = 0;
    int fd = open(dangling, O_RDONLY);
    printf("  open(悬空链接) = %d errno=%d(%s)——用的时候才爆\n",
           fd, errno, strerror(errno));
    errno = 0;
    int sr = stat(dangling, &sb);
    printf("  stat(悬空链接) = %d errno=%d(%s)\n", sr, errno, strerror(errno));

    /* ---------- ③ readlink 的裸字节串语义 ---------- */
    printf("\n== ③ readlink(): 裸路径串，不补 NUL ==\n");
    if (symlink(target, "/tmp/tlpi_c18_3_ok.lnk") == -1) { perror("symlink2"); return EXIT_FAILURE; }
    char buf[256];
    ssize_t n = readlink("/tmp/tlpi_c18_3_ok.lnk", buf, sizeof buf - 1);
    if (n == -1) { perror("readlink"); return EXIT_FAILURE; }
    buf[n] = '\0';                       /* 必须自己补 NUL */
    printf("  readlink = \"%s\" (%zd 字节，字符串长 %zu)\n", buf, n, strlen(buf));
    printf("  ⚠️ readlink 返回值是**写入的字节数**，不是字符串长——\n");
    printf("     超过缓冲会静默截断且无 NUL，必须按返回值处理。\n\n");

    /* ---------- ④ ELOOP ---------- */
    printf("== ④ 链接链：内核 ELOOP 保护 ==\n");
    char a[64], b2[64];
    snprintf(a, sizeof a, "/tmp/c18_3_loop_a");
    snprintf(b2, sizeof b2, "/tmp/c18_3_loop_b");
    unlink(a); unlink(b2);
    symlink(b2, a);
    symlink(a, b2);                      /* 互指成环 */
    errno = 0;
    fd = open(a, O_RDONLY);
    printf("  open(互指环) = %d errno=%d(%s)\n", fd, errno, strerror(errno));
    if (fd != -1) close(fd);
    /* 数一数最多能串几层 */
    int depth = 0;
    char cur[64], next[64];
    snprintf(cur, sizeof cur, "/tmp/c18_3_chain_0");
    unlink(cur);
    symlink("/tmp/c18_3_chain_base", cur);
    for (depth = 1; depth < 200; depth++) {
        snprintf(next, sizeof next, "/tmp/c18_3_chain_%d", depth);
        unlink(next);
        if (symlink(cur, next) == -1) break;
        snprintf(cur, sizeof cur, "%s", next);
    }
    errno = 0;
    fd = open(next, O_RDONLY);
    int ok = (fd != -1);
    if (ok) close(fd);
    printf("  串 %d 层链接 open = %s（errno=%d %s）\n",
           depth, ok ? "OK" : "失败", errno, strerror(errno));
    printf("  → 解析上限是内核常量（macOS=40，Linux=40 SYMLOOP/8 MAXSYMLINKS 语义见 man）；\n");
    /* 清理链条 */
    for (int i = 0; i <= depth; i++) {
        snprintf(next, sizeof next, "/tmp/c18_3_chain_%d", i);
        unlink(next);
    }
    unlink(a); unlink(b2);

    /* ---------- ⑤ 属主/权限的平台差异 ---------- */
    printf("\n== ⑤ 链接自身的属主与权限（平台差异实测）==\n");
    if (lstat("/tmp/tlpi_c18_3_ok.lnk", &sb) == -1) { perror("lstat2"); return EXIT_FAILURE; }
    printf("  macOS 实测: uid=%ld gid=%ld mode=%lo（链接有自己的 mode=0777&~umask；\n"
           "     跟随打开时的权限判定用目标文件——链接 mode 本身无访问语义）\n",
           (long) sb.st_uid, (long) sb.st_gid, (unsigned long) (sb.st_mode & 07777));
    printf("  ⚠️ 书上/Linux：链接权限被忽略、属主影响删除权（sticky 目录）；\n");
    printf("     macOS(BSD) 给链接自己的 uid/gid/mode——别跨平台假设。\n");
    unlink("/tmp/tlpi_c18_3_ok.lnk");
    unlink(dangling);
    return EXIT_SUCCESS;
}
```

实测输出：

```text
== ③ readlink(): 裸路径串，不补 NUL ==
  readlink = "/tmp/tlpi_c18_3_target.txt" (26 字节，字符串长 26)
  ⚠️ readlink 返回值是**写入的字节数**，不是字符串长——
     超过缓冲会静默截断且无 NUL，必须按返回值处理。
```

`26 字节 = 字符串长 26` 只是**恰好**没截断（缓冲 255 远大于 26）。若缓冲给 10，返回值是 10、`strlen` 未定义（没有 NUL）——这就是「必须按返回值处理」的含义。

## 实测：原书 Listing 18-4 —— readlink vs realpath 并排

```c
/* view_symlink.c

   Demonstrate the use of readlink() and realpath() to read and display
   the contents of a symbolic link.
*/
#include <sys/stat.h>
#include <limits.h>             /* For definition of PATH_MAX */
#include "tlpi_hdr.h"

#define BUF_SIZE PATH_MAX

int
main(int argc, char *argv[])
{
    struct stat statbuf;
    char buf[BUF_SIZE];
    ssize_t numBytes;

    if (argc != 2 || strcmp(argv[1], "--help") == 0)
        usageErr("%s pathname\n", argv[0]);

    /* User lstat() to check whether the supplied pathname is
       a symbolic link. Alternatively, we could have checked to
       whether readlink() failed with EINVAL. */

    if (lstat(argv[1], &statbuf) == -1)
        errExit("lstat");

    if (!S_ISLNK(statbuf.st_mode))
        fatal("%s is not a symbolic link", argv[1]);

    numBytes = readlink(argv[1], buf, BUF_SIZE - 1);
    if (numBytes == -1)
        errExit("readlink");
    buf[numBytes] = '\0';                       /* Add terminating null byte */
    printf("readlink: %s --> %s\n", argv[1], buf);

    if (realpath(argv[1], buf) == NULL)
        errExit("realpath");
    printf("realpath: %s --> %s\n", argv[1], buf);

    exit(EXIT_SUCCESS);
}
```

实测输出：

```text
$ ln -sf /etc/hosts slink && ./view_symlink slink
readlink: slink --> /etc/hosts
realpath: slink --> /private/etc/hosts
```

这个并排输出是本节最好的教材：

| | `readlink` | `realpath`（§18.13） |
|--|-----------|---------------------|
| 输出 | **裸串**：写进链接里的原文 | **解析后的绝对路径**（把 `/etc`→`/private/etc` 这种**文件系统层的符号链接**也展开了） |
| 是否访问文件系统 | 否（纯读链接内容） | 是（逐级解析） |
| 输入要求 | 必须是链接（否则 `EINVAL`） | 任意路径 |

注意 `/etc/hosts` → `/private/etc/hosts` 这个差异**不是**链接内容（链接里写的就是 `/etc/hosts`），而是 macOS 把 `/etc` 本身做成了指向 `/private/etc` 的符号链接——`realpath` 一路解析到底，`readlink` 只读了一层。

## 要点：什么时候用 `readlink`，什么时候用 `realpath`

| 需求 | 用谁 | 原因 |
|------|------|------|
| 「链接里到底写了什么」（存储/备份） | `readlink` | 只要原文，不要解析（解析会丢「相对性」） |
| 「这个路径最终指向哪个真实文件」（安全检查） | `realpath` | 全展开 + 消除 `.`/`..`，可用于目录穿越校验 |
| 判断两个路径是否同一文件 | `realpath` 后比串，或直接比 `st_dev`+`st_ino` | 字符串比对面有 `./x` vs `x` 这种平凡差异 |
| 把相对链接改写成绝对链接 | `readlink`（拿原文）+ 手动拼 | `realpath` 会连目标一起解析，丢失链接本身的信息 |

## 常见坑

| 坑 | 正解 |
|----|------|
| `readlink` 后直接 `printf("%s", buf)` | 不补 NUL → 未定义行为；必须 `buf[n] = '\0'` |
| `char buf[64]` 而 `readlink(path, buf, sizeof(buf))` | 截断且无 NUL；给 `sizeof(buf)-1` 并检查 `n == sizeof(buf)-1` |
| 以为 `readlink` 能读普通文件 | `EINVAL`（它不跟随）；读任意路径的解析结果用 `realpath` |
| `symlink` 返回 0 就认为「链接可用」 | 只说明**链接建好了**；目标可能不存在（悬空），要 `open`/`stat` 才知道 |
| 用 `symlink` 实现「原子替换」 | `symlink` 遇已存在名字报 `EEXIST`；先 `unlink`+`symlink` 有窗口，原子换向要用「临时名 + `rename`」或 Linux 的 `renameat2(RENAME_EXCHANGE)` |
| 把 `readlink` 的返回值当 `strlen` | 返回值是**写入字节数**；只有「没截断」时二者才相等 |

## HFT / 嵌入式关联

| 场景 | 本节机制怎么兑现 |
|------|----------------|
| 版本目录的原子换向 | `symlink(new_tmp)` → `rename(new_tmp, current)`：两步都原子，读者要么旧要么新；`readlink` 用于回滚时拿到上一版 |
| 配置/数据集指针 | 服务读 `data.current` 前先 `readlink` 记录「当前用的是哪个版本」，审计日志可直接落这个串 |
| 安全校验 | `realpath` 后确认前缀在白名单目录内，再 `open`——防目录穿越（`../../etc/passwd`） |
| 嵌入式打包 | 固件里 `.so -> .so.1` 链接**必须存相对串**；备份/烧录工具只 `readlink` 拿原文重建，用 `realpath` 会把相对性烧死成绝对路径 |
| `st_size` 即缓冲大小 | 读链接前 `lstat` 拿 `st_size+1` 分配缓冲，杜绝截断——是 `readlink` 唯一「自描述」的地方 |

<details>
<summary>代码自测（Q&A）</summary>

**Q1：`readlink` 为什么不像 `read` 那样自动补 NUL？**
A：因为链接内容本质是**字节串**而不是 C 字符串——某些场景（如存进元数据、做哈希）就是要原文长度。补 NUL 是调用者的责任，这也使得「被截断」变成可检测的状态（`n == bufsiz`）。

**Q2：怎么确定 readlink 没截断？**
A：两种办法：① 先 `lstat` 拿 `st_size`（= 链接串长度），按它分配缓冲，读完比对 `n == st_size`；② 用足够大缓冲，若 `n == sizeof(buf)-1` 就再放大重读。方法 ① 更省一次系统调用且天然免疫截断。

**Q3：`symlink("a", "b")` 时 `b` 已存在会怎样？和 `ln -s` 命令行为一致吗？**
A：`EEXIST`。`ln -sf` 的 `-f` 是命令**自己**先 `unlink` 再 `symlink`（所以那中间有窗口，不是原子的）。要原子换向必须走「临时名 + `rename`」。

**Q4：`readlinkat` 相比 `readlink` 的价值？**
A：① 锚定目录 fd，消除路径竞态（§18.11）；② 配合 `O_PATH` 打开的目录做受限遍历；③ `readlinkat(fd, "", buf, n)` 可以读**已打开文件本身**的链接（如 `/proc/PID/fd/N`），这是无 `dirfd` 版做不到的。

**Q5：链接串里能放 NUL 字节吗？**
A：不能。`symlink` 的目标以 NUL 结尾，串里不可能含 NUL。这也是为什么 `readlink` 的返回值通常是「长度+1」争议的根源——不存在「串里带了 NUL」这种可能。

**Q6：`view_symlink.c` 输出里 `/etc/hosts` → `/private/etc/hosts`，`readlink` 为什么只显示一层？**
A：`readlink` 只读**这一个链接**的内容（`/etc/hosts`），不解析。`/etc → /private/etc` 是**文件系统层的另一个链接**，只有 `realpath` 这种逐级解析的接口才会把它展开。

</details>
