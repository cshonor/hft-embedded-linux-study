## 本节讲什么

§18.2 讲了符号链接**是什么**，本节讲**怎么用**——两个接口、四个必须钉住的细节：

1. `symlink()` 创建时不检查目标（§18.2 已实测），但**检查链接名本身**（`EEXIST`）；
2. `readlink()` 返回**裸字节串**：不补 NUL、不解析、返回值是「写入的字节数」；
3. `readlink` 的语义陷阱：**静默截断**且**无 NUL**——最常见的崩溃源头；
4. 原书 Listing 18-4 (`view_symlink.c`) 把 `readlink` 与 `realpath` 并排，一眼看出「裸串」和「解析结果」的差别。

## 要点：两个接口的契约

```c
#include <unistd.h>
int symlink(const char *linkpath_target, const char *linkpath);
ssize_t readlink(const char *pathname, char *buf, size_t bufsiz);
ssize_t readlinkat(int dirfd, const char *pathname,
                   char *buf, size_t bufsiz);      /* POSIX.1-2008 */
```

| 项 | 规则 | 错误码（实测） |
|----|------|---------------|
| `symlink` 目标 | **不检查存在性**，任何字符串都行（悬空合法） | — |
| `symlink` 链接名 | 不得已存在 | `EEXIST` |
| `readlink` 缓冲 | 按 `bufsiz` 上限写，**不补 NUL** | 缓冲太小 → **静默截断**，返回 `bufsiz` |
| `readlink` 返回值 | **写入的字节数**（= `lstat().st_size`，若缓冲够大） | 失败 `-1` |
| `readlink` 非链接 | 报错（它不跟随） | `EINVAL` |

**`readlink` 的正确姿势**（三行，缺一不可）：

```c
char buf[PATH_MAX];
ssize_t n = readlink(path, buf, sizeof(buf) - 1);  /* 留 1 字节给 NUL */
if (n == -1) { /* 真出错：EINVAL=不是链接, ENOENT... */ }
buf[n] = '\0';                                     /* 自己补 NUL，n 是字节数不是长度 */
```

> ⚠️ 若 `n == sizeof(buf)-1` 说明**可能被截断**（目标串长度 ≥ 缓冲）。严谨实现应 `lstat` 拿 `st_size` 后分配 `st_size+1` 再读一次。

## 实测：readlink 的裸串语义（[`code/c18_3_symlink_readlink.c`](../code/c18_3_symlink_readlink.c)）

```text
== ③ readlink(): 裸路径串，不补 NUL ==
  readlink = "/tmp/tlpi_c18_3_target.txt" (26 字节，字符串长 26)
  ⚠️ readlink 返回值是**写入的字节数**，不是字符串长——
     超过缓冲会静默截断且无 NUL，必须按返回值处理。
```

`26 字节 = 字符串长 26` 只是**恰好**没截断（缓冲 255 远大于 26）。若缓冲给 10，返回值是 10、`strlen` 未定义（没有 NUL）——这就是「必须按返回值处理」的含义。

## 实测：原书 Listing 18-4 —— readlink vs realpath 并排（[`code/view_symlink.c`](../code/view_symlink.c)）

```text
$ ln -sf /etc/hosts slink && ./view_symlink slink
readlink: slink --> /etc/hosts
realpath: slink --> /private/etc/hosts
```

这个并排输出是本节最好的教材：

| | `readlink` | `realpath`（§18.13） |
|--|-----------|---------------------|
| 输出 | **裸串**：写进链接里的原文 | **解析后的绝对路径**（把 `/etc`→`/private/etc` 这种**文件系统层的符号链接**也展开了） |
| 是否访问文件系统 | 否（纯读链接内容） | 是（逐级解析） |
| 输入要求 | 必须是链接（否则 `EINVAL`） | 任意路径 |

注意 `/etc/hosts` → `/private/etc/hosts` 这个差异**不是**链接内容（链接里写的就是 `/etc/hosts`），而是 macOS 把 `/etc` 本身做成了指向 `/private/etc` 的符号链接——`realpath` 一路解析到底，`readlink` 只读了一层。

## 要点：什么时候用 `readlink`，什么时候用 `realpath`

| 需求 | 用谁 | 原因 |
|------|------|------|
| 「链接里到底写了什么」（存储/备份） | `readlink` | 只要原文，不要解析（解析会丢「相对性」） |
| 「这个路径最终指向哪个真实文件」（安全检查） | `realpath` | 全展开 + 消除 `.`/`..`，可用于目录穿越校验 |
| 判断两个路径是否同一文件 | `realpath` 后比串，或直接比 `st_dev`+`st_ino` | 字符串比对面有 `./x` vs `x` 这种平凡差异 |
| 把相对链接改写成绝对链接 | `readlink`（拿原文）+ 手动拼 | `realpath` 会连目标一起解析，丢失链接本身的信息 |

## 常见坑

| 坑 | 正解 |
|----|------|
| `readlink` 后直接 `printf("%s", buf)` | 不补 NUL → 未定义行为；必须 `buf[n] = '\0'` |
| `char buf[64]` 而 `readlink(path, buf, sizeof(buf))` | 截断且无 NUL；给 `sizeof(buf)-1` 并检查 `n == sizeof(buf)-1` |
| 以为 `readlink` 能读普通文件 | `EINVAL`（它不跟随）；读任意路径的解析结果用 `realpath` |
| `symlink` 返回 0 就认为「链接可用」 | 只说明**链接建好了**；目标可能不存在（悬空），要 `open`/`stat` 才知道 |
| 用 `symlink` 实现「原子替换」 | `symlink` 遇已存在名字报 `EEXIST`；先 `unlink`+`symlink` 有窗口，原子换向要用「临时名 + `rename`」或 Linux 的 `renameat2(RENAME_EXCHANGE)` |
| 把 `readlink` 的返回值当 `strlen` | 返回值是**写入字节数**；只有「没截断」时二者才相等 |

## HFT / 嵌入式关联

| 场景 | 本节机制怎么兑现 |
|------|----------------|
| 版本目录的原子换向 | `symlink(new_tmp)` → `rename(new_tmp, current)`：两步都原子，读者要么旧要么新；`readlink` 用于回滚时拿到上一版 |
| 配置/数据集指针 | 服务读 `data.current` 前先 `readlink` 记录「当前用的是哪个版本」，审计日志可直接落这个串 |
| 安全校验 | `realpath` 后确认前缀在白名单目录内，再 `open`——防目录穿越（`../../etc/passwd`） |
| 嵌入式打包 | 固件里 `.so -> .so.1` 链接**必须存相对串**；备份/烧录工具只 `readlink` 拿原文重建，用 `realpath` 会把相对性烧死成绝对路径 |
| `st_size` 即缓冲大小 | 读链接前 `lstat` 拿 `st_size+1` 分配缓冲，杜绝截断——是 `readlink` 唯一「自描述」的地方 |

<details>
<summary>代码自测（Q&A）</summary>

**Q1：`readlink` 为什么不像 `read` 那样自动补 NUL？**
A：因为链接内容本质是**字节串**而不是 C 字符串——某些场景（如存进元数据、做哈希）就是要原文长度。补 NUL 是调用者的责任，这也使得「被截断」变成可检测的状态（`n == bufsiz`）。

**Q2：怎么确定 readlink 没截断？**
A：两种办法：① 先 `lstat` 拿 `st_size`（= 链接串长度），按它分配缓冲，读完比对 `n == st_size`；② 用足够大缓冲，若 `n == sizeof(buf)-1` 就再放大重读。方法 ① 更省一次系统调用且天然免疫截断。

**Q3：`symlink("a", "b")` 时 `b` 已存在会怎样？和 `ln -s` 命令行为一致吗？**
A：`EEXIST`。`ln -sf` 的 `-f` 是命令**自己**先 `unlink` 再 `symlink`（所以那中间有窗口，不是原子的）。要原子换向必须走「临时名 + `rename`」。

**Q4：`readlinkat` 相比 `readlink` 的价值？**
A：① 锚定目录 fd，消除路径竞态（§18.11）；② 配合 `O_PATH` 打开的目录做受限遍历；③ `readlinkat(fd, "", buf, n)` 可以读**已打开文件本身**的链接（如 `/proc/PID/fd/N`），这是无 `dirfd` 版做不到的。

**Q5：链接串里能放 NUL 字节吗？**
A：不能。`symlink` 的目标以 NUL 结尾，串里不可能含 NUL。这也是为什么 `readlink` 的返回值通常是「长度+1」争议的根源——不存在「串里带了 NUL」这种可能。

**Q6：`view_symlink.c` 输出里 `/etc/hosts` → `/private/etc/hosts`，`readlink` 为什么只显示一层？**
A：`readlink` 只读**这一个链接**的内容（`/etc/hosts`），不解析。`/etc → /private/etc` 是**文件系统层的另一个链接**，只有 `realpath` 这种逐级解析的接口才会把它展开。

</details>
