# 18.4 Changing the Name of a File: rename() 改变文件的名字

> 本章：[TLPI 第 18 章 — Directories and Links](../README.md)

## 本节讲什么

`rename()` 是全章**唯一**带「原子替换」语义的接口，也是「可靠写入」模式的根：

1. 对已存在的目标文件：**原子替换**，任何时刻路径都指向一个完整的老文件或完整的新文件；
2. 对目录有一套独立规则（目标必须空、不能移进自己的子树、不能改 `..`）；
3. 它**不换 inode**——换的是目录项，所以文件时间戳/数据都不动；
4. 同一文件系统内 O(1)（只改目录表）；跨 FS 直接 `EXDEV`，不存在「自动帮你复制」。

## 要点：契约表

```c
#include <stdio.h>          /* 注意：stdio.h，不是 unistd.h */
int rename(const char *oldpath, const char *newpath);
#include <fcntl.h>
int renameat(int olddirfd, const char *oldpath,
             int newdirfd, const char *newpath);
int renameat2(int olddirfd, ..., unsigned int flags);  /* Linux 3.15+ 专有 */
```

| `oldpath` | `newpath` 不存在 | `newpath` 是文件 | `newpath` 是**空**目录 | `newpath` 是**非空**目录 |
|-----------|------------------|------------------|------------------------|--------------------------|
| 文件 | 改名 | **原子替换** | `EISDIR` | `EISDIR` |
| 目录 | 改名 | `ENOTDIR` | **整体搬过去** | `ENOTEMPTY` |

另两条独立规则：`newpath` 不能是 `oldpath` 的**子路径**（`EINVAL`，否则造出不可达的环）；`..` 不能被改名（`EINVAL`）。

## 实测：原子替换与全部目录规则

**完整源码（[`code/c18_2_rename.c`](../code/c18_2_rename.c)）：**

```c
/* c18_2_rename.c — Ch18 §18.4：rename() 的原子替换语义
 *
 * 钉住的点（全部实测）：
 *   ① rename(file, 存在的file) = **原子替换**：任何时刻路径都指向一个
 *      完整的老文件或完整的新文件，绝不会半新半旧——safe-write 模式的根；
 *   ② rename 对目录：目标必须是空目录；目录到文件（或反之）→ EISDIR/ENOTDIR；
 *   ③ 目录的 ".." 不可改、不能把目录移到自己子树里（EINVAL/EBUSY）；
 *   ④ rename 不换 inode（15.2 实测过：Linux 不动文件时间戳）；
 *   ⑤ 同文件系统内 O(1)（改目录项），跨 FS 会 EXDEV（内核搬数据，不原子）。
 *
 * 编译： cc -Wall -Wextra -o c18_2_rename c18_2_rename.c
 * 取材： man-pages 6.19 rename(2) + TLPI §18.4
 */
#include <errno.h>
#include <fcntl.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <sys/stat.h>
#include <sys/types.h>
#include <unistd.h>

static int try_rename(const char *oldp, const char *newp, const char *tag)
{
    errno = 0;
    int r = rename(oldp, newp);
    printf("  %-38s = %d %s\n", tag, r, r == 0 ? "" : strerror(errno));
    return r;
}

int main(void)
{
    const char *dir = "/tmp/tlpi_c18_2";
    char a[128], b[128], d1[128], d2[128];
    snprintf(a, sizeof a, "%s/a.txt", dir);
    snprintf(b, sizeof b, "%s/b.txt", dir);
    snprintf(d1, sizeof d1, "%s/dir1", dir);
    snprintf(d2, sizeof d2, "%s/dir2", dir);
    system("rm -rf /tmp/tlpi_c18_2 && mkdir /tmp/tlpi_c18_2");

    /* ---------- ① 原子替换 ---------- */
    printf("== ① rename(file, 存在的 file)：原子替换 ==\n");
    int fd = open(a, O_RDWR | O_CREAT | O_EXCL, 0644);
    if (fd == -1) { perror("open"); return EXIT_FAILURE; }
    write(fd, "NEW CONTENT\n", 12);
    close(fd);
    fd = open(b, O_RDWR | O_CREAT | O_EXCL, 0644);
    if (fd == -1) { perror("open2"); return EXIT_FAILURE; }
    write(fd, "OLD\n", 4);
    close(fd);
    try_rename(a, b, "rename(a → 已存在的 b)");
    char buf[64];
    int rfd = open(b, O_RDONLY);
    ssize_t n = read(rfd, buf, sizeof buf);
    printf("  b 现在的内容: \"%.*s\"（b 的旧内容被整体替换，无中间态）\n",
           (int) n, buf);
    close(rfd);
    struct stat s1;
    stat(b, &s1);
    printf("  ⚠️ inode=%lu 未变——rename 换的是目录项不是数据（§18.4）\n\n",
           (unsigned long) s1.st_ino);

    /* safe-write 惯用法演示 */
    printf("== safe-write 惯用法 ==\n");
    printf("  写配置 → 写到 temp → fsync → rename(temp, 配置) →\n");
    printf("  读者永远看到完整旧版或完整新版；崩溃也不会留下半截文件。\n\n");

    /* ---------- ② 目录规则 ---------- */
    printf("== ② 目录规则 ==\n");
    mkdir(d1, 0755); mkdir(d2, 0755);
    char inner[128];
    snprintf(inner, sizeof inner, "%s/inner.txt", d2);
    fd = open(inner, O_RDWR | O_CREAT | O_EXCL, 0644);
    if (fd == -1) { perror("open3"); return EXIT_FAILURE; }
    close(fd);
    try_rename(inner, d2, "rename(文件 → 目录)");
    try_rename(d2, inner, "rename(目录 → 文件)");
    try_rename(d1, d2, "rename(空 dir1 → 非空 dir2)");
    try_rename(d2, d1, "rename(非空 dir2 → 空 dir1)");   /* 此时 d2 已消失 */

    /* 目录进自己的子树：必须 EINVAL（否则会造出不可达的环） */
    char sub[160];
    snprintf(sub, sizeof sub, "%s/sub", d1);
    try_rename(d1, sub, "rename(dir1 → dir1/sub 自己的子树)");
    /* ".." 不能被 rename 改写 */
    char dotdot[160];
    snprintf(dotdot, sizeof dotdot, "%s/..", d1);
    try_rename(d1, dotdot, "rename(dir1 → dir1/..)");

    /* 清理 */
    unlink(inner); rmdir(d1); rmdir(d2);
    unlink(b);
    rmdir(dir);
    return EXIT_SUCCESS;
}
```

实测输出：

```text
== ① rename(file, 存在的 file)：原子替换 ==
  rename(a → 已存在的 b)           = 0 
  b 现在的内容: "NEW CONTENT"（b 的旧内容被整体替换，无中间态）
  ⚠️ inode=2277517 未变——rename 换的是目录项不是数据（§18.4）

== safe-write 惯用法 ==
  写配置 → 写到 temp → fsync → rename(temp, 配置) →
  读者永远看到完整旧版或完整新版；崩溃也不会留下半截文件。

== ② 目录规则 ==
  rename(文件 → 目录)              = -1 Is a directory
  rename(目录 → 文件)              = -1 Not a directory
  rename(空 dir1 → 非空 dir2)       = -1 Directory not empty
  rename(非空 dir2 → 空 dir1)       = 0 
  rename(dir1 → dir1/sub 自己的子树) = -1 Invalid argument
  rename(dir1 → dir1/..)               = -1 Invalid argument
```

三个值得停下来的点：

- **inode 未变**（2277517）：替换后 `b` 还是老 `a` 的 inode。也就是说 rename **不搬数据**，只改了两个目录表里的行。这与 §15.2 实测「rename 不动文件时间戳」互相印证。
- **目录四条全部与 Linux 一致**：本机实测的 `EISDIR` / `ENOTDIR` / `ENOTEMPTY` 与 man-pages `rename(2)` 逐条对上（这是本轮升级**专门核对过**的——早前笔记曾怀疑 macOS 与 Linux 在目录覆盖上有差异，实测证伪：**两边语义一致**）。
- **两条 `EINVAL`**：不能把目录移进自己的子树、不能改 `..`。第一条是防止「目录变成自己的后代」，否则 `nftw`、`find`、`..` 链全部失效。

## 要点：safe-write 惯用法（本节的工程价值所在）

```c
/* 1. 写到同目录的临时文件（同 FS 才能原子 rename）*/
int fd = open("/etc/app.conf.tmp", O_WRONLY|O_CREAT|O_TRUNC, 0644);
write(fd, new_conf, len);
fsync(fd);                /* 数据先落盘（掉电才有意义）*/
close(fd);
/* 2. 原子替换——读者要么看到完整旧版，要么看到完整新版 */
rename("/etc/app.conf.tmp", "/etc/app.conf");
```

四个**都必须**的细节，缺一个就可能翻车：

| 细节 | 缺了会怎样 |
|------|-----------|
| 临时文件与目标**同目录** | 跨 FS 时 `rename` 变 `EXDEV`，惯用法直接失效 |
| `fsync(fd)` 在 `rename` 之前 | 掉电后 rename 落盘了、数据没落，目标指向半截文件 |
| 目录也要 `fsync`（严格场景） | 极端掉电顺序下 rename 本身可能没落盘 |
| `chmod`/`chown` 临时文件 | `open(..., 0644)` 受 umask 削减，直接 rename 会把意外权限带入目标 |

## 实测：rename 换 inode 的另一个证据（习题 18-1）

**完整源码（[`code/ex18_1_txtbsy.c`](../code/ex18_1_txtbsy.c)）：**

```c
/* ex18_1_txtbsy.c — 习题 18-1：正在执行的程序为什么还能被「覆盖」？
 *
 * 题面（原书 §18 习题 18-1，按转述）：§4.3.2 说「文件正在被执行时不能以写方式
 * 打开（open 返回 -1，errno=ETXTBSY）」。但从 shell 里却可以：
 *     cc -o longrunner longrunner.c
 *     ./longrunner &                 # 后台留着跑
 *     vi longrunner.c                # 改源码
 *     cc -o longrunner longrunner.c  # 这条居然成功！
 * 为什么？（提示：两次编译后用 ls -li 看可执行文件的 i-node。）
 *
 * 答案（②③④三部分钉住）：
 *   ③ 直接以 O_WRONLY 打开**正在执行**的二进制 → Linux 拒（ETXTBSY）；
 *   ④ cc 的「覆盖」根本没写老文件，而是**建新 inode + rename 换目录项**：
 *      rename 成功、inode 号变了，而老 inode 被运行中进程的 fd 吊住
 *      （回到 §18.3：nlink 归零且无 fd 才真删）。所以「覆盖」安全，
 *      正在跑的程序用的仍是老那份数据。
 *
 * ⚠️ ⓪ 是本程序特意保留的「踩坑自证」环节，别删：
 *   最初长跑程序是 `cp /bin/sleep /tmp/prog` 造的，结果子进程**瞬间就退**——
 *   macOS 代码签名（AMFI/taskgated）会 SIGKILL 掉「离开原位置的平台二进制」
 *   （实测 rc=137 = 128+SIGKILL）。那样测出的「open 成功」只证明「打开了一个
 *   没在运行的文件」，结论完全无效。所以长跑程序改为**拷自己编译的二进制**。
 *
 * 编译： cc -Wall -Wextra -o ex18_1_txtbsy ex18_1_txtbsy.c
 * 取材： TLPI §4.3.2 / §18.1 / §18.3 / 习题 18-1；man-pages 6.19 open(2)(ETXTBSY)、rename(2)
 */
#include <errno.h>
#include <fcntl.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <sys/stat.h>
#include <signal.h>
#include <sys/wait.h>
#include <unistd.h>

#define PROG     "/tmp/ex18_1_longrunner"       /* 会被"覆盖"的可执行文件 */
#define PROG_NEW "/tmp/ex18_1_longrunner.new"   /* "重新编译"的产物 */
#define SYSCOPY  "/tmp/ex18_1_syscopy"          /* ⓪ 用的系统二进制副本 */

static ino_t ino_of(const char *p)
{
    struct stat sb;
    return stat(p, &sb) == 0 ? sb.st_ino : 0;
}

/* 三态探活：真的在跑 / 已退出 / 查询出错 */
static const char *probe(pid_t c)
{
    int st;
    errno = 0;
    pid_t w = waitpid(c, &st, WNOHANG);
    if (w == 0) return "仍在运行 ✔";
    if (w == c) return "已退出 ✘（子进程没跑住 → 本项测试无效）";
    return "waitpid 出错（ECHILD 等）";
}

/* 跑一小段以观察它是「正常退出」还是「被信号杀死」 */
static void exec_and_report(const char *prog, const char *tag)
{
    pid_t c = fork();
    if (c < 0) { perror("fork"); return; }
    if (c == 0) { execl(prog, prog, (char *) NULL); _exit(127); }
    int st;
    waitpid(c, &st, 0);
    if (WIFSIGNALED(st))
        printf("  %-22s 被信号杀死：SIG %d（rc=%d = 128+%d）\n",
               tag, WTERMSIG(st), 128 + WTERMSIG(st), WTERMSIG(st));
    else
        printf("  %-22s 正常退出 rc=%d\n", tag, WEXITSTATUS(st));
}

/* 子模式：被 exec 起来的长跑进程本体（也方便本程序自证「能跑住」）*/
static int child_mode(void)
{
    fprintf(stderr, "[longrunner] pid=%d 正在运行，sleep(20)\n", (int) getpid());
    sleep(20);
    return 0;
}

int main(int argc, char *argv[])
{
    if (argc > 1 && strcmp(argv[1], "--child") == 0)
        return child_mode();

    /* ---------- ⓪ 先演示那个坑：拷系统二进制 = 跑不起来 ---------- */
    printf("== ⓪ 陷阱预热：为什么长跑程序不能「拷」系统的 sleep ==\n");
    char cp[256];
    snprintf(cp, sizeof cp, "cp /bin/sleep %s 2>/dev/null && chmod 755 %s",
             SYSCOPY, SYSCOPY);
    if (system(cp) == 0) {
        exec_and_report(SYSCOPY, "cp /bin/sleep 的副本");
        printf("  → 平台签名二进制离开原位置即被 AMFI/taskgated 干掉。\n");
        printf("     若用它当长跑程序，子进程秒退 → 后面所有结论都是假的。\n");
        unlink(SYSCOPY);
    } else {
        printf("  （本机无 /bin/sleep，跳过此项）\n");
    }
    printf("  ✔ 正解：长跑程序拷**自己编译**的二进制（ad-hoc 签名可任意搬）。\n\n");

    /* ---------- 准备长跑程序：拷贝本程序自身 ---------- */
    unlink(PROG);
    snprintf(cp, sizeof cp, "cp %s %s", argv[0], PROG);
    if (system(cp) != 0) { perror("copy self"); return EXIT_FAILURE; }
    ino_t ino_before = ino_of(PROG);

    pid_t child = fork();
    if (child == -1) { perror("fork"); return EXIT_FAILURE; }
    if (child == 0) {
        execl(PROG, PROG, "--child", (char *) NULL);
        _exit(127);
    }
    sleep(1);                                  /* 等孩子进入 exec */

    printf("== ① 待测对象 ==\n");
    printf("  子进程 pid=%d 正在执行 %s（inode=%lu）\n",
           (int) child, PROG, (unsigned long) ino_before);
    printf("  探活：%s（若显示已退出，说明长跑程序没准备好，后面结论无效）\n",
           probe(child));

    printf("\n== ② 直接以写方式打开「正在执行」的二进制 ==\n");
    errno = 0;
    int fd = open(PROG, O_WRONLY);
    printf("  open(PROG, O_WRONLY) = %d errno=%d(%s)\n",
           fd, errno, fd == -1 ? strerror(errno) : "未置位");
    if (fd == -1)
        printf("  → 被拒。Linux 上此即 ETXTBSY(16)「Text file busy」。\n");
    else {
        printf("  → ⚠️ 本机 macOS(APFS) **不 enforce ETXTBSY**：正在执行的二进制\n");
        printf("     竟可被写打开（危险！）。Linux 上是 ETXTBSY(16)。跨平台务必单独验证。\n");
        close(fd);
    }

    printf("\n== ③ cc 的「覆盖」：建新 inode + rename，老 inode 被 fd 吊住 ==\n");
    snprintf(cp, sizeof cp, "cp %s %s", argv[0], PROG_NEW);   /* 冒充"重新编译的产物" */
    if (system(cp) != 0) { perror("copy new"); return EXIT_FAILURE; }
    printf("  「重新编译」产出 %s（inode=%lu）\n",
           PROG_NEW, (unsigned long) ino_of(PROG_NEW));
    errno = 0;
    int r = rename(PROG_NEW, PROG);            /* 就是 cc 落盘那一下 */
    printf("  rename(.new → 老名字) = %d %s\n", r, r == 0 ? "" : strerror(errno));
    printf("  覆盖后 PROG 的 inode = %lu  %s\n",
           (unsigned long) ino_of(PROG),
           ino_of(PROG) == ino_before ? "→ 没变（意外）"
                                      : "→ 已换成新 inode ✔（ls -li 可验证）");
    printf("  老 inode %lu 呢？", (unsigned long) ino_before);
    printf("  再次探活：%s\n", probe(child));
    printf("  ⇒ 所谓「覆盖正在执行的程序」= §18.4 的 rename 原子替换；\n");
    printf("     老 inode 因 nlink 归零但仍有 fd 而存活，直到进程退出（§18.3）。\n");

    printf("\n== ④ 子进程退出后再写打开 ==\n");
    int st;
    kill(child, SIGTERM);                      /* 不等 20 秒 */
    waitpid(child, &st, 0);
    errno = 0;
    fd = open(PROG, O_WRONLY);
    printf("  open(O_WRONLY) = %d errno=%d(%s)\n",
           fd, errno, fd == -1 ? strerror(errno) : "未置位");
    if (fd != -1) {
        printf("  → 成功。与 ② 对比：若 ② 为 ETXTBSY，这就是「忙 / 闲」的判据。\n");
        close(fd);
    }

    unlink(PROG); unlink(PROG_NEW);
    return EXIT_SUCCESS;
}
```

实测输出：

```text
== ③ cc 的「覆盖」：建新 inode + rename，老 inode 被 fd 吊住 ==
  老 inode 2278094 呢？  再次探活：仍在运行 ✔
  覆盖后 PROG 的 inode = 2278099  → 已换成新 inode ✔
```

完整解释见 [18.16 习题](18.16-exercises.md)：`cc` 之所以能「覆盖」正在运行的程序，正是因为 rename 换的是目录项——**老 inode 被运行中进程的 fd 吊着，数据根本没被碰**。

## 常见坑

| 坑 | 正解 |
|----|------|
| 以为 `rename` 能跨文件系统 | `EXDEV`；「跨 FS 移动」内核不提供原子接口，只能复制+删除（非原子） |
| safe-write 里忘了 `fsync` | 掉电后 rename 落了、数据没落，配置文件变半截——比不写还糟 |
| `rename(dir, dir/sub)` 期望移动 | `EINVAL`：不能把目录放进自己的子树（会造出不可达的环） |
| 用 `rename` 替换**目录**里的文件时忘了目录规则 | 目标目录必须**空**；非空目录不能被覆盖（`ENOTEMPTY`） |
| 以为 rename 会更新文件 mtime | 不会（[15.2 实测](../../chapter-15-file-attributes/notes/15.2-file-timestamps.md)：Linux 不动；macOS 会动 **ctime**——跨平台别当不变量） |
| 多线程下两个线程各 rename 到同一路径 | 结果是「最后一次赢」，但**每次都是原子的**——不会出现半截状态；要有序就加锁或用唯一临时名 |
| 拿 `rename` 当「加锁」原语 | `rename` 不报 `EEXIST`（直接覆盖）；互斥要么 `link()`（会 `EEXIST`）要么 `O_CREAT\|O_EXCL` |

## HFT / 嵌入式关联

| 场景 | 本节机制怎么兑现 |
|------|----------------|
| 配置热更新 | 「写 tmp + fsync + rename」是唯一能保证**读者永远看到一致文件**的手法；配合 inotify（Ch19）做无损重载 |
| 行情文件落盘 | 逐 tick 直接写会暴露半截数据；按「整文件写完再 rename」提交，下游 `open` 永远拿到完整版本 |
| 掉电安全 | 嵌入式无 UPS，`fsync`+`rename` 的顺序就是掉电安全协议；顺序错了 journal 也救不回 |
| 日志轮转 | `mv app.log app.log.1` 后**老进程还往旧 inode 写**——轮转工具必须配合「重开 fd」或用 `O_APPEND`+信号，否则磁盘悄悄涨 |
| 原子互斥 | `link()` 的 `EEXIST` 语义可做跨进程锁（比 `rename` 正确，见坑表最后一行） |

<summary>代码自测（Q&A）</summary>

**Q1：rename 是「原子的」到底指什么？**
A：指**可见性**——任何时刻，`newpath` 要么解析到完整的老文件、要么解析到完整的新文件，绝无「半新半旧」或「名字消失」的中间态。它**不**保证数据已落盘（那是 `fsync` 的事），也不保证并发 rename 的顺序。

**Q2：为什么 `rename(file, dir)` 是 `EISDIR` 而 `rename(dir, file)` 是 `ENOTDIR`？两个不是一回事吗？**
A：内核分两步检查：先看 `oldpath` 的类型能不能覆盖 `newpath` 的类型。文件→目录：目录不能被普通文件覆盖 → `EISDIR`（「newpath 是目录，而你给的是文件」）；目录→文件：目录不能被当文件写 → `ENOTDIR`。实测与 Linux 一致。

**Q3：`rename` 同目录和跨目录有性能差吗？**
A：同一 FS 内都是 O(1)（改几个目录项 + 移动 inode 的 parent 指针），跨目录只多一层目录的修改，量级不变。**真正的分水岭是跨文件系统**（`EXDEV`，必须复制）。

**Q4：safe-write 为什么要先 `fsync(fd)` 再 `rename`？顺序能反吗？**
A：不能反。`rename` 只是把目录项指向新 inode，这个操作自己会被 journal 记下；如果数据块还没落盘，掉电后 journal 回放可能得到「名字指向了新 inode，但新 inode 的数据块是垃圾」。先 `fsync` 保证数据先于名字可见。

**Q5：`renameat2` 的 `RENAME_EXCHANGE` 是什么？**
A：Linux 3.15+ 专有：**原子互换**两个路径（不是覆盖）。可以用来做「双缓冲目录」——但 macOS 没有，跨平台代码要留好降级路径。Pi5 复测清单可补一条实测。

**Q6：用 `rename` 做进程间锁为什么是错的？**
A：`rename` 的语义是「无条件覆盖」——两个进程同时 rename 同一目标，都会成功，锁形同虚设。正确的原子互斥用 `link()`（目标已存在则 `EEXIST`）或 `open(O_CREAT|O_EXCL)`；解锁用 `unlink`。
