# 18.6 Creating and Removing Directories: mkdir() and rmdir() 创建与删除目录

> 本章：[TLPI 第 18 章 — Directories and Links](../README.md)
> 实测环境：macOS 26.6.2 (arm64) · clang 23.1.0（micromamba cdev）· APFS；Linux 专有行为按 man-pages 6.19 / 内核 v6.6 源码标注
> 源码核验：man-pages **6.19** `mkdir(2)` / `rmdir(2)` / `unlinkat(2)` + Linux v6.6 `fs/namei.c`（`vfs_mkdir`/`vfs_rmdir`）
> - 上一节：[18.5 symlink() and readlink()](18.5-working-with-symbolic-links-symlink-and-.md)
> - 下一节：[18.7 remove()](18.7-removing-a-file-or-directory-remove.md)

---

## 本节讲什么

1. `mkdir()` 的 `mode` 参数**受 umask 削减**（和 `open` 同一套规则），且目录**必须有 `x` 才有用**；
2. `rmdir()` 只吃**空目录**——「空」的判定是「只有 `.` 和 `..`」；
3. 目录的 `st_nlink` 在这里形成闭环：新建目录的瞬间，父目录 +1、自己 = 2；
4. `mkdir` 的存在性检查是**内核原子**完成的，不是「先 stat 再 mkdir」。

---

## 要点：契约表

```c
#include <sys/stat.h>
int mkdir(const char *pathname, mode_t mode);   /* mode 受 umask 削减 */
int mkdirat(int dirfd, const char *pathname, mode_t mode);
#include <unistd.h>
int rmdir(const char *pathname);
```

| 调用 | 结果 | 实测错误码 |
|------|------|-----------|
| `mkdir(已存在)` | 失败 | `EEXIST`（File exists） |
| `mkdir(父目录不存在)` | 失败 | `ENOENT`（不自动建多级；要 `mkdir -p` 得自己循环） |
| `rmdir(非空目录)` | 失败 | `ENOTEMPTY`（Directory not empty） |
| `rmdir(普通文件)` | 失败 | `ENOTDIR`（Not a directory） |
| `rmdir(指向目录的符号链接)` | 失败 | `ENOTDIR` —— 删链接本身要用 `unlink` |
| `rmdir(".")` / `rmdir("..")` | 失败 | `EINVAL`（macOS 实测两者同码；Linux man-pages 只把「末组件为 `.` → `EINVAL`」写进契约，`..` 的具体码**待 Pi5 复测**） |

**「空」的精确定义**：目录里只剩 `.` 和 `..` 两条目录项。哪怕里面有一个**符号链接**或一个**空子目录**，都算非空——递归删除必须自后序遍历（见 §18.9 的 `FTW_DEPTH`）。

## 实测：umask 削减与 st_nlink 闭环（[`code/c18_6_mkdir_rmdir.c`](../code/c18_6_mkdir_rmdir.c)）

```text
== ① mkdir 的 mode 受 umask 削减 ==
  当前 umask = 0022
  mkdir(d, 0777)                             = 0 
  实得 mode = 0755（= 0777 & ~0022）

== ② 目录的 st_nlink = 2 + 子目录数 ==
  空目录 d          st_nlink = 2   ← 自己
  建 d/sub 之后 d   st_nlink = 3   ← +子目录的 ".."
  ⚠️ d/sub 自己的 st_nlink = 2（新建空目录恒为 2）

== ③ rmdir 只吃空目录 ==
  rmdir(非空 d)                            = -1 Directory not empty
  rmdir(普通文件)                        = -1 Not a directory
  rmdir(指向目录的符号链接)         = -1 Not a directory
  → 删链接本身请用 unlink；rmdir 只跟到底层对象的类型
  rmdir(".")                                 = -1 Invalid argument
  rmdir("..")                                = -1 Invalid argument

== ④ unlinkat(AT_REMOVEDIR) == rmdir ==
  unlinkat(dfd, "f", 0)             = 0 
  unlinkat(dfd, "sub", AT_REMOVEDIR)   = 0 

== ⑤ mkdir 的前置检查（都是内建原子性，不是先 stat 再建）==
  mkdir(已存在的 d)                      = -1 File exists
  mkdir(父目录不存在)                  = -1 No such file or directory
  rmdir(空 d)  ← 现在可以了          = 0 
```

三个要点：

- **umask 削减**：`0777 & ~0022 = 0755`。若要「确保」某权限位，`mkdir` 后得再 `chmod`（或先临时清 umask）。另注意：即使 umask 是 0，`mkdir` 也会**自动置上执行位**（内核保证目录至少 `x`）——因为没 `x` 的目录连 cd 都进不去。
- **`st_nlink` 闭环**：`mkdir(sub)` 同时做了两件事——给父目录 `nlink+1`，给新目录 `nlink=2`。所以「目录的 nlink 永远能被子目录数解释」（[18.1 实测](18.1-directories-and-hard-links.md)）。
- **`rmdir` 对符号链接报 `ENOTDIR`** 是最常被误判的一条：很多人以为它会顺着链接去删目录，实际它先 `lstat` 判类型——链接不是目录，所以拒绝。**删链接用 `unlink`**。

## 要点：mkdir 的原子性（与 TOCTOU 的关系）

`mkdir(已存在) → EEXIST` 意味着「检查 + 创建」在内核里是**一步**完成的。因此：

```c
/* ✗ 有竞态：stat 和 mkdir 之间目录可能被别人建出来 */
if (stat(dir, &sb) == -1) mkdir(dir, 0755);

/* ✓ 无竞态：EEXIST 就当作"已经在了" */
if (mkdir(dir, 0755) == -1 && errno != EEXIST) { /* 真错误 */ }
```

这个模式和 §18.3 的「先 open 再 unlink」、§18.4 的「link 做锁」是同一族：**把检查交给 syscall 的错误码，别自己排 stat**。

## 常见坑

| 坑 | 正解 |
|----|------|
| `mkdir(path, 0777)` 以为会得到 0777 | umask 削减（实测 0022 → 0755）；要精确权限就 mkdir 后 `chmod` |
| `mkdir("/a/b/c")` 期望自动建 `/a`、`/a/b` | `ENOENT`；多级要自己逐级 mkdir（`mkdir -p` 逻辑）或接受 `EEXIST` |
| `rmdir(符号链接)` 以为会删到目录 | `ENOTDIR`；删链接用 `unlink`，删目录用 `rmdir`，两种类型两种入口 |
| `rmdir` 非空目录后自己写递归删除 | 先序遍历会失败（父目录非空）；必须**后序**（先删子再删父），即 `nftw + FTW_DEPTH`（§18.9） |
| 以为 `rmdir("..")` 能「回到上层删掉自己」 | `EINVAL`；内核不许摘断树上的节点 |
| 拿 `mkdir` 做「只有第一个进程能成功」的锁 | 可以！`EEXIST` 语义天然适合做互斥（与 `open(O_CREAT\|O_EXCL)` 同族），但记得失败路径要清理 |

## HFT / 嵌入式关联

| 场景 | 本节机制怎么兑现 |
|------|----------------|
| 分桶目录创建 | 按 `HH/MM` 分桶存行情：`mkdir` + `errno==EEXIST` 判定，多线程/多进程无锁并发建目录 |
| 目录权限即访问边界 | 落盘目录 `0750`（组可进、他人不可见）；`0777 & ~umask` 的削减规律决定了「为什么部署脚本里总有人 chmod 不生效」 |
| 嵌入式 `mkdir -p` | BusyBox 的 `mkdir -p` 就是一个循环 + 忽略 `EEXIST`；自己实现时**忽略 EEXIST** 是关键，别把它当错误 |
| 掉电安全 | `mkdir` 是元数据操作，journal 化后要么成功要么失败，不会出现「半个目录」；但**目录里的文件**需要额外 fsync |
| 互斥引导 | 单实例守护进程用 `mkdir("/var/run/myapp.lock")` 抢占（`EEXIST` = 已在跑），比 PID 文件更原子 |

<details>
<summary>代码自测（Q&A）</summary>

**Q1：`mkdir(path, 0777)` 在 umask=0 时会得到 0777 吗？**
A：会得到 0777（或内核补充的必要位）。但 umask=0 的进程很少见；实测默认 0022 → 0755。要**精确**权限只能 mkdir 后 `chmod`，或临时 `umask(0)` 再恢复（多线程下危险）。

**Q2：为什么目录即使 umask 全掩也至少有 `x`？**
A：内核在 `vfs_mkdir` 里会 `|=S_IXUGO` 的必要部分——没有 `x` 的目录连 `cd` 都进不去，是个无意义的对象。这是「目录权限的最小可用集」的实现层保证。

**Q3：`rmdir` 对「指向目录的符号链接」报什么？为什么？**
A：`ENOTDIR`。内核先对路径做类型判定（等价 `lstat`），链接不是目录 → 拒绝。这与 `open`（会跟随链接）形成对比：**删除类接口对链接都是「删链接本身」**。

**Q4：`mkdir` 的 `EEXIST` 能当「目录已存在」的可信信号吗？**
A：能，而且**这正是它的推荐用法**。`mkdir` 在内核里原子完成「检查+创建」，`EEXIST` 表示「现在确实已经存在（不管是谁建的、什么时候建的）」。比「先 stat 再 mkdir」严格更优。

**Q5：`rmdir(".")` 为什么不允许？**
A：删掉「当前正在里面」的目录会让 cwd 悬空，且「.」是目录自身对自身的引用，摘掉它等于摘断树。内核直接 `EINVAL`。macOS 对 `..` 也给 `EINVAL`；Linux 的具体码未在本机核验，见 Pi5 复测清单。

**Q6：递归删除一个目录树，为什么必须后序（FTW_DEPTH）？**
A：`rmdir` 只删**空**目录。先序遍历会在子项还在时尝试删父目录 → `ENOTEMPTY`。后序保证到达一个目录时它的所有子项已被删光，`rmdir` 必然成功。

</details>
