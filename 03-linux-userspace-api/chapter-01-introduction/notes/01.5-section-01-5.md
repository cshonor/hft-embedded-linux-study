1. **应用层以 POSIX 为基准**（`open/read/write`、`fork`、`pthread`、信号、定时器、SHM…）→ 易在 x86 PC / ARM 板子间移植。 2. **驱动 / 内核模块不受 POSIX 约束**——POSIX 只管用户态 API；内核是 Linux 独有（走 LKD）。 3. SUS：几乎不关心（除非要迁 Solaris/AIX 等真 UNIX）。

## 要点

| 类型 | 例子 | 可移植性 |
|------|------|----------|
| **POSIX 标准 API** | `fork`、`pipe`、`socket`、`pthread`、`clock_gettime`、`mlock`、`SCHED_FIFO`（实时扩展） | Linux / macOS / BSD 等通用（程度因实现而异） |
| **Linux 特有扩展** | `epoll`、`signalfd`、`timerfd`、`io_uring`、`sched_setaffinity`、大页、`SO_BUSY_POLL` / TPACKET… | **仅 Linux** |

### 嵌入式 Linux（用户态应用）

1. **应用层以 POSIX 为基准**（`open/read/write`、`fork`、`pthread`、信号、定时器、SHM…）→ 易在 x86 PC / ARM 板子间移植。  
2. **驱动 / 内核模块不受 POSIX 约束**——POSIX 只管用户态 API；内核是 Linux 独有（走 LKD）。  
3. SUS：几乎不关心（除非要迁 Solaris/AIX 等真 UNIX）。  
4. LSB：静态链接、裁剪根文件系统场景下跨发行版二进制兼容无价值 → **忽略**。

### HFT（低延迟用户态）

1. **基础仍靠 POSIX**：单调时钟、pthread、实时信号、`mlock`、实时调度等。  
2. **极致延迟会用大量 Linux 私有扩展**（`io_uring`、亲和性、大页、忙轮询 socket…）。  
3. **规则：基础逻辑尽量 POSIX；热路径优化主动用 Linux 专属，放弃可移植。**  
4. SUS / LSB 对固化机房（固定发行版+内核）**无意义**。

### 极简工程守则

1. 学习 / 面试：弄清三者关系，**核心吃透 POSIX**。  
2. 业务：可移植 → 只用 POSIX；HFT/嵌入式底层优化 → 允许 Linux 扩展（文档标清「非标准」）。  
3. SUS：概念即可，不当硬约束。  
4. LSB：历史产物，现代开发不考虑。

## 与 C 语言学习的关系

系统调用与 C 标准库的关系是 C 语言系统编程的核心概念。C 标准只定义函数接口（如 `fopen`），不规定实现；Linux 上由 glibc 实现并最终调用内核系统调用。理解这一分层对掌握 Unix C 编程至关重要。对照 K&R 第 8 章学习文件 I/O 的 C 标准库接口，与本模块的 POSIX 系统调用接口对比。

## 常见陷阱

1. **混淆系统调用与库函数**

```c
/* printf 是库函数，write 是系统调用 */
printf("hello
");      /* glibc 处理缓冲+格式化 */
write(1, "hello
", 6);  /* 直接陷入内核 */
```

系统调用是内核接口（open/read/write），库函数是用户态封装（fopen/fread/fwrite）。库函数内部可能调用系统调用，但不是系统调用本身。

2. **errno 检查时机错误**

```c
int fd = open("f.txt", O_RDONLY);
if (errno) perror("open");  /* 错误! */
if (fd < 0) perror("open");  /* 正确 */
```

errno 只在系统调用失败时被设置，成功时不清零。必须先检查返回值判断是否出错，再读 errno。

3. **假设系统调用跨平台一致**

```c
/* Linux: signal() 不恢复默认handler */
/* BSD: signal() 恢复默认handler */
signal(SIGINT, handler);
```

同名的系统调用/库函数在不同 Unix 变体上行为可能不同。生产代码应查文档并用 POSIX 接口（如 sigaction 代替 signal）。

## 自测题

**题目 1（选择）：** 系统调用失败时通常返回什么？
A. 0
B. -1
C. NULL
D. 取决于函数

<details>
<summary>参考答案</summary>

B。大多数系统调用失败时返回 -1 并设置 errno。但 pthread 函数返回错误码，mmap 返回 MAP_FAILED。

</details>

**题目 2（判断）：** errno 在函数成功返回时会被清零。

<details>
<summary>参考答案</summary>

错误。errno 只在失败时被设置，成功时不会清零。不能通过 errno 判断是否出错，必须先检查返回值。

</details>

**题目 3（踩坑）：** 以下代码有什么问题？
```c
FILE *fp = fopen("f.txt", "r");
if (errno) {
    printf("error: %s
", strerror(errno));
}
```

<details>
<summary>参考答案</summary>

fopen 成功时 errno 不被清零——可能保留前一次调用的错误值。应检查返回值：`if (fp == NULL)` 而非 `if (errno)`。

</details>

**题目 4（应用）：** 写一个通用的错误检查宏，检查系统调用返回值并在失败时报错退出。

<details>
<summary>参考答案</summary>

```c
#define CHECK(call) do { \
    if ((call) < 0) { \
        perror(#call); \
        exit(EXIT_FAILURE); \
    } \
} while(0)
CHECK(open("f.txt", O_RDONLY));
```

</details>
