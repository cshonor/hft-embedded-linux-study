## 本节讲什么

**GNU**（GNU's Not Unix）是 Stallman 发起的自由软件项目：目标是提供一套**完全自由**、兼容 UNIX 风格的操作系统，重点在**用户态**组件（编译器、编辑器、C 库、shell、常用命令等）。 Linus 写的是 **Linux 内核**（1991）：管进程、内存、驱动、系统调用等底层；**不含** shell/`ls`/`gcc` 这类用户态程序。 GNU 自己的内核（Hurd）未成主流；和 Linux 内核一结合，才形成日常说的「Linux 系统」。

## 要点

**GNU**（GNU's Not Unix）是 Stallman 发起的自由软件项目：目标是提供一套**完全自由**、兼容 UNIX 风格的操作系统，重点在**用户态**组件（编译器、编辑器、C 库、shell、常用命令等）。  
Linus 写的是 **Linux 内核**（1991）：管进程、内存、驱动、系统调用等底层；**不含** shell/`ls`/`gcc` 这类用户态程序。  
GNU 自己的内核（Hurd）未成主流；和 Linux 内核一结合，才形成日常说的「Linux 系统」。

| 部件 | 谁 | 内容 |
|------|-----|------|
| **Linux 内核** | Linus 等 | 地基：硬件与资源管理、syscall |
| **GNU 用户态** | Stallman 项目等 | 房子：glibc、bash、gcc、make、coreutils（`ls`/`cp`…） |

**完整发行版 ≈ Linux 内核 + GNU 用户态工具链**（再加包管理、桌面等；其中也有非 GNU 组件，如 systemd）

类比：**内核 = 地基，GNU = 盖在上面的房子**；只有内核几乎没法日常用。

> ❌ 勿混：**Linux ≠ GNU**。内核与用户态是两套独立项目；Linus 没写 GNU，Stallman 也没写 Linux 内核。  
> glibc 封装 syscall — 对照 [04 LKD Ch5 libc≠syscall](../../05-linux-kernel/00_Book_3rd_Notes/chapter-05-system-calls/notes/section-5.1-与内核通信.md)

## 与 C 语言学习的关系

系统调用与 C 标准库的关系是 C 语言系统编程的核心概念。C 标准只定义函数接口（如 `fopen`），不规定实现；Linux 上由 glibc 实现并最终调用内核系统调用。理解这一分层对掌握 Unix C 编程至关重要。对照 K&R 第 8 章学习文件 I/O 的 C 标准库接口，与本模块的 POSIX 系统调用接口对比。

## 常见陷阱

1. **混淆系统调用与库函数**

```c
/* printf 是库函数，write 是系统调用 */
printf("hello
");      /* glibc 处理缓冲+格式化 */
write(1, "hello
", 6);  /* 直接陷入内核 */
```

系统调用是内核接口（open/read/write），库函数是用户态封装（fopen/fread/fwrite）。库函数内部可能调用系统调用，但不是系统调用本身。

2. **errno 检查时机错误**

```c
int fd = open("f.txt", O_RDONLY);
if (errno) perror("open");  /* 错误! */
if (fd < 0) perror("open");  /* 正确 */
```

errno 只在系统调用失败时被设置，成功时不清零。必须先检查返回值判断是否出错，再读 errno。

3. **假设系统调用跨平台一致**

```c
/* Linux: signal() 不恢复默认handler */
/* BSD: signal() 恢复默认handler */
signal(SIGINT, handler);
```

同名的系统调用/库函数在不同 Unix 变体上行为可能不同。生产代码应查文档并用 POSIX 接口（如 sigaction 代替 signal）。

## 自测题

**题目 1（选择）：** 系统调用失败时通常返回什么？
A. 0
B. -1
C. NULL
D. 取决于函数

<details>
<summary>参考答案</summary>

B。大多数系统调用失败时返回 -1 并设置 errno。但 pthread 函数返回错误码，mmap 返回 MAP_FAILED。

</details>

**题目 2（判断）：** errno 在函数成功返回时会被清零。

<details>
<summary>参考答案</summary>

错误。errno 只在失败时被设置，成功时不会清零。不能通过 errno 判断是否出错，必须先检查返回值。

</details>

**题目 3（踩坑）：** 以下代码有什么问题？
```c
FILE *fp = fopen("f.txt", "r");
if (errno) {
    printf("error: %s
", strerror(errno));
}
```

<details>
<summary>参考答案</summary>

fopen 成功时 errno 不被清零——可能保留前一次调用的错误值。应检查返回值：`if (fp == NULL)` 而非 `if (errno)`。

</details>

**题目 4（应用）：** 写一个通用的错误检查宏，检查系统调用返回值并在失败时报错退出。

<details>
<summary>参考答案</summary>

```c
#define CHECK(call) do { \
    if ((call) < 0) { \
        perror(#call); \
        exit(EXIT_FAILURE); \
    } \
} while(0)
CHECK(open("f.txt", O_RDONLY));
```

</details>
