## 本节讲什么

1. 新建文件的属主/属组**继承规则**——SYSV 与 BSD 两派在这里分家（实测把两派都钉住了）；
2. `chown()` 的三条规则（-1 语义 / 特权边界 / 特殊位清除）；
3. 非特权用户到底能改什么？本机实测给出了比书更细的答案。

---

## 要点：接口与新文件继承

```c
#include <unistd.h>
int chown(const char *pathname, uid_t owner, gid_t group);
int fchown(int fd, uid_t owner, gid_t group);
int lchown(const char *pathname, uid_t owner, gid_t group);  /* 不跟随链接 */
```

**§15.3.1 新文件的属组**——两派规则：

| 规则 | 适用 | 效果 |
|------|------|------|
| SYSV（Linux 默认） | 新文件属组 = 进程 **egid**；目录带 SGID 时 = **目录属组** | `/tmp` 下新文件 gid=你的组 |
| BSD（macOS 实测） | 新文件属组 = **父目录的属组**（S_ISGID 目录同理） | `/tmp`(root:wheel) 下新文件 gid=**0** |

**实测钉死**：在 macOS 的 `/tmp`（root:wheel）里新建文件，`st_gid=0` 而不是进程 egid=20——书上说"new file's group is the egid of the process"，那是 SYSV/Linux 的规则；BSD 一律继承父目录。跨平台工具别假设新文件的属组。

## 实测：chown 的三条规则

**完整源码（[`code/c15_4_chown.c`](../code/c15_4_chown.c)）：**

```c
/* c15_4_chown.c — Ch15 §15.3：chown() 的三条规则，本机（非特权用户）能验证哪几条
 *
 * TLPI §15.3.2 的规则（书中以特权进程为前提，本机 a0000 非 root，能实测
 * 的是子集，其余标注「需特权」）：
 *   ① 传 -1 表示「这一项不变」——chown(path, -1, -1) 合法且**会更新 ctime**；
 *   ② 非特权进程改属组：只能改成**自己补充组里已有的组**（Linux），
 *      BSD/macOS 规则不同（要求 egid 或补充组之一）——实测本机表现；
 *   ③ 非特权进程改属主：一律 EPERM（需 CAP_CHOWN / root）；
 *   ④ 非特权进程成功 chown 之后，S_ISUID/S_ISGID 位被内核清掉
 *      ——这是安全机制：防止「借 chown 保住 SUID」的提权路径。
 *      本机改不了属主，这条以「改组时 S_ISGID 是否被清」侧面观察。
 *
 * 编译： cc -Wall -Wextra -o c15_4_chown c15_4_chown.c
 * 取材： man-pages 6.19 chown(2)（EPERM / 特权与 SUID 清除段）
 *       TLPI §15.3.1/15.3.2（新文件属主规则 + chown 三规则）
 *       Linux v6.6 fs/attr.c notify_change()（ATTR_UID/ATTR_GID + SUID 清除）
 */
#include <errno.h>
#include <fcntl.h>
#include <grp.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <sys/stat.h>
#include <unistd.h>

/* 相当于 TLPI ugid_functions.h 的 groupIdFromName（本 demo 自带迷你版） */
static gid_t groupIdFromNameSafe(const char *name)
{
    struct group *g = getgrnam(name);
    return g ? g->gr_gid : (gid_t) -1;
}

static void show(const char *tag, const char *path)
{
    struct stat sb;
    if (stat(path, &sb) == -1) { perror("stat"); exit(EXIT_FAILURE); }
    printf("  %-22s uid=%-5ld gid=%-5ld mode=%04lo%s%s\n",
           tag, (long) sb.st_uid, (long) sb.st_gid,
           (unsigned long) (sb.st_mode & 07777),
           (sb.st_mode & S_ISGID) ? " +SGID" : "",
           (sb.st_mode & S_ISUID) ? " +SUID" : "");
}

int main(void)
{
    const char *path = "/tmp/tlpi_c15_4.txt";
    uid_t euid = geteuid();
    gid_t egid = getegid();

    printf("== ⓪ 本机身份：euid=%ld egid=%ld（非特权用户视角）==\n\n",
           (long) euid, (long) egid);

    /* ---------- ① chown(-1,-1) 合法且动 ctime ---------- */
    printf("== ① chown(path, -1, -1)：POSIX 要求更新 ctime；本机是否照做实测 ==\n");
    unlink(path);
    int fd = open(path, O_RDWR | O_CREAT | O_EXCL, 0644);
    if (fd == -1) { perror("open"); return EXIT_FAILURE; }
    struct stat b, a;
    if (stat(path, &b) == -1) { perror("stat"); return EXIT_FAILURE; }
    sleep(1);
    if (chown(path, -1, -1) == -1) { perror("chown(-1,-1)"); return EXIT_FAILURE; }
    if (stat(path, &a) == -1) { perror("stat2"); return EXIT_FAILURE; }
    printf("  ctime %ld.%09ld → %ld.%09ld（%s）\n",
           (long) b.st_ctimespec.tv_sec, (long) b.st_ctimespec.tv_nsec,
           (long) a.st_ctimespec.tv_sec, (long) a.st_ctimespec.tv_nsec,
           b.st_ctimespec.tv_sec != a.st_ctimespec.tv_sec ||
           b.st_ctimespec.tv_nsec != a.st_ctimespec.tv_nsec ? "动了" : "没动");
    printf("  ⚠️ POSIX 规定 chown() 成功后应更新 ctime（含 no-op 版）；Linux 实测\n");
    printf("     会动。本机 macOS 实测%s——BSD 对「值没变」短路了。\n",
           b.st_ctimespec.tv_sec != a.st_ctimespec.tv_sec ||
           b.st_ctimespec.tv_nsec != a.st_ctimespec.tv_nsec ? "动了" : "没动（跨平台差异！）");
    printf("     审计代码别依赖「空 chown 必动 ctime」，两个平台表现不同。\n\n");

    /* ---------- ②③ 非特权改属主 / 改属组 ---------- */
    printf("== ②③ 非特权进程改属主/属组：实测边界 ==\n");
    printf("  chown(path, 0, -1)（改成 root）: ");
    errno = 0;
    int r = chown(path, 0, -1);
    printf("ret=%d errno=%d(%s)  ← 改属主一律被拒（需 CAP_CHOWN）\n",
           r, errno, strerror(errno));

    /* 试试改成「 wheel 」（通常不是我们的补充组） */
    gid_t wheel = groupIdFromNameSafe("wheel");
    printf("  chown(path, -1, %ld)（wheel 组）: ", (long) wheel);
    errno = 0;
    r = chown(path, -1, wheel);
    printf("ret=%d errno=%d(%s)%s\n", r, errno, strerror(errno),
           r == 0 ? "  ← 本机竟然允许（BSD 不检查组成员关系）" : "");

    /* 改成自己所在的组 */
    printf("  chown(path, -1, %ld)（自己的 egid）: ", (long) egid);
    errno = 0;
    r = chown(path, -1, egid);
    printf("ret=%d errno=%d(%s)  ← 「不改任何东西」的改组总是允许\n",
           r, errno, strerror(errno));
    show("改组后", path);
    printf("  ⚠️ man-pages 写的是 Linux 规则（只能改成补充组里的组）；本机实测\n");
    printf("     macOS 连非成员的 wheel 都放行——BSD 实现比文档宽松。\n");
    printf("     跨平台程序对「改组会不会 EPERM」别做细粒度假设，以返回码为准。\n\n");

    /* ---------- ④ chown 是否清 SGID（侧面观察） ---------- */
    printf("== ④ chown 之后特殊位是否被清（侧面观察 SGID）==\n");
    if (chmod(path, 02755) == -1) { perror("chmod sgid"); return EXIT_FAILURE; }
    show("chmod +SGID 后", path);
    errno = 0;
    r = chown(path, -1, egid);
    printf("  再 chown(-1, 自己的 egid): ret=%d\n", r);
    show("chown 后", path);
    printf("  → 本机观察：%s\n",
           (stat(path, &a) == -1 ? "" :
            (a.st_mode & S_ISGID) ? "SGID 保留（改组前后属组没变，内核不清）"
                                  : "SGID 被清（chown 触发了特殊位清除）"));
    printf("  ⚠️ 书上的完整规则：非特权 chown 成功 → SUID/SGID 都被内核清掉\n");
    printf("     （Linux fs/attr.c 的 notify_change 里 kill S_ISUID|S_ISGID）。\n");
    printf("     完整验证需要 CAP_CHOWN（Pi 上 sudo 跑同一程序可复现）。\n");

    close(fd);
    unlink(path);
    return EXIT_SUCCESS;
}
```

**规则 ①：传 -1 表示"这一项不变"**。`chown(path, -1, -1)` 合法且按 POSIX 应更新 ctime。本机实测出了**跨平台差异**：

```text
== ① chown(path, -1, -1)：POSIX 要求更新 ctime；本机是否照做实测 ==
  ctime …679.428307392 → …679.428307392（没动）
  ⚠️ POSIX 规定 chown() 成功后应更新 ctime（含 no-op 版）；Linux 实测
     会动。本机 macOS 实测没动（跨平台差异！）——BSD 对「值没变」短路了。
```

**规则 ②：非特权的属主/属组边界**：

```text
== ②③ 非特权进程改属主/属组：实测边界 ==
  chown(path, 0, -1)（改成 root）: ret=-1 errno=1(Operation not permitted)  ← 改属主一律被拒（需 CAP_CHOWN）
  chown(path, -1, 0)（wheel 组）: ret=0  ← 本机竟然允许（BSD 不检查组成员关系）
  chown(path, -1, 20)（自己的 egid）: ret=0
  ⚠️ man-pages 写的是 Linux 规则（只能改成补充组里的组）；本机实测
     macOS 连非成员的 wheel 都放行——BSD 实现比文档宽松。
```

| 操作 | Linux（man-pages） | macOS 实测 |
|------|-------------------|-----------|
| 改属主（非特权） | EPERM（需 `CAP_CHOWN`） | EPERM ✅一致 |
| 改属组为补充组内的组 | 允许 | 允许 |
| 改属组为**任意**组 | EPERM | **允许**（宽松，实测 wheel 通过） |

**规则 ③：非特权 chown 成功后，SUID/SGID 被内核清掉**——安全机制，防止"借 chown 保住 SUID"的提权路径。本机侧面观察：

```text
== ④ chown 之后特殊位是否被清（侧面观察 SGID）==
  chmod +SGID 后        uid=501   gid=20    mode=2755 +SGID
  再 chown(-1, 自己的 egid): ret=0
  chown 后              uid=501   gid=20    mode=0755
  → 本机观察：SGID 被清（chown 触发了特殊位清除）
```

内核侧对应 `fs/attr.c notify_change()`：检测到 `ATTR_UID|ATTR_GID` 且无 `CAP_CHOWN` 时 `kill S_ISUID|S_ISGID`。

```c
/* t_chown.c

   Demonstrate the use of the chown() system call to change the owner
   and group of a file.

   Usage: t_chown owner group [file...]

   Either or both of owner and/or group can be specified as "-" to
   leave them unchanged.
*/
#include <pwd.h>
#include <grp.h>
#include "ugid_functions.h"             /* Declarations of userIdFromName()
                                           and groupIdFromName() */
#include "tlpi_hdr.h"

int
main(int argc, char *argv[])
{
    uid_t uid;
    gid_t gid;
    int j;
    Boolean errFnd;

    if (argc < 3 || strcmp(argv[1], "--help") == 0)
        usageErr("%s owner group [file...]\n"
                "        owner or group can be '-', "
                "meaning leave unchanged\n", argv[0]);

    if (strcmp(argv[1], "-") == 0) {            /* "-" ==> don't change owner */
        uid = -1;
    } else {                                    /* Turn user name into UID */
        uid = userIdFromName(argv[1]);
        if (uid == (uid_t) -1)
            fatal("No such user (%s)", argv[1]);
    }

    if (strcmp(argv[2], "-") == 0) {            /* "-" ==> don't change group */
        gid = -1;
    } else {                                    /* Turn group name into GID */
        gid = groupIdFromName(argv[2]);
        if (gid == (gid_t) -1)
            fatal("No such group (%s)", argv[2]);
    }

    /* Change ownership of all files named in remaining arguments */

    errFnd = FALSE;
    for (j = 3; j < argc; j++) {
        if (chown(argv[j], uid, gid) == -1) {
            errMsg("chown: %s", argv[j]);
            errFnd = TRUE;
        }
    }

    exit(errFnd ? EXIT_FAILURE : EXIT_SUCCESS);
}
```

（**原书 Listing 15-2**，dist 逐字镜像；`ugid_functions.{h,c}` 为 dist 随附）。要点：

- `owner` / `group` 传 `"-"` 即映射为 `-1`（"不变"）——**书里的用法演示正好依赖 -1 语义**；
- 非致命错误用 `errMsg` 继续处理后续文件，最后以 `EXIT_FAILURE` 退出——批量运维脚本的正确姿势。

macOS 实测：`t_chown - - file` 返回 0，属主属组均不变。

## 常见坑

| 坑 | 正解 |
|----|------|
| 假设新文件属组 = 进程 egid | BSD 继承父目录组（实测 /tmp 下 gid=0）。要确定就 `fstat` 看 |
| `chown` 后 SUID 还在 | 非特权 chown 必清 SUID/SGID；特权 chown 保住——这也是 15.4.5 安全设计的一环 |
| 用 `chown(-1,-1)`"刷新" ctime 做哨兵 | macOS 上 no-op 短路（实测没动）；Linux 才会动。跨平台哨兵别这么设 |
| `lchown` 与 `chown` 混用 | 对符号链接改属主用 `lchown`；`chown` 会跟到目标 |
| 以为改组也要 root | Linux 改到补充组内的组不需要；macOS 更宽松。以返回码为准 |

## HFT / 嵌入式关联

| 场景 | 本节机制怎么兑现 |
|------|----------------|
| 部署后权限收口 | 服务启动前 `chown` 配置文件到运行账户——顺带被清掉 SUID，正好是想要的 |
| 容器镜像分层 | `COPY --chown` 频繁改属主会复制层；理解 chown 的 inode 语义才能算镜像体积 |
| 嵌入式只读 rootfs | 属性改不动（EROFS），运行期属组策略要靠挂载点 + fstab options |
| 审计 | 属组变更伴随 ctime 更新（Linux）；SGID 被清意味着历史 SUID 程序在换代后可能失效 |
| 多用户数据目录 | SGID 目录 + SYSV 继承规则做共享目录（新建文件自动进项目组）；macOS 天然继承目录组，行为等价但机制不同 |

<details>
<summary>代码自测（Q&A）</summary>

**Q1：`chown(path, -1, -1)` 会不会把属主改成 uid=-1？**
A：不会。`-1` 是"不变"哨兵。实测 ret=0 且 uid/gid 均未变。（若真想设 uid=0xFFFFFFFF 也没有意义——uid_t 溢出值不合法。）

**Q2：非特权用户能把自己文件的属组改成任何组吗？**
A：平台相关。Linux（man-pages 规则）：只能改成补充组里的组，否则 EPERM；本机 macOS 实测连 wheel 都放行。唯一可移植写法是检查返回码。

**Q3：为什么 chown 之后 SUID 消失了？**
A：内核 `notify_change()` 在非特权属主变更时强制清除 S_ISUID/S_ISGID，切断「先做 SUID 后转手」的提权链。本机 SGID 侧写也实测到清除。

**Q4：`lchown()` 的用途？**
A：改符号链接**自身**的属主属组（链接属主无安全含义，但 `chown` 默认跟随链接会误伤目标文件）。

**Q5：新文件属组的两派规则，跨平台程序怎么写才稳？**
A：创建后立刻 `fstat` 读 `st_gid`，不要假设。或创建前给目录设 SGID（两派都认）。

**Q6：no-op chown 更新 ctime 吗？**
A：POSIX 要求更新；Linux 实测更新；macOS 实测不更新（值未变即短路）。别拿它做"touch inode"的技巧。

**Q7：批量 chown 中途出错该退出吗？**
A：学原书 t_chown.c：`errMsg` 记录继续处理剩余文件，最终 exit(EXIT_FAILURE)——批量运维"尽量多做、如实报告"。

</details>
