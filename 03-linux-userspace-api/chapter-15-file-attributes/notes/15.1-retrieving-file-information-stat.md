## 本节讲什么

一句话：**`struct stat` 是内核 inode 的用户态快照**，本节回答四个问题：

1. `stat()` / `lstat()` / `fstat()` 三个入口，对同一个符号链接返回的为什么是**两个 inode** 的信息？
2. `fstat()` 凭什么能躲开路径竞态（TOCTOU）？
3. `st_size`、`st_blocks`、`st_blksize` 三个"大小"各说各的，谁该信谁？
4. 三个时间戳的现代接口为什么必须带纳秒？

---

## 要点：三个调用一张表

```c
#include <sys/stat.h>

int  stat(const char *pathname, struct stat *buf);   /* 跟随符号链接 */
int lstat(const char *pathname, struct stat *buf);   /* 链接自身 */
int fstat(int fd, struct stat *buf);                 /* 已打开的 fd */
```

| 调用 | 符号链接 | TOCTOU | 典型场景 |
|------|---------|--------|---------|
| `stat` | 跟到目标 | 有（路径解析发生在调用时） | 一般查询 |
| `lstat` | 得到链接 inode（`S_ISLNK`） | 有 | `ls -l`、递归遍历 |
| `fstat` | fd 打开那一刻已定 | **无** | 安全检查、fd 复用 |

`fstat` 的价值（自编 demo 实测）：先 `open` 再 `fstat`，之后就算路径被 `rename` / 被换指向，`fstat(fd)` 看到的**永远是打开那一刻的对象**——路径解析只在 `open` 发生一次，这是躲开 TOCTOU 的正解。

---

## 实测：stat 与 lstat 对同一个链接返回两个 inode

完整源码 [`code/c15_1_stat_family.c`](../code/c15_1_stat_family.c)（关键段节选）：

```c
symlink(target, linkpath);          /* target.txt 与 link.lnk 两个 inode */
stat(linkpath, &sb_t);
lstat(linkpath, &sb_l);
/* stat  → regular,  st_size=16  （目标文件的）
   lstat → symlink,  st_size=26  （链接里存的路径串长度） */
```

实测（macOS / APFS）：

```text
== ① stat() 跟随链接，lstat() 看链接自身 ==
  stat(链接)     st_ino=2274505  type=regular st_size=16
  lstat(链接)    st_ino=2274506  type=symlink st_size=26
  链接的 st_size=26 恰好等于它装的目标路径 "/tmp/tlpi_c15_1/target.txt"（26 字节）
  ⚠️ 符号链接的 st_size 不是文件内容长度，是「链接里存的路径串长度」。
```

**符号链接的 `st_size` = 目标路径串的字节数**，这是大多数人第一次被 `struct stat` 打脸的地方。

## 实测：fstat 认 fd 不认路径

```text
== ② fstat() 认 fd 不认路径：rename 之后照样看老对象 ==
  fstat(fd) 的 st_ino = 2274505
  rename(target → linkpath) 后：路径 linkpath 已是普通文件
  stat(linkpath) st_ino = 2274505（路径是新的，对象还是老 inode——同目录 rename 不换 inode）
  fstat(fd)     st_ino = 2274505（还是打开时的老 inode！与 rename 前一致）
  ⚠️ 这就是「先 open 再 fstat」能躲开 TOCTOU 的原因：
     路径解析只发生在 open 那一刻，之后对手怎么改路径都碰不到它。
```

## 实测：三个"大小"的分工

```text
== ③ st_size / st_blocks / st_blksize 三个数各说各的 ==
  稀疏文件：st_size=1048577 B, st_blocks=8 (×512B = 4096 B)
  → 逻辑大小 1 MiB+1，实际磁盘占用只有 8 块（4096 字节）
  ⚠️ 判断「文件多大」用 st_size，判断「占多少磁盘」用 st_blocks×512。
  st_blksize = 4096（优选 IO 块；HFT 日志 IO 按它的倍数对齐最省 syscall）
```

`st_blocks` 的单位是 **512 字节块**（历史包袱，不是 `st_blksize`）——内核 `include/uapi/asm-generic/stat.h` 里写死的约定。

## `struct stat` 核心字段速查

| 字段 | 含义 | 实测备注 |
|------|------|---------|
| `st_dev` / `st_ino` | 所在设备 + inode 号 | 同一文件系统内 `(dev, ino)` 才唯一 |
| `st_mode` | 类型 + 权限 + 特殊位 | 类型用 `S_IS*()` 宏判，别裸与 `S_IFMT` |
| `st_nlink` | 硬链接计数 | 目录最低 2（`.` + 父目录项），见 Ch18 |
| `st_uid` / `st_gid` | 属主 / 属组 | 数字；转名字要查 passwd/group（Ch8） |
| `st_rdev` | 设备文件的 major/minor | 只有 `S_ISCHR/S_ISBLK` 有意义；用 `major()`/`minor()` 拆 |
| `st_size` | 逻辑字节数 | 符号链接=路径串长 |
| `st_blksize` | 优选 IO 块 | 实测 4096 |
| `st_blocks` | 512B 块数 | 稀疏文件可远小于 `st_size/512` |
| `st_atim/mtim/ctim` |三个时间戳（`timespec`） | macOS 叫 `st_atimespec` 等，见 15.2 |

设备号实测：`/dev/zero` 的 `st_rdev=50331651` 拆开是 `major=3 minor=3`。

## 原书 Listing 15-1

完整源码 [`code/t_stat.c`](../code/t_stat.c)（**原书 Listing 15-1**，dist 逐字镜像）：

```c
/* Listing 15-1 */

/* t_stat.c

   A program that displays the information returned by the stat()/lstat()
   system calls.

   Usage: t_stat [-l] file

   The '-l' option indicates that lstat() rather than stat() should be used.
*/
#include <sys/sysmacros.h>
#if defined(_AIX)
#define _BSD
#endif
#if defined(__sgi) || defined(__sun)            /* Some systems need this */
#include <sys/mkdev.h>                          /* To get major() and minor() */
#endif
#if defined(__hpux)                             /* Other systems need this */
#include <sys/mknod.h>
#endif
#include <sys/stat.h>
#include <time.h>
#include "file_perms.h"
#include "tlpi_hdr.h"

static void
displayStatInfo(const struct stat *sb)
{
    printf("File type:                ");

    switch (sb->st_mode & S_IFMT) {
    case S_IFREG:  printf("regular file\n");            break;
    case S_IFDIR:  printf("directory\n");               break;
    case S_IFCHR:  printf("character device\n");        break;
    case S_IFBLK:  printf("block device\n");            break;
    case S_IFLNK:  printf("symbolic (soft) link\n");    break;
    case S_IFIFO:  printf("FIFO or pipe\n");            break;
    case S_IFSOCK: printf("socket\n");                  break;
    default:       printf("unknown file type?\n");      break;
    }

    printf("Device containing i-node: major=%ld   minor=%ld\n",
                (long) major(sb->st_dev), (long) minor(sb->st_dev));

    printf("I-node number:            %ld\n", (long) sb->st_ino);

    printf("Mode:                     %lo (%s)\n",
            (unsigned long) sb->st_mode, filePermStr(sb->st_mode, 0));

    if (sb->st_mode & (S_ISUID | S_ISGID | S_ISVTX))
        printf("    special bits set:     %s%s%s\n",
                (sb->st_mode & S_ISUID) ? "set-UID " : "",
                (sb->st_mode & S_ISGID) ? "set-GID " : "",
                (sb->st_mode & S_ISVTX) ? "sticky " : "");

    printf("Number of (hard) links:   %ld\n", (long) sb->st_nlink);

    printf("Ownership:                UID=%ld   GID=%ld\n",
            (long) sb->st_uid, (long) sb->st_gid);

    if (S_ISCHR(sb->st_mode) || S_ISBLK(sb->st_mode))
        printf("Device number (st_rdev):  major=%ld; minor=%ld\n",
                (long) major(sb->st_rdev), (long) minor(sb->st_rdev));

    printf("File size:                %lld bytes\n", (long long) sb->st_size);
    printf("Optimal I/O block size:   %ld bytes\n", (long) sb->st_blksize);
    printf("512B blocks allocated:    %lld\n", (long long) sb->st_blocks);

    printf("Last file access:         %s", ctime(&sb->st_atime));
    printf("Last file modification:   %s", ctime(&sb->st_mtime));
    printf("Last status change:       %s", ctime(&sb->st_ctime));
}

int
main(int argc, char *argv[])
{
    struct stat sb;
    Boolean statLink;           /* True if "-l" specified (i.e., use lstat) */
    int fname;                  /* Location of filename argument in argv[] */

    statLink = (argc > 1) && strcmp(argv[1], "-l") == 0;
                                /* Simple parsing for "-l" */
    fname = statLink ? 2 : 1;

    if (fname >= argc || (argc > 1 && strcmp(argv[1], "--help") == 0))
        usageErr("%s [-l] file\n"
                "        -l = use lstat() instead of stat()\n", argv[0]);

    if (statLink) {
        if (lstat(argv[fname], &sb) == -1)
            errExit("lstat");
    } else {
        if (stat(argv[fname], &sb) == -1)
            errExit("stat");
    }

    displayStatInfo(&sb);

    exit(EXIT_SUCCESS);
}
```

配套的 [`code/file_perms.c`](../code/file_perms.c) / [`code/file_perms.h`](../code/file_perms.h)（原书 Listing 15-3/15-4）提供 `filePermStr()`，把 `st_mode` 转成 `rw-r--r--` 串。

macOS 实测（`/etc/hosts` 与指向它的链接各打一遍，两个 inode 分明）：

```text
File type:                regular file
Device containing i-node: major=1   minor=15
I-node number:            2161747
Mode:                     100644 (rw-r--r--)
Number of (hard) links:   1
Ownership:                UID=0   GID=0
File size:                213 bytes
Optimal I/O block size:   4096 bytes
512B blocks allocated:    8
Last file access:         Thu Sep  3 18:34:10 2026
Last file modification:   Thu Sep  3 18:34:10 2026
Last status change:       Wed Sep 16 01:55:21 2026
---
File type:                symbolic (soft) link
I-node number:            2274697
```

注意 `Mode: 120755`——类型位 `12` 就是 `S_IFLNK`，原书直接把整个 `st_mode` 八进制打出来。

**本目录为让原书零改动编译做的三件事**（见 [`code/tlpi_hdr.h`](../code/tlpi_hdr.h) 替身头注释）：

| 差异 | 处理 |
|------|------|
| macOS 无 `<sys/sysmacros.h>` | 空壳 shim（`major/minor` 本就在 `sys/types.h`） |
| 替身头缺 `errMsg` / `Boolean` | 按 ch12 替身模式补齐（`Boolean` 用 `typedef int`） |
| `t_chown.c` 需要 `ugid_functions.h` | dist 的 `ugid_functions.{h,c}` 直接随附 |

## 常见坑

| 坑 | 正解 |
|----|------|
| 用 `stat()` 检查完再 `open()` | TOCTOU：两次调用之间路径可被换。先 `open` 拿 fd，再 `fstat` |
| 拿 `st_size` 当磁盘占用 | 磁盘占用是 `st_blocks × 512`；稀疏文件两者差一个数量级 |
| 类型判断裸写 `(mode & S_IFMT) == S_IFREG` | 用 `S_ISREG(m)` 宏，可读且不会漏 |
| 符号链接的 `st_size` 当内容长度 | 它是目标路径串的长度 |
| 秒级 `st_atime` 做时序比较 | 同秒内两次写分不出先后，用 `st_atim`（见 ex15_3） |
| `st_rdev` 当 `st_dev` 用 | `st_dev`=文件所在的文件系统；`st_rdev`=设备文件指向的设备 |

## HFT / 嵌入式关联

| 场景 | 本节机制怎么兑现 |
|------|----------------|
| 热路径免路径解析 | 配置文件启动时 `open` + `fstat` 存下 `(st_dev, st_ino)`，运行期校验 fd 是否还是原文件——`fstat` 是 O(1) 且无路径竞态 |
| 日志 IO 对齐 | 按 `st_blksize`（实测 4096）对齐写，避免 read-modify-write |
| 磁盘配额/水位监控 | `st_blocks × 512` 才是真实占用；按 `st_size` 报容量会误判稀疏文件 |
| 固件/镜像完整性 | `(st_dev, st_ino, st_mtime, st_size)` 四元组做「文件被换过没有」的快速判据 |
| 嵌入式 flash | 芯片上 `st_blksize` 常等于擦除块，IO 对齐它可显著降写放大 |

<details>
<summary>代码自测（Q&A）</summary>

**Q1：`stat()` 和 `lstat()` 对符号链接返回不同的 `st_ino`，哪一个是"链接文件"的？**
A：`lstat()` 返回链接自身的（实测 `2274506` vs 目标 `2274505`）。链接是一个真实 inode，类型位是 `S_IFLNK`，内容就是目标路径串——所以它的 `st_size` 等于路径串长度。

**Q2：为什么"先 `open` 再 `fstat`"没有 TOCTOU？**
A：路径解析（目录项逐级查找 + 权限检查）只发生在 `open()` 那一刻，之后内核操作的是 inode/fd。实测把路径 `rename` 到另一个对象上，`fstat(fd)` 的 `st_ino` 纹丝不动。

**Q3：`st_blocks` 的单位是什么？为什么不是 `st_blksize`？**
A：512 字节（内核 `asm-generic/stat.h` 的历史约定）。`st_blksize` 是"一次 IO 多大最划算"（实测 4096），两者无关。

**Q4：稀疏文件 `st_size=1048577`、`st_blocks=8`，`du` 和 `ls -l` 分别显示什么？**
A：`ls -l` 显示 `st_size`（1 MiB+1），`du` 显示 `st_blocks×512`（4096B，向上取整到块）。哪个"对"取决于你问的是逻辑还是物理。

**Q5：怎么不用 root 也能证明 `fstat` 免疫路径替换？**
A：demo 里 `rename(target, linkpath)` 把符号链接整个覆盖成普通文件后，`stat(linkpath)` 与 `fstat(fd)` 的 `st_ino` 相同且等于打开时的 inode——路径已经指向"另一个名字"，fd 还认得老对象。

**Q6：`major()/minor()` 从哪来？**
A：Linux 在 `<sys/sysmacros.h>`，macOS 直接在 `<sys/types.h>`。本目录用空壳 shim 让原书 `t_stat.c` 在 macOS 零改动编译。

**Q7：`struct stat` 的三个时间戳字段，Linux 和 macOS 的名字差在哪？**
A：Linux `st_atim` / `st_mtim` / `st_ctim`（`struct timespec`），macOS 是 `st_atimespec` / `st_mtimespec` / `st_ctimespec`。跨平台代码用宏抹平（c15_1 的做法），别用秒级字段。

</details>
