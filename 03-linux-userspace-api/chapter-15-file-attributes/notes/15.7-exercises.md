## 15-1 权限论断的实验验证 ✅ 实测

**任务**：§15.4 有若干"什么操作需要什么权限"的论断，用命令或程序验证。

**实现**：[`code/ex15_1_perms.c`](../code/ex15_1_perms.c)，非特权用户可验证的三条全部实测为真：

```text
== (a) 文件 mode=0077：属主被拒（group/other 全开也没用）==
  [属主 open 0077 文件] Permission denied
  结论：属主被拒 = 真（论断成立）

== (b) 目录 mode=0644（无 x）：打开目录内文件被拒 ==
  结论：无 x 不能穿越 = 真（论断成立）

== (c) 目录 mode=0300（-wx）：能创建/删除，不能列 ==
  在 -wx 目录里创建新文件: OK
  在 -wx 目录里 opendir() 列内容: Permission denied
  结论：w 管「增删」，r 管「列名」，x 管「穿越」——三者独立。
```

## 15-2 stat() 会动时间戳吗 ✅ 纸面题

**任务**：`stat()` 会改变文件的三个时间戳吗？

**答案**：**都不会**。`stat` 是纯读操作（读 inode 到用户缓冲），不申请任何 inode 锁、不写任何元数据。三个戳里最"敏感"的 ctime 也纹丝不动——它只在 inode 状态**变更**时更新，读取不算。实测证据：15.2 的 c15_2_timestamps.c 在多次 stat 前后时间戳完全一致。

## 15-3 纳秒精度的时间戳显示 ✅ 实测

**任务**：修改 Listing 15-1（t_stat.c），使时间戳以纳秒精度显示。

**实现**：[`code/ex15_3_nanosecond_stat.c`](../code/ex15_3_nanosecond_stat.c)。三条要点：

1. 用 `st_atim`（Linux）/ `st_atimespec`（macOS）取 `struct timespec`，`strftime` 只管秒、纳秒自己补；
2. 对照 `ctime()` 的秒级输出——**信息在转换时被丢掉**，不是格式化问题；
3. 同一秒内两次 write，秒级比较分不出先后、纳秒可分辨：

```text
同一秒内两次 write 后：
  第一次 mtime: 1789520760.741808711
  第二次 mtime: 1789520760.741833127
  → 秒级比较分不出先后（两值同秒），纳秒比较 可分辨
```

## 15-4 按有效 ID 判权限的 access() ✅ 实测

**任务**：`access()` 按 real ID 判；写一个按 **effective** UID/GID（含补充组）判定的对应函数。

**实现**：[`code/ex15_4_eaccess.c`](../code/ex15_4_eaccess.c)。按 §15.4.3 算法三选一，输出命中哪个三元组：

```text
文件: /etc/hosts  mode=0644  属主=0 属组=0
本进程: euid=501 egid=20（access 按 ruid=501 判，本函数按 euid 判）
  eaccess(R_OK ) = 0   → 按其他三元组判
  eaccess(W_OK ) = -1  → 按其他三元组判
  eaccess(X_OK ) = -1  → 按其他三元组判
普通进程（ruid==euid）里与 access() 对拍： 一致
```

**设计加分**：基于 `fstat` 快照判定，天然免疫 access-then-open 的 TOCTOU 窗口；差异只在 SUID 程序里显现。

## 15-6 实现 chmod a+rX ✅ 实测

**任务**：实现 `a+rX` 语义（所有人加 r；仅当是目录、或已有任一 x 位时才给所有人加 x）。

**实现**：[`code/ex15_6_chmod_arX.c`](../code/ex15_6_chmod_arX.c)。关键：X 需要**旧 mode**，所以 stat→计算→一次 chmod：

```text
/tmp/ex15_6_demo: 0644 → 0644 (无 x: 只加 r)
/tmp/ex15_6_d:    0755 → 0755 (目录: x 全加)
```

## 15-7 简化版 chattr(1) ⛔ Linux 专有（方案保留）

**任务**：写一个简化版 `chattr(1)`（i-node 标志修改器，不需 -R/-V/-v）。
