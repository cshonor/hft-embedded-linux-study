# 15.5 I-node Flags（ext2 Extended File Attributes）i-node 标志

## 本节讲什么

权限位管"谁能做什么"，**i-node 标志**管"这个文件在 FS 层有什么行为"（追加只写、不可改、不 dump……）。与 xattr（Ch16）不同：这些标志由**文件系统解释**、只对 superuser 或文件属主开放修改、且有独立的 `ioctl` 接口 `FS_IOC_GETFLAGS` / `FS_IOC_SETFLAGS`。

---

## 要点：常用标志表

标志定义在内核 `include/uapi/linux/fs.h`（v6.6，坐标实测核对）：

| 标志 | 常量 | 作用 |
|------|------|------|
| Append-only | `FS_APPEND_FL` | 写只能追加（O_APPEND 强制），**root 也删不掉**（先清标志） |
| Immutable | `FS_IMMUTABLE_FL` | 内容/元数据/链接数全冻结，root 也要先清标志 |
| No dump | `FS_NODUMP_FL` | dump(8) 忽略 |
| No access time | `FS_NOATIME_FL` | 读不更新 atime（比 relatime 更狠，单文件粒度） |
| Compressed | `FS_COMPR_FL` | 透明压缩（ext2/4 未合入，btrfs 等） |
| Secure deletion | `FS_SECRM_FL` | 删除时覆写（现代 SSID/trims 下基本失效） |

**为什么 Append-only 是审计/安全基石**：攻击者拿到 root 也无法篡改 append-only 的日志文件——只能追加。HFT 主机与交易所审计都要求交易日志 `+a`。代价：日志轮转必须"改名重建"而不是原地截断。

## 修改接口与特权

```c
#include <sys/ioctl.h>
#include <linux/fs.h>
int fd = open(path, O_RDONLY);          /* 只读打开即可改标志 */
ioctl(fd, FS_IOC_GETFLAGS, &flags);     /* 读 */
flags |= FS_APPEND_FL;
ioctl(fd, FS_IOC_SETFLAGS, &flags);     /* 写（需 CAP_LINUX_IMMUTABLE 级特权） */
```

- 修改者必须是文件属主**或** `CAP_FOWNER`；`FS_IMMUTABLE_FL`/`FS_APPEND_FL` 的设置/清除还需 `CAP_LINUX_IMMUTABLE`；
- **清 immutable 标志本身**是 root 的两步操作：先 `FS_IOC_SETFLAGS` 去标志，再改/删——渗透测试与加固的熟客。

**完整源码（[`code/chiflag.c`](../code/chiflag.c)）：**

```c

/* Solution for Exercise 15-7 */

/* chiflag.c

   Change i-node flags (sometimes also known as ext2 extended file attributes)
   for files named on the command line. Usage is as shown in usageError() below.

   This program won't build on a system that takes its <linux/fs.h> from
   a kernel earlier than 2.6.19. You'll instead need to do something
   like including <linux/ext2_fs.h> and replacing all of the FS_* names
   below by EXT2_*.

   This program is Linux-specific.
*/
#define _GNU_SOURCE
#include <fcntl.h>
#include <sys/ioctl.h>
#include <linux/fs.h>
#include "tlpi_hdr.h"

static void
usageError(const char *progName)
{
    fprintf(stderr, "Usage: %s {+-=}{attrib-chars} file...\n\n", progName);
#define fpe(str) fprintf(stderr, "    " str)            /* Shorter! */
    fpe("+ add attribute; - remove attribute; "
                        "= set attributes absolutely\n\n");
    fpe("'attrib-chars' contains one or more of:\n");
    fpe("    a   Force open() to include O_APPEND "
                        "(privilege required)\n");
    fpe("    A   Do not update last access time\n");
    fpe("    c   Compress (requires e2compr package)\n");
    fpe("    d   Do not backup with dump(8)\n");
    fpe("    D   Synchronous directory updates\n");
    fpe("    i   Immutable (privilege required)\n");
    fpe("    j   Enable ext3/ext4 data journaling\n");
    fpe("    s   Secure deletion (not implemented)\n");
    fpe("    S   Synchronous file updates\n");
    fpe("    t   Disable tail-packing (Reiserfs only)\n");
    fpe("    T   Mark as top-level directory for Orlov algorithm\n");
    fpe("    u   Undelete (not implemented)\n");
    exit(EXIT_FAILURE);
}

int
main(int argc, char *argv[])
{
    if (argc < 3 || strchr("+-=", argv[1][0]) == NULL ||
            strcmp(argv[1], "--help") == 0)
        usageError(argv[0]);

    /* Build bit mask based on attribute string in argv[1] */

    int attr = 0;
    for (char *p = &argv[1][1]; *p != '\0'; p++) {
        switch (*p) {
        case 'a': attr |= FS_APPEND_FL;         break;
        case 'A': attr |= FS_NOATIME_FL;        break;
        case 'c': attr |= FS_COMPR_FL;          break;
        case 'd': attr |= FS_NODUMP_FL;         break;
        case 'D': attr |= FS_DIRSYNC_FL;        break;
        case 'i': attr |= FS_IMMUTABLE_FL;      break;
        case 'j': attr |= FS_JOURNAL_DATA_FL;   break;
        case 's': attr |= FS_SECRM_FL;          break;
        case 'S': attr |= FS_SYNC_FL;           break;
        case 't': attr |= FS_NOTAIL_FL;         break;
        case 'T': attr |= FS_TOPDIR_FL;         break;
        case 'u': attr |= FS_UNRM_FL;           break;
        default:  usageError(argv[0]);
        }
    }

    /* Open each filename in turn, and change its attributes */

    for (int j = 2; j < argc; j++) {
        int fd = open(argv[j], O_RDONLY);
        if (fd == -1) {         /* Most likely error is nonexistent file */
            errMsg("open: %s", argv[j]);
            continue;
        }

        /* If argv[1] starts with + or -, then retrieve existing
           attribute bit mask and modify as required */

        if (argv[1][0] == '+' || argv[1][0] == '-') {
            int oldAttr;
            if (ioctl(fd, FS_IOC_GETFLAGS, &oldAttr) == -1)
                errExit("ioctl1: %s", argv[j]);
            attr = (*argv[1] == '-') ? (oldAttr & ~attr) : (oldAttr | attr);
        }

        if (ioctl(fd, FS_IOC_SETFLAGS, &attr) == -1)
            errExit("ioctl2: %s", argv[j]);
        if (close(fd) == -1)
            errExit("close");
    }

    exit(EXIT_SUCCESS);
}
```

命令行式查看/修改 i-node 标志（`chiflag -a file` 等），是原书这一节的配套实验工具。**依赖 `<linux/fs.h>`，macOS 不可编译**——本目录保留逐字镜像，Pi 上验证：

```bash
# Pi5 (Debian/aarch64/ext4) 上的预期验证路径（未在本机执行，如实标注）：
gcc -Wall -o chiflag chiflag.c
sudo ./chiflag +a /var/log/trade.log     # 置 append-only
echo hack >> /var/log/trade.log          # OK：追加
echo x > /var/log/trade.log              # fail: Operation not permitted
sudo ./chiflag -a /var/log/trade.log     # 清标志才能截断
```

习题 15-7（简化版 `chattr(1)`）即以本工具为骨架；因为依赖 Linux ioctl，本目录不提供 macOS 可运行的实现，在 15.7 习题篇里给出方案与边界。

## 与相邻概念的区别

| 机制 | 层次 | 粒度 | 谁解释 |
|------|------|------|--------|
| 权限位（15.4） | VFS | 用户/组/其他 × rwx | VFS 判定算法 |
| **i-node flags（本节）** | FS 层 | 单文件行为开关 | 具体文件系统 |
| xattr（Ch16） | FS 层 | 任意 name=value | 应用自解释 |
| mount 选项 | 挂载点 | 全 FS（noatime 等） | VFS |

一句话：**flags 是"FS 给这个 inode 立的规矩"，比权限位更底层，比 mount 选项更细**。

## 常见坑

| 坑 | 正解 |
|----|------|
| 拿 flags 当可移植 API | Linux 专有（BSD 有 chflags 但常量/接口不同）；可移植代码降级为"试一下"并容忍 ENOTTY |
| `FS_IOC_SETFLAGS` 用写方式 open | 不需要也行——官方语义只读打开即可 ioctl |
| append-only 文件用 logrotate 原地截断 | EPERM；必须 copytruncate 之外的名改重建流（或先清标志） |
| immutable 只防内容 | 它同时冻结元数据/改名/删除/链接——比 chmod 000 更彻底 |
| 在 tmpfs 上设 flags | 多数 tmpfs 不实现，`ENOTTY`；验证 FS 支持再依赖 |

## HFT / 嵌入式关联

| 场景 | 本节机制怎么兑现 |
|------|----------------|
| 交易日志防篡改 | `+a`（append-only）是合规基线：即使 root 被拿下，历史日志不可改写 |
| 只读采集 | 高频行情落盘文件 `+a`，防手滑截断；配 logrotate 需重建式轮转 |
| 嵌入式寿命 | `FS_NOATIME_FL` 单文件关掉 atime，与挂载 noatime 组合减少 flash 写放大 |
| 固件防改 | 升级完成后对关键二进制置 immutable，重启自检时校验 |
| 应急取证 | 现场发现删不掉/改不动的文件，第一反应查 flags 而不是怀疑 FS 损坏 |

<details>
<summary>代码自测（Q&A）</summary>

**Q1：i-node flags 和权限位谁先起作用？**
A：分层不同：flags 在 FS 行为层。append-only 文件即使 0666，写也只允许追加；immutable 文件 chmod/chown/unlink 全部 EPERM——flags 优先于权限判定结果。

**Q2：为什么本节没有本机实测输出？**
A：接口 `<linux/fs.h>` 的 `FS_IOC_*` 是 Linux 专有，macOS 无此 ioctl。本目录逐字保留了 dist 的 chiflag.c 镜像，验证平台是 Pi5 的 ext4——不伪造实测，符合本仓库"诚实标注"的规矩。

**Q3：清 immutable 为什么需要额外特权？**
A：`FS_IMMUTABLE_FL`/`FS_APPEND_FL` 的设置与清除额外要求 `CAP_LINUX_IMMUTABLE`——把它从"普通 root 手滑"里隔离出来。

**Q4：append-only 与 O_APPEND 的区别？**
A：O_APPEND 是每次 write 的原子追加标志，进程可开可关；FS_APPEND_FL 是 FS 层强制——即使程序不带 O_APPEND 打开，写也只落文件尾。

**Q5：flags 会被备份/复制保留吗？**
A：取决于工具：cp 默认不保留；tar 需 `--acls/--xattrs` 类扩展；rsync 有 `--flags`。灾备演练要专门验证 flags 恢复，否则 append-only 防线可能在恢复后消失。

**Q6：怎么探测某 FS 支持哪些 flags？**
A：试探法：对测试文件 `FS_IOC_SETFLAGS` 逐个置位看返回（ENOTTY=不支持，EPERM=缺特权）。不同 FS（ext4/xfs/btrfs/tmpfs）支持集差异很大。

</details>
