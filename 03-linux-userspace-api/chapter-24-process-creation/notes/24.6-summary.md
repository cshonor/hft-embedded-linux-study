## 小结原文（书 p.529）

原书这一节只有两段，但把全章讲完了：

> *"The `fork()` system call creates a new process (the child) by making an almost exact
> duplicate of the calling process (the parent). The `vfork()` system call is a more efficient
> version of `fork()`, but is usually best avoided because of its unusual semantics, whereby
> the child uses the parent's memory until it either performs an `exec()` or terminates; in
> the meantime, execution of the parent process is suspended."*
>
> *"After a `fork()` call, we can't rely on the order in which the parent and the child are
> next scheduled to use the CPU(s). Programs that make assumptions about the order of
> execution are susceptible to errors known as race conditions. Because the occurrence of
> such errors depends on external factors such as system load, they can be difficult to find
> and debug."*

拆成三句人话：

| 原书句子 | 要点 |
|----------|------|
| "an **almost exact** duplicate" | 不是完全一样 —— 差异在 **PID / pending 信号 / fd 表是否复制**（vfork）/ 子进程只保留一条线程（Ch33） |
| "vfork() … **best avoided**" | vfork 的语义危险（SUSv3 三条 UB），COW 之后它的性能优势不再重要 |
| "we **can't rely** on the order … **race conditions**" | fork 之后谁先跑不确定；依赖顺序 = 竞态，且错误难复现 |

### Further information（书 p.530）

> *"[Bach, 1986] and [Goodheart & Cox, 1994] provide details of the implementation of
> `fork()`, `execve()`, `wait()`, and `exit()` on UNIX systems. [Bovet & Cesati, 2005] and
> [Love, 2010] provide Linux-specific implementation details of process creation and
> termination."*

| 原书参考 | 是什么 |
|----------|--------|
| [Bach, 1986] | *The Design of the UNIX Operating System* —— 传统 UNIX 里 fork/exec/wait/exit 的实现 |

## 本章值得记住的 8 条

1. **`fork()` 复制的是「进程」，不是「程序」**。子进程从 `fork()` 返回处继续执行，`fork()`
   在父进程里返回子进程 PID、在子进程里返回 0 —— 这是全网唯一的分叉判据。
2. **`fork()` 之后内存是「复制」的，fd 是「共享」的**。内存走 COW（写才复制），fd 走
   `get_file()` 加引用计数（同一个 open file description，**偏移量也共享**）。
3. **信号掩码继承、pending 清零、handler 继承**。这三条在写同步代码时决定成败。
4. **`vfork()` 不复制地址空间，父进程被挂起**，直到子进程 `exec()` 或 `_exit()`。
   SUSv3 明令：在 vfork 子进程里改数据 / `return` / 调别的函数都是**未定义行为**。
5. **`fork()` 之后谁先跑不确定**，而且不是均匀随机 —— 实测 `j ∈ [800, 860]` 有 92% 是
   child 先，紧邻的 `j ∈ [861, 999]` 是 0%。**依赖顺序 = 竞态 = 偶发故障。**
6. **原书点的 `sched_child_runs_first` 开关今天已经没了**：v6.6 里已成空壳（零消费点），
   **v6.7 起连定义都删除**，实测沙箱里 `/proc/sys/kernel/sched_child_runs_first` 是 `ENOENT`。
   ⇒ **`/proc` 路径是最容易腐烂的一类知识，见到先 `ls`。**
7. **同步信号必须在 `fork()` 之前屏蔽**。反过来写，子进程跑得快时会把信号消费在
   handler 里，父进程 `sigsuspend()` **永久挂起**。而且这个 bug 只在低负载机器上不出现。
8. **`WCOREDUMP` 不是布尔值**。glibc 里它是 `status & 0x80`（只能取 0 或 128）。
   实测 `WCOREDUMP = 128` 只说明「内核走完了 coredump 流程」，**不等于磁盘上有 core 文件**
   —— 实测 `./core` 和 `/core` 都不存在。

<details>
<summary>本章复习自测（Q&A）</summary>

**Q1：`fork()` 之后父子进程共享的三样东西是什么？**

A：① **文件描述符表**（更准确说是**同一批 open file description**，`get_file()` 加引用计数
⇒ 共享文件偏移和状态标志）；② 父进程已有的**信号处置（handler）**；③ **信号掩码**。
不共享的是：PID、pending 信号集、以及（写时复制的）内存。

**Q2：`t_fork` 里子进程打印 `idata=333 istack=666`，父进程打印 `111` / `222`，说明什么？**

A：说明 `fork()` 之后父子各有**自己的一份** `glob` / `loc` / 动态分配的 `dyn` / 栈上的
`istack`。子进程改自己的不影响父进程 —— 这是 COW 的正常表现。
**与 §24.3 的 `t_vfork`（`istack=666` 出现在父进程）正好对照。**

**Q3：为什么说「`vfork()` 用错会把父进程搞崩」？**

A：因为子进程跑在**父进程的地址空间和栈**上。① 从函数里 `return` 会把父进程的栈拆掉
（典型 SIGSEGV）；② 调库函数会破坏共享的 libc 状态；③ `exit()` 会刷 stdio（父子同一份缓冲区）。
SUSv3 明确把这三条列为未定义行为。

**Q4：`fork()` 之后父/子谁先跑，能不能靠内核参数控制？**

A：**今天不能。** 原书 p.526 说的 `/proc/sys/kernel/sched_child_runs_first` 实测已经
`ENOENT`；源码对照显示 v6.6 里它已是空壳、**v6.7 起 upstream 删除了定义**。
现在由 `wake_up_new_task()` → `check_preempt_curr(..., WF_FORK)` 按 EEVDF 的虚拟
deadline 决定。

**Q5：为什么同步信号非要在 `fork()` 之前屏蔽？**

A：因为要在**信号可能到达之前**就把门关上。若 `fork` 之后才屏蔽，子进程可能在这个窗口里
把信号发过来 —— 信号立刻被空的 handler 消费掉，父进程随后 `sigsuspend()` 就**永远等不到**。
而且因为掩码是继承的，在 fork 前屏蔽还顺便让子进程也处于一致的屏蔽状态。

**Q6：`WCOREDUMP(status)` 返回 128 是正常的吗？**

A：正常。glibc 里它是位掩码 `status & 0x80`（`bits/waitstatus.h`），所以只能取 **0 或 128**。
`status = 134 = 0x80 | 6` 表示「子进程被 6 号信号（SIGABRT）杀死，且内核走完了 coredump
流程」。**但它不代表磁盘上有 core 文件** —— 实测沙箱里 `./core` 和 `/core` 都不存在。

**Q7：本章 7 个官方文件里，哪一个属于别的章？**

A：`procexec/fork_stdio_buf.c`。它在官方源里，但归 **Ch25 的 Listing 25-2**
（讲 `fork` 之后 stdio 缓冲区的复制问题），不属于 Ch24。本章的 7 个文件是
`t_fork` / `fork_file_sharing` / `footprint` / `t_vfork` / `fork_whos_on_first` /
`fork_sig_sync` / `vfork_fd_test`（最后一个是习题 24-2 的解）。

</details>
