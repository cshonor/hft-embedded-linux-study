## 本节讲什么

`fork()` 做的不是「新建一个空进程」，而是**克隆调用者**。本节要把「克隆出来的是什么」
讲清楚，分三层：

| 层 | 原书节 | 一句话 | 本节程序 |
|----|--------|--------|---------|
| 内存 | §24.2 | 子进程拿到 stack/data/heap 的**副本**，改自己的不影响对方 | Listing 24-1 `t_fork.c` |
| 文件 | §24.2.1 | fd 表被**复制**，但 `struct file` 被**共享** ⇒ 文件偏移共享 | Listing 24-2 `fork_file_sharing.c` |
| 内存（进一步） | §24.2.2 | 副本靠 **COW** 实现；可以**主动**用它来"用完就还" | Listing 24-3 `footprint.c` |

外加一节**延伸 demo**（原书 Ch24 没有）：fork 到底继承什么、不继承什么 ——
用「信号掩码继承 / pending 不继承」这对可确定性观察的事实把它钉住。

⚠️ 原书 §24.2 的接口声明只有一行（书 p.516）：

```c
#include <unistd.h>

pid_t fork(void);
```

⭐ 但它下面的**返回值说明**才是重点，原文（书 p.516）：
*"In parent: returns process ID of child on success, or –1 on error; in successfully
created child: always returns 0"* —— 即**父得子 PID、子恒得 0、失败只有 -1**。

## 1. 内存语义：`idata` / `istack` 各改各的

原书 Listing 24-1（`t_fork.c`，书 p.517）是本章第一个程序：它把一个**静态变量**
（数据段）和一个**自动变量**（栈）各乘 3，然后父子都打印。

### 完整源码（Listing 24-1，原书书页 517）

[`code/t_fork.c`](../code/t_fork.c)

```c
/*************************************************************************\
*                  Copyright (C) Michael Kerrisk, 2026.                   *
*                                                                         *
* This program is free software. You may use, modify, and redistribute it *
* under the terms of the GNU General Public License as published by the   *
* Free Software Foundation, either version 3 or (at your option) any      *
* later version. This program is distributed without any warranty.  See   *
* the file COPYING.gpl-v3 for details.                                    *
\*************************************************************************/

/* t_fork.c

   Demonstrate the use of fork(), showing that parent and child
   get separate copies of stack and data segments.
*/
#include "tlpi_hdr.h"

static int idata = 111;             /* Allocated in data segment */

int
main(int argc, char *argv[])
{
    int istack = 222;               /* Allocated in stack segment */
    pid_t childPid;

    switch (childPid = fork()) {
    case -1:
        errExit("fork");

    case 0:
        idata *= 3;
        istack *= 3;
        break;

    default:
        sleep(3);                   /* Give child a chance to execute */
        break;
    }

    /* Both parent and child come here */

    printf("PID=%ld %s idata=%d istack=%d\n", (long) getpid(),
            (childPid == 0) ? "(child) " : "(parent)", idata, istack);

    exit(EXIT_SUCCESS);
}
```

### 编译命令

```bash
gcc -O0 -Wall -Wextra -o t_fork t_fork.c get_num.c
```

### CE 实测（`t_fork`）

```text
PID=3 (child)  idata=333 istack=666
PID=2 (parent) idata=111 istack=222
```

`execTime = 3020`（父进程里那个 `sleep(3)`），`exit code = 0`。

### 逐条解读

* **子进程看到的是 333 / 666，父进程看到的是 111 / 222** —— 同一个变量名，两份值。
  注意子进程的数字是**在副本上乘 3** 得到的（111×3、222×3），而不是"父子共享一个变量、
  谁先改谁赢"。
* ⚠️ 输出里 `(child)` 后面是**两个空格** —— 这是原书格式串自带的
  （`"PID=%ld %s idata=..."` 里的 `%s` 是 `"(child) "`，本身带一个尾空格），
  不是抄错。
* **`execTime = 3020` 毫秒**正对应父进程的 `sleep(3)`。也就是说这个程序**实际上
  白等了 3 秒** —— 原书拿它来"让子进程先跑完"，而原书紧接着就承认这**不可靠**：

  > 原书 p.517：*"Using sleep() in this manner is not a foolproof method of
  > guaranteeing this result; we look at a better method in Section 24.5."*

  这次之所以能成功，只是因为 3 秒足够长。§24.5 会给正确做法（信号同步）。

## 2. §24.2.1 文件语义：fd 表复制，但 `struct file` 共享

这是**最容易想错**的一处。fork 之后：

* **fd 表**（`fd` → `struct file *` 的映射）是**复制**的 —— 你 `close(3)` 不影响对方；
* 但 `struct file`（打开文件描述，里面装着**文件偏移**和 **open file status flags**）
  是**同一个对象** —— 所以父子 `write` 同一个 fd 会**接着对方的偏移往下写**。

原书 Listing 24-2（`fork_file_sharing.c`，书 p.519）用两条可观察量把这个语义扒出来：
**文件偏移** 和 **O_APPEND 标志**。

### 完整源码（Listing 24-2，原书书页 519）

[`code/fork_file_sharing.c`](../code/fork_file_sharing.c)

```c
/*************************************************************************\
*                  Copyright (C) Michael Kerrisk, 2026.                   *
*                                                                         *
* This program is free software. You may use, modify, and redistribute it *
* under the terms of the GNU General Public License as published by the   *
* Free Software Foundation, either version 3 or (at your option) any      *
* later version. This program is distributed without any warranty.  See   *
* the file COPYING.gpl-v3 for details.                                    *
\*************************************************************************/

/* fork_file_sharing.c

   Show that the file descriptors of a forked child refer to the
   same open file objects as the parent.
*/
#include <sys/stat.h>
#include <fcntl.h>
#include <sys/wait.h>
#include "tlpi_hdr.h"

int
main(int argc, char *argv[])
{
    int fd, flags;
    char template[] = "/tmp/testXXXXXX";

    setbuf(stdout, NULL);                   /* Disable buffering of stdout */

    /* Open a temporary file, set its file offset to some arbitrary value,
       and change the setting of one of the open file status flags. */

    fd = mkstemp(template);
    if (fd == -1)
        errExit("mkstemp");

    printf("File offset before fork(): %lld\n",
            (long long) lseek(fd, 0, SEEK_CUR));

    flags = fcntl(fd, F_GETFL);
    if (flags == -1)
        errExit("fcntl - F_GETFL");
    printf("O_APPEND flag before fork() is: %s\n",
            (flags & O_APPEND) ? "on" : "off");

    switch (fork()) {
    case -1:
        errExit("fork");

    case 0:     /* Child: change file offset and status flags */
        if (lseek(fd, 1000, SEEK_SET) == -1)
            errExit("lseek");

        flags = fcntl(fd, F_GETFL);         /* Fetch current flags */
        if (flags == -1)
            errExit("fcntl - F_GETFL");
        flags |= O_APPEND;                  /* Turn O_APPEND on */
        if (fcntl(fd, F_SETFL, flags) == -1)
            errExit("fcntl - F_SETFL");
        _exit(EXIT_SUCCESS);

    default:    /* Parent: can see file changes made by child */
        if (wait(NULL) == -1)
            errExit("wait");                /* Wait for child exit */
        printf("Child has exited\n");

        printf("File offset in parent: %lld\n",
                (long long) lseek(fd, 0, SEEK_CUR));

        flags = fcntl(fd, F_GETFL);
        if (flags == -1)
            errExit("fcntl - F_GETFL");
        printf("O_APPEND flag in parent is: %s\n",
                (flags & O_APPEND) ? "on" : "off");
        exit(EXIT_SUCCESS);
    }
}
```

### 编译命令

```bash
gcc -O0 -Wall -Wextra -o fork_file_sharing fork_file_sharing.c get_num.c
```

### CE 实测（`fork_file_sharing`）

```text
File offset before fork(): 0
O_APPEND flag before fork() is: off
Child has exited
File offset in parent: 1000
O_APPEND flag in parent is: on
```

`execTime = 28` 毫秒，`exit code = 0`。

### 逐条解读

* **偏移 0 → 1000**：子进程 `lseek(fd, 1000, SEEK_SET)` 之后**退出**，父进程再
  `lseek(fd, 0, SEEK_CUR)` 读到的却是 **1000**。如果 fd 表连同 `struct file` 一起被
  复制，父进程应该读到 0。
* **`O_APPEND` off → on**：文件**状态标志**也共享。子进程用 `fcntl(F_SETFL)` 打开
  `O_APPEND` 后，父进程用 `F_GETFL` 看到的也是 on。
* ⚠️ 两个「不共享」的对照（别搞混）：
  * **fd 表**不共享 —— 子进程 `close(fd)` 之后父进程那个 fd 还在（习题 24-2 就是用
    `vfork` 演示同一件事，见 §24.7）；
  * **fd 标志**（`FD_CLOEXEC`，用 `fcntl(F_SETFD)` 设）也不共享 —— 它是**每 fd** 的属性，
    不是打开文件的属性。
  共享的是**打开文件描述**：偏移 + 状态标志（`O_APPEND`/`O_NONBLOCK`…）+ 一些锁信息。
* 程序里那句 `setbuf(stdout, NULL)` 不是装饰：父子都往同一个 stdout 写，全缓冲会导致
  两边的缓冲互相覆盖/顺序错乱（§24.4 的 stdio 坑就是这个的极端版）。

## 3. §24.2.2 内存语义再进一步：COW 可以**主动利用**

原书 §24.2.2（书 p.522）说清了一件事：fork 时的"复制"是 **COW（copy-on-write）**——
一开始父子**指向同一批物理页**，只有谁**写**了才真正复制那一页。所以：

* fork 本身很便宜（不拷内存）；
* 但一旦父子都大量写，内存就会翻倍 —— 这时 COW 反而**没有**帮你省。

Listing 24-3（`footprint.c`，书 p.522）把 COW 反着用：**想让"用完就还"的内存不留在
自己身上，就把它放到子进程里去花**。子进程一退出，它占的那些物理页**全部还回系统**，
父进程的"内存足迹"一点没变。

### 完整源码（Listing 24-3，原书书页 522）

[`code/footprint.c`](../code/footprint.c)

```c
/*************************************************************************\
*                  Copyright (C) Michael Kerrisk, 2026.                   *
*                                                                         *
* This program is free software. You may use, modify, and redistribute it *
* under the terms of the GNU General Public License as published by the   *
* Free Software Foundation, either version 3 or (at your option) any      *
* later version. This program is distributed without any warranty.  See   *
* the file COPYING.gpl-v3 for details.                                    *
\*************************************************************************/

/* footprint.c

   Using fork() + wait() to control the memory footprint of an application.

   This program contains a function that (artificially) consumes a large
   amount of memory. To avoid changing the process's memory footprint, the
   program creates a child process that calls the function. When the child
   terminates, all of its memory is freed, and the memory consumption of
   the parent is left unaffected.
*/
#define _BSD_SOURCE     /* To get sbrk() declaration from <unistd.h> in case
                           _XOPEN_SOURCE >= 600; defining _SVID_SOURCE or
                           _GNU_SOURCE also suffices */
#include <sys/wait.h>
#include "tlpi_hdr.h"

static int
func(int arg)
{
    int j;

    for (j = 0; j < 0x100; j++)
        if (malloc(0x8000) == NULL)
            errExit("malloc");
    printf("Program break in child:  %10p\n", sbrk(0));

    return arg;
}

int
main(int argc, char *argv[])
{
    int arg = (argc > 1) ? getInt(argv[1], 0, "arg") : 0;
    pid_t childPid;
    int status;

    setbuf(stdout, NULL);           /* Disable buffering of stdout */

    printf("Program break in parent: %10p\n", sbrk(0));

    childPid = fork();
    if (childPid == -1)
        errExit("fork");

    if (childPid == 0)              /* Child calls func() and */
        exit(func(arg));            /* uses return value as exit status */

    /* Parent waits for child to terminate. It can determine the
       result of func() by inspecting 'status' */

    if (wait(&status) == -1)
        errExit("wait");

    printf("Program break in parent: %10p\n", sbrk(0));

    printf("Status = %d %d\n", status, WEXITSTATUS(status));

    exit(EXIT_SUCCESS);
}
```

### 编译命令

```bash
gcc -O0 -Wall -Wextra -o footprint footprint.c get_num.c
./footprint        # 默认 arg = 0
./footprint 7      # 带一个参数
```

### CE 实测（`footprint`，无参数）

```text
Program break in parent: 0x222d3000
Program break in child:  0x22ae5000
Program break in parent: 0x222d3000
Status = 0 0
```

### CE 实测（`footprint_7`，参数 `7`）

```text
Program break in parent: 0x1b5dc000
Program break in child:  0x1bdee000
Program break in parent: 0x1b5dc000
Status = 1792 7
```

### 逐条解读

* **`Program break in child` 比父进程大 8 MB 左右**：`func()` 里
  `0x100`（=256）次 `malloc(0x8000)`（=32 KB）≈ **8 MB**，`sbrk(0)` 就是堆顶。
  两行地址做减法能看到这个量级（具体差值随分配器/对齐而变，不是精确 8 MB）。
* ⚠️ **地址每次运行都不一样，而且 CE 可能换宿主机** —— 本节的四个地址是**同一次冻结
  日志里的原样**，只用来做**相对比较**（父 vs 子、前 vs 后），不能当"某个固定值"引用。
* **父进程前后两次 `sbrk(0)` 完全相同** —— 这就是 COW 的可见证据：子进程那 8 MB 与
  父进程的堆顶无关，子进程退出后**彻底还给系统**，父进程自己的堆顶一米没动。
* **`Status = 0 0` vs `Status = 1792 7`**：第二个数是 `WEXITSTATUS(status)`，即
  `func(arg)` 的返回值。传 `7` 就带回 `7`（第一次 `status` 是 1792 = `7 << 8`，
  原理见 §24.1 的 ④）。默认无参数时 `arg=0`，所以两个都是 0。
* ⭐ 这个模式（fork 出去干重活、干完 `exit` 把内存还掉、用 8 位退出码把结果带回来）
  是 HFT/后端里非常真实的手法，见「HFT / 嵌入式关联」。

## 4. 延伸 demo：fork 到底继承什么、不继承什么

⚠️ **原书没有这一节、也没有这个程序。**
TLPI §24.2 只讲了「内存副本」和「打开文件共享」两件事，**并没有**给出 fork 的完整
「继承 / 不继承」清单（我逐页核过 §24 正文：全章没有这类表格，也没有出现
pending 相关的论述 —— 记录锁在 §29、线程的 pending 集在 Ch33）。

但这条是**高频考点**，所以这里补一个可确定性观察的探针，把最容易搞混的一对钉死：

| 项 | fork 之后 | 为什么 |
|----|----------|--------|
| **信号掩码**（`sigprocmask` 设的） | **继承** | `copy_sighand()`/`copy_signal()` 把掩码带过去 |
| **pending 信号集**（已产生、未递送） | **不继承（清零）** | `copy_process()` 里显式 `init_sigpending(&p->pending)` |
| 信号**处置**（handler） | 继承 | 同一份 `sighand_struct` 内容被复制 |

依据：POSIX `fork()` 的 *"the set of signals pending for the child process shall be
initialized to the empty set"*；Linux v6.6 的实现见「源码坐标」一节（有行号）。

### 完整源码（本仓库自写）

[`code/c24_sigmask_inherit.c`](../code/c24_sigmask_inherit.c)

```c
/* c24_sigmask_inherit.c

   ⚠️ 延伸 demo —— **原书没有这个程序**。
      TLPI Ch24 正文只讲了「父子各拿到 stack/data/heap 的副本」（§24.2，
   Listing 24-1）与「共享同一个 open file description」（§24.2.1，Listing 24-2），
   **并没有**给出 fork() 的完整「继承 / 不继承」清单，也没有演示下面这两条。

   本程序用一对可确定性观察的探针把它们钉死：

     ① 信号掩码（signal mask）**继承**
        父进程里 SIGUSR1 处于屏蔽态 ⇒ 子进程里查询掩码，SIGUSR1 仍是屏蔽的。

     ② pending 信号**不继承**
        父进程先屏蔽 SIGUSR1，再 raise(SIGUSR1) ⇒ 这个信号变成「已产生但未递送」
        （pending）。此时 fork()：父进程的 sigpending() 里有 SIGUSR1，
        子进程的 sigpending() 是**空集**。

   依据：
     * POSIX fork(): "the set of signals pending for the child process shall be
       initialized to the empty set"
     * man 2 fork 的 NOTES 一节（Linux man-pages）列出 fork 后**不**继承的项；
       信号掩码在 "inherits" 那一侧，pending 集在 "does not inherit" 那一侧。

   ⚠️ 为什么原书 Ch24 没讲：TLPI 把 fork 的进程属性继承放在别处 —— 记录锁在
      §29（`man 7 fcntl` 亦如此）、线程的 pending 集在 Ch33。Ch24 只谈
      「内存副本 + 打开文件共享 + 调度顺序」这三件事。本节把这条常见考点补齐。

   编译（无需 tlpi_hdr.h，自包含）：
     gcc -O0 -Wall -Wextra -o c24_sigmask_inherit c24_sigmask_inherit.c
*/

#include <errno.h>
#include <signal.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <sys/wait.h>
#include <unistd.h>

static void die(const char *msg)
{
    fprintf(stderr, "ERROR: %s: %s\n", msg, strerror(errno));
    exit(EXIT_FAILURE);
}

int main(void)
{
    sigset_t blockSet, curSet, pendingSet;
    pid_t childPid;

    /* 关掉 stdout 缓冲：父子两段输出不会互相污染（CE 的 stdout 是 socket，
       glibc 会按 8KB 全缓冲 —— 不关的话父子各持一份副本缓冲，容易看不出真相）*/
    setvbuf(stdout, NULL, _IONBF, 0);

    /* ---------- 父进程：屏蔽 SIGUSR1，并让它变成 pending ---------- */
    sigemptyset(&blockSet);
    sigaddset(&blockSet, SIGUSR1);
    if (sigprocmask(SIG_BLOCK, &blockSet, NULL) == -1)
        die("sigprocmask(SIG_BLOCK)");

    if (raise(SIGUSR1) != 0)          /* 自己给自己发；因为被屏蔽 ⇒ 停在 pending */
        die("raise(SIGUSR1)");

    if (sigprocmask(SIG_BLOCK, NULL, &curSet) == -1)   /* 查询当前掩码 */
        die("sigprocmask(查询掩码)");
    if (sigpending(&pendingSet) == -1)
        die("sigpending");

    printf("父进程 pid=%ld ppid=%ld\n", (long) getpid(), (long) getppid());
    printf("  掩码 中 SIGUSR1 = %d   （1 = 屏蔽）\n", sigismember(&curSet, SIGUSR1));
    printf("  pending 中 SIGUSR1 = %d   （1 = 有未递送信号）\n",
            sigismember(&pendingSet, SIGUSR1));

    /* ---------- fork：掩码与 pending 的继承差异就在这一刻分开 ---------- */
    switch (childPid = fork()) {
    case -1:
        die("fork");

    case 0:   /* 子进程：什么都不改，只把继承到的东西读出来 */
        if (sigprocmask(SIG_BLOCK, NULL, &curSet) == -1)
            die("child sigprocmask(查询掩码)");
        if (sigpending(&pendingSet) == -1)
            die("child sigpending");

        printf("子进程 pid=%ld ppid=%ld\n", (long) getpid(), (long) getppid());
        printf("  掩码 中 SIGUSR1 = %d   （继承来的）\n", sigismember(&curSet, SIGUSR1));
        printf("  pending 中 SIGUSR1 = %d   （不继承）\n",
                sigismember(&pendingSet, SIGUSR1));
        _exit(EXIT_SUCCESS);

    default:
        if (waitpid(childPid, NULL, 0) == -1)
            die("waitpid");

        /* 父进程自己再看一眼：raise(SIGUSR1) 那个信号仍然挂在自己身上 */
        if (sigpending(&pendingSet) == -1)
            die("sigpending");
        printf("父进程 fork 之后：pending 中 SIGUSR1 = %d（自己的还留着）\n",
                sigismember(&pendingSet, SIGUSR1));
        _exit(EXIT_SUCCESS);
    }
}
```

```text

  掩码 中 SIGUSR1 = 1   （1 = 屏蔽）
  pending 中 SIGUSR1 = 1   （1 = 有未递送信号）
子进程 pid=3 ppid=2
  掩码 中 SIGUSR1 = 1   （继承来的）
  pending 中 SIGUSR1 = 0   （不继承）
父进程 fork 之后：pending 中 SIGUSR1 = 1（自己的还留着）
```

`execTime = 29` 毫秒，`exit code = 0`。

### 逐条解读

* **掩码 `1` → `1`**：子进程什么都没设，但 `SIGUSR1` 在它那里**也是屏蔽的** ⇒ 掩码继承。
* **pending `1` → `0`**：父进程 `raise(SIGUSR1)` 之后确实有一个未递送的信号；
  子进程的 `sigpending()` **空** ⇒ pending 集**不继承**。
* **父进程 fork 之后仍是 `1`**：证明父进程那个 pending 信号**没有因为 fork 被清掉或
  被抢走** —— 清零只发生在**新进程**身上。
* ⭐ 这条差异为什么重要：`fork_sig_sync.c`（Listing 24-6）**正是靠「掩码继承」才能
  在 fork **之前**屏蔽同步信号**（§24.5）。如果掩码不继承，那个程序立刻就有竞态。

| # | 坑 | 说明 |
|---|----|------|
| 1 | 以为 fork 会立刻拷贝内存 | 是 COW，写才复制；所以 fork 便宜，但"父子都猛写"会翻倍 |
| 2 | 以为父子**各自**有文件偏移 | 偏移在 `struct file` 里，**共享**；只有 fd 表和 fd 标志是各自的 |
| 3 | 把 `FD_CLOEXEC` 和 `O_APPEND` 混为一谈 | `FD_CLOEXEC` 是**每 fd**（`F_SETFD`），`O_APPEND` 是**每打开文件**（`F_SETFL`），fork 后前者不共享、后者共享 |
| 4 | **fork 之前不 `fflush(stdout)`** | 全缓冲下父进程缓冲里的内容会被子进程**继承一份**，于是同一行打印两遍。原书把这个坑放在 **Ch25 的 Listing 25-2**（`fork_stdio_buf.c`）；本仓库 `code/` 里也留了一份同主题的旧 demo |
| 5 | 子进程用 `exit()` 而不是 `_exit()` | `exit()` 会**刷 stdio 缓冲** ⇒ 上面第 4 条的"重复输出"就是这么来的。子进程正确姿势是 `_exit()`（或 `exit()` 前先 `fflush`） |
| 6 | 以为 fork 之后父子"共享全局变量" | 见 Listing 24-1：`idata` 是两份 |
| 7 | 以为 `sbrk` 地址会在两次运行时一样 | 地址随 ASLR/分配器变；本节只做**相对**比较 |
| 8 | 以为"pending 信号会被父子共享" | 恰恰相反：**清零**。见本节延伸 demo 与 `kernel/fork.c:2391` |

## HFT / 嵌入式关联

* **Listing 24-3 的 `footprint` 模式是真实手法**：想跑一次"吃 8 MB 的解析"又不让
  常驻进程的 RSS 涨上去，就 `fork` 出去做、用**退出码（8 位）**把结果带回来。
  HFT 里的场景：盘前一次性把历史数据反序列化成索引、或者跑一遍"预热/自检"。
  代价是结果只有 0–255，超了得走 pipe / 共享内存。
* **fd 共享偏移是 HFT 日志的暗坑**：行情录制进程 `fork` 出子进程后，父子都往同一个
  `O_APPEND` 日志 fd 写 —— 因为共享偏移，**不会互相覆盖**（这正是 `O_APPEND` 在
  `struct file` 里的意义）。但如果没有 `O_APPEND`，两条流会交错着互相破坏。
* **COW 与 HFT 的"快照语义"**：策略进程 `fork` 出风控进程后，风控看到的是**fork 那一刻
  的一致内存快照**（COW），不需要加锁。这是"用 fork 代替读写锁"的经典招式；代价是
  指针/句柄在父子间的语义必须自查（fd 是共享的，见上）。
* **嵌入式 / NOMMU**：`fork()` 需要 MMU 才能做 COW。uClinux 这类无 MMU 平台上
  **只有 `vfork()` 可用**（§24.3 会讲它为什么可行）；这也是很多 RTOS 移植里
  "为什么没有 fork" 的答案。
* **`RLIMIT_NOFILE = 100`（probe24 实测）**：嵌入式默认 fd 上限往往很小，
  fork 继承的 fd 表就这么大；写守护进程时 `close` 掉不需要的 fd 不只是卫生问题，
  是真会撞上限。

<summary>代码自测（Q&A）</summary>

**Q1：Listing 24-1 里子进程改了 `idata`，为什么父进程看不到？**

A：因为是 COW 出来的**副本**。`idata` 在数据段，父子的页表都指向同一批物理页，
子进程执行 `idata *= 3` 触发**写保护缺页**，内核这时才复制那一页并让子进程的页表
指过去。父进程的页表没动，所以仍读到 111。

**Q2：那为什么 Listing 24-2 里子进程改的偏移和 `O_APPEND`，父进程**看得到**？**

A：因为这俩**不在内存副本里**，而在内核的 `struct file` 里。`dup_fd()` 只复制
fd 表的**指针数组**并对每个 `struct file` 加引用计数（`fs/file.c:385` 的 `get_file(f)`），
父子指向**同一个** `struct file`。所以对它的修改双方都看得见。

**Q3：`Status = 1792 7` 里那个 1792 是什么？**

A：`7 << 8`。`wait(&status)` 的 `status` 是内核打包的终止信息，退出码占高 8 位。
第二个数才是 `WEXITSTATUS(status)` 的结果。这就是为什么**退出码只能是 0–255**。

**Q4：`footprint` 里父进程两次 `sbrk(0)` 一样，能不能推出"父进程内存完全没变"？**

A：**不能**。`sbrk(0)` 只是**堆顶**地址。子进程那 8 MB 与父进程堆顶无关，这一点是确定的；
但"父进程内存完全没变"需要看 RSS。原书用 `sbrk(0)` 是因为它足以说明「子进程分配的内存
没有算到父进程的堆上」——结论方向对，但证据强度要按"堆顶"这个口径来读。

**Q5：为什么本节反复强调 `setbuf(stdout, NULL)` / `_exit()`？**

A：因为 CE 的 stdout 是 **socket**（不是终端），glibc 会按 **8KB 全缓冲**。
于是「父子共享一份被复制过的缓冲区」这个经典坑**真的会发生**：不关缓冲、又用
`exit()`，同一行就会打印两遍。原书把这个坑正式放在 Ch25 的 Listing 25-2
（`fork_stdio_buf.c`）。

**Q6：延伸 demo 里为什么父进程的 pending 是 1，子进程是 0？**

A：`copy_process()` 里有一行 `init_sigpending(&p->pending);`
（`kernel/fork.c:2391`）—— 新进程的 pending 集**被显式清空**。这是 POSIX 的要求
（"shall be initialized to the empty set"），不是 Linux 的实现意外。
而信号**掩码**是 `copy_sighand()`/`copy_signal()` 复制过来的，所以继承。

**Q7：如果子进程在 fork 之后立刻 `close(0)`，父进程的 0 号 fd 会怎样？**

A：不受影响。fd **表**是复制的（`dup_fd` 造了新表），关闭只改自己那张表。
原书习题 24-2 就是考这个，而且是用 `vfork` 来演示（见 §24.7 的 `vfork_fd_test.c`）——
`vfork` 连**地址空间**都不复制，却仍然复制 fd 表，对照更强烈。

</details>
