**fork + exec**（shell / 起外部程序）：子进程关多余 fd、重定向，再 `exec*`；失败 `_exit(127)`。 **fork 后分叉业务**（多进程服务）：父子各跑逻辑；父须 `wait*` 防僵尸（Ch26）。 ---

## 与 C 语言学习的关系

`fork()` 是 C 语言系统编程的核心。C 语言没有内置的并发原语——`fork` 是 Unix 创建进程的唯一方式。理解 `fork` 的返回值（父返回子 PID，子返回 0）需要扎实的 C 语言指针和返回值概念。

## 常见陷阱

1. **fd 泄漏到 exec**

```c
int fd = open(...);
execvp(prog, argv);  /* fd 仍然打开 */
```

默认情况下 exec 后 fd 仍然打开。设 FD_CLOEXEC 或用 O_CLOEXEC 防止泄漏。

2. **exec 后代码继续执行**

```c
execvp(prog, argv);
printf("这里会执行吗?");  /* 会! exec 失败时 */
```

exec 成功时不返回，当前进程映像被替换。只有 exec 失败时才返回 -1。必须检查返回值。

3. **PATH 搜索差异**

```c
execlp("ls", "ls", NULL);   /* 搜索 PATH */
execl("/bin/ls", "ls", NULL);  /* 不搜索 PATH */
```

execlp/execvp 搜索 PATH，execl/execv 不搜索。用错可能找不到程序。

## 自测题

**题目 1（选择）：** `exec` 成功后会发生什么？
A. 创建新进程
B. 替换当前进程映像
C. 返回旧进程
D. 什么也不发生

<details>
<summary>参考答案</summary>

B。exec 用新程序替换当前进程映像。PID 不变，代码段/数据段/堆栈被替换。成功时不返回。

</details>

**题目 2（判断）：** `exec` 失败时返回 -1，原程序继续执行。

<details>
<summary>参考答案</summary>

正确。exec 失败时返回 -1，当前进程映像不变，代码继续执行。成功时不返回。

</details>

**题目 3（踩坑）：** 以下代码有什么问题？
```c
execvp("ls", args);
perror("exec failed");
```

<details>
<summary>参考答案</summary>

没有检查 execvp 返回值。应该：
`if (execvp("ls", args) < 0) { perror("exec"); exit(1); }`
perror 本身没问题，但应该配合 exit 确保失败后退出。

</details>

**题目 4（应用）：** 写代码：fork + exec 执行 `ls -l`，父进程等待子进程结束。

<details>
<summary>参考答案</summary>

```c
pid_t pid = fork();
if (pid == 0) {
    execlp("ls", "ls", "-l", NULL);
    perror("exec"); exit(1);
}
wait(NULL);
```

</details>
