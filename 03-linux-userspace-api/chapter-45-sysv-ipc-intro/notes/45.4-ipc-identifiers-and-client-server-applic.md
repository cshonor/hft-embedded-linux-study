# 45.4 IPC Identifiers and Client-Server Applications

> 本章：[TLPI 第 45 章 — System V IPC Introduction](./README.md)

## 本节讲什么

介绍 SysV IPC 的标识符系统：IPC key → IPC ID 的映射，以及如何利用 key 在无亲缘关系的客户端和服务器间定位同一个 IPC 对象。

## 要点

### IPC key 和 ID

| 概念 | 说明 |
|------|------|
| **IPC key** (`key_t`) | 客户端/服务器约定的标识符 |
| **IPC ID** | 内核分配的内部标识符 |
| **ftok()** | 从路径+项目号生成 key |
| **xxxget()** | 用 key 创建/获取 IPC 对象，返回 ID |

### IPC 对象创建流程

```
服务器:
  key = ftok("/usr/lib/hft", 'A');  /* 生成 key */
  id = msgget(key, IPC_CREAT | 0666);  /* 创建，返回 ID */

客户端:
  key = ftok("/usr/lib/hft", 'A');  /* 相同路径 → 相同 key */
  id = msgget(key, 0);  /* 获取已有对象 */
```

### ftok 函数

```c
key_t ftok(const char *pathname, int proj_id);
```

| 参数 | 说明 |
|------|------|
| `pathname` | 必须存在且可访问的文件路径 |
| `proj_id` | 项目标识（仅低 8 位有效，非 0） |
| 返回值 | 组合 inode 号 + dev 号 + proj_id 生成 key |
| 失败 | -1（文件不存在或不可访问） |

**ftok 的陷阱**：
- 路径文件被替换（重建）→ inode 变 → key 变
- 不同文件系统可能有相同 inode 号 → key 碰撞
- 建议用固定路径（如 `/usr/lib/myapp`）

### IPC 约定的 key 值

| 特殊 key | 含义 |
|---------|------|
| `IPC_PRIVATE` (= 0) | 创建私有对象，仅 fork 的子进程可继承 |
| `ftok()` 返回值 | 约定的公共 key |

### 客户端-服务器模式

**模式 1：服务器创建，客户端获取**
```
Server: id = xxxget(key, IPC_CREAT | 0666);
Client: id = xxxget(key, 0);  /* 必须已存在 */
```

**模式 2：IPC_PRIVATE（仅 fork 关系）**
```
Server: id = xxxget(IPC_PRIVATE, IPC_CREAT | 0666);
Server: 将 id 写入文件 / 通过管道传给 Client
Client: 使用收到的 id
```

**模式 3：客户端创建私有回复通道**
```
Client: reply_id = msgget(IPC_PRIVATE, IPC_CREAT | 0600);
Client: 将 reply_id 作为消息的一部分发给 Server
Server: 用 reply_id 向客户端回复
```

### IPC 对象的权限

```c
struct ipc_perm {
    uid_t  cuid;   /* 创建者 UID */
    gid_t  cgid;   /* 创建者 GID */
    uid_t  uid;    /* 当前属主 UID */
    gid_t  gid;    /* 当前属组 GID */
    mode_t mode;   /* 权限位 (rwx for owner/group/other) */
};
```

权限检查：
- 读操作需要 owner 读权限 / group 读权限 / other 读权限 / root
- 写操作需要对应的写权限

## HFT / 嵌入式关联

- **ftok 路径**：HFT 用固定路径如 `/var/run/hft` 生成 key
- **IPC_PRIVATE**：HFT 多进程通过共享 ID 文件传递 IPC ID
- **权限**：生产环境设 0600，仅允许服务用户访问
- **嵌入式**：SysV IPC 较少使用，通常用 POSIX IPC 或 socket
- **替代方案**：用 Unix socket + 抽象地址名替代 ftok 约定

## 代码示例

```c
#include <sys/ipc.h>
#include <sys/msg.h>
#include <stdio.h>

/* 服务器端 */
int server_init(void) {
    key_t key = ftok("/var/run/hft", 'M');
    if (key == -1) { perror("ftok"); return -1; }

    int msqid = msgget(key, IPC_CREAT | 0660);
    if (msqid == -1) { perror("msgget"); return -1; }

    printf("server: key=0x%x msqid=%d\n", (int)key, msqid);
    return msqid;
}

/* 客户端 */
int client_connect(void) {
    key_t key = ftok("/var/run/hft", 'M');
    if (key == -1) { perror("ftok"); return -1; }

    int msqid = msgget(key, 0);  /* 获取已存在对象 */
    if (msqid == -1) { perror("msgget"); return -1; }

    return msqid;
}
```

## 代码自测

<details>
<summary>1. ftok 为什么可能产生相同的 key？</summary>

`ftok` 组合三部分：文件的设备号（dev）、inode 号、proj_id。如果两个不同路径在不同文件系统上有相同的 inode 号和设备号组合，ftok 会返回相同的 key。这在 NFS 或某些文件系统上可能发生。解决：(1) 确保使用唯一的路径文件；(2) 用不同的 proj_id 区分；(3) 考虑用 `IPC_PRIVATE` + 文件传递 ID。
</details>

<details>
<summary>2. IPC_PRIVATE 和 ftok 生成的 key 有什么区别？</summary>

- `IPC_PRIVATE` (= 0)：创建一个私有 IPC 对象，无法被其他进程通过 key 找到。只能通过 fork 继承或 ID 文件传递。适用于有亲缘关系的进程间通信。
- `ftok()` 生成的 key：非 0 值，任何知道相同路径+proj_id 的进程都能找到同一个 IPC 对象。适用于无亲缘关系的客户端-服务器。
</details>
