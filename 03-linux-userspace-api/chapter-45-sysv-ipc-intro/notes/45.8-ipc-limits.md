# 45.8 IPC Limits

> 本章：[TLPI 第 45 章 — System V IPC Introduction](./README.md)

## 本节讲什么

介绍 SysV IPC 的系统级限制参数，以及如何查看和调整它们。

## 要点

### SysV IPC 限制参数

| 限制 | 默认 | /proc 路径 | 说明 |
|------|------|-----------|------|
| 最大消息队列数 | 32000 | `/proc/sys/kernel/msgmni` | 系统级 |
| 最大消息大小 | 8192 | `/proc/sys/kernel/msgmax` | 单条消息 |
| 队列最大总大小 | 16384 | `/proc/sys/kernel/msgmnb` | 单队列 |
| 最大信号量集数 | 32000 | `/proc/sys/kernel/semmni` | 系统级 |
| 每集最大信号量数 | 32000 | `/proc/sys/kernel/semmsl` | 每个集合 |
| 系统最大信号量数 | 1024000000 | `/proc/sys/kernel/semmns` | 全局 |
| 每次操作最大信号量数 | 500 | `/proc/sys/kernel/semopm` | 单次 semop |
| 最大共享内存段数 | 4096 | `/proc/sys/kernel/shmmni` | 系统级 |
| 最大共享段大小 | — | `/proc/sys/kernel/shmmax` | 单段 |
| 最大共享内存总量 | — | `/proc/sys/kernel/shmall` | 系统级 |

### 查看与调整

```bash
# 查看
sysctl kernel.msgmni kernel.msgmax kernel.msgmnb
sysctl kernel.semmni kernel.semmsl kernel.semmns
sysctl kernel.shmmni kernel.shmmax kernel.shmall

# 临时调整
sysctl -w kernel.msgmax=65536
sysctl -w kernel.shmmax=2147483648  # 2GB

# 永久调整
echo "kernel.shmmax=2147483648" >> /etc/sysctl.d/99-hft.conf
sysctl -p /etc/sysctl.d/99-hft.conf
``### 查看当前 IPC 对象

```bash
# 查看所有 SysV IPC 对象
ipcs

# 分类查看
ipcs -q    # 消息队列
ipcs -s    # 信号量
ipcs -m    # 共享内存
ipcs -a    # 全部（带限制信息）

# 查看限制
ipcs -l

# 删除对象
ipcrm -q <msqid>
ipcrm -s <semid>
ipcrm -m <shmid>
```

### 常见限制问题

| 问题 | 原因 | 解决 |
|------|------|------|
| `msgget` ENOSPC | 队列数达上限 | 调高 msgmni |
| `msgsnd` EINVAL | 消息太大 | 调高 msgmax |
| `msgsnd` ENOSPC | 队列总大小超限 | 调高 msgmnb |
| `semget` ENOSPC | 信号量集超限 | 调高 semmni |
| `shmget` ENOSPC | 共享段数超限 | 调高 shmmni |
| `shmget` EINVAL | 段大小超限 | 调高 shmmax |

## HFT / 嵌入式关联

- **shmmax 调大**：HFT 共享内存行情数据可能数 GB，需调高 shmmax 和 shmall
- **msgmax**：HFT 行情消息可能超过默认 8KB，调大到 64KB
- **shmmni**：多策略进程共享多段，可能需调高
- **systemd LimitSHM**：`LimitSHM=infinity` 放宽共享内存限制
- **嵌入式**：精简系统可能减少 IPC 限制或裁剪 SysV IPC 支持
- **监控**：运维脚本定期检查 `ipcs` 输出，发现泄漏 IPC 对象

## 代码示例

```c
#include <stdio.h>
#include <sys/shm.h>

void check_shm_limits(void) {
    int max_segments = 0;
    FILE *f = fopen("/proc/sys/kernel/shmmni", "r");
    if (f) { fscanf(f, "%d", &max_segments); fclose(f); }
    printf("max shm segments: %d\n", max_segments);

    long max_size = 0;
    f = fopen("/proc/sys/kernel/shmmax", "r");
    if (f) { fscanf(f, "%ld", &max_size); fclose(f); }
    printf("max shm size: %ld bytes (%.1f GB)\n",
           max_size, (double)max_size / (1<<30));
}

int create_large_shm(key_t key, size_t size) {
    int shmid = shmget(key, size, IPC_CREAT | 0660);
    if (shmid == -1) {
        if (errno == EINVAL) {
            fprintf(stderr, "size %zu exceeds shmmax\n", size);
        } else if (errno == ENOSPC) {
            fprintf(stderr, "shm segments limit reached\n");
        }
    }
    return shmid;
}
```

## 代码自测

<details>
<summary>1. shmmax 和 shmall 的区别？</summary>

- `shmmax`：单个共享内存段的最大字节数
- `shmall`：系统所有共享内存段的总页数上限（乘以页大小得到字节数）

即使 shmmax 允许创建 2GB 的段，如果 shmall 限制总共享内存为 4MB，也无法创建。两者需同时满足。
</details>

<details>
<summary>2. 为什么 IPC 对象不自动回收？</summary>

SysV IPC 对象的生命周期独立于创建进程——即使创建进程退出，IPC 对象仍然存在直到：(1) 显式 `xxxctl(IPC_RMID)` 删除；(2) 系统重启。这是设计意图（允许进程崩溃后 IPC 对象保留），但也是常见资源泄漏来源。运维需定期 `ipcs` 检查并 `ipcrm` 清理。
</details>
