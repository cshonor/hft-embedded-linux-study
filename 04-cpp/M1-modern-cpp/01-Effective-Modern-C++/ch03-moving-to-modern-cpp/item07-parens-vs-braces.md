# Item 7：区别 () 和 {} 创建对象

> 第 3 章 移步现代 C++ · Item 7 · 下一节：[Item 8 nullptr](item08-nullptr.md)

## 为什么要学这个（先建立直觉）

C 里初始化很简单——要么用 `=`，要么用 `{}`：

```c
int x = 42;        // 等号初始化
int arr[] = {1, 2, 3};  // 花括号初始化数组
struct Point p = {3, 4};  // 花括号初始化结构体
```

C++ 有了类、构造函数重载，初始化变得复杂。C++11 引入了统一初始化语法 `{}`，号称"能初始化一切"。但统一不等于无歧义——`{}` 和 `()` 在某些场景下行为完全不同，尤其是 `vector` 的 `(10, 20)` vs `{10, 20}` 陷阱，是新手最容易踩的坑之一。

**核心冲突：** `{}` 会优先匹配 `initializer_list` 构造函数，哪怕有更优匹配。这意味着你以为在调构造函数 A，实际调的是构造函数 B。

---

## 这节讲什么

C++11 的大括号初始化 `{}` 几乎能初始化一切，但和小括号 `()` 有微妙差异——尤其是 `{}` 会优先匹配 `initializer_list` 构造函数，导致反直觉的行为。

---

## () vs {} 对比

| 特性 | `()` | `{}` |
|------|------|------|
| 窄化转换 | 允许（`int(3.14)` 得 3） | **禁止**（`int{3.14}` 编译失败） |
| 最烦人解析 | 会中招（`Widget w();` 被解析成函数声明） | 免疫 |
| `initializer_list` 构造函数 | 不优先 | **优先匹配** |
| 适用范围 | 只能调构造函数 | 能初始化一切（数组、容器、内置类型、成员初始化列表） |

### 窄化转换防护

```cpp
int x1(3.14);     // OK，x1 = 3（截断，但编译通过）
int x2 = 3.14;    // OK，x2 = 3（同上）
int x3{3.14};     // 编译失败！{} 禁止窄化
int x4 = {3.14};  // 编译失败！同上

// HFT 场景：防止 double 截断
double price = 107.85;
int64_t qty1(price);   // OK 但危险——截断为 107
int64_t qty2{price};   // 编译失败——{} 拦住了！
```

### 最烦人解析（Most Vexing Parse）

```cpp
// 你以为在创建一个 Widget 对象，传入一个临时 Data
Widget w(Data());   // ← 编译器解析成：声明一个函数 w，参数是 Data(*)()
                     //   返回 Widget。这不是对象声明！

Widget w{};          // OK，调用默认构造
Widget w{Data{}};    // OK，传入临时 Data 对象
```

### initializer_list 优先陷阱

```cpp
std::vector<int> v1(10, 20);   // 10 个 20 → {20,20,...,20}（10 个元素）
std::vector<int> v2{10, 20};   // 2 个元素 → {10, 20}（匹配 initializer_list）

// 更隐蔽的例子：
std::vector<int> v3{10, 20};   // {10, 20}——你想要的
std::vector<int> v4(10, 20);   // 10 个 20——可能不是你想要的

// 空花括号
std::vector<int> v5{};   // 调用默认构造，空 vector（不是"1 个空元素"）
std::vector<int> v6();   // 最烦人解析！声明了一个函数
```

**规则总结：** `{}` 会**优先**匹配 `initializer_list` 构造函数，哪怕有更优匹配。空 `{}` 则调用默认构造（不会匹配 `initializer_list` 的空列表）。

## 常见错误（新手踩坑）

**错误 1：vector 初始化搞混 () 和 {}**
```cpp
std::vector<int> v{10, 20};  // 以为 10 个 20，实际 2 个元素 {10, 20}
// 根因：{} 优先匹配 initializer_list 构造函数
```
**修正：** 要 N 个相同值用 `()`，要列出元素用 `{}`。

**错误 2：最烦人解析导致"对象变函数"**
```cpp
Widget w();  // 以为创建默认构造的对象，实际声明了一个函数
// 编译能过，但 w 不能当对象用（w.size() 报错）
```
**修正：** 用 `Widget w;` 或 `Widget w{};`。

**错误 3：{} 防窄化导致编译失败，误以为是代码 bug**
```cpp
int x{some_double};  // 编译失败，但报错信息可能不直观
// 新手以为是变量没定义或头文件没包含，实际是 {} 在防窄化
```
**修正：** 理解这是 `{}` 的安全特性。如果确实需要截断，用 `static_cast<int>(some_double)` 显式转换。

## 新手要点（和 C 的区别）

| 维度 | C 怎么做 | C++ 怎么做 | 为什么 |
|------|---------|-----------|--------|
| 初始化语法 | `=` 或 `{}`（结构体/数组） | `=`、`()`、`{}` 三种 | C++ 有构造函数重载，需要区分 |
| 窄化转换 | 不检查（`int x = 3.14;` 静默截断） | `{}` 禁止，`()` 允许 | `{}` 的安全特性 |
| 最烦人解析 | 不存在（C 没有构造函数） | `Widget w();` 被解析成函数声明 | C++ 语法歧义 |
| 统一初始化 | 不需要 | `{}` 可用于一切场景 | C++11 统一初始化语法 |

**一句话总结：** C 程序员记住——`{}` 是 C++11 的"安全初始化"语法，防窄化、防最烦人解析，但对容器要小心 `initializer_list` 优先匹配。

---

## HFT 关联

- **防窄化**：`int64_t qty{order.qty()}` 比 `int64_t qty(order.qty())` 安全——后者在 `qty()` 返回 `double` 时不报错但截断，可能导致下单数量错误。
- **协议结构体初始化**：`Order o{symbol, price, qty, side};` 用 `{}` 一次初始化所有字段，比逐个赋值更清晰，也比 `()` 不容易搞混参数顺序。
- **成员初始化列表**：构造函数初始化列表推荐用 `{}`：`Widget() : data_{size}, cache_{nullptr} {}`，统一风格防窄化。
