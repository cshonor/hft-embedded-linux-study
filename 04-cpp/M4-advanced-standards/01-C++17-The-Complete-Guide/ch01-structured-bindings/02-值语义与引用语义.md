# 1.2 值语义与引用语义

> 第 1 章 结构化绑定 · 上一节：[1.1 三种绑定形式](01-三种绑定形式.md) · 下一节：[1.3 适用场景与限制](03-适用场景与限制.md)

## 这节讲什么

结构化绑定的 `auto` 前缀决定了绑定变量是拷贝还是引用。理解底层匿名变量机制才能正确选择 `auto`/`auto&`/`const auto&`，避免"改了绑定变量但原对象没变"的困惑。

## 核心区别

```cpp
struct Point { int x, y; };
Point p{1, 2};

auto [a, b] = p;           // 值语义：a/b 是拷贝
auto& [c, d] = p;          // 引用语义：c/d 是 p 成员的别名
const auto& [e, f] = p;    // 只读引用：e/f 只能读不能改
```

### 改绑定变量是否影响原对象？

```cpp
auto [a, b] = p;     // a/b 是匿名拷贝的成员
a = 100;             // 改的是拷贝，p.x 不变
// p.x 仍然是 1

auto& [c, d] = p;    // c/d 是 p 成员的别名
c = 100;             // 直接改 p.x
// p.x 变成 100
```

## 底层机制：匿名变量 e

`auto [x, y] = p` 的本质是两步：

```cpp
// 第一步：用 auto 声明匿名变量 e
auto e = p;          // e 是 p 的拷贝（值语义）
// auto& e = p;      // e 是 p 的引用（引用语义）
// const auto& e = p; // e 是 p 的 const 引用

// 第二步：x/y 是 e 的成员引用
auto& x = e.x;
auto& y = e.y;
```

**关键**：`auto`/`auto&`/`const auto&` 修饰的是匿名变量 `e`，不是直接修饰 `x/y`。`x/y` 永远是 `e` 成员的引用（别名）。

### 值语义的代价

```cpp
struct BigStruct { int data[1000]; };
BigStruct big{};

auto [a] = big;      // 拷贝 1000 个 int！
auto& [b] = big;     // 零拷贝，b 是 big.data 的别名
```

**HFT 教训**：大对象用 `auto [x] = obj` 会触发拷贝，热路径上用 `auto&` 或 `const auto&`。

## 在 range-for 中的选择

```cpp
std::vector<Tick> ticks = load_ticks();

// 值语义：每个 tick 拷贝一份（大对象别用）
for (auto [price, qty] : ticks) { ... }

// 引用语义：零拷贝（推荐）
for (auto& [price, qty] : ticks) { ... }

// 只读引用：最安全（推荐）
for (const auto& [price, qty] : ticks) { ... }
```

### map 遍历

```cpp
std::map<int, std::string> m;

// 只读遍历
for (const auto& [key, val] : m) {
    std::cout << key << " -> " << val << "\n";
}

// 修改 value
for (auto& [key, val] : m) {
    val += "_updated";  // 可以改 value
    // key = 0;          // 编译错误：map 的 key 是 const
}
```

注意：遍历 `std::map` 时，`key` 始终是 `const` 的（map 的特性），即使你用 `auto&`。

## 常见错误

### 错误 1：用值语义改绑定变量，以为改了原对象

```cpp
auto [x, y] = p;
x = 100;
// 以为 p.x 变了？没有！x 是拷贝
// 要改原对象用 auto& [x, y] = p;
```

### 错误 2：对临时对象用 auto&

```cpp
// 临时对象用 auto& 绑定——悬垂引用
auto& [a, b] = std::make_pair(1, 2);  // UB！临时对象在语句结束销毁

// 正确：用值语义
auto [a, b] = std::make_pair(1, 2);  // OK，a/b 是拷贝
```

### 错误 3：以为 auto&& 是万能引用

```cpp
auto&& [x, y] = p;  // 这不是万能引用！
// auto&& 在结构化绑定中：如果 p 是左值，e 是 p 的引用；如果 p 是右值，e 移动构造
// 实际中很少用 auto&& 做结构化绑定，用 auto 或 auto& 更清晰
```

## HFT 关联

```cpp
// 解包 tick（大对象用 const auto&）
const auto& [price, qty, side] = latest_tick;  // 零拷贝只读

// 修改 tick（用 auto&）
auto& [price, qty, side] = tick_ref;
price = new_price;  // 直接修改原对象

// 遍历订单表（map，用 const auto&）
for (const auto& [sym, orders] : order_book) {
    total += orders.size();
}
```

## 小结

| 形式 | 匿名变量 e | 改绑定影响原对象？ | 适用场景 |
|------|-----------|-------------------|---------|
| `auto [x,y] = p` | `auto e = p`（拷贝） | 不影响 | 小对象、需要副本 |
| `auto& [x,y] = p` | `auto& e = p`（引用） | 影响 | 修改原对象 |
| `const auto& [x,y] = p` | `const auto& e = p` | 不能改 | 只读遍历（推荐默认） |
