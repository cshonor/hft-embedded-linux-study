# 1.1 引用 References

> **来源**：The Cherno（Yan Chernikov）· *C++ Series* —— "REFERENCES in C++"
> **实测环境**：macOS 26.6.2 / Apple Silicon (arm64) · clang 23.1.0 · `-std=c++20`
> **Primer 对照**：[2.3.1 引用](../01-C++Primer/ch02-variables-and-basic-types/2.3-compound-types/2.3.1-引用.md)
> **本机实测源码**：`/tmp/ref_probe.cpp`、`/tmp/nullref_probe.cpp`、`/tmp/ref_copy.cpp`（命令见文中）

## 本集讲什么

视频的切入点是从指针过渡到引用：**引用是「不用写 `*` 和 `&` 的间接访问」**。Cherno 的原话是「上周讲了指针，没看的话必须回去看，因为引用其实就是指针的一种扩展」。

这句话作为**心智模型**够用，但作为**标准事实**不成立。本节把两者分清楚：

- 视频给的是「怎么用、什么时候用」的直觉；
- 标准与实测给的是「底层到底是什么」的边界。

## 一句话结论

**引用是对象的别名（不是对象本身）；语义上永不空闲、永不改绑；实现上「常常」是指针，但标准不保证、优化后常常连指针都不剩。**

## 1. 引用是别名，不是新变量

```cpp
int a = 1, b = 2;
int& r = a;            // r 是 a 的另一个名字
r = b;                 // ⚠ 这不是「把 r 改指到 b」，而是「把 b 的值赋给 a」
```

实测（`clang++ -std=c++20 -O0 -o ref_probe ref_probe.cpp && ./ref_probe`）：

```
&a=0x16dd4b098  &r=0x16dd4b098  (&a==&r)=1
after r=b -> a=2 b=2  (&r==&a)=1
```

两行各说明一件事：

1. `&r` 与 `&a` **完全相等**——引用没有自己的地址。
2. `r = b` 之后 `a` 变成 `2`，而 `&r == &a` 依然成立——引用**终身绑定** `a`。

对照 cppreference[^refdecl] 原文：

> "Once initialized, a reference cannot be reseated (changed) to refer to another object."

## 2. 引用 vs 指针：对照表

| 维度 | 指针 `int*` | 引用 `int&` |
|------|-------------|-------------|
| 是对象吗 | **是**（有自己的地址、可寻址） | **否**（`&r` 得到的是被引用对象的地址） |
| 可为空 | 可以 `nullptr` | 语言层面不允许（初始化即绑定有效对象） |
| 能否改绑 | 随时 `p = &other` | **终身绑定**，`r = x` 是赋值 |
| 使用语法 | `*p` / `p->` | 像普通变量直接用 |
| 算术运算 | 支持 `p+1` / `p[i]` | **不支持**（`r+1` 是对 `r` 的值做加法） |
| 数组 | `int* a[3]` 合法 | `int& a[3]` **非法** |
| 指针的指针 | `int**` 合法 | `int&&` 是**右值引用**，不是「引用的引用」 |
| 典型用途 | 可选参数、数组遍历、容器/内核、地址运算 | 函数参数避免拷贝、`const T&` 只读传参、运算符重载 |

第三条「数组」和第四条是「引用不是对象」的直接推论，cppreference[^refdecl] 原文：

> "Because references are not objects, there are no arrays of references, no pointers to references, and no references to references"

## 3. 「引用底层就是隐藏的指针」——这句话对一半

这是本集最容易被带偏的一点，值得单独拆。

### 3.1 标准怎么说

cppreference[^refdecl] 原文：

> "References are not objects; they do not necessarily occupy storage, although the compiler may allocate storage if it is necessary to implement the desired semantics (e.g. a non-static data member of reference type usually increases the size of the class by the amount necessary to store a memory address)."

翻译成三条：

- **不保证占存储**——「necessarily」是关键限定词；
- **需要时才分配**——典型是需要一个地址值的场合（类成员、跨 TU 传参）；
- 于是「引用 = 指针」只在**部分场合**成立。

### 3.2 实测：哪些场合「确实是」指针

**(a) 作为类成员——几乎必然占一个指针大小**

```cpp
struct RefMember { int& r; };
struct PtrMember { int* p; };
```

```
sizeof(RefMember)=8  sizeof(PtrMember)=8
```

64 位平台上两者都是 8 字节。这才是 cppreference 那句「usually increases the size ... by the amount necessary to store a memory address」的实证。

**(b) 作为函数参数——ABI 层就是指针**

```cpp
__attribute__((noinline)) void bump_ref(int& v) { ++v; }
__attribute__((noinline)) void bump_ptr(int* v) { ++(*v); }
```

`clang++ -std=c++20 -O0 -S` 产出（arm64，`x0` 是第一个参数寄存器）：

```asm
__Z8bump_refRi:                    ; void bump_ref(int&)
	sub	sp, sp, #16
	str	x0, [sp, #8]
	ldr	x9, [sp, #8]
	ldr	w8, [x9]
	add	w8, w8, #1
	str	w8, [x9]
	add	sp, sp, #16
	ret

__Z8bump_ptrPi:                    ; void bump_ptr(int*)
	sub	sp, sp, #16
	str	x0, [sp, #8]
	ldr	x9, [sp, #8]
	ldr	w8, [x9]
	add	w8, w8, #1
	str	w8, [x9]
	add	sp, sp, #16
	ret
```

**逐条指令完全相同。** 运行时结果也相同：

```
bump_ref: x=6   bump_ptr: y=6
```

也就是说：**在函数调用边界上，`int&` 和 `int*` 走的是同一条路——寄存器里传一个地址。**

### 3.3 实测：哪些场合「连指针都不剩」

**(a) 局部引用在 -O0 下占一个栈槽（= 指针），-O1 下彻底消失**

`-O0` 下 `const int& cr = 42;` 的现场：

```asm
sub	x8, x29, #44
mov	w9, #42
stur	w9, [x29, #-44]      ; 42 这个临时量被「物化」到栈上
stur	x8, [x29, #-40]      ; 把它的地址存进引用的槽位 ← 这里确实是个指针
```

同一次 `-O0` 里 `int z = 7; int& rz = z;`：

```asm
add	x8, sp, #48
mov	w9, #7
str	w9, [sp, #48]        ; z = 7
str	x8, [sp, #40]        ; rz 的槽位 = &z  ← 又是一个指针
ldr	x0, [sp, #40]
bl	__Z8take_refRKi
```

**(b) 但 `-O1` 下同一个函数只剩三条指令：**

```asm
__Z8bump_refRi:
	ldr	w8, [x0]
	add	w8, w8, #1
	str	w8, [x0]
	ret
```

指针的「取地址 → 存栈 → 再读出来」全没了，引用直接退化成对 `x0` 的直接访问——**零额外开销**。

结论（写进肌肉记忆）：

| 场合 | 引用是否 = 指针 |
|------|----------------|
| 类数据成员 | 是（占 8 字节） |
| 跨函数传参（ABI 层） | 是（寄存器里一个地址） |
| 局部引用，`-O0` | 是（占一个栈槽） |
| 局部引用，`-O1` 及以上 | **否**，完全被优化掉，无任何运行时痕迹 |

> 所以「引用是指针的语法糖」是**实现层面的常见做法**，不是标准保证。把它当直觉可以，当结论会翻车（典型翻车现场：以为引用成员不占内存，结果 `sizeof` 对不上）。

## 4. 「不存在空引用」的真相

语言层面：引用的初始化规则要求必须绑定到有效对象或函数，cppreference[^refdecl] 原文：

> "A reference is required to be initialized to refer to a valid object or function"

但**「语言不允许」不等于「物理上做不到」**。下面这段是 UB，却真的能编过：

```cpp
int* p = nullptr;
int& r = *p;                 // UB：对空指针解引用来形成引用
```

实测（`clang++ -std=c++20 -O0 -o nullref_probe nullref_probe.cpp && ./nullref_probe`）：

```
&r = 0x0   (是否等于 nullptr: 1)

warning: reference cannot be bound to dereferenced null pointer in well-defined C++ code;
         comparison may be assumed to always evaluate to false [-Wtautological-undefined-compare]
```

两点值得注意：

1. `&r` 实测就是 `0x0`——「空引用」在运行时**确实可以存在**；
2. clang 给的警告是 `-Wtautological-undefined-compare`，意思是**编译器在编译期就知道这个比较恒为假**——因为标准规定这是 UB，编译器有权假设它不发生。

**所以**：

- 写代码：引用参数**不需要判空**（这是引用优于指针的真实收益）；
- 读代码：看到把解引用结果绑到引用，要知道这是在刀尖上走；
- HFT：判空分支省下来的是**分支预测**成本，但代价是**一旦上游给了空指针就是 UB**——契约必须在上游用断言/校验锁死。

## 5. 引用不能改绑：`ref = b` 是赋值

```cpp
int a = 1, b = 2;
int& r = a;
r = b;      // a 变成 2；r 依然是 a 的别名，没有「改指到 b」
```

实测输出里的 `after r=b -> a=2 b=2  (&r==&a)=1` 就是这条。

Rust 的 `&mut` 可以重新绑定，C++ 引用不行。要「可改指向」只能用指针：

| 需求 | C++ 写法 |
|------|---------|
| 绑定后不改，只想少写 `*` | 引用 `T&` |
| 运行期要改指向 | 指针 `T*` |
| 可能「没有值」 | 指针 `T*`（判空）或 `std::optional<T>` |
| 只读 + 不拷贝 | `const T&` |

## 6. `const T&` 绑定临时量：生命周期延长

```cpp
const int& r  = 42;   // ✅ 合法：编译器物化一个临时量，并延长其生命周期
int& r2       = 42;   // ❌ 编译错误：非常量引用不能绑到临时量
```

### 6.1 规则原文

cppreference[^refinit] 原文：

> "Whenever a reference is bound to a temporary object or to a subobject thereof, the lifetime of the temporary object is extended to match the lifetime of the reference"

### 6.2 例外清单（面试与踩坑的真正考点）

同一页明确列出的「不延长」情形：

| 情形 | 后果 |
|------|------|
| `return` 语句里绑到返回值的临时量 | 立即销毁 → **返回悬空引用**（C++26 起该写法 ill-formed） |
| 函数调用的**引用参数**上的临时量 | 只活到包含该调用的**完整表达式**结束 |
| `new` 表达式初始化器里绑定的临时量 | 只活到该 `new` 所在完整表达式结束，**不跟对象同寿** |
| 聚合用**括号**初始化（C++20）的引用成员 | 悬空；用**花括号**才延长 |

还有一条总纲：

> "In general, the lifetime of a temporary cannot be further extended by 'passing it on'"

即：**延长不可传递**——从 `const&` 再初始化一个 `const&`，不会二次延长。

### 6.3 实测：临时量确实被「物化」了

`-O0` 汇编（`const int& cr = 42;`）已经展示过：`mov w9, #42` → `stur w9, [x29,#-44]`。这个 42 **真的占了内存**，且引用指向它。运行期输出：

```
const int& cr = 42 -> cr=42  &cr=0x16dd4b074
```

`&cr` 是个真实栈地址，不是凭空生成的值——这就是「延长生命周期」在机器层面的样子。

## 7. C → C++：函数参数怎么改

C 只有一种传参方式：**值传递**。想改调用方的变量，只能传地址、在函数里手动解引用：

```c
void increment(int *p) { (*p)++; }
int x = 5;
increment(&x);                 /* 调用方必须记得写 & */
```

C++ 引用把这两步（调用方取地址、函数内解引用）都藏起来了：

```cpp
void increment(int& v) { v++; }
int x = 5;
increment(x);                  // 调用方像传值一样写
```

**语义等价、汇编相同**（见 §3.2 实测），差别只在**人眼看到的代码**和**契约表达**。

给 C 程序员的四条转换规则：

1. C 的 `T*` 参数，若「一定要有、且不改指向」→ 换成 `T&`；
2. C 的 `const T*` 参数 → 换成 `const T&`；
3. 只有「可选 / 可为空 / 要改指向 / 做地址运算」才保留指针；
4. `&` 的含义由位置决定：**声明里** `int& r` 是引用，**表达式里** `&x` 是取地址。

## 8. HFT 关联

### 8.1 大对象 `const T&` 的收益是量级级别的

用拷贝构造函数计数（确定性，不受优化噪声影响）：

```cpp
struct Big { char buf[4096]; long long x; /* 自定义拷贝构造，拷贝时 ++copies */ };
__attribute__((noinline)) long long by_value(Big b)        { return b.x + b.buf[0]; }
__attribute__((noinline)) long long by_cref(const Big& b)  { return b.x + b.buf[0]; }
```

`clang++ -std=c++20 -O2`，各调用 1000 次：

```
by_value : 1000 次调用 -> 1000 次拷贝构造 (约 3.9 MB 内存搬运)
by_cref  : 1000 次调用 -> 0 次拷贝构造
by_ptr   : 1000 次调用 -> 0 次拷贝构造
sizeof(Big) = 4104
```

**这就是 HFT 里 `const Order&` / `const OrderBook&` 传参的全部动机**：省掉的是整个对象的拷贝，不是几个指令。

### 8.2 但别迷信「引用一定更快」

三条必须澄清的：

1. **小标量（`int` / `double` / 指针）传值通常比传引用快**。传值走寄存器，传引用要先取地址再解引用，多一层间接。`const int&` 只在大对象上才划算。
2. **引用并不比指针快**。§3.2 已证明 ABI 层两者等价，优化器对两者的处理能力也基本一致。选引用是为了**契约清晰**（不可能为空、不打算改指向），不是为了性能。
3. **引用会带进别名（aliasing）不确定性**。编译器看到 `const T&` 无法像看到局部值那样自由重排，某些场合传值反而让优化器更放得开。这是低延迟代码里真实存在的取舍。

一句话：**引用买的是「安全 + 可读」，性能是「不亏」而不是「更赚」。**

## 常见误区（自查清单）

| # | 误区 | 事实 |
|---|------|------|
| 1 | 「引用一定不占内存」 | 类成员引用占 8 字节；`-O0` 局部引用占栈槽 |
| 2 | 「引用就是指针，没区别」 | 标准层面不是（不是对象、不保证占存储、不能构成数组）；优化后可以完全消失 |
| 3 | 「引用绝对不可能为空」 | 语言禁止，但 UB 路径能造出来，实测 `&r == 0x0` |
| 4 | 「`r = b` 是把 r 改指到 b」 | 是赋值——改的是被引用对象的值 |
| 5 | 「`const T&` 绑临时量总是安全的」 | 有例外清单，`return` / `new` / 引用参数 / 聚合括号初始化都会悬空 |
| 6 | 「引用比指针快」 | ABI 等价；小标量传值更快；选引用是为了契约不是性能 |

## 代码自测

**1（判断）** 下面代码执行后 `a` 和 `b` 分别是多少？`&r == &a` 是否成立？

```cpp
int a = 1, b = 2;
int& r = a;
r = b;
```

**2（选择）** `sizeof(struct { int& r; })` 在 64 位平台上最可能是？

- A. `0`（引用不占存储）
- B. `4`（等于 `int`）
- C. `8`（等于一个指针）

**3（踩坑）** 下面哪些是合法的？

```cpp
int& a[3];        // ①
int&& b = 42;     // ②
int& c = 42;      // ③
const int& d = 42;// ④
int* p = nullptr; int& e = *p;   // ⑤
```

**4（实战）** 一个 `struct Order { char payload[256]; };`，函数 `void send(const Order& o)` 与 `void send(Order o)` 相比，单次调用的内存搬运差多少？

<details>
<summary>参考答案</summary>

1. `a == 2`，`b == 2`，`&r == &a` **成立**。`r = b` 不是改绑，是把 `b` 的值赋给 `r` 所引用的 `a`。实测输出：`after r=b -> a=2 b=2  (&r==&a)=1`。

2. **C**。引用成员通常占一个指针大小的存储（本机 clang 23.1.0 实测 `sizeof(RefMember)=8`）。cppreference：reference 数据成员 "usually increases the size of the class by the amount necessary to store a memory address"。

3. 只有 **②④** 合法（② 是 C++11 右值引用绑定临时量，④ 是 `const` 左值引用绑定临时量，两者都延长生命周期）。① 引用不是对象，不能构成数组；③ 非常量左值引用不能绑临时量；⑤ 语法上能编过但是 **UB**——实测可得到 `&e == 0x0`，clang 会以 `-Wtautological-undefined-compare` 提示。

4. 差 **256 字节 / 次**（按值传参每次调用都完整拷贝一份 `payload`；`const&` 不拷贝）。本节的 4104 字节版本实测是 1000 次调用 → 1000 次拷贝构造 ≈ 3.9 MB 搬运，`const&` 版本为 **0**。工程上真正的判据不是「256 字节看起来不大」，而是**调用频次**：HFT 里每秒百万次调用 = 每秒 256 MB 的无谓内存带宽。
