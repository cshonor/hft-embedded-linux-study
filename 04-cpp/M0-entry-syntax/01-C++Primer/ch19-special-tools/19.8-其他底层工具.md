# 19.8 其他底层工具

## 本节讲什么

`type_traits`（编译期类型问答）、`if constexpr`（编译期分支）、`void_t`（成员探测）、
`decltype` 高阶用法——这些是**模板库的探针**，也是读懂标准库实现的钥匙。
代码均经**本机 g++ 13.3 / -std=c++17 实测**（2026-10-07）。
（这节是 ch16 模板的延伸，深入 SFINAE/concepts 见 M1 Item 27-28 与 M5 C++20 概念。）

## ① type_traits：编译期的类型问答机（实测）

```cpp
template <typename T>
std::string describe(T v) {
    if constexpr (std::is_integral_v<T>)       return "整数(可加锁)";
    else if constexpr (std::is_floating_point_v<T>) return "浮点(注意精度)";
    else return "其他";
}
describe(42) / describe(3.14) / describe("s")
// 本机实测：整数(可加锁) / 浮点(注意精度) / 其他
```

**高频 traits 速查**：

| trait | 问什么 | 典型用途 |
|---|---|---|
| `is_integral_v<T>` / `is_floating_point_v<T>` | 算术类型分类 | 泛型数值代码分派 |
| `is_trivially_copyable_v<T>` | 能 memcpy 吗 | 零拷贝序列化/共享内存对象的门槛 |
| `is_nothrow_move_constructible_v<T>` | 移动会抛吗 | 自己的容器决定移动还是拷贝（vector 扩容逻辑同款） |
| `is_same_v<A, B>` | 两个类型一样吗 | static_assert 类型契约 |
| `decay_t<T>` / `remove_cvref_t<T>`（C++20） | 剥引用/const/数组 | 模板实参归一化 |
| `conditional_t<cond, A, B>` | 编译期类型二选一 | 按特性选实现类型 |

**`if constexpr`（C++17）是分水岭**：被丢弃的分支**不实例化**——
`is_integral_v<T>` 为 false 时，整数分支里的 `atomic<T>` 操作根本不会编译，
不再需要 tag dispatch / enable_if 的绕行（旧代码里那些 `std::enable_if_t` 现在都能写人话了）。

## ② void_t：探测"这个类型有没有某个成员"（实测）

```cpp
template <typename, typename = std::void_t<>>
struct has_size : std::false_type {};                    // 默认：没有

template <typename T>
struct has_size<T, std::void_t<decltype(std::declval<T>().size())>>
    : std::true_type {};                                  // 偏特化命中：有 .size()

has_size<std::string>::value    // 本机实测：1
has_size<int>::value            // 本机实测：0
```

**机制**（SFINAE 的现代包装）：`void_t<...>` 在 `...` 里的表达式**非法**时，
偏特化匹配失败但**不是错误**（SFINAE），回落到主模板（false_type）；
合法时偏特化命中（true_type）。`decltype(declval<T>().size())` 不真的调用，
只在编译期问"这个表达式类型合法吗"。

C++20 起这整套被 **concepts** 收编：`requires { t.size(); }` 一句话——
但 C++17 代码库里 void_t 仍是主力（→ M5 C++20 ch07 concepts）。

## ③ decltype 高阶用法（实测）

```cpp
// 尾置返回类型：返回值类型依赖参数运算结果
template <typename A, typename B>
auto add(A a, B b) -> decltype(a + b) { return a + b; }

std::is_same_v<decltype(add(1, 2.5)), double>     // 本机实测：1
```

**decltype 的三张脸**：

| 写法 | 得到什么 |
|---|---|
| `decltype(x)`（变量名） | 变量的**声明类型**（含引用/cv） |
| `decltype((x))`（加括号变表达式） | 表达式类型 + 值类别（左值表达式 → `T&`） |
| `decltype(auto)` | 按初始化表达式**完整保留**类型（引用不剥）——转发返回值用（→ 19.7 ③） |

陷阱高频：`decltype(auto) f() { int x = 0; return (x); }`——
`(x)` 是左值表达式 → 返回 `int&` **悬垂引用**。去掉括号就对了。

## ④ 编译期编程的最小工具箱（拼装视图）

```
type_traits（问） + void_t（探） + if constexpr（选） + static_assert（验）
     ↓ 拼起来就是
"编译期类型级 if-else + 断言"——标准库 90% 的模板魔法都是这四件拼的
```

实战一例（序列化库的入口约束）：

```cpp
template <typename T>
void zero_copy_send(const T& obj) {
    static_assert(std::is_trivially_copyable_v<T>,
                  "零拷贝发送要求 trivially copyable（能 memcpy）");
    static_assert(!std::is_pointer_v<T>, "禁止指针类型——发出去的是地址不是数据");
    wire_write(&obj, sizeof(T));       // → 19.5 的协议结构体纪律
}
```

## 和 C 的区别 / 新手要点

| C | C++ |
|---|---|
| `_Generic`（C11，弱类型选择） | type_traits + if constexpr（完整的编译期类型系统） |
| 宏探测特性 | void_t/SFINAE/concepts |
| `typeof`（GNU 扩展） | decltype（标准） |

新手要点：① `if constexpr` 分支里的代码只在**该分支选中时**实例化——
但不选中的分支仍要语法正确；② `decltype((x))` 和 `decltype(x)` 不一样；
③ traits 全在 `<type_traits>`，变量模板版带 `_v`（C++17）、类型版带 `_t`（C++14）。

## HFT 关联

- **零拷贝行情发送的入口守卫**（④ 的 static_assert 模式）：trivially copyable
  是"能 memcpy 上网线"的编译期门槛——把布局事故挡在编译期（→ 19.5）
- 自己的容器（无锁队列/订单簿）需要 `is_nothrow_move_constructible` 决定
  元素搬迁策略——和 vector 扩容同一套逻辑（18.1 ② 实测）
- 编译期分派替代运行期分支：协议族解码器按 `if constexpr (has_field_v<T, "seq">)`
  生成不同的字段提取代码——零运行期开销的多协议适配
- C++20 concepts 已在 M5 待命；C++17 代码库里 void_t 模式还会在行情解码库里活很多年

## 代码自测

**题目 1：** 下面这个 traits 判断为什么不可靠？

```cpp
template <typename T>
void process(T& container) {
    if (std::is_same_v<T, std::vector<int>>) { /* vector 专用路径 */ }
    else { /* 通用路径 */ }
}
```

<details>
<summary>参考答案</summary>

两个问题：① 普通 `if` 的两个分支**都实例化**——通用路径里的代码对
`vector<int>` 也必须能编译（比如调用了 vector 没有的方法就炸）；该用 `if constexpr`。
② `is_same_v<T, vector<int>>` 太死——`vector<int, MyAlloc>`、const 版本都不命中；
按"特性"判断（`has_size`、`is_random_access`）比按"具体类型"判断健壮。

</details>

**题目 2：** `decltype(auto) f() { static int x = 0; return (x); }` 安全吗？

<details>
<summary>参考答案</summary>

**安全**——`x` 是 static（静态生存期），返回 `int&` 指向静态对象，不悬垂。
危险的是把 static 去掉：局部变量经 `(x)` 返回引用 = 悬垂。
`decltype((expr))` 的规则是"左值表达式 → T&"，和"auto 总是剥引用"正好互补——
写转发函数时这两者的区别必须条件反射（19.7 ③ 的 `decltype(auto)` 同理）。

</details>

**题目 3：** 用本节工具写一个编译期检查：模板函数 `send(const T&)` 只接受
"trivially copyable 且非指针、非数组"的 T，违规给清晰报错。

<details>
<summary>参考答案</summary>

```cpp
template <typename T>
void send(const T& obj) {
    static_assert(std::is_trivially_copyable_v<T>,
                  "send 要求 trivially copyable（可 memcpy 的类型）");
    static_assert(!std::is_pointer_v<T>, "send 不接受指针（发地址没意义）");
    static_assert(!std::is_array_v<T>,   "send 不接受数组（请传 span/指针+长度）");
    wire_write(&obj, sizeof(T));
}
```

C++20 可升级为 concept（错误消息更短）：
`template <typename T> concept Wireable = std::is_trivially_copyable_v<T> && !std::is_pointer_v<T>;`
`void send(const Wireable auto& obj);`

</details>
