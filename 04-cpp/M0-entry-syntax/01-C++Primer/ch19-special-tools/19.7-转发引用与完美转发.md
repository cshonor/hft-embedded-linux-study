# 19.7 转发引用与完美转发

## 本节讲什么

`T&&` 在模板里**不是右值引用**，是"转发引用"（forwarding reference，旧称万能引用）——
它既能绑左值又能绑右值，配合 `std::forward` 把实参的**值类别原封不动**传给下一层。
这是 `emplace_back`/`make_unique` 等"包装层零损耗"的底层机制，也是 Effective Modern C++
Item 23-30 的根基（→ M1）。代码均经**本机 g++ 13.3 / -std=c++17 实测**（2026-10-07）。

## ① 引用折叠 + 特殊推导规则 = 转发引用

**引用折叠**（模板实例化时的规则）：

```
&  + &  → &      && + &  → &      （有左值引用参与，结果就是左值引用）
&  + && → &      && + && → &&
```

**推导规则**（`template <typename T> void f(T&&)` 专用）：

| 实参 | T 推导为 | 形参类型（折叠后） |
|---|---|---|
| 左值 `t` | `T = U&`（左值引用！） | `U& &&` → `U&` |
| 右值 `U{}` | `T = U`（非引用） | `U&&` |

所以 `T&&` 形参**总能匹配**——左值来变左值引用，右值来变右值引用。
**关键鉴别**：`T&&` 只有在"模板 + 类型推导"语境才是转发引用；
`void f(Widget&&)`（具体类型）或 `template <typename T> void f(const T&&)` 都不是。

## ② 完美转发：std::forward 恢复值类别（实测）

```cpp
void sink(const Tracer&) { std::cout << "sink 收到左值\n"; }
void sink(Tracer&&)      { std::cout << "sink 收到右值\n"; }

template <typename T>
void relay(T&& x) {
    sink(std::forward<T>(x));     // 左值来 → 转成左值；右值来 → 转成右值
}
Tracer t;
relay(t);          // 本机实测：T=左值引用，sink 收到左值
relay(Tracer{});   // 本机实测：T=非引用，sink 收到右值
```

**为什么需要 forward**：形参 `x` 是**有名变量**——变量永远是左值！
不用 forward 直接 `sink(x)`，右值传进来也会被当左值（移动语义丢失）。
`std::forward<T>(x)` 按 **T 的推导结果**做条件转换：`T` 是左值引用就转左值，否则转右值。
（`std::move` 是**无条件**转右值；`std::forward` 是**按推导结果**转换——这是两者的本质区别。）

## ③ 经典应用：包装层零损耗

```cpp
// emplace_back 的真身（→ 19.6 可变参数模板 + 本节 forward）
template <typename T, typename... Args>
void emplace(void* raw, Args&&... args) {
    new (raw) T(std::forward<Args>(args)...);   // 任意构造函数参数原样穿透
}

// 计时包装器：任何函数包一层计时，调用语义不变
template <typename F, typename... Args>
auto timed(F&& f, Args&&... args) -> decltype(auto) {
    auto t0 = clk::now();
    return std::forward<F>(f)(std::forward<Args>(args)...);   // 返回值类别也转发
}
```

注意返回类型写 `decltype(auto)`——返回引用时保持引用，值时保持值，
`auto` 会砍掉引用造成意外拷贝。

## ④ std::move 的真相：它不移动任何东西（实测）

```cpp
std::string a = "hello";
std::string b = std::move(a);      // move 只是"贴标签"：把 a 转成右值引用
// 本机实测：move 后 a.size()=0（libstdc++ 小字符串优化下被掏空）
```

- `std::move(x)` = `static_cast<remove_reference_t<T>&&>(x)`——**纯类型转换，零代码生成**
- 真正"移动"发生在**接收方**（移动构造/移动赋值被重载决议选中）那一刻
- move 后的对象处于"**有效但未指定**"状态：可以析构、可以赋值，**不要再读它的值**
  （`a.size()` 返回 0 是 libstdc++ 的实现细节，不是标准承诺——标准只说"有效但未指定"）

## ⑤ 三个高频翻车点

1. **转发引用重载会"吞掉"一切**：

```cpp
struct S {
    S(S&&) = default;
    template <typename T> S(T&&);      // 转发引用构造——比 S(S&) 更匹配左值！
};
S s1; S s2(s1);      // 意外命中模板构造（T=S&），不是拷贝构造！
```

修法：`enable_if`/`requires`（C++20）把模板构造限定在"不是 S 本身"的类型
（→ M1 Item 26）。

2. **一次 forward 只保一次**：`f(forward<T>(x)); g(forward<T>(x));` 第二次转发时
   x 可能已被移动——**转发后不再使用**是铁律。

3. **return 里的局部变量别 forward**：`return std::forward<T>(local);`
   局部变量返回本来就有 RVO/隐式 move，强行 forward 反而阻止 RVO（→ M1 Item 25）。

## 和 C 的区别 / 新手要点

| C | C++ |
|---|---|
| 函数参数按值拷 or 传指针 | 左值/右值两套重载 + 转发引用通吃 |
| 无值类别概念 | lvalue/prvalue/xvalue 三分 |
| 无 | `std::move`/`std::forward`（纯转换工具） |

新手要点：① 见 `T&&` 先问"是模板推导语境吗"；② move 是标签不是动作；
③ move 后的对象别再读值；④ forward 一次就够、转完别再用。

## HFT 关联

- **订单/行情对象的构造零拷贝**：`book.emplace(price, qty, side)` 参数穿透到
  placement new，无临时对象、无拷贝——19.1 + 19.6 + 本节三件套的合体
- 无锁队列 `push(T&&)`：`push` 移动元素进 ring buffer 后就地失效原对象——
  值类别语义在单生产者场景是明确的（→ 06.6.5 / 14-hft）
- 日志/监控包装层（③ 的 timed 模式）在热路径要求**零开销转发**：
  `decltype(auto)` + forward 全套，编译后通常只剩一次时钟调用

## 代码自测

**题目 1：** `template <typename T> void f(T&& x)` 分别用 `f(i)`（i 是 int 左值）
和 `f(42)` 调用时，T 各推导成什么？

<details>
<summary>参考答案</summary>

`f(i)`：`T = int&`（左值引用）→ 形参折叠为 `int&`；
`f(42)`：`T = int`（非引用）→ 形参为 `int&&`。
这就是转发引用的"通吃"原理（本机实测验证，见 ②）。

</details>

**题目 2：** `std::string s = "x"; auto t = std::move(s);` 之后 `s` 是"空"吗？能做什么？

<details>
<summary>参考答案</summary>

标准是"**有效但未指定**"状态——libstdc++ 实测 `s.size()=0`，但标准不保证。
能做的事：析构、赋新值（`s = "new"` 后完全恢复可用）、调不依赖值的方法（`clear()`）。
不能做的事：依赖它的值（读 `s[0]`、假设 `empty()`）。
要"可恢复的空"，显式 `s.clear()`，别依赖 move 后状态。

</details>

**题目 3：** 下面这段为什么把代码 reviewer 吓一跳？修。

```cpp
template <typename T>
T&& wrapper(T&& x) {
    use(x);
    return std::forward<T>(x);
}
```

<details>
<summary>参考答案</summary>

两个雷：① 返回类型 `T&&` 是转发引用推导——传左值时返回 `U&`（悬垂风险：
若 x 是转发来的临时量，返回引用指向已销毁对象）；② `use(x)` 之后 x 值类别未变
（x 是左值变量），但语义上"use 过又转发"说明所有权语义含糊。
修：明确语义——要转交所有权就返回值 `T`（`return std::forward<T>(x);` 配 `T` 返回类型），
要观察不改所有权就返回 `void`/`bool`。转发引用做返回类型只在极其特殊的设计里合理。

</details>
