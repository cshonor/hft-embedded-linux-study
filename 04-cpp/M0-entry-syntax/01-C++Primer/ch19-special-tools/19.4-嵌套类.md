# 19.4 嵌套类

## 本节讲什么

类里面再定义类——嵌套类是**作用域控制**工具：把"只属于这个类的辅助类型"
（迭代器、节点、Impl）收进类的命名空间，不污染外层。本节讲清嵌套类的访问规则、
独立性（不持有外部对象）、pImpl 惯用法。代码均经**本机 g++ 13.3 / -std=c++17 实测**（2026-10-07）。

## ① 定义与独立性（先破除最大误解）

```cpp
class Outer {
    int secret = 42;
public:
    class Inner {
        int inner_secret = 7;
    public:
        void peek(Outer& o) { o.secret = 99; }   // C++11 起：嵌套类可访问外部 private
        void show() const { std::cout << inner_secret << "\n"; }
    };
};
Outer::Inner i;              // 独立构造：不需要任何 Outer 实例！
// 本机实测：sizeof(Inner)=4——Inner 对象里**没有**指向 Outer 的指针
```

**核心事实**：嵌套类是**作用域上的嵌套，不是对象上的包含**——
`Inner` 的实例和 `Outer` 的实例毫无关联（不像 Java 的非静态内部类那样隐式持有外部引用）。
要访问某个 Outer 对象，必须显式传进来（`peek(Outer& o)`）。

## ② 访问规则（不对称！）

| 方向 | 规则 | 实测 |
|---|---|---|
| 嵌套类 → 外部类成员 | **可以访问一切**（含 private 非静态，C++11 起） | `o.secret = 99` ✅ |
| 外部类 → 嵌套类成员 | **受嵌套类的访问控制**——外部类不是嵌套类的友元 | `i.inner_secret` ❌ 编译错误 |
| 嵌套类 → 外部静态成员 | 直接访问（无需对象） | `s_count` ✅ |

记忆：**嵌套类是"客人有了钥匙"**——它能开主人的门，主人却开不了它的门
（除非嵌套类把成员设为 public 或声明友元）。

## ③ 真实用途

**用途一：容器把节点/迭代器收进内部**（标准库全是这么干的）：

```cpp
template <typename T>
class List {
    struct Node {           // 私有嵌套类：实现细节，用户根本不该知道
        T data; Node* next;
    };
    Node* head_ = nullptr;
public:
    class iterator {        // 公有嵌套类：作为类的接口一部分
        /*...*/
    };
};
// 用户写 List<int>::iterator——迭代器天然携带"属于哪个容器"的信息
```

`std::list<int>::iterator` 的类型全名就是这么来的。

**用途二：pImpl 惯用法**（编译防火墙）：

```cpp
// widget.h——用户只看到指针，实现细节全藏在 .cpp
class Widget {
    class Impl;                 // 前向声明嵌套类（不完整类型）
    std::unique_ptr<Impl> pImpl_;
public:
    Widget();
    ~Widget();                  // 必须在 .cpp 定义（Impl 完整后才能析构）
    void work();
};
// widget.cpp
class Widget::Impl { /* 全部实现细节：成员、辅助函数… */ };
Widget::Widget() : pImpl_(std::make_unique<Impl>()) {}
Widget::~Widget() = default;
void Widget::work() { /* 转发给 pImpl_ */ }
```

价值：改实现**不触发用户代码重编译**（头文件没动）——大型项目的编译时间救星；
ABI 稳定性的经典手段（→ M4 Effective C++ Item 31）。

**用途三：每类型的 trait/tag 载体**：

```cpp
class Strategy {
    struct BuySignal {};      // 策略专属的标签类型，收进类里不外泄
    struct SellSignal {};
};
```

## ④ 局部类与嵌套类的边界（顺带知道）

- **局部类**（函数内定义的类）：不能定义静态数据成员、不能作模板参数（C++11 前）——
  C++11 起可作模板实参，lambda 出现后用武之地大减
- 嵌套类也有**访问外部类名**的特权：`Outer::Inner` 里可以直接写 `Outer` 的 typedef/static

## 和 C 的区别 / 新手要点

| C | C++ |
|---|---|
| 结构体套结构体 = 对象包含（内存上嵌套） | 嵌套类 = 作用域嵌套（对象上独立！） |
| 无 pImpl 概念（.opaque 指针手搓） | `class Impl; unique_ptr<Impl>` 标准姿势 |
| 无 | 嵌套类访问外部 private 的不对称规则 |

新手要点：① 嵌套类实例**不含**外部对象指针（sizeof 实测）；② 访问规则不对称；
③ 名字查找：嵌套类里 `Outer::Inner` 写全，外部类成员函数里直接写 `Inner`。

## HFT 关联

- **pImpl 与热路径的矛盾**：pImpl 多一次指针间接（cache miss）+ 堆分配——
  热路径类型（订单/行情）**不用 pImpl**；配置/连接管理等冷路径对象随便用
- 嵌套 `Node`/`iterator` 是自定义容器（订单簿/无锁队列）的标准形态——
  类型归属清晰，且嵌套类能自由访问容器的私有存储（② 的规则正为此设计）
- 编译防火墙在大型交易系统里的价值：行情解码库改实现，策略层不用重编——
  发布节奏快时 pImpl 的编译解耦比那一点间接开销值钱（在**接口边界**用，不在数据路径用）

## 代码自测

**题目 1：** 嵌套类和外部类有什么访问关系？

```cpp
class Outer {
    int private_data;
    class Inner {
        void f(Outer& o) {
            o.private_data = 42;  // C++11 前合法吗？
        }
    };
};
```

<details>
<summary>参考答案</summary>

C++11 起：嵌套类可以访问外部类的 private 成员（包括静态和非静态）。C++11 前：嵌套类不能直接访问外部类的非静态 private 成员（需要友元声明）。嵌套类主要用于实现细节隐藏——如迭代器类通常嵌套在容器类内部。

</details>

**题目 2：** `sizeof(Outer::Inner)` 和 `sizeof(Outer)` 有必然关系吗？为什么？

<details>
<summary>参考答案</summary>

没有。嵌套类是**作用域**嵌套不是**内存**嵌套——`Inner` 对象不持有 `Outer` 的指针或子对象
（本机实测 `sizeof(Inner)=4`，只装自己的 `int`）。
要关联必须显式存一个 `Outer*` 或引用。这与 Java 非静态内部类（隐式持有外部引用）
是本质区别——从 Java 转过来的人最容易在这里想错。

</details>

**题目 3：** pImpl 的 `unique_ptr<Impl>` 成员下，为什么 `~Widget()` 必须在 .cpp 里定义，
不能 `= default` 在头文件？

<details>
<summary>参考答案</summary>

`unique_ptr<Impl>` 的析构要调用 `Impl` 的析构函数——这要求 Impl 在**析构点**是完整类型。
头文件里 `Impl` 只有前向声明（不完整类型），`= default` 会把析构定义放进每个包含者的 TU，
在它们眼里 Impl 都不完整 → 编译错误。
放 .cpp（Impl 完整的地方）定义析构，链接器统一用那一份。
（C++23 的 `std::expected` 式完整类型推导或自定义 deleter 也能绕，但 .cpp 定义仍是标准做法。）

</details>
