# 19.2 运行时类型信息补充 & 枚举进阶

## 本节讲什么

两块内容：① 18.4 RTTI 的延伸——`type_info` 还能做什么（`type_index` 作键、`before` 顺序）；
② 枚举的现代形态 `enum class`——为什么旧式 `enum` 在新代码里绝迹。
代码均经**本机 g++ 13.3 / -std=c++17 实测**（2026-10-07）。

## ① type_info 的三个工程用法（超出 typeid 比较）

```cpp
#include <typeindex>
#include <map>
std::map<std::type_index, const char*> names;
names[typeid(int)] = "整数"; names[typeid(double)] = "浮点";
names[typeid(1.5)];      // 本机实测：取出"浮点"

typeid(int).before(typeid(double))   // 实测 0（int 排在 double 后）——实现相关的全程序一致序
```

- **`std::type_index`**（C++11）：`type_info` 的可拷贝包装——`type_info` 本身不可拷贝
  不能进容器，`type_index` 可以。做"类型 → 处理器"注册表的键
- **`type_info::before`**：给全程序类型一个一致（但实现相关）的排序——
  排序键用途（`std::map` 默认键序、调试输出排序），**不要**跨进程/跨版本持久化这个序
- `.name()`：mangled 名（`St13runtime_error`），只用于日志；可移植 demangle 用
  `abi::__cxa_demangle`（GCC/Clang 专属）

**注册表模式**（动态工厂的 RTTI 版）：

```cpp
std::map<std::type_index, std::function<void(const MsgBase*)>> handlers;
handlers[typeid(SnapMsg)]  = [](const MsgBase* m) { on_snap(static_cast<const SnapMsg*>(m)); };
handlers[typeid(TradeMsg)] = [](const MsgBase* m) { on_trade(static_cast<const TradeMsg*>(m)); };
// 分发：handlers[typeid(*msg)](msg);   ← typeid(*多态) 是动态类型（18.4 ②）
```

冷路径（启动注册/插件加载）这么写没问题；热路径还是查表/switch（→ 18.4 HFT 关联）。

## ② enum class：把 C 的枚举病一次治完（实测）

旧式 `enum` 的三宗罪，`enum class`（C++11）逐个治：

```cpp
enum OldStyle { Red, Green };              // 罪1：枚举值泄进外层作用域（Red 直接可用，易撞名）
enum class Side : uint8_t { Buy = 1, Sell = 2 };

int y = Red;                    // 罪2：隐式转 int（本机实测 y=0 编译通过）
// int x = Side::Buy;           // ❌ 编译错误：enum class 不隐式转换
int x = static_cast<int>(Side::Buy);        // ✅ 必须显式

sizeof(Side) == 1               // 罪3 治疗：可指定底层类型（uint8_t），旧 enum 由编译器选
```

| | 旧式 `enum` | `enum class`（= `enum struct`） |
|---|---|---|
| 作用域 | 枚举值泄进外层 | 必须 `Side::Buy` 限定 |
| 隐式转 int | ✅（事故源） | ❌ 必须 static_cast |
| 底层类型 | 编译器自选（布局不可控） | 可显式指定 `: uint8_t` |
| 前向声明 | 只有指定底层类型才行 | 永远可以 |

**协议场景的硬要求**：跨网络/跨文件的枚举值必须**定宽**——
`enum class MsgType : uint16_t`，配 static_assert 钉布局（→ 19.5 ④）。

## ③ switch 穷尽性与编译器警告

```cpp
switch (s) {
    case Side::Buy:  std::cout << "买\n"; break;
    case Side::Sell: std::cout << "卖\n"; break;
    // 漏一个枚举值：-Wswitch 警告（g++ 默认开）——枚举新增成员时全仓漏分支一目了然
}
```

- `enum class` + `switch` 不加 `default`：让 `-Wswitch` 替你守穷尽性——
  协议加消息类型时编译器把所有没处理的 switch 列出来
- 旧式 enum 也有 `-Wswitch`，但隐式转换让"拿个 int 就 switch"成为可能，防线形同虚设

## 和 C 的区别 / 新手要点

| C | C++ |
|---|---|
| `enum` 就是 int 的花名 | `enum class` 是真正的独立类型 |
| 无 | `type_index` / `type_info::before` |
| `#define SIDE_BUY 1` | `enum class Side : uint8_t`（有类型、有作用域、可调试） |

新手要点：① 新代码一律 `enum class`；② 协议枚举指定底层定宽类型；
③ 旧代码里新旧混用时，转换全走 `static_cast`，别写 `(int)e` 这种 C 强转。

## HFT 关联

- 行情/订单协议的**每个枚举都必须定宽**（`Side : uint8_t`、`MsgType : uint16_t`）——
  否则结构体布局随编译器漂移，解码错位（→ 19.5 static_assert 三件套）
- switch 穷尽性 + `-Wswitch` 是"交易所加消息类型"时的编译期验收——
  比运行时漏处理安全一个数量级
- `type_index` 注册表用于**策略插件系统**（冷路径）；热路径分发用
  msg_type 查表（19.3 成员指针表）或 variant+visit（M5）

## 代码自测

**题目 1：** 为什么 `enum class Color { Red, Green }; enum class Light { Red, Green };` 能共存，
而两个旧式 enum 这么写就报错？

<details>
<summary>参考答案</summary>

旧式 enum 的枚举值**泄进外层作用域**——两个 `Red` 在同一作用域重定义。
`enum class` 的枚举值封闭在自己的作用域里（`Color::Red` / `Light::Red`），互不干扰。
这正是"罪1：作用域污染"的解药。

</details>

**题目 2：** `std::map<std::type_index, Handler>` 能直接用 `typeid(T)` 作键，
为什么 `type_info` 本身不行？

<details>
<summary>参考答案</summary>

`std::type_info` **不可拷贝**（拷贝构造/赋值被删除）——容器要求元素可拷贝或可移动，
所以 `typeid` 返回的 `const type_info&` 不能直接存。`std::type_index` 是标准库给的
可拷贝包装（内部存指针 + 提供比较运算符），就是为"类型作键"这个场景设计的。

</details>

**题目 3：** 协议枚举从 2 个值加到 3 个，但发版后解码端没更新——enum class 能救你吗？

<details>
<summary>参考答案</summary>

**不能**——enum class 只保证编译期类型安全，管不了线上版本错配。
解码端 `switch` 遇到未知的第 3 个枚举值时走 default/未定义分支。
真正的防线是：① switch 穷尽性检查（编译期，防"代码没改全"）；
② 协议版本协商/拒绝未知 msg_type（运行期，防"版本没对齐"）；
③ golden-packet 回放测试（发版前，防"新老不兼容"）。
enum class 解决的是语言层问题，协议演进是工程层问题，各管一段。

</details>
