# 19.1 内存分配与 new 重载

## 本节讲什么

`new` 不是一个操作，是**两个**：先调 `operator new` 拿内存，再在内存上调构造函数。
理解这个分层，才能谈 placement new、自定义分配器、内存池——以及为什么
"内存池"是 HFT 的基础设施。代码均经**本机 g++ 13.3 / -std=c++17 实测**（2026-10-07）。

## ① new 的两层结构（这是全节的钥匙）

```cpp
T* p = new T(args);
// 等价于：
//   void* raw = operator new(sizeof(T));   // 第一层：裸分配（可重载！）
//   T* p = new (raw) T(args);              // 第二层：在 raw 上构造（placement new）
//
// delete p;
// 等价于：
//   p->~T();                               // 先析构
//   operator delete(p);                    // 再释放（可重载）
```

**推论**：想控制"内存在哪分配"，重载 `operator new/delete`；
想控制"在指定内存上构造"，用 placement new。两件事独立。

## ② 重载全局 operator new/delete（实测）

```cpp
#include <new>
#include <cstdlib>
#include <iostream>
void* operator new(std::size_t n) {
    std::cout << "global new " << n << "B\n";
    return std::malloc(n);
}
void operator delete(void* p) noexcept { std::free(p); }
void operator delete(void* p, std::size_t) noexcept { std::free(p); }  // C++14 sized delete

int main() {
    int* p = new int(1); delete p;     // 打印 global new 4B
    struct Big { char buf[100]; };
    Big* b = new Big; delete b;        // 打印 global new 100B
}
```

**本机实测输出**：`global new 4B` / `global new 100B` —— 每次 `new` 都经过我们的重载。

要点：
- sized delete（带 `std::size_t` 第二参）：C++14 起编译器优先选它，
  让自定义分配器**不用存分配大小**就能释放（slab/池分配器的关键）
- 类内重载：`struct T { static void* operator new(size_t); }`——只对该类生效，
  池化单个高频类型的标准做法
- 重载是**替换**不是包裹：全局版一旦重载，所有 `new`（包括标准库容器的）都走你的版本——
  埋点统计全局分配量就这么做，但要小心与第三方库的相互影响

## ③ placement new：在指定内存上构造（实测）

```cpp
alignas(Big) char raw[sizeof(Big)];
Big* q = new (raw) Big;    // 只在 raw 上构造，不分配（实测：不触发 global new 打印）
q->~Big();                 // 必须手动析构！不能 delete q（raw 不是堆内存）
```

**铁律**：placement new 的对象**手动析构、永不 delete**；
内存的寿命由你（栈数组/mmap/池）负责。

**HFT 主战场**：

```cpp
// 无锁队列的元素构造：环形缓冲区是预分配的，push 就是 placement new
template <typename T, size_t N>
class SpscRing {
    alignas(T) char buf_[N * sizeof(T)];
public:
    template <typename... Args>
    void emplace(Args&&... args) {
        new (&buf_[tail_ * sizeof(T)]) T(std::forward<Args>(args)...);   // 零分配
        tail_ = (tail_ + 1) % N;
    }
};
```

## ④ nothrow new 与 bad_alloc（实测）

```cpp
int* r = new (std::nothrow) int[1UL<<40];   // 4TB 请求
// 本机实测：返回 nullptr，不抛 std::bad_alloc
```

- 默认 `new` 失败抛 `std::bad_alloc`；`new (std::nothrow)` 失败返回 `nullptr`——
  **nothrow 版必须判空**，否则解引用空指针
- `-fno-exceptions` 环境（HFT 热路径库常见）里 new 失败的行为依赖运行时配置，
  很多团队直接禁用裸 new：启动期池化一切，运行期零分配（→ 06.6.5 ch07 / 13-dpdk mbuf）

## ⑤ operator new 之外的三个分配控制点（全景）

| 控制点 | 粒度 | 用途 |
|---|---|---|
| 全局 `operator new/delete` 重载 | 全程序 | 分配统计/埋点；换 tcmalloc/jemalloc（其实直接用 LD_PRELOAD 更简单） |
| 类内 `operator new/delete` | 单类型 | 高频小对象池化（订单/行情消息的 per-type pool） |
| 容器 `Allocator` 模板参数 | 单容器实例 | `std::vector<T, PoolAlloc<T>>`——标准容器接管自定义内存（见 ch12 allocator） |
| placement new | 单次构造 | 环形缓冲/共享内存/内存映射文件上的对象构造 |

## 和 C 的区别 / 新手要点

| C | C++ |
|---|---|
| `malloc/free` 只搬内存 | `new/delete` = 分配 + 构造/析构（两层） |
| 无 | placement new / operator new 重载 / nothrow |
| `realloc` 扩容 | vector 扩容 = 新分配 + 移动/拷贝 + 析构旧块（没有原地扩容） |

新手要点：① `malloc` 出来的内存**不能** delete，`new` 的**不能** free（分配器可能完全不同）；
② placement new 的 `#include <new>` 别忘；③ 重载 operator new 就必须配对重载 operator delete
（含 sized 版）。

## HFT 关联

- **运行期零分配**是低延迟系统的铁律：启动时池化所有订单/行情对象，
  热路径的"new"实际是池的 `acquire()`（通常就是 freelist 弹出 + placement new）——
  本节的分层模型就是这个架构的语言基础
- sized delete 让池分配器省掉 per-object 的大小头（8 字节/对象的元数据开销）——
  小对象池的密度优化
- malloc 抖动来源（brk/mmap/锁竞争）在 06.6.5 ch07 有实测；jemalloc/tcmalloc 选型同理
- 自定义 `operator new` 埋点是排查"谁在热路径偷偷分配"的最快手段（每分配打印 stack）

## 代码自测

**题目 1：** 下面错在哪？

```cpp
char buf[sizeof(Foo)];
Foo* p = new (buf) Foo;
delete p;
```

<details>
<summary>参考答案</summary>

placement new 的对象构造在**栈数组**上，`delete p` 会把栈地址交给 operator delete
（堆释放器）——UB。正解：`p->~Foo();` 手动析构，栈内存随作用域自动回收。

</details>

**题目 2：** 为什么 C++14 的 sized delete 对内存池重要？

<details>
<summary>参考答案</summary>

`sized delete`（`operator delete(void*, size_t)`）在释放时直接告诉分配器**块大小**——
池分配器不需要在每个对象头上存 size（省 8 字节/对象），也不需要查表推算归属池。
编译器在类型大小已知时优先选 sized 版（本机实测两版并存时 sized 版被调用）。

</details>

**题目 3：** `std::vector<T>` 能保证扩容时 T 的析构不泄漏吗？如果 T 的移动构造抛异常呢？

<details>
<summary>参考答案</summary>

扩容流程：分配新缓冲区 → 逐元素移动/拷贝到新缓冲区 → 全部成功后析构旧缓冲区。
移动构造若抛异常且**未标 noexcept**，vector 根本不敢用移动（改用拷贝，见 18.1 ② 实测）；
拷贝抛异常时，新缓冲区里已构造的元素逐个析构、释放新缓冲区、旧数据原样保留——
这就是 vector 扩容的**强保证**。析构函数本身必须 noexcept，否则强保证无从谈起。

</details>
