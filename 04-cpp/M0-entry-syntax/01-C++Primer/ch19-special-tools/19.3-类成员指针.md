# 19.3 类成员指针

## 本节讲什么

"指向成员的指针"（pointer to member）是 C++ 独有的指针类别——它指向的是
**类的某个成员**而不是某个对象：同一个成员指针，配不同的对象实例就能访问不同对象的同一成员。
本节覆盖成员数据指针、成员函数指针、`.*`/`->*` 运算符，以及它在回调表/状态机里的真实用途。
代码均经**本机 g++ 13.3 / -std=c++17 实测**（2026-10-07）。

## ① 成员数据指针

```cpp
struct W { int v = 7; };
int W::*pd = &W::v;        // 注意：&W::v 取的是"成员"，不是某个对象的字段

W w; W* pw = &w;
w.*pd    == 7              // 对象 . * 成员指针
pw->*pd  == 7              // 对象指针 ->* 成员指针（本机实测均通过）
```

- 类型写法：`int W::*`（"W 的 int 成员"）；本质是**成员在对象内的偏移量**（不是地址！）
- 所以它可以便宜地复制、放数组当"字段选择器"

## ② 成员函数指针（语法全 C++ 最丑，没有之一）

```cpp
struct W {
    int v = 7;
    int add(int a, int b) { return a + b + v; }
};
int (W::*pf)(int, int) = &W::add;          // 声明：返回类型 (类::*名)(参数表)
(w.*pf)(1, 2);        // = 10（本机实测）
(pw->*pf)(3, 4);      // = 14
// 调用必须带对象：成员函数有隐式 this，裸成员指针没法独立调用
```

**记忆法**：`.*`/`->*` 的优先级低于函数调用，**括号一个都不能少**：
`(w.*pf)(1, 2)` —— 先 `(w.*pf)` 拿到函数，再 `(1, 2)` 调用。

## ③ 和普通函数指针的关键差异（实测）

```cpp
int (*fp)(int) = twice;                    // 普通函数指针
sizeof(fp) == 8                            // x86_64：一个代码地址
sizeof(pf) == 16                           // 本机实测：成员函数指针 16 字节！
```

**本机实测**：`sizeof(fp)=8` vs `sizeof(pf)=16`——成员函数指针要带**两份信息**：
代码地址 + this 调整量（虚函数时存 vtable 槽位，多重继承时存基类偏移）。
所以不能把它和 `void*`/普通函数指针互相转换，也不能 `printf("%p", pf)`。

## ④ 真实用途：状态机 / 命令分发表（替代 switch）

```cpp
struct FeedHandler {
    void on_snap(const Msg& m) { /* 快照 */ }
    void on_incr(const Msg& m) { /* 增量 */ }
    void on_trade(const Msg& m) { /* 逐笔 */ }
};
// 协议 msg_type → 处理函数的跳转表：一次数组索引代替 switch 链
using Handler = void (FeedHandler::*)(const Msg&);
static constexpr Handler table[] = {
    &FeedHandler::on_snap,    // 0 = SNAP
    &FeedHandler::on_incr,    // 1 = INCR
    &FeedHandler::on_trade,   // 2 = TRADE
};
void dispatch(FeedHandler& h, const Msg& m) {
    (h.*table[m.type])(m);    // O(1) 查表，无虚函数、无分支链
}
```

这就是成员函数指针的经典工业用法：**把"对象+操作"的绑定推迟到查表时刻**。
（现代 C++ 也常用 `std::function`/模板 lambda 表达同样意图——
成员指针版零类型擦除、可 `constexpr`，热路径仍有其一席之地。）

## ⑤ 与现代替代品的对照

| 方案 | 开销 | 适用 |
|---|---|---|
| 成员函数指针 + 表 | 一次间接调用，可 constexpr | 类型固定、热路径跳转表 |
| 虚函数 | vtable 跳转 | 类型层次开放的运行期多态 |
| `std::function` | 类型擦除（可能分配） | 类型不固定的通用回调 |
| 模板 + lambda | 零开销（内联） | 编译期已知的分发 |

## 和 C 的区别 / 新手要点

| C | C++ |
|---|---|
| 函数指针 `int (*fp)(int)` | 成员指针必须带类：`int (W::*)(int, int)` |
| qsort 回调传 `void* data` | 成员指针天然带 this 语义 |
| 无 | `.*` / `->*` 两个专用运算符 |

新手要点：① `&W::v` 不是地址是偏移；② 调用必须给对象；
③ 成员函数指针 ≠ 普通函数指针（大小/语义都不同，实测 16B vs 8B）；
④ `typedef`/`using` 起别名能救命：`using Handler = void (W::*)(const Msg&);`

## HFT 关联

- 行情处理的 **msg_type → handler 跳转表**（④ 的 dispatch 模式）是交易所网关的
  标准形态：比 switch 链分支更规律（间接跳转目标少，BTB 友好），且表可以 constexpr 生成
- 成员指针 + CRTP 可在**编译期**完成"策略基类调派生实现"的分发（无 vtable）——
  这是 M1/ch16 里 CRTP 惯用法的机制底座
- 注意 16 字节的尺寸：把成员指针塞进缓存行敏感的紧凑结构（订单簿条目）前先算对齐账

## 代码自测

**题目 1：** 下面为什么编译错误？怎么改？

```cpp
struct A { void f() {} };
void (*fp)() = &A::f;
```

<details>
<summary>参考答案</summary>

`&A::f` 的类型是 `void (A::*)()`（成员函数指针），不是 `void(*)()`——
成员函数有隐式 this，两者不兼容。改法：`void (A::*fp)() = &A::f;`，
调用 `(a.*fp)()` 或 `(pa->*fp)()`。要摆脱对象束缚用 lambda 捕获或 `std::bind`/`std::function`。

</details>

**题目 2：** `int A::*p = &A::x;` 里的 `p` 存的是什么？为什么 `sizeof(p)` 可以只有 4 或 8？

<details>
<summary>参考答案</summary>

存的是**成员 x 在 A 对象内的偏移量**（Itanium ABI 下成员数据指针就是偏移，单位字节，
从 -1 起表示空）——所以它和对象实例无关，大小是一个整数的尺寸（实测 8B），
不同于成员函数指针（16B，要带 this 调整/vtable 信息）。

</details>

**题目 3：** 用成员函数指针表实现三态状态机（IDLE/RUN/STOP，事件 TICK/RESET），
写出跳转表的核心两行。

<details>
<summary>参考答案</summary>

```cpp
using Action = void (Sm::*)(Event);
static constexpr Action next[3][2] = {
    /* IDLE */ { &Sm::start,  &Sm::stay   },
    /* RUN  */ { &Sm::tick,   &Sm::stop   },
    /* STOP */ { &Sm::stay,   &Sm::reset  },
};
// 转移：(sm.*next[state][ev])(ev);
```

查表替代嵌套 switch——状态/事件多时表格化更可审阅，且可加静态断言保证表完整。

</details>
