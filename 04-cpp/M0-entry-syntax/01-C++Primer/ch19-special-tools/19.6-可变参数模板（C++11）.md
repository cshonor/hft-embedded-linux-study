# 19.6 可变参数模板（C++11）

## 本节讲什么

可变参数模板（variadic template）让模板接受**任意个数、任意类型**的参数——
它是 `std::make_unique`/`emplace_back`/`std::tuple`/`printf` 替代品的基础设施。
本节覆盖参数包、递归展开、C++17 折叠表达式、`sizeof...`。
代码均经**本机 g++ 13.3 / -std=c++17 实测**（2026-10-07）。

## ① 参数包与递归展开（经典形态）

```cpp
void print() { std::cout << "\n"; }              // 递归终点（空包重载）

template <typename T, typename... Rest>
void print(T&& first, Rest&&... rest) {          // 每次剥一个
    std::cout << first << " ";
    print(rest...);                              // 参数包展开：rest 变成逐个实参
}
print(1, 2.5, "三", 'x');
// 本机实测输出：1 2.5 三 x
```

**三个 `...` 的位置各管一件事**：

| 位置 | 名字 | 作用 |
|---|---|---|
| `typename... Rest` | 模板参数包 | 声明"一包类型" |
| `Rest&&... rest` | 函数参数包 | 声明"一包值" |
| `rest...` / `f(args)...` | 包展开 | 把包拆成逗号分隔的序列 |

递归模式的实质：**每次实例化处理一个参数，剩余打包继续**——
实例化 N 层模板（N = 参数个数），编译期完全展开、零运行时开销。

## ② C++17 折叠表达式：递归的现代替代

```cpp
template <typename... Args>
auto sum(Args... args) { return (args + ...); }      // 一元右折叠

sum(1, 2, 3, 4)     // 本机实测 = 10
sum(1.5, 2)         // = 3.5（类型自动推导为 double）
```

四种折叠形态：

```cpp
(args + ...)        // 右折叠：a1 + (a2 + (a3 + a4))
(... + args)        // 左折叠：((a1 + a2) + a3) + a4
(init + ... + args) // 带初值：空包也得 init（(0 + ... + args) 空包=0）
(args , ...)        // 逗号折叠：对包中每个元素执行左侧语句
```

逗号折叠是"对每个参数做一件事"的现代写法，不再需要递归：

```cpp
template <typename... Args>
void log_all(Args&&... args) {
    ((std::cout << args << " "), ...);   // 实测等价于逐个打印
    std::cout << "\n";
}
```

## ③ sizeof... 与参数包计数

```cpp
template <typename... Args>
void log_count(Args... args) { std::cout << sizeof...(args) << "\n"; }
log_count(1, 2, 3, 4, 5);     // 本机实测：参数个数=5
```

- `sizeof...(pack)`：包中**元素个数**（注意是 `sizeof...` 不是 `sizeof`）
- 典型用途：`static_assert(sizeof...(Args) == 2)`、元组索引、编译期分派

## ④ 与完美转发的组合（完整形态）

可变参数模板几乎总和转发一起出现——这就是 `emplace_back` 的真身：

```cpp
template <typename T, typename... Args>
T* pool_emplace(void* raw, Args&&... args) {           // 转发引用接住一切
    return new (raw) T(std::forward<Args>(args)...);   // 原样转发给构造函数
}
// 任意构造函数签名的类型都能在不写包装的情况下直接构造（→ 19.7 完美转发）
```

`std::make_unique<T>(args...)`、`vector::emplace_back(args...)` 都是这个模式——
参数包负责"个数自由"，`&&`+`forward` 负责"值类别不丢"。

## ⑤ 与可变参数宏/`va_list` 的对比（为什么 C 的招在 C++ 都退役了）

| C（`va_list`/`##__VA_ARGS__`） | C++（参数包） |
|---|---|
| 类型擦除：全是 `void*`/int 提升 | **类型保留**：每个参数类型独立推导 |
| 运行时解析（`va_arg` 按类型取，取错 = UB） | **编译期展开**，类型错误 = 编译错误 |
| 个数靠格式串约定（printf 的 `%d` 数错就炸） | `sizeof...` 编译期可数、可断言 |
| 宏不可调试 | 模板实例化有完整诊断 |

## 和 C 的区别 / 新手要点

| C | C++ |
|---|---|
| `va_list`/`va_start`/`va_end` | `template <typename... Args>` |
| `##__VA_ARGS__` 宏拼接 | 折叠表达式 |
| printf 式运行时格式 | 类型安全的编译期展开 |

新手要点：① 三个 `...` 位置分清；② 递归展开要留**空包终点**（否则编译错误）；
③ C++17 项目里优先折叠表达式，递归只留给"需要逐个处理且逻辑不同"的场景。

## HFT 关联

- **日志系统的零开销格式层**：`log(fmt, args...)` 在编译期把参数包展开成
  逐参数的序列化调用（比 iostream 快一个量级；spdlog/fmt 就是这个原理）——
  热路径日志的标配技术（→ M1 / 14-hft-engineering）
- `emplace` 系列（订单簿条目就地构造）= 可变参数模板 + placement new（19.1）
- 事件多播：`template <typename... Sinks> void multicast(const Msg& m, Sinks&... s)`
  编译期展开为对每个 sink 的直接调用——无 vector 遍历、无类型擦除

## 代码自测

**题目 1：** 这段递归 print 少了什么？

```cpp
template <typename T, typename... Rest>
void print(T&& first, Rest&&... rest) {
    std::cout << first;
    print(rest...);
}
```

<details>
<summary>参考答案</summary>

少了**空包终点**（`void print()`）。剥到最后一个参数后 `rest` 为空包，
`print()` 无参调用找不到匹配重载 → 编译错误（递归模板最深的实例化失败，
错误信息会很长——看最后一层才是关键）。

</details>

**题目 2：** `(args + ...)` 和 `(... + args)` 对 `sum("a", "b", "c")`（字符串）结果一样吗？
对 `sub(100, 10, 1)` 呢？

<details>
<summary>参考答案</summary>

字符串：结果一样（"abc"，左结合/右结合对 + 都是合法拼接，顺序不同但结果相同——
不过中间临时对象的构造顺序不同，大字符串时性能有差）。
`sub`：**不一样**——减法不满足结合律：
右折叠 `100-(10-1) = 91`，左折叠 `(100-10)-1 = 89`。
折叠方向对非结合律运算符是语义差异，不只是风格。

</details>

**题目 3：** 用逗号折叠写 `push_all(vector<T>& v, Args... xs)`，把所有参数 push 进 v。

<details>
<summary>参考答案</summary>

```cpp
template <typename T, typename... Args>
void push_all(std::vector<T>& v, Args&&... xs) {
    (v.push_back(std::forward<Args>(xs)), ...);
}
```

逗号折叠按顺序对每个 `xs` 执行 `push_back`，转发保持值类别——
一行顶过去一个递归模板。要预留容量可先 `v.reserve(v.size() + sizeof...(xs));`。

</details>
