# 4.12.2 求值顺序与括号规范

## 本节讲什么

**求值顺序**与优先级的区别；未指定顺序的陷阱；教材推荐的括号写法。

## 优先级 ≠ 求值顺序

```cpp
int f(), g();
int h = f() + g();   // 先调 f 还是先调 g？**未指定**
```

编译器可任意选择，同一表达式多次运行结果可能一致，但**不能依赖**调用顺序。

| 有保证的情况 | 说明 |
|--------------|------|
| `&&` `||` | 左侧为假/真时，右侧**不求值**（短路） |
| `?:` | 只求值被选中的分支 |
| `,` 逗号 | 左侧先于右侧 |
| 赋值 `=` | 右侧先于左侧（对操作数求值） |

位运算 `&` `|` **没有**短路顺序保证。

## 未定义行为经典坑

### 同一表达式多次修改

```cpp
int i = 0;
// i = i++;           // ❌ UB
// v[i] = i++;        // ❌ UB（下标与右侧 i 无顺序）
```

### 函数实参

```cpp
// f(++i, ++i);       // ❌ UB：哪个实参先求值未指定
```

**HFT / 工程**：热路径表达式保持简单；需要顺序就拆成多条语句。

## 括号规范（教材建议）

1. **不靠背表**解决复杂式——**多加括号**表达意图  
2. 混合算术、关系、逻辑时括号分组  
3. `?:` 与 `<<`、`=` 混用**必加括号**  
4. 位运算与逻辑混用时分组：`(a & mask) != 0`  

```cpp
// 可读性优先
bool ok = (flags & kReady) != 0 && (flags & kValid);
```

## 背诵极简版

```
优先级：谁跟谁先结合；结合律：同级从左/从右
求值顺序：操作数何时算——f()+g() 顺序不定
&& || ?: , 赋值右侧 有顺序保证；& | 无短路
同一式子多次改同一变量 → UB
复杂表达式加括号，别硬背
```

## 示例

```cpp
#include <iostream>

int main() {
    int a = 2, b = 3;
    std::cout << a + b * 4 << "\n";           // 14

    int grade = 75;
    std::cout << (grade < 60 ? "fail" : "pass") << "\n";

    int x, y, z;
    x = y = z = 0;

    return 0;
}
```

## 课后考点

1. 说出 `*` 与 `+`、`.` 与 `*`、`?:` 与 `<<` 的优先级关系  
2. 赋值、前缀/后缀 `++`、三元运算符的结合方向  
3. **优先级 vs 求值顺序**的区别  
4. `i = i++` 为何 UB  
5. 何时用括号代替记忆优先级  

## 和 C 的区别（求值顺序：C/C++ 完全一致，这是"共享的坑"）

求值顺序是 C 和 C++ **完全共享**的"坑"——优先级不决定求值顺序、`f()+g()` 未指定、`i=i++` UB、函数实参求值未指定，两边一字不差：

| 对比点 | C | C++ |
|--------|----|------|
| 优先级 ≠ 求值顺序 | ✅ 一致 | ✅ 一致 |
| `f() + g()` 求值顺序未指定 | ✅ | ✅ 一致 |
| `&&` `\|\|` 短路 | ✅ | ✅ 一致 |
| `?:` 只算选中分支 | ✅ | ✅ 一致 |
| `,` 从左到右 | ✅ | ✅ 一致 |
| 赋值右侧先于左侧 | ✅ | ✅ 一致 |
| `i = i++` UB | ✅ | ✅ 一致 |
| 函数实参求值未指定 | ✅ | ✅ 一致 |
| 位运算无短路 | ✅ | ✅ 一致 |

**给 C 程序员的关键提醒：**
1. **求值顺序坑两边一模一样**——C 学的警惕心全部迁移。`f()+g()` 顺序未指定、`i=i++` UB、函数实参求值未指定，C 和 C++ 完全一致。
2. **C++17 起对部分运算符加了顺序保证**——`<<`、`>>`、赋值的右侧、后缀 `++`/`--` 等有了更多顺序保证（C++17 之前和 C 一样未指定）。但**别依赖**，老代码可能用 C++14 编译，行为不同。
3. **HFT 热路径表达式保持简单**——需要顺序就拆成多条语句，别在复杂表达式里赌求值顺序。C 程序员的"拆语句"习惯直接用。

## 常见错误

### 1. `i = i++` 以为"先赋值再自增"

```cpp
int i = 0;
i = i++;   // ❌ UB，不是"i=0 然后 i 变 1"
```

`i = i++` 在一次表达式中对 `i` 修改两次（一次 `=`、一次 `++`），且修改无顺序保证。C 和 C++ 都是 UB。**拆成两条语句**：`int tmp = i; ++i; i = tmp;` 或干脆 `i = i + 1;`。

### 2. 函数实参求值顺序依赖

```cpp
int i = 0;
f(++i, ++i);   // ❌ UB：两个实参求值未指定顺序
```

两个 `++i` 的求值顺序未指定——可能都先算 `++i`（i 变 2，传 `f(2, 2)`），也可能分别算（传 `f(1, 2)` 或 `f(2, 1)`）。**拆开**：

```cpp
int a = ++i;
int b = ++i;
f(a, b);
```

### 3. `v[i] = i++` 下标与右侧无序

```cpp
int i = 0;
std::vector<int> v(10);
v[i] = i++;   // ❌ UB：v[i] 的下标 i 和右侧 i++ 无序
```

`v[i]` 的下标 `i`（读）和右侧 `i++`（写）之间没有顺序保证——`i++` 可能在算下标前、后、中间执行。**拆开**：`v[i] = i; ++i;`。C 里 `arr[i] = i++` 同样 UB。

## 实测：哪些顺序是标准保证的（`examples/4.12-1-precedence-evalorder.cpp`）

用带打印的探针函数观察"谁先被求值"：

| 场景 | 有无保证 | 实测 |
|---|---|---|
| `&&` / `\|\|` | ✅ 短路 + 从左到右 | 左操作数为 0 时，右操作数**根本没被求值** |
| `?:` | ✅ 只求值选中分支 | `1 ? A : B` → 只有 A 被求值 |
| `,` 逗号 | ✅ 从左到右 | step1 逗号左、step2 逗号右 |
| `<<` / `>>` | ✅ **C++17 起** | step1 左侧、step2 右侧 |
| `=`、`[]`、`->*` | ✅ **C++17 起** | 右操作数先求值，再写入/索引 |
| **函数实参** | ❌ **至今未指定** | 实测 clang 从左到右，但标准不保证 |

**最容易被误以为有保证的是函数实参**。实测本机 clang 是 `f(A, B)` 里 A 先于 B，但换个编译器、换个优化级别都可能反过来——所以**绝不能在一个实参里改、另一个实参里读同一个变量**。

### C++14 vs C++17：同一个表达式，两种命运

```cpp
int i = 0;
i = i++;      // C++14：UB（-Wunsequenced 警告）
              // C++17：定义良好 = 0（右操作数先求值并写回，再把旧值赋给 i）
```

C++17 给赋值运算符加了"右操作数 sequenced-before 左操作数的写入"这条规则，于是 `i = i++` 从 UB 变成了有定义的行为（实测结果 0）。**但注意**：这只是"定义良好"，不代表"符合你的意图"——别写这种代码。

`j++ + ++j` 在任何标准下都是 UB（实测 2，换个优化级别可能不同）。

### 三句话

1. **优先级只决定"怎么加括号"，不决定"谁先算"**——这两件事由不同规则管。
2. 有保证的只有：`&&`、`\|\|`、`?:`、`,`，以及 C++17 起的 `<<`、`>>`、`=`、`[]`、`->*`。
3. **函数实参顺序至今未指定**，别在一个实参里改、另一个实参里读同一个变量。

### 常见错误补充

4. **依赖函数实参的求值顺序**：`f(g(i), ++i)` 在任何标准下都未指定顺序（实测 clang 从左到右，但不可依赖）。**修正**：拆成两条语句。
5. **以为 C++17 修好了所有求值顺序**：C++17 只修了 `<<`/`>>`/`=`/`[]`/`->*` 等少数几个，**函数实参依然未指定**。
6. **写 `i = i++`**：C++17 起虽然定义良好（实测结果 0），但语义反直觉，读代码的人一定会卡住。

## 自测题

**1. 选择题**　`f() + g()` 中 `f` 和 `g` 的调用顺序是：

- A. `f` 先调
- B. `g` 先调
- C. 未指定，编译器决定
- D. 并行调用

<details><summary>答案</summary>

**C**。`+` 操作数的求值顺序**未指定**——编译器可以任意选 `f` 或 `g` 先调。C 和 C++ 都这样。要保证顺序用 `;` 拆开：`int a = f(); int b = g(); int h = a + b;`。若 `f`/`g` 无副作用（不修改共享状态），顺序无所谓。

</details>

**2. 判断题**　`i = i++` 在 C++ 中是合法的，结果是 `i` 自增 1。

<details><summary>答案</summary>

**错**。`i = i++` 是 **UB**（未定义行为）——一次表达式中对 `i` 修改两次（`=` 和 `++`），且修改无顺序保证。C 也是 UB。可能结果是 0、1、或任意值，甚至崩溃。**拆成两条语句**：`i = i + 1;` 或 `++i;`。

</details>

**3. 踩坑题**　下面这段代码在 C 和 C++ 中行为如何？

```cpp
int i = 0;
std::cout << i << " " << i++ << " " << i;   // 想输出 "0 0 1"
```

<details><summary>答案</summary>

**UB（未定义行为）**，C 和 C++ 都是。`<<` 的多个操作数（`i`、`i++`、`i`）求值顺序未指定——`i++` 可能在第一个 `i` 前、后、中间执行，输出不可预测。可能输出 `0 0 1`、`1 0 0`、`0 0 0`，或其他。

**修复**（拆成多条语句）：

```cpp
int i = 0;
std::cout << i << " ";   // 0
++i;
std::cout << i - 1 << " " << i;   // 0 1
```

或用 C++17 的顺序保证（`<<` 的操作数从左到右求值，但**别依赖**，老编译器不支持）。

</details>

**4. 应用题**　HFT 代码要"自增计数器并记录前一个值"，如何安全写？

<details><summary>答案</summary>

```cpp
// ❌ UB：prev 和 counter++ 无序
// int prev = counter++;

// ✅ 安全：拆成两条语句
int prev = counter;
++counter;

// ✅ 或用后置 ++ 的返回值（标准保证后置 ++ 返回原值）
int prev = counter++;   // ✅ 合法！这是单独一条语句，不是混合表达式
```

要点：
- `int prev = counter++;` 是**合法**的——后置 `++` 标准保证"返回原值，再自增"，这是一条语句不是混合表达式
- `i = i++` 才是 UB（一次表达式里 `i` 被改两次）
- 担心可读性就拆开：`int prev = counter; ++counter;`

C 程序员的 `int prev = counter++;` 习惯直接用，C 和 C++ 都合法。

</details>

**4. 判断题**：`std::cout << i << " " << ++i;` 在 C++14 和 C++17 下分别是什么行为？

<details><summary>答案</summary>

- **C++14**：**未定义行为**。`<<` 的左右操作数求值顺序未指定，可能先算 `++i` 再读 `i`，输出 `1 1` 或其他。
- **C++17**：**输出 `0 1`**。C++17 规定 `<<` 的左操作数 sequenced-before 右操作数。

**教训**：不要在同一个表达式里既修改又读取同一个变量——即使 C++17 修了 `<<`，其他运算符的求值顺序依然可能未指定。

</details>

**5. 选择题**：下面哪些**有**求值顺序保证？（多选）
- A) `a && b`
- B) `f(g(), h())` 的两个实参
- C) `a << b`
- D) `cond ? x : y`

<details><summary>答案</summary>

**A、C、D（B 没有）**。

- A ✅ `&&`/`||`：短路 + 从左到右（C++ 一直如此）。
- B ❌ **函数实参的求值顺序至今未指定**，实测 clang 从左到右，但标准不保证，换编译器可能反过来。
- C ✅ C++17 起 `<<`/`>>` 的左操作数先于右操作数（C++14 及以前没有）。
- D ✅ `?:` 保证先求值条件，再只求值被选中的分支。

</details>
