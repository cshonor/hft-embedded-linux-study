# 4.1 基础

## 本节讲什么

表达式、运算符的基本概念：一元/二元/三元运算符、操作数、结果类型、优先级与结合律、求值顺序。这些是后面 4.2–4.12 所有运算符的"地基"。

## 核心概念

| 概念 | 含义 | 例子 |
|------|------|------|
| **运算符** | 对操作数做运算的符号 | `+` `-` `*` |
| **操作数** | 运算符作用的对象 | `a + b` 中 `a`、`b` 是操作数 |
| **一元运算符** | 1 个操作数 | `-x`、`!flag`、`*p` |
| **二元运算符** | 2 个操作数 | `a + b`、`a == b` |
| **三元运算符** | 3 个操作数（C++ 唯一） | `cond ? a : b` |
| **优先级** | 谁先跟谁结合 | `a + b * c` 中 `*` 先 |
| **结合律** | 同级从左还是从右算 | `a - b - c` 从左，`a = b = c` 从右 |
| **求值顺序** | 操作数何时算 | `f() + g()` 中 f/g 调用顺序**未指定** |

## 三个核心区分（必考）

### 1. 优先级 ≠ 求值顺序

```cpp
int f(), g();
int h = f() + g();   // + 决定结合方式，但 f/g 哪个先调？未指定
```

优先级只决定"谁跟谁结合"（语法结构），**不决定运行时求值顺序**。`f() + g()` 中编译器可任意选 f 或 g 先调。

### 2. 有顺序保证的运算符

| 运算符 | 顺序保证 |
|--------|----------|
| `&&` `\|\|` | 左侧先，左侧为假/真时右侧**不求值**（短路） |
| `?:` | 条件先，只算被选中的分支 |
| `,` 逗号 | 从左到右 |
| 赋值 `=` | 右侧先于左侧 |

**位运算 `&` `|` `^`、算术 `+` `-` `*` `/` 都没有顺序保证。**

### 3. 未定义行为（UB）经典坑

```cpp
int i = 0;
// i = i++;           // ❌ UB：i 被改两次无序
// v[i] = i++;        // ❌ UB：下标 i 与右侧 i++ 无序
// f(++i, ++i);       // ❌ UB：两个实参求值无序
```

**HFT 工程建议**：热路径表达式保持简单，需要顺序就拆成多条语句。

## 示例

```cpp
#include <iostream>
int main() {
    int i = 3, j = 4;
    std::cout << i + j << " " << i * j << std::endl;   // 7 12
    return 0;
}
```

## 和 C 的区别（表达式基础：C/C++ 几乎一致，C++ 多了几个运算符）

C 程序员对运算符、优先级、结合律这些概念**已经熟得不能再熟**——C++ 继承了 C 的全部运算符语义，规则几乎一一对应：

| 对比点 | C | C++ |
|--------|----|------|
| 一元/二元/三元 | ✅ 一致 | ✅ 一致 |
| 优先级表 | C 标准定义 | C++ 几乎相同，多了 `::` `.*` `->*` |
| 结合律 | ✅ 一致 | ✅ 一致 |
| 求值顺序 | 同样未指定 `f()+g()` | 完全一致 |
| UB 坑（`i=i++`） | ✅ C 也是 UB | ✅ 一致 |
| `::` 作用域运算符 | 无 | C++ 独有（最高优先级） |
| `.*` `->*` 成员指针 | 无 | C++ 独有 |
| `typeid`/`static_cast` 等 | 无 | C++ 独有（当运算符看） |

**给 C 程序员的关键提醒：**
1. **C 学的优先级表 C++ 直接用**——99% 相同。新增的 `::`、`.*`、`->*`、`static_cast` 等优先级最高或当后缀，日常不太会和算术/逻辑运算符混淆。
2. **求值顺序坑两边一样**——`f()+g()` 在 C 和 C++ 都是未指定顺序，`i=i++` 都是 UB。C 程序员的警惕心直接迁移过来。
3. **C++ 多了"类成员访问"运算符**——`obj.member`、`ptr->member`、`obj.*pmem`、`ptr->*pmem`。前两个和 C 的 struct 成员访问一致，后两个是 C++ 独有（成员指针，第 7 章详讲）。

## 常见错误

### 1. 以为优先级决定求值顺序

```cpp
int side_effect();
int x = side_effect() + 1;   // 以为 side_effect 一定先调？
```

**错**。`+` 的优先级决定 `1` 跟 `side_effect()` 结合，但 `side_effect()` 和 `1` 的求值顺序**未指定**——编译器可能先算 `1`（没副作用，无影响）。但如果换成 `f() + g()`，f/g 哪个先调未指定，若它们有共享状态副作用就 UB。

### 2. `i = i++` 以为"先赋值再自增"

```cpp
int i = 0;
i = i++;   // ❌ UB，不是"i=0 然后 i 变 1"
```

C 程序员也踩这个——两边都是 UB。`i = i++` 在一次表达式中对 `i` 修改两次（一次 `=`、一次 `++`），且两次修改无顺序保证。**拆成两条语句**：`int tmp = i; ++i; i = tmp;` 或干脆 `i = i + 1;`。

### 3. 复杂表达式不写括号，依赖记忆优先级

```cpp
if (flags & mask == 0) { ... }   // ❌ 等价 flags & (mask == 0)，不是 (flags & mask) == 0
```

`==` 优先级高于 `&`，所以先算 `mask == 0` 得 `bool`（0 或 1），再 `flags & 0/1`。**位运算和关系混用必加括号**：`if ((flags & mask) == 0)`。C 程序员也踩这个，C++ 同样坑。

## 表达式的两个属性：类型 + 值类别（C++11 起）

每个表达式都有两个独立属性：**类型**（`int`、`int&`……）和**值类别**（lvalue / xvalue / prvalue）。类型决定"能参与什么运算"，值类别决定"**有没有身份、能不能被移动**"——后者是 C++11 移动语义的地基。

> 为什么要关心？三件事由它决定：① 能不能取地址（`&x`）；② 能绑给哪种引用（`T&` 还是 `T&&`）；③ 重载决议走拷贝还是移动。

### 实测：让编译器替你分类

用重载探测（`examples/4.1-1-value-categories.cpp`，clang 23.1.0 / `-std=c++17`）：

| 表达式 | 值类别 | 说明 |
|---|---|---|
| 变量 `x` | **lvalue** | 有名字、能取地址 |
| 字面量 `42` | **prvalue** | 纯结果，没身份 |
| `x + 1` | **prvalue** | 运算结果 |
| `std::move(x)` | **xvalue** | 将亡值，可移动 |
| 返回 `int` 的调用 | **prvalue** | 返回类型决定类别 |
| 返回 `int&` 的调用 | **lvalue** | 所以能写在赋值左边：`g_lref() = 99;`（实测生效） |
| 返回 `int&&` 的调用 | **xvalue** | `static_cast`/move 同理 |
| `"abc"`（字符串字面量） | **lvalue** | 类型是 `const char[4]`，在只读段，能取地址 |

**返回类型决定值类别**，这就是 `T&` 返回能当左值用的原因：实测 `g_lref() = 99;` 之后 `g_storage` 真的变成 99。

### `decltype` 的两条规则（最易记混的一对）

```cpp
int x = 0;
decltype(x)      // int   —— 对不带括号的"变量名"，给出它的声明类型
decltype((x))    // int&  —— 加了括号就当普通表达式，而变量作为表达式是左值 → T&
decltype("abc")  // const char(&)[4]  ← 不是 const char[4]！字符串字面量是左值
```

第三行是我实测才发现的：本以为 `decltype("abc")` 是 `const char[4]`，实际是**数组的引用**。要用数组类型本身得写 `std::remove_reference_t<decltype("abc")>`。

**1. 选择题**　C++ 中有几个三元运算符？

- A. 0
- B. 1
- C. 2
- D. 3

<details><summary>答案</summary>

**B**。C++ 唯一的三元运算符是 `?:`（条件运算符）。C 也是 1 个，完全一致。

</details>

**2. 判断题**　`f() + g()` 中，C++ 标准保证 `f()` 一定先于 `g()` 调用。

<details><summary>答案</summary>

**错**。`+` 操作数的求值顺序**未指定**——编译器可以任意选 f 或 g 先调。C 也是同样规则。要保证顺序用 `;` 拆开：`int a = f(); int b = g(); int h = a + b;`。

</details>

**3. 踩坑题**　下面这段代码在 C 和 C++ 中行为如何？

```cpp
int i = 0;
int v[10];
v[i] = i++;
```

<details><summary>答案</summary>

**UB（未定义行为）**，C 和 C++ 都是。`v[i]` 中的 `i`（左值下标）和右侧 `i++`（修改 `i`）之间没有顺序保证——`i++` 可能在算 `v[i]` 的下标前、后、中间执行，结果不可预测。

**修复**：拆成两条语句：

```cpp
v[i] = i;
++i;
```

或用范围 for / 算法库避开手写下标 + 自增的组合。

</details>

**4. 应用题**　写一个表达式判断"价格 `p` 在 `[low, high]` 区间内"，要求用短路求值避免 `low > high` 时的误判。

<details><summary>答案</summary>

```cpp
bool in_range = (low <= high) && (low <= p) && (p <= high);
```

要点：
- 用 `&&` 短路：若 `low > high`，第一个条件 false，后面不算（虽然这里算不算都行，但短路是好习惯）
- 拆成三个比较，不用 `low <= p <= high`（这是 `(low <= p) <= high` 的常见错误）
- C 程序员的 `low <= p && p <= high` 习惯直接用

**错误写法**：`low <= p <= high` —— 等价 `(low <= p) <= high`，先算 `low <= p` 得 `bool`（0/1），再和 `high` 比，逻辑错。

</details>

**5. 选择题**：以下哪些表达式是左值？（多选）
- A) `x`（`int x;`）
- B) `42`
- C) `std::move(x)`
- D) `"abc"`

<details><summary>答案</summary>

**A 和 D。**

- A ✅ 变量名，经典左值，能取地址、能绑 `int&`。
- B ❌ prvalue（没有身份）。
- C ❌ xvalue——`std::move` 的返回值是 `int&&`，是"将亡值"，能绑 `T&&` 但不是左值。
- D ✅ 字符串字面量是**左值**，类型 `const char[4]`，存在只读段，`&"abc"` 合法。

</details>

**6. 代码题**：`decltype(x)` 与 `decltype((x))` 分别得到什么？为什么？

<details><summary>答案</summary>

`decltype(x)` → `int`；`decltype((x))` → `int&`。

规则：对**不带括号的标识符**（id-expression），`decltype` 给出该标识符的**声明类型**；一旦加括号，它就变成普通表达式，而"变量作为表达式"是左值，于是按左值规则给出 `T&`。

这个差别在写泛型代码（`decltype(auto)` 返回值、`decltype` 做 traits）时经常引发"莫名其妙多了一个引用"的问题。

</details>
