# 4.7 条件运算符

## 本节讲什么

C++ **唯一三元运算符** `cond ? expr1 : expr2`。

## 规则

- 条件为 **真** → 计算并返回 `expr1` 的值  
- 条件为 **假** → 计算并返回 `expr2` 的值  
- 两分支类型须能统一（可能隐式转换）

## 嵌套

```cpp
// grade > 90 ? "A" : grade > 60 ? "B" : "C"
```

## 优先级陷阱（必考）

`?:` 优先级**很低**，与 `<<` 混用时必须加括号：

```cpp
int grade = 75;
std::cout << (grade < 60 ? "fail" : "pass");  // ✅
// std::cout << grade < 60 ? "fail" : "pass"; // ❌ 等价 (cout<<grade)<60 ? ...
```

## 和 C 的区别（条件运算符：C/C++ 完全一致）

条件运算符是 C 和 C++ **完全共享**的语法——`cond ? a : b` 的语义、优先级、结合律（右结合）、类型统一规则都一样：

| 对比点 | C | C++ |
|--------|----|------|
| `cond ? a : b` 语法 | ✅ 一致 | ✅ 一致 |
| 右结合 | ✅ | ✅ 一致 |
| 优先级很低（仅高于 `=` 和 `,`） | ✅ | ✅ 一致 |
| 两分支类型须统一 | ✅（隐式转换） | ✅ 一致，但 C++ 更严格（左值分支） |
| `?:` 可作左值 | ❌ | ✅ C++ 独有（条件表达式可作左值，见下文） |

**给 C 程序员的关键提醒：**
1. **条件运算符 99% 一样**——语法、优先级、嵌套、`<<` 混用加括号，C 学的直接用。
2. **C++ 多了"条件表达式可作左值"**——`((cond) ? a : b) = value;` 在 C++ 合法（条件为真改 `a`，假改 `b`），C 里不行。但这种写法可读性差，**不推荐**。
3. **C++ 的类型检查更严**——两分支类型不同时，C 会做隐式转换（可能丢信息），C++ 也会转但编译器警告更积极。

## 为什么需要 `?:`（动机）

`?:` 是 C++ **唯一的三元运算符**，也是唯一能在**表达式**里做二选一的构造。`if-else` 只能用在语句位置，遇到下面三种场合就写不出来：

| 场合 | `if-else` 为什么不行 | `?:` |
|------|---------------------|------|
| 初始化 | `int x; if (c) x = a; else x = b;` —— const 变量、成员初始化列表里没法这么写 | `const int x = c ? a : b;` |
| 函数实参 / 返回值 | 要先声明临时变量，多两行 | `f(c ? a : b)` |
| 模板 / constexpr 上下文 | 语句不能出现在常量表达式里 | `?:` 可以是常量表达式（C++11 起） |

**一句话**：`if-else` 控制"执行哪段代码"，`?:` 计算"取哪个值"。需要的是**值**的时候用 `?:`。

## 底层实现与实测

> 环境：Apple clang 23.1.0，arm64-apple-darwin，`-std=c++17 -O2`。可跑版本见文末例子。

### 1. 只求值选中的那个分支（和 `&&` 一样是短路的）

```cpp
int left()  { ++g_l; return 1; }
int right() { ++g_r; return 2; }

(true  ? left() : right())   // 实测：left calls=1, right calls=0
(false ? left() : right())   // 实测：left calls=0, right calls=1
```

**这是 `?:` 与函数调用的关键区别**：`pick(true, left(), right())` 里两个实参都会被求值（而且顺序未指定），`?:` 只算一个。把昂贵计算放 `?:` 分支里是安全的。

### 2. 公共类型规则：同类型不提升，不同类型才做转换

实测 `sizeof`：

| 表达式 | `sizeof` | 说明 |
|--------|----------|------|
| `c ? (short)1 : (short)2` | **2** | 两分支同类型 → 结果就是 `short`，**不整型提升** |
| `c ? (char)1 : (char)2` | **1** | 同理，不提升 |
| `c ? (short)1 : (char)2` | 4 | 类型不同 → 都提升到 `int` |
| `c ? 'a' : 1` | 4 | `char` → `int` |
| `c ? 1 : 2.5` | 8 | `int` → `double` |
| `c ? 'a' : 1.5f` | 4 | `char` → `float` |
| `c ? 1 : 2u` | 4 | `int` → `unsigned` |

**最容易错的是第一行**：很多人以为 `?:` 会像算术运算一样做整型提升，其实**只有两分支类型不同时才走 usual arithmetic conversions**。写 `auto v = c ? (short)a : (short)b;` 得到的就是 `short`。

### 3. C++ 独有：两分支都是同类型左值时，结果是左值

```cpp
int p = 5, q = 9;
(p > 0 ? p : q) = 99;    // C++ 合法，实测 p=99 q=9
```

同一行 C 代码报错：

```
error: expression is not assignable
```

条件（C++ 规则）：两个分支是**相同类型的左值** → 整个 `?:` 结果是左值，可以赋值、可以取地址。任一分支是右值（如字面量、或两分支类型不同）→ 结果是纯右值，不能赋值。

> 教材和本节都建议**别用这个特性**——`(cond ? a : b) = v` 可读性极差。知道它存在是为了读懂别人的代码，不是为了写。

### 4. 右结合：`a ? b : c ? d : e` 是 `a ? b : (c ? d : e)`

```cpp
int g = 75;
g > 90 ? 'A' : g > 60 ? 'B' : 'C'    // 实测 'B'
```

如果是左结合，`(g>90 ? 'A' : g>60) ? 'B' : 'C'` 会得 `'B'` 之外的东西（实际会因类型不匹配报错）。`?:` 与 `=`、一元运算符是少数右结合的。

### 5. 与 `if-else` 生成**完全相同**的汇编

```cpp
int tern (int x) { return x > 0 ? x : -x; }
int ifver(int x) { if (x > 0) return x; else return -x; }
```

`-O2` 下两个函数的汇编**逐字节相同**：

```asm
cmp  w0, #0
cneg w0, w0, mi     ; 负数则取负 —— 条件选择指令，无分支
ret
```

现代编译器把两者都识别成"条件选择"（`csel` / `cneg` / `csinc`），根本不生成跳转。**所以 `?:` 与 `if-else` 之间不存在性能差异**，选哪个只看可读性。

### 6. 优先级陷阱：`?:` 几乎最低，与 `<<` 混用必炸

```cpp
std::cout << grade < 60 ? "fail" : "pass";   // 解析成 (cout << grade) < 60 ? ... 
std::cout << (grade < 60 ? "fail" : "pass"); // ✅
```

`?:` 的优先级只高于 `=` 和 `,`——比 `<<`、`==`、`&&` 都低。实际上第一种写法在 C++ 里**编译期就报错**（`ostream` 没有 `<` 运算符），算是个仁慈的失败；如果换成能和整数比较的类型，就会静默算错。

## HFT / 嵌入式视角

1. **`?:` 是常量表达式，能进模板参数和数组维度**。`std::array<int, N ? N : 1>`、`if constexpr` 之前的编译期分支都靠它。`if-else` 语句在这些位置根本不合法。
2. **把昂贵分支放后面没有意义——`?:` 只算选中的那个**。但反过来，如果两分支都便宜，`?:` 与 `if-else` 性能完全相同（实测汇编一致），别为了"省一次分支"硬写 `?:`，可读性优先。
3. **类型统一规则会静默改变精度**：`c ? price_int : price_double` 会把整数价格转成 `double`。HFT 里价格常用定点整数（`int64_t` 存 1e-8 精度），一旦被 `?:` 提升到 `double` 就丢了精确性，而且**没有任何警告**。**规矩：`?:` 两分支显式同类型**，热路径上宁可写 `static_cast`。
4. **`auto` + `?:` 是陷阱**：`auto v = c ? (short)a : (short)b;` 得到 `short`（实测 sizeof=2），而 `auto v = c ? (short)a : (char)b;` 得到 `int`。加了 `auto` 之后类型完全由公共类型规则决定，改一个分支的类型就会静默改变 `v` 的类型。
5. **别用 `(cond ? a : b) = v`**。虽然 C++ 合法（实测可行），但这是"最需要读者停下来想三秒"的写法之一。改成 `if (cond) a = v; else b = v;` 零成本。

## 常见错误

### 1. `?:` 与 `<<` 混用不加括号

```cpp
std::cout << grade < 60 ? "fail" : "pass";   // ❌
```

`<<` 优先级高于 `?:`，等价 `(std::cout << grade) < 60 ? "fail" : "pass"`——先输出 `grade`，再把 `cout` 和 60 比（无意义），最后条件判断。**修复**：`std::cout << (grade < 60 ? "fail" : "pass");`。C 里 `printf` 没这个坑（`printf("%s", grade<60?"fail":"pass")`），C++ 的 `<<` 容易踩。

### 2. 嵌套 `?:` 不加括号可读性差

```cpp
grade > 90 ? "A" : grade > 60 ? "B" : "C"   // 能跑但难读
```

`?:` 右结合，所以这等价 `grade > 90 ? "A" : (grade > 60 ? "B" : "C")`，逻辑对但可读性差。**复杂条件用 `if-else`**：

```cpp
char grade_letter;
if (grade > 90) grade_letter = 'A';
else if (grade > 60) grade_letter = 'B';
else grade_letter = 'C';
```

### 3. 两分支类型不匹配导致意外转换

```cpp
auto x = cond ? 1 : 2.5;   // x 类型是 double（1 隐式转 double）
```

两分支类型不同时，编译器会做隐式转换统一——`1`（int）和 `2.5`（double）统一为 `double`。若不注意，可能丢失信息或改变类型。**显式统一**：`cond ? 1.0 : 2.5` 或 `cond ? static_cast<double>(1) : 2.5`。

## 自测题

**1. 选择题**　`?:` 运算符的结合律是：

- A. 左结合
- B. 右结合
- C. 未指定
- D. 取决于编译器

<details><summary>答案</summary>

**B**。`?:` 右结合，`a ? b : c ? d : e` 等价 `a ? b : (c ? d : e)`。C 也是右结合，完全一致。赋值 `=`、一元运算符、`?:` 是少数右结合的运算符。

</details>

**2. 判断题**　`std::cout << x < 0 ? "neg" : "pos";` 能正确打印 `x` 的正负。

<details><summary>答案</summary>

**错**。`<<` 优先级高于 `?:`，等价 `(std::cout << x) < 0 ? "neg" : "pos"`——先输出 `x`，再把 `cout` 和 0 比（无意义），最后条件判断结果总是 `"pos"` 或 `"neg"` 但没输出。**修复**：`std::cout << (x < 0 ? "neg" : "pos");`，加括号。C 里 `printf` 没这个坑。

</details>

**3. 踩坑题**　下面这段代码想根据 `flag` 选 `a` 或 `b` 赋值给 `target`，哪里有问题？

```cpp
int a = 10, b = 20;
int target = 0;
flag ? a : b = 100;   // 想把选中的变量改为 100
```

<details><summary>答案</summary>

**`flag ? a : b = 100` 在 C 里是 UB 或语义错**——`?:` 优先级高于 `=`，等价 `(flag ? a : b) = 100`。C++ 里条件表达式可作左值（C 不行），所以**C++ 能编译**（`flag` 为真改 `a`，假改 `b`），但可读性极差。

**更清晰的写法**：

```cpp
if (flag) a = 100; else b = 100;
// 或
(flag ? a : b) = 100;   // C++ 合法但不推荐
```

C 里这种写法编译错误或行为错，C++ 能过但别这么写。

</details>

**4. 应用题**　用 `?:` 写一个 `abs` 函数，返回 `x` 的绝对值。

<details><summary>答案</summary>

```cpp
int my_abs(int x) {
    return x < 0 ? -x : x;
}
```

要点：
- `x < 0` 为真返回 `-x`，假返回 `x`
- 注意 `-INT_MIN` 是 UB（见 [4.2](./4.2-算术运算符.md)），生产代码要处理
- C 等价写法一模一样：`return x < 0 ? -x : x;`

C 程序员的 `?:` 习惯直接迁移，C++ 无差异。

</details>

**5. 判断题**　`?:` 比 `if-else` 快，因为它不产生分支跳转。

<details><summary>答案</summary>

**错**。`?:` 和 `if-else` 在 `-O2` 下生成的汇编**逐字节相同**。

实测（`x > 0 ? x : -x` vs `if (x>0) return x; else return -x;`）：

```asm
cmp  w0, #0
cneg w0, w0, mi     ; 条件取负，无分支跳转
ret
```

两个函数都编译成这两条指令——编译器把两者都识别成"条件选择"，用 `csel`/`cneg`/`csinc` 这类条件选择指令实现，**根本不生成跳转**。

**结论**：选 `?:` 还是 `if-else` 只看可读性（需要"值"用 `?:`，需要"执行动作"用 `if-else`），性能上没有任何区别。真正要避免的是**不可预测的分支**（见 [5.3 条件语句](../../ch05-statements/5.3-条件语句.md) 的分支预测实测），而不是 `?:` 这个语法形式。

</details>

**6. 应用题**　HFT 订单路由代码：

```cpp
int64_t price_fixed = ...;          // 定点价格，1e-8 精度，整数存储
double  price_dbl   = ...;          // 某些通道只收 double

auto p = use_double_channel ? price_dbl : price_fixed;   // ①
send(route(cond ? 'B' : 'S'), p);                        // ②
```

指出 `auto` + `?:` 的两处风险并给出改写。

<details><summary>答案</summary>

**风险 ①**：`auto p = use_double_channel ? price_dbl : price_fixed;`
两分支类型不同（`double` 和 `int64_t`）→ 公共类型是 `double` → **`p` 永远是 `double`**。定点价格被静默转成 `double`，`int64_t` 能精确表示的大整数（> 2^53）会**丢精度**，而且编译器一声不响。

**风险 ②**：`cond ? 'B' : 'S'` 两个 `char` 分支类型相同 → 结果是 `char`（sizeof=1），这没错；但如果哪天有人把一侧改成字符串字面量 `"B"`，公共类型瞬间变成 `const char*`，`route()` 的重载决议跟着变——**改一个分支的类型会静默改变整条表达式的类型**。

**改写**：显式类型 + 拆开写，别让 `auto` 猜。

```cpp
// ① 两条通道各自明确类型，不混在一个 ?: 里
if (use_double_channel) {
    send_double(route(cond ? 'B' : 'S'), static_cast<double>(price_fixed));
} else {
    send_fixed(route(cond ? 'B' : 'S'), price_fixed);   // 保持 int64_t 精确
}

// ② 如果确实要一个值，显式声明类型，不写 auto
char side = cond ? 'B' : 'S';
const char* side_str = cond ? "B" : "S";   // 需要字符串时另写一行
```

**要点**：
- **公共类型规则**：同类型不提升（实测 `short/short` → sizeof 2），不同类型才做转换（`int/double` → sizeof 8）。
- **`auto` + `?:` 的组合最危险**——变量类型完全由分支类型决定，改一处就静默改一片。热路径上一律显式写类型，或加 `static_cast` 固定。
- 定点价格绝不进 `double`。

</details>
