# 4.4 赋值运算符

## 本节讲什么

`=` 与复合赋值 `+=` `-=` `*=` `/=` `%=` `<<=` `>>=` `&=` `^=` `|=`。

## 基本规则

1. **`=` 左侧必须是可修改左值**

```cpp
// 10 = i;           // ❌ 字面量不能当左值
const int a = 1;
// a = 2;            // ❌ const 不可改
```

2. **复合赋值**等价展开：`i += 2` → `i = i + 2`（但**不是**简单文本替换，复合形式对类类型可能更高效）

3. **赋值返回左侧对象**，支持连续赋值：

```cpp
int a, b, c;
a = b = c = 0;   // 从右向左：c=0，返回值赋给 b，再赋给 a
```

复合赋值也返回左侧引用（类类型时常返回 `*this`）。

## 和 C 的区别（赋值运算符：C/C++ 完全一致，类类型有差异）

| 对比点 | C | C++ |
|--------|----|------|
| `=` 左值要求 | ✅ 一致 | ✅ 一致 |
| 复合赋值 `+=` 等 | ✅ 一致 | ✅ 一致 |
| 连续赋值 `a=b=c=0` | ✅ 右结合 | ✅ 一致 |
| 返回左侧引用 | 返回左值（值） | 类类型返回 `*this` 引用 |
| 左值可以是… | 变量、数组元素、解引用指针 | 同 C + 类成员、`[]`/`()` 重载、迭代器解引用 |

**给 C 程序员的关键提醒：**
1. **赋值运算符语义两边一模一样**——`=`、`+=`、连续赋值、右结合，C 学的直接用。
2. **C++ 的"差异"在类类型**——`string`/`vector`/自定义类的 `=` 是**拷贝赋值运算符**（深拷贝），可能触发内存分配。C 里 `struct` 赋值是 memcpy 级（浅拷贝），C++ 里含 `string` 成员的 struct 赋值会调 `string::operator=`（可能分配堆）。
3. **C++ 类类型的 `+=` 可能比 `= ... + ...` 高效**——`s += "tail"` 原地追加，`s = s + "tail"` 可能产生临时对象。C 里没这个差异（都是字节操作）。

## 为什么赋值要"返回左侧对象"（动机）

C 里 `=` 是语句，C++ 里 `=` 是**表达式**——它有值、有类型、还能当左值。这个设计不是语法糖，它撑起了三件事：

1. **链式赋值**：`a = b = c = 0`——靠"返回左侧对象"才写得出来。
2. **条件里赋值**：`if ((fd = open(path, O_RDONLY)) < 0)`——C/C++ 系统编程的标准写法，一条语句完成"赋值 + 判错"。
3. **类类型的资源管理**：`std::string s2 = s1;` 调的是**拷贝赋值运算符**，深拷贝内部缓冲区——这是 RAII 能成立的前提（见 [ch13](../../ch13-copy-control/README.md)）。

而在 C++ 里比 C 多出来的关键点只有一个：**赋值表达式是左值**（内置类型如此，类类型靠返回 `T&` 模拟），以及 **C++17 起求值顺序有了保证**。

## 底层实现与实测

> 环境：Apple clang 23.1.0，arm64-apple-darwin，`-std=c++17 -O2`。可跑版本见文末例子。

### 1. 复合赋值不只是"少打字"：左侧只求值一次

```cpp
std::vector<int> g_v{1,2,3,4,5};
int idx() { ++g_probe; return 2; }

g_v[idx()] += 10;                  // 实测 idx() 调用 1 次，g_v[2] = 13
g_v[idx()] = g_v[idx()] + 10;      // 实测 idx() 调用 2 次，g_v[2] = 23
```

`E1 += E2` 的语义是"**E1 只求值一次**"，不是"文本替换成 `E1 = E1 + E2`"。当左值表达式带副作用（函数调用、迭代器、volatile 读）时，两者行为不同——这是很多"手写展开"重构引入 bug 的地方。

### 2. 赋值表达式是左值（C++ 有，C 没有）

```cpp
int a = 0;
(a = 5) = 7;          // C++ 合法，实测 a = 7
int x=1, y=2, z=3;
(x = y) = z;          // 实测 x=3 y=2 z=3（先 x=y 得 2，再把 z 赋进去）
```

同一行 C 代码会直接报错：

```
lv.c:1:37: error: expression is not assignable
```

原因是 C 的赋值结果是**值**（右值），C++ 的赋值结果是**左值（引用）**。这条差异平时用不上，但它决定了 `(cond ? a : b) = v`、`*p = *q = 0` 这些写法在 C++ 里成立。

### 3. C++17 起：右操作数先于左操作数求值

```cpp
int arr[4] = {10,20,30,40};
int k = 0;
arr[k] = (k = 2);     // C++17 实测：k=2, arr[2]=2（保证写 arr[2]，不是 arr[0]）
```

C++17 之前这是 UB。规则是：**`E1 = E2` 中，先求 E2（右），再求 E1（左），最后做赋值**。同一个规则让 `i = i++` 从 UB 变成良定义（`i` 初值 5 时结果仍是 5）。

> 实测提醒：clang 23.1.0 在 `-std=c++17` 下对 `arr[k] = (k = 2)` **仍然发** `-Wunsequenced` 警告（历史遗留的告警逻辑），但语义已由标准定死。看到这条警告时先确认标准版本。

### 4. 类类型 `operator=` 返回 `T&`，连续赋值零多余拷贝

```cpp
struct Probe { int v=0; Probe& operator=(int x){ v=x; return *this; } };
Probe p1,p2,p3;
p1 = p2 = p3 = 99;    // 实测 p1.v=p2.v=p3.v=99
```

内置的 `int` 连续赋值在 `-O2` 下被完全优化掉——`a = b = c = c0; g = a+b+c;` 生成的汇编只有两条指令：

```asm
add  w8, w0, w0, lsl #1   ; w8 = 3 * c0
str  w8, [x9, _g_out@PAGEOFF]
```

编译器直接把"三次赋值 + 三次加法"折叠成一条乘 3。**赋值本身零成本。**

### 5. 但 std::string 的连续赋值是三次深拷贝

```cpp
std::string s1, s2, s3;
s1 = s2 = s3 = std::string(64, 'x');   // 实测 len=64，三次 O(n) 拷贝
```

C 里 `struct` 赋值是 memcpy，C++ 里含 `std::string` 成员的结构体赋值要逐成员调 `operator=`，每个 `string` 都是一次可能的堆分配。**热路径上别在循环里做 string 连续赋值。**

### 6. `s += x` vs `s = s + x`：20 万次差 869 倍

| 写法 | 20 万次耗时 |
|------|-------------|
| `s = s + "a"` | 871.8 ms |
| `s += "a"` | 1.00 ms |

`s = s + x` 每次都：`operator+` 造临时对象（可能分配）→ `operator=` 拷回（可能再分配）。`s += x` 原地追加，容量够时零分配。配合 `reserve()` 几乎零成本。

**这是 C 程序员最该改的一个习惯**：C 里 `i = i + 2` 和 `i += 2` 完全等价（都是整数），所以很多人到 C++ 还写 `s = s + x`——对 `std::string` 这是 869 倍的差距。

## HFT / 嵌入式视角

1. **`s += x` 是唯一选择**。日志拼接、FIX 报文组装这类热路径，用 `+=` + `reserve()`；`s = s + x` 会产生 O(n) 个临时对象。实测 869 倍不是理论值，是 20 万次循环的真数字。
2. **复合赋值用于 volatile 寄存器是刚需**。`REG->CR |= (1u << 3)` 在 ARM 上是 `ldr`+`orr`+`str` 三条指令（读-改-写），而 `REG->CR = REG->CR | (1u<<3)` 会**读两次寄存器**——对"读即清"（read-to-clear）类型的状态寄存器，第二次读到的值已经变了，行为完全不同。硬件寄存器操作一律用 `|=` / `&=`。
3. **别在 `if` 里随手写赋值**。`if ((fd = open(...)) < 0)` 是合法惯用法，但 `if (x = 5)` 是 bug。规矩：赋值当条件时必须**双层括号**并开 `-Wparentheses`，clang 会对"疑似把 `==` 写成 `=`"报警。
4. **C++17 的求值顺序保证要会用于正确性，不要用于炫技**。`arr[k] = (k = 2)` 有定义了，但这种代码 review 一定被打回。拆成两行零成本。
5. **含 `std::string` / `std::vector` 成员的结构体赋值不是 memcpy**。跨核共享内存、共享内存队列里放这种对象是灾难（指针指向各自进程的堆）。共享内存里只能放 POD。

## 常见错误

### 1. `==` 写成 `=`

```cpp
if (x = 5)   // ❌ 赋值不是比较，永远为真
```

经典 C 坑，C++ 也有。**防范**：常量放左边 `if (5 == x)`，或开编译器警告。

### 2. 复合赋值对类类型理解错

```cpp
std::string s = "hello";
s = s + " world";   // 产生临时 string，可能分配
s += " world";      // 原地追加，更高效
```

C 里 `i = i + 2` 和 `i += 2` 完全等价（都是整数运算）。C++ 里对 `string`/`vector` 这类管理资源的类，`s = s + x` 可能产生临时对象（先算 `s + x` 得临时，再赋给 `s`），`s += x` 原地修改，**`+=` 通常更高效**。

### 3. 连续赋值对类类型有性能陷阱

```cpp
std::string a, b, c;
a = b = c = "init";   // 三次拷贝赋值，可能三次分配
```

C 里 `a = b = c = 0` 是整数赋值，零成本。C++ 里 `string` 的连续赋值是三次拷贝（每次可能分配）。热路径上避免这种写法，或用移动：`a = b = c = std::string("init");`（移动语义，第 13 章详讲）。

## 自测题

**1. 选择题**　`a = b = c = 0` 的求值顺序（结合律）是：

- A. 从左到右：`((a = b) = c) = 0`
- B. 从右到左：`a = (b = (c = 0))`
- C. 未指定
- D. 编译错误

<details><summary>答案</summary>

**B**。赋值运算符**右结合**，`a = b = c = 0` 等价 `a = (b = (c = 0))`。先算 `c = 0` 返回 0，再 `b = 0` 返回 0，再 `a = 0`。C 也是同样规则。

</details>

**2. 判断题**　`const int x = 5; x = 10;` 是合法的赋值。

<details><summary>答案</summary>

**错**。`x` 是 `const`，不可修改，`x = 10` 编译错误。`=` 左侧必须是**可修改左值**，`const` 变量不是可修改的。C 和 C++ 都一样。

</details>

**3. 踩坑题**　C 程序员写下面这段 C++ 代码，性能上有什么可改进？

```cpp
std::string log;
for (int i = 0; i < 10; ++i) {
    log = log + "[" + std::to_string(i) + "]";
}
```

<details><summary>答案</summary>

**每次循环产生多个临时 `string`**：`log + "["` 产生临时 1，`+ std::to_string(i)` 产生临时 2，`+ "]"` 产生临时 3，最后赋值给 `log`（可能再分配）。10 次循环约 30+ 次堆分配。

**改进**用 `+=`：

```cpp
std::string log;
log.reserve(64);   // 预留容量
for (int i = 0; i < 10; ++i) {
    log += "[";
    log += std::to_string(i);
    log += "]";
}
```

`+=` 原地追加，无临时对象，配合 `reserve` 几乎零分配。C 程序员习惯 `s = s + x`（C 里等价 `s += x`），到 C++ 的 `string` 要改用 `+=`。

</details>

**4. 应用题**　C 里写 `struct Point p1 = {1, 2}; struct Point p2; p2 = p1;` 是合法的浅拷贝。C++ 里对一个含 `std::string` 成员的 struct 做同样赋值，会发生什么？

<details><summary>答案</summary>

```cpp
struct Person {
    std::string name;
    int age;
};
Person p1{"Alice", 30};
Person p2;
p2 = p1;   // ✅ 合法，但不是浅拷贝
```

C++ 里 `p2 = p1` 调用**编译器生成的默认赋值运算符**，对每个成员赋值——`name` 调 `string::operator=`（深拷贝内部 char 数组），`age` 直接拷贝。**不是 C 的 memcpy 浅拷贝**。

- C 的 `struct` 赋值是 memcpy（含指针成员会共享堆 → 双 free 风险）
- C++ 的 `struct` 赋值是逐成员调 `operator=`（`string`/`vector` 成员会正确深拷贝）

这是 C++ 比 C 安全的地方——含资源管理成员的 struct 赋值不会出错。但如果含**裸指针**成员，C++ 默认赋值仍是浅拷贝，要按三/五法则手写（见 [3.3.5](../../ch03-strings-vectors-arrays/3.3-library-type-vector/3.3.5-拷贝移动与扩容.md)）。

</details>

**5. 选择题**　`v[idx()] += 10` 与 `v[idx()] = v[idx()] + 10`，在 `idx()` 有副作用时：

- A. 完全等价，`+=` 只是语法糖
- B. `+=` 只调用 `idx()` 一次，手写展开调用两次
- C. 都不合法
- D. 取决于编译器

<details><summary>答案</summary>

**B**。复合赋值 `E1 op= E2` 的语义是 **E1 只求值一次**，不是文本替换。

实测（`idx()` 每次自增计数器）：
- `g_v[idx()] += 10` → `idx()` 调用 **1** 次，`g_v[2] = 13`
- `g_v[idx()] = g_v[idx()] + 10` → `idx()` 调用 **2** 次，`g_v[2] = 23`

**HFT/嵌入式含义**：左值表达式带副作用时（函数调用、迭代器解引用、**volatile 硬件寄存器**），手写展开会多求值一次。对"读即清"的硬件状态寄存器，多读一次就多清一次状态——是功能性 bug，不是性能问题。

</details>

**6. 应用题**　下面这段是嵌入式驱动里控制寄存器的代码，指出问题并改写：

```cpp
#define STATUS_REG  (*(volatile uint32_t*)0x40001000)
#define CLEAR_IRQ   0x02            // 读该位即清除中断

// 想"读状态 + 清除中断位 + 再置使能位"
uint32_t s = STATUS_REG;
STATUS_REG = (STATUS_REG | CLEAR_IRQ) | ENABLE_BIT;
```

<details><summary>答案</summary>

**问题**：`STATUS_REG` 被**读了两次**，而这是一个"读即清（read-to-clear）"的状态寄存器——第二次读到的值里中断位已经被第一次读清掉了，写入的结果可能丢状态。而且赋值右侧又展开了一次 `STATUS_REG`。

**改写**：一次读、就地改、一次写，全程用复合赋值：

```cpp
uint32_t s = STATUS_REG;             // 唯一一次读（同时也清了中断位）
s |= ENABLE_BIT;                     // 就地改（不碰硬件）
STATUS_REG = s;                      // 一次写
```

或直接用复合赋值（编译器会生成 ldr/orr/str 三条指令，仍是一次读一次写）：

```cpp
STATUS_REG |= ENABLE_BIT;            // 读-改-写，只读一次
```

**要点**三条：
1. **`volatile` 的每一次出现都是一次真实访存**——`STATUS_REG = STATUS_REG | x` 里有两次读，不是一次。
2. **复合赋值保证左值只求值一次**，对 `volatile` 左值这是语义保证，不是优化。
3. 用 `1u << n` 而不是 `1 << n`（`1 << 31` 是 UB，见 [4.8](./4.8-位运算符.md)）。

</details>
