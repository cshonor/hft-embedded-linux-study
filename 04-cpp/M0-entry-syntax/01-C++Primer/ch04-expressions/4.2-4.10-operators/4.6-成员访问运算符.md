# 4.6 成员访问运算符

## 本节讲什么

`.` 点运算符与 `->` 箭头运算符；与 `*` 的优先级陷阱。

## `.` 与 `->`

| 运算符 | 作用于 | 示例 |
|--------|--------|------|
| **`.`** | 对象 / 引用 | `obj.member`、`s.size()` |
| **`->`** | 指针 | `ptr->member`，等价 `(*ptr).member` |

```cpp
#include <string>

std::string s = "test";
std::string *p = &s;

s.size();      // 点：对象
p->size();     // 箭头：指针
(*p).size();   // 与 -> 等价

// *p.size();  // ❌ . 优先级高于 *，等价 *(p.size())，编译错误
```

`string`、`vector`、自定义类成员访问都遵循此规则（见 [3.2](../../ch03-strings-vectors-arrays/3.2-library-type-string/3.2-标准库类型string.md)、[7.1 类基础](../../ch07-classes/)）。

## 为什么要两个符号（动机）

`->` 本质是 **`(*p).` 的语法糖**——先解引用再取成员。那为什么还要单独一个符号？

**① 可读性。** 嵌套访问时 `(*(*a).b).c` 这种括号地狱，`->` 让 `a->b->c` 一眼看穿。

**② 可重载性。** `.` 在 C++ 里**不能重载**（这是语言设计上的有意决定：如果 `.` 能重载，任何表达式的含义都可能被改变，语言将失去可推理性）。而 `->` **可以重载**——这正是智能指针和迭代器能"假装是指针"的原因。

```cpp
std::unique_ptr<Order> up;
up->price;    // up 不是指针，是类对象；靠 operator-> 重载"假装"成指针
```

所以规则是：**`.` 用于对象/引用（不可重载），`->` 用于指针或重载了 `operator->` 的类**。

## 底层实现与实测

> 环境：Apple clang 23.1.0，libc++，`-std=c++17 -O2`。可跑版本见文末例子。

### 1. 优先级陷阱：`*p.member` 是编译错误，不是"取成员的值"

```cpp
Order* p = new Order{};
(*p).price;   // 实测 3.5  ✅
p->price;     // 实测 3.5  ✅
*p.price;     // ❌ 编译错误
```

`.` 的优先级**高于** `*`，所以 `*p.price` 被解析成 `*(p.price)`——先对**指针** `p` 取 `price` 成员，而指针没有成员，直接编译失败。

**这个坑在 C 里同样存在**（`*p.field` 一样错），但 C++ 里踩得更多，因为类成员访问频率高得多。好消息是：**它是编译错误，不是静默错误**——编译器会拦住你。

### 2. 引用用 `.`，不是 `->`

```cpp
Order& r = *p;
r.qty;     // 实测 10  ✅
r->qty;    // ❌ 编译错误
```

| | `sizeof` |
|---|----------|
| `Order*`（指针） | **8** |
| `r`（`Order&` 引用） | **16**（= `sizeof(Order)`） |

**`sizeof(引用)` 得到的是被引用对象的大小**——这从侧面说明引用不占独立存储，它就是对象的别名。语法上像对象，所以用 `.`。

### 3. `operator->` 会**递归展开**直到拿到裸指针

这是 `->` 最反直觉的特性：如果 `operator->` 返回的还是一个类对象（而不是裸指针），编译器会**继续对它应用 `->`**。

```cpp
struct Wrapper { Order o;  Order*    operator->() { return &o; } };
struct Wrap2   { Wrapper w; Wrapper  operator->() { return w; } };

Wrapper w;  w->qty;    // 实测 10  ← 一层：返回 Order*
Wrap2  w2; w2->qty;   // 实测 10  ← 两层：返回 Wrapper，编译器继续展开
```

`w2->qty` 实际展开成 `w2.operator->().operator->()->qty`。**这让"代理对象"可以完全伪装成指针**——迭代器和智能指针就靠这个工作。

### 4. 智能指针：`->` 能用，但 `[]` 不行

```cpp
auto up = std::make_unique<std::vector<int>>(std::initializer_list<int>{1,2,3});
up->size();     // 实测 3      ✅ operator-> 返回 vector<int>*
(*up)[0];       // 实测 1      ✅ 先解引用得 vector&，再下标
(*up).at(1);    // 实测 2      ✅
up[0];          // ❌ 编译错误：unique_ptr 没有 operator[]
```

**`unique_ptr` 只重载了 `*` 和 `->`，没有 `[]`**。要下标必须先解引用。这是从裸指针迁到智能指针时最常见的卡壳点——`vector<int>*` 能写 `p[0]`（因为指针自带下标），`unique_ptr<vector<int>>` 不能。

（如果是 `unique_ptr<T[]>` 数组特化，则**有** `operator[]`。）

### 5. `->*` 和 `.*`：指向成员的指针（C++ 独有）

```cpp
auto pm = &Order::price;    // pm 是"指向 Order 的 price 成员"的指针
p->*pm;     // 实测 3.5  （等价 p->price）
o2.*pm;     // 实测 9.9  （对象用 .*）
```

| 运算符 | 左侧 | 用途 |
|--------|------|------|
| `.*` | 对象/引用 | 用成员指针访问成员 |
| `->*` | 指针 | 同上 |

C 里没有对应物（C 只有 `offsetof`）。这两个运算符的实际用途是**把"访问哪个成员"变成运行期可变的**——比如按配置字段排序、通用的序列化框架。优先级上它们**低于** `.` 和 `->`，但**高于** `*`。

### 6. 空指针 `->` 是 UB

`nullptr->member` 是 UB（大多数实现直接段错误，但标准不保证）。`unique_ptr` 也一样：

```cpp
if (up) up->size();   // 先检查
```

## HFT / 嵌入式视角

1. **`.` / `->` 的选择在 `-O2` 下零成本差异**——`p->m` 和 `(*p).m` 生成完全相同的一条 `load`。选哪个只看可读性。
2. **`*p.member` 是编译错误而不是静默错误，这点很幸运**。但要注意类似形态的坑：`*v.begin().m` 之类，括号位置错了编译器会给你一长串模板报错。
3. **`operator->` 的递归展开是"零开销代理"的基础**。想写一个带日志/校验的行情句柄，重载 `operator->` 就能让调用方毫无感知——但要注意每一次 `->` 都是一次函数调用（`-O2` 下会内联）。
4. **空指针解引用在 HFT 里是最常见的 crash 来源之一**。行情代码里从 map 查找拿到的指针、从缓存取出的对象引用，访问前一律判空；`optional<T>` / `unique_ptr` 比裸指针更能表达"可能没有"。
5. **嵌入式上没有 MMU 时，空指针 `->` 不会段错误**，而是直接读写地址 0 附近的区域（往往是中断向量表）——后果比崩溃还糟。这类平台上智能指针的判空检查尤其重要。
6. **`->*` 在通用序列化/字段映射里很有用**，但热路径上它是间接访问，无法内联——字段固定的场景直接用 `.` 更好。

## 和 C 的区别（成员访问：C/C++ 一致，C++ 多了引用和重载）

| 对比点 | C | C++ |
|--------|----|------|
| `.` 点运算符 | ✅ 一致（struct 成员） | ✅ 一致（struct/class 成员） |
| `->` 箭头运算符 | ✅ 一致（指针访问成员） | ✅ 一致 |
| `(*p).member` ≡ `p->member` | ✅ | ✅ 一致 |
| `.` 优先级高于 `*` | ✅ | ✅ 一致 |
| 作用于**引用** | C 无引用 | C++ 独有：引用用 `.`，像对象 |
| 成员函数 | C struct 无成员函数 | C++ class/struct 有成员函数 `s.size()` |
| `->` 可重载 | 不能 | 智能指针/迭代器重载 `->` |

**给 C 程序员的关键提醒：**
1. **`.` 和 `->` 的选择规则两边一致**——有对象/引用用 `.`，有指针用 `->`。C 程序员的肌肉记忆直接用。
2. **C++ 多了"引用"**——引用在语法上像对象，用 `.`：

   ```cpp
   std::string s = "hi";
   std::string& r = s;   // r 是引用，不是指针
   r.size();             // ✅ 用 .，不是 ->
   ```

   C 程序员习惯了"非对象即指针"，到 C++ 要加上"还有引用，引用用 `.`"。
3. **C++ 的 `->` 可重载**——智能指针（`unique_ptr`、`shared_ptr`）和迭代器重载了 `->`，让它们能像裸指针一样访问成员：

   ```cpp
   std::unique_ptr<std::string> up = std::make_unique<std::string>("hi");
   up->size();   // ✅ up 是智能指针，重载了 ->
   ```

   C 里 `->` 只对裸指针生效。

## 常见错误

### 1. `*p.member` 优先级错

```cpp
std::string *p = &s;
std::cout << *p.size();   // ❌ 等价 *(p.size())，p 是指针没有 size 成员
```

`.` 优先级高于 `*`，所以 `*p.size()` 先算 `p.size()`（但 `p` 是指针没有 `size` 成员，编译错误）。**正确写法**：`(*p).size()` 或 `p->size()`。C 里 `*p.field` 同样错（`p` 是 struct 指针时），规则一致。

### 2. 对引用用 `->`

```cpp
std::string s = "hi";
std::string& r = s;
r->size();   // ❌ r 是引用不是指针，编译错误
```

引用在语法上像对象，用 `.`：`r.size()`。`->` 只用于指针。C 程序员没有引用概念，容易把引用当指针用。

### 3. 智能指针忘了 `->` 能用

```cpp
std::unique_ptr<std::string> up = std::make_unique<std::string>("hi");
(*up).size();   // ✅ 能用但啰嗦
up->size();     // ✅ 推荐，智能指针重载了 ->
```

智能指针重载了 `->`，能像裸指针一样访问成员。C 程序员从裸指针迁移到智能指针时，`->` 习惯不用改。

## 自测题

**1. 选择题**　`std::string s; std::string* p = &s;` 下列哪种访问 `s.size()` 的方式**错误**？

- A. `s.size()`
- B. `p->size()`
- C. `(*p).size()`
- D. `*p.size()`

<details><summary>答案</summary>

**D**。`*p.size()` 等价 `*(p.size())`——`.` 优先级高于 `*`，先算 `p.size()`，但 `p` 是指针没有 `size` 成员，编译错误。正确写法是 `(*p).size()`（括号改变优先级）或 `p->size()`（箭头运算符）。C 里同样规则。

</details>

**2. 判断题**　`std::string& r = s; r->size();` 是合法的成员访问。

<details><summary>答案</summary>

**错**。`r` 是**引用**，不是指针，用 `.` 不用 `->`。`r->size()` 编译错误。引用在语法上像对象，`r.size()` 才对。C 程序员没有引用概念，容易把引用当指针用 `->`。

</details>

**3. 踩坑题**　C 程序员写下面这段 C++ 代码，哪里有问题？

```cpp
struct Order { int qty; double price; };
Order* p = get_order();
if (*p.price > 0) {       // 检查价格
    send_order(*p);
}
```

<details><summary>答案</summary>

**`*p.price` 优先级错**——`.` 高于 `*`，等价 `*(p.price)`，但 `p` 是指针没有 `price` 成员，编译错误。

**修复**（两种）：

```cpp
if ((*p).price > 0) { ... }   // 括号改变优先级
if (p->price > 0) { ... }     // 推荐用 ->
```

C 里 `(*p).price` 和 `p->price` 也都合法，C 程序员的习惯直接迁移——只是 C++ 里这个坑更容易踩，因为类类型成员访问更频繁。

</details>

**4. 应用题**　用智能指针 `std::unique_ptr<std::vector<int>>` 创建一个 vector，访问其 `size()` 和第一个元素。

<details><summary>答案</summary>

```cpp
#include <memory>
#include <vector>

auto uv = std::make_unique<std::vector<int>>(std::initializer_list<int>{1, 2, 3});
// 或：std::unique_ptr<std::vector<int>> uv(new std::vector<int>{1,2,3});

std::cout << uv->size() << "\n";      // 3，智能指针重载了 ->
std::cout << (*uv)[0] << "\n";        // 1，先解引用得 vector，再下标
std::cout << uv->at(1) << "\n";       // 2，-> 访问成员函数

// 注意：uv[0] 不行——uv 是智能指针不是 vector，没有下标运算符
```

要点：
- 智能指针重载 `->`，能像裸指针一样访问成员
- `(*uv)[0]` 先解引用得 vector 引用，再下标
- `uv->at(1)` 通过 `->` 访问 vector 的成员函数

C 程序员用 `malloc`/`free` 管理 `vector*`，C++ 用 `unique_ptr` 自动释放，但访问语法 `->` 一致。

</details>

**5（选择）** `auto up = std::make_unique<std::vector<int>>(...);` 之后，下面哪个**编译不过**？
- A. `up->size()`
- B. `(*up)[0]`
- C. `up[0]`

**6（踩坑）** `struct Wrap2 { Wrapper w; Wrapper operator->() { return w; } };` —— `operator->` 返回的是类对象而非指针，这能编译吗？`w2->qty` 会怎样？

**7（应用）** C++ 里 `.` 不能重载但 `->` 可以，这个不对称是语言设计上的故意选择吗？它带来什么能力？

<details><summary>参考答案</summary>

5. **C**。`unique_ptr` 只重载了 `*` 和 `->`，**没有 `operator[]`**：
   - `up->size()` 实测 3 ✅（`operator->` 返回 `vector<int>*`）
   - `(*up)[0]` 实测 1 ✅（先解引用得 `vector&`，再下标）
   - `up[0]` **编译错误**
   
   从裸指针 `vector<int>*`（可以写 `p[0]`，因为指针自带下标）迁到 `unique_ptr` 时这里最容易卡壳。
   例外：`unique_ptr<T[]>` 数组特化**有** `operator[]`。

6. **能编译，而且能正常工作**。实测 `w2->qty == 10`。
   原因是 C++ 规定：**`operator->` 返回的如果不是裸指针，编译器会继续对它应用 `->`，递归展开直到拿到裸指针**。
   `w2->qty` 实际展开成 `w2.operator->().operator->()->qty`。
   
   这个"递归展开"特性就是**零开销代理**的基础：迭代器、智能指针都靠它让调用方毫无感知地"假装是指针"。

7. **是故意的**。如果 `.` 能重载，任何 `a.b` 的含义都可能被 `a` 的类型改写，语言将失去可推理性——
   连 `x.y` 是不是真的访问成员都无法确定。标准选择了"`.` 不可重载，但可以重载 `->` 让类伪装成指针"。
   
   带来的能力：**智能指针和迭代器可以像裸指针一样用**。
   ```cpp
   std::unique_ptr<Order> up;
   up->price;    // up 是类对象，不是指针，但用起来和 Order* 一样
   for (auto it = v.begin(); it != v.end(); ++it) it->field;
   ```
   代价是：每一次 `->` 都是一次函数调用（`-O2` 下会被内联，零开销；`-O0` 下有调用开销）。

</details>
