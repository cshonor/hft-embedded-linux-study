# 7.6 类的静态成员（Static Members）

## 本节讲什么

`static` 成员：属于**整个类**而非某个对象的成员。包括静态数据成员和静态成员函数。这是 C 程序员熟悉的概念——C 用文件级 `static` 变量/函数实现类似功能，C++ 把它纳入类作用域。

## static 的三个含义：先分清这集在讲哪一个

TheCherno 的 Static 一集把 C++ 的 `static` 拆成两个含义——"类外 = 内部链接（只在本翻译单元可见）"、"类内 = 全实例共享一份"。严格说是**三个**："类外"里还藏着一种跟链接完全无关的用法：

| `static` 出现在 | 含义 | 符号表里的样子（nm 实测） | 详解 |
|----------------|------|--------------------------|------|
| 命名空间作用域（文件级"类外"） | **内部链接**：本翻译单元私有 | **小写** local（`t`/`d`），不导出 | C 书 [3.6.2 内部链接](../../../../01-c-language/02-advanced-pointers-and-memory/ch03-data/3.6-linkage/3.6.2-内部链接.md)（C/C++ 规则相同） |
| 类作用域（本节） | **全实例共享一份**，不属于任何对象 | **大写** global（`S`/`D`），导出后由链接器跨 TU 合并成一份 | 本节下文 |
| 块作用域（函数内局部 static） | **静态存储期**：只初始化一次、活到程序结束；**与链接无关** | 小写 local（`b`），符号藏在本 TU | C 书 [3.8 static 关键字](../../../../01-c-language/02-advanced-pointers-and-memory/ch03-data/3.8-static/3.8-static关键字.md)；Primer §6.1.1 |

注意中间那行和第一行的对比：**同一个 `static`，在符号表里的可见性方向正好相反**——文件级 static 是要让符号"消失"（小写 local，别的 TU 看不见），类 static 反而要导出大写 global 符号、靠链接器把各 TU 的引用合并成全程序唯一一份。实测（clang 23.1.0）：`nm` 里类静态成员是 `S __ZN3Log7s_CountE`。

> **纠正 Cherno 一句话**："类之外使用 static 意味着内部链接"不严密——函数里的局部 `static` 也在"类之外"，但它跟链接没有任何关系，管的是**存储期**。

### 实测：类 static 共享一份 + 不进 sizeof

```cpp
struct Log {
    static int s_Count;      // 类内声明
    int m_Level = 0;
};
int Log::s_Count = 0;        // 类外定义：全程序只有这一份
```

```
b.s_Count      = 42   （改的是 a 的 s_Count，b 也看到 → 共享一份）
&a.s_Count     = 0x102be0010
&b.s_Count     = 0x102be0010   （同一个地址）
sizeof(Log)    = 4    （静态成员不进任何对象，躺在 .data/.bss）
```

### 共享性 × 访问权限：两套正交的机制

static 决定的是**存储与共享**（整个继承体系一份），访问说明符决定的是**谁能用名字碰到它**——两者互不干涉。继承场景下实测（clang 23）：

```cpp
class Base {
private:
    static int s_private;      // 类级共享，但名字只对 Base 开放
protected:
    static int s_protected;
public:
    static int s_public;
    static int peek() { return s_private; }   // 类内随便用
};
class Derived : public Base {
public:
    void poke() {
        (void)s_public;        // ✅
        (void)s_protected;     // ✅
        (void)s_private;       // ❌ 报错，见下
    }
};
```

```
error: 's_private' is a private member of 'Base'
note: declared private here
```

三个结论：

1. **报错措辞证明成员真的被继承了**——报的是 `'s_private' is a private member of 'Base'`，不是 "no member named"。名字查找在继承体系里**找到了**它（Derived 的作用域里可见 Base 的所有静态成员），卡在访问检查这一关。"private 子类碰不到"≠"子类没有"。
2. **private static 是"访问权属于定义类"，不是"存储属于定义类"**——整个继承体系仍然只有这一份。派生类对象路过 `Base::peek()` 这类静态成员函数照样能读到它的值（上面的 `peek()` 就是例证）；存储从不按继承分家。
3. **想让子类用，只改访问级别，别复制一份**——`protected` 让继承体系内可用，`public` 让全局可用；无论哪种，共享的都还是同一份。典型的家族配置是：`private static` 计数器 + `protected static` 的 `nextId()` 取号器。

一句话：**static 管的是"存几份"，访问说明符管的是"谁能碰名字"；private 优先于 static——哪怕全体系共享，名字也只对定义它的类开放。**

### 追加实测：子类名限定访问 = 还是父类那份

`public static` 在继承体系里可以经任何层级的类名限定访问（`Base::s_public` / `Derived::s_public` / `GrandSon::s_public`），但它们全是**同一个实体**：

```
&Base::s_public    = 0x104eb4018
&Derived::s_public = 0x104eb4018     ← 同一地址
Derived::s_public = 99;  →  Base::s_public 也变 99
```

符号层看得更透——`.o` 里只有一套符号，全部挂在 Base 名下，Derived/GrandSon 一个符号都没有：

```
D __ZN4Base8s_publicE      ← 唯一一份，data 段
S __ZN4Base8s_nextIdE      （protected）
S __ZN4Base9s_counterE     （private！照样是外部链接）
```

两个推论：

1. **`Derived::s_public` 不是"Derived 的成员"，只是名字查找穿透继承体系的结果**——编译器沿继承链找到 Base 里的声明，剩下的和写 `Base::s_public` 一模一样。
2. **访问控制不影响链接性**——private static 的符号照样是外部链接（`nm` 大写 S，全局可见）。private 是**编译期语言层面的墙**，不是链接器层面的墙。实测（UB，但能编能跑）：

    ```cpp
    extern "C" int stolen __asm__("__ZN4Base9s_counterE");   // asm 标签直指 mangling 后的私有符号
    stolen = 100;                       // 直接改 Base 的 private s_counter
    Base::peek()                        // → 100，类内读到的也被改了
    ```

    mangling 只是顺带的门槛（你得知道符号名），不是安全机制。**安全边界止于源码**——这正是访问说明符"封装边界"的真实含义：它防的是诚实的人写错，不是防恶意的人绕过。

### 局部 static 的隐藏开销：magic statics 与 guard

C++11 起局部 static 的初始化是**线程安全**的（"magic statics"），但这不是免费的——编译器为**动态初始化**的局部 static 生成守卫变量和加锁调用。实测对比：

```cpp
int dyn_id()   { static int last = read_seed(); return ++last; }  // 动态初始化
int const_id() { static int last = 0;           return ++last; }  // 常量初始化
```

| | 守卫变量（nm 里的 `_ZGV...`） | 每次调用的守卫检查 |
|---|---|---|
| `dyn_id`（动态初始化） | **有** `b __ZGVZ6dyn_idvE4last` | **有**：`ldaprb`（load-**acquire** 原子读守卫字节）→ 未初始化走 `__cxa_guard_acquire`/`release` 慢路径 |
| `const_id`（常量初始化） | **没有** | **没有**：零开销，加载期就已初始化 |

`dyn_id` 反汇编（重定位标注后）：

```asm
ldaprb  w8, [x8]                  ; 原子读 guard（ARM64 acquire 语义）
tbz     w8, #0, <慢路径>          ; guard 已置位 → 直接用
; 慢路径：
bl      ___cxa_guard_acquire      ; 抢初始化权（带锁）
bl      __Z9read_seedv            ; 真正执行初始化
bl      ___cxa_guard_release      ; 释放，置 guard
```

> **HFT 关联**：热路径上的局部 static 有两笔账——**每次调用**都要付一次 acquire 原子读（`ldaprb`），**首次调用**还可能撞锁。能常量初始化就常量初始化（连 guard 变量都消失）；必须在热路径用动态初始化的，进热循环前先**预热**调一次。单例惯用法 `static T instance;` 吃的就是这套 guard。

### 应用实测：Meyer's Singleton（局部 static 版单例）

> 单例的另一半功夫在构造函数：把构造函数私有化（或 `= delete`），外部才无法绕过 `Get()` 自己 `new` 一个。纯静态工具类阻止实例化也是同一招——见 [7.5 私有构造函数：阻止实例化](7.5-构造函数（Constructors）.md)。

Cherno 单例集给了两版写法，对比：

| | 类静态成员指针版 | Meyer's 局部静态版 |
|---|---|---|
| 写法 | `static Singleton* s_Instance;`（类内声明） | `static Singleton instance;`（写在 `Get()` 函数体内） |
| 定义/初始化 | 类外手动写 `Singleton* Singleton::s_Instance = new ...` | 无——首次调用 `Get()` 时自动构造（懒加载） |
| 空指针风险 | 有（忘了初始化 / 提前使用就是 nullptr 解引用） | 无（返回引用，不可能为空） |
| 线程安全 | 自己管（双检锁等，易错） | **C++11 起标准保证初始化线程安全**（就是上面那套 guard） |
| 析构 | 自己管（`delete` 时机是经典难题，常干脆不删） | 自动：退出阶段经 `__cxa_atexit` 调用 |

```cpp
class Singleton {
public:
    static Singleton& Get() {
        static Singleton instance;   // 局部静态：首次调用才构造，之后永远复用同一个
        return instance;             // 返回引用，不可能为空
    }
    void Hello() {}
};
// Singleton::Get().Hello() —— Get 是静态成员函数用 :: 调用；返回引用后 . 调用普通成员函数
```

**「不在栈上」实测**（clang 23.1.0，arm64）：

```text
main 局部变量(栈)  : 0x16f446628    ← 高地址，栈区
单例 instance      : 0x1009bc060    ← 低地址，贴着镜像基址
```

`nm` 确认落在 **data 段**（`D`），旁边就是它的守卫变量：

```text
00000000000004c8 D __ZZN9Singleton3GetEvE8instance      ← instance 本体
00000000000004d0 D __ZGVZN9Singleton3GetEvE8instance    ← magic statics 守卫
```

**析构顺序灾难（static deinitialization order fiasco）实测**——这版单例的小坑：它的析构发生在程序退出阶段，如果**别的静态对象的析构函数还在用单例**，顺序可能反过来。规则是「**析构 = 构造完成的逆序**」（局部 static 首次构造时经 `__cxa_atexit` 注册析构，反汇编里能看到调用）；atexit 队列像栈，后注册的先跑：

```cpp
struct Logger {
    ~Logger() { Singleton::Get().Hello(); }  // 析构时还想用单例
};
Logger g_logger;   // 启动时构造（main 之前）→ 析构注册得早
int main() { Singleton::Get().Hello(); }     // instance 首次构造在 main 里 → 注册得晚
```

实测输出：

```text
Logger() 构造              ← 启动时
Singleton() 构造           ← main 里首次 Get()
main 结束，进入退出阶段
~Singleton() 析构          ← ★ 单例先死（后构造的先析构）
~Logger() 析构，此时还想 Singleton::Get().Hello()：
  Hello() 被调用            ← ★ 在一具"尸体"上调用：UB，这次碰巧没崩
```

注意最后一行：`Hello()` **居然正常打印了**——这正是 fiasco 最阴险的地方：UB 不等于必崩，对象内存还没被复用时"碰巧能跑"，换个平台/优化级别/构建顺序就炸。**对策**：静态对象的析构函数里不要用其他单例；日志这类"活到最后一刻"的基础设施要么故意泄漏（`new` 出来永不 `delete`，退出时让 OS 回收），要么保证它最后构造（最先析构）。

## 核心用法

### 静态数据成员

```cpp
class Account {
public:
    static double rate() { return interest_rate; }   // 静态成员函数
    static void rate(double r);                       // 静态成员函数声明
private:
    static double interest_rate;                      // 静态数据成员声明
    double amount;
};

double Account::interest_rate = 0.05;    // 定义（类外），只能一次
void Account::rate(double r) { interest_rate = r; }
```

- 静态数据成员**不属于任何对象**，所有对象共享一份
- 必须在**类外定义**（分配存储），定义只能一次
- 例外：`constexpr` 静态成员可类内初始化（C++17 起更宽松）——见下面这一节

#### 实测：`static const` 整型成员能当数组大小，非 static 一个都别想

TheCherno 视频里那段 `Entity` 代码看着平平无奇，其实同时踩住了两个边界：

```cpp
class Entity {
public:
    static const int size = 5;   // ① 全类一份  ② 编译期常量表达式
    int example[size];           // ← 只有同时满足①②才能这么写
    Entity() { for (int i = 0; i < size; i++) example[i] = 2; }
};
```

**为什么合法**：数组维度要求**编译期常量表达式**。`static const` 整型成员就地初始化后恰好满足——它既是常量，又不依赖任何对象（`static` 保证不进对象存储）。本机实测输出：

```
Entity::size      = 5
sizeof(Entity)    = 20 字节 —— 就是 5 个 int
example[0..4]     = 2 2 2 2 2
&e.size  == &e2.size ? 是（两个对象访问的是同一个实体）
```

**删掉 `static` 立刻炸**（clang 23.1.0 实测）：

```cpp
class Entity {
public:
    const int size = 5;      // 非静态成员
    int example[size];       // ❌
};
```

```
error: invalid use of non-static data member 'size'
    4 |     int example[size];
      |                 ^~~~
```

注意报错理由**不是**「值不是常量」，而是「非静态数据成员」——类体还在定义时对象尚未存在，非静态成员连被引用做维度都不配。C 程序员的直觉（「我给了它初值 5 啊」）在这里完全不适用。

**第二个坑：值有了，存储不一定有。** 就地初始化只给了值，一旦有人取它的地址就发生 odr-use：

```cpp
const int* p = &Entity::size;   // C++17 前：链接期 undefined reference
```

```
Undefined symbols for architecture arm64:
  "Entity::size", referenced from:
      _main in odr-xxxxx.o
ld: symbol(s) not found for architecture arm64
```

在 `.cpp` 里补一句 `const int Entity::size;` 即可（**不能重复写初值**）——这就是本节开头「必须在类外定义」那条规则的适用场景，只是它躲在「用着没事、一取地址就崩」的阴影里。

更省事的是直接换 `static constexpr`：C++17 起它是 **inline 变量**，上面同样的取地址代码链接通过（实测 `&size = 0x102e1ffb4`）。

> **结论**：想拿静态成员当编译期常量用（数组维度、`switch case`、模板非类型参数），一律写 **`static constexpr`**。它隐含 inline，免掉类外定义，语义也更强——`constexpr` 强制初始值必须是编译期常量。`static const int` 是 C++11 时代的写法，能用但别默认用。

**顺带把主线串起来**：这里的 `example` 是**对象内嵌数组**，跟着对象走，`sizeof(Entity)` 就是实打实的 20 字节——**它不需要 `new`，也不需要 `delete`**。对照 [12.2 直接内存管理](../ch12-dynamic-memory/12.2-直接内存管理.md)：只有 `new int[size]` 出来的才需要手动释放，也才是 HFT 里要消灭的东西。

### 静态成员函数

```cpp
// 静态成员函数
Account::rate();        // 通过类名调用（推荐）
Account acc;
acc.rate();             // 也可通过对象调用（不推荐，误导）
```
- 静态成员函数**没有 `this` 指针**（不属于某个对象）
- 因此只能访问静态成员，不能访问非静态成员
- 不能声明为 const（const 是修饰 this 的，静态函数没 this）

#### 实测：静态成员函数 = 自由函数 + 类作用域（连隐藏的 this 都没有）

7.1 实测过"普通成员函数 = 自由函数 + 隐藏 `this`"。静态成员函数更进一步——**调用约定上和自由函数逐条指令相同**（clang 23.1.0，`-target x86_64-pc-windows-msvc -O0`，MSVC ABI 用 `rcx`/`edx` 传参）：

```asm
"?LogMessage@Log@@SAXH@Z"        ; 静态成员：参数表只有 (int)，只有 ecx
	movl	%ecx, 4(%rsp)
	movl	4(%rsp), %eax
	addl	"?g@@3HA"(%rip), %eax

"?FreeFn@@YAXH@Z"                ; 自由函数：指令逐条相同
	movl	%ecx, 4(%rsp)
	movl	4(%rsp), %eax
	addl	"?g@@3HA"(%rip), %eax

"?Work@Log@@QEAAXH@Z"            ; 普通成员：rcx 收 this、edx 才是 int
	movl	%edx, 12(%rsp)
	movq	%rcx, (%rsp)         ; ← 隐藏 this 在这
```

mangled name 也印证（MSVC 编码）：`S`（static，无 this）vs `QEAA`（非静态成员，thiscall）vs `Y`（自由函数）。

调用点的对比更直白——`main` 里三种写法：

```asm
	callq	"?LogMessage@Log@@SAXH@Z"   ; Log::LogMessage(1)：不传任何对象
	callq	"?LogMessage@Log@@SAXH@Z"   ; log.LogMessage(2)：★ 同样没有 leaq 取 &log
	leaq	32(%rsp), %rcx                ; log.Work(3)：先取 &log 进 rcx（隐藏 this）
	callq	"?Work@Log@@QEAAXH@Z"
```

**`log.LogMessage(2)` 这种"通过对象调用静态函数"的写法，编译器连 `log` 的地址都懒得加载**——对象被完全无视。所以 7.6 前文"不推荐用对象调用"现在有汇编证据了：它不是风格问题，是这个对象在生成的代码里**根本不存在**。

结论：**静态成员函数 ≈ 自由函数 + 类作用域 + 访问控制**。和普通成员函数的差别不只是"少个 this"——它从 ABI 层面就不是成员函数那套东西。

#### 推论：静态成员函数的地址就是普通函数指针（回调场景的门票）

"≈ 自由函数"不只是说法，类型系统里就是事实（clang 23.1.0 本机实测）：

```cpp
struct Counter {
    static int count;
    static int getCount() { return count; }
    int getCountObj() const { return count; }
};
int Counter::count = 42;

typedef int (*GetterFn)(void);          // C 风格回调：只收普通函数指针
GetterFn p = &Counter::getCount;        // ✅ 直接赋值，不需要任何对象
// GetterFn q = &Counter::getCountObj;  // ❌ error: cannot initialize 'int (*)()'
                                        //    with 'int (C::*)()' —— 类型根本不同
```

- `&Counter::getCount` 的类型经 `static_assert(std::is_same_v<..., int(*)()>)` 验证**就是普通函数指针**；传给 `call_back(GetterFn)` 正常返回 42。
- 普通成员函数的地址是**成员指针** `int (Counter::*)() const`——另一种类型，且必须配合对象（`obj.*p`）才能调用。
- **大小都不一样**（Itanium ABI）：`sizeof(普通函数指针) = 8`，`sizeof(成员函数指针) = 16`（成员指针要额外带一份 this 调整量，用于多继承/虚继承场景）。

**HFT/嵌入式关联**：C 风格的回调注册接口（`qsort` 的比较函数、FreeRTOS 的任务入口 `void(*)(void*)`、中断向量表、各类 C API 的 callback 参数）只认普通函数指针。想把"类里的逻辑"挂进去，**静态成员函数是唯一不需要 trampoline/全局包装函数的入口**——这也是为什么嵌入式 C++ 代码里回调一律写成 `static` 成员函数，需要上下文时再通过 `void*` 参数把对象捞回来（即 C 世界的 `userdata` 惯用法）。

顺带纠一个常见表述：普通成员函数也不"属于每个对象"——代码全程序一份，不占对象存储（前文 `sizeof(Log)=4` 已证）；差别只在**调用时多收一个 this 参数**。

### 静态成员的独特用途

静态成员可以是不完全类型（如指向自身类型的指针），非静态成员不行：
```cpp
class Node {
    static Node* root;     // OK，静态成员可以是指向自身的不完全类型指针
    // Node n;             // 错误：非静态成员必须是完全类型
};
```

## 和 C 的区别

| 维度 | C | C++ |
|------|---|-----|
| 类级共享变量 | 文件级 `static` 变量（无类作用域） | ✅ 类的 static 成员 |
| 作用域 | 文件作用域（容易命名冲突） | 类作用域（`Account::rate`） |
| 访问控制 | 无（全文件可见） | 受 public/private 控制 |
| 与类关联 | 无（只是约定放一起） | ✅ 语言层面关联 |

**C 程序员的理解**：

C 里"属于某类型的共享变量"用文件级 static 实现，但它在文件作用域，不属于任何类型：
```c
/* C：文件级 static 变量模拟"类级共享" */
static double interest_rate = 0.05;   // 文件作用域，不是 Account 的一部分
double account_get_rate(void) { return interest_rate; }
```

C++ 把它纳入类作用域，有访问控制，且语义上属于类：
```cpp
// C++：static 成员属于类，有作用域和访问控制
class Account {
private:
    static double interest_rate;   // Account 的一部分，private 保护
};
```
好处：1) 命名不冲突（`Account::rate` vs `Bank::rate`）；2) 访问控制（private static 外部不可见）；3) 与类绑定，语义清晰。

## 常见错误

1. **静态成员只在类内声明，忘了类外定义**：`static double interest_rate;` 在类内声明，如果没有类外 `double Account::interest_rate = 0;`，链接时"undefined reference"。**修正**：在 .cpp 文件中定义一次。
2. **静态成员函数访问非静态成员**：`static void f() { amount = 0; }` —— 静态函数没 this，不知道是哪个对象的 amount，编译错误。**修正**：传对象引用，或把要访问的成员也设为 static。
3. **静态成员函数声明为 const**：`static void f() const;` —— const 修饰的是 this，静态函数没 this，编译错误。静态函数不能是 const。

## 自测题

**1. 选择题**：下面关于静态成员的说法正确的是？
- A) 静态数据成员每个对象各有一份
- B) 静态成员函数有 this 指针
- C) 静态数据成员必须在类外定义（constexpr 除外）
- D) 静态成员函数可以访问非静态成员

<details><summary>答案</summary>

C。静态数据成员所有对象共享一份（A 错），必须类外定义（constexpr 静态成员可类内初始化）。静态函数没 this（B 错），不能访问非静态成员（D 错）。

</details>

**2. 判断题**：`Account::rate()` 和 `acc.rate()`（acc 是对象）调用同一个静态函数，效果完全一样。

<details><summary>答案</summary>

正确。两者调用的是同一个静态成员函数，效果一样。但**推荐用 `Account::rate()`**（类名调用），因为静态函数与具体对象无关，用对象调用会误导读者以为依赖该对象。

</details>

**3. 踩坑题**：下面代码链接时报错"undefined reference to Account::count_"，为什么？
```cpp
// account.h
class Account {
public:
    Account() { ++count_; }
private:
    static int count_;    // 声明
};
// account.cpp —— 空的，没写 count_ 的定义
```

<details><summary>答案</summary>

静态数据成员在类内只是**声明**，必须在类外（通常 .cpp 文件）**定义**分配存储。缺少定义导致链接错误。**修正**：在 account.cpp 加：
```cpp
int Account::count_ = 0;   // 定义并初始化，只能一次
```
例外：C++17 起可用 `inline static int count_ = 0;` 在类内直接定义，或 `constexpr` 静态成员类内初始化。

</details>

**4. 应用题**：用静态成员实现一个"全局唯一 ID 生成器"，每次调用 `next()` 返回递增 ID。说明静态成员相比 C 全局变量的优势。

<details><summary>答案</summary>

```cpp
class IdGen {
public:
    static long next() { return ++last_; }   // 静态函数
private:
    static long last_;                        // 静态数据，类外定义
};
long IdGen::last_ = 0;                        // 类外定义

// 使用
long a = IdGen::next();   // 1
long b = IdGen::next();   // 2
```
相比 C 全局变量 `static long last = 0;`：1) `last_` 是 private，外部不能直接改（C 全局变量文件内可改）；2) `IdGen::next` 有类作用域，不会和别的 `next` 冲突；3) 语义上 ID 生成器是个概念，封装成类更清晰；4) 容易扩展为线程安全（加 mutex 成员）。C 全局变量无封装、易冲突。

</details>

**5. 分析题**：下面三处 `static`，`nm` 看到的符号绑定（大写 global / 小写 local）分别是什么？哪一处其实跟链接无关？

```cpp
static int a;                    // ① 文件作用域
struct S { static int b; };      // ② 类作用域
int S::b = 0;
int f() { static int c = 0; return ++c; }   // ③ 块作用域
```

<details><summary>答案</summary>

- **① 文件级 static → 小写 local**（内部链接）：符号不导出，其他翻译单元看不见。这是 static 的"隐藏"语义。
- **② 类 static → 大写 global**（外部链接）：符号**导出**，靠链接器把各 TU 对它的引用合并成全程序唯一一份（实测 `S __ZN1S1bE` 这种大写符号）。注意它和①**可见性方向正好相反**——同一个关键字，一个是让符号消失，一个是让符号全局唯一。
- **③ 函数内 static → 小写 local，但它跟链接无关**：它管的是**存储期**（只初始化一次、活到程序结束），不是可见性。把它和①混为一谈正是"类外 static = 内部链接"这句话不严密的地方。

附带：③若用非常量表达式初始化（如 `static int c = read_seed();`），编译器还会生成 guard 变量（`nm` 里的 `_ZGV...`）和 `__cxa_guard_acquire` 调用——C++11 起局部 static 初始化线程安全的代价；常量初始化则完全免费。

</details>

**6. 陷阱题**：下面代码能不能编译？如果能，`A::foo(a)` 之后 `a.x` 是多少？

```cpp
struct A {
    int x = 0;
    static void foo(A a) { a.x = 10; }
};
int main() { A a; A::foo(a); }
```

<details><summary>答案</summary>

**能编译**——静态成员函数没有 this，但 `a` 是**你自己传进去的参数**，通过参数访问实例成员完全合法（这正是"传对象进去"的例外用法）。

**但 `a.x` 仍是 0**——这题的第二层坑：参数是**按值传递**，`foo` 里改的是副本，调用者的 `a` 原封不动。clang 23.1.0 实测：

```text
foo(a) 之后 a.x = 0（按值传参，改的是副本）
bar(a) 之后 a.x = 20（按引用传参 A&，真改了）
```

要真改调用者的对象，参数必须是 `A&` 或 `A*`。

**第三层**（顺带测了）：把 `x` 改成 private，`static void poke(B& b) { b.secret = 99; }` 照样能编译——**访问控制是"类级别"不是"对象级别"**：`poke` 是 `B` 的成员，对 `B` 的任何对象（哪怕是参数传进来的）都有 private 访问权。实测 `poke(b)` 后 `b.secret == 99`。

一句话总结：**static 缺的只是 this，不是访问权，也不是"碰不到实例成员"——给它一个对象（引用/指针），它和成员函数一样能干。**

</details>

**8. 陷阱题**：下面五条分别能不能通过？重点是④和⑤的"会不会编过"与"会不会链接过"不是一回事。

```cpp
struct A { static const int size = 5;      int arr[size]; };   // ①
struct B { const int size = 5;             int arr[size]; };   // ②
struct C { static constexpr int size = 5;  int arr[size]; };   // ③
const int* pa = &A::size;    // ④
const int* pc = &C::size;    // ⑤
```

<details><summary>答案</summary>

- **① 能通过**。`static const` 整型就地初始化 = 编译期常量表达式，可作数组维度；`size` 不占对象存储，`sizeof(A) = 20`。
- **② 编译错误**：`error: invalid use of non-static data member 'size'`。理由不是"值不是常量"，是非静态成员在类定义期根本没有实体——初值写 5 也没用。
- **③ 能通过，且比 ① 更好**：C++17 起 `constexpr` 静态成员隐含 inline。
- **④ 编译能过，链接崩**：`Undefined symbols for architecture arm64: "A::size"`。就地初始化只给值不给存储，取地址构成 odr-use，必须在 `.cpp` 补 `const int A::size;`（**不能再写初值**）。补完就正常。（注意这是 C++17 前的写法结论；编译器对新标准下的 ODR 处理会放宽，但保留类外定义永远安全。）
- **⑤ 能通过**：`static constexpr` 是 inline 变量，无需类外定义（实测 `&C::size = 0x102e1ffb4`）。

一句话：**要么别取地址（那就怎么写都行），要么写 `static constexpr`。**

</details>

**7. 分析题**：Meyer's 单例 + 一个全局日志器，退出阶段会发生什么？

```cpp
class Singleton {
public:
    static Singleton& Get() { static Singleton instance; return instance; }
    void Hello() {}
};
struct Logger { ~Logger() { Singleton::Get().Hello(); } };
Logger g_logger;
int main() { Singleton::Get().Hello(); }
```

<details><summary>答案</summary>

**`~Logger` 运行时单例已经析构了——UB**。析构顺序 = 构造完成的逆序：`g_logger` 启动时构造（main 之前），`instance` 首次 `Get()` 才构造（main 里，更晚）；所以退出阶段 `instance` 先析构，`g_logger` 后析构，它的析构函数在"尸体"上调用 `Hello()`。

实测这个程序**没崩**、`Hello()` 正常打印——UB 不等于必崩，对象内存还没被复用时"碰巧能跑"，这正是 static deinitialization order fiasco 最难排查的原因。对策：静态对象的析构函数不依赖其他单例；必须"活到最后"的基础设施故意泄漏（`new` 出来永不 `delete`）。

机制层面：局部 static 首次构造时编译器调用 `__cxa_atexit` 注册析构（反汇编可见），atexit 队列后注册先跑——和命名空间静态对象的析构混在同一个逆序队列里。

</details>

## 可跑的例子

**`examples/7.6-static-members.cpp`** —— 全类共享一份的存活计数器。

```bash
clang++ -std=c++20 examples/7.6-static-members.cpp -o /tmp/demo && /tmp/demo
```

真实输出（节选）：

```
初始存活订单 = 0
构造 3 个后 = 3
sizeof(Order) = 8 字节 —— 只有 id_，不含静态成员
出了作用域 = 0
通过对象调用 = 1，通过类名调用 = 1
```

**看出什么了？** 三个对象出生计数到 3、析构回落到 0——活着的订单被精确追踪。而 `sizeof(Order)` 只有 8 字节：静态成员 `live_` 存在 `.data/.bss`，**不进任何对象**。

> 这就是对象池/订单管理器核心状态的实现方式：静态计数 + 对象构造析构自动增减。

**`examples/7.6-static-const-array.cpp`** —— `static const` 当数组大小 vs `static constexpr`。

```bash
clang++ -std=c++20 -Wall examples/7.6-static-const-array.cpp -o /tmp/demo && /tmp/demo
```

真实输出：

```
--- Entity（static const）---
Entity::size      = 5
sizeof(Entity)    = 20 字节 —— 就是 5 个 int
example[0..4]     = 2 2 2 2 2
&e.size  == &e2.size ? 是（两个对象访问的是同一个实体）

--- Entity2（static constexpr，C++17 推荐）---
Entity2::size     = 5
sizeof(Entity2)   = 20 字节
example[0..4]     = 3 3 3 3 3
```

**看出什么了？** 两个对象访问到的 `size` 是同一个实体，而 `sizeof` 里只有那 5 个 int——这跟上一个例子里 `sizeof(Order)` 不含静态成员是同一件事，只是这次 `size` 反过来决定了对象的大小。

> HFT 视角：这种「编译期定长、对象内嵌」的数组正是热路径想要的东西——**连续内存、cache 友好、零次 malloc**。换成 `std::vector` 就有堆分配，换成 `new int[size]` 还要手动 `delete[]` 并额外付 16 字节头部（→ [12.2](../ch12-dynamic-memory/12.2-直接内存管理.md)）。
