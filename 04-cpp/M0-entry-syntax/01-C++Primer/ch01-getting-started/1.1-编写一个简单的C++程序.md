# 1.1 编写一个简单的 C++ 程序

> 第 1 章 开始 · 下一节：[1.2 初识输入输出](./1.2-初识输入输出.md)

## 本节讲什么

介绍 C++ 程序的基本结构。每个程序必须有一个 `main` 函数——操作系统通过调用它来运行程序。函数定义包含四部分：**返回类型**、**函数名**、**形参列表**、**函数体**。`main` 返回 `0` 表示执行成功。

## 最简单的 C++ 程序

```cpp
int main() {
    return 0;  // 返回 0 表示程序正常结束
}
```

函数定义四要素：

| 部分 | 上例中的值 | 说明 |
|------|-----------|------|
| 返回类型 | `int` | `main` 必须返回 `int`，操作系统靠这个返回值判断程序是否成功 |
| 函数名 | `main` | 程序入口，必须叫 `main`（全小写） |
| 形参列表 | `()`（空） | 这里不带参数；1.1 节先用空列表，带参数的写法后面讲 |
| 函数体 | `{ return 0; }` | 花括号包起来的语句块 |

程序要运行，还需经**编译**（源码 → 目标文件）和**链接**（目标文件 → 可执行文件）两步，1.5.2 会详讲。

## 和 C 的区别

| 维度 | C | C++ | 说明 |
|------|---|-----|------|
| `main` 返回类型 | `int` | `int` | 一样，都必须是 `int` |
| 不写 `return` | 返回值未定义（UB） | **`main` 特例：默认返回 0** | C++ 只有 `main` 有这个豁免，其他函数不写 return 行为未定义 |
| `return 0` 含义 | 成功 | 成功 | 一样，非 0 通常表示错误 |
| 头文件 | `#include <stdio.h>` | `#include <iostream>` | C++ 标准库头文件不带 `.h`（下节讲） |

**一句话：** C 程序员看 C++ 的 `main` 基本无障碍，唯一的"小惊喜"是 C++ 里 `main` 不写 `return` 也合法且默认返回 0——但**别依赖这个**，养成写 `return 0;` 的习惯更安全（也方便和 C 互移植）。

## 常见错误（新手踩坑）

**错误 1：`main` 拼错或大小写不对**
```cpp
int Main() { return 0; }   // ❌ 编译能过，但链接报错：找不到 main
int main() { return 0; }   // ✅
```
**为什么：** 链接器找的是小写 `main`，`Main` 不会被当成入口。

**错误 2：返回类型写成 `void`**
```cpp
void main() { }   // ❌ C++ 标准不允许（某些编译器放行，但不可移植）
int main() { }    // ✅
```
**为什么：** C++ 标准规定 `main` 必须返回 `int`。有些老编译器（MSVC）容忍 `void main`，但换编译器就崩，别养成坏习惯。

**错误 3：忘 `#include` 就用库**
```cpp
main() { std::cout << "hi"; }  // ❌ 没包含 <iostream>
```
这节还没讲输入输出（1.2 才讲），先记住：**用任何标准库设施都要先 `#include` 对应头文件**。

## 动机：为什么 `main` 的返回值值得较真

C 程序员第一反应是"`main` 谁不会写"。但 `main` 是**程序与操作系统唯一的契约接口**——它决定了 CI 能不能判断成败、`make` 会不会继续、`&&` 链会不会断。三个真实的动机：

1. **退出码是唯一的跨进程信号**。日志可能没刷出来、stdout 可能被重定向到 /dev/null，但退出码一定会被父进程看到。HFT 的盘前检查脚本、嵌入式设备的看门狗脚本都靠它。
2. **`main` 是标准里唯一被"特殊对待"的函数**（不写 return 默认 0、不能被取地址、不能被递归调用）。理解这些特例，才知道语言在哪些地方为"程序入口"开了后门。
3. **`main` 的返回类型直接决定 ABI**。弄清"返回值怎么传出去"，后面学函数返回、结构体返回、寄存器约定都有参照。

## 底层实测：`main` 的返回值到底怎么传出去的

> 全部在本机 clang 23.1.0 / arm64-apple-darwin 实测。

### ① 退出码只保留低 8 位

| 源码里的 return | `-O2` 汇编 | shell 里 `echo $?` |
|----------------|-----------|-------------------|
| `return 0;`    | `mov w0, #0`   | `0` |
| `return 3;`    | `mov w0, #3`   | `3` |
| `return 125;`  | `mov w0, #125` | `125` |
| `return 256;`  | `mov w0, #256` | **`0`** ← 截断 |
| `return -1;`   | `mov w0, #-1`  | **`255`** |
| `std::exit(256);` | 同 `return` 路径 | **`0`** |

**关键：** 汇编里写的是 `mov w0, #256`——**编译器没有截断**。截断发生在 OS 层（POSIX 的 `waitpid` 只把状态的低 8 位交给父进程）。所以自定义错误码**只能用 0–125**：128–255 会被信号占用，`256` 看起来等于 `0`。

### ② 不写 return 的 `main`：编译器真的补了 `return 0`

```cpp
int main() { }              // -O2: mov w0, #0 ; ret
int main() { return 0; }    // -O2: mov w0, #0 ; ret
```
两份汇编 `diff` **完全相同**。C++ 标准规定：控制流走到 `main` 的函数体结尾等价于 `return 0;`——而且这是 `main` **独有**的豁免，其它函数漏 `return` 仍是 UB。仍然建议显式写 `return 0;`：可移植、意图清晰、和 C 互移植时不会被 C89 咬到。

### ③ `main` 不能"被使用"——标准禁止，clang 当扩展放行

```cpp
int main() { if (0) main(); return 0; }        // 递归调用 main
int main() { auto p = &main; (void)p; return 0; }  // 取 main 地址
```
默认编译**不报错**（clang 扩展）。加上 `-pedantic-errors`：

```
error: referring to 'main' within an expression is a Clang extension [-Wmain]
```

标准 [basic.start.main] 的原话是 `The function main shall not be used within a program`。**别这么写**——换编译器就是硬错误。

### ④ 非法的 `main` 写法：实测报错原文

| 写法 | 结果 |
|------|------|
| `void main() { }` | `error: 'main' must return 'int'` |
| `long main() { return 0; }` | `error: 'main' must return 'int'` |
| `int Main() { return 0; }` | 编译通过，**链接**报错：`Undefined symbols for architecture arm64: "_main", referenced from: implicit entry/start for main executable` |

`Main` 那个尤其阴险：错误发生在**链接期**，源码里看不出问题。clang 还会贴心地提示 `^~~~ int`，意思是"你是不是想写 int"。

### ⑤ 头文件不是免费的

| 程序 | 二进制大小 | 编译耗时（3 次取最小） | `#include` 展开行数 |
|------|-----------|---------------------|-------------------|
| 空 `int main(){return 0;}` | 16 824 B | 0.12 s | 8 行（空） |
| 用 `<cstdio>` + `printf` | 49 960 B | 0.12 s | 699 行 |
| 用 `<iostream>` + `cout` | 52 536 B | **0.32 s** | **31 441 行** |

`<iostream>` 展开后 **31 441 行**，是 `<cstdio>` 的 **45 倍**；编译耗时约 **2.7 倍**。这在嵌入式交叉编译、大型项目增量编译上是实打实的成本——也是后面学"头文件分离""前置声明"的动机。

## HFT / 嵌入式视角

1. **退出码是运维契约**。盘前检查程序（校验行情源连通性、检查磁盘水位、核对合约表版本）**必须**用不同的非 0 码区分失败原因，让上游脚本能分流处理；只用 0/1 会让排障退化成"看日志猜"。
2. **退出码取值只用 0–125**。`return 256` 静默变成 0，是最难查的一类 bug——脚本以为成功了。
3. **不要用 `exit()` 乱杀进程**。`std::exit` 不析构局部对象（只析构静态对象），HFT 程序里未落盘的成交回报会丢。要走正常 `return` 路径，或至少在 `exit` 前手动 flush + 落盘。
4. **嵌入式上二进制体积直接是钱**。空程序 16 KB、加个 `iostream` 就 50 KB——在片上 Flash 只有几百 KB 的 MCU 上，`iostream` 基本不可用，得走 `printf` 精简实现或直接写 UART。这也是为什么嵌入式 C++ 常用 `-fno-exceptions -fno-rtti` 且不碰 `<iostream>`。
5. **`main` 之前还有启动代码**。用 `otool -l` 看可执行文件能看到 `LC_MAIN`（entryoff + stacksize），真正被操作系统调用的是 CRT 的入口，`main` 是被它调起来的——这解释了为什么全局对象的构造发生在 `main` 之前。

## 自测题

1. C++ 程序的入口函数必须叫什么？返回类型必须是什么？
2. `main` 函数不写 `return` 语句，程序行为是什么？这和 C 有什么不同？
3. 下面哪个能作为合法的 C++ 程序入口？为什么？
```cpp
(a) int main() { return 0; }
(b) void main() { }
(c) int Main() { return 0; }
```
4. `return 0;` 和 `return 1;` 对操作系统意味着什么？

<details>
<summary>参考答案</summary>

1. 入口函数必须叫 **`main`（全小写）**，返回类型必须是 **`int`**。操作系统/运行时只认这一个符号：`main` 由启动代码调用，其返回值作为进程退出码交回父进程。函数名外的四要素里，形参列表允许 `()` 或 `(int argc, char* argv[])`，但名字和返回类型没有商量余地。

2. C++：`main` 是 **唯一豁免** 的函数——控制流走到函数体结尾的 `}` 等价于 `return 0;`（标准规定，其它函数漏 `return` 仍是未定义行为）。C：C89/C90 下走到 `main` 结尾返回的是 **未定义值**（实现通常把某个寄存器的残留值当退出码，于是出现"运行结果随机"的现象）；**C99 起（5.1.2.2.3）C 也规定等价于 `return 0`**。所以真正的 C/C++ 差异只存在于 C89 及更早。仍然建议显式写 `return 0;`：可移植、意图清晰。

3. 只有 **(a)** 能作为入口。
   - (a) `int main() { return 0; }` ✅ 名字、返回类型都符合标准。
   - (b) `void main() { }` ❌ 返回类型必须是 `int`；`void main()` 只是某些实现（如 MSVC）的扩展，换编译器就报错，不可移植。
   - (c) `int Main() { return 0; }` ❌ C++ **大小写敏感**，`Main` 是一个普通函数，链接器找不到 `main` 符号 → 链接期报 "undefined reference to main"。

4. 返回值就是进程的**退出状态码（exit status）**：`0` 表示成功，非 `0` 表示失败（具体非零值含义由程序自己定义，如 `1`＝通用错误、`2`＝用法错误）。父进程/shell 用它决定成败：`$?` 查看，`&&`/`||`、`set -e`、make/CI 都据此判断。注意 POSIX 上只有**低 8 位**会被传出去（`exit(256)` 看起来等于 `exit(0)`），所以自定义错误码建议只用 0–125。

</details>

**5（踩坑·高价值）** 下面程序的退出码是多少？
```cpp
int main() { return 256; }
```
- A. 256
- B. 0
- C. 未定义

**6（判断）** `int main() { }` 和 `int main() { return 0; }` 生成的汇编完全相同。

**7（应用）** 你在写一个盘前检查程序，要区分"行情源连不上""磁盘水位过高""合约表版本不匹配"三种失败。退出码怎么定？为什么不能用 256、257、258？

<details><summary>参考答案</summary>

5. **B**。编译出的汇编确实是 `mov w0, #256`，但 POSIX 只把进程退出状态的**低 8 位**交给父进程，`256 & 0xFF == 0`。所以 shell 里 `echo $?` 得到 **0**——看起来"成功了"。这就是为什么自定义错误码只能用 **0–125**。

6. **对**。`-O2` 下两者汇编都是 `mov w0, #0 ; ret`，`diff` 完全相同。C++ 标准规定控制流走到 `main` 函数体结尾等价于 `return 0;`，且这是 `main` **独有**的豁免（其它函数漏 return 是 UB）。仍然建议显式写：可移植、意图清晰。

7. 用 **1 / 2 / 3**（或 1/2/3 之外的任意 0–125 内的不同值），并在文档里写明映射；成功返回 **0**。不能用 256/257/258 是因为退出码只有低 8 位有效——`256→0`、`257→1`、`258→2`，会和别的错误码撞车，而且 `256` 会被当成"成功"。另外要避开 **128–255**：这一段通常被 shell 用来表示"被信号杀死"（128+信号号），比如 137 = 被 SIGKILL。同理，也不要用 `std::exit` 直接退——它不析构局部对象，未落盘的回报会丢。

</details>

## 可跑例子

```bash
# 1.1-1  main 返回值、退出码截断、main 的三条禁令
clang++ -std=c++17 -O2 -Wall 1.1-1-main-return.cpp -o m

./m          ; echo "exit=$?"   # → 0   （源码里写的是 return 256）
./m x        ; echo "exit=$?"   # → 125

# 看不写 return 与写 return 0 的汇编是否相同
clang++ -std=c++17 -O2 -S 1.1-1-main-return.cpp -o m.s

# 验证 main 不能被"使用"（调用 / 取地址）
clang++ -std=c++17 -pedantic-errors 1.1-1-main-return.cpp -o /dev/null
```

例子文件里以注释形式保留了 `void main()` / `Main()` / 递归 `main` / 取 `&main` 四种非法写法的**实测报错原文**，取消注释即可逐个复现。
