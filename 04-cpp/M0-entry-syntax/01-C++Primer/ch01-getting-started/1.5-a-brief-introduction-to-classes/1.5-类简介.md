# 1.5 类简介

> 第 1 章 · 上一节：[1.4 控制流](../1.4-控制流.md) · 下一节：[1.6 书店程序](../1.6-书店程序.md)

## 本节讲什么

引入 C++ 最重要特性之一的**类（class）**。本节先用书中预设好的 `Sales_item` 类，让你**只管用、不管造**——学会定义对象、用 `.` 调成员函数、用运算符操作对象。类的定义留到后面章节。

## 核心概念

| 概念 | 例子 | 说明 |
|------|------|------|
| 定义对象 | `Sales_item item;` | 创建一个"盒子" |
| 调成员函数 | `item.isbn()` | 用 `.` 取对象里的方法/数据 |
| 运算符操作 | `cin >> item` / `item + item2` | 类可以重载运算符 |

## 和 C 的区别（这是重点）

这是 C 转 C++ 的**第一个大门槛**：

| 对比点 | C | C++ |
|--------|---|-----|
| 自定义类型 | `struct` 只装数据 | `class`/`struct` 装数据 **+ 函数** |
| 调"方法" | 函数传结构体指针：`isbn(&item)` | 对象直接调：`item.isbn()` |
| 访问控制 | 无（全公开） | `public`/`private` 控制可见性 |
| 运算符 | 不能让 `+` 作用于自定义类型 | 重载 `+` 后 `item + item2` 合法 |

**一句话：** C 的 `struct` 是"数据包"，C++ 的 `class` 是"数据包 + 工具包"——数据和行为绑在一起，还能控制谁能碰。

```c
/* C 写法：数据归数据，函数归函数 */
struct Book { char isbn[16]; int sold; double revenue; };
char* get_isbn(struct Book* b) { return b->isbn; }  // 函数操作结构体
```
```cpp
// C++ 写法：数据和函数绑在一起
class Sales_item {
public:
    std::string isbn() const { return bookNo; }  // 方法内嵌在类里
private:
    std::string bookNo;
};
Sales_item item;
item.isbn();  // 对象.方法()，不用传 this
```

## 动机：为什么 C++ 要把函数塞进 struct 里

C 程序员的第一反应是"把函数放进结构体有什么用？不过是 `isbn(&item)` 换成 `item.isbn()` 的语法糖"。**如果只是语法糖，不值得发明一整个语言**。真正的动机是三条：

1. **不变式（invariant）可以被强制**。C 的 `struct` 全公开，任何人都能 `order.price = -100`；C++ 用 `private` 把字段藏起来，只暴露 `set_price()`——校验逻辑写在类里，**没人能绕过**。这是 C++ 相对 C 最本质的增值，语法糖只是附赠。
2. **名字不污染全局**。`isbn()` 在类里，就不会和别人的 `isbn()` 撞；C 里得靠 `sales_item_isbn()` 这种前缀约定。
3. **接口和实现可以分离**。`public` 部分是契约，`private` 部分可以随便改而不影响调用方（1.5.1 详讲）。

**关键认知：`item.isbn()` 在机器层面确实就是 `isbn(&item)`**——下面用汇编证明。所以"面向对象"在这里**零运行时开销**，你买的单只是编译期的组织方式，不是运行时的跳转表。

## 底层实测：`item.isbn()` 真的等于 `isbn(&item)` 吗

> 全部在本机 clang 23.1.0 / arm64 实测。

### ① 汇编级证明：成员函数 = 普通函数 + 隐式 `this` 参数

```cpp
struct Box { long a, b, c; };

// C 风格：显式传指针
long free_sum(const Box* p) { return p->a + p->b + p->c; }

// C++ 风格：成员函数
struct BoxCxx {
    long a, b, c;
    long sum() const { return a + b + c; }
};
long call_member(const BoxCxx* p) { return p->sum(); }
```

`clang++ -std=c++17 -O1 -S` 后对比两个函数体：

```asm
; free_sum(const Box*)          ; call_member(const BoxCxx*)  ← 成员函数已内联进来
    ldp  x8, x9, [x0]               ldp  x8, x9, [x0]
    ldr  x10, [x0, #16]             ldr  x10, [x0, #16]
    add  x8, x9, x8                 add  x8, x9, x8
    add  x0, x8, x10                add  x0, x8, x10
    ret                             ret
```

**逐条指令完全相同**。`diff` 结果为空。唯一的差别是**符号名**：

| 写法 | mangled name | `c++filt` 还原 |
|------|-------------|---------------|
| 自由函数 | `_Z8free_sumPK3Box` | `free_sum(Box const*)` |
| 成员函数 | `_ZNK3Box3sumEv` | `Box::sum() const` |

注意成员函数 mangled name 里的 `K`（const）和结尾的 `v`（void 参数列表）——**`this` 不出现在参数列表里，它是隐式的**，但 name mangling 把 `const` 也编进去了，因为 `const` 成员函数和同名非 `const` 成员函数是两个不同的重载。

### ② `this` 就是对象的地址

```cpp
Tick t{10.5, 100};
std::cout << &t << "\n" << t.me() << "\n";   // me() 里 return this;
```

实测输出：

```
  &t     = 0x16d89ac40
  t.me() = 0x16d89ac40
  this == &t ? 是
```

所以 `this` **不是**"指向某个隐藏结构的指针"，就是 `&对象` 本身，通过 `x0`（arm64 第一个参数寄存器）传进去——和 `isbn(&item)` 里传 `&item` 完全一样。

### ③ 成员函数不占对象空间

| 类型 | 内容 | `sizeof` |
|------|------|---------|
| `struct Empty { }` | 空类 | **1** |
| `struct DataOnly { double px; int qty; }` | 只有 2 个字段 | 16 |
| `struct WithMethods { 同上 + 3 个方法 }` | 字段 + 方法 | **16**（不变） |
| `struct WithVirtual { 同上 + 虚函数 }` | 字段 + 虚析构 | **24** |

三点结论：
- **非虚成员函数零空间开销**——加 3 个方法 `sizeof` 不变，因为方法不在对象里，它们在代码段，靠 `this` 找到数据。
- **空类是 1 字节不是 0**——保证 `&a != &b`（两个不同对象必须有不同地址），否则数组、指针算术都会崩。
- **虚函数才加开销**：arm64 上多 8 字节的 vptr（虚表指针）。所以"面向对象 = 慢"这句话**只对虚函数成立**，对普通成员函数完全不成立。

### ④ `class` vs `struct`：只有默认访问权限不同

| | `class` | `struct` |
|---|---------|----------|
| 默认成员访问 | `private` | `public` |
| 默认继承方式 | `private` | `public` |
| 其它（能有方法、能继承、能多态） | 完全相同 | 完全相同 |

C 程序员用 `struct` 完全没问题（而且默认 public 更贴近 C 的直觉）；约定俗成是：**纯数据用 `struct`，有不变式要维护的用 `class`**。

## HFT / 嵌入式视角

1. **成员函数零开销，可以放心用**。在行情回调里写 `tick.mid()` 而不是 `mid(&tick)`，**汇编完全一致**，但可读性和不变式保护是白赚的。不要为了"性能"把 C++ 写成带类的 C。
2. **`private` 是不变式的唯一强制执行点**。订单的 `price` 必须 > 0、`qty` 必须 ≤ 上限——这些约束写在 `set_price()` 里，外部绕不过去。C 里只能靠"约定 + review"，而约定在 6 个月后的夜班改代码时一定会破。
3. **谨慎对待虚函数**。vptr 让对象从 16 字节变 24 字节（+50%），在 L1 cache 里塞行情快照时这是真金白银；而且虚调用是一次间接跳转，分支预测失败一次约 15~20 ns——对纳秒级策略是可见的。策略多态尽量用模板（编译期）或 `if constexpr`，把虚函数留给真正需要运行期动态分派的场合（如插件式风控）。
4. **空类 1 字节在嵌入式上会累积**。`struct Tag {};` 作为成员嵌进别的结构体，会因为对齐被放大（比如嵌进 8 字节对齐的结构体，可能占 8 字节）。确认真的不需要区分身份时，用 `[[no_unique_address]]`（C++20）或干脆别定义空类。
5. **`this` 存在的意义**：解释了为什么成员函数里可以直接写 `px`（等价于 `this->px`），也解释了为什么静态成员函数里不能写——**静态成员函数没有 `this`**。

## 自测题（导览）

**1（概念）** C 的 `struct` 和 C++ 的 `class` 最本质的区别是什么？

**2（判断）** `item.isbn()` 和 C 里的 `isbn(&item)` 本质做的是同一件事。

<details><summary>参考答案</summary>
1. C 的 `struct` 只有数据成员；C++ 的 `class`（和 `struct`）除了数据，还能有**成员函数**和**访问控制**（public/private）。数据和行为绑在一起。
2. 对。`item.isbn()` 在底层就是把 `item` 的地址作为隐式 `this` 指针传给 `isbn` 函数，和 C 的 `isbn(&item)` 本质相同。C++ 只是把这个"传指针"的动作藏进了语法糖。
</details>

**3（踩坑·高价值）** 下面两个类型，`sizeof` 分别是多少？
```cpp
struct A { double px; int qty; };
struct B { double px; int qty;
           double price() const { return px; }
           int    size()  const { return qty; }
           void   set(double p, int q) { px = p; qty = q; } };
```
- A. `A` = 16，`B` = 40（多了 3 个函数指针）
- B. `A` = 16，`B` = 16
- C. 取决于编译器

**4（判断）** C++ 里的 `struct` 不能有成员函数，只有 `class` 可以。

**5（应用）** 你有一个 `Order` 结构，要求 `price > 0` 且 `qty <= 10000`。用 C 和 C++ 分别怎么写？为什么 C++ 的写法能真正阻止非法值？

<details><summary>参考答案</summary>

3. **B**。两者都是 **16 字节**。非虚成员函数**不在对象里**——它们在代码段，靠隐式 `this` 找到数据。实测：`sizeof(DataOnly) == sizeof(WithMethods) == 16`。只有引入虚函数才会变大（实测 `WithVirtual == 24`，多一个 8 字节 vptr）。另外 `sizeof(空类) == 1`（不是 0，保证不同对象地址不同）。

4. **错**。`class` 和 `struct` 在 C++ 里**唯一**的区别是默认访问权限（`class` 默认 `private`，`struct` 默认 `public`）和默认继承方式。`struct` 一样可以有成员函数、构造/析构、继承、虚函数。约定是：纯数据用 `struct`，有不变式要维护的用 `class`。

5. C 写法（靠约定）：
   ```c
   struct Order { double price; int qty; };
   /* 文档写：调用前必须校验！但没人强制执行 */
   ```
   C++ 写法（靠编译器强制执行）：
   ```cpp
   class Order {
   public:
       bool set_price(double p) { if (p <= 0) return false; price_ = p; return true; }
       bool set_qty(int q)      { if (q > 10000) return false; qty_ = q; return true; }
       double price() const { return price_; }
       int    qty()   const { return qty_; }
   private:
       double price_ = 0;   // 外部写不到
       int    qty_   = 0;
   };
   ```
   关键差别：C 里 `order.price = -1;` 是**合法代码**，只能靠 review 发现；C++ 里 `order.price_ = -1;` 是**编译错误**，物理上不可绕过。不变式从"约定"升级成"编译期保证"，这是 `class` 相对 `struct` 的本质增值——而运行时开销为零（成员函数与普通函数汇编一致）。

</details>
