# 1.3 注释简介

> 第 1 章 · 上一节：[1.2 初识输入输出](./1.2-初识输入输出.md) · 下一节：[1.4 控制流](./1.4-控制流.md)

## 本节讲什么

C++ 的两种注释写法：单行 `//` 和多行 `/* */`。重点是一个坑——`/* */` 不能嵌套，这是 C/C++ 共有的经典陷阱。

## 核心用法

| 写法 | 作用 | 适用场景 |
|------|------|----------|
| `// 注释` | 从 `//` 到行尾 | 单行说明、临时禁用一行代码 |
| `/* 注释 */` | 跨多行 | 模块/函数头说明、大段注释 |

```cpp
// 读取委托价格和数量           ← 单行注释
int qty = 0;

/*
 * 委托处理模块                  ← 多行注释
 * 负责校验、下单、回报
 */
```

**编译器完全忽略注释**——注释里的代码不会执行，纯粹是给人看的。

## 和 C 的区别

**几乎没有区别。** 这是 C 和 C++ 高度一致的地方：

| 对比点 | C（C89） | C（C99 起） | C++ |
|--------|----------|-------------|-----|
| `/* */` | ✅ | ✅ | ✅ |
| `//` | ❌ 没有 | ✅ 加入 | ✅ 一直有 |
| 嵌套 `/* */` | ❌ 禁止 | ❌ 禁止 | ❌ 禁止 |

**给 C 程序员的提醒：** 如果你以前写 C89，`//` 在老 C 里不合法；但 C++ 一直支持，放心用。现代 C 项目（C99+）也都支持 `//` 了。

## 常见错误

**1. `/* */` 嵌套陷阱（最经典）**
```cpp
/*
 * 外层注释开始
 * /* 内层注释开始 */    ← 这里第一个 */ 就把外层注释关掉了！
 * 外层注释还没结束
 */                        ← 这个 */ 成了"悬空"的，编译报错
```
规则：**第一个 `*/` 就关闭整个注释**，不管你开了几个 `/*`。想临时注释掉一大段含 `/* */` 的代码，用 `#if 0 ... #endif`（预处理指令，不受注释规则限制）：
```cpp
#if 0
/* 这里的注释不会被误关闭 */
void old_code() { ... }
#endif
```

**2. `//` 注释不能跨行**
```cpp
// 这是第一行
    这是第二行    ← 这行不是注释，编译报错
```
`//` 只管到行尾。要跨行用 `//` 得每行都写，或用 `/* */`。

**3. 注释写在字符串里失效**
```cpp
std::cout << "价格 // 不是注释";  // 这里的 // 才是注释
```
字符串字面量里的 `//`、`/*` 都是普通字符，注释规则不生效。

## 动机：注释规则看着最无聊，却有三个真会坑人的地方

注释是全书最简单的一节，但**它藏着 C/C++ 翻译阶段的顺序问题**。值得较真的三个动机：

1. **注释不是"被删除"，而是"被替换成一个空格"**。这一条决定了 `a/**/b` 到底是一个 token 还是两个——写宏、写代码生成器时会踩。
2. **行拼接（翻译阶段 2）发生在注释处理（阶段 3）之前**。所以 `//` 末尾一个不起眼的反斜杠，会把下一行代码整个吃掉，而且**编译器不报"注释错误"**，只报"某个变量未声明"——错误信息离真凶很远。
3. **`/* */` 不能嵌套**导致"临时注释掉一大段代码"这个最常用的操作不可靠，必须用 `#if 0`。

## 底层实测：三个陷阱的复现与报错原文

> 全部在本机 clang 23.1.0 实测。

### 陷阱 ①：`/* */` 不能嵌套——第一个 `*/` 就关掉整个注释

```cpp
#include <iostream>
/* 外层注释开始
 * /* 内层注释开始 */
 * 外层注释还没结束
 */
int main() { std::cout << "ok\n"; return 0; }
```

实测报错：

```
nest.cpp:4:4: warning: '/*' within block comment [-Wcomment]
    4 |  * /* 内层注释开始 */
      |    ^
nest.cpp:5:4: error: a type specifier is required for all declarations
    5 |  * 外层注释还没结束
      |    ^
nest.cpp:5:28: error: expected ';' after top level declarator
```

**注意报错位置**：warning 在第 4 行（内层 `/*`），error 在第 5 行——因为第 4 行的 `*/` 已经把注释关掉了，第 5 行的 `外层注释还没结束` 变成了**代码**。而最后那个 `*/` 成了悬空符号。

**安全做法**：想整段禁用代码，用预处理指令，它不受注释规则限制：

```cpp
#if 0
/* 这里的注释不会被误关闭 */
void old_code() { ... }
#endif
```

### 陷阱 ②：`//` 末尾的反斜杠会吃掉下一行

```cpp
int main() {
    // 这行注释末尾有个反斜杠 \
    int x = 42;
    std::cout << "x=" << x << "\n";
    return 0;
}
```

实测：

```
c2.cpp:5:26: error: use of undeclared identifier 'x'
    5 |     std::cout << "x=" << x << "\n";
```

**`int x = 42;` 整行被吃掉了**。原因是 C/C++ 的翻译阶段顺序：

| 阶段 | 做什么 |
|------|--------|
| 1 | 字符映射（trigraph 也在这一步，C++17 已移除） |
| **2** | **行拼接：反斜杠 + 换行 → 删除** |
| **3** | 分解成 token，**注释替换为一个空格** |
| 4 | 预处理（`#include` / `#define`） |

**拼接发生在注释处理之前**，所以 `//` 后面的 `\` 先把下一行拼了上来，然后整块被当注释扔掉。用 `-E` 看预处理结果最直观——那两行会变成空行。

### 陷阱 ③：注释是"一个空格"，不是"被删除"

```cpp
int a = 1, b = 2;
int ab = a/**/b;        // 展开后是 `int ab = a b ;`
```

实测：`error: expected ';' at end of declaration`（`^` 指向 `a` 后面）。**`a` 和 `b` 没有粘成 `ab`**——注释替换成的那个空格把它们分成了两个 token。

正面利用：字符串字面量的相邻拼接**不受影响**：

```cpp
const char* s = "he"/*这句注释不影响*/"llo";   // → "hello"，sizeof == 6
int sum = a /*加号左*/ + /*加号右*/ b;        // → 3
```

### 陷阱 ④：`??/` 三字符词（trigraph）——C++17 之前同样会吃掉下一行

```cpp
// 注释末尾的 ??/ 在 C++11 下等于反斜杠 ??/
std::cout << "这行被吃了吗\n";
```

| 编译标准 | 运行结果 |
|---------|---------|
| `-std=c++11` | **什么都不输出**（下一行被拼接进注释） |
| `-std=c++17` | 输出 `这行被吃了吗` |

`??/` 是 trigraph，等价于 `\`。C++11/14 里它是语言的一部分；**C++17 起 trigraph 已从标准移除**，所以同一份代码在两个标准下行为不同。这种"换个 -std 就变语义"的东西，是跨项目移植时的暗雷。

## HFT / 嵌入式视角

1. **`#if 0` 是唯一可靠的整段禁用手段**。调试策略时临时注释掉一段下单逻辑，如果那段里有 `/* 订单状态说明 */`，用 `/* */` 包会导致代码被"部分禁用"——编译能过、行为全错，比直接报错危险得多。团队规范里应写明：**禁用代码一律 `#if 0 ... #endif`**。
2. **注释里的反斜杠要警惕**。宏定义、多行日志字符串旁边写注释时，行尾不小心留个 `\`（比如从 Windows 拷过来的路径 `C:\data\`），会静默吃掉下一行。CI 里加 `-Wall` 之外的 `-Wcomment`（clang 默认开）能抓到嵌套 `/*`，但**抓不到反斜杠续行**——只能靠 review。
3. **代码生成器 / 宏里别用注释分隔 token**。写 `#define CONCAT(a,b) a##b` 这类宏或在模板代码里插注释时，记住注释是"空格"：`a/**/b` 不会变成 `ab`，但 `"a"/*x*/"b"` 会拼成 `"ab"`——字符串和标识符的规则不一样。
4. **不要在代码里用 trigraph**。C++17 已移除，但存量代码可能还有；新代码一律禁用，遇到 `??` 开头的怪序列先怀疑它。
5. **注释不影响编译产物，但影响编译时间吗？** 不影响——注释在阶段 3 就被换成空格，预处理后的行数会保留（因为换行还在），但不产生 token。真正的编译时间大头是 `#include`（见 1.1 的 31 441 行实测）。

## 自测题

**1（选择）** 下面代码能否正确编译？
```cpp
/* 外层
   /* 内层 */
   外层继续
*/
```
- A. 能，嵌套注释合法
- B. 不能，第一个 `*/` 就关闭了外层注释，后面的 `*/` 悬空

**2（判断）** C++ 中 `//` 注释可以从一行延续到下一行。

**3（应用）** 你想临时禁用下面这段代码，哪种写法安全？
```cpp
/* config A */
int x = 1;
/* config B */
int y = 2;
```

<details><summary>参考答案</summary>
1. B。`/* */` 不能嵌套，第一个 `*/`（在"内层"后）就关掉了外层，最后的 `*/` 变成多余符号导致编译错误。
2. 错。`//` 只到行尾，换行后失效。要跨行每行写 `//`，或用 `/* */`。
3. 用 `#if 0 ... #endif` 包住整段最安全，因为里面的 `/* */` 不会触发嵌套陷阱：
   ```cpp
   #if 0
   /* config A */
   int x = 1;
   /* config B */
   int y = 2;
   #endif
   ```
</details>

**4（踩坑·高价值）** 下面这段代码为什么编译时报「`x` 未声明」？
```cpp
int main() {
    // 这是注释 \
    int x = 42;
    std::cout << x;
}
```

**5（判断）** `a/**/b` 会被解析成标识符 `ab`。

**6（应用）** 你要临时禁用下面这段含注释的代码，写出安全做法：
```cpp
/* 配置 A：限价单 */
void place_limit() { ... }
/* 配置 B：市价单 */
void place_market() { ... }
```

<details><summary>参考答案</summary>

4. 因为 `//` 注释**末尾的反斜杠**触发了**行拼接**，把下一行 `int x = 42;` 拼进了注释里。C/C++ 的翻译阶段顺序是：**阶段 2 行拼接 → 阶段 3 注释处理**，拼接在前，所以这一行整行消失。实测报错 `use of undeclared identifier 'x'`，错误位置在第 3 行，而真凶在第 2 行的行尾——这类错误排查成本很高。

5. **错**。注释在翻译阶段 3 被替换成**一个空格**，不是被删除。所以 `a/**/b` 展开成 `a b`，是**两个 token**，实测 `int ab = a/**/b;` 报 `error: expected ';' at end of declaration`。但字符串字面量的相邻拼接不受影响：`"he"/*x*/"llo"` 仍是 `"hello"`（`sizeof == 6`）。

6. 用预处理指令，不要用 `/* */` 包：
   ```cpp
   #if 0
   /* 配置 A：限价单 */
   void place_limit() { ... }
   /* 配置 B：市价单 */
   void place_market() { ... }
   #endif
   ```
   `/* */` 不能嵌套——外层注释会被里面第一个 `*/` 关掉，导致代码被"部分禁用"，编译能过但行为全错，比直接报错危险得多。

</details>
