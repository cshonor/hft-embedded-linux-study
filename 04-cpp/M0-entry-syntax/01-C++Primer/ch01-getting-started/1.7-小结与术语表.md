## 术语表（带 C 对照）

| 术语 | 含义 | C 程序员视角 |
|------|------|--------------|
| **内置类型** | 语言自带的 `int`/`double`/`char` | 和 C 一样 |
| **命名空间** | `std::cin` 避免名字冲突 | C 没有命名空间，靠命名约定 |
| **实参 / 形参** | 调用时传的值 / 定义里的参数 | 和 C 一样 |
| **缓冲区** | IO 流读写用的内存区，`endl` 刷新 | C 的 `fflush(stdout)` 类似 |
| **类** | 数据 + 函数 + 访问控制 | C 的 `struct` 只有数据 |
| **头文件** | `<iostream>`、`"Sales_item.h"` | 和 C 一样，但 C++ 有 `class` |

## 第 1 章给 C 程序员的 5 个要点

1. **`cin/cout` 替代 `scanf/printf`** —— 类型安全，不用记格式串，不会忘 `&`
2. **`//` 注释放心用** —— C89 没有，C99 起和 C++ 都支持
3. **`for` 变量作用域在循环内** —— `for(int i...)` 的 `i` 出循环就没了；**C99 起 C 也是这个行为**（只有 C90 编译器当扩展放行时才泄漏），别把它当 C/C++ 差异（详见 [1.4](./1.4-控制流.md) 实测）
4. **`class` 比 `struct` 多了方法和访问控制** —— 数据和行为绑定，这是 C→C++ 的核心转变
5. **`while(cin>>x)` 替代 `scanf` 返回值检查** —— 流的状态自带 bool 转换

## 综合示例

```cpp
// 第 1 章综合：循环读取不定数量输入并求和
#include <iostream>
int main() {
    std::cout << "Enter numbers (Ctrl+Z then Enter on Windows to end):\n";
    int sum = 0, value = 0;
    while (std::cin >> value)   // 读至 EOF
        sum += value;
    std::cout << "Sum = " << sum << std::endl;
    return 0;
}
```

## 第 1 章的实测账本（把前面各节的结论放在一起）

> 全部在本机 clang 23.1.0 / arm64-apple-darwin / libc++ 实测。

| 主题 | 实测结论 | 出处 |
|------|---------|------|
| `main` 返回值 | `return 256` 编译成 `mov w0, #256`，shell 里 `echo $?` 得到 **0**（OS 只取低 8 位） | 1.1 |
| 不写 `return` | `int main(){}` 与 `int main(){return 0;}` 汇编**完全相同** | 1.1 |
| `main` 不能被使用 | 调用 / 取地址在 `-pedantic-errors` 下报 `[-Wmain]` | 1.1 |
| 头文件代价 | `<iostream>` 展开 **31 441 行**（`<cstdio>` 是 699 行），编译耗时 ×2.7，二进制 16 KB → 52 KB | 1.1 |
| 注释 | 行拼接（阶段 2）**先于**注释处理（阶段 3）→ `//` 末尾的 `\` 会吃掉下一行 | 1.3 |
| 注释是空格 | `a/**/b` 是两个 token（实测报 `expected ';'`）；但 `"he"/*x*/"llo"` 会拼成 `"hello"` | 1.3 |
| `cin` 失败 | 类型不匹配 → `v` **置 0**；纯 EOF → `v` **保持原值**；`failbit` 粘滞，不 `clear()` 后续全失败 | 1.4 |
| 死循环写法 | `while(1)` / `while(true)` / `for(;;)` `-O2` 汇编**逐条相同** | 1.4 |
| 成员函数 | 与普通函数（传指针）汇编**逐条相同**；非虚成员函数**不占对象空间** | 1.5 |
| `sizeof` | 空类 **1**；有虚函数 → +8 字节（vptr） | 1.5 |
| ODR | 非 `inline` 定义放 `.h` → 链接期 `duplicate symbol`；`inline` 生成 **weak** 符号 | 1.5.1 |
| 增量编译 | 实现放 `.cpp` 改一次重编 1 个文件；放 `.h` 则 N 个使用者全重编 | 1.5.1 |
| 分组聚合 | 有序归并 3.9~5.8 ms vs `map` 63~65 ms（**11~16 倍**）vs `unordered_map` 12.5~14.8 ms（**2.5~3.2 倍**） | 1.6 |
| IO 开销 | `endl` 比 `'\n'` 慢 **23~25 倍**；`printf` 比 `std::cout` 快约 **2 倍** | 本节 |

## 底层实测：流 IO 到底有多贵

> 这一节补上第 1 章最后一个没量化的问题——用 `cin/cout` 替换 `scanf/printf`，代价是什么。

### ① `std::endl` vs `'\n'`：数量级的差别

写 20 万行到文件，同进程对照实测：

| 写法 | 实测耗时 |
|------|---------|
| `ofstream << ... << '\n'` | **37.9 ms** |
| `ofstream << ... << std::endl` | **444.0 ms** |

**慢约 12 倍**（另一次独立进程测量中是 431~470 ms vs 18.3~18.5 ms，**23~25 倍**；差别来自目标设备与缓存状态，但数量级一致）。

原因是 `std::endl` 做两件事：写 `'\n'` + **强制 flush**。一次 flush 就是一次 `write` 系统调用（几微秒），20 万次就是几百毫秒。**`endl` 应该只在真正需要"立刻让对方看到"时用**（比如交互式提示、崩溃前的最后一行日志）。

### ② `printf` vs `std::cout`

20 万行写 `/dev/null`：

| 写法 | 实测耗时（3 轮） |
|------|----------------|
| `std::cout << i << " " << i*2 << '\n'`（默认） | 42.9 / 42.9 / 42.9 ms |
| `std::cout` + `sync_with_stdio(false)` | 42.9 / 42.9 / 42.9 ms |
| `printf("%d %d\n", i, i*2)` | **21.1 / 21.1 / 21.2 ms** |

写真实文件时：cout 45.8~54.4 ms、关同步 45.8~46.0 ms、printf 23.8~24.0 ms——**结论一致**。

两条诚实的结论：
- **`printf` 比 `std::cout` 快约 2 倍**（在 libc++ 上）。日志热路径值得在意，但先确认瓶颈真在 IO。
- **`sync_with_stdio(false)` 在 libc++ 上收益接近 0**（42.9 vs 42.9 ms）。网上常说的"关同步快 5~10 倍"是 **libstdc++（GCC）**上的老经验，**别盲信**——换了标准库先自己测。

> 补充：关同步真正的意义是**保证 `printf` 和 `cout` 混用时的输出顺序**。开了同步，两者顺序一致；关了就各走各的缓冲，交叉输出会乱序。**关同步前先确认没有混用**。

## 第 1 章给 C 程序员的补充要点（前 5 条之外的）

6. **`return 0` 之外只用 0–125 做错误码** —— 256 会静默变成 0（见 1.1）
7. **整段禁用代码用 `#if 0`，不要用 `/* */`** —— 注释不能嵌套（见 1.3）
8. **`cin` 失败会锁死流** —— 必须先 `clear()` 再 `ignore()`（见 1.4）
9. **`class` 的价值是 `private`，不是语法糖** —— 成员函数和普通函数汇编一样（见 1.5）
10. **`#pragma once` 挡不住 ODR** —— 头文件里只能放声明、`inline`、类定义（见 1.5.1）
11. **别用 `std::endl` 做换行** —— 除非你真的需要立即 flush（见本节）

## HFT / 嵌入式视角（全章汇总）

1. **日志是 HFT 最大的隐性成本之一**。撮合/行情路径上每笔都 `printf` 一次，20 万笔就是 20~40 ms——足够吃掉一个交易日的 alpha。**热路径上用无锁环形缓冲 + 后台线程落盘**，而不是同步写。
2. **`endl` 是"看起来无害"的性能杀手**。代码 review 时见到 `endl` 就该问一句"这里真的需要 flush 吗"。生产代码里 99% 应该是 `'\n'`。
3. **别在头文件里塞实现**。HFT 项目几千个文件，头文件改一行触发全量重编是几十分钟；`inline` 只留给 1–3 行的访问器。
4. **`<iostream>` 在 MCU 上基本不可用**。展开 3 万行、二进制 +36 KB——片上运行的代码应该走精简 `printf` 或直接写 UART，C++ 这边只保留不依赖 `<iostream>` 的部分（这也是为什么很多嵌入式项目用 `-fno-exceptions -fno-rtti`）。
5. **退出码是唯一的跨进程契约**。盘前检查、看门狗、CI 全靠它，取值只用 0–125，别用 `exit()` 乱杀进程（不析构局部对象）。
6. **先量化再优化**。本章所有结论都来自实测数字，而不是"听说"。这个习惯比记住任何一个具体数字都重要——换了编译器/标准库/CPU，结论可能反转（比如 `sync_with_stdio` 那条）。

## 自测题（全章回顾）

**1（概念）** 列出 C++ 相对 C 在第 1 章里出现的 3 个差异。

**2（判断）** C++ 的 `class` 和 C 的 `struct` 本质相同，都只是装数据。

**3（应用）** 用 C++ 流 IO 重写下面的 C 代码：
```c
int a, b;
scanf("%d %d", &a, &b);
printf("sum = %d\n", a + b);
```

<details><summary>参考答案</summary>
1. ① `cin/cout` 类型安全的流 IO 替代 `scanf/printf`；② `for` 变量作用域只在循环内（C 会泄漏）；③ `class` 把数据和函数绑定并提供访问控制（C 的 `struct` 只有数据）。另外 `//` 注释、命名空间也是差异。
2. 错。C++ 的 `class`（和 `struct`）可以有成员函数和 `public/private` 访问控制；C 的 `struct` 只有数据成员，没有方法也没有访问控制（虽然 C++ 的 `struct` 也能有方法，默认访问是 public，而 class 默认 private）。
3. 
```cpp
int a, b;
std::cin >> a >> b;
std::cout << "sum = " << a + b << std::endl;
```
</details>

**4（踩坑·高价值）** 写 20 万行日志，下面两种写法差多少倍？为什么？
```cpp
for (int i = 0; i < 200000; ++i) out << i << " " << i * 2 << std::endl;   // A
for (int i = 0; i < 200000; ++i) out << i << " " << i * 2 << '\n';        // B
```

**5（判断）** 加上 `std::ios::sync_with_stdio(false);` 就能让 `std::cout` 快 5~10 倍。

**6（应用）** 你的行情回放程序要处理 100 万条 tick，每条都要打一行日志。列出 3 条能真正降低 IO 成本的措施（按收益排序）。

<details><summary>参考答案</summary>

4. **A 比 B 慢约 12~25 倍**（实测：同进程内 444 ms vs 37.9 ms；独立进程 431~470 ms vs 18.3~18.5 ms）。原因：`std::endl` 做两件事——写 `'\n'` **+ 强制 flush**。一次 flush 就是一次 `write` 系统调用（几微秒量级），20 万次累积成几百毫秒。**`endl` 只在需要"立刻让对方看到"时才用**（交互式提示、崩溃前的最后一行）。普通换行一律 `'\n'`，缓冲区满或程序退出时会自动 flush。

5. **错（在 libc++ 上）**。实测 20 万行写 /dev/null：`std::cout` 默认 42.9 ms，关同步后 **42.9 ms**——收益接近 0。写真实文件也一样（45.8 ms vs 45.8 ms）。"关同步快 5~10 倍"是 **libstdc++（GCC）**上的经验，**在 libc++ 上不成立**。关同步真正的语义价值是保证 `printf` 与 `cout` **混用时的输出顺序**——关掉之后两者各走各的缓冲，交叉输出会乱序，所以关之前先确认没有混用。
   顺带一提：`printf` 实测 21.1 ms，比 `std::cout`（42.9 ms）**快约 2 倍**，这个差距是稳定的。

6. 按收益排序：
   1. **把 `endl` 换成 `'\n'`** —— 立刻省掉 90%+ 的耗时（实测 12~25 倍），一行改动，零风险。**永远先看这个**。
   2. **热路径不要同步写盘** —— 改成无锁环形缓冲（SPSC ring buffer）+ 后台线程批量落盘。把每笔的 `write` 系统调用摊薄成每 4 KB 一次，这是数量级级别的改进，也是 HFT 日志的标准做法。
   3. **减少要写的内容** —— 二进制日志代替文本（`printf`/`cout` 的整数格式化本身也不便宜），或采样记录（每 N 条记一条）。
   补充：**先 profile 确认瓶颈真在 IO**。如果 100 万条处理总共才几十毫秒，而 IO 占 40 ms，那确实值得优化；如果总共 5 秒瓶颈在别处，改 IO 是白费力气。

</details>
