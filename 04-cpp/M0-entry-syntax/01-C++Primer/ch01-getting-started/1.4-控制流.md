# 1.4 控制流

## 本节讲什么

介绍允许程序跳出顺序执行、实现更复杂执行路径的语句。详细讲解 `while` 循环（反复检测条件并执行循环体直至条件为假）、`for` 循环（将初始化、循环条件和变量修改集中在循环头以简化代码）以及支持条件执行的 `if` 语句。还演示了如何使用 `while (std::cin >> value)` 不断读取数量不定的输入，直至遇到文件末尾（EOF）。

## 要点

- `while`：先判断条件，为真则重复执行循环体
- `for`：循环头包含初始化、条件、迭代语句，适合计数循环
- `if` / `else`：按条件选择执行路径
- `while (std::cin >> value)`：循环读取输入，直至 EOF 或输入失败
- Windows 下 EOF 常用 `Ctrl+Z` 后回车；Unix 下为 `Ctrl+D`
- **条件表达式的规则（与 Rust 不同）**：
  - `if` / `while` / `for` 的条件最终要当成**布尔值**来用
  - C++ 允许**隐式转换**：`0` → 假，`非 0` → 真
  - 所以 `while (1)` **合法**，表示一直循环（`1` 永远为真）
  - Rust 则**严格要求** `bool`，不能写 `while 1`
  - 现代 C++ 写死循环更推荐 `while (true)` 或 `for (;;)`，意图更清晰

## 和 C 的区别

**几乎没有区别。** `while`/`for`/`if` 语法 C 和 C++ 完全一致。细微差异：

| 对比点 | C | C++ | 说明 |
|--------|---|-----|------|
| `while (1)` 死循环 | ✅ | ✅ | 非 0 即真，C/C++ 都合法 |
| `for (int i=0; ...)` 在循环外用 `i` | ❌ 同样报错（C99 起） | ❌ `i` 作用域只在 for 内 | **C99 起 C 和 C++ 行为一致**；只有 C90 编译器当扩展放行（并告警） |
| 条件必须是 `bool` | ❌（整数即可） | ❌（整数即可） | C/C++ 都宽松，非 0 即真 |

**for 变量的作用域（常见误解澄清）。** 很多资料说"C 的 for 变量会泄漏到循环外，C++ 不会"——**这句话只在 C90 成立**。实测（clang 23.1.0）：

| 编译标准 | `for (int i=0;...){}` 后在循环外用 `i` |
|---------|--------------------------------------|
| C90（`-std=c90`） | ⚠️ 仅 warning `GCC does not allow variable declarations in for loop initializers before C99 [-Wgcc-compat]`，**放行**，`i` 泄漏（实测 `i=3`） |
| C99（`-std=c99`） | ❌ `error: use of undeclared identifier 'i'` |
| C11 / C17 | ❌ 同上 |
| C++（任意标准） | ❌ 同上 |

也就是说：**C99 起，C 和 C++ 在这一点上行为完全一致**——`for` 初始化语句里声明的变量，作用域就是整个 `for` 语句（含循环体），出循环即销毁。

```c
/* C99 代码 */
for (int i = 0; i < 3; i++) {}
printf("%d", i);   /* ❌ C99 也报错：use of undeclared identifier 'i' */
```
```cpp
// C++ 代码
for (int i = 0; i < 3; i++) {}
std::cout << i;    // 编译错误：i 不在作用域内
```

**记忆：** 别再把"for 变量泄漏"当成 C/C++ 的差异——**C99 之后两者一致**。真正要注意的是：循环后还要用这个变量，就得**提前声明**。

```cpp
int i = 0;
for (i = 0; i < 3; ++i) { /* ... */ }
std::cout << i;    // OK（C 和 C++ 都行）
```

## 通俗理解

- **`while (1)`** = 死循环：`1` 永远是非 0，一直被当成「真」
- **HFT 行情监听**：常用 `while (1)` 或 `while (true)` 做主循环，一直盯盘，满足条件时 `break` 退出
- **`if` / `for`** 同样适用：只有 `0` 是假，其他整数都算真

```cpp
while (1) {
    // poll_market();   // 拉行情
    // if (should_stop) break;  // 主动退出
}
```

## 示例

```cpp
#include <iostream>
int main() {
    // while：累加 1 到 10
    int sum = 0, val = 1;
    while (val <= 10) {
        sum += val;
        ++val;
    }
    std::cout << "Sum 1..10 = " << sum << std::endl;

    // for：同样效果
    sum = 0;
    for (int i = 1; i <= 10; ++i)
        sum += i;
    std::cout << "Sum 1..10 = " << sum << std::endl;

    // if：按分数输出等级
    int score = 85;
    if (score >= 90)
        std::cout << "A" << std::endl;
    else if (score >= 60)
        std::cout << "Pass" << std::endl;
    else
        std::cout << "Fail" << std::endl;

    // while(1) 死循环（C++ 允许，1 当 true）
    // while (true) { /* 轮询行情 */ break; }  // 更推荐的写法

    return 0;
}
```

## 常见错误

**1. `while (std::cin >> value)` 的结束条件搞混**
```cpp
int sum = 0, value = 0;
while (std::cin >> value)  // 什么时候停？
    sum += value;
```
结束条件：遇到 EOF（Windows `Ctrl+Z` 回车，Linux `Ctrl+D`），或输入类型不匹配（要 `int` 却输入字母）。`cin >> value` 的返回值是流本身，能转成 bool——读成功为真，失败为假。

**2. `for` 变量在循环外误用（C 程序员的坑）**
```cpp
for (int i = 0; i < 10; ++i) { /* ... */ }
std::cout << i;  // 编译错误！C++ 里 i 已经销毁
```
C90（编译器扩展下）`i` 循环外可见，**C99 起和 C++ 一样不可见**。要循环后用，提前声明：
```cpp
int i;
for (i = 0; i < 10; ++i) { /* ... */ }
std::cout << i;  // OK
```

**3. `if` 悬空 else（经典陷阱）**
```cpp
if (a > 0)
    if (b > 0)
        std::cout << "A";
else
    std::cout << "B";  // 这个 else 配的是内层 if，不是外层！
```
`else` 总是配最近的未配对 `if`。要配外层，用花括号：
```cpp
if (a > 0) {
    if (b > 0) std::cout << "A";
} else {
    std::cout << "B";  // 现在配外层
}
```

## 动机：控制流看着和 C 一模一样，真正的差别在"输入失败"上

`while` / `for` / `if` 的语法 C 程序员闭着眼都能写。这一节值得较真的是 **`while (std::cin >> value)` 这个惯用法**——它是 C 的 `scanf(...) != EOF` 的替代品，但**语义比 scanf 丰富得多**，也更容易被误用：

1. **循环的终止条件不止 EOF**。类型不匹配也会终止，而且终止后**流会卡住**，后续所有读取都失败——这是 C 程序员最容易懵的地方（`scanf` 失败后至少会跳过那个 token）。
2. **失败后变量的值是有规则的**，但规则分两种情况（实测见下），靠猜会猜错。
3. **条件表达式的隐式转换**决定了 `while (1)` 合法，也决定了 `if (ptr)`、`if (flags & MASK)` 这些写法在 C++ 里仍然成立——而 Rust/Java 会报错。

## 底层实测

> 全部在本机 clang 23.1.0 实测。

### ① `for` 变量作用域：C99 起 C 和 C++ 一致（见上方"和 C 的区别"已修正）

### ② `cin >> v` 失败后，`v` 到底是几？分两种情况

```cpp
int sum = 0, v = -999;
while (std::cin >> v) sum += v;
// 循环结束后打印 v 和流的四个状态位
```

| 输入 | `sum` | 循环结束时 `v` | good | eof | fail | bad |
|------|-------|---------------|------|-----|------|-----|
| `1 2 3 x` | 6 | **0** | 0 | 0 | **1** | 0 |
| `1 2 3`（直接 EOF） | 6 | **3**（保持原值） | 0 | **1** | 1 | 0 |

**为什么会不一样？** 关键在于失败发生在哪个阶段：

| 失败类型 | sentry 阶段 | num_get 阶段 | `v` 的值 |
|---------|-----------|-------------|---------|
| 类型不匹配（读到 `x`） | ✅ 成功 | ❌ 失败 | **置 0**（C++11 起标准规定） |
| 纯 EOF | ❌ 失败（eofbit 已置） | 根本没执行 | **保持上一次的值** |

也就是说：**只有 sentry 成功后提取才失败，`v` 才会被清零**。纯 EOF 时 `v` 是"上一次读到的值"——如果你的代码在循环后还用 `v`，就会拿到一个看起来合法其实是过期数据的数字。

### ③ 流失败后不 `clear()`，后续读取全部失效

输入 `x hello`：

```
第一次读 int：fail=1
未 clear 直接读 string → 读取失败     ← 数据还在缓冲区，但流已经"锁死"
clear() 后再读 string   → 读到 "x"    ← 卡住的那个 token 被吐出来
```

这是 `cin` 与 `scanf` 最大的行为差异：`scanf` 失败后只是返回，下次调用还能继续读；`cin` 的 `failbit` 是**粘滞**的，不 `clear()` 就永远读不了。恢复流程是 `clear()` 清状态 + `ignore()` 丢掉坏数据。

### ④ 四种死循环写法：`-O2` 下汇编逐条相同

```cpp
int sink;
void fn() { int i = 0; while (1)    { if (++i > 10) break; sink = i; } }
void fn() { int i = 0; while (true) { if (++i > 10) break; sink = i; } }
void fn() { int i = 0; for (;;)     { if (++i > 10) break; sink = i; } }
void fn() { int i = 0; for (;1;)    { if (++i > 10) break; sink = i; } }
```

四种写法在 `-O2` 下**生成完全相同的 4 条指令**：

```asm
mov  w8, #10
adrp x9, _sink@PAGE
str  w8, [x9, _sink@PAGEOFF]
ret
```

（循环被整个优化成 `sink = 10`。）所以 **`while(1)` / `while(true)` / `for(;;)` 没有任何性能差别**，选哪个纯粹是可读性问题。现代 C++ 推荐 `while (true)`（意图最清楚）或 `for (;;)`（最简短，`for(;;)` 里的空条件在 C 里也是惯用法）。

### ⑤ 悬空 else：`-Wall` 能抓到

```cpp
if (a > 0)
    if (b > 0) r = 1;
else
    r = 2;          // ← 这个 else 属于【内层】if
```

clang `-Wall` 报：`warning: add explicit braces to avoid dangling else [-Wdangling-else]`。

实测行为（`else` 配内层 `if`）：

| 调用 | 结果 | 说明 |
|------|------|------|
| `f(1, 0)` | **2** | 外层真、内层假 → 走 else（很多人以为会是 0） |
| `f(1, 1)` | 1 | 两层都真 |
| `f(-5, 0)` | 0 | 外层假，整个 if 跳过了 |

## HFT / 嵌入式视角

1. **`while (cin >> x)` 只适合原型，不适合生产**。它的失败处理是"悄悄停"，而且会把流锁死。生产代码要显式检查：`if (!(in >> x)) { /* 记日志 + 决定是跳过还是中止 */ }`。行情回放程序里，一条坏数据导致整个循环静默结束 = 少回放大半天行情。
2. **循环后别用循环变量的值**。实测 EOF 情形下 `v` 是"上一次的值"——`while (cin >> price) {...}` 之后用 `price` 做最后一笔的结算，会拿到过期价格。**要么在循环体内处理完整，要么显式初始化一个 `last_valid`。**
3. **`failbit` 粘滞是嵌入式串口/日志解析的常见坑**。按行解析配置/报文时，一次解析失败会让后续全部失败；正确姿势是 `clear()` + `ignore(n, '\n')` 跳过坏行再继续。
4. **死循环写法统一用 `while (true)`**。汇编一样，但审阅时能一眼看出"这是故意的死循环"，而不是"`while(1)` 是不是写错了"。HFT 主循环、嵌入式 `super-loop` 都是这个形态，可读性直接关系排障速度。
5. **条件里的隐式转换要显式化**。`if (ptr)` 在 C++ 里合法，但 `if (flags & MASK)` 这类写法在重构时极易改错优先级。写 `if (ptr != nullptr)` / `if ((flags & MASK) != 0)`，编译器不会因为你写得更啰嗦而生成更差的代码（实测汇编一致）。

## 自测题

**1（选择）** 下面 C++ 代码能否编译？
```cpp
for (int i = 0; i < 3; ++i) {}
std::cout << i;
```
- A. 能，输出 3
- B. 不能，`i` 不在作用域

**2（踩坑）** 下面代码输入 `1 2 3 x` 后 `sum` 是多少？
```cpp
int sum = 0, v = 0;
while (std::cin >> v) sum += v;
```

**3（判断）** C++ 中 `while (1)` 和 `while (true)` 完全等价。

**4（应用）** 把下面 C 习惯的代码改成 C++ 安全写法：
```cpp
int i;
for (i = 0; i < n; ++i) { ... }
// 后面要用 i 的最终值
```

<details><summary>参考答案</summary>
1. B。C++ 的 `for` 变量作用域只在循环体内，循环外不可见。**注意：C99 起 C 也是同样的行为**（实测 `-std=c99` 报 `use of undeclared identifier 'i'`），所以这不是 C/C++ 的差异；只有 C90 且编译器放行扩展时 `i` 才会泄漏。
2. `sum = 6`。读到 `x` 时 `cin >> v`（v 是 int）失败，循环结束。1+2+3=6。
3. 语义等价（都是死循环），但 `while (true)` 意图更清晰，现代 C++ 推荐这种写法。`while(1)` 也合法。
4. 这段代码在 C++ 里其实没问题（`i` 在循环外声明），只是不够现代。如果循环后不需要 `i`，应该写 `for (int i = 0; ...)` 让变量用完即丢；确实需要就用上面的写法（提前声明）。
</details>

**5（踩坑·高价值）** 输入 `1 2 3`（后面直接 EOF），循环结束后 `v` 的值是多少？
```cpp
int sum = 0, v = -999;
while (std::cin >> v) sum += v;
// 此时 v == ?
```
- A. 0
- B. 3
- C. -999

**6（判断）** `cin >> v` 失败后，只要再调一次 `cin >> w` 就能继续读（就像 `scanf` 那样）。

**7（应用）** `while (1)` 和 `while (true)` 哪个更快？如果一样，现代 C++ 推荐哪个？为什么？

<details><summary>参考答案</summary>

5. **B（v == 3）**。这是最容易猜错的一题。规则是：**只有 sentry 成功后提取才失败，`v` 才会被清零**（C++11 起标准规定：提取失败时写入 0）。纯 EOF 时 sentry 阶段就失败了（eofbit 已置），根本没走到写 `v` 那一步，所以 `v` **保持上一次读到的值 3**。对照：输入 `1 2 3 x`（类型不匹配）时 sentry 成功、`num_get` 失败 → `v` 被置 **0**。两种失败行为不同，别混为一谈。

6. **错**。`cin` 的 `failbit` 是**粘滞**的：流一旦 fail，后续所有 `>>` 都会**立即失败并返回**，哪怕缓冲区里还有数据（实测"未 clear 直接读 → 读取失败"）。恢复要两步：
   ```cpp
   std::cin.clear();                          // ① 清状态位
   std::cin.ignore(1024, '\n');               // ② 丢掉坏数据（否则下次又读到同一个坏 token）
   ```
   `scanf` 失败后不会锁死流，所以从 C 转过来特别容易在这里栽跟头。

7. **一样快**。`-O2` 下 `while(1)` / `while(true)` / `for(;;)` / `for(;1;)` 生成**完全相同的汇编**（本例实测都被优化成 4 条指令：直接写 `sink = 10`）。推荐 **`while (true)`**：语义最明确（"故意的死循环"），审阅者不用猜 `while(1)` 是不是笔误；`for(;;)` 也可以，是 C 里的传统惯用法。不要因为"性能"去选其中某一个。

</details>

## 可跑例子

```bash
# 1.4-1  for 作用域 / cin 失败后的值 / 流状态位 / 悬空 else

printf '1 2 3 x\n' | ./cf     # 类型不匹配 → v=0
printf '1 2 3'     | ./cf     # 纯 EOF     → v=3（保持原值）

# C 对照：for 变量作用域在 C90 / C99 / C11 / C17 下的差异

```
