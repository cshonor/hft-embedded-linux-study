# 2.3.3 void 指针与显式转换（C++ 视角）

## 本节讲什么

Primer §2.3.2 只用一小段带过 `void*`："可用于存放任意对象的地址，但我们对该地址中对象的类型一无所知"。C++ 里 `void*` 的**地位比 C 低得多**——泛型有模板、空指针有 `nullptr`、原始内存有 `std::byte*`——但它并没有消失：C API 边界、`operator new`、`memcpy` 家族、type erasure 的底层，全是它。

本节回答三个问题：

1. C++ 为什么**强制** `void*` 显式转换，四种 cast 该用哪个？
2. `delete void*`、`const void*` 各有什么坑？
3. 现代 C++ 用什么替代 `void*` 的旧场景？

C 侧的机制（三条铁律、GNU 扩展、函数指针边界）见 [C 语言 6.15 void 指针](../../../../../01-c-language/02-advanced-pointers-and-memory/ch06-pointers/6.15-void指针.md)，本节只讲 **C++ 独有的部分**。

文中编译行为均为本机实测（clang++ 23.1.0，macOS arm64，cdev 环境）。

## 铁律继承自 C，转换规则收紧

三条铁律与 C 完全相同：任何对象指针可隐式转 `void*`；不能解引用；不能算术。

差别在**回来的路**：C 双向隐式，C++ 只放行去程。

```cpp
int x = 57;
void *vp = &x;                  // ✅ 隐式（和 C 一样）
int *p = vp;                    // ❌ error: cannot initialize a variable of type
                                //    'int *' with an lvalue of type 'void *'
int *p2 = static_cast<int*>(vp); // ✅ 标准姿势
```

## 四种 cast 面对 void*：用哪个

| cast | `void*` → `int*` | 语义 | 结论 |
|------|------------------|------|------|
| `static_cast` | ✅（实测通过） | "我知道它原来就是这个类型" | **首选**：`void*` 往返是标准明确定义的 |
| C 风格 `(int*)vp` | ✅ | 此处等价 `static_cast` | 能过但**别用**：grep 不到、组合语义随上下文漂移 |
| `reinterpret_cast` | ✅（实测通过） | "重新解释位模式" | 能过但语义过重——`void*` 往返不需要它 |
| `const_cast` | ❌ 不能转类型 | 只能加/去 const | 与类型转换正交 |

标准保证（[conv.ptr]）：对象指针 → `void*` → **用 `static_cast` 转回原类型**，值不变。所以 `static_cast` 不只是"能过"，它是这条路径上**语义最精确**的写法。

```cpp
void *vp = &x;
int *a = static_cast<int*>(vp);        // 语义：转回"原来的类型"
int *b = reinterpret_cast<int*>(vp);   // 也能编译，但你在说"把位模式当 int*"
```

两者生成的机器码完全一样（cast 零指令），差别全在**给编译器和读者传达的意图**。

## `const void*`：const 与 void* 正交

`const` 的规则在 `void*` 上不打折。实测：

```cpp
const void *cvp = &x;
void *vp = cvp;   // ❌ error: cannot initialize a variable of type 'void *'
                  //    with an lvalue of type 'const void *'
```

要脱 const 只能 `const_cast`，且**先有类型、再谈 const**——`const_cast` 不能把 `const void*` 变成 `int*`，要分两步：

```cpp
const void *cvp = &x;
int *p = static_cast<int*>(const_cast<void*>(cvp));  // 先脱 const，再转类型
```

这种写法出现在即表示你在穿透两层保护，审查时应当多看一眼。

## `delete void*`：能编译，是 UB

这是 C++ 独有的坑（C 没有析构概念）：

```cpp
struct S { virtual ~S() {} int v; };
S *s = new S{};
void *vp = s;
delete vp;   // ⚠️ warning: cannot delete expression with pointer-to-'void'
             //    type 'void *' [-Wdelete-incomplete]
```

实测 clang++ 只给 **warning 就放行了**——但标准上这是 **UB**：`delete` 需要知道动态类型才能调析构函数，`void*` 没有类型信息，析构不会执行（`S` 的资源泄漏），行为未定义。

对照记忆：

| 操作 | 结果 |
|------|------|
| `free(vp)`（C 风格） | ✅ 安全——free 不需要类型信息 |
| `delete vp`（`void*`） | ❌ UB——delete 需要类型调析构 |
| `delete static_cast<S*>(vp)` | ✅ 转回真类型再删 |

`new` 返回**类型化指针**，`operator new`（分配原语）才返回 `void*`——分层就在这儿：`operator new`/`malloc` 这一层只认字节，往上一层才有对象。

## `std::byte*`（C++17）：比 void* 更现代的"原始内存指针"

`void*` 的问题是"没有类型"导致什么都不能做；`char*` 的问题是 char 同时是"字符"和"字节"两种身份。C++17 的 `std::byte` 把"原始字节"独立成一个类型：

```cpp
#include <cstddef>

int x = 0x12345678;
void *vp = &x;
std::byte *bp = static_cast<std::byte*>(vp);   // ✅ void* -> byte* 合法（实测）

std::to_integer<int>(bp[0]);   // 取值必须显式转换（实测输出 0x78，小端）
sizeof(std::byte);             // 1（实测）
```

| 维度 | `char*` | `std::byte*` | `void*` |
|------|---------|--------------|---------|
| 别名任意对象 | ✅ | ✅（同 char 特权） | ✅ |
| 指针算术 | ✅（1 字节） | ✅（1 字节） | ❌（GNU 扩展才行） |
| 解引用 | ✅ | ✅（得 `std::byte`） | ❌ |
| 是算术类型 | 是（能直接 `+`/赋值给 int） | **不是**（要 `to_integer`） | — |
| 与"字符"混淆 | 是 | **否** | — |

写内存池、序列化、协议缓冲区的 C++ 新代码，缓冲区类型用 `std::byte*` 而不是 `char*`/`void*`——它把"我只碰字节，不关心解释"这个意图变成了**类型系统能检查**的东西。

## 什么时候还得用 void*

| 场景 | 为什么绕不开 |
|------|--------------|
| C API 边界回调（`qsort`、`pthread_create`、第三方 C 库） | C 没有模板，上下文只能 `void*` |
| `operator new` / allocator / `memcpy` 家族 | 这些层在"对象之下"，只有字节 |
| type erasure 底层（`std::any`、`std::function` 的实现） | 擦除类型 = 存 `void*` + 存操作表 |
| C++23 `std::out_ptr` / 与 C 互操作 | 替你把 `void**` 出参包成安全的 |

反过来说，**纯 C++ 内部**的泛型需求不该用 `void*`：

| 旧写法（C 思维） | 现代 C++ 替代 |
|-------------------|----------------|
| `void*` + 元素大小 + 比较函数（qsort 模式） | 模板（`std::sort` 编译期实例化，零擦除开销） |
| `void*` 数组存异质对象 | `std::variant`（封闭集合）/ `std::any`（开放集合） |
| 回调带 `void* ctx` | lambda + `std::function`（捕获即上下文） |

## 和 C 的区别

| 对比点 | C | C++ |
|--------|---|-----|
| 三条铁律 | 一样 | 一样 |
| `void*` → `T*` | 隐式合法 | **必须显式 cast**（首选 `static_cast`） |
| 空指针 | `NULL` / `((void*)0)` | `nullptr`（**2.3.2**） |
| 释放 `void*` 指的内存 | `free` 安全 | `delete void*` 是 UB（析构不可达） |
| 原始字节类型 | `char` / `unsigned char` | 新增 `std::byte`（C++17，首选） |
| 泛型主力 | `void*`（唯一手段） | 模板；`void*` 退守边界层 |
| GNU 扩展算术 | `void*+1` 步长 1 字节 | clang++ 同样放行，同样不可移植 |

## 示例

```cpp
#include <cstddef>
#include <cstring>
#include <iostream>

// C 风格回调边界：void* ctx 传上下文（模拟 qsort/pthread 模式）
using Callback = void (*)(void *ctx, const void *data, size_t n);

void dump_as_int(void *ctx, const void *data, size_t n) {
    const char *name = static_cast<const char*>(ctx);
    // 边界内第一时间转回真类型，void* 不往深处传
    if (n == sizeof(int)) {
        int v;
        std::memcpy(&v, data, sizeof v);   // 别名安全的类型双关
        std::cout << name << ": " << v << "\n";
    }
}

int main() {
    int price = 57;
    void *vp = &price;

    int *p = static_cast<int*>(vp);    // 标准往返
    std::cout << *p << "\n";           // 57

    const char *tag = "price";
    dump_as_int(const_cast<char*>(tag), vp, sizeof price);

    std::byte *raw = static_cast<std::byte*>(vp);  // 原始内存视角
    std::cout << "first byte: 0x" << std::hex
              << std::to_integer<int>(raw[0]) << "\n";
}
```

要点：`void*` 只在**边界**出现，进函数第一步就 cast 回具体类型，绝不让 `void*` 在业务逻辑里流动。

## 常见错误

**1. C 习惯隐式转换**
```cpp
void *vp = malloc(4);
int *p = vp;   // C 合法，C++ error
```
C++ 写 `static_cast<int*>(vp)`；更好的问题是"为什么还在用 malloc"——`new` / 容器 / 智能指针。

**2. `delete` 一个 `void*`**
```cpp
void *vp = new S{};
delete vp;   // warning -Wdelete-incomplete，实际 UB：析构不执行
```
先 `static_cast` 回真类型再 `delete`；或 C 层分配的内存只走 `free`。

**3. 用 `reinterpret_cast` 做 void* 往返**
```cpp
int *p = reinterpret_cast<int*>(vp);   // 能编译，但语义错了
```
`void*` 往返是 `static_cast` 的标准场景；`reinterpret_cast` 留给"位模式重解释"（如指针转 `uintptr_t`）。

**4. 拿 `void*` 当泛型容器元素**
```cpp
std::vector<void*> stuff;   // C 思维：类型信息全丢，谁 delete？
```
用 `std::variant<A,B,C>` 或 `std::any`，或干脆多态基类 + `unique_ptr<Base>`。

## 自测题

**1（选择）** `void *vp = &x;` 要转回 `int*`，下列哪种写法语义最准确？
- A. `int *p = vp;`
- B. `int *p = static_cast<int*>(vp);`
- C. `int *p = reinterpret_cast<int*>(vp);`

**2（踩坑）** 下面代码编译只有 warning，运行时会发生什么？
```cpp
struct S { ~S() { release(); } };
void *vp = new S;
delete vp;
```

**3（判断）** `const void *cvp` 可以直接 `static_cast<void*>(cvp)` 去掉 const。

**4（开放）** C++17 之后写内存池，缓冲区指针为什么推荐 `std::byte*` 而不是 `char*` 或 `void*`？

<details><summary>参考答案</summary>
1. B。A 在 C++ 里直接编译错误；C 能编译但语义是"重解释位模式"，而 `void*` 往返是标准明确定义的 `static_cast` 场景——用 B 把"我知道它原来是什么"这个意图写进代码。
2. `-Wdelete-incomplete` 警告。`delete` 需要静态类型来调用析构，`void*` 没有类型信息：`~S()` **不会被调用**，`release()` 泄漏，行为未定义。正确做法：`delete static_cast<S*>(vp)`。
3. 错。`static_cast` 不能去 const——实测报 "casts away qualifiers"。要先 `const_cast<void*>(cvp)` 脱 const（且 `const_cast` 只动 const、不转类型）。
4. 三者都有别名任意对象的特权，但 `std::byte*`：① 有类型，可以合法做 1 字节步长的算术和解引用（`void*` 不行）；② 不是算术类型，误当整数用会编译错误（`char*` 不会）；③ 语义上把"原始字节"和"字符"分开，意图可读、可检查。
</details>
