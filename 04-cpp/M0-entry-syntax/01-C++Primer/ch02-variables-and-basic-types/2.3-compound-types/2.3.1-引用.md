# 2.3.1 引用

> **实测环境**：macOS 26.6.2 / Apple Silicon (arm64) · clang 23.1.0 · `-std=c++20`
> （x64 对照用 `-target x86_64-pc-windows-msvc` 交叉出目标汇编，不链接）

## 本节讲什么

为什么需要引用、`T&` 与 `const T&`，以及**引用在编译后到底变成了什么**——后者是面试和读汇编时最容易含糊的一环，本节全部给本机实测。

## 为什么 C++ 还要有引用？

已有指针，再引入引用，是为了解决指针在**业务代码**里的常见痛点。

### 指针的缺点

1. **可为空**（`nullptr`）→ 必须判空，漏了可能崩溃（HFT 里直接宕机）
2. **可随意改指向** → 逻辑容易乱
3. **语法繁琐** → `*p` 解引用、`*`/`&` 混用
4. **可做算术**（`p++`）→ 容易越界

```cpp
int a = 1, b = 2;
int *p = &a;
p = &b;   // 随时换指向
```

### 引用：受约束的「安全版指针」

编译器实现上，引用常类似 **`T* const`**（指向 `T` 的**常量指针**——地址绑死不能改）：

| 特性 | 指针 `int*` | 引用 `int&` |
|------|-------------|-------------|
| 可为空 | ✅ `nullptr` | ❌ 必须绑定对象 |
| 改指向 | ✅ `p = &other` | ❌ 绑定后不能换 |
| 使用语法 | `*p` | 直接当变量用 |
| 指针运算 | ✅ | ❌ |

```cpp
int a = 10;
int &ref = a;
ref = 20;              // 直接改 a，不用 *

// 底层直觉（概念模型，不是你要写的代码）：
// int *const p = &a;  // 地址固定，通过 *p 访问
```

**一句话**：引用 = **受限制、更安全、语法更简洁**的间接访问；日常业务优先引用，底层内存/DPDK 才用裸指针。

### 取舍标准（HFT 编码习惯）

**优先用引用：**

- 函数传参、避免拷贝：`void f(const OrderBook &book);`
- 运算符重载（语法要求）：`operator+`、`operator<<` 等

**必须用指针：**

- 后期要**改变指向**
- 对象**可能不存在**（可选）
- 数组、内核、DPDK 等需要**地址偏移**

## 底层实现：引用什么时候等于指针（实测）

「引用就是被隐藏的指针」这句话**对一半**。标准原文（cppreference[^refdecl]）：

> "References are not objects; they do not necessarily occupy storage, although the compiler may allocate storage if it is necessary to implement the desired semantics (e.g. a non-static data member of reference type usually increases the size of the class by the amount necessary to store a memory address)."

关键词是 **not necessarily**。下面四种场合实测，答案完全不同。

### 实测 1：作为类成员 —— 占一个指针大小

```cpp
struct RefMember { int& r; };
struct PtrMember { int* p; };
```

```
sizeof(RefMember)=8  sizeof(PtrMember)=8
```

64 位平台上两者都是 8 字节。这就是上面那句 "usually increases the size ... by the amount necessary to store a memory address" 的实证。

> ⚠ 常见翻车点：以为「引用不占内存」，结果类里放一个引用成员，`sizeof` 对不上、序列化错位。

### 实测 2：跨函数传参 —— ABI 层就是指针

```cpp
__attribute__((noinline)) void bump_ref(int& v) { ++v; }
__attribute__((noinline)) void bump_ptr(int* v) { ++(*v); }
```

`clang++ -std=c++20 -O0 -S`（arm64，`x0` 是第一个参数寄存器）——两个函数**逐条指令完全相同**：

```asm
__Z8bump_refRi:                    ; void bump_ref(int&)
	sub	sp, sp, #16
	str	x0, [sp, #8]
	ldr	x9, [sp, #8]
	ldr	w8, [x9]
	add	w8, w8, #1
	str	w8, [x9]
	add	sp, sp, #16
	ret

__Z8bump_ptrPi:                    ; void bump_ptr(int*)
	sub	sp, sp, #16
	str	x0, [sp, #8]
	ldr	x9, [sp, #8]
	ldr	w8, [x9]
	add	w8, w8, #1
	str	w8, [x9]
	add	sp, sp, #16
	ret
```

x64（`-target x86_64-pc-windows-msvc`）同样：`?bump_ref@@YAXAEAH@Z` 与 `?bump_ptr@@YAXPEAH@Z` 符号名不同（MSVC 把「引用/指针」编进了 mangled name），机器码一致。

**结论**：函数调用边界上，`int&` 和 `int*` 走同一条路——寄存器里传一个地址。

### 实测 3：局部引用 —— `-O0` 占栈槽，`-O1` 彻底消失

`const int& cr = 42;` 在 `-O0` 下：

```asm
sub	x8, x29, #44
mov	w9, #42
stur	w9, [x29, #-44]      ; 42 这个临时量被物化到栈上
stur	x8, [x29, #-40]      ; 把它的地址存进引用的槽位 ← 这里确实是个指针
```

同一个函数在 `-O1` 下：

```asm
__Z8bump_refRi:
	ldr	w8, [x0]
	add	w8, w8, #1
	str	w8, [x0]
	ret
```

「取地址 → 存栈 → 再读出来」全没了，引用退化成对 `x0` 的直接访问——**零额外开销**。

### 小结

| 场合 | 引用 = 指针？ | 实测依据 |
|------|--------------|---------|
| 类数据成员 | **是** | `sizeof == 8` |
| 跨函数传参（ABI 层） | **是** | 两个函数汇编逐条相同 |
| 局部引用，`-O0` | **是** | 汇编里 `str x8,[x29,#-40]` 存 `&a` |
| 局部引用，`-O1` 及以上 | **否**，什么都不剩 | 只剩 `ldr / add / str` |

> 所以「引用是指针的语法糖」是**实现层面的常见做法**，不是标准保证；而且它只在 `-O0` 这个心智模型里成立。

## 编译器替你写的那两个符号

同一件事写两遍：

```c
/* C：& 和 * 全手写 */
void Increment(int *value) { (*value)++; }
int a = 5;
Increment(&a);
```

```cpp
// C++：两个符号都交给编译器
void Increment(int &value) { value++; }
int a = 5;
Increment(a);
```

编译器在**编译期**做两件事：

| 位置 | 你写的 | 编译器生成的 |
|------|--------|--------------|
| 调用处 | `Increment(a)` | 取 `a` 的地址，放进参数寄存器 |
| 函数体内 | `value++` | `(*value)++`（通过那个地址读写） |

```cpp
void Increment(int& value) { value++; }
int main() { int a = 5; Increment(a); return a; }
```

x64（`-target x86_64-pc-windows-msvc -O0`，VS 同款目标）：

```asm
main:
	movl	$5, 32(%rsp)          ; a = 5
	leaq	32(%rsp), %rcx        ; ★ 这就是被藏起来的 &a
	callq	"?Increment@@YAXAEAH@Z"
	movl	32(%rsp), %eax        ; return a
```

arm64（本机 `-O0`）：

```asm
	add	x0, sp, #8            ; ★ 同一个 &a，但指令名不是 lea
	mov	w8, #5
	str	w8, [sp, #8]          ; a = 5
	bl	__Z9IncrementRi
```

函数体内那个「自动解引用」（arm64）：

```asm
__Z9IncrementRi:
	str	x0, [sp, #8]          ; 参数：一个地址
	ldr	x9, [sp, #8]
	ldr	w8, [x9]              ; ★ 自动 *value：按地址读
	add	w8, w8, #1
	str	w8, [x9]              ; ★ 写回 *value
	ret
```

> ⚠ **一个容易白找的点**：`lea` 是 **x86 专属**指令。在 Mac（arm64）上跑同一段代码，不会有 `lea`——是 `add xN, sp, #imm` / `sub xN, x29, #imm`。「取地址」两平台都有，只是指令名不同；按记忆去 arm64 汇编里搜 `lea` 会一无所获。

所以准确说法是：**引用不是「没有」`&` 和 `*`，而是编译器替你写了**。

顺带一个长期收益：把 C++ 代码在脑内「翻译」回 C 的指针形式，正是读内核源码（纯 C，满屏 `&` 和 `*`）的必备能力——C 的显式风格让内存操作永远可见。C 的设计哲学是「**发生了什么，代码上就必须看得见**」；引用牺牲了这一点，换来简洁。

## 引用：`T&` 与 `const T&`

### 1. 可变引用（可修改原对象）

```cpp
int a = 10;
int &ref = a;
ref = 20;        // ✅ 通过 ref 修改 a
// a 现在是 20
```

- `int&`：绑定原变量，**可读可写**

### 2. 常量引用（只读）

```cpp
int a = 10;
const int &ref = a;
// ref = 20;     // ❌ 编译错误，不能通过 ref 修改
std::cout << ref; // ✅ 只读
```

- `const int&`：**只能读**，不能通过引用改原对象
- 可绑定到字面量：`const int &r = 42;`（普通 `int&` 不能绑字面量）

### 3. 引用的硬性规则（C++ 独有）

1. **必须初始化**，不能空着
2. **绑定后不能改绑**到其他对象（Rust 的引用可以重新绑定）
3. 不存在「空引用」——**语言层面**（见下节实测，物理上能造出来）

### 4. 工程习惯（HFT / 日常 C++）

```cpp
// 传参优先：不拷贝 + 只读
void process(const std::string &s);

// 需要改入参时才用可变引用
void adjust(int &value);
```

| 场景 | 用法 |
|------|------|
| 只读、避免拷贝 | `const T&` |
| 需要修改原对象 | `T&` |
| 可选/可为空 | 用指针或 `std::optional`（指针章节） |

## 「不存在空引用」的真相（实测）

语言层面：引用的初始化规则要求必须绑定到有效对象或函数（cppreference[^refdecl]）：

> "A reference is required to be initialized to refer to a valid object or function"

但**「语言不允许」不等于「物理上做不到」**。下面这段是 UB，却真的能编过：

```cpp
int* p = nullptr;
int& r = *p;                 // UB：对空指针解引用来形成引用
```

实测（`clang++ -std=c++20 -O0`）：

```
&r = 0x0   (是否等于 nullptr: 1)

warning: reference cannot be bound to dereferenced null pointer in well-defined C++ code;
         comparison may be assumed to always evaluate to false [-Wtautological-undefined-compare]
```

两点值得注意：

1. `&r` 实测就是 `0x0`——「空引用」在运行时**确实可以存在**；
2. clang 的警告是 `-Wtautological-undefined-compare`，意思是**编译器编译期就知道这个比较恒为假**——因为标准规定这是 UB，编译器有权假设它不发生。

所以：

- 写代码：引用参数**不需要判空**（引用优于指针的真实收益）；
- 读代码：看到「解引用结果绑到引用」，要知道这是刀尖上走；
- HFT：省下的是分支预测成本，代价是**上游一旦给空指针就是 UB**，契约必须在上游用断言锁死。

## 临时量生命周期延长：规则与例外

```cpp
const int& r  = 42;   // ✅ 合法：物化一个临时量并延长其生命周期
int& r2       = 42;   // ❌ 编译错误：非常量引用不能绑临时量
```

规则原文（cppreference[^refinit]）：

> "Whenever a reference is bound to a temporary object or to a subobject thereof, the lifetime of the temporary object is extended to match the lifetime of the reference"

`-O0` 汇编里能看到「物化」确实发生（`mov w9, #42` → `stur w9, [x29,#-44]`），运行期 `&cr` 是个真实栈地址。

**但例外比规则更容易考**——以下情形**不延长**：

| 情形 | 后果 |
|------|------|
| `return` 语句里绑到返回值的临时量 | 立即销毁 → 返回悬空引用（C++26 起该写法 ill-formed） |
| 函数调用的**引用参数**上的临时量 | 只活到包含该调用的**完整表达式**结束 |
| `new` 表达式初始化器里绑定的临时量 | 只活到该 `new` 所在完整表达式结束，**不跟对象同寿** |
| 聚合用**括号**初始化的引用成员（C++20） | 悬空；用**花括号**才延长 |

还有一条总纲：

> "In general, the lifetime of a temporary cannot be further extended by 'passing it on'"

即 **延长不可传递**——从 `const&` 再初始化一个 `const&`，不会二次延长。

## 和 C 的区别（重点：引用是 C++ 独有）

**C 没有引用**——所有间接访问都靠指针。引用是 C++ 给 C 程序员的"安全糖"：

| 对比点 | C（只有指针） | C++（有引用） |
|--------|--------------|---------------|
| 间接访问 | `void f(int* p)` 调用要 `f(&x)` | `void f(int& r)` 调用直接 `f(x)` |
| 判空 | 必须判 `p != NULL` | 引用不能为空，不用判 |
| 改指向 | `p = &other` 随时改 | 引用绑定后不能换 |
| 解引用 | `*p` | 直接用 `r`，像普通变量 |
| 指针运算 | `p++` 可越界 | 引用没有运算 |

调用方与被调方的写法差异（汇编层面两者等价，见上文 `Increment` 实测）：

```c
/* C：传参要取地址，函数里要解引用 */
void bump(int *p) { (*p)++; }
int x = 5;
bump(&x);          // 调用方要写 &，容易忘
```
```cpp
// C++：引用让传参像普通变量
void bump(int &r) { r++; }
int x = 5;
bump(x);           // 调用方不用写 &，更自然
```

**给 C 程序员的关键转变：**

1. 函数参数优先用 `const T&`（只读不拷贝），替代 C 的 `const T*`
2. 要修改入参用 `T&`，替代 C 的 `T*`
3. 只有"可选/可为空/要改指向/数组"才用指针
4. C 里 `&x` 是取地址，C++ 里 `int &r = x` 是声明引用——同一个 `&` 符号，**位置决定含义**（声明里 `&` 在类型后=引用，表达式里 `&x`=取地址）

## 零开销？引用并不比指针快（HFT 关联）

`const T&` 省下的是**整个对象的拷贝**，这个收益是量级级别的。用拷贝构造函数计数（确定性，不受优化噪声影响）：

```cpp
struct Big { char buf[4096]; long long x; /* 自定义拷贝构造，拷贝时 ++copies */ };
__attribute__((noinline)) long long by_value(Big b)       { return b.x + b.buf[0]; }
__attribute__((noinline)) long long by_cref(const Big& b) { return b.x + b.buf[0]; }
```

`-O2`，各调用 1000 次：

```
by_value : 1000 次调用 -> 1000 次拷贝构造 (约 3.9 MB 内存搬运)
by_cref  : 1000 次调用 -> 0 次拷贝构造
by_ptr   : 1000 次调用 -> 0 次拷贝构造
sizeof(Big) = 4104
```

**这就是 HFT 里 `const Order&` / `const OrderBook&` 传参的全部动机**：省掉的是整个对象的拷贝。

但三条必须澄清：

1. **小标量（`int` / `double` / 指针）传值通常比传引用快**——传值走寄存器，传引用要先取地址再解引用，多一层间接。`const int&` 只在大对象上划算。
2. **引用并不比指针快**——上文已证 ABI 层两者等价，优化器对两者处理能力也一致。选引用是为了**契约清晰**，不是为了性能。
3. **引用会带进别名（aliasing）不确定性**——编译器看到 `const T&` 无法像局部值那样自由重排，某些场合传值反而让优化器更放得开。

一句话：**引用买的是「安全 + 可读」，性能是「不亏」而不是「更赚」。**

## 常见错误

**1. 引用不初始化**
```cpp
int &ref;   // 编译错误：引用必须初始化
```
引用没有"空状态"，定义时必须绑定。

**2. 引用绑定后试图改绑**
```cpp
int a = 1, b = 2;
int &ref = a;
ref = b;    // 这不是改绑！是把 b 的值赋给 a（a 变成 2）
```
`ref = b` 是赋值，不是重新绑定。引用一旦绑定 `a`，一辈子就是 `a` 的别名。
（实测：`after r=b -> a=2 b=2  (&r==&a)=1`——`&r` 依然等于 `&a`。）

**3. 局部引用返回悬空**
```cpp
int& bad() {
    int x = 42;
    return x;   // 悬空引用：x 出函数就销毁
}
```
返回引用要确保被引用的对象生命周期够长（如类的成员、静态变量、堆对象）。

**4. 用 UB 制造「空引用」**
```cpp
int* p = nullptr;
int& r = *p;     // UB：能编过，&r 实测 == 0x0，但后续使用就是未定义行为
```
语言不允许空引用，不代表造不出来。引用参数之所以「不用判空」，是**前提**由调用方保证，不是编译器会帮你兜。

**5. 类里放引用成员**
```cpp
struct S { int& r; };   // sizeof(S) == 8：引用成员占存储
```
会改变类大小，且该类**不能默认构造、不能赋值**（引用不可改绑），写容器时是常见坑。

## 自测题

**1（选择）** 下面代码执行后 `a` 是多少？
```cpp
int a = 1, b = 2;
int &ref = a;
ref = b;
```
- A. 1
- B. 2
- C. 编译错误

**2（判断）** `const int &r = 42;` 合法，`int &r = 42;` 不合法。

**3（踩坑）** 下面函数有什么问题？
```cpp
int& get_value() {
    int local = 100;
    return local;
}
```

**4（选择）** 64 位平台上 `sizeof(struct { int& r; })` 最可能是？
- A. 0（引用不占存储）
- B. 4（等于 int）
- C. 8（等于一个指针）

**5（实战）** `struct Order { char payload[256]; };`，`void send(const Order& o)` 与 `void send(Order o)` 相比，单次调用差多少内存搬运？

<details><summary>参考答案</summary>

1. B。`ref = b` 是赋值（把 b 的值 2 赋给 ref 引用的 a），不是改绑。引用绑定 a 后不能换，a 变成 2。
2. 对。`const int&` 可绑定到字面量（编译器生成临时量并延长其生命周期）；`int&` 不能绑字面量（字面量不可寻址、不能改）。注意：这个延长有 4 条例外（`return` 语句、函数调用的引用参数、`new` 初始化器、C++20 聚合的括号初始化），别把它当成万能。
3. 悬空引用。`local` 是局部变量，函数返回时销毁，返回的引用指向无效内存。调用者用这个引用是 UB。返回引用要保证对象存活（成员、静态、堆）。
4. **C**。引用成员通常占一个指针大小的存储（本机 clang 23.1.0 实测 `sizeof(RefMember) == 8`）。cppreference：reference 数据成员 "usually increases the size of the class by the amount necessary to store a memory address"。
5. 差 **256 字节 / 次**（按值传参每次都完整拷贝一份 `payload`；`const&` 不拷贝）。本节的 4104 字节版本实测是 1000 次调用 → 1000 次拷贝构造 ≈ 3.9 MB 搬运，`const&` 版本为 **0**。真正的判据不是「256 字节看着不大」，而是**调用频次**：HFT 里每秒百万次调用 = 每秒 256 MB 的无谓内存带宽。
