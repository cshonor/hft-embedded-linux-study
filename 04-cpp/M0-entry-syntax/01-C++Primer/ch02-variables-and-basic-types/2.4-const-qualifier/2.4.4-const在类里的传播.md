# 2.4.4 const 在类里的传播：从对象到成员函数

[← 2.4.3 constexpr 详解](./2.4.3-constexpr详解.md) | [2.4 const 限定符](./2.4-const限定符.md) | [7.1 定义抽象数据类型](../../ch07-classes/7.1-定义抽象数据类型.md)

## 本节讲什么

2.4.1 和 2.4.2 讲的是**变量自身**带不带 `const`：顶层还是底层、`const` 在 `*` 左边还是右边。这一节讲 `const` 进入类之后发生了什么——它顺着 `this` 传给**每一个成员**，以及唯一的例外 `mutable`。

本篇只补**类型机制**（`this` 的类型怎么变、报错为什么这么写、`const` 为什么能参与重载）。`const` 成员函数的语法入门与用法规范见 [7.1](../../ch07-classes/7.1-定义抽象数据类型.md)，`mutable` 的使用场景见 [7.4](../../ch07-classes/7.4-类的其他特性.md)，三处不重复。

## 一、现象：三条报错，同一个来源

Cherno 那集 `const` 的幻灯片里有一段代码，改成员时会立刻报错：

```cpp
class Entity {
    int m_X = 0, m_Y = 0;
public:
    int GetX() const { m_X = 2; return m_X; }   // 编译错误
};

void touch() {
    const int* const a = new int;
    *a = 1;          // 编译错误
    a  = nullptr;    // 编译错误
}
```

gcc 13.2，`-std=c++17 -Wall -Wextra`，原文：

```text
<source>:5:28: error: assignment of member 'Entity::m_X' in read-only object
<source>:11:8: error: assignment of read-only location '*(const int*)a'
<source>:12:7: error: assignment of read-only variable 'a'
```

三条措辞不同，来源是同一个：**被赋值的那一侧不是可修改左值**。

- 第 1 条说的是 `read-only object`，不是 `read-only variable`。编译器眼里被写的是 `*this`，不是 `m_X` 这个"变量"。
- 第 2 条把类型直接打了出来：`*(const int*)a`。
- 第 3 条才是 2.4.1 讲的顶层 `const`：指针本身只读。

## 二、机制：`const` 成员函数改的是 `this` 的类型

成员函数里的 `this` 是一个隐式参数，类型由函数声明尾部的 `const` 决定：

| 函数写法 | 函数体内 `this` 的类型 | 成员名 `m_X` 退化成的类型 | 能否赋值 |
|---|---|---|---|
| `int f()` | `Entity*` | `int` | 能 |
| `int f() const` | `const Entity*` | `const int` | 不能 |
| `int f() volatile` | `volatile Entity*` | `volatile int` | 能（但每次访问都读内存） |
| `int f() const volatile` | `const volatile Entity*` | `const volatile int` | 不能 |

`m_X` 在函数体里是 `this->m_X` 的简写，成员访问的结果继承对象表达式的 cv 属性。`this` 指向 `const Entity`，`m_X` 就是 `const int` 左值，赋值自然被拒。

这里要接回 2.4.1 的那张表：`const` 成员函数给 `this` 加的是**底层 const**（约束所指对象），不是顶层 const（约束指针本身）。`this` 本身是 prvalue，本来就不可赋值，加不加顶层 const 没有区别。

### 另一条报错把机制说得更直白

```cpp
struct S {
    void f() {}
};

int main() {
    const S s;
    s.f();          // const 对象调非 const 成员函数
}
```

```text
<source>:7:8: error: passing 'const S' as 'this' argument discards qualifiers [-fpermissive]
<source>:2:10: note:   in call to 'void S::f()'
```

这句话等于把成员函数的真实签名写出来了：

```cpp
void S::f(S* this);          // 源码里看到的
void S::f(const S* this);    // const 版本的真实形态
```

`const S` 对象只能提供 `const S*`，绑不到 `S*`——正是 2.4.1 里"拷贝/绑定不能丢弃底层 const"的同一条规则，只是这次被丢弃的是一个隐式参数。

## 三、传播链：`const` 会一层层往下传

同样一段"只读访问"，写在四个位置，`const` 的落点各不相同：

```cpp
const int   g = 1;                        // 变量
const int&  r = g;                        // 引用
const int*  p = &g;                       // 指针
const Entity e;                           // 对象
```

| `const` 加在谁身上 | 约束范围 | 传到哪里 |
|---|---|---|
| 变量 | 该变量自身 | 不传播 |
| 引用 / 指向 const 的指针 | 被绑/被指对象 | 通过它访问的一切都是 const |
| `const` 对象 | 对象本体 | **所有非 `mutable` 成员**都是 const |
| `const` 成员函数 | `*this` | 函数体内所有非 `mutable` 成员都是 const |

第四行就是这么来的：`const` 对象 → `this` 是 `const Entity*` → 成员全 const。三条路径，同一个机制。

### 溢出点：不能把 const 成员"漏"出去

传播是单向的，`const` 版本没法把自己变成可写引用返回：

```cpp
struct Buf {
    int data[4] = {};
    int& at(int i) const { return data[i]; }   // 想让 const 函数返回可写引用
};
```

```text
<source>:3:41: error: binding reference of type 'int&' to 'const int' discards qualifiers
```

这是写完 `const` 成员函数后第二高频的报错。要么返回 `const int&`，要么提供 `const` / 非 `const` 两个重载（`std::vector::operator[]` 就是这么做的）。

## 四、`mutable`：唯一能截断传播的修饰符

```cpp
class Entity {
    int m_X = 0;
    mutable int m_reads = 0;                        // 只有它能在 const 函数里写
public:
    int GetX() const { ++m_reads; return m_X; }     // 合法
    void SetX(int v) { m_X = v; }
    int Reads() const { return m_reads; }
};

int main() {
    Entity e;
    e.SetX(7);
    const Entity ce = e;

    int a  = e.GetX();
    int ra = e.Reads();
    int b  = ce.GetX();
    int rb = ce.Reads();
    std::printf("e.GetX()  = %d   e.Reads()  = %d\n", a, ra);
    std::printf("ce.GetX() = %d   ce.Reads() = %d\n", b, rb);
}
```

实测输出（gcc 13.2，`-std=c++17 -O0`）：

```text
e.GetX()  = 7   e.Reads()  = 1
ce.GetX() = 7   ce.Reads() = 1
```

`ce` 是 `const Entity`，`GetX()` 在里面照样能 `++m_reads`。机制上有两点要说清：

1. `mutable` 只写在**非静态数据成员**的声明上，是声明说明符的一部分。
2. 它的作用不是"绕过 const 检查"，而是让这个成员在 cv 传播时**不被加上 `const`**——所以在 const 对象里，`m_reads` 的类型仍是 `int`，是可修改左值。

`mutable` 不改布局、不加运行期检查（`sizeof(Entity)` 不变），只在类型系统里生效。

### 三条纪律

- **只给"逻辑只读、物理会变"的成员**：缓存、访问计数、懒初始化标志。真正影响对象状态的成员设 `mutable`，等于让 `const` 承诺作废。
- **`mutable` + `const` 成员函数 = 这个函数不再是只读的**。原先"const 方法可以并发调用"的假设直接失效，必须自己加同步。这是 HFT 代码里最容易忽略的一条（见第七节）。
- **不能用于静态数据成员**，也和引用成员没有意义（引用本身绑定后不可变）。

## 五、`const` 参与重载：编译出的是两个独立函数

```cpp
struct Over {
    int f()       { return 1; }
    int f() const { return 2; }
};
```

```text
o.f()  = 1
co.f() = 2
```

反汇编（gcc 13.2，`-std=c++17 -O0`）能看清调用点是怎么选的：

```text
call_nonconst(Widget&):
        call    Widget::f()

call_const(Widget const&):
        call    Widget::f() const
```

两个版本是**两个独立符号**，各自有函数体，调用点在编译期静态绑定。选择规则只有一条——隐式对象参数谁更匹配：

| 对象 | 隐式对象参数 | 候选 | 选中 |
|---|---|---|---|
| 非 const 对象 | `T&` | 两个都能绑 | 非 const 版（`T&` 精确匹配，`const T&` 需要加限定） |
| const 对象 | `const T&` | 只有 const 版能绑 | const 版 |
| const 对象，且只有非 const 版 | `const T&` | 无 | 报 `discards qualifiers` |

符号名层面，Itanium ABI 会把成员函数的 cv 限定编进名字（const 版本带 `K`，例如 `_ZNK6Widget1fEv`），这是它俩能共存在同一个目标文件里的原因。该编码规则属 ABI 规范，本次只核到汇编里的两个独立标签与两条不同的 `call`，未直接抓符号表。

一条设计提醒：`const` 重载通常应该**语义一致、只是可写性不同**（`begin()` 返回 `iterator` / `const_iterator`）。如果两个版本干的是不同的事，说明这个名字承担了两个职责。

## 六、`const int* const a = new int`：回到 2.4.1

```cpp
const int* const a = new int;
```

- 第一个 `const`（在 `*` 左边）：底层 const，`*a` 不可写。
- 第二个 `const`（贴 `a`）：顶层 const，`a` 不能改指向。
- 两个都占：值和指向都锁死，对应报错原文第 2、3 条。

这行还有一个与 `const` 无关的坑：`new int` **不带初始化**，`*a` 的值不确定，读它是未定义行为。它只适合演示类型，真要用就写 `new int(0)`。四种指针形态的辨析见 [2.4.1](./2.4.1-const基础与constexpr.md) 与 [2.4.2](./2.4.2-const口诀与声明语法.md)，这里不重复。

## 七、`const_cast` 的正确边界

`const` 成员函数想调一个历史遗留的非 const 接口时，代码通常长这样：

```cpp
class Cache {
    int v = 0;
public:
    void legacy_write() { v = 1; }
    void call_legacy() const {
        const_cast<Cache*>(this)->legacy_write();   // 编译通过
    }
};
```

能编译通过，但不等于合法。判据只有一条：**对象本体是不是 const**。

| 场景 | 行为 |
|---|---|
| 对象本身非 const，只是通过 `const` 引用/指针访问 | 去掉 const 再写，定义良好 |
| 对象本身是 `const` 对象 | **未定义行为**（修改 const 对象） |
| 数据放在只读内存（`.rodata`、ROM） | 写入触发段错误或硬件异常 |

所以 `const_cast` 不是"临时关掉检查"，而是"我保证这个对象本来就不是 const"。真正的 const 成员函数想改缓存，用 `mutable` 而不是 `const_cast`——这就是 `mutable` 存在的理由。

## 和 C 的区别

C 里没有成员函数，只读语义全靠形参上的 `const` 指针：

```c
struct Entity { int m_X, m_Y; };

int entity_get_x(const struct Entity *e) {
    /* e->m_X = 2; */          /* 同样编译错误：e 指向 const */
    return e->m_X;
}
```

单看这一句，C 和 C++ 的强制力是一样的。差别在别处：

| 维度 | C | C++ |
|---|---|---|
| 只读承诺的位置 | 形参类型（`const struct T *`） | 函数类型（成员函数尾部 `const`） |
| 能否参与重载 | 不能（`f(const T*)` 与 `f(T*)` 是两个不同名字才行） | 能，`f()` / `f() const` 直接共存 |
| 能否被调用方检查 | 靠头文件里写了 `const` 没有 | 编译器按对象 cv 属性选重载，漏写 const 立刻报错 |
| 传播到成员 | 无（struct 无成员函数） | 传播到所有非 `mutable` 成员 |
| `mutable` | 无 | 有 |
| 进入符号名 | 不影响 | 进入 mangled name，所以能共存 |

一句话：**C 的 `const` 只保证"通过这个指针不能写"，C++ 的 `const` 后缀还多了一层"这个函数承诺不改对象"，而且这层承诺是函数类型的一部分。**

## HFT / 嵌入式关联

**1. `const` 成员函数零运行开销。** 它不进对象布局、不加运行期检查，反汇编里就是普通函数。所以"接口一律标 const"不花任何代价，只买到调用方可以传 `const&` 不拷贝（2.4.2 的 `const Order&`）。

**2. `mutable` 在热路径上有两个隐性代价。** 一是**破坏并发只读假设**：`const` 成员函数里写 `mutable` 计数，等于在"只读"接口里塞了写操作，多线程下就是数据竞争。二是**伪共享**：计数器与业务数据挨在同一个 cacheline，每次自增都把别的核上正在读这条 cacheline 的线程打掉。要做统计就 per-thread 累加、或单独 cacheline 对齐，别塞进 `mutable`。

**3. 嵌入式：`const` 和 `volatile` 管的是两个不同维度。** `const` 约束"程序能不能写"，`volatile` 约束"编译器能不能优化掉访问"。寄存器场景必须两个一起看：

```c
const volatile uint32_t *CHIP_ID  = (uint32_t *)0x40000000;  /* 只读状态寄存器 */
volatile uint32_t       *CTRL     = (uint32_t *)0x40000004;  /* 普通读写寄存器 */
const uint32_t          *LUT      = lut_rom;                 /* 常量表，放 ROM/flash */
```

| 声明 | 程序可写 | 值会被外部改变 | 典型用途 |
|---|---|---|---|
| `const uint32_t *` | 否 | 否 | 常量表、只读数据 |
| `volatile uint32_t *` | 是 | 是 | 普通 MMIO 寄存器 |
| `const volatile uint32_t *` | 否 | 是 | 芯片 ID、硬件自增计数器、只读状态位 |
| `uint32_t *` | 是 | 假定否 | 普通内存 |

`const volatile` 看着别扭，其实是唯一能正确描述"程序只读、硬件会改"的组合。只写 `const` 会让编译器把多次读折叠成一次，读到的是旧值。

## 常见错误

**1. `const` 成员函数里给成员赋值**

```cpp
int GetX() const { m_X = 2; return m_X; }   // read-only object
```

先问"这个函数真的改状态吗"。真改就去掉 `const`；只是缓存/计数才用 `mutable`。给核心数据加 `mutable` 是掩盖设计问题。

**2. 只读接口忘了标 `const`**

```cpp
int GetX() { return m_X; }        // 漏了 const
const Entity e;
e.GetX();                         // discards qualifiers
```

这是实际项目里最常见的 API 缺陷：`const` 对象调用不了查询接口。修法是给所有不修改对象的成员函数补 `const`。

**3. `const` 成员函数返回非 const 引用**

```cpp
int& at(int i) const { return data[i]; }   // binding reference ... discards qualifiers
```

返回 `const int&`，或者加一个非 const 重载。

**4. 用 `const_cast` 硬改真正 const 的对象**

编译能过，运行是 UB，甚至直接段错误（对象在 `.rodata`）。判据见第七节。

**5. 以为 `const` 是运行期保护**

它只存在于编译期和类型系统里。`const_cast`、缓冲区越界、悬垂指针都能绕过去。`const` 是接口契约，不是安全边界。

## 代码自测

**1（机制）** 下面这段为什么编不过？请用 `this` 的类型解释。

```cpp
struct A { int x = 0; int get() const { x = 1; return x; } };
```

**2（重载）** `void f()` 与 `void f() const` 为什么能共存？非 const 对象调用时选哪个，为什么？

**3（mutable）** `mutable int cnt;` 在 `const A a;` 里，`a.cnt` 的类型是什么？为什么可写？

**4（判定）** 下面哪几行是安全的？

```cpp
void g(const A& r, A& m, const A* p) {
    const_cast<A&>(r).x = 1;          // 行 1
    const_cast<A&>(m).x = 2;          // 行 2
    const_cast<A*>(p)->x = 3;         // 行 3
}
```

<details>
<summary>参考答案</summary>

1. `get()` 尾部带 `const`，函数体内 `this` 的类型是 `const A*`，成员 `x` 退化为 `const int` 左值，`x = 1` 就是给只读对象赋值。报错原文是 `assignment of member 'A::x' in read-only object`——被写的是 `*this`，不是 `x` 这个变量。修法：去掉 `const`（它确实改状态），或把 `x` 改成缓存语义并标 `mutable`。

2. 因为 `const` 进入的是**隐式对象参数的类型**：`f()` 等价于 `f(A*)`，`f() const` 等价于 `f(const A*)`，函数参数表不同就是不同的重载，符号名也不同（Itanium ABI 里 const 版本带 `K`）。非 const 对象调用时选非 const 版——`A&` 是精确匹配，`const A&` 需要加限定；重载决议优先选限定更少的。实测：`o.f()` 得 1，`co.f()` 得 2。

3. 类型是 `int`（不是 `const int`）。`mutable` 的作用是让这个成员在 cv 传播时不被加上 `const`，所以即便对象是 `const A`，`a.cnt` 仍是可修改左值。它不改布局、不加运行期检查，只在类型系统里生效。

4. 只有**行 2** 安全。判据是对象本体是不是 const，不是手上的引用带不带 const：`m` 绑定的对象非 const，去掉 const 再写定义良好；`r` 与 `p` 指向的对象**可能**是真正的 const 对象（函数签名看不出来，取决于调用方），写入是未定义行为——`p` 更危险，const 对象可能落在只读段。

</details>
