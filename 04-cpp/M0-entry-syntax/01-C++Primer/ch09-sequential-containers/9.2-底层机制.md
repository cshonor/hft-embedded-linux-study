# 9.2 底层机制

## 本节讲什么

`vector`/`string` 等可变长容器的**扩容机制**：`capacity`（容量）vs `size`（元素数）、`reserve` 预留、`shrink_to_fit` 收缩。理解这个机制能避免性能尖峰和迭代器失效——对 HFT 尤为关键。

## 核心用法

### size vs capacity

```cpp
std::vector<int> v;
v.reserve(100);          // 预留 100 容量，不创建元素
std::cout << v.size();       // 0（没有元素）
std::cout << v.capacity();   // 100（已分配空间）

for (int i = 0; i < 100; ++i) v.push_back(i);
// 这 100 次 push_back 不会扩容（capacity 够用）

v.push_back(101);        // 超过 capacity，触发扩容
// 扩容：1) 分配更大空间（通常 2 倍）2) 拷贝/移动旧元素 3) 释放旧空间
// 此时所有旧迭代器/指针/引用全部失效！
```

### 扩容代价

扩容要：1) 分配新内存；2) 拷贝/移动所有旧元素到新内存；3) 析构旧元素；4) 释放旧内存。是 O(n) 操作。如果不 reserve，n 次 push_back 总扩容代价是 O(n) 摊还 O(1)，但单次扩容可能造成**延迟尖峰**。

### push_back 到底拷贝几次：形参写法 × 实参形态

这是最容易吵起来、也最容易被讲错的点。**拷贝次数由两个独立变量决定**：`push_back` 的**形参怎么写** + 调用处传的**实参是什么形态**。两者不分开谈，就一定答错。

**先记住一个前提**：`std::vector::push_back` 的签名只有两个重载，**从来不是值传递**：

```cpp
void push_back(const T& value);   // C++98 就有的左值版本
void push_back(T&& value);        // C++11 起的右值版本
```

> ⚠️ 网上/视频里讲的"传值进来拷贝一次"往往是**手写版** `void push_back(T value)`（值传递），那套代码下"2 次拷贝"是对的。但它不是标准库的 `push_back`，两者不能混着说。

**实测一：形参写法 × 实参形态（不含扩容，`T` 为带拷贝/移动构造的类类型）**

| 形参写法 | 传左值 `x` | 传临时对象 `T(7)` | 传 `std::move(x)` |
|---------|-----------|------------------|------------------|
| `T value`（值传递，手写版常见） | **拷贝 2 次** | 拷贝 1 次（C++17 保证省略入参那次） | 拷贝 1 + 移动 1 |
| `const T&` | **拷贝 1 次** | 拷贝 1 次 | 拷贝 1 次（⚠️ move 被吃掉） |
| `T&&` | 编译错误（右值引用不绑左值） | 移动 1 次 | 移动 1 次 |
| `T* p`（指针） | 拷贝 1 次（对象）+ 指针地址拷贝（8 字节） | — | — |

关键读法：

- **值传递 `T value`**：入参构造一次（`x` → `value`），再存入数组一次 → 左值下 **2 次拷贝**。C++17 传临时对象时入参那次被强制省略，只剩 1 次。
- **引用/指针传递**：**绑定引用本身零开销**，不是拷贝。只有"存进内部数组"那 1 次。所以 `const T&` 传左值 = **1 次拷贝**。
- **指针传递**：拷的是地址（8 字节），不是对象；但只要容器存的是对象（`vector<T>`），把 `*p` 放进去仍要 **1 次对象拷贝**。只有改成 `vector<T*>` 才做到 0 次对象拷贝——代价换成生命周期和悬垂指针问题。
- ⚠️ **`const T&` + `std::move(x)` = 白 move**：`std::move` 只把 `x` 转成右值，`const T&` 照样能绑定，函数体内只能拷贝。实测仍是拷贝 1 次、移动 0 次。要移动必须走 `T&&` 重载。

**实测二：`std::vector` 真实开销（`reserve` 过，容量有富余、无扩容）**

| 写法 | 拷贝 | 移动 |
|------|------|------|
| `v.push_back(x)`（左值变量） | **1** | 0 |
| `v.push_back(T(7))`（临时对象） | 0 | **1** |
| `v.push_back(std::move(x))` | 0 | **1** |
| `v.emplace_back(7)`（原地构造） | **0** | **0** |

**实测三：扩容是独立事件，跟上面叠加计算**

触发扩容时总代价 = 本次新元素 1 次 + 旧元素 N 次搬迁。旧元素搬运用**移动还是拷贝**，取决于元素类型的移动构造是否 `noexcept`（强异常安全保证）：

| 元素类型 | 拷贝 | 移动 | 说明 |
|---------|------|------|------|
| 移动构造 `noexcept` | 1（新元素 x） | 4（旧元素） | 旧元素逐个移动 |
| 移动构造**非** `noexcept` | **5** | 0 | 退化成全部拷贝 |

> 这正是 Effective C++ Item 14 / Item 29 强调"移动操作要标 `noexcept`"的直接原因：少标一个 `noexcept`，vector 每次扩容从移动退化成拷贝。
> 扩容倍数实测（libc++）：1 → 2 → 4 → 8（libstdc++ 同为 ×2，MSVC 为 ×1.5）。

**完整答案（把它背下来）**

- `std::vector` 的 `push_back(x)`（x 是普通变量，容量够）：**1 次拷贝**，不是 2 次——形参是 `const T&`，绑定引用不产生拷贝。
- 手写版 `push_back(T value)` 传左值：**2 次拷贝**（入参 1 次 + 存入数组 1 次）。标准库不用值传递，正是为了省掉入参这次。
- 传指针/引用：**入参传地址零开销**，但对象要进容器仍要 1 次（除非容器存指针）。
- 扩容：额外搬 N 个旧元素，`noexcept` 移动时为移动，否则为拷贝。**只在 `size == capacity` 时发生**，不是每次 push 都有。

<details><summary>实测代码（计数器版，clang -std=c++17）</summary>

```cpp
#include <cstdio>
#include <vector>
#include <utility>

static int g_copy = 0, g_move = 0;
struct T {
    int v;
    explicit T(int x) : v(x) {}
    T(const T& o) : v(o.v) { ++g_copy; }
    T(T&& o) noexcept : v(o.v) { ++g_move; }          // 对照组去掉 noexcept
};
alignas(T) unsigned char buf[sizeof(T)];

static void pb_value(T value)        { new(buf) T(value); }            // 值传递
static void pb_cref (const T& value) { new(buf) T(value); }            // const 引用
static void pb_rref (T&& value)      { new(buf) T(std::move(value)); } // 右值引用
static void pb_ptr  (T* p)           { new(buf) T(*p); }               // 指针

int main() {
    T x(7);
    std::vector<T> v; v.reserve(8);          // 保证无扩容
    // 逐个调用上面四个 + std::vector 四个写法，打印 g_copy / g_move 即可复现上表
}
```

去掉移动构造的 `noexcept` 重跑扩容场景，就能复现"拷贝 5 / 移动 0"的退化现象。

</details>

### 管理工具

| 操作 | 作用 |
|------|------|
| `v.reserve(n)` | 预留至少 n 容量，不改变 size，避免后续扩容 |
| `v.resize(n)` | 改变 size 到 n（多则填充默认值，少则截断） |
| `v.shrink_to_fit()` | 请求释放多余容量（非强制） |
| `v.capacity()` | 查当前容量 |

## 和 C 的区别

| 维度 | C (`realloc`) | C++ (`vector`) |
|------|---------------|----------------|
| 扩容 | 手动 `realloc`，返回新指针 | 自动，对用户透明 |
| 迭代器/指针失效 | `realloc` 可能移动内存，旧指针失效（但 C 程序员常忽视） | vector 扩容明确使所有迭代器失效 |
| 预留 | 手动算 size + malloc 大块 | `reserve(n)` 一行 |
| 移动 vs 拷贝 | 只能 `memcpy`（浅拷贝，含指针时危险） | 元素有移动构造时优先移动，安全 |
| 失败处理 | `realloc` 返回 NULL，原内存仍在 | 抛 `bad_alloc` 异常 |

**C 程序员最该理解的两点**：

1. **扩容导致迭代器/指针/引用全部失效**。C 的 `realloc` 也有同样问题（可能移动内存），但 C 程序员常忽视——因为 C 里很少缓存"指向数组元素的指针"。C++ 大量用迭代器/引用，扩容失效问题更突出。

```c
/* C：realloc 后旧指针可能悬垂 */
int* p = arr;
arr = realloc(arr, new_cap);   // arr 可能换了地址
*p = 5;                        // p 指向旧地址，可能已释放！UB
```
```cpp
// C++：vector 扩容后迭代器失效，同样问题
auto it = v.begin();
v.push_back(x);     // 若扩容，it 失效
*it = 5;            // UB！
```

2. **`reserve` 是性能关键**。知道大致大小时先 reserve，避免反复扩容。

```cpp
std::vector<int> v;
v.reserve(1000);          // 知道要 1000 个，预留
for (int i = 0; i < 1000; ++i) v.push_back(i);  // 零扩容
```

## 常见错误

1. **缓存了迭代器/引用，扩容后继续用**：`auto& ref = v[0]; v.push_back(x); ref = ...;` —— 若 push_back 触发扩容，ref 悬垂。**修正**：扩容后重新获取；或 reserve 保证不扩容。
2. **在循环里 push_back 不 reserve**：n 次 push_back 触发约 log(n) 次扩容，每次拷贝所有元素，O(n log n) 浪费。**修正**：能预估大小就 reserve。
3. **混淆 `reserve` 和 `resize`**：`reserve(10)` 不创建元素（size 不变，不可下标访问）；`resize(10)` 创建 10 个元素（size=10，可 `v[0]`）。用错会导致 `v[0]` 越界或意外默认构造。
4. **把"绑定引用"当成"拷贝"**：`push_back(const T&)` 绑定引用零开销，传左值只有 1 次拷贝（存进数组那次）。常见误解是"先拷贝给形参再拷贝进容器 = 2 次"——那只对手写版 `push_back(T value)` 成立。**判别方法：看形参是 `T value` 还是 `const T&`/`T&&`**。
5. **对 `const T&` 用 `std::move`**：`v.push_back(std::move(x))` 只在走 `T&&` 重载时才变成移动；一旦形参是 `const T&`（或函数只接受 `const T&`），`std::move` 完全失效，仍是 1 次拷贝。

## 自测题

**0. 拷贝计数题**：`v` 是 `std::vector<T>`（`T` 有 `noexcept` 移动构造），已 `reserve(8)` 且当前 `size=3`。问以下每句各自产生几次拷贝、几次移动？

```cpp
T x(7);
v.push_back(x);              // ①
v.push_back(T(7));           // ②
v.push_back(std::move(x));   // ③
v.emplace_back(7);           // ④
```

<details><summary>答案</summary>

**都没有扩容**（capacity 8 > size 3），所以只算"存进容器"那一步：

| 写法 | 拷贝 | 移动 | 走的重载 |
|------|------|------|---------|
| ① `push_back(x)` 左值 | **1** | 0 | `const T&` |
| ② `push_back(T(7))` 临时对象 | 0 | **1** | `T&&` |
| ③ `push_back(std::move(x))` | 0 | **1** | `T&&` |
| ④ `emplace_back(7)` 原地构造 | **0** | **0** | 就地构造 |

**最容易答错的是 ①**：很多人答 2 次（"先拷贝给形参"），但形参是 `const T&`，**绑定引用不产生拷贝**，只有 1 次。

**如果容量正好用完**（比如 `size==capacity==3`），还要叠加扩容代价：新元素 1 次 + 旧元素 3 次移动（移动构造 `noexcept` 时），去掉 `noexcept` 就变成 3 次拷贝。

</details>

**1. 选择题**：下面代码后 `v.size()` 和 `v.capacity()` 至少是多少？
```cpp
std::vector<int> v;
v.reserve(50);
v.push_back(1);
```
- A) size=1, capacity=50
- B) size=50, capacity=50
- C) size=1, capacity=1
- D) size=50, capacity=1

<details><summary>答案</summary>

A。`reserve(50)` 让 capacity >= 50，但不创建元素（size 仍 0）。`push_back(1)` 让 size=1，capacity 不变（仍 >= 50，因为没超）。reserve 只影响容量不影响 size，这是和 resize 的关键区别。

</details>

**2. 判断题**：`v.reserve(100)` 后，`v[0]` 可以安全访问。

<details><summary>答案</summary>

错误。`reserve` 只分配内存（capacity=100），不创建元素（size=0）。`v[0]` 访问的是不存在的元素，越界 UB。要创建元素用 `resize(100)`（size=100，可访问 v[0]..v[99]）。这是 reserve/resize 最常混淆的点。

</details>

**3. 踩坑题**：下面代码想"先存第一个元素的引用，添加更多元素后用"，但崩溃了，为什么？
```cpp
std::vector<int> v = {1};
int& first = v[0];
for (int i = 0; i < 100; ++i) v.push_back(i);
std::cout << first;    // 崩溃或乱码
```

<details><summary>答案</summary>

`first` 是 `v[0]` 的引用。循环里 push_back 触发多次扩容，每次扩容 vector 内部内存搬家，`v[0]` 换了地址，`first` 成悬垂引用，访问 UB。**修正**：1) 先 `reserve(101)` 保证不扩容；2) 或扩容后重新 `first = v[0]`；3) 或存值而非引用 `int first = v[0]`（拷贝，不受扩容影响）。

</details>

**4. 应用题**：你要从网络读未知数量的消息存入 vector，但要求**零扩容延迟尖峰**（HFT 热路径）。设计策略。

<details><summary>答案</summary>

```cpp
std::vector<Msg> msgs;
msgs.reserve(ESTIMATED_MAX);    // 按经验预估上限预留

while (receiving) {
    if (msgs.size() == msgs.capacity()) {
        // 接近上限，要么丢弃、要么预留更大、要么报错
        // HFT 热路径宁可丢消息也不要扩容尖峰
        handle_overflow(msgs);
        break;
    }
    msgs.emplace_back(read_msg());
}
```
HFT 策略：1) 启动时 reserve 到预估上限；2) 监控 size 接近 capacity 时主动处理（丢/转储），绝不触发扩容；3) 极端情况用固定大小环形 buffer（vector 预留 N + 取模索引），彻底消除动态分配。原则：热路径零分配。

</details>
