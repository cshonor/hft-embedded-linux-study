19.1

内存分配与 new 重载

本节讲什么

new 不是一个操作，是两个：先调 operator new 拿内存，再在内存上调构造函数。 理解这个分层，才能谈 placement new、自定义分配器、内存池——以及为什么 "内存池"是 HFT 的基础设施。代码均经本机 g++ 13.3 / -std=c++17 实测（2026-10-07）。

① new 的两层结构（这是全节的钥匙）

T* p = new T(args);
// 等价于：
//   void* raw = operator new(sizeof(T));   // 第一层：裸分配（可重载！）
//   T* p = new (raw) T(args);              // 第二层：在 raw 上构造（placement new）
//
// delete p;
// 等价于：
//   p->~T();                               // 先析构
//   operator delete(p);                    // 再释放（可重载）

推论：想控制"内存在哪分配"，重载 operator new/delete； 想控制"在指定内存上构造"，用 placement new。两件事独立。

② 重载全局 operator new/delete（实测）

#include <new>
#include <cstdlib>
#include <iostream>
void* operator new(std::size_t n) {
    std::cout << "global new " << n << "B\n";
    return std::malloc(n);
}
void operator delete(void* p) noexcept { std::free(p); }
void operator delete(void* p, std::size_t) noexcept { std::free(p); }  // C++14 sized delete

int main() {
    int* p = new int(1); delete p;     // 打印 global new 4B
    struct Big { char buf[100]; };
    Big* b = new Big; delete b;        // 打印 global new 100B
}

本机实测输出：global new 4B / global new 100B —— 每次 new 都经过我们的重载。

要点： - sized delete（带 std::size_t 第二参）：C++14 起编译器优先选它， 让自定义分配器不用存分配大小就能释放（slab/池分配器的关键） - 类内重载：struct T { static void* operator new(size_t); }——只对该类生效， 池化单个高频类型的标准做法 - 重载是替换不是包裹：全局版一旦重载，所有 new（包括标准库容器的）都走你的版本—— 埋点统计全局分配量就这么做，但要小心与第三方库的相互影响

③ placement new：在指定内存上构造（实测）

alignas(Big) char raw[sizeof(Big)];
Big* q = new (raw) Big;    // 只在 raw 上构造，不分配（实测：不触发 global new 打印）
q->~Big();                 // 必须手动析构！不能 delete q（raw 不是堆内存）

铁律：placement new 的对象手动析构、永不 delete； 内存的寿命由你（栈数组/mmap/池）负责。

HFT 主战场：

// 无锁队列的元素构造：环形缓冲区是预分配的，push 就是 placement new
template <typename T, size_t N>
class SpscRing {
    alignas(T) char buf_[N * sizeof(T)];
public:
    template <typename... Args>
    void emplace(Args&&... args) {
        new (&buf_[tail_ * sizeof(T)]) T(std::forward<Args>(args)...);   // 零分配
        tail_ = (tail_ + 1) % N;
    }
};

④ nothrow new 与 bad_alloc（实测）

int* r = new (std::nothrow) int[1UL<<40];   // 4TB 请求
// 本机实测：返回 nullptr，不抛 std::bad_alloc
  • 默认 new 失败抛 std::bad_alloc；new (std::nothrow) 失败返回 nullptr—— nothrow 版必须判空，否则解引用空指针
  • -fno-exceptions 环境（HFT 热路径库常见）里 new 失败的行为依赖运行时配置， 很多团队直接禁用裸 new：启动期池化一切，运行期零分配（→ 06.6.5 ch07 / 13-dpdk mbuf）

⑤ operator new 之外的三个分配控制点（全景）

控制点 粒度 用途
全局 operator new/delete 重载 全程序 分配统计/埋点；换 tcmalloc/jemalloc（其实直接用 LD_PRELOAD 更简单）
类内 operator new/delete 单类型 高频小对象池化（订单/行情消息的 per-type pool）
容器 Allocator 模板参数 单容器实例 std::vector<T, PoolAlloc<T>>——标准容器接管自定义内存（见 ch12 allocator）
placement new 单次构造 环形缓冲/共享内存/内存映射文件上的对象构造

和 C 的区别 / 新手要点

C C++
malloc/free 只搬内存 new/delete = 分配 + 构造/析构（两层）
无 placement new / operator new 重载 / nothrow
realloc 扩容 vector 扩容 = 新分配 + 移动/拷贝 + 析构旧块（没有原地扩容）

新手要点：① malloc 出来的内存不能 delete，new 的不能 free（分配器可能完全不同）； ② placement new 的 #include <new> 别忘；③ 重载 operator new 就必须配对重载 operator delete （含 sized 版）。

HFT 关联

  • 运行期零分配是低延迟系统的铁律：启动时池化所有订单/行情对象， 热路径的"new"实际是池的 acquire()（通常就是 freelist 弹出 + placement new）—— 本节的分层模型就是这个架构的语言基础
  • sized delete 让池分配器省掉 per-object 的大小头（8 字节/对象的元数据开销）—— 小对象池的密度优化
  • malloc 抖动来源（brk/mmap/锁竞争）在 06.6.5 ch07 有实测；jemalloc/tcmalloc 选型同理
  • 自定义 operator new 埋点是排查"谁在热路径偷偷分配"的最快手段（每分配打印 stack）

代码自测

题目 1： 下面错在哪？

char buf[sizeof(Foo)];
Foo* p = new (buf) Foo;
delete p;
参考答案

placement new 的对象构造在栈数组上，delete p 会把栈地址交给 operator delete （堆释放器）——UB。正解：p->~Foo(); 手动析构，栈内存随作用域自动回收。

题目 2： 为什么 C++14 的 sized delete 对内存池重要？

参考答案

sized delete（operator delete(void*, size_t)）在释放时直接告诉分配器块大小—— 池分配器不需要在每个对象头上存 size（省 8 字节/对象），也不需要查表推算归属池。 编译器在类型大小已知时优先选 sized 版（本机实测两版并存时 sized 版被调用）。

题目 3： std::vector<T> 能保证扩容时 T 的析构不泄漏吗？如果 T 的移动构造抛异常呢？

参考答案

扩容流程：分配新缓冲区 → 逐元素移动/拷贝到新缓冲区 → 全部成功后析构旧缓冲区。 移动构造若抛异常且未标 noexcept，vector 根本不敢用移动（改用拷贝，见 18.1 ② 实测）； 拷贝抛异常时，新缓冲区里已构造的元素逐个析构、释放新缓冲区、旧数据原样保留—— 这就是 vector 扩容的强保证。析构函数本身必须 noexcept，否则强保证无从谈起。

19.2

运行时类型信息补充 & 枚举进阶

本节讲什么

两块内容：① 18.4 RTTI 的延伸——type_info 还能做什么（type_index 作键、before 顺序）； ② 枚举的现代形态 enum class——为什么旧式 enum 在新代码里绝迹。 代码均经本机 g++ 13.3 / -std=c++17 实测（2026-10-07）。

① type_info 的三个工程用法（超出 typeid 比较）

#include <typeindex>
#include <map>
std::map<std::type_index, const char*> names;
names[typeid(int)] = "整数"; names[typeid(double)] = "浮点";
names[typeid(1.5)];      // 本机实测：取出"浮点"

typeid(int).before(typeid(double))   // 实测 0（int 排在 double 后）——实现相关的全程序一致序
  • std::type_index（C++11）：type_info 的可拷贝包装——type_info 本身不可拷贝 不能进容器，type_index 可以。做"类型 → 处理器"注册表的键
  • type_info::before：给全程序类型一个一致（但实现相关）的排序—— 排序键用途（std::map 默认键序、调试输出排序），不要跨进程/跨版本持久化这个序
  • .name()：mangled 名（St13runtime_error），只用于日志；可移植 demangle 用 abi::__cxa_demangle（GCC/Clang 专属）

注册表模式（动态工厂的 RTTI 版）：

std::map<std::type_index, std::function<void(const MsgBase*)>> handlers;
handlers[typeid(SnapMsg)]  = [](const MsgBase* m) { on_snap(static_cast<const SnapMsg*>(m)); };
handlers[typeid(TradeMsg)] = [](const MsgBase* m) { on_trade(static_cast<const TradeMsg*>(m)); };
// 分发：handlers[typeid(*msg)](msg);   ← typeid(*多态) 是动态类型（18.4 ②）

冷路径（启动注册/插件加载）这么写没问题；热路径还是查表/switch（→ 18.4 HFT 关联）。

② enum class：把 C 的枚举病一次治完（实测）

旧式 enum 的三宗罪，enum class（C++11）逐个治：

enum OldStyle { Red, Green };              // 罪1：枚举值泄进外层作用域（Red 直接可用，易撞名）
enum class Side : uint8_t { Buy = 1, Sell = 2 };

int y = Red;                    // 罪2：隐式转 int（本机实测 y=0 编译通过）
// int x = Side::Buy;           // ❌ 编译错误：enum class 不隐式转换
int x = static_cast<int>(Side::Buy);        // ✅ 必须显式

sizeof(Side) == 1               // 罪3 治疗：可指定底层类型（uint8_t），旧 enum 由编译器选
旧式 enum enum class（= enum struct）
作用域 枚举值泄进外层 必须 Side::Buy 限定
隐式转 int ✅（事故源） ❌ 必须 static_cast
底层类型 编译器自选（布局不可控） 可显式指定 : uint8_t
前向声明 只有指定底层类型才行 永远可以

协议场景的硬要求：跨网络/跨文件的枚举值必须定宽—— enum class MsgType : uint16_t，配 static_assert 钉布局（→ 19.5 ④）。

③ switch 穷尽性与编译器警告

switch (s) {
    case Side::Buy:  std::cout << "买\n"; break;
    case Side::Sell: std::cout << "卖\n"; break;
    // 漏一个枚举值：-Wswitch 警告（g++ 默认开）——枚举新增成员时全仓漏分支一目了然
}
  • enum class + switch 不加 default：让 -Wswitch 替你守穷尽性—— 协议加消息类型时编译器把所有没处理的 switch 列出来
  • 旧式 enum 也有 -Wswitch，但隐式转换让"拿个 int 就 switch"成为可能，防线形同虚设

和 C 的区别 / 新手要点

C C++
enum 就是 int 的花名 enum class 是真正的独立类型
无 type_index / type_info::before
#define SIDE_BUY 1 enum class Side : uint8_t（有类型、有作用域、可调试）

新手要点：① 新代码一律 enum class；② 协议枚举指定底层定宽类型； ③ 旧代码里新旧混用时，转换全走 static_cast，别写 (int)e 这种 C 强转。

HFT 关联

  • 行情/订单协议的每个枚举都必须定宽（Side : uint8_t、MsgType : uint16_t）—— 否则结构体布局随编译器漂移，解码错位（→ 19.5 static_assert 三件套）
  • switch 穷尽性 + -Wswitch 是"交易所加消息类型"时的编译期验收—— 比运行时漏处理安全一个数量级
  • type_index 注册表用于策略插件系统（冷路径）；热路径分发用 msg_type 查表（19.3 成员指针表）或 variant+visit（M5）

代码自测

题目 1： 为什么 enum class Color { Red, Green }; enum class Light { Red, Green }; 能共存， 而两个旧式 enum 这么写就报错？

参考答案

旧式 enum 的枚举值泄进外层作用域——两个 Red 在同一作用域重定义。 enum class 的枚举值封闭在自己的作用域里（Color::Red / Light::Red），互不干扰。 这正是"罪1：作用域污染"的解药。

题目 2： std::map<std::type_index, Handler> 能直接用 typeid(T) 作键， 为什么 type_info 本身不行？

参考答案

std::type_info 不可拷贝（拷贝构造/赋值被删除）——容器要求元素可拷贝或可移动， 所以 typeid 返回的 const type_info& 不能直接存。std::type_index 是标准库给的 可拷贝包装（内部存指针 + 提供比较运算符），就是为"类型作键"这个场景设计的。

题目 3： 协议枚举从 2 个值加到 3 个，但发版后解码端没更新——enum class 能救你吗？

参考答案

不能——enum class 只保证编译期类型安全，管不了线上版本错配。 解码端 switch 遇到未知的第 3 个枚举值时走 default/未定义分支。 真正的防线是：① switch 穷尽性检查（编译期，防"代码没改全"）； ② 协议版本协商/拒绝未知 msg_type（运行期，防"版本没对齐"）； ③ golden-packet 回放测试（发版前，防"新老不兼容"）。 enum class 解决的是语言层问题，协议演进是工程层问题，各管一段。

19.3

类成员指针

本节讲什么

"指向成员的指针"（pointer to member）是 C++ 独有的指针类别——它指向的是 类的某个成员而不是某个对象：同一个成员指针，配不同的对象实例就能访问不同对象的同一成员。 本节覆盖成员数据指针、成员函数指针、.*/->* 运算符，以及它在回调表/状态机里的真实用途。 代码均经本机 g++ 13.3 / -std=c++17 实测（2026-10-07）。

① 成员数据指针

struct W { int v = 7; };
int W::*pd = &W::v;        // 注意：&W::v 取的是"成员"，不是某个对象的字段

W w; W* pw = &w;
w.*pd    == 7              // 对象 . * 成员指针
pw->*pd  == 7              // 对象指针 ->* 成员指针（本机实测均通过）
  • 类型写法：int W::*（"W 的 int 成员"）；本质是成员在对象内的偏移量（不是地址！）
  • 所以它可以便宜地复制、放数组当"字段选择器"

② 成员函数指针（语法全 C++ 最丑，没有之一）

struct W {
    int v = 7;
    int add(int a, int b) { return a + b + v; }
};
int (W::*pf)(int, int) = &W::add;          // 声明：返回类型 (类::*名)(参数表)
(w.*pf)(1, 2);        // = 10（本机实测）
(pw->*pf)(3, 4);      // = 14
// 调用必须带对象：成员函数有隐式 this，裸成员指针没法独立调用

记忆法：.*/->* 的优先级低于函数调用，括号一个都不能少： (w.*pf)(1, 2) —— 先 (w.*pf) 拿到函数，再 (1, 2) 调用。

③ 和普通函数指针的关键差异（实测）

int (*fp)(int) = twice;                    // 普通函数指针
sizeof(fp) == 8                            // x86_64：一个代码地址
sizeof(pf) == 16                           // 本机实测：成员函数指针 16 字节！

本机实测：sizeof(fp)=8 vs sizeof(pf)=16——成员函数指针要带两份信息： 代码地址 + this 调整量（虚函数时存 vtable 槽位，多重继承时存基类偏移）。 所以不能把它和 void*/普通函数指针互相转换，也不能 printf("%p", pf)。

④ 真实用途：状态机 / 命令分发表（替代 switch）

struct FeedHandler {
    void on_snap(const Msg& m) { /* 快照 */ }
    void on_incr(const Msg& m) { /* 增量 */ }
    void on_trade(const Msg& m) { /* 逐笔 */ }
};
// 协议 msg_type → 处理函数的跳转表：一次数组索引代替 switch 链
using Handler = void (FeedHandler::*)(const Msg&);
static constexpr Handler table[] = {
    &FeedHandler::on_snap,    // 0 = SNAP
    &FeedHandler::on_incr,    // 1 = INCR
    &FeedHandler::on_trade,   // 2 = TRADE
};
void dispatch(FeedHandler& h, const Msg& m) {
    (h.*table[m.type])(m);    // O(1) 查表，无虚函数、无分支链
}

这就是成员函数指针的经典工业用法：把"对象+操作"的绑定推迟到查表时刻。 （现代 C++ 也常用 std::function/模板 lambda 表达同样意图—— 成员指针版零类型擦除、可 constexpr，热路径仍有其一席之地。）

⑤ 与现代替代品的对照

方案 开销 适用
成员函数指针 + 表 一次间接调用，可 constexpr 类型固定、热路径跳转表
虚函数 vtable 跳转 类型层次开放的运行期多态
std::function 类型擦除（可能分配） 类型不固定的通用回调
模板 + lambda 零开销（内联） 编译期已知的分发

和 C 的区别 / 新手要点

C C++
函数指针 int (*fp)(int) 成员指针必须带类：int (W::*)(int, int)
qsort 回调传 void* data 成员指针天然带 this 语义
无 .* / ->* 两个专用运算符

新手要点：① &W::v 不是地址是偏移；② 调用必须给对象； ③ 成员函数指针 ≠ 普通函数指针（大小/语义都不同，实测 16B vs 8B）； ④ typedef/using 起别名能救命：using Handler = void (W::*)(const Msg&);

HFT 关联

  • 行情处理的 msg_type → handler 跳转表（④ 的 dispatch 模式）是交易所网关的 标准形态：比 switch 链分支更规律（间接跳转目标少，BTB 友好），且表可以 constexpr 生成
  • 成员指针 + CRTP 可在编译期完成"策略基类调派生实现"的分发（无 vtable）—— 这是 M1/ch16 里 CRTP 惯用法的机制底座
  • 注意 16 字节的尺寸：把成员指针塞进缓存行敏感的紧凑结构（订单簿条目）前先算对齐账

代码自测

题目 1： 下面为什么编译错误？怎么改？

struct A { void f() {} };
void (*fp)() = &A::f;
参考答案

&A::f 的类型是 void (A::*)()（成员函数指针），不是 void(*)()—— 成员函数有隐式 this，两者不兼容。改法：void (A::*fp)() = &A::f;， 调用 (a.*fp)() 或 (pa->*fp)()。要摆脱对象束缚用 lambda 捕获或 std::bind/std::function。

题目 2： int A::*p = &A::x; 里的 p 存的是什么？为什么 sizeof(p) 可以只有 4 或 8？

参考答案

存的是成员 x 在 A 对象内的偏移量（Itanium ABI 下成员数据指针就是偏移，单位字节， 从 -1 起表示空）——所以它和对象实例无关，大小是一个整数的尺寸（实测 8B）， 不同于成员函数指针（16B，要带 this 调整/vtable 信息）。

题目 3： 用成员函数指针表实现三态状态机（IDLE/RUN/STOP，事件 TICK/RESET）， 写出跳转表的核心两行。

参考答案 
using Action = void (Sm::*)(Event);
static constexpr Action next[3][2] = {
    /* IDLE */ { &Sm::start,  &Sm::stay   },
    /* RUN  */ { &Sm::tick,   &Sm::stop   },
    /* STOP */ { &Sm::stay,   &Sm::reset  },
};
// 转移：(sm.*next[state][ev])(ev);

查表替代嵌套 switch——状态/事件多时表格化更可审阅，且可加静态断言保证表完整。

19.4

嵌套类

本节讲什么

类里面再定义类——嵌套类是作用域控制工具：把"只属于这个类的辅助类型" （迭代器、节点、Impl）收进类的命名空间，不污染外层。本节讲清嵌套类的访问规则、 独立性（不持有外部对象）、pImpl 惯用法。代码均经本机 g++ 13.3 / -std=c++17 实测（2026-10-07）。

① 定义与独立性（先破除最大误解）

class Outer {
    int secret = 42;
public:
    class Inner {
        int inner_secret = 7;
    public:
        void peek(Outer& o) { o.secret = 99; }   // C++11 起：嵌套类可访问外部 private
        void show() const { std::cout << inner_secret << "\n"; }
    };
};
Outer::Inner i;              // 独立构造：不需要任何 Outer 实例！
// 本机实测：sizeof(Inner)=4——Inner 对象里**没有**指向 Outer 的指针

核心事实：嵌套类是作用域上的嵌套，不是对象上的包含—— Inner 的实例和 Outer 的实例毫无关联（不像 Java 的非静态内部类那样隐式持有外部引用）。 要访问某个 Outer 对象，必须显式传进来（peek(Outer& o)）。

② 访问规则（不对称！）

方向 规则 实测
嵌套类 → 外部类成员 可以访问一切（含 private 非静态，C++11 起） o.secret = 99 ✅
外部类 → 嵌套类成员 受嵌套类的访问控制——外部类不是嵌套类的友元 i.inner_secret ❌ 编译错误
嵌套类 → 外部静态成员 直接访问（无需对象） s_count ✅

记忆：嵌套类是"客人有了钥匙"——它能开主人的门，主人却开不了它的门 （除非嵌套类把成员设为 public 或声明友元）。

③ 真实用途

用途一：容器把节点/迭代器收进内部（标准库全是这么干的）：

template <typename T>
class List {
    struct Node {           // 私有嵌套类：实现细节，用户根本不该知道
        T data; Node* next;
    };
    Node* head_ = nullptr;
public:
    class iterator {        // 公有嵌套类：作为类的接口一部分
        /*...*/
    };
};
// 用户写 List<int>::iterator——迭代器天然携带"属于哪个容器"的信息

std::list<int>::iterator 的类型全名就是这么来的。

用途二：pImpl 惯用法（编译防火墙）：

// widget.h——用户只看到指针，实现细节全藏在 .cpp
class Widget {
    class Impl;                 // 前向声明嵌套类（不完整类型）
    std::unique_ptr<Impl> pImpl_;
public:
    Widget();
    ~Widget();                  // 必须在 .cpp 定义（Impl 完整后才能析构）
    void work();
};
// widget.cpp
class Widget::Impl { /* 全部实现细节：成员、辅助函数… */ };
Widget::Widget() : pImpl_(std::make_unique<Impl>()) {}
Widget::~Widget() = default;
void Widget::work() { /* 转发给 pImpl_ */ }

价值：改实现不触发用户代码重编译（头文件没动）——大型项目的编译时间救星； ABI 稳定性的经典手段（→ M4 Effective C++ Item 31）。

用途三：每类型的 trait/tag 载体：

class Strategy {
    struct BuySignal {};      // 策略专属的标签类型，收进类里不外泄
    struct SellSignal {};
};

④ 局部类与嵌套类的边界（顺带知道）

  • 局部类（函数内定义的类）：不能定义静态数据成员、不能作模板参数（C++11 前）—— C++11 起可作模板实参，lambda 出现后用武之地大减
  • 嵌套类也有访问外部类名的特权：Outer::Inner 里可以直接写 Outer 的 typedef/static

和 C 的区别 / 新手要点

C C++
结构体套结构体 = 对象包含（内存上嵌套） 嵌套类 = 作用域嵌套（对象上独立！）
无 pImpl 概念（.opaque 指针手搓） class Impl; unique_ptr<Impl> 标准姿势
无 嵌套类访问外部 private 的不对称规则

新手要点：① 嵌套类实例不含外部对象指针（sizeof 实测）；② 访问规则不对称； ③ 名字查找：嵌套类里 Outer::Inner 写全，外部类成员函数里直接写 Inner。

HFT 关联

  • pImpl 与热路径的矛盾：pImpl 多一次指针间接（cache miss）+ 堆分配—— 热路径类型（订单/行情）不用 pImpl；配置/连接管理等冷路径对象随便用
  • 嵌套 Node/iterator 是自定义容器（订单簿/无锁队列）的标准形态—— 类型归属清晰，且嵌套类能自由访问容器的私有存储（② 的规则正为此设计）
  • 编译防火墙在大型交易系统里的价值：行情解码库改实现，策略层不用重编—— 发布节奏快时 pImpl 的编译解耦比那一点间接开销值钱（在接口边界用，不在数据路径用）

代码自测

题目 1： 嵌套类和外部类有什么访问关系？

class Outer {
    int private_data;
    class Inner {
        void f(Outer& o) {
            o.private_data = 42;  // C++11 前合法吗？
        }
    };
};
参考答案

C++11 起：嵌套类可以访问外部类的 private 成员（包括静态和非静态）。C++11 前：嵌套类不能直接访问外部类的非静态 private 成员（需要友元声明）。嵌套类主要用于实现细节隐藏——如迭代器类通常嵌套在容器类内部。

题目 2： sizeof(Outer::Inner) 和 sizeof(Outer) 有必然关系吗？为什么？

参考答案

没有。嵌套类是作用域嵌套不是内存嵌套——Inner 对象不持有 Outer 的指针或子对象 （本机实测 sizeof(Inner)=4，只装自己的 int）。 要关联必须显式存一个 Outer* 或引用。这与 Java 非静态内部类（隐式持有外部引用） 是本质区别——从 Java 转过来的人最容易在这里想错。

题目 3： pImpl 的 unique_ptr<Impl> 成员下，为什么 ~Widget() 必须在 .cpp 里定义， 不能 = default 在头文件？

参考答案

unique_ptr<Impl> 的析构要调用 Impl 的析构函数——这要求 Impl 在析构点是完整类型。 头文件里 Impl 只有前向声明（不完整类型），= default 会把析构定义放进每个包含者的 TU， 在它们眼里 Impl 都不完整 → 编译错误。 放 .cpp（Impl 完整的地方）定义析构，链接器统一用那一份。 （C++23 的 std::expected 式完整类型推导或自定义 deleter 也能绕，但 .cpp 定义仍是标准做法。）

19.5

联合（union）与位域

本节讲什么

union（所有成员共享同一块内存）和位域（bitfield，按位打包字段）是 协议解析和内存极致压缩的两件底层工具——也是"写出来的结构体必须和网线上字节流 一模一样"时唯一可靠的语言手段。代码均经本机 g++ 13.3 / -std=c++17 实测（2026-10-07）。

① union：同一块内存的多种解读

union Header {
    uint32_t raw;                    // 整个 4 字节当一个整数
    struct {                         // 或者按字段拆着看
        uint32_t type : 8;
        uint32_t seq  : 20;
        uint32_t flag : 4;
    } parts;
};
Header h{}; h.parts.type = 2; h.parts.seq = 1000;
// 本机实测：sizeof(Header)=4，h.raw=0x3e802——写 parts 立即反映到 raw

规则与要点： - sizeof(union) = 最大成员的尺寸（按对齐向上取整） - 任意时刻只有一个成员是"活"的——写 A 读 B 在 C++ 里技术上是 UB （实际中"同布局重解读"（type punning）广泛用于协议解析，编译器按扩展支持； 严格可移植的替代是 std::memcpy 或 C++20 std::bit_cast） - C++11 起 union 可以含非平凡成员（string/vector），但要自己管理 构造/析构（placement new + 手动析构）——工程上基本只放 trivial 类型

② struct 里的匿名 union：省一个名字，多一分类型安全

struct Tick {
    uint8_t kind;            // tag：后面 union 里谁活着
    union {                  // 匿名：成员直接提升为 Tick 的成员
        int64_t i;
        double d;
    };
};
Tick t{}; t.d = 3.14;
// 本机实测：sizeof(Tick)=16（tag + padding + 8B union，对齐到 8）

这就是经典 tagged union / discriminated union——C 时代的 variant。 现代替代品：std::variant<int64_t, double> 自带 tag 管理、类型安全访问 （std::get/std::visit），错误的类型访问抛异常而不是 UB（→ M5 C++17 ch16）。 协议解析选裸 union（要逐字节控制布局），业务逻辑选 variant（要安全）。

③ 位域：按位打包（实测）

struct alignas(1) Packed {
    uint8_t  a : 3;      // 3 位
    uint8_t  b : 5;      // 5 位——凑满 1 字节
    uint16_t c : 9;      // 9 位
};
// 本机实测：sizeof(Packed)=4（17 位按存储单元向上取整）

协议头的真实形态：

struct /* 某交易所行情头 */ {
    uint16_t msg_len;
    uint8_t  msg_type;
    uint8_t  flags;
    uint32_t seq_num;
} __attribute__((packed));   // GCC/Clang：禁对齐填充；MSVC 用 #pragma pack(1)

三个必须知道的坑： 1. 位域的布局是实现定义的（从高位还是低位开始排、跨单元规则）—— 跨编译器/跨平台的协议不能只靠位域，必须配 static_assert + 打包属性 + 抓包验证 2. 位域没有地址（&p.a 编译错误）——不能绑引用/指针 3. 位域的符号性随编译器（int x : 1 是 signed 还是 unsigned 不保证）—— 明确写 uint8_t/int32_t 等定宽类型

④ 布局三件套：协议结构体的验收纪律

static_assert(sizeof(Packed) == 4, "布局漂移！");
static_assert(offsetof(Tick, d) == 8, "union 偏移变了");
static_assert(alignof(Header) == 4, "对齐变了");

协议结构体改任何字段都必须过 static_assert 三件套—— 编译期挡住布局漂移，比上线后解码错位便宜一万倍。

和 C 的区别 / 新手要点

C C++
union 随便用（平凡类型） 非平凡成员要手动生命周期管理；有 variant 兜底
位域协议解析日常 同样日常，但多了 static_assert 编译期验收
无 std::bit_cast（C++20）做严格合法的 type punning

新手要点：① union 写谁读谁；② 位域没地址；③ 跨平台协议别裸信位域布局； ④ 业务代码用 std::variant 别手搓 tagged union。

HFT 关联

  • 行情解码的本质就是 union + 位域 + packed struct：协议头按字节映射成结构体， reinterpret_cast<const Header*>(buf) 直接读（零拷贝解码）—— 比逐字段反序列化快一个数量级（→ 14-hft-engineering 行情解码）
  • 缓存行预算下位域是压缩利器：订单簿一档的价格档标志位打包进 1 字节
  • 跨交易所协议适配层必须有 static_assert 三件套 + 每协议的 golden-packet 回放测试
  • 零拷贝解码的 UB 边界：严格来说要写 std::memcpy(&h, buf, sizeof h) 让编译器优化掉； reinterpret_cast 直读要确认对齐（alignof(Header) ≤ buf 对齐）与字节序（→ 03.5/hton）

代码自测

题目 1： union { uint32_t u32; uint8_t u8[4]; } 里写 u32 = 0x01020304， 小端机上 u8[0] 是多少？这段代码严格来说合法吗？

参考答案

u8[0] = 0x04（小端低地址放低字节）。 严格 C++ 语义：写 u32 读 u8 是"非活成员读取"，技术上 UB；但 u8[N] 有个特例—— 任何对象都可以按 char/unsigned char/std::byte 数组检查其表示，所以读 u8 是合法的。 反过来写 u8 读 u32 同样 UB（别名规则），工程上常用但要知道边界；严格写法用 std::memcpy 或 C++20 std::bit_cast<uint32_t>(u8)。

题目 2： 为什么不能对位域取地址？uint8_t& r = p.a;（a 是 3 位的位域）为什么编译失败？

参考答案

地址的最小单位是字节，而位域占的是字节内的若干位——硬件和 ABI 都无法表达 "第 3 字节的第 2 位起"这样的地址。所以位域没有地址，也就不能绑到引用或指针。 变通：给位域配 get/set 成员函数，或用 std::bitset 的 reference 代理。

题目 3： 交易所升级协议，把 seq 从 20 位扩到 24 位，flag 从 4 位砍到 0 并删除—— 除了改结构体，工程上还要动哪三处？

参考答案

① static_assert 三件套（布局断言按新布局更新）； ② golden-packet 回放测试（新老协议各准备样本包验证解码）； ③ 协议版本协商/识别逻辑（网关同时在线新老版本时按 msg_type 或版本字段分流， → 18.2 inline namespace 版本化）。 少了任何一处，布局漂移就会在开盘瞬间变成生产事故。

19.6

可变参数模板（C++11）

本节讲什么

可变参数模板（variadic template）让模板接受任意个数、任意类型的参数—— 它是 std::make_unique/emplace_back/std::tuple/printf 替代品的基础设施。 本节覆盖参数包、递归展开、C++17 折叠表达式、sizeof...。 代码均经本机 g++ 13.3 / -std=c++17 实测（2026-10-07）。

① 参数包与递归展开（经典形态）

void print() { std::cout << "\n"; }              // 递归终点（空包重载）

template <typename T, typename... Rest>
void print(T&& first, Rest&&... rest) {          // 每次剥一个
    std::cout << first << " ";
    print(rest...);                              // 参数包展开：rest 变成逐个实参
}
print(1, 2.5, "三", 'x');
// 本机实测输出：1 2.5 三 x

三个 ... 的位置各管一件事：

位置 名字 作用
typename... Rest 模板参数包 声明"一包类型"
Rest&&... rest 函数参数包 声明"一包值"
rest... / f(args)... 包展开 把包拆成逗号分隔的序列

递归模式的实质：每次实例化处理一个参数，剩余打包继续—— 实例化 N 层模板（N = 参数个数），编译期完全展开、零运行时开销。

② C++17 折叠表达式：递归的现代替代

template <typename... Args>
auto sum(Args... args) { return (args + ...); }      // 一元右折叠

sum(1, 2, 3, 4)     // 本机实测 = 10
sum(1.5, 2)         // = 3.5（类型自动推导为 double）

四种折叠形态：

(args + ...)        // 右折叠：a1 + (a2 + (a3 + a4))
(... + args)        // 左折叠：((a1 + a2) + a3) + a4
(init + ... + args) // 带初值：空包也得 init（(0 + ... + args) 空包=0）
(args , ...)        // 逗号折叠：对包中每个元素执行左侧语句

逗号折叠是"对每个参数做一件事"的现代写法，不再需要递归：

template <typename... Args>
void log_all(Args&&... args) {
    ((std::cout << args << " "), ...);   // 实测等价于逐个打印
    std::cout << "\n";
}

③ sizeof... 与参数包计数

template <typename... Args>
void log_count(Args... args) { std::cout << sizeof...(args) << "\n"; }
log_count(1, 2, 3, 4, 5);     // 本机实测：参数个数=5
  • sizeof...(pack)：包中元素个数（注意是 sizeof... 不是 sizeof）
  • 典型用途：static_assert(sizeof...(Args) == 2)、元组索引、编译期分派

④ 与完美转发的组合（完整形态）

可变参数模板几乎总和转发一起出现——这就是 emplace_back 的真身：

template <typename T, typename... Args>
T* pool_emplace(void* raw, Args&&... args) {           // 转发引用接住一切
    return new (raw) T(std::forward<Args>(args)...);   // 原样转发给构造函数
}
// 任意构造函数签名的类型都能在不写包装的情况下直接构造（→ 19.7 完美转发）

std::make_unique<T>(args...)、vector::emplace_back(args...) 都是这个模式—— 参数包负责"个数自由"，&&+forward 负责"值类别不丢"。

⑤ 与可变参数宏/va_list 的对比（为什么 C 的招在 C++ 都退役了）

C（va_list/##__VA_ARGS__） C++（参数包）
类型擦除：全是 void*/int 提升 类型保留：每个参数类型独立推导
运行时解析（va_arg 按类型取，取错 = UB） 编译期展开，类型错误 = 编译错误
个数靠格式串约定（printf 的 %d 数错就炸） sizeof... 编译期可数、可断言
宏不可调试 模板实例化有完整诊断

和 C 的区别 / 新手要点

C C++
va_list/va_start/va_end template <typename... Args>
##__VA_ARGS__ 宏拼接 折叠表达式
printf 式运行时格式 类型安全的编译期展开

新手要点：① 三个 ... 位置分清；② 递归展开要留空包终点（否则编译错误）； ③ C++17 项目里优先折叠表达式，递归只留给"需要逐个处理且逻辑不同"的场景。

HFT 关联

  • 日志系统的零开销格式层：log(fmt, args...) 在编译期把参数包展开成 逐参数的序列化调用（比 iostream 快一个量级；spdlog/fmt 就是这个原理）—— 热路径日志的标配技术（→ M1 / 14-hft-engineering）
  • emplace 系列（订单簿条目就地构造）= 可变参数模板 + placement new（19.1）
  • 事件多播：template <typename... Sinks> void multicast(const Msg& m, Sinks&... s) 编译期展开为对每个 sink 的直接调用——无 vector 遍历、无类型擦除

代码自测

题目 1： 这段递归 print 少了什么？

template <typename T, typename... Rest>
void print(T&& first, Rest&&... rest) {
    std::cout << first;
    print(rest...);
}
参考答案

少了空包终点（void print()）。剥到最后一个参数后 rest 为空包， print() 无参调用找不到匹配重载 → 编译错误（递归模板最深的实例化失败， 错误信息会很长——看最后一层才是关键）。

题目 2： (args + ...) 和 (... + args) 对 sum("a", "b", "c")（字符串）结果一样吗？ 对 sub(100, 10, 1) 呢？

参考答案

字符串：结果一样（"abc"，左结合/右结合对 + 都是合法拼接，顺序不同但结果相同—— 不过中间临时对象的构造顺序不同，大字符串时性能有差）。 sub：不一样——减法不满足结合律： 右折叠 100-(10-1) = 91，左折叠 (100-10)-1 = 89。 折叠方向对非结合律运算符是语义差异，不只是风格。

题目 3： 用逗号折叠写 push_all(vector<T>& v, Args... xs)，把所有参数 push 进 v。

参考答案 
template <typename T, typename... Args>
void push_all(std::vector<T>& v, Args&&... xs) {
    (v.push_back(std::forward<Args>(xs)), ...);
}

逗号折叠按顺序对每个 xs 执行 push_back，转发保持值类别—— 一行顶过去一个递归模板。要预留容量可先 v.reserve(v.size() + sizeof...(xs));。

19.7

转发引用与完美转发

本节讲什么

T&& 在模板里不是右值引用，是"转发引用"（forwarding reference，旧称万能引用）—— 它既能绑左值又能绑右值，配合 std::forward 把实参的值类别原封不动传给下一层。 这是 emplace_back/make_unique 等"包装层零损耗"的底层机制，也是 Effective Modern C++ Item 23-30 的根基（→ M1）。代码均经本机 g++ 13.3 / -std=c++17 实测（2026-10-07）。

① 引用折叠 + 特殊推导规则 = 转发引用

引用折叠（模板实例化时的规则）：

&  + &  → &      && + &  → &      （有左值引用参与，结果就是左值引用）
&  + && → &      && + && → &&

推导规则（template <typename T> void f(T&&) 专用）：

实参 T 推导为 形参类型（折叠后）
左值 t T = U&（左值引用！） U& && → U&
右值 U{} T = U（非引用） U&&

所以 T&& 形参总能匹配——左值来变左值引用，右值来变右值引用。 关键鉴别：T&& 只有在"模板 + 类型推导"语境才是转发引用； void f(Widget&&)（具体类型）或 template <typename T> void f(const T&&) 都不是。

② 完美转发：std::forward 恢复值类别（实测）

void sink(const Tracer&) { std::cout << "sink 收到左值\n"; }
void sink(Tracer&&)      { std::cout << "sink 收到右值\n"; }

template <typename T>
void relay(T&& x) {
    sink(std::forward<T>(x));     // 左值来 → 转成左值；右值来 → 转成右值
}
Tracer t;
relay(t);          // 本机实测：T=左值引用，sink 收到左值
relay(Tracer{});   // 本机实测：T=非引用，sink 收到右值

为什么需要 forward：形参 x 是有名变量——变量永远是左值！ 不用 forward 直接 sink(x)，右值传进来也会被当左值（移动语义丢失）。 std::forward<T>(x) 按 T 的推导结果做条件转换：T 是左值引用就转左值，否则转右值。 （std::move 是无条件转右值；std::forward 是按推导结果转换——这是两者的本质区别。）

③ 经典应用：包装层零损耗

// emplace_back 的真身（→ 19.6 可变参数模板 + 本节 forward）
template <typename T, typename... Args>
void emplace(void* raw, Args&&... args) {
    new (raw) T(std::forward<Args>(args)...);   // 任意构造函数参数原样穿透
}

// 计时包装器：任何函数包一层计时，调用语义不变
template <typename F, typename... Args>
auto timed(F&& f, Args&&... args) -> decltype(auto) {
    auto t0 = clk::now();
    return std::forward<F>(f)(std::forward<Args>(args)...);   // 返回值类别也转发
}

注意返回类型写 decltype(auto)——返回引用时保持引用，值时保持值， auto 会砍掉引用造成意外拷贝。

④ std::move 的真相：它不移动任何东西（实测）

std::string a = "hello";
std::string b = std::move(a);      // move 只是"贴标签"：把 a 转成右值引用
// 本机实测：move 后 a.size()=0（libstdc++ 小字符串优化下被掏空）
  • std::move(x) = static_cast<remove_reference_t<T>&&>(x)——纯类型转换，零代码生成
  • 真正"移动"发生在接收方（移动构造/移动赋值被重载决议选中）那一刻
  • move 后的对象处于"有效但未指定"状态：可以析构、可以赋值，不要再读它的值 （a.size() 返回 0 是 libstdc++ 的实现细节，不是标准承诺——标准只说"有效但未指定"）

⑤ 三个高频翻车点

  1. 转发引用重载会"吞掉"一切：
struct S {
    S(S&&) = default;
    template <typename T> S(T&&);      // 转发引用构造——比 S(S&) 更匹配左值！
};
S s1; S s2(s1);      // 意外命中模板构造（T=S&），不是拷贝构造！

修法：enable_if/requires（C++20）把模板构造限定在"不是 S 本身"的类型 （→ M1 Item 26）。

  1. 一次 forward 只保一次：f(forward<T>(x)); g(forward<T>(x)); 第二次转发时 x 可能已被移动——转发后不再使用是铁律。

  2. return 里的局部变量别 forward：return std::forward<T>(local); 局部变量返回本来就有 RVO/隐式 move，强行 forward 反而阻止 RVO（→ M1 Item 25）。

和 C 的区别 / 新手要点

C C++
函数参数按值拷 or 传指针 左值/右值两套重载 + 转发引用通吃
无值类别概念 lvalue/prvalue/xvalue 三分
无 std::move/std::forward（纯转换工具）

新手要点：① 见 T&& 先问"是模板推导语境吗"；② move 是标签不是动作； ③ move 后的对象别再读值；④ forward 一次就够、转完别再用。

HFT 关联

  • 订单/行情对象的构造零拷贝：book.emplace(price, qty, side) 参数穿透到 placement new，无临时对象、无拷贝——19.1 + 19.6 + 本节三件套的合体
  • 无锁队列 push(T&&)：push 移动元素进 ring buffer 后就地失效原对象—— 值类别语义在单生产者场景是明确的（→ 06.6.5 / 14-hft）
  • 日志/监控包装层（③ 的 timed 模式）在热路径要求零开销转发： decltype(auto) + forward 全套，编译后通常只剩一次时钟调用

题目 2： std::string s = "x"; auto t = std::move(s); 之后 s 是"空"吗？能做什么？

参考答案

题目 3： 下面这段为什么把代码 reviewer 吓一跳？修。

template <typename T>
T&& wrapper(T&& x) {
    use(x);
    return std::forward<T>(x);
}
参考答案

两个雷：① 返回类型 T&& 是转发引用推导——传左值时返回 U&（悬垂风险： 若 x 是转发来的临时量，返回引用指向已销毁对象）；② use(x) 之后 x 值类别未变 （x 是左值变量），但语义上"use 过又转发"说明所有权语义含糊。 修：明确语义——要转交所有权就返回值 T（return std::forward<T>(x); 配 T 返回类型）， 要观察不改所有权就返回 void/bool。转发引用做返回类型只在极其特殊的设计里合理。

其他底层工具

本节讲什么

type_traits（编译期类型问答）、if constexpr（编译期分支）、void_t（成员探测）、 decltype 高阶用法——这些是模板库的探针，也是读懂标准库实现的钥匙。 代码均经本机 g++ 13.3 / -std=c++17 实测（2026-10-07）。 （这节是 ch16 模板的延伸，深入 SFINAE/concepts 见 M1 Item 27-28 与 M5 C++20 概念。）

① type_traits：编译期的类型问答机（实测）

template <typename T>

高频 traits 速查：

trait 问什么 典型用途
is_integral_v<T> / is_floating_point_v<T> 算术类型分类 泛型数值代码分派

if constexpr（C++17）是分水岭：被丢弃的分支不实例化—— is_integral_v<T> 为 false 时，整数分支里的 atomic<T> 操作根本不会编译， 不再需要 tag dispatch / enable_if 的绕行（旧代码里那些 std::enable_if_t 现在都能写人话了）。

② void_t：探测"这个类型有没有某个成员"（实测）

template <typename, typename = std::void_t<>>
struct has_size : std::false_type {};                    // 默认：没有

template <typename T>
struct has_size<T, std::void_t<decltype(std::declval<T>().size())>>
    : std::true_type {};                                  // 偏特化命中：有 .size()

has_size<std::string>::value    // 本机实测：1
has_size<int>::value            // 本机实测：0

机制（SFINAE 的现代包装）：void_t<...> 在 ... 里的表达式非法时， 偏特化匹配失败但不是错误（SFINAE），回落到主模板（false_type）； 合法时偏特化命中（true_type）。decltype(declval<T>().size()) 不真的调用， 只在编译期问"这个表达式类型合法吗"。

C++20 起这整套被 concepts 收编：requires { t.size(); } 一句话—— 但 C++17 代码库里 void_t 仍是主力（→ M5 C++20 ch07 concepts）。

③ decltype 高阶用法（实测）

// 尾置返回类型：返回值类型依赖参数运算结果
template <typename A, typename B>
auto add(A a, B b) -> decltype(a + b) { return a + b; }

std::is_same_v<decltype(add(1, 2.5)), double>     // 本机实测：1

decltype 的三张脸：

写法 得到什么
decltype(x)（变量名） 变量的声明类型（含引用/cv）
decltype((x))（加括号变表达式） 表达式类型 + 值类别（左值表达式 → T&）
decltype(auto) 按初始化表达式完整保留类型（引用不剥）——转发返回值用（→ 19.7 ③）

陷阱高频：decltype(auto) f() { int x = 0; return (x); }—— (x) 是左值表达式 → 返回 int& 悬垂引用。去掉括号就对了。

④ 编译期编程的最小工具箱（拼装视图）

type_traits（问） + void_t（探） + if constexpr（选） + static_assert（验）

类级 operator new 用途： - 自定义内存池（避免 malloc 锁竞争 + 碎片） - 统计内存使用 - HFT 对象池：预分配 + 回收，零运行时分配

delete 同理： 先调析构，再调 FastAlloc::operator delete 释放回池。

union Value {

    std::string s;  // C++11: 合法吗？

C++11 起合法，但有限制： 1. 含非平凡成员（有构造/析构/拷贝）的 union，必须手动管理哪个成员是活跃的 2. 不能同时使用多个成员——写入一个成员后读取另一个是 UB 3. union 需要自定义构造/析构来管理非平凡成员的生命周期

Q4完美转发深入
template<typename T, typename... Args>
auto make_unique(Args&&... args) -> std::unique_ptr<T> {
    return std::unique_ptr<T>(new T(std::forward<Args>(args)...));
}
// 调用 make_unique<Widget>(42, "hello", 3.14)
// args 的类型分别是什么？

Args&&... 是什么？std::forward<Args>(args)... 做了什么？

答案与复习指引

Args&&...： 万能引用参数包——每个参数都能接受左值或右值。

`std::forward(args)...： 逐个参数完美转发——保留每个参数的原始左右值性。如果原始参数是左值就转发为左值引用，是右值就转发为右值引用。

这是 std::make_unique 的核心——它把构造参数原封不动地转发给 T 的构造函数，不丢失任何信息（左右值性、const 性）。如果不用 forward，所有参数都会变成左值，无法触发移动构造。
