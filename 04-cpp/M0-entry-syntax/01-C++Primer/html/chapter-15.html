15.1

基类与派生类

本节讲什么

本节讲解 C++ 继承体系的最基础概念：如何定义基类（base class）与派生类（derived class），派生列表的三种继承方式（public/protected/private），派生类对象在内存中如何包含基类子对象，以及 final 如何禁止进一步继承。这是 OOP 的起点——后面 15.2 的虚函数、15.3 的抽象基类、15.4 的拷贝控制都建立在本节之上。

一句话定位：继承表达 "is-a"（是一个） 关系——Derived 是一个 Base，所以 Base*/Base& 能指向 Derived 对象。这与"has-a"（包含）关系截然不同。

核心用法

1. 定义基类

基类通常会把"希望派生类覆盖"的函数声明为 virtual（虚函数，详见 15.2），并提供一个虚析构函数（详见 15.4）：

class Quote {
public:
    Quote() = default;
    Quote(const std::string &book, double sales_price)
        : bookNo(book), price(sales_price) { }
    std::string isbn() const { return bookNo; }
    // 虚函数：派生类可以覆盖它
    virtual double net_price(std::size_t n) const {
        return n * price;
    }
    virtual ~Quote() = default;   // 基类析构必须是虚的！
protected:                         // 派生类可直接访问
    double price = 0.0;
private:                          // 派生类也不能直接访问
    std::string bookNo;
};

关键点： - virtual 只在类内声明时加，类外定义不加 - protected 成员：派生类可访问，外部用户不可访问（介于 public 和 private 之间） - 基类析构函数几乎总是应该声明为 virtual（否则 delete base_ptr 不会调用派生类析构，资源泄漏）

2. 定义派生类

派生类使用派生列表（derivation list）声明继承关系：

class Bulk_quote : public Quote {   // public 继承
public:
    Bulk_quote() = default;
    Bulk_quote(const std::string &book, double p, std::size_t qty, double disc)
        : Quote(book, p), min_qty(qty), discount(disc) { }  // 显式初始化基类
    // 覆盖基类的虚函数
    double net_price(std::size_t n) const override {
        if (n >= min_qty)
            return n * (1 - discount) * price;   // 可访问 protected 成员
        else
            return n * price;
    }
private:
    std::size_t min_qty = 0;
    double discount = 0.0;
};

关键点： - 派生类构造函数必须通过初始值列表初始化基类部分（直接用基类名调用），不能在函数体里赋值——因为基类子对象在进入派生类构造体前就已构造完毕 - override 关键字（C++11）显式说明"我要覆盖基类的虚函数"，编译器会检查签名是否匹配，避免拼写错误导致的"隐藏而非覆盖" - 派生类可以访问 protected 成员，但不能访问 private 成员

3. 派生类对象 = 基类子对象 + 派生类自己的成员

一个 Bulk_quote 对象在内存中包含两个部分：

┌─────────────────┐
│  Quote 子对象    │  ← bookNo (private), price (protected)
├─────────────────┤
│  Bulk_quote 自己 │  ← min_qty, discount
└─────────────────┘

派生类到基类的转换（派生类引用/指针 → 基类引用/指针）之所以成立，正是因为派生类对象内部确实"包含"一个完整的基类子对象：

Quote item;          // 基类对象
Bulk_quote bulk;     // 派生类对象
Quote *p = &item;    // p 指向 Quote 对象
p = &bulk;           // p 指向 bulk 的 Quote 子对象（合法！）
Quote &r = bulk;     // r 绑定到 bulk 的 Quote 子对象

注意：这种转换是单向的——Base* → Derived* 需要显式 static_cast/dynamic_cast，且不安全。

4. 三种继承方式

派生列表中的访问说明符决定基类成员在派生类中的访问权限：

继承方式 基类 public 成员在派生类中 基类 protected 成员 基类 private 成员
public 继承 仍是 public 仍是 protected 不可访问
protected 继承 变成 protected 仍是 protected 不可访问
private 继承 变成 private 变成 private 不可访问
  • public 继承表达 "is-a"——几乎总是用这个
  • private 继承表达 "implemented-in-terms-of"（用基类实现），用得很少；通常用"包含一个成员"更好
  • protected 继承几乎从不使用
  • class 默认 private 继承，struct 默认 public 继承（与访问控制默认值一致），但永远显式写出继承方式

5. final：禁止继承

C++11 起可用 final 禁止某个类被继承：

class NoDerived final { /* ... */ };   // 不能作为基类
class Base { /* ... */ };
class Last : public Base { /* ... */ };
class Wrong : public Last { };  // 错误：Last 不是 final，但如果 Last 加 final 就错了

final 也用于虚函数，表示"禁止进一步覆盖"（详见 15.2）。

6. 静态类型 vs 动态类型

这是理解 15.2 动态绑定的前提：

Bulk_quote bulk;
Quote *p = &bulk;   // 静态类型：Quote*，动态类型：Bulk_quote*
  • 静态类型：声明时的类型，编译期已知，决定能调用哪些成员
  • 动态类型：实际指向的对象类型，运行期才确定，决定虚函数调用哪个版本
  • 仅当通过引用或指针调用虚函数时，才根据动态类型绑定（值对象调用是静态绑定的）

和 C 的区别

C 语言没有继承这一语言特性。要模拟"派生类复用基类"，C 程序员只能用两种土办法：

维度 C C++
表达 "is-a" 无直接支持 class D : public B
复用基类数据 手动把基类结构体作为第一个成员 派生类自动包含基类子对象
复用基类行为 函数指针 + switch 按类型分发 虚函数自动动态绑定
类型安全转换 强转 void*（无检查） 派生→基类自动安全转换，dynamic_cast 运行期检查
访问控制 无（全靠约定） public/protected/private + 三种继承方式

C 模拟继承的典型写法（对比）

// C：手动模拟"基类 + 派生类"
struct Quote {
    char bookNo[32];
    double price;
};
struct Bulk_quote {
    struct Quote base;    // 基类作为第一个成员（关键！）
    size_t min_qty;
    double discount;
};
// 派生类指针 → 基类指针：因为 base 是第一个成员，地址相同
struct Bulk_quote bulk;
struct Quote *p = (struct Quote *)&bulk;   // 靠"首成员对齐"约定

// C++：语言层面支持
struct Quote { std::string bookNo; double price; virtual ~Quote()=default; };
struct Bulk_quote : public Quote { size_t min_qty; double discount; };
Bulk_quote bulk;
Quote *p = &bulk;   // 编译器保证安全转换，无需强转

C 写法的致命问题：全靠约定——首成员对齐、函数指针表手动维护、没有编译期检查，一旦有人改了成员顺序就崩溃。C++ 把这一切交给语言和编译器。

HFT 视角：虚函数调用有一次 vtable 间接寻址（mov rax, [obj+vtable_off]; call [rax+func_off]），比普通函数多一次内存访问。极致热路径上有时用 CRTP（奇异递归模板）在编译期消除虚调用，换来零开销多态——但绝大多数场景 vtable 开销可忽略。

常见错误

错误 1：派生类构造函数忘记初始化基类部分

class Bulk_quote : public Quote {
public:
    Bulk_quote(const std::string &book, double p, std::size_t qty, double disc)
        : min_qty(qty), discount(disc) { }   // ❌ 没初始化 Quote！
    //                          ↑ Quote 部分被默认构造，bookNo 为空、price 为 0
private:
    std::size_t min_qty; double discount;
};

修复：在初始值列表里显式调用基类构造函数：

Bulk_quote(...) : Quote(book, p), min_qty(qty), discount(disc) { }

初始值列表的顺序不影响构造顺序——构造永远按声明顺序：先基类，再派生类成员。但显式写出来更清晰。

错误 2：基类忘记虚析构函数（资源泄漏元凶）

class Base {
public:
    ~Base() { }   // ❌ 非虚析构
};
class Derived : public Base {
    int *data = new int[1000];
public:
    ~Derived() { delete[] data; }
};
Base *p = new Derived;
delete p;   // ❌ 只调用 ~Base，~Derived 没被调用 → data 泄漏！

修复：基类析构声明为 virtual：

class Base { public: virtual ~Base() = default; };

这是 OOP 的"铁律"——只要这个类可能被继承，析构就声明为虚的。详见 15.4。

错误 3：误用 private 继承表达 "is-a"

class Dog : private Animal { };   // ❌ private 继承
// 后续：Animal* a = new Dog;  编译错误！private 继承不允许派生→基类转换

private 继承不是 "is-a"，而是 "implemented-in-terms-of"——Dog 不是 一个 Animal（不能传给期望 Animal* 的函数），只是借用了 Animal 的实现。如果真要 "is-a"，用 public 继承；如果只是想复用实现，优先用成员包含而非 private 继承：

class Dog {
private:
    Animal impl;   // 包含一个成员，比 private 继承更清晰
};

错误 4（隐蔽）：override 拼写错误 → 隐藏而非覆盖

class Base { public: virtual void foo() const; };
class Derived : public Base {
public:
    void foo() override { }   // ❌ 签名不一致（漏了 const），但没写 override 时编译器不报错
};

如果不写 override，Derived::foo 会隐藏（而非覆盖）Base::foo，通过 Base* 调用时仍走 Base::foo——这是极难发现的 bug。始终写 override，让编译器替你检查。

自测题

1. 选择题：以下哪种继承方式表达 "is-a" 关系，使得 Derived* 可以隐式转换为 Base*？

A. class Derived : private Base B. class Derived : protected Base C. class Derived : public Base D. 以上都可以

答案

C。只有 public 继承保留 "is-a" 语义，允许派生→基类的隐式转换。private/protected 继承切断了这种转换——它们表达的是"实现复用"而非"is-a"。

2. 判断题：派生类构造函数的初始值列表中，基类构造和成员初始化的书写顺序决定了构造的先后顺序。

答案

错。构造顺序由声明顺序决定：先基类子对象（按继承声明顺序），再派生类自己的成员（按在类中的声明顺序）。初始值列表的书写顺序只是给读者看的，编译器会忽略它。最佳实践是让列表书写顺序与声明顺序一致，避免误导。

3. 踩坑题：以下代码有什么问题？

class Base {
public:
    void cleanup() { }      // 非 virtual
    ~Base() { cleanup(); }
};
class Derived : public Base {
public:
    void cleanup() { /* 释放派生类资源 */ }
};
Base *p = new Derived;
delete p;
答案

两个问题： 1. 基类析构非虚：delete p 只调用 ~Base，~Derived 不会被调用，派生类资源泄漏。 2. cleanup() 非 virtual：即使补上虚析构，~Base 里调用 cleanup() 也是静态绑定到 Base::cleanup，不会调到 Derived::cleanup（且在析构期间调虚函数本就是反模式——此时派生部分已销毁）。

修复：基类析构声明 virtual；若要清理逻辑多态，在各自的析构函数里直接写，不要在析构链中调虚函数。

4. 应用题：用 C++ 设计一个简单的 Shape 基类和 Circle/Rectangle 派生类，要求： - Shape 有 name() 返回名字、area() 返回面积（派生类覆盖） - 基类析构安全 - 派生类构造函数正确初始化基类

答案 
#include <string>
#include <iostream>
class Shape {
public:
    Shape(const std::string &n) : name_(n) { }
    virtual ~Shape() = default;                    // 虚析构
    const std::string& name() const { return name_; }
    virtual double area() const = 0;               // 纯虚函数（见 15.3）
protected:
    std::string name_;
};
class Circle : public Shape {
public:
    Circle(double r) : Shape("circle"), radius(r) { }   // 显式初始化基类
    double area() const override {                     // override 显式标注
        return 3.14159 * radius * radius;
    }
private:
    double radius;
};
class Rectangle : public Shape {
public:
    Rectangle(double w, double h) : Shape("rectangle"), width(w), height(h) { }
    double area() const override { return width * height; }
private:
    double width, height;
};

要点：基类析构 virtual、派生类初始值列表调基类构造、override 标注、protected 存共享数据。

15.2

虚函数与动态绑定

本节讲什么

本节讲解 OOP 的核心机制——虚函数（virtual function）和动态绑定（dynamic binding）：为什么通过基类指针/引用调用 virtual 函数时，运行期会根据对象的实际类型选择正确的版本；vtable 是怎么工作的；override/final 如何帮你写出安全的虚函数覆盖；以及一个隐蔽但致命的坑——构造/析构期间调虚函数不走动态绑定。

一句话定位：虚函数 = "这个行为派生类可以改写，调用时按实际对象类型决定执行哪版"。这是多态（polymorphism）的实现基础。

核心用法

1. virtual 声明虚函数

class Base {
public:
    virtual void f1() const { }      // 虚函数
    virtual int  f2(int) { return 0; }
    void f3();                       // 非虚——派生类无法"覆盖"，只能"隐藏"
    virtual ~Base() = default;
};
class Derived : public Base {
public:
    void f1() const override { }     // 覆盖（签名必须完全一致）
    int  f2(int) override { return 1; }
};

规则： - virtual 只在类内声明时写，类外定义不写 - 一旦声明 virtual，所有派生层的同名同签名函数都自动是虚的（不管有没有再写 virtual） - 派生类覆盖时签名必须完全一致（参数列表、const 属性、返回类型都要匹配），否则是"隐藏"而非"覆盖" - 例外：返回类型可以是基类返回类型的协变（covariant）——基类返回 Base*，派生类返回 Derived* 合法

2. 动态绑定的触发条件

动态绑定只在通过引用或指针调用虚函数时发生：

Base b;
Derived d;

Base &r = d;          // 引用
r.f1();               // ✅ 动态绑定 → Derived::f1

Base *p = &d;
p->f1();              // ✅ 动态绑定 → Derived::f1

d.f1();               // 静态绑定（对象类型已知）→ Derived::f1
b.f1();               // 静态绑定 → Base::f1

Base obj = d;         // ❌ 拷贝！d 被切掉，obj 是一个 Base
obj.f1();             // 静态绑定 → Base::f1（对象切片，见 15.5）

为什么值对象不动态绑定？因为 Base obj = d; 会把 d 的 Base 部分拷贝过来，派生部分被"切掉"——obj 在编译期就是纯粹的 Base，没有派生信息可绑定了。这就是为什么多态总是用指针或引用。

3. vtable：虚函数表的工作原理

每个含虚函数的类，编译器都会生成一张虚函数表（vtable）——一个函数指针数组，每个槽位对应该类的一个虚函数实现：

   Base 对象              Derived 对象
  ┌──────────┐           ┌──────────┐
  │ vptr ────┼──┐        │ vptr ────┼──┐
  └──────────┘  │        └──────────┘  │
                ▼                      ▼
        Base vtable             Derived vtable
        ┌─────────┐             ┌──────────┐
        │ &Base::f1│            │ &Derived::f1│  ← 覆盖了
        │ &Base::f2│            │ &Base::f2  │  ← 未覆盖，继承基类版本
        └─────────┘             └──────────┘

调用 p->f1() 编译器生成类似这样的代码：

mov  rax, [p]          ; 取对象首地址
mov  rax, [rax]        ; 取 vptr（vtable 地址）
mov  rax, [rax + 0]    ; 取 vtable 第 0 槽（f1 的地址）
call rax               ; 间接调用

所以虚调用比普通调用多一次内存访问（读 vptr + 读槽位）。现代 CPU 分支预测器对 vtable 间接调用的预测相当好，绝大多数场景开销可忽略。

4. override 和 final（C++11）

override：显式告诉编译器"我要覆盖基类的虚函数"，编译器会检查签名是否匹配。永远写 override：

class Base { public: virtual void f(int) const; };
class Derived : public Base {
public:
    void f(int) const override { }     // ✅ 正确覆盖
    void f(int) override { }           // ❌ 漏 const → 编译错误（不是 override）
    void f(double) const override { }  // ❌ 参数类型不同 → 编译错误
};

final：禁止进一步覆盖（用在虚函数上）或禁止进一步继承（用在类上）：

class Base {
public:
    virtual void f() final;        // 派生类不能再覆盖 f
};
class Derived : public Base {
public:
    void f() override;             // ❌ 错误：f 是 final
};
class Last final : public Base { };  // Last 不能被继承
class Wrong : public Last { };        // ❌ 错误

5. 虚函数的默认实参坑

虚函数可以有默认实参，但默认实参是静态绑定的——按指针/引用的静态类型决定：

class Base {
public:
    virtual void f(int x = 10) { std::cout << x << "\n"; }
};
class Derived : public Base {
public:
    void f(int x = 20) override { std::cout << x << "\n"; }
};
Derived d;
Base *p = &d;
p->f();   // 输出 10！不是 20
// 调用 Derived::f（动态绑定），但默认实参取 Base 的（静态绑定）

最佳实践：基类和派生类的同名虚函数用相同的默认实参，避免这个坑。

6. 虚函数与内联

虚函数可以被声明 inline，但只有当编译器能确定静态类型时才会内联（此时不需要动态绑定）：

class Base { public: virtual void f() { } };
Base b;
b.f();              // ✅ 编译器知道静态类型是 Base，可内联
Base *p = &b;
p->f();             // ❌ 动态绑定，无法内联（除非去虚化）

现代编译器有去虚化（devirtualization）优化——若能证明动态类型唯一，会把虚调用转为直接调用并内联。但这依赖编译器分析能力，不要主动依赖。

和 C 的区别

C 没有虚函数，要实现"按类型分发"只能手动维护函数指针表 + switch：

维度 C C++
多态分发 函数指针 + switch(type) 手动写 virtual + vtable 自动
添加新类型 改所有 switch（漏改即 bug） 只需新增派生类，无需改已有代码
类型安全 强转 void*，无检查 dynamic_cast 运行期检查
默认实现 手动调"基类"函数指针 基类虚函数提供默认实现，派生类按需覆盖
性能 switch 可被优化，函数指针可内联 vtable 间接调用，同样可去虚化

C 模拟虚函数的典型写法

// C：手动模拟虚函数表
struct Shape;
struct ShapeVTable {
    double (*area)(const struct Shape*);
    void (*draw)(const struct Shape*);
};
struct Shape {
    const struct ShapeVTable *vtable;   // 手动维护的"vtable"
    /* 公共数据 */
};
struct Circle {
    struct Shape base;     // 第一个成员，地址对齐
    double radius;
};
static double circle_area(const struct Shape *s) {
    const struct Circle *c = (const struct Circle*)s;
    return 3.14159 * c->radius * c->radius;
}
static const struct ShapeVTable circle_vtable = { circle_area, circle_draw };
struct Circle* circle_new(double r) {
    struct Circle *c = malloc(sizeof(*c));
    c->base.vtable = &circle_vtable;
    c->radius = r;
    return c;
}
// 调用：s->vtable->area(s)

// C++：语言层面
struct Shape {
    virtual double area() const = 0;
    virtual void draw() const = 0;
    virtual ~Shape() = default;
};
struct Circle : Shape {
    double radius;
    Circle(double r) : radius(r) { }
    double area() const override { return 3.14159 * radius * radius; }
    void draw() const override { }
};
// 调用：s->area()

C 版本全靠程序员手动维护 vtable 指针、首成员对齐约定、强转安全——一旦漏掉 vtable = 赋值就是空指针解引用崩溃。C++ 把这一切交给编译器，且 override 让签名错误在编译期暴露。

HFT 视角：vtable 间接调用有一次内存访问 + 一次间接跳转，对分支预测敏感。在超低延迟热路径上，可用 CRTP（Curiously Recurring Template Pattern） 在编译期分发，零运行开销： cpp template <typename Derived> struct ShapeBase { double area() { return static_cast<Derived*>(this)->area_impl(); } }; struct Circle : ShapeBase<Circle> { double area_impl() { return 3.14159 * r * r; } }; 这样编译器能完全内联，无 vtable 开销。

常见错误

错误 1：忘记 virtual → 隐藏而非覆盖

class Base {
public:
    void f() { std::cout << "Base"; }   // ❌ 忘了 virtual
};
class Derived : public Base {
public:
    void f() { std::cout << "Derived"; }
};
Derived d;
Base *p = &d;
p->f();   // 输出 "Base"——非虚，静态绑定

非虚函数永远静态绑定。若希望多态，基类必须声明 virtual。

错误 2：签名不匹配导致隐藏（override 救命）

class Base {
public:
    virtual void f() const { }      // 注意 const
};
class Derived : public Base {
public:
    void f() { }                    // ❌ 漏了 const → 隐藏！
    void f() override { }           // 加 override → 编译器报错救你
};

永远写 override，让编译器替你检查签名。

错误 3（隐蔽致命）：构造/析构期间调虚函数

class Base {
public:
    Base() { init(); }              // ❌ 构造期间调虚函数
    virtual void init() { std::cout << "Base init"; }
};
class Derived : public Base {
public:
    void init() override { std::cout << "Derived init"; }
};
Derived d;   // 输出 "Base init"！不是 "Derived init"

原因：构造 Derived 时先构造 Base 子对象，此时对象的动态类型是 Base（Derived 还没开始构造），虚调用走 Base::init。析构同理（先析构派生部分，此时动态类型已变回 Base）。

教训：构造/析构期间永远不要调虚函数——它不会按你期望的多态分发。若要"构造时按派生类方式初始化"，让派生类构造函数显式传递参数给基类构造函数。

错误 4：虚函数默认实参不一致

见上文"核心用法 5"。p->f() 调用 Derived::f 但用 Base 的默认实参，输出令人困惑。统一默认实参值。

自测题

1. 选择题：以下哪种调用会触发动态绑定？

A. d.f() 其中 d 是 Derived 类型的对象 B. Base& r = d; r.f(); 其中 f 是虚函数 C. Base b = d; b.f(); 其中 f 是虚函数 D. Base::f() 显式限定调用

答案

B。动态绑定只在通过引用或指针调用虚函数时发生。A 是值对象调用（静态类型已知，静态绑定）；C 发生对象切片，b 是纯 Base，静态绑定；D 是显式限定（Base::），强制静态绑定。

2. 判断题：派生类覆盖虚函数时，如果基类版本有 const 限定而派生类版本没有，代码能编译通过（不写 override 时）。

答案

对（这是危险之处）。不写 override 时，签名不匹配会被当作"派生类定义了一个新函数，隐藏了基类版本"——编译能过，但行为是错的（通过基类指针调用走的是基类版本）。写 override 后编译器会报错——这正是 override 的价值。所以铁律：凡是要覆盖的函数都写 override。

3. 踩坑题：以下代码输出什么？为什么？

class Base {
public:
    Base() { log(); }
    virtual void log() const { std::cout << "Base\n"; }
};
class Derived : public Base {
public:
    void log() const override { std::cout << "Derived\n"; }
};
int main() {
    Derived d;
}
答案

输出 Base。构造 Derived d 时先执行 Base 的构造函数，此时对象的动态类型仍是 Base（Derived 部分还没构造），所以 log() 走 Base::log。这是"构造期间调虚函数"的经典陷阱——它不会多态到 Derived::log。教训：构造/析构期间不要调虚函数。

4. 应用题：用虚函数设计一个简单的 Logger 体系——基类 Logger 提供 log(msg) 虚函数（默认打印到 stdout），派生类 FileLogger 覆盖它写入文件。要求： - 基类析构安全 - 派生类用 override 标注 - 能通过 Logger* 多态调用

答案 
#include <iostream>
#include <fstream>
#include <string>
class Logger {
public:
    virtual ~Logger() = default;                         // 虚析构
    virtual void log(const std::string &msg) const {     // 虚函数，默认实现
        std::cout << "[stdout] " << msg << "\n";
    }
};
class FileLogger : public Logger {
public:
    explicit FileLogger(const std::string &path) : ofs_(path) { }
    void log(const std::string &msg) const override {    // override 标注
        if (ofs_) ofs_ << "[file] " << msg << "\n";
    }
private:
    mutable std::ofstream ofs_;   // log 是 const，文件流用 mutable
};
// 多态调用：
void run(Logger *lg) { lg->log("hello"); }   // 动态绑定到实际类型

要点：基类虚析构、virtual 声明、override 标注、const 成员函数 + mutable 文件流、通过基类指针多态调用。

15.3

抽象基类与访问控制

本节讲什么

本节讲解两个相关但独立的概念：(1) 纯虚函数和抽象基类（abstract base class, ABC）——如何用 = 0 定义"接口"，强制派生类实现；(2) protected 访问控制在继承体系中的作用，以及友元与继承的交互。这是 OOP 中"接口与实现分离"的核心工具。

一句话定位：抽象基类 = "只定义接口，不提供完整实现"——含纯虚函数的类不能实例化，只能作为基类；派生类必须实现所有纯虚函数才能实例化。

核心用法

1. 纯虚函数

在虚函数声明后加 = 0，使其成为纯虚函数（pure virtual function）：

class Shape {
public:
    virtual double area() const = 0;     // 纯虚函数
    virtual void draw() const = 0;       // 纯虚函数
    virtual ~Shape() = default;          // 即使是抽象类，析构也要虚
};

特点： - 纯虚函数可以提供定义（在类外），但通常不提供——它的意义就是"派生类必须自己实现" - 含纯虚函数的类是抽象类，不能创建对象： cpp Shape s; // ❌ 错误：Shape 是抽象类 Shape *p; // ✅ 可以定义指针/引用（用于多态）

2. 抽象基类作为"接口"

抽象基类的典型用法是定义接口契约——规定派生类必须提供哪些操作：

// 接口：定义"可比较"的概念
class Comparable {
public:
    virtual bool less_than(const Comparable &other) const = 0;
    virtual ~Comparable() = default;
};
// 派生类必须实现 less_than 才能实例化
class Number : public Comparable {
public:
    Number(int v) : val_(v) { }
    bool less_than(const Comparable &other) const override {
        const Number &n = dynamic_cast<const Number&>(other);
        return val_ < n.val_;
    }
private:
    int val_;
};

设计意图：抽象基类表达"是什么能力"（Comparable、Drawable、Serializable），而非"是什么东西"。这与 Java 的 interface 思路一致，但 C++ 的抽象类可以含数据成员和非纯虚函数（更灵活）。

3. 派生类必须实现所有纯虚函数

class Shape {
public:
    virtual double area() const = 0;
    virtual void draw() const = 0;
    virtual ~Shape() = default;
};
class Circle : public Shape {
public:
    double area() const override { return 3.14 * r * r; }
    // ❌ 没实现 draw()，Circle 仍是抽象类，无法实例化
};
class Square : public Shape {
public:
    double area() const override { return side * side; }
    void draw() const override { /* ... */ }   // ✅ 全部实现，可实例化
};

若派生类漏掉一个纯虚函数，派生类自身也变成抽象类——这通常是你忘了实现的信号。

4. 纯虚函数的"默认实现"（少用但合法）

纯虚函数可以在类外提供定义，派生类可显式调用：

class Base {
public:
    virtual void f() = 0;     // 声明纯虚
};
void Base::f() { std::cout << "default\n"; }   // 类外提供定义
class Derived : public Base {
public:
    void f() override {
        Base::f();            // 显式调用基类的默认实现
        std::cout << "extended\n";
    }
};

这种用法较少——通常若想提供默认实现，就直接写成普通虚函数（非纯虚）。纯虚 + 默认实现的语义是"派生类必须显式决定是否用默认实现"，略显啰嗦。

5. protected 访问控制

protected 成员：派生类可访问，外部用户不可访问——介于 public 和 private 之间：

class Base {
public:
    int pub;          // 谁都能访问
protected:
    int prot;         // 派生类可访问，外部不可
private:
    int priv;         // 只有 Base 自己能访问，派生类也不行
};
class Derived : public Base {
public:
    void f() {
        pub = 1;      // ✅
        prot = 2;     // ✅ 派生类能访问 protected
        priv = 3;     // ❌ 派生类也不能访问 private
    }
};
int main() {
    Base b;
    b.pub = 1;        // ✅
    b.prot = 2;       // ❌ 外部不能访问 protected
    b.priv = 3;       // ❌
}

设计权衡：protected 数据成员是"对派生类的承诺"——一旦暴露，改起来就要顾及所有派生类。优先用 protected 方法（接口）而非 protected 数据，保留演进自由。C++ 核心指南建议 protected 只放函数，数据一律 private。

6. 友元与继承

友元关系不能继承：

class Base {
    friend class FriendClass;     // FriendClass 能访问 Base 的所有成员
protected:
    int prot;
};
class Derived : public Base { };
class FriendClass {
public:
    void f(Base &b) { b.prot = 1; }       // ✅ 友元可访问 Base
    void g(Derived &d) { d.prot = 1; }    // ❌ 友元不能访问 Derived 的 Base 部分
};

友元关系也不能传递（A 是 B 的友元，B 是 C 的友元，A 不是 C 的友元）。友元是单向、不可继承、不可传递的。

7. 派生类向基类的转换规则（受继承方式影响）

继承方式 派生→基类转换 派生类成员函数访问基类成员
public 用户代码、派生类成员、友元都能转 能访问 public/protected
protected 只有派生类成员和友元能转 能访问 public/protected（都变 protected）
private 只有派生类成员和友元能转 能访问 public/protected（都变 private）

绝大多数情况下用 public 继承——后两者的派生→基类转换被限制在派生类内部，外部无法多态使用。

和 C 的区别

C 没有"抽象类"和"接口"的概念。要模拟"接口契约"，C 程序员靠约定 + 函数指针结构体：

维度 C C++
定义接口 头文件约定 + 函数指针表 纯虚函数 = 0
强制派生类实现 无（全靠注释约定，漏了运行崩溃） 编译期强制（漏了无法实例化）
不能实例化的"接口类" 无（struct 总能定义） 抽象基类编译期禁止实例化
访问控制 无（全靠 static 文件级隐藏） public/protected/private
protected 数据隐藏 无（成员全公开或全文件级 static） protected 限定派生类可见

C 模拟"抽象接口"的写法

// C：手动模拟"接口"
struct Shape;   // 不透明指针
struct ShapeOps {
    double (*area)(const struct Shape*);
    void (*draw)(const struct Shape*);
};
struct Shape {
    const struct ShapeOps *ops;   // 必须由派生类型填充
};
// 调用：s->ops->area(s)
// 若某个派生类型忘记实现 area，运行期 ops->area 是 NULL → 崩溃
// C++ 的纯虚函数让这个错误在编译期暴露

// C++：抽象基类
struct Shape {
    virtual double area() const = 0;   // 派生类必须实现，否则无法实例化
    virtual void draw() const = 0;
    virtual ~Shape() = default;
};

C 版本的痛点：接口契约靠注释，漏实现是运行期崩溃；C++ 让编译器替你检查。

设计哲学：C++ 的抽象基类让"接口"成为语言级概念——你定义的不只是数据布局，而是"派生类必须遵守的契约"。这是 OOP 相对 C 结构体编程的核心跃迁之一。

常见错误

错误 1：抽象基类忘记虚析构

class Shape {
public:
    virtual double area() const = 0;
    // ❌ 没声明虚析构
};
class Circle : public Shape { /* ... */ };
Shape *p = new Circle;
delete p;   // 行为未定义！可能只调基类析构（如果有），派生部分泄漏

修复：即使是抽象类，析构也要声明为虚的：

virtual ~Shape() = default;

错误 2：protected 暴露数据成员过多

class Base {
protected:
    int x, y, z;    // ❌ 全暴露给派生类，未来改不了
    std::vector<int> data;
};

一旦派生类直接用了这些成员，基类演进就受牵制。优先用 protected 方法暴露受控接口：

class Base {
public:
    virtual ~Base() = default;
protected:
    int get_x() const { return x; }      // 受控访问
    void set_x(int v) { x = validate(v); } // 可加校验
private:
    int x, y, z;                          // 数据私有
};

错误 3：派生类漏实现一个纯虚函数 → 仍是抽象类

class Iface {
public:
    virtual void f() = 0;
    virtual void g() = 0;
    virtual ~Iface() = default;
};
class Impl : public Iface {
public:
    void f() override { }
    // ❌ 忘了 g()，Impl 仍是抽象类
};
Impl x;   // 编译错误：不能实例化抽象类

报错信息通常指向"cannot declare variable of abstract type"——这时去检查是不是漏了某个纯虚函数的实现。

错误 4：误以为友元能继承

见上文"友元与继承"。friend class X 只授权 X 访问当前类，不授权 X 的派生类，也不授权当前类的派生类继承这个授权。

自测题

1. 选择题：以下关于纯虚函数的说法，哪个是错误的？

A. 含纯虚函数的类不能创建对象 B. 纯虚函数不能在类外提供定义 C. 派生类必须实现所有纯虚函数才能实例化 D. 纯虚函数声明形式是 virtual void f() = 0;

答案

B 错误。纯虚函数可以在类外提供定义，派生类可通过 Base::f() 显式调用。只是通常不这么做——若想提供默认实现，一般直接写成普通虚函数。

2. 判断题：派生类可以访问基类的 protected 成员，但不能访问其他派生类对象的 protected 成员（即使它们继承自同一个基类）。

答案

对（这是个细微但重要的规则）。protected 成员只能通过"自己的对象"或"自己的派生类对象"访问，不能通过"兄弟派生类对象"访问：

class Base { protected: int prot; };
class D1 : public Base {
public:
    void f(Base &b) { b.prot; }      // ❌ 不能通过 Base 访问
    void g(D1 &d) { d.prot; }        // ✅ 能通过 D1 访问（同类型）
};

这条规则防止 protected 变成"所有派生类共享的全局变量"。

3. 踩坑题：以下代码有什么问题？

class Drawable {
public:
    virtual void draw() const = 0;
};
class Circle : public Drawable {
public:
    void draw() const override { /* 画圆 */ }
};
int main() {
    Drawable *p = new Circle();
    p->draw();
    delete p;
}
答案

Drawable 没有虚析构函数。delete p 时，由于基类析构非虚，行为未定义——通常只销毁 Drawable 部分，Circle 的析构不调用，若 Circle 持有资源就泄漏。

修复：Drawable 加 virtual ~Drawable() = default;。这是抽象基类的铁律——即使是抽象类，析构也要声明为虚的。

4. 应用题：设计一个抽象基类 Serializer，定义 write(int) 和 write(const std::string&) 两个纯虚函数；派生类 JsonSerializer 和 BinarySerializer 分别实现它们。要求基类安全、派生类可多态使用。

答案 
#include <string>
#include <iostream>
class Serializer {
public:
    virtual ~Serializer() = default;                      // 虚析构
    virtual void write(int v) = 0;                        // 纯虚
    virtual void write(const std::string &s) = 0;         // 纯虚（重载）
};
class JsonSerializer : public Serializer {
public:
    void write(int v) override { std::cout << v; }        // JSON 数字直接输出
    void write(const std::string &s) override {           // JSON 字符串加引号
        std::cout << '"' << s << '"';
    }
};
class BinarySerializer : public Serializer {
public:
    void write(int v) override {
        std::cout.write(reinterpret_cast<const char*>(&v), sizeof(v));  // 二进制
    }
    void write(const std::string &s) override {
        int len = static_cast<int>(s.size());
        write(len);                                        // 先写长度
        std::cout.write(s.data(), len);                    // 再写内容
    }
};
// 多态使用：
void serialize(Serializer &s) {
    s.write(42);
    s.write("hello");
}

要点：基类虚析构、纯虚函数声明、override 标注、通过基类引用多态调用、两个派生类各自实现接口。

15.4

继承中的拷贝控制与类作用域

本节讲什么

本节讲解继承体系中两个较深入的话题：(1) 拷贝控制成员（拷贝/移动构造、拷贝/移动赋值、析构）在派生类中如何处理基类部分——派生类的拷贝构造必须显式调用基类拷贝构造，否则基类部分被默认构造；(2) 类作用域下的名字查找规则——派生类作用域嵌套在基类作用域内，派生类同名函数会隐藏基类所有重载版本（即使签名不同），using 声明可恢复。这是 OOP 中"为什么基类析构必须虚"的深究所在。

一句话定位：派生类对象的拷贝/移动/析构涉及"基类部分 + 派生部分"两个层面，每一层都要正确处理；名字查找在继承层次中按作用域嵌套进行，理解它才能避免"明明有这个函数却找不到"的诡异错误。

核心用法

1. 虚析构函数（铁律的深究）

只要一个类可能被用作基类（即可能被继承），其析构函数就应该声明为 virtual：

class Base {
public:
    virtual ~Base() = default;   // ✅ 虚析构
};
class Derived : public Base {
    int *data = new int[1000];
public:
    ~Derived() { delete[] data; }
};
Base *p = new Derived;
delete p;   // ✅ 先调 ~Derived（释放 data），再调 ~Base

如果不声明虚析构：

class BadBase {
public:
    ~BadBase() { }   // ❌ 非虚
};
Base *p = new Derived;
delete p;   // ❌ 行为未定义，通常只调 ~BadBase，~Derived 不调用 → data 泄漏

为什么？ delete p 时，编译器根据 p 的静态类型（Base*）决定调哪个析构。若析构非虚，静态绑定到 ~Base，派生部分不析构。若析构虚，动态绑定到 ~Derived，析构链完整：先 ~Derived，再自动调 ~Base（析构链总是从派生到基类）。

何时不需要虚析构：当类不打算被继承（如 final 类、或纯值类型如 std::string 的某些实现），或不通过基类指针删除时。加虚析构会增加一个 vptr，增大对象体积——所以不要给所有类都加。但只要打算做基类，就一定要加。

2. 派生类的拷贝构造

派生类的拷贝构造函数必须显式调用基类的拷贝构造，否则基类部分被默认构造（不是拷贝！）：

class Base {
public:
    Base() = default;
    Base(const Base &other) : data(other.data) { }
    virtual ~Base() = default;
protected:
    int data;
};
class Derived : public Base {
public:
    Derived() = default;
    // ✅ 正确：显式调用 Base 的拷贝构造
    Derived(const Derived &other)
        : Base(other), extra(other.extra) { }   // Base(other) 触发 Base::Base(const Base&)
    // ❌ 错误：忘了 Base(other)，基类部分被默认构造（data=0 而非拷贝）
    // Derived(const Derived &other) : extra(other.extra) { }
private:
    int extra;
};

注意 Base(other)：传的是 Derived 对象，但 Base 的拷贝构造接受 const Base&，派生类到基类的隐式转换让这个调用合法——它只拷贝 Derived 的 Base 部分（对象切片，但这里正是我们想要的）。

3. 派生类的拷贝赋值

派生类的拷贝赋值运算符必须显式调用基类的拷贝赋值，并处理自赋值：

class Derived : public Base {
public:
    Derived& operator=(const Derived &other) {
        if (this != &other) {              // 自赋值检查
            Base::operator=(other);        // ✅ 显式调基类赋值
            extra = other.extra;           // 再赋值派生类成员
        }
        return *this;
    }
private:
    int extra;
};

忘记 Base::operator=(other) 同样导致基类部分不被赋值——这是隐蔽 bug。

4. 派生类的移动构造/赋值（C++11）

类似拷贝，移动构造也必须显式调用基类的移动构造：

class Derived : public Base {
public:
    Derived(Derived &&other) noexcept
        : Base(std::move(other)),     // ✅ 显式调基类移动构造
          extra(std::move(other.extra)) { }
    Derived& operator=(Derived &&other) noexcept {
        if (this != &other) {
            Base::operator=(std::move(other));   // ✅ 显式调基类移动赋值
            extra = std::move(other.extra);
        }
        return *this;
    }
private:
    int extra;
};

noexcept 很重要：若派生类移动操作不是 noexcept，std::vector 在扩容时会改用拷贝（保证强异常安全）。给移动操作加 noexcept 是性能关键。

5. 派生类的析构链

析构总是按"先派生后基类"的顺序，自动进行——你不需要也无法在派生类析构里显式调基类析构：

class Derived : public Base {
public:
    ~Derived() {
        // 释放派生类资源
        // 函数体结束后，自动调 ~Base
    }
};

析构链顺序：~Derived → ~Base → ~Base 的基类 → ... → ~最顶层基类。这与构造顺序相反（构造是基类→派生类）。

6. 合成的拷贝控制规则

编译器为派生类合成的拷贝控制成员会自动处理基类部分：

成员 合成条件 合成版本的行为
默认构造 无用户定义构造 调基类默认构造 + 成员默认构造
拷贝构造 无用户定义拷贝构造 调基类拷贝构造 + 成员拷贝构造
移动构造 无用户定义移动/拷贝/析构 调基类移动构造 + 成员移动构造
拷贝赋值 无用户定义拷贝赋值 调基类拷贝赋值 + 成员拷贝赋值
移动赋值 无用户定义移动/拷贝赋值 调基类移动赋值 + 成员移动赋值
析构 总是合成 释放派生类成员，自动调基类析构

三/五/零法则在继承中的体现： - 三法则：若基类需要析构（通常因为是基类→虚析构），通常也需要拷贝/移动控制 - 五法则：定义了其中之一，通常都要定义 - 零法则：派生类若用 RAII 成员（unique_ptr/vector/string），啥都不写，合成版本自动正确处理基类和成员——这是最佳实践

class Derived : public Base {
    // 啥都不写！合成的拷贝/移动/析构会正确处理 Base 部分和 members
private:
    std::vector<int> data;    // RAII 成员
    std::unique_ptr<Cache> cache;
};

7. 类作用域与名字查找

派生类作用域嵌套在基类作用域内——名字查找从内向外：

全局作用域
  └─ Base 作用域
       └─ Derived 作用域
            └─ 代码处

查找规则：编译器从当前作用域开始向外找，找到第一个匹配名字就停下，然后检查类型是否兼容。这意味着派生类同名函数会隐藏基类所有同名函数（即使签名不同）：

class Base {
public:
    void f() { }              // 无参版本
    void f(int) { }           // int 版本
};
class Derived : public Base {
public:
    void f(double) { }        // 隐藏了 Base 的两个 f！
};
Derived d;
d.f();        // ❌ 编译错误：Derived::f(double) 不接受无参
d.f(1);       // ✅ 调 Derived::f(double)，1 转 double
d.f(1, 2);    // ❌ 编译错误

为什么 d.f() 报错？查找 f 在 Derived 作用域找到 f(double)，停下，不再往 Base 找——即使 Base 有 f() 也不考虑。然后类型检查 f() 无参 vs f(double) 需参 → 报错。

8. using 声明恢复基类名字

要让派生类同时拥有基类的重载版本，用 using 声明把它们"引入"派生类作用域：

class Derived : public Base {
public:
    using Base::f;            // ✅ 把 Base 的所有 f 引入 Derived 作用域
    void f(double) { }        // 再添加自己的版本
};
Derived d;
d.f();        // ✅ 调 Base::f()
d.f(1);       // ✅ 重载解析：Base::f(int) 更匹配，调它
d.f(1.5);     // ✅ 调 Derived::f(double)

using Base::f 把 Base 的所有 f 重载都"复制"到 Derived 作用域，与 Derived::f(double) 一起参与重载解析。

9. 名字查找 vs 类型检查（先找名字，再查类型）

这是 C++ 一个反直觉但重要的规则：名字查找在类型检查之前。如果名字在派生类作用域找到了（即使类型不匹配），就不再往基类找：

class Base {
public:
    void g(int) { }
};
class Derived : public Base {
public:
    void g(double) { }     // 隐藏 Base::g(int)
};
Derived d;
d.g(5);       // 调 Derived::g(double)，5 转 double——而非 Base::g(int)

5 本可以完美匹配 Base::g(int)，但因为 Derived::g 隐藏了 Base::g，查找停在 Derived，5 被转成 double 调 Derived::g。这种"隐藏导致非最优匹配"是隐蔽 bug 来源。

和 C 的区别

C 没有继承，也就没有"派生类拷贝控制涉及基类部分"的问题——C 结构体的拷贝就是 memcpy，一视同仁。但 C 结构体没有自动资源管理，深拷贝要手动写：

维度 C C++
结构体拷贝 memcpy 或手写 struct_copy 拷贝构造函数，自动调基类部分
析构链 手动调"基类析构"再"派生类析构" 自动从派生到基类
名字隐藏 无（C 无作用域嵌套） 派生类同名隐藏基类
虚析构保证 无（手动维护函数指针表） virtual ~Base() 语言保证
零法则 不适用（C 无 RAII） 用 RAII 成员，啥都不写

C 手动模拟"派生类拷贝"的写法

struct Base { int data; };
struct Derived { struct Base base; int extra; };
// 手动写拷贝函数
void derived_copy(struct Derived *dst, const struct Derived *src) {
    dst->base.data = src->base.data;    // 手动拷基类部分
    dst->extra = src->extra;            // 手动拷派生部分
    // 漏掉 base.data 的拷贝 → bug，编译器不报
}
// 手动写析构链
void derived_destroy(struct Derived *d) {
    /* 派生类资源释放 */
    base_destroy(&d->base);   // 手动调"基类析构"，顺序错就泄漏
}

// C++：合成版本自动正确
class Derived : public Base {
    std::vector<int> data;   // RAII
public:
    // 啥都不写！合成拷贝构造：先 Base 拷贝，再 data 拷贝
    // 合成析构：先释放 data，自动调 ~Base
};

C 版本全靠程序员记得调"基类部分"——漏了就是 bug。C++ 的合成版本和 RAII 把这一切自动化，零法则让你啥都不写就对了。

HFT 视角：派生类移动操作加 noexcept 极关键——std::vector<Base*> 扩容时若元素类型移动非 noexcept，会用拷贝（防止移动中途抛异常导致数据丢失）。noexcept 移动让 vector 扩容 O(n) 而非 O(n) 拷贝 + 析构，热路径性能差几倍。

常见错误

错误 1（铁律）：基类析构非虚

见上文"核心用法 1"。只要类可能被继承且通过基类指针删除，析构必须虚。这是 C++ OOP 第一铁律。

错误 2：派生类拷贝构造忘记调基类拷贝构造

class Derived : public Base {
public:
    Derived(const Derived &other) : extra(other.extra) { }  // ❌ 没调 Base(other)
};

基类部分被默认构造，data 不是从 other 拷贝来的——数据丢失。修复：Derived(const Derived &other) : Base(other), extra(other.extra) { }。

错误 3：派生类拷贝赋值忘记自赋值检查和基类赋值

Derived& operator=(const Derived &other) {
    extra = other.extra;     // ❌ 没调 Base::operator=，没查自赋值
    return *this;
}

两个问题：(1) 基类部分没赋值；(2) 自赋值时若成员是指针可能先释放再读。修复：

Derived& operator=(const Derived &other) {
    if (this != &other) {
        Base::operator=(other);
        extra = other.extra;
    }
    return *this;
}

错误 4（隐蔽）：派生类同名函数隐藏基类重载

见上文"核心用法 7"。Derived::f(double) 隐藏了 Base::f() 和 Base::f(int)，导致 d.f() 报错。修复：using Base::f; 把基类重载引入派生类作用域。

错误 5：析构链顺序搞反

~Derived() {
    Base::~Base();      // ❌ 不要手动调基类析构！
    // 释放派生资源
}

析构链自动按派生→基类顺序。手动调基类析构会导致基类被析构两次（一次手动，一次自动），未定义行为。派生类析构只管自己的资源，基类析构编译器自动调。

自测题

1. 选择题：派生类的拷贝构造函数初始值列表中，若没有显式调用 Base(other)，会发生什么？

A. 编译错误 B. 基类部分被默认构造 C. 基类部分被拷贝构造 D. 程序崩溃

答案

B。若不显式调基类拷贝构造，基类部分用默认构造初始化——这是隐蔽 bug：你以为拷贝了整个对象，实际基类部分是默认值，数据丢失。编译能过（基类有默认构造的话），运行时才发现。

2. 判断题：派生类析构函数执行完毕后，基类的析构函数会被自动调用，无需手动调用。

答案

对。析构链自动按"派生→基类"顺序进行，编译器在派生类析构函数体结束后自动插入对基类析构的调用。手动调基类析构会导致重复析构，未定义行为。

3. 踩坑题：以下代码有什么问题？

class Base {
public:
    virtual ~Base() = default;
    void log(int x) { std::cout << "int " << x; }
};
class Derived : public Base {
public:
    void log(double x) { std::cout << "double " << x; }
};
int main() {
    Derived d;
    d.log(5);        // 期望调 Base::log(int)
}
答案

d.log(5) 调的是 Derived::log(double)，输出 double 5——而非 Base::log(int)。因为 Derived::log 隐藏了 Base::log，名字查找停在 Derived 作用域，5 被转成 double。

若要让两个重载共存，加 using Base::log;：

class Derived : public Base {
public:
    using Base::log;            // 引入 Base::log(int)
    void log(double x) { /* ... */ }
};

此时 d.log(5) 重载解析选 Base::log(int)（精确匹配优于转换）。

4. 应用题：设计一个含动态资源的基类 Buffer 和派生类 LoggedBuffer，要求： - 基类有 char* 动态数组，虚析构 - 派生类额外有日志计数器 - 正确实现派生类的拷贝构造和拷贝赋值（处理基类部分） - 遵循零法则的话，你会怎么改？

答案

手动版（三法则）：

#include <cstring>
class Buffer {
public:
    Buffer(size_t n) : size_(n), data_(new char[n]) { }
    virtual ~Buffer() { delete[] data_; }
    Buffer(const Buffer &o) : size_(o.size_), data_(new char[o.size_]) {
        std::memcpy(data_, o.data_, size_);
    }
    Buffer& operator=(const Buffer &o) {
        if (this != &o) {
            char *tmp = new char[o.size_];      // 先分配再释放（异常安全）
            std::memcpy(tmp, o.data_, o.size_);
            delete[] data_;
            data_ = tmp; size_ = o.size_;
        }
        return *this;
    }
protected:
    size_t size_;
    char *data_;
};
class LoggedBuffer : public Buffer {
public:
    LoggedBuffer(size_t n) : Buffer(n), log_count_(0) { }
    LoggedBuffer(const LoggedBuffer &o)
        : Buffer(o), log_count_(o.log_count_) { }      // ✅ 显式调基类拷贝
    LoggedBuffer& operator=(const LoggedBuffer &o) {
        if (this != &o) {
            Buffer::operator=(o);                       // ✅ 显式调基类赋值
            log_count_ = o.log_count_;
        }
        return *this;
    }
private:
    size_t log_count_;
};

零法则版（推荐）——用 std::vector<char> 替代手写 char*，啥都不写：

class Buffer {
public:
    virtual ~Buffer() = default;                        // 虚析构仍是铁律
protected:
    std::vector<char> data_;                            // RAII，自动管理
};
class LoggedBuffer : public Buffer {
    // 啥都不写！合成拷贝/赋值/析构自动正确：
    // - 拷贝：先拷 data_（vector 拷贝），再拷 log_count_
    // - 析构：先析构 log_count_（trivial），自动析构 data_（vector 释放内存）
private:
    size_t log_count_ = 0;
};

零法则版的优越性：没有手动内存管理、没有自赋值检查、没有异常安全样板代码、不会忘记调基类部分——合成版本全对。能用 RAII 就用 RAII。

容器与继承

本节讲什么

本节讲解继承体系与容器交互时的两个核心难题：(1) 对象切片（object slicing）——为什么 vector<Base> 直接存派生类对象会"切掉"派生部分，必须用 vector<unique_ptr<Base>> 才能多态；(2) 菱形继承（diamond inheritance）与虚继承（virtual inheritance）——当派生类从多个路径继承同一个基类时，基类子对象会重复，虚继承如何解决。这是 OOP 实战中"容器 + 继承"的经典痛点。

一句话定位：容器存继承体系的对象，必须存基类的指针（最好是智能指针），不能存值——否则派生部分被切掉，多态失效。

核心用法

1. 对象切片问题

当派生类对象赋值给基类对象（值，非引用）时，派生部分被"切掉"，只拷贝基类部分：

class Base {
public:
    virtual void f() { std::cout << "Base"; }
    int base_data = 1;
};
class Derived : public Base {
public:
    void f() override { std::cout << "Derived"; }
    int derived_data = 2;    // 派生类独有
};
Derived d;
Base b = d;          // ❌ 对象切片！b 只拷贝了 Base 部分，derived_data 丢失
b.f();               // 输出 "Base"（b 的 vptr 指向 Base vtable）

切片发生的原因：b 是一个 Base 对象，内存大小固定为 sizeof(Base)，容纳不下 Derived 的额外成员。编译器只拷贝 Base 部分，且 b 的 vptr 被设为 Base 的——多态失效。

2. 容器与对象切片

直接用 vector<Base> 存继承体系的对象，每个派生类对象在插入时都被切片：

std::vector<Base> v;
v.push_back(Base{});
v.push_back(Derived{});    // ❌ 切片！存进去的是 Base，Derived 部分丢失
for (auto &x : v) x.f();   // 全输出 "Base"

正确做法：容器存基类的指针（或智能指针），多态才生效：

#include <vector>
#include <memory>
std::vector<std::unique_ptr<Base>> v;
v.push_back(std::make_unique<Base>());
v.push_back(std::make_unique<Derived>());    // ✅ 派生对象完整保留在堆上
for (auto &p : v) p->f();    // 输出 "Base" "Derived"（多态生效）
// unique_ptr 自动 delete，且因 Base 析构虚，~Derived 正确调用

为什么必须指针？ 容器元素大小固定，无法容纳不同大小的派生类。指针大小固定，指向堆上的实际对象（大小各异），多态通过虚函数实现。这是 C++ OOP 的标准惯用法。

3. 基类析构必须虚（再强调）

容器存 unique_ptr<Base>，析构时调 unique_ptr 的析构，它 delete 内部指针。若 Base 析构非虚，delete 只调 ~Base，~Derived 不调用——派生资源泄漏：

class Base {
public:
    ~Base() { }     // ❌ 非虚
};
class Derived : public Base {
    int *data = new int[100];
public:
    ~Derived() { delete[] data; }
};
{
    std::vector<std::unique_ptr<Base>> v;
    v.push_back(std::make_unique<Derived>());
}   // vector 析构 → unique_ptr 析构 → delete ptr → 只调 ~Base → data 泄漏！

铁律重申：只要类可能被继承且通过基类指针删除（容器场景必属此类），析构必须虚。详见 15.4。

4. shared_ptr 的拷贝与容器

shared_ptr<Base> 也常用于容器，且支持拷贝（多个容器共享同一对象）：

std::vector<std::shared_ptr<Base>> v1;
auto p = std::make_shared<Derived>();
v1.push_back(p);
std::vector<std::shared_ptr<Base>> v2 = v1;   // 浅拷贝，两个 vector 共享对象
// 引用计数管理，最后一个 shared_ptr 销毁时对象才 delete

选择 unique_ptr 还是 shared_ptr： - 独占所有权（一个容器独占对象）→ unique_ptr，零开销 - 共享所有权（多处需要持有同一对象）→ shared_ptr，引用计数有原子操作开销

5. 菱形继承问题

当一个派生类从两条路径继承同一个基类时，基类子对象会重复：

class Person {
public:
    std::string name;
};
class Student : public Person { /* ... */ };
class Teacher : public Person { /* ... */ };
class TA : public Student, public Teacher { };   // 菱形继承
TA ta;
ta.name = "Alice";    // ❌ 二义性！TA 有两个 Person 子对象（来自 Student 和 Teacher）
ta.Student::name = "Alice";   // 必须显式指定
ta.Teacher::name = "Bob";     // 两个 name 可以不同——通常不是你想要的

       Person
       /    \
   Student  Teacher
       \    /
        TA

TA 对象内存中有两份 Person 子对象，访问 name 二义。这在 C++ 多继承中是经典陷阱。

6. 虚继承解决菱形

virtual 继承让共享基类只保留一份子对象：

class Person { public: std::string name; };
class Student : virtual public Person { };    // ✅ virtual 继承
class Teacher : virtual public Person { };    // ✅ virtual 继承
class TA : public Student, public Teacher { };
TA ta;
ta.name = "Alice";    // ✅ 唯一一份 Person，无二义性

虚继承的代价： - 虚基类子对象通过指针间接访问（多一次内存访问） - 虚继承的构造较复杂：最远派生类（这里是 TA）负责初始化虚基类，中间类（Student/Teacher）对虚基类的构造调用被忽略 - 编译器实现通常用一个 vbase offset 表

设计建议：虚继承复杂且易错，优先用组合替代多继承。若必须多继承，常用模式是"接口多继承 + 实现单继承"——多个纯虚基类（接口）+ 一个具体基类，避开菱形数据继承。

7. 实战模式：多态容器 + 工厂

容器 + 继承的典型用法：

#include <vector>
#include <memory>
#include <iostream>
class Shape {
public:
    virtual void draw() const = 0;
    virtual ~Shape() = default;
};
class Circle : public Shape {
public:
    void draw() const override { std::cout << "○\n"; }
};
class Square : public Shape {
public:
    void draw() const override { std::cout << "□\n"; }
};
int main() {
    std::vector<std::unique_ptr<Shape>> shapes;
    shapes.push_back(std::make_unique<Circle>());
    shapes.push_back(std::make_unique<Square>());
    for (const auto &s : shapes) s->draw();   // 多态：○ □
    // unique_ptr 自动释放，虚析构保证 ~Circle/~Square 调用
}

和 C 的区别

C 没有继承，"容器存不同类型"靠 void* + 手动类型标签：

维度 C C++
异质容器 void* + enum type 标签 vector<unique_ptr<Base>>
类型分发 switch(type) 手动 虚函数自动
内存管理 手动 malloc/free，易泄漏 智能指针 RAII
析构链 手动调每个"派生"析构 虚析构自动
菱形继承 无（C 无多继承） 虚继承解决

C 模拟异质容器的写法

enum ShapeType { CIRCLE, SQUARE };
struct Shape {
    enum ShapeType type;
    void *impl;     // 指向具体数据
};
struct Circle { double radius; };
struct Square { double side; };
// 容器：struct Shape shapes[100];
// 绘制：switch (s.type) { case CIRCLE: draw_circle(s.impl); break; ... }
// 释放：switch (s.type) { case CIRCLE: free(s.impl); break; ... }
// 漏掉一个 case 就是 bug，没有编译器帮你检查

// C++：多态容器
std::vector<std::unique_ptr<Shape>> shapes;
// 添加新类型：只需定义新派生类，不改已有代码（开闭原则）
// 析构：虚析构 + unique_ptr 自动，不会漏

C 版本的全 switch 分发是维护噩梦——每加一个类型要改所有 switch。C++ 的虚函数让"加类型"只需新增派生类，符合开闭原则。

HFT 视角：多态容器用 unique_ptr 有堆分配开销，热路径上可能不可接受。替代方案：(1) 对象池 + 索引，避免反复分配；(2) std::variant<Circle, Square> + std::visit，编译期多态无堆分配（但类型集合固定）；(3) SoA（Structure of Arrays）布局，按类型分桶存连续内存，cache 友好。

常见错误

错误 1：容器存值类型 → 对象切片

std::vector<Base> v;
v.push_back(Derived{});    // ❌ 切片

修复：std::vector<std::unique_ptr<Base>> + make_unique<Derived>()。

错误 2：基类析构非虚 + 容器智能指针 → 泄漏

见上文"核心用法 3"。容器存 unique_ptr<Base> 时，Base 析构必须虚，否则派生资源泄漏。

错误 3：菱形继承未用虚继承 → 二义性

class A { public: int x; };
class B : public A { };
class C : public A { };
class D : public B, public C { };
D d;
d.x = 1;    // ❌ 二义性：D 有两份 A 子对象

修复：B 和 C 改为 virtual public A，让 D 只有一份 A。或重构为组合，避免菱形。

错误 4：容器存裸指针 → 忘记 delete

std::vector<Base*> v;
v.push_back(new Derived);
// ... 用完忘记 delete v[i] → 泄漏

修复：用 unique_ptr<Base>，RAII 自动释放。永远不要用裸指针容器，除非有明确的性能理由 + 对象池管理。

错误 5：shared_ptr 容器深拷贝期望

std::vector<std::shared_ptr<Base>> v1 = { std::make_shared<Derived>() };
auto v2 = v1;    // 浅拷贝！v1[0] 和 v2[0] 指向同一对象
v2[0]->modify(); // v1[0] 也被修改——可能不是你期望的"独立拷贝"

若需要独立拷贝，要实现虚 clone 函数：

class Base {
public:
    virtual std::unique_ptr<Base> clone() const = 0;
};
class Derived : public Base {
public:
    std::unique_ptr<Base> clone() const override {
        return std::make_unique<Derived>(*this);   // 拷贝构造
    }
};
// 深拷贝容器：
std::vector<std::unique_ptr<Base>> deep;
for (auto &p : v1) deep.push_back(p->clone());

自测题

1. 选择题：以下哪种容器声明能正确实现多态（存不同派生类对象并各自调对虚函数）？

A. std::vector<Base> B. std::vector<Base*> C. std::vector<std::unique_ptr<Base>> D. B 和 C 都可以，C 更安全

答案

D。A 会对象切片（值类型，派生部分丢失）；B 和 C 都存指针，多态生效。C 优于 B——unique_ptr 自动释放，避免手动 delete 的泄漏风险。前提是 Base 析构虚。

2. 判断题：菱形继承中，若 B 和 C 都 virtual public A，则 D : public B, public C 的对象中 A 子对象只有一份。

答案

对。虚继承的核心作用就是让虚基类在继承层次中只保留一份子对象，消除菱形继承的二义性。D 对象中 A 子对象唯一，d.x 无二义。

3. 踩坑题：以下代码有什么问题？

class Animal {
public:
    virtual void speak() { std::cout << "..."; }
    ~Animal() { }     // 注意：非虚
};
class Dog : public Animal {
public:
    void speak() override { std::cout << "Woof"; }
};
int main() {
    std::vector<std::unique_ptr<Animal>> zoo;
    zoo.push_back(std::make_unique<Dog>());
}
答案

Animal 析构非虚。当 zoo 析构时，unique_ptr 调 delete 内部指针，因析构非虚，只调 ~Animal，~Dog 不调用——若 Dog 持有资源（如 std::string name）则泄漏。

修复：virtual ~Animal() = default;。这是容器 + 继承场景的必备条件。

4. 应用题：设计一个简单的绘图程序，要求： - 抽象基类 Shape，派生类 Circle/Rectangle - 用 vector<unique_ptr<Shape>> 管理多个形状 - 遍历调 draw() 多态输出 - 支持深拷贝整个容器（虚 clone）

答案 
#include <vector>
#include <memory>
#include <iostream>
#include <string>
class Shape {
public:
    virtual void draw() const = 0;
    virtual std::unique_ptr<Shape> clone() const = 0;   // 虚 clone
    virtual ~Shape() = default;                         // 虚析构
};
class Circle : public Shape {
public:
    Circle(double r) : radius_(r) { }
    void draw() const override { std::cout << "Circle r=" << radius_ << "\n"; }
    std::unique_ptr<Shape> clone() const override {
        return std::make_unique<Circle>(*this);         // 拷贝构造
    }
private:
    double radius_;
};
class Rectangle : public Shape {
public:
    Rectangle(double w, double h) : w_(w), h_(h) { }
    void draw() const override { std::cout << "Rect " << w_ << "x" << h_ << "\n"; }
    std::unique_ptr<Shape> clone() const override {
        return std::make_unique<Rectangle>(*this);
    }
private:
    double w_, h_;
};
int main() {
    std::vector<std::unique_ptr<Shape>> shapes;
    shapes.push_back(std::make_unique<Circle>(5));
    shapes.push_back(std::make_unique<Rectangle>(3, 4));
    for (const auto &s : shapes) s->draw();             // 多态：Circle, Rect
    // 深拷贝：
    std::vector<std::unique_ptr<Shape>> copy;
    for (const auto &s : shapes) copy.push_back(s->clone());
    // 修改 copy 不影响 shapes
    return 0;
}

要点：抽象基类 + 纯虚 draw/clone、虚析构、unique_ptr<Shape> 容器、clone() 实现深拷贝、override 标注。

Q1虚函数分派
class Shape {
public:
    virtual void draw() { std::cout << "Shape "; }
    void print() { std::cout << "Print "; }
};
class Circle : public Shape {
public:
    void draw() override { std::cout << "Circle "; }
    void print() { std::cout << "CirclePrint "; }
};
Shape *s = new Circle;
s->draw();   // A
s->print();  // B

A 和 B 分别输出什么？virtual 的作用是什么？

答案与复习指引

A: Circle — draw() 是虚函数，运行时根据对象实际类型（Circle）调用 B: Print — print() 不是虚函数，编译时根据指针类型（Shape*）调用

virtual 的作用： 启用动态绑定（运行时分派）。虚函数通过 vptr→vtable 间接调用，代价是多一次间接访存 + 不可内联。

override 的作用： 让编译器检查是否真的重写了基类虚函数（签名必须匹配），防止"以为重写了其实没有"的 bug。

复习： → 虚函数与动态绑定

Q2虚析构函数
class Base {
public:
    ~Base() {}  // 非虚析构
};
class Derived : public Base {
    int *data;
public:
    Derived() : data(new int[100]) {}
    ~Derived() { delete[] data; }
};
Base *p = new Derived;
delete p;  // 会发生什么？

delete p 会发生什么？如何修复？

答案与复习指引

内存泄漏。 delete p 调用 Base 的析构（非虚），不调用 Derived 的析构 → data 泄漏。

修复： 基类析构声明为 virtual：

virtual ~Base() {}

这样 delete p 先调 Derived::~Derived()（释放 data），再调 Base::~Base()。

规则： 如果类可能被继承且通过基类指针删除，析构函数必须是 virtual。这是 OOP 的铁律。

复习： → 基类与派生类

Q3对象切片
class Animal {
public:
    virtual std::string sound() { return "..."; }
};
class Dog : public Animal {
public:
    std::string sound() override { return "Woof"; }
};
Dog d;
Animal a = d;  // 值拷贝
std::cout << a.sound();

输出是什么？为什么？如何避免切片？

答案与复习指引

输出： ... — a.sound() 调用 Animal::sound()，不是 Dog::sound()

原因： Animal a = d 把 Dog 对象拷贝到 Animal 对象——派生部分被"切掉"了。a 是一个纯正的 Animal 对象，它的 vptr 指向 Animal 的 vtable。

避免切片： 1. 通过指针/引用操作多态对象：Animal &a = d; 2. 容器存指针：vector<unique_ptr<Animal>> 3. 拷贝构造设为 protected 或 =delete
