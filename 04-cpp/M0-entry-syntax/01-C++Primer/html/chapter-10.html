章节摘要

泛型算法（不绑定容器、操作迭代器范围）：find/count/accumulate/fill/sort/unique/copy/transform 等。定制操作（lambda 表达式、谓词、函数对象）、再探迭代器（插入迭代器/流迭代器/反向迭代器）。

和 C 的区别

C C++
qsort + 函数指针 std::sort + lambda（类型安全+可内联）
bsearch std::binary_search/lower_bound
手写循环 std::for_each/std::transform/std::copy

10.1

基础算法与重排

本节讲什么

C++ 标准库 <algorithm> 提供的泛型算法：查找（find）、计数（count）、累加（accumulate）、排序（sort）、去重（unique）等。它们通过迭代器工作，对任意容器通用，且永不改变容器大小。C 程序员对应的是 qsort/bsearch，但 C++ 算法库丰富得多、类型安全、可内联。

核心用法

只读算法

#include <algorithm>
#include <numeric>      // accumulate 在这
std::vector<int> v = {3, 1, 4, 1, 5};

// find：查找，返回迭代器
auto it = std::find(v.begin(), v.end(), 4);
if (it != v.end()) std::cout << "found at " << (it - v.begin());

// count：计数
int n = std::count(v.begin(), v.end(), 1);   // 2

// accumulate：累加（注意初值类型决定结果类型）
int sum = std::accumulate(v.begin(), v.end(), 0);   // 14

排序与重排

std::vector<int> v = {3, 1, 4, 1, 5};

std::sort(v.begin(), v.end());                 // 升序：1,1,3,4,5
std::sort(v.begin(), v.end(), std::greater<>()); // 降序

// unique 去重（要求先排序），返回去重后末尾
auto last = std::unique(v.begin(), v.end());
v.erase(last, v.end());    // 真正删除（unique 只搬到末尾，不删）

关键原则：算法不改容器大小

find/sort/unique 等都不增删元素，只搬运/重排。要真删要用容器的 erase（如 erase-remove 惯用法）。

和 C 的区别

维度 C C++
排序 qsort（函数指针，不可内联，慢） std::sort（模板/lambda，可内联，快）
查找 bsearch（要已排序） find/find_if/binary_search
算法数量 极少（qsort/bsearch） <algorithm> 上百个
类型安全 ❌ qsort 用 void* + 元素大小，类型错就 UB ✅ 模板按类型推导
泛型性 只能对数组 任意迭代器范围（容器/数组/流）
比较函数 函数指针（间接调用，慢） 函数对象/lambda（可内联，快）

C 程序员最该体会的：

  1. 类型安全 + 可内联：C 的 qsort 用 void* 和元素大小，类型错就 UB，且函数指针无法内联（慢）。C++ 的 std::sort 是模板，类型编译期确定，比较器是 lambda/函数对象可内联，通常比 qsort 快几倍。
/* C：qsort，void* + 元素大小，类型不安全，函数指针不可内联 */
int cmp(const void* a, const void* b) {
    return *(const int*)a - *(const int*)b;   // int 溢出 UB
}
int arr[5] = {3,1,4,1,5};
qsort(arr, 5, sizeof(int), cmp);   // 慢（间接调用）+ 易错

// C++：sort，模板 + lambda，类型安全 + 可内联
std::vector<int> v = {3,1,4,1,5};
std::sort(v.begin(), v.end());                  // 默认 <
std::sort(v.begin(), v.end(), [](int a, int b){ return a > b; });  // lambda 可内联
  1. 算法丰富：C 只有 qsort/bsearch，C++ 有上百个算法（find/count/accumulate/copy/transform/remove/partition/merge/...），不用手写。

常见错误

  1. accumulate 初值类型错：std::accumulate(v.begin(), v.end(), 0) 对 vector<double> 会把 double 当 int 累加（初值 0 是 int），丢小数。修正：初值写 0.0。
  2. unique 后不 erase：unique 只把重复元素搬到末尾，不删除，size 不变。不 erase 就还有"垃圾"。惯用法：v.erase(std::unique(v.begin(),v.end()), v.end());
  3. 对未排序容器用 binary_search/lower_bound：这些要求已排序，对未排序容器用结果未定义。先 sort 再用。

自测题

1. 选择题：std::accumulate(v.begin(), v.end(), 0) 对 vector<double>{1.5, 2.5} 的结果是？ - A) 4.0 - B) 3 - C) 4 - D) 编译错误

答案

C) 4。初值 0 是 int，accumulate 的结果类型跟随初值，所以整个累加按 int 进行，1.5+2.5=4.0 但被截断为 int 4（每次加都截断）。修正：std::accumulate(v.begin(), v.end(), 0.0) 初值用 double，结果 4.0。这是 accumulate 最经典的坑。

2. 判断题：std::find 找不到元素时会返回 v.end()。

答案

正确。find 返回指向第一个匹配元素的迭代器，找不到返回结束迭代器 end()。所以用法是 if (it != v.end()) 判断找到。这与 C 的 bsearch（返回 NULL）不同，但语义类似。

3. 踩坑题：下面代码想去重，但 vector 里还有重复元素，为什么？

std::vector<int> v = {3, 1, 1, 4};
std::unique(v.begin(), v.end());
// v 仍是 {3,1,1,4} 之类，没真正去重
答案

两个问题：1) unique 只去除相邻重复，未排序时 {3,1,1,4} 的相邻 1 被去，但若不相邻就不管；2) unique 不删元素，只把重复搬到末尾，size 不变。正确去重：

std::sort(v.begin(), v.end());                 // 先排序
v.erase(std::unique(v.begin(), v.end()), v.end());  // 再 unique + erase

4. 应用题：用 std::sort + 自定义比较器把 vector<string> 按字符串长度排序（短的在前），写出代码并说明比 C 的 qsort 优势。

答案 
std::vector<std::string> words = {"banana", "apple", "kiwi", "pear"};
std::sort(words.begin(), words.end(),
          [](const std::string& a, const std::string& b){ return a.size() < b.size(); });
// 结果：kiwi, pear, apple, banana

C 的 qsort 版本要：1) 比较函数用 void* 强转（类型不安全）；2) 函数指针不可内联（慢）；3) 对 char* 数组排序要小心指针语义。C++ 的 lambda 类型安全 + 可内联，且能直接捕获上下文变量，灵活得多。

10.2

定制操作与 Lambda 表达式

本节讲什么

当默认的 </== 不够用时，给算法传自定义谓词（比较/判断函数）。重点是 C++11 的 lambda 表达式——匿名函数，能捕获上下文变量。这是 C 程序员完全没用过的强大工具。

核心用法

谓词（predicate）

谓词是返回 bool 的可调用对象，分一元（一个参数）和二元（两个参数）：

bool isPositive(int x) { return x > 0; }   // 一元谓词
bool longer(const std::string& a, const std::string& b) { return a.size() < b.size(); }  // 二元

std::vector<int> v = {-1, 2, -3, 4};
auto it = std::find_if(v.begin(), v.end(), isPositive);  // 找第一个正数

std::vector<std::string> words = {"banana", "kiwi"};
std::sort(words.begin(), words.end(), longer);           // 按长度排

Lambda 表达式

capture -> return_type { body }

auto it = std::find_if(v.begin(), v.end(), [](int x){ return x > 3; });  // 找第一个 >3

// 捕获外部变量
int threshold = 5;
auto it2 = std::find_if(v.begin(), v.end(),
    [threshold](int x){ return x > threshold; });   // 捕获 threshold

捕获方式

捕获 含义
[] 不捕获
[=] 按值捕获所有用到的变量
[&] 按引用捕获所有用到的变量
[x] 按值捕获 x
[&x] 按引用捕获 x
[=, &x] 默认按值，但 x 按引用
[this] 捕获 this（成员函数中）

和 C 的区别

维度 C C++
回调函数 函数指针（无状态，不可内联） 函数指针 / 函数对象 / lambda
携带状态 ❌ 函数指针无法带状态（只能用全局变量） ✅ lambda 捕获
匿名函数 ❌ 无 ✅ lambda
内联 ❌ 函数指针不可内联 ✅ lambda/函数对象可内联
标准库绑定 ❌ std::bind（已少用，lambda 替代）

C 程序员最该体会的：

C 的回调只能用函数指针，无法携带状态——要传"阈值"这类上下文，只能用全局变量或额外参数（qsort 的比较函数连额外参数都没有，只能用全局）。

/* C：回调无法带状态，只能用全局变量 */
int threshold;   // 全局！线程不安全
int cmp(const void* a, const void* b) {
    return (*(int*)a > threshold) - (*(int*)b > threshold);
}
qsort(arr, n, sizeof(int), cmp);   // threshold 靠全局传递，丑陋且非线程安全

C++ 的 lambda 捕获让回调能带状态，且类型安全、可内联：

int threshold = 5;
std::sort(v.begin(), v.end(),
    [threshold](int a, int b){ return a > threshold && !(b > threshold); });
// threshold 捕获进 lambda，无需全局，线程安全，可内联

这是 C→C++ 在"回调表达力"上的飞跃——lambda 是现代 C++ 最重要的特性之一。

常见错误

  1. 按引用捕获局部变量后，局部变量销毁仍用 lambda：auto f = [&x]{ return x; }; 出了 x 的作用域后调 f，x 悬垂引用 UB。修正：长期持有的 lambda 按值捕获 [x] 或 [=]。
  2. [=] 捕获 this 误解：[=] 在成员函数中会按值捕获 this 指针（不是对象），lambda 内访问成员仍通过 this 指向原对象，对象销毁则悬垂。C++20 用 [=, this] 显式或 [this]。修正：要拷贝对象用 [*this]（C++17）。
  3. lambda 返回类型推导错误：[](int x){ if(x>0) return x; return -x; } —— 两个 return 类型一致才可推导，否则报错。复杂分支可显式 -> int。

自测题

1. 选择题：下面 lambda 捕获方式正确的是？（想在 lambda 内修改外部变量 int n） - A) [n]{ n = 5; } - B) [&n]{ n = 5; } - C) [=n]{ n = 5; } - D) []{ n = 5; }

答案

B。要修改外部变量，必须按引用捕获 [&n]。A 按值捕获 n，lambda 内的 n 是拷贝，改了不影响外部（且默认 lambda 的值捕获是 const，改拷贝也编译错误）；C 语法 =n 错误；D 不捕获，无法访问 n。注意：按值捕获的变量在 lambda 内默认是 const，要修改加 mutable：[n] mutable { n = 5; } 但仍只改拷贝。

2. 判断题：lambda 表达式可以捕获局部变量，且捕获的值在 lambda 创建时就固定（按值捕获时）。

答案

正确。按值捕获 [x] 在 lambda 创建时拷贝 x 的当前值，之后外部 x 改变不影响 lambda 内的副本。按引用捕获 [&x] 则是绑定，外部改了 lambda 内看到新值。这是值捕获与引用捕获的关键区别。

3. 踩坑题：下面代码想"延迟执行"，但 lambda 执行时 i 已经变了，为什么？

std::vector<std::function<int()>> tasks;
for (int i = 0; i < 3; ++i) {
    tasks.push_back([&i]{ return i; });    // 按引用捕获 i
}
for (auto& f : tasks) std::cout << f();    // 期望 0 1 2，实际 3 3 3
答案

[&i] 按引用捕获 i，所有 lambda 共享同一个 i 引用。循环结束时 i=3（循环出口），之后调用所有 lambda 都返回 3。修正：按值捕获 [i]，每次循环创建 lambda 时拷贝当时的 i：

tasks.push_back([i]{ return i; });   // 每个 lambda 有自己的 i 副本

这是异步/延迟执行场景按引用捕获的经典坑。

4. 应用题：用 std::remove_if + lambda 删除 vector<int> 中所有小于阈值 threshold 的元素，threshold 是函数参数。

答案 
void filter(std::vector<int>& v, int threshold) {
    v.erase(std::remove_if(v.begin(), v.end(),
            [threshold](int x){ return x < threshold; }),
            v.end());
}

lambda 捕获 threshold，remove_if 把不满足条件的搬前、满足的搬后，erase 删尾部。C 版 qsort/remove 要用全局 threshold（非线程安全）或 bsearch 风格额外参数（remove_if 没有这能力），C++ lambda 捕获优雅解决。这是 erase-remove + lambda 的经典组合。

10.3

再探迭代器

本节讲什么

除了普通迭代器，C++ 还有四类特殊迭代器：插入迭代器、流迭代器、反向迭代器、移动迭代器。它们让泛型算法能做更灵活的事——比如算法"不改容器大小"的限制，用插入迭代器就能突破。

核心用法

插入迭代器（inserter）

绑定到容器，赋值给它变成"插入"操作，从而让算法能扩展容器：

#include <iterator>
std::vector<int> v1 = {1,2,3};
std::vector<int> v2;

// back_inserter：赋值变成 push_back
std::copy(v1.begin(), v1.end(), std::back_inserter(v2));
// v2 现在是 {1,2,3}（copy 本身不改大小，但 back_inserter 把赋值转成 push_back）

std::fill_n(std::back_inserter(v2), 3, 0);   // 追加 3 个 0

流迭代器（stream_iterator）

把 IO 流当容器遍历：

// 从 cin 读所有整数
std::vector<int> v;
std::copy(std::istream_iterator<int>(std::cin), std::istream_iterator<int>(),
          std::back_inserter(v));    // 一行读完 cin 所有 int

// 写到 cout，空格分隔
std::copy(v.begin(), v.end(),
          std::ostream_iterator<int>(std::cout, " "));

反向迭代器（reverse_iterator）

std::vector<int> v = {1,2,3,4,5};
for (auto it = v.rbegin(); it != v.rend(); ++it)
    std::cout << *it;   // 54321（逆序）

移动迭代器（move_iterator，C++11）

std::vector<std::string> src = {"a","b","c"};
std::vector<std::string> dst;
dst.reserve(src.size());
std::move(src.begin(), src.end(), std::back_inserter(dst));  // 移动而非拷贝
// src 中的 string 现在是空壳

和 C 的区别

维度 C C++
迭代器抽象 ❌ 只有指针 通用迭代器 + 四种特殊迭代器
算法扩展容器 ❌（手写循环 + realloc） 插入迭代器
流当容器 ❌ 流迭代器
反向遍历 手写索引递减 reverse_iterator

C 程序员的理解：C 里"遍历"就是指针/索引，没有这层抽象。C++ 的迭代器是"泛型指针"，让算法能统一处理数组、链表、流等各种序列。插入迭代器更是巧妙——把"赋值"语义转成"插入"，让原本不改大小的算法能扩展容器。

/* C：要把一个数组拷到另一个动态数组，手写循环 */
for (size_t i = 0; i < n1; ++i) {
    if (n2 == cap2) { cap2*=2; arr2 = realloc(arr2, cap2*sizeof(int)); }
    arr2[n2++] = arr1[i];   // 手动管理扩容
}

// C++：copy + back_inserter，一行
std::copy(v1.begin(), v1.end(), std::back_inserter(v2));   // 自动 push_back

常见错误

  1. back_inserter 用于不支持 push_back 的容器：std::back_inserter(a) 对 std::array（无 push_back）编译错误。修正：array 固定大小，用普通迭代器或换 vector/deque/list。
  2. 流迭代器读 EOF 处理：istream_iterator<T>() 是结束哨兵，要和它比较判断结束，不能解引用。
  3. reverse_iterator 与普通迭代器混用：v.rbegin() 和 v.begin() 类型不同，不能直接比较/转换。要用 it.base() 把 reverse_iterator 转普通迭代器（注意 base() 指向的位置偏移一格）。

自测题

1. 选择题：std::back_inserter(v) 对 v 的要求是？ - A) v 必须是 vector - B) v 必须支持 push_back - C) v 必须有 reserve - D) v 必须是空容器

答案

B。back_inserter 调用 v.push_back(x) 实现，所以 v 必须支持 push_back（vector/deque/list/string 都行，array/forward_list 不行）。A 错（deque/list 也行）；C/D 无关。

2. 判断题：std::copy(v1.begin(), v1.end(), v2.begin()) 能安全地把 v1 拷到 v2，即使 v2 比较小。

答案

错误。普通迭代器 v2.begin() 是直接覆盖，如果 v2 空间不够就越界 UB。要安全拷贝到可扩展容器，用 std::back_inserter(v2)；或保证 v2 预先 resize 到足够大。这是用普通迭代器 vs 插入迭代器的关键区别。

3. 踩坑题：下面代码想从 cin 读整数到 vector，但 vector 总是空的，为什么？

std::vector<int> v;
std::copy(std::istream_iterator<int>(std::cin),
          std::istream_iterator<int>(),
          v.begin());    // 注意：用了 v.begin()
答案

v.begin() 是普通迭代器，v 是空的，往空 vector 的 begin 写越界 UB（看似没读到，可能崩溃或乱写）。修正：用 std::back_inserter(v)：

std::copy(std::istream_iterator<int>(std::cin),
          std::istream_iterator<int>(),
          std::back_inserter(v));   // 转成 push_back，安全扩展

4. 应用题：用流迭代器一行实现"从 cin 读所有单词，排序去重，输出到 cout 每行一个"。

答案 
#include <algorithm>
#include <iterator>
#include <string>
#include <vector>

std::vector<std::string> words{
    std::istream_iterator<std::string>(std::cin),
    std::istream_iterator<std::string>()};   // 从 cin 构造 vector
std::sort(words.begin(), words.end());
words.erase(std::unique(words.begin(), words.end()), words.end());
std::copy(words.begin(), words.end(),
          std::ostream_iterator<std::string>(std::cout, "\n"));

流迭代器让"读输入→处理→写输出"能用泛型算法串联，C 要手写 scanf 循环 + qsort + 手写去重 + printf 循环，繁琐得多。

10.4

特定容器算法

本节讲什么

list/forward_list 因为链式内存结构，用通用 <algorithm> 的算法（如 sort）性能差（不能随机访问迭代器）。所以它们提供专用成员函数算法，比通用版本快得多。这是"通用算法"的例外。

核心用法

list 专用算法

#include <list>
std::list<int> l1 = {3, 1, 4}, l2 = {1, 5};

l1.sort();                       // 链表专用排序（归并），O(n log n)
l1.unique();                     // 去重（相邻相同）
l1.merge(l2);                    // 合并两个已排序链表，l2 变空
l1.reverse();                    // 反转
l1.remove(3);                    // 删除所有等于 3 的元素
l1.remove_if([](int x){ return x < 0; });  // 按条件删

splice（链表特有）

std::list<int> a = {1,2,3}, b = {4,5};
a.splice(a.begin(), b);    // 把 b 整个接到 a 开头，b 变空（O(1)，搬指针）
// a: 4,5,1,2,3  b: 空

splice 是链表的杀手锏——O(1) 把一段元素从一个链表搬到另一个，只改指针不拷贝数据。通用 vector 做不到（要拷贝）。

为什么 list 要专用算法

算法 通用 <algorithm> list 成员函数
sort std::sort 要随机访问迭代器，list 不支持，编译错误 l.sort() 归并排序，O(n log n)
unique 拷贝搬移，慢 改指针，O(n)
merge 拷贝 搬指针，O(n)
remove 拷贝搬移 改指针

和 C 的区别

维度 C C++
链表 手写 struct + 指针 list + 专用算法
链表排序 手写归并（极繁琐） l.sort()
链表拼接 手动改指针（易错） splice 一行

C 程序员的体会：

C 里链表操作全靠手写指针操作，排序/合并/拼接都极易出错（指针改错就内存损坏）：

/* C：手写链表 splice，改指针，极易错 */
void splice(Node** dst, Node** src) {
    Node* tmp = *src;
    *src = tmp->next;
    tmp->next = *dst;
    *dst = tmp;
    // 要处理各种边界，head/tail/空链表...
}

C++ 的 list::splice 把这些封装好，O(1) 且安全：

a.splice(a.begin(), b);   // 一行，安全，O(1)

常见错误

  1. 对 list 用 std::sort：std::sort(l.begin(), l.end()) —— list 迭代器是双向的（非随机访问），std::sort 要求随机访问，编译错误。修正：用 l.sort()。
  2. list::sort 与 std::sort 性能比较想当然：list::sort 是归并排序，但因链表 cache 不友好，实际常比 vector 的 std::sort（内省排序+连续内存）慢。选型：除非频繁中间增删，否则优先 vector。
  3. merge/splice 后还用源链表：a.merge(b) 后 b 变空；a.splice(..., b) 后 b 的元素搬走了。再用 b 的元素是错的。

自测题

1. 选择题：下面哪个操作 std::list 不能用 std::sort（通用算法）而要用成员函数？ - A) 排序 - B) 查找 - C) 计数 - D) 反转

答案

A。std::sort 要求随机访问迭代器，list 只有双向迭代器，用 std::sort 编译错误，要用 l.sort()。查找/计数/反转通用算法（find/count/reverse）只要求输入/双向迭代器，能用在 list 上。

2. 判断题：std::list::splice 是 O(1) 操作，且不拷贝元素。

答案

正确。splice 只改指针，把节点从一个链表搬到另一个，不拷贝元素数据，O(1)（搬单个）或 O(k)（搬一段 k 个，但要遍历找范围）。这是链表相对 vector 的核心优势之一——vector 插入/删除中间元素要 O(n) 移动，链表 O(1) 改指针。

3. 踩坑题：下面代码报编译错误，为什么？

std::list<int> l = {3,1,4};
std::sort(l.begin(), l.end());
答案

std::sort 要求随机访问迭代器，但 std::list 的迭代器是双向迭代器（只能 ++/--，不能 +n/[]），不满足要求，编译错误。修正：用 list 的成员函数 l.sort()，它实现归并排序，适配双向迭代器。这体现了"不同容器用合适算法"的原则。

4. 应用题：用 list::splice 实现一个 LRU 缓存的"访问即提到头部"操作，说明为什么用 list 而非 vector。

答案 
#include <list>
#include <unordered_map>

class LRUCache {
    std::list<int> lru;    // 头部是最近用，尾部是最久未用
    std::unordered_map<int, std::list<int>::iterator> pos;  // key→位置
public:
    void access(int key) {
        auto it = pos.find(key);
        if (it != pos.end()) {
            lru.splice(lru.begin(), lru, it->second);  // O(1) 提到头部
        } else {
            lru.push_front(key);
            pos[key] = lru.begin();
        }
    }
    int evict() {
        int oldest = lru.back();
        lru.pop_back();
        pos.erase(oldest);
        return oldest;
    }
};

用 list 因为 splice 能 O(1) 把节点从中间提到头部（改指针），vector 做同样操作要 O(n) 移动元素。这是 list 的杀手级应用——LRU、调度队列等"频繁中间移动"场景。
