C C++

1.1

编写一个简单的 C++ 程序

第 1 章 开始 · 下一节：1.2 初识输入输出

本节讲什么

介绍 C++ 程序的基本结构。每个程序必须有一个 main 函数——操作系统通过调用它来运行程序。函数定义包含四部分：返回类型、函数名、形参列表、函数体。main 返回 0 表示执行成功。

最简单的 C++ 程序

int main() {
    return 0;  // 返回 0 表示程序正常结束
}

函数定义四要素：

部分 上例中的值 说明
返回类型 int main 必须返回 int，操作系统靠这个返回值判断程序是否成功
函数名 main 程序入口，必须叫 main（全小写）
形参列表 ()（空） 这里不带参数；1.1 节先用空列表，带参数的写法后面讲
函数体 { return 0; } 花括号包起来的语句块

程序要运行，还需经编译（源码 → 目标文件）和链接（目标文件 → 可执行文件）两步，1.5.2 会详讲。

和 C 的区别

维度 C C++ 说明
main 返回类型 int int 一样，都必须是 int
不写 return 返回值未定义（UB） main 特例：默认返回 0 C++ 只有 main 有这个豁免，其他函数不写 return 行为未定义
return 0 含义 成功 成功 一样，非 0 通常表示错误
头文件 #include <stdio.h> #include <iostream> C++ 标准库头文件不带 .h（下节讲）

一句话： C 程序员看 C++ 的 main 基本无障碍，唯一的"小惊喜"是 C++ 里 main 不写 return 也合法且默认返回 0——但别依赖这个，养成写 return 0; 的习惯更安全（也方便和 C 互移植）。

常见错误（新手踩坑）

错误 1：main 拼错或大小写不对

int Main() { return 0; }   // ❌ 编译能过，但链接报错：找不到 main
int main() { return 0; }   // ✅

为什么： 链接器找的是小写 main，Main 不会被当成入口。

错误 2：返回类型写成 void

void main() { }   // ❌ C++ 标准不允许（某些编译器放行，但不可移植）
int main() { }    // ✅

为什么： C++ 标准规定 main 必须返回 int。有些老编译器（MSVC）容忍 void main，但换编译器就崩，别养成坏习惯。

错误 3：忘 #include 就用库

main() { std::cout << "hi"; }  // ❌ 没包含 <iostream>

这节还没讲输入输出（1.2 才讲），先记住：用任何标准库设施都要先 #include 对应头文件。

自测题

  2. main 函数不写 return 语句，程序行为是什么？这和 C 有什么不同？
  3. 下面哪个能作为合法的 C++ 程序入口？为什么？
(a) int main() { return 0; }
(b) void main() { }
(c) int Main() { return 0; }

1.2

初识输入输出

本节讲什么

C++ 通过标准库中的 iostream 提供 IO 机制，其中包含表示输入流的 istream 和表示输出流的 ostream 基础类型。讲解如何使用 std::cin 与输入运算符 >> 读取数据，使用 std::cout 与输出运算符 << 打印消息，使用 std::cerr 输出错误信息，以及使用操纵符 std::endl 结束当前行并刷新缓冲区。

要点

  • 标准库头文件 <iostream> 提供 IO 支持；istream / ostream 是输入流与输出流的基础类型
  • 管道比喻：cin/cout 是连接键盘、屏幕和程序的管道；箭头方向 = 数据流入/流出的方向
  • std::cin >> v：>> 指向变量，数据从键盘管道流进 v
  • std::cout << x：<< 指向 cout，数据从程序流出到屏幕管道
  • std::cerr << err：错误信息流出到屏幕，通常不缓冲，立刻显示
  • 变量是装数据的盒子：int v1 = 0, v2 = 0; 先声明两个能装整数的盒子；std::cin >> v1 >> v2; 让你依次敲两个数，第一个流进 v1，第二个流进 v2
  • cin >> 遇空白就停（空格 / Tab / 回车都算），不是「不按回车就一直读」；读带空格的整行用 getline（见 3.2.2 读写操作）
  • 输出顺序：从左到右，离 cout 最近的先输出
  • std::cout << v1 << " + " << v2; 从左往右读：先输出 v1，再输出 " + "，最后输出 v2
  • 若 v1=12、v2=34，屏幕显示 12 + 34
  • 把 << 看成「递给 cout」：cout 左边紧挨着的那个最先被递出去
  • std::endl：输出换行并刷新缓冲区

通俗理解：管道与数据流

可以把标准输入输出想成连接程序和外部的管道——iostream 库负责把键盘、屏幕等默认设备和你的程序连起来。

键盘 ──管道──► 程序          std::cin  +  >>
程序 ──管道──► 屏幕          std::cout +  <<
程序 ──管道──► 屏幕（错误）   std::cerr +  <<

箭头方向就是数据流的方向：

写法 数据往哪流 含义
std::cin >> v 键盘 → 变量 v 从输入通道读进程序
std::cout << x 程序 → 屏幕 从程序写出到屏幕
std::cerr << err 程序 → 屏幕 写出错误信息（通常不缓冲，立刻显示）
  • std::cin：输入管道，键盘敲的内容沿 >> 流进变量
  • std::cout：输出管道，程序里的内容沿 << 流到屏幕
  • std::cerr：错误输出管道，专门打错误/警告；不像 cout 那样先攒在缓冲区里，而是尽快显示，方便快速定位问题

连写多个 >> 或 << 时，一律从左到右依次处理：

std::cin >> v1 >> v2;
// ① 先读进 v1  ② 再读进 v2

std::cout << v1 << " + " << v2;
// ① 先输出 v1  ② 再输出 " + "  ③ 最后输出 v2
//    ▲ 紧挨 cout 的第一个，最先出现在屏幕上

输出顺序记忆法：cout 是要接东西的人，<< 是递东西的手——从左边开始递，离 cout 最近的那个最先输出，不是离得最远的先输出。

输入 vs 输出的顺序比喻：

比喻 含义
输出 cout << v1 << v2 先进先出（管道/队列） 先「放进」管道的 v1 先从另一端流到屏幕，再是 v2
输入 cin >> v1 >> v2 按顺序填格子 像铺地砖：先敲的第一个数填进 v1，第二个数填进 v2，严格按代码先后顺序

三条 IO 线：cin / cout / cerr

iostream 默认给程序连了三条线：

        ┌── cin  ──► 程序（键盘 → 程序）
键盘 ───┤
        └── （标准输入）

        ┌── cout ──► 屏幕（程序 → 屏幕，正常输出，有缓冲）
程序 ───┤
        └── cerr ──► 屏幕（程序 → 屏幕，错误输出，通常立刻显示）
线 方向 用途 缓冲
std::cin 键盘 → 程序 读入用户输入 —
std::cout 程序 → 屏幕 正常提示、结果打印 有缓冲区，可能攒一批再显示
std::cerr 程序 → 屏幕 错误、警告 无缓冲（或立即刷新），马上显示

举例（委托单）：

#include <iostream>

int main() {
    double price = 0;
    int qty = 0;

    std::cout << "请输入委托价格和数量: ";
    std::cin >> price >> qty;                    // cin：读入价格和数量

    if (price < 0) {
        std::cerr << "错误：委托价格不能为负\n";  // cerr：立刻报错，不缓冲
        return 1;
    }

    std::cout << "委托已提交：价格=" << price     // cout：正常业务提示
              << " 数量=" << qty << std::endl;
    return 0;
}
  • cin：读客户敲进来的价格和数量
  • cout：打印「委托已提交」等正常信息
  • cerr：价格非法时立刻打出错误，方便第一时间发现问题（生产环境常用专门日志库替代，但原理类似）

示例

#include <iostream>
int main() {
    std::cout << "Enter two numbers: ";

    int v1 = 0, v2 = 0;   // 两个「盒子」，用来装从键盘流进来的整数
    std::cin >> v1 >> v2; // 依次输入：第一个数 → v1，第二个数 → v2

    std::cout << v1 << " + " << v2 << " = " << v1 + v2 << std::endl;
    // 输出顺序（从左到右）：v1 → " + " → v2 → " = " → (v1+v2) → 换行
    // 例如 v1=12, v2=34 时屏幕显示：12 + 34 = 46
    return 0;
}

和 C 的区别

C 程序员第一反应：这不就是 scanf/printf 吗？是的，但 C++ 的流 IO 解决了 C 的几个老毛病：

对比点 C（stdio.h） C++（iostream） 为什么
类型安全 printf("%d", x) 写错 % 就崩 cout << x 自动按 x 的类型输出 编译期检查，不用记格式串
读入 scanf("%d", &v) 忘 & 就崩 cin >> v 不需要取地址 运算符重载替你取地址
换行刷新 printf("\n"); fflush(stdout); cout << endl;（一步到位） endl = 换行 + 刷新
错误流 fprintf(stderr, ...) cerr << ... 语法统一，且默认无缓冲
扩展性 自定义类型没法 printf 重载 << 就能 cout << obj 这才是 C++ 的核心优势

一句话总结： C 的 IO 靠"格式串 + 记类型"，C++ 靠"运算符重载自动识别类型"——写错概率大幅降低。

性能权衡（HFT 视角）： cin/cout 默认比 scanf/printf 慢，因为要同步 C 标准库。关同步：std::ios::sync_with_stdio(false); 后能接近 scanf 速度。但 HFT 热路径根本不用标准 IO，用自研二进制日志/网络库。

常见错误

1. 忘了 #include <iostream>

// int main() { std::cout << "hi"; }  // 编译报错：cout 未声明

报错信息常说 cout is not declared——第一个反应就检查头文件。

2. >> 和 << 写反

std::cin << v;   // 错：cin 是输入，应该用 >>（数据流进变量）
std::cout >> x;  // 错：cout 是输出，应该用 <<（数据流出程序）

记忆：箭头指向数据要去的地方。cin >> v 指向 v（进变量），cout << x 指向 cout（出屏幕）。

3. cin >> 读不到空格

std::string name;
std::cin >> name;        // 输入 "Zhang San"，name 只拿到 "Zhang"
std::getline(std::cin, name);  // 要读整行用 getline（见 3.2.2）

自测题

1（选择） 下面哪个写法能正确读入两个整数到 a、b？ - A. std::cin << a << b; - B. std::cin >> a >> b; - C. std::cin >> a, b; - D. std::cout >> a >> b;

2（判断） std::cerr 和 std::cout 都是输出到屏幕，所以它们完全等价。

3（踩坑） 下面代码输入 3.14 42 后输出什么？

int x; double y;
std::cin >> x >> y;
std::cout << x << " " << y;

4（概念） 为什么说 cin >> v 比 scanf("%d", &v) 更安全？两点以上。

参考答案
  1. B。>> 是输入运算符，连写从左到右依次读入。
  2. 错。cerr 默认无缓冲（立即输出），cout 有缓冲；用途不同（错误 vs 正常输出）。
  3. x 读 3，遇到 . 停（int 读不了小数点）；y 从 .14 开始读成 0.14？实际 y=0.14，输出 3 0.14。这是典型的"类型与输入不匹配"陷阱。
  4. ① 不需要手动写格式串，不会写错 %d/%f；② 不需要取地址 &v，避免忘写 & 导致崩溃；③ 编译器按 v 的类型自动选择读入方式，类型不匹配在编译期就能发现。

1.3

注释简介

第 1 章 · 上一节：1.2 初识输入输出 · 下一节：1.4 控制流

本节讲什么

C++ 的两种注释写法：单行 // 和多行 /* */。重点是一个坑——/* */ 不能嵌套，这是 C/C++ 共有的经典陷阱。

核心用法

写法 作用 适用场景
// 注释 从 // 到行尾 单行说明、临时禁用一行代码
/* 注释 */ 跨多行 模块/函数头说明、大段注释 
// 读取委托价格和数量           ← 单行注释
int qty = 0;

/*
 * 委托处理模块                  ← 多行注释
 * 负责校验、下单、回报
 */

编译器完全忽略注释——注释里的代码不会执行，纯粹是给人看的。

和 C 的区别

几乎没有区别。 这是 C 和 C++ 高度一致的地方：

对比点 C（C89） C（C99 起） C++
/* */ ✅ ✅ ✅
// ❌ 没有 ✅ 加入 ✅ 一直有
嵌套 /* */ ❌ 禁止 ❌ 禁止 ❌ 禁止

给 C 程序员的提醒： 如果你以前写 C89，// 在老 C 里不合法；但 C++ 一直支持，放心用。现代 C 项目（C99+）也都支持 // 了。

常见错误

1. /* */ 嵌套陷阱（最经典）

/*
 * 外层注释开始
 * /* 内层注释开始 */    ← 这里第一个 */ 就把外层注释关掉了！
 * 外层注释还没结束
 */                        ← 这个 */ 成了"悬空"的，编译报错

规则：第一个 */ 就关闭整个注释，不管你开了几个 /*。想临时注释掉一大段含 /* */ 的代码，用 #if 0 ... #endif（预处理指令，不受注释规则限制）：

#if 0
/* 这里的注释不会被误关闭 */
void old_code() { ... }
#endif

2. // 注释不能跨行

// 这是第一行
    这是第二行    ← 这行不是注释，编译报错

// 只管到行尾。要跨行用 // 得每行都写，或用 /* */。

3. 注释写在字符串里失效

std::cout << "价格 // 不是注释";  // 这里的 // 才是注释

字符串字面量里的 //、/* 都是普通字符，注释规则不生效。

自测题

1（选择） 下面代码能否正确编译？

/* 外层
   /* 内层 */
   外层继续
*/
  • A. 能，嵌套注释合法
  • B. 不能，第一个 */ 就关闭了外层注释，后面的 */ 悬空

2（判断） C++ 中 // 注释可以从一行延续到下一行。

3（应用） 你想临时禁用下面这段代码，哪种写法安全？

/* config A */
int x = 1;
/* config B */
int y = 2;
参考答案
  1. B。/* */ 不能嵌套，第一个 */（在"内层"后）就关掉了外层，最后的 */ 变成多余符号导致编译错误。
  2. 错。// 只到行尾，换行后失效。要跨行每行写 //，或用 /* */。
  3. 用 #if 0 ... #endif 包住整段最安全，因为里面的 /* */ 不会触发嵌套陷阱： cpp #if 0 /* config A */ int x = 1; /* config B */ int y = 2; #endif

1.4

控制流

本节讲什么

介绍允许程序跳出顺序执行、实现更复杂执行路径的语句。详细讲解 while 循环（反复检测条件并执行循环体直至条件为假）、for 循环（将初始化、循环条件和变量修改集中在循环头以简化代码）以及支持条件执行的 if 语句。还演示了如何使用 while (std::cin >> value) 不断读取数量不定的输入，直至遇到文件末尾（EOF）。

要点

  • while：先判断条件，为真则重复执行循环体
  • for：循环头包含初始化、条件、迭代语句，适合计数循环
  • if / else：按条件选择执行路径
  • while (std::cin >> value)：循环读取输入，直至 EOF 或输入失败
  • Windows 下 EOF 常用 Ctrl+Z 后回车；Unix 下为 Ctrl+D
  • 条件表达式的规则（与 Rust 不同）：
  • if / while / for 的条件最终要当成布尔值来用
  • C++ 允许隐式转换：0 → 假，非 0 → 真
  • 所以 while (1) 合法，表示一直循环（1 永远为真）
  • Rust 则严格要求 bool，不能写 while 1
  • 现代 C++ 写死循环更推荐 while (true) 或 for (;;)，意图更清晰

和 C 的区别

几乎没有区别。 while/for/if 语法 C 和 C++ 完全一致。细微差异：

对比点 C C++ 说明
while (1) 死循环 ✅ ✅ 非 0 即真，C/C++ 都合法
for (int i=0; ...) 在循环外用 i ✅（C99 起） ❌ i 作用域只在 for 内 C++ 更严格，循环变量不泄漏
条件必须是 bool ❌（整数即可） ❌（整数即可） C/C++ 都宽松，非 0 即真

关键差异：for 变量的作用域。 这是 C→C++ 最容易踩的点：

/* C 代码 */
for (int i = 0; i < 3; i++) {}
printf("%d", i);   /* C99: 合法，i 在循环外仍可见 */

// C++ 代码
for (int i = 0; i < 3; i++) {}
std::cout << i;    // 编译错误：i 不在作用域内

C++ 把 for 里声明的变量锁在循环体内，更安全（不会污染外层）。要从 C 转 C++，习惯把"循环后还要用 i"的变量提到循环外声明。

记忆： C 和 C++ 的控制流几乎一样，但 C++ 的 for 变量更"干净"——用完即丢，不泄漏到外面。

通俗理解

  • while (1) = 死循环：1 永远是非 0，一直被当成「真」
  • HFT 行情监听：常用 while (1) 或 while (true) 做主循环，一直盯盘，满足条件时 break 退出
  • if / for 同样适用：只有 0 是假，其他整数都算真
while (1) {
    // poll_market();   // 拉行情
    // if (should_stop) break;  // 主动退出
}

示例

#include <iostream>
int main() {
    // while：累加 1 到 10
    int sum = 0, val = 1;
    while (val <= 10) {
        sum += val;
        ++val;
    }
    std::cout << "Sum 1..10 = " << sum << std::endl;

    // for：同样效果
    sum = 0;
    for (int i = 1; i <= 10; ++i)
        sum += i;
    std::cout << "Sum 1..10 = " << sum << std::endl;

    // if：按分数输出等级
    int score = 85;
    if (score >= 90)
        std::cout << "A" << std::endl;
    else if (score >= 60)
        std::cout << "Pass" << std::endl;
    else
        std::cout << "Fail" << std::endl;

    // while(1) 死循环（C++ 允许，1 当 true）
    // while (true) { /* 轮询行情 */ break; }  // 更推荐的写法

    return 0;
}

常见错误

1. while (std::cin >> value) 的结束条件搞混

int sum = 0, value = 0;
while (std::cin >> value)  // 什么时候停？
    sum += value;

结束条件：遇到 EOF（Windows Ctrl+Z 回车，Linux Ctrl+D），或输入类型不匹配（要 int 却输入字母）。cin >> value 的返回值是流本身，能转成 bool——读成功为真，失败为假。

2. for 变量在循环外误用（C 程序员的坑）

for (int i = 0; i < 10; ++i) { /* ... */ }
std::cout << i;  // 编译错误！C++ 里 i 已经销毁

C 里 i 循环外可见，C++ 不可见。要循环后用，提前声明：

int i;
for (i = 0; i < 10; ++i) { /* ... */ }
std::cout << i;  // OK

3. if 悬空 else（经典陷阱）

if (a > 0)
    if (b > 0)
        std::cout << "A";
else
    std::cout << "B";  // 这个 else 配的是内层 if，不是外层！

else 总是配最近的未配对 if。要配外层，用花括号：

if (a > 0) {
    if (b > 0) std::cout << "A";
} else {
    std::cout << "B";  // 现在配外层
}

自测题

1（选择） 下面 C++ 代码能否编译？

for (int i = 0; i < 3; ++i) {}
std::cout << i;
  • A. 能，输出 3
  • B. 不能，i 不在作用域

2（踩坑） 下面代码输入 1 2 3 x 后 sum 是多少？

int sum = 0, v = 0;
while (std::cin >> v) sum += v;

3（判断） C++ 中 while (1) 和 while (true) 完全等价。

4（应用） 把下面 C 习惯的代码改成 C++ 安全写法：

int i;
for (i = 0; i < n; ++i) { ... }
// 后面要用 i 的最终值
参考答案
  1. B。C++ 的 for 变量作用域只在循环体内，循环外不可见。这是和 C（C99）的关键差异。
  2. sum = 6。读到 x 时 cin >> v（v 是 int）失败，循环结束。1+2+3=6。
  3. 语义等价（都是死循环），但 while (true) 意图更清晰，现代 C++ 推荐这种写法。while(1) 也合法。
  4. 这段代码在 C++ 里其实没问题（i 在循环外声明），只是不够现代。如果循环后不需要 i，应该写 for (int i = 0; ...) 让变量用完即丢；确实需要就用上面的写法（提前声明）。

1.6

书店程序

第 1 章 · 上一节：1.5 类简介 · 下一节：1.7 小结与术语表

本节讲什么

全章实战总结：把变量、输入输出、控制流、Sales_item 类串起来，写一个完整程序——读多条书籍销售记录，按书号分组汇总，输出每本书的总销售额、售出册数、平均售价。

核心逻辑

程序的结构是"分组累加"模式，HFT 里也常见（按合约分组统计成交量）：

  1. 读第一条记录作为"当前组"
  2. 循环读后续记录： - 书号相同 → 累加到当前组 - 书号不同 → 输出当前组汇总，开启新组
  3. 循环结束 → 输出最后一组

示例

#include <iostream>
#include "Sales_item.h"

int main() {
    Sales_item total;
    if (std::cin >> total) {               // 读入第一条记录
        Sales_item trans;
        while (std::cin >> trans) {        // 读入剩余记录
            if (total.isbn() == trans.isbn())
                total += trans;            // 同一本书，累加
            else {
                std::cout << total << std::endl;  // 不同书，输出上一本汇总
                total = trans;             // total 重置为新书
            }
        }
        std::cout << total << std::endl;   // 输出最后一本
    }
    return 0;
}

和 C 的区别

同样的"分组累加"逻辑，C 和 C++ 的写法对比：

对比点 C 写法 C++ 写法
读记录 scanf("%s %d %lf", isbn, &sold, &price) cin >> total（一行搞定）
比较 strcmp(isbn1, isbn2) == 0 total.isbn() == trans.isbn()
累加 手动加每个字段 total += trans（运算符重载）
输出 printf("%s %d %.2f\n", ...) cout << total 
/* C 版本骨架 */
struct Record { char isbn[16]; int sold; double revenue; };
struct Record total, trans;
scanf("%s %d %lf", total.isbn, &total.sold, &total.revenue);
while (scanf("%s %d %lf", trans.isbn, &trans.sold, &trans.revenue) == 3) {
    if (strcmp(total.isbn, trans.isbn) == 0) {
        total.sold += trans.sold;
        total.revenue += trans.revenue;
    } else {
        printf("%s %d %.2f\n", total.isbn, total.sold, total.revenue);
        total = trans;
    }
}

关键差异： C++ 把"怎么读、怎么加、怎么比"藏进了类的方法和运算符重载里，主程序逻辑干净得多。C 要手动操作每个字段，容易写错（忘加某个字段、格式串写错）。

常见错误

1. 忘了处理"没有输入"的情况

Sales_item total;
std::cin >> total;        // 如果没输入，下面 total 是未定义状态
while (std::cin >> trans) { ... }  // 直接进循环，行为未定义

原书代码用 if (std::cin >> total) 先判断第一条是否读成功，这是正确的防御性写法。

2. 换组时忘了重置 total

if (total.isbn() == trans.isbn())
    total += trans;
else {
    std::cout << total << std::endl;
    // 忘了 total = trans; → 下一组还是累加在旧 total 上
}

3. 输入没按书号排序 程序假设输入是按书号排好序的（同一本书的记录连续）。如果输入乱序，0-201 0-201 0-999 0-201 里的最后一个 0-201 会被当成新书，无法合并到前面的组。要处理乱序需要更复杂的数据结构（map），第 10 章会讲。

自测题

1（选择） 程序假设输入按什么排序？ - A. 按销量 - B. 按书号 - C. 不需要排序

2（踩坑） 如果输入为空（直接 EOF），原书代码会怎样？

3（应用） 把这个"分组累加"模式套到 HFT：按合约分组统计总成交量，伪代码怎么写？

参考答案
  1. B。按书号排序，同一本书的记录连续出现，程序才能正确分组。乱序会漏合并。
  2. if (std::cin >> total) 为假，跳过整个块，直接 return 0，什么都不输出。这是正确的防御性处理。
  3. 框架：读第一笔成当前组的"基准合约"；后续每笔若合约号相同则累加成交量，不同则输出当前组合计、开启新合约。和书店程序结构一模一样，只是 isbn 换成合约号、+= 换成成交量累加。

小结与术语表

术语表（带 C 对照）

术语 含义 C 程序员视角
内置类型 语言自带的 int/double/char 和 C 一样
命名空间 std::cin 避免名字冲突 C 没有命名空间，靠命名约定
实参 / 形参 调用时传的值 / 定义里的参数 和 C 一样
缓冲区 IO 流读写用的内存区，endl 刷新 C 的 fflush(stdout) 类似
类 数据 + 函数 + 访问控制 C 的 struct 只有数据
头文件 <iostream>、"Sales_item.h" 和 C 一样，但 C++ 有 class

第 1 章给 C 程序员的 5 个要点

  1. cin/cout 替代 scanf/printf —— 类型安全，不用记格式串，不会忘 &
  2. // 注释放心用 —— C89 没有，C99 起和 C++ 都支持
  3. for 变量作用域收紧 —— C++ 里 for(int i...) 的 i 出循环就没了，C 会泄漏到外层
  4. class 比 struct 多了方法和访问控制 —— 数据和行为绑定，这是 C→C++ 的核心转变
  5. while(cin>>x) 替代 scanf 返回值检查 —— 流的状态自带 bool 转换
