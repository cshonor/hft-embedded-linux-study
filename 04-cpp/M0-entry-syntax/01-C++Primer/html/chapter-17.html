17.1

tuple 元组

本节讲什么

本节讲解 std::tuple——一个固定大小、可存放不同类型元素的容器模板。它是 std::pair 的泛化版（pair 只能 2 个，tuple 任意个），常用于"函数一次返回多个不同类型结果"、"异构数据打包"等场景。

一句话定位：tuple = "能装不同类型元素的 struct，但不用先定义 struct"。

核心用法

1. 创建与访问

#include <tuple>
#include <string>
// 构造
std::tuple<std::string, int, double> t1{"book", 10, 9.9};
auto t2 = std::make_tuple("pen", 5, 1.5);    // 推导类型

// 访问：get<索引>
std::cout << std::get<0>(t1);    // "book"（string）
std::cout << std::get<1>(t1);    // 10（int）
// std::get<3>(t1);              // ❌ 编译错误：越界（只有 3 个元素）

// 按类型访问（要求该类型在 tuple 中唯一）
std::cout << std::get<std::string>(t1);   // "book"

2. 元素个数与类型查询

auto t = std::make_tuple(1, 2.0, "hi");
std::cout << std::tuple_size<decltype(t)>::value;   // 3
// 获取第 i 个元素的类型：
std::tuple_element<0, decltype(t)>::type;   // int

3. 解包：tie 与结构化绑定

std::tuple<std::string, int> get_person() { return {"Alice", 30}; }

// C++11：tie 解包
std::string name; int age;
std::tie(name, age) = get_person();

// C++17：结构化绑定（更优雅）
auto [name, age] = get_person();

4. tuple 的常见场景

  • 函数返回多值：return std::make_tuple(result, status, error_msg);
  • 异构数据临时打包：把不同类型数据一起传递，避免定义专用 struct
  • 模板元编程：作为"类型列表"载体

和 C 的区别

C 没有 tuple，要返回多个不同类型值只能定义 struct 或用 void*：

维度 C（struct） C++ tuple
定义成本 每处都定义 struct 即用即写，无需预定义
访问 s.name（有名字） get<i>（按位置）或结构化绑定
通用性 每种组合一个 struct 类型 模板，任意类型组合
解包 逐字段赋值 tie / 结构化绑定一行搞定 
// C：必须先定义 struct
struct Person { char name[32]; int age; };
struct Person get_person() { struct Person p = {"Alice", 30}; return p; }
// 用：struct Person p = get_person(); printf("%s %d", p.name, p.age);

// C++：tuple 即用即写
std::tuple<std::string, int> get_person() { return {"Alice", 30}; }
auto [name, age] = get_person();   // C++17 一行解包

取舍：若某个多值组合反复出现，定义 struct 更清晰（有字段名、可加方法）；若只是临时返回一次，tuple 更轻便。

常见错误

错误 1：get 索引越界或类型不匹配

std::tuple<int, double> t{1, 2.0};
std::get<2>(t);                  // ❌ 编译错误：只有 2 个元素
std::get<std::string>(t);        // ❌ 编译错误：没有 string 类型
std::get<int>(t);                // ❌ 若有多个 int 会二义；这里只有 1 个 int，OK

get 越界和类型不匹配都是编译期错误——这是 tuple 相对 void* 的安全优势。

错误 2：按类型访问时类型不唯一

auto t = std::make_tuple(1, 2);    // 两个 int
std::get<int>(t);                  // ❌ 编译错误：int 不唯一
std::get<0>(t);                    // ✅ 用索引

按类型访问要求该类型在 tuple 中唯一。

错误 3：忘记 tie 的左值语义

std::tuple<int,int> f() { return {1, 2}; }
int a, b;
std::tie(a, b) = f();    // ✅ tie 返回引用 tuple，赋值写入 a, b
// 对比：auto t = f();   // 这是拷贝到 t，不写入 a, b

自测题

1. 选择题：std::tuple<int, double, std::string> t{1, 2.0, "hi"}; 以下哪个访问合法？

A. std::get<3>(t) B. std::get<double>(t) C. std::get<int>(t) D. t[0]

答案

B。A 越界（只有 3 个元素，索引 0-2）；C 的 int 虽然唯一合法，但选项 B 也合法且更典型；D 错误——tuple 不支持 [] 运算符，只能用 get。get<double> 因 double 唯一而合法。若问"哪个非法"，答案是 A 和 D。

2. 判断题：std::tuple 的大小（元素个数）在编译期确定，不能运行期改变。

答案

对。tuple 是固定大小的模板，元素个数和类型在编译期已确定。若需运行期可变长度的异构容器，考虑 std::vector<std::variant<...>> 或 std::any。

3. 踩坑题：以下代码有什么问题？

std::tuple<int, int> get_coords() { return {3, 4}; }
int main() {
    int x, y;
    auto t = get_coords();
    std::tie(x, y);
    std::cout << x << " " << y;
}
答案

std::tie(x, y) 只是构造了一个引用 tuple，没有赋值——x/y 仍为未初始化。正确写法是 std::tie(x, y) = get_coords();（tie 在等号左边）。或用 C++17 结构化绑定：auto [x, y] = get_coords();。

4. 应用题：写一个函数 divide(int a, int b) 返回 (商, 余数, 是否成功)，成功时 true，除零时 false。用 tuple 返回，调用方用结构化绑定接收。

答案 
#include <tuple>
std::tuple<int, int, bool> divide(int a, int b) {
    if (b == 0) return {0, 0, false};
    return {a / b, a % b, true};
}
int main() {
    auto [q, r, ok] = divide(17, 5);    // C++17 结构化绑定
    if (ok) std::cout << q << " " << r;  // 3 2
    auto [q2, r2, ok2] = divide(10, 0);
    if (!ok2) std::cout << "div by zero";
}

要点：tuple 打包多返回值、结构化绑定一行解包、ok 标志处理错误（也可用 std::optional<tuple>）。

17.2

bitset 位集

本节讲什么

本节讲解 std::bitset——一个编译期固定大小的二进制位容器，专门做位运算（与、或、异或、置位、清位、翻转、计数）。它比手写 unsigned int + 位操作更安全（有边界检查接口）、更易读（bs.set(3) vs flags |= (1<<3)）、且支持任意位数（不限于 64）。

一句话定位：bitset = "类型安全的位标志数组"，权限掩码、状态标记的高效工具。

核心用法

1. 构造

#include <bitset>
std::bitset<8> b1;                    // 全 0：00000000
std::bitset<8> b2(0xFF);              // 从整数：11111111
std::bitset<8> b3("10101010");        // 从字符串：10101010
std::bitset<16> b4(0xABCD);           // 1010101111001101

bitset<N> 的 N 是编译期常量（模板非类型参数），不同 N 是不同类型。

2. 位操作

std::bitset<8> b("10101010");
b.set(0);          // 置位第 0 位：10101011
b.reset(0);        // 清位第 0 位：10101010
b.flip(0);         // 翻转第 0 位：10101011
b.flip();          // 全部翻转：01010100
b[0];              // 访问第 0 位（返回代理引用，可读可写）
b.test(0);         // 测试第 0 位（返回 bool，有边界检查）
b.any();           // 是否有任意 1
b.none();          // 是否全 0
b.count();         // 1 的个数
b.size();          // 总位数（编译期已知）
b.all();           // 是否全 1

3. 位运算

bitset 重载了 &/|/^/~/<</>>，像整数一样运算：

std::bitset<8> a("11001010");
std::bitset<8> b("10110101");
auto c = a & b;    // 按位与：10000000
auto d = a | b;    // 按位或：11111111
auto e = a ^ b;    // 按位异或：01111111
auto f = ~a;       // 按位取反：00110101
auto g = a << 2;   // 左移 2 位

4. 转换

std::bitset<8> b("10101010");
b.to_string();     // "10101010"
b.to_ulong();      // 170（unsigned long）
b.to_ullong();     // 170（unsigned long long，C++11）

5. 典型场景

// 权限掩码
std::bitset<4> permissions("1010");   // 读=1, 写=0, 执行=1, 删除=0
if (permissions.test(0)) { /* 可删除 */ }

// 状态标记集合
std::bitset<32> flags;
flags.set(3);    // 标记第 3 号事件发生
if (flags.any()) { /* 有事件 */ }

// 布尔数组（比 vector<bool> 或 bool[] 省内存 8 倍）
std::bitset<1000> present;   // 1000 个布尔，只用 125 字节

和 C 的区别

C 用 unsigned int + 位操作，手写掩码：

维度 C（unsigned int + 宏） C++ bitset
位数 限于 32/64 任意编译期常量
边界检查 无（越界 UB） test() 有检查
可读性 flags |= (1<<3) flags.set(3)
运算 手写 &/\| 重载运算符
字符串/整数转换 手写 to_string/to_ulong 
// C：手写位操作
unsigned int flags = 0;
flags |= (1u << 3);          // 置位 3
flags &= ~(1u << 3);         // 清位 3
if (flags & (1u << 3)) { }   // 测试位 3
int count = __builtin_popcount(flags);  // 数 1（GCC 扩展，非标准）
// 超过 32 位要手动拼接多个 int

// C++：bitset
std::bitset<64> flags;
flags.set(3);
flags.reset(3);
if (flags.test(3)) { }
int count = flags.count();   // 标准、可移植

HFT 视角：bitset 的位操作编译后通常是一条 CPU 指令（AND/OR/POPCNT），零额外开销。权限检查、状态标记用 bitset 比手写掩码更清晰，且性能不损。

常见错误

错误 1：大小不是编译期常量

int n = 64;
std::bitset<n> b;     // ❌ n 不是编译期常量
constexpr int N = 64;
std::bitset<N> b2;    // ✅

bitset 的 N 是模板非类型参数，必须编译期常量。运行期可变大小用 std::vector<bool>（虽有争议，但能动态扩容）。

错误 2：[] 越界无检查

std::bitset<8> b;
b[10] = 1;    // ❌ 越界，未定义行为（[] 不检查边界）
b.test(10);   // 抛 std::out_of_range 异常（test 有检查）

operator[] 不检查边界（性能优先），test() 检查。调试期用 test()，确认无误后可用 []。

错误 3：to_ulong 溢出

std::bitset<64> b("1111111111111111111111111111111111111111111111111111111111111111");
b.to_ulong();    // ❌ 若值超 unsigned long 范围，抛 overflow_error
b.to_ullong();   // C++11，用 unsigned long long，范围更大但仍可能溢出

bitset 大小可以超过 unsigned long 位数，此时 to_ulong 会溢出抛异常。检查 size() <= sizeof(unsigned long)*8 再转换。

自测题

1. 选择题：std::bitset<8> b("10101010"); b.count() 返回什么？

A. 8（总位数） B. 4（1 的个数） C. 170（整数值） D. 0

答案

B。count() 返回 1 的个数，"10101010" 有 4 个 1。size() 返回总位数 8，to_ulong() 返回整数值 170。

2. 判断题：std::bitset<N> 的 N 可以是运行期变量。

答案

错。N 是模板非类型参数，必须是编译期常量（字面量、constexpr、枚举）。运行期可变大小需用 std::vector<bool> 或自己管理动态位数组。

3. 踩坑题：以下代码有什么问题？

std::bitset<8> b;
for (int i = 0; i <= 8; ++i) b[i] = 1;
答案

i <= 8 越界——bitset<8> 的合法索引是 0-7。b[8] 是未定义行为（operator[] 不检查边界）。应改为 i < 8。若用 b.set(i) 仍越界但会抛异常（set 带边界检查）；operator[] 不检查是为了性能。

4. 应用题：用 bitset 实现一个简单的权限系统——4 种权限（读/写/执行/删除），函数 can(permission_set, perm) 检查是否有某权限。

答案 
#include <bitset>
#include <iostream>
enum Perm { READ = 0, WRITE = 1, EXEC = 2, DELETE = 3 };
bool can(const std::bitset<4> &perms, Perm p) {
    return perms.test(p);
}
int main() {
    std::bitset<4> user_perms("1010");   // 读=1, 写=0, 执行=1, 删除=0
    std::cout << can(user_perms, READ);    // 1
    std::cout << can(user_perms, WRITE);   // 0
    std::cout << can(user_perms, DELETE);  // 0
}

要点：enum 定义权限位、bitset<4> 存权限、test() 安全检查、字符串初始化直观。

17.3

正则表达式 regex

本节讲什么

本节讲解 C++11 <regex> 库——正则表达式全套工具：std::regex（正则对象）、std::smatch（匹配结果）、三大操作 regex_match/regex_search/regex_replace，以及迭代器遍历所有匹配。正则是文本处理的瑞士军刀——校验邮箱、提取数字、替换模式。

一句话定位：regex = "用模式串描述文本结构，编译器/库帮你匹配、提取、替换"。

核心用法

1. 基本三件套

#include <regex>
#include <string>
std::regex pat(R"(\d+)");         // 匹配连续数字
std::string s = "order 42 items";
std::smatch m;

// regex_search：查找第一个匹配（子串）
if (std::regex_search(s, m, pat)) {
    std::cout << m.str();          // "42"
    std::cout << m.position();     // 6（匹配起始位置）
}

// regex_match：完整匹配（整个字符串要符合模式）
std::regex email_pat(R"(\w+@\w+\.\w+)");
std::regex_match(std::string("a@b.com"), email_pat);    // true
std::regex_match(std::string("a@b.com extra"), email_pat); // false（未完整匹配）

// regex_replace：替换
std::string result = std::regex_replace(s, pat, std::string("##"));
// "order ## items"

2. 捕获组

用括号 () 捕获子匹配，smatch 用 [i] 访问：

std::regex pat(R"((\w+)=(\d+))");    // 两个捕获组：键和值
std::string s = "count=42";
std::smatch m;
if (std::regex_search(s, m, pat)) {
    m[0];    // 整个匹配 "count=42"
    m[1];    // 第一组 "count"
    m[2];    // 第二组 "42"
}

3. 遍历所有匹配

std::string s = "a1 b2 c3 d4";
std::regex pat(R"((\w)(\d))");
for (std::sregex_iterator it(s.begin(), s.end(), pat), end; it != end; ++it) {
    std::smatch m = *it;
    std::cout << m[1] << "->" << m[2] << "\n";   // a->1, b->2, c->3, d->4
}

4. 原始字符串字面量

正则里反斜杠多，用原始字符串 R"(...)" 避免双重转义：

std::regex r1("\\d+");        // 普通字符串：\\ 转义成 \，正则看到 \d+
std::regex r2(R"(\d+)");      // 原始字符串：直接写 \d+，无需转义
// 更复杂的：匹配 \w+@\w+\.\w+
std::regex r3("\\w+@\\w+\\.\\w+");    // 普通字符串，反斜杠地狱
std::regex r4(R"(\w+@\w+\.\w+)");     // 原始字符串，清晰

5. 正则语法选择

C++ 默认用 ECMAScript 语法（和 JavaScript 一样），也可选 POSIX 扩展等：

std::regex r(R"(\d+)", std::regex::ECMAScript);           // 默认
std::regex r2(R"([0-9]+)", std::regex::extended);         // POSIX 扩展
std::regex r3(R"(\d+)", std::regex::ECMAScript | std::regex::icase);  // 忽略大小写

和 C 的区别

C 标准库没有正则——要靠 POSIX regex.h 或第三方库（PCRE）：

维度 C（POSIX regex） C++ <regex>
标准化 POSIX 非普遍（Windows 无） C++11 标准，跨平台
API 风格 C 函数 + 手动管理 regex_t RAII 对象，自动释放
匹配结果 regmatch_t 数组 smatch 对象，支持迭代
语法 POSIX BRE/ERE ECMAScript（更熟悉） 
// C：POSIX regex（Linux 有，Windows 要额外库）
#include <regex.h>
regex_t re;
regcomp(&re, "[0-9]+", REG_EXTENDED);
regmatch_t match[1];
if (regexec(&re, "order 42", 1, match, 0) == 0) {
    // match[0].rm_so ... rm_eo 是匹配范围
}
regfree(&re);    // 手动释放

// C++：RAII，自动释放
std::regex re(R"(\d+)");
std::smatch m;
if (std::regex_search(std::string("order 42"), m, re)) {
    std::cout << m.str();
}
// re 自动析构，无需手动 free

性能提示：std::regex 构造开销大（编译正则），不要在循环里反复构造——把它做成 static const 或成员变量，只构造一次。极致性能场景可考虑 re2 库（线性时间匹配）。

常见错误

错误 1：regex_match vs regex_search 混淆

std::regex pat(R"(\d+)");
std::regex_match(std::string("abc 42"), pat);     // false！整个字符串不全是数字
std::regex_search(std::string("abc 42"), pat);    // true，找到子串 "42"

regex_match 要求整个字符串匹配；regex_search 只要有子串匹配即可。这是最常踩的坑。

错误 2：循环里反复构造 regex

for (auto &line : lines) {
    std::regex pat(R"(\d+)");    // ❌ 每次循环都编译正则，极慢
    std::regex_search(line, m, pat);
}
// 修复：提到循环外
std::regex pat(R"(\d+)");        // ✅ 只编译一次
for (auto &line : lines) {
    std::regex_search(line, m, pat);
}

错误 3：反斜杠转义错误

std::regex r("\d+");      // ❌ \d 在 C++ 字符串里不是合法转义，警告或报错
std::regex r("\\d+");     // ✅ \\ 转义成 \，正则看到 \d
std::regex r(R"(\d+)");   // ✅ 原始字符串，最清晰

错误 4：贪婪匹配非预期

std::regex r(R"(<.*>)");           // 贪婪：从第一个 < 匹配到最后一个 >
std::regex r(R"(<.*?>)");          // 非贪婪：匹配最近的 >
std::string s = "<a><b>";
std::regex_search(s, m, std::regex(R"(<.*>)"));   // m = "<a><b>"（贪婪）
std::regex_search(s, m, std::regex(R"(<.*?>)"));  // m = "<a>"（非贪婪）

*/+ 默认贪婪，加 ? 变非贪婪。

自测题

1. 选择题：以下哪个函数要求整个字符串都符合正则模式才算匹配？

A. regex_search B. regex_match C. regex_replace D. regex_find

答案

B。regex_match 要求整个字符串从头到尾完整匹配；regex_search 只需找到子串匹配；regex_replace 是替换。regex_find 不存在。

2. 判断题：std::regex 对象构造一次后可重复用于多次匹配，无需每次重新构造。

答案

对。regex 对象内部编译了正则，构造开销大但匹配快。正确做法是构造一次、匹配多次。把它做成 static const 或类成员，避免循环里反复构造。

3. 踩坑题：以下代码期望提取 "42"，实际输出什么？

std::regex pat(R"(\d+)");
std::string s = "abc 42 def";
std::smatch m;
if (std::regex_match(s, m, pat)) {
    std::cout << m.str();
} else {
    std::cout << "no match";
}
答案

输出 "no match"。regex_match 要求整个字符串 s 完全是数字，但 s 是 "abc 42 def"，不完整匹配。应改用 regex_search（查找子串）：

if (std::regex_search(s, m, pat)) {  // ✅ 找到子串 "42"
    std::cout << m.str();            // 42
}

4. 应用题：写一个函数 extract_emails(text)，用正则提取文本中所有形如 user@domain.com 的邮箱，返回 vector<string>。

答案 
#include <regex>
#include <string>
#include <vector>
std::vector<std::string> extract_emails(const std::string &text) {
    std::vector<std::string> result;
    std::regex pat(R"([\w.]+@[\w.]+\.\w+)");    // 简化版邮箱正则
    for (std::sregex_iterator it(text.begin(), text.end(), pat), end; it != end; ++it) {
        result.push_back(it->str());
    }
    return result;
}
// 用法：
auto emails = extract_emails("contact: a@b.com or c@d.org");
// emails = {"a@b.com", "c@d.org"}

要点：sregex_iterator 遍历所有匹配、it->str() 取匹配文本、原始字符串避免转义地狱。注意这是简化正则，生产环境邮箱正则更复杂。

17.4

随机数

本节讲什么

本节讲解 C++11 <random> 库的现代随机数架构：引擎（生成底层无符号原始数）+ 分布器（映射到目标区间和分布）。摒弃 C 的 rand()——它质量差、范围不均、不可复现。C++ 的引擎 + 分布分离让随机数可控、可复现、分布均匀，适合仿真、抽奖、测试、蒙特卡洛。

一句话定位：engine 产出原始随机数，distribution 把它映射到你想要的区间和分布——分离让两者各自最优。

核心用法

1. 引擎 + 分布器

#include <random>
// 引擎：生成 [0, max] 的无符号随机数
std::mt19937 eng;                    // 梅森旋转引擎（最常用）
std::default_random_engine eng2;     // 默认引擎（实现定义）

// 分布器：把引擎的原始数映射到目标区间
std::uniform_int_distribution<int> dist(1, 6);    // 1-6 均匀整数（骰子）
int roll = dist(eng);               // 调用：传入引擎，返回分布后的数

每次调用 dist(eng)：dist 从 eng 取一个原始数，按分布映射成目标区间的数。

2. 常用分布

std::mt19937 eng;
std::uniform_int_distribution<int>    d1(1, 100);    // 均匀整数 [1,100]
std::uniform_real_distribution<double> d2(0.0, 1.0); // 均匀浮点 [0,1)
std::normal_distribution<double>      d3(0.0, 1.0);  // 正态分布（均值0，标准差1）
std::bernoulli_distribution           d4(0.7);        // 伯努利：70% 概率 true
std::binomial_distribution<int>       d5(10, 0.5);   // 二项分布
for (int i = 0; i < 5; ++i) std::cout << d3(eng) << " ";  // 正态分布采样

3. 种子控制

// 固定种子：可复现（测试、调试）
std::mt19937 eng1(42);               // 每次运行结果相同

// 随机种子：每次不同
std::random_device rd;               // 真随机源（硬件熵）
std::mt19937 eng2(rd());             // 用 rd 播种

// C++11 推荐：random_device 一次性播种
std::mt19937 eng3(std::random_device{}());

可复现性对测试至关重要——用固定种子，bug 可重现。生产环境用 random_device 播种保证不可预测。

4. 正确使用模式

// 模式：引擎做成局部 static 或成员，只构造一次
int roll_dice() {
    static std::mt19937 eng(std::random_device{}());    // 只构造一次
    static std::uniform_int_distribution<int> dist(1, 6);
    return dist(eng);
}
// 不要：
int bad_roll() {
    std::mt19937 eng(std::random_device{}());    // ❌ 每次调用都重新构造 + 播种
    return eng() % 6 + 1;                         // ❌ % 6 分布不均（见下）
}

引擎构造开销大（尤其 mt19937 状态 2.5KB），不要在循环或频繁调用的函数里反复构造。

和 C 的区别

C 的 rand() 有严重缺陷：

维度 C rand() C++ <random>
质量 线性同余，低位周期短 梅森旋转，周期 2^19937-1
分布 rand()%N 分布不均 分布器精确映射
区间 rand()%N 手算 uniform_int_distribution(a,b)
可复现 种子固定即可 引擎种子明确
浮点 手动 rand()/RAND_MAX uniform_real_distribution
多种分布 无 正态/伯努利/二项等几十种

rand() % N 的分布不均问题

// C：rand() % 6 + 1 模拟骰子
int roll = rand() % 6 + 1;
// 问题：若 RAND_MAX = 32767，32767 不是 6 的倍数
// 余数 0-1 出现 5462 次，余数 2-5 出现 5461 次——轻微不均
// 对密码学、蒙特卡洛这种偏差不可接受

// C++：分布器精确映射
std::uniform_int_distribution<int> dist(1, 6);
int roll = dist(eng);   // 精确均匀，无偏差

HFT 视角：蒙特卡洛定价、回测模拟需高质量随机数。mt19937 周期极长、通过统计检验，是金融仿真的标准选择。密码学场景用 std::random_device（硬件熵）或专门密码库。

常见错误

错误 1：rand() % N 分布不均

见上文。修复：用 uniform_int_distribution，或至少用 int(double(rand()) / RAND_MAX * N)（仍有偏差但较小）。

错误 2：循环里反复构造引擎

for (int i = 0; i < 1000; ++i) {
    std::mt19937 eng(std::random_device{}());   // ❌ 每次构造 2.5KB 状态 + 系统调用
    result += eng();
}

修复：引擎提循环外：

std::mt19937 eng(std::random_device{}());
for (int i = 0; i < 1000; ++i) result += eng();

错误 3：忘记播种（默认种子每次相同）

std::mt19937 eng;    // 默认种子，每次运行结果相同
// 看似"随机"，实则是固定的——不适合需要不可预测性的场景

若需要每次不同，用 random_device 播种。若需要可复现（测试），用固定种子——这是特性不是 bug。

错误 4：浮点分布范围搞错

std::uniform_real_distribution<double> d(0.0, 1.0);
// 区间是 [0.0, 1.0) ——包含 0 不包含 1
// 若需 [0,1] 闭区间，用 d(0.0, std::nextafter(1.0, 2.0))

uniform_real_distribution 默认是半开区间 [a, b)，不含 b。整数分布 uniform_int_distribution(a,b) 是闭区间 [a,b]，含两端。

自测题

1. 选择题：C++ 随机数架构的"引擎"和"分布器"各自负责什么？

A. 引擎生成分布，分布器生成原始数 B. 引擎生成原始无符号数，分布器映射到目标区间和分布 C. 两者都生成最终随机数 D. 引擎播种，分布器生成

答案

B。引擎（如 mt19937）生成 [0, max] 的无符号原始数；分布器（如 uniform_int_distribution）从引擎取原始数，按目标分布映射到指定区间。分离让引擎专注质量、分布器专注映射，各司其职。

2. 判断题：std::mt19937 eng(42); 每次程序运行生成的随机数序列都相同。

答案

对。种子 42 固定，mt19937 是确定性算法，每次运行生成相同序列——这正是"可复现性"，对测试和调试极有用。若需每次不同，用 std::random_device{}() 播种。

3. 踩坑题：以下代码有什么问题？

#include <cstdlib>
#include <ctime>
int roll_dice() {
    srand(time(nullptr));      // 每次调用都播种
    return rand() % 6 + 1;
}
答案

三个问题： 1. srand(time(nullptr)) 在循环里反复调——同秒内 time 返回相同值，导致种子相同，后续 rand() 序列相同（非随机）。 2. rand() % 6 分布不均（RAND_MAX 不是 6 倍数）。 3. C 风格 rand() 质量低。

修复（C++ 风格）：

#include <random>
int roll_dice() {
    static std::mt19937 eng(std::random_device{}());   // 只构造播种一次
    static std::uniform_int_distribution<int> dist(1, 6);
    return dist(eng);    // 精确均匀
}

4. 应用题：写一个函数，模拟掷 2 个骰子 10000 次，统计各点数（2-12）出现频率。要求用现代 C++ 随机数。

答案 
#include <random>
#include <vector>
#include <iostream>
std::vector<int> simulate_dice(int times) {
    static std::mt19937 eng(std::random_device{}());
    static std::uniform_int_distribution<int> die(1, 6);
    std::vector<int> counts(13, 0);    // 索引 2-12
    for (int i = 0; i < times; ++i) {
        int sum = die(eng) + die(eng);
        counts[sum]++;
    }
    return counts;
}
int main() {
    auto counts = simulate_dice(10000);
    for (int s = 2; s <= 12; ++s)
        std::cout << s << ": " << counts[s] << "\n";
    // 7 应该最多（概率 1/6），2 和 12 最少（概率 1/36）
}

要点：static 引擎只构造一次、uniform_int_distribution 精确均匀、两个骰子分别采样再求和、counts 数组统计。理论分布：7 出现 ~1667 次，2/12 各 ~278 次。

17.5

计时工具（chrono）

本节讲什么

本节讲解 C++11 <chrono> 库——现代计时工具：三种时钟（system_clock/steady_clock/high_resolution_clock）、duration（时长，带单位）、time_point（时间点）。用于统计代码耗时、定时、时间戳转换。chrono 是 HFT 和性能调优的基础工具。

一句话定位：chrono = "类型安全的时间计算"——时长带单位编译期检查，不会把毫秒当微秒用。

核心用法

1. 三种时钟

时钟 特点 用途
system_clock 墙上时钟，可调（NTP 同步会跳） 时间戳、日历时间
steady_clock 单调递增，不被调整 测量耗时（首选）
high_resolution_clock 最高精度（通常=steady_clock） 高精度计时 
#include <chrono>
// 测量耗时——用 steady_clock（不会被 NTP 调整）
auto start = std::chrono::steady_clock::now();
// ... 被测代码 ...
auto end = std::chrono::steady_clock::now();
auto elapsed = end - start;

关键：测耗时永远用 steady_clock，不用 system_clock（NTP 同步会让时间倒退，测出负耗时）。

2. duration：时长

using namespace std::chrono;
milliseconds ms(100);       // 100 毫秒
microseconds us(1000);      // 1000 微秒
nanoseconds ns(1000000);    // 1000000 纳秒

// 单位转换：duration_cast
auto ms_from_us = duration_cast<milliseconds>(us);   // 1000us → 1ms
auto ns_from_ms = duration_cast<nanoseconds>(ms);    // 100ms → 100000000ns

// count() 取数值
std::cout << ms.count();    // 100

duration<Rep, Period> 是模板：Rep 是数值类型（int/double），Period 是单位比例（std::ratio<1,1000> 表示毫秒）。常用别名：nanoseconds/microseconds/milliseconds/seconds/minutes/hours。

3. time_point：时间点

using namespace std::chrono;
auto tp = steady_clock::now();                    // 当前时间点
auto later = tp + seconds(5);                      // 5 秒后
auto diff = later - tp;                            // duration：5 秒
duration_cast<milliseconds>(diff).count();         // 5000

4. 完整耗时测量

#include <chrono>
#include <iostream>
template <typename Func>
auto measure(Func f) {
    using namespace std::chrono;
    auto start = steady_clock::now();
    f();
    auto end = steady_clock::now();
    return duration_cast<microseconds>(end - start).count();
}
int main() {
    auto us = measure([]{
        volatile int sum = 0;          // volatile 防优化
        for (int i = 0; i < 1000000; ++i) sum += i;
    });
    std::cout << us << " us\n";
}

5. 睡眠与定时

#include <thread>
#include <chrono>
std::this_thread::sleep_for(std::chrono::milliseconds(100));   // 睡 100ms
std::this_thread::sleep_until(std::chrono::steady_clock::now() + std::chrono::seconds(1));

6. C++20 的 chrono 增强

C++20 让 chrono 支持日历和格式化：

// C++20：年月日
using namespace std::chrono;
auto today = year{2025}/July/19;
std::cout << today;   // 2025-07-19
// 时区支持
auto now = zoned_time{current_zone(), system_clock::now()};

和 C 的区别

C 用 clock()/time()/gettimeofday()，精度和类型安全都差：

维度 C（clock/time） C++ chrono
类型安全 无（全是整数，单位靠记） duration 带单位编译期检查
精度 clock() 毫秒级，gettimeofday 微秒 纳秒级（平台支持的话）
单位转换 手算除法 duration_cast 自动
单调时钟 无标准（POSIX clock_gettime） steady_clock 标准
可读性 clock()/CLOCKS_PER_SEC milliseconds(100) 
// C：clock() 测耗时
#include <time.h>
clock_t start = clock();
// ... 代码 ...
clock_t end = clock();
double seconds = (double)(end - start) / CLOCKS_PER_SEC;
// 问题：clock() 测 CPU 时间（不含 sleep），且精度毫秒级
// 测墙钟时间要用 gettimeofday（非标准 C，POSIX）

// C++：steady_clock 测墙钟耗时，纳秒精度
auto start = std::chrono::steady_clock::now();
// ... 代码 ...
auto end = std::chrono::steady_clock::now();
auto us = std::chrono::duration_cast<std::chrono::microseconds>(end - start).count();

HFT 视角：纳秒级计时对延迟测量至关重要。steady_clock 在 x86 上通常基于 RDTSC 指令，纳秒精度且单调。测一段代码的尾部延迟（P99/P999）用 steady_clock 采样 + 排序统计。注意 now() 本身有开销（~20-50ns），测量极短代码时要减去基准。

常见错误

错误 1：用 system_clock 测耗时

auto start = std::chrono::system_clock::now();
// ... 长任务 ...
auto end = std::chrono::system_clock::now();
auto diff = end - start;    // ❌ 若期间 NTP 调整时钟，diff 可能是负的或异常

修复：测耗时用 steady_clock（单调递增，不被调整）。system_clock 只用于时间戳/日历。

错误 2：duration_cast 截断

using namespace std::chrono;
auto us = microseconds(1500);
auto ms = duration_cast<milliseconds>(us);   // 1ms（截断，丢了 500us）
auto ms_d = duration<double, std::milli>(us); // 1.5ms（用浮点保留）

整数 duration_cast 向零截断。若需保留小数，用浮点 duration<double, ...>。

错误 3：单位混淆

using namespace std::chrono;
auto t = seconds(1) + milliseconds(500);   // 1.5 秒（自动提升到毫秒）
// t 的类型是 milliseconds，count() = 1500
auto wrong = seconds(1) + 500;             // ❌ 500 是 int 不是 duration，编译错

duration 之间可相加（自动提升到更精细单位），但不能直接加裸整数——要用 milliseconds(500) 包裹。

自测题

1. 选择题：测量一段代码的执行耗时，应使用哪个时钟？

A. system_clock B. steady_clock C. time(nullptr) D. clock()

答案

B。steady_clock 单调递增、不被 NTP 调整，是测耗时的首选。system_clock 会被调整（可能倒退，测出负值）；time()/clock() 是 C 接口，精度低且 clock() 测 CPU 时间非墙钟。

2. 判断题：std::chrono::duration_cast<std::chrono::milliseconds>(std::chrono::microseconds(1500)) 的结果是 1 毫秒。

答案

对。整数 duration_cast 向零截断，1500 微秒 = 1.5 毫秒，截断为 1 毫秒。若需 1.5 毫秒，用 std::chrono::duration<double, std::milli> 浮点 duration。

3. 踩坑题：以下代码有什么问题？

auto start = std::chrono::system_clock::now();
std::this_thread::sleep_for(std::chrono::seconds(2));
auto end = std::chrono::system_clock::now();
auto diff = std::chrono::duration_cast<std::chrono::seconds>(end - start).count();

答案

用 system_clock 测耗时——若期间 NTP 同步调整了系统时钟，diff 可能不是 2（甚至为负）。测耗时应用 steady_clock：

auto start = std::chrono::steady_clock::now();
std::this_thread::sleep_for(std::chrono::seconds(2));
auto end = std::chrono::steady_clock::now();
auto diff = std::chrono::duration_cast<std::chrono::seconds>(end - start).count();

steady_clock 单调递增，保证 diff 为 2（或略大于 2，因 sleep 精度）。

4. 应用题：写一个 benchmark(func, n) 模板函数，调用 func n 次，返回平均耗时（纳秒）。

答案 
#include <chrono>
template <typename Func>
double benchmark(Func func, int n) {
    using namespace std::chrono;
    auto start = steady_clock::now();
    for (int i = 0; i < n; ++i) func();
    auto end = steady_clock::now();
    auto total_ns = duration_cast<nanoseconds>(end - start).count();
    return static_cast<double>(total_ns) / n;   // 平均纳秒
}
// 用法：
double avg = benchmark([]{
    volatile int x = 0;
    for (int i = 0; i < 100; ++i) x += i;
}, 1000);
std::cout << avg << " ns/call\n";

要点：steady_clock 测耗时、nanoseconds 高精度、模板接受任意可调用对象、volatile 防优化掉循环。注意 now() 自身有 ~20-50ns 开销，测极短函数时要扣除基准。

特殊数值类型与可选值

本节讲什么

本节讲解 C++17 引入的几个"可选/多选"值类型工具：(1) std::optional<T>——可能存在也可能不存在的值；(2) std::variant<T...>——类型安全的 union；(3) std::any——任意类型的值；(4) std::numeric_limits——类型数值特性查询。这些是替代裸指针/union 的类型安全工具。

一句话定位：optional = "可能没有的值"（替代 T* + nullptr）；variant = "类型安全的 union"；numeric_limits = "编译期查 int 的最大值"。

核心用法

1. std::optional

表示"可能有值也可能没有"——替代 T* + nullptr 或 bool + T 双返回：

#include <optional>
std::optional<int> find(const std::vector<int> &v, int target) {
    for (size_t i = 0; i < v.size(); ++i)
        if (v[i] == target) return i;      // 有值
    return std::nullopt;                    // 无值
}
auto r = find(v, 42);
if (r) std::cout << *r;            // 解引用
std::cout << r.value_or(-1);       // 有值返回值，无值返回 -1
r.has_value();                     // 是否有值
r.reset();                         // 清空

optional 的优势：相比 T* + nullptr，它不涉及堆分配（值就地存储），且语义更明确——"这个函数可能找不到结果"。

2. std::variant

类型安全的 union——同一时间只持有一种类型，编译期知道所有可能类型：

#include <variant>
std::variant<int, double, std::string> v;
v = 42;                    // 当前是 int
v = 3.14;                  // 当前是 double
v = "hello";               // 当前是 string

// 访问
std::get<int>(v);          // 若当前是 int 返回，否则抛异常
std::get_if<int>(&v);      // 若是 int 返回指针，否则 nullptr

// 访问器：std::visit
std::visit([](auto &&x) {
    std::cout << x;
}, v);                     // 对当前持有的类型调 lambda

variant 相比 union 的优势：类型安全（知道当前是哪种）、自动调析构、支持 visit 多态访问。

3. std::any

任意类型的值（C++17）——比 variant 更灵活但更不安全：

#include <any>
std::any a = 42;
a = "hello";
a = 3.14;
// 访问：必须知道实际类型
std::any_cast<double>(a);    // 若类型对返回，否则抛异常
auto p = std::any_cast<double>(&a);   // 指针版，类型错返回 nullptr

any 用得少——若知道所有可能类型，用 variant（编译期检查）；若完全不知道，通常说明设计有问题。

4. std::numeric_limits

编译期查询数值类型的特性：

#include <limits>
std::numeric_limits<int>::max();        // 2147483647
std::numeric_limits<int>::min();        // -2147483648
std::numeric_limits<double>::epsilon(); // 2.22045e-16（机器 epsilon）
std::numeric_limits<float>::digits;     // 24（有效位数）
std::numeric_limits<int>::is_signed;    // true

替代 C 的 INT_MAX/DBL_EPSILON 宏——类型安全、模板化、可扩展到自定义类型。

和 C 的区别

C 没有 optional/variant，用裸指针或 union：

维度 C C++
可选值 T* + nullptr（堆分配 + 悬垂风险） optional<T>（栈上，无指针）
多类型值 union（无类型标签，易误访问） variant（编译期类型安全）
任意类型 void* + 手动强转 any + any_cast
数值特性 INT_MAX 宏 numeric_limits<T> 模板 
// C：可选值用指针 + nullptr
int* find(int *arr, int n, int target) {
    for (int i = 0; i < n; ++i)
        if (arr[i] == target) return &arr[i];
    return NULL;
}
int *r = find(arr, n, 42);
if (r) printf("%d", *r);    // 悬垂风险：arr 释放后 r 失效

// C++：optional 无指针风险
std::optional<int> find(std::vector<int> &v, int target) {
    for (auto &x : v) if (x == target) return x;
    return std::nullopt;
}
auto r = find(v, 42);
if (r) std::cout << *r;    // r 是值副本，不悬垂

// C：union 无类型安全
union Data { int i; double d; };
union Data d;
d.i = 42;
double x = d.d;    // ❌ 误当 double 读——未定义行为，无检查

// C++：variant 类型安全
std::variant<int, double> v;
v = 42;
std::get<double>(v);    // 抛异常（类型错），而非 UB
std::get_if<double>(&v); // 返回 nullptr

HFT 视角：optional 常用于"查询可能失败的函数"——订单查找、配置读取。它比抛异常轻量（无栈展开），比返回指针安全（无悬垂）。variant 适合"状态机"——订单状态可能是 Pending/Filled/Cancelled，每种带不同数据，visit 替代 switch 分发且编译期保证穷尽。

常见错误

错误 1：解引用空的 optional

std::optional<int> o;
std::cout << *o;    // ❌ 未定义行为（o 为空）
std::cout << o.value();   // 抛 std::bad_optional_access
std::cout << o.value_or(0);   // ✅ 安全

*o 不检查是否为空（UB），value() 检查并抛异常，value_or() 最安全。

错误 2：variant 访问错误类型

std::variant<int, double> v = 42;
std::get<double>(v);    // ❌ 抛异常（当前是 int）
auto p = std::get_if<double>(&v);   // p == nullptr

用 get_if 安全检查，或用 visit 多态访问。

错误 3：any_cast 类型不匹配

std::any a = 42;
std::any_cast<double>(a);    // ❌ 抛异常（实际是 int）

any 完全失去类型信息，any_cast 必须精确匹配——包括 const。这是 any 比 variant 危险的原因。

错误 4：用 optional<T*> 制造悬垂

std::optional<int*> find_ptr(std::vector<int> &v, int t) {
    for (auto &x : v) if (x == t) return &x;
    return std::nullopt;
}
auto r = find_ptr(v, 42);
// 若 v 扩容/销毁，*r 悬垂

optional<T*> 仍有指针的悬垂风险。若可能，返回 optional<size_t>（索引）或 optional<int>（值副本）更安全。

自测题

1. 选择题：std::optional<int> o; 以下哪个访问不会抛异常或 UB？

A. *o B. o.value() C. o.value_or(-1) D. o->something()

答案

C。o 为空时：*o 是 UB（不检查）；o.value() 抛 bad_optional_access；o.value_or(-1) 返回 -1（安全）。D 语法上对 optional 的 -> 访问内部成员，但空时是 UB。value_or 是访问可选值的最安全方式。

2. 判断题：std::variant<int, double> 同一时间可以同时持有 int 和 double 两个值。

答案

错。variant 同一时间只持有一种类型的值（像 union）。它知道当前是哪种类型，且切换时自动析构旧值、构造新值。若需同时持有多值，用 tuple。

3. 踩坑题：以下代码有什么问题？

std::variant<int, std::string> v = 42;
auto s = std::get<std::string>(v);
std::cout << s;
答案

v 当前持有 int（42），但用 std::get<std::string> 访问——类型不匹配，抛 std::bad_variant_access 异常。

修复：

if (auto p = std::get_if<std::string>(&v)) {
    std::cout << *p;
} else if (auto p = std::get_if<int>(&v)) {
    std::cout << *p;
}
// 或用 visit：
std::visit([](auto &&x) { std::cout << x; }, v);

4. 应用题：用 optional 实现一个安全的"配置查找"函数 get_config(map, key)，从 map<string,string> 查 key，找不到返回空。

答案 
#include <optional>
#include <string>
#include <unordered_map>
std::optional<std::string> get_config(
    const std::unordered_map<std::string, std::string> &m,
    const std::string &key) {
    auto it = m.find(key);
    if (it != m.end()) return it->second;   // 找到，返回值
    return std::nullopt;                     // 没找到
}
// 用法：
std::unordered_map<std::string,std::string> cfg = {{"host","localhost"},{"port","8080"}};
std::string host = get_config(cfg, "host").value_or("default");
std::string db = get_config(cfg, "db").value_or("test");
// host = "localhost", db = "test"

要点：optional<string> 表示可能失败、value_or 提供默认值、相比返回 string*（悬垂风险）或抛异常（开销大）更安全优雅。

和 C 的区别（全章总览）

综合示例

把本章几个工具串起来——一个"带计时的随机抽样配置查询"：

#include <chrono>
#include <optional>
#include <random>
#include <string>
#include <unordered_map>
#include <iostream>
#include <tuple>

// 配置查找：可能失败，返回 optional
std::optional<std::string> get_config(
    const std::unordered_map<std::string, std::string> &cfg,
    const std::string &key) {
    auto it = cfg.find(key);
    if (it != cfg.end()) return it->second;
    return std::nullopt;
}

// 随机抽样：从 N 个元素中随机选一个索引
template <typename T>
size_t random_index(const T &container) {
    static std::mt19937 eng(std::random_device{}());
    std::uniform_int_distribution<size_t> dist(0, container.size() - 1);
    return dist(eng);
}

// 带计时的操作：返回 (结果, 耗时纳秒)
template <typename Func>
auto timed(Func f) {
    auto start = std::chrono::steady_clock::now();
    auto result = f();
    auto end = std::chrono::steady_clock::now();
    auto ns = std::chrono::duration_cast<std::chrono::nanoseconds>(end - start).count();
    return std::make_tuple(std::move(result), ns);
}

int main() {
    std::unordered_map<std::string, std::string> cfg = {
        {"host", "localhost"}, {"port", "8080"}, {"db", "test"}
    };
    std::vector<std::string> keys = {"host", "port", "db", "cache"};

    // 随机选一个 key 查询，并计时
    auto random_key = keys[random_index(keys)];
    auto [result, ns] = timed([&] { return get_config(cfg, random_key); });

    std::cout << "key: " << random_key << "\n";
    if (result) {
        std::cout << "value: " << *result << "\n";
    } else {
        std::cout << "not found\n";
    }
    std::cout << "took " << ns << " ns\n";
    return 0;
}

这个示例综合了： - optional：配置查找可能失败 - 随机数：随机选 key（mt19937 + uniform_int_distribution） - chrono：steady_clock 测耗时 - tuple + 结构化绑定：timed 返回 (结果, 耗时)，auto [result, ns] = ... 解包 - 模板 + lambda：timed 接受任意可调用对象

自测题

1. 选择题：以下哪个 C++ 工具最适合表达"函数可能返回有效值，也可能找不到结果"？

A. 返回裸指针 T*，找不到返回 nullptr B. 抛异常 std::runtime_error C. std::optional<T> D. 返回 std::vector<T>，空表示没找到

答案

C。optional<T> 是表达"可能没有的值"的标准方式——栈上存储无堆分配、无悬垂风险、value_or 提供默认值。A 有悬垂和堆分配问题；B 抛异常开销大且语义不对（找不到不是异常情况）；D 语义混淆（空 vector 可能表示"找到了但是空集合"）。

2. 判断题：测量代码执行耗时时，应使用 std::chrono::system_clock，因为它代表真实墙钟时间。

答案

错。测耗时应用 steady_clock——它单调递增、不被 NTP 调整。system_clock 会被 NTP 同步调整（可能倒退），导致测出负耗时或异常值。system_clock 用于时间戳/日历转换，不用于测耗时。

3. 应用题：综合题——写一个函数，从 vector<int> 中随机选一个偶数，返回 optional<int>（若无偶数返回空），并打印查询耗时。

答案 
#include <optional>
#include <random>
#include <vector>
#include <chrono>
#include <iostream>
std::optional<int> random_even(const std::vector<int> &v) {
    if (v.empty()) return std::nullopt;
    static std::mt19937 eng(std::random_device{}());
    // 收集所有偶数（简化：多次随机尝试）
    std::uniform_int_distribution<size_t> dist(0, v.size() - 1);
    for (int attempt = 0; attempt < 100; ++attempt) {
        size_t idx = dist(eng);
        if (v[idx] % 2 == 0) return v[idx];
    }
    return std::nullopt;   // 尝试 100 次都没偶数，认为没有
}
int main() {
    std::vector<int> v = {1, 3, 5, 7, 2, 9, 4, 6};
    auto start = std::chrono::steady_clock::now();
    auto result = random_even(v);
    auto end = std::chrono::steady_clock::now();
    auto ns = std::chrono::duration_cast<std::chrono::nanoseconds>(end - start).count();
    if (result) std::cout << "found: " << *result << "\n";
    else std::cout << "no even\n";
    std::cout << "took " << ns << " ns\n";
}

要点：optional<int> 表示可能无结果、mt19937 + uniform_int_distribution 随机采样、steady_clock 测耗时、value_or/*result 访问。（更严谨的做法是先收集所有偶数再随机选，这里为简洁用了尝试法。）

Q4random 引擎
#include <random>
std::mt19937 gen(42);  // 固定种子

输出固定吗？为什么不用 rand()？

答案与复习指引

输出固定： 种子固定为 42，每次运行输出相同序列（7 49 在大多数实现中，但具体值取决于实现）。

不用 rand() 的原因： 1. 质量差：rand() 周期短、分布不均匀（低位熵低） 2. 不可控分布：rand() % 100 有模偏差，不是均匀分布 3. 不可重现：rand() 依赖全局状态（非线程安全），mt19937 是独立对象（线程安全）

HFT 用途： 回测模拟、压力测试数据生成——用固定种子保证可重现性。
