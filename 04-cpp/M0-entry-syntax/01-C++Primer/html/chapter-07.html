章节摘要

类的核心概念：数据抽象与封装。包括定义抽象数据类型、this 指针、访问控制（public/private/protected）、友元、构造函数、类的静态成员。

和 C 的区别

C struct C++ class
只有数据 数据 + 函数（成员函数）
无访问控制 public/private/protected
无构造/析构 自动调用构造/析构
无 this 隐式 this 指针
无静态成员 static 成员
7.1

定义抽象数据类型

本节讲什么

如何用 class 定义一个抽象数据类型（ADT）：把数据和相关操作捆绑在一起，对外暴露接口、对内隐藏实现。核心概念是隐式 this 指针和const 成员函数。这是 C 转 C++ 最重要的范式转变——C 的 struct 只是数据集合，C++ 的 class 是数据+行为。

核心用法

一个完整的 ADT 示例

#include <string>
#include <iostream>

class Sales_data {
public:
    // 成员函数（接口）
    const std::string& isbn() const { return bookNo; }   // const 成员函数
    Sales_data& combine(const Sales_data&);              // 返回 *this，可链式调用
    double avg_price() const;

private:
    // 数据成员（实现）
    std::string bookNo;
    unsigned units_sold = 0;   // 类内初始值（C++11）
    double revenue = 0.0;
};

// 类外定义成员函数
Sales_data& Sales_data::combine(const Sales_data& rhs) {
    units_sold += rhs.units_sold;
    revenue += rhs.revenue;
    return *this;              // 返回调用对象自身的引用
}

this 指针

成员函数内部，this 是一个隐式参数，指向调用该函数的对象：

total.combine(trans);
// 编译器把它理解为：
// Sales_data::combine(&total, trans);
// 函数内 this == &total，*this == total

const 成员函数

参数列表后加 const，表示"该函数不会修改对象"：

double avg_price() const;   // const 成员函数，this 类型是 const Sales_data*
  • const 对象只能调用 const 成员函数
  • 非 const 对象两种都能调
  • 这是 C++ 类型安全的重要部分——编译器保证 const 成员不修改对象

和 C 的区别

维度 C C++
struct 纯数据集合，无成员函数 可以有成员函数，与 class 等价（仅默认访问不同）
class 关键字 ❌ C 没有 ✅ C++ 独有
数据+操作绑定 数据放 struct，操作是独立函数 数据和操作都在 class 内
this 指针 ❌ 无（C 函数显式传对象指针） ✅ 隐式传入
const 成员函数 ❌（C 靠程序员自觉/const T* 形参） ✅ 编译器强制
类内初始值 ❌ C89 无（C 起支持 = {0} 等） ✅ C++11 起每个成员可有默认值

C 程序员的认知转变：

C 里"一个类型+相关操作"是这样组织的——数据和函数分离：

/* C：数据是 struct，操作是独立函数，显式传对象指针 */
struct Sales_data {
    char bookNo[16];
    unsigned units_sold;
    double revenue;
};
double sales_avg(const struct Sales_data* s);          // 显式传指针
void sales_combine(struct Sales_data* lhs, const struct Sales_data* rhs);

C++ 把数据和操作绑进 class，调用时 obj.combine(rhs) 而非 combine(&obj, rhs)，且 const 成员函数由编译器保证不改对象：

// C++：数据和操作一体，this 隐式传入
total.combine(trans);   // 等价 combine(&total, trans)，但更自然

这是从"数据+自由函数"到"对象封装"的范式转变，是 OOP 的起点。

常见错误

  1. const 成员函数里修改成员：void f() const { x = 1; } —— 编译错误，const 成员函数的 this 是 const T*，不能改成员。例外：用 mutable 修饰的成员可在 const 函数中改（见 §7.4）。
  2. 返回 *this 的类型用错：Sales_data combine(...) 返回值类型会拷贝，无法链式调用 a.combine(b).combine(c)。应返回引用 Sales_data& combine(...) 返回 *this。
  3. 类内初始值用圆括号：int x(0); 在类内成员声明处非法（会被当成函数声明）。修正：用 = 0 或 {0}（C++11 起类内初始值只能用 = 或 {}）。

自测题

1. 选择题：下面关于 this 的说法正确的是？ - A) this 是成员函数的隐式参数，指向调用对象 - B) this 可以被重新赋值 - C) this 在静态成员函数中也存在 - D) this 是引用类型

答案

A。this 是 T* const（指向非 const 对象）或 const T* const（const 成员函数中）的指针，是隐式参数指向调用对象。B 错（const 指针不能改指向）；C 错（静态成员函数没有 this，因为它不属于某个对象）；D 错（this 是指针不是引用，虽然实践中常 return *this 当引用用）。

2. 判断题：const 对象可以调用非 const 成员函数。

答案

错误。const 对象只能调用 const 成员函数。因为非 const 成员函数的 this 是 T*，而 const 对象的地址是 const T*，把 const T* 转 T* 是去 const，非法。这是 C++ 类型系统的强制保护，编译期检查。

3. 踩坑题：下面代码想实现链式调用，但没生效，为什么？

class Builder {
public:
    Builder add(int x) { val += x; return *this; }   // 注意返回类型
    int val = 0;
};
Builder b;
b.add(1).add(2).add(3);   // 期望 b.val == 6
答案

b.val 实际只有 1。add 返回值类型是 Builder（不是引用），每次 return *this 都拷贝一个临时对象，后续 add 作用在拷贝上，不影响原 b。修正：返回引用 Builder& add(int x) { val += x; return *this; }，这样链式调用都作用在原对象上。

4. 应用题：把下面的 C 代码改写成 C++ class 风格，体现封装和 const 成员函数。

struct Counter { int count; };
void counter_init(struct Counter* c) { c->count = 0; }
void counter_inc(struct Counter* c) { c->count++; }
int counter_get(const struct Counter* c) { return c->count; }
答案 
class Counter {
public:
    Counter() : count_(0) {}        // 构造函数替代 init
    void inc() { ++count_; }        // 非_const_成员，可修改
    int get() const { return count_; }  // const 成员函数，只读
private:
    int count_;                     // 私有，外部不能直接访问
};
Counter c;        // 自动初始化，不用手动 init
c.inc();
std::cout << c.get();   // 1
// c.count_ = 10;        // 编译错误：private，封装

对比 C：1) 构造函数替代手动 init，不会忘；2) count_ 私有，外部无法绕过 inc 直接改，保证不变式；3) get() 是 const 成员函数，编译器保证不改对象；4) 调用语法 c.inc() 比 counter_inc(&c) 自然。

7.2

访问控制与封装

本节讲什么

C++ 的访问控制符 public/private/protected，以及 class 与 struct 的唯一区别（默认访问权限）。这是实现封装——隐藏实现细节、暴露稳定接口——的语言机制。

核心用法

三个访问说明符

说明符 含义 谁能访问
public 公有接口 任何代码
private 私有实现 该类的成员函数和友元
protected 受保护 该类及派生类的成员（继承章详讲） 
class Account {
public:                                   // 外部可调用的接口
    void deposit(double amount) { balance_ += amount; }
    double balance() const { return balance_; }
private:                                  // 外部不可见的实现
    double balance_ = 0;
};

Account acc;
acc.deposit(100);          // OK，public
// acc.balance_ = 100;     // 错误：private，外部不可访问

class vs struct

class A { int x; };     // x 默认 private
struct B { int x; };    // x 默认 public

唯一区别：默认成员访问权限和默认继承方式不同。class 默认 private，struct 默认 public。其他完全一样（struct 也能有成员函数、构造函数、继承……）。

封装的意义

  • 不变式保护：把数据设 private，只能通过成员函数访问，函数内可加校验，防止外部直接破坏不变式
  • 实现自由：private 细节可随时改，不影响使用者（ABI/接口稳定）
  • 可读性：使用者只看 public 接口，不必关心实现

和 C 的区别

维度 C C++
struct 成员访问控制 全部公开，无 private 可有 public/private，与 class 等价
封装机制 ❌ 无（数据全公开，靠程序员自觉） ✅ 编译器强制
class 关键字 ❌ 无 ✅
private/public ❌ 无 ✅

C 程序员的认知转变：

C 里 struct 的成员全是公开的，外部可任意读写，封装全靠"约定"和文档：

/* C：数据全公开，外部可绕过函数直接改 */
struct Account {
    double balance;    // 谁都能直接访问
};
struct Account a;
a.balance = -1000;     // 没人拦你，破坏不变式

C++ 用 private 把数据藏起来，外部只能通过 public 函数访问，函数内可校验：

// C++：private 保护数据，public 函数控制访问
class Account {
public:
    bool deposit(double amt) {
        if (amt < 0) return false;   // 校验
        balance_ += amt;
        return true;
    }
private:
    double balance_ = 0;             // 外部碰不到
};
Account a;
// a.balance_ = -1000;   // 编译错误，private
a.deposit(-100);        // 运行期被拒

这是从"约定式封装"到"语言强制封装"的转变，C++ 编译器替你守不变式。

常见错误

  1. 把所有成员都 public：把 class 当 C struct 用，数据全公开，失去封装意义。建议：数据成员默认 private，只暴露必要的接口函数。
  2. class 和 struct 混用困惑：同一个类型一会儿用 class 声明一会儿用 struct 前向声明，没问题（它们是同一类型），但默认访问不同容易出错。建议：有封装需求用 class（默认 private 安全），纯数据聚合用 struct（默认 public 方便）。
  3. getter/setter 暴露一切：为每个 private 成员都写 get_x()/set_x()，本质还是公开数据，封装形同虚设。建议：接口应反映"行为"而非"字段"，只在确有必要时暴露。

自测题

1. 选择题：下面代码 main 中哪些访问合法？

class P {
public:  int a;
private: int b;
};
int main() {
    P p;
    p.a = 1;
    p.b = 2;
}
  • A) 都合法
  • B) 都非法
  • C) p.a=1 合法，p.b=2 非法
  • D) p.a=1 非法，p.b=2 合法
答案

C。a 是 public，外部可访问；b 是 private，外部不可访问（只有 P 的成员函数和友元能访问）。这是 C++ 封装的基本规则，编译期强制。

2. 判断题：C++ 中 struct 可以有构造函数、成员函数、继承，和 class 功能完全一样。

答案

正确。C++ 的 struct 和 class 唯一区别是默认访问权限（struct 默认 public，class 默认 private）和默认继承方式。功能上完全等价，struct 也能有构造函数、成员函数、虚函数、继承等。实践中：有封装用 class，纯数据聚合用 struct。

3. 踩坑题：下面类想保护 count_ 不被外部直接改，但有漏洞吗？

class Counter {
public:
    int& count() { return count_; }   // 返回 count_ 的引用
private:
    int count_ = 0;
};
答案

封装被绕过。count() 返回 int&，调用者拿到引用就能直接改 count_：Counter c; c.count() = 100; 完全绕过了私有性。修正：返回值类型 int（拷贝）或 const int&（只读引用），不要返回非 const 引用暴露内部数据。

4. 应用题：设计一个 Temperature 类，内部用开尔文存储，对外提供 set_celsius/get_celsius 和 set_fahrenheit/get_fahrenheit 接口。说明封装的好处。

答案 
class Temperature {
public:
    void set_celsius(double c) { kelvin_ = c + 273.15; }
    double get_celsius() const { return kelvin_ - 273.15; }
    void set_fahrenheit(double f) { kelvin_ = (f - 32) * 5 / 9 + 273.15; }
    double get_fahrenheit() const { return (kelvin_ - 273.15) * 9 / 5 + 32; }
private:
    double kelvin_ = 0;   // 内部统一用开尔文，外部不感知
};

封装好处：1) 内部表示（开尔文）可随时改（如换成微开尔文定点数）而不破坏接口；2) 外部无法设置低于绝对零度的非法值（可在 setter 加校验）；3) 使用者只需关心摄氏/华氏接口，不需理解内部存储。C 做不到这种"接口与实现分离"的强制。

7.3

友元（Friend）

本节讲什么

friend 关键字：让特定的外部函数或类访问某个类的私有成员。这是封装的一个"逃生舱"——在确实需要时打破封装，但要显式声明、可控。

核心用法

友元函数

class Point {
    friend std::ostream& operator<<(std::ostream& os, const Point& p);  // 声明友元
public:
    Point(int x, int y) : x_(x), y_(y) {}
private:
    int x_, y_;   // 私有
};

// 友元函数不是成员函数，但能访问 Point 的私有成员
std::ostream& operator<<(std::ostream& os, const Point& p) {
    return os << "(" << p.x_ << "," << p.y_ << ")";  // 直接访问 p.x_、p.y_
}

友元类

class Node {
    friend class List;   // List 的所有成员函数都能访问 Node 的私有成员
private:
    int data;
    Node* next;
};

友元成员函数

class Window {
    friend void Screen::refresh(const Window&);   // 只让 Screen::refresh 访问
private:
    int width, height;
};

和 C 的区别

维度 C C++
访问控制 ❌ 无封装，无友元概念 ✅ private + friend 逃生舱
友元 无（数据本就全公开） ✅

C 程序员的理解：C 里没有封装，也就不需要友元——所有数据都公开，任何函数都能访问。C++ 引入 private 后，有时确实需要让某个特定函数访问私有成员（典型场景：operator<< 不能是成员函数但需要读私有数据），友元就是为此设计的。

友元不是"成员"，它只是被授予了访问权限。一个函数可以是某类的友元但不是其成员。

常见错误

  1. 友元关系不是相互的：A 是 B 的友元，不代表 B 是 A 的友元。要双向访问，两边都要声明 friend。
  2. 友元破坏封装：滥用友元，把半个代码库都设成友元，封装形同虚设。建议：友元用于"接口需要"的场景（如运算符重载、迭代器访问容器内部），不用于偷懒。
  3. 友元声明位置混淆：友元声明可放在类的任意访问区（public/private/protected 都行，不受访问控制影响），但通常放最前面或最后，并加注释说明意图。

自测题

1. 选择题：关于友元，下面说法正确的是？ - A) 友元函数是类的成员函数 - B) 友元关系是相互的 - C) 友元函数可以访问类的私有成员 - D) 友元声明受 public/private 影响

答案

C。友元函数不是成员函数（A 错），它只是被授权访问私有成员的外部函数。友元关系不相互（B 错）。友元声明不受访问说明符影响，放哪都生效（D 错）。

2. 判断题：class A { friend class B; }; 之后，B 的所有成员函数都能访问 A 的私有成员，但 A 不能访问 B 的私有成员（除非 B 也声明 A 为友元）。

答案

正确。友元是单向授权：A 授予 B 访问权，B 能访问 A 的私有，但 A 不能访问 B 的私有（除非 B 反过来声明 friend class A）。这是友元的单向性。

3. 踩坑题：为什么 operator<< 通常要做成友元而不是成员函数？

答案

如果 operator<< 是成员函数，左操作数必须是当前对象，调用形式变成 p << std::cout（对象在左，流在右），反人类。标准用法是 std::cout << p（流在左），这要求 operator<< 的左操作数是 ostream&，所以它必须是非成员函数。但它又要读 p 的私有数据，于是用 friend 授权。这是友元最经典的用途。

class Point {
    friend std::ostream& operator<<(std::ostream&, const Point&);  // 友元
};
std::ostream& operator<<(std::ostream& os, const Point& p) { return os << p.x_; }
// 用法：std::cout << p;   ✓

4. 应用题：一个 Matrix 类想让自己的迭代器 MatrixIterator 访问其内部存储，但不想把内部存储公开。用友元设计这个关系，写出关键声明。

答案 
class Matrix {
    friend class MatrixIterator;   // 授权迭代器访问私有
public:
    MatrixIterator begin();
    MatrixIterator end();
private:
    double* data_;      // 内部存储，不公开
    size_t rows_, cols_;
};

class MatrixIterator {
public:
    double& operator*() { return mat_->data_[idx_]; }   // 访问 Matrix 私有
    // ...
private:
    Matrix* mat_;
    size_t idx_;
};

这样 Matrix 的内部存储对外保密，但 MatrixIterator 能访问实现高效遍历。这是 STL 容器和迭代器关系的简化版——迭代器通常是容器的友元。

7.4

类的其他特性

本节讲什么

类的几个进阶特性：类类型成员、内联成员函数、mutable 数据成员、返回 *this 的成员函数、类类型作为成员的初始化。这些是写好 class 的实用技巧。

核心用法

类类型作为成员

class Screen {
    std::string contents;   // 成员是另一个类类型
    pos cursor;             // 成员是类型别名
};

类类型的成员会在构造函数体执行前被自动构造（调用其默认构造函数），析构时自动析构——这是 RAII 链式工作的基础。

内联成员函数

class Screen {
public:
    char get() const { return contents[cursor]; }   // 类内定义，隐式 inline
    Screen& move(pos r, pos c);                     // 类外定义，非 inline
};
inline Screen& Screen::move(pos r, pos c) {          // 加 inline 显式
    cursor = r * width + c;
    return *this;
}

mutable 数据成员

class Screen {
public:
    void display() const {
        ++access_count_;    // 即使在 const 函数中也能改 mutable 成员
        // ... 显示内容
    }
private:
    mutable size_t access_count_ = 0;   // mutable：永远可变，即使在 const 对象中
    std::string contents;
};

mutable 用于"逻辑上不影响对象状态、但物理上需要修改"的成员（如访问计数、缓存）。

返回 *this 实现链式调用

class Screen {
public:
    Screen& set(char c) { contents[cursor] = c; return *this; }
    Screen& move(pos r, pos c) { cursor = r * width + c; return *this; }
};
// 链式调用
Screen s;
s.move(0, 0).set('A').set('B');   // 全作用在 s 上

const 成员函数返回 *this

class Screen {
public:
    Screen& display() { /* ... */ return *this; }        // 非 const 版，返回 Screen&
    const Screen& display() const { /* ... */ return *this; }  // const 版，返回 const Screen&
};

对 const 成员函数，*this 是 const Screen&，返回类型也要对应 const，否则会去 const。

和 C 的区别

维度 C C++
类类型成员自动构造/析构 ❌ C struct 成员不会自动初始化 ✅ 成员自动构造/析构（RAII 链）
inline 成员函数 ❌ C 无成员函数 ✅
mutable ❌ 无 ✅ C++ 独有
链式调用 a.f().g() ❌ C 无成员函数 ✅ 靠返回 *this

C 程序员最该理解的：类类型成员的自动构造/析构。C 里 struct 嵌 struct，内层 struct 不会自动初始化，必须手动调 init：

/* C：嵌套 struct 要手动初始化每一层 */
struct Inner { int x; };
struct Outer { struct Inner inner; };
struct Outer o;
o.inner.x = 0;   // 不初始化就是垃圾值，要手动

// C++：成员自动构造，内层类类型先于外层构造
class Outer {
    Inner inner;     // Outer 构造时，inner 先调用 Inner 的默认构造
};
Outer o;             // inner 已自动构造，不用手动 init

这是 RAII 的基础——对象构造时所有成员就绪，析构时成员自动清理。

常见错误

  1. const 成员函数返回非 const *this：Screen& display() const { return *this; } —— 在 const 函数里 *this 是 const Screen&，返回 Screen& 要去 const，编译错误。修正：返回 const Screen&，或提供 const/非 const 两个重载。
  2. 滥用 mutable 破坏 const 语义：把核心数据成员设 mutable，让 const 函数能改它，const 保证形同虚设。建议：mutable 只用于"逻辑 const"的成员（缓存、计数、懒初始化标志），不用于真正影响对象状态的成员。
  3. 成员初始化顺序与声明顺序不符：构造函数初始化列表写的顺序不等于初始化顺序——按成员声明顺序初始化，与初始化列表写法无关。跨成员依赖时易错。

自测题

1. 选择题：关于 mutable，下面说法正确的是？ - A) mutable 成员在 const 对象中也能修改 - B) mutable 让任何成员都能在 const 函数中改 - C) mutable 成员不占用对象空间 - D) mutable 只能用于静态成员

答案

A。mutable 修饰的成员即使在 const 对象/const 成员函数中也可修改，用于"逻辑 const"场景（如缓存、计数）。B 错（只修饰 mutable 成员，不是所有成员）；C 错（仍占空间）；D 错（用于非静态数据成员）。

2. 判断题：成员的初始化顺序由构造函数初始化列表中写的顺序决定。

答案

错误。成员按声明顺序初始化，与初始化列表中的书写顺序无关。例如：

class C {
    int a; int b;
public:
    C(int x) : b(x), a(b) {}   // 实际先初始化 a（用未初始化的 b），再 b
};

这里 a 会用到未初始化的 b，是 UB。编译器通常会警告。

3. 踩坑题：下面 const 成员函数想返回 *this 供链式调用，编译报错，为什么？

class Builder {
public:
    Builder& append(const std::string& s) const {
        buf_ += s;       // buf_ 不是 mutable
        return *this;
    }
private:
    std::string buf_;
};
答案

两个问题：1) buf_ += s 在 const 函数中修改非 mutable 成员，编译错误；2) return *this 在 const 函数中 *this 是 const Builder&，返回 Builder& 要去 const，编译错误。修正：要么去掉 const（append 要改对象）；要么提供非 const 版做修改 + const 版只读。append 本质是修改操作，不该是 const。

4. 应用题：为一个 Logger 类设计一个带缓存的 log() const 成员函数：每次调用写入缓存（mutable），缓存满时刷盘。说明为什么用 mutable。

答案 
class Logger {
public:
    void log(const std::string& msg) const {     // const：逻辑上不改 Logger 状态
        cache_ += msg + "\n";
        if (cache_.size() > 4096) flush_();       // 缓存满刷盘
    }
private:
    void flush_() const { /* 写文件 */ cache_.clear(); }
    mutable std::string cache_;    // mutable：物理改变，逻辑上 Logger 不变
};

用 mutable 因为：log() 逻辑上是"只读"操作（Logger 的配置/状态没变），但物理上要改缓存。这是"逻辑 const vs 物理 const"的经典区分——mutable 让我们表达"这个修改不影响对象的可观察状态"。

7.5

构造函数（Constructors）

本节讲什么

构造函数控制对象的初始化：构造函数初始值列表、委托构造、默认构造函数、explicit 抑制隐式转换。构造函数是 C 程序员最该认真学的——C 没有构造函数，对象初始化全靠手动 init，容易忘。

核心用法

构造函数初始值列表

class Person {
public:
    Person(std::string n, int a) : name_(std::move(n)), age_(a) {}  // 初始值列表
private:
    std::string name_;
    int age_;
};

初始值列表在函数体执行前初始化成员。如果不用初始值列表，成员会先默认构造，再在函数体里赋值——对类类型成员（如 string）是双重开销（先默认构造再赋值）。

委托构造（C++11）

class Sales_data {
public:
    Sales_data(std::string s, unsigned n, double p)
        : bookNo(s), units_sold(n), revenue(n*p) {}      // 主构造
    Sales_data(std::string s) : Sales_data(s, 0, 0) {}   // 委托给主构造
    Sales_data() : Sales_data("") {}                      // 委托给上一个
};

一个构造函数调用另一个构造函数，避免重复初始化代码。

默认构造函数

class C {
public:
    C() = default;   // 显式要求编译器生成默认构造（C++11）
};
  • 只有当类没有声明任何构造函数时，编译器才自动生成默认构造
  • 一旦声明了带参构造，默认构造就不会自动生成，需要 = default 或手写

explicit 抑制隐式转换

class String {
public:
    explicit String(const char* s);   // explicit：禁止隐式转换
};
void f(String s);
f("hello");          // 没 explicit 时：隐式 char*→String，合法；有 explicit：编译错误
f(String("hello"));  // 显式构造，始终合法

explicit 防止"一个参数的构造函数"被编译器用来做意外的隐式类型转换。

和 C 的区别

维度 C C++
构造函数 ❌ 无，对象用 = {0} 或手动 init ✅ 自动调用
初始化保证 ❌ 不 init 就是垃圾值 ✅ 构造后对象处于有效状态
忘记 init 常见 bug 构造函数强制调用，不会忘
explicit ❌ 无隐式转换概念 ✅ C++ 独有

C 程序员最该体会的转变：

C 里 struct 初始化是手动且易忘的——忘了 init 就用垃圾值，是经典 bug 源：

/* C：必须手动 init，忘了就是垃圾值 */
struct Person { char name[32]; int age; };
struct Person p;          // age 是垃圾值！
person_init(&p, "Alice", 30);   // 必须记得调 init

C++ 构造函数保证对象一创建就处于有效状态，不可能"忘记初始化"：

// C++：构造函数强制调用，对象一生成就有效
class Person {
public:
    Person(std::string n, int a) : name_(std::move(n)), age_(a) {}
private:
    std::string name_;
    int age_;
};
Person p("Alice", 30);   // 创建即初始化，age_ 一定是 30

这从语言层面消除了"未初始化对象"这一整类 bug，是 C→C++ 最大的安全提升之一。

常见错误

  1. 类类型成员没用初始值列表：Person(string n, int a) { name_=n; age_=a; } —— name_ 先默认构造（空串），再赋值，多一次开销。修正：用初始值列表 : name_(std::move(n)), age_(a)。
  2. 声明带参构造后没有默认构造：class C { public: C(int); }; 然后 C obj; 编译错误——有了带参构造，默认构造不再自动生成。修正：加 C() = default; 或手写默认构造。
  3. 该用 explicit 没用：单参构造函数不加 explicit，导致意外的隐式转换。例如 String s = "x" 看着无害，但 void f(String) 接收 f("x") 会偷偷构造临时 String，可能引发性能问题或歧义。建议：单参构造默认加 explicit，确需隐式转换再去除。

自测题

1. 选择题：下面哪种情况下编译器不会自动生成默认构造函数？ - A) 类没有任何构造函数 - B) 类只声明了一个带参构造函数 - C) 类有 const 成员但没类内初始值 - D) B 和 C 都是

答案

D。A：没有构造函数时编译器会生成默认构造。B：一旦声明任何构造函数，默认构造不再自动生成。C：有 const 成员或引用成员且没有类内初始值时，编译器无法生成默认构造（const/引用必须初始化）。所以 B 和 C 都会导致默认构造不被生成。

2. 判断题：构造函数初始值列表的书写顺序决定成员初始化顺序。

答案

错误。成员按声明顺序初始化，与初始值列表的书写顺序无关。这是常见误解。如果列表顺序与声明顺序不一致，编译器通常警告。跨成员依赖时要按声明顺序组织。

3. 踩坑题：下面代码 f(42) 能编译吗？为什么？

class Size {
public:
    Size(int n) {}    // 单参构造，没加 explicit
};
void f(Size s);
f(42);               // 传 int 给 Size 形参
答案

能编译。42 通过 Size 的单参构造函数隐式转换成临时 Size 对象。这有时是想要的，有时是 bug（你以为传的是 int，结果偷偷构造了对象）。修正：加 explicit Size(int n);，则 f(42) 编译错误，必须 f(Size(42)) 显式构造，避免意外。

4. 应用题：为一个 Vector2D 类设计构造函数：1) 默认构造 (0,0)；2) 接收 x,y；3) 接收单个值同时设 x 和 y。用委托构造减少重复，并说明哪个该加 explicit。

答案 
class Vector2D {
public:
    Vector2D(double x, double y) : x_(x), y_(y) {}        // 主构造
    Vector2D() : Vector2D(0, 0) {}                         // 委托：默认 (0,0)
    explicit Vector2D(double v) : Vector2D(v, v) {}        // 委托：单值，加 explicit
private:
    double x_, y_;
};
Vector2D a;              // (0,0)
Vector2D b(1, 2);        // (1,2)
Vector2D c(5.0);         // (5,5)，需要 explicit 也能用
// Vector2D d = 5.0;     // 编译错误：explicit 禁止隐式转换

单参构造 Vector2D(double) 应加 explicit，否则 double 会隐式转成 Vector2D，在数学运算里容易引发意外（如 v + 3.0 你以为加标量，实际加了个 Vector2D(3,3)）。双参和默认构造不需要 explicit（无法隐式转换）。

7.6

类的静态成员（Static Members）

本节讲什么

static 成员：属于整个类而非某个对象的成员。包括静态数据成员和静态成员函数。这是 C 程序员熟悉的概念——C 用文件级 static 变量/函数实现类似功能，C++ 把它纳入类作用域。

核心用法

静态数据成员

class Account {
public:
    static double rate() { return interest_rate; }   // 静态成员函数
    static void rate(double r);                       // 静态成员函数声明
private:
    static double interest_rate;                      // 静态数据成员声明
    double amount;
};

double Account::interest_rate = 0.05;    // 定义（类外），只能一次
void Account::rate(double r) { interest_rate = r; }
  • 静态数据成员不属于任何对象，所有对象共享一份
  • 必须在类外定义（分配存储），定义只能一次
  • 例外：constexpr 静态成员可类内初始化（C++17 起更宽松）

静态成员函数

// 静态成员函数
Account::rate();        // 通过类名调用（推荐）
Account acc;
acc.rate();             // 也可通过对象调用（不推荐，误导）
  • 静态成员函数没有 this 指针（不属于某个对象）
  • 因此只能访问静态成员，不能访问非静态成员
  • 不能声明为 const（const 是修饰 this 的，静态函数没 this）

静态成员的独特用途

静态成员可以是不完全类型（如指向自身类型的指针），非静态成员不行：

class Node {
    static Node* root;     // OK，静态成员可以是指向自身的不完全类型指针
    // Node n;             // 错误：非静态成员必须是完全类型
};

和 C 的区别

维度 C C++
类级共享变量 文件级 static 变量（无类作用域） ✅ 类的 static 成员
作用域 文件作用域（容易命名冲突） 类作用域（Account::rate）
访问控制 无（全文件可见） 受 public/private 控制
与类关联 无（只是约定放一起） ✅ 语言层面关联

C 程序员的理解：

C 里"属于某类型的共享变量"用文件级 static 实现，但它在文件作用域，不属于任何类型：

/* C：文件级 static 变量模拟"类级共享" */
static double interest_rate = 0.05;   // 文件作用域，不是 Account 的一部分
double account_get_rate(void) { return interest_rate; }

C++ 把它纳入类作用域，有访问控制，且语义上属于类：

// C++：static 成员属于类，有作用域和访问控制
class Account {
private:
    static double interest_rate;   // Account 的一部分，private 保护
};

好处：1) 命名不冲突（Account::rate vs Bank::rate）；2) 访问控制（private static 外部不可见）；3) 与类绑定，语义清晰。

常见错误

  1. 静态成员只在类内声明，忘了类外定义：static double interest_rate; 在类内声明，如果没有类外 double Account::interest_rate = 0;，链接时"undefined reference"。修正：在 .cpp 文件中定义一次。
  2. 静态成员函数访问非静态成员：static void f() { amount = 0; } —— 静态函数没 this，不知道是哪个对象的 amount，编译错误。修正：传对象引用，或把要访问的成员也设为 static。
  3. 静态成员函数声明为 const：static void f() const; —— const 修饰的是 this，静态函数没 this，编译错误。静态函数不能是 const。

自测题

1. 选择题：下面关于静态成员的说法正确的是？ - A) 静态数据成员每个对象各有一份 - B) 静态成员函数有 this 指针 - C) 静态数据成员必须在类外定义（constexpr 除外） - D) 静态成员函数可以访问非静态成员

答案

C。静态数据成员所有对象共享一份（A 错），必须类外定义（constexpr 静态成员可类内初始化）。静态函数没 this（B 错），不能访问非静态成员（D 错）。

2. 判断题：Account::rate() 和 acc.rate()（acc 是对象）调用同一个静态函数，效果完全一样。

答案

正确。两者调用的是同一个静态成员函数，效果一样。但推荐用 Account::rate()（类名调用），因为静态函数与具体对象无关，用对象调用会误导读者以为依赖该对象。

3. 踩坑题：下面代码链接时报错"undefined reference to Account::count_"，为什么？

// account.h
class Account {
public:
    Account() { ++count_; }
private:
    static int count_;    // 声明
};
// account.cpp —— 空的，没写 count_ 的定义
答案

静态数据成员在类内只是声明，必须在类外（通常 .cpp 文件）定义分配存储。缺少定义导致链接错误。修正：在 account.cpp 加：

int Account::count_ = 0;   // 定义并初始化，只能一次

例外：C++17 起可用 inline static int count_ = 0; 在类内直接定义，或 constexpr 静态成员类内初始化。

4. 应用题：用静态成员实现一个"全局唯一 ID 生成器"，每次调用 next() 返回递增 ID。说明静态成员相比 C 全局变量的优势。

答案 
class IdGen {
public:
    static long next() { return ++last_; }   // 静态函数
private:
    static long last_;                        // 静态数据，类外定义
};
long IdGen::last_ = 0;                        // 类外定义

// 使用
long a = IdGen::next();   // 1
long b = IdGen::next();   // 2

相比 C 全局变量 static long last = 0;：1) last_ 是 private，外部不能直接改（C 全局变量文件内可改）；2) IdGen::next 有类作用域，不会和别的 next 冲突；3) 语义上 ID 生成器是个概念，封装成类更清晰；4) 容易扩展为线程安全（加 mutex 成员）。C 全局变量无封装、易冲突。

class 和 struct 的唯一区别是什么？

答案与复习指引

唯一区别： 默认访问权限——class 默认 private，struct 默认 public。其余完全相同（都可以有成员函数、构造/析构、继承等）。

实践： 纯数据聚合用 struct（公开数据），有不变式/封装需求用 class（私有数据 + 公开接口）。

复习： → 访问控制与封装

Q3构造函数
class Point {
    int x, y;
public:
    Point() : x(0), y(0) {}           // A: 默认构造
    Point(int a, int b) : x(a), y(b) {}  // B: 带参构造
};
int main() {
    Point p1;           // 调用 A
    Point p2(3, 4);     // 调用 B
    Point p3();         // 调用...？
}

p3 是什么？

答案与复习指引

p3 是函数声明！ 声明了一个名为 p3、无参返回 Point 的函数。这就是"最烦人解析"（Most Vexing Parse）。

正确写法： Point p3{};（C++11 花括号初始化）或 Point p3;（不写括号）。

复习： → 构造函数（Constructors）

Q4友元
class Wallet {
    int money = 100;
    friend void audit(const Wallet &w);  // 友元函数
};
void audit(const Wallet &w) {
    std::cout << w.money;  // 合法：友元可访问私有成员
}

友元函数和成员函数有什么区别？友元破坏封装吗？

答案与复习指引

区别： - 友元函数不是类的成员，但可以访问私有成员 - 友元函数没有 this 指针 - 友元声明在类内，但定义在类外

是否破坏封装： 友元是有控制的开放——由类自己决定谁是友元，不是随便谁都能访问。比 public 所有成员更安全。典型用途：运算符重载（operator<< 需要访问私有成员但不是成员函数）。

复习： → 友元（Friend）

Q5静态成员
class Bank {
    static int total_accounts;
public:
    Bank() { ++total_accounts; }
    static int get_total() { return total_accounts; }
};
int Bank::total_accounts = 0;  // 类外定义
int main() {
    Bank b1, b2, b3;
    std::cout << Bank::get_total();
}

输出是什么？静态成员和全局变量有什么区别？

答案与复习指引

输出： 3

和全局变量的区别： 1. 静态成员受类作用域约束（Bank::total_accounts），不污染全局命名空间 2. 受访问控制约束（可以是 private） 3. 可以是 private 的，只有类成员/友元能访问

注意： 静态成员变量必须在类外定义（分配存储），C++17 起可用 inline static 在类内定义。

复习： → 类的静态成员（Static Members）
