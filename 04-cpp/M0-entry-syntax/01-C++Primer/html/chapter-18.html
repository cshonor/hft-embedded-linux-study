18.1

异常处理（深入版）

本节讲什么

第 5 章仅为入门，本章深入：

要点

  • 完整机制：throw 抛出、多层函数栈自动回溯、try-catch 捕获
  • noexcept：标记函数是否会抛出异常
  • 异常对象、继承体系（exception、runtime_error、logic_error 等）
  • 工程准则：RAII 配合异常保证资源不泄漏
  • 异常安全三级：基础保证、强保证、无异常保证

示例

#include <iostream>
#include <stdexcept>
double safe_divide(double a, double b) {
    if (b == 0) throw std::invalid_argument("b is zero");
    return a / b;
}
int main() {
    try {
        std::cout << safe_divide(10, 2) << std::endl;
    } catch (const std::exception &e) {
        std::cerr << e.what() << std::endl;
    }
    return 0;
}

代码自测

题目 1： 以下代码的异常安全性如何？如何改进？

void f() {
    int* p = new int[100];
    do_work(p);  // 可能抛异常
    delete[] p;
}
参考答案

如果 do_work 抛异常，p 泄漏。改进：用 RAII（智能指针）：

void f() {
    auto p = std::make_unique<int[]>(100);
    do_work(p.get());  // 异常时 p 自动析构释放
}

C++ 异常安全三个级别：基本保证（不泄漏不损坏）、强保证（操作成功或回滚）、不抛保证（noexcept）。

18.2

命名空间 namespace

本节讲什么

解决大型项目命名冲突：

要点

  • 自定义命名空间、嵌套命名空间、内联命名空间
  • using 声明 vs using namespace 指令，滥用全局 using 的坑
  • 标准库 std 原理、库版本兼容、第三方库整合避重名

示例

#include <iostream>
namespace utils {
    void hello() { std::cout << "hello from utils\n"; }
}
int main() {
    utils::hello();
    using utils::hello;
    hello();
    return 0;
}

代码自测

题目 1： 以下两种 using 用法有什么区别？

using namespace std;       // 方式A
using std::cout;           // 方式B
参考答案

方式A：using 指令——引入整个命名空间，可能导致名称冲突，不推荐在头文件中使用。方式B：using 声明——只引入特定名称，更安全。C++17 起可用嵌套命名空间：namespace A::B::C { ... }。推荐在 .cpp 文件中用 using 声明，头文件中用完整限定名。

18.3

多重继承与虚继承

本节讲什么

  1. 多重继承：一个类继承多个父类 → 菱形继承、成员名冲突、二义性
  2. 菱形继承：公共祖先多份拷贝、数据冗余
  3. 虚继承 virtual public：公共基类只保留一份实例
  4. 多重继承下的构造/析构顺序、类型转换、虚函数重写规则

示例

#include <iostream>
class Base {
public:
    virtual void f() { std::cout << "Base\n"; }
};
class D1 : public Base {};
class D2 : public Base {};
class Most : public D1, public D2 {};
int main() {
    Most m;
    m.D1::f();
    return 0;
}

代码自测

题目 1： 以下菱形继承如何解决？

class A { int a; };
class B : public A {};
class C : public A {};
class D : public B, public C {};
D d;
d.a = 1;  // 歧义？
参考答案

歧义——D 有两份 A 子对象。用虚继承：

class B : virtual public A {};
class C : virtual public A {};
class D : public B, public C {};

虚继承保证 D 中只有一份 A。但虚继承有额外开销（虚基类指针），应尽量避免。C++ 多重继承的设计比其他语言（如 Java 的接口）更复杂。

18.4

运行时类型识别 RTTI

本节讲什么

适用：多态体系里判断实际对象类型。开销略大，能靠虚函数解决就尽量不用 RTTI。

要点

运算符 用途
dynamic_cast 安全向下转型，失败返回 nullptr
typeid 获取 type_info 类型信息

示例

#include <iostream>
#include <typeinfo>
class Base { public: virtual ~Base() = default; };
class Derived : public Base {};
int main() {
    Derived d;
    Base &b = d;
    std::cout << typeid(b).name() << std::endl;
    if (auto *p = dynamic_cast<Derived *>(&b))
        std::cout << "ok\n";
    return 0;
}

代码自测

题目 1： 以下 dynamic_cast 和 typeid 各返回什么？

Base* p = new Derived;
Derived* d = dynamic_cast<Derived*>(p);  // d 的值？
if (typeid(*p) == typeid(Derived)) { ... }  // 条件？
参考答案

dynamic_cast<Derived*>(p) 返回有效指针（p 实际是 Derived）。如果 p 实际不是 Derived，返回 nullptr。typeid(*p) == typeid(Derived) 为 true——typeid 返回 type_info 引用，可比较类型。RTTI 需要 vtable（类必须有虚函数），否则 typeid 返回静态类型。-fno-rtti 可关闭 RTTI。

18.5

学习优先级

本节讲什么

中大型项目架构必学：异常、命名空间、多重继承、RTTI 是工程基础。

示例

#include <iostream>
// 第 18 章回顾：异常 + 命名空间
namespace app {
    void run() { std::cout << "running\n"; }
}
int main() {
    try { app::run(); }
    catch (...) { std::cerr << "error\n"; }
    return 0;
}

代码自测

题目 1： C++Primer 第 18 章（大型程序工具）中哪些主题对 HFT 最重要？

参考答案

1) 异常安全（RAII 保证资源不泄漏）；2) 命名空间（避免大型项目名称冲突）；3) RTTI（谨慎使用，有性能开销）。多重继承和虚继承在 HFT 中应避免——vtable 开销和复杂内存布局。异常在热路径中应禁用（-fno-exceptions），用错误码替代。

章节自测

Q1异常安全与 RAII
void process() {
    std::vector<int> v(1000);
    std::ifstream f("data.txt");
    // ... 处理 ...
    throw std::runtime_error("error");
    // v 和 f 会泄漏吗？
}

throw 后 v 和 f 会泄漏吗？为什么？

答案与复习指引

不会泄漏。 异常抛出后栈展开（stack unwinding）——所有局部对象的析构函数自动调用。v 的析构释放内存，f 的析构关闭文件。这就是 RAII 的核心优势。

和 C 的区别： C 的 longjmp 不调用析构函数（C 也没有析构），跳转路径上的资源全泄漏。C++ 异常保证栈展开时 RAII 对象自动清理。

教训： 用 RAII 管理资源（智能指针/容器/文件流），异常安全自然得到。

Q2namespace
namespace math {
    int abs(int x) { return x < 0 ? -x : x; }
}
namespace physics {
    int abs(int x) { return x < 0 ? -x : x; }  // 不同含义
}
int main() {
    std::cout << math::abs(-5) << " " << physics::abs(-5);
}

输出是什么？namespace 解决了什么问题？

答案与复习指引

输出： 5 5

namespace 解决的问题： 命名冲突。不同库可以有同名函数/类，通过命名空间区分。C 用前缀（math_abs/physics_abs）绕开冲突，丑且易错。

using 声明： using math::abs; 引入特定名称；using namespace math; 引入整个命名空间（慎用，可能引入意外冲突）。

复习： → 18.2 命名空间 namespace

Q3dynamic_cast
class Base { public: virtual ~Base() {} };
class Derived : public Base { public: void special() { std::cout << "special"; } };
Base *b = new Derived;
Derived *d = dynamic_cast<Derived*>(b);
if (d) d->special();

输出是什么？dynamic_cast 失败时返回什么？引用版本的 dynamic_cast 失败时呢？

答案与复习指引

输出： special

失败行为： - 指针版本：返回 nullptr - 引用版本：抛 std::bad_cast 异常（引用不能为空）

前提： dynamic_cast 只对多态类型（有虚函数的类）有效——靠 vtable 里的 type_info 运行时检查类型。非多态类型用 dynamic_cast 编译错误。

代价： 运行时类型查找有开销（cache miss + 字符串比较），HFT 热路径避免使用。

复习： → 18.4 运行时类型识别 RTTI

Q4多重继承
class A { public: int a; };
class B { public: int b; };
class C : public A, public B { public: int c; };
C obj;
obj.a = 1; obj.b = 2; obj.c = 3;
// sizeof(C) 是多少（假设 int=4）？

sizeof(C) 是多少？多重继承的布局是什么？

答案与复习指引

sizeof(C) = 12（三个 int，通常无 padding）

布局： C 对象内存中依次排列 A 子对象（int a）、B 子对象（int b）、C 自身成员（int c）。

多重继承的代价： 1. 如果 A/B 有虚函数，各有自己的 vptr → 对象更大 2. 基类指针转换需要 this 调整：B *pb = &obj; 的 pb 不指向 obj 开头，而是指向 B 子对象的位置 3. 菱形继承（A→B, A→C, D:B,C）导致 A 的数据存两份——用虚继承解决
