9.1

容器概览与操作

本节讲什么

C++ 标准库的顺序容器：vector、deque、list、forward_list、array、string。本节概览各容器特性、选型建议，以及公共操作（增删改查、大小管理）。C 没有任何标准容器——这是 C 程序员转 C++ 最直接的红利。

核心用法

顺序容器一览

容器 底层结构 随机访问 头尾增删 中间增删 迭代器失效
vector 动态数组 O(1) 尾 O(1) O(n) 扩容/插入/删除全失效
string 动态数组（char） O(1) 尾 O(1) O(n) 同 vector
deque 分段连续 O(1) 头尾 O(1) O(n) 部分失效
array 固定数组 O(1) ❌ 不能 O(n) —
list 双向链表 ❌ 头尾 O(1) O(1)（已知位置） 仅被删元素失效
forward_list 单向链表 ❌ 头 O(1) O(1)（已知位置） 仅被删元素失效

选型建议（关键！）

  • 默认用 vector：连续内存，cache 友好，绝大多数场景最优
  • 频繁头尾增删 → deque
  • 频繁中间增删（且已持有迭代器）→ list/forward_list
  • 大小固定 → array（替代 C 数组）
  • 字符串 → string（替代 char[]）

公共操作

std::vector<int> v = {1, 2, 3};

v.push_back(4);          // 尾部添加
v.pop_back();            // 尾部删除
v.emplace_back(5);       // 尾部原地构造（避免临时对象）
v.size();                // 元素数
v.empty();               // 是否空
v.clear();               // 清空
v.erase(v.begin());      // 删除指定位置
v.insert(v.begin(), 0);  // 指定位置插入
v.resize(10);            // 改变大小

迭代器遍历

for (auto it = v.begin(); it != v.end(); ++it) { /* *it */ }
for (auto& x : v) { /* x 是引用，可修改 */ }       // 范围 for，更简洁

和 C 的区别

维度 C C++
动态数组 手写 malloc/realloc + 手动管理大小 vector 自动管理
链表 手写 struct + 指针操作 list 现成
队列/栈 手写或调非标准库 queue/stack
边界检查 ❌ 全靠自觉 at() 有检查，[] 无（同 C）
内存管理 手动 malloc/free RAII 自动释放
通用算法 自己写 <algorithm> 提供排序/查找等

C 程序员最该体会的：

C 里"动态数组"要手写 realloc + memcpy + 大小管理，几十行易错代码：

/* C：手写动态数组 */
int* arr = NULL;
size_t size = 0, cap = 0;
void push(int x) {
    if (size == cap) {
        cap = cap ? cap * 2 : 4;
        arr = realloc(arr, cap * sizeof(int));   // 忘了检查返回值就 UB
    }
    arr[size++] = x;
}
// 还要记得 free(arr)，忘了就泄漏

C++ 的 vector 一行搞定，且析构自动释放：

std::vector<int> v;
v.push_back(x);    // 自动扩容，自动管理
// 析构自动释放，不泄漏

这是从"手写基础设施"到"直接用现成"的飞跃——省下的精力用于业务逻辑。

常见错误

  1. 用 [] 越界访问不报错：v[v.size()] 越界但 [] 不检查，UB（可能看似正常，可能崩溃）。修正：需要检查用 v.at(i)（越界抛 out_of_range），或严格保证不越界。
  2. 迭代器失效后继续用：v.push_back 触发扩容后，之前存的迭代器全失效，再用 UB。修正：扩容后重新获取迭代器；HFT 热路径用 reserve 预留避免扩容。
  3. 选错容器：频繁中间插入用 vector（O(n) 移动），应该用 list；需要随机访问用 list（O(n) 遍历），应该用 vector。选型错误导致性能差。

自测题

1. 选择题：下面哪种场景 std::list 比 std::vector 更合适？ - A) 需要随机访问 arr[i] - B) 频繁在尾部追加 - C) 频繁在中间插入/删除，且已持有迭代器 - D) 数据量小，要 cache 友好

答案

C。list 是链表，中间插入/删除（已知位置）是 O(1)，vector 是 O(n) 移动元素。A 要随机访问用 vector；B 尾部追加 vector 更优（连续内存）；D 小数据 vector cache 友好更快。实践中 list 用得少——vector 的连续内存优势通常盖过 list 的插入优势，除非插入极频繁。

2. 判断题：std::vector<int> v; v[0] = 1; 在 v 为空时是未定义行为。

答案

正确。[] 不做边界检查，空 vector 访问 v[0] 越界，UB（可能崩溃、可能写坏内存）。要安全访问用 v.at(0)（抛异常）或先 push_back/resize。这是 C/C++ 共同坑——C 数组越界也是 UB。

3. 踩坑题：下面代码想删除所有偶数，但结果不对，为什么？

std::vector<int> v = {1, 2, 3, 4, 5, 6};
for (auto it = v.begin(); it != v.end(); ++it) {
    if (*it % 2 == 0) v.erase(it);
}
答案

erase 返回下一个有效迭代器，但循环里 ++it 在 erase 后用的是已失效的迭代器，导致跳过元素或 UB。正确写法：

for (auto it = v.begin(); it != v.end(); ) {
    if (*it % 2 == 0) it = v.erase(it);   // erase 返回下一个，不 ++it
    else ++it;
}

或更简洁用 erase-remove 惯用法：v.erase(std::remove_if(v.begin(), v.end(), [](int x){return x%2==0;}), v.end());

4. 应用题：实现一个简单的"最近 N 条消息"缓冲区——保存最近 N 条，超出自动丢弃最旧的。选什么容器？写出关键代码。

答案

用 std::deque（头尾 O(1)）或环形 buffer。deque 版本：

#include <deque>
std::deque<std::string> recent;
size_t N = 100;
void add(const std::string& msg) {
    recent.push_back(msg);
    if (recent.size() > N) recent.pop_front();   // 丢弃最旧
}

vector 也可（erase 头部 O(n)），但 N 大时 deque 头部弹出更高效。HFT 实战常用固定大小环形 buffer（vector 预留 N + 取模索引）避免任何动态分配。

9.2

底层机制

本节讲什么

vector/string 等可变长容器的扩容机制：capacity（容量）vs size（元素数）、reserve 预留、shrink_to_fit 收缩。理解这个机制能避免性能尖峰和迭代器失效——对 HFT 尤为关键。

核心用法

size vs capacity

std::vector<int> v;
v.reserve(100);          // 预留 100 容量，不创建元素
std::cout << v.size();       // 0（没有元素）
std::cout << v.capacity();   // 100（已分配空间）

for (int i = 0; i < 100; ++i) v.push_back(i);
// 这 100 次 push_back 不会扩容（capacity 够用）

v.push_back(101);        // 超过 capacity，触发扩容
// 扩容：1) 分配更大空间（通常 2 倍）2) 拷贝/移动旧元素 3) 释放旧空间
// 此时所有旧迭代器/指针/引用全部失效！

扩容代价

扩容要：1) 分配新内存；2) 拷贝/移动所有旧元素到新内存；3) 析构旧元素；4) 释放旧内存。是 O(n) 操作。如果不 reserve，n 次 push_back 总扩容代价是 O(n) 摊还 O(1)，但单次扩容可能造成延迟尖峰。

管理工具

操作 作用
v.reserve(n) 预留至少 n 容量，不改变 size，避免后续扩容
v.resize(n) 改变 size 到 n（多则填充默认值，少则截断）
v.shrink_to_fit() 请求释放多余容量（非强制）
v.capacity() 查当前容量

和 C 的区别

维度 C (realloc) C++ (vector)
扩容 手动 realloc，返回新指针 自动，对用户透明
迭代器/指针失效 realloc 可能移动内存，旧指针失效（但 C 程序员常忽视） vector 扩容明确使所有迭代器失效
预留 手动算 size + malloc 大块 reserve(n) 一行
移动 vs 拷贝 只能 memcpy（浅拷贝，含指针时危险） 元素有移动构造时优先移动，安全
失败处理 realloc 返回 NULL，原内存仍在 抛 bad_alloc 异常

C 程序员最该理解的两点：

  1. 扩容导致迭代器/指针/引用全部失效。C 的 realloc 也有同样问题（可能移动内存），但 C 程序员常忽视——因为 C 里很少缓存"指向数组元素的指针"。C++ 大量用迭代器/引用，扩容失效问题更突出。
/* C：realloc 后旧指针可能悬垂 */
int* p = arr;
arr = realloc(arr, new_cap);   // arr 可能换了地址
*p = 5;                        // p 指向旧地址，可能已释放！UB

// C++：vector 扩容后迭代器失效，同样问题
auto it = v.begin();
v.push_back(x);     // 若扩容，it 失效
*it = 5;            // UB！
  1. reserve 是性能关键。知道大致大小时先 reserve，避免反复扩容。
std::vector<int> v;
v.reserve(1000);          // 知道要 1000 个，预留
for (int i = 0; i < 1000; ++i) v.push_back(i);  // 零扩容

常见错误

  1. 缓存了迭代器/引用，扩容后继续用：auto& ref = v[0]; v.push_back(x); ref = ...; —— 若 push_back 触发扩容，ref 悬垂。修正：扩容后重新获取；或 reserve 保证不扩容。
  2. 在循环里 push_back 不 reserve：n 次 push_back 触发约 log(n) 次扩容，每次拷贝所有元素，O(n log n) 浪费。修正：能预估大小就 reserve。
  3. 混淆 reserve 和 resize：reserve(10) 不创建元素（size 不变，不可下标访问）；resize(10) 创建 10 个元素（size=10，可 v[0]）。用错会导致 v[0] 越界或意外默认构造。

自测题

1. 选择题：下面代码后 v.size() 和 v.capacity() 至少是多少？

std::vector<int> v;
v.reserve(50);
v.push_back(1);
  • A) size=1, capacity=50
  • B) size=50, capacity=50
  • C) size=1, capacity=1
  • D) size=50, capacity=1
答案

A。reserve(50) 让 capacity >= 50，但不创建元素（size 仍 0）。push_back(1) 让 size=1，capacity 不变（仍 >= 50，因为没超）。reserve 只影响容量不影响 size，这是和 resize 的关键区别。

2. 判断题：v.reserve(100) 后，v[0] 可以安全访问。

答案

错误。reserve 只分配内存（capacity=100），不创建元素（size=0）。v[0] 访问的是不存在的元素，越界 UB。要创建元素用 resize(100)（size=100，可访问 v[0]..v[99]）。这是 reserve/resize 最常混淆的点。

3. 踩坑题：下面代码想"先存第一个元素的引用，添加更多元素后用"，但崩溃了，为什么？

std::vector<int> v = {1};
int& first = v[0];
for (int i = 0; i < 100; ++i) v.push_back(i);
std::cout << first;    // 崩溃或乱码
答案

first 是 v[0] 的引用。循环里 push_back 触发多次扩容，每次扩容 vector 内部内存搬家，v[0] 换了地址，first 成悬垂引用，访问 UB。修正：1) 先 reserve(101) 保证不扩容；2) 或扩容后重新 first = v[0]；3) 或存值而非引用 int first = v[0]（拷贝，不受扩容影响）。

4. 应用题：你要从网络读未知数量的消息存入 vector，但要求零扩容延迟尖峰（HFT 热路径）。设计策略。

答案 
std::vector<Msg> msgs;
msgs.reserve(ESTIMATED_MAX);    // 按经验预估上限预留

while (receiving) {
    if (msgs.size() == msgs.capacity()) {
        // 接近上限，要么丢弃、要么预留更大、要么报错
        // HFT 热路径宁可丢消息也不要扩容尖峰
        handle_overflow(msgs);
        break;
    }
    msgs.emplace_back(read_msg());
}

HFT 策略：1) 启动时 reserve 到预估上限；2) 监控 size 接近 capacity 时主动处理（丢/转储），绝不触发扩容；3) 极端情况用固定大小环形 buffer（vector 预留 N + 取模索引），彻底消除动态分配。原则：热路径零分配。

9.3

string 的额外操作

本节讲什么

把 string 视作"元素的 char 特化容器"之外，它还有大量额外操作：子串、拼接、替换、搜索、与数值互转。本节梳理这些 C 字符串函数（str* 族）的 C++ 现代替代品。

核心用法

构造与子串

std::string s("hello world");
std::string sub = s.substr(0, 5);    // "hello"（位置 0 起 5 个字符）
std::string s2(s, 6);                 // "world"（位置 6 到末尾）

拼接与追加

std::string s = "hello";
s += " world";                       // 追加
s.append("!!!");                     // 等价
s.push_back('!');                    // 追加单字符

替换与插入

std::string s = "hello world";
s.replace(6, 5, "C++");              // 位置 6 起 5 个字符替换为 "C++" → "hello C++"
s.insert(5, ",");                    // 位置 5 插入 "," → "hello, C++"
s.erase(5, 1);                       // 位置 5 起删 1 个字符

搜索

std::string s = "hello world";
auto pos = s.find("world");          // 6（找到返回位置）
auto pos2 = s.find("xyz");           // std::string::npos（没找到）
if (pos != std::string::npos) { /* 找到 */ }

s.rfind("o");                        // 从后往前找，7
s.find_first_of("aeiou");            // 找第一个元音，1
s.find_last_of("o");                 // 最后一个 o，7

数值与字符串互转（C++11）

std::to_string(42);                  // "42"
std::to_string(3.14);                // "3.140000"
std::stoi("42abc");                  // 42（解析到非数字停）
std::stod("3.14xyz");                // 3.14
size_t idx;
int n = std::stoi("42abc", &idx);    // n=42, idx=2（消耗字符数）

和 C 的区别

维度 C C++
字符串类型 char[] + '\0' std::string（带长度，不靠 '\0'）
长度 strlen O(n) 遍历 s.size() O(1)
拼接 strcat/strncat（易溢出） +=/append（自动扩容）
子串 strncpy + 手动算偏移 substr
查找 strstr/strchr find/rfind/find_first_of
数值转换 atoi/sprintf/sscanf（不安全/易错） stoi/to_string（类型安全）
内存管理 手动 malloc/free RAII 自动
溢出风险 高（strcat/sprintf 易溢出） 无（自动扩容）

C 程序员最该体会的：

  1. 不溢出 + 自动管理内存：C 的字符串操作是安全重灾区（strcat/strcpy/sprintf 都易溢出，导致安全漏洞）。std::string 自动扩容，从根本上消除溢出。
/* C：strcat 溢出风险 */
char buf[10] = "hi";
strcat(buf, " world");    // 超过 10 字节，溢出 UB，可能被利用

// C++：自动扩容，不溢出
std::string s = "hi";
s += " world";            // 自动扩容，安全

  1. 长度 O(1)：C 的 strlen 要遍历到 '\0'，O(n)。string::size() 直接读存的长度，O(1)。循环里频繁取长度时差异明显。

  2. 数值转换类型安全：C 的 atoi("abc") 返回 0（无法区分"0"和"错误"），sprintf 格式串易错。C++ 的 stoi 可通过 idx 和异常区分错误。

常见错误

  1. find 不检查 npos 就用结果：s[s.find("x")] —— 没找到时返回 npos（一个很大的数，通常 size_t 最大值），用作下标越界 UB。修正：auto pos = s.find("x"); if (pos != npos) {...}。
  2. stoi 不检查异常：stoi("") 或 stoi("99999999999999")（溢出）会抛 invalid_argument/out_of_range。不 catch 就崩溃。修正：try/catch 或先校验。
  3. 混用 string 和 C 字符串接口：把 string 传给要 char* 的 C 函数，要用 s.c_str()（返回 const char*）。修改 C 函数的内容要用 &s[0]（C++17 起保证连续）且确保有 '\0'。

自测题

1. 选择题：std::string("hello").find("xyz") 的返回值是？ - A) 0 - B) -1 - C) std::string::npos - D) 抛异常

答案

C。find 没找到返回 std::string::npos（一个特殊值，通常等于 size_t(-1)，是个很大的无符号数）。不返回 -1（int 的 -1），不抛异常。关键：判断找到与否必须 pos != npos，不能 pos != -1（虽然数值常相等，但类型不同，习惯要正确）。

2. 判断题：std::string s; std::cout << s.size(); 输出 0，且 s 内部没有 '\0'。

答案

前半正确（size 是 0），后半"没有 '\0'"不准确。std::string 不靠 '\0' 计长度（靠存的 size 成员），但 c_str() 返回的 C 字符串保证以 '\0' 结尾，所以内部通常有个 '\0' 在末尾（C++11 起保证连续且 '\0' 结尾）。但这个 '\0' 不计入 size。

3. 踩坑题：下面代码想取 "world" 子串，但结果是空串，为什么？

std::string s = "hello world";
std::string sub = s.substr(6, 5);    // 想取 "world"
std::cout << sub;   // 实际输出 "world"，没问题？

等等，再看这个：

std::string s = "hello world";
std::string sub = s.substr(6, 11);   // 想取位置 6 到末尾
答案

第一个是对的，输出 "world"。第二个的 substr(6, 11) 中第二个参数是长度不是结束位置，"hello world" 从位置 6 到末尾只有 5 个字符（"world"），请求 11 个但只有 5 个，substr 不会越界，自动取到末尾返回 "world"。但如果你以为第二个参数是结束下标（像 Python 的切片），会困惑。记法：substr(pos, len)，pos 是起始，len 是长度。

4. 应用题：写一个安全的"解析配置行 key=value"函数，把 key 和 value 分离。对比 C 的 strtok 方案。

答案 
#include <string>
bool parse(const std::string& line, std::string& key, std::string& val) {
    auto pos = line.find('=');
    if (pos == std::string::npos) return false;    // 没找到 =
    key = line.substr(0, pos);                     // = 之前
    val = line.substr(pos + 1);                    // = 之后到末尾
    return true;
}

对比 C 的 strtok：

/* C：strtok 破坏原串、非线程安全、要可变缓冲 */
char buf[256];
strcpy(buf, line);            // strtok 要修改，得先拷贝
char* key = strtok(buf, "=");
char* val = strtok(NULL, "");

C++ 版：1) 不破坏原串（const 引用）；2) 线程安全；3) 不用管缓冲区大小；4) 类型安全。strtok 的"非重入"是 C 字符串处理的经典坑。

容器适配器

本节讲什么

容器适配器（adapter）：stack（栈）、queue（队列）、priority_queue（优先队列）。它们不是独立容器，而是对底层容器（默认 deque/vector）的接口包装，只暴露特定行为。C 没有标准库提供这些，全靠手写。

核心用法

stack（栈，LIFO）

#include <stack>
std::stack<int> s;       // 默认底层 deque
s.push(1); s.push(2);
s.top();                 // 2（看栈顶，不弹出）
s.pop();                 // 弹出栈顶（无返回值！）
s.size(); s.empty();
操作 复杂度
push/pop O(1)
top O(1)

queue（队列，FIFO）

#include <queue>
std::queue<int> q;       // 默认底层 deque
q.push(1); q.push(2);
q.front();               // 1（队首）
q.back();                // 2（队尾）
q.pop();                 // 弹出队首

priority_queue（优先队列，最大堆）

#include <queue>
std::priority_queue<int> pq;    // 默认 vector + 最大堆
pq.push(3); pq.push(1); pq.push(2);
pq.top();                // 3（最大值在顶）
pq.pop();                // 弹出最大值

// 最小堆：用 greater 作比较器
std::priority_queue<int, std::vector<int>, std::greater<int>> min_pq;
min_pq.push(3); min_pq.push(1);
min_pq.top();            // 1（最小值在顶）
操作 复杂度
push/pop O(log n)
top O(1)

自定义底层容器

// stack 默认用 deque，可换 vector 或 list
std::stack<int, std::vector<int>> s;    // 底层 vector
std::stack<int, std::list<int>> s2;     // 底层 list

和 C 的区别

维度 C C++
栈 手写数组 + top 指针 stack 现成
队列 手写数组（环形 buffer）或链表 queue 现成
优先队列 手写堆（极繁琐） priority_queue 现成
边界保护 ❌ 全靠自觉 有 empty() 检查
内存管理 手动 RAII

C 程序员最该体会的：

C 里栈/队列要手写几十行，优先队列（堆）更繁琐易错：

/* C：手写栈 */
int stack[100], top = -1;
void push(int x) { stack[++top] = x; }
int pop(void) { return stack[top--]; }   // 空栈时越界 UB
int peek(void) { return stack[top]; }
// 没有边界检查，没有泛型，每个类型重写一遍

C++ 一个模板类搞定，类型安全，边界可查：

std::stack<int> s;
s.push(1);
if (!s.empty()) s.pop();    // 安全检查
// 想要 stack<string>？改一个字就行

优先队列差距更大——C 手写堆（sift up/down）极繁琐，C++ 的 priority_queue 一行声明。

常见错误

  1. 空栈/空队列调 top/front：std::stack<int> s; s.top(); —— 空栈访问 top 是 UB。修正：先 if (!s.empty())。
  2. 以为 pop 返回元素：int x = s.pop(); —— C++ 的 stack/queue 的 pop 返回 void（不返回弹出值）。要先 top()/front() 取值再 pop()。这是与某些其他语言（Java 的 pop 返回值）的区别。
  3. priority_queue 想要最小堆写错比较器：默认是 less（最大堆），要最小堆用 greater。容易搞反——less 反直觉地对应最大堆，因为"less"描述的是父子关系。

自测题

1. 选择题：std::priority_queue<int> 默认是？ - A) 最小堆（top 是最小值） - B) 最大堆（top 是最大值） - C) 按插入顺序 - D) 随机

答案

B。默认 priority_queue 用 less<int> 作比较器，top 是最大值（最大堆）。要最小堆用 std::greater<int>：std::priority_queue<int, std::vector<int>, std::greater<int>>。这个"less 对应最大堆"反直觉，记法：比较器定义的是"父节点应优于子节点"的序，less 意味着父应不小于子→父最大。

2. 判断题：std::stack<int> s; int x = s.pop(); 能正确取出栈顶元素。

答案

错误。C++ 标准库的 stack::pop() 返回 void，不返回弹出值（出于异常安全考虑——若 pop 先拷贝再删除，拷贝抛异常则元素既没取出也没了）。要先 int x = s.top(); 再 s.pop();。这是 C++ 容器适配器的设计哲学，与 Java 的 Stack.pop() 返回值不同。

3. 踩坑题：下面代码用优先队列处理任务，但发现每次取的不是最紧急的，为什么？

struct Task { int priority; std::string name; };
std::priority_queue<Task> pq;     // 想优先级高的先处理
pq.push({1, "low"});
pq.push({5, "high"});
auto t = pq.top();                // 期望拿到 high，但...
答案

priority_queue<Task> 默认用 less<Task>，但 Task 没定义 operator<，编译错误或行为未定义。需要自定义比较器：

auto cmp = [](const Task& a, const Task& b){ return a.priority < b.priority; };
std::priority_queue<Task, std::vector<Task>, decltype(cmp)> pq(cmp);

或给 Task 定义 operator<（按 priority 排）。自定义类型用 priority_queue 必须提供比较方式，否则编译失败。

4. 应用题：用 priority_queue 实现一个"实时求中位数"的结构：随时插入数字，随时能查当前中位数。提示：用两个堆。

答案 
#include <queue>

class MedianFinder {
    std::priority_queue<int> left;     // 最大堆，存较小的一半
    std::priority_queue<int, std::vector<int>, std::greater<int>> right;  // 最小堆，较大的一半
public:
    void addNum(int num) {
        left.push(num);
        right.push(left.top()); left.pop();    // 平衡
        if (left.size() < right.size()) {      // 维持 left >= right
            left.push(right.top()); right.pop();
        }
    }
    double findMedian() {
        if (left.size() > right.size()) return left.top();
        return (left.top() + right.top()) / 2.0;
    }
};

思路：最大堆 left 存较小半，最小堆 right 存较大半，保持 left.size >= right.size。中位数在 left.top（奇数个）或两堆 top 平均（偶数个）。C 手写两个堆极繁琐，C++ 直接用 priority_queue。O(log n) 插入，O(1) 查中位数。

A/B/C/D 分别选什么容器？

答案与复习指引

Q2vector capacity/reserve
std::vector<int> v;
std::cout << v.size() << " " << v.capacity() << "\n";
v.push_back(1);
v.push_back(2);
v.push_back(3);
v.reserve(100);
std::cout << v.size() << " " << v.capacity();

两行输出分别是什么？

答案与复习指引

第一行： 0 0（空 vector，size 和 capacity 都是 0） 第二行： 3 100（3 个元素，reserve 到 100 后 capacity = 100，但 size 仍为 3）

reserve 的意义： 预分配 capacity，避免 push_back 时多次扩容（每次扩容拷贝所有元素）。HFT 启动时按峰值 reserve。

size vs capacity： size = 实际元素数；capacity = 已分配的底层内存能容纳的元素数。

Q3erase-remove 惯用法
std::vector<int> v = {1, 2, 3, 2, 4, 2, 5};
v.erase(std::remove(v.begin(), v.end(), 2), v.end());
// v 现在是什么？

v 是什么？为什么不直接 v.erase(it) 遍历删除？

答案与复习指引

v = {1, 3, 4, 5} — 删除了所有 2。

erase-remove 惯用法： - remove 把不等于 2 的元素移到前面，返回新的逻辑终点迭代器 - erase 删除从新终点到旧终点之间的"垃圾"元素

不直接遍历 erase 的原因： 1. 遍历中 erase 会使迭代器失效——it = v.erase(it) 才安全，但容易写错 2. 每次 erase 是 O(n) 移动，遍历 erase 总共 O(n²)；erase-remove 是 O(n)
