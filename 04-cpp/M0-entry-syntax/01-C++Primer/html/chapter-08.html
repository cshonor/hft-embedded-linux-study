C C++
FILE* + fprintf/fscanf ostream/istream + <</>>

8.1

IO 类体系

本节讲什么

C++ 的 IO 类层次：iostream（控制台）、fstream（文件）、sstream（内存 string）。重点是继承关系让它们可互换——一个接受 istream& 的函数既能读 cin，也能读文件、读 string。这是 C 的 FILE* 做不到的多态。

核心用法

三大头文件

头文件 类 用途
<iostream> istream/ostream/iostream 控制台 IO（cin/cout/cerr/clog）
<fstream> ifstream/ofstream/fstream 文件 IO
<sstream> istringstream/ostringstream/stringstream 内存 string IO

继承层次（简化）

        ios_base
            │
          ios
         ╱   ╲
    istream   ostream
       ╲       ╱
       iostream
       ╱   ╲   ╱
ifstream  stringstream  fstream ...

ifstream 继承自 istream，istringstream 也继承自 istream。所以一个 istream& 参数可以接收 cin、ifstream、istringstream——多态。

多态的好处

// 一个函数，能从任意输入流读
void process(std::istream& in) {
    int x;
    while (in >> x) std::cout << x << " ";
}

process(std::cin);                              // 读控制台
std::ifstream f("data.txt");
process(f);                                     // 读文件
std::istringstream iss("1 2 3");
process(iss);                                   // 读 string

和 C 的区别

维度 C (stdio) C++ (iostream)
控制台 scanf/printf cin/cout
文件 fopen/fread/fprintf ifstream/ofstream
内存 sscanf/sprintf istringstream/ostringstream
类型安全 ❌ 格式串手动对齐类型，易错 ✅ 编译器按类型重载 <</>>
多态 ❌ FILE* 无继承，函数各写各的 ✅ 继承层次，istream& 通用
资源管理 手动 fclose RAII 析构自动关闭
扩展自定义类型 ❌ 要自己写 printf 格式 ✅ 重载 operator<< 支持任意类型

C 程序员最该体会的：

  1. 类型安全：C 的 printf 格式串和参数类型不匹配时，编译器不查（GCC 有 -Wformat 但不强制），运行 UB。C++ 的 <</>> 按类型重载，编译期保证类型正确。
/* C：格式串和类型不匹配，运行 UB，编译器不一定警告 */
int x = 42;
printf("%f\n", x);        // 用 %f 打 int，UB！

// C++：编译器按类型选 operator<<，类型安全
int x = 42;
std::cout << x << "\n";   // 调 operator<<(ostream&, int)，安全

  1. 多态：C 的读文件、读控制台、读内存是三套不同函数（fscanf/scanf/sscanf），无法统一。C++ 一个 istream& 参数全搞定。

  2. RAII：C 的 FILE* 必须手动 fclose，忘了就泄漏。C++ 的 fstream 析构自动关闭。

常见错误

  1. 忘了检查流状态：in >> x; use(x); —— 如果读取失败（EOF、格式错），x 未定义却继续用。修正：if (in >> x) { use(x); } 或 while (in >> x)。
  2. 复制流对象：ifstream f2 = f; —— 流对象不可复制（防止多个对象管同一资源）。只能传引用或移动。
  3. 混用 C stdio 和 C++ iostream 不同步：同时用 printf 和 std::cout 输出可能交错。修正：调 std::ios::sync_with_stdio(false); 关同步（性能提升，但不能再混用）或保持默认同步。

自测题

1. 选择题：下面函数参数类型最通用（能接收 cin/ifsteam/istringstream）的是？ - A) void f(std::iostream in) - B) void f(std::istream& in) - C) void f(std::ifstream& in) - D) void f(FILE* in)

答案

B。istream& 是基类引用，cin/ifstream/istringstream 都派生自 istream，可多态接收。A 流不可复制，不能值传递；C 只能接收 ifstream；D 是 C 的 FILE*，与 iostream 无关。

2. 判断题：C++ 的 std::cout << x 比 C 的 printf("%d", x) 更安全。

答案

正确。<< 按类型重载，编译器根据 x 的类型选对应 operator<<，类型不匹配编译错误。printf 的格式串是运行期字符串，编译器默认不检查与参数类型的匹配，printf("%d", 3.14) 编译过但运行 UB。C++ 的类型安全在编译期消除整类错误。

3. 踩坑题：下面代码想读完整数后继续读，但读取失败后陷入死循环，为什么？

int x;
while (true) {
    std::cin >> x;
    std::cout << x;
}

（输入 abc）

答案

输入 abc 不是整数，cin >> x 失败，流进入失败状态，x 未赋值，且后续 >> 都直接返回失败不读取——死循环打印垃圾。修正：检查流状态，失败时 break 并 clear：

while (std::cin >> x) std::cout << x;
// 退出循环说明失败（EOF 或格式错）

4. 应用题：写一个 count_words 函数，能从 cin、文件、string 任意来源统计单词数。用 istream& 参数实现多态。

答案 
#include <iostream>
#include <fstream>
#include <sstream>
#include <string>

size_t count_words(std::istream& in) {
    size_t n = 0;
    std::string word;
    while (in >> word) ++n;   // >> 按空白分割
    return n;
}

// 三种来源都能用：
// count_words(std::cin);
// std::ifstream f("a.txt"); count_words(f);
// std::istringstream iss("hello world foo"); count_words(iss);

C 要写三个函数（count_stdin/count_file/count_string），C++ 一个 istream& 参数全搞定——这是继承多态的直接收益。C 的 FILE* 没有这种统一接口（scanf/fscanf/sscanf 是三个不同函数）。

8.2

管理条件状态

本节讲什么

每个 IO 流对象维护一组条件状态标志，记录流是否处于有效、EOF、失败等状态。本节讲如何查询和复位这些状态——这是健壮 IO 处理的基础，C 程序员对应的是 feof/ferror/errno。

核心用法

四种状态标志

标志 含义 查询函数
goodbit 一切正常 good()
eofbit 到达文件尾 eof()
failbit 操作失败（如格式不匹配），可恢复 fail()
badbit 严重错误（如流损坏），不可恢复 bad()

流作为条件

int x;
while (std::cin >> x) {     // operator>> 返回流引用，流可转 bool（查 !fail()）
    std::cout << x;
}
// 循环退出：遇到 EOF 或读取失败
if (std::cin.eof()) std::cout << "正常结束";
else std::cout << "格式错误";

复位状态

std::cin.clear();           // 清除所有错误标志，恢复 good 状态
std::cin.ignore(10000, '\n');  // 丢弃缓冲区残留

clear() 用于从 failbit 恢复（如读错类型后清状态继续读）。

和 C 的区别

维度 C C++
状态查询 feof()/ferror() eof()/fail()/bad()/good()
错误区分 只有 EOF 和 error 两类 区分 fail（可恢复）和 bad（不可恢复）
错误码 errno（全局，易被覆盖） 状态标志在流对象内，不冲突
状态复位 无标准方式（clearerr） clear()
作为循环条件 while (fscanf(...)!=EOF) while (cin >> x) 更简洁

C 程序员的认知转变：

C 检查 IO 错误靠返回值 + feof/ferror，比较繁琐：

/* C：靠返回值和 feof/ferror 判断 */
int x;
while (fscanf(stdin, "%d", &x) == 1) {
    printf("%d\n", x);
}
if (feof(stdin)) printf("EOF\n");
else if (ferror(stdin)) printf("error\n");
else printf("format mismatch\n");   // fscanf 没读到完整 int

C++ 流对象自带状态，且流可直接当条件用，更简洁：

// C++：流当条件，状态在对象内
int x;
while (std::cin >> x) std::cout << x << "\n";
if (std::cin.eof()) std::cout << "EOF\n";
else if (std::cin.fail()) std::cout << "format mismatch\n";

关键区别：C++ 区分 failbit（格式不匹配，可恢复）和 badbit（流损坏，不可恢复）。C 的 ferror 不区分，恢复更难。

常见错误

  1. 读取失败后不清状态继续读：cin >> x 失败后流进入 fail 状态，后续所有 >> 直接返回失败，陷入死循环或读到垃圾。修正：失败后 cin.clear() 清状态 + cin.ignore() 丢弃坏输入，再继续。
  2. 用 !cin.eof() 作循环条件：while (!cin.eof()) { cin >> x; use(x); } —— EOF 是在尝试读取失败后才设置的，所以最后一次 use(x) 会用未定义的 x。修正：while (cin >> x) use(x);，把读取和判断合并。
  3. 混淆 fail() 和 bad()：bad() 是不可恢复错误（如设备损坏），fail() 是可恢复的（格式不匹配）。对 bad() 调 clear() 后流仍不可用（底层已坏）。

自测题

1. 选择题：输入 abc 时，std::cin >> x（x 是 int）后，cin 的状态是？ - A) goodbit - B) eofbit - C) failbit - D) badbit

答案

C) failbit。abc 不是整数，>> 解析失败，设置 failbit（可恢复错误）。不是 eof（没到文件尾），不是 bad（流没损坏）。可调 clear() 恢复。

2. 判断题：while (!std::cin.eof()) { std::cin >> x; process(x); } 是安全的读取循环。

答案

错误。这是经典 bug：EOF 标志在读取失败后才设置，所以当输入最后一个有效数据后，eof() 还是 false，循环再进一次，cin >> x 失败（这次才设 eof），但 process(x) 已经用未定义的 x 执行了。正确写法：while (std::cin >> x) process(x);，把读取和条件判断合并，失败时不进循环体。

3. 踩坑题：下面代码想"读错就跳过继续读"，但进入死循环，为什么？

int x;
while (true) {
    if (std::cin >> x) {
        std::cout << x;
    }
    // 失败了想跳过继续
}

（输入 abc）

答案

cin >> x 读 abc 失败，进入 fail 状态。之后循环里每次 cin >> x 都立即返回失败（流在 fail 状态时不读任何东西），且没清状态 → 死循环。修正：

if (std::cin >> x) { std::cout << x; }
else {
    if (std::cin.eof()) break;
    std::cin.clear();                    // 清错误状态
    std::cin.ignore(1000, '\n');         // 丢弃坏输入
}

4. 应用题：写一个健壮的"读整数"循环：从 cin 读整数直到 EOF，遇到非整数输入时打印提示并跳过继续，不崩溃不死循环。

答案 
int x;
while (true) {
    std::cout << "Enter int: ";
    if (std::cin >> x) {
        std::cout << "Got: " << x << "\n";
    } else if (std::cin.eof()) {
        break;                            // 正常结束
    } else {
        std::cout << "Not an int, skip\n";
        std::cin.clear();                 // 清 failbit
        std::cin.ignore(10000, '\n');     // 丢弃本行坏输入
    }
}

关键：失败时先 clear() 恢复流状态，再 ignore() 丢弃导致失败的输入，否则流卡在 fail 状态死循环。C 要用 fscanf 返回值 + 手动清缓冲区，更繁琐。

8.3

文件输入输出

本节讲什么

fstream 处理文件 IO：ifstream（读）、ofstream（写）、fstream（读写）。重点讲文件打开/关闭的 RAII、文件模式（in/out/app/trunc/binary）。C 程序员对应的是 fopen/fclose/模式字符串。

核心用法

打开与关闭

#include <fstream>
#include <string>

// 构造时打开
std::ifstream in("data.txt");        // 构造即打开
if (!in) { /* 打开失败 */ }          // 检查是否成功

std::string line;
while (std::getline(in, line))       // 逐行读
    std::cout << line << "\n";
// in 在作用域结束析构时自动 close，不用手动调

文件模式

模式 含义 C 对应
std::ios::in 读 "r"
std::ios::out 写 "w"
std::ios::app 追加（每次写到末尾） "a"
std::ios::ate 打开后定位到末尾 "a+" 类似
std::ios::trunc 打开时截断（清空） "w" 含此
std::ios::binary 二进制模式 "b" 
std::ofstream out("log.txt", std::ios::app);   // 追加模式
out << "new line\n";

std::ifstream bin("data.bin", std::ios::binary | std::ios::in);  // 二进制读

成员函数 open/close

std::ifstream f;
f.open("a.txt");      // 显式打开
// ...
f.close();            // 显式关闭（也可等析构）
f.open("b.txt");      // 同一对象可复用打开多个文件，但要先 close

和 C 的区别

维度 C (stdio) C++ (fstream)
打开 fopen("f","r") 返回 FILE* 构造 ifstream in("f")
关闭 手动 fclose(fp) RAII 析构自动关闭
忘关 泄漏 fd 不会（析构保证）
模式 字符串 "rb"/"w+" 枚举 binary|in
错误检查 返回 NULL 流对象可转 bool
异常安全 ❌ 出异常就泄漏 ✅ 栈展开自动析构

C 程序员最该体会的：RAII 自动关闭

C 的 FILE* 必须手动 fclose，异常或提前 return 时容易漏：

/* C：手动管理，异常路径易漏 fclose */
FILE* f = fopen("a.txt", "r");
if (!f) return;
// ... 处理 ...
if (error) return;        // 忘了 fclose！泄漏 fd
fclose(f);

C++ 的 fstream 析构自动关闭，无论正常返回还是异常，都不会泄漏：

// C++：RAII，析构自动关闭
void f() {
    std::ifstream in("a.txt");
    if (!in) return;
    // ... 处理 ...
    if (error) return;     // in 析构自动 close，不泄漏
    throw std::runtime_error("x");  // 异常路径也自动 close
}   // 正常退出也自动 close

这是 RAII 的经典范例——资源（文件句柄）的生命周期绑定到对象生命周期，编译器保证释放。

常见错误

  1. 打开后不检查是否成功：std::ifstream in("x.txt"); in >> data; —— 文件不存在时 in 处于失败状态，>> 读不到东西。修正：if (!in) { /* 处理错误 */ }。
  2. 同一 fstream 对象重复 open 前 没 close：f.open("a"); f.open("b"); —— 第二次 open 会失败（已关联文件）。修正：先 f.close() 或直接用新对象。
  3. ofstream 默认 trunc 误清空文件：std::ofstream out("f"); 默认是 out|trunc，会清空已有文件！想保留内容用 std::ios::app。这是 C 也有但容易忘的坑（C 的 "w" 也清空）。

自测题

1. 选择题：下面哪种方式打开文件不会清空已有内容？ - A) std::ofstream out("f"); - B) std::ofstream out("f", std::ios::out); - C) std::ofstream out("f", std::ios::app); - D) std::ofstream out("f", std::ios::trunc);

答案

C。app（追加）模式在末尾写，不清空。A/B/D 都会清空——A 默认是 out|trunc；B 显式 out 隐含 trunc；D 显式 trunc。要保留内容追加用 app，要读写保留用 in|out。

2. 判断题：std::ifstream in("nonexistent.txt"); 后，in >> x 会抛异常。

答案

错误。fstream 默认不抛异常，打开失败只是让流进入失败状态，>> 静默失败（不读数据，x 不变）。要检查 if (!in)。如果想让它抛异常，要调 in.exceptions(...) 设置异常掩码，但默认不抛。这与许多新手的直觉相反。

3. 踩坑题：下面函数在异常发生时会泄漏什么？C++ 风格如何避免？

FILE* f = fopen("a.txt", "w");
FILE* g = fopen("b.txt", "w");
do_work();          // 可能抛异常/出错返回
fclose(g);
fclose(f);
答案

do_work 出错返回或抛异常（C++ 场景）时，两个 fclose 都不执行，泄漏两个文件句柄。C++ 用 fstream + RAII 彻底避免：

void f() {
    std::ofstream f("a.txt");
    std::ofstream g("b.txt");
    do_work();          // 抛异常时，g 先析构 close，再 f 析构 close
}                       // 正常也自动 close

析构按构造逆序自动执行，无论正常还是异常路径，都不泄漏。这是 RAII 对 C 手动管理的根本优势。

4. 应用题：写一个"安全追加日志"函数：以追加模式打开日志文件，写一条带时间戳的日志，保证任何情况下都不丢 fd、不清空已有日志。

答案 
#include <fstream>
#include <chrono>
#include <iomanip>

void log(const std::string& file, const std::string& msg) {
    std::ofstream out(file, std::ios::app);   // app 模式：追加不清空
    if (!out) return;                          // 打开失败静默返回（或抛异常）
    auto t = std::chrono::system_clock::to_time_t(
        std::chrono::system_clock::now());
    out << std::put_time(std::localtime(&t), "%F %T") << " " << msg << "\n";
    // out 析构自动 close，异常也安全
}

app 保证不清空；ofstream RAII 保证 fd 不泄漏；析构刷新缓冲（写盘）。C 版要手动 fclose + goto cleanup 处理异常路径，繁琐且易错。

8.4

string 流

本节讲什么

sstream：在内存 string 上做格式化读写。istringstream（从 string 读）、ostringstream（向 string 写）、stringstream（双向）。C 程序员对应的是 sscanf/sprintf/snprintf。

核心用法

istringstream：字符串解析

#include <sstream>
#include <string>

std::string line = "Alice 30 55000.5";
std::istringstream iss(line);
std::string name;
int age;
double salary;
iss >> name >> age >> salary;     // 按空白分割，自动类型转换
// name="Alice", age=30, salary=55000.5

逐行读取后逐单词解析的经典模式：

std::string line;
while (std::getline(in, line)) {       // 整行读
    std::istringstream iss(line);      // 绑定到这一行
    std::string word;
    while (iss >> word) {              // 单词解析
        // 处理每个单词
    }
}

ostringstream：字符串格式化

std::ostringstream oss;
oss << "name=" << name << ", age=" << age << ", salary=" << std::fixed << salary;
std::string result = oss.str();        // 取出结果字符串

stringstream：双向

std::stringstream ss;
ss << 42;                              // 写
int x;
ss >> x;                               // 读回（注意读写指针位置）

和 C 的区别

维度 C (sprintf/sscanf) C++ (sstream)
格式化写入 sprintf(buf, "%s=%d", s, n) ostringstream << s << "=" << n
解析读取 sscanf(buf, "%s %d", s, &n) istringstream >> s >> n
缓冲区管理 手动 char 数组，易溢出 自动管理 string，不溢出
类型安全 ❌ 格式串手动对齐 ✅ 编译器按类型重载
大小限制 固定数组，sprintf 溢出 UB 自动扩容
复用 每次新 buf 流对象可复用

C 程序员最该体会的：

  1. 不溢出：C 的 sprintf 写入固定 char 数组，超出长度就溢出 UB（经典安全漏洞）。snprintf 改进了但要手动算大小。ostringstream 内部用 string 自动扩容，永不溢出。
/* C：sprintf 溢出风险 */
char buf[16];
sprintf(buf, "%s", long_string);   // 超过 16 字节就溢出 UB

// C++：ostringstream 自动扩容，不溢出
std::ostringstream oss;
oss << long_string;                // 想多长多长
std::string s = oss.str();

  1. 类型安全：sscanf("%d", &s)（s 是 string）编译过但运行崩；istringstream >> s（s 是 string）和 >> n（n 是 int）按类型选 operator，不会错。

  2. 逐行解析更自然：C 要 strtok（破坏原串、非重入）或手动指针遍历；C++ 用 istringstream >> word 按空白分割，不破坏原串。

常见错误

  1. stringstream 复用前不清空：ss << 1; ss >> x; ss << 2; ss >> y; —— 第二次写前没清，读位置和内容混乱。修正：复用要 ss.clear()（清状态）+ ss.str("")（清内容）。
  2. istringstream 绑定到空 string 或读完没检查：iss >> x 读到末尾失败，x 未赋值却继续用。修正：if (iss >> x)。
  3. 用 ostringstream 拼接大字符串性能差：频繁 << 小片段、再 str() 拷贝，比直接 string += 慢。建议：大量拼接用 string + reserve，需要格式化（数字、对齐）才用 ostringstream。

自测题

1. 选择题：下面代码输出什么？

std::istringstream iss("10 20 30");
int a, b;
iss >> a >> b;
std::cout << a << b;
  • A) 1020
  • B) 102030
  • C) 30
  • D) 未定义
答案

A) 1020。>> 按空白分割，先读 10 给 a，再读 20 给 b，30 仍在流里未读。输出 a << b 拼接为 "1020"。

2. 判断题：std::ostringstream oss; oss << 3.14; std::string s = oss.str(); 得到的 s 内容是 "3.14"。

答案

正确（默认格式下）。operator<< 对 double 用默认浮点格式，3.14 输出为 "3.14"。注意默认精度是 6 位有效数字，所以 3.14159265 会输出 "3.14159"。要控制格式用 std::fixed/std::setprecision。

3. 踩坑题：下面代码想复用 stringstream 读多个数据，但第二次读不到，为什么？

std::stringstream ss;
ss << "1 2 3";
int a; ss >> a;        // a=1
ss << "4 5";           // 想追加
int b; ss >> b;        // b 想是 4，但读到 2
答案

两个问题：1) ss << "4 5" 是追加写入，但读写指针在读完 1 后停在 1 后面，"4 5" 被追加到末尾（"1 2 34 5"），而读指针继续读 2；2) 写入和读取共用一个位置指针，混乱。正确做法：要么用两个流（一个 istringstream 一个 ostringstream），要么复用时 clear+str 重置：

ss.clear();       // 清状态
ss.str("4 5");    // 重置内容
int b; ss >> b;   // b=4

4. 应用题：用 istringstream 解析 CSV 行 "Alice,30,55000.5"（逗号分隔），提取姓名、年龄、薪资。提示：用 getline 配合分隔符。

答案 
#include <sstream>
#include <string>

std::string line = "Alice,30,55000.5";
std::istringstream iss(line);
std::string name, age_str, salary_str;
std::getline(iss, name, ',');        // 读到逗号为止
std::getline(iss, age_str, ',');
std::getline(iss, salary_str);       // 最后一个不用分隔符
int age = std::stoi(age_str);
double salary = std::stod(salary_str);

技巧：getline(流, string, 分隔符) 可指定分隔符（默认 '\n'），用 ',' 分割 CSV。比 C 的 strtok（破坏原串、非线程安全）或手动 strchr 干净得多。复杂 CSV（字段含引号/逗号）建议用专门库。

void process_file(const std::string &path) {
    std::ifstream in(path);
    if (!in) { /* 错误处理 */ return; }
    std::string line;
    while (std::getline(in, line)) {
        // 处理 line
    }
}   // in 在这里析构，自动关闭文件

和 C 的 FILE* 相比有什么优势？

答案与复习指引

优势： 1. RAII 自动关闭：ifstream 析构自动调用 close()，即使异常也不泄漏文件描述符 2. 类型安全：>> 根据变量类型自动解析，不像 fscanf 要手写格式符 3. 错误检查更直观：if (!in) 或 if (in >> x) 检查流状态

C 的写法： 需要 FILE *fp = fopen(...); ... fclose(fp);，忘记 fclose 或异常路径不 fclose 会泄漏 fd。
