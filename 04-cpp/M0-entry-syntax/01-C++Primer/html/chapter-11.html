11.1

核心类型

本节讲什么

C++ 标准库的关联容器：按键（key）存储和查找，而非按位置。分两类——有序（红黑树，O(log n)）和无序（哈希表，平均 O(1)）。C 没有任何关联容器，map/set 全靠手写——这是 C 程序员的重大红利。

核心用法

两大类八种容器

类别 容器 底层 查找 是否允许重复键
有序 map 红黑树 O(log n) ❌
有序 set 红黑树 O(log n) ❌
有序 multimap 红黑树 O(log n) ✅
有序 multiset 红黑树 O(log n) ✅
无序 unordered_map 哈希表 平均 O(1) ❌
无序 unordered_set 哈希表 平均 O(1) ❌
无序 unordered_multimap 哈希表 平均 O(1) ✅
无序 unordered_multiset 哈希表 平均 O(1) ✅

map 基本用法

#include <map>
std::map<std::string, int> word_count;
word_count["hello"] = 1;          // 下标访问（key 不存在则插入 0）
word_count["world"] = 2;
word_count["hello"]++;            // 改值

// 遍历（有序，按键排序）
for (const auto& [key, val] : word_count)   // C++17 结构化绑定
    std::cout << key << ": " << val << "\n";

set 基本用法

#include <set>
std::set<int> s = {3, 1, 4, 1, 5};   // 自动去重排序：{1,3,4,5}
s.insert(2);
s.count(3);    // 1（存在）
s.count(6);    // 0（不存在）

有序 vs 无序怎么选

  • 需要按键顺序遍历 → 有序（map/set）
  • 只要快速查找，不关心顺序 → 无序（unordered_map，通常更快）
  • 自定义类型作键：有序要定义 <；无序要定义 == 和哈希函数

和 C 的区别

维度 C C++
关联容器 ❌ 无标准库 map/set/multimap/multiset + 无序版本
哈希表 手写或第三方（uthash 等） unordered_map
红黑树 手写（极繁琐） map/set
查找复杂度 取决于手写实现 有序 O(log n)，无序 O(1)
内存管理 手动 RAII

C 程序员最该体会的：

C 里"按键查找"要手写哈希表或二分查找数组，几十到上百行易错代码：

/* C：手写简单哈希表（极简版，真实场景更复杂） */
struct Entry { char* key; int val; struct Entry* next; };
struct Entry* table[BUCKET_SIZE];
int lookup(const char* key) {
    unsigned h = hash(key) % BUCKET_SIZE;
    for (struct Entry* e = table[h]; e; e = e->next)
        if (strcmp(e->key, key) == 0) return e->val;
    return -1;   // 没找到
}
// 还要写 insert、扩容、释放...几百行

C++ 一行声明，现成可用：

std::unordered_map<std::string, int> m;
m["key"] = 42;        // 插入
int v = m["key"];     // 查找
// 析构自动释放

这是从"造轮子"到"用现成"的飞跃，省下大量易错的基础设施代码。

常见错误

  1. map::operator[] 副作用插入：if (m["x"] == 0) —— 即使 "x" 不存在，[] 也会插入默认值 0。导致意外的空条目。修正：查找用 m.find("x") 或 m.count("x")，不要用 [] 纯查找。
  2. 无序容器用自定义类型忘了提供哈希函数：unordered_map<MyType, int> —— MyType 没有默认哈希，编译错误。修正：特化 std::hash<MyType> 或传自定义哈希器。
  3. 混淆 multimap 的 []：multimap 不支持 []（一键多值，无法确定哪个）。要用 insert/equal_range。

自测题

1. 选择题：下面哪个查找 std::unordered_map 不会产生"副作用插入"？ - A) m["x"] - B) m.at("x") - C) m.find("x") - D) B 和 C

答案

D。operator[] 在 key 不存在时会插入默认值（副作用）；at 在不存在时抛 out_of_range，不插入；find 返回 end()，不插入。所以纯查找应避免 []，用 at（要异常处理）或 find。

2. 判断题：std::map 的元素是按键排序存储的。

答案

正确。map/set 基于红黑树，元素按键有序存储，遍历得到排序序列，查找 O(log n)。unordered_map/unordered_set 基于哈希表，无序，查找平均 O(1)。这是有序与无序容器的根本区别。

3. 踩坑题：下面代码统计单词出现次数，但结果里多了很多计数为 0 的单词，为什么？

std::map<std::string, int> count;
for (auto& w : all_words) {
    if (count[w] == 0)   // 检查是否第一次出现
        count[w] = 1;
    else
        ++count[w];
}
答案

count[w] 在 w 不存在时会插入默认值 0，所以每次检查都产生一个条目。结果所有单词都有条目，包括只检查过一次的（值为 0 然后被设为 1，看似没问题？）。等等，重新看：w 不存在时 count[w] 插入 0，==0 为真，设为 1——逻辑对。但问题是 count[w] 已插入条目，else 分支的 ++count[w] 再加。实际逻辑没错，但风格差——用 [] 检查本就插入。更优写法：++count[w]; 一行（不存在时插入 0 再 ++ 成 1）。原写法虽对但啰嗦，且依赖 [] 的副作用，易让读者困惑。

4. 应用题：统计一段文本中每个单词的出现次数，按字母顺序输出。选什么容器？写出关键代码。

答案 
#include <map>
#include <string>
#include <iostream>

std::map<std::string, int> count;
std::string word;
while (std::cin >> word) ++count[word];   // map 自动处理插入和计数

for (const auto& [w, n] : count)          // 按字母序遍历（map 有序）
    std::cout << w << ": " << n << "\n";

选 std::map 因为：1) 按键（单词）排序输出——map 有序；2) 查找/插入 O(log n) 足够；3) ++count[word] 一行完成"不存在则插入 0 再 ++"。C 版要手写哈希表 + 排序，上百行。这是 map 的经典应用。

11.2

pair 类型

本节讲什么

std::pair<T1, T2>：持有两个对象的简单模板，是 map 元素的实际类型（key-value 对）。也常用于函数返回两个值。C 程序员可类比为"只有两个成员的 struct"，但 pair 是模板、可复用。

核心用法

创建与访问

#include <utility>
std::pair<std::string, int> p{"key", 42};
p.first;        // "key"
p.second;       // 42

// make_pair 推导类型
auto p2 = std::make_pair("key", 42);   // pair<const char*, int>

// C++11 列表初始化
std::pair<int, double> p3{1, 2.5};

map 的元素就是 pair

std::map<std::string, int> m = {{"a", 1}, {"b", 2}};
for (const auto& p : m) {
    std::cout << p.first << ": " << p.second;   // pair 的 first/second
}
// C++17 结构化绑定更清晰
for (const auto& [key, val] : m) {
    std::cout << key << ": " << val;
}

作返回值（返回两个值）

std::pair<bool, int> find(int key) {
    auto it = data.find(key);
    return {it != data.end(), it == data.end() ? -1 : it->second};
    // 返回 {找到?, 值}
}
auto [found, val] = find(42);   // C++17 解构

和 C 的区别

维度 C C++
两个值的组合 手写 struct（每个场景一个） pair<T1,T2> 模板复用
作返回值 结构体或输出参数 pair + 结构化绑定
map 元素 手写 Entry {key,val} map 元素就是 pair
标准库支持 ❌ std::pair/make_pair

C 程序员的体会：

C 里"返回两个值"要么手写 struct（每种组合一个），要么用输出参数：

/* C：返回两个值要手写 struct 或输出参数 */
struct Result { bool found; int val; };
struct Result find(int key) { ... }
// 或用输出参数：
int find(int key, int* found);   // 丑陋

C++ 的 pair 是现成的"二元组"，配合 C++17 结构化绑定很优雅：

auto [found, val] = find(42);   // 一行解构两个返回值

常见错误

  1. 混淆 first/second：pair 没有具名字段，p.first/p.second 易记混。建议：C++17 用结构化绑定 auto [k, v] = p 给具名，更清晰。
  2. make_pair 与显式类型不一致：make_pair("x", 1) 推导出 pair<const char*, int>，若目标是 pair<string,int> 要转换。建议：直接 pair<string,int>{"x",1} 或 make_pair(string("x"), 1)。
  3. pair 排序默认按 first 然后 second：std::sort 对 pair 默认按 first 字典序，first 相同按 second。若要别的序要自定义比较器。

自测题

1. 选择题：std::map<K,V> 的元素类型是？ - A) struct { K key; V value; } - B) std::pair<const K, V> - C) std::pair<K, V> - D) std::tuple<K, V>

答案

B。map 的元素是 pair<const K, V>——key 是 const（map 依赖 key 排序，改 key 会破坏树结构），value 可改。遍历 map 得到 pair<const K,V>&，改 p.second（value）可以，改 p.first（key）编译错误。

2. 判断题：auto [a, b] = some_pair;（C++17 结构化绑定）能解构 pair。

答案

正确。C++17 结构化绑定能解构 pair/tuple/数组/聚合体。auto [a, b] = p 把 p.first 绑到 a、p.second 绑到 b，比 p.first/p.second 清晰得多。这是现代 C++ 处理多返回值的标准方式。

3. 踩坑题：下面代码想改 map 中的 value，编译报错，为什么？

std::map<std::string, int> m = {{"a",1}};
for (auto& p : m) {       // 注意 auto&
    p.first = "b";        // 想改 key
    p.second = 2;
}
答案

p.first 是 const（map 的元素是 pair<const K, V>），给 const key 赋值编译错误。map 的 key 不能改（改了破坏红黑树排序），只能删了重新插。修正：删了重插：

int val = m["a"]; m.erase("a"); m["b"] = val;

或者只改 value：for (auto& [k, v] : m) v = 2;（key 仍 const，v 可改）。

4. 应用题：写一个函数同时返回"最小值和最大值"，用 pair + 结构化绑定，对比 C 的输出参数写法。

答案 
#include <utility>
#include <algorithm>

std::pair<int, int> minmax(const std::vector<int>& v) {
    auto [lo, hi] = std::minmax_element(v.begin(), v.end());
    return {*lo, *hi};
}
auto [mn, mx] = minmax(v);   // 一行解构

C 版要输出参数：

void minmax(const int* v, size_t n, int* mn, int* mx);   // 丑陋
int mn, mx; minmax(arr, n, &mn, &mx);

pair + 结构化绑定让"返回多值"像单返回值一样自然，这是现代 C++ 相对 C 的表达力提升。

11.3

特有操作

本节讲什么

关联容器（map/set）相对顺序容器的特有操作：插入（insert/emplace）、下标访问（map::operator[]/at）、查找（find/count/lower_bound/equal_range）。重点是"下标访问会副作用插入"这个坑。

核心用法

插入

std::map<std::string, int> m;

// insert：插入 pair
m.insert({"key", 1});
m.insert(std::make_pair("key2", 2));

// emplace：原地构造（避免临时 pair）
m.emplace("key3", 3);

// insert 返回 pair<iterator, bool>：bool 表示是否插入成功（key 已存在则 false）
auto [it, inserted] = m.insert({"key", 99});
if (!inserted) std::cout << "key 已存在，未覆盖";

下标访问（仅 map，非 multimap）

m["key"];        // 不存在则插入默认值（副作用！）
m.at("key");     // 不存在则抛 out_of_range（不插入）

m["key"] = 5;    // 不存在则插入 5，存在则覆盖

查找（不插入）

auto it = m.find("key");    // 返回迭代器，没找到返回 m.end()
size_t n = m.count("key");  // 0 或 1（multimap 可能 >1）

// 有序容器的范围查找
auto lo = m.lower_bound("b");   // 第一个 >= "b"
auto hi = m.upper_bound("d");   // 第一个 > "d"
auto [lo2, hi2] = m.equal_range("c");  // 等于 "c" 的范围

删除

m.erase("key");             // 按 key 删，返回删除数量
m.erase(it);                // 按迭代器删
m.erase(m.begin(), m.end()); // 范围删

和 C 的区别

维度 C C++
插入查重 手写（先查再插） insert 原子返回是否成功
下标访问 手写查找 + 默认值逻辑 [] 一步（但注意副作用）
范围查找 手写遍历 lower_bound/upper_bound/equal_range
删除 手写链表节点操作 erase

C 程序员的体会：

C 里"插入并查重"要先查找再决定插不插，两步非原子（多线程要加锁）：

/* C：先查后插，非原子 */
if (lookup(key) == -1) {        // 查
    insert(key, val);           // 插
}
// 两步之间可能被其他线程插入，需加锁

C++ 的 insert 一步原子完成"查重+插入"，返回是否成功：

auto [it, ok] = m.insert({key, val});
if (!ok) { /* 已存在，没插 */ }
// 原子操作，无需手动加锁（单线程操作内）

常见错误

  1. 用 [] 纯查找导致副作用插入：if (m["x"] == 0) 即使 "x" 不存在也插入 0。修正：纯查找用 find/count/at。
  2. 以为 insert 会覆盖已存在的 key：m.insert({"x", 1}) 后 m.insert({"x", 2}) —— 第二次 insert 不覆盖（key 已存在，insert 失败，值仍 1）。要覆盖用 [] 或 insert_or_assign（C++17）。
  3. multimap 用 []/at：multimap 一键多值，[]/at 无法确定哪个，编译错误。multimap 要用 equal_range/find。

自测题

1. 选择题：std::map<int,int> m; m[1]=10; m[1]=20; 后 m[1] 的值是？ - A) 10 - B) 20 - C) 30 - D) 编译错误

答案

B) 20。m[1]=10 插入 1→10；m[1]=20 key 1 已存在，[] 返回引用，赋值覆盖为 20。注意这与 insert 不同——insert 不覆盖已存在的 key，[] 赋值会覆盖。

2. 判断题：m.insert({1, 99}) 在 m 中已有 key 1 时会覆盖原值。

答案

错误。insert 在 key 已存在时不插入也不覆盖，返回 {existing_iterator, false}。要覆盖用 m[1]=99 或 m.insert_or_assign(1, 99)（C++17）。这是 insert 与下标赋值的关键区别——insert 尊重已有元素，下标赋值覆盖。

3. 踩坑题：下面代码想统计"从未出现的 key"，但结果不对，为什么？

std::map<std::string, int> seen;
for (auto& w : words) {
    if (seen[w] == 0) {        // 检查是否没见过
        std::cout << "new: " << w;
    }
    seen[w] = 1;
}
答案

seen[w] 在 w 不存在时插入 0，于是 ==0 为真打印"new"，然后设为 1。看似对，但问题：每个 w 第一次访问都插入 0，第二次访问 seen[w] 是 1，不打印。逻辑其实是对的！但风格依赖 [] 的副作用插入，易让读者困惑，且 map 会膨胀到所有不同单词数。更清晰写法用 find：

if (seen.find(w) == seen.end()) {   // 明确"没见过"
    std::cout << "new: " << w;
}
seen[w] = 1;

不依赖副作用，意图清晰。

4. 应用题：用 map 实现"单词首次出现位置"记录：遍历单词列表，记录每个单词第一次出现的下标。要求不产生多余条目。

答案 
std::map<std::string, size_t> first_pos;
for (size_t i = 0; i < words.size(); ++i) {
    auto [it, inserted] = first_pos.emplace(words[i], i);
    // emplace 在 key 已存在时不插入（不覆盖），返回是否成功
    // 只有第一次遇到才记录位置
}

关键用 emplace/insert——它们在 key 已存在时不覆盖，正好符合"只记第一次"。若用 first_pos[words[i]] = i 会覆盖成最后一次位置，错。emplace 返回的 inserted bool 还能判断是否首次。C 要手写查找+插入两步。

章节自测

Q1map operator[] 副作用
std::map<std::string, int> m;
m["apple"] = 5;
std::cout << m["banana"];  // A
std::cout << m.size();     // B

A 和 B 分别输出什么？operator[] 有什么副作用？

答案与复习指引

A: 0（"banana" 不存在，operator[] 会插入一个默认构造的值 0 并返回） B: 2（m 现在有 "apple" 和 "banana" 两个元素！）

副作用： operator[] 在 key 不存在时会自动插入（值初始化）。如果只是想查找，应该用 find() 或 at()（后者不存在时抛异常）。这个副作用在性能敏感代码中是隐患——每次查找都可能触发插入。

复习： → 特有操作

Q2map vs unordered_map
std::map<int, std::string> m;
std::unordered_map<int, std::string> um;
// 两者都插入 10000 个元素
for (int i = 0; i < 10000; ++i) {
    m[i] = std::to_string(i);
    um[i] = std::to_string(i);
}

map 和 unordered_map 的查找复杂度分别是什么？底层实现是什么？

答案与复习指引
map unordered_map
底层 红黑树 哈希表
查找 O(log n) O(1) 均摊（最坏 O(n)）
有序 是（按 key 排序遍历） 否
内存 节点分散，cache 不友好 桶数组+链表，稍好

HFT 场景： 小规模/需要有序遍历用 map；大规模纯查找用 unordered_map + reserve 避免 rehash。

复习： → 核心类型

Q3set 去重
std::vector<int> v = {3, 1, 4, 1, 5, 9, 2, 6, 5, 3, 5};
std::set<int> s(v.begin(), v.end());
std::cout << s.size();
for (auto x : s) std::cout << " " << x;
