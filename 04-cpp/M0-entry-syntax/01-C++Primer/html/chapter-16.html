章节摘要

模板与泛型编程：函数模板、类模板、非类型模板参数、模板实参推断、可变参数模板、完美转发。

和 C 的区别

C C++
void* + 函数指针泛型 模板（类型安全 + 编译期生成）
宏 #define MAX(a,b) template<class T> T max(T a, T b)
无泛型容器 vector<T>/map<K,V>
__VA_ARGS__ 可变参数模板 template<class... Args>
16.1

定义模板

本节讲什么

本节讲解 C++ 模板的基础——函数模板和类模板：如何用 template <typename T> 定义泛型函数和泛型类，编译期如何根据使用实例化出具体版本，以及模板的编译模型（为什么模板代码通常要放在头文件里）。这是 C++ 泛型编程的起点，也是 C++ 相对 C 最强大的特性之一——编译期多态 + 类型安全 + 零运行开销。

一句话定位：模板 = "写一份代码，编译器为每种类型生成一份定制版本"。它是 void* 和宏的安全替代品，既类型安全又能内联优化。

核心用法

1. 函数模板

template <typename T>
T maximum(const T &a, const T &b) {
    return a > b ? a : b;     // 要求 T 支持 operator>
}
int main() {
    std::cout << maximum(3, 7) << "\n";          // T=int，调用 maximum<int>
    std::cout << maximum(3.14, 2.71) << "\n";    // T=double
    std::cout << maximum(3, 7.0) << "\n";        // ❌ 推断冲突：T 既是 int 又是 double
    std::cout << maximum<double>(3, 7.0) << "\n";// ✅ 显式指定 T=double，3 转 double
}

关键点： - template <typename T> 声明一个类型参数 T（typename 和 class 等价，但推荐 typename） - 调用时编译器从实参推断 T 的类型，生成对应版本（实例化） - 模板代码隐式要求 T 支持所用操作（这里是 operator>），不支持则编译错误 - 推断冲突时需显式指定模板实参：maximum<double>(3, 7.0)

2. 类模板

template <typename T>
class Stack {
public:
    void push(const T &v) { data_.push_back(v); }
    T pop() {
        T v = data_.back();
        data_.pop_back();
        return v;
    }
    bool empty() const { return data_.empty(); }
private:
    std::vector<T> data_;
};
int main() {
    Stack<int> si;        // ✅ 类模板必须显式指定类型（不像函数模板能推断）
    si.push(1); si.push(2);
    std::cout << si.pop() << "\n";    // 2
    Stack<std::string> ss;
    ss.push("hello");
}

关键点： - 类模板必须显式指定模板实参（Stack<int>），编译器不从构造函数推断（C++17 的 CTAD 例外，见下） - 类模板名 Stack 本身不是类型，Stack<int> 才是类型——在类模板内部，Stack 可简写（指代 Stack<T>），外部必须写全 - 类模板的成员函数也是模板，定义在类外时要带完整模板声明： cpp template <typename T> void Stack<T>::push(const T &v) { data_.push_back(v); }

3. C++17 类模板参数推断（CTAD）

C++17 起，若构造函数能推断出模板参数，可省略 <T>：

template <typename T>
struct Point {
    T x, y;
    Point(T x_, T y_) : x(x_), y(y_) { }
};
Point p(3, 4);        // C++17：推断 Point<int>（等价于 Point<int> p(3,4)）
Point q(3.0, 4.0);    // Point<double>

但许多场景仍需显式指定（如 Stack，因为构造函数不涉及 T）。

4. 模板实例化（编译期）

模板本身不是代码，是"代码生成器"。编译器看到 maximum(3, 7) 时：

  1. 推断 T = int
  2. 实例化：把模板里的 T 替换为 int，生成一份 maximum<int> 的真实代码
  3. 编译这份生成的代码

实例化是按需的——只有实际用到的类型组合才会生成代码。没用到的 maximum<std::string> 不会生成（即使 std::string 没有 operator>，也不会报错，因为根本没实例化）。

源代码                    编译器实例化             最终二进制
template<typename T>      maximum<int>(...)        maximum<int> 代码
T maximum(...)  ────┬──→ maximum<double>(...) ──→ maximum<double> 代码
                    └──→ (未用类型不生成)

5. 模板的编译模型（为什么放头文件）

模板代码通常必须放在头文件里，原因：

  • 模板实例化发生在使用它的那个 .cpp 文件中
  • 编译器需要看到模板的完整定义才能生成实例化代码
  • 若模板定义在 .cpp 里，其他 .cpp 包含头文件只能看到声明，无法实例化 → 链接错误
// stack.h
template <typename T>
class Stack {
public:
    void push(const T &v);     // 声明
    T pop();
private:
    std::vector<T> data_;
};
// ❌ 错误：定义放 .cpp
// stack.cpp: template<typename T> void Stack<T>::push(...) { ... }
// main.cpp: Stack<int> s; s.push(1);  → 链接错误：找不到 Stack<int>::push

// ✅ 正确：定义放头文件
// stack.h:
template <typename T>
void Stack<T>::push(const T &v) { data_.push_back(v); }

例外：可以在 .cpp 里显式实例化（template class Stack<int>;），让编译器为特定类型生成代码。但泛型库通常不用这招，直接放头文件。

6. 模板的两阶段检查

模板代码分两阶段检查：

  1. 定义阶段：检查与模板参数无关的错误（语法、拼写、未声明的名字）
  2. 实例化阶段：检查与模板参数相关的错误（T 是否支持 operator>）
template <typename T>
void f(T x) {
    y = x;          // ❌ 第一阶段：y 未定义（不依赖 T）
    x.nonexist();   // 第一阶段不报（依赖 T），第二阶段（实例化时）若 T 无 nonexist 才报
}

这就是为什么模板错误信息常常又长又深——要到实例化时才暴露依赖 T 的错误。

和 C 的区别

C 没有模板，泛型编程只能靠 void* 或宏——都不类型安全：

维度 C（void* + 宏） C++ 模板
类型安全 无（void* 任意转换） 编译期检查
性能 函数指针间接调用，难内联 每类型独立代码，可内联
错误时机 运行期崩溃 编译期错误
代码膨胀 无（一份代码） 每类型一份（按需生成）
抽象能力 弱（无法表达"T 要支持某操作"） 强（概念、SFINAE）

C 用 void* 实现泛型栈（对比）

// C：void* 实现泛型栈——不类型安全
struct Stack {
    void *data[100];
    int top;
};
void push(struct Stack *s, void *v) { s->data[s->top++] = v; }
void *pop(struct Stack *s) { return s->data[--s->top]; }
// 用：
struct Stack s = {0};
int x = 42;
push(&s, &x);            // 存的是 int* 的地址
char *str = "hello";
push(&s, str);           // 存的是 char*——和 int* 混在一起！
int *p = (int*)pop(&s);  // ❌ 取出 char* 强转 int*，运行期崩溃

// C++：模板实现——类型安全
template <typename T>
class Stack {
    std::vector<T> data_;
public:
    void push(const T &v) { data_.push_back(v); }
    T pop() { T v = data_.back(); data_.pop_back(); return v; }
};
Stack<int> si;           // 只能存 int
si.push(42);
si.push("hello");        // ❌ 编译错误：const char* 不能转 int——编译期挡住

C 的 void* 栈把不同类型指针混存，运行期崩溃；C++ 模板栈每种类型独立，编译期就挡住类型错误。

HFT 视角：模板的内联能力是热路径性能关键。std::sort 模板版比 C 的 qsort 快几倍——因为 qsort 通过函数指针调比较函数（无法内联），而 std::sort 的比较器是模板参数，编译器完全内联，省去每次调用的间接跳转 + 参数压栈。这是 C++ 在数值计算上常胜 C 的核心原因之一。

常见错误

错误 1：模板定义放 .cpp → 链接错误

// stack.h
template <typename T> class Stack { void push(const T&); };
// stack.cpp
template <typename T> void Stack<T>::push(const T &v) { /*...*/ }
// main.cpp
Stack<int> s; s.push(1);   // ❌ undefined reference to Stack<int>::push

修复：把模板成员函数定义放头文件，或显式实例化。这是模板新手第一大坑。

错误 2：模板参数 T 不支持所需操作

template <typename T>
T maximum(const T &a, const T &b) { return a > b ? a : b; }
struct Point { int x, y; };    // 没有 operator>
maximum(Point{1,2}, Point{3,4});   // ❌ 实例化时报错：no match for operator>

错误信息可能很深，但核心是 T 不满足模板隐式要求。修复：给 Point 重载 operator>，或用 C++20 概念（concept）明确要求。

错误 3：类模板名当类型用

template <typename T> class Stack { /*...*/ };
Stack s;            // ❌ Stack 不是类型，Stack<T> 才是
Stack<int> s;       // ✅

在类模板内部 Stack 可简写（指代 Stack<T>），但外部必须写全 Stack<T>。

错误 4：函数模板实参推断冲突

template <typename T>
T maximum(const T &a, const T &b) { return a > b ? a : b; }
maximum(3, 7.0);    // ❌ T 既是 int 又是 double

修复：显式指定 maximum<double>(3, 7.0)，或定义两个类型参数的版本。

自测题

1. 选择题：以下关于模板实例化的说法，正确的是？

A. 模板定义时编译器就生成所有类型的代码 B. 模板只有被使用（调用/实例化）时才生成对应类型的代码 C. 模板代码放在 .cpp 文件里，其他文件 include 头文件就能用 D. 模板实例化发生在链接期

答案

B。模板是"代码生成器"，按需实例化——只有实际用到的类型组合才生成代码。这也解释了为什么没用到的类型即使不满足模板要求也不报错（没实例化）。实例化在编译期，不是链接期；模板定义通常放头文件（C 错）。

2. 判断题：类模板可以像函数模板那样，让编译器从构造函数实参推断模板参数（无需写 <T>）。

答案

部分对（C++17 起）。C++17 的 CTAD（Class Template Argument Deduction）允许在构造函数能推断时省略 <T>，如 std::pair p(1, 2.0) 推断为 pair<int,double>。但许多场景构造函数不涉及 T（如 Stack 的默认构造），仍需显式 Stack<int>。所以不能一概而论。

3. 踩坑题：以下代码哪里有问题？

// vec.h
template <typename T>
class Vec {
public:
    void push(const T &);
    T get(int);
private:
    T *data_;
};
// vec.cpp
#include "vec.h"
template <typename T>
void Vec<T>::push(const T &v) { /* ... */ }
template <typename T>
T Vec<T>::get(int i) { return data_[i]; }
// main.cpp
#include "vec.h"
int main() {
    Vec<int> v;
    v.push(42);
}
答案

模板成员函数定义放在 vec.cpp 里，main.cpp 包含 vec.h 只能看到声明，无法实例化 Vec<int>::push → 链接错误（undefined reference）。

修复方案二选一： 1. 把成员函数定义移到 vec.h（推荐，泛型库标准做法） 2. 在 vec.cpp 末尾显式实例化：template class Vec<int>;（只对已知类型有效，失去泛型性）

4. 应用题：用模板实现一个泛型 Pair<T1, T2>，存储两个可能不同类型的值，提供 first()/second() 访问。要求能 Pair<int, double> p(1, 2.0); 使用。

答案 
template <typename T1, typename T2>
class Pair {
public:
    Pair(const T1 &a, const T2 &b) : first_(a), second_(b) { }
    const T1& first() const { return first_; }
    const T2& second() const { return second_; }
private:
    T1 first_;
    T2 second_;
};
// 用法：
Pair<int, double> p(1, 2.0);
std::cout << p.first() << ", " << p.second();   // 1, 2.0
// C++17 CTAD：Pair p(1, 2.0);  也可

要点：两个类型参数 T1/T2、构造函数初始化、const& 返回避免拷贝、const 成员函数。

16.2

模板参数与成员模板

本节讲什么

本节讲解模板参数的多种形式：(1) 类型参数（typename T）；(2) 非类型参数（整型、指针等编译期常量）；(3) 默认模板实参；(4) 成员模板（类成员本身是模板）；(5) typename 指明依赖类型。这些是把模板从"简单泛型函数"扩展到"复杂泛型库"的基础工具。

一句话定位：模板参数不只能传"类型"，还能传"编译期常量"；类成员也能是模板——这让模板能表达 std::array<int, 10> 这种"类型 + 大小"的泛型。

核心用法

1. 类型参数：typename vs class

template <typename T> class A { };   // typename
template <class T> class B { };      // class —— 完全等价

两者等价，推荐 typename（更明确"这是个类型"）。class 在模板语境下不暗示必须是类类型——int、指针都行。

2. 非类型参数

模板参数可以是非类型的编译期常量——整型、指针、引用、auto（C++17）、nullptr：

template <typename T, std::size_t N>   // N 是非类型参数（编译期常量）
class Array {
    T data_[N];
public:
    T& operator[](std::size_t i) { return data_[i]; }
    std::size_t size() const { return N; }
};
Array<int, 10> arr;          // 10 个 int 的数组，N=10 在编译期确定
Array<double, 100> darr;     // 不同 N 是不同类型，不能互相赋值

非类型参数的限制： - 必须是编译期常量表达式（字面量、constexpr 变量、枚举） - 类型只能是整型（含 char/bool/枚举）、指针、引用、auto（C++17 起） - 不能是浮点数（历史原因，C++20 仍不允许） - 必须是 const——不能在运行期修改

template <double D> class X { };   // ❌ 浮点不能作非类型参数
int n = 10;
Array<int, n> a;                   // ❌ n 不是编译期常量
constexpr int N = 10;
Array<int, N> b;                   // ✅

3. 模板的默认实参

模板参数可以有默认值（类似函数默认实参）：

template <typename T, typename Container = std::vector<T>>
class Stack {
public:
    void push(const T &v) { data_.push_back(v); }
private:
    Container data_;
};
Stack<int> s1;                           // Container 默认 vector<int>
Stack<int, std::deque<int>> s2;          // 显式指定 deque

默认实参从右向左匹配，所有带默认值的参数必须在参数列表末尾。C++11 起函数模板也支持默认实参。

4. 成员模板

类的成员本身可以是模板——这让类能"对某些类型提供泛型操作"：

class Logger {
public:
    // 成员模板：可记录任意可输出类型
    template <typename T>
    void log(const T &v) {
        std::cout << v << "\n";
    }
};
Logger lg;
lg.log(42);          // T=int
lg.log("hello");     // T=const char*
lg.log(3.14);        // T=double

成员模板的典型应用：智能指针的构造函数。unique_ptr<Derived> 能转 unique_ptr<Base>，靠的就是构造函数是模板：

template <typename T>
class unique_ptr {
public:
    unique_ptr() = default;
    // 接受其他类型 U 的指针，只要 U* 能转 T*
    template <typename U>
    unique_ptr(U *p) : ptr_(p) { }
private:
    T *ptr_ = nullptr;
};
class Base { virtual ~Base() = default; };
class Derived : public Base { };
unique_ptr<Base> p = new Derived();   // U=Derived, T=Base，Derived* 转 Base* 合法

5. 模板的模板参数

参数本身是一个模板（少用但强大）：

template <typename T, template <typename> class Container>
class Stack {
public:
    void push(const T &v) { data_.push_back(v); }
private:
    Container<T> data_;    // Container 是模板，要传类型参数
};
Stack<int, std::vector> s;   // Container=vector，内部 vector<int>

注意 template <typename> class Container——Container 是"接受一个类型参数的模板"，不是具体类型。C++17 起可用 typename 替代 class（template <typename> typename Container）。

这种用法较少——通常直接传 Container<T> 作为类型参数更简单。模板模板参数主要用于需要"延迟绑定容器类型"的高级库设计。

6. typename 指明依赖类型

模板内部，某些名字依赖模板参数（如 T::value_type），编译器不知道它是类型还是变量——默认假设是变量。要告诉编译器"这是类型"，用 typename 前缀：

template <typename Container>
void f(const Container &c) {
    // Container::value_type 是依赖类型——不知道 Container 是什么
    typename Container::value_type x = c.front();   // ✅ typename 指明是类型
    // Container::value_type x = ...;   // ❌ 编译器默认认为是变量名，报错
}

规则：依赖模板参数的嵌套类型名，前面必须加 typename。这是模板编程的常见陷阱。

例外：基类列表和成员初始化列表里不需要 typename（编译器已知那里是类型）。

7. using 模板别名（C++11）

typedef 无法给模板起别名，C++11 引入 using：

template <typename T>
using Vec = std::vector<T, std::allocator<T>>;
Vec<int> v;   // 等价于 vector<int>
// 旧 typedef 做不到：
// template<typename T> typedef std::vector<T> Vec;  // ❌ 不合法

using 别名让模板代码更简洁，是现代 C++ 替代 typedef 的首选。

和 C 的区别

C 没有模板参数概念，要实现"类型 + 编译期大小"的泛型只能用宏：

维度 C（宏 + void*） C++ 模板参数
编译期大小参数 宏 #define ARRAY(T,N) T arr_##N[N] 非类型参数 template<size_t N>
类型安全 无 编译期检查
不同大小是不同类型 宏展开后是同名数组 Array<int,10> ≠ Array<int,20>
默认容器 无 默认模板实参
成员泛型 无（C 结构体成员无模板） 成员模板

C 用宏模拟"类型 + 大小"泛型

// C：宏模拟泛型数组
#define DEFINE_ARRAY(T, N) \
    typedef struct { T data[N]; size_t size; } T##_##N##_Array; \
    /* 等等，宏没法干净地做这个 */
// 实际 C 做法：用 void* + 运行期大小，放弃编译期类型安全
struct Array {
    void *data;
    size_t size;
    size_t elem_size;
};
void array_init(struct Array *a, size_t n, size_t es) {
    a->data = malloc(n * es);
    a->size = n;
    a->elem_size = es;
}
// 访问要强转 + 手动算偏移，无类型检查

// C++：非类型参数
template <typename T, std::size_t N>
struct Array {
    T data[N];
    constexpr std::size_t size() const { return N; }
};
Array<int, 10> a;        // 编译期已知大小，类型安全
Array<double, 100> b;    // 不同类型，不能混用

C 的 void* 数组把类型信息丢了，访问靠 memcpy + 偏移；C++ 的非类型参数让大小成为类型的一部分，编译器全程类型检查。

HFT 视角：std::array<T, N> 是非类型参数的典范——栈上固定大小数组，零堆分配，cache 友好。HFT 热路径上常用 std::array<double, 64> 替代 std::vector<double>，避免堆分配和扩容开销。

常见错误

错误 1：非类型参数用浮点数

template <double D> class X { };   // ❌ 浮点不能作非类型参数

C++ 标准不允许浮点非类型参数（历史原因）。替代：用整数 + 缩放（如用毫秒整数表示时间），或 constexpr 函数转换。

错误 2：忘记 typename 指明依赖类型

template <typename T>
void f(T &c) {
    T::value_type x;        // ❌ 编译器认为 T::value_type 是变量名
    typename T::value_type y;   // ✅
}

依赖模板参数的嵌套类型，前加 typename。这是模板编程高频错误。

错误 3：默认实参顺序错误

template <typename T = int, typename U>   // ❌ 带默认值的参数必须在后
class X { };
template <typename T, typename U = int>   // ✅
class Y { };

默认实参从右向左匹配，带默认值的必须在末尾。

错误 4：不同非类型参数值误以为是同一类型

Array<int, 10> a;
Array<int, 20> b;
a = b;    // ❌ 不同类型，不能赋值

非类型参数是类型的一部分——Array<int,10> 和 Array<int,20> 是完全不同的类型。若需要"任意大小"，用 std::vector（运行期大小）。

自测题

1. 选择题：以下哪个不能作为模板的非类型参数？

A. int 整型常量 B. std::size_t 常量 C. double 浮点常量 D. 指向外部对象的指针

答案

C。C++ 标准不允许浮点数作为非类型参数。整型（含 size_t）、枚举、指针、引用、auto（C++17）都可以。这是历史遗留限制，C++20 仍未放开。

2. 判断题：在模板代码中，Container::iterator 这种形式（Container 是模板参数）必须写成 typename Container::iterator 才能作为类型使用。

答案

对。因为 Container 是模板参数，编译器不知道 Container::iterator 是类型还是静态成员变量——默认假设是变量。要作为类型使用，必须加 typename 前缀显式指明。例外：基类列表和成员初始化列表里不需要。

3. 踩坑题：以下代码哪里有问题？

template <typename T, typename Container = std::vector<T>>
class Stack {
public:
    void push(const T &v) { data_.push_back(v); }
    T pop() { T v = data_.back(); data_.pop_back(); return v; }
private:
    Container data_;
};
Stack s;        // 使用
答案

Stack s; 没有指定任何模板实参。类模板不能像函数模板那样完全推断——即使有默认实参，也至少要写 <> 或依赖 CTAD（但这里没有能推断的构造函数）。

修复：

Stack<int> s;                    // ✅ T=int, Container=vector<int>（默认）
Stack<int, std::deque<int>> s2;  // ✅ 显式指定

C++17 CTAD 也救不了这种场景（构造函数不涉及 T），仍需显式写 Stack<int>。

4. 应用题：用模板实现一个 FixedBuffer<T, N>，N 是编译期大小，要求： - 栈上数组存储 N 个 T - push(v) 添加（满则忽略） - size() 返回当前元素数 - capacity() 返回 N（constexpr）

答案 
#include <cstddef>
template <typename T, std::size_t N>
class FixedBuffer {
public:
    void push(const T &v) {
        if (count_ < N) data_[count_++] = v;
    }
    std::size_t size() const { return count_; }
    static constexpr std::size_t capacity() { return N; }   // 编译期常量
    const T& operator[](std::size_t i) const { return data_[i]; }
private:
    T data_[N];              // 栈上数组，编译期大小
    std::size_t count_ = 0;
};
// 用法：
FixedBuffer<int, 16> buf;
for (int i = 0; i < 20; ++i) buf.push(i);   // 只存前 16 个
static_assert(FixedBuffer<int,16>::capacity() == 16, "");  // 编译期检查

要点：非类型参数 N、static constexpr capacity() 可编译期求值、栈上数组零堆分配、static_assert 验证。这是 HFT 热路径的典型模式。

16.3

模板实参推断

本节讲什么

本节讲解函数模板的实参推断（编译器如何从调用实参推算模板参数类型），以及两个进阶但极重要的机制：(1) 尾置返回类型 + decltype 让返回类型依赖参数；(2) 引用折叠（reference collapsing）——这是 std::move 和 std::forward（完美转发）的底层原理。这是把模板从"简单泛型"推进到"能正确处理左右值"的关键章节。

一句话定位：实参推断 = "编译器看你怎么调用，反推 T 是什么"；引用折叠 = "当引用套引用时，左值引用压倒一切"——理解它才能看懂 std::move/std::forward。

核心用法

1. 函数模板实参推断

编译器从调用实参推算模板参数：

template <typename T>
void f(T x);
f(42);        // T=int（实参 42 是 int）
f(3.14);      // T=double
f("hi");      // T=const char*（字符串字面量 decay 为指针）
int a[10];
f(a);         // T=int*（数组 decay 为指针）

推断规则要点： - 若形参是 T（非引用非指针），实参的顶层 const 和引用被忽略，数组/函数 decay 为指针 cpp template <typename T> void f(T x); const int ci = 42; f(ci); // T=int（顶层 const 忽略） int &r = ci; f(r); // T=int（引用忽略） - 若形参是 T&（引用），实参的 const 保留： cpp template <typename T> void f(T &x); const int ci = 42; f(ci); // T=const int（const 保留） int i = 1; f(i); // T=int - 推断不做隐式算术转换：f(3, 7.0) 若 T 是同一个参数，推断冲突报错

2. 显式指定模板实参

推断冲突或无法推断时，显式指定：

template <typename T>
T maximum(const T &a, const T &b) { return a > b ? a : b; }
maximum(3, 7.0);                 // ❌ T 既是 int 又是 double
maximum<double>(3, 7.0);         // ✅ 显式 T=double，3 转 double

template <typename T1, typename T2, typename T3>
T1 sum(T2 a, T3 b) { return a + b; }
auto s = sum<int>(3.14, 7);      // T1=int, T2=double, T3=int（T2/T3 推断，T1 显式）

显式实参从左到右匹配——所以把需要显式指定的参数放左边。sum 的返回类型 T1 无法从实参推断（返回类型不参与推断），必须显式指定。

3. 尾置返回类型 + decltype

当返回类型依赖参数时，用尾置返回类型 + decltype：

template <typename It>
auto f(It beg, It end) -> decltype(*beg) {   // 返回类型 = *beg 的类型
    return *beg;
}

decltype(*beg) 通常是 T&（引用），若想返回值类型，用 std::remove_reference：

template <typename It>
auto f(It beg, It end) -> typename std::remove_reference<decltype(*beg)>::type {
    return *beg;
}

C++14 起，auto 返回类型推导让这更简洁：

template <typename It>
auto f(It beg, It end) {   // C++14：编译器从 return 推导返回类型
    return *beg;            // 返回 decltype(*beg)
}

C++14 的 decltype(auto) 保留引用性：

template <typename It>
decltype(auto) f(It beg, It end) { return *beg; }   // 保留 *beg 的引用性

4. 引用折叠（reference collapsing）

模板参数为引用时，可能产生"引用的引用"——C++ 不允许直接写 int& &，但模板推断会产生，此时引用折叠规则生效：

组合 折叠结果
T& & T&
T& && T&
T&& & T&
T&& && T&&

口诀：只要有一个左值引用，折叠为左值引用；只有两个右值引用才折叠为右值引用。

为什么会产生引用的引用？因为 T&&（ forwarding reference，转发引用）在推断时有特殊规则：

template <typename T>
void f(T &&x);        // T&& 是转发引用（不是"右值引用"！）

int i = 42;
f(i);                 // 实参是左值 → T=int&，T&& 折叠为 int& && = int&
f(42);                // 实参是右值 → T=int，T&& 是 int&&

关键区分：T&& 在模板参数推断语境下是"转发引用"（可绑左值也可绑右值），不是"右值引用"。只有非模板语境的 int&& 才是纯右值引用。

5. std::move 的原理

std::move 本质是一个无条件的右值转换，靠引用折叠实现：

// std::move 的简化实现
template <typename T>
typename std::remove_reference<T>::type&& move(T &&x) noexcept {
    return static_cast<typename std::remove_reference<T>::type&&>(x);
}
// 调用：
int i = 42;
std::move(i);    // T=int&（i 是左值），remove_reference<int&>::type=int
                 // 返回 int&& —— 把左值转成右值
std::move(42);   // T=int（42 是右值），返回 int&& —— 保持右值

std::move 不移动任何东西——它只是 static_cast 成右值引用，让重载解析选择移动构造/赋值。实际移动发生在移动构造函数里。

6. 完美转发 std::forward

std::forward 保持实参的左右值属性，用于"转发"给其他函数：

template <typename T>
void wrapper(T &&x) {
    target(std::forward<T>(x));    // 保持 x 的左右值属性转发
}
void target(int &x)       { std::cout << "lvalue\n"; }
void target(const int &x) { std::cout << "const lvalue\n"; }
void target(int &&x)      { std::cout << "rvalue\n"; }

int i = 42;
wrapper(i);     // 输出 "lvalue"——i 是左值，forward 保持左值
wrapper(42);    // 输出 "rvalue"——42 是右值，forward 保持右值

// std::forward 的简化实现
template <typename T>
T&& forward(typename std::remove_reference<T>::type &x) noexcept {
    return static_cast<T&&>(x);
}
// wrapper(i): T=int&（i 左值），forward<int&> 返回 int& && = int&（左值引用）
// wrapper(42): T=int（42 右值），forward<int> 返回 int&&（右值引用）

std::forward 是有条件转换——T 是左值引用时转左值，T 是非引用时转右值。这与 std::move 的无条件右值转换不同。

7. 完美转发的应用：泛型工厂

template <typename T, typename... Args>
std::unique_ptr<T> make_unique(Args&&... args) {   // 可变参数 + 转发引用
    return std::unique_ptr<T>(new T(std::forward<Args>(args)...));
}
class Widget {
public:
    Widget(int, const std::string&);
};
auto w = std::make_unique<Widget>(42, "hello");   // 参数完美转发给 Widget 构造函数

Args&&... args 是可变转发引用包，std::forward<Args>(args)... 保持每个参数的左右值属性转发。这是 std::make_unique/std::make_shared/emplace_back 的核心机制——零拷贝地把参数传给构造函数。

和 C 的区别

C 没有引用，也没有模板——"转发"靠 void* + 手动管理左右值（C 根本不区分左右值）：

维度 C C++ 模板
实参类型推断 无（函数签名固定） 编译器自动推断 T
左右值区分 无（都是值或指针） 转发引用 + 引用折叠保留属性
完美转发 无（要么拷贝要么传指针） std::forward 零开销转发
类型安全转换 强转 void* 无检查 模板实参推断编译期检查

C 的"转发"困境

// C：要把参数传给内部函数，只能拷贝或传指针
void target(int x);
void wrapper(int x) {
    target(x);    // 拷贝一次——若 target 需要修改 x，得传指针
}
// C 无法表达"如果原实参是临时值，就让 target 接管它"——C 没有移动语义
// 也无法泛型地"转发任意类型参数"——C 函数签名固定

// C++：完美转发
template <typename T>
void wrapper(T &&x) {
    target(std::forward<T>(x));   // 保持左右值，零额外拷贝
}

C++ 的引用折叠 + 完美转发让"泛型包装器"成为可能——这是 std::make_unique、emplace_back、std::bind 等基础设施的基石，C 完全无法表达。

HFT 视角：完美转发对性能极关键。std::vector::emplace_back 用转发直接在容器内存里构造对象，避免"先构造临时对象再移动/拷贝"的开销。热路径上 emplace_back 比 push_back 快得多，尤其对大对象或非可拷贝类型。

常见错误

错误 1：模板实参推断冲突

template <typename T>
void f(T a, T b);
f(3, 7.0);    // ❌ T 既是 int 又是 double

推断不做算术转换。修复：显式指定 f<double>(3, 7.0)，或用两个类型参数。

错误 2：误以为 T&& 是"右值引用"

template <typename T>
void f(T &&x);     // 这是"转发引用"，不是纯右值引用！
int i = 42;
f(i);              // ✅ 合法！T=int&，T&& 折叠为 int&

在模板参数推断语境下，T&& 是转发引用，能绑左值也能绑右值。只有非模板的 int&& 才是纯右值引用（只能绑右值）。

错误 3：转发时忘记 std::forward

template <typename T>
void wrapper(T &&x) {
    target(x);    // ❌ x 是左值（有名字），永远调左值重载
}

即使 x 的类型是 int&&，作为具名变量它本身是左值——target(x) 调左值版本。修复：target(std::forward<T>(x)); 保持原始左右值属性。

错误 4：std::move 用在 const 对象上

const std::string s = "hello";
auto copy = std::move(s);   // ❌ move 不了！s 是 const
// std::move(s) 返回 const string&&，重载解析选拷贝构造（const string&& 转 const string&）
// 结果是拷贝，不是移动——且 s 未变

std::move 对 const 对象无效——const 阻止移动构造（移动构造要修改源对象）。这是"move 一个 const 对象得到拷贝"的隐蔽陷阱。

自测题

1. 选择题：template <typename T> void f(T &&x); 中，T&& 是什么？

A. 右值引用，只能接受右值 B. 转发引用，可接受左值和右值 C. 万能引用，可接受任何类型 D. 引用的引用，非法

答案

B。在模板参数推断语境下，T&& 是"转发引用"（forwarding reference，又称万能引用）——左值实参让 T=int&，引用折叠成 int&；右值实参让 T=int，T&& 是 int&&。它能绑左值也能绑右值。只有非模板语境的 int&& 才是纯右值引用。

2. 判断题：引用折叠规则中，T& && 折叠为 T&&（右值引用）。

答案

错。T& && 折叠为 T&（左值引用）。折叠规则口诀："只要有一个左值引用，折叠为左值引用；只有两个右值引用才折叠为右值引用"。四种组合里只有 T&& && → T&&，其余三种都折成 T&。

3. 踩坑题：以下代码输出什么？

void target(int &)       { std::cout << "A"; }
void target(const int &) { std::cout << "B"; }
void target(int &&)      { std::cout << "C"; }
template <typename T>
void wrapper(T &&x) { target(x); }       // 注意：没 forward
int main() {
    wrapper(42);    // 期望输出 C（42 是右值）
}
答案

输出 A（不是 C）。虽然 42 是右值，wrapper 中 T=int、x 类型是 int&&，但 x 作为具名变量本身是左值——target(x) 调用左值重载。int& 比 const int& 更匹配非 const 左值，选 A。

修复：target(std::forward<T>(x));——std::forward<int>(x) 返回 int&&，调 target(int&&) 输出 C。

教训：转发必须用 std::forward，否则左右值属性丢失。

4. 应用题：实现一个简单的 make_unique（简化版，单个参数），要求： - 接受任意类型参数 - 完美转发给 T 的构造函数 - 返回 std::unique_ptr<T>

答案 
#include <memory>
#include <utility>
template <typename T, typename Arg>
std::unique_ptr<T> my_make_unique(Arg &&arg) {
    return std::unique_ptr<T>(new T(std::forward<Arg>(arg)));
}
// 用法：
struct Widget {
    Widget(int x) : val(x) { }
    Widget(const std::string &s) : name(s) { }
    int val = 0;
    std::string name;
};
auto w1 = my_make_unique<Widget>(42);              // 转发 int
auto w2 = my_make_unique<Widget>(std::string("hi")); // 转发右值 string
std::string s = "hello";
auto w3 = my_make_unique<Widget>(s);               // 转发左值 string（拷贝）

要点：Arg&& 转发引用、std::forward<Arg>(arg) 保持左右值、new T(...) 原地构造。真正的 std::make_unique 用可变参数模板 template<typename T, typename... Args>，原理相同。

16.4

高级特性

本节讲什么

本节讲解模板的三个进阶特性：(1) 模板重载——函数模板可以像普通函数一样重载；(2) 可变参数模板（variadic template）——接受任意数量任意类型的参数，是 std::make_unique/printf 类型安全版的基础；(3) 模板特例化（specialization）——为特定类型提供定制实现。这是把模板从"简单泛型"推向"复杂元编程"的门槛。

一句话定位：可变参数模板 = "类型安全的 printf"；特例化 = "这个类型我单独写一份更好的实现"。

核心用法

1. 函数模板重载

函数模板可以与普通函数、其他模板重载，编译器按"最特化"原则选择：

template <typename T>
void f(T) { std::cout << "template\n"; }       // 通用模板
void f(int) { std::cout << "int\n"; }          // 非模板重载
void f(double) { std::cout << "double\n"; }    // 另一个非模板重载

f(42);        // int（非模板精确匹配优先于模板）
f(3.14);      // double（非模板）
f("hi");      // template（无非模板匹配，用模板 T=const char*）
f('a');       // template（char 无非模板匹配，T=char）

重载选择规则（简化）： 1. 候选集：所有可见的函数和模板实例 2. 对每个候选做参数匹配，能匹配的进入"可行函数集" 3. 优先级：精确匹配的非模板 > 特化的模板 > 通用模板

2. 可变参数模板

C++11 起，模板可接受参数包（parameter pack）——零个或多个参数：

template <typename... Args>           // Args 是类型参数包
void f(Args... args);                 // args 是函数参数包
f();                                  // 0 个参数
f(1, 2, 3);                           // 3 个 int
f(1, "hello", 3.14);                  // int, const char*, double

sizeof...(args) 返回参数个数（编译期常量）：

template <typename... Args>
void f(Args... args) {
    std::cout << sizeof...(args) << " args\n";
}
f(1, 2, 3);   // 3 args

3. 递归展开参数包

参数包不能直接遍历，经典做法是递归 + 基础情形：

// 递归终止基础情形：0 个参数
void print() { std::cout << "\n"; }

// 递归版本：取第一个，递归处理剩余
template <typename T, typename... Rest>
void print(const T &first, const Rest&... rest) {
    std::cout << first << " ";
    print(rest...);    // 递归调用，参数包少一个
}
print(1, "hello", 3.14);   // 输出 "1 hello 3.14\n"
// 调用链：print(1,"hello",3.14) → print("hello",3.14) → print(3.14) → print()

每次递归剥离第一个参数，直到参数包为空，命中基础情形 print() 终止。

4. C++17 折叠表达式（fold expression）

C++17 起用折叠表达式简化参数包展开：

// 一元右折叠：对每个参数调用 f
template <typename... Args>
void print(const Args&... args) {
    ((std::cout << args << " "), ...);    // 折叠表达式
}
print(1, "hello", 3.14);   // 1 hello 3.14

// 求和：
template <typename... Args>
auto sum(Args... args) {
    return (args + ...);    // 折叠加法：((a1+a2)+a3)+...
}
sum(1, 2, 3, 4);    // 10

折叠表达式四种形式： - (args op ...) —— 一元右折叠：a1 op (a2 op (... op aN)) - (... op args) —— 一元左折叠：((a1 op a2) op ...) op aN - (args op ... op init) —— 二元右折叠（带初值） - (init op ... op args) —— 二元左折叠（带初值）

template <typename... Args>
auto sum(Args... args) { return (0 + ... + args); }   // 二元左折叠，初值 0
sum();   // 0（空包，二元折叠有初值不报错）

5. 可变参数模板的应用：类型安全 printf

void printf_safe(const char *fmt) {   // 基础情形：无额外参数
    std::cout << fmt;
}
template <typename T, typename... Args>
void printf_safe(const char *fmt, const T &val, const Args&... rest) {
    for (; *fmt; ++fmt) {
        if (*fmt == '%') {
            std::cout << val;          // 输出当前参数
            printf_safe(fmt + 1, rest...);  // 递归处理剩余
            return;
        }
        std::cout << *fmt;
    }
}
printf_safe("Hello %, you have % messages\n", "Alice", 5);
// 输出 "Hello Alice, you have 5 messages\n"

这是 C 的 printf 的类型安全版——参数类型在编译期检查，不会有 %d 配 const char* 的运行期崩溃。

6. 模板特例化（全特化）

为特定类型提供定制实现——全特化（full specialization）固定所有模板参数：

// 通用模板
template <typename T>
struct TypeInfo {
    static const char* name() { return "unknown"; }
};
// 全特化：int
template <>
struct TypeInfo<int> {
    static const char* name() { return "int"; }
};
// 全特化：double
template <>
struct TypeInfo<double> {
    static const char* name() { return "double"; }
};
TypeInfo<int>::name();      // "int"
TypeInfo<char>::name();     // "unknown"（用通用模板）

函数模板也可全特化：

template <typename T>
void f(const T &) { std::cout << "general\n"; }
template <>
void f<int>(const int &) { std::cout << "int specialization\n"; }
f(3.14);    // general
f(42);      // int specialization

7. 类模板偏特化

类模板可偏特化（partial specialization）——只固定部分参数或限定某种形式：

template <typename T>
struct RemoveRef { using type = T; };
// 偏特化：左值引用
template <typename T>
struct RemoveRef<T&> { using type = T; };
// 偏特化：右值引用
template <typename T>
struct RemoveRef<T&&> { using type = T; };
RemoveRef<int>::type        // int
RemoveRef<int&>::type       // int（偏特化匹配）
RemoveRef<int&&>::type      // int（偏特化匹配）

偏特化让"对某类形式特殊处理"成为可能——这是 std::remove_reference、std::vector<bool> 等标准库设施的基础。

8. 函数模板不能偏特化

重要限制：函数模板不能偏特化，只能重载或全特化。若想"对引用类型特殊处理函数模板"，用重载：

// ❌ 非法：函数模板不能偏特化
// template <typename T> void f<T&>(T& x) { ... }

// ✅ 用重载代替
template <typename T> void f(T x) { /* 通用 */ }
template <typename T> void f(T &x) { /* 引用特殊处理 */ }

这是模板设计的有意约束——函数重载已能表达"针对不同参数形式不同行为"，偏特化会和重载解析冲突。

和 C 的区别

C 的可变参数靠 va_list（<stdarg.h>），完全不类型安全：

维度 C va_list C++ 可变参数模板
类型检查 无（运行期按格式串解释） 编译期类型检查
参数个数 运行期约定（如 printf 的 % 个数） 编译期 sizeof... 已知
错误时机 运行期崩溃 编译期错误
性能 间接（va_list 遍历） 可内联（编译期展开）
特化 无 全特化/偏特化

C va_list 的不安全

#include <stdarg.h>
int sum(int count, ...) {
    va_list args;
    va_start(args, count);
    int total = 0;
    for (int i = 0; i < count; ++i)
        total += va_arg(args, int);    // 强制按 int 读——若实参是 double，读错
    va_end(args);
    return total;
}
sum(3, 1, 2, 3);          // 6
sum(3, 1.5, 2, 3);        // ❌ 1.5 是 double，按 int 读——未定义行为，可能崩溃
// count 和实际参数个数不符也是未定义行为——没有任何检查

// C++：类型安全
template <typename... Args>
auto sum(Args... args) {
    return (args + ...);    // 每个参数按其实际类型参与加法
}
sum(1, 2, 3);               // 6（int）
sum(1.5, 2, 3);             // 6.5（double）——不会读错类型
// sum(1, "hello");         // 编译错误：int + const char* 无 operator+

C 的 va_list 把"类型"和"个数"都丢给了运行期，printf("%d %s", 42, 3.14) 这种格式串与实参不匹配是经典崩溃源。C++ 可变参数模板让"类型安全的多参数函数"成为可能，编译期挡住所有类型错误。

HFT 视角：可变参数模板 + 折叠表达式是编译期计算的基础。例如编译期把一组价格展开成无分支代码、把订单字段展开成序列化代码——零运行开销，且类型安全。这是 C++ 在超低延迟领域胜过 C 的关键武器之一。

常见错误

错误 1：函数模板偏特化（非法）

template <typename T> void f(T);
template <typename T> void f<T&>(T&) { }   // ❌ 函数模板不能偏特化

修复：用重载 template <typename T> void f(T&) { }，或用类模板偏特化包装。

错误 2：全特化签名不匹配

template <typename T>
void f(T x) { }
template <>
void f<int>(int x, int extra) { }   // ❌ 特化签名多了参数，与模板不符

特化版本的签名必须与主模板匹配（参数个数、类型一致）。修复：template <> void f<int>(int x) { }。

错误 3：可变参数模板缺少基础情形

template <typename T, typename... Rest>
void print(const T &first, const Rest&... rest) {
    std::cout << first;
    print(rest...);    // 递归
}
// ❌ 没有基础情形 print()，当 rest... 为空时无法终止
print(1);   // 调 print(1) → print() → 找不到匹配，编译错误

修复：定义基础情形 void print() { } 终止递归，或用 C++17 折叠表达式避免手写递归。

错误 4：特化 vs 重载混淆

template <typename T> void f(T) { }      // 通用模板
template <> void f<int>(int) { }         // 全特化
void f(int) { }                          // 非模板重载
f(42);   // 调哪个？

非模板重载优先级高于模板特化——f(42) 调非模板 f(int)。若你写了特化却发现没被调用，检查是不是被重载盖住了。最佳实践：优先用重载而非特化，特化不参与重载解析的第一轮（特化只在主模板被选中后才考虑）。

自测题

1. 选择题：以下关于可变参数模板的说法，错误的是？

A. sizeof...(args) 返回参数包的个数，是编译期常量 B. 可变参数模板可通过递归 + 基础情形展开参数包 C. C++17 折叠表达式可替代手写递归展开 D. 可变参数模板的参数个数在运行期才确定

答案

D 错误。参数包的个数在编译期就已知（sizeof...(args) 是编译期常量），编译器在编译期展开所有递归调用或折叠表达式。运行期没有"参数个数"的概念——展开后的代码就像手写了一串重载。这是与 C va_list（运行期才知道个数）的本质区别。

2. 判断题：函数模板可以偏特化，类模板也可以偏特化。

答案

错。函数模板不能偏特化，只能全特化或重载。类模板可以偏特化（固定部分参数或限定形式）。若需要对函数模板"针对引用类型特殊处理"，用重载代替偏特化。

3. 踩坑题：以下代码有什么问题？

template <typename T, typename... Rest>
void log(const T &first, const Rest&... rest) {
    std::cout << first << " ";
    log(rest...);    // 递归
}
int main() {
    log("start", 42, 3.14);
}
答案

缺少基础情形。log("start", 42, 3.14) → log(42, 3.14) → log(3.14) → log()（空包）→ 找不到匹配的 log()，编译错误。

修复方案：

// 方案 1：加基础情形
void log() { }   // 终止
template <typename T, typename... Rest>
void log(const T &first, const Rest&... rest) {
    std::cout << first << " ";
    log(rest...);
}

// 方案 2：C++17 折叠表达式（无需递归）
template <typename... Args>
void log(const Args&... args) {
    ((std::cout << args << " "), ...);
}

4. 应用题：用可变参数模板实现一个 max_of(a, b, c, ...) 函数，返回任意数量参数中的最大值（要求类型相同）。

答案 
#include <iostream>
// 方案 1：递归 + 基础情形
template <typename T>
T max_of(const T &a) { return a; }   // 基础情形：单参数
template <typename T, typename... Rest>
T max_of(const T &first, const Rest&... rest) {
    T rest_max = max_of(rest...);
    return first > rest_max ? first : rest_max;
}
// 方案 2：C++17 折叠表达式（更简洁）
template <typename T, typename... Rest>
T max_of_fold(const T &first, const Rest&... rest) {
    T result = first;
    ((result = rest > result ? rest : result), ...);   // 折叠更新
    return result;
}
// 用法：
int main() {
    std::cout << max_of(3, 1, 4, 1, 5, 9, 2, 6);   // 9
    std::cout << max_of_fold(3.14, 2.71, 1.41);     // 3.14
}

要点：递归版需要基础情形 max_of(const T&) 终止；折叠版用逗号折叠逐个更新最大值。两者都要求参数类型相同（隐式转换到 T）。

Q1函数模板推导
template<typename T>
T add(T a, T b) { return a + b; }
int main() {
    std::cout << add(1, 2);      // A
    std::cout << add(1, 2.0);    // B
    std::cout << add<double>(1, 2.0);  // C
}

B 编译成功吗？A 和 C 分别输出什么？

答案与复习指引

B: 编译错误。 add(1, 2.0) 中 T 从 1 推导为 int，从 2.0 推导为 double——冲突，推导失败。

A: 3 — T = int C: 3 — 显式指定 T = double，1 隐式转换为 double

教训： 模板推导不做隐式类型转换。如果两种类型不同，要显式指定模板参数或用两个类型参数。

复习： → 定义模板

Q2类模板
template<typename T, size_t N>
class Array {
    T data[N];
public:
    T& operator[](size_t i) { return data[i]; }
    constexpr size_t size() const { return N; }
};
Array<int, 5> arr;
arr[0] = 42;
std::cout << arr.size() << " " << arr[0];

输出是什么？非类型模板参数 N 是什么？

答案与复习指引

输出： 5 42

非类型模板参数 N： 模板参数可以是值而非类型。N 必须是编译期常量（size_t N=5）。std::array 就是这样实现的。

和 C 宏的区别： 模板是类型安全的——Array<int, 5> 和 Array<double, 5> 是不同类型，编译器分别生成代码。C 的宏只是文本替换，无类型检查。

复习： → 定义模板

Q3可变参数模板
template<typename T>
void print(T t) { std::cout << t << std::endl; }
template<typename T, typename... Args>
void print(T t, Args... rest) {
    std::cout << t << " ";
    print(rest...);
}
int main() {
    print(1, "hello", 3.14, 'x');
}

输出是什么？Args... 是什么？

答案与复习指引

输出： 1 hello 3.14 x

Args...： 参数包（parameter pack），可以接受任意数量、任意类型的参数。递归展开：每次取第一个参数 T t 输出，剩余 rest... 递归调用 print，直到只剩一个参数走基础版本。

和 C 的 va_list 区别： 模板参数包是类型安全的——编译器知道每个参数的类型。C 的 printf 用 va_list 不检查类型，格式符和参数不匹配是 UB。

复习： → 高级特性

Q4完美转发
template<typename T>
void wrapper(T &&arg) {
    target(std::forward<T>(arg));
}
// 如果传入左值 lval：T 推导为？arg 类型是？
// 如果传入右值 rval：T 推导为？arg 类型是？

左值和右值分别推导出什么？std::forward 的作用是什么？

答案与复习指引
  • 传入左值 lval（int&）：T 推导为 int&，arg 类型为 int&（引用折叠 int& && → int&），forward<int&>(arg) 转发为左值
  • 传入右值 rval（int&&）：T 推导为 int，arg 类型为 int&&，forward<int>(arg) 转发为右值

std::forward<T> 的作用： 有条件地转换——当原始实参是右值时转成右值（允许移动），是左值时保持左值。这叫"完美转发"——转发函数保留了原始实参的左右值性。

T&& 在模板中是万能引用（不是纯右值引用），能同时接受左值和右值。
