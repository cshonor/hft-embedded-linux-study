4.1

基础

本节讲什么

表达式、运算符的基本概念：一元/二元/三元运算符、操作数、结果类型、优先级与结合律、求值顺序。这些是后面 4.2–4.12 所有运算符的"地基"。

核心概念

概念 含义 例子
运算符 对操作数做运算的符号 + - *
操作数 运算符作用的对象 a + b 中 a、b 是操作数
一元运算符 1 个操作数 -x、!flag、*p
二元运算符 2 个操作数 a + b、a == b
三元运算符 3 个操作数（C++ 唯一） cond ? a : b
优先级 谁先跟谁结合 a + b * c 中 * 先
结合律 同级从左还是从右算 a - b - c 从左，a = b = c 从右
求值顺序 操作数何时算 f() + g() 中 f/g 调用顺序未指定

三个核心区分（必考）

1. 优先级 ≠ 求值顺序

int f(), g();
int h = f() + g();   // + 决定结合方式，但 f/g 哪个先调？未指定

优先级只决定"谁跟谁结合"（语法结构），不决定运行时求值顺序。f() + g() 中编译器可任意选 f 或 g 先调。

2. 有顺序保证的运算符

运算符 顺序保证
&& \|\| 左侧先，左侧为假/真时右侧不求值（短路）
?: 条件先，只算被选中的分支
, 逗号 从左到右
赋值 = 右侧先于左侧

位运算 & | ^、算术 + - * / 都没有顺序保证。

3. 未定义行为（UB）经典坑

int i = 0;
// i = i++;           // ❌ UB：i 被改两次无序
// v[i] = i++;        // ❌ UB：下标 i 与右侧 i++ 无序
// f(++i, ++i);       // ❌ UB：两个实参求值无序

HFT 工程建议：热路径表达式保持简单，需要顺序就拆成多条语句。

示例

#include <iostream>
int main() {
    int i = 3, j = 4;
    std::cout << i + j << " " << i * j << std::endl;   // 7 12
    return 0;
}

和 C 的区别（表达式基础：C/C++ 几乎一致，C++ 多了几个运算符）

C 程序员对运算符、优先级、结合律这些概念已经熟得不能再熟——C++ 继承了 C 的全部运算符语义，规则几乎一一对应：

对比点 C C++
一元/二元/三元 ✅ 一致 ✅ 一致
优先级表 C 标准定义 C++ 几乎相同，多了 :: .* ->*
结合律 ✅ 一致 ✅ 一致
求值顺序 同样未指定 f()+g() 完全一致
UB 坑（i=i++） ✅ C 也是 UB ✅ 一致
:: 作用域运算符 无 C++ 独有（最高优先级）
.* ->* 成员指针 无 C++ 独有
typeid/static_cast 等 无 C++ 独有（当运算符看）

给 C 程序员的关键提醒： 1. C 学的优先级表 C++ 直接用——99% 相同。新增的 ::、.*、->*、static_cast 等优先级最高或当后缀，日常不太会和算术/逻辑运算符混淆。 2. 求值顺序坑两边一样——f()+g() 在 C 和 C++ 都是未指定顺序，i=i++ 都是 UB。C 程序员的警惕心直接迁移过来。 3. C++ 多了"类成员访问"运算符——obj.member、ptr->member、obj.*pmem、ptr->*pmem。前两个和 C 的 struct 成员访问一致，后两个是 C++ 独有（成员指针，第 7 章详讲）。

常见错误

1. 以为优先级决定求值顺序

int side_effect();
int x = side_effect() + 1;   // 以为 side_effect 一定先调？

错。+ 的优先级决定 1 跟 side_effect() 结合，但 side_effect() 和 1 的求值顺序未指定——编译器可能先算 1（没副作用，无影响）。但如果换成 f() + g()，f/g 哪个先调未指定，若它们有共享状态副作用就 UB。

2. i = i++ 以为"先赋值再自增"

int i = 0;
i = i++;   // ❌ UB，不是"i=0 然后 i 变 1"

C 程序员也踩这个——两边都是 UB。i = i++ 在一次表达式中对 i 修改两次（一次 =、一次 ++），且两次修改无顺序保证。拆成两条语句：int tmp = i; ++i; i = tmp; 或干脆 i = i + 1;。

3. 复杂表达式不写括号，依赖记忆优先级

if (flags & mask == 0) { ... }   // ❌ 等价 flags & (mask == 0)，不是 (flags & mask) == 0

== 优先级高于 &，所以先算 mask == 0 得 bool（0 或 1），再 flags & 0/1。位运算和关系混用必加括号：if ((flags & mask) == 0)。C 程序员也踩这个，C++ 同样坑。

自测题

1. 选择题　C++ 中有几个三元运算符？

  • A. 0
  • B. 1
  • C. 2
  • D. 3
答案

B。C++ 唯一的三元运算符是 ?:（条件运算符）。C 也是 1 个，完全一致。

2. 判断题　f() + g() 中，C++ 标准保证 f() 一定先于 g() 调用。

答案

错。+ 操作数的求值顺序未指定——编译器可以任意选 f 或 g 先调。C 也是同样规则。要保证顺序用 ; 拆开：int a = f(); int b = g(); int h = a + b;。

3. 踩坑题　下面这段代码在 C 和 C++ 中行为如何？

int i = 0;
int v[10];
v[i] = i++;
答案

UB（未定义行为），C 和 C++ 都是。v[i] 中的 i（左值下标）和右侧 i++（修改 i）之间没有顺序保证——i++ 可能在算 v[i] 的下标前、后、中间执行，结果不可预测。

修复：拆成两条语句：

v[i] = i;
++i;

或用范围 for / 算法库避开手写下标 + 自增的组合。

4. 应用题　写一个表达式判断"价格 p 在 [low, high] 区间内"，要求用短路求值避免 low > high 时的误判。

答案 
bool in_range = (low <= high) && (low <= p) && (p <= high);

要点： - 用 && 短路：若 low > high，第一个条件 false，后面不算（虽然这里算不算都行，但短路是好习惯） - 拆成三个比较，不用 low <= p <= high（这是 (low <= p) <= high 的常见错误） - C 程序员的 low <= p && p <= high 习惯直接用

错误写法：low <= p <= high —— 等价 (low <= p) <= high，先算 low <= p 得 bool（0/1），再和 high 比，逻辑错。

题目 1： 以下代码在 C 和 C++ 中的行为有什么不同？

int x = 10;

4.3

关系与逻辑运算符

本节讲什么

关系比较与逻辑组合；短路求值是核心考点。

关系运算符 < <= > >= == !=

  • 结果类型为 bool（打印时可能显示 0/1）
  • 错误写法：a < b < c 等价 (a < b) < c，不是数学上的「介于两者之间」
int a = 1, b = 2, c = 3;
// if (a < b < c)  // 先 (a<b)→true→1，再 1<c，逻辑常错
if (a < b && b < c)  // ✅

逻辑运算符 ! && ||

运算符 含义 短路
! 逻辑非，优先级在 &&/|| 之上 —
&& 与 左侧为 false，右侧不执行
|| 或 左侧为 true，右侧不执行 
if (b != 0 && a / b) { /* 左侧假则不算 a/b，防除零 */ }

注意：位运算 & | 没有短路（见 4.8）。

和 C 的区别（关系/逻辑运算符：C99 起几乎一致，C++ 多了 bool 类型）

对比点 C（C89） C（C99+） C++
关系运算符 ✅ 一致 ✅ 一致 ✅ 一致
&& \|\| ! ✅ 一致 ✅ 一致 ✅ 一致
短路求值 ✅ ✅ ✅ 一致
结果类型 int（0/1） bool（_Bool） bool
true/false 关键字 无 <stdbool.h> 引入 原生关键字
a < b < c 坑 ✅ 同样错 ✅ 同样错 ✅ 一致

给 C 程序员的关键提醒： 1. C89 的关系/逻辑运算符结果是 int（0/1），C99 引入 _Bool 和 <stdbool.h> 后才有 bool。C++ 从一开始就有原生 bool 类型，true/false 是关键字。但运算符语义完全一致——短路、优先级、a < b < c 坑都一样。 2. 短路求值两边一模一样——b != 0 && a/b 防 除零在 C 和 C++ 都有效。C 程序员的肌肉记忆直接用。 3. C++ 里 bool 能隐式转 int（true→1、false→0），但反过来 int 转 bool（非 0→true、0→false）。C89 里没有 bool，用 int 代替，习惯一致。

常见错误

1. a < b < c 不是"介于两者之间"

if (a < b < c)   // 等价 (a < b) < c

a < b 先算得 bool（0 或 1），再和 c 比。若 a=1, b=2, c=0，1<2 得 true（1），1<0 得 false——但数学上 1 不在 (2, 0) 区间。正确写法：a < b && b < c。C 和 C++ 都有这个坑。

2. & 误用为 &&

if (p != NULL & *p == 5)   // ❌ 先算 *p，p 为 NULL 时崩溃

& 是位与，没有短路——两侧都求值。p != NULL 为 false 时仍会算 *p，解引用 NULL 崩溃。用 && 才短路。C 程序员也踩这个，C++ 同样坑。

3. == 写成 =

if (x = 5)   // ❌ 赋值，不是比较，永远为真（5 非 0）

经典 C 坑，C++ 也有。防范： - C 习惯把常量放左边：if (5 == x)（写成 5 = x 编译报错） - C++ 习惯用 const 或 constexpr，编译器会警告某些 = 误用 - 编译器开 -Wall / /W4，会警告 if (x = 5)

自测题

1. 选择题　a < b < c 在 C++ 中等价于：

  • A. a < b && b < c（数学上的"介于两者之间"）
  • B. (a < b) < c（先比较得 bool，再和 c 比）
  • C. a < (b < c)
  • D. 编译错误
答案

B。< 左结合，a < b < c 等价 (a < b) < c。先算 a < b 得 bool（0/1），再和 c 比较。C 也是同样行为。要"介于两者之间"写 a < b && b < c。

2. 判断题　b != 0 && a / b > 1 中，若 b == 0，a / b 不会被计算。

答案

对。&& 短路求值——左侧 b != 0 为 false 时，右侧 a / b > 1 不求值，避免除零 UB。C 和 C++ 都保证短路。这是用 && 替代 if 防御的常见技巧。

3. 踩坑题　下面这段代码想"指针非空且值为 5 才执行"，哪里有问题？

int* p = get_ptr();
if (p != NULL & *p == 5) {
    do_something();
}
答案

用了 &（位与）而不是 &&（逻辑与）。& 没有短路——两侧都求值。p != NULL 为 false 时仍会算 *p == 5，解引用 NULL 指针是 UB（可能崩溃）。

修复：if (p != NULL && *p == 5)，用 && 短路。或更现代：if (p && *p == 5)（指针在条件上下文隐式转 bool）。

C 程序员也踩这个——& 和 && 的区别两边一样。

4. 应用题　HFT 代码要"订单有效（qty > 0）且价格在合理区间（low <= price <= high）才发单"，用一行表达式写。

答案 
if (order.qty > 0 && low <= order.price && order.price <= high) {
    send_order(order);
}

要点： - && 短路：qty <= 0 时后面不算（虽然这里没副作用，但是好习惯） - low <= price && price <= high 拆成两个比较，不用 low <= price <= high - 用 && 连接三个条件

C 等价写法一模一样：if (order.qty > 0 && low <= order.price && order.price <= high)。

4.4

赋值运算符

本节讲什么

= 与复合赋值 += -= *= /= %= <<= >>= &= ^= |=。

基本规则

  1. = 左侧必须是可修改左值
// 10 = i;           // ❌ 字面量不能当左值
const int a = 1;
// a = 2;            // ❌ const 不可改

  1. 复合赋值等价展开：i += 2 → i = i + 2（但不是简单文本替换，复合形式对类类型可能更高效）

  2. 赋值返回左侧对象，支持连续赋值：

int a, b, c;
a = b = c = 0;   // 从右向左：c=0，返回值赋给 b，再赋给 a

复合赋值也返回左侧引用（类类型时常返回 *this）。

和 C 的区别（赋值运算符：C/C++ 完全一致，类类型有差异）

对比点 C C++
= 左值要求 ✅ 一致 ✅ 一致
复合赋值 += 等 ✅ 一致 ✅ 一致
连续赋值 a=b=c=0 ✅ 右结合 ✅ 一致
返回左侧引用 返回左值（值） 类类型返回 *this 引用
左值可以是… 变量、数组元素、解引用指针 同 C + 类成员、[]/() 重载、迭代器解引用

给 C 程序员的关键提醒： 1. 赋值运算符语义两边一模一样——=、+=、连续赋值、右结合，C 学的直接用。 2. C++ 的"差异"在类类型——string/vector/自定义类的 = 是拷贝赋值运算符（深拷贝），可能触发内存分配。C 里 struct 赋值是 memcpy 级（浅拷贝），C++ 里含 string 成员的 struct 赋值会调 string::operator=（可能分配堆）。 3. C++ 类类型的 += 可能比 = ... + ... 高效——s += "tail" 原地追加，s = s + "tail" 可能产生临时对象。C 里没这个差异（都是字节操作）。

常见错误

1. == 写成 =

if (x = 5)   // ❌ 赋值不是比较，永远为真

经典 C 坑，C++ 也有。防范：常量放左边 if (5 == x)，或开编译器警告。

2. 复合赋值对类类型理解错

std::string s = "hello";
s = s + " world";   // 产生临时 string，可能分配
s += " world";      // 原地追加，更高效

C 里 i = i + 2 和 i += 2 完全等价（都是整数运算）。C++ 里对 string/vector 这类管理资源的类，s = s + x 可能产生临时对象（先算 s + x 得临时，再赋给 s），s += x 原地修改，+= 通常更高效。

3. 连续赋值对类类型有性能陷阱

std::string a, b, c;
a = b = c = "init";   // 三次拷贝赋值，可能三次分配

C 里 a = b = c = 0 是整数赋值，零成本。C++ 里 string 的连续赋值是三次拷贝（每次可能分配）。热路径上避免这种写法，或用移动：a = b = c = std::string("init");（移动语义，第 13 章详讲）。

自测题

1. 选择题　a = b = c = 0 的求值顺序（结合律）是：

  • A. 从左到右：((a = b) = c) = 0
  • B. 从右到左：a = (b = (c = 0))
  • C. 未指定
  • D. 编译错误
答案

B。赋值运算符右结合，a = b = c = 0 等价 a = (b = (c = 0))。先算 c = 0 返回 0，再 b = 0 返回 0，再 a = 0。C 也是同样规则。

2. 判断题　const int x = 5; x = 10; 是合法的赋值。

答案

错。x 是 const，不可修改，x = 10 编译错误。= 左侧必须是可修改左值，const 变量不是可修改的。C 和 C++ 都一样。

3. 踩坑题　C 程序员写下面这段 C++ 代码，性能上有什么可改进？

std::string log;
for (int i = 0; i < 10; ++i) {
    log = log + "[" + std::to_string(i) + "]";
}
答案

每次循环产生多个临时 string：log + "[" 产生临时 1，+ std::to_string(i) 产生临时 2，+ "]" 产生临时 3，最后赋值给 log（可能再分配）。10 次循环约 30+ 次堆分配。

改进用 +=：

std::string log;
log.reserve(64);   // 预留容量
for (int i = 0; i < 10; ++i) {
    log += "[";
    log += std::to_string(i);
    log += "]";
}

+= 原地追加，无临时对象，配合 reserve 几乎零分配。C 程序员习惯 s = s + x（C 里等价 s += x），到 C++ 的 string 要改用 +=。

4. 应用题　C 里写 struct Point p1 = {1, 2}; struct Point p2; p2 = p1; 是合法的浅拷贝。C++ 里对一个含 std::string 成员的 struct 做同样赋值，会发生什么？

答案 
struct Person {
    std::string name;
    int age;
};
Person p1{"Alice", 30};
Person p2;
p2 = p1;   // ✅ 合法，但不是浅拷贝

C++ 里 p2 = p1 调用编译器生成的默认赋值运算符，对每个成员赋值——name 调 string::operator=（深拷贝内部 char 数组），age 直接拷贝。不是 C 的 memcpy 浅拷贝。

  • C 的 struct 赋值是 memcpy（含指针成员会共享堆 → 双 free 风险）
  • C++ 的 struct 赋值是逐成员调 operator=（string/vector 成员会正确深拷贝）

这是 C++ 比 C 安全的地方——含资源管理成员的 struct 赋值不会出错。但如果含裸指针成员，C++ 默认赋值仍是浅拷贝，要按三/五法则手写（见 3.3.5）。

4.5

自增自减

本节讲什么

++ -- 前置与后置的区别——重点考点。

前置 ++i / --i（推荐）

  • 先自增/自减，再返回修改后的对象
  • 返回左值（可继续链式使用）
  • 无多余临时副本，性能更好

后置 i++ / i--

  • 先返回原值的副本（右值），再修改变量
  • 多一次临时，热路径避免
int i = 10;
i += 2;      // i = 12
++i;         // i = 13
int j = i++; // j = 13，i 变为 14
// cout << i << " " << j;  →  14 13

完整示例解析

#include <iostream>

int main() {
    int i = 10;
    i += 2;    // 复合赋值，i = 12
    ++i;       // 前置自增，i = 13
    int j = i++;  // 后置：j 得 13，i 变 14
    std::cout << i << " " << j << std::endl;  // 14 13
    return 0;
}

禁忌

同一表达式中对同一变量多次自增/自减 → 未定义行为：

// int k = i++ + i++;  // ❌ UB

教材建议：默认写 前置 ++i。

和 C 的区别（自增自减：C/C++ 对内置类型一致，C++ 迭代器有差异）

对比点 C C++
内置类型 ++i/i++ ✅ 一致 ✅ 一致
前置返回左值 ✅ ✅ 一致
后置返回右值（原值副本） ✅ ✅ 一致
i++ + i++ UB ✅ UB ✅ 一致
对迭代器用 ++it/it++ 无迭代器 ✅，前置更高效
对类类型重载 ++ 无 C++ 独有（前置 ++t 返回引用，后置 t++ 返回副本）

给 C 程序员的关键提醒： 1. 内置类型上 C 和 C++ 完全一致——int i; ++i; i++; 的语义、返回值、UB 坑都一样。C 的肌肉记忆直接用。 2. C++ 的"差异"在迭代器和类类型——对 vector<int>::iterator 用 ++it 比 it++ 高效（后置要拷贝旧迭代器）。C 里 p++ 和 ++p 对裸指针一样快，但到 C++ 迭代器要改习惯。 3. HFT 热路径上 ++i 是"免费"的优化——内置类型虽然差异微乎其微，但迭代器/复杂类型上前置 ++ 省一次拷贝。养成 ++i 习惯，代码换类型不用改。

常见错误

1. i++ + i++ 以为"先取 i 再取 i+1"

int i = 1;
int k = i++ + i++;   // ❌ UB

C 程序员也踩这个——两边都是 UB。两个 i++ 在同一表达式中对 i 修改两次，且修改无顺序保证。拆开：int tmp1 = i++; int tmp2 = i++; int k = tmp1 + tmp2;。

2. 对迭代器用后置 it++

for (auto it = v.begin(); it != v.end(); it++) { ... }   // 能跑但低效

it++ 后置要拷贝旧迭代器返回再前进，循环里每次多一次拷贝。改 ++it：

for (auto it = v.begin(); it != v.end(); ++it) { ... }

C 里 p++ 和 ++p 对裸指针一样快，但 C++ 迭代器要换习惯。

3. 误以为后置 i++ 比 ++i "更安全"

// 误以为 ++i "太激进"，i++ "更温和"

错。两者对 i 的修改效果完全相同（都让 i 加 1），区别只在返回值——++i 返回修改后的 i，i++ 返回修改前的副本。单独写 ++i; 或 i++;（不用返回值）时两者完全等价。推荐 ++i 是因为对类类型/迭代器更高效，不是"更激进"。

自测题

1. 选择题　int i = 5; int j = ++i; 之后 i 和 j 的值分别是：

  • A. i=5, j=6
  • B. i=6, j=5
  • C. i=6, j=6
  • D. i=5, j=5
答案

C。前置 ++i 先让 i 变 6，再返回 i（6），赋给 j。所以 i=6, j=6。若用后置 i++：先返回 i 的原值（5）赋给 j，再让 i 变 6，结果 i=6, j=5。C 也是同样规则。

2. 判断题　对内置 int 类型，++i 和 i++ 在性能上有显著差异。

答案

错。内置类型上 ++i 和 i++ 性能几乎无差异（编译器优化后一样）。差异主要体现在类类型和迭代器——后置 i++ 要拷贝旧值返回，前置 ++i 直接返回引用。推荐 ++i 是为了在所有类型上都高效，养成习惯。

3. 踩坑题　下面这段代码哪里是 UB？

int i = 0;
int a = i++ + ++i;       // ①
int b = i++ + i++;       // ②
v[i] = i++;              // ③
答案

三个都是 UB： - ① i++ 和 ++i 在同一表达式对 i 修改两次，无序 → UB - ② 两个 i++ 同上 → UB - ③ v[i] 的下标 i 和右侧 i++ 修改 i 无序 → UB

C 里也都是 UB。修复：拆成多条语句，每个表达式只对同一变量修改一次。

4. 应用题　C 程序员写惯了 for (i = 0; i < n; i++)，到 C++ 遍历 vector 时应该怎么改？为什么？

答案 
// C 习惯（能跑但低效）
for (auto it = v.begin(); it != v.end(); it++) { ... }

// C++ 推荐
for (auto it = v.begin(); it != v.end(); ++it) { ... }

原因：it++ 后置要拷贝旧迭代器返回再前进，每次循环多一次拷贝。++it 前置直接前进返回引用，无拷贝。对内置 int 无差异，对迭代器有差异。

C 程序员习惯 i++ 是因为 C 里只有裸指针/整数，++ 和 i++ 等价。到 C++ 遍历容器要改 ++it。

更现代的写法用范围 for：

for (auto& x : v) { ... }   // 不用手写 ++ 或 it

4.6

成员访问运算符

本节讲什么

. 点运算符与 -> 箭头运算符；与 * 的优先级陷阱。

. 与 ->

运算符 作用于 示例
. 对象 / 引用 obj.member、s.size()
-> 指针 ptr->member，等价 (*ptr).member 
#include <string>

std::string s = "test";
std::string *p = &s;

s.size();      // 点：对象
p->size();     // 箭头：指针
(*p).size();   // 与 -> 等价

// *p.size();  // ❌ . 优先级高于 *，等价 *(p.size())，编译错误

string、vector、自定义类成员访问都遵循此规则（见 3.2、7.1 类基础）。

和 C 的区别（成员访问：C/C++ 一致，C++ 多了引用和重载）

对比点 C C++
. 点运算符 ✅ 一致（struct 成员） ✅ 一致（struct/class 成员）
-> 箭头运算符 ✅ 一致（指针访问成员） ✅ 一致
(*p).member ≡ p->member ✅ ✅ 一致
. 优先级高于 * ✅ ✅ 一致
作用于引用 C 无引用 C++ 独有：引用用 .，像对象
成员函数 C struct 无成员函数 C++ class/struct 有成员函数 s.size()
-> 可重载 不能 智能指针/迭代器重载 ->

给 C 程序员的关键提醒： 1. . 和 -> 的选择规则两边一致——有对象/引用用 .，有指针用 ->。C 程序员的肌肉记忆直接用。 2. C++ 多了"引用"——引用在语法上像对象，用 .：

cpp std::string s = "hi"; std::string& r = s; // r 是引用，不是指针 r.size(); // ✅ 用 .，不是 ->

C 程序员习惯了"非对象即指针"，到 C++ 要加上"还有引用，引用用 ."。 3. C++ 的 -> 可重载——智能指针（unique_ptr、shared_ptr）和迭代器重载了 ->，让它们能像裸指针一样访问成员：

cpp std::unique_ptr<std::string> up = std::make_unique<std::string>("hi"); up->size(); // ✅ up 是智能指针，重载了 ->

C 里 -> 只对裸指针生效。

常见错误

1. *p.member 优先级错

std::string *p = &s;
std::cout << *p.size();   // ❌ 等价 *(p.size())，p 是指针没有 size 成员

. 优先级高于 *，所以 *p.size() 先算 p.size()（但 p 是指针没有 size 成员，编译错误）。正确写法：(*p).size() 或 p->size()。C 里 *p.field 同样错（p 是 struct 指针时），规则一致。

2. 对引用用 ->

std::string s = "hi";
std::string& r = s;
r->size();   // ❌ r 是引用不是指针，编译错误

引用在语法上像对象，用 .：r.size()。-> 只用于指针。C 程序员没有引用概念，容易把引用当指针用。

3. 智能指针忘了 -> 能用

std::unique_ptr<std::string> up = std::make_unique<std::string>("hi");
(*up).size();   // ✅ 能用但啰嗦
up->size();     // ✅ 推荐，智能指针重载了 ->

智能指针重载了 ->，能像裸指针一样访问成员。C 程序员从裸指针迁移到智能指针时，-> 习惯不用改。

自测题

1. 选择题　std::string s; std::string* p = &s; 下列哪种访问 s.size() 的方式错误？

  • A. s.size()
  • B. p->size()
  • C. (*p).size()
  • D. *p.size()
答案

D。*p.size() 等价 *(p.size())——. 优先级高于 *，先算 p.size()，但 p 是指针没有 size 成员，编译错误。正确写法是 (*p).size()（括号改变优先级）或 p->size()（箭头运算符）。C 里同样规则。

2. 判断题　std::string& r = s; r->size(); 是合法的成员访问。

答案

错。r 是引用，不是指针，用 . 不用 ->。r->size() 编译错误。引用在语法上像对象，r.size() 才对。C 程序员没有引用概念，容易把引用当指针用 ->。

3. 踩坑题　C 程序员写下面这段 C++ 代码，哪里有问题？

struct Order { int qty; double price; };
Order* p = get_order();
if (*p.price > 0) {       // 检查价格
    send_order(*p);
}
答案

*p.price 优先级错——. 高于 *，等价 *(p.price)，但 p 是指针没有 price 成员，编译错误。

修复（两种）：

if ((*p).price > 0) { ... }   // 括号改变优先级
if (p->price > 0) { ... }     // 推荐用 ->

C 里 (*p).price 和 p->price 也都合法，C 程序员的习惯直接迁移——只是 C++ 里这个坑更容易踩，因为类类型成员访问更频繁。

4. 应用题　用智能指针 std::unique_ptr<std::vector<int>> 创建一个 vector，访问其 size() 和第一个元素。

答案 
#include <memory>
#include <vector>

auto uv = std::make_unique<std::vector<int>>(std::initializer_list<int>{1, 2, 3});
// 或：std::unique_ptr<std::vector<int>> uv(new std::vector<int>{1,2,3});

std::cout << uv->size() << "\n";      // 3，智能指针重载了 ->
std::cout << (*uv)[0] << "\n";        // 1，先解引用得 vector，再下标
std::cout << uv->at(1) << "\n";       // 2，-> 访问成员函数

// 注意：uv[0] 不行——uv 是智能指针不是 vector，没有下标运算符

要点： - 智能指针重载 ->，能像裸指针一样访问成员 - (*uv)[0] 先解引用得 vector 引用，再下标 - uv->at(1) 通过 -> 访问 vector 的成员函数

C 程序员用 malloc/free 管理 vector*，C++ 用 unique_ptr 自动释放，但访问语法 -> 一致。

4.7

条件运算符

本节讲什么

C++ 唯一三元运算符 cond ? expr1 : expr2。

规则

  • 条件为 真 → 计算并返回 expr1 的值
  • 条件为 假 → 计算并返回 expr2 的值
  • 两分支类型须能统一（可能隐式转换）

嵌套

// grade > 90 ? "A" : grade > 60 ? "B" : "C"

优先级陷阱（必考）

?: 优先级很低，与 << 混用时必须加括号：

int grade = 75;
std::cout << (grade < 60 ? "fail" : "pass");  // ✅
// std::cout << grade < 60 ? "fail" : "pass"; // ❌ 等价 (cout<<grade)<60 ? ...

和 C 的区别（条件运算符：C/C++ 完全一致）

条件运算符是 C 和 C++ 完全共享的语法——cond ? a : b 的语义、优先级、结合律（右结合）、类型统一规则都一样：

对比点 C C++
cond ? a : b 语法 ✅ 一致 ✅ 一致
右结合 ✅ ✅ 一致
优先级很低（仅高于 = 和 ,） ✅ ✅ 一致
两分支类型须统一 ✅（隐式转换） ✅ 一致，但 C++ 更严格（左值分支）
?: 可作左值 ❌ ✅ C++ 独有（条件表达式可作左值，见下文）

给 C 程序员的关键提醒： 1. 条件运算符 99% 一样——语法、优先级、嵌套、<< 混用加括号，C 学的直接用。 2. C++ 多了"条件表达式可作左值"——((cond) ? a : b) = value; 在 C++ 合法（条件为真改 a，假改 b），C 里不行。但这种写法可读性差，不推荐。 3. C++ 的类型检查更严——两分支类型不同时，C 会做隐式转换（可能丢信息），C++ 也会转但编译器警告更积极。

常见错误

1. ?: 与 << 混用不加括号

std::cout << grade < 60 ? "fail" : "pass";   // ❌

<< 优先级高于 ?:，等价 (std::cout << grade) < 60 ? "fail" : "pass"——先输出 grade，再把 cout 和 60 比（无意义），最后条件判断。修复：std::cout << (grade < 60 ? "fail" : "pass");。C 里 printf 没这个坑（printf("%s", grade<60?"fail":"pass")），C++ 的 << 容易踩。

2. 嵌套 ?: 不加括号可读性差

grade > 90 ? "A" : grade > 60 ? "B" : "C"   // 能跑但难读

?: 右结合，所以这等价 grade > 90 ? "A" : (grade > 60 ? "B" : "C")，逻辑对但可读性差。复杂条件用 if-else：

char grade_letter;
if (grade > 90) grade_letter = 'A';
else if (grade > 60) grade_letter = 'B';
else grade_letter = 'C';

3. 两分支类型不匹配导致意外转换

auto x = cond ? 1 : 2.5;   // x 类型是 double（1 隐式转 double）

两分支类型不同时，编译器会做隐式转换统一——1（int）和 2.5（double）统一为 double。若不注意，可能丢失信息或改变类型。显式统一：cond ? 1.0 : 2.5 或 cond ? static_cast<double>(1) : 2.5。

自测题

1. 选择题　?: 运算符的结合律是：

  • A. 左结合
  • B. 右结合
  • C. 未指定
  • D. 取决于编译器
答案

B。?: 右结合，a ? b : c ? d : e 等价 a ? b : (c ? d : e)。C 也是右结合，完全一致。赋值 =、一元运算符、?: 是少数右结合的运算符。

2. 判断题　std::cout << x < 0 ? "neg" : "pos"; 能正确打印 x 的正负。

答案

错。<< 优先级高于 ?:，等价 (std::cout << x) < 0 ? "neg" : "pos"——先输出 x，再把 cout 和 0 比（无意义），最后条件判断结果总是 "pos" 或 "neg" 但没输出。修复：std::cout << (x < 0 ? "neg" : "pos");，加括号。C 里 printf 没这个坑。

3. 踩坑题　下面这段代码想根据 flag 选 a 或 b 赋值给 target，哪里有问题？

int a = 10, b = 20;
int target = 0;
flag ? a : b = 100;   // 想把选中的变量改为 100
答案

flag ? a : b = 100 在 C 里是 UB 或语义错——?: 优先级高于 =，等价 (flag ? a : b) = 100。C++ 里条件表达式可作左值（C 不行），所以C++ 能编译（flag 为真改 a，假改 b），但可读性极差。

更清晰的写法：

if (flag) a = 100; else b = 100;
// 或
(flag ? a : b) = 100;   // C++ 合法但不推荐

C 里这种写法编译错误或行为错，C++ 能过但别这么写。

4. 应用题　用 ?: 写一个 abs 函数，返回 x 的绝对值。

答案 
int my_abs(int x) {
    return x < 0 ? -x : x;
}

要点： - x < 0 为真返回 -x，假返回 x - 注意 -INT_MIN 是 UB（见 4.2），生产代码要处理 - C 等价写法一模一样：return x < 0 ? -x : x;

C 程序员的 ?: 习惯直接迁移，C++ 无差异。

位运算符

本节讲什么

~ << >> & | ^——教材建议只对无符号整数使用。

各运算符

运算符 含义
~ 按位取反
<< 左移：右侧丢弃，左侧补 0；等价 × 2ⁿ（无溢出时）
>> 右移：无符号左侧补 0；有符号补符号位（实现相关，不推荐）

unsigned flags = 0x01;

与逻辑运算符区别

  • & | ^：无短路，两侧都求值
  • && ||：短路（见 4.3）

HFT 典型用途

协议标志位、权限掩码、快速 ×2 / ÷2（无符号左移/右移）；解析二进制字段时常与 unsigned 掩码配合。

和 C 的区别（位运算符：C/C++ 完全一致）

位运算符是 C 和 C++ 完全共享的部分——~ << >> & | ^ 的语义、整型提升、有符号右移实现相关，两边一字不差：

对比点 C C++
~ & \| ^ 按位运算 ✅ 一致 ✅ 一致
<< 左移补 0 ✅ ✅ 一致
>> 有符号补符号位（实现相关） ✅ ✅ 一致
>> 无符号补 0 ✅ ✅ 一致
整型提升（char/short → int） ✅ ✅ 一致
&/\| 无短路 ✅ ✅ 一致
有符号左移溢出 UB ✅ ✅ 一致

给 C 程序员的关键提醒： 1. 位运算符无需任何转变——C 学的"位运算心法"直接用。掩码、置位、测位、异或交换、x & (x-1) 消最低位 1 这些技巧两边通用。 2. 教材建议"只对无符号用位运算"两边都适用——有符号右移补符号位是实现相关（不同编译器可能不同），有符号左移溢出是 UB。用 unsigned/uint32_t 做位运算是跨平台安全的做法。 3. C++ 多了 std::bitset——固定大小位集合，比手写 unsigned flags 更安全（自带边界检查、[] 访问位、to_string/to_ulong 转换）。但 HFT 热路径仍用 uint64_t + 位运算（零开销）。

常见错误

1. 对有符号整数右移

int x = -8;
int y = x >> 1;   // 实现相关：可能是 -4（算术右移）或大正数（逻辑右移）

有符号右移补符号位（算术右移）还是补 0（逻辑右移）是实现相关——x86/GCC/Clang 补符号位，某些嵌入式平台补 0。用 unsigned 保证补 0。C 和 C++ 都有这个坑。

2. & 误用为 &&

if (flags & 0x01) { ... }      // ✅ 测位：flags 和 0x01 按位与，非 0 为真
if (flags && 0x01) { ... }     // ❌ 逻辑与：flags 非 0 且 0x01 非 0（恒真）

& 是位与，&& 是逻辑与。测位用 &，逻辑判断用 &&。C 程序员分得清，但 C++ 里 bool 和 int 隐式转换更容易混。

3. 移位位数超过类型宽度

int x = 1;
int y = x << 32;   // ❌ UB（int 通常 32 位，移 32 位未定义）

移位位数 >= 类型位宽是 UB（C 和 C++ 都一样）。int 32 位时 << 32、<< 33、<< 100 都是 UB。确保移位位数 < sizeof(T)*8。

自测题

1. 选择题　unsigned x = 0xF0; x & 0x0F 的结果是：

  • A. 0xF0
  • B. 0x0F
  • C. 0xFF
  • D. 0x00
答案

D。0xF0（11110000）和 0x0F（00001111）按位与，每位都不同，结果是 0x00。这是"掩码取低位"的反例——x & 0x0F 取 x 的低 4 位，但 x = 0xF0 的低 4 位是 0。C 也是同样运算。

2. 判断题　int x = -1; x >> 1 的结果在所有 C++ 实现上都相同。

答案

错。有符号右移是实现相关——x86/GCC/Clang 补符号位（算术右移），-1 >> 1 还是 -1；某些嵌入式平台补 0（逻辑右移），-1 >> 1 是大正数。用 unsigned 保证补 0，跨平台一致。C 也有同样问题。

3. 踩坑题　HFT 代码用位运算快速除以 2，哪里有问题？

int qty = -10;
int half = qty >> 1;   // 想得到 -5
答案

结果实现相关。qty 是 int（有符号），>> 1 在 x86/GCC/Clang 上补符号位（算术右移）得 -5，但在补 0 的平台上得大正数。修复：

// 方法 1：用除法（编译器会优化为右移）
int half = qty / 2;   // 总是 -5，跨平台一致

// 方法 2：用 unsigned（但会改变负数语义）
// unsigned 不能表示 -10，要先转

// 方法 3：HFT 常用定点小数，用 int64_t + 显式除法

C 程序员习惯用 >> 1 替代 / 2（快），但对负数不安全。现代编译器会把 / 2 优化成右移，无需手写 >>。

4. 应用题　用位运算实现"置位、清位、测位、翻转位"四个操作，操作 flags 的第 n 位。

答案 
unsigned flags = 0;
int n = 3;   // 操作第 3 位（0-indexed）

flags |= (1u << n);       // 置位：或上 1<
flags &= ~(1u << n);      // 清位：与上 ~(1<
bool set = flags & (1u << n);   // 测位：与 1<
flags ^= (1u << n);       // 翻转位：异或 1<<

要点： - 用 1u（unsigned）避免有符号移位问题 - n 必须 < sizeof(unsigned)*8（通常 32），否则 UB - C 程序员的位运算心法直接迁移，C++ 无差异

C++ 还可用 std::bitset：

std::bitset<32> flags;
flags.set(n);      // 置位
flags.reset(n);    // 清位
flags.test(n);     // 测位
flags.flip(n);     // 翻转

更安全但稍有开销，HFT 热路径仍用 unsigned + 位运算。

4.9

sizeof 运算符

本节讲什么

计算类型或表达式占用的字节数；返回 size_t（无符号）。

两种写法

sizeof(int);     // 类型
sizeof(var);     // 表达式（一般不求值 var，见下）
sizeof var;      // 变量可省略括号（不推荐与类型混淆）

两大特性（必考）

1. 数组名 vs 指针

int arr[10];
sizeof(arr);     // 整个数组：10 * sizeof(int)
int *p = arr;
sizeof(p);       // 指针大小，如 8（64 位）

数组不退化的例外之一（见 3.5.3）。

2. 不对指针解引用

int *p = nullptr;
sizeof(*p);      // ✅ 只算 int 的大小，不访问 *p，不崩溃

用途

  • 估算结构体/数组占用
  • sizeof(arr)/sizeof(arr[0]) 得数组元素个数（仅当 arr 仍是数组名时）

和 C 的区别（sizeof：C/C++ 几乎一致，C++ 多了成员/类类型支持）

对比点 C C++
sizeof(type) ✅ 一致 ✅ 一致
sizeof(expr) ✅ 一致 ✅ 一致
返回 size_t ✅ ✅ 一致
数组不退化 ✅ ✅ 一致
不求值操作数 ✅ ✅ 一致
sizeof 类/struct 成员 C99 起部分支持 ✅ 完整支持
sizeof 类类型本身 C 无 class ✅
编译期常量 ✅（除 VLA） ✅（C++ 无 VLA，恒编译期）

给 C 程序员的关键提醒： 1. sizeof 语义两边几乎一致——sizeof(int)、sizeof(arr)、sizeof(arr)/sizeof(arr[0]) 这些用法 C 学的直接用。 2. C++ 多了对类类型的支持——sizeof(std::string)、sizeof(std::vector<int>)、sizeof(MyClass) 都合法。但要注意：sizeof(std::string) 是 string 对象本身的大小（通常 24/32 字节），不是字符串内容长度（用 s.size()）。 3. C 的 VLA 让 sizeof 可能是运行期——C99 的 VLA int arr[n]; 让 sizeof(arr) 在运行期求值。C++ 不支持 VLA（标准层面），sizeof 恒编译期常量。这是少数 C++ 比 C 更"静态"的地方。

常见错误

1. 数组传参后 sizeof 拿不到长度

void f(int arr[]) {
    size_t n = sizeof(arr) / sizeof(arr[0]);   // ❌ arr 退化指针，n = 8/4 = 2
}

数组传参退化为指针，sizeof(arr) 是指针大小。C 和 C++ 都有这个坑。用 std::array/vector 或模板引用避开。

2. sizeof(string) 误以为是字符串长度

std::string s = "hello";
std::cout << sizeof(s);   // 24 或 32（string 对象大小），不是 5
std::cout << s.size();    // 5（字符串长度）

sizeof(std::string) 是 string 对象本身的字节大小（固定，通常 24/32 字节，含指针/长度/容量），不是字符串内容长度。内容长度用 s.size() 或 s.length()。C 程序员习惯了 sizeof(char[]) 算字符数组长度，到 string 要改用 size()。

3. sizeof(*nullptr) 以为会崩

int* p = nullptr;
std::cout << sizeof(*p);   // ✅ 4（int 大小），不崩溃

sizeof 的操作数不求值——编译器只看类型，不执行解引用。所以 sizeof(*p) 安全，等于 sizeof(int)。但别依赖这个写运行期代码——*p 在运行期仍是 UB，只是 sizeof 上下文不求值。

自测题

1. 选择题　int arr[5]; int* p = arr; 下列哪个表达式返回指针大小（而非数组大小）？

  • A. sizeof(arr)
  • B. sizeof(arr[0])
  • C. sizeof(p)
  • D. sizeof(*p)
答案

C。sizeof(p) 是指针大小（如 8 字节，64 位）。sizeof(arr) 是整个数组大小（5*4=20）；sizeof(arr[0]) 是单个 int 大小（4）；sizeof(*p) 是 int 大小（4）。C 也是同样规则。

2. 判断题　std::string s = "hello"; sizeof(s) 返回 5。

答案

错。sizeof(s) 返回 std::string 对象本身的字节大小（固定，通常 24 或 32 字节，含内部指针/长度/容量），不是字符串内容长度。内容长度用 s.size()（返回 5）。C 程序员习惯 sizeof(char[]) 算字符数组长度，到 string 要改用 size()。

3. 踩坑题　C 程序员写下面这段 C++ 代码，想算数组长度，哪里有问题？

void process(int arr[]) {
    size_t n = sizeof(arr) / sizeof(arr[0]);
    for (size_t i = 0; i < n; ++i) {
        std::cout << arr[i] << " ";
    }
}
答案

sizeof(arr) 在函数内是指针大小，不是数组大小。数组传参退化为指针，sizeof(arr) 是 8（64 位指针），sizeof(arr[0]) 是 4，n = 8/4 = 2，只打印前 2 个元素。

修复（三种）：

// 方法 1：C 风格，另传长度
void process(int* arr, size_t n);

// 方法 2：C++ 模板引用数组，保留类型
template <size_t N>
void process(int (&arr)[N]) {
    for (size_t i = 0; i < N; ++i) std::cout << arr[i] << " ";
}

// 方法 3：用 std::array 或 vector
void process(const std::vector<int>& v);

C 程序员习惯了"另传 n"，C++ 推荐用容器或模板引用避开退化。

4. 应用题　写一个模板函数 array_size，编译期返回任意内置数组的元素个数。

答案 
#include <cstddef>

template <typename T, size_t N>
constexpr size_t array_size(const T (&)[N]) {
    return N;
}

// 用法
int arr[10];
constexpr size_t n = array_size(arr);   // 编译期得 10
double vals[5];
constexpr size_t m = array_size(vals);  // 5

要点： - const T (&)[N] 是"对数组的引用"，不退化 - 模板推导自动得 N，函数内返回 N - constexpr 让结果可在编译期使用（C++ 独有，替代 #define 那种宏）

C 没有这种能力——C 的数组传参必然退化，只能 #define ARRAY_SIZE(a) (sizeof(a)/sizeof((a)[0])) 用宏，但宏在传参后同样失效。

C++17 起还有 std::size(arr)，直接返回数组长度。

4.10

逗号运算符

本节讲什么

逗号运算符 , 的求值顺序与返回值；与函数参数逗号、初始化列表逗号的区别。

规则

  • 从左到右依次求值每个子表达式
  • 整个表达式的值 = 最右侧子表达式的值
  • 优先级最低（见 4.12）
int a = (1, 2, 3);   // a == 3

典型用途：for 多变量

for (int i = 0, j = 10; i < j; ++i, --j)
    /* ... */;

不是逗号运算符的情况

场景 逗号含义
f(a, b) 函数参数分隔
int a{1, 2, 3} 初始化列表（容器/数组）
int i, j; 声明分隔多个变量

教材建议：少滥用逗号运算符写复杂表达式，可读性差。

和 C 的区别（逗号运算符：C/C++ 完全一致）

逗号运算符是 C 和 C++ 完全共享的语法——求值顺序（从左到右）、返回值（最右侧）、优先级（最低），两边一字不差：

对比点 C C++
, 从左到右求值 ✅ 一致 ✅ 一致
返回最右侧值 ✅ ✅ 一致
优先级最低 ✅ ✅ 一致
for (i=0, j=10; ...; ++i, --j) ✅ ✅ 一致
函数参数逗号不是运算符 ✅ ✅ 一致
声明逗号不是运算符 ✅ ✅ 一致
重载 , 不能 C++ 能（但极少推荐）

给 C 程序员的关键提醒： 1. 逗号运算符两边完全一样——C 学的用法直接迁移。for 多变量、(expr1, expr2) 顺序求值，语义一致。 2. C++ 允许重载 ,（类类型可定义 operator,），但强烈不推荐——重载后失去短路顺序保证（无法保证左侧先求值），且语义混乱。标准库和现代 C++ 几乎不重载 ,。 3. C++ 初始化列表的逗号不是运算符——int a[] = {1, 2, 3};、vector<int> v{1, 2, 3}; 里的逗号是分隔符，不触发逗号运算符。C 里同样规则。

常见错误

1. 函数参数逗号误当运算符

f(a, b);   // 这是两个参数，不是逗号运算符
f((a, b)); // 这才是一个参数：先算 a，再算 b，传 b 给 f

f(a, b) 是调用 f 传两个参数；f((a, b)) 是调用 f 传一个参数（逗号表达式的结果 b）。两者完全不同，别混淆。

2. 逗号运算符滥用降低可读性

int x = (a++, b++, a + b);   // 能跑但难读

虽然合法（先 a++、再 b++、返回 a+b），但可读性差。拆成多条语句：

++a;
++b;
int x = a + b;

3. for 的逗号混淆

for (int i = 0, j = 10; i < j; ++i, --j) { ... }

这里有两个逗号： - int i = 0, j = 10 是声明逗号（同时声明 i 和 j） - ++i, --j 是逗号运算符（顺序执行 ++i 和 --j）

别混淆。声明逗号不是运算符，不返回值。

自测题

1. 选择题　int a = (1, 2, 3); 之后 a 的值是：

  • A. 1
  • B. 2
  • C. 3
  • D. 编译错误
答案

C。逗号运算符从左到右求值，返回最右侧值。(1, 2, 3) 先算 1（丢弃）、再算 2（丢弃）、最后算 3（返回），所以 a = 3。C 也是同样规则。

2. 判断题　f(a, b) 和 f((a, b)) 等价。

答案

错。f(a, b) 调用 f 传两个参数 a 和 b；f((a, b)) 调用 f 传一个参数（逗号表达式的结果 b，a 被求值但丢弃）。两者完全不同。函数参数的逗号是分隔符，不是逗号运算符。

3. 踩坑题　下面这段代码用逗号运算符"同时更新两个变量"，可读性如何？怎么改？

for (int i = 0, j = n - 1; i < j; i++, j--) {
    swap(arr[i], arr[j]);
}
答案

这个用法是合理的——for 循环里用逗号运算符同时更新 i 和 j 是常见且可接受的写法。C 和 C++ 都这么写。

但若循环体复杂，可读性要求高时，可改用 while：

int i = 0, j = n - 1;
while (i < j) {
    swap(arr[i], arr[j]);
    ++i;
    --j;
}

要点：for 里的逗号运算符（i++, j--）是合理用法，别滥用到循环体外。

4. 应用题　C 程序员写下面这段代码，C++ 里行为如何？

int i = 0;
int x = (i++, i++, i++);
std::cout << x << " " << i;
答案

输出 2 3。

  • i++ 第一次：返回 0（i 变 1），丢弃
  • i++ 第二次：返回 1（i 变 2），丢弃
  • i++ 第三次：返回 2（i 变 3），这是逗号表达式的返回值
  • x = 2，i = 3

C 和 C++ 行为完全一致——逗号运算符从左到右，返回最右。但这种写法可读性差，生产代码别这么写，拆成多条语句更清晰。

4.11

.1 隐式类型转换

本节讲什么

编译器无提示、自动完成的类型转换——发生在运算、赋值、初始化、传参等场景。

1. 整型提升（最基础）

小于 int 的小整型（char / short / bool）参与运算时，先提升为 int；若 int 放不下则提升为 unsigned int。

char c = 'a';
auto res = c + 10;   // c 先提升为 int 再计算

HFT 解析单字节字段时，char 参与算术前几乎总会先变 int——与 3.2.5 unsigned char 配合，避免符号扩展坑。

2. 常用算术转换（混合运算）

向范围更大、精度更高的类型转换，尽量避免精度丢失：

  • 有浮点 → 全部转浮点（int + double → int 转 double）
  • 全整型：无符号优先级常高于有符号；宽度小的转宽度大的
int a = 3;
double b = 3.14;
auto sum = a + b;    // a 隐式转为 double

3. 数组 → 指针（高频）

绝大多数场景数组名退化为首元素指针。

不退化例外：sizeof(arr)、&arr、用字符串字面量初始化 char 数组（见 3.5.3）。

int arr[5];
int *p = arr;        // 等价 &arr[0]

4. 指针相关隐式转换

转换 说明
0 / nullptr → 任意指针 空指针
非 const 对象指针 → void* 通用指针
非 const 指针/引用 → 对应 const 版 只加 const，不能反向 
int i = 10;
const int &r = i;    // ✅ 普通引用 → const 引用
// int &r2 = r;      // ❌ 不能去掉 const

与 2.4.1 底层 const 一致。

5. 布尔转换（条件判断）

标量（数字、指针）在条件上下文转 bool：

  • 0、空指针 → false
  • 非 0、有效指针 → true
int x = 5;
if (x) { /* true */ }

int *p = nullptr;
while (p) { /* false，不进入 */ }

6. 赋值 / 初始化 / 传参

右侧、实参自动转为左侧、形参类型：

double d = 3.99;
int i = d;           // double → int，**截断小数**，i == 3（非四舍五入）

HFT：价格 double 隐式赋给 int 会静默丢小数——业务层应显式处理或统一用定点/整数价位。

和 C 的区别（隐式类型转换：C/C++ 几乎一致，C++ 对 bool 更严格）

隐式类型转换是 C 和 C++ 高度共享的部分——整型提升、算术转换、数组退化、指针转换、布尔转换，两边规则几乎一字不差：

对比点 C C++
整型提升（char/short → int） ✅ 一致 ✅ 一致
算术转换（向更宽/浮点转） ✅ 一致 ✅ 一致
数组 → 指针退化 ✅ 一致 ✅ 一致
0 → 空指针 ✅ 一致 ✅ 一致，但推荐 nullptr
指针 → void* ✅ 一致 ✅ 一致
加 const ✅ 一致 ✅ 一致
非 0 → true、0 → false ✅（C89 用 int） ✅（C++ 有原生 bool）
浮点 → 整型截断 ✅ 一致 ✅ 一致
void* → 其他指针 ✅ 隐式转换 ❌ 必须 static_cast

给 C 程序员的关键提醒： 1. 隐式转换规则两边几乎一致——整型提升、算术转换、数组退化这些 C 学的"坑"全部迁移。C 程序员的警惕心直接用。 2. C++ 比 C 严格的地方：void* 不能隐式转其他指针——C 里 int* p = malloc(...)（malloc 返回 void*）合法，C++ 里 int* p = malloc(...) 编译错误，必须 int* p = static_cast<int*>(malloc(...)); 或用 new。这是 C++ 类型系统更严格的体现。 3. C++ 推荐 nullptr 替代 0/NULL——0 在 C++ 里既是整数又是空指针（重载歧义），nullptr 是专门的空指针字面量（类型 nullptr_t），不会和整数混淆。详见 2.3.2。

常见错误

1. 浮点转整型静默截断

double price = 3750.99;
int rounded = price;   // 3750，不是 3751（截断非四舍五入）

C 程序员也踩这个——两边都是截断小数，不是四舍五入。要四舍五入用 std::lround(price) 或 static_cast<int>(price + 0.5)（正数）。HFT 价格通常用定点整数（如"厘"为单位），避开浮点。

2. 有符号和无符号混用导致负数变大正数

int i = -1;
unsigned n = 10;
if (i < n) { ... }   // ❌ false！i 转为 unsigned 变成 4294967295

有符号和无符号比较时，有符号隐式转为无符号——-1 变成 UINT_MAX（巨大正数），< n 为 false。C 和 C++ 都有这个坑。用 size_t 时尤其小心，下标和负数比较容易踩。

3. char 符号扩展

char c = 0x80;          // 有符号 char，值为 -128
int i = c;              // 符号扩展，i = -128（不是 128）
unsigned char uc = 0x80;
int j = uc;             // 零扩展，j = 128

char 是否有符号实现相关（x86 通常有符号，ARM 通常无符号）。char 转 int 时若有符号会符号扩展（高位补 1）。处理二进制字节用 unsigned char 或 std::byte。C 程序员也踩这个，C++ 同样坑。

自测题

1. 选择题　int i = -1; unsigned u = 1; 下列哪个表达式为 true？

  • A. i < u
  • B. i > u
  • C. i == u
  • D. 编译错误
答案

B。i < u 比较时，i（int -1）隐式转为 unsigned，变成 UINT_MAX（4294967295），UINT_MAX > 1 为 true，所以 i > u 为 true。这是有符号/无符号混用的经典坑。C 也是同样行为。避免混用，或显式 static_cast<int>(u) 比较。

2. 判断题　double d = 3.99; int i = d; 之后 i 的值是 4（四舍五入）。

答案

错。浮点转整型是截断小数（向零取整），不是四舍五入。i = 3，不是 4。要四舍五入用 std::lround(d) 或 static_cast<int>(d + 0.5)（正数）。C 程序员也踩这个，两边一致。

3. 踩坑题　C 程序员写下面这段 C++ 代码，哪里编译失败？

void* p = malloc(100);
int* ip = p;   // 想用 malloc 分配 int 数组
答案

int* ip = p; 编译错误——C++ 不允许 void* 隐式转 int*（C 允许）。C 程序员的 int* ip = malloc(...) 习惯到 C++ 要改。

修复（三种）：

// 方法 1：C++ 显式转换
int* ip = static_cast<int*>(malloc(100 * sizeof(int)));

// 方法 2：用 new（C++ 推荐）
int* ip = new int[100];

// 方法 3：用 vector（最推荐）
std::vector<int> v(100);

C++ 的 new/vector 比 malloc 更安全（类型安全、调用构造函数、RAII），优先用。

4. 应用题　HFT 代码读一个 unsigned char 字节，想转成 int 做算术，如何避免符号扩展坑？

答案 
unsigned char byte = read_byte();   // 0..255
int value = byte;                    // ✅ 零扩展，value = 0..255

// 对比：若用 char
char c = read_byte();               // 若 byte >= 128，c 是负数
int wrong = c;                      // ❌ 符号扩展，可能变负数
int fixed = static_cast<unsigned char>(c);  // ✅ 先转 unsigned char 再转 int

要点： - 处理二进制字节用 unsigned char（或 C++17 的 std::byte），不用 char - unsigned char 转 int 是零扩展，不会变负数 - char 转 int 是符号扩展，可能变负数

C 程序员也踩这个——<cctype> 函数（isalpha 等）要求 unsigned char 转 int 参数，传 char 可能 UB。

4.11

.2 显式转换与四种 cast

本节讲什么

老式 C 风格强转 vs C++ 四种命名强制转换：static_cast、const_cast、reinterpret_cast、dynamic_cast。

老式转换（不推荐）

double d = 3.14;
int i1 = (int)d;     // C 风格
int i2 = int(d);     // 函数式

缺点：一次写法可同时完成去 const、指针重解释等多种语义，难以审查，易埋雷。

C++ 命名转换（推荐）

统一语法：转换名<目标类型>(表达式)

① static_cast（最常用）

温和、相对安全的编译期转换：

  • 基础算术互转（double↔int、float↔long）
  • void* 与普通指针互转
  • 继承体系父子类指针上行/下行（编译期检查有限）

不能修改 const 属性。

double d = 3.14;
int i = static_cast<int>(d);   // 3，截断小数

② const_cast（唯一能增删 const/volatile）

仅修改常量限定，不改变底层类型。

const char *str = "test";
char *p = const_cast<char*>(str);   // 去掉 const（仍须谨慎使用）

const int ci = 100;
const int *cp = &ci;
int *p2 = const_cast<int*>(cp);
// *p2 = 200;  // ❌ 若 ci 原本真是 const，这是 UB

警告：通过 const_cast 修改原本就是 const 的对象 → 未定义行为。合法典型场景：调用只接受非 const 指针的遗留 API，而对象本身可变。

③ reinterpret_cast（底层比特重解释，极高风险）

把内存二进制位直接当成另一种类型，无类型安全检查：

  • 指针与整数互转
  • 不相关类型指针互转
int num = 0x1234;
char *pc = reinterpret_cast<char*>(&num);

HFT：解析二进制报文、对齐字段时偶见；日常业务尽量少用，优先 memcpy + 明确布局（见 2.1 基本类型）。

④ dynamic_cast（运行时多态转换）

仅用于带虚函数的多态类；基类指针/引用 → 派生类，运行时校验，失败指针版返回 nullptr。

本章仅提及；详见第 7 / 15 章继承与多态。

四种 cast 速查

cast 用途 风险
static_cast 算术、void*、继承转换 低～中（浮点截断等）
const_cast 增删 const/volatile 改真 const → UB
reinterpret_cast 比特重解释 极高
dynamic_cast 多态向下转型 低（失败可检测）

和 C 的区别（显式转换：C++ 的四种 cast 替代 C 风格强转）

这是 C 转 C++ 最该改变习惯的部分之一。C 只有一种强转 (type)expr，C++ 提供四种命名 cast，让转换意图更明确、更易审查：

对比点 C C++
算术转换 (int)d 或 int(d) static_cast<int>(d)
去 const (int*)cp（同一写法） const_cast<int*>(cp)
指针重解释 (char*)&num reinterpret_cast<char*>(&num)
多态向下转型 无（C 无继承） dynamic_cast<Derived*>(bp)
void* → 其他指针 int* p = (int*)vp; 或 int* p = vp;（隐式） static_cast<int*>(vp)（必须显式）
审查难度 (type)expr 一眼看不出意图 cast 名字暴露意图

给 C 程序员的关键转变： 1. static_cast 替代 C 的 (type)expr 用于算术/指针转换——static_cast<int>(d) 比 (int)d 更显眼、更易搜索（grep static_cast 一搜一个准）。语义等价，但意图清晰。 2. const_cast 是 C++ 独有的"去 const"方式——C 里 (int*)cp 一行就能去 const，C++ 必须用 const_cast<int*>(cp)。这是有意的设计——去 const 是危险操作，命名 cast 让它在代码审查时更醒目。 3. reinterpret_cast 替代 C 的指针重解释——(char*)&num 在 C++ 用 reinterpret_cast<char*>(&num)。reinterpret_ 这个名字本身就在警告"我在重新解释比特"。 4. dynamic_cast 是 C++ 独有——C 没有继承/多态，没有这种转换。运行时检查向下转型是否安全。 5. C 风格 (type)expr 在 C++ 仍合法但不推荐——它"什么都能干"（同时去 const + 重解释），难以审查。用四种命名 cast 替代是 C 转 C++ 的重要习惯转变。

常见错误

1. 用 static_cast 去 const

const int ci = 100;
const int* cp = &ci;
int* p = static_cast<int*>(cp);   // ❌ 编译错误：static_cast 不能去 const

static_cast 不能修改 const——去 const 必须用 const_cast。这是 C++ 有意的设计——去 const 是危险操作，要用专门的 cast 名字暴露意图。C 里 (int*)cp 一行搞定，C++ 要分清。

2. const_cast 修改原本就是 const 的对象

const int ci = 100;
const int* cp = &ci;
int* p = const_cast<int*>(cp);
*p = 200;   // ❌ UB：ci 原本是 const，改它是未定义行为

const_cast 只是"骗编译器"（去掉 const 检查），但运行期对象是否真可改取决于它原本是否 const。原本 const 的对象可能存在只读内存，改它 UB。合法场景：对象本身非 const，但被 const 接口返回，调用者知道可改。

3. 用 reinterpret_cast 做不相关类型转换

double d = 3.14;
int i = reinterpret_cast<int>(d);   // ❌ 编译错误：reinterpret_cast 不能用于算术类型

reinterpret_cast 只用于指针/引用的比特重解释，不用于算术类型转换。算术转换用 static_cast。C 里 (int)d 既可用于算术也可用于指针（一锅烩），C++ 分得清。

自测题

1. 选择题　要去掉指针的 const 限定，应该用哪种 cast？

  • A. static_cast
  • B. const_cast
  • C. reinterpret_cast
  • D. dynamic_cast
答案

B。const_cast 是唯一能增删 const/volatile 的 cast。static_cast 不能改 const（编译错误）；reinterpret_cast 改的是比特解释不是 const；dynamic_cast 用于多态向下转型。C 里 (int*)cp 一行能去 const，C++ 要用 const_cast 暴露意图。

2. 判断题　C 风格的 (int)d 在 C++ 中是编译错误。

答案

错。C 风格 (int)d 在 C++ 仍合法（向后兼容），但不推荐——它"什么都能干"（同时去 const、重解释指针、算术转换），难以审查。C++ 推荐 static_cast<int>(d) 这种命名 cast，意图清晰、易搜索。

3. 踩坑题　C 程序员写下面这段 C++ 代码，哪里有问题？

const char* s = "hello";
char* p = (char*)s;        // C 风格强转去 const
p[0] = 'H';                 // 想改成 "Hello"
答案

两个问题： 1. C 风格强转不推荐——C++ 应该用 const_cast<char*>(s)，暴露"去 const"的意图 2. 修改字符串字面量是 UB——"hello" 是字符串字面量，存在只读内存，p[0] = 'H' 可能崩溃（段错误）

修复（若真要改字符串）：

char buf[] = "hello";      // 数组，可改
buf[0] = 'H';              // ✅ "Hello"
// 或用 std::string
std::string s = "hello";
s[0] = 'H';                // ✅

C 里这种写法也是 UB（字符串字面量只读），但 C++ 的 std::string 更安全——赋值就拷贝一份可改的。

4. 应用题　HFT 代码要从 void* 缓冲读 int 数据。C 写法 (int*)buf，C++ 应该怎么写？

答案 
// C 写法（C++ 也能编译，但不推荐）
void* buf = malloc(100 * sizeof(int));
int* ip = (int*)buf;

// C++ 推荐：static_cast
void* buf = malloc(100 * sizeof(int));
int* ip = static_cast<int*>(buf);

// C++ 更推荐：new 或 vector
int* ip = new int[100];
// 或
std::vector<int> v(100);
int* ip = v.data();

要点： - void* → int* 用 static_cast（C++ 必须显式，不能隐式） - reinterpret_cast 也能用但过头——static_cast 足够且更安全 - C++ 推荐 new/vector 替代 malloc（类型安全、RAII）

C 程序员的 (int*)buf 习惯要改成 static_cast<int*>(buf)。

4.11

.3 规范、易错点与示例

本节讲什么

教材使用规范、高频易错点、背诵版与完整可运行示例。

使用规范

  1. 优先隐式转换——能自动统一类型就不手写强转
  2. 必须强转时，用四种命名 cast，拒绝 (type)expr
  3. 精度丢失、一般指针转换 → static_cast；只改 const → const_cast；底层比特重解释 → reinterpret_cast（慎用）
  4. 浮点 → 整型截断小数，非四舍五入；编译器常给警告

高频易错点

  1. 隐式转换只能单向加 const，不能去掉 const
  2. static_cast 无法移除 const，必须用 const_cast
  3. 数组转指针有例外：sizeof(arr) 是整个数组大小，不是指针大小
  4. 浮点转整型直接截断，不是四舍五入
  5. reinterpret_cast 不做校验，误用易崩溃 / 未对齐访问

背诵极简版

隐式：整型提升、算术转换、数组→指针、加const、→bool、赋值截断
显式：static_cast 算术/void*；const_cast 改const；reinterpret 比特；dynamic 多态
拒绝 (int)d 和 int(d)；优先 static_cast
float→int 截断；static_cast 不能去 const
sizeof(arr) 不退化；&arr 类型是 int(*)[N]

完整示例

#include <iostream>

int main() {
    double d = 3.14;
    int i = static_cast<int>(d);
    std::cout << i << "\n";          // 3

    const int ci = 100;
    const int *cp = &ci;
    int *p = const_cast<int*>(cp);   // 仅演示语法；勿通过 p 改 ci

    short s = 5;
    auto sum = s + 2.5;              // short→int→double
    std::cout << sum << "\n";

    int arr[3] = {1, 2, 3};
    int *ap = arr;                   // 隐式数组→指针
    std::cout << sizeof(arr) << " " << sizeof(ap) << "\n";

    return 0;
}

  2. 整型提升、算术转换、数组退化（及例外）
  3. 四种命名 cast 的适用边界
  4. const 只能加不能减；const_cast 的 UB 风险
  5. 浮点截断、老式强转为何不推荐

和 C 的区别（类型转换章节总结：C++ 的四种 cast 是最大转变）

整个 4.11 章节是 C 转 C++ 最该改变习惯的部分。C 的转换是"一锅烩"——(type)expr 什么都能干，难以审查；C++ 拆成四种命名 cast，每种有明确用途：

场景 C 写法 C++ 推荐 区别
算术转换 (int)d static_cast<int>(d) C++ 命名 cast 更显眼
去 const (int*)cp const_cast<int*>(cp) C++ 强制命名，暴露意图
指针重解释 (char*)&n reinterpret_cast<char*>(&n) C++ 警告"重解释比特"
void* → int* 隐式或 (int*)vp static_cast<int*>(vp) C++ 禁止隐式，必须显式
多态向下转型 无（C 无继承） dynamic_cast<Derived*>(bp) C++ 独有
整型提升 ✅ 一致 ✅ 一致 无差异
算术转换 ✅ 一致 ✅ 一致 无差异
数组退化 ✅ 一致 ✅ 一致 无差异

给 C 程序员的"心法转变"： 1. 隐式转换规则两边几乎一致——整型提升、算术转换、数组退化、浮点截断这些坑 C 学的直接迁移，无需转变。 2. 显式转换要换习惯——C 的 (type)expr 在 C++ 改用四种命名 cast：static_cast（算术/void*）、const_cast（去 const）、reinterpret_cast（重解释）、dynamic_cast（多态）。 3. C++ 的 void* 不能隐式转其他指针——C 里 int* p = malloc(...) 合法（malloc 返回 void* 隐式转），C++ 编译错误，必须 static_cast<int*>(malloc(...)) 或用 new/vector。 4. C++ 推荐 nullptr 替代 0/NULL——避免重载歧义，详见 2.3.2。

常见错误

1. C 风格强转"一锅烩"

const int* cp = &some_const;
int* p = (int*)cp;        // C 风格：同时去 const + 指针类型不变，看不出意图

C 风格 (int*)cp 一行同时去 const 和保持指针类型，无法区分"只想去 const"还是"想重解释"。C++ 用 const_cast<int*>(cp) 明确"只去 const"。代码审查时，const_cast 一眼看出危险，(int*) 容易漏。

2. 有符号/无符号混用导致负数变大正数

int idx = -1;
size_t n = vec.size();
if (idx < n) { ... }   // ❌ idx 转 size_t 变成 SIZE_MAX，< n 为 false

有符号和无符号比较时，有符号隐式转无符号——-1 变成巨大正数。C 和 C++ 都有这个坑。用 int 比较或显式 static_cast<int>(n)。

3. 浮点转整型静默截断

double price = 3750.99;
int cents = price * 100;   // 375099，不是 375100（截断）

price * 100 = 375099.0（浮点），转 int 截断小数得 375099。HFT 价格用定点整数（如"厘"为单位）避开浮点，或显式 std::lround。

自测题

1. 选择题　下列哪种 cast 不能用于去掉 const？

  • A. const_cast<int*>(cp)
  • B. (int*)cp（C 风格）
  • C. static_cast<int*>(cp)
  • D. reinterpret_cast<int*>(const_cast<const int*>(cp))
答案

C。static_cast 不能修改 const，static_cast<int*>(cp)（cp 是 const int*）编译错误。const_cast 是唯一能去 const 的命名 cast；C 风格 (int*)cp 能去（但不推荐）；reinterpret_cast 配合 const_cast 也能去（啰嗦）。C++ 设计上让去 const 必须用 const_cast，暴露意图。

2. 判断题　void* p = ...; int* ip = p;（隐式转换）在 C++ 中合法。

答案

错。C++ 不允许 void* 隐式转其他指针类型——必须 int* ip = static_cast<int*>(p);。C 允许隐式（int* ip = malloc(...) 合法）。这是 C++ 比 C 类型系统更严格的体现，强迫程序员显式表达转换意图。

3. 踩坑题　C 程序员写下面这段 C++ 代码，编译错误，怎么改？

void* buf = malloc(100);
int* ip = buf;        // 想用 buf 当 int 数组
答案

int* ip = buf; 编译错误——C++ 不允许 void* 隐式转 int*。C 程序员的 int* ip = malloc(...) 习惯要改。

修复（三种）：

// 方法 1：static_cast
int* ip = static_cast<int*>(buf);

// 方法 2：用 new（C++ 推荐）
int* ip = new int[25];   // 100 字节 = 25 个 int

// 方法 3：用 vector（最推荐）
std::vector<int> v(25);
int* ip = v.data();

C++ 推荐 new/vector 替代 malloc——类型安全、调用构造函数、RAII 自动释放。

4. 应用题　写一个函数 safe_int_div，接受两个 double 参数，返回整数结果，要求：除零时返回 0，结果四舍五入（非截断）。

答案 
#include <cmath>

int safe_int_div(double a, double b) {
    if (b == 0.0) return 0;                         // 防除零
    double result = a / b;
    return static_cast<int>(std::lround(result));   // 四舍五入，不是截断
}

要点： - 显式判 b == 0.0 防除零 UB - std::lround 四舍五入（static_cast<int>(result) 会截断） - static_cast<int> 显式转换，不用 C 风格 (int)

C 等价写法：

int safe_int_div(double a, double b) {
    if (b == 0.0) return 0;
    return (int)lround(a / b);   // C 风格强转
}

C++ 用 static_cast 替代 (int)，意图更清晰。

经典例题

* 高于 +

int a = 2, b = 3;
std::cout << a + b * 4 << std::endl;  // 2 + 12 = 14，不是 20

. 高于 *

// *p.size();     // ❌ 等价 *(p.size())

和 C 的区别（优先级表：C/C++ 几乎一致，C++ 多了几个运算符）

C 程序员对 C 的运算符优先级表已经倒背如流——* 高于 +、&& 高于 ||、赋值右结合、逗号最低，这些 C++ 完全继承。C++ 只是多了几个新运算符：

运算符 C C++ 优先级位置
:: 作用域解析 无 ✅ 最高（1 级）
.* ->* 成员指针 无 ✅ 高（2 级，后缀类）
static_cast/const_cast/... 无 ✅ 后缀类（2 级）或前缀（3 级）
typeid 无 ✅ 2 级
new/delete 无 ✅ 3 级（前缀）
算术/关系/逻辑/位运算 ✅ 一致 ✅ 一致 4-13 级完全相同
?: 三元 ✅ 一致 ✅ 一致 14 级
赋值 = += 等 ✅ 一致 ✅ 一致 15 级右结合
逗号 , ✅ 一致 ✅ 一致 16 级最低

给 C 程序员的关键提醒： 1. C 学的优先级表 95% 直接用——算术、关系、逻辑、位运算、赋值、逗号，优先级和结合律完全一致。a + b * c、a < b && b < c、a = b = c 这些 C 的肌肉记忆到 C++ 不用改。 2. C++ 多了 ::（最高优先级）——作用域解析运算符，如 std::cout、MyClass::method。它优先级最高，不会和别的运算符混淆。 3. C++ 多了 .* ->*（成员指针）——用于通过成员指针访问类成员，优先级较高（后缀类）。日常很少用，第 7 章详讲。 4. C++ 的 static_cast<...>(...) 等"看起来像函数"——优先级当后缀看，static_cast<int>(d) + 1 先算 cast 再加 1，不会出错。 5. 复杂表达式别靠背表，多加括号——C 和 C++ 共同建议。优先级表是"查"的，不是"背"的。

常见错误

1. 位运算与关系运算混用不加括号

if (flags & mask == 0) { ... }   // ❌ 等价 flags & (mask == 0)

== 优先级高于 &，先算 mask == 0 得 bool（0/1），再 flags & 0/1。正确：if ((flags & mask) == 0)。C 程序员也踩这个，C++ 同样坑。

2. << 与 ?: 混用不加括号

std::cout << x > 0 ? "pos" : "neg";   // ❌ 等价 (cout << x) > 0 ? ...

<< 优先级高于 ?:，先算 cout << x，再和 0 比。正确：std::cout << (x > 0 ? "pos" : "neg")。C 里 printf 没这个坑，C++ 的 << 容易踩。

3. 以为优先级决定求值顺序

int side_effect();
int x = side_effect() + 1;   // 以为 side_effect 一定先调？

优先级只决定"谁跟谁结合"（语法结构），不决定求值顺序。side_effect() + 1 中 + 决定结合方式，但 side_effect() 和 1 哪个先算未指定（这里没影响，但 f() + g() 就有影响）。C 和 C++ 都这样。

自测题

1. 选择题　a & b && c 的求值顺序（结合方式）是：

  • A. (a & b) && c（先位与再逻辑与）
  • B. a & (b && c)（先逻辑与再位与）
  • C. a & b && c 未指定
  • D. 编译错误
答案

A。&（位与，9 级）优先级高于 &&（逻辑与，12 级），所以 a & b && c 等价 (a & b) && c。先算 a & b（位与，无短路），再和 c 逻辑与（有短路）。C 也是同样优先级。

2. 判断题　std::cout << x < 0 ? "neg" : "pos"; 能正确打印 x 的正负。

答案

错。<< 优先级高于 <，< 高于 ?:，所以等价 ((std::cout << x) < 0) ? "neg" : "pos"——先输出 x，再把 cout 和 0 比（无意义），最后条件判断。修复：std::cout << (x < 0 ? "neg" : "pos");，加括号。C 里 printf 没这个坑。

3. 踩坑题　下面这段代码想测试 flags 的第 3 位是否为 1，哪里有问题？

unsigned flags = 0x08;   // 二进制 1000，第 3 位是 1
if (flags & 0x08 == 0x08) {
    std::cout << "bit 3 is set";
}
答案

== 优先级高于 &，等价 flags & (0x08 == 0x08) → flags & true → flags & 1。flags = 0x08 的最低位是 0，所以 flags & 1 == 0，条件 false，不打印——但逻辑上第 3 位确实为 1。

修复（加括号）：

if ((flags & 0x08) == 0x08) { ... }
// 或更简单：
if (flags & 0x08) { ... }   // 非 0 即真

C 程序员也踩这个——位运算和关系混用必加括号。

4. 应用题　不用查表，判断 a < b == c < d 的结合方式（假设 a,b,c,d 是 int）。

答案

< 和 == 同级（关系/相等运算符，7/8 级），左结合，所以 a < b == c < d 等价 ((a < b) == (c < d))——先算 a < b 得 bool，再算 c < d 得 bool，最后比较两个 bool 是否相等。

这种写法虽然合法，但可读性差，建议加括号：((a < b) == (c < d)) 或拆成 (a < b) && (c < d)（若想表达"两个条件都成立"）。C 也是同样优先级。

4.12

.2 求值顺序与括号规范

本节讲什么

求值顺序与优先级的区别；未指定顺序的陷阱；教材推荐的括号写法。

优先级 ≠ 求值顺序

int f(), g();
int h = f() + g();   // 先调 f 还是先调 g？**未指定**

编译器可任意选择，同一表达式多次运行结果可能一致，但不能依赖调用顺序。

有保证的情况 说明
&& || 左侧为假/真时，右侧不求值（短路）
?: 只求值被选中的分支
, 逗号 左侧先于右侧
赋值 = 右侧先于左侧（对操作数求值）

位运算 & | 没有短路顺序保证。

未定义行为经典坑

同一表达式多次修改

int i = 0;
// i = i++;           // ❌ UB
// v[i] = i++;        // ❌ UB（下标与右侧 i 无顺序）

函数实参

// f(++i, ++i);       // ❌ UB：哪个实参先求值未指定

HFT / 工程：热路径表达式保持简单；需要顺序就拆成多条语句。

括号规范（教材建议）

  1. 不靠背表解决复杂式——多加括号表达意图
  2. 混合算术、关系、逻辑时括号分组
  3. ?: 与 <<、= 混用必加括号
  4. 位运算与逻辑混用时分组：(a & mask) != 0 
// 可读性优先
bool ok = (flags & kReady) != 0 && (flags & kValid);

背诵极简版

优先级：谁跟谁先结合；结合律：同级从左/从右
求值顺序：操作数何时算——f()+g() 顺序不定
&& || ?: , 赋值右侧 有顺序保证；& | 无短路
同一式子多次改同一变量 → UB
复杂表达式加括号，别硬背

示例

#include <iostream>

int main() {
    int a = 2, b = 3;
    std::cout << a + b * 4 << "\n";           // 14

    int grade = 75;
    std::cout << (grade < 60 ? "fail" : "pass") << "\n";

    int x, y, z;
    x = y = z = 0;

    return 0;
}

课后考点

  1. 说出 * 与 +、. 与 *、?: 与 << 的优先级关系
  2. 赋值、前缀/后缀 ++、三元运算符的结合方向
  3. 优先级 vs 求值顺序的区别
  4. i = i++ 为何 UB
  5. 何时用括号代替记忆优先级

和 C 的区别（求值顺序：C/C++ 完全一致，这是"共享的坑"）

求值顺序是 C 和 C++ 完全共享的"坑"——优先级不决定求值顺序、f()+g() 未指定、i=i++ UB、函数实参求值未指定，两边一字不差：

对比点 C C++
优先级 ≠ 求值顺序 ✅ 一致 ✅ 一致
f() + g() 求值顺序未指定 ✅ ✅ 一致
&& \|\| 短路 ✅ ✅ 一致
?: 只算选中分支 ✅ ✅ 一致
, 从左到右 ✅ ✅ 一致
赋值右侧先于左侧 ✅ ✅ 一致
i = i++ UB ✅ ✅ 一致
函数实参求值未指定 ✅ ✅ 一致
位运算无短路 ✅ ✅ 一致

给 C 程序员的关键提醒： 1. 求值顺序坑两边一模一样——C 学的警惕心全部迁移。f()+g() 顺序未指定、i=i++ UB、函数实参求值未指定，C 和 C++ 完全一致。 2. C++17 起对部分运算符加了顺序保证——<<、>>、赋值的右侧、后缀 ++/-- 等有了更多顺序保证（C++17 之前和 C 一样未指定）。但别依赖，老代码可能用 C++14 编译，行为不同。 3. HFT 热路径表达式保持简单——需要顺序就拆成多条语句，别在复杂表达式里赌求值顺序。C 程序员的"拆语句"习惯直接用。

常见错误

1. i = i++ 以为"先赋值再自增"

int i = 0;
i = i++;   // ❌ UB，不是"i=0 然后 i 变 1"

i = i++ 在一次表达式中对 i 修改两次（一次 =、一次 ++），且修改无顺序保证。C 和 C++ 都是 UB。拆成两条语句：int tmp = i; ++i; i = tmp; 或干脆 i = i + 1;。

2. 函数实参求值顺序依赖

int i = 0;
f(++i, ++i);   // ❌ UB：两个实参求值未指定顺序

两个 ++i 的求值顺序未指定——可能都先算 ++i（i 变 2，传 f(2, 2)），也可能分别算（传 f(1, 2) 或 f(2, 1)）。拆开：

int a = ++i;
int b = ++i;
f(a, b);

3. v[i] = i++ 下标与右侧无序

int i = 0;
std::vector<int> v(10);
v[i] = i++;   // ❌ UB：v[i] 的下标 i 和右侧 i++ 无序

v[i] 的下标 i（读）和右侧 i++（写）之间没有顺序保证——i++ 可能在算下标前、后、中间执行。拆开：v[i] = i; ++i;。C 里 arr[i] = i++ 同样 UB。

自测题

1. 选择题　f() + g() 中 f 和 g 的调用顺序是：

  • A. f 先调
  • B. g 先调
  • C. 未指定，编译器决定
  • D. 并行调用
答案

C。+ 操作数的求值顺序未指定——编译器可以任意选 f 或 g 先调。C 和 C++ 都这样。要保证顺序用 ; 拆开：int a = f(); int b = g(); int h = a + b;。若 f/g 无副作用（不修改共享状态），顺序无所谓。

2. 判断题　i = i++ 在 C++ 中是合法的，结果是 i 自增 1。

答案

错。i = i++ 是 UB（未定义行为）——一次表达式中对 i 修改两次（= 和 ++），且修改无顺序保证。C 也是 UB。可能结果是 0、1、或任意值，甚至崩溃。拆成两条语句：i = i + 1; 或 ++i;。

3. 踩坑题　下面这段代码在 C 和 C++ 中行为如何？

int i = 0;
std::cout << i << " " << i++ << " " << i;   // 想输出 "0 0 1"
答案

UB（未定义行为），C 和 C++ 都是。<< 的多个操作数（i、i++、i）求值顺序未指定——i++ 可能在第一个 i 前、后、中间执行，输出不可预测。可能输出 0 0 1、1 0 0、0 0 0，或其他。

修复（拆成多条语句）：

int i = 0;
std::cout << i << " ";   // 0
++i;
std::cout << i - 1 << " " << i;   // 0 1

或用 C++17 的顺序保证（<< 的操作数从左到右求值，但别依赖，老编译器不支持）。

4. 应用题　HFT 代码要"自增计数器并记录前一个值"，如何安全写？

答案 
// ❌ UB：prev 和 counter++ 无序
// int prev = counter++;

// ✅ 安全：拆成两条语句
int prev = counter;
++counter;

// ✅ 或用后置 ++ 的返回值（标准保证后置 ++ 返回原值）
int prev = counter++;   // ✅ 合法！这是单独一条语句，不是混合表达式

要点： - int prev = counter++; 是合法的——后置 ++ 标准保证"返回原值，再自增"，这是一条语句不是混合表达式 - i = i++ 才是 UB（一次表达式里 i 被改两次） - 担心可读性就拆开：int prev = counter; ++counter;

C 程序员的 int prev = counter++; 习惯直接用，C 和 C++ 都合法。

Q2四种 cast
const char *pc = "hello";

答案与复习指引

A 行失败： static_cast 不能去掉 const。去掉 const 必须用 const_cast。

C 行是 UB： 字符串字面量 "hello" 存储在只读区，通过 const_cast 去掉 const 后修改只读内存是未定义行为（可能段错误）。const_cast 只用于"原本不是 const 但被 const 接口传出来"的场景。

四种 cast 用途： - static_cast：常规类型转换（int→double, void→int） - dynamic_cast：多态向下转型（运行时检查） - const_cast：增删 const - reinterpret_cast：位模式重新解释（最危险）

Q3隐式转换陷阱
unsigned int u = 10;
int i = -42;
std::cout << i + i << std::endl;   // A
std::cout << u + i << std::endl;   // B

A 和 B 分别输出什么？为什么？

答案与复习指引

A: -84（两个 int 相加，正常） B: 4294967254（i 被隐式转换为 unsigned int，-42 变成 4294967254，再加 10 = 4294967264... 实际取决于 unsigned 的位宽）

根因： 当 int 和 unsigned 混合运算时，int 被隐式转换为 unsigned。负数转为 unsigned 会变成很大的正数。这是 C/C++ 共有的经典 bug 来源。

Q4条件运算符
int grade = 85;
std::string final = (grade < 60) ? "fail" : "pass";
// 嵌套条件运算符
std::string level = (grade >= 90) ? "A" : (grade >= 80) ? "B" : (grade >= 70) ? "C" : "F";

level 是什么？条件运算符的结合方向是什么？

答案与复习指引

level = "B"（85 >= 80）

条件运算符 ?: 是右结合的——嵌套条件运算符从右往左组合，等价于 grade>=90 ? "A" : (grade>=80 ? "B" : (grade>=70 ? "C" : "F"))。这与 if-else if-else 链的语义一致。

Q5sizeof 与类型
struct Empty {};
class Base { virtual void f() {} };
struct Derived : Base { int x; };

std::cout << sizeof(Empty) << " " << sizeof(Base) << " " << sizeof(Derived);

输出是什么（64 位系统）？为什么 sizeof(Empty) 不为 0？

答案与复习指引

输出： 1 8 16（具体取决于编译器/对齐）

  • sizeof(Empty) = 1：C++ 规定空类大小不为 0（通常为 1），保证不同对象地址唯一
  • sizeof(Base) = 8：有虚函数的类含 vptr（8 字节指针）
  • sizeof(Derived) = 16：vptr（8）+ int x（4）+ padding（4，对齐到 8）
