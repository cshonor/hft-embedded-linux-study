# 14.3 类型转换运算符

## 本节讲什么

**类型转换运算符**：定义自定义类型向其他类型的转换，如 `operator int() const` 让对象能隐式转 int。重点是隐式转换的危险和 `explicit` 的作用。

## 核心用法

### 定义转换

```cpp
class Fraction {
public:
    Fraction(int n, int d=1) : num(n), den(d) {}
    // 转换为 double
    operator double() const { return double(num) / den; }
private:
    int num, den;
};
Fraction f(1, 2);
double d = f;          // 隐式调用 operator double()，d = 0.5
```

### explicit 转换（C++11）

```cpp
class Fraction {
public:
    explicit operator double() const { return double(num)/den; }   // explicit
};
Fraction f(1,2);
// double d = f;          // 错误：explicit 禁止隐式转换
double d = static_cast<double>(f);   // OK：显式转换
```
`explicit` 防止意外的隐式转换，只允许显式 `static_cast`。

### 转换为 bool

```cpp
class Stream {
public:
    explicit operator bool() const { return !failed_; }   // explicit bool
private:
    bool failed_ = false;
};
Stream s;
if (s) { /* s 转 bool 为真 */ }   // OK：if/while 条件中 explicit bool 仍可用
bool b = s;                       // 错误：explicit 禁止隐式
```
`operator bool` 几乎总是应该 `explicit`——否则对象会在各种意外处转 bool（如 `int x = obj + 1` 可能先转 bool 再加）。

## 和 C 的区别

| 维度 | C | C++ |
|------|---|-----|
| 自定义类型转换 | ❌ 无（只能写函数） | ✅ 转换运算符 |
| 隐式转换控制 | 无机制 | `explicit` 限制 |
| 内置类型互转 | 算术转换规则 | 一致 + 自定义类型可参与 |

**C 程序员的理解**：

C 里"把 Fraction 转 double"只能写函数：
```c
double fraction_to_double(struct Fraction f) { return (double)f.num / f.den; }
double d = fraction_to_double(f);   // 显式函数调用
```

C++ 的转换运算符让转换"自动"发生，但这也带来风险——隐式转换可能在不经意处触发。所以 C++11 引入 `explicit` 限制，让你控制"只允许显式转换"。

## 常见错误

1. **隐式转换导致意外行为**：`operator int()` 让对象在任何需要 int 处隐式转换，可能引发意外（如 `obj + 1` 把对象转 int 再加）。**修正**：加 `explicit`，或避免定义转换运算符，改用具名函数 `to_int()`。
2. **转换二义性**：同时定义 `operator int()` 和 `operator double()`，在 `obj + 1.0` 时编译器不知道转 int 还是 double，二义性。**修正**：只定义一个，或都 explicit 用时显式转。
3. **`operator bool` 不加 explicit**：非 explicit 的 bool 转换会让对象在算术运算中意外转 bool 再转 int（如 `obj + 1` 变成 `bool(obj) + 1`）。**修正**：`explicit operator bool`。

## 自测题

**1. 选择题**：下面代码合法吗？
```cpp
class C { public: explicit operator int() const { return 42; } };
C obj;
int x = obj;
```
- A) 合法，x=42
- B) 编译错误：explicit 禁止隐式转换
- C) 运行错误
- D) 合法，x 未定义

<details><summary>答案</summary>

B。`explicit operator int` 禁止隐式转换，`int x = obj` 是隐式转换，编译错误。**修正**：`int x = static_cast<int>(obj);` 显式转换。例外：`explicit operator bool` 在 `if/while/!` 等条件上下文中仍可用（语言特例，称"contextual conversion"），因为 bool 转换在条件中太常用。

</details>

**2. 判断题**：定义 `operator bool()` 时建议加 `explicit`。

<details><summary>答案</summary>

正确。非 explicit 的 `operator bool` 会让对象在算术运算中意外转 bool 再转 int（如 `obj + 1` 变成 `(bool)obj + 1`，结果 0 或 1 加 1）。加 `explicit` 后，bool 转换只在条件上下文（if/while/!）触发，避免意外，同时保留 `if (obj)` 的便利。这是 C++11 的最佳实践。

</details>

**3. 踩坑题**：下面代码报"二义性"错误，为什么？
```cpp
class C {
public:
    operator int() const { return 1; }
    operator double() const { return 1.0; }
};
C obj;
double d = obj + 1.0;   // 二义性
```

<details><summary>答案</summary>

`obj + 1.0` 中，编译器可以把 obj 转 int 再加 1.0，或转 double 再加 1.0，两个转换路径都合理，二义性报错。**修正**：1) 只保留一个转换运算符；2) 都加 explicit，用时显式 `static_cast<double>(obj) + 1.0`；3) 改用具名函数 `to_int()`/`to_double()` 避免隐式转换。原则：避免定义多个隐式转换运算符，易二义。

</details>

**4. 应用题**：为一个"安全 bool"的 File 类设计 `operator bool`（文件打开成功为真），说明为什么要 explicit。

<details><summary>答案</summary>

```cpp
class File {
public:
    explicit operator bool() const { return fp_ != nullptr; }
private:
    FILE* fp_ = nullptr;
};
File f("a.txt");
if (f) { /* 文件打开成功 */ }    // OK：条件上下文，explicit bool 可用
f + 1;                           // 错误：explicit 禁止算术中转 bool
```
要 explicit 因为：1) 防止 `f + 1` 这类算术意外把 f 转 bool 再转 int（0/1+1）；2) 防止 `int n = f` 这种意外赋值；3) 保留 `if (f)` 的便利（条件上下文允许 explicit bool）。这是 C++11 的"safe bool idiom"，比 C++03 的复杂 hack 简洁得多。C 里 FILE* 直接当 bool 用（NULL 检查），但 C++ 包装类需要 explicit operator bool 才安全。

</details>
