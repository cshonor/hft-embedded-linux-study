# 6.6 函数匹配：重载决议的完整规则

[← 6.5 函数指针](./6.5-函数指针.md) | [第 6 章 函数](./README.md) | [7.1 定义抽象数据类型](../ch07-classes/7.1-定义抽象数据类型.md)

## 本节讲什么

[6.3](./6.3-函数重载（OverloadedFunctions）.md) 讲的是"重载怎么写"，匹配规则只有三句话。这一节讲"编译器怎么选"：候选集怎么来、隐式转换怎么分级、什么情况下算二义性。

同一组实参、不同的重载集，结果可以完全不同。先看实测（gcc 13.2 / x86-64 / `-std=c++17`）：

```cpp
void f(int);    void f(double);
void g(float);  void g(double);
void m(int);    void m(long);
void k(int&);   void k(const int&);

f(3.14f);   g(3.14f);   m('x');   k(42);
```

```text
f(double)
g(float)
m(int)
k(const int&)
```

`f(3.14f)` 不选 `f(int)`、`g(3.14f)` 选了 `g(float)`、`m('x')` 又回到 `m(int)`——三者的差别只有一个：**转换被分成了不同等级，而等级不能互相抵消**。

## 一、三步走

```cpp
void print(int);                 // #1
void print(double);              // #2
void print(const char*);         // #3
void print(int, int);            // #4
```

```cpp
print(42);      // 只有 #1 可行
print(3.14);    // 只有 #2 可行
print("hi");    // #3（数组退化为指针）
print(1, 2);    // #4
```

| 步骤 | 做什么 | 淘汰规则 |
|---|---|---|
| 1. 候选函数 | 收集同名、声明可见的函数 | 名字不同、作用域不可见 → 不在候选里 |
| 2. 可行函数 | 检查能否用这次实参调用 | 实参个数不匹配（且默认实参补不齐）、某个实参无可行转换 → 淘汰 |
| 3. 最佳匹配 | 逐个实参比较隐式转换序列（ICS） | 没有任何候选"不劣于其余全部且至少一项更优" → 报二义性 |

关键在第 3 步的措辞：不是"平均分最高"，而是**必须严格胜出**。

## 二、转换等级：五档，不能跨档抵消

```cpp
void take(long);
take(3.14f);     // float→long：转换
```

| 等级 | 内容 | 例子 |
|---|---|---|
| 1. 精确匹配 | 类型一致、左值变换、加限定、引用绑定 | `int` → `int`；`int[6]` → `int*`；`int` → `const int&` |
| 2. 提升（promotion） | 整型提升、浮点提升 | `char`/`short`/`bool` → `int`；`float` → `double` |
| 3. 转换（conversion） | 算术转换、指针转换、`bool` 转换 | `int` → `double`；`int` → `long`；`T*` → `void*` |
| 4. 用户定义转换 | 转换构造函数、转换函数 | `const char*` → `std::string` |
| 5. 省略号 | `...` | 最后兜底 |

规则只有一条：**前一级整体优于后一级**。提升和转换是两个不同等级，这一条决定了本节开头那几个结果：

| 调用 | 候选与各自的 ICS | 结果 |
|---|---|---|
| `f(3.14f)` | `f(int)` 需转换 ／ `f(double)` 仅提升 | `f(double)` |
| `g(3.14f)` | `g(float)` 精确 ／ `g(double)` 需提升 | `g(float)` |
| `m('x')` | `m(int)` 仅提升 ／ `m(long)` 需转换 | `m(int)` |
| `k(42)` | `k(int&)` 不可行（右值绑不到非 const 左值引用） ／ `k(const int&)` 精确 | `k(const int&)` |

`k` 那一行还说明一件事：**绑定到临时对象也是精确匹配**，所以 `const T&` 能接字面量，且不因此在等级上吃亏。

## 三、二义性：同级之间分不出胜负

两条铁律：

- **不能跨实参折中。** 候选 A 在第一个实参上更好、候选 B 在第二个上更好，结果不是"综合更优"，而是二义性。
- **同一等级之间没有默认优先。** 两个标准转换谁也不比谁好。

四个实测案例（gcc 13.2，`-std=c++17 -Wall -Wextra`，报错原文）：

```cpp
void a(long);          void a(double);          a(3);
void b(long);          void b(unsigned long);   b(0);
void c(short);         void c(unsigned short);  c('x');
void d(int);           void d(int&);            d(x);   // x 是 int 左值
```

```text
<source>:14:6: error: call of overloaded 'a(int)' is ambiguous
<source>:1:6: note: candidate: 'void a(long int)'
<source>:2:6: note: candidate: 'void a(double)'
<source>:15:6: error: call of overloaded 'b(int)' is ambiguous
<source>:4:6: note: candidate: 'void b(long int)'
<source>:5:6: note: candidate: 'void b(long unsigned int)'
<source>:16:6: error: call of overloaded 'c(char)' is ambiguous
<source>:7:6: note: candidate: 'void c(short int)'
<source>:8:6: note: candidate: 'void c(short unsigned int)'
<source>:18:6: error: call of overloaded 'd(int&)' is ambiguous
<source>:10:6: note: candidate: 'void d(int)'
<source>:11:6: note: candidate: 'void d(int&)'
```

逐个看根因：

| 案例 | 两个候选的 ICS | 为什么平手 |
|---|---|---|
| `a(3)` | `int→long`、`int→double` | 都是转换级 |
| `b(0)` | `int→long`、`int→unsigned long` | 都是转换级，符号性不构成等级差 |
| `c('x')` | `char→short`、`char→unsigned short` | 都是转换级（`char→int` 才是提升） |
| `d(x)` | `int` 精确、`int&` 精确 | 值传递与引用绑定都是精确匹配 |

### 一个反直觉但确实二义的组合

```cpp
void h(int);
void h(const int&);
h(42);
```

```text
<source>:16:6: error: call of overloaded 'h(int)' is ambiguous
<source>:9:6: note: candidate: 'void h(int)'
<source>:10:6: note: candidate: 'void h(const int&)'
```

值传递和 `const` 引用传递都是精确匹配，标准里没有"值优于引用"的规则，所以不能共存。工程上的含义很直接：**同一个函数不要同时提供 `T` 和 `const T&` 两个重载**。

## 四、成员函数：隐式对象参数也参加匹配

这是 [2.4.4](../ch02-variables-and-basic-types/2.4-const-qualifier/2.4.4-const在类里的传播.md) 那条机制的延伸——`const` 成员函数与非 `const` 成员函数的区别，本质是隐式对象参数的类型不同：

```cpp
struct Widget {
    int f()       { return 1; }
    int f() const { return 2; }
};
```

| 调用者 | 隐式对象参数 | 选中 |
|---|---|---|
| 非 const 对象 `w` | `Widget&` | `f()`（`const` 版本需要加限定，劣一档） |
| const 对象 `cw` | `const Widget&` | `f() const`（非 const 版本不可行） |

实测输出 `w.f() = 1`、`cw.f() = 2`。这条规则同样适用于 `operator[]`、`begin()` 这类成对出现的接口。

## 五、和 C 的区别

C 里同名函数直接冲突，编译器和链接器都没有"选一个"的机制：

```c
int  print_int(int x);
int  print_double(double x);
/* int print(int x); int print(double x);   // 重复定义 */
```

```cpp
int print(int x);
int print(double x);      // 合法：形参列表不同
```

| 维度 | C | C++ |
|---|---|---|
| 同名不同参 | 冲突 | 合法重载 |
| 符号名 | 原样（`print`） | mangling，参数类型进名字（`_Z5printi` / `_Z5printd`） |
| 跨语言调用 | 天然可用 | 需要 `extern "C"` 关闭 mangling |
| 多类型分派 | `_Generic`（C11）或函数指针表 | 重载决议（编译期完成） |

`extern "C"` 的关键作用不是"换个名字"，而是**关闭重载能力**：C 链接名里没有参数信息，两个同名函数必然撞车。所以在 `extern "C"` 块里写重载，编译期就会报错。

## 六、常见错误

**1. 把提升当成转换，误判成二义性**

```cpp
void f(int);
void f(double);
f(3.14f);      // 实测选 f(double)，不是二义性
```

`float→double` 是提升，`float→int` 是转换，提升优先。只有两边都落在转换级才会平手（如 `f(int)` 与 `f(long)` 收到 `short`）。

**2. 跨实参折中**

```cpp
void g(int, double);
void g(double, int);
g(1, 1);       // 二义：第一参 g#1 更优，第二参 g#2 更优
```

编译器不做加权求和，遇到这种交叉就直接报二义。

**3. 用 `0` 同时命中整型与指针重载**

```cpp
void f(int);
void f(void*);
f(0);          // f(int)：字面量 0 是 int，精确匹配
f(nullptr);    // f(void*)：nullptr_t 只能转指针
```

要表达空指针就写 `nullptr`，别写 `0` 或 `NULL`。

**4. 值 + const 引用重载共存**

```cpp
void h(int);
void h(const int&);   // h(42) 二义
```

**5. 默认实参不改善匹配**

默认实参只影响"能不能调用"（可行集），不参与"谁更优"。`void f(int); void f(int, int = 0); f(1);` 之所以二义，是因为两个候选在唯一实参上的 ICS 完全相同。

## 七、决议落点实测：五组"到底选了谁"

> 规则背不下来没关系，把 `examples/6.6-1-resolution-traps.cpp` 跑一遍，编译器选了谁会直接打印出来。以下均为本机实测（clang 23.1.0 / `-std=c++17`）。

| 调用 | 实际落点 | 起作用的规则 |
|---|---|---|
| `pick(1)`（`pick(int)` 与 `template<T> pick(T&&)` 并存） | **`pick(int)`** | 同等级时**非模板优先于模板** |
| `pick(1.5)` | `pick(T&&)` | 只有模板能匹配 `double` |
| `take2(1, 2)`（`take2(int,int)` 与 `take2(initializer_list<int>)`） | **`take2(int,int)`** | 圆括号 = 普通实参列表 |
| `take2({1, 2})` | **`take2(initializer_list<int>)`** | **列表初始化优先选 `initializer_list`** |
| `which(nullptr)`（`char*` vs `int`） | **`which(char*)`** | `nullptr_t` 不能转整型 |
| `which(0)` | `which(int)` | 精确匹配 |
| `conv('a')`（`int` vs `double`） | **`conv(int)`** | 整型**提升** > 整型转换 |
| `conv(1.5f)` | **`conv(double)`** | 浮点**提升** > 转换 |
| `bind(x)`（`const int&` vs `int&&`） | `bind(const int&)` | 左值绑左值引用 |
| `bind(1)` / `bind(x + 1)` | `bind(int&&)` | 右值绑右值引用 |
| `str("literal")`（`const std::string&` vs `const char*`） | **`str(const char*)`** | 精确匹配，无需用户定义转换 |

### 三个高频误判

**① `{}` 和 `()` 不是一回事。** `f({1,2})` 与 `f(1,2)` 可能落进两个完全不同的重载——前者优先 `initializer_list`。容器接口设计时必须两个版本都提供，否则调用者用花括号写就是另一个语义。

**② 完美转发模板 `template<class T> void f(T&&)` 会"通吃"。** 它对几乎所有实参都是精确匹配，很容易抢走本该走非模板重载的调用。实测 `pick(1)` 仍选非模板（规则偏向非模板），但 `pick(1.5)`、`pick(std::string)` 全被模板吃掉——**这是 `std::string` 传进 `f(T&&)` 后又被转走的常见原因**。要收窄就用 `enable_if` / C++20 `requires` 约束模板。

**③ 用户定义转换属于最低档。** `const char*` → `std::string` 只能算"转换级"；当两个候选都需要一次用户定义转换时，谁也不比谁好 → 二义。实测 `str(0)` 就是二义（`0` 既能当 `const char*` 又能转 `string`）。

## HFT / 嵌入式关联

1. **决议在编译期完成，运行期零开销。** 反汇编里只有一条 `call`，没有类型判断、没有分派表。这一点和虚函数、`std::function` 是本质区别——重载是编译期多态。

2. **隐式转换会静默选错版本。** 重载集里同时有 `int32_t` 和 `int64_t` 版本时，传一个 `long` 实参，选哪个取决于平台：Linux LP64 上 `long` 是 64 位，Windows LLP64 上是 32 位。同一份代码在两个平台可能走进不同重载。这类问题编译期不报错，只在行为上分叉。

3. **用 `explicit` / `= delete` 封住不想要的隐式路径。** `void f(bool)` 会被整数和指针实参隐式命中，是最典型的误选来源。要么删掉 `bool` 重载，要么把它写成模板加 `static_assert`。

4. **定宽类型 + `static_assert` 把假设写死。** 涉及重载的接口参数统一用 `int32_t` / `int64_t`，再补 `static_assert(sizeof(long) == 8)` 之类的断言，能把"平台悄悄改选重载"变成编译错误。

## 代码自测

**1（等级）** `void f(int); void f(double);` 调用 `f(3.14f)` 选谁？如果把 `f(int)` 换成 `f(long)`，结果变不变？

**2（二义）** `void a(long); void a(unsigned long);` 调用 `a(0)` 为什么二义？换成 `a(0L)` 呢？

**3（引用）** `void d(int); void d(int&);` 调用 `d(x)`（`x` 是 `int` 左值）为什么二义？给出两种修法。

**4（指针）** `void f(int); void f(void*);` 调用 `f(0)` 与 `f(nullptr)` 分别选谁？
**5（模板 vs 非模板）** `void g(int);` 与 `template<class T> void g(T&&);` 同时存在时，`g(1)`、`g(1.5)` 分别选谁？如果要让模板只接受算术类型，怎么改？

**6（列表 vs 圆括号）** `void t(int,int);` 与 `void t(std::initializer_list<int>);` 并存时，`t(1,2)` 和 `t({1,2})` 各选谁？这对容器接口设计有什么启示？


<details>
<summary>参考答案</summary>

1. 选 `f(double)`：`float→double` 是浮点提升，`float→int` 是算术转换，提升整体优先。换成 `f(long)` 结果不变——`float→long` 仍是转换级，依然劣于提升，还是 `f(double)`。

2. 二义：`0` 是 `int`，`int→long` 与 `int→unsigned long` 都属转换级，符号性不构成等级差，没有候选严格胜出。改成 `a(0L)` 后第一个候选是精确匹配，直接胜出。实测 gcc 报 `call of overloaded 'a(int)' is ambiguous`。

3. 值传递与绑定到 `int&` 都是精确匹配，标准没有"值优于引用"的规则。修法：删掉其中一个；或把引用版改成 `const int&`（此时右值只会选它，但左值仍可能与值版本二义，最稳的是只保留一个）。

4. `f(0)` 选 `f(int)`：字面量 `0` 是 `int` 精确匹配，转 `void*` 需要转换。`f(nullptr)` 选 `f(void*)`：`nullptr_t` 可转指针，不能转 `int`。

5. `g(1)` 选**非模板 `g(int)`**（同转换等级时非模板优先）；`g(1.5)` 选**模板 `g(T&&)`**（只有它能精确匹配 `double`）。收窄办法：
```cpp
template <class T, class = std::enable_if_t<std::is_arithmetic_v<std::decay_t<T>>>>
void g(T&&);                       // C++11/14/17
// 或 C++20：template <class T> requires std::integral<T> || std::floating_point<T>
void g(T&&);
```

6. `t(1,2)` → `t(int,int)`；`t({1,2})` → `t(std::initializer_list<int>)`。**启示**：容器/工厂接口只要提供了 `initializer_list` 版本，就得同时保留普通参数版本，否则 `f(1,2)` 这种写法会落不进 `initializer_list`（或反过来），调用点语义随写法变化——这正是 `std::vector<int> v(3)`（3 个 0）与 `std::vector<int> v{3}`（1 个 3）天差地别的根源。


</details>
