# 6.5 函数指针

## 本节讲什么

指向函数的指针：声明语法、赋值、调用、用作形参/返回值，以及 C++ 独有的**成员函数指针**。函数指针在 C 也有，但 C++ 更复杂（重载、成员函数）。

## 核心用法

### 声明与使用

```cpp
int add(int a, int b) { return a + b; }

// 声明函数指针：返回类型 (*指针名)(形参列表)
int (*pf)(int, int) = add;   // pf 指向 add
int (*pf2)(int, int) = &add; // 等价，& 可省

// 调用
int r1 = pf(1, 2);           // 3
int r2 = (*pf)(1, 2);        // 等价，显式解引用
```

### 用作形参（回调）

```cpp
// 比较函数指针作为排序参数
void sort(int* a, int n, bool (*cmp)(int, int));
bool less(int a, int b) { return a < b; }
sort(arr, n, less);          // 传入函数名，自动转指针
```

### 典型用途（为什么需要它）

函数指针把「**行为**」当成数据来传递和保存——这是 C 里唯一的多态手段，也是 C++ 回调机制的底座。四个典型场景：

**① 回调**：把函数交给别人，让它在合适时机回头调你。`qsort` 就是靠这个——它只管排序算法，比较规则由调用方的 `compar` 决定。

```cpp
void qsort(void* base, size_t n, size_t size, int (*compar)(const void*, const void*));
```

**② 运行时动态选择**：代码写完后，运行时才决定调哪个函数。

```cpp
void (*op)(int, int) = (c == '+') ? Add : Sub;
op(3, 5);
```

**③ 设备表 / C 风格多态**：结构体里放函数指针，不同实例填不同实现（Linux 内核 `struct file_operations` 就是这个套路）。

```cpp
struct Device {
    const char* name;
    int (*open)(void);
    int (*read)(char*, int);
    int (*write)(const char*, int);
};
static const Device kUart = {"uart", uart_open, uart_read, uart_write};
dev->read(buf, n);        // 上层代码不关心具体是哪种设备
```

**④ 中断 / 信号注册**：告诉内核"发生中断时跑这个函数"，本身就是传函数指针（嵌入式、驱动最常见）。Cortex-M 的中断向量表本质就是函数指针数组。

### 用 `typedef`/`using` 简化

```cpp
using BinOp = int(*)(int, int);   // C++11 别名，清晰
BinOp op = add;
op(1, 2);
```

## 和 C 的区别

| 维度 | C | C++ |
|------|---|-----|
| 函数指针基本语法 | ✅ 一致 | ✅ 一致 |
| 取地址 `&func` | 可省 | 可省 |
| 重载函数取地址 | ❌ 无重载 | C++ 要靠形参列表区分取哪个重载版本 |
| 成员函数指针 | ❌ C 无成员函数 | C++ 独有 `.*`/`->*` 语法 |
| 类型推导 | ❌ | `auto`/`decltype` 简化 |
| 函数对象（仿函数） | ❌ | C++ 有，比函数指针更高效（可内联） |

**成员函数指针**是 C++ 独有的复杂语法，C 程序员看到容易懵：

```cpp
struct C {
    int f(int x) { return x; }
};
int (C::*pmf)(int) = &C::f;   // 指向 C 的成员函数 f
C obj;
int r = (obj.*pmf)(42);       // 通过对象调用成员函数指针
C* p = &obj;
int r2 = (p->*pmf)(42);       // 通过指针调用
```

**C 程序员更该学的现代替代**：C++ 里回调优先用**函数对象（lambda）**或 `std::function`，而不是裸函数指针——函数指针无法内联（实测比可内联的模板慢约 6 倍，见下方「实测 3」），且类型不灵活、不能携带状态。

```c
/* C：回调用函数指针，无法内联 */
void apply(int* a, int n, int (*fn)(int)) {
    for (int i = 0; i < n; ++i) a[i] = fn(a[i]);   // 间接调用
}
```
```cpp
// C++：lambda + 模板，可内联，零开销
template <class F>
void apply(int* a, int n, F fn) {
    for (int i = 0; i < n; ++i) a[i] = fn(a[i]);   // 编译器可内联 lambda
}
apply(arr, n, [](int x){ return x * 2; });
```

## 底层实现与实测

> 以下均为本机实测（Apple clang 23.1.0，arm64，`-std=c++17 -O2`）。函数指针的代价**不在语法，在"能不能内联"**。

### 实测 1：它就只是一个地址

```cpp
void Hello(int x) {}
void (*p)(int) = Hello;
```

| 量 | 实测值 |
|---|---|
| `sizeof(p)` | **8**（和 `void*` 一样，就是一个地址） |
| `p == Hello` | **true**（函数名自动退化） |
| `p(100)` vs `(*p)(100)` | 完全等价，两种写法都合法 |

段地址实测（`&fn` 是代码段，`&g_data` 是数据段）：

```
函数 fn         = 0x1023dfe78     ← 代码段（__TEXT）
字符串常量      = 0x1023dffaa     ← 只读段
全局 int g_data = 0x1023e4010     ← 数据段（__DATA）
```

桌面/服务器是**冯诺依曼架构**：代码和数据在同一地址空间，所以函数指针和 `void*` 大小相同、也能互转（`dlsym` 返回 `void*` 再转函数指针就是这个前提）。**但 C++ 标准只说这是 conditionally-supported**——哈佛架构的 MCU（如 AVR）代码和数据在不同地址空间，`sizeof` 都可能不同，**这正是标准不肯保证互转的原因**。POSIX 额外要求必须支持，`dlsym` 才可用。

### 实测 2：直接调用 vs 通过指针调用，汇编差一条指令

```asm
__Z6directi:                 ; void direct(int x) { target(x); }
    bl  __Z6targeti          ; bl  = 直接跳转，目标地址编码在指令里

__Z8indirectPFviEi:          ; void indirect(void (*f)(int), int x) { f(x); }
    ldr x8, [sp, #8]         ; ① 先把指针值从栈里读出来
    ldr w0, [sp, #4]
    blr x8                   ; ② blr = 跳到寄存器里的地址
```

差别就在 `bl` → `blr`：目标地址**运行时才知道**，所以编译器没法把被调函数内联进来、也没法做跨函数的常量传播。这是函数指针一切性能代价的源头。

### 实测 3：回调的三种写法，一次调用多少钱

1000 万次调用 × 3 轮（被调函数带副作用、`volatile` 函数指针挡住「间接调用提升」）：

| 写法 | 实测 | 说明 |
|---|---|---|
| **模板 + lambda**（`template <class F>`） | **0.32 ns/次** | 编译期已知具体函数 → 整个循环被内联 |
| **裸函数指针** `long(*)(long)` | **2.03 ns/次** | 一次 `blr` 间接跳转 |
| **`std::function`** | **2.04 ns/次** | 类型擦除，也是一次间接跳转 |

**两个关键结论**，都跟直觉相反：

1. **真正的分水岭是"能不能内联"（约 6 倍），不是"裸指针 vs std::function"**——后两者实测几乎相同（2.03 vs 2.04 ns）。所以「为了性能不用 `std::function` 改用裸函数指针」基本是白优化，真正的提速是把回调改成模板参数。
2. 但 `sizeof(std::function<long(long)>) = 32`，裸指针 8。`std::function` 的额外成本主要在**构造和拷贝**（捕获内容超过小对象缓冲会堆分配），以及无法内联，而不在单次调用。

> ⚠ 测量陷阱：第一版测出裸函数指针和模板都是 `0.00 ms`——clang 做了「间接调用提升」（推测指针值恒为 `add1` 后内联）。**测间接调用必须让指针值不可推测**（`volatile` 函数指针）或被调函数带副作用，否则会得出"函数指针和内联一样快"的错误结论。

### 实测 4：函数指针跳转表 vs if-else——基本持平

| 写法 | 实测 |
|---|---|
| `table[k&3](i)` 跳转表 | 0.74 ns/次 |
| `if (k==0) ... else if ...` | 0.74 ns/次 |

分支目标固定时，CPU 的分支预测器对两者都能预测成功。**函数指针省的是代码行数和可扩展性（加一个分支 = 数组加一项），不是 CPU 时间。** 别为了"性能"把 if-else 改成跳转表。

### 实测 5：qsort vs std::sort（回调代价最直观的例子）

10 万个 `int` × 20 轮：

| | 比较器形式 | 实测 |
|---|---|---|
| `qsort` | `int(*)(const void*, const void*)` 函数指针 | **7.38 ms/轮** |
| `std::sort` | 模板参数，编译期已知 | **1.73 ms/轮** |
| | | **快 4.25 倍** |

同样的快速排序算法，只因为比较器能不能内联就差 4 倍——这是"回调 vs 内联"最有说服力的一组数据。

### 实测 6：成员函数指针是 16 字节，不是 8

```
sizeof(void(*)())       = 8      ← 普通函数指针
sizeof(void(A::*)())    = 16     ← 成员函数指针，两倍
```

多出来的 8 字节用来处理**虚函数的虚表偏移**和**多重继承的 this 调整**。所以它不能当普通指针用，也不能转 `void*`。

### 实测 7：类型必须完全匹配，连 `noexcept` 都算

```cpp
void f1() noexcept {}
void f2() {}
void (*a)()          = f1;   // ✅ noexcept → 非 noexcept，允许（缩小承诺）
void (*b)() noexcept = f2;   // ❌ 编译错误：different exception specifications
```

C++17 起 **`noexcept` 是函数类型的一部分**，所以也是函数指针类型的一部分。同理参数类型、返回类型、调用约定都必须一致；`int` 和 `double` 参数、返回 `void` 和 `int`，实测都是硬编译错误。

### 实测 8：调用空函数指针直接段错误

```cpp
void (*f)(int) = nullptr;
f(1);                       // 实测 SIGSEGV，退出码 139
```

裸函数指针**没有空检查**（不像 `std::function` 会抛 `std::bad_function_call`）。回调指针来自外部（注册表、配置、插件）时，调用前必须 `if (f)`。

## HFT/嵌入式关联

- **订单/行情回调**用 `std::function` 还是模板？注册一次、调用频繁的回调（on_tick / on_order）走**模板或 CRTP 静态多态**，避免每次调用都 `blr`；只在**调用频率低、需要运行时替换**（策略热切换、插件）的地方用 `std::function`/函数指针。
- **比较器、哈希器**一律传模板参数（像 `std::sort` 那样），不要用函数指针——实测 4 倍差距在撮合排序、订单簿遍历上就是延迟尖峰。
- **状态机/消息分发**：用函数指针数组做跳转表（比 switch 易扩展），但别指望它更快——实测与 if-else 持平。
- **嵌入式驱动**：`struct file_operations`、设备表（`open/read/write` 函数指针）是 C 里做多态的标准手段，和实测 ⑤ 的 `Device` 结构同构；新增设备只加一个结构体实例，上层代码不动。
- **中断向量表**：Cortex-M 的向量表本质就是函数指针数组，由硬件在异常入口按编号索引跳转。注意 Thumb 指令集下向量表里的地址**最低位必须为 1**（标识 Thumb 状态），写 ISR 地址时被工具链处理，手工填表时是最常见的坑。
- **回调不能阻塞**：中断/行情回调里做 I/O、加锁会放大抖动，工程上通常只做「入队 + 唤醒」，实际处理挪到工作线程。

## 常见错误

1. **成员函数指针与普通函数指针混用**：`int (*pf)(int) = &C::f;` —— 成员函数指针类型是 `int (C::*)(int)`，与普通函数指针类型不同，不能互转。新手常踩。
2. **取重载函数地址不指定版本**：`void f(int); void f(double); auto pf = &f;` —— 编译器不知道取哪个重载。**修正**：`int (*pf)(int) = &f;` 或 `auto pf = static_cast<void(*)(int)>(&f);`。
3. **函数指针类型不匹配**：`int (*pf)(int) = &func;` 但 `func` 签名是 `int(int,int)`，类型不匹配编译错误。函数指针类型严格，必须返回类型和形参列表都一致。
4. **调用未判空的函数指针**：`void (*cb)(int) = lookup(name); cb(1);` —— `lookup` 没找到返回 `nullptr` 时，实测 **SIGSEGV（退出码 139）**，裸指针不会帮你检查。**修正**：`if (cb) cb(1);`，或改用 `std::function`（空时抛 `std::bad_function_call`，至少可控）。
5. **以为有捕获的 lambda 也能转函数指针**：`void (*f)(int) = [y](int x){...};` 编译错误（no viable conversion）。只有**无捕获** lambda 才有到函数指针的转换——捕获需要状态，8 字节的指针装不下。**修正**：要么去掉捕获，要么用 `std::function`。
6. **忽略 `noexcept` 也是类型的一部分**：C++17 起 `void(*)() noexcept` 和 `void(*)()` 是不同类型，把非 `noexcept` 函数赋给 `noexcept` 指针是编译错误（实测 `different exception specifications`）。反过来（`noexcept` 函数 → 普通指针）允许。

## 自测题

**1. 选择题**：下面哪个能正确声明"指向 `int(int, int)` 函数的指针"？
- A) `int* pf(int, int);`
- B) `int (*pf)(int, int);`
- C) `int (pf*)(int, int);`
- D) `int (*pf)int, int;`

<details><summary>答案</summary>

B。`int (*pf)(int, int)` —— `pf` 是指针，指向"接收两个 int 返回 int 的函数"。A 是"返回 int* 的函数 pf"；C/D 语法错误。这种声明读法：从变量名出发，先和 `*` 结合（指针），再看外面的 `()`（指向函数），最后看返回类型。

</details>

**2. 判断题**：C++ 中 `&func` 和 `func`（函数名）作为函数指针赋值时等价。

<details><summary>答案</summary>

正确。函数名会自动退化为函数指针（类似数组名退化为指针），所以 `pf = func` 和 `pf = &func` 等价，调用 `pf(1)` 和 `(*pf)(1)` 也等价。这是 C/C++ 共有的便利规则。

</details>

**3. 踩坑题**：下面代码想存一个类的成员函数到指针，哪里错了？
```cpp
struct S {
    int get() { return 42; }
};
int (*pf)() = &S::get;   // 想存成员函数
```

<details><summary>答案</summary>

类型不匹配。`&S::get` 是**成员函数指针**，类型 `int (S::*)()`，不能赋给普通函数指针 `int (*)()`。成员函数指针需要对象才能调用，类型也不同。**修正**：
```cpp
int (S::*pmf)() = &S::get;
S obj; int r = (obj.*pmf)();
```

</details>

**4. 应用题**：用 `std::function` 实现一个简单的"命令分发器"，把字符串命令名映射到处理函数。说明相比裸函数指针的优势。

<details><summary>答案</summary>

```cpp
#include <functional>
#include <unordered_map>
#include <string>

void cmd_help() { /* ... */ }
void cmd_quit() { /* ... */ }

std::unordered_map<std::string, std::function<void()>> cmds = {
    {"help", cmd_help},
    {"quit", cmd_quit},
    {"echo", [](const std::string& s){ /* ... */ }}   // 还能存 lambda
};
// cmds["help"]();   // 调用
```
`std::function` 优势：1) 能存任意可调用对象（函数指针、lambda、函数对象、bind 表达式）；2) 类型统一 `std::function<R(Args...)>`，不用记复杂函数指针语法；3) 可携带状态（lambda 捕获）。代价：有运行时开销（类型擦除 + 间接调用），热路径仍优先用模板/函数指针。

> **实测校准（见「底层实现与实测 3」）**：`std::function` 的**单次调用开销和裸函数指针基本相同**（2.04 vs 2.03 ns/次），两者都是一次间接跳转。真正的差距是**模板 + lambda 可内联**（0.32 ns/次，快约 6 倍）。所以"为性能把 `std::function` 换成裸函数指针"收效甚微，要提速得上模板。`std::function` 的额外成本主要在构造/拷贝（`sizeof` 32 字节，捕获内容超出小对象缓冲时堆分配）。

</details>

**5. 判断题**：下面两句话对不对？
> (a) 用函数指针数组做跳转表，比一长串 `if-else` 快得多，因为省掉了分支判断。
> (b) 函数指针比 `std::function` 快得多，因为 `std::function` 有类型擦除开销。

<details><summary>答案</summary>

**两句都错**，实测都打脸：

(a) **跳转表 0.74 ns/次 vs if-else 0.74 ns/次——基本持平。** 分支目标固定时 CPU 分支预测器对两者都能预测成功。函数指针跳转表的价值是**可扩展性**（新增分支 = 数组加一项，上层代码不动）和可读性，不是性能。

(b) **裸函数指针 2.03 ns vs `std::function` 2.04 ns——几乎相同。** 两者都是一次间接跳转，`std::function` 的多出来的是"取 invoke 指针"这一步，被流水线吃掉了。真正快的是**模板参数 + lambda（0.32 ns）**，因为能被内联。

**一句话记住**：分水岭是**编译期能不能确定被调用者**（能不能内联），不是用什么语法写回调。

</details>
