# 6.4 特殊用途语言特性

## 本节讲什么

四个 C++ 函数相关特性：**默认实参**、**内联函数 `inline`**、**`constexpr` 函数**、**调试辅助 `assert`/`NDEBUG`**。前三者都是 C 没有的。

## 核心用法

### 默认实参

```cpp
void log(const std::string& msg, int level = 0);  // level 默认 0
log("startup");          // 等价 log("startup", 0)
log("error", 3);         // 显式传 level
```
- 默认实参只能出现在形参列表**最右边**
- 一个形参在给定时只能默认一次

### inline 函数

```cpp
inline int square(int x) { return x * x; }   // 建议编译器内联展开
```
`inline` 是**建议**不是命令，编译器可能不内联（递归、太大等）。主要用途：避免函数调用开销 + 让函数定义放头文件。

### constexpr 函数（C++11）

```cpp
constexpr int factorial(int n) {
    return n <= 1 ? 1 : n * factorial(n - 1);
}
constexpr int x = factorial(5);   // 编译期计算 = 120
int arr[factorial(3)];            // 6 个元素，编译期
```
`constexpr` 函数**可在编译期求值**（实参是常量表达式时），也可在运行期调用。这是替代 `#define` 宏的强工具。

### 调试辅助

```cpp
#include <cassert>
assert(ptr != nullptr);     // NDEBUG 未定义时检查，失败 abort

// 定义 NDEBUG 关闭所有 assert
#define NDEBUG
```

## 和 C 的区别

| 维度 | C | C++ |
|------|---|-----|
| 默认实参 | ❌ C 没有 | ✅ |
| `inline` 关键字 | ❌ C89 无（C99 加了 `inline` 但语义不同） | ✅，且用于头文件定义 |
| `constexpr` 函数 | ❌ 完全没有 | ✅ C++11 起 |
| 编译期常量函数 | 只能用 `#define` 宏（无类型检查/作用域） | `constexpr` 函数（类型安全） |
| `assert`/`NDEBUG` | ✅ 一致 | ✅ 一致 |

**C 程序员最该迁移的**：用 `constexpr` 替代 `#define` 宏做常量。宏没有类型、没有作用域、调试难看；`constexpr` 有类型、有作用域、可在调试器查看。

```c
/* C：宏做常量，无类型，易错 */
#define BUFSIZE 1024
#define MAX(a,b) ((a)>(b)?(a):(b))   // 参数求值两次，副作用坑
```
```cpp
// C++：constexpr，类型安全
constexpr int BUFSIZE = 1024;
constexpr int max(int a, int b) { return a > b ? a : b; }  // 只求值一次
int arr[BUFSIZE];                       // OK，编译期常量
```

### 四件事分别解决什么问题（动机）

| 特性 | 没有它时可怎么办 | 它真正解决的事 |
|---|---|---|
| 默认实参 | 手写一堆 wrapper：`log(msg)` 内部调 `log(msg, 0)` | 消除「只差一个参数」的重复函数 |
| `inline` | 头文件里放函数定义 → 两个 TU 包含就 duplicate symbol | **ODR 豁免**：函数定义可以进头文件（现代主要语义） |
| `constexpr` | `#define` 宏常量、手写常量表、模板元编程 | 把运行期计算搬到编译期，零运行成本 |
| `assert` / `NDEBUG` | `#ifdef DEBUG` 手写开关 | 调试期检查、发布版零成本消失（但副作用也会消失，见实测 4） |

## 底层实现与实测

> 以下均为本机实测（Apple clang 23.1.0，arm64，`-std=c++17 -O2`）。

### 实测 1：默认实参是在**调用点**填进去的

```cpp
__attribute__((noinline)) int add(int a, int b = 10) { return a + b; }
int use_default3(int x) { return add(x); }
```

```asm
use_default3(int):
    mov  w1, #10          ; =0xa      ← 默认值在"调用方"里被补上
    b    add(int, int)                ← 函数本身只有 add(int,int) 一个签名
```

三个直接推论：

1. 符号表里**只有** `add(int, int)`，没有「带默认值的重载」——默认实参不产生重载，也不算函数类型的一部分。
2. **改默认值必须重新编译所有调用方**（默认值被烧进每个调用点的指令里）。库里改成 20，老调用方二进制里还是 10。这是比「改了没生效」更难查的 ABI 级坑。
3. 虚函数的默认实参是**静态绑定**的：

```cpp
struct B { virtual void f(int x = 1) { printf("B::f x=%d\n", x); } };
struct D : B { void f(int x = 2) override { printf("D::f x=%d\n", x); } };
D* d = new D;  B* b = d;
b->f();   // 实测输出：D::f x=1   ← 函数体是 D 的，默认值却是 B 的
d->f();   // 实测输出：D::f x=2
```

函数走虚表（动态），默认值按指针的**静态类型**在编译期填（静态）。**Effective C++ Item 37 就讲这条**：绝不重新定义继承来的默认实参值。

### 实测 2：`inline` 关键字不决定内联，决定的是 ODR

```cpp
inline int square(int x) { return x * x; }
int use(int x) { return square(x); }
```

| 编译选项 | `use` 的汇编 | 是否被内联 |
|---|---|---|
| `-O0`（**写了** `inline`） | `bl square(int)` | ❌ 没内联 |
| `-O2`（**写了** `inline`） | `mul w0, w0, w0` | ✅ 内联 |
| `-O2`（**不写** `inline`，小函数） | `mul w0, w0, w0` | ✅ 照样内联 |

**结论**：内联与否由优化器和函数体大小决定，`inline` 只是"建议"。那 `inline` 还剩什么用？——**ODR 豁免**：

```console
$ clang++ a.cpp b.cpp            # 两个 TU 都定义 int dup() { ... }
ld: 1 duplicate symbol for architecture arm64

$ clang++ a.cpp b2.cpp           # b2.cpp 里是 inline int dup() { ... }
（链接通过）
```

所以现代 C++ 里 `inline` 的实际语义是「**这个函数可以出现在多个翻译单元，只要定义完全一致**」——这正是头文件里能直接写函数体（类内成员函数默认就是 inline）的原因。

### 实测 3：`constexpr` 到底有没有编译期求值，看汇编就知道

```cpp
constexpr int fact(int n) { return n <= 1 ? 1 : n * fact(n - 1); }
int use_constexpr() { return fact(5); }     // 实参是常量
int use_runtime(int n) { return fact(n); }  // 实参运行期才知
```

```asm
use_constexpr():
    mov  w0, #120        ; =0x78     ← 编译期算完，一条立即数，零调用

use_runtime(int):
    ...
    bl   fact(int)                    ← 退化成普通函数调用（递归被展开成向量化循环）
```

`constexpr` 是「**能**在编译期求值」，不是「**一定**在编译期求值」。想强制，C++20 有 `consteval`：

```console
consteval int sq(int x) { return x * x; }
int n = argc;  return sq(n);
error: call to consteval function 'sq' is not a constant expression
```

编译期递归有上限（clang 默认 512）：

```console
static_assert(fact(1000) == 0);
error: constexpr evaluation exceeded maximum depth of 512 calls
```

需要更深时加 `-fconstexpr-depth=N`（实测加到 2000 后深度不再是瓶颈，但会撞下一步数限制）。**别在编译期算 Fibonacci(40) 这类指数级展开**——编译时间会爆炸。

### 实测 4：`NDEBUG` 会把 assert **整句**删掉，连带副作用

```cpp
int g_bump = 0;
int bump() { ++g_bump; return g_bump; }
int main() { assert(bump() > 0); printf("g_bump = %d\n", g_bump); }
```

| 编译方式 | 输出 | 说明 |
|---|---|---|
| `clang++ -O2 x.cpp` | `g_bump = 1` | assert 生效，`bump()` 真被调用 |
| `clang++ -O2 -DNDEBUG x.cpp` | `g_bump = 0` | **整句被移除，副作用也没了** |

断言失败时进程 `abort`：

```console
Assertion failed: (p != nullptr), function main, file special.cpp, line 41.
exit=134          ← 128 + SIGABRT(6)
```

**工程铁律**：`assert` 里只能放"检查"，不能放"必须执行的动作"。`assert(fclose(f) == 0)` 在 Release 构建下文件根本没关——这是真实项目里出现过的数据丢失 bug。

## HFT / 嵌入式视角

- **`constexpr` 查表替代运行期计算**：撮合里的手续费档位、tick size 表、CRC/哈希多项式表，`constexpr` 生成后落进 `.rodata`，热路径零计算。比运行期 `if-else` 档位判断省掉一次不可预测分支。
- **`inline` 与头文件实现**：低延迟库普遍 header-only（`inline` 或模板），配合 `-flto` 才能跨 TU 内联；否则跨编译单元的小函数会保留真实调用（`bl`），一次约 1 ns。
- **默认实参用作版本开关要小心**：`send(msg, /*retry=*/true)` 这类布尔默认值，一旦改默认行为必须全量重编（实测 1）；更好的做法是显式传或独立函数名。
- **`assert` 在实盘的取舍**：生产构建通常 `-DNDEBUG`，但**前置条件检查不能只靠 assert**（会被删）。校验外部输入（行情包、订单字段）要用返回错误码的显式检查，assert 只用于「内部不可能为假」的不变量。
- **嵌入式**：`constexpr` 把配置算进固件（不占 RAM），`assert` 失败在裸机环境通常没有 stderr，需自行实现 `__assert_func` 或直接避免依赖。

## 常见错误

1. **默认实参中间留空**：`void f(int a=1, int b, int c=3)` —— 默认实参必须连续在最右，`b` 没默认值却出现在 `a`（有默认）之后，错误。
2. **`constexpr` 函数含运行期操作**：C++11 的 `constexpr` 函数只能有 `return` 一条语句；C++14 放宽（可有局部变量、循环）。但若实参不是常量表达式，函数退化为运行期调用——别误以为"加了 constexpr 就一定编译期求值"。
3. **`inline` 放声明而非定义**：`inline` 应放在函数**定义**上。放声明上无效，且如果定义在另一文件会造成链接错误（`inline` 函数必须在每个使用它的 TU 中可见，通常放头文件）。
4. **把必须执行的动作写进 `assert`**：`assert(fclose(f) == 0);` / `assert(send(sock, buf, n) == n);` —— `-DNDEBUG` 后整句消失（实测 4），文件没关、包没发。**修正**：`int r = fclose(f); assert(r == 0);` 把动作和检查分开。
5. **改默认实参值后只重编库**：默认值被编译进每个调用点（实测 1：`mov w1, #10`），老调用方二进制里仍是旧值。**修正**：默认值用 `constexpr` 常量表达，改动后全量重编；或干脆不用默认实参表达"策略"。
6. **重新定义继承来的默认实参**：`Base::f(int=1)` 被 `Derived::f(int=2)` 覆盖时，通过 `Base*` 调用拿到的是 1（实测 1 推论 3，输出 `D::f x=1`）。**修正**：不重写默认实参，或用非虚接口（NVI）模式让虚函数不带默认实参。

## 自测题

**1. 选择题**：下面哪个 `constexpr` 函数在 C++11 中合法？
- A) `constexpr int f(int n) { int s=0; for(int i=0;i<n;++i) s+=i; return s; }`
- B) `constexpr int f(int n) { return n < 0 ? -n : n; }`
- C) `constexpr int f(int n) { if (n > 0) return n; return 0; }`
- D) `constexpr void f(int n) { /* 副作用 */ }`

<details><summary>答案</summary>

B。C++11 的 `constexpr` 函数只能有**一条 return 语句**，B 用三元运算符满足。A 有循环和局部变量（C++14 才允许）；C 有 if 语句（C++14 才允许）；D 返回 void，constexpr 函数不能返回 void（C++14 起 void 也可以，但 C++11 不行）。

</details>

**2. 判断题**：`inline` 关键字保证函数一定被内联展开。

<details><summary>答案</summary>

错误。`inline` 只是**建议**，编译器根据优化等级、函数大小、是否递归等决定是否真的内联。现代编译器即使没写 `inline` 也会内联小函数（LTO 下跨文件内联），写了 `inline` 也可能不内联。`inline` 的现代主要语义是"允许多次定义（ODR 放宽）"，让函数能放头文件。

</details>

**3. 踩坑题**：下面声明合法吗？
```cpp
void f(int a = 1, int b);     // a 有默认，b 没有
void g(int a, int b = 2, int c = 3);  // OK
```

<details><summary>答案</summary>

第一行不合法。默认实参必须**从右向左**连续，`b` 在 `a` 右边但没默认值，错误。第二行合法（b、c 都有默认，a 没有，从右向左连续）。**修正**第一行：`void f(int a, int b = 1);` 或 `void f(int a = 1, int b = 2);`。

</details>

**4. 应用题**：用 `constexpr` 写一个编译期阶乘函数，并用它定义一个编译期数组 `int fact_table[10]`，每个元素是 `fact(i)`。说明相比 `#define` 宏方案的优势。

<details><summary>答案</summary>

```cpp
constexpr int fact(int n) {
    return n <= 1 ? 1 : n * fact(n - 1);   // C++11 单 return + 递归
}
int main() {
    int fact_table[10] = {
        fact(0), fact(1), fact(2), fact(3), fact(4),
        fact(5), fact(6), fact(7), fact(8), fact(9)
    };
    // 编译期全部算好，运行期零开销
}
```
相比 `#define FACT5 (5*4*3*2*1)` 手写：1) 类型安全（int 而非无类型）；2) 有作用域（函数作用域）；3) 递归通用，不用每个数手写；4) 调试器能看到 `fact` 的值；5) 不会像宏那样因参数求值两次产生副作用。

</details>

**5. 判断题**：下面两句话对不对？
> (a) 写了 `inline` 的函数一定会被内联展开，没写的就不会。
> (b) 加了 `constexpr` 的函数一定在编译期求值。

<details><summary>答案</summary>

**两句都错。**

(a) 实测：`-O0` 下写了 `inline` 的 `square` 仍是 `bl square(int)`（没内联）；`-O2` 下**不写** `inline` 的小函数照样被内联成 `mul`。内联由优化器决定，`inline` 的现代主要语义是 **ODR 豁免**（两个 TU 各定义一次非 inline 同名函数 → `duplicate symbol`；改成 `inline` → 链接通过）。

(b) 实测：`fact(5)` 编译成 `mov w0, #120`（编译期）；`fact(n)`（`n` 运行期才知）退化成真正的 `bl fact(int)`。`constexpr` 是"能"不是"必"。要强制编译期，C++20 用 `consteval`（实测：传运行期实参报 `call to consteval function 'sq' is not a constant expression`）。

</details>

**6. 输出题**：下面程序两次运行的输出是什么？
```cpp
struct B { virtual void f(int x = 1) { printf("B::f x=%d\n", x); } };
struct D : B { void f(int x = 2) override { printf("D::f x=%d\n", x); } };
int main() {
    D* d = new D;  B* b = d;
    b->f();   // ①
    d->f();   // ②
}

int g = 0;  int bump() { ++g; return g; }
assert(bump() > 0);  printf("g=%d\n", g);   // ③ 不带 NDEBUG / 带 -DNDEBUG
```

<details><summary>答案</summary>

① `D::f x=1` —— **函数体是 D 的（虚表动态分派），默认实参却是 B 的 1**（静态类型决定，编译期填）。
② `D::f x=2` —— 静态类型是 `D*`，填 2。
③ 不带 `NDEBUG`：`g=1`；带 `-DNDEBUG`：`g=0`（整句 assert 被移除，`bump()` 根本没跑）。

**两条教训**：(1) 绝不重新定义继承来的默认参数值（Effective C++ Item 37），避免"函数走子类、默认值走父类"这种精神分裂；(2) assert 里只放检查，不放必须发生的副作用。

</details>
