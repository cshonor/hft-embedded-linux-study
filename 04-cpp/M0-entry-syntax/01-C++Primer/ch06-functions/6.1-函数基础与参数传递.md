# 6.1 函数基础与参数传递

## 本节讲什么

函数的组成（返回类型、函数名、形参列表、函数体），以及 C++ 两种关键的参数传递方式：**传值**和**传引用**。传引用是 C 没有、C 程序员必须掌握的特性。

## 核心用法

### 函数形参

| 形参形式 | 写法 | 作用 |
|---------|------|------|
| 传值 | `void f(int x)` | 拷贝实参，形参改动不影响实参 |
| 传引用 | `void f(int& x)` | 绑定实参，可改实参 |
| 传 const 引用 | `void f(const int& x)` | 绑定实参，只读，避免拷贝 |
| 传指针 | `void f(int* p)` | 通过指针改实参（C 也能） |
| 数组形参 | `void f(int* a)` / `void f(int a[])` | 退化为指针 |

### 传引用 vs 传指针

```cpp
// 传引用：语法更干净，函数体内直接用 x
void inc(int& x) { ++x; }
int a = 10;
inc(a);              // a 变 11，调用处看不出在修改

// 传指针：调用处要取地址，更明显
void inc(int* p) { ++(*p); }
int a = 10;
inc(&a);             // a 变 11，调用处知道会改
```

### 可变形参

```cpp
#include <initializer_list>
void log(std::initializer_list<int> args) {
    for (auto x : args) std::cout << x << " ";
}
log({1, 2, 3, 4});   // 4 个参数
```

## 和 C 的区别

| 维度 | C | C++ |
|------|---|-----|
| 传值 | ✅ | ✅ |
| 传指针 | ✅ | ✅ |
| 传引用 | ❌ C 完全没有 | ✅ `&` 是 C++ 独有 |
| 传 const 引用避免拷贝 | ❌（只能传指针） | ✅ |
| 可变形参 | `va_list`（不安全，无类型检查） | `initializer_list<T>`（类型安全） |
| `main(int, char**)` | 一致 | 一致 |

**C 程序员最该学的**：传引用。C 里要让函数修改实参，只能传指针（`f(&a)`）；C++ 可以直接传引用（`f(a)`），代码更干净。但**只读大对象避免拷贝**用 `const T&` 是 C++ 的惯用法，C 做不到——C 里只能传指针（仍是间接寻址）或传值（拷贝开销）。

```c
/* C：要让函数改实参，必须传指针 */
void inc(int* p) { ++(*p); }
int a = 10; inc(&a);
```
```cpp
// C++：传引用，更干净
void inc(int& x) { ++x; }
int a = 10; inc(a);

// C++ 独有：const 引用避免拷贝大对象
void print(const std::string& s) { std::cout << s; }  // 不拷贝
```

## 底层实现与实测

> 以下均为本机 clang 实测（`-std=c++17`，Apple Silicon）。传值和传引用的差别**不是语法糖层面的**，在汇编和拷贝计数上都能直接看出来。

### 实测 1：传引用在 ABI 层就是传指针

同一个 `return x + 1` 写三遍，分别用值、`const int&`、`const int*` 作形参，`-O0 -S` 看汇编：

```asm
__Z2fvi:                    ; int fv(int x)          —— 传值
    ldr  w8, [sp, #12]      ; 直接从栈槽取"值"
    add  w0, w8, #1
    ret

__Z2frRKi:                  ; int fr(const int& x)   —— 传引用
    ldr  x8, [sp, #8]       ; 先取"地址"
    ldr  w8, [x8]           ; 再解引用
    add  w0, w8, #1
    ret

__Z2fpPKi:                  ; int fp(const int* x)   —— 传指针
    ldr  x8, [sp, #8]       ; 完全一样的两条
    ldr  w8, [x8]
    add  w0, w8, #1
    ret
```

**结论**：`fr`（引用）和 `fp`（指针）生成的指令**逐条相同**——引用在机器层面就是"自动解引用的指针"。差别只在语言规则（引用不能为空、不能重绑定、不能绑右值），不在运行时开销。这也解释了为什么引用"零开销"的说法只对大对象成立：它省的是**拷贝**，不是**间接寻址**。

### 实测 2：传值到底拷几次

给类型加一个拷贝构造计数器，同一个对象调用 1000 次：

| 形参写法 | 1000 次调用的拷贝构造次数 |
|---------|------------------------|
| `void f(Counted x)` 传值 | **1000** |
| `void f(const Counted& x)` | **0** |

传值每次进来都要构造一个形参副本；`const T&` 只是绑定，一次都不拷。这个计数器和 [3.3 vector push_back 的拷贝计数](../ch03-strings-vectors-arrays/3.3-library-type-vector/3.3.5-拷贝移动与扩容.md) 是同一套方法。

### 实测 3：大对象传参的真实代价

4 KB 的对象（`char buf[4096]`），拷贝构造带副作用（防止编译器把拷贝优化掉），`noinline` 调用 20 万次：

| 形参写法 | 20 万次耗时 | 折合单次 |
|---------|-----------|---------|
| `by_value(BigC)` 传值 | 2.1 ~ 2.6 ms | **≈ 10.5 ~ 13.0 ns** |
| `by_cref(const BigC&)` | 1.1 ~ 1.3 ms | **≈ 5.4 ~ 6.6 ns** |

**注意一个容易测错的地方**：第一版我用的是"只读一个字节"的普通结构体，实测两者都是 0.57 ms——因为编译器发现副本没人改，直接把拷贝优化没了。**要测出真实差距，拷贝构造必须带副作用**（或类型非 trivially copyable），否则你会得到"传值和传引用一样快"的错误结论。

### 实测 4：`initializer_list` 是"栈上临时数组的视图"

```cpp
std::initializer_list<int> il = {1,2,3,4,5};
sizeof(il) == 16            // 两个指针：首地址 + 长度
il.begin() == 0x16f962d50   // 打印出来是栈地址
```

**它不是容器**：不拥有元素。`{1,2,3,4,5}` 由编译器在**调用方的栈帧**上开一个临时数组，`initializer_list` 只是指向它的一对指针。所以：

```cpp
std::initializer_list<int> bad() { return {1,2,3}; }   // ❌ 返回即悬垂
```

这与 `std::span` 的视图语义同类（见 [3.5.6](../ch03-strings-vectors-arrays/3.5-arrays/3.5.6-C++在内建数组之上补的三层.md)）。

### 实测 5：哪些实参能绑给哪种形参

| 形参 | 实参 `int a` | 实参 `42`（右值） | 实参 `std::move(a)` |
|------|------------|-----------------|-------------------|
| `T x`（值） | ✅ 拷贝 | ✅ 拷贝 | ✅ 移动（若有移动构造） |
| `T& x` | ✅ 绑定 | ❌ `error: no matching function for call to 'f'` | ❌ 同上 |
| `const T& x` | ✅ 绑定 | ✅ 绑定（临时对象） | ✅ 绑定 |

非 const 左值引用**拒绝右值**，这是编译期硬错误，不是警告。

### 实测 6：传值 vs 传引用——差距只在"大对象"上真正拉开

200 万次调用，`noinline` 挡住内联，`-O2`（`examples/6.1-2-abi-params.cpp`）：

| 结构体大小 | 传值 | 传 `const&` | 差 |
|---|---|---|---|
| 4 B | 2.84 ns | 2.68 ns | 噪声级 |
| 8 B | 2.34 ns | 2.35 ns | 噪声级 |
| 16 B | 2.00 ns | 2.00 ns | 持平 |
| 32 B | 1.93 ns | 1.74 ns | −10% |
| 64 B | 1.95 ns | 1.57 ns | −19% |
| **256 B** | **5.84 ns** | **1.38 ns** | **−76%（快约 4 倍）** |

**诚实读法**：≤64 字节时两者差距在 ±8% 内，属于噪声——**别拿这个数字去改代码风格**。真正拉开差距的是 256 字节这种"放不进寄存器"的对象：传值要多做一次 `memcpy`，传引用只传 8 字节地址。

> ⚠ 这组数据是 `noinline` 下测的"传参 + 调用"裸开销。真实代码里小对象传值**通常能被内联**（不用取地址、可做常量传播），那时传值反而更好。所以真正的排序是：**能不能内联 > 传值/传引用**。

### 实测 7：`initializer_list` 是栈上的一块临时数组

```
[dangling 内] 元素地址: 0x16cfeed28 0x16cfeed2c 0x16cfeed30（间距 4，连续 = 数组）
[dangling 外] 再读：1 2 3   ← 值还在纯属巧合，栈还没被覆盖（UB）
auto il = {1,2,3};  sizeof(il) = 16   ← 就是 {指针, 长度}
```

`std::initializer_list` **不拥有元素**：它只是一个指向编译器在栈上造的临时数组的视图。返回 `il.begin()` 等于返回悬空指针；只有把它绑定到变量（`auto il = {...}`）时，底层数组的生命周期才跟随该变量。

### 实测 8：三种可变形参的类型安全差多少

| 写法 | 类型检查 | 实测 |
|---|---|---|
| C varargs `sum(int n, ...)` | ❌ 无 | `sum_varargs(1, 3.14)` 用 `int` 读 `double` → **1374389535** |
| `initializer_list<int>` | ✅ 限同类型 | 编译期拒绝异类 |
| 模板变参 `template<class...Ts>` + fold | ✅ 任意类型 | `sum_tmpl(1, 2.5)` → 3（明确截断） |

那个 `1374389535` 不是乱码，是 `3.14` 的 IEEE754 位模式 `0x40091EB851EB851F` 的**低 32 位** `0x51EB851F`——把 `double` 当 `int` 读的典型结果。varargs 的错误**静默无声**，这也是 C++ 里应当优先用 `initializer_list` 或模板变参的原因。

## HFT/嵌入式关联

- **热路径形参的默认值**：大对象（> 寄存器宽度）一律 `const T&` 或 `std::span`，实测 4 KB 对象单次节省约 6 ns；高频调用（order book 更新、行情回调）乘上每秒几十万次就是毫秒级差异。
- **但别走极端**：引用在机器层是指针（实测 1），函数内每次访问都要多一次 load。对 `int`/`double`/小 POD，传值反而更直接——**传值省的是间接寻址，传引用省的是拷贝**，两者针对不同对象大小。
- **`const T&` 不是万能的**：绑定临时对象时生命周期只延长到**当前完整表达式**（见 [2.3.1 临时量生命周期延长](../ch02-variables-and-basic-types/2.3-compound-types/2.3.1-引用.md)），把它存进成员或容器就悬垂。跨调用保存请用值或 `shared_ptr`。
- **不要返回/保存 `initializer_list`**（实测 4）：它是栈上临时数组的视图，函数返回即失效。需要长期持有就改用 `std::vector`/`std::array`。
- **可变形参选型**：`initializer_list<T>` 类型安全、只能同类型，适合配置项；`va_list` 无类型检查，窄化/类型不匹配一律 UB，**工程代码不要用**。

## 常见错误

1. **传引用导致调用处看不出副作用**：`inc(a)` 表面看像传值，实际改了 `a`。大型工程里这降低可读性。**建议**：要修改实参用指针或非 const 引用，且命名体现（`out_param`）；只读用 `const T&`。
2. **`const T&` 绑定临时对象后长期使用**：`const std::string& s = compute();` 合法且延长临时对象生命周期，但若 `compute()` 返回引用指向已销毁对象则悬垂。区分"返回引用"和"返回值"。
3. **数组形参sizeof误判**：`void f(int a[10]) { int n = sizeof(a); }` —— `a` 退化为指针，`sizeof(a)` 是指针大小不是数组大小。C/C++ 共同坑。
4. **把 `const T&` 形参存起来当长期引用**：形参绑定到调用方的对象，函数返回后引用即悬垂——
   ```cpp
   struct Holder { const std::string& name; };
   Holder make(const std::string& s) { return {s}; }   // ❌ s 可能是临时对象
   Holder h = make("abc");                             // h.name 已悬垂
   ```
   **判据**：引用成员的生命周期必须长于持有者；不确定就改存值 `std::string name`。
5. **返回或保存 `initializer_list`**（实测 4）：它只是栈上临时数组的 `{首地址, 长度}`，函数返回即失效。要持有就拷进 `std::vector`。

7. **返回 `initializer_list` 的指针/迭代器**：它只是栈上临时数组的视图，函数返回即悬空。要返回"一串值"，返回 `std::vector`/`std::array` 这种真正拥有元素的容器。
8. **用 C varargs 传非 `int`/`double` 兼容类型**：`printf` 族之外的 varargs 不做任何类型检查，传 `double` 用 `%d` 读、传 `char`/`float`（会被提升）都可能静默出错。改用 `initializer_list`（同类型）或模板变参（异类型）。

## 自测题

**1. 选择题**：下面函数想避免拷贝又只读访问 `vector`，哪种形参最合适？
- A) `void f(std::vector<int> v)`
- B) `void f(std::vector<int>& v)`
- C) `void f(const std::vector<int>& v)`
- D) `void f(std::vector<int>* v)`

<details><summary>答案</summary>

C) `const std::vector<int>&`。`const` 保证只读，`&` 避免拷贝。A 会拷贝整个 vector；B 不能绑定 const 对象；D 要调用方取地址，且没 const 不保证只读。

</details>

**2. 判断题**：C++ 中 `void f(int& x)` 可以接受字面量 `f(42)`。

<details><summary>答案</summary>

错误。非 const 引用不能绑定到右值（字面量、临时对象）。`f(42)` 编译错误。如果要接受字面量，形参改为 `int x`（传值）或 `const int& x`（const 引用可绑定右值）。

</details>

**3. 踩坑题**：下面代码想返回数组的引用供调用者修改，但有问题吗？
```cpp
int (&f())[10] {
    int arr[10] = {0};
    return arr;     // 返回数组引用
}
```

<details><summary>答案</summary>

悬垂引用。`arr` 是局部数组，函数返回后销毁，返回的引用指向已释放内存，使用即 UB。**修正**：返回 `std::array`（值返回，会移动/拷贝），或返回堆上 `std::vector`，或传入外部数组引用由调用者管理。C++ 不要返回局部数组的指针/引用。

</details>

**4. 应用题**：写一个 `swap` 函数，分别用 C 指针风格和 C++ 引用风格实现，对比可读性。

<details><summary>答案</summary>

```cpp
// C 风格：指针
void swap_c(int* a, int* b) { int t=*a; *a=*b; *b=t; }
int x=1, y=2; swap_c(&x, &y);

// C++ 风格：引用
void swap_cpp(int& a, int& b) { int t=a; a=b; b=t; }
int x=1, y=2; swap_cpp(x, y);
```
引用版本函数体内 `a`、`b` 直接当变量用，无需解引用 `*a`，可读性好得多。标准库的 `std::swap` 就是引用风格。

</details>

**5. 选择题**：`f(const std::vector<int>&)` 与 `f(std::vector<int>)`，哪个更快？

<details><summary>答案</summary>

**没有固定答案，取决于能不能内联。**

- 可内联的小函数：传值通常更好（无需取地址、可做常量传播、可放进寄存器）。
- 不可内联（`noinline`/跨 TU/递归）：实测 256 字节对象传值 5.84 ns、传引用 1.38 ns，**传引用快约 4 倍**；但 ≤64 字节时两者差距在噪声级。

**工程结论**：内置类型和小 POD（≤2 个寄存器）传值；大对象、容器、字符串传 `const&`；需要拷贝所有权（要存下来）就传值 + `std::move`。

</details>

**6. 踩坑题**：下面代码有什么问题？
```cpp
std::initializer_list<int> make() { return {1, 2, 3}; }
auto xs = make();
int first = *xs.begin();
```

<details><summary>答案</summary>

**悬空**。`initializer_list` 不拥有元素，底层数组是 `make()` 栈上的临时对象，函数返回即销毁。`*xs.begin()` 读的是已释放的栈内存——实测"碰巧还能读到 1 2 3"，但换个调用栈就会被覆盖。

**修正**：返回真正拥有元素的容器：
```cpp
std::vector<int> make() { return {1, 2, 3}; }        // ✅ 值语义 + NRVO，零拷贝
std::array<int, 3> make2() { return {1, 2, 3}; }     // ✅ 固定长度，栈上，无堆分配
```

</details>
