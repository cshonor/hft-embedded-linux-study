# 6.3 函数重载（Overloaded Functions）

## 本节讲什么

C++ 的**函数重载**：同一作用域内，函数名相同但形参列表不同。编译器通过**重载匹配**（overload resolution）决定调用哪个版本。这是 **C 没有的特性**，C 程序员必须理解匹配规则。

## 核心用法

### 典型用途（为什么需要它）

重载解决的是「同一件事、不同类型」的**命名爆炸**问题。四个真实场景：

**① 打印 / 格式化**：`log(int)`、`log(double)`、`log(const char*)`、`log(const std::string&)` 对外就是一个 `log`，调用方不必记住 `log_int` / `log_double` 这些后缀。

**② 构造函数**：`std::string` 有 `string()`、`string(const char*)`、`string(size_t, char)`、`string(const string&)`……全是同名构造函数，靠实参分派。

**③ 容器的 const / 非 const 双版本**：

```cpp
T&       operator[](size_t i);        // 非 const 对象：返回可改的引用
const T& operator[](size_t i) const;  // const 对象：返回只读引用
```

这是 C++ 里最常见的重载模式，`v[0]` 能否被赋值由 `v` 是否 const 决定。

**④ HFT / 嵌入式里的统一入口**：行情字段的格式化函数对 `Price`（定点整数）、`Qty`、`Timestamp` 各有一个版本，上层代码只写 `fmt(x)`；设备寄存器写入对 8/16/32 位宽度各一个版本 `write_reg(addr, v)`。

### 重载的条件

函数名相同，但下列任一不同即可重载：
- 形参**个数**不同
- 形参**类型**不同
- 形参**顺序**不同（类型层面）

```cpp
void print(int i);          // #1
void print(double d);       // #2  类型不同
void print(const char* s);  // #3  类型不同
void print(int a, int b);   // #4  个数不同

print(42);        // 调 #1
print(3.14);      // 调 #2
print("hi");      // 调 #3
print(1, 2);      // 调 #4
```

**注意**：返回类型**不参与**重载区分——`int f(int)` 和 `void f(int)` 不能共存（调用 `f(1)` 无法区分）。

### 重载匹配的转换等级

匹配不是"能转就行"，而是按等级排序（完整规则见 [6.6 函数匹配](./6.6-函数匹配（重载决议）.md)）：

| 等级 | 内容 |
|---|---|
| 精确匹配 | 类型一致、左值变换（数组/函数→指针）、加 const、引用绑定 |
| 提升 | 整型提升（`char`/`short`→`int`）、浮点提升（`float`→`double`） |
| 转换 | 算术转换（`int`→`double`）、指针转换、`bool` 转换 |
| 用户定义转换 | 转换构造函数 / 转换函数 |
| 省略号 | `...` |

前一级整体优于后一级。**二义性不是"第三档"**，而是同级之间分不出胜负时的失败态。

```cpp
void f(int);
void f(double);
f(3.14);     // 精确匹配 f(double)
f(42);       // 精确匹配 f(int)
f(3.14f);    // 实测选 f(double)：float→double 是提升，float→int 是转换
```

> 实测（Apple clang 23.1.0，见下方「底层实现与实测 2」）：`f(3.14f)` 走 `f(double)`，不是二义性。把"提升"和"转换"当成同一档，会得出相反结论——这是本笔记早期版本的一处误判，已按实测修正。

## 和 C 的区别

| 维度 | C | C++ |
|------|---|-----|
| 函数重载 | ❌ 同名函数只能有一个 | ✅ 形参列表不同即可 |
| 处理多类型 | C 用不同名字：`print_int`/`print_double` | 统一 `print`，编译器分派 |
| 名字修饰 | C 简单（`_func`） | C++ name mangling（`_f_i`/`_f_d`） |
| `extern "C"` | — | C++ 用来禁用重载、与 C 互操作 |

**C 程序员的认知转变**：C 里 `print_int`、`print_double`、`print_string` 是常态；C++ 里统一叫 `print`，编译器按实参类型自动分派。这能显著减少命名负担，但要注意匹配二义性。

```c
/* C：每个类型一个名字 */
void print_int(int x);
void print_double(double x);
void print_str(const char* s);
```
```cpp
// C++：统一名字，编译器分派
void print(int x);
void print(double x);
void print(const char* s);
```

**与 C 互操作**：C++ 为了能调用 C 库，提供 `extern "C"` 关闭 name mangling：
```cpp
extern "C" void c_func(int);   // 用 C 链接规则，不 mangling
```

## 底层实现与实测

> 以下均为本机实测（Apple clang 23.1.0，arm64，`-std=c++17 -O2`）。重载的全部判断**发生在编译期**，运行期零开销——这是它和虚函数/函数指针最根本的区别。

### 实测 1：重载在二进制里就是「不同符号」（name mangling）

```cpp
int f(int x);  double f(double x);  int f(int a, int b);
extern "C" int c_add(int, int);
```

```console
$ clang++ -std=c++17 -c mangle.cpp -o mangle.o && llvm-nm -g mangle.o | c++filt
0000000000000018 T f(double)
0000000000000000 T f(int)
0000000000000034 T f(int, int)
0000000000000054 T _c_add          ← extern "C"：不 mangling，C 符号
```

未 demangle 的原始符号是 `__Z1fi` / `__Z1fd` / `__Z1fii`（Itanium C++ ABI）：
`_Z` + 名字长度 `1` + 名字 `f` + 参数类型编码 `i`=int / `d`=double / `ii`=int,int。
**返回类型不在里面**——这正是「返回类型不参与重载」的物理原因：链接器根本看不到返回值信息。

推论：加了 `extern "C"` 就退回 C 规则，重载立刻失效：

```console
error: conflicting types for 'cf'     ← extern "C" void cf(int) 与 cf(double) 冲突
```

### 实测 2：决议结果一览（`examples/6.3-1-overload-resolution.cpp`）

| 调用 | 实参类型 | 选中 | 为什么 |
|---|---|---|---|
| `f(42)` | `int` | `f(int)` | 精确匹配 |
| `f(3.14)` | `double` | `f(double)` | 精确匹配 |
| `f(3.14f)` | `float` | **`f(double)`** | float→double 是**提升**，float→int 是**转换**，提升优先 |
| `f('a')` | `char` | `f(int)` | 整型提升 |
| `f(true)` | `bool` | `f(int)` | 整型提升 |
| `f(s)`（`short`） | `short` | `f(int)` | 整型提升 |
| `g(0)` | `int` | `g(int)` | 精确匹配（0 是 int，不是空指针） |
| `g(nullptr)` | `nullptr_t` | `g(const char*)` | nullptr→指针是**转换**且精确；nullptr→int 不允许 |
| `pick(x)`（左值） | `int` 左值 | `pick(int&)` | 非 const 引用优先于 const 引用 |
| `pick(42)`（右值） | `int` 右值 | `pick(const int&)` | 非 const 引用绑不了右值 |
| `pick(y)`（const 左值） | `const int` | `pick(const int&)` | `int&` 丢 const，不可行 |

### 实测 3：`NULL` 是重载的经典地雷

```cpp
printf("typeid(NULL).name() = %s\n", typeid(NULL).name());   // 输出 l  → long
printf("sizeof(NULL) = %zu\n", sizeof(NULL));                // 输出 8
```

macOS/LLVM 里 `NULL` 是 `__null`（本质是 `long`），**不是指针**。于是：

```console
void g(int); void g(const char*);
g(NULL);
error: call to 'g' is ambiguous          ← long→int 与 long→指针 同为"转换"级
```

而 `g(nullptr)` 干净地选中 `g(const char*)`；`g(0)` 干净地选中 `g(int)`。
**结论**：C++11 起一律用 `nullptr`，`NULL` 在重载集里是定时炸弹（在没有指针重载、`long`/`int` 并存时它还会悄悄选中 `long`）。

### 实测 4：顶层 const 忽略——「重复声明」合法，「重复定义」才报错

```cpp
void h(int x);
void h(const int x);   // ✅ 合法：与上一行是同一个函数的再次声明
void h(int x) { }      // ✅ 定义一次，OK
```

```console
void f(int x) {}
void f(const int x) {}
error: redefinition of 'f'     ← 定义两次才报
```

> 修正：本笔记早期版本写「`f(int)` 与 `f(const int)` 报重复定义」，措辞不准——**重复声明完全合法**，只有重复定义才报 redefinition。形参的顶层 const 只影响函数**内部**能否改这份副本，不构成新函数类型。

### 实测 5：三种二义性，编译器原话

| 代码 | 报错 |
|---|---|
| `void f(int); void f(double); f(3u);` | `call to 'f' is ambiguous`（unsigned→int 与 unsigned→double 都是转换级） |
| `void f(long); void f(double); f(42);` | `call to 'f' is ambiguous`（int→long 与 int→double 都是转换级） |
| `extern "C" void cf(int); extern "C" void cf(double);` | `conflicting types for 'cf'` |

### 实测 6：重载是编译期分派，比运行期分派快 5 倍

2 000 万次调用，`-O2`（`examples/` 同款基准，被调函数可内联）：

| 分派方式 | 实测 | 汇编形态 |
|---|---|---|
| **重载**（静态分派，可内联） | **0.13–0.18 ns/次** | 调用点被展开，甚至只剩一条 `add` |
| 函数指针（`volatile` 防提升） | 0.94 ns/次 | `ldr` + `blr` |
| 虚函数（vtable） | 0.99 ns/次 | 两次 `ldr` 取 vptr/槽位 + `blr` |

**重载本身不花一分钱**：编译器在编译期就把「调哪个」定死了，剩下的成本只取决于能不能内联。这也是为什么 C++ 里能用重载/模板（静态多态）就不要上虚函数（动态多态）——差的那 ~0.8 ns 在纳秒级撮合里就是真金白银。

### 实测 7：三个"边角"规则，教科书常常不讲

（`examples/6.3-2-overload-details.cpp`）

**① `extern "C"` 里没有重载**：C 链接不做 name mangling，同一个名字只能对应一个符号，写两份签名直接 `redefinition`。所以**给 C 用的头文件里不能有重载**——这也是 C API 常见 `foo_i` / `foo_d` 命名后缀的来源。

**② 默认实参会制造二义性**：
```cpp
void amb(int);
void amb(int, int = 0);
amb(1);        // ❌ call to 'amb' is ambiguous（两个候选都匹配得上，没有理由偏好谁）
amb(1, 2);     // ✅ 只有 amb(int,int) 可行
```
声明本身合法，撞车发生在调用点。**给重载函数加默认实参前，先把所有可能的调用点列一遍。**

**③ 重载集不能直接传给算法**：
```cpp
int sq(int); double sq(double);
std::transform(v.begin(), v.end(), out.begin(), sq);              // ❌ 推不出 sq 是哪个
std::transform(v.begin(), v.end(), out.begin(),
               static_cast<int(*)(int)>(sq));                     // ✅ 显式定型
std::transform(v.begin(), v.end(), out.begin(),
               [](int x){ return sq(x); });                       // ✅ 推荐：还能内联
```
重载集是一个**名字**，不是一个值；要当值传递必须先定型（`static_cast` 或包一层 lambda）。

**④ const 重载**：`S::get()` 与 `S::get() const` 是两个函数，按对象的常量性在**编译期**分派——这正是容器 `operator[]` 要有"可读版 / 可写版"两份的原因（实测非 const 对象 → 1，const 对象 → 2）。

## HFT / 嵌入式视角

- **用重载替代运行期类型判断**：行情消息解码 `decode(const OrderMsg&)` / `decode(const TradeMsg&)` 在编译期定死分支，热路径上没有 if-else 链、没有虚表查询。
- **但别用重载做「配置开关」**：`send(msg, /*retry=*/true)` 这种布尔默认实参极易误读，用强类型枚举或独立函数名（`send_with_retry`）更稳。
- **C 里的等价物是 `_Generic`（C11）**：没有真重载，只能靠宏挑函数，实测可用但只是语法糖——没有 mangling，也没有类型安全的重载决议：

```c
#define print(x) _Generic((x), int: print_int, double: print_double, \
                          char*: print_str, const char*: print_str)(x)
print(42);  print(3.14);  print("hi");   /* 实测：分别落到三个函数 */
```

- **嵌入式**：`write_reg(uint16_t addr, uint8_t/16_t/32_t)` 重载在 -O2 下全部内联成单条 `str` 指令；若改用函数指针表，每次寄存器访问多一次 `blr` 且无法内联。

## 常见错误

1. **二义性调用**：`void f(long); void f(double); f(3);` —— int→long 和 int→double 都是标准转换，谁也不比谁好，二义性报错。**修正**：显式转换 `f(static_cast<long>(3))` 或加 `f(int)` 重载。
2. **重载与默认实参冲突**：`void f(int); void f(int, int=0); f(1);` —— 调用 `f(1)` 二义性。**修正**：避免这种设计。
3. **以为返回类型参与重载**：`int f(int); void f(int);` —— 编译错误"重复定义"。返回类型不区分重载。底层原因：mangled 名字里只有参数类型，没有返回类型（实测 1 的 `__Z1fi`）。
4. **在重载集里传 `NULL`**：`void g(int); void g(const char*); g(NULL);` —— 实测报错 `call to 'g' is ambiguous`（`NULL` 是 `long`，两个方向都是"转换"级）。**修正**：一律写 `nullptr`；传整数就写 `0`。
5. **改默认实参后只重编库、不重编调用方**：默认实参是在**调用点**填充的（实测见 [6.4](./6.4-特殊用途语言特性.md)：汇编 `mov w1, #10` 出现在调用方里）。库里把默认值从 10 改成 20，老调用方二进制里仍是 10——这类"改了没生效"的 bug 极难查。**修正**：默认值写 `constexpr` 常量，且改动后全量重编。

7. **在 `extern "C"` 块里写重载**：C 链接没有 mangling，同一名字只能有一个符号，两份签名是 `redefinition`。需要给 C 用时，用 `foo_int` / `foo_double` 这样的名字区分。
8. **给重载函数加默认实参**：`void f(int)` + `void f(int,int=0)` 在 `f(1)` 处直接二义。加默认实参前把所有调用点过一遍。
9. **把重载函数名直接传给 `std::transform` / `std::sort` 等**：重载集无法推导模板实参。用 `static_cast<int(*)(int)>(f)` 或包一层 lambda。

## 自测题

**1. 选择题**：下面哪些能构成合法重载（同作用域内）？
- A) `int f(int)` 与 `void f(int)`
- B) `int f(int)` 与 `int f(const int)`
- C) `int f(int)` 与 `int f(int&)`
- D) `int f(int)` 与 `int f(int, int)`

<details><summary>答案</summary>

C 和 D。A 返回类型不同不构成重载（重复定义）；B 形参的顶层 const 在函数类型里被忽略，`f(int)` 与 `f(const int)` 是同一个函数，报重复定义；C 形参类型不同（值 vs 引用），合法——但 `f(x)` 这种左值调用会二义，见 [6.6](./6.6-函数匹配（重载决议）.md)；D 个数不同，合法。

</details>

**2. 判断题**：C++ 中 `void f(int&)` 和 `void f(const int&)` 可以重载，且 `f(42)` 调用后者。

<details><summary>答案</summary>

正确。非 const 引用不能绑右值，`42` 是右值，所以 `f(42)` 精确匹配 `f(const int&)`（const 引用能绑右值）。`int x=1; f(x)` 则优先匹配 `f(int&)`（非 const 优先）。这是容器 `operator[]` 常见的 const/非 const 重载模式。

</details>

**3. 踩坑题**：下面调用合法吗？为什么？
```cpp
void f(long);
void f(double);
f(42);
```

<details><summary>答案</summary>

二义性，编译错误。`42` 是 int，int→long 和 int→double 都是"标准转换"（同一优先级），编译器无法选最优。**修正**：`f(static_cast<long>(42))` 或 `f(42L)` 显式指定，或添加 `void f(int)` 重载。

</details>

**4. 应用题**：为一个日志函数设计重载集，支持 `int`、`double`、`const char*`、`const std::string&` 四种参数，写出声明并说明 `log("hello")`（字符串字面量）会匹配哪个。

<details><summary>答案</summary>

```cpp
void log(int x);
void log(double x);
void log(const char* s);
void log(const std::string& s);
```
`log("hello")` 中 `"hello"` 是 `const char[6]`，**精确匹配** `log(const char*)`（数组退化到指针），优先于 `log(const std::string&)`（后者要类类型转换，优先级低）。所以调 `log(const char*)`。如果想强制走 string 版，写 `log(std::string("hello"))`。

</details>

**5. 踩坑题**：下面三次调用分别选中哪个重载？能否编译？
```cpp
void g(int);
void g(const char*);
g(NULL);
g(nullptr);
g(0);
```

<details><summary>答案</summary>

- `g(NULL)` —— **编译失败**：`error: call to 'g' is ambiguous`。本机 `NULL` 是 `long`（`typeid(NULL).name()` 输出 `l`，`sizeof` 8），long→int 和 long→`const char*` 都是"转换"级，同级无法决胜。
- `g(nullptr)` —— `g(const char*)`，`nullptr_t` 只能转指针，唯一可行。
- `g(0)` —— `g(int)`，精确匹配。

**修正**：指针就写 `nullptr`，整数就写 `0`，永远不要在重载集里写 `NULL`。

</details>

**6. 底层题**：为什么 C++ 不允许「返回类型不同」构成重载？从链接符号的角度解释。

<details><summary>答案</summary>

因为 **mangled 符号里没有返回类型**。`int f(int)` 和 `double f(int)` 会 mangled 成同一个名字 `__Z1fi`（Itanium ABI：`_Z` + 名字长 `1` + `f` + 参数码 `i`）。两者若共存，目标文件里出现两个同名符号，链接器无法区分——所以语言层直接禁止。

反过来也说明为什么**参数类型**能构成重载：它们进了符号（`__Z1fi` / `__Z1fd` / `__Z1fii`）。可实测：`clang++ -c x.cpp -o x.o && llvm-nm -g x.o | c++filt`。

顺带一个推论：调用 `f(1);` 丢弃返回值时调用方根本没写期望类型，即使标准想按返回类型分派也无上下文可用。

</details>

**6. 选择题**：以下哪个**能**编译通过？
- A) `extern "C" { void f(int); void f(double); }`
- B) `void g(int); void g(int, int = 0);` 然后调用 `g(1);`
- C) `std::transform(v.begin(), v.end(), out.begin(), sq);`（`sq` 有两个重载）
- D) `int h(int); double h(int);`

<details><summary>答案</summary>

**都不行，四个全是编译错误**（只是错法不同）：

- A ❌：C 链接没有 name mangling → `redefinition of 'f'`。
- B ❌：声明合法，但 `g(1)` 调用点 `call to 'g' is ambiguous`。
- C ❌：重载集无法推导模板实参 → `couldn't infer template argument '_UnaryOperation'`。
- D ❌：`functions that differ only in their return type cannot be overloaded`。

修正：A 改名；B 去掉默认实参或去掉一个重载；C 用 `static_cast` 或 lambda 定型；D 返回值不同不构成重载，必须改形参。

</details>

**7. 踩坑题**：`std::string` 的 `operator[]` 为什么要有两个版本？用一个 `int& operator[](size_t)` 不行吗？

<details><summary>答案</summary>

因为**只读场景要能作用于 const 对象**。成员函数按隐式对象参数（`this` 的 const 性）分派：

```cpp
char& operator[](size_t);              // 非 const 对象 → 可写
const char& operator[](size_t) const;  // const 对象 → 只读
```

只写一个非 const 版本，`const std::string s; s[0];` 就编译不过（实测：`S::get()` 非 const 对象 → 1，const 对象 → 2）。

注意：**返回类型不同本身不构成重载**，能重载是因为第二个版本多带了 `const` 限定（隐式对象参数类型不同）。

</details>
