# 6.2 返回类型

## 本节讲什么

函数的返回类型：值返回、引用返回、返回指针，以及 C++11 的**尾置返回类型**和 `auto` 返回类型推导。重点讲"返回引用"的注意事项——避免悬垂引用。

## 核心用法

| 返回形式 | 写法 | 说明 |
|---------|------|------|
| 返回值 | `int f()` | 拷贝/移动结果返回 |
| 返回引用 | `int& f()` | 返回引用，可作左值，避免拷贝 |
| 返回 const 引用 | `const int& f()` | 只读引用，避免拷贝 |
| 返回指针 | `int* f()` | 返回指针，注意所有权 |
| 尾置返回（C++11） | `auto f() -> int` | 复杂返回类型时清晰 |
| auto 推导（C++14） | `auto f()` | 编译器推导返回类型 |

### 返回引用作左值

```cpp
int& at(int* arr, int i) { return arr[i]; }
int a[3] = {0,0,0};
at(a, 1) = 42;        // 返回的引用直接当左值用
```

### 尾置返回类型

```cpp
// 数组指针返回类型，传统写法很难读
int (*func(int i))[10];

// C++11 尾置返回，清晰得多
auto func(int i) -> int(*)[10];
```

## 和 C 的区别

| 维度 | C | C++ |
|------|---|-----|
| 返回值/指针 | ✅ | ✅ |
| 返回引用 | ❌ C 没有 | ✅ C++ 独有，可作左值 |
| 尾置返回类型 | ❌ | ✅ C++11 |
| `auto` 返回推导 | ❌ | ✅ C++14 |
| 返回类型参与重载 | ❌ | C++ 有重载 |

**返回引用是 C 程序员要学的新东西**：C 里函数返回的总是值或指针，不能"返回一个可直接赋值的位置"。C++ 的 `operator[]` 等就是靠返回引用实现的（`v[i] = x` 才能工作）。

```c
/* C：要改数组某元素，只能传指针+下标 */
void set(int* a, int i, int v) { a[i] = v; }
set(arr, 1, 42);
```
```cpp
// C++：返回引用作左值，语法更自然
int& at(int* a, int i) { return a[i]; }
at(arr, 1) = 42;
```

## 底层实现与实测

> 本机 clang 实测（`-std=c++17`）。返回类型这块最容易讲错的一点是"返回大对象很贵"——实测下来 **C++17 之后它常常是零开销的**，但要分清哪一种是语言保证、哪一种只是优化。

### 实测 1：RVO / NRVO —— 一个是语言保证，一个只是优化

给类型加上 ctor / COPY / MOVE / dtor 打印，两种返回方式对比，`noinline` 防止整个函数被内联掉：

```cpp
T make(int n)          { return T(n); }              // ① 返回 prvalue（临时量）
T make_named(int n)    { T t(n); return t; }         // ② 返回具名局部对象（NRVO 候选）
T make_moved(int n)    { T t(n); return std::move(t); }  // ③ 手动 move
```

**默认编译（`-O0`）：**

```
① return T(n);           ctor(1) → a=1 → dtor(1)
② return t;              ctor(2) → b=2 → dtor(2)
③ return std::move(t);   ctor(3) → MOVE(3) → dtor(3) → c=3 → dtor(3)   ← 多一次移动！
```

**加 `-fno-elide-constructors` 关掉省略后：**

```
① return T(n);           ctor(1) → a=1 → dtor(1)          ← 依然零拷贝！
② return t;              ctor(2) → MOVE(2) → dtor(2)      ← 退化成移动
③ return std::move(t);   ctor(3) → MOVE(3) → dtor(3)      ← 与默认时一样
```

**这张表是本节最该记住的：**

| 返回形式 | C++17 起的性质 | `-fno-elide-constructors` 下 |
|---------|--------------|---------------------------|
| `return T(args);`（prvalue） | **强制省略**，不是优化，是语言规则 | 依然零拷贝 |
| `return local_var;`（NRVO） | **允许但非保证**的优化 | 退化成 **MOVE**（无移动构造则 COPY） |
| `return std::move(local);` | ❌ 反而**阻止** NRVO | 强制 MOVE |

最后一行是常见反向优化：想"手动帮它移动"，结果把 NRVO 挡掉了，白多一次 MOVE。**返回局部对象就直接 `return t;`，不要加 `std::move`。**

### 实测 2：返回局部对象的引用 —— 编译期就警告，运行期数值会变

```cpp
int& bad() { int x = 42; return x; }
int main() { int& r = bad(); printf("%d\n", r); printf("%d\n", r); }
```

```
warning: reference to stack memory associated with local variable 'x' returned [-Wreturn-stack-address]
  r = 42        ← 第一次读"碰巧"还是 42
  r = 1         ← 第二次读就被覆盖成垃圾了
```

`printf` 调用复用了那块栈帧，值立刻被改写。所以"我试了一下能打印出 42"**完全不能证明它安全**——这正是悬垂引用最阴的地方：它经常"看起来能用"，然后在别处随机崩。

### 实测 3：返回引用作左值

```cpp
char& front(std::string& s) { return s[0]; }
front(g) = 'X';      // 实测输出 g = Xbc
```

这正是 `v[i] = x`、`m[key] = v`、`os << a << b` 能工作的原理——它们返回的都是引用。（`<<` 返回 `ostream&` 才能链式。）

## HFT/嵌入式关联

- **工厂函数返回值，不返回引用**：实测 1 表明 `return T(args)` 在 C++17 下零拷贝是**语言保证**，所以"为了避免拷贝而改成返回引用/出参"是**过时做法**——出参（`void f(T& out)`）反而破坏了组合性。要真转移所有权就返回 `unique_ptr`。
- **热路径别返回 `std::string`/`std::vector` 的引用**：引用把生命周期暴露给调用方，一旦底层容器 rehash / 扩容（见 [3.3.5](../../ch03-strings-vectors-arrays/3.3-library-type-vector/3.3.5-拷贝移动与扩容.md)），引用立刻失效。要稳定地址就用 `std::deque` 或索引。
- **`auto` 返回推导在模板里要小心**：`auto` 会丢顶层 const 和引用，`template<class T> auto get(T& c) { return c[0]; }` 返回的是**值拷贝**，想保留引用必须写 `decltype(auto)`。这在泛型行情访问器里是典型的"改了返回值语义却不报错"的坑。
- **别返回 `initializer_list`**（见 [6.1 实测 4](./6.1-函数基础与参数传递.md)）：它是栈上临时数组的视图。

## 常见错误

1. **返回局部对象的引用/指针**（悬垂引用）：`int& f() { int x=10; return x; }` —— x 销毁后引用悬垂，UB。C/C++ 共同坑，但 C++ 引用更容易让人忽视（指针至少看着吓人）。
2. **返回局部对象的引用并依赖"延长生命周期"误解**：`const T&` 绑定临时对象会延长其生命周期，但**仅限于直接绑定**——经函数返回的引用不会延长。`const T& r = f();` 中如果 `f` 返回的是值（临时），合法；但若 `f` 返回的是指向局部变量的引用，仍悬垂。
3. **返回 `auto` 但多个 return 类型不一致**：`auto f(bool b) { if(b) return 1; return 3.14; }` —— C++14 auto 推导要求所有 return 类型一致，这里报错。要么统一类型，要么显式指定 `double`。

## 自测题

**1. 选择题**：下面哪个函数返回的引用可以安全用作左值？
- A) `int& f() { int x=1; return x; }`
- B) `int& f(int& x) { return x; }`
- C) `int& f() { return 42; }`
- D) `int& f(int* p) { int local=0; return local; }`

<details><summary>答案</summary>

B。返回的引用绑定到传入的引用形参 `x`，调用者的对象生命周期由调用者保证，安全。A 和 D 返回局部变量引用，悬垂；C 返回字面量引用，非法（非 const 引用不能绑右值）。

</details>

**2. 判断题**：C++14 中 `auto f() { return 42; }` 的返回类型会被推导为 `int`。

<details><summary>答案</summary>

正确。C++14 起 `auto` 返回类型推导，按 return 表达式推导，`42` 推导为 `int`。注意 `auto` 会丢顶层 const/引用，要保留用 `decltype(auto)`。

</details>

**3. 踩坑题**：下面代码看起来合理，运行却崩溃，为什么？
```cpp
const std::string& get_name() {
    return std::string("tmp");   // 返回临时 string 的引用
}
std::cout << get_name();
```

<details><summary>答案</summary>

悬垂引用。`std::string("tmp")` 是临时对象，函数返回时销毁，返回的 `const&` 指向已释放内存。"const 引用延长生命周期"规则**只对直接绑定局部 const 引用生效**，不适用于"函数返回 const 引用"。**修正**：改成按值返回 `std::string get_name()`。

⚠️ 措辞校准：不少资料把按值返回说成"移动返回，零拷贝"，这个说法**不准确**。按 [实测 1](#实测-1rvo--nrvo--一个是语言保证一个只是优化)，`return std::string("tmp")` 返回的是 prvalue，C++17 起拷贝省略是**强制的语言规则**——对象直接构造在调用方的存储里，**连移动构造都不会调用**（实测加 `-fno-elide-constructors` 也关不掉）。"移动"只在 NRVO 被禁、或返回具名局部对象且省略未发生时才会出现。

</details>

**4. 应用题**：用尾置返回类型写一个函数 `make_arr_ptr(int i)`，返回"指向 10 元素 int 数组的指针"，说明为什么尾置写法比传统写法好读。

<details><summary>答案</summary>

```cpp
// 传统写法：int (*make_arr_ptr(int i))[10];   难读
auto make_arr_ptr(int i) -> int(*)[10] {
    static int arr[10];
    return &arr;
}
```
传统写法 `int (*f(int))[10]` 要从内往外读：f 是函数(int)→返回指针→指向 int[10]。尾置写法把返回类型放后面，函数签名 `f(int) -> 返回类型` 更直观，类似现代语言（Go/Rust）的写法。

</details>
