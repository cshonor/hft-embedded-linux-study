# 3.5.1 定义与初始化

## 本节讲什么

内置数组的语法、维度规则、两种初始化方式，以及**不能拷贝/赋值**的致命限制。

## 语法格式

```cpp
T 数组名[常量表达式];

int arr[10];              // 10 个 int
constexpr int n = 5;
double nums[n];           // ✅ 维度是常量表达式

// int m; double a[m];    // ❌ m 是运行时变量，非法 → 见 2.4.3 constexpr
```

**规则：**

- 元素类型**不能是引用**：不存在 `int &ref_arr[5];`
- 数组尺寸必须 **> 0**，**编译期确定**（须 `constexpr` 等常量表达式，见 [2.4.3 constexpr 详解](../../ch02-variables-and-basic-types/2.4-const-qualifier/2.4.3-constexpr详解.md)）
- 局部数组通常在**栈**上；过大易**栈溢出**（HFT 超大缓冲慎用栈数组）

## 列表初始化

可**省略维度**，由初值个数推断：

```cpp
int a1[] = {1, 2, 3};       // 维度 = 3
int a2[5] = {1, 2};         // 前 2 个为 1、2，后 3 个**值初始化为 0**
std::string s[3] = {"hi"};  // 第一个 "hi"，后两个空串 ""

// int err[2] = {1, 2, 3};  // ❌ 初值个数超过数组长度
```

## 字符数组与字符串字面量

用双引号字符串初始化会**自动追加 `'\0'`**：

```cpp
char c1[] = "abc";                    // 实际 4 字节：'a' 'b' 'c' '\0'
// char c2[3] = "abc";              // ❌ 需要 4 字节，放不下结束符
char c3[] = {'a', 'b', 'c', '\0'};  // 等价 c1
```

与 [3.2.4 string 与 C 风格字符串](../3.2-library-type-string/3.2.4-string与C风格字符串.md) 衔接：业务字符串优先 `std::string`；必须 `char[]` 时要**自己保证 `\0` 与边界**。

## 数组不能拷贝、不能整体赋值

```cpp
int a[3] = {1, 2, 3};
// int b[3] = a;   // ❌ 非法：不能拷贝初始化
// b = a;          // ❌ 非法：不能整体赋值
```

只能**逐元素**循环拷贝；这也是传参易丢长度、应优先 `vector` 的原因之一。

## 栈数组 vs 堆数组（Cherno 数组集）

Cherno 数组集的核心对照：

```cpp
int example[5];                      // 栈数组：元素跟着作用域活
int* another = new int[5];           // 堆数组：new 返回的是指针，不是数组
// ...
delete[] another;                    // 手动归还；example 出作用域自动死
```

本机实测（clang 23, `-O0`）三笔账：

| 账 | 实测结果 |
|---|---|
| ① sizeof | `sizeof(example)=20`（类型自带长度）；`sizeof(another)=8`——**堆数组不记长度**，拿到的只是首元素指针 |
| ② 地址分区 | `example=0x16b6865e4`（栈，高地址）；`another=0x123e04210`（堆）；`&another=0x16b6865d0`——指针本身也在栈上，栈堆分工一目了然 |
| ③ 生命周期 | `example` 出作用域自动死（free 都轮不到你）；`another` 必须 `delete[]`，忘了就泄漏 |

**什么时候必须上堆**：数组要活得比创建它的作用域久（典型：从函数返回给调用者）。栈数组返回即悬垂——

```cpp
int* make_stack_arr() {
    int local[5] = {1,2,3,4,5};
    return local;         // warning: address of stack memory associated
                          // with local variable 'local' returned
                          // [-Wreturn-stack-address]（默认就开）
}
```

运行实测两连：刚返回立刻读，**碰巧打出正确值**（栈没被覆盖——悬垂指针最阴险的形态）；中间插一个 `smash()` 函数调用占掉那块栈帧，再读就是 `-7 41435136` 垃圾值。这类 bug 能"时好时坏"地潜伏很久。

**`delete` 与 `new[]` 配对**：`new[]` 出来的必须 `delete[]`。写漏 `[]`（`delete a;`）是 UB——clang `-Wall` 下默认就警告：

```
warning: 'delete' applied to a pointer that was allocated with
'new[]'; did you mean 'delete[]'? [-Wmismatched-new-delete]
```

为什么必须配 `[]`：`delete[]` 要先逐个析构每个元素再整块归还，析构多少个需要编译器在分配时偷偷记的**元素计数**（对 non-trivial 类型存在指针前面的 cookie 里）；不带 `[]` 的 `delete` 只析构一个元素、还按另一套布局归还内存。int 这种平凡类型多数实现"碰巧"不崩，但行为未定义——标准不兜底。

**工程建议**（Cherno 也这么收尾）：需要堆数组的场景，现代 C++ 直接 `std::vector`（要扩容）或 `std::unique_ptr<int[]>`（确定不扩容但要堆生存期）；裸 `new[]`/`delete[]` 配对自己记，错一次就是泄漏或 UB。

## 和 C 的区别（内置数组：C/C++ 语法几乎一致，细节有差异）

内置数组是 C 和 C++ **共享**的语法，大部分行为一致，但 C++ 有几个细节不同：

| 对比点 | C | C++ |
|--------|----|------|
| 维度用变量 | C99 起支持 VLA（变长数组）`int a[n];` | **不支持 VLA**（GCC 扩展除外） |
| 维度用常量 | `#define N 5` 或 `enum` | `constexpr int N = 5;`（推荐） |
| 整体拷贝赋值 | 不支持 | 不支持（两边一样） |
| `auto` 推断数组 | 无 `auto` | `auto a = arr;` 退化为指针（不是数组） |
| 范围 for 遍历 | 无 | `for (int x : arr) {...}`（C++11） |
| `begin`/`end` | 无 | `std::begin(arr)`/`std::end(arr)`（C++11） |

**给 C 程序员的关键提醒：**
1. **C99 的 VLA 在 C++ 不是标准**——`int n = 5; int arr[n];` 在 C99 合法（VLA），在 C++ 是编译错误（GCC 扩展能过但不推荐）。C++ 要么用 `constexpr`（编译期常量），要么用 `vector`（运行时动态）。
2. **`#define N 5` 在 C++ 仍能用**，但 `constexpr int N = 5;` 更好——有类型、有作用域、调试可见。详见 [2.4.3 constexpr](../../ch02-variables-and-basic-types/2.4-const-qualifier/2.4.3-constexpr详解.md)。
3. **数组不能整体拷贝**这条 C 和 C++ 一样——`int b[3] = a;` 在两边都非法。C++ 的解法是 `vector`（可拷贝），C 的解法是 `memcpy`。

## 常见错误

### 1. 用普通变量当数组维度

```cpp
int n = 5;
int arr[n];   // ❌ C++ 标准不允许 VLA（GCC 扩展能过，移植性差）
```

C 程序员（尤其 C99 用的熟的）会习惯 VLA。C++ 要么 `constexpr int n = 5;`（编译期），要么 `std::vector<int> v(n);`（运行时动态）。HFT 热路径上**别用 VLA**——栈大小不定，可能栈溢出。

### 2. `char buf[3] = "abc";` 忘了 `\0`

```cpp
char buf[3] = "abc";   // ❌ 需要 4 字节（'a','b','c','\0'），放不下
```

字符串字面量 `"abc"` 实际是 4 字节（含结尾 `\0`）。`char buf[3]` 只有 3 字节，装不下。C 程序员也踩这个坑（C 里同样错），但 C++ 里更推荐 `std::string` 或 `char buf[] = "abc";`（让编译器算维度）。

### 3. 数组传参后 `sizeof` 拿不到长度

```cpp
void process(int arr[]) {
    size_t n = sizeof(arr) / sizeof(arr[0]);   // ❌ arr 退化为指针，n = 指针大小/元素大小
}
```

数组传参时**退化为指针**，函数内 `sizeof(arr)` 是指针大小（如 8），不是数组总字节。C 和 C++ 都有这个坑。**正确做法**：另传长度参数 `void process(int* arr, size_t n);`，或用 `vector`/`std::array` 自带长度。详见 [3.5.3](./3.5.3-数组退化与指针.md)。

## 自测题

**1. 选择题**　下列哪种数组定义在标准 C++ 中**合法**？

- A. `int n = 5; int arr[n];`
- B. `int arr[5] = {1, 2, 3, 4, 5};`
- C. `int arr[3] = {1, 2, 3, 4};`
- D. `int &ref_arr[3];`

<details><summary>答案</summary>

**B**。A 是 VLA，C++ 标准不支持；C 初值个数超过维度，非法；D 元素不能是引用（不存在引用数组）。B 是标准列表初始化。

</details>

**2. 判断题**　`int arr[5] = {1, 2};` 中后 3 个元素是未初始化的垃圾值。

<details><summary>答案</summary>

**错**。列表初始化时，**未显式给初值的元素会值初始化为 0**。`arr` = `{1, 2, 0, 0, 0}`。这是 C 和 C++ 共有的规则。但如果是 `int arr[5];`（不初始化），局部数组才是垃圾值。

</details>

**2.5 判断题**　函数里 `int* make() { int a[5] = {1,2,3,4,5}; return a; }` 返回后立刻打印 `p[0]`，结果是 1，所以这个写法没问题。

<details><summary>答案</summary>

**错**。这是悬垂指针的经典陷阱：返回的 `p` 指向已死亡的栈数组，**立刻读碰巧拿到正确值**只是因为没人踩过那块栈帧。实测：中间插一个别的函数调用再读，就是垃圾值（`-7 41435136`）。clang `-Wreturn-stack-address` 默认就警告。想跨作用域携带数组，用堆数组（`new int[5]` + `delete[]`）、`std::vector` 或 `std::array`（返回时是值拷贝）。

</details>

**3. 踩坑题**　下面这段 C 风格代码迁移到 C++，有什么问题？

```cpp
#define N 100
int buf[N];

void fill() {
    for (int i = 0; i <= N; ++i)   // 注意 <=
        buf[i] = i;
}
```

<details><summary>答案</summary>

**`buf[N]` 越界写**——`buf` 合法下标是 `0` 到 `N-1`，`buf[N]` 是越界 UB。C 程序员也踩这个，但 C++ 里更推荐：

1. 用 `constexpr int N = 100;` 替代 `#define`（有类型、有作用域）
2. 用范围 for 或 `std::begin`/`std::end` 避免手写下标边界：
   ```cpp
   int i = 0;
   for (int& x : buf) x = i++;
   ```
3. 考虑 `std::array<int, 100>` 替代裸数组（自带 `size()`、可拷贝、边界友好）

</details>

**4. 应用题**　HFT 里要存"最近 10 个 tick"，固定大小。用内置数组和 `std::array` 各写一版，对比。

<details><summary>答案</summary>

```cpp
// C 风格
struct Tick { double price; int qty; };
Tick recent[10];           // 内置数组
size_t count = 0;
// 传参：void process(Tick* arr, size_t n);  丢失长度

// C++ 风格
#include <array>
std::array<Tick, 10> recent;   // std::array
size_t count = 0;
// 传参：void process(const std::array<Tick, 10>& arr);  自带长度
// recent.size() == 10，recent[i] 访问，可整体拷贝
```

`std::array` 优势：
- 自带 `size()`，传参不丢长度
- 支持整体拷贝赋值（`a = b;`）
- 接口和 `vector` 一致（`begin`/`end`/`at`/`[]`）
- 零开销抽象（内存布局和 `Tick[10]` 完全一样）

HFT 热路径上 `std::array` 比 `vector` 省一次堆分配（栈上），比裸数组安全。

</details>
