# 3.5.6 C++ 在内建数组之上补的三层

## 本节讲什么

C++ **没有发明新的数组**——它原封不动继承了 C 的内置数组。真正的差异在别处：C++ 在 `T[N]` 之上补了三个更安全的类型。

本节做两件事：

1. **划清「完全继承」与「真正不同」的边界**（哪些语义 C/C++ 一模一样，哪些是 C++ 新增）
2. **补上 `std::size`/`std::ssize`、`std::array`、`std::span` 三层**——这是 [3.5.1](./3.5.1-定义与初始化.md)–[3.5.5](./3.5.5-易错点与示例.md) 没覆盖的空白

> 实测环境：Compiler Explorer，`g132`（gcc 13.2.0，x86-64 Linux，`-O1 -S -masm=intel`）。
> 本机无 C/C++ 编译器，所有汇编与诊断均为 CE 实测原文。源码见 `examples/3.5.6-*.cpp`。

## 一、完全一致的部分：C 语义原封不动继承

这部分**没有任何 C++ 特有行为**，C 程序员无需重新学习。逐条用汇编钉死：

### 1.1 布局与「数组名不等于指针」

```cpp
int a[4];                  // 连续存储，无边界检查
sizeof(a) == 16            // 作用域内不退化
int (*p)[4] = &a;          // 指向整个数组的指针
```

**实测**（`examples/3.5.6-1-layout-and-decay.cpp`）：

```asm
size_in_scope():     mov eax, 16 ; ret      // 作用域内 sizeof(a) = 16
size_param():        mov eax, 8  ; ret      // 传参后退化，指针 8 字节
size_multi():        mov eax, 24 ; ret      // int[2][3] = 24
size_multi_row():    mov eax, 12 ; ret      // int[3] 一行 = 12
diff_multi():        mov eax, 12 ; ret      // &m[1]-&m[0] = 12（一整行）
diff_whole():        mov eax, 4  ; ret      // &a[1]-&a[0] = 4（一个元素）
```

最后两行是多维数组最容易被忽略的点：`m` 退化成 `int(*)[3]`，**指针算术的步长是「一整行 12 字节」**，不是一个 `int`。

### 1.2 退化有编译器的自证

编译器会主动警告，这是最直观的证据：

```
warning: 'sizeof' on array function parameter 'a' will return size of 'int*'
         [-Wsizeof-array-argument]
  9 | std::size_t size_param(int a[4]) { return sizeof(a); }
    |                                                 ~^~
note: declared here
  9 | std::size_t size_param(int a[4]) { return sizeof(a); }
    |                        ~~~~^~~~
```

注意函数签名里的 `int a[4]` 在汇编层面已被改写成 `int*`——GCC 输出的形参类型就是 `raw(int*)`。

### 1.3 其余一致项速查

| 语义 | C / C++ 是否一致 |
|------|------------------|
| `int a[2][3]` 二维数组 | 一致 |
| 聚合初始化 `{1,2,3}` | 一致 |
| 多维 decay（`a` → `int(*)[3]`） | 一致 |
| `offsetof` 可用 | 一致 |
| `memcpy` 语义 | 一致 |
| VLA（变长数组）**不是标准特性** | 一致（都是编译器扩展） |
| 数组名**不是对象**：不能返回/赋值/当结构体字段 | 一致 |

**VLA 补充实测**：`int vla[n];` 在 gcc 13.2 下编译通过且 `-O1` 汇编只有一条 `ret`（数组完全优化掉）——但这是 GCC 扩展，C++ 标准没有 VLA，Clang 在 `-pedantic-errors` 下会报错。换编译器即失效，别依赖。

## 二、C++ 真正改的三处

| 维度 | C | C++ |
|------|---|-----|
| 拿长度 | `sizeof(a)/sizeof(a[0])` | `std::size(a)`（C++17）、`std::ssize(a)`（C++20） |
| 遍历 | 裸 `for` | 范围 `for (auto x : a)`（C++11 起对内建数组直接可用） |
| 替代类型 | 无 | `std::array<T,N>`（C++11）、`std::span<T,N>`（C++20） |

### 2.1 `std::size` / `std::ssize`——取长度不再靠除法

```cpp
int a[7];
auto n1 = std::size(a);    // size_t    = 7（C++17 起对内建数组可用）
auto n2 = std::ssize(a);   // ptrdiff_t = 7（C++20）
```

**为什么要 `ssize` 而不只用 `size`**：`size_t` 是无符号的，「剩余元素数」用无符号表达时 `0 - 1` 会回绕成天文数字。

```cpp
std::size_t n = std::size(a);
if (i > 0 && n - i < 2) {   // n=0、i=0 时：0-0=0 侥幸正确
    return;                  // n=0、i=1 时：0-1 = 18446744073709551615 ❌
}
```

`std::ssize` 返回 `std::ptrdiff_t`（有符号），`-1` 就是「空/无效」，判断自然。实测 `static_assert` 钉住类型：

```cpp
static_assert(std::is_same_v<decltype(std::ssize(a)), std::ptrdiff_t>);  // ✅ 通过
```

**实测汇编**（gcc 13.2 `-O1`）——两者都是编译期常量，一条指令：

```asm
len_cpp17():  mov eax, 7 ; ret      // std::size(c_arr)，无符号
len_cpp20():  mov eax, 7 ; ret      // std::ssize(c_arr)，有符号
```

> 版本注意：`std::size` 对**内建数组**的 overload 是 **C++17** 才有的；C++11/14 只有容器 overload。所以 C++11 项目里 `std::size(c_array)` 编译不过，要退回 `sizeof(a)/sizeof(a[0])`。

### 2.2 `std::array<T,N>`——布局等价 `T[N]`，零开销

内部就是 `struct { T elems[N]; }`。标准**保证**无额外 padding、可平凡拷贝、与 `T[N]` 内存表示等价：

```cpp
struct WireHeader {
    std::array<std::byte, 16> raw;   // 定长报文头
}

static_assert(sizeof(WireHeader) == 16);          // ✅ 没有额外 tag
static_assert(alignof(WireHeader) == 1);          // ✅ 对齐 1，可按字节 memcpy
static_assert(std::is_standard_layout_v<std::array<int, 4>>);
static_assert(std::is_trivially_copyable_v<std::array<int, 4>>);
```

这四条 `static_assert` 全部编译通过（`examples/3.5.6-2-std-array-span-size.cpp`），所以能安全地 `reinterpret_cast` 打到网络报文或 mmap 缓冲区上——**这是 C 版定长结构体的等价物，但类型安全**。

**零开销的汇编证据**：

```asm
raw_ptr(const std::array<int,4>&):   mov rax, rdi ; ret    // 地址原样传出，一条指令
raw_bytes(const std::array<int,4>&): mov eax, 16  ; ret
```

取地址就是取底层对象地址，没有包装、没有拷贝。

### 2.3 `std::span<T,N>`——外部缓冲区零拷贝切一段

```cpp
std::span<const std::byte> make_hdr(const std::byte* buf) {
    return {buf, 16};      // 不分配、不拷贝，只存 {ptr, len}
}
```

**实测**（`examples/3.5.6-2-std-array-span-size.cpp`，gcc 13.2 `-O1`）：

```asm
make_hdr(std::byte const*):              // 长度是常量 16，被优化成立即数
        mov     rax, rdi        ; ptr 直接传出
        mov     edx, 16         ; 长度压第二个寄存器
        ret                     ; 整个函数 3 条指令

hdr_len(std::span<std::byte const>):     // 动态 extent：长度在第二个寄存器
        mov     rax, rsi        ; 取 span 的 len 字段
        ret

take16(std::span<std::byte const, 16>):  // 静态 extent，体内不用 span
        ret                                 ; 零运行时开销
```

`std::span` 内部就是「指针 + 长度」两个机器字，所以传参**不退化**，长度信息跟着走：

```cpp
std::int64_t hdr_len(std::span<const std::byte> s) { return std::ssize(s); }
// 汇编：mov rax, rsi —— 直接取 len 字段
```

两种 extent 的取舍：

| 写法 | 长度 | 代价 |
|------|------|------|
| `std::span<const std::byte>` | 运行时 | 两条指令 |
| `std::span<const std::byte, 16>` | **编译期常量** | 零指令（`ret` 直接返回），长度写错**编译失败** |

固定长度报文头应该用静态 extent——把「长度对不对」从运行时检查前移成编译期错误。

## 三、一个真正会咬人的差异

```cpp
auto a = {1, 2, 3};     // ❌ std::initializer_list<int> —— 不是数组！
std::array b{1,2,3};    // ✅ 这才是数组
```

`auto` 推导出的是 `std::initializer_list<int>`：内部只有「指向临时数组的指针 + 长度」两个机器字，**不延长底层数组寿命**。

### 3.1 编译器自己把这件事写进了符号表

**实测**（`examples/3.5.6-3-initializer-list-trap.cpp`，`-O1`）：

```asm
a:
        .quad   reference temporary for a      ; ← 符号名自曝这是「a 的临时对象」
        .quad   3
reference temporary for a:
        .long   1
        .long   2
        .long   3                              ; ← 底层数组，和 a 同为静态存储期

get_a(unsigned int):
        mov     rax, QWORD PTR a[rip]          ; 先取临时数组指针
        mov     eax, DWORD PTR [rax+rdi*4]     ; 再索引
        ret
get_b(unsigned int):
        mov     eax, DWORD PTR b[0+rdi*4]      ; std::array 一次寻址
        ret
```

两个硬证据：

1. 符号名叫 `reference temporary for a` —— 编译器给底层数组起的就是这个名字
2. `get_a` 比 `get_b` **多一次 load**：`auto` 版本每次访问都要先取「临时数组指针」

上面 `a` 之所以「看起来能用」，是因为它定义在**全局**——底层数组与 `a` 同为静态存储期，寿命一样长。函数内就完全不同了。

### 3.2 编译器直接拒绝 / 警告

```cpp
auto make() { return {1, 2, 3}; }
```
```
error: returning initializer list
```

显式写返回类型也一样，GCC 13.2 给出**警告原文**：

```cpp
std::initializer_list<int> make3() { return {1, 2, 3}; }
```
```
warning: returning temporary 'initializer_list' does not extend the lifetime
         of the underlying array [-Winit-list-lifetime]
```

`-Winit-list-lifetime` 这条警告就是「临时数组随语句结束析构」的编译器原话。

对照正确写法，汇编只有两条 `mov` + `ret`：

```asm
make2():  mov DWORD PTR [rsp-20], 1
          mov DWORD PTR [rsp-16], 2
          mov rax, QWORD PTR [rsp-20]
          mov edx, 3
          ret
```

### 3.3 HFT 里的典型 UB

```cpp
auto arr = {0};        // initializer_list<int>，不是数组
arr[0] = 1;            // 若 arr 在函数内 → 悬垂访问，UB
for (auto x : arr) {}  // 同上
```

单元素花括号最容易误判——`auto x = {0}` 看着像「一个 0」，实际类型是 `initializer_list<int>`。修复：

```cpp
int x = 0;                 // 就要一个值，别用花括号
std::array<int, 1> a{0};   // 确实要数组
int a[1] = {0};            // 或者 C 风格
```

## 四、`std::array` 按值传参：长度信息能不能拿回来

常见说法是「`std::array` 作形参依然 decay 成裸指针」——**这个说法不准确，实测证明是错的**。

### 4.1 先看实测

```cpp
std::size_t probe_byval(std::array<int,4> a) { return sizeof(a); }   // 16 ← 不是 8
std::size_t probe_byref(std::array<int,4>& a) { return sizeof(a); }  // 16
std::size_t probe_tmpl(int (&a)[4])        { return sizeof(a); }     // 16
```

```asm
probe_byval(std::array<int, 4ul>):  mov eax, 16 ; ret
probe_byref(std::array<int, 4ul>&): mov eax, 16 ; ret
probe_tmpl(int (&) [4]):            mov eax, 16 ; ret
```

`probe_byval` 得到 **16 而不是 8**，说明 `std::array<int,4>` **没有退化**。

原因不难理解：退化规则只作用于**数组类型**（`T[N]`），而 `std::array<T,N>` 是**类类型**（聚合类型，内部有唯一成员 `T elems[N]`）。类类型按值传参就是拷贝构造/移动，不存在「数组名变指针」这回事。`sizeof` 拿到 16 说明体内拿到的仍是完整的 `std::array` 对象。

### 4.2 那真正的问题是什么

不是 decay，而是**传参代价与长度固定性**：

| 写法 | 传参代价 | 体内 `.size()` | 长度能否换 |
|------|---------|--------------|------------|
| `f(std::array<int,4> a)` | **按值拷贝 16 字节** | 可用，返回 `4` | 不能（N 是类型的一部分） |
| `f(std::array<int,4>& a)` | 传引用，零拷贝 | 可用，返回 `4` | 不能 |
| `f(T (&a)[N])` | 传引用，零拷贝 | 无 `.size()` | **能**（N 是模板参数） |
| `f(std::span<const byte>)` | 传「指针+长度」 | 可用 | 不能（长度运行时） |
| `f(std::span<const byte,16>)` | 同上 | 可用 | 不能，但**长度写错编译失败** |

所以工程建议是：

- **小对象、长度固定** → `f(const std::array<int,4>&)`，引用传参零拷贝
- **泛型代码（长度也要当参数用）** → `template <class T, size_t N> f(T (&)[N])`，长度进模板参数
- **外部缓冲区** → `f(std::span<const byte, N>)`，零拷贝且长度写错编译失败

### 4.3 与内建数组的真正差别

| | `int a[4]` | `std::array<int,4>` |
|---|---|---|
| 按值传参 | 退化成 `int*`，`sizeof` = 8 | **不退化**，`sizeof` = 16（按值拷贝） |
| 体内拿长度 | 拿不到（`sizeof` 是指针大小） | `a.size()` 可用 |
| 能否整体赋值 | 不能 | 能 |
| 内存布局 | `T[N]` | 等价 `T[N]`（standard-layout + trivially-copyable） |
| 捕获进 lambda | 按引用捕获才行 | 可按值捕获（仍是数组布局，不含指针） |

最后一行是 HFT 相关的一个实际差别：`std::array` 捕获进 lambda 是值语义，不会因为原数组离开作用域而悬垂。

```cpp
auto f = [a] { return a[0]; };   // std::array：按值捕获，安全
auto g = [a] { return a[0]; };   // int[4]：只能按引用捕获，否则退化后是悬垂指针
```

### 4.4 `std::array<T,N>` 作形参：N 只能走模板参数

`std::array<T,N>` 的 `N` 是**非类型模板参数**，属于类型的一部分（→ [ch16.2 §CE 实测](../../ch16-templates/16.2-模板参数与成员模板.md)）。所以「接收任意长度的 `std::array`」只能写成：

```cpp
template <class T, std::size_t N>
void f(const std::array<T, N>& a);     // ✅ N 由编译器推导
```

三种写法实测（gcc 13.2 / clang 18.1.0，`-std=c++20`）：

| 写法 | 结果 |
|---|---|
| `template<class T,size_t N> f(const std::array<T,N>&)` | ✅ N=3/5/4/8 全部推对，`std::array<float,4>` 也接得住 |
| `f(const std::array<int,6>&)` | ✅ 只收 N=6 |
| `f(const std::array<int, std::size_t N>&)` | ❌ gcc：`template argument 2 is invalid`；clang：`type-id cannot have a name` |

**不退化 ≠ 没有代价**：`std::array<int,256>` 按值传参，函数体内 `sizeof(a)` 实测是 **1024**——不退化意味着**整体 1KB 拷贝真的发生了**（内建数组反而是 8 字节指针）。所以大数组一律 `const&`。

两个与「模板参数 N」直接相关的坑：

**① `array<T,N>` 转不了 `array<const T,N>`**（`int*`→`const int*` 可以，类模板不自动给元素加 const）：

```text
error: invalid initialization of reference of type 'const std::array<const int, 3>&'
       from expression of type 'std::array<int, 3>'
```

⇒ 形参写 `const std::array<T,N>&` 让 `T` 自己推导，别手写 `array<const T,N>`。

**② 形参引用上的 `.size()` 不是常量表达式**：

```cpp
static_assert(N == arr.size());   // ❌ 'arr' is not a constant expression
```

`size()` 是 `constexpr` 成员函数，但 `arr` 是形参引用。编译期要长度用 `N` 或 `std::tuple_size_v<std::array<T,N>>`；反过来 `constexpr std::array<int,3> g{1,2,3}; static_assert(g.size()==3);` 是成立的。

**`N=0` 合法**：`std::array<int,0> a0{}` 实测 `size()==0`、`sizeof==1`、`data()==nullptr`、`begin()==end()`，模板函数能正常接住。

### 4.5 `std::array<char,N>` 与 `'\0'`：容器不管终止符

`std::array<char,N>` **不是字符串**——它只是 `char[N]` 的类包装（§2.2 已证布局等价），没有「自动补 `'\0'`」这回事。但有两条实测值得知道（clang 23.1.0，macOS arm64，2026-10-16）：

```cpp
std::array<char,4> a{"abc"};              // ✅ 能编过（聚合花括号省略，字面量初始化内层 char[4]）
// a.size() == 4, strlen(a.data()) == 3

std::array<char,6> b{'h','e','l','l','o'}; // 只写 5 个
// b[5] == '\0' —— 聚合初始化补零规则对它照样生效
```

| 写法 | 有 `'\0'` 吗 |
|------|:---|
| `std::array<char,4> a{"abc"};` | ✅ 字面量自带（brace elision 透传到内层数组） |
| `std::array<char,6> b{'h',...,'o'};`（没写满） | ✅ 剩余槽位聚合补零，碰巧有了终止符 |
| `std::array<char,5> c{'h','e','l','l','o'};`（写满） | ❌ 没有——`strlen(c.data())` 越界 UB |

规则和内建 `char[N]` **一模一样**（→ [2.1.1 §6](../../ch02-variables-and-basic-types/2.1.1-字符与字符串字面量-C++对C.md) 的聚合补零小节）——这本身就是「布局等价」的直接推论。要拿它当 C 字符串用（`.data()` 传给 `printf("%s")` / C API），终止符的责任全在你。

## 五、多维下标 `a[i,j]`：一个需要更正的说法

C++ 中 `a[i,j]` 的现状**不是「C++23 起等价 `a[i][j]`」**，而是分两种情况：

**提案 P2128R5（Multidimensional subscript operator）明确不修改 C 数组的语义**——FAQs 里写得很直白：

> We do not propose modifications to C arrays […] The usefulness of this should be discussed in the C26 time frame.

所以：

| 类型 | `a[i,j]` 现状 |
|------|---------------|
| 内建数组 `int a[2][3]` | **仍是逗号表达式** `(i, j)`，且 C++ 起 deprecated |
| `std::span` / `std::mdspan` 等新类型 | 支持多维下标，`s[i,j]` 正常 |

**实测**（gcc 13.2，`-std=c++23`，内建数组）：

```
warning: top-level comma expression in array subscript changed meaning in C++23
         [-Wcomma-subscript]
error: invalid conversion from 'int*' to 'int' [-fpermissive]
  6 | int get23(int i, int j) { return a[i,j]; }
    |                                   ^~~~~~
    |                                   int*
```

同一个文件里 `std::span<int,6>` 的 `s[i,j]` 只有警告、没有 error——**新类型支持，内建数组不支持**。

需要显式括号时用 `a[i][j]`，或把内建数组换成 `std::array<std::array<T,N2>,N1>` / `std::mdarray`。

## 六、工程结论

| 场景 | 用什么 | 理由 |
|------|--------|------|
| 热路径 / 内核态交互 / 报文定长字段 | `int[N]`（内建） | 零开销、无隐藏语义、ABI 与 C 一致 |
| 需要 `.size()` 和边界检查 | `std::array<T,N>` | 布局等价 `T[N]`，有 size |
| 「传一个外部缓冲区 + 长度」 | `std::span<T,N>` | 零拷贝，长度跟着走 |
| 需要 `T[N]` 但要对 `memcpy`/C 互操作 | `std::array<T,N>` + `static_assert` | standard-layout 可证 |

**`std::vector` 在 HFT 延迟敏感路径上依然是最差选择**——两次分配加一次拷贝（扩容时还有第三次）。热路径上它只适合「初始化后不再变化」的场景。

---

## 自测题

**1. 判断题**　`std::array<int, 4> a{};` 按值传给函数后，函数内 `sizeof(a)` 是 8（退化成指针了）。

<details><summary>答案</summary>

**错**，实测 `sizeof(a)` 是 **16**。

退化规则只作用于**数组类型**（`T[N]`）；`std::array<T,N>` 是**类类型**，按值传参是拷贝整个对象，不存在「数组名变指针」这回事。

gcc 13.2 `-O1` 实测：

```asm
probe_byval(std::array<int, 4ul>):  mov eax, 16 ; ret
probe_byref(std::array<int, 4ul>&): mov eax, 16 ; ret
probe_tmpl(int (&) [4]):            mov eax, 16 ; ret
```

真正该避免的是**按值传参的拷贝开销**（`std::array<int,64>` 就是 256 字节的拷贝）。改传引用 `void f(const std::array<int,4>&)`。

</details>

**2. 踩坑题**　下面代码有什么问题？

```cpp
auto lookup = {0};
int& slot(int i) { return lookup[i]; }   // 返回引用
```

<details><summary>答案</summary>

`lookup` 的类型是 `std::initializer_list<int>`，不是数组。它只持有一个指向临时数组的指针。

**若 `lookup` 是全局对象**（如题），底层数组与它同为静态存储期，此时侥幸能用——gcc 汇编里符号名就叫 `reference temporary for lookup`。

**若在函数内**（HFT 代码的常态），底层数组在语句结束时析构，`lookup` 里的指针悬垂，`slot()` 返回的是悬垂引用 —— **UB**。

GCC 13.2 对显式返回 `initializer_list` 会报 `-Winit-list-lifetime` 警告：
`returning temporary 'initializer_list' does not extend the lifetime of the underlying array`。

修复：`std::array<int,N> lookup{0}`，或 `int lookup[N] = {0}`，或只要一个值就写 `int lookup = 0`。

</details>

**3. 应用题**　需要解析一个 `int32_t prices[64]` 的定长报文区块，要求零拷贝、不分配、长度在编译期就是 64。写出函数签名。

<details><summary>答案</summary>

```cpp
#include <span>

// 静态 extent 最佳：长度编译期确定，运行时零开销，长度写错编译失败
void process(std::span<const std::int32_t, 64> prices);

// 汇编只有一条 ret
```

三档写法的取舍：

| 签名 | 长度 | 运行时开销 |
|------|------|-----------|
| `void f(int32_t* p, size_t n)` | 运行时传 | 正常调用开销 |
| `void f(std::span<const int32_t> p)` | 运行时（藏在 span 里） | 两条指令（mov ptr / mov len） |
| `void f(std::span<const int32_t, 64> p)` | **编译期常量** | **零**（`ret`） |

「外部缓冲区 + 长度」正是 `std::span` 的设计场景——不拥有内存、不拷贝、只借用视图。

</details>

**4. 判断题**　C++23 起 `int a[2][3]; a[i,j]` 等价于 `a[i][j]`。

<details><summary>答案</summary>

**错**。提案 **P2128R5** 明确 *「We do not propose modifications to C arrays」*——多维下标只对 `std::span`/`std::mdspan` 等新类型生效。

对内建数组，`a[i,j]` 仍是**逗号表达式** `(i, j)`（等价于 `a[j]`），并已 deprecated。gcc 13.2 实测报
`-Wcomma-subscript` 警告 + `invalid conversion from 'int*' to 'int'` error。

</details>
