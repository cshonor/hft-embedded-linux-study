# 3.1 命名空间的 using 声明

> 第 3 章 · 上一章：[第 2 章 小结](../ch02-variables-and-basic-types/2.7-小结.md) · 下一节：[3.2 标准库类型 string](./3.2-library-type-string/3.2-标准库类型string.md)

## 本节讲什么

用 `using std::cin;` 这样的声明把命名空间里的名字引入当前作用域，省得每次写 `std::` 前缀。

## 核心用法

| 写法 | 作用 |
|------|------|
| `using std::cin;` | 引入单个名字，之后写 `cin` 即可 |
| `using std::cin, std::cout;` | C++17 起可一次引入多个 |
| `using namespace std;` | 引入整个命名空间（**慎用**） |

```cpp
#include <iostream>
#include <string>
using std::cin;       // 之后写 cin 即可
using std::cout;
using std::endl;
using std::string;

int main() {
    string line;
    getline(cin, line);
    cout << line << endl;
    return 0;
}
```

## 和 C 的区别（命名空间是 C++ 独有）

**C 没有命名空间。** C 靠命名约定（前缀）和 `static`（文件作用域）避免名字冲突：

| 对比点 | C | C++ |
|--------|---|-----|
| 避免冲突机制 | 命名前缀（`mylib_func`）、`static` | 命名空间 `namespace mylib { }` |
| 调用写法 | `mylib_func()` | `mylib::func()` 或 `using mylib::func;` 后 `func()` |
| 头文件污染 | 用前缀规避 | `using namespace` 会污染 |

**给 C 程序员的关键提醒：**
1. C 里你给函数加前缀（`orderbook_init`、`orderbook_add`）来"模拟命名空间"；C++ 用真正的 `namespace orderbook { void init(); }`，更清晰。
2. `using namespace std;` 相当于把标准库所有名字"倒"进当前作用域——小文件省事，大工程易冲突。**头文件里绝对不要写**，会污染所有包含它的文件。
3. `.cpp` 里写 `using std::string;`（引入确定不冲突的常用名）是合理折中。

## 常见错误

**1. 头文件里写 `using namespace std;`**
```cpp
// myheader.h
using namespace std;   // ❌ 所有包含此头的 .cpp 都被污染
```
头文件会被多个 `.cpp` 包含，污染扩散全工程。头文件用全限定名 `std::string`。

**2. `using` 了不存在的名字**
```cpp
using std::notexist;   // 编译错误：notexist 不是 std 的成员
```

## 自测题

**1（选择）** 下面哪种写法在头文件里最安全？
- A. `using namespace std;`
- B. `using std::string;`
- C. `std::string`（全限定名）

**2（判断）** C 语言也有命名空间机制。

**3（应用）** 把 C 的前缀命名风格 `orderbook_init()`、`orderbook_add()` 改成 C++ 命名空间写法。

<details><summary>参考答案</summary>
1. C。头文件用全限定名最安全，不会污染包含它的文件。`using namespace std` 绝对禁止；`using std::string` 在头文件也不推荐（虽比前者轻）。
2. 错。C 没有命名空间，靠命名前缀和 `static`（文件作用域）避免冲突。命名空间是 C++ 独有。
3. 
```cpp
namespace orderbook {
    void init();
    void add(...);
}
// 调用：orderbook::init(); orderbook::add(...);
```
</details>
