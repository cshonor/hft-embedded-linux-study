# 3.3.5 拷贝移动与扩容

## 本节讲什么

`vector` 扩容时如何拷贝/移动元素；浅拷贝 vs 深拷贝；C `realloc`/`memcpy` 对照；HFT 禁用拷贝、POD 选型。

## C++ 如何实现「可复制」

靠 **拷贝构造** `T(const T&)` 和 **拷贝赋值** `operator=(const T&)`：

| 机制 | 何时调用 |
|------|----------|
| 拷贝构造 | 扩容搬元素、`push_back(x)` |
| 拷贝赋值 | 覆盖已有元素 |

**未手写时**编译器隐式生成 **逐成员浅拷贝**：

- 成员全是标量 → 浅拷贝 = 深拷贝，**安全进 `vector`**
- 含 **裸指针 / 动态内存** → 共享堆块 → 扩容拷贝后 **双析构**；须手写深拷贝（三/五法则，见 [13.1](../../ch13-copy-control/13.1-拷贝控制成员.md)）

```cpp
struct MarketData {
    double bid{0}, ask{0};
    std::int64_t ts{0};
    MarketData() = default;
    MarketData(const MarketData&) = default;
    MarketData& operator=(const MarketData&) = default;
};

std::vector<MarketData> v;
v.push_back({100.5, 100.6});   // 扩容时逐成员拷贝，便宜
```

## 和 C 的区别（拷贝、移动与扩容）

C 程序员对"动态数组扩容"有肌肉记忆：`realloc` 不够就 `malloc` 新块 + `memcpy` + `free` 旧块。C++ 的 `vector` 扩容**本质相同**，但搬元素的方式从 `memcpy` 升级为**拷贝构造/移动构造**：

| 对比点 | C（realloc + memcpy） | C++（vector 扩容） |
|--------|------------------------|---------------------|
| 触发时机 | 自己判断 `n >= cap` 调 `realloc` | `push_back` 容量不够时自动 |
| 搬元素方式 | `memcpy`（**仅 POD 安全**） | 调拷贝构造/移动构造（**任意类型正确**） |
| 含指针的 struct | `memcpy` 后两份共享堆 → 双 free | 调深拷贝构造，各管各的堆 |
| 不可拷贝对象 | C 无此概念（都是字节） | `= delete` 拷贝构造，编译期拒绝 |
| 移动语义 | 无（只能 memcpy 或指针赋值） | `T&&` 移动构造，搬资源不深拷贝 |
| 释放旧内存 | `realloc` 内部处理 | 析构旧元素 + 释放旧缓冲 |

**给 C 程序员的关键转变：**
1. **`memcpy` 不是万能搬元素法**——C 里习惯了 `memcpy(dst, src, n * sizeof(T))`，但只要 `T` 含指针成员（指向堆）、或含 `string`/`vector` 这类管理资源的成员，`memcpy` 就是**浅拷贝**，会导致双 free。C++ 用拷贝构造做深拷贝。
2. **移动语义是 C 没有的**——`HeavyBook&&` 把内部堆块"过户"给新对象，旧对象置空，零拷贝。C 里要实现类似效果得手动交换指针、把旧对象置 NULL。
3. **C 的 `realloc` 失败返回 NULL，旧块还在**；`vector` 扩容失败抛 `std::bad_alloc`，旧数据完整。异常安全比 C 强。

## HFT：禁用拷贝、只允许移动

```cpp
struct HeavyBook {
    std::vector<double> levels;
    HeavyBook() = default;
    HeavyBook(HeavyBook&&) = default;
    HeavyBook& operator=(HeavyBook&&) = default;
    HeavyBook(const HeavyBook&) = delete;
    HeavyBook& operator=(const HeavyBook&) = delete;
};

std::vector<HeavyBook> books;
books.push_back(HeavyBook{});  // 扩容时移动元素，无深拷贝尖刺
```

不可移动时用 **`vector<unique_ptr<T>>`**，扩容只搬指针。

## 为什么常选 POD 作元素

**POD**（Plain Old Data）：基本类型或只含 POD 成员的 `struct`。

| POD / 轻量 struct | 重对象 |
|-------------------|--------|
| 扩容 **memcpy 级**拷贝 | 深拷贝、分配尖刺 |
| 缓存友好 | cache miss 多 |

工程组合：

1. 热路径 `vector<Tick>`，Tick 全标量
2. 容量已知 → **`reserve(n)`** 只扩一次
3. 大对象 → **`vector<unique_ptr<T>>`**

## 常见错误

### 1. struct 含裸指针，没写深拷贝 → 双 free

```cpp
struct Bad {
    int* data;
    Bad() : data(new int[100]) {}
    ~Bad() { delete[] data; }
    // 没写拷贝构造 → 编译器生成浅拷贝
};

std::vector<Bad> v;
v.push_back(Bad{});   // 扩容时浅拷贝，两个 Bad 共享同一块 int[]
// 析构时双 delete[] → 崩溃
```

**C 程序员尤其要警惕**：C 里 `struct { int* p; }` 你不会"拷贝 struct"（C 数组不整体赋值），所以没事；C++ 里 `vector` 会**主动拷贝**元素，就出事了。要么用 `std::vector<int>` 替代裸指针，要么按三/五法则写深拷贝。

### 2. `= delete` 拷贝后还想 `push_back` 拷贝

```cpp
struct NoCopy {
    NoCopy() = default;
    NoCopy(const NoCopy&) = delete;
};
std::vector<NoCopy> v;
NoCopy obj;
v.push_back(obj);   // ❌ 编译错误：拷贝构造被 delete
```

禁拷贝的对象只能**移动**进 vector：`v.push_back(std::move(obj));` 或 `v.emplace_back();` 原地构造。C 没有这个限制（C 不区分拷贝/移动，都是 memcpy）。

### 3. 误以为移动一定比拷贝快

```cpp
struct Small {
    int arr[4];   // 16 字节
};
std::vector<Small> v;
v.push_back(std::move(s));   // 移动 ≈ 拷贝，没省
```

**移动只对"持有资源"的类型有意义**（如 `vector`、`string`、`unique_ptr`）。全是标量的 POD，移动和拷贝都是 memcpy，没区别。HFT 热路径上 `Tick`（全标量）直接拷贝就行，不用纠结 `std::move`。

## 自测题

**1. 选择题**　`vector` 扩容时搬元素，下列哪种类型**不能**放进 `vector`？

- A. 含 `std::string` 成员的 struct
- B. 含裸指针且手写了深拷贝的 struct
- C. 拷贝构造 `= delete`、移动构造也 `= delete` 的 struct
- D. 全是 `double` 的 POD struct

<details><summary>答案</summary>

**C**。既不可拷贝也不可移动，`vector` 扩容时无法搬动元素，编译期就被拒绝。A、B、D 都能正确搬动（A 调 `string` 的拷贝构造，B 调用户写的深拷贝，D memcpy 级拷贝）。

</details>

**2. 判断题**　C 里 `realloc` 用 `memcpy` 搬元素是安全的，所以 C++ `vector` 扩容也用 `memcpy` 就行。

<details><summary>答案</summary>

**错**。`memcpy` 只对 **POD** 安全。如果元素含指针成员（指向堆），`memcpy` 会让两份对象共享同一块堆 → 双析构。C++ `vector` 调**拷贝构造/移动构造**，能正确处理任意类型。C 里"安全"是因为 C struct 通常不"拥有"资源，且 C 不会自动调析构。

</details>

**3. 踩坑题**　下面这段代码哪里会出问题？

```cpp
struct Buffer {
    char* data;
    size_t len;
    Buffer(size_t n) : data(new char[n]), len(n) {}
    ~Buffer() { delete[] data; }
};

int main() {
    std::vector<Buffer> v;
    v.reserve(2);
    v.push_back(Buffer(64));
    v.push_back(Buffer(64));
    v.push_back(Buffer(64));   // 触发扩容
    return 0;
}
```

<details><summary>答案</summary>

**扩容时崩溃**（双 free）。`Buffer` 没写拷贝构造，编译器生成**浅拷贝**——扩容时新旧 `Buffer` 的 `data` 指向同一块堆，析构时 `delete[]` 两次。

**修复**（三法则）：
```cpp
struct Buffer {
    char* data; size_t len;
    Buffer(size_t n) : data(new char[n]), len(n) {}
    ~Buffer() { delete[] data; }
    Buffer(const Buffer& o) : data(new char[o.len]), len(o.len) {
        std::memcpy(data, o.data, len);
    }
    Buffer& operator=(const Buffer& o) {
        if (this != &o) { delete[] data; data = new char[o.len]; len = o.len; std::memcpy(data, o.data, len); }
        return *this;
    }
};
```

或更简单：**用 `std::vector<char>` 替代裸 `char*`**，让 RAII 接管。

</details>

**4. 应用题**　HFT 里有一个 `BigSnapshot`，内含 `vector<double>`（几千个价格档位）。要把它放进 `vector<BigSnapshot>`，如何设计才能避免热路径扩容尖刺？

<details><summary>答案</summary>

```cpp
struct BigSnapshot {
    std::vector<double> levels;
    BigSnapshot() = default;
    // 禁拷贝，允许移动
    BigSnapshot(const BigSnapshot&) = delete;
    BigSnapshot& operator=(const BigSnapshot&) = delete;
    BigSnapshot(BigSnapshot&&) = default;
    BigSnapshot& operator=(BigSnapshot&&) = default;
};

std::vector<BigSnapshot> snaps;
snaps.reserve(64);   // 预留容量
snaps.emplace_back();   // 原地构造
```

要点：
- 禁拷贝 + 允许移动 → 扩容时 `vector` 调移动构造，把 `levels` 的堆块"过户"，零深拷贝
- `reserve` 避免多次扩容
- `emplace_back` 原地构造，少一次临时对象

</details>
