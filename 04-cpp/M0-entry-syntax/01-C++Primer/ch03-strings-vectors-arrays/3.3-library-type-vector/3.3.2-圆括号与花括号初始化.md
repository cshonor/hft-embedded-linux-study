# 3.3.2 圆括号与花括号初始化

## 本节讲什么

`vector` 的 **`()` 默认值初始化** vs **`{}` 列表初始化**——新手最高频坑；HFT 里 `size()` 错一位会静默读错行情。

这是 **`vector` 最容易混的两套逻辑**：

| | **小括号 `()`** | **花括号 `{}`** |
|---|----------------|-----------------|
| 叫法 | **默认值 / 个数初始化** | **列表初始化**（C++11 统一初始化） |
| 语义 | 「给我 **n 个**元素，每个按规则填初值」 | 「花括号里 **有几个数，容器就有几个元素**」 |
| 典型 | `v(10)` → 10 个 `0` | `v{1,2,3}` → 3 个元素，就是 1、2、3 |
| 自定义类 | 每个元素调 **默认构造函数** | 用列表里的值 **逐个构造**，不多生成默认对象 |

## 圆括号：个数 + 默认值初始化

**`vector<int> v(10)`** = **给我 10 个 `int`，每个都用默认值 `0` 填充**。

| 写法 | 含义 | `size()` |
|------|------|----------|
| `vector<int> v(10);` | **10 个 `int`**，值初始化 → `0` | 10 |
| `vector<int> v(10, 5);` | **10 个 `int`**，每个都是 `5` | 10 |
| `vector<MarketData> v(100);` | **100 个对象**，各调默认构造 | 100 |

```cpp
std::vector<int> v(10);      // 10 个 0
std::vector<int> v2(10, 5);  // 10 个 5

struct MarketData { double bid{0}, ask{0}; };
std::vector<MarketData> book(100);  // 100 个默认构造的 tick 槽位
```

## 花括号：列表初始化（挨个塞初值）

**`vector<int> v{1, 2, 3}`** = 花括号里 **3 个数 → 3 个元素**，值就是 `1、2、3`，**不会**再补默认值。

| 写法 | 含义 | `size()` |
|------|------|----------|
| `vector<int> v{1, 2, 3};` | 恰好 3 个元素：`1, 2, 3` | 3 |
| `vector<int> v{10, 5};` | 恰好 **2** 个元素：`10` 和 `5` | **2**（不是 10 个 5！） |
| `vector<int> v{10};` | 恰好 **1** 个元素：`10` | 1 |

```cpp
std::vector<int> a(10, 5);   // size=10，全是 5
std::vector<int> b{10, 5};   // size=2，元素是 10 和 5  ← 最容易写反
```

## 对照记忆

```
v(10)      → 10 个元素，默认填 0（或默认构造）
v(10, 5)   → 10 个元素，全是 5
v{1,2,3}   → 3 个元素，就是 1、2、3
v{10, 5}   → 2 个元素，就是 10 和 5   （不是 v(10,5)！）
```

## HFT：长度错了 = 静默读错行情

- 预分配 **100 档深度**：`vector<Level>(100)`。⚠️ 注意 `vector<Level>{100}` **不一定**只有 1 个元素——
  实测 `Level` 是聚合类型时它**也**是 100 个（详见下方"回退规则"）。安全做法：**表达"个数"一律用圆括号**
- 写完后 **`assert(v.size() == expected)`** 锁死长度

## 为什么要有两套语法（动机）

`vector` 的初始化有两套语法，根源是 **C++11 的"统一初始化"（uniform initialization）**——标准想用 `{}` 取代一切初始化写法，于是给 `vector` 加了一个 `initializer_list<T>` 构造函数。结果就是：**同一个 `v(10)` 和 `v{10}`，走的是两个不同的构造函数**。

编译器按这条规则选（**`initializer_list` 优先，失败才回退**）：

```
写 v{...} 时：
  ① 先试 initializer_list<T> 构造 —— 列表里每个元素都能转成 T 吗？
     能   → 用列表初始化，size = 列表长度
     不能 → ② 回退到圆括号语义 v(n) / v(n, value)
             （此时若 T 没有默认构造 → 编译错误）
```

**回退规则是这条笔记最反直觉的地方**，也是绝大多数教程没讲的：

| 写法 | 元素类型能否从 `int` 构造 | 实测结果 |
|------|--------------------------|----------|
| `vector<int> v{3}` | ✅ 能（`int`→`int`） | **size=1**，元素 3 |
| `vector<double> v{3}` | ✅ 能 | **size=1**，元素 3.0 |
| `vector<string> v{3}` | ❌ 不能（`string` 无法从 `3` 构造） | **size=3**，3 个空串 ← 回退！ |
| `vector<Level> v{100}` | ❌ 不能（聚合类型） | **size=100**，100 个默认对象 ← 回退！ |
| `vector<Explic> v{100}` | ❌ 不能（`explicit` 不参与） | **编译错误**（回退后要默认构造，没有） |

> ⚠️ 本节原文里"`vector<Level>{100}` 只有 1 个元素"的说法是**错的**，实测是 **100 个**。只有当 `T` 能从一个 `int` 构造出来时（如 `int`、`double`），`{}` 才会被当成列表。

## 底层实现与实测

> 环境：Apple clang 23.1.0，libc++，`-std=c++17 -O2`。可跑版本见文末例子。

### 1. 全部写法实测对照

```cpp
std::vector<int> v(10);        // size=10  v[0]=0
std::vector<int> v{10};        // size=1   v[0]=10
std::vector<int> v(10, 5);     // size=10  v[0]=5  v[9]=5
std::vector<int> v{10, 5};     // size=2   v[0]=10 v[1]=5
std::vector<int> v{};          // size=0   （空列表 → 默认构造，等价 vector<int> v;）
std::vector<int> v = {};       // size=0
std::vector<string> v(3);      // size=3   v[0]==""
std::vector<Level> v(100);     // size=100
std::vector<vector<int>> v(3, vector<int>(4));  // size=3，每行 4 个
std::vector<int> v(0);         // size=0   （合法，不开内存）
```

**`v{}` 不是"1 个元素"**——空花括号走的是**默认构造函数**，得到的是空 vector。想得到一个元素写 `v{0}`，想得空容器写 `{}` 或不写。

### 2. 回退规则实测：元素类型决定一切

```cpp
struct Level { double bid{0}, ask{0}; };      // 聚合类型，无 int 构造
struct Explic { explicit Explic(int){} };     // explicit 单参构造

std::vector<Level> a{100};     // 实测 size=100 ！ a[0].bid=0 a[99].ask=0
std::vector<string> c{3, "x"}; // 实测 size=3，三个都是 "x"（3 不能转 string → 回退成 v(3,"x")）
std::vector<Explic> b{100};    // ❌ 编译错误：no matching constructor for 'Explic'
```

`vector<Explic> b{100}` 的报错信息很典型：回退到 `v(100)` 后要**默认构造 100 个 `Explic`**，而 `Explic` 只有 `explicit Explic(int)`，没有默认构造 → 硬错误。**`explicit` 在这里起的作用就是"不让 `100` 被隐式转换"，从而触发回退**。

### 3. 窄化：花括号拒绝，圆括号静默

这是两套语法**安全性**上的本质差别：

```cpp
std::vector<int> d{1, 2.5};   // ❌ error: type 'double' cannot be narrowed to 'int'
                              //          in initializer list [-Wc++11-narrowing]
std::vector<int> e(1, 2.5);   // ⚠️ 只 warning，编译通过：v[0] == 2（2.5 被截断）
std::vector<double> f{1, 2.5};// ✅ size=2（double→double 不是窄化）
```

**`{}` 在标准层面禁止窄化转换**（`double`→`int`、`long`→`int` 等丢失信息的转换），这是 C++11 引入 `{}` 的主要动机之一——把 C 里 `int x = 2.5;` 这种静默截断变成编译错误。圆括号只是普通函数调用，走普通隐式转换。**在行情代码里这能挡住实数价格被静默取整的 bug。**

### 4. most vexing parse：`vector<int> v();` 不是变量

```cpp
std::vector<int> v();   // 这是【函数声明】：返回一个 vector<int> 的无参函数 v
                        // 不是"定义一个空 vector"
```

C++ 规定"能被解析成函数声明的，就解析成函数声明"。**用 `{}` 就没有这个歧义**：`vector<int> v{};` 一定是变量。这也是推荐 `{}` 的理由之一——但对 `vector` 来说 `{}` 又会踩回退坑，所以最稳的写法是 **`vector<int> v;`（不写括号）**。

### 5. 嵌套 vector：圆括号才对

```cpp
std::vector<std::vector<int>> m(3, std::vector<int>(4));  // 3 行 × 4 列，全 0
std::vector<std::vector<int>> m{3, std::vector<int>(4)};  // 实测同样是 3 行 × 4 列！
```

第二行之所以"看起来应该出错却没出错"：`vector<int>` 的单参构造 `vector(size_type)` 是 **`explicit`**，`3` 不能隐式转换成 `vector<int>` → `initializer_list<vector<int>>` 匹配失败 → 回退成 `m(3, vector<int>(4))`。**结果和圆括号一模一样，纯属巧合**。

## HFT / 嵌入式视角

1. **长度错了 = 静默读错行情**。预分配 100 档深度要 `vector<Level>(100)`。但注意：`vector<Level>{100}` 在 `Level` 是聚合类型时**也**是 100 个（回退），只有在 `Level` 有 `Level(int)` 单参构造时才变成 1 个——**这个行为随 `Level` 的定义变化，是维护期的定时炸弹**。所以规则应该是：**表达"个数"一律用圆括号，`{}` 只用于列出具体元素**。
2. **写完 `assert(v.size() == expected)`**。初始化歧义不会报错、不会警告，只会让 `size()` 差一位。一行 `assert` 的成本远低于一次读错盘口的损失。
3. **`{}` 的窄化检查是免费的类型安全**。价格、数量字段用 `{}` 初始化能挡住 `double`→`int` 的静默截断；圆括号只会给一个容易被忽略的 `-Wliteral-conversion` warning。建议在 CI 里把这类 warning 升级为错误（`-Werror=literal-conversion`）。
4. **嵌入式上 `v(n)` 是一次分配 + 一次清零**。1000 万个 `int` 的清零也要几毫秒，在启动路径上算进预算。要"开槽但不清零"只能 `reserve` + `push_back`，或者自己管一块静态数组。
5. **`vector<int> v();` 在嵌入式代码里更隐蔽**：它不报错，只是后面 `v.push_back(...)` 才报 `member reference base type 'std::vector<int> ()' is not a structure or union`，错误信息离真正的错误位置很远。

## 和 C 的区别

**C 没有 vector**，用固定大小数组。`()` vs `{}` 的歧义是 C++ vector 独有的坑：

| 对比点 | C（数组） | C++（vector） |
|--------|----------|---------------|
| 预分配 N 个 | `int arr[N] = {0};` | `vector<int> v(N);` 或 `v(N, 0)` |
| 指定元素 | `int arr[] = {1,2,3};` | `vector<int> v{1,2,3};` |
| `()` vs `{}` 歧义 | ❌ 无（C 数组只有 `{}`） | ✅ **C++ 独有坑**：`v(10)` vs `v{10}` |

**给 C 程序员的关键提醒：** C 数组初始化只有 `{}`，没有 `()`。C++ 的 vector 多了 `()`（个数+默认值），导致 `v(10)` 和 `v{10}` 含义完全不同——这是 C 转 C++ 最容易踩的初始化坑。记住：**`()` 是"几个、什么默认值"，`{}` 是"就这些元素"**。

## 自测题

**1（选择）** `vector<int> v{10, 5};` 的 `size()` 是多少？
- A. 10
- B. 2
- C. 5

**2（踩坑）** 想要 100 个默认构造的 `Level` 对象，应该写哪个？
- A. `vector<Level> v{100};`
- B. `vector<Level> v(100);`

<details><summary>参考答案</summary>
1. B。`{10, 5}` 是列表初始化，2 个元素：10 和 5。要 10 个 5 写 `v(10, 5)`（圆括号）。
2. B。`v(100)` 是 100 个默认构造对象；`v{100}` 是 1 个元素，值为 100（如果 Level 能从 100 构造），不是 100 个对象。
</details>

**3（踩坑·高价值）** `std::vector<std::string> v{3};` 的 `size()` 是多少？
- A. 1（一个元素，值是 `"3"`）
- B. 3（三个空串）
- C. 编译错误

**4（选择）** 下面哪一句**编译不过**？
- A. `std::vector<int> a{1, 2.5};`
- B. `std::vector<int> b(1, 2.5);`
- C. `std::vector<double> c{1, 2.5};`

**5（踩坑）** `std::vector<int> v();` 之后 `v.size()` 会怎样？
- A. 返回 0
- B. 编译错误：`v` 是函数声明，不能 `.size()`
- C. 未定义行为

**6（应用）** 你要为 8 个合约各建一个深度为 20 的买卖盘（`Level` 是聚合结构体），正确的初始化写法是？

<details><summary>参考答案</summary>

3. **B**。`std::string` 不能从 `int 3` 构造，`initializer_list<string>` 匹配失败 → **回退**成 `v(3)` 的默认构造语义 = 3 个空串。实测 `size()==3, v[0]==""`。同理 `vector<Level>{100}`（聚合类型）也是 **100 个元素**，不是 1 个。

4. **A**。花括号禁止**窄化转换**：`2.5`（double）→ `int` 会丢信息，clang 报
   `error: type 'double' cannot be narrowed to 'value_type' (aka 'int') in initializer list [-Wc++11-narrowing]`。
   B 只是 `-Wliteral-conversion` **warning**，编译通过且 `b[0]==2`（静默截断）；C 是 `double→double`，不窄化，合法。

5. **B**。这是 **most vexing parse**：`vector<int> v();` 被解析成"声明了一个无参、返回 `vector<int>` 的函数 `v`"。后面写 `v.size()` 会报
   `member reference base type 'std::vector<int> ()' is not a structure or union`。
   要空容器写 `vector<int> v;` 或 `vector<int> v{};`。

6. 用圆括号：
   ```cpp
   struct Level { double bid{0}, ask{0}; };
   std::vector<std::vector<Level>> book(8, std::vector<Level>(20));
   assert(book.size() == 8 && book[0].size() == 20);
   ```
   别用 `book{8, std::vector<Level>(20)}`——本例恰好回退成同样结果，但一旦有人给 `Level` 加个 `Level(int)` 构造函数，语义就悄悄变了。

</details>
