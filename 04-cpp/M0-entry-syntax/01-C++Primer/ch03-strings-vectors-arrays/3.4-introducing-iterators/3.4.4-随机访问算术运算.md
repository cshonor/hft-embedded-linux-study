# 3.4.4 随机访问算术运算

## 本节讲什么

`string` / `vector` 等**连续内存**容器支持的迭代器加减与距离——**随机访问迭代器**专属能力。

## 哪些容器支持

| 支持 `it + n`、`it1 - it2`、`<` 比较 | 不支持（双向或前向迭代器） |
|--------------------------------------|---------------------------|
| `string`、`vector`、`array`、`deque` | `list`、`map`、`set`、`forward_list` 等 |

## 算术运算

| 运算 | 含义 |
|------|------|
| `it + n` / `n + it` | 向前跳 `n` 个元素 |
| `it - n` | 向后跳 `n` 个元素 |
| `it += n` / `it -= n` | 复合赋值 |
| `it1 - it2` | 两迭代器间**元素个数**，类型 `difference_type`（有符号整数） |
| `it1 < it2` / `>` / `<=` / `>=` | 位置前后比较（仅随机访问） |

```cpp
std::vector<int> v{1, 2, 3, 4, 5};

auto mid = v.begin() + v.size() / 2;   // 指向中间元素
std::cout << *mid << std::endl;        // 3

auto dis = v.end() - v.begin();        // 5，元素总数
```

### HFT 示意

对 tick 缓冲做**二分**、取**中间档位**时，随机访问迭代器 + 算术比手写下标更通用（算法库第 10 章大量依赖此类迭代器）。

## 为什么迭代器要分等级（动机）

C 的指针**天然**支持 `p + n`、`p1 - p2`、`p < q`——因为 C 数组总是连续的。但 C++ 容器里有链表、树、哈希表，它们的迭代器**没法**在 O(1) 内跳 n 步。

如果标准规定"所有迭代器都必须支持 `+n`"，那么 `list` 只能把 `it + n` 实现成**循环 n 次 `++`**（O(n)），调用方会误以为它是 O(1) 而写出 O(n²) 的算法。

所以 C++ 把迭代器分成 **5 个类别**，每类只承诺自己能高效做到的操作：

| 类别 | 承诺的操作 | 典型容器 |
|------|-----------|----------|
| 输入 / 输出 | `*it`、`++it`（单次扫描） | `istream_iterator` |
| 前向 | 可重复扫描、多次 `++` | `forward_list` |
| 双向 | 额外支持 `--it` | `list`、`map`、`set` |
| **随机访问** | 额外支持 `it+n`、`it1-it2`、`<` | `vector`、`string`、`array`、`deque` |

**分类的意义是"让复杂度可见"**：`<algorithm>` 里的算法用 `iterator_traits<It>::iterator_category` 做标签分发，对随机访问迭代器走 O(1) 路径，对双向走 O(n) 路径。**同一个 `std::distance`，在不同容器上复杂度不同**——这不是缺陷，是设计。

## 底层实现与实测

> 环境：Apple clang 23.1.0，libc++，`-std=c++17 -O2`。可跑版本见文末例子。

### 1. 各容器迭代器类别实测（`iterator_category`）

| 容器 | 类别 | 支持 `it + n`？ |
|------|------|-----------------|
| `vector<int>` | **随机访问** | ✅ |
| `std::string` | **随机访问** | ✅ |
| `std::array<int,5>` | **随机访问** | ✅ |
| `std::deque<int>` | **随机访问** | ✅ |
| `std::list<int>` | 双向 | ❌（只能 `++`/`--`） |
| `std::map<int,int>` | 双向 | ❌ |
| `std::set<int>` | 双向 | ❌ |
| `std::forward_list<int>` | 前向 | ❌（连 `--` 都不行） |

**注意 `deque` 也是随机访问**——它不是严格连续（分段连续），但 `it + n` 仍能 O(1) 做到（因为是定长分段，跳跃是算术可算的）。

### 2. `difference_type` 就是 `ptrdiff_t`（有符号）

| 检查 | 结果 |
|------|------|
| `vector<int>::difference_type` 是 `ptrdiff_t` | **1（是）** |
| 有符号 | **1（是）** |
| `sizeof` | **8 字节** |

### 3. 负数转 `size_t` 的实测后果

```cpp
std::vector<int> v{1,2,3,4,5};
auto d2 = v.begin() - v.end();            // 实测 -5
std::size_t bad = static_cast<std::size_t>(d2);
std::cout << bad;                          // 实测 18446744073709551611
std::cout << (bad < 100);                  // 实测 0（false！）
```

**`18446744073709551611` = 2⁶⁴ - 5**。而且不止值错，**后续所有比较都错**（`bad < 100` 是 false）。这就是"别把 `it1 - it2` 赋给 `size_t`"的实证——一旦方向反了，你拿到的是一个天文数字，任何范围判断都会失效。

**规则**：用 `difference_type`（或 `ptrdiff_t`、`auto`）接收距离；只有在**确定 `it1 >= it2`** 时才转无符号。

### 4. `std::distance` 的复杂度随类别变化：63000 倍

| | 100 万元素的 `distance(begin, end)` | 复杂度 |
|------|--------------------------------------|--------|
| `list` | **2.583 ms** | O(n)（逐个 `++`） |
| `vector` | **0.000041 ms** | **O(1)（一次减法）** |
| 比值 | **约 63000 倍** | |

`std::distance` 内部就是标签分发：

```cpp
// 简化版
if constexpr (is_random_access<It>)  return last - first;      // O(1)
else { n = 0; while (first != last) { ++first; ++n; } return n; }  // O(n)
```

**这也是为什么算法库要求你提供正确的 `iterator_category`**——它决定了算法的实际复杂度。同理 `std::advance(it, n)` 对 `list` 是 n 次 `++`，对 `vector` 是一次加法。

### 5. 二分查找：手写迭代器算术 vs `std::lower_bound`

| | 20 万次查找（100 万有序 `int`） |
|------|-------------------------------|
| 手写二分（`beg + (end-beg)/2`） | 10.10 ~ 14.25 ms |
| `std::lower_bound` | **6.33 ~ 8.05 ms** |
| 比值 | `lower_bound` **快 1.6 ~ 1.8 倍** |

**别手搓二分**。`std::lower_bound` 更快的原因是它用了**分支更少、更可预测的写法**，20 万次查找差 4~6 ms（多次运行稳定快 1.6~1.8 倍）。而且手写二分有个经典 bug 家族——`(beg + end) / 2` 根本编译不过（两个迭代器不能相加），溢出、边界处理错误更是高发区。

### 6. 两个迭代器**不能相加**

```cpp
auto mid = (v.begin() + v.end()) / 2;   // ❌ 编译错误：没有 operator+(iterator, iterator)
auto mid = v.begin() + (v.end() - v.begin()) / 2;   // ✅ 差值 ÷ 2 再加
```

这是 C 指针和迭代器的一个细微差别：C 里 `p + q` 同样非法（指针加指针无意义），但很多人第一次写二分时会下意识地敲出来。

## HFT / 嵌入式视角

1. **热路径只用随机访问容器**。`vector` / `array` / 静态数组的迭代器算术是 O(1)，且和指针算术生成相同指令。订单簿、行情快照这类需要"跳到第 k 档"的场景，`list` 的迭代器算术缺失会逼你写 O(n) 的循环。
2. **`std::distance` 在 `list` 上是 O(n)**。实测 63000 倍。如果你在循环里反复调 `distance`，算法复杂度会悄悄从 O(n) 变成 O(n²)。**在循环外算一次，或者直接用 `vector`**。
3. **距离一律用有符号类型接收**。实测反方向相减得到 `18446744073709551611`，且后续比较全错。行情系统里"两个快照之间差了多少 tick"这类计算，用 `ptrdiff_t` 或 `auto`，别用 `size_t`。
4. **用 `std::lower_bound` 而不是手写二分**。实测快 1.77 倍，还省掉一整类边界 bug。它接受随机访问迭代器，返回的位置减 `begin()` 就是下标。
5. **迭代器算术越界同样是 UB**。`v.begin() - 1`、`v.end() + 1`、`v.begin() + 100`（超出 size）都是 UB，不会抛异常。debug 构建开 libc++ hardening 能抓到一部分。
6. **嵌入式上 `deque` 的分段连续性要注意**：虽然它是随机访问迭代器，但跨段访问会有额外一次间接跳转，缓存表现不如 `vector`。

## 和 C 的区别（随机访问算术：迭代器 vs 指针算术）

C 程序员对指针算术驾轻就熟——`p + n`、`p1 - p2`、`p < q` 这些在 `int*` 上天天用。C++ 的随机访问迭代器**语法完全一致**，但只对**连续内存容器**生效：

| 操作 | C（指针算术） | C++（随机访问迭代器） |
|------|---------------|----------------------|
| 跳 n 步 | `p + n` | `it + n` |
| 两指针距离 | `p1 - p2`（ptrdiff_t） | `it1 - it2`（difference_type） |
| 大小比较 | `p < q` | `it1 < it2` |
| 适用对象 | 任意连续内存（数组） | `vector`/`string`/`array`/`deque` 的迭代器 |
| 不支持的对象 | — | `list`/`map`/`set` 等（双向/前向迭代器） |

**给 C 程序员的关键提醒：**
1. **C 的指针"天然是随机访问"**——因为 C 数组总是连续内存。C++ 迭代器分**5 个类别**（输入/输出/前向/双向/随机访问），只有 `vector`/`string`/`array`/`deque` 是随机访问，`list`/`map` 不是。
2. **`it1 - it2` 的类型是 `difference_type`**（有符号），不是 `size_t`。C 里是 `ptrdiff_t`，含义一致。**别赋给 `size_t`**——若 `it1 < it2` 结果是负数，转无符号会变成大正数。
3. **随机访问迭代器能 `it + n` 跳跃**，但跳到容器外（如 `v.begin() - 1` 或 `v.end() + 1`）仍是 UB。C 里 `arr - 1`、`arr + n + 1` 同样 UB。

## 常见错误

### 1. 对 `list`/`map` 迭代器用算术

```cpp
std::list<int> l = {1,2,3};
auto it = l.begin() + 1;   // ❌ 编译错误：list 迭代器不支持 +
auto mid = l.begin() + l.size() / 2;   // ❌ 同上
```

`list` 是双向迭代器，只能 `++`/`--` 一步步走。要"走到中间"只能循环 `++`。**需要随机访问就用 `vector`/`array`**。

### 2. `it1 - it2` 赋给 `size_t`

```cpp
auto dist = v.end() - v.begin();   // 类型是 difference_type（有符号）
size_t n = dist;                   // 一般 OK
size_t m = v.begin() - v.end();    // ❌ 负数转无符号 → 巨大正数
```

`difference_type` 是有符号的。若 `it1 < it2`，`it1 - it2` 是负数，赋给 `size_t`（无符号）会变成一个大正数。**确保 `it1 >= it2` 再减**，或保持用 `difference_type` 接收。

### 3. `v.begin() + v.size()` 当成"最后一个元素"

```cpp
auto last = v.begin() + v.size();   // 这是 v.end()，尾后！
std::cout << *last;                 // ❌ UB，尾后不可解引用
```

`v.begin() + v.size()` 等于 `v.end()`，是**尾后位置**，不可解引用。最后一个元素是 `v.begin() + v.size() - 1` 或 `v.end() - 1`。C 程序员写 `arr + n` 也容易犯这个，但 C 里 `arr[n]` 越界通常不会崩在解引用上（栈上相邻内存），C++ 这里同样 UB。

## 自测题

**1. 选择题**　下列哪个容器的迭代器**支持** `it + n` 算术运算？

- A. `std::list<int>`
- B. `std::map<int, int>`
- C. `std::array<int, 5>`
- D. `std::set<int>`

<details><summary>答案</summary>

**C**。`std::array` 是连续内存，随机访问迭代器，支持 `+n`。`list`/`map`/`set` 都是节点容器，迭代器只能 `++`/`--`（双向），不支持算术。

</details>

**2. 判断题**　`v.end() - v.begin()` 的结果类型是 `size_t`（无符号整数）。

<details><summary>答案</summary>

**错**。是 `difference_type`（有符号整数，通常是 `ptrdiff_t`）。虽然 `v.end() >= v.begin()` 时值非负，但类型本身是有符号的。若反向相减（`v.begin() - v.end()`）会得到负数。

</details>

**3. 踩坑题**　下面这段代码想取 `vector` 中间元素，哪里有问题？

```cpp
std::vector<int> v = {1, 2, 3, 4, 5};
auto mid = v.begin() + v.size() / 2;
std::cout << *mid << std::endl;
v.push_back(6);
std::cout << *mid << std::endl;   // 还想用 mid
```

<details><summary>答案</summary>

**第二次 `*mid` 是 UB**。`push_back(6)` 可能触发扩容，`mid` 失效。即使没扩容，`mid` 仍指向"原中间"，但语义上 `v.size()` 已变，"中间"也变了。

**修复**：扩容后重取，或改用下标：

```cpp
v.push_back(6);
auto mid2 = v.begin() + v.size() / 2;   // 重取
std::cout << *mid2 << std::endl;
```

或用下标（扩容不影响下标语义）：`std::cout << v[v.size() / 2] << std::endl;`

</details>

**4. 应用题**　用迭代器算术写一个二分查找，在**已排序**的 `vector<int>` 中找目标值，返回下标或 -1。

<details><summary>答案</summary>

```cpp
int binary_search(const std::vector<int>& v, int target) {
    auto beg = v.begin(), end = v.end();
    while (beg < end) {
        auto mid = beg + (end - beg) / 2;   // 随机访问算术
        if (*mid == target)
            return static_cast<int>(mid - v.begin());   // 距离即下标
        else if (*mid < target)
            beg = mid + 1;
        else
            end = mid;
    }
    return -1;
}
```

要点：
- `beg + (end - beg) / 2` 避免 `(beg + end) / 2`（两个迭代器不能相加）
- `mid - v.begin()` 得到下标（difference_type 转 int）
- `beg < end` 用 `<`（随机访问迭代器支持）

C 等价写法是 `int *lo = arr, *hi = arr + n; while (lo < hi) { int *mid = lo + (hi - lo) / 2; ... }`，几乎一一对应。

</details>

**5（选择）** `std::distance(l.begin(), l.end())` 对 100 万元素的 `list` 和 `vector`，实测差多少？
- A. 差不多，都是 O(1)
- B. `list` 约 63000 倍慢（O(n) vs O(1)）
- C. `vector` 更慢

**6（踩坑）** 有人写 `std::size_t n = v.begin() - v.end();`，实测会得到什么？为什么危险？

**7（应用）** 二分查找用手写迭代器算术还是 `std::lower_bound`？实测数据支持你的选择吗？

<details><summary>参考答案</summary>

5. **B**。实测：
   - `distance(list 100万)` = 2.583 ms（逐个 `++`，**O(n)**）
   - `distance(vector 100万)` = 0.000041 ms（一次减法，**O(1)**）
   - 比值约 **63000 倍**
   
   原因：`distance` 用 `iterator_category` 做标签分发——随机访问走 `last - first`，其他走循环 `++`。
   同理 `std::advance(it, n)` 对 `list` 是 n 次 `++`。**在循环里反复调 `distance` 会把 O(n) 变 O(n²)。**

6. **实测得到 `18446744073709551611`（= 2⁶⁴ - 5）**，而且 `bad < 100` 的结果是 **false**。
   `v.begin() - v.end()` 是 **-5**（`difference_type` 有符号），转 `size_t` 后绕回成天文数字。
   危险之处不只是值错，**后续所有范围判断都会失效**。
   规则：用 `difference_type` / `ptrdiff_t` / `auto` 接收；只在确定 `it1 >= it2` 时才转无符号。

7. **用 `std::lower_bound`**。实测 20 万次查找（100 万有序 `int`）：
   手写二分 10.10~14.25 ms vs `lower_bound` **6.33~8.05 ms**，**快 1.6~1.8 倍**。
   除了更快，还避开了一整类手写 bug——比如 `(beg + end) / 2` 根本编译不过
   （两个迭代器不能相加，必须写 `beg + (end - beg) / 2`）。
   用法：`auto it = std::lower_bound(v.begin(), v.end(), key);  auto idx = it - v.begin();`

</details>
