# 3.4.2 begin、end 与常量迭代器

## 本节讲什么

`begin` / `end` / `cbegin` / `cend` 的语义、返回类型与读写权限。

## begin() — 指向第一个元素

- 返回类型：`容器::iterator`（如 `std::vector<int>::iterator`）
- 指向**第一个有效元素**
- 可读写：`*it = value;`

```cpp
std::vector<int> v{1, 2, 3};
auto it = v.begin();
*it = 10;   // v 变为 {10, 2, 3}
```

## end() — 尾后迭代器（终止标记）

- 返回**尾后（past-the-end）迭代器**
- **不指向任何有效元素**，仅表示「遍历到这里结束」
- **禁止解引用**：`*v.end()` → **未定义行为**（可能崩溃）
- **空容器**：`begin() == end()`，遍历循环体**一次都不执行**

```cpp
std::vector<int> empty;
if (empty.begin() == empty.end())  // true，等价 empty.empty()
    /* 无元素 */;
```

## cbegin() / cend()（C++11 常量迭代器）

- 返回 `容器::const_iterator`，**只读**
- 即使容器本身**不是** `const`，也不能通过 `cit` 修改元素：`*cit = 10;` **编译报错**
- **只遍历、不修改**时优先用，防止误改数据

| 调用 | 返回类型 | 能否改元素 |
|------|----------|------------|
| `v.begin()` | `vector::iterator` | ✅ 可读写 |
| `v.cbegin()` | `vector::const_iterator` | ❌ 只读 |
| `const vector<int> cv; cv.begin()` | `vector::const_iterator` | ❌ 只读 |

```cpp
std::vector<int> v{1, 2, 3};
for (auto cit = v.cbegin(); cit != v.cend(); ++cit) {
    std::cout << *cit;
    // *cit = 0;  // ❌ 编译错误
}
```

## 类型书写（`auto` 之前）

```cpp
std::vector<int>::iterator it = v.begin();
std::vector<int>::const_iterator cit = v.cbegin();
std::string::iterator sit = s.begin();
```

现代 C++ 直接 **`auto`** 推导即可。

## 为什么要有 `const_iterator`（动机）

`begin()` 已经能用，为什么还要多一个 `cbegin()`？答案是 **const 正确性（const-correctness）**——把"这个函数只读、不修改"从**注释和约定**变成**编译期强制的契约**。

```cpp
void print(const std::vector<int>& v) {
    for (auto it = v.begin(); ...) ...   // 编译器已经保证 *it 不可改
}
void scan(std::vector<int>& v) {
    for (auto it = v.cbegin(); ...) ...  // 我主动声明：这里只读
}
```

第二行的价值在于：**将来有人在这段循环里加一行 `*it = 0;`，编译器立即报错**，而不是等上线后才发现订单被清零。在高频交易系统里，这类"只读路径误写"是最难查的 bug 之一——它不崩，只是数据悄悄变了。

`const_iterator` 的本质是**把权限编码进类型**，让类型系统帮你在编译期抓 bug。

## 底层实现与实测

> 环境：Apple clang 23.1.0，libc++，`-std=c++17 -O2`。可跑版本见文末例子。

### 1. 三种调用返回什么（`type_traits` 实测）

| 调用 | 是 `const_iterator` 吗 |
|------|------------------------|
| `v.begin()`（非 const 容器） | **0（否）** → `iterator` |
| `v.cbegin()` | **1（是）** |
| `cv.begin()`（`const vector`） | **1（是）** ← 重载按容器 const 性选 |

**关键点**：`begin()` 有两个重载，`const` 容器调用时自动选返回 `const_iterator` 的那个。所以**参数写成 `const vector<T>&` 就自动获得了只读保证**，不需要手动写 `cbegin()`。`cbegin()` 的用武之地是**容器本身非 const、但你只想读**。

### 2. `iterator` 和 `const_iterator` 是**两个不同的类型**

| 检查 | 结果 |
|------|------|
| `is_same<iterator, const_iterator>` | **0（不同类型）** |
| `iterator → const_iterator` 可隐式转换 | **1（可以）** |
| `const_iterator → iterator` 可转换 | **0（不行）** |

**单向转换**：加 const 是安全的、自动的；去 const 需要 `const_cast`，标准容器不提供。这就是为什么把 `iterator` 传给接受 `const_iterator` 的函数没问题，反过来不行。

### 3. `*it` 的类型决定能不能改

| 表达式 | `decltype` 实测 |
|--------|-----------------|
| `*v.begin()` | **`int&`** → 可写：`*it = 10;` |
| `*v.cbegin()` | **`const int&`** → `*it = 10;` **编译错误** |

注意 `decltype(*it)` 是**引用类型**而不是 `int` 值——这也意味着 `auto x = *it;` 会**拷贝一份**（`x` 是 `int`），要避免拷贝得写 `auto& x = *it;`（遍历只读时用 `const auto&`）。

### 4. 空容器：`begin() == end()`

实测 `e.begin() == e.end()` → **1**，`e.end() - e.begin()` → **0**。

所以遍历循环天然正确（一次都不进），**不需要**先判空。`if (v.begin() == v.end())` 等价于 `v.empty()`，但后者更清楚。

### 5. 非成员版本：`std::begin` / `std::end`（C++11）、`std::cbegin`（C++14）

```cpp
std::begin(v);   // == v.begin()
std::end(v);     // == v.end()
std::cbegin(v);  // == v.cbegin()，实测返回 const_iterator
```

非成员版存在的理由：**对 C 数组也能用**。

```cpp
int arr[3] = {7, 8, 9};
std::begin(arr);                        // 实测 *std::begin(arr) == 7
std::end(arr) - std::begin(arr);        // 实测 3
```

C 数组**没有成员函数**，所以 `arr.begin()` 不存在，但 `std::begin(arr)` 可以——这让泛型代码能同时吃容器和裸数组。**写模板时优先用非成员版**（ADL 会找到成员版）。

### 6. `std::as_const`（C++17）：把一个非 const 变量临时变 const

```cpp
std::vector<int> v{1,2,3};
std::as_const(v).begin();   // 实测返回 const_iterator
```

`as_const` 返回 `const T&`，用途是**在调用处表达"这里只读"**，尤其配合 `auto` 时：`for (auto& x : std::as_const(v))` 会让 `x` 成为 `const int&`。比 `cbegin()` 更通用（对任何对象都行，不限于容器）。

### 7. `string` 也有一套完整迭代器

实测 `*s.begin() == 'a'`，`s.end() - s.begin() == 3`，`sizeof(string::iterator) == 8`。

`std::string` 在标准里不算"容器"，但提供了完整的 `begin/end/cbegin/iterator/const_iterator`，所有 `<algorithm>` 都能直接用。

## HFT / 嵌入式视角

1. **只读路径一律用 `const` 参数 + `cbegin()`**。双重保险：函数签名写 `const vector<Tick>&`，循环里再写 `cbegin()`。这样"只读"是编译期保证，不是靠人记住。
2. **`iterator → const_iterator` 是单向的**，这个方向性本身就是保护。如果你发现自己需要 `const_iterator → iterator`，那说明设计有问题（十有八九该用 `const_cast` 之外的方式，或者那个数据本来就不该是 const）。
3. **遍历只读元素写 `const auto&`，别写 `auto`**。`for (auto x : v)` 中 `x` 是**拷贝**——对 `int` 无所谓，对 `Tick`（32 字节）或 `std::string` 就是每轮一次拷贝/分配。热点循环里这个开销很实在（见 [3.3.1](../3.3-library-type-vector/3.3.1-动态数组基础.md) 的 `reserve` 实测）。
4. **模板代码用非成员 `std::begin/std::end`**。这样同一份代码能同时处理 `vector`、`array` 和 C 数组，在需要兼容"老代码传进来的裸数组"时尤其有用。
5. **`as_const` 比 `cbegin` 更适合表达"这个函数里我不改 v"**。它作用于变量本身，读者一眼看出意图，且不限于容器。

## 和 C 的区别（begin/end 对应数组首尾指针）

`begin()`/`end()` 对应 C 里"数组首指针"和"尾后指针"的概念：

| 对比点 | C（指针） | C++（迭代器） |
|--------|----------|---------------|
| 起始 | `arr`（首元素地址） | `v.begin()` |
| 尾后 | `arr + n`（不指向有效元素） | `v.end()`（一样，不指向有效元素） |
| 遍历 | `for (p=arr; p!=arr+n; ++p)` | `for (it=v.begin(); it!=v.end(); ++it)` |
| 只读 | `const int* p` | `v.cbegin()` / `const_iterator` |

**给 C 程序员的关键提醒：**
1. `end()` 就是 C 里的 `arr + n`——尾后位置，**不指向有效元素**，不能解引用。这个概念你已经懂。
2. `cbegin()`/`cend()` 返回只读迭代器，对应 C 的 `const int*`——只遍历不改时用，防止误修改。
3. C++11 范围 for `for (auto& x : v)` 底层就是 `begin()`/`end()`，不用手写。

## 自测题

**1（选择）** 下面哪个会 UB？
- A. `auto it = v.begin(); std::cout << *it;`（v 非空）
- B. `auto it = v.end(); std::cout << *it;`

**2（判断）** `v.cbegin()` 返回的迭代器能修改元素。

**3（应用）** 用 C 指针和 C++ 迭代器分别写遍历数组的循环，对比相似性。

<details><summary>参考答案</summary>
1. B。`end()` 是尾后迭代器，不指向有效元素，解引用是 UB。`begin()` 指向第一个元素（若非空），可以解引用。
2. 错。`cbegin()` 返回 `const_iterator`，只读，`*cit = x` 会编译报错。要修改用 `begin()`（返回普通 `iterator`）。
3. 
```c
/* C */
int arr[] = {1,2,3};
for (int *p = arr; p != arr + 3; ++p) printf("%d ", *p);
```
```cpp
// C++
std::vector<int> v{1,2,3};
for (auto it = v.begin(); it != v.end(); ++it) std::cout << *it << " ";
```
写法几乎一模一样——迭代器就是泛型化的指针。
</details>

**4（选择）** 关于 `iterator` 和 `const_iterator`，实测正确的是？
- A. 它们是同一个类型，只是调用方式不同
- B. 是不同类型，`iterator` 能隐式转成 `const_iterator`，反过来不行
- C. 是不同类型，两个方向都能隐式转换

**5（踩坑）** 下面这段"只看不改"的遍历有什么隐藏开销？
```cpp
std::vector<Tick> ticks;   // Tick 是 32 字节的 POD
for (auto x : ticks) { if (x.qty > 0) sum += x.price; }
```

**6（应用）** 你写了一个模板函数要同时处理 `vector<int>` 和 C 数组 `int arr[10]`，`begin()` 该怎么写？

<details><summary>参考答案</summary>

4. **B**。实测：
   - `is_same<iterator, const_iterator>` = **0**（不同类型）
   - `iterator → const_iterator` 可隐式转换 = **1**
   - `const_iterator → iterator` 可转换 = **0**
   
   单向性本身就是保护：加 const 安全且自动，去 const 标准容器不提供。

5. **`auto x` 是拷贝**，不是引用。`decltype(*it)` 是 `int&`（引用），但 `auto x = *it` 会**值拷贝**——
   每个 32 字节的 `Tick` 每轮拷一次。改成：
   ```cpp
   for (const auto& x : ticks) { ... }   // 零拷贝，且表达只读
   ```
   对 `int`（4 字节）无所谓，对 `Tick`/`std::string` 就是实打实的开销（`string` 还会触发堆分配）。

6. **用非成员 `std::begin` / `std::end`**：
   ```cpp
   template <class C>
   void process(C& c) {
       for (auto it = std::begin(c); it != std::end(c); ++it) ...
   }
   ```
   实测 `std::begin(arr)` 对 C 数组 `int arr[3]` 也能用（`*std::begin(arr) == 7`），
   而 `arr.begin()` **不存在**（C 数组没有成员函数）。
   对有成员 `begin()` 的容器，ADL 会找到成员版，所以非成员写法是**严格更通用**的。
   （`std::cbegin/cend` 是 C++14 才有的非成员版。）

</details>
