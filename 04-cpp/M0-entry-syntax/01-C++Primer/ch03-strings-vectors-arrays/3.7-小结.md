# 3.7 小结

## 本节讲什么

本章是 **C++ 标准库学习的起点**。回顾 `string`、`vector`、迭代器与内置数组的关系，并强调：开发者应**优先选用**标准库提供的 `string` 和 `vector`，只在必要时才考虑底层的数组或指针。

## 要点

- **`using` 声明**：简化 `std::` 前缀，头文件中慎用
- **`string`**：可变长字符串，配合 `cctype` 处理字符
- **`vector`**：标准库**动态数组 / 容器**（向量），同类型元素、`push_back` 增容；下标只访问已有元素，**不能越界添加**（HFT 热路径 OOB 写可能静默错价或崩溃）
- **迭代器**：全容器通用遍历；`begin`/`end`（尾后勿解引用）、`cbegin`/`cend`（只读）；`it != end()`；`vector` 扩容后迭代器失效（见 [3.4](./3.4-introducing-iterators/3.4-迭代器介绍.md)）
- **内置数组**：编译期固定、不能拷贝；数组名退化指针；优先 `vector`/`string`（见 [3.5](./3.5-arrays/3.5-数组.md)）
- **多维数组**：本质是数组的数组；可用范围 for 与类型别名简化

## 示例

```cpp
#include <iostream>
#include <string>
#include <vector>

int main() {
    std::vector<std::string> words{"C++", "Primer", "Chapter3"};

    for (const auto &w : words)
        std::cout << w << " ";
    std::cout << std::endl;

    // 标准库类型组合：比裸数组 + 指针更安全、更易用
    return 0;
}
```

## 和 C 的区别（本章总结：C++ 标准库 vs C 手工管理）

整章的核心是：**C++ 用标准库容器替代了 C 的手工内存管理**。C 程序员的肌肉记忆是"数组 + 指针 + 手动 malloc/free"，C++ 的范式是"vector/string + 迭代器 + RAII"：

| 场景 | C 习惯 | C++ 现代写法 | 好处 |
|------|--------|---------------|------|
| 字符串 | `char[N]` / `char*` + `strcat`/`strcpy` | `std::string` | 自动扩容、运算符重载、RAII |
| 动态数组 | `malloc`/`realloc`/`free` | `std::vector` | 自动管理、自带 size、扩容安全 |
| 固定数组 | `int arr[N]` | `std::array<int, N>` | 自带 size、可拷贝、接口友好 |
| 遍历 | `for (p=arr; p<arr+n; ++p)` | `for (auto x : v)` 或迭代器 | 不手写边界、防越界 |
| 字符处理 | `<ctype.h>` 的 `isalpha` 等 | `<cctype>` 同样函数 | 一致，C++ 命名规范 |
| 命名组织 | 前缀 `mylib_xxx` / `static` | `namespace mylib { ... }` | 防冲突、可嵌套、可别名 |
| 算法 | 手写循环 | `std::sort`/`std::find`/`std::transform` | 通用、高效、正确 |

**给 C 程序员的"心法转变"：**
1. **从"手动管理"到"RAII 自动"**——`vector`/`string` 析构自动释放，不用 `free`。忘 `free` 是 C 最常见的泄漏源，C++ 用容器就没了。
2. **从"下标 + 长度"到"迭代器 + 范围 for"**——迭代器适配所有容器（`list`/`map` 也能用），下标只能连续内存。范围 for 不手写边界，防越界。
3. **从"`#define`/手写循环"到"`constexpr` + 算法库"**——`constexpr` 有类型有作用域，`std::sort` 比手写快排更可靠。
4. **HFT 热路径仍可回退到 C 风格**——`char[N]`/`std::array` 栈上零分配，但要严格管边界。

## 全章术语表（带 C 对照）

| C++ 术语 | 含义 | C 对应/区别 |
|----------|------|-------------|
| `namespace` | 命名空间，防名字冲突 | C 无，靠前缀和 `static` |
| `using` 声明 | 引入命名空间中的名字 | C 无 |
| `std::string` | 可变长字符串类 | C 的 `char[]` + `string.h` 函数 |
| `std::vector<T>` | 动态数组容器 | C 的 `malloc`/`realloc` 手工管理 |
| `push_back` | 末尾追加元素 | C 里手动 `arr[n++] = x;` |
| `emplace_back` | 末尾原地构造 | C 无（无构造函数概念） |
| `reserve` | 预留容量 | C 里 `malloc(N * sizeof(T))` 一次到位 |
| `size()` | 当前元素个数 | C 里自己记 `size_t n` |
| `at(i)` | 带边界检查的下标 | C 无（越界 UB） |
| 迭代器 | 泛型指针，遍历所有容器 | C 的指针（只连续内存） |
| `begin()`/`end()` | 首/尾后迭代器 | C 的 `arr`/`arr + n` |
| `cbegin()`/`cend()` | 只读迭代器 | C 的 `const T*` |
| `std::array<T, N>` | 固定大小容器 | C 的 `T arr[N]`（但自带 size、可拷贝） |
| 范围 for | `for (x : container)` | C 无 |
| 数组退化 | 数组名转指针 | C/C++ 共享规则 |
| RAII | 资源获取即初始化 | C 无（手动 free） |

## 给 C 程序员的 10 个要点

1. **优先 `string`/`vector`/`array`**，业务代码别用裸数组/裸指针
2. **`vector` 扩容会让旧迭代器/指针/引用失效**——HFT 热路径用 `reserve` 保证不扩容
3. **`push_back` 是正确增容方式**，下标只能访问已有元素，不能"添加"
4. **`v(n)` 是 n 个元素，`v{a,b}` 是列表**——`vector<int> v{10, 5}` 是 2 个元素不是 10 个 5
5. **遍历用 `it != end()`，不用 `<`**；自增用 `++it`，不用 `it++`
6. **`string::find` 返回 `npos` 不是 `-1`**，必须 `!= npos` 判断
7. **`c_str()` 返回的指针在 string 改动后失效**，要长期持有先拷贝
8. **数组传参退化为指针丢长度**——用 `std::array`/`vector` 或模板引用避开
9. **`const` 全局在 C++ 是内部链接**（C 是外部），头文件里直接定义 `const int x = 5;` 安全
10. **HFT 热路径仍可用 `char[N]`/`std::array`** 栈上零分配，但要严管边界和 `\0`

## 自测题（全章回顾）

**1. 选择题**　下列关于 `std::vector` 和 C 数组的对比，**错误**的是：

- A. `vector` 能动态扩容，C 数组编译期固定
- B. `vector` 有 `size()` 成员，C 数组传参后 `sizeof` 拿不到长度
- C. `vector` 越界 `[]` 访问会抛异常，C 数组越界是 UB
- D. `vector` 析构自动释放内存，C 的 `malloc` 数组要手动 `free`

<details><summary>答案</summary>

**C**。`vector::operator[]` **不检查边界**，越界和 C 数组一样是 UB。要抛异常用 `at(i)`。这是 C 程序员常误以为的"C++ 容器自动安全"——`[]` 仍零开销，`at` 才检查。

</details>

**2. 判断题**　`std::vector<int> v(10);` 和 `int v[10];`（局部）都把元素初始化为 0。

<details><summary>答案</summary>

**错**。`vector<int> v(10);` 会**值初始化**为 0（10 个 0）；`int v[10];`（局部、非静态）是**未初始化的垃圾值**。这是 C 和 C++ 的差异——C++ 容器构造会值初始化，C 数组不会。要 C 数组也初始化得 `int v[10] = {0};`。

</details>

**3. 踩坑题**　下面这段代码混用了 C 风格和 C++ 风格，有什么问题？

```cpp
std::vector<char> buf;
buf.resize(256);
char* p = buf.data();
read_from_socket(p, 256);       // C 接口填充
buf.push_back('\0');            // 加结尾符
printf("%s", p);                // 打印
```

<details><summary>答案</summary>

**`p` 可能失效**。`push_back('\0')` 若触发扩容，`buf` 搬家，`p` 指向已释放的旧内存，`printf(p)` 是 use-after-free。

**修复**（三种）：

```cpp
// 方法 1：reserve 保证不扩容
buf.reserve(257);
buf.resize(256);
read_from_socket(buf.data(), 256);
buf.push_back('\0');
printf("%s", buf.data());   // 重取

// 方法 2：push_back 后重取
buf.push_back('\0');
printf("%s", buf.data());

// 方法 3：直接用 string
std::string s;
s.resize(256);
read_from_socket(&s[0], 256);
s.push_back('\0');
printf("%s", s.c_str());
```

C 程序员的肌肉记忆是"数组地址不变"，到 `vector`/`string` 要改——**任何可能扩容的操作后，旧指针/迭代器都视为失效**。

</details>

**4. 应用题**　用本章所学，写一个 HFT 日志缓冲类：固定容量 1024 条日志，每条是 `string`，循环覆写（环形），支持遍历打印最近 N 条。

<details><summary>答案</summary>

```cpp
#include <vector>
#include <string>
#include <iostream>

class LogBuffer {
    std::vector<std::string> buf_;
    size_t head_ = 0, count_ = 0;
public:
    LogBuffer() : buf_(1024) {}   // 预分配 1024 个空 string

    void push(std::string msg) {
        buf_[head_] = std::move(msg);   // 移动赋值，无深拷贝
        head_ = (head_ + 1) % 1024;
        if (count_ < 1024) ++count_;
    }

    // 打印最近 n 条（n <= count_）
    void print_recent(size_t n) const {
        if (n > count_) n = count_;
        // 最新的是 (head_ - 1)，往前 n 条
        for (size_t i = 0; i < n; ++i) {
            size_t idx = (head_ - 1 - i + 1024) % 1024;
            std::cout << buf_[idx] << "\n";
        }
    }

    size_t size() const { return count_; }
};
```

要点（本章综合）：
- `buf_(1024)` 预分配 1024 个空 `string`（[3.3.1](./3.3-library-type-vector/3.3.1-动态数组基础.md)）
- `std::move(msg)` 移动赋值，避免深拷贝（[3.3.5](./3.3-library-type-vector/3.3.5-拷贝移动与扩容.md)）
- 环形覆写用下标取模，不 `push_back`（避免扩容）（[3.3.3](./3.3-library-type-vector/3.3.3-下标与增删.md)）
- 析构自动释放所有 `string`（RAII）

C 程序员会写 `char* buf[1024];` + 手动 `strdup`/`free`，C++ 版用 `vector<string>` 全自动。

</details>
