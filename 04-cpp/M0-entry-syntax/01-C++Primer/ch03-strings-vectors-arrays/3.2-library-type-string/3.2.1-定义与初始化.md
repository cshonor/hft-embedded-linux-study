# 3.2.1 定义与初始化

> 第 3 章 · 上一节：[3.2 string](./3.2-标准库类型string.md) · 下一节：[3.2.2 读写操作](./3.2.2-读写操作.md)

## 本节讲什么

`std::string` 的多种构造方式：默认空串、字面值、拷贝、`string(n, c)` 重复字符、C++11 列表初始化。

## 核心用法

```cpp
#include <string>

std::string s1;                    // 空串 ""
std::string s2 = "hello";          // 字面值
std::string s3(s2);                // 拷贝
std::string s4(10, 'c');           // "cccccccccc"
std::string s5 = std::string(5, 'x');  // "xxxxx"
std::string s6{"IF2406"};          // C++11 列表初始化
```

| 写法 | 结果 |
|------|------|
| `string s;` | 默认构造，空串 |
| `string s = "abc";` | 从 C 风格字面量拷贝内容 |
| `string s(other);` | 深拷贝 `other` 的字符序列 |
| `string s(n, c);` | `n` 个字符 `c` |
| `string s{"abc"};` | C++11 列表初始化 |

## 和 C 的区别（string vs char 数组）

这是 C→C++ 的**核心升级**——C 用 `char[]` 手动管理，C++ 用 `string` 自动管理：

| 对比点 | C（`char[]`/`char*`） | C++（`std::string`） |
|--------|----------------------|----------------------|
| 长度 | `strlen(s)` 扫 `\0` | `s.size()` 直接拿 |
| 初始化 | `char s[] = "hello";` 固定大小 | `string s = "hello";` 自动管理 |
| 拷贝 | `strcpy(dst, src)` 怕越界 | `string s2 = s1;` 深拷贝，安全 |
| 重复字符 | `memset(buf, 'c', 10); buf[10]=0;` | `string s(10, 'c');` |
| 内存释放 | 手动 `free`/`delete[]` | 析构自动释放（RAII） |

**给 C 程序员的关键提醒：**
1. `string` 不需要你管 `\0`、不需要你算长度、不需要你手动释放——析构时自动回收内存。
2. `string s2 = s1;` 是**深拷贝**（独立内存），不是 C 里 `char* p = s` 的指针复制（浅拷贝）。
3. `string` 可变长，不用像 C 的 `char[64]` 那样提前估大小。

```c
/* C：char 数组，手动管理 */
char s1[16] = "hello";        /* 固定大小，长了截断 */
char s2[16];
strcpy(s2, s1);               /* 怕越界 */
size_t len = strlen(s2);      /* 扫 \0 */
/* 离开作用域自动回收（栈），但堆的要 free */
```
```cpp
// C++：string 自动管理
std::string s1 = "hello";     /* 可变长，不截断 */
std::string s2 = s1;          /* 深拷贝，安全 */
size_t len = s2.size();       /* 直接拿，不扫 \0 */
/* 离开作用域析构自动释放 */
```

## 同一行 `name[2] = 'a'`：string 合法、`char*` 崩（实测）

TheCherno Strings 一集里的关键切换——把 `char* name = "Cherno"` 换成 `std::string name = "Cherno"`，同一行 `name[2] = 'a';` 从**当场崩溃**变成**合法**。原因就是上表那句"从 C 风格字面量**拷贝**内容"：字面量本体仍在只读段没人碰，string 构造时把字符抄进了**自己的可写缓冲**。

实测（clang 23.1.0，macOS arm64，libc++，2026-10-16）：

```
字面量 "Cherno"      = 0x102197dac  (__TEXT 只读段)
&name（string 对象）  = 0x16dc66f78  (栈)
name.data()           = 0x16dc66f78  <- 短串 SSO：缓冲就在对象内部
long_s.data()         = 0x12d604920  <- 长串（100 字符）：堆上另分配
sizeof(std::string)   = 24
name.capacity()       = 22           (SSO 容量)
name 改后             = Charno
字面量本体            = Cherno       <- 不受影响
```

三个观察：

1. **`name.data() == &name`**——短串（≤ 22 字节，libc++ arm64）的缓冲直接嵌在 string 对象内部，**零堆分配**（SSO，短字符串优化）。改 `name[2]` 改的是栈上对象里的字节。
2. **长串才上堆**——100 个字符的 `long_s`，`data()` 落在堆区（0x12d6…），是 `operator new` 另分配的一块（→ [12.2 直接内存管理](../../ch12-dynamic-memory/12.2-直接内存管理.md)）。
3. **字面量本体没被碰**——改完 `name`，`lit` 仍输出 `Cherno`。

| 写法 | `name[2]='a'` | 原因 |
|------|:---:|------|
| `char* name = "Cherno"` | ❌ SIGBUS（exit 138） | 指针**指向**字面量本体，在 `__TEXT` 只读段（→ [2.1.1 §6](../../ch02-variables-and-basic-types/2.1.1-字符与字符串字面量-C++对C.md)） |
| `char name[] = "Cherno"` | ✅ | 数组是栈上**拷贝** |
| `std::string name = "Cherno"` | ✅ | 构造时**拷贝**进 string 自己的缓冲 |

记忆法：**指针是"指过去"，数组和 string 都是"拷过来"——只有拷过来的才能改。**

> HFT 视角：SSO 让 ≤ 22 字节的串**完全没有堆分配**——合约码、短字段白嫖这个优化；一旦超过容量就有一次 `operator new`，热路径上这就是要警惕的抖动来源（对应 [3.2.4](./3.2.4-string与C风格字符串.md) 的固定缓冲折中）。

## 常见错误

**1. 以为 `string s2 = s1` 是浅拷贝**
C 里 `char* p = s` 是指针复制（两个指针指向同一块）；C++ 的 `string s2 = s1` 是深拷贝（独立内存）。改 `s2` 不影响 `s1`。

**2. `string s = 'c';` 单字符赋值**
```cpp
std::string s = 'c';   // ❌ 不合法：单字符不是字符串
std::string s(1, 'c'); // ✅ 一个 'c'："c"
std::string s = "c";   // ✅ 字符串字面量
```

## 自测题

**1（选择）** `std::string s2 = s1;` 后修改 `s2`，`s1` 会变吗？
- A. 会变（浅拷贝）
- B. 不变（深拷贝）

**2（判断）** C++ 的 `string` 需要手动管理 `\0` 结束符。

**3（应用）** 用 C++ string 实现：创建一个 20 个 `'-'` 的字符串（分割线）。

**4（内存）** `std::string a = "xy";` 和 `std::string b(100, 'x');` 各自发生了几次堆分配？为什么 `a[0] = 'X'` 合法而 `char* p = "xy"; p[0] = 'X';` 会崩？

<details><summary>参考答案</summary>
1. B。`string` 的拷贝是深拷贝，`s2` 有独立内存，改 `s2` 不影响 `s1`。C 里 `char* p = s` 才是浅拷贝（指针复制）。
2. 错。`string` 内部维护长度和结束符，你不用管 `\0`。`size()` 返回字符数，不含 `\0`。只有调 `c_str()` 和 C 接口互操作时才关心 `\0`。
3. `std::string line(20, '-');` —— 第一个参数是数量，第二个是字符。
4. `a` **0 次**、**`b` 1 次**。libc++（arm64）SSO 容量 22 字节，"xy" 直接放进对象内部的缓冲（实测 `a.data() == &a`）；100 个字符超过容量，才 `operator new` 一块堆内存。`a[0]='X'` 合法是因为构造时字面量已**拷贝**进 string 自己的可写缓冲；`p[0]='X'` 崩是因为 `p` 指向字面量本体，躺在 `__TEXT` 只读段（macOS arm64 实测 SIGBUS，exit 138）。记忆法：指针是"指过去"，数组和 string 是"拷过来"——只有拷过来的才能改。
</details>
