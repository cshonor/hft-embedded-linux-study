# 特殊数值类型与可选值

## 本节讲什么

本节讲解 C++17 引入的几个"可选/多选"值类型工具：(1) `std::optional<T>`——可能存在也可能不存在的值；(2) `std::variant<T...>`——类型安全的 union；(3) `std::any`——任意类型的值；(4) `std::numeric_limits`——类型数值特性查询。这些是替代裸指针/union 的类型安全工具。

> **一句话定位**：`optional` = "可能没有的值"（替代 `T*` + nullptr）；`variant` = "类型安全的 union"；`numeric_limits` = "编译期查 int 的最大值"。

## 核心用法

### 1. std::optional<T>

表示"可能有值也可能没有"——替代 `T*` + nullptr 或 `bool` + `T` 双返回：

```cpp
#include <optional>
std::optional<int> find(const std::vector<int> &v, int target) {
    for (size_t i = 0; i < v.size(); ++i)
        if (v[i] == target) return i;      // 有值
    return std::nullopt;                    // 无值
}
auto r = find(v, 42);
if (r) std::cout << *r;            // 解引用
std::cout << r.value_or(-1);       // 有值返回值，无值返回 -1
r.has_value();                     // 是否有值
r.reset();                         // 清空
```

`optional` 的优势：相比 `T*` + nullptr，它**不涉及堆分配**（值就地存储），且语义更明确——"这个函数可能找不到结果"。

### 2. std::variant<T...>

类型安全的 union——同一时间只持有一种类型，编译期知道所有可能类型：

```cpp
#include <variant>
std::variant<int, double, std::string> v;
v = 42;                    // 当前是 int
v = 3.14;                  // 当前是 double
v = "hello";               // 当前是 string

// 访问
std::get<int>(v);          // 若当前是 int 返回，否则抛异常
std::get_if<int>(&v);      // 若是 int 返回指针，否则 nullptr

// 访问器：std::visit
std::visit([](auto &&x) {
    std::cout << x;
}, v);                     // 对当前持有的类型调 lambda
```

`variant` 相比 union 的优势：类型安全（知道当前是哪种）、自动调析构、支持 `visit` 多态访问。

### 3. std::any

任意类型的值（C++17）——比 `variant` 更灵活但更不安全：

```cpp
#include <any>
std::any a = 42;
a = "hello";
a = 3.14;
// 访问：必须知道实际类型
std::any_cast<double>(a);    // 若类型对返回，否则抛异常
auto p = std::any_cast<double>(&a);   // 指针版，类型错返回 nullptr
```

`any` 用得少——若知道所有可能类型，用 `variant`（编译期检查）；若完全不知道，通常说明设计有问题。

### 4. std::numeric_limits

编译期查询数值类型的特性：

```cpp
#include <limits>
std::numeric_limits<int>::max();        // 2147483647
std::numeric_limits<int>::min();        // -2147483648
std::numeric_limits<double>::epsilon(); // 2.22045e-16（机器 epsilon）
std::numeric_limits<float>::digits;     // 24（有效位数）
std::numeric_limits<int>::is_signed;    // true
```

替代 C 的 `INT_MAX`/`DBL_EPSILON` 宏——类型安全、模板化、可扩展到自定义类型。

## 和 C 的区别

C 没有 `optional`/`variant`，用裸指针或 union：

| 维度 | C | C++ |
|------|---|-----|
| 可选值 | `T*` + nullptr（堆分配 + 悬垂风险） | `optional<T>`（栈上，无指针） |
| 多类型值 | `union`（无类型标签，易误访问） | `variant`（编译期类型安全） |
| 任意类型 | `void*` + 手动强转 | `any` + `any_cast` |
| 数值特性 | `INT_MAX` 宏 | `numeric_limits<T>` 模板 |

```c
// C：可选值用指针 + nullptr
int* find(int *arr, int n, int target) {
    for (int i = 0; i < n; ++i)
        if (arr[i] == target) return &arr[i];
    return NULL;
}
int *r = find(arr, n, 42);
if (r) printf("%d", *r);    // 悬垂风险：arr 释放后 r 失效
```

```cpp
// C++：optional 无指针风险
std::optional<int> find(std::vector<int> &v, int target) {
    for (auto &x : v) if (x == target) return x;
    return std::nullopt;
}
auto r = find(v, 42);
if (r) std::cout << *r;    // r 是值副本，不悬垂
```

```c
// C：union 无类型安全
union Data { int i; double d; };
union Data d;
d.i = 42;
double x = d.d;    // ❌ 误当 double 读——未定义行为，无检查
```

```cpp
// C++：variant 类型安全
std::variant<int, double> v;
v = 42;
std::get<double>(v);    // 抛异常（类型错），而非 UB
std::get_if<double>(&v); // 返回 nullptr
```

> **HFT 视角**：`optional` 常用于"查询可能失败的函数"——订单查找、配置读取。它比抛异常轻量（无栈展开），比返回指针安全（无悬垂）。`variant` 适合"状态机"——订单状态可能是 `Pending`/`Filled`/`Cancelled`，每种带不同数据，`visit` 替代 switch 分发且编译期保证穷尽。

## 常见错误

### 错误 1：解引用空的 optional

```cpp
std::optional<int> o;
std::cout << *o;    // ❌ 未定义行为（o 为空）
std::cout << o.value();   // 抛 std::bad_optional_access
std::cout << o.value_or(0);   // ✅ 安全
```

`*o` 不检查是否为空（UB），`value()` 检查并抛异常，`value_or()` 最安全。

### 错误 2：`variant` 访问错误类型

```cpp
std::variant<int, double> v = 42;
std::get<double>(v);    // ❌ 抛异常（当前是 int）
auto p = std::get_if<double>(&v);   // p == nullptr
```

用 `get_if` 安全检查，或用 `visit` 多态访问。

### 错误 3：`any_cast` 类型不匹配

```cpp
std::any a = 42;
std::any_cast<double>(a);    // ❌ 抛异常（实际是 int）
```

`any` 完全失去类型信息，`any_cast` 必须精确匹配——包括 `const`。这是 `any` 比 `variant` 危险的原因。

### 错误 4：用 `optional<T*>` 制造悬垂

```cpp
std::optional<int*> find_ptr(std::vector<int> &v, int t) {
    for (auto &x : v) if (x == t) return &x;
    return std::nullopt;
}
auto r = find_ptr(v, 42);
// 若 v 扩容/销毁，*r 悬垂
```

`optional<T*>` 仍有指针的悬垂风险。若可能，返回 `optional<size_t>`（索引）或 `optional<int>`（值副本）更安全。

## 自测题

**1. 选择题**：`std::optional<int> o;` 以下哪个访问**不会**抛异常或 UB？

A. `*o`
B. `o.value()`
C. `o.value_or(-1)`
D. `o->something()`

<details>
<summary>答案</summary>

**C**。`o` 为空时：`*o` 是 UB（不检查）；`o.value()` 抛 `bad_optional_access`；`o.value_or(-1)` 返回 -1（安全）。D 语法上对 `optional` 的 `->` 访问内部成员，但空时是 UB。`value_or` 是访问可选值的最安全方式。

</details>

**2. 判断题**：`std::variant<int, double>` 同一时间可以同时持有 int 和 double 两个值。

<details>
<summary>答案</summary>

**错**。`variant` 同一时间只持有**一种**类型的值（像 union）。它知道当前是哪种类型，且切换时自动析构旧值、构造新值。若需同时持有多值，用 `tuple`。

</details>

**3. 踩坑题**：以下代码有什么问题？

```cpp
std::variant<int, std::string> v = 42;
auto s = std::get<std::string>(v);
std::cout << s;
```

<details>
<summary>答案</summary>

`v` 当前持有 `int`（42），但用 `std::get<std::string>` 访问——类型不匹配，抛 `std::bad_variant_access` 异常。

**修复**：
```cpp
if (auto p = std::get_if<std::string>(&v)) {
    std::cout << *p;
} else if (auto p = std::get_if<int>(&v)) {
    std::cout << *p;
}
// 或用 visit：
std::visit([](auto &&x) { std::cout << x; }, v);
```

</details>

**4. 应用题**：用 `optional` 实现一个安全的"配置查找"函数 `get_config(map, key)`，从 `map<string,string>` 查 key，找不到返回空。

<details>
<summary>答案</summary>

```cpp
#include <optional>
#include <string>
#include <unordered_map>
std::optional<std::string> get_config(
    const std::unordered_map<std::string, std::string> &m,
    const std::string &key) {
    auto it = m.find(key);
    if (it != m.end()) return it->second;   // 找到，返回值
    return std::nullopt;                     // 没找到
}
// 用法：
std::unordered_map<std::string,std::string> cfg = {{"host","localhost"},{"port","8080"}};
std::string host = get_config(cfg, "host").value_or("default");
std::string db = get_config(cfg, "db").value_or("test");
// host = "localhost", db = "test"
```

要点：`optional<string>` 表示可能失败、`value_or` 提供默认值、相比返回 `string*`（悬垂风险）或抛异常（开销大）更安全优雅。

</details>
