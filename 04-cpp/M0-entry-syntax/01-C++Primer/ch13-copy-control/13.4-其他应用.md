# 13.4 其他应用

## 本节讲什么

拷贝控制的其他应用：自定义 `swap`、消息传递模型（Message/Folder）、动态内存管理类。重点是 `swap` 在赋值运算符和算法中的应用。

## 核心用法

### 自定义 swap

```cpp
class HasPtr {
    friend void swap(HasPtr&, HasPtr&);
public:
    HasPtr(const std::string& s) : ps(new std::string(s)) {}
    // 用 copy-and-swap 实现赋值
    HasPtr& operator=(HasPtr rhs) {   // 注意：传值（拷贝），不是引用
        swap(*this, rhs);              // 交换 this 和 rhs
        return *this;                  // rhs 析构时释放旧资源
    }
private:
    std::string* ps;
    int i;
};
inline void swap(HasPtr& a, HasPtr& b) {
    using std::swap;
    swap(a.ps, b.ps);    // 交换指针，不拷贝 string
    swap(a.i, b.i);
}
```

### copy-and-swap 惯用法

赋值运算符传**值**（而非 const 引用），调用方决定拷贝还是移动，函数内 swap，rhs 析构自动释放旧资源。一次写法同时处理拷贝赋值、移动赋值、自赋值、异常安全。

### Message/Folder 模型

一个 Message 可属于多个 Folder，一个 Folder 含多个 Message。增删时两边都要更新。这种"双向关系"的资源管理是拷贝控制的综合应用。

## 和 C 的区别

| 维度 | C | C++ |
|------|---|-----|
| swap | 手写三步交换（temp=a;a=b;b=temp） | `std::swap` + 可自定义 |
| 赋值安全 | 全靠手动 | copy-and-swap 惯用法 |
| 双向关系管理 | 手动维护两边一致性 | 拷贝控制封装 |

**C 程序员的体会**：

C 里赋值运算符不存在（struct 赋值是浅拷贝），要安全赋值含资源的 struct 要手写函数处理自赋值、异常、资源释放：
```c
/* C：手动写赋值函数，处理各种边界 */
int hasptr_assign(struct HasPtr* dst, const struct HasPtr* src) {
    if (dst == src) return 0;                    // 自赋值
    char* tmp = strdup(src->ps);                  // 先分配（异常安全）
    if (!tmp) return -1;
    free(dst->ps);
    dst->ps = tmp;
    return 0;
}
```

C++ 的 copy-and-swap 把这些边界情况一次解决，且代码简洁：
```cpp
HasPtr& operator=(HasPtr rhs) {   // 传值：自动拷贝（或移动）
    swap(*this, rhs);              // 交换
    return *this;                  // rhs 析构释放旧资源
}   // 自赋值安全（拷贝再和自己交换）、异常安全（拷贝在传值时完成）
```

## 常见错误

1. **`swap` 不调 `std::swap` 成员**：自定义 swap 要 `using std::swap; swap(a.x, b.x);` 而非 `std::swap(a.x, b.x)`——前者让 ADL 找到成员类型的自定义 swap，后者强制用 std 版。对含自定义 swap 的成员类型，前者更优。
2. **copy-and-swap 传引用而非传值**：`operator=(const HasPtr& rhs)` 传引用，则需手动拷贝，失去"自动选择拷贝/移动"的好处。传值 `operator=(HasPtr rhs)` 让编译器按实参是左值/右值选拷贝/移动构造。
3. **Message/Folder 忘记在拷贝/析构时同步对方**：拷贝 Message 要把它加入所有原 Folder；析构要从所有 Folder 移除。漏了一边就关系不一致。

## 自测题

**1. 选择题**：copy-and-swap 惯用法中，赋值运算符的参数为什么传值（`HasPtr rhs`）而非 const 引用？
- A) 性能更好
- B) 让编译器按实参左值/右值自动选拷贝构造或移动构造
- C) 避免自赋值
- D) 强制深拷贝

<details><summary>答案</summary>

B。传值时，实参是左值则拷贝构造 rhs，是右值则移动构造 rhs——一个赋值运算符同时处理拷贝赋值和移动赋值。若传 const 引用则要手动判断并分别处理。传值 + swap 让代码简洁且自动适配拷贝/移动。自赋值也安全（拷贝出 rhs 再和自己 swap）。性能上，现代编译器可优化掉多余拷贝。

</details>

**2. 判断题**：自定义 `swap` 应该调用 `std::swap` 来交换成员。

<details><summary>答案</summary>

部分正确。应写 `using std::swap; swap(a.member, b.member);` —— `using` 后的非限定 `swap` 会通过 ADL（参数依赖查找）优先找成员类型的自定义 swap，找不到才用 std::swap。直接写 `std::swap(a.member, b.member)` 强制用 std 版，忽略成员可能的自定义 swap（性能差）。这是自定义 swap 的标准写法。

</details>

**3. 踩坑题**：下面 copy-and-swap 实现看似正确，但有隐患吗？
```cpp
HasPtr& operator=(HasPtr rhs) {
    swap(*this, rhs);
    return *this;
}
```
（假设 swap 实现正确）

<details><summary>答案</summary>

实现本身正确（传值 + swap + rhs 析构释放旧资源）。但要注意：1) 自赋值 `a = a` 时，rhs 是 a 的拷贝，swap 后 a 持有拷贝的资源，rhs 持有 a 原资源并析构释放——正确但有一次多余拷贝。2) 若 HasPtr 没有移动构造，传值时 rhs 总是拷贝构造（即使实参是右值），失去移动优化。**改进**：提供移动构造，让传值能移动。整体上 copy-and-swap 是好惯用法，隐患小。

</details>

**4. 应用题**：用 copy-and-swap 为一个含 `char*` 的简单 String 类写赋值运算符，并说明它如何同时满足自赋值安全、异常安全、拷贝/移动统一。

<details><summary>答案</summary>

```cpp
class String {
    char* data_;
public:
    String(const char* s) : data_(strdup(s)) {}
    String(const String& o) : data_(strdup(o.data_)) {}          // 拷贝构造
    String(String&& o) noexcept : data_(o.data_) { o.data_=nullptr; }  // 移动构造
    ~String() { free(data_); }
    friend void swap(String& a, String& b) noexcept {
        using std::swap; swap(a.data_, b.data_);
    }
    // copy-and-swap：传值
    String& operator=(String rhs) noexcept {
        swap(*this, rhs);   // this 持有 rhs 的资源，rhs 持有 this 旧资源
        return *this;       // rhs 析构 free 旧资源
    }
};
```
三个保证：1) **自赋值安全**——`a=a` 时 rhs 是 a 的拷贝（或移动），swap 后 a 持拷贝资源，rhs 持旧资源析构，正确；2) **异常安全**——拷贝在传值时完成（可能抛），swap 是 noexcept，赋值体内不抛，强异常安全；3) **拷贝/移动统一**——实参左值拷贝构造 rhs，右值移动构造 rhs，一个运算符搞定。这是 C++ 资源管理的优雅范式，C 无对应。

</details>
