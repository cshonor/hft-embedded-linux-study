# 13.1 拷贝控制成员

## 本节讲什么

C++ 类的五个**拷贝控制成员**：拷贝构造、拷贝赋值、移动构造、移动赋值、析构函数。它们控制对象被拷贝/移动/销毁时的行为。这是 C 完全没有的概念——C 的 struct 赋值是浅拷贝（memcpy），含指针就出问题。C 程序员必须理解这套机制。

## 核心用法

### 五个成员

| 成员 | 何时调用 | 作用 |
|------|---------|------|
| 拷贝构造 `T(const T&)` | 用同类型对象初始化新对象 | 深拷贝 |
| 拷贝赋值 `T& operator=(const T&)` | 已存在对象赋值 | 先释放旧资源再深拷贝 |
| 移动构造 `T(T&&)` (C++11) | 用右值初始化新对象 | 偷资源（不拷贝） |
| 移动赋值 `T& operator=(T&&)` (C++11) | 已存在对象被右值赋值 | 释放旧资源再偷 |
| 析构 `~T()` | 对象销毁 | 释放资源 |

### 析构函数：何时被调用

**语法**：`~` + 类名，`~Entity() { /* 清理 */ }`。`~` 在 C 里是按位取反——析构就是构造的"反"，记号上故意互补。与构造函数对比，约束全来自实测报错原文（clang 23）：

| | 构造 | 析构 |
|---|---|---|
| 名字 | 类名 | `~` + 类名 |
| 返回类型 | 无 | 无（连 `void` 都不能写） |
| 参数 | 任意 → **可重载** | `~A(int)` → `error: destructor cannot have any parameters` → **不可重载，一个类只有一个** |
| `static` | 不允许 | `static ~C()` → `error: destructor cannot be declared 'static'` |
| 想"重载"两个 | 合法 | `error: destructor cannot be redeclared` |

**为什么析构不能有参数**：析构是编译器在对象死亡点**替你**调用的，你根本没有机会传参——"怎么清理"必须在构造时就用成员变量记好。这也是 RAII 的设计推论：清理逻辑不依赖外部输入。

Cherno 析构函数集一句话："**任何时候对象被销毁，析构函数都会被调用**"。关键是"销毁"到底发生在哪些时刻——用打印实测（clang 23，`-O0`）：

```cpp
class Entity {
public:
    Entity(const char* name) : name_(name) {
        arr_ = new int[50];                 // 构造里拿资源
        std::printf("ctor  %s\n", name_);
    }
    ~Entity() {                             // 销毁时释放
        std::printf("dtor  %s\n", name_);
        delete[] arr_;
    }
private:
    const char* name_;
    int* arr_;
};

void by_value(Entity e) { (void)e; }

int main() {
    Entity outer("outer");                  // ① main 栈对象
    {
        Entity inner("inner");              // ② 内层作用域
    }                                       // ← inner 死在这行
    Entity* heap = new Entity("heap");      // ③ 堆对象：不会自动死
    delete heap;                            // ← 显式 delete 才调析构
    by_value(Entity("temp"));               // ④ 临时对象
    std::printf("main ends\n");
    return 0;
}                                           // ← outer 死在 main 收尾
```

真实输出：

```
ctor  outer
ctor  inner
dtor  inner        ← ② 出内层作用域立刻析构，不等 main 结束
ctor  heap
dtor  heap         ← ③ delete 那一刻才析构；不 delete 就永不调用（泄漏）
ctor  temp
dtor  temp         ← ④ C++17 拷贝省略：临时量直接构造进形参，返回时析构
main ends
dtor  outer        ← ① 栈对象死在所属作用域的右大括号
```

| 场景 | 析构时机 | C 程序员的对应直觉 |
|------|---------|-------------------|
| 栈对象 | **出作用域**（逆声明序） | 没有对应物——C 没有自动清理 |
| 堆对象 | 只有 `delete` 时 | `free` 的时刻，但 C++ 是 `delete` 先调析构再还内存 |
| 临时对象/按值形参 | 所在全表达式结束 / 函数返回 | 无 |
| 静态/全局对象 | `main` 返回后（`__cxa_atexit` 逆序，见 7.6 fiasco 实测） | 无 |
| 异常栈展开 | 展开路径上每个已构造对象 | C 的 `longjmp` 不做任何清理 |

C 程序员最容易带过来的坏习惯是第 ③ 行：`new` 出来的对象**不会**像栈对象那样自动析构，`delete` 漏了析构就永远不执行——这是"构造函数自动、析构函数也自动"说法的唯一例外，自动的是栈对象。

**手动调析构是合法语法，但几乎总是错**（Cherno 也提醒"极少需要"）：

```cpp
Entity e;
e.~Entity();        // 编译通过！但作用域结束时还会再析构一次
```

实测下场：`dtor` 打印两次，然后 `malloc: Double free of object 0x...`，进程被 SIGABRT（exit 134）——同一指针 `delete[]` 两次。手动调析构的唯一正常用途是配合 **placement new**（对象躺在自己管理的内存池里，不会自动析构，必须手动 `p->~T()`），嵌入式写 slab/pool 分配器时会遇到。

构造拿资源、析构释放资源，这个配对就是 **RAII** 的雏形——把资源生命周期绑在对象生命周期上，后面的 [13.2](13.2-资源管理与三五法则.md) 会展开。

### 经典例子：含指针的类

```cpp
class HasPtr {
public:
    HasPtr(const std::string& s) : ps(new std::string(s)) {}
    // 拷贝构造：深拷贝（new 一份新 string）
    HasPtr(const HasPtr& p) : ps(new std::string(*p.ps)) {}
    // 拷贝赋值：先 new 新的，再 delete 旧的（异常安全）
    HasPtr& operator=(const HasPtr& rhs) {
        auto newp = new std::string(*rhs.ps);  // 先分配（可能抛异常）
        delete ps;                              // 再释放旧的
        ps = newp;
        return *this;
    }
    ~HasPtr() { delete ps; }
private:
    std::string* ps;
};
```

### 为什么需要深拷贝

如果用编译器生成的默认浅拷贝（拷贝指针值），两个对象指向同一块内存，析构时**双 delete** → 崩溃。所以含动态资源的类必须自定义拷贝控制。

## 和 C 的区别

| 维度 | C | C++ |
|------|---|-----|
| struct 赋值 | 浅拷贝（memcpy），含指针就危险 | 可自定义拷贝行为 |
| 构造/析构 | ❌ 无 | ✅ 自动调用 |
| 深拷贝 | 手动写 dup 函数 | 拷贝构造函数 |
| 资源释放 | 手动 free | 析构函数自动 |
| 浅拷贝双 free | 常见 bug | 自定义拷贝控制避免 |

**C 程序员最该理解的问题：浅拷贝导致的 double free**

C 里 struct 含指针，赋值是浅拷贝，两个 struct 指向同一块内存，都 free 就崩：
```c
/* C：struct 赋值是浅拷贝，含指针危险 */
struct HasPtr { char* s; };
struct HasPtr a; a.s = strdup("hi");
struct HasPtr b = a;          // 浅拷贝！b.s == a.s，指向同一块
free(a.s);
free(b.s);                    // double free，崩溃！
```

C 里要避免，只能手动写深拷贝函数，且要记得调：
```c
struct HasPtr b = hasptr_dup(&a);   // 手动深拷贝，容易忘
```

C++ 用拷贝构造函数让"深拷贝"自动发生，且编译器保证调用：
```cpp
HasPtr a("hi");
HasPtr b = a;    // 自动调拷贝构造，深拷贝，安全
// 析构各自 delete 自己的 string，不双 free
```

这是 C→C++ 在"资源管理正确性"上的根本提升——把易错的拷贝行为交给类设计者一次性写对，使用者无脑用也不出错。

## 常见错误

1. **浅拷贝导致双 delete**：类含指针但没自定义拷贝控制，默认浅拷贝 → 双 free。**修正**：自定义拷贝构造/赋值做深拷贝，或 `=delete` 禁止拷贝，或用智能指针/值语义避免。**注意**：这条只针对"拥有型"裸指针（本类 new、析构 delete）；视图型裸指针（只指向外部内存、析构不 delete，见 13.2）默认浅拷贝是安全的，不需要手写。
2. **拷贝赋值不处理自赋值**：`a = a` 时，若先 `delete ps` 再用 `rhs.ps`，rhs 就是 *this，已 delete → UB。**修正**：先 new 新的再 delete 旧的（上例写法），或检查自赋值。
3. **拷贝赋值不异常安全**：`delete ps; ps = new string(*rhs.ps);` —— 若 new 抛异常，ps 已 delete，对象处于无效状态。**修正**：先 new 成功再 delete 旧（上例写法）。
4. **手动调析构**：`e.~Entity();` 是合法语法，但栈对象出作用域时会**再析构一次** → 析构体内的 `delete[]` 执行两次 → double free（实测 SIGABRT）。**规则**：栈/堆对象永远让编译器调析构；只有 placement new 出来的对象才手动 `p->~T()`。
5. **new 了忘 delete，以为析构会自动来**：堆对象不会自动析构——`new Entity` 后没有 `delete`，析构函数永远不会执行（实测输出里 heap 的 dtor 只在 delete 那一刻出现）。**修正**：配对的 new/delete，或直接用 `std::unique_ptr` 把 delete 也交给 RAII。

## 自测题

**1. 选择题**：下面类没定义拷贝控制成员，`HasPtr b = a;` 后会发生什么？
```cpp
class HasPtr { public: std::string* ps; HasPtr(std::string s){ps=new std::string(s);} ~HasPtr(){delete ps;} };
```
- A) 编译错误
- B) 浅拷贝，b.ps == a.ps，析构时双 delete
- C) 深拷贝，安全
- D) 运行正常

<details><summary>答案</summary>

B。没定义拷贝构造，编译器生成默认浅拷贝，b.ps 和 a.ps 指向同一块内存。两个对象析构都 delete 同一块 → 双 free，崩溃。这是含指针类不定义拷贝控制的经典后果。**修正**：定义拷贝构造做深拷贝，或用 `unique_ptr`/`string` 值成员避免裸指针。

</details>

**2. 判断题**：拷贝赋值运算符必须处理自赋值（`a = a`）。

<details><summary>答案</summary>

正确。自赋值虽少见但会发生（如 `a[i] = a[j]` 当 i==j）。若实现是 `delete ps; ps = new string(*rhs.ps);`，自赋值时 rhs.ps 就是 ps，先 delete 了再用 → UB。**异常安全写法**（先 new 再 delete）天然处理自赋值：`auto p = new string(*rhs.ps); delete ps; ps = p;` —— 即使 rhs 是 *this，先 new 拷贝好再 delete 旧的，安全。

</details>

**3. 踩坑题**：下面拷贝赋值实现有 bug，找出来。
```cpp
HasPtr& operator=(const HasPtr& rhs) {
    delete ps;              // 先释放自己的
    ps = new string(*rhs.ps);   // 再 new
    return *this;
}
```

<details><summary>答案</summary>

两个 bug：1) **自赋值 UB**——`a = a` 时先 `delete ps`，然后 `*rhs.ps`（rhs 就是 *this）访问已 delete 的内存；2) **不异常安全**——若 `new string` 抛异常，ps 已 delete，对象处于"ps 悬垂"的无效状态。**修正**：先 new 成功再 delete 旧：
```cpp
auto newp = new string(*rhs.ps);   // 先 new（可能抛异常，此时 ps 未动）
delete ps;                          // 成功后才 delete 旧
ps = newp;
return *this;
```
这种写法同时解决自赋值和异常安全。

</details>

**4. 应用题**：用智能指针改写上面的 HasPtr，使其无需手动定义拷贝控制（用默认即可），说明原理。

<details><summary>答案</summary>

```cpp
class HasPtr {
public:
    HasPtr(const std::string& s) : ps(std::make_unique<std::string>(s)) {}
    // 无需自定义拷贝构造/赋值/析构？——等等，unique_ptr 不可拷贝
private:
    std::unique_ptr<std::string> ps;
};
```
问题：`unique_ptr` 不可拷贝，所以 HasPtr 也不可拷贝（默认拷贝构造被删除）。若要可拷贝，用 `shared_ptr`：
```cpp
class HasPtr {
public:
    HasPtr(const std::string& s) : ps(std::make_shared<std::string>(s)) {}
    // 默认拷贝控制：拷贝 shared_ptr（计数+1），析构计数-1，归0才 delete
private:
    std::shared_ptr<std::string> ps;
};
```
shared_ptr 让多个 HasPtr 共享同一 string，引用计数管理，无需手写拷贝控制。代价是共享语义（改一个影响所有）。若要值语义（独立拷贝），还是得手写深拷贝，或用 `std::string` 值成员（最简单）：
```cpp
class HasPtr { std::string ps; /* 默认拷贝控制即可，深拷贝 */ };
```
**教训**：优先用值成员或智能指针，让编译器生成的默认拷贝控制正确工作，避免手写易错的拷贝控制。

</details>

**5. 输出题**：写出下面程序的完整输出（`Entity` 构造/析构各打印一行 `ctor <name>` / `dtor <name>`）：

```cpp
int main() {
    Entity a("a");
    {
        Entity b("b");
        Entity* c = new Entity("c");
    }
    Entity* d = new Entity("d");
    delete d;
    return 0;
}
```

<details><summary>答案</summary>

```
ctor a
ctor b
ctor c
dtor b        ← 内层作用域结束，只有栈对象 b 析构
ctor d
dtor d        ← delete 的那一刻
dtor a        ← main 收尾
```

两个关键：① `c` 的析构**永远不会打印**——它是堆对象，出了作用域只是指针变量没了，对象本体没人 `delete`，泄漏；② 栈对象析构严格逆声明序（b 先于 a），且发生在所属作用域的右大括号，不是 main 末尾统一处理。

</details>

## 可跑的例子

**`examples/13.1-copy-control-members.cpp`** —— 给每个特殊成员函数装一个计数器。

```bash
clang++ -std=c++20 13.1-copy-control-members.cpp -o /tmp/demo && /tmp/demo
```

真实输出（统计部分）：

```
=== 统计 ===
  构造     = 5
  拷贝构造 = 1
  移动构造 = 3
  拷贝赋值 = 1
  移动赋值 = 1
  析构     = 9

  创建对象数 = 9，析构数 = 9  -> 配平，没有泄漏
```

**「创建数 = 析构数」是 C++ 里最重要的自检等式之一。** 只要你的类自己管资源，这个等式就必须成立——不成立就意味着泄漏或重复释放。

顺带还能看出：`vector::push_back` 传入临时对象时，走的是**移动构造**而不是拷贝构造。
