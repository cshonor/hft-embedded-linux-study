# 13.3 对象移动（C++11）

## 本节讲什么

C++11 的**移动语义**：通过**右值引用** `T&&` 和 `std::move`，让对象在转移所有权时"偷"资源而非拷贝，大幅提升性能。这是 C 完全没有的概念——C 的所有赋值都是拷贝，对大对象代价高。

## 核心用法

### 左值 vs 右值

| 概念 | 含义 | 例子 |
|------|------|------|
| 左值（lvalue） | 有名字、可取地址 | `int x;` 中的 x |
| 右值（rvalue） | 临时值、不可取地址 | `42`、`x+1`、`std::string("hi")` |
| 左值引用 `T&` | 绑定左值 | `int& r = x;` |
| 右值引用 `T&&` | 绑定右值 | `int&& r = 42;` |

### 移动构造/赋值

```cpp
class String {
public:
    // 拷贝构造：深拷贝（慢）
    String(const String& o) : data(new char[o.size+1]) { strcpy(data, o.data); }
    // 移动构造：偷资源（快，O(1)）
    String(String&& o) noexcept : data(o.data), size(o.size) {
        o.data = nullptr;   // 置空源对象，防止它 delete
        o.size = 0;
    }
    ~String() { delete[] data; }
private:
    char* data; size_t size;
};
```

### std::move：把左值转成右值

```cpp
String a("hello");
String b = std::move(a);   // 调移动构造，偷 a 的资源
// a 现在是空壳，不要再用 a 的值（但可析构）
```
`std::move` 其实没"移动"任何东西——它只是把左值**强制转换**成右值引用，从而匹配移动构造函数。真正的"偷"在移动构造函数里发生。

### 移动让 vector 扩容高效

```cpp
std::vector<String> v;
v.push_back(String("hi"));   // 临时 String 是右值，移动进 vector（O(1)）
// 若没有移动构造，会深拷贝（O(n)）
```
vector 扩容时，若元素类型有移动构造，会用移动（O(1) 搬指针），否则用拷贝（O(n)）。这就是"noexcept 移动构造"对性能的关键意义。

## 和 C 的区别

| 维度 | C | C++ |
|------|---|-----|
| 赋值语义 | 总是拷贝（memcpy） | 可移动（偷资源） |
| 临时对象处理 | 拷贝 | 移动（C++11） |
| 大对象传递 | 指针（手动管理） | 移动（自动） |
| 资源转移 | 手动搬指针（易错） | 移动构造封装 |

**C 程序员最该理解的：移动 vs 拷贝**

C 里"把一个大缓冲区交给另一个变量"只能 memcpy（慢）或转移指针（手动，源对象状态要自己管）：
```c
/* C：转移大缓冲区要么 memcpy（慢），要么手动搬指针 */
struct Buf { char* data; size_t len; };
struct Buf a = make_big_buf();   // a.data 指向 1MB 内存

// 方式1：memcpy（慢，拷贝 1MB）
struct Buf b = a;                // 1MB 拷贝
// 方式2：手动搬指针（快，但要管 a 的状态）
struct Buf b; b.data = a.data; b.len = a.len;
a.data = NULL; a.len = 0;        // 手动置空 a，否则 double free
```

C++ 的移动语义把"方式2"封装进移动构造，自动且安全：
```cpp
Buf a = make_big_buf();          // 返回值是右值
Buf b = std::move(a);            // 移动构造：O(1) 搬指针，a 自动置空
// a 是空壳，析构安全（移动构造已置空 a.data）
```
这就是移动语义的价值——像指针转移一样快，但像拷贝一样安全（源对象自动处于有效状态）。

## 常见错误

1. **移动后用源对象**：`String b = std::move(a); use(a);` —— 移动后 a 处于"有效但未指定"状态（通常是空壳），用 a 的值是 UB 或逻辑错误。**原则**：move 后只对 a 赋值或析构，不读它的值。
2. **移动构造不加 `noexcept`**：vector 扩容时，只有移动构造是 `noexcept` 才会用移动，否则退化为拷贝（保证强异常安全）。**修正**：移动构造应标 `noexcept`（它通常不抛异常）。
3. **以为 `std::move` 真的移动了**：`std::move(x)` 只是转成右值引用，不移动任何东西。若目标类型没有移动构造，仍会拷贝。移动发生在移动构造/赋值函数内。

## 自测题

**1. 选择题**：`std::move(x)` 做了什么？
- A) 把 x 的内容移到别处
- B) 把 x 强制转换为右值引用
- C) 销毁 x
- D) 拷贝 x

<details><summary>答案</summary>

B。`std::move` 是 `static_cast<T&&>` 的包装，只做类型转换（左值→右值引用），不移动任何东西。真正的移动发生在匹配的移动构造/赋值函数内。若目标类型无移动构造，`auto y = std::move(x)` 仍会拷贝。`move` 这个名字有误导性，它其实是"允许移动"的标记。

</details>

**2. 判断题**：移动构造函数应该标记为 `noexcept`。

<details><summary>答案</summary>

正确。移动构造通常只搬指针不分配内存，不抛异常。标 `noexcept` 很重要——`std::vector` 扩容时，只有当元素类型的移动构造是 `noexcept` 才会用移动（保证强异常安全），否则退化为拷贝（慢）。所以"移动构造不标 noexcept 等于没移动"是常见性能陷阱。

</details>

**3. 踩坑题**：下面代码想用移动提升性能，但 vector 扩容时仍拷贝，为什么？
```cpp
class Big {
public:
    Big(const Big&) { /* 深拷贝 */ }       // 拷贝构造
    Big(Big&&) { /* 搬指针 */ }            // 移动构造，没标 noexcept
    /* ... */
};
std::vector<Big> v;
for (int i = 0; i < 1000; ++i) v.push_back(Big());  // 临时 Big 是右值
```

<details><summary>答案</summary>

移动构造没标 `noexcept`，vector 扩容时为了保证强异常安全（移动途中抛异常会丢失元素），退化为拷贝。**修正**：`Big(Big&&) noexcept { /* 搬指针 */ }`。加 noexcept 后 vector 才放心用移动，扩容 O(n) 搬指针而非 O(n) 深拷贝。这是"移动性能"最常踩的坑。

</details>

**4. 应用题**：写一个简单的动态字符串类，实现拷贝构造（深拷贝）和移动构造（搬指针 + noexecpt），并演示 `vector<String>` push_back 时的移动。

<details><summary>答案</summary>

```cpp
class String {
    char* data_;
    size_t size_;
public:
    String(const char* s) : data_(strdup(s)), size_(strlen(s)) {}
    // 拷贝构造：深拷贝
    String(const String& o) : data_(strdup(o.data_)), size_(o.size_) {}
    // 移动构造：搬指针，noexcept
    String(String&& o) noexcept : data_(o.data_), size_(o.size_) {
        o.data_ = nullptr; o.size_ = 0;   // 置空源
    }
    ~String() { free(data_); }
    // ...
};

std::vector<String> v;
v.reserve(10);
for (int i = 0; i < 5; ++i)
    v.push_back(String("hi"));   // 临时 String 右值，调移动构造（O(1)）
// 若没移动构造，每次 push_back 深拷贝（O(n)）
```
C 里要做同样的事，要么 memcpy（慢），要么手动搬指针 + 管源对象状态（易错）。C++ 移动语义把"高效转移"封装成构造函数，自动且安全。

</details>
