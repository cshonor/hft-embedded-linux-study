# 8.3 文件输入输出

## 本节讲什么

`fstream` 处理文件 IO：`ifstream`（读）、`ofstream`（写）、`fstream`（读写）。重点讲**文件打开/关闭的 RAII**、**文件模式**（in/out/app/trunc/binary）。C 程序员对应的是 `fopen`/`fclose`/模式字符串。

## 核心用法

### 打开与关闭

```cpp
#include <fstream>
#include <string>

// 构造时打开
std::ifstream in("data.txt");        // 构造即打开
if (!in) { /* 打开失败 */ }          // 检查是否成功

std::string line;
while (std::getline(in, line))       // 逐行读
    std::cout << line << "\n";
// in 在作用域结束析构时自动 close，不用手动调
```

### 文件模式

| 模式 | 含义 | C 对应 |
|------|------|--------|
| `std::ios::in` | 读 | `"r"` |
| `std::ios::out` | 写 | `"w"` |
| `std::ios::app` | 追加（每次写到末尾） | `"a"` |
| `std::ios::ate` | 打开后定位到末尾 | `"a+"` 类似 |
| `std::ios::trunc` | 打开时截断（清空） | `"w"` 含此 |
| `std::ios::binary` | 二进制模式 | `"b"` |

```cpp
std::ofstream out("log.txt", std::ios::app);   // 追加模式
out << "new line\n";

std::ifstream bin("data.bin", std::ios::binary | std::ios::in);  // 二进制读
```

### 成员函数 open/close

```cpp
std::ifstream f;
f.open("a.txt");      // 显式打开
// ...
f.close();            // 显式关闭（也可等析构）
f.open("b.txt");      // 同一对象可复用打开多个文件，但要先 close
```

## 和 C 的区别

| 维度 | C (`stdio`) | C++ (`fstream`) |
|------|-------------|-----------------|
| 打开 | `fopen("f","r")` 返回 `FILE*` | 构造 `ifstream in("f")` |
| 关闭 | 手动 `fclose(fp)` | RAII 析构自动关闭 |
| 忘关 | 泄漏 fd | 不会（析构保证） |
| 模式 | 字符串 `"rb"`/`"w+"` | 枚举 `binary|in` |
| 错误检查 | 返回 NULL | 流对象可转 bool |
| 异常安全 | ❌ 出异常就泄漏 | ✅ 栈展开自动析构 |

**C 程序员最该体会的：RAII 自动关闭**

C 的 `FILE*` 必须手动 `fclose`，异常或提前 return 时容易漏：
```c
/* C：手动管理，异常路径易漏 fclose */
FILE* f = fopen("a.txt", "r");
if (!f) return;
// ... 处理 ...
if (error) return;        // 忘了 fclose！泄漏 fd
fclose(f);
```

C++ 的 `fstream` 析构自动关闭，无论正常返回还是异常，都不会泄漏：
```cpp
// C++：RAII，析构自动关闭
void f() {
    std::ifstream in("a.txt");
    if (!in) return;
    // ... 处理 ...
    if (error) return;     // in 析构自动 close，不泄漏
    throw std::runtime_error("x");  // 异常路径也自动 close
}   // 正常退出也自动 close
```
这是 RAII 的经典范例——资源（文件句柄）的生命周期绑定到对象生命周期，编译器保证释放。

## 常见错误

1. **打开后不检查是否成功**：`std::ifstream in("x.txt"); in >> data;` —— 文件不存在时 `in` 处于失败状态，`>>` 读不到东西。**修正**：`if (!in) { /* 处理错误 */ }`。
2. **同一 fstream 对象重复 open 前 没 close**：`f.open("a"); f.open("b");` —— 第二次 open 会失败（已关联文件）。**修正**：先 `f.close()` 或直接用新对象。
3. **ofstream 默认 trunc 误清空文件**：`std::ofstream out("f");` 默认是 `out|trunc`，会清空已有文件！想保留内容用 `std::ios::app`。这是 C 也有但容易忘的坑（C 的 `"w"` 也清空）。

## 自测题

**1. 选择题**：下面哪种方式打开文件**不会**清空已有内容？
- A) `std::ofstream out("f");`
- B) `std::ofstream out("f", std::ios::out);`
- C) `std::ofstream out("f", std::ios::app);`
- D) `std::ofstream out("f", std::ios::trunc);`

<details><summary>答案</summary>

C。`app`（追加）模式在末尾写，不清空。A/B/D 都会清空——A 默认是 `out|trunc`；B 显式 `out` 隐含 trunc；D 显式 trunc。要保留内容追加用 `app`，要读写保留用 `in|out`。

</details>

**2. 判断题**：`std::ifstream in("nonexistent.txt");` 后，`in >> x` 会抛异常。

<details><summary>答案</summary>

错误。fstream **默认不抛异常**，打开失败只是让流进入失败状态，`>>` 静默失败（不读数据，x 不变）。要检查 `if (!in)`。如果想让它抛异常，要调 `in.exceptions(...)` 设置异常掩码，但默认不抛。这与许多新手的直觉相反。

</details>

**3. 踩坑题**：下面函数在异常发生时会泄漏什么？C++ 风格如何避免？
```c
FILE* f = fopen("a.txt", "w");
FILE* g = fopen("b.txt", "w");
do_work();          // 可能抛异常/出错返回
fclose(g);
fclose(f);
```

<details><summary>答案</summary>

`do_work` 出错返回或抛异常（C++ 场景）时，两个 `fclose` 都不执行，泄漏两个文件句柄。C++ 用 fstream + RAII 彻底避免：
```cpp
void f() {
    std::ofstream f("a.txt");
    std::ofstream g("b.txt");
    do_work();          // 抛异常时，g 先析构 close，再 f 析构 close
}                       // 正常也自动 close
```
析构按构造逆序自动执行，无论正常还是异常路径，都不泄漏。这是 RAII 对 C 手动管理的根本优势。

</details>

**4. 应用题**：写一个"安全追加日志"函数：以追加模式打开日志文件，写一条带时间戳的日志，保证任何情况下都不丢 fd、不清空已有日志。

<details><summary>答案</summary>

```cpp
#include <fstream>
#include <chrono>
#include <iomanip>

void log(const std::string& file, const std::string& msg) {
    std::ofstream out(file, std::ios::app);   // app 模式：追加不清空
    if (!out) return;                          // 打开失败静默返回（或抛异常）
    auto t = std::chrono::system_clock::to_time_t(
        std::chrono::system_clock::now());
    out << std::put_time(std::localtime(&t), "%F %T") << " " << msg << "\n";
    // out 析构自动 close，异常也安全
}
```
`app` 保证不清空；`ofstream` RAII 保证 fd 不泄漏；析构刷新缓冲（写盘）。C 版要手动 fclose + goto cleanup 处理异常路径，繁琐且易错。

</details>
