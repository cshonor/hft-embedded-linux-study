# 8.4 string 流

## 本节讲什么

`sstream`：在内存 `string` 上做格式化读写。`istringstream`（从 string 读）、`ostringstream`（向 string 写）、`stringstream`（双向）。C 程序员对应的是 `sscanf`/`sprintf`/`snprintf`。

## 核心用法

### istringstream：字符串解析

```cpp
#include <sstream>
#include <string>

std::string line = "Alice 30 55000.5";
std::istringstream iss(line);
std::string name;
int age;
double salary;
iss >> name >> age >> salary;     // 按空白分割，自动类型转换
// name="Alice", age=30, salary=55000.5
```

逐行读取后逐单词解析的经典模式：
```cpp
std::string line;
while (std::getline(in, line)) {       // 整行读
    std::istringstream iss(line);      // 绑定到这一行
    std::string word;
    while (iss >> word) {              // 单词解析
        // 处理每个单词
    }
}
```

### ostringstream：字符串格式化

```cpp
std::ostringstream oss;
oss << "name=" << name << ", age=" << age << ", salary=" << std::fixed << salary;
std::string result = oss.str();        // 取出结果字符串
```

### stringstream：双向

```cpp
std::stringstream ss;
ss << 42;                              // 写
int x;
ss >> x;                               // 读回（注意读写指针位置）
```

## 和 C 的区别

| 维度 | C (`sprintf`/`sscanf`) | C++ (`sstream`) |
|------|------------------------|-----------------|
| 格式化写入 | `sprintf(buf, "%s=%d", s, n)` | `ostringstream << s << "=" << n` |
| 解析读取 | `sscanf(buf, "%s %d", s, &n)` | `istringstream >> s >> n` |
| 缓冲区管理 | 手动 char 数组，易溢出 | 自动管理 string，不溢出 |
| 类型安全 | ❌ 格式串手动对齐 | ✅ 编译器按类型重载 |
| 大小限制 | 固定数组，`sprintf` 溢出 UB | 自动扩容 |
| 复用 | 每次新 buf | 流对象可复用 |

**C 程序员最该体会的**：

1. **不溢出**：C 的 `sprintf` 写入固定 char 数组，超出长度就溢出 UB（经典安全漏洞）。`snprintf` 改进了但要手动算大小。`ostringstream` 内部用 `string` 自动扩容，永不溢出。

```c
/* C：sprintf 溢出风险 */
char buf[16];
sprintf(buf, "%s", long_string);   // 超过 16 字节就溢出 UB
```
```cpp
// C++：ostringstream 自动扩容，不溢出
std::ostringstream oss;
oss << long_string;                // 想多长多长
std::string s = oss.str();
```

2. **类型安全**：`sscanf("%d", &s)`（s 是 string）编译过但运行崩；`istringstream >> s`（s 是 string）和 `>> n`（n 是 int）按类型选 operator，不会错。

3. **逐行解析更自然**：C 要 `strtok`（破坏原串、非重入）或手动指针遍历；C++ 用 `istringstream >> word` 按空白分割，不破坏原串。

## 常见错误

1. **stringstream 复用前不清空**：`ss << 1; ss >> x; ss << 2; ss >> y;` —— 第二次写前没清，读位置和内容混乱。**修正**：复用要 `ss.clear()`（清状态）+ `ss.str("")`（清内容）。
2. **istringstream 绑定到空 string 或读完没检查**：`iss >> x` 读到末尾失败，x 未赋值却继续用。**修正**：`if (iss >> x)`。
3. **用 ostringstream 拼接大字符串性能差**：频繁 `<<` 小片段、再 `str()` 拷贝，比直接 `string +=` 慢。**建议**：大量拼接用 `string` + `reserve`，需要格式化（数字、对齐）才用 ostringstream。

## 自测题

**1. 选择题**：下面代码输出什么？
```cpp
std::istringstream iss("10 20 30");
int a, b;
iss >> a >> b;
std::cout << a << b;
```
- A) 1020
- B) 102030
- C) 30
- D) 未定义

<details><summary>答案</summary>

A) 1020。`>>` 按空白分割，先读 10 给 a，再读 20 给 b，30 仍在流里未读。输出 `a << b` 拼接为 "1020"。

</details>

**2. 判断题**：`std::ostringstream oss; oss << 3.14; std::string s = oss.str();` 得到的 s 内容是 "3.14"。

<details><summary>答案</summary>

正确（默认格式下）。`operator<<` 对 double 用默认浮点格式，3.14 输出为 "3.14"。注意默认精度是 6 位有效数字，所以 3.14159265 会输出 "3.14159"。要控制格式用 `std::fixed`/`std::setprecision`。

</details>

**3. 踩坑题**：下面代码想复用 stringstream 读多个数据，但第二次读不到，为什么？
```cpp
std::stringstream ss;
ss << "1 2 3";
int a; ss >> a;        // a=1
ss << "4 5";           // 想追加
int b; ss >> b;        // b 想是 4，但读到 2
```

<details><summary>答案</summary>

两个问题：1) `ss << "4 5"` 是**追加写入**，但读写指针在读完 1 后停在 1 后面，"4 5" 被追加到末尾（"1 2 34 5"），而读指针继续读 2；2) 写入和读取共用一个位置指针，混乱。**正确做法**：要么用两个流（一个 istringstream 一个 ostringstream），要么复用时 clear+str 重置：
```cpp
ss.clear();       // 清状态
ss.str("4 5");    // 重置内容
int b; ss >> b;   // b=4
```

</details>

**4. 应用题**：用 istringstream 解析 CSV 行 "Alice,30,55000.5"（逗号分隔），提取姓名、年龄、薪资。提示：用 `getline` 配合分隔符。

<details><summary>答案</summary>

```cpp
#include <sstream>
#include <string>

std::string line = "Alice,30,55000.5";
std::istringstream iss(line);
std::string name, age_str, salary_str;
std::getline(iss, name, ',');        // 读到逗号为止
std::getline(iss, age_str, ',');
std::getline(iss, salary_str);       // 最后一个不用分隔符
int age = std::stoi(age_str);
double salary = std::stod(salary_str);
```
技巧：`getline(流, string, 分隔符)` 可指定分隔符（默认 '\n'），用 ',' 分割 CSV。比 C 的 `strtok`（破坏原串、非线程安全）或手动 `strchr` 干净得多。复杂 CSV（字段含引号/逗号）建议用专门库。

</details>
