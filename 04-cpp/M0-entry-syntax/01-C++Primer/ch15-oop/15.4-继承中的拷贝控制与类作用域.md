# 继承中的拷贝控制与类作用域

## 本节讲什么

本节讲解继承体系中两个较深入的话题：(1) **拷贝控制成员**（拷贝/移动构造、拷贝/移动赋值、析构）在派生类中如何处理基类部分——派生类的拷贝构造必须显式调用基类拷贝构造，否则基类部分被默认构造；(2) **类作用域**下的名字查找规则——派生类作用域嵌套在基类作用域内，派生类同名函数会**隐藏**基类所有重载版本（即使签名不同），`using` 声明可恢复。这是 OOP 中"为什么基类析构必须虚"的深究所在。

> **一句话定位**：派生类对象的拷贝/移动/析构涉及"基类部分 + 派生部分"两个层面，每一层都要正确处理；名字查找在继承层次中按作用域嵌套进行，理解它才能避免"明明有这个函数却找不到"的诡异错误。

## 核心用法

### 1. 虚析构函数（铁律的深究）

**只要一个类可能被用作基类（即可能被继承），其析构函数就应该声明为 `virtual`**：

```cpp
class Base {
public:
    virtual ~Base() = default;   // ✅ 虚析构
};
class Derived : public Base {
    int *data = new int[1000];
public:
    ~Derived() { delete[] data; }
};
Base *p = new Derived;
delete p;   // ✅ 先调 ~Derived（释放 data），再调 ~Base
```

如果不声明虚析构：
```cpp
class BadBase {
public:
    ~BadBase() { }   // ❌ 非虚
};
Base *p = new Derived;
delete p;   // ❌ 行为未定义，通常只调 ~BadBase，~Derived 不调用 → data 泄漏
```

**为什么？** `delete p` 时，编译器根据 `p` 的静态类型（`Base*`）决定调哪个析构。若析构非虚，静态绑定到 `~Base`，派生部分不析构。若析构虚，动态绑定到 `~Derived`，析构链完整：先 `~Derived`，再自动调 `~Base`（析构链总是从派生到基类）。

> **何时不需要虚析构**：当类**不打算被继承**（如 `final` 类、或纯值类型如 `std::string` 的某些实现），或**不通过基类指针删除**时。加虚析构会增加一个 vptr，增大对象体积——所以不要给所有类都加。但只要打算做基类，就一定要加。

### 2. 派生类的拷贝构造

派生类的拷贝构造函数**必须显式调用基类的拷贝构造**，否则基类部分被默认构造（不是拷贝！）：

```cpp
class Base {
public:
    Base() = default;
    Base(const Base &other) : data(other.data) { }
    virtual ~Base() = default;
protected:
    int data;
};
class Derived : public Base {
public:
    Derived() = default;
    // ✅ 正确：显式调用 Base 的拷贝构造
    Derived(const Derived &other)
        : Base(other), extra(other.extra) { }   // Base(other) 触发 Base::Base(const Base&)
    // ❌ 错误：忘了 Base(other)，基类部分被默认构造（data=0 而非拷贝）
    // Derived(const Derived &other) : extra(other.extra) { }
private:
    int extra;
};
```

注意 `Base(other)`：传的是 `Derived` 对象，但 `Base` 的拷贝构造接受 `const Base&`，派生类到基类的隐式转换让这个调用合法——它只拷贝 `Derived` 的 `Base` 部分（对象切片，但这里正是我们想要的）。

### 3. 派生类的拷贝赋值

派生类的拷贝赋值运算符**必须显式调用基类的拷贝赋值**，并处理自赋值：

```cpp
class Derived : public Base {
public:
    Derived& operator=(const Derived &other) {
        if (this != &other) {              // 自赋值检查
            Base::operator=(other);        // ✅ 显式调基类赋值
            extra = other.extra;           // 再赋值派生类成员
        }
        return *this;
    }
private:
    int extra;
};
```

忘记 `Base::operator=(other)` 同样导致基类部分不被赋值——这是隐蔽 bug。

### 4. 派生类的移动构造/赋值（C++11）

类似拷贝，移动构造也必须显式调用基类的移动构造：

```cpp
class Derived : public Base {
public:
    Derived(Derived &&other) noexcept
        : Base(std::move(other)),     // ✅ 显式调基类移动构造
          extra(std::move(other.extra)) { }
    Derived& operator=(Derived &&other) noexcept {
        if (this != &other) {
            Base::operator=(std::move(other));   // ✅ 显式调基类移动赋值
            extra = std::move(other.extra);
        }
        return *this;
    }
private:
    int extra;
};
```

> **noexcept 很重要**：若派生类移动操作不是 `noexcept`，`std::vector` 在扩容时会改用拷贝（保证强异常安全）。给移动操作加 `noexcept` 是性能关键。

### 5. 派生类的析构链

析构总是按"先派生后基类"的顺序，**自动**进行——你不需要也无法在派生类析构里显式调基类析构：

```cpp
class Derived : public Base {
public:
    ~Derived() {
        // 释放派生类资源
        // 函数体结束后，自动调 ~Base
    }
};
```

析构链顺序：`~Derived` → `~Base` → `~Base 的基类` → ... → `~最顶层基类`。这与构造顺序相反（构造是基类→派生类）。

### 6. 合成的拷贝控制规则

编译器为派生类合成的拷贝控制成员会**自动处理基类部分**：

| 成员 | 合成条件 | 合成版本的行为 |
|------|---------|-------------|
| 默认构造 | 无用户定义构造 | 调基类默认构造 + 成员默认构造 |
| 拷贝构造 | 无用户定义拷贝构造 | 调基类拷贝构造 + 成员拷贝构造 |
| 移动构造 | 无用户定义移动/拷贝/析构 | 调基类移动构造 + 成员移动构造 |
| 拷贝赋值 | 无用户定义拷贝赋值 | 调基类拷贝赋值 + 成员拷贝赋值 |
| 移动赋值 | 无用户定义移动/拷贝赋值 | 调基类移动赋值 + 成员移动赋值 |
| 析构 | 总是合成 | 释放派生类成员，自动调基类析构 |

**三/五/零法则在继承中的体现**：
- **三法则**：若基类需要析构（通常因为是基类→虚析构），通常也需要拷贝/移动控制
- **五法则**：定义了其中之一，通常都要定义
- **零法则**：派生类若用 RAII 成员（`unique_ptr`/`vector`/`string`），**啥都不写**，合成版本自动正确处理基类和成员——这是最佳实践

```cpp
class Derived : public Base {
    // 啥都不写！合成的拷贝/移动/析构会正确处理 Base 部分和 members
private:
    std::vector<int> data;    // RAII 成员
    std::unique_ptr<Cache> cache;
};
```

### 7. 类作用域与名字查找

派生类作用域**嵌套在**基类作用域内——名字查找从内向外：

```
全局作用域
  └─ Base 作用域
       └─ Derived 作用域
            └─ 代码处
```

查找规则：编译器从当前作用域开始向外找，找到第一个匹配名字就停下，然后检查类型是否兼容。**这意味着派生类同名函数会隐藏基类所有同名函数（即使签名不同）**：

```cpp
class Base {
public:
    void f() { }              // 无参版本
    void f(int) { }           // int 版本
};
class Derived : public Base {
public:
    void f(double) { }        // 隐藏了 Base 的两个 f！
};
Derived d;
d.f();        // ❌ 编译错误：Derived::f(double) 不接受无参
d.f(1);       // ✅ 调 Derived::f(double)，1 转 double
d.f(1, 2);    // ❌ 编译错误
```

为什么 `d.f()` 报错？查找 `f` 在 `Derived` 作用域找到 `f(double)`，停下，不再往 `Base` 找——即使 `Base` 有 `f()` 也不考虑。然后类型检查 `f()` 无参 vs `f(double)` 需参 → 报错。

### 8. using 声明恢复基类名字

要让派生类同时拥有基类的重载版本，用 `using` 声明把它们"引入"派生类作用域：

```cpp
class Derived : public Base {
public:
    using Base::f;            // ✅ 把 Base 的所有 f 引入 Derived 作用域
    void f(double) { }        // 再添加自己的版本
};
Derived d;
d.f();        // ✅ 调 Base::f()
d.f(1);       // ✅ 重载解析：Base::f(int) 更匹配，调它
d.f(1.5);     // ✅ 调 Derived::f(double)
```

`using Base::f` 把 `Base` 的所有 `f` 重载都"复制"到 `Derived` 作用域，与 `Derived::f(double)` 一起参与重载解析。

### 9. 名字查找 vs 类型检查（先找名字，再查类型）

这是 C++ 一个反直觉但重要的规则：**名字查找在类型检查之前**。如果名字在派生类作用域找到了（即使类型不匹配），就不再往基类找：

```cpp
class Base {
public:
    void g(int) { }
};
class Derived : public Base {
public:
    void g(double) { }     // 隐藏 Base::g(int)
};
Derived d;
d.g(5);       // 调 Derived::g(double)，5 转 double——而非 Base::g(int)
```

`5` 本可以完美匹配 `Base::g(int)`，但因为 `Derived::g` 隐藏了 `Base::g`，查找停在 `Derived`，`5` 被转成 `double` 调 `Derived::g`。这种"隐藏导致非最优匹配"是隐蔽 bug 来源。

## 和 C 的区别

C 没有继承，也就没有"派生类拷贝控制涉及基类部分"的问题——C 结构体的拷贝就是 `memcpy`，一视同仁。但 C 结构体**没有自动资源管理**，深拷贝要手动写：

| 维度 | C | C++ |
|------|---|-----|
| 结构体拷贝 | `memcpy` 或手写 `struct_copy` | 拷贝构造函数，自动调基类部分 |
| 析构链 | 手动调"基类析构"再"派生类析构" | 自动从派生到基类 |
| 名字隐藏 | 无（C 无作用域嵌套） | 派生类同名隐藏基类 |
| 虚析构保证 | 无（手动维护函数指针表） | `virtual ~Base()` 语言保证 |
| 零法则 | 不适用（C 无 RAII） | 用 RAII 成员，啥都不写 |

### C 手动模拟"派生类拷贝"的写法

```c
struct Base { int data; };
struct Derived { struct Base base; int extra; };
// 手动写拷贝函数
void derived_copy(struct Derived *dst, const struct Derived *src) {
    dst->base.data = src->base.data;    // 手动拷基类部分
    dst->extra = src->extra;            // 手动拷派生部分
    // 漏掉 base.data 的拷贝 → bug，编译器不报
}
// 手动写析构链
void derived_destroy(struct Derived *d) {
    /* 派生类资源释放 */
    base_destroy(&d->base);   // 手动调"基类析构"，顺序错就泄漏
}
```

```cpp
// C++：合成版本自动正确
class Derived : public Base {
    std::vector<int> data;   // RAII
public:
    // 啥都不写！合成拷贝构造：先 Base 拷贝，再 data 拷贝
    // 合成析构：先释放 data，自动调 ~Base
};
```

C 版本全靠程序员记得调"基类部分"——漏了就是 bug。C++ 的合成版本和 RAII 把这一切自动化，零法则让你啥都不写就对了。

> **HFT 视角**：派生类移动操作加 `noexcept` 极关键——`std::vector<Base*>` 扩容时若元素类型移动非 `noexcept`，会用拷贝（防止移动中途抛异常导致数据丢失）。`noexcept` 移动让 vector 扩容 O(n) 而非 O(n) 拷贝 + 析构，热路径性能差几倍。

## 常见错误

### 错误 1（铁律）：基类析构非虚

见上文"核心用法 1"。只要类可能被继承且通过基类指针删除，析构必须虚。这是 C++ OOP 第一铁律。

### 错误 2：派生类拷贝构造忘记调基类拷贝构造

```cpp
class Derived : public Base {
public:
    Derived(const Derived &other) : extra(other.extra) { }  // ❌ 没调 Base(other)
};
```

基类部分被默认构造，`data` 不是从 `other` 拷贝来的——数据丢失。**修复**：`Derived(const Derived &other) : Base(other), extra(other.extra) { }`。

### 错误 3：派生类拷贝赋值忘记自赋值检查和基类赋值

```cpp
Derived& operator=(const Derived &other) {
    extra = other.extra;     // ❌ 没调 Base::operator=，没查自赋值
    return *this;
}
```

两个问题：(1) 基类部分没赋值；(2) 自赋值时若成员是指针可能先释放再读。**修复**：
```cpp
Derived& operator=(const Derived &other) {
    if (this != &other) {
        Base::operator=(other);
        extra = other.extra;
    }
    return *this;
}
```

### 错误 4（隐蔽）：派生类同名函数隐藏基类重载

见上文"核心用法 7"。`Derived::f(double)` 隐藏了 `Base::f()` 和 `Base::f(int)`，导致 `d.f()` 报错。**修复**：`using Base::f;` 把基类重载引入派生类作用域。

### 错误 5：析构链顺序搞反

```cpp
~Derived() {
    Base::~Base();      // ❌ 不要手动调基类析构！
    // 释放派生资源
}
```

析构链**自动**按派生→基类顺序。手动调基类析构会导致基类被析构两次（一次手动，一次自动），未定义行为。**派生类析构只管自己的资源，基类析构编译器自动调**。

## 自测题

**1. 选择题**：派生类的拷贝构造函数初始值列表中，若没有显式调用 `Base(other)`，会发生什么？

A. 编译错误
B. 基类部分被默认构造
C. 基类部分被拷贝构造
D. 程序崩溃

<details>
<summary>答案</summary>

**B**。若不显式调基类拷贝构造，基类部分用**默认构造**初始化——这是隐蔽 bug：你以为拷贝了整个对象，实际基类部分是默认值，数据丢失。编译能过（基类有默认构造的话），运行时才发现。

</details>

**2. 判断题**：派生类析构函数执行完毕后，基类的析构函数会被自动调用，无需手动调用。

<details>
<summary>答案</summary>

**对**。析构链自动按"派生→基类"顺序进行，编译器在派生类析构函数体结束后自动插入对基类析构的调用。手动调基类析构会导致重复析构，未定义行为。

</details>

**3. 踩坑题**：以下代码有什么问题？

```cpp
class Base {
public:
    virtual ~Base() = default;
    void log(int x) { std::cout << "int " << x; }
};
class Derived : public Base {
public:
    void log(double x) { std::cout << "double " << x; }
};
int main() {
    Derived d;
    d.log(5);        // 期望调 Base::log(int)
}
```

<details>
<summary>答案</summary>

`d.log(5)` 调的是 `Derived::log(double)`，输出 `double 5`——而非 `Base::log(int)`。因为 `Derived::log` 隐藏了 `Base::log`，名字查找停在 `Derived` 作用域，`5` 被转成 `double`。

若要让两个重载共存，加 `using Base::log;`：
```cpp
class Derived : public Base {
public:
    using Base::log;            // 引入 Base::log(int)
    void log(double x) { /* ... */ }
};
```
此时 `d.log(5)` 重载解析选 `Base::log(int)`（精确匹配优于转换）。

</details>

**4. 应用题**：设计一个含动态资源的基类 `Buffer` 和派生类 `LoggedBuffer`，要求：
- 基类有 `char*` 动态数组，虚析构
- 派生类额外有日志计数器
- 正确实现派生类的拷贝构造和拷贝赋值（处理基类部分）
- 遵循零法则的话，你会怎么改？

<details>
<summary>答案</summary>

**手动版（三法则）**：
```cpp
#include <cstring>
class Buffer {
public:
    Buffer(size_t n) : size_(n), data_(new char[n]) { }
    virtual ~Buffer() { delete[] data_; }
    Buffer(const Buffer &o) : size_(o.size_), data_(new char[o.size_]) {
        std::memcpy(data_, o.data_, size_);
    }
    Buffer& operator=(const Buffer &o) {
        if (this != &o) {
            char *tmp = new char[o.size_];      // 先分配再释放（异常安全）
            std::memcpy(tmp, o.data_, o.size_);
            delete[] data_;
            data_ = tmp; size_ = o.size_;
        }
        return *this;
    }
protected:
    size_t size_;
    char *data_;
};
class LoggedBuffer : public Buffer {
public:
    LoggedBuffer(size_t n) : Buffer(n), log_count_(0) { }
    LoggedBuffer(const LoggedBuffer &o)
        : Buffer(o), log_count_(o.log_count_) { }      // ✅ 显式调基类拷贝
    LoggedBuffer& operator=(const LoggedBuffer &o) {
        if (this != &o) {
            Buffer::operator=(o);                       // ✅ 显式调基类赋值
            log_count_ = o.log_count_;
        }
        return *this;
    }
private:
    size_t log_count_;
};
```

**零法则版（推荐）**——用 `std::vector<char>` 替代手写 `char*`，啥都不写：
```cpp
class Buffer {
public:
    virtual ~Buffer() = default;                        // 虚析构仍是铁律
protected:
    std::vector<char> data_;                            // RAII，自动管理
};
class LoggedBuffer : public Buffer {
    // 啥都不写！合成拷贝/赋值/析构自动正确：
    // - 拷贝：先拷 data_（vector 拷贝），再拷 log_count_
    // - 析构：先析构 log_count_（trivial），自动析构 data_（vector 释放内存）
private:
    size_t log_count_ = 0;
};
```

零法则版的优越性：没有手动内存管理、没有自赋值检查、没有异常安全样板代码、不会忘记调基类部分——合成版本全对。能用 RAII 就用 RAII。

</details>
