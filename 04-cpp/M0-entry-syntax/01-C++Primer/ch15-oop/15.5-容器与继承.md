# 容器与继承

## 本节讲什么

本节讲解继承体系与容器交互时的两个核心难题：(1) **对象切片（object slicing）**——为什么 `vector<Base>` 直接存派生类对象会"切掉"派生部分，必须用 `vector<unique_ptr<Base>>` 才能多态；(2) **菱形继承（diamond inheritance）**与**虚继承（virtual inheritance）**——当派生类从多个路径继承同一个基类时，基类子对象会重复，虚继承如何解决。这是 OOP 实战中"容器 + 继承"的经典痛点。

> **一句话定位**：容器存继承体系的对象，必须存**基类的指针（最好是智能指针）**，不能存值——否则派生部分被切掉，多态失效。

## 核心用法

### 1. 对象切片问题

当派生类对象赋值给基类对象（值，非引用）时，派生部分被"切掉"，只拷贝基类部分：

```cpp
class Base {
public:
    virtual void f() { std::cout << "Base"; }
    int base_data = 1;
};
class Derived : public Base {
public:
    void f() override { std::cout << "Derived"; }
    int derived_data = 2;    // 派生类独有
};
Derived d;
Base b = d;          // ❌ 对象切片！b 只拷贝了 Base 部分，derived_data 丢失
b.f();               // 输出 "Base"（b 的 vptr 指向 Base vtable）
```

切片发生的原因：`b` 是一个 `Base` 对象，内存大小固定为 `sizeof(Base)`，容纳不下 `Derived` 的额外成员。编译器只拷贝 `Base` 部分，且 `b` 的 vptr 被设为 `Base` 的——多态失效。

### 2. 容器与对象切片

直接用 `vector<Base>` 存继承体系的对象，每个派生类对象在插入时都被切片：

```cpp
std::vector<Base> v;
v.push_back(Base{});
v.push_back(Derived{});    // ❌ 切片！存进去的是 Base，Derived 部分丢失
for (auto &x : v) x.f();   // 全输出 "Base"
```

**正确做法**：容器存**基类的指针（或智能指针）**，多态才生效：

```cpp
#include <vector>
#include <memory>
std::vector<std::unique_ptr<Base>> v;
v.push_back(std::make_unique<Base>());
v.push_back(std::make_unique<Derived>());    // ✅ 派生对象完整保留在堆上
for (auto &p : v) p->f();    // 输出 "Base" "Derived"（多态生效）
// unique_ptr 自动 delete，且因 Base 析构虚，~Derived 正确调用
```

> **为什么必须指针？** 容器元素大小固定，无法容纳不同大小的派生类。指针大小固定，指向堆上的实际对象（大小各异），多态通过虚函数实现。这是 C++ OOP 的标准惯用法。

### 3. 基类析构必须虚（再强调）

容器存 `unique_ptr<Base>`，析构时调 `unique_ptr` 的析构，它 `delete` 内部指针。若 `Base` 析构非虚，`delete` 只调 `~Base`，`~Derived` 不调用——派生资源泄漏：

```cpp
class Base {
public:
    ~Base() { }     // ❌ 非虚
};
class Derived : public Base {
    int *data = new int[100];
public:
    ~Derived() { delete[] data; }
};
{
    std::vector<std::unique_ptr<Base>> v;
    v.push_back(std::make_unique<Derived>());
}   // vector 析构 → unique_ptr 析构 → delete ptr → 只调 ~Base → data 泄漏！
```

**铁律重申**：只要类可能被继承且通过基类指针删除（容器场景必属此类），析构必须虚。详见 15.4。

### 4. shared_ptr 的拷贝与容器

`shared_ptr<Base>` 也常用于容器，且支持拷贝（多个容器共享同一对象）：

```cpp
std::vector<std::shared_ptr<Base>> v1;
auto p = std::make_shared<Derived>();
v1.push_back(p);
std::vector<std::shared_ptr<Base>> v2 = v1;   // 浅拷贝，两个 vector 共享对象
// 引用计数管理，最后一个 shared_ptr 销毁时对象才 delete
```

选择 `unique_ptr` 还是 `shared_ptr`：
- **独占所有权**（一个容器独占对象）→ `unique_ptr`，零开销
- **共享所有权**（多处需要持有同一对象）→ `shared_ptr`，引用计数有原子操作开销

### 5. 菱形继承问题

当一个派生类从两条路径继承同一个基类时，基类子对象会**重复**：

```cpp
class Person {
public:
    std::string name;
};
class Student : public Person { /* ... */ };
class Teacher : public Person { /* ... */ };
class TA : public Student, public Teacher { };   // 菱形继承
TA ta;
ta.name = "Alice";    // ❌ 二义性！TA 有两个 Person 子对象（来自 Student 和 Teacher）
ta.Student::name = "Alice";   // 必须显式指定
ta.Teacher::name = "Bob";     // 两个 name 可以不同——通常不是你想要的
```

```
       Person
       /    \
   Student  Teacher
       \    /
        TA
```

`TA` 对象内存中有**两份** `Person` 子对象，访问 `name` 二义。这在 C++ 多继承中是经典陷阱。

### 6. 虚继承解决菱形

`virtual` 继承让共享基类只保留**一份**子对象：

```cpp
class Person { public: std::string name; };
class Student : virtual public Person { };    // ✅ virtual 继承
class Teacher : virtual public Person { };    // ✅ virtual 继承
class TA : public Student, public Teacher { };
TA ta;
ta.name = "Alice";    // ✅ 唯一一份 Person，无二义性
```

虚继承的代价：
- 虚基类子对象通过指针间接访问（多一次内存访问）
- 虚继承的构造较复杂：**最远派生类**（这里是 `TA`）负责初始化虚基类，中间类（`Student`/`Teacher`）对虚基类的构造调用被忽略
- 编译器实现通常用一个 vbase offset 表

> **设计建议**：虚继承复杂且易错，**优先用组合替代多继承**。若必须多继承，常用模式是"接口多继承 + 实现单继承"——多个纯虚基类（接口）+ 一个具体基类，避开菱形数据继承。

### 7. 实战模式：多态容器 + 工厂

容器 + 继承的典型用法：

```cpp
#include <vector>
#include <memory>
#include <iostream>
class Shape {
public:
    virtual void draw() const = 0;
    virtual ~Shape() = default;
};
class Circle : public Shape {
public:
    void draw() const override { std::cout << "○\n"; }
};
class Square : public Shape {
public:
    void draw() const override { std::cout << "□\n"; }
};
int main() {
    std::vector<std::unique_ptr<Shape>> shapes;
    shapes.push_back(std::make_unique<Circle>());
    shapes.push_back(std::make_unique<Square>());
    for (const auto &s : shapes) s->draw();   // 多态：○ □
    // unique_ptr 自动释放，虚析构保证 ~Circle/~Square 调用
}
```

## 和 C 的区别

C 没有继承，"容器存不同类型"靠 `void*` + 手动类型标签：

| 维度 | C | C++ |
|------|---|-----|
| 异质容器 | `void*` + `enum type` 标签 | `vector<unique_ptr<Base>>` |
| 类型分发 | `switch(type)` 手动 | 虚函数自动 |
| 内存管理 | 手动 `malloc`/`free`，易泄漏 | 智能指针 RAII |
| 析构链 | 手动调每个"派生"析构 | 虚析构自动 |
| 菱形继承 | 无（C 无多继承） | 虚继承解决 |

### C 模拟异质容器的写法

```c
enum ShapeType { CIRCLE, SQUARE };
struct Shape {
    enum ShapeType type;
    void *impl;     // 指向具体数据
};
struct Circle { double radius; };
struct Square { double side; };
// 容器：struct Shape shapes[100];
// 绘制：switch (s.type) { case CIRCLE: draw_circle(s.impl); break; ... }
// 释放：switch (s.type) { case CIRCLE: free(s.impl); break; ... }
// 漏掉一个 case 就是 bug，没有编译器帮你检查
```

```cpp
// C++：多态容器
std::vector<std::unique_ptr<Shape>> shapes;
// 添加新类型：只需定义新派生类，不改已有代码（开闭原则）
// 析构：虚析构 + unique_ptr 自动，不会漏
```

C 版本的全 `switch` 分发是维护噩梦——每加一个类型要改所有 switch。C++ 的虚函数让"加类型"只需新增派生类，符合开闭原则。

> **HFT 视角**：多态容器用 `unique_ptr` 有堆分配开销，热路径上可能不可接受。替代方案：(1) 对象池 + 索引，避免反复分配；(2) `std::variant<Circle, Square>` + `std::visit`，编译期多态无堆分配（但类型集合固定）；(3) SoA（Structure of Arrays）布局，按类型分桶存连续内存，cache 友好。

## 常见错误

### 错误 1：容器存值类型 → 对象切片

```cpp
std::vector<Base> v;
v.push_back(Derived{});    // ❌ 切片
```

**修复**：`std::vector<std::unique_ptr<Base>>` + `make_unique<Derived>()`。

### 错误 2：基类析构非虚 + 容器智能指针 → 泄漏

见上文"核心用法 3"。容器存 `unique_ptr<Base>` 时，`Base` 析构必须虚，否则派生资源泄漏。

### 错误 3：菱形继承未用虚继承 → 二义性

```cpp
class A { public: int x; };
class B : public A { };
class C : public A { };
class D : public B, public C { };
D d;
d.x = 1;    // ❌ 二义性：D 有两份 A 子对象
```

**修复**：`B` 和 `C` 改为 `virtual public A`，让 `D` 只有一份 `A`。或重构为组合，避免菱形。

### 错误 4：容器存裸指针 → 忘记 delete

```cpp
std::vector<Base*> v;
v.push_back(new Derived);
// ... 用完忘记 delete v[i] → 泄漏
```

**修复**：用 `unique_ptr<Base>`，RAII 自动释放。**永远不要用裸指针容器**，除非有明确的性能理由 + 对象池管理。

### 错误 5：`shared_ptr` 容器深拷贝期望

```cpp
std::vector<std::shared_ptr<Base>> v1 = { std::make_shared<Derived>() };
auto v2 = v1;    // 浅拷贝！v1[0] 和 v2[0] 指向同一对象
v2[0]->modify(); // v1[0] 也被修改——可能不是你期望的"独立拷贝"
```

若需要独立拷贝，要实现**虚 clone** 函数：
```cpp
class Base {
public:
    virtual std::unique_ptr<Base> clone() const = 0;
};
class Derived : public Base {
public:
    std::unique_ptr<Base> clone() const override {
        return std::make_unique<Derived>(*this);   // 拷贝构造
    }
};
// 深拷贝容器：
std::vector<std::unique_ptr<Base>> deep;
for (auto &p : v1) deep.push_back(p->clone());
```

## 自测题

**1. 选择题**：以下哪种容器声明能正确实现多态（存不同派生类对象并各自调对虚函数）？

A. `std::vector<Base>`
B. `std::vector<Base*>`
C. `std::vector<std::unique_ptr<Base>>`
D. B 和 C 都可以，C 更安全

<details>
<summary>答案</summary>

**D**。A 会对象切片（值类型，派生部分丢失）；B 和 C 都存指针，多态生效。C 优于 B——`unique_ptr` 自动释放，避免手动 `delete` 的泄漏风险。前提是 `Base` 析构虚。

</details>

**2. 判断题**：菱形继承中，若 `B` 和 `C` 都 `virtual public A`，则 `D : public B, public C` 的对象中 `A` 子对象只有一份。

<details>
<summary>答案</summary>

**对**。虚继承的核心作用就是让虚基类在继承层次中只保留一份子对象，消除菱形继承的二义性。`D` 对象中 `A` 子对象唯一，`d.x` 无二义。

</details>

**3. 踩坑题**：以下代码有什么问题？

```cpp
class Animal {
public:
    virtual void speak() { std::cout << "..."; }
    ~Animal() { }     // 注意：非虚
};
class Dog : public Animal {
public:
    void speak() override { std::cout << "Woof"; }
};
int main() {
    std::vector<std::unique_ptr<Animal>> zoo;
    zoo.push_back(std::make_unique<Dog>());
}
```

<details>
<summary>答案</summary>

`Animal` 析构非虚。当 `zoo` 析构时，`unique_ptr` 调 `delete` 内部指针，因析构非虚，只调 `~Animal`，`~Dog` 不调用——若 `Dog` 持有资源（如 `std::string name`）则泄漏。

修复：`virtual ~Animal() = default;`。这是容器 + 继承场景的必备条件。

</details>

**4. 应用题**：设计一个简单的绘图程序，要求：
- 抽象基类 `Shape`，派生类 `Circle`/`Rectangle`
- 用 `vector<unique_ptr<Shape>>` 管理多个形状
- 遍历调 `draw()` 多态输出
- 支持深拷贝整个容器（虚 clone）

<details>
<summary>答案</summary>

```cpp
#include <vector>
#include <memory>
#include <iostream>
#include <string>
class Shape {
public:
    virtual void draw() const = 0;
    virtual std::unique_ptr<Shape> clone() const = 0;   // 虚 clone
    virtual ~Shape() = default;                         // 虚析构
};
class Circle : public Shape {
public:
    Circle(double r) : radius_(r) { }
    void draw() const override { std::cout << "Circle r=" << radius_ << "\n"; }
    std::unique_ptr<Shape> clone() const override {
        return std::make_unique<Circle>(*this);         // 拷贝构造
    }
private:
    double radius_;
};
class Rectangle : public Shape {
public:
    Rectangle(double w, double h) : w_(w), h_(h) { }
    void draw() const override { std::cout << "Rect " << w_ << "x" << h_ << "\n"; }
    std::unique_ptr<Shape> clone() const override {
        return std::make_unique<Rectangle>(*this);
    }
private:
    double w_, h_;
};
int main() {
    std::vector<std::unique_ptr<Shape>> shapes;
    shapes.push_back(std::make_unique<Circle>(5));
    shapes.push_back(std::make_unique<Rectangle>(3, 4));
    for (const auto &s : shapes) s->draw();             // 多态：Circle, Rect
    // 深拷贝：
    std::vector<std::unique_ptr<Shape>> copy;
    for (const auto &s : shapes) copy.push_back(s->clone());
    // 修改 copy 不影响 shapes
    return 0;
}
```

要点：抽象基类 + 纯虚 `draw`/`clone`、虚析构、`unique_ptr<Shape>` 容器、`clone()` 实现深拷贝、`override` 标注。

</details>
