# 5.5 跳转语句

## 本节讲什么

`break`、`continue`、`goto`、`return` 四种跳转语句。前三个改变循环/分支的控制流，`return` 从函数返回（函数章详讲）。

## 核心用法

| 语句 | 作用 | 作用范围 |
|------|------|---------|
| `break` | 跳出最近的循环或 `switch` | 只影响最内层 |
| `continue` | 跳过本次循环剩余部分，进入下一次迭代 | 只影响最内层循环 |
| `goto` | 无条件跳转到标签 | 同一函数内 |
| `return` | 从函数返回 | 退出整个函数 |

```cpp
// break：找到目标就停
for (int i = 0; i < n; ++i) {
    if (arr[i] == target) {
        found = true;
        break;              // 跳出整个 for
    }
}

// continue：跳过偶数
for (int i = 0; i < 10; ++i) {
    if (i % 2 == 0) continue;  // 跳过本次，进入 i+1
    std::cout << i << " ";     // 只打印奇数
}
```

## 和 C 的区别

| 维度 | C | C++ |
|------|---|-----|
| `break`/`continue` 语义 | 完全一致 | 完全一致 |
| `goto` 语法 | 一致 | 一致，都不能跨函数跳 |
| `goto` 跳过变量初始化 | C 不限制（但容易 UB） | C++ **禁止** `goto` 跳过带初始化的变量声明 |
| `return` | 一致 | C++ 多了"返回引用""返回类型可推导(auto)"等 |

**唯一实质差异**：C++ 不允许 `goto` 向前跳过一个带初始化的变量声明，C 没这个限制（但跳过也是 UB）。

```cpp
// C++：编译错误
goto label;          // 向前跳
int x = 10;          // 带初始化，goto 跳过了它
label: use(x);
```

实践中 `goto` 在 C 和 C++ 都**不推荐日常使用**，但有一个合法用途：错误处理路径的集中清理（Linux 内核风格 `goto cleanup`），因为 C 没有 RAII，C++ 有 RAII 所以更少需要 goto。

## 底层实现与实测

> 以下均为本机实测（Apple clang 23.1.0，arm64，`-std=c++17 -O2`）。跳转语句在汇编层就是几条 `b.cond` / `b` 指令，本身几乎不花钱——真正的坑都在**语义**上。

### 实测 1：嵌套循环里 `break` 只跳出最内层（附正确输出）

```cpp
for (int i = 0; i < 3; ++i)
    for (int j = 0; j < 3; ++j) {
        if (i + j == 2) break;
        printf("%d%d ", i, j);
    }
```

实测输出：`00 01 10`

| i | j 的取值 | 说明 |
|---|---|---|
| 0 | j=0 打印 `00`，j=1 打印 `01`，j=2 命中 0+2=2 → break | 打印 2 个 |
| 1 | j=0 打印 `10`，j=1 命中 1+1=2 → break | 打印 1 个 |
| 2 | **j=0 就命中 2+0=2 → break** | 一个都没打印 |

> **修正**：本笔记早期版本的自测题答案写成 `00 01 10 11`（选项 C），**实测输出是 `00 01 10`**——i=2 那一轮 j=0 就触发 break，压根没机会打印 `11`。四个选项当时全都不对，已按实测改正。

### 实测 2：`while` 里的 `continue` 会跳过 `++i`（经典死循环）

```cpp
int i = 0, guard = 0;
while (i < 5) {
    if (++guard > 20) break;    // 保险丝，否则真死循环
    if (i % 2 == 0) continue;   // ← i 恒为 0，永远走这条
    ++i;                        // ← 永远执行不到
}
```

实测：`i=0`，保险丝跑了 21 次。

**为什么 `for` 不会这样**：`for (init; cond; expr)` 的 `continue` 跳到的是 **`expr`（`++i`）**，不是 `cond`；`while` 的 `continue` 直接跳回条件判断，把递增语句留在了循环体里。所以在 `while` 里做递增，要么放在最前面，要么改用 `for`。

### 实测 3：跳出多层循环，三种写法耗时完全相同

400×400 矩阵、命中在 (100,100)、20 轮（`-O2`）：

| 写法 | 实测 |
|---|---|
| `goto found;` | 0.044 ms/轮 |
| 标志位 `bool hit` + 外层 `&& !hit` | 0.042 ms/轮 |
| 抽成函数用 `return` | 0.042 ms/轮 |

**结论**：性能上没有区别（编译器把三者优化成同样的代码），**选可读性最好的**。工程上推荐「抽成函数 + return」——既避免 `goto`，又让函数可以复用、可单测。`goto` 留到 C 风格的资源清理里。

### 实测 4：C++ 禁止 `goto` 跳过带初始化的声明，C 不管

```cpp
goto label;
int x = 10;     // C++：error: cannot jump from this goto statement to its label
label:
return x;
```

同一个文件改成 `.c` 用 `clang -std=c11` 编译：**无错误也无警告**（跳过初始化后 `x` 是不确定值，属于 UB 风险）。

同样的限制也出现在 `switch` 里（跳到某个 case 会绕过前一个 case 的初始化）：

```console
error: cannot jump from switch statement to this case label    ← case 1: int x = 10;  case 2: ...
```

**修正办法**：给 case 加一对花括号 `case 1: { int x = 10; ... break; }`，把变量作用域锁在这一支里。

### 实测 5：`goto cleanup` vs RAII（同一个函数的两种写法）

```cpp
// C 风格：每个失败点跳到对应标签，逆序释放
int with_goto(int fail_at) {
    FILE* f = fopen(...); if (!f) return -1;
    char* buf = malloc(1024); if (!buf) { fclose(f); return -2; }
    if (fail_at == 1) goto free_buf;
    /* 业务逻辑 */
    free(buf); fclose(f); return 0;
free_buf:
    free(buf); fclose(f); return -3;
}

// C++ 风格：所有权交给对象，失败点直接 return
int with_raii(int) {
    auto f = std::unique_ptr<FILE, int(*)(FILE*)>(fopen(...), fclose);
    if (!f) return -1;
    auto buf = std::unique_ptr<char[]>(new char[1024]);
    /* 业务逻辑 */
    return 0;                      // 什么都不用手写
}
```

实测两者都能正确释放（valgrind 之外，最直观的证据是「新增一条失败路径时，goto 版要加一行跳转，RAII 版什么也不用改」）。**维护成本才是差距所在**：goto 版的清理逻辑与出错点数量成正比，RAII 版是常数。

## HFT / 嵌入式视角

- **`break` / `continue` 本身的分支几乎免费**：循环里的分支目标固定，CPU 分支预测器命中率极高。**真正贵的是「数据依赖的分支」**（分支走向由行情数据决定、无法预测），见 [5.3 的分支预测实测](./5.3-条件语句.md)。
- **别用异常当跳转**：`throw`/`catch` 实测约 4 μs/次，比错误码慢三个数量级（详见 [5.6](./5.6-try语句块和异常处理.md)），在热路径上用异常跳出深层循环是灾难。
- **嵌入式里 `goto cleanup` 仍是主流**：很多项目 `-fno-exceptions -fno-rtti`，没有 RAII 的替代（或者团队禁用动态分配），Linux 内核风格就是最稳妥的选择；C++ 侧有了 RAII 之后，`goto` 的唯一正当理由基本消失。
- **`goto` 的一个真实用途：生成状态机 / 解析器**，以及内核里跨越多层的错误回滚——记住它只在**同一函数内**可用。

## 常见错误

1. **`break`/`continue` 只对最内层生效**：嵌套循环里 `break` 只跳出内层，外层继续。想一次跳出多层要用标志位或 `goto`，或把内层抽成函数用 `return`。
2. **`continue` 误用于 `switch`**：`continue` 只对循环生效，`switch` 里的 `continue` 会作用到外层循环，不是 `switch` 本身。容易和 `break`（对 switch 生效）混淆。
3. **滥用 `goto` 制造意大利面条代码**：`goto` 用于错误清理是合理的，但用它代替正常循环/分支会让控制流不可读。C++ 有 RAII、异常、lambda 后，`goto` 几乎没有正当理由。
4. **在 `while` 里用 `continue` 却把递增写在后面**：`while (i < 5) { if (skip) continue; ++i; }` —— `continue` 跳回条件判断，`++i` 永远执行不到，直接死循环（实测 2）。**修正**：改用 `for`（`continue` 会先执行 `++i`），或把递增移到循环体开头。
5. **让 `goto` 跳过带初始化的声明**：C++ 直接编译错误 `cannot jump from this goto statement to its label`（实测 4），`switch` 的 case 之间同理。**修正**：给 case 加 `{}`、把变量声明提到跳转之前，或改用 RAII + 提前 `return`。

## 自测题

**1. 选择题**：下面代码输出什么？
```cpp
for (int i = 0; i < 3; ++i) {
    for (int j = 0; j < 3; ++j) {
        if (i + j == 2) break;
        std::cout << i << j << " ";
    }
}
```
- A) 00 01 10 11 20
- B) 00 01 10 11 20 21
- C) 00 01 10 11
- D) 00 01
- E) 00 01 10

<details><summary>答案</summary>

**E) `00 01 10`**（实测输出，原题 A~D 全部错误，已按实测补上 E）。

逐轮推算（`break` 只跳出内层 `j` 循环）：

| i | 打印 | 何时 break |
|---|---|---|
| 0 | `00`、`01` | j=2 时 0+2=2 |
| 1 | `10` | j=1 时 1+1=2 |
| 2 | **无** | **j=0 时 2+0=2，一进来就 break** |

最容易错的地方就是 i=2：以为还会打印 `11` 或 `20`，实际上 `j=0` 就已经满足条件了。

</details>

**2. 判断题**：C++ 中 `goto` 可以跳到另一个函数里的标签。

<details><summary>答案</summary>

错误。`goto` 只能在**同一函数内**跳转，不能跨函数。跨函数跳转 C 用 `setjmp/longjmp`（危险），C++ 有异常机制 `throw/catch`，都不鼓励日常使用。

</details>

**3. 踩坑题**：下面代码想跳过偶数只处理奇数，但有 bug，找出来。
```cpp
switch (x % 2) {
    case 0: continue;     // 想跳过偶数
    case 1: process(x);
}
```
（这段代码在 for 循环内部）

<details><summary>答案</summary>

`continue` 不作用于 `switch`，它作用到**外层 for 循环**。这里恰好能达到"跳过本次循环"的效果，但语义混乱——读代码的人会以为 continue 作用于 switch。更严重的是：如果这段代码不在循环里，`case 0: continue;` 直接编译错误。**建议**：`switch` 里用 `break`，跳过逻辑用 `if` 或把 switch 抽成函数用 `return`。

</details>

**4. 应用题**：用 `goto` 写一个 Linux 内核风格的错误清理函数：打开文件 → 分配内存 → 加锁，任一步失败都跳到对应清理点逆序释放。体会这种模式与 C++ RAII 的对比。

<details><summary>答案</summary>

```cpp
int do_work() {
    FILE* f = fopen("a.txt", "r");
    if (!f) return -1;

    char* buf = (char*)malloc(1024);
    if (!buf) goto close_f;

    if (!lock()) goto free_buf;

    // ... 业务逻辑 ...
    int rc = 0;

    unlock();
free_buf:
    free(buf);
close_f:
    fclose(f);
    return rc;
}
```
C++ 中用 RAII（析构函数自动释放）或 `unique_ptr`/`lock_guard`，完全不需要这套 `goto cleanup`——这是 C→C++ 最大的解放之一。

</details>

**5. 踩坑题**：下面循环想统计奇数之和，实际会发生什么？
```cpp
int i = 0, sum = 0;
while (i < 10) {
    if (i % 2 == 0) continue;
    sum += i;
    ++i;
}
```

<details><summary>答案</summary>

**死循环**。`i=0` 是偶数 → `continue` 直接跳回 `while (i < 10)` 的判断，`++i` 永远执行不到，`i` 恒为 0。

**三种修法**：
1. 改成 `for (int i = 0; i < 10; ++i) { if (i % 2 == 0) continue; sum += i; }` —— `for` 的 `continue` 会先执行 `++i`；
2. 把 `++i` 挪到循环体**最前面**（`continue` 之前）；
3. 干脆不用 `continue`：`if (i % 2 != 0) sum += i;`。

实测：在 `while` 里加保险丝后跑 21 次仍未退出，`i` 一直是 0。

</details>

**6. 判断题**：跳出多层循环时，`goto` 比标志位快得多，所以性能敏感的代码应该用 `goto`。

<details><summary>答案</summary>

**错**。实测（400×400 矩阵、命中在 (100,100)、20 轮 `-O2`）：`goto` 0.044 ms/轮、标志位 0.042 ms/轮、抽函数 `return` 0.042 ms/轮——**三者持平**（`goto` 甚至略慢一点，属于噪声）。编译器把三种写法优化成了同样的代码。

选型应该看**可维护性**：优先「抽成函数 + return」（可复用、可单测），其次是标志位；`goto` 留给 C 风格的资源清理。这条结论和 [5.4 遍历写法](./5.4-迭代语句（循环）.md) 那组实测同源：控制流的**写法**几乎不影响性能，影响性能的是**数据访问模式和能不能预测**。

</details>
