# 5.4 迭代语句（循环）

## 本节讲什么

四种循环：`while`、传统 `for`、**范围 for（range-for，C++11）**、`do-while`。重点讲范围 for 的用法与限制——这是 C 程序员最该学的新东西。

## 核心用法

| 语句 | 形式 | 适用场景 |
|------|------|---------|
| `while` | `while (cond) stmt` | 次数未知，先判断后执行 |
| 传统 `for` | `for (init; cond; expr) stmt` | 按步骤迭代，可控制增量 |
| 范围 for | `for (decl : coll) stmt` | 遍历容器/数组的每个元素 |
| `do-while` | `do stmt while (cond);` | 至少执行一次 |

### 范围 for（C++11）

```cpp
std::vector<int> v = {1, 2, 3, 4, 5};

// 只读遍历：用 const auto&
for (const auto& x : v)
    std::cout << x << " ";

// 修改元素：用 auto&
for (auto& x : v)
    x *= 2;

// 注意：不要在范围 for 中改变容器大小（push_back/erase）
```

范围 for 等价于：
```cpp
auto it = v.begin();
auto end = v.end();
for (; it != end; ++it) {
    auto& x = *it;
    // 循环体
}
```

## 和 C 的区别

| 维度 | C | C++ |
|------|---|-----|
| `while` / `for` / `do-while` | 完全一致 | 完全一致 |
| `for` 变量作用域 | C89：循环外可见；C99 起：块作用域 | 一直是块作用域 |
| 范围 for | ❌ C 没有任何等价语法 | ✅ C++11 起有 |
| 遍历容器 | C 要手写索引或指针循环 | 范围 for 一行搞定 |

**范围 for 是 C 程序员转 C++ 最直接受益的特性之一**——C 里遍历数组只能写 `for (int i=0; i<n; ++i) a[i]`，C++ 里直接 `for (auto& x : a)`，且不会越界。

```c
/* C：手写索引，容易越界 */
int sum = 0;
for (int i = 0; i < n; ++i)   // n 维护错了就 UB
    sum += arr[i];
```
```cpp
// C++：范围 for，无需维护索引
int sum = 0;
for (int x : arr)   // arr 是数组或容器，自动取 begin/end
    sum += x;
```

## 底层实现与实测

> 本机 clang 实测（`-std=c++17`，Apple Silicon）。这一节最容易被"经验之谈"误导——比如"迭代器比下标快""范围 for 有额外开销"，实测下来都不成立。

### 实测 1：五种遍历写法，性能差别几乎为零

100 万个 `int` 的 `vector`，每种写法跑 20 轮求和（`-O2`）：

| 写法 | 20 轮耗时（两次运行） | 折合每轮 |
|------|---------------------|---------|
| 下标 `v[i]`（`size_t i`） | 2.83 / 2.02 ms | ≈ 0.10 ms |
| 下标 `v[i]`（`int i`，缓存 size） | 2.83 / 2.01 ms | ≈ 0.10 ms |
| 迭代器 `begin()/end()` | 2.84 / 2.00 ms | ≈ 0.10 ms |
| 范围 for（`auto x` 拷贝） | 2.41 / 1.94 ms | ≈ 0.10 ms |
| 范围 for（`const auto& x`） | 2.33 / 1.74 ms | ≈ 0.09 ms |

**结论**：`-O2` 下这五种写法生成的机器码几乎一样，差距落在噪声范围内（1 亿次访存 ≈ 2 ms，即**瓶颈是内存带宽，不是循环写法**）。所以：

- 别为了"性能"在下标和迭代器之间纠结，**选可读性最好的那个**；
- 真正的性能差异只在**循环体**里（有没有拷贝元素、有没有分支、有没有 cache miss）。

### 实测 2：`for (auto x)` 的拷贝是真的会发生

```cpp
struct Big { std::string s; int pad[8]; };   // sizeof = 56
std::vector<Big> v(3);
for (auto  x : v) x.s = "changed";   // 改的是副本
for (auto& x : v) x.s = "changed";   // 改的是元素
```

实测输出：

```
  for(auto x)     改后 v[0].s = ""        ← 一个都没改到
  for(auto& x)    改后 v[0].s = "changed"
```

每个元素拷贝 56 字节 × N 个，且**编译器不会告诉你**。对小类型（`int`、`char`）无所谓，对结构体/字符串就是实打实的开销加静默 bug。

### 实测 3：`size_t` 逆向循环会回绕而不是停下

```cpp
std::vector<int> v{1,2,3};
for (size_t i = v.size() - 1; i >= 0; --i) { ... }   // ❌
```

实测第 6 次迭代时 `i = 18446744073709551613`（即 2⁶⁴−3）——`i >= 0` 对无符号数**恒为真**，减到 0 后再减就回绕。要么改成 `for (size_t i = v.size(); i-- > 0; )`，要么直接用有符号 `ptrdiff_t`/`int`。同源坑见 [3.5.2 下标访问与越界](../ch03-strings-vectors-arrays/3.5-arrays/3.5.2-下标访问与越界.md)。

## HFT/嵌入式关联

- **热循环的选型依据是循环体，不是循环头**（实测 1）。行情快照遍历、order book 分层扫描这类代码，先确认有没有在循环里做无谓拷贝（实测 2）或随机访存，再谈下标 vs 迭代器。
- **范围 for 只用于"遍历"，不用于"增删"**：`end()` 在循环开始时缓存，任何改变容器大小的操作都让它失效（UB）。要边遍历边删，用 `erase-remove` 惯用法或索引循环——见 [10.1 基础算法与重排](../../ch10-generic-algorithms/10.1-基础算法与重排.md)。
- **遍历前先 `reserve`**：循环里 `push_back` 触发扩容会搬迁全部旧元素（实测见 [3.3.5](../../ch03-strings-vectors-arrays/3.3-library-type-vector/3.3.5-拷贝移动与扩容.md)），在延迟敏感的循环里这是典型的毛刺来源。
- **小类型用值、大类型用引用**：`char`/`int`/`double` 走值即可（引用底层是指针，反而多一次 load，汇编证据见 [6.1 实测 1](../../ch06-functions/6.1-函数基础与参数传递.md)）；结构体、字符串一律 `const auto&`。

## 常见错误

1. **范围 for 用值类型导致无法修改 + 性能损耗**：`for (auto x : v)` 会拷贝每个元素，既不能修改原元素，大对象还慢。**修正**：只读用 `const auto&`，要改用 `auto&`。
2. **范围 for 中修改容器大小**：`for (auto& x : v) v.push_back(x);` —— `end()` 在循环开始时缓存，扩容后迭代器失效，UB。**修正**：先拷贝或用索引循环。
3. **范围 for 遍历 `vector<bool>` 用 `auto&`**：`vector<bool>` 的元素不是真正的 bool，是代理对象，`auto&` 推导出的是代理引用而非 bool&。**修正**：用 `auto` 或 `const auto&`。
4. **用 `size_t` 做逆向循环**（实测 3）：`for (size_t i = n-1; i >= 0; --i)` 永远成立，减到 0 后回绕成 2⁶⁴−1，越界访问。**修正**：`for (size_t i = n; i-- > 0; )` 或改用有符号下标。
5. **循环条件里重复调用 `size()`**：`for (size_t i = 0; i < s.size(); ++i)` 中 `size()` 理论上每次都要算。实测 1 表明 `-O2` 下编译器会把它提到循环外（几种写法耗时相同），所以这属于**可读性问题而非性能问题**——但 `-O0` 调试构建下确实会变慢，别拿 debug 构建测性能。

## 自测题

**1. 选择题**：下面哪种写法能正确地把 `vector<int>` 每个元素翻倍？
- A) `for (auto x : v) x *= 2;`
- B) `for (auto& x : v) x *= 2;`
- C) `for (const auto& x : v) x *= 2;`
- D) `for (auto x : v) v[x] *= 2;`

<details><summary>答案</summary>

B。`auto&` 是引用绑定，能修改原元素。A 是拷贝改不动原值；C 是 const 引用不能修改；D 的 `x` 是元素值不是索引，逻辑错误。

</details>

**2. 判断题**：范围 for 循环里调用 `v.clear()` 是安全的。

<details><summary>答案</summary>

错误。`clear()` 让所有迭代器失效，范围 for 内部持有的 `end()` 和当前迭代器都会失效，属于未定义行为。范围 for 只适合"只读遍历"或"就地修改元素值"，不能增删元素。

</details>

**3. 踩坑题**：下面代码打印什么？为什么？
```cpp
std::vector<int> v = {1, 2, 3};
for (auto x : v) {
    v.push_back(x);   // 想复制一份
}
std::cout << v.size();
```

<details><summary>答案</summary>

未定义行为。范围 for 开始时缓存了 `end()`，但 `push_back` 可能触发扩容使 `end()` 失效，循环无法正确终止，可能死循环或崩溃。**正确做法**：先记录要添加的元素，循环结束后再批量 push，或用索引循环并提前 reserve。

</details>

**4. 应用题**：用范围 for 统计一个 `std::string` 中元音字母的个数，要求高效（不拷贝）。

<details><summary>答案</summary>

```cpp
std::string s = "hello world";
int vowels = 0;
for (char c : s) {                 // char 是小类型，用值即可；大对象用 const auto&
    if (c=='a'||c=='e'||c=='i'||c=='o'||c=='u' ||
        c=='A'||c=='E'||c=='I'||c=='O'||c=='U')
        ++vowels;
}
std::cout << vowels;  // 3
```
`char` 是 trivially copyable 类型，用值比引用更高效（引用底层是指针，反而多一次间接寻址）。

</details>
