# 5.1–5.2 简单语句与作用域

## 本节讲什么

C++ 的最基本语句形式：表达式语句、空语句、复合语句（块），以及变量在控制结构中形成的**块作用域**。这些是构成后面所有控制流的基础。

## 核心用法

### 五种基本语句

| 语句 | 形式 | 说明 |
|------|------|------|
| 表达式语句 | `expr;` | 末尾加分号，如 `i = 0;`、`std::cout << x;` |
| 空语句 | `;` | 只有一个分号，循环体为空时用，如 `while (cin >> x) ;` |
| 声明语句 | `int i;` | C++ 中声明也是语句，可出现在任何位置 |
| 复合语句（块） | `{ ... }` | 用花括号括起来的语句序列，是一个作用域 |
| 控制语句 | `if`/`for`/`while`... | 后续章节讲 |

### 语句作用域

在 `if`、`for`、`while` 等控制结构内部定义的变量，只在**该控制结构内可见**，出了结构即销毁：

```cpp
while (int i = get_value()) {  // i 在整个 while 循环可见
    // i 在循环体内可见
}  // i 在这里销毁，外部不可访问
```

```cpp
for (int i = 0; i < 10; ++i) {
    int sq = i * i;  // sq 只在本次循环体可见
    std::cout << sq << " ";
}
// i 和 sq 在这里都已销毁
```

## 和 C 的区别

| 维度 | C（C89） | C99 / C++ | C++ 额外 |
|------|---------|-----------|---------|
| 声明位置 | C89 强制声明必须在**块开头**，语句之后不能再声明 | C99 放宽，允许声明与语句混合；C++ 一直允许 | — |
| `for` 变量作用域 | C89：`for` 里定义的变量在循环外仍可见 | C99 起：循环外不可见（与 C++ 一致） | C++ 从一开始就是块作用域 |
| 声明即语句 | ❌ C89 不行 | ✅ C99 起可以 | ✅ C++ 一直可以 |

**C 程序员最常踩的坑**：从 C89 习惯过来，把所有声明堆在函数开头。C++ 鼓励"用到时再声明"，可以提升可读性，有时还能减少作用域污染。

```c
/* C89 风格：声明全堆在开头 */
void f(void) {
    int i, sq, sum;     /* 必须在这里 */
    sum = 0;
    for (i = 0; i < 10; ++i) { sq = i*i; sum += sq; }
}
```
```cpp
// C++ 风格：用到时再声明
void f() {
    int sum = 0;
    for (int i = 0; i < 10; ++i) {   // i 只在 for 内可见
        int sq = i * i;              // sq 只在本次循环可见
        sum += sq;
    }
}
```

## 底层实现与实测

> 以下均为本机实测（Apple clang 23.1.0，arm64，`-std=c++17 -O2`）。作用域是**编译期概念**——它决定「什么时候调析构函数」和「哪个名字可见」，但**不保证**内存复用。

### 实测 1：作用域什么时候结束？让析构函数告诉你

用 RAII 探针（构造/析构各打印一行）：

```cpp
struct Probe {
    const char* name;
    explicit Probe(const char* n) : name(n) { printf("+ 构造 %s\n", name); }
    ~Probe() { printf("- 析构 %s\n", name); }
};

for (int i = 0; i < 2; ++i) {
    Probe p("loop-body");
    printf("i=%d\n", i);
}
```

实测输出：

```
+ 构造 loop-body      i=0
- 析构 loop-body
+ 构造 loop-body      i=1
- 析构 loop-body
```

**循环体里的对象每轮迭代都构造 + 析构一次。** 这是热路径上最容易忽略的成本：`for` 里写 `std::string s = fmt(x);` 意味着每轮一次构造 + 可能的堆分配。

手动加一对花括号可以精确控制生命周期：

```
+ 构造 block-a
+ 构造 block-b
- 析构 block-b        ← 内层块结束就析构
（b 已销毁）
- 析构 block-a
```

### 实测 2：出了作用域，栈内存**不一定**复用

```cpp
{ int x = 1; printf("块1 x 地址 %p\n", (void*)&x); }
{ int x = 2; printf("块2 x 地址 %p\n", (void*)&x); }
```

实测：`块1 0x16d222cdc` / `块2 0x16d222cd8`——相邻但**不同**。

编译器按自己的栈布局分配槽位，"变量出了作用域，它占的内存就被释放/复用"是**错误直觉**。真正可靠的只有一条：**出了作用域，对象的析构函数已经跑过了，再访问它就是 UB**（悬垂指针/引用，见 [6.2 返回类型](../ch06-functions/6.2-返回类型.md) 的悬垂引用实测）。

### 实测 3：遮蔽（shadowing）合法，但编译器能帮你抓

```cpp
int v = 100;
{ int v = 200; /* 内层 v 盖住外层 */ }
```

```console
$ clang++ -std=c++17 -Wshadow x.cpp
warning: declaration shadows a local variable [-Wshadow]
```

注意区分两件事（详见 [3.5.5 易错点](../ch03-strings-vectors-arrays/3.5-arrays/3.5.5-易错点与示例.md)）：**内层块**遮蔽外层变量是合法的；**同一作用域**里同名声明两次是 `error: redefinition`。

### 实测 4：C89 vs C++——声明位置

| 代码 | `clang -std=c89 -pedantic`（C） | `-std=c99`（C） | C++ |
|---|---|---|---|
| `for (int i = 0; ...)` | warning: `variable declaration in for loop is a C99-specific feature` | ✅ | ✅（一直允许） |
| 语句之后再声明 | warning: `mixing declarations and code is a C99 extension` | ✅ | ✅ |

所以从 C89 移植代码时，「把声明堆在块开头」是历史习惯而不是语言要求；C++ 从一开始就允许随处声明，C99 才追上来。

### 实测 5：C++17 带初始化的 `if` / `switch`（C 完全没有）

```cpp
if (int n = get_value(); n > 0) { /* n 可见 */ }
else                            { /* n 也可见 */ }
switch (int k = argc; k) { case 1: /* k 可见 */ break; }
```

实测变量在 `if` 的**两个分支**和 `switch` 的**所有 case** 里都可见，出了结构就销毁。价值：把「只给条件用的临时变量」锁死在条件结构里，避免污染外层作用域——这正是 `if (auto it = m.find(k); it != m.end())` 这类写法的目的。

### 实测 6：空语句有专门的警告

```cpp
while (j < n);   // ← 分号
```

```console
warning: while loop has empty body [-Wempty-body]
note: put the semicolon on a separate line to silence this warning
```

把分号单独放一行（`while (cond)` 换行 `;`）是社区惯例——明确告诉读者"这是故意的空循环体"。

## HFT / 嵌入式视角

- **作用域 = 临界区长度**：`std::lock_guard` 的作用域就是持锁时间。实测 1 说明「块结束即析构」，把锁塞进最小块能直接缩短锁竞争窗口——低延迟代码里最常用的一招。
- **热循环里别在循环体构造对象**：实测 1 的证据——每轮一次构造 + 析构。`std::string`、`std::vector`、`std::lock_guard` 都算；能提到循环外就提出来（hoist）。
- **嵌入式栈很小**（常见 8–16 KB，RTOS 任务栈可能只有 1–2 KB）：块作用域变量占栈，深层嵌套 + 大数组容易爆栈；大缓冲改 `static` 或放全局。
- **声明时立即初始化**：`int x;` 在块作用域里是不确定值，读到就是 UB（ASan 未必每次都能抓到）。写 `int x{};`。
- **别依赖栈内存复用**（实测 2）：返回局部变量地址在任何优化等级下都是错的，哪怕"看起来还能读到旧值"。

## 常见错误

1. **在控制结构外用内部变量**：`for (int i=0;...) {...}` 之后再用 `i`，C89 能过、C++ 报错。这是从 C 移植代码时最常见的编译错误之一。
2. **空语句误用导致逻辑错误**：`while (i < n); { ++i; }` —— 末尾分号让循环体变成空语句，花括号成了独立块，导致死循环。
3. **误以为 `for` 条件里的变量在整个函数可见**：在 `for (int i...)` 后还想用 `i` 做别的事，应该把 `i` 提到循环外声明。
4. **在循环体里构造昂贵对象**：实测 1 显示循环体对象每轮构造 + 析构一次。`for (...) { std::string s = fmt(x); ... }` 在百万级循环里就是百万次构造/析构。**修正**：能复用就在循环外声明并 `clear()`，或改用 `std::string_view` / 栈上定长缓冲。
5. **以为出了作用域内存就会被复用**：实测 2（两个块的 `x` 落在相邻但不同的地址）。把局部变量地址返回或保存到外面，读到什么全看编译器心情，是 UB。

## 自测题

**1. 选择题**：以下代码在 C++ 中的输出是？
```cpp
int i = 0;
for (int i = 0; i < 3; ++i) { /* 空 */ }
std::cout << i;
```
- A) 0
- B) 3
- C) 编译错误
- D) 未定义行为

<details><summary>答案</summary>

A) 0。`for` 里的 `i` 遮蔽了外层的 `i`，循环结束后内层 `i` 销毁，外层 `i` 仍为 0。这是合法但容易混淆的写法。

</details>

**2. 判断题**：在 C++ 中，`int x = 10; std::cout << x;` 可以在函数体中间直接写，不必把 `int x` 放在块开头。

<details><summary>答案</summary>

正确。C++ 允许声明语句出现在任意位置，这是 C++ 相对 C89 的一个进步（C99 也放宽了）。

</details>

**3. 踩坑题**：下面代码意图是累加，但运行结果是死循环，为什么？
```cpp
int n = 5, sum = 0;
int i = 0;
while (i < n);
{
    sum += i;
    ++i;
}
```

<details><summary>答案</summary>

`while (i < n);` 末尾的分号构成空语句，循环体为空，`i` 永远不变化 → 死循环。下面的 `{ sum += i; ++i; }` 是一个独立的复合语句块，不属于循环。**修正**：去掉 `while` 后的分号。

</details>

**4. 应用题**：把下面 C89 风格代码改写成 C++ 推荐风格（用到时再声明，最小化作用域）。
```c
void process(int* arr, int n) {
    int i, j, tmp;
    for (i = 0; i < n; ++i)
        for (j = i+1; j < n; ++j)
            if (arr[j] < arr[i]) {
                tmp = arr[i]; arr[i] = arr[j]; arr[j] = tmp;
            }
}
```

<details><summary>答案</summary>

```cpp
void process(int* arr, int n) {
    for (int i = 0; i < n; ++i)
        for (int j = i + 1; j < n; ++j)
            if (arr[j] < arr[i]) {
                int tmp = arr[i];   // 用到时再声明
                arr[i] = arr[j];
                arr[j] = tmp;
            }
}
```
`i`、`j`、`tmp` 都限定在最小作用域内，外层不再可见，减少误用风险。

</details>

**5. 输出题**：下面代码里 `Probe` 会打印几组构造/析构？顺序如何？
```cpp
struct Probe { Probe(const char*); ~Probe(); };   // 各打印一行
for (int i = 0; i < 3; ++i) {
    Probe p("body");
    if (i == 1) { Probe q("inner"); }
}
```

<details><summary>答案</summary>

`body` 构造/析构 **3 组**（每轮一次），`inner` **1 组**（只在 i==1 那轮、且在内层块结束时析构）。顺序：

```
+ body   (i=0)
- body
+ body   (i=1)
+ inner      ← 进入内层块
- inner      ← 内层块结束立即析构，不等循环结束
- body       ← 循环体结束
+ body   (i=2)
- body
```

要点：**内层块有自己的生命周期，不等外层**。这正是把 `std::lock_guard` 塞进最小块就能缩短临界区的原理。

</details>

**6. 判断题**：下面两句对不对？
> (a) 变量出了作用域，它占的栈内存就一定会被后面的变量复用。
> (b) `for` 循环体里的对象只构造一次，循环结束才析构。

<details><summary>答案</summary>

**两句都错。**

(a) 实测：两个相邻块里的 `int x` 地址是 `0x16d222cdc` 和 `0x16d222cd8`——相邻但**不同**。栈槽怎么分配由编译器决定，语言只保证"出了作用域析构函数已跑过、再访问是 UB"，不保证内存复用。把局部变量地址传出去是经典 UB。

(b) 实测输出（`examples/5.1-1`）：`+ 构造 → i=0 → - 析构 → + 构造 → i=1 → - 析构`——**每轮迭代都构造 + 析构一次**。热循环里放昂贵对象（string/vector/lock_guard）会被放大成百万次开销。

</details>
