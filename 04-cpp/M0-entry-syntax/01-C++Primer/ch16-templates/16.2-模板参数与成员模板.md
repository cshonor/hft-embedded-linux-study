# 模板参数与成员模板

## 本节讲什么

本节讲解模板参数的多种形式：(1) **类型参数**（`typename T`）；(2) **非类型参数**（整型、指针等编译期常量）；(3) **默认模板实参**；(4) **成员模板**（类成员本身是模板）；(5) **`typename` 指明依赖类型**。这些是把模板从"简单泛型函数"扩展到"复杂泛型库"的基础工具。

> **一句话定位**：模板参数不只能传"类型"，还能传"编译期常量"；类成员也能是模板——这让模板能表达 `std::array<int, 10>` 这种"类型 + 大小"的泛型。

## 核心用法

### 1. 类型参数：`typename` vs `class`

```cpp
template <typename T> class A { };   // typename
template <class T> class B { };      // class —— 完全等价
```

两者等价，推荐 `typename`（更明确"这是个类型"）。`class` 在模板语境下不暗示必须是类类型——`int`、指针都行。

### 2. 非类型参数

模板参数可以是**非类型**的编译期常量——整型、指针、引用、`auto`（C++17）、`nullptr`：

```cpp
template <typename T, std::size_t N>   // N 是非类型参数（编译期常量）
class Array {
    T data_[N];
public:
    T& operator[](std::size_t i) { return data_[i]; }
    std::size_t size() const { return N; }
};
Array<int, 10> arr;          // 10 个 int 的数组，N=10 在编译期确定
Array<double, 100> darr;     // 不同 N 是不同类型，不能互相赋值
```

非类型参数的限制：
- 必须是**编译期常量表达式**（字面量、`constexpr` 变量、枚举）
- C++17 前类型只能是整型（含 `char`/`bool`/枚举）、指针、引用、`auto`（C++17 起）
- 浮点数：**C++20 起允许**（实测 clang 23.1.0：`template <double D> struct X {...}; X<1.5>{};` 在 `-std=c++20` 下编译通过；C++17 报 `a non-type template parameter cannot have type 'double' before C++20`）。C++20 之所以能放开，是把要求改成了"结构化类型"（成员公开、可 `==` 比较）——连某些字面类类型都能当非类型参数了
- 必须是 `const`——不能在运行期修改

```cpp
template <double D> class X { };   // C++17 ❌ / C++20 ✅（见上）
int n = 10;
Array<int, n> a;                   // ❌ 实测报 non-type template argument is not a constant expression
constexpr int N = 10;
Array<int, N> b;                   // ✅
```

### CE 实测：`std::array<T,N>` 的 N 为什么必须写进 `template<>`

> gcc 13.2 / clang 18.1.0，`-std=c++20 -O0`，两份源码输出逐字一致。

`std::array` 的第二个模板参数声明是 `template<typename _Tp, std::size_t _Nm>`——**长度是非类型参数，属于类型的一部分**，不是随对象走的值。所以「长度」只能出现在模板参数位置，三种写法实测：

| 写法 | 实测结果 |
|---|---|
| `template<class T, size_t N> void f(const std::array<T,N>&)` | ✅ N 自动推导：`N=3 / 5 / 4 / 8`；`std::array<float,4>` 也接得住（T 一起推导） |
| `void f(const std::array<int,6>&)` | ✅ 但只收 N=6，传别的长度直接失败 |
| `void f(const std::array<int, size_t N>&)` | ❌ 编译失败 |

第三种的错误原文（把机制直接说破了）：

```text
gcc 13.2    : error: template argument 2 is invalid
              error: invalid template-id
clang 18.1.0: error: type-id cannot have a name
              error: template argument for non-type template parameter must be an expression
              note: template parameter is declared here
                    array:93 | template<typename _Tp, std::size_t _Nm>
```

参数列表里的 `size_t N` 是**声明符**（在声明一个变量），而模板实参位置只接受**表达式**——两者不是同一种语法槽位，所以根本没法写进去。

**「不同 N 是不同类型」实测**：

```cpp
std::is_same_v<std::array<int,3>, std::array<int,5>>   // 0
std::is_same_v<std::array<int,3>, std::array<long,3>>  // 0
```

```text
want4(a3);   // want4 收 const std::array<int,4>&，传的是 std::array<int,3>
error: invalid initialization of reference of type 'const std::array<int, 4>&'
       from expression of type 'std::array<int, 3>'
```

#### ⚠️ 两个讲义里通常不提的坑

**坑 1：`array<T,N>` → `array<const T,N>` 没有隐式转换。**
`int*` 能转 `const int*`，但 `std::array<int,3>` 转不了 `std::array<const int,3>`——类模板不会自动给元素加 const：

```text
want_const_elem(a3);   // 形参写作 const std::array<const int,3>&
error: invalid initialization of reference of type 'const std::array<const int, 3>&'
       from expression of type 'std::array<int, 3>'
```

⇒ 固定长度形参就写 `const std::array<T,N>&`，让 `T` 自己推导；不要手写 `array<const T,N>` 去「加 const」，那反而把调用方全挡在外面。

**坑 2：形参引用上 `.size()` 不是常量表达式。**
`size()` 确实是 `constexpr` 成员函数，但 `arr` 是**形参引用**，编译期看不到它的值：

```cpp
static_assert(N == arr.size(), "...");   // ❌
```

```text
gcc 13.2    : error: non-constant condition for static assertion
              error: 'arr' is not a constant expression
clang 18.1.0: error: static assertion expression is not an integral constant expression
              note: function parameter 'arr' with unknown value cannot be used in a constant expression
```

⇒ 「N 和 `arr.size()` 等价」**只在运行期成立**。编译期要长度只能用 `N` 或 `std::tuple_size_v<std::array<T,N>>`。反过来，容器本身是 `constexpr` 对象时就没问题：`constexpr std::array<int,3> g{1,2,3}; static_assert(g.size() == 3);` ✅

#### ⭐ `N = 0` 是合法长度

```cpp
std::array<int, 0> a0{};
// 实测：a0.size() == 0，sizeof(a0) == 1，a0.data() == nullptr，a0.begin() == a0.end()
```

模板函数能正常接住 `N=0`（循环体一次不执行），但注意 `sizeof` 是 1 不是 0——任何完整对象类型至少占 1 字节。

### CE 实测：每个 N 一份代码，代价与收益

模板版 `sum_tmpl<N>` 用 N=3/5/8 各调一次，`-O0` 下目标文件里有三个独立符号：

```text
long sum_tmpl<3ul>(std::array<int, 3ul> const&)
long sum_tmpl<5ul>(std::array<int, 5ul> const&)
long sum_tmpl<8ul>(std::array<int, 8ul> const&)
sum_span(std::span<int const, 18446744073709551615ul>)     ← span 版只有这一个
```

但代码膨胀换来的不只是「多几份」，`-O2` 下优化质量差距明显：

| 调用 | 模板版（N 是编译期常量） | `std::span` 版（长度是运行期值） |
|---|---|---|
| N=3 | 完全展开，4 条 `movsx`+`add`，无循环 | 内联后 gcc 恢复出常量，同样展开 |
| N=5 | **完全展开**（12 条，无循环） | **仍是循环**：`lea rcx,[rdi+20]` + `cmp/jne` 回边 |
| N=8 | SIMD：`movdqu` + `pcmpgtd`/`paddq` | SIMD（同样向量化，但要先取长度） |

⇒ `N` 是编译期常量时，编译器知道确切迭代次数，能按 N 展开或向量化；把长度降级成 `std::span` 的运行期值后，**N=5 这一档就退化成循环了**。所以「模板版代码膨胀」不是纯缺点——热路径上它换来的是无分支、无回边的直线代码。

选型（HFT 视角）：

| 场景 | 选择 | 理由 |
|---|---|---|
| 长度固定且已知，热路径 | `template<class T, size_t N> f(const std::array<T,N>&)` | N 编译期常量 → 展开/向量化，零分支 |
| 长度固定，但函数体很大 | `f(std::span<const T, N>)`（静态 extent） | 只实例化一份，长度写错仍编译失败 |
| 长度运行期才定 | `f(std::span<const T>)` | 一份代码，代价是丢掉按 N 展开 |
| 长度要变 | `std::vector` | `std::array` 的 N 编译期定死，改不了 |

> `std::span` 是 **C++20** 起的：`-std=c++17` 下报 `'span' is not a member of 'std'` / `note: 'std::span' is only available from C++20 onwards`。

**补充**：`std::array` 支持 C++17 CTAD，`std::array a{1,2,3};` 推导为 `std::array<int,3>`（实测 `is_same_v<decltype(a), std::array<int,3>>` = 1），调用方连 `<int,3>` 都不用写——但 N 依旧是类型的一部分，只是由编译器补全。

### 3. 模板的默认实参

模板参数可以有默认值（类似函数默认实参）：

```cpp
template <typename T, typename Container = std::vector<T>>
class Stack {
public:
    void push(const T &v) { data_.push_back(v); }
private:
    Container data_;
};
Stack<int> s1;                           // Container 默认 vector<int>
Stack<int, std::deque<int>> s2;          // 显式指定 deque
```

默认实参从右向左匹配，所有带默认值的参数必须在参数列表末尾。C++11 起函数模板也支持默认实参。

### 4. 成员模板

类的成员本身可以是模板——这让类能"对某些类型提供泛型操作"：

```cpp
class Logger {
public:
    // 成员模板：可记录任意可输出类型
    template <typename T>
    void log(const T &v) {
        std::cout << v << "\n";
    }
};
Logger lg;
lg.log(42);          // T=int
lg.log("hello");     // T=const char*
lg.log(3.14);        // T=double
```

成员模板的典型应用：**智能指针的构造函数**。`unique_ptr<Derived>` 能转 `unique_ptr<Base>`，靠的就是构造函数是模板：

```cpp
template <typename T>
class unique_ptr {
public:
    unique_ptr() = default;
    // 接受其他类型 U 的指针，只要 U* 能转 T*
    template <typename U>
    unique_ptr(U *p) : ptr_(p) { }
private:
    T *ptr_ = nullptr;
};
class Base { virtual ~Base() = default; };
class Derived : public Base { };
unique_ptr<Base> p = new Derived();   // U=Derived, T=Base，Derived* 转 Base* 合法
```

### 5. 模板的模板参数

参数本身是一个模板（少用但强大）：

```cpp
template <typename T, template <typename> class Container>
class Stack {
public:
    void push(const T &v) { data_.push_back(v); }
private:
    Container<T> data_;    // Container 是模板，要传类型参数
};
Stack<int, std::vector> s;   // Container=vector，内部 vector<int>
```

注意 `template <typename> class Container`——`Container` 是"接受一个类型参数的模板"，不是具体类型。C++17 起可用 `typename` 替代 `class`（`template <typename> typename Container`）。

> 这种用法较少——通常直接传 `Container<T>` 作为类型参数更简单。模板模板参数主要用于需要"延迟绑定容器类型"的高级库设计。

### 6. typename 指明依赖类型

模板内部，某些名字依赖模板参数（如 `T::value_type`），编译器不知道它是类型还是变量——默认假设是变量。要告诉编译器"这是类型"，用 `typename` 前缀：

```cpp
template <typename Container>
void f(const Container &c) {
    // Container::value_type 是依赖类型——不知道 Container 是什么
    typename Container::value_type x = c.front();   // ✅ typename 指明是类型
    // Container::value_type x = ...;   // ❌ 编译器默认认为是变量名，报错
}
```

规则：**依赖模板参数的嵌套类型名，前面必须加 `typename`**。这是模板编程的常见陷阱。

例外：基类列表和成员初始化列表里不需要 `typename`（编译器已知那里是类型）。

### 7. using 模板别名（C++11）

`typedef` 无法给模板起别名，C++11 引入 `using`：

```cpp
template <typename T>
using Vec = std::vector<T, std::allocator<T>>;
Vec<int> v;   // 等价于 vector<int>
// 旧 typedef 做不到：
// template<typename T> typedef std::vector<T> Vec;  // ❌ 不合法
```

`using` 别名让模板代码更简洁，是现代 C++ 替代 `typedef` 的首选。

## 和 C 的区别

C 没有模板参数概念，要实现"类型 + 编译期大小"的泛型只能用宏：

| 维度 | C（宏 + void*） | C++ 模板参数 |
|------|---------------|------------|
| 编译期大小参数 | 宏 `#define ARRAY(T,N) T arr_##N[N]` | 非类型参数 `template<size_t N>` |
| 类型安全 | 无 | 编译期检查 |
| 不同大小是不同类型 | 宏展开后是同名数组 | `Array<int,10>` ≠ `Array<int,20>` |
| 默认容器 | 无 | 默认模板实参 |
| 成员泛型 | 无（C 结构体成员无模板） | 成员模板 |

### C 用宏模拟"类型 + 大小"泛型

```c
// C：宏模拟泛型数组
#define DEFINE_ARRAY(T, N) \
    typedef struct { T data[N]; size_t size; } T##_##N##_Array; \
    /* 等等，宏没法干净地做这个 */
// 实际 C 做法：用 void* + 运行期大小，放弃编译期类型安全
struct Array {
    void *data;
    size_t size;
    size_t elem_size;
};
void array_init(struct Array *a, size_t n, size_t es) {
    a->data = malloc(n * es);
    a->size = n;
    a->elem_size = es;
}
// 访问要强转 + 手动算偏移，无类型检查
```

```cpp
// C++：非类型参数
template <typename T, std::size_t N>
struct Array {
    T data[N];
    constexpr std::size_t size() const { return N; }
};
Array<int, 10> a;        // 编译期已知大小，类型安全
Array<double, 100> b;    // 不同类型，不能混用
```

C 的 `void*` 数组把类型信息丢了，访问靠 `memcpy` + 偏移；C++ 的非类型参数让大小成为类型的一部分，编译器全程类型检查。

> **HFT 视角**：`std::array<T, N>` 是非类型参数的典范——栈上固定大小数组，零堆分配，cache 友好。HFT 热路径上常用 `std::array<double, 64>` 替代 `std::vector<double>`，避免堆分配和扩容开销。

## 常见错误

### 错误 1：非类型参数用浮点数（C++17 及以前 ❌，C++20 起 ✅）

```cpp
template <double D> class X { };   // C++17 ❌ / C++20 ✅
```

⚠️ 本条下文与 §2 曾自相矛盾，这里以实测为准（gcc 13.2 与 clang 18.1.0 结论一致）：

```text
-std=c++17  gcc  : error: 'double' is not a valid type for a template non-type parameter
-std=c++17  clang: error: a non-type template parameter cannot have type 'double' before C++20
-std=c++20  gcc  : 编译通过，X<1.5>::value == 1.5
-std=c++20  clang: 编译通过，X<1.5>::value == 1.5
```

C++20 把非类型参数的要求从「整型/指针/引用」放宽成了「结构化类型」（成员公开、可 `==` 比较），浮点与某些字面类类型因此被放行。**替代**（在 C++17 及以前）：用整数 + 缩放（如用毫秒整数表示时间），或 `constexpr` 函数转换。

### 错误 2：忘记 `typename` 指明依赖类型

```cpp
template <typename T>
void f(T &c) {
    T::value_type x;        // ❌ 编译器认为 T::value_type 是变量名
    typename T::value_type y;   // ✅
}
```

依赖模板参数的嵌套类型，前加 `typename`。这是模板编程高频错误。

### 错误 3：默认实参顺序错误

```cpp
template <typename T = int, typename U>   // ❌ 带默认值的参数必须在后
class X { };
template <typename T, typename U = int>   // ✅
class Y { };
```

默认实参从右向左匹配，带默认值的必须在末尾。

### 错误 4：不同非类型参数值误以为是同一类型

```cpp
Array<int, 10> a;
Array<int, 20> b;
a = b;    // ❌ 不同类型，不能赋值
```

非类型参数是类型的一部分——`Array<int,10>` 和 `Array<int,20>` 是完全不同的类型。若需要"任意大小"，用 `std::vector`（运行期大小）。

标准库里最常撞上这条的就是 `std::array<T,N>`：`std::array<int,3>` 与 `std::array<int,5>` 是两个无关类型，所以「接收任意长度的 `std::array`」只能把 `N` 也写成模板参数（详见上文 CE 实测段）。

## 自测题

**1. 选择题**：以下哪个**不能**作为模板的非类型参数？

A. `int` 整型常量
B. `std::size_t` 常量
C. `double` 浮点常量
D. 指向外部对象的指针

<details>
<summary>答案</summary>

**C**（仅对 C++17 及以前成立）。整型（含 `size_t`）、枚举、指针、引用、`auto`（C++17）在 C++11 起就可以；浮点是 **C++20 才放开**的（见「错误 1」的实测）。若题目默认 C++17 标准，答案是 C；C++20 下四个选项全都能作非类型参数。

</details>

**2. 判断题**：在模板代码中，`Container::iterator` 这种形式（`Container` 是模板参数）必须写成 `typename Container::iterator` 才能作为类型使用。

<details>
<summary>答案</summary>

**对**。因为 `Container` 是模板参数，编译器不知道 `Container::iterator` 是类型还是静态成员变量——默认假设是变量。要作为类型使用，必须加 `typename` 前缀显式指明。例外：基类列表和成员初始化列表里不需要。

</details>

**3. 踩坑题**：以下代码哪里有问题？

```cpp
template <typename T, typename Container = std::vector<T>>
class Stack {
public:
    void push(const T &v) { data_.push_back(v); }
    T pop() { T v = data_.back(); data_.pop_back(); return v; }
private:
    Container data_;
};
Stack s;        // 使用
```

<details>
<summary>答案</summary>

`Stack s;` 没有指定任何模板实参。类模板**不能**像函数模板那样完全推断——即使有默认实参，也至少要写 `<>` 或依赖 CTAD（但这里没有能推断的构造函数）。

**修复**：
```cpp
Stack<int> s;                    // ✅ T=int, Container=vector<int>（默认）
Stack<int, std::deque<int>> s2;  // ✅ 显式指定
```
C++17 CTAD 也救不了这种场景（构造函数不涉及 `T`），仍需显式写 `Stack<int>`。

</details>

**4. 应用题**：用模板实现一个 `FixedBuffer<T, N>`，N 是编译期大小，要求：
- 栈上数组存储 N 个 T
- `push(v)` 添加（满则忽略）
- `size()` 返回当前元素数
- `capacity()` 返回 N（constexpr）

<details>
<summary>答案</summary>

```cpp
#include <cstddef>
template <typename T, std::size_t N>
class FixedBuffer {
public:
    void push(const T &v) {
        if (count_ < N) data_[count_++] = v;
    }
    std::size_t size() const { return count_; }
    static constexpr std::size_t capacity() { return N; }   // 编译期常量
    const T& operator[](std::size_t i) const { return data_[i]; }
private:
    T data_[N];              // 栈上数组，编译期大小
    std::size_t count_ = 0;
};
// 用法：
FixedBuffer<int, 16> buf;
for (int i = 0; i < 20; ++i) buf.push(i);   // 只存前 16 个
static_assert(FixedBuffer<int,16>::capacity() == 16, "");  // 编译期检查
```

要点：非类型参数 `N`、`static constexpr capacity()` 可编译期求值、栈上数组零堆分配、`static_assert` 验证。这是 HFT 热路径的典型模式。

</details>

**5. 踩坑题**：想写一个「接收任意长度 `std::array`」的函数，下面三种写法各是什么结果？

```cpp
// (a)
template <class T, std::size_t N> void f(const std::array<T, N>& a);
// (b)
void f(const std::array<int, 6>& a);
// (c)
void f(const std::array<int, std::size_t N>& a);
```

<details>
<summary>答案</summary>

- **(a) ✅ 正确**，也是唯一能接任意长度的写法。`N` 与 `T` 一起由编译器推导，`std::array<int,3>`、`std::array<float,4>` 都能传。
- **(b) ✅ 能编译**，但只收 `N=6`；传 `std::array<int,3>` 报 `invalid initialization of reference of type 'const std::array<int, 4>&' from expression of type 'std::array<int, 3>'`。
- **(c) ❌ 编译失败**。参数列表里的 `std::size_t N` 是**声明符**（在声明一个变量），而模板实参位置只接受**表达式**，两者不是同一种语法槽位：

```text
gcc 13.2     : error: template argument 2 is invalid
               error: invalid template-id
clang 18.1.0 : error: type-id cannot have a name
               error: template argument for non-type template parameter must be an expression
```

一句话：**长度属于类型，就只能出现在 `template<...>` 里。**

</details>

**6. 判断题**：`std::array::size()` 是 `constexpr` 成员函数，所以在模板函数里写 `static_assert(N == arr.size(), "")` 一定成立。

<details>
<summary>答案</summary>

**错**。`size()` 确实是 `constexpr`，但 `arr` 是**形参引用**——编译期看不到它的值，整个表达式不是常量表达式：

```text
gcc 13.2     : error: non-constant condition for static assertion
               error: 'arr' is not a constant expression
clang 18.1.0 : error: static assertion expression is not an integral constant expression
               note: function parameter 'arr' with unknown value cannot be used in a constant expression
```

⇒ 「`N` 和 `arr.size()` 等价」**只在运行期成立**。编译期要长度用 `N` 或 `std::tuple_size_v<std::array<T,N>>`。反过来，容器本身是 `constexpr` 对象时就没问题：`constexpr std::array<int,3> g{1,2,3}; static_assert(g.size() == 3);` ✅

</details>

## 可跑的例子

**`examples/16.2-template-params.cpp`** —— 编译期定尺寸的环形缓冲。

```bash
clang++ -std=c++20 examples/16.2-template-params.cpp -o /tmp/demo && /tmp/demo
```

真实输出（节选）：

```
4 槽环形缓冲: 装了 6 个后 count = 4（旧的被覆盖）
1024 槽环形缓冲: count = 1

sizeof(RingBuffer<long,4>)    = 48
sizeof(RingBuffer<long,1024>) = 8208
```

**看出什么了？** N 不是类型而是编译期常量，尺寸直接烙进类型：48 字节 vs 8208 字节，是两个**不同类型**——4 槽缓冲赋给 1024 槽变量直接编译失败。数据内嵌在对象里，一次堆分配都没有。

> 行情窗口、滑点统计、固定槽位对象池全是这个形状。编译期尺寸换来的：零堆分配、无间接寻址、优化器可利用的边界信息。

**`examples/16.2-array-nttp.cpp`** —— 非类型参数作形参的三种写法（`std::array<T,N>` 的 N）。

```bash
g++ -std=c++20 -Wall -Wextra examples/16.2-array-nttp.cpp -o /tmp/demo && /tmp/demo
```

真实输出（gcc 13.2 与 clang 18.1.0 逐字一致，`-Wall -Wextra` 下 0 诊断）：

```text
N=3 size=3  1 2 3
N=5 size=5  10 20 30 40 50
N=4 size=4  1 2 3 4
N=8 size=8  1 2 3 4 5 6 7 8
fixed size=6
same type (3 vs 5)?      0
same type (int,3 vs long,3)? 0
N=0: size=0 sizeof=1 data=(nil) begin==end? 1
N=0 size=0
CTAD: is array<int,3>? 1  N=3
sum_tmpl(a1)=6 sum_tmpl(a4)=36 sum_span(a2)=150
sizeof(array<int,256>)=1024
```

**看出什么了？** 同一个 `show_array` 接住了 `int/3`、`int/5`、`float/4`、`int/8`、`int/0` 五种长度——N 由编译器推导，调用方一个字都不用传。文件末尾注释里另附三个**反例**的错误原文（把 `N` 写进参数列表、形参引用上用 `.size()` 做 `static_assert`、`array<T,N>`→`array<const T,N>`），取消注释即可复现。
