# 定义模板

## 本节讲什么

本节讲解 C++ 模板的基础——**函数模板**和**类模板**：如何用 `template <typename T>` 定义泛型函数和泛型类，编译期如何根据使用实例化出具体版本，以及模板的编译模型（为什么模板代码通常要放在头文件里）。这是 C++ 泛型编程的起点，也是 C++ 相对 C 最强大的特性之一——**编译期多态 + 类型安全 + 零运行开销**。

> **一句话定位**：模板 = "写一份代码，编译器为每种类型生成一份定制版本"。它是 `void*` 和宏的安全替代品，既类型安全又能内联优化。

## 核心用法

### 1. 函数模板

```cpp
template <typename T>
T maximum(const T &a, const T &b) {
    return a > b ? a : b;     // 要求 T 支持 operator>
}
int main() {
    std::cout << maximum(3, 7) << "\n";          // T=int，调用 maximum<int>
    std::cout << maximum(3.14, 2.71) << "\n";    // T=double
    std::cout << maximum(3, 7.0) << "\n";        // ❌ 推断冲突：T 既是 int 又是 double
    std::cout << maximum<double>(3, 7.0) << "\n";// ✅ 显式指定 T=double，3 转 double
}
```

关键点：
- `template <typename T>` 声明一个类型参数 `T`（`typename` 和 `class` 等价，但推荐 `typename`）
- 调用时编译器从实参**推断** `T` 的类型，生成对应版本（实例化）
- 模板代码**隐式要求** `T` 支持所用操作（这里是 `operator>`），不支持则编译错误
- 推断冲突时需**显式指定**模板实参：`maximum<double>(3, 7.0)`

### 1.1 别把 `template<>` 当成模板的"开头标记"

新手常把这两件事混为一谈：

| 写法 | 含义 |
|---|---|
| `template <typename T>` / `template <class T>` | **主模板**的开头——尖括号里**必须有内容**（类型参数或非类型参数） |
| `template <>` | 尖括号是**空的**，它是**全特化**的开头：为某个具体类型替换掉通用实现 → [16.4 §6 全特化](./16.4-高级特性.md) |

```cpp
template <typename T> bool eq(T a, T b) { return a == b; }            // 主模板
template <> bool eq<const char*>(const char* a, const char* b) {       // 全特化：空实参列表
    return std::strcmp(a, b) == 0;    // 比内容而不是比指针
}
eq(1, 1);          // 主模板   → true
eq("ab", "ab");    // 特化版   → true（实测 11，两个都成立）
```

也就是说：`template<>` 的出现意味着"我已经知道具体类型了，别用通用版"，**不是**写模板的固定起手式。写主模板一律 `template <typename T>`（`typename` 与 `class` 在这里完全等价，`typename` 更表意）。

### 1.2 模板的"鸭子类型"：约束只看你实际用到了什么（实测）

模板对 `T` 没有任何"必须继承谁、必须实现哪个接口"的声明式要求——它只在你实例化那一刻，逐条检查模板体里用到的操作是否成立。这就是编译期的**结构化约束**（俗称鸭子类型）：

```cpp
template <typename T> void print(T x) { std::cout << x << "\n"; }   // 用到了 <<
```

- 传 `int` → ✅ 内置插入器
- 传 `Student` 但**没**重载 `operator<<` → ❌ 实测报错：
  `error: invalid operands to binary expression ('ostream' and 'Student')`
- 补上 `std::ostream& operator<<(std::ostream&, const Student&)` → ✅ 立刻通过

同理，模板体里写 `a > b`，`T` 就必须有 `operator>`；写 `a == b` 就必须有 `operator==`。**没用到的操作不会被检查**——`maximum` 模板即使 `T` 没有 `operator<`，只要不实例化就不报错。

**还有一层常被漏掉：不只要求运算符"存在"，还要求它的结果类型对得上。**

```cpp
template <typename T> T add(T a, T b) { return a + b; }
```

传 `Student` 进去，光有 `operator+` 不够——`add` 的返回类型是 `T = Student`，所以 `a + b` 的结果必须能转回 `Student`。若把 `operator+` 写成返回 `int`：

```
error: no viable conversion from returned value of type 'int' to function return type 'Student'
```

改成 `Student operator+(const Student&, const Student&)` 就通过了（实测输出 `张三李四,38`）。**模板的约束是"整个表达式链"成立，不只是"那个符号找得到"**——这也是模板报错信息能长到吓人的原因之一。

> 与别的语言对比：Rust 的 `trait bound` / C# 的 `where T : IComparable` 是**声明式**的（签名处写明要求，报错在调用点且信息清晰）；C++ 模板是**结构化**的（要求隐含在代码里，报错落在模板内部、可能很深）。C++20 的 `concept` 就是把这份隐式约束提到签名上，兼具两者（见 [16.4](./16.4-高级特性.md)）。

### 1.3 `template` 只是一个"标签"，只贴在紧跟着的那一个声明上

把 `template <typename T>` 理解成**贴在下一个声明头上的标签**最省事——它本身既不是函数也不是类，也不"管辖"后面的代码：

```cpp
template <typename T>
T maximum(T a, T b) { return a > b ? a : b; }   // ← 模板：被上面那行标签管着

void hello() { std::cout << "hello\n"; }        // ← 普通函数，完全不受影响
```

所以"后面跟函数 → 函数模板、后面跟 `class`/`struct` → 类模板"这句话成立的前提是**紧跟着**。标签与声明之间插个空行没事（空白不算声明），插个别的声明就断了。

**类模板的成员函数：类内不写第二遍，类外必须写回来**（实测 clang 23.1.0）：

```cpp
template <typename T>
class Box {
public:
    T value;
    void set(T v) { value = v; }     // ✅ 类内：跟着类走，不能再写 template
};

template <typename T>                // ← 类外定义：这一行不能省
void Box<T>::set(T v) { value = v; }
```

类外定义漏掉 `template <typename T>` 会被编译器理解成"你要写特化"，实测报错：

```
error: template specialization requires 'template<>'
    3 | void Box<int>::set(int v) { value = v; }
      |      ~~~~~~~~  ^
      | template<>
```

——正好反证 §1.1：`template<>` 在编译器眼里就是"特化"的记号，不是通用起手式。

**别把两件事混为一谈**（名字只差几个字）：

| 名称 | 写法 | 含义 |
|---|---|---|
| 类模板的成员函数 | `void set(T v)`，类内直接写 | `T` 是**类的**参数，函数只是跟着类实例化 |
| 成员模板 | 成员函数**自己再开一层** `template <typename U>` | `U` 是**函数的**参数，独立于类的 `T` |

```cpp
template <typename T>
class Box {
public:
    T value;
    template <typename U>                      // ← 成员模板：多一层
    void assign(const U& u) { value = static_cast<T>(u); }
};
Box<int> b; b.assign(3.9);   // 类参数 T=int，函数参数 U=double，实测 b.value = 3
```

成员模板是 `std::shared_ptr` 能从 `shared_ptr<Derived>` 构造出 `shared_ptr<Base>` 的那一类机制，详见 [16.2 模板参数与成员模板](./16.2-模板参数与成员模板.md)。

### 1.4 函数模板 vs 类模板：用法对照速查

两者共用同一套 `template <typename T>` 语法，差别全在**怎么用**：

| | 函数模板 | 类模板 |
|---|---|---|
| 写法 | `template <typename T>` + 函数 | `template <typename T>` + `class`/`struct` |
| 怎么用 | `print(100)` / `print<int>(50)` | `Box<int> b;` —— **类型必须写在尖括号里** |
| 能否自动推导 | ✅ 能（从实参推 `T`），尖括号可省 | C++17 前 ❌ 必须手写 `<T>`；C++17 起 CTAD 可从构造函数推（见 §3） |
| 显式指定的用途 | 强制类型 / 让实参做一次隐式转换（见 [16.3 §2](./16.3-模板实参推断.md)） | 本来就要写，谈不上"省" |
| 典型代表 | `std::max`、`std::sort` 里的比较器 | `std::vector<T>`、`std::optional<T>` |

共同点（两条都成立）：

1. **模板本身不生成任何机器码**——只有真正被用到（`print(10)`、`Box<int>`）才实例化出对应版本；没用到的类型组合连检查都不会做。
2. **定义一般整体放头文件**——实例化时必须看得见完整函数体（见 §5）。

### 2. 类模板

```cpp
template <typename T>
class Stack {
public:
    void push(const T &v) { data_.push_back(v); }
    T pop() {
        T v = data_.back();
        data_.pop_back();
        return v;
    }
    bool empty() const { return data_.empty(); }
private:
    std::vector<T> data_;
};
int main() {
    Stack<int> si;        // ✅ 类模板必须显式指定类型（不像函数模板能推断）
    si.push(1); si.push(2);
    std::cout << si.pop() << "\n";    // 2
    Stack<std::string> ss;
    ss.push("hello");
}
```

关键点：
- 类模板**必须显式指定**模板实参（`Stack<int>`），编译器不从构造函数推断（C++17 的 CTAD 例外，见下）
- 类模板名 `Stack` 本身不是类型，`Stack<int>` 才是类型——在类模板内部，`Stack` 可简写（指代 `Stack<T>`），外部必须写全
- 类模板的成员函数也是模板，定义在类外时要带完整模板声明：
  ```cpp
  template <typename T>
  void Stack<T>::push(const T &v) { data_.push_back(v); }
  ```

### 3. C++17 类模板参数推断（CTAD）

C++17 起，若构造函数能推断出模板参数，可省略 `<T>`：

```cpp
template <typename T>
struct Point {
    T x, y;
    Point(T x_, T y_) : x(x_), y(y_) { }
};
Point p(3, 4);        // C++17：推断 Point<int>（等价于 Point<int> p(3,4)）
Point q(3.0, 4.0);    // Point<double>
```

但许多场景仍需显式指定（如 `Stack`，因为构造函数不涉及 `T`）。

### 4. 模板实例化（编译期）

模板本身不是代码，是"代码生成器"。编译器看到 `maximum(3, 7)` 时：

1. 推断 `T = int`
2. **实例化**：把模板里的 `T` 替换为 `int`，生成一份 `maximum<int>` 的真实代码
3. 编译这份生成的代码

实例化是**按需**的——只有实际用到的类型组合才会生成代码。没用到的 `maximum<std::string>` 不会生成（即使 `std::string` 没有 `operator>`，也不会报错，因为根本没实例化）。

```
源代码                    编译器实例化             最终二进制
template<typename T>      maximum<int>(...)        maximum<int> 代码
T maximum(...)  ────┬──→ maximum<double>(...) ──→ maximum<double> 代码
                    └──→ (未用类型不生成)
```

### 5. 模板的编译模型（为什么放头文件）

模板代码通常**必须放在头文件**里，原因：

- 模板实例化发生在**使用它的那个 .cpp 文件**中
- 编译器需要看到模板的完整定义才能生成实例化代码
- 若模板定义在 .cpp 里，其他 .cpp 包含头文件只能看到声明，无法实例化 → 链接错误

```cpp
// stack.h
template <typename T>
class Stack {
public:
    void push(const T &v);     // 声明
    T pop();
private:
    std::vector<T> data_;
};
// ❌ 错误：定义放 .cpp
// stack.cpp: template<typename T> void Stack<T>::push(...) { ... }
// main.cpp: Stack<int> s; s.push(1);  → 链接错误：找不到 Stack<int>::push

// ✅ 正确：定义放头文件
// stack.h:
template <typename T>
void Stack<T>::push(const T &v) { data_.push_back(v); }
```

> **例外**：可以在 .cpp 里**显式实例化**（`template class Stack<int>;`），让编译器为特定类型生成代码。但泛型库通常不用这招，直接放头文件。

### 6. 模板的两阶段检查

模板代码分两阶段检查：

1. **定义阶段**：检查与模板参数无关的错误（语法、拼写、未声明的名字）
2. **实例化阶段**：检查与模板参数相关的错误（`T` 是否支持 `operator>`）

```cpp
template <typename T>
void f(T x) {
    y = x;          // ❌ 第一阶段：y 未定义（不依赖 T）
    x.nonexist();   // 第一阶段不报（依赖 T），第二阶段（实例化时）若 T 无 nonexist 才报
}
```

这就是为什么模板错误信息常常又长又深——要到实例化时才暴露依赖 `T` 的错误。

## 和 C 的区别

C 没有模板，泛型编程只能靠 `void*` 或宏——都不类型安全：

| 维度 | C（void* + 宏） | C++ 模板 |
|------|---------------|---------|
| 类型安全 | 无（`void*` 任意转换） | 编译期检查 |
| 性能 | 函数指针间接调用，难内联 | 每类型独立代码，可内联 |
| 错误时机 | 运行期崩溃 | 编译期错误 |
| 代码膨胀 | 无（一份代码） | 每类型一份（按需生成） |
| 抽象能力 | 弱（无法表达"T 要支持某操作"） | 强（概念、SFINAE） |

### C 用 `void*` 实现泛型栈（对比）

```c
// C：void* 实现泛型栈——不类型安全
struct Stack {
    void *data[100];
    int top;
};
void push(struct Stack *s, void *v) { s->data[s->top++] = v; }
void *pop(struct Stack *s) { return s->data[--s->top]; }
// 用：
struct Stack s = {0};
int x = 42;
push(&s, &x);            // 存的是 int* 的地址
char *str = "hello";
push(&s, str);           // 存的是 char*——和 int* 混在一起！
int *p = (int*)pop(&s);  // ❌ 取出 char* 强转 int*，运行期崩溃
```

```cpp
// C++：模板实现——类型安全
template <typename T>
class Stack {
    std::vector<T> data_;
public:
    void push(const T &v) { data_.push_back(v); }
    T pop() { T v = data_.back(); data_.pop_back(); return v; }
};
Stack<int> si;           // 只能存 int
si.push(42);
si.push("hello");        // ❌ 编译错误：const char* 不能转 int——编译期挡住
```

C 的 `void*` 栈把不同类型指针混存，运行期崩溃；C++ 模板栈每种类型独立，编译期就挡住类型错误。

> **宏 vs 模板的正面对比**（含 `SQUARE(a+1)`、`MAX(x++,y)` 双求值的实测触发条件）见 [Effective C++ 条款 2](../../../../04-cpp/M6-Classic-Effective/01-Effective-C++/ch01-accustom-yourself/item02-尽量以const、enum、inline替换#define.md)——宏是预处理期纯文本替换，模板是编译期类型感知的代码生成，这是两者最本质的分界。

> **HFT 视角**：模板的内联能力是热路径性能关键。`std::sort` 模板版比 C 的 `qsort` 快几倍——因为 `qsort` 通过函数指针调比较函数（无法内联），而 `std::sort` 的比较器是模板参数，编译器完全内联，省去每次调用的间接跳转 + 参数压栈。这是 C++ 在数值计算上常胜 C 的核心原因之一。

## 常见错误

### 错误 1：模板定义放 .cpp → 链接错误

```cpp
// stack.h
template <typename T> class Stack { void push(const T&); };
// stack.cpp
template <typename T> void Stack<T>::push(const T &v) { /*...*/ }
// main.cpp
Stack<int> s; s.push(1);   // ❌ undefined reference to Stack<int>::push
```

**修复**：把模板成员函数定义放头文件，或显式实例化。这是模板新手第一大坑。

### 错误 2：模板参数 `T` 不支持所需操作

```cpp
template <typename T>
T maximum(const T &a, const T &b) { return a > b ? a : b; }
struct Point { int x, y; };    // 没有 operator>
maximum(Point{1,2}, Point{3,4});   // ❌ 实例化时报错：no match for operator>
```

错误信息可能很深，但核心是 `T` 不满足模板隐式要求。**修复**：给 `Point` 重载 `operator>`，或用 C++20 概念（concept）明确要求。

### 错误 3：类模板名当类型用

```cpp
template <typename T> class Stack { /*...*/ };
Stack s;            // ❌ Stack 不是类型，Stack<T> 才是
Stack<int> s;       // ✅
```

在类模板内部 `Stack` 可简写（指代 `Stack<T>`），但外部必须写全 `Stack<T>`。

### 错误 4：函数模板实参推断冲突

```cpp
template <typename T>
T maximum(const T &a, const T &b) { return a > b ? a : b; }
maximum(3, 7.0);    // ❌ T 既是 int 又是 double
```

**修复**：显式指定 `maximum<double>(3, 7.0)`，或定义两个类型参数的版本。

### 错误 5：`using namespace std;` 时自己写 `max` 会撞车（实测）

```cpp
#include <iostream>
using namespace std;
template<typename T> T max(T a, T b) { return a > b ? a : b; }
cout << max(3, 5);      // ❌ error: call to 'max' is ambiguous
```

实测 clang 报 `call to 'max' is ambiguous`，并同时列出两个候选：你的 `::max(T, T)` 和标准库的 `std::max(const _Tp&, const _Tp&)`——`using namespace std;` 把 `std::max` 拉进了同一个候选集，两者推断结果一样好，谁都压不过谁。

**修复**三选一：① 别 `using namespace std;`（写 `std::cout`）；② 换个名字（教学代码里叫 `mymax`）；③ 显式调用 `::max(3,5)` 限定全局版本。这个坑不只 `max`——`min`、`swap`、`distance`、`count` 等常见名字都在 `std` 里有同款。

## 自测题

**1. 选择题**：以下关于模板实例化的说法，正确的是？

A. 模板定义时编译器就生成所有类型的代码
B. 模板只有被使用（调用/实例化）时才生成对应类型的代码
C. 模板代码放在 .cpp 文件里，其他文件 include 头文件就能用
D. 模板实例化发生在链接期

<details>
<summary>答案</summary>

**B**。模板是"代码生成器"，按需实例化——只有实际用到的类型组合才生成代码。这也解释了为什么没用到的类型即使不满足模板要求也不报错（没实例化）。实例化在编译期，不是链接期；模板定义通常放头文件（C 错）。

</details>

**2. 判断题**：类模板可以像函数模板那样，让编译器从构造函数实参推断模板参数（无需写 `<T>`）。

<details>
<summary>答案</summary>

**部分对**（C++17 起）。C++17 的 CTAD（Class Template Argument Deduction）允许在构造函数能推断时省略 `<T>`，如 `std::pair p(1, 2.0)` 推断为 `pair<int,double>`。但许多场景构造函数不涉及 `T`（如 `Stack` 的默认构造），仍需显式 `Stack<int>`。所以不能一概而论。

</details>

**3. 踩坑题**：以下代码哪里有问题？

```cpp
// vec.h
template <typename T>
class Vec {
public:
    void push(const T &);
    T get(int);
private:
    T *data_;
};
// vec.cpp
#include "vec.h"
template <typename T>
void Vec<T>::push(const T &v) { /* ... */ }
template <typename T>
T Vec<T>::get(int i) { return data_[i]; }
// main.cpp
#include "vec.h"
int main() {
    Vec<int> v;
    v.push(42);
}
```

<details>
<summary>答案</summary>

模板成员函数定义放在 `vec.cpp` 里，`main.cpp` 包含 `vec.h` 只能看到声明，无法实例化 `Vec<int>::push` → 链接错误（undefined reference）。

**修复方案二选一**：
1. 把成员函数定义移到 `vec.h`（推荐，泛型库标准做法）
2. 在 `vec.cpp` 末尾显式实例化：`template class Vec<int>;`（只对已知类型有效，失去泛型性）

</details>

**4. 踩坑题**：`print(s1)`（`s1` 是自定义 `Student` 对象）能否编译，取决于什么？模板里是 `cout << x`。

<details>
<summary>答案</summary>

取决于 `Student` **有没有重载 `operator<<`**——就这一件事，与它继承谁、是不是 POD 无关。

```cpp
std::ostream& operator<<(std::ostream& os, const Student& s);   // 有这条就过
```

没有的话实测报 `error: invalid operands to binary expression ('ostream' and 'Student')`。这正是模板的"鸭子类型"：约束是**结构化**的，只检查模板体里实际用到的操作。模板体里换一个运算符，要求就变了——写 `a > b` 就要 `operator>`，写 `a == b` 就要 `operator==`。

</details>

**5. 应用题**：用模板实现一个泛型 `Pair<T1, T2>`，存储两个可能不同类型的值，提供 `first()`/`second()` 访问。要求能 `Pair<int, double> p(1, 2.0);` 使用。

<details>
<summary>答案</summary>

```cpp
template <typename T1, typename T2>
class Pair {
public:
    Pair(const T1 &a, const T2 &b) : first_(a), second_(b) { }
    const T1& first() const { return first_; }
    const T2& second() const { return second_; }
private:
    T1 first_;
    T2 second_;
};
// 用法：
Pair<int, double> p(1, 2.0);
std::cout << p.first() << ", " << p.second();   // 1, 2.0
// C++17 CTAD：Pair p(1, 2.0);  也可
```

要点：两个类型参数 `T1`/`T2`、构造函数初始化、`const&` 返回避免拷贝、`const` 成员函数。

</details>

**6. 判断题**：下面三处，`template` 该写还是不该写？

```cpp
template <typename T>
class Box {
public:
    T value;
    void set(T v) { value = v; }        // ① 这里要不要再写 template？
    template <typename U>               // ② 这行是什么？
    void assign(const U& u) { value = static_cast<T>(u); }
};

/* ③ */ void Box<int>::set(int v) { value = v; }   // ③ 这样写行不行？
```

<details>
<summary>答案</summary>

- **① 不要写**。`set` 是类模板的成员函数，`T` 来自类，类内定义跟着类走。写了反而错（嵌套模板参数非法）。
- **② 这是成员模板**：`U` 是**函数自己的**参数，和类的 `T` 相互独立。`Box<int> b; b.assign(3.9);` → `T=int`、`U=double`，实测 `b.value = 3`。
- **③ 不行，漏了 `template <typename T>`**（而且 `Box<int>::` 也会让它被当成特化）。实测报错 `error: template specialization requires 'template<>'`。正确写法是补齐模板头并写 `Box<T>::`：

```cpp
template <typename T>
void Box<T>::set(T v) { value = v; }
```

一句话记：**类内不写，类外补回来；多一层 `U` 才是成员模板。**

</details>

**7. 踩坑题**：`template <typename T> T add(T a, T b) { return a + b; }`，传两个 `Student` 进去想编译通过，要重载哪个运算符？还有别的隐含要求吗？

<details>
<summary>答案</summary>

要重载 **`operator+`**（非成员 `Student operator+(const Student&, const Student&)` 或成员版均可）。

但不止这一条——`add` 的返回类型是 `T = Student`，所以 `a + b` 的结果**必须能转回 `Student`**。若 `operator+` 返回 `int`，实测：

```
error: no viable conversion from returned value of type 'int' to function return type 'Student'
```

另外 `T add(T a, T b)` 是**按值**传参和返回，`Student` 还得可拷贝（或可移动）。

这正是 §1.2 说的：模板的约束是**整个表达式链**成立，不是"那个符号找得到"就行。对比第 4 题的 `print`（`cout << x`）——那边只要求 `operator<<` 存在，因为返回类型是 `void`，没有结果类型要对齐。

</details>

## 可跑的例子

**`examples/16.1-templates.cpp`** —— 证明编译器真的生成了两份代码。

```bash
clang++ -std=c++20 examples/16.1-templates.cpp -o /tmp/demo && /tmp/demo
```

真实输出（节选）：

```
调用 max_of(3, 7):
  实例化自: T max_of(const T &, const T &) [T = int]
  结果 = 7
调用 max_of(1.5, 2.5):
  实例化自: T max_of(const T &, const T &) [T = double]
  结果 = 2.500000
```

**看出什么了？** `__PRETTY_FUNCTION__` 直接展示每次调用的实例身份：`[T = int]` 和 `[T = double]` 是**两份不同的代码**。`max_of(3, 1.5)` 则编译失败——T 只有一个，签不下两个类型（例子里留了注释）。Counter<int> 和 Counter<double> 互不相干也同理。

> 模板不是"一份代码"，是"一个代码工厂"。滥用实例化会撑大二进制——模板膨胀的定量起点。
