# 高级特性

## 本节讲什么

本节讲解模板的三个进阶特性：(1) **模板重载**——函数模板可以像普通函数一样重载；(2) **可变参数模板**（variadic template）——接受任意数量任意类型的参数，是 `std::make_unique`/`printf` 类型安全版的基础；(3) **模板特例化**（specialization）——为特定类型提供定制实现。这是把模板从"简单泛型"推向"复杂元编程"的门槛。

> **一句话定位**：可变参数模板 = "类型安全的 `printf`"；特例化 = "这个类型我单独写一份更好的实现"。

## 核心用法

### 1. 函数模板重载

函数模板可以与普通函数、其他模板重载，编译器按"最特化"原则选择：

```cpp
template <typename T>
void f(T) { std::cout << "template\n"; }       // 通用模板
void f(int) { std::cout << "int\n"; }          // 非模板重载
void f(double) { std::cout << "double\n"; }    // 另一个非模板重载

f(42);        // int（非模板精确匹配，与模板 T=int 打平 → 平手时非模板赢）
f(3.14);      // double（同上）
f("hi");      // template（int/double 接不住 const char*，只剩模板可行）
f('a');       // template（模板 T=char 精确匹配，赢过 int/double 需要的类型提升）
```

**⚠️ 一个流传很广的错误说法**："优先选普通函数；普通函数匹配不上，才去尝试实例化模板。"——**顺序说反了**。真实规则是两步（实测 clang 23.1.0）：

1. **先比匹配好坏**：非模板和所有模板实例**一起进候选集**，比的是谁的实参转换更少（精确 > 提升 > 标准转换 > 自定义转换）。
2. **打平了才偏袒非模板**：转换序列相同的情况下，非模板胜出。

所以模板完全可能**赢过**存在的非模板函数：

```cpp
template <typename T> void foo(T x) { /* ... */ }
void foo(double x) { /* ... */ }

foo(5.5);     // 普通 double —— 两边都是精确匹配，打平，非模板赢
foo(5.5f);    // 模板 T=float —— 精确匹配，赢过 float→double 的转换！
foo(5);       // 模板 T=int   —— 同上
```

实测输出：

```
foo(5.5)   → 普通  double
foo(5.5f)  → 模板  T=void foo(T) [T = float]
foo(5)     → 模板  T=void foo(T) [T = int]
```

想**强制**走模板（哪怕有非模板精确匹配），用尖括号显式实例化：`print<int>(100)`——一旦写了 `<...>`，编译器只在模板里挑，非模板直接出局（实测 `print(100)` 走非模板、`print<int>(100)` 走模板）。

**顺带一条名词边界的实测**：非模板 class 和同名函数可以共存（C 遗留的 tag 命名空间，POSIX 的 `struct stat` + `stat()` 就是这么工作的）：

```cpp
struct Thing { int v; };
void Thing() {}                 // ✅ 合法；引用类要写 struct Thing
```

但**类模板**不行：

```cpp
template <typename T> struct Thing { T v; };
void Thing() {}                 // ❌ error: redefinition of 'Thing' as different kind of symbol
```

「模板重载」只发生在**函数**模板之间（以及函数模板与非模板函数之间）；类模板靠特化定制，不参与重载。

### 2. 可变参数模板

C++11 起，模板可接受**参数包**（parameter pack）——零个或多个参数：

```cpp
template <typename... Args>           // Args 是类型参数包
void f(Args... args);                 // args 是函数参数包
f();                                  // 0 个参数
f(1, 2, 3);                           // 3 个 int
f(1, "hello", 3.14);                  // int, const char*, double
```

`sizeof...(args)` 返回参数个数（编译期常量）：
```cpp
template <typename... Args>
void f(Args... args) {
    std::cout << sizeof...(args) << " args\n";
}
f(1, 2, 3);   // 3 args
```

### 3. 递归展开参数包

参数包不能直接遍历，经典做法是**递归** + 基础情形：

```cpp
// 递归终止基础情形：0 个参数
void print() { std::cout << "\n"; }

// 递归版本：取第一个，递归处理剩余
template <typename T, typename... Rest>
void print(const T &first, const Rest&... rest) {
    std::cout << first << " ";
    print(rest...);    // 递归调用，参数包少一个
}
print(1, "hello", 3.14);   // 输出 "1 hello 3.14\n"
// 调用链：print(1,"hello",3.14) → print("hello",3.14) → print(3.14) → print()
```

每次递归剥离第一个参数，直到参数包为空，命中基础情形 `print()` 终止。

### 4. C++17 折叠表达式（fold expression）

C++17 起用折叠表达式简化参数包展开：

```cpp
// 一元右折叠：对每个参数调用 f
template <typename... Args>
void print(const Args&... args) {
    ((std::cout << args << " "), ...);    // 折叠表达式
}
print(1, "hello", 3.14);   // 1 hello 3.14

// 求和：
template <typename... Args>
auto sum(Args... args) {
    return (args + ...);    // 折叠加法：((a1+a2)+a3)+...
}
sum(1, 2, 3, 4);    // 10
```

折叠表达式四种形式：
- `(args op ...)` —— 一元右折叠：`a1 op (a2 op (... op aN))`
- `(... op args)` —— 一元左折叠：`((a1 op a2) op ...) op aN`
- `(args op ... op init)` —— 二元右折叠（带初值）
- `(init op ... op args)` —— 二元左折叠（带初值）

```cpp
template <typename... Args>
auto sum(Args... args) { return (0 + ... + args); }   // 二元左折叠，初值 0
sum();   // 0（空包，二元折叠有初值不报错）
```

### 5. 可变参数模板的应用：类型安全 printf

```cpp
void printf_safe(const char *fmt) {   // 基础情形：无额外参数
    std::cout << fmt;
}
template <typename T, typename... Args>
void printf_safe(const char *fmt, const T &val, const Args&... rest) {
    for (; *fmt; ++fmt) {
        if (*fmt == '%') {
            std::cout << val;          // 输出当前参数
            printf_safe(fmt + 1, rest...);  // 递归处理剩余
            return;
        }
        std::cout << *fmt;
    }
}
printf_safe("Hello %, you have % messages\n", "Alice", 5);
// 输出 "Hello Alice, you have 5 messages\n"
```

这是 C 的 `printf` 的类型安全版——参数类型在编译期检查，不会有 `%d` 配 `const char*` 的运行期崩溃。

### 6. 模板特例化（全特化）

为特定类型提供定制实现——**全特化**（full specialization）固定所有模板参数：

```cpp
// 通用模板
template <typename T>
struct TypeInfo {
    static const char* name() { return "unknown"; }
};
// 全特化：int
template <>
struct TypeInfo<int> {
    static const char* name() { return "int"; }
};
// 全特化：double
template <>
struct TypeInfo<double> {
    static const char* name() { return "double"; }
};
TypeInfo<int>::name();      // "int"
TypeInfo<char>::name();     // "unknown"（用通用模板）
```

函数模板也可全特化：
```cpp
template <typename T>
void f(const T &) { std::cout << "general\n"; }
template <>
void f<int>(const int &) { std::cout << "int specialization\n"; }
f(3.14);    // general
f(42);      // int specialization
```

### 7. 类模板偏特化

类模板可**偏特化**（partial specialization）——只固定部分参数或限定某种形式：

```cpp
template <typename T>
struct RemoveRef { using type = T; };
// 偏特化：左值引用
template <typename T>
struct RemoveRef<T&> { using type = T; };
// 偏特化：右值引用
template <typename T>
struct RemoveRef<T&&> { using type = T; };
RemoveRef<int>::type        // int
RemoveRef<int&>::type       // int（偏特化匹配）
RemoveRef<int&&>::type      // int（偏特化匹配）
```

偏特化让"对某类形式特殊处理"成为可能——这是 `std::remove_reference`、`std::vector<bool>` 等标准库设施的基础。

### 8. 函数模板不能偏特化

重要限制：**函数模板不能偏特化**，只能重载或全特化。若想"对引用类型特殊处理函数模板"，用重载：

```cpp
// ❌ 非法：函数模板不能偏特化
// template <typename T> void f<T&>(T& x) { ... }

// ✅ 用重载代替
template <typename T> void f(T x) { /* 通用 */ }
template <typename T> void f(T &x) { /* 引用特殊处理 */ }
```

这是模板设计的有意约束——函数重载已能表达"针对不同参数形式不同行为"，偏特化会和重载解析冲突。

## 和 C 的区别

C 的可变参数靠 `va_list`（`<stdarg.h>`），完全不类型安全：

| 维度 | C `va_list` | C++ 可变参数模板 |
|------|-----------|---------------|
| 类型检查 | 无（运行期按格式串解释） | 编译期类型检查 |
| 参数个数 | 运行期约定（如 `printf` 的 `%` 个数） | 编译期 `sizeof...` 已知 |
| 错误时机 | 运行期崩溃 | 编译期错误 |
| 性能 | 间接（va_list 遍历） | 可内联（编译期展开） |
| 特化 | 无 | 全特化/偏特化 |

### C `va_list` 的不安全

```c
#include <stdarg.h>
int sum(int count, ...) {
    va_list args;
    va_start(args, count);
    int total = 0;
    for (int i = 0; i < count; ++i)
        total += va_arg(args, int);    // 强制按 int 读——若实参是 double，读错
    va_end(args);
    return total;
}
sum(3, 1, 2, 3);          // 6
sum(3, 1.5, 2, 3);        // ❌ 1.5 是 double，按 int 读——未定义行为，可能崩溃
// count 和实际参数个数不符也是未定义行为——没有任何检查
```

```cpp
// C++：类型安全
template <typename... Args>
auto sum(Args... args) {
    return (args + ...);    // 每个参数按其实际类型参与加法
}
sum(1, 2, 3);               // 6（int）
sum(1.5, 2, 3);             // 6.5（double）——不会读错类型
// sum(1, "hello");         // 编译错误：int + const char* 无 operator+
```

C 的 `va_list` 把"类型"和"个数"都丢给了运行期，`printf("%d %s", 42, 3.14)` 这种格式串与实参不匹配是经典崩溃源。C++ 可变参数模板让"类型安全的多参数函数"成为可能，编译期挡住所有类型错误。

> **HFT 视角**：可变参数模板 + 折叠表达式是编译期计算的基础。例如编译期把一组价格展开成无分支代码、把订单字段展开成序列化代码——零运行开销，且类型安全。这是 C++ 在超低延迟领域胜过 C 的关键武器之一。

## 常见错误

### 错误 1：函数模板偏特化（非法）

```cpp
template <typename T> void f(T);
template <typename T> void f<T&>(T&) { }   // ❌ 函数模板不能偏特化
```

**修复**：用重载 `template <typename T> void f(T&) { }`，或用类模板偏特化包装。

### 错误 2：全特化签名不匹配

```cpp
template <typename T>
void f(T x) { }
template <>
void f<int>(int x, int extra) { }   // ❌ 特化签名多了参数，与模板不符
```

特化版本的签名必须与主模板匹配（参数个数、类型一致）。**修复**：`template <> void f<int>(int x) { }`。

### 错误 3：可变参数模板缺少基础情形

```cpp
template <typename T, typename... Rest>
void print(const T &first, const Rest&... rest) {
    std::cout << first;
    print(rest...);    // 递归
}
// ❌ 没有基础情形 print()，当 rest... 为空时无法终止
print(1);   // 调 print(1) → print() → 找不到匹配，编译错误
```

**修复**：定义基础情形 `void print() { }` 终止递归，或用 C++17 折叠表达式避免手写递归。

### 错误 4：特化 vs 重载混淆

```cpp
template <typename T> void f(T) { }      // 通用模板
template <> void f<int>(int) { }         // 全特化
void f(int) { }                          // 非模板重载
f(42);   // 调哪个？
```

非模板重载优先级高于模板特化——`f(42)` 调非模板 `f(int)`。若你写了特化却发现没被调用，检查是不是被重载盖住了。**最佳实践**：优先用重载而非特化，特化不参与重载解析的第一轮（特化只在主模板被选中后才考虑）。

## 自测题

**1. 选择题**：以下关于可变参数模板的说法，错误的是？

A. `sizeof...(args)` 返回参数包的个数，是编译期常量
B. 可变参数模板可通过递归 + 基础情形展开参数包
C. C++17 折叠表达式可替代手写递归展开
D. 可变参数模板的参数个数在运行期才确定

<details>
<summary>答案</summary>

**D** 错误。参数包的个数在**编译期**就已知（`sizeof...(args)` 是编译期常量），编译器在编译期展开所有递归调用或折叠表达式。运行期没有"参数个数"的概念——展开后的代码就像手写了一串重载。这是与 C `va_list`（运行期才知道个数）的本质区别。

</details>

**2. 判断题**：函数模板可以偏特化，类模板也可以偏特化。

<details>
<summary>答案</summary>

**错**。函数模板**不能**偏特化，只能全特化或重载。类模板可以偏特化（固定部分参数或限定形式）。若需要对函数模板"针对引用类型特殊处理"，用重载代替偏特化。

</details>

**3. 踩坑题**：以下代码有什么问题？

```cpp
template <typename T, typename... Rest>
void log(const T &first, const Rest&... rest) {
    std::cout << first << " ";
    log(rest...);    // 递归
}
int main() {
    log("start", 42, 3.14);
}
```

<details>
<summary>答案</summary>

缺少基础情形。`log("start", 42, 3.14)` → `log(42, 3.14)` → `log(3.14)` → `log()`（空包）→ 找不到匹配的 `log()`，编译错误。

**修复方案**：
```cpp
// 方案 1：加基础情形
void log() { }   // 终止
template <typename T, typename... Rest>
void log(const T &first, const Rest&... rest) {
    std::cout << first << " ";
    log(rest...);
}

// 方案 2：C++17 折叠表达式（无需递归）
template <typename... Args>
void log(const Args&... args) {
    ((std::cout << args << " "), ...);
}
```

</details>

**4. 应用题**：用可变参数模板实现一个 `max_of(a, b, c, ...)` 函数，返回任意数量参数中的最大值（要求类型相同）。

<details>
<summary>答案</summary>

```cpp
#include <iostream>
// 方案 1：递归 + 基础情形
template <typename T>
T max_of(const T &a) { return a; }   // 基础情形：单参数
template <typename T, typename... Rest>
T max_of(const T &first, const Rest&... rest) {
    T rest_max = max_of(rest...);
    return first > rest_max ? first : rest_max;
}
// 方案 2：C++17 折叠表达式（更简洁）
template <typename T, typename... Rest>
T max_of_fold(const T &first, const Rest&... rest) {
    T result = first;
    ((result = rest > result ? rest : result), ...);   // 折叠更新
    return result;
}
// 用法：
int main() {
    std::cout << max_of(3, 1, 4, 1, 5, 9, 2, 6);   // 9
    std::cout << max_of_fold(3.14, 2.71, 1.41);     // 3.14
}
```

要点：递归版需要基础情形 `max_of(const T&)` 终止；折叠版用逗号折叠逐个更新最大值。两者都要求参数类型相同（隐式转换到 `T`）。

</details>

**5. 判断题**：已知

```cpp
template <typename T> void foo(T x) { std::cout << "模板\n"; }
void foo(double x)                { std::cout << "普通\n"; }
```

`foo(5.5)`、`foo(5.5f)`、`foo(5)` 分别走哪一个？"优先选普通函数，普通函数匹配不上才用模板"这个说法对吗？

<details>
<summary>答案</summary>

- `foo(5.5)`（`double`）→ **普通函数**：模板 `T=double` 也是精确匹配，两边打平，**平手时非模板赢**。
- `foo(5.5f)`（`float`）→ **模板**：`T=float` 是精确匹配，普通 `foo(double)` 需要 `float→double` 转换，**匹配好坏优先**，模板赢。
- `foo(5)`（`int`）→ **模板**：同理，`T=int` 精确匹配赢过 `int→double` 转换。

那个说法**不对**——顺序说反了。不是"先看普通函数、不行再看模板"，而是**两者一起进候选集比转换序列，打平才偏袒非模板**。只要模板的匹配更好（更少转换），模板就赢。想强制走模板：`foo<int>(5)` 显式实例化，非模板出局。

</details>

## 可跑的例子

**`examples/16.4-advanced.cpp`** —— 特化分岔 + 参数包一口吞下任意个参数。

```bash
clang++ -std=c++20 examples/16.4-advanced.cpp -o /tmp/demo && /tmp/demo
```

真实输出（节选）：

```
TypeName<int>::get()        = 未知类型（通用版）
TypeName<const char*>::get() = C 字符串（特化版）

3 阶段总延迟 = 16 us
6 阶段总延迟 = 28 us
```

**看出什么了？** 同一个模板，`int` 走通用版、`const char*` 走特化版——特化是"对个别类型另写一份"的机制。参数包则把**参数个数**也变成模板参数：3 个阶段和 6 个阶段用同一个 `latency_us`，递归展开每次剥一层。

> 特化管类型维度的定制（hash、vector<bool> 靠它），参数包管个数维度的定制（make_unique / emplace_back 的地基）。
