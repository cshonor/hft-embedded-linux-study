# 18.4 运行时类型识别 RTTI

## 本节讲什么

RTTI（Run-Time Type Identification）让你在**运行时**问一个多态对象"你到底是什么类型"：
`dynamic_cast`（安全向下转型）和 `typeid`（类型信息）。本节讲清两者的行为差异、
实现机制（vtable 里的 type_info）、开销，以及"需要 RTTI 往往是设计信号"的工程判断。
代码均经**本机 g++ 13.3 / -std=c++17 实测**（2026-10-07）。

## ① dynamic_cast：指针版 vs 引用版（实测）

```cpp
struct Base { virtual ~Base() {} };
struct Derived : Base { void special() { std::cout << "special\n"; } };
struct Other : Base {};

Base* b1 = new Derived; Base* b2 = new Other;
if (auto* d = dynamic_cast<Derived*>(b1)) d->special();      // ✅ special
dynamic_cast<Derived*>(b2);                                   // → nullptr（指针版失败）
dynamic_cast<Derived&>(*b2);                                  // → 抛 std::bad_cast（引用版）
```

**本机实测输出**：

```
special
b2 转 Derived*: nullptr          ← 指针版失败 = 返回空
引用版失败: bad_cast             ← 引用版失败 = 抛异常（引用不能为"空"）
```

**使用纪律**：
- 前提：类型必须**多态**（有虚函数）——非多态类型用 dynamic_cast 是**编译错误**
- 指针版适合"试探"（`if (auto* d = dynamic_cast<...>)`），引用版适合"必须成功"（失败即 bug）
- 向上转（派生→基类）永远成功且编译期就处理，dynamic_cast 的价值只在**向下/横向**（MI 交叉转换）

## ② typeid：动态类型 vs 静态类型（实测）

```cpp
typeid(*b1) == typeid(Derived)    // 1 ← 多态对象：运行时动态类型
typeid(b1)  == typeid(Base*)      // 1 ← 指针本身：编译期静态类型（不发生解引用！）
typeid(i).name()                  // "i" ← 非多态：纯编译期求值
```

**关键区分**：

| 表达式 | 求值时机 | 结果 |
|---|---|---|
| `typeid(*多态指针)` | **运行时**（解引用发生） | 对象动态类型 |
| `typeid(指针)` / `typeid(非多态对象)` | **编译期** | 静态类型 |
| `typeid(类型名)` | 编译期 | 该类型本身 |

- `typeid` 返回 `const std::type_info&`，用途是**比较**（`==`/`!=`）和调试打印
  （`.name()` 是实现相关的 mangled 名，不可移植）
- 想要可移植的类型名：`typeid(T).name()` 只用于日志，逻辑分支用 `dynamic_cast` 或下面的更好方案

## ③ 实现机制与开销

- 多态类的 vtable 里除了虚函数指针，还存一个指向 `type_info` 的指针；
  `dynamic_cast` 沿继承链做**运行时类型遍历**（单继承快，MI/虚继承要查虚基表更慢）
- `typeid(*p)` 就是解引用 vptr 读 type_info 指针——O(1)，很便宜
- **`dynamic_cast` 不是 O(1)**：继承链越深越慢，且带一次潜在 cache miss——
  热路径循环里做 dynamic_cast 是性能反模式

## ④ "需要 RTTI" 常常是设计信号

优先考虑这三个替代方案，RTTI 留作最后手段：

| 需求 | 首选 | 次选 |
|---|---|---|
| 按类型分发行为 | **虚函数**（把行为放进类里） | `std::variant` + `std::visit`（类型集合封闭时） |
| 从基类容器取特定派生 | 重新设计接口 | `dynamic_cast` 一次转型后缓存结果 |
| 类型安全的异构容器 | `std::any` / variant | typeid 做键（`std::type_index`） |

教科书级的坏味道：一长串 `if (dynamic_cast<A*>(p)) ... else if (dynamic_cast<B*>(p)) ...`
——这是在用 RTTI 手搓虚函数分发，改成虚函数或 variant  visitor。

## ⑤ -fno-rtti 与工程边界

- GCC/Clang 支持 `-fno-rtti`：typeid/dynamic_cast 禁用，vtable 里不再生成 type_info——
  省一点二进制体积和每次 RTTI 查询成本；标准库的 `typeid`/`dynamic_cast` 同样不可用
- 与 `-fno-exceptions` 常一起出现在热路径库编译选项里（→ 18.1 HFT 关联）；
  注意 `dynamic_cast` 引用版依赖异常（bad_cast），关异常后引用版也编不过

## 和 C 的区别 / 新手要点

| C | C++ |
|---|---|
| 枚举 tag + union 手工判别类型 | dynamic_cast/typeid 语言级支持 |
| `void*` + 祈祷 | 类型安全的向下转型 |
| 无 | type_info/vtable 联动（C 没有 vtable） |

新手要点：① 先想"能不能用虚函数"再问"怎么转"；② `typeid(*p)` 才是动态类型，
`typeid(p)` 永远是静态指针类型（高频错题）；③ 引用版失败抛 `bad_cast` 不是返回空。

## HFT 关联

- **行情解码不用 RTTI**：协议消息类型判别用协议头里的 **msg_type 字段 + switch**
  （查表 O(1)、分支可预测），比 dynamic_cast 的继承链遍历快一个量级且确定
- 策略/订单对象若需要异构存储，`std::variant<LimitOrder, IcebergOrder, ...>` + `visit`
  是编译期分发，无 vtable 跳转——现代 HFT C++ 的主流写法（→ M5 C++17 ch17 variant）
- `-fno-rtti` 在部分团队的热路径库是默认选项；代价是失去 dynamic_cast 的调试便利，
  折中：热路径库关 RTTI，外围工具链保留

## 代码自测

**题目 1：** 输出是什么？

```cpp
struct A { virtual ~A(){} }; struct B : A {};
A* p = new B;
std::cout << (typeid(p) == typeid(A*)) << (typeid(*p) == typeid(B));
```

<details>
<summary>参考答案</summary>

`11`。`typeid(p)` 问的是指针本身的类型（`A*`，编译期）；`typeid(*p)` 解引用多态对象，
问运行时动态类型（`B`）。"指针类型"与"指向对象的类型"是两回事——typeid 高频错题。

</details>

**题目 2：** 为什么这段编译错误？

```cpp
struct NoVirt { int x; };
struct Sub : NoVirt {};
NoVirt* p = new Sub;
Sub* s = dynamic_cast<Sub*>(p);
```

<details>
<summary>参考答案</summary>

`NoVirt` 没有虚函数 = **非多态类型**，没有 vtable 也就没有 type_info 可查——
`dynamic_cast` 向下转型要求源类型多态，编译期直接拒绝。
修法：给基类加虚函数（虚析构最常用），或用 `static_cast`（但那是"我知道它就是"的无检查强转）。

</details>

**题目 3：** 热路径上要把 `MsgBase*` 分发到 5 种消息处理器，给两个不用 dynamic_cast 的方案。

<details>
<summary>参考答案</summary>

① **虚函数**：`MsgBase::handle(Engine&)` 虚函数，每个消息类实现自己的 handler——
一次 vtable 跳转，O(1)。
② **variant + visit**（C++17）：消息类型集合封闭时
`std::variant<MsgA, MsgB, ...>` + `std::visit(overloaded{...})`——
编译期分发，连 vtable 跳转都省了，还能享受内联。
行情场景还有③：按协议头的 msg_type 字段 switch 到具体解码器（查表/分支预测友好）。

</details>
