# 6.3 异常处理开销

> 第 6 章 · 上一节：[6.2 RTTI](02-rtti.md) · 下一章：[第 7 章 高级对象模型](../ch07-advanced-object-model/README.md)

## 这节讲什么

C++ 的零开销异常模型——正常路径几乎零开销（异常表在 .gcc_except_table），抛异常极慢（栈展开 + 查表）。

---

## 零开销模型

- **无异常抛出时**：table-based EH 在正常路径几乎零开销——异常表存在 `.gcc_except_table` 段，不污染热路径指令。
- **抛异常时**：昂贵——栈展开 + 析构 + 查异常表，比正常返回慢 2-3 个数量级。

```
正常路径：无额外指令（异常表在只读段，不执行）
抛异常：查 .gcc_except_table → 定位 handler → 栈展开 → 析构 → 跳转
```

`-fno-exceptions` 关闭异常可减小二进制 + 略加速，但禁用 `try`/`throw`。

---

## 新手要点

- **C 用错误码**：C 程序员习惯返回 `int` 错误码 + 手动检查。C++ 的异常在正常路径零开销——但抛异常极慢。
- **异常 vs 错误码**：异常适合"不可恢复错误"（如 `bad_alloc`），错误码适合"可预期的失败"（如连接超时）。HFT 热路径用错误码，异常当致命错误。

---

## HFT 关联

- **异常零开销模型的真相**：正常路径零开销，但抛异常极慢——HFT 把异常当"致命错误"用（崩溃重启），不当控制流。
- **`-fno-exceptions`**：部分 HFT 引擎整体关异常，换二进制体积 + 确定性。但会失去 STL 的异常保证。
