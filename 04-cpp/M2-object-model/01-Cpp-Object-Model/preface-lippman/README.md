# 前言（Lippman）

**Preface**

## 要点

Stanley Lippman 曾是 Cfront（最早的 C++ 编译器）的实现者，本书源自他实现编译器时对"对象底层模型"的洞察。他指出：C++ 的很多特性代价不是语言规范定的，而是**编译器实现**决定的——理解实现，才能理解代价。

本书的目标读者是想从"会用 C++"进阶到"理解 C++ 代价与底层"的工程师。不是语法教程，是"对象模型解密"。

## 自测题

1. Lippman 的编译器实现背景如何影响了本书的视角？
2. C++ 特性的代价由语言规范还是编译器实现决定？

<details>
<summary>参考答案</summary>

1. 作为 Cfront 实现者，Lippman 从编译器如何把类、继承、virtual、构造和成员访问降级为底层表示来解释语言。
   因而本书关注的不只是语法效果，还包括对象布局、隐式代码、ABI 约定及这些机制的实际成本。
2. 语言标准规定可观察语义和必须满足的约束，但通常不固定 vptr/vtable 形态、成员偏移或具体指令成本。
   这些由 ABI、编译器、优化级别和目标架构决定；讨论布局时应限定为典型 Itanium C++ ABI / 主流编译器实现并实际验证。

</details>
