导读

本章讲什么

C++17 规定在某些情况下必须省略拷贝/移动——返回 prvalue 时不再"可选地"省略，而是语法上就不产生临时对象。这改变了"返回值必定拷贝"的旧观念。

要点

C++17 之前：可选省略（NRVO/RVO）

// C++14：编译器"可以"省略拷贝，但不保证
std::string make() {
    return std::string("hi");   // RVO：可能省略，可能不省
}
std::string s = make();   // 可能 0 次、1 次或 2 次构造

NRVO（Named RVO）和 RVO 是编译器优化，标准允许但不强制。关掉优化（-fno-elide-constructors）就会真的拷贝。

C++17：强制省略（guaranteed copy elision）

C++17 规定：返回 prvalue（纯右值）时，不产生临时对象——不是"省略拷贝"，而是语法上根本没东西可拷贝。

// C++17：返回 prvalue，零拷贝，语法保证
std::string make() {
    return std::string("hi");   // prvalue，直接在 s 的位置构造
}
std::string s = make();   // 1 次构造（在 s 处），0 次拷贝

关键区别：C++14 的 RVO 是"构造临时对象 + 可能省略拷贝"；C++17 是"根本不构造临时对象"。

影响：不可移动/不可拷贝的类型也能返回

struct Immovable {
    Immovable() = default;
    Immovable(const Immovable&) = delete;
    Immovable(Immovable&&) = delete;
};

Immovable make() {
    return Immovable{};   // C++17 OK：无拷贝无移动
    // C++14 编译失败：需要拷贝/移动构造
}

std::lock_guard、std::atomic 这类不可拷贝不可移动的类型，C++17 可以直接返回。

传参也有未物化

void foo(std::string s);   // 按值传参
foo(std::string("hi"));    // C++17：prvalue 直接在参数位置构造，零拷贝

不是所有场景都省略

强制省略只针对 prvalue。对 lvalue（有名变量）返回仍可能拷贝/移动（NRVO 仍是可选优化）：

std::string make() {
    std::string s = "hi";
    return s;   // lvalue：NRVO 可选，可能移动
}

HFT 关联

  • 返回行情对象零拷贝：Tick make_tick() 返回 prvalue，C++17 保证零拷贝直接在调用方构造。
  • 不可移动类型工厂：atomic 包装类、lock_guard 持有者这类不可移动对象，C++17 可安全工厂返回。
  • 临时对象减少：prvalue 不物化临时对象，减少分配/构造开销，热路径更可预测。
  • NRVO 仍需手写：返回有名变量时 NRVO 仍可选，HFT 热路径要测编译器是否真的省略（-O2 通常会）。
  • 配合 return {...}：return Tick{ts, px, qty}; 是 prvalue，强制省略。
5.1

强制拷贝省略机制

第 5 章 强制拷贝省略与未物化传值 · 下一节：5.2 未物化传值与返回值优化

这节讲什么

C++17 之前，拷贝省略（copy elision）是编译器可选优化——可能做也可能不做，RVO/NRVO 不是保证的。C++17 规定了强制性拷贝省略（mandatory copy elision）——在某些场景下，编译器必须省略拷贝，不再当成优化。

为什么要学这个（先建立直觉）

C 程序员传结构体给函数：

// C：值传递 = 拷贝整个结构体
struct Big { int data[1000]; };
void process(struct Big b) { ... }  // 拷贝 4000 字节

struct Big b = {{...}};
process(b);  // 拷贝一次

C++ 返回值也有类似问题：

// C++14：返回大对象可能拷贝
std::vector<int> make_data() {
    std::vector<int> v(1000);
    // 填充 v...
    return v;  // 可能 NRVO 省略拷贝，但不保证
}

auto data = make_data();  // 可能再拷贝一次（RVO 省略，但不保证）

C++17 保证某些场景下不拷贝：

// C++17：返回 prvalue 必须省略拷贝
std::vector<int> make_data() {
    return std::vector<int>(1000);  // prvalue，保证不拷贝
}

auto data = make_data();  // 保证不拷贝，直接在 data 的位置构造

什么是 prvalue 和"未物化"

C++17 引入了"值类别"新规则：

  • prvalue（pure rvalue）：纯右值——还没有物化到内存中的值。如 std::vector<int>(1000)、42、x + 1
  • xvalue（expiring value）：将亡值——即将移动的对象。如 std::move(x)
  • lvalue：左值——有名字、有地址的对象。如 x

C++17 的核心变化：prvalue 不再是对象——它只是一个"值的描述"，只有在需要时才会"物化"（materialize）成临时对象。

强制省略的场景

场景 1：prvalue 初始化同类型对象

// C++17：保证不拷贝
std::string s = std::string("hello");  // prvalue 初始化 s，直接构造

// 等价于
std::string s("hello");  // 直接构造，没有中间临时对象

场景 2：函数返回 prvalue

std::vector<int> make() {
    return std::vector<int>(1000);  // 返回 prvalue
}

auto v = make();  // C++17 保证：vector 直接在 v 的位置构造
                  // 零拷贝、零移动

场景 3：函数参数传 prvalue

void process(std::vector<int> v);

process(std::vector<int>(1000));  // C++17 保证：直接在参数位置构造

不保证省略的场景

NRVO（Named Return Value Optimization）

std::vector<int> make() {
    std::vector<int> v(1000);
    // 填充 v...
    return v;  // 命名变量，NRVO 是可选优化，不保证
}

C++17 不保证 NRVO——因为 v 是个有名字的对象，编译器理论上可以不省略。

传入已存在的对象

std::vector<int> existing(1000);
auto copy = existing;  // 拷贝！不是省略

有可访问的拷贝/移动构造函数的要求

C++17 之前，即使编译器省略了拷贝，拷贝/移动构造函数仍然必须存在且可访问：

// C++14：不可拷贝不可移动的类型
struct NonCopyable {
    NonCopyable() = default;
    NonCopyable(const NonCopyable&) = delete;
    NonCopyable(NonCopyable&&) = delete;
};

NonCopyable make() {
    return NonCopyable();  // C++14：可能编译错误（拷贝构造被删除）
                           // 即使编译器想省略，规则要求拷贝构造可访问
}

// C++17：保证省略，不需要拷贝/移动构造函数
NonCopyable make() {
    return NonCopyable();  // C++17：OK！不需要拷贝/移动构造
}

auto x = make();  // C++17：OK！

这是 C++17 强制省略的最大实际影响——不可拷贝不可移动的类型可以通过 prvalue 返回。

HFT 关联

// 不可拷贝的独占资源（如 SPSC 队列）
struct RingBuffer {
    void* buf;
    size_t size;
    RingBuffer(size_t n) : buf(malloc(n)), size(n) {}
    ~RingBuffer() { free(buf); }
    RingBuffer(const RingBuffer&) = delete;  // 禁拷贝
    RingBuffer(RingBuffer&&) = delete;       // 禁移动
};

// C++17：可以返回不可拷贝不可移动的对象
RingBuffer make_ring(size_t n) {
    return RingBuffer(n);  // prvalue，强制省略
}

auto ring = make_ring(65536);  // 直接构造，零拷贝零移动

小结

场景 C++14 C++17
prvalue 初始化 可选省略 强制省略
返回 prvalue 可选 RVO 强制省略
返回命名变量 可选 NRVO 可选 NRVO（未变）
需要拷贝构造可访问 是 否（prvalue 场景）

5.2

未物化传值与返回值优化

第 5 章 强制拷贝省离 · 上一节：5.1 强制拷贝省略机制

这节讲什么

C++17 的"未物化传值"（passing unmaterialized objects）是强制拷贝省略的理论基础。本节深入讲解 prvalue 如何"延迟物化"，以及实际工程中 RVO/NRVO 的行为差异。

prvalue 的延迟物化

C++17 中，prvalue 不再是"对象"——它只是一个"值的配方"。只有在需要用到对象的地方，prvalue 才会"物化"为临时对象。

// prvalue：只是一个"配方"，没有实际对象
std::string("hello");  // prvalue：描述了"用 hello 构造 string"的操作

// prvalue 物化：在需要对象的地方才创建临时对象
const std::string& ref = std::string("hello");  // 物化为临时对象，ref 绑定它

// prvalue 直接初始化：不物化，直接构造目标
std::string s = std::string("hello");  // s 直接构造，没有临时对象

物化的时机

prvalue 在以下场景物化为临时对象： 1. 绑定到 const 引用 2. 作为 auto&& 的初始化值 3. 作为 decltype 的操作数 4. 在 sizeof / typeid 中（不实际物化） 5. 成员访问 . 操作（f().x 中 f() 物化）

// 绑定到 const 引用：物化
const std::string& r = std::string("tmp");  // 临时对象生命周期延长到 r 的作用域

// 直接初始化：不物化
std::string s = std::string("tmp");  // 直接在 s 构造，无临时对象

返回值优化详解

RVO（Return Value Optimization）

std::string make() {
    return std::string("hello");  // 返回 prvalue
}

// C++17：强制省略
auto s = make();
// 等价于：make() 的返回值直接在 s 的位置构造
// 没有临时对象，没有拷贝，没有移动

NRVO（Named Return Value Optimization）

std::string make() {
    std::string result = "hello";  // 命名变量
    // 修改 result...
    return result;  // 返回 lvalue（命名变量）
}

// C++17：NRVO 仍然是可选优化
auto s = make();
// 编译器可能：
// 1. NRVO：result 直接在 s 的位置构造（最优）
// 2. 移动：result 移动到返回值，再移动到 s

NRVO 失效的场景

std::string make(int flag) {
    std::string a = "hello";
    std::string b = "world";
    if (flag) return a;  // 返回 a
    return b;            // 返回 b
    // NRVO 失效：编译器不能确定返回哪个，必须拷贝/移动
}

保证 NRVO 的写法

std::string make(int flag) {
    std::string result;
    if (flag) {
        result = "hello";
    } else {
        result = "world";
    }
    return result;  // 只有一个返回点，NRVO 更容易触发
}

参数传递中的省略

传值参数 + prvalue 实参

void process(std::string s);  // 传值

// C++17：prvalue 直接在参数位置构造
process(std::string("hello"));  // 零拷贝

// 已有对象：拷贝
std::string existing = "hello";
process(existing);  // 拷贝

返回值链式传递

std::string transform(std::string s) {
    s += "!";
    return s;  // NRVO 可能触发
}

// C++17：整个链条可能零拷贝
auto result = transform(std::string("hello"));
// 1. "hello" 直接在 transform 的参数 s 位置构造（强制省略）
// 2. s 修改为 "hello!"
// 3. NRVO：s 直接在 result 位置（如果 NRVO 触发）

移动语义 vs 拷贝省略

std::vector<int> make() {
    std::vector<int> v(1000);
    return v;  // C++17：NRVO（可选）或移动
}

// 如果 NRVO 没触发，C++17 会自动移动：
// return std::move(v);  // 编译器隐式插入
// 所以即使 NRVO 失效，也只是移动（便宜），不是拷贝（贵）

不要显式 std::move 返回局部变量

std::vector<int> make() {
    std::vector<int> v(1000);
    return std::move(v);  // ❌ 坏！阻止 NRVO
    // 编译器看到 std::move(v) 是 xvalue，不是 lvalue
    // NRVO 只对 lvalue 生效，所以这里强制移动，阻止了 NRVO
}

// 正确
std::vector<int> make() {
    std::vector<int> v(1000);
    return v;  // 编译器自动选择 NRVO 或移动
}

HFT 关联

// 大对象返回：C++17 保证零拷贝
struct OrderBook {
    std::array<Level, 100> bids;
    std::array<Level, 100> asks;
    // 1.6KB+ 的大对象
};

OrderBook snapshot() {
    return OrderBook{...};  // prvalue，强制省略
}

auto book = snapshot();  // 直接构造，零拷贝零移动

// 不可拷贝的独占资源返回
struct Socket {
    int fd;
    Socket(int f) : fd(f) {}
    Socket(const Socket&) = delete;
    Socket(Socket&&) = delete;
};

Socket connect(const char* addr) {
    int fd = ::socket(...);
    ::connect(fd, ...);
    return Socket(fd);  // C++17：OK，强制省略
}

概念 说明
prvalue "值的配方"，不是对象
物化 prvalue 在需要时变成临时对象
强制省略 prvalue 初始化同类型对象时必须省略
NRVO 命名变量的返回值省略（可选）
不要 return std::move(v) 阻止 NRVO

Q1保证的拷贝省略
struct Widget {
    Widget() { std::puts("default"); }
    Widget(const Widget&) { std::puts("copy"); }
    Widget(Widget&&) { std::puts("move"); }
};

Widget make() { return Widget(); }  // 返回临时对象

Widget w = make();  // C++17 前后分别输出什么？

C++17 的保证拷贝省略与 C++14 的 NRVO 有什么区别？

答案与复习指引

C++17：输出 "default"（仅一次构造，无拷贝无移动）。保证的拷贝省略（guaranteed copy elision）是语言规则——编译器必须省略拷贝/移动，不是优化选项。

C++14：通常也输出 "default"（NRVO/RVO 优化），但标准允许拷贝/移动。如果关闭优化或编译器不优化，可能输出 "default" + "move"。

区别： - C++14 的 RVO 是优化（编译器可以选择做） - C++17 的保证省略是语义（编译器必须做，不可省略的对象直接在目标位置构造）

关键场景：不可移动不可拷贝的类型（如 std::mutex、std::atomic）在 C++17 可以从函数返回：

std::mutex make_mutex() { return std::mutex(); }  // C++17 OK
