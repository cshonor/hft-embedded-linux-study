## 1. 两种继承的成本对照（效率视角）

| | 接口继承（public 虚函数族） | 实现继承（复用基类代码） |
|---|---|---|
| 目的 | 多态（统一调用） | 少写代码 |
| 代价 | vptr/vtable/间接/不可内联（item20 全单） | 几乎零（非虚调用可内联） |
| 正确工具 | 纯虚接口（无数据） | **复合/私有继承**（item38/39） |
| 混淆后果 | 为多态付了全款，却只用了"复用" | LSP 谎言 + 无谓虚函数 |

**典型混淆现场**：

```cpp
class Order {
public:
    virtual void validate();    // 派生类真的需要定制 validate 吗？
    virtual uint64_t id();      // 还是想复用基类的 id 实现？
};
// 如果答案全是"复用"——这些虚函数是白付的成本：
// 每次调用间接跳转、永不可内联、还放开了 override 的口子（行为分裂风险，
// → Effective item36）
```

## 2. 三种"想要实现继承"的正确替代

| 真实需求 | 正确工具 | 成本 |
|---|---|---|
| 复用基类的非虚实现 | **直接继承非虚函数**（不需要 virtual！） | 零 |
| 复用 + 允许定制个别点 | **NVI**：非虚外壳 + 私有虚定制点（item35） | 仅定制点付虚成本 |
| 只要代码不要类型关系 | **复合**（item38） | 零（还可换实现） |

**关键认知**：C++ 里"继承实现"**不需要 virtual**——
`class D : public B {}` 自动复用 B 的所有非虚函数，零成本。
virtual 只为"运行期多态"存在；给复用加 virtual 是买椟还珠。

## 3. 判别清单（review 继承体系时逐条过）

```text
□ 这个虚函数有"派生类必须给出不同行为"的真实需求吗？
   → 没有：去掉 virtual（非虚继承零成本）
□ 派生类用基类指针被**统一处理**吗？
   → 从不：多态不存在，继承本身都该改复合（item38）
□ 基类有数据成员吗？
   → 有 + 多基类：菱形风险（→ 18.3 ② 实测代价）
□ 这个"接口"的虚函数个数？
   → >3 个要警惕：接口太胖（→ item21 虚函数预算）
```

## HFT 关联

- 策略框架的"伪多态"审计：很多策略体系的虚函数 90% 从未被 override——
  它们是为"想象中的扩展性"付的真实成本；NVI 化后虚函数只剩定制点
- 消息解码族：解码逻辑 80% 相同（头部解析）+ 20% 定制（体部）——
  正确形态是**非虚骨架 + 纯虚定制点**（Effective item34 形态四），
  不是"整个 decode() 全虚"
- 复合的收益在交易系统里被低估：撮合引擎的"风控检查"做成
  成员对象（可换实现）比虚函数钩子**更快也更灵活**——
  运行期换风控策略不动 vtable，编译期绑定则零间接（item35 替代二）

## 代码自测

**题目 1：** "想复用基类实现"为什么不需要 virtual？

<details>
<summary>参考答案</summary>

因为 C++ 的继承**默认就复用非虚实现**：`class D : public B {}` 后，
D 直接拥有 B 的全部非虚函数（编译期静态绑定、可内联、零 vtable 成本）。
virtual 的唯一职责是**运行期多态**（经基类指针调到派生版）——
为"复用"加 virtual，相当于为一个免费得到的东西买了一份
"调用间接 + 不可内联 + ABI 冻结"的全套账单（item20/21 的成本单）。
判别：派生类会**覆盖**这个函数且需要经基类指针**统一调用**吗？
两个都"是"才 virtual；缺任何一个，非虚（甚至复合）就是更优解。

</details>

**题目 2：** NVI 如何同时满足"复用骨架"和"定制个别点"？它的成本结构是什么？

<details>
<summary>参考答案</summary>

```cpp
class Decoder {
public:
    void decode(const Buf& b) {         // 非虚：骨架复用，零虚成本、可内联
        parse_header(b);                // 80% 公共逻辑
        do_parse_body(b);               // 20% 定制点
    }
    virtual ~Decoder() = default;
private:
    virtual void do_parse_body(const Buf&) = 0;   // 私有纯虚：唯一定制点
};
```

成本结构：**骨架零成本**（非虚、可内联）+ **定制点一份虚成本**
（vtable 一个槽 + 一次间接）——虚函数预算精确花在真正需要多态的地方。
对比"整个 decode() 全虚"：每次调用全部走间接（骨架部分白付），
且骨架可被派生类整个覆盖（纪律失守，→ Effective item34 形态四）。
NVI 是"接口继承与实现继承分离"在成本维度的最优解。

</details>

**题目 3：** 审查发现策略基类 12 个虚函数里 9 个从未被任何策略 override——怎么收编？

<details>
<summary>参考答案</summary>

分三类处置：
① **从未被 override 且行为全类统一** → 去 virtual 改非虚
（直接消除 9 份虚成本：间接/不可内联/override 口子全消失，
Effective item36 的重定义陷阱一并关闭）；
② **从未被 override 但语义上是"定制点"** → 下沉为 NVI 私有虚
（保留多态能力但收窄到骨架控制内，item35）；
③ **从未被 override 且根本没人调** → 删除（死代码——
虚函数表里的死槽位还占 ABI，item21 的 vtable 化石层）。
收编原则：**虚函数的存在必须有"被 override 的真实证据"**——
想象中的扩展性不是证据，Git 历史里的 override 才是。

</details>
