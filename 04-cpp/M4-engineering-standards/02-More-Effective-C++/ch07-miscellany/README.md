## 代码自测

### Q1: C/C++ 混合编程

```cpp
// C 头文件 cheader.h
#ifdef __cplusplus
extern "C" {
#endif
void c_function(int x);
#ifdef __cplusplus
}
#endif
// C++ 代码
#include "cheader.h"
int main() { c_function(42); }
```

> `extern "C"` 的作用是什么？为什么需要它？

<details>
<summary>答案与复习指引</summary>

**`extern "C"` 的作用：** 禁止 C++ 的 name mangling（名称修饰），让 C++ 编译器生成 C 风格的符号名（`c_function` 而非 `_Z11c_functioni`），以便 C 代码链接。

**为什么需要：** C++ 编译器会对函数名做修饰（编码参数类型到符号名中，支持重载）。C 编译器不做修饰。混合链接时符号名不匹配 → 链接错误。

**典型场景：**
- C++ 调用 C 库（`#include <cstdint>` 等 C 头文件内部已用 `extern "C"`）
- C 调用 C++ 库（C++ 函数需 `extern "C"` 导出）
- 嵌入式/HFT 混用 C 驱动 + C++ 业务逻辑

**复习：** → [条款 34：C++ 和 C 混合编程](./item34-C++和C混合编程的规范、链接、命名修饰、库兼容避坑.md)
</details>

### Q2: 非叶子类设计为抽象类

```cpp
// 方案 A: 具体基类
class Animal {
public:
    virtual void sound() { std::cout << "..."; }
    virtual ~Animal() {}
};
// 方案 B: 抽象基类
class Animal2 {
public:
    virtual void sound() = 0;  // 纯虚
    virtual ~Animal2() {}
};
```

> 为什么建议把非叶子类设计为抽象类？

<details>
<summary>答案与复习指引</summary>

**抽象基类优势：**
1. **强制实现接口**：派生类必须实现 `sound()`，不能"忘记"
2. **防止误实例化**：`Animal2 a;` 编译错误——不能创建抽象类对象。这符合"Animal 是抽象概念，不该直接实例化"的语义
3. **防止对象切片**：不能值传递 `Animal2`，只能通过指针/引用操作

**具体基类问题：** `Animal a;` 合法——你可以创建一个"不知道发出什么声音的动物"，这在语义上是荒谬的。而且值拷贝会导致对象切片。

**规则：** 非叶子类（可能被继承的类）设计为抽象类（至少一个纯虚函数），叶子类（不会被继承的类）可以是具体类。

**复习：** → [条款 33：把非叶子类设计为抽象类](./item33-把非叶子类设计为抽象类，强制约束子类实现接口，架构约束.md)
</details>
