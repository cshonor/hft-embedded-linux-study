## 代码自测

### Q1: 构造函数抛异常

```cpp
class Widget {
    int *a;
    int *b;
public:
    Widget() : a(new int[100]), b(new int[100]) {
        // 如果 b 的 new 抛 bad_alloc：
        // a 会泄漏吗？
    }
    ~Widget() { delete[] a; delete[] b; }
};
```

> `b` 的 `new` 抛异常时，`a` 会泄漏吗？

<details>
<summary>答案与复习指引</summary>

**会泄漏。** 构造函数中 `b` 的 `new` 抛异常时，对象未完全构造——析构函数**不会被调用**。`a` 已经分配但无法释放。

**修复（用智能指针）：**
```cpp
class Widget {
    std::unique_ptr<int[]> a;
    std::unique_ptr<int[]> b;
public:
    Widget() : a(std::make_unique<int[]>(100)), b(std::make_unique<int[]>(100)) {}
};
```
`a` 是 `unique_ptr` 成员——构造 `b` 抛异常时，`a` 的析构在部分构造的成员逆序析构中自动调用，释放内存。

**规则：** 用 RAII 成员管理资源——部分构造时，已构造的 RAII 成员自动析构，不泄漏。

**复习：** → [条款 10：构造函数抛出异常时防止泄漏](./item10-构造函数抛出异常时，如何防止内存资源泄漏.md)
</details>

### Q2: 析构不抛异常

```cpp
class Session {
    ~Session() {
        try { close_connection(); }
        catch (...) { log_error(); /* 吞掉异常 */ }
    }
};
```

> 为什么析构函数不应该抛异常？

<details>
<summary>答案与复习指引</summary>

**析构抛异常的危险：**
1. **栈展开期间**：如果异常正在传播（栈展开中析构其他对象），此时析构再抛异常 → `std::terminate` 直接崩溃
2. **不可恢复**：析构是清理阶段，此时抛异常调用方无法处理（析构通常在作用域退出/异常路径自动调用）

**规则：** 析构函数绝不抛异常。如果清理操作可能失败，在析构中 `try/catch` 吞掉异常，或提供一个单独的 `close()` 方法让调用方在非析构路径处理。

**C++11：** 析构函数默认 `noexcept`——抛异常会 `terminate`。

</details>
