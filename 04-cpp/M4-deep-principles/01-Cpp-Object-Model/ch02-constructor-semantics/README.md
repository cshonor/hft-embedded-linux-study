# 第 2 章 构造函数语义

**The Semantics of Constructors**

## 本章讲什么

你写的类没定义默认构造函数，编译器何时会"偷偷"合成一个？拷贝构造是按位拷贝还是逐成员拷贝？成员初始化列表为什么有时是必须的？本章讲编译器在构造函数上的隐式行为——这些行为决定了对象初始化的正确性与性能。

## 要点

### 编译器合成默认构造的四种情况

仅当以下情况，编译器才合成默认构造（且只合成它需要的，不为用户不需要的行为买单）：
1. 类含**有默认构造的成员对象**（需调成员默认构造）
2. **基类有默认构造**（需调基类默认构造）
3. 类有**虚函数**（需初始化 vptr）
4. 类有**虚基类**（需初始化虚基类指针/偏移）

否则不合成——POD 类不合成默认构造，`memset` 安全。

### 按位拷贝 vs 逐成员拷贝

拷贝构造默认是**按位拷贝（bitwise copy）**——逐字节复制。只有当类含上述四种情况之一（成员对象、基类、vptr、虚基类）时，编译器才合成**逐成员拷贝（memberwise copy）**构造，调用各成员/基类的拷贝构造。

按位拷贝对含指针的类是灾难（浅拷贝 → 双重释放），这就是"大三律"要求手写拷贝构造的根因。

### 成员初始化列表

```cpp
class A { const int x; int& r; public: A(int v) : x(v), r(someRef) {} };
```
`const` 成员、引用成员、无默认构造的成员对象**必须**在初始化列表初始化（不能在构造体赋值）。初始化列表比构造体赋值高效（直接构造 vs 默认构造+赋值）。

### NRVO（命名返回值优化）

```cpp
Widget make() { Widget w; ...; return w; }  // NRVO：w 直接在调用者栈构造，零拷贝
```
编译器消除返回值的拷贝。C++17 起对返回纯右值（`return Widget();`）是**强制拷贝省略**。

## HFT 关联

- **POD 零构造开销**：POD 类（无虚函数、无自定义构造）不合成构造，`vector<Tick>` 扩容用 `memcpy` 移动——HFT 数据结构尽量 POD。
- **初始化列表换性能**：成员对象用初始化列表省一次默认构造 + 赋值，热路径配置对象用列表。
- **NRVO 消除返回拷贝**：工厂函数返回大对象依赖 NRVO，不要 `std::move` 返回局部变量（阻碍 NRVO）。

## 代码自测

### Q1: 编译器何时合成默认构造函数
```cpp
class Widget {
public:
    int id;
    // 没有写任何构造函数
};

class Logger {
public:
    Logger() { log("created"); }  // 有用户定义构造
};

class Holder {
public:
    Widget w;
    Logger lg;
    // 没有写构造函数
};
```
> `Widget w;` 会触发合成构造吗？`Holder h;` 呢？编译器在什么条件下合成默认构造？

<details>
<summary>答案与复习指引</summary>

- `Widget w;`：**不会**合成。Widget 没有虚函数、没有基类、成员都是 trivial 类型，编译器认为不需要合成。
- `Holder h;`：**会**合成。因为 Holder 有一个成员 `Logger lg`，Logger 有用户定义的默认构造——编译器必须合成 Holder 的默认构造来调用 Logger 的构造。

**规则**：编译器只在需要时（成员有非 trivial 构造、基类有构造、有虚函数）才合成默认构造，且合成的构造只做编译器需要的初始化（调用成员/基类构造、设 vptr），不初始化 POD 成员。

</details>

### Q2: 成员初始化顺序
```cpp
class Risk {
public:
    int price, qty, value;
    Risk(int p, int q) : value(p * q), price(p), qty(q) {}
};
```
> `Risk r(100, 5);` 后 `r.value` 是多少？初始化顺序由什么决定？

<details>
<summary>答案与复习指引</summary>

`r.value` = **500**（100 * 5）。

**初始化顺序由成员声明顺序决定，不是初始化列表顺序**。这里 price 先于 qty 先于 value 声明，所以按 price → qty → value 初始化。但注意：如果初始化列表写 `value(p * q)` 在 price/qty 之前，而 price/qty 此时还没初始化，就会得到未定义值。**好的习惯：初始化列表顺序与声明顺序一致。**

**复习：** → [成员初始化顺序](./README.md)
</details>
