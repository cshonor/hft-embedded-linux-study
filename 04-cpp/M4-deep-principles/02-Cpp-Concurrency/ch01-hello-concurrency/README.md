# 第 1 章 你好，并发

**Hello, Concurrency**

## 本章讲什么

并发编程的动因（性能、响应性）、并发与并行的区别、以及并发的主要风险（数据竞争、死锁、悬垂引用）。本章是并发学习的入口，建立基本概念框架。

## 要点

### 并发 vs 并行

- **并发（concurrency）**：逻辑上的"同时"——单核时间片切换也能并发。
- **并行（parallelism）**：物理上的"同时"——多核真正同时执行。
- 并发是设计（管理多个任务），并行是执行（同时跑）。

### 并发动机

- **性能**：多核利用，把任务拆分并行加速。
- **响应性**：后台任务不阻塞主线程（UI/网络/IO）。

### 并发风险

| 风险 | 描述 |
|------|------|
| 数据竞争 | 多线程无同步访问共享可变数据 → UB |
| 死锁 | 互相等待对方持有的锁 |
| 悬垂引用 | 线程引用了已销毁的局部变量 |
| 线程开销 | 创建/调度/销毁有成本，过多线程反降性能 |

## HFT 关联

HFT 是并发的重度场景：行情线程 + 策略线程 + 风控线程 + IO 线程并行。但 HFT 并发的目标不只是"快"，更是**确定性**——避免数据竞争导致的非确定延迟。

## 代码自测

### Q1: 并发 vs 串行
```cpp
// 串行
void serial() {
    for (int i = 0; i < 1000000; ++i) work(i);
}

// 并发
void parallel() {
    std::thread t1([] { for (int i = 0; i < 500000; ++i) work(i); });
    std::thread t2([] { for (int i = 500000; i < 1000000; ++i) work(i); });
    t1.join();
    t2.join();
}
```
> 并发版本一定比串行快吗？什么情况下反而更慢？

<details>
<summary>答案与复习指引</summary>

**不一定**。以下情况反而更慢：
1. **`work()` 太轻**：线程创建/销毁开销（~微秒级）超过工作量
2. **共享数据竞争**：两个线程争抢同一 cache 行（false sharing）
3. **上下文切换**：线程数超过 CPU 核数时调度开销
4. **数据依赖**：线程间有同步等待（join/mutex），串行等待抵消并行收益

HFT 的教训：不是"用线程就快"，而是"让独立的数据在独立的核上并行"才有收益。
