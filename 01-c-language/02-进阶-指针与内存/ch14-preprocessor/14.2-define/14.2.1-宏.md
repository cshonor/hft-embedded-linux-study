# 14.2.1 宏

## 本节讲什么

这一节聚焦**对象宏**（object-like macro）——无参数的 `#define`，用于定义常量、标志位、字符串。核心是**括号陷阱**：宏是纯文本替换，不加括号会导致运算符优先级错乱，是 C 工程最经典的初级错误。

认知锚点：对象宏看起来最简单，却藏着最易踩的坑。`#define SQR(x) x*x` 调用 `SQR(1+2)` 得到 `1+2*1+2 = 5` 而非 9，这种 bug 在线上代码里屡见不鲜。**括号是宏的护身符**——整体加括号、参数各自加括号，是写宏的铁律。

## 要点

### 基本形态

```c
#define BURST_SIZE 32
#define PKT_FLAG_ORDER (1U << 2)
#define APP_NAME "hft-engine"
#define LOG_PREFIX "[hft] "

uint16_t n = rte_eth_rx_burst(port, q, pkts, BURST_SIZE);  /* 替换为 32 */
uint32_t flags = mbuf->ol_flags & PKT_FLAG_ORDER;          /* 替换为 (1U<<2) */
printf("%s%s starting\n", LOG_PREFIX, APP_NAME);           /* 字面量替换 */
```

宏体可以是任意 token 序列：数字、字符串、表达式、关键字。预处理器不解析语义，只做文本替换。

### 括号陷阱：经典反例

```c
#define MUL(a, b)  a * b
int x = MUL(1+2, 3+4);
/* 展开：1+2 * 3+4 = 1 + (2*3) + 4 = 11，非 (1+2)*(3+4)=21 */
```

运算符优先级让 `*` 先于 `+` 结合，宏体 `a * b` 在参数是表达式时出错。**正确写法**：

```c
#define MUL(a, b)  ((a) * (b))
int x = MUL(1+2, 3+4);
/* 展开：((1+2) * (3+4)) = 21 */
```

两层括号：① 每个参数加括号，防止参数内部表达式与宏体运算符错位；② 整体加括号，防止宏体作为子表达式时与外部运算符错位。

### 整体括号的必要性

```c
#define DOUBLE(x)  (x) * 2
int y = 3 + DOUBLE(4);
/* 展开：3 + (4) * 2 = 3 + 8 = 11，非 3 + 4*2 = 11（碰巧对） */

#define BAD(x)  (x) + 1
int z = 5 * BAD(3);
/* 展开：5 * (3) + 1 = 16，非 5 * ((3)+1) = 20 */
```

`BAD` 宏体 `(x) + 1` 参数有括号但整体无括号，与外部 `*` 结合时优先级错乱。**整体加括号**：

```c
#define GOOD(x)  ((x) + 1)
int z = 5 * GOOD(3);   /* 5 * ((3)+1) = 20 */
```

### 位运算的陷阱

```c
#define FLAG_A  1 << 0
#define FLAG_B  1 << 1

int mask = FLAG_A | FLAG_B;
/* 看似 OK，但 */

int bad = FLAG_A + FLAG_B;
/* 展开：1 << 0 + 1 << 1 = 1 << (0+1) << 1 = 1 << 1 << 1 = 2 << 1 = 4 */
/* 本意：(1<<0) + (1<<1) = 1 + 2 = 3 */
```

移位运算符 `<<` 优先级低于 `+`，`1 << 0 + 1` 被解析为 `1 << (0+1)`。**位掩码宏必须整体加括号**：

```c
#define FLAG_A  (1U << 0)
#define FLAG_B  (1U << 1)
#define FLAG_C  (1U << 2)
```

DPDK、内核的标志位定义全部遵守此规则。

### 字符串字面量宏

```c
#define APP_NAME "hft-engine"
#define LOG_PREFIX "[hft] "
#define VERSION_STR "1.3.0"

printf("%s%s v%s\n", LOG_PREFIX, APP_NAME, VERSION_STR);
/* 输出：[hft] hft-engine v1.3.0 */
```

字符串字面量宏无需加括号（字符串本身就是不可分割的 token）。但若宏体是字符串拼接，仍需注意：

```c
#define GREETING "hello, " "world"   /* 编译期自动拼接 */
const char *s = GREETING;            /* "hello, world" */
```

### 宏的三大特点

| 特性 | 说明 | 影响 |
|------|------|------|
| **无类型** | 宏是文本替换，预处理器不检查类型 | 类型错误要到编译期才暴露 |
| **无作用域** | 从 `#define` 到 `#undef` 或文件末，无视函数/块边界 | 全局污染，命名冲突 |
| **调试难** | 宏在预处理阶段已展开，gdb 看不到宏名 | 断点只能打在展开后的代码 |

```c
#define BURST_SIZE 32

void f(void) {
    /* BURST_SIZE 在此可见 */
    int x = BURST_SIZE;
}

/* 函数边界对宏无效 */

void g(void) {
    /* BURST_SIZE 仍可见 */
    int y = BURST_SIZE;
}
```

`BURST_SIZE` 一旦定义，整个文件都可见，无法限制在单个函数内。这是宏相比 `static const` 的根本缺陷。

### 宏的展开检查

```bash
# 查看预处理后的展开结果
gcc -E foo.c -o foo.i
grep "BURST_SIZE" foo.i   # 应该无输出（已展开）

# 保留注释查看
gcc -E -C foo.c -o foo.i

# 只看某段
gcc -E foo.c | grep -A 2 -B 2 "关键代码"
```

`-E` 选项让 gcc 停在预处理后，输出 `.i` 文件。排查宏展开问题第一手段。

## HFT 关联

### 配置常量宏

```c
#define MAX_ORDERS        100000
#define ORDERBOOK_DEPTH   10
#define HEARTBEAT_NS      1000000000ULL
#define MAX_STRATEGIES    32

_Static_assert(MAX_ORDERS > 0, "MAX_ORDERS must be positive");
_Static_assert(ORDERBOOK_DEPTH >= 1 && ORDERBOOK_DEPTH <= 100,
               "ORDERBOOK_DEPTH out of range");
```

HFT 配置常量用宏，配合 `_Static_assert` 编译期校验。`-D` 构建注入：

```bash
gcc -DMAX_ORDERS=200000 -DORDERBOOK_DEPTH=20 ...
```

### 标志位掩码

```c
#define FLAG_BID         (1U << 0)
#define FLAG_ASK         (1U << 1)
#define FLAG_IOC         (1U << 2)   /* Immediate or Cancel */
#define FLAG_FOK         (1U << 3)   /* Fill or Kill */
#define FLAG_SELF_TRADE  (1U << 4)

uint32_t flags = FLAG_BID | FLAG_IOC;
if (order->flags & FLAG_FOK) { /* ... */ }
```

标志位用宏不用 `enum`——宏可用于预处理条件、静态初始化，`enum` 在预处理阶段不可用。

### 协议字段偏移

```c
#define PKT_OFFSET_MAGIC    0
#define PKT_OFFSET_VERSION  4
#define PKT_OFFSET_TYPE     6
#define PKT_OFFSET_SEQ      8
#define PKT_OFFSET_PAYLOAD  16

uint8_t *p = rte_pktmbuf_mtod(mbuf, uint8_t *);
uint16_t type = *(uint16_t *)(p + PKT_OFFSET_TYPE);
```

协议字段偏移用宏，编译期替换为常量。`-Warray-bounds` 能基于这些常量做越界检查。

### 编译期版本检查

```c
#define MIN_DPDK_VERSION 21111   /* DPDK 21.11 */

#if RTE_VERSION < MIN_DPDK_VERSION
    #error "DPDK version too old, need >= 21.11"
#endif
```

依赖库版本在编译期校验，优于运行期检查。

## UB 边界

| 情形 | 后果 | 防护 |
|------|------|------|
| 宏体缺整体括号 | 与外部运算符优先级错乱 | 宏体整体加括号 |
| 参数缺括号 | 参数内部表达式与宏体运算符错位 | 每个参数加括号 |
| 位掩码宏无括号 | `<<` 与 `+` 优先级错乱 | `(1U << n)` 加括号 |
| 宏名与 C 关键字同名 | 编译错误或未定义行为 | 宏名全大写，避开关键字 |
| 宏名与变量同名 | 宏展开覆盖变量 | 宏名全大写，变量名小写 |
| 递归宏定义 | 预处理器不递归，宏体保留原样 | 避免自引用 |

### 宏名冲突的隐蔽性

```c
#define SIZE 100

void f(void) {
    int SIZE = 5;   /* 编译错误：宏展开为 int 100 = 5 */
}
```

宏无视 C 作用域，函数内定义名为 `SIZE` 的变量会被宏展开破坏。**宏名全大写**是约定俗成的隔离手段，但不是强制的——大型项目用前缀（`RTE_`、`PKT_`）进一步隔离。
