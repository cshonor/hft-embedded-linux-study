# 14.2.5 宏参数的命名约定

## 本节讲什么

宏的命名规范是 C 工程的「软法律」——不强制但必须遵守。这一节给出宏名、参数、前缀的命名约定，并深入介绍 GNU statement expression（DPDK/内核 MIN/MAX 的实现基础）和 `#undef` 的工程用法。

认知锚点：宏命名不像函数有作用域保护，一旦定义全文件可见。**全大写命名 + 工程前缀**是隔离宏命名空间的唯一手段。读 DPDK/内核源码时，`RTE_MIN`、`min_t`、`container_of` 这类宏的写法是工业级范例。

## 要点

### 命名规范

| 约定 | 说明 | 示例 |
|------|------|------|
| 宏名**全大写** | 与变量/函数区分 | `BURST_SIZE`、`RTE_LOG` |
| 参数加括号使用 | 防优先级错乱 | `(x)` 非 `x` |
| 避免短名作全局宏 | 防与字段/局部变量冲突 | 不用 `i`、`n`、`p` 作全局宏 |
| 工程前缀 | 防命名空间污染 | `RTE_`、`PKT_`、`LINUX_` |
| 下划线分隔 | 全大写下划线分词 | `MAX_PKT_BURST` |

```c
/* 内核/DPDK 风格 */
#define RTE_MIN(a, b)  ({ ... })
#define RTE_MAX(a, b)  ({ ... })
#define RTE_DIV_ROUND_UP(n, d)  (((n) + (d) - 1) / (d))
#define RTE_ALIGN(val, align)   (((val) + (align) - 1) & ~((align) - 1))
```

### 全大写约定的重要性

```c
#define max(a, b)  ((a) > (b) ? (a) : (b))   /* 小写，危险 */

struct stats {
    int max;        /* 字段名 max，与宏冲突 */
};

struct stats s = { .max = 100 };
int x = s.max;     /* 展开为 s.((max)>(max)?(max):(max))，编译错误 */
```

宏名小写会与变量、字段名冲突。**全大写是隔离手段**——变量/字段用小写或驼峰，宏用全大写，互不干扰。

### 工程前缀的必要性

```c
/* 无前缀，全局污染 */
#define MIN(a, b)  ...
#define MAX(a, b)  ...

/* 有前缀，隔离命名空间 */
#define RTE_MIN(a, b)  ...
#define RTE_MAX(a, b)  ...
#define PKT_MIN(a, b)  ...
```

无前缀的 `MIN`/`MAX` 是头文件冲突的高发区——多个库都定义 `MIN`，包含时互相覆盖。**工程前缀**（`RTE_`、`PKT_`、`LINUX_`）让宏隶属于特定命名空间，避免冲突。

### 参数命名

```c
/* 短参数名：宏体内可读性差 */
#define MUL(a, b)  ((a) * (b))

/* 描述性参数名：可读性好 */
#define MULTIPLY(factor, multiplicand)  ((factor) * (multiplicand))
```

宏参数命名权衡：短名（`a`、`b`）简洁但宏体内含义不清；长名（`factor`、`multipand`）清晰但调用时看不出参数顺序。**工业惯例**：短参数名 + 宏名语义化（`RTE_MIN(a, b)` 的 `a`/`b` 不重要，`MIN` 已说明语义）。

#### 避免与字段冲突的参数名

```c
/* 危险：参数名 x 与结构体字段 x 冲突 */
#define GET_X(s)  ((s)->x)

struct point { int x, y; };
int px = GET_X(p);   /* OK，但若字段改名则宏失效 */

/* 安全：参数名用 _ 前缀 */
#define GET_FIELD(s, field)  ((s)->field)
int px = GET_FIELD(p, x);
```

宏参数名用 `_` 前缀或描述性名字，避免与字段名混淆。

### GNU Statement Expression

```c
#define RTE_MIN(a, b) ({ \
    __typeof(a) _a = (a); \
    __typeof(b) _b = (b); \
    _a < _b ? _a : _b; \
})
```

这是 DPDK/内核 MIN/MAX 的标准实现。语法拆解：

| 元素 | 含义 |
|------|------|
| `({ ... })` | GNU statement expression，块内语句，最后一条表达式作为整个块的值 |
| `__typeof(a)` | 取 `a` 的类型（GNU 扩展） |
| `_a = (a)` | 把参数求值一次存入局部变量 |
| `_a < _b ? _a : _b` | 比较，返回最小值 |

**优势**：

1. **单次求值**：参数 `(a)` 只在 `_a = (a)` 处求值一次，后续用 `_a`，避免副作用（见 14.2.4）。
2. **类型泛型**：`__typeof(a)` 自动取参数类型，`int`/`long`/`double`/指针都能用。
3. **可作表达式**：`({})` 块有值，可放任何表达式位置（`int m = RTE_MIN(x, y);`）。

**代价**：非标准（GCC/Clang 扩展，MSVC 不支持）。可移植代码用 `static inline` 每种类型一份。

#### statement expression 的边界

```c
#define BAD() ({ int x = 1; int y = 2; })   /* 无返回值表达式，结果未定义 */

#define GOOD() ({ int x = 1; int y = 2; x + y; })   /* 返回 3 */
```

`({})` 块的最后一条**表达式**（不是语句）作为整个块的值。`x + y;` 是表达式语句，值是 `x + y`。若最后是声明或无表达式，结果未定义。

### `min_t` / `max_t`：显式类型

```c
/* linux/minmax.h */
#define min_t(type, a, b)  ({ \
    type _a = (a); \
    type _b = (b); \
    _a < _b ? _a : _b; \
})

int x = min_t(int, a, b);
long y = min_t(long, c, d);
```

显式指定类型，避免 `__typeof` 在 `a` 和 `b` 类型不同时的问题：

```c
/* 危险：a 和 b 类型不同，比较时隐式转换 */
int a = 5;
long b = 10;
auto m = min(a, b);   /* _a 是 int，_b 是 long，比较时 int 转 long */

/* 安全：显式指定类型 */
long m = min_t(long, a, b);   /* _a 和 _b 都是 long */
```

### `#undef` 的工程用法

```c
#define TEMP_DEBUG 1

/* ... 使用 TEMP_DEBUG ... */

#undef TEMP_DEBUG   /* 取消定义，后续不可见 */
```

`#undef` 取消宏定义，让宏只在需要的代码段可见。工程场景：

1. **局部宏**：只在某段代码用的宏，用完 `#undef` 避免泄漏。
2. **X-Macro 重定义**：同一份 `.def` 文件用不同宏展开，每次包含后 `#undef`（见 14.2.3）。
3. **重定义前取消**：标准要求重定义前先 `#undef`（虽然允许相同重定义）。

```c
/* X-Macro 的 #undef 模式 */
#define DEFINE_EVENT(name, val, str)  EVT_##name = val,
enum events {
    #include "events.def"
    EVT_NUM
};
#undef DEFINE_EVENT

#define DEFINE_EVENT(name, val, str)  [val] = str,
static const char *const evt_str[] = {
    #include "events.def"
};
#undef DEFINE_EVENT
```

### `container_of` 宏

```c
/* linux/kernel.h */
#define container_of(ptr, type, member) ({ \
    void *__mptr = (void *)(ptr); \
    _Static_assert( \
        __builtin_types_compatible_p(typeof(ptr), typeof(&((type *)0)->member)) || \
        __builtin_types_compatible_p(typeof(ptr), void *), \
        "container_of: type mismatch"); \
    ((type *)(__mptr - offsetof(type, member))); \
})

/* DPDK 简化版 */
#define container_of(ptr, type, member) \
    ((type *)((char *)(ptr) - offsetof(type, member)))
```

`container_of` 是内核/DPDK 最经典的宏：

1. 接收「成员指针 `ptr`、外层类型 `type`、成员名 `member`」。
2. 用 `offsetof(type, member)` 算成员在外层结构中的偏移。
3. `ptr - 偏移` 得到外层结构起始地址。
4. 强转回 `type *`。

详见 ch12.3.2 与 ch13。

## HFT 关联

### DPDK 宏规范

```c
/* rte_common.h 的核心宏 */
#define RTE_MIN(a, b)      ({ ... })   /* GNU statement expression */
#define RTE_MAX(a, b)      ({ ... })
#define RTE_ARRAY_SIZE(a)  (sizeof(a) / sizeof((a)[0]))
#define RTE_DIM(a)         RTE_ARRAY_SIZE(a)
#define RTE_PTR_ADD(ptr, x)  ((void *)((char *)(ptr) + (x)))
#define RTE_PTR_SUB(ptr, x)  ((void *)((char *)(ptr) - (x)))
#define RTE_PTR_ALIGN(ptr, align)  ((ptr + align - 1) & ~(align - 1))
```

DPDK 宏全部带 `RTE_` 前缀，避免与其他库冲突。读 `rte_common.h` 是学习工业级宏写法的最佳途径。

### 内核宏规范

```c
/* linux/kernel.h */
#define container_of(ptr, type, member)  ({ ... })
#define offsetof(TYPE, MEMBER)  ((size_t)&((TYPE *)0)->MEMBER)
#define ARRAY_SIZE(arr)  (sizeof(arr) / sizeof((arr)[0]))
#define max_t(type, a, b)  ({ ... })
#define min_t(type, a, b)  ({ ... })
#define clamp(val, lo, hi)  min(max(val, lo), hi)
```

内核宏不带前缀（内核自身就是命名空间），但用 `_t` 后缀区分类型版本（`min_t`/`max_t`）。

### HFT 项目自定义宏

```c
/* my_hft_macros.h */
#define HFT_MIN(a, b)  ({ __typeof(a) _a = (a); __typeof(b) _b = (b); _a < _b ? _a : _b; })
#define HFT_MAX(a, b)  ({ __typeof(a) _a = (a); __typeof(b) _b = (b); _a > _b ? _a : _b; })
#define HFT_ALIGN(x, a)  (((x) + (a) - 1) & ~((a) - 1))
#define HFT_DIV_ROUND_UP(n, d)  (((n) + (d) - 1) / (d))
#define HFT_ARRAY_SIZE(a)  (sizeof(a) / sizeof((a)[0]))
```

自研项目用 `HFT_` 前缀，与 DPDK `RTE_`、内核 `linux/` 区分。

### 宏的版本兼容

```c
/* 不同版本编译器/库的兼容宏 */
#if defined(__GNUC__) && __GNUC__ >= 5
    #define HFT_ASSUME(cond)  __builtin_assume(cond)
#else
    #define HFT_ASSUME(cond)  do { if (!(cond)) __builtin_unreachable(); } while (0)
#endif
```

跨编译器版本时，用条件编译为同一宏名提供不同实现。调用方用 `HFT_ASSUME(cond)`，不关心底层差异。

## UB 边界

| 情形 | 后果 | 防护 |
|------|------|------|
| 宏名小写与字段冲突 | 编译错误或行为异常 | 宏名全大写 |
| 无前缀宏名跨库冲突 | 重定义警告或覆盖 | 工程前缀（`RTE_`、`HFT_`） |
| `({})` 在 MSVC 编译 | 编译错误 | 可移植代码用 `static inline` |
| `__typeof` 在 MSVC 编译 | 编译错误 | 用 `_Generic`（C11）或 inline |
| `#undef` 后误用 | 未展开，编译错误 | `#undef` 后注释说明 |
| 重定义宏未先 `#undef` | 警告或错误 | 重定义前 `#undef` |

### MSVC 的 GNU 扩展缺失

```c
/* MSVC 不支持 GNU statement expression 和 __typeof */
#define RTE_MIN(a, b)  ({ ... })   /* MSVC 编译失败 */

/* 跨平台方案 */
#ifdef __GNUC__
    #define HFT_MIN(a, b)  ({ __typeof(a) _a = (a); __typeof(b) _b = (b); _a < _b ? _a : _b; })
#else
    static inline int hft_min_int(int a, int b) { return a < b ? a : b; }
    #define HFT_MIN(a, b)  hft_min_int((a), (b))   /* 类型受限 */
#endif
```

MSVC 不支持 `({})` 和 `__typeof`，跨平台项目需条件编译或改用 `static inline`。HFT 主要在 Linux x86/ARM 部署，GNU 扩展可用，但开源库需考虑可移植性。
