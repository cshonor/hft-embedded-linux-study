# 10.1 结构基础知识

## 本节讲什么

**struct** 是 C 语言把多个字段绑成**单一二进制数据模型**的核心机制——协议头、DPDK mbuf 元数据、内核对象、订单簿条目都依赖它。struct 不是面向对象的"类"（无方法、无继承、无封装），它**纯粹是内存布局的描述**：告诉编译器"这块内存的前 4 字节是 `seq`，接下来 2 字节是 `price`"。这种朴素性正是 HFT 喜欢它的原因——零抽象开销，布局可预测。

本节是 struct 章的入口，覆盖声明、嵌套、整体赋值；后续小节展开初始化、访问、对齐、位段、联合。

### 历史背景

C 的 struct 继承自 CPL（1967）和 BCPL（1966）的 record 概念，1972 年 K&R C 定型。与 C++ 的 class 不同，C struct **无方法、无访问控制、无继承**——纯布局描述。C11 标准加入匿名 struct/union 成员，是少数后续扩展。POSIX/DPDK/Linux 内核的几乎所有数据结构都以 struct 为骨架。

## 要点

### 基本声明与定义

```c
struct quote_hdr {
    uint32_t seq;        /* 4 字节 */
    uint16_t price;      /* 2 字节 */
    uint8_t  pkt_type;   /* 1 字节 */
};

typedef struct quote_hdr QuoteHdr;   /* typedef 简化 */
QuoteHdr pkt;                       /* 定义变量 */
```

- `struct quote_hdr` 是**类型**，`pkt` 是**变量**
- `typedef` 让后续写法更简洁，DPDK/内核标准做法
- 注意 `struct` 标签和 `typedef` 名在**不同命名空间**，可以同名（见 10.1.1）

### 字段绑定

struct 把多个字段绑成一个**整体**，可以整体赋值、传参、返回：

```c
QuoteHdr a = { .seq = 1001, .price = 9999, .pkt_type = PKT_QUOTE };
QuoteHdr b;
b = a;   /* 整体赋值：逐成员拷贝 */
```

这是与"散落变量"的根本区别——`seq/price/pkt_type` 在内存中**连续**且**一同移动**。

### 嵌套结构体

```c
struct pkt_head {
    uint32_t magic;
    struct quote_hdr quote;   /* 嵌套 struct */
    uint8_t  payload[64];
};

struct pkt_head *p = /* ... */;
p->quote.seq = 1001;          /* 嵌套访问 */
```

- 嵌套 struct 在外层 struct 中**内联存储**（非指针），布局连续
- DPDK `rte_mbuf`、内核 `task_struct` 都是多层嵌套 struct
- 嵌套深度无标准限制，但过深影响可读性

### 整体赋值的代价

```c
QuoteHdr a = {0}, b;
b = a;   /* 编译器生成 memcpy(&b, &a, sizeof(QuoteHdr)) */
```

- 小 struct（≤16 字节）：编译器可能展开为寄存器移动，几周期
- 大 struct（≥64 字节）：生成 `memcpy` 调用，几十到几百纳秒
- **HFT 铁律**：大 struct **传指针**（10.4），避免按值拷贝

### struct 与数组的对比

| 维度 | **struct** | **数组** |
|------|------------|----------|
| 成员类型 | **可异构** | 同质 |
| 访问方式 | **名字**（`.field`） | 下标 `[i]` |
| 大小 | 编译期固定 | 编译期固定（VLA 除外） |
| 整体赋值 | **支持**（`b = a`） | **不支持**（需 `memcpy`） |
| 比较相等 | **不支持**（需 `memcmp`） | 不支持 |
| 传参退化 | **不退化**（按值拷贝整个） | 退化为指针 |

struct 不退化为指针是它与数组的关键区别——按值传 struct 会拷贝整个内容。

### 与 C++ class 的区别

| 特性 | **C struct** | **C++ class/struct** |
|------|--------------|----------------------|
| 方法 | **无** | 有 |
| 访问控制 | 无 | public/private/protected |
| 继承 | 无 | 有 |
| 构造/析构 | 无 | 有 |
| 虚函数 | 无 | 有 |
| 默认访问 | — | struct=public, class=private |

C++ 的 struct 只是"默认 public 的 class"，但 HFT 代码通常**只用 C 风格 struct**（POD），避免虚函数表开销。

## HFT 关联

- **协议头建模**：`struct eth_hdr`、`struct ip_hdr`、`struct tcp_hdr` 是报文解析的基础
- **DPDK rte_mbuf**：核心数据结构是 struct，包含物理地址、长度、端口、时间戳等字段
- **订单簿条目**：`struct order { uint64_t order_id; uint32_t price; uint32_t qty; }` 
- **内核对象**：`task_struct`、`file`、`socket` 都是 struct
- **共享内存**：跨进程共享的 struct 必须用 `__attribute__((packed))` 或显式偏移，避免对齐差异（10.3）

### 实操：协议头 struct

```c
#include <stdint.h>
#include <arpa/inet.h>

struct eth_hdr {
    uint8_t  dst[6];
    uint8_t  src[6];
    uint16_t type;
} __attribute__((packed));

struct ip_hdr {
    uint8_t  ver_ihl;
    uint8_t  tos;
    uint16_t total_len;
    uint16_t id;
    uint16_t flags_frag;
    uint8_t  ttl;
    uint8_t  protocol;
    uint16_t checksum;
    uint32_t src_ip;
    uint32_t dst_ip;
} __attribute__((packed));

/* 解析 */
const uint8_t *pkt = /* 报文指针 */;
const struct eth_hdr *eth = (const struct eth_hdr *)pkt;
uint16_t eth_type = ntohs(eth->type);
if (eth_type == 0x0800) {
    const struct ip_hdr *ip = (const struct ip_hdr *)(pkt + 14);
    /* ... */
}
```

注意 `__attribute__((packed))` 确保 struct 布局与线格式一致，无 padding。
