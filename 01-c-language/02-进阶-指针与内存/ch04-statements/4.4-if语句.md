# 4.4 if 语句

## 本节讲什么

**if 语句** 是 C 最基础的条件分支:表达式非 0 为真、0 为假。本节讲 if 的语法、惯用写法、**悬垂 else** 这个缩进欺骗人眼的经典陷阱,以及 HFT 风控/报文校验里 if 链的工程规范。

## 要点

### 基本语法

```c
if (expr)
    stmt;
else if (expr2)        /* else if 是 "else { if (...) }" 的语法糖 */
    stmt2;
else
    stmt3;
```

- 表达式求值:非 0 → 真,0 → 假
- 浮点 0.0、空指针 NULL、'\0' 都是"假";任何非 0 都是"真"
- `else if` 不是独立关键字,是 `else` 后跟 `if` 的嵌套简写

### 惯用写法(HFT/驱动风格)

```c
if (mbuf)            /* 等价 mbuf != NULL, 指针非空判断 */
if (!err)            /* 等价 err == 0, 错误码为 0 */
if (cnt)             /* 等价 cnt != 0, 非空计数 */
```

- 不必写 `== 1` 或 `!= 0`;指针、整数均可直接作条件
- 但布尔语义用 `_Bool`/`bool`(C99/C23)更清晰:`if (is_valid)` 而非 `if (is_valid != 0)`

### 悬垂 else(dangling else)

```c
/* 缩进欺骗人眼: else 看似属于外层 if */
if (a > 0)
    if (b > 0)
        puts("a>0,b>0");
else                        /* ← 实际绑定内层 if! */
    puts("???");            /* a<=0 时什么都不打印, a>0 且 b<=0 打印 */
```

**规则**:`else` 匹配**最近未配对的 `if`**,缩进无效。

等价展开:

```c
if (a > 0) {
    if (b > 0)
        puts("a>0,b>0");
    else                    /* 属于内层 if (b>0) */
        puts("a>0,b<=0");
}
/* a<=0 时无任何输出 —— 常与意图不符 */
```

**根治**:每层 `if` 加 `{}`,或多层改 `else if` 扁平化:

```c
if (a <= 0) {
    /* a<=0 处理 */
} else if (b > 0) {
    puts("a>0,b>0");
} else {
    puts("a>0,b<=0");
}
```

### if 链 vs switch(选哪个)

| 维度 | if-else 链 | switch |
|------|-----------|--------|
| 条件 | 任意表达式(范围、浮点、指针) | 整型/枚举等值匹配 |
| 可读 | 范围判断灵活 | 多分支等值清晰 |
| 优化 | 顺序比较,分支预测敏感 | 跳转表 O(1)(4.8) |
| 漏分支 | 无警告 | `-Wswitch` 可查 |

- 报文类型/错误码枚举:优先 switch(可被 `-Wswitch-enum` 检查完整性)
- 范围/复合条件:用 if-else

## 与 HFT/DPDK

### 风控与报文校验的 if 链

```c
int on_order(const struct order *o) {
    if (!o) return -EINVAL;
    if (o->price <= 0 || o->price > MAX_PRICE) return -EINVAL;
    if (o->qty <= 0 || o->qty > MAX_QTY) return -EINVAL;
    if (o->side != BUY && o->side != SELL) return -EINVAL;
    /* ... 多重校验 ... */
    return execute(o);
}
```

- 早返回(early return)扁平化 if 链,比深层嵌套 if-else 更易读
- 校验顺序:从便宜到昂贵(指针非空 < 字段范围 < 跨表查询)

### 分支预测提示(__builtin_expect)

```c
if (__builtin_expect(error, 0)) {   /* error 大概率不发生 */
    handle_error();
}
/* DPDK 宏: */
#define likely(x)   __builtin_expect(!!(x), 1)
#define unlikely(x) __builtin_expect(!!(x), 0)

if (unlikely(nb == 0)) continue;    /* 0 包是少数情况 */
```

- `__builtin_expect` 告诉编译器分支走向,生成的汇编把"likely 路径"放连续区,减少分支预测失败
- HFT 热路径对"错误/罕见"分支标 `unlikely`,正常路径标 `likely`
- 滥用反而干扰 CPU 静态预测,**只给真正有偏的分支**

### 分支预测失败的代价

- 现代 CPU 流水线 14-20 级,分支预测失败 → 冲刷流水线 → 10-20 周期
- HFT 微秒级延迟里,几次预测失败就是显著开销
- 这就是为什么热路径要"数据无分支"(branchless)或分支偏置明显

## 常见误区

| 误区 | 真相 |
|------|------|
| else 匹配缩进对齐的 if | 不,匹配最近未配对 if |
| `if (a = b)` 是比较 | 是赋值,见 4.2 |
| `if (x = 0)` 与 `if (x == 0)` 等价 | 前者恒假,后者判等 |
| if 链和 switch 性能一样 | switch 可用跳转表 O(1),if 链顺序比较 |
| `__builtin_expect` 一定加速 | 用错反而干扰预测;只给真有偏的分支 |

## 实操

```bash
# 1. 悬垂 else 验证
cat > t.c <<'EOF'
#include <stdio.h>
int main(void){
  int a = -1, b = 5;     /* a<=0 */
  if (a > 0)
    if (b > 0)
      printf("a>0,b>0\n");
  else
    printf("else branch\n");   /* 不打印! else 属于内层 */
  printf("done\n");
  return 0;
}
EOF
gcc -std=c11 -Wall t.c -o t && ./t
# 只打印 done —— else 被内层 if 吞掉

# 2. __builtin_expect 汇编对比
cat > e.c <<'EOF'
int f(int x){
  if (__builtin_expect(x, 0)) return 1;
  return 0;
}
EOF
gcc -O2 -S e.c -o e.s   # 看 likely 路径是否放前面, 分支指令方向
```

## 代码自测

**题目 1：** 以下代码有什么问题？
```c
if (x > 0);
    printf("positive\n");
```

<details>
<summary>参考答案</summary>

if 后面的 ; 是空语句，构成 if 的体。所以 printf 不受 if 控制——无论 x > 0 是否成立，printf 都会执行。这是一个常见的 bug：误在 if 后加了分号。

</details>
