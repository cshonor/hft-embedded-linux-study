# 5.3 左值和右值

## 本节讲什么

**左值(lvalue)** 是"有对象标识、可取址、命名了内存中某块存储"的表达式;**右值(rvalue)** 是"临时计算结果、无持久存储、常出现在赋值右侧"的表达式。这个区分决定了哪些表达式能被赋值、能取址、能做 `++` 操作数 —— 也解释了为什么 `3 = x` 非法、`&(a+b)` 非法、`42++` 非法。本节讲 lvalue/rvalue 定义(含标准条款与底层视角)、可修改性、与指针/赋值/`++`/`&` 的关系,以及副作用与序列点如何产生 UB。

> 本节是 lvalue/rvalue 的**唯一定义处**。ch03 数据章、ch06 指针、ch08 数组、ch10 结构体凡涉及"这表达式是不是左值"都回这里。

## 核心定义

**左值(lvalue)** = 一个引用了内存中某个对象的表达式——也就是说,它有地址。

```c
int x = 42;     // x 是左值——有存储位置
x = 10;         // ✅ 左值能放赋值左边

int *p = &x;    // & 要求操作数是左值——取地址必须有地方可指

42 = 10;        // ❌ 42 是右值(字面量),没地址,不能赋值
int y = x + 1;  // (x+1) 是右值——结果在寄存器里,没固定地址
```

> 名字来源:**l**eft **value**——能出现在赋值号左边的表达式。但这只是记忆法,不是定义——`const` 变量是左值但不能放赋值左边。更准确的理解是 **"locator value"**:定位到一块内存。

### 标准定义(C11 §6.3.2.1)

> An **lvalue** is an expression (with an object type or incomplete type other than `void`) that potentially identifies an object.

关键词 **"potentially"**:

- `*p` 是左值,即使 `p` 是野指针——标准说"potentially",不要求实际指向有效对象
- 左值"转换为右值"(读取其值)时才要求对象真的存在且类型有效,否则 UB

## 左值 vs 右值

| 维度 | 左值(lvalue) | 右值(rvalue) |
|------|---------------|---------------|
| 例子 | 变量 `x`、`*p`、`arr[i]`、`s.field` | 字面量 `42`、`a+b`、函数返回值 |
| 赋值左侧 | 合法 `x = 1` | 非法 `3 = x` |
| 取址 | 合法 `&x` | 非法 `&(a+b)` |
| `++`/`--` 操作数 | 合法 `x++` | 非法 `(a+b)++` |
| 本质 | 命名了内存中的对象(可定位) | 临时计算结果,无持久存储 |

- **lvalue** = "locator value",指代一块内存(可定位)
- **rvalue** = "read value",读取的值(临时)

## 哪些是左值

| 表达式 | 左值? | 说明 |
|--------|--------|------|
| `x`(变量) | ✅ | 命名对象,有地址 |
| `*p` | ✅ | 解引用得到对象,指向的内存有了名字 |
| `arr[i]` | ✅ | 等价 `*(arr+i)`,数组元素有地址 |
| `s.field` | ✅ | 结构体成员,可赋值 |
| `p->field` | ✅ | 等价 `(*p).field` |
| `arr`(数组名) | ✅(不可修改) | 数组本身是左值,但不能整体赋值 |
| `s.bitfield` | ✅(不可取址) | 位域是左值但 `&` 非法 |
| `42`(字面量) | ❌ | 常量,无存储 |
| `a + b` | ❌ | 算术结果,临时,在寄存器 |
| `a == b` | ❌ | 比较结果,临时 int |
| `f()`(返回非数组) | ❌(通常) | 返回值临时,见下 |
| `&x` | ❌ | 取地址结果是"地址值"(指针右值),不是可定位的存储 |
| `x++`(后缀) | ❌ | 后缀自增返回旧值的右值 |

**关键:** `&x` 不是左值——`&` 产生一个"地址值"(rvalue),你不能再对它取地址 `&(&x)`。

## 可修改 vs 不可修改左值

C 标准把 lvalue 细分为**可修改左值**(modifiable lvalue)和不可修改左值;只有可修改左值能被赋值、做 `++`/`--` 操作数。

```c
const int ci = 5;
int arr[3];
struct { int f : 4; } s;

ci = 10;         // ❌ ci 是左值(有地址),但 const 不可修改
arr = NULL;      // ❌ arr 是左值(有地址),但数组不可整体赋值
arr[0] = 1;      // ✅ arr[0] 是可修改左值
s.f = 7;         // ✅ 位域是左值,可赋值
&s.f;            // ❌ 位域不可取址(地址最小粒度是字节)
```

| 左值 | 可修改? | 原因 |
|-----|---------|------|
| `int x` | ✅ | 普通变量 |
| `const int ci` | ❌ | const 限定 |
| `int arr[3]`(整体) | ❌ | 数组不可整体赋值 |
| `arr[i]` | ✅ | 元素是可修改左值 |
| `*p` | ✅ | 解引用,目标可写 |
| 位域 `s.f` | ❌(取址) | 可赋值但不可取址 |
| 字符串字面量 `"abc"` | ❌ | `.rodata` 只读 |

## 左值规则——哪些操作要求左值

### 1. 赋值左边必须可修改左值

```c
x = 10;           // ✅ x 是可修改左值
// (x + 1) = 10;  // ❌ (x+1) 不是左值
// 42 = 10;       // ❌ 42 不是左值
```

### 2. `&` 取地址——操作数必须左值

```c
int x;
int *p = &x;          // ✅ x 是左值
// int *q = &(x + 1); // ❌ (x+1) 不是左值
// int *r = &42;      // ❌ 42 不是左值
```

### 3. `++` / `--`——操作数必须左值(要原地修改)

```c
int i = 0;
i++;            // ✅ i 是左值
// (i + 1)++;   // ❌ (i+1) 不是左值
```

### 4. 三目运算符——两个分支都是左值,结果才是左值

```c
int a, b;
(a > b ? a : b) = 10;   // ✅ 两边都是左值,整个表达式是左值
(a > b ? a : 0) = 10;   // ❌ 0 不是左值,整个表达式退化为右值
```

## 函数返回值与左值

```c
int f(void){ return 42; }
int *g(void){ static int x; return &x; }

f() = 1;        /* 非法: f() 是右值 */
*g() = 1;       /* 合法: *g() 解引用返回的指针, 是左值 */
```

- 函数返回非引用类型 → 右值,不能赋值
- 函数返回指针 → 解引用后是左值,可赋值(C 没有引用,靠指针实现"返回可赋值对象")

## 底层视角

编译器把左值理解为"**一个存储位置的描述**":

- **左值** = 编译器记录的"某块存储的地址"(可能需要运行时计算,如 `arr[i]` = `base + i*4`)
- **右值** = 直接的数值,不需要地址计算

```c
int arr[4];
int x = arr[2];   // 左值 arr[2] → 编译期算出 [rsp+8]
                   // 读值 → mov eax, [rsp+8]

int *p = arr;
int y = p[2];     // 左值 p[2] → 运行期 [rdi+8]
                   // 读值 → mov eax, [rdi+8]
```

所以左值本质上回答的是"**这东西存在哪**",右值回答的是"**这东西值多少**"。

## 与指针的关系

| 概念 | 左值角色 |
|------|---------|
| `&x` 取地址 | x 必须左值——才能拿到地址 |
| `*p` 解引用 | 结果是左值——p 指向的那块内存有了名字 |
| `*p = 10` 赋值 | `*p` 是左值,写入目标内存 |
| `int *q = p` | p 本身是左值(指针变量有地址),q 也是左值 |
| `p++` | p 必须左值——原地修改指针变量 |

```c
int x = 10;
int *p = &x;   // &x 要求 x 是左值 → 拿到 x 的地址
*p = 20;       // *p 是左值 → 写入 p 指向的内存(即 x)
               // 现在 x == 20
```

## 副作用(side effect)

**副作用** = 求值过程中改变了环境状态:修改变量、写文件、改 `volatile` 对象等。

| 运算符 | 是否有副作用 |
|--------|--------------|
| `=` `+=` 等 | 是(改左值) |
| `++` `--` | 是(改左值) |
| `*p = ...` | 是(通过指针改对象) |
| 函数调用 | 可能(取决于函数) |
| `a + b` | 否(纯计算) |
| `a == b` | 否 |

```c
a = b;          /* 副作用: a 被改 */
a++;            /* 副作用: a 自增 */
printf("hi");   /* 副作用: 输出 */
a + b;          /* 无副作用, 死代码, -Wunused-value 警告 */
```

- 无副作用的纯计算表达式会被编译器消除(死代码消除)
- `volatile` 访问是有副作用的,编译器不能消除/合并 —— 见下方 HFT/DPDK

## 序列点与 UB(5.4.3 预告)

```c
arr[i++] = i;        /* UB: i 被修改一次但读取一次, 顺序未定义 */
a = a++ + ++a;       /* UB: 两次修改, 无序列点隔开 */
printf("%d", a++ + a++);   /* UB */
```

- 两个**序列点**之间,同一变量**最多修改一次**,且若修改则不能同时读取
- 违反 → UB,编译器可任意处理(gcc/clang 结果常不同)
- 详见 5.4.3

## 与 HFT/DPDK

### 通过指针返回可修改对象

```c
/* DPDK mempool get: 返回指针, 调用者解引用后是左值 */
struct rte_mbuf *m = rte_pktmbuf_alloc(pool);
m->data_len = 64;          /* *(&m->data_len) = 64, 左值赋值 */
m->pkt_len  = 64;
```

- C 没有"引用",靠"返回指针 + 解引用"实现可修改返回
- 这是 DPDK/Libevent 等库 API 的常见模式

### MMIO 寄存器与位域

```c
struct nic_regs {
    uint32_t tx_enable : 1;
    uint32_t rx_enable : 1;
    uint32_t link_mode : 3;
} __attribute__((packed));
volatile struct nic_regs *nic = (volatile struct nic_regs *)0xFB000000;

nic->tx_enable = 1;        /* 位域是左值, 可赋值 */
/* &nic->tx_enable; */     /* 非法: 位域不可取址 */
```

- 位域让硬件寄存器位字段可读可写,但不能取址(地址粒度是字节)
- 实际驱动更倾向用位掩码 + 整体读写,位域有可移植性问题(ch10)

### 其他左值场景

| 场景 | 左值意义 |
|------|---------|
| `mmio_reg->ctrl = 0x1` | `->` 解引用是左值,写入 MMIO 地址 |
| `rte_ring->head++` | `++` 要求左值,原地修改生产者头 |
| `(uint16_t *)pkt` cast 后解引用 | cast 结果不是左值,但 `*(uint16_t *)pkt` 解引用后是左值 |
| `static int counter` | counter 是左值,地址在 `.data`/`.bss` |

### volatile 访问是副作用

```c
volatile uint32_t *flag = (volatile uint32_t *)0x1000;
while (!*flag) ;           /* 副作用: 每次读 *flag, volatile 保证不被优化掉 */
```

- 无副作用的纯计算表达式会被编译器消除(死代码消除)
- `volatile` 访问是有副作用的,编译器不能消除/合并

## 常见误区

| 误区 | 真相 |
|------|------|
| `3 = x` 合法 | 非法,3 是右值不可赋值 |
| `&(a+b)` 合法 | 非法,a+b 是右值无地址 |
| 数组名可赋值 | 不可,数组名是不可修改左值 |
| 位域可取址 | 不可,地址最小粒度是字节 |
| 函数返回值总能赋值 | 返回非指针类型是右值,不能赋值 |
| `a++ + a++` 是 2a+1 | UB,序列点内两次修改 |
| `const` 变量不是左值 | 是左值(有地址),只是不可修改 |
| `&x` 是左值 | 不是,`&` 产生地址值(右值),不能 `&(&x)` |

## 实操

```bash
# 1. 左值 vs 右值: 赋值与取址
cat > t.c <<'EOF'
#include <stdio.h>
int x = 10;
int *ret_ptr(void){ return &x; }   /* 返回指针, 解引用是左值 */
int ret_val(void){ return 42; }    /* 返回值, 右值 */
int main(void){
  *ret_ptr() = 20;                  /* 合法 */
  printf("x=%d\n", x);              /* 20 */
  /* ret_val() = 1; */              /* 非法: 非左值 */
  /* &(ret_val()); */               /* 非法: 右值取址 */
  int a = 1;
  /* a = a++ + ++a; */              /* UB, 注释掉 */
  return 0;
}
EOF
gcc -std=c11 -Wall t.c -o t && ./t

# 2. 块内 static 跨调用保留(左值在 .data/.bss)
cat > t2.c <<'EOF'
#include <stdio.h>
void f(void){ static int n=0; printf("n=%d\n", ++n); }
int main(void){ f(); f(); f(); return 0; }
EOF
gcc -std=c11 -Wall t2.c -o t2 && ./t2   # n=1, n=2, n=3
```

## 代码自测

**题目 1：** 以下哪些是合法的左值？
```c
int x = 1, y = 2, arr[5] = {0};
int *p = &x;
// A: x
// B: x + y
// C: *p
// D: &x
// E: arr[x]
// F: x++
// G: (x > y ? x : y)
// H: 42
// I: *(&x)
```

<details>
<summary>参考答案</summary>

| 表达式 | 左值？ | 理由 |
|--------|-------|------|
| A: `x` | ✅ | 变量，有地址 |
| B: `x + y` | ❌ | 算术结果在寄存器 |
| C: `*p` | ✅ | 解引用，指向 x 的内存 |
| D: `&x` | ❌ | 取地址结果是"地址值"（指针右值），不是可定位的存储 |
| E: `arr[x]` | ✅ | 数组元素，有地址 |
| F: `x++` | ❌ | `++` 后缀返回旧值的右值 |
| G: `(x > y ? x : y)` | ✅ | 两边都是左值 → 整个是左值 |
| H: `42` | ❌ | 字面量 |
| I: `*(&x)` | ✅ | `&x` 得到地址，`*` 解引用后等价于 x |

**关键：** `&x` 不是左值——`&` 产生一个"地址值"（rvalue），你不能再对它取地址 `&(&x)`。

</details>

**题目 2：** 为什么 `const int ci = 5; ci = 10;` 编译报错？ci 不是左值吗？

<details>
<summary>参考答案</summary>

ci **是**左值（它有地址，`&ci` 合法），但它是**不可修改左值**——`const` 限定符剥夺了可修改性。赋值号左边要求的是**可修改左值**（modifiable lvalue），不只是左值。

</details>

**题目 3：** `*p++` 中 `*p` 和 `p++` 分别是不是左值？

<details>
<summary>参考答案</summary>

- `*p` 是左值（解引用 → 指向的内存）
- `p++` 的结果**不是**左值——`p++` 是后缀自增，返回 p 增加前的旧地址值（rvalue）。但 p 本身是左值，`p++` 修改了 p。
- `*p++` 整体等价于 `*(p++)`，先取 `*p` 的值，再 `p++`。`*p++` 作为表达式是右值（取出的值）。

</details>
