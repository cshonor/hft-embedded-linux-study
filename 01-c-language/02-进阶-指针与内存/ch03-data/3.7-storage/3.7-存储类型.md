# 3.7 存储类型

## 本节讲什么

**存储期(storage duration)** 决定"对象存活多久、何时初始化、何时销毁"。它和**链接**(能否跨文件)、**作用域**(在哪可见)是三个独立维度,合起来描述对象的完整生命周期。本节把四类存储期(自动/静态/线程/动态)与 **ELF 段**(`.text/.rodata/.data/.bss/栈/堆`)的对应讲透,这是 ch03 与 ch18 运行时环境的桥梁。

## 要点

### 四种存储期

| 存储期 | 关键字 | 位置 | 初值 | 生命周期 | 详见 |
|--------|--------|------|------|----------|------|
| **自动**(automatic) | auto(默认局部) | **栈** | 不保证 | 块开始~块结束 | [3.7.1](./3.7.1-自动存储期.md) |
| **静态**(static) | static(局部/文件) | **.data/.bss** | 0 或显式 | 程序全程 | [3.7.2](./3.7.2-静态存储期.md) |
| **线程**(thread) | _Thread_local(C11) | TLS | 视情况 | 线程全程 | [3.7.3](./3.7.3-线程存储期.md) |
| **动态**(allocated) | malloc/calloc/realloc | **堆** | malloc 不保证 | malloc~free | [3.7.4](./3.7.4-动态内存.md) |

> ⚠️ 区别**存储期**(活多久)与**链接**(能否跨文件):static 在块内只改存储期不改链接;在文件级改链接不改存储期。3.8 详。

### 三轴视角:存储期只管"活多久"这一轴

3.5 画过三轴对照表,3.6 从链接视角重画过。本节讲存储期——**存储期只决定"对象何时创建/销毁",不管在哪可见(作用域)也不管能否跨文件(链接)**。从存储期视角重画:

```
                      存储期            作用域          链接
auto 局部              自动(栈)          块              无
static 局部            静态(.bss/.data) 块              无          ← 改了存储期,作用域/链接都不变
全局(无 static)        静态              文件            外部
static 全局            静态              文件            内部        ← 改了链接,存储期本来就静态
extern 声明            静态              文件/块         外部        ← 引用,不分配存储
_Thread_local          线程              文件/块         看搭配
malloc(见 3.7.4)      动态(堆)          指针可见,对象无名字  无
```

关键:**static 局部是三轴错位的典型**——作用域还在块里(出了块"看不见"),但存储期跨到程序结束(对象还活着)。3.5 的"作用域≠存储期"坑就长在这。三个轴独立变化,组合出 C 的全部存储语义。

### 五个存储类关键字总表

| 存储类 | 生命周期 | 链接属性 | 存放位置 |
|--------|----------|----------|----------|
| `auto`(C23 起改为类型推导) | 块执行期间 | 无链接 | 栈 |
| `static`(块内) | 程序全程 | 无链接 | .data/.bss |
| `static`(文件级,含函数) | 程序全程 | **内部链接**(仅本 TU) | .data/.bss/.text |
| `extern` | 程序全程 | **外部链接**(跨文件) | 定义处 .data/.bss |
| `register`(C23 已移除) | 块执行期间 | 无链接 | 尝试寄存器,回退栈;不能 `&x` |
| `_Thread_local` | **线程**存活期间 | 看搭配:单独用=外部,配 static=内部 | TLS 块 |

- 存储类**不改变数据类型**,只控制生命周期+链接两轴
- **文件作用域 `_Thread_local` 可单独用**;块作用域必须配 static/extern
- 单条声明**至多一个存储类**(C11 6.7.1p2),`static extern int x;` 是约束违例;例外:`_Thread_local` 可与 static/extern 同用

### ELF 段映射(为什么会自动清零)

```
可执行文件布局(概念):
+-----------------+  加载地址低
| .text           |  代码, 只读可执行
| .rodata         |  字符串常量, const 只读数据
| .data           |  有初值全局/static     ← 占文件体积
| .bss            |  无初值全局/static     ← 不占文件, 加载时清零
+-----------------+
| 堆(向上长)      |  malloc 申请, 运行时扩展
| ...             |
| 栈(向下长)      |  函数帧, 局部 auto
+-----------------+  加载地址高
```

| 段 | 内容 | 自动清零? | 占文件? |
|----|------|-----------|---------|
| `.text` | 机器码 | - | 是 |
| `.rodata` | const 数据、字符串字面量 | - | 是 |
| `.data` | 有初值全局/static | 否(用初值) | 是 |
| `.bss` | 无初值或初值=0 全局/static | **是**(加载器清零) | 否 |
| 栈 | auto 局部、形参 | **否** | - |
| 堆 | malloc | **否** | - |

### 自动存储期(栈)

栈帧生命周期、默认存储类判定、形参存储类限制 —— **详见 [3.7.1 自动存储期](./3.7.1-自动存储期.md)**

### 默认存储类:由作用域决定

| 声明位置 | 不写存储类时 | 语义 |
|----------|--------------|------|
| 块内 `int x;` | **auto**(自动存储期,栈) | 块结束销毁 |
| 文件域 `int g;` | **不是 auto** —— 暂定定义,外部链接,静态存储期 | C11 6.2.2p5:文件域无存储类说明符 → 外部链接 |
| 形参 `void f(int a)` | **自动存储期**(语义上同 auto) | 但语法上只能加 `register`,见下 |

> ⚠️ **"全局默认是隐式 extern"是危险的说法**:`int g;`(文件域)的**链接属性**确实是外部的,但它是一个**定义**(暂定定义),和 `extern int g;`(**声明**)在链接器眼里完全不同:
> - 两个 TU 各写 `int g;` → `-fno-common` 下 `multiple definition` 报错
> - `extern int g;` 放头文件随便包含,不报错
>
> "外部链接"是链接属性,不是存储类——别说成"隐式 extern"。

**形参的存储类限制**(C11 6.7.6.3 约束):

```c
void f1(register int a);   /* ✅ 唯一允许的存储类 */
void f2(auto int a);       /* ❌ 约束违例,编译报错 */
void f3(static int a);     /* ❌ 约束违例 */
```

- 形参**有**自动存储期(语义上同 auto),但 `auto` 关键字**不能出现在形参声明里**——标准原文:*"The only storage-class specifier that shall occur in a parameter declaration is register"*
- 这不是"老语法没人写",是**从来没合法过**
- `register int a` 也只是提示;取地址 `&a` 时编译器自动降级为栈变量

### 动态存储期(堆)

```c
int *p = malloc(sizeof(int));    /* 堆, 不清零 */
int *q = calloc(1, sizeof(int)); /* 堆, 清零 */
free(p); free(q);                /* 显式释放 */
```

- 堆对象生命周期由 `malloc` 到 `free`,跨函数调用仍有效
- `malloc` 不清零;`calloc` 清零;`realloc` 保留前 N 字节
- **详见 [3.7.4 动态内存](./3.7.4-动态内存.md)**——malloc/calloc/realloc/free/aligned_alloc 完整章节,含 brk vs mmap 底层机制、calloc 溢出检查、realloc 经典 bug

## 与 HFT/DPDK

### hugepage 与 mempool(动态内存的工程化)

- DPDK 不用 `malloc`/`free` 在热路径,而用 **mempool**:启动时从 hugepage 预分配固定大小对象池
- 收包:`rte_mempool_get()` 取一个 mbuf,处理完 `rte_pktmbuf_free()` 归还 —— O(1),无锁(单线程)或无锁队列
- 避免 malloc 在多核下的锁竞争和碎片化 —— 这是 HFT 延迟可控的关键

### 静态配置表用 .bss 清零

```c
/* 嵌入式/DPDK: 大配置数组放 bss 利用清零, 不占镜像 */
static struct device g_devs[MAX_DEV];   /* .bss, 启动时全 0 */
```

- 只读配置改 `static const` 进 `.rodata`,可被多核安全共享

### per-thread 缓存避免伪共享

```c
struct stats {
    uint64_t rx_pkts  __rte_cache_aligned;   /* 缓存行对齐 */
    uint64_t tx_pkts  __rte_cache_aligned;
} __rte_cache_aligned;
static __thread struct stats t_stats;        /* 每核独立 */
```

- 多核场景下,共享计数器在同一个缓存行 → 原子更新触发缓存行乒乓(伪共享),延迟剧增
- 解法:per-thread + 缓存行对齐,见 ch16/ch18

### 栈使用监控

- 多线程栈小(2-8MB),递归或大数组易溢出 → 段错误或不可复现崩溃
- 工具:`valgrind --tool=drd`、`gcc -fstack-protector`、`ulimit -s`

## 常见误区

| 误区 | 真相 |
|------|------|
| 全局 `int g;` 是"未初始化" | 是定义为 0,放 .bss |
| malloc 内存是 0 | 不保证,要 calloc 或 memset |
| 栈对象"销毁"=清零 | 只是栈指针回退,内容残留 |
| static 局部每次重初始化 | 启动前初始化一次(C11 6.2.4p3),后续保留 |
| `_Thread_local` 必须搭配 static/extern | 仅**块作用域**必须;文件作用域可单独用 |
| `static extern int x;` 写一起是 UB | 单条声明两个存储类是**约束违例**(C11 6.7.1p2),编译报错;真正的 UB 是同一 TU 内同一名字先 static 后 extern 声明(C11 6.2.2p7,链接冲突) |
| _Thread_local 自动线程安全 | 是 per-thread 副本,无需锁;但跨线程访问仍需同步 |

## 实操

```bash
# 1. readelf 看段布局
cat > t.c <<'EOF'
int g_init = 1; int g_zero; static int s_init = 2; static int s_zero;
const char *msg = "hi";
int main(void){ int x; return 0; }
EOF
gcc -c t.c && readelf -S t.o | grep -E 'text|rodata|data|bss'
nm t.o | sort        # D=g_init, B=g_zero, d=s_init, b=s_zero, R="hi"

# 2. 栈残留验证
cat > s.c <<'EOF'
#include <stdio.h>
void f(void){ int x; printf("x=%d\n", x); }
int main(void){ f(); f(); return 0; }
EOF
gcc -O0 s.c -o s && ./s    # 两次输出常不同

# 3. thread_local 演示
cat > tl.c <<'EOF'
#include <stdio.h>
#include <threads.h>
static _Thread_local int t = 0;
int run(void *a){ t++; printf("t=%d\n", t); return 0; }
int main(void){ thrd_t a,b; thrd_create(&a,run,0); thrd_create(&b,run,0);
  thrd_join(a,0); thrd_join(b,0); }
EOF
gcc -std=c11 tl.c -o tl -pthread && ./tl   # 两线程都输出 t=1
```

## 代码自测

**题目 1：** 以下变量的存储类型（存储位置和生命周期）分别是什么？
```c
int g;           // (1)
static int s;    // (2)
void f(void) {
    int l;       // (3)
    static int sl; // (4)
}
```

<details>
<summary>参考答案</summary>

(1) 全局变量：静态存储，零初始化，整个程序生命周期。(2) 静态全局：同(1)但内部链接。(3) 局部变量：自动存储（栈），未初始化（值不确定），函数返回时销毁。(4) 静态局部：静态存储，零初始化，整个程序生命周期，但作用域仅限函数内。

</details>

**题目 2：** 以下声明哪一行语法错误？
```c
void demo(void)
{
    static int a;
    auto int b;
    register int c;
    static _Thread_local int d;
}
```

<details>
<summary>参考答案</summary>

**C11/C17 下四行全部合法。**

- a：块内 static，静态存储期，合法
- b：块内 auto 冗余但合法（C23 起 auto 改为类型推导，不能与显式类型同用，这行会编译错误）
- c：合法（C23 起 register 被移除，这行也会编译错误）
- d：合法——块作用域 `_Thread_local` 必须搭配 static/extern，这里带了 static；裸写 `_Thread_local int d;` 才是约束违例

**C23 视角**：b 和 c 两行在 C23 下编译不过（auto 变类型推导、register 被移除），a 和 d 依然合法。

</details>

**题目 3：** 下面这段代码，static 局部 `n` 什么时候被初始化为 5？首次调用 `f()` 时函数体里有没有"把 5 写进 n"的指令？
```c
void f(void) {
    static int n = 5;
    n++;
}
```

<details>
<summary>参考答案</summary>

**程序启动前**初始化，不是首次调用。C11 6.2.4p3：静态存储期对象 "initialized only once, prior to program startup"。C11 6.7.9p4 要求初始化器是常量表达式，所以 5 直接烧进 `.data` 段镜像，加载器 mmap 时就位。函数体里**没有任何初始化指令**——objdump 反汇编只能看到 inc，nm 可以看到 `n` 是 D 类符号带初值。"首次调用时初始化"是 C++ 的动态初始化语义，C 没有这条。

</details>

**题目 4：** 以下变量的默认/显式存储类和链接分别是什么？`void foo(auto int arg)` 能编译吗？
```c
int v1;
void f(void) {
    int v2;
    static int v3;
}
```

<details>
<summary>参考答案</summary>

- v1：文件域，无存储类说明符 → **外部链接 + 静态存储期**，是**暂定定义**（注意：不是"隐式 extern"——extern 是声明，这个是定义，两个 TU 各写一份会 multiple definition）
- v2：块内默认 auto，自动存储期（栈），无链接
- v3：显式 static，静态存储期 + 无链接，作用域仍限块内
- `void foo(auto int arg)` **编译不过**：形参声明里唯一允许的存储类是 `register`（C11 6.7.6.3 约束），写 `auto`/`static`/`extern` 都是约束违例。形参有自动存储期是**语义**，不代表能写 `auto` 关键字。

</details>
