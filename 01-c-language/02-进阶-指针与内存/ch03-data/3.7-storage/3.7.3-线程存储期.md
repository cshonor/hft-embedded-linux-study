# 3.7.3 线程存储期

## 本节讲什么

**线程存储期(thread storage duration)** 的对象每个线程各有一份独立副本,无需加锁访问。C11 引入 `_Thread_local` 关键字,DPDK/内核用 GCC 扩展 `__thread`。本节讲作用域规则、TLS 底层实现(initial-exec vs general-dynamic)、per-thread 计数器模式。

## 要点

### 声明语法

```c
_Thread_local int t_count = 0;    /* 关键字(C11 6.7.1),不需要任何头文件 */
#include <threads.h>
thread_local int t_count2 = 0;    /* 宏(C11 7.26),等价 _Thread_local */
```

- 每个线程有自己的副本,无需加锁访问 —— per-thread 计数器/缓存常用
- HFT 多核收包:per-lcore 计数器用 thread_local,避免共享缓存行伪共享
- `__thread` 是 GCC 早于 C11 的扩展,DPDK/内核大量使用,语义基本同 `_Thread_local`

### 作用域规则(C11 6.7.1)

- **文件作用域可单独用**——`_Thread_local int x;` 合法(外部链接+线程存储期)
- **块作用域必须搭配 static/extern**——块内裸写 `_Thread_local int x;` 是约束违例,因为块内无 static/extern 的对象是自动存储期,与线程存储期矛盾

### TLS 底层实现(x86-64)

- 每个线程启动时,线程库在 `%fs` 段基址寄存器存一个指针,指向本线程的 TLS 块
- 访问 TLS 变量编译成段相对寻址:`mov %fs:0xfffffff8, %eax` —— **一次访存、没有函数调用**,与普通全局几乎同速(initial-exec 模型)
- 主程序里的 TLS 走 initial-exec 零额外开销;**动态加载的 `.so` 里的 TLS** 走 general-dynamic 模型,要先调 `__tls_get_addr()` 查地址,慢一个量级 —— HFT 热路径把 TLS 变量放主程序,别放插件 so

## 与 HFT/DPDK

### per-thread 缓存避免伪共享

```c
struct stats {
    uint64_t rx_pkts  __rte_cache_aligned;   /* 缓存行对齐 */
    uint64_t tx_pkts  __rte_cache_aligned;
} __rte_cache_aligned;
static __thread struct stats t_stats;        /* 每核独立 */
```

- 多核场景下,共享计数器在同一个缓存行 → 原子更新触发缓存行乒乓(伪共享),延迟剧增
- 解法:per-thread + 缓存行对齐,见 ch16/ch18

## 常见误区

| 误区 | 真相 |
|------|------|
| `_Thread_local` 必须搭配 static/extern | 仅**块作用域**必须;文件作用域可单独用 |
| _Thread_local 自动线程安全 | 是 per-thread 副本,无需锁;但跨线程访问仍需同步 |
| `__thread` 和 `_Thread_local` 不同 | 语义基本相同,`__thread` 是 GCC 扩展,早于 C11 |

## 实操

```bash
cat > tl.c <<'EOF'
#include <stdio.h>
#include <threads.h>
static _Thread_local int t = 0;
int run(void *a){ t++; printf("t=%d\n", t); return 0; }
int main(void){ thrd_t a,b; thrd_create(&a,run,0); thrd_create(&b,run,0);
  thrd_join(a,0); thrd_join(b,0); }
EOF
gcc -std=c11 tl.c -o tl -pthread && ./tl   # 两线程都输出 t=1
```

## 代码自测

**题目 1：** 以下声明哪一行语法错误？

```c
_Thread_local int a;              /* (1) 文件作用域 */
static _Thread_local int b;       /* (2) 文件作用域 */
void f(void) {
    _Thread_local int c;          /* (3) 块作用域 */
    static _Thread_local int d;   /* (4) 块作用域 + static */
}
```

<details>
<summary>参考答案</summary>

**(3) 约束违例,其余合法。**

- (1) 文件作用域可单独用 `_Thread_local`,合法(外部链接+线程存储期)
- (2) 文件作用域 + static,内部链接+线程存储期,合法
- (3) **块作用域裸写 `_Thread_local` 是约束违例**——块内无 static/extern 的对象默认自动存储期,与线程存储期矛盾
- (4) 块作用域 + static 搭配 `_Thread_local`,合法

</details>
