# 3.6.2 内部链接

## 本节讲什么

**内部链接(internal linkage)**:标识符仅在当前翻译单元内有效,不导出给链接器,其他 `.c` 看不到也引用不了。靠 `static` 关键字在文件作用域实现。这是 C 模块封装的基础——private 函数和模块私有状态全靠它。

## 要点

### 条件与示例

```c
/* 文件作用域 + static → 内部链接 */
static int s_state = 0;          /* 模块私有变量 */
static void helper(void){}       /* 模块私有函数 */
```

- 文件作用域(全局)声明的变量/函数,**加 static** → 内部链接
- 链接器**不导出**该符号,其他 `.o` 看不到
- C11 §6.2.2p3:文件作用域标识符,声明带 `static` → 内部链接

### static 函数 = 模块私有

```c
/* foo.c */
static void parse_header(const uint8_t *pkt) { ... }  /* 仅 foo.c 可见 */
void foo_api(void) { parse_header(pkt); }              /* 对外只暴露 api */
```

- `static` 函数 = 内部链接 = 模块的 private 方法
- 编译器可以内联 static 函数(因为确信没有外部调用者),有性能收益
- 未被调用的 static 函数,编译器 `-Wunused-function` 会警告

### 内部链接的符号隔离

```c
/* foo.c */
static int count = 0;          /* 内部链接, 不导出符号 */
static void helper(void){}     /* 内部链接 */

/* bar.c */
static int count = 0;          /* 另一个独立 count, 互不冲突 */
```

- 两个 `.c` 各自 `static int count;` 是**两个不同对象**,互不干扰 —— 这是模块封装的基础
- `nm foo.o` 看到 `count` 是小写 `d`/`b`(local),`bar.o` 里也是 local,链接器不合并

### static 隔离的失败阶段:编译错还是链接错?

别的 .c 想访问本文件的 `static int s_hidden`,失败分两种情况,记住一条口诀:**没声明 = 编译错;声明了但链接不到 = 链接错**。

- **情况 1:不写声明,直接 `s_hidden++`** → **编译错**(`'s_hidden' undeclared`)。名字都没声明,编译器第一步就拦下
- **情况 2:写了 `extern int s_hidden;` 再用** → **编译过、链接错**(`undefined reference`)。编译器只查"名字有没有声明",不管来源;static 的内部链接符号不导出给链接器,链接期才发现找不到

情况 2 是更隐蔽的那个——代码看着没错,编译也过,链接才炸:

```c
/* bar.c */
extern int s_hidden;          /* 编译能过: 声明语法合法 */
void bar(void){
    s_hidden++;               /* 链接报错: undefined reference to 's_hidden' */
}
```

验证:foo.o 里 s_hidden 是 local 符号,`nm foo.o` 显示小写 `t`/`d`,不进动态符号表——对比外部链接符号是大写 `T`/`D`。

> 详见 3.5.2 先声明后使用(作用域视角)、3.6 链接器视角(符号表)

### nm 符号表中的内部链接

```bash
gcc -c foo.c -o foo.o
nm foo.o
# 0000000000000010 t helper        # t = 内部链接, text 段
# 0000000000000004 b s_hidden      # b = 内部链接, bss 段
```

| nm 字符 | 含义 |
|---------|------|
| 小写 `t` | 内部链接(static),代码段(.text) |
| 小写 `d` | 内部链接(static),已初始化数据段(.data) |
| 小写 `b` | 内部链接(static),未初始化数据段(.bss) |
| 小写 `r` | 内部链接(static),只读数据段(.rodata) |

**大小写区分链接属性**:大写 = 外部链接(导出),小写 = 内部链接(不导出)。一个字母的差别就是 public/private 的分界。

## 与 HFT/DPDK

### 模块封装

- HFT 网关模块(网络层、协议解析、风控……)各自 `.c`,靠 static 隐藏实现细节
- 只暴露 `xxx_api()` 函数和 `extern` 声明的全局配置,其余全 static
- 与面向对象语言的 private 等价,但零运行时开销

### DPDK 驱动注册(weak 符号)

```c
/* DPDK 用 weak 符号 + 链接器选择机制做驱动注册 */
RTE_INIT(my_driver_init)        /* 构造函数属性, 链接时收集 */
static void my_driver_init(void){ ... }
```

- `__attribute__((weak))` 弱符号可被强符号覆盖,DPDK/PMD 用它做可选驱动
- `__attribute__((constructor))` 让函数在 `main` 前执行,常用于驱动自注册

### 链接期符号冲突排查

```bash
# 报 "multiple definition of 'x'"
nm -C *.o | grep ' x$'          # 找哪些 .o 定义了 x
# 如果都是小写 t/d → 都是 static,不该冲突,检查头文件是否漏 static
```

## 常见误区

| 误区 | 真相 |
|------|------|
| static 全局变量其他 .c 可见 | 不可见,内部链接 |
| 同名 static 全局在两个 .c 是同一对象 | 不是,各自独立,链接器不合并 |
| static 函数不能被同文件其他函数调用 | 能,本文件内随意调用 |
| static 函数一定被内联 | 不一定,但编译器有权内联(确信无外部调用者) |

## 实操

```bash
# static 隔离实验
cat > a.c <<'EOF'
#include <stdio.h>
static int priv = 2;          /* 内部链接 */
void show(void){ printf("priv=%d\n", priv); }
EOF
cat > d.c <<'EOF'
#include <stdio.h>
static int priv = 100;       /* 与 a.c 的 priv 是不同对象 */
void d_show(void){ printf("d priv=%d\n", priv); }
EOF
cat > main.c <<'EOF'
extern void show(void);
extern void d_show(void);
int main(void){ show(); d_show(); return 0; }
EOF
gcc a.c d.c main.c -o ad && ./ad    # priv=2 / d priv=100
nm a.o | grep priv                   # b priv (小写=内部)
nm d.o | grep priv                   # b priv (小写=内部,同名但不冲突)
```

## 代码自测

**题目 1：** 以下代码能链接成功吗？如果可以，输出什么？
```c
/* a.c */ static int x = 10;
/* b.c */ static int x = 20;
/* main.c */
extern void print_a(void);
extern void print_b(void);
/* print_a 打印 a.c 的 x, print_b 打印 b.c 的 x */
```

<details>
<summary>参考答案</summary>

能链接成功。两个 `x` 都是 static（内部链接），各自独立，链接器不合并。`nm a.o` 和 `nm b.o` 都会看到小写 `d x`（或 `b x`），但它们是不同对象。这是 C 模块封装的基础——static 实现了文件级私有。

</details>

**题目 2：** bar.c 写了 `extern int s_hidden;` 去引用 foo.c 的 `static int s_hidden;`，在哪一步报错？如果不写 extern 直接用呢？

<details>
<summary>参考答案</summary>

- 写了 `extern int s_hidden;` → **编译过，链接错**（`undefined reference`）。编译器只查"有没有声明"，extern 语法合法；但 static 是内部链接，符号不导出（nm 里是小写 d/t），链接器合并时找不到定义。
- 不写 extern 直接用 → **编译错**（`'s_hidden' undeclared`）。名字都没声明，编译器第一步就拦下。

口诀：**没声明 = 编译错；声明了但链接不到 = 链接错**。

</details>
