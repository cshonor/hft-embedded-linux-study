# 2.2.3 自由形式的源代码

## 本节讲什么

C 是**自由格式（free-form）**语言：空白符（空格、制表、换行）仅用于**分隔 Token**，排版不影响语义。本节讲清楚空白在词法层的角色、什么时候**不能省略**空白、以及工程上为什么"自由不等于随意"。

## 空白的词法角色

### 规则

- 空格、制表符、换行在词法分析中**基本等同**——都是 token 分隔符
- 多个连续空白 ≡ 一个空白
- **排版不影响语义**——你可以把整个程序写在一行（理论上）

```c
int    a    ;      /* 等价 */
int a;             /* 等价 */
```

### 空白的作用：分隔 Token

空白帮助词法分析器"断开"token：

```c
int x;       /* 三个 token：int、x、; */
intx;        /* 一个 token：intx（非法标识符） */
```

- 没有空白，`intx` 被当成一个标识符——不是 `int` + `x`
- 空白在**关键字与标识符之间**、**标识符与标识符之间**不可省略

### 空白在操作符之间可省略

```c
a+b    /* 等价 */
a + b  /* 等价 */
a +b   /* 等价，但可读性差 */
```

操作符本身就是独立 token，不需要空白分隔（贪心法会正确切分）。但**加空白提升可读性**。

## 什么时候空白**不可省略**

| 场景 | 不加空白的后果 |
|------|--------------|
| `int x;` → `intx;` | 变成一个非法标识符 |
| `return 0;` → `return0;` | 变成标识符 `return0` |
| `a / *p` → `a/*p` | `/*` 被当成注释开始！（2.2.2） |
| `#define F (x)` → `#define F(x)` | 宏参数 vs 整体括号（ch14） |
| `a + ++b` → `a+++b` | 贪心法切成 `(a++)+b` 而非 `a+(++b)`（2.2） |

> **关键**：空白不只是"好看"，它**控制 token 切分**。`a/*p` 和 `a / *p` 是完全不同的程序。

## 预处理行的特殊规则

预处理指令（`#` 开头的行）有**续行**规则：

```c
#define LONG_MACRO(a, b) \
    do { \
        (a) += (b); \
    } while (0)
```

- 预处理行末尾的 `\` + 换行 = **续行**，下一行接上
- 续行符后**不能有任何字符**（包括注释和空格）——`\` 必须紧跟换行
- 宏定义跨行必须用 `\`，否则宏在第一行换行处就结束了

### 字符串字面量跨行

```c
/* C 自动拼接相邻字符串字面量 */
char *s = "hello "
          "world";    /* 等价 "hello world" */
```

- 字符串字面量**不能直接包含换行**——`"hello\n world"` 的 `\n` 是转义，不是物理换行
- 跨行字符串用相邻拼接，不用 `\` 续行

## 自由格式的边界

自由格式有几个**不自由**的例外：

1. **预处理指令**：`#` 必须在逻辑行首（可以有前置空白），`#` 后跟指令名
2. **字符串字面量内部**：空白和换行是字符串内容的一部分（物理换行需用 `\` 续行或相邻拼接）
3. **字符常量内部**：`' '` 是空格字符，不是分隔符
4. **续行符 `\`**：必须紧跟换行，中间不能有空格
5. **三字符组（trigraphs）**：`??=` 表示 `#` 等（C99 有，实际几乎不用，C17 移除）

## 工程规范：自由不等于随意

"自由格式"意味着编译器不关心排版，但**人类和团队关心**：

### 格式规范

| 项 | 惯例 |
|----|------|
| 缩进 | **4 空格**（内核/DPDK）或 **tab**（部分项目），**禁止混用** |
| 行宽 | 内核 80 列，DPDK 100 列，现代项目 120 列 |
| 大括号 | K&R（`{` 同行）或 Allman，项目统一 |
| 换行 | 运算符放行首或行尾，团队统一 |
| 一行一事 | 不要塞多条语句在一行 |

### 为什么混用 tab/space 是灾难

- tab 宽度在不同编辑器/终端不同（4/8/2）
- 混用 → 同级缩进对不齐 → diff 全文飘红 → merge conflict
- **解决**：`.editorconfig` + `clang-format` 强制，CI 检查

### 工具强制

- **`.editorconfig`**：编辑器层面统一缩进/换行/编码
- **`clang-format`**：自动格式化，内核/DPDK/LLVM 都有配置文件
- **`checkpatch.pl`**：内核风格检查脚本
- **`-Werror`**：把格式相关的警告当错误

## 为什么格式对 HFT/内核重要

| 场景 | 格式的影响 |
|------|-----------|
| **code review** | 统一格式让改动一目了然 |
| **`git blame`** | 一次格式大改让历史断裂，查不到真正作者 |
| **merge conflict** | 不一致格式是冲突头号元凶 |
| **grep/搜索** | 统一缩进让正则更可靠 |
| **嵌入式受限终端** | tab 宽度不一在某些老终端错位 |

## 常见误区

| 误区 | 纠正 |
|------|------|
| 空白只是"好看" | 空白控制 token 切分：`a/*p` 和 `a / *p` 是不同程序 |
| 可以省略所有空白 | `intx` 是一个标识符，不是 `int x` |
| tab 和 space 等价 | 词法上等价，但工程上混用是灾难 |
| 字符串可以跨行 | 物理换行不行，要用 `\` 续行或相邻拼接 |
| 续行符后可以有空格 | `\` 必须紧跟换行，否则续行失败 |
| 自由格式可以随意排版 | 编译器不管，但团队必须统一，交给工具强制 |

## 实操

1. `gcc -E` 看 `int    a    ;` 和 `int a;` 预处理后是否相同
2. 故意写 `intx;`，看编译错误
3. 写 `a/*p`（除法×解引用），看是否被注释掉；加空格 `a / *p` 修复
4. 写一个跨行宏，故意在 `\` 后加空格，看编译错误
5. 配置 `clang-format` 格式化一段代码

## 代码自测

**题目 1：** 以下代码合法吗？
```c
int\
  x = 1;
```

<details>
<summary>参考答案</summary>

合法。反斜杠加换行是行继续符，预处理阶段会把这两行合并为一行：int  x = 1;。这在写长宏定义时常用。但注意：反斜杠后必须紧跟换行符，不能有空格。

</details>
