# 7.2 字符 I/O

## 本节讲什么

最底层的字符 I/O：**`getchar()`** / **`putchar()`**，以及 **`EOF`** 结束标记。第 1 章已用 `getchar` 做文件复制；本章系统展开流模型。

## 要点

- **`getchar()`**：从 **stdin** 读一个 `unsigned char` 转为 `int` 返回；无更多数据时返回 **`EOF`**
- **`putchar(c)`**：向 **stdout** 写一个字符
- **字符流抽象**：终端、管道、文件在 C 标准 I/O 层都是**连续字节序列**，区别在是否重定向、`FILE*` 绑定
- **`EOF`**：通常为 `-1`，表示流结束或错误（需结合 `feof`/`ferror` 区分，见 7.5、7.6）
- `getchar`/`putchar` 往往经 **stdio 缓冲**；`fflush(stdout)` 在交互提示后常用

## 示例

```c
#include <stdio.h>

int c;
while ((c = getchar()) != EOF)
    putchar(c);
```

重定向：`prog < in.txt > out.txt` —— 程序不变，stdin/stdout 换绑文件。

## 底层映射

| 场景 | 对应 |
|------|------|
| 串口字符流 | 逐字节 read/write，概念同 getchar |
| UEFI ConOut | 类 putchar 输出到 GOP/串口 |
| HFT 日志 | 热路径少用 stdio，但调试仍靠字符流 |

## 常见陷阱

1. **`char` 类型存 `getchar()` 返回值**：`char c; while ((c = getchar()) != EOF)` ——若 `char` 无符号（部分平台），EOF(-1) 被截断为 255，永不等于 -1，死循环；若 `char` 有符号，0xFF(合法字节)被当成 -1，提前结束。**必须用 `int` 存 getchar 返回值**。

> **为什么返回 `int` 而不是 `char`？** `getchar` 需要返回 257 种不同结果：字节值 0~255（`unsigned char` 范围）+ EOF（-1）。但 `char` 只有 8 位，最多表示 256 个值。无论 `char` 是有符号还是无符号，0xFF 和 -1 中必有一对碰撞。用 `int` 返回，257 个值轻松装下：`0~255` 是合法字节，`-1` 是 EOF，互不歧义。用 `char` 接收等于亲手制造歧义，把 `int` 重新塞回 8 位的坑里。

2. **`fflush(stdin)` 是未定义行为**：标准只允许 `fflush` **输出流**（如 stdout）。`fflush(stdin)` 在某些实现（如旧 VC++）能清输入缓冲，但不可移植。清输入缓冲用 `while (getchar() != '\n');` 或 `scanf("%*[^\n]"); getchar();`。
3. **stdout 缓冲导致输出丢失**：stdout 默认行缓冲（终端）或全缓冲（重定向到文件）。程序崩溃时缓冲区未 flush，最后几行输出丢失。调试时在关键点 `fflush(stdout)` 或 `setvbuf(stdout, NULL, _IONBF, 0)` 关缓冲。

## 自测题

**1. 选择**：`getchar()` 的返回类型是？
- A. `char`
- B. `int`
- C. `unsigned char`
- D. `void`

<details><summary>答案</summary>
B。`getchar()` 返回 `int`——它要能表示所有 `unsigned char` 值（0–255）**外加** EOF（通常 -1）。用 `char` 接收会丢失区分：0xFF 的合法字节和 EOF 都可能变成 -1。这是 K&R 反复强调的经典坑。
</details>

**2. 判断**：`fflush(stdin)` 可以清空输入缓冲区。

<details><summary>答案</summary>
错（标准层面）。C 标准只定义 `fflush` 用于**输出/更新流**，`fflush(stdin)` 是未定义行为。部分编译器（如 MSVC）作为扩展支持，但不可移植。可移植做法：`int c; while ((c = getchar()) != '\n' && c != EOF);` 清到行尾。
</details>

**3. 踩坑**：程序输出到终端正常，重定向到文件 `prog > log.txt` 后末尾几行丢失，为什么？

<details><summary>答案</summary>
stdout 在终端是**行缓冲**（遇 `\n` 自动 flush），重定向到文件后变**全缓冲**（缓冲区满才 flush，默认 4KB/8KB）。程序正常退出时 `exit` 会 flush，但若**异常崩溃**（如 SIGSEGV、`_exit`）缓冲区未 flush，末尾输出丢失。修复：关键日志后 `fflush(stdout)`，或用 `stderr`（无缓冲）输出调试信息。
</details>

**4. 应用**：写一个统计输入行数的程序，正确处理 EOF 和 `char` 类型陷阱。

<details><summary>答案</summary>
```c
#include <stdio.h>

int main(void) {
    int c;          /* 必须 int，不是 char */
    long lines = 0;
    while ((c = getchar()) != EOF) {
        if (c == '\n')
            lines++;
    }
    printf("%ld lines\n", lines);
    return 0;
}
```
关键点：`int c`（不是 char）、`!= EOF` 判断、`%ld` 匹配 long。这是 K&R 1.5 的经典例题。
</details>

## ungetc：字符推回

**`ungetc(c, fp)`** 把字符 `c` 推回输入流，下次读会先读到它。实现「读多看一、再退回」的 parser 必备。

### 要点

- 每个流通常只允许**少量**推回（常 1 个，实现定义）
- 成功返回 `c`；失败返回 `EOF`
- 与 `fgetc`/`getchar` 配合：试探下一字符，若非预期则 `ungetc`

```c
int c = fgetc(fp);
if (c == '/')
    c = fgetc(fp);   // 看第二个字符
else {
    ungetc(c, fp);   // 不是 '/'，退回让上层处理
    /* 按其它规则处理 */
}
```

### 陷阱

1. **只保证推回一个字符**：`ungetc('a', fp); ungetc('b', fp);` — 标准只保证至少一个，第二个不保证成功。需要多字符 lookahead 时自己维护回退缓冲区。
2. **推回的字符不必是之前读到的**：`ungetc('z', fp)` 可以推回任意字符，不只是刚读的。可用作 parser「插入虚拟字符」，但也容易误用。
3. **`fseek`/`rewind`/`fsetpos` 会丢弃推回的字符**：任何改变文件位置的操作都清除 `ungetc` 的推回缓冲区。
4. **`ungetc` 影响 `ftell`**：推回后 `ftell` 返回值减一，反映逻辑位置后退。

### 自测题

**1.** 以下代码连续推回两个字符，可靠吗？
```c
ungetc('a', stdin);
ungetc('b', stdin);  // 先读到 'b' 还是 'a'？
```
<details><summary>答案</summary>
不可靠。标准只保证至少能推回一个字符。如果实现支持多个，以 LIFO 顺序返回（先读 'b' 再读 'a'）。某些实现只保留最后一个，'a' 被丢弃。需要多字符 lookahead 应自建回退缓冲区。
</details>

**2.** `fseek(fp, 100, SEEK_SET); fgetc(fp); ungetc('x', fp);` 之后 `ftell(fp)` 返回多少？
<details><summary>答案</summary>
返回 100。`fgetc` 前进到 101，`ungetc` 后退到 100。`ftell` 考虑推回字符，返回逻辑位置。
</details>

**3.** 设计一个「读两个字符判断是否是 `//` 注释」的函数，如果不是就退回。
<details><summary>答案</summary>
```c
int is_comment(FILE *fp) {
    int c1 = fgetc(fp);
    if (c1 != '/') {
        if (c1 != EOF) ungetc(c1, fp);
        return 0;
    }
    int c2 = fgetc(fp);
    if (c2 != '/') {
        if (c2 != EOF) ungetc(c2, fp);
        ungetc(c1, fp);   // 退回第一个 '/' 也要退回！
        return 0;
    }
    return 1;  // 确认是 //
}
```
关键：不是注释时要**逆序退回所有**读到的字符。注意检查 EOF——`ungetc(EOF, fp)` 行为未定义。
</details>

## EOF 的两种含义：feof vs ferror

`EOF` 返回后无法直接区分是**读到文件末尾**还是**I/O 出错**。需要两个函数进一步判断：

| 函数 | 返回真表示 | 典型场景 |
|------|-----------|----------|
| `feof(fp)` | 真的读到流末尾 | 文件读完、管道对端关闭 |
| `ferror(fp)` | 流发生 I/O 错误 | 磁盘故障、网络断开 |

```c
int c;
while ((c = getchar()) != EOF) {
    putchar(c);
}
/* 循环退出后区分原因 */
if (ferror(stdin)) {
    fprintf(stderr, "I/O error occurred\n");
} else if (feof(stdin)) {
    /* 正常读完，无需额外处理 */
}
```

## 交互场景：fflush(stdout) + getchar

`stdin`/`stdout` 终端模式默认行缓冲。打印提示不带 `\n` 时，提示文字卡在 stdout 缓冲区，用户看不到：

```c
/* ❌ 错误：提示不显示 */
printf("请输入：");        /* 没有 \n，卡在缓冲区 */
int c = getchar();         /* 用户不知道要输入什么 */

/* ✅ 正确：手动刷新 */
printf("请输入：");
fflush(stdout);            /* 强制刷 stdout，提示立刻显示 */
int c = getchar();         /* 用户看到提示后输入 */
```
