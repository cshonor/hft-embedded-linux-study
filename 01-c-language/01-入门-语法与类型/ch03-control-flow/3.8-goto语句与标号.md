# 3.8 goto 语句与标号

## 本节讲什么

C **保留** `goto` 与**标号**（`label:`），可从任意处跳转到同一函数内的标号。K&R 承认其存在，但**不鼓励滥用**；规范场景是**多层循环统一出口**或**错误处理集中清理**。

## 要点

- 形式：`goto 标号;` 与 `标号: 语句`
- 标号作用域为**整个函数**；不能跨函数跳转
- 不能跳进另一个块并跳过变量初始化（C 规则限制，避免未初始化使用）
- 书中推荐用途：
  - 深层嵌套循环**一次跳出多层**
  - 错误路径 **`goto err;`**，在 `err:` 集中释放资源（内核常见模式）

## 合理 vs 滥用

| 合理 | 滥用 |
|------|------|
| 统一错误处理、资源清理 | 替代结构化 if/循环， spaghetti 代码 |
| 从多重循环 breakout | 正常业务分支全靠 goto |
| 有限状态机代码生成、手写汇编对应 | 跳来跳去难以维护 |

## 示例（错误集中处理）

```c
if (setup_a() < 0)
    goto fail;
if (setup_b() < 0)
    goto fail;
/* 正常路径 */
return 0;

fail:
    cleanup();
    return -1;
```

多层循环跳出也可 `goto done;`，比多个 flag + break 更清晰。

## goto 的限制

| 限制 | 说明 |
|------|------|
| 不能跨函数 | goto 只在同一函数内跳转，跨函数用 `setjmp`/`longjmp`（危险） |
| 不能跳过 VLA 声明 | 跳过变长数组声明进入其作用域是 UB |
| 不能跳过带初始化的声明（C99+） | `goto` 跳过 `int x = 5;` 后使用 x 是 UB（GCC 报错） |
| 标号作用域 = 整个函数 | 标号在函数内任何位置可见，但只能 goto 到已执行的标号之后 |

## 内核中的 goto 模式

Linux 内核大量使用 goto 做资源清理，典型模式：

```c
int driver_probe(struct device *dev) {
    void *reg = ioremap(...);
    if (!reg) goto err_mem;

    int irq = request_irq(...);
    if (irq < 0) goto err_irq;

    /* ... 正常逻辑 ... */
    return 0;

err_irq:
    iounmap(reg);
err_mem:
    return -ENOMEM;
}
```

**为什么内核用 goto 而非 if-else 嵌套**：每个资源申请可能失败，goto 到对应清理标签比层层嵌套 if-else 更扁平、更不易遗漏清理步骤。Linus Torvalds 在内核编码规范中明确支持这一模式。

## 常见陷阱

1. **goto 跳过变量初始化**：`goto skip; int x = compute(); skip: use(x);` ——C99+ 中跳过带初始化的声明是 UB（x 的值不确定）。GCC 报错 `jump bypasses variable initialization`。修复：把声明移到 goto 之前，或用 `int x; goto skip; skip: x = compute();`（先声明不初始化，跳过后再赋值）。

2. **goto 制造循环（向后跳）导致可读性崩塌**：`label: ... if (cond) goto label;` 等价于 `while`/`for`/`do-while`，但可读性差。编译器对 goto 循环和结构化循环生成的代码通常一样，没有性能优势。唯一合理的向后 goto 是实现状态机或手写汇编对照。正常循环一律用 `while`/`for`。

3. **多个清理标号顺序写反**：`err_irq: free_irq(); err_mem: iounmap();` ——清理必须按**申请的逆序**释放。如果标号顺序写反（先 iounmap 再 free_irq），可能在 irq handler 仍访问寄存器时释放了映射。大型函数清理链容易写错，review 时需逐条核对申请-释放配对。

## 自测题

**1. 选择**：以下代码有什么问题？
```c
goto skip;
int x = 42;
skip:
printf("%d\n", x);
```
- A. 没问题，x 被初始化为 42
- B. 编译错误或 UB，goto 跳过了 x 的初始化
- C. x 的值是 0
- D. 标号不能在变量声明前

<details><summary>答案</summary>
B。C99+ 规定 goto 跳过带初始化的声明是**未定义行为**。GCC/Clang 报错 `jump bypasses variable initialization`。修复：把 `int x;` 放到 goto 之前，初始化 `x = 42;` 放到 skip 之后；或去掉初始化改为 `int x = 0;`（但语义可能不对）。注意：跳过**无初始化**的声明（`int x;`）是合法的，只是 x 的值不确定。
</details>

**2. 判断**：goto 可以跳转到另一个函数中的标号。

<details><summary>答案</summary>
错。goto 的标号作用域是**当前函数**，不能跨函数跳转。跨函数跳转需用 `setjmp`/`longjmp`（C 标准库），但 longjmp 跳回 setjmp 时会展开栈帧，若中间有未释放的资源会泄漏——比 goto 危险得多。C++ 的异常机制（throw/catch）是更安全的跨函数跳转，但它有运行时开销。
</details>

**3. 踩坑**：以下内核风格代码的清理顺序有什么问题？
```c
struct resource *a = alloc_a();
if (!a) goto out;
struct resource *b = alloc_b();
if (!b) goto out;
/* 正常逻辑 */
return 0;
out:
    free_a(a);
    free_b(b);
    return -1;
```

<details><summary>答案</summary>
问题：当 `alloc_b()` 失败时执行 `goto out`，此时 `b` 是 NULL，`free_b(b)` 传 NULL 可能没问题（如果 free_b 检查了 NULL）。但更严重的是**当 alloc_a 失败时**，`b` 还没声明就跳到 out，`free_b(b)` 访问未声明变量——编译错误。
正确写法用**分级标号**：
```c
if (!a) goto err_a;
if (!b) goto err_b;
return 0;
err_b: free_b(b);
err_a: free_a(a);
return -1;
```
每个标号只清理到该点为止已申请的资源，**逆序释放**。
</details>

**4. 应用**：用 goto 实现一个多层循环的"找到即退出"，说明为什么不用 break + flag。

<details><summary>答案</summary>
```c
for (int i = 0; i < N; i++)
    for (int j = 0; j < M; j++)
        if (matrix[i][j] == target)
            goto found;
/* 未找到 */
return -1;

found:
    printf("found at [%d][%d]\n", i, j);
    return 0;
```
不用 break + flag 的原因：需要两层 break 外加一个外层循环条件检查（`if (found) break`），代码更长且容易忘记某一层。`goto found` 一步到位，语义清晰。Linux 内核搜索循环常用此模式。C 没有 `break N`（break N 层循环）语法，goto 是最直接的多层退出方式。
</details>

## 与后续衔接

Linux 内核大量 `goto out;` / `goto err_free;` 模式；读驱动、网络栈时会天天见到。掌握「标号 + 单向清理」比排斥一切 goto 更实用。

## 代码自测

**题目 1：** goto 在什么场景下是合理的？
```c
for (i = 0; i < n; i++)
    for (j = 0; j < m; j++)
        if (found)
            goto done;
done:
```

<details>
<summary>参考答案</summary>

多重循环的跳出是 goto 最常见的合理用法——C 没有 `break N` 语法，goto 比设标志位 + 多重 break 更清晰。另一个合理场景是错误处理（类似 goto cleanup）。其余情况应避免 goto——它破坏结构化编程，使控制流难以追踪。

</details>
