# 4.11.3 条件包含

## 本节讲什么

**条件编译**：根据宏是否定义，选择性地包含或排除代码。跨平台、调试开关、可选功能的标配（Linux `CONFIG_*`、UEFI 平台宏）。

## 要点

```c
#ifdef DEBUG
    fprintf(stderr, "debug: %s\n", msg);
#endif

#ifndef MYHDR_H
#define MYHDR_H
/* 头文件内容 */
#endif

#if defined(LINUX) && !defined(__KERNEL__)
    /* ... */
#elif defined(_WIN32)
    /* ... */
#else
    /* ... */
#endif
```

### 常见指令

| 指令 | 含义 |
|------|------|
| `#ifdef` / `#ifndef` | 宏已定义 / 未定义 |
| `#if` / `#elif` / `#else` / `#endif` | 常量表达式条件 |
| `#defined(NAME)` | 在 `#if` 中测试宏是否定义 |

### 典型用途

- **调试日志**：`-DDEBUG` 编译时打开
- **平台差异**：Windows vs Linux 分支
- **内核 Kconfig**：`CONFIG_NET` 决定是否编译网络栈
- **头文件守卫**：`#ifndef HEADER_H`

## 常见陷阱

1. **`#ifdef` 判断"是否定义"而非"值是否为真"**：`#define DEBUG 0` 后 `#ifdef DEBUG` 仍然为真（DEBUG 已定义，只是值为 0）。想按值判断用 `#if DEBUG`（值为 0 时为假）。这是调试日志关不掉的常见原因。
2. **`#if 0 ... #endif` 注释大段代码时内部有 `/* */`**：`#if 0` 之间的代码仍被预处理器扫描，如果内部有未闭合的 `/* */`，会破坏后续。用 `#if 0` 注释代码比 `/* */` 安全（可嵌套），但内部不能有裸露的 `*/`。
3. **头文件守卫宏名冲突**：两个不同的头文件都用了 `#ifndef CONFIG_H` 作为 guard，导致后包含的头被跳过。规则：guard 宏名用**项目前缀 + 路径 + 文件名**确保全局唯一。

## 自测题

**1. 选择**：`#if defined(A) && defined(B)` 表示什么？
- A. A 和 B 的值都非零
- B. A 和 B 都已定义（无论值是多少）
- C. A 和 B 都未定义
- D. A 定义且 B 未定义

<details><summary>答案</summary>
B。`defined(NAME)` 测试宏是否被定义（`#define` 过，哪怕值为 0 或空），与值无关。`#if A && B` 才是判断值非零。`#ifdef A` 等价于 `#if defined(A)`。
</details>

**2. 判断**：`#define DEBUG 0` 后，`#ifdef DEBUG` 块会被编译。

<details><summary>答案</summary>
对。`#ifdef` 只判断"是否定义"，DEBUG 已被 `#define` 定义（值为 0 也算定义），所以 `#ifdef DEBUG` 为真，块会被编译。想按值判断用 `#if DEBUG`（0 为假，不编译）。这是新手常踩的坑：以为 `#define DEBUG 0` 就关掉了调试代码，实际没关。
</details>

**3. 踩坑**：想关掉调试日志，写了 `#define DEBUG 0`，但 `#ifdef DEBUG` 块还是被编译，怎么办？

<details><summary>答案</summary>
两种修法：
1. 用 `#if DEBUG` 替代 `#ifdef DEBUG`——值为 0 时为假，块不编译。
2. 用 `#undef DEBUG` 取消定义，再 `#ifdef DEBUG` 就为假。

推荐方案 1，语义更清晰（按值开关）。或用 `#if defined(DEBUG) && DEBUG` 两者兼顾。
</details>

**4. 应用**：写一个跨平台头文件，Windows（`_WIN32`）用 `__stdcall`，Linux（`__linux__`）用默认调用约定，定义一个 `API_CALL` 宏。

<details><summary>答案</summary>
```c
#ifdef _WIN32
    #define API_CALL __stdcall
#elif defined(__linux__)
    #define API_CALL
#else
    #define API_CALL
#endif
```
大型工程（如内核、UEFI）的条件编译动辄数十层，读代码时先理清 `#ifdef` 分支是哪条路径激活的。
</details>

## 与后续衔接

读任何大型 C 工程，先找 Makefile/CMake 里 `-D` 传递了哪些宏，再读 `#ifdef` 分支，否则容易跟错代码路径。
