# 1.5.1 文件复制

## 本节讲什么

K&R 第一个完整程序：从标准输入读字符，原样写到标准输出。等价 `cat` 无参行为，是所有流式 I/O 的原型。

## 核心代码

```c
#include <stdio.h>

main()              /* K&R 原书风格：省略返回类型 */
{
    int c;          /* ← 必须用 int，不能用 char */

    while ((c = getchar()) != EOF)
        putchar(c);
}
```

### 逐行解析

| 代码 | 作用 |
|------|------|
| `int c` | 存放读到的字符。必须 `int`，不能 `char`（见下方坑） |
| `getchar()` | 从 stdin 读一个字符，返回 `int`。无字符可读时返回 `EOF`（通常是 -1） |
| `(c = getchar())` | 赋值表达式，值就是赋给 c 的值。括号不能省 |
| `!= EOF` | 没到文件结尾就继续循环 |
| `putchar(c)` | 把字符写到 stdout |

### 括号为什么不能省

```c
while (c = getchar() != EOF)    /* ❌ 错！ */
```

`!=` 优先级高于 `=`，等价于 `c = (getchar() != EOF)`——c 拿到的是 0 或 1，不是字符本身。

### 重定向

```bash
./copy < input.txt > output.txt   # 文件复制，程序不碰文件名
./copy < input.txt                # 相当于 cat
```

程序只读写 stdin/stdout，文件由 shell 重定向处理。这是 Unix 哲学：**程序处理流，不处理文件名**。

## HFT 关联

流式处理是 HFT 数据管道的基础——行情解码器逐字节读取网络数据流，和 `getchar` 循环结构一模一样。`EOF` 检测对应网络读返回 0（连接关闭）。

## 常见坑

1. **`char c` 而非 `int c`**：EOF 通常是 -1，若 `char` 是 unsigned，-1 变成 255，某个有效字符（ÿ）被误认为 EOF，循环提前终止。若 `char` 是 signed，EOF(-1) 和真实字符 0xFF 冲突。**必须 `int`**。
2. **省略赋值括号**：`c = getchar() != EOF` 是经典编译警告（`-Wparentheses`）。
3. **`main()` 省略返回类型**：K&R 时代合法，C89 默认 `int`，C99 起非法。现代写 `int main(void)`。

## 自测题

1. 为什么 `c` 必须声明为 `int` 而不是 `char`？
<details><summary>答案</summary>

`getchar()` 返回 `int`，EOF 通常是 -1。如果 `c` 是 `char`：unsigned char 时 -1 变 255，有效字符 ÿ 被误判为 EOF；signed char 时 0xFF 和 EOF 冲突。`int` 能完整区分 256 个字符值 + EOF。

</details>

2. `while (c = getchar() != EOF)` 有什么问题？
<details><summary>答案</summary>

`!=` 优先级高于 `=`，等价 `c = (getchar() != EOF)`，c 拿到 0 或 1，不是字符。`putchar(c)` 会输出 0x00 或 0x01。必须加括号：`while ((c = getchar()) != EOF)`。

</details>

3. 如何用这个程序实现文件复制？
<details><summary>答案</summary>

`./copy < input.txt > output.txt`。程序本身不打开任何文件，shell 的重定向把 stdin/stdout 接到文件上。

</details>

4. `getchar()` 返回 `int` 而非 `char`，这个设计决定的根本原因是什么？
<details><summary>答案</summary>

需要额外表示"无数据可读"的状态（EOF）。`char` 只有 256 个值，全部用于字符；`int` 多出空间放 EOF(-1) 作为哨兵值。这是 C 标准库的一致模式：有效数据 + 额外状态码。

</details>
