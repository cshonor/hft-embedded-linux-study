# 第 1 章 词法「陷阱」

**Lexical Pitfalls** — Andrew Koenig, *C Traps and Pitfalls*

## 本章目标

掌握编译器 **词法分析（lex）** 如何把源码拆成 **token**，从 **字符流** 根源规避歧义，杜绝「看起来合法、拆分逻辑却错了」的隐性 bug。

> 词法 → 语法 → 语义 → 连接 → 库 → 预处理 → 可移植性（全书链路；见 [ch00](../ch00-introduction/)）

## 词法分析是什么

```text
源码字符流  →  [词法分析 lex]  →  token 流  →  [语法分析 parse]  →  ...
                关键字、标识符、
                123、010、'0'、"0"、
                ++、==、/* */
```

本章所有坑：**编译器在切 token 时产生歧义或误读**。

## 速查表

| 陷阱 | 正确习惯 |
|------|----------|
| `if (x = 0)` | `if (0 == x)` 或分两句 |
| 注释屏蔽含 `*/` 的块 | `#if 0` … `#endif` |
| `c == "0"` | `c == '0'` |
| `010` | 写 `07` 或 `0o10` 注释说明八进制 |
| `a+++b` | 自增单独一行，加括号 |
| 宏与关键字同名 | 避免 `#define int` 类恶作剧 |

### Q1: 赋值还是比较？

```c
int flag = 0;
if (flag = 0) {
    printf("checked\n");
} else {
    printf("unchecked\n");
}
```

> 输出什么？为什么？

<details>
<summary>答案与复习指引</summary>

**答案：** 输出 `unchecked`。`flag = 0` 是**赋值**（不是比较），赋值表达式的值为 0，`if (0)` 为假。

**防护：** 写 `if (0 == flag)`（Yoda 条件），漏写一个 `=` 时编译器报错。

**复习：** → [1.1 等号与相等判断](./1.1-等号与相等判断.md)

</details>

### Q2: 注释嵌套陷阱

```c
int code = 0;
/*
    config_reset();
    /* TODO: verify */
    code = 1;
*/
printf("code = %d\n", code);
```

> `code` 的值是多少？为什么？

<details>
<summary>答案与复习指引</summary>

**答案：** `code = 0`（甚至可能编译失败）。C 注释 `/* */` **不能嵌套**——第一个 `*/`（在 TODO 后）就关闭了注释块，后面的 `code = 1;` 变成**正常代码执行**，最后的 `*/` 导致编译错误。

**更隐蔽的情况：** 如果没有最后一个 `*/`，`code = 1` 会静默执行——注释没生效！

**正确做法：** 屏蔽大段代码用 `#if 0 ... #endif`。

**复习：** → [1.2 注释不嵌套](./1.2-注释不嵌套.md)

</details>

### Q3: 字符还是字符串？

```c
char c = 'A';
if (c == "A") {
    printf("match\n");
} else {
    printf("no match\n");
}
```

> 输出什么？编译器会警告吗？

<details>
<summary>答案与复习指引</summary>

**答案：** 输出 `no match`（可能伴随编译警告）。`'A'` 是 `int` 类型（值 65）；`"A"` 是 `char*` 类型（指向字符串字面量的指针）。比较 `char` 和 `char*` ——编译器可能警告类型不匹配，但 C 允许隐式转换。

**实际行为：** `c` 被提升为指针值（如 0x41），与字符串 `"A"` 的地址比较——几乎不可能相等。

**复习：** → [1.3 字符与字符串常量](./1.3-字符与字符串常量.md)

</details>

### Q4: 八进制陷阱

```c
int a = 010;
int b = 10;
int c = 08;

printf("a=%d b=%d c=%d\n", a, b, c);
```

> 三个变量的值分别是多少？`c` 能编译通过吗？

<details>
<summary>答案与复习指引</summary>

**答案：** `a = 8`（前导 0 表示八进制，`010` = 1×8+0 = 8）；`b = 10`（十进制）；`c` **编译失败**——`8` 不是合法的八进制数字（八进制只有 0-7）。

**HFT/嵌入式场景：** 寄存器地址 `0x100` 写成 `0100` 意味着八进制 64，地址完全错误。

**复习：** → [1.4 数字字面量](./1.4-数字字面量.md)

</details>

### Q5: 最长匹配原则

```c
int a = 1, b = 2, c;
c = a+++b;
printf("c=%d a=%d b=%d\n", c, a, b);
```

> `c`、`a`、`b` 分别是多少？

<details>
<summary>答案与复习指引</summary>

**答案：** `c=3, a=2, b=2`。词法分析器采用**最长匹配（maximal munch）**：`a+++b` 被切分为 `(a++) + b`，而非 `a + (++b)`。

**原理：** 词法分析器从左到右贪心匹配最长合法 token。`+++` 不合法，所以切 `++` + `+`。

**工程规则：** 自增/自减单独一行，复杂表达式加括号。

**复习：** → [1.5 最长匹配原则](./1.5-最长匹配原则.md)

</details>
