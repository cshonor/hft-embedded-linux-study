# 6.7 条件编译与注释陷阱

## 本节讲什么

预处理指令 **不被 C 注释屏蔽**。把 `#ifdef` 写在 `/* ... */` 或 `//` 注释里，预处理器 **仍会扫描** 并处理，导致意外分支或语法残片。

## 要点

```c
/*
#ifdef DEBUG
    printf("log\n");
#endif
*/
/* 注释无法“注释掉”预处理指令 */
```

### 正确禁用大段代码

```c
#if 0
    /* 任意代码、甚至非法语法，均不进入编译 */
    broken experimental();
#endif
```

### `#ifdef` vs `#if`

```c
#define DEBUG
#ifdef DEBUG    /* 只问“是否定义”，空宏也算真 */
#endif

#define DEBUG 1
#if DEBUG       /* 可区分 0/1 */
#endif
```

## 代码自测

**题目 1：** 以下代码有什么问题？
```c
#define DEBUG 1
/* 注释 #if DEBUG */
#if DEBUG
    printf("debug");
#endif
```

<details>
<summary>参考答案</summary>

注释中的 `#if DEBUG` 不会被执行——注释在预处理之前被移除（C 标准规定注释在翻译阶段 3 移除，预处理在阶段 4）。但如果注释中有 `*/`，可能提前结束注释块。条件编译指令 `#if`/`#ifdef` 只在注释外有效。防范：不要在注释中放预处理指令，避免混淆。

</details>
