# 10.3.1 中断处理流程

## 本节讲什么

从外设拉高中断线到 **ISR 返回**，CPU 与 NVIC 做了哪些硬件动作？本节梳理 **Cortex-M 中断流程**，说明 **SysTick 触发抢占调度** 与 **PendSV 延迟切换** 的分工，对应 **demo03_preempt** 的 ARM 路径。

## 要点

**Cortex-M 硬件自动流程**：

```
1. 完成当前指令（或异常点）
2. 硬件压栈：xPSR, PC, LR, R12, R3, R2, R1, R0  → 当前 SP（任务或 MSP）
3. 读向量表 → 跳 ISR
4. LR = EXC_RETURN（标记返回用哪个栈、是否 FPU）
5. ISR 执行 ...
6. BX LR  → 硬件弹栈 → 回到被打断代码
```

**向量表**：

```c
/* startup 中 */
void (* const vector_table[])(void) = {
    stack_top,
    Reset_Handler,
    NMI_Handler,
    HardFault_Handler,
    /* ... */
    SysTick_Handler,
    PendSV_Handler,
};
```

**SysTick + PendSV 协作**（FreeRTOS 经典模式，**demo03_preempt**）：

```c
void SysTick_Handler(void) {
    tick_count++;
    if (--current->timeslice == 0) {
        current->timeslice = QUANTUM;
        SCB_ICSR |= PENDSVSET;   /* 仅请求 PendSV，不在此切换 */
    }
}

void PendSV_Handler(void) {
    __asm volatile (
        "mrs r0, psp\n"
        "stmfd r0!, {r4-r11}\n"   /* 保存 callee-saved */
        "str r0, [current]\n"
        /* 选 next，加载 sp，ldmfd ... pc */
    );
}
```

- **为何分两步**：SysTick 优先级可较高保证 tick 准；**上下文切换** 放最低优先级 PendSV，避免嵌套切换混乱

**中断嵌套**：

- 高优先级 ISR 可打断低优先级 ISR
- 每层嵌套多占 **一份硬件压栈帧** → 任务栈或 MSP 深度增加（**10.3.2**）

**中断延迟组成**：

```
延迟 = 当前指令完成 + 更高优先级 ISR + 临界区关中断时间 + 流水线
```

- RTOS 中 `taskENTER_CRITICAL()` 会 **抬 BASEPRI**，屏蔽低于阈值的 IRQ

**Bottom Half / 任务 defer**：

```
UART ISR: 读 FIFO → 入 ringbuf → queue_send_from_isr → 唤醒解析任务
解析任务: 协议状态机、printf（可阻塞）
```

## 常见陷阱

1. **ISR 内调用阻塞 API → 死锁**
   ISR 不在任何任务上下文，调度器不能切到 ISR——调 `os_sem_wait()`、`malloc()`、`printf()` 等阻塞 API 永远等不到唤醒，系统死。**约定**：ISR 只做①读硬件寄存器②清中断标志③`FromISR` 版 API 唤醒任务，剩余逻辑放 bottom half（任务）。RTOS 提供 `xQueueSendFromISR`、`xSemaphoreGiveFromISR` 专为 ISR 用——非 FromISR 版在 ISR 调用是 UB。

2. **ISR 内忘了清中断标志 → 反复重入**
   外设中断标志需软件清除（写寄存器 bit）。若 ISR 末尾不清，退出瞬间 NVIC 看到标志仍 active，再次进 ISR——CPU 100% 在 ISR 歪循环，看门狗复位。**坑**：某些外设要求"先清标志再读数据"，"先读数据再清"会丢一字节。**约定**：进 ISR 第一件事清标志，再处理数据；或按芯片手册规定的顺序。

3. **volatile 误用 → 编译器优化掉 ISR 写的标志**
   `int flag = 0; void ISR(void) { flag = 1; }` 主循环 `while (!flag);`——编译器可能优化为"flag 已读为 0，循环不变"，永远转死。`flag` 必须 `volatile`：`volatile int flag;` 强制每次重新读。**完整规则**：ISR 写、主循环读的标志必须 volatile；但如果标志是 `uint64_t` 或结构体，volatile 不保证原子——仍需关中断或 `__atomic_load`。

## 自测题

**1.（选择）** Cortex-M 进入 ISR 时，硬件自动压栈的寄存器数量是？
- A. 4 个（R0-R3）
- B. 8 个（R0-R3, R12, LR, PC, xPSR）
- C. 16 个（全部）
- D. 取决于 ISR 优先级

<details><summary>答案</summary>

**B**。Cortex-M 硬件自动压栈 **8 个寄存器**：R0, R1, R2, R3, R12, LR, PC, xPSR——这是 C ABI 的 caller-saved 寄存器集，保证 ISR 可像普通 C 函数调用。R4-R11（callee-saved）由 ISR 自己 `push`/`pop`。FPU 启用时额外压 S0-S15, FPSCR。**坑**：任务切换在 PendSV 里手动 `stmdb r0!, {r4-r11}` 保存 callee-saved——硬件不会自动做这步。

</details>

**2.（判断）** ISR 内可以调用 `printf` 调试输出。

<details><summary>答案</summary>

**错**——生产代码严禁。`printf` 通常：
1. 调 `write` 系统调用（Linux）或 UART 阻塞发送（裸机）——阻塞。
2. 内部用 `malloc`/缓冲——可能拿不到锁。
3. 执行时间长——ISR 应微秒级返回。
**调试时**可用专门的 `ITM_SendChar`（Cortex-M ITM 跟踪口）或 `semihosting`——非阻塞、专为 ISR 设计。**生产代码**用 ringbuf 缓存日志，ISR 入队、任务出队打印。

</details>

**3.（踩坑）** ISR 内 `volatile int flag = 0;` 改为 `flag = 1;`，主循环 `while (flag == 0);` 仍在某次编译后死循环。为什么？

<details><summary>答案</summary>

**`volatile int flag = 0;` 是局部变量**——每次进 ISR 重新初始化为 0，主循环读的是另一个变量（全局或堆栈）。正确：
```c
static volatile int flag = 0;   /* 全局 + volatile */
void ISR(void) { flag = 1; }
void main_loop(void) { while (flag == 0); /* ... */ }
```
**坑点**：
1. `static` 保证全局生命周期，不会重置。
2. `volatile` 强制每次重新读，不被优化掉。
3. 仍不保证原子——若 `flag` 是 `uint64_t`，32 位 CPU 上读/写需多条指令，ISR 可能在中间打断。用 `volatile sig_atomic_t`（C 标准）或 `__atomic_load_n(&flag, __ATOMIC_ACQUIRE)`。
**完整规则**：ISR 与任务共享变量，必须 `volatile` + 类型 ≤ CPU 字长 + 必要时关中断/原子操作。

</details>

**4.（应用）** 设计一个 UART 接收驱动：ISR 收字节入 ringbuf，达到 64 字节或遇到 `\n` 时唤醒解析任务。给出 ISR 骨架和唤醒机制。

<details><summary>答案</summary>

```c
#define BUF_SZ 256
struct uart_rx {
    uint8_t  buf[BUF_SZ];
    volatile uint16_t head;
    uint16_t line_len;       /* 当前行长度（任务读，ISR 写） */
};
static struct uart_rx rx;
static os_sem_t rx_ready;

void UART_ISR(void) {
    uint8_t b = UART->DR;             /* 读数据同时清 RXNE 标志 */
    uint16_t h = rx.head;
    rx.buf[h & (BUF_SZ - 1)] = b;
    rx.head = h + 1;
    rx.line_len++;

    int wake = 0;
    if (b == '\n') wake = 1;
    else if (rx.line_len >= 64) wake = 1;
    /* 溢出保护 */
    if ((uint16_t)(rx.head - /*tail*/) >= BUF_SZ) wake = 1;

    if (wake) {
        rx.line_len = 0;
        os_sem_give_from_isr(&rx_ready, /*pxHigherPriorityTaskWoken=*/NULL);
    }
}

void parse_task(void *arg) {
    while (1) {
        os_sem_take(&rx_ready, OS_WAIT_FOREVER);
        /* 处理 rx.buf 中累积的一行/64 字节 */
        process_line(&rx);
    }
}
```
要点：
- **ISR 只做**：读 DR、入 ringbuf、判唤醒条件、`FromISR` 唤醒——微秒级返回。
- **任务做**：协议状态机、printf、malloc——任意阻塞。
- **ringbuf 无锁**：SPSC（ISR 写、task 读），`volatile head` 即可。
- **唤醒策略**：行结束或长度阈值——兼顾延迟与吞吐。
- **溢出兜底**：ringbuf 满强制唤醒，避免丢字节静默。

</details>
