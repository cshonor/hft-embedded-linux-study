# 6.7.1 地址对齐：aligned

## 本节讲什么

**对齐** 指对象地址 mod N == 0。硬件要求 **4 字节 int**、**8 字节 double**、**16 字节 SSE**、**64 字节 cache line** 等于不同 N。编译器默认按 ABI 对齐；`aligned` 属性 **提高** 对齐要求。

## 要点

```c
char c __attribute__((aligned(64)));   /* 64 字节对齐 — cache line */
int  x __attribute__((aligned(8)));

_Static_assert(__alignof__(x) >= 8, "align");
```

```c
/* 栈/堆数组手动对齐 — C11 */
#include <stdalign.h>
alignas(64) char buf[128];
```

| N | 典型用途 |
|---|----------|
| 4 | ARM 32-bit 字 |
| 8 | double / 指针 |
| 16 | NEON / SSE |
| 64 | 防 false sharing（DPDK per-lcore） |

```bash
gcc -std=gnu11 -O2 -c align.c
objdump -t align.o | grep -E 'buf|c '
```

- **`__alignof__(type)`** / **`_Alignof`**：查询对齐
- DMA buffer 常 **`posix_memalign(..., 4096, size)`** 或 **`aligned_alloc`**
- 内核 **`kmalloc`** 保证 `SMP_CACHE_BYTES` 对齐变体

## 常见陷阱

1. **`aligned` 只能"提高"，不能"降低"对齐**
   `__attribute__((aligned(N)))` 中 N 必须 ≥ 类型自然对齐。对 `char` 用 `aligned(1)` 是无意义但合法；对 `int` 用 `aligned(2)` 会触发警告或忽略——编译器不会主动降低对齐，因为可能违反 ABI。要降低对齐用 `packed`，但代价是访问性能/原子性。

2. **栈上变量 `aligned` 在某些 GCC 版本不可靠**
   `char buf[128] __attribute__((aligned(64)));` 在栈上要求 64 字节对齐，老版 GCC（< 4.6）或某些 ABI 下可能只保证到 16 字节。**C11 `alignas`** 是标准写法，更可靠。内核用 `__aligned(N)` 宏统一封装，但在栈上仍依赖编译器版本。

3. **`aligned` 不能修复已存在的 false sharing**
   对**单个变量** `aligned(64)` 防止它与其他变量共享 cache line。但若结构体内**多个成员**被不同 CPU 频繁写，整体对齐结构体没用——成员间仍在同一 cache line。需要把每个 hot 字段拆到独立 `aligned(64)` 变量，或用 `____cacheline_aligned`（内核）/ `__rte_cache_aligned`（DPDK）放在结构体内**字段间**。

## 自测题

**1.（选择）** 下列哪条对齐声明是合法且有意义的？
- A. `char c __attribute__((aligned(1)));`
- B. `int x __attribute__((aligned(2)));`
- C. `char buf[128] __attribute__((aligned(64)));`
- D. `double d __attribute__((aligned(4)));`

<details><summary>答案</summary>

**C**。`char` 自然对齐 1，`aligned(1)` 无意义；`int` 自然对齐 4，`aligned(2)` 会被忽略或警告（不能降低）；`double` 自然对齐 8，`aligned(4)` 同理不能降低。只有 **C** 是"提高对齐"——`char[128]` 提到 64 字节对齐用于 cache line 对齐，常见且合法。

</details>

**2.（判断）** `aligned(N)` 保证了对象地址 mod N == 0，无论对象在栈、堆、全局段。

<details><summary>答案</summary>

**对，但有 caveat**。栈/全局段由编译器在编译期布局，保证对齐。**堆**需 `posix_memalign` / `aligned_alloc` / `memalign`——普通 `malloc` **不保证**大于 `alignof(max_align_t)`（通常 16）的对齐。DPDK `rte_malloc` 也提供 `rte_malloc_socket` + 对齐参数。坑：对全局 `aligned(64)` 变量取地址可以，但 `malloc` 后强转 `aligned` 指针运行时仍是 `malloc` 的对齐——`aligned` 属性只对**定义**生效，不对**指针类型**生效。

</details>

**3.（踩坑）** 多线程程序中两个 `int counter_a, counter_b;` 被两个 CPU 频繁自增，性能远低于预期。`perf c2c` 显示 false sharing 严重。但加上 `int counter_a __attribute__((aligned(64)));` 后性能几乎没改善。为什么？

<details><summary>答案</summary>

**坑在只对齐了单个变量**：`counter_a` 在 64 字节边界，但 `counter_b` 紧跟其后（4 字节偏移），**两者仍在同一 cache line**。修复方式：
```c
struct counters {
    int a __attribute__((aligned(64)));
    int b __attribute__((aligned(64)));
};
```
或独立结构体：
```c
static int counter_a __aligned(64);
static int counter_b __aligned(64);
```
关键：false sharing 是**多个变量在同 cache line** 问题，必须**每个变量独立对齐到 cache line**，仅对齐其中一个无济于事。内核 `____cacheline_aligned` / `____cacheline_internodealigned_in_smp` 专治此症。

</details>

**4.（应用）** 给定 `void *p`（可能是栈/堆/全局），写一个可移植函数判断其是否 N 字节对齐。

<details><summary>答案</summary>

```c
#include <stdint.h>
#include <stdbool.h>

static inline bool is_aligned(const void *p, size_t n) {
    return ((uintptr_t)p & (n - 1)) == 0;
}
```
原理：N 是 2 的幂时 `n-1` 是掩码（低 `log2(N)` 位全 1），按位与为 0 即对齐。**关键点**：
- 必须 `uintptr_t`（无符号，足以容纳指针），不能用 `int`（截断）。
- N 必须是 2 的幂——非 2 幂对齐无意义（硬件也不支持）。
- C11 后更标准：`_Alignof(T)` 取类型对齐，再 `is_aligned(p, _Alignof(T))`。

</details>
