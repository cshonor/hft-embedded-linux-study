# 6.9 位字段

## 本节讲什么

**位域（bit-fields）**：在结构体中为成员指定**占用的 bit 数**，紧凑打包标志位；常见于**硬件控制/状态寄存器**本地建模。

## 要点

```c
struct flags {
    unsigned int is_valid : 1;
    unsigned int type     : 3;
    unsigned int priority : 4;
    /* 可能仍有 padding 到 int 边界 */
};
```

- 语法：`类型 成员名 : 位数;`
- 类型多为 **`unsigned int`** / **`int`**（实现相关）
- **布局由编译器决定**：位序、是否跨字、signed 位域算术 —— **跨平台不兼容**
- **`&位域成员` 非法**（无独立地址，不能取址）

## 适用场景

| 适合 | 不适合 |
|------|--------|
| 本地 MCU 寄存器模型 | 网络协议 on-wire 格式 |
| 驱动私有状态压缩 | 跨编译器二进制 interchange |
| 无人机电机/中断掩码 | 需严格 ABI 的 API |

## 与手动掩码对比

```c
#define CTRL_ENABLE  (1u << 0)
reg |= CTRL_ENABLE;

/* vs 位域 */
ctrl.enable = 1;
```

- 可移植协议：`uint32_t reg;` + 宏 **`(reg >> n) & mask`**
- 单平台固件：位域可读性更好

## 考点

- 位域 vs 位运算：面试常问优缺点
- 大小与对齐不可手算，需看编译器输出或 `sizeof`

## 常见陷阱

1. **对位域成员取地址非法**：`&flags.type` 编译错误——位域没有独立地址（它只占几个 bit，不是完整字节）。因此 `scanf("%d", &flags.type)` 不行，位域不能传入需要指针的函数。只能先读到一个普通变量再赋值：`int t; scanf("%d", &t); flags.type = t;`。
2. **位域布局跨平台不兼容**：位序（MSB/LSB first）、是否跨存储单元、signed 位域的符号扩展都由编译器决定。同一 `struct` 在 x86 和 ARM 上 `sizeof` 和位排列可能不同。**网络协议/on-wire 格式绝不用位域**，用 `uint32_t` + 显式移位掩码。
3. **signed 位域的算术实现相关**：`signed int x:3;` 赋值 8（超出 3 位范围）的结果是实现定义。尽量用 `unsigned` 位域；若必须表示负数，明确用 `signed` 并测试目标编译器行为。

## 自测题

**1. 选择**：`struct { unsigned a:3; } x; x.a = 5;` 后 `x.a` 的值是？
- A. 5
- B. 7
- C. 1
- D. 未定义

<details><summary>答案</summary>
C（通常）。3 位无符号数范围是 0–7，但 5 的二进制 101 能表示，所以 x.a = 5 没问题。若赋 8（超出 3 位），则截断为 0。题目若问 `x.a = 8`，答案才是 0（截断）。注意：unsigned 位域范围是 0 到 2^n - 1，超出则取低位。
</details>

**2. 判断**：可以对位域成员取地址 `&flags.enable`。

<details><summary>答案</summary>
错。位域成员没有独立地址（它只占 1 个 bit，不占完整字节），`&` 运算符对位域非法。需要指针的场景（如 scanf、传参）必须先用普通变量中转。这是位域和普通成员的关键区别。
</details>

**3. 踩坑**：用位域定义网络协议头 `struct Header { unsigned ver:4; unsigned len:4; unsigned type:8; }`，在 x86 和 ARM 上 sizeof 不同，抓包解析错位，为什么？

<details><summary>答案</summary>
位域的**位序、是否跨字节、对齐**全部由编译器决定：
1. x86 可能 ver 在低 4 位，ARM 可能 ver 在高 4 位（位序不同）。
2. 编译器可能在 4 位后补 4 位 padding，也可能紧凑打包。
3. sizeof 可能是 2 也可能是 4（对齐填充不同）。

修复：网络协议用 `uint16_t` + 显式移位：`uint8_t ver = (buf[0] >> 4) & 0xF;`。位域只用于**单平台**的硬件寄存器建模（如 STM32 CMSIS）。
</details>

**4. 应用**：用位域定义一个中断状态寄存器（enable 1 位、type 2 位、priority 4 位），并说明为什么不能用 `scanf` 直接读入 priority。

<details><summary>答案</summary>
```c
struct IntStatus {
    unsigned enable   : 1;
    unsigned type     : 2;
    unsigned priority : 4;
};

struct IntStatus s;
/* scanf("%u", &s.priority);  /* 错误：位域不能取地址 */
unsigned p;
scanf("%u", &p);
s.priority = p;   /* 通过普通变量中转 */
```
位域适合本地寄存器建模（可读性好），但要注意不能取地址、不能跨平台。Linux 内核寄存器定义常混用位域和移位宏。
</details>
