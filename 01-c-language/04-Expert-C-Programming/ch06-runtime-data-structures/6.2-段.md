# 6.2 段

## 本节讲什么

C 程序在内存里不是「一整块字节」，而是按 **段（segment / section）** 组织：**代码、只读数据、可写全局数据、未初始化数据、堆、栈** 各司其职。本节建立 **Linux 典型进程虚拟地址布局**（低地址 → 高地址），对照 **ch05** 的 ELF 节名，并用 **demo01_memory_layout** 打印各区域地址验证直觉。

## 要点

### 五大内存区域（进程视角）

典型 **Linux x86-64** 用户进程（具体地址因 **ASLR** 每次不同，**相对顺序** 稳定）：

```text
  高地址  ┌─────────────────────────┐
          │         栈 stack         │  ← 向下增长（6.5, 6.9）
          │            ↓             │
          ├─────────────────────────┤
          │      （映射区 / 空洞）    │
          ├─────────────────────────┤
          │         堆 heap          │  ← 向上增长（malloc, 6.9）
          ├─────────────────────────┤
          │   .bss  未初始化全局/静态  │
          ├─────────────────────────┤
          │   .data 已初始化全局/静态  │
          ├─────────────────────────┤
          │   .rodata 只读常量        │
          ├─────────────────────────┤
          │   .text  程序代码         │
  低地址  └─────────────────────────┘
```

| 区域 | 典型内容 | 存储期 | 谁分配 |
|------|----------|--------|--------|
| **`.text`** | 函数机器码 | 程序生命周期 | 链接器 + 载入只读映射 |
| **`.rodata`** | 字符串字面量、`const` 全局 | 程序生命周期 | 同上 |
| **`.data`** | 有初值的全局 / 文件内 `static` | 程序生命周期 | ELF 映像 **拷贝**（**6.3**） |
| **`.bss`** | 无初值的全局 / 文件内 `static` | 程序生命周期 | 载入时 **清零**（**NOBITS**） |
| **堆 heap** | `malloc` / `mmap` 块 | 直到 `free` | 运行时库 / 内核 |
| **栈 stack** | 局部变量、返回地址、调用链 | 函数调用期间 | 编译器 + CPU **rsp/rbp** |

### ELF 节与运行时区域的对应

| C 源码 | ELF 节 | 运行时 |
|--------|--------|--------|
| `int g = 1;` | **`.data`** | 可写数据段 |
| `int g;` | **`.bss`** | 可写数据段（零初始化） |
| `static int s;`（文件作用域） | **`.bss`** | 同进程内持久 |
| `void foo(void){...}` | **`.text`** | 可执行、通常只读 |
| `"hello"` | **`.rodata`** | 只读 |
| `int x;`（函数内 **auto**） | （无 ELF 节） | **栈**（**6.5**, **6.6**） |
| `static int cnt;`（函数内） | **`.bss` / `.data`** | **不在栈上**（**6.6**, **demo02**） |

### demo01 地址模式（定性）

**demo01_memory_layout** 打印：

- **`main` / 函数指针** → **`.text`** 附近（低地址区）
- **`ro_msg`** → **`.rodata`**
- **`global_init`、`static_init`** → **`.data`**
- **`global_uninit`、`static_uninit`、`file_static`** → **`.bss`**
- **`malloc` 返回** → **堆**
- **`&stack_var`** → **栈**（通常最高）

**注意**：ASLR 下绝对地址每次运行变化；比较 **相对高低** 与 **同区域聚类** 即可。

### 与 ch05 段表一致

**5.1** 已在 **`.o`** 级别区分：

```bash
readelf -S main.o | egrep '\.(text|data|bss|rodata)'
size main.o    # text / data / bss 三列摘要（6.11）
```

链接后 **可执行文件** 仍保留这些节，载入器按 **Program Header** 映射（**6.3**）。

### 堆与栈不是 ELF 里的「节」

| 对象 | 在 ELF 文件中？ | 何时出现 |
|------|-----------------|----------|
| `.text/.data/.bss` | **有**（或 bss 为 NOBITS） | 链接时确定 **大小/内容** |
| **堆** | **无** | **`_start` / crt** 初始化 brk 或 mmap  arena（**6.4**, **6.9**） |
| **栈** | **无** | 内核为进程建 **栈映射**，`rsp` 指向栈顶 |

### 权限与安全（预告）

- **`.text` / `.rodata`**：**读 + 执行 / 只读**，防止代码被改写
- **`.data` / `.bss` / 堆 / 栈**：可读写，**不可执行**（NX / W^X，**6.3**）
- 把数据当函数跳转 → **SIGSEGV**（**ch07 7.7** 总线 / 段错误）

## 常见陷阱

1. **以为字符串字面量 `"hello"` 在 `.data`**：实际在 **`.rodata`**（只读），尝试 `s[0] = 'H'` 触发 **SIGSEGV**。常见写法 `char *p = "hi"; p[0] = 'H';` 崩溃；而 `char buf[] = "hi"; buf[0] = 'H';` 能改——因为 `buf` 是栈上数组，`"hi"` 只是初始化源，拷贝到栈。
2. **以为函数内 `static int s;` 在栈上**：实际在 **`.bss`**（未初始化）或 **`.data`**（有初值），**程序生命周期存活**，地址固定在数据段，不在栈。`auto int x;` 才在栈上，函数返回失效。
3. **以为 `.bss` 占磁盘空间**：`.bss` 是 **NOBITS**——ELF 文件里**不占字节**，只记录大小和位置；载入时内核分配并**清零**。所以 `int big[1000000];`（全局未初始化）几乎不增加可执行文件大小，但运行时占 4MB 内存。

## 自测题

**1.（选择）** `char *s = "hello";` 中 `"hello"` 存在哪个段？
- A. `.text`  B. `.data`  C. `.rodata`  D. 栈

<details><summary>答案</summary>
C。字符串字面量是只读常量，进 `.rodata`。`s` 这个指针变量本身在哪取决于声明位置（全局在 `.data`/`.bss`，局部在栈），但它指向的 `"hello"` 在 `.rodata`。改 `s[0]` 会 SIGSEGV。
</details>

**2.（判断）** `int g;`（全局未初始化）在 ELF 文件里占 4 字节。
<details><summary>答案</summary>
错。`g` 进 `.bss`，是 **NOBITS** 节——文件里**不占字节**，只记录大小。载入时内核清零分配。`int g = 0;` 才进 `.data` 占 4 字节。用 `size a.out` 看 bss 列能验证。
</details>

**3.（踩坑）** `char buf[] = "hi"; buf[0] = 'H';` 能改，但 `char *p = "hi"; p[0] = 'H';` 崩溃，为什么？
<details><summary>答案</summary>
`buf[]` 是**栈上数组**，`"hi"` 只是初始化源，内容被拷贝到栈，`buf` 可写。`p` 是指针，指向 `.rodata` 里的 `"hi"`（只读），`p[0] = 'H'` 写只读页 → SIGSEGV。写法上差一个 `[]` vs `*`，语义完全不同。
</details>

**4.（应用）** 画出 Linux x86-64 进程从低地址到高地址的内存区域布局，标出 `.text`/`.rodata`/`.data`/`.bss`/堆/栈的位置和增长方向。
<details><summary>答案</summary>
低地址→高地址：`.text`（代码）→ `.rodata`（只读常量）→ `.data`（已初始化全局）→ `.bss`（未初始化全局）→ 堆（向上增长，malloc）→ （映射区/空洞）→ 栈（向下增长，最高地址）。堆向上、栈向下相向生长。ASLR 下绝对地址每次变化，**相对顺序稳定**。用 `demo01_memory_layout` 打印各区域地址验证。
</details>
