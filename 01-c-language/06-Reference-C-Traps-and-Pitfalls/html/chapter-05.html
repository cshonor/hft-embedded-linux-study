5.1

printf / 可变参数 stdarg 系列

本节讲什么

printf 及同类可变参数函数 不做实参类型检查，仅按格式串从栈/寄存器 按约定宽度 取二进制位。格式符与实参不匹配、漏传参数、%s 传 NULL —— 编译通常 零告警，运行输出乱码或 直接崩溃。

要点

5.1.1 格式符与实参类型不匹配

int a = 10;
printf("%f", a);   /* %f 读 8 字节 double，int 仅 4 字节 → 脏内存 */

long x = 0x123456789ABC;
printf("%d", x);   /* 64 位下截断高位 */
格式符 期望实参类型
%d %i int
%u unsigned int
%ld %lu long / unsigned long
%lld %llu long long / unsigned long long
%f %lf double
%s char *
%p void *

5.1.2 漏传参数

printf("%d %s");   /* 从栈读垃圾值，不可预测 */

5.1.3 默认参数提升（default argument promotions）

可变参数中：

  • float → 提升为 double（故 %f 对应 double，无 %f 配 float 的独立约定）
  • char / short → 提升为 int

写 printf("%c", ch) 时 ch 已是 int 宽度。

5.1.4 %s 要求非空指针

char *p = NULL;
printf("%s", p);   /* 解引用空指针 → 崩溃 */

工程规范

  • 开启 -Wformat（-Wall 通常包含），GCC/Clang 能捕获 部分 静态格式串错误
  • 动态格式串（用户输入）极度危险
  • 64 位：size_t 用 %zu，ptrdiff_t 用 %td

代码自测

题目 1： 以下 printf 调用有什么问题？

printf("%d %d %d\n", 1);  // 参数不够
printf("%d\n", 1, 2, 3);   // 参数过多
参考答案

参数不够：%d 读取 1 后，第二三个 %d 读取栈上垃圾值——输出未定义。 参数过多：多余参数被忽略——通常不会崩溃，但是浪费。 printf 是变参函数，无法在编译期检查参数数量和类型。防范：1) 开启 -Wformat 警告；2) C++ 中用类型安全的 iostream 或 fmt 库。

5.2

字符串处理函数

本节讲什么

<string.h> 中 strcpy / strcat / strlen / strcmp 等是 安全重灾区：多数接口 不检查缓冲区长度，溢出、缺 \0、NULL 解引用在协议解析、驱动、嵌入式中极常见。

要点

5.2.1 strcpy — 无长度检查

char buf[16];
strcpy(buf, very_long_str);   /* 覆盖相邻栈/堆 → 漏洞 */

替代：strncpy / snprintf / 自研带边界拷贝；Linux 内核常用 strlcpy（非标准 C）。

strncpy 陷阱：拷贝 n 字节后 若源串 ≥ n，不会补 \0：

char dst[4];
strncpy(dst, "hello", 4);   /* dst = "hell"，无终止符 */
strlen(dst);                /* 越界读 */

安全模式：

strncpy(dst, src, sizeof(dst) - 1);
dst[sizeof(dst) - 1] = '\0';

5.2.2 strcat — 同样无边界

拼接前不校验目标剩余空间；须先 strlen(dst) + strlen(src) < cap。

5.2.3 strlen — 不含 \0

strlen("abc") == 3；存放需 strlen(src) + 1 字节。

经典 off-by-one：

char buf[strlen(src)];   /* 少 1 字节，无法存 '\0' */

5.2.4 strcmp — NULL 崩溃

strcmp(NULL, "test");    /* 内部解引用 NULL → 崩溃 */

调用前判空，或封装安全比较。

代码自测

题目 1： 以下代码有什么缓冲区溢出风险？

char buf[10];
strcpy(buf, user_input);  // user_input 长度未知
strcat(buf, suffix);      // buf 可能已满
参考答案

strcpy 和 strcat 不检查缓冲区大小——如果 user_input 超过 10 字节，缓冲区溢出。安全替代：

strncpy(buf, user_input, sizeof(buf) - 1);
buf[sizeof(buf) - 1] = '\0';
// 或
snprintf(buf, sizeof(buf), "%s%s", user_input, suffix);

snprintf 是最安全的选择——自动截断并保证终止。

5.3

内存分配 malloc / free

本节讲什么

堆内存管理错误 —— 判空遗漏、双重释放、释放栈地址 —— 往往 延迟爆发：堆元数据损坏后，后续 malloc/free 随机卡死或崩溃，极难调试。

要点

5.3.1 malloc(0) 行为未标准化

实现可能返回 NULL 或 唯一非 NULL 指针；不能统一当作「分配失败」。

5.3.2 失败返回 NULL

int *p = malloc(1000);
*p = 1;   /* p==NULL 时崩溃 */

必须判空；大分配考虑 calloc / 检查溢出 n * size。

5.3.3 双重 free / free 栈内存

int *p = malloc(4);
free(p);
free(p);        /* 双重 free → 堆损坏 */

int arr[10];
free(arr);      /* 只能 free 堆指针 → UB */

释放后置 p = NULL，避免悬空指针误用。

5.3.4 free(NULL) 合法

free(NULL) 无操作，安全；可简化错误路径。

工程规范

  • 谁分配谁释放；模块边界用明确 ownership
  • 避免 malloc 后 memcpy 到栈再 free 的复杂生命周期混乱

代码自测

题目 1： 以下代码有什么内存错误？

int* p = malloc(sizeof(int) * 10);
free(p);
free(p);         // 错误1
int* q = malloc(sizeof(int));
free(q);
q[0] = 42;       // 错误2
int* r = realloc(NULL, 100);
free(r);
r = malloc(50);  // 错误3
free(r);
参考答案

错误1：double free——释放已释放的内存，未定义行为。错误2：use-after-free——释放后访问，未定义行为。错误3：dangling pointer——r 已 free，再赋值前使用了 r（虽然这里 r = malloc 覆盖了旧值，但如果 realloc 失败返回 NULL 而 r 被覆盖则原内存泄漏）。规则：free 后立即置 NULL。

5.4

字符分类函数 ctype.h

本节讲什么

isdigit / isspace / isprint 等接受 int，合法取值仅为 unsigned char 能表示的值 或 EOF。传入 带符号 char 的负值（如 0xFF）会导致内部查表 越界 → UB。

要点

char ch = 0xFF;           /* 若 char 有符号 → -1 */
if (isprint(ch)) { }      /* 危险：负索引 */

if (isprint((unsigned char)ch)) { }   /* 安全 */

原因

函数实现通常：

return table[(unsigned char)c];

若 c 为负，(unsigned char)c 在传入前已按 int 提升，负 char 仍是负 int，索引可能为负。

工程规范

  • 凡 ctype.h 函数：入参强转 (unsigned char)
  • 已确认为 EOF 时直接分支，勿传 EOF 给 isprint 等（仅部分函数明确定义 EOF 行为）

代码自测

题目 1： 以下代码有什么问题？

char c = getchar();
if (isalpha(c)) { ... }
参考答案

c 声明为 char，getchar() 返回 int——如果 char 是 signed 且 c 的值为负（如某些扩展 ASCII 字符），传给 isalpha 可能导致越界访问（isalpha 实现常用查表，负索引越界）。正确：

int c = getchar();
if (c != EOF && isalpha(c)) { ... }

isalpha 等函数的参数应为 int 且值为 unsigned char 范围或 EOF。

5.5

文件 I/O：fopen / gets / fgets

本节讲什么

标准 I/O 中 gets 已废弃（C11 移除），fgets / fopen 仍有典型误用：无长度限制的输入、忽略 \n、打开失败未判空。

要点

5.5.1 gets — 彻底禁用

gets(buf);   /* 无长度参数，任意长输入 → 必溢出 */

一律 用 fgets(buf, sizeof(buf), stdin) 或平台安全 API。

5.5.2 fgets 保留换行符

fgets(line, sizeof(line), fp);
/* line 可能为 "hello\n\0" — 比较/存储前需去掉 \n */
line[strcspn(line, "\n")] = '\0';

5.5.3 fopen 失败返回 NULL

FILE *fp = fopen(path, "r");
if (!fp) { perror(path); return -1; }
/* 未判空直接 fread → 崩溃 */

代码自测

题目 1： 以下代码有什么问题？

FILE* fp = fopen("data.txt", "w");
fputs("hello", fp);
// 程序崩溃，没有 fclose
参考答案

没有 fclose——缓冲区中的数据可能未写入文件，数据丢失。fclose 刷新缓冲区并关闭文件描述符。如果程序崩溃，缓冲区数据丢失。防范：1) 始终 fclose；2) 关键数据用 fflush(fp) 强制刷新；3) 用 setvbuf(fp, NULL, _IONBF, 0) 关闭缓冲（性能降低但数据安全）。

5.6

数学库与隐式转换

本节讲什么

<math.h> 函数（如 sqrt / sin）参数与返回值均为 浮点（多数为 double）。整型实参会 提升为 double，返回值若赋给整型会 截断小数，精度与范围陷阱在数值代码、嵌入式标定中常见。

要点

int x = sqrt(4);        /* 合法：结果为 2.0 → 截断为 2 */
double y = sqrt(2);     /* 正确接收 */

float f = 1.0f;
sqrt(f);                /* float 提升为 double 传入 */

链接注意

使用 sqrt 等需 链接数学库 -lm（部分平台 gcc 默认已链，嵌入式/静态链接常需显式）：

gcc main.c -lm

与 ch04 4.5 库顺序问题叠加。

其他陷阱

  • pow(0.1, 2) 浮点误差 — 勿用 == 比较浮点结果
  • 大整数开方：先转 double 可能 丢失精度（>2^53）

题目 1： 以下代码链接时报「未定义引用 sin」，原因是什么？

#include <math.h>
double x = sin(3.14);
// gcc main.c  (不加 -lm)
参考答案

数学函数在 libm 中，需要 -lm 链接：gcc main.c -lm。某些系统（如 macOS）的 libc 包含数学函数，不需要 -lm，但 Linux 需要。这是库链接顺序和依赖的常见问题。排查：用 nm -D /usr/lib/libm.so | grep sin 确认函数在哪个库中。

章节自测

库函数陷阱：printf、字符串、堆、ctype、IO。看代码 → 想答案 → 点开验证。

Q1printf 格式符不匹配
long big = 1000000000L;
printf("big = %d\n", big);       // A
printf("big = %ld\n", big);     // B

size_t sz = sizeof(int);
printf("sz = %d\n", sz);         // C
printf("sz = %zu\n", sz);       // D

A 和 C 在 64 位系统上可能出什么问题？

答案与复习指引

答案： - A：%d 读 int（4 字节），但 long 在 LP64 上是 8 字节——读了一半，或者后续参数错位。UB，可能输出错误值。 - B：%ld 正确匹配 long。 - C：size_t 在 64 位上是 unsigned long（8 字节），%d 读 4 字节——UB。 - D：%zu 正确匹配 size_t。

规则： 格式符必须与类型严格对应。64 位系统用 %ld/%lld/%zu。

复习： → 5.1 printf 与可变参数

Q2strncpy 的坑
char buf[5];
strncpy(buf, "hello world", 5);
buf[5] = '\0';
printf("%s\n", buf);

这段代码有什么问题？

答案与复习指引

答案： 两个问题： 1. 越界写： buf[5] 越界（数组只有 0-4）。strncpy 在源串 ≥ n 时不追加 \0，需要手动加——但这里位置错了。 2. 无终止符： strncpy(buf, "hello world", 5) 只拷贝 5 字节 hello，不追加 \0。正确做法是 buf[4] = '\0' 或 buf[sizeof(buf)-1] = '\0'。

规则： strncpy 后手动在最后一个位置加 \0——buf[n-1] = '\0'。

复习： → 5.2 字符串函数

Q3malloc 与 free 陷阱
char *p = malloc(0);
if (p == NULL)
    printf("NULL\n");
else {
    printf("non-NULL\n");
    free(p);
    free(p);   // 双重 free
}

malloc(0) 返回什么？双重 free 会怎样？

答案与复习指引

答案： - malloc(0)：实现定义——可能返回 NULL，也可能返回一个非空但不可解引用的指针。两种都合法。 - 双重 free：UB——堆元数据已被破坏，可能导致堆崩溃或安全漏洞。free(NULL) 是安全的（什么也不做），但 free(非空指针) 两次是 UB。

规则： free 后置 p = NULL；同一指针只 free 一次。

复习： → 5.3 malloc 与 free

Q4ctype 入参陷阱
char c = 0xFF;   // char signed 时 c = -1
if (isprint(c))
    printf("printable\n");
else
    printf("not printable\n");

在 char 为有符号的平台上，这段代码可能出什么问题？

答案与复习指引

答案： UB。isprint 的参数要求是 EOF(-1) 或 unsigned char 范围（0-255）的值。当 char 有符号时，c = 0xFF 变成 -1，与 EOF 冲突——实现可能用 -1 作为查找表索引，导致越界访问。

修正： isprint((unsigned char)c) — 强制转换为 unsigned char 再传给 ctype 函数。

复习： → 5.4 ctype 字符分类

Q5fgets 换行处理
char buf[16];
FILE *f = fopen("data.txt", "r");
if (f) {
    fgets(buf, sizeof(buf), f);
    // 文件第一行是 "hello\n"
    printf("[%s]\n", buf);
}

输出中是否包含换行符？如何去掉？

答案与复习指引

答案： 输出 [hello\n]（fgets 保留换行符）。与 gets（已移除）不同，fgets 读到 \n 时把它存入缓冲区。

去掉换行：

buf[strcspn(buf, "\n")] = '\0';

规则： fgets 后必须处理换行符——strcspn 比 strlen-1 更安全（不假设最后一定是 \n）。
