2.1

运算符优先级

本节讲什么

词法切完 token 后，语法分析按 优先级与结合性 把 token 组装成表达式树。记不全优先级、少写括号，程序 编译通过但逻辑完全跑偏——本章最高频坑。

要点

易错：== 高于 &

位运算 & | ^ 优先级 低于 关系运算 == !=：

if (x & 0x01 == 1)   /* 等价 if (x & (0x01 == 1)) → if (x & 1) */
if (x & 0x02 == 2)   /* 等价 if (x & (0x02 == 2)) → if (x & 0) 永远假！ */
错误写法 实际解析 本意
val & mask == 1 val & (mask == 1) (val & mask) == 1
a \| b == 0 a \| (b == 0) (a \| b) == 0

完整表见 Expert C ch08 operator-precedence-cheatsheet。

其他常见组合

  • && / || 低于 ==，高于 =
  • = 赋值 极低：if (a = b > 0) → a = (b > 0)（ch01 1.1 + Expert C Halloween）
  • . / -> 高于 *：p->member 先成员后解引用

工程规范

位运算、混合比较一律手动加括号，不靠记忆。

if ((x & 0x02) == 0x02)  /* 判断 bit1 */
if ((status & MASK) != 0)

代码自测

题目 1： 以下表达式的求值顺序是什么？

int x = a & b + c;
int y = a << 2 + 1;
参考答案

a & b + c → a & (b + c)（+ 优先级高于 &） a << 2 + 1 → a << (2 + 1)（+ 优先级高于 <<） 位运算的优先级低于算术运算，这是常见陷阱。防范：位运算表达式始终加括号。

2.2

else 就近匹配（悬垂 else）

本节讲什么

else 永远绑定离它最近、尚未配对的 if，与 缩进、注释、人类阅读意图 无关。这是典型的 人脑逻辑 ≠ 编译器语法 问题。

要点

经典悬垂 else

if (a > 0)
    if (b > 0)
        puts("a,b>0");
else
    puts("a<=0");   /* 绑定内层 if(b>0)，不是外层 if(a>0) */

等价结构：

if (a > 0) {
    if (b > 0)
        puts("a,b>0");
    else
        puts("a<=0");  /* b<=0 时打印，a<=0 时什么都不做 */
}

修复

外层加大括号，明确作用域：

if (a > 0) {
    if (b > 0)
        puts("a,b>0");
} else {
    puts("a<=0");
}

工程规范（内核 / HFT / 嵌入式）

  1. 所有 if/else/for/while 一律写 {}，即使只有一行
  2. else if 链保持统一缩进，不依赖「看起来属于哪层」
  3. 复杂条件提取为 bool 变量或函数，减少嵌套

代码自测

题目 1： 以下代码的 else 匹配哪个 if？

if (a)
    if (b) x = 1;
else x = 2;
参考答案

else 匹配内层 if (b)（就近匹配原则）。如果想让 else 匹配外层 if (a)，必须用花括号：

if (a) {
    if (b) x = 1;
} else x = 2;

这是 C 语法中最常见的陷阱之一。规则：始终用花括号。

2.3

函数声明与调用

本节讲什么

函数名在表达式中的含义、是否带 ()、以及 是否提前声明，都属于语法层陷阱。漏写括号会 先调用再传参；隐式声明会让 类型完全错位。

要点

func vs func()

写法 含义
handler 函数地址（函数指针值）
handler() 调用函数，表达式值为返回值 
signal(SIGINT, handler);    /* 正确：注册处理函数 */
signal(SIGINT, handler()); /* 错：先执行 handler，把返回值传给 signal */

同类：pthread_create(..., thread_func, ...) 传 函数名，不是 thread_func()。

隐式函数声明（C89 / 老代码）

C89 允许调用 未声明 的函数，编译器假设：

/* 未声明 void foo(double x); */
foo(3.14);
/* 旧编译器假定 int foo(); 参数按旧规则传递 → double 截断/错乱 */
标准 规则
C99/C11 隐式 int 函数声明 删除，未声明调用 → 诊断
老内核/嵌入式 大量 K&R 风格残留

现代实践：

#include "foo.h"   /* 或 static 原型在 .c 顶部 */
-Werror=implicit-function-declaration

与 ch04 连接

未声明函数 + 错误原型 → 链接期 符号/类型不匹配（ch04）。

代码自测

题目 1： 以下两种声明有什么区别？

int f();      // C89
int f(void);  // C89/C99
参考答案

int f() 在 C 中表示「参数未指定」——调用时可以传任意参数，编译器不检查。 int f(void) 明确表示「无参数」——传参数会编译错误。 C++ 中 f() 和 f(void) 等价（都表示无参数），但在 C 中不同。这是 C/C++ 的一个重要区别。规则：C 中无参数函数用 f(void)。

2.4

括号缺失与语句体

本节讲什么

if / for / while 没有 {} 时，语法上仅紧跟的「一条语句」属于体；下一行已是独立语句，不受控制——与缩进无关。

要点

经典错误

if (flag)
    a = 100;
    b = 200;   /* 永远执行！不属于 if */

等价于：

if (flag)
    a = 100;
b = 200;

宏展开叠加（ch06 预告）

#define INC(x) x++; x++
if (ok)
    INC(a);   /* 展开后多条语句，仅第一条受 if 控制 */

见 ch06 预处理器。

修复

if (flag) {
    a = 100;
    b = 200;
}

工程规范

  • Mandatory braces：内核风格、MISRA、多数 HFT 规范要求控制语句必带 {}
  • 调试时在 if 下加 log 行，忘加 {} 极易引入新 bug

代码自测

题目 1： 以下宏展开后有什么问题？

#define SQR(x) (x)*(x)
int y = 10 / SQR(2);  // 结果是？
参考答案

展开为 10 / (2)*(2) = (10/2)*(2) = 10，而非 10/(2*2) = 2。整个宏体应加外层括号：

#define SQR(x) ((x)*(x))

展开为 10 / ((2)*(2)) = 2。宏定义中每层括号都有作用：参数加括号防止参数表达式优先级问题，整体加括号防止宏在表达式中被错误组合。

2.5

逗号：分隔符 vs 逗号运算符

本节讲什么

同一个 , 在不同语法位置含义不同：分隔符（无组合值） vs 逗号运算符（从左求值，结果为 最右 表达式）。

要点

逗号运算符

int x = (1, 2, 3);   /* x = 3 */
if (a++, b < 100)    /* 先 a++，再判断 b<100 */

分隔符（不是逗号运算符）

位置 作用
函数实参 f(a, b) 分隔参数；求值顺序未指定（C17 前）
声明 int a, b; 声明多个变量
for (i=0, j=10; ...; i++, j--) 初始化/步进里的 逗号运算符（合法）

易错

func(i++, ++i);  /* 实参逗号：非序列点，同一变量多次修改 → UB */

见 Expert C ch08 demo05。

工程建议

  • 复杂表达式 不用逗号运算符 拼逻辑
  • 实参列表 不 在多个参数里改同一变量
  • for 里 i++, j-- 清晰可读时可用；业务逻辑不要塞进条件

代码自测

题目 1： 以下两个逗号各是什么作用？

int a = 1, b = 2;  // 第一个逗号
int c = (1, 2);    // 第二个逗号
参考答案

第一个逗号是声明分隔符——同时声明 a 和 b。 第二个逗号是逗号运算符——(1, 2) 求值为 2（最右边的值）。c 被赋值为 2。 区分：在声明、函数参数列表、初始化列表中的逗号是分隔符；在表达式中的逗号是运算符。逗号运算符优先级最低。

2.6

数组下标与结构体成员

本节讲什么

下标、成员访问的语法糖背后是指针运算；优先级 决定 &st.member 如何分组。可读性陷阱 i[a] 语法合法但应禁止。

要点

下标等价

a[i]  等价  *(a + i)
i[a]  等价  *(i + a)  /* 语法合法：交换律，禁止在工程代码中使用 */

Expert C ch04 强调数组 ≠ 指针，但 下标运算符 仍是指针算术语法糖。

结构体成员优先级

写法 解析
st.member 成员访问
p->member (*p).member
&st.member &(st.member) — . 高于 &
&p->member 正确取成员地址

错误理解：*p.member 等价 *(p.member)（把 member 当指针）—— 实际是 *(p->member) 需看 p 类型。

代码自测

题目 1： 以下声明分别是什么？

int a[10];           // ?
struct Point { int x, y; } p, *q;  // ?
int b[10], c[20];    // ?
参考答案

int a[10] — 10 个 int 的数组 struct Point { ... } p, *q — 定义结构体 Point 的同时声明变量 p 和指针 q int b[10], c[20] — b 是 10 个 int 的数组，c 是 20 个 int 的数组（不是 2D 数组） 注意：int a, b[10] 中 a 是 int，b 是 int[10]——数组分量只作用于紧邻的标识符。

章节自测

语法陷阱：token 组装成语句时的逻辑错误。看代码 → 想答案 → 点开验证。

Q1位运算优先级
int val = 0x06;  // 0b110
int mask = 0x02; // 0b010

if (val & mask == 2)
    printf("bit set\n");
else
    printf("bit not set\n");

输出什么？如何修正？

答案与复习指引

答案： 输出 bit not set。== 优先级高于 &，所以表达式被解析为 val & (mask == 2)，即 val & 1 = 0x06 & 1 = 0（假）。

修正： if ((val & mask) == 2) — 位运算和比较一律加括号。

复习： → 2.1 运算符优先级

Q2悬垂 else
int x = 1, y = 0;
if (x > 0)
    if (y > 0)
        printf("both positive\n");
else
    printf("x not positive\n");

输出什么？缩进是否反映实际逻辑？

答案与复习指引

答案： 没有输出。else 绑定最近的 if（if (y > 0)），而非缩进暗示的外层 if (x > 0)。实际逻辑等价于：

if (x > 0) {
    if (y > 0)
        printf("both positive\n");
    else
        printf("x not positive\n");  // y <= 0 时执行
}

x=1, y=0 → y > 0 为假 → 输出 x not positive。

等等，重新分析：x=1 > 0 为真，进入内层。y=0 > 0 为假，执行 else → 输出 x not positive。

修正： 外层 if 加 {} 明确意图。

复习： → 2.2 else 就近匹配

Q3函数声明还是调用？
void handler(int sig) {
    printf("signal %d\n", sig);
}

int main() {
    signal(SIGINT, handler);    // 正确：传函数指针
    signal(SIGINT, handler());  // 错误：调用 handler 后传返回值
    return 0;
}

第二行 handler() 有什么问题？

答案与复习指引

答案： handler() 是调用 handler 函数（无参，但 handler 需要 int 参数——编译警告或 UB），然后把返回值 void 当参数传给 signal。正确写法是 handler（不带括号 = 函数指针）。

规则： 函数名即地址；加 () 就是调用。

复习： → 2.3 函数声明与调用

Q4缺少大括号
int debug = 0;

if (debug)
    log_message("starting");
    log_message("phase 1");
    log_message("phase 2");

printf("done\n");

debug=0 时输出什么？debug=1 时呢？

答案与复习指引

答案： debug=0 时输出 phase 1、phase 2、done——只有 log_message("starting") 受 if 控制，后两行总是执行（缩进欺骗人眼）。debug=1 时输出全部四行。

规则： 所有 if/else/for/while 体一律加 {}，即使只有一行。

复习： → 2.4 括号缺失与语句体

Q5逗号运算符 vs 实参分隔
int f(int a, int b) { return a + b; }

int x = 1, y = 2;

int r1 = f(x, y);        // A
int r2 = f((x, y), 3);   // B

r1 和 r2 分别是多少？

答案与复习指引

答案： r1 = 3（f(1, 2) = 1+2）。r2 = 5（(x, y) 是逗号运算符——求值 x 丢弃，求值 y=2 作为第一个实参，f(2, 3) = 2+3）。

关键区别： 函数调用 f(a, b) 的逗号是分隔符；(a, b) 中的逗号是运算符（左求值丢弃，右求值为结果）。
