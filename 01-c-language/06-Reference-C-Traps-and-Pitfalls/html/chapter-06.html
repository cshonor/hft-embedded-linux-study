6.1

宏参数不加括号，优先级错乱

本节讲什么

宏是 纯文本替换，不参与 C 语法分析，不会 给参数自动加括号。参数表达式若含 +、*、移位等运算符，展开后优先级与结合性与直觉不符。

要点

#define SQUARE(x) x * x
SQUARE(a + 1);
/* 展开：a + 1 * a + 1  →  a + (1*a) + 1，不是 (a+1)² */

标准写法

#define SQUARE(x) ((x) * (x))
  • 参数 加括号：(x)
  • 整体 加括号：((x) * (x))，避免嵌入更大表达式时优先级再错

类似陷阱

#define DOUBLE(x) x + x        /* 错 */
#define DOUBLE(x) ((x) + (x))  /* 对 */

代码自测

题目 1： 以下宏展开后结果是什么？如何修复？

#define DBL(x) x+x
int y = DBL(3) * 4;  // 结果是？
参考答案

展开为 3+3*4 = 15（不是 24）。宏参数必须加括号：

#define DBL(x) ((x)+(x))

展开为 ((3)+(3))*4 = 24。宏是纯文本替换，不遵守运算符优先级。

6.2

宏参数含自增/赋值，多次副作用

本节讲什么

即使参数已加括号，宏 仍会重复展开 同一实参文本。实参含 ++、--、赋值、函数调用等 有副作用 表达式时，副作用执行次数不可控。

要点

#define SQUARE(x) ((x) * (x))
int i = 2;
int res = SQUARE(i++);
/* 展开：((i++) * (i++)) — i 自增两次，res 不可预测 */

规范

  • 禁止 向宏传入含副作用的表达式
  • 能写 static inline 函数 就不写宏（C99+）
  • 内核等必须宏的场景：文档标明「参数求值多次」

inline 对比

static inline int square(int x) { return x * x; }
square(i++);  /* i 只自增一次 */

代码自测

题目 1： 以下宏有什么问题？

#define MAX(a, b) ((a) > (b) ? (a) : (b))
int x = 1, y = 2;
int z = MAX(x++, y++);  // x 和 y 各自增几次？
参考答案

x++ 或 y++ 可能被求值两次——展开为 ((x++) > (y++) ? (x++) : (y++))。如果 x < y，y++ 执行两次，x++ 执行一次。副作用被重复执行是宏的经典陷阱。解决：1) 用内联函数替代宏；2) 用 GCC 语句表达式 { typeof(a) _a = (a); typeof(b) _b = (b); _a > _b ? _a : _b; }。

6.3

多行宏与分号：if-else 绑定崩坏

本节讲什么

多行宏用 \ 续行；调用处若加分号，或宏内自带多余分号，在 if / else 上下文中会破坏 语句绑定，导致逻辑错误或编译失败。

要点

经典 if-else 陷阱

#define BAD() foo(); bar()

if (cond)
    BAD();
else
    baz();

/* 展开：
if (cond)
    foo(); bar();    ← else 无法匹配 bar() 前的 if
else
    baz();
*/

裸 SWAP 与 if

#define SWAP(a,b) int t=a; a=b; b=t;

if (flag)
    SWAP(x,y);
/* if 只控制第一行；或 C 语法不允许 if 后直接跟声明 */

标准：do { ... } while (0)

#define SWAP(a,b) do { int t = (a); (a) = (b); (b) = t; } while (0)

可安全用于：

if (flag)
    SWAP(x, y);
else
    x = 0;

末尾分号成为 while(0); 的空语句，语法合法。

代码自测

题目 1： 以下多行宏有什么问题？

#define SWAP(a, b) do { \
    int tmp = a; a = b; b = tmp; \
} while (0)

if (x > y)
    SWAP(x, y);  // 末尾分号
else
    ...
参考答案

如果宏不用 do { ... } while(0) 包裹，展开后 if-else 结构会断裂。do { ... } while(0) 是标准惯用法——它接受末尾分号，在 if-else 中行为正确。如果直接用 { }，末尾分号会产生空语句，导致 else 匹配错误。do { ... } while(0) 是多语句宏的最佳实践。

6.4

字符串化 `#` 与连接 `##`

本节讲什么

# 将宏参数 字符串化；## 在预处理阶段 粘贴 两个 token 成一个标识符。二者仅在宏体内、预处理期生效，易与运行时字符串混淆。

要点

# 字符串化

#define PRINT_VAR(x) printf(#x " = %d\n", x)
PRINT_VAR(num);
/* → printf("num" " = %d\n", num);  相邻字符串字面量自动拼接 */

坑：参数含空格、逗号会 原样 进入字符串；PRINT_VAR(a + b) → "a + b"，不是 "a+b"。

## token 粘贴

#define CAT(a, b) a##b
int val1 = 10;
printf("%d\n", CAT(val, 1));   /* val1 */

限制：

  • 结果必须是 合法标识符
  • 不能随意拼数字开头、关键字
  • 调试困难，可读性差

代码自测

题目 1： 以下宏展开后是什么？

#define STR(x) #x
#define XSTR(x) STR(x)
#define VERSION 42
const char* s1 = STR(VERSION);   // ?
const char* s2 = XSTR(VERSION);  // ?
参考答案

STR(VERSION) → "VERSION"（# 直接字符串化参数文本，不展开） XSTR(VERSION) → "42"（先展开 VERSION 为 42，再字符串化） 这是两层宏的技巧：外层宏让参数先展开，内层宏做字符串化。# 字符串化，## 连接：CAT(a, b) → ab。

6.5

宏与关键字、typedef、标准库名字冲突

本节讲什么

预处理 先于 编译；#define 会替换 所有 匹配的标识符 token，包括 typedef 名、标准库函数名、甚至关键字（若未防护），造成全工程类型/语法错乱或 静默行为篡改。

宏 不管 C 块作用域 / 函数作用域，也不按 Rust 词法作用域规则 —— 从 #define 出现位置到文件末（或 #undef），纯文本全文替换。

要点

1. 篡改类型：#define int long

#define int long
int a;           /* → long a;  整文件 int 语义被篡改 */

2. 劫持标准库：#define getchar my_getchar（HFT 致命隐藏 bug）

#include <stdio.h>
#define getchar my_getchar

int c = getchar();   /* 预处理后 → int c = my_getchar(); */
  • 源码里 看起来 调 <stdio.h> 的 getchar，编译 可能仍通过
  • 实际走的是 my_getchar：缓冲、锁、syscall 次数、延迟全可能变
  • 无报错、无 shadow 警告 —— 预处理器不做作用域分析
  • HFT 热路径上：profile 对不上、replay 与实盘不一致，极难定位

<stdio.h> 中 getchar 等本身 常为宏；再 #define 一层等于 二次劫持。

3. 其他常见撞名

危险写法 后果
#define max(a,b) ... 与 C++ std::max、内核 max 宏冲突
#define uint32_t my_u32 整文件类型语义崩坏
#define DEBUG 空宏 #ifdef DEBUG 误触发（见 6.7）

4. 规范

  • 宏名 全大写 + 项目前缀：HFT_RING_SIZE、MYDRV_MAX_BUF
  • 禁止 #define 标准关键字、常用 typedef（uint32_t、size_t）、标准库函数名（getchar、malloc、printf…）
  • 取消误定义：#undef getchar（极少用，优先别定义）
  • 排查：gcc -E file.c | less，或 grep -r '#define getchar' include/

5. 与链接衔接

ch04 中 链接期 符号名冲突（重复定义 foo）；宏冲突发生在 编译更早期 的预处理，连类型检查都还没开始。

题目 1： 以下代码有什么问题？

#define min(a, b) ((a) < (b) ? (a) : (b))
#include <algorithm>  // C++ 中也有 min

6.6

头文件重复包含防护

本节讲什么

同一头文件被多条 #include 链 重复展开 时，无防护则结构体、枚举、函数声明、误写的全局定义 重复出现 → 编译错误或链接多重定义。

要点

标准 include guard

#ifndef MYMODULE_H
#define MYMODULE_H
/* 内容 */
#endif

#pragma once

多数现代编译器支持，简洁；老嵌入式工具链 可能不支持，可移植项目优先 #ifndef。

与 ch04 衔接

ch04 4.8 从链接角度；本章从 预处理重复展开 角度。

循环包含

A.h → B.h → A.h：guard 使第二次跳过内容，打破循环。

与后续衔接

  • 6.7：条件编译与注释交互
  • ch04：extern 头文件只声明

代码自测

题目 1： 以下两种头文件保护方式有什么区别？

// 方式A: include guard
#ifndef MYHEADER_H
#define MYHEADER_H
...
#endif
// 方式B: pragma once
#pragma once
...
参考答案

方式A：标准 C，所有编译器支持。需要手动确保宏名唯一。方式B：非标准但主流编译器支持（GCC/Clang/MSVC）。更简洁，不需要宏名。不需要 #endif。 两者功能等价——防止重复包含。#pragma once 的潜在问题：如果同一个文件通过不同路径被引用（如符号链接），可能不被识别为同一文件。实践中两者都可用，#pragma once 更流行。

6.7

条件编译与注释陷阱

本节讲什么

预处理指令 不被 C 注释屏蔽。把 #ifdef 写在 /* ... */ 或 // 注释里，预处理器 仍会扫描 并处理，导致意外分支或语法残片。

要点

/*
#ifdef DEBUG
    printf("log\n");
#endif
*/
/* 注释无法“注释掉”预处理指令 */

正确禁用大段代码

#if 0
    /* 任意代码、甚至非法语法，均不进入编译 */
    broken experimental();
#endif

#ifdef vs #if

#define DEBUG
#ifdef DEBUG    /* 只问“是否定义”，空宏也算真 */
#endif

#define DEBUG 1
#if DEBUG       /* 可区分 0/1 */
#endif

代码自测

题目 1： 以下代码有什么问题？

#define DEBUG 1
/* 注释 #if DEBUG */
#if DEBUG
    printf("debug");
#endif
参考答案

注释中的 #if DEBUG 不会被执行——注释在预处理之前被移除（C 标准规定注释在翻译阶段 3 移除，预处理在阶段 4）。但如果注释中有 */，可能提前结束注释块。条件编译指令 #if/#ifdef 只在注释外有效。防范：不要在注释中放预处理指令，避免混淆。

6.8

宏替代函数无类型检查

本节讲什么

宏 不建立函数作用域，不对实参做类型检查；任意类型 token 均可填入，比较、赋值语义由 展开后的 C 表达式 决定，易静默逻辑错误。

要点

#define MAX(a, b) ((a) > (b) ? (a) : (b))

MAX("abc", 123);
/* 指针与整数比较 → 无报错，结果无意义 */

指针陷阱

#define PTR_MAX(p, q) ((p) > (q) ? (p) : (q))
/* 比较的是地址大小，不是指向内容 */

优先 inline

static inline int max_int(int a, int b) { return a > b ? a : b; }

泛型需求：C11 _Generic、C++ 模板、或多次重载宏（内核 min/max 风格）。

题目 1： 以下宏有什么类型安全问题？

#define ABS(x) ((x) < 0 ? -(x) : (x))
ABS(-3.14);   // OK
ABS(-3);      // OK

参考答案

宏不做类型检查——ABS("hello") 展开后字符串字面量参与比较和取负，编译可能通过但行为未定义。C11 的 _Generic 可以实现类型安全的泛型宏。更好的方案：用 C++ 模板或 C 的内联函数（但对不同类型需要多个版本）。

6.9

空宏与未定义宏判断

本节讲什么

#ifdef MACRO / #ifndef MACRO 只检测 是否被 #define 过，不 检查宏体是否为空、是否为 0。开关型宏需用 #if 显式数值判断。

要点

#define DEBUG          /* 空宏 */
#ifdef DEBUG
    /* 始终编译进来 */
#endif

推荐开关写法

#define DEBUG 1        /* 1=开 0=关 */

#if DEBUG
    fprintf(stderr, "trace\n");
#endif

或构建系统传递：-DDEBUG=0 / -DDEBUG=1。

#defined 运算符

#if defined(DEBUG) && DEBUG

避免在 #if 表达式中裸写标识符（未定义时行为与 defined() 不同）。

defined 与 #ifdef

写法 含义
#ifdef FOO FOO 已定义（含空定义）
#if defined(FOO) 同 #ifdef
#if FOO FOO 须为 整常量 宏，未定义则视为 0

与后续衔接

  • 6.7：#if 0 禁用代码

代码自测

题目 1： 以下代码的 #if defined() 和 #ifdef 有什么区别？

#define FOO       // 空宏
#if defined(FOO)  // true
#ifdef FOO        // true
#if FOO           // false（空宏展开为空，#if 中视为 0）
参考答案

defined(FOO) 和 #ifdef FOO 都检查宏是否定义——空宏也算已定义，都为 true。#if FOO 检查宏的值——空宏展开为空，在 #if 表达式中视为 0。区别：defined 可组合逻辑 #if defined(A) && !defined(B)，#ifdef 不能。#if FOO 用于检查宏的值（如 #if DEBUG > 0）。

预处理器陷阱：纯文本替换，不理解类型和优先级。看代码 → 想答案 → 点开验证。

Q1宏括号缺失
#define SQUARE(x) x*x

int r1 = SQUARE(3);
int r2 = SQUARE(3 + 1);
int r3 = SQUARE(2 + 3);

r1、r2、r3 分别是多少？

答案与复习指引

答案： - r1 = 9（3*3） - r2 = 7（3+1*3+1 = 3+3+1 = 7，不是 16） - r3 = 11（2+3*2+3 = 2+6+3 = 11，不是 25）

修正： #define SQUARE(x) ((x)*(x)) — 参数和整体都加括号。

复习： → 6.1 宏参数括号

Q2副作用重复求值
#define MAX(a, b) ((a) > (b) ? (a) : (b))

int i = 3, j = 5;
int m = MAX(i++, j++);
printf("m=%d i=%d j=%d\n", m, i, j);

m、i、j 分别是多少？

答案与复习指引

答案： m=6, i=4, j=7（或类似值，具体取决于求值顺序）。

展开：((i++) > (j++) ? (i++) : (j++))。i++=3 vs j++=5，3 < 5 为真，走 j++ 分支 → j 被自增两次（6→7），i 自增一次（3→4）。m = 第二次 j++ 的值 = 6。

UB 警告： 三目运算符的 condition 和选中分支之间的求值顺序是 sequenced 的，但 i++/j++ 各被执行了不确定次数——行为不可靠。

修正： 用 inline 函数替代宏；或用 GNU 语句表达式 ({ typeof(a) _a=(a); ... })。

复习： → 6.2 宏副作用重复

Q3do-while(0) 宏
#define SAFE_FREE(p) \
    if (p) { free(p); p = NULL; }

int main() {
    char *a = malloc(10), *b = malloc(10);
    if (1)
        SAFE_FREE(a);
    else
        SAFE_FREE(b);    // 会被执行吗？
    return 0;
}

else 分支的 SAFE_FREE(b) 会如预期执行吗？如何修复？

答案与复习指引

答案： 不会如预期。展开后：

if (1)
    if (a) { free(a); a = NULL; }
else
    if (b) { free(b); b = NULL; }

else 绑定内层 if (a)，而非外层 if (1)——悬垂 else 问题。

修复： 用 do { ... } while(0) 包裹宏：

#define SAFE_FREE(p) do { if (p) { free(p); p = NULL; } } while(0)

do-while(0) 保证宏体是一个语句，不受外层 if-else 影响。

复习： → 6.3 多行宏与分号

Q4字符串化
#define STR(x) #x
#define XSTR(x) STR(x)

#define VERSION 42

const char *a = STR(VERSION);
const char *b = XSTR(VERSION);

a 和 b 分别是什么字符串？

答案与复习指引

答案： a = "VERSION"（# 在宏参数展开之前字符串化）；b = "42"（XSTR 的参数先展开 VERSION → 42，再传给 STR 字符串化）。

用途： 调试宏中打印表达式和值：printf("%s = %d\n", STR(x), x);

Q5#ifdef vs #if
#define DEBUG 0
#define RELEASE

#ifdef DEBUG
    int debug_mode = 1;    // A
#endif

#if DEBUG
    int debug_verbose = 1; // B
#endif

#ifdef RELEASE
    int release_mode = 1;  // C
#endif

A、B、C 三行哪些会被编译？

答案与复习指引

答案： A 和 C 编译，B 不编译。

  • #ifdef DEBUG：检查 DEBUG 是否被定义（不管值是多少）——DEBUG 定义为 0，仍然"已定义" → A 编译。
  • #if DEBUG：检查 DEBUG 的值是否非零——DEBUG = 0 → B 不编译。
  • #ifdef RELEASE：RELEASE 已定义（空宏）→ C 编译。

规则： 想用 0/1 开关用 #if；只想检查是否定义用 #ifdef。
