3.1

指针与数组的根本混淆

本节讲什么

语义层最核心规则：数组 ≠ 指针。数组名在多数表达式中 decay 为首元素指针，但 sizeof / & 例外；函数形参处 永远退化为指针。

要点

decay 与例外

语境 int arr[10] 的类型/行为
一般表达式 int*（首元素地址）
sizeof(arr) 整个数组：40（10×4）
&arr int (*)[10]，步长 40
形参 int arr[] 等价 int *arr 
int arr[10];
sizeof(arr);     /* 40 */
sizeof(&arr);    /* 8（指针宽度，64 位） */
int *p = arr;
sizeof(p);       /* 8 — 不是缓冲区长度！ */

内核/嵌入式坑

void copy(int *buf) {
    memcpy(dst, buf, sizeof(buf));  /* 错：得到 8，不是缓冲区字节数 */
}

必须 单独传 size_t len 或用 sizeof 仅对 未 decay 的数组对象。

函数参数

void func(int arr[]);  /* 完全等价 */
void func(int *arr);
/* 函数内 sizeof(arr) == sizeof(int*) */

见 Expert C ch04、ch09。

代码自测

题目 1： 以下代码有什么问题？

int a[10];
int* p = a;
sizeof(a);  // 值是？
sizeof(p);  // 值是？
参考答案

sizeof(a) = 40（10 * 4 字节，a 是数组）。sizeof(p) = 8（指针大小）。虽然 a 和 p 在很多上下文中可以互换使用（数组退化为指针），但 sizeof 是例外——sizeof(数组名) 得到数组总大小，sizeof(指针) 得到指针大小。

3.2

空指针解引用

本节讲什么

NULL（地址 0）解引用属于 未定义行为（UB）。表现因平台而异：用户态常 SIGSEGV；裸机可能 静默写硬件寄存器。

要点

典型错误

char *p = NULL;
*p = 'a';           /* UB */
if (p) *p = 'a';    /* 正确：先检查 */

平台差异

环境 行为
Linux 用户态 段错误，易调试
MCU 地址 0 映射寄存器 无崩溃，硬件被改
内核 NULL 指针保护 故意映射不可访问页，触发 oops

与短路求值

if (p != NULL && *p == 'x')  /* 安全：右侧不执行 */

语法见 ch02 2.1 && 短路。

工程规范

  • 解引用前 显式判空
  • API 文档标明谁负责分配/释放
  • 可选：assert(p != NULL) 调试版

与后续衔接

  • ch05 库函数：malloc 失败返回 NULL
  • Expert C ch07：野指针、use-after-free

代码自测

题目 1： 以下代码会发生什么？

int* p = NULL;
*p = 42;  // ?
int x = *p;  // ?
参考答案

段错误（SIGSEGV）——解引用空指针是未定义行为，通常导致进程崩溃。但空指针的地址不一定是 0（虽然绝大多数平台是），C 标准只保证 NULL 不等于任何有效指针。防范：使用指针前检查 if (p != NULL)。注意：free 后置 p = NULL 防止 use-after-free。

3.3

有符号与无符号隐式转换

本节讲什么

usual arithmetic conversions：有符号与无符号混合运算时，有符号操作数常 转为无符号。比较、循环边界因此 静默颠倒。

要点

比较陷阱

unsigned u = 10;
int i = -1;
if (i < u)   /* 假！i 转为 UINT_MAX 量级 */

等价：if ((unsigned)i < u) → 巨大无符号数 < 10 为假。

无符号循环死循环

for (unsigned i = 10; i >= 0; i--)
    ;  /* i 永远 >= 0，永不退出 */

无 unsigned 不存在负数，i-- 到 0 后再减 → 回绕到 UINT_MAX。

底层危害

  • HFT 遍历数组 for (size_t i = n; i >= 0; i--) 卡死
  • 驱动 DMA 长度 int len 与 size_t 混比

工程规范

  1. 循环计数器类型统一（全 size_t 或全 int 且保证非负）
  2. 与无符号比较前 显式 cast 或改类型
  3. 负数场景 不用 unsigned 存「可能为负」的量

./demo/demo03_unsigned_loop/main     # 演示回绕（有限步）

与后续衔接

  • 3.4：无符号 定义 回绕 vs 有符号溢出 UB
  • ch07 可移植性：size_t 宽度

代码自测

题目 1： 以下代码输出什么？

unsigned int u = 5;
int s = -10;
if (u + s > 0) printf("positive");
else printf("negative");
参考答案

输出 positive。s 被隐式转为 unsigned int（约 4294967286），加 5 后远大于 0。有符号/无符号混合运算时，有符号数被转换为无符号。防范：1) 避免混用；2) 显式转换 if ((int)(u + s) > 0)；3) 开启 -Wsign-compare 警告。

3.4

整型溢出

本节讲什么

无符号溢出：标准定义为 模 2^N 回绕。有符号溢出：标准规定为 UB，编译器可假定不发生并激进优化。

要点

对比

类型 溢出
unsigned 定义行为：UINT_MAX + 1 → 0
signed UB；-O2 下可能删「不可能」分支 
int x = INT_MAX;
x + 1;  /* UB */
unsigned u = UINT_MAX;
u + 1;  /* 0，定义明确 */

典型场景

  • 计数器、金额、偏移用 int 累加越界 → 逻辑错乱
  • 编译器见 if (x + 1 < x) 推断 x+1 溢出不可能，删掉检查

工程建议

  • 可能溢出用 long long / int64_t 或库函数检测
  • 无符号长度/索引用 size_t
  • 金融/HFT：固定点或 decimal，避免裸 float/int 混用

与后续衔接

  • 3.3：无符号回绕与循环
  • ch07：int/long 宽度可移植性

代码自测

题目 1： 以下代码的行为是什么？

int x = INT_MAX;
x = x + 1;  // 有符号溢出
unsigned int y = UINT_MAX;
y = y + 1;  // 无符号溢出
参考答案

有符号整数溢出是未定义行为——可能回绕、可能崩溃、编译器可能优化掉相关检查。无符号整数溢出是明确定义的——回绕到 0（模运算）。这是 C 标准的重要区别。防范有符号溢出：在加法前检查 if (x > INT_MAX - 1)。C 的整型溢出是安全漏洞的常见来源。

3.5

指针运算规则

本节讲什么

指针 +/- 的单位是 指向类型的大小，不是 1 字节。void* 不能 直接算术（C99 前）；需转为 char* 或具体类型。

要点

int *p = ...;
p + 1;    /* +sizeof(int) */

char *cp = ...;
cp + 1;   /* +1 字节 */

void *vp = ...;
/* vp + 1; 非法 */
(char *)vp + 1;  /* 字节遍历内存 */

同类型指针相减

仅当指向 同一数组 内元素时有定义：

int a[5];
int *p1 = &a[0], *p2 = &a[3];
ptrdiff_t d = p2 - p1;  /* 3 */

跨对象相减 → UB。

与数组

arr[i] ≡ *(arr + i) — 步长由元素类型决定（ch02 2.6）。

与后续衔接

  • 3.1：数组连续 vs 指针
  • Expert C ch10：锯齿 int** vs int[][]

代码自测

题目 1： 以下代码输出什么？

int a[5] = {10, 20, 30, 40, 50};
int* p = a + 3;
printf("%d\n", *p);      // ?
printf("%d\n", p[-2]);    // ?
printf("%ld\n", p - a);   // ?
参考答案

*p = 40（a[3]） p[-2] = 20（a[1]，负下标合法——p + (-2) = a + 3 - 2 = a + 1） p - a = 3（指针减法返回元素个数，不是字节数） 指针运算按元素大小缩放：p + n 实际偏移 n * sizeof(*p) 字节。指针减法返回 ptrdiff_t。

3.6

函数实参求值顺序

本节讲什么

C 标准 不规定 函数实参的求值顺序（C17 前）。同一实参列表里 多次修改同一变量 → UB。

要点

int i = 1;
func(i++, i);  /* UB：结果 (1,2) 或 (2,1) 皆可能 */

与 ch02 2.5 实参逗号 非序列点 一致；Expert C ch08 Christmas 问题同源。

工程规范

  • 实参 无副作用：不自增、不赋值同一变量
  • 复杂计算 拆成临时变量 再传入
int a = i++;
int b = i;
func(a, b);

与后续衔接

  • ch02 2.5：逗号运算符 vs 实参分隔
  • ch08：序列点总结

代码自测

题目 1： 以下代码输出什么？

int i = 1;
printf("%d %d\n", i++, i++);
参考答案

未定义行为。C 标准不规定函数参数的求值顺序——两个 i++ 的顺序不确定，且两次修改同一变量之间没有序列点。可能输出 1 2 或 2 1。不同编译器/平台结果不同。规则：不要在同一表达式中对同一变量做多次修改。

3.7

数组下标越界

本节讲什么

C 不做 数组边界检查。越界读写是 UB，常表现为 覆盖栈/堆相邻数据、随机崩溃或静默数据损坏。

要点

int buf[4];
buf[5] = 100;  /* UB：可能改相邻栈变量 */

危害场景

场景 后果
HFT 报文解析 订单字段被篡改
内核栈缓冲区 历史提权漏洞类
嵌入式栈小 栈溢出复位

缓解

  • 所有访问 index < len 显式检查
  • memcpy/strcpy 传 目标容量
  • 工具：ASan、valgrind（用户态）

make -C demo/demo05_bounds && ./demo/demo05_bounds/main

与后续衔接

  • ch05 库函数：strcpy 无界
  • Expert C ch06：栈帧与溢出

代码自测

题目 1： 以下代码会发生什么？

int a[5] = {1, 2, 3, 4, 5};
a[5] = 10;    // 越界写
a[10] = 20;   // 严重越界
int x = a[-1]; // 负下标
参考答案

全部是未定义行为。C 不做数组边界检查——越界写可能覆盖其他变量、栈帧、甚至返回地址（缓冲区溢出攻击的原理）。越界读可能读到垃圾值或其他变量。a[-1] 读取数组前一个内存位置。防范：1) 始终检查边界；2) 用 snprintf 替代 sprintf；3) 开启 AddressSanitizer 编译。

3.8

结构体与位域

本节讲什么

结构体 sizeof 含 padding；跨机器/协议 不能直接 memcpy 整 struct 当 wire format。位域 signed/unsigned 混用导致符号解释错误。

要点

对齐与填充

struct S { char a; int b; };
/* sizeof(S) 常为 8，不是 5 */

见 Expert C ch07 对齐手算；网络协议用 packed 或 手动序列化。

位域

struct Flags {
    unsigned ok : 1;
    signed   err : 4;  /* 高位可能按符号扩展 */
};

工程规范

  • 协议：固定宽度类型 + 显式字节序
  • 硬件寄存器：对照手册偏移，不假设 offsetof 跨编译器相同（除非 packed + 固定 ABI）

与后续衔接

  • ch07 可移植性：端序、对齐
  • Embedded ch06：__attribute__((packed))

代码自测

题目 1： 以下结构体的大小是多少？位域有什么陷阱？

struct Flags {
    unsigned a : 1;
    unsigned b : 7;
    unsigned c : 8;
};
sizeof(struct Flags);  // ?
参考答案

通常 4 字节（编译器可能对齐到 int 大小）。位域的陷阱：1) 位域的内存布局是实现定义的（大小端、对齐、是否跨字节）；2) 位域不能取地址（&flags.a 不合法）；3) 不同编译器的位域布局可能不同——不可移植。位域适合硬件寄存器映射，但可移植代码应手动用位运算。

3.9

字符串字面量只读

本节讲什么

字符串字面量存储在 只读段（.rodata）。char *p = "hello" 后 修改 p[i] 为 UB，常 SIGSEGV。

要点

char *p = "hello";
p[0] = 'H';        /* UB / 段错误 */

char arr[] = "hello";
arr[0] = 'H';      /* 合法：栈/数据段副本 */

与 ch01 衔接

ch01 1.3："0" 是指针，'0' 是字符。

与链接衔接

跨文件 extern char msg[] vs extern char *msg — Expert C ch04/ch05。

工程规范

  • 只读文本用 const char *
  • 需要修改 → char buf[] 或 malloc + 拷贝

代码自测

题目 1： 以下代码会发生什么？

char* s = "hello";
s[0] = 'H';  // 合法吗？
参考答案

未定义行为。字符串字面量存储在只读段（.rodata），修改它可能段错误。正确做法：

char s[] = "hello";  // 在栈上复制一份
s[0] = 'H';  // OK

char* s = "hello" 中 s 指向只读内存；char s[] = "hello" 中 s 是栈数组，内容可修改。C11 起字符串字面量类型为 const char[]（但为了向后兼容，赋给 char* 只警告不报错）。

章节自测

语义陷阱：类型、指针、内存的实际含义出错。全书最难一章。看代码 → 想答案 → 点开验证。

Q1sizeof 数组 vs 指针
void process(int arr[], int n) {
    printf("sizeof(arr) = %zu\n", sizeof(arr));
}

int main() {
    int data[10] = {0};
    printf("sizeof(data) = %zu\n", sizeof(data));
    process(data, 10);
    return 0;
}

两次 sizeof 分别输出多少？（假设 64 位系统，int=4）

答案与复习指引

答案： sizeof(data) = 40（10×4=40 字节，真数组）；sizeof(arr) = 8（形参 arr 已退化为 int*，64 位指针 8 字节）。

教训： 函数内无法用 sizeof 获取数组长度——必须靠参数 n 传递。sizeof(ptr) 是最经典的数组/指针混淆。

复习： → 3.1 指针与数组混淆

Q2有符号无符号比较
unsigned int len = 5;
int idx = -1;

if (idx < len)
    printf("valid index\n");
else
    printf("invalid\n");

for (unsigned int i = len - 1; i >= 0; i--) {
    printf("%u ", i);
    if (i == 0) break;
}

输出什么？循环正常结束吗？

答案与复习指引

答案： 输出 invalid。idx=-1 与 unsigned 比较时，idx 被隐式转换为 unsigned，变成 4294967295（UINT_MAX），远大于 5。

循环：i >= 0 对 unsigned 永远为真——当 i=0 再 i-- 变成 4294967295，死循环。这里靠 if (i==0) break 逃出。

规则： 循环计数器不要用 unsigned 做 >= 0 判断；不混用 signed/unsigned 比较。

复习： → 3.3 有符号无符号转换

Q3整型溢出差异
int si = INT_MAX;      // 2147483647
unsigned ui = UINT_MAX; // 4294967295

si = si + 1;
ui = ui + 1;

printf("si = %d\nui = %u\n", si, ui);

两个结果分别是什么？哪个是 UB？

答案与复习指引

答案： - si + 1：UB（有符号溢出）。实际常回绕为 -2147483648，但编译器可假设不溢出做优化。 - ui + 1：明确定义——回绕为 0（mod 2^32）。

HFT 关联： 累加成交量用 int 可能溢出 UB → 用 uint64_t（回绕确定）或做前置溢出检查。

复习： → 3.4 整型溢出

Q4实参求值顺序
int i = 1;
printf("%d %d\n", i, i++);

输出什么？这是 UB 吗？

答案与复习指引

答案： 未定义行为（UB）。函数实参的求值顺序在 C 标准中是 unspecified（编译器可选择任意顺序），而 i++ 修改了 i 且另一个实参也读 i——同一对象的无序读写是 UB。

可能的输出：1 1、2 1、或任何值。

规则： 函数实参不要有副作用（++/--）——拆成两行。

复习： → 3.6 实参求值顺序

Q5字符串字面量只读
char *s = "hello";
s[0] = 'H';
printf("%s\n", s);

这段代码会发生什么？

答案与复习指引

答案： UB——字符串字面量 "hello" 存储在只读段（.rodata），修改它可能触发 SIGSEGV（段错误）。某些旧系统可能不崩溃，但行为未定义。
