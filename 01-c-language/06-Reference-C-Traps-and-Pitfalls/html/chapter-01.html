1.1

等号与相等判断 `=` / `==`

本节讲什么

C 在 if/while 条件里 允许赋值表达式，编译器不会把 = 当成笔误报错。x = 0 与 x == 0 是最经典、最危险的 静默 bug 之一。

要点

赋值 vs 比较

if (x = 0)   /* 赋值：x 变为 0，表达式值为 0 → 条件为假 */
if (x == 0)  /* 比较：判断 x 是否为 0 */
写法 效果
if (x = expr) 把 expr 赋给 x，条件看 赋值后的值
if (x == expr) 仅比较，不修改 x

典型危害

  • 分支永远走错：本意判断阈值，实际每次把变量清零
  • HFT/策略逻辑颠倒：无崩溃、无断言，回测与实盘偏差极难查
  • 与 ch02 叠加：if (a = b > 0) 实际是 a = (b > 0)（Expert C ch08 Halloween 陷阱）

工程规避

  1. Yoda 条件：if (0 == x) — 漏写 = 成 if (0 = x) 编译报错
  2. 赋值与判断分离：先赋值，再 if (x == 0)
  3. 开启警告：-Wall -Wparentheses，部分场景 -Wassignments（若编译器支持）
  4. 静态分析：clang-tidy、if (x = ...) 模式

代码自测

题目 1： 以下代码在 C 中合法吗？if 条件是什么意思？

if (x = 0) { ... }
参考答案

合法但几乎一定是 bug——x = 0 是赋值表达式，值为 0（false），条件永远为假。本意应该是 x == 0（相等判断）。C 的赋值是表达式不是语句，可以出现在条件中。防范：1) 把常量放左边 if (0 == x)（Yoda 条件）；2) 开启编译器警告 -Wall（-Wparentheses）。

1.2

注释不会嵌套

本节讲什么

C 只认 /* … */ 块注释 与 // 行注释（C99+）。块注释 不能嵌套：从第一个 /* 到 遇到的第一个 */ 即结束，中间一切（包括另一个 /*）都被当作注释内容。

要点

错误示例

/* 外层开始
   int a;
   /* 内层？ */
   int b;
*/

编译器视角：

  1. 第一个 /* 开始注释
  2. 遇到 第一个 */（「内层？」后面）→ 注释 结束
  3. 后面的 int b; 变成 正常代码；再出现的 */ → 非法 token，编译报错

实用坑

场景 后果
用 /* */ 整块注释掉 已含注释的代码 提前截断，语法错乱
驱动里临时屏蔽大段初始化 以为全禁用了，实际只禁了一部分
文档里写 /* example */ 嵌在外层注释 外层被意外关闭

正确做法

  1. 临时屏蔽：用 #if 0 … #endif（预处理器，可嵌套）
  2. 行注释：逐行 //（注意字符串里不要有未闭合的 /*）
  3. 版本控制：删代码靠 git，不靠长期大块注释
#if 0
/* 这里可以安全地写 /* 也不会破坏外层 */
int legacy_code(void) { return 0; }
#endif

与后续衔接

  • ch06 预处理器：#if 0 是屏蔽代码的首选
  • ch02：注释内的 /* 不影响词法，但会破坏 块注释 边界

代码自测

题目 1： 以下代码的注释范围是什么？

/* 外层注释 /* 内层注释 */ 代码 */
参考答案

注释到第一个 */ 结束——即 /* 外层注释 /* 内层注释 */，后面的 代码 */ 不在注释中，导致编译错误。C 注释不支持嵌套。如果需要注释掉包含注释的代码块，用 #if 0 ... #endif（预处理指令）。

1.3

字符常量与字符串常量

本节讲什么

单引号与双引号在词法上是 不同类别的 token，类型与用法完全不同。混用会导致 比较永远为假 或 段错误。

要点

对比

写法 类型 含义
'a' int（字符常量） ASCII/编码值，如 97
"a" char[]（字符串） 字符 'a' + 结尾 '\0'，占 2 字节
'ab' 多字符常量（实现定义） 少用，可移植性差

致命错误

char c = '0';      /* 字符零，值为 48 */
if (c == "0")      /* 错！比较 char 与 char* 地址 */
if (c == '0')      /* 对 */
  • "0" 是 指针（字符串首地址），不是字符 '0'
  • 编译器可能仅给 warning，逻辑 永远不成立

字符串与只读

char *s = "hello";  /* 指向 .rodata，s[0]='H' 可能 SIGSEGV */
char s[] = "hello"; /* 栈/数据段副本，可修改 */

见 Expert C ch07 .rodata 与 ch04 链接 extern 陷阱。

底层场景

  • 寄存器读回 char c = (char)REG;，与 '0'/'1' 比较 — 勿写 "0"
  • 协议单字节字段：用 'A'，不是 "A"

与后续衔接

  • ch03 语义：指针与整数比较的类型规则
  • ch05 库函数：strcmp 需要 char*，不是 'x'

代码自测

题目 1： 以下代码有什么问题？

char c = "a";  // 正确吗？
char* s = 'a';  // 正确吗？
参考答案

两个都错。"a" 是字符串字面量（char[2]，含 '\0'），赋给 char 截断为地址的低位字节。'a' 是字符常量（int 类型，值 97），赋给 char* 把 97 当地址——段错误。正确：char c = 'a'; char* s = "a";。单引号是字符，双引号是字符串。

1.4

数字字面量歧义

本节讲什么

数字在词法阶段的写法直接决定 进制、类型、值。010 不是十进制 10；后缀决定 unsigned/long/float。

要点

八进制陷阱

写法 实际值
07 十进制 10
010 八进制 → 十进制 8
06 非法（八进制无数字 9） 
int addr = 010;  /* 常见误读：以为是 10，实为 8 */

硬件/驱动：数据手册写八进制地址时，源码 0120 与 120 完全不同。

十六进制

0x 前缀：0x10 = 16。与八进制混淆较少，但注意 无前缀的 0。

浮点

写法 等价
.5 0.5
5. 5.0
1e2 100.0

后缀

后缀 含义
U / u unsigned
L / l long
LL / ll long long
F / f float
UL unsigned long 
123U
123L
123.0F

无后缀整型：类型为 int，超出范围才变 long（规则见 K&R / 标准）。

代码自测

题目 1： 以下整数字面量各是什么进制和值？

int a = 010;   // ?
int b = 0x10;  // ?
int c = 10;    // ?
参考答案

010 → 八进制（前导 0），值为 8 0x10 → 十六进制（前导 0x），值为 16 10 → 十进制，值为 10 经典坑：想写十进制 10 不小心加了前导 0 变成八进制 8。防范：不要在十进制数字前加 0。

1.5

运算符最长匹配（maximal munch）

本节讲什么

词法分析器扫描运算符时，采用 最长匹配：在多种合法拆法下，尽可能吃掉更长的 token。这是 a+++b、x---y 等行为与直觉不符的根源。

要点

规则

遇到 +、-、<、>、= 等时，编译器 向前看 组成最长合法运算符：

字符序列 拆分 不是
a+++b (a++) + b a + (++b)
x---y (x--) - y x - (--y)
i+++++j 非法（++ 后不能再 ++ 接 + 形成合法 token 链） —
<<= <<= 一个 token << + =

与语法/优先级的关系

  • 词法 先定 token 边界（本章）
  • 语法/优先级 再定表达式树（ch02）
  • 两者叠加：a+++b 先被切成 a++、+、b，再按左结合做加法

自增混用风险

int a = 1, b = 2;
int c = a+++b;  /* c = (a++) + b → a 变 2, c = 1+2 = 3 */

同一表达式多次修改 a 的变体（++a + ++a）属于 UB（Expert C ch08 Christmas 问题）—— 词法合法 ≠ 语义合法。

工程建议

  1. 自增 单独一行
  2. 复杂表达式 加括号（帮助人类，不改变词法拆分）
  3. 禁止在宏里拼 a++ 与相邻 +

  • ch02：++ 与 * 结合（*p++ vs (*p)++）

代码自测

题目 1： 以下代码的 a---b 如何解析？

int z = a---b;
参考答案

解析为 a-- - b（最长匹配原则：编译器从左到右尽可能多地匹配字符为 token）。-- 是一个 token，所以 a---b = (a--) - b。如果想要 a - (--b)，必须加空格：a - --b。这是词法分析中的「贪心原则」或「最大匹配原则」。

1.6

标识符与关键字

本节讲什么

标识符（变量名、函数名）与 保留字 keyword 在词法阶段分开识别。误用关键字、混淆宏与关键字，会导致编译错误或静默替换。

要点

关键字

C 保留字 不能 作普通标识符，例如：

auto break case char const continue default do double else enum extern float for goto if inline int long register return short signed sizeof static struct switch typedef union unsigned void volatile while

（C99+ 另有 restrict、_Bool/bool 等，依标准版本。）

区分大小写

Int 不是关键字，可作变量名；int 不可。

宏 vs 关键字

名字 性质
NULL 宏（通常 #define NULL ((void*)0)），不是关键字
true/false C99 前常是宏；C99 _Bool + <stdbool.h>
min/max 某些头文件宏，污染命名空间 
#define int double  /* 极端恶作剧：破坏整个翻译单元 */

实现扩展

编译器扩展关键字：__attribute__、__asm__ 等（Embedded ch06 GNU 扩展）。

链接与标识符

  • 外部链接符号名受 链接器 限制（C++ name mangling 见 Expert C ch11）
  • 内部 static 文件作用域标识符不导出

与后续衔接

  • ch04 连接：同名符号、链接器可见性
  • ch06 预处理器：宏名与关键字冲突

代码自测

题目 1： 以下哪些是 C 关键字，不能用作标识符？

int  class  main  register  asm  inline  restrict  _Bool
参考答案

int、register 是 C89 关键字。inline、restrict 是 C99 关键字。_Bool 是 C99 关键字（通常用 <stdbool.h> 的 bool 宏）。asm 是 GNU 扩展（非标准关键字）。class 在 C 中不是关键字（C++ 中是）。main 不是关键字——是程序入口函数名，可以用作其他标识符（不推荐）。

章节自测

词法陷阱：编译器切 token 时的歧义。看代码 → 想答案 → 点开验证。

Q1赋值还是比较？
int flag = 0;
if (flag = 0) {
    printf("checked\n");
} else {
    printf("unchecked\n");
}

输出什么？为什么？

答案与复习指引

答案： 输出 unchecked。flag = 0 是赋值（不是比较），赋值表达式的值为 0，if (0) 为假。

防护： 写 if (0 == flag)（Yoda 条件），漏写一个 = 时编译器报错。

复习： → 1.1 等号与相等判断

Q2注释嵌套陷阱
int code = 0;
/*
    config_reset();
    /* TODO: verify */
    code = 1;
*/
printf("code = %d\n", code);

code 的值是多少？为什么？

答案与复习指引

答案： code = 0（甚至可能编译失败）。C 注释 /* */ 不能嵌套——第一个 */（在 TODO 后）就关闭了注释块，后面的 code = 1; 变成正常代码执行，最后的 */ 导致编译错误。

更隐蔽的情况： 如果没有最后一个 */，code = 1 会静默执行——注释没生效！

正确做法： 屏蔽大段代码用 #if 0 ... #endif。

复习： → 1.2 注释不嵌套

Q3字符还是字符串？
char c = 'A';
if (c == "A") {
    printf("match\n");
} else {
    printf("no match\n");
}

输出什么？编译器会警告吗？

答案与复习指引

答案： 输出 no match（可能伴随编译警告）。'A' 是 int 类型（值 65）；"A" 是 char* 类型（指向字符串字面量的指针）。比较 char 和 char* ——编译器可能警告类型不匹配，但 C 允许隐式转换。

实际行为： c 被提升为指针值（如 0x41），与字符串 "A" 的地址比较——几乎不可能相等。

复习： → 1.3 字符与字符串常量

Q4八进制陷阱
int a = 010;
int b = 10;
int c = 08;

printf("a=%d b=%d c=%d\n", a, b, c);

三个变量的值分别是多少？c 能编译通过吗？

答案与复习指引

答案： a = 8（前导 0 表示八进制，010 = 1×8+0 = 8）；b = 10（十进制）；c 编译失败——8 不是合法的八进制数字（八进制只有 0-7）。

HFT/嵌入式场景： 寄存器地址 0x100 写成 0100 意味着八进制 64，地址完全错误。

复习： → 1.4 数字字面量

Q5最长匹配原则
int a = 1, b = 2, c;
c = a+++b;
printf("c=%d a=%d b=%d\n", c, a, b);

c、a、b 分别是多少？

答案与复习指引

答案： c=3, a=2, b=2。词法分析器采用最长匹配（maximal munch）：a+++b 被切分为 (a++) + b，而非 a + (++b)。

原理： 词法分析器从左到右贪心匹配最长合法 token。+++ 不合法，所以切 ++ + +。

工程规则： 自增/自减单独一行，复杂表达式加括号。

复习： → 1.5 最长匹配原则
