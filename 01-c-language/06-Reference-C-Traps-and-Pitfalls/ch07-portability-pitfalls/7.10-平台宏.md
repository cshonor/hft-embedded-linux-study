# 7.10 预处理器平台宏差异

## 本节讲什么

识别 CPU/OS 的预定义宏 **无单一标准**；直接写死 `__x86_64__` 在 MSVC 上不存在，写 `_WIN32` 在 Linux 上无效。 scattered `#ifdef` 导致维护噩梦。

## 要点

| 编译器/平台 | 常见宏 |
|-------------|--------|
| GCC x86_64 | `__x86_64__`, `__GNUC__` |
| GCC ARM | `__arm__`, `__aarch64__` |
| MSVC | `_MSC_VER`, `_WIN64`, `_WIN32` |
| Linux | `__linux__` |
| Apple | `__APPLE__`, `__MACH__` |

### 规范

集中封装 `platform.h`：

```c
#if defined(_WIN32)
#  define MY_PLATFORM_WIN 1
#elif defined(__linux__)
#  define MY_PLATFORM_LINUX 1
#else
#  error "unsupported platform"
#endif
```

业务代码只 include `platform.h`，不直接散落架构宏。

## 代码自测

**题目 1：** 如何用预处理宏检测当前操作系统和编译器？
```c
#ifdef _WIN32     // ?
#ifdef __linux__   // ?
#ifdef __GNUC__    // ?
#ifdef _MSC_VER    // ?
```

<details>
<summary>参考答案</summary>

`_WIN32` — Windows（32/64 位都定义）
`__linux__` — Linux
`__GNUC__` — GCC（也包括 Clang，因为 Clang 定义了 GCC 兼容宏）
`_MSC_VER` — MSVC
其他常见：`__APPLE__`（macOS）、`__x86_64__`（x86-64）、`__aarch64__`（ARM64）、`__cplusplus`（C++ 编译）。用这些宏做条件编译实现跨平台代码。

</details>
