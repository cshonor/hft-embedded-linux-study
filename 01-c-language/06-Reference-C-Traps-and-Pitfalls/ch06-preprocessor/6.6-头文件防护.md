# 6.6 头文件重复包含防护

## 本节讲什么

同一头文件被多条 `#include` 链 **重复展开** 时，无防护则结构体、枚举、函数声明、**误写的全局定义** 重复出现 → 编译错误或链接多重定义。

## 要点

### 标准 include guard

```c
#ifndef MYMODULE_H
#define MYMODULE_H
/* 内容 */
#endif
```

### `#pragma once`

多数现代编译器支持，简洁；**老嵌入式工具链** 可能不支持，可移植项目优先 `#ifndef`。

### 与 ch04 衔接

[ch04 4.8](../ch04-linking/4.8-头文件保护.md) 从链接角度；本章从 **预处理重复展开** 角度。

### 循环包含

A.h → B.h → A.h：guard 使第二次跳过内容，打破循环。

## 代码自测

**题目 1：** 以下两种头文件保护方式有什么区别？
```c
// 方式A: include guard
#ifndef MYHEADER_H
#define MYHEADER_H
...
#endif
// 方式B: pragma once
#pragma once
...
```

<details>
<summary>参考答案</summary>

方式A：标准 C，所有编译器支持。需要手动确保宏名唯一。方式B：非标准但主流编译器支持（GCC/Clang/MSVC）。更简洁，不需要宏名。不需要 `#endif`。
两者功能等价——防止重复包含。`#pragma once` 的潜在问题：如果同一个文件通过不同路径被引用（如符号链接），可能不被识别为同一文件。实践中两者都可用，`#pragma once` 更流行。

</details>
