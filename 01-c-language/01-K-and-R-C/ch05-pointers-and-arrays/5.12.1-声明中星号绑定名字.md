# 5.12.1 声明里的 `*`：不绑定类型、绑定名字（精炼）

> **declaration mimics use**：声明怎么写，将来使用表达式就怎么写。  
> ❌ 勿把 `int*` / `char*` 当成语法上「不可拆的原子类型」  
> ✅ 口语说「类型是 `char *`」可以；那是类型系统里的 *pointer to char*  
> 详解：[5.12](./5.12-复杂声明.md) · [2.4 声明](../ch02-types-operators-expressions/2.4-声明.md) · argv：[1.1.1](../ch01-introduction/1.1.1-命令行参数-main-argc-argv.md)

---

## 1. 语法本源：`*` 修饰声明符（变量名）

```c
int *p;
/* 将来写 *p = 10; → *p 是 int → 故 p 是「指向 int 的指针」 */
```

不要看成 `(int*) p` 把 `int*` 打包成整体。  
书写 `int* p;`（星贴类型）易养成错误直觉。

### 铁证：`*` 只绑紧邻的名字

```c
int* a, b;    /* a: int*；b: int  ← 仅 a 有 * */
int *a, *b;   /* 两个都是指针 */
```

若 `int*` 是完整独立类型，`b` 也该是指针——现实不是。  
→ **`*` 绑定变量名，不绑定前面的基础类型名。**

---

## 2. 两层勿混

| 层 | 说法 | |
|----|------|--|
| **声明语法** | `*` 属声明符；`int* a,b` 陷阱 | 啃标准 / 笔试严守 |
| **类型系统 / 口语** | 「`p` 的类型是 `char *` / pointer to char」 | 写代码、读内核完全可用 |

之前否定的是：「语法上 `char*` 是不可分割的类型单元」。  
**没有否定**：存在「指向 char 的指针」这种类型。

---

## 3. 套到 `char *argv[]`

声明读法：`argv` 是数组；元素带 `*` → 每项 *pointer to char*。  
使用侧：`*(argv[i])` 得 `char` → `argv[i]` 是指向 `char` 的指针。与上完全一致。

口语「元素类型是 `char *`」= 类型系统说法；语法上仍是 `*` 跟在名字一侧（勿与 `int* a,b` 陷阱混谈）。

---

## 4. 延伸：`char **argv`（形参等价物）逐层

形参 `char *argv[]` ≡ `char **argv`。

| 表达式 | 读法 | 类型（概念） |
|--------|------|----------------|
| `argv` | 指向「`char *`」的指针 | pointer to pointer to char |
| `*argv` / `argv[0]` | 解一层 → 一个 `char *` | pointer to char |
| `**argv` / `argv[0][0]` | 再解 → 字符 | `char` |

```
argv (char **) ──→ [ char* | char* | ... | NULL ]
                      │
                      └──→ 'a','p','p','\0'
```

---

## 5. 自测

1. `int* x, y;` 里 `y` 是什么？→ **`int`**。  
2. 为何推荐写成 `int *x, *y;`？→ `*` 跟名字，一眼不错绑。  
3. `char **p` 与 `char *p[]`（形参）关系？→ **等价**（第一维退化）。
