# 5.3.1 数组形参为何退化为指针（底层）

> 结论：C **不允许把完整数组拷贝进函数栈**（栈溢出 + 拷贝代价）；形参 `T arr[]` / `T arr[N]` **一律等价 `T *arr`**。  
> 详解正文：[5.3](./5.3-指针与数组.md) · 联动 [1.1.1 argv](../ch01-introduction/1.1.1-命令行参数-main-argc-argv.md) · [5.6.1](./5.6.1-指针数组vs数组指针-精炼.md)

---

## 1. 硬件 / 性能动机

若 `void f(int arr[1000]);` 真把 1000 个 `int` 整表压栈：

1. 大数组易 **栈溢出**  
2. 每次调用都是 **大块拷贝**  
3. 多数 API 只要 **首地址** 即可  

→ 只传首元素地址（64 位下通常 8 字节）。这是退化规则的原始动机。

---

## 2. 两条关联规则

### 规则 A（表达式，处处生效）

除 **`sizeof(arr)`、`&arr`** 外，数组名在表达式中 → **首元素指针**。

```c
int a[10];
int *p = a;   /* a → &a[0] */
```

### 规则 B（形参语法）

```c
void func(int arr[]);   /* 编译器重写为 void func(int *arr); */
```

调用 `func(buf)` 时，实参 `buf` 已按规则 A 变成 `&buf[0]`；形参用指针接收，与运行模型一致。  
`T arr[]` 写成数组模样，是**阅读向的语法糖**，不是栈上再开一份数组。

---

## 3. 只退化第一层（面试高频）

```c
void f1(int arr[]);        /* → int * */
void f2(int arr[][5]);     /* → int (*arr)[5]  数组指针；不是 int ** */
```

二维：外层 `[]` 退化；内层维度保留在元素类型里。

---

## 4. `sizeof` 证据

```c
void func(int arr[]) {
    printf("%zu\n", sizeof(arr));   /* 指针宽，如 8 */
}
int buf[10];
printf("%zu\n", sizeof(buf));       /* 40 = 10*sizeof(int) */
func(buf);
```

形参侧 **再也拿不到原数组长度** → C API 常另传 `len`（如 `read`）。

Demo：[`demo_param_decay`](../ch01-introduction/demo/demo_param_decay/)

---

## 5. 延伸：`a` vs `&a`（嵌入式常考）

| 表达式 | 类型（`int a[10]`） | `+1` 步长 |
|--------|---------------------|-----------|
| `a` / `&a[0]` | `int *` | `sizeof(int)` |
| `&a` | `int (*)[10]` | **整行** `10*sizeof(int)` |

数值上 `a` 与 `&a` 常相同，**类型与指针算术不同**。详见 [5.3 §两大不退化例外](./5.3-指针与数组.md)。

---

## 6. 与 `argv`

```c
int main(int argc, char *argv[])  /* → char **argv */
```

内核/`execve` 传来的是**指针表首址**；每项仍是 `char *`。`argc` 补长度信息。

---

## 精简背诵

1. 目的：避免整表入栈  
2. 形参 `T a[]`/`T a[N]` ≡ `T *`  
3. 仅第一层退化；`T a[][N]` ≡ `T (*)[N]`  
4. 退化后无长度 → 另传 `n`  
5. 与「数组名表达式退化」同一体系；`sizeof`/`&` 不退化
