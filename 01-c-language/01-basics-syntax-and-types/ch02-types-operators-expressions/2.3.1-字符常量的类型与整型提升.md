# 2.3.1 字符常量的类型与整型提升

## 本节讲什么

把 [2.3 §3](./2.3-常量.md) 里那一行「字符常量类型是 **`int`**」拆到底：**变量本身的类型** 和 **整数提升（integer promotion）** 是两件事，而 `sizeof('c')` 正是钉死这个区分的那根钉子 —— 它等于 **4**，不是 1。

本节做三件事：给出 **取证手段**（`_Generic` / `static_assert` / 编译器告警），划清「提升发生 / 不发生」的 **边界表**，并现场复现 `char ch = 0xFF` 这个在网络与内核代码里反复出现的经典 bug。

**前置**：[2.3 常量 §3](./2.3-常量.md)、[2.2 数据类型及长度](./2.2-数据类型及长度.md)、[2.2.3 stdint.h](./2.2.3-stdint.h.md)。  
**后续**：[2.7 类型转换](./2.7-类型转换.md)（提升的完整规则 + signed/unsigned 混算）、[2.9 按位运算符](./2.9-按位运算符.md)、[ch07 输入输出](../ch07-input-and-output/)（`getchar` 返回 `int` 的原因）。

> **配套 demo**：[`demo/demo02_char_promotion`](./demo/demo02_char_promotion/main.c)。本节所有数字均为 **本机实测**（clang 23.1.0 / arm64 macOS，`-Wall -Wextra -std=c11` 零告警）。

## 要点

### 0. 先把两件事分开（本节最重要的一句）

| 问题 | 答案 |
|------|------|
| `'x'` 这个 **字符常量** 是什么类型？ | **`int`** —— 标准硬性规定，C89 到 C23 都一样 |
| `char c` 这个 **变量** 是什么类型？ | **`char`** —— 1 字节；**有无符号是实现定义** |
| `sizeof('c')` | **4**（= `sizeof(int)`） |
| `sizeof(c)` | **1** |
| `c` 用于表达式 / 传参时 | 提升为 **`int`** 后再算 |

**关键区分**：

- **类型** 是 **静态属性**，声明那一刻就定了，编译期可见；
- **提升** 是 **表达式求值时的临时转换** —— 求值完就没了，**不会改变变量自己的类型**。

所以「`c` 参与运算会变成 `int`」这句话，严格说是：**`c` 参与运算时，使用的是一个提升后的 `int` 临时值；`c` 本身仍然是 `char`（`sizeof(c)` 依旧 1）。**

### 1. 标准怎么说（出处别记混）

| 标准 | 章节号 | 标题 |
|------|--------|------|
| C89/C90 | §3.1.3.4 | Character constants |
| C99 / C11 / C17 | **§6.4.4.4** | Character constants |
| C23 | §6.4.4.5 | （编号后移） |

**规定原文**（单字节整数字符常量）：

> Such constant **has type `int`** and a value equal to the representation of c-char in the execution character set as a value of type `char` mapped to `int`.

同一节里还有一句经常被忽略、但后面那个坑全靠它的话：

> a character constant may have a **negative value if `char` is signed**: on such implementations **`'\xFF'` is an `int` with the value `-1`**.

**完整的字符常量类型表**：

| 写法 | 类型 | 备注 |
|------|------|------|
| `'a'` / `'\n'` / `'\x41'` | **`int`** | 值 = 执行字符集里的字节值；**始终是 int** |
| `u8'a'`（**C23 起**） | `char8_t` | 值 = ISO 10646 码点；**唯一不是 `int` 的单字符常量** |
| `u'a'`（C11 起） | `char16_t` | 值 = UTF-16 码元 |
| `U'a'`（C11 起） | `char32_t` | 值 = UTF-32 码元 |
| `L'a'` | `wchar_t` | Linux 4 字节，Windows 2 字节 —— 平台相关 |
| `'AB'` 多字符 | **`int`** | 类型仍是 `int`，**值实现定义**（clang 按大端拼接字节） |

**C++ 对照**：普通字符字面量类型是 **`char`**，不是 `int` —— 这是同一个语法在两种语言里唯一的硬差异，见文末对照表。

### 2. 三种「取证」手段

推断「这个表达式是什么类型」时，别靠背 —— 让编译器回答。

#### 2.1 `_Generic`：编译期问类型（C11）

```c
#define TYPEOF(x) _Generic((x),          \
        char: "char",                    \
        signed char: "signed char",      \
        unsigned char: "unsigned char",  \
        short: "short",                  \
        int: "int",                      \
        unsigned int: "unsigned int",    \
        long: "long",                    \
        default: "other")

char c = 'A';
printf("%s\n", TYPEOF('c'));    /* int  */
printf("%s\n", TYPEOF(c));      /* char */
printf("%s\n", TYPEOF(c + c));  /* int  */
```

**为什么它能区分？** `_Generic` 的控制表达式会做 **左值转换 / 数组转指针 / 函数转指针**，但 **不做整数提升**。所以 `TYPEOF(c)` 老老实实给出 `char`，`TYPEOF(c + c)` 给出 `int` —— 恰好就是本节要区分的这两件事。

本机实测（`demo02` §2）：

| 表达式 | 类型 |
|--------|------|
| `'c'` | `int` |
| `c` | `char` |
| `c + c` | `int` |
| `c << 1` | `int` |
| `c == 0` | `int` |
| `~c` | `int` |

#### 2.2 `static_assert`：编译期断言（C11）

```c
#include <assert.h>
static_assert(sizeof('c') == sizeof(int), "C 语言里字符常量的类型就是 int");
```

这行编译得过，就说明「字符常量是 `int`」这条在本平台成立。想反过来验证 C++，同一个文件用 `clang++` 编译这行 **直接报错**。

#### 2.3 编译器告警：让编译器替你抓

```c
char ch = (char)0xFF;
if (ch == 0xFF) puts("eq");     /* clang: warning: result of comparison of
                                   constant 255 with expression of type 'char'
                                   is always false
                                   [-Wtautological-constant-out-of-range-compare] */
```

本机实测：**clang 23.1.0 在 `-Wall` 下默认就报**这条告警，一眼就能定位。GCC 侧对应的是 `-Wtype-limits` / `-Wtautological-compare`（**本机 `gcc` 是 Xcode 的 shim、未同意 license，跑不动；这一条未在 gcc 上实测**，待 Pi 上 `gcc-14` 复核）。

**结论**：这类「提升 + 符号性」的 bug，**带上 `-Wall -Wextra -Wconversion` 编译能把大半挡在门外**。

### 3. 边界表：什么时候提升，什么时候不提升

这是本节最实用的一张表 —— **「参与运算就提升」是粗略说法，`sizeof` 就是反例**：

| 上下文 | 整数提升 | 实测证据 |
|--------|:--------:|----------|
| 算术 `+ - * / %` | ✅ | `TYPEOF(c + c)` = `int` |
| 比较 `< > <= >= == !=` | ✅ | `TYPEOF(c == 0)` = `int` |
| 位运算 `& \| ^ ~`、逻辑 `!` | ✅ | `TYPEOF(~c)` = `int` |
| 移位 `<< >>` | ✅ | `TYPEOF(c << 1)` = `int` |
| 三元 `?:` 的两支 | ✅ | 见 [2.11](./2.11-条件表达式.md) |
| **函数传参**（含 `printf` 可变参数） | ✅ | 传进去的是 `int`，见 §6 |
| `switch (c)` 的整型条件 | ✅ | `case 'a':` 匹配的是 `int` 97 |
| **`sizeof` 的操作数** | ❌ | `sizeof(c)` = **1** |
| **`_Generic` 控制表达式** | ❌ | `TYPEOF(c)` = `char` |
| `&c` 取地址 / `_Alignof` | ❌ | 取的是 `char` 对象本身 |
| 赋值给更宽类型（`int x = c;`） | 效果类似，但严格说属 **转换** 不是提升 | 见 [2.7](./2.7-类型转换.md) |

**怎么把「不提升」的场合变成「提升」？自己造一个表达式就行**：

```c
sizeof(c)      /* 1 —— 变量本身 */
sizeof(+c)     /* 4 —— 一元 + 是表达式，提升发生 */
sizeof(c + 0)  /* 4 */
sizeof(c == 0) /* 4 */
sizeof(c << 0) /* 4 */
```

本机实测输出：

```
sizeof(c)      = 1   <- 变量本身，不提升
sizeof(+c)     = 4   <- 一元 + 是表达式，提升发生
sizeof(-c)     = 4
sizeof(c << 0) = 4
sizeof(c + 0)  = 4
sizeof(c == 0) = 4
```

**想要「1 字节的字符常量」怎么写？** 显式转：`sizeof((char)'c')` = 1。或者干脆用 `sizeof(char)`（语义更清楚）。

### 4. 提升的**正收益**：窄类型算术不塌

提升不是纯麻烦，它是 C 里 **窄类型能参与算术**的前提：

```c
unsigned char x = 100, y = 200;
printf("%d\n", x - y);                      /* -100：先提升为 int 再减 */
printf("%d\n", (unsigned char)(x - y));     /*  156：截回 8 位才回绕 */
```

本机实测：

```
x=100, y=200  ->  x - y        = -100   <- 提升为 int，得到负数而非回绕
             ->  (unsigned char)(x - y) = 156    <- 截回 8 位才是回绕值
```

若 C 在 8 位里算，`100 - 200` 会悄悄回绕成 `156`，负差就永远判不出来。**「小减大得负数」这个直觉，是整型提升给的。**

（[2.7 §一.1](./2.7-类型转换.md) 里 `uint8_t a=200, b=100; a-b == 100` 是同一个机制的顺光面。）

### 5. 经典坑：`char ch = 0xFF`

```c
char ch = 0xFF;              /* 0xFF = 255，char 装不下！ */
if (ch == 0xFF) { ... }      /* 永远不成立 */
```

**逐步拆解**（本机实测，`char` 为 **signed**）：

1. `char ch = 0xFF;` —— `255` 是 `int`，赋给 8 位有符号 `char` → **实现定义**，本机按补码截断成 **`-1`**；
2. `ch` 参与比较 → 提升为 `int` → **`0xFFFFFFFF`（即 -1）**；
3. 另一边 `0xFF` 字面量本身就是 `int` → **`0x000000FF`（即 255）**；
4. `-1 == 255` → **false**。

本机实测输出：

```
char is signed on this platform
(int)ch                    = -1   (0xFFFFFFFF)
ch == mask(0xFF)           -> false   <- 两边都提升为 int 再比
ch == -1                   -> true
(unsigned char)ch == 0xFF  -> true    <- 截回 8 位再提升，才对得上
```

**三条修法**（按推荐度排序）：

| # | 写法 | 说明 |
|---|------|------|
| 1 | `uint8_t ch = 0xFF;` | **首选** —— 用 `stdint.h` 定宽类型，语义明确「我是一个 8 位无符号字节」（[2.2.3](./2.2.3-stdint.h.md)） |
| 2 | `if ((unsigned char)ch == 0xFF)` | 比较前截回 8 位。**网络报文、寄存器**读出的字节必须这么写 |
| 3 | `if (ch == (char)0xFF)` 或 `ch == -1` | 把常量也降到 `char` 语义。缺点：可读性差，别人看不出你在防什么 |

**为什么内核 / 网络代码里天天见**：协议字段、寄存器值天然是「8 位无符号字节」，而裸 `char` 的符号性是 **实现定义** 的 —— 同一段代码在 x86_64/arm64 Linux（signed char）能过，在把 `char` 当无符号的平台上语义就变了。**跨平台代码里，字节就得写成 `unsigned char` / `uint8_t`。**

### 6. 同一个规则的另一面：为什么 `getchar()` 返回 `int`

标准库的原型是：

```c
int getchar(void);      /* 不是 char */
```

理由和内核对齐：它要返回 **256 个字符值 + 一个 `EOF`（-1）**，共 257 种可能 —— **`char` 装不下**。写成 `char c = getchar();` 之后，`EOF` 会被截成 `0xFF` 再提升为 `-1` 之外的形态，`while ((c = getchar()) != EOF)` 直接死循环。

```c
int c;                                   /* ✅ 必须 int */
while ((c = getchar()) != EOF) { ... }

char c;                                  /* ❌ EOF 判不出来 */
while ((c = getchar()) != EOF) { ... }
```

**同一条规则的两种面孔**：`'x'` 是 `int`（因为常量的类型是 int）；`getchar()` 返回 `int`（因为要让提升后的值装得下）。见 [ch07 输入输出](../ch07-input-and-output/)。

### 7. 那 `printf("%c", c)` 为什么没事

因为提升 **已经替你做完了**：`c`（`char`）→ 提升为 `int`（值 65）→ 传进 `printf` → `printf` 内部再按 `%c` 取低 8 位输出。

```c
char z = 'A';
printf("%c", z);    /* A   —— 传进去的是 int 65，按 %c 取低字节 */
printf("%d", z);    /* 65  —— 同一个 int，按 %d 打印 */
```

**⚠ 反例**：`printf("%s", z)` 是 **UB** —— 传进去的是 `int`（无论提升与否都不是指针），`%s` 却按 `char *` 解引用。可变参数函数 **没有原型保护**，类型错了编译器一般也不报，这是 [2.7](./2.7-类型转换.md) 特别强调「不依赖隐式规则」的场景。

本机实测：

```
printf("%c", z) = A      printf("%d", z) = 65
```

## 本节核心考点

1. **`'x'` 是 `int`**（C89–C23 皆然）；`char c` 是 `char`。`sizeof('c')` = **4**，`sizeof(c)` = **1**
2. **类型是静态的，提升是求值期的**。变量参与运算 **不会改变自身类型**
3. **`sizeof` 的操作数、`_Generic` 的控制表达式不做整数提升**；想让提升发生就造表达式（`sizeof(+c)` = 4）
4. **字符常量类型表**：`'a'`→`int`；`u8'a'`（C23）→`char8_t`；`u'a'`/`U'a'`/`L'a'` → `char16_t`/`char32_t`/`wchar_t`；多字符 `'AB'`→`int` 但值实现定义
5. **`'\xFF'` 在 `char` 有符号的实现上是值为 -1 的 `int`** —— 标准明写，这就是 `ch == 0xFF` 恒假的根源
6. **修法**：字节一律 `uint8_t` / `unsigned char`；比较前先对齐符号性
7. **`getchar()` 返回 `int`** 和「字符常量是 `int`」是同一套规则的两种面孔
8. **`printf("%c", c)` 安全（提升已代为完成）**，`printf("%s", c)` 是 UB

## HFT / 底层开发的用处

1. **协议字段解析**：帧头字段、状态码天然是「8 位无符号字节」。读进 `char` 再和 `0x80`、`0xFF` 这种掩码比，就是 §5 的坑 —— 一律 `uint8_t`（[2.2.3](./2.2.3-stdint.h.md)）
2. **寄存器位域**：`volatile uint8_t *reg` 读回的值参与运算必先提升为 `int`；显式 cast 到 `uint32_t` 后再移位/掩码，避免符号扩展把高位带进来
3. **`switch` 分发**：`case 'A':` 能工作正是因为 `case` 常量是 `int`、`switch` 条件也被提升 —— 但这也意味着 **`switch` 不会帮你发现 `char`/`int` 的符号性差异**
4. **热路径上的对齐成本**：提升本身是零成本（寄存器本来就是 32 位宽），编译器直接生成 32 位运算；**代价只在语义上**，不在指令数上
5. **编译开关**：CI / 本地构建带 `-Wall -Wextra -Wconversion -Wsign-compare`，能把这一类问题挡在提交前

```c
/* 报文解析的安全写法：字段一律无符号定宽，比较前统一符号性 */
uint8_t flags = buf[3];
if ((flags & 0x80u) != 0u) { ... }          /* 掩码带 u，两边都走 unsigned */
if ((uint32_t)flags == 0xFFu) { ... }       /* 显式拓宽，语义清楚 */
```

## 与 C++ 的差异

| 主题 | C | C++ |
|------|---|-----|
| **普通字符字面量 `'a'` 的类型** | **`int`** | **`char`**（`sizeof('c')` = 1） |
| `sizeof('c')` | **4** | **1** |
| 多字符常量 `'AB'` | 类型 `int`，值实现定义 | 类型 `int`，值实现定义（C++17 起 `int`，语义收紧） |
| `printf("%c", c)` / 模板推导 | 提升后传 `int` | `char` 不提升时按 `char` 处理，模板里能看出差别 |
| 定宽字节 | `<stdint.h>` 的 `uint8_t` | `<cstdint>` 的 `std::uint8_t` |
| `u8'a'` | C23 起 `char8_t` | C++17 起 `char`，C++20 起 `char8_t` |

**实践含义**：同一份「`sizeof('c')` 是几」的代码，C 里是 4、C++ 里是 1 —— 混合编译的工程里，凡是依赖这个值的断言/数组长度，**两边要分开写**。

char c = 'A';
printf("%zu\n", sizeof('c'));
printf("%zu\n", sizeof(c));

1      sizeof((char)'c')  —— 显式降到 char

**题目 2：** 这段代码输出什么？为什么？

```c
char ch = 0xFF;
printf("%d\n", ch);
printf("%d\n", (int)ch);
printf("%d\n", (unsigned char)ch);
printf("%s\n", (ch == 0xFF) ? "equal" : "not equal");
```

<details>
<summary>参考答案</summary>

```
-1          ch 的实际值：0xFF 装进 8 位有符号 char，按补码是实现定义 → -1
-1          (int)ch：提升为 int，符号扩展 → 0xFFFFFFFF
255         (unsigned char)ch：先截回 8 位无符号 255，再提升为 int 打印
not equal   ch 提升为 int 得 -1；0xFF 字面量是 int 255；-1 != 255
```

**修正**：把类型改成 `uint8_t ch = 0xFF;`，或比较时写 `(unsigned char)ch == 0xFF`。

**复习**：[2.3.1 §5](./2.3.1-字符常量的类型与整型提升.md)。用 `-Wall` 编译，clang 会直接告诉你「comparison is always false」。

</details>

**题目 3：** 用 `_Generic` 与 `static_assert` 各写一行，证明「C 里字符常量的类型是 `int`」。这两行的差别是什么？

<details>
<summary>参考答案</summary>

```c
#include <assert.h>

/* 1) 编译期「查出」类型：_Generic 控制表达式不做整数提升，所以能区分 'c' 与 c */
#define TYPEOF(x) _Generic((x), char: "char", int: "int", default: "other")
printf("%s\n", TYPEOF('c'));        /* int  */
printf("%s\n", TYPEOF((char)'c'));  /* char */

/* 2) 编译期「断言」：成立才编得过，不成立直接编译错误 */
static_assert(sizeof('c') == sizeof(int), "字符常量的类型必须是 int");
```

**差别**：`_Generic` 是 **取值**（运行时打印出来，能看见具体类型）；`static_assert` 是 **断言**（编译期判真伪，失败即中断编译）。**前者用来观察，后者用来防守。**

**复习**：[2.3.1 §2](./2.3.1-字符常量的类型与整型提升.md)、demo `demo02_char_promotion`。

</details>
