# 6.8 联合

## 本节讲什么

**`union`**：多个成员**共享同一块内存**，同一时刻只有**一个成员**的值有效；大小至少为最大成员的大小。

## 要点

```c
union u_tag {
    int i;
    float f;
    char str[4];
};

union u_tag u;
u.i = 123;      /* 写入 i 的布局 */
/* 此时读 u.f 依赖实现，类型 punning —— 需谨慎 */
```

- 所有成员**首地址相同**
- **`sizeof(union)`** = 最大成员大小（含对齐到 union 对齐要求）
- 写入一成员后再读另一成员：C99+ 有 **common initial sequence** 等规则；否则可能未定义或实现定义

## 用途

| 场景 | 用法 |
|------|------|
| 二进制转换 | `u32` 与 4×`u8` 同址查看 |
| 可变报文 | 同一缓冲按类型解析不同字段 |
| 寄存器多视图 | 整字写入、位域/字节读出 |
| 省内存 | 互斥状态机若干字段共用存储 |

## 与 struct 对比（考点）

| | struct | union |
|---|--------|--------|
| 内存 | 各成员独立，可能 padding | 成员重叠 |
| 同时有效 | 全部成员各有存储 | 同一时刻通常只认一个 |
| 典型用途 | 记录聚合 | 类型双关、省空间 |

## 注意

- **无内置同步**；多线程同时写不同成员 → 数据竞争
- 网络协议公开格式优先 **显式偏移 + struct**，少用 union 避免可移植性问题

## 常见陷阱

1. **写入一成员后读另一成员（类型双关）多为 UB**：`u.i = 1; printf("%f", u.f);` 除 C99 的 common initial sequence（两个结构体共享相同开头的成员）外，跨类型读取是实现定义或未定义。想安全做 int/float 双关，用 `memcpy` 而非直接 union 读。
2. **忘记记录当前有效成员**：union 同一时刻只有一个成员有效，但 union 本身不带 tag。读错成员得到的是垃圾。解决：**配一个外部 tag**（`enum type; union { ... } u;`），即 tagged union 模式。
3. **对 union 做 `==` 比较非法**：`union { int i; float f; } u; if (u == v)` 编译错误——union 没有 `==` 运算符（不知该比哪个成员）。必须取出当前有效成员再比。

## 自测题

**1. 选择**：`sizeof(union { int i; char c[6]; })`（假设 int=4 字节，union 对齐为 4）是多少？
- A. 4
- B. 6
- C. 8
- D. 10

<details><summary>答案</summary>
C。union 大小至少为最大成员（`char c[6]` = 6 字节），但要对齐到 union 的对齐要求（int 对齐 = 4），所以补齐到 4 的倍数 = 8。注意 union 对齐取所有成员中最严格的对齐要求。实际 sizeof 需看编译器输出，不能手算臆断。
</details>

**2. 判断**：union 的所有成员首地址相同。

<details><summary>答案</summary>
对。这是 union 的核心特性——所有成员共享同一块内存的起始地址。`&u.i == &u.f == &u.c` 都指向 union 的起始字节。这也是 union 能做类型双关的基础（同一地址按不同类型解读）。
</details>

**3. 踩坑**：`union { int i; float f; } u; u.i = 0x40490FDB; printf("%f\n", u.f);` 输出 3.141593，但换到另一台机器可能不同，为什么？

<details><summary>答案</summary>
这是类型双关（type punning）——把 int 的位模式当 float 读。结果依赖：
1. **字节序**（大端/小端）——int 的 0x40490FDB 在内存中的排列不同，float 解读不同。
2. **int 和 float 的大小/对齐**——若 int 不是 32 位则错位。
3. C 标准上这种跨类型读取是**实现定义/未定义**，可移植代码应用 `memcpy`：`float f; memcpy(&f, &u.i, sizeof f);`。网络协议/二进制解析尤其要注意字节序。
</details>

**4. 应用**：用 union + enum tag 实现一个可变类型 `Value`，能存 int、double 或字符串，并写一个 `print_value` 函数。

<details><summary>答案</summary>
```c
enum Type { T_INT, T_DOUBLE, T_STR };
struct Value {
    enum Type type;
    union {
        int i;
        double d;
        char *s;
    } u;
};

void print_value(struct Value v) {
    switch (v.type) {
        case T_INT:    printf("%d\n", v.u.i); break;
        case T_DOUBLE: printf("%f\n", v.u.d); break;
        case T_STR:    printf("%s\n", v.u.s); break;
    }
}
```
这就是 tagged union——内核 `sk_buff`、AST 节点、JSON 值都用这个模式。C 没有变体类型，这是最接近的模拟。
</details>
