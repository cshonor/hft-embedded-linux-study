# 8.3 open、creat、close 和 unlink

## 本节讲什么

打开/创建/关闭文件，以及 **unlink** 删除目录项。配合 **link** 理解硬链接与引用计数。

## 要点

### open

```c
#include <fcntl.h>
int open(const char *path, int flags, /* mode_t mode */);
```

常用 **flags**（可 `|` 组合）：

| 标志 | 含义 |
|------|------|
| `O_RDONLY` | 只读 |
| `O_WRONLY` | 只写 |
| `O_RDWR` | 读写 |
| `O_CREAT` | 不存在则创建（需 `mode`） |
| `O_TRUNC` | 存在则截断为 0 |
| `O_APPEND` | 追加写 |

- 成功返回 **fd**；失败 **`-1`**

### creat

```c
int creat(const char *path, mode_t mode);
```

- 等价 **`open(path, O_WRONLY | O_CREAT | O_TRUNC, mode)`**

### close

```c
close(fd);
```

- 释放 fd 编号；内核在**引用计数为 0** 时释放文件对象
- 进程 **`exit`** 时关闭所有 fd（除 `FD_CLOEXEC` 等例外）

### unlink

```c
unlink(path);
```

- 删除**目录项**（文件名），**不立刻删磁盘数据**
- 硬链接计数减 1；为 **0** 且无进程打开该 inode 时才释放空间
- 文件仍被某 fd 打开时，unlink 后该 fd 仍可读写

### link（硬链接）

```c
link(oldpath, newpath);
```

- 两个目录项指向**同一 inode**
- 不能跨文件系统；目录一般不可硬链接

## 考点

- **unlink vs 删除数据**：计数与 fd 仍打开
- **O_CREAT** 必须写八进制 **mode**（如 `0644`），还受 **umask** 影响

## 与后续衔接

设备节点 `open("/dev/xxx")`；HFT 日志 `O_APPEND` 追加；ELF/镜像 `O_RDONLY`。

## 常见陷阱

1. **O_CREAT 忘传 mode 参数**：`open("log.txt", O_WRONLY | O_CREAT)` ——少了第三个参数 `mode`。open 的第三个参数是可变参数，不传时读到栈上的垃圾值，可能创建权限奇怪的文件（如 0777 或 0000）。正确：`open("log.txt", O_WRONLY | O_CREAT | O_TRUNC, 0644)`。注意：只有 flags 含 `O_CREAT`（或 `O_TMPFILE`）时才需要 mode，且 mode 受 `umask` 影响：实际权限 = mode & ~umask。

2. **unlink 后以为磁盘空间立即释放**：`unlink("big.dat")` 只删目录项（文件名），**不删 inode 和数据块**。如果仍有进程打开该文件（持有 fd），空间不释放——直到最后一个 fd 关闭。利用这个特性可以做"临时文件"：open + unlink，文件在 /tmp 不可见但 fd 仍可读写，进程退出自动回收。但也可能导致磁盘被"已删除但仍打开"的大文件撑满。

3. **open 的 O_TRUNC 意外截断已有文件**：`open("config.txt", O_WRONLY | O_TRUNC)` ——如果 config.txt 已存在且有内容，O_TRUNC 立即清零文件。这是 shell `>` 重定向的底层原理，但如果误操作会丢失数据。安全做法：先 `open(O_RDONLY)` 检查文件是否存在，或用 `O_CREAT | O_EXCL`（文件已存在则失败）保护。日志文件追加用 `O_APPEND` 而非 `O_TRUNC`。

## 自测题

**1. 选择**：`open("f.txt", O_WRONLY | O_CREAT, 0644)` 在 umask=022 下创建的文件权限是？
- A. 0644
- B. 0622
- C. 0640
- D. 0777

<details><summary>答案</summary>
B。实际权限 = mode & ~umask = 0644 & ~022 = 0644 & 0755 = 0644 - 0020 = 0622。具体：0644 = rw-r--r--，umask 022 去掉同组 w 和其他 w → 0622 = rw--w--w-。注意 umask 影响所有 O_CREAT 创建的文件。临时改 umask 用 `umask(0)` 创建后再恢复，或创建后用 `fchmod(fd, 0644)` 精确设置。
</details>

**2. 判断**：`unlink` 删除文件后，如果有进程仍持有该文件的 fd，磁盘空间会立即释放。

<details><summary>答案</summary>
错。unlink 只删除**目录项**（文件名到 inode 的映射），减少 inode 的**硬链接计数**。当链接计数为 0 **且**没有进程打开该文件（无 fd 指向 inode）时，内核才释放数据块。如果有进程仍持有 fd，空间不释放——直到最后一个 fd 关闭。这个特性常用于临时文件：`fd = open(...); unlink(path);` ——文件在文件系统中不可见，但 fd 仍可读写，进程退出自动回收。
</details>

**3. 踩坑**：以下代码在多进程同时写同一日志文件时，日志行交错混乱，为什么？
```c
int fd = open("app.log", O_WRONLY | O_CREAT, 0644);
write(fd, "START\n", 6);
write(fd, "END\n", 4);
```

<details><summary>答案</summary>
没有 `O_APPEND` 标志时，每个进程的 write 从各自的文件偏移写入——多个进程同时写会互相覆盖或交错。加 `O_APPEND` 后，每次 write 前内核原子地把偏移移到文件末尾，保证追加不冲突。但 `O_APPEND` 只保证每次 write 原子追加，**不保证**单次 write 不被信号拆断（短 write）。大块写入仍需循环写或用 `pwrite`。
</details>

**4. 应用**：写一个安全的临时文件创建函数——文件不存在则创建，已存在则失败（防止覆盖），权限 0600。

<details><summary>答案</summary>
```c
int create_temp_file(const char *path) {
    /* O_CREAT | O_EXCL：文件已存在则 open 失败（EEXIST） */
    int fd = open(path, O_WRONLY | O_CREAT | O_EXCL, 0600);
    if (fd < 0 && errno == EEXIST) {
        fprintf(stderr, "%s already exists\n", path);
        return -1;
    }
    if (fd < 0) { perror("open"); return -1; }
    return fd;
}
```
关键：`O_EXCL` + `O_CREAT` 组合确保只在文件不存在时创建——防止符号链接攻击和意外覆盖。`mkstemp` 函数内部就是用这个模式生成随机文件名。权限 0600（仅 owner 读写）防止其他用户读取临时文件中的敏感数据。
</details>
