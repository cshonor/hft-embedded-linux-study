# 8.5 实例：fopen 和 getc 函数的实现

## 本节讲什么

K&R 用 **fd + read + 用户缓冲** 手写简化版 **`fopen`/`getc`**，揭示第 7 章 stdio 的本质：**在系统调用之上加缓冲与状态**。

## 要点

### 典型 FILE 结构（概念）

```c
struct io_buf {
    int fd;           /* 底层文件描述符 */
    char *buf;        /* 缓冲 */
    char *bufp;       /* 当前读指针 */
    int n;            /* 缓冲中剩余字符数 */
    /* 错误/EOF 标志等 */
};
```

### getc 逻辑

1. 若缓冲有字符 → 直接返回
2. 否则 **`read(fd, buf, BUFSIZ)`**  refill
3. `read` 返回 0 → EOF；`-1` → 错误

### fopen 逻辑

1. **`open(path, flags, mode)`** 得 fd
2. 分配 `FILE` 结构与缓冲
3. 返回指针供 `getc`/`putc` 使用

## stdio vs 原生 read（重难点）

| stdio 带缓冲 | read 无 stdio 缓冲 |
|--------------|-------------------|
| 减少 syscall，吞吐高 | 单次延迟可控 |
| 交互式可能行缓冲 | 适合 HFT、自管 ring |
| `printf` 需 flush | 直接写内核 |

## 与后续衔接

理解后可读 glibc `stdio` 源码、实现简易日志库；**`fileno(fp)`** 在 fd 与 `FILE*` 间桥接。

## FILE 结构的本质

K&R 展示的简化 FILE 结构揭示了 stdio 的核心思想——**在 fd 之上加用户态缓冲**：

```c
typedef struct {
    int fd;           /* 底层文件描述符 */
    unsigned char *buf;  /* 缓冲区 */
    unsigned char *bufp; /* 当前读写位置 */
    int n;            /* 缓冲中剩余字节 */
    int flags;        /* EOF / 错误 / 读写模式 */
} FILE;
```

**getc 的完整逻辑**：

```
getc(fp):
  if (fp->n > 0)              ← 缓冲区还有数据？
      return *fp->bufp++;      ← 直接返回一个字符，不 syscall
  else                         ← 缓冲区空了
      n = read(fp->fd, fp->buf, BUFSIZ)  ← refill：一次 syscall 读一批
      if (n == 0) { fp->flags |= EOF; return EOF; }
      if (n < 0)  { fp->flags |= ERR;   return EOF; }
      fp->n = n; fp->bufp = fp->buf;
      return *fp->bufp++;
```

**缓冲的意义**：读一个字符如果不缓冲，每次都要 syscall（用户态→内核态切换约 1-2μs）。缓冲后 BUFSIZ（通常 4096 或 8192）个字符只需一次 syscall，平均每字符开销降到 ~0.25ns。这是 stdio 比裸 read 快的原因——以空间换时间。

## 常见陷阱

1. **混用 stdio 和 fd 操作导致缓冲不一致**：`fgetc(fp)` 读了一些数据到 stdio 缓冲，但内核 fd 的偏移已经前进了一整块（BUFSIZ 字节）。此时用 `lseek(fileno(fp), ...)` 改 fd 偏移，stdio 缓冲中的数据就失效了——下次 fgetc 读到的是旧缓冲内容，不是 lseek 后的新位置。混用前必须 `fflush(fp)`（写）或 `fseek(fp, 0, SEEK_CUR)`（读，丢弃缓冲）。

2. **getc 是宏还是函数**：K&R 的 getc 实现为宏（`#define getc(fp) ...`），避免函数调用开销。glibc 的 `getc` 和 `fgetc` 的区别就是宏 vs 函数——`getc` 可能展开为宏（有副作用风险），`fgetc` 一定是函数。表达式 `c = getc(fp)` 中 fp 如果有副作用（如 `getc(fp++)`），宏展开可能多次求值。标准要求 `getc` 可以是宏，`fgetc` 必须是真正的函数。

3. **putc 的写缓冲未 flush 就 crash**：`fputc('x', fp)` 只写到 stdio 缓冲，不一定立刻 `write` 到 fd。如果程序在此期间崩溃（SIGSEGV、`_exit`），缓冲区数据丢失。`exit` 会 flush 但 `_exit` 不会。调试时在关键点 `fflush(fp)` 或用 `setvbuf(fp, NULL, _IONBF, 0)` 关闭缓冲。日志文件用 `setvbuf(fp, NULL, _IOLBF, 0)` 设行缓冲，每行自动 flush。

## 自测题

**1. 选择**：getc/fgetc 读取一个字符时，什么时候会触发 `read` 系统调用？
- A. 每次调用 getc 都触发一次 read
- B. 只在 stdio 缓冲区为空时触发一次 read（读取 BUFSIZ 字节）
- C. 只在第一次调用时触发 read
- D. 从不触发 read

<details><summary>答案</summary>
B。getc 先检查 stdio 内部缓冲区是否有剩余字符，有则直接返回（不 syscall）。缓冲区空时才调用 `read` 一次读入 BUFSIZ 字节（通常 4KB/8KB），之后后续 getc 从缓冲区取字符。这意味着读 N 个字符只需约 N/BUFSIZ 次 syscall，而非 N 次。这是 stdio 比裸 read 高效的核心原因。HFT 场景如果需要精确控制每次 syscall，则用裸 read + 自管缓冲。
</details>

**2. 判断**：`getc` 和 `fgetc` 在 C 标准中完全等价。

<details><summary>答案</summary>
对（语义上）。两者都从指定流读一个字符，返回值和错误处理完全相同。区别在**实现**：`getc` 可以是宏（标准允许），`fgetc` 必须是真正的函数。宏版本避免了函数调用开销（适合高频字符读取），但参数有副作用时会多次展开。`getc(fp++)` 如果 getc 是宏，fp 可能自增多次。安全做法：参数无副作用时用 getc（快），有副作用时用 fgetc。
</details>

**3. 踩坑**：以下代码先用 `read` 读了一些数据，再 `fgetc(fp)` 读，结果读到的字符不对，为什么？
```c
int fd = open("data.txt", O_RDONLY);
read(fd, buf, 10);         /* 用 fd 直接读了 10 字节 */
FILE *fp = fdopen(fd, "r"); /* 包装成 FILE* */
char c = fgetc(fp);         /* 读到的不是第 11 个字符 */
```

<details><summary>答案</summary>
`fdopen` 把已打开的 fd 包装成 `FILE*`，但 fd 的**当前偏移**已经被 `read` 前进了 10 字节。`fgetc` 触发 `read` 从**当前位置**（第 11 字节）读一大块（BUFSIZ）到缓冲区，然后返回缓冲区第一个字符——这确实是第 11 个字符。但如果之前 `read` 读的不是 10 而是 BUFSIZ 的倍数，或者 fdopen 时 fd 偏移不在预期位置，结果就会混乱。混用 fd 和 FILE* 的关键是理解：两者共享同一个 fd 偏移，但 FILE* 有额外的用户态缓冲。先 `lseek` 确认偏移，或不要混用。
</details>

**4. 应用**：仿照 K&R 思路，写一个简化版 `my_getc`，用一个 4096 字节的缓冲区包装 `read`。

<details><summary>答案</summary>
```c
#include <unistd.h>
#include <stdlib.h>

typedef struct {
    int fd;
    unsigned char buf[4096];
    int pos;    /* 当前读取位置 */
    int len;    /* 缓冲中有效字节数 */
} MyFile;

int my_getc(MyFile *f) {
    if (f->pos >= f->len) {      /* 缓冲区空了 */
        f->len = read(f->fd, f->buf, sizeof f->buf);
        if (f->len <= 0) return -1;  /* EOF 或出错 */
        f->pos = 0;
    }
    return f->buf[f->pos++];
}

MyFile *my_fopen(const char *path, int flags) {
    int fd = open(path, flags);
    if (fd < 0) return NULL;
    MyFile *f = calloc(1, sizeof(MyFile));
    f->fd = fd;
    f->pos = f->len = 0;
    return f;
}
```
这就是 stdio 的核心机制——缓冲+refill。glibc 的 `__GI__IO_file_underflow` 做的是同样的事，只是更复杂（支持不同缓冲模式、错误处理、编码转换）。
</details>
