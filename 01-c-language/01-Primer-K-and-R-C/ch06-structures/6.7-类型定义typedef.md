# 6.7 类型定义 typedef

## 本节讲什么

**`typedef`** 为已有类型起**别名**，简化 `struct`、指针、函数指针等复杂声明；UEFI、Linux 内核用其统一跨平台字长命名。

## 要点

```c
typedef struct {
    int x, y;
} Point;          /* 之后可直接 Point p; */

typedef unsigned long UINT64;   /* UEFI 风格 */
typedef int (*comp_t)(const void *, const void *);
```

- **`typedef` 不创建新类型**，仅编译期别名
- 常与 **`struct`  tag** 并用：`typedef struct node { ... } Node;`
- 匿名 struct + typedef 可省略每次写 `struct`

### 工程规范

| 风格 | 例子 |
|------|------|
| UEFI | `UINTN`、`EFI_STATUS`、`EFI_HANDLE` |
| Linux 内核 | `u32`、`size_t`、`loff_t` |
| HFT | 固定宽度 `int64_t`、`uint32_t`（`<stdint.h>` 亦常用） |

### 与 `#define` 区别

- `typedef` 是类型，受类型检查
- `#define` 是文本替换，无类型安全

## 考点

- 读 typedef 复杂声明：与 5.12 右左法则结合
- **`typedef struct X X`** 自引用链表中的惯用写法

## 常见陷阱

1. **`typedef` 指针与 `#define` 指针的声明差异**：`typedef char* Str; Str a, b;` —— a 和 b **都是** `char*`。但 `#define Str char*` 后 `Str a, b;` —— a 是 `char*`，b 是 `char`（宏展开为 `char* a, b;`）。多人协作时这是隐蔽 bug 源。
2. **`const` 修饰 typedef 指针的方向**：`typedef char* Str; const Str s;` 等价于 `char* const s;`（**指针本身 const**，指向可变），而非 `const char* s;`（指向 const char）。typedef 把 `char*` 当整体，const 修饰的是这个整体。
3. **自引用结构 typedef 顺序错**：`typedef struct { Node *next; } Node;` 编译错误——定义体内用 `Node` 时它还没定义。正确写法：`typedef struct Node { struct Node *next; } Node;`（先有 tag `struct Node`，body 内用 `struct Node*`，typedef 别名在结尾）。

## 自测题

**1. 选择**：`typedef int (*FP)(int, int);` 中 `FP` 表示什么？
- A. 返回 int 的函数
- B. 指向"接受两个 int 返回 int 的函数"的指针
- C. 两个 int 参数的函数
- D. int 型二维数组

<details><summary>答案</summary>
B。用"右左法则"读：`FP` 是 typedef 名，往左看 `(*FP)` 表示指针，往右看 `(int,int)` 是参数，最左 `int` 是返回值。合起来：FP 是"指向 `int(int,int)` 函数的指针"。函数指针 typedef 是回调机制的基础（内核 `file_operations` 大量使用）。
</details>

**2. 判断**：`typedef` 创建了一个全新的、与原类型不同的类型。

<details><summary>答案</summary>
错。`typedef` 只创建**别名**，不创建新类型。`typedef int Meters; Meters m = 5;` 和 `int m = 5;` 在类型检查上完全等价——`Meters` 和 `int` 可互相赋值。想要真正的类型区分（防混用），C 没有直接手段，C++ 才有强类型枚举/类型包装。
</details>

**3. 踩坑**：`typedef char* Str; const Str s = "hi";`，然后 `s[0] = 'H';` 能编译过吗？`s = "bye";` 呢？

<details><summary>答案</summary>
- `s[0] = 'H';` **能**编译——s 指向的是普通 char（非 const char），可修改。
- `s = "bye";` **不能**——`const Str` 等价于 `char* const`，指针本身不可变。

这正是陷阱：直觉以为 `const Str` 是"指向 const char 的指针"（`const char*`），实际是"const 指针指向 char"（`char* const`）。typedef 把 `char*` 当整体，const 修饰整体即指针本身。
</details>

**4. 应用**：为链表节点写 typedef，支持 `Node *p` 而非 `struct Node *p`，且节点能自引用 next。

<details><summary>答案</summary>
```c
typedef struct Node {
    int data;
    struct Node *next;   /* body 内必须用 struct Node，不能用 Node */
} Node;

Node *head = NULL;       /* 有了 typedef，直接 Node* */
```
关键：body 内 typedef 别名 `Node` 尚未生效（typedef 在结尾才完成），必须用 `struct Node`。这是 C 里自引用结构的标准写法。
</details>

## 与后续衔接

Portable 二进制协议优先 `<stdint.h>` 定长类型；typedef 让内核/固件 API 在 32/64 位间平滑切换。
