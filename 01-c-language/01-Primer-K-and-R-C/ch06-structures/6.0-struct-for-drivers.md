## 1. 是什么

**结构体 = 自定义复合类型**：把不同类型成员打成一个整体。

类比「按键」：`gpio` 编号 + 有效电平 + 名字 → 一个 `struct button`，比一堆散变量清晰。

```c
struct button {
	int gpio_num;
	int active_level;   /* 0 低有效，1 高有效 */
	char name[16];
};
```

---

## 2. 定义变量

```c
struct button key1;           /* 先有类型，再定义变量 */

struct button {
	int gpio_num;
} key2;                       /* 定义类型同时定义变量（少见） */
```

内核里常见：`struct platform_device *pdev` — 类型在头文件，变量/指针在函数里。

---

## 3. `.` 与 `->`（驱动天天混）

| 运算符 | 用在谁身上 | 例 |
|--------|------------|-----|
| **`.`** | 结构体**变量**（实体） | `key1.gpio_num = 5;` |
| **`->`** | 结构体**指针** | `pkey->gpio_num = 5;` |

口诀：**实体用点，指针用箭头。**  
`p->m` 等价于 `(*p).m`。

---

## 4. 初始化（驱动超高频）

### 按顺序（老写法）

```c
struct button key1 = { 5, 0, "user_key" };  /* 顺序不能乱，难读 */
```

### 指定成员（读驱动第一眼）

```c
static const struct of_device_id match_table[] = {
	{ .compatible = "broadcom,bcm2835-uart" },
	{ /* sentinel */ }
};
```

- 写作 `.成员 = 值`，顺序可调，可读性高  
- **`platform_driver` / `file_operations` / `of_device_id` 标准姿势**  
- C99 已标准化；内核里仍当「必会」——见 [GNU 6.0](../../04-Kernel-Prep-Embedded-C-Self-Cultivation/ch06-gnu-c-extensions/6.0-driver-how-much-gnu-c.md)、[8.1 DT 绑定](../../../08-embedded-boot-build/primer-system-overview/chapter-08-device-driver-basics/8.1-dts-driver-relationship.md)

## 5. 对齐与 `packed`（寄存器重中之重）

CPU 常为效率在成员间插入 **padding**。  
例：`char` + `int` 可能占 **8** 字节而非 5。

硬件寄存器映射 **不能有空洞** → GNU：

```c
struct reg {
	u8  status;
	u32 data;
} __attribute__((packed));
```

看不懂 `packed` / 对齐 → MMIO 结构体容易读写错位。深挖对齐章 + [packed 小节](../../04-Kernel-Prep-Embedded-C-Self-Cultivation/ch06-gnu-c-extensions/6.7-aligned/6.7.4-属性声明-packed.md)。

---

## 6. 几乎总是传指针

驱动少「传整个结构体拷贝」，多传指针（省拷贝、可改原对象）：

```c
void btn_init(struct button *btn)
{
	btn->gpio_num = 10;
}
```

`probe(struct platform_device *pdev)` 等全是指针参数。

---

## 7. 嵌套与数组

```c
struct device {
	struct bus_type *bus;
	struct resource res;     /* 嵌套值类型 */
};

struct button keys[] = {
	{ .gpio_num = 5, .name = "k1" },
	{ .gpio_num = 6, .name = "k2" },
};
```

匹配表、资源表 = **结构体数组** + 指定初始化。

---

## 8. 和驱动框架的对应

| 你会见到 | 本质 |
|----------|------|
| `struct platform_driver` | 结构体 + `.probe` / `.driver.of_match_table` |
| `struct file_operations` | 函数指针成员的结构体 |
| `of_device_id[]` | 结构体数组 + `.compatible` |
| 寄存器块 | 常 `packed` 结构体 + 指针映射 |

## 9. 自测

```c
struct student {
	char c;
	long num;
};
struct student s;
struct student *p = &s;
/* 访问 c 的两种写法？ */
```

**答：** `s.c`（实体用 `.`）与 `p->c`（指针用 `->`）。也可写 `(*p).c`。

## 代码自测

**题目 1：** 以下结构体设计体现了 Linux 驱动开发中的什么模式？
```c
struct file_operations {
    int (*open)(struct inode *, struct file *);
    ssize_t (*read)(struct file *, char __user *, size_t, loff_t *);
    int (*release)(struct inode *, struct file *);
};
```

<details>
<summary>参考答案</summary>

体现了用函数指针表实现多态（vtable 模式）。struct file_operations 是一张函数指针表，不同驱动提供不同的实现——内核通过同一接口调用不同驱动的函数。这是 C 实现 OOP 多态的标准方式：结构体包含函数指针，不同实现填充不同的函数地址。内核的 file_operations、net_device_ops 等都用这种模式。

</details>
