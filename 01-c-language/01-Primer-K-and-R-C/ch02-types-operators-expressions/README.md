C 的底层核心：类型如何在内存中存储、表达式如何求值、运算符如何组合。**无指针、无复杂项目**，全是数值与位层面的细节，为第 5 章指针打基础。

## 学习重点（Linux / OS / HFT）

- **位运算**、**有符号/无符号转换**、**整型提升** —— 寄存器、驱动、DPDK、内核天天用
- **短路求值**、**优先级** —— 避免隐蔽 bug
- 理解各类型**宽度**与符号性，是读内存布局、ABI 的前提

### Q1: 数据类型与长度

```c
#include <stdio.h>

int main() {
    printf("char   = %zu\n", sizeof(char));
    printf("short  = %zu\n", sizeof(short));
    printf("int    = %zu\n", sizeof(int));
    printf("long   = %zu\n", sizeof(long));
    printf("float  = %zu\n", sizeof(float));
    printf("double = %zu\n", sizeof(double));
    return 0;
}
```

> 在 64 位 Linux 上，这 6 行各输出什么？哪些类型的宽度是"固定不变的"？

<details>
<summary>答案与复习指引</summary>

**典型输出（Linux x86_64, LP64）：**
```
char   = 1
short  = 2
int    = 4
long   = 8
float  = 4
double = 8
```

**解析：** 只有 `char` 恒为 1 字节。`int` 在 16 位机是 2 字节，32/64 位机是 4 字节。`long` 在 LLP64（Windows）= 4，LP64（Linux）= 8。跨平台定宽用 `<stdint.h>` 的 `int32_t` / `int64_t`。

**复习：** → [2.2 数据类型及长度](./2.2-数据类型及长度.md) · [2.2.4 stdint.h](./2.2.4-stdint.h.md)

</details>

### Q2: 整型提升

```c
char a = 0xFF;
char b = 0x01;
printf("%d\n", a);
printf("%d\n", a + b);
printf("%x\n", a + b);
```

> 如果 `char` 是有符号的，这三行各输出什么？

<details>
<summary>答案与复习指引</summary>

**输出：**
```
-1
0
0
```

**解析：** `char` 在多数平台为 `signed char`，`0xFF` = -1。`a + b` 时 `char` 提升为 `int`，`-1 + 1 = 0`。`%x` 打印 0 也是 `0`。整型提升保证运算至少在 `int` 级别进行，避免 `char` 溢出。

**复习：** → [2.7 类型转换](./2.7-类型转换.md) — 整型提升、usual arithmetic conversions

</details>

### Q3: 按位运算

```c
unsigned int flags = 0xF0;  // 1111 0000

// 置第 0 位
flags |= (1u << 0);

// 清第 4 位
flags &= ~(1u << 4);

// 测试第 0 位
if (flags & (1u << 0))
    printf("bit 0 set\n");

printf("flags = 0x%X\n", flags);
```

> 最终 `flags` 是什么值？每行做什么？

<details>
<summary>答案与复习指引</summary>

**输出：**
```
bit 0 set
flags = 0xE1
```

**解析：**
- `0xF0` = `1111 0000`
- 置位 0 → `1111 0001`（`0xF1`）
- 清位 4 → `1110 0001`（`0xE1`）
- 测试位 0 → 非 0，打印 "bit 0 set"

位操作三件套：`|=` 置位、`&= ~` 清位、`&` 测位。内核、驱动、协议解析天天用。

**复习：** → [2.9 按位运算符](./2.9-按位运算符.md)

</details>

### Q4: 运算符优先级陷阱

```c
int a = 5, b = 3, c = 2;
int r = a + b * c;
int s = (a + b) * c;
int t = a << b + c;
int u = (a << b) + c;

printf("r=%d s=%d t=%d u=%d\n", r, s, t, u);
```

> 四个值各是多少？`<<` 和 `+` 谁优先级高？

<details>
<summary>答案与复习指引</summary>

**输出：** `r=11 s=16 t=40 u=42`

**解析：**
- `r = 5 + (3*2) = 11`（`*` 高于 `+`）
- `s = (5+3)*2 = 16`
- `t = 5 << (3+2) = 5 << 5 = 160`... 等等，让我重算

实际上 `+` 优先级**高于** `<<`：
- `t = a << (b + c) = 5 << 5 = 160`
- `u = (5 << 3) + 2 = 40 + 2 = 42`

**教训：** `<<` 优先级低于 `+`，`a << b + c` 意为 `a << (b+c)` 不是 `(a<<b)+c`。移位混算术时**必须加括号**。

**复习：** → [2.13 运算符优先级与结合性](./2.13-运算符优先级与结合性.md)

</details>

### Q5: 有符号与无符号混算

```c
int x = -1;
unsigned int y = 1;

if (x < y)
    printf("x < y\n");
else
    printf("x >= y\n");
```

> 输出什么？为什么？

<details>
<summary>答案与复习指引</summary>

**输出：** `x >= y`

**解析：** 有符号 `int` 与无符号 `int` 混算时，有符号数被隐式转换为无符号。`-1` 的补码 = `0xFFFFFFFF` = 4294967295，大于 1。这是 C 语言最隐蔽的 bug 之一。

**教训：** 混用 signed/unsigned 时务必显式转换。

**复习：** → [2.7 类型转换](./2.7-类型转换.md) — signed/unsigned 混算

</details>

### Q6: 自增与求值顺序

```c
int i = 3;
int a = i++ + i++;
printf("i=%d a=%d\n", i, a);
```

> 输出什么？这段代码有什么问题？

<details>
<summary>答案与复习指引</summary>

**答案：** **未定义行为（UB）**。在同一表达式中多次修改同一变量、且在该表达式中有多个序列点之间的读取，标准未规定求值顺序。

**解析：** 不同编译器可能输出 `i=5 a=6`（左到右：3+4）或 `i=5 a=7`（右到左：4+3）或其他值。`i` 最终为 5（两次自增），但 `a` 的值不确定。

**教训：** 不要在同一表达式中对同一变量做多次 `++`/`--`。

**复习：** → [2.8 自增运算符与自减运算符](./2.8-自增运算符与自减运算符.md) · [2.13 运算符优先级与结合性](./2.13-运算符优先级与结合性.md) — 求值顺序 vs 分组

</details>

### Q7: 条件表达式与逗号

```c
int x = 5;
int y = (x > 3) ? 10 : 20, z = 30;
printf("y=%d z=%d\n", y, z);
```

> `y` 和 `z` 各是多少？逗号在这里起什么作用？

<details>
<summary>答案与复习指引</summary>

**输出：** `y=10 z=30`

**解析：** 这里的逗号是**声明分隔符**（不是逗号运算符）。`int y = (x>3) ? 10 : 20, z = 30;` 声明了两个 `int`：`y=10`（三元表达式结果）和 `z=30`。

**注意：** 逗号运算符 `a, b` 是先求 `a` 丢弃，再求 `b` 作为结果。在声明中的逗号只是分隔多个变量，不是逗号运算符。

**复习：** → [2.11 条件表达式](./2.11-条件表达式.md) · [2.12 逗号运算符](./2.12-逗号运算符.md)
