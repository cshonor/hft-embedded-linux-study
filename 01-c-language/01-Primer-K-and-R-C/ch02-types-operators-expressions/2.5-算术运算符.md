# 2.5 算术运算符

## 本节讲什么

二元算术：`+ - * / %` 及整型、浮点混合时的行为。看似简单，但**整数除法截断方向**、**取模符号**、**溢出**是 C 语言经典坑源。

## 要点

### 五个运算符

| 运算符 | 含义 | 整数行为 | 浮点行为 |
|--------|------|----------|----------|
| `+` | 加 | 溢出 UB（有符号） | IEEE 754 |
| `-` | 减 | 溢出 UB（有符号） | IEEE 754 |
| `*` | 乘 | 溢出 UB（有符号） | IEEE 754 |
| `/` | 除 | **截断小数**（toward zero） | 正常除法 |
| `%` | 取模 | **仅整数**，符号随被除数 | 非法（编译错误） |

### 整数除法截断

C99 起明确规定**向零截断**（truncation toward zero）：

```c
 7 /  2 == 3      /* 截断 0.5 */
-7 /  2 == -3     /* 截断 -0.5，不是 -4 */
 7 / -2 == -3
-7 / -2 == 3
```

C89 之前行为**实现定义**——可能向零截断，也可能向负无穷取整（floor）。K&R 第 2 版基于 ANSI C89，书中提到这一点。现代编译器（GCC/Clang）默认 C99+ 行为。

### 取模符号

C99 规定：`(a/b)*b + a%b == a`，由此推出 **`a%b` 的符号与 `a`（被除数）相同**：

```c
 7 %  3 ==  1
-7 %  3 == -1     /* 符号随被除数 */
 7 % -3 ==  1
-7 % -3 == -1
```

### 浮点除法

至少一侧为浮点即为浮点除法：

```c
9 / 2    == 4       /* 整数除法 */
9 / 2.0  == 4.5     /* 浮点除法 */
9.0 / 2  == 4.5
```

### 溢出行为

| 类型 | 溢出行为 | 例子 |
|------|----------|------|
| 有符号整数 | **未定义行为（UB）** | `INT_MAX + 1` 可能 wrap、可能 trap |
| 无符号整数 | 模 2^n 回绕（well-defined） | `UINT_MAX + 1 == 0` |
| 浮点 | IEEE 754（inf/nan） | `DBL_MAX * 2 == inf` |

HFT/内核里计时、对齐常用 `%` 与 `/` 组合（如 `offset % align`、`ticks / freq`）。

## 常见陷阱

1. **有符号整数溢出是 UB，编译器可能激进优化**：`for (int i = 0; i <= N; i++)` 当 N = INT_MAX 时，`i++` 溢出是 UB，GCC -O2 可能假定循环不会溢出从而生成无限循环。安全写法用 `unsigned` 或加边界检查。`INT_MAX + 1` 在 GCC -O2 下可能得到 `INT_MIN`（wrap），也可能触发 trap（`-ftrapv`），取决于编译选项——UB 意味着编译器可以做任何事。

2. **`a / b * b` 不等于 `a`（整数除法丢精度）**：`7 / 2 * 2 == 6`（不是 7），因为 `7/2` 先截断为 3。浮点类似：`0.1 + 0.2 != 0.3`（IEEE 754 精度问题）。涉及金额计算时用整数（分/厘）或定点数，不用浮点。对齐计算 `addr / align * align` 是安全的（因为能被整除时不丢精度）。

3. **`%` 的符号方向常被搞反**：以为 `-7 % 3 == 2`（正数），实际 C99 规定 `-7 % 3 == -1`（符号随被除数）。Python 的 `%` 结果符号随除数（`-7 % 3 == 2`），和 C 不同。写环形缓冲索引 `(idx - 1) % N` 时，若 `idx = 0` 则 `-1 % N` 在 C 中为 -1（不是 N-1），需要 `(idx + N - 1) % N` 修正。

## 自测题

**1. 选择**：C99 中 `-7 / 2` 的结果是？
- A. -4
- B. -3
- C. -3.5
- D. 实现定义

<details><summary>答案</summary>
B。C99 规定整数除法向零截断（truncation toward zero），`-7 / 2 = -3.5` 截掉小数部分得 -3。C89 之前是**实现定义**（可能 -3 或 -4），现代编译器默认 C99+ 行为。注意：这不是 floor（向下取整），floor(-3.5) = -4。
</details>

**2. 判断**：`unsigned int` 溢出是未定义行为。

<details><summary>答案</summary>
错。**无符号整数**溢出是**良好定义的**——按模 2^n 回绕（C 标准 6.2.5/9）。`UINT_MAX + 1 == 0` 是确定的。只有**有符号整数**溢出才是 UB。因此循环计数器、环形缓冲索引常用 `size_t`（无符号），溢出行为可预测。但注意无符号减法 `0u - 1` 得到 `UINT_MAX`，可能导致意外循环。
</details>

**3. 踩坑**：环形缓冲回绕写 `(idx - 1) % N`，当 `idx = 0` 时结果不是 `N-1`，为什么？

<details><summary>答案</summary>
`idx = 0` 时 `idx - 1 = -1`，`-1 % N` 在 C99 中符号随被除数，结果为 **-1**（不是 N-1）。数组下标 -1 是越界访问。修复：`(idx + N - 1) % N`（先加 N 保证非负），或用无符号 `((unsigned)idx - 1) % N`（无符号取模回绕为 N-1）。这是环形缓冲/哈希表探测的经典坑。
</details>

**4. 应用**：写一个安全的 `div_round_up(a, b)` 向上取整除法，处理正数和负数。

<details><summary>答案</summary>
```c
/* 向上取整：正数用 (a + b - 1) / b，负数直接截断即向上 */
int div_round_up(int a, int b) {
    if (b == 0) return 0;  /* 防除零 */
    if ((a >= 0) == (b > 0))
        return (a + (b > 0 ? b - 1 : b + 1)) / b;
    else
        return a / b;  /* 异号：截断即向上取整 */
}
/* div_round_up(7, 3) == 3, div_round_up(-7, 3) == -2 */
```
常见简化版（仅正数）：`(a + b - 1) / b`。用于计算需要的页数/块数/缓冲数。注意 `a + b - 1` 本身可能溢出。
</details>

**题目 1：** 以下表达式结果是多少？
```c
int x = -7 / 2;   // ?
int y = -7 % 2;   // ?
```

<details>
<summary>参考答案</summary>

C89 中行为实现定义——可能 -3/-1 或 -4/-1。C99 起规定向零截断：`-7 / 2 = -3`（截断小数），`-7 % 2 = -1`（符号与被除数相同）。这是 C89 和 C99 的一个重要区别。

</details>
