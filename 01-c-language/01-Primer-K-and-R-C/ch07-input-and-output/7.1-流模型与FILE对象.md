# 7.1 流模型与 FILE 对象

> 原 K&R 7.5「文件访问」的前半部分，提前到全章开头。stdio 的核心不是某个函数，而是 `FILE` 这个对象。

## 本节讲什么

C 标准 I/O 库（stdio）的**核心抽象**：`FILE` 结构体——它封装了文件描述符、缓冲区、读写位置指针、错误/EOF 标志。所有 stdio 函数（`getchar`、`printf`、`fgets`、`fread`…）都围绕 `FILE*` 展开。理解了 `FILE`，后续每一节都是在操作同一个对象的不同方法。

K&R 原书把这部分放在 7.5（文件访问），但 `FILE*` 是全章基础——`getchar` 底层操作的就是 `stdin`（一个 `FILE*`），`printf` 底层操作的就是 `stdout`（另一个 `FILE*`）。先讲对象，再讲方法，逻辑更清晰。

## FILE 结构体

```c
/* <stdio.h> 中的定义（简化，各实现不同） */
typedef struct _iobuf {
    int   fd;          /* 底层文件描述符 */
    char *buf;         /* 缓冲区指针 */
    char *ptr;         /* 当前读写位置 */
    char *end;         /* 缓冲区末尾 */
    int   mode;        /* 读/写模式 */
    int   flags;       /* EOF 标志、错误标志等 */
} FILE;
```

- `FILE` 是**不透明类型**（opaque type）：标准只要求它能表示流，不暴露内部字段
- 你永远不直接操作 `FILE` 的字段，只通过函数（`fgetc`、`fclose`…）间接操作
- 对应的**指针** `FILE*` 才是你实际使用的句柄

### 三个标准流

程序启动时自动打开三个 `FILE*`：

```c
#include <stdio.h>

FILE *stdin;    /* 标准输入，fd=0 */
FILE *stdout;   /* 标准输出，fd=1 */
FILE *stderr;   /* 标准错误，fd=2，通常无缓冲 */
```

- `getchar()` 等价于 `fgetc(stdin)`
- `putchar(c)` 等价于 `fputc(c, stdout)`
- `printf(...)` 等价于 `fprintf(stdout, ...)`

### 缓冲模式

stdio 在用户态维护缓冲区，减少 `read`/`write` 系统调用次数：

| 模式 | 宏 | 刷新触发条件 | 典型场景 |
|------|-----|-------------|----------|
| 全缓冲 | `_IOFBF` | 缓冲区满 / `fflush` / `fclose` / 正常退出 | 磁盘文件、stdout 重定向到文件/管道 |
| 行缓冲 | `_IOLBF` | 遇 `\n` / 缓冲区满 / `fflush` / 从无缓冲流读输入时 | **终端上的** stdout、stdin |
| 无缓冲 | `_IONBF` | 每个字符立即 `write` | stderr |

#### 默认分配规则（isatty 判断）

glibc 在 `fopen` 时用 `isatty(fd)` 判断流是否连终端，动态决定缓冲模式：

```
fopen 返回 FILE*
  │
  ├─ isatty(fd)==1 (终端)?
  │    ├─ stdout / stdin → _IOLBF (行缓冲)
  │    └─ stderr        → _IONBF (无缓冲)
  │
  └─ isatty(fd)==0 (文件/管道)?
       └─ → _IOFBF (全缓冲)
```

| 流 | 连终端 | 重定向到文件/管道 |
|----|--------|-------------------|
| stdin | 行缓冲 | 全缓冲 |
| stdout | 行缓冲 | **全缓冲**（最常踩坑） |
| stderr | 无缓冲 | 无缓冲 |

> **关键陷阱**：`./a.out > log.txt` 后 stdout 从行缓冲变成全缓冲，`\n` 也不再触发刷新。日志"卡住"不是因为程序没输出，而是数据还在用户态缓冲区里。

#### setvbuf — 手动设置缓冲模式

```c
#include <stdio.h>

int setvbuf(FILE *stream, char *buf, int mode, size_t size);
void setbuf(FILE *stream, char *buf);   /* setvbuf 简化版 */
```

- `setbuf(fp, buf)` ≡ `setvbuf(fp, buf, buf ? _IOFBF : _IONBF, BUFSIZ)`
- `setbuf(fp, NULL)` ≡ `setvbuf(fp, NULL, _IONBF, 0)`（关闭缓冲）
- `setvbuf(stdout, NULL, _IOLBF, 0)` — 强制 stdout 行缓冲（即使重定向）
- `fflush(stdout)` — 主动刷新

**调用规则**：
1. 必须在 `fopen` 后、任何 `fread`/`fwrite`/`fprintf` **之前**调用，否则 UB
2. `buf` 为 `NULL` 时库会自己分配缓冲区
3. `buf` 非 NULL 时，其生命周期必须覆盖 `fp` 的整个使用期，否则 UB
4. `fflush` 只对**输出流**有意义；`fflush(stdin)` 是未定义行为
5. 程序正常退出时 `exit` / `return` from `main` 会自动 flush 所有流；`_exit` 不会

### 三层抽象

```
用户空间:
  ┌─────────────────────────────────┐
  │  getchar / printf / fread / …   │  ← C 标准库 (stdio.h)
  │       操作 FILE* (带用户缓冲)    │
  └────────────┬────────────────────┘
               │ fileno(fp) → int fd
               │ fflush() → 刷到内核
               ▼
  ┌─────────────────────────────────┐
  │  read / write / open / close    │  ← Linux 系统调用 (unistd.h)
  │       操作 int fd (无用户缓冲)   │
  └────────────┬────────────────────┘
               │
               ▼
内核空间:    页缓存 (page cache) → 磁盘
```

- `FILE*` 是用户态封装，内核**完全不知道**这块缓冲区存在
- `int fd` 是内核视角，没有用户缓冲
- `fileno(fp)` 从 `FILE*` 取出底层 `fd`，是两层之间的桥梁
- **不要混用** `fwrite(fp)` 和 `write(fd)` 操作同一个文件——两套缓冲各自独立，数据顺序错乱

```c
#include <stdio.h>
#include <unistd.h>

FILE *fp = fopen("data.txt", "w");
int fd = fileno(fp);    /* 从 FILE* 拿到 fd */

/* 以下两种写法不要混用！ */
fprintf(fp, "via stdio");   /* → 用户缓冲区 */
write(fd, "via syscall", 11); /* → 直接进内核页缓存 */
/* 两者数据顺序不可预测 */
```

### fileno() — 从 FILE* 拿到底层 fd

```c
#include <stdio.h>
int fileno(FILE *stream);     /* FILE* → int fd */
FILE *fdopen(int fd, const char *mode);  /* int fd → FILE* (反方向) */
```

- `fileno` 是**向下拆箱**：从 C 标准库的 `FILE*` 取出底层 `int fd`
- `fdopen` 是**向上装箱**：拿一个已有的 `fd` 包装成 `FILE*`（加用户缓冲）

| | `fileno(fp)` | `fdopen(fd, mode)` |
|---|---|---|
| 方向 | `FILE*` → `fd` | `fd` → `FILE*` |
| 缓冲 | 不改变 | **新建**一个用户缓冲区 |
| 所有权 | `fclose(fp)` 会关闭 `fd` | `fclose(fp)` 会关闭 `fd` |
| 典型用途 | 对 stdio 流调系统调用 | 给 `open()` 返回的 fd 加缓冲 |

三个标准流的 fileno：

```c
fileno(stdin)   → 0
fileno(stdout)  → 1
fileno(stderr)  → 2
```

什么时候需要 `fileno`：系统调用只认 `fd`，不认 `FILE*`。

| 场景 | 示例 |
|------|------|
| 强制落盘 | `fsync(fileno(fp))` |
| 设非阻塞 | `fcntl(fileno(fp), F_SETFL, O_NONBLOCK)` |
| 内存映射 | `mmap(NULL, len, PROT_READ, MAP_SHARED, fileno(fp), 0)` |
| 判断终端 | `isatty(fileno(stdout))` |
| 取文件属性 | `fstat(fileno(fp), &sb)` |

**混用陷阱**：`fprintf` 走用户缓冲区，`write(fileno(fp))` 直接进内核，两者各走各的，数据顺序不可预测。混用前必须 `fflush(fp)` 同步。

```c
FILE *fp = fopen("log.txt", "w");
fprintf(fp, "AAA");           /* 还在用户 buf 里 */
fflush(fp);                   /* 刷干净 */
write(fileno(fp), "BBB", 3); /* 现在顺序正确 */
```

> 详见 TLPI 13.2–13.3（stdio 缓冲与混用陷阱）。

## fopen / fclose

### 打开文件

```c
FILE *fp = fopen("data.txt", "r");
if (fp == NULL) {
    perror("fopen");    /* 打印错误原因 */
    exit(1);
}
```

### 打开模式

| 模式 | 读 | 写 | 位置 | 文件不存在时 |
|------|----|----|------|-------------|
| `r` | ✅ | ❌ | 开头 | 失败 |
| `w` | ❌ | ✅ | 开头 | 创建（清空已有） |
| `a` | ❌ | ✅ | 末尾 | 创建 |
| `r+` | ✅ | ✅ | 开头 | 失败 |
| `w+` | ✅ | ✅ | 开头 | 创建（清空已有） |
| `a+` | ✅ | ✅ | 末尾 | 创建 |

- 加 **`b`**（如 `rb`、`wb`）= 二进制模式：避免 Windows 文本模式下 `\r\n` ↔ `\n` 转换
- Linux 不区分文本/二进制模式（`"r"` 和 `"rb"` 相同），但跨平台代码应始终加 `b`
- 失败返回 `NULL`，**必须检查**

### 关闭文件

```c
fclose(fp);    /* 刷新缓冲、释放资源、关闭 fd */
```

- 每个 `FILE*` 占用一个 fd 和内部缓冲；忘记 `fclose` 会泄漏资源
- 长期运行的服务进程泄漏 fd 最终触发 `EMFILE`（too many open files）
- 多处 `return` 的函数用 `goto cleanup` 模式确保关闭

## 常见陷阱

1. **fopen 返回值未检查直接使用**：`FILE *fp = fopen("x.txt", "r"); fgets(buf, 100, fp);` ——若文件不存在，fp 是 NULL，fgets 对 NULL 解引用即段错误。**每次 fopen 必须检查 NULL**，出错用 `perror` 或 `strerror(errno)` 打印原因。

2. **忘记 fclose 导致资源泄漏**：函数中多处 `return` 但只在末尾 `fclose`，提前 return 的路径泄漏。用 `goto cleanup` 模式或 GCC `__attribute__((cleanup))`。长期运行的服务进程泄漏 fd 最终触发 `EMFILE`。

3. **stdout 缓冲导致输出丢失**：stdout 在终端是行缓冲，重定向到文件后变全缓冲。程序崩溃时缓冲区未 flush，末尾输出丢失。调试时在关键点 `fflush(stdout)` 或用 `stderr`（无缓冲）输出调试信息。

4. **`"r"` 读二进制文件在 Windows 上提前 EOF**：Windows 文本模式把 `0x1A`（Ctrl-Z）当作 EOF，还会做 `\r\n` → `\n` 转换。读二进制文件必须用 `"rb"`。

## 自测题

**1. 选择**：`getchar()` 底层操作的是哪个 `FILE*`？
- A. `stderr`
- B. `stdin`
- C. `stdout`
- D. 没有关联的 `FILE*`

<details><summary>答案</summary>
B。`getchar()` 等价于 `fgetc(stdin)`，`putchar(c)` 等价于 `fputc(c, stdout)`。printf 等价于 fprintf(stdout, ...)。理解了标准流，就明白前面几节的函数都在操作 `FILE*`——只是隐式使用了 stdin/stdout。
</details>

**2. 判断**：`FILE` 结构体的内部字段（如 `fd`、`buf`）可以直接访问。

<details><summary>答案</summary>
错。`FILE` 是不透明类型，标准不暴露内部字段。不同实现的字段名和布局不同（glibc 的 `FILE` 和 musl 的完全不同）。你只能通过函数（`fgetc`、`fclose`、`feof`…）间接操作。直接访问 `fp->fd` 是不可移植的，且可能在未来版本中编译失败。
</details>

**3. 踩坑**：程序输出到终端正常，`prog > log.txt` 后末尾几行丢失，为什么？

<details><summary>答案</summary>
stdout 在终端是**行缓冲**（遇 `\n` 自动 flush），重定向到文件后变**全缓冲**（缓冲区满才 flush）。程序正常退出时 `exit` 会 flush，但若**异常崩溃**（如 SIGSEGV、`_exit`）缓冲区未 flush，末尾输出丢失。修复：关键日志后 `fflush(stdout)`，或用 `stderr`（无缓冲）输出调试信息。
</details>

**4. 应用**：写一个安全的 `open_file` 函数——封装 fopen + 错误检查，失败时打印错误信息并返回 NULL。

<details><summary>答案</summary>
```c
FILE *open_file(const char *path, const char *mode) {
    FILE *fp = fopen(path, mode);
    if (fp == NULL) {
        fprintf(stderr, "cannot open '%s': %s\n",
                path, strerror(errno));
        return NULL;
    }
    return fp;
}
/* 调用：
 * FILE *fp = open_file("config.txt", "r");
 * if (fp == NULL) exit(1);
 * ... 使用 fp ...
 * fclose(fp);
 */
```
关键：fopen 检查 NULL、strerror(errno) 翻译错误码、错误信息输出到 stderr。这是文件操作的第一原则。
</details>
