# 7.7 错误处理

## 本节讲什么

**`stderr`** 标准错误流与 **`stdout`** 分离；**`exit`** 终止进程；**`ferror`/`clearerr`** 管理流错误。日志分级与调试输出的基础。

## 要点

### stderr

```c
fprintf(stderr, "fatal: cannot open %s\n", path);
```

- 通常**无缓冲**或行缓冲，错误信息及时可见
- 可重定向：`prog 2> err.log`（stdout 仍走 1）
- 正常结果走 stdout，诊断走 stderr —— `grep`、管道不误吞错误

### exit

```c
#include <stdlib.h>
exit(0);    /* 成功 */
exit(1);    /* 失败，返回给 shell */
```

- 调用 **`atexit`** 注册的函数，刷新 stdio 缓冲
- 与 **`return`** from `main` 等价于 `exit(返回值)`

### 流错误

- 读写出错后 **`ferror(fp)`** 为真
- **`clearerr(fp)`** 清除错误与 EOF 标志以便重试
- 不要仅用 **`getchar() == EOF`** 判断错误类型

## 底层场景

| 场景 | 做法 |
|------|------|
| UEFI 固件调试 | 错误码 + 串口/屏幕 Print |
| HFT | 分级日志：trade → 文件，error → stderr |
| 工具链 | 编译器 diagnostic 走 stderr |

## 与后续衔接

第 8 章 **`perror`** 把 `errno` 转成字符串；系统调用失败常 `perror("read")` 写 stderr。

## 常见陷阱

1. **exit vs _exit 的区别被忽略**：`exit` 刷新 stdio 缓冲、调用 `atexit` 注册的函数。`_exit`（POSIX）直接陷入内核，**不刷新缓冲**。fork 后子进程若用 `exit`，父进程的 stdio 缓冲被复制后再次刷新——同一输出写两遍。子进程应用 `_exit`（或 `exec` 后自然替换）。vfork 后尤其要注意。

2. **stderr 缓冲策略假设**：标准说 stderr **默认不缓冲**（unbuffered），但某些实现是行缓冲。如果你的错误信息没有 `\n` 结尾，行缓冲的实现可能延迟输出。关键路径上用 `fflush(stderr)` 确保立即输出，或写到底层 `write(2, msg, len)` 绕过 stdio。

3. **errno 不是清零的——只在出错后查**：`errno` 只在库函数**返回错误**时被设置，成功调用**不会清零**。模式 `errno = 0; x = strtoul(s, NULL, 0); if (errno != 0) error();` 是正确用法。`if (errno) error();` 不行——之前的调用可能设了 errno 而本次成功。perror/ferror 也同理：先确认操作失败再查 errno。

## 自测题

**1. 选择**：`exit(1)` 和 `_exit(1)` 的关键区别是？
- A. 没有区别
- B. exit 刷新 stdio 缓冲并调用 atexit，_exit 不做
- C. _exit 刷新缓冲，exit 不做
- D. exit 给父进程发信号，_exit 不发

<details><summary>答案</summary>
B。`exit` 是 C 标准库函数：调用 `atexit` 注册的清理函数、刷新所有 stdio 缓冲、关闭 stdio 流，然后调用 `_exit`。`_exit` 是 POSIX 系统调用：直接陷入内核，**不刷新任何用户态缓冲**。fork 后子进程用 `exit` 会导致父进程 stdio 缓冲被复制后重复刷新——同一输出写两遍。子进程应用 `_exit` 或直接 `exec`。
</details>

**2. 判断**：`errno` 在成功的函数调用后会被自动清零。

<details><summary>答案</summary>
错。C 标准规定 `errno` 只在**出错时被设置**，成功调用**不会清零**。因此 `if (errno) ...` 在之前有错误发生时会误判。正确用法：调用前手动 `errno = 0;`，调用后检查返回值是否出错，出错时再查 errno。只有 `strtol`/`strtoul` 等少数函数要求这样做（因为它们返回的合法值可能与错误返回值重叠）。
</details>

**3. 踩坑**：程序崩溃（SIGSEGV）后，最后几行 `fprintf(stderr, ...)` 的输出丢失了，为什么？

<details><summary>答案</summary>
即使 stderr 默认无缓冲，某些实现仍是行缓冲。如果最后的 fprintf 没有 `\n` 结尾，行缓冲的输出未 flush 就被信号杀死。更严重的是：如果错误信息写到了 stdout（被重定向到文件，全缓冲），崩溃时缓冲区未 flush，末尾输出丢失。修复：1) 调试信息用 `fprintf(stderr, ...)` 加 `\n`；2) 关键路径 `fflush(stdout)`；3) 信号处理函数中只能调用异步信号安全函数（`write` 可以，`printf` 不行）。
</details>

**4. 应用**：写一个 `die(const char *fmt, ...)` 函数——输出到 stderr 并 `exit(1)`，要求带格式化输出和 errno 翻译。

<details><summary>答案</summary>
```c
#include <stdarg.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <errno.h>

void die(const char *fmt, ...) {
    va_list ap;
    va_start(ap, fmt);
    fprintf(stderr, "fatal: ");
    vfprintf(stderr, fmt, ap);
    va_end(ap);
    if (errno)
        fprintf(stderr, ": %s", strerror(errno));
    fprintf(stderr, "\n");
    exit(1);
}
/* 调用：die("cannot open %s", path); */
/* 输出：fatal: cannot open config.txt: No such file or directory */
```
关键：vfprintf 封装变参、strerror(errno) 翻译错误码、最后 exit(1)。很多 CLI 工具（如 git 源码）都有类似的 die/usage 函数。
</details>
