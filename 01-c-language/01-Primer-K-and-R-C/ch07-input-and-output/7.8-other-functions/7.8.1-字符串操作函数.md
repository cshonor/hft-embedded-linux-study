# 7.8.1 字符串操作函数

## 本节讲什么

**`<string.h>`** 中 C 字符串核心 API：长度、拷贝、比较、连接。第 5 章用指针实现，此处为标准库封装。

## 要点

| 函数 | 作用 |
|------|------|
| `strlen(s)` | 长度（不含 `'\0'`） |
| `strcpy(dst, src)` | 拷贝（**不检查 dst 大小**） |
| `strncpy(dst, src, n)` | 最多 n 字节，可能不补 `'\0'` |
| `strcat(dst, src)` | 连接 |
| `strcmp(s1, s2)` | 比较，返回 `<0` `0` `>0` |
| `strncmp` | 限长比较 |
| `strchr` / `strstr` | 查找字符/子串 |

## 安全习惯

- 优先 **`strncpy` + 手动 `'\0'`** 或 **`snprintf`**
- 内核常用 **`strlcpy`/`strscpy`**（非 K&R 标准 C）

## 与后续衔接

报文定长字段、符号表 `name` 比较都依赖这些原语；二进制数据用 `memcpy`（`<string.h>`）。

## 常见陷阱

### 1. `strncpy` 不保证 `\0` 终止

```c
char buf[5];
strncpy(buf, "hello world", 5);  // buf = {'h','e','l','l','o'} — 没有 '\0'！
printf("%s", buf);  // 越界读，直到碰巧遇到 '\0'
```

`strncpy` 拷贝正好 n 字节，如果 src 前 n 字节没有 `\0`，dst 就不会以 `\0` 结尾。必须手动补：

```c
strncpy(buf, src, sizeof(buf) - 1);
buf[sizeof(buf) - 1] = '\0';
```

### 2. `strcat` 不检查目标缓冲区大小

```c
char buf[10] = "abc";
strcat(buf, "defghijklmnop");  // 写越界 — buf 只有 7 字节剩余空间
```

`strcat` 从 dst 的 `\0` 处开始追加，但不知道 dst 有多大。安全替代：`strncat`（限长）或 `snprintf`（自动截断）。

### 3. `strcmp` 返回值不是 -1/0/1

```c
if (strcmp(s1, s2) == -1)   // ❌ 错！可能返回任意负数
    /* ... */;
```

`strcmp` 返回「小于零」「等于零」「大于零」三种关系，具体值实现定义（可能返回差值如 -50 或 200）。正确写法：

```c
if (strcmp(s1, s2) < 0)   // ✓
if (strcmp(s1, s2) == 0)  // ✓ 相等
```

### 4. `memcpy` vs `memmove` — 重叠区域

```c
char s[] = "abcdef";
memcpy(s + 2, s, 4);   // 行为未定义！源和目标重叠
memmove(s + 2, s, 4);  // ✓ 安全 — memmove 内部处理重叠
```

`memcpy` 不处理重叠，`memmove` 会根据方向选择正向/反向拷贝。内存重叠时必须用 `memmove`。

## 代码自测

**题目 1：** 以下代码有什么缓冲区溢出风险？
```c
char dst[10];
char src[] = "Hello, World! This is a long string";
strcpy(dst, src);  // 安全吗？
```

<details>
<summary>参考答案</summary>

不安全——`strcpy` 不检查目标缓冲区大小，src 超过 10 字节会导致缓冲区溢出。用 `strncpy` 或 `snprintf`：
```c
strncpy(dst, src, sizeof(dst) - 1);
dst[sizeof(dst) - 1] = '\0';  // strncpy 不保证终止
// 或更安全
snprintf(dst, sizeof(dst), "%s", src);
```
`strncpy` 不自动添加 `\0`——这是另一个陷阱。

</details>

**题目 2：** 以下代码输出什么？为什么？
```c
char buf[5] = {0};
strncpy(buf, "hello", 5);
printf("%zu\n", strlen(buf));  // 输出？
```

<details>
<summary>参考答案</summary>

输出不确定（UB）。`strncpy(buf, "hello", 5)` 正好拷贝 5 字节 `'h','e','l','l','o'`，没有 `\0` 终止符。`strlen` 会越界读直到遇到 `\0`。虽然 buf 初始化为 `{0}`（全部清零），但 strncpy 正好覆盖了全部 5 字节，`\0` 被覆盖。如果 buf 后面的内存恰好是 0，strlen 可能返回 5；否则越界读取。修正：`strncpy(buf, "hello", 4)` 留一个字节给 `\0`，或手动 `buf[4] = '\0'`。

</details>

**题目 3：** `memcpy` 和 `memmove` 有什么区别？什么时候必须用 `memmove`？
```c
char s[] = "abcdef";
// memcpy(s + 2, s, 4);    // ?
// memmove(s + 2, s, 4);   // ?
```

<details>
<summary>参考答案</summary>

`memcpy` 假设源和目标不重叠，重叠时行为未定义。`memmove` 内部检测重叠并选择拷贝方向（正向或反向），保证正确。上例中 `s+2` 和 `s` 有 4 字节重叠（`cdef`），必须用 `memmove`。`memcpy` 可能先拷 `'a'` 到 `s[2]`，再拷 `s[2]`（已是 `'a'`）到 `s[4]`——数据被污染。经验法则：只要 src 和 dst 可能有任何重叠，就用 `memmove`。

</details>

**题目 4：** `strcmp("abc", "abd")` 的返回值是什么？为什么不能写 `== -1`？

<details>
<summary>参考答案</summary>

返回一个**负整数**（具体值实现定义，可能是 -1 也可能是 `'c' - 'd'` = -1 或其他负数）。标准只保证三种关系：`<0`（s1 < s2）、`0`（相等）、`>0`（s1 > s2）。写 `== -1` 是错的——某些实现返回差值如 -50 或 -1，不保证恰好是 -1。正确写法：`strcmp(s1, s2) < 0`。

</details>
