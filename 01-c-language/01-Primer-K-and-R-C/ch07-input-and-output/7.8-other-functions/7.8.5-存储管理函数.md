# 7.8.5 存储管理函数

## 本节讲什么

**`malloc` `calloc` `realloc` `free`** —— **堆区**分配（[4.3.1 内存布局](../../ch04-functions-and-program-structure/4.3.1-程序内存布局.md)），6.5 链表、6.6 符号表、动态缓冲的基础。第 8 章从系统角度讲堆与 `sbrk`。

## 要点

```c
void *malloc(size_t n);           /* 未初始化 */
void *calloc(size_t n, size_t sz); /* 清零 */
void *realloc(void *p, size_t n);  /* 调整大小，可能搬迁 */
void free(void *p);
```

- 失败返回 **`NULL`**，必须检查
- **`free(NULL)`** 合法无操作
- **禁止**：`free` 非堆指针、double-free、use-after-free
- 分配大小 **`n * sz`** 注意溢出

## 底层取舍

| 场景 | 策略 |
|------|------|
| HFT 热路径 | 预分配对象池，避免 malloc |
| 内核 | `kmalloc`/`kfree`，非 stdlib |
| UEFI | `AllocatePool`/`FreePool` |
| 工具/解析器 | malloc 可接受 |

## 与后续衔接

`fread` 读变长记录前常 `malloc` 缓冲；第 8 章 `brk`/`sbrk` 揭示堆与内核边界。

## 常见陷阱

### 1. `realloc` 后旧指针失效

```c
int *p = malloc(10 * sizeof(int));
int *q = realloc(p, 100 * sizeof(int));
// p 可能已失效！如果 realloc 搬迁了内存
p[0] = 42;   // ❌ 可能段错误
```

`realloc` 可能返回新地址（原空间不够，分配新块 + 拷贝 + 释放旧块）。搬迁后旧指针 `p` 指向已释放的内存。正确用法：

```c
int *tmp = realloc(p, 100 * sizeof(int));
if (tmp) {
    p = tmp;   // 只在成功时更新 p
} else {
    // realloc 失败，p 仍指向原来的有效内存
    free(p);   // 按需处理
}
```

### 2. `calloc(n, size)` 的隐式溢出保护

```c
int *p = malloc(n * sizeof(int));      // n * sizeof(int) 可能溢出！
int *q = calloc(n, sizeof(int));       // ✓ calloc 内部检查乘法溢出
```

`malloc(n * sizeof(int))` 中如果 `n` 来自用户输入且很大，`n * sizeof(int)` 可能整数溢出回绕为一个小值，`malloc` 分配小块，后续写入越界。`calloc(n, size)` 内部检查 `n * size` 是否溢出，溢出时返回 `NULL`。安全分配模式：

```c
if (n > SIZE_MAX / sizeof(int)) {  /* 溢出检查 */
    return NULL;
}
int *p = malloc(n * sizeof(int));
```

或直接用 `calloc`。

### 3. `free` 后不置空 — 悬垂指针

```c
free(p);
// p 仍然保存原来的地址值 — 悬垂指针
if (p != NULL)      // 通过检查！
    p[0] = 42;       // ❌ use-after-free
```

`free` 不会把指针设为 `NULL`——它只释放内存，不动指针变量。释放后立即置空：

```c
free(p);
p = NULL;           // 防止后续误用
```

### 4. `realloc(p, 0)` 的行为不一致

```c
realloc(p, 0);  // C99: 释放 p，返回 NULL 或实现定义
                // C11: 行为实现定义，可能 UB
```

`realloc(p, 0)` 在 C99 中等价于 `free(p)`（但返回值不确定），C11 中行为是实现定义。不要依赖这个——显式用 `free(p)` 释放。

## 代码自测

**题目 1：** 以下代码有什么问题？
```c
int* p = malloc(sizeof(int) * 10);
// ... 使用 p ...
free(p);
p[0] = 42;  // 合法吗？
```

<details>
<summary>参考答案</summary>

use-after-free——`free(p)` 后 p 指向的内存已释放，再访问是未定义行为。释放后应立即置空：`free(p); p = NULL;`。其他常见内存错误：1) 忘记 free（内存泄漏）；2) double free（释放两次）；3) free 非 malloc 返回的指针；4) realloc 后仍用旧指针。用 valgrind/AddressSanitizer 检测内存错误。

</details>

**题目 2：** 以下代码有什么 bug？
```c
int *p = malloc(n * sizeof(int));
// ... 填充 p ...
p = realloc(p, n * 2 * sizeof(int));
if (p == NULL) {
    perror("realloc");
    return -1;
}
```

<details>
<summary>参考答案</summary>

如果 `realloc` 失败返回 `NULL`，原指针 `p` 被覆盖为 `NULL`——原来的内存**泄漏**了（无法再 `free`）。正确写法用临时变量：
```c
int *tmp = realloc(p, n * 2 * sizeof(int));
if (tmp == NULL) {
    free(p);   // 原内存仍有效，可以释放
    perror("realloc");
    return -1;
}
p = tmp;       // 成功才更新
```
`realloc` 失败时原内存不被释放——这是标准保证的，但前提是你没有用 `NULL` 覆盖原指针。

</details>

**题目 3：** `malloc(n * sizeof(int))` 和 `calloc(n, sizeof(int))` 有什么区别？哪个更安全？

<details>
<summary>参考答案</summary>

三个区别：1) `malloc` 不清零（内容是垃圾），`calloc` 清零（全 0）；2) `calloc(n, size)` 内部检查 `n * size` 乘法溢出，溢出时返回 `NULL`，而 `malloc(n * size)` 的乘法在调用者侧完成，可能溢出；3) 性能：`calloc` 通常延迟清零（内核的 CoW zero page），实际首次写入时才触发缺页清零，可能更快。安全角度 `calloc` 更好——防溢出 + 初始化。

</details>

**题目 4：** 以下代码会导致什么问题？如何修复？
```c
char *p = malloc(100);
char *q = p;
free(p);
free(q);  // 会怎样？
```

<details>
<summary>参考答案</summary>

double free——`p` 和 `q` 指向同一块内存。`free(p)` 释放后，`free(q)` 再次释放同一块，是未定义行为。glibc 的 ptmalloc 可能检测到并 abort（"double free or corruption"），但标准不保证检测。某些攻击利用 double free 破坏堆元数据实现代码执行。修复：释放后置空，且只用一个指针管理生命周期：
```c
char *p = malloc(100);
// ... 使用 p ...
free(p);
p = NULL;     // 防止 q 侧误用
// q 也要管理——最佳实践是只有一个"所有者"负责 free
```

</details>
