# 7.8.3 ungetc 函数

## 本节讲什么

**`ungetc(c, fp)`** 把字符 **`c`** **推回**输入流，下次读会先读到它。实现「读多看一、再退回」的 parser 必备。

## 要点

- 每个流通常只允许**少量**推回（常 1 个，实现定义）
- 成功返回 `c`；失败返回 `EOF`
- 与 **`fgetc`** 配合：试探下一字符，若非预期则 `ungetc`

## 示例

```c
int c = fgetc(fp);
if (c == '/')
    c = fgetc(fp);
else {
    ungetc(c, fp);
    /* 按其它规则处理 */
}
```

## 与后续衔接

递归下降解析、mini-shell、配置文件 tokenizer；网络协议「预读 opcode 再分支」同类逻辑。

## 常见陷阱

### 1. 只保证推回一个字符

```c
ungetc('a', fp);
ungetc('b', fp);  // 不保证成功！
```

标准只保证**至少**能推回一个字符。推回多个的行为是实现定义的——某些实现用单字符缓冲区，第二个 `ungetc` 会覆盖第一个或失败。如果需要 lookahead 多个字符，自己维护回退缓冲区：

```c
#define PUSHBACK_SIZE 4
char pushback[PUSHBACK_SIZE];
int pushback_cnt = 0;

int my_getc(FILE *fp) {
    if (pushback_cnt > 0)
        return pushback[--pushback_cnt];
    return fgetc(fp);
}

void my_ungetc(int c, FILE *fp) {
    if (pushback_cnt < PUSHBACK_SIZE)
        pushback[pushback_cnt++] = c;
}
```

### 2. 推回的字符不一定是之前读到的

```c
int c = fgetc(fp);    // 读到 'x'
ungetc('z', fp);      // 推回 'z'（不是 'x'！）
c = fgetc(fp);        // 读到 'z'
```

`ungetc` 允许推回**任意字符**，不必是刚才读到的。这在 parser 中很有用——可以插入「虚拟字符」改变后续解析路径。但也容易误用：如果无意中推回了错误字符，调试困难。

### 3. `fseek`/`rewind`/`fsetpos` 会丢弃推回的字符

```c
ungetc('a', fp);
fseek(fp, 0, SEEK_SET);  // 丢弃推回的 'a'！
c = fgetc(fp);            // 读到文件开头，不是 'a'
```

任何改变文件位置的操作（`fseek`、`rewind`、`fsetpos`）都会清除 `ungetc` 的推回缓冲区。如果先 `ungetc` 再 `fseek`，推回的字符就丢了。

### 4. `ungetc` 影响 `ftell` 的返回值

```c
long pos = ftell(fp);     // 假设 100
ungetc('x', fp);
long pos2 = ftell(fp);    // 返回 99 — 推回的字符让位置"后退"
```

`ftell` 在 `ungetc` 后返回的值会减一（反映推回的字符）。这在需要精确文件位置时可能造成困惑。

## 代码自测

**题目 1：** `ungetc` 的用途是什么？有什么限制？
```c
int c = getchar();
ungetc(c, stdin);  // 把字符退回输入流
```

<details>
<summary>参考答案</summary>

`ungetc` 将一个字符退回输入流，下次 `getchar` 会再读到它。用途：读取时需要「向前看一个字符」——读到非目标字符后退回，让上层处理。限制：1) 只保证能退回一个字符（实现可能支持更多）；2) 退回的字符不一定是之前读到的字符；3) 如果在两个不同的读取位置之间调用 ungetc，行为可能不一致。

</details>

**题目 2：** 以下代码连续推回两个字符，可靠吗？
```c
ungetc('a', stdin);
ungetc('b', stdin);  // 先读到 'b' 还是 'a'？
```

<details>
<summary>参考答案</summary>

不可靠。标准只保证至少能推回一个字符。如果实现支持多个，它们以 LIFO（后进先出）顺序返回——先读到 `'b'`，再读到 `'a'`。但某些实现可能只保留最后一个推回的字符，`'a'` 被丢弃。如果需要多字符 lookahead，应自己维护回退缓冲区而非依赖多次 `ungetc`。

</details>

**题目 3：** 以下代码的 `ftell` 返回值是多少？
```c
fseek(fp, 100, SEEK_SET);
fgetc(fp);
ungetc('x', fp);
long pos = ftell(fp);  // 返回？
```

<details>
<summary>参考答案</summary>

返回 100。`fgetc` 前进到 101，`ungetc` 后退到 100。`ftell` 会考虑 `ungetc` 推回的字符，返回逻辑位置（100）而非物理位置。但如果在 `fseek` 之后调用 `ungetc`，行为是实现定义的——某些实现会丢弃推回的字符。

</details>

**题目 4：** 设计一个「读两个字符判断是否是 `//` 注释」的函数，如果不是就退回。如何用 `ungetc` 实现？

<details>
<summary>参考答案</summary>

```c
int is_comment(FILE *fp) {
    int c1 = fgetc(fp);
    if (c1 != '/') {
        if (c1 != EOF) ungetc(c1, fp);
        return 0;
    }
    int c2 = fgetc(fp);
    if (c2 != '/') {
        if (c2 != EOF) ungetc(c2, fp);
        ungetc(c1, fp);   // 退回第一个 '/' 也要退回！
        return 0;
    }
    return 1;  // 确认是 //
}
```
关键：不是注释时要退回**所有**读到的字符（逆序退回），让上层重新解析。注意检查 EOF——`ungetc(EOF, fp)` 行为未定义。

</details>
