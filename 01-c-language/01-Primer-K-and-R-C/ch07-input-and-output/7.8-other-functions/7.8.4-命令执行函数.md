# 7.8.4 命令执行函数

## 本节讲什么

**`system(const char *cmd)`** 调用 shell 执行命令，等待结束并返回状态。简单脚本集成用，**安全与可移植性有限**。

## 要点

```c
int status = system("ls -l");
```

- 依赖 **`/bin/sh`**（或平台 shell）
- 返回值编码实现相关；需用宏 **`WEXITSTATUS`** 等（`<sys/wait.h>`，第 8 章）解析
- **安全风险**：若 `cmd` 含用户输入 → 命令注入
- 嵌入式/内核/UEFI **无 system**；HFT 生产环境通常禁用
- `system` 内部执行 `fork` + `exec` + `wait`，是阻塞调用——等子进程结束才返回

### 返回值解析

```c
int status = system("ls -l");
if (status == -1) {
    /* fork 失败或 shell 不可用 */
} else if (WIFEXITED(status)) {
    int code = WEXITSTATUS(status);  /* 子进程的 exit code */
    if (code != 0)
        fprintf(stderr, "command failed: %d\n", code);
} else if (WIFSIGNALED(status)) {
    int sig = WTERMSIG(status);  /* 被信号杀死 */
    fprintf(stderr, "killed by signal: %d\n", sig);
}
```

`system` 返回的不是直接 exit code——是 `wait` 返回的状态码，需要 `WIFEXITED`/`WEXITSTATUS` 解码。直接 `if (status == 0)` 在大多数情况下碰巧能工作（exit 0 时 status 也为 0），但不可靠。

## 常见陷阱

### 1. 命令注入 — 拼接用户输入

```c
char cmd[256];
snprintf(cmd, sizeof(cmd), "cat %s", user_input);
system(cmd);   // user_input = "; rm -rf /" → 灾难
```

`system` 通过 shell 执行，shell 会解释 `;`、`|`、`$`、`` ` `` 等特殊字符。任何来自用户的输入拼入 cmd 都是安全漏洞。安全替代：用 `execvp` 直接执行（不经 shell），或严格转义特殊字符。

### 2. 忽略 `system` 的返回值

```c
system("make install");  // 返回值被丢弃
/* 假装成功了 */
```

`system` 可能失败：shell 不存在（`-1`）、命令不存在（exit 127）、命令执行失败（非零 exit code）。不检查返回值就继续，会导致后续逻辑基于错误假设运行。始终检查返回值。

### 3. 阻塞调用 — 在实时/服务器中误用

```c
system("sleep 60");  // 阻塞 60 秒，整个进程卡住
```

`system` 是阻塞的——它会 `wait` 子进程结束。在服务器主线程、HFT 热路径、GUI 主线程中调用会导致整个程序卡死。需要异步执行命令时应自行 `fork` + `exec`，或用 `popen` + 非阻塞读。

### 4. 环境变量劫持

```c
system("myapp");  // 依赖 PATH — 攻击者可篡改 PATH
```

`system` 继承当前进程的环境变量，包括 `PATH`。如果攻击者能修改 `PATH`，可以让 `system("myapp")` 执行恶意程序。高安全场景应指定完整路径：`system("/usr/bin/myapp")`，或用 `execv` 显式传环境变量。

## 代码自测

**题目 1：** `system("ls -l")` 有什么安全风险？
```c
char* cmd = getenv("USER_CMD");
system(cmd);  // 安全吗？
```

<details>
<summary>参考答案</summary>

命令注入风险——如果 `cmd` 来自用户输入，可能包含 `; rm -rf /` 等恶意命令。`system` 通过 shell 执行，shell 会解释特殊字符。安全做法：1) 不用 `system`，用 `execvp` 直接执行（不经 shell）；2) 如果必须用 `system`，严格过滤输入中的 shell 特殊字符。这是 C 语言安全编程的基本原则。

</details>

**题目 2：** 以下代码如何正确检查命令是否成功？
```c
int status = system("grep error /var/log/app.log");
if (status == 0) {
    printf("found errors\n");
}
```

<details>
<summary>参考答案</summary>

不完整。`status` 是 `wait` 返回的原始状态码，不是 exit code。如果 `grep` 找不到匹配（exit 1），`status` 不是 1 而是 `0x100`（exit code 左移 8 位）。正确写法：
```c
if (WIFEXITED(status) && WEXITSTATUS(status) == 0)
    printf("found errors\n");
else if (WIFEXITED(status) && WEXITSTATUS(status) == 1)
    printf("no errors found\n");
else
    perror("system failed");
```
还要检查 `WIFSIGNALED`（被信号杀死）和 `status == -1`（fork 失败）。

</details>

**题目 3：** 为什么 HFT 或服务器中不应该用 `system`？

<details>
<summary>参考答案</summary>

三个原因：1) **阻塞**——`system` 内部 `fork`+`exec`+`wait`，等子进程结束才返回，期间整个进程卡住；2) **fork 开销**——`fork` 需要复制页表、文件描述符表，即使 COW 也有微秒级延迟；3) **shell 依赖**——`system` 依赖 `/bin/sh`，嵌入式环境可能没有。替代方案：用 `posix_spawn` 或 `vfork`+`exec` 减少开销，或用 `popen` 异步读取输出。

</details>

**题目 4：** 如何安全地执行一个带参数的外部命令，不经过 shell？

<details>
<summary>参考答案</summary>

用 `execvp`（或 `execv`），直接调用内核 `execve` 系统调用，不经 shell，不会解释特殊字符：
```c
pid_t pid = fork();
if (pid == 0) {
    /* 子进程 */
    char *args[] = {"grep", "error", "/var/log/app.log", NULL};
    execvp("grep", args);
    perror("execvp");
    _exit(127);
} else {
    /* 父进程 */
    int status;
    waitpid(pid, &status, 0);
}
```
参数以数组形式传递，每个参数是独立字符串，shell 特殊字符（`;`、`|`、`$`）被当作普通字符。这是安全执行外部命令的标准做法。

</details>
