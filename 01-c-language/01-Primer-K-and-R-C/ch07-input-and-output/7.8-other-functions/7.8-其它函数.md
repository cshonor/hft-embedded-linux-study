## 常见陷阱

### 1. 标准库函数的缓冲区安全盲区

```c
strcpy(dst, src);     // 不检查大小
strcat(dst, src);     // 不检查大小
gets(buf);             // 不检查大小（C11 已移除）
sprintf(buf, fmt, x);  // 不检查大小
```

K&R 时代的标准库函数多数不检查缓冲区大小——它们假设调用者保证空间足够。这是 C 语言安全问题的头号来源。现代替代：`strncpy`/`snprintf`/`fgets`，或更安全的 `strlcpy`/`strscpy`（非标准但广泛可用）。

### 2. `atoi` vs `strtol` — 静默失败 vs 错误报告

```c
int a = atoi("abc");     // 返回 0 — 和 atoi("0") 无法区分
int b = atoi("999999999999");  // 返回 0 或截断值 — 静默溢出
long c = strtol("abc", &end, 10);  // 返回 0, end 指向 "abc" — 可检测
```

`atoi` 没有错误报告机制——无法区分「输入是 0」和「输入无效」。`strtol` 通过 `end` 指针和 `errno` 提供完整的错误信息。规则：生产代码用 `strtol`/`strtod`，不用 `atoi`/`atof`。

### 3. 随机数与安全的混淆

```c
srand(time(NULL));
int token = rand();  // ❌ 不可用于密码学！
```

`rand()` 是伪随机数生成器（PRNG），给定种子完全可预测。攻击者知道种子（如 `time(NULL)`）就能重现整个序列。密码学场景必须用 CSPRNG：`/dev/urandom`、`getrandom()`、`arc4random()`。`rand()` 仅适合测试、仿真、负载生成。

## 代码自测

**题目 1：** `atoi` 和 `strtol` 有什么区别？哪个更安全？
```c
int a = atoi("123abc");   // 返回？
long b = strtol("123abc", &end, 10);  // 返回？
```

<details>
<summary>参考答案</summary>

`atoi("123abc")` 返回 123——解析到非数字字符停止，但无法区分「0」和「abc」（都返回 0）。`strtol` 更安全：返回 123，`end` 指向 "abc"，可以通过 `end` 判断是否完全解析，还能检测溢出（设置 `errno`）。规则：用 `strtol` 替代 `atoi`，用 `strtod` 替代 `atof`。

</details>

**题目 2：** 以下哪些标准库函数不检查缓冲区大小？
```c
strcpy(dst, src);
strncpy(dst, src, n);
fgets(buf, n, fp);
sprintf(buf, "%s", src);
snprintf(buf, n, "%s", src);
```

<details>
<summary>参考答案</summary>

不检查大小：`strcpy`、`sprintf`（以及 `strcat`、`gets`）——这些函数假设调用者保证缓冲区足够大，是缓冲区溢出漏洞的主要来源。检查大小：`strncpy`（限长 n）、`fgets`（限长 n-1）、`snprintf`（限长 n-1，自动截断）。规则：永远用带长度参数的版本。`gets` 已在 C11 中完全移除。

</details>

**题目 3：** `rand()` 适合用于什么场景？不适合什么场景？

<details>
<summary>参考答案</summary>

适合：测试数据生成、Monte Carlo 仿真、负载模拟、fuzz 测试种子——这些场景不需要密码学安全性，只需统计上的均匀分布。不适合：密码/密钥生成、session token、CSRF token、一次性密码——`rand()` 是线性同余 PRNG，给定种子完全可预测。攻击者知道 `srand(time(NULL))` 就能重现序列。安全场景用 `/dev/urandom`、`getrandom()`、`arc4random()`。

</details>

**题目 4：** 以下代码有什么问题？
```c
char *p = malloc(100);
strcpy(p, user_input);  // user_input 来自网络
```

<details>
<summary>参考答案</summary>

两个问题：1) `malloc` 返回值未检查——可能返回 `NULL`（内存不足），`strcpy(NULL, ...)` 段错误。2) `strcpy` 不检查 `user_input` 长度——如果超过 100 字节就是缓冲区溢出。修正：
```c
char *p = malloc(100);
if (p == NULL) { perror("malloc"); return -1; }
strncpy(p, user_input, 99);
p[99] = '\0';
```
或用 `snprintf(p, 100, "%s", user_input)`。这是 C 语言网络编程中最常见的安全漏洞模式——永远不信任外部输入的长度。

</details>
