# 7.8.7 随机数发生器函数

## 本节讲什么

**`rand()`** 返回伪随机整数；**`srand(seed)`** 设种子。非密码学安全，适合仿真、测试、负载抽样。

## 要点

```c
srand((unsigned)time(NULL));
int r = rand() % N;   /* 0..N-1，% 有轻微偏差 */
```

- 周期与质量实现相关；**不要**用于安全/token
- C99 **`random()`** / **`srandom()`**（部分系统）质量更好
- 需要可重复测试：**固定 seed**

## 与 HFT / 回测

- 回测用固定 seed 复现随机成交
- 生产撮合随机性用硬件 RNG 或专用库，非 `rand()`

## 与后续衔接

Monte Carlo 仿真、 fuzz 测试入门；密码学见 `<stdint.h>` + OS 接口。

## 常见陷阱

### 1. 模偏差 — `rand() % N` 不均匀

```c
int r = rand() % 2;  // 看似 0/1 各 50%
```

如果 `RAND_MAX` 是奇数（如 32767），`rand()` 产生 0-32767 共 32768 个值。`% 2` 时偶数有 16384 个（0,2,...,32766），奇数有 16384 个（1,3,...,32767）——碰巧均匀。但如果 `% 3`：0 和 1 各有 10923 个，2 只有 10922 个——偏差虽小但存在。`RAND_MAX` 越小、N 越大，偏差越显著。消除方法：

```c
int r = rand() / (RAND_MAX / N + 1);  // 舍弃高位，减少偏差
// 更精确的拒绝采样：
int r;
do { r = rand(); } while (r >= RAND_MAX - (RAND_MAX % N));
r %= N;
```

### 2. 快速循环中 `srand(time(NULL))` 种子重复

```c
for (int i = 0; i < 1000; i++) {
    srand(time(NULL));  // ❌ time 精度 1 秒
    printf("%d\n", rand());  // 同一秒内 1000 次调用产生相同序列！
}
```

`time(NULL)` 返回秒级时间戳。如果循环在同一秒内执行多次（通常如此），每次 `srand` 种子相同，`rand()` 产生完全相同的序列。**`srand` 只应在程序启动时调用一次**。

### 3. `rand()` 低比特位质量差

```c
int bit = rand() % 2;  // ❌ 低位的随机性差
```

某些 `rand()` 实现（线性同余法 LCG）的低位周期很短——最低位可能是 0,1,0,1,... 交替。用高位更随机：

```c
int bit = (rand() >> 10) & 1;  // 取高位，随机性更好
```

或用 `random()`（POSIX）或 C++11 `<random>` 引擎。

### 4. 线程不安全

```c
// 线程 A                    线程 B
srand(123);                   srand(456);
int a = rand();               int b = rand();
// rand 内部有全局状态——数据竞争！
```

`rand`/`srand` 使用全局内部状态，多线程同时调用是数据竞争（UB）。POSIX 提供 `rand_r`（传入自己的状态变量），或用 `arc4random`（线程安全，BSD/macOS）。

## 代码自测

**题目 1：** 以下代码生成的随机数有什么问题？
```c
srand(42);
for (int i = 0; i < 10; i++)
    printf("%d\n", rand() % 100);
```

<details>
<summary>参考答案</summary>

1) `srand(42)` 固定种子——每次运行产生相同的序列。如果需要不可预测的随机数，用 `srand(time(NULL))`。2) `rand() % 100` 有模偏差——`RAND_MAX` 可能不是 100 的倍数，导致低位数字出现频率更高。3) `rand()` 质量低（线性同余），不适合加密或科学计算。C11 的 `arc4random` 或自行实现 Mersenne Twister 更好。

</details>

**题目 2：** 以下代码在 1 秒内循环 1000 次，会输出什么？
```c
for (int i = 0; i < 1000; i++) {
    srand(time(NULL));
    printf("%d\n", rand());
}
```

<details>
<summary>参考答案</summary>

输出 1000 个**相同的数字**。`time(NULL)` 返回秒级时间戳，同一秒内所有循环迭代拿到相同的种子。`srand` 重置随机序列到同一起点，`rand()` 返回序列的第一个值——1000 次完全相同。修正：`srand` 在循环外只调用一次。这是新手最常见的随机数错误。

</details>

**题目 3：** 为什么 `rand() % 2` 可能不是均匀的 0/1？如何改进？

<details>
<summary>参考答案</summary>

两个问题：1) **模偏差**——如果 `RAND_MAX` 是偶数（如 32766），`rand()` 产生 0-32766 共 32767 个值，`% 2` 时偶数有 16384 个、奇数有 16383 个，偏差虽小但存在。2) **低位质量差**——线性同余法 LCG 的低位周期短，最低位可能 0,1 交替。改进：
```c
// 方法 1：取高位
int bit = (rand() >> (BITS_PER_RAND - 1)) & 1;
// 方法 2：拒绝采样消除模偏差
int r;
do { r = rand(); } while (r > RAND_MAX - (RAND_MAX % 2));
bit = r % 2;
// 方法 3：用更好的随机源
uint32_t val = arc4random_uniform(2);  // BSD/macOS
```

</details>

**题目 4：** 在多线程程序中如何安全地生成随机数？

<details>
<summary>参考答案</summary>

`rand`/`srand` 使用全局内部状态，多线程同时调用是数据竞争。解决方案：
```c
// 方案 1：POSIX rand_r（每线程自己的状态）
unsigned int seed = (unsigned int)(uintptr_t)arg;
int r = rand_r(&seed);  // 线程安全

// 方案 2：BSD arc4random（线程安全，无需种子）
uint32_t r = arc4random_uniform(100);

// 方案 3：C11 无 lock-free 方案，用 mutex 保护 rand
pthread_mutex_lock(&rand_lock);
int r = rand();
pthread_mutex_unlock(&rand_lock);

// 方案 4（最佳）：每线程一个 PRNG 状态（如 xorshift128+）
uint64_t state[2];  // 每线程独立
uint64_t xorshift128plus() { /* ... */ }
```
密码学场景用 `/dev/urandom` 或 `getrandom()` 系统调用。

</details>
