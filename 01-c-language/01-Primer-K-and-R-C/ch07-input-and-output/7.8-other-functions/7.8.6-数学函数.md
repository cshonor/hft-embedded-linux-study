# 7.8.6 数学函数

## 本节讲什么

**`<math.h>`** 浮点数学：`sin` `cos` `sqrt` `pow` `log` `floor` `ceil` 等。链接时常需 **`-lm`**。

## 要点

- 多数函数操作 **`double`**；`float` 版本常有 **`sinf`** 等（C99）
- **`pow(x,y)`** 通用但非最快；热路径可用专用近似
- 检查 **`errno`** 或返回值处理域错误（如 `sqrt(-1)`）
- 整数除法 `1/2 == 0`（截断），浮点除法 `1.0/2.0 == 0.5`
- `<math.h>` 链接时常需 **`-lm`**（某些工具链将数学库分离）

### 常用函数速查

| 函数 | 作用 | 域错误 |
|------|------|--------|
| `sqrt(x)` | 平方根 | x < 0 → NaN + errno |
| `pow(x, y)` | x^y | x<0 且 y 非整数 → NaN |
| `log(x)` / `log10(x)` | 自然对数 / 常用对数 | x <= 0 → NaN/-HUGE_VAL |
| `exp(x)` | e^x | 溢出 → HUGE_VAL |
| `sin` / `cos` / `tan` | 三角函数（弧度！） | 无 |
| `floor(x)` / `ceil(x)` | 向下/向上取整 | 无 |
| `fabs(x)` | 绝对值 | 无 |
| `fmod(x, y)` | 浮点取余 | y == 0 → NaN |

## 与飞控 / 仿真的关系

- 姿态解算、PID、滤波会用到三角与开方
- 嵌入式可换 **CMSIS-DSP** 或定点库替代 double
- HFT 热路径避免 `pow`/`sin`——用查表或泰勒展开近似

## 与后续衔接

本章 I/O 与数学并列属标准库概览；数值性能不是 K&R 重点，工程上另选库。

## 常见陷阱

### 1. 整数除法 vs 浮点除法

```c
double avg = 1 / 2;        // ❌ = 0.0！先整数除法截断，再转 double
double avg = 1.0 / 2.0;    // ✓ = 0.5
double avg = (double)a / b; // ✓ 显式转换
```

`1 / 2` 两个操作数都是 `int`，执行整数除法得 0，赋给 `double` 变成 0.0。这是 C 语言最经典的陷阱之一——**只要有一个操作数是浮点，就按浮点除法**。

### 2. NaN 传播 — 一个 NaN 污染整条链

```c
double x = sqrt(-1.0);   // x = NaN
double y = x + 100;      // y = NaN（NaN 传播）
double z = y * 0;        // z = NaN（不是 0！）
if (z == 0) ...          // 不成立（NaN != 0）
if (z != z) ...          // ✓ 唯一可靠的 NaN 检测
```

NaN 的特性：与任何值比较都返回 false（包括自己）。`NaN * 0 = NaN`（不是 0）。一个 NaN 会沿着计算链传播到底。用 `isnan(x)`（C99）或 `x != x` 检测。

### 3. 三角函数参数是弧度不是角度

```c
double rad = 90 * 3.14159 / 180;  // 90度转弧度
double s = sin(rad);              // sin(π/2) = 1.0
double wrong = sin(90);           // ❌ sin(90弧度) ≈ 0.894
```

`sin`/`cos`/`tan` 的参数是**弧度**，不是角度。`sin(90)` 不是 1 而是 sin(90 弧度) ≈ 0.894。转换：`弧度 = 角度 * π / 180`。

### 4. 浮点精度 — `0.1 + 0.2 != 0.3`

```c
if (0.1 + 0.2 == 0.3) {  // ❌ false！
    /* 永远不执行 */
}
```

二进制浮点无法精确表示 0.1（就像十进制无法精确表示 1/3）。`0.1 + 0.2 = 0.30000000000000004`。浮点比较要用容差：

```c
if (fabs(a - b) < 1e-9)  // ✓ 容差比较
```

## 代码自测

**题目 1：** 以下代码有什么问题？
```c
double x = sqrt(-1.0);
printf("%f\n", x);  // 输出？
```

<details>
<summary>参考答案</summary>

`sqrt(-1.0)` 返回 NaN（Not a Number）。NaN 的特性：`NaN != NaN`（自己不等于自己），`NaN + 1 = NaN`（传播）。检查 NaN：`isnan(x)`（C99）。其他特殊值：`INFINITY`、`-INFINITY`、`-0.0`。浮点运算的精度问题也是常见陷阱：`0.1 + 0.2 != 0.3`。

</details>

**题目 2：** 以下代码计算平均值，结果为什么是 0？
```c
int a = 3, b = 2;
double avg = a / b;  // 期望 1.5
printf("%f\n", avg); // 输出 1.000000
```

<details>
<summary>参考答案</summary>

`a / b` 两个操作数都是 `int`，执行整数除法得 1，赋给 `double` 变成 1.0。要得到 1.5，至少一个操作数需为浮点：
```c
double avg = (double)a / b;   // ✓ 3.0 / 2 = 1.5
double avg = a / (double)b;   // ✓ 3 / 2.0 = 1.5
double avg = (a + b) / 2.0;   // ✓ 5 / 2.0 = 2.5（注意这不是平均值）
```
这是 C 语言最经典的陷阱——整数除法截断。`(double)a / b` 的转换在除法前发生，所以是浮点除法。

</details>

**题目 3：** 如何检测一个 `double` 是否是 NaN？为什么 `x == NaN` 不行？

<details>
<summary>参考答案</summary>

`x == NaN` 永远是 false——NaN 与任何值比较（包括自己）都返回 false，这是 IEEE 754 标准规定的。检测 NaN 的方法：
```c
if (x != x)         // ✓ 经典方法：NaN 是唯一不等于自己的值
if (isnan(x))       // ✓ C99 标准方法，更可读
```
NaN 传播特性：任何涉及 NaN 的运算结果都是 NaN（`NaN + 1 = NaN`，`NaN * 0 = NaN`）。这会在计算链中无声地传播错误，所以应尽早检测和隔离。

</details>

**题目 4：** `sin(90)` 返回 1 吗？为什么？

<details>
<summary>参考答案</summary>

不是。`sin(90)` 计算的是 sin(90 **弧度**) ≈ 0.894，不是 sin(90°) = 1。C 的三角函数参数是弧度。转换：`弧度 = 角度 * π / 180`。正确写法：
```c
#define PI 3.14159265358979323846
double s = sin(90 * PI / 180.0);  // ✓ sin(π/2) = 1.0
```
这是数值编程中最常见的单位错误。角度转弧度用 `* PI / 180`，弧度转角度用 `* 180 / PI`。

</details>
