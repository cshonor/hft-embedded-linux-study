# 7.2 字符 I/O

## 本节讲什么

最底层的字符 I/O：**`getchar()`** / **`putchar()`**，以及 **`EOF`** 结束标记。第 1 章已用 `getchar` 做文件复制；本章系统展开流模型。

## 要点

- **`getchar()`**：从 **stdin** 读一个 `unsigned char` 转为 `int` 返回；无更多数据时返回 **`EOF`**
- **`putchar(c)`**：向 **stdout** 写一个字符
- **字符流抽象**：终端、管道、文件在 C 标准 I/O 层都是**连续字节序列**，区别在是否重定向、`FILE*` 绑定
- **`EOF`**：通常为 `-1`，表示流结束或错误（需结合 `feof`/`ferror` 区分，见 7.5、7.6）
- `getchar`/`putchar` 往往经 **stdio 缓冲**；`fflush(stdout)` 在交互提示后常用

## 示例

```c
#include <stdio.h>

int c;
while ((c = getchar()) != EOF)
    putchar(c);
```

重定向：`prog < in.txt > out.txt` —— 程序不变，stdin/stdout 换绑文件。

## 底层映射

| 场景 | 对应 |
|------|------|
| 串口字符流 | 逐字节 read/write，概念同 getchar |
| UEFI ConOut | 类 putchar 输出到 GOP/串口 |
| HFT 日志 | 热路径少用 stdio，但调试仍靠字符流 |

## 常见陷阱

1. **`char` 类型存 `getchar()` 返回值**：`char c; while ((c = getchar()) != EOF)` ——若 `char` 无符号（部分平台），EOF(-1) 被截断为 255，永不等于 -1，死循环；若 `char` 有符号，0xFF(合法字节)被当成 -1，提前结束。**必须用 `int` 存 getchar 返回值**。
2. **`fflush(stdin)` 是未定义行为**：标准只允许 `fflush` **输出流**（如 stdout）。`fflush(stdin)` 在某些实现（如旧 VC++）能清输入缓冲，但不可移植。清输入缓冲用 `while (getchar() != '\n');` 或 `scanf("%*[^\n]"); getchar();`。
3. **stdout 缓冲导致输出丢失**：stdout 默认行缓冲（终端）或全缓冲（重定向到文件）。程序崩溃时缓冲区未 flush，最后几行输出丢失。调试时在关键点 `fflush(stdout)` 或 `setvbuf(stdout, NULL, _IONBF, 0)` 关缓冲。

## 自测题

**1. 选择**：`getchar()` 的返回类型是？
- A. `char`
- B. `int`
- C. `unsigned char`
- D. `void`

<details><summary>答案</summary>
B。`getchar()` 返回 `int`——它要能表示所有 `unsigned char` 值（0–255）**外加** EOF（通常 -1）。用 `char` 接收会丢失区分：0xFF 的合法字节和 EOF 都可能变成 -1。这是 K&R 反复强调的经典坑。
</details>

**2. 判断**：`fflush(stdin)` 可以清空输入缓冲区。

<details><summary>答案</summary>
错（标准层面）。C 标准只定义 `fflush` 用于**输出/更新流**，`fflush(stdin)` 是未定义行为。部分编译器（如 MSVC）作为扩展支持，但不可移植。可移植做法：`int c; while ((c = getchar()) != '\n' && c != EOF);` 清到行尾。
</details>

**3. 踩坑**：程序输出到终端正常，重定向到文件 `prog > log.txt` 后末尾几行丢失，为什么？

<details><summary>答案</summary>
stdout 在终端是**行缓冲**（遇 `\n` 自动 flush），重定向到文件后变**全缓冲**（缓冲区满才 flush，默认 4KB/8KB）。程序正常退出时 `exit` 会 flush，但若**异常崩溃**（如 SIGSEGV、`_exit`）缓冲区未 flush，末尾输出丢失。修复：关键日志后 `fflush(stdout)`，或用 `stderr`（无缓冲）输出调试信息。
</details>

**4. 应用**：写一个统计输入行数的程序，正确处理 EOF 和 `char` 类型陷阱。

<details><summary>答案</summary>
```c
#include <stdio.h>

int main(void) {
    int c;          /* 必须 int，不是 char */
    long lines = 0;
    while ((c = getchar()) != EOF) {
        if (c == '\n')
            lines++;
    }
    printf("%ld lines\n", lines);
    return 0;
}
```
关键点：`int c`（不是 char）、`!= EOF` 判断、`%ld` 匹配 long。这是 K&R 1.5 的经典例题。
</details>
