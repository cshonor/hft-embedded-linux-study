# 7.5 文件访问

## 本节讲什么

**`FILE *` 流**：`fopen` / `fclose`、字符 I/O、格式化 I/O、**二进制块读写**、**文件定位**。本章 IO 核心；承接第 6 章 struct 直接读写复合数据。

## 要点

### 标准流

```c
FILE *stdin;   /* 标准输入 */
FILE *stdout;  /* 标准输出 */
FILE *stderr;  /* 标准错误，通常无缓冲 */
```

### fopen 模式

| 模式 | 含义 |
|------|------|
| `r` | 只读 |
| `w` | 写，清空或新建 |
| `a` | 追加 |
| `r+` | 读写，不截断 |
| `w+` | 读写，清空或新建 |
| `a+` | 读+追加 |

- **二进制**：加 **`b`** —— `rb` `wb` `ab` 等，避免 Windows 文本模式下 `\r\n` 转换
- 失败返回 **`NULL`**，须检查

### 关闭与状态

```c
fclose(fp);           /* 刷新缓冲、释放资源 */
feof(fp);             /* 是否因 EOF 停止 */
ferror(fp);           /* 是否出错 */
clearerr(fp);         /* 清除错误与 EOF 标志 */
```

### 字符 I/O

- **`fgetc(fp)`** / **`fputc(c, fp)`** —— 文件版 getchar/putchar
- **`ungetc(c, fp)`** —— 推回一个字符（7.8.3）

### 二进制块读写（用户 7.7）

```c
fwrite(&hdr, sizeof hdr, 1, fp);
fread(buf, size, 1, fp);
```

- 按**字节块**读写，不受换行、编码影响
- 直接读写 **struct** 时注意：**padding、字节序、ABI**（第 6 章）—— 跨设备/跨平台易错

### 文件定位（用户 7.8）

```c
long pos = ftell(fp);
fseek(fp, offset, SEEK_SET);  /* SEEK_CUR, SEEK_END */
rewind(fp);                   /* 等价 fseek(fp, 0L, SEEK_SET) */
```

- 随机访问 ELF 头、镜像分片、历史 tick 文件某偏移
- 大文件用 **`fseeko`/`ftello`**（POSIX，`off_t`）

## 难点

| 坑 | 说明 |
|----|------|
| 文本 vs 二进制 | Windows 文本模式 `\n`↔`\r\n` |
| struct 整块 fread | 对齐/endian 不可移植 |
| EOF vs 错误 | `feof` 仅在读失败后判断；先看返回值 |

## 与后续衔接

第 8 章 **`open`/`read`/`write`** 是更底层 fd I/O；stdio 带缓冲，适合可移植工具，内核/DPDK 多用直接 syscall。

## 常见陷阱

1. **fopen 返回值未检查直接使用**：`FILE *fp = fopen("x.txt", "r"); fgets(buf, 100, fp);` ——若文件不存在，fp 是 NULL，fgets 对 NULL 解引用即段错误。**每次 fopen 必须检查 NULL**，出错用 `perror` 或 `strerror(errno)` 打印原因。这是 C 文件操作的第一原则。

2. **忘记 fclose 导致资源泄漏**：每个打开的 `FILE*` 占用一个 fd 和内部缓冲。函数中多处 `return` 但只在末尾 `fclose`，提前 return 的路径泄漏。用 `goto cleanup` 模式或 C 的 `cleanup` 属性（GCC `__attribute__((cleanup))`）。长期运行的服务进程泄漏 fd 最终触发 `EMFILE`（too many open files）。

3. **feof 的误用——在读之前检查 feof**：`while (!feof(fp)) { fgets(...); process(line); }` ——这是经典错误。feof 只在**读操作到达 EOF 后**才返回真，不能用来预判是否还有数据。最后一次 fgets 读到 EOF 时返回 NULL，但循环体已经执行了一次处理空行。正确写法：`while (fgets(buf, sizeof buf, fp) != NULL) { process(buf); }`——先读再处理，用返回值判断结束。

## 自测题

**1. 选择**：`fopen("data.txt", "r")` 返回 NULL，最可能的原因是？
- A. 内存不足
- B. 文件不存在或无读权限
- C. 文件为空
- D. 文件被其他进程打开

<details><summary>答案</summary>
B。fopen("r") 失败最常见原因是文件不存在（ENOENT）或无读权限（EACCES）。文件为空不会导致 fopen 失败（空文件可以正常打开，只是读时立即返回 EOF）。出错后应查 `errno` 确定具体原因：`if ((fp = fopen(...)) == NULL) { perror("fopen"); exit(1); }`。
</details>

**2. 判断**：`while (!feof(fp)) { fgets(buf, 100, fp); ... }` 是正确的文件读取循环。

<details><summary>答案</summary>
错。feof 在**读操作遇到 EOF 之后**才返回真，不能预判。当 fgets 最后一次读到 EOF 返回 NULL 时，feof 此时才为真，但循环体已经多执行了一次处理无效数据。正确写法：`while (fgets(buf, sizeof buf, fp) != NULL) { ... }`——用 fgets 的返回值判断是否读到数据。这是 C 新手最常见的 IO 错误之一。
</details>

**3. 踩坑**：Windows 上用 `fopen("data.bin", "r")` 读二进制文件，偶尔读到 `0x1A` 就提前 EOF，为什么？

<details><summary>答案</summary>
Windows 文本模式（`"r"` 而非 `"rb"`）会把 `0x1A`（Ctrl-Z）当作 EOF 标记（CP/M 遗留），还会做 `\r\n` → `\n` 转换。读二进制文件必须用 `"rb"` 模式，避免文本翻译。Linux 不区分文本/二进制模式（`"r"` 和 `"rb"` 相同），但跨平台代码应始终加 `b`。同理写二进制用 `"wb"`。
</details>

**4. 应用**：写一个安全的配置文件读取函数，逐行读入并跳过注释行（`#` 开头）和空行，返回成功读取的行数。

<details><summary>答案</summary>
```c
int read_config(const char *path, char lines[][256], int max_lines) {
    FILE *fp = fopen(path, "r");
    if (!fp) { perror("fopen"); return -1; }

    char buf[256];
    int count = 0;
    while (fgets(buf, sizeof buf, fp) != NULL && count < max_lines) {
        if (buf[0] == '#' || buf[0] == '\n' || buf[0] == '\0')
            continue;
        /* 去掉行尾换行 */
        buf[strcspn(buf, "\n")] = '\0';
        strncpy(lines[count], buf, 255);
        lines[count][255] = '\0';
        count++;
    }
    fclose(fp);
    return count;
}
```
关键：fopen 检查 NULL、fgets 返回值判断结束、strcspn 去换行、strncpy 防溢出。这是配置/日志解析的标准框架。
</details>
