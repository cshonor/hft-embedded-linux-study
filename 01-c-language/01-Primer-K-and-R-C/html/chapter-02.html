2.1

变量名

本节讲什么

讲解 C 语言 标识符（identifier） 的词法基础 —— 变量名、函数名、宏名、结构体名、typedef 名 等自定义名称的合法格式、关键字 限制、大小写 特性，以及工程命名惯例。属于 词法最底层 规则：后续所有声明、定义都建立在合法标识符之上。

前置依赖：无（ch02 开篇）。
后续： 2.2 类型与长度、2.4 声明、ch04 存储类、GNU/DPDK/内核命名拓展。

要点

1. 标识符合法组成规则

规则 说明
允许字符 英文字母 a–z / A–Z、数字 0–9、下划线 _
首字符 不能 以数字开头
禁止 #、-、空格、中文标点等 非字母数字下划线 符号 
int data;        /* 合法 */
int buf_len;     /* 合法 */
int Val100;      /* 合法 */

int 1num;        /* 非法：数字开头 */
int user-name;   /* 非法：含 '-' */
int #temp;       /* 非法 */

标识符长度：C99 起 至少 63 字节 有效字符须被编译器区分（更早实现可能更短）；工程上 勿写超长名。

2. 大小写敏感

C 严格区分大小写 —— 大小写不同即 不同标识符：

int sum, Sum, SUM;   /* 三个互不相关的变量 */
惯例（工程） 示例
普通变量、函数 小写 + 下划线：buf_len、get_line
宏常量 全大写 + 下划线：MAXLINE、RTE_PKTMBUF_HEADROOM
结构体 / typedef 类型名 首字母大写或统一前缀：OrderBook、rte_mbuf（库风格）

3. 关键字（保留字）：单独禁止 vs 嵌入允许

分 两层 理解：完整关键字 不能当标识符；嵌入 在更长名字里 语法允许（工程上仍不推荐）。

3.1 单独完整关键字 —— 绝对不能当标识符

int、if、return 等 整词 做变量名 → 编译报错：

int int;      /* 非法 */
int if;       /* 非法 */
int return;   /* 非法 */

编译器对关键字做 完整 token 匹配，不是子串搜索。

3.2 关键字嵌入标识符 —— 语法合法

只要 不是单独一个关键字，作为名字 一部分 即可：

int int_val;      /* 内含 int，允许 */
int if_flag;      /* 内含 if，允许 */
int return_buf;   /* 内含 return，允许 */
int num_if;       /* 关键字在末尾，允许 */

3.3 下划线包裹关键字 —— 仍合法

int _if;
int if_;
int __int__;

语法 通过，但 可读性差，内核/DPDK 规范一般避免。

3.4 C++ 关键字同理

int class_buf;      /* C/C++ 均可：嵌入允许 */
int namespace_id;   /* 嵌入允许 */
int class;          /* C++ 非法：完整关键字 */

3.5 工程建议（语法允许 ≠ 推荐）

做法 语法 工程
int int; 禁止 —
int int_val; 允许 不推荐 — 易误读、混编歧义
int max_count; 允许 推荐 — 见名知意、无关键字子串
  • 完整清单：见 附录 A；C99 新增 5 个见 2.1.1 C99 标准与演进
  • 宏名 禁止 撞完整关键字或标准库名（1.4 §5）

总结：完整独立关键字 禁止；作为子串嵌入 语法允许，不推荐。

4. 可读性命名 + 底层工程风格

通用原则

  1. 见名知意：max_line_len 优于 m；单字母仅循环 i/j/k、数学下标等短作用域
  2. 避免 与标准库 / 常见缩写撞名：open、read、index（POSIX 函数名）
  3. 宏全大写 + 前缀：HFT_RING_SIZE，避免 #define getchar 劫持标准库（1.5）

内核 / DPDK / HFT 常见风格

前缀/模式 含义 示例
rte_ DPDK 公共 API 前缀 rte_mbuf、rte_eth_rx_burst
__ 开头 实现保留 / 内核私有（业务代码慎用） __kernel_*；与用户空间 __ 扩展规则见 GNU 文档
static 文件内 本 .c 私有符号，不污染全局命名空间（ch04） static int dbg_count

双下划线、_ 开头保留规则在 GNU 扩展 / 可移植性 章节展开；初学：自定义标识符用字母/下划线开头，别用 __ 开头。

C 与 C++ 标识符区别

主题 C C++
词法规则 字母数字下划线、数字非首 同左
关键字数量 较少（C11 约 44 个） 更多：class、namespace、template、public、private、new、delete…
.c 纯 C 文件 避开 C 关键字 即可 —
混编 / 共用头文件 变量名须 同时避开 C 与 C++ 关键字，防 .cpp 编译失败 同左 
/* 在 .h 被 C++ include 时，下面在 C++ 里会炸 */

共用头文件用：

extern "C" {
#endif
/* C API 声明 */

}
#endif

HFT / 底层开发的用处

  1. 协议字段名 与 宏名 分离：字段 price_ticks，上限 MAX_TICKS
  2. DPDK 代码 识别 rte_ 即库 API，勿自建 rte_foo 假官方符号
  3. Code review：关键字拼写错误、大小写混用（Int vs int）一眼抓
  4. 链接符号：函数名即链接名，命名冲突见 ch04 / C 陷阱 ch04

参考答案

2.1

.1 C99 标准与演进

本节讲什么

C99 = ISO/IEC 9899:1999（1999 年第二版国际标准），在 C89（ANSI C） 基础上大规模升级，是当今 Linux 内核、DPDK、嵌入式、HFT 最主流的 C 方言基线。说明 C99 相对 C89 的核心变化、5 个新增关键字（与 2.1 变量名 衔接）、常用语法特性与编译启用方式。

一、C89 vs C99 一句话

标准 年代 定位
C89 / ANSI C 1989 初代统一标准；语法限制多
C99 1999 现代 C 工业底层标配；实用语法、<stdint.h>、// 注释
C11 / C17 / C23 后续 在 C99 上继续增特性（_Generic、线程等）

演进脉络：K&R C → C89 → C99 → C11 → C17 → C23
C99 承上启下，几乎所有底层与高性能框架以 C99 为最低共识。

二、C99 新增 5 个关键字

C89 原有关键字不变；C99 新增 下列保留字 —— 不能单独作标识符，可嵌入 更长名字（见 2.1 §3）：

关键字 用途
inline 内联函数，减少调用开销
restrict 指针无别名承诺，利于优化（DPDK/内核热点）
_Bool 布尔基础类型；配 <stdbool.h> 用 bool/true/false
_Complex 复数类型
_Imaginary 虚数类型 
int inline_val;    /* 嵌入：语法允许，工程不推荐 */
inline void foo(void) { }   /* inline 作函数修饰 */

_Bool flag;        /* 或 #include <stdbool.h> 后 bool flag; */

混编：除 C99 关键字，共用头文件还须避开 C++ 独有关键字（class、namespace、template…）。

三、相对 C89 的高频新特性

1. 语法层面

特性 C89 C99
注释 仅 /* */ 支持 // 单行注释
变量声明位置 块内变量须在语句 之前 用到再声明；for (int i = 0; …) 合法
VLA 变长数组 无 int n = 10; int buf[n];（长度运行期定；内核部分场景用，栈风险需注意）
指定初始化 顺序初始化 struct A s = {.y = 10, .x = 1};
复合字面量 无 func((struct A){1, 2}); 临时结构体

2. 数据类型扩展

  1. long long / unsigned long long — 64 位整数（见 2.2）
  2. _Bool — 布尔；<stdbool.h> 提供 bool、true、false
  3. <stdint.h> — int32_t、uint64_t 等定宽类型（2.2.1 选型总览）
  4. _Complex — 复数浮点

3. 函数与性能

  • inline — 内联定义，减少函数调用（仍受 static/链接规则约束，ch04）
  • restrict — 承诺指针是访问对象的 唯一途径，编译器可激进优化；误用 → 未定义行为

4. 预处理与库

  • 可变参数宏：#define LOG(fmt, ...) printf(fmt, __VA_ARGS__)
  • 数学库扩展、IEEE 754 浮点、<tgmath.h> 类型泛化数学
  • 柔性数组成员：结构体末尾 int arr[];（常见内核结构体模式，ch06）

四、编译器如何启用

gcc -std=c99 -Wall -Wextra -o prog prog.c
clang -std=c99 ...
编译器 说明
GCC / Clang -std=c99 明确标准；默认常为 GNU11（GNU 扩展 + C11 超集，兼容多数 C99）
MSVC C99 支持 不完整；工业底层多用 GCC/Clang（WSL、Linux、交叉编译）

本仓库 demo 常用：-std=c11（C99 超集，向后兼容 C99 特性）。

五、与 2.1 变量名 的关联

  1. 5 个 C99 关键字 不能整词作变量名；restrict_ptr 类嵌入合法但不推荐
  2. 标识符有效长度（C99）：外部链接 至少 31 字符、内部 至少 63 字符须区分 —— 长名不再像 C89 那样易被截断歧义
  3. restrict / inline 与 rte_ / __ 工程命名并列出现：前者是 语言修饰符，后者是 项目/实现命名空间

六、HFT / 内核 / DPDK 实践

C99 特性 典型场景
<stdint.h> 报文字段、时间戳、定长协议
restrict 热循环内指针别名优化
inline 头文件内小函数、static inline 工具函数
// 注释 全工程可读性
long long / int64_t 纳秒时间、大计数

注意：VLA 在 Linux 内核已移除；用户态可用但大 VLA 易栈溢出 —— 大缓冲用 malloc 或固定数组。

2.2

数据类型及长度

本节讲什么

内置类型的 存储宽度 与 有符号/无符号 语义——理解内存、寄存器、协议字段、ABI 对齐的基础。

核心结论：

  1. 标准 C 只规定最小取值范围与相对大小，不固定各类型字节数
  2. 实际占用字节、数值上下限，由 CPU 架构（32/64 位 x86、ARM）+ 编译器 + OS ABI 决定

与 1.2 变量与算术表达式 的 int/float 衔接；与 C 陷阱 ch07 7.1 可移植性专题对照。

四个标准头怎么选、怎么用 → 2.2.1 整型头文件选型总览（limits.h / stdint.h / inttypes.h / float.h）。

要点

1. 基础类型与 CPU 的关联（含存储用途）

类型 典型字节 受 CPU 影响 说明 存储用途
char 1 极小 最小可寻址单元；有符号 -128~127 / 无符号 0~255（实现定义 signed/unsigned） ① 单个 ASCII 字符（字母、符号）
② 小块二进制缓冲、字节流
③ 极小范围数值标记（0~255）
④ 字符串底层（char[] / char* 存文本）
short ≥2，通常 2 很小 标准：sizeof(short) ≥ sizeof(char) ① 范围不大的整数，省内存
② 音频采样、屏幕坐标、硬件寄存器短数值
③ 嵌入式、大数组小整数场景
int ≥2，现代几乎 4 较大 32 位 CPU 普遍 4 字节；64 位 x86/ARM 多数仍 4；老 16 位机曾见 2 字节 ① 日常通用整数：循环、ID、数量、偏移
② 普通运算，CPU 原生 int 效率最高
③ 文件大小、下标、函数返回状态码
long ≥4 很大 32 位：4；Win64 LLP64：4；Linux/macOS LP64：8 ① 32 位平台略大范围整数
② Linux/macOS 64 位：文件偏移、PID、时间戳
⚠️ 跨平台勿当固定 64 位
long long ≥8，通常 8 小 C99 起；32/64 位平台普遍 8 字节 ① 超大整数：大文件长度、高精度计数、金额
② 跨平台固定 64 位，少踩 long 差异
③ 加密、哈希、64 位寄存器数据
float 4 现代 x86/ARM 较统一 IEEE 754 单精度 ① 精度要求一般的小数：游戏坐标、图形、传感器实时数据
② 对内存敏感的浮点数组
double 8 现代 x86/ARM 较统一 IEEE 754 双精度 ① 高精度科学计算、金融、物理仿真
② C 标准库 <math.h> 函数默认 double
③ 需减少舍入误差的场景
void * 4 或 8 = CPU 位宽 所有对象指针 大小一致；不可直接解引用 ① 通用指针：malloc 返回值、泛型容器
② 存任意类型地址再 cast 回去
③ 判断 32/64 位；内核/驱动通用地址

标准只保证：char ≤ short ≤ int ≤ long ≤ long long，且 sizeof(char) == 1。

选型速记

需求 优先选型
日常整数 int — CPU 优化最好，无特殊需求首选
char 不只是字符 本质 1 字节数；二进制 I/O 靠 char / uint8_t
跨平台 64 位大数 long long 或 int64_t — 避开 long 的 Win/Linux 差异
浮点 省内存 → float；要精度、少误差 → double
协议 / wire format stdint.h 定宽类型（见 §5）

指针类型配套用途

与 1.8.1 指针形参 衔接 —— 指针 存的都是地址，* 左侧类型 决定解引用读宽与语义：

指针类型 典型用途
char * 字符串首地址、命令行参数；原始字节流（文件、网络包）
int * 整型数组批量读写；传参改外部 int（交换、多结果）
float * / double * 浮点数组、矩阵、图像像素批量处理
long long * 超大数值数组；64 位硬件数据交互
void * 类型未知时暂存地址；malloc；回调泛型参数

2. 有符号 / 无符号范围由字节长度推导

字节越多，可表示范围越大（有符号补码 / 无符号模 (2^n)）：

宽度 有符号 int 量级 无符号量级
4 字节 约 ±21 亿 约 42 亿
8 字节 约 ±9×10¹⁸ 约 1.8×10¹⁹

CPU 寄存器宽度影响编译器对「自然整型」的选择，这是 int/long 随平台变化 的根源。

3. sizeof 与 <limits.h>

#include <stdio.h>

int main(void)
{
    printf("sizeof char=%zu short=%zu int=%zu long=%zu long long=%zu void*=%zu\n",
           sizeof(char), sizeof(short), sizeof(int),
           sizeof(long), sizeof(long long), sizeof(void *));
    return 0;
}
  • sizeof(T)：编译期常量，类型 字节数
  • <limits.h>：INT_MAX、LONG_MAX 等 实现定义 上下限（详见 2.2.1 选型总览）
  • 打印 sizeof 用 %zu（size_t），不要用 %d

4. 直观例子：同一 long，不同平台

printf("long size: %zu\n", sizeof(long));
环境 典型输出
32 位 Linux 4
Windows 64 位（LLP64） 4
64 位 Ubuntu / WSL（LP64） 8

同一份源码，long 能表示的范围完全不同——跨平台用裸 long 存时间戳、大计数易溢出或截断。

5. 固定宽度整数：stdint.h（嵌入式 / HFT 必用）

为消除架构差异，C99 提供 定长类型：

#include <stdint.h>

uint8_t   u8;
int16_t   i16;
uint32_t  u32;
int64_t   i64;
类型 保证
int32_t / uint32_t 恰好 32 位
int64_t / uint64_t 恰好 64 位

不管 32 还是 64 位 CPU，wire format、寄存器镜像、跨进程协议 应优先用这套；size_t / ptrdiff_t 用于大小与指针差。配套选型与 PRIu64 等见 2.2.1 整型头文件选型总览、2.2.3 stdint.h。

6. HFT / 嵌入式实用总结

  1. 普通 int / long 有平台差异，底层高性能代码勿假设固定宽度
  2. 一律用 <stdint.h> 定长类型，屏蔽 CPU/ABI 差异
  3. float/double 在现代 x86/ARM64 上通常 4/8 字节，但仍勿用 == 比浮点
  4. 指针宽度 = CPU 位宽；指针与整数互转用 uintptr_t，不用 int（见 C 陷阱 7.5）
  5. 字节数据用 unsigned char / uint8_t，不裸用可能 signed 的 char

题目 1： int、int32_t、int_fast32_t、int_least32_t 各有什么区别？

参考答案

int：编译器选择的最优宽度，通常 4 字节但不保证。 int32_t：恰好 32 位，如果平台不支持则不存在。 int_least32_t：至少 32 位的最小类型（可能 >32 位）。 int_fast32_t：至少 32 位的最快类型（可能 >32 位，选运算最快的宽度）。 需要精确宽度用 int32_t，需要可移植且性能优先用 int_fast32_t。

题目 2： 如何获取 int 的最大值？为什么不直接写 2147483647？

参考答案

用 <limits.h> 中的 INT_MAX 宏。直接写 2147483647 假设了 int 是 32 位——在 16 位平台上 int 最大值是 32767，这个字面量会溢出。INT_MAX 在每个平台上都正确定义。同理用 INT_MIN、UINT_MAX、LLONG_MAX 等。

三、核心使用场景

1. 数值溢出判断（相加前检查）

#include <limits.h>
#include <stdio.h>

int a = 2000000000;
int b = 2000000000;

if (a > INT_MAX - b) {
    printf("相加溢出\n");
} else {
    printf("%d\n", a + b);
}

通用写法（含负数下溢）：

int add_safe(int a, int b)
{
    if (b > 0 && a > INT_MAX - b)
        return -1;   /* 上溢 */
    if (b < 0 && a < INT_MIN - b)
        return -1;   /* 下溢 */
    return a + b;
}

HFT / 协议层更常直接用 stdint.h 定宽类型 + 显式位宽检查；limits.h 适合围绕 原生 int 的通用工具代码。

2. 通用业务与循环边界

  • 不涉及硬件固定位宽、单平台工具：用 INT_MAX 做阈值
  • 循环、缓冲区上限：替代硬编码 2147483647

3. 跨平台兼容：拒绝硬编码魔数

/* 错 */
if (num > 2147483647)

/* 对 */
if (num > INT_MAX)

4. 位运算与缓冲区

  • CHAR_BIT：1 字节多少位，通用掩码/移位计算
  • 与 2.9 按位运算符 衔接

5. 无符号类型无 UINT_MIN

无符号最小值恒为 0；标准 不提供 UINT_MIN、ULONG_MIN 等宏，判断下限时直接与 0 比即可。

  1. int / long 宽度随平台变 —— 32 位 long 常 4 字节；64 位 Linux long 常 8 字节；协议/寄存器勿依赖 LONG_MAX 当 64 位上限

  3. 兼容性：C89 可用主体宏；long long 宏仅 C99+
  4. 打印 LLONG_MAX 用 %lld；int64_t 用 PRId64（<inttypes.h>）

.4 inttypes.h

本节讲什么

C99 标准头文件，必须配合 <stdint.h> 使用（#include <inttypes.h> 会 自动包含 stdint.h）。两大作用：

  1. 为 int8_t / uint32_t / int64_t 等定宽整数提供 printf / scanf 格式化宏（PRId32、PRIu64…）
  2. 提供 intmax_t / uintmax_t 及 imaxabs、strtoimax 等跨平台大整数辅助

一、为什么不能直接用 %d / %ld？

类型 问题
int32_t 多数平台 = int，%d 常能用 —— 但 标准不保证 与 int 同一 typedef
int64_t 有的平台是 long，有的是 long long

硬写 %lld 或 %ld → 部分平台 警告、输出错乱。

inttypes.h 宏 在预处理期展开为 本平台正确 的转换说明符，统一源码写法。

printf("%" PRId64 "\n", (int64_t)x);   /* 跨平台 */
/* 不要写死 printf("%lld\n", x);       除非确定平台 */

与 1.1.2 printf 衔接。

有符号十进制 PRIdN

宏 类型

PRId32 int32_t
PRId64 int64_t

无符号十进制 PRIuN

PRIu8 / PRIu16 / PRIu32 / PRIu64

常量

本节讲什么

讲解 C 语言中的常量机制：#define 宏常量（预处理文本替换、不占运行时内存）与 const 只读变量 / 字面量（编译进程序、常放常量存储区）。并分 整型、浮点、字符、字符串 四类字面量的语法与存储，衔接 1.4 #define、1.9 字符数组。

字面量属于编译器 词法分析 阶段的 token；预处理之后，编译前端按规则解析进制、转义、后缀，翻译成符号表中的数值或只读数据。

0. C 里「常量」的两种机制（先分清）

口语里说「常量」常混两类，处理阶段 和 占不占内存 完全不同：

#define 宏常量 const 只读变量 / 字面量
是什么 预处理 文本替换 的名字 有类型的 变量 或源码里的 字面量
处理阶段 预处理（编译前） 编译 / 链接
运行时内存 宏名 本身不占 内存；替换后的值可能变成 立即数 或并入只读数据 const 全局、字符串字面量 等通常进 常量存储区（4.3.1 §4）
能否修改 无「对象」可改 —— 只有替换 运行期 不可写（写 const / 改字面量 → 未定义行为或编译错误）
典型写法 #define MAXLINE 1000 const int maxline = 1000;、"hello" 
#define BUFSIZE 1024          /* 预处理：BUFSIZE → 1024，宏名不占运行时空间 */

const int max_conn = 64;      /* 只读变量；全局 const 常放 .rodata */
char *msg = "ready";          /* 字面量 "ready" 在常量存储区，不可改 *msg */

记忆：

  1. #define：编译前 全文替换，不是变量，没有类型、一般不能取址。
  2. const + 字面量：是 程序数据，加载后躺在 常量区（或局部 const 在栈上但仍 只读），运行期间 不能改。

0.1 函数外部的 const：像全局，但默认「文件私有」

在 函数外（文件顶层）写 const，和 全局变量 有相似之处，也有关键区别：

无 static 全局 int g 文件级 const int limit（默认）
存储 全局/静态区（可写） 常量存储区（只读，4.3.1 §4）
作用域 本文件全文可见 本文件全文可见（文件作用域，同全局）
能否改值 ✅ 运行期可写 ❌ 只读
默认链接 外部链接 内部链接（C 规则：未写 extern 的 const 默认内部）
他文件 extern ✅ extern int g; 可引用 ❌ 不能 像普通全局那样跨文件引用 
/* a.c */
int num = 10;                 /* 非 static 全局 → b.c: extern int num; ✅ */
static int s_num = 20;        /* static 全局 → 仅 a.c ✅，b.c extern ❌ */
const int c_num = 30;         /* 常量区，默认内部 → 仅 a.c；不能 c_num=40 */

/* b.c */
extern int num;               /* ✅ 用 a.c 那份，可改 */
/* extern int s_num; */       /* ❌ */
/* extern const int c_num; */ /* ❌ 除非 a.c 定义写成 extern const int c_num = 30; */

若 确实要跨文件共享 只读常量，a.c 定义处须 extern const：

/* a.c —— 唯一定义 */
extern const int c_num = 30;   /* 外部链接 + 只读；b.c 可 extern 引用，仍不能改值 */

/* b.c */
extern const int c_num;
printf("%d\n", c_num);         /* OK */
/* c_num = 40; */              /* 编译错误 */

完整三变量对照见 4.3 §1.2。

记忆：文件级 const 像全局（整文件能用、放常量区），但 本质是只读的；且 默认内部链接，和 非 static 可写全局 不同 —— 他文件 不能 单靠 extern 接到你没导出的那份。

static 不等于只读：static int s_num=20 在 a.c 内可改；加了 const 才 不能改。

文件级 static const：const → 常量区、只读；static → 仅本 .c；既不能改，也不能被他文件 extern（4.6 §2）。

详见 4.4 §3、4.3 §1.1、1.4。

声明

本节讲什么

讲解 C 语言 变量基础声明语法：类型 标识符; / 带初始化；局部 与 全局 声明的存储位置、生命周期直观差异。本章只讲 表层规则 —— static / extern 完整语义、单定义规则、作用域细节留 ch04 与 1.10 外部变量。

前置：2.1 变量名、2.2 类型。
后续：2.5 起表达式运算；ch04 存储类；Expert C ch03 复杂声明。

要点

1. 基础声明两种格式

① 仅声明（无初值）

int a;
double val;

② 声明并初始化

int num = 10;
float pi = 3.14f;
形式 说明
类型 标识符; 引入名字与类型；局部未初始化 → 垃圾值；全局/静态 → 0
类型 标识符 = 常量/表达式; 定义 + 赋初值

2. 一行多变量（逗号分隔）

同类型可 共用 前置类型关键字：

int x, y, z;              /* x、y、z 全是 int */
int a = 1, b, c = 5;      /* 混用初始化 */

⚠️ 指针坑（与 1.8.1 同源）：

int *p, q;    /* 只有 p 是指针；q 是普通 int */
int *p, *q;   /* 两个都是指针 */

逗号 只分隔变量名，不会 让每个名字都带上 *。

3. 类型声明 围绕标识符（指针 / 数组读法）

C 的声明不是简单「从左到右念类型再念名字」，而是 以标识符为中心，** [] () 等 绑在名字上，表示「对名字做什么操作得到什么类型」。

读法：先找到 标识符，问「对它解引用 / 取下标 / 调用，得到什么？」

void *p —— p 是指针，解引用后是 void

void *p;
/* 读：*p 是 void → p 是 void 指针（通用指针） */
步骤 含义
标识符 p
紧邻 * 对 p 解引用 → 得到 void
结论 p 是 void *

与 4.1 void vs void * 呼应：左边写 void * 作返回类型，同样是「返回的那个东西，解引用一层是 void」。

int *a[10] —— a 是数组，元素是 int 指针

int *a[10];
/* 读：a[10] 是 int* → a 是含 10 个元素的数组，每个元素是 int 指针 */
步骤 含义
标识符 a
紧邻 [10] a[10] → 数组，共 10 个元素
再往前 int * 每个元素类型是 int *
结论 a 是指针数组（不是「指向数组的指针」）

对比（ch05 5.12）：

int *a[10];     /* a：数组，元素 int*  —— [] 先绑 a */
int (*b)[10];   /* b：指针，指向 int[10] —— () 让 * 先绑 b */

为何这么设计：简单声明 int x 与复杂声明 int *p、int a[10] 同一套规则 —— 都是「修饰符围绕标识符」，避免再发明另一套数组/指针语法。

完整螺旋法则、int (*signal(...))(...) 见 5.12、Expert C ch03。

项 说明
位置 main、自定义函数、if/for 的 {} 内
存储类别 默认 自动存储 auto（关键字可省略）→ 栈

C89 vs C99 声明位置：

标准 规则
C89 块内所有声明须在 第一条语句之前

项 说明

6. 基础限定符：const（本节仅提及）

  • 文件顶层 const：通常进 常量区；C 里 默认内部链接 —— 他文件不能像普通全局那样 extern 引用（见 2.3 §0.1）

声明（declaration） 定义（definition）

2.5

算术运算符

本节讲什么

二元算术：+ - * / % 及整型、浮点混合时的行为。看似简单，但整数除法截断方向、取模符号、溢出是 C 语言经典坑源。

要点

五个运算符

运算符 含义 整数行为 浮点行为
+ 加 溢出 UB（有符号） IEEE 754
- 减 溢出 UB（有符号） IEEE 754
* 乘 溢出 UB（有符号） IEEE 754
/ 除 截断小数（toward zero） 正常除法
% 取模 仅整数，符号随被除数 非法（编译错误）

整数除法截断

C99 起明确规定向零截断（truncation toward zero）：

 7 /  2 == 3      /* 截断 0.5 */
-7 /  2 == -3     /* 截断 -0.5，不是 -4 */
 7 / -2 == -3
-7 / -2 == 3

C89 之前行为实现定义——可能向零截断，也可能向负无穷取整（floor）。K&R 第 2 版基于 ANSI C89，书中提到这一点。现代编译器（GCC/Clang）默认 C99+ 行为。

取模符号

C99 规定：(a/b)*b + a%b == a，由此推出 a%b 的符号与 a（被除数）相同：

 7 %  3 ==  1
-7 %  3 == -1     /* 符号随被除数 */
 7 % -3 ==  1
-7 % -3 == -1

浮点除法

至少一侧为浮点即为浮点除法：

9 / 2    == 4       /* 整数除法 */
9 / 2.0  == 4.5     /* 浮点除法 */
9.0 / 2  == 4.5

溢出行为

类型 溢出行为 例子
有符号整数 未定义行为（UB） INT_MAX + 1 可能 wrap、可能 trap
无符号整数 模 2^n 回绕（well-defined） UINT_MAX + 1 == 0
浮点 IEEE 754（inf/nan） DBL_MAX * 2 == inf

HFT/内核里计时、对齐常用 % 与 / 组合（如 offset % align、ticks / freq）。

常见陷阱

  1. 有符号整数溢出是 UB，编译器可能激进优化：for (int i = 0; i <= N; i++) 当 N = INT_MAX 时，i++ 溢出是 UB，GCC -O2 可能假定循环不会溢出从而生成无限循环。安全写法用 unsigned 或加边界检查。INT_MAX + 1 在 GCC -O2 下可能得到 INT_MIN（wrap），也可能触发 trap（-ftrapv），取决于编译选项——UB 意味着编译器可以做任何事。

  2. a / b * b 不等于 a（整数除法丢精度）：7 / 2 * 2 == 6（不是 7），因为 7/2 先截断为 3。浮点类似：0.1 + 0.2 != 0.3（IEEE 754 精度问题）。涉及金额计算时用整数（分/厘）或定点数，不用浮点。对齐计算 addr / align * align 是安全的（因为能被整除时不丢精度）。

  3. % 的符号方向常被搞反：以为 -7 % 3 == 2（正数），实际 C99 规定 -7 % 3 == -1（符号随被除数）。Python 的 % 结果符号随除数（-7 % 3 == 2），和 C 不同。写环形缓冲索引 (idx - 1) % N 时，若 idx = 0 则 -1 % N 在 C 中为 -1（不是 N-1），需要 (idx + N - 1) % N 修正。

自测题

1. 选择：C99 中 -7 / 2 的结果是？ - A. -4 - B. -3 - C. -3.5 - D. 实现定义

答案

B。C99 规定整数除法向零截断（truncation toward zero），-7 / 2 = -3.5 截掉小数部分得 -3。C89 之前是实现定义（可能 -3 或 -4），现代编译器默认 C99+ 行为。注意：这不是 floor（向下取整），floor(-3.5) = -4。

2. 判断：unsigned int 溢出是未定义行为。

答案

错。无符号整数溢出是良好定义的——按模 2^n 回绕（C 标准 6.2.5/9）。UINT_MAX + 1 == 0 是确定的。只有有符号整数溢出才是 UB。因此循环计数器、环形缓冲索引常用 size_t（无符号），溢出行为可预测。但注意无符号减法 0u - 1 得到 UINT_MAX，可能导致意外循环。

3. 踩坑：环形缓冲回绕写 (idx - 1) % N，当 idx = 0 时结果不是 N-1，为什么？

答案

idx = 0 时 idx - 1 = -1，-1 % N 在 C99 中符号随被除数，结果为 -1（不是 N-1）。数组下标 -1 是越界访问。修复：(idx + N - 1) % N（先加 N 保证非负），或用无符号 ((unsigned)idx - 1) % N（无符号取模回绕为 N-1）。这是环形缓冲/哈希表探测的经典坑。

4. 应用：写一个安全的 div_round_up(a, b) 向上取整除法，处理正数和负数。

答案 
/* 向上取整：正数用 (a + b - 1) / b，负数直接截断即向上 */
int div_round_up(int a, int b) {
    if (b == 0) return 0;  /* 防除零 */
    if ((a >= 0) == (b > 0))
        return (a + (b > 0 ? b - 1 : b + 1)) / b;
    else
        return a / b;  /* 异号：截断即向上取整 */
}
/* div_round_up(7, 3) == 3, div_round_up(-7, 3) == -2 */

常见简化版（仅正数）：(a + b - 1) / b。用于计算需要的页数/块数/缓冲数。注意 a + b - 1 本身可能溢出。

后续：2.7 类型转换、2.13 优先级；2.1.1 C99 中 _Bool / <stdbool.h>。

要点

1. 关系运算符（比较大小、相等）

运算符 含义
< > 小于、大于
<= >= 小于等于、大于等于
== != 等于、不等于

结果类型：int，只有 1（真） 或 0（假）。

5 > 3;      /* 1 */
10 == 10;   /* 1 */
7 != 7;     /* 0 */

布尔真值与 C89 / C99

标准 布尔表示
C89 无原生布尔类型；0 = 假，任意非 0 = 真
C99 新增 _Bool；<stdbool.h> 提供 bool、true、false 
#include <stdbool.h>

bool ok = (x > 0);   /* 底层仍是整数语义：true→1, false→0 */

关系运算 始终返回 int 的 0/1，与是否使用 bool 类型无关。

⚠️ = 与 == 混淆（高频错误）

if (x = 5)    /* 合法语法：赋值，x 变为 5，表达式值 5 → 永远“真” */
if (x == 5)   /* 正确：判断 x 是否等于 5 */
  • = 是 赋值，表达式结果是 右值
  • == 是 相等比较，结果是 0 或 1
  • 部分编译器对 if (x = 5) 会警告；工程上可用 Yoda 写法 if (5 == x) 防手滑（习惯因人而异）

2. 逻辑运算符（拼接多个条件）

运算符 名称 目数
&& 逻辑与 二元
\|\| 逻辑或 二元
! 逻辑非 一元

统一真假标准

  • 0 = 假
  • 所有非 0 整数、非空指针等 = 真

指针单独作条件时：NULL / 空指针 = 假，有效地址 = 真（不必写 != NULL，但显式写法更清晰）。

! 逻辑非

!0;     /* 1 —— 假变真 */
!100;   /* 0 —— 真变假 */
!!x;    /* 归一化为 0/1（少见，了解即可） */

&& 逻辑与 —— 左假短路

规则：左操作数为假（0）时，整体为假，右操作数不再求值、不执行。

A && B
├── A == 0  →  结果 0，B 不算
└── A != 0  →  才计算 B，结果由 B 真假决定

考题：

if (i && f())
/* i 为 0：f() 根本不调用
   i 非 0：才调用 f()，整体真假看 f() 返回值 */

空指针安全（短路是标准写法）：

if (p != NULL && p->len > 0)
/* p 为 NULL 时左边为假 → 不会执行 p->len，避免段错误 */

1.6 数组 中 c >= '0' && c <= '9' 同理：先排除非法字符，再参与运算。

|| 逻辑或 —— 左真短路

规则：左操作数为真（非 0）时，整体为真，右操作数不再求值、不执行。

A || B
├── A != 0  →  结果 1，B 不算
└── A == 0  →  才计算 B，结果由 B 决定

考题：

if (!i || g())
/* i == 0：!i 为真，整体为真，g() 不调用
   i != 0：!i 为假，才调用 g() */

短路与副作用

短路保证：右侧带副作用的表达式可能被跳过 —— 既是安全特性，也是陷阱：

if (ptr && *ptr++)   /* ptr 为 NULL 时 *ptr++ 不执行 */
if (lock() || retry())  /* lock 成功则 retry 不调 —— 锁顺序要刻意设计 */

内核 / 并发代码里，&& / || 左右顺序若牵涉 锁、引用计数、IO，须按依赖关系排列，不能假设两边总会执行。

3. 本节涉及优先级（完整表见 2.13）

从高到低（本节相关部分）：

!          （逻辑非，一元）
> < >= <=  （关系）
== !=      （相等）
&&         （逻辑与）
||         （逻辑或）

a > 0 && b < 10 || !c
/* 等价于 */ ((a > 0) && (b < 10)) || (!c)

复杂条件 建议加括号 提升可读性，不必死记全表（2.13 汇总）。

4. 关系 vs 逻辑：结果仍是 0/1

int r1 = (3 < 5);           /* 1 */
int r2 = (1 && 0);          /* 0 */
int r3 = (10 > 5 || 0);     /* 1 */

可赋给 int、bool（C99），也可直接用于 if / while / for 条件。

三、易混点与高频考点

# 要点
1 比较运算 只返回 0/1；C89 无 true/false 关键字
2 && 左假短路、|| 左真短路 —— 右侧函数、指针访问可能被跳过
3 p != NULL && p->field 是判空标准模式
4 = 与 == 混淆导致逻辑错误或“永远为真”的 if
5 指针、整数都能当条件：0/NULL 假，其余真
6 短路 ≠ 优先级：先按优先级分组，再在组内短路

HFT / 底层提示

  • 热路径条件尽量 无函数调用，或把可能失败的检查放 && 左侧（少做无用计算）
  • 解析协议字段：if (len >= HDR_SZ && buf != NULL) —— 先长度再指针，或先指针再访问，按依赖排列
  • 不要用 if (ptr) 与 if (ptr != NULL) 混用风格于同一模块；团队统一即可
  • 布尔返回值函数配合短路：if (valid_pkt(hdr) && parse_body(hdr))

代码自测

题目 1： 以下代码为什么不会编译报错但逻辑错误？

if (0 < x < 10) { ... }  // 本意：x 在 0 到 10 之间
参考答案

C 不支持链式比较。0 < x < 10 等价于 (0 < x) < 10——先算 0 < x（0 或 1），再与 10 比较，结果恒为 1（true）。正确写法：if (x > 0 && x < 10)。这是数学符号到 C 代码的常见翻译错误。

2.7

类型转换

本节讲什么

讲解 C 两种类型转换机制：隐式自动转换（整型提升 integral promotion、常规算术转换 usual arithmetic conversions）与 显式强制转换 (类型)表达式。本节是 OS / 驱动 / HFT 最容易出 隐蔽 bug 的章节 —— 无运行时报错，只会逻辑错乱、死循环、内存访问异常。

前置：2.2 类型与长度、2.4 声明、2.6 关系/逻辑运算符（比较时转换坑最多）、2.2.3 stdint.h。
后续：ch05 指针与整数互转；C 陷阱 7.1 可移植性；网络字节序、溢出检测。

要点

一、隐式转换（编译器自动，无需写代码）

1. 整型提升 Integral Promotion

规则：宽度 小于 int 的整数类型（char、short、unsigned char、uint8_t、uint16_t 等）在参与大多数运算、比较、函数传参（默认提升）前，先 提升为 int（若 int 装不下 unsigned int 的全部值，则提升为 unsigned int —— 少见）。

触发场景：+ - * / %、比较 > < ==、位运算 & | ^、~、!、?: 等。

uint8_t a = 200;
uint8_t b = 100;
int res = a - b;   /* a、b 先提升为 int 再减 → res == 100 */

若 不提升，uint8_t 减法会在 8 位模 256 下溢；提升为 int 后按有符号整型算，结果符合直觉。

char c = 'A';
int x = c + 1;     /* c 提升为 int，再与 int 运算 */

2. 常规算术转换 Usual Arithmetic Conversions

两个 不同类型 的操作数做 二元算术或比较（+ - * / %、< > <= >= == != 等）时，编译器先把两边对齐到 公共类型（common type），再运算。

对齐顺序（简化记忆）：

优先级 规则
1 浮点优先：任一侧为 float/double/long double → 另一侧也转浮点（float 常升为 double）
2 整数：按 宽度 + 符号类别 对齐到能容纳两者值的类型
3 同符号：窄 → 宽（int → long → long long）
4 一有 unsigned、一有 signed：signed 按 unsigned 的位模式重新解释（本节最大坑） 
int i = 3;
double d = 2.5;
double r = i + d;    /* i 隐式转为 double */

3. 窄 → 宽 vs 宽 → 窄（小转大 vs 大转小）

方向 典型例子 结果
窄 → 宽（小转大） float → double；int → long；short → int 一般安全，有效位通常 保留
宽 → 窄（大转小） double → float；long → int；int → short 可能精度损失 —— 截断低位有效数字；超出目标范围 → 溢出/未定义 
float  f = 3.14f;
double d = f;          /* 小转大：OK，f 精确装入 double */

double x = 1.23456789012345;
float  y = (float)x;   /* 大转小：float 有效位少，低位被截断 */

long   L = 10000000000L;
int    n = (int)L;     /* 大转小：若 int 装不下 → 实现定义/溢出 */

return 时同样适用（4.1、4.2）：return 表达式 隐式转换 为函数声明的返回类型 —— 返回类型比表达式 窄 时，与赋值窄化规则一致，可能丢精度。

int truncate_pi(void)
{
    return 3.14;       /* double → int：截断为 3 */
}

float narrow(void)
{
    double x = 1.23456789012345;
    return x;          /* double → float：低位有效数字可能丢失 */
}

工程原则：函数返回类型与 return 表达式 尽量同宽；必须窄化时 显式 cast 并注释意图，或先检查范围。

3.1 浮点数 → int：砍掉小数，不是四舍五入

浮点转整型 = 把 小数部分直接砍掉，只留 整数部分（C 标准：向零截断 truncate toward zero）。

浮点值 转成 int 说明
3.9f 3 小数 .9 砍掉，不是 四舍五入成 4
-2.7f -2 负数的 .7 也砍掉，不是 -3
3.0f 3 无小数部分 
float a = 3.9f;
float b = -2.7f;
int   i = (int)a;      /* 3 */
int   j = (int)b;      /* -2，不是 -3 */

int k = 3.14;          /* 赋值/return 隐式转换：同样截断 → 3 */
要点 说明
规则 向零取整 —— 正数往下砍、负数往上砍（朝 0 方向）
≠ 四舍五入 要四舍五入用 round()、lround()（<math.h>）等
溢出 浮点值 超过 int 能表示的范围 → 结果 不可控（实现定义 / 未定义行为）
隐式发生 int x = 3.9f;、return 3.14;（int 函数）、int 形参传 float 实参 
/* 危险：超大浮点转 int */
float huge = 1e20f;
int bad = (int)huge;   /* 超出 INT_MAX → 不可控 */

/* 若要四舍五入 */
#include <math.h>
int rounded = (int)roundf(3.9f);   /* 4 */

见 4.2 返回非整型；return 3.14 给 int 函数是同一规则。

4. 有符号 / 无符号混合 —— 致命坑（必考）

当 signed 与 unsigned 同级宽度 比较或运算时，signed 操作数转为 unsigned，按 无符号 规则解释位模式。

经典拆解：

unsigned u = 1;
int i = -1;

if (u < i)   /* 常为真（1）—— 与直觉相反！ */
    ...

执行流程：

  1. i == -1 与 unsigned 运算 → i 转为 unsigned
  2. -1 的补码全 1 → 解释为 unsigned 时约为 UINT_MAX
  3. 1 < UINT_MAX → 真
直觉 实际（常见 32 位）
-1 < 1 (unsigned)-1 是巨大正数，1 < 巨大正数 为真

衍生：无符号死循环

unsigned int n = 10;
for (; n >= 0; n--)   /* 死循环：unsigned 永远 ≥ 0 */
    ...

n-- 到 0 后再减 → 按模 (2^{32}) 回绕到 UINT_MAX，条件 n >= 0 恒真。

安全写法：

for (int n = 10; n >= 0; --n) { ... }

/* 或 */
for (unsigned n = 10; n > 0; --n) { ... }
/* 单独处理 n == 0 */

协议字段比较（wire 全是无符号）：

uint16_t pkt_len = read_u16(buf);
int max = 1500;
if (pkt_len > max)   /* max 转为 uint16_t/unsigned，负的 max 变巨大正数 */

→ 比较前 统一类型：(int)pkt_len > max 或 (uint16_t)max 并保证语义正确。

二、显式强制转换 (目标类型)表达式

1. 本质

内存中的二进制位通常不变（合法转换前提下），只改变编译器对同一段位的解读方式。

效果 说明
截断 宽 → 窄：丢弃高位；uint32_t → uint8_t 只留低 8 位
符号翻转 同宽度有符号 ↔ 无符号：位不变，正负判断变
整数 ↔ 指针 地址与整数互转；不改变硬件地址，只改类型系统（ch05、uintptr_t）
浮点 ↔ 整数 可能舍入、截断小数；超大整数转浮点可能丢精度 
uint32_t raw = 0xFFFFFFFFu;
int val = (int)raw;        /* 位不变，解读为 -1（补码） */

double x = 3.9;
int n = (int)x;            /* 3：砍小数，非四舍五入 */

float neg = -2.7f;
int m = (int)neg;          /* -2，不是 -3 */

void *p = (void *)(uintptr_t)0xFFFF800012340000ull;  /* 寄存器映射 */

注意：非法转换（如错误对齐的指针强转）是 未定义行为 UB，编译器不报错。

2. 典型使用场景

场景 示例
规避隐式 signed/unsigned 陷阱 (int)u 与 i 比较
寄存器 / DMA 地址 (volatile uint32_t *)REG_BASE
指针与整数互转 (uintptr_t)p、(void *)addr
浮点转整数 (int)price_tick
消除警告、匹配 API (size_t)len

工程原则：跨符号、跨宽度运算 主动显式 cast，不依赖编译器隐式规则。

三、底层工程场景（OS / 驱动 / HFT）

场景 风险
硬件寄存器 uint8_t/uint32_t 与 int 混算触发提升与 unsigned 规则
DMA 物理地址 uint64_t 强转指针；须 uintptr_t + 对齐
网络报文解析 字段全 uint16_t/uint32_t，与 int 比较逻辑反转
HFT 数值 float/double/int64_t 混用，隐式转 double 或精度丢失
循环下标 size_t（无符号）与 int（有符号）比较 → signed 变 unsigned

工程规范建议

  1. 优先 stdint.h 定宽类型（uint32_t、int64_t），少用裸 int/long 表示协议与硬件（2.2）
  2. 禁止 无符号与有符号 直接比较；统一 cast 到同一符号类别
  3. 寄存器 / 地址 必须显式 cast + volatile（按需）；用 uintptr_t/intptr_t，不用 unsigned long 冒充（2.2.3 stdint.h）
  4. 怀疑转换时 打印十六进制 + 两侧类型（PRIu32、PRId32）
/* 寄存器读改写 —— 显式宽度 + volatile */
volatile uint32_t *reg = (volatile uint32_t *)(uintptr_t)0x40001000u;
uint32_t v = *reg;
*reg = (v | 0x1u) & ~0x2u;

/* 安全比较 */
int32_t delta = (int32_t)a - (int32_t)b;   /* 先统一到够宽的 signed */

四、隐式 vs 显式对照

隐式转换 显式强制转换
写法 无，编译器自动 (type)expr
可见性 易忽略，隐蔽 bug 意图明确
典型场景 整型提升、算术对齐 寄存器、指针、刻意截断
底层建议 少依赖 主动写

五、易混点与高频考点

# 要点
1 短整型参与运算前 几乎必先整型提升为 int
2 signed + unsigned 混合 → signed 转 unsigned，比较可 逻辑颠倒
3 强制转换 不改变位模式（合法转换下），只改 类型解释

5 浮点与整数运算 → 整数 升为浮点
6 浮点→int：向零截断（3.9f→3，-2.7f→-2），非四舍五入；超范围 溢出
7 窄→宽 一般安全；宽→窄（含 return）→ 截断/溢出
8 截断高位、符号变化、指针强转 —— 无运行时检查
9 2.6 里每个比较都可能先经历本节规则

HFT / 内核提示

  • 订单簿价格差：int64_t 全程，避免 int 与 uint32_t 混比
  • DPDK mbuf 长度：uint16_t data_len 与常量比较用同类型或显式 (unsigned) 两侧
  • 内核 size_t 与 int 比较是经典 bug 源；用 ssize_t 或 cast 一致

题目 1： 以下代码输出什么？为什么？

参考答案

2.8

自增运算符与自减运算符

本节讲什么

讲解一元运算符 ++（自增）、--（自减） 的两种写法：前置 ++i / --i 与 后置 i++ / i--。核心区分二者 表达式返回值 与 修改变量的时机；并强调 同一表达式内多次修改同一变量 属于 未定义行为（UB） —— 高频面试与生产禁区。

前置：2.4 声明、2.10 赋值；1.3 for 语句 循环步进。
后续：ch05 指针 p++；2.13 求值次序；C 陷阱表达式专题。

要点

一、前置 vs 后置对照（设 i 初值为 3）

写法 执行逻辑 表达式整体结果 运算后 i
++i 前置自增 ① i 先 +1
② 返回 新 i		 加完之后的值 i = i + 1
i++ 后置自增 ① 先取 旧 i 作结果
② i 再 +1		 自增 之前 的原值 i = i + 1
--i 前置自减 ① i 先 −1
② 返回新值		 减完之后的值 i = i - 1
i-- 后置自减 ① 先取旧值作结果
② i 再 −1		 自减 之前 的原值 i = i - 1

分步拆解

int i = 3;
int a = ++i;
/* ① i = i + 1  →  i = 4
   ② 表达式值为 4，赋给 a
   结果：a = 4，i = 4 */

int b = i++;
/* ① 表达式值为 i 当前值 4
   ② b = 4
   ③ i = i + 1  →  i = 5
   结果：b = 4，i = 5 */

自减完全对称：

int j = 5;
int c = --j;   /* c=4, j=4 */
int d = j--;   /* d=4, j=3 */

二、单独使用时：前置与后置无差别

若 ++i / i++ 不参与 其他运算、不赋值、不嵌套，只是 单独一条语句，效果相同 —— 变量都 ±1：

i++;
++i;
/* 单独写，最终 i 都 +1，无差异 */

典型场景：for 循环步进（1.3）

for (i = 0; i < n; i++)    /* 后置 */
for (i = 0; i < n; ++i)    /* 前置 —— 此处等价 */

循环第三表达式只求 副作用（让 i 前进），不关心表达式 返回值，故 i++ 与 ++i 等价 —— 判断逻辑与执行次数都不变（见 3.5 §4）。

例外：while 条件里的 ++ / --（与 for 步进不同）

for 的第三部分在 循环体之后 才执行，且返回值 不参与判断；while (i++ < n) 却把自增塞进 条件表达式 —— 直接改变判断时的 i：

int i = 9;
while (i++ < 10)   /* 用 9 比，能进体；i 变 10 */
while (++i < 10)   /* 先变 10，10<10 假，进不去 */

int j = 0;
while (j++ < 10);   /* 结束时 j == 11 */
while (++j < 10);   /* 结束时 j == 10，次数也不同 */

详见 3.5 while 与 for §2–§4。工程上更推荐 i < n + 体内 i++ 或标准 for，少在 while 条件里写自增。

三、同一表达式多次修改同一变量 → UB（严禁）

C 标准 不规定 同一表达式内对同一对象的多次修改与读取的求值顺序；不同编译器、优化级别结果可完全不同。生产代码一律禁止。

经典陷阱：

int i = 0;
a[i++] = i;   /* UB：同时读/写 i，顺序未定义 */

同类违规：

printf("%d %d", i++, ++i);   /* UB */
int x = i++ + ++i;           /* UB */
a[i] = i++;                  /* UB */
为何危险 说明
无标准顺序 编译器可任意安排子表达式求值
优化干扰 -O2 可能与 -O0 结果不同
无诊断 常 编译通过，运行才暴露

安全写法：拆成多条语句，一次表达式只改一次：

int idx = i;
i++;
a[idx] = i;

/* 或 */
a[i] = i + 1;
i++;

详见 2.13：优先级 ≠ 求值顺序；&& || ?: 有序，多数二元运算左右次序 不保证。

四、适用范围（C 语言限制）

++ / -- 只能作用于 可修改的左值（modifiable lvalue）：

允许 不允许
整型变量：char short int long stdint 定宽 常量、++10
指针变量（ch05：p++ 按所指类型跨度偏移） 纯表达式：(i+1)++
字符串字面量、"abc"++ 
++10;       /* 非法 */
(i + 1)++;  /* 非法：非左值 */

浮点：C 标准 不允许 double d; d++;（与 C++ 不同）。

五、C 与 C++ 的区别

C C++
对象 仅内置算术类型、指针 可对类、迭代器 重载 ++
前置 vs 后置性能 无差别（无重载） 后置常需 临时保存旧值，前置迭代器惯例更高效
工程习惯 for 里 i++/++i 随意 自定义类型优先 ++it

学 C 时勿把 C++ 的「前置更高效」套到裸 int 循环上 —— 对 int 二者生成相同机器码。

六、常见正确用法

/* 数组遍历 */

    buf[k] = 0;

/* 前置：需要「新值」参与后续表达式 */

2.9

按位运算符

本节讲什么

讲解仅对 整数类型 生效的 6 个按位运算符：& | ^ ~ << >>。这是硬件寄存器、OS 页表、DPDK 报文标记、裸机系统的 核心工具；与 2.7 类型转换 联动时，整型提升、有符号/无符号差异会带来大量隐蔽坑。

前置：2.7 类型转换、2.2 定宽类型。
后续：ch05 地址与掩码；内核 PTE、DPDK rte_* flags；网络字节序 htonl。

要点

一、6 个按位运算符对照

运算符 名称 核心用途
& 二元 按位与 掩码 提取、清除 特定位；保留指定 bit
\| 二元 按位或 置 1（打开指定 bit）
^ 二元 按位异或 翻转 指定 bit；两数交换（少用）
~ 一元 按位取反 全 bit 0↔1；配合 & 清位
<< 二元 左移 低位补 0；等价 × (2^n)
>> 二元 右移 逻辑/算术右移；等价 ÷ (2^n)（有符号负数有坑）

限制：操作数须为 整型（char/short/int/long/stdint 定宽）；不能 用于 float/double。

uint32_t x = 0x0F;
uint32_t y = x & 0x03;   /* 0x03 */
uint32_t z = x | 0xF0;   /* 0xFF */
uint32_t w = x ^ 0x0F;   /* 0x00 */
uint32_t t = ~0u;        /* 全 1（注意加 u 避免 ~0 为有符号全 1） */

二、四大标准位操作模板（工程高频）

设 MASK_ENABLE = 0x01、MASK_READY = 0x02（通常 #define 或 enum 单 bit）：

1. 置位（目标 bit → 1，其余不变）

flags |= MASK_ENABLE;

2. 清位（目标 bit → 0，其余不变）

flags &= ~MASK_ENABLE;
/* ~MASK 后：目标位为 0，其余为 1；& 保留其它位 */

3. 检测某一位是否为 1

if (flags & MASK_READY)
    /* 为真：该位已置 1；勿写 flags & MASK == MASK 除非刻意 */

4. 提取指定区间 bit（如高 8 位）

uint16_t word = 0x1234;
uint8_t high8 = (word >> 8) & 0xFF;   /* 0x12 */
uint8_t low8  = word & 0xFF;          /* 0x34 */

多 bit 掩码：

#define FIELD_MASK  0xF00u
#define FIELD_SHIFT 8
uint32_t field = (reg & FIELD_MASK) >> FIELD_SHIFT;

三、移位规则与未定义行为（UB）

1. 左移 <<

  • 低位 补 0
  • 语义上相当于 × (2^{\text{shift}})（无溢出前提下）
  • 风险：移出位宽的高位 丢弃，无警告
  • UB（标准禁止，结果不可预测）：
  • 移位量 ≥ 操作数类型宽度（如 32 位 x << 32）
  • 移位量为 负数
  • 左移 有符号负数 或移入符号位（C99+ 规则细，安全做法：用无符号）
uint32_t x = 1u;
x << 31;    /* OK */
x << 32;    /* UB */
x << -1;    /* UB */

2. 右移 >> —— 逻辑 vs 算术（重点）

操作数类型 常见行为 可移植性
无符号 unsigned / uint32_t 逻辑右移：高位补 0 标准保证
有符号非负 通常逻辑右移 较安全
有符号负数 算术右移：高位补 符号位（常见） 实现定义（C 标准不强制唯一） 
int i = -1;        /* 补码：全 1 */
i >> 1;            /* 多数平台 → -1（补 1），实现定义 */

unsigned u = 0x80000000u;
u >> 1;            /* 逻辑右移 → 0x40000000，高位补 0 */

工程建议：寄存器、协议、位域 一律 uint32_t / uint8_t，右移行为确定。

3. 移位与赋值

flags <<= 1;       /* 左移 1，等价 flags *= 2（无符号语义） */
val >>= 3;         /* 右移 3，等价 val /= 8（无符号确定） */

四、与 2.7 类型转换联动坑点

1. 整型提升 + ~ 截断

char/short/uint8_t 参与 ~、&、| 前先 提升为 int：

uint8_t flags = 0x0F;
flags &= ~0x01;    /* ~0x01 在 int 上为 0xFFFFFFFE，再 & 后赋回 uint8_t 截断 → OK */

uint8_t v = 0x80;
uint8_t r = ~v;    /* ~v 先提升：~0x80 → 0xFFFFFF7F，截断为 uint8_t → 0x7F */

清位模板 对窄类型仍安全，因 & 后只保留低 8 位；但 ~ 单独赋给窄类型 要小心预期。

2. 有符号 / 无符号混合位运算

二元 & | ^ 遵循 usual arithmetic conversions（2.7）：

int mask = 0xFF;
unsigned flags = 0x100;
flags & mask;      /* mask 可能转为 unsigned，语义依宽度而定 */

规范：位操作数 统一无符号定宽：

uint32_t flags = ...;
flags &= (uint32_t)~MASK;

3. 有符号数左移

int x = 1;
x << 31;           /* 可能 UB（移入符号位） */
uint32_t y = 1u;
y << 31;           /* OK → 0x80000000 */

4. 比较位标志时用 & 结果当布尔

if (flags & MASK)          /* OK：非 0 为真 */
if ((flags & MASK) == MASK) /* 检测「所有 MASK 位都置 1」 */

勿与 2.6 混淆：& 是 位与，&& 是 逻辑与。

五、异或与实用技巧

/* 翻转指定位 */
flags ^= MASK_TOGGLE;

/* 交换两整数（无临时变量，面试题，生产少用） */
a ^= b; b ^= a; a ^= b;

/* 判奇偶 */
if (n & 1)   /* 最低位为 1 → 奇 */

/* 对齐：向上取 2 的幂边界（无分支常用技巧，另章展开） */

2.10

赋值运算符与表达式

本节讲什么

讲解基础赋值 = 与全套 复合赋值 运算符。核心两点：赋值本身是有返回值的完整表达式；a op= b 与 a = a op b 不完全等价（左侧只求值一次）。并梳理优先级、工程易错陷阱，关联 2.7 类型转换 隐式规则。

前置：2.7 类型转换、2.8 自增、2.9 按位运算、2.6 = vs ==。
后续：2.11 条件表达式、2.12 逗号、2.13 优先级。

要点

一、运算符分类

1. 基础赋值 =

把 右侧 运算结果存入 左侧可修改左值：

int x;
x = 42;
buf[i] = c;
*p = val;

2. 复合赋值（算术 + 位运算全套）

类别 运算符
算术 += -= *= /= %=
位运算（内核/寄存器高频） &= \|= ^= <<= >>=

统一形式：a OP= b

逻辑近似：a = a OP b —— 但关键区别是左侧 a 只求值一次。

/* 复合赋值：arr 的下标表达式只求值一次 */
arr[i++] |= 1;

/* 若手写展开（错误示范） */
arr[i++] = arr[i++] | 1;   /* i++ 执行两次 → 下标错乱 */
写法 左侧求值次数
a += b 1 次
a = a + b 1 次（a 是简单变量时）
arr[i++] op= x i++ 1 次
arr[i++] = arr[i++] op x i++ 2 次 → 危险

底层改寄存器、mbuf 标记、位域大量使用：

reg |= BIT(3);
flags &= ~MASK_ERR;
cnt += pkt_len;

二、赋值表达式的核心特性

1. 赋值有返回值

整个 a = b 表达式的值 = 赋值完成后 a 的值（不是 b 的「旧」语义上的独立副本概念，而是左值当前内容）。

int x, y;
y = (x = 5) + 1;   /* x=5，表达式 x=5 值为 5，y=6 */

2. 链式赋值（右结合）

int a, b, c;
a = b = c = 10;
/* 结合顺序：a = (b = (c = 10))
   ① c = 10，表达式值 10
   ② b = 10
   ③ a = 10 */

可读性：生产代码链式过长时建议拆开，调试更直观。

三、优先级与结合性

项 规则
优先级 所有赋值运算符 极低 —— 低于算术、移位、关系、位运算、逻辑；仅高于逗号 ,（2.13）
结合性 右结合 → 支持 a = b = c 
int x = 2 + 3;        /* 先 2+3=5，再 x=5 → x = (2+3) */
flags |= val << 2;      /* 先 val<<2，再 |= → flags |= (val << 2) */
a += b * c;             /* 先 b*c，再 += → a += (b * c) */

记忆：「先算右边表达式里的运算，最后再赋给左边」。

四、高频易错坑

坑 1：条件里误写 = 而非 ==

if (x = y)    /* 合法：赋值，再判 x 是否非 0 —— 经典 bug */
if (x == y)   /* 正确：相等比较 */
现象 说明
if (x = 0) x 被清零，条件为假
if (x = func()) 故意写法：赋值并检测成功；须注释说明

工程规范：条件中 避免赋值；若必须，写 if ((ptr = get()) != NULL) 并加括号/注释。

与 2.6 的 Yoda 写法 if (5 == x) 可防手滑。

坑 2：复合赋值触发隐式类型转换（联动 2.7）

a += b 等价于 a = a + b，完整经历 usual arithmetic conversions：

unsigned u = 10;
int i = -20;
u += i;   /* i 转为 unsigned；结果巨大正数，非 -10 */

uint8_t a = 200;
a += 100; /* 提升为 int 运算，再截断赋回 uint8_t → 44 */

规范：位标志用 同类型无符号；混合符号先 显式 cast 再复合赋值。

坑 3：把复合赋值当「保证求值一次」的万能药

左侧若是 宏 或 函数返回引用，op= 只求值一次仍可能因宏展开踩坑（1.4 宏）。复杂左值优先 临时变量：

volatile uint32_t *reg = ...;
uint32_t v = *reg;
v |= MASK;
*reg = v;

坑 4：浮点复合赋值精度

f += 0.1 累积舍入误差；金融/HFT 计数用 整数 tick + int64_t，少用 double +=。

2.11

条件表达式

本节讲什么

讲解 C 唯一的三元运算符 条件 ? 表达式2 : 表达式3（?:），用单行实现简易分支逻辑。核心特性：分支短路求值（只算一支）、两分支结果经 usual arithmetic conversions（2.7）对齐为公共类型。

前置：2.6 逻辑/关系运算、2.7 类型转换、短路概念（&& ||）。
后续：2.12 逗号、2.13 优先级。

要点

一、完整执行规则

语法：expr1 ? expr2 : expr3

步骤 行为
1 先计算 expr1（条件）
2 若 expr1 != 0（真）：只求值并返回 expr2，expr3 完全不计算
3 若 expr1 == 0（假）：只求值并返回 expr3，expr2 完全不计算

与 && / || 同属 短路机制 —— 未选中的分支可含函数调用、指针解引用，且 不会执行。

短路验证：

int a = 1;
a ? printf("执行2\n") : printf("执行3\n");
/* a 为真 → 只打印「执行2」，第二个 printf 不运行 */

if (p != NULL ? p->len > 0 : 0)
/* p 为 NULL 时不会解引用 p->len —— 但勿滥用，if-else 更清晰 */

二、最常用极简场景

1. 取最大 / 最小值

int max = a > b ? a : b;
int min = a < b ? a : b;

2. 简易绝对值（int 雏形，注意 INT_MIN 溢出）

int abs_x = x > 0 ? x : -x;

3. printf 格式化分支

printf("数字：%s\n", x >= 0 ? "正数" : "负数");

4. 指针 / 默认值

const char *msg = err ? err_msg : "ok";
size_t n = count ? count : DEFAULT_SZ;

5. 内核 / DPDK 宏风格

#define MIN(a, b) ((a) < (b) ? (a) : (b))
/* 宏内 ?: 极常见；参数求值次数仍受 ?: 短路保护（每支只求值一次） */

三、类型转换规则（联动 2.7）

expr2 与 expr3 类型不同时，对 两支结果 做 usual arithmetic conversions，整个 ?: 表达式的类型为对齐后的 公共类型。

unsigned u = 10;
int i = -1;
/* 条件为 1（真）→ 取 i；但公共类型含 unsigned 时 i 转 unsigned */
unsigned res = 1 ? i : u;   /* i=-1 → 巨大 unsigned */
场景 风险
signed + unsigned 两支 signed 支可能按 unsigned 解释
窄类型 + 宽类型 提升为宽类型
指针两支类型不完全兼容 须指向 兼容 类型，否则编译错误

安全写法：两支 显式 cast 到同一类型：

int64_t v = cond ? (int64_t)a : (int64_t)b;
uint32_t x = ok ? (uint32_t)val : 0u;

指针两支：

void *p = cond ? (void *)pa : (void *)pb;  /* 须可安全转换 */

四、优先级与结合性

项 规则
优先级 很低 —— 低于赋值、算术、移位、关系、位运算、逻辑 && \|\|；高于逗号 ,（2.13）
结合性 右结合 → 嵌套时从右分组 
a ? b : c ? d : e
/* 等价于 */ a ? b : (c ? d : e)

嵌套示例（可读性差，慎用）：

int grade = score >= 90 ? 'A' : score >= 60 ? 'B' : 'C';
/* 等价于 score >= 90 ? 'A' : (score >= 60 ? 'B' : 'C') */

加括号澄清：

int m = (a > b) ? a : (c > d ? c : d);

与赋值混用：

x = cond ? y : z;   /* 等价 x = (cond ? y : z)，因 ?: 低于 = */

五、代码风格规范

说明
优点 一行替代简单 if-else；宏、内联取值、日志紧凑
缺点 多层嵌套晦涩；调试单步不便；分支含副作用时难读
建议 单层 ?: 可直接用
超过两层 嵌套改 if-else
复杂逻辑 不要 塞进 printf、宏实参
分支勿写过长表达式 —— 提取临时变量 
/* 不推荐 */
result = a > b ? (foo() + bar()) : (baz() ? qux() : 0);

/* 推荐 */
if (a > b)
    result = foo() + bar();
else if (baz())
    result = qux();
else
    result = 0;

六、与 if-else 语句对比

?: 表达式 if-else 语句
性质 表达式，有值 语句，无统一“表达式值”
用途 赋值、实参、返回值内嵌 多语句分支、副作用
短路 仅一支求值 仅执行一支
可读性 简单场景好 复杂场景更好 
/* 表达式语境 —— ?: 合适 */
return n > 0 ? n : 0;

/* 多语句 —— if-else */
if (n > 0) {
    log("positive");
    return n;
} else {
    return 0;
}

七、易混点

  1. ?: 是表达式，可嵌在 =、return、printf 实参中；不是语句
  2. 条件 expr1 总会求值；只有 expr2/expr3 二选一
  3. 两支 类型须能对齐；混 signed/unsigned 见 2.7 坑
  4. 右结合：a ? b : c ? d : e 从 右 挂 ?:
  5. ?: 优先级 低于 && || —— 条件常可直接写关系表达式
/* OK */
x = a && b ? y : z;   /* (a && b) ? y : z */

/* 易读性：加括号 */
x = (a && b) ? y : z;

HFT / 底层提示

  • 热路径取 min/max：latency = t1 < t2 ? t1 : t2; 常编译为 条件传送（cmov），无分支
  • 日志级别：if (lvl) ? log(...) : (void)0 在宏里常见；注意 短路 避免昂贵 printf
  • 协议字段默认值：len = hdr->len ? hdr->len : DEFAULT_MTU;
  • 避免嵌套 ?: 选三种以上状态 —— 用 switch 或查表

2.12

逗号运算符

本节讲什么

讲解逗号运算符 , 构成的 逗号表达式：从左到右 依次求值、整体值为最右侧 表达式、全场最低优先级。重点区分 「运算符逗号」 与 「函数参数分隔逗号」 两种完全不同的语义；给出规范使用场景与禁用滥用场景；GNU 语句表达式 ({ ... }) 后置到 Embedded ch06 展开。

前置：2.8 自增（副作用）、2.10 赋值、2.11 三元（优先级对比）。
后续：2.13 优先级总表；1.4 宏副作用；GNU 语句表达式。

要点

一、逗号表达式基础语法与规则

语法：expr1 , expr2 , expr3 , … , exprN

规则 说明
求值顺序 严格从左到右；前一段副作用（自增、赋值、函数调用）全部生效后，再算下一段
表达式值 最右侧 exprN 的结果
优先级 全场最低，比赋值 =、三元 ?: 都低 —— 不加括号极易出错

示例拆解

int a = (1 + 2, 3 + 4, 5);
/* ① 1+2 → 3，丢弃
   ② 3+4 → 7，丢弃
   ③ 5 作为整个逗号表达式的值
   a = 5 */

无括号错误示范（优先级坑）

int a = 1 + 2, 3 + 4;

不是 a = (1+2, 3+4)！等价于：

int a = 1 + 2;   /* 声明并初始化 a = 3 */
/* 3 + 4 是独立表达式语句语境下的错误/无意义片段 —— 实际是声明符里的逗号分隔多个声明 */

更准确地说，int a = 1+2, 3+4 在语法上会被解析为 用逗号分隔的两个声明（第二个 3+4 非法），而非逗号表达式赋值。教训：要对逗号表达式赋值必须加括号：

int a = (1 + 2, 5);   /* OK：a = 5 */

int x = 0, y = 0;
x = (x++, y += 2, x + y);
/* ① x++ → x=1
   ② y+=2 → y=2
   ③ x+y=3 作为整个值 → x=3 */

二、唯一规范推荐场景：for 循环头部

for 的 初始化、步进 部分允许逗号表达式，同时 操作多个变量 —— 标准、可读、常见写法：

for (i = 0, j = n - 1; i < j; i++, j--)
    swap(&arr[i], &arr[j]);
for 部分 逗号角色
i = 0, j = n - 1 逗号运算符（初始化段）
i < j 条件；分号分隔，非逗号表达式
i++, j-- 逗号运算符（步进段）

与 1.3 for 语句 衔接。

for (int i = 0, j = 0; i < n; ++i, j += 2)  /* C99：声明里的逗号分隔变量，非逗号表达式 */

注意：for (int i = 0, j = 0; …) 中第一个逗号是 声明符列表逗号，不是本节「逗号运算符」。

三、关键区分：两种逗号完全不是一回事

1. 逗号运算符（构成逗号表达式）

出现在：括号内、for 三段中的初始化/步进、switch 中某些语境：

int x = (a++, b);           /* 括号内：逗号运算符 */
for (i = 0, k = 0; ; i++, k++)  /* for 内：逗号运算符 */

保证：左 → 右依次求值；值为 最右。

2. 函数参数分隔逗号（仅分隔，非逗号表达式）

函数调用 () 内的逗号 只分隔实参，不 构成一个逗号表达式：

func(a++, b++);
逗号运算符 函数实参逗号
语义 一个表达式，值为最右 分隔多个独立实参
求值顺序 保证 左 → 右 C17 前 不保证 实参求值顺序
典型风险 滥用可读性 func(i++, i++) → UB（2.8） 
printf("%d %d", i++, ++i);   /* 实参逗号：顺序未定义 → UB */

不要 把函数实参逗号当成「从左到右执行」的逗号运算符。

3. 其它「看起来像逗号」的逗号

语境 逗号类型
int a, b, c; 声明符分隔
f(a, b) 实参分隔
(a, b) 逗号运算符
for (a=0, b=0; …; a++, b++) 逗号运算符（初始化/步进）
初始化列表 {1, 2, 3} 初始化器分隔（C99 指定初始化另论）

四、工程规范：禁止滥用逗号表达式

x = (y++, z);        /* 可读性极差 */
if (a = foo(), a < 0) /* 条件里藏赋值+逗号 —— 难维护 */
return (cleanup(), err);  /* 除非团队规范明确允许 */

负面问题：

  1. 多段逻辑挤一行，调试器难以对 中间段 单独断点
  2. 与函数参数逗号 视觉混淆
  3. 隐藏副作用，Code Review 易漏

推荐：用分号拆成多条语句：

y++;
x = z;

a = foo();
if (a < 0)
    ...

例外：for 头多变量、少量内核惯用宏（GNU 语句表达式）—— 团队有约定时可用。

五、与宏、GNU 扩展关联

1. 标准宏规避逗号藏副作用

#define MAX(a, b) ((a) > (b) ? (a) : (b))   /* 安全：无逗号 */

若用逗号强行合并多操作：

/* 反例：危险、难懂 */
#define BAD(x) ((printf("x=%d\n", x), x))

实参若含副作用，宏展开后求值次数与顺序更难推理（1.4）。

2. GNU C 语句表达式 ({ ... })（拓展，非标准 C）

Linux 内核、DPDK 常见：

#define max(a, b) ({ \
    typeof(a) _a = (a); \
    typeof(b) _b = (b); \
    _a > _b ? _a : _b; \
})
  • 内部多条语句用 ; 分隔，最后一条 作为 ({ }) 的值（语义类似逗号表达式「取最右」）
  • 不属于 C99 标准；GCC/Clang 在 -std=gnu11 等模式下支持
  • 详见 Embedded ch06 · GNU 扩展

六、优先级在表达式中的位置

… 逻辑 && || → 条件 ?: → 赋值 = += … → 逗号 , （最低）

a = 1, 2;        /* (a = 1), 2 —— 赋值先算，再逗号，整体值 2 */
a = (1, 2);      /* a = 2 */

与 2.13 完整表对照。

2.13

运算符优先级与结合性

本节讲什么

梳理 C 全部运算符的 优先级（谁先分组运算）与 结合性（同优先级从哪边结合），并区分两个极易混淆的概念：优先级/结合性 ≠ 求值顺序。寄存器掩码、报文解析、复杂条件判断的歧义根源，多在本节。

要点

一、优先级完整排序（高 → 低，12 级）

数字越小 优先级越高，先参与分组；同级 看 结合性。

级 运算符 说明
1 () [] . ->、后缀 ++ -- 调用、下标、成员、后置自增
2 ! ~、前置 ++ --、+ -（一元）、* &、(type) sizeof 逻辑非、取反、前置自增、解引用、取址、强转
3 * / % 乘、除、模
4 + - 二元加、减
5 << >> 移位
6 < > <= >= 关系比较
7 == != 相等判断
8 & ^ \| 位与 → 位异或 → 位或（同级内 左结合）
9 && \|\| 逻辑与 → 逻辑或
10 ?: 三元条件
11 = += -= *= /= %= &= \|= ^= <<= >>= 赋值与复合赋值
12 , 逗号（全场最低）

速记口诀：后缀一元 > 前缀一元 > 算术 > 移位 > 关系 > 相等 > 位 > 逻辑 > 三元 > 赋值 > 逗号。

实战易错示例

flags |= val << 2;
/* 移位(5) > 复合或赋值(11)
   → flags |= (val << 2)  ✓ */

if (a & MASK != 0)
/* !=(7) 高于 &(8)？ 错！
   相等(7) 高于 位与(8)
   → if (a & (MASK != 0))  ✗ 几乎永远错 */

if ((a & MASK) != 0)   /* 正确 ✓ */

*p++        /* 后缀 ++ 绑定 p：*(p++)，不是 (*p)++ */
a + b << 1  /* << 高于 + → a + (b << 1) */

二、结合性（同优先级如何分组）

1. 左结合（绝大多数二元运算符）

同优先级时 从左往右 分组：

a - b - c     →  (a - b) - c
a / b / c     →  (a / b) / c
a >> 1 >> 2   →  (a >> 1) >> 2
a & b ^ c     →  (a & b) ^ c   /* & 与 ^ 不同级：& 先 */
a & b | c     →  (a & b) | c
a && b || c   →  (a && b) || c

2. 右结合（少数）

运算符 示例 分组
一元 ! ~ ++ -- * & + - *++p *(++p)（一元从右挂）
三元 ?: a ? b : c ? d : e a ? b : (c ? d : e)
赋值 = op= a = b = 0 a = (b = 0) 
*&a           →  *(&a)
a ? b : c ? d : e  →  a ? b : (c ? d : e)
x = y = z     →  x = (y = z)

注意：结合性决定 括号怎么插，不决定 子表达式谁先 求值（见第三节）。

三、重中之重：优先级 ≠ 求值顺序

概念 回答的问题
优先级 + 结合性 运算 如何加括号分组
求值顺序 子表达式 按什么先后执行（含副作用）

二者 独立。优先级只规定 a + b * c 是 a + (b * c)，不规定 a 与 b 谁先算。

1. 有严格求值顺序保证的（标准规定）

运算符 顺序规则
&& 左 → 右；左假则右不求值（2.6）
\|\| 左 → 右；左真则右不求值
?: 先 expr1；再 仅 expr2 或 expr3 之一（2.11）
, 严格左 → 右，值为最右（2.12）

2. 无固定求值顺序（C17 前：未规定；乱写 → UB）

  • 普通二元运算 + - * & | 等：左右操作数谁先求值 编译器自由决定
  • 函数实参列表：各实参谁先求值 不保证

严禁 依赖左右先后：

i++ + i++;           /* UB：同一表达式多次改 i（[2.8](./2.8-自增运算符与自减运算符.md)） */
func(a++, b++);      /* 实参顺序未定义；若同一变量更糟 */
a[i++] = i;          /* UB */
printf("%d %d", i++, ++i);  /* UB */

C17 起：部分求值顺序有所规定，但 同一表达式多次修改同一对象 仍为 UB —— 永远不要写。

3. 对比小结

/* 优先级：分组明确 */
a + b * c   →  a + (b * c)

/* 求值顺序：a 与 b*c 谁先算？—— 无保证（只要不违反 UB） */

/* 逗号：分组且顺序都有保证 */
(x++, y++)  →  先 x++，再 y++，值为 y++ 结果

五、底层工程建议（寄存器 / 掩码 / 协议）

  1. 不要死记优先级表 —— 复杂位运算、判断 手动加括号
  2. 位与 + 相等 必须括号：if ((val & BIT(0)) != 0)
  3. 移位 + 掩码 + 或赋值 分步写清：
/* 差：易看错 */
reg |= data << 8 & 0xFF00;

/* 好 */
reg |= (data << 8) & 0xFF00u;
  1. 超长条件 拆多行 或提布尔变量
  2. 审查 grep：&.*==、<<.*&、条件里的 =
#define BIT(n)  (1u << (n))

if ((status & BIT(3)) != 0)
    handle_ready();

uint32_t field = (reg >> FIELD_SHIFT) & FIELD_MASK;

六、与类型转换的交互

分组确定后，各子表达式仍受 2.7 整型提升、usual arithmetic conversions 约束 —— 优先级 不解决 signed/unsigned 混算坑。

代码自测

题目 1： 以下表达式的求值顺序是什么？

*p++      // ?
*p & 0xFF  // ?
a < b == c < d  // ?
参考答案

*p++ → *(p++)（后置++优先级高于，先取 p 的值解引用，再 p++） *p & 0xFF → (*p) & 0xFF（ 高于 &） a < b == c < d → (a < b) == (c < d)（< 和 > 高于 ==） 规则：不用背优先级表，有歧义就加括号。

章节自测

题目 1： 以下代码在 K&R C 和 ANSI C 中有什么区别？

unsigned x = -1;
printf("%u\n", x);
参考答案

输出 UINT_MAX（如 4294967295）。-1 被转换为 unsigned，按补码解释为最大值。K&R C 和 ANSI C 都允许有符号到无符号的隐式转换，但 K&R C 的转换规则在某些边缘情况不同。现代 C 中这种隐式转换虽然合法但容易出错——编译器会警告。
