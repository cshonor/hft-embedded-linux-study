入门 Getting Started

本节讲什么

从经典 Hello, world 出发，建立 C 程序最小骨架：头文件、main、标准输出与转义字符；并理清 编译 → 链接 → 运行 三阶段。有 C++ 基础时，本节重点是 甩掉 iostream 习惯，区分 K&R 老式写法与现代标准 C。

要点

1. 基础输出与转义字符

  • printf：C 标准格式化输出，声明在 <stdio.h>（完整说明见 附录 B.1 stdio.h；格式与安全见 1.1.2 printf）
  • 常用转义符：
转义 含义
\n 换行
\t 制表符
\b 退格
\" 双引号字符
\\ 反斜杠
  • 字符串必须用 双引号 "..."；单引号 'a' 只表示 单个字符（char），不是字符串

2. C 程序完整工作流

  hello.c ──► 编译(cc -c) ──► hello.o ──► 链接(cc / ld) ──► a.out ──► 运行
                  │                              │
            预处理+语法+语义              合并 .o + libc（如 crt 启动代码）
  1. 编译：.c → 预处理 → 翻译单元 → 目标文件 .o（机器码 + 未解析符号）
  2. 链接：多个 .o + 系统库（libc 等）→ 可执行文件；解析 printf 等外部符号
  3. 运行：加载器把二进制映射进内存，从 main 入口开始执行

与 C 陷阱 ch04 连接 、Expert C ch05 链接 后续展开。

3. Hello World 示例

K&R 原书写法（历史遗留，工程勿用）：

#include <stdio.h>

main()
{
    printf("hello, world\n");
}
  • 省略 main 返回类型时，老式编译器默认 int main()
  • 无 return 时，旧实现可能默认返回 0

现代标准 C（工业代码必须这样写）：

#include <stdio.h>

int main(void)
{
    printf("hello, world\n");
    return 0;
}
  • int main(void)：明确无命令行参数；有参数时用 int main(int argc, char *argv[])（见下文 §4）
  • return 0：表示成功退出；非 0 常表示错误（脚本/CI 可检测退出码）
  • -Wall -Wextra 下，main() 无类型常触发告警；C99 起 不允许 隐式 int
gcc -Wall -Wextra -std=c11 -o hello hello.c
./hello

4. 为何写 int main(void)，不能只写 int main()

C 与 C++ 对空括号 () 的含义完全不同——这是 C++ 转 C 时最容易误判的一点。

C 语言规则

声明 含义
main() 参数未指定（老式 K&R 遗留）：原型上不约束实参个数与类型
main(void) 明确无参数：调用时传任何实参 → 编译错误

普通函数同理，一眼看懂：

/* C：空括号 = 参数未指定，不是「无参」 */
void func_old()
{
}

void func_new(void)
{
}

void demo(void)
{
    func_old(1, 2, 3);   /* 可能编译通过 —— 隐患 */
    func_new(1);         /* 编译错误 ✓ */
}

C23 之前，f() 的「空括号 = 参数未指定」仍广泛存在于老代码；新代码一律 (void)。

C++ 规则（与 C 相反）

在 C++ 中，int main() 与 int main(void) 等价，都表示无参数。因此从 C++ 过来时容易误以为 C 里两者也一样——不是。

放在 main 上的实际意义

  • int main()：编译器不检查是否误传参，风格不严谨，移植/静态检查易出问题
  • int main(void)：C99/C11/C17 规范写法；显式声明「程序入口不要入参」——内核模块、DPDK、嵌入式工程通用习惯

工业标准完整写法

#include <stdio.h>

int main(void)
{
    printf("hello world\n");
    return 0;   /* int 返回类型必须配套 return */
}

带命令行参数时（与无参版本互斥）

需要读取启动参数时才写：

int main(int argc, char *argv[])
{
    /* argc = 参数个数；argv[0] 通常是程序名 */
    return 0;
}

不要同时混用 void 与 argc/argv；选 无参 或 带参 其一即可。

完整专题见 1.1.1 命令行参数（argc/argv 拆解、示例、用法模板、demo）。

与 C++ 的差异（已有 C++ 基础时）

主题 C++ C
I/O 头文件 #include <iostream> #include <stdio.h>
输出 std::cout << "x\n"; printf("x\n");
输入 std::cin >> x; scanf("%d", &x);（须取地址）
main 写法 int main() ≡ int main(void)（C++ 不区分） 规范：int main(void)；main() 在 C 里表示参数未指定
老式 main() 部分编译器仍接受 K&R 兼容；新工程禁止

C 没有 命名空间、类、RAII；I/O 与内存管理（后续 malloc）都是 显式、底层 的——这正是内核、DPDK、HFT 数据面使用 C 的原因。

.1 命令行参数 `main(int argc, char *argv[])`（精炼）

与 1.1 入门 衔接：无参用 main(void)；要读启动参数用本节。
类型口诀：5.6.1 · * 声明规则：5.12.1 · 5.10。

1. 一句话 + 元素类型

char *argv[] 是指针数组；每个元素是 pointer to char（口语：char *）。
声明语法上 * 跟名字走，见 5.12.1；不是把 char* 当成不可拆类型单元（对比 int* a, b）。

char *argv[];
/* 本质：指针数组；argv[i] 的类型 = char * */
表达式 类型 含义
argv[i] char * 数组元素：指向某参数字符串
argv（形参里） char ** 退化后：指向「首个 char *」的指针
argv[i][0] char 该串首字符

不是二维字符数组 char argv[][]：后者是连续字符块；前者是一排指针，字符串可分散存放。

argv[0] (char*) → "./app"
argv[1] (char*) → "input"
argv[2] (char*) → NULL

1b. 两处场景（核心矛盾：能否写 char *argv[]）

很多人把「不定长数组不能单独定义」套到 main 上，其实是两处场景：

场景 A：普通变量（局部 / 全局）

char *argv[];                      /* ❌ 无长度、无初始化 → 非法 */
char *argv[] = {"a", "b", NULL};   /* ✅ 由初始化推导长度 */

普通对象里的数组必须能确定大小。

场景 B：函数形参（main 就在这里）

int main(int argc, char *argv[]) { ... }
/* 标准允许；编译器等价为 */
int main(int argc, char **argv) { ... }

规则：形参里写 T arr[] 永远等价 T *arr（第一维 [] 退化成指针）。
char *argv[] 只是语法糖，形参位置并不真正定义数组；只收到「指针表」的首地址（通常来自 execve）。

普通变量 T a[] 函数形参 T a[]
无长度无初始化 非法 合法，= T *
sizeof 整数组字节数 一个指针的大小

面试一句：形参里看起来像数组，本质是指针；函数内部局部变量才是真数组，不初始化就不能省略长度。
为何如此设计（栈/性能/规则 A+B） → 5.3.1 · 类型对比 5.6.1。

2. 索引规范（POSIX / C）

下标 内容
argv[0] 程序路径/名（由 execve 调用者决定，可被篡改；勿做业务硬依赖）
argv[1] … argv[argc-1] 用户参数
argv[argc] 强制 NULL

argc 最小为 1（无用户参数时仍有 argv[0]）。

安全遍历：

/* 推荐：靠 argc */
for (int i = 0; i < argc; i++)
    puts(argv[i]);

/* 靠末尾 NULL（标准保证 argv[argc]==NULL） */
char **p = argv;
while (*p != NULL) {
    puts(*p);
    p++;
}

3. 工程坑（嵌入式 / Linux 后台通用）

  1. 指向的字符串通常可改内容；长期改写 argv[0] 不推荐（日志/ps 等常依赖）。
  2. 全是 \0 结尾的 C 字符串；数字仍是串 → 用 strtol 等转换。
  3. shell 的 *.txt 由 shell 展开；程序若收到字面量 *.txt，说明通配被关/未走 shell。
  4. 分段：空格切分；含空格用引号：./a "my file" → 一段。

4. 衔接 TLPI / 进程

execve(path, argv, envp) 在用户态构造这套数组。扩展签名（POSIX）：

int main(int argc, char *argv[], char *envp[]);  /* envp 同结构，末尾 NULL */

→ TLPI：Ch24–27 进程/exec

自测

  1. 局部 char *argv[] 与 main 形参为何含义不同？
    → 普通变量：真数组，须定长或初始化；形参：语法糖，= char **。
  2. 只写 while (argv[i]) 不判 i < argc？
    → 若保证 argv[argc]==NULL 且 i 递增则合法；优先 i < argc。
  3. 能 free(argv[0]) 吗？
    → 不能。非本程序 malloc；free → UB。
  4. 形参里 sizeof(argv) 是多少？
    → 一个指针大小（如 8），不是「参数字符串总长度」。

代码自测

题目 1： 以下代码中 argc 和 argv 的值分别是什么？

// 编译：gcc prog.c -o prog
// 运行：./prog hello world 42
int main(int argc, char *argv[]) {
    for (int i = 0; i < argc; i++)
        printf("%d: %s\n", i, argv[i]);
}
参考答案

argc = 4, argv[0] = "./prog", argv[1] = "hello", argv[2] = "world", argv[3] = "42"。argc 是命令行参数个数（含程序名），argv 是参数字符串数组。argv[0] 始终是程序名。argv[argc] 始终是 NULL。遍历参数从 argv[1] 开始。

.2 `printf` 格式、安全与工程规范

本节讲什么

printf 格式化输出的 完整注意事项：语法前提、% 占位符与类型匹配、转义字符、缓冲区刷新、格式化漏洞、宽度精度、C99 %zd、内核/DPDK 日志习惯。承接 1.1 入门 与 附录 B.1 <stdio.h>。

一、基础前提

#include <stdio.h>   /* 必须；否则无 printf 声明 */
项 说明
原型 int printf(const char *format, ...);
返回值 成功输出的 字符数；可接收可忽略
无头文件 旧编译器可能仅警告；C99 起 无声明使用 → 错误 
int n = printf("hi\n");   /* n 常为 3 */

二、格式控制符（% 系列 — 极易踩坑）

1. 类型必须匹配

变量类型 正确占位符 常见错误
int %d long 用 %d → 异常
long %ld（ll → %lld） printf("%d", 1L)
unsigned %u 负数用 %u → 超大正数
float %f（float 提升为 double 传参） —
double %f / %e / %g int 用 %f → 乱数
char %c 勿用 %s 打单字符
字符串 char* %s 须 以 \0 结尾 的有效串
指针 %p 打印地址 
int num = 3;
printf("%f", num);   /* 错：类型不匹配，UB/乱码 */
printf("%d", num);   /* 对 */

2. %s 高危

坑 后果
printf("%s", NULL) 段错误
无 '\0' 的 char[] 越界读，垃圾字符

3. 输出字面量 % —— 写 %%

printf("进度50%%\n");   /* 输出：进度50% */

三、转义字符

转义 含义
\n 换行（推荐；触发 stdout 行缓冲 刷新）
\t 制表

四、缓冲区刷新（底层高频坑）

stdout 默认行缓冲（连终端时）：

五、安全风险（禁止滥用）

1. 格式化字符串漏洞

char buf[128];
/* 假设 buf 来自用户输入 */
printf(buf);         /* 危险！buf 中含 %n %x 可写内存 */
printf("%s", buf);   /* 安全：格式串固定 */

规则：格式串 必须是 程序员控制的字面量 或可信常量；用户数据只做 %s 等参数。

2. 长度限制

printf("%.10s", str);   /* 最多打印 10 个字符，防超长 */

六、宽度、对齐、精度

写法 效果 示例输出
%5d 宽度 5，右对齐，空格填充 12
%05d 宽度 5，不足 前导 0 00012
%-5d 左对齐 12
%.2f 保留 2 位小数 3.14 
printf("%05d\n", 12);    /* 00012 */

七、C99 / 可移植补充

size_t len = sizeof(int);
printf("%zd\n", len);    /* C99：size_t；勿用 %d */
类型 推荐格式
size_t %zu 或 %zd（有符号场景少见）
int32_t / int64_t <inttypes.h> PRId32/PRId64
uintptr_t %#" PRIxPTR 或 %p（指针）

打印 VLA 或串时，长度变量 须合法，避免越界 %.*s 误用。

八、工程规范（内核 / DPDK / HFT）

  1. 调试前缀：printf("[DEBUG] len=%zd\n", len); — 便于 grep
  2. 热路径少 printf — IO 开销大；正式版用分级日志、环形缓冲、条件编译 DEBUG
  3. 错误走 stderr：

  1. 低延迟路径：避免 stdio；用 ch08 write(2) 或专用日志框架

变量与算术表达式

本节讲什么

K&R 第一章第二个经典示例：华氏 → 摄氏温度对照表。引入 int / float、四则运算、for 循环与 printf 格式控制，完成第一个「有计算、有循环、有表格输出」的实用小程序。

核心目标：

  1. 认识 int 整型、float 浮点型；牢记 C 规则：变量必须先声明，后使用
  2. 掌握 + - * /、运算符优先级与括号
  3. 入门控制流：if 条件判断、while / for 循环（本章以 for 为主）
  4. 掌握标准循环模板：初始化 → 循环体计算 → 更新循环变量 → 输出
  5. 打印 0～300℉ 每隔 20 度对应的摄氏度

要点

1. 数据类型与变量声明

int fahr;    /* 循环变量：0, 20, 40 … 300，整数步进 */
float celsius;  /* 若单独存结果，用小数类型 */
类型 用途 本章示例
int 整数 华氏温度 fahr
float 单精度浮点 摄氏结果 (5.0/9.0)*(fahr-32)
  • C 没有「先用后声明」（与 C++ 局部变量块内乱序不同）；声明通常放在块开头或循环外
  • 与 C++ 对比：C++ 有 double、初始化列表；本章 C 示例以 float + printf 为主

2. 整数截断（本节第一坑）

C 里 / 两侧都是整数 → 结果仍是整数，小数直接丢弃：

5 / 9;      /* 结果 0，不是 0.555… */
5.0 / 9.0;  /* 浮点除法，结果正确 */

温度公式：(celsius = \frac{5}{9}(fahr - 32))

写法 结果
(5/9)*(fahr-32) 错 — 先算 5/9==0，整表全 0
(5.0/9.0)*(fahr-32) 对 — 浮点运算

推广：涉及小数的公式，至少一侧用浮点常量或 cast，见 C 陷阱 ch03 语义。

3. for 循环模板

for (fahr = 0; fahr <= 300; fahr = fahr + 20)
    /* 循环体 */

等价于三步：

  初始化: fahr = 0
  条件:   fahr <= 300 为真则进入循环体
  更新:   每次末尾 fahr = fahr + 20
部分 示例 含义
初始值 fahr = 0 从 0℉ 开始
条件 fahr <= 300 到 300℉ 为止
更新 fahr += 20 或 fahr = fahr + 20 步长 20

while 可写同样逻辑，本书先给 for 表格式循环；1.3 会单独练 for。

4. printf 格式控制（打表格）

printf("%3d %6.1f\n", fahr, celsius);
格式 含义
%3d 整数，至少占 3 字符宽度，右对齐（不足补空格）
%6.1f 浮点，总宽 6、小数 1 位
\n 每行结束换行

输出列对齐，便于肉眼对照；调试日志、指标打印同样靠格式符控制列宽。

1.3

for 语句

本节讲什么

承接 1.2 温度转换，同一华氏 → 摄氏案例分别用 while 与 for 实现，对比循环结构：for 把 初始化、终止条件、步进更新 收拢到一行，代码更集中；while 则三段逻辑分散在循环外/内。

要点

1. for 完整语法（C / C++ / Java / JS 同形）

for (初始化表达式; 循环条件表达式; 自增/后置表达式) {
    循环体;
}

核心规则：

  1. 三段表达式全部可选 —— 任意一段、两段、三段都能删掉
  2. 分隔三段的两个英文分号 ; 绝对不能省略 —— 编译器靠分号区分三个槽位，少一个即 语法错误

执行顺序：初始化（一次）→ 判条件 → 循环体 → 步进 → 再判条件 → …

2. 为什么两个分号不能丢？

编译器用 两个分号 划分三个固定槽位：

for ( [槽1 初始化] ; [槽2 条件] ; [槽3 步进] )
         ↑              ↑              ↑
      分号1前        两分号之间      分号2后
槽位 作用 省略时
槽1 初始化 常已在循环外完成
槽2 条件 恒真 → 无限循环
槽3 步进 常改在循环体内

3. 各种省略示例

① 省略第一段（初始化）

int i = 0;
for (; i < 10; i++) {
}

② 省略第二段（条件 → 无限死循环）

for (i = 0; ; i++) {
}   /* C99 前：int i 须在 for 外声明 */

③ 省略第三段（步进改在循环体内）

for (i = 0; i < 10; ) {
    i++;
}

④ 省略两段：初始化 + 条件

int i = 0;
for (;; i++) {
}

⑤ 省略两段：条件 + 步进

for (i = 0; ; ) {
    i++;
}

⑥ 三段全省略 —— for(;;) 最简死循环

for (;;) {
}

等价 while (1)；内核轮询、事件循环常见，循环体内须有 break/return。

汇总表：

写法 含义
for (; fahr <= 300; fahr += 20) 初始化在循环外
for (fahr = 0; ; fahr += 20) 无显式条件 → 死循环
for (fahr = 0; fahr <= 300; ) 步进在循环体末尾
for (;;) 无限循环

4. 反面错误：丢分号直接编译失败

for (int i = 0 i < 10; i++) { }   /* 错：少第一个 ; */
for (int i = 0; i < 10 i++) { }   /* 错：少第二个 ; */
for (int i = 0 i < 10 i++) { }    /* 错：两个 ; 全丢 */

5. for vs while 适用场景

while for
典型场景 次数不确定、纯条件驱动（等信号、阻塞读、轮询硬件） 次数已知、数组/表遍历、批量计算
代码结构 初始化在循环外，更新在循环末，三段分散 初始化、条件、步进同一行
温度表 适合理解循环三要素 K&R 推荐写法，更紧凑

底层经验：

  • for：DPDK mbuf 批量处理、行情数组回放、寄存器表索引、固定长度报文解析
  • while：read/recv 直到 EAGAIN、事件循环 while (running)、无固定上界的队列消费

6. 循环体与大括号

  • 循环体 只有一条语句 时，{} 可省略（K&R 原书常省略）
  • 多条语句 必须用 { ... } 组成复合语句
  • 工程规范：一律加 {}，避免 C 陷阱 dangling else 类问题；与 1.2 整数截断、5.0/9.0 公式相同，不再重复

同案例两种写法对照

while 版本（初始化、更新分散）

#include <stdio.h>

int main(void)
{
    int fahr = 0;              /* 初始化：循环外 */

    while (fahr <= 300) {      /* 条件 */
        printf("%3d %6.1f\n", fahr, (5.0 / 9.0) * (fahr - 32));
        fahr = fahr + 20;      /* 步进：循环末 */
    }

    return 0;
}

for 版本（三段逻辑收拢）

#include <stdio.h>

int main(void)
{
    int fahr;

    for (fahr = 0; fahr <= 300; fahr += 20) {
        printf("%3d %6.1f\n", fahr, (5.0 / 9.0) * (fahr - 32));
    }

    return 0;
}

./fahr_for

两种写法 输出完全一致；选哪种取决于可读性与团队规范，表驱动计数更常写 for。

HFT / 嵌入式开发的用处

  1. for 是底层遍历高频写法：报文队列、行情 buffer、DMA 描述符环、内存块按索引扫描
  2. while 多用于阻塞/轮询：等 socket 可读、等 ring 非空、无固定次数的事件监听
  3. 按场景选循环：避免把本适合 for 的定长遍历拆成分散的 while 变量，减少漏写步进导致的 死循环或越界

1.4

符号常量

本节讲什么

承接 1.3 for 语句 的温度表循环，把 0、300、17 等 魔法数字 提成 符号常量：用 #define 在 预处理阶段 做纯文本替换，让循环上下限、步长 一眼可读，改数值只动一处。

要点

1. 核心概念

#define 是 C 语言 预处理器指令，用来定义 符号常量，替代代码里零散、无注释的裸数字。

#define 常量名 替换文本
  • 编译器在 编译前（预处理阶段）做 纯文本替换
  • 不是变量：没有类型、不能取地址、不参与运行时赋值；宏名本身不占用运行时内存空间
  • 行末 不必加分号（加了会把 ; 一并替换进代码，可能引发语法错误）

2. 三大要点

① 文本替换机制

预处理阶段直接全文替换，不存在数据类型，和普通变量完全不同。

#define UPPER 300
/* 源码里每一处 UPPER 在编译前都变成 300 */

② 提升可维护性

数值只定义一次；后续修改只改 #define 一行，整个程序全部生效，不用到处搜数字。

③ 本节只讲无参宏

带参数的复杂宏（函数式宏）留到 第 4 章预处理器 与 K&R ch4 再学。

3. 魔法数字 vs 符号常量

写法 问题
for (fahr = 0; fahr <= 300; fahr += 20) 0 / 300 / 17 含义不明，改步长易漏改
for (fahr = LOWER; fahr <= UPPER; fahr = fahr + STEP) 名字自带语义，循环头自解释

4. 优点总结

  1. 可读性：UPPER 一看即上限，STEP 即步长
  2. 易维护：改数值只改一处
  3. 统一规范：避免相同数字写多份、改错一份

5. 宏不管作用域 —— 能「偷偷」覆盖标准库（HFT 致命坑）

#define 由 预处理器 处理，发生在编译之前；它 不认 C 的块作用域、函数作用域，也 不认 Rust 那套词法作用域 —— 只要 token 匹配，全文替换。

#define getchar my_getchar

int c = getchar();   /* 预处理之后 → int c = my_getchar(); */

后果：

  • <stdio.h> 里的 getchar 宏/函数名被劫持，后面所有 getchar 都变成 my_getchar
  • 编译 仍可能通过，行为却在运行时 静默跑偏 —— 读缓冲策略、锁、延迟全变了
  • HFT 热路径里这种 bug 极难查：源码看起来调的是标准库，预处理后根本不是
机制 #define 宏 const / 函数
处理阶段 预处理（编译前） 编译、链接
作用域 无 — 从定义点到 #undef 或文件末 块/文件/链接域
能否覆盖 getchar 能，纯文本替换 不能靠名字偷偷换 stdio
运行时内存 宏名不占；替换结果可能是立即数 const 对象占内存（常在常量区）

与 const 只读变量、字符串字面量 对比见 2.3 §0、4.3.1 常量区。

工程规范：

  • 宏名 全大写 + 项目前缀：HFT_RING_SIZE，不要叫 getchar、max、min
  • 禁止 #define 标准库函数名、关键字、常见 typedef（uint32_t、size_t）
  • 怀疑被宏污染时：gcc -E file.c | less 看预处理结果；或 #undef getchar（仅当确知误定义）

详见 C 陷阱 6.5 宏名冲突；与 1.5 getchar 循环 对照理解。

完整示例（温度表 + 符号常量）

#include <stdio.h>

#define LOWER  0    /* 华氏下限 */
#define UPPER  300  /* 华氏上限 */
#define STEP   20   /* 步长 */

int main(void)
{
    int fahr;

    for (fahr = LOWER; fahr <= UPPER; fahr = fahr + STEP) {
        printf("%3d %6.1f\n", fahr, (5.0 / 9.0) * (fahr - 32));
    }

    return 0;
}

对比裸数字版：别人不必猜 300 是上限还是别的业务阈值；改表范围时只改 #define UPPER。

1.6

数组

本节讲什么

承接 1.5 字符 I/O 的 getchar 循环，引入 一维数组：声明、下标访问、初始化；用数组做 桶计数（数字 0~9、空白、其他字符各计一次）。同时厘清 中括号绑在谁身上、++ndigit[k] 与前置/后置自增，并预告 指针数组 vs 数组指针（第 5 章展开）。

要点

1. 一维数组声明与下标

int ndigit[10];   /* ndigit 是含 10 个 int 元素的数组 */
规则 说明
下标从 0 开始 长度 10 → 合法下标 0～9，没有 ndigit[10]
下标是整型表达式 可以是 c - '0'、i、f(x) 等
越界 语言 不检查；越界是 未定义行为，内核/DPDK/HFT 同样致命

2. 中括号在变量名右边，不在类型右边

C 里 [] 紧跟变量名，表示 这个变量是数组：

int ndigit[10];     /* 对：ndigit 是 int 数组 */
int[10] ndigit;     /* 错：C 语法不允许 */

读法：int ndigit[10] = 变量名 ndigit + 「含 10 个 int 的数组」。

这样设计是为了声明 组合类型 时，运算符优先级能表达：

  • 数组、指针、函数返回类型可以 叠在一起
  • 读复杂声明时从 变量名 出发，见 §6 与 ch05 指针

对比 C++：int arr[10] 同样绑在变量名侧；Java int[] arr 把 [] 写在类型侧 —— C 不是 Java 写法。

3. 与 getchar 结合：数字字符桶计数

K&R 经典模式：读字符流，按类别 分桶累加。

int ndigit[10];      /* 桶 0～9：字符 '0'～'9' 各计几次 */
int nwhite, nother;  /* 空白、其他 */

/* 初始化略；静态存储默认 0，局部数组需显式清零 */

while ((c = getchar()) != EOF) {
    if (c >= '0' && c <= '9')
        ++ndigit[c - '0'];
    else if (c == ' ' || c == '\n' || c == '\t')
        ++nwhite;
    else
        ++nother;
}

c - '0' 为何能当下标？

  • 字符 '0'～'9' 在 ASCII 中 连续编码
  • '0' 的码值 + 0 = '0'，+ 1 = '1'，…
  • 故 '3' - '0' → 整数 3，正好对应 ndigit[3]
字符 c c - '0' 写入桶
'0' 0 ndigit[0]
'5' 5 ndigit[5]
'9' 9 ndigit[9]

必须先 if (c >= '0' && c <= '9') 再减 '0'，否则 'A'-'0' 等会得到荒谬下标。

4. ++ndigit[k] 与 i++ / ++i

前置 ++i：先把 i 加 1，再用新值参与运算。
后置 i++：先用 i 当前值参与运算，再把 i 加 1。

对 单独一条语句 只关心副作用（把计数加 1）时，二者等价：

++ndigit[k];    /* 前置：ndigit[k] 先 +1 */
ndigit[k]++;    /* 后置：ndigit[k] 也 +1；单独语句效果相同 */

嵌进复杂表达式时差别很大：

int a[3] = {10, 20, 30};
int i = 0;

/* 后置：先用 ndigit[i] 的旧值参与，再 +1 */
x = ndigit[i]++;   /* x 得旧值，然后 ndigit[i] 加 1 */

/* 前置：先把 ndigit[i] +1，再用新值 */
x = ++ndigit[i];   /* x 得加 1 后的新值 */

工程建议：计数、循环步进写独立语句 时用 ++ndigit[k] 或 ndigit[k]++ 均可；不要在一条表达式里混用前置/后置与别的运算 —— HFT 热路径要 可读、可预测。

5. 完整示例思路（字符分类统计）

#include <stdio.h>

int main(void)
{
    int c, i;
    int ndigit[10];
    int nwhite, nother;

    nwhite = nother = 0;
    for (i = 0; i < 10; ++i)
        ndigit[i] = 0;

    while ((c = getchar()) != EOF) {
        if (c >= '0' && c <= '9')
            ++ndigit[c - '0'];
        else if (c == ' ' || c == '\n' || c == '\t')
            ++nwhite;
        else
            ++nother;
    }

    for (i = 0; i < 10; ++i)
        printf(" %d", ndigit[i]);
    printf(", white space = %d, other = %d\n", nwhite, nother);

    return 0;
}

6. 指针数组 vs 数组指针（易混，别记反）

两者都用到 * 和 []，括号决定绑定关系 —— 中括号、星号 跟谁绑，跟谁就是数组/指针。

名称 含义 写法 读法
指针数组 数组，元素类型是指针 int *arr[10]; arr 是 10 个元素 的数组，每个元素是 int *
数组指针 单个指针，指向整个数组 int (*arr)[10]; arr 是 指针，指向「含 10 个 int 的数组」 
int *parr[10];     /* 指针数组：10 个 int* 槽位，常用来存字符串指针 argv 风格 */
int (*parr)[10];   /* 数组指针：一个指针，指向 int[10] 整块 */

记忆口诀：

  • [] 离变量名更近 → 先数组：int *p[10] → 指针数组（很多指针）
  • () 把 * 和变量名括在一起 → 先指针：int (*p)[10] → 数组指针（指向一整块数组）

本章只用到 int ndigit[10] 这种最简单形式；ch05 会系统讲 [] 与 * 的声明阅读规则。

7. 「声明随使用」—— C 没有独立的指针类型写法

不是「指针类型无法表述」，而是 C 不提供 Rust 那种单独的类型名：

// Rust：类型名与变量名分离
let p: *mut [i32; 10];

C 里 「指向 int 数组的指针」 这种整体类型，只能 通过绑定写法体现：

int (*p)[10];   /* p 是指针；*p 使用时是 int[10] */

读声明的核心逻辑（声明随使用 / declaration follows use）：

  1. 从 变量名 出发，看 使用时 对它做什么操作
  2. 操作的结果类型 反推 变量本身 是什么
声明 使用时 反推
int x; x 就是 int x 是 int
int *p; *p 是 int p 是指向 int 的指针
int arr[10]; arr[i] 是 int arr 是含 10 个 int 的数组
int (*p)[10]; (*p)[i] 是 int p 是指向「int[10]」的指针

所以你的理解对：不是先写一个直观的「指针类型名」再挂变量，而是 先写变量名 + 修饰符（*、[]），告诉编译器「对它解引用 / 下标之后得到什么」，反推 它自身类型。

*、 [] 写在 变量名旁边，就是在描述 「用这个变量时，左边/解引用后的类型长什么样」。
完整螺旋规则见 Expert C ch03；typedef 可把复杂声明 起别名（如 typedef int (*arrptr)[10];），但底层仍是同一套绑定语法。

8. 同时声明两个指针：int *p, *q 不是 int *p, q

* 只绑定紧挨它的那个标识符：

int *p, *q;    /* 对：p、q 都是 int* */
int *p, q;     /* 错：只有 p 是指针，q 是普通 int */

规范：每行只声明一个指针变量，或每个名字前都写 *：

int *p;
int *q;

/* 或 */
int *p, *q;

HFT / 内核代码 review 时，int *p, q 是常见 隐藏 bug 来源。

1.7

函数

本节讲什么

如何 定义、声明、调用 自定义函数，用 函数分解 降低 main 复杂度；示例为整数幂 power(m, n)。

核心规则（纠正常见说法）：不是「除 main 外必须把声明写在文件最开头」，而是 调用出现在定义之前时，必须先让编译器见过声明或完整定义。声明放文件顶部只是 工程上最常用，不是语法硬性要求。main 是入口，没有代码会提前调用它，故 main 永远不需要提前声明。

要点

1. 为什么需要函数声明（函数原型）

C 编译器 从上到下逐行编译 当前翻译单元（.c 文件）：

  • 调用 add(1, 2) 时，若编译器 还没见过 add 的 定义（函数体） 或 声明（原型），会 报错（C99 起）；旧编译器可能 隐式假设 int 返回、参数类型乱猜 —— 极易出错
  • 函数声明 / 原型 提前告诉编译器：叫什么、参数类型是什么、返回什么类型，调用处才能生成正确的参数传递与返回值处理
int add(int a, int b);   /* 原型：不是函数体，末尾分号 */

2. 三种合法写法（声明位置不限）

只要满足 「首次调用前，编译器已见过声明或定义」 即可。

方式 1：声明放文件顶部（最常用、工程规范）

int add(int a, int b);   /* 声明 */

int main(void)
{
    add(1, 2);           /* OK：上面已声明 */
    return 0;
}

int add(int a, int b)    /* 定义在后 */
{
    return a + b;
}

方式 2：定义写在 main 前面 —— 无需额外声明

定义 本身自带 原型信息；编译器先看到完整定义，后面调用自然认识：

int add(int a, int b)
{
    return a + b;
}

int main(void)
{
    add(1, 2);           /* OK：add 已在上方定义 */
    return 0;
}

方式 3：声明写在 main 内部（合法但极少用）

块内声明 只在该块内可见，其他函数 看不见：

int main(void)
{
    int add(int a, int b);   /* 仅 main 内有效 */
    add(1, 2);
    return 0;
}

int add(int a, int b) { return a + b; }
/* 若别的函数也调 add，仍须在文件级或 .h 再声明 */
方式 适用
顶部声明 + 后部定义 默认首选；原型一览、与 K&R power 示例一致
定义在前 小文件、辅助函数紧挨调用者
main 内声明 教学/临时；不推荐 工程代码

3. 多文件工程：声明进 .h

大型项目不会在每个 .c 复制一堆原型，而是：

/* math_utils.h */
int add(int a, int b);

/* main.c */
#include "math_utils.h"
/* 或 math_utils.c 里 #include 同一 .h */

/* math_utils.c */
#include "math_utils.h"
int add(int a, int b) { return a + b; }

#include 把 .h 里的声明 粘贴 进当前文件 —— 本质仍是 调用前让编译器看见原型（ch4 预处理器展开）。

4. main 为何不需要声明

  • main 由 链接器 / 运行时 作为程序入口调用，没有 你的 C 代码会在前面 main(...) 一下
  • 因此 不需要 也 不应依赖 在文件里写 int main(void); 来满足「先声明后调用」（写了通常也无害，但无必要）

5. 函数定义 vs 函数原型（声明）

造零件 vs 贴标签：

比喻 含义
函数定义 = 造零件 返回类型、函数名、参数列表 + 函数体 —— 把 怎么干活 全写出来
函数原型 = 贴标签 只写返回类型、函数名、参数列表 —— 提前告诉编译器 叫什么、收什么、返什么；无函数体，末尾 ; 
int power(int m, int n);              /* 贴标签：原型 */

int power(int base, int n)            /* 造零件：定义 */
{
    int p;
    for (p = 1; n > 0; --n)
        p = p * base;
    return p;
}

调用写在定义前面时，编译器还没见过这个零件的 标签 → 报错。必须先写 声明（原型），或把 定义 挪到调用之前。

对比 原型（贴标签） 定义（造零件）
函数体 无 有
典型位置 调用 之前、头文件 .c 源文件
次数 可多次 只能 一次

详见 4.1 §6。

6. 函数形式与 return

int add(int a, int b)     /* 返回类型 int 写在函数名左边 */
{
    语句;
    return 表达式;        /* 非 void 必须能返回值 */
}
  • 返回类型 在函数名 左侧：int add(...)、void f(...) —— 详见 4.1
  • C89 及以前：省略返回类型 → 隐式 int；没 return 也当返回 int，但值 未定义
  • C99 起：必须显式写返回类型，不写直接报错

  • 形参列表 void 表示无参：int f(void);（与 int f(); 旧式不同，见 K&R 演进）

1.8

参数传值调用

本节讲什么

讲解 C 语言 唯一的 参数传递机制：传值调用（call by value） —— 形参是实参值的 副本，函数内改形参 不影响 外部变量。用 swap 经典反例 说明「为何普通交换失效」；并 讲透指针传参：C 仍全是值传递，传指针 = 拷贝 地址，解引用可改原数据，但改形参指针本身无效（需二级指针，ch5 展开）。

承接 1.7 函数 的 power 调用；为 ch05 指针 铺路。
入门速查（& / * / 指针形参怎么传）：1.8.1 指针形参与取地址。
进阶专篇（Pointers on C）： 7.3.1 值拷贝无例外。

要点

1. 核心结论

  1. C 不存在 传引用（pass by reference）；所有 函数参数一律 传值
  2. 传指针 不是 传引用，而是把 指针变量里存的地址数值 再拷贝一份给形参
  3. 分 两层 理解指针传参： - 不能 修改实参 指针变量本身（一级指针形参里 p = &b 只改副本） - 可以 通过拷贝来的地址 解引用，修改指针 指向的内存（*p = 100 改外面的 a）

2. 传值调用流程

实参表达式求值 → 得到一份值 → 拷贝给形参 → 形参、实参两块独立内存
步骤 说明
1 先计算实参表达式，得到一个 值
2 将该值 拷贝一份 给函数内部的形参
3 形参、实参 存储位置不同，生命周期独立；函数返回后形参销毁

在函数内部 修改形参，只改 副本，不会影响 外部原始变量。

3. 示例 1：普通 int，传值改不动原变量

void func(int x)
{
    x = 100;   /* 只改形参副本 */
}

int main(void)
{
    int a = 10;
    func(a);
    /* a 仍是 10 */
    return 0;
}

原因：把 a 的数值 07 复制 给形参 x，两者完全独立。

4. swap 经典陷阱

void swap(int x, int y)
{
    int temp = x;
    x = y;
    y = temp;   /* 只交换了副本 x、y */
}

int main(void)
{
    int a = 1, b = 2;
    swap(a, b);
    /* a 仍是 1，b 仍是 2 —— 交换失效 */
    return 0;
}
  • x、y 只是 a、b 的 拷贝
  • 函数内交换副本，返回后副本销毁，主函数 a、b 保持原样
  • 要真正交换外部变量，需传 地址（指针）——见下文示例 2、ch5

5. 示例 2：传一级指针 —— 可修改指向的数据

void func(int *p)
{
    *p = 100;   /* 通过地址改原内存 */
}

int main(void)
{
    int a = 10;
    func(&a);
    /* a 变成 100 */
    return 0;
}

拆解（仍是值传递）：

  1. &a 得到 a 的 地址
  2. 把这个 地址数值 拷贝 给形参指针 p（不是把 a 本体搬进去）
  3. p 与调用时的 &a 存同一个地址
  4. *p 访问该地址上的 int，修改的就是外面的 a

6. 重点误区：一级指针改不了实参指针本身

void func(int *p)
{
    int b = 999;
    p = &b;   /* 只改形参 p 副本里存的地址 */
}

int main(void)
{
    int a = 10;
    int *ptr = &a;
    func(ptr);
    /* ptr 依旧指向 a，没有变成指向 b */
    return 0;
}
操作 效果
*p = 100 改 指针指向的内容（外面可见）
p = &b 改 形参指针副本 存的地址（外面 ptr 不变）

p 是 ptr 的 副本；改副本里的地址，不影响 原指针 ptr。

7. 想改指针变量本身：传二级指针

void func(int **pp)
{
    int b = 999;
    *pp = &b;   /* 解引用改「原指针 ptr」里存的地址 */
}

int main(void)
{
    int a = 10;
    int *ptr = &a;
    func(&ptr);
    /* ptr 现在指向 b */
    return 0;
}

依旧是值传递：把 &ptr（指针变量的地址）拷贝给形参 pp。
*pp 就是外面的 ptr；通过 *pp = &b 才能改 实参指针变量本身。ch5 会系统讲。

8. 跨语言区分

语言 模型 与 C 的差异
C 纯传值 无引用形参；指针 = 拷贝地址
C++ 传值 + int &x 引用传参 写 C 时要 摒弃 引用思维
Java 基本类型传值；对象传 引用的拷贝 对象形参改字段，外面可见；但 不能 让外面变量指向新对象（类似 C 一级指针陷阱）
Python 名字绑定对象；传的是 对象引用的拷贝 可变对象原地改可见；重新赋值形参不影响外面

从 C++/Java 转 C：「传指针就能改外面」 只对 *p 改内容 成立，对 p 改指向 不成立。

9. 数组特例（预告）

数组作实参时会发生 数组退化（decay） 为 指向首元素的指针 —— 表面像「传地址」，本质仍是 拷贝指针值（地址）。
本章统一用 传值 + 副本隔离 心智；ch05 详讲。

1.8

.1 指针形参、`&` 取地址、`*` 解引用

本节讲什么

一次性讲清四个常混概念：普通变量、指针形参、& 取地址、* 解引用。承接 1.8 参数传值调用 —— C 永远值传递；形参写 int *p 时，实参该传 数字 还是 地址？何时写 &、何时直接传指针名？

声明 * vs 表达式 *： Pointers on C · 6.0

四个核心概念

符号/写法 是什么 例子
变量 a 存 数据 的内存单元 int a = 10; — a 里是 10
&a 取地址 — 得到 a 所在内存的地址（指针值） &a 类型是 int *
int *p 指针变量 p，专门存 地址 p = &a;
*p 解引用 — 通过 p 里的地址访问那块内存里的 数据 *p = 999; 改的是 a 
  变量 a          指针 p
┌─────────┐      ┌─────────┐
│  10     │ ←──  │ &a 地址 │
└─────────┘      └─────────┘
   数据              存的是「指向 a 的地址」

一、形参是指针，实参怎么传？

规则：形参类型是 int *p（指针）→ 实参必须传 地址，用 &变量 取出地址。

示例 1：普通变量 → 必须 &num

#include <stdio.h>

void func(int *p)
{
    *p = 999;   /* 通过地址改外面 num 的值 */
}

int main(void)
{
    int num = 10;

    func(&num);          /* 形参是指针 → 实参传 &num */
    printf("%d\n", num); /* 999 */
    return 0;
}

逻辑拆解：

步骤 说明
1 func 形参 int *p → p 只能接收 地址
2 num 是普通 int，存的是 数字 10，不是地址
3 func(num) 类型错误 — 不能把 int 当 int * 传
4 &num = num 的内存地址 → 类型 int *，匹配形参
5 仍是 值传递：把 地址这个值 拷贝给 p；*p = 999 改的是 num 所在内存

示例 2：不用指针 — 值传递改不动外面

void func(int x)
{
    x = 999;   /* 只改副本 */
}

int main(void)
{
    int num = 10;
    func(num);           /* 传数字 10 的拷贝 */
    printf("%d\n", num); /* 仍是 10 */
    return 0;
}
传参方式 传进去的是什么 函数里改形参 外面变量
func(num) 数值 拷贝 改副本 不变
func(&num) 地址 拷贝给 int *p *p = … 改原内存 变

口语里的「传地址」在 C 标准里仍是 把地址当作值拷贝给指针形参，不是 C++ 引用。

二、实参已经是指针 — 不用再加 &

主函数里 已有指针变量 p，且 p 里已经存了地址时，直接传 p：

void func(int *pt)
{
    *pt = 666;
}

int main(void)
{
    int a = 20;
    int *p = &a;   /* p 里已是 a 的地址 */

    func(p);       /* 传指针变量 p，不要写 func(&p) */
    return 0;
}

关键区分（必背）

实参类型 写法 原因
普通变量 num func(&num) 要取出 变量的地址
指针变量 p func(p) p 本身就是地址值
错误 func(&p) 传的是 指针变量 p 自己的地址（int ** 才需要，见 1.8 二级指针） 
int num = 10;
int *p = &num;

func(&num);  /* 对：把 num 的地址给 int * 形参 */
func(p);     /* 对：p 里就是 num 的地址 */
func(&p);    /* 错：除非形参是 int **，否则类型不匹配 */

三、& 和 * 在传参里的分工

运算符 名称 在传参场景的作用
& 取地址 从 普通变量 生成指针值，匹配 int * 形参
* 解引用 在函数 内部，通过指针形参访问/修改 原变量 的数据

一句话：形参是 int *p 时 —— 外面用 &变量 把地址送进来；里面用 *p 动原来的数据。

五、误区 1：定义里的 * 不是解引用，是类型修饰符

* 分两种场景，含义完全不同，不能混：

场景 写法 * 的含义
定义变量 int *p; 类型修饰：p 是指针；int 表示 *p 解引用后得到的是 int 类型 — 此处 没有 解引用动作
执行表达式 *p = 100; 解引用运算符：用 p 里的地址去内存读/写数据 
int a = 10;
int *p = &a;   /* 定义时 *：标记 p 是 int 型指针 */
*p = 20;       /* 表达式里 *：解引用，改 a */
声明 读法
char *q q 是 char 指针；*q 得到 char
float *f f 是 float 指针；*f 得到 float

极简：int *p 里定义时的 * = 类型标记；代码里的 *p = 解引用操作 —— 两个不是一回事。

六、误区 2：指针里都存地址，为什么还要 int* / char* / float*？

对的一半：所有指针变量存的都是 内存地址（一串数字）；64 位下指针变量自身通常都占 8 字节，32 位 4 字节。

关键：地址只是 起始编号；编译器不知道从该地址起 读几个字节、按什么规则解释 二进制。

假设地址 0x1000 处字节为：61 00 00 00（小端示意）

指针类型 *p 行为
char *p 读 1 字节 → 'a'（0x61）
int *p 读 4 字节 0x1000~0x1003 → 整数（如 97）
float *p 同样 4 字节，按 IEEE 754 解析 → 浮点数（完全不同于 int 97）

指针类型决定两件事：

  1. 解引用时读多少字节（步长 / sizeof）
  2. 二进制按什么语义解析（整数 / 字符 / 浮点）

不分类型，编译器只有门牌号，不知道屋里是 1 字节字符还是 4 字节浮点 —— 运算、赋值、传参全乱。

七、误区 3：「地址是整数，所以指针都该是 int*」

  • 指针变量里存的：地址数值（可想象成整数）
  • 指针指向的内存里存的：类型由 int / char / float 决定

类比：门牌号都是数字，门后住的东西不同：

类型 门后（解引用 *p）
char* 1 个字母
int* 一整块整数（通常 4 字节）
float* 按浮点规则解读的数

不能把 char* 当 int* 乱传 —— 地址数字可能一样，解引用读宽度和语义不同。

底层另有 void* 等特殊规则；本章先建立「类型带语义」心智，ch05 / ch02 再讲 void*、严格别名。

八、串一遍：&num 与 &ch 为何不能混用

void func_int(int *p)   { *p = 100; }
void func_char(char *p) { *p = 'b'; }

int main(void)
{
    int num = 1;
    char ch = 'a';

    func_int(&num);   /* &num 类型 int*，匹配形参 */
    func_char(&ch);   /* &ch  类型 char*，匹配形参 */
    return 0;
}
  • &num 不只是「一个地址数字」，类型是 int * —— 告诉编译器：从这里起按 int 解读
  • &ch 类型是 char * —— 按 char 读 1 字节
  • 地址 数值格式 相似，类型不同 就不能 func_int(&ch) —— 解引用会读错宽度、错语义

九、与 1.8 两层修改对照

void f(int *p)
{
    *p = 100;    /* OK：改指针指向的内容（外面可见） */
    p = NULL;    /* 只改形参 p 的副本，外面 ptr 不变 */
}

详见 1.8 §6–§7 一级指针改不了实参指针本身、二级指针 int **。

十、极简收尾

  1. int *p：p 存地址；int 规定 *p 取出的是 整型语义 + int 宽度
  2. 所有指针存的地址都是数字，但 指向内存的长度与编码规则不同，必须用 int/char/float 区分
  3. 定义里的 * = 类型标记；表达式里的 *变量 = 解引用 —— 两码事

HFT / 底层提示

  • API 设计：void update_price(int *ticks) + 调用 update_price(&price) — 模式固定
  • 已有指针：Order *o = …; process(o); — 不要画蛇添足 process(&o)（除非要改 o 本身）
  • 热路径：弄清传的是 数据拷贝 还是 地址拷贝，避免隐式大结构体传值

  1. 可读写：line[i] = 'x' 自由改单个字符
  2. 遍历：循环直到 '\0'、换行 '\n' 或 EOF（读入时）
  3. 边界：固定长度 MAXLINE，超出 → 缓冲区溢出（本章截断防溢出）

7. 最长行程序：算法思路

循环读每一行
  → getline 读入 line[]，返回长度 len
  → 若 len > max：更新 max，copy(line → longest)
输入结束 → 打印 longest
缓冲区 作用
line[MAXLINE] 临时，每读一行覆盖
longest[MAXLINE] 持久，仅出现更长行时覆盖

8. 完整源码（无 string.h、无动态分配）

注意：下文 getline 是 K&R 自定义函数，不是 POSIX getline(3)。

#include <stdio.h>

#define MAXLINE 1000   /* 单行最大字符数（含 '\n'，不含末尾 '\0' 占位逻辑见下） */

int getline(char line[], int lim);
void copy(char to[], char from[]);

int main(void)
{
    int len;
    int max = 0;
    char line[MAXLINE];
    char longest[MAXLINE];

    while ((len = getline(line, MAXLINE)) > 0) {
        if (len > max) {
            max = len;
            copy(longest, line);
        }
    }

    if (max > 0)
        printf("最长行：%s", longest);

    return 0;
}

/* 读一行存入 s，返回该行字符总数（含 '\n' 若存在） */
int getline(char s[], int lim)
{
    int c, i;

    for (i = 0; i < lim - 1 && (c = getchar()) != EOF && c != '\n'; ++i)
        s[i] = c;

    if (c == '\n') {
        s[i] = c;
        ++i;
    }

    s[i] = '\0';
    return i;
}

/* 手动拷贝：逐字符直到源串 '\0'（含 '\0' 一并拷贝） */
void copy(char to[], char from[])
{
    int i = 0;

    while ((to[i] = from[i]) != '\0')
        ++i;
}

9. 关键函数与变量说明

getline(char s[], int lim)

  • 循环上限 lim - 1：预留 1 字节给 '\0'，防溢出
  • 若读到 '\n'，一并存入 数组（K&R 风格行含换行符）
  • 强制 s[i] = '\0'，保证合法 C 字符串
  • 返回值 i：本行总字符数（含 '\n'）
  • 空行仅 "\n" → 长度 1
  • EOF 且无字符 → 0，while 结束

copy(char to[], char from[])

  • 逐字符 to[i] = from[i]，直到拷贝到 '\0'
  • 不能写 to = from —— 数组名是 地址常量，不能整体赋值

#define MAXLINE 1000

  • 单行容量上限；超长输入 截断，尾部丢失（易错点 §）

12. 为何不单独造 string 类型？

  1. 极简设计：复杂结构用数组、指针、结构体搭建
  2. 统一字节模型：文本与二进制都是 char 序列 — 文件 I/O、网络包、协议解析同一套底层
  3. 零开销：无隐藏分配；HFT/内核可完全掌控缓冲生命周期

一句话：C 的「字符串」= 带 '\0' 结尾的 char[] / char*，不是独立数据类型。

C 字符数组 vs C++ std::string

对比维度 C（本章 char[]） C++ std::string
底层表示 char buf[N] + 手动 '\0' 封装类，内部自动管理缓冲
获取长度 手动计数 / 后续 strlen .size() / .length()，通常 O(1)
内存边界 固定大小，越界 → 缓冲区溢出 动态扩容，相对安全
拼接/查找 手动循环或 ch7 strcat/strstr +、find、erase 等
内存管理 栈上静态数组；堆需 malloc/free RAII 自动释放
头文件 <stdio.h>；串函数 ch7 <string.h> <string>

HFT / 底层开发的用处

  1. 固定栈缓冲：热路径日志、临时格式化常用 char buf[256]，长度可控、无 malloc
  2. 协议字段：定长 symbol、memcpy 前须知 NUL 与可见字符边界
  3. 最长行模式：环形缓冲里「当前最长帧」与 K&R 最长行同构 — 维护 max + 拷贝赢家

本节高频易错点

  1. 忘记末尾 '\0' → printf / copy 越界读、乱码
  2. 容量算错：循环应 < lim - 1，不是 < lim
  3. 混淆长度：getline 返回值 含 '\n'；日后 strlen 不含 '\0'、通常 不含 '\n'（除非串里真有）
  4. 超长输入：超过 MAXLINE-1 可见字符被截断，静默丢数据

1.10

外部变量与作用域

本节讲什么

承接 1.9 最长行示例，对比 自动局部变量 与 外部全局变量；区分三个核心概念：

  1. 作用域（scope）：在 当前 .c 里 哪段代码 能看见这个名字（编译期）
  2. 链接（linkage）：链接器合并多个 .c 的 .o 时，同名符号能否关联 —— static = 内部链接（各编译单元各用各的）；无 static = 外部链接（可合并成一份）。编译单元 ≈ 一个 .c 文件（4.4 §3、4.5）
  3. 存储期 / 生命周期（lifetime）：内存 何时分配、何时释放（运行期）

讲清 四种作用域、extern 声明、定义 vs 声明（Define once; declare many times），用 全局变量版最长行 做完整示例，铺垫 ch04 存储类（4.4 四种作用域、4.3 外部变量、4.6 静态变量）、多文件编译、static。

要点

1. 局部自动变量（auto）

定义位置：函数或代码块 {} 内部；默认存储类 auto（关键字可省略）。

特性 说明
作用域 仅当前函数/块内可见；getline 的 i 与 copy 的 i 互不干扰
生命周期 函数调用时在 栈 分配，返回即释放；多次调用 不保留 上次值
初值 未赋值 → indeterminate（垃圾值），不 自动清零

短板：函数间无法直接共享数据，只能靠 1.8 传参/返回值；复杂时参数列表冗长。

2. 外部变量与全局变量

定义位置：所有函数 之外（文件顶层）。

一句话：从 定义开始 到 整个程序结束 都有效，内存 一直在（不像局部变量函数结束就销毁）。其中 无 static 的全局变量 就是 外部变量（外部链接），同一程序 里有多少个 .c 都行：一处定义，其他文件 extern 声明 即可跨文件共用 同一份 对象。static 全局 虽也在全局/静态区，但 仅限本 .c，不能被他文件 extern（见 4.3 §1.1）。

特性 说明
存储 静态数据区；程序启动分配，退出释放
生命周期 启动 → 结束；函数返回 不 销毁全局
跨文件 他文件 extern int x; 引用，不重复分配（详见 4.3 §2）
初值 未显式初始化 → 编译器 清零（0、'\0'、NULL）
坏处 修改点分散、耦合高、难测试、难追踪
  1. 本文件：从 定义行 到文件末尾，所有函数可见（文件作用域）
  2. 加 static：作用域 仅限本 .c，他文件 不能用（extern 也无效）；防不同文件间同名冲突
  3. 无 static：外部链接；他文件 extern 声明后 可直接用 —— 作用域扩展到整个项目多文件（4.4 §1②）
  4. 多文件：一处 int num; 定义；其余 extern 或 include 头文件；禁止两文件各定义无 static 同名全局

3. 定义 vs 声明（本节重中之重）

定义（definition） 声明（declaration）
写法 文件顶层 不带 extern extern 开头
内存 分配 存储 不分配，仅引用已有对象
次数 整个程序 只能一次 可 多次 
int max;              /* 定义：分配内存 */
extern int max;       /* 声明：不分配，引用别处/本文件前面的定义 */

准则：Define once; declare many times（定义一次，声明多次）。

extern 两种场景：

  1. 同文件：全局变量定义在函数 后面 时，函数内要先 extern int max; 才能用
  2. 多文件：A.c 定义，B.c extern 引用；更常见是 a.h 里 extern int global_num;，B.c/C.c 只 #include "a.h" 即可读写 同一份 global_num —— 谁改谁可见最新值（见 4.5 §2.1）

extern int a; 不能 同时做定义式初始化（C 里带初始化的 extern 仍是定义）；int a = 1; 在文件顶层才是定义并赋初值。

4. K&R 示例：用外部变量重写最长行

getline 改名为 mgetline，避免与 POSIX getline(3) 冲突。

#include <stdio.h>

#define MAXLINE 1000

/* 外部变量定义：全局，分配内存 */
int max;
char line[MAXLINE];
char longest[MAXLINE];

int mgetline(void);
void copy(void);

int main(void)
{
    int len;

    extern int max;           /* 显式 extern（定义在顶部时可省略） */
    extern char longest[];

    max = 0;
    while ((len = mgetline()) > 0) {
        if (len > max) {
            max = len;
            copy();
        }
    }
    if (max > 0)
        printf("%s", longest);
    return 0;
}

int mgetline(void)
{
    int c, i;

    extern char line[];

    for (i = 0; i < MAXLINE - 1 && (c = getchar()) != EOF && c != '\n'; ++i)
        line[i] = c;
    if (c == '\n') {
        line[i] = c;
        ++i;
    }
    line[i] = '\0';
    return i;
}

void copy(void)
{
    int i = 0;

    extern char line[], longest[];

    while ((longest[i] = line[i]) != '\0')
        ++i;
}

7. 优缺点与工程禁忌

优势

  1. 多函数共享数据时 简化参数（全局缓冲、配置）
  2. 调用间 持久状态（计数器、最长行 max）
  3. 多文件共享 单一资源（需注意链接与可见性）

滥用缺陷（重点）

  1. 强耦合：任意函数可改，逻辑难追踪
  2. 难调试：多处写入，难定位谁改了值
  3. 不可重入 / 线程不安全：竞态；内核/HFT 热路径须 锁或无锁设计
  4. 单元测试难：函数依赖全局环境，无法隔离

工程建议：大型项目用 结构体 + 指针传参 封装状态；全局仅用于 真正单一实例 的资源（且加 static 或锁）。

内核 / HFT 拓展

  1. 共享全局状态配 自旋锁 / 互斥锁；热路径避免无保护全局写
  2. 模块私有：static 全局变量 — 文件内可见，不污染符号表
  3. 跨模块：Linux EXPORT_SYMBOL / EXPORT_SYMBOL_GPL 导出；对应「受控的全局接口」
  4. 超大缓冲：勿放栈上局部数组（栈溢出），可全局/static/堆分配

本节高频易错点

  1. 定义 vs 声明：extern int a; 不分配内存；int a = 1; 才是定义
  2. 重复定义全局变量 → 链接 multiple definition
  3. 局部遮蔽全局，误以为改的是全局
  4. static 全局：只 缩作用域，不改变静态存储期（ch4）
  5. 大数组放栈：局部 char buf[1<<20] → 栈溢出；改全局或 malloc
  6. 多文件 未 extern → undefined reference / 未声明标识符

题目 1： 以下代码中 sp 在多线程环境下有什么问题？

int sp = 0;
double val[MAXVAL];
void push(double f) { val[sp++] = f; }
double pop(void) { return val[--sp]; }
参考答案

sp 是全局变量，多线程同时 push/pop 会有数据竞争——两个线程同时 sp++ 可能丢失一次递增。需要加锁保护或用线程局部存储（_Thread_local，C11）。全局变量还降低模块化程度、增加耦合。K&R 时代没有多线程概念，现代代码应尽量避免全局状态。
