3.1

语句与程序块

本节讲什么

C 程序由 语句 组成；多条语句可用花括号 {} 打包 成一条 复合语句（块）。块既是 if、循环、函数体里「管多条语句」的手段，也定义 块作用域 —— 块内声明的变量，出了 {} 就不能再用。

后续：3.2 if-else、1.10 作用域、2.4 声明。

要点

1. 语句与分号

  • 多数语句以 ; 结束：表达式语句、声明、空语句 ;
  • 控制流（if、for、while 等）按各自语法，不都在末尾加单独分号代表「整条控制流结束」

2. 复合语句：把多条语句「打包」成一条

{
    printf("A\n");
    printf("B\n");
}

语法上 { ... } 整体算一条语句，因此可以写在只允许 一条 子语句的位置（if、else、for 体等）。

概念 说明
复合语句 { 声明; 语句; ... }
作用 把多条语句合成 一条，交给 if / 循环管辖
无 {} 控制流只能管 紧挨着的那一条 语句

3. if 不加花括号：只管 紧挨着的一条

规则：if (条件) 后面若 没有 {，则只管辖 语法上紧跟其后的那一条完整语句；再下一行起，已经不在 if 里。

什么叫「一条语句」？

算 一条 不算「多行多条」
printf("ok\n"); 两个带 ; 的表达式语句 = 两条
return n;
{ ... } 复合语句 块内可有 10 行，整体仍算一条 
if (ok) {
    a();
    b();
}   /* 花括号把 a、b 打包成「一条」复合语句 */

经典误读：第二行「看起来在 if 里」

if (score >= 60)
    printf("及格\n");
    printf("发证书\n");   /* 不在 if 里！无论真假都会执行 */

编译器分组（等价写法）：

if (score >= 60)
    printf("及格\n");
printf("发证书\n");        /* 与 if 同级，已脱离 */

缩进 不改变 语法；只有 {} 或「确实只有一条语句」才算在分支内。

缩进不是语法（新手高频坑）

C 完全不看缩进，只认 语法结构。第二条语句与 if 对齐得再整齐，没有 {} 就不在 if 里：

if (score >= 60)
    printf("及格\n");
    printf("发证书\n");   /* 缩进对齐，仍在 if 外 */
误区 实际
「两行对齐了，都在 if 里」 错 —— 只认紧挨的一条
Python 靠缩进表块 C 靠 {} 和分号
多缩进 = 进分支 无效

踩坑原因：把 缩进当语法；读 C 要画 {} / 分号 的语法树，不能靠眼睛对齐。

/* 乱缩进也一样：只有第一条归 if */
if (x)
printf("only this\n");
        printf("always runs\n");

加花括号：两条都归 if 管

if (score >= 60) {
    printf("及格\n");
    printf("发证书\n");   /* 只有及格才执行 */
}

if-else 时：各自也只搂住一条（无 {}）

if (x > 0)
    printf("正\n");
else
    printf("非正\n");
printf("结束\n");          /* 三条分支语句执行完后都会执行 */

if (x > 0)
    if (x < 10)
        printf("小正\n");
else
    printf("???\n");       /* else 只绑内层 if，见 3.2 §5 */

while / for 同理

while (n-- > 0)
    sum += a[i++];
    i++;                   /* 不在 while 里！循环体实际只有 sum 那一行 */

for (i = 0; i < n; i++)
    process(i);
    log(i);                /* 每次循环结束都会 log，不在 for 体内 */

循环与 if 相同：无 {} → 体部 = 紧挨着的一条。

工程习惯

建议 原因
分支/循环体一律 {} 防插入第二行掉出控制流
不依赖缩进表达结构 读代码的人、diff、宏展开都靠语法树
无 {} 有 {}
管辖范围 下一条语句 only 块内全部
多行时 第 2 行起 易失控 意图明确

4. 块作用域：出了 {} 变量不可用

块内 声明 的标识符，从声明点到 } 可见；离开块后 名字失效（对象销毁，见 1.10 生命周期）。

{
    int x = 1;
    printf("%d\n", x);
}
/* x 在此不可见，不可再使用 */

if (n > 0) {
    int i;
    for (i = 0; i < n; i++)
        /* ... */
}  /* i 仅在此 if 块内有效 */
项 说明
可见性 块内声明 → 块外 不能引用
生命周期 进入块创建（若未 static），离开 } 销毁（自动存储）
隔离 不同块可同名变量，互不影响

5. C89 vs C99 声明位置

标准 块内声明
C89 须在块 第一条语句之前
C99 用到再声明；for (int i = 0; …) 合法（2.1.1 C99）

6. 单独 {} 限制临时变量

while (read_pkt(&hdr) == 0) {
    {
        uint32_t len = ntohl(hdr.len);  /* 仅本迭代需要 */

    }
}

热路径用块 缩小变量作用域，利优化与审查。

3.2

if-else 语句

本节讲什么

根据条件选择执行路径：if 单分支、if-else 双分支。条件为 表达式：非 0 为真、0 为假（与 2.6 关系/逻辑运算 一致）。语法简单，但 else 就近匹配、无 {} 只管住一条 是经典易错点（见 3.1 块）。

要点

1. 形式

if (表达式)
    语句;

if (表达式)
    语句1;
else
    语句2;

if / else 后面各跟 一条语句 —— 可以是单条表达式语句，也可以是 { 复合语句 }（打包多条）。

2. 真假规则：非 0 即真，只有 0 为假

if 判断的是表达式 最终的值，不是「是否为 1」：

条件 结果
if (5)、if (-3) 真 → 进 if 分支
if (0) 假 → 跳过 if，有则进 else
if (x > y) 结果为 0/1，0 假 1 真 
if (5)
    printf("总是执行\n");

if (0)
    printf("永不执行\n");
else
    printf("走 else\n");

C89 无 bool 类型；C99 可用 _Bool / <stdbool.h>，但 if 仍看 0 / 非 0（2.1.1 C99）。

3. 指针作条件

指针 当 if 条件
非空 真
NULL / 空指针 假 
if (p)
    use(p);

if (!p)
    return -1;

if (p != NULL && p->len > 0)   /* 短路判空，见 2.6 */
    parse(p);

if (p) 与 if (p != NULL) 语义相同；团队统一风格即可。非空 ≠ 指针合法（野指针、悬垂仍可能非 0）。

4. 无花括号：只管住一条

if (ok)
    step1();
    step2();    /* 不在 if 里！ */

有 else 时同样：只有 else 前面那条 属于 if，else 与 最近未配对的 if 绑定（见下节）。

5. else 就近匹配（悬空 else）——分步模拟

规则：else 与 离它最近、尚未匹配 else 的 if 配对；不是「视觉上最外层」的 if。

5.1 无花括号嵌套：编译器实际看到的结构

if (n > 0)              /* 外层 if —— 记为 IF_OUT */
    if (n < 100)        /* 内层 if —— 记为 IF_IN  */
        return n;
else                     /* 与谁配对？ */
    return -1;

配对过程（从 else 往上扫）：

  1. 遇到 else，需要找「最近的、还没有 else 的 if」
  2. 往上看：紧挨 else 上方是 return n;（属于 IF_IN 的体）
  3. 再往上是 if (n < 100) → 这是 IF_IN，且 尚未有 else
  4. else 绑定 IF_IN，不是 if (n > 0)

编译器等价解析（缩进表达逻辑，不是写法要求）：

if (n > 0)
    if (n < 100)
        return n;
    else                    /* else 属于内层 if */
        return -1;
/* 外层 if (n > 0) 没有 else！ */

5.2 真值表：你以为 vs 实际

n 程序员常以为 实际执行
50 return 50 return 50 ✓
150 可能走外层 else → return -1 不进内层 n<100；内层 else 执行 → return -1 ✓（此例碰巧一致）
-5 外层假，跳过？ 外层假，不进任何 if 体；return -1 不执行 → 函数继续往下走（与「外层 else」预期不同）

n = -5 是关键：若你以为 else 属于外层「n>0 不成立就 -1」，会错——**根本没有外层else**，-5` 时 什么都不 return。

5.3 再加一层：else 永远找「最近」

if (a)
    if (b)
        if (c)
            f();
        else
            g();    /* 匹配 if (c)，不是 if (a) 或 if (b) */
else 绑定 不是
if (c) if (b)、if (a)

5.4 加花括号：明确「else 归谁」

意图：仅当 n > 0 且不在 (0,100) 内才 -1 vs 只要 n <= 0 就 -1 —— 必须用 {} 写清：

/* 意图：n<=0 走 else */
if (n > 0) {
    if (n < 100)
        return n;
} else {
    return -1;
}

/* 意图：n>0 但 n>=100 走 -1（内层 else） */
if (n > 0)
    if (n < 100)
        return n;
    else
        return -1;

第二种在 n > 0 已成立 的前提下，由 内层 else 处理 n >= 100；n <= 0 仍不会进 return -1（除非外层另有逻辑）。

工程习惯：复杂嵌套 哪怕只有一条语句也加 {}，避免 else 挂错层。

5.5 经典 K&R 示例（原文结构）

if (n > 0)
    if (n < 100)
        return n;
else
    return -1;

与 §5.1–5.2 相同：else → 内层 if (n < 100)。

改写：外层加块，或 3.3 else-if 扁平化：

if (n > 0) {
    if (n < 100)
        return n;
} else {
    return -1;
}

6. 高频坑

坑 说明
if (x = y) 赋值，非比较；结果非 0 则永远进 if（2.6 = vs ==）
浮点 if (a == b) 慎用；用 epsilon（2.2.1 float.h）
无 {} 多行 第二行不在分支内
宏展开 if (x) MACRO(); 注意宏内多条语句需 do { } while(0)

7. 示例

if (x > y)
    printf("x is greater\n");
else
    printf("x is not greater\n");

if (mbuf != NULL) {
    if (mbuf->data_len > 0)
        decode(mbuf);
} else {
    stats.null_mbuf++;
}

HFT / 内核提示

  • 热路径：if (unlikely(err)) 风格 —— 条件仍是 非 0 真
  • 协议：if (flags & RX_OK) —— 位与结果非 0 为真；测单 bit 用 (flags & MASK) != 0 更清晰（2.9）
  • 分支内始终 {}，避免维护时插入第二行掉出 if

题目 1： 以下代码的 else 匹配哪个 if？如何修改？

if (a > 0)
    if (b > 0)
        x = 1;
else
    x = 2;
参考答案

else 匹配最近的 if（if (b > 0)），不是 if (a > 0)。这叫「else 悬空」问题。如果想让 else 匹配外层 if，加花括号：

if (a > 0) {
    if (b > 0)
        x = 1;
} else {
    x = 2;
}

规则：始终用花括号，即使只有一条语句。

3.3

else-if 多分支结构

本节讲什么

把多层嵌套 if 写成 if ... else if ... else 链，按顺序测试条件，命中即执行并跳过后续分支。适合多状态、多档位判断。

要点

  • 语法糖：else { if (...) ... } 写成 else if (...) ...
  • 自上而下依次求值，第一个为真的分支执行后，整条链结束
  • 各分支互斥；若可能同时满足多个条件，顺序即优先级
  • 末尾可选 else 作兜底（未匹配任何条件时执行）
  • 比深层嵌套 if 更易读、更少 else 配对错误

示例

if (n < 0)
    sign = -1;
else if (n == 0)
    sign = 0;
else
    sign = 1;

与 switch 的选择

场景 更合适
离散整型常量（状态码、枚举） switch（3.4）
区间、不等式、浮点比较 else if 链
条件复杂且各不相干 else if 或拆成独立 if

else-if 链的求值机制

if (cond1)      body1;       // cond1 为真 → 执行 body1，跳过整条链剩余部分
else if (cond2) body2;       // cond1 假 + cond2 为真 → 执行 body2
else if (cond3) body3;       // cond1 假 + cond2 假 + cond3 为真
else            body_default; // 全部为假

关键：这是顺序短路求值——一旦某个条件为真，后续条件不会被求值。如果条件有副作用（函数调用），顺序直接影响行为。

常见陷阱

  1. dangling else（悬空 else）：if (a) if (b) x; else y; 中 else 与最近的 if (b) 配对，不是 if (a)。缩进不能改变配对规则。想 else 配外层 if，必须加花括号：if (a) { if (b) x; } else y;。K&R 专门强调这一点。现代编译器加 -Wdangling-else 可告警。

  2. 把高频分支放在链尾：100 个 else-if 从头测试到尾，最坏 O(n)。如果统计数据已知，应把高频分支放前面。更彻底的优化：switch + jump table（O(1)）或查找表/哈希。协议解析中 90% 流量是某一种消息类型，放第一个分支立即返回。

  3. 条件有副作用时顺序敏感：if (next() > 0) ... else if (next() > 0) ... ——第二个分支里的 next() 只有在第一个为假时才调用。如果 next() 有副作用（读游标前进），改变分支顺序会改变行为。应先取出所有需要的值，再用纯条件判断。

自测题

1. 选择：以下代码 else 与哪个 if 配对？

if (a)
    if (b)
        x = 1;
else
    x = 2;
  • A. 与 if (a) 配对
  • B. 与 if (b) 配对
  • C. 语法错误
  • D. 取决于缩进
答案

B。C 标准：else 与最近未配对的 if 配对，缩进不影响。代码等价于 if (a) { if (b) x=1; else x=2; }——a 为真且 b 为假时 x=2，a 为假时什么都不做。如果想 else 配外层，必须加花括号：if (a) { if (b) x=1; } else x=2;。编译选项 -Wdangling-else 可告警。

2. 判断：else-if 链中，如果第一个条件为真，后续条件的表达式仍会被求值。

答案

错。else-if 是顺序短路的——第一个为真的分支执行后，整条链结束，后续条件不会被求值。这与 && 的短路类似。如果后续条件含函数调用（如 else if (check_expensive())），不会执行。这在性能上有意义：把简单判断放前面、昂贵判断放后面。

3. 踩坑：以下代码在什么情况下 y 没有被赋值？

if (score >= 90) y = 'A';
else if (score >= 80) y = 'B';
else if (score >= 70) y = 'C';

缺少什么？

答案

当 score < 70 时，所有条件都不满足，y 未被赋值。如果后续使用 y，读的是未初始化值——UB。修复：末尾加 else y = 'F'; 兜底，或在使用前初始化 char y = 'F';。这是 else-if 链最常见的 bug：忘了兜底分支，边界值未处理。

4. 应用：用 else-if 链实现一个 log_level_to_str(int level)，0→"TRACE", 1→"DEBUG", 2→"INFO", 3→"WARN", 4→"ERROR"，未知返回 "UNKNOWN"。然后说明如何优化。

答案 
const char *log_level_to_str(int level) {
    if (level == 0) return "TRACE";
    else if (level == 1) return "DEBUG";
    else if (level == 2) return "INFO";
    else if (level == 3) return "WARN";
    else if (level == 4) return "ERROR";
    else return "UNKNOWN";
}

优化：离散整型常量用查找表更简洁高效：

static const char *names[] = {"TRACE","DEBUG","INFO","WARN","ERROR"};
if (level >= 0 && level <= 4) return names[level];
return "UNKNOWN";

O(1) 直接索引，无分支判断。switch 也可以（编译器可能优化为跳表），但查找表最直观。

题目 1： 以下 else-if 链的效率如何优化？

if (x == 1) ...
else if (x == 2) ...
else if (x == 3) ...
... (100 个分支)
参考答案

100 个 else-if 是 O(n) 线性查找。优化：1) 高频分支放前面；2) 用查找表（数组/哈希表）O(1)；3) 用 switch 编译器可能优化为跳表。如果 x 是小范围连续整数，switch + jump table 是最优选择。

3.4

switch 语句

本节讲什么

对 整型控制表达式 做 精准常量匹配 的多路分支：switch (表达式) + 若干 case 常量:。匹配后从该 case 继续向下执行（穿透 fall-through），直到 break、return、goto 或 switch 结束。与 3.3 else-if 互补——离散常量用 switch，区间/不等式用 else if。

前置：3.1 块与 {}、3.2 非 0 即真。

要点

1. 基本形式

switch (表达式) {
case 常量1:
    语句;
    break;
case 常量2:
    语句;
    break;
default:
    语句;
    break;
}
  • switch (表达式)：控制表达式须为 整型（char 会提升为整型比较）
  • 不能 对 float / double 做 switch（C 标准）

2. case 后必须是整型常量表达式

核心规则：case 后面只能是 整型类型的常量 —— 编译期就能确定的一个 整数标号。switch 做的是 整型相等跳转，不是通用多态分发。

可以写 不可以写
整数字面量 case 1:、case -3: 变量 case n:
字符常量 case 'a':（单引号 → ASCII 等 整型码值） 浮点数 case 1.0:、case 3.14:
enum 常量 case ST_RUN: 字符串 case "read":
宏常量 #define OP 3 → case OP: 运行时表达式 case a + 1:、case x > 0:

归纳记忆：

  • 数字 → 直接写
  • 字符 → 单引号，编译期转成码值整数
  • 除此之外（变量、浮点、字符串、不等式）→ 都不能 放 case 后面

精准匹配常量值 —— case 标签必须是 编译期可求值的整型常量，不能是变量或运行时表达式。

#define CMD_READ  1
enum { ST_IDLE, ST_RUN };

switch (op) {
case 'q':              /* 字符常量，按整型值匹配 */
    quit();
    break;
case CMD_READ:         /* 宏常量 */
    read();
    break;
case ST_RUN:           /* 枚举常量 */
    run();
    break;
default:
    break;
}

char 写 'A' 时，与 提升后的整型值 匹配（与 int 控制表达式一致）。

2.1 字符常量：单引号 + 单个字符 → 整型码值

字符常量就是用 单引号 括起来的 一个字符，例如 '5'、'#'、'x'。C 在编译期把它转成该字符在执行字符集里的 数值（常见环境即 ASCII 码）：

写法 含义 常见 ASCII 值
'a' 字母 a 97
'5' 字符 5（不是整数 5） 53
'#' 井号 35
'\n' 换行（转义字符 也算字符常量） 10 
'a' == 97;     /* 常见 ASCII */
'5' == 53;     /* 字符 '5' ≠ 整数字面量 5 */
'\n' == 10;    /* 换行符的码值 */

getchar() 读到的是码值（存 char 也会提升为 int），switch (c) 实际比较的是 整型相等——case 'a': 在 ASCII 下等价于 case 97:。正因为字符常量本质是整数，switch 才能用 case 匹配字符。

详见 2.3 字符常量。

2.2 单引号 vs 双引号：case 只能用前者

写法 类型含义 能否 case
'a' 单引号 单个字符 的整型常量（int 字符值） 可以 case 'a':
"a" 双引号 字符串（char 数组 / char *，含 '\0'） 不能 case "a": 
switch (c) {
case 'a':              /* OK：字符常量，整型值 97 等 */
    handle_a();
    break;
case '\n':             /* OK：转义字符常量，码值 10 */
    handle_newline();
    break;
/* case "a":           非法：case 标签须整型常量，字符串不是 */
}

记忆（与 1.1 入门、1.9 字符数组、2.3 常量 一致）：

  • 单引号 'x' → 一个字符 的常量，本质是 整数
  • 双引号 "x" → 字符串（至少 x + '\0'），是 地址 / 数组，不是编译期整型标号

switch 做的是 整型相等跳转，不是比字符串内容，故 case 不支持字符串。

2.3 字符串多分支：只能用 else if + strcmp

对 命令行参数、协议字段名、配置 key 等 字符串 分支，用 比较函数 链：

#include <string.h>

if (strcmp(cmd, "read") == 0) {
    do_read();
} else if (strcmp(cmd, "write") == 0) {
    do_write();
} else if (strcmp(cmd, "quit") == 0) {
    do_quit();
} else {
    fprintf(stderr, "unknown: %s\n", cmd);
}
方式 适用
switch + case 'q' 单个 字符（如 getchar()、快捷键）
else if + strcmp 完整字符串 多路匹配
哈希表 / 完美哈希（进阶） 大量字符串命令，冷路径配置

注意：strcmp 返回 0 表示相等 —— 要写成 strcmp(a, b) == 0，不能 if (strcmp(a, b)) 当相等（非 0 为真）。

/* 错：相等时 strcmp 返回 0，条件为假 */
if (strcmp(s, "ok"))

/* 对 */
if (strcmp(s, "ok") == 0)

2.4 C switch 限制多 —— 与其他语言对比

C 的 switch 是 整型常量表跳转，设计年代早、语义窄，不像很多现代语言 那样支持多种 case 类型或模式匹配：

语言 switch / 多分支能力（概览）
C 仅 整型控制表达式 + 整型常量 case；字符靠码值；字符串/浮点不行
C++ 同 C；C++17 起可选 enum class 更严，本质仍是整型标号
Java Java 7+ 可 switch (String)；enum；新版本有 switch 表达式
Go switch 无表达式也可；case 可为 表达式；另有 type switch
Rust 用 match 模式匹配，支持枚举、范围、绑定等，远比 C switch 强
JavaScript case 可写 字符串；比较用 ===（仍有限制，但比 C 宽）
C# 可 switch string；新版本 模式匹配

工程含义（HFT / 内核仍大量用 C）：

  • 协议 opcode、状态字、enum → C switch 很合适
  • 命令行子命令、配置 key 等字符串 → 老老实实 else if + strcmp（或表驱动）
  • 需要「按类型分发」→ C 没有 type switch，用 函数指针表 / 多态（C++ 另论）

C 的限制不是缺陷，而是 语义简单、可预测 —— 编译器易生成 跳转表，热路径开销低；代价是 表达能力 不如 Rust match / Go switch。

3. 穿透（fall-through）：匹配后一路往下

匹配到某个 case 后，从 该标号下第一条语句 开始执行，不会自动只执行本 case 就停 —— 必须靠 break 跳出，否则会 掉进下一个 case。

switch (n) {
case 1:
    printf("one\n");    /* 若缺 break */
case 2:
    printf("two\n");    /* n==1 时也会执行到这里 */
    break;
}

n == 1 输出：

one
two
结束穿透的方式 说明
break; 跳出整个 switch
return / goto 离开函数或跳转
switch 右花括号 } 自然结束

无匹配 且无 default：整个 switch 体 不执行。

4. 故意穿透 vs bug

刻意合并 多个 case 共用一段代码（K&R 数字分类）：

switch (c) {
case '0': case '1': case '2': case '3': case '4':
case '5': case '6': case '7': case '8': case '9':
    digit = c - '0';
    break;
case EOF:
    break;
default:
    digit = -1;
    break;
}

忘记 break 在业务代码里多为 bug；若故意穿透，必须注释 /* fall through */。

5. default

default:
    handle_unknown();
    break;
  • 可选；处理 所有未列出的值
  • 习惯放 末尾（可读性）；语法上位置不限

6. switch vs else if：怎么选？

不是在「谁更高级」之间纠结，而是看 条件形状：

场景 更合适 原因
离散整型常量（状态码、opcode、enum、ASCII） switch 常量表清晰；编译器可优化跳转表
区间 n < 0 / n > 100 else if case 不能写不等式
浮点、字符串比较 else if 不能 switch 浮点 / 字符串
多条件组合 a > 0 && b < 10 else if 或拆 if case 只比 相等
分支内逻辑差异大 皆可 switch 利于扫一眼所有状态码
分支要按优先级第一个命中 else if 自上而下，第一个真即停 
/* else if：区间、符号 */
if (n < 0)
    sign = -1;
else if (n == 0)
    sign = 0;
else
    sign = 1;

/* switch：状态机状态字 */
switch (state) {
case ST_IDLE:   idle();   break;
case ST_RUN:    run();    break;
case ST_ERROR:  error();  break;
default:        break;
}

HFT / 协议：报文 type 字段、msg id → switch；价格区间分档 → else if。

7. 与 if 相同的 {} 习惯

case 后若跟多条语句，用 {} 块（并产生块作用域）：

case OP_RESET: {
    int tmp = read_reg();
    reset(tmp);
    break;
}

单条语句可不加 {}；多条 建议加块，与 3.1 一致。

易混点

# 要点

3.5

while 循环与 for 循环

本节讲什么

回顾第 1 章已用过的循环，系统梳理 while 与 for 的等价关系、执行顺序，以及条件里写 i++ / ++i 时的差异。遍历、计数、条件驱动三种场景如何选型。

前置：3.1 块与 {}、3.2 非 0 即真、2.8 自增/自减。

要点

1. while：先判断，再执行

while (条件)
    语句;

执行顺序（每轮）：

  1. 先求值「条件」表达式（含其中的副作用，如 i++）
  2. 结果为 非 0 → 执行 循环体
  3. 回到步骤 1
  4. 结果为 0 → 跳出，不再执行循环体

条件 第一次就为假 时，循环体 一次都不执行。

int i = 0;
while (i < 3) {
    printf("%d ", i);
    i++;
}
/* 输出：0 1 2 */

2. 条件里写 i++：先用旧值比，再立刻自增

while 的「条件」是一个 完整表达式。若写成 while (i++ < 10)，自增发生在「判断」这一步，不是循环体里。

后置 i++ 规则（见 2.8）：

  1. 表达式 返回值 = 自增 前 的 i
  2. 整个子表达式求完后，i 立刻 +1

逐步示例：while (i++ < 10)

设 i 当前为 9：

步骤 发生的事
① 求 i++ 返回值 9；副作用 i 变为 10
② 求 9 < 10 成立 → 进入循环体
③ 循环体执行完 回到条件
④ 此时 i 已是 10；再求 i++ 返回值 10；i 变为 11
⑤ 求 10 < 10 不成立 → 循环结束

退出时 i 为 11（不是 10）—— 因为 最后一次 判断里 i++ 仍会把 07 加成 08，尽管比较结果为假。

int i = 0;
while (i++ < 10)
    printf("%d ", i);
/* 打印 1 2 3 ... 10 —— 共 10 次；结束时 i == 11 */

记忆：while (i++ < n) = 「用 当前 i 去比，比完 马上 i+1」；条件成立才进循环体。

3. 换成 ++i：先自增，再判断 —— 逻辑不同

前置 ++i：先 i+1，再用 新值 参与比较。

int i = 0;
while (++i < 10)
    printf("%d ", i);
/* 打印 1 2 3 ... 9 —— 共 9 次；结束时 i == 10 */
条件写法 首次用于比较的 i 典型循环次数（初值 0，界 10） 退出时 i
i++ < 10 旧值 0、1、… 10 次 11
++i < 10 新值 1、2、… 9 次 10
i < 10 + 体内 i++ 0、1、… 10 次 10

结论：条件里塞 ++/-- 时，前置与后置不等价；工程上更常见 for (i = 0; i < n; i++) 或 while (i < n) { ...; i++; }，把「比较」与「步进」拆开，可读性更好。

同一 i = 9：进不进循环，取决于写法

自增写在 while 条件里 时，直接改变「判断那一刻」的 i：

条件（i 当前为 9） 用于比较的值 判断后 i 本轮进不进循环体
i++ < 10 9（旧值） 10 进（9 < 10 成立）
++i < 10 10（新值） 10 不进（10 < 10 不成立） 
int i = 9;
while (i++ < 10)   /* 还能再进一轮 */
    body();
/* 判断用 9，i 变 10，进入 body */

int j = 9;
while (++j < 10)   /* 直接结束，体一次都不执行 */
    body();
/* 先 j=10，10<10 假，不进 body */

while 把自增塞进条件 → i++ 与 ++i 改变判断逻辑、循环次数、退出时 i，必须分开记。

4. for：自增在循环体之后 —— i++ 与 ++i 无差别

for (初始化; 条件; 步进)
    语句;

等价于：

初始化;
while (条件) {
    语句;
    步进;
}
for 特点 说明
三部分 任意可省略，分号保留 for (;;) = 无限循环
先判断、后步进 步进在循环体 之后 执行
初始化、步进可用逗号表达式 for (i = 0, j = n-1; i < j; i++, j--)
第三部分只求 副作用 i++ 与 ++i 等价 —— 判断逻辑与循环次数 不变

for 每轮顺序：判断条件 → 执行体 → 步进。第三部分 i++ / ++i 只负责让 i 前进，返回值不参与条件，故两种写法 完全等价：

for (i = 0; i < 10; i++)   /* 10 次，退出 i == 10 */
for (i = 0; i < 10; ++i)   /* 同上：次数、判断、终值都一样 */
while (i++ < 10) for (i=0; i<10; i++)
自增发生时机 判断时（条件表达式内） 体执行完之后（第三部分）
i++ vs ++i 不等价，改变次数与终值 等价，只关心 +1 副作用
与 i < 10 + 体内 i++ 不等价（时机不同） 等价

因此 for (i = 0; i < 10; i++) 与 while (i++ < 10) 不等价；与 while (i < 10) { ...; i++; } 才等价。

/* 字符计数 — while */
while ((c = getchar()) != EOF)
    ++nc;

/* 同上 — for（步进在体后，体可为空语句） */
for (nc = 0; (c = getchar()) != EOF; ++nc)
    ;

5. 无限循环

while (1) { ... }
for (;;) { ... }    /* 中间、第三部分皆空 */

内核线程、行情泵、事件循环常见；退出靠 break、return 或信号。

6. 选用建议

场景 倾向 原因
已知次数、下标遍历 for 初始化/条件/步进一目了然
读直到 EOF、等事件 while 条件在循环内才明确
条件含赋值 while ((c = get()) != EOF) while K&R 惯用写法
无限服务循环 while (1) / for (;;) 等价，风格问题
条件里写 i++ / ++i 慎用 易 off-by-one；见 §2、§3

易混点

# 要点
1 while 先判断；假则体 零次
2 条件里的 i++：先用旧值比，比完立刻 +1
3 while (i++ < 10) 退出时 i 常为 11（最后一次失败判断仍 ++）
4 i=9 时：while (i++<10) 能进；while (++i<10) 不进
5 for 步进在 体之后；i++/++i 等价，判断与次数不变

7 无 {} 时循环体只有 紧跟的一条语句（同 3.1）

HFT / 内核提示

  • 热路径遍历：for (size_t i = 0; i < n; ++i) —— 边界与步进分离，利于审查与向量化
  • while (read_pkt(&hdr) == 0)：条件驱动，比硬写 for 更贴语义
  • 避免 while (i++ < len) 处理缓冲区 —— off-by-one 是安全漏洞温床；显式 i < len + 体内 i++

3.6

do-while 循环

本节讲什么

先执行循环体，再判断条件；条件为真则继续。与 while 的关键区别：至少执行一次。口语里可记 「先斩后奏」 —— 不管条件一开始是真是假，先把循环体跑一遍，再决定要不要继续。适合「无论如何先干一遍，再根据结果决定要不要再来」的逻辑。

前置：3.5 while 与 for、3.2 非 0 即真。

要点

1. 语法格式

do {
    循环体;
} while (条件);    /* 末尾分号不能少！ */
部分 说明
do 关键字，表示「先进入循环体」
{ ... } 循环体；多条语句 必须用花括号
while (条件) 体执行 完之后 再判断
末尾 ; while (条件) 之后 必须有分号 —— 漏写是语法错误

单条语句 也建议写 {}，避免维护时加第二行却不在循环里（同 3.1）。

do
    x++;
while (x < 10);   /* 合法但可读性差；生产代码多用 {} */

2. 执行顺序：「先斩后奏」

每轮：

  1. 先执行循环体（不问条件）
  2. 再求值条件
  3. 非 0 → 回到步骤 1；0 → 退出

因此 无论条件一开始是真是假，循环体至少跑 1 次 —— 先干活，后审批。

口诀 含义
while 先奏后斩 —— 条件不过，体 一次都不执行
do-while 先斩后奏 —— 至少执行一次，再判要不要继续

3. 与 while 对比

while do-while
判断时机 每次迭代 之前 每次迭代 之后
最少执行次数 0 1
典型场景 可能零次（已 EOF、已满足退出） 先做一次，再决定要不要继续
语法 while (cond) stmt; do { stmt; } while (cond); 
/* while：条件一开始就假 → 体零次 */
while (0)
    printf("never\n");

/* do-while：至少打印一次 */
do {
    printf("once\n");
} while (0);

4. 典型场景：菜单程序（至少显示一次）

用户说的经典用法：先出菜单让用户选，再判断要不要退出 —— 菜单总得显示至少一遍。

#include <stdio.h>

    printf("=== Menu ===\n");
    printf("1. New file\n");
    printf("2. Open file\n");
    printf("0. Quit\n");
    printf("Choice: ");
    scanf("%d", &choice);

    switch (choice) {
    case 1: new_file();  break;
    case 2: open_file(); break;
    case 0: break;
    default:
        printf("Invalid choice, try again.\n");
        break;
    }
} while (choice != 0);

若改成 while (choice != 0) { ... }，还得在循环 之前 先赋初值或先显示一次菜单，否则要么多写重复代码，要么第一次逻辑别扭。do-while 把「至少显示一次」写进结构里。

5. 密码验证：比 while 更顺手的例子

验证密码：先让用户输入，再判断对不对；不对就再输 —— 第一次输入没有理由跳过，典型 先斩后奏。

#include <stdio.h>
#include <string.h>

#define PASSWORD "secret123"

char buf[64];
int ok;

do {
    printf("Enter password: ");
    if (scanf("%63s", buf) != 1)
        buf[0] = '\0';
    ok = (strcmp(buf, PASSWORD) == 0);
    if (!ok)
        printf("Wrong password, try again.\n");
} while (!ok);

printf("Access granted.\n");
写法 别扭之处
do-while 自然：读 → 判 → 错则继续
while (!ok) 进入循环前 ok 未定，得先 人为 设 ok = 0 或把 第一次读密码 写在循环外，逻辑拆成两段 
/* 用 while 也能写，但要多绕一步 */
int ok = 0;                    /* 仅为让 while 第一次能进体 */
while (!ok) {
    printf("Enter password: ");
    scanf("%63s", buf);
    ok = (strcmp(buf, PASSWORD) == 0);
    if (!ok)
        printf("Wrong password, try again.\n");
}

语义相同，但 do-while 更贴「至少试一次」 —— 条件 !ok 放在末尾，表示「这次没通过，要不要再来」。

3.7

break 与 continue

本节讲什么

在循环和 switch 中改变正常控制流：break 提前结束当前结构；continue 跳过本轮循环剩余语句，进入下一轮。嵌套循环时，二者 只作用于离它最近的那一层 —— 笔试与读代码的高频考点。

前置：3.5 while / for、3.4 switch、3.6 do-while。

要点

1. break：跳出 当前这一层

用在哪 效果
switch 结束整个 switch，不再执行后续 case（见 3.4）
循环（while / for / do-while） 跳出 最内层（enclosing）的那一圈循环

只跳一层 —— 不会一次跳出两层、三层嵌套。

2. continue：跳过本轮，进入 本层 下一轮

  • 仅用于循环，不能 用于 switch
  • 跳过 本次迭代 中 continue 之后的语句
  • 然后进入 同一层循环 的下一轮（不是外层）
循环类型 continue 之后
while / do-while 回到 条件判断
for 先执行 第三部分步进，再 条件判断 
for (i = 0; i < n; i++) {
    if (a[i] < 0)
        continue;   /* 跳过负数；i++ 仍会执行 */
    sum += a[i];
}

3. 嵌套循环：只影响 最近一层

两层 for 嵌套时，在内层写的 break / continue 只管内层，外层照常继续。

for (i = 0; i < 3; i++) {
    for (j = 0; j < 3; j++) {
        if (j == 1)
            break;      /* 只跳出内层 for(j) */
        printf("(%d,%d) ", i, j);
    }
    printf("| ");       /* 外层 for(i) 每轮都会执行到这里 */
}

输出（break 在内层 j == 1 时触发）：

(0,0) | (1,0) | (2,0) |

内层每次只打印 j == 0，然后 break；外层 i 仍 0→1→2 完整跑完。

continue 在内层：只跳过内层本轮

for (i = 0; i < 2; i++) {
    for (j = 0; j < 4; j++) {
        if (j % 2 == 1)
            continue;   /* 跳过内层 j 为奇数的那次 */
        printf("%d%d ", i, j);
    }
}

输出：

00 02 10 12

j == 1、j == 3 时被 continue 跳过，内层 j 的下一次（2、4…）照常进行；外层 i 不受影响。

写法位置 break continue
内层循环 只结束 内层；外层继续 只跳过 内层本轮；内层下一轮正常
外层循环 结束 外层（内层已不在） 跳过 外层本轮 剩余代码

4. 逐步理解：内层 break，外层继续

for (i = 0; i < 3; i++) {          /* 外层 */
    for (j = 0; j < 5; j++) {      /* 内层 */
        if (some_error(j))
            break;                 /* ① 只跳出内层 */
        process(i, j);
    }
    /* ② 内层 break 后到这里；外层 i++，开始新一轮内层 */
}
  • 内层 break ≠ 程序结束，也 ≠ 两层一起退出
  • 外层 不知道 内层是正常结束还是 break 出来的 —— 若需通知外层，用 标志变量 或 3.8 goto

5. 想一次跳出多层怎么办？

C 的 break 没有标签，不能写 break outer（Java 可以）。

做法 说明

标志变量 内层 break 前置 done = 1，外层每轮检查
goto 标号 内核/错误处理常见，跳到多层外（3.8）
return 直接结束 整个函数
改成函数 break 变 return，用返回值表示是否提前结束

        }
    }
}

3.8

goto 语句与标号

本节讲什么

C 保留 goto 与标号（label:），可从任意处跳转到同一函数内的标号。K&R 承认其存在，但不鼓励滥用；规范场景是多层循环统一出口或错误处理集中清理。

要点

  • 形式：goto 标号; 与 标号: 语句
  • 标号作用域为整个函数；不能跨函数跳转
  • 不能跳进另一个块并跳过变量初始化（C 规则限制，避免未初始化使用）
  • 书中推荐用途：
  • 深层嵌套循环一次跳出多层
  • 错误路径 goto err;，在 err: 集中释放资源（内核常见模式）

合理 vs 滥用

合理 滥用
统一错误处理、资源清理 替代结构化 if/循环， spaghetti 代码
从多重循环 breakout 正常业务分支全靠 goto
有限状态机代码生成、手写汇编对应 跳来跳去难以维护

示例（错误集中处理）

if (setup_a() < 0)
    goto fail;
if (setup_b() < 0)
    goto fail;
/* 正常路径 */
return 0;

fail:
    cleanup();
    return -1;

多层循环跳出也可 goto done;，比多个 flag + break 更清晰。

goto 的限制

限制 说明
不能跨函数 goto 只在同一函数内跳转，跨函数用 setjmp/longjmp（危险）
不能跳过 VLA 声明 跳过变长数组声明进入其作用域是 UB
不能跳过带初始化的声明（C99+） goto 跳过 int x = 5; 后使用 x 是 UB（GCC 报错）
标号作用域 = 整个函数 标号在函数内任何位置可见，但只能 goto 到已执行的标号之后

内核中的 goto 模式

Linux 内核大量使用 goto 做资源清理，典型模式：

int driver_probe(struct device *dev) {
    void *reg = ioremap(...);
    if (!reg) goto err_mem;

    int irq = request_irq(...);
    if (irq < 0) goto err_irq;

    /* ... 正常逻辑 ... */
    return 0;

err_irq:
    iounmap(reg);
err_mem:
    return -ENOMEM;
}

为什么内核用 goto 而非 if-else 嵌套：每个资源申请可能失败，goto 到对应清理标签比层层嵌套 if-else 更扁平、更不易遗漏清理步骤。Linus Torvalds 在内核编码规范中明确支持这一模式。

常见陷阱

  1. goto 跳过变量初始化：goto skip; int x = compute(); skip: use(x); ——C99+ 中跳过带初始化的声明是 UB（x 的值不确定）。GCC 报错 jump bypasses variable initialization。修复：把声明移到 goto 之前，或用 int x; goto skip; skip: x = compute();（先声明不初始化，跳过后再赋值）。

  2. goto 制造循环（向后跳）导致可读性崩塌：label: ... if (cond) goto label; 等价于 while/for/do-while，但可读性差。编译器对 goto 循环和结构化循环生成的代码通常一样，没有性能优势。唯一合理的向后 goto 是实现状态机或手写汇编对照。正常循环一律用 while/for。

  3. 多个清理标号顺序写反：err_irq: free_irq(); err_mem: iounmap(); ——清理必须按申请的逆序释放。如果标号顺序写反（先 iounmap 再 free_irq），可能在 irq handler 仍访问寄存器时释放了映射。大型函数清理链容易写错，review 时需逐条核对申请-释放配对。

自测题

1. 选择：以下代码有什么问题？

goto skip;
int x = 42;
skip:
printf("%d\n", x);
  • A. 没问题，x 被初始化为 42
  • B. 编译错误或 UB，goto 跳过了 x 的初始化
  • C. x 的值是 0
  • D. 标号不能在变量声明前
答案

B。C99+ 规定 goto 跳过带初始化的声明是未定义行为。GCC/Clang 报错 jump bypasses variable initialization。修复：把 int x; 放到 goto 之前，初始化 x = 42; 放到 skip 之后；或去掉初始化改为 int x = 0;（但语义可能不对）。注意：跳过无初始化的声明（int x;）是合法的，只是 x 的值不确定。

2. 判断：goto 可以跳转到另一个函数中的标号。

答案

错。goto 的标号作用域是当前函数，不能跨函数跳转。跨函数跳转需用 setjmp/longjmp（C 标准库），但 longjmp 跳回 setjmp 时会展开栈帧，若中间有未释放的资源会泄漏——比 goto 危险得多。C++ 的异常机制（throw/catch）是更安全的跨函数跳转，但它有运行时开销。

3. 踩坑：以下内核风格代码的清理顺序有什么问题？

struct resource *a = alloc_a();
if (!a) goto out;
struct resource *b = alloc_b();
if (!b) goto out;
/* 正常逻辑 */
return 0;
out:
    free_a(a);
    free_b(b);
    return -1;
答案

问题：当 alloc_b() 失败时执行 goto out，此时 b 是 NULL，free_b(b) 传 NULL 可能没问题（如果 free_b 检查了 NULL）。但更严重的是当 alloc_a 失败时，b 还没声明就跳到 out，free_b(b) 访问未声明变量——编译错误。 正确写法用分级标号：

if (!a) goto err_a;
if (!b) goto err_b;
return 0;
err_b: free_b(b);
err_a: free_a(a);
return -1;

每个标号只清理到该点为止已申请的资源，逆序释放。

            goto found;
/* 未找到 */
return -1;

found:
    printf("found at [%d][%d]\n", i, j);
    return 0;

不用 break + flag 的原因：需要两层 break 外加一个外层循环条件检查（if (found) break），代码更长且容易忘记某一层。goto found 一步到位，语义清晰。Linux 内核搜索循环常用此模式。C 没有 break N（break N 层循环）语法，goto 是最直接的多层退出方式。

与后续衔接

Linux 内核大量 goto out; / goto err_free; 模式；读驱动、网络栈时会天天见到。掌握「标号 + 单向清理」比排斥一切 goto 更实用。

代码自测

题目 1： goto 在什么场景下是合理的？

for (i = 0; i < n; i++)
    for (j = 0; j < m; j++)
        if (found)
            goto done;
done:
参考答案

多重循环的跳出是 goto 最常见的合理用法——C 没有 break N 语法，goto 比设标志位 + 多重 break 更清晰。另一个合理场景是错误处理（类似 goto cleanup）。其余情况应避免 goto——它破坏结构化编程，使控制流难以追踪。

章节自测

题目 1： 以下代码中 if-else 的配对关系是怎样的？

if (a > 0)
    if (b > 0)
        x = 1;
else
    x = 2;
参考答案

else 与最近的 if 配对（dangling else 问题）——else 属于 if (b > 0)，不是 if (a > 0)。当 a <= 0 时，x 不被赋值。如果想 else 属于外层 if，需要用花括号：if (a > 0) { if (b > 0) x = 1; } else x = 2;。K&R 建议始终用花括号避免歧义。
