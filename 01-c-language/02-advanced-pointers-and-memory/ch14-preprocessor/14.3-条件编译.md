# 14.3 条件编译

## 本节讲什么

条件编译是预处理器的「编译期分支」——`#if`/`#ifdef`/`#ifndef`/`#elif`/`#else`/`#endif` 让代码块根据宏定义或常量表达式选择性编译。这一节给出条件编译的三大用途（调试开关、跨平台、特性裁剪）、指令对照表，以及 HFT 工程里线上关日志、跨架构编译、特性开关的实际形态。

认知锚点：条件编译不是「可选的预处理器特性」，而是 C 工程的**基础设施**。Linux 内核、DPDK、glibc 全部依赖条件编译适配不同架构、不同配置、不同编译器。理解条件编译，才能理解为什么同一份 C 代码能在 x86、ARM、PowerPC 上跑——靠的就是这套机制。

## 要点

### 指令对照表

| 指令 | 作用 | 示例 |
|------|------|------|
| `#if EXPR` | 表达式非 0 则编译 | `#if BURST_SIZE > 16` |
| `#ifdef NAME` | 宏已定义则编译 | `#ifdef DEBUG` |
| `#ifndef NAME` | 宏未定义则编译 | `#ifndef HEADER_H` |
| `#elif EXPR` | 否则若 | `#elif defined(__arm__)` |
| `#else` | 否则 | `#else` |
| `#endif` | 结束条件块 | `#endif` |

### `#ifdef` vs `#if defined`

```c
/* 等价 */
#ifdef DEBUG
    ...
#endif

#if defined(DEBUG)
    ...
#endif

/* 多条件时 #if defined 更清晰 */
#if defined(DEBUG) && defined(VERBOSE)
    ...
#endif

/* ifdef 不支持逻辑组合 */
#ifdef DEBUG && VERBOSE   /* 语法错误 */
```

**`#if defined(NAME)`** 是通用形式，支持 `&&`、`||`、`!` 逻辑组合。`#ifdef NAME` 是单宏判断的简写。复杂条件用 `#if defined`，单宏判断用 `#ifdef`。

### `#if` 的常量表达式

```c
#if BURST_SIZE > 0 && BURST_SIZE <= 256
    /* 合法范围 */
#elif BURST_SIZE > 256
    #error "BURST_SIZE too large"
#endif
```

`#if` 的表达式必须是**预处理常量表达式**：

- 宏替换后是整型常量表达式。
- `defined(NAME)` 判断宏是否定义。
- 不能用 `sizeof`、不能调用函数（C99 起部分放宽）。
- 未定义的宏在表达式中视为 `0`。

```c
#if UNKNOWN_MACRO    /* UNKNOWN_MACRO 未定义，视为 0，条件为假 */
    ...
#endif
```

> **官方原文（GCC CPP 手册 4.2.2 If）**：
> Identifiers that are not macros, which are all considered to be the number zero.
> This allows you to write `#if MACRO` instead of `#ifdef MACRO`, if you know that MACRO,
> when defined, will always have a nonzero value. Function-like macros used without their
> function call parentheses are also treated as zero.
> In some contexts this shortcut is undesirable. The `-Wundef` option causes GCC to warn
> whenever it encounters an identifier which is not a macro in an `#if`.

#### ⭐ 「未定义宏 ⇒ `#if` 报错」是错的（CE 复核）

「如果宏根本没定义，`#if MACRO >= 2` 语法错误！」——这个说法流传很广，**但它是错的**。
实测把四种情况分开（gcc 13.3，CE 端 `cg133`）：

| 写法 | 实测结果 |
|------|---------|
| `#if UNDEFINED_MACRO >= 2` | ✅ 编译通过、**0 诊断**，`0 >= 2` 为假走 `#else` |
| `#if UNKNOWN_A + UNKNOWN_B == 0` | ✅ 两个都当 0，条件成立（0 诊断） |
| 同上 + `-Wundef` | ⚠️ 才出声：`warning: "UNDEFINED_MACRO" is not defined, evaluates to 0 [-Wundef]` |
| `#define EMPTY`（定义了但为空）+ `#if EMPTY >= 2` | ❌ **`error: operator '>=' has no left operand`** |
| `#if sizeof(int) == 4` | ❌ **`error: missing binary operator before token "("`** |
| `#if FOO(1)`（`FOO` 未定义） | ❌ 同上 —— `FOO` 当 0，后面的 `(` 就非法了 |

**精确边界**：未定义标识符**本身永远不报错**，它只是变成 `0`。会报错的只有两种：

1. **宏定义了但展开为空** —— `#if EMPTY >= 2` 展开成 `#if >= 2`，左操作数没了；
2. **替换成 0 之后整个表达式变非法** —— `sizeof`、`enum` 常量、函数式宏名都归这类
   （手册原句：`sizeof` operators are not recognized in `#if`, and neither are `enum` constants.
   They will be taken as identifiers which are not macros, and replaced by zero.
   In the case of `sizeof`, this is likely to cause the expression to be invalid.）。

而「静默为假」比报错更危险，所以建议项目里默认开 **`-Wundef`**。

### 调试开关：HFT 线上关日志

```c
/* debug.h */
#if HFT_DEBUG_LEVEL >= 2
    #define DBG_TRACE(fmt, ...)  log_trace(fmt, ##__VA_ARGS__)
#elif HFT_DEBUG_LEVEL >= 1
    #define DBG_TRACE(fmt, ...)  ((void)0)
#else
    #define DBG_TRACE(fmt, ...)  ((void)0)
#endif

/* 调用 */
DBG_TRACE("seq=%lu processing\n", seq);
```

**关闭时零开销**：`((void)0)` 展开为空操作，编译器完全删除调用。汇编中无 `log_trace` 调用，无参数准备，无分支判断。HFT 数据面要求生产环境日志零开销，条件编译是唯一手段。

#### 编译期日志级别

```bash
# 开发环境
gcc -DHFT_DEBUG_LEVEL=2 ...

# 测试环境
gcc -DHFT_DEBUG_LEVEL=1 ...

# 生产环境
gcc -DHFT_DEBUG_LEVEL=0 ...
```

构建系统通过 `-D` 注入日志级别，同一份源码编译出不同行为的二进制。生产环境关掉 TRACE/DEBUG 日志，保留 ERROR。

### 跨平台编译

```c
#if defined(__x86_64__) && defined(__linux__)
    /* x86-64 Linux */
    #define HFT_ARCH_X86_64 1
    #define HFT_CACHE_LINE 64
    #define HFT_MEMBAR()    asm volatile("" ::: "memory")  /* x86 强模型 */
#elif defined(__aarch64__) && defined(__linux__)
    /* ARM64 Linux */
    #define HFT_ARCH_ARM64 1
    #define HFT_CACHE_LINE 64
    #define HFT_MEMBAR()    asm volatile("dmb ish" ::: "memory")  /* ARM 弱模型 */
#elif defined(__powerpc64__)
    /* PowerPC 64 */
    #define HFT_ARCH_PPC64 1
    #define HFT_CACHE_LINE 128
    #define HFT_MEMBAR()    asm volatile("lwsync" ::: "memory")
#else
    #error "unsupported platform"
#endif
```

**条件编译隐藏平台差异**：调用方用 `HFT_MEMBAR()`，不关心是 x86 空操作还是 ARM `dmb ish`。这是 DPDK `rte_smp_wmb`、内核 `smp_wmb` 的设计原理。

### 特性开关

```c
#ifdef HFT_ENABLE_TCP_FAST
    /* TCP Fast Open 快速路径 */
    int fast_send(struct sock *sk, ...) {
        /* ... */
    }
#else
    /* 兼容路径 */
    int fast_send(struct sock *sk, ...) {
        return compat_send(sk, ...);
    }
#endif
```

特性开关让同一份代码编译出「带特性」和「不带特性」两个版本。HFT 工程用于：

- **实验特性**：新策略默认关闭，灰度时开启。
- **许可证特性**：付费用户开启，免费用户关闭。
- **硬件特性**：某些网卡支持零拷贝，不支持则走传统路径。

### 头文件保护

```c
#ifndef QUOTE_PROTO_H
#define QUOTE_PROTO_H

/* 头文件内容 */

#endif /* QUOTE_PROTO_H */
```

**include guard** 防止头文件重复包含。详见 14.4.2。

### 嵌套条件编译

```c
#if defined(__linux__)
    #if defined(__x86_64__)
        /* Linux x86-64 */
    #elif defined(__aarch64__)
        /* Linux ARM64 */
    #endif
#elif defined(__FreeBSD__)
    /* FreeBSD */
    #if defined(__x86_64__)
        /* FreeBSD x86-64 */
    #endif
#endif
```

嵌套可读性差，**深度超过 3 层应重构**。用 `#if defined(A) && defined(B)` 合并条件，或拆分到不同头文件。

### `#elif defined` 链

```c
#if defined(__GNUC__)
    #define COMPILER_GCC 1
#elif defined(__clang__)
    #define COMPILER_CLANG 1
#elif defined(_MSC_VER)
    #define COMPILER_MSVC 1
#else
    #define COMPILER_UNKNOWN 1
#endif
```

`#elif defined` 链是编译器检测的标准写法。注意**顺序敏感**：Clang 同时定义 `__clang__` 和 `__GNUC__`，必须先检 Clang。

## HFT 关联

### DPDK CONFIG_ 宏

```c
/* DPDK 的配置宏，由 meson build 生成 */
#ifdef RTE_LIBRTE_MLX5_PMD
    /* Mellanox 网卡 PMD 启用 */
#endif

#ifdef RTE_ARCH_X86_64
    /* x86-64 专用优化 */
#endif

#ifdef RTE_LIBRTE_JOBSTATS
    /* 任务统计启用 */
#endif
```

DPDK 用 `RTE_LIBRTE_*` 系列宏控制功能裁剪。`meson configure -Denable_mlx5=true` 注入对应宏，编译出包含/不包含该 PMD 的版本。

### 内核 Kconfig

```c
/* 内核配置宏，由 Kconfig 生成 autoconf.h */
#ifdef CONFIG_SMP
    /* 对称多处理 */
#endif

#ifdef CONFIG_PREEMPT
    /* 抢占内核 */
#endif

#ifdef CONFIG_HUGETLB_PAGE
    /* 大页支持 */
#endif
```

内核的 `make menuconfig` 配置生成 `autoconf.h`，里面有所有 `CONFIG_*` 宏定义。条件编译让同一份内核源码编译出从嵌入式到服务器不同规模的版本。

### 策略灰度发布

```c
#ifdef HFT_STRATEGY_ALPHA_V2
    #include "strategy_alpha_v2.c"
#else
    #include "strategy_alpha_v1.c"
#endif
```

策略版本灰度：开发完 v2 后，编译时用 `-DHFT_STRATEGY_ALPHA_V2` 切换。**不开则继续用 v1**，开了灰度切到 v2。回滚只需重新编译不定义该宏。

### 硬件特性检测

```c
#ifdef HFT_NIC_OFFLOAD_CHKSUM
    /* 网卡硬件校验和卸载 */
    mbuf->ol_flags |= PKT_TX_IP_CKSUM | PKT_TX_L4_CKSUM;
#else
    /* 软件校验和 */
    sw_checksum(mbuf);
#endif
```

不同网卡能力不同，条件编译让代码自适应。HFT 部署时根据实际网卡能力编译对应版本。

### 调试构建

```c
#ifdef HFT_DEBUG
    /* 调试断言、检查、日志全开 */
    #define HFT_ASSERT(cond)  do { if (!(cond)) { log_err("assert: %s", #cond); abort(); } } while (0)
    #define HFT_DBG_LOG(fmt, ...)  log_debug(fmt, ##__VA_ARGS__)
#else
    /* 生产构建：断言保留，调试日志关闭 */
    #define HFT_ASSERT(cond)  do { if (!(cond)) { log_err("assert: %s", #cond); abort(); } } while (0)
    #define HFT_DBG_LOG(fmt, ...)  ((void)0)
#endif
```

调试构建开日志和详细检查，生产构建关日志但保留断言。**断言通常保留在生产环境**——HFT 对正确性要求极高，宁可崩溃也不能错单。

## UB 边界

| 情形 | 后果 | 防护 |
|------|------|------|
| `#if` 用未定义宏 | 视为 0，可能非预期 | 显式 `defined()` 检查 |
| `#ifdef NAME` 与 `#if NAME` 混淆 | `#if NAME` 未定义时为 0，`#ifdef` 检测定义 | 区分「定义」与「值为真」 |
| 嵌套过深 | 可读性差 | 拆分头文件或合并条件 |
| `#endif` 缺失 | 编译错误（块未闭合） | 配对检查，注释 `#endif // NAME` |
| 宏**定义了但为空** | `error: operator '>=' has no left operand` | 别写 `#define NAME` 这种空定义 |
| `#if sizeof(int) == 4` | `error: missing binary operator before token "("` | 预处理期不认 `sizeof`/`enum` 常量 |
| `#if` 用未定义宏 + 没开 `-Wundef` | **不报错**，静默当 0（比报错更危险） | 默认加 `-Wundef` |
| 条件内语法错误 | 被排除的块不检查，编译通过但运行错误 | 用 `#if 0` 暂时排除时仍需保证语法正确 |
| 宏重定义冲突 | 警告或覆盖 | include guard + `#undef` 后重定义 |

### `#if 0` 暂时排除代码

```c
#if 0
/* 暂时禁用的代码，保留但不编译 */
void experimental_feature(void) {
    ...
}
#endif
```

`#if 0` 是注释掉大段代码的标准方式——比 `/* */` 更可靠（C 不支持嵌套块注释）。恢复时改成 `#if 1`。

### ⭐ 一个被抄来抄去的错误示例：用 `#ifdef __STRICT_ANSI__` 选 `__attribute__`

网上有一道很流行的「快速小测验」：

```c
#ifdef __STRICT_ANSI__
char buf[0];
#else
char buf[0] __attribute__((packed));   /* ← 号称「GNU 扩展分支，严格模式用不了」 */
#endif
```

「`-std=c17` 下保留前半段」这个**结论对**（`__STRICT_ANSI__` 确实被定义）。
但它想教的推论是错的，而且例码本身两边都站不住：

| 疑点 | 实测（gcc 13.3） |
|------|-----------------|
| 「严格模式下不能用 `__attribute__`」？ | ❌ `-std=c17 -DQUIZ` 下**编译通过**，`sizeof(buf) = 0`，与 `buf` 相关的诊断 **0 条** |
| `packed` 加在**变量**上有意义吗？ | ❌ `warning: 'packed' attribute ignored [-Wattributes]`——`packed` 只对 struct/union/enum 有效（见 [2.2.4 属性声明 packed](../../05-embedded-kernel-practice/02-ch2-gnu-c-advanced/2.2-aligned/2.2.4-属性声明-packed.md)） |
| 真需要这个 `#ifdef` 分支吗？ | **不需要**。`__attribute__` 是双下划线形态，任何方言、任何 `-pedantic` 强度下都能用 |

**该写 `#ifdef __STRICT_ANSI__` 分支的只有裸关键字**：`typeof` / `asm` / `inline`——
这也正是「内核必须用 `gnu11`」的全部理由。完整实测、官方原文与二分心智模型见
[GNU C 书 §1.1 网传说法逐条勘误](../../05-embedded-kernel-practice/01-ch1-gnu-c-basics/1.1-c-standard/1.1-C语言标准和编译器.md)。

> ⚠️ 顺带一个反讽：**`#warning` 自己就不是 ISO C**（C23 才转正，见 [14.5](14.5-其他指令.md)）。
> 拿它去警示「GNU 扩展不可用」时，`-std=c17 -pedantic-errors` 下会先挨一句
> `error: #warning before C2X is a GCC extension`。

### `#error` 编译期阻断

```c
#if BURST_SIZE > 256
    #error "BURST_SIZE must be <= 256"
#endif

#if !defined(HFT_ARCH_X86_64) && !defined(HFT_ARCH_ARM64)
    #error "Unsupported architecture"
#endif
```

`#error` 在编译期打印消息并失败，优于运行期崩溃。HFT 工程在配置校验、平台检测、版本检查中大量使用。

## 口述自测题

4. Clang 同时定义 `__clang__` 和 `__GNUC__`。**检测编译器的 `#elif defined` 链应该怎么排顺序**？为什么 Clang 必须在 GCC 之前？
5. `#if 0 ... #endif` 相比 `/* ... */` 注释掉大段代码有什么优势？**C 不支持什么**导致块注释不可靠？`#error` 在编译期阻断相比运行期崩溃有什么好处？

7. 一段代码用 `#ifdef __STRICT_ANSI__` 在「标准版」和「`__attribute__((packed))` 版」之间二选一。**这个分支有必要吗**？如果没有，那段 `#ifdef` 在语义上其实等价于什么？
