# 6.14 空指针判空的硬件路径：ZF 标志、test/cmp 与 0 页保护

## 本节讲什么

6.6 讲了 NULL 的**语言语义**（空指针常量、解引用为什么崩）。本节下沉一层，回答四个硬件问题：

1. `if (p)` 到了 CPU 上到底执行什么？
2. 比较两个指针和比较两个整数，硬件路径有区别吗？
3. x86 的 `test`/`cmp` + ZF 与 ARM64 的 `cmp`/`cbnz` 有何不同？
4. "空指针是数值 0"和"第 0 页保护"是什么关系？

核心结论一句话：**CPU 层面没有"指针"这个概念，只有二进制数。空指针就是数值 0，指针判空和整数判零走完全相同的硬件路径。**

文中所有汇编均为本机实测（clang 23.1.0，macOS arm64；x86-64 为同编译器交叉生成）。

## 要点

```c
int *p = NULL;
if (p) { /* ... */ }        /* 判空：只动寄存器，不访问内存，安全 */
if (*p == 0) { /* ... */ }  /* 解引用：访问地址 0 → 0 页无映射 → SIGSEGV */
```

- `cmp a, b` 本质是**做减法 `a - b`**，丢弃结果只留标志位；**ZF=1 ⟺ 差为 0 ⟺ 两数相等**
- `jnz` 和 `jne` 是**同一条指令的两个名字**（同为 opcode `75` / `0F 85`）
- 指针就是 64 位整数，比较指针 = 比较整数，**无需任何特殊处理**
- `if (p == q)` 比的是**地址**（纯寄存器）；`if (*p == *q)` 比的是**内容**（先 load 再 cmp）
- x86 判空常用 `test rdi, rdi`（自己 AND 自己），比 `cmp rdi, 0` 指令更短，ZF 效果一样
- ARM64 **没有 `test` 指令**；且 `cbz/cbnz` 比较+跳转一条指令完成，**根本不写标志寄存器**

## 实测：四种写法的汇编对照

测试源码（`int` 指针，`sizeof(int)=4`）：

```c
int f_if_p(int *p)            { if (p)        return 1; return 0; }
int f_p_eq_q(int *p, int *q)  { if (p == q)   return 1; return 0; }
int f_deref_eq(int *p, int *q){ if (*p == *q) return 1; return 0; }
int f_ptr_diff(int *a, int *b){ return b - a; }
```

### x86-64（clang -O1，AT&T 语法）

```asm
f_if_p:                          # if (p)
    xorl   %eax, %eax
    testq  %rdi, %rdi            # p AND p → 只设标志：全 0 则 ZF=1
    setne  %al                   # ZF=0（非空）→ al=1
    retq

f_p_eq_q:                        # if (p == q)：纯寄存器，不访存
    xorl   %eax, %eax
    cmpq   %rsi, %rdi            # p - q → 只留标志
    sete   %al                   # ZF=1（相等）→ al=1
    retq

f_deref_eq:                      # if (*p == *q)：先 load 再比
    movl   (%rdi), %ecx          # *p  → ecx（这里才访问内存！）
    xorl   %eax, %eax
    cmpl   (%rsi), %ecx          # *q 与 *p 相减
    sete   %al
    retq

f_ptr_diff:                      # b - a：自动除 sizeof(int)=4
    movq   %rsi, %rax
    subq   %rdi, %rax            # 字节差
    shrq   $2, %rax              # ÷4 = 元素个数差
    retq
```

### ARM64（clang -O1）

```asm
_f_if_p:                         // if (p)
    cmp  x0, #0                  // p - 0 → 设 NZCV
    cset w0, ne                  // Z=0（非空）→ w0=1
    ret

_f_p_eq_q:                       // if (p == q)
    cmp  x0, x1
    cset w0, eq
    ret

_f_deref_eq:                     // if (*p == *q)
    ldr  w8, [x0]                // *p
    ldr  w9, [x1]                // *q
    cmp  w8, w9
    cset w0, eq
    ret

_f_ptr_diff:                     // b - a
    sub  x8, x1, x0
    lsr  x0, x8, #2              // ÷4
    ret
```

### ARM64 的低优化特例：`cbnz` 不碰标志位

`-O0` 时 `if (p)` 编成：

```asm
    ldr  x8, [sp]
    cbnz x8, LBB0_1              // compare-and-branch-nonzero：一条指令判零+跳转
```

**`cbz/cbnz` 不写 NZCV 标志寄存器**——ARM64 的"判零跳转"可以不经过标志位，比较与跳转融合在一条指令里。所以"判零 ⟺ 查 ZF"这条因果链是 **x86 世界观**；ARM 上 ZF（Z 标志）只在你显式用 `subs`/`cmp` 时才存在。

### 两个 ISA 的机制差异表

| 维度 | x86-64 | ARM64 |
|------|--------|-------|
| 判空典型指令（-O1） | `testq %rdi, %rdi` | `cmp x0, #0` |
| `test`（AND 型判零） | 有 | **无此指令** |
| 比较-跳熔合指令 | 无（宏融合是 µop 层面） | `cbz/cbnz`（不写标志） |
| 标志寄存器 | RFLAGS（ZF 等） | NZCV（Z 等） |
| 相等跳转 | `je`/`jz`（同 opcode） | `b.eq` |

## 0 页保护：数值 0 与"第 0 页"是一回事

| 视角 | 事实 |
|------|------|
| 数值视角 | 空指针的 64 bit 全 0，就是整数 0 |
| 地址视角 | 地址 0 落在**第 0 页**（0x0 ~ 0xFFF） |
| OS 设计 | 故意**不映射**第 0 页 → 解引用空指针立即页错误 → SIGSEGV |

**0 页保护 = 给空指针设的陷阱**：让 bug 在第一次 `*p` 时立刻暴露，而不是静默读写垃圾数据。

关键区分：

- **比较** `if (p)`：只动寄存器数值，不访问内存 → 安全
- **解引用** `*p`：访问地址 0 → 第 0 页无映射 → 页错误 → SIGSEGV

保护范围：

| 平台 | 低地址保留 | 机制 |
|------|-----------|------|
| Linux | 默认低 64KB | `/proc/sys/vm/mmap_min_addr` = 65536 |
| macOS arm64 | 低 **4GB** 全保留 | 链接器 `__PAGEZERO` 段 |

知识链条总览：

```
if (p)                                    ← C 源码（指针隐式转 bool）
  ↓ 编译
test rdi, rdi  /  cmp x0, #0              ← 汇编（AND 或减法）
  ↓ 执行
ZF/Z = (p 的 64 bit 是否全 0)              ← CPU 标志位（cbnz 路径无此步）
  ↓
je 跳过 if 体（空）/ 顺序执行（非空）         ← 条件跳转
─────────────────────────────────
*p（解引用）→ 访问地址 0 → 第 0 页无映射 → 页错误 → SIGSEGV  ← 0 页保护
```

## HFT / 嵌入式关联

| 场景 | 要点 |
|------|------|
| 热路径判空 | `if (!pkt) return;` 编译后就是一条 test/cmp + 分支，零额外成本——放心写，不用担心"判空浪费指令" |
| 分支预测 | 热路径上指针几乎恒非空，分支预测器直接命中，实际代价≈0；把 `if (p)` 放冷路径侧（unlikely 分支）即可 |
| 嵌入式裸机 | Cortex-M **没有 MMU**，默认没有 0 页保护：NULL 解引用会真去读/写地址 0（通常是 Flash 起始或向量表），**不崩溃、静默出错**——比段错误更难查 |
| MPU 兜底 | 有 MPU 的 MCU（如 STM32F4/H7）可用 MPU 把 0 地址区设为不可访问，人工实现"0 页保护" |
| 内核 | 内核可用 `ioremap`/`fixmap` 让虚拟地址 0 有真映射（见 6.6"内核边界"），此时机器值 0 ≠ 空指针语义 |

## 常见误区

| 误区 | 事实 |
|------|------|
| "判空要'减 0'所以较慢" | x86 -O1 用 `test`（AND）一步到位，根本不减；ARM 用 `cmp x0, #0` 或 `cbnz` |
| "所有 CPU 判零都查 ZF" | x86 特有世界观；ARM64 `cbz/cbnz` 不写标志寄存器 |
| "`jnz` 和 `jne` 是两条指令" | 同一条指令的两个助记符，机器码完全相同 |
| "比较指针要特殊指令" | 指针就是 64 位整数，`cmp` 原样用 |
| "0 页保护是 CPU 功能" | 是 **OS 的页表设计**——故意不映射低地址；裸机没有这层保护 |
| "`if (p)` 会访问 p 指向的内存" | 只读 p 这个变量本身（在寄存器里），不碰 `*p` |

## 代码自测

**题目 1：** 下面这段 x86-64 汇编对应哪个 C 函数？为什么能确定不是另外两个？

```asm
func:
    movl   (%rdi), %ecx
    xorl   %eax, %eax
    cmpl   (%rsi), %ecx
    sete   %al
    retq
```

候选：A. `if (p)`  B. `if (p == q)`  C. `if (*p == *q)`

<details>
<summary>参考答案</summary>

**答案：C**。关键证据是两条访存指令 `movl (%rdi), %ecx` 和 `cmpl (%rsi), %ecx`——出现了 `(%rdi)`、`(%rsi)` 这种**寄存器间接寻址**，说明 CPU 真的去内存里取了 `*p` 和 `*q` 的值。

- A（`if (p)`）只会是 `testq %rdi, %rdi`，**没有任何括号寻址**——判空不访存。
- B（`if (p == q)`）是 `cmpq %rsi, %rdi`，两个寄存器直接比，也不访存。
- C 必须先 load 再 cmp，且比较的是 32 位（`movl`/`cmpl`，因为 `int` 是 4 字节）而不是 64 位指针本身。

**核心判据：有没有 `(%rdi)` 出现 = 有没有解引用发生。**

</details>

**题目 2：** 同一份 C 代码 `if (p) return 1; return 0;`，clang -O1 在 x86-64 上生成 `testq` + `setne`，在 ARM64 -O0 上却生成 `cbnz`——两条路径都经过 ZF/Z 标志吗？

<details>
<summary>参考答案</summary>

**不是。**

- x86-64 路径：`testq %rdi, %rdi` 做按位 AND，结果全 0 则 **ZF=1**，`setne` 读 ZF 取值——**经过标志寄存器**。
- ARM64 -O0 路径：`cbnz x8, target` 是一条**比较-分支熔合指令**，硬件内部判 `x8 != 0` 然后直接决定跳不跳，**不写 NZCV 标志寄存器**——判零这件事发生在指令内部，标志位根本没参与。

这正是"判零 ⟺ 查 ZF"是 x86 特有世界观的原因。ARM64 上想要标志位，得显式用 `cmp x0, #0`（即 `subs xzr, x0, #0`）或 `subs` 这类带 S 后缀的指令。

</details>

**题目 3：** 在 Linux 用户态把 `/proc/sys/vm/mmap_min_addr` 改成 0，然后 `mmap` 把地址 0 映射成可读写页，再执行 `int *p = NULL; *p = 42;` 会发生什么？这和 6.6 说的"内核边界"有什么呼应？

<details>
<summary>参考答案</summary>

**程序不会崩溃，`*p = 42` 会真的写进地址 0 的那页内存**（需 root 权限才能改 `mmap_min_addr`）。

这说明三件事：

1. **0 页保护不是 CPU 的功劳，是 OS 页表的设计选择**——一旦映射存在，地址 0 和其他地址没有任何区别。
2. **"空指针 = 数值 0"与"地址 0 不可访问"本来是两回事**，平时它们绑定在一起只是因为 OS 故意不映射。
3. 这正是 6.6"内核边界"的用户态翻版：内核里 `ioremap`/`fixmap` 可以让虚拟地址 0 有真映射，此时机器值为 0 的指针**可以正常解引用**，但它在 C 语义上仍是空指针——**语法语义与机器值脱钩**。

历史上这也是真实安全漏洞（NULL pointer dereference 提权）的利用前提，所以现代 Linux 默认 `mmap_min_addr = 65536` 且不允许普通用户降低它。

</details>
