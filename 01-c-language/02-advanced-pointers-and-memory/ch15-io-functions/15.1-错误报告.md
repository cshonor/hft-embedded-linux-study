# 15.1 错误报告

## 本节讲什么

I/O 操作可能失败——文件不存在、权限不足、磁盘满、网络断。C 标准库通过 **`errno` + `perror` + `strerror`** 三件套提供错误报告机制。这一节给出它们的用法、`errno` 的线程局部性、`stderr` 无缓冲特性，以及 HFT 工程里故障日志的实践。

认知锚点：`errno` 不是「错误码变量」，而是**线程局部的可修改左值**——每次系统调用或库函数失败时设置，成功时不保证清零。理解这一点才能正确使用：**先保存 errno，再调用可能修改它的函数**。

## 要点

### perror：打印错误

```c
FILE *fp = fopen("quote.dat", "rb");
if (!fp) {
    perror("fopen quote.dat");
    /* 输出：fopen quote.dat: No such file or directory */
    return -1;
}
```

`perror(prefix)` 输出 `prefix: strerror(errno)\n` 到 `stderr`。**`prefix` 是用户提供的上下文**，便于定位是哪个操作失败。

### strerror：错误码转字符串

```c
#include <string.h>
#include <errno.h>

int err = errno;   /* 先保存 */
fprintf(stderr, "fopen failed: %s\n", strerror(err));
```

`strerror(errno)` 返回错误码对应的可读字符串。**调用前先保存 `errno`**——`fprintf` 等函数可能修改 `errno`。

#### strerror_r：线程安全版本

```c
char buf[256];
int ret = strerror_r(errno, buf, sizeof(buf));
/* POSIX: 返回 0 成功，buf 内是字符串 */
/* GNU:  返回字符串指针（可能不是 buf） */
```

`strerror` 返回静态字符串指针，多线程并发调用可能互相覆盖。`strerror_r` 是线程安全版本，但 POSIX 与 GNU 实现签名不同（详见 ch09）。

### errno 的线程局部性

```c
/* C11 起 errno 是线程局部的可修改左值 */
errno = 0;              /* 显式清零 */
FILE *fp = fopen(...);
if (!fp) {
    int err = errno;    /* 立即保存 */
    /* ... 其他函数调用可能修改 errno ... */
    log_err("fopen failed: %s", strerror(err));
}
```

| 特性 | 说明 |
|------|------|
| 线程局部 | 每个线程有自己的 errno，互不干扰 |
| 成功不清零 | 函数成功时 errno 不保证清零，**不能靠 errno 判断成功** |
| 失败才设置 | 函数失败时设置为对应错误码 |
| 必须立即保存 | 后续函数调用可能覆盖 errno |

**正确模式**：检查返回值判断成功/失败，失败时立即保存 errno 到局部变量。

### stderr 无缓冲

```c
fprintf(stderr, "fatal: %s\n", msg);   /* 立即输出，不等 \n */
```

`stderr` 默认无缓冲，每次 `fprintf` 立即输出。崩溃前的最后一条日志不会因缓冲丢失。**致命错误日志必须用 stderr**，不能用 stdout（行缓冲，崩溃可能丢失）。

### 常见 errno 值

| 错误码 | 含义 | 典型场景 |
|--------|------|----------|
| `ENOENT` | No such file or directory | fopen 不存在的文件 |
| `EACCES` | Permission denied | 权限不足 |
| `EEXIST` | File exists | 创建已存在的文件 |
| `ENOSPC` | No space left on device | 磁盘满 |
| `EBADF` | Bad file descriptor | fd 无效 |
| `EINVAL` | Invalid argument | 参数非法 |
| `ENOMEM` | Cannot allocate memory | 内存不足 |
| `EAGAIN` | Resource temporarily unavailable | 非阻塞 I/O 无数据 |
| `EINTR` | Interrupted system call | 信号中断 |
| `EPIPE` | Broken pipe | 写已关闭的管道 |

## HFT 关联

### 故障日志规范

```c
#define LOG_FATAL(fmt, ...) do { \
    int _err = errno; \
    fprintf(stderr, "[FATAL %s:%d %s] " fmt " (errno=%d: %s)\n", \
            __FILE__, __LINE__, __func__, ##__VA_ARGS__, \
            _err, strerror(_err)); \
    fflush(stderr); \
} while (0)

FILE *fp = fopen("/data/quote.dat", "rb");
if (!fp) {
    LOG_FATAL("cannot open quote file");
    exit(1);
}
/* 输出：[FATAL engine.c:42 init] cannot open quote file (errno=2: No such file or directory) */
```

致命错误日志集成 `__FILE__`/`__LINE__`/`__func__` + errno + strerror，一行定位问题。**`fflush(stderr)` 确保崩溃前落盘**（虽然 stderr 无缓冲，但显式 flush 是保险）。

### 磁盘满降级

```c
size_t n = fwrite(batch, sizeof(batch[0]), 32, log_fp);
if (n < 32 && ferror(log_fp)) {
    int err = errno;
    LOG_FATAL("log write partial: %d/%d written", n, 32);
    if (err == ENOSPC) {
        /* 磁盘满，切换到降级模式：只写内存环形缓冲 */
        log_mode = LOG_MODE_MEMORY_ONLY;
    }
}
```

HFT 系统对磁盘满要降级而非崩溃——行情日志写不下时切到内存缓冲，保证数据面继续运行。`errno == ENOSPC` 是磁盘满的标志。

### errno 与多线程

```c
/* 多线程下 errno 是线程局部的，安全 */
void *worker_thread(void *arg) {
    FILE *fp = fopen(...);
    if (!fp) {
        int err = errno;   /* 本线程的 errno */
        log_err("fopen failed: %s", strerror(err));
    }
    return NULL;
}
```

C11 起 `errno` 是线程局部的，多线程并发使用安全。但 `strerror` 返回静态字符串，多线程并发调用不安全——用 `strerror_r`。

### 数据面避免 perror

```c
/* 数据面热路径避免 perror/fprintf */
/* 用内存日志缓冲 + 异步落盘 */
static char log_buf[64 * 1024];
static size_t log_pos = 0;

static inline void log_fast(const char *msg, size_t len) {
    if (log_pos + len < sizeof(log_buf)) {
        memcpy(log_buf + log_pos, msg, len);
        log_pos += len;
    }
}
```

HFT 数据面热路径不用 `perror`/`fprintf`——它们有锁、有格式化、有系统调用。日志写入内存缓冲，由专门日志线程异步落盘。

## UB 边界

| 情形 | 后果 | 防护 |
|------|------|------|
| 不保存 errno 直接调用 strerror | errno 可能被中间函数覆盖 | 先 `int err = errno` 保存 |
| 用 errno 判断成功 | 成功时 errno 不清零，误判 | 用返回值判断成功/失败 |
| `strerror` 多线程并发 | 静态字符串互相覆盖 | 用 `strerror_r` |
| `strerror` 传入非法 errno | 返回 "Unknown error N" | 检查 errno 范围 |
| perror 在 stdout 输出 | perror 输出到 stderr，不是 stdout | 理解 perror 输出流 |

### errno 的「成功不清零」陷阱

```c
errno = 0;
FILE *fp = fopen("exists.txt", "r");
/* fopen 成功，但 errno 可能被内部调用设为非 0 */
if (errno != 0) {
    /* 误判：fopen 成功但 errno 非 0 */
    log_err("fopen failed?");
}
```

**正确做法**：用返回值判断成功/失败，失败时才看 errno。
