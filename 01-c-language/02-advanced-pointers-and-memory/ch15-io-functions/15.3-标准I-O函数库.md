# 15.3 标准 I/O 函数库

## 本节讲什么

`<stdio.h>` 是 C 标准库的 I/O 接口，提供**带缓冲的高层 I/O 抽象**——`FILE *` 流、`fopen`/`fclose`、`fread`/`fwrite`、`printf` 族等。这一节给出 stdio 的函数分类总览、与底层 POSIX I/O（`open`/`read`/`write`）的关系，以及 HFT 工程里控制面与数据面对 stdio 的不同取舍。

认知锚点：stdio 不是「I/O 的唯一方式」，而是**用户态缓冲层**——它在底层系统调用之上加了一层缓冲，减少 syscall 次数，提高吞吐。但缓冲引入延迟抖动，HFT 数据面追求纳秒级延迟时必须绕过 stdio，直接用系统调用或 DPDK。

## 要点

### stdio 函数分类

| 类别 | 代表函数 | 用途 |
|------|----------|------|
| 打开/关闭 | `fopen`, `fclose`, `freopen` | 流的生命周期 |
| 字符 I/O | `fgetc`, `fputc`, `getchar`, `putchar` | 逐字节读写 |
| 行 I/O | `fgets`, `fputs`, `puts`, `gets`(已移除) | 文本行读写 |
| 格式化 I/O | `printf`, `fprintf`, `sprintf`, `snprintf`, `scanf` 族 | 格式化文本 |
| 二进制 I/O | `fread`, `fwrite` | 原始内存块读写 |
| 定位 | `fseek`, `ftell`, `rewind`, `fgetpos`, `fsetpos` | 随机访问 |
| 刷新 | `fflush` | 强制写缓冲 |
| 错误 | `feof`, `ferror`, `clearerr`, `perror` | 状态查询 |
| 缓冲控制 | `setvbuf`, `setbuf` | 调整缓冲模式 |
| 临时文件 | `tmpfile`, `tmpnam` | 临时存储 |
| 文件操作 | `remove`, `rename` | 文件系统操作 |

### stdio 与 POSIX I/O 的层次

```
应用代码
   |
   | stdio 层（<stdio.h>）：FILE *、缓冲、格式化
   |   fopen → open + fdopen
   |   fread → read（经缓冲）
   |   fwrite → write（经缓冲）
   |   fclose → close（先 fflush）
   v
POSIX 层（<unistd.h>, <fcntl.h>）：fd、syscall
   |   open, read, write, close, lseek
   v
内核：VFS、文件系统驱动
```

| 维度 | stdio (`FILE *`) | POSIX (`fd`) |
|------|------------------|--------------|
| 抽象层级 | 高层 | 低层 |
| 缓冲 | 用户态缓冲 | 无（除非自己实现） |
| 格式化 | printf/fscanf | 需手动或第三方 |
| 跨平台 | C 标准，可移植 | POSIX，类 Unix |
| 性能 | 批量减少 syscall | 每次 read/write 一次 syscall |
| 延迟 | 缓冲引入抖动 | 直接 syscall，延迟可预测 |
| HFT 数据面 | 不用 | 部分场景用 |

### FILE 结构（典型实现）

```c
/* glibc 的 FILE 结构（简化） */
struct _IO_FILE {
    int    _flags;          /* 标志位 */
    char  *_IO_read_ptr;    /* 当前读位置 */
    char  *_IO_read_end;    /* 读缓冲末尾 */
    char  *_IO_read_base;   /* 读缓冲起始 */
    char  *_IO_write_base;  /* 写缓冲起始 */
    char  *_IO_write_ptr;   /* 当前写位置 */
    char  *_IO_write_end;   /* 写缓冲末尾 */
    char  *_IO_buf_base;    /* 缓冲区起始 */
    char  *_IO_buf_end;     /* 缓冲区末尾 */
    int    _fileno;         /* 底层文件描述符 */
    int    _mode;           /* 文本/二进制 */
    size_t _IO_buf_len;     /* 缓冲区长度 */
    /* ... 更多字段 ... */
};
```

`FILE *` 是指向这个结构的指针。每个 `FILE` 封装：

- **文件描述符 `fd`**：底层 POSIX fd。
- **用户态缓冲区**：减少 syscall。
- **读写位置**：当前偏移。
- **错误/EOF 标志**：状态查询。
- **缓冲模式**：全缓冲/行缓冲/无缓冲。

### stdio 的缓冲机制

```
应用 fwrite(buf, 1, 100, fp)
   |
   | 数据拷贝到 fp 的用户态缓冲区
   v
fp 缓冲区（用户态，4KB 默认）
   |
   | 缓冲区满 或 fflush 或 流关闭
   v
write(fd, 缓冲区, 4096)   ← 一次 syscall
   |
   v
内核页缓存（Page Cache）
   |
   | fsync 或内核回写
   v
磁盘
```

**缓冲的好处**：100 次 `fwrite` 各 100 字节，只触发 1 次 `write` syscall（缓冲区 4KB）。

**缓冲的代价**：数据在用户态缓冲区停留，崩溃可能丢失；延迟不可预测（什么时候 flush 不确定）。

### stdio 与 HFT 的取舍

| 场景 | 选型 | 理由 |
|------|------|------|
| 启动配置读取 | stdio (`fgets`) | 简单、低频、可读性高 |
| 日志写入 | stdio (`fprintf`) + 自定义缓冲 | 格式化方便，批量减少 syscall |
| 行情数据持久化 | stdio (`fwrite`) | 批量二进制读写高效 |
| 历史行情回放 | stdio (`fread`) | 批量读、缓冲友好 |
| 数据面报文收发 | **绕过 stdio**，用 DPDK | 纳秒级延迟，不能容忍缓冲 |
| 数据面网络 I/O | **绕过 stdio**，用 `recv`/`send` 或 epoll | 直接 syscall，延迟可预测 |

**口诀**：**控制面/管理面用 stdio，数据面绕过 stdio**。stdio 的缓冲是为吞吐优化，与 HFT 数据面的延迟需求冲突。

## HFT 关联

### DPDK 完全绕过 stdio

```c
/* DPDK 报文收发：完全不用 stdio */
struct rte_mbuf *pkts[32];
uint16_t n = rte_eth_rx_burst(port, queue, pkts, 32);
/* 直接从网卡环形队列取报文，无 syscall、无 stdio、无缓冲 */

for (uint16_t i = 0; i < n; i++) {
    process(pkts[i]);
    rte_pktmbuf_free(pkts[i]);
}
```

DPDK 用用户态网卡驱动（PMD）直接操作网卡环形队列，**不经过内核、不经过 stdio**。延迟从微秒级降到纳秒级。

### 日志系统的分层

```c
/* 数据面热路径：内存缓冲，无 stdio */
static char log_ring[64 * 1024];
static size_t log_pos = 0;

static inline void log_fast(const char *msg, size_t len) {
    size_t pos = __atomic_fetch_add(&log_pos, len, __ATOMIC_RELAXED);
    pos &= (sizeof(log_ring) - 1);   /* 环形缓冲 */
    memcpy(log_ring + pos, msg, len);
}

/* 日志线程：用 stdio 异步落盘 */
void *log_thread(void *arg) {
    FILE *fp = fopen("/var/log/hft.log", "a");
    while (running) {
        /* 从 log_ring 取数据，fprintf 落盘 */
        fprintf(fp, "%s\n", log_entries[i]);
        fflush(fp);
    }
    fclose(fp);
    return NULL;
}
```

HFT 日志系统分层：数据面写内存环形缓冲（纳秒级），专门日志线程用 stdio 异步落盘（毫秒级可接受）。**数据面绝不直接调用 fprintf**。

### 行情数据持久化

```c
/* 用 fwrite 批量持久化行情 */
struct quote batch[32];
/* ... 填充 batch ... */

size_t n = fwrite(batch, sizeof(batch[0]), 32, market_data_fp);
if (n != 32) {
    perror("fwrite market data");
}
```

`fwrite` 批量写 32 个报价，stdio 缓冲减少 syscall。延迟要求不高（落盘是异步操作），用 stdio 合适。

### 历史行情回放

```c
FILE *fp = fopen("history_20240101.dat", "rb");
struct quote q;
while (fread(&q, sizeof(q), 1, fp) == 1) {
    replay_quote(&q);
}
fclose(fp);
```

回放引擎用 `fread` 逐条读历史行情。stdio 缓冲预读，比逐条 `read` syscall 高效。

## UB 边界

| 情形 | 后果 | 防护 |
|------|------|------|
| `FILE *` 未初始化就使用 | 野指针，崩溃 | `fopen` 后判空 |
| `fclose` 后继续使用 `FILE *` | UAF | `fclose` 后置 NULL |
| 多线程并发使用同一 `FILE *` | 数据竞争 | 加锁或每线程独立流 |
| 缓冲区指针越界 | 内存损坏 | 用 `fread`/`fwrite` 而非直接操作缓冲 |
| `fflush(stdin)` | UB | 不要 fflush 输入流 |

### stdio 的线程安全

```c
/* glibc 的 FILE 默认加锁，多线程并发安全但慢 */
fputs("hello", fp);   /* 内部加锁 */

/* flockfile/funlockfile 手动控制 */
flockfile(fp);
fputs("hello ", fp);
fputs("world\n", fp);   /* 不重复加锁 */
funlockfile(fp);

/* _unlocked 后缀版本：不加锁，需自己保护 */
fputs_unlocked("hello", fp);   /* 快但不安全 */
```

stdio 默认线程安全（加锁），但锁开销显著。HFT 高频日志场景可用 `_unlocked` 版本 + 外部锁，或每线程独立缓冲。
