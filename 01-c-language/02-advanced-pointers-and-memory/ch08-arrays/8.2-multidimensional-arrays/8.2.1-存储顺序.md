# 8.2.1 存储顺序

## 本节讲什么

多维数组在内存中**按行平铺**（row-major），无指针间接层。这是 C 数组 cache 友好的根因，也是"按行遍历 vs 按列遍历"性能差异的来源——HFT 批量数组的核心。

## 要点

```c
int buf[4][3];
/* 内存顺序：[0][0] [0][1] [0][2] [1][0] [1][1] [1][2] [2][0] ... [3][2] */
```

- 地址递增：`&buf[i][j+1]` 相邻（同行内）；换行跳 `sizeof(int[3])` = 12 字节
- `buf[i][j]` 地址 = `base + (i*3 + j) * sizeof(int)`
- CPU 缓存：**按行访问局部性好**——HFT 批量数组优势
- 与指针数组不同：后者每元素是指针，**不一定连续**

### 按行 vs 按列遍历

```c
/* 按行遍历：cache 友好 */
for (i = 0; i < 4; i++)
    for (j = 0; j < 3; j++)
        buf[i][j] = 0;       /* 内层 j 连续访问 */

/* 按列遍历：cache 不友好 */
for (j = 0; j < 3; j++)
    for (i = 0; i < 4; i++)
        buf[i][j] = 0;       /* 内层 i 跨行，每步跳 12 字节 */
```

按行：内层 `j` 步进 4 字节，cache line 64 字节能装 16 个 int，连续命中。按列：内层 `i` 步进 12 字节，跨行可能每步 miss。

## 底层映射

### cache 行为对比

```
按行遍历 buf[4][3]（共 48 字节，< 1 cache line）：
  访问 [0][0],[0][1],[0][2],[1][0],... 地址递增
  → 1 次 cache miss 载入整块，后续全命中

按列遍历（假设大数组 buf[1024][1024]）：
  访问 [0][0],[1][0],[2][0],... 每步跳 4KB
  → 每步可能 miss（4KB 跨多个 cache line）
  → 性能差 10x+
```

这是为什么"循环嵌套顺序"对大数组性能影响巨大——把连续维度放内层。

### 行优先 vs 列优先（其他语言）

- C / C++ / Python numpy：**行优先**（row-major）
- Fortran / MATLAB：**列优先**（column-major）
- 互操作（BLAS/LAPACK）时要转置或注意 leading dimension

## HFT / DPDK

| 场景 | 要点 |
|------|------|
| 行情快照 `snap[N_SYM][N_LEVEL]` | 按行情遍历，内层 level 连续 |
| 帧缓冲 | stride 可能 ≥ 行宽（对齐填充），跨行跳更多 |
| 多端口队列 | `port_q[NPORT][NQ]` 按口遍历 |
| 矩阵运算 | 内层连续维度，触发 SIMD 向量化 |

### stride（跨度）

某些帧缓冲或图像格式行宽不等于 `width*sizeof(pixel)`——有对齐填充：

```c
/* stride ≥ width，跨行要跳 stride 而非 width */
for (i = 0; i < h; i++)
    for (j = 0; j < w; j++)
        fb[i*stride + j] = ...;   /* 显式 stride */
```

## 常见误区

| 误区 | 事实 |
|------|------|
| "按行按列遍历性能一样" | 大数组按列差 10x+（cache） |
| "多维数组有指针间接层" | 没有，连续平铺 |
| "C 是列优先" | 行优先（row-major） |
| "stride 等于行宽" | 对齐填充时 stride > 行宽 |

## 实操

```bash
# 对比按行 vs 按列遍历的 cache miss
cat > t.c << 'EOF'
#define N 2048
int big[N][N];
int main(void){
  int i,j,s=0;
  for(i=0;i<N;i++)for(j=0;j<N;j++)s+=big[i][j];   /* 按行 */
  return s;
}
EOF
gcc -O0 t.c -o t_row
# 改成按列，对比
perf stat -e cache-misses ./t_row
perf stat -e cache-misses ./t_col
# 看内存布局连续性
gcc -O2 -S t.c -o - | grep -A5 'main'
```

## 代码自测

**题目 1：** 以下代码中 arr[0][2] 和 arr[1][0] 在内存中哪个在前？
```c
int arr[2][3] = {{1, 2, 3}, {4, 5, 6}};
```

<details>
<summary>参考答案</summary>

arr[0][2]（值 3）在前。C 多维数组按行优先（row-major）存储——先存第一行所有元素，再存第二行。内存布局：arr[0][0], arr[0][1], arr[0][2], arr[1][0], arr[1][1], arr[1][2]。所以 arr[0][2] 紧挨在 arr[1][0] 前面。

</details>
