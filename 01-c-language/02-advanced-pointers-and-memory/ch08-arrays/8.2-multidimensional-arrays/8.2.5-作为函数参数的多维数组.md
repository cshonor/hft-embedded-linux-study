# 8.2.5 作为函数参数的多维数组

## 本节讲什么

二维数组传参：**第一维可省略，其余维度必须指定**——编译器需知**行字节宽**来算 `tbl[i][j]` 的线性偏移。这是多维接口最易写错的地方，也是经典面试题。

## 要点

```c
/* 合法：第二维 3 必须写 */
void process(int tbl[][3], int rows);
void process(int (*tbl)[3], int rows);   /* 等价 */

/* 非法：缺第二维 */
void bad(int tbl[][], int rows);          /* 编译错误 */
void bad(int tbl[][], ...);
```

- 形参类型实质：**指向 `int[3]` 的指针** `int (*)[3]`
- `tbl + i` 跳 i 行，每行 `3 * sizeof(int)` 字节
- 必须传 **`rows`**（第一维长度）

### 为什么第一维可省、其余不能

编译器算 `tbl[i][j]` 的线性地址需要"每行多少元素"（第二维 3）。第一维只决定"有多少行"，由调用者通过额外参数 `rows` 传入，编译器不需要它算偏移。

```
tbl[i][j] 地址 = base + (i*COLS + j)*sizeof(int)
                       ↑ COLS 必须已知（第二维）
```

第三维及以上同理：最外层可省，内层全要写。

```c
int cube[2][4][3];
void f(int c[][4][3], int n);    /* 只省第一维 */
```

### 三种等价写法

```c
void f(int tbl[][3], int rows);      /* 写法 1：方括号 */
void f(int (*tbl)[3], int rows);     /* 写法 2：数组指针 */
void f(int tbl[10][3], int rows);    /* 写法 3：第一维长度被忽略 */
```

写法 1 和 2 完全等价；写法 3 的 10 无约束作用（仅文档）。

## 底层映射

### 退化层次

```c
void f(int tbl[][3], int rows);
/* tbl 实际类型：int (*)[3] —— 指向一行的指针 */
/* tbl[i]：跳 i 行，类型 int*（行首元素） */
/* tbl[i][j]：int 值 */
```

`tbl` 退化成"指向一行的指针"，和 8.2.4 数组指针一致。

### 对比一维

```c
void f(int *p, int n);               /* 一维退化成指针 */
void g(int (*p)[COLS], int rows);    /* 二维退化成数组指针 */
void h(int **p, int rows);           /* 指针数组的退化（行分散） */
```

`int **p` 和 `int (*p)[COLS]` **完全不同**：前者是"行分散"的二级指针，后者是"行连续"的数组指针。传错类型 → UB 或编译错误。

## HFT / DPDK

| 接口 | 签名 |
|------|------|
| 连续行情表 | `void f(struct quote (*tbl)[N_LEVEL], int rows)` |
| 配置矩阵 | `void f(int (*cfg)[COLS], int rows)` |
| 帧缓冲 | `void f(char (*fb)[WIDTH], int rows)` |
| 分散 mbuf | `void f(struct mbuf **pkts, int n)`（指针数组） |

### DPDK 类比

连续二维行情表传 `quote (*table)[COLS]` + row count。分散 mbuf 用 `struct rte_mbuf **pkts`（指针数组退化）。

## 常见误区

| 误区 | 事实 |
|------|------|
| "`int tbl[][]` 合法" | 非法，缺第二维编译失败 |
| "`int **tbl` 能接收二维数组" | 不能，类型不匹配（行连续 vs 行分散） |
| "所有维都能省" | 只第一维可省，其余必须 |
| "`tbl[10][3]` 的 10 有约束" | 被忽略，仅文档 |

## 实操

```bash
# 验证第一维可省、第二维必须
cat > t.c << 'EOF'
void ok(int tbl[][3], int rows) {}
void ok2(int (*tbl)[3], int rows) {}
void bad(int tbl[][], int rows) {}   /* 应编译失败 */
EOF
gcc -c t.c -o t.o    # bad 报错
# 故意传 int** 给 int(*)[3] 看告警
cat > t2.c << 'EOF'
void f(int (*tbl)[3], int rows){}
int main(void){
  int **grid=0;
  f(grid, 4);    /* 类型不匹配告警 */
  return 0;
}
EOF
gcc -Wall t2.c -c
```

## 代码自测

**题目 1：** 以下哪种函数声明能正确接收 int arr[3][4] 参数？
```c
// A
void f(int **arr);
// B
void f(int (*arr)[4]);
// C
void f(int arr[3][4]);
```

<details>
<summary>参考答案</summary>

B 和 C 可以，A 不行。int arr[3][4] 的元素类型是 int[4]，退化为 int(*)[4]（指向 int[4] 的指针）。A 的 int** 是指向 int* 的指针，类型不匹配。B 和 C 等效（C 的第一维被忽略）。这是二维数组传参的经典陷阱。

</details>
