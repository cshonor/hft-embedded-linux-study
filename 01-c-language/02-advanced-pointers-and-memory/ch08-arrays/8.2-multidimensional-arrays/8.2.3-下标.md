# 8.2.3 下标

## 本节讲什么

二维下标展开与行/列访问模式。这一节把 `buf[i][j]` 的双重解引用拆开，讲清每次下标"剥一层"的过程——并钉死两件事：**两次 `*` 并不对称**（第一次免费、第二次才真正 load），以及**二维数组不是 `int**`**（真双重解引用是两次 load + 行分散）。

## 要点

```c
buf[i][j] == *(buf[i] + j) == *(*(buf + i) + j)
```

### 双重展开：五次类型变化

```c
int buf[4][3];
buf[i][j] == *(buf[i] + j) == *(*(buf + i) + j)
```

| 步骤 | 表达式 | 类型 | 步长 |
|------|--------|------|------|
| 退化 | `buf` | `int (*)[3]`（指向第 0 行） | — |
| 行偏移 | `buf + i` | `int (*)[3]`（第 i 行地址） | `sizeof(int[3])` = 12 |
| 第一次 `*` | `*(buf+i)` ≡ `buf[i]` | `int[3]`（行数组）→ 再退化为 `int *` | — |
| 列偏移 | `*(buf+i) + j` | `int *`（`&buf[i][j]`） | `sizeof(int)` = 4 |
| 第二次 `*` | `*(*(buf+i)+j)` | `int`（值） | — |

```c
/* buf + i：跳 i 行（每行 3 个 int） → 指向第 i 行 */
/* *(buf + i) = buf[i]：第 i 行，退化为 &buf[i][0]（int*） */
/* buf[i] + j：跳 j 个 int → 指向 buf[i][j] */
/* *(buf[i] + j) = buf[i][j]：int 值 */
```

### 两次 `*` 不对称：第一次免费，第二次才 load

"双重解引用"是个**有迷惑性的俗称**。C 语义层写了两个 `*`，机器层只有**一次** load：

- **第一次 `*` 不产生任何内存访问。** `*(buf+i)` 得到的是行数组 `int[3]`（一个左值），它作为 `+` 的操作数**立即又退化**成 `int *`——地址数值不变，只是类型解释从 `int(*)[3]` 换成 `int*`。编译器眼里 `*(buf+i)+j` 和 `(int*)(buf+i)+j` 是同一个值。
- **第二次 `*` 才真正 load**，从 `&buf[i][j]` 取出 `int`。

**真正的双重解引用是 `int **`：第一次 `*` 必须先去内存读出一个指针（行地址存在别处），第二次才能读值——两次 load，而且各行可能分散在堆上。对比：

| | `int buf[4][3]` | `int *p[4]`（退化为 `int**`） |
|--|------------------|------------------------------|
| 内存布局 | 12 个 int 连续 48 字节 | 4 个指针连续，各行**分散**在堆上 |
| `x[i][j]` 访存 | **1 次 load**（基址+(i×3+j)×4 编译期算） | **2 次 load**（先读行指针，再读值） |
| `sizeof(x)` | 48 | 32（4 个指针） |
| cache | 行连续，预取友好 | 行分散，可能每行一次 miss |

HFT 落点：热路径传二维表用 `int (*row)[COLS]` 或干脆打平成 `buf[i*COLS+j]` 的一维数组——**不要 `int**`**。

### 行列遍历

```c
for (i = 0; i < 4; i++)
    for (j = 0; j < 3; j++)
        buf[i][j] = 0;     /* 按行，cache 友好（8.2.1） */
```

外层 `i` 选行，内层 `j` 选列——内层连续访问，cache 命中率高。

### 指针风格的二维遍历

```c
int (*row)[3];
for (row = buf; row < buf + 4; row++) {     /* 行游标 */
    int *p;
    for (p = *row; p < *row + 3; p++)        /* 列游标 */
        *p = 0;
}
```

`row` 是数组指针（**8.2.4**），`*row` 是当前行首元素地址（`int*`）。

## 底层映射

### 编译期线性化

```c
int buf[4][3];
buf[i][j] = 0;
```

```
; x86-64 -O2（buf 在 [rsp]）
; buf[i][j] 地址 = base + (i*3 + j)*4
mov     DWORD PTR [rsp + rdi*12 + rsi*4], 0
; i 在 rdi（乘 12 = 3*4），j 在 rsi（乘 4）
; 硬件 SIB 比例变址：[base + idx1*scale1 + idx2*scale2]
```

编译器用第二维（3）算行宽，把 `buf[i][j]` 线性化成 `[base + i*行宽 + j]`。硬件 SIB 寻址原生支持两个比例变址，无 imul。

### 三维及以上

```c
int cube[2][4][3];
cube[i][j][k] == *(*(*(cube + i) + j) + k);
/* 地址 = base + (i*4*3 + j*3 + k)*sizeof(int) */
```

每多一维，多一层"剥皮"，编译器用各维大小算线性偏移。

## HFT / DPDK

| 场景 | 用法 |
|------|------|
| 内核设备表 | `dev[id][chan]` |
| 行情深度 | `quote[symbol][level]` |
| 配置矩阵 | `cfg[row][col]` |
| 帧缓冲 | `fb[y][x]`（注意 stride） |

### VLA 多维（C99）

```c
void f(int rows, int cols) {
    char grid[rows][cols];    /* VLA 二维 */
    grid[i][j] = ...;
}
```

VLA 二维的行宽运行时定，编译器无法编译期线性化——要运行时乘法。HFT 热路径禁用（**8.1.7**）。

## 常见误区

| 误区 | 事实 |
|------|------|
| "`buf[i][j]` 有两次访存" | 编译期线性化成一次访存（连续存储） |
| "'双重解引用' = 两次 `*` 都读内存" | 第一次 `*` 免费（行数组立即退化回同地址）；真两次 load 的是 `int**` |
| "`int **p = buf` 只是风格不同" | 布局都不同：二维连续 48 字节 vs 指针数组 + 行分散；`buf` 退化是 `int(*)[3]`，类型也不匹配 |
| "外层内层顺序无所谓" | 大数组按列遍历 cache 差 10x |
| "三维数组更复杂访存" | 仍编译期线性化，一次访存 |
| "VLA 二维和定长一样快" | VLA 要运行时乘法算偏移 |

## 实操

```bash
# 看二维下标的线性化汇编
cat > t.c << 'EOF'
int buf[4][3];
int get(int i, int j) { return buf[i][j]; }
EOF
gcc -O2 -S t.c -o - | grep -A5 '^get'
# 看 [base + idx*12 + idx*4] 的比例变址
# 三维同理
cat > t3.c << 'EOF'
int cube[2][4][3];
int get(int i,int j,int k){return cube[i][j][k];}
EOF
gcc -O2 -S t3.c -o - | grep -A5 '^get'
```

## 代码自测

**题目 1：** 以下代码合法吗？输出什么？
```c
int arr[2][3] = {{1, 2, 3}, {4, 5, 6}};
int *p = &arr[0][0];
printf("%d\n", p[4]);
```

<details>
<summary>参考答案</summary>

合法，输出 5。二维数组在内存中是连续的，p 指向首元素。p[4] 等价于 *(p + 4)，访问第 5 个 int，即 arr[1][1] = 5。这种"扁平化"访问虽然合法，但不推荐——可读性差。

</details>

**题目 2：** `int buf[3][4];` 放进表达式里，`buf` 退化之后是什么类型？

A. `int **`　B. `int *`　C. `int (*)[4]`　D. `int[4]`

<details>
<summary>参考答案</summary>

**C**。退化规则是"指向首元素的指针"——二维数组的首元素不是单个 `int`，而是**一整行 `int[4]`**，所以 `buf` 退化为指向行的指针 `int (*)[4]`。这是最多人卡壳的地方：不管几维数组，退化只剥**最外一层**。选 A 是把"二维"和"指针的指针"混为一谈（布局完全不同，见本节对比表）；选 B 忘了首元素是行；选 D 没退化。

</details>

**题目 3：** 64 位平台，`int buf[3][4];`：

1. `sizeof(buf)`、`sizeof(buf[0])`、`sizeof(&buf[0])` 各是多少？
2. `buf + 1` 和 `&buf + 1` 的地址差各是多少字节？

<details>
<summary>参考答案</summary>

1. **48 / 16 / 8**。`sizeof(buf)` 是整个数组 3×4×4；`buf[0]` 是一行 `int[4]` 为 16；`&buf[0]` 是指针，恒 8。
2. `buf + 1`：`buf` 退化为 `int(*)[4]`，步长 = 一行 = **16 字节**；`&buf + 1`：类型 `int(*)[3][4]`，步长 = 整个数组 = **48 字节**。两者数值起点相同，类型不同，步长差 3 倍——同一地址的三种解释（`buf` / `&buf[0][0]` / `&buf`）见 8.2.2。

</details>
