# 8.1 一维数组

## 本节讲什么

**同类型连续内存块**；承接 **ch06** 的 `arr[i] ≡ *(arr+i)`，展开初始化、传参退化、长度计算与字符数组。数组是 C 里最基础也最易错的数据结构——"数组不是指针"这个误区会在 8.1.5 彻底澄清。

## 要点

- **数组是对象，指针是变量**：`sizeof(a)`=40 vs `sizeof(p)`=8；数组名**不可赋值、不可自增**
- 退化只发生在特定上下文：**4 个上下文不转换**（`sizeof` / `_Alignof` / 一元 `&` / 字符串字面量初始化数组），详见 [8.1.1](./8.1.1-数组名.md)
- 局部数组 → **栈**；全局/static → **`.data`/`.bss`**
- 传参必带 **长度**（退化后 `sizeof` 失效）
- 数组不可整体赋值（`a = b` 非法），只能逐元素或 `memcpy`
- **`= {0}` 结果上是全 0**，但机制是「第 0 个元素显式给 0 + 其余按标准隐式补 0」——**不是「一个总的 0」**（用 `{1}` 一行证伪，详见 [8.1.8](./8.1.8-初始化.md)）

```c
int a[10];                 /* 栈上，未初始化 → 脏值 */
int b[10] = {0};           /* 全 0 */
int c[] = {1, 2, 3};       /* 长度推导为 3 */
static int s[100];          /* .bss，自动清零 */
```

## 底层映射

### 存储位置与初始化

| 定义 | 段 | 未初始化值 |
|------|-----|-----------|
| 函数内 `int a[10];` | 栈 | 脏值 |
| 函数内 `int a[10] = {0};` | 栈 | 0（显式） |
| 全局 `int g[10];` | `.bss` | 0 |
| 全局 `int g[10] = {1};` | `.data` | g[0]=1，其余 0 |
| `static int s[10];` | `.bss` | 0 |

栈数组未初始化是脏值——上一个栈帧的残留（**ch06 6.5**）。HFT 惯例：**需要确定性初值**的栈数组用 `= {0}`；马上被完整覆盖的中转缓冲可不清（判据见 [8.1.8](./8.1.8-初始化.md)）。

### 数组 vs 指针：一句话对照

| | `int a[10]` | `int *p` |
|---|---|---|
| 是什么 | 对象（10 个 int 的连续块） | 变量（存一个地址） |
| `sizeof` | 40 | 8 |
| `&x` 类型 | `int (*)[10]` | `int **` |
| `x = ...` / `x++` | **非法** | 合法 |
| 传参 | 退化为 `int *` | `int *` |

完整 12 项对照 + 六条独立证据（类型探针 / sizeof / 步长 / 可修改性 / 符号表 / 汇编）见 [8.1.5](./8.1.5-数组和指针.md)。

### 退化规则（核心，8.1.1 详）

数组类型的表达式（数组名/字符串字面量/复合字面量）在**除以下 4 个上下文外**都转换为首元素指针：

```c
int a[10];
size_t n = sizeof(a);       /* 40，不转换（例外 1） */
int (*p)[10] = &a;          /* 指向整个数组，不转换（例外 3） */
int *q = a;                 /* 转换 → &a[0] */
f(a);                       /* 传参转换 */
char s[] = "hi";            /* 字面量不转换（例外 4，主语是字面量不是数组名） */
```

## 核心要点速查

把本章散落的机制串成一条主线：**退化 → 内存分段 → 传参 → 拷贝**。

### ① 退化：主语是「数组类型表达式」，例外属于「上下文」（C11 6.3.2.1p3）

| 上下文 | 是否转换 | 结果 |
|--------|----------|------|
| 一般表达式 `arr` | 退化 | `int *`，值 = `&arr[0]` |
| `sizeof(arr)` | **不转换**（例外 1） | `40`，整个数组字节数 |
| `_Alignof(arr)` | 标准只吃 type-name | `_Alignof(arr)` 是 GNU 扩展；标准写 `_Alignof(int[10])` |
| `&arr` | **不转换**（例外 3） | `int (*)[10]`，值同类型不同 |
| 用于初始化数组的字符串字面量 | **不转换**（例外 4） | `char s[] = "hi"` → `char[3]` |
| 函数实参 | 退化 | 形参本质就是指针 |

> ⚠️ **例外数目为什么有 3/4 两种说法**：C11 6.3.2.1p3 文本列了 **4 项**（`sizeof`、`_Alignof`、一元 `&`、字符串字面量初始化数组）；但 6.5.3.4p3 规定 `_Alignof` 只接受 **type-name**，不接受表达式——所以**对表达式实际生效的是 3 项**。两个数都没错，但必须说清在数什么。详见 [8.1.1](./8.1.1-数组名.md)。
> ⚠️ 第 4 条例外的主语是**字符串字面量**，不是数组名——数组名压根不可能出现在初始化器位置（`char t[] = s;` 报 `invalid initializer`）。

### ② 内存分段：有无 `=` 决定 `.data`，函数内外决定栈/静态

| 声明 | 位置 | 初值 |
|------|------|------|
| 函数内 `int a[10];` | **栈** | 脏值 |
| 函数内 `int b[10] = {0};` | **栈** | 全 0 |
| 全局 + 有初始化 | **`.data`** | 给定值，其余补 0 |
| 全局 + 无初始化 | **`.bss`**（Mach-O 实测为 `__common`） | 自动清零 |
| `static int s[100];` | **`.bss`** | 自动清零 |

### ③ 传参必退化：长度必须自己带

```c
void func(int arr[], int len);   /* 两种写法完全等价 */
void func(int *arr, int len);    /* 编译器眼里没有区别 */
```

函数内 `sizeof(arr)` 是 **8**。clang 会主动警告 `-Wsizeof-array-argument`。

### ④ 不能整体赋值：只有 for 和 memcpy

```c
int a[10], b[10];
a = b;                                 /* ❌ array type 'int[10]' is not assignable */
for (i = 0; i < 10; i++) a[i] = b[i];  /* ✅ 逐元素 */
memcpy(a, b, sizeof(a));               /* ✅ 整块复制（必须在定义域） */
```

### ⑤ 三处流传很广但不严谨的说法

| 常见说法 | 更正 |
|---------|------|
| "数组名不退化的第三例外是 `[]` 推导长度" | 因果错位。标准是**字面量**在那个上下文不转换（第 4 条例外），`[]` 能推导长度是**结果** |
| "数组名有三个不退化例外" | 不严谨。① 例外属于**上下文**，不属于数组名这个实体；② C11 文本 **4 项**；③ 第 4 个上下文里数组名不可能出现 |
| "`sizeof(&arr)` 能拿到数组大小" | 不能，是 8。要 40 用 `sizeof(arr)` 或 `sizeof(*&arr)` |
| "未初始化全局数组在 `.bss`" | ELF 成立；Mach-O 实测落 `__DATA,__common`。共同点：不占文件体积、加载时清零 |
| "`printf("%p", arr)` 没问题" | 严格应写 `(void *)arr`；可变参数不做隐式转换，传 `int *` 形式上是 UB |

## 工程陷阱（本章汇总）

| 陷阱 | 规避 |
|------|------|
| 传参丢长度 | 显式 `len` 参数 |
| 栈上大数组爆栈 | `malloc`/静态池 |
| 未初始化栈数组脏值 | `= {0}` |
| 大 VLA 栈溢出 | HFT 禁用，改堆或定长 |
| 越界无运行时检查 | ASan / 显式边界检查 |
| 游标越过尾后（`arr+n+1`）| 半开区间 `[arr, arr+n)` + `<`，别用 `!=`（[8.1.3](./8.1.3-指针与下标.md)） |
| 跨数组指针用 `<` 比较 | UB 且 sanitaizer 抓不到，改用序号 / 时间戳 |
| 跨数组指针相减 `&b[0]-&a[0]` | 同样是 UB——相减与 `<` 受同一条限制（§6.5.6p9） |
| `sizeof(arr)` 在函数内失效 | 传 `len`，或用宏仅在定义域 |

## HFT / DPDK

| 场景 | 用法 |
|------|------|
| 报文缓冲 | `char buf[2048]` 栈上定长 |
| 批量收包 | `struct rte_mbuf *pkts[32]` 指针数组 |
| 行情快照 | `struct quote snap[MAX_SYMBOLS]` 静态池 |
| 配置表 | `const struct cfg tables[N]` 在 `.rodata` |
| 只读查表 | `static const int opcode_map[] = {...}` 落只读段，缺页即映射，不占可写页 |
| 整块拷贝 | `memcpy(dst, src, sizeof(src))` 优于 for，编译器常内联为向量指令 |
| 栈空间预算 | 内核栈仅 4–16 KB，函数内 `char buf[4096]` 就有溢出风险；大数组声明为 `static`/全局落 `.bss` |
| 零初始化代价 | `int b[N] = {0}` 对大数组有清零开销；热路径按需赋值，不要每次 `memset` |

## 常见误区

| 误区 | 事实 |
|------|------|
| "数组就是指针" | 不是——数组有大小，多数表达式里退化 |
| "栈数组自动清零" | 不，栈数组未初始化是脏值 |
| "函数内 sizeof(arr) 能拿数组大小" | 退化成指针，拿到 8 |
| "VLA 和定长数组一样安全" | VLA 大小运行时定，栈溢出风险 |

## 代码自测

**题目 1：** 以下代码输出什么？为什么？
```c
int arr[5] = {1, 2, 3, 4, 5};
printf("%d %d\n", arr[0], *arr);
printf("%d %d\n", arr[2], *(arr + 2));
```

<details>
<summary>参考答案</summary>

两行都输出相同的值：1 1 和 3 3。数组名 arr 在表达式中退化为指向首元素的指针。arr[0] 和 *arr 等价，arr[2] 和 *(arr + 2) 等价。C 中 a[i] 就是 *(a + i) 的语法糖。

</details>
