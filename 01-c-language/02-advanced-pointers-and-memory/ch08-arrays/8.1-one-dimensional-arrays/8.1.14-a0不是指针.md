# 8.1.14 `a[0]` 不是指针

## 本节讲什么

**一句话：`a[0]` 是 `int` 类型的对象（数组的第一个元素），不是指针。**

它是 `*(a + 0)` 的**解引用结果**——拿到的是"那个地址上存的数据"，不是地址本身。本节把 `a`、`&a[0]`、`&a`、`a[0]` 四个表达式一次分清，并解决三个由此派生的高频混淆：

1. `a[0]` 是**左值**（可取地址、可赋值），而退化后的 `a` **不是左值**
2. 二维数组里 `m[0]` **是数组**（退化后才是 `int *`）——"下标取出来的是不是指针"，取决于**元素类型**
3. 指针数组 `struct mbuf *pkts[32]` 的 `pkts[0]` **本来就是指针**

配套：[8.1.1 数组名与退化](./8.1.1-数组名.md)、[8.1.13 数组指针的步长](./8.1.13-数组指针的步长.md)、[8.1.12 `void *` 与地址值](./8.1.12-void指针与地址值.md)。

## 要点

```c
int a[5] = {10, 20, 30, 40, 50};

a;       /* 数组表达式，一般上下文退化 → int *        （指针） */
&a[0];   /* 取元素地址 → int *                        （指针） */
&a;      /* 取整个数组地址 → int (*)[5]               （指针） */
a[0];    /* 元素本身 → int                            （不是指针！） */
```

| 表达式 | 类型 | 是指针吗 | `sizeof` | 能不能放赋值号左边 |
|--------|------|---------|----------|-------------------|
| `a` | 一般上下文 `int *`（`sizeof` 下是 `int[5]`） | 退化后是 | **20** | ❌ `array type 'int[5]' is not assignable` |
| `&a[0]` | `int *` | ✅ | 8 | ❌（不是左值） |
| `&a` | `int (*)[5]` | ✅ | 8 | ❌（不是左值） |
| `a[0]` | `int` | ❌ **不是** | **4** | ✅ **可修改左值** |

### 拆解 `a[0]` 的本质（三步）

```c
a[0]   ≡   *(a + 0)          /* C11 6.5.2.1p2 的定义，不是"语法糖" */
```

| 步 | 发生了什么 | 结果 |
|----|-----------|------|
| ① `a` | 数组表达式退化（6.3.2.1p3） | `int *`，值 = `&a[0]` |
| ② `a + 0` | 指针算术，步长 `sizeof(int)`，加 0 不变 | `int *`，值仍是 `&a[0]` |
| ③ `* (...)` | **解引用**（6.5.3.2p4） | `int`——访问该地址上存的那个数据 |

C11 **6.5.2.1p2**（逐字要点）：

> A postfix expression followed by an expression in square brackets `[]` is a subscripted designation of an element of an array object. The definition of the subscript operator `[]` is that `E1[E2]` is identical to `*((E1)+(E2))`.

标准用的是 **"identical to"（等同）**——这是**定义**，不是"编译器把它展开成"的实现细节。所以 `a[0]`、`*a`、`*(a+0)`、`0[a]` 四者是**同一个表达式的四种写法**，类型和值完全一致。

### 类比

| 概念 | 比喻 |
|------|------|
| 指针（`a`、`&a[0]`） | 门牌号（地址） |
| `a[0]` | 房间**里面**放的那个数字 |
| `&a[0]` | 101 房间的门牌号 |

门牌号不是房间里的内容——`a[0]` 是内容，`&a[0]` 才是门牌号。

## ★ 左值性：`a[0]` 与 `a` 的硬分界

C11 **6.5.3.2p4**：一元 `*` 的操作数若指向一个对象，**结果是左值**（lvalue）。所以 `a[0]` ≡ `*(a+0)` 是左值：

```c
int a[5] = {10, 20, 30, 40, 50};
&a[0];          /* ✅ 能取地址 → 说明 a[0] 是左值 */
a[0] = 99;      /* ✅ 能赋值   → 说明是可修改左值 */
```

反过来，退化出来的指针**不是左值**——6.3.2.1p3 结尾那句常常被漏掉：

> ... is converted to an expression with type "pointer to type" that points to the initial element of the array object **and is not an lvalue**.

而数组本身也不可赋值（实测 clang 23.1.0）：

```
$ clang -std=c11 -c t.c        # 源码写 a = 0;
error: array type 'int[5]' is not assignable
```

> **一句话**：`a[0]` 是"对象"（有身份、可取地址、可写）；`a` 退化后只是"一个地址值"（无身份）。这也是 [8.1.5](./8.1.5-数组和指针.md)"数组是对象、指针是变量"的另一条证据。

### `sizeof` 的三个答案（退化例外的现场）

同一块 20 字节内存，问法不同答案不同：

```c
sizeof(a);      /* 20 —— sizeof 上下文不退化，量整个数组 */
sizeof(&a[0]);  /*  8 —— 指针值 */
sizeof(a[0]);   /*  4 —— 元素本身 */
```

这三个数同时出现，就是"退化属于上下文、不属于数组名这个实体"最直观的演示（详见 [8.1.1](./8.1.1-数组名.md)）。

## ★ 混淆的真正来源：二维数组里 `m[0]` 是数组

很多人"觉得 `a[0]` 是指针"，是因为把**二维数组**的经验套回了一维：

```c
int a[5];        /* 一维：a[0] 是 int            —— 元素类型是 int   */
int m[3][5];     /* 二维：m[0] 是 int[5]（数组） —— 元素类型是 int[5] */
```

实测（clang 23.1.0，`_Generic` 探针 + `sizeof`）：

```
[1] a[0]      type=int          sizeof=4   value=10
    *a        type=int          value=10
    *(a+0)    type=int          value=10
    0[a]      type=int          value=10

[4] 二维：m[0] type=int *  sizeof=20  退化后 sizeof=8
    *m        type=int *
```

注意 `[4]` 那两行看似矛盾、实则完美对上：

- `sizeof m[0]` = **20** → `m[0]` 的**真实类型**是 `int[5]`（一整行）
- `_Generic(m[0])` 显示 `int *`，`sizeof(m[0] + 0)` = **8** → 一旦进入"一般表达式"上下文（做算术、当函数实参），它就**退化**成 `int *`

也就是说：**一维的 `a[0]` 是 `int`；二维的 `m[0]` 是 `int[5]`（退化后才是 `int *`）**。下标取出来的东西是什么类型，永远看**元素类型**，不看下标本能。

> 顺带一个实测副产品：`sizeof(m[0] + 0)` 会触发
> `warning: sizeof on pointer operation will return size of 'int *' instead of 'int[5]' [-Wsizeof-array-decay]`
> ——clang 直接告诉你"这里已经退化了"，是排查这类 bug 的免费提示。

### 指针数组：元素本来就是指针

```c
struct mbuf *pkts[32];   /* 元素类型是 struct mbuf * */
pkts[0];                 /* 类型 struct mbuf * —— 它本来就是指针 */
```

实测：`pkts[0] type=struct mbuf *  sizeof=8`。

所以"下标取出来的是不是指针"这个问题的答案是：**取决于元素类型**。

| 声明 | 元素类型 | `x[0]` 的类型 | 是指针吗 |
|------|---------|--------------|---------|
| `int a[5]` | `int` | `int` | ❌ |
| `int m[3][5]` | `int[5]` | `int[5]`（退化后 `int *`） | 退化后是 |
| `struct mbuf *pkts[32]` | `struct mbuf *` | `struct mbuf *` | ✅ 本来就是 |
| `char buf[64]` | `char` | `char` | ❌ |

## 标准依据

| 条款 | 内容 | 对本节的意义 |
|------|------|-------------|
| C11 **6.5.2.1p2** | `E1[E2]` **identical to** `*((E1)+(E2))` | `a[0]` ≡ `*(a+0)` 是**定义**；`0[a]` 因此也合法 |
| C11 **6.3.2.1p3** | 数组表达式退化 → 首元素指针，**且不是左值** | 为什么 `a = 0` 非法 |
| C11 **6.5.3.2p4** | `*` 作用于指向对象的指针 → 结果是**左值** | 为什么 `a[0]` 可取地址、可赋值 |
| C11 **6.5.6p8** | 指针算术越界 → UB | `a[5]`（第 6 个元素）不存在，形成即 UB |

## 实测

**完整输出**（clang 23.1.0，`-std=c11 -Wall`，arm64 / LP64）：

```
[1] a[0]      type=int  sizeof=4  value=10
    *a        type=int  value=10
    *(a+0)    type=int  value=10
    0[a]      type=int  value=10
[2] a         type=int *  sizeof=20
    &a[0]     type=int *  sizeof=8
    &a        type=int (*)[5]  sizeof=8
[3] 左值性：&a[0] = 0x16d3fb5d0  （a[0] 可取地址 → 是左值）
    a[0] = 99 后 a[0] = 99  （可赋值 → 可修改左值）
[4] 二维：m[0] type=int *  sizeof=20  退化后 sizeof=8
    *m        type=int *
[5] 指针数组：pkts[0] type=struct mbuf *  sizeof=8
```

`[2]` 第一行最值得看：`_Generic(a)` 说 `int *`（退化），`sizeof a` 说 **20**（`sizeof` 上下文不退化）——同一个 `a`，两个上下文给出两种身份。

## HFT / DPDK

| 场景 | 写法 | 要点 |
|------|------|------|
| 行情池取值 | `snap[i]` 是**结构体对象**，不是指针 | 要地址写 `&snap[i]` 或 `snap + i` |
| burst 数组 | `pkts[i]` **是指针**（`struct rte_mbuf *`） | 直接用，不要写 `*pkts[i]` |
| 批量遍历 | `for (i = 0; i < n; i++) decode(pkts[i]);` | `pkts[i]` 传的就是指针 |
| 定长表 | `opcode_map[i]` 是 `int` 值 | 查表拿值，不是地址 |
| 字节缓冲 | `buf[i]` 是 `char` | 做偏移请用 `buf + i`（指针）或 `&buf[i]` |
| 大对象 | 传 `&big[i]` 而非拷贝 `big[i]` | 结构体元素传值会整块拷贝 |

## 常见误区

| 误区 | 事实 |
|------|------|
| "`a[0]` 是指针，它和 `a` 一样" | `a[0]` 是 `int`；`a` 退化后才是 `int *` |
| "`a[0]` 和 `&a[0]` 是一回事" | 前者是元素值（`int`），后者是元素地址（`int *`） |
| "`a[0]` 不是左值，不能赋值" | 是**可修改左值**：`a[0] = 99` 完全合法（6.5.3.2p4） |
| "`a = 0` 只是不能改数组首地址" | `array type 'int[5]' is not assignable`——数组表达式压根不是左值 |
| "二维数组 `m[0]` 是 `int`" | 是 `int[5]`（`sizeof m[0]` = 20），退化后才是 `int *` |
| "`pkts[0]` 要解引用才是 mbuf" | `pkts[0]` **本身**就是 `struct mbuf *` |
| "`[]` 取出来的一定是元素、不是指针" | 取决于**元素类型**：`pkts[0]` 就是指针 |
| "`a[5]` 读到的是尾后" | `a[5]` 越界，形成即 UB（不是"读到垃圾"，是未定义） |

## 实操

```bash
# 1. 四个表达式的类型 / sizeof / 左值性全量探针
cat > t.c << 'EOF'
#include <stdio.h>
#define TY(x) _Generic((x), int: "int", int *: "int *", \
                       int (*)[5]: "int (*)[5]", default: "?")
int main(void) {
    int a[5] = {10,20,30,40,50};
    int m[3][5] = {0};
    struct mbuf { int x; } *pkts[3] = {0};
    printf("a[0]=%s sizeof=%zu val=%d\n", TY(a[0]), sizeof a[0], a[0]);
    printf("a   =%s sizeof=%zu\n",        TY(a),    sizeof a);
    printf("&a[0]=%s sizeof=%zu\n",       TY(&a[0]),sizeof &a[0]);
    printf("&a  =%s sizeof=%zu\n",        TY(&a),   sizeof &a);
    printf("m[0] sizeof=%zu (退化后=%zu)\n", sizeof m[0], sizeof(m[0]+0));
    printf("pkts[0]=%s sizeof=%zu\n",
           _Generic((pkts[0]), struct mbuf *: "struct mbuf *", default: "?"),
           sizeof pkts[0]);
    a[0] = 99;                    /* 左值：可赋值 */
    printf("&a[0]=%p  a[0]=%d\n", (void *)&a[0], a[0]);   /* 可取地址 */
    return 0;
}
EOF
clang -std=c11 -Wall t.c -o t && ./t

# 2. 数组表达式不是左值
printf 'int main(void){int a[5];a=0;return 0;}\n' > lv.c
clang -std=c11 -c lv.c -o /dev/null     # error: array type 'int[5]' is not assignable

# 3. 二维下标的退化告警（免费提示）
printf '#include <stdio.h>\nint main(void){int m[3][5];printf("%%zu",sizeof(m[0]+0));}\n' > d.c
clang -std=c11 -c d.c -o /dev/null      # -Wsizeof-array-decay
```

## 代码自测

**题目 1：** 表达式 `*(a)` 的类型是什么？（`int a[5];`）

A. `int`　　B. `int *`　　C. `int (*)[5]`

<details>
<summary>参考答案</summary>

**A（`int`）。**

`a` 退化成 `int *`（值 = `&a[0]`），`*` 对这个指针解引用 → 得到 `a[0]` 这个 `int` 对象。实测 `_Generic(*a)` → `int`，`sizeof *a` = 4。

要 `int *` 请写 `a` 或 `&a[0]`；要 `int (*)[5]` 请写 `&a`。

</details>

**题目 2：** 以下代码分别输出什么？为什么？

```c
int a[5] = {10, 20, 30, 40, 50};
printf("%zu %zu %zu\n", sizeof(a), sizeof(&a[0]), sizeof(a[0]));
```

<details>
<summary>参考答案</summary>

**20  8  4**（64 位、`sizeof(int) = 4`）。

- `sizeof(a)` = 20：`a` 作 `sizeof` 操作数**不退化**，量的是整个数组
- `sizeof(&a[0])` = 8：已经是 `int *` 指针值
- `sizeof(a[0])` = 4：`a[0]` 是 `int` 元素本身

同一块 20 字节内存，三种问法三个答案——退化是**上下文**的属性，不是数组名的属性（[8.1.1](./8.1.1-数组名.md)）。

</details>

**题目 3：** `a[0]` 能放在赋值号左边吗？`a` 呢？

<details>
<summary>参考答案</summary>

- `a[0] = 99;` **可以**。`a[0]` ≡ `*(a+0)`，按 6.5.3.2p4，解引用指向对象的指针得到**左值**，而且是可修改左值。`&a[0]` 也因此合法。
- `a = 0;` **不行**。数组表达式退化产生的指针"is not an lvalue"（6.3.2.1p3），数组本身也不可赋值。实测：`error: array type 'int[5]' is not assignable`。

想改数组内容就逐元素赋值或 `memcpy`（[8.1.4](./8.1.4-指针的效率.md) 有性能对照）。

</details>

**题目 4：** `int m[3][5];` 中 `m[0]` 是什么类型？为什么有人会以为它是 `int`？

<details>
<summary>参考答案</summary>

`m[0]` 的类型是 **`int[5]`**（一整行，`sizeof m[0]` = **20**）；进入一般表达式上下文后退化成 `int *`（所以 `_Generic(m[0])` 显示 `int *`、`sizeof(m[0]+0)` = 8）。

混淆来自把**一维**的经验套过来：一维 `int a[5]` 的元素类型是 `int`，所以 `a[0]` 是 `int`；二维 `int m[3][5]` 的元素类型是 `int[5]`，所以 `m[0]` 是数组。

**判据**：下标取出来的是什么，永远看**元素类型**，不看下标本能。这也解释了 `struct mbuf *pkts[32]` 的 `pkts[0]` 为什么是 `struct mbuf *`——元素类型就是指针。

</details>
