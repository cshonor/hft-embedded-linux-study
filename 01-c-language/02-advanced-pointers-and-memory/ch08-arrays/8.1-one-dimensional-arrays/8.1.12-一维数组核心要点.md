# 8.1.12 一维数组核心要点

## 本节讲什么

把 8.1.1–8.1.11 散落的机制串成一条主线：**退化 → 内存分段 → 传参 → 拷贝**，并在真机（arm64 / LP64）上用 `sizeof`、指针算术、`nm` 逐条实测验证。同时纠正三个流传很广但**表述不严谨**的说法。

## 要点

### 一、数组名的退化与三个例外

```c
int arr[10];
sizeof(arr);      /* 不退化：40（10 * sizeof(int)） */
sizeof(&arr[0]);  /* 退化：8（指针大小） */
sizeof(&arr);     /* 也是 8：&arr 本身是指针值 */
```

| 上下文 | 是否退化 | 结果 |
|--------|----------|------|
| 一般表达式 `arr` | 退化 | `int *`，值 = `&arr[0]` |
| `sizeof(arr)` | **不退化** | `40`，整个数组字节数 |
| `&arr` | **不退化** | `int (*)[10]`，值同但类型不同 |
| 字符串字面量初始化数组 | **不退化** | 见下方第三条修正 |
| 函数实参 | 退化 | 形参本质就是指针 |

### 二、数组存放在哪一段

| 声明 | 位置 | 初值 |
|------|------|------|
| 函数内 `int a[10];` | **栈** | 脏值（栈上残留） |
| 函数内 `int b[10] = {0};` | **栈** | 全 0（有初始化） |
| `static int s[100];`（含函数内 static） | **`.bss`** | 自动清零 |
| 全局 + 显式初始化 `int g[4] = {...};` | **`.data`** | 给定值 |
| 全局 + 无初始化 `int g[4];` | **`.bss`**（Mach-O 上为 `__common`） | 自动清零 |

### 三、传参必退化：长度必须自己带

```c
void func(int arr[], int len);   /* 两种写法完全等价 */
void func(int *arr, int len);    /* 编译器眼里没有区别 */
```

函数内 `sizeof(arr)` 拿到的是**指针大小 8**，不是数组长度。clang 甚至会主动警告：

```
warning: sizeof on array function parameter will return size of 'int *'
         instead of 'int[]' [-Wsizeof-array-argument]
```

### 四、数组不能整体赋值

```c
int a[10], b[10];
a = b;                        /* ❌ 非法：array type is not assignable */
for (i = 0; i < 10; i++) a[i] = b[i];   /* ✅ 逐元素 */
memcpy(a, b, sizeof(a));                /* ✅ 整块复制 */
```

## 底层映射

### 数值相同、类型不同：用指针算术才看得见

光打印 `%p` 只能看到三者数值相同，**看不出类型差异**。真正能"看见"类型的是步长：

```
arr     = 0x16dbe09c0
&arr    = 0x16dbe09c0     ← 数值完全相同
&arr[0] = 0x16dbe09c0

arr  + 1 = 0x16dbe09c4    前进  4 字节  ← 步长 = sizeof(int)
&arr + 1 = 0x16dbe09e8    前进 40 字节  ← 步长 = sizeof(整个数组)
```

同一个起始地址，`+1` 一个跳 4 字节、一个跳 40 字节——这就是 `int *` 与 `int (*)[10]` 的硬证据。

### 段归属的二进制证据（`nm`）

```bash
$ llvm-nm -m array_decay_demo | grep -E 'g_init|g_uninit|s_uninit|_main'
0000000100008030 (__DATA,__data)   external _g_init
0000000100008360 (__DATA,__common) external _g_uninit
0000000100008040 (__DATA,__bss)    non-external _main.s
00000001000081d0 (__DATA,__bss)    non-external _s_uninit
```

注意 `g_uninit` 落的是 **`__common` 而非 `__bss`**——这是 Mach-O 与 ELF 的一个真实差异（见下一节）。

### 字符串字面量的标准依据（C11 6.3.2.1p3）

标准原文列出的三种"不转换"情形是：`sizeof` 的操作数、一元 `&` 的操作数、**用于初始化数组的字符串字面量**。第三种针对的是**字面量本身**，不是数组名：

```c
char s[] = "hello";   /* 字面量不退化 → 推导出 char[6]，sizeof(s) == 6 */
char *p  = "hello";   /* 同一字面量在此退化为 char*，sizeof(p) == 8 */
```

## HFT / DPDK

| 场景 | 要点 |
|------|------|
| 行情缓冲池 | 大数组声明为 `static` 或全局 → 落 `.bss`，避免占用有限栈空间 |
| 内核栈 | 内核栈仅 4–16 KB，函数内 `char buf[4096]` 就有溢出风险 |
| 传数组 | 一律 `f(buf, len)`；绝不在函数内用 `sizeof` 求长度 |
| 整块拷贝 | `memcpy(dst, src, sizeof(src))` 比 for 循环快，且编译器常内联为向量指令 |
| 零初始化 | `int b[N] = {0}` 对大数组有清零开销；热路径上按需赋值而非每次 memset |
| 只读表 | `static const int opcode_map[] = {...}` → 落只读段，缺页即映射，不占可写页 |

## 常见误区

| 误区 | 事实 |
|------|------|
| "数组名不退化的第三个例外是 `char s[]` 的 `[]` 推导长度" | 因果错位。标准说的是**字符串字面量**在该上下文不退化（6.3.2.1p3），`[]` 能推导长度是**结果**不是原因。且 `char *p = "hello"` 中同一字面量会退化 |
| "`sizeof(&arr)` 能拿到数组大小" | 不能。`&arr` 是指针值，`sizeof(&arr) == 8`。想拿 40 用 `sizeof(*&arr)` 或 `sizeof(arr)` |
| "未初始化的全局数组在 `.bss`" | **ELF（Linux/嵌入式）成立**；Mach-O 上落在 `__DATA,__common`。二者共同点是不占文件体积、加载时清零 |
| "`printf("%p", arr)` 没问题" | 严格应写 `(void *)arr`。`%p` 期望 `void *`，可变参数不做隐式转换，传 `int *` 形式上是 UB |
| "函数内 `sizeof` 能求数组长度" | 退化后是 8；clang 会报 `-Wsizeof-array-argument` |
| "数组可以 `a = b` 整体赋值" | 非法，只能逐元素或 `memcpy` |

## 代码自测

**题目 1：** 以下函数想求数组长度，能成功吗？输出什么？

```c
void f(int arr[10]) {
    printf("%zu\n", sizeof(arr));
}
int main(void) { int a[10]; f(a); return 0; }
```

<details>
<summary>参考答案</summary>

输出 **8**（64 位平台），不是 40。

`int arr[10]` 作为形参会被编译器调整为 `int *arr`——**数组参数声明中的长度信息被完全丢弃**，`[10]` 只是给读代码的人看的。所以 `sizeof(arr)` 求的是指针大小。

正确做法是把长度作为独立参数传入：`void f(int *arr, size_t len)`。clang 开启 `-Wsizeof-array-argument`（`-Wall` 已包含）时会直接报警告，这是最容易在代码审查中漏掉的坑之一：函数签名看着像"接收 10 个元素的数组"，实际什么长度都能传进来。

</details>

**题目 2：** `arr` 和 `&arr` 打印出来的地址完全相同，能否说"它们是同一个东西"？如何证明？

<details>
<summary>参考答案</summary>

**数值相同，但不是同一个东西。** 证明方式是做指针算术：

```c
int arr[10];
printf("arr+1  = %p\n", (void *)(arr + 1));
printf("&arr+1 = %p\n", (void *)(&arr + 1));
```

- `arr + 1` 前进 **4** 字节——因为 `arr` 退化后类型是 `int *`，步长 = `sizeof(int)`
- `&arr + 1` 前进 **40** 字节——因为 `&arr` 类型是 `int (*)[10]`，步长 = `sizeof(int[10])`

地址值相同只是因为数组起始地址只有一个字节位置；**类型决定步长**，步长才是类型的可见证据。这个差异在多维数组传参（8.2.5）和 `int (*p)[N]` 声明中直接决定代码对错。

补充：`&arr + 1` 形成的是"尾后指针"（one-past-end），**形成合法但不可解引用**。

</details>

**题目 3：** 下面两段代码，`sizeof` 分别是多少？为什么不同？

```c
char s[] = "hello";   /* (1) */
char *p  = "hello";   /* (2) */
```

<details>
<summary>参考答案</summary>

- `(1) sizeof(s) == 6` —— `s` 是 `char[6]`（5 个字符 + 结尾 `'\0'`）
- `(2) sizeof(p) == 8` —— `p` 只是个指针

关键在于 **C11 6.3.2.1p3**：数组类型的左值在多数上下文会转换为指向首元素的指针，但有三种例外——`sizeof` 的操作数、一元 `&` 的操作数、**用于初始化数组的字符串字面量**。

`"hello"` 这个字面量本身的类型是 `char[6]`：
- 在 `(1)` 中它用于初始化数组，命中第三种例外，**不退化**，于是 `s` 被推导为 `char[6]`，长度信息保留
- 在 `(2)` 中它不用于初始化数组，**退化**为 `char *`，`p` 只拿到地址，长度信息丢失

所以要区分清楚：这个例外针对的是**字符串字面量**，不是"数组名"。把它记成"数组名的第三个不退化例外"是常见的归类错误——数组名在 `(1)` 里根本还没参与转换。

</details>
