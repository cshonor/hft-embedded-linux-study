# 8.1.1 数组名

## 本节讲什么

**数组名**在表达式中的精确含义。先纠正一个流传很广的说法：标准里退化规则的**主语不是「数组名」，而是「数组类型的表达式」**——C11 6.3.2.1p3 原文是 *an expression that has type "array of type"*。数组名只是这类表达式最常见的一种，字符串字面量、复合字面量同样是。**例外条款约束的是「上下文」，不是「数组名」这个实体**——这是本节要钉死的核心。

顺带：`&a` 和 `a` 数值常相同但类型不同，这是多维数组指针运算正确性的前提。

## 要点

```c
int a[10];
int *p = a;      /* a 退化为 &a[0] */
```

| 表达式 | 类型 | 含义 |
|--------|------|------|
| `a`（一般表达式） | `int *` | 首元素地址 `&a[0]` |
| `sizeof(a)` | `size_t` | 整个数组字节 `10*sizeof(int)` |
| `&a` | `int (*)[10]` | 指向整个数组的指针 |
| `&a[0]` | `int *` | 首元素地址 |

- **`&a`** 与 **`a`** 数值常相同（都是数组起始地址），**类型不同**
- `&a` 类型 `int (*)[10]`：`+1` 跳整个数组（10 个 int）
- `a` 退化后类型 `int *`：`+1` 跳一个 int

### 三种语义对比

```c
int a[10];
printf("%p %p %p\n", (void *)a, (void *)&a[0], (void *)&a);
/* 三者数值相同 */
printf("%zu %zu\n", sizeof(a), sizeof(&a));
/* 40（数组） vs 8（指针） */
printf("%p %p\n", (void *)(a + 1), (void *)(&a + 1));
/* a+1 跳 4 字节；&a+1 跳 40 字节（整个数组后） */
```

### 退化规则的主语是「表达式」，不是「数组名」

先钉住前提。C11 6.3.2.1p3 原文（逐字引用）：

> Except when it is the operand of the `sizeof` operator, the `_Alignof` operator, or the unary `&` operator, or is a string literal used to initialize an array, **an expression that has type ''array of type''** is converted to an expression with type ''pointer to type'' that points to the initial element of the array object and is not an lvalue.

主语是 **an expression that has type "array of type"**——「类型为『T 的数组』的表达式」。

**标准全文没有出现 "array name"（数组名）这个词。**「数组名退化」是中文教材的通俗简称，不是标准的说法——一旦拿它当准绳，就会推出"数组名有三个例外"这种讲不清的结论。

「数组类型表达式」至少有三种：

| 表达式 | 类型 | 是数组类型表达式 |
|--------|------|-----------------|
| 数组名 `a`（`int a[10]`） | `int[10]` | ✅ |
| 字符串字面量 `"hello"` | `char[6]` | ✅ |
| 复合字面量 `(int[]){1,2,3}` | `int[3]` | ✅ |
| 元素 `a[0]` | `int` | ❌（不是数组） |
| `&a` | `int (*)[10]` | ❌（是指针） |

### 例外约束的是「上下文」，不是「数组名」

标准列的例外有 **4 项**（C11；C99 只有 3 项，无 `_Alignof`）：

| # | 不转换的上下文 | 不转换时得到 |
|---|---------------|-------------|
| 1 | 作 `sizeof` 的操作数 | 整个数组字节数 `N*sizeof(T)` |
| 2 | 作 `_Alignof` 的操作数 | 数组对齐（★ 有坑，见下） |
| 3 | 作一元 `&` 的操作数 | `T (*)[N]` 数组指针 |
| 4 | **用于初始化数组的字符串字面量** | 字面量保留数组身份，长度信息不丢 |

关键：**这 4 条是对「任何数组类型表达式」统一的规则**，区别只在"哪些表达式能出现在那个位置"：

| 上下文 | 数组名 `a` | 字符串字面量 `"hi"` | 复合字面量 `(int[]){1,2}` |
|--------|-----------|--------------------|--------------------------|
| 普通表达式（`x = a`） | 退化 → `int *` | 退化 → `char *` | 退化 → `int *` |
| 作 `sizeof` 操作数 | 40 | 3 | 8 |
| 作一元 `&` 操作数 | `int (*)[10]` | `char (*)[3]` | `int (*)[3]` |
| **初始化数组的位置** | **N/A（数组名不可能出现在这）** | **不退化（唯一现场）** | 不退化 |

于是那几个流传的说法可以校准了：

| 说法 | 判定 | 说明 |
|------|------|------|
| "数组名有三个不退化例外" | ❌ 不严谨 | ① 例外属于**上下文**，不属于"数组名"这个实体；② C11 文本是 **4 项**；③ 第 4 个上下文里数组名**根本不可能出现** |
| "数组类型表达式有 4 个不转换的上下文" | ✅ | 标准的说法 |
| "对表达式实际生效的例外是 3 个" | ✅ | 因为 `_Alignof` 标准只吃类型名，不吃表达式（见下） |

#### 第 4 条例外的位置，数组名进不去

`char t[] = s;`（`s` 是数组名）编译直接拒绝：

```
error: invalid initializer
```

初始化器的位置只接受**初始化列表**或**字符串字面量**，数组名两者都不是。所以"数组名在第 4 条例外里"这个说法无从成立——那格是 **N/A**，不是"它的例外"。

#### ★ `_Alignof` 是什么（第 2 条例外的主角）

第 2 条例外最容易被忽略——因为很多人**根本不知道 `_Alignof` 在量什么**。它量的是**对齐要求**。

**对齐要求 = 这个类型的对象，地址必须是几的倍数。** 最小代码：

```c
int    x;   /* _Alignof(int)    = 4  → x 的地址必须是 4 的倍数 */
double d;   /* _Alignof(double) = 8  → d 的地址必须是 8 的倍数 */
char   c;   /* _Alignof(char)   = 1  → 放哪都行 */
```

标准原文（C11 §6.5.3.4p3，逐字引用）：

> The `_Alignof` operator yields the **alignment requirement** of its operand type. The operand **is not evaluated** and the result is an **integer constant**. When applied to an **array type**, the result is the **alignment requirement of the element type**.

三个要点拆开：

| 要点 | 含义 | 实际后果 |
|------|------|---------|
| 量的是**类型**的对齐 | 不是某个变量的地址 | `_Alignof(int)` 是编译期常量 |
| **操作数不被求值** | 只看类型，不看值 | 写 `_Alignof(int[1000000])` 不会真去分配内存 |
| 数组类型 → 取**元素**的对齐 | 与长度**无关** | `_Alignof(int[10]) == _Alignof(int[100]) == 4` |

最后一行是关键：`int[10]` 有 40 字节却只要求 4 字节对齐——**对齐由元素决定，不由长度决定**。
这正是 [8.1.5 §十](./8.1.5-数组和指针.md) 用来证明"数组是对象"的第一条证据。

**结果类型是 `size_t`**（§6.5.3.4p5 一句同时管 `sizeof` 和 `_Alignof`），所以打印用 `%zu`：

```c
printf("%zu %zu\n", _Alignof(int[10]), sizeof(int[10]));   /* 4  40 */
```

#### 顺带：三个名字别混

| 写法 | 来源 | 说明 |
|------|------|------|
| `_Alignof(T)` | **C11 关键字** | 标准写法，**只吃类型名**。C23 起**弃用**，但仍作为替代拼写保留可用 |
| `alignof(T)` | **C23 关键字** | C11 里它只是 `<stdalign.h>` 的便利宏（`#define alignof _Alignof`）；**C23 起该宏被移除**，`alignof` 自己成了关键字 |
| `__alignof__(x)` | **GCC/Clang 扩展** | 可以吃表达式——下面坑 2 就是它带来的 |

> **约束**（§6.5.3.4p1）：`_Alignof` 不得用于**函数类型**或**不完整类型**。
> （`sizeof` 的约束更严：连位域成员也不行。）

> **工程上写 `_Alignof(int)` 这种类型名形式**。表达式形式（`_Alignof a`）不是标准 C。

#### 两个坑

**坑 1：`_Alignof` 是 C11 新增的。** C99 没有，严格模式直接拒：

```bash
$ gcc -std=c99 -pedantic-errors -c t.c
error: ISO C99 does not support '_Alignof' [-Wpedantic]
$ gcc -std=c11 -c t.c && echo OK
OK
```

**坑 2：标准 C11 的 `_Alignof` 只接受「类型名」，不接受「表达式」。**

```bash
$ gcc -std=c11 -pedantic-errors -c t.c        # t.c 里写 _Alignof a
error: ISO C does not allow '_Alignof (expression)' [-Wpedantic]
$ clang -std=c99 -c t.c                        # clang 说得更直白
warning: '_Alignof' applied to an expression is a GNU extension
```

`_Alignof a` 是 **GNU 扩展**，标准写法是 `_Alignof(int[10])`（括号里是类型名）。

**这个坑的连带结论**：C11 6.3.2.1p3 虽把 `_Alignof` 并列进例外，但标准语法里 `_Alignof` 后面跟的是**类型名**——类型名不是表达式，不参与"数组到指针"的转换，这一条对「数组类型表达式」而言是**空转（no-op）**。

真正实际可观测的表达式例外只有 **3 个**：`sizeof`、一元 `&`、字面量初始化数组。这就是"三个例外"说法的合理来源——**但准确表述是"对表达式实际生效的例外有 3 个"，不是"数组名有 3 个例外"**。

#### 第 4 条例外为什么必须存在

假设标准不列它：`char s[] = "hello";` 里的 `"hello"` 类型是 `char[6]`，若按常规退化 → `char *`，这行就变成"用 `char *` 初始化 `char[]`"——**C 不允许用指针初始化数组**，初始化直接非法。

对照 `int a[] = {1,2,3};`：这里**不需要**任何例外，因为 `{1,2,3}` 是 **initializer-list（初始化列表）**，不是表达式，压根不参与数组→指针转换。

> **一句话**：字符串字面量是唯一「本身是数组类型表达式、又能直接当数组初始器」的东西，所以只有它需要这条例外。

#### 实测（WSL gcc 13.3 / clang 18.1.3）

```c
#include <stdio.h>
int a[10] = {0};
int main(void) {
    printf("sizeof a              = %zu\n", sizeof a);
    printf("_Alignof a            = %zu\n", _Alignof a);   /* GNU 表达式形式 */
    printf("sizeof &a             = %zu\n", sizeof &a);
    printf("sizeof \"hello\"       = %zu\n", sizeof "hello");
    printf("_Alignof \"hello\"     = %zu\n", _Alignof "hello");
    printf("sizeof (int[]){1,2,3} = %zu\n", sizeof (int[]){1,2,3});
    printf("a+1  step = %td\n", (char*)(a+1)   - (char*)a);
    printf("&a+1 step = %td\n", (char*)(&a+1)  - (char*)a);
    printf("&\"hello\"+1 step = %td\n", (char*)(&"hello"+1) - (char*)"hello");
    return 0;
}
```

实测输出：

```
sizeof a              = 40    数组名 · 例外1
_Alignof a            =  4    数组名 · 例外2（GNU 表达式形式）
sizeof &a             =  8    &a 是指针值，此处不适用例外
sizeof "hello"        =  6    字面量 · 例外1
_Alignof "hello"      =  1    字面量 · 例外2
sizeof (int[]){1,2,3} = 12    复合字面量 · 例外1
a+1    step =  4              退化 → int*，跳 sizeof(int)
&a+1   step = 40              int(*)[10]，跳整个数组
&"hello"+1 step = 6           char(*)[6]，字面量的 & 同样命中例外
```

编译期类型（`_Generic` 探针，`gcc -std=c11`）：

```
a        -> int *            ← 退化
&a       -> int (*)[10]      ← 不退化
"hello"  -> char *           ← 退化
&"hello" -> char (*)[6]      ← 不退化（关键证据）
```

最后一行最能说明问题：`&"hello"` 的类型是 `char (*)[6]`——**如果字符串字面量不是「数组类型表达式」，它不可能得到数组指针类型**。这直接证明退化规则的主语是「数组类型表达式」，而不是「数组名」。

详见 [8.1.11 字符数组的初始化](./8.1.11-字符数组的初始化.md)。

### `sizeof(&a)` 也是 8，不是 40

顺着"`&a` 是整个数组"推，很容易以为 `sizeof(&a)` 会得到 40——**不会**：

```c
int a[10];
printf("%zu\n", sizeof(a));     /* 40 — 不退化 */
printf("%zu\n", sizeof(&a));    /*  8 — &a 本身是个指针值 */
printf("%zu\n", sizeof(*&arr)); /* 40 — 解引用回到数组，才拿得到 40 */
```

实测：`sizeof(arr)=40`、`sizeof(&arr[0])=8`、`sizeof(&arr)=8`、`sizeof(*&arr)=40`。

> 想拿数组总字节，只能用 `sizeof(a)` 或 `sizeof(*&a)`；`sizeof(&a)` 永远是指针宽度。

## 底层映射

### 为什么数值相同类型不同

数组在内存里是一段连续空间，起始地址只有一个。`a`、`&a[0]`、`&a` 都指向这个起始字节——所以数值相同。差异在"指针算术的步长"：步长由类型决定（**ch06 6.13.1**）。

```
地址:    0x1000        0x1004        0x1008        ...
内容:    a[0]          a[1]          a[2]          ...
         ↑             ↑
         a, &a[0], &a  a+1
                                     &a+1 = 0x1028（跳 40 字节，整个数组后）
```

### 汇编视角

```c
int a[10];
int *q = a;          /* 退化：lea rax, [rsp] */
int x = a[3];        /* 退化后 [rsp+12] */
size_t n = sizeof(a);/* 编译期常量 40，无指令 */
```

```
lea     rax, [rsp]            ; q = &a[0]（数组首地址）
mov     DWORD PTR [rsp+8], eax; 存 q
mov     eax, DWORD PTR [rsp+12]; x = a[3]，编译期算偏移
mov     QWORD PTR [rsp+16], 40; n = 40，立即数
```

`sizeof(a)` 是编译期常量，根本不生成访存指令——这就是"不退化"的体现：编译器知道 `a` 是 10 元数组。

## HFT / DPDK

| 用法 | 要点 |
|------|------|
| 传首地址 | `f(a)` 退化为 `&a[0]` |
| 整数组大小 | `sizeof(a)` 仅在定义域有效 |
| 尾后指针 | `&a + 1` 或 `a + 10`，合法比较不可解引用 |
| `memcpy` | `memcpy(dst, a, sizeof(a))` 整数组拷贝 |

## 常见误区

| 误区 | 事实 |
|------|------|
| "数组名退化" | 通俗简称。标准主语是**数组类型表达式**（含数组名、字符串字面量、复合字面量）——标准全文无 "array name" 一词 |
| "数组名有三个不退化例外" | ① 例外属于**上下文**，不属于数组名这个实体；② C11 文本 **4 项**；③ 第 4 个上下文里数组名根本不可能出现（`char t[] = s;` 报 `invalid initializer`） |
| "`_Alignof a` 是标准写法" | 标准 C11 的 `_Alignof` 只吃**类型名**（`_Alignof(int[10])`）；`_Alignof a` 是 GNU 扩展，`-pedantic-errors` 会被拒 |
| "`&a` 和 `a` 是一回事" | 数值相同，类型不同，`+1` 步长差 10 倍 |
| "`sizeof(a)` 在函数内能拿数组大小" | 退化后是指针，拿到 8 |
| "`sizeof(&a)` 是 40（整个数组）" | 是 8——`&a` 本身是指针值；要 40 用 `sizeof(a)` 或 `sizeof(*&a)` |
| "数组名能赋值 `a = b`" | 非法，数组不可整体赋值 |
| "`&a + 1` 越界" | 合法形成（one-past-end），但不可解引用 |

## 实操

```bash
# 打印 a, &a[0], &a 的值与 a+1, &a+1 的步长差
cat > t.c << 'EOF'
#include <stdio.h>
int main(void) {
    int a[10];
    printf("a=%p &a[0]=%p &a=%p\n",(void*)a,(void*)&a[0],(void*)&a);
    printf("a+1=%p &a+1=%p\n",(void*)(a+1),(void*)(&a+1));
    printf("sizeof(a)=%zu sizeof(&a)=%zu\n",sizeof(a),sizeof(&a));
    return 0;
}
EOF
gcc t.c -o t && ./t
# 汇编看 sizeof(a) 是立即数
gcc -O2 -S t.c -o - | grep -i 'mov.*40'
```

**arm64 / LP64 实测输出**（clang 23.1.0，`int a[10]`）：

```
sizeof(arr)     = 40
sizeof(&arr[0]) =  8
sizeof(&arr)    =  8
sizeof(*&arr)   = 40

arr     = 0x16efafcf0
&arr    = 0x16efafcf0      ← 数值相同
&arr[0] = 0x16efafcf0
arr  + 1 → 0x16efafcf4  (前进  4 字节)   ← 步长 sizeof(int)
&arr + 1 → 0x16efafd18  (前进 40 字节)   ← 步长 sizeof(整个数组)
```

三个地址**数值完全相同**，只有做指针算术才看得出类型差异。这也是为什么小测验要问"类型一样吗"——光 `%p` 打印答不出来，必须打印 `a+1` 和 `&a+1` 的差值。

> **`%p` 的严谨写法**：`%p` 期望的是 `void *`，可变参数不做隐式转换，直接传 `int *` 在标准上是未定义行为（主流实现都能跑，clang/gcc 默认也不告警，但别养成习惯）。写成 `printf("%p\n", (void *)a);` 是零成本的正确写法。

## 代码自测

**题目 1：** 以下代码能编译吗？为什么？
```c
int arr[5] = {1, 2, 3, 4, 5};
arr++;
```

<details>
<summary>参考答案</summary>

不能编译。数组名不是可修改的左值——它是地址常量（指向数组首元素），不能被赋值或自增。数组名虽然可以隐式转换为指针使用，但它本身不是指针变量。如果想遍历数组，需要用单独的指针变量：int *p = arr; p++;。

</details>

**题目 2：** `arr` 和 `&arr` 打印出的地址完全相同，能否说"它们是同一个东西"？如何证明？

<details>
<summary>参考答案</summary>

**数值相同，但不是同一个东西。** 证明方式是做指针算术：

```c
int arr[10];
printf("arr+1  = %p\n", (void *)(arr + 1));
printf("&arr+1 = %p\n", (void *)(&arr + 1));
```

- `arr + 1` 前进 **4** 字节——`arr` 退化后类型是 `int *`，步长 = `sizeof(int)`
- `&arr + 1` 前进 **40** 字节——`&arr` 类型是 `int (*)[10]`，步长 = `sizeof(int[10])`

地址值相同只是因为数组起始地址只有一个字节位置；**类型决定步长**，步长才是类型可见的证据。这个差异在多维数组传参（**8.2.5**）和 `int (*p)[N]` 声明中直接决定代码对错。

补充：`&arr + 1` 形成的是"尾后指针"（one-past-end），**形成合法但不可解引用**。

</details>
