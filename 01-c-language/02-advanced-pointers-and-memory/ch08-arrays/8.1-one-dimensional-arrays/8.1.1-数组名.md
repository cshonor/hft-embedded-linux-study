# 8.1.1 数组名

## 本节讲什么

**数组名**在表达式中的精确含义：通常退化为首元素地址，但有三个例外。`&a` 和 `a` 数值常相同但类型不同——这是多维数组指针运算正确性的前提。

## 要点

```c
int a[10];
int *p = a;      /* a 退化为 &a[0] */
```

| 表达式 | 类型 | 含义 |
|--------|------|------|
| `a`（一般表达式） | `int *` | 首元素地址 `&a[0]` |
| `sizeof(a)` | `size_t` | 整个数组字节 `10*sizeof(int)` |
| `&a` | `int (*)[10]` | 指向整个数组的指针 |
| `&a[0]` | `int *` | 首元素地址 |

- **`&a`** 与 **`a`** 数值常相同（都是数组起始地址），**类型不同**
- `&a` 类型 `int (*)[10]`：`+1` 跳整个数组（10 个 int）
- `a` 退化后类型 `int *`：`+1` 跳一个 int

### 三种语义对比

```c
int a[10];
printf("%p %p %p\n", (void *)a, (void *)&a[0], (void *)&a);
/* 三者数值相同 */
printf("%zu %zu\n", sizeof(a), sizeof(&a));
/* 40（数组） vs 8（指针） */
printf("%p %p\n", (void *)(a + 1), (void *)(&a + 1));
/* a+1 跳 4 字节；&a+1 跳 40 字节（整个数组后） */
```

### 三个不退化的例外（C11 6.3.2.1p3）

标准原文列出三种"数组名保留数组身份"的上下文：

| # | 上下文 | 效果 | 说明 |
|---|--------|------|------|
| 1 | `sizeof(a)` 的操作数 | 得到整个数组字节数 | 编译器知道 `a` 是 10 元数组 |
| 2 | 一元 `&` 的操作数 | 得到 `int (*)[10]` | 数组指针，不是元素指针 |
| 3 | **初始化数组的字符串字面量** | `char s[] = "hi"` → `char[3]` | ⚠️ 见下方澄清 |

**关于第 3 条的关键澄清（易错）**：这一条的作用对象**不是数组名，是字符串字面量本身**。同一个字面量 `"hello"` 在不同上下文有两种命运：

```c
char s2[] = "hello";   /* 字面量不退化 → s2 推导为 char[6]，sizeof = 6 */
char *p2  = "hello";   /* 同一字面量在此退化为 char* → p2 只有 8 字节 */
```

实测（arm64 / LP64）：

```
char s2[] = "hello";  sizeof(s2) = 6  (推导 char[6])
char *p2  = "hello";  sizeof(p2) = 8  (退化为 char*)
```

所以不能说"数组名有三个不退化例外"——前两条针对数组名，第三条针对**初始化器里的字面量**。写成"数组名的性质"会让读者误以为是数组名在起作用。详见 [8.1.11 字符数组的初始化](./8.1.11-字符数组的初始化.md)。

### `sizeof(&a)` 也是 8，不是 40

顺着"`&a` 是整个数组"推，很容易以为 `sizeof(&a)` 会得到 40——**不会**：

```c
int a[10];
printf("%zu\n", sizeof(a));     /* 40 — 不退化 */
printf("%zu\n", sizeof(&a));    /*  8 — &a 本身是个指针值 */
printf("%zu\n", sizeof(*&arr)); /* 40 — 解引用回到数组，才拿得到 40 */
```

实测：`sizeof(arr)=40`、`sizeof(&arr[0])=8`、`sizeof(&arr)=8`、`sizeof(*&arr)=40`。

> 想拿数组总字节，只能用 `sizeof(a)` 或 `sizeof(*&a)`；`sizeof(&a)` 永远是指针宽度。

## 底层映射

### 为什么数值相同类型不同

数组在内存里是一段连续空间，起始地址只有一个。`a`、`&a[0]`、`&a` 都指向这个起始字节——所以数值相同。差异在"指针算术的步长"：步长由类型决定（**ch06 6.13.1**）。

```
地址:    0x1000        0x1004        0x1008        ...
内容:    a[0]          a[1]          a[2]          ...
         ↑             ↑
         a, &a[0], &a  a+1
                                     &a+1 = 0x1028（跳 40 字节，整个数组后）
```

### 汇编视角

```c
int a[10];
int *q = a;          /* 退化：lea rax, [rsp] */
int x = a[3];        /* 退化后 [rsp+12] */
size_t n = sizeof(a);/* 编译期常量 40，无指令 */
```

```
lea     rax, [rsp]            ; q = &a[0]（数组首地址）
mov     DWORD PTR [rsp+8], eax; 存 q
mov     eax, DWORD PTR [rsp+12]; x = a[3]，编译期算偏移
mov     QWORD PTR [rsp+16], 40; n = 40，立即数
```

`sizeof(a)` 是编译期常量，根本不生成访存指令——这就是"不退化"的体现：编译器知道 `a` 是 10 元数组。

## HFT / DPDK

| 用法 | 要点 |
|------|------|
| 传首地址 | `f(a)` 退化为 `&a[0]` |
| 整数组大小 | `sizeof(a)` 仅在定义域有效 |
| 尾后指针 | `&a + 1` 或 `a + 10`，合法比较不可解引用 |
| `memcpy` | `memcpy(dst, a, sizeof(a))` 整数组拷贝 |

## 常见误区

| 误区 | 事实 |
|------|------|
| "`&a` 和 `a` 是一回事" | 数值相同，类型不同，`+1` 步长差 10 倍 |
| "`sizeof(a)` 在函数内能拿数组大小" | 退化后是指针，拿到 8 |
| "`sizeof(&a)` 是 40（整个数组）" | 是 8——`&a` 本身是指针值；要 40 用 `sizeof(a)` 或 `sizeof(*&a)` |
| "字符串字面量初始化是'数组名不退化'的第三例外" | 作用对象是**字面量**，不是数组名；同一字面量在 `char *p = "x"` 里照样退化 |
| "数组名能赋值 `a = b`" | 非法，数组不可整体赋值 |
| "`&a + 1` 越界" | 合法形成（one-past-end），但不可解引用 |

## 实操

```bash
# 打印 a, &a[0], &a 的值与 a+1, &a+1 的步长差
cat > t.c << 'EOF'
#include <stdio.h>
int main(void) {
    int a[10];
    printf("a=%p &a[0]=%p &a=%p\n",(void*)a,(void*)&a[0],(void*)&a);
    printf("a+1=%p &a+1=%p\n",(void*)(a+1),(void*)(&a+1));
    printf("sizeof(a)=%zu sizeof(&a)=%zu\n",sizeof(a),sizeof(&a));
    return 0;
}
EOF
gcc t.c -o t && ./t
# 汇编看 sizeof(a) 是立即数
gcc -O2 -S t.c -o - | grep -i 'mov.*40'
```

**arm64 / LP64 实测输出**（clang 23.1.0，`int a[10]`）：

```
sizeof(arr)     = 40
sizeof(&arr[0]) =  8
sizeof(&arr)    =  8
sizeof(*&arr)   = 40

arr     = 0x16efafcf0
&arr    = 0x16efafcf0      ← 数值相同
&arr[0] = 0x16efafcf0
arr  + 1 → 0x16efafcf4  (前进  4 字节)   ← 步长 sizeof(int)
&arr + 1 → 0x16efafd18  (前进 40 字节)   ← 步长 sizeof(整个数组)
```

三个地址**数值完全相同**，只有做指针算术才看得出类型差异。这也是为什么小测验要问"类型一样吗"——光 `%p` 打印答不出来，必须打印 `a+1` 和 `&a+1` 的差值。

> **`%p` 的严谨写法**：`%p` 期望的是 `void *`，可变参数不做隐式转换，直接传 `int *` 在标准上是未定义行为（主流实现都能跑，clang/gcc 默认也不告警，但别养成习惯）。写成 `printf("%p\n", (void *)a);` 是零成本的正确写法。

## 代码自测

**题目 1：** 以下代码能编译吗？为什么？
```c
int arr[5] = {1, 2, 3, 4, 5};
arr++;
```

<details>
<summary>参考答案</summary>

不能编译。数组名不是可修改的左值——它是地址常量（指向数组首元素），不能被赋值或自增。数组名虽然可以隐式转换为指针使用，但它本身不是指针变量。如果想遍历数组，需要用单独的指针变量：int *p = arr; p++;。

</details>

**题目 2：** `arr` 和 `&arr` 打印出的地址完全相同，能否说"它们是同一个东西"？如何证明？

<details>
<summary>参考答案</summary>

**数值相同，但不是同一个东西。** 证明方式是做指针算术：

```c
int arr[10];
printf("arr+1  = %p\n", (void *)(arr + 1));
printf("&arr+1 = %p\n", (void *)(&arr + 1));
```

- `arr + 1` 前进 **4** 字节——`arr` 退化后类型是 `int *`，步长 = `sizeof(int)`
- `&arr + 1` 前进 **40** 字节——`&arr` 类型是 `int (*)[10]`，步长 = `sizeof(int[10])`

地址值相同只是因为数组起始地址只有一个字节位置；**类型决定步长**，步长才是类型可见的证据。这个差异在多维数组传参（**8.2.5**）和 `int (*p)[N]` 声明中直接决定代码对错。

补充：`&arr + 1` 形成的是"尾后指针"（one-past-end），**形成合法但不可解引用**。

</details>
