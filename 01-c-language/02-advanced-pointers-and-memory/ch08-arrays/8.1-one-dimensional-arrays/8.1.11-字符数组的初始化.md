# 8.1.11 字符数组的初始化

## 本节讲什么

**字符数组** vs **字符串指针数组**——报文缓冲与协议常量表的两种典型写法。这一节讲清"可写缓冲"和"只读常量表"的存储差异。

## 要点

### 可读写二维字符数组

```c
char pkt_buf[16][64];   /* 16×64 连续可写缓冲 */
strncpy(pkt_buf[0], data, 63);
pkt_buf[0][63] = '\0';
```

- 每行 64 字节连续可写，适合批量报文缓冲
- 二进制报文无 `\0` 时**勿用 strlen**——用显式长度
- 内存连续，cache 友好

### 字符串指针数组（只读表）

```c
const char *pkt_type_name[] = {
    "HEARTBEAT", "QUOTE", "ORDER", "CANCEL"
};
```

- 各字符串在 **`.rodata`**，修改 → 段错误
- 指针数组本身在栈/全局，存的是各字符串地址
- 适合错误码、opcode 名称表

### 字符数组 vs 字符指针（单串）

```c
char s1[] = "writable";    /* 栈数组，字面量拷贝进来，可改 */
char *s2 = "rodata";      /* 指向 .rodata，只读，改崩 */
const char *s3 = "rodata"; /* 同上，但 const 标记意图 */
```

| 形式 | 存储 | 可改 | `sizeof` | 用途 |
|------|------|------|---------|------|
| `char s[] = "abc"` | 栈/全局（拷贝进来） | 是 | **4**（含 `\0`） | 可改缓冲 |
| `char *s = "abc"` | 指向 `.rodata` | 否（改崩） | **8**（指针） | 只读（不推荐） |
| `const char *s = "abc"` | 指向 `.rodata` | 否（编译拦） | **8**（指针） | 只读（推荐） |

### 同一个字面量，两种命运（退化第 4 条例外的主场）

这是 [8.1.1](./8.1.1-数组名.md) 所说“第 4 条例外（字符串字面量用于初始化数组）”的具体现场——**同一个 `"hello"`，换个写法大小差 2 字节**：

```c
char s2[] = "hello";   /* 字面量不退化 → 推导为 char[6]，拷贝进栈 */
char *p2  = "hello";   /* 同一字面量退化为 char* → p2 只存地址 */
```

实测（arm64 / LP64）：

```
char s2[] = "hello";  sizeof(s2) = 6  (推导 char[6]，含 '\0')
char *p2  = "hello";  sizeof(p2) = 8  (退化为 char*)
```

```
s2（栈）:  'h' 'e' 'l' 'l' 'o' '\0'      ← 6 字节，可改
                    ↑
p2 ─────────────────┘ .rodata 里的同一串  ← 只读，改则 SIGSEGV
```

**关键点**：差异不来自字面量，而来自**左边的声明形式**。`[]` 触发"推导数组长度"，`*` 触发"退化为指针"。所以严格讲这不是"数组名的性质"，而是**初始化器上下文**决定的。

推论——算字符串长度时踩的坑：

```c
char s[] = "hello";
sizeof(s);      /* 6 —— 含 '\0' */
strlen(s);      /* 5 —— 不含 '\0' */
```

用 `sizeof` 当长度会多算 1；而一旦传进函数退化成 `char *`，`sizeof` 又变成 8。**两个方向都可能错**，所以字符串长度一律用 `strlen` 或显式 `n`。

## 底层映射

### `.rodata` 字符串字面量

```c
const char *names[] = {"HEARTBEAT", "QUOTE"};
```

```
.rodata 段:
  "HEARTBEAT\0"   ← names[0] 指向这里
  "QUOTE\0"       ← names[1] 指向这里

names 数组（栈/全局）:
  [0] → 0x401234  (指向 .rodata)
  [1] → 0x40123e
```

`names` 是指针数组，存的是地址；字符串本身在只读段。改 `names[0][0] = 'h'` 会尝试写 `.rodata` → `SIGSEGV`。

### 二维字符数组的连续存储

```c
char buf[3][16] = {"abc", "defgh", "x"};
```

```
地址:     0    1    2 ... 15    16   17 ...
内容:    'a' 'b' 'c' \0 ...  'd'  'e'  'f' ...
         ↑ buf[0]            ↑ buf[1]
```

每行 16 字节连续，`buf[i]` 跳 `16*sizeof(char)`。整体在栈或全局，可改。

## HFT / DPDK

| 场景 | 写法 |
|------|------|
| 报文缓冲池 | `char buf[16][2048]` 二维数组 |
| opcode 名称表 | `const char *names[] = {...}` |
| 协议字面量 | `const char *proto = "FIX.4.2"` |
| 错误码 | `const char *err_str[] = {"OK", "TIMEOUT", "FULL"}` |

### 工程纪律

- 二进制报文用显式长度，不靠 `\0`（**ch09**）
- 只读常量表用 `const char *[]`，编译期拦误改
- 可写缓冲用 `char buf[]`，不用 `char *` 指向字面量
- `char *s = "abc"` 已 deprecated，用 `const char *`

## 常见误区

| 误区 | 事实 |
|------|------|
| "`char *s = "abc"; s[0]='X';` 没事" | 改 `.rodata`，`SIGSEGV` |
| "二进制报文能用 strlen" | 无 `\0` 时不行，用显式长度 |
| "指针数组里的串能改" | 在 `.rodata`，改崩 |
| "`char s[]="abc"` 和 `char *s="abc"` 一样" | 前者可改拷贝，后者只读指向 |

## 实操

```bash
# 看字符串字面量在 .rodata
cat > t.c << 'EOF'
const char *s = "FIX.4.2";
int main(void){return 0;}
EOF
gcc t.c -o t && objdump -s -j .rodata ./t
# 故意改只读字面量
cat > t.c << 'EOF'
int main(void){char *s="abc";s[0]='X';return 0;}
EOF
gcc t.c -o t && ./t; echo $?    # Segmentation fault (139)
# 指针数组 vs 二维数组的地址布局
cat > t.c << 'EOF'
#include <stdio.h>
int main(void){
  char buf[3][16]={"a","bb","ccc"};
  const char *p[]={"a","bb","ccc"};
  printf("buf[0]=%p buf[1]=%p (contiguous)\n",(void*)buf[0],(void*)buf[1]);
  printf("p[0]=%p p[1]=%p (rodata, may be far)\n",(void*)p[0],(void*)p[1]);
  return 0;
}
EOF
gcc t.c -o t && ./t
```

## 代码自测

**题目 1：** 以下两种初始化有什么区别？
```c
char a[] = "hello";
char b[] = {'h', 'e', 'l', 'l', 'o'};
```

<details>
<summary>参考答案</summary>

a 有 6 个元素（h, e, l, l, o, \0）——字符串字面量自动添加终止符。b 有 5 个元素（h, e, l, l, o）——没有终止符。sizeof(a) = 6, sizeof(b) = 5。用 b 作为字符串传递给 strlen/printf 会越界读取。

</details>

**题目 2：** 下面两段代码，`sizeof` 分别是多少？为什么不同？

```c
char s[] = "hello";   /* (1) */
char *p  = "hello";   /* (2) */
```

<details>
<summary>参考答案</summary>

- `(1) sizeof(s) == 6` —— `s` 是 `char[6]`（5 个字符 + 结尾 `'\0'`）
- `(2) sizeof(p) == 8` —— `p` 只是个指针

关键在于 **C11 6.3.2.1p3**：数组类型的表达式在多数上下文会转换为指向首元素的指针，但标准文本列了 **4 项**例外——`sizeof` 操作数、`_Alignof` 操作数、一元 `&` 操作数、**用于初始化数组的字符串字面量**。（其中 `_Alignof` 只接受 type-name，对表达式实际生效的是 3 项，详见 [8.1.1](./8.1.1-数组名.md)。）

`"hello"` 这个字面量本身的类型是 `char[6]`：
- 在 `(1)` 中它用于初始化数组，命中第 **4** 条例外，**不退化**，于是 `s` 被推导为 `char[6]`，长度信息保留
- 在 `(2)` 中它不用于初始化数组，**退化**为 `char *`，`p` 只拿到地址，长度信息丢失

要区分清楚两件事：① 这条例外的主语是**字符串字面量**（一种数组类型表达式），不是“数组名”——数组名压根不可能出现在初始化器位置（`char t[] = s;` 报 `invalid initializer`）；② 不能把它记成“数组名的三个例外之一”，那会把“例外属于上下文”错记成“例外属于数组名”。

</details>
