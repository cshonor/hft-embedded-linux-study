# 8.1.8 初始化

## 本节讲什么

数组**定义时**初始化；全局/static 未列元素自动补 **0**，栈数组未初始化是**脏值**。这一节还讲 VLA（变长数组）的栈溢出风险——HFT 热路径禁用。

## 要点

```c
int a[5] = {1, 2, 3};     /* a[0..2]=1,2,3；a[3..4]=0 */
int b[] = {1, 2, 3};      /* 长度推导为 3 */
int c[100] = {0};         /* 全部清零——工程常用 */
int d[10];                /* 栈：脏值；全局：全 0 */
```

### 四象限：存储期 × 初始化 → 落在哪个段

| 定义 | 存储期 | 段 | 元素初值 |
|------|--------|-----|---------|
| `int a[10];`（函数内） | 自动 | **栈** | **脏值** |
| `int b[10] = {0};`（函数内） | 自动 | **栈** | 0（编译器清） |
| `int g[10];`（全局，无初始化） | 静态 | **`.bss`**（Mach-O 为 `__common`） | 0 |
| `int g[10] = {1};`（全局，有初始化） | 静态 | **`.data`** | 第 0 个 1，其余 0 |
| `static int s[100];`（无论函数内外） | 静态 | **`.bss`** | 0 |

一句话记忆：**有没有 `= {...}` 决定进不进 `.data`；函数内外决定栈还是静态区**。

```c
int a[10];          /* 局部 → 栈 → 未初始化 → 脏值 */
int b[10] = {0};    /* 局部 → 栈 → 显式清 0        */
int c[] = {1,2,3};  /* 编译器推导长度 = 3          */
static int s[100];  /* static → .bss → 自动清零    */
```

⚠️ **推导长度只在定义域有效**：`int c[]` 的 `[]` 由 initializer 个数决定，一旦传给函数就退化成 `int *`，长度信息彻底丢失（**8.1.6**）。

### 初始化规则

- initializer 列表元素少于数组大小 → 剩余补 **0**（C99 6.7.8）
- 列表多于数组大小 → 编译错误
- 不写 initializer：全局补 0，栈是脏值
- 指定初始化（C99）：`int a[10] = {[5] = 99};` 其余 0

### VLA（变长数组，C99）

```c
void f(int n) {
    char buf[n];   /* VLA，栈上，n 运行时定 */
}
```

- **HFT 热路径禁止大 VLA** → 栈溢出（n 运行时才知，无法预估）
- VLA 不可全局、不可初始化（`int v[n] = {0}` 非法）
- `sizeof(buf)` 是运行时值（非编译期常量）
- VLA 在 C11 降为可选特性（`__STDC_NO_VLA__` 可检测）

## 底层映射

### `.bss` 的自动清零

```c
int g[1000];   /* 全局，未初始化 */
```

```
$ objdump -h ./prog
.bss  00000fa0 ...   # 0xfa0 = 4000 字节（1000 × sizeof(int)）
```

`.bss` 段在 ELF 里只记大小不记内容——程序启动时内核把整段 mmap 清零（`/dev/zero` 映射），所以全局未初始化变量是 0，且**不占可执行文件空间**。这是为什么大缓冲放全局比放栈省可执行文件体积。

### Mach-O 的第三个段：`__common`

教材常说"未初始化全局 → `.bss`"，但在 macOS / Mach-O 上**实测会看到 `__common`**：

```c
int g_init[10]    = {1, 2, 3};   /* 显式初始化 */
int g_uninit[10];                /* 全局未初始化 */
static int s_uninit[10];         /* 文件作用域 static */
void f(void) { static int s[100]; }  /* 函数内 static */
```

```
$ llvm-nm -m ./prog
0000000100008030 (__DATA,__data)   external _g_init
0000000100008210 (__DATA,__common) external _g_uninit
00000001000081e8 (__DATA,__bss)    non-external _s_uninit
0000000100008058 (__DATA,__bss)    non-external _f.s
```

| 符号 | Mach-O 段 | ELF 对应 | 判定依据 |
|------|-----------|----------|---------|
| `g_init`（全局 + 有初始化） | `__DATA,__data` | `.data` | 初值要存进文件 |
| `g_uninit`（全局 + 无初始化） | `__DATA,__common` | `.bss` | **外部链接**、无初值 |
| `s_uninit`（文件作用域 static） | `__DATA,__bss` | `.bss` | 内部链接 |
| `f.s`（函数内 static） | `__DATA,__bss` | `.bss` | 内部链接 |

**为什么会有 `__common`**：历史遗留的"tentative definition"（暂定定义）机制——多个翻译单元可以都写 `int g_uninit[10];` 而不冲突，链接器最后合并成一块。这需要保留符号的"大小 + 对齐"信息，于是单独放 `__common`。加了 `static`（内部链接）就不需要合并，直接进 `__bss`。

> 两者共同点：都不占文件体积、加载时清零。写嵌入式 / ELF 语境时统称 `.bss` 没问题，但在 Mac 上看 `nm` / map 文件会撞见 `__common`——做链接脚本或分析体积时别误判。

**去掉 tentative definition 的办法**：显式写一次定义，其余文件用 `extern` 声明；或加 `-fno-common`（gcc/clang），此时重复的暂定定义会报链接错误，同时 `g_uninit` 会落进 `__bss`。

### 栈数组的脏值

```c
void f(void) {
    int a[10];   /* 栈，未初始化 */
    /* a 的内容是上一个用这段栈的函数留下的残值 */
}
```

栈帧复用：`f` 退出后，下一个函数的局部变量占用同一块栈，残留 `a` 的旧值。`-ftrivial-auto-var-init=zero` 强制栈变量清零（**ch06 6.5**）。

## HFT / DPDK

| 场景 | 选择 |
|------|------|
| 报文缓冲定长 | `char buf[2048] = {0}` 栈上 |
| 大缓冲 | `malloc` 或静态池（避免栈溢出） |
| 配置表 | 全局 `static const`，`.rodata`/`.bss` |
| 运行时大小缓冲 | 堆或 mempool，不用 VLA |

### 工程纪律

- 栈数组一律 `= {0}` 或显式赋值
- 大缓冲（> 几 KB）放堆或静态，不占栈
- VLA 仅在大小有上界且小、非热路径时用
- 全局大缓冲利用 `.bss` 自动清零，省代码体积

## 常见误区

| 误区 | 事实 |
|------|------|
| "栈数组自动清零" | 不，是脏值；全局才自动清零 |
| "VLA 和定长一样安全" | VLA 大小运行时定，栈溢出风险 |
| "全局大数组占可执行文件空间" | `.bss` 不占，只记大小 |
| "`int a[10] = {0}` 只清 a[0]" | 整个清零（剩余补 0 规则） |

## 实操

```bash
# 看栈数组脏值
cat > t.c << 'EOF'
#include <stdio.h>
void dirty(void){int a[4];printf("%d %d %d %d\n",a[0],a[1],a[2],a[3]);}
int main(void){int x[4]={0xdead,0xbeef,0xcafe,0xbabe};dirty();return 0;}
EOF
gcc -O0 t.c -o t && ./t   # 可能打印 0xdead 等残值
# 强制栈清零
gcc -ftrivial-auto-var-init=zero -O0 t.c -o t && ./t
# 看 .bss 大小
gcc -c t.c -o t.o && size t.o
```

## 代码自测

**题目 1：** 以下代码中 arr 的各元素值是什么？
```c
int arr[5] = {1, 2};
```

<details>
<summary>参考答案</summary>

arr = {1, 2, 0, 0, 0}。部分初始化时，未指定的元素自动初始化为 0。这是 C 的规则：只要有初始化列表，剩余元素就为零。如果完全不初始化（int arr[5];），在函数内是局部数组，元素值是不确定的。

</details>
