# 8.1.10 数组指针的步长（`a` 与 `&a`）

## 本节讲什么

**ch06 6.13.1** 讲了"**`p + 1` 跳多少由 `T` 决定**"，但只举了 `char*` / `int*` / `struct*` 这类普通类型。本节补上最后一个、也最能暴露误区的案例：**当 `T` 本身是一个数组类型时**——也就是 `int (*)[5]`（数组指针）——步长会变成**整个数组的字节数**。

同一个地址，两种类型，`+1` 差距 5 倍。这是"数组 ≠ 指针"最锋利的证据，也是二维数组行遍历、burst 数组传参能不能写对的直接前提。

配套小节：[8.1.1 数组名与退化](./8.1.1-数组名.md)（这四个表达式从哪来）、[8.1.11 数组类型表达式清单](./8.1.11-数组类型表达式清单.md)（`a[0]` 不是指针、元素与地址的分界）。原 8.1.12《`void *` 与地址值》已并入本节（见「转成 `void *`：类型差异消失」）。

## 要点

```c
int a[5] = {10, 20, 30, 40, 50};
int *p1      = a;    /* 退化 → &a[0]，类型 int *        ，+1 跳  4 字节 */
int (*p2)[5] = &a;   /* 不退化，类型 int (*)[5]         ，+1 跳 20 字节 */
```

| 表达式 | 值（地址） | 类型 | `+1` 步长 |
|--------|-----------|------|-----------|
| `a`（一般表达式）、`&a[0]` | `0x100` | `int *` | `sizeof(int)` = **4** |
| `&a` | `0x100` | `int (*)[5]` | `sizeof(int[5])` = **20** |

> 完整四表达式对照（含 `a[0]` 的类型与**左值性**、`sizeof` 的三个答案）见
> [8.1.11 数组类型表达式清单](./8.1.11-数组类型表达式清单.md)。本节只保留**步长**这一列——它是本节独有的权威点。

> **一句话核心**：数值相同（同一个起始字节），类型不同（决定步长）。**只看 `%p` 永远看不出差别，只有做指针算术才看得出。**

### 三层递进：怎么"看见"类型差异

| 层 | 观测手段 | 结论 |
|----|---------|------|
| ① 数值 | `printf("%p", (void *)a)` vs `(void *)&a` | **完全相同**——看不出区别 |
| ② 类型 | `_Generic` 探针 | `int *` vs `int (*)[5]`——编译期可见 |
| ③ 步长 | 打印 `(char *)(x + 1) - (char *)x` | 4 vs 20——**运行期唯一可观测证据** |

```c
#define TY(x) _Generic((x), int *: "int *", int (*)[5]: "int (*)[5]", default: "?")
printf("a  = %p type=%s\n", (void *)a,  TY(a));    /* int *       */
printf("&a = %p type=%s\n", (void *)&a, TY(&a));   /* int (*)[5]  */
```

### 退化：只在"一般表达式"里成立

`a` 变成 `&a[0]` 不是恒等式，是**数组类型表达式在一般上下文的转换**（C11 6.3.2.1p3）。四个上下文**不转换**：

```c
int a[5];
size_t n  = sizeof a;        /* 20，不转换 ← 唯一能拿到数组字节数的地方 */
int (*p)[5] = &a;            /* 不转换，得到数组指针 */
int *q     = a;              /* 转换 → &a[0] */
f(a);                        /* 传参转换 */
```

详见 [8.1.1 数组名](./8.1.1-数组名.md)（含标准逐字引用、4 条例外的完整辨析、`_Alignof` 那条为什么是空转）。

### 内存布局（示意，`sizeof(int) = 4`）

```
地址:   0x100    0x104    0x108    0x10C    0x110    │0x114
        a[0]=10  a[1]=20  a[2]=30  a[3]=40  a[4]=50  │（尾后）
        ↑                                            ↑
        a, &a[0], &a                                 &a + 1
        （三个值都是 0x100）                          （+20 字节，跳过整个数组）

   a + 1 → 0x104        （+4 字节，走到 a[1]）
```

`&a + 1` 指向的是**整个数组对象之后**，不是 `a[4]` 之后——它和"最后一个元素之后"在数值上重合，但类型语义完全不同。

## 标准依据

| 条款 | 内容 | 对本节的意义 |
|------|------|-------------|
| C11 **6.3.2.1p3** | 数组类型表达式 → 指向首元素的指针，且**不是左值**；`sizeof` / `_Alignof` / 一元 `&` / 字面量初始化数组除外 | `a` 为什么变成 `&a[0]`、`&a` 为什么不退化 |
| C11 **6.5.6p7** | 指向**非数组元素对象**的指针做算术时，视作"长度为 1 的数组的首元素指针" | `&a + 1` **合法**的依据（`&a` 指向的 `int[5]` 是一个对象） |
| C11 **6.5.6p8** | 结果若越过尾后一位 → **UB**；指向尾后一位的指针**不得解引用** | `&a + 1` 可形成、可比较，**不可 `*`（解引用）** |
| C11 **6.5.9p6** | 两指针相等 ⟺ ……"including a pointer to an object and a **subobject at its beginning**" | **标准明确保证** `&a` 与 `&a[0]` 相等（首元素是数组的起始子对象） |
| C11 **6.3.2.3p1** | `void *` 与任意**对象类型**指针可互转，转回后与原指针相等 | 双向隐式转换的依据；**不含函数指针** |
| C11 **6.5.16.1p1** | 赋值时一边是对象指针、一边是 `void *` → 合法 | 为什么转 `void *` 不需要写 cast |
| C11 **6.5.6p2** | 加法要求操作数是**指向完整对象类型的指针** | `vp + 1`（`void *` 算术）**不合法**的依据 |
| C11 **6.5.9p2** | `==` 允许一边是对象指针、一边是 `void *` | `v1 == v2` 合法；`a == &a` 为什么不合法（两个都不是 `void *`） |
| C11 **6.3.2.3p7** | 转回不同类型时**对齐不足** → UB | 转回原类型安全；转别的类型看对齐 |
| C11 §7.21.6.1 | `%p` 的实参应为 **pointer to void** | `printf("%p", a)` 形式上是 UB |

> ⚠️ 常见误传："C 标准只保证地址数值相等"。措辞不准——标准不是"只保证数值"，而是**直接保证相等**（6.5.9p6）。真正的坑在下面那条。

### ★ `a == &a` 不能直连：约束违规

C11 **6.5.9p2** 要求 `==` 的两个操作数满足其一：都是算术类型 / 指向**兼容类型** / 一个是指针另一个是 `void *` / 一个是空指针常量。`int *` 与 `int (*)[5]` **不兼容**，也不涉及 `void *`——所以直接比较是**约束违规，编译器必须诊断**。

实测（clang 23.1.0）：

```c
printf("%d\n", a == &a);   /* 源码原文 */
```

```
$ clang -std=c11 -pedantic-errors -c t.c
error: comparison of distinct pointer types ('int *' and 'int (*)[5]')
       [-Werror,-Wcompare-distinct-pointer-types]

$ clang -std=c11 -c t.c                      # 默认只降级成 warning
warning: comparison of distinct pointer types ('int *' and 'int (*)[5]')
```

正确写法——先转成同一类型：

```c
(void *)a == (void *)&a           /* ✅ 实测得 1 */
(uintptr_t)a == (uintptr_t)&a     /* ✅ 需要 <stdint.h> */
```

> 顺带：`printf("%p", a)` 严格应写 `(void *)a`——可变参数不做隐式转换，传 `int *` 形式上是 UB。

## 数组指针怎么用

### 解引用回到数组

```c
int a[5] = {10, 20, 30, 40, 50};
int (*p2)[5] = &a;

(*p2)[1]        /* 20 —— 圆括号必须写，[] 优先级高于 * */
*p2[1]          /* ❌ 等价于 *(p2[1])，越界一个数组 */
sizeof(*p2)     /* 20 —— 解引用回到数组对象，拿得到总字节 */
sizeof(*&a)     /* 20 —— 同理；sizeof(&a) 只有 8 */
```

### 二维数组的行指针（真正上岗的地方）

`int (*)[N]` 在一维数组里显得多余，因为 `int *` 就够用；它的主场是**二维数组按行走**：

```c
int m[3][5];
int (*row)[5] = m;      /* m 退化一层 → &m[0]，类型 int (*)[5]，不是 int ** */
row + 1;                /* 跳 20 字节 = 一整行 */
(*row)[2];              /* 第 0 行第 2 列 */
```

实测（clang 23.1.0 / arm64，`int m[3][5]`）：

```
m        @ 0x16ce0f5ac  type=int (*)[5]        ← 二维数组退化一层
m[0]     @ 0x16ce0f5ac  type=int *             ← 行内退化到元素
&m[0]    @ 0x16ce0f5ac  type=int (*)[5]        ← 行指针
&m       @ 0x16ce0f5ac  type=int (*)[3][5]     ← 整个二维数组

m[0] + 1  step =  4 bytes   （行内走一个 int）
m    + 1  step = 20 bytes   （跳一行 5 个 int）
&m   + 1  step = 60 bytes   （跳过整个 3×5）
sizeof m = 60，rows = sizeof m / sizeof m[0] = 3
```

四个地址数值依旧全部相同，靠步长才分得出谁是谁。

### 传参时保留长度信息

```c
void f_bad (int a[5]);      /* 等价于 int *a，长度丢失，sizeof = 8 */
void f_good(int (*a)[5]);   /* 保留"5 个 int"这个类型信息，sizeof(*a) = 20 */
```

唯一能穿过函数调用把数组大小带进去的写法就是数组指针（[8.1.6 声明数组参数](./8.1.6-声明数组参数.md)）。

## 转成 `void *`：类型差异消失（原 8.1.12 并入）

`a`（`int *`）和 `&a`（`int (*)[5]`）一旦都转成 `void *`，**类型差异彻底消失，只剩地址数字**：

```
编译期                             运行期（值）
a    → int *        ──┐
                      ├─ 隐式转 void* ─→  0x16da635e0（纯数字，无类型）
&a   → int (*)[5]   ──┘                   0x16da635e0
```

`void *` 是 C 里唯一的"通用对象指针"，也是唯一能抹平类型差异的指针类型。类型信息从来不在指针的**值**里，只在**类型**里——这就是为什么光 `%p` 打印永远看不出 `a` 和 `&a` 的区别（8.1.1 反复强调：必须打印 `a+1` 与 `&a+1` 的差值）。

### 转换规则：对象指针 ↔ `void *` 双向隐式

C11 **6.3.2.3p1**（逐字引用）：

> A pointer to `void` may be converted to or from a pointer to any object type. A pointer to any object type may be converted to a pointer to `void` and back again; the result shall compare equal to the original pointer.

配合 **6.5.16.1p1**（简单赋值约束）：两个操作数都是指针，且一个是指向对象类型的指针、另一个是 `void *` → 允许隐式转换，不需要写 cast。所以 `void *v = p1;` 和 `int *q = v;` 都不必强转。

> ⚠️ **函数指针不在保证范围内。** `void *p = f;`（`f` 是函数）标准不保证——6.3.2.3p1 说的是 *object type*。实测（clang 23.1.0）：
> ```
> $ clang -std=c11 -pedantic-errors -c t.c
> error: initializing 'void *' with an expression of type 'int (void)'
>        converts between void pointer and function pointer [-Werror,-Wpedantic]
> ```
> POSIX 的 `dlsym` 返回 `void *` 再转函数指针属于**平台扩展**（C11 J.5.7 列为常见扩展），移植代码别依赖。

### `void *` 能做什么、不能做什么

| 操作 | `int *` / `int (*)[5]` | `void *` |
|------|------------------------|----------|
| 存地址值 | ✅ | ✅（只存值，不存类型） |
| `==` / `!=` 比较 | ✅ | ✅（互相比、与对象指针比都行，§6.5.9p2） |
| `+ n` / `- n` 算术 | ✅（步长 = `sizeof(T)`） | ❌ **禁止** |
| 解引用 `*` / 下标 `[]` | ✅ | ❌（`void` 不是完整类型，无法形成值） |
| `printf("%p")` | 需强转 `(void *)` | ✅ 本来就是 |

> **一句话核心**：`void *` **只存地址值、不携带类型信息**。指针运算靠类型提供步长，类型一丢，步长就没了——所以算术、解引用全部失效。

### ★ `void *` 不能做指针算术（GNU 扩展按 1 字节）

C11 **6.5.6p2**（加法约束）：两个操作数要么都是算术类型，要么一个是指向**完整对象类型**的指针、另一个是整数。`void` 是**不完整类型**，`sizeof(void)` 都不存在，步长无从计算。实测（clang 23.1.0）：

```
$ clang -std=c11 -pedantic-errors -c t.c
error: arithmetic on a pointer to void is a GNU extension [-Werror,-Wgnu-pointer-arith]
error: invalid application of 'sizeof' to a void type [-Werror,-Wpointer-arith]

$ clang -std=c11 t.c && ./t          # GNU 扩展放行：悄悄把 void 当 1 字节
vp + 1 step = 1 bytes
sizeof(void) = 1
```

> 这条扩展是有害的：同一份代码在 `-pedantic` 下编译不过，在默认模式下**静默按 `char *` 语义跑**。工程上要么显式写成 `(char *)vp + 1`，要么开 `-Wgnu-pointer-arith -Werror`。

### 转回去：对齐决定合法性，不是"原不匹配就错"

C11 **6.3.2.3p7**：指向对象类型的指针转成指向**不同类型**的指针时，若结果**未针对该类型正确对齐** → **UB**。转回**原类型**必然对齐满足 → 定义良好。

```c
void *v2 = &a;                     /* int (*)[5] 转来的 */
int (*q2)[5] = (int (*)[5])v2;     /* 转回原类型：✅ 定义良好，步长恢复 20 */
int  *q      = (int *)v2;          /* 转成 int*：✅ 也合法（4 对齐满足） */
```

实测（clang 23.1.0，`int a[5]` 起始于 `0x16da635e0`）：

```
p1 = 0x16da635e0   p2 = 0x16da635e0
v1 = 0x16da635e0   v2 = 0x16da635e0
v1 == v2 ? 1
sizeof(void *) = 8

*(int *)v2       = 10          ← 该地址上确实有 int 对象（a[0]），解引用合法
(int *)v2 + 1        step =  4 bytes
(*(int (*)[5])v2)[1] = 20      ← 转回原类型，正常访问
(int (*)[5])v2 + 1   step = 20 bytes
```

> ⚠️ **校准一个常见说法**："`v2` 强行转回 `int *` 属于类型误用、逻辑错误"——**转换本身和解引用 `a[0]` 都是合法的**（那个地址上真的有个 `int` 对象，有效类型就是 `int`，对齐也满足）。真正错的是**步长语义**：`(int *)v2 + 1` 只走 4 字节，而你的本意（`int (*)[5]`）是走 20 字节。用它遍历就会走错位置。
>
> 所以准确说法是：**地址对、访问合法，但类型解释变了 → 遍历语义错**。只有当目标类型对齐要求更高（比如把 `char *` 转来的地址转成 `double *`）时才是真正的 UB。

### 为什么 `%p` 打出来一模一样

`printf` 是可变参数函数，**可变参数不做隐式转换**（只做默认实参提升）。C11 §7.21.6.1 规定 `%p` 的实参应为 **pointer to void**。所以：

```c
printf("%p\n", a);          /* 传的是 int *，形式上 UB */
printf("%p\n", (void *)a);  /* ✅ 零成本的正确写法 */
```

实测（`-Wformat-pedantic` 会抓）：

```
warning: format specifies type 'void *' but the argument has type 'int *' [-Wformat-pedantic]
```

而且因为两个 `void *` 值本来就相等，`%p` 输出自然一模一样——**这不是"它们相同"的证据，只是"它们起始于同一字节"的证据**。

### 汇编：转换是零成本的

`void *` 与 `int *`、`int (*)[5]` 在机器层面**都是同一个 64 位寄存器值**，转换不产生任何指令：

```c
int *to_int(void *v)       { return v; }          /* clang -O2: 直接 ret，无指令 */
int (*to_arr(void *v))[5]  { return v; }
```

arm64 `-O2` 下两个函数都被折叠成一条 `ret`。**类型信息只存在于编译期**，不编码进指针值——代价就是 `void *` 丢了类型，运行时再也拿不回步长。

| | 指针的值（运行期） | 类型（编译期） |
|---|---|---|
| 内容 | 一个地址数字（8 字节） | 被指对象的布局 |
| 决定 | 指向哪里 | `+1` 走几字节、`*` 得到什么 |
| `void *` | ✅ 保留 | ❌ 丢弃 |

`void *` 就是只剩"地址数值"的极端形态——本节的步长结论（由类型决定，不由地址数值决定）在它身上体现得最彻底。

## 底层映射

### 汇编：步长是编译期立即数，没有乘法

```c
int step_intptr  (int *p)       { return (char *)(p + 1) - (char *)p; }
int step_arrayptr(int (*p)[5])  { return (char *)(p + 1) - (char *)p; }
```

arm64 `clang -O2` 输出：

```
_step_intptr:
	mov	w0, #4      ; =0x4
	ret
_step_arrayptr:
	mov	w0, #20     ; =0x14
	ret
```

两个函数都被常量折叠成一条 `mov`。**步长在编译期就算完了**，运行期不产生 `imul`——硬件的 SIB / 比例变址只认 1/2/4/8 倍率，`int[5]` 这种 20 字节步长由编译器直接编进立即数或 `add`。所以数组指针不会带来额外开销，但也别指望它比手写偏移更快。

## HFT / DPDK

| 场景 | 用法 | 要点 |
|------|------|------|
| burst 数组 | `struct rte_mbuf *pkts[32]` | 这是**指针数组**，退化后是 `struct rte_mbuf **`，不是数组指针 |
| 定长二维表 | `int (*row)[N]` 按行走 | `row + 1` 跳一整行，比 `row[i][j]` 手写索引更不容易错 |
| 传参保留长度 | `void f(int (*a)[N])` | 唯一能在被调用方 `sizeof(*a)` 拿到 N 的写法 |
| 报文偏移 | 用 `char *` / `uint8_t *` 做字节级 | 别用 `struct pkt *` 加常量——步长会变成 sizeof(struct) |
| 对象池 / ring | `rte_ring` 存 `void *`，取出后 cast 回真实类型 | **cast 回具体类型后再做算术**，`void *` 阶段只能搬运 |
| `memcpy` / `memset` | 签名就是 `void *` | 内部按字节操作，与类型无关 |
| 通用回调 | `void *arg` 传上下文 | 回调内第一行就 cast 回真实结构体类型 |
| 报文解析 | `(struct eth_hdr *)pkt` | 不用写 `(struct eth_hdr *)(void *)pkt` 两步转换；对齐要自己保证 |
| 求长度 | `sizeof a / sizeof a[0]` | **不要写 `(&a)[1] - a`**：那是解引用尾后指针，UB（见误区表） |

## 常见误区

| 误区 | 事实 |
|------|------|
| "`a` 和 `&a` 是一回事" | 数值相同，类型不同，`+1` 步长差 N 倍 |
| "`a` 就是 `&a[0]`（恒等）" | 只在一般表达式成立；`sizeof` / 一元 `&` 等 4 个上下文不转换 |
| "`a == &a` 能编译过，值相等" | 约束违规（§6.5.9p2），`-pedantic-errors` 直接 error；要写 `(void *)a == (void *)&a` |
| "`&a + 1` 越界了" | 形成**合法**（尾后一位），比较合法，**解引用 UB** |
| "标准只保证地址数值相等" | 6.5.9p6 明确保证相等（对象指针 vs 其起始子对象指针） |
| "`sizeof(&a)` 能拿数组大小" | 是 8；要 20 用 `sizeof a` 或 `sizeof *&a` |
| "`(&a)[1] - a` 是求长度技巧" | 标准上是 UB——`(&a)[1]` ≡ `*(&a + 1)`，解引用尾后。用 `sizeof` 除法 |
| "二维数组退化成 `int **`" | 只退化**一层**：`int (*)[5]`。层层递进见 `ch08 8.2.2` |
| "`vp + 1` 能编译过，说明合法" | GNU 扩展（按 1 字节）；`-pedantic-errors` 直接 `error: arithmetic on a pointer to void` |
| "`sizeof(void)` 是 1" | 标准中 `void` 不完整，`sizeof(void)` 非法；1 是 GNU 扩展 |
| "转回任意类型都 UB" | 只有**对齐不足**才 UB（§6.3.2.3p7）；转回原类型必然安全 |
| "`v2` 转 `int *` 后解引用一定错" | 该地址上真有 `int` 对象 → 访问 `a[0]` 合法（实测得 10）；错的是**步长语义**（4 vs 20） |
| "函数指针也能转 `void *`" | 标准只保证**对象类型**；`void *p = f;` 在 `-pedantic` 下报错，`dlsym` 那套是 POSIX 扩展 |
| "`%p` 传 `int *` 没问题" | 可变参数不转换，`-Wformat-pedantic` 会报 `format specifies type 'void *' but the argument has type 'int *'` |
| "`void *` 记得原类型，转回时自动恢复" | 不记得。指针值里只有地址，恢复全靠你写对类型 |
| "用 `void *` 做字节偏移很自然" | 要步长 1 请用 `char *`；`void *` 做算术是非标准 |

## 实操

```bash
# 1. 类型探针 + 步长差（本节主实验）
cat > t.c << 'EOF'
#include <stdio.h>
#define TY(x) _Generic((x), int *: "int *", int (*)[5]: "int (*)[5]", default: "?")
int main(void) {
    int a[5] = {10,20,30,40,50};
    int *p1 = a; int (*p2)[5] = &a;
    printf("a   =%p type=%s\n", (void *)a,  TY(a));
    printf("&a  =%p type=%s\n", (void *)&a, TY(&a));
    printf("sizeof a=%zu  sizeof &a=%zu  sizeof *&a=%zu\n", sizeof a, sizeof &a, sizeof *&a);
    printf("p1+1 step=%td\n", (char *)(p1+1) - (char *)p1);
    printf("p2+1 step=%td\n", (char *)(p2+1) - (char *)p2);
    printf("(void*)a==(void*)&a ? %d\n", (void *)a == (void *)&a);
    printf("(*p2)[1] = %d\n", (*p2)[1]);
    return 0;
}
EOF
clang -std=c11 -Wall t.c -o t && ./t

# 2. 直连比较会被拒（约束违规）
printf '#include <stdio.h>\nint main(void){int a[5];printf("%%d",a==&a);return 0;}\n' > c.c
clang -std=c11 -pedantic-errors c.c -o /dev/null    # error
clang -std=c11 c.c -o /dev/null                     # 只 warning

# 3. 汇编看步长是立即数
clang -O2 -S t.c -o - | grep -E 'mov.*#(4|20)'

# 4. void* 算术：严格模式报错 vs GNU 扩展放行
printf '#include <stdio.h>\nint main(void){int a[5];void *vp=&a;\
printf("%%td %%zu",(char*)(vp+1)-(char*)vp,sizeof(void));return 0;}\n' > g.c
clang -std=c11 -pedantic-errors g.c -o /dev/null   # 2 errors
clang -std=c11 g.c -o g && ./g                     # 1 1
```

**实测输出**（arm64 / LP64，clang 23.1.0）：

```
a        = 0x16b60f620   type=int *
&a[0]    = 0x16b60f620   type=int *
&a       = 0x16b60f620   type=int (*)[5]      ← 三者数值完全相同
sizeof(a)=20  sizeof(&a)=8  sizeof(*&a)=20
p1+1 - p1 = 4 bytes                            ← sizeof(int)
p2+1 - p2 = 20 bytes                           ← sizeof(int[5])，5 倍
(void*)a == (void*)&a ? 1
(*p2)[1] = 20
```

## 代码自测

**题目 1：** `p1 + 1` 和 `p2 + 1` 的地址偏移字节数是否相同？

```c
int a[5];
int *p1 = a;
int (*p2)[5] = &a;
```

A. 相同　　B. 不同

<details>
<summary>参考答案</summary>

**B（不同）。** `p1` 类型是 `int *`，步长 `sizeof(int)` = **4 字节**，`p1+1` 指向 `a[1]`；`p2` 类型是 `int (*)[5]`，步长 `sizeof(int[5])` = **20 字节**，`p2+1` 指向整个数组之后。

判据只有一条：**指针算术的步长由被指类型决定，与地址数值无关**。实测 `p1+1 - p1 = 4`、`p2+1 - p2 = 20`（clang 23.1.0 / arm64）。

</details>

**题目 2：** 以下代码能编译吗？如果不能，为什么？怎么改？

```c
int a[5];
if (a == &a) puts("same");
```

<details>
<summary>参考答案</summary>

严格 C 下**不能**——是约束违规。C11 §6.5.9p2 要求 `==` 的两操作数指向**兼容类型**，或一个为 `void *`；`int *` 与 `int (*)[5]` 二者皆不满足。

- `clang -std=c11 -pedantic-errors` → `error: comparison of distinct pointer types ('int *' and 'int (*)[5]')`
- 默认模式只给 warning，多数人因此误以为"能编译过，值相等"

改成 `if ((void *)a == (void *)&a)`，实测结果为 1（标准 §6.5.9p6：对象指针与其起始子对象指针相等）。

</details>

**题目 3：** `int m[3][5];` 中 `m + 1`、`m[0] + 1`、`&m + 1` 分别前进多少字节？`m` 退化成什么类型？

<details>
<summary>参考答案</summary>

- `m` 退化**一层** → `&m[0]`，类型 `int (*)[5]`（**不是** `int **`）
- `m + 1` → **20 字节**（跳过一行 5 个 int）
- `m[0] + 1` → **4 字节**（`m[0]` 是 `int[5]`，退化 → `int *`）
- `&m + 1` → **60 字节**（`&m` 类型 `int (*)[3][5]`，跳过整个二维数组）

实测：4 / 20 / 60，`sizeof m = 60`。

</details>

**题目 4：** 有人说"用 `(&a)[1] - a` 能求数组长度"，这个写法能学吗？

<details>
<summary>参考答案</summary>

**不能。** `(&a)[1]` 就是 `*(&a + 1)`，而 `&a + 1` 是尾后指针——C11 §6.5.6p8 规定尾后指针**不得解引用**，所以这是 UB（哪怕实现上"看起来都对"）。

正确做法是 `sizeof a / sizeof a[0]`（编译期常量，VLA 与形参场景另有边界，见 `8.1.8`）。

</details>

**题目 5（原 8.1.12）：** 标准 C（C11）中，`vp + 1` 是否合法？

```c
int a[5];
int (*p)[5] = &a;
void *vp = p;
vp + 1;
```

A. 合法　　B. 不合法

<details>
<summary>参考答案</summary>

**B（不合法）。** C11 §6.5.6p2 要求加法的一个操作数是**指向完整对象类型的指针**，而 `void` 是不完整类型——`sizeof(void)` 都不存在，步长无从计算，所以是约束违规。

- `clang -std=c11 -pedantic-errors` → `error: arithmetic on a pointer to void is a GNU extension [-Werror,-Wgnu-pointer-arith]`
- GCC/Clang 默认按 GNU 扩展放行，把 `void` 当 1 字节（实测 `vp + 1` 前进 1 字节、`sizeof(void) = 1`）——**这是扩展，不是标准**

需要步长 1 的场合，请显式用 `char *` / `uint8_t *`。

</details>

**题目 6（原 8.1.12）：** 以下代码合法吗？输出什么？

```c
int a[5] = {10, 20, 30, 40, 50};
int (*p2)[5] = &a;
void *v2 = p2;
printf("%d\n", *(int *)v2);
```

<details>
<summary>参考答案</summary>

合法，输出 **10**。

`v2` 里存的是数组起始地址，那个地址上确实存在一个 `int` 对象（`a[0]`，有效类型 `int`，对齐满足）→ 转换合法（§6.3.2.3p7 只禁止对齐不足的情形），解引用也合法。

**但别被这个"能跑"误导**：`(int *)v2 + 1` 只走 4 字节，而 `p2 + 1` 走 20 字节。地址没错、访问没错，错的是**遍历语义**。

</details>

**题目 7（原 8.1.12）：** 为什么 `printf("%p", a)` 和 `printf("%p", &a)` 输出完全相同？这能证明 `a` 和 `&a` 是同一个东西吗？

<details>
<summary>参考答案</summary>

`%p` 要求 `void *`（C11 §7.21.6.1），两者都转成 `void *` 后只剩地址数字——而数组起始字节只有一个，所以输出必然相同。

**不能证明它们是同一个东西。** `void *` 只保留地址值、丢弃类型信息，所以这一步恰好把唯一的区别（`int *` vs `int (*)[5]`）抹掉了。要看差别必须做指针算术：打印 `a + 1`（+4）和 `&a + 1`（+20）的差值。

顺带：正确写法是 `printf("%p", (void *)a)`，直接传 `int *` 在标准上是 UB（`-Wformat-pedantic` 会告警）。

</details>

**题目 8（原 8.1.12）：** `void *p = f;`（`f` 是函数名）在标准 C 中能保证吗？为什么 `dlsym` 那套代码能工作？

<details>
<summary>参考答案</summary>

**标准不保证。** C11 6.3.2.3p1 只覆盖 `void *` 与**对象类型**指针的互转，函数指针不在其中。实测 `clang -std=c11 -pedantic-errors` → `error: initializing 'void *' with an expression of type 'int (void)' converts between void pointer and function pointer`。

`dlsym` 返回 `void *` 再转函数指针能工作，是因为 **POSIX 额外提供了这个保证**（C11 J.5.7 把它列为常见扩展）；主流实现上函数指针与对象指针宽度一致，所以实际能跑。移植到分段架构/哈佛架构平台不能依赖。

</details>
