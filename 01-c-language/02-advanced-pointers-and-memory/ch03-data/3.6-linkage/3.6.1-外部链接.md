# 3.6.1 外部链接

## 本节讲什么

**外部链接(external linkage)**:标识符在多个翻译单元间指向同一对象/函数。链接器把各 `.o` 中同名的外部链接符号合并成一个。`extern` 声明、函数原型、全局变量定义、`-fno-common` vs `-fcommon`——C 工程里跨文件协作的全靠它。本节从语言层、链接器符号表、工程模板三层讲透。

## 要点

### 条件与示例

```c
/* 文件作用域,无 static → 外部链接 */
int g_count = 0;           /* 全局变量定义,外部链接 */
void foo_api(void){}       /* 函数定义,外部链接 */
```

- 文件作用域(全局)声明的变量/函数,**不加 static** → 外部链接
- 链接器把各 `.o` 中同名外部链接符号合并为一个对象
- 其他 `.c` 通过 `extern` 声明引用同一对象

### 函数默认外部链接

```c
void f(void){}        /* 默认外部链接,可被其他 .c 调用 */
static void h(void){} /* 内部链接,仅本文件 */
```

- C11 §6.2.2p5:文件作用域标识符,无 static → 外部链接
- 函数原型 `void f(void);` 等价 `extern void f(void);`——都是外部链接声明

### extern 的语义

```c
extern int g;             /* 声明: g 在别处定义, 链接器去找 */
extern void f(void);      /* 声明函数原型, 等价 void f(void); */

int g = 1;                /* 定义: 分配存储, 外部链接 */
void f(void){}            /* 定义: 函数体, 外部链接 */
```

- `extern` 关键字 = "声明而非定义,引用别处"
- 函数原型默认就是 extern 语义(`void f(void);` 与 `extern void f(void);` 等价)
- `extern int g;` **不分配存储**;若没有任何 `.c` 定义 `g`,链接器报 `undefined reference to 'g'`

### 定义全局唯一

```c
/* a.c */ int g = 1;
/* b.c */ int g = 2;     /* 两个定义 → 链接器报 multiple definition of 'g' */
```

- 现代 GCC/ld 默认 `-fno-common`:全局变量定义即独占,重复定义立即报错
- 旧版 GCC 默认 `-fcommon`:把"无初值全局"当 tentative definition,允许多文件合并(易出 bug,已改)

> ⚠️ `int g;`(文件域,无初值)是**暂定定义**(tentative definition),不是 `extern` 声明:两个 TU 各写 `int g;` 在 `-fno-common` 下报 `multiple definition`;`extern int g;` 放头文件随便包含不报错。"外部链接"是链接属性,不是存储类——别说成"隐式 extern"。

### nm 符号表中的外部链接

```bash
gcc -c foo.c -o foo.o
nm foo.o
# 0000000000000000 T foo_api       # T = 外部链接, text 段
# 0000000000000000 D g_count       # D = 外部链接, data 段
#                  U memcpy        # U = 未定义, 等链接器从 libc 找
```

| nm 字符 | 含义 |
|---------|------|
| 大写 `T` | 外部链接,代码段(.text) |
| 大写 `D` | 外部链接,已初始化数据段(.data) |
| 大写 `B` | 外部链接,未初始化数据段(.bss) |
| 大写 `R` | 外部链接,只读数据段(.rodata) |
| `U` | 未定义引用,需链接器从其他 `.o`/库解析 |

## 与 HFT/DPDK

### 多 `.o` 链成网关

- HFT 网关几十上百个 `.c`:网络层、协议解析、风控、订单管理、日志……
- 模块间靠 `extern` 共享 API —— 与面向对象的 public 等价
- 头文件只放 `extern` 声明 + 函数原型,定义放 `.c`

### 链接期符号冲突排查

```bash
# 报 "undefined reference to 'y'"
nm -C *.o | grep ' U y'         # 找谁引用了未定义的 y
# 看最终可执行文件符号
nm a.out | sort
objdump -T a.out                # 动态符号表(共享库)
```

## 常见误区

| 误区 | 真相 |
|------|------|
| 头文件写 `int g;` 是声明 | 是定义(暂定),多文件 include 会重复定义 |
| `extern int g;` 分配存储 | 不,是声明,引用别处 |
| 函数默认无链接 | 默认外部链接,可被其他 `.c` 调 |
| `int g;` 和 `extern int g;` 等价 | 不等:前者是暂定定义(分配存储),后者是声明(不分配) |

## 实操

```bash
# 1. extern 引用实验
cat > a.c <<'EOF'
#include <stdio.h>
int shared = 1;              /* 外部链接定义 */
void show(void){ printf("shared=%d\n", shared); }
EOF
cat > b.c <<'EOF'
extern int shared;           /* 引用 a.c */
extern void show(void);
int main(void){ shared = 10; show(); return 0; }
EOF
gcc a.c b.c -o ab && ./ab          # shared=10
nm a.o | grep -E 'shared|show'     # D shared, T show

# 2. 重复定义错误
cat > c.c <<'EOF'
int shared = 99;             /* 与 a.c 冲突 */
EOF
gcc a.c c.c -o ac    # multiple definition of 'shared'

# 3. undefined reference
cat > d.c <<'EOF'
extern int missing;
int main(void){ return missing; }
EOF
gcc d.c -o d    # undefined reference to 'missing'
```

## 代码自测

**题目 1：** 以下两行放在不同 .c 文件中，链接结果是什么？
```c
/* a.c */ int g = 1;
/* b.c */ int g = 2;
```

<details>
<summary>参考答案</summary>

现代 GCC 默认 `-fno-common`，两个定义都是外部链接 → 链接器报 `multiple definition of 'g'`。旧版 GCC 默认 `-fcommon` 时，无初值全局会被当暂定定义合并，但这里两个都有初值，即使在 `-fcommon` 下也会报错。

</details>
