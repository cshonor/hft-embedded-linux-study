# 13.1 进一步探讨指向指针的指针

## 本节讲什么

一级指针 `T *` 让函数能改「`T` 类型的对象」；二级指针 `T **` 让函数能改「指向 `T` 的指针」本身。这条递推听起来平凡，却是 C 工程里最易写错的一类声明——它的核心难点不是语法，而是**「我到底在改谁的谁」**的语义层级。

本节把多级指针的内存模型画清楚，给出「函数内改外部指针数组」的完整模板，并交代工程约束：**生产代码控制在三级以内**，超过三级基本可以认定设计出了问题。

## 要点

### 内存模型：三级视图

```c
char *msg_table[32];    /* 32 个 char* 槽位，栈/静态 */
char **p = msg_table;   /* p 指向数组的第 0 个槽位 */
char ***pp = &p;        /* pp 指向 p 本身 */
```

```
栈/静态区:
  +-----------+      堆区(strdup):       .rodata:
  | msg_table |      +----------+        +---------+
  | [0] ------+----->| "QUOTE\0"|<-------+ "QUOTE" |
  | [1] ------+----->| "ORDER\0"|        +---------+
  | [2] = NULL|      +----------+
  | ...       |
  | [31]      |
  +-----------+
       ^
       |
  p = msg_table    （char**，存数组首地址）
       ^
       |
  pp = &p          （char***，存 p 的地址）
```

| 层级 | 类型 | 存什么 | 典型用途 |
|------|------|--------|----------|
| 0 | `char` | 字符本身 | 字符串内容 |
| 1 | `char *` | 字符串首地址 | 单个字符串 |
| 2 | `char **` | 指针数组元素地址 | 字符串数组（如 argv） |
| 3 | `char ***` | 改外部 `char **` 头 | 函数内重分配数组（少用） |

### 动态字符串数组

```c
char **msg_table = calloc(32, sizeof(char *));
if (!msg_table) return -1;

msg_table[0] = strdup("QUOTE");   /* strdup 内部 malloc */
msg_table[1] = strdup("ORDER");
/* ... */
```

`calloc` 而非 `malloc`：保证未赋值的槽位是 `NULL`，后续遍历可 `while (table[i])` 安全终止。`strdup` 失败时要回滚已分配的——见下文释放顺序。

### 函数内改外部指针数组

```c
/* 把外部 char** 头替换为更大的数组（三级指针场景） */
int msg_table_grow(char ***ptable, size_t *cap, size_t need)
{
    char **old = *ptable;
    char **new = realloc(old, need * sizeof(char *));
    if (!new) return -1;
    /* realloc 成功后 old 已失效，但 new 可能 == old（原地扩展） */
    for (size_t i = *cap; i < need; i++)
        new[i] = NULL;            /* 清零新增槽位 */
    *ptable = new;                /* 改外部头 */
    *cap = need;
    return 0;
}

/* 调用 */
char **table = calloc(8, sizeof(char *));
size_t cap = 8;
msg_table_grow(&table, &cap, 64);  /* 传 &table，三级指针 */
```

**`&table` 才是 `char ***`**，不是 `table`。这是三级指针的合法场景之一：函数要改调用方的「指针数组头」本身。若只传 `char **`，函数改的是副本，调用方看到的还是旧头——与单链表头插必须传 `Node **` 同理（见 ch12）。

### 释放顺序：自底向上

```c
void msg_table_free(char **table, size_t n)
{
    for (size_t i = 0; i < n; i++)
        free(table[i]);    /* 先释放每个字符串 */
    free(table);           /* 再释放指针数组本身 */
}
```

**顺序不可颠倒**：若先 `free(table)`，每个 `table[i]` 的内存虽还在（free 不立刻清零），但访问已释放内存是 UB，ASan 会报「heap-use-after-free」。批量场景下漏释放任一层 = 内存泄漏。

### 失败回滚

```c
char **msg_table_alloc(const char *src[], size_t n)
{
    char **t = calloc(n, sizeof(char *));
    if (!t) return NULL;

    for (size_t i = 0; i < n; i++) {
        t[i] = strdup(src[i]);
        if (!t[i]) {
            /* 回滚：释放已成功的 + 数组本身 */
            for (size_t j = 0; j < i; j++)
                free(t[j]);
            free(t);
            return NULL;
        }
    }
    return t;
}
```

`goto cleanup` 模式在更复杂的多资源场景下更清晰（见 ch11.6），这里循环回滚足够。

## HFT 关联

### 报文批量处理

DPDK 收包的核心 API 签名：

```c
uint16_t rte_eth_rx_burst(uint16_t port_id, uint16_t queue_id,
                          struct rte_mbuf **rx_pkts,
                          uint16_t nb_pkts);
```

`rx_pkts` 是 `struct rte_mbuf **`——一个 mbuf 指针数组的头。DPDK 一次拷贝最多 `nb_pkts` 个 mbuf 指针进来，调用方拿到的是一个**指针数组**，不是 mbuf 数组本身。这样设计的好处：

1. mbuf 在 mempool 里原地不动，只是把指针填进数组，cache 友好。
2. 调用方拿到指针后可批量处理，不需要逐个 dequeue。
3. 释放时 `rte_pktmbuf_free_bulk(rx_pkts, n)`，一次归还。

```c
struct rte_mbuf *pkts[32];
uint16_t n = rte_eth_rx_burst(port, q, pkts, 32);
for (uint16_t i = 0; i < n; i++) {
    process(pkts[i]);
    rte_pktmbuf_free(pkts[i]);   /* 或批量 free */
}
```

`pkts` 是栈上的指针数组（32 × 8 = 256 字节），DPDK 把 mbuf 指针填进来。**这是 `T **` 在 HFT 数据面最高频的用法**。

### 订单池批量扩容

```c
struct order **orders = calloc(cap, sizeof(struct order *));
/* ... 满了需要扩容 ... */
struct order **grown = realloc(orders, new_cap * sizeof(*grown));
if (grown) {
    orders = grown;       /* 注意：调用者要更新自己的头 */
    cap = new_cap;
}
```

`realloc` 失败时 `orders` 仍指向旧块，**不能直接 `orders = realloc(...)`**——失败会丢指针（见 ch11.3）。封装成函数时必须传 `&orders`（三级指针）或返回新指针。

### 多级指针与 cache 局部性

每多一级指针，访问数据就多一次内存间接。`pkts[i]` 需要：① 读 `pkts` 数组的第 i 项（一次访存）→ ② 沿指针读 mbuf 本体（又一次访存）。两级访存意味着 mbuf 必须在 L1/L2 cache 命中，否则延迟翻倍。DPDK 用 mempool 预热 + 同核复用保证 mbuf 常驻热 cache，是这种设计的工程基础。

## UB 边界

| 情形 | 后果 | 防护 |
|------|------|------|
| 释放顺序颠倒（先 free 数组） | 后续 free 元素是 UAF | 自底向上：先元素后数组 |
| `realloc` 失败直接 `p = realloc(p, ...)` | 旧块泄漏，p 变 NULL | 用临时变量接收，判空后再赋值 |
| 三级指针传错（传 `p` 而非 `&p`） | 函数改副本，调用方看到旧头 | 类型即文档：`char ***` 必须 `&p` |
| `calloc(0, ...)` 或 `realloc(p, 0, ...)` | 实现定义，可能返回 NULL 或特殊指针 | 避免零长度分配 |
| 未初始化的 `char **` 当数组用 | 野指针，崩溃 | `calloc` 保证零初始化，或显式 `= NULL` |

### 三级指针的滥用警讯

```c
char ****x;   /* 几乎必然是设计错误 */
```

四级以上指针在生产代码里出现，通常意味着：

- 该用结构体封装却裸用指针（应改成 `struct table *table`）。
- 该用返回值却用出参层层传递（应改成 `char **grow(char **)` 返回新头）。
- 函数职责过重（应拆分）。

内核、DPDK、glibc 几乎找不到四级指针的合法用例。**三级已是上限**。
