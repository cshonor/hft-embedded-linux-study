# 13.2 高级声明

## 本节讲什么

C 的声明语法被讽刺为「spiral rule（螺旋法则）」——标识符在中间，运算符按优先级向外螺旋展开。本节把这条规则拆成可操作的步骤，覆盖五大经典声明：**指针数组、数组指针、函数指针、函数指针数组、多级指针**，并给出 typedef 简化的工程必要性。

认知锚点：复杂声明不是炫技，而是**阅读内核/DPDK/glibc 头文件的必备技能**。`int (*handler[16])(int, void *)` 这类声明在 `file_operations`、`sigaction`、PMD 驱动表里随处可见，看不懂就无法读懂核心代码。

## 要点

### 右左法则（螺旋法则）步骤

1. **找到标识符**（变量名），从它开始。
2. **看右边**：若是 `[]` 是数组，若是 `()` 是函数，按优先级处理。
3. **看左边**：若是 `*` 是指针，若是类型修饰符则记录。
4. **遇到括号 `()`**：先处理括号内，再向外。
5. **类型名最后处理**：最外层的类型是「最终指向/返回的类型」。

口诀：**先找标识符 → 括号优先 → 先右后左 → 螺旋向外**。

### 五大经典声明对照

| 声明 | 解读步骤 | 中文读法 |
|------|----------|----------|
| `int *arr[10];` | arr → [10] → int * | **指针数组**：10 个 `int *` |
| `int (*arr)[10];` | arr → * → [10] → int | **数组指针**：指向含 10 个 int 的数组 |
| `int (*func)(int);` | func → * → (int) → int | **函数指针**：入参 int，返回 int |
| `int (*table[16])(int);` | table → [16] → * → (int) → int | **函数指针数组**：16 个函数指针 |
| `char ***msg;` | msg → * → * → * → char | **三级 char 指针** |

#### 关键对比：`int *arr[10]` vs `int (*arr)[10]`

```
int *arr[10];       // arr 是数组，每个元素是 int*
                    // [] 优先级高于 *，所以 arr 先和 [] 结合
                    // sizeof(arr) = 10 * 8 = 80（x86-64）

int (*arr)[10];     // arr 是指针，指向 int[10]
                    // 括号强制 * 先结合
                    // sizeof(arr) = 8（一个指针）
```

混淆这两者会导致：

- 用 `int (*)[10]` 接收 `int *[10]`：类型不匹配，编译警告（C 允许某些隐式转换，但行为未定义）。
- 二维数组传参 `int matrix[3][4]` 退化为 `int (*)[4]`，若函数声明成 `int **` 是错的——后者是指针数组，内存布局完全不同（见 ch08 多维传参）。

### 函数指针数组的精确解读

```c
int (*table[16])(int, void *);
```

螺旋展开：

1. `table` 是标识符。
2. 右边 `[16]`：table 是 16 元素的数组。
3. 左边 `*`：数组的每个元素是指针。
4. 右边 `(int, void *)`：指针指向函数，入参 `(int, void *)`。
5. 最外 `int`：函数返回 int。

合起来：**table 是 16 元素数组，每个元素是「入参 (int, void*)、返回 int」的函数指针**。

这正是 Linux 内核 `struct file_operations` 的字段类型，也是 DPDK `eth_dev_ops` 的核心。

### typedef 简化：工程强制规范

```c
/* 痛苦写法 */
int (*handlers[16])(int, void *);

/* typedef 简化 */
typedef int (*handler_fn_t)(int, void *);
handler_fn_t handlers[16];
```

| 维度 | 裸声明 | typedef |
|------|--------|---------|
| 可读性 | 低，需螺旋展开 | 高，名字即语义 |
| 修改成本 | 改签名要全文搜索替换 | 改 typedef 一处 |
| 强制规范 | 无 | 内核/DPDK 强制 |
| 错误信息 | 类型推导报错晦涩 | 类型名清晰 |

**规则**：函数指针、回调签名、复杂结构指针**必须 typedef**。glibc、Linux、DPDK、nginx 全部遵守此规则。

### 复杂声明的 typedef 拆解

```c
/* 信号处理函数原型 */
void (*sig_t)(int);

/* typedef 化 */
typedef void (*sig_t)(int);
sig_t old_handler = signal(SIGINT, new_handler);
```

```c
/* qsort 比较函数 */
typedef int (*cmp_fn_t)(const void *, const void *);
cmp_fn_t cmp = my_compare;
qsort(arr, n, sizeof(arr[0]), cmp);
```

### 实战：file_operations 字段

```c
struct file_operations {
    ssize_t (*read)(struct file *, char __user *, size_t, loff_t *);
    ssize_t (*write)(struct file *, const char __user *, size_t, loff_t *);
    long (*unlocked_ioctl)(struct file *, unsigned int, unsigned long);
    int (*open)(struct inode *, struct file *);
    int (*release)(struct inode *, struct file *);
    /* ... */
};
```

每个字段都是「函数指针」。驱动初始化时用指定初始化（C99）填入：

```c
static const struct file_operations my_fops = {
    .read    = my_read,
    .write   = my_write,
    .open    = my_open,
    .release = my_release,
};
```

未指定的字段默认 NULL，内核 VFS 层调用时判空跳过。**这是「声明即文档」的最佳范例**——typedef 让字段名成为 API 描述。

## HFT 关联

### DPDK 报文处理表

```c
struct rte_mbuf *pkts[32];                 /* 指针数组 */
int (*cmp)(const void *, const void *);    /* qsort 式比较函数指针 */
```

`pkts` 是栈上的 mbuf 指针数组，`cmp` 是比较函数指针，两者都是本节五大声明的实例。DPDK `eth_dev_ops`、`rte_mempool_ops` 全部用函数指针表实现多态。

### 策略插件热加载

```c
typedef int (*strategy_fn_t)(struct market_state *, struct order *);

struct strategy {
    const char       *name;
    strategy_fn_t     on_quote;
    strategy_fn_t     on_trade;
    strategy_fn_t     on_depth;
};
```

策略模块以 `.so` 形式 `dlopen` 加载，通过 `dlsym` 拿到 `struct strategy *`，挂入策略表。**所有多态分发都依赖函数指针声明**，看不懂声明就无法设计插件系统。

### 内联函数指针调用的代价

```c
handler(args);   /* 间接调用 */
```

间接调用比直接调用多一次访存（取函数地址）+ 一次跳转，且**分支预测器对间接跳转的预测准确率较低**。HFT 数据面优化时：

1. **PGO（profile-guided optimization）**：让编译器看到热点分支，优化间接跳转预测。
2. **手工展开热点**：高频分支单独 if-else，低频走转移表。
3. **`__builtin_expect` 提示**：辅助分支预测。

## UB 边界

| 情形 | 后果 | 防护 |
|------|------|------|
| `int *arr[10]` 误当 `int (*)[10]` 用 | 类型不匹配，UB | 看清 `[]` 和 `*` 的优先级 |
| 函数指针赋值不同签名 | 调用时栈帧错乱，UB | typedef 锁定签名，编译器警告 |
| 未初始化的函数指针调用 | 跳到野地址，崩溃 | `= NULL` 初始化，调用前判空 |
| 把「函数」当「函数指针」直接赋值给 `void *` | 标准不允许（POSIX 实践允许） | 用对应函数指针类型中转 |
| 函数指针与数据指针互转 | 部分平台不兼容（哈佛架构） | 不要互转，用 `union` 或专门类型 |

### 函数指针 ≠ 数据指针

C 标准不保证函数指针能转成 `void *` 再转回来——哈佛架构（代码与数据分离）上两者位数可能不同。POSIX 强制要求 `void *` 能容纳函数指针（为了 `dlsym`），但**可移植代码应避免这种转换**。`dlsym` 返回 `void *` 是 POSIX 妥协，使用时强转到正确函数指针类型。

### 空函数指针判空

```c
handler_fn_t cb = NULL;       /* 显式初始化 */
if (cb) cb(args);             /* 调用前判空 */
```

`NULL` 函数指针调用是 UB，通常崩溃但**不保证**——某些嵌入式平台可能跳到 0 地址执行。判空是工程铁律。
