# 7.2.4 C 为什么没有重载（overload）

## 本节讲什么

**直接结论：C 语言没有函数重载。函数名字就是全部——函数名必须独一无二，不看参数、不看返回值。** 本节从符号生成机制（无 name mangling）讲清根源，对照 C++ 的重载实现，并给出 C 模拟"多态"的三种工程方案。

## 要点

C 的符号规则：函数符号**只由函数名字决定，参数列表、返回类型完全不参与符号生成**：

```c
void func(int a);
int  func(double b);   /* ❌ C：两者符号都叫 func，冲突 */
```

在 C 眼里：名字一样就是同一个函数，参数不一样也不行；返回值不一样也不行
（`void foo(void)` 和 `int foo(void)` 同样冲突）——**返回值不区分函数**。

> C++ 会做名字改编（name mangling）：把参数类型编码进符号名（`_Z4funci` / `_Z4funcd`），
> 所以允许重载。**C 没有 mangling，符号名就是函数名本身。**

### 那两个 .c 分开写呢？（易错例）

```c
/* file1.c */ void calc(int a)    {}
/* file2.c */ int  calc(double a) {}
```

分开编译各自都能过；**链接时两个符号都叫 `calc` → multiple definition 报错**。
C 链接器根本不看参数，只看名字。若在同一翻译单元里写两个声明，编译期就报
`conflicting types for 'calc'`（类型不兼容，约束违反）——不用等到链接。

### 返回值不同：C 与 C++ 都拒绝

只改返回值、不改参数时两边都拒绝（返回值不参与重载）：

| 代码 | C（gcc） | C++（g++） |
|------|----------|------------|
| `int foo(int);` + `void foo(int);` | `error: conflicting types for 'foo'; have 'void(int)'` | `error: ambiguating new declaration of 'void foo(int)'` |

### 同一份代码，C 和 C++ 是另一回事

把"错误声明 + 真实定义"（见 **7.2.3** 情况一）丢给 `g++`，**编译通过**——因为 `void foo(void)` 和 `int foo(int)` 参数不同，在 C++ 里构成一个**合法的重载集**；随后 `foo()` 重载决议选中了那个**从未定义**的版本：

```
$ g++ -std=c++17 demo1.cpp -o demo1pp
/usr/bin/ld: undefined reference to `foo()'
```

## 底层映射：name mangling 实测

```bash
$ printf 'void test(int x){}\nvoid test(double x){}\n' > t.cc
$ g++ -c t.cc && nm t.cc
0000000000000000 T _Z4testd    # C++：double 版，类型编进符号名
0000000000000008 T _Z4testi    # C++：int 版，两个不同符号 → 重载合法

$ gcc -c t.c   # 同样两个定义
t.c:2:6: error: conflicting types for 'test'   # C：编译期直接拦
```

C 的符号表里函数名"裸奔"（`test` 就是 `test`）——这就是 `extern "C"` 存在的原因：
C++ 代码要被 C 链接器找到，必须关掉 mangling，副作用是**该函数不能重载**（符号只能有一个）。

## C 模拟"多态"的三种方案

| 方案 | 写法 | 场景 |
|------|------|------|
| ① 名字加后缀（工业界最常见） | `func_int()` / `func_double()` | 内核到处都是（`__u32`/`__u64` 系列） |
| ② `void*` + 类型标记（模拟动态多态） | `void print(void *data, int type)` | 传 void* 再传类型标记，函数内部分发；qsort 回调、很多库这么干 |
| ③ 结构体函数指针（**运行时多态**） | `struct ops { void (*read)(void); void (*write)(void); }` | Linux 内核 file_operations 大量使用；不同设备填不同实现，同一接口不同行为（→ **ch13.3** 函数指针） |

### 两个概念不要混

| 概念 | 时机 | C 支持？ |
|------|------|----------|
| **函数重载**（编译期多态，C++） | 同名不同参，编译器自动选版本 | ❌ 不支持 |
| **运行时多态**（函数指针分发） | 结构体存函数指针，运行时切换实现 | ✅ 支持，内核大量使用 |

## 常见误区

| 误区 | 事实 |
|------|------|
| "C 里参数不同就是重载" | 符号只看函数名，同名不管参数都是同一个函数，冲突 |
| "返回值不同算两个函数" | 返回值不参与符号生成，`void f()` 和 `int f()` 同样冲突 |
| "签名不同拆到两个 .c 就没事" | 编译各过各的，链接期 multiple definition——链接器只配对名字 |
| "C++ 的 `void foo(void)` 和 `int foo(int)` 一起给 C 用没关系" | C 里是约束违反；C++ 里合法但可能决议到从未定义的版本 |

## 代码自测

**题目 1：** 同一份代码，C 和 C++ 各会怎样？

```c
void test(int x);
void test(double x);
```

<details>
<summary>参考答案</summary>

**C：编译期就报错。** 同一翻译单元内两个 `test` 声明类型不兼容——这是约束违反，
GCC/Clang 直接报 `error: conflicting types for 'test'`，根本活不到链接阶段。
（若拆到两个 .c 各自定义，则各自编译通过、链接期 multiple definition。）

**C++：完全合法。** name mangling 把两个版本编成不同符号：
`_Z4testi`（int 版）/ `_Z4testd`（double 版），重载决议按实参类型在**编译期**挑选版本。

根源：C 的符号名就是函数名本身，参数/返回值不参与；C++ 把参数类型编码进符号名。
这也是 `extern "C"` 的意义——C++ 函数要让 C 链接器找到必须关掉 mangling，
代价是该函数不能重载。
