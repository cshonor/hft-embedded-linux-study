# 10.5 位段

## 本节讲什么

**Bit-field（位段）** 在 struct 内按 **bit** 分配成员，允许多个字段共享同一字节。它看似适合映射**紧凑的硬件寄存器**和协议标志位，但有**致命的平台相关性**：bit 分配顺序、跨字节边界、对齐方式都由实现定义。因此**位段禁止用于网络协议线格式**——改用显式移位和掩码（ch05）。

本节剖析位段的语法、规则、平台相关性陷阱、以及正确的替代方案。

## 要点

### 基本语法

```c
struct dev_status {
    uint32_t ready : 1;    /* 1 bit */
    uint32_t err   : 2;    /* 2 bits */
    uint32_t mode  : 3;    /* 3 bits */
    uint32_t rsv   : 26;   /* 26 bits */
};
/* sizeof = 4 字节，共 32 bits 填满一个 uint32_t */
```

- `成员名 : 宽度` 声明位段
- 宽度是 **bit 数**，非字节数
- 通常用 `unsigned int` / `uint32_t` 作为载体类型

### 访问与赋值

```c
struct dev_status s = {0};
s.ready = 1;
s.err = 3;
s.mode = 5;

uint32_t reg;
memcpy(&reg, &s, sizeof reg);   /* 取出 32 位寄存器值 */
```

- 位段成员可像普通字段读写
- 编译器生成移位和掩码指令
- **取地址非法**：`&s.ready` 是编译错误（位段无独立地址）

### 平台相关性陷阱

位段的**所有**布局细节都是**实现定义**：

| 维度 | 平台差异 |
|------|----------|
| **bit 分配顺序** | 大端机从 MSB 分配，小端机从 LSB 分配 |
| **跨字节边界** | 有的实现允许跨字节，有的强制新字节开始 |
| **载体类型** | `int` 可能是 signed/unsigned，符号位行为不同 |
| **对齐** | struct 总对齐由载体类型决定 |
| **最大宽度** | 通常 ≤ 载体类型宽度（如 `uint32_t` 最多 32 bit） |

### 大小端对位段的影响

```c
struct flags {
    uint16_t a : 4;
    uint16_t b : 4;
    uint16_t c : 8;
};
```

- 小端 x86：`a` 在低 4 位，`b` 在次 4 位，`c` 在高 8 位
- 大端 SPARC：`a` 在高 4 位，`b` 在次 4 位，`c` 在低 8 位
- **同一 C 源码，不同平台产生不同内存布局**

这就是位段**不能用于网络协议**的根本原因——接收端可能用不同字节序，导致字段错位。

### 禁止取地址

```c
struct dev_status s;
uint32_t *p = &s.ready;   /* 编译错误：位段成员不能取地址 */
```

- 位段无独立存储地址（共享字节）
- 不能用指针操作位段
- 不能传给 `scanf("%d", &s.ready)`

### 位段 vs 显式移位

```c
/* 反例：位段（平台相关） */
struct tcp_flags_bitfield {
    unsigned fin : 1;
    unsigned syn : 1;
    unsigned rst : 1;
    /* ... */
};

/* 正例：显式移位（平台无关） */
uint16_t flags = ntohs(tcp->flags);
int fin = (flags >> 0) & 1;
int syn = (flags >> 1) & 1;
int rst = (flags >> 2) & 1;
```

显式移位的优势：

- **完全可移植**：bit 位置由代码定义，与平台无关
- **可取地址**：`flags` 是普通 uint16_t
- **可序列化**：直接 `htonl`/`htons` 发送
- **可调试**：调试器能看到完整值

### 位段的合理用例

**硬件寄存器映射**（PCI/MMIO）：

```c
struct pci_status {
    uint32_t int_pending : 1;
    uint32_t int_line    : 3;
    uint32_t dev_id      : 5;
    uint32_t rsv         : 23;
};

volatile struct pci_status *reg = (volatile struct pci_status *)0xFE000000;
if (reg->int_pending) {
    /* 处理中断 */
}
```

- 硬件手册定义的 bit 布局，与平台字节序一致（同机内）
- 驱动代码与硬件强绑定，移植性不是目标
- `volatile` 防止编译器优化掉访存

**紧凑标志集合**（内存极度受限）：

```c
struct compact_flags {
    uint8_t is_valid : 1;
    uint8_t is_dirty : 1;
    uint8_t is_locked : 1;
    uint8_t type : 5;
};
/* 1 字节存 8 个标志 */
```

嵌入式 MCU 场景，每字节都珍贵。

### 位段的限制

| 限制 | 说明 |
|------|------|
| 不能取地址 | `&bf.field` 非法 |
| 不能用 `sizeof` | `sizeof(bf.field)` 非法 |
| 不能用 `scanf` | 无法取地址 |
| 不能是数组 | 位段成员不能为数组 |
| 不能跨实现移植 | 布局是实现定义 |
| 不能用作线格式 | 字节序和边界规则不同 |

## HFT 关联

- **协议头标志位**：TCP flags、IP flags **不用位段**，用显式移位和掩码
- **PCI 配置空间**：DPDK PMD 驱动用位段映射网卡寄存器（同机内，移植性非目标）
- **订单标志**：`is_cancelled`、`is_filled` 等用 `uint8_t` + 移位，或单独 `uint8_t flags` + 宏
- **性能**：位段访问是移位+掩码，与手动移位性能相当；但可移植性差，HFT 代码倾向手动移位
- **调试**：位段在调试器中可见名字，但跨平台调试时布局可能不同

### 实操：协议标志位的正确做法

```c
/* TCP flags 字节 */
#define TCP_FIN 0x01
#define TCP_SYN 0x02
#define TCP_RST 0x04
#define TCP_PSH 0x08
#define TCP_ACK 0x10
#define TCP_URG 0x20

uint8_t flags = tcp_hdr->flags;   /* 直接取字节 */
if (flags & TCP_SYN) { /* SYN 标志 */ }
if (flags & TCP_ACK) { /* ACK 标志 */ }
```

平台无关、可移植、可调试。

### 实操：硬件寄存器位段

```c
struct nic_status {
    uint32_t link_up    : 1;
    uint32_t link_speed : 3;
    uint32_t duplex     : 1;
    uint32_t rsv        : 27;
};

volatile struct nic_status *reg =
    (volatile struct nic_status *)mmap_addr;

if (reg->link_up) {
    uint32_t speed = reg->link_speed;
}
```

驱动代码，与硬件强绑定，位段可接受。

### 实操：位段取地址错误

```c
struct flags f = {0};
f.a = 1;
uint32_t *p = &f.a;   /* 编译错误：cannot take address of bit-field */
scanf("%u", &f.a);    /* 同样错误 */
```
