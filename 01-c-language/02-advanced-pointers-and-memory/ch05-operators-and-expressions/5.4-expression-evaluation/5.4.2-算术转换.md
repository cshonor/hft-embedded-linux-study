# 5.4.2 算术转换

## 本节讲什么

二元算术/关系运算前,两操作数要转成**共同类型** —— 这套规则叫**寻常算术转换(usual arithmetic conversions)**。它解释了为什么 `unsigned + signed` 常被当无符号算、负数变巨大正数,这是 HFT 代码里隐蔽数值 bug 的主要根源。本节讲转换层级、陷阱、HFT 防御写法。

## 要点

### 寻常算术转换规则(自上而下)

```
若有一边 long double  → 两边 long double
否则若有一边 double   → 两边 double
否则若有一边 float    → 两边 float
否则(整型):
   1. 先整型提升(char/short → int)
   2. 按整数转换等级向更宽类型提升
   3. 同宽时:若一边 unsigned → 两边 unsigned
```

**整数转换等级**(自高到低):

```
unsigned long long, long long
unsigned long,    long
unsigned int,     int
unsigned short,   short
unsigned char,    char
_Bool(最低)
```

### 浮点优先

```c
int i = 1;
double d = 2.5;
double r = i + d;      /* i 转 double, 结果 3.5(double) */
```

- 任何一边是浮点 → 两边转该浮点类型
- 浮点转整型会**截断小数**;整型转浮点可能丢精度(int64 → double 低 11 位可能丢)

### 整型的"signed → unsigned"陷阱

```c
int          a = -1;
unsigned int b = 5;

if (a < b)              /* a 转 unsigned = 0xFFFFFFFF, 4294967295 < 5 → 假! */
    printf("runs\n");    /* 不打印 */
```

**分析**:

1. a 是 int(-1),b 是 unsigned int(5)
2. 同宽(都 32 位),一边 unsigned → 两边 unsigned
3. a 转为 unsigned int:模 2^32,即 0xFFFFFFFF = 4294967295
4. `4294967295 < 5` → 假

这是"`unsigned` 吞噬负数"的经典场景:`-1` 比任何 `unsigned` 都"大"。

### 常见陷阱表

| 表达式 | 预期 | 实际 | 原因 |
|--------|------|------|------|
| `-1 < 5u` | 真 | 假 | -1 转 unsigned = 0xFFFFFFFF |
| `sizeof(int) < -1` | 假 | 真 | sizeof 返回 size_t(unsigned),-1 转 size_t = 巨大 |
| `5u - 8u` | -3 | 4294967293 | unsigned 减法环绕 |
| `int + unsigned` | 有符号算 | unsigned 算 | 同宽 signed→unsigned |

> **铁律**:有符号与无符号混合比较/运算前,**显式 cast** 到同一类型,别靠隐式转换。

### 算术转换与 HFT 类型选择

| HFT 数据 | 推荐类型 | 理由 |
|----------|----------|------|
| 价格 | `int64_t` 定点 | 避免浮点精度、避免 unsigned 比较陷阱 |
| 序列号/时间戳 | `uint64_t` | 环绕定义良好、足够大 |
| 长度 | `size_t` | 与库 API 一致,但偏移先检查 ≥0 |
| 报文字节 | `uint8_t` | 不用 char(符号不定) |
| 计数 | `uint64_t` | 防溢出,环绕可控 |

## 与 HFT/DPDK

### 时间戳与序列号统一 uint64

```c
uint64_t now = rte_get_tsc_cycles();      /* uint64 时间戳 */
uint64_t seq = next_seq();                 /* uint64 序列号 */
uint64_t elapsed = now - start;            /* uint64 减法, 环绕定义良好 */
```

- uint64 范围足够大(584 年纳秒级),实战不会环绕
- uint64 减法即便环绕也定义良好,不像有符号溢出 UB

### 价格定点运算

```c
/* 价格用 int64 定点, 1 单位 = 1e-7 */
int64_t price = 1234567;       /* = 0.1234567 */
int64_t qty = 100;
int64_t notional = price * qty;   /* int64 乘法, 检查溢出 */

if (notional / price != qty) {   /* 溢出检查 */
    return -EOVERFLOW;
}
```

- 避免浮点:精度可控、比较确定
- int64 乘法溢出是 UB,要检查(或用 __int128 临时)

### 长度与偏移

```c
size_t len = get_len();
int off = get_offset();
/* 反例 */
if (off < len) {                 /* off<0 时变巨大, 真 */
    buf[off] = 0;                /* 越界写 */
}
/* 正解 */
if (off >= 0 && (size_t)off < len) {
    buf[off] = 0;
}
```

- 有符号偏移与无符号长度比较 → 负偏移变巨大正数 → 越界
- 规范:先检查 `off >= 0` 再 cast 比较,或用 ptrdiff_t

### 比较的显式 cast

```c
int32_t x = -1;
uint32_t y = 5;

/* 反例 */
if (x < y) ...                  /* x 转 unsigned = 0xFFFFFFFF, 假 */

/* 正解 */
if ((int64_t)x < (int64_t)y) ...   /* 显式 cast 到同类型 */
```

## 常见误区

| 误区 | 真相 |
|------|------|
| `-1 < 5u` 恒真 | 假;-1 转 unsigned = 0xFFFFFFFF |
| `int + unsigned` 按 int 算 | 按 unsigned 算,负数变巨大 |
| `sizeof(x) < -1` 假 | 真;sizeof 是 size_t(unsigned) |
| `5u - 8u == -3` | 不,等于 4294967293(环绕) |
| 浮点转整型四舍五入 | 不,截断小数 |
| int64 转 double 精确 | 低 11 位可能丢(52 位尾数装不下 64 位) |

## 实操

```bash
cat > t.c <<'EOF'
#include <stdio.h>
#include <stdint.h>
int main(void){
  int a = -1; unsigned int b = 5;
  printf("(-1) < 5u: %d\n", a < b);          /* 0, 假! */
  printf("5u - 8u = %u\n", 5u - 8u);          /* 4294967293 */
  printf("sizeof(int) < -1: %d\n", sizeof(int) < -1);  /* 1, 真! */
  /* 显式 cast 拯救 */
  printf("cast: %d\n", (int64_t)a < (int64_t)b);  /* 1, 真 */
  double d = (double)9223372036854775807LL;     /* INT64_MAX */
  printf("INT64_MAX as double: %lld\n", (int64_t)d);  /* 可能丢精度 */
  return 0;
}
EOF
gcc -std=c11 -Wall -Wsign-compare -Wconversion t.c -o t && ./t
```

## 代码自测

**题目 1：** 以下代码中 c1 + c2 的结果类型是什么？
```c
char c1 = 100, c2 = 100;
int result = c1 + c2;
```

<details>
<summary>参考答案</summary>

char 在算术运算中会被提升为 int（整数提升），所以 c1 + c2 的结果类型是 int，值为 200。这也是为什么 sizeof(c1 + c2) 等于 sizeof(int) 而非 sizeof(char)。

</details>
