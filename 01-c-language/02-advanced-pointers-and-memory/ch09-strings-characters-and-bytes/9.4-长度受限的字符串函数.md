# 9.4 长度受限的字符串函数

## 本节讲什么

**`strncpy` / `strncat` / `strncmp`** 是 str 系列的"限长版"：多了一个 `n` 参数。但**关键认知**是：它们**仍依赖 `\0` 语义**，**不是**真正的二进制安全 API。`n` 只是上界，扫描仍可能在 `\0` 处提前停止。这族函数有**行为不一致**的著名坑（`strncpy` 不补 `\0`、`strncat` 补 `\0`），是 C 标准库被诟病的设计缺陷之一。

本节剖析三个函数的细节、与 `strlcpy`/`strlcat` 的对比、以及工程上的正确选择。

## 要点

### 函数清单

| 函数 | 原型 | 行为 | 补 `\0`？ |
|------|------|------|-----------|
| **`strncpy`** | `char *strncpy(char *dst, const char *src, size_t n)` | 最多拷 `n` 字节 | **不一定** |
| **`strncat`** | `char *strncat(char *dst, const char *src, size_t n)` | 最多追加 `n` 字符 | **总是** |
| **`strncmp`** | `int strncmp(const char *s1, const char *s2, size_t n)` | 最多比 `n` 字节 | — |

### strncpy 的两个坑

**坑 1：src 长 ≥ n 时不补 `\0`**

```c
char d[5];
strncpy(d, "hello world", 5);
/* d = {'h','e','l','l','o'} —— 无 \0！ */
printf("%s", d);   /* UB：越界读直到碰巧 \0 */
```

**必须手动补**：

```c
strncpy(d, src, sizeof(d) - 1);
d[sizeof(d) - 1] = '\0';   /* 铁律：strncpy 后手动终止 */
```

**坑 2：src 短时填充 `\0` 到 n 字节**

```c
char d[8];
strncpy(d, "ab", 8);
/* d = {'a','b','\0','\0','\0','\0','\0','\0'} —— 填充 6 个 \0 */
```

这是**性能浪费**——拷贝 2 字节却写了 8 字节，且编译器优化难以消除（标准要求如此）。`strlcpy` 不做这种填充。

### strncat 的微妙之处

```c
char d[8] = "abc";
strncat(d, "defghij", 3);
/* d = "abcdef\0?" —— 追加最多 3 字符，再补 \0，共写 4 字节 */
```

- `n` 是**最多从 src 取的字符数**，**不含 `\0`**
- `strncat` **总是**在结果末尾补 `\0`
- 所需 dst 容量 = `strlen(dst) + min(strlen(src), n) + 1`
- 与 `strncpy` 不补 `\0` **形成对比**——同族函数行为不一致，是 C 标准库的著名设计缺陷

### strncmp 的行为

```c
strncmp("foobar", "foobaz", 3);   /* 0 —— 前 3 字节相同 */
strncmp("foobar", "foo", 10);     /* >0 —— 第 4 字节 'b' > '\0' */
strncmp("foobar", "foobaz", 10);  /* <0 —— 第 5 字节 'a' < 'z' */
```

- 最多比较 `n` 字节
- 遇 `\0` 或差异或满 `n` 停止
- **仍依赖 `\0`**——若两串前 `n` 字节相同且都无 `\0`，返回 0

### strlcpy / strlcat：更安全的替代

OpenBSD 1996 年引入，Linux 内核 2016 年、glibc 2.38（2023）跟进。

```c
size_t strlcpy(char *dst, const char *src, size_t dstsize);
size_t strlcat(char *dst, const char *src, size_t dstsize);
```

**strlcpy 优势**：

- 拷贝至多 `dstsize-1` 字节，**总是补 `\0`**
- 返回 `strlen(src)`，调用方可判断是否截断：`if (ret >= dstsize) /* 截断 */`
- **不**做 `strncpy` 那种无意义填充

**strlcat 优势**：

- 在 `dst` 末尾追加，至多写 `dstsize-1` 字节（含已有 + 新增）
- 返回**尝试的总长度** `strlen(dst) + strlen(src)`
- 总是补 `\0`

```c
char d[8] = "abc";
size_t r = strlcat(d, "defghij", sizeof(d));
/* d = "abcdefg\0"（截断），r = 10（尝试的总长度） */
if (r >= sizeof(d)) { /* 截断了 */ }
```

### strscpy：Linux 内核新版

```c
ssize_t strscpy(char *dst, const char *src, size_t size);
```

- 返回 `-E2BIG` 表示截断，否则返回已写长度
- 比 `strlcpy` 更符合 POSIX 错误处理惯例
- Linux 4.3（2016）引入内核，用户态尚未普及

### 工程选择决策表

| 场景 | 推荐 | 理由 |
|------|------|------|
| 文本拷贝（已知 dst 大小） | `strlcpy` 或 `snprintf` | 总是补 `\0`，可检测截断 |
| 文本拷贝（兼容旧系统） | `strncpy` + 手动补 `\0` | 唯一可移植选项 |
| 文本拼接 | `strlcat` 或 `snprintf` + offset | 安全 |
| 二进制拷贝 | **`memcpy` + n** | 与 `\0` 无关 |
| 文本比较 | `strncmp` | 限长防越界 |
| 二进制比较 | **`memcmp`** | 显式 n |
| 跨平台安全 API | `snprintf` | C89 起标准，最可移植 |

### snprintf：最可移植的安全选择

```c
snprintf(dst, sizeof dst, "%s", src);
```

- C89 起标准化，**所有平台都有**
- 总是补 `\0`
- 返回需要的总长度，可检测截断
- 缺点：格式串解析有开销，热路径上不如 `strlcpy` 快

## HFT 关联

- **DPDK rte_strlcpy**：DPDK 18.11 起提供，行为与 `strlcpy` 一致
- **配置字符串拷贝**：`rte_eal_init` 的 argv 处理用 `strlcpy` 或 `snprintf`
- **报文头部拷贝**：定长字段用 `memcpy`，**不**用 `strncpy`（填充浪费周期）
- **FIX tag 拷贝**：变长字段用 `memcpy` + 显式 `field_len`
- **日志前缀拼接**：`snprintf` 是标准范式，**不**用 `strncat`
- **性能**：`strncpy` 的 `\0` 填充在 64 字节缓冲上浪费约 10-20ns，HFT 热路径不可忽视

### 实操：strncpy 截断后 printf 乱码

```c
char buf[5];
strncpy(buf, "hello world", 5);
/* buf 无 \0 */
printf("[%s]\n", buf);   /* 输出 "[hello???]" —— 越界读到栈上偶然 \0 */

/* ASan 报：stack-buffer-overflow */
```

修复：

```c
char buf[5];
strncpy(buf, "hello world", sizeof(buf) - 1);
buf[sizeof(buf) - 1] = '\0';
printf("[%s]\n", buf);   /* "[hell]" */
```
