# 9.2 字符串长度

## 本节讲什么

**`strlen(s)`** 与 **`sizeof(x)`** 是 C 字符串最高频的踩坑点，根因是二者**语义完全不同**但常被新手混用：前者是**运行时函数**，扫描到 `\0` 才停；后者是**编译期运算符**，求的是变量占用的字节数。混淆这两者在二进制报文场景会直接导致越界读或长度计算错误。

## 要点

### 核心区别

| 函数/运算符 | 含义 | 求值时机 | 含 `\0`？ | 适用对象 |
|-------------|------|----------|-----------|----------|
| **`strlen(s)`** | 第一个 `\0` 前的字符数 | **运行时**（O(n) 扫描） | **否** | C 字符串（必须含 `\0`） |
| **`sizeof(x)`** | 对象占用的字节数 | **编译时** | **是**（char 数组） | 任意对象或类型 |

### 实例对比

```c
char a[] = "quote";   /* 6 字节的数组：'q''u''o''t''e''\0' */
strlen(a);    /* 5 —— 扫描到 a[5] 的 \0 停 */
sizeof(a);    /* 6 —— 编译期数组大小 */

char *p = a;        /* 指针，指向数组首元素 */
strlen(p);    /* 5 —— 仍扫描内容 */
sizeof(p);    /* 8（x86-64）—— 指针本身宽度，与字符串无关 */
```

`sizeof(p) == 8` 而非 6，这是**指针退化**的典型表现（ch08 已详述）：数组名 `a` 作为 `sizeof` 操作数时不退化，但赋给指针 `p` 后 `p` 只是一个 8 字节的指针变量，`sizeof(p)` 求的是**指针本身**的大小，与它指向什么无关。

### strlen 的实现与复杂度

glibc 的 `strlen` 用 SIMD（SSE2/AVX2）一次比对 16/32 字节，但仍**必须扫到 `\0`** 才返回，**最坏 O(n)**。在热路径上反复调用 `strlen(s)` 是经典性能陷阱：

```c
/* 反例：每轮循环都重新 strlen */
for (size_t i = 0; i < strlen(s); i++) { /* ... */ }  /* O(n^2) */

/* 正例：缓存长度 */
size_t n = strlen(s);
for (size_t i = 0; i < n; i++) { /* ... */ }           /* O(n) */
```

### 致命风险：缓冲无 `\0` → 越界读 UB

```c
char buf[5] = { 'a', 'b', 'c', 'd', 'e' };  /* 无 \0 */
strlen(buf);   /* UB：扫描越过 buf，直到碰巧遇到 0x00 */
```

- 栈上紧邻数据可能很快遇到 0，结果"看起来正常"
- ASan 会报 `stack-buffer-overflow`
- 二进制报文里 `pkt_len` 字段给出的字节流**常常不含 `\0`**，调 `strlen` 直接越界

### 安全替代：strnlen

POSIX 的 `strnlen(s, maxlen)` 最多扫描 `maxlen` 字节，找到 `\0` 或扫满 `maxlen` 即返回，**有上界**：

```c
size_t len = strnlen(maybe_unterminated, sizeof(buf));
```

注意 MSVC 早期版本不支持 `strnlen`，跨平台代码需自写：

```c
size_t my_strnlen(const char *s, size_t max) {
    size_t i = 0;
    while (i < max && s[i]) i++;
    return i;
}
```

### 二进制报文：始终显式 `size_t len`

HFT/DPDK 的报文长度**永远不要**靠 `strlen` 推断：

```c
/* DPDK 报文：长度由 mbuf 元数据给出 */
size_t pkt_len = rte_pktmbuf_data_len(m);
uint8_t *p = rte_pktmbuf_mtod(m, uint8_t *);
/* 后续操作用 p 和 pkt_len，禁止 strlen(p) */
```

报文长度来自 IP 头 `total_length` 字段或 TCP 段长度，是**协议字段**而非字符串属性。

## HFT 关联

- **FIX tag-value**：变长字段靠 `len` prefix（SOH 分隔但 SOH=0x01 不是 `\0`），`strlen` 仍可用但效率低，生产解析器用偏移表
- **SBE 定长字段**：长度由 schema 编译期确定，运行时根本不调 `strlen`
- **日志缓冲**：构建可读日志时 `strlen(buf)` 算 offset 是常见操作，但要确保 buf 始终 `\0` 终止（`snprintf` 自动补）
- **性能**：glibc `strlen` 在 64 字节内约 5-10 ns，但若每包调 10 次累计 50-100 ns，对 100ns 级 HFT 路径不可忽视
- **ASan 工程铁律**：所有报文处理路径在 ASan 下必须零 `stack-buffer-overflow` 报错，否则上线即定时炸弹
