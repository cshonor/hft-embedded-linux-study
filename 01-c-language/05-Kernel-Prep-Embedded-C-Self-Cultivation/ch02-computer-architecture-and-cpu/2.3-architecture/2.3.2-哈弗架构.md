# 2.3.2 哈佛架构

## 本节讲什么

**指令总线 / 数据总线分离** —— MCU 常见；取指与访存可并行，吞吐更高。

## 要点

| 对比 | 冯·诺依曼 | 哈佛 |
|------|-----------|------|
| 总线 | 指令+数据复用 | **分开** |
| 并行 | 取指时难同时读数据 | 可并行 |
| 典型 | PC、服务器 | **Cortex-M**、DSP |

- 许多 MCU **对外**冯·诺依曼、**片上**哈佛（**2.3.3**）  
- 嵌入式固件常放 **Flash 指令** + **RAM 数据**

## 与后续衔接

**ch03** STM32 类 MCU；**ch10** 外设与内存映射。

## 代码自测

**题目 1：** 哈佛架构为什么比冯诺依曼架构快？有什么代价？

<details>
<summary>参考答案</summary>

快的原因：指令和数据有独立总线，取指和访存可以并行。代价：(1)需要两套总线，硬件复杂；(2)指令和数据空间不共享——程序大小和数据大小各自有限制。ARM Cortex-M 系列采用哈佛架构（指令和数据 L1 Cache 分离）。

</details>
