# 2.8.4 大小端字节序

## 本节讲什么

**Big / Little Endian** —— 多字节在内存中的排布；串口、网络、Flash 必考。

## 要点

```c
uint32_t v = 0x12345678;
/* 小端(x86/ARM LE): 低地址存 0x78
   大端(网络/DSP):   低地址存 0x12 */
```

| 端序 | 低地址字节 |
|------|------------|
| **小端** | 低位字节 |
| **大端** | 高位字节 |

### 检测代码

```c
static int is_little_endian(void)
{
    uint32_t x = 0x01020304;
    return *(uint8_t *)&x == 0x04;
}
```

见 **`demo/demo01_endian.c`**。

### gdb 验证

```bash
gcc -g demo/demo01_endian.c -o demo01_endian
gdb ./demo01_endian
(gdb) break main
(gdb) run
(gdb) x/4xb &v
```

### 工程坑

- 网络协议 **大端** → `htonl/ntohl`  
- 跨 MCU 通信须约定端序  
- 联合体/view 解析错端 → 数值全错  

## 与后续衔接

**ch07** 数据存储；**ch03** ARM 字节访问。

## 代码自测

**题目 1：** 以下代码在小端 ARM 和大端 PowerPC 上分别输出什么？
```c
uint32_t x = 0x12345678;
uint8_t *p = (uint8_t *)&x;
printf("%02x %02x %02x %02x\n", p[0], p[1], p[2], p[3]);
```
<details>
<summary>参考答案</summary>

小端（ARM/x86）：`78 56 34 12`（最低有效字节在最低地址）
大端（PowerPC/网络字节序）：`12 34 56 78`（最高有效字节在最低地址）

判断方法：`if (*(uint8_t *)&x == 0x78)` 则是小端。
网络通信必须统一字节序：`htonl()`/`ntohl()` 转换，因为 TCP/IP 规定网络字节序为大端。

</details>
