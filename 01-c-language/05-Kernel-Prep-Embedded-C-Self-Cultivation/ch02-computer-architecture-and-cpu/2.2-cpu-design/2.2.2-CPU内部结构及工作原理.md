# 2.2.2 CPU 内部结构及工作原理

## 本节讲什么

**寄存器、PC、PSR/FLAGS、总线** —— C 语句在 CPU 内的执行载体。

## 要点

### 通用寄存器

- CPU **唯一零延迟**存储；运算前须 **Load** 进寄存器  
- 分类：数据、地址、**SP/FP**（栈帧，**ch05**）  
- 32/64 位宽决定一次运算与指针宽度  

### PC（Program Counter）

- 存**下一条指令**地址；顺序执行 PC 自增  
- **函数调用/跳转** = 写 PC  

### PSR / FLAGS

| 标志 | 含义 | C 对应 |
|------|------|--------|
| **Z** | 结果为 0 | `if (a==0)` |
| **N** | 负数 | 有符号比较 |
| **C** | 进位 | 无符号溢出 |
| **V** | 溢出 | 有符号溢出 |

- **if/for** 底层：cmp → 条件跳转读 FLAGS（Demo03 **objdump**）

### 一条赋值语句的硬件流

```c
a = b + c;
```

1. Load `b`,`c` → 寄存器  
2. ALU add  
3. Store → `a` 内存地址  

## 实操

`gdb` 单步 + `info registers`；`objdump -d` 看 cmp/je。

## 代码自测

**题目 1：** 以下代码在 CPU 流水线上可能产生什么问题？如何解决？
```c
int data = 0;
void f(void) {
    if (data) { /* A */ }
    data = 1;
}
```
<details>
<summary>参考答案</summary>

分支预测问题：CPU 在执行 `if (data)` 时，data 的值可能还未确定（如果前面有对 data 的 store 操作还在流水线中），导致流水线停顿或预测失败。

流水线冒险类型：
- **数据冒险**：后续指令依赖前序指令的结果
- **控制冒险**：分支指令改变 PC，预取的指令作废
- **结构冒险**：多条指令同时需要同一硬件资源

解决：数据前递（forwarding）、分支预测、流水线暂停（stall）。

</details>
