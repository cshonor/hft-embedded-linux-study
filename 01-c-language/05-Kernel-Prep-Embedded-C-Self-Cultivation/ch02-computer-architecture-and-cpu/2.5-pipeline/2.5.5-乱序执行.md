# 2.5.5 乱序执行

## 本节讲什么

**OoO（Out-of-Order）** —— 在保持 **程序语义** 前提下重排指令，填流水线 bubble。

## 要点

```
保留站 → 执行单元就绪即发射 → 重排序缓冲(ROB) → 按序提交
```

- **提交（commit）** 仍按程序顺序；异常/精确中断点可恢复  
- 隐藏 **Cache miss、长延迟乘除** 带来的停顿  
- 对程序员：**单线程内存模型** 仍复杂（需 memory barrier）；多核见 **2.6**

- DPDK 无锁队列仍依赖 **原子 + barrier**；不能假设源码顺序 = 执行顺序

## 与后续衔接

**2.5.7** 多发射配合 OoO；**ch06** `volatile` / barrier 语义。

## 代码自测

**题目 1：** 乱序执行（OoO）如何提高性能？以下指令序列如何乱序执行？
```
1. LD R1, [R2]    // 慢：访存
2. ADD R3, R4, R5  // 快：ALU
3. MUL R6, R1, R7  // 依赖 R1
```

<details>
<summary>参考答案</summary>

指令 2 不依赖指令 1，可以在指令 1 等待内存时先执行——乱序执行。指令 3 依赖 R1，必须等指令 1 完成。乱序执行通过保留站/重排序缓冲区（ROB）实现——指令可以乱序执行但必须顺序提交（保证精确异常）。这大幅提高了 IPC。

</details>
