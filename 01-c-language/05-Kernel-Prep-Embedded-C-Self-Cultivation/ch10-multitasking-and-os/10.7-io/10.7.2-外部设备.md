# 10.7.2 外部设备

## 本节讲什么

**外部设备** 通过控制器挂到总线上，由 **寄存器组** 控制。本节介绍 **设备驱动分层**、**轮询 vs 中断**、Linux **字符/块/网络驱动** 与 RTOS **HAL** 的对应关系。

## 要点

**驱动分层**（衔接 **ch09**）：

```
app 任务
  │  os_queue / read()
  ▼
driver/uart.c     ← 模块：init, send, irq_handler
  │  MMIO
  ▼
hardware UART IP
```

**访问模式**：

| 模式 | 适用 |
|------|------|
| **轮询** | 简单、bootloader、短超时 |
| **中断** | 异步事件、省 CPU（**10.3**） |
| **DMA** | 大批量传输，CPU 做别的任务 |

**Linux 设备模型**：

```
应用 open("/dev/ttyS0")
  → 内核 tty 层
  → serial_driver ops
  → platform_driver probe(DT)
  → readl/writel 硬件
```

**RTOS HAL**：

- ST HAL `HAL_UART_Transmit_IT` + 回调
- 与 **demo06_mini_rtos** 的 `bsp/uart` + `kernel/queue` 同构

**设备树描述**（Linux）：

- `compatible` 匹配驱动；`reg` 基址；`interrupts` 线号
- 与裸机 `#define UART_BASE` 信息等价，可自动生成头文件（**pinctrl**）

**并发注意**：

- 同一 UART 多任务打印 → **mutex 或 log queue**（**demo05_queue**）
- ISR 与任务共享 ringbuf → **临界区** 或 **无锁 SPSC**（单生产者单消费者）

## 代码自测

**题目 1：** 以下代码操作 GPIO 点灯，为什么需要先使能时钟？
```c
// STM32 HAL 风格
__HAL_RCC_GPIOA_CLK_ENABLE();  // 先使能 GPIOA 时钟

GPIOA->MODER &= ~(3 << (5*2));
GPIOA->MODER |=  (1 << (5*2));  // PA5 输出模式
GPIOA->ODR |= (1 << 5);        // PA5 输出高电平
```
<details>
<summary>参考答案</summary>

如果不使能时钟，对 GPIOA 寄存器的写入不生效（寄存器值不变），GPIO 不会有输出。

原因：ARM SoC 为了降低功耗，每个外设都有独立的时钟使能位。时钟关闭时，外设内部寄存器不接收任何写操作，总线无响应。

这是嵌入式开发的常见陷阱：操作任何外设前必须先使能其时钟。流程是：查阅芯片手册找到对应外设的时钟使能寄存器（如 RCC_AHB1ENR），设置对应 bit，等待几个时钟周期确保稳定，然后才能正常读写外设寄存器。

</details>
