# 7.6.4 使用枚举需要注意的地方

## 本节讲什么

枚举提升可读性，但不能替代**输入校验**与**完整性检查**。从用户态、寄存器、网络包读入的值可能落在枚举定义之外；`switch` 缺少 `default` 会导致静默错误。本节汇总驱动开发中的 enum 防守式用法。

## 要点

| 陷阱 | 对策 |
|------|------|
| 未定义枚举值 | `default:` 分支日志 + 错误码 |
| 用作位掩码 | 勿用连续 enum，改用 `#define FL_FOO BIT(0)` |
| sizeof 假设 | 协议字段用 `uint8_t` 存，不假设 enum 1 字节 |
| 跨模块数值依赖 | 公共头文件单一来源 |

```c
int handle_op(op_t op) {
    if (op < 0 || op >= OP_COUNT)
        return -EINVAL;
    return jump_table[op](a, b);
}

switch (st) {
case DRV_IDLE:
case DRV_ACTIVE:
    break;
default:
    pr_err("bad state %d\n", st);
    return -EIO;
}
```

```c
/* 不要 */
enum flags { F_READ = 1, F_WRITE = 2, F_RDWR = 3 }; /* 非位标志 */

/* 要 */
#define F_READ  BIT(0)
#define F_WRITE BIT(1)
```

- **编译器 `-Wswitch`**：遗漏 case 告警（依赖 enum 范围分析）
- **JSON/配置解析**：字符串 → enum 映射表，非法串拒绝
- **与函数指针表**：下标必须 `< OP_COUNT` → **demo04**

## 代码自测

**题目 1：** 以下枚举使用有什么问题？
```c
// 问题1
enum { A, B, C };
enum { B, D, E };  // B 重复

// 问题2
enum flag { FLAG_A = 0x01, FLAG_B = 0x02 };
enum flag f = FLAG_A | FLAG_B;  // 结果是 0x03，不在枚举范围内

// 问题3
enum big { VAL = 0xFFFFFFFF };  // 在 16 位系统上溢出
```
<details>
<summary>参考答案</summary>

问题 1：**名称冲突**。两个匿名枚举都定义了 B，在同一作用域内编译错误。

问题 2：**位运算不在枚举范围内**。`FLAG_A | FLAG_B = 0x03`，但 enum flag 没有值 3。C 不检查范围，但逻辑上 0x03 不是一个有效的 enum flag 值。位标志应该用 `#define` 或 `unsigned int` 而非 enum。

问题 3：**平台依赖**。enum 的底层类型是 int，16 位系统上 int 是 16 位，0xFFFFFFFF 超出范围。用 `UINT32_C(0xFFFFFFFF)` 或 `#define`。

其他注意事项：
- 不要依赖 enum 的具体数值（可能跨版本变化），用名称
- 不要序列化 enum 的数值到文件/网络（不同编译器/版本可能不同）
- 跨平台代码中 enum 大小不确定，用 `uint32_t` 存储序列化的值

</details>
