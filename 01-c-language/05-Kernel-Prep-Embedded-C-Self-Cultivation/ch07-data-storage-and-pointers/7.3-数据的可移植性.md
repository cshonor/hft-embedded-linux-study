# 7.3 数据的可移植性

## 本节讲什么

同一份 C 源码在不同 CPU、编译器、ABI 下，类型宽度、`int`/`long`/指针关系、对齐与字节序可能不同。**可移植**代码不依赖实现细节，而用标准定宽类型与显式转换。内核通过 `arch/`、`include/linux/types.h` 抽象平台差异；DPDK 通过 `rte_*` 类型与编译目标固定环境。

## 要点

| 不可移植假设 | 可移植替代 |
|--------------|------------|
| `int` 32 位 | `int32_t` |
| `long` 与指针同宽 | `intptr_t` / `uintptr_t` |
| `enum` 1 字节 | 显式 `uint8_t` 字段 |
| 结构体无 padding | `packed` + 文档化 或 序列化函数 |

```c
#include <stdint.h>
#include <stddef.h>

/* POSIX / Linux 内核风格 */
typedef uint8_t  u8;
typedef uint32_t u32;
typedef uintptr_t dma_addr_t;  /* 平台相关，头文件封装 */
```

**ABI 影响**：

- 结构体成员对齐、调用约定、参数传递
- `bool`/`wchar_t` 宽度
- 位域顺序与填充

```bash
# 32 位 vs 64 位对比 sizeof
gcc -m32 -dM -E - < /dev/null | grep SIZEOF
gcc -m64 -dM -E - < /dev/null | grep SIZEOF
```

- **`limits.h` / `stdint.h`**：编译期常量 `UINT32_MAX`、`SIZE_MAX`
- **序列化**：网络/磁盘格式用**大端 + 定宽**，与主机布局脱钩
- **条件编译**：`#if __SIZEOF_POINTER__ == 8` 仅作最后手段

## 代码自测

**题目 1：** 如何编写可移植的 C 代码？以下代码在 32/64 位系统上有什么问题？
```c
long size = 0;
int *p = malloc(n * sizeof(int));
size = (long)p;
printf("addr = %lx\n", size);
```
<details>
<summary>参考答案</summary>

问题：
1. `long` 在 64 位 Windows（LLP64）是 4 字节，存不下 8 字节指针 → 截断
2. `(long)p` 将指针转整数，应该用 `uintptr_t` 保证能容纳指针
3. `malloc` 返回值未检查 NULL

可移植代码：
```c
#include <stdint.h>
uintptr_t addr = (uintptr_t)p;
printf("addr = %" PRIxPTR "\n", addr);
```

可移植原则：
1. 用 `stdint.h` 固定宽度类型（`uint32_t` 而非 `unsigned long`）
2. 用 `size_t` 表示大小/长度（而非 `int`）
3. 用 `uintptr_t` 存储指针值
4. 用 `PRIxxx` 宏打印（`PRId32`/`PRIu64`）
5. 不依赖 `int`/`long`/`指针` 的大小关系
6. 注意字节序和对齐差异

</details>
