3.6

C语言和汇编语言混合编程

本节讲什么

同一工程内 C 调汇编、汇编调 C、C 内嵌汇编 三种路径；须共同遵守 AAPCS/ATPCS 调用约定，否则参数、返回值、栈帧错乱——内核 asm/ 与驱动里极常见。

代码自测

题目 1： C 和汇编混合编程有哪几种方式？各适用什么场景？

参考答案

三种主要方式：

  1. 内联汇编（Inline Assembly）：C 函数中直接嵌入汇编，用 asm/__asm__ 关键字。适用于少量特殊指令（如 MSR/CP15 操作寄存器、内存屏障）。

  2. C 调汇编：C 中声明 extern 函数，汇编中用 .global 导出。适用于性能关键路径的手写优化。

  3. 汇编调 C：汇编中按 ATPCS 约定传参（R0-R3），BL 调用 C 函数。适用于启动代码（如 U-Boot 的 _start 调用 C 的 board_init）。

内核中常见内联汇编：读写系统寄存器、原子操作、内存屏障。

3.6

.1 ATPCS规则

本节讲什么

ATPCS（ARM-Thumb Procedure Call Standard），GNU/Linux 上即 AAPCS：规定函数调用时 寄存器分工、栈方向、栈帧布局——混合编程的核心契约。

要点

寄存器约定

寄存器 角色
R0–R3 参数 / 返回值（≤4 字）；多余参数入栈
R4–R11 被调者保存（callee-saved）
R12 (IP) 临时 / 跳板
R13 (SP) 栈指针，满递减（向下生长）
R14 (LR) 返回地址
R15 (PC) 程序计数器

栈帧示例：int add(int a, int b)（C 编译）

add:
    push    {fp, lr}        @ 保存帧指针与返回地址
    add     fp, sp, #4      @ fp 指向旧 sp
    sub     sp, sp, #8      @ 局部空间（若需要）
    str     r0, [fp, #-8]   @ 存参数 a（编译器可选）
    str     r1, [fp, #-12]  @ 存参数 b
    ldr     r2, [fp, #-8]
    ldr     r3, [fp, #-12]
    add     r0, r2, r3        @ 返回值 → r0
    sub     sp, fp, #4
    pop     {fp, pc}        @ 恢复并返回

手写 add_asm 极简版（demo）

add_asm:
    add r0, r0, r1    @ 参数已在 r0,r1；结果 r0
    bx  lr            @ 调用者保存 r0-r3，我们不碰 r4-r11
  • leaf 函数可不建立帧指针，不碰 callee-saved 即可 bx lr
  • 内核 __switch_to 等必须完整保存 callee-saved + SP

  • ch05 画栈图；3.6.2 内联 asm 破坏寄存器须声明

代码自测

题目 1： ATPCS（ARM-Thumb Procedure Call Standard）的寄存器使用约定是什么？以下 C 函数的参数如何传递？

int add(int a, int b, int c, int d, int e) {
    return a + b + c + d + e;
}
参考答案

ATPCS 寄存器约定： - R0-R3：参数寄存器（传前 4 个参数），也是返回值寄存器（R0） - R4-R11：被调用者保存（callee-saved），函数内使用前必须 push - R12 (IP)：临时寄存器（caller-saved） - R13 (SP)：栈指针 - R14 (LR)：返回地址 - R15 (PC)：程序计数器

该函数 5 个参数：a→R0, b→R1, c→R2, d→R3, e→栈。返回值在 R0。超过 4 个参数用栈传递。

3.6

.2 在C程序中内嵌汇编代码

本节讲什么

GCC asm / __asm__ 把 ARM 指令嵌入 C；volatile 禁止优化删除/重排；约束 描述操作数与寄存器对应——内核 read_cpuid、wfe、dmb 的实现方式。

要点

int add_inline(int a, int b)
{
    int sum;
    asm volatile (
        "add %0, %1, %2"
        : "=r" (sum)           /* 输出 */
        : "r" (a), "r" (b)     /* 输入 */
        : "cc"                 /* 破坏标志位 */
    );
    return sum;
}
要素 含义
volatile 有副作用，勿删勿挪
"=r" 写寄存器输出
"r" 读寄存器输入
"cc" / "memory" clobber 标志 / 内存 
/* 内核风格：内存屏障 */
#define barrier() asm volatile("" ::: "memory")
  • 多语句用 \n\t 连接；勿随意写 clobber，否则优化错误
  • DPDK rte_rmb() 等平台屏障在 ARM 上常为 dmb ish 内联汇编

与后续衔接

  • ch06 扩展语法 asm goto、输入输出修饰符
  • 3.7.1 编译器与汇编分工

代码自测

题目 1： 以下内联汇编代码的作用是什么？输出操作数和输入操作数分别是什么？

int result;
__asm__ volatile (
    "MRS %[res], CPSR"  // 指令
    : [res] "=r" (result)  // 输出
    : // 输入
    : // clobber
);
参考答案

该代码读取当前程序状态寄存器（CPSR）到 C 变量 result。

  • MRS %[res], CPSR：将 CPSR 读入指定寄存器
  • [res] "=r" (result)：输出操作数，%[res] 是占位符，"=r" 表示输出到任意寄存器，(result) 绑定到 C 变量
  • volatile：禁止编译器优化掉这条汇编（读 CPSR 有副作用）

内联汇编格式：asm volatile("指令" : 输出 : 输入 : clobber)。内核中用于操作 CP15/系统寄存器。

3.6

.3 在汇编程序中调用C程序

本节讲什么

启动代码、异常向量或裸机 reset 里用 bl main 跳入 C 世界；须先初始化 栈 SP、BSS，并遵守 AAPCS 传参。

要点

    .global _start
    .type _start, %function
_start:
    ldr sp, =stack_top      @ 必须：C 需要有效栈
    bl  main                @ 进入 C
    b   .                   @ main 返回后死循环

    .bss
    .space 4096
stack_top:

    mov r0, #3              @ main(int argc, ...) 可设 r0
    mov r1, #0
    bl  main
  • bl printf 等同理；C 运行时可能依赖 _start → __libc_start_main
  • 裸机链接脚本把 stack_top 放在 RAM 顶端
  • U-Boot 跳内核前设好寄存器（ATAGs/DTB 指针曾用 r0–r2）

与后续衔接

  • ch04 链接脚本 ENTRY(_start)；ch10 OS 启动流程

代码自测

题目 1： 以下汇编代码如何调用 C 函数？需要遵守什么约定？

// C 函数
int add(int a, int b) { return a + b; }

// 汇编调用
    MOV R0, #10     @ 第一个参数
    MOV R1, #20     @ 第二个参数
    BL add          @ 调用
    // R0 现在是返回值 30
参考答案

汇编调用 C 函数必须遵守 ATPCS/ABI 约定： 1. 参数传递：前 4 个参数放 R0-R3，更多参数压栈 2. 调用：BL 函数名（自动保存返回地址到 LR） 3. 返回值：C 函数返回值在 R0 4. 寄存器保存：C 函数会自动保存 R4-R11，R0-R3 可能被修改

本例：R0=10, R1=20 传参 → BL add 调用 → 返回后 R0=30。

注意：调用前确保栈指针 SP 有效（如果 C 函数用到栈），R0-R3 的值调用后不保证保留。

题目 1： GNU 汇编器和 ARM 标准汇编器的主要语法差异是什么？

// GNU

题目 1： 以下 C 代码编译为 ARM 汇编后大概是什么样？

int add(int a, int b) { return a + b; }
参考答案 
add:
    ADD R0, R0, R1  ; R0 = a + b
    BX LR           ; 返回

ARM 调用约定：参数通过 R0-R3 传递，返回值在 R0。a 在 R0, b 在 R1，加法结果放 R0，BX LR 返回。函数 prologue/epilogue 被省略（叶子函数不需要保存寄存器）。编译器可以优化掉帧指针。

3.7

.2 GNU ARM编译器的伪操作

本节讲什么

GNU as 特有伪操作：控制 ARM/Thumb、literal 池、CPU 特性——写启动代码与内联汇编外围 .S 时常用。

要点

.syntax unified
.arm                    @ 后续为 ARM 32 位指令
.thumb                  @ Thumb-2
.ltorg                  @ 在此放置 literal pool
.cpu cortex-a7
.fpu vfpv3-d16

.ltorg 防止 ldr = 跳转过远
.arm / .thumb 切换指令集
.code 32 / .code 16 同义切换
.fnstart / .fnend 栈展开元数据（异常处理）

代码自测

题目 1： GNU ARM 汇编器和 ARM 汇编器的伪操作有什么差异？以下 GNU 伪操作的含义是什么？

.section .text        @ ?
.align 4              @ ?
.type func, %function  @ ?
.size func, 16         @ ?
参考答案

GNU 汇编器（GAS）和 ARM 汇编器（armasm）伪操作不同： - ARM: AREA |text|, CODE, READONLY vs GNU: .section .text - ARM: ALIGN vs GNU: .align 4（4 表示 2^4=16 字节对齐） - ARM: 无类型声明 vs GNU: .type/.size

  • .section .text：声明代码段
  • .align 4：4 字节对齐（ARM 上 .align n = 2^n 对齐，x86 上 .align n = n 字节对齐）
  • .type func, %function：标记 func 为函数类型（调试信息）
  • .size func, 16：标记 func 大小为 16 字节（调试信息）

内核代码用 GNU 汇编语法。

3.7

.3 GNU ARM汇编语言中的标号

本节讲什么

GNU 标号规则：局部标号 1:/2:、向前/向后引用 1f/1b，减少无意义全局符号。

要点

1:  subs r0, r0, #1
    bne 1b                 @ 向后跳到标号 1
2:  add r1, r1, #4
    cmp r1, r2
    blt 2b
  • 局部标号可重复；用 3f 指向下一个 3:，3b 指向上一个
  • 全局标号须以字母或 _ 开头；数字单独为局部
  • ENTRY(irq_handler) 生成全局 irq_handler 供向量表引用

与后续衔接

代码自测

题目 1： 以下 GNU 汇编代码中标号的作用是什么？

loop:
    ADD R0, R0, #1
    CMP R0, #10
    BNE loop
参考答案

标号 loop 标记代码位置，BNE loop 跳转回标号处。标号是地址的符号名——编译时替换为相对地址偏移。循环逻辑：R0 从 0 开始每次加 1，直到 R0 == 10 退出。局部标号可以用数字（如 1:、2:），用 BNE 1b 引用（b=backward, f=forward）。

3.7

.4 .section伪操作

本节讲什么

.section / .text / .data / .bss / .rodata 把代码与数据分入 ELF 段，链接脚本按段布置到 Flash/RAM。

要点

    .section .text.boot, "ax", %progbits
    .section .data.cacheline_aligned, "aw", %progbits
    .previous
    .pushsection .rodata
    .popsection
段 典型内容
.text 代码
.rodata 常量、字符串
.data 已初始化全局变量
.bss 未初始化，占址不占 ROM
  • 内核 __cacheline_aligned 把 per-CPU 变量放入对齐段
  • DPDK __rte_cache_aligned 同理，避免 false sharing

与后续衔接

题目 1： 以下 GNU 汇编代码中 .section 的作用是什么？

参考答案

.section 指定后续代码/数据放入哪个段。.text 是代码段（只读），.data 是已初始化数据段（可读写），.bss 是未初始化数据段。段是链接器组织程序的基本单位——不同段有不同的属性（读/写/执行权限）。ELF 文件由多个段组成。

代码自测

题目 1： 分析以下 U-Boot 启动汇编代码的功能：它完成了什么操作？

_start:
    LDR R0, =0x70000000
    ORR R0, R0, #0x13
    MCR p15, 0, R0, c1, c0, 0
参考答案

该代码配置 ARM 的协处理器 CP15 来设置系统控制：

  1. LDR R0, =0x70000000：加载常量到 R0
  2. ORR R0, R0, #0x13：R0 |= 0x13（设置位 0,1,4）
  3. MCR p15, 0, R0, c1, c0, 0：写 R0 到 CP15 的系统控制寄存器（SCTLR）

位 0 = MMU 使能，位 1 = 对齐检查，位 4 = D-cache 使能。0x13 = MMU on + 对齐检查 + D-cache on。MCR = Move to Coprocessor Register，从 ARM 寄存器写到协处理器。

这是典型的裸机/启动代码：直接操作 CP15 系统寄存器。

3.8

AArch64拓展

本节讲什么

AArch64（ARMv8+ 64 位执行状态）是服务器、树莓派 3/4、Ampere 等 Linux/DPDK 主流平台。与 ARM32 相比：固定 64 位指令、31 个 64 位通用寄存器、无 Thumb、异常级别 EL0–EL3。

要点

寄存器 X0–X30

寄存器 别名 用途
X0–X7 — 参数 / 返回值（可传 8 个）
X8 — 间接结果 / syscall 号
X9–X15 — 临时（调用者保存）
X16–X17 IP0/IP1 跳板 / PLT
X18 — 平台保留（内核 per-CPU）
X19–X28 — 被调者保存
X29 FP 帧指针
X30 LR 链接寄存器
— SP 栈指针（独立编码）
— PC 独立，非通用寄存器
  • 访问低 32 位写 Wn（零扩展）；如 W0 为 X0 低半部
  • 无 CPSR 条件执行全场：条件分支用显式 b.eq 等

与 ARM32 对照

@ ARM32
mov r0, #1
bl  func
bx  lr

// AArch64
mov x0, #1
bl  func
ret                          @ 等价 bx lr

ldr x0, [x1, #8]             @ 64 位加载
add x2, x0, x1, lsl #3

无 Thumb

  • AArch64 仅 A64 指令集，无 16/32 位 Thumb 混编；简化取指与工具链
  • 32 位用户态程序在 AArch64 CPU 上通过 AArch32 兼容（可选，独立工具链 arm-linux-gnueabihf）

工具链与内核

aarch64-linux-gnu-gcc -c foo.S
aarch64-linux-gnu-objdump -d foo.o
  • Linux 内核 arch/arm64/、entry.S 用 ELx 切换
  • DPDK 在 ARM64 上 mbuf/ring 热点多为 NEON + 64 位 load pair

与后续衔接

  • 3.1 ARM32 模式 → AArch64 EL 与 3.9 异常向量
  • ch04 AArch64 重定位类型不同；ch10 SMP 启动 cpu_on

代码自测

题目 1： AArch64（ARMv8）相比 AArch32（ARMv7）有哪些主要变化？对 C 编程有什么影响？

参考答案

AArch64 主要变化： - 寄存器：31 个 64 位通用寄存器 X0-X30（AArch32 只有 16 个 32 位 R0-R15） - 指令长度：固定 32 位（与 AArch32 相同），但操作 64 位数据 - 调用约定：X0-X7 传参（8 个，AArch32 只有 4 个），X0 返回值 - 栈指针：SP 专用寄存器，不再与 R13 共用 - LR：X30 专用，不再与 R14 共用

对 C 编程影响：long/指针 在 AArch64 是 8 字节（LP64 模型），AArch32 是 4 字节（ILP32）。跨平台代码需用 uintptr_t/size_t 而非 int/unsigned long。
