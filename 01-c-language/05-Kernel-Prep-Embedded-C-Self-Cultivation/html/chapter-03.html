3.1

ARM体系结构

本节讲什么

ARM 是 RISC load-store 架构：运算只在寄存器间进行，访存须通过 LDR/STR。本章以 ARM32（AArch32） 为主（arm-linux-gnueabihf 工具链），并对比 AArch64（3.8）。理解 7 种处理器模式、CPSR/SPSR 与 R0–R15，是读内核启动代码、DPDK 绑核汇编和异常现场的基础。

要点

RISC 与 load-store

  • CISC：内存操作数可直接参与运算（如 x86 add [mem], eax）
  • ARM：add r0, r1, r2 只在寄存器间运算；读写内存必须 ldr/str
  • 好处：指令规整、流水线友好；代价：更多显式 load/store

ARM32 vs AArch64

维度 ARM32 (AArch32) AArch64
通用寄存器 R0–R15，32 位 X0–X30，64 位
指令集 ARM / Thumb-2 单一 A64，无 Thumb
模式 7 种处理器模式 EL0–EL3 异常级别
Linux 用户态 arm-linux-gnueabihf aarch64-linux-gnu

7 种处理器模式（ARM32）

模式 缩写 典型用途
User usr 应用程序、DPDK 用户态轮询
FIQ fiq 快速中断（旧平台）
IRQ irq 普通外设中断
Supervisor svc 系统调用、Bootloader
Abort abt 数据/指令预取异常
Undefined und 未定义指令
System sys 特权，与用户共享寄存器

模式切换时部分寄存器 banked（如 FIQ 的 R8–R14）；User 模式无法直接改 CPSR。

CPSR / SPSR

  • CPSR（Current Program Status Register）：N Z C V 标志位 + T（Thumb）+ 模式位
  • SPSR（Saved PSR）：异常/中断入口时硬件保存旧 CPSR，返回用 subs pc, lr, #4 恢复
  • 内核 entry-armv.S、中断向量表都围绕 CPSR/SPSR 现场切换

R0–R15 与别名

寄存器 别名 作用
R0–R12 — 通用；AAPCS：R0–R3 传参/返回值，R4–R11 被调者保存
R13 SP 栈指针；每种模式可有独立 SP
R14 LR 链接寄存器；BL 保存返回地址
R15 PC 程序计数器；ARM 状态 PC 低 2 位为 0 
mov r0, #3        @ 第一个参数
mov r1, #5        @ 第二个参数
bl  add_asm        @ LR = 返回地址，结果在 r0

与 x86 的差异（嵌入式/DPDK 视角）

  • 条件执行：ARM32 几乎所有指令可带条件码（3.2.6），减少分支
  • 对齐：未对齐访问可能触发 Abort；DPDK rte_memcpy 等会考虑对齐
  • 端序：多数 ARM SoC 小端；网络字节序仍须 htonl

题目 1： ARM 处理器的 RISC 设计有哪些核心特征？与 x86 CISC 相比对 C 编程有什么影响？

参考答案

ARM RISC 核心特征： - Load-Store 架构：只有 LDR/STR 指令访问内存，运算指令只操作寄存器 - 固定长度指令：ARM 模式 32 位，Thumb 模式 16 位 - 大量通用寄存器：R0-R15 共 16 个（x86 只有 8 个通用寄存器） - 条件执行：几乎所有指令可带条件后缀（如 MOVEQ）

3.2

ARM汇编指令

本节讲什么

ARM32 指令按功能分为 存储访问、数据传送、算术逻辑、比较、条件执行、跳转 六类。运算遵循 load-store：先 ldr 取数，再 add/cmp，最后 str 写回。读懂这些指令，才能对照 objdump -d 反汇编内核/DPDK 热点函数。

要点

指令分类总览

类别 代表指令 小节
存储访问 ldr str ldm stm 3.2.1
数据传送 mov mvn 3.2.2
算术逻辑 add sub and orr eor 3.2.3
操作数扩展 #imm Rm 移位 3.2.4
比较 cmp cmn tst 3.2.5
条件执行 addeq movne … 3.2.6
跳转 b bl bx 3.2.7

典型片段：两数相加写回

ldr r1, [r0]          @ 从 r0 指向的地址读
add r2, r1, #1        @ r2 = r1 + 1
str r2, [r0]          @ 写回

调用约定预览

mov r0, #3
mov r1, #5

                      @ r0 = 返回值，bx lr 返回

内核/DPDK 常见模式

  • 批量访存：ldm/stm 保存/恢复寄存器现场（3.2.1、3.9）
  • 无分支优化：cmp + 条件 mov 代替 b（3.2.6）
  • 内联汇编：asm volatile 中常用 mov/mcr/mrc（3.6.2）

题目 1： 以下 ARM 汇编指令各完成什么操作？

MOV R0, #5      @ ?
ADD R1, R0, #3   @ ?
LDR R2, [R0]     @ ?
STR R1, [R0, #4] @ ?
CMP R0, R1       @ ?
参考答案
  • MOV R0, #5：R0 = 5（立即数赋值）
  • ADD R1, R0, #3：R1 = R0 + 3 = 8

  • CMP R0, R1：比较 R0 和 R1，设置 CPSR 标志位

ARM 是 Load-Store 架构：运算只在寄存器间进行，访问内存必须用 LDR/STR。

3.2

.1 存储访问指令

本节讲什么

LDR/STR 在寄存器与内存间搬运数据；LDM/STM 一次访问多个寄存器，用于函数序言/尾声和中断现场保存。

要点

ldr r0, [r1]              @ r0 = *r1
ldr r0, [r1, #4]          @ 基址+偏移
str r0, [r1, #4]!         @ 写后 r1 += 4（前变址）
ldrb r0, [r1]             @ 字节加载
ldrh r0, [r1]             @ 半字

stmfd sp!, {r4-r11, lr}   @ 入栈：满递减栈
ldmfd sp!, {r4-r11, pc}   @ 出栈并返回（pc 代替 lr）
  • B：字节；H：半字；无后缀为字（32 位）
  • ! 表示写回基址；{} 内寄存器列表顺序影响存储布局
  • 内核异常入口常用 stmfd sp, {r0-r12, lr} 压栈

与后续衔接

  • 寻址形式见 3.3；批量寻址 3.3.6
  • 3.6.1 栈帧建立依赖 stmfd/ldmfd
  • 3.9 中断上下文保存用 stm 系列

代码自测

题目 1： 以下 ARM 汇编指令实现了什么操作？LDR 和 STR 的区别是什么？

LDR R0, [R1]      ; A
STR R0, [R1, #4]  ; B
参考答案

A：从 R1 指向的地址加载 4 字节到 R0（Load）。B：将 R0 的值存储到 R1+4 指向的地址（Store）。LDR/STR 是 ARM 中唯一的内存访问指令（加载/存储架构）。[R1] 是寄存器间接寻址，[R1, #4] 是基址加偏移寻址。

3.2

.2 数据传送指令

本节讲什么

MOV/MVN 在寄存器间或立即数到寄存器之间传送数据，不访问内存——load-store 架构中最常用的「赋值」手段。

要点

mov r0, #10           @ r0 = 10（8 位旋转立即数）
mov r0, r1            @ r0 = r1
mov r0, r1, lsl #2    @ r0 = r1 << 2
mvn r0, #0            @ r0 = ~0 = 0xFFFFFFFF
  • MOV 目标、源；源可为 operand2（3.2.4）
  • 立即数受 ARM 编码限制，大常数用 3.4.1 LDR 伪指令
  • MOV PC, LR 已废弃；返回用 bx lr 或 pop {pc}

与后续衔接

  • 参数装载：mov r0, #n 配合 3.6.1 AAPCS
  • 内联汇编 asm("mov %0, #1" : "=r"(x)) 见 3.6.2

代码自测

题目 1： 以下 ARM 指令中 MOV 和 MVN 的区别是什么？

MOV R0, #0xFF     ; A
MVN R0, #0xFF     ; B
参考答案

A：R0 = 0xFF（直接传送）。B：R0 = ~0xFF = 0xFFFFFF00（取反传送）。MVN 是 Move Not——先取反再传送。ARM 的 MOV 指令对立即数有限制——只有能通过 8 位值偶数循环右移得到的 32 位立即数才能直接编码。

3.2

.3 算术逻辑运算指令

本节讲什么

ADD/SUB/AND/ORR/EOR 等在寄存器上完成算术与位运算；可带 S 后缀更新 CPSR 标志位，供条件执行使用。

要点

add r0, r1, r2        @ r0 = r1 + r2
adds r0, r1, #1       @ 加并更新 N,Z,C,V
sub r2, r1, r3, lsr #1 @ r2 = r1 - (r3>>1)
and r0, r0, #0xFF     @ 掩码低 8 位
orr r0, r0, r1        @ 按位或
eor r0, r0, r1        @ 按位异或
  • 三操作数格式：OP Rd, Rn, operand2
  • S 后缀：结果写 CPSR；cmp 本质是 subs 丢弃写回（3.2.5）
  • DPDK 位图、掩码操作在反汇编中常见 and/orr

与后续衔接

  • operand2 移位/立即数见 3.2.4
  • 带条件：addeq 等 3.2.6

代码自测

题目 1： 以下 ARM 指令中 ADDS 和 ADD 的区别是什么？

ADD R0, R1, R2    ; A
ADDS R0, R1, R2   ; B
参考答案

A：R0 = R1 + R2，不影响标志位。B：R0 = R1 + R2，更新 N/Z/C/V 标志位。S 后缀表示更新 CPSR 中的标志位——后续指令可以根据结果做条件判断。ADDS 后跟条件分支是常见的模式。

3.2

.4 操作数：operand2详解

本节讲什么

ARM 数据 processing 指令的第三操作数 operand2 可以是立即数、寄存器，或 带移位的寄存器——一条指令内完成「运算+移位」，减少指令条数。

要点

add r0, r1, #0x100        @ 立即数（8 位旋转）
add r0, r1, r2            @ 寄存器
add r0, r1, r2, lsl #2    @ r2 逻辑左移 2 位后相加
add r0, r1, r2, lsr #4    @ 逻辑右移
add r0, r1, r2, asr #1    @ 算术右移
add r0, r1, r2, ror #8    @ 循环右移
  • 立即数：8 位值 + 4 位旋转量；不是任意 32 位数 → 用 ldr =label
  • 移位量 0–31；lsl #32 等价为 0
  • 编译器调度：*8 常编译为 lsl #3

与后续衔接

  • 大立即数 3.4.1；寻址中同类移位 3.3.3

代码自测

题目 1： ARM 的 operand2 有哪些形式？以下指令合法吗？

ADD R0, R1, #0x12345678
参考答案

operand2 可以是：(1)立即数 #imm（受限）；(2)寄存器 Rm；(3)寄存器移位 Rm, LSL #n。该指令不合法——ARM 的立即数编码方式要求值能由 8 位数循环右移偶数次得到。0x12345678 不满足此条件。用 LDR 伪指令加载大立即数：LDR R0, =0x12345678。

3.2

.5 比较指令

本节讲什么

CMP/CMN/TST/TEQ 做减法或位运算但不写回结果，只更新 CPSR 标志位，驱动后续条件执行或分支。

要点

cmp r0, r1            @ 等价 subs r0, r0, r1（丢弃写回）
cmp r0, #10
cmn r0, r1            @ 比较 -r1（adds 不写回）
tst r0, #0x1          @ 测试最低位（ands 不写回）
beq label             @ Z=1 则跳转
bgt label             @ 有符号大于
标志 含义
N 负数
Z 零
C 进位/无符号借位
V 有符号溢出

与后续衔接

  • 条件码后缀 3.2.6；分支 3.2.7
  • C 中 if (a > b) 编译为 cmp + ble/bgt

代码自测

题目 1： CMP 指令做了什么操作？以下代码后 EQ 标志什么时候为真？

CMP R0, R1
BEQ label
参考答案

CMP R0, R1 计算 R0 - R1 但不保存结果，只更新标志位。如果 R0 == R1，Z 标志置 1，BEQ（Branch if Equal）跳转到 label。CMP 实际上是 SUBS 的别名（减法但不写回结果）。条件分支依赖前一条指令设置的标志位。

3.2

.6 条件执行指令

本节讲什么

ARM32 几乎所有指令可带 条件码后缀，仅在 CPSR 标志满足时执行——用 cmp + 条件 mov 代替分支，减少流水线冲刷（AArch64 已弱化此特性）。

要点

cmp r0, r1
movgt r2, #1          @ r0>r1（有符号）时 r2=1
moveq r2, #0          @ 相等时 r2=0
addeq r0, r0, #1      @ Z=1 时加 1
后缀 条件
eq/ne 相等/不等
gt/lt/ge/le 有符号比较
hi/ls 无符号高于/低于
mi/pl 负/正
  • 默认后缀 AL（总是执行）可省略
  • 内核早期手写汇编常用；现代 C 编译器仍对简单 cmov 模式生成条件指令

与后续衔接

  • 与 3.2.7 分支互补；3.9 异常返回用条件 subs pc

题目 1： ARM 的条件执行是 RISC 架构的独特特性。以下代码有什么优势？

CMP R0, #0
MOVGT R1, #1     ; R0 > 0 时执行
MOVLE R1, #0     ; R0 <= 0 时执行
参考答案

条件执行避免了分支指令——两条 MOV 根据 CMP 设置的标志位选择性执行。优势：(1)避免分支预测失败的开销；(2)代码更紧凑；(3)流水线不断流。几乎所有 ARM 指令都可以加条件后缀（EQ/NE/GT/LT/GE/LE 等），这是 ARM 区别于其他 RISC 的特色。

BL 分支并链接（调用）

本节讲什么

题目 1： 以下 ARM 指令实现了什么操作？

题目 1： 以下 ARM 代码中 B 指令使用什么寻址方式？

  • LSL #2：第二操作数（operand2，R1 逻辑左移 2 位）
  • @：注释（GNU 汇编用 @，ARM 汇编器用 ;）

该指令：若 Z=1，则 R0 = R1 << 2。

3.6

.1 ATPCS规则

本节讲什么

ATPCS（ARM-Thumb Procedure Call Standard），GNU/Linux 上即 AAPCS：规定函数调用时 寄存器分工、栈方向、栈帧布局——混合编程的核心契约。

要点

寄存器约定

寄存器 角色
R0–R3 参数 / 返回值（≤4 字）；多余参数入栈
R4–R11 被调者保存（callee-saved）
R12 (IP) 临时 / 跳板
R13 (SP) 栈指针，满递减（向下生长）
R14 (LR) 返回地址
R15 (PC) 程序计数器

栈帧示例：int add(int a, int b)（C 编译）

add:
    push    {fp, lr}        @ 保存帧指针与返回地址
    add     fp, sp, #4      @ fp 指向旧 sp
    sub     sp, sp, #8      @ 局部空间（若需要）
    str     r0, [fp, #-8]   @ 存参数 a（编译器可选）
    str     r1, [fp, #-12]  @ 存参数 b
    ldr     r2, [fp, #-8]
    ldr     r3, [fp, #-12]
    add     r0, r2, r3        @ 返回值 → r0
    sub     sp, fp, #4
    pop     {fp, pc}        @ 恢复并返回

A：加载 1 字节（Byte）到 R0，高位补零。B：加载 2 字节（Halfword）到 R0。C：加载 4 字节（Word）到 R0。还有 LDRSB/LDRSH（有符号扩展）。对应存储指令：STRB/STRH/STR。数据宽度匹配在内存映射 IO 中非常重要——读错误宽度可能产生错误结果。

题目 1： 分析以下 U-Boot 启动汇编代码的功能：它完成了什么操作？

_start:
    LDR R0, =0x70000000
    ORR R0, R0, #0x13
    MCR p15, 0, R0, c1, c0, 0
参考答案

该代码配置 ARM 的协处理器 CP15 来设置系统控制：

  1. LDR R0, =0x70000000：加载常量到 R0
  2. ORR R0, R0, #0x13：R0 |= 0x13（设置位 0,1,4）
  3. MCR p15, 0, R0, c1, c0, 0：写 R0 到 CP15 的系统控制寄存器（SCTLR）

位 0 = MMU 使能，位 1 = 对齐检查，位 4 = D-cache 使能。0x13 = MMU on + 对齐检查 + D-cache on。MCR = Move to Coprocessor Register，从 ARM 寄存器写到协处理器。

这是典型的裸机/启动代码：直接操作 CP15 系统寄存器。

3.8

AArch64拓展

本节讲什么

AArch64（ARMv8+ 64 位执行状态）是服务器、树莓派 3/4、Ampere 等 Linux/DPDK 主流平台。与 ARM32 相比：固定 64 位指令、31 个 64 位通用寄存器、无 Thumb、异常级别 EL0–EL3。

要点

寄存器 X0–X30

寄存器 别名 用途
X0–X7 — 参数 / 返回值（可传 8 个）
X8 — 间接结果 / syscall 号
X9–X15 — 临时（调用者保存）
X16–X17 IP0/IP1 跳板 / PLT
X18 — 平台保留（内核 per-CPU）
X19–X28 — 被调者保存
X29 FP 帧指针
X30 LR 链接寄存器
— SP 栈指针（独立编码）
— PC 独立，非通用寄存器
  • 访问低 32 位写 Wn（零扩展）；如 W0 为 X0 低半部
  • 无 CPSR 条件执行全场：条件分支用显式 b.eq 等

与 ARM32 对照

@ ARM32
mov r0, #1
bl  func
bx  lr

// AArch64
mov x0, #1
bl  func
ret                          @ 等价 bx lr

ldr x0, [x1, #8]             @ 64 位加载
add x2, x0, x1, lsl #3

无 Thumb

  • AArch64 仅 A64 指令集，无 16/32 位 Thumb 混编；简化取指与工具链
  • 32 位用户态程序在 AArch64 CPU 上通过 AArch32 兼容（可选，独立工具链 arm-linux-gnueabihf）

工具链与内核

aarch64-linux-gnu-gcc -c foo.S
aarch64-linux-gnu-objdump -d foo.o
  • Linux 内核 arch/arm64/、entry.S 用 ELx 切换
  • DPDK 在 ARM64 上 mbuf/ring 热点多为 NEON + 64 位 load pair

题目 1： AArch64（ARMv8）相比 AArch32（ARMv7）有哪些主要变化？对 C 编程有什么影响？

参考答案

AArch64 主要变化： - 寄存器：31 个 64 位通用寄存器 X0-X30（AArch32 只有 16 个 32 位 R0-R15） - 指令长度：固定 32 位（与 AArch32 相同），但操作 64 位数据 - 调用约定：X0-X7 传参（8 个，AArch32 只有 4 个），X0 返回值 - 栈指针：SP 专用寄存器，不再与 R13 共用 - LR：X30 专用，不再与 R14 共用

对 C 编程影响：long/指针 在 AArch64 是 8 字节（LP64 模型），AArch32 是 4 字节（ILP32）。跨平台代码需用 uintptr_t/size_t 而非 int/unsigned long。

3.9

异常与中断汇编

本节讲什么

异常/中断发生时 CPU 硬件自动切换模式 并跳向量；汇编负责 保存上下文、调用 C handler、恢复返回——内核 entry-armv.S、GIC 中断与 ch10 多任务的前置。

要点

ARM32 异常类型

向量 触发
Reset 上电
Undefined 非法指令
SWI/SVC 系统调用
Prefetch Abort 取指_fault
Data Abort 数据_fault
IRQ / FIQ 外设中断

上下文保存（典型 IRQ 入口）

irq_handler:
    sub lr, lr, #4              @ 修正返回地址
    stmfd sp!, {r0-r12, lr}     @ 保存通用寄存器
    mrs r0, spsr                @ 保存程序状态
    stmfd sp!, {r0}
    bl  do_irq_handler          @ C 处理函数
    ldmfd sp!, {r0}
    msr spsr_cf, r0
    ldmfd sp!, {r0-r12, pc}^    @ ^ 恢复 CPSR 并返回
  • SPSR 保存进入异常前的 CPSR；返回须恢复
  • LR_irq 为异常专属链接寄存器（banked）
  • 内核还需保存 r13_svc 等，避免重入错乱

与 C 的边界

  • 汇编：最少保存、清中断源、栈对齐（AAPCS 8 字节）
  • C do_irq_handler()：设备逻辑；request_irq() 注册
  • DPDK 用户态常用 UIO/vfio 轮询，不走内核 IRQ 路径，但 SoC 启动仍靠同类向量

AArch64 简述

  • 异常进 EL1/EL2；stp x0, x1, [sp, #-16]! 成对保存
  • eret 从 ELR/SPSR 返回（3.8）

题目 1： ARM 异常向量表的结构是什么？以下代码如何处理 IRQ 中断？

.vector_table:
    B Reset_Handler      @ 0x00: Reset
    B Undef_Handler      @ 0x04: Undefined
    B SVC_Handler        @ 0x08: Supervisor Call
    B PrefAbort_Handler  @ 0x0C: Prefetch Abort
    B DataAbort_Handler  @ 0x10: Data Abort
    B .                  @ 0x14: Reserved
    B IRQ_Handler        @ 0x18: IRQ
    B FIQ_Handler        @ 0x1C: FIQ
参考答案

ARM 异常向量表位于地址 0x00000000（或 VBAR 指定的高地址），每个异常入口 4 字节（一条 B 指令）：

  • 0x00 Reset：上电/复位
  • 0x04 Undefined：未定义指令
  • 0x08 SVC：超级调用（系统调用）
  • 0x0C Prefetch Abort：取指失败
  • 0x10 Data Abort：数据访问失败
  • 0x14 Reserved：保留
  • 0x18 IRQ：普通中断
  • 0x1C FIQ：快速中断

IRQ 处理器需：保存上下文（R0-R12, LR, SPSR）→ 读中断控制器 → 处理 → 清中断 → 恢复上下文 → SUBS PC, LR, #4 返回（IRQ 返回地址是 PC-4）。
