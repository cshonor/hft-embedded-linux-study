7.3

数据的可移植性

本节讲什么

同一份 C 源码在不同 CPU、编译器、ABI 下，类型宽度、int/long/指针关系、对齐与字节序可能不同。可移植代码不依赖实现细节，而用标准定宽类型与显式转换。内核通过 arch/、include/linux/types.h 抽象平台差异；DPDK 通过 rte_* 类型与编译目标固定环境。

要点

不可移植假设 可移植替代
int 32 位 int32_t
long 与指针同宽 intptr_t / uintptr_t
enum 1 字节 显式 uint8_t 字段
结构体无 padding packed + 文档化 或 序列化函数 
#include <stdint.h>
#include <stddef.h>

/* POSIX / Linux 内核风格 */
typedef uint8_t  u8;
typedef uint32_t u32;
typedef uintptr_t dma_addr_t;  /* 平台相关，头文件封装 */

ABI 影响：

  • 结构体成员对齐、调用约定、参数传递
  • bool/wchar_t 宽度
  • 位域顺序与填充
# 32 位 vs 64 位对比 sizeof
gcc -m32 -dM -E - < /dev/null | grep SIZEOF
gcc -m64 -dM -E - < /dev/null | grep SIZEOF
  • limits.h / stdint.h：编译期常量 UINT32_MAX、SIZE_MAX
  • 序列化：网络/磁盘格式用大端 + 定宽，与主机布局脱钩
  • 条件编译：#if __SIZEOF_POINTER__ == 8 仅作最后手段

代码自测

题目 1： 如何编写可移植的 C 代码？以下代码在 32/64 位系统上有什么问题？

long size = 0;
int *p = malloc(n * sizeof(int));
size = (long)p;
printf("addr = %lx\n", size);
参考答案

问题： 1. long 在 64 位 Windows（LLP64）是 4 字节，存不下 8 字节指针 → 截断 2. (long)p 将指针转整数，应该用 uintptr_t 保证能容纳指针 3. malloc 返回值未检查 NULL

可移植代码：

#include <stdint.h>
uintptr_t addr = (uintptr_t)p;
printf("addr = %" PRIxPTR "\n", addr);

可移植原则： 1. 用 stdint.h 固定宽度类型（uint32_t 而非 unsigned long） 2. 用 size_t 表示大小/长度（而非 int） 3. 用 uintptr_t 存储指针值 4. 用 PRIxxx 宏打印（PRId32/PRIu64） 5. 不依赖 int/long/指针 的大小关系 6. 注意字节序和对齐差异

7.4

Linux内核中的size_t类型

本节讲什么

size_t 是 C 标准定义的无符号整数类型，表示对象大小与数组下标，宽度与 sizeof 结果一致（32 位机常为 32 位，64 位机为 64 位）。内核中几乎所有长度、计数、memcpy/strlen 返回值都用 size_t；与 int 混用是比较与循环 bug 的重灾区。

要点

#include <stddef.h>   /* size_t */
#include <string.h>

size_t n = strlen(buf);
void *p = malloc(n + 1);   /* n+1 前检查溢出，7.1.3 */

/* 内核 */
size_t copy_to_user(void __user *to, const void *from, size_t n);
API 返回/参数中的 size_t
sizeof size_t
strlen / strnlen size_t
malloc / kmalloc 请求 size_t
read / write count 常为 size_t

经典陷阱：

int len = -1;
size_t u = 10;
if (len < u) { }  /* false：len 转为巨大 size_t */

for (int i = 0; i < strlen(s); i++)  /* 每次 O(n)，且 i 类型不佳 */

相关类型：

类型 用途
ssize_t 有符号大小/错误码（-1）
ptrdiff_t 指针相减
off_t 文件偏移 
grep -r 'typedef.*size_t' /usr/include 2>/dev/null | head
  • 内核 kmalloc(size, gfp)：size 过大返回 NULL；注意 SIZE_MAX 边界
  • DPDK 类似用 size_t 与 uint32_t 描述 buffer length（依 API）
  • 格式化：%zu 打印 size_t；%zd 给 ssize_t

代码自测

题目 1： size_t 和 ssize_t 的区别是什么？为什么内核要自定义这些类型？

size_t len = sizeof(int);      // 无符号
ssize_t ret = read(fd, buf, len); // 有符号，可能返回 -1
参考答案

size_t：无符号整数，表示对象大小（sizeof 返回类型）。32 位系统 4 字节，64 位 8 字节。

ssize_t：有符号整数，表示大小或错误码。read()/write() 返回 ssize_t，正数表示读/写字节数，-1 表示错误。

内核自定义类型： - size_t：对象大小 - ssize_t：有符号大小 - loff_t：文件偏移（64 位） - dma_addr_t：DMA 地址 - phys_addr_t：物理地址 - gfp_t：内存分配标志

为什么自定义： 1. 明确语义（phys_addr_t 比 unsigned long 更清晰） 2. 跨架构一致（不同架构可能不同大小） 3. 类型安全（不同 typedef 之间编译器可警告） 4. 抽象层（未来可调整底层类型不影响用户代码）

7.10

指针与结构体

本节讲什么

结构体指针用 -> 访问成员，等价 (*p).mbr。offsetof 计算成员字节偏移，是协议解析、container_of（ch06 6.4）、FAM 分配的基础。packed 改变偏移规则，与 7.2 对齐理论直接相关。demo03 对比 normal/packed 布局。

要点

struct normal {
    uint8_t  type;
    uint32_t value;
    uint16_t flags;
};

struct normal n = { .type = 1, .value = 0x12345678, .flags = 0xABCD };
struct normal *p = &n;

p->value = 0;              /* (*p).value */

#include <stddef.h>
offsetof(struct normal, value);   /* 典型 4；packed 为 1 */

/* ch06 container_of */
#define container_of(ptr, type, member) ({              \
    void *__mptr = (void *)(ptr);                         \
    ((type *)((char *)__mptr - offsetof(type, member))); \
})
话题 要点
-> 左操作数为指针
offsetof 编译期常量，单位字节
packed 无 padding，可能未对齐访问
FAM struct hdr { int n; char data[]; }; + 一次分配 ch06 6.5 
/* FAM 分配示意 */
struct pkt {
    size_t len;
    uint8_t body[];   /* GNU 扩展 / C99 FAM */
};
struct pkt *h = malloc(sizeof *h + payload_len);

代码自测

题目 1： 如何通过指针访问结构体成员？-> 和 . 的区别是什么？

struct point { int x, y; };
struct point p = {3, 4};
struct point *ptr = &p;
printf("%d %d\n", p.x, ptr->x);   // ?
printf("%d %d\n", (*ptr).y, ptr->y); // ?
参考答案

输出 3 3 和 4 4。

  • p.x：直接用 . 访问结构体变量成员
  • ptr->x：通过指针用 -> 访问成员。-> 是 (*ptr).x 的简写
  • (*ptr).y：先解引用得到结构体，再用 . 访问。与 ptr->y 完全等价

-> 的本质：ptr->member 等价于 (*ptr).member。

链式访问：

struct node { int data; struct node *next; };
head->next->next->data  // 链表遍历

容器场景：

struct device {
    int id;
    struct list_head node;  // 嵌入链表节点
};
struct list_head *lp = &dev->node;
struct device *d = container_of(lp, struct device, node);  // 从成员指针获取容器
7.12

函数指针

本节讲什么

函数指针保存函数入口地址，实现回调、虚表、跳转表（jump table） 与运行时策略切换。内核 file_operations、IRQ handler、DPDK burst API 均依赖函数指针。用 typedef 声明签名是工程惯例；demo04 用 enum op_t 索引分发表。

要点

typedef int (*calc_fn)(int, int);

static int add(int a, int b) { return a + b; }
static int sub(int a, int b) { return a - b; }

calc_fn fp = add;
fp(3, 4);                    /* 7 */
calc_fn table[] = { add, sub };
table[0](10, 3);

demo04 jump table：

typedef enum { OP_ADD, OP_SUB, OP_MUL, OP_DIV, OP_COUNT } op_t;

static calc_fn jump_table[OP_COUNT] = {
    [OP_ADD] = add,
    [OP_SUB] = sub,
    [OP_MUL] = mul,
    [OP_DIV] = div_safe,
};

static int dispatch(op_t op, int x, int y) {
    if (op >= OP_COUNT || !jump_table[op])
        return 0;
    return jump_table[op](x, y);
}
模式 用途
回调 qsort 比较函数、request_irq
ops 表 struct file_operations
状态机 handlers[state]()
替代 switch 密集 op 码分派 
/* 内核 file_operations 片段（示意） */
struct file_operations {
    ssize_t (*read)(struct file *, char __user *, size_t, loff_t *);
    ssize_t (*write)(struct file *, const char __user *, size_t, loff_t *);
};

nm demo04 | grep -E ' add| sub'
  • 函数名 decay：add 与 &add 同义
  • NULL 槽：分发表可留空，调用前检查
  • 与数据指针互转：标准不要求，勿玩弄

代码自测

题目 1： 函数指针的作用是什么？以下代码如何实现回调？

typedef int (*compare_t)(const void *, const void *);
int int_cmp(const void *a, const void *b) {
    return *(const int *)a - *(const int *)b;
}
int arr[5] = {3, 1, 4, 1, 5};
qsort(arr, 5, sizeof(int), int_cmp);
参考答案

函数指针：指向函数的指针，可通过它调用函数。

  • compare_t：typedef，函数指针类型，指向 int(const void*, const void*) 函数
  • int_cmp：比较函数，返回 a-b
  • qsort：接收函数指针作为参数，排序时调用 int_cmp 比较元素

函数指针用途： 1. 回调函数：qsort/bsearch 的比较器、信号处理器 2. 策略模式：不同排序/查找策略 3. 虚函数表：C 实现 OOP 多态 4. 中断向量表：裸机中断处理 5. 插件/驱动注册：内核 file_operations

函数指针 vs 直接调用： - 直接调用：编译时确定地址，可内联 - 函数指针调用：运行时确定地址，不可内联（有间接调用开销）

内核中函数指针无处不在：struct file_operations 的每个成员都是函数指针。

7.13

重新认识void

本节讲什么

void 表示无类型：不能声明 void 变量；void * 是通用指针，可保存任意对象地址，解引用前须转为具体类型。void 函数无返回值。restrict（C99）修饰指针，承诺无别名以助优化。三者常与 memcpy、回调、MMIO 封装一起出现。

要点

void noop(void) { }              /* 无返回值 */

void *p = malloc(64);            /* 任意类型地址 */
int *ip = p;                     /* 转回，须对齐且知对象类型 */
free(p);

/* 不声明 void x; — 非法 */
话题 规则
void * 算术 非法，须先 cast
void * 比较 可与任意对象指针比较
memcpy void * 目的，const void * 源

restrict（优化契约）：

void sum(size_t n, const int *restrict src, int *restrict dst) {
    for (size_t i = 0; i < n; i++)
        dst[i] += src[i];   /* 编译器假设 src/dst 不重叠 */
}
/* 内核热路径；重叠须用 memmove */

volatile（回顾 demo05）：

volatile uint32_t *reg = (volatile uint32_t *)base;
*reg = val;   /* 每次真实访问设备 */

/* MMIO 宏模式 demo07 */
#define REG32(addr)  (*(volatile uint32_t *)(addr))
#define BIT(n)       (1u << (n))
REG32(GPIO_BASE + 0x04) |= BIT(0);
  • void ** 少见：通用容器用 void * + 类型标签
  • 函数指针与 void *：POSIX dlsym 返回后 cast，C 标准严格说不保证
  • C++：void * 不能隐式转 T *；C 可以

代码自测

题目 1： void 在 C 语言中有哪些用途？void * 指针的特点是什么？

void func(void);          // 无参数无返回值
void *malloc(size_t size); // 返回无类型指针
void *vp = malloc(100);
int *ip = vp;              // 隐式转换，合法吗?
*vp;                        // 合法吗?
参考答案

void 的用途： 1. 函数返回类型：void func() 表示无返回值 2. 函数参数：func(void) 表示无参数（func() 在 C 中表示参数未指定） 3. void 指针：void * 无类型指针

void * 特点： - 通用指针：可以指向任何类型的数据 - 隐式转换：void * 可与其他指针类型互相转换，无需强制 cast（C 语言） - int *ip = vp 合法（C 中 void 隐式转换，C++ 需要 cast） - 不能解引用：*vp 不合法——不知道读取多少字节 - 不能做指针运算*：vp + 1 不合法——不知道步长 - malloc 返回 void *，调用者负责转换为正确类型

用途： - 泛型接口：qsort 的比较器接收 const void * - 内存操作：memcpy/memset 接收 void * - 抽象句柄：void *handle = lib_init();

void * 是 C 语言实现泛型的核心工具。
