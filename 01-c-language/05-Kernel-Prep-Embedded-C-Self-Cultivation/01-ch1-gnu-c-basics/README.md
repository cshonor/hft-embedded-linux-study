# CH1 · GNU C 基础扩展语法

**GNU C Extensions — Syntax Level**

> 一句话概括这一章：**写在源码里就能看懂的扩展**。
> 不用翻编译器手册，看一眼大概能猜出它的意思——因为它们改变的是「你怎么写」。

## CH1 与 CH2 的分界线

把 GNU C 扩展砍成两刀，判据不是难不难，而是**它在哪个阶段起作用**：

| | **CH1 基础扩展语法**（本章） | [CH2 高级特性](../02-ch2-gnu-c-advanced/) |
|---|---|---|
| 作用阶段 | **写代码的语法** | **编译期 / 链接期行为** |
| 看不懂的后果 | 读不懂源码 | 代码能跑，但**静默出错** |
| 典型代表 | `typeof`、语句表达式、柔性数组、指定初始化 | `weak`、`packed`、`section`、内联汇编 |
| 出错时的表现 | 编译报错，立刻发现 | 链接通过、运行崩或性能崩 |
| 类比 | 多背了几个单词 | 多了几条**隐式契约** |

> **CH1 是源码表面看得见的部分；CH2 是源码看不见却真实发生的部分。**
> 所以 CH2 的每一条都必须实测——这一章可以先靠直觉建立语感。

## 跨平台 / 标准兼容提醒

这些扩展**都不在标准 C 里**。写可移植代码时用宏隔离：

```c
/* 标准写法 vs GNU 写法，用宏切换 */
#ifdef __GNUC__
#  define FAM_SIZE 0            /* GNU: 零长度数组 */
#else
#  define FAM_SIZE 1            /* C99: 柔性数组 */
#endif
struct pkt { uint16_t len; uint8_t data[FAM_SIZE]; };
```

> 更系统的可移植写法见 **[CH5 基于 GNU C 的跨平台模块化设计](../05-ch5-portable-modular/)**。

**Q1：`typeof` 在编译期还是运行期求值？**

<details><summary>答案</summary>
编译期。`typeof` 不求值表达式，只取它的类型——所以 `typeof(f())` 里的 `f()` **不会被调用**（无副作用）。这正是它能用在宏里做类型检查的前提。
</details>

**Q2：语句表达式 `({...})` 和代码块 `{...}` 的本质区别？**

<details><summary>答案</summary>
代码块是**语句**，没有值；语句表达式是**表达式**，最后一行的值就是它的值。所以 `x = ({...})` 合法，而 `x = {...}` 不合法。这让宏可以「先算一堆中间值，再返回一个结果」。
</details>

**Q3：为什么零长度数组只能放在结构体末尾？**

<details><summary>答案</summary>
它不占任何字节（`sizeof` 不计入），只是给结构体末尾一个「地址锚点」。放中间会让后面成员的偏移量全乱，编译器直接拒绝（`flexible array member not at end of struct`）。详见 [6.5](./6.5-zero-length-array/6.5-零长度数组.md)。
</details>
