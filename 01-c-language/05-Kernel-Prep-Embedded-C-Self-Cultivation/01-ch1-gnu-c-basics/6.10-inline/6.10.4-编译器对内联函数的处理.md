# 6.10.4 编译器对内联函数的处理

## 本节讲什么

是否 inline 由 **启发式** 决定：函数大小、`-O` 级别、**`always_inline`**、**LTO**。

## 要点

```bash
gcc -O0 -S foo.c -o O0.s
gcc -O2 -S foo.c -o O2.s
diff O0.s O2.s | head
```

| 因素 | 倾向 |
|------|------|
| `-O2`/`-O3` | 更 aggressive inline |
| 函数体大 | 不 inline |
| **LTO** | 跨文件 inline |

## 代码自测

**题目 1：** `-O0` 和 `-O2` 下，`static inline` 函数的行为有什么区别？
```c
static inline int add(int a, int b) { return a + b; }
int caller(int x) { return add(x, 1); }
```

<details>
<summary>参考答案</summary>

`-O0`（不优化）：编译器通常不内联，会生成 `add` 的 out-of-line 副本然后 `call`。`-O2`（优化）：编译器大概率内联展开，`caller` 直接变成 `return x + 1`，不生成 `add` 的独立函数体。`static` 保证不产生外部符号，如果未被内联也只在本文件可见。`-Winline` 可警告哪些 inline 没被内联。`always_inline` 在 `-O0` 也能强制内联。

</details>
