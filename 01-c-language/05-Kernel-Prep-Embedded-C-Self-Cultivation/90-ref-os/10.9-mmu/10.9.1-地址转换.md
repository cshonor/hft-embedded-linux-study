# 10.9.1 地址转换

## 本节讲什么

**虚拟地址（VA）** 经 **页表** 转为 **物理地址（PA）**；TLB 缓存近期映射加速访问。本节介绍 **两级/多级页表、段/页粒度** 与 **地址空间布局**，衔接 **10.6.2** 与 Linux **`/proc/pid/maps`**。

## 要点

**为何需要 VA**：

- 每个进程 **以为** 拥有从 0 开始的连续空间
- **简化链接**：PIE 可加载到任意基址
- **共享库** 映射到多个进程同一物理页

**ARM 32 两级页表示意**：

```
VA [31:22] → L1 项 → 指向 L2 表
VA [21:12] → L2 项 → 物理页框号 + 属性
VA [11:0]  → 页内偏移
```

**常见页大小**：4 KB；ARM 还支持 **1 MB section**（启动早期简化）

**地址空间布局（Linux 32 位用户态典型）**：

```
0x00000000  ──► 代码 text
            ──► heap ↑
            ──► mmap 区（共享库、文件映射）
0xBF000000  ──► 栈 ↓
```

**查看映射**：

```bash
cat /proc/self/maps
```

**RTOS 无完整 MMU**：

- 链接脚本固定 **物理地址**；`0x20000000` 即 RAM
- **MPU**：仅 8 区域，粗粒度保护任务栈

**切换进程/任务**：

- Linux：`switch_mm` 换 **TTBR0** + **ASID** 减 TLB flush
- RTOS MPU：上下文切换时 **重配 MPU 区域**

**与 DMA**：

- DMA 用 **物理地址**；CPU 用 VA → 驱动 `dma_map_single` 得到 bus addr

## 常见陷阱

1. **TLB 未在切换进程时 invalidate → 跨进程读到旧映射**
   切换进程时若不清 TLB，新进程的 VA 可能命中旧进程的 TLB 项，读到旧物理页——**安全漏洞**（跨进程数据泄露）。Linux 用 **ASID**（Address Space ID）避免每次切换都全清 TLB：每个进程有 8/16 位 ASID，TLB 项标记 ASID，查找时 VA + ASID 都匹配才命中。**坑**：ASID 溢出时仍需全局 flush——某些老旧 ARM 核 ASID 仅 8 位，进程多时频繁 flush 影响性能。x86 用 PCID 类似机制。

2. **DMA 用 VA 传地址 → 数据写到错误物理页**
   DMA 控制器**不看页表**，只认物理地址。代码 `dma_start(buf_va, len)` 把虚拟地址给 DMA，DMA 写到 `buf_va` 这个数值对应的物理地址——可能根本不是 `buf_va` 实际映射的物理页，**踩内存**。**正确**：`dma_map_single(dev, va, len, dir)` 返回 bus address（物理地址或 IOMMU 映射地址），DMA 用返回值。坑：`virt_to_phys` 在直接映射区可用，但 vmalloc / 用户态地址不行——必须走 DMA API。

3. **大页（hugepage）与普通页混用 → TLB 压力反而上升**
   大页（2MB/1GB）减少 TLB 项数量，降低 TLB miss。但若程序随机使用大页（如部分 `mmap` 用大页、部分用普通页），TLB 反而**碎片化**——大页和普通页 TLB 通常分开缓存（ITLB/iTLB、L1/L2 dTLB、huge TLB），混用占满两种 TLB。**约定**：大页用于**大块连续**分配（数据库缓冲池、DPDK mempool），零散分配用普通页。`madvise(MADV_HUGEPAGE)` 提示内核透明大页（THP），但 THP 不是保证。

## 自测题

**1.（选择）** 32 位 ARM 二级页表中，4KB 页的 VA 拆分是？
- A. [31:20] L1 + [19:12] L2 + [11:0] offset
- B. [31:22] L1 + [21:12] L2 + [11:0] offset
- C. [31:12] L1 + [11:0] offset
- D. [31:24] L1 + [23:16] L2 + [15:8] L3 + [7:0] offset

<details><summary>答案</summary>

**B**。32 位 ARM 二级页表：
- L1 索引：VA[31:22]，共 10 位 → 1024 项 L1 表
- L2 索引：VA[21:12]，共 10 位 → 1024 项 L2 表
- 页内偏移：VA[11:0]，共 12 位 → 4KB 页
每项 L1 指向一个 L2 表（4KB），每个 L2 表 1024 项 × 4 字节 = 4KB——刚好一页。**64 位** ARM（AArch64）用 4 级或 5 级页表，每级 9 位索引，VA 48/57 位。

</details>

**2.（判断）** RTOS（如 FreeRTOS on Cortex-M）通常不启用 MMU。

<details><summary>答案</summary>

**对**。Cortex-M 系列（M0/M3/M4/M7/M33）**没有完整 MMU**——只有 MPU（Memory Protection Unit），8 或 16 个区域，粗粒度保护。RTOS 通常：
- 链接脚本固定物理地址（`0x20000000` 是 RAM，`0x08000000` 是 Flash）。
- 不做 VA→PA 转换，CPU 直接用物理地址。
- MPU 用于保护任务栈/特权区，但不提供"每进程独立地址空间"。
**Linux on Cortex-A** 才用完整 MMU——A 系列有 MMU，可跑 Linux；M 系列无 MMU，跑 RTOS 或裸机。**坑**：RTOS 代码移植到 Linux 时，"直接访问物理地址"需改为 `mmap(/dev/mem)` 或 `ioremap`。

</details>

**3.（踩坑）** 驱动代码：
```c
void *buf = vmalloc(4096);           /* 内核虚拟地址 */
memset(buf, 0, 4096);
dma_start(phy_addr_of(buf), 4096);   /* 期望 DMA 写到 buf */
```
DMA 写完后 `buf` 内容没变。为什么？

<details><summary>答案</summary>

**`vmalloc` 返回的虚拟地址不是直接映射**——`phy_addr_of(buf)` 用 `virt_to_phys` 对 vmalloc 区是**错误**的，返回的物理地址可能任意（vmalloc 用非连续物理页拼成连续 VA）。DMA 写到该"物理地址"对应的任意物理页，**不是 buf 实际映射的页**。
**修复**：
```c
/* 方案一：用 dma_alloc_coherent 分配 DMA 友好内存 */
void *cpu_addr;
dma_addr_t dma_handle;
cpu_addr = dma_alloc_coherent(dev, 4096, &dma_handle, GFP_KERNEL);
/* cpu_addr 给 CPU 用，dma_handle 给 DMA 用 */
dma_start(dma_handle, 4096);

/* 方案二：用 dma_map_single 映射已有内存 */
dma_handle = dma_map_single(dev, buf, 4096, DMA_TO_DEVICE);
dma_start(dma_handle, 4096);
/* 完成后 dma_unmap_single(dev, dma_handle, 4096, DMA_TO_DEVICE); */
```
**关键**：DMA 地址必须通过 DMA API 获取，不能用 `virt_to_phys`——后者只对直接映射区（`__pa`）有效。某些平台有 IOMMU，DMA 地址甚至不是物理地址，是 IOMMU 分配的总线地址。

</details>

**4.（应用）** 给定一个用户态地址 `void *p`，写代码：① 判断是否可读；② 获取其物理地址（若有权限）。说明限制。

<details><summary>答案</summary>

```c
#include <stdio.h>
#include <unistd.h>
#include <fcntl.h>
#include <stdint.h>
#include <sys/mman.h>

int main() {
    volatile char *p = (volatile char *)0x12345678;  /* 待测地址 */

    /* ① 判断是否可读：用 pipe + write 触发拷贝 */
    int pipefd[2];
    pipe(pipefd);
    char c = *p;                       /* 直接读：可能 segfault */
    /* 安全做法：mincore 判断是否驻留，但不验证权限 */

    /* ② 通过 /proc/self/pagemap 取物理地址 */
    uint64_t vaddr = (uint64_t)p;
    int fd = open("/proc/self/pagemap", O_RDONLY);
    lseek(fd, (vaddr / 4096) * 8, SEEK_SET);
    uint64_t entry;
    read(fd, &entry, 8);
    close(fd);

    if (entry & (1ULL << 63)) {        /* bit 63 = present */
        uint64_t pfn = entry & ((1ULL << 55) - 1);
        uint64_t paddr = (pfn << 12) | (vaddr & 0xFFF);
        printf("VA %p → PA %llx\n", p, (unsigned long long)paddr);
    } else {
        printf("VA %p not present\n", p);
    }
    return 0;
}
```
**限制**：
1. **① 判断可读**：用户态**无干净方法**——`mincore` 只查驻留，不查权限；`write(pipe, &p, 1)` 若 `p` 不可读会返回 EFAULT，但仍是 syscall 开销。最可靠是 SIGSEGV handler + `setjmp`/`longjmp`，但侵入性强。
2. **② 物理地址**：`/proc/self/pagemap` 需 root 或 `CAP_SYS_ADMIN`（内核 4.0+ 限制，防侧信道攻击）。物理地址对用户态程序**几乎无用**——不能直接 `mmap` 物理地址（需 `/dev/mem`），多进程下 VA→PA 映射随时变（swap、迁移）。
3. **生产代码**几乎不需做这两件事——内核/驱动才关心物理地址，用户态用 VA 抽象即可。

</details>
