# 4.6.1 操作系统环境下的程序运行

## 本节讲什么

Linux 运行 ELF 可执行文件时，内核解析 **程序头（Program Header）**，将 `PT_LOAD` 段映射到进程虚拟地址空间，**物理页** 按需分配；`ld-linux.so` 处理动态段、重定位与初始化，再跳转到用户入口。

## 要点

### execve 装载

```bash
readelf -l ./prog
# LOAD 段：/bin 或 /lib 文件偏移 → 虚拟地址 VMA
strace -e execve,mmap ./prog 2>&1 | head -30
```

### 虚拟内存布局（典型 x86-64）

```
高地址  栈 ↓
        mmap / 堆 ↑
        共享库 .so
        .bss / .data / .rodata / .text
低地址
```

```bash
cat /proc/self/maps              # 运行中查看
pmap -x $(pidof prog)
```

### 动态链接器

- `.interp` 段指定 `/lib64/ld-linux-x86-64.so.2`
- `ld.so` 读取 `.dynamic`：`NEEDED`、`REL`、`INIT`

```bash
readelf -d ./prog
readelf --dyn-syms ./prog | head
```

### ASLR 与 PIE

```bash
gcc -pie -fPIE -o prog main.c
readelf -h prog | grep Type       # DYN（位置无关可执行）
```

## 代码自测

**题目 1：** 在有 OS 的环境下，C 程序的 main 函数真的是第一个执行的代码吗？
<details>
<summary>参考答案</summary>

不是。`_start`（C 运行时库的启动代码）先于 main 执行。

启动流程：
1. **内核加载 ELF**：设置虚拟内存映射
2. **跳转 `_start`**（来自 crt1.o）：设置栈、清 BSS
3. **`__libc_start_main`**：初始化 C 库（stdio/malloc/locale），注册 atexit
4. **调用 `main(argc, argv, envp)`**
5. **main 返回后**：`exit()` → atexit 回调 → `_exit()`（系统调用，回收进程）

`readelf -h hello | grep Entry` 查看入口地址，通常是 `_start` 而非 `main`。

裸机环境没有 C 运行时，需自己实现 `_start` → 直接调用 main 或业务逻辑。

</details>
