# 6.5.3 内核中的零长度数组

## 本节讲什么

内核大量使用 FAM / `[0]`：**sk_buff 尾部**、**netlink 属性**、**ioctl 结构**、**BPF map 值**。读 `include/linux/skbuff.h` 等头文件时识别「头 + 变长」模式。

## 要点

```c
/* 概念示意 — 非完整内核定义 */
struct nlattr {
    uint16_t nla_len;
    uint16_t nla_type;
    char     nla_data[0];
};

/* 分配 attr */
static struct nlattr *nla_alloc(uint16_t type, uint16_t dlen)
{
    struct nlattr *na = kmalloc(sizeof(*na) + dlen, GFP_KERNEL);
    if (na) {
        na->nla_type = type;
        na->nla_len  = sizeof(*na) + dlen;
    }
    return na;
}
```

```c
/* skb 线性数据 — 历史上有 headroom/data/tail 与 frags */
/* 变长体现在 data_len、frag_list、paged offset 等组合 */
```

- 内核 coding style 倾向 **`[]` FAM**（C99）而非 `[0]`，视树版本而定
- **用户态拷贝**：`copy_to_user` 需传递 **总长度** `sizeof(hdr)+payload`
- DPDK **mbuf** 用固定 headroom + dynfield 扩展，思想类似「头 + 可变数据区」

## 代码自测

**题目 1：** Linux 内核中哪些结构体使用了零长数组？为什么不用指针代替？
<details>
<summary>参考答案</summary>

内核中使用零长数组/柔性数组的结构体：

1. `struct sk_buff`：网络数据包，`char cb[48]` 控制块（固定），数据区用 head 指针
2. `struct usb_request`：USB 请求，数据缓冲区
3. `struct inode`/`struct dentry`：文件系统元数据
4. `struct bio_vec`：块 IO 向量
5. 各种 `*_header` + 变长选项（网络协议头）

不用指针的原因：
1. **一次分配**：结构体 + 数据一次 kmalloc，减少内存碎片
2. **一次释放**：一次 kfree，减少遗漏
3. **Cache 友好**：结构体和数据在同一 Cache Line，减少 Cache Miss
4. **DMA 友好**：连续物理内存，适合 DMA 传输
5. **原子性**：分配要么全成功要么全失败，不会出现结构体分配成功但数据分配失败

</details>
