# 6.11.5 内建函数：__builtin_expect(exp,c)

## 本节讲什么

**`__builtin_expect(long exp, long c)`** 告知编译器 **exp 最可能等于 c**，用于 **基本块布局**（hot path fall-through）。**不改变** exp 的语义与求值次数；主要影响 **代码排列**，而非直接「加速 CPU 分支预测」。

## 要点

```c
#define likely(x)   __builtin_expect(!!(x), 1)
#define unlikely(x) __builtin_expect(!!(x), 0)

if (likely(ptr != NULL)) {
    use(ptr);
} else {
    return -EINVAL;
}
```

```c
/* 常见误解：不会改变调用次数 */
int v = unlikely expensive();  /* expensive() 仍调用一次 */
```

| 项 | 说明 |
|----|------|
| 参数 | `exp` 任意整型；`c` 为期望值 |
| 效果 | 重组 CFG，hot label 布局 |
| 替代 | **PGO**（Profile-Guided Optimization） |

```bash
gcc -O2 -S -o expect.s expect.c
# 对比加 likely 前后基本块顺序
objdump -d expect | less
```

- **Case range** `case 1 ... 5:`（GNU）与 expect 同属编译器扩展工具箱
- DPDK **`rte_likely`/`rte_unlikely`** 在 `rte_branch_prediction.h`

## 代码自测

**题目 1：** __builtin_expect 的作用是什么？likely/unlikely 宏如何使用它？
```c
#define likely(x)   __builtin_expect(!!(x), 1)
#define unlikely(x) __builtin_expect(!!(x), 0)

// 使用
if (unlikely(ptr == NULL))
    return -EINVAL;
if (likely(data->flag))
    process(data);
```
<details>
<summary>参考答案</summary>

`__builtin_expect(exp, c)`：告诉编译器 exp 很可能等于 c，用于分支预测优化。

效果：
- `likely(x)`：x 很可能为真。编译器将"真"分支的代码放在"假"分支前面（顺序执行，减少跳转）
- `unlikely(x)`：x 很可能为假。编译器将"假"分支的代码放在前面

运行时 `__builtin_expect` 不做任何事（返回 exp 原值），只影响编译器的代码布局。

`!!(x)` 将 x 转为 0/1（双取反），统一类型。

使用场景：
- 错误检查：`if (unlikely(err))` 错误路径很少执行
- 热路径：`if (likely(cache_hit))` 命中是常见情况

注意：现代 CPU 有硬件分支预测器，`__builtin_expect` 的收益主要在代码布局（减少 icache miss），而非分支预测本身。滥用可能反而降低性能。

</details>
