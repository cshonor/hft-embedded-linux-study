# 6.3 宏构造「利器」：语句表达式

## 本节讲什么

**语句表达式（statement expression）** 写法是 `({ 语句; 语句; 表达式; })`——把**一个代码块**变成**一个有值的表达式**。

它和 [6.4 typeof](../6.4-typeof-container-of/6.4-typeof与container_of宏.md) 配成"内核宏两件套"，缺一不可：

| 两件套 | 解决的问题 |
|---|---|
| **`typeof`** | 宏能"看见"实参的**类型** → 声明临时变量 |
| **语句表达式** | 宏能拥有**局部作用域** → 放得下那条声明语句 |

没有 `typeof`，宏不知道该声明什么类型的临时变量；没有语句表达式，宏连一条声明语句都放不进去。两者合体才有了 `min`/`max`/`container_of`/`swap`/`clamp`。

| 关键事实 | 说明 |
|---|---|
| 是 GNU 扩展 | 标准 C 到 C23 都没有；但 **gcc / clang / ICC 都支持**，连 **g++ / clang++ 也支持** |
| 只在**函数内**可用 | 用在全局初始化器、位域宽度、枚举常量 → 直接编译错误 |
| 不是常量表达式 | 哪怕是 `({4;})` 这种"看起来恒定"的，也不能当数组维度（会退化成 VLA） |
| `-O2` 下**零开销** | 与手写三元表达式、与 `static inline` 函数生成**逐字节相同**的指令 |
| 有一个**静默 UB 陷阱** | 实参名与宏内临时变量同名 → 自我初始化，gcc `-Wall -Wextra` 抓不到 |

## 一、语法：把代码块变成表达式

```c
({ 语句1; 语句2; ...; 最后一条表达式 })
```

- 外面是**圆括号**，里面是**花括号**——少任何一半都不是语句表达式
- **最后一条必须是表达式语句**，它的值就是整个 `({ })` 的值
- 内部可以声明变量、写循环、写 `if`、嵌套另一个 `({ })`

```c
int v1 = ({ int a = 3; int b = 4; a + b; });   /* 7 */
int v3 = ({ 42; });                            /* 只有一条语句也行 */
int v4 = ({ int x = ({ 10; }); x * 2; });      /* 嵌套：20 */
```

### 1.1 值的类型 = 最后那条表达式的类型

实测：

```c
double v2 = ({ int a = 3; a; });   /* 值是 int 3，赋给 double 时隐式转换 -> 3.000000 */
```

所以**语句表达式本身是"类型透明"的**——它不自带类型，完全由最后一条表达式决定。这一点和 `typeof` 搭配时很关键：`__typeof__(a) _a = (a);` 里 `_a` 的类型就是实参 `a` 的类型。

### 1.2 最后一条不是表达式 → 编译错误

| 写法 | 结果 |
|---|---|
| `({ int a = 1; })` —— 最后是**声明** | ❌ `error: void value not ignored as it ought to be` |
| `({ })` —— 空块 | ❌ 同上 |
| `({ printf("hi"); })` —— 最后是 void 调用 | ⚠️ 只能当语句用，不能赋给变量 |

反过来，**void 的语句表达式当语句用是合法的**，这正是很多调试宏的写法：

```c
({ printf("side effect ok\n"); });   /* 合法，整体是 void 表达式 */
```

### 1.3 内部可以有流程控制

```c
int sum = ({
    int s = 0;
    for (int i = 1; i <= 5; i++) s += i;
    s;                      /* <- 返回值 */
});                         /* 实测 15 */
```

## 二、作用域：不进不出

### 2.1 内部变量遮蔽外层，但**不会泄漏**到外面

```c
int a = 100;
int v = ({ int a = 7; a; });   /* 实测 inner=7, outer=100 */

int w = _a;                    /* ❌ error: '_a' undeclared */
```

遮蔽是**正常的块作用域**行为，同名内层变量盖住外层；块结束后外层变量完好无损（实测外层 `_a` 仍是 100）。

### 2.2 生命周期到此结束——返回地址就是悬垂指针

```c
#define BAD_PTR() ({ int _x = 42; &_x; })   /* 返回栈上临时量的地址 */
int *p = BAD_PTR();                          /* p 立刻悬垂 */
```

| 编译器 | 是否告警 |
|---|---|
| gcc 13.3 | ✅ `-Wdangling-pointer=`：*using a dangling pointer to '_x'*，并指向宏定义行 |
| clang 18 | ❌ **零警告** |

> 这是语句表达式最容易写错的地方之一：**它给了你一个块，块里的自动变量活不过右括号**。
> 想要"返回一个数组"请用**复合字面量** `(int[]){1,2,3}`，它的生命周期是**所在块**（实测有效）。

## 三、跳转语义：return / break / continue / goto 全部穿透

这一点非常反直觉但很有用：语句表达式**不是函数**，跳转语句直接作用于**外层的函数或循环**。

| 跳转 | 在语句表达式里的行为 | 实测 |
|---|---|---|
| `return` | 从**包含它的函数**返回（不是从块返回） | `early_return(-5)` 返回 -1 ✅ |
| `break` | 跳出**外层**循环 | 循环中 `if (i==4) break;` 生效 ✅ |
| `continue` | 继续**外层**循环 | `if (i==3) continue;` 生效 ✅ |
| `goto` | 可以跳到**外层**标签 | 跳到 `done:` 生效 ✅ |

```c
static int early_return(int x)
{
    int v = ({
        if (x < 0) return -1;   /* 直接从 early_return 返回！ */
        x * 2;
    });
    return v;
}
```

### 3.1 `__label__`：在宏里声明局部标签

宏可能被同一个函数调用多次，如果用普通标签会**重复定义**。GCC 提供 `__label__`（clang 也支持）在语句表达式里声明**局部标签**：

```c
#define FIRST_NEG(arr, n) ({                        \
    __label__ found;                                \
    __typeof__(&(arr)[0]) _a = (arr);               \
    int _i, _res = -1;                              \
    for (_i = 0; _i < (n); _i++)                    \
        if (_a[_i] < 0) { _res = _i; goto found; }  \
found:                                              \
    _res;                                           \
})
/* 实测：a[5]={1,2,-8,4,-5} -> 返回 2，gcc 与 clang 都通过 */
```

## 四、禁区：它不是常量表达式

**最重要的一条限制**：语句表达式**只能出现在函数体内**。

| 用法 | 结果 | gcc 报错 |
|---|---|---|
| 全局初始化器 `int g = ({5;});` | ❌ | `braced-group within expression allowed only inside a function` |
| 全局数组维度 `int arr[({3;})];` | ❌ | 同上 |
| 位域宽度 `unsigned x : ({3;});` | ❌ | 同上 + `bit-field width not an integer constant` |
| 枚举常量 `enum { A = ({1;}) };` | ❌ | 同上 |
| `case ({1;}):` | ❌ | `case label does not reduce to an integer constant` |
| 块内数组维度 `int a[({4;})];` | ⚠️ 能编过 | **但退化成 VLA**：`-Wvla` 报 *"array 'a' whose size cannot be evaluated"* |
| `_Static_assert(({1;}) == 1, "")` | ⚠️ gcc 接受 | 别这么写，clang 未必买账 |

> **一句话**：需要**编译期常量**的地方一律不能用；哪怕块里写的是字面量 `4`，编译器也只在运行时才知道它的值。

## 五、标准兼容性（实测矩阵）

### 5.1 不带 `-pedantic`：所有模式零诊断

同一份 `MAX` 宏（WSL gcc 13.3 / clang 18.1.3，加 `-Wall -Wextra`）：

| `-std` | gcc | clang |
|---|---|---|
| `c99` / `c11` / `c17` / `c2x` | ✅ 零诊断 | ✅ 零诊断 |
| `gnu99` / `gnu11` / `gnu17` | ✅ 零诊断 | ✅ 零诊断 |

### 5.2 带 `-pedantic`：全部告警（但仍能编过）

| 编译器 | 诊断 |
|---|---|
| gcc | `warning: ISO C forbids braced-groups within expressions [-Wpedantic]` |
| clang | `warning: use of GNU statement expression extension [-Wpedantic]` |

> **对比 6.4 的 `typeof`**：裸 `typeof` 在 `gcc -std=c11` 下是**硬错误**（被当成隐式函数调用），而语句表达式在同样的 ISO 模式下只是 **warning**。
> 原因不同：`typeof` 是**关键字**层面的冲突，`({ })` 是**语法**层面的扩展——GCC 认为语法扩展"无害"，只在你显式要 ISO 合规时才提醒。

### 5.3 C++ 呢？两个编译器都支持

| 编译器 | 结果 |
|---|---|
| `g++ -std=c++11` / `-std=c++17` | ✅ 编译通过，零诊断 |
| `clang++ -std=c++17` | ✅ 编译通过，零诊断 |

所以头文件里用语句表达式**不会**把 C++ 用户挡在门外（这是它相对某些 GCC 扩展的优势）。

### 5.4 可移植包装

```c
#if defined(__GNUC__) || defined(__clang__)
#  define HAVE_STMT_EXPR 1
#  define STMT(...)      (__VA_ARGS__)      /* 有语句表达式时照常展开 */
#else
#  define HAVE_STMT_EXPR 0
#  define STMT(...)      (0)                /* 退化：换成 static inline 实现 */
#endif
```

实践建议：**Linu 内核、DPDK、U-Boot 这类项目直接假定可用**；要支持 MSVC 的库代码，就用 `#ifdef` 切成 `static inline` 函数。

## 六、核心价值：消除宏参数的双重求值

这是语句表达式存在的**第一理由**。

### 6.1 朴素宏的灾难

```c
#define MAX_NAIVE(a, b)  ((a) > (b) ? (a) : (b))
#define MAX_GNU(a, b) ({ __typeof__(a) _a = (a);   \
                         __typeof__(b) _b = (b);   \
                         _a > _b ? _a : _b; })
```

实测（函数 `bump()` 每调用一次计数 +1）：

| 调用 | 朴素版 | 语句表达式版 |
|---|---|---|
| `MAX(bump(), 0)` | 返回 **2**，`bump()` 调用 **2 次** | 返回 **1**，调用 **1 次** |
| `MAX(arr[idx++], 5)` | `idx` 变成 **2** | `idx` 变成 **1** |

朴素版不仅多求值，而且**返回值是第二次调用的结果**（`bump()` 第二次返回 2，所以 `MAX` 返回 2 而不是 1）——**结果本身都错了**。

### 6.2 嵌入式场景：这是真事故，不是理论问题

硬件寄存器**读一次和读两次是两回事**：

```c
/* 朴素版：v 出现两次 -> 读两次寄存器 */
#define LIMIT_NAIVE(v)  (((v) > 4095u) ? 4095u : (v))
/* 语句表达式版：先存到临时变量，只读一次 */
#define LIMIT_GNU(v) ({ __typeof__(v) _v = (v); _v > 4095u ? 4095u : _v; })
```

实测（模拟每次读取值都在变的寄存器）：

| 版本 | 返回值 | 读寄存器次数 |
|---|---|---|
| `LIMIT_NAIVE(read_reg())` | **101**（第二次读到的值！） | **2** |
| `LIMIT_GNU(read_reg())` | 100（正确） | **1** |

> **为什么致命**：
> 1. **W1C（write-one-to-clear）寄存器**读一次就清一次标志——读两次 = **丢中断**。
> 2. **自增型 FIFO / DMA 指针**读一次就往前走一格——读两次 = **丢数据**。
> 3. **volatile MMIO** 编译器不敢合并，两次读一定真的发生两次。
>
> 这在裸机驱动里是最难查的一类 bug：逻辑"看起来"完全正确。

## 七、零开销实测：-O2 下与手写代码逐字节相同

```c
int max_gnu_fn(int a, int b) { return MAX_GNU(a, b); }   /* 语句表达式宏 */
int max_ref_fn(int a, int b) { return a > b ? a : b; }   /* 手写三元 */
```

**`-O0`（未优化）**——宏版多出栈上搬运：

```asm
max_gnu_fn:
    mov    %edi,-0x14(%rbp)     ; 存 a
    mov    %esi,-0x18(%rbp)     ; 存 b
    mov    -0x14(%rbp),%eax
    mov    %eax,-0x8(%rbp)      ; _a = a
    mov    -0x18(%rbp),%eax
    mov    %eax,-0x4(%rbp)      ; _b = b
    ...
    cmovge %edx,%eax
```

**`-O2`**——两个版本**完全一致**：

```asm
max_gnu_fn:                     max_ref_fn:
    cmp    %esi,%edi                cmp    %edi,%esi
    mov    %esi,%eax                mov    %edi,%eax
    cmovge %edi,%eax                cmovge %esi,%eax
    ret                             ret
```

**与 `static inline` 函数对比**（`-O2`，两次 min 相加）：

| 版本 | 指令 |
|---|---|
| 语句表达式宏 | `mov $0x7,%eax; mov $0x3,%edx; cmp; cmovle; cmp; cmovg; add; ret` |
| `static inline` 函数 | **完全相同** |

> **结论**：优化后，临时变量 `_a`/`_b` 一个字节都不占。语句表达式纯粹是**编译期构造**。
> 唯一代价是 `-O0` 调试时的栈搬运和**符号可读性**（见第九节）。

## 八、内核 / 嵌入式里的真实宏

### 8.1 min / max（最经典）

```c
#define min(a, b) ({            \
    __typeof__(a) _a = (a);     \
    __typeof__(b) _b = (b);     \
    _a < _b ? _a : _b;          \
})
```

实测支持 `int` / `double` / **指针**（`const char *`）自动推导，一份宏吃所有算术类型与指针。

### 8.2 clamp（限幅，ADC 采样天天用）

```c
#define clamp(v, lo, hi) ({                 \
    __typeof__(v)  _v  = (v);               \
    __typeof__(lo) _lo = (lo);              \
    __typeof__(hi) _hi = (hi);              \
    _v < _lo ? _lo : (_v > _hi ? _hi : _v); \
})
/* 实测：clamp(4200, 0, 4095) = 4095，clamp(-50, 0, 4095) = 0 */
```

### 8.3 swap（不用调用方准备临时变量）

```c
#define swap(a, b) ({ __typeof__(a) _t = (a); (a) = (b); (b) = _t; })
/* 实测：swap(x,y) -> x=2 y=1；swap(arr[0],arr[1]) 正常；swap(x,x) 也安全（x 不变） */
```

注意 `swap` 里 `(a)` 出现两次而 `(b)` 出现两次——**它是故意的**（一次读一次写，语义需要），别把它当成双重求值 bug。

### 8.4 寄存器字段读改写（嵌入式）

```c
/* 提取字段：mask 0x0FF0 -> 移位 4 位 */
#define FIELD_GET(msk, v) ({ __typeof__(v) _v = (v); \
                             (_v & (msk)) >> (__builtin_ffs(msk) - 1); })

/* 读-改-写：把字段设成 val，其余位保持 */
#define REG_SET_FIELD(reg, msk, val) ({                                 \
    __typeof__(reg) _r = (reg);                                         \
    (_r & ~(msk)) | (((val) << (__builtin_ffs(msk) - 1)) & (msk));      \
})
/* 实测：0x0000A53C mask 0x0FF0 -> 提取 0x53；设成 0x12 -> 0x0000A12C */
```

> 注意真实驱动里这两步之间还需要 **关中断 / 加锁**——语句表达式只保证"表达式级"的原子性，**不保证线程/中断安全**。

### 8.5 container_of（[6.4](../6.4-typeof-container-of/6.4-typeof与container_of宏.md) 的主角）

```c
#define container_of(ptr, type, member) ({                  \
    const __typeof__(((type *)0)->member) *__mptr = (ptr);  \
    (type *)((char *)__mptr - offsetof(type, member)); })
```

**没有语句表达式，这个宏写不出来**——它需要先声明 `__mptr` 做类型检查，再返回计算结果。

## 九、五种坑（实测）

### 坑 1：实参名与宏内临时变量同名 → 自我初始化 UB ★最危险

```c
#define min(a,b) ({ __typeof__(a) _a=(a); __typeof__(b) _b=(b); _a<_b?_a:_b; })

int _a = 100;
int r = min(_a, 1);        /* 展开成：__typeof__(_a) _a = (_a);  <- 用自己初始化自己！ */
```

展开后 `_a` 在自己的初始化表达式里引用自己——**未定义行为**。

| 观测 | 结果 |
|---|---|
| 某次实测返回值 | **-265410072**（垃圾） |
| 另一次实测返回值 | **1**（碰巧对） |
| 外层 `_a` | 始终是 100，没被破坏 |

**最可怕的地方是它"有时对"**：两个栈槽复用时恰好读到外层的值，看起来正常；一旦栈布局变化就返回垃圾。

**告警覆盖率（实测）**：

| 编译器 / 选项 | 能否抓到 |
|---|---|
| gcc `-Wall -Wextra` | ❌ **抓不到**（0 个警告） |
| gcc `-Wall -Wextra -Winit-self` | ✅ `'_a' is used uninitialized [-Wuninitialized]` |
| gcc `-Wshadow` | ✅ `declaration of '_a' shadows a previous local` |
| **clang `-Wall -Wextra`** | ✅ **默认就能抓**：*variable '_a' is uninitialized when used within its own initialization* |

> **给 gcc 用户的建议**：把 `-Winit-self` 和 `-Wshadow` 加进你的编译选项。**clang 默认就比 gcc 安全**。

**内核用 `__x`/`__y` 双下划线能防住吗？** 不能——只是降低了撞名概率，实测 `min_kr(__x, 1)` 同样中招。

**真正防住的办法**：用 `__COUNTER__` 生成唯一变量名，但**必须把变量名作为宏参数传进实现体**：

```c
#define CONCAT_(a,b) a##b
#define CONCAT(a,b)  CONCAT_(a,b)
/* 关键：__COUNTER__ 在调用点只展开一次，变量名作为参数传进来 */
#define min_impl(a, b, ta, tb) ({ __typeof__(a) ta=(a); __typeof__(b) tb=(b); ta<tb?ta:tb; })
#define min_safe(a, b) min_impl(a, b, CONCAT(_sa_, __COUNTER__), CONCAT(_sb_, __COUNTER__))
/* 实测：min_safe(_sa_2, 1) = 1 正确；嵌套 min_safe(min_safe(9,3),5) = 3 正确 */
```

❌ **错误写法**（很多人踩）：在宏体里多处写 `CONCAT(_sa_, __COUNTER__)`——`__COUNTER__` **每次出现都递增**，第二次引用拿到的是 `_sa_2` 而不是 `_sa_0`，直接 `error: '_sa_2' undeclared`。

### 坑 2：返回内部变量的地址（见 [2.2](#22-生命周期到此结束返回地址就是悬垂指针)）

gcc 能告警，clang 沉默。

### 坑 3：类型不匹配只是 warning

```c
#define min_chk(a,b) ({ __typeof__(a) _a=(a); __typeof__(b) _b=(b); \
                        (void)(&_a == &_b);   /* 指针类型不兼容 -> 告警 */ \
                        _a < _b ? _a : _b; })
```

传 `int` 和 `long` 时只有 `warning: comparison of distinct pointer types lacks a cast`。

想要**硬错误**就加 `_Static_assert`：

```c
#define __same_type(a,b) __builtin_types_compatible_p(__typeof__(a), __typeof__(b))
#define min_hard(a,b) ({                                            \
    _Static_assert(__same_type(a,b), "min: argument types differ");  \
    __typeof__(a) _a=(a); __typeof__(b) _b=(b);                      \
    _a < _b ? _a : _b;                                              \
})
/* 实测传 int vs long：error: static assertion failed: "min: argument types differ" */
```

### 坑 4：调试时错误信息指向宏内部

```c
int f(void){ struct { int a; } s; return MAX(s, 3); }
```

gcc 报：

```
error: invalid operands to binary > (have 'struct <anonymous>' and 'int')
note: in expansion of macro 'MAX'
```

错误位置落在**宏定义那一行的第 N 列**，而不是调用点。宏越复杂，越难定位。

### 坑 5：嵌套时的 `-Wshadow`

`min(min(9,3),5)` 能正常工作（实测 3），但 `-Wshadow` 会报两层 `_a` 互相遮蔽。这是**预期行为**（内层块遮蔽外层块），不是 bug，但会让 `-Werror` 项目编译失败。

## 十、四种"打包代码块"方案对比

| 方案 | 有返回值 | 能声明变量 | 类型泛型 | 能当常量 | 典型用途 |
|---|---|---|---|---|---|
| **语句表达式 `({ })`** | ✅ | ✅ | ✅（配 `typeof`） | ❌ | `min`/`max`/`container_of` |
| `do { } while (0)` | ❌ **只是语句** | ✅ | ❌ | ❌ | 多语句宏（日志、断言） |
| **复合字面量 `(T){ }`** | ✅ | ❌（只能初始化） | ❌（要写类型） | ❌ | 临时数组/结构体 |
| `static inline` 函数 | ✅ | ✅ | ❌（类型固定） | ❌（但可常量折叠） | 首选方案（见下） |

实测：`int r = DMAX(1,2);`（`do-while` 版）→ `error: expected expression before 'do'`。

> **优先用 `static inline`**：`-O2` 下性能与宏**完全相同**（第七节实测），而且有类型检查、能调试、无双重求值、无自我初始化风险。
> **只有需要类型泛型时才用语句表达式宏**——这是它不可替代的唯一理由。

## 十一、HFT / 嵌入式关联

| 场景 | 怎么用 |
|---|---|
| **驱动寄存器访问** | `LIMIT_`/`FIELD_GET`/`REG_SET_FIELD` 必须只读一次寄存器（见 [6.2](#62-嵌入式场景这是真事故不是理论问题)） |
| **限幅与饱和** | `clamp()` 在 ADC / PID 输出里天天用，参数带自增时不能重复求值 |
| **HFT 热点路径** | `-O2` 下零开销（与手写一致），但**优先选 `static inline`**——宏的可维护性差 |
| **协议解析** | 报文长度字段校验 `min(hdr->len, sizeof(buf))`，避免 `hdr->len++` 被求值两次 |
| **跨编译器项目** | gcc/clang/g++/clang++ 全支持；但 ISO `-pedantic` 会告警，`-Werror` 项目要评估 |

## 代码自测

**题目 1：** 语句表达式和逗号表达式都能"放多条东西"，区别是什么？
<details>
<summary>答案</summary>

| | 逗号表达式 `(a, b)` | 语句表达式 `({ a; b; })` |
|---|---|---|
| 能声明变量 | ❌ | ✅ |
| 能写 `if` / `for` | ❌（只能是表达式） | ✅ |
| 能 `return` / `break` | ❌ | ✅（穿透到外层） |
| 值 | 最后一项 | 最后一条表达式 |
| 用于消除双重求值 | ❌ 做不到 | ✅ 核心用途 |

逗号表达式解决不了"先存起来再比较"的问题——它没有地方放 `__typeof__(a) _a = (a);` 这条**声明**。

</details>

**题目 2：** `MAX_NAIVE(bump(), 0)` 返回几？`bump()` 被调用几次？
<details>
<summary>答案</summary>

朴素版 `((a) > (b) ? (a) : (b))`：`bump()` 先返回 1，`1 > 0` 成立，于是**再求值一次** `(a)`，得到 2。
**返回 2，调用 2 次。**

语句表达式版：`_a = bump()` 只调用一次 → **返回 1，调用 1 次**。

**注意返回值本身都错了**（2 而不是 1）。实测如此。

</details>

**题目 3：** 为什么 `int g = ({5;});` 编不过，但函数里的 `int g = ({5;});` 可以？
<details>
<summary>答案</summary>

GCC 的限制是 **braced-group within expression allowed only inside a function**——语句表达式只能出现在函数体内。
全局（文件作用域）初始化器必须是**常量表达式**，而语句表达式永远不是常量表达式（哪怕块里只有 `5`）。

函数内的局部初始化器没有这个限制，所以合法。

</details>

**题目 4：** 说出语句表达式在 `-O2` 下的开销，以及它相对 `static inline` 的取舍。
<details>
<summary>答案</summary>

**开销为零**。实测 `-O2` 下 `max_gnu_fn`（宏）与 `max_ref_fn`（手写三元）反汇编完全一致（`cmp / mov / cmovge / ret`）；与 `static inline` 版本也逐字节相同。

**取舍**：既然性能一样，**优先用 `static inline` 函数**——有类型检查、能下断点、无双重求值、无自我初始化 UB。
只有在需要**类型泛型**（同一个宏吃 int/double/指针）时才用语句表达式宏，这是它的不可替代之处。

</details>

**题目 5：** `min(_a, 1)` 为什么会返回垃圾值？怎么防？
<details>
<summary>答案</summary>

宏展开成 `__typeof__(_a) _a = (_a);`——**内部 `_a` 遮蔽了外部 `_a`，于是用自己初始化自己**，读的是未初始化的栈槽，UB。

**可怕之处**：结果不确定。实测一次得到 -265410072，另一次得到正确的 1（两个栈槽恰好复用）。

**检测**：
- gcc `-Wall -Wextra` **抓不到**；需要 `-Winit-self`（报 `used uninitialized`）或 `-Wshadow`
- clang `-Wall -Wextra` **默认就能抓**

**防范**：
1. 宏内临时变量用不易撞名的名字（内核用 `__x`/`__y`，但仍有风险）
2. 用 `__COUNTER__` 生成唯一名，**且必须作为参数传入实现宏**（否则 `__COUNTER__` 每次展开都递增，导致 `undeclared`）
3. 能用 `static inline` 就用 `static inline`

</details>

**题目 6：** 嵌入式里 `LIMIT_NAIVE(read_reg())` 有什么实际危害？
<details>
<summary>答案</summary>

朴素宏里 `v` 出现两次 → **寄存器被读两次**（实测 reads=2，返回的是第二次读到的 101 而非 100）。

危害：
1. **W1C 寄存器**（写 1 清除）：读一次就清一次标志 → 读两次丢中断
2. **自增型 FIFO / DMA 指针**：读一次前进一格 → 读两次丢数据
3. **volatile MMIO**：编译器不会合并两次读，两次访问一定都发生
4. 两次读之间值可能被 ISR 改掉 → 得到"撕裂"的值

改成语句表达式版 `LIMIT_GNU` 后只读一次（实测 reads=1，返回 100）。

</details>

**题目 7：** `({ int _x = 42; &_x; })` 返回什么？gcc 和 clang 谁会告警？
<details>
<summary>答案</summary>

返回**悬垂指针**——`_x` 是语句表达式块内的自动变量，出了右括号就失效。

- **gcc**：`-Wdangling-pointer=` 告警，并精确定位到宏定义里的 `_x` 声明处
- **clang**：**零警告**

要返回一块临时数据，用**复合字面量** `(int[]){1,2,3}`，它的生命周期是所在块（实测有效）。

</details>

**题目 8：** 语句表达式里的 `return` 从哪返回？`break` 跳出哪个循环？
<details>
<summary>答案</summary>

语句表达式**不是函数**，它是内联展开的一段代码，所以所有跳转都作用于**外层**：

- `return` → 从**包含它的函数**返回（实测 `early_return(-5)` 返回 -1）
- `break` / `continue` → 作用于**外层循环**
- `goto` → 跳到**外层标签**

宏里需要局部标签时用 `__label__`（gcc/clang 都支持），避免同一函数多次展开时标签重复定义。

</details>

**题目 9：** 为什么 `min` 要配 `(void)(&__x == &__y);`？它够强吗？
<details>
<summary>答案</summary>

这行是**类型检查**：对两个不同类型的指针做 `==` 比较，编译器会告警。
它能在 `min(int, long)` 这种误用时给出 `comparison of distinct pointer types lacks a cast`。

**不够强**——只是 warning，`-Werror` 之外的项目可能被忽略。

**加强版**用 `_Static_assert` + `__builtin_types_compatible_p`，直接变成**硬错误**：

```c
_Static_assert(__same_type(a,b), "min: argument types differ");
/* 实测：error: static assertion failed: "min: argument types differ" */
```

</details>

**题目 10：** 下面这段代码错在哪？
```c
#define CONCAT_(a,b) a##b
#define CONCAT(a,b)  CONCAT_(a,b)
#define min_bad(a,b) ({                                 \
    __typeof__(a) CONCAT(_sa_, __COUNTER__) = (a);       \
    __typeof__(b) CONCAT(_sb_, __COUNTER__) = (b);       \
    CONCAT(_sa_, __COUNTER__) < CONCAT(_sb_, __COUNTER__) \
        ? CONCAT(_sa_, __COUNTER__) : CONCAT(_sb_, __COUNTER__); \
})
```
<details>
<summary>答案</summary>

**`__COUNTER__` 每次展开都递增**，所以声明时是 `_sa_0`，后面引用时却变成了 `_sa_2`、`_sa_3`……
实测报错：`error: '_sa_2' undeclared (first use in this function); did you mean '_sa_0'?`

**正确写法**：让 `__COUNTER__` 在**调用点只展开一次**，变量名作为宏参数传进实现体：

```c
#define min_impl(a, b, ta, tb) ({ __typeof__(a) ta=(a); __typeof__(b) tb=(b); ta<tb?ta:tb; })
#define min_safe(a, b) min_impl(a, b, CONCAT(_sa_, __COUNTER__), CONCAT(_sb_, __COUNTER__))
```

</details>

**题目 11：** 语句表达式在 C++ 里能用吗？在 `-std=c11 -pedantic` 下呢？
<details>
<summary>答案</summary>

- **C++**：`g++ -std=c++11/17` 与 `clang++ -std=c++17` **都能用**，零诊断。所以头文件里用语句表达式不会把 C++ 用户挡在门外。
- **`-std=c11 -pedantic`**：能编过，但有告警——gcc 报 `ISO C forbids braced-groups within expressions`，clang 报 `use of GNU statement expression extension`。
- **不带 `-pedantic`**：gcc/clang 在 c99/c11/c17/c2x/gnu* **全部零诊断**。

对比 `typeof`：裸 `typeof` 在 ISO 模式下是**硬错误**（关键字层面冲突），语句表达式只是 warning（语法层面扩展）。

</details>

**题目 12：** 一句话说清 `typeof` 和语句表达式为什么必须成对出现。
<details>
<summary>答案</summary>

- `typeof` 让宏**知道该声明什么类型的临时变量**
- 语句表达式给宏**一个能放声明语句的局部作用域**

只有 `typeof` 而没有语句表达式：你算出了类型，却没地方写 `__typeof__(a) _a = (a);` 这条语句（表达式上下文不能出现声明）。
只有语句表达式而没有 `typeof`：你能声明变量，却不知道该声明成什么类型（除非再让调用方传类型名，像内核的 `min_t(type, a, b)`）。

两者合体 = **类型泛型 + 只求值一次 + 零运行时开销**，这就是 `min`/`max`/`container_of`/`swap` 的全部秘密。

</details>
