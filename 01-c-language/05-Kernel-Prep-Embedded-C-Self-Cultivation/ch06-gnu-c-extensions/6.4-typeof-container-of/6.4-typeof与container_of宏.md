# 6.4 typeof与container_of宏

## 本节讲什么

**typeof** 在编译期取得表达式类型；**container_of** 从结构体成员指针反推宿主结构体地址。二者是 Linux 内核 **侵入式链表**、**device model** 的基石；DPDK 部分代码沿用相同技巧。

## 要点

- `typeof(x)` 等价于 `x` 的类型，可声明临时变量
- `container_of(ptr, type, member)` = `ptr` 所在 `type` 的首地址
- 依赖 **GNU typeof** + **语句表达式** + **`offsetof`**

## 代码自测

**题目 1：** 写出一个简化版 `container_of` 宏，并解释它如何工作。为什么不能用简单的指针减法？
```c
struct node { int data; struct node *next; };
struct node n;
struct node *np = &n.next;  // 假设有这个成员
// 如何从 np 得到 &n ?
```

<details>
<summary>参考答案</summary>

```c
#define container_of(ptr, type, member) ({ \
    const typeof(((type *)0)->member) *__mptr = (ptr); \
    (type *)((char *)__mptr - offsetof(type, member)); \
})
```
原理：(1) `typeof` 取成员指针类型，确保类型安全；(2) `offsetof(type, member)` 算出成员在结构体中的偏移；(3) 成员指针减偏移得到宿主结构体首地址。不能简单减法是因为不同成员偏移不同，且需要类型检查。`typeof` 是 GNU 扩展。Linux 内核侵入式链表 `list_entry` 就基于此。

</details>
