# 6.9.3 弱符号的用途

## 本节讲什么

Weak 典型场景：**默认 stub**、**可选 feature**、**测试 mock**、**单内核多 BSP**。避免 `#ifdef` 泛滥；链接时自动选最强定义。本节展开四种主流用法、`alias + weak` 组合、与 `#ifdef` 的取舍。

## 要点

### 用法一：默认 stub（BSP/驱动钩子）

```c
/* 默认空实现，板级可覆盖 */
void __attribute__((weak)) pm_suspend(void) { }
void __attribute__((weak)) trace_irq(int irq) { (void)irq; }
```

调用方代码不变，链接时若 BSP 提供 strong 实现则自动选中。

### 用法二：Kconfig 可选 feature

```c
/* kernel/panic.c */
void __attribute__((weak)) panic_handler(const char *msg) { /* 默认空 */ }

/* 如果 CONFIG_DEBUG_PANIC 开启，debug.c 提供 strong 版本打印栈 */
```

Kconfig 关闭 feature 时仍链 weak stub，无需 `#ifdef` 包裹调用点。

### 用法三：单测 mock

```c
/* prod.c */
time_t time_now(void) { return real_clock(); }

/* test.c */
time_t time_now(void) { return fake_time; }   /* 强符号，单测链接时覆盖 */
```

测试程序链接 `test.o` + `prod.o`（去掉原 `time_now` 或保留 weak 版），mock 自动生效。无需改生产代码。

### 用法四：alias + weak 组合（默认实现可被部分覆盖）

```c
static void default_log(int level, const char *msg) {
    fprintf(stderr, "[%d] %s\n", level, msg);
}
void log_info(int level, const char *msg)
    __attribute__((weak, alias("default_log")));
```

`alias` 让 `log_info` 默认指向 `default_log`，弱符号允许用户重写 `log_info` 而无需碰 `default_log`。内核 `__weak` + `__alias` 在 `init/main.c` 处处可见。

### 与 `#ifdef` 的取舍

| 维度 | `#ifdef` | weak |
|------|----------|------|
| 编译期 vs 链接期 | 编译期决定 | 链接期决定 |
| 灵活性 | 必须重新编译 | 换 `.o` 即可 |
| 可读性 | 嵌套 `#ifdef` 难读 | 调用点干净 |
| 可测试性 | 测试需 mock 头文件 | 直接 strong 覆盖 |
| 适用 | 编译时配置（Kconfig 项） | 运行时多板/多场景 |

经验：**编译时确定的差异用 `#ifdef`**（如 `CONFIG_SMP`），**链接时可替换的用 weak**（如 BSP 钩子）。

| 场景 | 说明 |
|------|------|
| BSP | 板级 `board_init` 覆盖 weak 空函数 |
| Kconfig 关闭 feature | 仍链 weak stub |
| 单测 | 测试文件 strong 替换 `time_now()` |
| 库默认行为 | libc/数学库弱 stub，应用可覆盖 |

- 与 **6.9.4 alias** 组合：`alias("default")` + weak
- 内核 `__weak` 宏定义在 `include/linux/compiler.h`，跨编译器抽象

## 常见陷阱

1. **weak 函数被内联后失去 weak 语义**
   如果 weak 函数在头文件中 `inline` 定义，调用方可能直接内联默认版，**链接期 strong 覆盖失效**。坑：`static inline __attribute__((weak))` 几乎肯定是错的——`static` 已限定本编译单元，weak 无意义。weak 必须是**具有外部链接**的函数，定义在 `.c` 文件中。

2. **LTO 下 weak 行为变化**
   `-flto` 跨编译单元优化时，编译器可能"看穿" weak 函数调用，直接内联默认实现，**绕过 strong 覆盖**。GCC 10+ 修复了大部分场景，但边界情况仍有问题。生产代码用 LTO + weak 需测试覆盖确认。内核默认不开 LTO（部分架构可开 `CONFIG_LTO`）。

3. **weak 不能覆盖动态库符号（默认）**
   可执行文件调 `printf`，libc 中 `printf` 即使被声明 weak，**运行时仍走 libc 实现**——主可执行文件的符号优先级高于 `.so`，但**反之不行**：`.so` 中的 strong 定义不会覆盖主程序中的 weak 定义（除非 `LD_PRELOAD` 或 `dlopen(RTLD_GLOBAL)`）。误以为"weak 总能被覆盖"在动态链接下踩坑。

## 自测题

**1.（选择）** 以下哪种场景**最适合**用 weak 而不是 `#ifdef`？
- A. 编译时根据 `CONFIG_SMP` 决定是否启用自旋锁
- B. 不同 BSP 提供不同 `board_early_init` 实现
- C. 调试版本打开详细日志
- D. 64 位 vs 32 位平台差异

<details><summary>答案</summary>

**B**。BSP 差异在**链接时**通过替换 `.o` 文件实现，无需重新编译内核主体——正是 weak 的适用场景。A/C/D 都是**编译期配置**，`#ifdef` 更合适（编译时决定，运行时无开销）。weak 的代价是**间接调用**（无法内联），编译期配置零运行时开销。

</details>

**2.（判断）** `static inline void f(void) __attribute__((weak));` 是合理的 weak 用法。

<details><summary>答案</summary>

**错**。`static` 限定符号为编译单元内部，无外部链接，weak 属性无意义（链接器看不到该符号）。`inline` 进一步暗示编译器内联，更削弱"链接期覆盖"语义。**正确写法**：weak 函数必须 `extern`（默认），定义在 `.c` 文件中，调用方通过头文件 `extern` 声明看到 weak 标记。

</details>

**3.（踩坑）** 单测中 mock 了 `time_now`（strong 覆盖 weak 默认实现），生产代码用 `-O2` 编译。单测跑过，但**线上仍用默认实现**。定位后发现 `time_now` 在头文件中 `static inline` 定义。为什么？

<details><summary>答案</summary>

**`static inline` 函数无外部链接，weak 失效，调用方直接内联默认实现**。链接期 strong 版本根本没机会被选中——编译器已在每个调用点展开默认代码。**修复**：
1. 默认实现移到 `.c` 文件，去掉 `static inline`，标 `weak`。
2. 头文件只留 `extern` 声明（带 weak 属性）。
3. 关键路径若性能敏感，用宏或 `always_inline` 内联版 + weak 兜底版双轨。
**教训**：weak 与 inline 是对立语义——inline 要求编译期展开，weak 要求链接期替换，二者不可兼得。

</details>

**4.（应用）** 用 `alias + weak` 实现一组日志函数，默认全部转发到 `default_log`，但允许用户单独覆盖 `log_err`。

<details><summary>答案</summary>

```c
/* log_default.c */
#include <stdio.h>
static void default_log(int level, const char *msg) {
    fprintf(stderr, "[%d] %s\n", level, msg);
}

void log_info(int lvl, const char *msg)
    __attribute__((weak, alias("default_log")));
void log_warn(int lvl, const char *msg)
    __attribute__((weak, alias("default_log")));
void log_err(int lvl, const char *msg)
    __attribute__((weak, alias("default_log")));
```
```c
/* app.c — 只覆盖 log_err */
#include "log.h"
void log_err(int lvl, const char *msg) {   /* 不写 weak = 强 */
    fprintf(stderr, "ERROR: %s\n", msg);
    notify_ops_team(msg);
}
```
要点：
- `alias` 让多个符号默认指向同一实现，避免重复代码。
- `weak` 允许单独覆盖某一符号，其他仍走 alias。
- 覆盖方不带 weak（自动成强）。
- 内核 `printk` 体系、glibc 多个 `__libc_*` 别名都用此模式。

</details>
