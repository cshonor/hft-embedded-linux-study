# 9.4.1 基本概念

## 本节讲什么

头文件（`.h`）通过 `#include` 被**文本插入**到源文件中，形成**翻译单元**——编译器每次只看到一个 `.c` 及其展开后的内容。本节澄清预处理机制、include guard、头文件与源文件的职责分工，为后续声明/定义规则打基础。

## 要点

**`#include` 本质**：

```c
#include "mod_uart.h"   /* 先搜当前目录，再 -I 路径 */
#include <stdio.h>      /* 仅搜系统/ -I 标准路径 */
```

- 预处理是**纯文本替换**，不是链接
- 同一 guard 保护的头在同一翻译单元只展开一次

**include guard 标准写法**：

```c
#ifndef MOD_UART_H
#define MOD_UART_H

/* 声明区 */

#endif /* MOD_UART_H */
```

| 方式 | 优点 | 注意 |
|------|------|------|
| `#ifndef`/`#define` | 可移植、内核标准 | guard 名全局唯一 |
| `#pragma once` | 简洁 | 极少数老编译器；内核较少用 |

**头文件 vs 源文件**：

| 文件 | 放什么 | 不放什么 |
|------|--------|----------|
| **`.h`** | 函数声明、typedef、`enum`、宏、`extern` 变量声明 | 非 inline 函数体、变量定义 |
| **`.c`** | 函数定义、变量定义、`static` 实现 | 通常不被其他模块 include |

**翻译单元与符号**：

```
main.c  +  #include 展开  →  编译  →  main.o
mod_uart.c                  →  编译  →  mod_uart.o
                                    ↘
                              链接 → app.elf
```

- 每个 `.c` **独立编译**；类型不匹配在编译期报错，符号缺失在链接期报错
- 头文件是多个 `.c` 之间的**类型契约**，必须一致（**9.4.6**）

**头文件注释模板**：

```c
/**
 * @file mod_uart.h
 * @brief UART 驱动公开 API
 * @note 线程不安全；多线程请外部加锁
 */
```

## 代码自测

**题目 1：** C 语言中声明和定义的区别是什么？以下哪些是声明，哪些是定义？
```c
extern int x;        // ?
int y = 10;           // ?
int z;                // ?
void func(void);      // ?
void func(void) {}    // ?
struct point { int x; }; // ?
```
<details>
<summary>参考答案</summary>

声明（Declaration）：告诉编译器某个名字的类型，不分配存储。
定义（Definition）：分配存储/生成代码。

- `extern int x`：**声明**（告诉编译器 x 存在，定义在别处）
- `int y = 10`：**定义**（分配内存并初始化）
- `int z`：**定义**（C 中未初始化全局变量是"暂定定义"tentative definition，分配 BSS 内存）
- `void func(void)`：**声明**（函数原型）
- `void func(void) {}`：**定义**（函数实现）
- `struct point { int x; }`：**定义**（定义结构体类型）

规则：
- 一个变量/函数只能定义一次，可以声明多次
- 头文件放声明，源文件放定义
- `extern` 关键字表示"声明而非定义"
- `struct/union/enum` 类型定义可以多次出现（只要完全一致）

`int z;` 在 C 中是暂定定义（tentative definition）：如果别处有完整定义则作为声明，否则作为定义（值 0）。

</details>
