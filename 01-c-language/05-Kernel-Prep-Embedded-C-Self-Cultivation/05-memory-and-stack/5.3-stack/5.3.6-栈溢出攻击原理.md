# 5.3.6 栈溢出攻击原理

## 本节讲什么

**栈溢出**：写越界覆盖相邻栈内容，典型目标是 **saved LR/返回地址** 或 **栈 canary**。历史上用于注入 shellcode；现代有 **NX、ASLR、Stack Protector**。嵌入式无 MMU 时同样会因栈越界踩坏相邻 RAM。

## 要点

### 成因

```c
void vuln(void) {
    char buf[64];
    gets(buf);              /* 无边界检查 → 覆盖 fp/lr */
}
```

- 递归过深、超大局部数组 → **合法但危险**，触发 SIGSEGV
- **demo03**（见 demo/README）：无限递归或超大数组，用 GDB 观察

```bash
gcc -g -O0 -fstack-protector-all -o vuln vuln.c
ulimit -s 4096
gdb ./vuln
(gdb) run
(gdb) bt
(gdb) info registers sp lr
```

### 防护

| 机制 | 作用 |
|------|------|
| `-fstack-protector` | 帧入口插入 canary，返回前校验 |
| NX / W^X | 栈不可执行 |
| ASLR | 栈/库基址随机 |
| **ASAN** | 编译期插桩，检测越界（`-fsanitize=address`） |

```bash
gcc -fsanitize=address -g -O0 -o vuln_asan vuln.c
./vuln_asan
```

### 嵌入式规则

- **禁止** `gets/strcpy/sprintf` 无界 API；用 `snprintf`、显式长度
- 为每任务 **实测栈水位**（填充字 + 运行时检查）
- 内核栈仅 **8KB/16KB** 级，内核代码严禁大栈数组

## 代码自测

**题目 1：** 以下代码有什么安全漏洞？攻击者如何利用？
```c
void check_password(void) {
    char password[8];
    int authorized = 0;
    printf("Enter password: ");
    gets(password);  // 危险！
    if (strcmp(password, "secret") == 0)
        authorized = 1;
    if (authorized)
        printf("Access granted!\n");
}
```
<details>
<summary>参考答案</summary>

**栈溢出漏洞**：`gets()` 不检查输入长度，攻击者输入超过 8 字符会覆盖 `password` 后面的 `authorized` 变量。

内存布局（栈从高到低）：`authorized(4字节)` → `password(8字节)`

攻击：输入 12 个字符（8 填满 password + 4 覆盖 authorized 为非零）→ 跳过密码检查。

更严重：如果输入足够长，可以覆盖返回地址（LR），跳转到任意代码（shellcode）。

防护：
- 用 `fgets(password, sizeof(password), stdin)` 限制长度
- 栈保护（Stack Canary）：编译器在返回地址前插入随机值，返回前检查
- ASLR：地址空间随机化
- NX：栈不可执行
- `gcc -fstack-protector` 启用栈保护

</details>
