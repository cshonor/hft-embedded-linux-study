# 8.3 Linux内核中的OOP思想：封装

## 本节讲什么

Linux 内核是 **C 模拟 OOP** 的教科书：**不透明抽象**、**list 封装**、**device/bus 分层**都体现封装思想。本节总览内核如何用「只暴露必要接口」控制复杂度——驱动作者操作 `struct device` 与 `list_head` 钩子，而非直接遍历全局数组；链表实现细节藏在 `list_add()` 内部。

## 要点

**内核封装三层**：

| 层次 | 机制 | 隐藏的内容 |
|------|------|------------|
| **类型封装** | 不完整 struct 声明 | 驱动私有数据布局 |
| **API 封装** | `list_add`/`list_del` | 指针 manip 细节 |
| **子系统封装** | `device_register` | 总线匹配、uevent、sysfs |

```c
/* include/linux/list.h — 公开 */
struct list_head {
    struct list_head *next, *prev;
};

static inline void list_add(struct list_head *new, struct list_head *head);

/* 驱动 embed 链表节点，不直接改 next/prev */
struct my_driver {
    struct list_head node;
    int irq;
};
```

- **`container_of`**（**ch06 6.4**）是从封装节点「解密」宿主对象的唯一推荐路径
- **`dev_set_drvdata` / `dev_get_drvdata`** 把私有指针挂在 `struct device` 上，进一步封装
- 错误示范：驱动直接访问 `bus->devices` 内部数组 → 内核版本升级即 break

## 代码自测

**题目 1：** Linux 内核如何用 C 实现 OOP 封装？struct file 和 struct file_operations 的关系是什么？
```c
struct file {
    const struct file_operations *f_op;
    void *private_data;
    // ...
};
// 使用
struct file *f = filp_open("/dev/tty", O_RDWR, 0);
f->f_op->read(f, buf, len, &pos);
```
<details>
<summary>参考答案</summary>

内核 OOP 封装：

1. **对象**：`struct file` 代表一个打开的文件（实例）
2. **方法表**：`struct file_operations` 是函数指针表（类的方法集合）
3. **绑定**：`f->f_op` 指向具体文件系统的 file_operations（多态绑定）
4. **私有数据**：`f->private_data` 存储设备特定数据（封装）

封装机制：
- `struct file` 定义在内核头文件中（公开）
- 内部字段由内核管理，驱动不直接修改大部分字段
- 驱动通过 `f->private_data` 存储自己的数据（类似 C++ 的 this）
- `file_operations` 是接口约定，驱动按需实现

调用流程：
- `read()` 系统调用 → VFS → `f->f_op->read(f, ...)` → 具体驱动的 read 实现
- 不同文件系统（ext4/proc/sysfs）注册不同的 file_operations
- 用户态调用统一的 read()，底层多态分发

</details>
