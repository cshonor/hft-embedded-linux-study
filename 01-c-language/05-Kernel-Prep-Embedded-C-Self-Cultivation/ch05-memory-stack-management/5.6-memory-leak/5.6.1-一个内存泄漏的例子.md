# 5.6.1 一个内存泄漏的例子

## 本节讲什么

最小泄漏：`malloc` 后 **从不 free**，进程退出时 OS 回收，但 **长期运行** 会耗尽内存。`demo04_heap_leak.c` 故意泄漏 1024 字节供工具抓现行。

## 要点

```c
void *p = malloc(1024);
(void)p;
return 0;   /* 泄漏：无 free，无其它指针指向 p */
```

```bash
cd demo && make demo04_heap_leak
valgrind --leak-check=full --show-leak-kinds=all ./demo04_heap_leak
# ==xxx== 1024 bytes in 1 blocks are definitely lost in loss record 1 of 1
# ==xxx==    at 0x...: malloc (...)
# ==xxx==    by 0x...: main (demo04_heap_leak.c:6)
```

### 变体

- 循环 `malloc(64)` 不 free → RSS 持续升
- 重新赋值丢旧指针：`p = malloc(n); p = malloc(m);` 第一块泄漏

```bash
/usr/bin/time -v ./demo04_heap_leak   # Maximum resident set size
```

## 代码自测

**题目 1：** 以下代码有两处内存泄漏，分别是什么？
```c
void func(void) {
    char *p = malloc(100);
    p = malloc(200);  // 泄漏1
    char *q = malloc(50);
    if (some_error) {
        return;       // 泄漏2
    }
    free(p);
    free(q);
}
```
<details>
<summary>参考答案</summary>

泄漏 1：`p = malloc(200)` 覆盖了第一次 malloc(100) 的指针，100 字节的内存无法释放（原指针丢失）。

泄漏 2：`some_error` 为真时直接 return，p 和 q 都没 free。

修复：
```c
void func(void) {
    char *p = malloc(100);
    // 使用 p...
    free(p);           // 先释放
    p = malloc(200);   // 再重新分配
    char *q = malloc(50);
    if (some_error) {
        free(p); free(q);  // 错误路径也要释放
        return;
    }
    free(p); free(q);
}
```

原则：每个 malloc 必须有对应的 free，包括所有 return 路径。用 goto cleanup 模式处理错误路径。

</details>
