# 5.6 内存泄漏与防范

## 本节讲什么

**内存泄漏**：已分配堆块 **失去所有指针** 且未 `free`，进程 RSS 单调涨。长期运行的服务器、嵌入式长期任务、DPDK 数据面均需 **配对分配/释放** 与工具检测。

## 要点

- 典型：`malloc` 后丢指针、异常路径未 `free`、循环里重复 alloc
- 检测：**Valgrind**、**mtrace**、ASAN leak、内核 **kmemleak**
- 预防：谁分配谁释放、RAII 思想（C 里 goto cleanup）、池化复用

```bash
cd demo && valgrind --leak-check=full ./demo04_heap_leak
```

## 代码自测

**题目 1：** 以下函数有什么内存泄漏风险？如何用 `valgrind` 检测？
```c
char *make_msg(int n) {
    char *buf = malloc(100);
    if (n < 0) return NULL;  // 泄漏！
    snprintf(buf, 100, "value=%d", n);
    return buf;
}
```

<details>
<summary>参考答案</summary>

`n < 0` 时直接返回 NULL，已分配的 100 字节 `buf` 泄漏——调用者无法 `free`。修法：`if (n < 0) { free(buf); return NULL; }`。用 `valgrind --leak-check=full ./a.out` 检测，会报告 `definitely lost: 100 bytes in 1 blocks`，并给出泄漏点的调用栈。嵌入式无 valgrind 时可用 `mtrace` 或 ASAN 的 `__lsan_do_leak_check`。

</details>
