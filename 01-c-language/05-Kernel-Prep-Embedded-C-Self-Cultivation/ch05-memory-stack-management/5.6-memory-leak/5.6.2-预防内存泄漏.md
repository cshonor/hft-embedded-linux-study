# 5.6.2 预防内存泄漏

## 本节讲什么

从 **设计习惯** 上保证每条 `malloc` 路径都有对应 `free`：单一出口 cleanup、结构体析构函数模式、避免隐式所有权转移混乱。

## 要点

### 实践

```c
int foo(void) {
    char *p = malloc(n);
    if (!p) return -1;
    if (err) { free(p); return -1; }   /* 每出口释放 */
    ...
    free(p);
    return 0;
}
```

- **配对 API**：`fopen/fclose`、`mmap/munmap`、`rte_malloc/rte_free`
- **容器销毁函数**：`list_destroy()` 内部遍历 free
- 禁用或封装裸 `malloc`；用 **静态分析**（clang-tidy `clang-analyzer-*`）

### 内核 / 嵌入式

- **kmalloc 必须 kfree**；错误路径 `goto err_free`
- 裸机池：**固定生命周期** 对象不 free，重启时整块回收
- **DPDK mempool**：预分配 mbuf，用完 `rte_pktmbuf_free` 回池，非传统 free

```bash
cppcheck --enable=all *.c
```

## 代码自测

**题目 1：** C 语言中预防内存泄漏有哪些最佳实践？
<details>
<summary>参考答案</summary>

预防内存泄漏的最佳实践：

1. **谁分配谁释放**：malloc 和 free 在同一函数内，或分配方提供配套的 free 函数
2. **goto cleanup 模式**：错误路径统一跳转到 cleanup 标签释放
```c
int func(void) {
    char *a = malloc(100);
    if (!a) return -1;
    char *b = malloc(200);
    if (!b) goto free_a;
    // ...
    free(b);
free_a:
    free(a);
    return 0;
}
```
3. **配对检查**：代码审查时数 malloc/free 个数是否匹配
4. **RAII 模拟**：用 `__attribute__((cleanup))` 自动释放
5. **工具辅助**：Valgrind/ASan 定期检测
6. **引用计数**：复杂生命周期用引用计数管理
7. **内存池**：批量分配/释放，减少遗漏

</details>
