# 5.5.2 mmap 映射实现机制分析

## 本节讲什么

用户态 `mmap()` → 内核 **`do_mmap`/`mmap_region`**：在进程 **mm_struct** 找空洞建 **VMA**，`mmap` 文件则挂 **file->f_mapping**，匿名则只 reserve 虚拟区；**首次访问** 触发缺页分配物理页或读入页缓存。

## 要点

### 流程

1. 找合适虚拟地址（`mmap_base` 向下或 `hint`）
2. 创建 VMA（`vm_area_struct`：start/end/prot/flags/file）
3. 读/写缺页 → **filemap_fault** 或 **匿名零页**
4. `munmap` 拆 VMA、释放页表项

```bash
cat /proc/self/maps
# 地址范围 权限 offset dev inode pathname
```

### 与 brk

| brk | mmap |
|-----|------|
| 堆顶连续 bump | 任意空洞 |
| 小对象 heap | 大块、文件、设备 |
| 单 main arena 延伸 | 独立 VMA |

- **TLB shootdown**：多核修改页表需 IPI
- **内核模块**：`ioremap` 把 **物理 MMIO** 映射到内核虚拟（非用户 mmap）

## 代码自测

**题目 1：** mmap 的内核实现机制是什么？为什么 mmap 不立即分配物理内存？
<details>
<summary>参考答案</summary>

mmap 内核机制：

1. **建立虚拟映射**：mmap 只在进程的 VMA（Virtual Memory Area）链表中记录一段虚拟地址范围的属性（权限、映射对象、偏移），**不分配物理内存**
2. **缺页中断**：首次访问该虚拟地址时触发缺页异常
3. **分配物理页**：内核分配物理页面，从文件读取对应数据填入
4. **建立页表映射**：将虚拟地址映射到物理页

这就是**延迟分配**（demand paging）：只有实际访问时才分配物理内存，节省内存。

对于匿名 mmap（无文件）：缺页时分配零页（zero page）。

MAP_SHARED 的写入通过页缓存写回文件（write-back）。

</details>
