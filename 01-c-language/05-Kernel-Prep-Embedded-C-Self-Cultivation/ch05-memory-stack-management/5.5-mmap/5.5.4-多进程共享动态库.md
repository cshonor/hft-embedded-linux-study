# 5.5.4 多进程共享动态库

## 本节讲什么

**动态库 `.so`** 经 **ld.so** `mmap` 进各进程，**代码段只读共享** 物理页，**数据段 per-process CoW**。多进程同时跑同一 `.so` 省 RAM——与 **ch04 4.8** PIC/GOT/PLT 衔接。

## 要点

```bash
gcc -fPIC -shared -o libfoo.so foo.c
gcc -o app app.c -L. -lfoo
ldd app
cat /proc/self/maps | grep libfoo
```

| 段 | 共享 |
|----|------|
| `.text` / `.rodata` | 多进程共享同一物理页 |
| `.data` / `.bss` | 映射后 CoW，各自副本 |

- **GOT/PLT**：每进程一份 GOT 写权限页；延迟绑定改 GOT 项
- **内核模块**：类似共享库，但在内核空间 `insmod` 链接导出符号
- **DPDK**：静态链 PMD 常见；动态插件亦靠 `dlopen` + mmap

```bash
readelf -d app | grep NEEDED
pmap -x $$ | grep '\.so'
```

## 与后续衔接

- **ch04 4.8** GOT/PLT/延迟绑定
- **5.2** maps 中 `r-xp` 库路径行

## 代码自测

**题目 1：** 多个进程加载同一个 .so 文件时，如何实现内存共享？
<details>
<summary>参考答案</summary>

共享库映射机制：

1. **代码段共享**：.so 的 .text 段以 MAP_SHARED|PROT_READ 映射，多个进程映射到同一物理页（页缓存）。每个进程的虚拟地址不同，但物理页相同。
2. **数据段私有**：.so 的 .data/.bss 以 MAP_PRIVATE 映射（写时复制）。某进程修改全局变量时，触发 COW，分配新物理页，不影响其他进程。
3. **GOT/PLT 私有**：每个进程有自己的 GOT（存储已解析的函数地址）。

节省内存：1MB 的 libc.so 被 100 个进程使用，代码段只占 1MB 物理内存（非 100MB）。

`cat /proc/PID/maps` 可看到不同进程的 libc 映射虚拟地址不同，但 `pmap` 显示的 RSS（物理内存）中共享部分标记为 S（shared）。

</details>
