# 5.7.5 内存检测神器：Valgrind

## 本节讲什么

**Valgrind Memcheck** 在 **虚拟 CPU** 上跑程序，拦截每次内存访问，报告 **非法读写、未初始化使用、泄漏、double free**。开发期标配；ARM Linux 可用，嵌入式裸机不可用。

## 要点

### 常用命令

```bash
valgrind --leak-check=full --show-leak-kinds=all ./demo04_heap_leak
valgrind --track-origins=yes ./prog          # 未初始化值来源
valgrind --tool=memcheck --vgdb=yes ./prog   # 配合 gdb
valgrind --help
```

### 报告解读

```
Invalid read of size 4          → 越界读
Use of uninitialised value    → 未初始化
Invalid free / double free    → 释放错误
definitely lost               → 确定泄漏
```

### 与 ASAN 对比

| | Valgrind | ASAN |
|--|----------|------|
| 原理 | 动态二进制翻译 | 编译插桩 |
| 速度 | 很慢 | 约 2x 慢 |
| 需重编译 | 否 | 是 |
| 内核 | 否 | KASAN（内核） |

```bash
gcc -fsanitize=address,undefined -g -O0 -o prog prog.c
./prog
# 内核模块：CONFIG_KASAN=y
```

### DPDK 注意

- 用户态 DPDK 可在 **非 PMD 测试代码** 上 Valgrind；性能路径/hugepage 行为可能误报，需 `--suppressions`

## 代码自测

**题目 1：** Valgrind 的 Memcheck 能检测哪些内存错误？以下命令的输出含义是什么？
```c
$ valgrind --leak-check=full ./a.out
==12345== Invalid read of size 4
==12345==    at 0x40053A: main (test.c:5)
==12345==  Address 0x5203040 is 0 bytes inside a block of size 40 free'd
```
<details>
<summary>参考答案</summary>

Valgrind Memcheck 检测的内存错误类型：
- **Invalid read/write**：访问未分配/已释放的内存
- **Use of uninitialized value**：使用未初始化的变量
- **Invalid free**：重复释放或释放非堆指针
- **Memory leak**：malloc 没有 free（分 definitely lost / indirectly lost）
- **Syscall with invalid pointer**：系统调用传入非法指针

输出解读：
- `Invalid read of size 4`：在第 5 行读取了 4 字节（如 int）的无效内存
- `Address ... is 0 bytes inside a block of size 40 free'd`：该地址在一个已 free 的 40 字节块开头 → **Use-After-Free**

Valgrind 原理：JIT 翻译，在每条指令前插入检查代码。性能开销 10-20 倍。

替代方案：ASan（`-fsanitize=address`），编译时插桩，开销 2 倍，适合 CI 流水线。

</details>
