导读

本章目标

掌握 C 声明的统一读法：把任意声明拆成 存储类 + 基本类型 + 声明符；熟练运用 螺旋规则（Spiral Rule） 与 图表法 解析 *、[]、() 嵌套；理解 typedef 与 #define 的本质区别 及 PSTR 陷阱；能口述 书中全部例题（含 signal）；为 ch04 数组非指针、ch08 类型转换、Embedded ch07 指针 提供类型阅读能力。

核心算法：螺旋规则四步

步骤 动作
1 找到 identifier，写「X 是 ……」
2 顺时针 扫描：括号 由内向外 优先
3 遇 [N] → 数组（N 个元素）；遇 (params) → 函数；遇 * → 指针
4 函数写 返回类型；数组写 元素类型；指针写 指向类型；重复至基本类型

优先级：( ) 改变顺序 → [] 与 () 优先于 *（详见 3.3）。

四组对比表（必背）

声明 主体类型 完整含义
char *str[10] 数组 10 个元素，每个元素是 char*（指针数组）
char (*p)[10] 指针 指向含 10 个 char 的数组（数组指针）
int (*func)(int, char) 指针 指向「接受 (int,char)，返回 int」的函数
int *f(int) 函数 接受 int，返回 int*（对比：int (*fp)(int) 才是函数指针）

扩展对比（3.8）：

声明 含义
int *(*a[10])() 数组 [10]：元素为「返回 int* 的无参函数指针」
int (*(*a)[10])() 指针 → 指向 [10] 数组：元素为「返回 int 的无参函数指针」

3.1

只有编译器才会喜欢的语法

本节讲什么

本章开篇点题：C 语言的声明语法是为编译器设计的，不是为人设计的。同一行里 *、[]、() 反复出现，读起来像「绕口令」，却是面试、读头文件、写函数指针时的基本功。本节说明 为何声明难读、为何必须学，并预告全书唯一的通用解法——螺旋规则（Spiral Rule）。

要点

声明为何让人头疼

C 声明把 类型信息 和 名字 揉在一起，且 从右向左、由内向外 绑定，与日常从左到右阅读习惯相反：

int *p;              /* p 是指向 int 的指针 */
int *p, q;           /* 常见误解：p、q 都是指针？错！只有 p 是指针，q 是 int */
char *str[10];       /* str 是数组，元素是指向 char 的指针 */
char (*p)[10];       /* p 是指针，指向含 10 个 char 的数组 */
int (*func)(int, char); /* func 是指针，指向接受 (int,char) 返回 int 的函数 */
现象 原因
* 贴类型还是贴名字？ 语法上属于 declarator；int* p, q 不能表示两个指针
[] 与 * 谁优先？ [] 和 () 优先于 *（见 3.3）
多层嵌套 函数返回指针、指针指向函数、数组元素是指针……组合爆炸
typedef 再叠一层 宏替换与 typedef 作用域不同（3.5–3.6）

「只有编译器才会喜欢」

  • 历史：B/C 单遍编译、声明与使用分离；语法极简，不引入类似 Pascal var p: ^integer 的显式类型后置写法。
  • 符号过载：*、&、[] 在表达式与声明中含义不同（ch02 2.3 已述）。
  • 可读性牺牲：一行声明可编码任意复杂的类型；编译器有固定文法，人脑没有。
程序员期望：名字 → 类型，线性阅读
C 文法实际：declarator 递归嵌套，* [] () 按优先级绑定到 identifier

不学声明的代价

场景 后果
读 stdio.h、signal.h 看不懂回调、函数指针原型
内核/DPDK 回调 void (*handler)(...) 写错类型 → 编译通过、运行崩溃
与 ch04 数组 分不清 char *p 与 char p[] 在声明中的差异
与 ch08 类型转换 隐式转换建立在「先搞清真实类型」之上

题目 1： 以下声明是什么含义？

int *const *(*next)(void);
参考答案

next 是一个指针，指向一个函数（参数 void），返回一个指针，该指针指向一个 const 指针，该 const 指针指向 int。即：next 是指向「返回 intconst 的函数」的指针。复杂声明的解析是 C 专家的基本功。

3.2

声明是如何形成的

本节讲什么

任意 C 声明都可拆成 三个部分：存储类说明符、基本类型、声明符（declarator）。声明符携带名字，并通过 *、[]、() 递归描述「这个名字是什么」。本节建立拆解模板，为 3.3 螺旋规则 提供「从哪开始、绕哪转」的语法基础。

要点

声明的三段式

[存储类]  基本类型  声明符;
部分 常见内容 作用
存储类 auto、register、static、extern、typedef 链接性、存储期；typedef 时整行定义别名而非对象
基本类型 int、char、void、struct foo、enum bar、typedef 名 声明符最终「指向/返回/元素」的底层类型
声明符 标识符 + * / [] / () 组合 把基本类型变成具体对象类型

示例：

static unsigned long int *p;
/* ^^^^^^ 存储类
          ^^^^^^^^^^^^^^^^^ 基本类型
                            ^ 声明符：*p → p 是指针，指向 unsigned long int */

声明符是递归结构

文法上，声明符 = 指针声明符 | 直接声明符，可嵌套：

direct-declarator:
    identifier
    ( declarator )          ← 括号改变绑定顺序
    direct-declarator [ ]   ← 数组
    direct-declarator ( )   ← 函数

pointer:
    * type-qualifiers? pointer?

因此 char (*p)[10] 中：p 是 direct-declarator，外层 (*p) 用括号让 * 先绑定到 p，再 [10] 表示指向数组。

多个声明符共享前缀

unsigned long int *p, **pp, arr[10];
  • p：unsigned long int 的指针
  • pp：指向「unsigned long int 指针」的指针
  • arr：不是指针，是含 10 个 unsigned long int 的数组

规则：逗号分隔的每个声明符 独立 与左侧「基本类型 + 已读的指针/数组/函数后缀」组合；* 只作用于紧挨它的那个名字。

存储类与 typedef 的特殊行

typedef int *IntPtr;     /* 定义类型名 IntPtr，不是变量 */
extern int count;        /* 声明对象，可能在其他 TU 定义 */
static void helper(void); /* 内部链接函数 */

typedef 行中，「存储类」位置被 typedef 占用，声明符里的名字变成类型名（详见 3.5–3.7）。

类型限定符

const、volatile、restrict 可出现在基本类型或指针各层：

const int *p;    /* 指向 const int：不能通过 p 改 *p */
int * const p;   /* p 本身 const：不能改 p 指向谁 */
const int * const p; /* 两者都 const */

解析时：限定符随 螺旋规则 扫到 * 时挂到对应指针层（demo03_const_typedef）。

与表达式的对比

上下文 *p p[i] f()
声明 p 是指针 p 是数组（或函数参数退化为指针） p 是函数
表达式 解引用 下标 调用

同一符号，声明读 类型结构，表达式读 运算——ch02 2.3 的符号过载根源。

3.3

优先级规则

本节讲什么

解析 C 声明的 唯一通用算法——螺旋规则（The Spiral Rule，也称 Right-Left Rule）：从 标识符 出发，顺时针 沿声明符移动，按 [] 与 () 优先于 * 的顺序读，直到整行声明被消费完毕。本节给出四步流程与优先级表，是 3.4 图表法 和 3.8 全部例题 的理论基础。

要点

优先级（绑定顺序）

优先级 构造 含义（读到它时对 identifier 说什么）
最高 ( ) 括号 改变扫描顺序：先解析括号 内 的 declarator
高 [ N ] identifier 是（或 元素为）含 N 个元素的数组
高 ( params ) identifier 是 接受 params 的 函数
低 * identifier 是指针，指向……（继续扫得到的类型）

记忆：括号和方括号、函数括号像「胶水」，比星号贴得更紧。

char *str[10];    /* [] 先绑定 str → str 是数组，* 修饰元素 → char 的指针数组 */
char (*p)[10];    /* () 强制 * 先绑定 p → p 是指针，[] 修饰所指 → 指向 char[10] */

螺旋规则四步

以 char *(*next)(); 为例（书中经典）：

Step 0 — 找到 identifier（如 next）。

Step 1 — 默认：next 是 ……（待补全的类型）。

Step 2 — 顺时针 移动，先处理 括号内（若有），再处理 紧贴 identifier 的 []、()，最后处理 *：

char * ( * next ) ( ) ;
              ↑
         从 next 开始
  • 遇 ( * next )：括号内 → next 是指针
  • 遇 ( )：next 是函数，参数列表空
  • 继续向外：函数 返回 ……
  • 遇 *：返回 指针，指向 ……
  • 遇 char：…… char

Step 3 — 用英语（或中文）串起来：

next 是一个 函数，返回 指向 char 的 指针。

等价 typedef 写法：

typedef char *(*NextFn)(void);
NextFn next;

四步速查表

步骤 动作
1 写名字：X 是 ……
2 顺时针：括号内优先；[] → 数组；( ) 带参数 → 函数；* → 指针
3 函数：读 返回类型；数组：读 元素类型；指针：读 指向类型
4 重复直到基本类型（int、char、void、typedef 名）

常见对比（必背）

声明 解析结果
int *p p 是指向 int 的指针
int arr[10] arr 是含 10 个 int 的数组
int *p[10] p 是含 10 个「int 指针」的数组
int (*p)[10] p 是指向「含 10 个 int 的数组」的指针
int f(int) f 是函数，接受 int，返回 int
int (*fp)(int) fp 是指向「接受 int 返回 int 的函数」的指针
int *f(int) f 是函数，接受 int，返回 int*

与 C 运算符优先级的区别

不要混淆：表达式里 []、()、* 的优先级与 声明符绑定规则 相关但不相同。声明解析 只用螺旋规则，不要套「乘号比加减优先」那套。

练习建议

  1. 先 遮掉存储类和 typedef，只练 declarator
  2. 每遇一层，用 中文半句 标注（「是指针」「是数组」「是函数，返回……」）
  3. 与 3.4 框图 对照：每个框 = 螺旋上的一站

3.4

通过图表分析 C 语言的声明

本节讲什么

图表法 与 3.3 螺旋规则 等价：把声明画成 以 identifier 为中心的框图，箭头表示指针，方框表示数组/函数，最终落到基本类型。适合纸笔推演、白板面试、复杂声明分步验证。本节给出画法规范与两个完整示例。

要点

图表元素约定

符号 含义
方框 + 名字 当前正在解析的 identifier
→ 或 * 指针：「指向」右侧类型
[N] 数组：「含 N 个元素，元素类型为……」
(params) 函数：「接受 params，返回……」
括号 ( ) 先解析内部，再与外部连接

方向：从 identifier 向外扩，与螺旋规则 顺时针 一致。

示例 1：char *str[10]

        str
         |
      [ 10 ]          ← str 是数组，10 个元素
         |
        char *         ← 每个元素是指向 char 的指针

读法：str 是一个数组，数组有 10 个元素，每个元素是 char 的指针。

对比 char (*p)[10]：

         p
         |
         *            ← p 是指针
         |
      [ 10 ]          ← 指向的对象是含 10 个 char 的数组
         |
        char

读法：p 是指针，指向含 10 个 char 的数组。

示例 2：int (*func)(int, char)

        func
         |
         *            ← func 是指针
         |
    ( int, char )     ← 指向「函数：参数 int,char」
         |
        int           ← 该函数返回 int

读法：func 是指针，指向接受 (int, char) 且返回 int 的函数。

调用方式：(*func)(42, 'x'); 或 C 习惯写法 func(42, 'x');。

示例 3：多层 char *(*(*x())[])()

分步（与 3.8 同步）：

3.5

typedef 可以成为你的朋友

本节讲什么

typedef 把 声明符 + 基本类型 打包成 新类型名，让复杂声明可读、可复用。但 typedef 不是宏：替换规则、const 绑定、多变量声明行为与 #define 不同。本节重点讲 typedef 的正确用法 与 PSTR 经典陷阱——typedef char *PSTR; PSTR a, b; 中 a、b 都是指针，而 char *a, b 中 只有 a 是指针。

要点

typedef 做了什么

typedef unsigned long ulong;
typedef int (*CompareFn)(const void *, const void *);
typedef char (*RowPtr)[80];   /* 指向含 80 char 的数组的指针 */
  • 编译器在符号表增加 类型别名，不是新对象
  • 别名与 int、struct foo 一样参与声明解析
  • 可读性：回调、函数指针、数组指针在 API 中几乎必用 typedef（demo02_func_ptr）

PSTR 陷阱（必考）

typedef char *PSTR;

PSTR a, b;
/* 等价于：char *a; char *b;  ← a、b 都是 char* */

char *a, b;
/* 等价于：char *a; char b;    ← 只有 a 是指针，b 是 char */
写法 a b
char *a, b char* char
PSTR a, b（typedef char *PSTR） char* char*

原因：typedef 定义的是 完整类型 PSTR；PSTR a, b 中每个声明符都独立获得该类型。而 char *a, b 里 * 只属于 declarator a。

工程建议：

typedef char *PSTR;
PSTR a;
PSTR b;          /* 清晰，避免与 char* 一行多变量混淆 */

/* 或 */
typedef char PSTR_unit;  /* 若本意是「字符串单元类型 char」——别用 PSTR 表示指针 */

const 与 typedef 的绑定（demo03）

typedef char *Str;
const Str s = "hello";
  • const Str s → s 本身 不能改指向（Str = char*，const 贴在外层指针）
  • 不是 const char*：仍可通过 s[0] = 'H' 修改所指内容（除非指向字符串字面量则 UB）

若要 指向内容不可改：

typedef const char *CStr;
CStr s = "hello";   /* *s 不可改 */

规则：const/volatile 出现在 typedef 之后，修饰的是 typedef 展开后的整体，而非「替换成 const char」那么简单——需按 3.2 声明符* 展开再看。

typedef 作为「朋友」的场景

场景 示例
函数指针 typedef void (*SignalHandler)(int);
数组指针 typedef char (*Line)[256];（demo01_arr_ptr）
回调注册 typedef int (*ioctl_fn)(struct file *, unsigned cmd, unsigned long arg);
跨平台整数 typedef uint32_t u32;

复杂声明 先 typedef 命名中间层，再写业务代码——维护成本远低于一行怪物声明。

typedef 不是银弹

问题 说明
隐藏指针 PSTR 看不出是指针，易误用 sizeof(PSTR)
与宏混用 #define 文本替换会破坏 typedef 语义（3.6）
重复 typedef struct typedef struct foo { } foo; 三处 foo 含义不同（3.7）
C++ 兼容 typedef 与 using、模板交互另论；纯 C 系统代码仍以 typedef 为主

3.6

typedef int x[10] 和 #define x int[10] 的区别

本节讲什么

typedef 与 #define 都能造「别名」，但 机制完全不同：typedef 在 编译器符号表 中定义 完整类型；#define 在 预处理阶段 做 文本替换。本节用 typedef int x[10] 与 #define x int[10] 对比 声明展开、多变量、const、可读性，说明为何 类型别名用 typedef，常量/条件编译用宏。

要点

核心对比

typedef int x[10];
#define x int[10]
维度 typedef int x[10]; #define x int[10]
处理阶段 编译（符号表类型） 预处理（文本替换）
x 是什么 类型名：「含 10 个 int 的数组」 宏：替换成 token 序列 int[10]
x y, z 含义 y、z 都是 int[10] 展开 int[10] y, z → 语法错误
unsigned x y 非法（unsigned 不能修饰数组类型名） 展开 unsigned int[10] y → 可能合法但难读
作用域 遵循 C 作用域与 typedef 规则 从 #define 到 #undef 或文件尾
调试器 可显示类型名 x 无类型信息，只见 int[10]

多变量声明：决定性差异

typedef int x[10];
x y, z;           /* OK：y 和 z 都是 int[10] */

#define x int[10]
x y, z;           /* 预处理 → int[10] y, z;  ← 非法 */
x y; x z;         /* 勉强：两行各自 OK，但宏污染 */

面试一句话：typedef 定义 类型；#define x int[10] 只是把 x 换成 [10] 前面的片段拼进声明符，无法 像类型一样与多个 declarator 组合。

更隐蔽的宏陷阱

#define int_ptr int *
int_ptr a, b;
/* 展开：int * a, b;  → 只有 a 是指针！与 PSTR 陷阱同源（3.5） */

typedef int *int_ptr;
int_ptr a, b;
/* a、b 都是 int* */
需求 正确工具
指针/数组/函数类型别名 typedef
字面常量、MIN/MAX（谨慎） 宏 或 static inline（ch02 2.2）
条件编译 #ifdef，不是 typedef

const 绑定差异

typedef char *string_t;
const string_t s;     /* const 指针，不是 const char* */

#define string_t char *
const string_t s;     /* 预处理 → const char * s;  ← const 贴 char*，语义不同！ */

宏在 const 之前 展开，qualifier 绑定顺序可能 与 typedef 路径不一致——又一个 别用宏 typedef 指针 的理由。

何时仍用 #define

  • 包含守卫、版本号、功能开关
  • 需要 字符串化 #、连接 ##
  • 标准库常：NULL、BUFSIZ（部分环境）

类型层面：C11 起可考虑 _Generic 做类型选择；C++ 侧 using；纯 C 系统头文件仍以 typedef 为主（size_t、uint32_t）。

记忆口诀

typedef → 「这是一个类型，名字叫 x」
#define  → 「见到 x 就替换成一串字符」

复杂声明 先 typedef 拆层（3.5），不要用宏伪造 typedef。

题目 1： 用「右左法则」解析以下声明：

int (*foo(int))(int);
参考答案

foo 是一个函数（参数为 int），返回一个指针，该指针指向一个函数（参数为 int），返回 int。即：foo 是返回函数指针的函数。解析方法：从变量名出发，先右后左，遇 () 改方向。*foo(int) → foo 是函数，返回指针；int (*)(int) → 指向参数 int 返回 int 的函数的指针。

3.7

typedef struct foo { ... foo; } 的含义

本节讲什么

C 语法允许 结构体标签（tag） 与 typedef 类型名 同名，写成 typedef struct foo { ... } foo;。一行里 三个 foo 角色不同：结构体标签、typedef 别名、成员访问时的类型。本节厘清 tag vs typedef 名、与 C++ struct foo 差异、以及 匿名 struct + typedef 的惯用法。

要点

一行三角色

typedef struct foo {
    int   id;
    char  name[32];
} foo;
/*      ^^^ tag          ^^^ typedef 名（类型别名） */
位置 foo 的角色 用途
struct foo { 结构体标签（tag） struct foo x; 合法（C 中）
} foo; typedef 引入的类型名 foo x; 合法，无需写 struct
成员函数式写法 类型名 foo *p;、sizeof(foo)

效果：既可用 K&R 风格 struct foo a;，也可用 typedef 简写 foo a;——在头文件中极常见（Linux 内核、glib、SDK）。

与「仅 tag、无 typedef」对比

struct bar {
    int x;
};
struct bar a;      /* 必须带 struct */
/* bar b;           错误：bar 不是类型名，只是 tag */

typedef struct bar {
    int x;
} bar_t;
bar_t a;           /* 推荐：类型名与 tag 分离，更清晰 */
struct bar b;      /* 仍可用 tag */

现代风格建议：typedef 名用 foo_t 或 Foo，与 tag struct foo 区分，避免三个同名 foo 初学者晕头转向。

自引用与不完整类型

typedef struct node {
    int         data;
    struct node *next;   /* 必须用 struct node*：此时 typedef node 尚未完成 */
} node;
  • 结构体 内部 自引用：标准写法 struct tag *
  • C 允许指向不完整类型的指针
  • typedef 名在 } 之后才完全生效

匿名 struct + typedef

typedef struct {
    int x, y;
} Point;
/* 无 tag，仅 Point 可用；不能写 struct ??? */
写法 tag 自引用 典型场景
typedef struct foo { } foo; 有 内部用 struct foo* 传统头文件
typedef struct { } Point; 无 需前向声明技巧 简单 POD
struct foo { }; 无 typedef 有 必须 struct foo 减少命名空间污染

与 C++ 的对比（阅读混合代码时）

  • C++ 中 struct foo { }; foo x; 无需 typedef——foo 自动进类型命名空间
  • C 中 必须 typedef 或 struct foo 前缀
  • 移植头文件时注意 #ifdef __cplusplus 包装

易错点

错误 说明
sizeof(struct foo) vs sizeof(foo) typedef 后二者相同
重复定义 同一 TU 不能两次定义同一 tag
与 enum/union 同名 同一作用域 tag 命名空间共享，别撞名
以为 foo 是变量 行末 foo 是 类型名，不是实例

内核/API 示例（概念）

typedef struct file_operations {
    struct module *owner;
    ssize_t (*read)(struct file *, char __user *, size_t, loff_t *);
    /* ... */
} file_operations;

读回调声明 = 3.3 螺旋规则 + 3.5 typedef 命名 的组合——读懂头文件的基础。

3.8

理解所有分析过程的代码段

本节讲什么

全书 声明分析 的实战章：对书中 每一道 经典声明，用 3.3 螺旋规则 逐步口播解析，并给出 typedef 改写 与 调用方式。涵盖基础对比、x() 级嵌套、a[10] 与括号位置 的致命差异，以及面试圣杯 signal。建议 先遮答案自推，再对照。

要点

基础四组（必会）

1. char *str[10]

str 是数组 → 10 个元素 → 每个元素是 char 的指针

中文：str 是 含 10 个元素的数组，元素类型为 指向 char 的指针（指针数组）。

char *s = str[0];   /* 第 0 个元素是 char* */

2. char (*p)[10]

p 是指针 → 指向 → 含 10 个 char 的数组

中文：p 是 指针，指向 含 10 个 char 的数组（数组指针）。

char arr[10];
p = &arr;           /* 数组指针取整个数组地址 */
(*p)[0] = 'a';      /* demo01_arr_ptr 同类 */
声明 主体 对比
char *str[10] str 是数组 元素为 char*
char (*p)[10] p 是指针 指向 char[10]

3. int (*func)(int, char)

func 是指针 → 指向 → 函数(int, char) → 返回 int

中文：func 是 函数指针，指向 接受 (int, char)、返回 int 的函数。

int example(int a, char c) { return a + c; }
func = example;
func(1, 'x');       /* 或 (*func)(1, 'x'); — demo02_func_ptr */

typedef：

typedef int (*Func)(int, char);
Func func;

4. int *f(int) vs int (*fp)(int)

声明 解析
int *f(int) f 是函数，参数 int，返回 int*
int (*fp)(int) fp 是指针，指向 接受 int、返回 int 的函数

记忆：* 贴名字且被括号包住 → 函数 指针；* 在返回类型侧、名字旁无括号 → 返回指针的函数。

进阶：char *(*(*x())[])()

从 identifier x 顺时针：

步 遇到 对 x 说
1 x x 是 ……
2 ( ) x 是函数，参数列表 空
3 向外 函数 返回 ……
4 * …… 指针
5 [ ] …… 指向 数组（维度未写 = 不完整/取决于上下文）
6 元素 * 数组元素是 指针
7 ( ) 指向 函数，参数空
8 返回 函数 返回 char *

完整中文：

x 是一个函数；调用时不带参数；返回 一个 指针，该指针指向 数组；数组 元素 是指向 函数 的指针；那些函数 无参数，返回 char*。

typedef 分层（推荐）：

typedef char *(*InnerFn)(void);
typedef InnerFn InnerFnArray[];      /* 元素为 InnerFn 的数组 */
typedef InnerFnArray *InnerArrPtr;
typedef InnerArrPtr (*OuterFn)(void);

OuterFn x;

经典对比：int *(*a[10])() vs int (*(*a)[10])()

两声明 仅括号位置不同，语义 天差地别。

A. int *(*a[10])()

a 是数组[10] → 每个元素是指针 * → 指向函数() → 返回 int*

中文：a 是 含 10 个元素的数组；每个元素是 函数指针；所指函数 无参，返回 int*。

/* a[i] 是函数指针；a[i]() 返回 int* */

B. int (*(*a)[10])()

a 是指针 * → 指向数组[10] → 元素是指针 * → 指向函数() → 返回 int

中文：a 是 指针；指向 含 10 个元素的数组；数组 元素 是 函数指针；所指函数 无参，返回 int（注意：返回 int，不是 int*）。

对比记忆：
  *a[10]  → [] 先绑 a → 「指针的数组」再 * → 函数指针数组
  (*a)[10] → * 先绑 a → 「指向数组的指针」，数组里再放函数指针
声明 a 本身 第一层
int *(*a[10])() 数组 [10] 元素：返回 int* 的函数指针
int (*(*a)[10])() 指针 指向 [10] 数组；元素：返回 int 的函数指针

圣杯：void (*signal(int sig, void (*handler)(int)))(int)

分两段读：外层是 声明 signal；内层 void (*handler)(int) 是 参数类型。

Part 1 — 参数 void (*handler)(int)

handler 是 指针，指向 接受 int、返回 void 的函数（标准信号处理回调）。

Part 2 — 整体 signal(...)

从 identifier signal 出发：

步 构造 含义
1 signal signal 是 ……
2 (int sig, void (*handler)(int)) signal 是函数，两参数
3 外层 (int) 该函数 返回 ……
4 * …… 函数指针
5 (int) 指向的函数 接受 int，返回 void

完整中文：

signal 是一个函数：
- 参数 1：int sig（信号编号）
- 参数 2：void (*handler)(int)（新的处理函数指针）
- 返回值：函数指针，指向 接受 int、返回 void 的函数（即 先前的 处理函数）

typedef 写法（可读性）：

typedef void (*SigHandler)(int);

SigHandler signal(int sig, SigHandler handler);
/* signal 返回 SigHandler */

使用示例：

SigHandler old = signal(SIGINT, my_handler);
/* old 保存旧 handler；my_handler 签名必须为 void my_handler(int) */

面试口述模板：「signal 是函数；参数是 sig 和 handler；handler 本身是指向 void(int) 的指针；signal 返回 void(int) 的函数指针。」

声明解析错误示例：

/* 本意：指向 10 个 uint32_t 寄存器的指针数组 */

与 signal 声明的呼应（3.8）

Unix signal 的怪物声明：

题目 1： 以下声明是什么含义？

int *const *(*next)(void);
参考答案

next 是一个指针，指向一个函数（参数 void），返回一个指针，该指针指向一个 const 指针，该 const 指针指向 int。即：next 是指向「返回 intconst 的函数」的指针。复杂声明的解析是 C 专家的基本功。

章节自测

C 声明读法：螺旋规则、指针数组 vs 数组指针、typedef 陷阱。看代码 → 想答案 → 点开验证。

Q1指针数组 vs 数组指针
char *str[10];      // A
char (*p)[10];      // B

A 和 B 的类型分别是什么？用螺旋规则分析。

答案与复习指引

答案： - A：str 是指针数组——10 个元素，每个是 char*。 - 螺旋：str → [10]（数组 10 元素）→ *（每个元素是指针）→ char（指向 char） - B：p 是数组指针——指向含 10 个 char 的数组。 - 螺旋：p → *（指针）→ [10]（指向 10 元素数组）→ char（元素类型 char）

优先级： [] 高于 *，所以 char *str[10] = char *(str[10])；括号改变顺序 char (*p)[10]。

复习： → 3.3 优先级规则 · 3.8 理解所有分析过程的代码段

Q2typedef 与 #define
typedef char *PSTR;
#define DSTR char *

PSTR a, b;    // A
DSTR c, d;    // B

A 和 B 中，a/b/c/d 的类型分别是什么？

答案与复习指引

答案： - A：a 和 b 都是 char*（typedef 是真正的类型别名，对每个声明符都适用） - B：c 是 char*，d 是 char（#define 是纯文本替换，展开为 char *c, d — * 只修饰 c）

教训： typedef 是类型层面的别名；#define 是文本替换，不理解 C 语法。多变量声明时差异致命。

复习： → 3.5 typedef 可以成为你的朋友 · 3.6 typedef vs #define

Q3signal 声明
void (*signal(int sig, void (*handler)(int)))(int);

用螺旋规则分析：signal 是什么？

答案与复习指引

答案： signal 是一个函数： 1. 找到 signal → 它是…… 2. (int sig, void (*handler)(int)) → 接受两个参数：int 和一个函数指针 void (*)(int) 3. 向左看 * → 返回值是一个指针 4. 向右看 (int) → 指向接受 int 返回 void 的函数 5. 即：返回 void (*)(int) 类型的函数指针（旧信号处理器的地址）

简化用 typedef：

typedef void (*SigHandler)(int);
SigHandler signal(int sig, SigHandler handler);

复习： → 3.8 理解所有分析过程的代码段

Q4const typedef 陷阱
typedef char *Str;
const Str s = "hello";    // A

const char *t = "hello";  // B

A 中 s 和 B 中 t 的 const 语义有什么区别？

答案与复习指引

答案： - A：s 是 char * const（指针本身是常量，但 *s 可修改）——const 修饰 Str 即 char* 整体 - B：t 是 const char *（指向的内容是常量，但 t 可改指向）

A 等价于： char *const s = "hello"; → s[0] = 'H' 合法（但字符串字面量只读 → UB），s = "world" 不合法。

教训： typedef 替换后 const 修饰的是整个 typedef 名，不是最左边的类型。
