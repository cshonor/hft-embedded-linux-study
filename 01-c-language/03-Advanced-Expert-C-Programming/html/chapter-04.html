导读

本章目标

建立 数组 ≠ 指针 的硬结论：理解 数组名退化（decay） 规则及 sizeof / &arr 例外；掌握 跨文件 extern 声明必须与定义类型一致（char arr[] ≠ extern char *arr），能解释 4.2 经典段错误；熟记 四项本质差异、形参 int a[] ≡ int *a（仅限形参）、a[i] 与 *(a+i)；为 ch05 链接、ch09 再论数组、Embedded ch07 指针与存储 打底。

数组名退化的四种典型场景

多数表达式中，数组名 由 T[N] 调整为 T*（指向首元素）：

# 场景 示例
1 赋给指针 int *p = arr;
2 函数实参 foo(arr); → 形参收到 int*
3 下标 / 算术运算 arr[i]、arr + 1（先 decay 再算）
4 比较 if (arr == p) 比较地址

不退化（必记例外）：

语境 行为
sizeof(arr) 整个数组字节数
&arr 类型 T (*)[N]，步长为数组总大小
声明/定义行 int arr[10] 中 arr 仍是数组
（对比）文件作用域 extern 必须写 extern T arr[]，不能 写 extern T *arr（4.4）

四项本质差异（必背）

维度 数组 T a[N] 指针 T *p
存储 N 个 T 连续存放 一个地址值
sizeof N * sizeof(T) sizeof(T*)
& T (*)[N] T **
赋值 不可 a = ... 可 p = &x

详见 4.1、4.5；demo01_sizeof 验证 sizeof 与 &arr+1 vs arr+1。

函数形参等价（仅形参）

void f(int a[]);    /* 完全等价 */
void f(int a[10]);  /* 10 被忽略 */
void f(int *a);
  • 形参处 没有真正的数组类型，sizeof(a) 是指针大小（4.5）。
  • 切勿 将此等价推广到 extern 声明（4.2–4.4）。

下标定义（4.5，demo03_subscript）：

a[i]  ≡  *(a + i)  ≡  i[a]

高频考点 / 面试题

  1. 数组和指针是一回事吗？ → 不是。多数语境数组名 退化为首元素指针；对象是数组时 sizeof、& 行为不同（4.1, demo01）

  2. extern char *arr 与 char arr[] = "hi" 一起链接会怎样？ → 链接可能成功，运行把首字符当指针值解引用 → 崩溃（4.2, demo02_wrong）

  3. sizeof(数组名) 与 sizeof(指针)？ → 前者 元素总大小；后者 指针宽度。函数形参里写 int a[] 仍是指针，sizeof(a) 是指针大小（4.5）

  4. arr+1 和 &arr+1 区别？ → arr 退化为 T*，加 1 跳 一个元素；&arr 是 T(*)[N]，加 1 跳 整个数组（4.5, demo01）

  5. 函数参数 int a[] 和 int *a 一样吗？ → 等价（数组形参调整为指针）。但 文件作用域 extern int a[] 不等于 extern int *a（4.4, 4.5）

  6. a[i] 和 *(a+i)、i[a]？ → 三者等价；i[a] 合法但勿在生产代码使用（4.5, demo03）

4.1

数组并非指针

本节讲什么

本章标题即结论：数组（array）和指针（pointer）是两种不同的对象类型，不能混为一谈。初学者常以为「数组名就是指针」，因为多数表达式里数组名会 自动退化为（decay） 指向首元素的指针——但这只是 使用规则，不改变 类型本质。本节建立正确心智模型，并列出 不退化 的例外场景（sizeof、&arr、声明语境），为 4.2–4.4 的跨文件崩溃案例和 4.5 的细节对比打基础。

要点

核心结论

概念 数组 指针
是什么 连续存储的 同类型元素序列 存放 地址 的标量对象
声明 int a[10] — a 的类型是 int[10] int *p — p 的类型是 int*
内存 分配 10×sizeof(int) 字节 通常只分配 一个指针宽度
能否重赋值 不能 a = ... 能 p = &x 
int a[10];
int *p = a;     /* 合法：a 在此语境退化为 int*，赋给 p */
/* a = p;       非法：数组名不是左值，不可赋值 */

数组名的退化（decay）

在 大多数表达式 中，若数组名不是下列例外之一，编译器将其 替换 为「指向首元素的指针」，类型由 T[N] 变为 T*：

int arr[5];
int *p = arr;           /* arr → &arr[0]，类型 int* */
printf("%d\n", arr[2]); /* 先 decay 再下标，等价 *(arr+2) */
if (arr == p) { }       /* 比较的是地址 */

退化不等于「数组是指针」：退化是 临时的类型转换规则；对象在内存里仍是数组，声明里的类型仍是数组。

不退化的三种（必记）例外

语境 行为 示例（int a[10]，假设 int 4 字节）
sizeof(a) 求 整个数组 字节数 sizeof(a) == 40
&a 类型为 指向数组的指针 int (*)[10] &a + 1 跳过 40 字节（见 4.5）
声明语句中 a 仍是数组名，描述类型而非取值 extern int a[]; 声明的是数组，不是指针 
void foo(int arr[]);   /* 形参处也「像声明」——见 4.5：等价 int *arr */

口诀：只有 sizeof 和 取地址 & 能「看见」数组的真实尺寸；其余多数场合看见的是 首元素地址。

与 sizeof 相关的常见误解

int local[10];
void test(int arr[]) {
    sizeof(arr);  /* 指针宽度！通常 4 或 8，不是 40 */
}
  • 在 定义数组 的作用域内：sizeof(数组名) = 元素个数 × 元素大小（demo01_sizeof）。
  • 在 函数形参 里：arr[] 已退化为指针，sizeof(arr) = sizeof(int*) —— 无法 用 sizeof 反推数组长度。

类型层面的区分（衔接 ch03）

用 3.3 螺旋规则 读声明，主体类型一目了然：

声明 主体 含义
char a[10] a 是数组 10 个 char
char *p p 是指针 指向 char
char (*pa)[10] pa 是指针 指向含 10 个 char 的数组

4.2 的经典 bug 正是把 char a[] 的定义与 extern char *a 的声明混为一谈——编译器/linker 不报错，运行却崩溃。

何时「看起来一样」

场景 说明
下标访问 a[i] 与 *(a+i) 在 a 退化后一致（4.5）
传给函数 数组实参退化为指针（4.5，ch09 9.3 深入）
赋给指针 p = a 合法

何时绝不一样：跨文件 声明/定义匹配（4.3–4.4）、sizeof、& 运算、存储布局（4.5）。

代码自测

题目 1： 数组和指针在什么情况下「相同」，什么情况下「不同」？

int a[10];
int *p = a;
参考答案

相同：作为函数参数时（数组退化为指针）、下标访问时（a[i] ≡ *(a+i) ≡ *(p+i) ≡ p[i]）。 不同：1) sizeof(a) = 40（数组大小），sizeof(p) = 8（指针大小）；2) &a 类型是 int(*)[10]，&p 类型是 int**；3) 数组不可赋值（a = p 非法），指针可赋值；4) 数组名是地址常量，指针是变量。

4.2

我的代码为什么无法运行

本节讲什么

全书最著名的 跨文件 bug 之一：一个 .c 里 定义 char arr[] = "hello"，另一个 .c 里 声明 extern char *arr，编译、链接 都能通过，运行却在访问 arr 时 段错误（SIGSEGV） 或输出乱码。本节用内存布局逐步解释 为何编译器/linker 抓不出来，以及 错在哪里。

要点

问题代码结构

文件 A（定义） — arr_def.c：

char arr[] = "hello";

文件 B（错误声明） — use_wrong.c：

extern char *arr;   /* 错！定义侧是数组，不是指针变量 */

int main(void) {
    printf("%s\n", arr);  /* 崩溃或乱码 */
}

文件 B（正确声明） — use_correct.c：

extern char arr[];  /* 对：与 char arr[] = "hello" 类型一致 */

对应 demo02_extern：make demo02_correct 正常；make demo02_wrong 可能 SIGSEGV。

内存里实际有什么

定义 char arr[] = "hello" 时：

地址低 ──────────────────────────────► 高
arr:  'h' 'e' 'l' 'l' 'o' '\0'   ← 6 字节连续存储，arr 是这块区域的名字

若错误地当作 char *arr 理解，编译器认为：

arr 是一个指针变量（4/8 字节），其「值」应是某个地址

但链接器把 符号 arr 的地址 绑到 字符 'h' 所在位置（数据段里数组首字节），并没有 单独的指针槽存放「指向 hello 的地址」。

崩溃机制（逐步）

  1. use_wrong.c 中 extern char *arr 告诉编译器：arr 是 指针变量，*arr 是从 arr 里读出的地址 再解引用。
  2. 链接时符号 arr 解析为 数组首元素的字节地址，例如 0x601040。
  3. 访问 *arr 或 printf("%s", arr) 时，编译器生成的代码会： - 从地址 0x601040 读取 4/8 字节 当作「指针值」； - 那些字节实际是字符 'h' 'e' 'l' 'l'（小端下可能是 0x006c6c6568 一类）； - 再把这个「假地址」解引用 → 访问非法地址 → SIGSEGV。
正确模型：arr 就是 'h' 的地址，arr[0]=='h'，arr 作为整体是 char[6]

错误模型：arr 是指针变量 → 先读 arr 的内容（把 'hell' 当指针）→ 再解引用 → 崩溃

为何编译器和 linker 都不报错

阶段 为何放过
编译 各 TU 单独编译；char* 与 char[] 在 表达式 里都能用 []、都能传给 printf("%s")
链接 只核对 符号名 arr 是否存在、是否唯一；不检查 两侧 C 类型是否一致（C 链接 无类型）
运行 类型误解体现在 错误的机器指令（多读一次内存）

这是 C 的类型系统漏洞：链接层不携带完整类型信息（与 C++ name mangling 不同）。

正确写法与原则

/* 定义（一个 .c） */
char arr[] = "hello";

/* 声明（其他 .c / .h）—— 类型必须匹配 */
extern char arr[];     /* 推荐：可省略长度 */
extern char arr[6];    /* 也可写全长度，须 ≥ 实际定义长度 */

禁止：

extern char *arr;      /* 与 char arr[] 定义不匹配 */

头文件惯例：

/* header.h */
extern char arr[];     /* 不是 extern char *arr */

与 char *p = "hello" 的对比

写法 存储 类型 能否修改内容
char arr[] = "hello" 数组在 可写 数据段（或栈若局部） char[6] 可改 arr[0]（字符串字面量初始化后数组本身可写）
char *p = "hello" p 存 字面量地址；字面量常在 只读 段 char* 改 *p 可能 未定义行为

跨文件时：定义是什么类型，extern 就必须声明同一类型——数组对数组，指针对指针。

调试线索

现象 可能原因
链接成功、一访问全局 arr 就崩 extern char * vs char[] 不匹配
printf("%p", arr) 合理但 printf("%s", arr) 崩 把数组首地址当成了「指针变量里存的值」
仅首字符相关代码「碰巧」能跑 误把 ASCII 'h'(0x68) 当小地址解引用，有时不立即 crash

4.3

什么是声明，什么是定义

本节讲什么

4.2 的崩溃根源之一是：在 A 文件 定义 了数组，却在 B 文件用 错误类型的声明 引用它。要修复这类问题，必须先分清 C 里 声明（declaration） 与 定义（definition）——前者告诉编译器「名字与类型」，后者 分配存储 并通常 初始化。本节厘清概念、存储类说明符，以及「只声明不定义」的 extern 用法。

要点

声明 vs 定义

声明 定义
作用 引入 名字 和 类型，供编译器做类型检查 为名字 分配存储（或函数体），是 实体
出现次数 可 多次（同一作用域内类型须一致） 整个程序中 一次（函数、非 extern 变量）
是否占存储 否（仅符号表信息） 是
典型关键词 extern（仅声明）、函数原型 无 extern 的变量；带函数体的函数 
/* 声明：告诉编译器 arr 的类型是 char 数组，不在此 TU 分配存储 */
extern char arr[];

/* 定义：分配存储并初始化 */
char arr[] = "hello";

变量：声明与定义示例

extern int count;        /* 声明 */
int count = 0;           /* 定义 + 初始化 */

extern char buffer[];    /* 声明：不完整数组类型 OK */
char buffer[1024];       /* 定义：长度在此确定 */

int x;                   /* 定义：未显式初始化 → 静态存储归零 */

规则：

  • 带 extern 且 无初始化 → 通常是声明（不在此文件分配空间）。
  • 无 extern 或有 初始化器 → 定义。

函数：声明与定义

/* 声明（原型） */
void print_first(void);

/* 定义 */
void print_first(void) {
    printf("...\n");
}

函数 定义 也是 声明（同时引入名字）。4.2 demo 中 arr_def.c 定义 print_first，use_*.c 只有原型——链接时合并。

extern 的精确含义

extern int g;     /* 声明：g 的定义在别的 TU */
int g = 42;       /* 定义：在此 TU 分配 g */
写法 含义
extern int g; 仅声明，不分配
int g;（文件作用域） 定义，静态存储，初值 0
extern int g = 1; C 中仍视为 定义（有初始化）

数组 extern：

extern char arr[];    /* OK：长度未知，类型为不完整数组 */
extern char arr[10];  /* OK：长度已知，须与定义兼容 */

定义侧 char arr[] = "hello" 时，声明侧 不能 写成 extern char *arr——类型不是同一声明链（4.4）。

声明链（declaration chain）

C 要求：同一标识符的多次声明必须 兼容，最终与 唯一定义 一致。

header.h:   extern char msg[];
file_a.c:   char msg[] = "error";    /* 定义 */
file_b.c:   #include "header.h"     /* 声明 */

若 file_b.c 写 extern char *msg，则与定义 不兼容——编译器 各自 TU 内 可能不报错，链接也不查类型（4.2）。

不完整类型（incomplete type）

extern char arr[];   /* 元素类型已知，长度未知 — 不完整数组类型 */
  • 可以 用于 extern 声明（长度由定义 TU 提供）。
  • 不可以 用于局部自动数组 char arr[];（缺长度且无初始化）。
  • sizeof(arr) 在 不完整 extern 声明 处 非法（长度未知）。

与存储类的关系

存储类 常见用途
extern 引用他处定义
static（文件作用域） 内部链接，仅本 TU 可见
（默认） 外部链接，全局定义

常见误区

误区 正解
「头文件里写的就是定义」 头文件应放 声明；定义通常在一个 .c
「extern char *arr 和 extern char arr[] 差不多」 完全不同类型，链接后运行才暴露

4.4

使声明与定义相匹配

本节讲什么

4.3 区分了声明与定义；本节给出 可操作的匹配规则：当数组在一个编译单元 定义、在其它单元通过 extern 引用 时，声明符必须 逐字对应类型结构——[] 与 * 不可互换。同时说明 数组长度 在声明/定义两侧如何省略或写全，以及头文件、多文件工程中的 最佳实践。

要点

黄金法则

定义用什么类型，extern 声明就必须用同一类型。

定义（某个 .c） 正确声明 错误声明
char arr[] = "hello"; extern char arr[]; extern char *arr;
int table[256]; extern int table[]; 或 extern int table[256]; extern int *table;
char *msg = "err"; extern char *msg; extern char msg[];

4.2 崩溃 = 违反本条 + C 链接 无类型检查。

为何 extern char arr[] 而非 extern char *arr

/* defs.c — 定义 */
char arr[] = "hello";

/* use.c — 声明 */
extern char arr[];

编译器在 use.c 中知道：

  • arr 的类型是 数组（长度不完整但 元素连续）；
  • arr 就是 首元素地址，不是 「存地址的指针变量」；
  • arr[i] 等价于从 arr 首地址偏移 i 个 char。

若写成 extern char *arr：

  • 编译器认为存在 指针对象 arr；
  • 访问路径变成 load 指针值 → 再解引用；
  • 与定义侧内存布局 不一致（4.2 逐步推演）。

数组长度的匹配规则

/* 定义 */
char buf[100] = {0};

/* 声明 — 以下均可（若兼容） */
extern char buf[];      /* 省略长度：最常见 */
extern char buf[100];   /* 完全匹配 */
extern char buf[80];    /* C：长度可更小？不 — 声明长度须 ≥ 定义使用范围，且兼容规则以标准为准 */

实践建议：

做法 说明
extern char buf[]; 推荐：长度只在 定义处 维护一处
extern char buf[N]; 头文件用 #define N 统一，定义也用 N
不要在声明侧随意改 [] 为 * 即使「用起来像字符串」

注意：extern char arr[6] 与 char arr[] = "hello"（6 含 \0）兼容；声明长度 不能小于 实际元素个数（否则越界风险）。

头文件模板

/* shared.h */
#ifndef SHARED_H
#define SHARED_H

extern char arr[];           /* 数组：与定义 char arr[] = ... 配对 */
extern int *index_table;     /* 指针：与定义 int *index_table = ... 配对 */

void print_first(void);

#endif

/* arr_def.c */
#include "shared.h"

char arr[] = "hello";

void print_first(void) {
    printf("arr[0]=%c\n", arr[0]);
}

/* main.c */
#include "shared.h"

int main(void) {
    print_first();
    printf("%s\n", arr);
    return 0;
}

demo02_extern 即此模式的极简版：arr_def.c + use_correct.c / use_wrong.c。

函数声明与数组声明的对比

对象 声明可省略的信息 仍须匹配的核心
函数 参数名可省略 返回类型、参数 类型列表
数组 extern 可省略长度 必须是数组 不能变指针
指针 — 指向类型必须一致

函数形参 void f(int a[]) 与 void f(int *a) 等价——那是 函数形参的特殊规则（4.5），不适用于 文件作用域的 extern。

链接器视角（为何必须人眼保证）

       ↓

4.5

数组和指针的其他区别

本节讲什么

在 4.1 确立「数组 ≠ 指针」、4.2–4.4 解决跨文件匹配之后，本节汇总 运行时与语义层面 的其它关键差异：存储布局、sizeof 行为、arr+1 与 &arr+1 的指针算术、函数形参退化、下标与解引用的等价关系，以及 2[arr] 为何合法。配合 demo01_sizeof、demo03_subscript 验证。

要点

四项本质差异（必背表）

维度 数组 int a[10] 指针 int *p
存储 10 个 int 连续存放 仅 一个地址（通常 4/8 字节）
sizeof 10 * sizeof(int)（40） sizeof(int*)（4/8）
& 运算 &a 类型 int (*)[10] &p 类型 **int **
赋值 a = ... 非法 p = &x 合法 
int a[10];
int *p = a;

sizeof(a);   /* 40 — 数组总大小 */
sizeof(p);   /* 4 或 8 — 指针本身大小 */

/* a = p;     编译错误 */
p = a;       /* OK：a 退化为 int* */

demo01_sizeof 还会展示：函数内 sizeof(arr) 当形参为 int arr[] 时 只剩指针大小。

存储布局示意

数组 a[3]（假设 int 4 字节）:
  地址:  1000   1004   1008
         [ a0 ] [ a1 ] [ a2 ]

指针 p（指向 a[0]）:
  地址:  2000
         [ 1000 ]  ← 只存首元素地址

数组 是 数据；指针 指向 数据。char arr[] = "hi" 把字符串 拷贝进数组；char *p = "hi" 让 p 指向 只读字面量 区域。

指针算术：arr+1 vs &arr+1

对 int local[10]（sizeof(int)==4）：

表达式 类型 地址变化 含义
local（退化） int* — 首元素地址，如 0x1000
local + 1 int* +4 下一个 元素
&local int (*)[10] — 整个数组 的地址（值常等于首元素地址）
&local + 1 int (*)[10] +40 跳过 整个数组 对象 
printf("local=%p  &local=%p\n", (void*)local, (void*)&local);
/* 数值常相同，类型不同 */
printf("local+1=%p  &local+1=%p\n",
       (void*)(local+1), (void*)(&local+1));
/* local+1 跳 1 元素；&local+1 跳 10 元素 — demo01 */

记忆：&arr 的类型是「指向 数组对象 的指针」，步长是 数组总字节数。

函数形参：数组退化为指针

void foo(int arr[]);   /* 等价于 void foo(int *arr); */
void bar(int *arr);    /* 完全相同的原型 */

C 标准规定：函数参数里的数组类型会被调整为指针类型。

位置 int a[10] 的含义
文件/块作用域 定义 真正的 int[10] 数组
函数形参 调整为 int*

因此：

void test(int arr[]) {
    sizeof(arr);  /* sizeof(int*)，不是 10*sizeof(int) */
}

不能 在函数内用 sizeof 求「传入数组元素个数」——须 额外传长度 或 传指针+size 参数（ch09 9.3 详述设计原因）。

重要：此等价 仅适用于形参；4.4 的文件作用域 extern 不适用。

形参等价写法对照

写法 是否同一原型
void f(int a[]) ✓
void f(int a[10]) ✓（长度被 忽略）
void f(int *a) ✓
void f(int a[static 10]) C99：特殊，仍与上不同语义（少见） 
/* 以下声明完全兼容 */
void f(int *);
void f(int[]);
void f(int[9999]);  /* 9999 被忽略，仍是指针形参 */

下标与解引用：a[i] == *(a+i)

C 定义下标运算符为：

a[i]  ≡  *(a + i)

其中 a 在表达式中通常 先退化为指针，再加 i（按元素类型缩放）。

int arr[] = {10, 20, 30};
int *p = arr;

arr[1];      /* 20 */
*(arr + 1);  /* 20 */
p[1];        /* 20 */
1[arr];      /* 20 — 见下 */

demo03_subscript 打印四者相等。

为什么 2[arr] 合法

由定义：

a[b]  =  *(a + b)  =  *(b + a)  =  b[a]

因此：

arr[2]  ==  2[arr];   /* 都等价 *(arr+2) */

可读性为零，标准允许，面试常考，生产代码勿用。

数组名不是左值（不可赋值）

int a[5], b[5];
/* a = b;   非法：数组名不是 modifiable lvalue */
int *p = a;  /* 合法：退化后赋给指针 */

指针是 可修改左值；数组名在表达式中是 地址常量（退化结果），不能作为赋值左端。

退化发生的典型场景（小结）

场景 数组名行为
赋给指针、传函数实参 退化为 T*
下标、+、- 运算 先退化再算
sizeof(a) 不退化
&a 不退化，得 T (*)[N]
声明/定义行 类型仍是数组

要点

什么是回文

回文：从左读到右与从右读到左 相同（常忽略大小写、空格、标点）。

类型 例子
单词 radar、level、rotor
句子 A man, a plan, a canal: Panama

与 C 字符串的朴素联系

判断 C 字符串是否回文，典型写法用到 4.5 的知识：

#include <ctype.h>
#include <string.h>

int is_palindrome(const char *s)
{
    size_t i, j;

    if (s == NULL)
        return 0;
    j = strlen(s);
    if (j == 0)
        return 1;
    j--;
    for (i = 0; i < j; i++, j--) {
        while (s[i] && !isalnum((unsigned char)s[i]))
            i++;
        while (j > i && !isalnum((unsigned char)s[j]))
            j--;
        if (tolower((unsigned char)s[i]) !=
            tolower((unsigned char)s[j]))
            return 0;
    }
    return 1;
}

要点：

  • 参数 const char *s：只读遍历，不假定 s 是数组还是指针——4.5 中二者在下标访问上可互换。
  • s[i] 与 *(s+i) 等价；也可用 i[s] 作恶作剧（4.5，勿用于正式代码）。
  • 若串在 char arr[] 中定义，传 arr 时 退化为 char* 传入函数。

双指针从两端夹逼

  "racecar"
   ↑     ↑
   i     j   比较 s[i] 与 s[j]，向中间移动

与 数组连续存储 一致：下标 i、j 是对 同一底层 char 序列 的偏移，不涉及「数组名 vs 指针」的跨文件陷阱。

Q1sizeof 的差异
int arr[10];
int *p = arr;

printf("%zu %zu\n", sizeof(arr), sizeof(p));
// 假设 64 位，int=4

void func(int a[10]) {
    printf("%zu\n", sizeof(a));
}

三处 sizeof 分别输出多少？

答案与复习指引

答案： 40 8（arr 是真数组 10×4=40；p 是指针 8 字节）；函数内 sizeof(a) = 8（形参退化为指针）。

关键： 数组名在 sizeof 和 & 时不退化；做函数形参时总是退化为指针。

复习： → 4.1 数组并非指针 · 4.5 数组和指针的其他区别

Q2extern 类型不匹配段错误
// def.c
char msg[] = "hello";

// use.c
extern char *msg;
int main() {
    printf("%c\n", msg[0]);
    return 0;
}

链接能通过吗？运行时发生什么？

答案与复习指引

答案： 链接可能成功（C 链接器不做类型检查），运行时崩溃。

def.c 中 msg 是 char[6]（6 字节数据 h,e,l,l,o,\0）。use.c 中 extern char *msg 把它当指针——读取 msg 的前 8 字节（64 位）作为地址值，即把 "hello\0" + 后续内存的字节解释为一个指针地址，然后解引用 → SIGSEGV。

规则： 跨文件 extern 必须类型完全一致。char[] ≠ char *。

复习： → 4.2 我的代码为什么无法运行 · 4.4 使声明与定义相匹配

Q3arr+1 vs &arr+1
int arr[5] = {10, 20, 30, 40, 50};
int *p1 = arr + 1;
int (*p2)[5] = &arr + 1;

printf("%d %d\n", *p1, *(p2 - 1)[0]);

*p1 和 *(p2 - 1)[0] 分别是多少？两个 +1 跳过的字节数？

答案与复习指引

答案： *p1 = 20，*(p2-1)[0] 等价于 arr[0] = 10（p2-1 指回 arr 的起始，[0] 取首元素）。

  • arr + 1：arr 退化为 int*，+1 跳 4 字节（一个 int）→ 指向 arr[1]
  • &arr + 1：&arr 类型是 int (*)[5]，+1 跳 20 字节（整个数组 5×4）→ 指向数组末尾之后

Q4形参等价性
void f1(int a[])     { /* sizeof(a) = ? */ }
void f2(int a[10])   { /* sizeof(a) = ? */ }
void f3(int *a)      { /* sizeof(a) = ? */ }

// 以下调用都合法吗？
int arr[5] = {0};
f1(arr);
f2(arr);
f3(arr);

int big[100] = {0};
f2(big);   // 形参写 [10]，但传了 [100]

三个函数的 sizeof(a) 是否相同？f2(big) 能编译通过吗？

答案与复习指引

答案： 三个 sizeof(a) 相同——都是指针大小（8 字节）。形参处 int a[]、int a[10]、int *a 完全等价，编译器都调整为 int *a。数组大小 10 被忽略。

f2(big) 能编译通过——形参的 10 不起约束作用，C 不检查数组大小。

但注意： 文件作用域的 extern int a[] 不等于 extern int *a——只有函数形参处才等价。
