2.1

这关语言特性何事，在Fortran里这就是Bug呀

本节讲什么

本章开篇用一个 Fortran DO 循环 的经典事故说明：程序员眼中的「明显 Bug」，在语言规则下可能是 完全合法的行为。C 同样充满这类「语言特性」——它们往往来自 历史妥协（为兼容旧代码、简化编译器、贴近硬件），而非现代语言设计中的「最佳实践」。本节建立全书基调：先读懂规则，再谈对错。

要点

Fortran DO 循环事故

程序员本意（循环 I 从 1 到 10）：

      DO 10 I = 1, 10
         ... 循环体 ...
   10  CONTINUE

若 漏写逗号，写成：

      DO 10 I = 1.10

在 Fortran 规则下可能被解析为：

  1. DO 10 I = 1 — 把常数 1 赋给 I，并 只执行一次 标号为 07 的语句
  2. .10 — 被当作浮点常数或标号相关 token，而非「从 1 到 10 的步进」

结果：本应是 10 次迭代的循环变成 单次赋值 + 一次跳转，航天器制导软件因此出错——在 Fortran 里这是 按语法合法 的，在工程上却是灾难。

视角 结论
程序员 「漏了一个逗号，显然是 Bug」
语言规范 「空格/标点解析结果符合文法 → 合法程序」
工程教训 编译器不会替你想意图；静态分析、代码审查、测试必不可少

「Bug」vs「语言特性」

类型 含义 C 中的例子（后文详述）
语言特性 标准明确规定的行为，可能反直觉但可预测 switch 贯穿、unsigned 比较提升
未定义行为（UB） 标准不保证后果，编译器可任意处理 有符号溢出、越界访问
实现定义 标准允许多种行为，文档需说明 char 有符号与否
真·历史 Bug 设计失误但无法移除 三字符组（trigraphs），见 2.5

核心区分：特性 = 可读标准能推导出行为；UB = 标准放手，优化器可「删掉你的代码」。

历史妥协：C 为何继承怪癖

C 不是从零设计的「干净语言」，而是 B → C → Unix 工具链 演进产物（见 ch01 1.1–1.2）：

硬件/编译器约束（PDP-11、单遍编译）
    ↓
语法极简、少运行时检查
    ↓
「多做」：默认 extern 链接、字符串自动拼接、宏文本替换
「少做」：无数组边界、无内建 bool（C89）、字符串无长度
「误做」：运算符优先级、* & [] 多重含义
    ↓
ANSI C（1989）标准化 → 保留绝大多数旧行为（quiet change，见 ch01 1.10）

妥协逻辑：已有海量 C 代码与 Unix 生态；改语义 = 静默破坏旧程序。标准选择 文档化现有行为，而非全面修正。

读本章的方法

  1. 遇到怪行为：先查是 特性、UB 还是实现定义（ch01 1.6）
  2. 写可移植代码：假设最严格语义；开启 -Wall -Wextra -Wconversion
  3. 写系统/内核代码：更要懂 实现定义 与 GCC/clang 扩展（Embedded C ch06）

代码自测

题目 1： 以下代码有什么「语言特性」导致的陷阱？

char* p = malloc(0);  // 返回什么？
参考答案

malloc(0) 的行为是实现定义的：可能返回 NULL，也可能返回一个非 NULL 但不可解引用的指针。不能假设返回值——可移植代码应检查 if (p == NULL)。这是 C 标准中「实现定义行为」的典型例子。其他常见陷阱：sizeof('a') 在 C 中是 sizeof(int) 不是 sizeof(char)。

2.2

多做之过

本节讲什么

Sins of Commission（多做之过）：语言 主动做了额外的事——有时是便利，有时是陷阱。本节覆盖 switch 贯穿、相邻字符串字面量拼接、文件作用域标识符默认 extern 链接、K&R 时代的 隐式 int 与 无原型函数声明，以及预处理器宏 多做 的文本替换（MULT、MAX）。这些行为在标准中合法，却常年制造生产事故。

要点

1. switch 贯穿（fall-through）

C 规定：case 标签 不会自动 break；匹配后代码 一直执行到 switch 结束或遇到 break。

switch (x) {
case 1: puts("one");
case 2: puts("two");   /* 无 break → 继续 */
case 3: puts("three"); break;
}
/* x==2 时输出 two 然后 three */
设计动机 风险
早期编译器简单；多 case 共享一段代码 漏写 break → 逻辑错误
C 刻意保留（非疏忽） 现代可用 -Wimplicit-fallthrough、注释 /* fallthrough */

Demo：demo/demo01_switch.c — x=2 时先打印 case2 再 case3。

cd demo && make all && ./demo01_switch

工程习惯：除非故意贯穿，每个 case 末尾写 break；或改用 if-else / 查表。

2. 相邻字符串字面量自动拼接

char *msg = "Hello, " "world!";   /* 等价于 "Hello, world!" */
printf("part1" "part2" "part3");   /* 编译期合并为一个字符串 */
  • 只做一件事：在 编译前 把相邻字面量合成一个
  • 用途：长字符串分行写、宏展开后拼接
  • 陷阱：与 宽字符、字符串化 # 混用时需小心；不是运行时拼接

3. 文件作用域默认 extern 链接

/* file1.c */
int counter = 0;        /* 定义：extern 链接，其他 .c 可见 */

/* file2.c */
extern int counter;     /* 声明，链接到 file1 的定义 */
关键字 链接属性 典型用途
（默认）全局变量/函数 external linkage 跨翻译单元共享
static（文件作用域） internal linkage 仅本 .c 可见，防符号冲突
extern（声明） 引用外部定义 头文件中声明 API

多做之过：不写 static 就 默认对外暴露符号 → 链接时命名冲突、意外耦合。头文件应配合 include guard 与 单一职责（ch05 链接专题）。

4. 隐式 int 与 K&R 函数声明

隐式 int（C89 前 / 宽松模式）：

f(x)   /* 未声明返回类型 → 默认 int */
{
    auto y;            /* 未声明类型 → 默认 int */
}

无原型声明（K&R）：

int f();             /* 不是 void f()！表示「返回 int，参数未指定」 */
f(3.14, "hello");    /* 旧式：不检查参数个数与类型 → 栈/寄存器错乱 */

ANSI C 要求 原型：

int f(int a, double b);   /* 类型检查 */
int g(void);              /* 无参数必须用 void */
对比 K&R int f() ANSI int f(void) / int f(int)
参数检查 无 有
与 f(...) 可变参 易混淆 用 <stdarg.h> 规范处理

见 ch01 1.4、demo01_kr_vs_ansi.c。

5. 预处理器：宏的「多做」

宏是 纯文本替换，编译器不做语义分析——比 Fortran 漏逗号更隐蔽。

MULT / MUL：缺少括号 → 优先级陷阱

#define MULT(a, b) a * b
#define MULT_SAFE(a, b) ((a) * (b))

MULT(1 + 2, 3 + 4);
/* 展开: 1 + 2 * 3 + 4  → 按 * 优先 → 1 + 6 + 4 = 11，而非 21 */
MULT_SAFE(1 + 2, 3 + 4);  /* ((1+2)*(3+4)) = 21 */

Demo：demo/demo03_macro_mul.c。

MAX：括号仍挡不住副作用重复求值

#define MAX(a, b) ((a) > (b) ? (a) : (b))

int i = 0, j = 5;
MAX(i++, j++);   /* i++, j++ 可能各执行两次 → 未定义行为 */
问题 原因 对策
优先级 宏体无括号 整体与参数 双层括号
副作用 a/b 在 ?: 两侧各出现一次 改用 inline 函数（C99）或 GCC statement expression
无类型 文本替换 static inline + <stdbool.h> / 泛型（C11 _Generic） 
static inline int max_int(int a, int b)
{
    return a > b ? a : b;   /* 实参只求值一次 */
}

与 ch01 1.3 的关系：1.3 讲宏机制；本节强调 「多做」的替换次数 与 链接/声明 类陷阱。

小结：多做之过清单

特性 「多做了什么」 防御
switch fall-through 匹配后继续执行 显式 break / 编译器警告
字符串拼接 合并相邻字面量 intentional 使用，别与指针运算混淆
默认 extern 全局符号导出 文件内 helper 用 static
隐式 int / 无原型 缺省类型与参数 -std=c11 -Wall、头文件原型
宏替换 展开整段文本 括号、避免副作用、优先 inline

2.3

误做之过

本节讲什么

Sins of Omission（误做之过）：van der Linden 在此节重点写 符号过载（overloaded symbols）——同一记号的含义依赖上下文，编译器 不会 替你在 = 与 ==、* 与 . 之间做「意图推断」。另有 static 双重语义、运算符优先级陷阱、非 void 函数缺 return 等。这类错误代码 常能编译通过，却在运行时或优化后产生离奇结果。

要点

1. static 的双重含义

位置 含义 存储期 / 链接
文件作用域 static int x; 内部链接 整个程序生命周期；仅本翻译单元可见
块作用域 static int cnt; 无链接属性变化 静态存储期：只初始化一次，下次进入块保留值 
void counter(void)
{
    static int n = 0;   /* 只初始化一次 */
    n++;
    printf("%d\n", n);
}
/* 多次调用 counter → 1, 2, 3, ... */

Demo：demo/demo04_static_dual.c — 对比文件 static 与块内 static。

误做之过：同一个关键字表示 链接限制 与 持久局部变量 两件不同的事；读代码必须看 声明位置。

2. 运算符优先级：* vs . / ->

结构体指针访问：

struct foo { int x; } s, *p = &s;

(*p).x = 1;    /* 正确：先解引用再取成员 */
*p.x = 1;      /* 错误：等价于 *(p.x)，把 . 当更高优先级 */
p->x = 1;      /* 推荐：-> 专为指针设计 */

记忆：. 与 -> 优先级 高于 一元 *；想对解引用结果取成员 必须加括号。

3. if 中的 =、==、&

if (a = b)       /* 赋值：b 的值赋给 a，条件为 b 是否非零 */
if (a == b)      /* 比较：相等为真 */
if (a & b)       /* 按位与：结果非零为真 */
写法 常见意图 实际
if (x = 0) 想判断等于 0 赋值 0，条件恒为假；编译器 -Wparentheses 可能警告
if (x == 0) 判断等于 0 正确
if (flags & MASK) 测试位 正确；别写成 if (flags = MASK)

防御：惯用 if (0 == x)（Yoda 条件，现代较少用）；更常见 if (x == 0) + 开启 -Wall；赋值进 if 时写 if ((ptr = get()) != NULL) 并加括号。

优先级链（节选）：

高 → 低：  ()  []  ->  .  →  !  *  &  →  ==  !=  →  &  →  |  →  &&  →  ||  →  =

== 高于 & 吗？ 不 — &（按位与）优先级 低于 ==：

if (a & MASK == 0)   /* 解析为 a & (MASK == 0)，通常不是本意 */
if ((a & MASK) == 0) /* 正确 */

4. 符号过载：*、&、[]

同一符号，多种含义：

符号 可能含义
* 乘法、指针解引用、声明指针
& 按位与、取地址
[] 下标、声明数组、函数参数「伪数组」 
int *p;           /* 声明：p 是指向 int 的指针 */
*p = 3;           /* 解引用 */
int a = 2 * 3;    /* 乘法 */

int i = 5;
int *q = &i;      /* 取地址 */
flags = flags & MASK;  /* 按位与 */

声明读法 需右左规则（ch03 整章）：int *p 中 * 绑定 p 而非 int。

int* a, b;   /* a 是指针，b 是 int — 易误读为两个指针 */

5. 非 void 函数缺少 return

int pick(int x)
{
    if (x > 0)
        return 1;
    /* x <= 0 时执行流到达函数末尾 — 未定义行为（C99 起） */
}
标准 行为
C89 可能返回「垃圾值」，部分编译器静默
C99+ ** reaching end of non-void function → UB **
优化 编译器可假设「不会到达末尾」，删除「看似可达」的代码（ch01 1.6 UB）

防御：所有路径 return；或用 -Wreturn-type；switch 加 default 与 return。

6. 与宏的交叉（衔接 2.2）

宏展开 不 改变 C 运算符规则：

#define SET_BIT(reg, bit) reg = reg | (1 << bit)
if (SET_BIT(x, 3))   /* 展开后 if 里是赋值，不是比较 */

复杂逻辑 不要用多语句裸宏；用 do { ... } while (0) 或 static inline 函数。

2.4

少做之过

本节讲什么

Sins of Subtraction（少做之过）：C 故意省略 现代语言常内置的检查与抽象——无数组边界、C89 无内建 bool、字符串无长度、隐式整型转换（尤其 signed/unsigned）。这些「不做」换取了接近硬件的速度与极简编译器，却把安全责任 完全推给程序员；系统编程与嵌入式领域必须正面理解这些缺口。

要点

1. 无数组边界检查

int a[10];
a[10] = 0;      /* 越界写 — 未定义行为 */
a[-1] = 0;      /* 同样 UB */
C 的做法 后果
不生成边界检查指令 性能接近手写汇编；内核/DPDK 依赖于此
越界 = UB 编译器可假设「下标永远合法」做激进优化
不保证 crash 可能 静默覆盖 栈上其他变量、函数返回地址

防御：

  • 显式检查下标；使用 sizeof(a)/sizeof(a[0]) 算长度（仅对 真实数组 有效，指针不行——ch04）
  • C99 VLA、C11 _Static_assert；C++ 边界 std::vector
  • 工具：ASan、UBSan（-fsanitize=address,undefined）
  • 内核：KASAN；Embedded C 5.7 内存踩踏监测

2. 没有 bool（C89）与「真值」语义

C89 用 int 表示逻辑值：非零为真，零为假。

/* C89 风格 */
if (flag) { ... }

/* C99 起 */
#include <stdbool.h>
bool ok = true;
时期 类型 注意
C89 int / 自定义 typedef if (p = malloc(...)) 等惯用法
C99+ _Bool / bool 与 int 可互转；<stdbool.h>
陷阱 bool promoted 到 int 与 可变参、位域 混用时读标准

少做之过：长期无专用布尔类型，加剧 = 与 == 混淆（2.3）。

3. C 字符串：无长度，以 \0 结尾

char s[] = "hello";   /* 6 字节：'h'..'o' + '\0' */
strlen(s);            /* 扫描直到 \0 — O(n) */
strcpy(dst, src);     /* 不检查 dst 容量 → 经典溢出 */
缺失 影响
不存储长度 不能 O(1) 知长度；二进制数据不能直接用 C 字符串
NUL 终止 中间不能含 \0；漏写终止符 → 越界读
库函数 strcpy/strcat 不 带 bounds → 改用 strncpy/snprintf（仍需谨慎）

现代替代：POSIX strnlen、C11 bounds-checking 附录（可选）、C++ std::string_view。内核自研 strscpy 等安全 API。

4. 隐式转换：signed 与 unsigned

当 有符号与无符号 同处一个表达式，C 倾向于 把有符号转为无符号 再运算。

unsigned u = 5;
int i = -1;

if (u > i)   /* i 转为 unsigned → 巨大正数 → 条件为假 */
    puts("u > i");
else
    puts("u <= i");   /* 实际走这里 */

Demo：demo/demo02_sign_unsigned.c。

场景 典型坑
比较 u > i 负 int → 大 unsigned
unsigned 减法下溢 0u - 1u → UINT_MAX，循环永不结束
混合赋值 -1 赋给 unsigned → 全 1 位模式
移位 负值或超位宽移位 → UB 或 impl-defined

整型提升（integer promotion）：

char c1, c2;
c1 = c2 + c3;   /* c2、c3 先提升为 int 再相加，再截断赋回 char — 可能溢出 */

见 ch01 1.2 float 提升；ch08 整型与浮点转换。

防御：

  • 比较前 显式 cast 到同一类型，并注释意图
  • 无符号仅用于 位掩码 / 模运算；循环计数慎用 unsigned
  • 编译选项 -Wsign-compare -Wconversion
  • 可移植整数：<stdint.h>（Embedded C ch07）

5. 四类「少做」叠加效应

无边界 + 无长度字符串 + 隐式转换 + 无 bool
    ↓
一次 off-by-one 或符号错误
    ↓
缓冲区溢出 / 死循环 / 安全漏洞
    ↓
「在别的编译器上能跑」的 UB 地雷

Heartbleed 类漏洞与 长度字段缺失 的协议解析，都可追溯到「C 少做 + 程序员假设过多」。

语言未提供 程序员必须
数组边界 自行检查；用 Sanitizer
bool（C89） 约定 0/非 0；C99 用 <stdbool.h>
字符串长度 传递 size_t n；用 snprintf
安全算术 显式类型；避免 signed/unsigned 混比

轻松一下——有些特性确实就是Bug

本节讲什么

并非所有怪癖都能用「历史妥协」优雅开脱——有些特性是 设计失误或标准化事故，因 已有代码依赖 或 无法从语法中抠除 而长期留存。本节用轻松笔调列举 三字符组（trigraphs）、C89 前没有 // 注释、悬空 else 等案例，并区分：可学规则避坑 vs 只能指望编译器默认关闭/警告 的真 Bug 级特性。

要点

1. 三字符组（Trigraphs）——标准里的「幽灵」

为适配 键盘缺少 #[]{}|^~ 的老式终端，C 引入 三字符组 替换：

三字符组 替换为
??= #
??/ \
??(' |[`
??) ]
??<' |{`
??> }
??! \|
??- ~ 
/* 程序员写： */
printf("What??!??!");
/* 可能被预处理成含 | 和 ! 的 token 序列 — 字符串内也可能受影响（视阶段而定） */

为何像 Bug：意图是 可移植输入，结果却是 源码里看不见的二义性；现代编辑器与 ASCII 键盘普及后 毫无益处。

现状：

  • C23 起 trigraphs 移除（长期 deprecated）
  • GCC/Clang 默认通常 不启用；-trigraphs 才打开
  • 教训：别在代码里写 ?? 序列开玩笑

2. // 注释：在「老 C」里不是语言特性

标准 // 单行注释
K&R / C89 不支持 — 只有 /* */
C99 起 标准化
C++ 一直支持 
/* C89 合法 */
int x = 1; /* 注释 */

// 这在 C89 中是语法错误（或部分编译器当扩展）
// int y = 2;

少做之过 + 真混乱：混合 C/C++ 项目、老旧嵌入式编译器若锁 -std=c89，// 会导致 整文件编译失败。GNU 扩展曾提前提供 //，造成 「在我机器上能跑」 的移植坑。

习惯：需 C89 的公共头文件 只用 /* */；.c 若允许 C99 再用 //。

3. 悬空 else（Dangling else）

if (a)
    if (b)
        x = 1;
else        /* 绑定内层 if 还是外层 if？ */
    x = 2;

C 规则：else 与最近 unmatched 的 if 配对 → 上面 else 属于 if (b)。

写法 效果
默认 else 挂内层 if
意图挂外层 外层 if 加 大括号 
if (a) {
    if (b)
        x = 1;
} else
    x = 2;

不是解析器 Bug，但 语言设计易误导；属于 2.3 误做之过 的「人类可读性缺失」。

4. 其他「真·Bug 味」特性

特性 问题 应对
digraphs <: :> 等 类似 trigraph，输入兼容 几乎不见；别写
# 与宏换行 反斜杠续行易错 宏用工具生成或 inline
空宏 #define X 替换为空，残留空格 用 #ifdef 而非空定义
typedef 重名（旧代码） 作用域规则曾更松 遵循 C89 后规则

5. 特性 vs 真 Bug：如何判断

能写清楚标准语义、且可稳定推导 → 语言特性（即使讨厌）
标准都说不清的优化空间 → UB（2.1、ch01 1.6）
标准承认是败笔但不能删 → 2.5 本节（trigraphs）
编译器默认关闭 + 文档警告 deprecated → 等标准删除

轻松一下的严肃结论：读 Expert C 不是为了嘲笑 C，而是 在写内核、协议栈、DPDK 热路径之前，知道哪些地雷是 规则、哪些是 标准也后悔的遗产。

章节自测

语言特性 vs Bug：三类之过——多做、误做、少做。看代码 → 想答案 → 点开验证。

Q1switch 贯穿
int level = 2;
int points = 0;

switch (level) {
    case 1:
        points += 10;
    case 2:
        points += 20;
    case 3:
        points += 30;
    default:
        points += 5;
}

printf("points = %d\n", points);

points 的值是多少？这是 Bug 还是语言特性？

答案与复习指引

答案： points = 55（20+30+5）。case 2 匹配后没有 break，贯穿执行后续所有 case 直到 break 或结束。

这是语言特性（fall-through），不是 Bug——但容易引发错误。-Wimplicit-fallthrough 可检测意外贯穿。

用途： 有意贯穿可以简化代码（如 case 1: case 2: ... 共享逻辑）。

复习： → 2.2 多做之过

Q2signed vs unsigned 比较
unsigned int remaining = 10;
int requested = -1;

if (requested <= remaining)
    printf("OK: sending %d items\n", requested);
else
    printf("ERROR: too many\n");

输出什么？为什么？

答案与复习指引

答案： 输出 ERROR: too many。requested = -1 与 unsigned 比较时，requested 被隐式转换为 unsigned，变成 4294967295（UINT_MAX），远大于 10。

这是"少做之过"——C 不阻止 signed/unsigned 混合比较，编译器通常只给 warning。

HFT 灾难： 如果用 int 表示订单数量，-1 作为"无效"标记，与 unsigned 库存比较时永远"充足"。

复习： → 2.4 少做之过

Q3宏优先级陷阱
#define MULT(a, b) a * b

int r1 = MULT(2, 3);        // A
int r2 = MULT(1 + 2, 3);    // B
int r3 = MULT(2, 1 + 2);    // C

r1、r2、r3 分别是多少？

答案与复习指引

答案： r1 = 6，r2 = 5（1 + 2 * 3 = 7？不对——展开是 1 + 2 * 3 = 1+6 = 7），r3 = 5（2 * 1 + 2 = 4？不对——展开是 2 * 1 + 2 = 2+2 = 4）。

重新计算： - r2 = 1 + 2 * 3 = 1 + 6 = 7 - r3 = 2 * 1 + 2 = 2 + 2 = 4

修正： #define MULT(a, b) ((a) * (b)) — 每个参数和整体都加括号。

复习： → 2.2 多做之过

Q4static 双义
// file scope（文件顶部）
static int counter = 0;       // 含义 A

void func(void) {
    static int call_count = 0; // 含义 B
    call_count++;
    counter++;
}

// 另一个文件
extern int counter;           // 能链接吗？

含义 A 和 B 分别是什么？extern 能访问 counter 吗？

答案与复习指引

答案： - A（文件作用域 static）：内部链接——只在本 .c 文件可见，extern 无法访问。 - B（块作用域 static）：静态存储期——函数返回后值不丢失，但作用域仍限于函数内。只在首次调用时初始化。
