# 3.9 字符串字面量只读

## 本节讲什么

字符串字面量存储在 **只读段（`.rodata`）**。`char *p = "hello"` 后 **修改 `p[i]`** 为 UB，常 **SIGSEGV**。

## 要点

```c
char *p = "hello";
p[0] = 'H';        /* UB / 段错误 */

char arr[] = "hello";
arr[0] = 'H';      /* 合法：栈/数据段副本 */
```

## 代码自测

**题目 1：** 以下代码会发生什么？
```c
char* s = "hello";
s[0] = 'H';  // 合法吗？
```

<details>
<summary>参考答案</summary>

未定义行为。字符串字面量存储在只读段（.rodata），修改它可能段错误。正确做法：
```c
char s[] = "hello";  // 在栈上复制一份
s[0] = 'H';  // OK
```
`char* s = "hello"` 中 s 指向只读内存；`char s[] = "hello"` 中 s 是栈数组，内容可修改。

> ⚠️ **勘误**：此处原写「C11 起字符串字面量类型为 `const char[]`」——**错误**。
> C 标准从 C89 到 C23，字符串字面量的类型始终是 **`char[N]`（不带 const）**，修改它才是 UB；
> **`const char[N]` 是 C++ 的规则**。正因 C 里不加 const，`char *s = "hello";` 在默认 `-Wall` 下
> **连警告都没有**（实测 clang 23.1.0），坑被推迟到运行期才爆。详见
> [《C和指针》8.1.11 数组类型表达式清单](../../02-advanced-pointers-and-memory/ch08-arrays/8.1-one-dimensional-arrays/8.1.11-数组类型表达式清单.md)。

**实测补充**（clang 23.1.0 / macOS arm64）：

```c
char *p = "hello";
p[0] = 'H';      /* UB */
```

| 环境 | 实际结果 |
|------|---------|
| macOS arm64（实测） | 进程收到 **SIGBUS(10)**，`echo $?` = **138**，不是 139 |
| Linux x86-64/aarch64 | 通常 **SIGSEGV(11)**，`$?` = 139 |
| 裸机 MCU（Flash 常量区） | 可能**静默失败**（写被丢弃），也可能 HardFault——**没有任何一种保证崩溃** |

所以"大概率直接段错误"只是**带 MMU 的通用 OS** 上的表现，标准只保证**未定义行为**，不保证崩溃。工程上靠 `const char *` 在编译期挡住，而不是指望运行期崩给你看。

</details>
