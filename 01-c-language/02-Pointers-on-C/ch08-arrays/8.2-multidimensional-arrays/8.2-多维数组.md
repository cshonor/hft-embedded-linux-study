# 8.2 多维数组

## 本节讲什么

**数组的数组**：`int buf[4][3]` 为 4 行 × 3 列，**行优先**连续存储。内核页表、DPDK 多端口队列、HFT 批量行情池的基础。多维数组的关键是"连续平铺 + 行优先"，它决定了 cache 行为和传参规则。

## 要点

- **`buf[i][j] == *(*(buf + i) + j)`**（双重解引用）
- **`buf[i]`** 是第 i 行（`int[3]`），退化为 `&buf[i][0]`
- 传参：**仅第一维可省略**，其余维度必须写死（**8.2.5**）
- 存储：行优先连续平铺，无指针间接层（**8.2.1**）

```c
int buf[4][3];           /* 4 行 3 列 */
buf[2][1] = 42;          /* 第 2 行第 1 列 */
int (*row)[3] = buf;     /* 数组指针，指向一行（8.2.4） */
```

### 退化层次

```c
int buf[4][3];
/* buf 退化为 &buf[0]，类型 int(*)[3] —— 指向"一行" */
/* buf[i] 退化为 &buf[i][0]，类型 int* —— 指向一个元素 */
/* buf[i][j] 是 int 值 */
```

每多一个下标，"剥一层"：`buf` 是"行的数组"，`buf[i]` 是"int 的数组"，`buf[i][j]` 是 int。

## 底层映射

### 内存布局

```
地址递增 →
[0][0][0][0][1][0][2] [1][0][1][1][1][2] [2][0]... [3][2]
 └── 第 0 行 ──┘  └── 第 1 行 ──┘  └ 第 2 行 ┘  └第3行┘
```

`buf[i][j]` 的地址 = `base + (i*3 + j) * sizeof(int)`。编译器用第二维 3 算行宽——这就是为什么传参必须保留第二维（**8.2.5**）。

### vs 指针数组（**8.3**）

| | `int buf[4][3]`（二维数组） | `int *arr[4]`（指针数组） |
|---|---|---|
| 存储 | 连续平铺 | 指针连续，所指分散 |
| `arr[i][j]` | 一次访存 | 两次访存（先取指针再取元素） |
| cache | 友好 | 每行可能 miss |
| 适合 | 固定大小表 | 不等长行（如字符串表） |

## HFT / DPDK

| 场景 | 用法 |
|------|------|
| 行情快照表 | `struct quote snap[N_SYM][N_LEVEL]` |
| 多端口队列 | `struct rte_mbuf *port_q[NPORT][NQ]` |
| 配置矩阵 | `int cfg[N_ROW][N_COL]` |
| 帧缓冲 | `char fb[HEIGHT][WIDTH]`（stride 可能 ≥ 行宽） |

## 常见误区

| 误区 | 事实 |
|------|------|
| "多维数组有指针间接层" | 没有，连续平铺 |
| "`buf[i]` 是个 int" | 是第 i 行（`int[3]`），退化为 `int*` |
| "传参所有维都能省" | 只第一维可省，其余必须（**8.2.5**） |
| "`int **` 能指向二维数组" | 不能，类型不匹配（行连续 vs 行分散） |
