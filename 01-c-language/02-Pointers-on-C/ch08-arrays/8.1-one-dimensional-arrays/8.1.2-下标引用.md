# 8.1.2 下标引用

## 本节讲什么

**`arr[i]`** 访问第 i 个元素；下标从 **0** 到 **length-1**。这一节讲清下标的本质（就是指针算术）、越界的 UB 性质、以及为什么 C 没有运行时边界检查。

## 要点

- 编译器将 `arr[i]` 转为 `*(arr + i)`（**ch06 6.11**）
- 越界 → **UB**：C 标准不要求运行时检查
- 负下标仅当指针已偏移到合法区域前才有定义（`p[-1]` 当 `p` 指向 arr[1]）
- `0 <= i < length` 是唯一合法范围

```c
int arr[10];
arr[0] = 1;       /* 首元素 */
arr[9] = 10;      /* 末元素 */
arr[10] = 0;      /* UB：越界写 */
arr[-1] = 0;      /* UB：越界写 */
```

### 负下标的合法用法

```c
int arr[10];
int *p = arr + 5;     /* p 指向 arr[5] */
int x = p[-1];        /* 合法：等价 arr[4] */
int y = p[-5];        /* 合法：等价 arr[0] */
int z = p[-6];        /* UB：越界 */
```

负下标本质是"指针向前偏移"——只要落在数组范围内就合法。实际工程少见，但读内核代码偶尔遇到。

## 底层映射

### 越界为什么"能跑"又危险

C 不插入边界检查——`arr[i]` 直接生成 `mov [base + i*scale]`，硬件不问越界：

```c
int arr[10];
arr[20] = 0xdead;   /* 写到 arr 起始 + 80 字节处 */
```

```
mov DWORD PTR [rsp + 80], 0xdead   ; 直接算地址写，不检查
```

- 若 `arr + 80` 落在可写栈页 → 静默踩别的局部变量，bug 远离现场才爆
- 若落在不可写页 → `SIGSEGV`
- 若落在堆块 → 堆破坏，UAF 式灾难

这就是为什么 C 数组越界是"最阴险的 UB"——不崩比崩更可怕。

### 边界检查工具

| 工具 | 机制 | 开销 |
|------|------|------|
| **ASan** (`-fsanitize=address`) | 红区 + 影子内存 | 2x 速度 |
| **UBSan** (`-fsanitize=bounds`) | 插入运行时检查 | 低 |
| `-fbounds-checking` | 旧式插桩 | 中 |

```bash
# UBSan 专门抓数组越界
gcc -g -fsanitize=undefined,bounds t.c -o t && ./t
# 报告: index 20 out of range for type 'int [10]'
```

## HFT / DPDK

```c
for (i = 0; i < nb_pkts; i++)
    process(pkts[i]);      /* 下标遍历，-O2 后常归一为指针 */
```

### 工程纪律

- 循环边界用 `< length`，不用 `<= length - 1`（防 length=0 溢出）
- 接收外部长度时显式检查 `if (n > BURST) return -EINVAL;`
- CI 开 `-fsanitize=address,undefined` 跑测试
- 静态分析（`scan-build`、clang-tidy）找越界嫌疑

## 常见误区

| 误区 | 事实 |
|------|------|
| "越界一定立刻崩" | 最怕"碰巧能跑"，掩盖问题 |
| "C 有运行时边界检查" | 没有，直接生成访存指令 |
| "负下标永远非法" | 指针向前偏移到合法范围内合法 |
| "ASan 能抓所有越界" | 栈红区有限，远越界可能漏 |

## 实操

```bash
# ASan/UBSan 抓越界
gcc -g -fsanitize=address,undefined t.c -o t && ./t
# 看越界生成的无检查访存
gcc -O2 -S t.c -o - | grep 'mov.*rsp'
# 故意越界写，看"碰巧能跑"的阴险
cat > t.c << 'EOF'
int main(void) {
    int arr[10], victim = 0;
    arr[12] = 0xdead;        /* 踩到附近栈 */
    return victim;           /* 可能被改 */
}
EOF
gcc -O0 t.c -o t && ./t; echo $?
```

## 代码自测

**题目 1：** 以下代码输出什么？
```c
int arr[5] = {10, 20, 30, 40, 50};
int i = 2;
printf("%d %d %d\n", arr[i], i[arr], *(arr + i));
```

<details>
<summary>参考答案</summary>

三行都输出 30。arr[i] 等价于 *(arr + i)，而 i[arr] 等价于 *(i + arr)——加法交换律使得两者相同。虽然 i[arr] 语法合法，但极不推荐，仅供理解 C 的下标语义。

</details>
