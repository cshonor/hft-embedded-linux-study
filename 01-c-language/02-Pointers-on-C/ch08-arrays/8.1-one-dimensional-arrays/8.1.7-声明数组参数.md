# 8.1.7 声明数组参数

## 本节讲什么

形参声明的三种等价写法；**方括号内长度被忽略**（多维除外，见 8.2.5）。这一节讲清三种写法为什么等价、什么时候方括号长度有文档意义。

## 要点

```c
void f(int arr[]);          /* 写法 1：不指定长度 */
void f(int arr[1024]);      /* 写法 2：指定长度（被忽略） */
void f(int *arr);           /* 写法 3：指针 */
/* 三者完全等价 */
```

- C 标准：数组参数调整为**指针**（adjustment）
- 方括号内的长度**无约束作用**，仅作文档
- 文档性长度可写 `char name[64]` 提示读者"期望 64 字节缓冲"

### 三种等价的证明

```c
void f(int arr[]);       
void f(int arr[1024]);  
void f(int *arr);        
```

```bash
$ gcc -c t.c   # 不会报"重复定义"，因为三者是同一签名
```

编译器把三者都调整成 `void f(int *)`。方括号长度 1024 不产生任何检查代码。

### 什么时候方括号长度有意义

**仅多维数组的第一维可省，其余维度必须保留**（**8.2.5**）：

```c
void g(int tbl[][3], int rows);   /* 第二维 3 必须写 */
void g(int (*tbl)[3], int rows);   /* 等价 */
void bad(int tbl[][]);             /* 非法：缺第二维 */
```

第二维告诉编译器"每行几个元素"，用于 `tbl + i` 的步长计算（跳 `3*sizeof(int)`）。

## 底层映射

### `static` 长度提示（C99）

```c
void f(int arr[static 64]) {   /* 提示：arr 至少 64 元素 */
    ...
}
```

`static` 关键字告诉编译器"调用者保证传至少 64 元素的数组"。部分编译器据此优化（如展开循环、向量化），但**不强制运行时检查**。GCC/Clang 会给告警若能静态分析出不足。

### 文档性长度的工程价值

```c
void parse_pkt(const uint8_t pkt[64]) {  /* 提示以太网帧 64 字节 */
    ...
}
```

读代码的人一眼知道"期望 64 字节缓冲"。但记住这只是文档——`pkt` 实际是 `const uint8_t *`，调用者传 10 字节也不报错（除非加 `static` 且编译器分析到）。

## HFT / DPDK

| 写法 | 用途 |
|------|------|
| `void f(int *arr, size_t n)` | 通用数组，长度显式 |
| `void g(char buf[2048])` | 报文缓冲，文档性 |
| `void h(int tbl[][COLS], int rows)` | 二维表 |
| `void p(int arr[static 64])` | C99 最小长度提示 |

## 常见误区

| 误区 | 事实 |
|------|------|
| "`f(int arr[1024])` 能限定调用者传 1024 元素" | 不能，长度被忽略 |
| "三种写法不等价" | 完全等价，都调整成指针 |
| "`static 64` 会运行时检查" | 不会，仅编译期静态分析告警 |
| "多维第一维也必须写" | 第一维可省，其余必须 |

## 实操

```bash
# 验证三种写法等价（不报重复定义）
cat > t.c << 'EOF'
void f(int arr[]);
void f(int arr[1024]);
void f(int *arr);
EOF
gcc -c t.c -o t.o   # 无错误
# static 长度提示的告警
cat > t.c << 'EOF'
void f(int arr[static 64]);
int main(void){int a[10];f(a);return 0;}
EOF
gcc -Wall t.c -c    # warning: argument too small
```
