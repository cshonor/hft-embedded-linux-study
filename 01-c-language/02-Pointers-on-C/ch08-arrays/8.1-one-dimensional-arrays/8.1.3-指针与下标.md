# 8.1.3 指针与下标

## 本节讲什么

**下标与指针算术完全等价**——`arr[i]` ≡ `*(arr+i)`。两种遍历风格在 `-O2` 后常归一成同一段汇编，选哪个主要是可读性。这一节用汇编证据消除"指针一定更快"的误区（**8.1.4** 样板详）。

## 要点

```c
/* 下标风格 */
for (i = 0; i < n; i++)
    sum += arr[i];

/* 指针风格 */
for (p = arr; p < arr + n; p++)
    sum += *p;
```

- 两者语义等价，`-O2` 后常生成相同汇编
- `p[i]` 合法：`p` 指向某元素时，`p[i]` ≡ `*(p+i)`
- **`3[arr]`** 合法（`*(3+arr)`），但禁止写——可交换性的副产品

### 何时指针风格更清晰

- 遍历连续区间：`for (p = begin; p < end; p++)` 的"游标"语义
- 字符串操作：`while (*s) s++;`
- 报文偏移：`uint8_t *p = pkt; p += parse_hdr(p);`

### 何时下标更清晰

- 多维访问：`tbl[i][j]` 比 `*(*(tbl+i)+j)` 易读
- 随机访问：`arr[rand_idx]`
- 固定位置：`header->fields[3]`

## 底层映射

### `-O2` 后两种风格归一

```c
int sum_idx(const int *arr, int n) {
    int s = 0;
    for (int i = 0; i < n; i++) s += arr[i];
    return s;
}
int sum_ptr(const int *arr, int n) {
    int s = 0;
    const int *p;
    for (p = arr; p < arr + n; p++) s += *p;
    return s;
}
```

```bash
$ gcc -O2 -S t.c -o -
```

```
; 两者核心循环都是：
.L1:
    add     eax, DWORD PTR [rdi + rcx*4]   ; arr 在 rdi，i/游标在 rcx
    inc     rcx
    cmp     ecx, edx
    jl      .L1
```

下标版用 `[rdi + i*4]`（比例变址），指针版用 `[rdi]` + 游标推进——优化器把它们归一成同一段。所以"指针必快"是 70 年代的陈旧直觉（**8.1.4** 详）。

### 指针风格利于优化的真实机制

不是 `*p++` 本身快，而是**指针更易承若 `restrict`**，触发向量化：

```c
void add(int *restrict a, const int *restrict b, int n) {
    for (int i = 0; i < n; i++) a[i] += b[i];   /* restrict 触发 paddd */
}
```

`restrict` 让编译器假设无别名，一次处理 8 个 int（**ch06 6.9**）。这才是性能差异的真正来源。

## HFT / DPDK

| 场景 | 风格 |
|------|------|
| 连续报文遍历 | 指针游标 `p++` |
| 多维表 | 下标 `tbl[i][j]` |
| 批量收包 | 下标 `pkts[i]` |
| 字符串解析 | 指针 `while (*p) ...` |

## 常见误区

| 误区 | 事实 |
|------|------|
| "指针遍历一定比下标快" | `-O2` 后常归一，差异在 restrict 而非写法 |
| "`3[arr]` 是错的" | 标准合法（`*(3+arr)`），但禁止写 |
| "下标更慢因为有乘法" | 硬件比例变址免费，无 imul |
| "指针风格总是更 C" | 可读性优先，按场景选 |

## 实操

```bash
# 对比两种风格的汇编
gcc -O2 -S t.c -o - | grep -A6 'sum_idx\|sum_ptr'
# 看 restrict 如何触发向量化
gcc -O3 -mavx2 -S t.c -o - | grep paddd
# 3[arr] 合法性演示
cat > t.c << 'EOF'
#include <stdio.h>
int main(void){int a[]={10,20,30};printf("%d\n",2[a]);return 0;}
EOF
gcc t.c -o t && ./t   # 30
```

## 代码自测

**题目 1：** 以下两种遍历方式哪个更快？为什么？
```c
// 方式 A：下标
for (int i = 0; i < n; i++)
    sum += arr[i];
// 方式 B：指针
for (int *p = arr; p < arr + n; p++)
    sum += *p;
```

<details>
<summary>参考答案</summary>

现代编译器（GCC/O2）下两者生成相同的机器码——编译器会将下标访问优化为指针递增。但在早期的 C 教材中，指针方式被认为更快（少一次加法）。实际差异取决于编译器优化能力。可读性方面，下标方式更清晰。

</details>
