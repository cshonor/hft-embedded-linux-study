# 11.5 常见错误

## 本节讲什么

动态内存的**四大故障**——**内存泄漏、悬垂指针、双重释放、堆越界**——是 HFT/网关线上崩溃的主因。它们都是 UB，表现各异：泄漏导致 OOM 被杀，悬垂导致静默踩踏，双重释放立即 SIGABRT，堆越界延迟崩溃。本节剖析每种错误的成因、症状、检测工具、根治方法。

## 要点

### 1. 内存泄漏 Memory Leak

**成因**：malloc 后未 free，或指针丢失导致无法 free。

```c
/* 泄漏 1：忘记 free */
void f(void) {
    char *buf = malloc(1024);
    /* ... 用完 ... */
    /* 忘记 free(buf) —— 泄漏 1024 字节 */
}

/* 泄漏 2：指针被覆盖 */
void f(void) {
    char *p = malloc(100);
    p = malloc(200);   /* 原 100 字节地址丢失，泄漏 */
    free(p);           /* 只释放了 200 字节块 */
}

/* 泄漏 3：异常路径漏 free */
int f(void) {
    char *buf = malloc(1024);
    if (step1() < 0) return -1;   /* 漏 free(buf) */
    free(buf);
    return 0;
}
```

**症状**：

- 进程 RSS 持续增长
- 长跑进程最终 OOM 被 kill
- 短期可能无明显症状

**检测**：

```bash
valgrind --leak-check=full ./prog
# 或
ASAN_OPTIONS=detect_leaks=1 ./prog_asan
```

**根治**：

- 每条 malloc 配对 free
- 异常路径用 `goto cleanup`
- 静态分析：`clang-tidy`、`cppcheck`

### 2. 悬垂指针 Dangling Pointer

**成因**：free 后仍通过原指针访问。

```c
int *p = malloc(sizeof(int));
*p = 42;
free(p);
*p = 100;   /* UB：已释放 */
int x = *p; /* UB：读取已释放内存 */
```

**症状**：

- 立即崩溃（若页已归还内核）—— 少见
- **静默踩踏**（若内存被复用）—— 更危险
- 数据随机错乱，难复现

**检测**：

```bash
# ASan：use-after-free
ASAN_OPTIONS=detect_leaks=1 ./prog_asan
# ==12345==ERROR: AddressSanitizer: heap-use-after-free

# valgrind
valgrind ./prog
# Invalid write of size 4
```

**根治**：

```c
free(p);
p = NULL;   /* 铁律：free 后置 NULL */

/* 后续误用时立即 SIGSEGV，而非静默踩踏 */
*p = 100;   /* NULL 解引用，SIGSEGV */
```

### 3. 双重释放 Double Free

**成因**：同一地址 free 两次。

```c
int *p = malloc(sizeof(int));
free(p);
free(p);   /* UB：双重释放 */
```

**症状**：

- glibc 检测到 `double free or corruption` → SIGABRT
- 其他实现可能静默破坏 free list → 后续随机崩溃
- 是安全漏洞（CVE）的常见根源

**检测**：

```bash
ASan: attempting double-free
valgrind: Invalid free
```

**根治**：

```c
/* 模式 1：判 NULL */
if (p) {
    free(p);
    p = NULL;
}

/* 模式 2：SAFEREE 宏 */
#define SAFEREE(p) do { free(p); (p) = NULL; } while (0)
```

`free(NULL)` 是安全空操作，所以置 NULL 后再 free 也无碍。

### 4. 堆越界 Heap Out-of-Bounds

**成因**：读写超过 malloc 请求的大小。

```c
int *arr = malloc(10 * sizeof(int));
arr[10] = 42;    /* UB：越界写 */
arr[15] = 100;   /* UB：越界写，可能破坏元数据 */
int x = arr[20]; /* UB：越界读 */
```

**症状**：

- **延迟崩溃**：越界写覆盖 malloc 头部元数据，下次 free/malloc 时崩溃
- **数据错乱**：越界写到相邻块，改了别人的数据
- **静默**：若越界落在 padding 区域，可能无症状
- 是 Heartbleed（CVE-2014-0160）的根因

**检测**：

```bash
# ASan：堆越界
ASAN_OPTIONS=detect_leaks=1 ./prog_asan
# ==12345==ERROR: AddressSanitizer: heap-buffer-overflow

# valgrind
valgrind ./prog
# Invalid write of size 4
```

**根治**：

```c
size_t cap = 10;
int *arr = malloc(cap * sizeof(int));
if (!arr) return;

/* 每次访问前校验 */
for (int i = 0; i < cap; i++) {   /* i < cap，非 i <= cap */
    arr[i] = i;
}

/* 或用带边界检查的抽象 */
typedef struct { int *data; size_t cap, size; } vec;
int vec_set(vec *v, size_t i, int x) {
    if (i >= v->cap) return -1;   /* 边界检查 */
    v->data[i] = x;
    return 0;
}
```

### 5. 整数溢出导致的小块分配

**成因**：`n * sizeof(T)` 溢出，malloc 分配远小于预期。

```c
size_t n = 0x100000001;   /* 假设 32 位 size_t */
int *p = malloc(n * sizeof(int));   /* 溢出：n * 4 = 4，实际只分 4 字节 */
p[0] = 1;   /* 似乎正常 */
p[100] = 2; /* 越界，UB */
```

**根治**：

```c
/* 用 calloc：内置溢出检测 */
int *p = calloc(n, sizeof(int));
if (!p) return;

/* 或手动检测 */
if (n > SIZE_MAX / sizeof(int)) return NULL;
int *p = malloc(n * sizeof(int));
```

### 6. use-after-scope

**成因**：返回栈地址或闭包捕获栈引用。

```c
int *f(void) {
    int x = 42;
    return &x;   /* UB：返回栈地址，函数返回后栈帧失效 */
}

int *p = f();
*p;   /* UB：访问已失效的栈内存 */
```

**根治**：

- 栈对象只在本函数内使用
- 需返回对象用堆或输出参数

### 工具对比

| 工具 | 检测能力 | 性能开销 | 适用 |
|------|----------|----------|------|
| **ASan** | 越界、UAF、double free、泄漏 | 2-5x | 开发/CI |
| **UBSan** | 整数溢出、UB | 1.2x | 开发 |
| **valgrind/memcheck** | 越界、UAF、泄漏 | 20-50x | 开发 |
| **valgrind/massif** | 内存增长分析 | 20x | 调优 |
| **gdb** | 事后 core 分析 | 0 | 调试 |
| **mtrace** | malloc/free 追踪 | 1.1x | 泄漏定位 |

### 工业级建议

- **CI 流程**：所有测试在 ASan + UBSan 下运行
- **性能测试**：valgrind massif 分析内存增长
- **线上**：jemalloc 的 `opt.prof` 栈采样，定位泄漏
- **HFT**：热路径零 malloc，所有内存预分配，从设计上消除上述故障

## HFT 关联

- **DPDK mempool**：固定块大小，无越界；alloc/free 配对，无泄漏
- **零 malloc 原则**：热路径不调 malloc，从根源避免四大故障
- **ASan CI**：DPDK 单元测试在 ASan 下运行
- **线上监控**：RSS 监控、`/proc/<pid>/status` 的 VmRSS
- **CVE 教训**：Heartbleed 是堆越界读，Morris 蠕虫是栈溢出——HFT 网关面向互联网，安全至关重要

### 实操：ASan 检测

```bash
gcc -O0 -g -fsanitize=address,undefined -fno-omit-frame-pointer prog.c -o prog_asan
./prog_asan
# ASan 报告包含：
# - 错误类型（heap-buffer-overflow / use-after-free / double-free）
# - 出错栈
# - 分配/释放栈（若是 UAF）
# - 影子内存映射
```

### 实操：valgrind 检测

```bash
valgrind --leak-check=full --show-leak-kinds=all ./prog
# 报告：
# - definitely lost / indirectly lost / possibly lost
# - invalid read/write
# - uninitialized value
```

### 实操：双重 free

```c
int *p = malloc(sizeof(int));
free(p);
free(p);   /* glibc: double free or corruption (fasttop) → SIGABRT */
```

### 实操：堆越界延迟崩溃

```c
int *a = malloc(10 * sizeof(int));
a[10] = 42;   /* 越界，写元数据 */
free(a);      /* 可能立即崩溃：corrupted size vs. prev_size */

int *b = malloc(10 * sizeof(int));
free(b);
int *c = malloc(10 * sizeof(int));
/* c 可能等于 b，因为 b 刚释放 */
/* 现在访问 b 是 UAF，可能读到 c 的数据 */
```
