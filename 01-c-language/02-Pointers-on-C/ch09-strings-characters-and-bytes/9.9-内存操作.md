# 9.9 内存操作

## 本节讲什么

**`<string.h>`** 中的 **`mem*`** 系列是 HFT/DPDK/内核报文处理的**真正主力**：`memcpy`、`memmove`、`memset`、`memcmp`、`memchr`。它们**显式接受 `size_t n` 长度参数**，**不依赖 `\0`**，因此**完全二进制安全**——0x00 是合法数据字节，扫描由 `n` 决定。这与 `str*` 系列（依赖 `\0`）形成根本对立。

本节剖析各函数机制、重叠处理原理、SIMD 优化、与 `str*` 的对比，以及 HFT 报文解析的标准范式。

## 要点

### 函数清单

| 函数 | 原型 | 作用 | 重叠处理 |
|------|------|------|----------|
| **`memcpy`** | `void *memcpy(void *dst, const void *src, size_t n)` | 拷贝 n 字节 | **不可**重叠 |
| **`memmove`** | `void *memmove(void *dst, const void *src, size_t n)` | 拷贝 n 字节 | **可**重叠 |
| **`memset`** | `void *memset(void *dst, int c, size_t n)` | 填充 n 字节为 c | — |
| **`memcmp`** | `int memcmp(const void *a, const void *b, size_t n)` | 比较 n 字节 | — |
| **`memchr`** | `void *memchr(const void *s, int c, size_t n)` | 前 n 字节中找 c | — |

### 核心特征

1. **显式长度 `n`**：与 `\0` 无关，二进制安全
2. **`void *` 参数**：任意类型指针，按字节操作
3. **`size_t` 长度**：无符号，最大支持 `SIZE_MAX` 字节
4. **无 `\0` 依赖**：0x00 是合法数据字节
5. **HFT 首选**：报文长度由协议字段给出，不靠扫描

### memcpy vs memmove：重叠处理

```c
char buf[10] = "abcdef";
memcpy(buf + 2, buf, 4);     /* UB：重叠 */
memmove(buf + 2, buf, 4);    /* OK：结果 "ababcd" */
```

**重叠 UB 的根因**：

- `memcpy` 假设 `dst` 和 `src` 不重叠，可按任意顺序拷贝（前向/后向/SIMD 块）
- 若重叠，部分字节在拷贝前被覆盖，结果不可预测
- glibc `memcpy` 用 SIMD 块拷贝，重叠时**前向拷贝**会导致源数据被破坏

**memmove 的正确实现**：

```c
void *memmove(void *dst, const void *src, size_t n) {
    uint8_t *d = dst;
    const uint8_t *s = src;
    if (d < s) {
        /* dst 在 src 前，前向拷贝 */
        while (n--) *d++ = *s++;
    } else {
        /* dst 在 src 后，后向拷贝（避免覆盖未读字节） */
        d += n; s += n;
        while (n--) *--d = *--s;
    }
    return dst;
}
```

**汇编视角**：memmove 先比较 `dst` 和 `src` 地址，选择前向或后向拷贝方向。`memcpy` 无此检测，直接前向，故快约 5-10%。

**工程铁律**：

- **不确定是否重叠时用 `memmove`**
- 性能敏感且确认不重叠时用 `memcpy`（或 `rte_memcpy`）
- 编译器在 `-O2` 下对小区间 `memcpy` 常展开为寄存器移动

### memset：填充

```c
memset(buf, 0, sizeof(buf));          /* 清零 */
memset(buf, 0xFF, sizeof(buf));       /* 填 0xFF */
memset(&struct_val, 0, sizeof(struct_val));  /* struct 清零 */
```

- `c` 被转为 `unsigned char`，填充 `n` 字节为该字节值
- **不能**用来设置 int 数组为非零值（`memset(arr, 1, ...)` 让每个 int 变成 `0x01010101`，不是 1）
- struct 清零推荐 `= {0}` 初始化（编译期）或 `memset`（运行时）

### memcmp：二进制比较

```c
uint8_t magic[4] = { 'F', 'I', 'X', 0x01 };
if (memcmp(pkt, magic, 4) == 0) { /* 是 FIX 报文 */ }
```

- 按字节 `unsigned char` 比较
- 返回 `<0/0/>0`，符号有意义
- **不保证常量时间**（glibc 短路返回）——认证场景需手写
- 性能：`memcmp(pkt, magic, 4)` 在 `-O2` 下常编译为 4 字节整数比较，1-2 周期

### memchr：二进制查找

```c
const uint8_t *p = memchr(pkt, 0x01, pkt_len);   /* FIX SOH 分隔符 */
```

- 在前 `n` 字节中查找字节 `c`
- 返回位置指针或 NULL
- **与 `strchr` 对立**：`memchr` 不受 0x00 影响，`strchr` 在 0x00 停
- glibc 用 SIMD，约 1-2 ns/16 字节

### 指针遍历报文的标准范式

```c
uint8_t *p = payload;
uint8_t *end = p + pkt_len;
for (; p < end; p++) {
    parse_byte(*p);
}
```

- **`end` 是上界指针**，不是 `\0`
- 即使中间出现 0x00 仍继续
- `p < end` 是无符号比较，安全（`size_t` 无负值）

### 大小端铺垫

```c
uint32_t net = 0x12345678;   /* 网络序（大端） */
uint8_t b0 = (net >> 24) & 0xFF;   /* 0x12 */
uint8_t b1 = (net >> 16) & 0xFF;   /* 0x34 */
uint8_t b2 = (net >> 8) & 0xFF;    /* 0x56 */
uint8_t b3 = net & 0xFF;           /* 0x78 */
```

- 网络字节序是**大端**（高位在前）
- x86-64 是**小端**（低位在前）
- 转换：`htonl/ntohl`（32 位）、`htons/ntohs`（16 位）
- **禁用** union 或指针强转做大小端转换——不可移植，且违反严格别名
- 推荐用移位（如上），编译器优化为单条 `bswap` 指令

### 工程准则

| 数据类型 | API | 理由 |
|----------|-----|------|
| 文本（有 `\0`） | `str*` / `snprintf` | 语义清晰 |
| 二进制（含 0x00） | **`mem*` + len** | 二进制安全 |
| 协议头 | `memcmp` / `memcpy` | 定长，编译期已知 |
| struct 清零 | `memset` 或 `= {0}` | 通用 |
| 不确定重叠 | `memmove` | 安全 |
| 确认不重叠 | `memcpy` / `rte_memcpy` | 快 |

## HFT 关联

### DPDK rte_memcpy

```c
#include <rte_memcpy.h>
rte_memcpy(dst, src, n);   /* 优化版 memcpy */
```

- 按对齐和长度选择 SSE/AVX 路径
- 4-64 字节范围比 glibc `memcpy` 快 1.5-3 倍
- **仍要求不重叠**（与 `memcpy` 一致）
- HFT 报文拷贝主力

### 报文拷贝标准操作

```c
uint8_t pkt_raw[1024];
size_t pkt_len = rte_pktmbuf_data_len(mbuf);
memcpy(pkt_raw, rte_pktmbuf_mtod(mbuf, void *), pkt_len);
/* 或 rte_memcpy 更快 */
```

### 报文头部提取

```c
struct eth_hdr {
    uint8_t dst[6], src[6];
    uint16_t type;
} __attribute__((packed));

struct eth_hdr eth;
memcpy(&eth, pkt, sizeof(eth));   /* 对齐安全拷贝 */
uint16_t eth_type = ntohs(eth.type);
```

**为什么用 `memcpy` 而非直接强转**：

```c
struct eth_hdr *bad = (struct eth_hdr *)pkt;   /* UB：未对齐访问 */
```

x86-64 允许未对齐访问但有性能惩罚，ARM/MIPS 上是 **SIGBUS**。`memcpy` 是**唯一可移植**的对齐安全结构体读取方式，编译器优化为单条 `mov` 或 `movups`。

### 协议头分派

```c
if (pkt_len < 14) return;
uint16_t eth_type;
memcpy(&eth_type, pkt + 12, 2);
eth_type = ntohs(eth_type);

if (eth_type == 0x0800) {
    /* IPv4 */
} else if (eth_type == 0x86DD) {
    /* IPv6 */
} else if (eth_type == 0x8100) {
    /* 802.1Q VLAN */
}
```

### FIX 报文分词

```c
uint8_t *p = pkt, *end = pkt + pkt_len;
while (p < end) {
    uint8_t *sep = memchr(p, 0x01, end - p);   /* SOH 分隔 */
    size_t field_len = sep ? (size_t)(sep - p) : (size_t)(end - p);
    process_field(p, field_len);
    if (!sep) break;
    p = sep + 1;
}
```

**保留空字段**（与 `strtok` 不同），二进制安全。

### 性能特征

| 函数 | 64 字节 | 1 KB | 备注 |
|------|---------|------|------|
| `memcpy` | ~5 ns | ~30 ns | SSE2，glibc |
| `rte_memcpy` | ~3 ns | ~20 ns | AVX2，DPDK 优化 |
| `memmove` | ~6 ns | ~32 ns | 多一次方向检测 |
| `memset` | ~4 ns | ~25 ns | SSE2 |
| `memcmp` | ~3 ns | ~20 ns | 短路返回 |

在 100ns 级 HFT 路径上，4 字节 `memcmp` 编译为整数比较约 1 周期，可忽略；1KB `memcpy` 约 20-30ns 需评估是否必要。

### 实操：memcpy 重叠 UB

```c
char buf[10] = "abcdef";
memcpy(buf + 2, buf, 4);
/* UB：glibc 前向拷贝，buf 可能变成 "abababef" 而非期望的 "ababcdef" */

memmove(buf + 2, buf, 4);   /* OK：后向拷贝，结果 "ababcd" */
```

ASan 检测：

```
ERROR: AddressSanitizer: memcpy-param-overlap
```

### 实操：memset 不能设 int 数组

```c
int arr[10];
memset(arr, 1, sizeof(arr));
/* 每个 int 变成 0x01010101 = 16843009，不是 1 */
```

修复：

```c
for (int i = 0; i < 10; i++) arr[i] = 1;
```

### 实操：结构体对齐安全读取

```c
/* 反例：未对齐强转 */
uint16_t type = *(uint16_t *)(pkt + 12);   /* UB：未对齐 */

/* 正例：memcpy 让编译器处理对齐 */
uint16_t type;
memcpy(&type, pkt + 12, 2);
type = ntohs(type);
```

`-O2` 下 `memcpy(&type, pkt+12, 2)` 编译为单条 `movzx` 或 `movups`，零开销。
