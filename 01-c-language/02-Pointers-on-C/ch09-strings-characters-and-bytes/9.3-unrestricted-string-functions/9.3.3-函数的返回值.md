# 9.3.3 函数的返回值

## 本节讲什么

`<string.h>` 各函数的**返回值语义**并不统一：写函数（`strcpy`/`strcat`/`memcpy`）多返回 **`dst`**（第一参数的副本），便于链式写法；查找函数（`strchr`/`strstr`）返回**位置指针**或 **NULL**；比较函数（`strcmp`/`memcmp`）返回 **int**。理解这些语义是正确使用 API、避免 NULL 解引用 UB 的前提。

## 要点

### 返回值语义总表

| 函数 | 返回值 | 含义 | 可能为 NULL？ |
|------|--------|------|---------------|
| **`strcpy(dst, src)`** | `dst` | 第一参数副本 | 否（除非 dst 本身为 NULL，UB） |
| **`strcat(dst, src)`** | `dst` | 第一参数副本 | 否（同上） |
| **`strncpy(dst, src, n)`** | `dst` | 第一参数副本 | 否 |
| **`strncat(dst, src, n)`** | `dst` | 第一参数副本 | 否 |
| **`strlen(s)`** | `size_t` | 长度 | — |
| **`strcmp(s1, s2)`** | `<0/0/>0` | 字典序差 | — |
| **`strncmp(...)`** | `<0/0/>0` | 限长字典序差 | — |
| **`strchr(s, c)`** | 指针或 NULL | 找到则位置，否则 NULL | **是** |
| **`strrchr(s, c)`** | 指针或 NULL | 反向查找 | **是** |
| **`strstr(s, sub)`** | 指针或 NULL | 子串位置 | **是** |
| **`strpbrk(s, set)`** | 指针或 NULL | 字符集中任一字符位置 | **是** |
| **`memcpy(dst, src, n)`** | `dst` | 第一参数副本 | 否 |
| **`memmove(dst, src, n)`** | `dst` | 第一参数副本 | 否 |
| **`memset(dst, c, n)`** | `dst` | 第一参数副本 | 否 |
| **`memcmp(a, b, n)`** | `<0/0/>0` | 字节序差 | — |
| **`memchr(s, c, n)`** | 指针或 NULL | 在前 n 字节中查找 | **是** |

### 返回 dst 的设计意图：链式写法

```c
char buf[64];
size_t n = strlen(strcat(strcpy(buf, "ts="), "12345"));
/* 等价于：
 *   strcpy(buf, "ts=");
 *   strcat(buf, "12345");
 *   n = strlen(buf);
 */
```

这种链式风格源自 1970s UNIX 早期 C 代码，**当时看起来优雅**，但现代工程实践**不推荐**：

- 可读性差，调试断点难放
- 一旦中间步骤出错（如 `strcat` 溢出），后续操作放大错误
- 编译器优化后链式与分步无性能差异

**推荐范式**：分步写，每步结果可检查。

### 查找函数的 NULL 陷阱

```c
char *p = strchr(line, '=');
*p = '\0';   /* 若 line 无 '='，p == NULL，这里 SIGSEGV */
```

**铁律**：查找函数返回值**必须先判 NULL**再解引用：

```c
char *p = strchr(line, '=');
if (p) {
    *p = '\0';
    value = p + 1;
} else {
    /* 无等号，处理错误或跳过 */
}
```

### strcmp 返回值的细节

```c
int r = strcmp("abc", "abd");
/* r < 0，但具体值不保证是 -1 */
```

- 返回值的**符号**有意义（`<0/0/>0`），**数值大小不保证**
- glibc 实现返回 `(*s1 - *s2)` 的差，但其他实现可能只返回 `-1/0/1`
- **不要**写 `if (strcmp(a, b) == -1)`，应写 `if (strcmp(a, b) < 0)`
- C23 新增 `strcasecmp`/`strncasecmp` 标准化（原 POSIX 扩展）

### errno 与 strerror 的返回值

```c
char *msg = strerror(errno);   /* 返回静态存储指针 */
```

- 返回的指针指向**静态缓冲区**，下次调用覆盖
- 多线程下**非线程安全**，应改用 `strerror_r`（POSIX）或 `strerror_s`（C11 Annex K）
- 见 **9.7** 详述

### strtol/strtod 的指针返回值

```c
char *end;
long v = strtol(s, &end, 10);
if (*end != '\0') /* 有非数字字符 */;
```

- `end` 指向第一个未转换字符，可用于格式校验
- 这是"输出参数 + 返回值"的混合范式，比纯返回值信息量大

## HFT 关联

- **DPDK `rte_strscpy`/`rte_strlcpy`**：返回值与 `strlcpy` 一致，便于检测截断
- **协议字段查找**：`memchr(pkt, 0x01, pkt_len)` 查找 FIX SOH 分隔符，**必须**判 NULL
- **日志格式化**：`vsnprintf` 返回**需要的总长度**（不含 `\0`），即使截断也返回完整长度，便于调用方分配足够缓冲
- **错误处理**：`rte_errno` + `rte_strerror` 模式与 POSIX 一致，同样需注意线程安全
- **性能**：返回 `dst` 的设计让链式写法省一次变量，但现代编译器 SSA 分析后无差异

### snprintf 返回值的微妙之处

```c
int r = snprintf(buf, sizeof(buf), "%s", long_str);
if (r < 0) { /* 错误 */ }
else if ((size_t)r >= sizeof(buf)) { /* 截断，需要 r+1 字节 */ }
else { /* 完整，写了 r 字节（不含 \0） */ }
```

- 返回值是**需要的总长度**（不含 `\0`），**不是**实际写入长度
- 这让调用方能判断是否截断并分配更大缓冲
- 是 C 标准库**少有的**能检测截断的 API
