# 9.3.2 连接字符串

## 本节讲什么

**`strcat(dst, src)`** 在 `dst` 末尾的 `\0` 处追加 `src`（含新 `\0`）。它本质是"先 `strlen(dst)` 再 `strcpy`"，**继承 strcpy 的所有溢出风险**，且**多一次扫描**。本节剖析其机制、性能陷阱与安全替代。

## 要点

### 函数原型与行为

```c
char *strcat(char *dst, const char *src);
```

- 找到 `dst` 中第一个 `\0`，从该位置开始拷贝 `src`（含 `\0`）
- 返回 `dst`
- **不检查 dst 容量**——若 `strlen(dst) + strlen(src) + 1 > sizeof(dst)`，溢出 UB
- `dst` 必须已 `\0` 终止，否则 `strcat` 越界找末尾——UB on UB

### 简化实现

```c
char *strcat(char *dst, const char *src) {
    char *p = dst;
    while (*p) p++;           /* 扫到 dst 末尾 \0 */
    while ((*p++ = *src++))   /* 从 \0 位置开始拷 src */
        ;
    return dst;
}
```

**两次扫描**：先扫 `dst` 找末尾，再扫 `src` 拷贝。复杂度 O(strlen(dst) + strlen(src))。

### 性能陷阱：链式 strcat 是 O(n²)

```c
/* 反例：每次 strcat 都重新扫描整个已构建字符串 */
char buf[1024] = "";
for (int i = 0; i < argc; i++) {
    strcat(buf, argv[i]);      /* 第 i 次扫描 strlen(buf) 次 */
    strcat(buf, " ");
}
/* 总扫描次数 ≈ Σstrlen(buf_i) ≈ O(n²) */
```

**正确范式**：维护一个 offset 指针，O(n) 完成：

```c
char buf[1024];
char *p = buf;
char *end = buf + sizeof(buf);
for (int i = 0; i < argc && p < end; i++) {
    int n = snprintf(p, end - p, "%s ", argv[i]);
    if (n < 0) break;
    p += (n < end - p) ? n : (end - p - 1);  /* 截断保护 */
}
```

### 替代方案对比

```c
/* 1. strncat：限长但仍需保证 dst 容量，且 n 是 src 最多追加字符数 */
strncat(dst, src, sizeof(dst) - strlen(dst) - 1);
/* 注意：strncat 自己补 \0，n 不含 \0 */

/* 2. snprintf + offset：安全，推荐 */
size_t off = strlen(dst);
snprintf(dst + off, sizeof(dst) - off, "%s", piece);

/* 3. strlcat：BSD，返回尝试的总长度，便于检测截断 */
strlcat(dst, src, sizeof(dst));

/* 4. memcpy + offset：二进制，HFT 首选 */
size_t off = /* 已知 */;
memcpy(dst + off, src, piece_len);
off += piece_len;
```

### strncat 的微妙之处

```c
char d[8] = "abc";
strncat(d, "defghij", 3);
/* d = "abcdef\0?" —— 追加最多 3 字符，再补 \0，共写 4 字节 */
```

- `n` 是**最多从 src 取的字符数**，**不含 `\0`**
- `strncat` **总是**在结果末尾补 `\0`
- 所需 dst 容量 = `strlen(dst) + min(strlen(src), n) + 1`
- 与 `strncpy` 不补 `\0` 形成对比——同族函数行为不一致，是 C 标准库的著名坑

### 重叠 UB

```c
char s[10] = "abc";
strcat(s, s);   /* UB：src 与 dst 重叠 */
```

需要重叠操作时用 `memmove`（9.9）。

## HFT 关联

- **日志拼接**：DPDK `rte_log` 内部用 `vsnprintf`，**不用** `strcat`——格式化一次完成
- **报文组装**：构建 FIX 报文时用 `memcpy` + offset 累加，每段长度已知
- **配置字符串拼接**：`snprintf` 链式写入是标准范式
- **性能**：在 100ns 级热路径上**任何** `strcat` 都是性能 bug——多一次 `strlen` 扫描就是 5-30ns
- **SBE 编码**：长度编译期已知，直接 `memcpy` 到偏移位置，零扫描

### 实操：strcat 链 vs snprintf 链

```c
/* 反例：1000 次 strcat，每次扫描越来越长 */
char buf[8192] = "";
for (int i = 0; i < 1000; i++)
    strcat(buf, "x");      /* 总扫描 O(1+2+...+1000) = O(500500) */

/* 正例：维护 offset */
char buf[8192];
size_t off = 0;
for (int i = 0; i < 1000 && off < sizeof(buf) - 1; i++)
    buf[off++] = 'x';
buf[off] = '\0';           /* 总写入 O(1000) */
```

实测在 1KB 字符串上，前者比后者慢 **500 倍**。
