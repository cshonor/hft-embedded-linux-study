# 7.6 可变参数列表

## 本节讲什么

**`...` 可变参数**函数：`printf`、`rte_log`、`printk` 等的基础。可变参是 C 的"灵活陷阱"——能写通用接口，但类型不检查、靠格式串或 count 约定。这一节是总览：语法与最小示例、四个 stdarg 宏、与"原型"概念的衔接，以及 **C23 对 `void f(...)` 的解禁**；实现细节在 7.6.1（stdarg 宏），限制在 7.6.2。

## 要点

- 至少一个**固定参数**（常为 `format` 或 `count`），作为 `va_start` 的锚点
- 编译器**不检查**可变部分类型 → 传错 → **UB**
- 底层优先**固定签名** API；日志/格式化场景再用可变参

### 典型签名

```c
int printf(const char *format, ...);              /* C 标准库 */
void rte_log(uint32_t level, const char *format, ...); /* DPDK 日志 */
void err(int status, const char *format, ...);    /* 自定义错误 */
```

### 语法规则

```c
#include <stdarg.h>

void foo(int last, ...);   /* last 是固定参数，... 代表可变数量参数 */
```

- `...` **必须放在参数列表最后**
- `...` **前面至少要有 1 个固定参数**（C17 及以前的硬性要求——**C23 有变化，见下**）
- `...` 前后可有逗号可无：`foo(int a, ...)` ≡ `foo(int a, ...)`
- 标准库最典型的例子：`int printf(const char *fmt, ...);`

### 最小可运行示例

```c
#include <stdio.h>
#include <stdarg.h>

void sum(int count, ...)
{
    va_list ap;
    va_start(ap, count);            /* 从最后一个固定参数 count 启动 */

    for (int i = 0; i < count; i++) {
        int val = va_arg(ap, int);  /* 取出下一个 int 参数 */
        printf("%d ", val);
    }
    va_end(ap);                     /* 清理 */
}

int main(void)
{
    sum(3, 10, 20, 30);   /* 输出: 10 20 30 */
    return 0;
}
```

四个核心宏（**7.6.1** 详）：

| 宏 | 作用 |
|----|------|
| `va_list ap` | 可变参数的迭代变量（不透明类型） |
| `va_start(ap, 固定参数名)` | 初始化，**必须传紧邻 `...` 前面的那个固定参数** |
| `va_arg(ap, 类型)` | 取下一个参数，**要显式指定类型** |
| `va_end(ap)` | 结束清理，必须与 `va_start` 配对 |

### 与"原型"的关联（→ **7.2.1**）

```c
void sum(int count, ...);   /* ✅ 这是完整原型——编译器知道后面是可变参数 */
void sum();                 /* ❌ 这不是可变参数，是"参数信息完全未知"的旧式声明 */
```

两码事，别混为一谈。`void sum();` 只是说"返回 void，参数未知"，它既不是原型也不声明可变参。

**带 `...` 的原型检查范围是不对称的**（gcc 13 实测 `-Wall -Wextra`）：

```c
void sum(int count, ...);
sum("not-an-int", 1, 2);   /* 固定参数类型错 → warning: passing argument 1 of 'sum'
                              makes integer from pointer without a cast */
sum(2, 3.14, 9.9);         /* 可变部分传 double → 零警告（不检查） */
```

**固定参数照常检查，可变部分完全不检查**——这是 `...` 型原型的真实语义，不是"整个函数都不检查"。

### C 没有重载，所以靠 `...` 处理参数数量变化

C++ 可以写多个同名不同参的重载；C 里函数名全局唯一（**7.2**），要接受"参数数量不定"只能用 `...`。代价就是**放弃编译期类型检查**——这是语言层面的取舍，不是用法问题。

### 为什么需要至少一个固定参数

`va_start(ap, last)` 需要 `last` 作为"最后一个固定参数"来定位可变参在栈/寄存器里的起始位置（**7.6.1**）。没有固定参数就找不到起点——所以 `...` 不能是唯一的参数。

> #### ⚠️ 但 C23 改了这条：可以不要固定参数了
>
> **C23（N2975 "Relax requirements for `va_start`"）允许 `void f(...)` 这种完全无固定参数的写法**，配套 `va_start(ap, ...)` 的新形式：
>
> ```c
> void sum_all(...)                 /* C23 起合法：没有任何固定参数 */
> {
>     va_list ap;
>     va_start(ap, ...);            /* C23 新形式：第二个参数直接写 ... */
>     for (int i = 0; i < 3; i++)
>         printf("%d ", va_arg(ap, int));
>     va_end(ap);
> }
> ```
>
> gcc 13.3 `-pedantic-errors` 逐标准实测：
>
> | 写法 | C99 | C11 | C17 | C2X (C23) |
> |------|-----|-----|-----|-----------|
> | `void f(...);` 仅声明 | ❌ | ❌ | ❌ | ✅ |
> | `void f(...) {}` + `va_start(ap, ...)` | ❌ | ❌ | ❌ | ✅ 且正确运行 |
> | `void sum(int count, ...)` 传统写法 | ✅ | ✅ | ✅ | ✅ 行为不变 |
>
> 拒绝信息本身就是证据：`error: ISO C requires a named argument before '...' **before C2X**`——
> 措辞里的 "before C2X" 说明 C2X 起这条约束被撤掉了。
>
> 注意 gcc/clang 在**不加 `-pedantic`** 时默认把它当扩展静默接受（`-Wall -Wextra` 也零警告），
> 所以"我的 C11 项目里 `void f(...)` 也能编过"不代表它合法——加上 `-pedantic-errors` 就现形。
>
> **C23 没改的**：默认参数提升、`va_arg` 无类型检查、必须 `va_end` 配对——这些老规则全部保留。
> 所以"至少一个固定参数"在 C17 及以前是硬性要求，在 C23 只是**可选项**；写可移植代码仍应保留固定参数。

### count 说谎：可变参最典型的运行期 UB

`va_arg` 不会告诉你"还有没有下一个"。`count` 写大了就往栈/寄存器残留区继续读：

```c
sum(3, 10, 20);   /* count 说 3 个，实际只传 2 个 */
```

实测三次运行（`-O0`）：

```
10 20 -619250256
10 20 1228213680
10 20 1531653552
```

第三次读的是上一个函数留下的寄存器残留——**每次都不一样，退出码 0，零警告**。
这也是为什么可变参的"个数约定"必须由调用方严格履行：格式串（printf）、NULL 哨兵（execl）、显式 count，本质都是同一个问题的不同解法。

### 内核 printk

```c
/* Linux 内核 —— printk 本身就是可变参函数 */
asmlinkage int printk(const char *fmt, ...);
/* 驱动里的典型包装 */
#define dev_err(dev, fmt, ...) ...
```

内核大量使用 `<stdarg.h>`，`printk` 族、`dev_err/dev_info`、seq_file 的 `seq_printf` 全是变参接口。内核的规则是：**热路径（数据面/中断上半部）不用变参**，因为它类型不安全、格式串解析有开销。

### 可变参 vs 数组传参

```c
/* 可变参：类型异质，不检查 */
void logf(const char *fmt, ...);          /* %d 给 int，%f 给 double */

/* 数组传参：类型同质，有 count，安全 */
void log_n(int n, const struct evt *evs); /* 每个元素都是 evt */
```

可变参适合"异质类型 + 格式化"；同质批量用数组 + count 更安全。

## 底层映射

### 寄存器 + 栈混合传递

x86-64 ABI：固定参数和可变参前 6 个走寄存器（`rdi..r9`），超出进栈。`va_list` 实现是"寄存器保存区 + 栈溢出区"的抽象——`va_arg` 按类型从对应位置取。

```
调用 logf("level=%d price=%f", 3, 9.9):
  rdi = "level=%d price=%f"   (固定参数 fmt)
  rsi = 3                      (可变参 1, int)
  xmm0 = 9.9                   (可变参 2, double)
  栈上可能还有保存区
```

`va_arg(ap, int)` 从 `rsi` 区取，`va_arg(ap, double)` 从 `xmm` 区取。类型错了就读错位置 → 垃圾或崩。

### 默认参数提升（**7.6.2** 详）

可变参里 `float` → `double`，`char/short` → `int`。所以 `va_arg(ap, float)` 是**错的**，要 `va_arg(ap, double)`。固定参数**不**做这个提升。

## HFT / DPDK

| 用法 | 例子 |
|------|------|
| 日志 | `RTE_LOG(INFO, "pkt=%p\n", pkt);` |
| 格式化 | `snprintf(buf, n, "%s:%d", host, port);` |
| 调试打印 | `debug_dump("hdr=%p len=%zu", hdr, len);` |
| 错误 | `errx(1, "bad magic: 0x%x", magic);` |

### 工程纪律

- **数据面核心路径禁用可变参**：类型不安全、格式串解析开销、分支不可预测
- 日志（非热路径）可用，配 `__attribute__((format))` 让编译器检查（**7.6.2**）
- 批量数据用数组 + count，不用 `...`

## 常见误区

| 误区 | 事实 |
|------|------|
| "`...` 能传任意类型" | 能传，但取回时类型必须对，否则 UB |
| "可变参比数组灵活更好" | 灵活但不安全，热路径禁用 |
| "`f(...)` 能不要固定参数" | 不能，至少一个固定参数作锚点 |
| "可变参类型编译器会检查" | 不会，靠 format 串或人工约定 |
| "带 `...` 的原型整个函数都不检查" | 不对称——固定参数照常检查，只有可变部分不检查 |
| "`void sum();` 也是可变参数" | 不是——旧式未指定参数，连原型都不是（→ **7.2.1**） |
| "`void f(...)` 在所有 C 标准里都非法" | C23（N2975）起合法；C17 及以前非法，但 gcc/clang 不加 -pedantic 会静默接受 |
| "C23 改了可变参数规则" | 只改了"必须有固定参数"这一条；提升/无类型检查/va_end 配对都没变 |
| "count 写错了会崩" | 往往不崩，读寄存器残留得到垃圾值，退出码仍是 0 |

## 实操

```bash
# 看 printf 的可变参实现
gcc -O2 -S t.c -o - | grep -A20 'logf'
# __attribute__((format)) 让编译器检查格式串（7.6.2）
gcc -Wformat -Wformat-security t.c
# 故意传错类型看 UB
cat > t.c << 'EOF'
#include <stdio.h>
int main(void) { printf("%d\n", 3.14); return 0; }  /* 给 double 取 int */
EOF
gcc -Wformat t.c -o t && ./t        # 告警 + 运行时垃圾值
```

## 代码自测

**题目 1：** 以下可变参数函数有什么问题？
```c
int sum_all(int first, ...) {
    va_list args;
    va_start(args, first);
    int total = first;
    while (1) {
        int val = va_arg(args, int);
        if (val == 0) break;
        total += val;
    }
    va_end(args);
    return total;
}
```

<details>
<summary>参考答案</summary>

使用 0 作为结束标记——如果调用方忘记传 0，函数会越界读取内存。这是可变参数函数的常见陷阱：编译器无法检查参数数量。更安全的方法：(1) 像 printf 那样用格式串指定参数数量；(2) 像 execl 那样用 NULL 结尾（但仍有忘记的风险）；(3) 显式传参数个数。

</details>

**题目 2：** 逐项判定下列声明是否合法（按 C17 与 C23 分别回答），并说明哪些是原型：
```c
void a(int n, ...);     // 行 1
void b(...);            // 行 2
void c();               // 行 3
void d(void);           // 行 4
int  e(const char *fmt, ...);  // 行 5
```

<details>
<summary>参考答案</summary>

| 行 | C17 | C23 | 是原型？ |
|----|-----|-----|----------|
| 1 `void a(int n, ...)` | ✅ | ✅ | ✅ 是（带 `...` 的原型） |
| 2 `void b(...)` | ❌ ISO C requires a named argument before '...' | ✅ C23 起合法 | ✅ 是 |
| 3 `void c()` | ✅ 但危险 | ⚠️ C23 起语义 = `c(void)` | ❌ 不是（旧式未指定参数） |
| 4 `void d(void)` | ✅ | ✅ | ✅ 是 |
| 5 `int e(const char *, ...)` | ✅ | ✅ | ✅ 是（printf 就是这个形状） |

要点：
- 行 2 在 C17 下是约束违反，但 gcc/clang **不加 `-pedantic` 会静默接受**（当扩展），
  `-Wall -Wextra` 也不报——只有 `-pedantic-errors` 才让它现形。
- 行 3 与行 4 的差别就是 **7.2.2** 的主题：`()` 是"不检查"，`(void)` 是"不要参数"。
  行 3 不是原型，所以调用 `c(1,2,3)` 不检查；C23 起它等价于 `c(void)`。
- 行 2 在 C23 下可以配 `va_start(ap, ...)` 使用（N2975），但可移植代码仍应保留固定参数。

</details>
