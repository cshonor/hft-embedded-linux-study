# 7.3 函数的参数

## 本节讲什么

C **只有值传递**：形参是实参的**副本**。要改外部内存，传**指针的副本**，通过解引用间接改。这一节把传参模式、ABI 寄存器传参、大 struct 的开销、改指针本身的需求讲透——它是 HFT 接口设计的地基。

> **专篇（表 + 思考题）：** [7.3.1 值拷贝无例外](./7.3.1-值拷贝无例外.md) —— int / 指针 / struct / 数组退化 / 二级指针一表记清。

## 要点

```c
void set_val(int x)   { x = 100; }      /* 改副本，外部不变 */
void set_ptr(int *x)  { *x = 100; }     /* 改外部：通过指针副本解引用 */
```

| 实参 | 拷贝内容 | 改外部？ | 开销 |
|------|----------|----------|------|
| `int` / 小标量 | 整数值 | 否 | 寄存器，近零 |
| `int *` / 指针 | 地址值 | 是（通过 `*`） | 寄存器，近零 |
| `const T *` | 地址值 | 只读不改 | 寄存器 |
| 大 `struct` 值 | 整块结构 | 否 | 拷贝 N 字节，昂贵 |
| `struct` 指针 | 地址值 | 是 | 寄存器 |

### 工程选型（DPDK/HFT）

- **大结构体 / mbuf**：传**指针**（`const` 若只读）
- **小标量**：传值（寄存器，零开销，且不改外部是好事）
- **输出多个结果**：指针参数或 struct 指针
- **改调用者指针**：`T **`（**ch06 6.10**）

```c
/* 典型 HFT 接口：只读输入 + 可写输出 + 错误码返回 */
int decode(const uint8_t *pkt, size_t len, struct quote *out);
```

### 改指针本身

```c
int alloc_buf(char **out, size_t n) {
    char *p = malloc(n);
    if (!p) return -1;
    *out = p;          /* 改调用者的指针 */
    return 0;
}

char *buf = NULL;
alloc_buf(&buf, 1024);   /* 传 &buf，二级指针 */
```

C 值传递意味着 `char *out` 形参是 `buf` 的副本，改 `out` 不影响 `buf`——必须传 `&buf`（`char**`），改 `*out` 才写到 `buf`（**ch06 6.10**）。

## 底层映射

### ABI 寄存器传参（x86-64 System V）

| 参数序号 | 整数/指针 | 浮点 |
|---------|----------|------|
| 1 | `rdi` | `xmm0` |
| 2 | `rsi` | `xmm1` |
| 3 | `rdx` | `xmm2` |
| 4 | `rcx` | `xmm3` |
| 5 | `r8` | `xmm4` |
| 6 | `r9` | `xmm5` |
| 7+ | 栈 | 栈 |

```c
int f(int a, int b, struct mbuf *m) { return a + b + m->len; }
```

```
; x86-64 -O2
f:
    mov     eax, edi             ; a 在 rdi
    add     eax, esi             ; b 在 rsi
    add     eax, DWORD PTR [rdx] ; m 在 rdx，取 m->len
    ret
```

三个参数全走寄存器，零内存拷贝——这是小标量和指针传值几乎零开销的根因。

### 大 struct 按值 vs 按指针

```c
struct big { char data[1024]; };
void f_val(struct big b)            { /* 拷贝 1024 字节到栈 */ }
void f_ptr(const struct big *p)     { /* 一条 mov，8 字节指针 */ }
```

```bash
$ gcc -O2 -S t.c -o -
# f_val: 一串 rep movsb 或多次 mov，拷贝 1024 字节
# f_ptr: mov rdi, ... 一条指令
```

struct 太大时（如 > 16 字节），ABI 改用"调用者分配空间 + 隐式首参数传指针"（**ch10** 详）——但仍比显式传指针多一次拷贝。HFT 报文常上百字节，几乎全用指针。

## HFT / DPDK

| 模式 | 例子 |
|------|------|
| 只读报文 + 输出解析 | `int parse(const uint8_t *, size_t, struct quote *);` |
| 批量接口 | `rte_eth_rx_burst(port, q, pkts, BURST)` |
| 改句柄 | `int ctx_init(struct ctx **out)` |
| 回调注册 | `void reg_handler(handler_t cb)` |

### 函数指针铺垫

```c
typedef int (*handler_t)(struct pkt *);
handler_t h = process_order;   /* 函数名退化为地址 */
h(pkt);                        /* 通过指针调用 */
```

**ch13** 详：回调、报文分发器、中断处理的基础。

## 常见误区

| 误区 | 事实 |
|------|------|
| "传指针一定比传值快" | `int` 传值更快——少一次解引用 |
| "`int a[]` 参数是数组" | 退化为 `int *`，sizeof 是指针大小 |
| "传大 struct 按值和按指针一样" | 按值要拷贝整块，昂贵 |
| "改调用者指针用 `T*` 就行" | 必须用 `T**`，传 `&调用者指针` |
| "函数参数 const 是装饰" | 是契约，编译期拦误改 |
