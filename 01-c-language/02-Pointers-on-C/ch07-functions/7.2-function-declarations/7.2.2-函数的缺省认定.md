# 7.2.2 函数的缺省认定

## 本节讲什么

**`f()`** vs **`f(void)`**：旧式 C 的"缺省认定"与现代规范的分水岭。这一节讲清两写的语义差异、K&R 旧式定义的历史包袱、以及为什么现代工程一律用 `(void)`。

## 要点

| 写法 | C 含义 | C++ 含义 |
|------|--------|----------|
| **`f(void)`** | **无参数**；调用 `f(1)` 报错 | 同 C，无参 |
| **`f()`** | 旧式：参数**未指定**（K&R），不检查实参 | **无参**（与 `f(void)` 同） |
| **无原型调用** | C89 隐式返回 `int`，不检查 → C99 起非法 | 非法 |

```c
int f(void);   /* 现代：明确无参 */
int g();       /* 旧式：参数未指定，调用 g(1,2,3) 都不报错（仅告警） */
```

关键：在 C 里 `f()` **不等于** `f(void)`——`f()` 是"不检查参数"，`f(void)` 是"不要参数"。C++ 里两者等价。

### 旧式 K&R 定义（了解即可）

```c
/* K&R 风格：参数名列表 + 类型声明分开 */
int f(a, b)
    int a;
    float b;
{
    return a + (int)b;
}
```

读内核老代码可能遇到；新代码一律用 ANSI 原型：

```c
int f(int a, float b) { return a + (int)b; }
```

### 无原型调用的灾难

```c
/* 忘了 #include <stdlib.h>，调用 malloc */
char *p = malloc(64);   /* 隐式假定返回 int，截断 64 位指针！ */
```

C89：未声明函数 → 隐式假定返回 `int`。`malloc` 实际返回 `void*`（64 位），被当 `int` 截断 → 32 位平台上指针高位丢失 → 崩。C99 起非法，但很多编译器默认仍只告警。

## 底层映射

### 默认参数提升

无原型（或可变参 `...`）调用时，实参做**默认参数提升**：

| 实参类型 | 提升后 |
|---------|--------|
| `char` / `signed char` / `short` | `int` |
| `unsigned char` / `unsigned short` | `int` 或 `unsigned int` |
| `float` | `double` |

```c
void old();            /* 旧式 */
old('a', 3.14f);       /* 实参提升：'a'→int, 3.14f→double */
```

有原型时**不**做默认提升——按形参类型精确转换。这就是原型更安全的原因之一：`f(float)` 收到 `3.14f` 仍是 `float`，无精度损失。

### 寄存器传参的差异

有原型 → 编译器知道精确类型 → SSE 寄存器传 `float`（`xmm0`）；无原型 → 提升 `double` → 走 `xmm0` 但按 8 字节读。`va_arg(ap, float)` 在可变参里**错的**——必须 `va_arg(ap, double)`（**7.6.2**）。

## 工程强制

- 公共 API 一律 `func(void)` 表示无参
- 禁止无原型调用
- CI 开：

```bash
gcc -Wall -Wextra -Werror=strict-prototypes \
    -Werror=implicit-function-declaration \
    -Werror=implicit-int t.c
```

- 读老代码遇到 `f()` K&R 定义，理解为"历史遗留"即可，新代码不写

## HFT / DPDK

| 规范 | 例子 |
|------|------|
| 无参 API 用 `(void)` | `queue_t *queue_create(void);` |
| 禁隐式声明 | `#include <rte_malloc.h>` 不能漏 |
| -Werror=implicit-int | 防 `malloc` 返回值被截断 |
| 跨语言边界 | C++ 调 C 用 `extern "C"`，原型仍 `(void)` |

## 常见误区

| 误区 | 事实 |
|------|------|
| "`f()` 和 `f(void)` 一样" | C 里不同：前者不检查参数，后者禁参数 |
| "忘了 include 没事，能链接" | 隐式 int 假定，64 位指针截断 → 崩 |
| "K&R 定义更灵活" | 是历史包袱，新代码禁用 |
| "C++ 里 `f()` 也表示不检查" | C++ 里 `f()` ≡ `f(void)` |

## 实操

```bash
# 对比 f() vs f(void) 的告警
cat > t.c << 'EOF'
int f();                  /* 旧式 */
int g(void);              /* 现代 */
int main(void) { f(1,2,3); g(1); return 0; }
EOF
gcc -Wall -Wstrict-prototypes t.c -o t   # 看 f 不告警、g 告警
# 强制无隐式声明
gcc -Werror=implicit-function-declaration t.c
# 看 K&R 定义（老内核代码可能遇到）
```

## 代码自测

**题目 1：** 以下代码在 C89 中会发生什么？
```c
int main() {
    int r = compute(3, 4);
    return 0;
}
```
compute 未声明，实际定义为：
```c
double compute(double a, double b) { ... }
```

<details>
<summary>参考答案</summary>

C89 中编译器会隐式假设 compute 返回 int 并接受未知参数。调用时传入的 int 3 和 4 按值压栈，但 compute 期望 double——参数类型不匹配导致读取错误的字节。返回值也按 int 读取但实际是 double——完全错误。这是 C89 隐式声明的经典陷阱。

</details>
