# 7.2.1 原型

## 本节讲什么

**函数原型（prototype）**：返回类型 + 函数名 + **参数类型列表**（参数名可选）。原型是 C89 引入的"编译期类型契约"——有它编译器能校验调用，没它就是 K&R 时代的裸奔。这一节同时厘清**声明 / 原型 / 定义**三者的包含关系：所有原型都是声明，但旧式空括号 `int f();` 是声明而非原型。

## 要点

```c
int parse(const uint8_t *pkt, size_t len, struct quote *out);
void log_err(const char *fmt, ...);   /* 可变参 7.6 */
int f(void);                          /* 无参，f() 不能传参 */
```

- 调用前可见原型 → 类型/个数检查
- 头文件放原型；实现文件 `#include` 自己的 `.h`，让编译器校验声明与定义一致
- `extern` 可省略：`extern int foo(int);` ≡ `int foo(int);`
- 参数名在原型里**可选**，但写出来有文档作用（现代风格保留）

### 声明 / 原型 / 定义：三者的关系

> **所有函数原型都是函数声明，但不是所有函数声明都是函数原型。**

| | 函数声明 | 函数原型 | 函数定义 |
|---|----------|----------|----------|
| 是什么 | 告知编译器"有这个函数，长这样" | **带参数类型列表**的声明 | 带函数体 `{ }` 的实现 |
| 参数类型 | 可有可无 | **必须逐个写出** | 必须写出 |
| 生成机器码 | 否 | 否 | **是** |
| 可重复 | 是（签名须一致） | 是 | 否（ODR，唯一） |
| 例子 | `int add();` 或 `int add(int,int);` | `int add(int a, int b);` | `int add(int a,int b){ return a+b; }` |

```c
int add(int a, int b);        /* ① 函数声明，同时是函数原型（现代 C，推荐） */
int add(int, int);            /* ② 仍是原型——参数名可省略，类型列表在就行 */
int add();                    /* ③ 旧式声明：是声明，但【不是】原型（K&R 遗留，禁止） */
int add(int a, int b) { return a + b; }   /* ④ 定义：有函数体，生成真实代码 */
```

**③ 为什么不是原型**：`int add();` 只告诉编译器"返回 int"，**不说明参数个数、不说明参数类型**，编译器对调用不做任何参数检查，传错了直接 UB。这正是 **7.2.2** 讲的缺省认定，`f()` ≠ `f(void)`。

**② 参数名可省略但依然完整有效**（gcc 13 实测）：

```c
int h(int, int);              /* 省略参数名，照样是原型 */
int h(int a, int b){ return a+b; }
int main(void){ return h(1); }        /* error: too few arguments to function 'h' */
```

原型是否成立**只看参数类型列表，不看参数名**——参数名仅供文档/IDE 使用（**要点** 一节）。

#### 现代 C 的唯一正确姿势

- 头文件 `.h` 里放的**一律是函数原型**，保证所有 `.c` 拿到统一签名
- 无参一律写 `(void)`，绝不留空括号
- 旧式 K&R 写法（`f()` 空括号 / 旧式定义）全部废弃

#### ⚠️ C23 起：`int f();` 的语义变了

C23（N2432）删除了旧式函数声明——**`int f();` 从此等价于 `int f(void);`**（和 C++ 一致）。gcc 13 `-std=c2x` 实测：

```c
int f();                   /* C11：旧式未指定参数 */
int f(int a, int b){...}   /* C11：与上者兼容      */
/* C11 -std=c11  : 编译通过（composite type 合并），调用点按 int(int,int) 检查 */
/* C23 -std=c2x  : error: conflicting types for 'f'; have 'int(int, int)'
                   note: previous declaration of 'f' with type 'int(void)'  */
```

也就是说同一个源文件，换了标准版本会从"通过"变成"编译错误"——**这正是旧式声明必须淘汰的实证**：它在 C17 和 C23 下是两种语义。K&R 旧式定义在 C23 下也降级为 `-Wold-style-definition` 告警。

#### 反直觉：同 TU 内"旧式声明 + 带原型定义"，调用点仍会被检查

gcc 13 实测（`-std=c11`）：

```c
int f();                            /* 旧式 */
int f(int a, int b){ return a+b; }  /* 定义带原型 */
int main(void){ return f(1,2,3); }  /* error: too many arguments to function 'f' */
```

注意报错的 note 指向**定义那一行**（`declared here`），不是第 1 行的旧式声明——因为同一作用域内旧式声明与后续原型会合并成**复合类型（composite type）**，类型被补齐了。

**旧式声明真正致命的场景是跨 TU**：调用点只看得到 `int f();`，定义在别的 `.c`：

```c
/* f_main.c */ int f();  int main(void){ return f(1,2,3); }   /* 3 个实参 */
/* f_impl.c */ int f(int a, int b){ return a+b; }             /* 2 个形参 */
```

```
$ gcc -std=c11 -Wall -Wextra -c f_main.c    # 零输出
$ gcc -std=c11 -Wall -Wextra -c f_impl.c    # 零输出
$ gcc f_main.o f_impl.o -o f_prog           # 链接零报错
$ ./f_prog ; echo $?
0
```

传 3 个参数给 2 参函数，**零警告、链接通过、退出码 0**。更极端的：旧式声明下给 `int f(int,int)` 传 `("hello", 3.14)` 同样零警告（实测）；换成原型 `int f(int,int);` 立刻报
`warning: passing argument 1 of 'f' makes integer from pointer without a cast`。

> 原型的价值就在这一刻兑现：**把运行期静默错误提前到编译期**。
> 补一个诚实的边界：`double → int` 是合法隐式转换，原型+`-Wall` 也不报，要 `-Wconversion` 才拦
> （`warning: conversion from 'double' to 'int' changes value ... [-Wfloat-conversion]`）。

### 与定义必须兼容

- 声明与定义的返回类型、参数类型必须"兼容"（C99 术语）
- `const`、指针层级都属于类型一部分，必须一致
- 不一致 → UB，`-Werror=strict-prototypes` 拦

```c
/* 声明 */
int f(const char *s);
/* 定义 — 忘了 const，类型不兼容，UB */
int f(char *s) { return 0; }
```

### 前向声明

```c
struct queue;                       /* 不完整类型，前向声明 */
struct queue *queue_create(void);   /* 原型只需指针，不需完整布局 */
```

只用指针的函数原型不需要完整结构体定义——这是 opaque ADT 的基础（**7.4**）。

## 底层映射

### 编译期校验

有原型时，编译器对每个调用做"实参类型 → 形参类型"的隐式转换检查：

```c
size_t f(const char *s);
f(123);      /* 有原型：warning / -Werror 拦 */
f("abc");    /* OK */
```

无原型（**7.2.2**）时实参做默认提升（`float→double`、`char/short→int`），不检查类型——`f(123)` 会被当成"传个 int 给未知函数"静默通过。

### 历史包袱：隐式声明

C89 允许"调用未声明函数 → 隐式假定返回 `int`"。C99 起非法，但很多编译器仍只告警不报错：

```bash
# C99 起非法，必须显式声明
gcc -std=c11 -Werror=implicit-function-declaration t.c
# 更严格：要求原型
gcc -Werror=strict-prototypes t.c
```

Linux 内核、DPDK 等大型项目都开这两个 error。

## 工程规范

- 每个 `.c` 对应 `.h` 导出公共 API
- 私有函数 `static` 放 `.c` 内，不进 `.h`
- 公共 API 一律 `(void)` 表示无参（**7.2.2**）
- CI 开 `-Werror=implicit-function-declaration -Werror=strict-prototypes`

## HFT / DPDK

| 规范 | 例子 |
|------|------|
| 原型 + `const` 标只读 | `int decode(const uint8_t *, size_t, struct quote *);` |
| 前向声明藏布局 | `struct rte_mbuf;` 在公共头，布局在内部 |
| 错误码返回 + 输出参数 | `int parse(..., struct quote *out);` |
| 可变参仅限日志 | `void rte_log(int level, const char *fmt, ...);` |

## 常见误区

| 误区 | 事实 |
|------|------|
| "原型只是文档" | 是编译期类型契约，拦住大量 UB |
| "声明里参数名没用" | 编译期可选，但文档工具、IDE 提示依赖它 |
| "`f()` 和 `f(void)` 一样" | 不同：`f()` 是旧式未指定参数（**7.2.2**） |
| "声明和定义 const 不一致没事" | UB，编译器可能拦也可能不拦 |
| "声明就是原型" | 旧式 `int f();` 是声明但不是原型——原型必须带参数类型列表 |
| "原型省略参数名就不完整" | 参数名可选，类型列表在就是完整原型，检查照做 |
| "`int f();` 写在哪都一个语义" | C23 起等价于 `f(void)`，同一份代码在 C17/C23 下可能通过/报错两种结果 |
| "同 TU 里 `int f();` 一定不检查" | 后面若出现带原型定义，composite type 会被补齐，调用点照样检查 |

## 实操

```bash
# 开严格原型检查
gcc -Werror=strict-prototypes -Werror=implicit-function-declaration t.c
# 看声明与定义不一致的告警
gcc -Werror=incompatible-pointer-types t.c
# cscope / clangd 跳转：原型在 .h，定义在 .c
```

## 代码自测

**题目 1：** 以下代码有什么问题？
```c
// file1.c
double f(double x) { return x * 2; }
// file2.c (没有 #include 头文件)
int main() {
    double r = f(3);
    return 0;
}
```

<details>
<summary>参考答案</summary>

file2.c 中 f 被隐式声明为返回 int（C89）或编译错误（C99）。即使 C89 能编译，f 实际返回 double 但调用方以为是 int，返回值会被截断。正确做法：在 file2.c 中声明原型 double f(double); 或通过头文件包含。

</details>

**题目 2：** 下列四行，哪些是原型？哪些只是声明？
```c
int add(int a, int b);     // 行 1
int add(int, int);         // 行 2
int add();                 // 行 3
int add(void);             // 行 4
```

<details>
<summary>参考答案</summary>

- 行 1 **是原型**：返回类型 + 每个参数类型都明确。
- 行 2 **是原型**：参数名省略不影响——原型只看**参数类型列表**是否存在。
- 行 3 **只是声明，不是原型**：旧式 K&R 写法，参数未指定，编译器不做实参检查。C23 起语义改为 `int add(void)`。
- 行 4 **是原型**：`(void)` 明确表示无参数，调用 `add(1)` 报 `too many arguments`。

记忆：**空括号 `()` 不是原型，`(void)` 才是**——C 里两者完全不同（→ **7.2.2**），
C++ 里 `f()` ≡ `f(void)`。

</details>
