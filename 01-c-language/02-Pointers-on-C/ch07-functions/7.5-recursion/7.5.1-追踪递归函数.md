# 7.5.1 追踪递归函数

## 本节讲什么

手工 / 调试器**追踪递归调用栈**：每层参数、局部变量、返回点。理解栈帧如何叠加，是读递归代码、调试爆栈、看 Oops 的基本功。

## 要点

以链表打印为例：

```c
void print_list(struct node *p)
{
    if (p == NULL)
        return;                  /* 基线 */
    printf("%d\n", p->data);
    print_list(p->next);         /* 先序：先打印再递归 */
}
```

### 先序 vs 后序

```c
/* 先序：进入节点时处理 */
void pre(node *p) {
    if (!p) return;
    printf("%d\n", p->data);   /* 先处理当前 */
    pre(p->next);               /* 再递归 */
}

/* 后序：回退时处理 */
void post(node *p) {
    if (!p) return;
    post(p->next);              /* 先递归到底 */
    printf("%d\n", p->data);    /* 回退时打印 → 逆序输出 */
}
```

先序输出 `1 2 3`，后序输出 `3 2 1`（链表逆序）——后序在回退时处理，自然得到逆序。

### 追踪表（概念）

| 层 | p 指向 | 进入时执行 | 待返回后执行 |
|----|--------|-----------|--------------|
| 1 | node1 | printf(1) | （回到调用者） |
| 2 | node2 | printf(2) | return 到层 1 末尾 |
| 3 | node3 | printf(3) | return 到层 2 末尾 |
| 4 | NULL | return | return 到层 3 末尾 |

每层有自己的 `p` 副本（值传递，**7.3**），互不干扰。回退按"后进先出"逐层 `ret`。

### gdb 追踪

```bash
(gdb) b print_list
(gdb) run
(gdb) bt              # 看递归深度
#0  print_list (p=0x...) at t.c:5
#1  print_list (p=0x...) at t.c:6
#2  print_list (p=0x...) at t.c:6
...
(gdb) frame 3         # 切到第 3 层
(gdb) print p         # 看那一层的 p 指向谁
(gdb) info locals     # 看那一层的局部变量
```

`bt`（backtrace）是读递归的核心——每一帧就是一层递归调用。

## 底层映射

### 栈帧叠加（后进先出）

```
高地址（栈底）
  ┌─ main 帧 ─────────────┐
  │  ...                  │
  ├─ print_list(node1) ───┤  ← 第一次调用
  │  p=node1, ret=main    │
  ├─ print_list(node2) ───┤  ← 递归 1
  │  p=node2, ret=层1     │
  ├─ print_list(node3) ───┤  ← 递归 2
  │  p=node3, ret=层2     │
  ├─ print_list(NULL) ────┤  ← 递归 3（基线）
  │  p=NULL, ret=层3      │
  └───────────────────────┘
低地址（栈顶，向低增长）
```

每帧有独立的 `p`（参数副本）和返回地址。基线 `return` 后，逐帧 `ret` 弹出，栈收缩。

### 内核 Oops 的 stack trace

内核崩溃时打印的 call trace 就是递归式栈回溯（`dump_stack()`）：

```
[  123.456] Call trace:
[  123.456]  walk_tree+0x42/0x80
[  123.456]  walk_tree+0x3a/0x80   ← 递归层 2
[  123.456]  walk_tree+0x3a/0x80   ← 递归层 1
[  123.456]  sys_ioctl+0x...
```

看到同名函数连续出现 = 递归。深度异常 = 爆栈嫌疑。

## HFT / DPDK

| 场景 | 用法 |
|------|------|
| 调试链表死循环 | `gdb` attach 后 `bt` 看深度 |
| 内核 Oops | 读 call trace 判断递归栈 |
| AST 遍历 | 限深 + 追踪表辅助理解 |
| 配置解析 | 递归下降解析器，追踪每层 token |

## 常见误区

| 误区 | 事实 |
|------|------|
| "所有层共享同一个 p" | 每层有独立副本（值传递） |
| "先序后序结果一样" | 后序逆序，因为处理在回退时 |
| "bt 看不出递归深度" | 同名帧连续出现就是递归层 |
| "递归回退顺序是先进先出" | 后进先出（栈结构） |

## 实操

```bash
# gdb 追踪递归
gcc -g -O0 t.c -o t
gdb ./t -ex 'b print_list' -ex r -ex bt -ex 'frame 2' -ex 'p p'
# 内核 dump_stack() 看 call trace
# 手画追踪表：对 5 节点链表，列出每层 p 和执行顺序
```
