# 7.5.2 递归与迭代

## 本节讲什么

同一问题**递归** vs **循环**实现的权衡。HFT 与内核热路径偏好迭代——栈深度可控、无 call/ret 开销、cache 友好。这一节还讲"尾递归优化"在 C 里的真实情况：标准不保证，gcc 常做但不总能。

## 要点

| | 递归 | 迭代 |
|---|------|------|
| 代码 | 简洁、贴近数学定义 | 常多几行状态变量 |
| 栈 | O(深度) | O(1) |
| 性能 | call/ret 开销 + 栈帧 | 常更快 |
| 可控性 | 栈深度难预估 | 显式 |
| HFT | **避免** | **首选** |

### 链表遍历：递归 vs 迭代

```c
/* 递归版 */
void print_list_rec(struct node *p) {
    if (!p) return;
    printf("%d\n", p->data);
    print_list_rec(p->next);
}

/* 迭代版 */
void print_list_iter(struct node *p) {
    for (; p != NULL; p = p->next)
        printf("%d\n", p->data);
}
```

迭代版：一个游标指针 `p`，O(1) 栈，无 call/ret。链表遍历几乎总是迭代更优。

### 尾递归与 TCO

**尾递归**：递归调用是函数最后一步（返回值就是递归调用的返回值，无后续运算）。

```c
/* 非尾递归：n + sum(n-1)，递归返回后还要加 n */
int sum(int n) { return n <= 0 ? 0 : n + sum(n - 1); }

/* 尾递归：acc 累加，递归调用是最后一步 */
int sum_tail(int n, int acc) {
    return n <= 0 ? acc : sum_tail(n - 1, acc + n);
}
```

尾递归可优化成循环（TCO，Tail Call Optimization）：复用同一栈帧，O(1) 空间。

**但 C 标准不保证 TCO**。gcc/clang 在 `-O2` 通常会做（叶子函数 + 尾调用），但不总能——尤其有调试信息、复杂栈帧、或非纯尾调用时。**不要依赖 TCO 保证不爆栈**，要 O(1) 就显式写循环。

```bash
# 看尾递归是否被优化成循环（jmp 而非 call）
gcc -O2 -S t.c -o -
# 尾递归优化后：sum_tail 内是 jmp sum_tail（循环），无 call
# 非尾递归 sum：仍是 call sum（递归），有 call/ret
```

### 显式栈模拟递归

深度不可控但需要"栈式"处理时，用显式栈数组替代：

```c
void walk_tree_iter(node *root) {
    node *stack[64];              /* 限深 64 */
    int sp = 0;
    stack[sp++] = root;
    while (sp > 0) {
        node *n = stack[--sp];
        if (!n) continue;
        visit(n);
        stack[sp++] = n->right;   /* 先压右，后压左 → 左先访问 */
        stack[sp++] = n->left;
    }
}
```

栈深度显式可控（数组大小），爆栈变成可预测的"栈满"错误。**ch17** 详。

### 何时仍用递归

- 深度有界且小（AST、配置树）
- 非热路径工具代码（启动期配置加载）
- 代码清晰度远胜迭代（数学递归定义）

## 底层映射

### 性能对比（同一链表）

```bash
$ perf stat -e instructions,cache-misses ./rec
$ perf stat -e instructions,cache-misses ./iter
# 迭代版：指令数少（无 call/ret/prologue），cache-miss 少（栈帧少）
```

递归每层 = `call` + prologue + body + epilogue + `ret`，指令数和 cache 压力都更高。

### gcc TCO 的实际行为

```c
int sum_tail(int n, int acc) {
    return n <= 0 ? acc : sum_tail(n - 1, acc + n);
}
```

```bash
$ gcc -O2 -S t.c -o -
sum_tail:
.L1:
    test    edi, edi
    jle     .L2
    add     esi, edi             ; acc += n
    dec     edi                  ; n--
    jmp     .L1                  ; ← jmp 不是 call！TCO 生效
.L2:
    mov     eax, esi
    ret
```

`jmp` 替代 `call` = 复用栈帧 = O(1) 空间。但换个稍复杂写法 gcc 可能不做——所以别赌。

## HFT / DPDK

| 场景 | 选择 |
|------|------|
| 链表 walk | 迭代 |
| 树遍历（限深） | 迭代 + 显式栈 |
| 报文解析 | 迭代游标 |
| 回测/工具 | 可递归（非热路径） |
| 信号处理 | 禁递归（handler 内递归=找死） |

## 常见误区

| 误区 | 事实 |
|------|------|
| "尾递归一定不爆栈" | C 标准不保证 TCO，gcc 常做但不总能 |
| "递归和迭代性能一样" | 递归多 call/ret + 栈帧，慢且 cache 差 |
| "显式栈比递归慢" | 常更快，且深度可控 |
| "递归一定更易读" | 链表遍历迭代更清晰 |

## 实操

```bash
# 对比递归 vs 迭代的指令数与 cache
perf stat -e instructions,cache-misses ./rec
perf stat -e instructions,cache-misses ./iter
# 看尾递归是否被 TCO（找 jmp 而非 call）
gcc -O2 -S t.c -o - | grep -A10 'sum_tail'
# 故意深递归看爆栈
gcc -O0 t.c -o t && ./t       # -O0 禁 TCO，必爆
```
