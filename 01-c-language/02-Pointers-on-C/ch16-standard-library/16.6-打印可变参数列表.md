# 16.6 打印可变参数列表

## 本节讲什么

`<stdarg.h>` 的 `va_list` / `va_start` / `va_arg` / `va_end` / `va_copy`，以及配合 `vfprintf` / `vsnprintf` / `vprintf` 实现自定义可变参数函数。这是 C 语言实现 `printf` 风格日志接口的底层机制，DPDK `rte_log`、glibc `syslog`、所有现代日志库都建立在它之上。本节重点讲 ABI 相关的微妙之处、`va_list` 的所有权语义、以及为什么 `va_copy` 在某些平台必不可少。

## 要点

### 基本接口

```c
#include <stdarg.h>

void foo(const char *fmt, ...) {
    va_list ap;
    va_start(ap, fmt);          /* 绑定最后一个固定参数 */
    
    int x = va_arg(ap, int);    /* 取下一个 int */
    double d = va_arg(ap, double);
    char *s = va_arg(ap, char *);
    
    va_end(ap);                 /* 清理 */
}
```

| 宏 | 作用 | 调用时机 |
|----|------|----------|
| `va_start(ap, last)` | 初始化 `va_list`，绑定最后一个有名参数 | 取参数前 |
| `va_arg(ap, type)` | 取下一个参数并推进 | 每次取参数 |
| `va_end(ap)` | 清理（某些平台释放在栈上的状态） | 函数返回前 |
| `va_copy(dest, src)` | 复制 `va_list` 状态 | 需要二次遍历时 |

### va_list 是什么

`va_list` 是一个不透明类型，在不同平台实现差异巨大：

| 平台 | va_list 实现形式 |
|------|------------------|
| x86-64 System V | 结构体（寄存器保存区 + 溢出区指针） |
| x86 cdecl | `char *`，指向栈上参数 |
| ARM | `struct __va_list` |
| Itanium | 复杂结构 |

所以 `va_list` 不能直接赋值复制（`va_list a = b` 在某些平台 UB），必须用 `va_copy`。

### 整数提升与默认参数提升

`va_arg(ap, type)` 的 `type` 受"默认参数提升"约束：

- `char`/`short` → 提升为 `int`
- `unsigned char`/`unsigned short` → 提升为 `int` 或 `unsigned int`
- `float` → 提升为 `double`

```c
void foo(...) {
    va_list ap;
    va_start(ap, fmt);
    char c = va_arg(ap, int);      /* 不是 char! */
    short s = va_arg(ap, int);     /* 不是 short! */
    float f = va_arg(ap, double);  /* 不是 float! */
    va_end(ap);
}
```

用 `va_arg(ap, char)` 是 UB——编译器可能不报错，但取出的值是错的。

### va_start 的第二参数

`va_start(ap, last)` 的 `last` 是函数参数列表里**最后一个有名参数**。编译器用它定位可变参数在栈上的起点：

```c
void log_msg(int level, const char *fmt, ...) {
    va_list ap;
    va_start(ap, fmt);   /* fmt 是最后一个有名参数 */
    /* ... */
}
```

如果函数被声明为 `(...)` 没有任何有名参数（C23 之前非法，C23 允许），`va_start` 无法工作。C 标准 `...` 前必须有至少一个有名参数。

### va_end 为什么必要

某些平台（如 x86-64）的 `va_list` 是栈上结构，`va_start` 可能分配了动态资源（罕见但存在）。`va_end` 释放这些资源。即使在不需要的平台上，遗漏 `va_end` 也是 UB——标准要求每个 `va_start` 必须有匹配的 `va_end`。

### va_copy：二次遍历

```c
void log_both(FILE *f1, FILE *f2, const char *fmt, ...) {
    va_list ap1, ap2;
    va_start(ap1, fmt);
    va_copy(ap2, ap1);   /* 复制状态, ap2 独立 */
    
    vfprintf(f1, fmt, ap1);
    vfprintf(f2, fmt, ap2);   /* 第二次遍历 */
    
    va_end(ap1);
    va_end(ap2);
}
```

`va_list` 被 `vfprintf` 消费后状态不确定（某些平台 `ap` 被改到末尾，某些平台不变）。要二次遍历必须 `va_copy` 复制一份。这是 C99 引入 `va_copy` 的原因。

### vfprintf / vsnprintf / vprintf

```c
int vfprintf(FILE *stream, const char *fmt, va_list ap);
int vsnprintf(char *str, size_t size, const char *fmt, va_list ap);
int vprintf(const char *fmt, va_list ap);
```

`v` 前缀版本接受 `va_list` 而不是 `...`。这是实现"自定义 printf"的关键——你的函数收 `...`，用 `va_start` 转 `va_list`，再转发给 `vfprintf`。

### 自定义日志函数模板

```c
#include <stdarg.h>
#include <stdio.h>
#include <time.h>

static FILE *g_log_fp = NULL;
static int g_log_level = LOG_INFO;

void log_init(FILE *fp, int level) {
    g_log_fp = fp;
    g_log_level = level;
}

void log_msg(int level, const char *fmt, ...) {
    if (level < g_log_level) return;
    if (!g_log_fp) return;
    
    /* 时间戳 */
    struct timespec ts;
    clock_gettime(CLOCK_REALTIME, &ts);
    struct tm tm_buf;
    localtime_r(&ts.tv_sec, &tm_buf);
    char timebuf[32];
    strftime(timebuf, sizeof timebuf, "%H:%M:%S", &tm_buf);
    
    fprintf(g_log_fp, "[%s.%03ld] ", timebuf, ts.tv_nsec / 1000000);
    
    /* 用户消息 */
    va_list ap;
    va_start(ap, fmt);
    vfprintf(g_log_fp, fmt, ap);
    va_end(ap);
    
    fputc('\n', g_log_fp);
}
```

### printf 风格宏包装

```c
#define LOG(level, fmt, ...) \
    log_msg(level, "[%s:%d] " fmt, __FILE__, __LINE__, ##__VA_ARGS__)

LOG(LOG_INFO, "connected to %s:%d", host, port);
/* 展开为:
 * log_msg(LOG_INFO, "[%s:%d] connected to %s:%d", __FILE__, __LINE__, host, port);
 */
```

`__FILE__`/`__LINE__` 是预处理符号，自动注入源码位置。`##__VA_ARGS__` 处理无参数时去掉前导逗号（GNU 扩展，C23 `__VA_OPT__` 标准化）。

### va_list 的所有权与 ABI 跨界

`va_list` 的 ABI 因平台而异，**不能跨函数边界传递 `va_list` 本身的指针**然后期望另一函数 `va_arg`——除非该函数签名声明接受 `va_list*`。直接传 `va_list` 值在某些平台是按值传递（复制），某些平台按引用（指针），行为不一致。跨函数转发用 `va_list` 值传递 + 被调函数用 `va_copy` 保留副本最安全。

## HFT 关联

- **日志宏核心**：HFT 网关统一日志 API `LOG(level, fmt, ...)` 内部就是 `va_start` + `vsnprintf` + 队列入队
- **DPDK rte_log**：DPDK 日志接口 `rte_log(level, fmt, ...)` 同模式，内部 `vfprintf` 到注册的流
- **异步日志**：数据面 `LOG` 宏把格式化后的字符串入队（`vsnprintf` 到栈缓冲 + `memcpy` 到 ring），后台线程 `write` 落盘——避免数据面直接 syscall
- **崩溃栈打印**：信号 handler 里用 `vsnprintf` 格式化栈帧到固定缓冲，`write(STDERR_FILENO, ...)` 输出（async-signal-safe）
- **可变参数避免数据面**：数据面热路径不用可变参数，固定字段直接 `memcpy` 到日志结构体，比 `vsnprintf` 快十倍
- **format string 注入**：外部数据绝不能直接当 `fmt`，必须 `LOG("%s", user_data)`
- **va_list 跨线程**：`va_list` 不能跨线程传递（栈状态），日志异步队列存的是格式化后的字符串，不是 `va_list`
