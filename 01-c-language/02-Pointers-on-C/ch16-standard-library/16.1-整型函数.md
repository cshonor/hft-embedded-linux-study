# 16.1 整型函数

## 本节讲什么

`<stdlib.h>` 里与整数相关的工具：字符串转整数的 `atoi` 族与 `strtol` 族、伪随机数 `rand`/`srand`、排序与查找 `qsort`/`bsearch`、简单算术 `abs`/`div`。这是配置解析、订单排序检索的基础工具集，也是 C 程序员最容易写出"看似能用实际有坑"代码的地方——`atoi` 静默失败、`rand` 全局状态、`qsort` 比较函数溢出，每一个都是生产事故源。

## 要点

### 字符串转整数：atoi 禁用，strtol 必选

```c
int atoi(const char *nptr);           /* 静默失败, 返回 0 */
long atol(const char *nptr);
long long atoll(const char *nptr);

long strtol(const char *nptr, char **endptr, int base);
long long strtoll(const char *nptr, char **endptr, int base);
unsigned long strtoul(...);
unsigned long long strtoull(...);
```

`atoi` 的三大罪状：

1. **无错误检测**：`atoi("abc")` 返回 0，与 `atoi("0")` 无法区分
2. **无溢出处理**：`atoi("99999999999999")` 行为未定义，可能返回任意值
3. **无尾指针**：无法知道解析到哪停，`atoi("123abc")` 返回 123 但不告诉你后面有垃圾

`strtol` 的完整错误检测：

```c
char *end;
errno = 0;
long long v = strtoll(s, &end, 10);
if (end == s) {
    /* 没有任何数字被解析 */
} else if (*end != '\0') {
    /* 解析了部分, 后面有非数字字符 */
}
if (errno == ERANGE) {
    /* 溢出, v 被钳位到 LLONG_MAX 或 LLONG_MIN */
}
```

| 输入 | atoi | strtoll | endptr 指向 |
|------|------|---------|-------------|
| `"123"` | 123 | 123 | `'\0'` |
| `"123abc"` | 123 | 123 | `'a'` |
| `"abc"` | 0 | 0 | `'a'`（== s） |
| `"99999999999999999999"` | UB | LLONG_MAX | 末尾，errno=ERANGE |
| `"  -42"` | -42 | -42 | `'\0'`（跳前导空白） |
| `"0x1A"` | 0 | 0（base=10）或 26（base=16） | 取决于 base |

### base 参数与自动检测

`strtol(s, &end, 0)` 自动根据前缀判断进制：`0x` 开头按 16 进制，`0` 开头按 8 进制，其余 10 进制。HFT 配置文件一般显式 `base=10` 避免 `"08"` 被当 8 进制报错。

### 随机数：rand 的全局状态陷阱

```c
srand((unsigned)time(NULL));
int r = rand();   /* [0, RAND_MAX], 典型 32767 */
```

问题：

1. **全局状态**：`rand` 内部维护全局种子，多线程调用需加锁，争锁成为瓶颈
2. **周期短质量差**：`rand` 常用线性同余，周期 2^31，统计性质差，不适合 Monte Carlo
3. **可预测**：知道种子就能复现整个序列，加密不安全
4. **RAND_MAX 小**：16 位平台只有 32767，32 位平台通常 2^31-1

替代方案：

| 接口 | 特点 | 适用 |
|------|------|------|
| `rand_r(unsigned *seed)` | 可重入，POSIX | 多线程压测 |
| `drand48_r` / `nrand48` | 48 位 LCG，质量略好 | POSIX 系统 |
| `arc4random` / `getrandom` | 内核熵源，加密安全 | 安全场景 |
| DPDK `rte_rand` | 无锁，每核种子，性能高 | HFT 数据面 |
| xorshift / PCG | 用户态实现，周期长质量好 | 回测/模拟 |

HFT 压测随机订单生成用每线程独立种子的 xorshift128+，避免 `rand` 锁。

### qsort：通用排序与比较函数陷阱

```c
void qsort(void *base, size_t nmemb, size_t size,
           int (*compar)(const void *, const void *));
```

比较函数的三大坑：

#### 1. 直接减法溢出

```c
/* 错误: 大数相减溢出 */
int cmp(const void *a, const void *b) {
    return *(int*)a - *(int*)b;   /* INT_MIN - INT_MAX 溢出 UB */
}
```

正确写法：

```c
int cmp(const void *a, const void *b) {
    int x = *(const int *)a, y = *(const int *)b;
    return (x > y) - (x < y);   /* 无溢出, 返回 -1/0/1 */
}
```

#### 2. 不满足严格弱序

比较函数必须满足：`a < b` 和 `b < a` 不能同时为真，`a == a` 必须返回 0。如果用 `<=` 或 `>=` 会破坏 qsort 的内部不变式，导致越界或死循环。

#### 3. 类型双关严格别名

`*(const uint64_t *)a` 在 `a` 实际指向 `uint32_t` 数组时是 UB。qsort 回调里务必保证类型一致，或用 `memcpy` 安全转换。

### qsort 的性能特征

- 标准没规定算法，glibc 用 mergesort+insertion sort 混合，平均 O(n log n)
- 比较函数通过函数指针调用，无法内联，每次比较有间接调用开销
- `void*` + `size` 元素大小，swap 时按字节拷贝，无法用类型特化的 `memcpy`
- 海量数据（百万级）HFT 排序常手写专用排序：定长元素 + 内联比较 + 类型特化 swap，比 qsort 快 2-5x

### bsearch：二分查找

```c
void *bsearch(const void *key, const void *base, size_t nmemb, size_t size,
              int (*compar)(const void *, const void *));
```

- 数组必须已排序
- 返回指向匹配元素的指针，未找到返回 NULL
- 多个匹配元素时返回哪个未指定
- 比较函数必须与排序时一致

### abs/div 等辅助

```c
abs(INT_MIN);   /* UB! INT_MIN 的绝对值超出 int 范围 */
labs(LLONG_MIN); /* 同样 UB */
div_t d = div(17, 5);   /* d.quot=3, d.rem=2, 一次操作同时取商和余 */
```

`div`/`ldiv`/`lldiv` 在一条指令同时取商和余，编译器能优化成单条 `idiv`，比分开写 `/` 和 `%` 快。

## HFT 关联

- **配置解析**：`gateway.conf` 里 `port=8125` 用 `strtoll` 解析，errno + endptr 双重校验
- **订单 ID 排序**：回测按 `seq` 排序历史 tick，`qsort` 通用但慢，百万级用手写 radix sort 或 std::sort
- **订单簿查找**：按价格档位二分查找，`bsearch` 或自写 lower_bound
- **随机订单生成**：压测每线程独立 xorshift 种子，避免 `rand` 全局锁
- **时间戳取模**：纳秒时间戳对齐到微秒用 `div`，编译器优化成单条指令
- **价格溢出检测**：`strtoll` 解析价格字符串时检查 ERANGE，防止配置错误导致天量订单
- **DPDK rte_rand**：数据面随机退避、负载均衡哈希扰动用无锁 `rte_rand`
