# 3.7 存储类型

## 本节讲什么

**存储期(storage duration)** 决定"对象存活多久、何时初始化、何时销毁"。它和**链接**(能否跨文件)、**作用域**(在哪可见)是三个独立维度,合起来描述对象的完整生命周期。本节把四类存储期(自动/静态/线程/动态)与 **ELF 段**(`.text/.rodata/.data/.bss/栈/堆`)的对应讲透,这是 ch03 与 ch18 运行时环境的桥梁。

## 要点

### 四种存储期

| 存储期 | 关键字 | 位置 | 初值 | 生命周期 |
|--------|--------|------|------|----------|
| **自动**(automatic) | auto(默认局部) | **栈** | 不保证 | 块开始~块结束 |
| **静态**(static) | static(局部/文件) | **.data/.bss** | 0 或显式 | 程序全程 |
| **线程**(thread) | _Thread_local(C11) | TLS | 视情况 | 线程全程 |
| **动态**(allocated) | malloc/calloc/realloc | **堆** | malloc 不保证 | malloc~free |

> ⚠️ 区别**存储期**(活多久)与**链接**(能否跨文件):static 在块内只改存储期不改链接;在文件级改链接不改存储期。3.8 详。

### 五个存储类关键字总表

| 存储类 | 生命周期 | 链接属性 | 存放位置 |
|--------|----------|----------|----------|
| `auto`(C23 起改为类型推导) | 块执行期间 | 无链接 | 栈 |
| `static`(块内) | 程序全程 | 无链接 | .data/.bss |
| `static`(文件级,含函数) | 程序全程 | **内部链接**(仅本 TU) | .data/.bss/.text |
| `extern` | 程序全程 | **外部链接**(跨文件) | 定义处 .data/.bss |
| `register`(C23 已移除) | 块执行期间 | 无链接 | 尝试寄存器,回退栈;不能 `&x` |
| `_Thread_local` | **线程**存活期间 | 看搭配:单独用=外部,配 static=内部 | TLS 块 |

- 存储类**不改变数据类型**,只控制生命周期+链接两轴
- **文件作用域 `_Thread_local` 可单独用**;块作用域必须配 static/extern
- 单条声明**至多一个存储类**(C11 6.7.1p2),`static extern int x;` 是约束违例;例外:`_Thread_local` 可与 static/extern 同用

### ELF 段映射(为什么会自动清零)

```
可执行文件布局(概念):
+-----------------+  加载地址低
| .text           |  代码, 只读可执行
| .rodata         |  字符串常量, const 只读数据
| .data           |  有初值全局/static     ← 占文件体积
| .bss            |  无初值全局/static     ← 不占文件, 加载时清零
+-----------------+
| 堆(向上长)      |  malloc 申请, 运行时扩展
| ...             |
| 栈(向下长)      |  函数帧, 局部 auto
+-----------------+  加载地址高
```

| 段 | 内容 | 自动清零? | 占文件? |
|----|------|-----------|---------|
| `.text` | 机器码 | - | 是 |
| `.rodata` | const 数据、字符串字面量 | - | 是 |
| `.data` | 有初值全局/static | 否(用初值) | 是 |
| `.bss` | 无初值或初值=0 全局/static | **是**(加载器清零) | 否 |
| 栈 | auto 局部、形参 | **否** | - |
| 堆 | malloc | **否** | - |

### 自动存储期(栈)

```c
void f(int n) {
    int x = n;           /* x 在栈帧, f 返回即"销毁"(栈指针回退) */
    int arr[100];        /* 栈帧扩展, 内容是上次残留 */
}
```

- 每次函数调用压栈一个"帧":返回地址、保存寄存器、局部变量
- 返回后栈指针回退,内存内容残留,直到下次被覆盖
- 这就是"返回局部地址"是 UB 的根因

### 默认存储类:由作用域决定

| 声明位置 | 不写存储类时 | 语义 |
|----------|--------------|------|
| 块内 `int x;` | **auto**(自动存储期,栈) | 块结束销毁 |
| 文件域 `int g;` | **不是 auto** —— 暂定定义,外部链接,静态存储期 | C11 6.2.2p5:文件域无存储类说明符 → 外部链接 |
| 形参 `void f(int a)` | **自动存储期**(语义上同 auto) | 但语法上只能加 `register`,见下 |

> ⚠️ **"全局默认是隐式 extern"是危险的说法**:`int g;`(文件域)的**链接属性**确实是外部的,但它是一个**定义**(暂定定义),和 `extern int g;`(**声明**)在链接器眼里完全不同:
> - 两个 TU 各写 `int g;` → `-fno-common` 下 `multiple definition` 报错
> - `extern int g;` 放头文件随便包含,不报错
>
> "外部链接"是链接属性,不是存储类——别说成"隐式 extern"。

**形参的存储类限制**(C11 6.7.6.3 约束):

```c
void f1(register int a);   /* ✅ 唯一允许的存储类 */
void f2(auto int a);       /* ❌ 约束违例,编译报错 */
void f3(static int a);     /* ❌ 约束违例 */
```

- 形参**有**自动存储期(语义上同 auto),但 `auto` 关键字**不能出现在形参声明里**——标准原文:*"The only storage-class specifier that shall occur in a parameter declaration is register"*
- 这不是"老语法没人写",是**从来没合法过**
- `register int a` 也只是提示;取地址 `&a` 时编译器自动降级为栈变量

### 静态存储期(.data/.bss)

```c
int g_init = 42;           /* .data, 外部链接 */
int g_zero;                /* .bss, 自动 0 */
static int s_init = 1;     /* .data, 内部链接 */
static int s_zero;         /* .bss, 自动 0 */
void f(void) {
    static int call = 0;   /* .data/.bss, 块作用域但静态存储期 */
    call++;
}
```

- 静态对象**程序全程存活**,作用域仍按声明位置(块/文件)
- `.data` 占文件体积(存初值);`.bss` 不占,加载时清零
- static 局部:作用域限块,存储期静态 —— 3.8 详

### 线程存储期(C11 _Thread_local)

```c
_Thread_local int t_count = 0;    /* 关键字(C11 6.7.1),不需要任何头文件 */
#include <threads.h>
thread_local int t_count2 = 0;    /* 宏(C11 7.26),等价 _Thread_local */
```

- 每个线程有自己的副本,无需加锁访问 —— per-thread 计数器/缓存常用
- HFT 多核收包:per-lcore 计数器用 thread_local,避免共享缓存行伪共享
- **作用域规则**(C11 6.7.1):**文件作用域可单独用**——`_Thread_local int x;` 合法(外部链接+线程存储期);**块作用域必须搭配 static/extern**——块内裸写 `_Thread_local int x;` 是约束违例,因为块内无 static/extern 的对象是自动存储期,与线程存储期矛盾
- `__thread` 是 GCC 早于 C11 的扩展,DPDK/内核大量使用,语义基本同 `_Thread_local`

**TLS 底层实现(x86-64)**:

- 每个线程启动时,线程库在 `%fs` 段基址寄存器存一个指针,指向本线程的 TLS 块
- 访问 TLS 变量编译成段相对寻址:`mov %fs:0xfffffff8, %eax` —— **一次访存、没有函数调用**,与普通全局几乎同速(initial-exec 模型)
- 主程序里的 TLS 走 initial-exec 零额外开销;**动态加载的 `.so` 里的 TLS** 走 general-dynamic 模型,要先调 `__tls_get_addr()` 查地址,慢一个量级 —— HFT 热路径把 TLS 变量放主程序,别放插件 so

### 动态存储期(堆)

```c
int *p = malloc(sizeof(int));    /* 堆, 不清零 */
int *q = calloc(1, sizeof(int)); /* 堆, 清零 */
free(p); free(q);                /* 显式释放 */
```

- 堆对象生命周期由 `malloc` 到 `free`,跨函数调用仍有效
- `malloc` 不清零;`calloc` 清零;`realloc` 保留前 N 字节
- ch11 专章

#### malloc / calloc / realloc / free

| 函数 | 签名 | 初始化 | 失败返回 |
|------|------|--------|----------|
| `malloc` | `void *malloc(size_t size)` | **不清零**(脏内存) | `NULL` |
| `calloc` | `void *calloc(size_t nmemb, size_t size)` | **整块清零** | `NULL` |
| `realloc` | `void *realloc(void *ptr, size_t size)` | 保留前 min(旧,新) 字节 | `NULL`(原 ptr 仍有效) |
| `free` | `void free(void *ptr)` | — | — |

**malloc vs calloc——不只是"清不清零"的区别**:

```c
/* ❌ 危险:n*size 可能整数溢出 → 分配小缓冲 → 堆溢出 */
int *a = malloc(n * sizeof(int));

/* ✅ 安全:calloc 内部做 n*size 乘法溢出检查(C11 7.22.3.2) */
int *b = calloc(n, sizeof(int));
```

> ⚠️ **calloc ≠ malloc + memset**。两个参数分开传,内部在乘法前检查溢出——这是**安全功能**,不是"部分平台的优化"。`malloc(n * sizeof(int))` 里 `n` 来自外部输入时,`n * sizeof(int)` 溢出到一个小值 → malloc 分配小缓冲 → 后续写入越界 → 堆溢出 CVE。大分配优先 calloc。

**realloc 行为表**:

| 调用 | 等价行为 |
|------|----------|
| `realloc(NULL, size)` | 等价 `malloc(size)` |
| `realloc(ptr, 0)` | C11: 实现定义(可能 free 后返回 NULL,也可能返回非空指针);C23 起明确 UB |
| `realloc(ptr, bigger)` | 可能原地扩展,也可能分配新块+拷贝+释放旧块 |
| `realloc(ptr, smaller)` | 通常原地缩短,返回值可能等于 ptr |

```c
/* 正确用法:用临时变量接,避免 realloc 失败丢原指针 */
int *tmp = realloc(p, new_size);
if (tmp) p = tmp;        /* 成功才覆盖 */
else { /* 失败:原 p 仍有效,可继续使用或 free */ }
```

> 经典 bug:`p = realloc(p, new_size);` —— realloc 失败返回 NULL,原 p 丢失→内存泄漏+野指针。

**free 的规则**:
- `free(NULL)` 安全,什么都不做(C11 7.22.3.3)
- free 后指针变成野指针——**不要再解引用**
- 防御性写法:`free(p); p = NULL;`
- 不要 free 栈上变量、不要重复 free 同一指针 → UB

#### malloc 底层:brk vs mmap

```
malloc 如何向 OS 要内存(glibc ptmalloc):

  分配大小 ≤ 128KB(默认 MMAP_THRESHOLD)
  → brk/sbrk 调整 program break,扩展 heap 区
  → free 后内存不一定还给 OS(仍挂在 free 链上,RSS 不降)
  → 适合频繁的小分配

  分配大小 > 128KB
  → mmap(NULL, size, PROT_RW, MAP_PRIVATE|MAP_ANONYMOUS, -1, 0)
  → free 后 munmap 立即还 OS,RSS 下降
  → 大块分配更"干净"但 mmap 系统调用开销大
```

- 详见 2.1.2 执行环境
- 128KB 阈值可调(`mallopt(M_MMAP_THRESHOLD, ...)`)但很少动
- `free` 不一定降低 RSS:小块还挂在 ptmalloc 的 fastbin/smallbin 上,下次 malloc 直接复用——这是性能优化,但 `valgrind --tool=massif` 会看到堆峰值不降
- 碎片化:频繁 malloc/free 不同大小 → 空间不连续 → 虽然总量够但无法满足大块请求

#### aligned_alloc(C11)——HFT 对齐分配

```c
/* C11 7.22.3.1:按 alignment 对齐分配 size 字节 */
void *aligned_alloc(size_t alignment, size_t size);
/* 约束:alignment 必须是支持的对齐值(通常 2^n),size 必须是 alignment 的整数倍 */

/* DPDK 封装 */
void *rte_malloc(const char *type, size_t size, unsigned align);
```

- HFT 场景:DMA 收发缓冲区要 **4K 页对齐**;共享计数器要 **cache line 对齐(64B)** 避免伪共享
- `posix_memalign()` 是 POSIX 版本,参数顺序不同但功能类似
- 旧代码常见 `malloc + 手动偏移对齐`,又慢又容易错

#### void* 返回值与 C/C++ 巕异

```c
/* C: void* 隐式转换为任意指针类型,不需要强转 */
int *p = malloc(10 * sizeof(int));    /* ✅ C 合法 */

/* C++: void* 不会隐式转换,必须强转 */
int *p = static_cast<int *>(malloc(10 * sizeof(int)));  /* C++ */
```

- C 里写 `(int*)malloc(...)` 不是错误,但**不必要**——且如果忘了 `#include <stdlib.h>`,强转会**掩盖**编译器因缺少原型而产生的隐式 int 警告(C89 遗留坑,C99 起隐式 int 已不合法)

## 与 HFT/DPDK

### hugepage 与 mempool(动态内存的工程化)

- DPDK 不用 `malloc`/`free` 在热路径,而用 **mempool**:启动时从 hugepage 预分配固定大小对象池
- 收包:`rte_mempool_get()` 取一个 mbuf,处理完 `rte_pktmbuf_free()` 归还 —— O(1),无锁(单线程)或无锁队列
- 避免 malloc 在多核下的锁竞争和碎片化 —— 这是 HFT 延迟可控的关键

### 静态配置表用 .bss 清零

```c
/* 嵌入式/DPDK: 大配置数组放 bss 利用清零, 不占镜像 */
static struct device g_devs[MAX_DEV];   /* .bss, 启动时全 0 */
```

- 只读配置改 `static const` 进 `.rodata`,可被多核安全共享

### per-thread 缓存避免伪共享

```c
struct stats {
    uint64_t rx_pkts  __rte_cache_aligned;   /* 缓存行对齐 */
    uint64_t tx_pkts  __rte_cache_aligned;
} __rte_cache_aligned;
static __thread struct stats t_stats;        /* 每核独立 */
```

- 多核场景下,共享计数器在同一个缓存行 → 原子更新触发缓存行乒乓(伪共享),延迟剧增
- 解法:per-thread + 缓存行对齐,见 ch16/ch18

### 栈使用监控

- 多线程栈小(2-8MB),递归或大数组易溢出 → 段错误或不可复现崩溃
- 工具:`valgrind --tool=drd`、`gcc -fstack-protector`、`ulimit -s`

## 常见误区

| 误区 | 真相 |
|------|------|
| 全局 `int g;` 是"未初始化" | 是定义为 0,放 .bss |
| malloc 内存是 0 | 不保证,要 calloc 或 memset |
| 栈对象"销毁"=清零 | 只是栈指针回退,内容残留 |
| static 局部每次重初始化 | 启动前初始化一次(C11 6.2.4p3),后续保留 |
| `_Thread_local` 必须搭配 static/extern | 仅**块作用域**必须;文件作用域可单独用 |
| `static extern int x;` 写一起是 UB | 单条声明两个存储类是**约束违例**(C11 6.7.1p2),编译报错;真正的 UB 是同一 TU 内同一名字先 static 后 extern 声明(C11 6.2.2p7,链接冲突) |
| _Thread_local 自动线程安全 | 是 per-thread 副本,无需锁;但跨线程访问仍需同步 |

## 实操

```bash
# 1. readelf 看段布局
cat > t.c <<'EOF'
int g_init = 1; int g_zero; static int s_init = 2; static int s_zero;
const char *msg = "hi";
int main(void){ int x; return 0; }
EOF
gcc -c t.c && readelf -S t.o | grep -E 'text|rodata|data|bss'
nm t.o | sort        # D=g_init, B=g_zero, d=s_init, b=s_zero, R="hi"

# 2. 栈残留验证
cat > s.c <<'EOF'
#include <stdio.h>
void f(void){ int x; printf("x=%d\n", x); }
int main(void){ f(); f(); return 0; }
EOF
gcc -O0 s.c -o s && ./s    # 两次输出常不同

# 3. thread_local 演示
cat > tl.c <<'EOF'
#include <stdio.h>
#include <threads.h>
static _Thread_local int t = 0;
int run(void *a){ t++; printf("t=%d\n", t); return 0; }
int main(void){ thrd_t a,b; thrd_create(&a,run,0); thrd_create(&b,run,0);
  thrd_join(a,0); thrd_join(b,0); }
EOF
gcc -std=c11 tl.c -o tl -pthread && ./tl   # 两线程都输出 t=1
```

## 代码自测

**题目 1：** 以下变量的存储类型（存储位置和生命周期）分别是什么？
```c
int g;           // (1)
static int s;    // (2)
void f(void) {
    int l;       // (3)
    static int sl; // (4)
}
```

<details>
<summary>参考答案</summary>

(1) 全局变量：静态存储，零初始化，整个程序生命周期。(2) 静态全局：同(1)但内部链接。(3) 局部变量：自动存储（栈），未初始化（值不确定），函数返回时销毁。(4) 静态局部：静态存储，零初始化，整个程序生命周期，但作用域仅限函数内。

</details>

**题目 2：** 以下声明哪一行语法错误？
```c
void demo(void)
{
    static int a;
    auto int b;
    register int c;
    static _Thread_local int d;
}
```

<details>
<summary>参考答案</summary>

**C11/C17 下四行全部合法。**

- a：块内 static，静态存储期，合法
- b：块内 auto 冗余但合法（C23 起 auto 改为类型推导，不能与显式类型同用，这行会编译错误）
- c：合法（C23 起 register 被移除，这行也会编译错误）
- d：合法——块作用域 `_Thread_local` 必须搭配 static/extern，这里带了 static；裸写 `_Thread_local int d;` 才是约束违例

**C23 视角**：b 和 c 两行在 C23 下编译不过（auto 变类型推导、register 被移除），a 和 d 依然合法。

</details>

**题目 3：** 下面这段代码，static 局部 `n` 什么时候被初始化为 5？首次调用 `f()` 时函数体里有没有"把 5 写进 n"的指令？
```c
void f(void) {
    static int n = 5;
    n++;
}
```

<details>
<summary>参考答案</summary>

**程序启动前**初始化，不是首次调用。C11 6.2.4p3：静态存储期对象 "initialized only once, prior to program startup"。C11 6.7.9p4 要求初始化器是常量表达式，所以 5 直接烧进 `.data` 段镜像，加载器 mmap 时就位。函数体里**没有任何初始化指令**——objdump 反汇编只能看到 inc，nm 可以看到 `n` 是 D 类符号带初值。"首次调用时初始化"是 C++ 的动态初始化语义，C 没有这条。

</details>

**题目 5：** 以下代码有什么问题？
```c
int *p = realloc(p, 1024 * sizeof(int));
if (p == NULL) { /* ... */ }
```

<details>
<summary>参考答案</summary>

**`p = realloc(p, ...)` 是经典 bug**。realloc 失败时返回 NULL，但原 p 仍然有效——直接赋值覆盖后，原指针丢失，既无法使用也无法 free → **内存泄漏 + 野指针**。正确写法：
```c
int *tmp = realloc(p, 1024 * sizeof(int));
if (tmp) p = tmp;
else { /* 原 p 仍有效，可继续用或 free(p) */ }
```

**题目 6：** `char *buf = calloc(5, sizeof(char));` 之后 `buf[0]`~`buf[4]` 的值是什么？为什么说 `calloc(n, size)` 比 `malloc(n * size)` 更安全？

<details>
<summary>参考答案</summary>

`buf[0]`~`buf[4]` 全部是 0——calloc 分配后整块清零。

安全差异：calloc 两个参数分开传，内部在执行 `nmemb * size` 乘法**之前**检查溢出（C11 7.22.3.2）；而 `malloc(n * size)` 由调用者自己算乘积，`n` 来自外部输入时 `n * size` 可能整数溢出到一个小值 → malloc 分配小缓冲 → 后续按 `n` 个元素写入 → 堆溢出。这是 CVE 常见模式，不是"部分平台的优化"。

</details>
```c
int v1;
void f(void) {
    int v2;
    static int v3;
}
```

<details>
<summary>参考答案</summary>

- v1：文件域，无存储类说明符 → **外部链接 + 静态存储期**，是**暂定定义**（注意：不是"隐式 extern"——extern 是声明，这个是定义，两个 TU 各写一份会 multiple definition）
- v2：块内默认 auto，自动存储期（栈），无链接
- v3：显式 static，静态存储期 + 无链接，作用域仍限块内
- `void foo(auto int arg)` **编译不过**：形参声明里唯一允许的存储类是 `register`（C11 6.7.6.3 约束），写 `auto`/`static`/`extern` 都是约束违例。形参有自动存储期是**语义**，不代表能写 `auto` 关键字。

</details>
