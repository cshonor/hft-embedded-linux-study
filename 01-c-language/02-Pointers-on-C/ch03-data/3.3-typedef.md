# 3.3 typedef

## 本节讲什么

`typedef` 给**已有类型**起新名字,**不创建新类型**。它是 C 跨平台、定宽、可读、可移植的基石 —— `<stdint.h>` 的 `uint8_t/uint64_t`、DPDK 的 `rte_mbuf`、Linux 内核的 `size_t/ssize_t/pid_t` 全部建立在 typedef 之上。本节讲它的语义、与 `#define`/`enum` 的边界、读复杂声明时它如何救命。

## 要点

### 基本语法

```c
typedef unsigned char  uint8_t;          /* 定宽类型 */
typedef unsigned long long uint64_t;
typedef struct rte_mbuf rte_mbuf_t;      /* 结构体别名, 可省 struct 关键字 */
typedef int (*cmp_fn)(const void*, const void*);  /* 函数指针别名 */
```

- 语法上 typedef 像"加一个名字的变量声明":把变量名换成类型别名
- **不是文本替换**(区别 `#define`):typedef 受类型检查、有作用域、不能跨编译单元被宏展开破坏

### 为什么用 typedef

| 价值 | 说明 | 例子 |
|------|------|------|
| **定长** | 避免 `long`/`int` 在 ILP32/LLP64/LP64 宽度不一 | `uint32_t` 永远 32 位 |
| **可读** | 复杂类型一行看懂 | `cmp_fn` 比 `int(*)(const void*,const void*)` 清晰 |
| **可移植** | 平台换类型不改源码 | `size_t` 在 32/64 位分别是 4/8 |
| **封装** | 改底层类型只动 typedef | `typedef int_fast16_t fast16;` |

### 与 `#define` 区别(常考点)

```c
#define  WORD unsigned int
typedef unsigned int WORD;     /* 等价于此行 */
```

| 维度 | `#define` | `typedef` |
|------|-----------|-----------|
| 处理阶段 | 预处理,文本替换 | 编译期,符号进类型系统 |
| 类型检查 | 无 | 有,可触发诊断 |
| 作用域 | 无,文件级 | 遵守作用域(可在块内) |
| 复杂类型 | 易错(指针组合难) | 准确(函数指针/数组指针) |
| 调试可见 | 替换后看不到原名 | 调试器/错误信息常保留原名 |

经典反例(指针):

```c
#define PINT int*
PINT a, b;        /* 替换后: int *a, b; —— b 是 int 不是指针! */
typedef int* PintT;
PintT c, d;       /* c 和 d 都是 int* */
```

### 与 enum / struct 配合

```c
typedef enum { PKT_ORDER=0, PKT_QUOTE, PKT_HEARTBEAT } pkt_type_t;
typedef struct rte_mbuf { /* ... */ } rte_mbuf_t;
```

- C 时代习惯加 `_t` 后缀;POSIX 保留 `_t` 给实现,Linux/DPDK 大量使用 `_t`(争议存在,但事实如此)
- struct 自带"省 struct 关键字"的副作用,typedef 后 `rte_mbuf_t m;` 比 `struct rte_mbuf m;` 短

## 与 HFT/DPDK

### `<stdint.h>` 定宽类型

```c
uint8_t  b;       /* 报文字节 */
uint16_t len;     /* 报文长度字段 */
uint32_t seq;     /* 序号 */
int32_t  price;   /* 定点价格, 4 位小数 */
```

| 类型 | 用途 | 注意 |
|------|------|------|
| `intN_t` | 定宽精确宽度 N | 协议字段、寄存器 |
| `uintN_t` | 无符号定宽 | 字节、掩码 |
| `int_leastN_t` | 至少 N 位 | 可移植算法 |
| `int_fastN_t` | 至少 N 位但更快 | 循环计数器常用 `size_t`/`int_fast32_t` |
| `intptr_t` | 存指针的整数 | 把指针转整数运算 |
| `intmax_t` | 最大宽度 | printf 调试 |

- HFT 价格**绝不用 float**,用 `int64_t` 定点(如 1e-7 精度),避免 IEEE 754 误差和舍入分歧

### 函数指针类型别名(回调签名规范化)

```c
typedef void (*pkt_cb)(const uint8_t *pkt, size_t len, void *user);
static pkt_cb g_handler;
void on_packet(pkt_cb cb){ g_handler = cb; }
```

- DPDK ethdev 的 `rte_eth_rx_callback_fn`、信号处理的 `sighandler_t` 都是这种 typedef
- 用 typedef 后函数指针数组声明从天书变成可读

### 读复杂声明的螺旋法则(预告)

```c
int (*signal(int, void(*)(int)))(int);
```

- 不用 typedef 几乎读不出"signal 是函数,接受(int, 函数指针),返回函数指针"
- 用 typedef 拆解:

```c
typedef void (*handler_t)(int);
typedef handler_t (*signal_fn)(int, handler_t);
signal_fn my_signal = signal;
```

可读性天差地别 —— 这是 ch13 函数指针与复杂声明专题的入口。

## 常见误区

| 误区 | 真相 |
|------|------|
| typedef 创建新类型 | 不,是已有类型的别名;类型检查按底层走 |
| typedef 和 #define 等价 | 不;宏是文本替换,无类型检查无作用域 |
| `typedef int* P; P a,b;` 中 b 是 int | 不,typedef 后 a、b 都是 int* |
| `_t` 后缀是标准强制 | 不是;POSIX 保留,用户 typedef 也常用,有争议但事实 |
| typedef 能前向声明结构 | typedef 不能凭空造类型,要先有 struct 定义 |

## 实操

```bash
cat > t.c <<'EOF'
#include <stdint.h>
#include <stdio.h>
typedef int (*cmp_fn)(const void*, const void*);
static int int_cmp(const void*a,const void*b){
  return *(const int*)a - *(const int*)b;
}
int main(void){
  cmp_fn f = int_cmp;
  int x=3,y=5;
  printf("%d\n", f(&x,&y));
  printf("size uint64=%zu intptr=%zu\n",
         sizeof(uint64_t), sizeof(intptr_t));
}
EOF
gcc t.c -o t && ./t
nm t | grep -i cmp     # 看符号

# 看 stdint.h 怎么 typedef 各平台
grep -E 'typedef.*uint32_t' /usr/include/stdint.h
```
