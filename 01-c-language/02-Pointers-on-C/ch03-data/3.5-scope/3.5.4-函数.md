# 3.5.4 函数

## 本节讲什么

**函数作用域(function scope)** 是 C 四种作用域里最特殊的一种:它**只用于 label**(goto 目标),且整个函数体内有效,与块作用域规则无关。本节短,但讲清"label 作用域""goto 的合理使用""Linux `goto out` 错误处理模式"这几个工程点。

## 要点

### 函数作用域只给 label

```c
void f(void) {
    goto end;              /* 前向跳转, 合法 —— end 在整个函数内有效 */
    /* ... */
end:                       /* label: 函数作用域, 可被前面 goto 命中 */
    ;
}
```

- C 的 label 是**函数作用域**:整个函数体内可见,可前向/后向跳转
- 这是 C 唯一一个"函数作用域"用途 —— 注意:**函数名本身不是函数作用域**,函数名是文件作用域(或块作用域)
- label 与变量名**不共享命名空间**:同一作用域内可同时有变量 `x` 和 label `x`(但混淆,别这么写)

### label 与命名空间

```c
void f(void){
    int x = 1;
  x:                       /* label x, 与变量 x 不同命名空间, 合法但极糟 */
    x++;
    goto x;                /* 死循环, 但合法 */
}
```

- C 有四类命名空间:① label(函数作用域)② 标签/struct/union/enum(tag)③ 成员名(每结构体内)④ 普通标识符(变量/函数/typedef)
- label 与变量同名合法,但工程规范禁止,可读性灾难

### goto 的合理使用

```c
/* 反例: 滥用 goto 制造意大利面 */
void spaghetti(void){
    if (a) goto L1;
    if (b) goto L2;
L1: ...
L2: ...
}

/* 合理: 错误处理 + 资源清理 */
int open_resources(void){
    int *a = malloc(100); if (!a) goto out_a;
    int *b = malloc(200); if (!b) goto out_b;
    int *c = malloc(300); if (!c) goto out_c;
    /* 正常路径 */
    return 0;
out_c:  free(b);
out_b:  free(a);
out_a:  return -1;
}
```

- **Linux 内核 `goto out` 模式**:多步资源申请,任一失败就跳到对应清理点,顺序释放
- 这是 goto 在现代 C 代码里**最被接受**的用法,内核 checkpatch 反而鼓励这种结构化错误处理
- 比多层嵌套 `if` 更扁平、比提前 `return` 多次重复清理代码更干净

## 与 HFT/DPDK

### Linux 驱动的 `goto out` 惯用法

```c
/* 内核驱动初始化函数典型结构 */
static int probe(struct pci_dev *pdev){
    int err;
    err = pci_enable_device(pdev);             if (err) goto out;
    err = pci_request_regions(pdev, "mydrv");   if (err) goto out_disable;
    void *base = pci_ioremap_bar(pdev, 0);     if (!base){ err=-ENOMEM; goto out_release; }
    /* ... */
    return 0;
out_release:  pci_release_regions(pdev);
out_disable: pci_disable_device(pdev);
out:         return err;
}
```

- 失败路径"逆序释放":每个 `out_xxx` 对应一个已申请的资源
- 资源越多越体现 goto 优势,避免 if 嵌套金字塔

### goto 跳出多重循环

```c
for (i=0;i<N;i++)
    for (j=0;j<M;j++)
        if (match(a[i][j])) goto found;
/* 未找到 */
return -1;
found:
    /* 处理找到的元素 */
    return 0;
```

- 跳出多重循环是 goto 另一个合理场景,比用 flag 控制两层 break 更清晰
- C 没有 `break N;`(Java 有),goto 是规范做法

### HFT 收包循环里的 goto

```c
while (true) {
    nb = rx_burst(port, q, pkts, 32);
    for (i=0;i<nb;i++){
        if (filter(pkts[i])) goto tx;
        free_mbuf(pkts[i]);
    }
tx:
    if (nb) tx_burst(port, q, pkts, i);
}
```

- 收包热循环里偶尔用 goto 提前跳出,避免多一层 flag 判定
- 别滥用,循环逻辑复杂时优先拆函数

## 常见误区

| 误区 | 真相 |
|------|------|
| goto 是"邪恶的",一律禁用 | 不,Linux 内核鼓励 `goto out` 做错误处理 |
| label 与变量名重名报错 | 不,不同命名空间;但工程禁止 |
| label 只能在声明后跳 | 不,函数作用域,可前向跳转 |
| goto 能跳出函数 | 不能,只能函数内 |
| 函数名是函数作用域 | 不,函数名是文件/块作用域,函数作用域只给 label |

## 实操

```bash
cat > t.c <<'EOF'
#include <stdio.h>
#include <stdlib.h>
int alloc_chain(void){
  int *a = malloc(8);  if(!a) goto out_a;
  int *b = malloc(8);  if(!b) goto out_b;
  int *c = malloc(8);  if(!c) goto out_c;
  printf("all ok\n");
  free(c); free(b); free(a); return 0;
out_c: free(b);
out_b: free(a);
out_a: printf("alloc failed\n"); return -1;
}
int main(void){ return alloc_chain(); }
EOF
gcc -std=c11 -Wall t.c -o t && ./t
```

## 代码自测

**题目 1：** 以下代码中 x 的作用域到哪里结束？
```c
int f(int x) {
    return x * 2;
}
// 此处还能访问 x 吗？
```

<details>
<summary>参考答案</summary>

x 的作用域到函数 f 的右花括号结束。函数参数的作用域是整个函数体。出了函数体，x 就不存在了。函数返回后，x 占用的栈空间被回收（但值可能还在内存中——这就是为什么返回局部变量地址是 UB）。

</details>
