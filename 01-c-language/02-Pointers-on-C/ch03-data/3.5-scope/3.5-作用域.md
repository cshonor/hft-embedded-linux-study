# 3.5 作用域

## 本节讲什么

**作用域(scope)** 决定"标识符在哪段源代码里可见"。它和**存储期**(活多久,3.7)、**链接**(能否跨翻译单元,3.6)是三个独立维度,合起来决定一个对象的完整生命周期。本节是作用域总览,四个小节分别讲 C 的四种作用域:代码块、文件、原型、函数。ch02 已入门,本章从**数据对象**视角细化。

## 要点

### C 的四种作用域

| 作用域 | 起止 | 典型对象 | 详见 |
|--------|------|----------|------|
| **块作用域**(block) | 声明点到所在 `{}` 结束 | auto 局部、`for(int i...)` 的 i | 3.5.1 |
| **文件作用域**(file) | 声明点到文件末尾 | 全局变量、static 文件级、函数定义 | 3.5.2 |
| **函数原型作用域** | 原型参数列表内 | 函数原型参数名(可省) | 3.5.3 |
| **函数作用域** | 整个函数体 | **仅 label**(goto 目标) | 3.5.4 |

> 注意:**函数作用域**只给 label,不给函数名。函数名是文件作用域(或块作用域,块内声明)。

### 三轴独立(关键认知)

```
                  存储期(活多久)       链接(能否跨文件)      作用域(在哪可见)
auto 局部          自动                  无                    块
static 局部        静态(.bss/.data)    无                    块  ← 仅作用域限块
全局                静态                  外部                  文件(可用 extern 扩到别文件)
static 全局        静态                  内部                  文件  ← 仅链接变内部
```

- **块作用域 + 静态存储期**(static 局部)是最易混:可见性限块内,但生命周期到程序结束
- **作用域 ≠ 存储期**:这是 C 入门最易踩的认知坑,3.7 / 3.8 会再强调

### 遮蔽(shadowing)

```c
int x = 1;
void f(void) {
    int x = 2;          /* 内层 x 遮蔽外层 x, 内核规范常禁止 */
    {
        int x = 3;      /* 再遮蔽, 嵌套同名 */
        /* 这里 x = 3 */
    }
    /* 这里 x = 2 */
}
```

- 内层同名标识符遮蔽外层,合法但**易错** —— Linux 内核 checkpatch 把 shadow 警告标为 style 问题
- `-Wshadow` 可开,HFT/嵌入式常升 `-Werror=shadow`

### C99 起的声明位置放宽

```c
void f(void) {
    for (int i = 0; i < 10; i++) {  /* for 内声明, C99 起 */
        int v = compute(i);          /* 任意位置声明 */
    }
}
```

- C89 要求所有声明在块首;C99 起可"用到才声明",更接近"最小作用域"原则
- 工程规范:**变量声明尽量靠近首次使用**,作用域越小越安全

## 与 HFT/DPDK

### 文件作用域 + static 实现模块私有

```c
/* foo.c */
static rte_spinlock_t g_lock;        /* 文件作用域, 内部链接, 其他 .c 看不到 */
static int helper(void){ ... }       /* 模块私有函数 */

/* foo.h */
void foo_api(void);                  /* 公共 API, 外部链接 */
```

- 模块化靠 static 隐藏实现细节,只暴露头文件声明的 API
- DPDK/内核大量使用这种"对象式"封装(虽然 C 没有类)

### 块作用域缩小变量可见性

```c
int parse(const uint8_t *pkt, size_t len) {
    if (len < 8) return -1;
    uint16_t type = pkt[0] << 8 | pkt[1];   /* 仅此处用 */
    if (type == ORDER) {
        int64_t price = read_int64(pkt+2);  /* 仅本块用 */
        /* ... */
    }
    /* type 仍可见, price 不可见 —— 缩小 price 误用范围 */
}
```

- 作用域越小,误用、并发修改、维护误改的概率越低

### 原型作用域影响 API 风格

```c
void parse(const uint8_t *buf, size_t len);   /* 参数名 buf, len 是文档 */
void parse(const uint8_t *, size_t);           /* 省略参数名也合法 */
```

- HFT/驱动头文件常**保留参数名**作文档,因为类型名(uint8_t/size_t)不足以表达语义

## 常见误区

| 误区 | 真相 |
|------|------|
| static 局部只在块内可见所以是 auto | 错;static 改存储期不改作用域,块内静态 |
| 全局变量所有 .c 都能见 | 不;要 extern 声明,且 static 全局只本文件见 |
| 内层同名变量合法就行 | 合法但易错,Linux 规范禁止 |
| for(int i...) 的 i 在函数全局见 | C99 起作用域限 for 语句内 |
| 函数作用域给函数名 | 不,只给 label |

## 实操

```bash
cat > t.c <<'EOF'
#include <stdio.h>
int x = 1;
static int s = 10;          /* 文件作用域, 内部链接 */
void f(void){
  int x = 2;                 /* 遮蔽全局 */
  for (int i=0;i<1;i++){ int x=3; printf("%d\n",x); }
  printf("%d\n", x);
}
void g(void){ static int n=0; printf("n=%d\n", ++n); }  /* 静态局部 */
int main(void){ f(); g(); g(); return 0; }
EOF
gcc -std=c11 -Wall -Wshadow t.c -o t && ./t   # 3, 2, n=1, n=2
nm t | grep -E ' x| s '                       # 看符号
```

## 代码自测

**题目 1：** 以下代码输出什么？为什么？
```c
int x = 1;
int main(void) {
    int x = 2;
    {
        int x = 3;
        printf("%d\n", x);
    }
    printf("%d\n", x);
}
```

<details>
<summary>参考答案</summary>

输出 3 和 2。内层代码块声明了新的 x = 3，遮蔽了外层的 x = 2。离开内层块后，x 恢复为外层的 2。文件作用域的 x = 1 始终被局部 x 遮蔽。

</details>
