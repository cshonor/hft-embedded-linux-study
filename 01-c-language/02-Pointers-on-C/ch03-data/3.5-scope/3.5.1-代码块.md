# 3.5.1 代码块

## 本节讲什么

**块作用域(block scope)**:在 `{}` 内声明的标识符,仅该块(含嵌套子块)可见。这是 C 里最常用、也最该优先使用的作用域 —— 块结束,auto 对象销毁,可见性消失,误用面自然缩小。本节讲块的边界、嵌套遮蔽、C99 声明位置放宽、栈帧关系。

## 要点

### 块的边界

```c
void f(void) {
    int x = 1;                 /* 块开始 */
    if (x) {
        int y = 2;             /* 子块开始 */
        /* x, y 可见 */
    }                          /* y 销毁 */
    /* x 可见, y 不可见 */
}                              /* x 销毁 */
```

- 块 = `{` 与 `}` 之间的语句组,可嵌套
- `if`/`else`/`for`/`while`/`switch` 子句即使一条语句,加 `{}` 也成块
- 块内声明的标识符:从声明点到所在 `}` 结束可见

### 嵌套遮蔽

```c
int x = 1;
void f(void){
    int x = 2;             /* 遮蔽外层 */
    {
        int x = 3;          /* 再遮蔽 */
        printf("%d", x);    /* 3 */
    }
    printf("%d", x);        /* 2 */
}
```

- 合法但**易错**,读代码时混淆
- `-Wshadow` 警告,Linux checkpatch 也禁

### C99:声明位置放宽

```c
/* C89: 声明必须在块首 */
void f89(void) {
    int a, b;
    a = 1;
    b = 2;
    /* 不能在这里 int c */
}

/* C99+: 任意位置声明 */
void f99(void) {
    int a = 1;
    /* 可有语句 */
    int b = compute(a);    /* 用到才声明 */
    for (int i=0; i<b; i++) {  /* for 内声明 */
        /* i 仅本循环可见 */
    }
}
```

- 现代工程统一 C99+,鼓励"声明靠近首次使用"
- 好处:作用域最小化、初值即声明(免未初始化)、读代码时类型信息就近

### 块结束 = auto 销毁

```c
void f(void) {
    int arr[100];          /* 栈帧扩展 */
    /* ... */
}                          /* arr 所占栈空间"释放"(逻辑上), 下次调用复用 */
```

- "释放"是逻辑语义:栈指针回退,内存内容仍存在,直到下次被覆盖
- 这就是"返回局部变量地址"是 UB 的根因:内存可能还在,但下次调用会覆盖

### 块内 static(重点:两轴独立,HFT/内核高频考点)

**核心认知:作用域(看得见)和生命周期(活多久)是两套完全独立的概念。**

```c
void f(void) {
    static int n = 0;     /* 作用域: 块(仅 f 内可见);存储期: 静态(.bss/.data, 程序结束才销) */
    n++;                  /* 跨调用累加 */
}
/* 第 1 次调用: n=0 → 1;第 2 次调用: 不重新初始化, 1 → 2 */
```

对比普通 auto 局部:

| | `static int n = 0;` | `int n = 0;`(auto) |
|---|---|---|
| 可见性 | 块内(f 里) | 块内(f 里)——两轴里作用域轴**完全一样** |
| 存放位置 | 全局数据段(.bss/.data),不在栈上 | 当前栈帧 |
| 生命周期 | 程序启动 → 程序结束 | 进函数 → 出函数 |
| 跨调用保值 | ✅ 保留上次值 | ❌ 每次重新初始化 |

**初始化时机的精确版(常见误解:"第一次调用时初始化")**

- 真相:static 存储期对象在**程序启动之前**就完成初始化(C11 §6.2.4p3),加载器把初值直接放进镜像——不是"第一次调用 f 时执行 n=0"
- 推论 1:**初始化必须是编译期常量表达式**,`static int n = compute();` 编译报错
- 推论 2:**多线程无初始化竞争**——值在所有线程跑起来之前就躺在 .bss/.data 里,不存在"两个线程同时首次调用"的 race
- 这两点是 C 与 C++ 的真实差异:C++ 的 function-local static 支持运行期初值+惰性初始化(代价是编译器插线程安全 guard),C 没有
- 落点:`= 0` 进 **.bss**(零初始化,不占可执行文件体积),`= 1` 进 **.data**,`objdump -h` / `size` 一看便知

**线程安全注意**

块内 static 是全局数据段上的**单一共享对象**,多线程不加锁直接读写 = 数据竞争。HFT 热路径多线程场景:要么加锁/原子,要么改 `_Thread_local`(每线程一份,3.7.3 讲 TLS 开销)。

- 这是"函数级单例"惯用法,3.8 展开双语义

## 与 HFT/DPDK

### 栈帧大小与块内大数组

```c
void bad(void) {
    uint8_t ring[1<<24];      /* 16MB > 8MB 默认栈,一进来就爆 */
}
void good(void) {
    static uint8_t ring[1<<24];   /* 改 .bss, 不占栈 —— 但全进程共享, 非线程安全 */
    /* 或: 从 dpdk mempool 取(HFT 业务优先) */
}
```

**数字要对得上**:主线程默认栈 8MB(`ulimit -s` 可查),单个 1MB 数组**并不会**爆——真正爆栈的常见形态:

- **线程栈比主栈小**:`pthread_attr_setstacksize` 设小了(DPDK lcore/自建 worker 常见 256KB~2MB),此时 1MB 数组真的爆
- **多个局部大缓冲叠加** + 无人看 `-fstack-usage` 报告
- **深递归**:每层帧不大,层数乘出来爆

崩溃特征:dmesg 里 SIGSEGV 地址紧贴栈底 guard page。大缓冲用 mempool / 堆 / hugepage,不放栈。

### for 内声明让循环变量作用域最小

```c
for (uint32_t i = 0; i < nb_pkts; i++) {
    struct rte_mbuf *m = pkts[i];
    /* i, m 仅本循环可见 */
}
/* 循环外用 i 是错误 —— 防止循环泄漏变量 */
```

### 临时变量压栈栈帧

- 每进入一个块,栈指针可能下移为局部变量腾空间;退出时上移
- `alloca(size)` 是手动在当前栈帧分配,函数返回自动释放 —— 灵活但溢出风险高

## 常见误区

| 误区 | 真相 |
|------|------|
| for 里的 i 循环外还可见 | C99 起仅 for 内可见 |
| 块结束内存被清零 | 只是栈指针回退,内容残留 |
| 返回块内局部地址安全 | UB,下次调用覆盖 |
| 块内 static 每次调用重新初始化 | 不;程序启动前初始化一次,后续调用直接用上次的值 |
| 块内 static 第一次调用时才初始化 | 不;启动前就初始化完毕(C11 §6.2.4p3),所以初值必须是常量表达式,且多线程无初始化 race |
| 加 `{}` 括号影响性能 | 不影响;现代编译器优化掉冗余块 |

## 实操

```bash
cat > t.c <<'EOF'
#include <stdio.h>
#include <stdint.h>
void f(void){
  int x=1;
  { int x=2; printf("inner %d\n", x); }   /* 遮蔽 */
  printf("outer %d\n", x);
}
int *bad(void){ int x=42; return &x; }    /* UB: 返回局部地址 */
int main(void){
  f();
  int *p = bad();
  printf("dangling %d\n", *p);             /* 可能 42, 可能被覆盖 */
  return 0;
}
EOF
gcc -std=c11 -Wall -Wshadow t.c -o t && ./t
# 看栈复用: 多次调用 bad 后 *p 可能变
```

## 代码自测

**题目 1：** 以下代码合法吗？
```c
for (int i = 0; i < 3; i++) {
    int i = 10;
    printf("%d\n", i);
}
```

<details>
<summary>参考答案</summary>

合法但容易混淆。C99 允许在 for 的初始化部分声明变量，其作用域是整个 for 循环体。循环体内的 int i = 10 声明了一个新的 i，遮蔽了循环变量。每次循环都打印 10，循环变量 i 不受影响。

</details>

**题目 2：** 以下代码连续调用两次 `test()`，a 最终等于多少？
```c
void test(void) {
    static int a = 1;
    a++;
}
```

<details>
<summary>参考答案</summary>

a = 3。`a = 1` 的初始化发生在程序启动之前（加载进 .data 段），不在任何一次调用里执行；两次调用各执行一次 a++，1 → 2 → 3。对比：若去掉 static（auto 局部），每次进函数都重新执行 a=1，两次调用后 a 的最终有效值仍是 2（且两次互不相干）。顺带一问：`static int a = compute();` 合法吗？——不合法，static 存储期初值必须是编译期常量表达式。

</details>
