# 3.5.1 代码块

## 本节讲什么

**块作用域(block scope)**:在 `{}` 内声明的标识符,仅该块(含嵌套子块)可见。这是 C 里最常用、也最该优先使用的作用域 —— 块结束,auto 对象销毁,可见性消失,误用面自然缩小。本节讲块的边界、嵌套遮蔽、C99 声明位置放宽、栈帧关系。

## 要点

### 块的边界

```c
void f(void) {
    int x = 1;                 /* 块开始 */
    if (x) {
        int y = 2;             /* 子块开始 */
        /* x, y 可见 */
    }                          /* y 销毁 */
    /* x 可见, y 不可见 */
}                              /* x 销毁 */
```

- 块 = `{` 与 `}` 之间的语句组,可嵌套
- `if`/`else`/`for`/`while`/`switch` 子句即使一条语句,加 `{}` 也成块
- 块内声明的标识符:从声明点到所在 `}` 结束可见

### 嵌套遮蔽

```c
int x = 1;
void f(void){
    int x = 2;             /* 遮蔽外层 */
    {
        int x = 3;          /* 再遮蔽 */
        printf("%d", x);    /* 3 */
    }
    printf("%d", x);        /* 2 */
}
```

- 合法但**易错**,读代码时混淆
- `-Wshadow` 警告,Linux checkpatch 也禁

### C99:声明位置放宽

```c
/* C89: 声明必须在块首 */
void f89(void) {
    int a, b;
    a = 1;
    b = 2;
    /* 不能在这里 int c */
}

/* C99+: 任意位置声明 */
void f99(void) {
    int a = 1;
    /* 可有语句 */
    int b = compute(a);    /* 用到才声明 */
    for (int i=0; i<b; i++) {  /* for 内声明 */
        /* i 仅本循环可见 */
    }
}
```

- 现代工程统一 C99+,鼓励"声明靠近首次使用"
- 好处:作用域最小化、初值即声明(免未初始化)、读代码时类型信息就近

### 块结束 = auto 销毁

```c
void f(void) {
    int arr[100];          /* 栈帧扩展 */
    /* ... */
}                          /* arr 所占栈空间"释放"(逻辑上), 下次调用复用 */
```

- "释放"是逻辑语义:栈指针回退,内存内容仍存在,直到下次被覆盖
- 这就是"返回局部变量地址"是 UB 的根因:内存可能还在,但下次调用会覆盖

### 块内 static(双轴特例)

```c
void f(void) {
    static int n = 0;     /* 块作用域 + 静态存储期 */
    n++;                  /* 跨调用累加 */
}
```

- 可见性限块(只有 f 内能写 n),但生命周期到程序结束
- 这是"函数级单例"惯用法,3.8 展开

## 与 HFT/DPDK

### 栈帧大小与块内大数组

```c
void bad(void) {
    uint8_t ring[1<<20];     /* 1MB 在栈, 多线程栈小则溢出 */
}
void good(void) {
    static uint8_t ring[1<<20];  /* 改 .bss, 不占栈 —— 但非可重入 */
    /* 或: 从 mempool 取 */
}
```

- 线程栈:Linux 默认 8MB,某些嵌入式 4KB-32KB,Python 子线程 2MB
- 大缓冲用 mempool / 堆 / hugepage,不放栈

### for 内声明让循环变量作用域最小

```c
for (uint32_t i = 0; i < nb_pkts; i++) {
    struct rte_mbuf *m = pkts[i];
    /* i, m 仅本循环可见 */
}
/* 循环外用 i 是错误 —— 防止循环泄漏变量 */
```

### 临时变量压栈栈帧

- 每进入一个块,栈指针可能下移为局部变量腾空间;退出时上移
- `alloca(size)` 是手动在当前栈帧分配,函数返回自动释放 —— 灵活但溢出风险高

## 常见误区

| 误区 | 真相 |
|------|------|
| for 里的 i 循环外还可见 | C99 起仅 for 内可见 |
| 块结束内存被清零 | 只是栈指针回退,内容残留 |
| 返回块内局部地址安全 | UB,下次调用覆盖 |
| 块内 static 每次重新初始化 | 只首次,后续保留值 |
| 加 `{}` 括号影响性能 | 不影响;现代编译器优化掉冗余块 |

## 实操

```bash
cat > t.c <<'EOF'
#include <stdio.h>
#include <stdint.h>
void f(void){
  int x=1;
  { int x=2; printf("inner %d\n", x); }   /* 遮蔽 */
  printf("outer %d\n", x);
}
int *bad(void){ int x=42; return &x; }    /* UB: 返回局部地址 */
int main(void){
  f();
  int *p = bad();
  printf("dangling %d\n", *p);             /* 可能 42, 可能被覆盖 */
  return 0;
}
EOF
gcc -std=c11 -Wall -Wshadow t.c -o t && ./t
# 看栈复用: 多次调用 bad 后 *p 可能变
```

## 代码自测

**题目 1：** 以下代码合法吗？
```c
for (int i = 0; i < 3; i++) {
    int i = 10;
    printf("%d\n", i);
}
```

<details>
<summary>参考答案</summary>

合法但容易混淆。C99 允许在 for 的初始化部分声明变量，其作用域是整个 for 循环体。循环体内的 int i = 10 声明了一个新的 i，遮蔽了循环变量。每次循环都打印 10，循环变量 i 不受影响。

</details>
