# 3.4 常量

## 本节讲什么

"常量"在 C 里有两层:**字面量**(整型、浮点、字符、字符串、枚举)和 **const 对象**(只读变量,可进 `.rodata`)。本节把各类字面量、转义、字符串拼接、`enum`、`const` 对象的底层段布局讲透 —— 这些是写协议解析、寄存器掩码、配置表的日常。

## 要点

### 术语辨析:"常量"的标准名 vs 教材名

国内教材把"值不变的东西"统称常量,再分字面量和 const 常变量——这是**考试口径**,不是标准口径。标准术语的历史演变:

| 标准 | 官方叫法 | 出处 |
|------|----------|------|
| C89–C17 | **constant**(integer/character/floating constant) | §6.4.4 |
| C23 | 改名 **literal**(integer/character literal...) | §6.4.4 |

两个细节:

- "字面量(literal)"反而是 **C23 才有的官方词**——之前标准写的全是 constant。中文教材的"常量"是老标准 constant 的直译,再把 const 变量塞进同一个词,混淆由此而来
- **字符串字面量从来不在 §6.4.4**:它在 §6.4.5 "string literals",从 C89 起就叫 literal。C11 时代 "'A' 是 constant、\"abc\" 是 literal" 两术语并存,C23 统一为 literal

> 判别"它是不是常量"的最硬测试:`static int arr[N];`(文件域数组长度)。编译过 = N 是编译期常量。`#define`/enum/字面量过,`const int N` 编译错误——C 的 const 不是 C++ 的 const,这是两语言最著名分歧之一。

### 整型常量

| 进制 | 写法 | 用途 |
|------|------|------|
| 十进制 | `123` | 普通数值 |
| 八进制 | `0123` (= 83) | **易错**,C 没单独前缀,leading 0 即八进制 |
| 十六进制 | `0x1F` / `0X1F` | 寄存器地址、掩码、报文字段 |
| 二进制(C23) | `0b1010` | 位字段掩码(早期靠 `0b` GCC 扩展) |

**后缀**(控制类型):

| 后缀 | 类型 |
|------|------|
| 无 | 十进制:`int`/`long`/`long long` 取最小容纳 |
| `U`/`u` | 无符号版 |
| `L`/`l` | 至少 `long` |
| `LL`/`ll` | 至少 `long long` |
| `ULL` | `unsigned long long` |

> 命名常量优先**大写 + 后缀齐全**:`0xFFFFFFFFUL`、`1000ULL`,避免窄类型隐式转换。

### 字符与转义

```c
'A'      /* int, 字符常量是 int 不是 char */
'\n'     /* 换行 */
'\0'     /* 空字节 */
'\x0F'   /* 16 进制转义, 任意字节 */
'\101'   /* 8 进制转义, = 'A' */
```

| 转义 | 含义 |
|------|------|
| `\n \t \r` | 换行/制表/回车 |
| `\\ \' \"` | 字面 \ ' " |
| `\0` | NUL,字符串终止符 |
| `\xHH` | 任意 16 进制字节,**报文字节常量** |
| `\OOO` | 8 进制字节 |

- 字符常量类型在 C 是 `int`(C++ 是 `char`),`sizeof('A')` 在 C 得 4
- 报文字节:`uint8_t magic[] = {'T','I','C','\x01'};` 比裸数字可读

**为什么 `'\n'` "不是两个符号"——追到翻译阶段(translation phases)**

- **Phase 3**(分词):`'\n'` 被切成**一个**预处理 token。词法分析器看到 `'` 就进入字符常量模式,读到配对 `'` 才结束——`\` 和 `n` 从未作为独立符号存在过
- **Phase 5**(pp-token → token):转义序列求值,`'\n'` 变成值 10 的 `int`

所以准确说法不是"编译后变成 1 字节",是**分词阶段它就是不可分割的一个 token**。这也是为什么 `'\x0F'` 是单个转义,而字符串里 `"abc\` 后跟断行会直接报 lexer 错误。

字面量 vs const 变量的本质区别:**字面量没有内存对象**,是编译期直接嵌进指令的立即数(`&'\t'` 直接编译错误);**const 变量有地址**,运行期存在(`&c` 合法)。

### 字符串常量

```c
"abc"               /* .rodata, 只读, 含 '\0' */
"hello" "world"     /* 编译期拼接 → "helloworld" */
sizeof("abc")       /* == 4(含 '\0') */
strlen("abc")       /* == 3(不含 '\0') */
```

- **拼接特性**常用于多行宏、长字符串断行:

```c
const char *help =
    "Usage: prog [-p port] [-v]\n"
    "  -p  监听端口\n"
    "  -v  详细输出\n";
```

- **修改字符串常量内容 = UB**:可能 SIGSEGV(放 `.rodata` 的平台),可能"恰好工作"(某些嵌入式放可写 RAM)

### 浮点常量

```c
3.14       /* double */
1e-6       /* double, 科学计数 */
3.14f      /* float */
3.14L      /* long double */
NAN        /* 需 <math.h> */
INFINITY   /* 需 <math.h> */
```

- 默认 `double`,加 `f` 才是 `float`;HFT 内部不用浮点存价格,但概率/统计可能用到

### enum

```c
enum pkt_type {
    PKT_ORDER    = 0,
    PKT_QUOTE,                /* 1 */
    PKT_HEARTBEAT,            /* 2 */
    PKT_CANCEL    = 0x10,     /* 可跳号 */
    PKT_ACK                    /* 0x11 */
};
enum pkt_type t = PKT_QUOTE;
```

- 编译期整型常量;底层类型通常是 `int`(C23 起可指定底层类型)
- 默认从 0 递增,可显式赋值跳号
- **优于 `#define`** 之处:① 调试器可见名字 ② 有作用域 ③ 可被 switch 检查完整性(`-Wswitch`)

**从零理解:枚举常量没有内存**

```c
enum { MAX_CONN = 4096 };
```

编译器**不为 `MAX_CONN` 分配任何内存**。它就是个立即数,用在哪嵌到哪——`int arr[MAX_CONN]` 嵌进指令的就是 4096,`cmp eax, MAX_CONN` 就是 `cmp eax, 4096`。反汇编里看不到 `MAX_CONN`,只有数字。

有内存的是**枚举变量**:`enum pkt_type t;` 里的 `t` 是真变量(通常 int 宽度)。常量和变量是两回事——和"字面量 `'\t'` 无对象、const 变量 `c` 有对象"完全同构。

**为什么 HFT 协议码表必用 enum(而不是 #define)**

```c
switch (t) {
    case PKT_ORDER:  ...
    case PKT_QUOTE:  ...
    /* 漏了 PKT_HEARTBEAT → -Wswitch 编译期报警 */
}
```

宏是纯文本,编译器不知道它们是一组;enum 让编译器知道"这些值构成全集",漏 case 能在编译期揪出来。协议新增报文类型时,漏处理一种心跳包 = 误判断线,这个检查价值极大。

**C23:指定底层类型(嵌入式/协议打包)**

```c
enum pkt_type : uint8_t { PKT_ORDER, PKT_QUOTE };   /* C23 */
```

以前枚举变量固定 int(4 字节),协议结构体想要 1 字节字段只能 `uint8_t type;` 加强转;C23 起枚举本身可以就是 1 字节。

### const 对象(只读变量)

```c
const int max_retry = 3;        /* 只读, 可进 .rodata */
static const char *g_name = "default";
```

- **不是编译期常量**:不能用作数组长度(需 C99 VLA)、case 标签、位域宽度
- 想要"编译期符号常量"用 `#define` / `enum` / `static const` + 编译器折叠

### 三种"常量"机制对比(终局版)

| | `#define MAX 10` | `enum { MAX=10 }` | `const int MAX=10` |
|------|-----------------|-------------------|--------------------|
| 生效阶段 | 预处理(phase 4,文本替换) | 编译期(词法符号,立即数) | 运行期(变量,只读) |
| 有没有内存 | 无 | 常量无(变量有) | **有**,可 `&MAX` |
| 类型检查 | **无**——纯文本,`#define MAX "abc"` 都行 | int | 有,完整类型系统 |
| 作用域 | 定义处到文件尾,无视块作用域 | 遵守块作用域 | 遵守块作用域 |
| 调试器可见 | 不可见(替换完了) | 可见 | 可见 |
| 当数组长度/case 标签 | ✅ | ✅ | ❌ |
| 典型用途 | 数组长度、宏 | 状态码、协议类型 | 配置、只读表 |

**选型口诀**:要当编译期常量(数组长度/case/位域宽度)→ `#define` 或 `enum`;一组相关的整数码 → 必用 `enum`(图 `-Wswitch`);运行期只读配置(可取地址、放 .rodata)→ `const`。三者不冲突,一个项目里都会出现,各干各的活。

**C23 补坑:`constexpr` 进 C**

```c
constexpr int N = 100;      /* C23: 真正的编译期常量 */
int arr[N];                 /* OK,不是 VLA */
```

"const 只读但不常"这个 40 年的坑终于有了官方解法。C23 的 constexpr 语义与 C++ 不同(限定为对象定义),新 GCC/Clang 已支持(`-std=c23`/`-std=c2x`)。

## 与 HFT/DPDK

### 协议魔数与掩码

```c
#define MAGIC 0x54494301UL       /* "TIC" + 0x01 */
enum { MASK_LEN = 0xFFFF, MASK_SEQ = 0xFFFF0000UL };
const uint32_t g_seq_mask = 0xFFFF0000UL;   /* .rodata, 可取地址 */
```

### 字符串拼接做 help/version

```c
static const char version[] =
    "hft-gw 1.0 (built " __DATE__ " " __TIME__ ")\n"
    "compile: gcc -O2 -std=c11\n";
```

### enum 让 switch 完整性检查生效

```c
enum pkt_type { ORDER, QUOTE, HEARTBEAT };
const char *name(enum pkt_type t){
    switch (t) {
        case ORDER:     return "order";
        case QUOTE:     return "quote";
        case HEARTBEAT: return "hb";
    }   /* -Wswitch-enum: 漏 case 报警, 编译器无法保证 default */
}
```

### 字符串常量修改陷阱

```c
char *s = "hello";
s[0] = 'H';          /* UB: 可能 SIGSEGV(.rodata 只读) */
"hello"[0] = 'x';    /* 等价写法:直接对字面量数组下标,同样 UB */
char a[] = "hello";  /* a 是栈数组, 拷贝, 可改 */
a[0] = 'H';          /* ok */
```

HFT 代码静态扫描常禁 `char *` 直接接字符串字面量,要求 `const char *`。

**为什么编译不报错?**

C 标准规定字符串字面量的类型是 **`char[N]`,不是 `const char[N]`**——语法层面赋给 `char *` 完全合法,只是**语义上**修改它是 UB。坑在运行期才爆。

> C++ 做了改进:字面量类型是 `const char[N]`,`char *s = "hello"` 在 C++11 起非法(必须 `const char *`)。这是 C/C++ 又一处不兼容。

**字面量复用(字符串池)**

```c
char *p1 = "abc";
char *p2 = "abc";
/* p1 == p2 可能为真:编译器把相同字面量合并到 .rodata 同一地址 */
```

编译器可以(gcc/clang 默认会)去重合并相同字面量。极端情况:某处"成功"修改了字面量(嵌入式可写 RAM 场景),所有指向它的指针看到的都变了——另一个不用裸 `char *` 指字面量的理由。

**底层视角**

`.rodata` 段在程序加载时由 OS 标记为**只读页**(MMU 页保护)。写入触发 CPU 保护异常 → 内核送 `SIGSEGV`。这不是 C 编译器检查的,是硬件+OS 兜底。验证:`readelf -l` 看 `LOAD` 段的 `W` 标志,`.rodata` 落在无 `W` 的页。

```bash
gcc -O2 t.c -o t && readelf -l t | grep LOAD
# 第一个 LOAD (r--/r-x) 含 .rodata;含 .data/.bss 的 LOAD 才有 W
```

## 常见误区

| 误区 | 真相 |
|------|------|
| 八进制 `012` 等于十进制 12 | 等于十进制 10;leading 0 即八进制 |
| `sizeof("abc")` == 3 | == 4,含 `\0` |
| 修改字符串常量安全 | UB;放 .rodata 时 SIGSEGV |
| `const int N=10; int a[N];` 合法 | C89 不合法(非编译期常量);C99 VLA 可,但 static 文件域仍要编译期常量 |
| enum 底层一定是 int | C23 前基本是,但实现可选;C23 可指定 `enum x : uint8_t` |
| `1 << 32` 没问题 | 32 位 int 移位 ≥ 宽度是 UB,要 `1UL << 32` |

## 实操

```bash
cat > t.c <<'EOF'
#include <stdio.h>
#include <string.h>
int main(void){
  printf("sizeof 'A'=%zu\n", sizeof('A'));          /* C: 4 */
  printf("sizeof \"abc\"=%zu strlen=%zu\n",
         sizeof("abc"), strlen("abc"));              /* 4, 3 */
  enum { A=0, B, C=0x10, D };
  printf("B=%d D=%d\n", B, D);                       /* 1, 0x11 */
  char *s = "hi"; s[0]='H';                         /* UB, 可能崩 */
  return 0;
}
EOF
gcc -std=c11 -Wall t.c -o t && ./t   # 最后那行常段错误
readelf -p .rodata t                  # 看字符串常量段
```

## 代码自测

**题目 1：** 以下代码有什么问题？
```c
const int SIZE = 100;
int arr[SIZE];
```

<details>
<summary>参考答案</summary>

在 C89 中，数组大小必须是编译期常量表达式，const int 变量不是编译期常量（C 的 const 只读变量不同于 C++ 的 const）。C99 起支持变长数组（VLA），但 VLA 不能在文件作用域声明。正确做法：用 #define SIZE 100 或 enum { SIZE = 100 };。

</details>

**题目 2：** 以下哪个是字符字面量？
```c
const char c = '\t';
```
A：`c`　B：`'\t'`

<details>
<summary>参考答案</summary>

B。`'\t'` 是字符字面量——phase 3 分词为一个 token，phase 5 求值为 9（类型 int，无内存对象，是嵌进指令的立即数）。`c` 是 const 限定的 char **变量**，有内存、可以 `&c`，只是写入违反约束。判别标准：字面量没有对应的内存对象（`&'\t'` 编译错误），const 变量有地址。

</details>

**题目 3：** "C 语言中常量包括字面量和 const 修饰的变量"——这句对吗？

<details>
<summary>参考答案</summary>

是教材的通俗归类，不是标准口径。C 标准（C23 前 §6.4.4）里 constant 指 integer/character/floating constant（C23 改名 literal），const 修饰的是"不能修改的变量"（const-qualified object），不是常量。const 变量不能当数组长度、case 标签——通不过"编译期常量"测试。考试按教材记，写代码和读标准文档要区分。

</details>
