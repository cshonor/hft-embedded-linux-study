# 3.7.1 动态内存

## 本节讲什么

**动态存储期(allocated duration)** 决定"对象由 `malloc` 创建、由 `free` 销毁"。这是唯一由程序员手动控制生命周期的存储期——忘了 `free` 就泄漏，`free` 后再用就 UB。本节把 `malloc`/`calloc`/`realloc`/`free`/`aligned_alloc` 五个函数、底层 brk/mmap 机制、以及 HFT 场景的对齐分配讲透。

> 本节从 3.7 拆出,3.7 保留四种存储期概览 + ELF 段映射 + 自动/静态/线程存储期。

## 四函数对照表

| 函数 | 签名 | 初始化 | 失败返回 |
|------|------|--------|----------|
| `malloc` | `void *malloc(size_t size)` | **不清零**(脏内存) | `NULL` |
| `calloc` | `void *calloc(size_t nmemb, size_t size)` | **整块清零** | `NULL` |
| `realloc` | `void *realloc(void *ptr, size_t size)` | 保留前 min(旧,新) 字节 | `NULL`(原 ptr 仍有效) |
| `free` | `void free(void *ptr)` | — | — |

## malloc vs calloc——不只是"清不清零"的区别

```c
/* ❌ 危险:n*size 可能整数溢出 → 分配小缓冲 → 堆溢出 */
int *a = malloc(n * sizeof(int));

/* ✅ 安全:calloc 内部做 n*size 乘法溢出检查(C11 7.22.3.2) */
int *b = calloc(n, sizeof(int));
```

> ⚠️ **calloc ≠ malloc + memset**。两个参数分开传,内部在乘法前检查溢出——这是**安全功能**,不是"部分平台的优化"。`malloc(n * sizeof(int))` 里 `n` 来自外部输入时,`n * sizeof(int)` 溢出到一个小值 → malloc 分配小缓冲 → 后续写入越界 → 堆溢出 CVE。大分配优先 calloc。

### malloc vs calloc:什么时候用哪个

| 场景 | 选谁 | 原因 |
|------|------|------|
| 大小来自外部输入(报文、配置) | **calloc** | malloc 的 `n*size` 可能溢出 → 堆溢出 CVE |
| 需要零初始化(计数器、标志、结构体) | **calloc** | 逻辑上需要 0,顺手拿到安全检查 |
| 马上全部填充的缓冲区 | **malloc** | 清零是白干——刚 memset 完又要覆盖 |
| HFT 热路径频繁小块分配 | **malloc** | 少一次 memset,零开销都要抠 |

```c
/* 需要清零 → calloc */
struct session *s = calloc(1, sizeof(*s));   /* 成员全 0,安全 */

/* 马上填充 → malloc,清零浪费 */
int *buf = malloc(n * sizeof(int));          /* n 是内部常量,无溢出风险 */
for (int i = 0; i < n; i++) buf[i] = fetch(i);

/* 大小来自网络 → calloc,防溢出 */
uint32_t count = ntohl(hdr->count);          /* 攻击者可控 */
struct entry *entries = calloc(count, sizeof(*entries));
if (!entries) return -1;
```

> 记忆:**calloc 是"安全默认",malloc 是"性能默认"**。拿不准用 calloc 不会错;热路径且不需要清零时用 malloc。核心看两点——**要不要清零**、**大小安不安全**。
>
> calloc 不一定比 malloc 慢:如果内存来自新 mmap 的匿名页,内核本来就零初始化过(写时填零),calloc 跳过 memset;只有复用 free 链上的脏块才需要实际清零。

## realloc 行为表

| 调用 | 等价行为 |
|------|----------|
| `realloc(NULL, size)` | 等价 `malloc(size)` |
| `realloc(ptr, 0)` | C11: 实现定义(可能 free 后返回 NULL,也可能返回非空指针);C23 起明确 UB |
| `realloc(ptr, bigger)` | 可能原地扩展,也可能分配新块+拷贝+释放旧块 |
| `realloc(ptr, smaller)` | 通常原地缩短,返回值可能等于 ptr |

```c
/* 正确用法:用临时变量接,避免 realloc 失败丢原指针 */
int *tmp = realloc(p, new_size);
if (tmp) p = tmp;        /* 成功才覆盖 */
else { /* 失败:原 p 仍有效,可继续使用或 free */ }
```

> 经典 bug:`p = realloc(p, new_size);` —— realloc 失败返回 NULL,原 p 丢失→内存泄漏+野指针。

## free 的规则

- `free(NULL)` 安全,什么都不做(C11 7.22.3.3)
- free 后指针变成野指针——**不要再解引用**
- 防御性写法:`free(p); p = NULL;`
- 不要 free 栈上变量、不要重复 free 同一指针 → UB

## malloc 底层:brk vs mmap

```
malloc 如何向 OS 要内存(glibc ptmalloc):

  分配大小 ≤ 128KB(默认 MMAP_THRESHOLD)
  → brk/sbrk 调整 program break,扩展 heap 区
  → free 后内存不一定还给 OS(仍挂在 free 链上,RSS 不降)
  → 适合频繁的小分配

  分配大小 > 128KB
  → mmap(NULL, size, PROT_RW, MAP_PRIVATE|MAP_ANONYMOUS, -1, 0)
  → free 后 munmap 立即还 OS,RSS 下降
  → 大块分配更"干净"但 mmap 系统调用开销大
```

- 详见 2.1.2 执行环境
- 128KB 阈值可调(`mallopt(M_MMAP_THRESHOLD, ...)`)但很少动
- `free` 不一定降低 RSS:小块还挂在 ptmalloc 的 fastbin/smallbin 上,下次 malloc 直接复用——这是性能优化,但 `valgrind --tool=massif` 会看到堆峰值不降
- 碎片化:频繁 malloc/free 不同大小 → 空间不连续 → 虽然总量够但无法满足大块请求

## aligned_alloc(C11)——HFT 对齐分配

```c
/* C11 7.22.3.1:按 alignment 对齐分配 size 字节 */
void *aligned_alloc(size_t alignment, size_t size);
/* 约束:alignment 必须是支持的对齐值(通常 2^n),size 必须是 alignment 的整数倍 */

/* DPDK 封装 */
void *rte_malloc(const char *type, size_t size, unsigned align);
```

- HFT 场景:DMA 收发缓冲区要 **4K 页对齐**;共享计数器要 **cache line 对齐(64B)** 避免伪共享
- `posix_memalign()` 是 POSIX 版本,参数顺序不同但功能类似
- 旧代码常见 `malloc + 手动偏移对齐`,又慢又容易错

## void* 返回值与 C/C++ 差异

```c
/* C: void* 隐式转换为任意指针类型,不需要强转 */
int *p = malloc(10 * sizeof(int));    /* ✅ C 合法 */

/* C++: void* 不会隐式转换,必须强转 */
int *p = static_cast<int *>(malloc(10 * sizeof(int)));  /* C++ */
```

- C 里写 `(int*)malloc(...)` 不是错误,但**不必要**——且如果忘了 `#include <stdlib.h>`,强转会**掩盖**编译器因缺少原型而产生的隐式 int 警告(C89 遗留坑,C99 起隐式 int 已不合法)

## 常见误区

| 误区 | 真相 |
|------|------|
| malloc 内存是 0 | 不保证,要 calloc 或 memset |
| `calloc ≈ malloc + memset` 只差清零 | calloc 还有 `n*size` 乘法溢出检查(安全功能) |
| `p = realloc(p, new_size)` 安全 | 失败丢原指针,经典 bug |
| `realloc(ptr, 0)` 一定 free | C11 是实现定义,C23 是 UB |
| malloc 的 void* 需要 `(int*)` 强转 | C 不需要,且会掩盖缺原型警告 |

## 实操

```bash
# 1. 看 malloc/calloc 初值差异
cat > mc.c <<'EOF'
#include <stdio.h>
#include <stdlib.h>
int main(void) {
    int *m = malloc(4 * sizeof(int));
    int *c = calloc(4, sizeof(int));
    printf("malloc: %d %d %d %d\n", m[0], m[1], m[2], m[3]);
    printf("calloc: %d %d %d %d\n", c[0], c[1], c[2], c[3]);
    free(m); free(c);
}
EOF
gcc mc.c -o mc && ./mc   # malloc 是垃圾值,calloc 全 0

# 2. 看 brk vs mmap 分界
strace ./mc 2>&1 | grep -E 'brk|mmap'

# 3. realloc 失败丢指针演示
cat > re.c <<'EOF'
#include <stdlib.h>
#include <stdio.h>
int main(void) {
    int *p = malloc(4 * sizeof(int));
    p[0] = 42;
    /* 请求超大内存让 realloc 失败 */
    int *tmp = realloc(p, (size_t)-1);
    if (!tmp) { printf("realloc failed, p[0]=%d still valid\n", p[0]); }
    free(p);
}
EOF
gcc -O0 re.c -o re && ./re
```

## 代码自测

**题目 1：** 以下代码有什么问题？
```c
int *p = realloc(p, 1024 * sizeof(int));
if (p == NULL) { /* ... */ }
```

<details>
<summary>参考答案</summary>

**`p = realloc(p, ...)` 是经典 bug**。realloc 失败时返回 NULL，但原 p 仍然有效——直接赋值覆盖后，原指针丢失，既无法使用也无法 free → **内存泄漏 + 野指针**。正确写法：
```c
int *tmp = realloc(p, 1024 * sizeof(int));
if (tmp) p = tmp;
else { /* 原 p 仍有效，可继续用或 free(p) */ }
```

</details>

**题目 2：** `char *buf = calloc(5, sizeof(char));` 之后 `buf[0]`~`buf[4]` 的值是什么？为什么说 `calloc(n, size)` 比 `malloc(n * size)` 更安全？

<details>
<summary>参考答案</summary>

`buf[0]`~`buf[4]` 全部是 0——calloc 分配后整块清零。

安全差异：calloc 两个参数分开传，内部在执行 `nmemb * size` 乘法**之前**检查溢出（C11 7.22.3.2）；而 `malloc(n * size)` 由调用者自己算乘积，`n` 来自外部输入时 `n * size` 可能整数溢出到一个小值 → malloc 分配小缓冲 → 后续按 `n` 个元素写入 → 堆溢出。这是 CVE 常见模式，不是"部分平台的优化"。

</details>

**题目 3：** 以下分配，哪个有安全风险？为什么？
```c
/* A */ int *a = malloc(40);
/* B */ int *b = malloc(10 * sizeof(int));
/* C */ int *c = calloc(10, sizeof(int));
```

<details>
<summary>参考答案</summary>

- **A 有跨平台风险**：手写 `40` 假设 `int` 是 4 字节，在 `int` 为 2 字节的平台上分配不够。应该用 `sizeof(int)`。
- **B 在 `n` 来自外部输入时有溢出风险**：`10 * sizeof(int)` 如果 `10` 换成攻击者可控的大数，乘法溢出到小值 → 堆溢出。本例 `10` 是常量无风险，但模式危险。
- **C 最安全**：calloc 内部做乘法溢出检查 + 清零。

</details>
