# 3.6 链接属性

## 本节讲什么

**链接(linkage)** 决定"一个标识符在多个翻译单元间能否指向同一对象/函数"。它是 C 工程化最关键的语义 —— 多个 `.c` 编译成 `.o` 后如何拼成一个可执行/库,完全由链接属性决定。本节从语言层(external/internal/none)、链接器视角(符号表)、工程模板(头文件 extern + .c 定义)三层讲透,这是 ch03 最该吃透的一节。

## 要点

### 三种链接

| 链接 | 条件 | 例子 | 含义 |
|------|------|------|------|
| **外部**(external) | 文件域,无 static | `int g;` `void f(){}` | 跨 `.o` 共享,链接器合并 |
| **内部**(internal) | 文件域 + static | `static int s;` `static void h(){}` | 仅本翻译单元,不导出 |
| **无**(none) | 块域 auto / 形参 / typedef 名 | `int x;`(块内) | 不参与链接,各翻译单元独立 |

- **函数默认外部链接**:`void f(){}` 可被其他 `.c` 调用(需原型声明)
- **static 函数 = 内部链接**:`static void h(){}` 仅本文件,这是模块私有的标准做法

### extern 的语义

```c
extern int g;             /* 声明: g 在别处定义, 链接器去找 */
extern void f(void);      /* 声明函数原型, 等价 void f(void); */

int g = 1;                /* 定义: 分配存储, 外部链接 */
void f(void){}            /* 定义: 函数体, 外部链接 */
```

- `extern` 关键字 = "声明而非定义,引用别处"
- 函数原型默认就是 extern 语义(`void f(void);` 与 `extern void f(void);` 等价)
- `extern int g;` **不分配存储**;若没有任何 `.c` 定义 `g`,链接器报 `undefined reference to 'g'`

### 定义全局唯一

```c
/* a.c */ int g = 1;
/* b.c */ int g = 2;     /* 两个定义 → 链接器报 multiple definition of 'g' */
```

- 现代 GCC/ld 默认 `-fno-common`:全局变量定义即独占,重复定义立即报错
- 旧版 GCC 默认 `-fcommon`:把"无初值全局"当 tentative definition,允许多文件合并(易出 bug,已改)

### 内部链接的符号隔离

```c
/* foo.c */
static int count = 0;          /* 内部链接, 不导出符号 */
static void helper(void){}     /* 内部链接 */

/* bar.c */
static int count = 0;          /* 另一个独立 count, 互不冲突 */
```

- 两个 `.c` 各自 `static int count;` 是**两个不同对象**,互不干扰 —— 这是模块封装的基础
- `nm foo.o` 看到 `count` 是小写 `d`/`b`(local),`bar.o` 里也是 local,链接器不合并

## 链接器视角(符号表)

```bash
gcc -c foo.c -o foo.o
nm foo.o
# 输出形如:
# 0000000000000000 T foo_api       # T = 外部链接, text 段
# 0000000000000010 t helper        # t = 内部链接, text 段
# 0000000000000000 D g_count       # D = 外部链接, data 段
# 0000000000000004 b s_hidden      # b = 内部链接, bss 段
#                  U memcpy        # U = 未定义, 等链接器从 libc 找
```

| nm 字符 | 含义 |
|---------|------|
| 大写 `T/D/B/R` | 外部链接,text/data/bss/rodata |
| 小写 `t/d/b/r` | 内部链接(static) |
| `U` | 未定义引用,需链接器解析 |
| `W`/`V` | weak 符号(可被覆盖) |

## 工程模板(头文件 extern + .c 定义)

```c
/* foo.h —— 公共接口 */
#ifndef FOO_H
#define FOO_H
extern int g_count;                 /* 声明, 不分配 */
void foo_api(void);                 /* 函数原型 = extern 声明 */
#endif

/* foo.c —— 实现 */
#include "foo.h"
int g_count = 0;                    /* 唯一定义, 外部链接 */
static int s_state = 0;             /* 内部链接, 模块私有 */
static void helper(void){}          /* 内部链接 */
void foo_api(void){ g_count++; helper(); }

/* bar.c —— 使用方 */
#include "foo.h"
void bar(void){ foo_api(); g_count--; }   /* 引用同一对象 */
```

> 这是 C 工程的标准范式。**头文件只放 extern 声明,定义放 .c**,否则多文件包含即重复定义。

## 与 HFT/DPDK

### 多 `.o` 链成网关

- 一个 HFT 网关可能几十上百个 `.c`:网络层、协议解析、风控、订单管理、日志……
- 模块间靠 `extern` 共享 API,靠 `static` 隔离实现 —— 与面向对象语言的 public/private 等价
- 链接器把所有外部链接符号合并,内部链接符号各自独立

### DPDK 驱动注册(weak 符号)

```c
/* DPDK 用 weak 符号 + 链接器选择机制做驱动注册 */
RTE_INIT(my_driver_init)        /* 构造函数属性, 链接时收集 */
static void my_driver_init(void){ ... }
```

- `__attribute__((weak))` 弱符号可被强符号覆盖,DPDK/PMD 用它做可选驱动
- `__attribute__((constructor))` 让函数在 `main` 前执行,常用于驱动自注册

### 链接期符号冲突排查

```bash
# 报 "multiple definition of 'x'"
nm -C *.o | grep ' x$'          # 找哪些 .o 定义了 x
# 报 "undefined reference to 'y'"
nm -C *.o | grep ' U y'         # 找谁引用了未定义的 y
# 看最终可执行文件符号
nm a.out | sort
objdump -T a.out                # 动态符号表(共享库)
```

## 常见误区

| 误区 | 真相 |
|------|------|
| 头文件写 `int g;` 是声明 | 是定义(tentative),多文件 include 会重复定义 |
| `extern int g;` 分配存储 | 不,是声明,引用别处 |
| static 全局变量其他 .c 可见 | 不可见,内部链接 |
| 函数默认无链接 | 默认外部链接,可被其他 .c 调 |
| 同名 static 全局在两个 .c 是同一对象 | 不是,各自独立,链接器不合并 |

## 实操

```bash
# 1. 多文件链接实验
cat > a.c <<'EOF'
#include <stdio.h>
int shared = 1;              /* 外部链接定义 */
static int priv = 2;         /* 内部链接 */
void show(void){ printf("shared=%d priv=%d\n", shared, priv); }
EOF
cat > b.c <<'EOF'
extern int shared;           /* 引用 a.c */
extern void show(void);
int main(void){ shared = 10; show(); return 0; }
EOF
gcc a.c b.c -o ab && ./ab          # shared=10 priv=2
nm a.o                              # T show, D shared, d priv
nm ab | grep -E 'shared|priv|show'

# 2. 重复定义错误
cat > c.c <<'EOF'
int shared = 99;             /* 与 a.c 冲突 */
EOF
gcc a.c c.c -o ac    # multiple definition of 'shared'

# 3. static 隔离
cat > d.c <<'EOF'
#include <stdio.h>
static int priv = 100;       /* 与 a.c 的 priv 是不同对象 */
void d_show(void){ printf("d priv=%d\n", priv); }
EOF
gcc a.c d.c -main.c -o ad    # 链接成功, 两个 priv 互不冲突
```

## 代码自测

**题目 1：** 以下三个变量/函数的链接属性分别是什么？
```c
int a;           // (1)
extern int b;   // (2)
static int c;   // (3)
```

<details>
<summary>参考答案</summary>

(1) a 是外部链接——其他文件可以通过 extern int a; 访问。(2) b 是外部链接——声明在其他文件定义的外部变量。(3) c 是内部链接——只在当前文件可见，其他文件无法访问。static 在文件作用域改变链接属性为内部。

</details>
