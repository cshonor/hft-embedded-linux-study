# 3.12 字符常量的类型陷阱

> 补充节 · C vs C++ 经典面试考点

## 核心要点

### 1. `'A'` 的类型

| 语言 | `'A'` 的类型 | `sizeof('A')` |
|------|-------------|---------------|
| **C** | `int` | 4（32 位平台） |
| **C++** | `char` | 1 |

C 标准（C11 §6.4.4.4）：
> An integer character constant has type **int**.

这是 C 和 C++ 最隐蔽的不兼容点之一。同样的代码，用 `gcc` 编译（C）和 `g++` 编译（C++）结果不同。

```c
/* C 语言 */
char c = 'A';          /* c 是 char 变量，1 字节 */
int  x = 'A' + 1;      /* x = 66，'A' 是 int，加法结果 int */

sizeof(c);             /* 1 —— char 变量 */
sizeof('A');           /* 4 —— 字符常量是 int */
sizeof('A' + 0);       /* 4 —— int + int = int */
```

### 2. 为什么 C 把 `'A'` 设为 `int`？

历史原因：C 诞生于 PDP-11，该机器的寄存器是 16 位，没有单字节算术指令。字符常量天生要参与算术（`'A' + 1`），用 `int` 避免了不必要的截断。C++ 设计时认为"字符就是字符"，改为 `char` 更符合类型直觉——但破坏了与 C 的兼容性。

### 3. `'A'` 的值

实现定义的字符编码值。ASCII 环境下 `'A'` = 65。

等价写法：
```c
'\x41'   /* 十六进制转义，= 65 */
'\101'   /* 八进制转义，= 65 */
```

### 4. 常用转义序列

| 转义 | 含义 | 用途 |
|------|------|------|
| `'\n'` | 换行 | 输出格式 |
| `'\t'` | 水平制表 | 对齐 |
| `'\0'` | 空字符 | **字符串结束标记** |
| `'\\'` | 反斜杠本身 | 路径、正则 |
| `'\''` | 单引号 | 字符常量内嵌引号 |
| `'\x41'` | 十六进制字节 | **报文魔数、寄存器值** |
| `'\101'` | 八进制字节 | 罕用，但标准支持 |

> ⚠️ `\x` 后可跟任意位十六进制数字（直到非十六进制字符），`\` 后最多 3 位八进制数字。`'\x1234'` 在 32 位 `int` 上合法，值由实现定义。

## 常见陷阱

### 陷阱 1：`'A'` 赋值给 `char` 发生截断

```c
char c = 'A';        /* 一般没问题：65 截断为 char 仍是 65 */
char c = '\xFF';     /* 陷阱：'\xFF' = 255 (int)，截断为 char */
                     /* 若 char 是 signed：c = -1 */
                     /* 若 char 是 unsigned：c = 255 */
```

→ 与 [3.11 char 的符号性陷阱](./3.11-char的符号性陷阱.md) 联动：`'\xFF'` 本身是 `int` 255，但赋值给 `char` 后符号行为跨平台不同。

### 陷阱 2：字符常量 vs 字符串字面量

```c
'A'     /* int (C) / char (C++)，单个字符常量，4/1 字节 */
"A"     /* char[2]，数组，含 'A' + '\0'，2 字节 */
```

| | `'A'` | `"A"` |
|---|---|---|
| 类型 | `int`（C）/ `char`（C++） | `char[2]` |
| sizeof | 4（C）/ 1（C++） | 2 |
| 含 `\0`? | 否 | 是 |
| 存储段 | 立即数（无地址） | `.rodata` |

### 陷阱 3：多字符常量 `'AB'`

```c
int x = 'AB';    /* C 允许，类型 int，值由实现定义 */
                 /* gcc x86: 'A' 在低字节，'B' 在高字节 → 0x4241 */
                 /* ARM: 字节序可能相反 */
```

C 标准允许 1~4 个字符的字符常量（multicharacter constant），但**值由实现定义**。C++ 同样允许但更不推荐。

实际用途：FourCC 码（如 `'RIFF'`、`'AVI '`）——但跨端序平台不可移植，工程上应改用 `uint32_t` + 显式字节拼接。

### 陷阱 4：`sizeof('A')` 用于跨 C/C++ 代码

```c
#ifdef __cplusplus
static_assert(sizeof('A') == 1, "C++: char");
#else
_Static_assert(sizeof('A') == sizeof(int), "C: int");
#endif
```

混合 C/C++ 项目（如 DPDK 被 C++ 包装）中，`sizeof('A')` 在不同编译单元里值不同，不能用作数组长度等编译期常量。

### 陷阱 5：`'0'` ≠ `0` ≠ `'\0'`

三个长得像的东西，值完全不同：

```c
char a = '0';    /* 字符 '0'：ASCII 48 */
char b = 0;      /* 数值 0 */
char c = '\0';   /* 转义：数值 0，和 b 一样 */

printf("%d %d %d\n", a, b, c);   /* 48 0 0 */
```

| 写法 | 值 | 含义 |
|------|-----|------|
| `'0'` | **48** | 字符"零"，是数字字符 |
| `0` | 0 | 整数零 |
| `'\0'` | 0 | 空字符，字符串终止符 |

报文解析判断数字字段的经典写法：

```c
if (buf[i] >= '0' && buf[i] <= '9')   /* 判断是否数字字符：48~57 */
    val = val * 10 + (buf[i] - '0');  /* 字符转数值：减去 '0' (48) */
```

> 写 `buf[i] - 48` 能跑，但 `buf[i] - '0'` 才是可移植写法（非 ASCII 平台上 `'0'` 不一定是 48）。

### 陷阱 6：`char c = "A"` 非法

```c
char c1 = 'A';    /* ✅ 字符常量 (int 65) → 截断为 char */
char c2 = "A";    /* ❌ 编译警告/错误 */
```

`"A"` 是 `char[2]` 数组，在表达式中退化为 `char *`（指针），赋给 `char` 变量是**指针转整数**——窄化 + 类型完全不符。gcc 报 `warning: initialization of 'char' from 'char *' makes integer from pointer`，MSVC 直接报错。

### 陷阱 7：无 `'\0'` 的 char 数组不是 C 字符串

```c
char s1[] = "hello";                          /* ✅ 6 字节，含 '\0'，是字符串 */
char s2[] = {'h','e','l','l','o','\0'};       /* ✅ 等价写法 */
char s3[] = {'a','b'};                        /* ⚠️ 合法数组，但不是字符串 */
```

`s3` 没有终止符，传给 `printf("%s", s3)` / `strlen(s3)` 会**越界读**直到碰巧遇到 0 字节——UB，输出乱码还是崩溃看运气。

> 区分"合法"和"是字符串"：`s3` 是完全合法的 char 数组，只是不能当 C 字符串用。长度已知时按数组处理（`sizeof` / 显式长度参数）反而更快——HFT 报文解析从不依赖 `\0`，一律长度字段 + `memcmp`。

## HFT / 内核关联

1. **报文魔数用 `'\x'` 转义**：比裸数字可读
   ```c
   uint8_t magic[] = {'T', 'I', 'C', '\x01'};   /* 协议头 */
   if (buf[0] == 'T' && buf[1] == 'I') ...
   ```

2. **寄存器字节常量**：MMIO 写入用 `'\xFF'` 比 `0xFF` 更"字符化"，但建议直接用 `0xFFU` 避免歧义

3. **FourCC 跨端序陷阱**：`'RIFF'` 在 x86（小端）和 ARM 大端模式下值不同 → 用 `uint32_t` 显式拼

4. **C/C++ 混编**：内核纯 C 不受影响；但 DPDK 被 C++ 调用时，`sizeof('A')` 差异需注意

## 自测题

### Q1: `sizeof('A' + 0)` 的结果？

<details>
<summary>答案</summary>

**4**。`'A'` 本身是 `int`（C），`int + int = int`，`sizeof(int)` = 4。

C++ 中 `'A'` 是 `char`，`char + int` 经整数提升为 `int`，结果也是 4。

</details>

### Q2: `char ch = 'A'; sizeof(ch)` 的结果？

<details>
<summary>答案</summary>

**1**。`ch` 是 `char` 类型变量，和字面量 `'A'` 的类型（`int`）无关。

关键区分：**变量类型** vs **字面量类型**。`char c = 'A'` 中，`c` 的类型由声明决定（`char`），`'A'` 的类型由语言标准决定（C 中 `int`）。赋值时发生 `int → char` 的隐式截断。

</details>

### Q3: 以下代码在 x86（`char` = signed）和 ARM（`char` = unsigned）上输出什么？

```c
char c = '\xFF';
printf("%d\n", c);
if (c > 0) printf("positive\n");
else       printf("non-positive\n");
```

<details>
<summary>答案</summary>

**x86**（`char` = signed）：
- `'\xFF'` = 255 (int) → 截断为 signed char → -1
- 输出 `-1`，`non-positive`

**ARM**（`char` = unsigned）：
- `'\xFF'` = 255 (int) → 截断为 unsigned char → 255
- 输出 `255`，`positive`

一行代码，两个平台结果完全相反。→ 参见 [3.11 char 的符号性陷阱](./3.11-char的符号性陷阱.md)

</details>

### Q4: `'AB'` 的 `sizeof` 和值？

<details>
<summary>答案</summary>

`sizeof('AB')` = `sizeof(int)` = **4**（C 中多字符常量类型始终是 `int`）。

值由实现定义。gcc x86 小端：`'A'` = 0x41 在低字节，`'B'` = 0x42 在高字节 → **0x4241** = 16961。

跨平台不可移植，工程上不推荐使用。

</details>

### Q5: `char c = '0';` 里存的是什么？

<details>
<summary>答案</summary>

**48**（ASCII 编码下），不是数值 0。

- `'0'` 是字符"零"，ASCII 码 48
- `'\0'` 才是数值 0（字符串终止符）
- `0` 是整数零

字符转数值：`c - '0'`；数值转字符：`n + '0'`。不要硬编码 48——`'0'` 写法在非 ASCII 平台也正确。

</details>
