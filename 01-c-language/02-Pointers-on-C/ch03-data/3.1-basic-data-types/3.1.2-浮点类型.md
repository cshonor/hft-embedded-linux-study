# 3.1.2 浮点类型

## 本节讲什么

`float`/`double`/`long double` 的精度、范围、存储格式（IEEE 754），以及 HFT 行业的核心惯例：**撮合/风控核心路径不用浮点，用整型定点存价格**。理解浮点为什么不精确、为什么 `==` 判等危险，是金融交易代码的基本素养。

## 三种浮点类型

| 类型 | 典型位宽 | 尾数位 | 指数位 | 有效数字 | 工程场景 |
|------|---------|--------|--------|---------|---------|
| `float` | 32 | 23 | 8 | ~7 位 | 图形、传感器（HFT 几乎不用） |
| `double` | 64 | 52 | 11 | ~15 位 | 回测、统计、展示 |
| `long double` | 80(x86)/128(ARM) | 64/113 | 15/15 | ~18~33 位 | 高精度科学计算（HFT 极少用） |

## IEEE 754 浮点格式

### 32 位 float 的内存布局

```
 sign | exponent(8) | mantissa(23)
  1位    8位           23位
```

- **sign**：1 = 负，0 = 正
- **exponent**：指数，偏移 127
- **mantissa**：尾数（隐含最高位 1）

### 浮点为什么不"精确"

浮点用二进制小数表示——**不是所有十进制小数都能精确表示**：

```
0.1（十进制）= 0.0001100110011...（二进制无限循环）
```

- `0.1 + 0.2` 在 `double` 里 ≠ `0.3`，而是 `0.30000000000000004`
- `0.5`、`0.25`、`0.125` 能精确（2 的负幂）；`0.1`、`0.2`、`0.3` 不能
- 累加大量小浮点数会累积舍入误差

### `==` 判等陷阱

```c
double a = 0.1 + 0.2;
double b = 0.3;
if (a == b) { ... }   /* 几乎永远为假！a = 0.30000000000000004 */
```

**正确做法**：用 epsilon 容差比较：

```c
#include <math.h>
if (fabs(a - b) < 1e-9) { ... }   /* 容差比较 */
```

> 金融场景更严格：根本不用浮点比较，用整型定点——见后文。

## 浮点的边界值

| 特殊值 | 表示 |
|--------|------|
| `+0.0` / `-0.0` | 符号位不同，`==` 判等但 `1/0.0` 不同（+INF vs -INF） |
| `+INF` / `-INF` | 指数全 1、尾数全 0；溢出结果 |
| `NaN` | 指数全 1、尾数非 0；`0.0/0.0`、`sqrt(-1)` |
| 非规格化数 | 指数全 0、尾数非 0；极小值，运算慢 |

- `NaN != NaN`——`if (x != x)` 可以检测 NaN
- `isinf()`/`isnan()`/`isfinite()` 是安全的检测函数
- 非规格化数在 x86 上运算**极慢**（几十倍），HFT 要避免——`-ffast-math` 会刷成 0

## 整型与浮点的转换

```c
int    i = 1000000;
double d = i;           /* OK：int → double 常可精确表示 */

double big = 1e20;
int    j = (int)big;    /* UB：超出 int 范围 → 截断/溢出 */
```

- `int → double`：2^53 以内的整数可精确表示（double 有 52 位尾数 + 隐含 1）
- `double → int`：超出范围是 **UB**（未定义行为），不是"截断"
- `int → float`：超过 2^24（float 尾数 23 位）精度丢失

## HFT 核心惯例：定点整数存价格

### 为什么不用浮点存价格

| 问题 | 后果 |
|------|------|
| `0.1` 不能精确表示 | 累加千万次后误差累积 |
| `==` 判等失效 | 撮合时"价格相等"判断出错 |
| 舍入不确定 | 四舍五入规则不统一，跨平台不一致 |
| 非规格化慢 | 极小值运算拖慢热路径 |

### 定点方案

```c
/* 价格用"分"（或厘/毫）存，1 元 = 100 分 */
int64_t price_cents = 12345;   /* 123.45 元 */

/* 加减法直接算 */
int64_t total = price_cents * quantity;   /* 总价（分） */

/* 需要展示时再转浮点 */
double display = price_cents / 100.0;     /* 123.45 */
```

| 路径 | 用什么 | 原因 |
|------|--------|------|
| 撮合/风控核心 | `int64_t` 定点 | 精确、可 `==` 判等、无舍入 |
| 回测/统计 | `double` | 精度够、库函数丰富 |
| 展示/日志 | `double` 或格式化字符串 | 人类可读 |
| 行情解析 | 按交易所协议（常定点） | 交易所规定 |

### 定点的精度管理

- 确定小数位数：分（2 位）、厘（3 位）、毫（4 位）——按交易所规定
- 乘法后要除以 scale 因子——注意溢出（`int64_t` 最大 ~9.2e18）
- 四舍五入用 `(x + 5) / 10` 或银行家舍入

## 字面量

```c
3.14           /* double */
3.14F          /* float */
3.14L          /* long double */
1e-6           /* double, 0.000001 */
1e3            /* double, 1000.0 */
```

- 不加后缀默认 `double`，不是 `float`
- `3.14` 赋给 `float` 会有隐式转换 + 精度截断警告

## HFT 浮点的其他注意

- **浮点运算不满足结合律**：`(a+b)+c` ≠ `a+(b+c)`（舍入方向不同）→ 不能随意重排
- **`-ffast-math`**：允许重排和刷非规格化，快但破坏 IEEE 语义——HFT 慎用
- **FPU 状态字**：x86 浮点运算可能修改 FPU 状态字，多线程切换有开销——定点避免此问题
- **SIMD 向量化**：`double` 可以 AVX 一次算 4 个，但金融核心路径常不需要浮点向量化

## 常见误区

| 误区 | 纠正 |
|------|------|
| `0.1 + 0.2 == 0.3` | 不等，浮点不精确 |
| 浮点 `==` 判等安全 | 不安全，用 epsilon 或定点 |
| `double → int` 超范围只是截断 | 是 UB，不是确定的截断 |
| `float` 更快 | 现代 CPU 上 `float` 和 `double` 速度相当；`float` 省内存/带宽 |
| 价格用 `double` 就行 | 金融核心路径用定点整数，避免舍入和判等问题 |
| 非规格化数无所谓 | x86 上运算慢几十倍，HFT 要避免 |

## 实操

1. `printf("%.20f\n", 0.1 + 0.2)` 看不是 0.3
2. `if (0.1 + 0.2 == 0.3)` 看永远为假
3. `printf("%d\n", (int)1e20)` 看 UB（可能是个垃圾值）
4. 写定点价格加减乘，验证精确
5. `isinf(1.0/0.0)`、`isnan(0.0/0.0)` 看特殊值

## 代码自测

**题目 1：** 以下代码输出什么？为什么？
```c
double d = 0.1 + 0.2;
if (d == 0.3) printf("equal");
else printf("not equal");
```

<details>
<summary>参考答案</summary>

输出 not equal。浮点数在二进制中无法精确表示 0.1 和 0.2，0.1 + 0.2 的结果是 0.30000000000000004，不等于 0.3。比较浮点数应该用误差范围：if (fabs(d - 0.3) < 1e-9)。

</details>
