# 3.1.2 浮点类型

## 本节讲什么

`float`/`double`/`long double` 的精度、范围、存储格式（IEEE 754），以及 HFT 行业的核心惯例：**撮合/风控核心路径不用浮点，用整型定点存价格**。理解浮点为什么不精确、为什么 `==` 判等危险，是金融交易代码的基本素养。

## 三种浮点类型

| 类型 | 典型位宽 | 尾数位 | 指数位 | 有效数字 | 工程场景 |
|------|---------|--------|--------|---------|---------|
| `float` | 32 | 23 | 8 | ~7 位 | 图形、传感器（HFT 几乎不用） |
| `double` | 64 | 52 | 11 | ~15 位 | 回测、统计、展示 |
| `long double` | 80(x86)/128(ARM) | 64/113 | 15/15 | ~18~33 位 | 高精度科学计算（HFT 极少用） |

> **精度怎么来的**：float 尾数 23 位 + 隐含 1 = 24 位 → 2^24 = 16777216 → log₁₀(2^24) ≈ 7.22 → **约 7 位有效十进制数字**。double 尾数 52 + 1 = 53 位 → 2^53 = 9007199254740992 → log₁₀(2^53) ≈ 15.95 → **约 15-16 位**。

## IEEE 754 浮点格式

### 32 位 float 的内存布局

```
 sign | exponent(8) | mantissa(23)
  1位    8位           23位
```

- **sign**：1 = 负，0 = 正
- **exponent**：指数，偏移 127（存的不是真实指数，要减去 127）
- **mantissa**：尾数（隐含最高位 1，不存到内存）

### 完整数值公式

```
value = (-1)^sign × (1.mantissa)₂ × 2^(exponent - 127)
```

**工作示例**：float 内存中 `0 01111111 00000000000000000000000`
- sign = 0 → 正数
- exponent = 01111111 = 127 → 真实指数 = 127 - 127 = 0 → 2^0 = 1
- mantissa = 全 0 → 1.000... = 1.0
- value = (+1) × 1.0 × 2^0 = **1.0**

另一个：`0 10000000 00000000000000000000000`
- exponent = 10000000 = 128 → 真实指数 = 128 - 127 = 1 → 2^1 = 2
- value = 1.0 × 2^1 = **2.0**

### 64 位 double 的内存布局

```
 sign | exponent(11) | mantissa(52)
  1位    11位           52位
```

- 偏移量 1023（不是 127）
- 尾数 52 位 + 隐含 1 = 53 位精度

### 浮点为什么不"精确"

浮点用二进制小数表示——**不是所有十进制小数都能精确表示**：

```
0.1（十进制）= 0.0001100110011...（二进制无限循环）
```

- `0.1 + 0.2` 在 `double` 里 ≠ `0.3`，而是 `0.30000000000000004`
- `0.5`、`0.25`、`0.125` 能精确（2 的负幂）；`0.1`、`0.2`、`0.3` 不能
- 累加大量小浮点数会累积舍入误差

### `==` 判等陷阱

```c
double a = 0.1 + 0.2;
double b = 0.3;
if (a == b) { ... }   /* 几乎永远为假！a = 0.30000000000000004 */
```

**正确做法**：用 epsilon 容差比较：

```c
#include <math.h>
if (fabs(a - b) < 1e-9) { ... }   /* 容差比较 */
```

> **epsilon 的坑**：固定 `1e-9` 只对接近 1 的数有效。如果比较两个大数（如 `a = 1e15, b = 1e15 + 1`），`fabs(a-b) = 1` 远大于 `1e-9` → 判不相等，但 double 在 1e15 量级的精度间隔已经是 1.0 了（2^53 ≈ 9e15，超过就不连续了）。正确做法是**相对 epsilon**：`fabs(a-b) < fabs(a) * EPS`，或用 `FLT_EPSILON`/`DBL_EPSILON`（`<float.h>`，分别是 1.19e-7 和 2.22e-16）。

> 金融场景更严格：根本不用浮点比较，用整型定点——见后文。

## 浮点的边界值

| 特殊值 | 表示 |
|--------|------|
| `+0.0` / `-0.0` | 符号位不同，`==` 判等但 `1/0.0` 不同（+INF vs -INF） |
| `+INF` / `-INF` | 指数全 1、尾数全 0；溢出结果 |
| `NaN` | 指数全 1、尾数非 0；`0.0/0.0`、`sqrt(-1)` |
| 非规格化数 | 指数全 0、尾数非 0；极小值，运算慢 |

- `NaN != NaN`——`if (x != x)` 可以检测 NaN
- `isinf()`/`isnan()`/`isfinite()` 是安全的检测函数
- **非规格化数为什么慢**：正常浮点隐含最高位是 1，硬件可以直接算；非规格化数隐含位是 0，CPU 要走特殊微码路径处理。x86 上慢 20-50 倍。HFT 热路径如果累减到极小值可能突然掉速——`-ffast-math` 会把这些值刷成 0（FTZ/DAZ 模式），快但破坏 IEEE 语义

## 整型与浮点的转换

**核心：转换是数值重新编码，不是内存比特拷贝。**

### 范围 vs 精度：浮点能表示大数，但"表示"≠"精确表示"

浮点用二进制科学计数法 `±1.xxxxx × 2^n`，指数 11 位（double）→ **范围**可达 ±1.8×10³⁰⁸，远超 int64。但范围大不等于精度够——**尾数只有 52+1 = 53 位**：

- **≤ 2⁵³（约 9×10¹⁵）的整数**：double 一个不差地精确表示
- **> 2⁵³ 的整数**：只能表示"最近的那个浮点数"，**丢的是整数低位，不是小数**。比如 2⁵³+1 转 double 变成 2⁵³

原因：数越大，相邻两个可表示浮点数的间隔（ULP）越大。指数每 +1，ULP 翻倍；超过 2⁵³ 后 ULP ≥ 2，连每个整数都覆盖不全。**能不能精确表示，看的是尾数位数，不是数值大小**。

### 转换规则归纳（三条线分开记，别合成一条"就是舍掉"）

| 场景 | 行为 |
|------|------|
| 小 double（如 3.99）转 int | 小数位**向零截断**（C11 6.3.1.4），整数部分保留 |
| 大整数（≤2⁵³）转 double | 精确，无损 |
| 大整数（>2⁵³）转 double | **丢整数低位**（尾数不够），不是丢小数 |
| 超大 double（超目标整型范围）转 int | **UB**（x86 上典型是变成 INT_MIN，即 cvttsd2si 溢出，但标准不保证） |

> 口诀：**大数进浮点丢低位（尾数不够），小数进整数丢小数（向零截断），超范围直接 UB**。

### int → double（安全）

```c
int    i = 1000000;
double d = i;           /* OK：所有 32 位 int 转 double 都精确 */
```

- 32 位 int 范围 -2³¹ ~ 2³¹-1，全部 ≤ 31 位比特；double 尾数 52+1 = 53 位，**装得下**
- CPU 读出 int 的整数值，重新编码为 IEEE 754 格式（符号/指数/尾数），写入 8 字节——**不是**把 4 字节拷进 8 字节
- **int64_t 超 2^53 才丢精度**：`(double)(int64_t)` 大于 2^53 时低位丢失

### double → int（向零截断，不是四舍五入）

```c
double f1 = 3.9;
int i1 = (int)f1;    /* 3 —— 扔掉 .9 */

double f2 = -3.9;
int i2 = (int)f2;    /* -3 —— 扔掉 .9，向零靠拢，不是 -4 */
```

- C 标准（C11 6.3.1.4）：**向零截断**（truncate toward zero），小数部分直接丢弃
- 要四舍五入用 `round()`（返回 double，再 cast）；`lround()` 直接返回 long

### 危险边界：UB

```c
double big = 1e20;
int    j = (int)big;    /* UB：超出 int 范围，结果完全不可预测 */
```

- 超出目标整型范围是 **UB**（C11 6.3.1.4），不是"截断"——不同编译器/平台结果可能不同
- 浮点转整数前**必须做范围判断**（`isfinite()` + 上下界检查）

### 指针强转 ≠ 数值转换（新手大坑）

```c
int x = 1;
double *p = (double *)&x;   /* ⚠️ 不是数值转换！ */
```

- `(double)x`：读数值 → 重新编码 → **类型转换**
- `(double *)&x`：原样保留内存比特 → **类型双关**，4 字节 int 被强当 8 字节 double 解读——越界读 + 违反严格别名，双重 UB
- 详见 3.1.3 严格别名一节；合法的比特级查看方式是 `memcpy` 或 union

### int → float 的精度边界

- `int → float`：float 尾数只有 23+1 = 24 位，int 超过 2^24（16777216）就丢精度——`16777217` 转 float 变成 `16777216`

## HFT 核心惯例：定点整数存价格

### 为什么不用浮点存价格

| 问题 | 后果 |
|------|------|
| `0.1` 不能精确表示 | 累加千万次后误差累积 |
| `==` 判等失效 | 撮合时"价格相等"判断出错 |
| 舍入不确定 | 四舍五入规则不统一，跨平台不一致 |
| 非规格化慢 | 极小值运算拖慢热路径 |

### 定点方案

```c
/* 价格用"分"（或厘/毫）存，1 元 = 100 分 */
int64_t price_cents = 12345;   /* 123.45 元 */

/* 加减法直接算 */
int64_t total = price_cents * quantity;   /* 总价（分） */

/* 需要展示时再转浮点 */
double display = price_cents / 100.0;     /* 123.45 */
```

| 路径 | 用什么 | 原因 |
|------|--------|------|
| 撮合/风控核心 | `int64_t` 定点 | 精确、可 `==` 判等、无舍入 |
| 回测/统计 | `double` | 精度够、库函数丰富 |
| 展示/日志 | `double` 或格式化字符串 | 人类可读 |
| 行情解析 | 按交易所协议（常定点） | 交易所规定 |

### 定点的精度管理

- 确定小数位数：分（2 位）、厘（3 位）、毫（4 位）——按交易所规定
- 乘法后要除以 scale 因子——注意溢出（`int64_t` 最大 ~9.2e18）
- 四舍五入用 `(x + 5) / 10` 或银行家舍入

## 字面量

```c
3.14           /* double */
3.14F          /* float */
3.14L          /* long double */
1e-6           /* double, 0.000001 */
1e3            /* double, 1000.0 */
```

- 不加后缀默认 `double`，不是 `float`
- `3.14` 赋给 `float` 会有隐式转换 + 精度截断警告

## HFT 浮点的其他注意

- **浮点运算不满足结合律**：`(a+b)+c` ≠ `a+(b+c)`（舍入方向不同）→ 不能随意重排
- **`-ffast-math`**：允许重排和刷非规格化，快但破坏 IEEE 语义——HFT 慎用
- **FPU 状态字**：x86 浮点运算可能修改 FPU 状态字，多线程切换有开销——定点避免此问题
- **SIMD 向量化**：`double` 可以 AVX 一次算 4 个，但金融核心路径常不需要浮点向量化

## 常见误区

| 误区 | 纠正 |
|------|------|
| `0.1 + 0.2 == 0.3` | 不等，浮点不精确 |
| 浮点 `==` 判等安全 | 不安全，用 epsilon 或定点 |
| `double → int` 超范围只是截断 | 是 UB，不是确定的截断 |
| `float` 更快 | 现代 CPU 上 `float` 和 `double` 速度相当；`float` 省内存/带宽 |
| 价格用 `double` 就行 | 金融核心路径用定点整数，避免舍入和判等问题 |
| 非规格化数无所谓 | x86 上运算慢几十倍，HFT 要避免 |

## 实操

1. `printf("%.20f\n", 0.1 + 0.2)` 看不是 0.3
2. `if (0.1 + 0.2 == 0.3)` 看永远为假
3. `printf("%d\n", (int)1e20)` 看 UB（可能是个垃圾值）
4. 写定点价格加减乘，验证精确
5. `isinf(1.0/0.0)`、`isnan(0.0/0.0)` 看特殊值

## 代码自测

**题目 1：** 以下代码输出什么？为什么？
```c
double d = 0.1 + 0.2;
if (d == 0.3) printf("equal");
else printf("not equal");
```

<details>
<summary>参考答案</summary>

输出 not equal。浮点数在二进制中无法精确表示 0.1 和 0.2，0.1 + 0.2 的结果是 0.30000000000000004，不等于 0.3。比较浮点数应该用误差范围：if (fabs(d - 0.3) < 1e-9)。

</details>

**题目 2：** 以下代码输出什么？为什么？
```c
int64_t big = 9007199254740993;   /* 2^53 + 1 */
double d = big;
printf("%lld\n", (int64_t)d);
```

<details>
<summary>参考答案</summary>

输出 9007199254740992（即 2^53）。2^53 + 1 超出 double 尾数 53 位的精确表示范围——此时 ULP（相邻浮点数间隔）已经是 2，2^53 + 1 落在 2^53 和 2^53 + 2 正中间，舍入到最近的偶数尾数 2^53。丢的是**整数低位**，不是小数。这验证了"大数进浮点丢低位（尾数不够）"这条规则。

</details>

**题目 3：** 判断对错："`double` 能表示 ±1.8×10³⁰⁸，所以任何 int64 都能无损转成 double 再转回来。"

<details>
<summary>参考答案</summary>

错。范围（指数决定）和精度（尾数决定）是两回事。double 只有 53 位尾数，int64 有 63 位有效数字位（外加符号），超过 2^53 的 int64 转成 double 必然丢失低位，round-trip 回不去。范围大只保证"能表示一个近似值"，不保证"每个整数都有位置"。

</details>
