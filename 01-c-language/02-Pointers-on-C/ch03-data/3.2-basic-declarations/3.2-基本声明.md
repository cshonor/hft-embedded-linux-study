# 3.2 基本声明

## 本节讲什么

**声明（declaration）** 告诉编译器"这个名字是什么";**定义（definition）** 同时分配存储。一条 C 声明可同时承载**存储类 / 类型 / 限定符 / 名字 / 初始化**五类信息,这是 C 声明语法比多数语言复杂、却也更贴近硬件的根源。本节是 ch03 的"声明语法总览",四个小节分别细化初始化、数组、指针、隐式声明。

## 要点

### 声明的组成

一条完整声明的位置顺序(读法见 ch11 / K&R "螺旋法则"):

```
[存储类] [类型限定符] [类型说明符] [声明符 = 初始化] ;
   ↑           ↑            ↑            ↑
 static     const        int          a = 10
 extern     volatile     struct T     *p, arr[N]
            restrict     uint32_t
```

- **存储类**:`auto`(默认局部,C23 起改为类型占位)/ `static` / `extern` / `register`(C17 弃用,C23 移除)/ `_Thread_local`(C11)
- **类型限定符**:`const` / `volatile` / `restrict`(C99) / `_Atomic`(C11)
- 一条声明可挂多个名字:`int a, b, c;` —— 但**限定符只对紧跟其后的声明符生效**,`const int a, b;` 中 a、b 都是 const,而 `int *p, q;` 中 q 是 int 不是指针

### 顺序：风格铁律 vs 语法规则

> C11 6.7 的 `declaration-specifiers` 是递归产生式,storage-class / type-specifier / type-qualifier **语法上可以任意顺序**。但 C11 6.11.5 把"storage-class 不放开头"标记为 **obsolescent feature**（过时特性,将来可能移除）。

| 写法 | 定性 | 说明 |
|------|------|------|
| `static const int a;` | ✅ 推荐写法 | 存储类放开头,工程铁律 |
| `const static int a;` | ✅ 合法 | 限定符之间顺序无所谓 |
| `int static const a;` | ⚠️ 合法但 obsolescent | 能编译,但标准标记为过时,别这么写 |

> **工程铁律**：存储类放最开头,然后限定符,然后类型说明符,最后声明符。这是风格要求,不是"颠倒了就编译不过"。

### `restrict` 不能放在 declaration-specifiers 里

```c
static restrict char *buf;   /* ❌ 约束违例 */
```

`restrict` 在 declaration-specifiers 位置会修饰**被指向的类型** `char`——但 C11 6.7.3 规定 `restrict` 只能限定**指针类型**,`char` 不是指针 → **约束违例**。

```c
static char *restrict buf;   /* ✅ restrict 在 * 后面,修饰指针本身 */
```

这和 `const` 位置的坑是同一个道理——限定符在 declaration-specifiers 里修饰被指向类型,在 `*` 后面修饰指针本身。`restrict` 只能修饰指针,所以只能在 `*` 后面。

### `const` 位置：declaration-specifiers vs 声明符内部

```c
const uint32_t *p;        /* const 在 declaration-specifiers → 修饰被指向的 uint32_t */
uint32_t * const p;       /* const 在 * 后面(声明符内部) → 修饰指针 p 本身 */
```

| 写法 | const 修饰谁 | 含义 |
|------|-------------|------|
| `const uint32_t *p` | 被指向的 `uint32_t` | `*p` 只读,`p` 可改（指向别处） |
| `uint32_t *const p` | 指针 `p` 本身 | `p` 只读（不能指向别处）,`*p` 可改 |
| `const uint32_t *const p` | 两者都修饰 | `p` 和 `*p` 都只读 |

> `* const p` 里的 `const` **不属于 declaration-specifiers 那一栏**——它落在**声明符**内部。这是很多人搞混的关键：前面的 `const` 修饰被指向类型；`*` 后面的 `const` 修饰指针变量本身。

### `typedef` 是 storage-class

C11 6.7.1 把 `typedef` 归类为 **storage-class specifier**,和 `static`/`extern` 同级,放第一个槽位：

```c
typedef int (*fp)(int);    /* typedef=存储类, int=类型说明符, (*fp)(int)=声明符 */
```

区别是 `typedef` 不创建变量,而是把声明符变成**类型别名**。语法位置和 `static` 完全一样,只是语义不同。

### 声明 vs 定义(易混)

| 形式 | 性质 | 是否分配存储 |
|------|------|--------------|
| `extern int x;` | 声明 | 否,只引别处定义 |
| `int x;` | **定义**(tentative,可被合并) | 是 |
| `int x = 1;` | 定义(带初值) | 是 |
| `static int s;` | 定义(内部链接) | 是 |
| `struct T;` | 前向声明 | 否 |

- 文件域**重复定义**同一外部符号 → 链接器 `multiple definition of 'x'`(现代 ld 默认 `-fno-common` 后)
- 头文件只放 `extern` 声明,定义放 `.c` —— 这是工程铁律,见 3.6

## 限定符三宝(底层视角)

| 限定符 | 语义(编译器视角) | 典型 HFT 用途 | 反例(陷阱) |
|--------|------------------|---------------|------------|
| **const** | 写该对象为 UB;可进 `.rodata` | 报文缓冲入参 `const uint8_t *pkt`、配置表 | const 局部仍可能在栈,不保证 ROM |
| **volatile** | 每次访问必须真访存,禁寄存器化/重排 | MMIO 寄存器、ISR 共享标志 | 热路径滥用 → 破坏优化、增延迟 |
| **restrict** | 承诺该指针是对象的**唯一访问路径** | DPDK `rte_memcpy` 拷贝、向量化热点 | 承诺不成立 → UB,难复现的数据损坏 |

> ⚠️ **HFT 铁律**:热路径(`rte_pipeline` / 收包回调)里 `volatile` 只给**真 MMIO 和 ISR 标志**。用 `volatile` 当"线程同步"是经典错误 —— 它不保证原子、不保证内存序,该用 `_Atomic` 或 `rte_atomic`/`stdatomic.h`。

## 何时该拆声明、何时不该

| 场景 | 做法 |
|------|------|
| 公共 API | 头文件 `extern` 声明 + `.c` 定义 |
| 模块私有 | 文件域 `static`,不进头文件 |
| 跨线程共享 | `_Atomic` 或显式锁,别靠 `volatile` |
| 性能热点入参 | `const + restrict` 双限定 |
| 配置表 | `static const struct cfg g_cfg = {...};` 进 `.rodata` |

## 常见误区

| 误区 | 真相 |
|------|------|
| `const int x;` 是常量 | 是只读**变量**,不是编译期常量;数组长度要它需 C99 VLA 或 `enum`/`#define` |
| `static` 让变量线程安全 | 只改存储期/链接,与并发无关 |
| `register` 能加速 | 现代编译器无视它;C23 已删除该关键字 |
| 多变量声明 `int* a, b;` b 是指针 | b 是 `int`;`*` 跟声明符不跟类型 |

## 实操

```bash
# 1. 看限定符如何影响段布局
cat > t.c <<'EOF'
const int g_ro = 1;      /* .rodata */
int g_rw = 2;            /* .data   */
int g_bss;               /* .bss    */
static int s_rw = 3;     /* .data, 内部链接 */
EOF
gcc -c t.c && readelf -S t.o | grep -E '\.(rodata|data|bss)'
nm t.o                    # 小写=local(static), 大写=global
```

## 代码自测

**题目 1：** 以下声明各定义了什么？
```c
int a, *b, c[10];
```

<details>
<summary>参考答案</summary>

a 是 int 变量，b 是 int* 指针，c 是 int[10] 数组。注意：* 只修饰 b，不修饰 a 和 c。这是 C 声明语法的常见陷阱——以为 int* a, b 声明了两个指针，实际上 b 是 int。

</details>
