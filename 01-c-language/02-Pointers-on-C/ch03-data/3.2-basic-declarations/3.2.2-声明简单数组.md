# 3.2.2 声明简单数组

## 本节讲什么

**数组**是 C 最基础的聚合类型:连续同类型元素、长度在定义时确定(VLA 是 C99 例外)。数组声明的语法简单,但"数组名在多数表达式里退化为指针"这条规则贯穿 ch06/ch08,是 C 入门与进阶的分水岭。本节先讲声明本身,退化留到后续章节。

## 要点

### 声明形式

```c
int buf[1024];               /* 长度必须是编译期常量(C99 前) */
char msg[64];
uint8_t pkt[1500];           /* MTU 级缓冲 */
int dims[3][4];              /* 多维: 3 行 × 4 列, 行优先 */
const char *names[] = {"a","b"}; /* 指针数组, 2 元素 */
```

- 长度表达式:**整型常量表达式**(C89);C99 起**非常量表达式**产生 VLA(变长数组,栈分配,大小运行时确定)
- 多维数组在内存里是**行优先**连续:`dims[i][j]` 地址 = base + `(i*4 + j)*sizeof(int)`

### sizeof 与退化(decay)

```c
int buf[1024];
sizeof(buf)        == 1024 * sizeof(int)   /* 4096, 仍是数组类型 */
sizeof(buf + 0)    == sizeof(int*)        /* 退化为指针后大小是 8(x64) */

void f(int a[100]) { sizeof(a); }  /* 形参 a 退化为 int*, sizeof==8, 不是 400 */
```

**退化规则**:数组名在以下场景之外都退化为"指向首元素的指针":
1. `sizeof` 操作数
2. `&`(取地址,得到 `int(*)[N]` 指向数组的指针)
3. 字符串字面量初始化数组(`char s[]="abc";`)

> 退化是 C 数组"传参像传指针""sizeof 在函数里失真"的根源。ch06 / ch08 会展开。
>
> ⚠️ **常见记混**：把 `_Alignof` 列入"实际不退化"的场景。C11 6.3.2.1p3 确实列了 `_Alignof`，但 6.5.3.4p3 规定它只接受 **type-name**（`_Alignof(int[100])`），不接受表达式（`_Alignof(arr)` 是 GCC 扩展）。实际中真正重要的三个例外是 `sizeof`、`&`、字符串字面量初始化。

### `&arr` vs `arr`：不退化的 `&`

```c
int arr[10];

/* &arr 不退化：类型是 int(*)[10]——指向整个数组的指针 */
int (*pa)[10] = &arr;     /* ✅ */

/* arr 退化为 int*——指向首元素 */
int *p = arr;             /* ✅ 等价 int *p = &arr[0]; */

/* 数值相同，类型不同，+1 步长差 10 倍 */
printf("%p %p\n", (void*)(arr + 1),  (void*)(&arr + 1));
/* arr+1 跳 4 字节（一个 int）；&arr+1 跳 40 字节（整个数组） */
```

| 表达式 | 退化？ | 类型 | `+1` 步长 |
|--------|--------|------|-----------|
| `arr` | ✅ 退化为 `int*` | `int *` | `sizeof(int)` = 4 |
| `&arr` | ❌ 不退化 | `int (*)[10]` | `sizeof(int[10])` = 40 |
| `&arr[0]` | — | `int *` | `sizeof(int)` = 4 |

> `arr` 和 `&arr` 数值相同（都是数组起始地址），区别在指针类型决定步长。详见 8.1.1。

### `size_t`：sizeof 的返回类型

`sizeof` 返回的不是 `int` 也不是 `unsigned long`，而是 **`size_t`**——标准库定义的"本机适合描述字节数量的无符号整数类型"。

**定义位置**：`<stddef.h>`（最先定义），`<stdlib.h>`、`<string.h>`、`<stdio.h>` 等头文件也会暴露。

**平台自适应**：

| 编译目标 | `size_t` 底层类型 | 宽度 |
|----------|-------------------|------|
| 32 位 (ILP32) | `unsigned int` | 4 字节 |
| 64 位 Linux/Mac (LP64) | `unsigned long` | 8 字节 |
| 64 位 Windows (LLP64) | `unsigned __int64` | 8 字节 |

> `size_t` 解决的是**源码跨平台**——同一份 `.c` 源码在 32 位编译时 `size_t` 自动变 4 字节，64 位编译时自动变 8 字节。不是让同一套二进制跨 32/64 位跑。重新编译时 `size_t` 自适应；如果你的代码写死一个超过 32 位无符号最大值的常量，`size_t` 不会魔法兼容——那是代码本身的问题。

**无符号陷阱**：

```c
size_t a = 0;
a - 1;           // 回绕成 SIZE_MAX（64 位 = 0xFFFFFFFFFFFFFFFF）

/* 经典死循环 */
for (size_t i = n - 1; i >= 0; i--) { ... }  /* i >= 0 恒为真 → 永远不退出 */

/* 正确写法 */
for (size_t i = n; i > 0; i--) { ... i - 1 ... }  /* i 减到 0 退出 */
```

> `SIZE_MAX` 定义在 `<stdint.h>`，是 `size_t` 能表示的最大值。`size_t` 和 `-1` 比较的陷阱在 3.1.1 已讲：`size_t` 和 `int` 同宽或更宽，不触发整数提升，`-1` 被寻常算术转换吞成 `SIZE_MAX`。

**哪些地方用 size_t**：

| 场景 | 例子 |
|------|------|
| `sizeof` 返回值 | `size_t n = sizeof(arr);` |
| `malloc` / `calloc` 参数 | `void *malloc(size_t size);` |
| `memcpy` / `memset` 长度参数 | `void *memcpy(void *dst, const void *src, size_t n);` |
| `strlen` 返回值 | `size_t len = strlen(s);` |
| 数组下标（标准允许） | `arr[i]` 中 `i` 可以是 `size_t` |

### `size_t` vs `uint32_t` vs `uintptr_t`

| 类型 | 头文件 | 位数 | 用途 | 平台自适应 |
|------|--------|------|------|-----------|
| `uint8_t` / `uint32_t` / `uint64_t` | `<stdint.h>` | **写死** | 协议字段、寄存器宽度、定宽类型 | ❌ 位数不变 |
| `size_t` | `<stddef.h>` | **自适应** | 字节计数、数组大小、memcpy 长度 | ✅ 32 位=4, 64 位=8 |
| `uintptr_t` | `<stdint.h>` | **自适应** | 存内存地址（整数形式） | ✅ 跟指针等宽 |

> 一句话：`size_t` 存"字节有多少"，`uintptr_t` 存"地址是什么"，`uint32_t` 存"这块数据按协议是几字节"。

### 数组作参数:指针 + 长度

```c
void parse(const uint8_t *pkt, size_t len);   /* 推荐 */
void bad(int arr[100]);                        /* 长度被忽略, 等价 int *arr */
```

- 函数形参里的 `[N]` 是**糖**,编译器忽略 N,实际是指针
- 因此数组"传值"实际传首地址,函数内 `sizeof(arr)` 拿到指针大小而非数组大小
- 工程规范:**长度显式参数**,别用 `sizeof` 猜数组大小

## 与 HFT/DPDK

### 栈上大数组 = 栈溢出风险

```c
void bad(void) {
    uint8_t pkt[1500];           /* 1.5KB, 一般 ok */
    uint8_t ring[1<<20];         /* 1MB, 8MB 默认栈下危险, 多线程栈更小 */
}
```

- 线程栈常 2MB 甚至更小(Python/某些 RTOS),大数组应改 static / 全局 / 堆 / mempool
- DPDK 收包缓冲、ring table 都从 **hugepage mempool** 取,不在栈上

### 报文定长字段用数组

```c
struct fix_header {
    char msg_type[2];     /* "8"=Execution Report */
    char symbol[8];
    char price[12];       /* 定点字符串, 精度可控 */
};
```

- 金融协议常用定长字符字段而非变长字符串,直接映射报文,免序列化开销

### 数组与缓存局部性

```c
/* 行优先遍历(快): 连续访问, 缓存命中高 */
for (i=0; i<N; i++) for (j=0; j<M; j++) a[i][j]++;

/* 列优先遍历(慢): 跨行跳跃, cache miss 频繁 */
for (j=0; j<M; j++) for (i=0; i<N; i++) a[i][j]++;
```

- 这是 ch08 / ch13 矩阵优化的核心:遍历顺序决定 cache 命中率,影响可达 5-10 倍

### VLA 何时用、何时别用

```c
int n = read_len();
int buf[n];              /* VLA: 在栈, 大小运行时; n<=0 是 UB, 栈溢出风险 */
```

- VLA 灵活但:① 不检查栈大小,易溢出;② 分配/释放有开销;③ C11 改为可选特性
- HFT/嵌入式**禁止 VLA**,改用固定缓冲 + 长度校验,或 `alloca` 显式控制,或 mempool

## 常见误区

| 误区 | 真相 |
|------|------|
| `int a[100]; void f(){ a[100]=0; }` 合法 | 越界 UB;有效下标 0..99 |
| 函数里 `sizeof(arr)` 得到数组大小 | 形参退化,得到指针大小 |
| 多维数组是"指针的指针" | 是连续内存;`int **` 与 `int [N][M]` 布局完全不同 |
| `int a[n];`(VLA)和定长数组等价 | VLA 在栈、大小运行时、不安全,语义不同 |
| `extern int arr[];` 后能用 sizeof | 不能;未知大小,只能当指针用 |

## 实操

```bash
cat > t.c <<'EOF'
#include <stdio.h>
#include <stdint.h>
int buf[1024];
void f(int a[100]){ printf("in f: %zu\n", sizeof(a)); }
int main(void){
  printf("global: %zu\n", sizeof(buf));
  f(buf);
  return 0;
}
EOF
gcc t.c -o t && ./t
# 输出: global: 4096, in f: 8  —— 退化已发生

# 看多维数组布局
cat > m.c <<'EOF'
#include <stdio.h>
int a[3][4];
int main(void){
  printf("%p %p %p\n", (void*)a, (void*)a[0], (void*)&a[0][0]);
  printf("a[1][0] offset=%ld\n", (char*)&a[1][0]-(char*)a);
}
EOF
gcc m.c -o m && ./m   # a, a[0], &a[0][0] 地址相同; offset=16(=1行*4*4)
```

## 代码自测

**题目 1：** 以下两种数组声明有什么区别？
```c
int a[5] = {1, 2, 3};
int b[] = {1, 2, 3, 4, 5};
```

<details>
<summary>参考答案</summary>

a 有 5 个元素，前 3 个初始化为 1、2、3，后 2 个自动初始化为 0（部分初始化时剩余元素为零）。b 的大小由初始化列表决定，是 5 个元素。如果需要全零初始化，可以写 int a[5] = {0};。

</details>

**题目 2：** 64 位 Linux 下，`s1`、`s2` 分别等于多少？
```c
int buf[256];
size_t s1 = sizeof(buf);
size_t s2 = sizeof(buf + 0);
```

<details>
<summary>参考答案</summary>

- **s1 = 1024**：`buf` 直接作为 `sizeof` 操作数 → **不退化**，得到整个数组大小 `256 * sizeof(int)` = `256 * 4` = `1024`。类型 `size_t`。
- **s2 = 8**：`buf + 0` 中 `buf` 参与 `+` 运算 → **退化为 `int*`**，`sizeof(int*)` 在 64 位下 = `8`。

关键：`sizeof(buf)` 和 `sizeof(buf + 0)` 只差一个 `+ 0`，结果差 128 倍——因为 `+` 迫使数组退化，`sizeof` 拿到的不再是数组而是指针。

</details>

**题目 3：** 以下代码有什么问题？
```c
void process(int arr[100]) {
    size_t n = sizeof(arr) / sizeof(arr[0]);
    for (size_t i = 0; i < n; i++) {
        arr[i] *= 2;
    }
}
```

<details>
<summary>参考答案</summary>

`sizeof(arr)` 在函数内是 `sizeof(int*)` = 8，`sizeof(arr[0])` = 4，`n` = 8/4 = **2**——只处理前 2 个元素，其余 98 个被跳过。

函数形参 `int arr[100]` 里的 `100` 被编译器忽略，`arr` 就是指针。正确做法是显式传长度参数：

```c
void process(int *arr, size_t n) {
    for (size_t i = 0; i < n; i++) arr[i] *= 2;
}
```

</details>
