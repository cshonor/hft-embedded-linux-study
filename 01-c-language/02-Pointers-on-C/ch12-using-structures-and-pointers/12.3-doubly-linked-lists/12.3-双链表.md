# 12.3 双链表

## 本节讲什么

单向链表只能「向右走」，删一个节点必须先找到它的前驱；双向链表在每个节点里多塞一个 `prev` 指针，**让每个节点都同时知道自己的前驱和后继**。这一改动看似只是多 8 字节内存，却带来两个结构性能力：

1. **O(1) 摘除已知节点**——不再需要遍历找 prev，写高频删除场景（订单撤单、定时器超时摘除）的关键。
2. **反向遍历**——日志回放、缓冲区回溯等需要从尾向头走的场景不再受限。

本节先定下节点结构、与单链的选型对比，再展开内核 `list_head` 的**哨兵头节点**思想，这是后续 ch13 `container_of`、ch17 通用容器的基石。

## 要点

### 节点结构

```c
#include <stdint.h>
#include <stddef.h>

typedef struct dnode {
    uint64_t        seq;     /* 业务序号，例如订单号 */
    struct dnode   *next;    /* 后继 */
    struct dnode   *prev;    /* 前驱 */
} DNode;
```

内存布局（x86-64，按 8 字节对齐）：

```
偏移  字段       字节
 0    seq         8
 8    next        8
16    prev        8
总大小 sizeof(DNode) = 24，对齐 = 8
```

三个 8 字节字段天然 8 对齐，无 padding。若再追加一个 `void *payload`，仍是 8 对齐，结构紧凑。这是双向链表相对单链「多一个指针」的代价：每节点多 8 字节，换 O(1) 删除。

### 单链 vs 双链 选型对比

| 维度 | 单链表 | 双链表 |
|------|--------|--------|
| 节点内存 | 2 字段（seq + next） | 3 字段（seq + next + prev） |
| 头插 | O(1) | O(1) |
| 头删 | O(1) | O(1) |
| 删**已知节点** | O(n)（必须找 prev） | **O(1)**（直接改 prev/next） |
| 反向遍历 | 不支持 | 支持 |
| 实现复杂度 | 低 | 中（四指针维护） |
| UB 风险面 | 小 | 中（prev/next 任一失配） |
| HFT 典型场景 | 单生产者任务队列、报文批量收 | 订单簿挂单撤单、定时器轮 |

**选型口诀**：**只头删、永远不删中间 → 单链**；**要按业务键随机删 → 双链**。HFT 订单簿里，撤单是按订单号定位后立即摘除，双链是必选。

### 哨兵头节点（内核 list_head 思想）

朴素双链用 `DNode *head`，空链 `head == NULL`，每次插入/删除都要判空处理首尾边界。Linux 内核换了个思路：**头节点本身是真实存在的对象**，`head.next` 和 `head.prev` 初始都指向自己，构成一个自环。

```c
typedef struct list_head {
    struct list_head *next, *prev;
} list_head;

#define LIST_HEAD_INIT(name) { &(name), &(name) }
#define LIST_HEAD(name) \
    struct list_head name = LIST_HEAD_INIT(name)
```

空链判断从 `head == NULL` 变成 `list_empty(head) = (head->next == head)`。带来的红利：

- 插入/删除时**不再需要判空**：`list_add` 永远是「在两个有效节点之间插入」，没有 NULL 分支。
- 头节点恒定存在，**头指针永不变化**，多线程下头节点是只读共享数据，减少了一类竞争。
- `list_for_each` 遍历到 `head` 自身即结束，**终止条件统一**。

代价：每个链多占一个 `list_head` 大小（16 字节）的常驻内存，对内核是可忽略的。

### 朴素双链 vs 哨兵双链 空链状态

```
朴素空链：  head = NULL

哨兵空链：  +--------+
            |  head  |
            | next --+--+
            | prev --+--+   (自环)
            +--------+  |  |
                ^       |  |
                +-------+--+
```

哨兵模式下的「空」不是 NULL，而是**自指**。这种统一形式让所有链表操作的代码路径合并为一条，是工程上极高性价比的设计。

## HFT 关联

### 订单簿双向挂单

限价订单簿的每个价位是一个双向链表头，同价位的订单按时间序挂入。撤单时直接拿到 `DNode *` 指针，O(1) 摘除：

```c
/* 撤单：node 已由订单号哈希表定位 */
dlist_remove(node);      /* O(1) 摘链 */
order_free(node);        /* 归还订单池 */
```

若用单链，撤单要遍历同价位链找前驱，价位挂单多时延迟不可控——HFT 不可接受。

### 双向 prefetch

L1 cache 预取指令 `__builtin_prefetch` 可以指定读方向。双向链表允许同时预取 next 和 prev，做反向回放（例如撮合后回滚）时不用先反向建链：

```c
__builtin_prefetch(cur->next, 0, 0);
__builtin_prefetch(cur->prev, 0, 0);
```

### DPDK rte_ring 与双链的边界

DPDK 的 `rte_ring` 是无锁环形队列，本质上是一个**定长数组 + head/tail 原子索引**，不是链表。它解决的是 SPSC/MPMC 批量入队出队，节点不可摘除。**「需要随机删除」时不能用 rte_ring，必须用双链**——这是 HFT 选型时容易混淆的点。

### 内核 timer wheel

Linux 旧版定时器轮（`include/linux/timer.h`）每个槽位是 `struct list_head`，超时定时器挂双向链。到期检查时整链扫描 + 摘除，O(1) 摘除是性能关键。新版本改用基于 RB-tree 的方案，但 list_head 思路在内核无处不在。

## UB 边界

| 情形 | 后果 | 防护 |
|------|------|------|
| `n->prev` 是已 `free` 的节点 | UAF，可能读到垃圾指针 | 摘链与 free 必须成对，先摘后 free |
| `n->next` / `n->prev` 同时被多核改写 | 数据竞争，UB | 加写屏障 `smp_wmb()` 或用 RCU |
| 删除后未把 `n->next/prev` 置 NULL | 误用旧指针二次摘链 | `LIST_POISON1/2` 注入魔数，触发可识别崩溃 |
| 头节点未初始化就插入 | 野指针 | 用 `LIST_HEAD` 宏初始化，杜绝手动赋值 |

`LIST_POISON1 = ((void *) 0x00100100)`、`LIST_POISON2 = ((void *) 0x00200200)` 是内核在 `list_del` 后写入 next/prev 的「毒药值」，任何后续访问都会触发页错误，让 UAF 立即可见，比 NULL 更易调试。
