# 18.9 静态分析 vs 动态调试边界

## 核心区分

| | 静态分析 | 动态调试 |
|---|---------|---------|
| **工具** | nm / readelf / objdump | GDB / crash / strace / ltrace |
| **程序状态** | 不用跑，分析磁盘上的文件 | 运行中 / 暂停 / core dump |
| **能看到** | 符号、ELF 结构、重定位、汇编 | 内存值、寄存器、栈、变量、断点 |
| **看不到** | 运行时变量的值、动态分配的地址 | — |
| **适用场景** | 链接错误、符号缺失、编译器优化分析、逆向 | 运行时崩溃、逻辑错误、数据竞争 |

## 什么时候用静态分析

### 1. 链接错误

```bash
# 报 undefined reference to foo
nm -D libxxx.so | grep foo        # foo 在不在这个 .so？
nm -u main.o                      # main.o 期望的 foo 是什么名字？
```

### 2. 符号缺失 / 导出问题

```bash
# 内核模块加载报 Unknown symbol
nm -u mod.ko                      # 模块依赖什么？
cat /proc/kallsyms | grep <sym>   # 内核导出了吗？
```

### 3. 分析编译器优化

```bash
# -O2 后行为变了，看编译器做了什么
objdump -dS main_O2.o             # 源码+汇编混排
```

### 4. 没有源码的逆向

```bash
# 只有二进制，没有源码
objdump -d ./unknown_binary       # 反汇编看逻辑
readelf -s ./unknown_binary       # 看符号表找线索
nm -D ./unknown_binary            # 看动态符号，推测功能
```

### 5. ELF 布局 / 段大小

```bash
size a.out                        # text/data/bss 多大？
readelf -S a.out                  # 所有节的大小和地址
readelf -l a.out                  # 运行时 LOAD 段布局
```

## 什么时候用动态调试（GDB）

### 1. 运行时崩溃

```bash
gdb ./app core
(gdb) bt                          # 崩溃栈
(gdb) print *ptr                  # 崩溃时指针的值
```

静态分析看不到运行时的值——变量在运行时才被写入内存。

### 2. 逻辑错误（不崩溃但行为不对）

```bash
gdb ./app
(gdb) break loop_body
(gdb) run
(gdb) next
(gdb) print count                 # 看循环变量实际值
```

### 3. 多线程竞争

```bash
gdb -p <PID>
(gdb) info threads                # 所有线程在干什么
(gdb) thread apply all bt         # 全栈快照
```

### 4. 内存泄漏 / 踩内存

```bash
gdb ./app
(gdb) watch *corrupted_addr       # 谁在写这块内存？
# 或用 Valgrind（更适合内存泄漏）
```

## 完整排错工作流

```
遇到问题
    │
    ├── 编译/链接时错误 ──→ 静态分析
    │   ├── undefined reference → nm -D / nm -u
    │   ├── 符号冲突 → nm -g / readelf -s
    │   └── 段大小异常 → size / readelf -S
    │
    ├── 运行时崩溃 ──→ 动态调试 + 静态辅助
    │   ├── core dump → gdb bt
    │   ├── 崩溃地址 → objdump -d 找函数
    │   └── 依赖缺失 → readelf -d / ldd
    │
    ├── 运行时行为异常 ──→ 动态调试
    │   ├── 逻辑错误 → gdb 断点 + print
    │   ├── 多线程 → gdb info threads
    │   └── 性能问题 → perf（不是 gdb 强项）
    │
    └── 只有二进制 ──→ 静态分析
        ├── 反汇编 → objdump -d
        ├── 符号表 → nm / readelf -s
        └── 依赖 → readelf -d
```

## 工具能力对照

| 能力 | nm | readelf | objdump | GDB |
|------|----|---------|---------|-----|
| 看符号 | ✓ | ✓（更全） | ✓（-t） | ✓（info functions） |
| 看 ELF 结构 | ✗ | ✓（最全） | ✓（-h） | ✗ |
| 反汇编 | ✗ | ✗ | ✓（-d/-S） | ✓（disassemble） |
| 重定位 | ✗ | ✓（-r） | ✓（-r） | ✗ |
| 动态段 | ✗ | ✓（-d） | ✗ | ✗ |
| 运行时变量值 | ✗ | ✗ | ✗ | ✓（print） |
| 断点/单步 | ✗ | ✗ | ✗ | ✓ |
| core dump 分析 | ✗ | ✓（-h 看 CORE） | ✗ | ✓ |

## 思考题

> **静态工具能不能看到程序运行时变量的值？为什么？**

不能。nm/readelf/objdump 分析的是磁盘上的 ELF 文件，变量值在进程运行时才写入内存。静态工具只能看到变量的**地址/偏移**和**初始值**（.data 段里），看不到运行时被修改后的值。运行时值要看 GDB（`print var`）或 `/proc/<pid>/mem`。
