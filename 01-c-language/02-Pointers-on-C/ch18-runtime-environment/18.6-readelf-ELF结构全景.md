# 18.6 readelf：ELF 结构全景

## readelf 是什么

`readelf` 解析 ELF 文件的**所有结构信息**——头部、节、段、符号、重定位、动态段。它是不依赖 BFD 库的纯解析器，输出最原始准确。

> readelf 看**结构**，objdump 看**内容**（特别是反汇编）。

## 常用选项速查

| 选项 | 看什么 | 示例 |
|------|--------|------|
| `-h` | ELF 头（类型、架构、入口地址） | `readelf -h a.out` |
| `-S` | 节头表（所有 sections） | `readelf -S a.out` |
| `-l` | 程序头表（所有 segments） | `readelf -l a.out` |
| `-s` | 符号表（等价 nm 但更详细） | `readelf -s a.out` |
| `--dyn-syms` | 动态符号表 `.dynsym` | `readelf --dyn-syms libdpdk.so` |
| `-r` | 重定位信息 | `readelf -r mod.ko` |
| `-d` | 动态段（依赖哪些 .so） | `readelf -d libdpdk.so` |
| `-a` | 所有信息（汇总） | `readelf -a a.out` |
| `-x .text` | 十六进制 dump 指定节 | `readelf -x .rodata a.out` |

## ELF 头（-h）

```bash
$ readelf -h a.out
Class:                             ELF64
Data:                              2's complement, little endian
Type:                              DYN (shared object file)    ← PIE 可执行
Machine:                           Advanced Micro Devices X86-64
Entry point address:               0x1050
Number of section headers:         31
Number of program headers:         11
```

关键字段：
- **Type**：REL（.o）/ EXEC（可执行）/ DYN（.so 或 PIE）/ CORE（core dump）
- **Entry point**：程序入口地址（`_start`，不是 `main`）
- **Machine**：目标架构

## 程序头表（-l）

```bash
$ readelf -l a.out
  Type           Offset   VirtAddr           PhysAddr           FileSiz  MemSiz   Flg Align
  LOAD           0x000000 0x0000000000000000 0x0000000000000000 0x0006c8 0x0006c8 R   0x1000
  LOAD           0x001000 0x0000000000001000 0x0000000000001000 0x000201 0x000201 R E 0x1000
  LOAD           0x002000 0x0000000000002000 0x0000000000002000 0x0000e0 0x0000e0 R   0x1000
  LOAD           0x002db0 0x0000000000003db0 0x0000000000003db0 0x000260 0x000268 RW  0x1000
  DYNAMIC        0x002dc0 0x0000000000003dc0 0x0000000000003dc0 0x0001c0 0x0001c0 RW  0x8
```

Flag 含义：`R` 只读、`R E` 可读可执行（.text）、`RW` 可读写（.data/.bss）

## 重定位信息（-r）

**内核模块 .ko 的灵魂**。模块编译时不知道函数地址，只留重定位项，`insmod` 时内核填入实际地址。

```bash
$ readelf -r mydriver.ko
Relocation section '.rela.text' at offset 0x3a8 contains 12 entries:
  Offset          Info           Type           Sym. Value    Sym. Name + Addend
0000000000030  000a00000002 R_X86_64_PC32     0000000000000000 printk - 4
0000000000040  000500000002 R_X86_64_PC32     0000000000000000 devm_ioremap - 4
000000000006c  000800000002 R_X86_64_PC32     0000000000000000 platform_driver_register - 4
```

- **Offset**：需要修补的地址（在 .text 中的偏移）
- **Type**：重定位类型（`R_X86_64_PC32` = 相对调用 `call`）
- **Sym. Name**：要填入的符号名

> 内核模块 ko 的重定位段是最重要的信息——加载时内核帮填符号地址，`readelf -r` 看这个过程需要修补哪些地方。

## 动态段（-d）

```bash
$ readelf -d libdpdk.so
  0x0000000000000001 (NEEDED)             Shared library: [libnuma.so.1]
  0x0000000000000001 (NEEDED)             Shared library: [librt.so.1]
  0x0000000000000001 (NEEDED)             Shared library: [libc.so.6]
  0x000000000000000e (SONAME)             Library soname: [librte_eth.so.22]
  0x000000006ffffffb (FLAGS_1)            Flags: DYNSUM
```

- **NEEDED**：运行时依赖哪些 `.so`
- **SONAME**：这个库自己的名字（动态链接器用来找版本）

## DPDK 静态库 .a

DPDK 静态库 `librte_eth.a` 本质是一堆 `.o` 的归档（`ar` 打包），同样可以 readelf 分析：

```bash
# 解包
ar x librte_eth.a

# 分析里面的 .o
readelf -S rte_ethdev.o
nm rte_ethdev.o
```

## 思考题

> **objdump 和 readelf 都能看符号、重定位，核心区别是什么？**

readelf 是**只读解析器**——解析 ELF 结构并显示，不依赖 BFD 库，输出更原始准确；objdump 是**基于 BFD 的工具**——能反汇编（`-d`），能源码混排（`-S`），但解析依赖 BFD 对格式的理解。一句话：readelf 看**结构**，objdump 看**内容**。
