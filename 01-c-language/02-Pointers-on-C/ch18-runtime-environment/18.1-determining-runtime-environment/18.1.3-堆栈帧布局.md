# 18.1.3 堆栈帧布局

## 本节讲什么

x86-64 栈帧的物理布局：`call`/`ret` 指令、`rbp`/`rsp` 寄存器、局部变量在栈上的排列、ABI 对齐要求。这是理解函数调用开销、调试栈回溯、避免栈溢出的基础。HFT 场景里这一节直接决定"能不能用递归"、"局部数组多大安全"、"为什么返回局部变量地址是 UB"。

## 要点

### 栈帧的生命周期

```
调用者                    被调用者
─────                    ─────────
call func     ──────→    [返回地址]    ← rsp 指向
                          [旧 rbp]      ← rbp 指向 (push rbp; mov rbp,rsp)
                          [局部变量]
                          [保存的寄存器]
                          ...
                          [参数 7+]     (若有, 调用者压栈)
                          ───
                          leave         ← mov rsp,rbp; pop rbp
                          ret           ← pop 返回地址, 跳回
            ←──────
```

### call/ret 指令

`call func` 等价于 `push 返回地址; jmp func`：

- 把下一条指令地址压栈（rsp -= 8, [rsp] = 返回地址）
- 跳转到 func

`ret` 等价于 `pop 跳转地址; jmp`：

- 从栈顶取返回地址（跳转地址 = [rsp], rsp += 8）
- 跳回调用者

### 函数 prologue / epilogue

```asm
func:
    push rbp              ; 保存调用者的 rbp
    mov rbp, rsp          ; rbp 指向当前栈帧
    sub rsp, 64           ; 开 64 字节局部变量空间
    
    ; ... 函数体 ...
    
    leave                 ; mov rsp, rbp; pop rbp (恢复调用者 rbp)
    ret                   ; 返回
```

- `rbp`：基址指针，指向当前栈帧，用于定位局部变量（`rbp-8` 是第一个局部变量）
- `rsp`：栈顶指针，随 push/pop/sub 移动
- `leave`：恢复 rsp 和 rbp 到调用者状态
- `ret`：返回调用者

### 局部变量在栈上的排列

```c
void func() {
    int a = 1;      /* rbp-4 */
    char b = 'x';   /* rbp-8 */
    int c = 2;      /* rbp-16 (对齐到 4 字节, b 后 padding) */
    char d[10];     /* rbp-32 */
}
```

栈帧布局（从高地址到低地址）：

```
[rbp]     旧 rbp
[rbp-4]   a (int, 4 字节)
[rbp-8]   b (char, 1 字节) + padding
[rbp-16]  c (int, 4 字节)
[rbp-32]  d (char[10])
```

编译器按对齐要求排列，可能有 padding。`-O0` 时变量按声明顺序，`-O2` 可能重排优化 cache。

### x86-64 System V ABI 要点

| 项 | 规则 |
|----|------|
| 整数/指针参数 | 前 6 个用 rdi, rsi, rdx, rcx, r8, r9 |
| 浮点参数 | 前 8 个用 xmm0-xmm7 |
| 多余参数 | 从右向左压栈 |
| 返回值 | rax（及 rdx 用于 128 位返回） |
| 浮点返回 | xmm0 |
| 被调保存寄存器 | rbx, rbp, r12-r15（被调函数需保存恢复） |
| 调用者保存 | 其他所有（调用前若需保留，调用者保存） |
| 栈对齐 | call 前 rsp 必须 16 字节对齐 |
| 红区 | 叶子函数可用 rsp-128 到 rsp-128 临时空间（不调其他函数时） |

### 寄存器保存约定

- **被调保存（callee-saved）**：`rbx`/`rbp`/`r12`/`r13`/`r14`/`r15`——被调函数若用这些寄存器，必须在 prologue 保存、epilogue 恢复
- **调用者保存（caller-saved）**：`rax`/`rcx`/`rdx`/`rsi`/`rdi`/`r8`-`r11`/`xmm0`-`xmm15`——调用其他函数前若需保留，调用者自己保存

这意味着：调用一个函数后，`rbx` 等被调保存寄存器保证不变，但 `rax` 等可能被改写。

### 栈对齐

x86-64 ABI 要求 `call` 指令执行前 `rsp` 是 16 字节对齐。`call` 压入 8 字节返回地址后，进入函数时 `rsp` 是 `16k - 8`（非对齐）。`push rbp` 后 `rsp` 是 `16k - 16`（对齐），`sub rsp, N` 的 N 通常补足到 16 的倍数。

某些 SIMD 指令（`movdqa`）要求 16 字节对齐，栈对齐保证局部数组能用对齐指令。

### 红区（Red Zone）

System V ABI 规定：叶子函数（不调用其他函数）可以使用 `rsp-128` 到 `rsp-8` 这 128 字节作为临时空间，不需 `sub rsp` 调整。这减少 prologue 开销。

```c
/* 叶子函数, 利用红区 */
int leaf(int x) {
    int tmp = x * 2;   /* 可能放 rsp-4, 红区内 */
    return tmp + 1;
}
```

信号处理会破坏红区（信号 handler 在同栈运行），所以信号安全函数不能用红区。`-mno-red-zone` 禁用（内核代码必须禁用）。

### 工程结论：HFT 禁忌

| 禁止 | 原因 |
|------|------|
| 深递归 | 栈 ~8MB 耗尽 → SIGSEGV |
| 大局部数组 `char buf[1024*1024]` | 栈溢出 |
| 返回局部变量地址 | 函数返回后栈帧失效，悬垂指针 UB |
| 写字符串字面量 `"abc"[0]='x'` | `.rodata` 只读 → SIGSEGV |

### 返回局部变量地址的 UB

```c
int *bad_func() {
    int local = 42;
    return &local;   /* UB! 函数返回后栈帧失效 */
}

int *p = bad_func();
*p;   /* 悬垂指针, 读到的是栈上被覆盖的垃圾 */
```

`ret` 后 `rsp` 回到调用者，`local` 所在栈空间会被后续函数调用复用。访问 `p` 读到的是垃圾，写可能破坏其他函数的栈帧。

正确做法：

- 返回值（非地址）
- 调用者提供缓冲，函数填充
- `malloc` 堆分配（调用者负责 free）
- `static` 局部变量（但失去线程安全）

### gdb 观察栈帧

```bash
(gdb) break func
(gdb) run
(gdb) info frame       # 当前栈帧信息
(gdb) info args        # 参数
(gdb) info locals      # 局部变量
(gdb) x/10gx $rsp      # 查看栈内存
(gdb) backtrace        # 栈回溯
(gdb) frame 2          # 切换到第 2 层栈帧
```

`backtrace` 依赖 `rbp` 链——每层栈帧的 `[rbp]` 指向上层 rbp，遍历这条链得到调用栈。`-fomit-frame-pointer` 优化会省略 rbp 保存，backtrace 依赖 .eh_frame 信息。

### 函数调用开销

一次函数调用的开销：

- `call`：压返回地址 + 跳转（~2-3 周期）
- prologue：push rbp + mov rbp,rsp + sub rsp（~3-5 周期）
- 参数传递：寄存器传参零开销，栈传参有 push 开销
- epilogue：leave + ret（~2-3 周期）

总计 ~10-15 周期。3GHz CPU 约 3-5ns。热路径高频小函数用 `static inline` 消除调用开销。

### tail call optimization（TCO）

```c
/* 尾递归, 编译器可优化成循环 */
int sum(int n, int acc) {
    if (n == 0) return acc;
    return sum(n - 1, acc + n);   /* 尾调用, 无需保留当前栈帧 */
}
```

尾调用：递归调用是函数最后操作，当前栈帧无需保留。编译器优化成 `jmp` 而非 `call`，复用当前栈帧，无栈增长。`-O2` 启用 TCO。

## HFT 关联

- **禁深递归**：数据面报文解析用显式栈迭代，避免栈溢出
- **禁大局部数组**：大缓冲用堆或 mempool，局部数组控制在 KB 级
- **禁返回栈地址**：返回值或调用者提供缓冲
- **inline 消除调用开销**：热路径小函数 `static inline`
- **栈大小调优**：`ulimit -s` 或 `pthread_attr_setstacksize` 按需调整
- **gdb 栈回溯**：崩溃后 `backtrace` 定位调用链，依赖 rbp 链或 .eh_frame
- **红区禁用**：内核代码 `-mno-red-zone`，信号安全函数不能用红区
- **栈对齐**：SIMD 局部数组依赖 16 字节栈对齐
- **TCO**：尾递归优化成循环，无栈增长，但不要依赖（优化选项可能关）
