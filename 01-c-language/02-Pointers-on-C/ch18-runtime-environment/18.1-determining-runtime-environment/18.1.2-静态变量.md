# 18.1.2 静态变量

## 本节讲什么

`static` 关键字的双重含义（内部链接 + 持久存储）、`extern` 声明、跨文件初始化顺序陷阱、动态库符号可见性。这是 C 语言链接属性的核心——理解 `static` 才能写出模块化、无冲突的大型工程代码。

## 要点

### static 的双重含义

`static` 在不同位置含义不同：

| 位置 | 作用 |
|------|------|
| 函数外 `static int x;` | 内部链接（仅本 .c 可见）+ 持久存储（.data/.bss） |
| 函数内 `static int x;` | 持久存储（.data/.bss）+ 函数内作用域 |
| 函数前 `static void f()` | 内部链接（仅本 .c 可调用） |

注意：函数内 `static` 变量持久（跨调用保持值），但作用域仍局部（函数外不可见）。

```c
int counter() {
    static int count = 0;   /* .bss, 持久, 仅 counter 内可见 */
    return ++count;
}
```

### 链接属性三分类

| 关键字 | 链接 | 例子 |
|--------|------|------|
| `static`（函数外） | 内部链接 | `static int x;` 仅本 .c |
| 无 static（函数外） | 外部链接 | `int x;` 全局可见 |
| `extern` | 声明引用 | `extern int x;` 定义在他处 |
| 函数内声明 | 无链接 | `int local;` 栈上 |

### extern 声明 vs 定义

```c
/* a.c */
int g_counter = 0;   /* 定义, 分配存储 */

/* b.c */
extern int g_counter;   /* 声明, 不分配, 引用 a.c 的定义 */
void use() { g_counter++; }
```

- 定义（definition）：分配存储，只能有一处
- 声明（declaration）：声明类型和名字，可多处
- `extern` 声明告诉编译器"这个符号在别处定义，链接时找"

链接时若找不到定义 → `undefined reference` 错误。

### ODR（One Definition Rule）

C 标准：每个外部链接符号在程序中只能有一处定义。违反：

```c
/* a.c */ int x;
/* b.c */ int x;   /* 重复定义 */
```

链接报 `multiple definition of 'x'`。C 比 C++ 宽松（C 允许"临时定义" tentative definition），但工程上仍应避免。

### 头文件放声明，.c 放定义

```c
/* counter.h */
#pragma once
extern int g_counter;          /* 声明 */
void inc_counter(void);        /* 函数声明 */

/* counter.c */
#include "counter.h"
int g_counter = 0;             /* 定义 */
static int internal_state;     /* 内部链接, 不暴露 */
void inc_counter(void) { g_counter++; internal_state++; }
```

头文件放 `extern` 声明和函数原型，`.c` 放定义。`static` 变量和辅助函数只在 `.c` 内，不进头文件。

### 跨文件初始化顺序陷阱

```c
/* a.c */
int buf_size = 1024;

/* b.c */
extern int buf_size;
int *buf = malloc(buf_size * sizeof(int));   /* 全局初始化调用 malloc */
```

**C 标准不规定不同 .c 文件全局变量的初始化顺序**。`b.c` 的 `buf` 初始化时 `buf_size` 可能还是 0（.bss 清零后未加载 .data）。

实际 glibc 行为：按链接顺序初始化，但仍不可依赖。根治方法：

- 复杂初始化放 `main` 开头显式调用
- 用"构造函数"属性 `__attribute__((constructor))`（GCC 扩展）指定优先级
- 惰性初始化（首次访问时检查）

```c
/* 惰性初始化 */
static int *buf = NULL;
static size_t buf_size = 0;

int *get_buf(size_t size) {
    if (!buf) {
        buf = malloc(size * sizeof(int));
        buf_size = size;
    }
    return buf;
}
```

### __attribute__((constructor)) / destructor

```c
void init_module(void) __attribute__((constructor(101)));
void cleanup_module(void) __attribute__((destructor(101)));

void init_module(void) {
    /* main 前执行, 优先级 101 (小先执行) */
}
void cleanup_module(void) {
    /* exit 后执行 */
}
```

GCC 扩展，在 `main` 前后执行。优先级数字小的先执行。用于库的自动初始化/清理，类似 C++ 全局对象构造/析构。

### 动态库符号可见性

```c
/* 默认所有全局符号导出到 .so 动态符号表 */
int api_func(void);   /* 外部可见 */

/* 隐藏符号, 不导出 */
__attribute__((visibility("hidden"))) int internal_func(void);

/* 显式导出 (配合 -fvisibility=hidden) */
__attribute__((visibility("default"))) int api_func(void);
```

编译 `.so` 时用 `-fvisibility=hidden` 默认隐藏所有符号，只显式导出 API：

- 减少动态符号表大小，加快 `dlopen`
- 防止内部符号被外部覆盖
- 优化器对隐藏符号能更激进优化

DPDK/内核模块大量用此特性。Linux 内核等价物是 `EXPORT_SYMBOL`/`EXPORT_SYMBOL_GPL`。

### static 与 inline 配合

```c
/* 头文件里定义 inline 函数, 用 static 避免多重定义 */
static inline int max(int a, int b) {
    return a > b ? a : b;
}
```

`static inline` 让每个 .c 包含头文件时都有自己的副本，链接时不冲突。编译器内联优化，无函数调用开销。C99 起标准支持。

### 内核 EXPORT_SYMBOL 对照

Linux 内核模块的符号导出：

```c
/* 内核模块 */
int my_api(void) { ... }
EXPORT_SYMBOL(my_api);   /* 导出, 其他模块可调用 */

static int my_internal(void) { ... }   /* 不导出, 仅本模块 */
```

`EXPORT_SYMBOL` 把符号加入内核全局符号表，类似 `.so` 的 `visibility("default")`。`static` 函数不导出。

## HFT 关联

- **模块封装**：`static` 辅助函数 + `extern` API 是 HFT 框架模块化基础
- **内部链接防冲突**：多个 .c 的辅助函数同名用 `static` 避免链接冲突
- **符号可见性优化**：`-fvisibility=hidden` 减小 .so，加快动态链接
- **跨文件初始化避免**：复杂初始化放 `main` 开头，不依赖全局构造
- **constructor 属性**：HFT 框架模块自动注册（如策略注册表）
- **static inline**：性能关键小函数放头文件，零调用开销
- **DPDK 符号导出**：`rte_` 前缀 + visibility 控制，版本化符号
- **避免全局可变状态**：`static` 全局变量是隐式耦合，HFT 数据面倾向 per-thread 状态
