# 18.1 判断运行时环境

## 本节讲什么

Linux 进程的虚拟地址空间六大段：`.text`/`.rodata`/`.data`/`.bss`/堆/栈，以及它们在 ELF 加载后的真实布局。这是全书收尾——把 ch02 的变量存储类、ch11 的堆分配、ch07 的栈帧映射到运行时的真实内存布局。理解这一节，前面所有"变量在哪里"的疑问都有了具体答案。

## 要点

### 虚拟地址空间六大段

```
高地址 ┌────────────────────┐
       │ Stack (↓ 向下增长)   │  局部变量、栈帧、信号栈
       │                      │  默认 8MB (ulimit -s)
       │ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ │
       │                      │
       │ mmap 区 (↓ 向下)     │  mmap/malloc 大块、共享库、DPDK hugepage
       │                      │
       │ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ │
       │                      │
       │ Heap (↑ 向上增长)     │  malloc/brk，小块分配
       │                      │
       ├────────────────────┤
       │ .bss                │  未初始化全局/static (加载时清零)
       ├────────────────────┤
       │ .data               │  已初始化全局/static
       ├────────────────────┤
       │ .rodata             │  字符串字面量、const 全局 (只读)
       ├────────────────────┤
       │ .text               │  机器码 (读+执行)
低地址 └────────────────────┘
```

### 各段详解

| 段 | 内容 | 权限 | 加载来源 |
|----|------|------|----------|
| `.text` | 函数编译后的机器码 | 读+执行 | ELF 文件 .text 节 |
| `.rodata` | 字符串字面量、`const` 全局、跳转表 | 只读 | ELF 文件 .rodata 节 |
| `.data` | 已初始化的全局/static 变量 | 读写 | ELF 文件 .data 节 |
| `.bss` | 未初始化或初始化为 0 的全局/static | 读写 | 加载时内核清零，不占 ELF 文件 |
| Heap | `malloc`/`brk`/`mmap` 分配 | 读写 | 运行时动态 |
| Stack | 局部变量、栈帧、返回地址 | 读写 | 运行时动态，向下增长 |

### .bss 不占文件空间

```c
int big[1000000];   /* 未初始化, 在 .bss, 占 4MB 内存但不占 ELF 文件 */
```

`.bss` 段在 ELF 文件里只记录大小和起始地址，实际内存在加载时由内核分配并清零。这就是为什么"未初始化全局数组"不会让可执行文件变大。

### 虚拟地址 vs 物理地址

进程看到的是**虚拟地址**，通过页表映射到物理地址：

- 虚拟地址 0x400000 可能映射到物理地址 0x1F300000
- 不同进程的同一虚拟地址映射到不同物理页
- 访问未映射的虚拟地址 → 缺页 → 内核处理（分配物理页或 SIGSEGV）

缺页（page fault）是惰性分配的基础——`malloc` 只预留虚拟地址，真正访问时才分配物理页。

### mmap 区：大块与共享

```c
void *p = mmap(NULL, 4096, PROT_READ|PROT_WRITE,
               MAP_PRIVATE|MAP_ANONYMOUS, -1, 0);
```

`mmap` 在堆和栈之间分配独立映射区：

- 大块 `malloc`（通常 > 128KB）用 `mmap` 而非 `brk`
- 共享库 `.so` 加载到 mmap 区
- DPDK hugepage 用 `mmap(MAP_HUGETLB)` 映射 2MB/1GB 大页
- `MAP_SHARED` 让多进程共享同一物理页（DPDK 多进程模式）

### 堆与栈的增长方向

- 堆向上增长（`brk`/`sbrk` 提升堆顶）
- 栈向下增长（`rsp` 递减）
- 中间是 free 空间，两者相向增长

栈默认 8MB（`ulimit -s`），堆可达 GB 级。栈溢出（深递归、大局部数组）→ SIGSEGV。

### readelf 观察段布局

```bash
readelf -S ./a.out   # 列出所有 section
readelf -l ./a.out   # 列出 program headers (加载段)
objdump -h ./a.out   # 类似 readelf -S
```

输出示例：

```
Section Headers:
  [ 1] .text   PROGBITS  0000000000401000  001000  0001a0  00  AX  0   0 16
  [ 2] .rodata PROGBITS  0000000000402000  002000  000020  00   A  0   0  4
  [ 3] .data   PROGBITS  0000000000403000  003000  000010  00  WA  0   0  8
  [ 4] .bss    NOBITS    0000000000403010  003010  000008  00  WA  0   0  4
```

- `AX` = Alloc + eXecute（.text）
- `A` = Alloc（.rodata 只读）
- `WA` = Write + Alloc（.data/.bss 可写）
- `NOBITS` = 不占文件（.bss）

### /proc/self/maps 观察运行时布局

```bash
cat /proc/self/maps
```

输出进程当前的内存映射，每行一个映射区：

```
00400000-00401000 r-xp 00000000 ...  /path/to/a.out   (.text)
00600000-00601000 r--p 00000000 ...  /path/to/a.out   (.rodata)
00601000-00602000 rw-p 00001000 ...  /path/to/a.out   (.data/.bss)
7f...           r-xp 00000000 ...  /lib/libc.so.6    (共享库)
7ffff7...
7ffff7fff000-rwxp 00000000 ...  [stack]              (栈)
```

这是调试内存问题、验证布局的利器。

### DPDK 的内存布局特殊性

DPDK 用 hugepage + `MAP_SHARED`：

- hugepage：2MB 或 1GB 大页，减少 TLB miss
- `MAP_SHARED`：多进程共享同一物理大页（primary/secondary 模式）
- 内存预分配：启动时一次性映射所有大页，运行时不再 `mmap`
- 物理连续：DMA 要求物理连续，hugepage 提供大块连续物理内存

DPDK 进程的 `/proc/<pid>/maps` 会看到大量 `hugepage` 映射，这是与普通进程的最大区别。

## HFT 关联

- **地址空间布局理解**：调试段错误、内存泄漏的基础
- **`.bss` 不占文件**：大型静态查表（如合约表）放 `.bss` 不增可执行文件体积
- **`.rodata` 只读保护**：字符串字面量、配置常量写修改触发 SIGSEGV，帮助捕获 bug
- **hugepage 减 TLB miss**：DPDK 强制 hugepage，TLB miss 从微秒降到纳秒
- **`MAP_SHARED` 多进程**：DPDK primary/secondary 共享订单簿、行情缓冲
- **mmap 区零拷贝**：`mmap` 行情文件做内存映射，避免 `fread` 拷贝
- **栈大小限制**：数据面禁深递归、禁大局部数组，避免栈溢出 SIGSEGV
- **`/proc/<pid>/maps` 调试**：OOM、内存泄漏、共享库加载问题的第一现场
