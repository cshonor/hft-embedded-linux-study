# 18.1.1 测试程序

## 本节讲什么

用打印地址 + `readelf` 实际观察进程各段的地址分布，以及 `crt0 → main` 的启动流程。这是把抽象的"段布局"变成可触摸的具体地址的实操——亲眼看到 `main` 在 `.text`、字符串字面量在 `.rodata`、`malloc` 在堆、局部变量在栈。

## 要点

### 测试程序

```c
#include <stdio.h>
#include <stdlib.h>

int g_init = 42;        /* .data, 已初始化全局 */
int g_zero;             /* .bss, 未初始化全局, 加载时清零 */
static int s_init = 1;  /* .data, static 仍在 .data, 但不导出符号 */
static int s_zero;      /* .bss, static 仍在 .bss */

int main(void)
{
    int local = 0;                  /* 栈 */
    void *heap = malloc(16);        /* 堆 */
    
    printf("text   main   %p\n", (void *)main);
    printf("rodata \"str\"  %p\n", (void *)"quote");
    printf("data   g_init %p\n", (void *)&g_init);
    printf("data   s_init %p\n", (void *)&s_init);
    printf("bss    g_zero %p\n", (void *)&g_zero);
    printf("bss    s_zero %p\n", (void *)&s_zero);
    printf("stack  local  %p\n", (void *)&local);
    printf("heap   malloc %p\n", heap);
    
    free(heap);
    return 0;
}
```

### 典型输出（x86-64 Linux, PIE 关闭）

```
text   main   0x401000
rodata "str"  0x402004
data   g_init 0x404010
data   s_init 0x404014
bss    g_zero 0x404020
bss    s_zero 0x404024
stack  local  0x7fffffffe24c
heap   malloc 0x602010
```

观察规律：

- `.text`（`main`）和 `.rodata`（字符串）地址最低，相近
- `.data` 和 `.bss` 紧随其后，`s_init`/`s_zero` 与全局变量同段（static 只影响链接不影响存储）
- 堆地址在 `.bss` 之上（`brk` 从 `.bss` 末尾向上扩展）
- 栈地址最高（`0x7fff...`），接近用户态顶

### PIE（Position Independent Executable）

现代 Linux 默认开启 PIE，每次运行地址不同（ASLR 地址空间随机化）：

```
$ ./a.out
text   main   0x555555555500
$ ./a.out
text   main   0x5555555550a0   ← 地址变了
```

PIE 是安全特性（防 ROP 攻击），但调试时地址变化不便。`gcc -no-pie` 关闭 PIE 固定地址。

### readelf 观察段

```bash
$ readelf -S ./a.out
Section Headers:
  [ 1] .text   PROGBITS  0000000000401000  001000  0001a0  00  AX  0   0 16
  [ 2] .rodata PROGBITS  0000000000402000  002000  000020  00   A  0   0  4
  [ 3] .data   PROGBITS  0000000000403000  003000  000010  00  WA  0   0  8
  [ 4] .bss    NOBITS    0000000000403010  003010  000008  00  WA  0   0  4
```

字段含义：

- `Addr`：段在虚拟地址空间的起始地址
- `Offset`：段在 ELF 文件中的偏移
- `Size`：段大小
- `Flags`：`AX`(执行) `A`(只读) `WA`(可写) `NOBITS`(不占文件)

### 启动流程：crt0 → main

程序不是直接进 `main`。ELF 入口点 `_start`（由 `crt0.o` 提供）做一系列初始化：

```
1. 内核 execve(2) 加载 ELF
   → 分配虚拟地址空间
   → 映射 .text/.rodata/.data
   → .bss 清零
   → 设置 argc/argv/environ 在栈上
   → 跳到 ELF 入口点 _start

2. _start (crt0.o)
   → 设置栈帧
   → 调用 __libc_start_main
     → 初始化线程局部存储 (TLS)
     → 初始化 stdio (stdin/stdout/stderr)
     → 注册 atexit 回调
     → 解析环境变量
     → 加载动态库 (ld.so)
   → 调用 main(argc, argv, environ)

3. main 返回
   → __libc_start_main 调用 exit
     → 跑 atexit 回调 (逆序)
     → flush stdio
     → 删 tmpfile
     → _exit(返回码) 交给内核
```

### 启动链的工程意义

- **静态变量在 main 前已初始化**：`.data` 从 ELF 文件加载，`.bss` 由内核清零，`main` 开始时全局变量已就绪
- **stdio 在 main 前可用**：`printf` 不需手动初始化
- **动态库在 main 前加载**：`dlopen` 之前，`LD_PRELOAD` 的库已就位
- **atexit 在 main 后执行**：`main` return 触发完整退出链

### 退出路径

| 退出方式 | atexit | flush stdio | tmpfile 删除 | core dump |
|----------|--------|-------------|--------------|-----------|
| `return` from main | ✓ | ✓ | ✓ | ✗ |
| `exit(0)` | ✓ | ✓ | ✓ | ✗ |
| `_exit(0)` | ✗ | ✗ | ✗ | ✗ |
| `abort()` | ✗ | 部分 | ✗ | ✓ |
| SIGSEGV/SIGABRT | ✗ | ✗ | ✗ | ✓ |

异常退出（abort/信号）跳过 atexit 和 stdio flush，日志可能丢失。崩溃前 `fflush(stderr)` 保证错误信息输出。

### ASLR 与地址随机化

```
$ cat /proc/sys/kernel/randomize_va_space
2   ← 0 关闭, 1 部分, 2 完全
```

- 栈地址随机
- 堆地址随机
- mmap 区（共享库）随机
- `.text` 地址随机（仅 PIE 编译时）

ASLR 防 ROP 攻击，但调试时地址变化不便。`setarch -R` 或 `echo 0 > /proc/sys/kernel/randomize_va_space` 关闭。

## HFT 关联

- **调试段错误**：`/proc/<pid>/maps` + `readelf` 定位崩溃地址所在段
- **ASLR 与延迟**：ASLR 增加首次访问缺页，HFT 启动后 warm-up 预热所有页
- **静态链接**：HFT 数据面用 `-static` 避免 `ld.so` 动态解析，启动快且确定
- **crt0 开销**：动态链接程序启动需解析 `.so`，HFT 用静态链接减少启动时间
- **atexit 资源清理**：HFT 注册 atexit 回调 dump 订单簿快照、关闭连接
- **崩溃前 fflush**：信号 handler 里 `fflush(stderr)` 保证栈帧输出不丢
- **hugepage 预留**：启动前 `sysctl vm.nr_hugepages` 预留，避免运行时缺页

## 代码自测

**题目 1：** 以下代码探测栈的增长方向，原理是什么？
```c
void sub(int *prev) {
    int curr;
    if (prev) {
        if (&curr > prev) printf("stack grows up\n");
        else printf("stack grows down\n");
    }
    sub(&curr);
}
```

<details>
<summary>参考答案</summary>

比较两次函数调用的局部变量地址。如果后调用的 curr 地址大于先调用的 prev 地址，栈向上增长；反之向下增长。大多数系统栈向下增长（地址递减）。注意：比较不同栈帧的局部变量地址在技术上是实现定义行为，但实际可行。

</details>
