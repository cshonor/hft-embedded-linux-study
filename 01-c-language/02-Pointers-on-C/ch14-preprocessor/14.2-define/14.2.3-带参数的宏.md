# 14.2.3 带参数的宏

## 本节讲什么

函数宏的高级用法：**`#` 字符串化**、**`##` 标记拼接**、**`__VA_ARGS__` 可变参数**、**`do { } while(0)` 多语句宏**。这四样是宏区别于函数的核心能力——它们让宏能在预处理阶段做「符号操作」，是 C 工程实现代码生成、日志框架、断言机制的基础。

认知锚点：`#` 和 `##` 是预处理器独有的运算符，函数完全做不到。`__FILE__`/`__LINE__` 只能在宏里捕获调用点。`do {} while(0)` 是多语句宏的语法包装。理解这四样，才能读懂内核/DPDK 的宏密集代码，才能写出自己的日志/断言/代码生成宏。

## 要点

### 函数宏基础

```c
#define MIN(x, y)  ((x) < (y) ? (x) : (y))
#define MAX(x, y)  ((x) > (y) ? (x) : (y))
#define ABS(x)     ((x) < 0 ? -(x) : (x))

int m = MIN(3, 5);   /* 展开：((3) < (5) ? (3) : (5)) = 3 */
```

函数宏的参数是文本替换——参数 `x` 在宏体中每次出现都被替换成调用时的实参文本。括号规则见 14.2.1。

### `#` 字符串化

```c
#define STR(x)      #x
#define LOG_VAR(name) printf(#name " = %d\n", name)

int seq = 42;
LOG_VAR(seq);
/* 展开：printf("seq" " = %d\n", seq); */
/* 输出：seq = 42 */

const char *s = STR(hello world);
/* s = "hello world" */
```

`#` 紧贴参数名，把参数的文本形式转成字符串字面量。**字符串字面量相邻自动拼接**，所以 `"seq" " = %d\n"` 等价 `"seq = %d\n"`。

#### 字符串化中的转义

```c
#define STR(x) #x

const char *s1 = STR("quoted");   /* s1 = "\"quoted\"" */
const char *s2 = STR(a\b);        /* s2 = "a\\b" */
```

`#` 会自动转义字符串内的 `"` 和 `\`。这让 `STR("quoted")` 的结果是字面量 `"\"quoted\""`（包含转义引号的字符串）。

### `##` 标记拼接

```c
#define CONCAT(a, b)   a##b
#define PKT_TYPE(name) PKT_##name

uint32_t t = PKT_TYPE(QUOTE);
/* 展开：PKT_QUOTE */

int xy = CONCAT(he, llo);
/* 展开：hello（一个标识符） */
```

`##` 把两个 token 拼成一个新 token。**必须是合法的 token**——`##` 拼出的结果必须是标识符、数字、或运算符，否则编译错误。

#### X-Macro 技巧

```c
/* msg_types.def：类型表（被多次包含） */
DEFINE_MSG_TYPE(HEARTBEAT, 0, "HEARTBEAT")
DEFINE_MSG_TYPE(QUOTE,     1, "QUOTE")
DEFINE_MSG_TYPE(ORDER,     2, "ORDER")
DEFINE_MSG_TYPE(CANCEL,    3, "CANCEL")

/* 头文件：用宏生成枚举 */
enum msg_type {
    #define DEFINE_MSG_TYPE(name, val, str) MSG_##name = val,
    #include "msg_types.def"
    #undef DEFINE_MSG_TYPE
    MSG_TYPE_NUM
};

/* 头文件：用宏生成字符串表 */
static const char *const msg_type_str[] = {
    #define DEFINE_MSG_TYPE(name, val, str) [val] = str,
    #include "msg_types.def"
    #undef DEFINE_MSG_TYPE
};

/* 头文件：用宏生成处理函数声明 */
#define DEFINE_MSG_TYPE(name, val, str) \
    void handle_##name(struct rte_mbuf *pkt);
#include "msg_types.def"
#undef DEFINE_MSG_TYPE
```

**X-Macro** 是 C 代码生成的经典技巧：一份 `.def` 文件定义数据，多次包含并用不同宏展开生成枚举、字符串表、函数声明等。新增类型只需改 `.def` 一处，所有生成的代码自动同步。内核、DPDK 大量使用这种模式。

### `__VA_ARGS__` 可变参数

```c
#define LOG(fmt, ...)  printf("[LOG] " fmt, __VA_ARGS__)

LOG("x=%d\n", x);    /* printf("[LOG] " "x=%d\n", x); */
LOG("ok\n");         /* printf("[LOG] " "ok\n", ); <-- 末尾逗号错误！ */
```

C99 的 `__VA_ARGS__` 代表所有可变参数。但**无参时末尾逗号导致编译错误**。解决方案：

```c
/* GCC 扩展：## 去掉前面的逗号 */
#define LOG(fmt, ...)  printf("[LOG] " fmt, ##__VA_ARGS__)

LOG("ok\n");         /* printf("[LOG] " "ok\n"); <-- 逗号被去掉 */
LOG("x=%d\n", x);    /* printf("[LOG] " "x=%d\n", x); */
```

`##__VA_ARGS__` 是 GCC 扩展，`__VA_ARGS__` 为空时 `##` 会吃掉前面的逗号。C20/C23 引入 `__VA_OPT__` 提供标准方案：

```c
/* C23 标准 */
#define LOG(fmt, ...)  printf("[LOG] " fmt __VA_OPT__(,) __VA_ARGS__)

LOG("ok\n");         /* printf("[LOG] " "ok\n"); <-- __VA_OPT__() 为空 */
LOG("x=%d\n", x);    /* printf("[LOG] " "x=%d\n", x); <-- __VA_OPT__(,) 为逗号 */
```

`__VA_OPT__(x)` 在 `__VA_ARGS__` 非空时展开为 `x`，为空时展开为空。这是标准化的逗号消除方案。

### 命名参数 vs `__VA_ARGS__`

```c
/* C99：可变参数只能用 __VA_ARGS__ */
#define LOG(level, fmt, ...) log(level, fmt, ##__VA_ARGS__)

/* GNU 扩展：可命名可变参数 */
#define LOG(level, fmt, args...) log(level, fmt, ##args)
```

GNU 扩展允许给可变参数命名（`args...`），可读性更好但非标准。可移植代码用 `__VA_ARGS__`。

### `do { } while(0)` 多语句宏

```c
#define SWAP(a, b) do { \
    typeof(a) _tmp = (a); \
    (a) = (b); \
    (b) = _tmp; \
} while (0)

if (cond)
    SWAP(x, y);     /* 单语句位置正确 */
else
    other();

/* 若宏体是 { ... }（无 do-while） */
#define BAD_SWAP(a, b) { typeof(a) _t = (a); (a) = (b); (b) = _t; }

if (cond)
    BAD_SWAP(x, y);  /* 末尾分号导致 else 无 if 配对，编译错误 */
else
    other();
```

`do { ... } while(0)` 是多语句宏的标准包装：

1. **单语句语义**：`do-while` 循环整体是一个语句，可放在任何单语句位置（`if`/`for` 体）。
2. **分号自然**：调用方写 `SWAP(x, y);` 末尾分号自然结束语句。
3. **作用域隔离**：宏内局部变量（`_tmp`）在 `do-while` 块内，不污染外部。

替代方案 `{ }` 的问题是末尾分号会制造空语句，与 `if-else` 配对出错。

### 宏内 `goto` 与 `return`

```c
#define TRY(cond, label) \
    do { if (!(cond)) goto label; } while (0)

int f(void) {
    void *a = malloc(100);
    TRY(a, fail_a);

    void *b = malloc(200);
    TRY(b, fail_b);

    /* ... */
    return 0;
fail_b:
    free(a);
fail_a:
    return -1;
}
```

宏内 `goto` 是错误处理的常见模式，但**宏内 `return` 是坏实践**——隐藏控制流，调用方不知道宏会 return。`goto` 至少跳到函数内的可见 label。

## HFT 关联

### DPDK rte_log

```c
#define rte_log(level, type, fmt, ...) \
    do { \
        if (rte_log_get_level(type) >= level) \
            __rte_log(level, type, fmt, ##__VA_ARGS__); \
    } while (0)
```

三个宏技巧的集成：① `do-while(0)` 多语句；② `##__VA_ARGS__` 可变参数去逗号；③ 内嵌 `if` 实现日志级别过滤。生产环境关日志时 `rte_log_get_level` 返回低值，整个 `do-while` 优化为空，**零开销**。

### 内核 pr_info / pr_err

```c
#define pr_info(fmt, ...)  printk(KERN_INFO pr_fmt(fmt), ##__VA_ARGS__)
#define pr_err(fmt, ...)   printk(KERN_ERR  pr_fmt(fmt), ##__VA_ARGS__)

#define pr_fmt(fmt) KBUILD_MODNAME ": " fmt   /* 模块名前缀 */
```

`pr_fmt` 是可重定义的格式前缀宏，让每个模块的日志自动带模块名。这种「宏调用宏」的分层设计是 C 工程的常见模式。

### 断言宏

```c
#define ASSERT(cond) do { \
    if (__builtin_expect(!(cond), 0)) { \
        fprintf(stderr, "ASSERT failed: %s at %s:%d in %s\n", \
                #cond, __FILE__, __LINE__, __func__); \
        abort(); \
    } \
} while (0)

#define STATIC_ASSERT(cond, msg) \
    _Static_assert(cond, msg)
```

`ASSERT` 集成四样技巧：① `#cond` 字符串化条件；② `__FILE__`/`__LINE__`/`__func__` 位置捕获；③ `do-while(0)` 多语句；④ `__builtin_expect` 分支预测提示。这是宏的集大成应用。

### 字段偏移生成

```c
#define DEFINE_FIELD(name, type, offset) \
    static inline type get_##name(const uint8_t *p) { \
        return *(type *)(p + offset); \
    } \
    static inline void set_##name(uint8_t *p, type v) { \
        *(type *)(p + offset) = v; \
    }

DEFINE_FIELD(seq, uint64_t, 0)
DEFINE_FIELD(type, uint16_t, 8)
DEFINE_FIELD(price, uint32_t, 16)
/* 生成 get_seq/set_seq/get_type/set_type/... */
```

`##` 拼接 + 函数宏，自动生成协议字段的访问函数。新增字段一行宏调用，避免手写重复代码。

### 代码生成的极限：X-Macro

```c
/* 订单事件 X-Macro */
/* events.def */
EVENT(NEW,      on_new,      "new order")
EVENT(ACK,      on_ack,      "acknowledged")
EVENT(FILLED,   on_filled,   "filled")
EVENT(CANCELLED,on_cancelled,"cancelled")
EVENT(REJECTED, on_rejected, "rejected")

/* 生成枚举 */
enum order_event {
    #define EVENT(name, handler, desc) ORD_EVT_##name,
    #include "events.def"
    #undef EVENT
    ORD_EVT_NUM
};

/* 生成处理函数指针表 */
static const event_handler_t handlers[ORD_EVT_NUM] = {
    #define EVENT(name, handler, desc) [ORD_EVT_##name] = handler,
    #include "events.def"
    #undef EVENT
};

/* 生成描述字符串表 */
static const char *const evt_desc[ORD_EVT_NUM] = {
    #define EVENT(name, handler, desc) [ORD_EVT_##name] = desc,
    #include "events.def"
    #undef EVENT
};
```

一份 `events.def` 生成三份代码（枚举、函数表、字符串表），新增事件改 `.def` 一处，**永远同步**。HFT 策略引擎、协议解析、状态机定义全部适合 X-Macro。

## UB 边界

| 情形 | 后果 | 防护 |
|------|------|------|
| `##` 拼出非法 token | 编译错误 | 拼接前确认结果合法 |
| `##__VA_ARGS__` 跨编译器 | 非 C99 标准 | 用 `__VA_OPT__`（C23）或检测编译器 |
| 多语句宏无 `do-while` | `if-else` 配对错误 | 强制 `do { ... } while(0)` |
| 宏内 `return` | 隐藏控制流 | 用 `goto` 替代 |
| `#` 字符串化未转义 | 字符串内 `"`/`\` 错乱 | 让预处理器自动转义，不要手动处理 |
| X-Macro 宏未 `#undef` | 污染后续展开 | 每次包含后 `#undef` |

### `##` 拼接的合法性

```c
#define BAD(a, b) a##b
int x = BAD(123, 456);   /* 123456，合法数字 */
int y = BAD(+, +);       /* ++，合法运算符 */
int z = BAD(/, *);       /* /*，注释起始，编译错误 */
```

`##` 拼出的必须是合法 token。`/*` 被解析为注释起始，导致后续代码被吞。**宏定义里慎用 `##`**，确认拼接结果合法。
