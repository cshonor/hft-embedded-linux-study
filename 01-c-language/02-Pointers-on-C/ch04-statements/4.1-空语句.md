# 4.1 空语句

## 本节讲什么

**空语句(null statement)** 仅由一个分号 `;` 构成,语法合法、运行时无操作。它本身平淡,却催生了 C 里最常见、最隐蔽的一类 bug:`if (cond);` 后的"空语句"吞掉了条件控制,后续语句无条件执行。本节讲空语句的合法用途、陷阱、以及工程上如何根治。

## 要点

### 语法

```c
;            /* 一个分号就是一条空语句 */
```

空语句在语法上是一条完整语句,可出现在任何语句允许的位置。

### 合法场景

```c
/* 1. 循环体为空: 所有工作在条件/更新里完成 */
while (getchar() != '\n')
    ;                        /* 清空输入行到换行 */

for (; *p; p++)
    ;                        /* 找字符串结尾, 循环体空 */

/* 2. 标签后必须有语句 */
end: ;                       /* goto end; 跳到这里, ; 占位 */

/* 3. 占位(未实现函数体) */
void todo(void)
    ;                        /* 函数体占位, 链接器报 "未定义" 才发现 */

/* 4. 经典惯用法: 活儿全在条件里干完 */
char *p = s;
while (*p++)                 /* 找字符串结尾 */
    ;                        /* 空体有意为之 */
while (*dst++ = *src++)      /* 字符串拷贝, 拷完全 0 退出 */
    ;
```

风格约定:**有意为之的空体,分号必须单独占一行并缩进**——让读者一眼看出不是手滑,而 `while (cond);` 写在同一行则恰恰无法区分是故意还是笔误。

### 陷阱:`if (cond);`

```c
if (flag);                   /* ← 空语句, if 控制到此结束 */
    do_something();          /* ← 无条件执行! */

while (cnt-- > 0);           /* ← 循环体空, 只在条件里递减 */
    process();               /* ← 循环结束后只执行一次 */
```

- 这是**驱动/量化代码最常见隐蔽 bug 之一**:编译通过、单元测试可能恰好通过、线上偶发
- 根因:人眼读缩进,编译器读分号

### 编译器视角:那是两条独立语句

```c
if (x > 0);
    func();
```

编译器眼里不存在"缩进"这种东西,它看到的是:

1. `if (x > 0) ;` —— 条件成立就执行空语句,等于什么都没干
2. `func();` —— 无条件执行的下一条语句

所以运行结果:不管 x 是多少,func() 都会被调用。这类 bug 能通过编译,警告也常常没有,`-Wempty-body` 专抓它。

### while 中招更狠:直接挂死

```c
while (i < n);               /* 死循环: 条件为真就一直转, 体是空的 */
    i++;                     /* 这行不在循环里, 永远轮不到它 */

while (i < n)                /* 正确写法 */
    i++;
```

if 版本只是"多执行一次函数",while 版本是**条件无副作用就死循环挂死**——HFT 场景里一个热路径线程就这么空转吃满一个核,还不报错。

### 与其他"空"陷阱的对比

```c
if (a > 0);                  /* 空语句吞条件 */
if (a = 0) ...               /* 赋值而非比较, 见 4.2 */
if (a == 0); else ...        /* 空语句吞 if, else 成独立 */
```

## 与 HFT/DPDK

### 工程规范:if/else/循环一律 `{}`

- Linux 内核、DPDK、MISRA C 强制要求 if/else/for/while 后**必须加 `{}`,即使单条语句**
- 这一条规范直接消灭 `if (cond);` 类 bug —— 因为 `if (cond) { ; }` 仍可疑,但 `if (cond);` 会被 review 抓出
- GCC/Clang:`-Wempty-body` 把"if/else/while 后跟空语句"标为警告,HFT 团队常升 `-Werror=empty-body`

### 编译器警告开关

```bash
-Wempty-body                 # if/else/while 后空语句
-Wmissing-semicolon          # 部分场景缺分号
-Wparentheses                # 赋值在条件里 / 括号省略导致歧义
-Wall -Wextra                # 综合基础
```

## 常见误区

| 误区 | 真相 |
|------|------|
| `if (flag);` 后的语句受 if 控制 | 不受,空语句吞掉了控制 |
| `while (cond);` 是死循环 | 取决于 cond 是否有副作用;`while (cnt--);` 会自减到 0 退出 |
| 空语句无害 | 合法但常是 bug;review 必查 |
| 加 `{}` 太啰嗦 | 是最有效的防御;现代风格强制 |

## 实操

```bash
cat > t.c <<'EOF'
#include <stdio.h>
int main(void){
  int flag = 0;
  if (flag);
    printf("always runs\n");     /* flag=0 也打印 */
  return 0;
}
EOF
gcc -std=c11 -Wall -Wextra -Wempty-body t.c -o t
# warning: empty body in an 'if' statement
./t                              # 输出 always runs

# 加 {} 后:
sed -i 's/if (flag);/if (flag) {;}/' t.c   # 显式空块, 仍可疑但可读
```

## 代码自测

**题目 1：** 以下代码的循环体会执行几次？
```c
for (int i = 0; i < 5; i++);
    printf("%d\n", i);
```

<details>
<summary>参考答案</summary>

循环体执行 0 次——; 是空语句，作为 for 的循环体。printf 在循环结束后执行一次，但 i 的作用域到 for 结束就消失了（C99），所以会编译错误。如果 i 在 for 外声明，printf 打印 5。这是空语句导致的常见 bug。

</details>
