# 4.5 while 循环

## 本节讲什么

**while 循环** 是"先判断、后执行":条件为假时**零次**循环体。本节讲 while 的执行流程、赋值在条件里的陷阱、break/continue 语义,以及 DPDK 批量收包这种 HFT 典型 while 模式。

## 要点

### 基本语法与流程

```c
while (expr)
    stmt;

/* 带块 */
while (expr) {
    stmt1;
    stmt2;
}
```

执行流程:

1. 求值 `expr`
2. 非 0 → 执行循环体 → 回到 1
3. 0 → 退出循环

- 条件为假时循环体**零次执行**(对比 do-while 至少一次)
- 循环体必须改变条件涉及的变量,否则死循环

### 赋值陷阱(4.2 同源)

```c
while (ret = 0)      /* 赋值 0, 条件恒假, 不执行 */
    ...;
while (ret = 1)      /* 赋值 1, 条件恒真, 死循环 */
    ...;
while ((ret = read()) != 0)   /* 故意赋值 + 比较, 加括号 */
    ...;
```

- 意图比较用 `==`;故意赋值要**加括号并注释**
- `-Wparentheses` 会警告"赋值在条件里"

### break / continue

```c
while (1) {
    if (bad_pkt)
        continue;          /* 跳过本次体剩余, 回 while 条件 */
    if (shutdown)
        break;             /* 跳出 while */
    process();
}
```

| 语句 | 作用 | 在 while 里的效果 |
|------|------|------------------|
| **break** | 跳出**最内层** enclosing 循环或 switch | 立即退出 while |
| **continue** | 跳过剩余体,回到**条件判断** | 回到 while 条件 |

- 多层嵌套 break 只出一层;外层退出需 flag 或 goto(4.9)
- continue 在 while 里**回到条件**;在 for 里**先执行更新**(4.6)—— 二者语义不同

### 无限循环

```c
while (1) { ... }          /* 恒真, 靠 break 退出 */
while (1) { if (cond) break; }
```

- `while(1)` 和 `for(;;)` 等价,都是无限循环
- DPDK 数据面主循环就是这种,靠 shutdown 标志 break

## 与 HFT/DPDK

### 批量收包循环(经典模式)

```c
uint16_t nb;
struct rte_mbuf *pkts[32];

while ((nb = rte_eth_rx_burst(port, q, pkts, 32)) > 0) {
    for (int i = 0; i < nb; i++) {
        if (unlikely(pkts[i]->pkt_len < HDR_MIN)) {
            rte_pktmbuf_free(pkts[i]);
            continue;
        }
        dispatch(pkts[i]);
    }
}
```

- `rte_eth_rx_burst` 返回 0 表示队列空,循环退出 → 线程让出或忙等
- 批量处理降低每包开销:一次 burst 32 个,摊薄分支预测/缓存开销

### 指针遍历字符串

```c
char *p = s;
while (*p) {                /* 到 '\0' 退出 */
    if (*p == target) return p;
    p++;
}
```

- `while (*p)` 是字符串遍历惯用法,见 ch09
- 指针步进 + 终止条件,while 比 for 更自然

### 轮询设备寄存器

```c
volatile uint32_t *stat = (volatile uint32_t *)NIC_STAT;
while (*stat & TX_BUSY) ;    /* 忙等发送就绪 */
```

- MMIO 轮询必须 volatile(3.2.3)
- 忙等(busy-wait)是 HFT 低延迟常态,不让出 CPU

### 分支预测在循环里的影响

- 循环条件每轮都判,**likely 路径是"继续循环"**
- 编译器默认假设 backward branch(回跳)为 taken —— 这是 CPU 静态预测规则
- 因此 `while (cond)` 里 cond 应该"大多时候为真",避免频繁退出导致预测失败

## 常见误区

| 误区 | 真相 |
|------|------|
| `while (ret = 0)` 是比较 | 是赋值,恒假,零次循环 |
| continue 在 while 和 for 里一样 | 在 while 回到条件(不执行更新);在 for 先执行更新 |
| `while (cnt--)` 循环 cnt 次 | 循环 cnt 次,但 cnt 最终变 -1(或 unsigned 下溢) |
| `while (1)` 和 `for(;;)` 有性能差 | 无,等价;编译后都是 jmp 回跳 |
| 忙等轮询"浪费 CPU" | HFT 低延迟场景故意占用 CPU,不切上下文 |

## 实操

```bash
cat > t.c <<'EOF'
#include <stdio.h>
int main(void){
  int n = 5;
  while (n--) printf("%d ", n);   /* 4 3 2 1 0, 共 5 次, n 最终 = -1 */
  printf("\n%d\n", n);            /* -1 */
  return 0;
}
EOF
gcc -std=c11 -Wall t.c -o t && ./t

# 赋值陷阱警告
cat > t2.c <<'EOF'
int main(void){ int r; while (r = 0) ; return 0; }
EOF
gcc -std=c11 -Wall -Wparentheses t2.c   # warning: assignment in condition
```
