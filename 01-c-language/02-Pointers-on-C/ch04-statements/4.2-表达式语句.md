# 4.2 表达式语句

## 本节讲什么

**表达式 + 分号 = 表达式语句**。C 里几乎所有"动作"都是表达式语句:赋值、自增、函数调用。本节讲表达式语句的求值与副作用、`return` 的语义、以及 `if (a = b)` 这个把赋值当比较的经典陷阱 —— 它在 HFT 代码里仍每年制造事故。

## 要点

### 表达式语句的求值

```c
a = 10;                        /* 赋值, 副作用: 改 a */
count++;                       /* 自增, 副作用: 改 count */
rte_ring_enqueue(ring, mbuf);  /* 函数调用, 副作用: 入队 */
(void)close(fd);               /* 显式丢弃返回值 */
a + b;                         /* 求值后丢弃, 无副作用 —— 死代码 */
```

- 表达式求值后**结果丢弃**,除非有副作用(赋值/自增/函数调用)改变状态
- 纯求值无副作用的语句(`a + b;`)是死代码,编译器警告 `-Wunused-value`

### return 语句

```c
return 0;          /* 带值返回, 值经 ABI 约定寄存器传递 */
return;            /* void 函数, 无值 */
return a + b;      /* 表达式, 自动转换为函数返回类型 */
```

- 执行 return 后函数立即结束,**栈帧销毁**(栈指针回退,局部变量失效)
- 返回值经 **ABI** 约定寄存器传递:x86-64 整数/指针走 `rax`,浮点走 `xmm0`;AArch64 整数走 `x0`,浮点走 `v0/d0`
- 返回值表达式**自动转换为函数返回类型**(可能截断/提升,见 ch05)

### ABI 与返回值(ch18 预告)

```
函数调用栈帧(x86-64 System V):
高地址  | 返回地址 |          ← call 指令压入
        | 旧 rbp   |          ← push rbp
        | 局部变量  |
        | ...      |
低地址  | 寄存器保存 |
返回值 ≤ 16 字节: 走 rax/rdx(整数) 或 xmm0/xmm1(浮点)
返回值 > 16 字节: 调用方在 rdi 传隐式指针, 被调方写过去
```

- 大结构体返回时,调用方先分配空间,把地址作为隐式第一参数传入 —— 这是"返回大结构体"开销的根源
- HFT 热路径倾向**指针出参 + 返回错误码**,避免大结构体值返回

### 陷阱:赋值当比较

```c
if (a = b)          /* 赋值: a 被改为 b 的值, 条件是该值是否非 0 */
    do();           /* b 非 0 时执行, 几乎肯定不是意图 */

if (a == b)         /* 比较: 不改 a, 条件是 a 与 b 是否相等 */
    do();
```

- `if (a = b)` 合法但几乎总是 bug —— 意图是 `==`
- GCC/Clang:`-Wparentheses`(默认开)或 `-Wall` 会警告"assignment used as truth value"
- 防御写法:常量在左 `if (0 == a)`,漏一个 `=` 立即编译错(Yoda 风格,争议存在)

### 函数调用语句与返回值丢弃

```c
close(fd);                    /* 返回值丢弃 —— 是否该检查? */
(void)write(fd, buf, n);      /* 显式丢弃, 告诉读者"我知道有返回值" */
if (write(fd, buf, n) < 0)    /* 正确: 检查错误码 */
    handle_err();
```

- HFT 工程规范:**系统调用/库函数返回值默认要检查**,除非 `(void)` 显式声明"故意忽略"
- 静态分析工具(Coverity/cppcheck)把"未检查返回值"列为高危

## 与 HFT/DPDK

### DPDK 返回值检查惯例

```c
int rc = rte_eth_rx_burst(port, q, pkts, 32);   /* 返回包数, ≥0 */
if (rc == 0) continue;                           /* 无包 */
/* ... */
int rc2 = rte_eth_tx_burst(port, q, pkts, rc);
if (rc2 < rc) {
    /* 未发完, 释放剩余 mbuf 防泄漏 */
    for (int i = rc2; i < rc; i++) rte_pktmbuf_free(pkts[i]);
}
```

- DPDK API 几乎都返回 int 错误码或个数,**必须检查**否则内存泄漏/丢包静默
- `rte_errno` 类似 errno,但多线程安全

### 热路径的副作用最小化

```c
/* 反例: 热循环里有无副作用表达式 */
for (i=0; i<n; i++) {
    price + qty;          /* 死代码, 浪费 CPU, 警告 */
}

/* 正解: 副作用明确 */
for (i=0; i<n; i++) {
    notional[i] = price[i] * qty[i];
}
```

## 常见误区

| 误区 | 真相 |
|------|------|
| `if (a = b)` 是语法错误 | 不是,合法但几乎总是 bug |
| `return a + b;` 中 a+b 类型必须匹配函数返回类型 | 不,自动转换(可能截断) |
| `close(fd);` 丢弃返回值无害 | 危险,关闭失败可能导致后续误用 fd |
| `(void)write(...);` 安全 | 仍可能写失败,只是显式声明不检查 |
| 返回大结构体和无开销 | 有,ABI 用隐式指针出参 |

## 实操

```bash
# 1. 赋值当比较警告
cat > t.c <<'EOF'
int main(void){
  int a=1, b=2;
  if (a = b) return 1;   /* 警告: assignment as truth value */
  return 0;
}
EOF
gcc -std=c11 -Wall -Wextra t.c -o t   # warning
# Yoda 写法防漏 =
cat > t2.c <<'EOF'
int main(void){
  int a=1;
  if (1 = a) return 1;   /* 编译错: 赋值给常量 */
  return 0;
}
EOF
gcc t2.c   # error: lvalue required as left operand

# 2. 大结构体返回的 ABI 开销
cat > big.c <<'EOF'
struct Big { char data[64]; };
struct Big make(void){ struct Big b = {0}; return b; }
EOF
gcc -O2 -S big.c -o big.s
# 看 make 是否通过 rdi 隐式指针写返回值
```
