# 4.3 代码块

## 本节讲什么

**复合语句(compound statement,代码块)** `{ ... }` 把多条语句在语法上合成"一条"。它是 C 控制结构的承载容器:if/for/while/函数体都必须是语句,而 `{}` 让多条语句能作为一个整体出现。本节讲代码块的语法、块作用域、栈帧关系、以及工程上"一律加 `{}`"的规范根因。

## 要点

### 语法

```c
{
    statement1;
    statement2;
    /* ... */
}                /* 末尾不需要分号 —— 块本身是语句, 已完整 */
```

- 块内可嵌套块,任意深度
- 块内可声明变量(C99 起可"用到才声明",C89 要求声明在块首)
- 块末尾**不需要分号**(加分号是空语句,无害但多余)

### 块作用域(回顾 3.5.1)

```c
void f(void) {
    int x = 1;              /* 块作用域 */
    {
        int y = 2;          /* 子块作用域, 遮蔽规则适用 */
        int x = 3;          /* 合法但易错, -Wshadow 警告 */
        /* x=3, y=2 可见 */
    }                        /* y 销毁, x 恢复外层 =1 */
}
```

- 块内声明的标识符从声明点到 `}` 结束可见
- 内层同名遮蔽外层,合法但工程规范常禁(`-Wshadow`)
- 块结束:auto 变量销毁(栈指针回退);static 变量保留

### 栈帧与代码块

```c
void f(void) {
    int a;                   /* 进入块: 栈帧扩展 */
    if (cond) {
        int b;               /* 进入子块: 栈帧再扩展 */
        /* a, b 都在栈 */
    }                        /* 退出子块: b 所占栈"释放"(逻辑) */
    /* a 仍有效, b 不可见 */
}
```

- 编译器通常在函数入口一次性分配整个栈帧(不为每层块单独 adjust),但概念上"块结束变量失效"
- 栈指针回退后,内存内容残留,直到下次被覆盖 —— 这就是返回局部地址是 UB 的根因(3.7)

### `{}` 在控制结构里

```c
if (cond) stmt;              /* 单条语句, 不需 {} —— 但工程禁 */
if (cond) { stmt1; stmt2; } /* 多条必须 {} —— 工程强制 */

for (;;) ;                    /* 空循环体, 合法但可疑 */
for (;;) { rx(); tx(); }     /* DPDK 主循环标准写法 */
```

- 语法上 if/for/while 后跟**任意一条语句**(包括空语句、表达式语句、块语句)
- 工程规范:**一律加 `{}`**,即使单条 —— 防止后续追加语句时忘加导致 bug

## 与 HFT/DPDK

### 工程规范:强制 `{}`

| 规范来源 | 要求 |
|----------|------|
| Linux 内核 | if/else/for/while 后必须 `{}` |
| DPDK | 同上 |
| MISRA C | 同上,且块内声明在块首 |
| Google C++ Style | 同上 |

- 这一条规范直接消灭 `if (cond);`(4.1)、悬垂 else(4.4)两大类 bug
- review 第一道关:看控制结构有没有 `{}`

### 资源申请与清理配对

```c
int parse(const uint8_t *pkt) {
    struct rte_mbuf *m = rte_pktmbuf_alloc(pool);
    if (!m) return -ENOMEM;
    /* ... */
    rte_pktmbuf_free(m);          /* 配对释放, 必须在同一可见域 */
    return 0;
}
```

- malloc/alloc 与 free/release 必须在同一代码块或同函数可见域配对
- 跨函数的"申请在 A,释放在 B"是泄漏温床,静态分析难抓

### 块作用域缩小误用面

```c
int parse(const uint8_t *pkt, size_t len) {
    if (len < 8) return -1;
    uint16_t type = pkt[0] << 8 | pkt[1];
    if (type == ORDER) {
        int64_t price = read_int64(pkt+2);   /* 仅本块用 */
        /* ... */
    }
    /* price 不可见 —— 防止误用 */
    return 0;
}
```

- 变量作用域越小,误改、并发访问、维护出错的概率越低
- "用到才声明 + 最小块作用域"是现代 C 工程的核心纪律

## 常见误区

| 误区 | 真相 |
|------|------|
| `if (cond) stmt;` 单条不需 `{}` | 语法对,工程禁;后续加语句易漏 `{}` |
| 块末尾要加分号 | 不需要;加分号是多余空语句 |
| 块结束变量内存清零 | 只是栈指针回退,内容残留 |
| 内层同名变量报错 | 不,合法遮蔽;但 `-Wshadow` 警告 |
| 大括号影响性能 | 不影响;编译器优化掉冗余块结构 |

## 实操

```bash
cat > t.c <<'EOF'
#include <stdio.h>
#include <stdlib.h>
int parse(void){
  char *p = malloc(16); if (!p) return -1;
  {
    int x = 42;               /* 子块, 作用域限此 */
    snprintf(p, 16, "%d", x);
  }                           /* x 销毁, p 仍有效 */
  printf("%s\n", p);
  free(p);                    /* 配对释放 */
  return 0;
}
int main(void){ return parse(); }
EOF
gcc -std=c11 -Wall -Wshadow t.c -o t && ./t   # 42
```
