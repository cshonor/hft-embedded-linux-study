10.1

结构基础知识

本节讲什么

struct 是 C 语言把多个字段绑成单一二进制数据模型的核心机制——协议头、DPDK mbuf 元数据、内核对象、订单簿条目都依赖它。struct 不是面向对象的"类"（无方法、无继承、无封装），它纯粹是内存布局的描述：告诉编译器"这块内存的前 4 字节是 seq，接下来 2 字节是 price"。这种朴素性正是 HFT 喜欢它的原因——零抽象开销，布局可预测。

本节是 struct 章的入口，覆盖声明、嵌套、整体赋值；后续小节展开初始化、访问、对齐、位段、联合。

历史背景

C 的 struct 继承自 CPL（1967）和 BCPL（1966）的 record 概念，1972 年 K&R C 定型。与 C++ 的 class 不同，C struct 无方法、无访问控制、无继承——纯布局描述。C11 标准加入匿名 struct/union 成员，是少数后续扩展。POSIX/DPDK/Linux 内核的几乎所有数据结构都以 struct 为骨架。

要点

基本声明与定义

struct quote_hdr {
    uint32_t seq;        /* 4 字节 */
    uint16_t price;      /* 2 字节 */
    uint8_t  pkt_type;   /* 1 字节 */
};

typedef struct quote_hdr QuoteHdr;   /* typedef 简化 */
QuoteHdr pkt;                       /* 定义变量 */
  • struct quote_hdr 是类型，pkt 是变量
  • typedef 让后续写法更简洁，DPDK/内核标准做法
  • 注意 struct 标签和 typedef 名在不同命名空间，可以同名（见 10.1.1）

字段绑定

struct 把多个字段绑成一个整体，可以整体赋值、传参、返回：

QuoteHdr a = { .seq = 1001, .price = 9999, .pkt_type = PKT_QUOTE };
QuoteHdr b;
b = a;   /* 整体赋值：逐成员拷贝 */

这是与"散落变量"的根本区别——seq/price/pkt_type 在内存中连续且一同移动。

嵌套结构体

struct pkt_head {
    uint32_t magic;
    struct quote_hdr quote;   /* 嵌套 struct */
    uint8_t  payload[64];
};

struct pkt_head *p = /* ... */;
p->quote.seq = 1001;          /* 嵌套访问 */
  • 嵌套 struct 在外层 struct 中内联存储（非指针），布局连续
  • DPDK rte_mbuf、内核 task_struct 都是多层嵌套 struct
  • 嵌套深度无标准限制，但过深影响可读性

整体赋值的代价

QuoteHdr a = {0}, b;
b = a;   /* 编译器生成 memcpy(&b, &a, sizeof(QuoteHdr)) */
  • 小 struct（≤16 字节）：编译器可能展开为寄存器移动，几周期
  • 大 struct（≥64 字节）：生成 memcpy 调用，几十到几百纳秒
  • HFT 铁律：大 struct 传指针（10.4），避免按值拷贝

struct 与数组的对比

维度 struct 数组
成员类型 可异构 同质
访问方式 名字（.field） 下标 [i]
大小 编译期固定 编译期固定（VLA 除外）
整体赋值 支持（b = a） 不支持（需 memcpy）
比较相等 不支持（需 memcmp） 不支持
传参退化 不退化（按值拷贝整个） 退化为指针

struct 不退化为指针是它与数组的关键区别——按值传 struct 会拷贝整个内容。

与 C++ class 的区别

特性 C struct C++ class/struct
方法 无 有
访问控制 无 public/private/protected
继承 无 有
构造/析构 无 有
虚函数 无 有
默认访问 — struct=public, class=private

C++ 的 struct 只是"默认 public 的 class"，但 HFT 代码通常只用 C 风格 struct（POD），避免虚函数表开销。

HFT 关联

  • 协议头建模：struct eth_hdr、struct ip_hdr、struct tcp_hdr 是报文解析的基础
  • DPDK rte_mbuf：核心数据结构是 struct，包含物理地址、长度、端口、时间戳等字段
  • 订单簿条目：struct order { uint64_t order_id; uint32_t price; uint32_t qty; }
  • 内核对象：task_struct、file、socket 都是 struct
  • 共享内存：跨进程共享的 struct 必须用 __attribute__((packed)) 或显式偏移，避免对齐差异（10.3）

实操：协议头 struct

#include <stdint.h>
#include <arpa/inet.h>

struct eth_hdr {
    uint8_t  dst[6];
    uint8_t  src[6];
    uint16_t type;
} __attribute__((packed));

struct ip_hdr {
    uint8_t  ver_ihl;
    uint8_t  tos;
    uint16_t total_len;
    uint16_t id;
    uint16_t flags_frag;
    uint8_t  ttl;
    uint8_t  protocol;
    uint16_t checksum;
    uint32_t src_ip;
    uint32_t dst_ip;
} __attribute__((packed));

/* 解析 */
const uint8_t *pkt = /* 报文指针 */;
const struct eth_hdr *eth = (const struct eth_hdr *)pkt;
uint16_t eth_type = ntohs(eth->type);
if (eth_type == 0x0800) {
    const struct ip_hdr *ip = (const struct ip_hdr *)(pkt + 14);
    /* ... */
}

注意 __attribute__((packed)) 确保 struct 布局与线格式一致，无 padding。

10.1

.1 结构的声明

本节讲什么

声明 struct 涉及类型声明、变量定义、typedef 简化三件套，以及标签命名空间、前置声明、不完全类型等较隐蔽的细节。DPDK 和 Linux 内核有成熟的 struct 声明风格，本节剖析最佳实践与常见陷阱。

要点

三种声明风格

/* 风格 1：标准声明 + typedef（DPDK/内核推荐） */
struct quote_hdr {
    uint32_t seq;
    uint16_t price;
    uint8_t  pkt_type;
};
typedef struct quote_hdr quote_hdr_t;   /* _t 后缀是 POSIX 约定 */
quote_hdr_t pkt;

/* 风格 2：合并声明（最常见） */
typedef struct quote_hdr {
    uint32_t seq;
    uint16_t price;
    uint8_t  pkt_type;
} quote_hdr_t;

/* 风格 3：匿名 struct + typedef（仅单次定义时） */
typedef struct {
    uint32_t seq;
    uint16_t price;
    uint8_t  pkt_type;
} quote_hdr_t;
/* 注意：匿名 struct 无法自引用（见 10.2.3） */

工程推荐：风格 2——既有标签名（支持前置声明和自引用），又有 typedef 简化使用。

标签命名空间

struct 标签在独立命名空间，与普通标识符和 typedef 名不冲突：

struct quote_hdr { /* ... */ };   /* 标签 quote_hdr 在 struct 命名空间 */
typedef struct quote_hdr quote_hdr;  /* typedef 名 quote_hdr 在普通命名空间 */
quote_hdr pkt;                    /* 用 typedef 名 */
struct quote_hdr pkt2;            /* 用标签，也合法 */

DPDK 大量使用 struct rte_mbuf + typedef struct rte_mbuf rte_mbuf 同名约定，既可写 struct rte_mbuf（强调类型），也可写 rte_mbuf（简洁）。

前置声明与不完全类型

struct quote_hdr;   /* 前置声明：只声明标签，不定义布局 */

void process(const struct quote_hdr *p);   /* 合法：指针参数 */

struct quote_hdr pkt;   /* 错误：未定义，编译器不知大小 */
size_t n = sizeof(struct quote_hdr);   /* 错误：不完全类型不能求大小 */
  • 前置声明只够指针使用，因为指针大小与所指类型无关
  • 定义变量、求 sizeof、访问成员都需要完整定义
  • 用途：减少头文件依赖、打破循环依赖（PIMPL 模式）

PIMPL（Pointer to IMPLementation）模式：

/* quote.h */
typedef struct quote_hdr quote_hdr_t;
quote_hdr_t *quote_new(void);
void quote_process(quote_hdr_t *self);

/* quote.c */
struct quote_hdr {   /* 完整定义藏在 .c */
    uint32_t seq;
    uint16_t price;
};

ABI 稳定、编译解耦，C++ 也广泛使用。

typedef 的时机

/* 反例：typedef 在前，标签缺失 */
typedef struct { int x; } point_t;
point_t *p;
/* 无法前置声明 point_t，因为它无标签 */

/* 正例：始终带标签 */
typedef struct point { int x; } point_t;
struct point;   /* 可前置声明 */

定长无符号类型

协议字段必须用 <stdint.h> 的定长类型：

类型 宽度 用途
uint8_t 1 字节 协议标志、小整数
uint16_t 2 字节 端口、长度字段
uint32_t 4 字节 IP 地址、序列号
uint64_t 8 字节 时间戳、订单 ID
int8_t/16_t/32_t/64_t 对应宽度 有符号字段

禁用 int/long——宽度随平台变化（int 在 ILP32 是 16 位，LP64 是 32 位，long 在 LLP64 是 32 位、LP64 是 64 位）。

struct 的作用域

struct file_scope { int x; };   /* 文件作用域 */

void f(void) {
    struct block_scope { int y; };   /* 块作用域 */
    struct block_scope v = { 1 };
}
  • struct 标签遵循普通作用域规则
  • 块作用域 struct 仅在该块可见
  • 头文件中的 struct 是翻译单元级共享

静态断言校验布局

C11 _Static_assert 可在编译期校验 struct 大小：

struct eth_hdr { /* ... */ } __attribute__((packed));
_Static_assert(sizeof(struct eth_hdr) == 14, "eth_hdr must be 14 bytes");

协议头 struct 必须用 _Static_assert 锁定大小，防止 padding 差异导致解析错位。

HFT 关联

  • DPDK：struct rte_mbuf、struct rte_eth_conf、struct rte_pktmbuf 全用风格 2 声明
  • Linux 内核：struct task_struct、struct file、struct socket 用 struct 标签 + 部分 typedef
  • 协议头：struct eth_hdr、struct ip_hdr 必须用 __attribute__((packed)) + _Static_assert
  • PIMPL 模式：HFT 库的公开 API 用前置声明隐藏实现，ABI 稳定
  • 跨进程共享：共享内存中的 struct 必须用定长类型 + packed + _Static_assert

实操：前置声明减少依赖

/* bad: 引入完整定义 */
#include "huge_header_with_full_struct.h"
void process(const struct huge *p);

/* good: 仅前置声明 */
struct huge;   /* 编译器只需指针大小 */
void process(const struct huge *p);

编译时间从 N 秒降到 N 毫秒，是大型 HFT 项目的关键优化。

实操：_Static_assert 防布局漂移

struct tcp_hdr {
    uint16_t src_port;
    uint16_t dst_port;
    uint32_t seq;
    uint32_t ack;
    uint16_t flags;
    uint16_t window;
    uint16_t checksum;
    uint16_t urg_ptr;
} __attribute__((packed));
_Static_assert(sizeof(struct tcp_hdr) == 20, "TCP header must be 20 bytes");

若有人误改字段类型，编译立即失败。

10.1

.2 结构的初始化

本节讲什么

struct 初始化有三种常用方式：顺序初始化（C89）、指定成员初始化（C99 .field =）、零初始化（= {0}）。DPDK mbuf 和协议头清零标配 = {0} 或 memset。本节剖析各方式、部分初始化的隐含规则、以及运行时清零的两种范式。

要点

顺序初始化（C89）

QuoteHdr pkt = {1001, 9999, PKT_QUOTE};
  • 值按声明顺序对应成员
  • 顺序错位是常见 bug：{9999, 1001, PKT_QUOTE} 编译通过但语义错
  • 可读性差，不推荐

指定成员初始化（C99，推荐）

QuoteHdr pkt = {
    .seq      = 1001,
    .pkt_type = PKT_QUOTE,
    .price    = 9999,
};
  • 顺序无关，按名字绑定
  • 可读性强，重构时改成员顺序不影响初始化
  • 未列出的成员自动为 0
  • GCC/Clang/MSVC（C99+）全支持

零初始化

QuoteHdr pkt = {0};   /* 全部成员置 0 */
  • {0} 是 C 标准约定的"通用零初始化"惯用法
  • 对任意类型（struct/array/scalar）都有效
  • 编译器展开为 memset(&pkt, 0, sizeof pkt) 或更优
  • DPDK/内核标配：所有 struct 先零初始化再填字段
/* 运行时清零 */
memset(&pkt, 0, sizeof pkt);   /* 等价于 pkt = (QuoteHdr){0}; */

部分初始化的规则

QuoteHdr a = { .seq = 1001 };   /* price=0, pkt_type=0 */
QuoteHdr b = { 1001 };          /* price=0, pkt_type=0 */

铁律：未列出的成员自动为 0（C89/C99 一致）。这与局部变量"不初始化是垃圾值"不同——只要有初始化列表，未列出的成员都为 0。

陷阱：

void f(void) {
    QuoteHdr pkt;   /* 无初始化列表 → 全部成员是垃圾值！ */
    pkt.seq = 1001; /* 仅 seq 有意义，price/pkt_type 仍是垃圾 */
}

嵌套 struct 的初始化

struct pkt_head {
    uint32_t magic;
    struct quote_hdr quote;
    uint8_t  payload[64];
};

/* C99 指定成员 */
struct pkt_head h = {
    .magic   = 0xDEADBEEF,
    .quote   = { .seq = 1001, .price = 9999, .pkt_type = PKT_QUOTE },
    .payload = { 0x01, 0x02, 0x03 },   /* 其余自动 0 */
};

/* 嵌套可省略外层花括号（不推荐） */
struct pkt_head h2 = { 0xDEADBEEF, { 1001, 9999, PKT_QUOTE }, { 0x01 } };

数组成员的初始化

struct buf {
    uint8_t data[8];
    size_t  len;
};

struct buf b = { .data = { 1, 2, 3 }, .len = 3 };   /* data[3..7] 自动 0 */
struct buf b2 = { .len = 0 };                        /* data 全 0 */

指定数组成员的初始化（C99）

uint8_t crc_table[256] = {
    [0x00] = 0x00, [0x01] = 0x07, [0x02] = 0x0E,
    /* 其余自动 0 */
};
  • 用 [index] = value 指定特定下标
  • 适用于稀疏数组（如 CRC 表、字符映射表）

复合字面量（C99）

pkt = (QuoteHdr){ .seq = 1001, .price = 9999 };   /* 运行时构造 */
  • 在运行时创建临时 struct 值
  • 可用于赋值、传参
  • 生命周期到所在块结束

静态存储 vs 自动存储

static QuoteHdr s_pkt = {0};   /* 静态存储：编译期初始化，进 .bss */
void f(void) {
    QuoteHdr a_pkt = {0};      /* 自动存储：运行时栈上初始化 */
}
  • 静态 struct 的初始化值必须是编译期常量
  • 自动 struct 可用运行时值初始化
  • 静态零初始化进 .bss 段，无运行时开销

HFT 关联

  • DPDK mbuf 初始化：struct rte_mbuf m = {0} 是标准范式，避免未初始化字段导致 UB
  • 协议头构造：struct eth_hdr eth = { .type = htons(0x0800) }，其余字段后填
  • 报文模板：静态 static struct order_tmpl = { .magic = MAGIC, .ver = 2 }，复用时 pkt = tmpl; pkt.seq = next_seq++;
  • 清零成本：memset(&pkt, 0, sizeof pkt) 对 64 字节 struct 约 4-5 ns，HFT 热路径需评估是否可避免
  • 共享内存初始化：跨进程 struct 必须显式 = {0} 或 memset，不能依赖"BSS 自动清零"（共享内存不是 BSS）

实操：部分初始化陷阱

void f(void) {
    QuoteHdr pkt;          /* 无初始化 → 垃圾值 */
    pkt.seq = 1001;
    /* pkt.price 和 pkt.pkt_type 是垃圾 */
    send_pkt(&pkt);        /* UB：发送了垃圾字段 */
}

    pkt.seq = 1001;

}

10.2

结构的访问

本节讲什么

struct 成员访问有两个运算符：.（直接访问，对象是 struct 实体）和 ->（间接访问，对象是 struct 指针）。理解二者的区别、运算符优先级、嵌套与数组的混合访问，是写出正确 C 代码的基础。DPDK/内核代码几乎都用 ->（因为大 struct 总是传指针），栈上小 struct 才用 .。

本节是访问章节的总览，子节展开直接访问、间接访问、自引用。

要点

两种运算符

运算符 对象 等价写法 典型场景
pkt.seq struct 变量 — 栈上小 struct
p->seq struct 指针 (*p).seq 堆对象、传参、DPDK/内核 
QuoteHdr pkt;
QuoteHdr *p = &pkt;

pkt.seq = 1001;   /* 直接访问 */
p->seq  = 1001;   /* 间接访问，等价 (*p).seq */

运算符优先级

C 的运算符优先级中，. 与 -> 优先级最高（与 [] 和后置 () 同级，左结合）：

*p.seq;       /* 等价 *(p.seq)，不是 (*p).seq */
*p->next;     /* 等价 *(p->next)，p->next 先解 */
arr[i].seq;   /* 等价 (arr[i]).seq */
p->arr[i];    /* 等价 (p->arr)[i] */
*p->arr[i];   /* 等价 *((p->arr)[i])，链式解 */

经验法则：-> 总是先于 *，所以 *p->next 是"先取 p->next，再解引用"，而非"先解 p，再取 next"。

嵌套 struct 访问

struct pkt_head {
    uint32_t magic;
    struct quote_hdr quote;
    uint8_t  payload[64];
};

struct pkt_head pkt;
struct pkt_head *p = &pkt;

pkt.quote.seq = 1001;   /* 直接：. 链 */
p->quote.seq  = 1001;   /* 间接：-> 然后 . */
  • p->quote 返回内层 struct（左值），再用 . 访问其字段
  • 混合使用 -> 和 . 是常态——指针路径用 ->，实体路径用 .

数组与 struct 混合

struct order orders[100];
struct order *arr[10];   /* 指针数组 */

orders[0].seq = 1001;     /* 数组下标先，. 后 */
arr[0]->seq = 1001;       /* 数组下标先，-> 后 */

struct ring {
    struct order entries[64];
    size_t head, tail;
};

struct ring *r = /* ... */;
r->entries[r->head].seq = 1001;   /* 三层混合 */

解析：r->entries[r->head].seq

  1. r->entries → struct order 数组（左值）
  2. [r->head] → 取该数组第 head 个元素（struct order 左值）
  3. .seq → 取该 struct 的 seq 字段

多级指针

struct node **pp;   /* 指向指针的指针 */
(*pp)->next = /* ... */;   /* 先解 pp 得 node*，再 -> next */

二级指针在链表操作中常见（如 Node **head 让函数能修改头指针）。

常见错误

/* 错误 1：对指针用 . */
QuoteHdr *p = &pkt;
p.seq = 1001;       /* 编译错误：p 是指针，应用 -> */

/* 错误 2：对实体用 -> */
QuoteHdr pkt;
pkt->seq = 1001;    /* 编译错误：pkt 不是指针 */

/* 错误 3：混淆 * 和 -> 优先级 */
QuoteHdr *p = &pkt;
*p.seq;             /* 等价 *(p.seq)，但 p 是指针，p.seq 错 */
(*p).seq;           /* 正确，但啰嗦，应写 p->seq */

const 与访问

const QuoteHdr *p = &pkt;   /* 指向 const struct 的指针 */
p->seq = 1001;              /* 编译错误：不能修改 const */
uint32_t s = p->seq;        /* OK：只读访问 */
  • const T *p：不能通过 p 修改 struct
  • T *const p = &pkt：p 本身不能改，但可修改 struct
  • const T *const p：两者都 const

offsetof 宏

#include <stddef.h>
size_t off = offsetof(QuoteHdr, price);   /* price 字段的偏移 */
  • 编译期计算字段偏移
  • 用于泛型序列化、协议字段提取
  • 协议头 struct 用 _Static_assert 校验偏移

HFT 关联

  • DPDK rte_mbuf：mbuf->pkt_len、mbuf->data_off、mbuf->port 是热路径访问
  • 协议头解析：eth->type、ip->protocol、tcp->flags 链式访问
  • 订单簿：orders[idx].price、orders[idx].qty 数组+字段
  • 链表遍历：for (node = head; node; node = node->next) 标准范式
  • 性能：-> 涉及一次指针解引用（约 4-5 周期，若 cache 命中），. 是直接偏移（1 周期）。链式 -> 在 cache miss 时是性能杀手。

实操：DPDK mbuf 访问

struct rte_mbuf *m = /* 收到的报文 */;
uint16_t port = m->port;
uint32_t pkt_len = m->pkt_len;
void *data = rte_pktmbuf_mtod(m, void *);   /* 等价 (void *)((char *)m + m->data_off) */

struct eth_hdr *eth = (struct eth_hdr *)data;
uint16_t eth_type = ntohs(eth->type);

注意 rte_pktmbuf_mtod 是宏，内部用 -> 访问 data_off。

实操：链表遍历优先级

struct node { struct node *next; uint64_t id; };
struct node *head = /* ... */;

/* 正确：遍历并访问 */
for (struct node *p = head; p; p = p->next) {
    printf("%lu\n", p->id);
}

/* 错误：混淆优先级 */
for (struct node *p = head; p; p = *p->next) {
    /* *p->next 等价 *(p->next)，即 next 指向的对象，
       不是 next 指针本身 —— 指针类型不匹配，编译警告 */
}

10.2

.1 结构的直接访问

本节讲什么

对struct 实体变量用 . 运算符读写字段，称为"直接访问"。这是 struct 访问的两种基本形式之一，适用于栈上小 struct、静态全局 struct、按值传递的 struct。本节剖析 . 的语义、嵌套与数组混合访问、以及何时选择直接访问而非间接访问。

要点

基本用法

QuoteHdr pkt;            /* 栈上 struct 实体 */
pkt.seq      = 10001;
pkt.price    = 9999;
pkt.pkt_type = PKT_QUOTE;

uint32_t s = pkt.seq;    /* 读取 */
  • pkt.seq 是左值（可读可写）
  • 编译期已知 seq 字段相对 struct 起点的偏移
  • 访问开销：1 条 mov 指令，约 1 周期（cache 命中）

汇编视角

struct point { int x; int y; } p;
p.y = 42;

movl $42, -8(%rbp)     ; p.y 在栈上偏移 -8（p 起点 -12，y 偏移 +4）
  • struct 字段访问编译为基址 + 编译期偏移的寻址
  • 无运行时开销，与访问局部变量几乎等价

嵌套 struct 的直接访问

struct pkt_head {
    uint32_t magic;
    struct quote_hdr quote;   /* 嵌套实体 */
    uint8_t  payload[64];
};

struct pkt_head pkt;
pkt.magic = 0xDEADBEEF;
pkt.quote.seq = 1001;         /* . 链：外层 . 再内层 . */
pkt.quote.price = 9999;
pkt.payload[0] = 0x01;
  • 嵌套 struct 是内联存储，无指针间接
  • pkt.quote.seq 编译为 *(int *)((char *)&pkt + offsetof(quote) + offsetof(seq))
  • 偏移在编译期折叠为常数

数组成员的直接访问

struct ring {
    struct order entries[64];
    size_t head;
};

struct ring r;
r.entries[0].seq = 1001;      /* 数组下标 + 字段 */
r.entries[r.head].price = 9999;
r.head = (r.head + 1) % 64;
  • entries[i] 返回 struct order 左值
  • 再 . 访问其字段
  • 运算符优先级：[] 与 . 同级，左结合

结构体数组的遍历

struct order orders[100];
for (int i = 0; i < 100; i++) {
    orders[i].seq = i;
    orders[i].price = 100 + i;
}
  • orders[i] 是 struct 实体，用 .
  • cache 友好：连续内存访问，预取器有效
  • HFT 订单簿常用定长数组 + head/tail 指针，而非链表

何时用直接访问 .

场景 选择 理由
栈上小 struct（≤16 字节） . 无间接，最快
静态全局 struct . 直接寻址
按值传递的 struct 参数 . 形参是实体副本
嵌套 struct 实体 . 内联存储
数组元素 arr[i] . arr[i] 是实体
大 struct（≥64 字节） ->（指针） 避免按值拷贝
堆对象 malloc 返回 -> 只有指针

const struct 的直接访问

const struct config cfg = { .port = 8080 };
uint16_t p = cfg.port;   /* OK：只读 */
cfg.port = 9090;         /* 编译错误：const */
  • const struct 的字段也是 const
  • 编译器把 const 全局放进 .rodata，修改触发 SIGSEGV

复合字面量的直接访问

struct point p = (struct point){ .x = 1, .y = 2 };
p.x = 10;   /* OK：p 是左值 */

((struct point){ .x = 1, .y = 2 }).x;   /* C99：取复合字面量字段 */
  • 复合字面量是左值，可取字段
  • 生命周期到所在块结束

HFT 关联

  • 栈上小 struct：HFT 热路径常用 struct hdr 在栈上构造，用 . 访问，避免 malloc
  • 定长订单数组：orders[i].price cache 友好，比链表快 2-5 倍
  • 静态配置：static const struct config cfg = {0} 全局只读配置
  • 性能：. 是 1 周期操作，-> 多一次解引用（4-5 周期，cache miss 时 100+ 周期）
  • DPDK mbuf：mbuf 本身用 ->（指针），但 mbuf 内嵌的小 struct 字段用 .

实操：栈上协议头构造

void send_quote(uint32_t seq, uint16_t price) {
    struct quote_hdr hdr = {0};   /* 栈上零初始化 */
    hdr.seq = seq;
    hdr.price = price;
    hdr.pkt_type = PKT_QUOTE;
    /* 发送：memcpy 到发送缓冲 */
    memcpy(tx_buf, &hdr, sizeof hdr);
    send(tx_buf, sizeof hdr);
}

栈上构造避免 malloc，约 5-10 ns。

实操：订单簿数组遍历

struct order_book {
    struct order entries[1024];
    size_t count;
};

struct order_book book = {0};

for (size_t i = 0; i < book.count; i++) {
    if (book.entries[i].price == target) {
        match(&book.entries[i]);   /* 传指针，避免拷贝 */
        break;
    }
}

注意 match(&book.entries[i]) 取数组元素指针——遍历用 .，调用用 ->（在 match 内部）。

10.2

.2 结构的间接访问

本节讲什么

对struct 指针用 -> 运算符访问字段，称为"间接访问"。这是 DPDK、Linux 内核、HFT 代码最常用的访问方式——因为大 struct 几乎总是以指针传递，避免按值拷贝。本节剖析 -> 的语义、与 (*p).field 的等价关系、空指针陷阱、以及 const 修饰的层次。

要点

基本用法

QuoteHdr pkt;
QuoteHdr *p = &pkt;       /* p 指向 struct */
p->seq      = 10001;      /* 间接访问 */
p->price    = 9999;
p->pkt_type = PKT_QUOTE;

/* 等价写法 */
(*p).seq = 10001;         /* 啰嗦，但等价 */
  • p->seq 等价 (*p).seq，但更简洁，是惯用写法
  • -> 是运算符，不是语法糖——C 标准定义的独立运算符
  • 访问开销：1 次指针解引用 + 1 次 mov，约 4-5 周期（cache 命中）

汇编视角

struct point { int x; int y; } *p;
p->y = 42;

movq -8(%rbp), %rax    ; 取 p 的值（指向 struct 的地址）
movl $42, 4(%rax)      ; 写 *(p + 4) = 42
  • 先从 p 取出 struct 地址（1 次访存）
  • 再用基址 + 编译期偏移（+4）写字段（1 次访存）
  • 比 . 多一次访存——取指针本身

常见指针来源

/* 1. 取栈上 struct 地址 */
QuoteHdr pkt;
QuoteHdr *p = &pkt;

/* 2. 堆对象 */
QuoteHdr *p = malloc(sizeof *p);

/* 3. DPDK mbuf */
struct rte_mbuf *m = rte_pktmbuf_alloc(pool);
uint32_t len = m->pkt_len;

/* 4. 报文指针强转 */
const struct eth_hdr *eth = (const struct eth_hdr *)pkt_data;
uint16_t type = ntohs(eth->type);

/* 5. 链表节点 */
struct node *n = head;
n->next->next = /* ... */;

空指针陷阱

QuoteHdr *p = NULL;
p->seq = 1001;   /* UB：解引用空指针，通常 SIGSEGV */
  • x86-64 Linux：地址 0 所在页是 unmapped，访问触发 SIGSEGV
  • 内核态：NULL 解引用是 kernel oops
  • 铁律：解引用前检查 if (p) p->seq = ...;
  • DPDK/内核有 RTE_ASSERT(p) 等宏做断言

多级 -> 链

struct node *head;
head->next->next->value = 42;
  • 链式 -> 每一级都是一次指针解引用
  • 任一中间指针为 NULL → SIGSEGV
  • cache miss 时性能急剧下降：每级 100+ 周期
  • 链表遍历是 HFT 性能敏感操作，定长数组通常更优

-> 与 . 混合

struct pkt_head {
    uint32_t magic;
    struct quote_hdr quote;   /* 嵌套实体 */
};

struct pkt_head *p = /* ... */;
p->quote.seq = 1001;   /* -> 然后 . */
  • p->quote 返回内层 struct 实体（左值）
  • 再 . 访问其字段
  • 指针路径用 ->，实体路径用 .
struct outer {
    struct inner *p;   /* 指针成员 */
};

struct outer o;
o.p->field = 42;       /* . 然后 -> */

结构体含指针成员的访问链

struct B { int val; };
struct A { struct B *pb; };   /* A 只存 B 的指针，不含 B 实体 */

struct B b_obj = { .val = 666 };
struct A a_obj;
a_obj.pb = &b_obj;

struct A *pa = &a_obj;
pa->pb->val = 999;   /* 两级指针解引用 */

内存布局：

pa (0x100)
 ↓
struct A [ pb = 0x200 ]      ← A 只存一个地址
0x200 → struct B { val }     ← B 本体在别处
  • pa->pb 取出 0x200（B 的地址）
  • pa->pb->val 跳到 0x200 再取 val
  • 等价写法：(*(pa->pb)).val

野指针陷阱：struct A 里的 pb 不会自动指向有效 B 内存。如果只定义 struct A a; 不初始化 a.pb，a.pb 是垃圾地址，pa->pb->val 直接 SIGSEGV。

浅拷贝陷阱

struct A a1;
a1.pb = &b_obj;

struct A a2 = a1;     /* 结构体赋值 = 浅拷贝 */
/* a2.pb 和 a1.pb 指向同一个 B！ */
a2.pb->val = 999;     /* a1.pb->val 也变成 999 */

结构体赋值拷贝了 pb 指针值（0x200），但两个指针指向同一个 B 对象。修改一个，另一个也跟着变。要独立修改，需深拷贝（为 a2.pb 分配新的 B 内存并复制内容）。

函数参数同理：传 struct A *pa 进函数，pa->pb->val = 999 改的就是原始 B——因为 pb 存的是 B 的地址，不是副本。即使值传递 struct A a，a.pb 还是指向同一个 B。

const QuoteHdr *p1 = &pkt;        /* 指向 const struct：不能改 struct */
QuoteHdr *const p2 = &pkt;        /* const 指针：不能改 p，能改 struct */
const QuoteHdr *const p3 = &pkt;  /* 两者都 const */

p1->seq = 1001;   /* 编译错误：const struct */
p2->seq = 1001;   /* OK */
p2 = &other;      /* 编译错误：const 指针 */
p3->seq = 1001;   /* 编译错误 */
p3 = &other;      /* 编译错误 */

经验法则：函数参数用 const T * 表示"只读"，是 API 契约的一部分。

restrict 修饰

void process(QuoteHdr *restrict a, QuoteHdr *restrict b);
  • restrict 承诺 a 和 b 不别名
  • 允许编译器更激进优化（向量化、重排）
  • 详见 ch06 指针章节

指针算术与 ->

struct order *base = /* 数组首地址 */;
struct order *p = base + 3;   /* 指针算术：偏移 3 个 struct */
p->seq = 1001;                /* 等价 base[3].seq */

/* 等价 */
(base + 3)->seq = 1001;
base[3].seq = 1001;
  • base + 3 是 struct order *，指向第 3 个元素
  • 指针算术按 sizeof(struct order) 步进

.3 结构的自引用

本节讲什么

struct 可以包含指向自身类型的指针（不能包含自身实体——大小无限递归）。这是链表、树、图等递归数据结构的根基，也是 ch12（结构体与指针）和 ch17（经典 ADT）的前置知识。本节剖析自引用的合法性、不完整类型在其中的作用、以及链表的基本操作。

要点

合法与非法自引用

/* 合法：指针成员 */
typedef struct node {
    uint64_t order_id;
    struct node *next;   /* 指针，大小已知（8 字节） */
} Node;

/* 非法：实体成员 */
struct bad {
    uint64_t id;
    struct bad next;     /* 错误：大小无限递归 */
};

根因：

  • 指针大小与所指类型无关（x86-64 上 8 字节），编译器无需知道 struct node 完整定义即可确定 struct node * 的大小
  • 实体成员要求编译器已知其大小，但 struct bad 的大小依赖 struct bad 本身——无限递归

不完全类型的作用

struct node;   /* 前置声明：不完全类型 */
typedef struct node Node;

struct node {          /* 完整定义 */
    uint64_t order_id;
    Node *next;        /* 此时 Node 仍可作指针类型 */
};
  • 前置声明让 struct node * 可用
  • 完整定义后才能定义实体、求 sizeof、访问成员
  • 自引用 struct 在定义体内部，struct node 是不完全类型，但 struct node * 合法

链表节点

typedef struct node {
    uint64_t order_id;
    uint32_t price;
    uint32_t qty;
    struct node *next;
} Node;

内存布局（x86-64）：

偏移  0    8    16   20   24
     +----+----+----+----+----+
     | id |price|qty | next |   （假设 8 字节对齐）
     +----+----+----+----+----+
                      |
                      v
                   下一个 Node

单向链表基本操作

头插法：

Node *head = NULL;

void push_front(Node **head, uint64_t id) {
    Node *n = malloc(sizeof *n);
    if (!n) return;
    n->order_id = id;
    n->next = *head;
    *head = n;
}
  • head 是 Node **（二级指针），让函数能修改调用方的 head
  • 时间复杂度 O(1)

遍历：

for (Node *p = head; p; p = p->next) {
    printf("%lu\n", p->order_id);
}

查找：

Node *find(Node *head, uint64_t id) {
    for (Node *p = head; p; p = p->next) {
        if (p->order_id == id) return p;
    }
    return NULL;
}

删除：

void remove(Node **head, uint64_t id) {
    Node **pp = head;
    while (*pp) {
        if ((*pp)->order_id == id) {
            Node *victim = *pp;
            *pp = victim->next;
            free(victim);
            return;
        }
        pp = &(*pp)->next;
    }
}

注意用 Node **pp（指向指针的指针）技巧，避免单独处理头节点。

双向链表

    uint64_t id;

  • 删除 O(1)（给定节点指针）
  • Linux 内核 list_head 是侵入式双向链表的标准实现

  • 链表节点嵌入数据结构内部，不持有数据指针
  • 一个对象可挂多个链表（多个 list_head 成员）
  • Linux 内核、DPDK 都用此模式
  • container_of 是核心宏，通过 offsetof 反算外层结构

循环引用与内存

自引用结构易导致内存泄漏：链表节点互相引用，忘记 free 整链。HFT 通常用内存池（DPDK mempool）避免 malloc/free 开销，且池有上限防止泄漏。

HFT 关联

  • 订单簿：买卖盘链表，每个价位一个链表头
  • DPDK mempool：空闲块用链表管理，自引用 struct
  • 内核 task_struct：进程链表、子进程链表都是自引用
  • 定时器：定时器事件用链表或最小堆，自引用节点
  • 性能铁律：链表遍历 cache 不友好，HFT 热路径优先用定长数组 + 索引

实操：订单簿链表

typedef struct order {
    uint64_t order_id;
    uint32_t price;
    uint32_t qty;
    struct order *next;
} Order;

Order *bid_head = NULL;   /* 买盘 */

void add_bid(uint64_t id, uint32_t price, uint32_t qty) {
    Order **pp = &bid_head;
    while (*pp && (*pp)->price > price)   /* 按价格降序 */
        pp = &(*pp)->next;
    Order *o = pool_alloc();   /* 从池分配，不用 malloc */
    o->order_id = id;
    o->price = price;
    o->qty = qty;
    o->next = *pp;
    *pp = o;
}

实操：container_of 宏

#include <stddef.h>

struct order {
    uint64_t id;
    struct list_head list;
};

    struct order *o = container_of(node, struct order, list);
    printf("order %lu\n", o->id);
}

container_of 让链表代码与数据结构解耦——链表操作只需 list_head *，不关心外层类型。

10.3

结构的存储分配

本节讲什么

内存对齐、padding、sizeof 是 struct 章节最关键的内容——网络协议解析错位、跨平台移植 bug、共享内存不一致的头号根源。struct 不是字段的简单拼接，编译器会按对齐规则插入 padding 字节，导致 sizeof 大于字段宽度之和。HFT/网络代码必须用 __attribute__((packed)) 或显式偏移，才能让 struct 布局与线格式一致。

本节是 ch10 的重点章，详细剖析对齐规则、padding 计算、packed 权衡、跨平台陷阱。

要点

对齐规则（x86-64 Linux 典型）

三条铁律：

  1. 成员起始偏移 = 该成员自身宽度的整数倍
  2. struct 总大小 = 最大成员宽度的整数倍（末尾可能补 padding）
  3. 不足处编译器自动插入 padding 字节

实例分析

struct test1 {
    char a;     /* 1 字节，偏移 0 */
                /* 3 字节 padding */
    int  b;     /* 4 字节，偏移 4 */
};
/* sizeof = 8，不是 5 */

struct test2 {
    int  b;     /* 4 字节，偏移 0 */
    char a;     /* 1 字节，偏移 4 */
                /* 3 字节 padding（满足规则 2） */
};
/* sizeof = 8，不是 5 —— 末尾 padding */

struct test3 {
    char a;     /* 1 字节，偏移 0 */
    char b;     /* 1 字节，偏移 1 */
    char c;     /* 1 字节，偏移 2 */
    char d;     /* 1 字节，偏移 3 */
};
/* sizeof = 4，无 padding */

struct test4 {
    uint8_t  a;   /* 1 字节，偏移 0 */
    uint32_t b;   /* 4 字节，偏移 4（3 字节 padding 后） */
    uint8_t  c;   /* 1 字节，偏移 8 */
};
/* sizeof = 12，不是 6 —— 头尾 padding */

字段重排减少 padding

/* 反例：字段顺序混乱，padding 多 */
struct bad {
    uint8_t  a;     /* 1 */
                  /* 7 padding */
    uint64_t b;     /* 8 */
    uint8_t  c;     /* 1 */
                  /* 3 padding */
    uint32_t d;     /* 4 */
};   /* sizeof = 24 */

/* 正例：按宽度降序排列 */
struct good {
    uint64_t b;     /* 8 */
    uint32_t d;     /* 4 */
    uint8_t  a;     /* 1 */
    uint8_t  c;     /* 1 */
                  /* 2 padding */
};   /* sizeof = 16，省 8 字节 */

工程铁律：struct 字段按宽度从大到小排列，可显著减少 padding。Google C++ Style Guide 和 Linux 内核都强调这一点。

对齐的原因

CPU 访问内存按对齐粒度进行（x86-64 通常 8/16 字节）：

  • 对齐访问：单次总线事务，1 周期
  • 非对齐访问：跨缓存行/页，x86 上 2-3 周期，ARM 上可能 SIGBUS
  • padding 让字段落在自然边界，换取访问速度

sizeof 与对齐

printf("%zu\n", sizeof(struct test1));   /* 8 */
printf("%zu\n", _Alignof(struct test1)); /* 4（最大成员对齐） */
  • sizeof 是 struct 占用的总字节数（含 padding）
  • _Alignof（C11）是 struct 的对齐要求
  • 二者关系：sizeof % _Alignof == 0

packed：紧凑布局

struct __attribute__((packed)) quote_hdr {
    uint32_t seq;       /* 4，偏移 0 */
    uint16_t price;     /* 2，偏移 4 */
    uint8_t  pkt_type;  /* 1，偏移 6 */
};
/* sizeof = 7，无 padding —— 与线格式一致 */
  • GCC/Clang：__attribute__((packed))
  • MSVC：#pragma pack(1) 或 __declspec(align(1))
  • 取消所有 padding，字段紧挨
  • 用于协议头、共享内存、持久化二进制——布局必须与线格式一致

packed 的代价

struct __attribute__((packed)) bad {
    uint8_t  a;
    uint32_t b;   /* 偏移 1，非对齐 */
};

struct bad x;
x.b = 42;   /* x86：3 周期（跨缓存行）；ARM：SIGBUS */
  • 非对齐访存：x86 允许但有性能惩罚，ARM/MIPS/SPARC 上是硬件异常
  • HFT 热路径：packed struct 的字段访问比普通慢 2-10 倍
  • 权衡：协议头用 packed（布局正确性优先），运行时数据用普通 struct（性能优先）

正确加载线格式

方案 1：packed struct + memcpy

struct __attribute__((packed)) quote_hdr {
    uint32_t seq;
    uint16_t price;
    uint8_t  pkt_type;
};
_Static_assert(sizeof(struct quote_hdr) == 7, "quote_hdr must be 7 bytes");

struct quote_hdr hdr;
memcpy(&hdr, payload, sizeof hdr);    /* 一次性载入 */
uint32_t seq = ntohl(hdr.seq);        /* 大端转小端 */
uint16_t price = ntohs(hdr.price);

方案 2：手动偏移解析（最可移植）

uint32_t seq = ntohl(*(uint32_t *)(payload + 0));   /* UB：未对齐 */
/* 正确：memcpy 到局部变量 */
uint32_t seq;
memcpy(&seq, payload + 0, 4);
seq = ntohl(seq);

memcpy 是唯一对齐安全的结构体读取方式，编译器优化为单条 mov 或 movups，零开销。

共享内存的致命陷阱

struct shm_data {
    uint32_t seq;
    time_t   ts;      /* 32 位系统 4 字节，64 位系统 8 字节 */
    uint64_t order_id;
};
  • 32 位进程和 64 位进程共享此 struct 时，time_t 宽度不同 → 偏移错位
  • 修复：所有字段用 uint32_t/uint64_t 定长类型 + packed
  • _Static_assert 锁定大小

持久化二进制的陷阱

/* 进程 A 写入文件 */
struct config cfg = /* ... */;
write(fd, &cfg, sizeof cfg);

/* 进程 B（不同编译器/平台）读取 */
struct config cfg;
read(fd, &cfg, sizeof cfg);   /* 偏移可能不一致 */
  • 不同编译器的 padding 策略可能不同
  • 同一编译器 32/64 位模式不同
  • 铁律：持久化二进制必须用 packed 或显式偏移序列化

位段对齐（详见 10.5）

struct flags {
    uint32_t a : 1;
    uint32_t b : 31;
};
/* sizeof = 4，位段在 uint32_t 内紧凑排列 */
  • 位段按 bit 分配，但仍受对齐约束
  • 位段顺序平台相关，禁用于线格式

HFT 关联

  • 协议头：struct eth_hdr、struct ip_hdr、struct tcp_hdr 必须 packed + _Static_assert
  • DPDK mbuf：struct rte_mbuf 字段精心重排，cache 行友好
  • 订单簿：struct order 按 order_id(8) → price(4) → qty(4) 排列，64 字节对齐填满一个缓存行
  • 共享内存：跨进程 struct 必须 packed + 定长类型 + _Static_assert
  • 性能铁律：HFT 热路径 struct 设计要考虑 cache 行（64 字节），热门字段放前 64 字节

struct order {
    uint64_t order_id;    /* 8 */

作为函数参数的结构

本节讲什么

struct 作为函数参数有按值传递和按指针传递两种方式，这是 HFT 延迟优化的关键选择。按值拷贝整个 struct，对小 struct 简洁安全，对大 struct 是性能灾难；按指针只传地址，快但需注意所有权和生命周期。本节剖析两种方式的 ABI 实现、性能权衡、const 的作用、以及返回 struct 的细节。

要点

两种传递方式

/* 按值：拷贝整个 struct 到栈 */
void process_by_value(QuoteHdr pkt);

/* 按指针：只传地址 */
void process_by_ptr(const QuoteHdr *p);
方式 参数开销 调用方 被调方 适用
按值 sizeof(struct) 字节拷贝 简洁 副本，安全 小 struct（≤16 字节）
指针 8 字节地址 取地址 共享原对象 大 struct、热路径、需修改
const T * 8 字节地址 取地址 只读共享 只读访问，避免拷贝

按值传递的 ABI 细节

x86-64 System V ABI：

  • struct ≤ 16 字节：通过寄存器传递（整数用 rdi/rsi/...，浮点用 xmm0-7）
  • struct > 16 字节：通过栈传递，或由调用方分配空间传指针（RAX 指向）
struct small { int a, b; };   /* 8 字节 */
void f(struct small s);       /* 通过 rdi 传 8 字节 */

struct big { int arr[100]; }; /* 400 字节 */
void g(struct big b);         /* 栈拷贝 400 字节 */

ARM64 ABI 类似，但阈值不同（≤16 字节用寄存器）。

按指针的性能优势

/* 反例：按值传 256 字节 struct */
void process(struct big b);   /* 每次调用拷贝 256 字节 */

/* 正例：传指针 */
void process(const struct big *b);   /* 8 字节地址 */
  • 256 字节拷贝：约 30-50 ns（memcpy）
  • 指针传递：约 1-2 ns（寄存器移动）
  • HFT 铁律：大于 16 字节的 struct 传指针

const 指针的语义

/* 只读：承诺不修改 struct */
uint32_t get_seq(const QuoteHdr *p) {
    return p->seq;
}

/* 读写：可能修改 struct */
void set_seq(QuoteHdr *p, uint32_t seq) {
    p->seq = seq;
}
  • const T *p：API 契约，告知调用方"我不会改你的数据"
  • 编译器在函数内对 p->field = ... 报错
  • 是 C 代码中最重要的 const 修饰，影响 API 设计

所有权与生命周期

/* 借用：调用方仍拥有 */
void process(const QuoteHdr *p) {
    /* p 的生命周期由调用方保证 */
    printf("%u\n", p->seq);
}

/* 转移所有权：被调方负责释放 */
void consume(QuoteHdr *p) {
    /* 用完后 free(p) */
    free(p);
}

C 没有所有权标注（C++ 有 unique_ptr），靠注释和命名约定：

  • process / print / get：通常借用
  • consume / destroy / free：通常转移所有权
  • DPDK 用 rte_pktmbuf_free(m) 明确释放语义

返回 struct

/* 按值返回小 struct：通过寄存器 */
struct point make_point(int x, int y) {
    return (struct point){ .x = x, .y = y };
}

/* 按值返回大 struct：调用方传入隐藏指针 */
struct big make_big(void) {
    struct big b = {0};
    /* ... */
    return b;   /* 实际写入调用方提供的缓冲 */
}
  • 小 struct：寄存器返回，高效
  • 大 struct：调用方分配空间，被调方填充（RVO 类似优化）
  • HFT 铁律：大 struct 返回用"输出参数"风格
/* 输出参数风格：避免大 struct 返回 */
int make_big(struct big *out) {
    if (!out) return -1;
    *out = (struct big){0};
    /* ... */
    return 0;
}

与 memcpy 的关系

/* 按值传参 */
void f(struct big b);
struct big x = /* ... */;
f(x);   /* 等价 memcpy(&b_stack_slot, &x, sizeof(struct big)) */
  • 按值传递本质是编译器生成的 memcpy
  • 大 struct 时这就是性能开销

struct 数组参数

/* 数组退化为指针，无拷贝 */
void process_all(struct order orders[], size_t n);
void process_all(struct order *orders, size_t n);   /* 等价 */
  • struct 数组退化为 struct order *，只传首地址
  • 调用 process_all(arr, 100) 不拷贝 100 个 struct

HFT 关联

  • DPDK mbuf：rte_eth_rx_burst(port, queue, pkts, n) 传 struct rte_mbuf *pkts[]（指针数组），不拷贝 mbuf
  • 协议头：parse(const struct eth_hdr *eth) 传只读指针，零拷贝
  • 订单处理：process_order(const struct order *o) 传指针，避免 64 字节 struct 拷贝
  • 回调函数：void cb(const struct event *e, void *user) 标准事件回调签名
  • 性能铁律：热路径所有 struct 参数传 const T *，仅在需要修改时用 T *

10.5

位段

本节讲什么

Bit-field（位段） 在 struct 内按 bit 分配成员，允许多个字段共享同一字节。它看似适合映射紧凑的硬件寄存器和协议标志位，但有致命的平台相关性：bit 分配顺序、跨字节边界、对齐方式都由实现定义。因此位段禁止用于网络协议线格式——改用显式移位和掩码（ch05）。

本节剖析位段的语法、规则、平台相关性陷阱、以及正确的替代方案。

要点

基本语法

struct dev_status {
    uint32_t ready : 1;    /* 1 bit */
    uint32_t err   : 2;    /* 2 bits */
    uint32_t mode  : 3;    /* 3 bits */
    uint32_t rsv   : 26;   /* 26 bits */
};
/* sizeof = 4 字节，共 32 bits 填满一个 uint32_t */
  • 成员名 : 宽度 声明位段
  • 宽度是 bit 数，非字节数
  • 通常用 unsigned int / uint32_t 作为载体类型

访问与赋值

struct dev_status s = {0};
s.ready = 1;
s.err = 3;
s.mode = 5;

uint32_t reg;
memcpy(&reg, &s, sizeof reg);   /* 取出 32 位寄存器值 */
  • 位段成员可像普通字段读写
  • 编译器生成移位和掩码指令
  • 取地址非法：&s.ready 是编译错误（位段无独立地址）

平台相关性陷阱

位段的所有布局细节都是实现定义：

维度 平台差异
bit 分配顺序 大端机从 MSB 分配，小端机从 LSB 分配
跨字节边界 有的实现允许跨字节，有的强制新字节开始
载体类型 int 可能是 signed/unsigned，符号位行为不同
对齐 struct 总对齐由载体类型决定
最大宽度 通常 ≤ 载体类型宽度（如 uint32_t 最多 32 bit）

大小端对位段的影响

struct flags {
    uint16_t a : 4;
    uint16_t b : 4;
    uint16_t c : 8;
};
  • 小端 x86：a 在低 4 位，b 在次 4 位，c 在高 8 位
  • 大端 SPARC：a 在高 4 位，b 在次 4 位，c 在低 8 位
  • 同一 C 源码，不同平台产生不同内存布局

这就是位段不能用于网络协议的根本原因——接收端可能用不同字节序，导致字段错位。

禁止取地址

struct dev_status s;
uint32_t *p = &s.ready;   /* 编译错误：位段成员不能取地址 */
  • 位段无独立存储地址（共享字节）
  • 不能用指针操作位段
  • 不能传给 scanf("%d", &s.ready)

位段 vs 显式移位

/* 反例：位段（平台相关） */
struct tcp_flags_bitfield {
    unsigned fin : 1;
    unsigned syn : 1;
    unsigned rst : 1;
    /* ... */
};

/* 正例：显式移位（平台无关） */
uint16_t flags = ntohs(tcp->flags);
int fin = (flags >> 0) & 1;
int syn = (flags >> 1) & 1;
int rst = (flags >> 2) & 1;

显式移位的优势：

  • 完全可移植：bit 位置由代码定义，与平台无关
  • 可取地址：flags 是普通 uint16_t
  • 可序列化：直接 htonl/htons 发送
  • 可调试：调试器能看到完整值

位段的合理用例

硬件寄存器映射（PCI/MMIO）：

struct pci_status {
    uint32_t int_pending : 1;
    uint32_t int_line    : 3;
    uint32_t dev_id      : 5;
    uint32_t rsv         : 23;
};

volatile struct pci_status *reg = (volatile struct pci_status *)0xFE000000;
if (reg->int_pending) {
    /* 处理中断 */
}
  • 硬件手册定义的 bit 布局，与平台字节序一致（同机内）
  • 驱动代码与硬件强绑定，移植性不是目标
  • volatile 防止编译器优化掉访存

紧凑标志集合（内存极度受限）：

struct compact_flags {
    uint8_t is_valid : 1;
    uint8_t is_dirty : 1;
    uint8_t is_locked : 1;
    uint8_t type : 5;
};
/* 1 字节存 8 个标志 */

嵌入式 MCU 场景，每字节都珍贵。

位段的限制

限制 说明
不能取地址 &bf.field 非法
不能用 sizeof sizeof(bf.field) 非法
不能用 scanf 无法取地址
不能是数组 位段成员不能为数组
不能跨实现移植 布局是实现定义
不能用作线格式 字节序和边界规则不同

HFT 关联

  • 协议头标志位：TCP flags、IP flags 不用位段，用显式移位和掩码
  • PCI 配置空间：DPDK PMD 驱动用位段映射网卡寄存器（同机内，移植性非目标）
  • 订单标志：is_cancelled、is_filled 等用 uint8_t + 移位，或单独 uint8_t flags + 宏
  • 性能：位段访问是移位+掩码，与手动移位性能相当；但可移植性差，HFT 代码倾向手动移位
  • 调试：位段在调试器中可见名字，但跨平台调试时布局可能不同

实操：协议标志位的正确做法

#define TCP_ACK 0x10
#define TCP_URG 0x20

if (flags & TCP_ACK) { /* ACK 标志 */ }

实操：硬件寄存器位段

10.6

联合

本节讲什么

union 让多个成员共享同一块内存，大小等于最大成员。union 是 C 的"类型双关"机制——同一块字节可以用不同类型解读。它用于字节拆分、寄存器多视图、变体载荷等场景，但无类型标记——读错成员是静默 UB，需配合判别字段（10.6.1 变体记录）。union 也是严格别名规则的关键例外（C 标准允许通过 union 做类型双关，但仍有陷阱）。

本节是 union 总览，子节展开变体记录和初始化。

要点

基本语法

union raw_data {
    uint32_t word;
    uint8_t  bytes[4];
};

union raw_data u;
u.word = 0x12345678;
/* 此时 u.bytes 可读取同样 4 字节 */
printf("%02x %02x %02x %02x\n",
       u.bytes[0], u.bytes[1], u.bytes[2], u.bytes[3]);
/* 小端 x86 输出：78 56 34 12 */
  • 所有成员起始地址相同，共享存储
  • sizeof(union) = 最大成员的 sizeof
  • 同一时刻仅一个成员"有效"——写入一个成员后读另一个是 UB（C99 前严格 UB，C99 后有例外）

内存布局

union raw_data:
偏移  0    1    2    3
     +----+----+----+----+
     | word (4 字节)       |
     +----+----+----+----+
     | b0 | b1 | b2 | b3 |   ← bytes[4] 同一存储
     +----+----+----+----+
  • word 和 bytes 起点都是偏移 0
  • 4 字节存储，两种解读

union vs struct

维度 struct union
成员存储 各自独立，连续 共享，重叠
大小 Σ成员大小 + padding max(成员大小) + padding
同时有效 所有成员 仅一个成员
典型用途 字段绑定 类型双关、变体
访问开销 直接 直接（无间接）

类型双关

union {
    float f;
    uint32_t u;
} x;
x.f = 1.0f;
printf("%08x\n", x.u);   /* 读取 float 的位表示 */
  • 用 union 实现 float 与 uint32_t 的位重新解读
  • C99 起，写入一个成员后读另一个是允许的（类型双关例外）
  • C++ 行为不同——C++ 标准说"未指定"，但 GCC/Clang 实践与 C 一致
  • 比 *(uint32_t *)&f 更安全——后者违反严格别名

严格别名与 union 例外

C 标准的严格别名规则（C11 6.5p7）禁止通过不兼容类型的指针访问对象：

float f = 1.0f;
uint32_t u = *(uint32_t *)&f;   /* 严格别名 UB（除 char* 外） */

但 union 有例外（C11 6.5.2.3 脚注 95）：通过 union 做类型双关是允许的：

union { float f; uint32_t u; } x;
x.f = 1.0f;
uint32_t u = x.u;   /* 合法：union 类型双关 */
  • 这是 C 标准明确允许的类型双关方式
  • GCC/Clang 都支持，MSVC 也支持
  • 是可移植的"位重新解读"惯用法

大小端与 union

union { uint32_t w; uint8_t b[4]; } u;
u.w = 0x12345678;

/* 小端 x86：b[0]=0x78, b[1]=0x56, b[2]=0x34, b[3]=0x12 */
/* 大端 SPARC：b[0]=0x12, b[1]=0x34, b[2]=0x56, b[3]=0x78 */
  • union 的字节拆分依赖大小端
  • 跨平台代码不能依赖 union 做字节序转换
  • 应该用显式移位：uint8_t b0 = (u.w >> 24) & 0xFF;（大端语义）

union 的大小

union {
    uint8_t  a;    /* 1 字节 */
    uint32_t b;    /* 4 字节 */
    uint64_t c;    /* 8 字节 */
} u;
/* sizeof = 8（最大成员） */
/* _Alignof = 8（uint64_t 对齐） */
  • 大小 = 最大成员
  • 对齐 = 最大成员的对齐要求
union {
    uint32_t a;    /* 4 字节 */
    char b[10];    /* 10 字节 */
} u;
/* sizeof = 12（10 字节 + 2 padding 满足 4 对齐） */

末尾 padding 让总大小是最大对齐的整数倍。

匿名 union/struct（C11）

struct pkt {
    uint8_t type;
    union {                    /* 匿名 union */
        uint32_t seq;
        uint8_t  raw[4];
    };                         /* 直接 .seq 访问 */
};

struct pkt p;
p.type = 1;
p.seq = 0x12345678;           /* 直接访问，无需 p.anon.seq */
  • C11 标准化（GCC 早就支持为扩展）
  • 简化变体记录的访问语法
  • 适用于"同一消息载荷多种解读"

union 作为"变体载荷"

struct msg {
    uint8_t type;   /* 判别字段 */
    union {
        struct { uint64_t order_id; } order;
        struct { uint32_t seq; } quote;
    } body;
};

struct msg m;
m.type = PKT_ORDER;
m.body.order.order_id = 1001;   /* 写入 order 分支 */

if (m.type == PKT_ORDER) {
    use(m.body.order.order_id);  /* 必须先判 type */
}
  • 配合判别字段实现"带标签的联合"（tagged union）
  • 详见 10.6.1 变体记录

HFT 关联

  • DPDK mbuf：union { struct rte_mbuf *next; void *buf_addr; } 多视图访问同一字段
  • 报文载荷多视图：union { struct eth_hdr eth; uint8_t raw[14]; } 同时按字段和原始字节访问
  • 类型双关：float 与 uint32_t 转换用 union，比指针强转安全
  • 变体消息：FIX/SBE 不同消息类型用 tagged union 建模
  • 寄存器视图：union { uint32_t reg; struct { uint8_t a, b, c, d; } bytes; } 硬件寄存器多视图

10.6

.1 变体记录

本节讲什么

变体记录（variant record） 是 union 最有价值的应用：同一消息头后，载荷类型不同——用 union + 类型判别字段 建模。这是 FIX/SBE/Protobuf 等协议的"带标签联合"（tagged union）模式，也是 C 语言实现"多态"的传统方式。本节剖析变体记录的结构、判别字段的安全使用、匿名 union 简化、以及 HFT 协议的实际应用。

要点

基本结构

struct msg {
    uint32_t magic;        /* 公共头部 */
    uint8_t  type;         /* 判别字段 */
    uint16_t len;
    union {                /* 变体载荷 */
        struct { uint64_t order_id; uint32_t qty; } order;
        struct { uint32_t seq; uint16_t price; } quote;
        struct { uint64_t cancel_id; } cancel;
    } body;
};

三个组成部分：

  1. 公共头部：所有变体共有的字段（magic、type、len）
  2. 判别字段：标识当前有效变体（type）
  3. union 载荷：按 type 解读不同结构

判别字段的安全使用

struct msg m;
memcpy(&m, buf, sizeof m);

switch (m.type) {
case PKT_ORDER:
    printf("order %lu qty %u\n",
           (unsigned long)m.body.order.order_id,
           m.body.order.qty);
    break;
case PKT_QUOTE:
    printf("quote seq %u price %u\n",
           m.body.quote.seq, m.body.quote.price);
    break;
case PKT_CANCEL:
    printf("cancel %lu\n",
           (unsigned long)m.body.cancel.cancel_id);
    break;
default:
    printf("unknown type %u\n", m.type);
}

铁律：

  • 必须先判 type 再访问 body 对应分支
  • 禁止无判别地读 union 另一分支——静默 UB
  • default 处理未知类型，防止未来协议扩展

判别字段缺失的陷阱

/* 反例：无判别字段 */
union {
    struct { uint64_t order_id; } order;
    struct { uint32_t seq; } quote;
} body;

body.order.order_id = 1001;
/* 后续代码无法知道这个 union 当前是 order 还是 quote */
printf("%u\n", body.quote.seq);   /* UB：读错分支 */

无判别字段的 union 是定时炸弹——任何"读错"都是静默 UB。

匿名 union 简化（C11）

struct msg {
    uint32_t magic;
    uint8_t  type;
    uint16_t len;
    union {                /* 匿名 union */
        struct { uint64_t order_id; uint32_t qty; } order;
        struct { uint32_t seq; uint16_t price; } quote;
    };                     /* 无成员名 */
};

struct msg m;
m.type = PKT_ORDER;
m.order.order_id = 1001;   /* 直接访问，无需 m.body.order */
  • C11 标准化（GCC 早就支持为扩展）
  • 简化访问语法
  • 可读性更好

公共前缀模式

struct pkt_base {
    uint32_t magic;
    uint8_t  type;
    uint16_t len;
};

struct order_pkt {
    struct pkt_base base;   /* 公共前缀 */
    uint64_t order_id;
    uint32_t qty;
};

struct quote_pkt {
    struct pkt_base base;   /* 相同前缀 */
    uint32_t seq;
    uint16_t price;
};

/* 通过 base.type 判别 */
void process(void *buf) {
    struct pkt_base *base = buf;
    switch (base->type) {
    case PKT_ORDER: {
        struct order_pkt *o = buf;
        /* ... */
        break;
    }
    case PKT_QUOTE: {
        struct quote_pkt *q = buf;
        /* ... */
        break;
    }
    }
}
  • 公共前缀作为"基类"
  • 强转后访问具体类型
  • 是 C 的"继承"惯用法，Linux 内核大量使用

复合字面量构造

struct msg make_order(uint64_t id, uint32_t qty) {
    return (struct msg){
        .magic = MAGIC,
        .type = PKT_ORDER,
        .len = sizeof(struct { uint64_t; uint32_t; }),
        .body.order = { .order_id = id, .qty = qty },
    };
}

C99 复合字面量让变体记录的构造简洁。

变体记录的内存布局

struct msg {
    uint32_t magic;     /* 4 字节，偏移 0 */
    uint8_t  type;      /* 1 字节，偏移 4 */
    uint16_t len;       /* 2 字节，偏移 6（padding 后） */
    union {             /* 偏移 8 */
        struct { uint64_t order_id; uint32_t qty; } order;   /* 16 字节 */
        struct { uint32_t seq; uint16_t price; } quote;      /* 8 字节 */
    } body;
};
/* sizeof = 24（union 取最大 16，加前缀 8） */

union 让所有变体共享同一块载荷空间，大小等于最大变体。

变体记录 vs 继承

维度 变体记录 C++ 继承
判别 显式 type 字段 vtable 隐式
内存 单块，union 共享 对象 + vtable 指针
扩展 加 union 分支 派生类
性能 switch 分派，可预测 间接调用，分支预测
适用 C、HFT、协议 C++、动态多态

HFT 代码倾向变体记录——switch 比 vtable 更利于分支预测和内联。

HFT 关联

  • FIX 协议：消息类型字段（MsgType=35）判别不同消息体，用变体记录建模
  • SBE 协议：schema 定义的变体消息，编译期生成 tagged union
  • DPDK rte_mbuf：不同报文类型（Ethernet/IP/ARP）用 union 共享缓冲
  • 订单事件：struct event { uint8_t type; union { Order; Quote; Cancel; } body; }
  • 性能：switch 分派可被分支预测器优化，热路径比 vtable 快

实操：FIX 消息变体

    FIX_NEW_ORDER = 'D',

10.6

.2 联合的初始化

本节讲什么

union 初始化与 struct 类似但有关键区别：union 同一时刻仅一个成员有效，初始化时必须明确指定哪个成员。C89 规定不指定时初始化第一个成员；C99 起支持指定成员初始化（.member =），这是初始化 union 的推荐方式。本节剖析初始化规则、与 struct 的区别、切换成员时的清零需求、以及运行时构造。

要点

C89：默认第一个成员

union raw_data {
    uint32_t word;
    uint8_t  bytes[4];
};

union raw_data u = { 0x12345678 };   /* 初始化第一个成员 word */
  • C89 只能用值列表初始化第一个成员
  • 顺序对应第一个成员的结构
  • 想初始化其他成员需先初始化第一个，再赋值

C99：指定成员初始化（推荐）

union raw_data u = { .word = 0x12345678 };
union raw_data u2 = { .bytes = { 0x78, 0x56, 0x34, 0x12 } };
  • .member = value 明确指定初始化哪个成员
  • 只能指定一个成员（union 同时只有一个有效）
  • 未指定的成员共享存储，值未定义

铁律：C99 起，union 初始化总是用指定成员，避免歧义。

嵌套 union 在 struct 中

struct msg {
    uint32_t magic;
    uint8_t  type;
    union {
        struct { uint64_t order_id; uint32_t qty; } order;
        struct { uint32_t seq; uint16_t price; } quote;
    } body;
};

struct msg m = {
    .magic = 0xDEADBEEF,
    .type = PKT_ORDER,
    .body.order = { .order_id = 1001, .qty = 100 },
};
  • 外层 struct 用 .field =
  • 内层 union 用 .member =，指定哪个变体
  • 嵌套初始化可读性强

匿名 union 的初始化

struct msg {
    uint32_t magic;
    uint8_t  type;
    union {                           /* 匿名 union */
        struct { uint64_t order_id; uint32_t qty; } order;
        struct { uint32_t seq; uint16_t price; } quote;
    };
};

struct msg m = {
    .magic = 0xDEADBEEF,
    .type = PKT_ORDER,
    .order = { .order_id = 1001, .qty = 100 },   /* 直接初始化匿名 union 成员 */
};
  • 匿名 union 的成员直接在外层 struct 初始化列表中指定
  • 语法更简洁

未初始化成员的值

union raw_data u = { .word = 0x12345678 };
/* u.bytes 的值是 0x12345678 的字节解读（小端：78 56 34 12） */
/* 但"读 bytes"在 C99 前是 UB，C99 后允许（类型双关例外） */

union raw_data u2 = { .bytes = { 1, 2, 3, 4 } };
/* u2.word 的值未定义（除非通过 union 类型双关读取） */
  • 初始化一个成员后，其他成员的值是该字节的重新解读
  • C99 起允许通过 union 读取（类型双关）
  • C89 严格 UB

切换成员时的清零

union raw_data u;
u.word = 0x12345678;     /* 写入 word */
/* 现在想用 bytes */
memset(&u, 0, sizeof u); /* 清零，避免残留 */
u.bytes[0] = 0xFF;       /* 只设第一个字节，其余 0 */
  • 切换 union 成员时，原成员的值仍存在于共享存储
  • 若新成员比旧成员小，残留字节可能影响后续读取
  • 谨慎做法：切换前 memset 清零
  • 实践做法：知道自己在做什么，通常不需清零

运行时构造

union raw_data u;
u.word = 0x12345678;   /* 运行时赋值 */

/* 或复合字面量 */
union raw_data u2 = (union raw_data){ .word = 0x12345678 };
  • 运行时赋值与初始化语法一致
  • 复合字面量可在任意位置构造 union 值

union 数组的初始化

union slot {
    uint64_t value;
    struct { uint32_t a, b; } pair;
};

union slot arr[3] = {
    { .value = 1 },
    { .pair = { .a = 2, .b = 3 } },
    { .value = 4 },
};
  • 每个元素独立指定成员
  • 可混合不同变体

静态 union 的初始化

static union raw_data s_u = { .word = 0x12345678 };
/* 编译期初始化，进 .data 段 */

static union raw_data s_zero = { 0 };
/* C89：第一个成员 word = 0 */
/* C99：仍合法，等价 .word = 0 */
  • 静态 union 的初始化值必须是编译期常量
  • {0} 是通用零初始化惯用法，对 union 也有效

const union

const union raw_data c_u = { .word = 0x12345678 };
/* c_u.word = 0; */   /* 编译错误：const */
uint32_t w = c_u.word;   /* OK：只读 */
  • const union 的所有成员都不可修改
  • 用于只读配置、协议模板

HFT 关联

  • 协议模板：static const struct msg order_tmpl = { .magic = MAGIC, .type = PKT_ORDER, .body.order = { 0 } }
  • 报文构造：构造订单报文时用指定成员初始化 union 载荷
  • DPDK mbuf：mbuf 的 union 字段在 mempool 分配后清零，再按需写入
  • 测试夹具：单元测试中构造变体消息用复合字面量
  • 共享内存：跨进程 union 必须用 packed + 定长类型 + 显式初始化

实操：协议模板复用

static const struct msg ORDER_TMPL = {
    .magic = 0x4F524431,   /* "ORD1" */

    .body.order = { .order_id = 0, .qty = 0 },

实操：切换成员的清零

union payload {
    uint8_t  bytes[8];
    uint64_t word;

u.word = 0xFFFFFFFFFFFFFFFF;   /* 全 1 */
/* 现在只用 bytes[0] */

题目 1： 以下结构体在 64 位系统上 sizeof 是多少？

struct S {
    char a;
    int b;
    char c;
};
参考答案

通常是 12 字节。由于对齐要求，a 占 1 字节后填充 3 字节到 b（偏移 4），b 占 4 字节，c 占 1 字节后填充 3 字节使总大小是 4 的倍数。布局：a(1) + pad(3) + b(4) + c(1) + pad(3) = 12。如果改为 struct S { int b; char a; char c; }; 则 sizeof = 8。
