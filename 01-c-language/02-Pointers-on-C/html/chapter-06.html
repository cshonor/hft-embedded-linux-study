6.0

指针入门：声明里的 `*` ≠ 表达式里的 `*`

指针最易踩坑点 · 展开见 6.4 间接访问 · 6.1 内存和地址
本质速记： 下文 §7（地址定位 + 类型怎么读）
传参值拷贝 → 7.3.1 · K&R 速查 → 1.8.1

这是什么

一份指针「语法分水岭」笔记：同一个 *，声明里和表达式里含义完全不同。

1. * 的两个场景

① 声明：int *p;

  • * 属于声明语法，修饰变量名 p：p 是指针变量
  • p 本身存地址；*p 表示该地址上的 int
  • 正确读法：「p 是指向 int 的指针」
  • ❌ 不要读成「*p 是变量」

语法特点：* 贴变量，不是贴类型。

int* a, b;   /* a 是指针；b 只是普通 int —— 常见误读 */
int *a, *b;  /* 若两个都要指针，每个变量前都写 * */

② 表达式：*p = 10;

  • * 是解引用运算符
  • 含义：取出 p 保存的地址，访问该地址对应的内存

2. & 与 * 配对

int x = 10;
int *p = &x;   /* &：取 x 的地址，赋给 p */
*p = 20;       /* *：顺着地址改内存 → x 变成 20 */
符号 直觉
& 拿盒子的门牌号（地址）
* 拿着门牌号找盒子，读写里面的内容

3. 和 argv 的关联

char *argv[];
  • 声明场景： * 修饰数组元素 → 每个元素是 char *
  • 作函数参数时常退化为 char **argv，仍遵守：声明 vs 解引用两套 * 规则

（指针数组 vs 数组指针 → 后文 6.x / Expert C 对照。）

自测 1：*ptr = 666 之后 num？

int num = 100;
int *ptr = &num;   /* 注意是 &num，不是错误写法 # */
*ptr = 666;

答：num = 666。

完整拆解

int num = 100;     /* 开辟 int 空间，存入 100 */
int *ptr = &num;   /* &num 取地址；ptr 保存该地址 */
*ptr = 666;        /* 解引用：顺着 ptr 找到 num，写入 666 */

内存视角（地址仅示意）：

变量 自己的地址（示意） 里面存的内容
num 0x100 先是 100，后被写成 666
ptr 0x200 0x100（num 的地址）

*ptr = 666 → 往 0x100 写入 → 直接改 num 本身。

要点：

  • ptr 只存放地址
  • *ptr 相当于 num 的别名，代表那块内存对象

易混对比

int num = 100;
int *ptr = &num;

ptr = (int *)0x999;   /* 只改 ptr 自己存的地址；num 不受影响（且此地址通常非法） */
*ptr = 666;           /* 改 ptr 指向的那块内存（num）——前提是 ptr 仍指向合法对象 */
写法 改的是谁
ptr = … 指针变量自己（门牌号换了）
*ptr = … 指向的对象（盒子里的内容）

自测 2（追问）

int a = 10;
int *p = &a;
int b = *p;   /* 把 *p 的值拷贝给 b */
*p = 20;      /* 改 a */
/* b 等于多少？a 等于多少？ */

答：b = 10，a = 20。

  • int b = *p：读出当时的 a（10），拷贝进 b；之后 b 与 a 独立
  • *p = 20：只改 a，不会回头改已经拷走的 b

4. 解引用放左边还是右边？*p1 = *p2？

问题 1：* 能不能放在 = 左边？

可以，而且非常常用。

int num = 100;
int *ptr = &num;

*ptr = 666;   /* ✔ *ptr 在左边：写内存 */
位置 含义
*ptr 在 = 左边 左值 / 写：往该地址写入
*ptr 在 = 右边 读：取出该地址里的值 
int a, b;
int *p = &a;

*p = 10;     /* 左边：写 → a = 10 */
b = *p;      /* 右边：读 → b = 10 */

* 本身不分左右；看整个表达式在赋值的哪一侧，决定读还是写。

⚠ 声明里的 * 不是解引用：

int *p;   /* 声明语法：p 是指针；此阶段没有「解引用操作」 */

问题 2：能不能写成 *p1 = *p2（两边都带星）？

合法，经典「拷贝指向的数据」。

int x = 10, y = 20;
int *p1 = &x;
int *p2 = &y;

*p1 = *p2;   /* 读 y → 写入 x；结果 x=20, y=20 */

拆解：

  1. 右边 *p2：读 → 得到 17
  2. 左边 *p1：写 → 把 17 写入 x
  3. p1、p2 里存的地址不变（仍分别指向 x、y）

对比（不带星）：

p1 = p2;   /* 拷贝地址 → p1 也指向 y；x 的值不变 */
代码 做了什么
*p1 = *p2; 拷贝指向的数据
p1 = p2; 拷贝指针里的地址

易错坑：野指针当左值

int *p;
*p = 99;   /* ❌ 野指针写随机内存 → 崩溃 / UB */

解引用无论左右，前提：指针必须指向合法对象。

自测 3

int m = 1, n = 2;
int *q1 = &m;
int *q2 = &n;
*q1 = *q2;   /* ① */
q1 = q2;     /* ② */
/* m、n 最终分别等于多少？ */

答：m = 2，n = 2。

  1. *q1 = *q2 → 把 n 的值 2 写入 m → m=2, n=2
  2. q1 = q2 → 只让 q1 也指向 n；不再改 m/n 的数值（仍是 2 和 2）

5. 指针创建后还能改指向吗？

能。 普通 int *p 完全可以改它存的地址——不带 *，直接把指针名放在 = 左边。

int a = 100, b = 200;
int *p = &a;   /* p 存 a 的地址 */
p = &b;        /* ✅ 改 p 本身 → 现在指向 b */
代码 操作对象 是否改变「指向哪里」
p = &xxx; 指针变量 p 本身 ✅ 更新 p 里存的地址
*p = val; p 指向的内存 ❌ 地址不变，只改目标数据

两段对比

int a = 10, b = 20;
int *p = &a;

p = &b;    /* 不带 *：改指向 → p→b；a 仍是 10 */
*p = 99;   /* 带 *：改内容 → b 变成 99；p 仍指向 b */

示意：

int *p = &a;   →  p 里是 a 的地址
p = &b;        →  p 里改成 b 的地址（指向切换）
*p = 99;       →  p 仍是 b 的地址；b 的内容写成 99

const 时要小心

int x = 1, y = 2;

const int *p = &x;
p = &y;      /* ✅ 可以改指向；不能 *p = 10 改内容 */

int * const q = &x;
q = &y;      /* ❌ q 本身被 const 锁住，不能改指向 */

普通 int *p（无 const）→ 指向随便改。
展开：const 四式见 6.9 指针常量。

自测 4

int v1 = 11;
int v2 = 22;
int *ptr = &v1;
ptr = &v2;     /* ① 改指向 → 指向 v2 */
*ptr = 999;    /* ② 改 v2 的内容 */
/* v1、v2 最后分别是多少？ */

答：v1 = 11，v2 = 999。

  • ptr = &v2 只切换指向，不动 v1
  • *ptr = 999 写的是当前指向的 v2

6. 指针能不能再 &？——&p1 合法

术语先分清：

符号 名字 作用
& 取地址（取指符） 拿到变量的内存地址
* 解引用 顺着地址拿内容

p1 是指针变量，它自己也占内存，所以 &p1 完全合法。

int a = 10;
int *p1 = &a;

/* p1  → 存着 a 的地址
 * *p1 → 解引用 → a 的值（10）
 * &p1 → 取 p1 自己的地址 → 类型是 int **
 */
int **pp = &p1;   /* ✅ */

层级：

a     ：普通 int
p1    ：int *，保存 a 的地址
&p1   ：p1 自身的地址，类型 int **（二级指针）
表达式 含义
pp 存 p1 的地址
*pp 等价于 p1（即 a 的地址）
**pp 等价于 *p1（即 a 的值）

**pp 拆解：先 *pp → 得到 p1；再 * → 得到 a。

易错

写法 含义
p1 = &a 把 a 的地址放进 p1 → p1 指向 a
pp = &p1 把 p1 自己的地址放进 pp → pp 指向 p1
  • *p1 = 解引用（跟内容）
  • &p1 = 取 p1 自身地址（产出二级指针）
    两者完全不同。

现实用途：函数里改外面指针的指向

void func(int **pp) {
    *pp = NULL;   /* 改外面 p 里存的地址 */
}

int main(void) {
    int *p;
    func(&p);     /* 传 &p */
}

int x = 100;
int *p = &x;
int **pp = &p;

/* *pp 等于什么？
 * **pp 等于什么？
 * &p 是什么类型？
 */

答：

表达式 结果

&p 类型 int **

7. 内存与指针的本质

你的理解对：指针存的是内存地址（编号）；int * / char * 里的 int/char 规定：从这个地址起，读多少字节、怎么翻译。

1. 地址只是数字

例如 0x2000 —— CPU 只知道「某个位置」。
不知道从这里读几个字节、怎么解释。

2. 类型干两件事

int  *p;
char *q;

p、q 里存的都是地址数字；差别在解引用时：

类型 解引用时
int 通常读 4 字节，按整数规则拼
char 读 1 字节

例：0x100..0x103 存着字节 01 00 00 00（小端）：

  • int *pi 指向 0x100 → *pi 读 4 字节 → 得到 1
  • char *pc 指向 0x100 → *pc 只读 1 字节 → 得到 0x01

同一地址、不同类型 → 读出结果可以完全不同。
（和 SIGNED-UNSIGNED 同一思路：比特靠「怎么读」解释。）

3. 指针变量自己也占内存

int a = 10;
int *p = &a;
是什么
a 一块内存，存 07，按 int 解（常见 4 字节）
p 另一块内存，存的是 a 的地址（64 位常见 8 字节）

int * 同时说明：

  1. p 用来存地址
  2. 那地址指向的对象按 int 解析

两层别混：

  • p 自己的内存 → 装地址编号
  • p 指向的内存 → 靠类型告诉 CPU 怎么读

4. 强制转换改的是「读法」，不是字节

char *q;
int *pi = (int *)q;

一般不改内存里任何字节，只改解释规则：「请按 int 来读这个地址」。
若实际只有 1 字节有效数据却用 int * 解引用 → 多读后面字节 → 越界 / UB。

极简两句

  1. 指针 = 存放内存地址编号的变量；地址负责定位起点。
  2. int* / char* 里的类型 = 从该起点读多少字节、怎么翻译——不是「指针本身长什么样」。

自测 6（64 位机）

int a;
int  *p = &a;
char *q = (char *)&a;   /* 或等价地讨论「指向同一地址的 char*」 */
/* p 占几个字节？q 占几个字节？ */

答：p 和 q 作为指针变量，本身都占地址宽度——64 位上通常各 8 字节。
int / char 的差别在 *p / *q 读几个字节，不在指针变量自己的大小。
（可用 sizeof(p)、sizeof(q) 验证；sizeof(*p) 才是 4，sizeof(*q) 才是 1。）

展开：6.1 内存和地址 · 6.2 值和类型。

一句话

声明里的 * 告诉编译器「这是指针变量」；表达式里的 * 才是「跟着地址去读写」。
*p 可在 = 左（写）或右（读）；*p1 = *p2 拷数据，p1 = p2 拷地址。
改指向用 p = &x（不带星）；改内容用 *p = val（带星）。
&p 取的是指针自己的地址 → int **；和 *p 不是一回事。
地址定位；类型规定怎么读。指针变量自己也只是一块存地址的内存。

代码自测

题目 1： 以下代码中两个 * 分别是什么含义？

int x = 42;
int *p = &x;  // 第一个 *
*p = 100;      // 第二个 *
参考答案

第一个 * 是声明中的指针修饰符——int p 声明 p 是指向 int 的指针。第二个 * 是解引用操作符——p 访问 p 指向的内存。同一个 * 符号在不同语境下含义完全不同：声明中是指针标记，表达式中是解引用。

6.1

内存和地址

本节讲什么

内存 = 可字节寻址的数组 + 地址：每个变量占连续若干字节，地址标识其起始字节。指针就是「存放地址的变量」—— DPDK mbuf、内核 task_struct、HFT 报文缓冲的共同语言。这一节把"地址"在硬件、操作系统、C 语言三个层面讲透，后面 14 节都建立在这之上。

要点

  • 虚拟地址：进程看到的地址，经 MMU/页表翻译成物理地址（ch18 详）
  • x86-64 Linux：用户态通常 48 位有效（高 16 位必须全 0 或全 1，否则 SIGSEGV），5 级页表可到 57 位
  • 指针变量占 8 字节（64 位），与指向类型无关：sizeof(int*) == sizeof(char*) == sizeof(void*) == 8
  • 普通变量存数据；指针变量存"另一对象的首地址"
  • & 取址；* 解引用（6.4）
int val = 10;
int *p = &val;   /* p 的内容 = val 的首地址 */

地址空间布局（x86-64 Linux 用户态）

高地址  ┌─────────────────────┐ 0x7fff_ffff_ffff (栈底，48 位上限)
        │  栈 ↓ 向下增长       │  局部变量、帧指针、返回地址
        │  ...                │
        │  ↕ 共享库 mmap 区    │  libc.so / vdso
        │  堆 ↑ 向上增长       │  malloc/mmap
        ├─────────────────────┤
        │  .bss  (未初始化全局) │  运行时清零
        │  .data (已初始化全局) │
        │  .rodata (只读字面量) │  "FIX.4.2" 在这
        │  .text  (代码)       │
低地址  └─────────────────────┘ 0x400000 (non-PIE 典型基址；现代默认 PIE+ASLR 随机化)

&val 在栈区；字符串字面量在 .rodata；malloc 返回在堆或 mmap 区。

底层映射

内存层级与延迟（HFT 必背）

层级 容量 延迟（约） 备注
寄存器 ~16×64B 0 cycle 编译器尽量常驻
L1 d-cache 32 KB/核 ~4 cycle cache line 64B
L2 1 MB/核 ~12 cycle 私有
L3 数十 MB ~40 cycle 全核共享
DRAM GB 级 ~200 cycle（~60ns） 主存
NVMe TB 级 ~10μs 持久化

HFT 关键路径数据必须在 L1/L2。一次 DRAM 访问 ≈ 50 次 L1，"指针跳转链表"慢就慢在每次 next 都可能 miss。

地址对齐

  • 自然对齐：地址是其类型宽度的整数倍（int* 的地址 % 4 == 0）
  • x86-64 允许非对齐访问但有性能代价；某些 ISA（ARM 旧版）直接 SIGBUS
  • SIMD（__m256）要求 32 字节对齐，否则 movaps 崩溃
  • alignof(T) 查询；_Alignas(64) / __attribute__((aligned(64))) 强制 cache line 对齐

mmap：指针与后备存储（先画区、后填页）

mmap 返回的 void *，指向的是一块被内核绑定了「后备」的虚拟地址——后备可以是磁盘文件、设备 DMA 缓冲区、或匿名页。它和 malloc 的关键区别在「数据什么时候到位」：

返回的指针指向 数据何时到位
malloc 虚拟地址，后备是零页 + COW 首次写触发缺页，分配真实页并清零
mmap 虚拟地址，后备可显式指定（文件/设备/匿名） 访问时触发缺页，内核从文件/设备填页

先画区、后填页：mmap 只建立「虚拟地址 ↔ 物理/磁盘」的映射关系，不立刻把数据拷进内存。解引用 *p 才会触发缺页中断（page fault）——这是 CPU 的内存管理机制，不等于 mmap。

两个进程的指针，能否指向同一物理页？

mmap 的 flags 决定映射关系的共享程度，本质是「两个进程的虚拟地址，翻译后落在同一块物理页，还是各自一块」：

/* 共享：两个进程的 p/q 指向同一物理页 */
void *p = mmap(NULL, sz, PROT_READ|PROT_WRITE, MAP_SHARED, fd, 0);   /* 进程 A */
void *q = mmap(NULL, sz, PROT_READ|PROT_WRITE, MAP_SHARED, fd, 0);   /* 进程 B */
/* A 写 *p，B 读 *q 立刻看到变化 —— 同一物理页 */

/* 私有：各自一份副本，首写 COW */
void *r = mmap(NULL, sz, PROT_READ|PROT_WRITE, MAP_PRIVATE, fd, 0);  /* 进程 A */
void *s = mmap(NULL, sz, PROT_READ|PROT_WRITE, MAP_PRIVATE, fd, 0);  /* 进程 B */
/* A 写 *r 触发写时复制(COW)，只改自己的物理页，B 的 *s 不变 */
flags 物理页 写语义 典型场景
MAP_SHARED 多进程同一物理页 一改全可见（文件映射可回盘） 共享文件、设备缓冲区
MAP_PRIVATE 每进程各自副本 首写 COW，互不影响 加载 text 段、私有匿名分配

指针可以直接指向设备内存

设备的 DMA 缓冲区也能 mmap 进用户态——此时指针指向的是设备内存（网卡 DMA 环形缓冲区、采集卡寄存器），访存即碰外设，省掉 read/write 的一次拷贝：

/* 网卡零拷贝：报文被 DMA 直写进用户态可访问的缓冲区 */
struct pkt_ring *ring = mmap(NULL, ring_sz, PROT_READ|PROT_WRITE,
                             MAP_SHARED, dev_fd, 0);
/* 直接解引用读报文，不经过内核协议栈拷贝 */

独占设备：锁在驱动，不在 mmap

独占设备（麦克风、独占采集卡）❌ 不是给每个进程各做一份 mmap；✅ 是设备驱动里做独占锁——同一时刻只允许一个进程 mmap 成功，别的进程调用 mmap 失败/阻塞：

/* 驱动侧：独占设备同一时刻只允许一个进程映射 */
static int mic_mmap(struct file *filp, struct vm_area_struct *vma)
{
    if (!atomic_add_unless(&mic_open, 1, 1))
        return -EBUSY;             /* 已被独占 → mmap 失败 */
    return remap_pfn_range(vma, vma->vm_start,
                           mic_dma_paddr >> PAGE_SHIFT,
                           vma->vm_end - vma->vm_start,
                           vma->vm_page_prot);
}

关键：互斥逻辑写在设备驱动里，mmap 只是「给指针一块能碰到设备的虚拟地址」，本身不提供任何互斥。设备能不能让你映射，由驱动说了算。

#include <stdio.h>
#include <stdint.h>
#include <fcntl.h>
#include <unistd.h>

uint64_t vaddr_to_pfn(void *vaddr) {
    uint64_t page = (uint64_t)vaddr / 4096, entry;
    int fd = open("/proc/self/pagemap", O_RDONLY);
    pread(fd, &entry, 8, page * 8);
    close(fd);
    return entry & 0x7fffffffffffffULL;  /* bit 63=present，低 57 位=PFN */
}

int main(void) {
    int x = 42;
    printf("&x=%p pfn=0x%lx\n", &x, vaddr_to_pfn(&x));
    return 0;
}

6.2

值和类型

本节讲什么

类型决定三件事：占多少字节、位模式如何解释、指针 +1 的步长。同一地址，换个类型解读，读出的内容完全不同——这是协议解析、序列化的基础，也是严格别名规则的雷区。

要点

  • 类型 = 语义：地址相同，int* 读 4 字节按补码解释，float* 读 4 字节按 IEEE 754 解释，char* 读 1 字节
  • sizeof(T) 得对象字节数（编译期常量）
  • 指针类型 T* 表示"指向 T 的指针"，T* + 1 移动 sizeof(T) 字节（6.13.1）

声明陷阱（经典面试题）

int *a, b;      /* a 是 int*，b 是 int —— * 只跟最近一个名字 */
int *a, *b;     /* 两个都是 int* */

C 的声明语法是"声明符"逐个修饰，* 是前缀修饰单个声明符。推荐一行一个指针：

int *a;
int *b;

类型双关（type punning）

同一块内存，用不同类型读：

float f = 1.0f;
uint32_t bits = *(uint32_t *)&f;   /* 读出 IEEE 754 位模式 */

这种"指针 cast 后解引用"在严格别名下是 UB（见下）。安全做法是用 union 或 memcpy：

union { float f; uint32_t u; } u;
u.f = 1.0f;
uint32_t bits = u.u;              /* 合法：union 保证可读任意成员 */

/* 或者 memcpy，编译器优化成寄存器移动，无开销 */
uint32_t bits;
memcpy(&bits, &f, sizeof bits);

底层映射

严格别名规则（Strict Aliasing）

C99 6.5/7：通过类型 T 的左值访问对象，对象的实际类型必须与 T 兼容（或 char/void 的特例）。违反 → UB，-O2 起编译器会做"两个不同类型指针必不指向同一对象"的假设，导致静默错误结果。

int    x = 0x40490FDB;   /* 1.0f 的位模式，但 x 是 int */
float *fp = (float *)&x;
*fp = 2.0f;              /* 严格别名 UB：通过 float* 改 int 对象 */
printf("%d\n", x);       /* -O2 下可能仍是旧值（编译器认为没人改它） */

例外：char* / unsigned char* / void* 可以别名任意类型（所以 memcpy 的实现合法）。

# 开启严格别名检查（gcc）
gcc -O2 -fstrict-aliasing -Wstrict-aliasing=3
# 关闭（某些遗留代码需要）
gcc -O2 -fno-strict-aliasing

协议解析的合法路径

struct __attribute__((packed)) eth_hdr {
    uint8_t  dst[6];
    uint8_t  src[6];
    uint16_t ether_type;
};

const uint8_t *pkt = ...;   /* char* 别名任意，合法 */
const struct eth_hdr *h = (const struct eth_hdr *)pkt;
uint16_t etype = ntohs(h->ether_type);

pkt 是 uint8_t*（字符类型特例），cast 到结构体指针后解引用——只要布局对齐合法即可。HFT 协议栈大量用 packed 结构体 + 字符指针 base。

6.3

指针变量的内容

本节讲什么

指针变量存储的内容是一个地址值——本质上是一个无符号整数（uintptr_t 可互转）。指针变量自己也在内存里，自己也有地址。搞清"指针的内容""指针的地址""指针指向的对象"三者，是后面多级指针、调试、ABI 的基础。

要点

int a = 1, b = 2;
int *p = &a;            /* p 的内容 = a 的地址 */

printf("%p\n", (void *)p);   /* p 的内容：a 的地址 */
p = &b;                      /* 指针变量自身可被赋值，改存 b 的地址 */
  • 打印用 %p + (void *) cast（%p 规范要求 void*，否则 UB）
  • 指针也有地址：&p 是"指向指针的指针"（6.10）
  • 指针内容可转为整数：uintptr_t addr = (uintptr_t)p;（C99 定宽，往返合法）

三者关系图

变量名    内存地址      内存内容
 a      0x7ffd_0010  →  1          (int)
 p      0x7ffd_0008  →  0x7ffd_0010 (=&a，指针变量自身存的是 a 的地址)
&p      0x7ffd_0008   (p 这个变量自身的地址)

p 在地址 0x7ffd_0008，内容是 0x7ffd_0010（即 a 的地址）。*p 取 p 的内容当地址，去该地址读 → 得到 1。

6.4

间接访问操作符

本节讲什么

* 解引用：通过指针访问其所指对象。C 里同一个 * 在声明和表达式里语义完全不同——这是新手第一道坎，也是理解"指针即地址 + 类型语义"的钥匙。本节还把解引用落到汇编层，看清"间接访问"在 CPU 上究竟是什么。

入门速记： 6.0 星号两场景（声明 * vs 表达式 * · &/* 配对 · 自测）

要点

int num = 100;
int *ptr = &num;

printf("%d", *ptr);   /* 读 num：*ptr 求值为 100 */
*ptr = 200;           /* 写 num：*ptr 是左值，可被赋值 */
上下文 * 含义 例子
声明 T *p 类型修饰符："p 是指向 T 的指针" int *p;
表达式 *p 解引用运算符：取 p 所指对象 *p = 1;
类型名 T* 类型的一部分 sizeof(int*)
  • 解引用前指针必须有效：非 NULL、非悬垂、非野、在合法范围内
  • *p 的结果是左值（可赋值、可取地址），类型为 T
  • 对 p 本身取地址 &(*p) 等价于 &num（在有效指针上）

底层映射

解引用 = 一条访存指令

*ptr 读 → mov 从 [reg] 加载；*ptr = 写 → mov 存储。

int num = 100;
int *ptr = &num;
*ptr = 200;        /* 解引用写 */
int x = *ptr;      /* 解引用读 */

; x86-64 -O1
    mov     DWORD PTR [rsp+4], 100        ; num = 100
    lea     rax, [rsp+4]                  ; ptr = &num
    mov     DWORD PTR [rax], 200          ; *ptr = 200  (store)
    mov     eax, DWORD PTR [rax]          ; x = *ptr    (load)

核心：一条访存指令。指针在寄存器（rax）里存地址，CPU 用 [rax] 去内存（或 cache）取数。延迟取决于该地址在不在 cache（6.1 内存层级）。

别名分析（编译器优化的核心）

void f(int *a, int *b) {
    *a = 1;
    *b = 2;              /* 编译器要问：b 会不会指向 a？ */
    return *a;           /* 若可能别名，必须重新 load *a；否则保持 1 */
}
  • 若编译器能证明 a != b（如 restrict 承诺，6.9），*a 直接常量折叠成 1
  • 若不能证明，每次写 *b 后都要重新 load *a——这就是 restrict 提速的原理

HFT / DPDK

场景 解引用模式
改调用者变量 *out = value;（输出参数）
链表遍历 p = p->next;（-> 等价 (*p).member，ch10）
报文字段 pkt->ether_type
批量改结构体 for (...) { p[i].flag = 1; }

-> 是 * + . 的语法糖：p->m ≡ (*p).m。优先级：-> 和 . 高于 *，所以 *p.m 实际是 *(p.m)，要写 (*p).m——这就是 -> 存在的理由。

常见误区

误区 事实
"声明 int *p 里的 * 和 *p = 1 里的 * 一样" 完全不同：前者类型修饰，后者运算符
"解引用一定快" 取决于所指地址是否在 cache；miss 一次 200 cycle
"*p 总能取地址" 悬垂/野指针解引用本身已是 UB
"写 *p = x 就一条指令" 是，但前面可能有 null 检查、边界检查的开销

int **pp = &p;
参考答案

pp 等于 42。pp 指向 p，*pp 得到 p（即 p 的值，也就是 &x），pp 得到 *p（即 x 的值 42）。二级指针就是指向指针的指针，解引用两次才能到达最终值。

6.5

未初始化和非法的指针

本节讲什么

野指针与悬垂指针——生产环境段错误、堆破坏、数据损坏的 Top 原因。这一节把这几类坏指针的成因、表现、检测手段、编译期防护讲全。HFT 系统里一次 UAF 可能让订单重复成交，必须从写第一行代码就建立纪律。

要点

野指针（未初始化）

int *p;        /* 自动存储期，未初始化 → 栈帧上的垃圾值 */
*p = 1;        /* 把垃圾当地址写 → SIGSEGV 或踩坏别人 */

局部变量在栈帧上，内容是上一个函数留下的残值。这个值可能碰巧落在可写页 → 静默踩数据，可能落在不可写页 → SIGSEGV。最坏情况是"碰巧能跑"，因为问题被掩盖到很远的地方才爆。

规范：局部指针声明即 = NULL，或立即赋有效地址。

悬垂指针（use-after-free）

int *p = malloc(sizeof(int));
free(p);
/* p 仍存旧地址 —— 悬垂 */
*p = 10;       /* UAF：堆破坏，可能写到别人 malloc 的块上 */

free 不改 p 的内容（它不知道 p 在哪），只是把堆块标记为可再分配。UAF 的恐怖在于：内存可能已被 malloc 给了别人，*p = 10 写到别人对象上，不崩，但数据错乱。

规范：free(p); p = NULL; —— 让悬垂指针解引用变成可预测的 SIGSEGV（解 NULL）而非静默踩数据。

非法指针的其他来源

  • 越界：arr + 100 后解引用（UB，6.13）
  • 栈局部返回：int *f() { int x; return &x; }（ch07，返回即失效）
  • 修改只读字面量：char *s = "abc"; s[0] = 'X';（6.11，.rodata 段，SIGSEGV）
  • 未对齐的 cast：int *p = (int *)((char *)malloc(1) + 1);（某些平台 SIGBUS）

底层映射

栈垃圾值演示

void leak(void) {
    int *p;          /* 不初始化 */
    /* 这里 p 的值是上一个栈帧的残留 */
}

int main(void) {
    int arr[4] = {0xdead, 0xbeef, 0xcafe, 0xbabe};
    leak();          /* leak 的栈帧复用 arr 的位置 */
}

不开优化时，p 很可能指向 arr 区域——解引用"能跑"但语义全错。这就是野指针最阴险之处。

6.6

NULL 指针

本节讲什么

NULL 表示指针"不指向任何对象"。它是 C 里"空值"的标准写法——初始化、比较、函数"无可返回"语义都靠它。这一节把 NULL 的定义、解引用为什么崩、内核/错误码扩展用法讲清。

要点

#define NULL ((void *)0)   /* 常见定义，C99 起 */

int *p = NULL;
if (p == NULL) { /* ... */ }
if (p != NULL && p->len > 0) { /* 短路：p 为 NULL 不会解引用 */ }
  • *NULL → 段错误（见下"零页保护"）
  • C11 可选 nullptr（<stddef.h>，若定义 __STDC_VERSION__ >= 202311L）；C++ 用 nullptr
  • 释放后置 NULL 使二次 free 安全（标准要求 free(NULL) 是 no-op），但不应依赖此"安全"——double-free 本身就是 bug

NULL 的定义演变

标准 典型定义
C89/C90 ((void *)0) 或 0
C99 ((void *)0)，整数常量 0 也可作空指针
C23 引入 nullptr 关键字（如启用）

0 和 ((void*)0) 在比较时等价：p == 0 和 p == NULL 都判空。但传参时 0 给 va_arg 的 void* 在某些 ABI 上会出问题，推荐始终用 NULL 或显式 (void*)0。

底层映射

零页保护

x86-64 Linux：低地址（典型 0–4KB，可配 /proc/sys/vm/mmap_min_addr）映射为不可读不可写页。*NULL → CPU 发出 mov [0] → MMU 检查权限失败 → SIGSEGV。

NULL 解引用路径:
  *p (p=NULL=0)
  → mov eax, [0]            ; CPU 访存
  → MMU 查页表，0 地址页无权限
  → page fault → 内核送 SIGSEGV

"零页"是特意留出来的——让 NULL 解引用确定性崩溃而非踩随机数据。某些嵌入式系统不设零页，NULL 解引用会写到向量表 → 死机。

内核错误码编码（IS_ERR 模式）

内核指针的低端不用，高端一段（典型 (unsigned long)-4095 ~ -1）编码错误码：

/* 内核源码模式 */
static inline bool IS_ERR(const void *ptr) {
    return (unsigned long)ptr >= (unsigned long)-4095;
}
static inline long PTR_ERR(const void *ptr) {
    return (long)ptr;
}

void *p = kmalloc(...);
if (IS_ERR(p)) {
    int err = PTR_ERR(p);   /* 取回负错误码 */
    /* 处理 */
}

返回值既是指针也是错误码——内核惯用手法。用户态 HFT 不常用，但理解它对读内核代码、DPDK 移植有帮助。

HFT / DPDK

用法 例子
报文不存在 if (!pkt) return;
链表尾哨兵 for (; p != NULL; p = p->next)
配置缺失 config->cb = NULL; 表示未设回调
可选资源 struct ring *r = NULL; 按需创建

常见误区

误区 事实
"NULL 一定是 0" 实现可定义，但主流都是全零位模式
"free 后 p 自动变 NULL" 不会，必须手动 p = NULL
"判 NULL 用 !p 是偷懒" 合法且常见，等价于 p == NULL
"C++ 的 NULL 和 C 一样" C++ 推荐用 nullptr，类型安全（不会和 0 歧义）

6.7

指针和间接访问

本节讲什么

通过指针间接读写的完整模式——这是 C 函数"修改调用者变量"的唯一干净手段（值传递所致）。这一节把传址模式、ABI 寄存器传参、批量接口讲清，是 HFT 数据接口设计的地基。

要点

void inc(int *p) {
    *p += 1;        /* 通过指针改调用者的变量 */
}

int x = 10;
inc(&x);           /* x 变为 11 —— 传的是 x 的地址 */
  • C 一律值传递：形参是实参的副本。要改外部变量，传指针的副本，通过解引用改原对象
  • 读：v = *p；写：*p = v
  • 多级间接：**pp（6.10）
  • 函数参数指针常配 const 表示"不改所指对象"（6.9）

三种语义模型

声明 含义 调用者视角
void f(int v) 传值，函数拿副本 调用者变量不被改
void f(const int *p) 传只读指针 函数读但不改
void f(int *p) 传可写指针 函数能改原对象
void f(int **out) 传指针的指针 函数能改调用者的指针（6.10）

底层映射

ABI 寄存器传参

x86-64 System V：前 6 个整数/指针参数走寄存器（rdi, rsi, rdx, rcx, r8, r9），第 7 个起进栈。

void inc(int *p) { *p += 1; }

; x86-64 -O2
inc:
    add     DWORD PTR [rdi], 1     ; 一条指令：p 在 rdi，直接 [rdi] += 1
    ret

int *p 走 rdi，函数体直接 add [rdi], 1——传指针几乎零开销（不拷贝整个对象）。传结构体则按字段规则，ch10 详。

为什么传指针比传大对象高效

struct big { char data[1024]; };

void f_val(struct big b)     { /* 拷贝 1024 字节到栈 */ }
void f_ptr(const struct big *p) { /* 一条 mov，8 字节指针进寄存器 */ }

传 1KB 结构体要拷贝 1KB 到栈帧；传指针一条 mov。HFT 报文常上百字节，几乎全用指针。

HFT / DPDK

输出参数模式

/* 解析报文，成功返回 0，输出解析结果到 *out */
int parse(const uint8_t *in, size_t len, struct quote *out);

struct quote q;
if (parse(pkt, n, &q) == 0) {  /* &q 是输出参数 */
    use(&q);
}

返回值留作错误码，真正结果通过指针写回——Linux/DPDK 系统调用风格的标配。

批量接口

/* DPDK 收包：把一批 mbuf 指针写入 pkts[]，返回数量 */
uint16_t n = rte_eth_rx_burst(port, q, pkts, BURST);
for (int i = 0; i < n; i++)
    process(pkts[i]);      /* pkts[i] 是 struct rte_mbuf* */

pkts 是 struct rte_mbuf *[BURST]——指针数组（6.11），调用者提供缓冲，函数填充。批量收发是 DPDK 性能关键。

常见误区

误区 事实
"传指针一定比传值快" 小对象（int）传值更快——少一次解引用
"函数参数 int a[] 是数组" 实际是 int *a，sizeof 退化（6.11）
"const int *p 不能改 p 自己" 能改 p 指向，不能改 *p（6.9）
"输出参数必须用指针" C23 引入 out 参数属性，但工程实践仍是指针

6.8

指针和变量

本节讲什么

指针变量和普通变量一样：有存储、有内容、有地址、能被重新赋值。这一节把"指针自身也是变量"这个事实讲透——它是理解 int *const、二级指针、迭代器式遍历的前提。

要点

int a = 1, b = 2;
int *p = &a;
p = &b;          /* 改指向，不影响 a（除非已通过 *p 写过） */
int **pp = &p;   /* pp 指向指针变量 p 本身 */
  • p 的内容是某个对象的地址；改 p 只改"指向谁"，不改变原指向对象的值
  • p 自身有地址：&p，类型 int **
  • 指针可重新指向，但指向 const 的指针有约束（6.9）
  • 迭代器式遍历：for (p = arr; p < arr+n; p++)（6.13），改 p 本身

三种"指针常量"组合（详见 6.9）

声明 指向对象 指针自身
int *p 可改 可改
const int *p 只读 可改
int *const p 可改 只读（初始化后不能改指向）
const int *const p 只读 只读

int *const p = &a; 的含义：p 这个变量本身是 const，不能 p = &b，但可以 *p = 1。读法：const 修饰其左边的 *，即修饰指针自身。

底层映射

重新指向的内存视图

初始：p → a(=1), b(=2)
  p 的内容 = &a

p = &b;
  p 的内容 = &b  (a 不变，仍为 1；除非之前 *p 改过)

*pp = &b;   /* 等价于 p = &b，因为 *pp 即 p */
**pp = 5;   /* 等价于 *p = 5，即改 b */

              ┌───┐
   pp  ──→   │ p │ ──→  a 或 b
              └───┘
   pp 是"指向指针的指针"，*pp 是 p，**pp 是 p 指向的对象

const 指针的编译检查

int *const p = &a;
p  = &b;   /* 编译错误：p 是 const */
*p = 5;    /* OK：改的是所指对象 */

const 在编译期就拦下，没有运行时开销。常用于"函数内不让指针被改指向"的防御性编程：

size_t sum(const int *arr, size_t n) {
    int *const end = (int *)arr + n;   /* end 锁定，不会被误改 */
    size_t s = 0;
    while (arr < (const int *)end) s += *arr++;
    return s;
}

arr 可改（迭代），end 锁死——读代码的人一眼看出 end 不变。

HFT / DPDK

用法 例子
游标指针遍历 for (p = base; p < end; p++) decode(p);
锁定的尾指针 int *const end = base + n; 防误改
可重指向的缓冲 rte_mbuf *m = ...; m = m->next;
多级管理 rte_mbuf **pp = &m; 改 m 的指向

常见误区

误区 事实
"p = &b 会改 a" 只改 p 的内容，a 不变（除非已通过 *p 改过）
"int *const p 表示所指对象只读" 错——只读的是 p 自身；要看 const 在 * 哪一侧（6.9）
"*p 和 p 是一回事" p 是指针变量，*p 是它指向的对象
"const 指针有运行时开销" 没有，纯编译期检查

指针常量

本节讲什么

const 与指针的四种组合 + void* 通用指针 + restrict 别名承诺（ch03 延伸，本章落地）。restrict 是 HFT 性能优化的核心关键字——它触发向量化，本节给出汇编证据。

要点

const 四层（读法：const 修饰它左边紧邻的 *；若在最左则修饰基类型）

声明 指向对象 指针自身 读法
int *p 可改 可改 普通指针

int *const q = &a;
q = &b;      /* 编译错误：改指针自身 */

restrict 与向量化（汇编证据）

restrict 承诺"在我生命周期内，这块内存只能通过我这个指针访问"——编译器据此假设无别名，可激进优化。

}

.L1:

    vpaddd   ymm0, ymm0, [rsi+rax*4]; 一次加 8 个
    vmovdqu  [rdi+rax*4], ymm0      ; 写回

    add     eax, [rsi+rcx*4]
    mov     [rdi+rcx*4], eax
    inc     rcx
    ...

6.10

指针的指针

本节讲什么

二级指针 T **：指向"指向 T 的指针"。它是"在函数内改调用者的指针"、"指针数组"、"argv"的语法基础。二级指针是新手最容易绕晕的地方，本节用内存图把它讲死。

要点

int x = 10;
int *p = &x;        /* p 指向 x */
int **pp = &p;      /* pp 指向 p */

**pp = 20;          /* 改 x：**pp == *p == x */
*pp = &y;           /* 改 p 的指向：*pp == p，现在 p 指向 y */

三层关系图

地址         内容             变量
0x1000  →    10            ← x (int)
0x1008  →    0x1000        ← p  (int*)，内容是 x 的地址
0x1010  →    0x1008        ← pp (int**)，内容是 p 的地址

*pp   = 取 pp 内容当指针，去该地址 → 得到 p（即 &x 这个地址值本身）
**pp  = 取 *pp 内容当指针，去该地址 → 得到 x 的值（10）

记忆：**pp = "解两次引用"。每解一次就往数据方向走一层。

两种改动的区别（核心考点）

**pp = 20;    /* 改 x 的值：p 不变，仍指向 x，但 x 变了 */
*pp  = &y;    /* 改 p 的指向：x 不变，p 现在指向 y */

6.11

指针表达式

本节讲什么

指针与数组的等价关系、指针数组 vs 数组指针、字符串与字符指针——这三组概念是"数组 ≠ 指针"误区的总根源，也是协议解析、字符串处理正确性的前提。本节把它们一次讲透。

要点

arr[i] ≡ *(arr + i)（核心等价）

char buf[64];
buf[3] == *(buf + 3);     /* 永远相等 */
3[buf] == *(3 + buf);     /* 也合法但禁止写 —— 交换律的副产品 */

C 标准把 E1[E2] 定义为 *((E1)+(E2))，加法可交换，所以 3[buf] 合法。工程上从不这么写，但理解它揭示了下标的本质。

数组名的三种语义（最易错）

表达式 含义 类型
buf（多数上下文） 首元素地址 &buf[0] char *
sizeof(buf) 整个数组的大小 编译期常量 64
&buf "指向整个数组的指针" char (*)[64]
&buf[0] 首元素地址 char * 
char buf[64];
char *p = buf;            /* buf 退化为 &buf[0]，char* */
char (*arrptr)[64] = &buf;/* &buf 是"指向 64 元数组的指针" */
size_t n = sizeof(buf);   /* 64，不退化 */

数组名在 sizeof、&、字符串字面量初始化的 [] 之外，都退化为首元素指针。

指针数组 vs 数组指针（经典区分）

struct rte_mbuf *pkts[32];        /* 指针数组：32 个 mbuf*，pkts 是 struct rte_mbuf**(退化后) */
struct rte_mbuf (*row)[32];       /* 数组指针：1 个指针，指向 32 元数组 */
声明 类型 含义
T *arr[N] T *[N] → 退化为 T ** N 个 T* 摆一起
T (*p)[N] T (*)[N] 一个指针，指向 T[N]

读法（螺旋法则，ch13 详）：从变量名出发，先右后左，遇 () 跳出。

字符串与字符指针

char *s = "rodata";        /* 字符串字面量在 .rodata，只读 */
s[0] = 'R';                /* SIGSEGV —— 改只读段 */

char t[] = "writable";     /* t 是栈数组，字面量被拷贝进来 */
t[0] = 'W';                /* OK */

const char *proto = "FIX.4.2";  /* 推荐：const 标记只读意图 */
形式 存储 可改 用途
char *s = "abc" .rodata 否（改崩） 只读常量
char t[] = "abc" 栈/全局 是 可改缓冲
const char *s = "abc" .rodata 否（编译器拦） 只读常量（推荐）

char *s = "abc" 在 C89 合法但 C11 起 deprecated，C23 起 UB——应一律用 const char *。

底层映射

buf[3] 的汇编

char buf[64];
char c = buf[3];

; x86-64 -O2
movsx   eax, BYTE PTR [rsp+3]    ; 直接 [rsp+3]，编译期算好偏移

数组在栈上，buf[3] 编译期已知偏移 = 3 字节，直接 [rsp+3]。若是指针：

char *p = ...;
char c = p[3];

movsx   eax, BYTE PTR [rdi+3]    ; p 在 rdi，运行期地址 + 3

差异：数组偏移编译期定，指针偏移运行期加。-O2 后两者常归一，但数组大小信息会丢（退化）。

实例

本节讲什么

把前 11 节的指针知识综合到一个实例：模拟 DPDK 批量收包 + 指针遍历 + 空指针过滤 + const 报文缓冲。这一节是 ch06 的"综合演练"，把理论落到 HFT 数据面的真实代码模式。

要点

实例 1：指针数组批量处理（DPDK burst 模式）

#define BURST 32
struct pkt { int type; /* ... */ };

void process_burst(struct pkt *pkts[BURST], int n)
{
    /* pkts 是指针数组，退化成 struct pkt ** */
    int i;
    for (i = 0; i < n; i++) {
        struct pkt *p = pkts[i];        /* *（pkts+i）取第 i 个指针 */
        if (p == NULL) continue;        /* 空指针过滤（6.6） */
        if (p->type == HEARTBEAT) continue;
        decode(p);
    }
}

关键点： - pkts[BURST] 退化为 struct pkt **（6.11） - pkts[i] ≡ *(pkts+i)，取"第 i 个指针" - 判空 p == NULL 在解引用 p->type 之前（短路，ch05）

实例 2：连续数组的指针算术遍历

void walk(struct pkt *base, int n)
{
    struct pkt *end = base + n;          /* 尾后一位（6.13.1） */
    for (; base < end; base++)           /* base 自增，步长 = sizeof(struct pkt) */
        decode(base);
}

关键点： - base + n 是 one-past-end，合法但不能解引用（6.13.1） - base++ 步长 = sizeof(struct pkt)，不是 1 字节（6.13.1） - base < end 同数组内比较，合法（6.13.2） - 遍历改的是 base 本身，原数组不动（6.8）

实例 3：const 报文 + 可改元数据

int handle(const uint8_t *in, size_t len, struct meta *out)
{
    /* in 只读：不改报文（6.9 const） */
    /* out 可写：写元数据 */
    if (len < HEADER_SIZE) return -1;            /* 边界检查 */
    const struct eth_hdr *h = (const struct eth_hdr *)in;
    out->ether_type = ntohs(h->ether_type);      /* 解析后写回 */
    return 0;
}

  • [ ] free(p); p = NULL; 成对（6.5）

底层映射

两种遍历的 cache 行为对比

连续数组遍历（walk）：
  base, base+1, base+2 ... 地址连续
  → 预取器 detects 顺序访问 → 自动 prefetch → L1 命中率高

指针数组遍历（process_burst）：
  pkts[0] → 报文A（某地址）
  pkts[1] → 报文B（另一地址）
  → 每次解引用可能 cache miss → 延迟高

这是为什么 DPDK 把报文集中放 mempool（连续大块）而非零散 malloc——cache 友好。

ABI 视角：pkts 走哪个寄存器

void process_burst(struct pkt *pkts[32], int n);

x86-64 SysV ABI：pkts（struct pkt **）走 rdi，n 走 esi。函数体里 pkts[i] = mov rax, [rdi + rsi*8]（8 = 指针宽度）。

常见误区

误区 事实
"base + n 解引用没事" one-past-end 解引用是 UB
"指针数组遍历和连续数组一样快" 指针数组每跳可能 miss，慢得多
"const 报文也能改" 改 .rodata 或 const 段会 SIGSEGV
"函数内 malloc 返回批量数组更方便" 调用者管理生命周期更安全

代码自测

题目 1： 以下代码试图用指针遍历数组，有什么问题？

int arr[5] = {1, 2, 3, 4, 5};
int *p = arr;
while (*p)
    printf("%d ", *p++);
参考答案

数组没有以 0 结尾，while (*p) 会在数组越界后继续读取内存，直到遇到值为 0 的内存位置才停止——这是未定义行为。对于非字符串数组，应该用索引或长度控制循环。
