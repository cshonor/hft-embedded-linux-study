12.1

链表

本节讲什么

链表是堆上 struct + 自引用指针构成的动态容器——节点在堆上分配，通过 next（和 prev）指针串联。链表是 DPDK mbuf 链、Linux 内核设备列表、HFT 订单池的公共模型。本章从链表节点设计、二级指针修改头、单链表/双链表操作、侵入式链表等方面，把 ch10（struct）和 ch11（动态内存）的概念落地为数据结构实现。

本节是链表章的入口，覆盖节点设计、二级指针、嵌套堆对象释放、结构体数组 vs 指针数组。

要点

链表节点设计

typedef struct quote {
    uint64_t seq;          /* 业务字段 */
    uint32_t bid, ask;
    struct quote *next;    /* 自引用指针，串联链表 */
} Quote;
  • 业务字段在前，next 在后（cache 友好，遍历时关键字段在前）
  • next 是指针，不是实体（ch10.2.3 自引用合法性）
  • calloc 优先于 malloc——指针自动清零为 NULL，避免野指针

堆上创建节点

Quote *new_quote(void) {
    Quote *node = calloc(1, sizeof *node);
    return node;   /* NULL = 内存耗尽 */
}
规范 说明
calloc 优先于 malloc，指针/数值清零
判空 分配后立即检查，NULL 表示 OOM
sizeof *node 惯用法，类型只出现一次

二级指针 Quote **

修改链表头指针必须用二级指针：

void list_push_front(Quote **head, Quote *new_node) {
    new_node->next = *head;
    *head = new_node;   /* 修改调用方的 head */
}

/* 调用 */
Quote *head = NULL;
Quote *n = new_quote();
list_push_front(&head, n);   /* 传 &head，让函数能改 head */

为什么需要 T**：

  • C 是值传递，void f(Quote *head) 只能修改 head 指向的对象，不能修改 head 本身
  • 要让函数能改调用方的 head，必须传 &head（即 Quote **）
  • 这是链表操作的核心模式——头插、头删、清空都需要 T**

嵌套堆对象释放

typedef struct msg {
    uint32_t magic;
    struct quote *quote_hdr;   /* 堆子对象指针 */
    uint8_t *payload;          /* 堆缓冲指针 */
} Msg;

void free_msg(Msg *m) {
    if (!m) return;
    free(m->quote_hdr);   /* 先 free 子对象 */
    free(m->payload);
    free(m);              /* 最后 free 本体 */
}

释放顺序铁律：先 free 子对象，再 free 本体

  • 若先 free 本体，子对象指针丢失，无法 free → 泄漏
  • 内嵌实体（struct quote hdr 而非指针）随外层一并释放，无需单独 free
/* 内嵌实体 vs 指针成员 */
typedef struct msg_inline {
    struct quote hdr;     /* 内嵌：随 msg 一并释放 */
} MsgInline;

typedef struct msg_ptr {
    struct quote *hdr;    /* 指针：需单独 free */
} MsgPtr;

结构体数组 vs 指针数组

类型 布局 适用
Quote arr[32] 连续实体，sizeof = 32×sizeof(Quote) 栈上固定小批，cache 友好
Quote *arr[32] 仅存地址，sizeof = 32×8 rte_rx_burst 批量收包

指针数组的优势：

  • 无大 struct 拷贝，只移动指针
  • 节点可分散在不同内存位置（堆、池）
  • DPDK rte_rx_burst 收包返回 struct rte_mbuf *pkts[BURST]，正是此模式
struct rte_mbuf *pkts[32];
uint16_t n = rte_eth_rx_burst(port, queue, pkts, 32);
for (int i = 0; i < n; i++) {
    process(pkts[i]);
    rte_pktmbuf_free(pkts[i]);   /* 用完归还池 */
}

链表 vs 数组选型

维度 链表 数组
随机访问 O(n) O(1)
头插/头删 O(1) O(n)
已知节点删除 单向 O(n)，双向 O(1) O(n)
内存局部性 差（节点分散） 好（连续）
大小 动态 固定（或需 realloc）
每节点开销 多一个/两个指针 无额外
HFT 倾向 订单池、空闲链 订单簿、报文缓冲

HFT 选型铁律：

  • 需要频繁头插/头删、大小变化大 → 链表
  • 需要随机访问、cache 友好、大小固定 → 数组
  • 订单簿（按价格查询）→ 定长数组 + 索引
  • 订单池（按 order_id 管理）→ 链表或哈希表

HFT 关联

  • DPDK mbuf 链：rte_mbuf 的 next 字段把多个 mbuf 串成分段报文（jumbo frame）
  • 订单池：未成交订单按 order_id 管理，用链表或哈希表
  • 内核设备列表：struct device 挂在双向链表上，list_head 侵入式设计
  • 空闲块管理：DPDK mempool 的空闲块用链表管理，无锁 per-lcore
  • 定时器：定时事件按到期时间排序的链表或最小堆

实操：DPDK mbuf 链

/* 收到的 jumbo frame 可能跨多个 mbuf */
struct rte_mbuf *m = /* 第一个 mbuf */;
while (m) {
    process_segment(m);
    struct rte_mbuf *next = m->next;   /* 保存 next */
    rte_pktmbuf_free(m);                /* 释放当前 */
    m = next;                           /* 移到下一个 */
}

注意释放前先保存 next——free 后 m->next 是 UAF。

实操：嵌套堆对象释放

typedef struct order {
    uint64_t id;
    char *clordid;        /* 堆上字符串 */
    struct order *next;
} Order;

void free_order(Order *o) {
    if (!o) return;
    free(o->clordid);   /* 先 free 子对象 */
    free(o);            /* 再 free 本体 */
}

void free_all(Order *head) {
    while (head) {
        Order *next = head->next;
        free_order(head);   /* 释放节点及其子对象 */
        head = next;
    }
}

12.2

单链表

本节讲什么

单向链表是链表的最简形式：每个节点只有 next 指针，只能单向遍历。本节是单链表的完整范式——头插、遍历、按 key 删除、全链销毁。这些操作是 HFT 订单池管理、空闲链表、事件队列的基础。掌握单链表是理解双链表（12.3）和经典 ADT（ch17）的前提。

本节是总览，子节展开插入节点和其他操作。

要点

节点结构

typedef struct quote {
    uint64_t seq;
    uint32_t bid, ask;
    struct quote *next;   /* 单向，仅 next */
} Quote;
  • 每个 node 含业务字段 + next 指针
  • 末节点的 next == NULL（标记链表结束）
  • calloc 创建节点时 next 自动为 NULL

核心操作复杂度

操作 复杂度 说明
头插 O(1) 改两个指针
头删 O(1) 改一个指针
尾插 O(n) 需遍历找尾
尾删 O(n) 需遍历找倒数第二
按值查找 O(n) 线性扫描
按值删除 O(n) 需找前驱
遍历 O(n) 顺序访问

HFT 偏好头插：O(1)，免尾遍历，订单池/空闲链常用。

头插 O(1)

void list_push_front(Quote **head, Quote *new_node) {
    new_node->next = *head;
    *head = new_node;
}

只需两步：

  1. new_node->next = *head：新节点指向原头
  2. *head = new_node：头指针更新为新节点

遍历

for (Quote *cur = head; cur; cur = cur->next) {
    process_quote(cur);
}
  • cur 从 head 开始，沿 next 前进
  • cur == NULL 时结束
  • 禁止在遍历中 free 当前节点——会丢失 next

全链销毁

void list_free_all(Quote **head) {
    Quote *cur = *head;
    while (cur) {
        Quote *tmp = cur;
        cur = cur->next;   /* 先存 next */
        free(tmp);         /* 再 free */
    }
    *head = NULL;
}

铁律：先保存 next，再 free 当前节点。free 后 cur->next 是 UAF。

按 seq 删除

int list_remove_by_seq(Quote **head, uint64_t target_seq) {
    Quote *cur = *head, *prev = NULL;
    while (cur) {
        if (cur->seq == target_seq) {
            if (prev)
                prev->next = cur->next;
            else
                *head = cur->next;   /* 删头节点 */
            free(cur);
            return 1;
        }
        prev = cur;
        cur = cur->next;
    }
    return 0;
}
  • 需维护 prev 指针（前驱）
  • 删头节点时 prev == NULL，需更新 *head
  • 删除中间节点：prev->next = cur->next

单链表的限制

  • 不能反向遍历：只有 next，无 prev
  • 删除已知节点需找前驱：O(n)，因为单链表无法从节点回溯到前驱
  • 不能 O(1) 删除当前节点：除非用"拷贝下一节点数据"技巧
/* 技巧：删除 cur（非尾节点）时，拷贝下一节点数据到 cur，再删 next */
void remove_by_copy(Quote *cur) {
    if (!cur || !cur->next) return;   /* 不能删尾节点 */
    Quote *victim = cur->next;
    *cur = *victim;        /* 拷贝数据 */
    cur->next = victim->next;
    free(victim);
}

这个技巧有副作用——cur 的地址变了（数据被覆盖），若有外部指针指向 cur->next 会失效。

HFT 关联

  • 订单池：未成交订单按 order_id 管理，头插 O(1) 添加
  • 空闲 mbuf 链：DPDK mempool 的空闲块用单链表，头插/头删 O(1)
  • 事件队列：FIFO 队列用尾插 + 头删（需维护 tail 指针）
  • 撤单处理：按 order_id 查找并删除，O(n) 但订单数通常可控
  • 性能：链表遍历 cache 不友好，热路径优先用定长数组

实操：订单池

Quote *order_pool = NULL;   /* 全局订单池头 */

void add_order(uint64_t seq, uint32_t bid, uint32_t ask) {
    Quote *o = calloc(1, sizeof *o);
    if (!o) return;
    o->seq = seq;
    o->bid = bid;
    o->ask = ask;
    list_push_front(&order_pool, o);   /* O(1) 头插 */
}

void cancel_order(uint64_t seq) {
    list_remove_by_seq(&order_pool, seq);
}

实操：事件队列（FIFO）

typedef struct event {
    uint64_t ts;
    void *data;
    struct event *next;
} Event;

Event *q_head = NULL, *q_tail = NULL;

void enqueue(Event *e) {
    e->next = NULL;
    if (q_tail)
        q_tail->next = e;   /* 尾插 */
    else
        q_head = e;         /* 空队列 */
    q_tail = e;
}

Event *dequeue(void) {
    if (!q_head) return NULL;
    Event *e = q_head;
    q_head = e->next;
    if (!q_head) q_tail = NULL;   /* 队列空 */
    return e;
}

维护 tail 指针让尾插也 O(1)，实现 FIFO 队列。

12.2

.1 插入节点

本节讲什么

头插法 list_push_front 是低延迟链表追加节点的标准写法——O(1) 复杂度，只需改两个指针。本节剖析头插的实现、与尾插的对比、二级指针的必要性、以及 HFT 场景的应用。

要点

头插实现

void list_push_front(Quote **head, Quote *new_node) {
    new_node->next = *head;
    *head = new_node;
}

两步操作：

  1. new_node->next = *head：新节点的 next 指向原头节点（或 NULL 若链表空）
  2. *head = new_node：头指针更新为新节点

内存布局示意

插入前：
head -> [A] -> [B] -> NULL
         ↑
       *head

new_node = [X]

插入后：
head -> [X] -> [A] -> [B] -> NULL
         ↑
       *head

只需改 new_node->next 和 *head，原有节点 [A] 和 [B] 不动。

用法

Quote *head = NULL;

Quote *n = new_quote();   /* calloc 创建 */
if (n) {
    n->seq = 1001;
    list_push_front(&head, n);   /* 传 &head */
}
要点 说明
入参 Quote ** 可修改调用方的 head
new_node->next calloc 后为 NULL，头插到空链表也安全
不需要判空 头插对空链表和非空链表统一处理

为什么需要 Quote **

/* 反例：用 Quote *，无法修改调用方的 head */
void bad_push(Quote *head, Quote *new_node) {
    new_node->next = head;
    head = new_node;   /* 只改了局部变量！调用方的 head 不变 */
}

Quote *head = NULL;
bad_push(head, n);   /* head 仍是 NULL！ */

C 是值传递：

  • void f(Quote *head) 中 head 是调用方指针的副本
  • 修改副本不影响调用方的原指针
  • 要改调用方的指针，必须传指针的地址（Quote **）
/* 正例：用 Quote **，能修改调用方的 head */
void good_push(Quote **head, Quote *new_node) {
    new_node->next = *head;   /* *head 是调用方的 head 值 */
    *head = new_node;         /* 修改调用方的 head */
}

Quote *head = NULL;
good_push(&head, n);   /* 传 &head，head 被更新 */

尾插对比

void list_push_back(Quote **head, Quote *new_node) {
    new_node->next = NULL;
    if (!*head) {
        *head = new_node;   /* 空链表 */
        return;
    }
    Quote *tail = *head;
    while (tail->next)       /* 遍历找尾，O(n) */
        tail = tail->next;
    tail->next = new_node;
}
  • 尾插需遍历找尾，O(n)
  • 维护 tail 指针可让尾插 O(1)，但增加维护成本
  • HFT 订单池/空闲链常用头插——O(1)，免尾遍历

有序插入

void list_insert_sorted(Quote **head, Quote *new_node) {
    Quote **pp = head;
    while (*pp && (*pp)->seq < new_node->seq)
        pp = &(*pp)->next;   /* 二级指针遍历 */
    new_node->next = *pp;
    *pp = new_node;
}
  • 按 seq 升序插入
  • 用 Quote **pp 遍历，避免单独处理头节点
  • 复杂度 O(n)，但保持链表有序

批量插入

void list_push_batch(Quote **head, Quote **nodes, size_t n) {
    for (size_t i = 0; i < n; i++) {
        list_push_front(head, nodes[i]);
    }
}
  • 批量头插，每个 O(1)
  • 注意顺序：头插后 nodes 数组的顺序在链表中是逆序

HFT 关联

  • 订单池：新订单头插 O(1)，无延迟
  • 空闲 mbuf 链：DPDK mempool 归还 mbuf 用头插，O(1)
  • 事件队列：FIFO 需要尾插，维护 tail 指针
  • 批量收包：rte_rx_burst 返回多个 mbuf，可批量头插入处理队列
  • 性能：头插是链表最快操作，约 5-10 ns（cache 命中）

实操：订单池头插

typedef struct order {
    uint64_t order_id;
    uint32_t price, qty;
    struct order *next;
} Order;

Order *pool = NULL;

void new_order(uint64_t id, uint32_t price, uint32_t qty) {
    Order *o = calloc(1, sizeof *o);
    if (!o) return;
    o->order_id = id;
    o->price = price;
    o->qty = qty;
    o->next = pool;    /* calloc 已让 next=NULL，这里覆盖 */
    pool = o;
}

实操：二级指针遍历

/* 删除第一个 seq 匹配的节点，用二级指针简化 */
int remove_first(Quote **head, uint64_t seq) {
    Quote **pp = head;
    while (*pp) {
        if ((*pp)->seq == seq) {
            Quote *victim = *pp;
            *pp = victim->next;   /* 跳过 victim */
            free(victim);
            return 1;
        }
        pp = &(*pp)->next;
    }
    return 0;
}

Quote **pp 技巧避免单独处理头节点——*pp 始终是要检查的节点指针，pp 是指向该指针的指针。

12.2

.2 其他操作

本节讲什么

单向链表的核心操作：遍历、全链销毁、按 key 删除、头删。这些是撤单、过期清理、防泄漏的核心。本节详细剖析每个操作的实现、陷阱、以及 HFT 线上常见 bug 模式。

要点

遍历

void list_iterate(Quote *head) {
    for (Quote *cur = head; cur; cur = cur->next) {
        process_quote(cur);
    }
}
  • cur 从 head 开始，沿 next 前进
  • cur == NULL 时结束（末节点的 next 是 NULL）
  • 复杂度 O(n)
  • 禁止在遍历中 free 当前节点——会丢失 next

全链销毁（防泄漏）

void list_free_all(Quote **head) {
    Quote *cur = *head;
    while (cur) {
        Quote *tmp = cur;
        cur = cur->next;   /* 先存 next */
        free(tmp);         /* 再 free */
    }
    *head = NULL;
}

铁律：先存 next，再 free 当前

/* 反例：free 后读 next，UB */
while (cur) {
    free(cur);
    cur = cur->next;   /* UAF！cur 已 free */
}
  • free 后 cur 指向的内存可能被复用
  • cur->next 读取的是已释放内存，UB
  • 可能"看起来正常"（内存未复用），也可能立即崩溃

按 seq 删除

int list_remove_by_seq(Quote **head, uint64_t target_seq) {
    Quote *cur = *head, *prev = NULL;
    while (cur) {
        if (cur->seq == target_seq) {
            if (prev)
                prev->next = cur->next;   /* 删中间/尾 */
            else
                *head = cur->next;        /* 删头节点 */
            free(cur);
            return 1;
        }
        prev = cur;
        cur = cur->next;
    }
    return 0;   /* 未找到 */
}

关键点：

  • 需维护 prev（前驱指针）
  • 删头节点时 prev == NULL，更新 *head
  • 删中间/尾节点：prev->next = cur->next

二级指针简化删除

int list_remove_v2(Quote **head, uint64_t target_seq) {
    Quote **pp = head;
    while (*pp) {
        if ((*pp)->seq == target_seq) {
            Quote *victim = *pp;
            *pp = victim->next;   /* 跳过 victim */
            free(victim);
            return 1;
        }
        pp = &(*pp)->next;
    }
    return 0;
}

Quote **pp 技巧：

  • pp 始终指向"指向当前节点的指针"
  • *pp = victim->next 自动处理头节点和中间节点
  • 无需 prev 变量，代码更简洁

头删

void list_pop_front(Quote **head) {
    if (!*head) return;   /* 空链表 */
    Quote *del = *head;
    *head = del->next;
    free(del);
}
  • O(1)
  • 需 Quote ** 修改调用方的 head
  • 空链表检查防 UB

查找

Quote *list_find(Quote *head, uint64_t seq) {
    for (Quote *cur = head; cur; cur = cur->next) {
        if (cur->seq == seq) return cur;
    }
    return NULL;   /* 未找到 */
}
  • O(n) 线性扫描
  • 返回节点指针或 NULL
  • 调用方必须判 NULL 再解引用

长度

size_t list_length(Quote *head) {
    size_t n = 0;
    for (Quote *cur = head; cur; cur = cur->next)
        n++;
    return n;
}
  • O(n)
  • 若频繁需要长度，应维护 size 字段（链表头结构体）

反转

void list_reverse(Quote **head) {
    Quote *prev = NULL, *cur = *head;
    while (cur) {
        Quote *next = cur->next;
        cur->next = prev;   /* 反转指向 */
        prev = cur;
        cur = next;
    }
    *head = prev;
}
  • O(n) 时间，O(1) 空间
  • 三指针遍历：prev/cur/next

线上陷阱总结

陷阱 1：只 free 外层，漏嵌套堆指针

typedef struct order {
    char *clordid;        /* 堆上字符串 */
    struct order *next;
} Order;

/* 反例：漏 free clordid */
void bad_free_all(Order **head) {
    Order *cur = *head;
    while (cur) {
        Order *tmp = cur;
        cur = cur->next;
        free(tmp);   /* 只 free 节点，clordid 泄漏！ */
    }
}

/* 正例：先 free 子对象 */
void good_free_all(Order **head) {
    Order *cur = *head;
    while (cur) {
        Order *tmp = cur;
        cur = cur->next;
        free(tmp->clordid);   /* 先 free 子对象 */
        free(tmp);            /* 再 free 节点 */
    }
    *head = NULL;
}

陷阱 2：free 后再读 next

/* 反例 */
while (cur) {
    free(cur);
    cur = cur->next;   /* UAF！ */
}

/* 正例 */
while (cur) {
    Quote *next = cur->next;   /* 先存 */
    free(cur);
    cur = next;
}

陷阱 3：删头用 Quote * 无法改外部 head

/* 反例 */
void bad_remove_head(Quote *head) {
    if (!head) return;
    Quote *del = head;
    head = head->next;   /* 只改局部变量！ */
    free(del);
}

Quote *mylist = /* ... */;
bad_remove_head(mylist);   /* mylist 不变，del 已 free → 悬垂 */

陷阱 4：malloc 未清零 → 野 next

/* 反例 */
Quote *n = malloc(sizeof *n);   /* malloc，未清零 */
n->seq = 1001;
list_push_front(&head, n);   /* n->next 是垃圾值！遍历会越界 */

/* 正例 */
Quote *n = calloc(1, sizeof *n);   /* calloc，next 自动 NULL */
n->seq = 1001;
list_push_front(&head, n);   /* 安全 */

HFT 关联

  • 撤单处理：list_remove_by_seq 按 order_id 删除
  • 过期清理：定时遍历，删除过期订单
  • 批量释放：rte_pktmbuf_free 批量归还 mbuf 到池
  • 订单池销毁：进程退出时 list_free_all 释放所有订单
  • valgrind 验证：CI 流程用 valgrind 确保无泄漏

实操：撤单

void cancel_order(Quote **order_pool, uint64_t order_id) {
    if (list_remove_by_seq(order_pool, order_id)) {

实操：定时清理过期订单

void purge_expired(Quote **head, uint64_t now_ts, uint64_t ttl) {
    Quote **pp = head;
    while (*pp) {
        if (now_ts - (*pp)->seq > ttl) {   /* seq 作为时间戳 */
            Quote *victim = *pp;
            *pp = victim->next;
            free(victim);
        } else {
            pp = &(*pp)->next;
        }
    }
}

注意：删除时 pp 不前进（因为 *pp 已变），保留时才前进。

12.3

双链表

本节讲什么

单向链表只能「向右走」，删一个节点必须先找到它的前驱；双向链表在每个节点里多塞一个 prev 指针，让每个节点都同时知道自己的前驱和后继。这一改动看似只是多 8 字节内存，却带来两个结构性能力：

  1. O(1) 摘除已知节点——不再需要遍历找 prev，写高频删除场景（订单撤单、定时器超时摘除）的关键。
  2. 反向遍历——日志回放、缓冲区回溯等需要从尾向头走的场景不再受限。

本节先定下节点结构、与单链的选型对比，再展开内核 list_head 的哨兵头节点思想，这是后续 ch13 container_of、ch17 通用容器的基石。

要点

节点结构

#include <stdint.h>
#include <stddef.h>

typedef struct dnode {
    uint64_t        seq;     /* 业务序号，例如订单号 */
    struct dnode   *next;    /* 后继 */
    struct dnode   *prev;    /* 前驱 */
} DNode;

内存布局（x86-64，按 8 字节对齐）：

偏移  字段       字节
 0    seq         8
 8    next        8
16    prev        8
总大小 sizeof(DNode) = 24，对齐 = 8

三个 8 字节字段天然 8 对齐，无 padding。若再追加一个 void *payload，仍是 8 对齐，结构紧凑。这是双向链表相对单链「多一个指针」的代价：每节点多 8 字节，换 O(1) 删除。

单链 vs 双链 选型对比

维度 单链表 双链表
节点内存 2 字段（seq + next） 3 字段（seq + next + prev）
头插 O(1) O(1)
头删 O(1) O(1)
删已知节点 O(n)（必须找 prev） O(1)（直接改 prev/next）
反向遍历 不支持 支持
实现复杂度 低 中（四指针维护）
UB 风险面 小 中（prev/next 任一失配）
HFT 典型场景 单生产者任务队列、报文批量收 订单簿挂单撤单、定时器轮

选型口诀：只头删、永远不删中间 → 单链；要按业务键随机删 → 双链。HFT 订单簿里，撤单是按订单号定位后立即摘除，双链是必选。

哨兵头节点（内核 list_head 思想）

朴素双链用 DNode *head，空链 head == NULL，每次插入/删除都要判空处理首尾边界。Linux 内核换了个思路：头节点本身是真实存在的对象，head.next 和 head.prev 初始都指向自己，构成一个自环。

typedef struct list_head {
    struct list_head *next, *prev;
} list_head;

#define LIST_HEAD_INIT(name) { &(name), &(name) }
#define LIST_HEAD(name) \
    struct list_head name = LIST_HEAD_INIT(name)

空链判断从 head == NULL 变成 list_empty(head) = (head->next == head)。带来的红利：

  • 插入/删除时不再需要判空：list_add 永远是「在两个有效节点之间插入」，没有 NULL 分支。
  • 头节点恒定存在，头指针永不变化，多线程下头节点是只读共享数据，减少了一类竞争。
  • list_for_each 遍历到 head 自身即结束，终止条件统一。

代价：每个链多占一个 list_head 大小（16 字节）的常驻内存，对内核是可忽略的。

朴素双链 vs 哨兵双链 空链状态

朴素空链：  head = NULL

哨兵空链：  +--------+
            |  head  |
            | next --+--+
            | prev --+--+   (自环)
            +--------+  |  |
                ^       |  |
                +-------+--+

哨兵模式下的「空」不是 NULL，而是自指。这种统一形式让所有链表操作的代码路径合并为一条，是工程上极高性价比的设计。

HFT 关联

订单簿双向挂单

限价订单簿的每个价位是一个双向链表头，同价位的订单按时间序挂入。撤单时直接拿到 DNode * 指针，O(1) 摘除：

/* 撤单：node 已由订单号哈希表定位 */
dlist_remove(node);      /* O(1) 摘链 */
order_free(node);        /* 归还订单池 */

若用单链，撤单要遍历同价位链找前驱，价位挂单多时延迟不可控——HFT 不可接受。

双向 prefetch

L1 cache 预取指令 __builtin_prefetch 可以指定读方向。双向链表允许同时预取 next 和 prev，做反向回放（例如撮合后回滚）时不用先反向建链：

__builtin_prefetch(cur->next, 0, 0);
__builtin_prefetch(cur->prev, 0, 0);

DPDK rte_ring 与双链的边界

DPDK 的 rte_ring 是无锁环形队列，本质上是一个定长数组 + head/tail 原子索引，不是链表。它解决的是 SPSC/MPMC 批量入队出队，节点不可摘除。「需要随机删除」时不能用 rte_ring，必须用双链——这是 HFT 选型时容易混淆的点。

内核 timer wheel

Linux 旧版定时器轮（include/linux/timer.h）每个槽位是 struct list_head，超时定时器挂双向链。到期检查时整链扫描 + 摘除，O(1) 摘除是性能关键。新版本改用基于 RB-tree 的方案，但 list_head 思路在内核无处不在。

UB 边界

情形 后果 防护
n->prev 是已 free 的节点 UAF，可能读到垃圾指针 摘链与 free 必须成对，先摘后 free
n->next / n->prev 同时被多核改写 数据竞争，UB 加写屏障 smp_wmb() 或用 RCU
删除后未把 n->next/prev 置 NULL 误用旧指针二次摘链 LIST_POISON1/2 注入魔数，触发可识别崩溃
头节点未初始化就插入 野指针 用 LIST_HEAD 宏初始化，杜绝手动赋值

LIST_POISON1 = ((void *) 0x00100100)、LIST_POISON2 = ((void *) 0x00200200) 是内核在 list_del 后写入 next/prev 的「毒药值」，任何后续访问都会触发页错误，让 UAF 立即可见，比 NULL 更易调试。

12.3

.1 插入节点

本节讲什么

双向链表的插入操作本质上只有两种：头插（在 head 之前）和中间插入（在某个已知节点 prev 之后或之前）。本节给出这两种操作的精确代码、指针改写顺序的图解，以及哨兵头节点模式下「无 NULL 分支」的简化版本。

关键认知：双向链表插入是四指针改写，不是两指针。顺序写错会丢指针，留下野指针或环。HFT 场景下这种 bug 一旦上线，订单簿会随机丢单，且 ASan 不一定能在生产环境捕获（多线程下读写交错）。

要点

头插（朴素双链）

void dlist_push_front(DNode **head, DNode *n)
{
    n->prev = NULL;
    n->next = *head;
    if (*head)
        (*head)->prev = n;
    *head = n;
}

四步图解（假设原链为 A -> B，插入 N）：

初始：  head --> A --> B --> NULL   ；A.prev = NULL, B.prev = A

步骤1： n->prev = NULL          // N 的前驱置空
步骤2： n->next = *head (=A)    // N 的后继指向 A
        +--+   +--+   +--+
        |N |-->|A |-->|B |-->NULL
        |  |<--|  |<--|  |
        +--+   +--+   +--+
        ^ prev=NULL
        | next 仍指向 NULL（A.prev 还没改）

步骤3： (*head)->prev = n       // A 的前驱改为 N
        +--+   +--+   +--+
        |N |-->|A |-->|B |-->NULL
        |  |<--|  |<--|  |
        +--+   +--+   +--+
        prev=NULL   prev=N

步骤4： *head = n               // 头指针指向 N
        head
          |
          v
        +--+   +--+   +--+
        |N |-->|A |-->|B |-->NULL
        |  |<--|  |<--|  |
        +--+   +--+   +--+

DNode **head 是必须的——头插要改头指针本身，值传递 DNode *head 改的是副本，调用方看不到新头。这与单链表头插同理（详见 12.2.1）。

中间插入（在 prev 之后插入 new）

void dlist_insert_after(DNode *prev, DNode *n)
{
    n->next = prev->next;
    n->prev = prev;
    if (prev->next)
        prev->next->prev = n;
    prev->next = n;
}

四步图解（在 A 之后插入 N，原链 A -> B）：

初始：  ... -> A -> B -> ...
              A.next=B, B.prev=A

步骤1： n->next = prev->next (=B)   // N 的后继先指向 B
步骤2： n->prev = prev (=A)         // N 的前驱指向 A
步骤3： prev->next->prev = n        // B 的前驱改为 N（先于改 A.next！）
步骤4： prev->next = n              // A 的后继改为 N

步骤 3 和 4 的顺序不可颠倒：必须先用 prev->next 找到原后继 B 并改它的 prev，然后才能覆盖 prev->next。一旦先写 prev->next = n，B 的 prev 指针就再也没人改了，链断了。

中间插入的 NULL 处理

if (prev->next) 判空处理的是「prev 是尾节点」的情形——此时 prev->next = NULL，没有后继需要改 prev。这是朴素双链的边界分支。

哨兵头节点模式下的插入

引入哨兵后，链永不为空，所有插入都变成「在两个有效节点之间插入」，NULL 判空全部消失：

/* 哨兵模式：head 是 list_head，不是指针 */
static inline void list_add(list_head *head, list_head *n)
{
    __list_add(n, head, head->next);
}

static inline void __list_add(list_head *n,
                              list_head *prev,
                              list_head *next)
{
    next->prev = n;
    n->next = next;
    n->prev = prev;
    prev->next = n;
}

四步无任何 if，性能可预测（无分支预测失败）。这正是内核 list_add 的核心实现，HFT 借鉴这种写法可以减少分支预测的不确定性。

头插 vs 尾插

/* 头插：在 head 与 head->next 之间 */
list_add(head, n);        /* 新节点变成第一个 */

/* 尾插：在 head->prev 与 head 之间 */
list_add_tail(head, n);   /* 新节点变成最后一个 */

哨兵模式下，head->prev 恒等于尾节点（自环特性），尾插无需遍历。朴素双链尾插要 O(n) 遍历或维护单独的 tail 指针。

HFT 关联

批量插入避免 cache 行 ping-pong

HFT 订单簿同一价位频繁头插，多个核同时挂单会让 head 节点所在 cache 行不断失效。优化思路：

  1. 批量挂单：收集一批订单，单核一次性链入，减少 head cache 行的失效次数。
  2. per-CPU 链 + 合并：每核一条本地链，定期合并到全局链，类似内核 percpu 设计。
  3. cache 行对齐：head 用 alignas(64) 独占一行，避免与相邻字段 false sharing。
struct orderbook_level {
    struct list_head head  __attribute__((aligned(64)));
    uint32_t          count;
    uint32_t          total_qty;
} __attribute__((aligned(64)));

跨核可见性与写屏障

多核场景下，步骤 3「改 B 的 prev」和步骤 4「改 A 的 next」必须在其他核看来按顺序生效，否则别的核可能看到 A.next = N 但 N.prev 还没改，反向遍历会野指针。x86 强内存模型下写-写天然有序，但 ARM64（DPDK 部分场景）需要显式写屏障：

n->next = prev->next;       /* 先把 n 自己写好 */
n->prev = prev;
prev->next->prev = n;
smp_wmb();                  /* 写屏障：保证上面的写对其他核可见 */
prev->next = n;             /* 最后才让 n 进入链 */

读端用 smp_rmb() 或 READ_ONCE 配合。RCU 场景下读端可以无锁遍历，写端用 synchronize_rcu() 等待读者退出。

订单簿挂单的实际代码骨架

void ob_add_order(struct orderbook_level *lvl, struct order *o)
{
    /* 同价位按时间序挂到尾部，避免插队 */
    list_add_tail(&lvl->head, &o->link);
    lvl->count++;
    lvl->total_qty += o->qty;
}

注意 list_add_tail 是 O(1)，因为 lvl->head.prev 直接给出尾节点。若用朴素双链且只维护 head，挂尾要 O(n)，HFT 不可接受。

UB 边界

情形 后果 防护
步骤 3、4 顺序颠倒 B 的 prev 永远是旧值，反向遍历野指针 严格按「先改后继的 prev，再改前驱的 next」
插入前 prev 已 free UAF，读到垃圾指针 调用方负责保证 prev 有效
n 已在另一条链上 同一节点出现在两条链，遍历死循环或丢指针 插入前断言 n->next == n->prev == NULL（朴素模式）或调用 list_del_init 先摘除

摘除再插入的合并陷阱

/* 错误：先 list_del 再 list_add，中间窗口期 n 不在任何链上 */
list_del(n);
list_add(head, n);

/* 内核提供 list_move 原子语义（实际仍是非原子，但语义清晰） */
list_move(head, n);   /* = list_del + list_add，调用方负责锁 */

list_move 不是真原子，多线程下仍需外部锁。但语义统一、代码更短，减少手写错误。

12.3

.2 其他操作

本节讲什么

本节覆盖双向链表除插入外的所有日常操作：前向/反向遍历、O(1) 摘除已知节点、全链销毁、哨兵模式下的统一删除。重点是 container_of 反向定位外层结构——这是内核链表、DPDK 链表、HFT 订单簿把 list_head 当作「内嵌链节点」使用的核心机制。

认知锚点：双向链表的 O(1) 摘除不是「技巧」，而是结构性能力。它使得订单撤单、定时器超时摘除、epoll 就绪摘除等高频操作可在常数时间完成，是 HFT 链表选双不选单的根本理由。

要点

前向遍历

for (DNode *cur = head; cur; cur = cur->next)
    process(cur);

哨兵模式：

list_for_each(pos, head) {
    /* pos 是 list_head *，需 container_of 取外层 */
    struct order *o = list_entry(pos, struct order, link);
    process(o);
}

反向遍历（双链独有）

for (DNode *cur = tail; cur; cur = cur->prev)
    process(cur);

朴素双链反向遍历需要单独维护 tail 指针，否则要从 head 走到尾再回溯，O(n²)。哨兵模式下 head->prev 即尾节点，反向遍历 O(n) 一次走完。

O(1) 摘除已知节点

void dlist_remove(DNode *n)
{
    if (n->prev)
        n->prev->next = n->next;
    else
        /* n 是 head，需由调用者更新 *head */;

    if (n->next)
        n->next->prev = n->prev;
}

朴素模式下，若 n 恰好是 head，n->prev == NULL，无法通过 prev 改前驱——必须由调用方拿 DNode **head 或返回新 head。这是朴素双链的边界麻烦。

哨兵模式下没有任何 NULL，代码统一为三行：

static inline void __list_del(list_head *prev, list_head *next)
{
    next->prev = prev;
    prev->next = next;
}

static inline void list_del(list_head *entry)
{
    __list_del(entry->prev, entry->next);
    entry->next = LIST_POISON1;
    entry->prev = LIST_POISON2;
}

LIST_POISON1/2 是非空魔数（0x00100100 / 0x00200200），任何后续访问都会触发页错误，让 UAF 立即可见。比置 NULL 更安全：NULL 解引用可能被零页映射掩盖，毒药值必然崩。

全链销毁

void dlist_free_all(DNode **head)
{
    DNode *cur = *head;
    while (cur) {
        DNode *tmp = cur;
        cur = cur->next;   /* 先存 next 再 free */
        free(tmp);
    }
    *head = NULL;
}

先存 next 再 free 是铁律——free 之后访问 cur->next 是 UAF，ASan 必报。哨兵模式下遍历到 head 自身即停，无需单独判 NULL。

container_of 反向定位外层

朴素双链里 DNode 自身就是业务节点，链节点与业务字段同处一个结构。哨兵模式下 list_head 是内嵌的小结构，业务结构把它作为成员之一：

struct order {
    uint64_t          order_id;
    uint32_t          price;
    uint32_t          qty;
    struct list_head  link;   /* 内嵌链节点 */
};

挂入链表的是 &order->link，遍历时拿到的是 list_head *，怎么取回外层 struct order *？答案：container_of。

#define container_of(ptr, type, member) \
    ((type *)((char *)(ptr) - offsetof(type, member)))

#define list_entry(ptr, type, member) \
    container_of(ptr, type, member)

/* 使用 */
struct order *o = list_entry(pos, struct order, link);

推导过程

offsetof(type, member) 是 member 字段在 type 起始处的字节偏移。给定 &order->link 的地址 ptr，外层 order 的起始地址 = ptr - offsetof(struct order, link)。强转回 struct order * 即可。

struct order 内存布局（假设 8 对齐）：
偏移  字段
 0    order_id
 8    price + qty  （4+4）
16    link.next
24    link.prev

offsetof(struct order, link) = 16

ptr = &order->link  // 指向偏移 16
order_addr = (char *)ptr - 16

这是纯指针算术，不依赖任何运行时信息，编译期即可折叠为单条 lea 指令（x86-64）。

为何不直接用「包含业务的节点」

朴素 DNode 把业务字段（seq）与链字段（next/prev）揉在一个结构里，问题：

  1. 同一业务对象无法同时挂在多条链上——只有一个 next/prev，挂到链 A 就不能挂到链 B。
  2. 链代码与业务代码耦合——链操作要知道业务字段名，无法通用化。

list_head 内嵌 + container_of 解决了这两点：

  • 业务对象可以同时挂多条链：每个链一个 list_head 成员，挂不同链用不同成员。
  • 链操作完全 generic：list_add/list_del 只操作 list_head，不知道也不关心外层是什么类型。

这是内核 list.h 能用一套代码挂接进程、文件、网络包、定时器的根本原因。

哨兵模式下「链不空」的语义

static inline int list_empty(const struct list_head *head)
{
    return head->next == head;
}

空链 = head 自指。注意：list_empty 在多线程下不可靠——读到 head->next 时别的核可能已经插入。RCU 场景下要用 list_empty_rcu，但本质仍是「近似判断」，精确语义需要锁。

HFT 关联

订单撤单 O(1) 摘除

/* 订单号 -> struct order * 的哈希表已定位到 o */
void ob_cancel_order(struct order *o)
{
    list_del(&o->link);          /* O(1) 摘链 */
    order_pool_free(o);          /* 归还 mempool */
}

若用单链，撤单要在同价位链上遍历找前驱，同价位挂单多时延迟数十到数百纳秒，HFT 不可接受。双链 O(1) 摘除是订单簿的标配。

DPDK rte_ring 与 list_head 的分工

场景 选型 理由
收发包批量入队/出队 rte_ring 无锁 SPSC/MPMC，定长数组，cache 友好
订单簿同价位挂单 list_head 双链 需要随机摘除，rte_ring 做不到
定时器超时管理 list_head 双链 O(1) 摘除到期 timer
per-CPU 本地积压 list_head 双链 单核访问，无需无锁，简单

rte_ring 解决批量流转，list_head 解决随机摘除——两者分工明确，不是替代关系。

epoll 就绪链表

内核 epoll 用 list_head 把就绪的 epoll_item 串成就绪链。ep_send_events 遍历就绪链、摘除已处理的项，全程 O(就绪数)。这是 HFT 网络线程核心路径的内核侧实现，与用户态双链操作同构。

mempool 与链表的协作

DPDK rte_mempool 内部用 ring 做无锁对象池，但取出后的 mbuf 在用户代码里常挂 list_head（例如批量收包后挂到处理链）。mempool 负责「对象生命周期」，list_head 负责「对象组织」，职责分离。

UB 边界

情形 后果 防护
摘除后未 free，又用 n->next 读到 LIST_POISON1，页错误 摘链与释放成对，ASan 编译期能查部分
同一节点 list_del 两次 第二次读到 POISON，崩溃 摘除后置 n->next = n->prev = NULL（朴素模式）或用 list_del_init 重置为自环
遍历中 free 当前节点 UAF，ASan 必报 先存 next 再 free
container_of 用错 member 类型 指针偏移错位，读到错位字段 _Static_assert(offsetof(...) 或编译期类型检查
多核同时 list_del 同一节点 数据竞争，prev/next 半改状态 锁或 RCU
list_for_each_safe 误用普通 list_for_each 后删节点 遍历指针野 删除场景必须用 _safe 版本

list_for_each_safe 的必要性

list_for_each_safe(pos, n, head) {
    struct order *o = list_entry(pos, struct order, link);
    if (should_remove(o)) {
        list_del(pos);
        order_pool_free(o);
        /* n 已预存了 pos->next，安全继续 */
    }
}

普通 list_for_each 在删除后，pos->next 已被改成 POISON，下一轮 pos = pos->next 必崩。_safe 版本预先保存 next，是删除场景的标准用法。

list_del_init 的「安全再挂」

list_del_init(entry);   /* 摘链并重置为自环 */
/* 后续可安全 list_add 到其他链 */

相比 list_del 写 POISON，list_del_init 把 entry 重置成「自环空链」状态，可直接再挂入新链。适用于对象池化复用场景——HFT 订单复用 mempool 时常用。

章节自测

题目 1： 以下链表删除节点的代码有什么问题？

void delete(Node *head, int val) {
    Node *cur = head;
    while (cur->next && cur->next->val != val)
        cur = cur->next;
    if (cur->next) {
        Node *tmp = cur->next;
        cur->next = tmp->next;
        // 没有 free(tmp)
    }
}
参考答案

内存泄漏——删除的节点 tmp 没有被 free。虽然从链表中移除了，但内存仍然占用。正确做法：free(tmp); 在 cur->next = tmp->next; 之后。此外，如果要删除的是头节点，这段代码无法处理（需要二级指针或返回新头）。
