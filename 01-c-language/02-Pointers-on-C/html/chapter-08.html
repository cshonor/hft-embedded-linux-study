8.3

指针数组

本节讲什么

指针数组 Type *arr[N]：数组元素为指针。DPDK rte_rx_burst 的 pkts[BURST] 即此模型。这一节把它和 8.2.4 的数组指针彻底区分，并讲清它在 HFT 批量接口里的核心地位。

要点

struct rte_mbuf *pkts[32];          /* 32 个 mbuf*，指针数组 */
pkts[0] = rte_pktmbuf_alloc(pool);  /* 给第 0 槽填一个 mbuf 地址 */

/* 多端口 */
struct rte_mbuf *port_queue[8][16]; /* 8 口 × 16 队列槽 */
特性 说明
布局 连续存放 指针值（8 字节 × N）
指向 各元素可分散（堆 mbuf 各自 malloc）
传参 退化为 T **
arr[i][j] 两次访存：先取 arr[i] 指针，再取元素

与数组指针对比（核心区分）

int *a[5];       /* 指针数组：5 个 int* */
int (*b)[5];    /* 数组指针：1 个指向 int[5] 的指针 */
指针数组 T *a[N] 数组指针 T (*b)[N]
存储 N 个指针连续，所指分散 指向连续 N 元块
a[i][j] 两次访存（取指针+取元素） 一次访存（线性寻址）
cache 每个所指可能 miss 连续，cache 友好
退化 T ** T (*)[N]
适合 不等长/分散对象 固定大小连续表

字符串指针数组

const char *names[] = {"HEARTBEAT", "QUOTE", "ORDER", "CANCEL"};
/* names 是 const char *[4]，退化为 const char ** */
/* 各串在 .rodata，分散存储 */

适合错误码表、opcode 名称表——每串不等长，用指针数组省空间（不等长二维字符数组会按最长行对齐，浪费）。

底层映射

两次访存

struct rte_mbuf *pkts[32];
pkts[i]->port;       /* 两次访存 */

; x86-64
mov     rax, QWORD PTR [pkts + i*8]   ; 第一次：取 pkts[i]（mbuf 指针）
mov     eax, DWORD PTR [rax + offset] ; 第二次：取 mbuf->port

第一次取指针（数组连续，cache 命中），第二次取所指对象（可能分散，cache miss）。这是指针数组比连续数组慢的根因。

退化

void handle(struct rte_mbuf *pkts[32], uint16_t nb);
/* pkts 退化为 struct rte_mbuf ** */

T *pkts[N] 退化成 T **pkts——指针的指针。函数内 pkts[i] 取第 i 个指针。

DPDK rte_rx_burst

struct rte_mbuf *pkts[BURST];
uint16_t n = rte_eth_rx_burst(port_id, queue_id, pkts, BURST);
/* 函数内把收到的 mbuf 指针填进 pkts[0..n-1] */
for (int i = 0; i < n; i++)
    process(pkts[i]);

pkts 是调用者提供的指针数组缓冲，DPDK 填充 mbuf 指针。mbuf 本身在 mempool 里（可能分散），但指针数组连续——遍历指针数组快，访问 mbuf 内容可能 miss。

HFT / DPDK

场景 用法
批量收包 struct rte_mbuf *pkts[32]
多端口队列 struct rte_mbuf *port_q[8][16]
错误码表 const char *err_str[]
回调表 handler_t callbacks[N]（函数指针数组，ch13）
不等长字符串表 const char *names[]

选型：指针数组 vs 连续数组

指针数组 连续数组
对象大小 不等长可行 必须等长
cache 指针连续，对象分散 全连续
访存 两次 一次
生命周期 各对象独立管理 整块
适合 mbuf/字符串/回调 行情快照/配置表

常见误区

误区 事实
"int *a[5] 和 int (*a)[5] 一样" 完全不同：前者 5 个指针，后者 1 个数组指针
"指针数组和连续数组一样快" 两次访存，所指分散时慢
"pkts[i]->port 是一次访存" 两次：先取 pkts[i]，再取 ->port
"指针数组退化成 int (*)[N]" 退化成 T **，不是数组指针

代码自测

题目 1： 以下代码输出什么？

char *names[] = {"Alice", "Bob", "Charlie"};
printf("%c\n", names[1][0]);
printf("%s\n", names[2]);
参考答案

输出 B 和 Charlie。names 是 char* 指针数组，每个元素指向一个字符串字面量。names[1] 指向 "Bob"，names[1][0] 是 'B'。names[2] 指向 "Charlie"。指针数组常用于管理多个字符串，比二维字符数组更灵活（每个字符串可以不同长度）。

章节自测

题目 1： 以下代码在 C 语言中能编译吗？说明了 C 的什么特性？

#include <stdio.h>
int main() {
    printf("hello\n");
}
参考答案

能编译。C 是编译型语言——源代码经过预处理、编译、汇编、链接四个阶段生成可执行文件。这个程序体现了 C 的基本结构：包含头文件、main 函数入口、标准库函数调用。C 的设计哲学是"信任程序员"——它不会像 Java 那样强制检查很多东西。
