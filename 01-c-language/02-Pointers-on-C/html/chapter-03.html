3.3

typedef

本节讲什么

typedef 给已有类型起新名字,不创建新类型。它是 C 跨平台、定宽、可读、可移植的基石 —— <stdint.h> 的 uint8_t/uint64_t、DPDK 的 rte_mbuf、Linux 内核的 size_t/ssize_t/pid_t 全部建立在 typedef 之上。本节讲它的语义、与 #define/enum 的边界、读复杂声明时它如何救命。

要点

基本语法

typedef unsigned char  uint8_t;          /* 定宽类型 */
typedef unsigned long long uint64_t;
typedef struct rte_mbuf rte_mbuf_t;      /* 结构体别名, 可省 struct 关键字 */
typedef int (*cmp_fn)(const void*, const void*);  /* 函数指针别名 */
  • 语法上 typedef 像"加一个名字的变量声明":把变量名换成类型别名
  • 不是文本替换(区别 #define):typedef 受类型检查、有作用域、不能跨编译单元被宏展开破坏

为什么用 typedef

价值 说明 例子
定长 避免 long/int 在 ILP32/LLP64/LP64 宽度不一 uint32_t 永远 32 位
可读 复杂类型一行看懂 cmp_fn 比 int(*)(const void*,const void*) 清晰
可移植 平台换类型不改源码 size_t 在 32/64 位分别是 4/8
封装 改底层类型只动 typedef typedef int_fast16_t fast16;

与 #define 区别(常考点)

#define  WORD unsigned int
typedef unsigned int WORD;     /* 等价于此行 */
维度 #define typedef
处理阶段 预处理,文本替换 编译期,符号进类型系统
类型检查 无 有,可触发诊断
作用域 无,文件级 遵守作用域(可在块内)
复杂类型 易错(指针组合难) 准确(函数指针/数组指针)
调试可见 替换后看不到原名 调试器/错误信息常保留原名

经典反例(指针):

#define PINT int*
PINT a, b;        /* 替换后: int *a, b; —— b 是 int 不是指针! */
typedef int* PintT;
PintT c, d;       /* c 和 d 都是 int* */

与 enum / struct 配合

typedef enum { PKT_ORDER=0, PKT_QUOTE, PKT_HEARTBEAT } pkt_type_t;
typedef struct rte_mbuf { /* ... */ } rte_mbuf_t;
  • C 时代习惯加 _t 后缀;POSIX 保留 _t 给实现,Linux/DPDK 大量使用 _t(争议存在,但事实如此)
  • struct 自带"省 struct 关键字"的副作用,typedef 后 rte_mbuf_t m; 比 struct rte_mbuf m; 短

与 HFT/DPDK

<stdint.h> 定宽类型

uint8_t  b;       /* 报文字节 */
uint16_t len;     /* 报文长度字段 */
uint32_t seq;     /* 序号 */
int32_t  price;   /* 定点价格, 4 位小数 */
类型 用途 注意
intN_t 定宽精确宽度 N 协议字段、寄存器
uintN_t 无符号定宽 字节、掩码
int_leastN_t 至少 N 位 可移植算法
int_fastN_t 至少 N 位但更快 循环计数器常用 size_t/int_fast32_t
intptr_t 存指针的整数 把指针转整数运算
intmax_t 最大宽度 printf 调试
  • HFT 价格绝不用 float,用 int64_t 定点(如 1e-7 精度),避免 IEEE 754 误差和舍入分歧

函数指针类型别名(回调签名规范化)

先从零理解函数指针本身:

普通指针存数据变量的地址;函数指针存函数的地址。函数放在内存代码段(.text),它也有地址,可以存进指针变量:

#include <stdio.h>

int add(int a, int b) { return a + b; }

int (*fp)(int, int);     /* fp:函数指针变量,只能存"返回int、接收两个int"的函数 */

int main(void)
{
    fp = add;             /* 函数名转成地址,不用写 & */
    printf("%d\n", fp(3,5));  /* 等价 add(3,5) */
}

关键易错点——括号不能少:

int *p(int a, int b);   /* 返回 int* 的函数声明,不是函数指针! */
int (*p)(int a, int b); /* p 才是函数指针 */

再用 typedef 起别名——函数指针是 C 里唯一不写 typedef 基本没法维护的场景:

typedef int (*fp_t)(int, int);
fp_t fp;                 /* 等价 int (*fp)(int, int); */

fp_t 不是变量,是函数指针类型——就像 int 是整数类型。最大现实用途是回调函数:qsort 不知道你要怎么比较数据,你写比较函数、把函数地址通过函数指针传进去,qsort 内部回调你的逻辑。

速判 Quiz:

void hello(void) {}
void (*f)(void);
/* A. f = hello;   B. *f = hello;  哪条是把 hello 的地址存进 f? */
答案

A 正确:hello 是函数指示符,转换为函数指针后赋值给 f(C11 §6.3.2.1p4,与数组退化平行)。

B 错误:f 解引用得到函数类型* void(void),函数类型不能作为赋值左值——转换只发生在右值上下文,f 在左值位置不转换,约束违反。

函数指针的完整深入(标准依据、.text 段底层视角、分发器、file_operations、间接调用性能代价)见 ch13 13.3-函数指针。

工程上的回调签名规范化:

typedef void (*pkt_cb)(const uint8_t *pkt, size_t len, void *user);
static pkt_cb g_handler;
void on_packet(pkt_cb cb){ g_handler = cb; }
  • DPDK ethdev 的 rte_eth_rx_callback_fn、信号处理的 sighandler_t 都是这种 typedef
  • 用 typedef 后函数指针数组声明从天书变成可读

读复杂声明的螺旋法则(预告)

int (*signal(int, void(*)(int)))(int);
  • 不用 typedef 几乎读不出"signal 是函数,接受(int, 函数指针),返回函数指针"
  • 用 typedef 拆解:
typedef void (*handler_t)(int);
typedef handler_t (*signal_fn)(int, handler_t);
signal_fn my_signal = signal;

可读性天差地别 —— 这是 ch13 函数指针与复杂声明专题的入口。

常见误区

误区 真相
typedef 创建新类型 不,是已有类型的别名;类型检查按底层走
typedef 和 #define 等价 不;宏是文本替换,无类型检查无作用域
typedef int* P; P a,b; 中 b 是 int 不,typedef 后 a、b 都是 int*
_t 后缀是标准强制 不是;POSIX 保留,用户 typedef 也常用,有争议但事实
typedef 能前向声明结构 typedef 不能凭空造类型,要先有 struct 定义

代码自测

题目 1： 以下两种写法有什么本质区别？

typedef int *IntPtr;
#define IntPtr int *

IntPtr a, b;
参考答案

typedef 版本：a 和 b 都是 int。#define 版本：展开为 int a, b，a 是 int* 但 b 是 int。typedef 是真正的类型别名，对声明中的每个变量都生效；#define 只是文本替换，只对第一个变量有效。

3.4

常量

本节讲什么

"常量"在 C 里有两层:字面量(整型、浮点、字符、字符串、枚举)和 const 对象(只读变量,可进 .rodata)。本节把各类字面量、转义、字符串拼接、enum、const 对象的底层段布局讲透 —— 这些是写协议解析、寄存器掩码、配置表的日常。

要点

术语辨析:"常量"的标准名 vs 教材名

国内教材把"值不变的东西"统称常量,再分字面量和 const 常变量——这是考试口径,不是标准口径。标准术语的历史演变:

标准 官方叫法 出处
C89–C17 constant(integer/character/floating constant) §6.4.4
C23 改名 literal(integer/character literal...) §6.4.4

两个细节:

  • "字面量(literal)"反而是 C23 才有的官方词——之前标准写的全是 constant。中文教材的"常量"是老标准 constant 的直译,再把 const 变量塞进同一个词,混淆由此而来
  • 字符串字面量从来不在 §6.4.4:它在 §6.4.5 "string literals",从 C89 起就叫 literal。C11 时代 "'A' 是 constant、\"abc\" 是 literal" 两术语并存,C23 统一为 literal

判别"它是不是常量"的最硬测试:static int arr[N];(文件域数组长度)。编译过 = N 是编译期常量。#define/enum/字面量过,const int N 编译错误——C 的 const 不是 C++ 的 const,这是两语言最著名分歧之一。

整型常量

进制 写法 用途
十进制 123 普通数值
八进制 0123 (= 83) 易错,C 没单独前缀,leading 0 即八进制
十六进制 0x1F / 0X1F 寄存器地址、掩码、报文字段
二进制(C23) 0b1010 位字段掩码(早期靠 0b GCC 扩展)

后缀(控制类型):

后缀 类型
无 十进制:int/long/long long 取最小容纳
U/u 无符号版
L/l 至少 long
LL/ll 至少 long long
ULL unsigned long long

命名常量优先大写 + 后缀齐全:0xFFFFFFFFUL、1000ULL,避免窄类型隐式转换。

字符与转义

'A'      /* int, 字符常量是 int 不是 char */
'\n'     /* 换行 */
'\0'     /* 空字节 */
'\x0F'   /* 16 进制转义, 任意字节 */
'\101'   /* 8 进制转义, = 'A' */
转义 含义
\n \t \r 换行/制表/回车
\\ \' \" 字面 \ ' "
\0 NUL,字符串终止符
\xHH 任意 16 进制字节,报文字节常量
\OOO 8 进制字节
  • 字符常量类型在 C 是 int(C++ 是 char),sizeof('A') 在 C 得 4
  • 报文字节:uint8_t magic[] = {'T','I','C','\x01'}; 比裸数字可读

为什么 '\n' "不是两个符号"——追到翻译阶段(translation phases)

  • Phase 3(分词):'\n' 被切成一个预处理 token。词法分析器看到 ' 就进入字符常量模式,读到配对 ' 才结束——\ 和 n 从未作为独立符号存在过
  • Phase 5(pp-token → token):转义序列求值,'\n' 变成值 10 的 int

所以准确说法不是"编译后变成 1 字节",是分词阶段它就是不可分割的一个 token。这也是为什么 '\x0F' 是单个转义,而字符串里 "abc\ 后跟断行会直接报 lexer 错误。

字面量 vs const 变量的本质区别:字面量没有内存对象,是编译期直接嵌进指令的立即数(&'\t' 直接编译错误);const 变量有地址,运行期存在(&c 合法)。

字符串常量

"abc"               /* .rodata, 只读, 含 '\0' */
"hello" "world"     /* 编译期拼接 → "helloworld" */
sizeof("abc")       /* == 4(含 '\0') */
strlen("abc")       /* == 3(不含 '\0') */
  • 拼接特性常用于多行宏、长字符串断行:
const char *help =
    "Usage: prog [-p port] [-v]\n"
    "  -p  监听端口\n"
    "  -v  详细输出\n";
  • 修改字符串常量内容 = UB:可能 SIGSEGV(放 .rodata 的平台),可能"恰好工作"(某些嵌入式放可写 RAM)

浮点常量

3.14       /* double */
1e-6       /* double, 科学计数 */
3.14f      /* float */
3.14L      /* long double */
NAN        /* 需 <math.h> */
INFINITY   /* 需 <math.h> */
  • 默认 double,加 f 才是 float;HFT 内部不用浮点存价格,但概率/统计可能用到

enum

enum pkt_type {
    PKT_ORDER    = 0,
    PKT_QUOTE,                /* 1 */
    PKT_HEARTBEAT,            /* 2 */
    PKT_CANCEL    = 0x10,     /* 可跳号 */
    PKT_ACK                    /* 0x11 */
};
enum pkt_type t = PKT_QUOTE;
  • 编译期整型常量;底层类型通常是 int(C23 起可指定底层类型)
  • 默认从 0 递增,可显式赋值跳号
  • 优于 #define 之处:① 调试器可见名字 ② 有作用域 ③ 可被 switch 检查完整性(-Wswitch)

从零理解:枚举常量没有内存

enum { MAX_CONN = 4096 };

编译器不为 MAX_CONN 分配任何内存。它就是个立即数,用在哪嵌到哪——int arr[MAX_CONN] 嵌进指令的就是 4096,cmp eax, MAX_CONN 就是 cmp eax, 4096。反汇编里看不到 MAX_CONN,只有数字。

有内存的是枚举变量:enum pkt_type t; 里的 t 是真变量(通常 int 宽度)。常量和变量是两回事——和"字面量 '\t' 无对象、const 变量 c 有对象"完全同构。

为什么 HFT 协议码表必用 enum(而不是 #define)

switch (t) {
    case PKT_ORDER:  ...
    case PKT_QUOTE:  ...
    /* 漏了 PKT_HEARTBEAT → -Wswitch 编译期报警 */
}

宏是纯文本,编译器不知道它们是一组;enum 让编译器知道"这些值构成全集",漏 case 能在编译期揪出来。协议新增报文类型时,漏处理一种心跳包 = 误判断线,这个检查价值极大。

C23:指定底层类型(嵌入式/协议打包)

enum pkt_type : uint8_t { PKT_ORDER, PKT_QUOTE };   /* C23 */

以前枚举变量固定 int(4 字节),协议结构体想要 1 字节字段只能 uint8_t type; 加强转;C23 起枚举本身可以就是 1 字节。

const 对象(只读变量)

const int max_retry = 3;        /* 只读, 可进 .rodata */
static const char *g_name = "default";
  • 不是编译期常量:不能用作数组长度(需 C99 VLA)、case 标签、位域宽度
  • 想要"编译期符号常量"用 #define / enum / static const + 编译器折叠

三种"常量"机制对比(终局版)

#define MAX 10 enum { MAX=10 } const int MAX=10
生效阶段 预处理(phase 4,文本替换) 编译期(词法符号,立即数) 运行期(变量,只读)
有没有内存 无 常量无(变量有) 有,可 &MAX
类型检查 无——纯文本,#define MAX "abc" 都行 int 有,完整类型系统
作用域 定义处到文件尾,无视块作用域 遵守块作用域 遵守块作用域
调试器可见 不可见(替换完了) 可见 可见
当数组长度/case 标签 ✅ ✅ ❌
典型用途 数组长度、宏 状态码、协议类型 配置、只读表

选型口诀:要当编译期常量(数组长度/case/位域宽度)→ #define 或 enum;一组相关的整数码 → 必用 enum(图 -Wswitch);运行期只读配置(可取地址、放 .rodata)→ const。三者不冲突,一个项目里都会出现,各干各的活。

C23 补坑:constexpr 进 C

constexpr int N = 100;      /* C23: 真正的编译期常量 */
int arr[N];                 /* OK,不是 VLA */

"const 只读但不常"这个 40 年的坑终于有了官方解法。C23 的 constexpr 语义与 C++ 不同(限定为对象定义),新 GCC/Clang 已支持(-std=c23/-std=c2x)。

enum 让 switch 完整性检查生效

enum pkt_type { ORDER, QUOTE, HEARTBEAT };
const char *name(enum pkt_type t){
    switch (t) {
        case ORDER:     return "order";
        case QUOTE:     return "quote";
        case HEARTBEAT: return "hb";
    }   /* -Wswitch-enum: 漏 case 报警, 编译器无法保证 default */
}

字符串常量修改陷阱

char *s = "hello";
s[0] = 'H';          /* UB: 可能 SIGSEGV(.rodata 只读) */
"hello"[0] = 'x';    /* 等价写法:直接对字面量数组下标,同样 UB */
char a[] = "hello";  /* a 是栈数组, 拷贝, 可改 */
a[0] = 'H';          /* ok */

HFT 代码静态扫描常禁 char * 直接接字符串字面量,要求 const char *。

为什么编译不报错?

C 标准规定字符串字面量的类型是 char[N],不是 const char[N]——语法层面赋给 char * 完全合法,只是语义上修改它是 UB。坑在运行期才爆。

C++ 做了改进:字面量类型是 const char[N],char *s = "hello" 在 C++11 起非法(必须 const char *)。这是 C/C++ 又一处不兼容。

字面量复用(字符串池)

char *p1 = "abc";
char *p2 = "abc";
/* p1 == p2 可能为真:编译器把相同字面量合并到 .rodata 同一地址 */

编译器可以(gcc/clang 默认会)去重合并相同字面量。极端情况:某处"成功"修改了字面量(嵌入式可写 RAM 场景),所有指向它的指针看到的都变了——另一个不用裸 char * 指字面量的理由。

底层视角

.rodata 段在程序加载时由 OS 标记为只读页(MMU 页保护)。写入触发 CPU 保护异常 → 内核送 SIGSEGV。这不是 C 编译器检查的,是硬件+OS 兜底。验证:readelf -l 看 LOAD 段的 W 标志,.rodata 落在无 W 的页。

gcc -O2 t.c -o t && readelf -l t | grep LOAD
# 第一个 LOAD (r--/r-x) 含 .rodata;含 .data/.bss 的 LOAD 才有 W

代码自测

题目 1： 以下代码有什么问题？

const int SIZE = 100;
int arr[SIZE];
参考答案

在 C89 中，数组大小必须是编译期常量表达式，const int 变量不是编译期常量（C 的 const 只读变量不同于 C++ 的 const）。C99 起支持变长数组（VLA），但 VLA 不能在文件作用域声明。正确做法：用 #define SIZE 100 或 enum { SIZE = 100 };。

题目 2： 以下哪个是字符字面量？

const char c = '\t';

A：c　B：'\t'

参考答案

B。'\t' 是字符字面量——phase 3 分词为一个 token，phase 5 求值为 9（类型 int，无内存对象，是嵌进指令的立即数）。c 是 const 限定的 char 变量，有内存、可以 &c，只是写入违反约束。判别标准：字面量没有对应的内存对象（&'\t' 编译错误），const 变量有地址。

题目 3： "C 语言中常量包括字面量和 const 修饰的变量"——这句对吗？

参考答案

是教材的通俗归类，不是标准口径。C 标准（C23 前 §6.4.4）里 constant 指 integer/character/floating constant（C23 改名 literal），const 修饰的是"不能修改的变量"（const-qualified object），不是常量。const 变量不能当数组长度、case 标签——通不过"编译期常量"测试。考试按教材记，写代码和读标准文档要区分。

3.9

作用域、存储类型示例

本节讲什么

把 ch03 学的作用域(块/文件/原型/函数)、存储期(自动/静态/线程/动态)、链接(外部/内部/无)三个维度,放在同一个程序里综合演示。本节是 ch03 的总结性实验:用一段源码 + readelf + nm + gdb 验证每个变量落在哪个段、什么链接、什么可见性。建议照着敲一遍,用工具亲眼看一遍。

要点

典型布局(综合源码)

#include <stdio.h>
#include <stdlib.h>

/* ===== 文件作用域(全局/static 文件级)===== */
int g_init = 42;              /* .data, 外部链接, 静态存储期 */
int g_zero;                   /* .bss,  外部链接, 自动 0 */
static int s_file = 1;        /* .data, 内部链接, 仅本文件 */
static int s_zero;            /* .bss,  内部链接, 自动 0 */
const char *g_msg = "hi";     /* ptr 在 .data, "hi" 在 .rodata */
const int g_const = 100;      /* .rodata, 外部链接只读 */

/* ===== 函数原型作用域 ===== */
extern void other(void);      /* 参数表空, 无原型参数名 */

/* ===== 块作用域 + 不同存储期 ===== */
void demo(int param /* 原型作用域, 此处即块 */) {
    auto int x;               /* 栈, 自动存储期, 未初始化(脏) */
    static int call = 0;      /* .data/.bss, 静态存储期, 仅 demo 可见 */
    register int i;           /* 现代编译器忽略 register, 概念上建议进寄存器 */
    call++;
    printf("call=%d x=%d g_init=%d\n", call, x, g_init);
    if (x) {
        int y = x + 1;        /* 子块, 块作用域, 自动 */
        printf("y=%d\n", y);
    }
    /* y 不可见 */
}

cleanup:                       /* 函数作用域 label, 整个 demo 内有效 */
    ;                         /* 占位 */

int main(void) {
    int *p = malloc(sizeof(int));   /* 堆, 动态存储期 */
    demo(1);
    demo(1);
    other();                   /* 跨文件调用, extern 声明 */
    free(p);
    return 0;
}

变量观察清单(三轴对应表)

变量 作用域 存储期 链接 段 初值
g_init 文件 静态 外部 .data 42
g_zero 文件 静态 外部 .bss 0(自动)
s_file 文件 静态 内部 .data 1
s_zero 文件 静态 内部 .bss 0(自动)
g_msg 文件 静态 外部 .data(指针) + .rodata("hi") 指向 "hi"
g_const 文件 静态 外部 .rodata 100
param 块(demo 内) 自动 无 栈 调用方传入
x 块 自动 无 栈 不确定(脏)
call 块 静态 无 .data/.bss 0(首次)
y 子块 自动 无 栈 计算得
p 块(main) 自动 无 栈 malloc 返回值
*p 堆 动态 无 堆 不确定

关键对照:call 与 x 作用域同(块),但存储期不同(静态 vs 自动);s_file 与 g_init 存储期同(静态),但链接不同(内部 vs 外部)。三轴独立,不能混。

$ nm t.o | sort

题目 1： 以下代码能正确交换两个变量吗？为什么？

void swap(int a, int b) {
    int temp = a;
    a = b;
    b = temp;
}
int main(void) {
    int x = 1, y = 2;
    swap(x, y);
}
参考答案

不能。C 函数参数是值传递，swap 内交换的是 a 和 b 的副本，不影响 main 中的 x 和 y。要实现交换，需要传指针：void swap(int a, int b)，调用 swap(&x, &y)。
