17.1

内存分配

本节讲什么

ADT（抽象数据类型）容器的内存策略：不透明指针封装、节点分配模式、释放回调设计、预分配 vs 动态分配的工程取舍。这是 ch17 全章的工程基础——栈/队列/树的实现细节千差万别，但内存管理遵循同一套原则。HFT 场景里这套原则直接决定容器能否上数据面。

要点

ADT 两大工程原则

1. 封装隐藏（不透明指针）

头文件只暴露 typedef struct Queue Queue;，结构体定义藏在 .c 里：

/* queue.h */
typedef struct Queue Queue;
Queue *queue_create(size_t cap);
int    queue_enqueue(Queue *q, void *data);
void  *queue_dequeue(Queue *q);
void   queue_destroy(Queue **q, void (*free_cb)(void *));

/* queue.c */
#include "queue.h"
struct Queue {
    struct Node *head, *tail;
    size_t len;
    size_t cap;
};

收益：

  • 使用者无法直接访问 q->head，强制走 API
  • 内部实现可自由重构（链表换环形数组）而不破坏 ABI 的使用者
  • 编译依赖最小化——改 struct Queue 内部只需重编 queue.c，不用重编所有使用者

2. 接口隔离

create/destroy/enqueue/dequeue 四件套是容器标准接口。底层可以是链表、环形数组、甚至无锁结构——使用者无感知。这是 HFT"控制面用链表、数据面换 ring"的设计基础。

不透明指针的代价

  • 只能在堆上分配（栈分配需要编译期知道大小）
  • 每次操作都是间接访问（指针解引用）
  • 不能内联优化跨 .c 边界

HFT 数据面有时为极致性能牺牲封装，把结构体定义暴露在头里允许栈分配和内联。这是工程权衡，不是默认选择。

节点分配模式

容器节点本身和载荷（payload）是两层内存：

struct Node {
    void *payload;        /* 载荷指针, 用户数据 */
    struct Node *next;    /* 链接 */
};
  • 节点：容器自己 malloc/calloc 管理
  • 载荷：用户传入 void*，容器不关心它的来源（栈/堆/mempool）

calloc 优于 malloc + 手动清零——编译器能优化成一次操作。节点小（典型 16-24 字节）时 calloc 几乎无开销。

释放回调 free_cb

容器 destroy 时，节点内存由容器释放，但载荷的释放策略容器不知道——可能是 free、可能是 mempool_put、可能不该释放（外部所有）。所以 destroy 接受回调：

void list_destroy(List **lst, void (*free_cb)(void *))
{
    Node *cur = (*lst)->head;
    while (cur) {
        Node *next = cur->next;
        if (free_cb) free_cb(cur->payload);   /* 载荷由回调决定 */
        free(cur);                             /* 节点容器自己释放 */
        cur = next;
    }
    free(*lst);
    *lst = NULL;   /* 置空防止悬垂 */
}

不传 free_cb → 载荷泄漏。传 free → 标准 heap 释放。传 mempool_put → 归还 mempool。这是 HFT 容器与 mempool 协作的标准模式。

destroy 的二级指针

void list_destroy(List **lst, ...) 用二级指针是为了能在 destroy 后把调用者的 List* 置 NULL：

List *mylist = list_create();
/* ... */
list_destroy(&mylist, free);   /* mylist 被置 NULL */
/* 现在用 mylist 会立即段错误, 而不是用已释放内存 */

如果用一级指针 list_destroy(List *lst, ...)，调用者的 mylist 仍指向已释放内存，后续误用是 use-after-free。二级指针让悬垂指针立即变 NULL，降低 UAF 风险。

预分配 vs 动态分配

维度 链表 + malloc 预分配 Ring
分配时机 运行时按需 启动时一次
分配延迟 不确定（malloc 锁 + 碎片） 零（运行时无分配）
容量 无上限 固定
碎片 长跑易碎片 无碎片
cache 节点分散，局部性差 连续内存，cache 友好
多线程 malloc 全局锁 SPSC 可无锁
HFT 适用 控制面 数据面

HFT 数据面铁律：运行时零分配。所有容器必须预分配，运行时只做指针搬运。DPDK rte_ring/rte_mempool 就是这一原则的工业实现。

realloc 扩容的临时指针

动态数组容器扩容时：

void **newbuf = realloc(s->buf, newcap * sizeof(void *));
if (!newbuf) {
    /* 扩容失败, 原 buf 仍有效, 容器保持可用 */
    return -1;
}
s->buf = newbuf;   /* 成功后才赋值 */
s->cap = newcap;

直接 s->buf = realloc(...) 失败时原 buf 丢失，内存泄漏 + 容器损坏。必须用临时指针。详见 ch11。

容器与 mempool 的协作

HFT 容器常配合 mempool：

/* 预分配 mempool 存节点 */
rte_mempool *node_pool = rte_mempool_create("nodes", 4096,
    sizeof(struct Node), 0, NULL, NULL, NULL, NULL,
    SOCKET_ID_ANY, 0);

/* push 时从 mempool 取, 不 malloc */
struct Node *n = rte_mempool_get(node_pool);
n->payload = data;
n->next = s->head;
s->head = n;

/* pop 时归还 mempool, 不 free */
struct Node *old = s->head;
s->head = old->next;
rte_mempool_put(node_pool, old);

零运行时分配 + 无锁 per-lcore cache，这是 DPDK 容器的标准范式。

HFT 关联

  • 数据面零分配：所有容器预分配，运行时只指针搬运，rte_ring/rte_mempool 是工业实现
  • 控制面可用 malloc：配置加载、会话管理、慢路径处理用链表+malloc 容器可接受
  • free_cb 与 mempool：容器 destroy 回调传 rte_mempool_put 把载荷归还池，零泄漏
  • 二级指针防 UAF：长跑进程 destroy 后立即 NULL，避免偶发重用已释放内存
  • cache 局部性：预分配 Ring 连续内存，cache line 预取友好；链表节点分散，TLB miss 频繁
  • 无锁 SPSC：单生产者单消费者场景 ring 用原子 + 内存序实现无锁，避免 mutex 抖动
  • 订单簿容器选型：价格档位用有序数组（bsearch）或专用结构，挂单量用链表，整体是混合容器

代码自测

题目 1： 以下代码有什么问题？

int *p = malloc(sizeof(int));
if (p) {
    *p = 42;
    p = malloc(sizeof(int));
    *p = 99;
}
参考答案

内存泄漏。第一次 malloc 的地址被第二次 malloc 覆盖，原来的内存无法 free。正确做法：先 free(p) 再重新赋值，或用不同的指针变量。每次 malloc 都必须保存指针以便后续 free——丢失指针 = 泄漏。

17.2

堆栈

本节讲什么

栈 ADT（LIFO 后进先出）的设计：栈顶 push/pop/peek 三操作，数组与链表两种实现选型。栈是计算机科学最基础的 ADT 之一——函数调用栈、表达式求值、递归转迭代、错误回滚都依赖它。HFT 场景里栈用于报文递归解析、事务回滚、深度优先遍历。

要点

栈的核心操作

操作 语义 复杂度
push(data) 入栈顶 O(1)
pop() 出栈顶并返回 O(1)
peek() 读栈顶不弹出 O(1)
len() 元素个数 O(1)
destroy(free_cb) 释放栈 + 载荷 O(n)

LIFO 语义：最后 push 的最先 pop，像一摞盘子。

两种实现选型

维度 数组实现（17.2.2） 链表实现（17.2.3）
内存 连续，cache 友好 节点分散
分配 预分配或 realloc 每次 push malloc
容量 固定或动态扩容 无上限
push 延迟 稳定 O(1) malloc 不确定
HFT 数据面 首选 慎用
适用 定长、热路径 变长、控制面

栈的典型应用

1. 函数调用栈

硬件栈就是 LIFO——call 压返回地址，ret 弹出。递归本质是隐式用硬件栈。

2. 表达式求值

中缀转后缀、后缀求值都用操作数栈和运算符栈：

/* 后缀表达式求值 */
for each token:
    if 数字: push(stack, token)
    if 运算符: b=pop, a=pop, push(a op b)
结果 = pop(stack)

3. 递归转迭代

/* 递归 */
void tree_inorder(Node *n) {
    if (!n) return;
    tree_inorder(n->left);
    visit(n);
    tree_inorder(n->right);
}

/* 迭代, 用显式栈 */
void tree_inorder_iter(Node *root) {
    Stack *s = stack_create();
    Node *cur = root;
    while (cur || !stack_empty(s)) {
        while (cur) {
            stack_push(s, cur);
            cur = cur->left;
        }
        cur = stack_pop(s);
        visit(cur);
        cur = cur->right;
    }
    stack_destroy(&s, NULL);
}

显式栈避免递归过深爆栈，且栈大小可控。

4. 错误回滚（undo 栈）

事务操作前 push 回滚信息，失败时 pop 并执行回滚：

stack_push(undo, make_rollback_record(state));
if (do_action() < 0) {
    rollback_record *r = stack_pop(undo);
    r->rollback(r);   /* 撤销 */
    free(r);
}

内核文件系统、数据库事务、HFT 订单修改都用类似模式。

5. 括号匹配

for each char c:
    if c 是开括号: push(stack, c)
    if c 是闭括号:
        if stack_empty: 错误
        top = pop(stack)
        if not match(top, c): 错误
if !stack_empty: 错误

栈与递归的关系

任何递归都能用显式栈转成迭代。递归的隐式代价：

  • 每层调用压栈帧（返回地址 + 局部变量 + 寄存器保存）
  • 栈帧大小固定，深递归可能爆栈（默认栈 8MB，每帧百字节就是几万层）
  • 函数调用开销（call/ret + 栈帧建立）

迭代 + 显式栈的优势：

  • 栈大小可控（可分配大块堆内存）
  • 栈帧只存必要数据，更紧凑
  • 可中断/恢复（协程基础）

HFT 报文解析的深层嵌套用显式栈避免递归爆栈。

空栈与溢出处理

  • 空栈 pop：返回 NULL 或错误码，不能 UB
  • 数组栈溢出：返回 -1 或 realloc 扩容
  • 链表栈溢出：malloc 失败返回 -1

API 设计必须在文档里说明空栈/溢出行为，调用者必须检查。

栈的线程安全

标准栈不是线程安全的——并发 push/pop 会破坏链表或数组索引。HFT 场景：

  • 每线程独占栈（thread-local），无锁
  • 共享栈加 mutex（控制面可接受）
  • 无锁栈用 CAS（数据面，但实现复杂）

HFT 关联

  • 报文递归解析：FIX/二进制协议嵌套结构用显式栈解析，避免递归爆栈
  • 错误回滚栈：订单修改失败时按 undo 栈逆序回滚，保证一致性
  • 表达式求值：策略引擎的条件表达式（price > 100 && qty < 50）用栈求值
  • 深度优先遍历：订单簿按价格树 DFS 遍历，显式栈避免递归
  • 硬件栈与爆栈：递归过深触发 SIGSEGV（栈溢出），HFT 数据面禁用深递归
  • thread-local 栈：每线程预分配栈容器，无锁无争用
  • DPDK 无栈 ADT：DPDK 库本身不提供通用栈，HFT 自行实现或用 ring 替代

题目 1： 以下用数组实现的栈有什么问题？

#define MAX 100
int stack[MAX];
int top = 0;
void push(int val) {
    stack[top++] = val;

参考答案

没有检查栈满。如果 top >= MAX 还继续 push，会越界写入 stack 数组之后的内容——缓冲区溢出。正确做法：void push(int val) { if (top >= MAX) { / error / return; } stack[top++] = val; }。防御性编程要求检查所有边界条件。

17.2

.1 堆栈的接口

本节讲什么

栈 ADT 的对外 API 设计：不透明 Stack * 句柄、push/pop/peek/destroy 四件套、错误处理约定、载荷所有权规则。这是 ADT 接口设计的范式——同样的模式会出现在队列、树、哈希表等所有容器上。掌握这一节等于掌握了 C 语言 ADT 接口设计的方法论。

要点

完整接口

/* stack.h */
#ifndef HFT_STACK_H
#define HFT_STACK_H

#include <stddef.h>

typedef struct Stack Stack;

/* 创建栈, cap=0 表示动态扩容 */
Stack *stack_create(size_t cap);

/* 入栈, 成功返回 0, 失败返回 -1 */
int    stack_push(Stack *s, void *data);

/* 出栈并返回载荷, 空栈返回 NULL */
void  *stack_pop(Stack *s);

/* 读栈顶不弹出, 空栈返回 NULL */
void  *stack_peek(const Stack *s);

/* 元素个数 */
size_t stack_len(const Stack *s);

/* 是否为空 */
int    stack_empty(const Stack *s);

/* 销毁栈, free_cb 非空时对每个载荷调用, q 置 NULL */
void   stack_destroy(Stack **s, void (*free_cb)(void *));

#endif

接口设计原则

1. 不透明指针

typedef struct Stack Stack; 在头文件，struct Stack {...} 在 .c。使用者只能通过 Stack * 句柄操作，无法直接访问成员。

2. 一致的生命周期

create → 多次 push/pop → destroy。每个 create 必须配一个 destroy，否则泄漏。

3. 错误返回约定

  • 返回 int 的操作：0 成功，负数失败
  • 返回指针的操作：成功返回指针，失败返回 NULL
  • errno 用于诊断，不依赖它判断成功失败

4. const 正确性

stack_peek(const Stack *s) 和 stack_len(const Stack *s) 标 const——不修改栈的只读操作。这让 const Stack* 仍能调用这些接口，编译期保证安全。

5. 载荷所有权

容器只持有 void* 指针，不拥有载荷内存：

  • push 后，载荷的生命周期由容器"引用"，调用者不能在 pop 前释放它
  • pop 后，所有权回到调用者，调用者负责释放
  • destroy(free_cb) 时，对每个仍在栈内的载荷调用 free_cb，统一释放

这是 C 语言 ADT 的标准所有权模型——容器不管载荷怎么来的，只管 destroy 时按调用者指定的方式清理。

空栈与错误的区分

stack_pop 空栈返回 NULL，但 NULL 也可能是合法的载荷指针（用户主动 push 了 NULL）。两种区分方式：

方案 A：先检查再 pop

if (stack_empty(s)) {
    /* 真的空了 */
} else {
    void *data = stack_pop(s);
    /* data 可能是 NULL（用户 push 的 NULL）, 但栈确实非空 */
}

方案 B：pop 带输出参数

int stack_pop(Stack *s, void **out);   /* 返回 0 成功, -1 空栈 */

out 输出载荷，返回值区分成功失败。彻底无歧义。

HFT 生产代码倾向方案 B，避免 NULL 歧义。但方案 A 更符合 stdio 风格（fgetc 返回 EOF 类似）。

peek 与 pop 的关系

peek 是 pop 的只读版本——读栈顶但不移除。常用于"看一眼再决定要不要 pop"：

void *top = stack_peek(s);
if (should_process(top)) {
    stack_pop(s);   /* 确认处理才 pop */
    process(top);
}

注意 peek 后 pop 是两次操作，多线程下可能中间被其他线程修改——共享栈必须加锁。

destroy 的 free_cb 语义

void stack_destroy(Stack **s, void (*free_cb)(void *));
  • free_cb == NULL：只释放栈结构，不碰载荷（载荷由外部管理）
  • free_cb == free：标准堆释放
  • free_cb == custom：自定义释放（如 mempool_put、close fd 等）

调用者根据载荷来源选择：

/* 载荷是 malloc 的 */
stack_destroy(&s, free);

/* 载荷是 mempool 来的 */
stack_destroy(&s, mempool_put_wrapper);

/* 载荷是栈上变量, 不该释放 */
stack_destroy(&s, NULL);

接口与实现分离的收益

/* 控制面: 用链表栈 */
#include "stack_list.h"
Stack *s = stack_create(0);

/* 数据面: 换数组栈, 接口完全一样 */

业务代码不变，编译时切换头文件即可换实现。这是 ADT 的核心价值——接口稳定，实现可替换。

HFT 关联

  • 统一容器接口：HFT 框架的栈/队列/树都遵循 create/push/pop/destroy 范式，降低学习成本
  • 不透明指针 ABI 稳定：Stack * 是稳定 ABI，内部重构不需重编使用者
  • free_cb 与 mempool：数据面栈 destroy 传 rte_mempool_put 把载荷归还池
  • const 正确性：只读操作标 const，编译期防止误改，便于静态分析
  • 错误返回约定：0/负数风格与 DPDK rte_ 系列、Linux 内核一致
  • 线程局部栈：每线程独占栈，接口无需考虑锁，性能最优
  • 接口切换：控制面链表栈、数据面数组栈，同一套业务代码

17.2

.2 用数组实现堆栈

本节讲什么

栈的数组实现：固定容量或动态扩容的连续缓冲区 + top 索引。这是 HFT 数据面最友好的栈实现——无 per-push malloc、cache 友好、延迟可预测。本节重点讲 top 索引语义、扩容策略、与环形缓冲区的对比。

要点

结构定义

struct Stack {
    void **buf;      /* 指针数组, 每个元素是 void* 载荷 */
    size_t cap;      /* 容量 */
    size_t top;      /* 栈顶, 指向下一个空位 */
};

top 语义：指向下一个空位。栈空时 top == 0，栈满时 top == cap。元素 buf[0] 是栈底，buf[top-1] 是栈顶。

push 实现

int stack_push(Stack *s, void *data)
{
    if (s->top >= s->cap) {
        /* 固定容量: 返回错误 */
        if (s->cap == 0) return -1;

        /* 动态扩容: realloc */
        size_t newcap = s->cap * 2;
        void **newbuf = realloc(s->buf, newcap * sizeof(void *));
        if (!newbuf) return -1;
        s->buf = newbuf;
        s->cap = newcap;
    }
    s->buf[s->top++] = data;   /* 先写入, 再自增 */
    return 0;
}

关键点：

  • 先检查 top >= cap，满了才扩容或报错
  • realloc 必须用临时指针（17.1 详述）
  • s->buf[s->top++] = data 是后自增——先写入当前 top 位置，再 top+1

pop 实现

void *stack_pop(Stack *s)
{
    if (s->top == 0) return NULL;   /* 空栈 */
    return s->buf[--s->top];        /* 先自减, 再读出 */
}

关键点：

  • --s->top 是前自减——先把 top 减 1，再读 buf[top]
  • 不清零 buf[top]（可选，帮助 ASan 检测 use-after-pop，但增加开销）
  • 空栈返回 NULL，注意 NULL 歧义（17.2.1）

peek 实现

void *stack_peek(const Stack *s)
{
    if (s->top == 0) return NULL;
    return s->buf[s->top - 1];   /* 读 top-1 位置, 不改 top */
}

create 与 destroy

Stack *stack_create(size_t cap)
{
    Stack *s = malloc(sizeof *s);
    if (!s) return NULL;
    s->cap = cap;
    s->top = 0;
    s->buf = cap ? malloc(cap * sizeof(void *)) : NULL;
    if (cap && !s->buf) {
        free(s);
        return NULL;
    }
    return s;
}

void stack_destroy(Stack **s, void (*free_cb)(void *))
{
    if (!s || !*s) return;
    Stack *stk = *s;
    if (free_cb) {
        for (size_t i = 0; i < stk->top; i++) {
            free_cb(stk->buf[i]);   /* 释放仍在栈内的载荷 */
        }
    }
    free(stk->buf);
    free(stk);
    *s = NULL;
}

top 索引 vs 指针

数组栈有两种风格：

风格 A：索引 top

struct Stack { void **buf; size_t cap, top; };
/* push: buf[top++] = data */
/* pop:  return buf[--top] */

风格 B：指针 sp（stack pointer）

struct Stack { void **base, **sp, **end; };
/* push: *sp++ = data */
/* pop:  return *--sp */

风格 B 用指针直接操作，省一次 buf + 加法。但 sp == end 的满栈检查仍需要。现代编译器对索引和指针优化后差别极小，风格 A 更易读。

扩容策略

策略 扩容倍数 特点
倍增 2x 摊还 O(1)，内存峰值 2x
1.5x 1.5x 摊还 O(1)，内存峰值 1.5x，可能复用旧块
固定增量 +N 最坏 O(n)，不推荐
预分配固定 不扩容 HFT 数据面首选

倍增的摊还分析：n 次 push 总拷贝量 1+2+4+...+n ≈ 2n，摊到每次 push 是 O(1)。但单次扩容瞬间延迟尖峰（memcpy 大块）。HFT 数据面禁用动态扩容，启动时预分配足量。

固定容量与溢出

Stack *s = stack_create(4096);   /* 固定 4096 */
if (stack_push(s, data) < 0) {
    /* 栈满, 业务必须处理: 丢弃、告警、或 fatal */
    log_warn("stack overflow");
}

HFT 数据面栈溢出是设计错误——预分配大小应覆盖最坏场景。运行时溢出说明容量估算错了，必须告警 + 排查。

cache 友好性

数组栈的 buf 是连续内存，push/pop 访问 buf[top] 命中同一 cache line 的概率高。相比链表栈每次 push 访问新 malloc 的节点（可能跨页），数组栈 cache miss 少一个数量级。

数组栈 vs 环形缓冲区

数组栈用 top 索引线性增长，环形缓冲区用 r_idx/w_idx 取模循环。区别：

维度 数组栈 环形缓冲区
语义 LIFO FIFO
索引 top 线性 r/w 循环取模
满 top == cap len == cap
空 top == 0 len == 0
HFT 栈 ADT 队列 ADT

栈不需要取模（top 只增不减），队列需要（r/w 循环）。这是栈比队列简单的根本原因。

线程安全

数组栈的 push/pop 不是原子操作（读 top、写 buf、改 top 三步）。多线程共享栈必须加锁：

pthread_mutex_lock(&s->mtx);
stack_push(s, data);
pthread_mutex_unlock(&s->mtx);

无锁栈用 CAS 操作链表头（Treiber stack），但实现复杂且 ABA 问题。HFT 倾向每线程独占栈避免锁。

HFT 关联

  • 数据面首选：预分配固定容量数组栈，零运行时分配，延迟可预测
  • cache 友好：连续 buf 访问模式命中 cache，相比链表栈快数倍
  • thread-local 栈：每线程独占数组栈，无锁无争用
  • 容量预分配：启动时按最坏场景分配，运行时溢出即告警排查
  • mbuf 解析栈：DPDK 报文解析嵌套隧道（VXLAN-in-IP）用数组栈保存各层 header 指针
  • 订单簿回滚栈：订单修改前 push 旧状态，失败时 pop 回滚，数组栈延迟稳定
  • 避免 realloc 抖动：数据面栈永不扩容，控制面栈扩容可接受
  • SIMD 友好：连续内存可被 AVX 批量处理（如批量 pop N 个元素）

题目 1： 以下数组栈的 top 变量表示什么？

int stack[MAX];
int top = 0;  // top 指向下一个空位

如何判断栈空和栈满？

参考答案

top 指向下一个空闲位置（不是栈顶元素）。栈空：top == 0。栈满：top == MAX。push 先写入 stack[top] 再 top++，pop 先 top-- 再读取 stack[top]。如果 top 指向栈顶元素（而非下一个空位），逻辑需要调整：push 先 top++ 再写入，pop 先读取再 top--。两种约定都可以，但要保持一致。

17.2

.3 用链表实现堆栈

本节讲什么

栈的链表实现：单向链表头插/头删，O(1) push/pop，无容量上限。这是变长场景的标准栈实现，配合 mempool 可用于 HFT 控制面。本节重点讲头插的指针改写、链表与数组栈的选型、以及链表栈的 cache 代价。

要点

结构定义

struct Node {
    void *payload;
    struct Node *next;
};

struct Stack {
    struct Node *head;   /* 链表头 = 栈顶 */
    size_t len;
};

栈顶就是链表头——push 是头插，pop 是头删。这是链表栈的核心思想。

push：头插

int stack_push(Stack *s, void *data)
{
    struct Node *n = malloc(sizeof *n);
    if (!n) return -1;
    n->payload = data;
    n->next = s->head;   /* 新节点指向原头 */
    s->head = n;          /* 头指针更新 */
    s->len++;
    return 0;
}

四步：

  1. malloc 新节点
  2. n->payload = data 装载荷
  3. n->next = s->head 新节点接管原链表
  4. s->head = n 头指针前移

步骤 3 和 4 顺序不能反——先 s->head = n 会丢失原链表。

pop：头删

void *stack_pop(Stack *s)
{
    struct Node *n = s->head;
    if (!n) return NULL;   /* 空栈 */
    void *data = n->payload;
    s->head = n->next;     /* 头指针后移 */
    free(n);                /* 释放节点 */
    s->len--;
    return data;
}

四步：

  1. 保存 s->head 到临时 n
  2. 取出 n->payload
  3. s->head = n->next 跳过 n
  4. free(n) 释放节点

注意：先取 payload 再 free，反了就是 use-after-free。

peek

void *stack_peek(const Stack *s)
{
    return s->head ? s->head->payload : NULL;
}

create 与 destroy

Stack *stack_create(void)
{
    Stack *s = malloc(sizeof *s);
    if (!s) return NULL;
    s->head = NULL;
    s->len = 0;
    return s;
}

void stack_destroy(Stack **s, void (*free_cb)(void *))
{
    if (!s || !*s) return;
    Stack *stk = *s;
    struct Node *cur = stk->head;
    while (cur) {
        struct Node *next = cur->next;   /* 先存 next, free 后不能再访问 */
        if (free_cb) free_cb(cur->payload);
        free(cur);
        cur = next;
    }
    free(stk);
    *s = NULL;
}

destroy 遍历的关键：free(cur) 前必须保存 cur->next，否则 free 后访问 cur->next 是 UAF。

链表栈 vs 数组栈

维度 链表栈 数组栈
容量 无上限 固定或扩容
push 延迟 malloc 不确定 O(1) 稳定
内存 节点分散 连续
cache 差，每次 push 新节点 好，访问 buf[top]
碎片 长跑易碎片 无碎片
per-push 开销 malloc + 指针改写 直接写 buf[top]
变长场景 适合 需扩容
HFT 数据面 慎用 首选

链表栈的 malloc 是最大痛点——延迟不确定（可能触发 mmap 扩堆）、多线程争全局锁、长期产生碎片。数组栈预分配后零分配。

配合 mempool 改造

把链表栈的 malloc/free 换成 mempool 的 get/put，可消除运行时分配：

/* push: 从 mempool 取节点 */
struct Node *n = rte_mempool_get(node_pool);
if (!n) return -1;
n->payload = data;
n->next = s->head;
s->head = n;

/* pop: 节点归还 mempool */
struct Node *old = s->head;
s->head = old->next;
void *data = old->payload;
rte_mempool_put(node_pool, old);   /* 不 free, 归还池 */

这样链表栈也能用于数据面——运行时零 malloc，节点从预分配池获取。但 cache 局部性仍不如数组栈（节点内存分散在 mempool 各处）。

Treiber 无锁栈

链表栈可以无锁化——用 CAS 原子更新 head：

int stack_push_lockfree(Stack *s, void *data)
{
    struct Node *n = malloc(sizeof *n);
    if (!n) return -1;
    n->payload = data;

    struct Node *old_head;
    do {
        old_head = s->head;        /* 读当前头 */
        n->next = old_head;        /* 新节点指向当前头 */
    } while (!__atomic_compare_exchange_n(&s->head, &old_head, n,
                                          0, __ATOMIC_ACQ_REL, __ATOMIC_ACQUIRE));
    /* CAS: 若 s->head 仍是 old_head 则换成 n, 否则重试 */
    return 0;
}

这是 Treiber stack（1986）。无锁 push 的关键：CAS 确保"读头 + 换头"原子。

ABA 问题：线程 A 读 head=X，线程 B pop X、push Y、再 push X（X 被回收复用）。线程 A 的 CAS 看到 head 仍是 X，成功——但中间的 pop/push 被忽略。解决方案：指针 + 计数器（tagged pointer）、Hazard Pointer、epoch-based reclamation。

HFT 数据面无锁栈是高级话题，通常用 mempool + 单线程独占避免无锁复杂性。

链表栈的 cache 代价

每次 push malloc 返回的节点地址可能分散在堆各处：

  • L1 cache line 64B，节点 16B，可能 4 个节点共享一行
  • 但 malloc 不保证连续分配，节点可能跨页
  • push 时写 n->next、n->payload 触发新 cache line 加载
  • pop 时读 cur->next 可能 cache miss

数组栈的 buf 连续，buf[top] 大概率已在 cache。实测数组栈 push/pop 比链表栈快 3-5x（无 mempool 时）。

链表栈的内存开销

每个节点额外 8 字节 next 指针（64 位）：

  • 载荷 8 字节 + 节点头 16 字节 = 24 字节/元素
  • 数组栈：8 字节/元素（只存指针）
  • 链表栈内存开销是数组栈的 3x

百万级元素时链表栈多耗 16MB，对 cache 友好性影响显著。

HFT 关联

  • 控制面可用：会话管理、配置解析等变长场景用链表栈可接受
  • 数据面慎用：malloc 延迟不确定 + cache 差，除非配 mempool
  • mempool 改造：链表栈 + mempool 消除运行时分配，但仍不如数组栈 cache 友好
  • 无锁 Treiber stack：多线程共享栈可用，但 ABA 问题需谨慎
  • 订单簿历史栈：按时间序保存订单修改历史，链表栈变长无上限
  • 递归转迭代：显式栈深度不可预测时用链表栈避免预分配过大
  • 避免长跑碎片：链表栈长跑 malloc/free 产生碎片，定期 defrag 或换 mempool

题目 1： 以下链表栈的 pop 操作有什么问题？

int pop(Node **top) {
    if (*top == NULL) return -1;
    int val = (*top)->data;
    Node *tmp = *top;
    *top = (*top)->next;
    // 缺少 free(tmp)

队列

本节讲什么

队列 ADT（FIFO 先进先出）：enqueue 尾入、dequeue 头出，链表与环形数组两种实现。队列是 HFT/DPDK 价值最高的 ADT——行情分发、订单下发、批处理链、日志异步队列全是队列。本节概览两种实现选型，具体细节在 17.3.1-17.3.3。

要点

队列核心操作

操作 语义 复杂度
enqueue(data) 尾入队 O(1)
dequeue() 头出队并返回 O(1)
peek() 读队头不出队 O(1)
len() 元素个数 O(1)
destroy(free_cb) 释放 + 载荷清理 O(n)

FIFO 语义：最早入队的最早出队，像排队买票。

两种实现选型

维度 链表队列（17.3.3） 环形数组队列（17.3.2）
内存 节点分散 连续
分配 每次 enqueue malloc 预分配
容量 无上限 固定
enqueue 延迟 malloc 不确定 O(1) 稳定
cache 差 好
碎片 长跑易碎片 无碎片
多线程 mutex SPSC 无锁
HFT 数据面 慎用 首选（rte_ring 原型）

队列与栈的对比

维度 栈（LIFO） 队列（FIFO）
操作端 同一端（栈顶） 两端（队尾入、队头出）
数组实现 top 线性增长 r/w 索引循环取模
链表实现 头插/头删 头删/尾插（需 tail 指针）
典型应用 递归、回滚 缓冲、分发

队列比栈复杂——需要维护两个端（head/tail 或 r_idx/w_idx），环形数组需要取模。

队列的典型应用

1. 生产者-消费者缓冲

/* 生产者线程 */
while (running) {
    Packet *pkt = receive();
    queue_enqueue(q, pkt);
}

/* 消费者线程 */
while (running) {
    Packet *pkt = queue_dequeue(q);
    if (pkt) process(pkt);
}

这是最经典的队列用法——解耦生产与消费速率。HFT 行情收发就是这模式。

2. 任务分发

/* 主线程接收, 分发到 worker 队列 */
for (int i = 0; i < nworkers; i++) {
    if (!queue_full(worker_q[i])) {
        queue_enqueue(worker_q[i], task);
        break;
    }
}

多 worker 各自有队列，主线程按负载分发。

3. 日志异步队列

/* 数据面线程: 只入队, 不等落盘 */
LOG_ASYNC("seq=%u bid=%u", seq, bid);   /* 内部 enqueue 到日志队列 */

/* 日志线程: 批量出队落盘 */
while (running) {
    LogEntry *batch[256];
    int n = queue_dequeue_batch(log_q, batch, 256);
    write(log_fd, batch, n * sizeof *batch);
}

数据面 LOG 只做 memcpy + enqueue（亚微秒），实际落盘由专门线程处理。这是 HFT 日志架构的核心。

4. 批处理

/* DPDK rte_eth_rx_burst 批量收包 */
struct rte_mbuf *bufs[32];
int n = rte_eth_rx_burst(port, queue, bufs, 32);
for (int i = 0; i < n; i++) {
    process(bufs[i]);
}

DPDK 的 burst 是队列的批处理变种——一次取多个元素，减少队列操作次数。

5. 滑动窗口

TCP 滑动窗口、限流令牌桶、HFT 订单流控都用队列实现窗口：

/* 滑动窗口限流 */
while (queue_len(q) >= max_window) {
    dequeue(q);   /* 丢弃最老的 */
}
enqueue(q, new_item);

队列的满与空

队列有两个边界条件：

  • 空：len == 0，dequeue 返回 NULL 或错误
  • 满：len == cap，enqueue 返回 -1 或丢弃最老元素

处理策略：

策略 行为 适用
阻塞 enqueue 满时等待 控制面
丢弃 enqueue 满时返回错误 数据面（绝不阻塞）
覆盖 enqueue 满时丢最老元素 实时监控（保最新）
扩容 enqueue 满时 realloc 控制面变长

HFT 数据面用"丢弃 + 告警"——满即说明消费跟不上，阻塞会放大延迟，宁可丢数据也要保延迟。

多线程队列分类

模型 生产者 消费者 同步
SPSC 单 单 可无锁
MPMC 多 多 需锁或复杂无锁
MPSC 多 单 可简化无锁
SPMC 单 多 较少见

SPSC（单生产者单消费者）是无锁队列的最佳场景——环形缓冲区 + 原子读写索引，零锁。DPDK rte_ring 默认 MP/MC 用 CAS，可配置成 SPSC 模式更快。

队列与背压

当消费者跟不上，队列堆积导致：

  • 内存增长（链表）或丢数据（环形）
  • 延迟上升（排队等待时间）
  • 生产者被迫降速（背压）

HFT 背压设计：

  • 行情队列满 → 丢弃旧行情（保最新）
  • 订单队列满 → 拒绝新订单（返回错误）
  • 日志队列满 → 丢弃日志（不阻塞数据面）

背压是分布式系统稳定的关键，队列是背压的实现载体。

HFT 关联

  • rte_ring：DPDK 无锁环形队列，HFT 数据面核心数据结构
  • 行情分发：收线程 enqueue，策略线程 dequeue，SPSC 无锁
  • 订单下发：策略线程 enqueue，发单线程 dequeue 批量发送
  • 日志异步：数据面 enqueue 内存，日志线程 dequeue 落盘
  • 批处理 burst：一次 dequeue 多个元素，减少队列操作开销
  • 背压设计：队列满即丢弃/告警，绝不阻塞数据面
  • SPSC 无锁：单生产者单消费者环形队列是 HFT 最优队列
  • MPMC rte_ring：多线程共享队列用 CAS，延迟略高但通用
  • 订单簿事件队列：订单簿变更 enqueue 事件，策略引擎 dequeue 处理

代码自测

题目 1： 以下循环队列实现中，队空和队满的条件分别是什么？

int queue[MAX];
int front = 0, rear = 0;

rear 指向下一个插入位置。

参考答案

队空：front == rear。队满：(rear + 1) % MAX == front。注意：循环队列中最多存 MAX-1 个元素——因为如果存 MAX 个，front == rear 会和队空条件冲突。牺牲一个位置是循环队列的标准做法。另一种方案是额外维护一个 size 变量记录元素个数。

17.3

.1 队列的接口

本节讲什么

队列 ADT 的标准 API：不透明 Queue *、enqueue/dequeue/peek/destroy、容量参数、批处理扩展。这是 ADT 接口设计的第二个范式（第一个是栈），与栈接口镜像对称。本节重点讲队列接口相比栈的额外设计——容量参数、批处理、多线程扩展。

要点

完整接口

/* queue.h */
#ifndef HFT_QUEUE_H
#define HFT_QUEUE_H

#include <stddef.h>

typedef struct Queue Queue;

/* cap>0 预分配环形; cap=0 动态链表 */
Queue *queue_create(size_t cap);

int    queue_enqueue(Queue *q, void *data);   /* 尾入, 0成功 -1满 */
void  *queue_dequeue(Queue *q);                /* 头出, NULL空 */
void  *queue_peek(const Queue *q);             /* 读队头不出 */
size_t queue_len(const Queue *q);
int    queue_full(const Queue *q);             /* 环形专用 */
void   queue_destroy(Queue **q, void (*free_cb)(void *));

/* 批处理扩展 (HFT 常用) */
size_t queue_enqueue_batch(Queue *q, void **items, size_t n);
size_t queue_dequeue_batch(Queue *q, void **out, size_t max);

#endif

与栈接口的对比

栈 队列
stack_create(void) queue_create(size_t cap)
stack_push (栈顶) queue_enqueue (队尾)
stack_pop (栈顶) queue_dequeue (队头)
无容量参数 cap 参数
无 full 检查 queue_full
无批处理 批处理扩展

队列多了 cap 参数——环形队列需要预分配容量，链表队列 cap=0 表示无上限。栈也可以有 cap，但栈的"满"通常是动态扩容解决，队列的"满"常是设计语义（丢弃/背压）。

容量参数的语义

Queue *q1 = queue_create(4096);   /* 环形, 容量 4096 */
Queue *q2 = queue_create(0);      /* 链表, 无上限 */
  • cap > 0：环形数组实现，预分配 cap 个槽位，满时 enqueue 返回 -1
  • cap == 0：链表实现，无上限，enqueue 失败仅因 malloc 失败
  • 实现选择由 cap 决定，使用者接口一致

HFT 数据面用 cap > 0 预分配，控制面用 cap == 0 变长。

enqueue 的返回值

int queue_enqueue(Queue *q, void *data);
  • 返回 0：成功
  • 返回 -1：队列满（环形）或 malloc 失败（链表）

调用者必须检查：

if (queue_enqueue(q, pkt) < 0) {
    /* 满, 业务决策: 丢弃、告警、背压 */
    drop_packet(pkt);
    stats.queue_full++;
}

不检查返回值是常见 bug——数据无声丢失。

dequeue 的空队列处理

void *queue_dequeue(Queue *q);

空队列返回 NULL。与栈同样有 NULL 歧义（用户可能 enqueue 了 NULL）。生产代码可用：

int queue_dequeue(Queue *q, void **out);   /* 0成功 -1空 */

或先检查：

if (queue_len(q) > 0) {
    void *data = queue_dequeue(q);
    process(data);
}

批处理接口

HFT 高频场景单元素 enqueue/dequeue 开销大——每次操作有函数调用 + 可能的锁。批处理一次操作多个元素：

/* 批量入队, 返回实际入队数 */
size_t queue_enqueue_batch(Queue *q, void **items, size_t n)
{
    size_t i;
    for (i = 0; i < n; i++) {
        if (queue_enqueue(q, items[i]) < 0) break;
    }
    return i;
}

/* 批量出队, 返回实际出队数 */
size_t queue_dequeue_batch(Queue *q, void **out, size_t max)
{
    size_t i;
    for (i = 0; i < max; i++) {
        out[i] = queue_dequeue(q);
        if (!out[i]) break;
    }
    return i;
}

DPDK rte_eth_rx_burst/rte_eth_tx_burst 就是批处理接口——一次取/发 32 个 mbuf，比逐个操作快数倍。

peek 与只读操作

void *queue_peek(const Queue *q);
size_t queue_len(const Queue *q);
int queue_full(const Queue *q);

const 修饰表示不修改队列。多线程下 const 操作仍需同步——其他线程可能并发修改。

多线程扩展

标准接口是单线程的。多线程需要扩展：

/* 加锁版 */
typedef struct TsQueue {
    Queue *q;
    pthread_mutex_t mtx;
    pthread_cond_t not_empty, not_full;
} TsQueue;

int ts_queue_enqueue(TsQueue *q, void *data);
void *ts_queue_dequeue(TsQueue *q);

/* 无锁 SPSC 版 */
typedef struct SpScRing {
    void **buf;
    size_t cap;
    size_t mask;   /* cap-1, 要求 cap 是 2 的幂 */
    volatile size_t r_idx, w_idx;   /* 原子读写 */
} SpScRing;

接口形态一致，实现差异巨大。ADT 的价值——业务代码不感知底层同步机制。

接口与实现的可替换性

/* 控制面: 链表队列 */
Queue *q = queue_create(0);

/* 数据面: 环形队列 */
Queue *q = queue_create(4096);

/* 接口完全一致, 业务代码不变 */
queue_enqueue(q, data);
void *d = queue_dequeue(q);

编译时切换实现，业务代码零修改。这是 ADT 接口设计的核心收益。

HFT 关联

  • rte_ring 接口：DPDK rte_ring_enqueue/rte_ring_dequeue/rte_ring_enqueue_burst 遵循此范式
  • 批处理 burst：数据面高频收发用批量接口，减少函数调用与锁开销
  • SPSC 无锁：单生产者单消费者场景接口形态不变，实现换无锁 ring
  • 容量预分配：数据面队列 cap 固定，满即丢弃 + 告警，绝不阻塞
  • 接口稳定 ABI：Queue * 不透明指针，内部重构不需重编使用者
  • 多线程接口扩展：TsQueue 加锁版、SpScRing 无锁版，按场景选择
  • 日志异步队列：数据面 enqueue_batch 批量入队，日志线程 dequeue_batch 批量落盘

题目 1： 以下队列接口使用二级指针有什么好处？

参考答案

17.3

.2 用数组实现队列

本节讲什么

环形缓冲区（ring buffer）队列：固定容量数组 + 读写索引循环取模。这是 DPDK rte_ring 的思想原型，也是 HFT 数据面最核心的数据结构——SPSC 无锁、零运行时分配、cache 友好。本节重点讲取模优化、满空判别、无锁 SPSC 实现、内存序。

要点

结构定义

struct Ring {
    void **buf;
    size_t cap;
    size_t r_idx;   /* 读索引, 消费者维护 */
    size_t w_idx;   /* 写索引, 生产者维护 */
    size_t len;     /* 当前元素数 (多线程需原子) */
};

基本操作

int ring_enqueue(Ring *r, void *data)
{
    if (r->len >= r->cap) return -1;   /* 满 */
    r->buf[r->w_idx] = data;
    r->w_idx = (r->w_idx + 1) % r->cap;   /* 循环 */
    r->len++;
    return 0;
}

void *ring_dequeue(Ring *r)
{
    if (r->len == 0) return NULL;   /* 空 */
    void *data = r->buf[r->r_idx];
    r->r_idx = (r->r_idx + 1) % r->cap;
    r->len--;
    return data;
}

关键：索引到 cap-1 后取模回到 0，形成环形。

取模优化：2 的幂

% cap 是除法指令，慢。若 cap 是 2 的幂，% cap 等价 & (cap - 1)：

/* cap = 4096 = 2^12, mask = 4095 = 0xFFF */
r->w_idx = (r->w_idx + 1) & r->mask;   /* 位与替代取模 */

DPDK rte_ring 强制 cap 是 2 的幂，用 mask 替代取模。位与比除法快 10-20x。

struct Ring {
    void **buf;
    size_t cap;    /* 必须是 2 的幂 */
    size_t mask;   /* cap - 1 */
    size_t r_idx, w_idx;
};

Ring *ring_create(size_t cap)
{
    /* cap 向上取整到 2 的幂 */
    size_t real_cap = 1;
    while (real_cap < cap) real_cap <<= 1;

    Ring *r = malloc(sizeof *r);
    r->buf = calloc(real_cap, sizeof(void *));
    r->cap = real_cap;
    r->mask = real_cap - 1;
    r->r_idx = r->w_idx = 0;
    return r;
}

满空判别的两种方案

方案 A：显式 len

struct Ring { ..., size_t len; };
/* 满: len == cap */
/* 空: len == 0 */

简单直观，但 len 多线程需原子更新。

方案 B：留一个空槽

struct Ring { size_t r_idx, w_idx; size_t cap; };
/* 满: (w_idx + 1) % cap == r_idx */
/* 空: w_idx == r_idx */

不存 len，但容量实际是 cap - 1（永远留一个空槽区分满空）。DPDK 早期用此方案。

方案 C：独立计数器（无锁常用）

struct Ring {
    void **buf;
    size_t cap, mask;
    volatile size_t r_idx, w_idx;   /* 只用索引, 不存 len */
};
/* 空: r_idx == w_idx */
/* 满: w_idx - r_idx == cap */

索引单调递增（不取模），用 w_idx - r_idx 算元素数。索引值可能很大但 size_t 足够长（2^64 溢出要 58000 年@1GHz）。DPDK rte_ring 用此方案。

int ring_enqueue(Ring *r, void *data)
{
    size_t w = r->w_idx;
    if (w - r->r_idx >= r->cap) return -1;   /* 满 */
    r->buf[w & r->mask] = data;              /* 用 mask 取模 */
    __atomic_store_n(&r->w_idx, w + 1, __ATOMIC_RELEASE);
    return 0;
}

void *ring_dequeue(Ring *r)
{
    size_t rd = r->r_idx;
    if (rd == r->w_idx) return NULL;   /* 空 */
    void *data = r->buf[rd & r->mask];
    __atomic_store_n(&r->r_idx, rd + 1, __ATOMIC_RELEASE);
    return data;
}

SPSC 无锁的正确性

单生产者单消费者场景下，w_idx 只被生产者写、消费者读；r_idx 只被消费者写、生产者读。两个变量各只有一个写者，无需 CAS，只需正确的内存序：

  • 生产者写 buf[w] 后用 RELEASE 序发布 w_idx，确保消费者看到新 w_idx 时 buf[w] 已可见
  • 消费者读 buf[r] 前用 ACQUIRE 序读 w_idx，确保看到 w_idx 的更新时 buf 数据已加载
/* 生产者 */
r->buf[w & r->mask] = data;
__atomic_store_n(&r->w_idx, w + 1, __ATOMIC_RELEASE);   /* 发布 */

/* 消费者 */
size_t w = __atomic_load_n(&r->w_idx, __ATOMIC_ACQUIRE);   /* 获取 */
if (rd == w) return NULL;
void *data = r->buf[rd & r->mask];
__atomic_store_n(&r->r_idx, rd + 1, __ATOMIC_RELEASE);

这是无锁 SPSC 队列的标准模式，DPDK rte_ring 的 SPSC 模式即是此。

MPMC 的 CAS 复杂化

多生产者时，多个线程同时 r->w_idx = w + 1 会冲突。用 CAS：

size_t w, next_w;
do {
    w = __atomic_load_n(&r->w_idx, __ATOMIC_ACQUIRE);
    if (w - r->r_idx >= r->cap) return -1;   /* 满 */
    next_w = w + 1;
} while (!__atomic_compare_exchange_n(&r->w_idx, &w, next_w,
        0, __ATOMIC_ACQ_REL, __ATOMIC_ACQUIRE));
/* CAS 成功, 槽位 w 已预留 */
r->buf[w & r->mask] = data;
/* 注意: 这里 buf[w] 写入与 w_idx 更新不是原子的,
 * 消费者可能看到 w_idx 更新但 buf[w] 还是旧值!
 * DPDK 用两段式: 预留 + 提交, 中间有 visible 标记 */

MPMC 无锁队列实现复杂，常需两阶段（reserve + commit）+ visible 标志。DPDK rte_ring 的 MPMC 模式如此。

批处理

size_t ring_dequeue_batch(Ring *r, void **out, size_t max)
{
    size_t rd = __atomic_load_n(&r->r_idx, __ATOMIC_ACQUIRE);
    size_t w = __atomic_load_n(&r->w_idx, __ATOMIC_ACQUIRE);
    size_t available = w - rd;
    size_t n = available < max ? available : max;

    for (size_t i = 0; i < n; i++) {
        out[i] = r->buf[(rd + i) & r->mask];
    }
    __atomic_store_n(&r->r_idx, rd + n, __ATOMIC_RELEASE);
    return n;
}

一次取多个，减少原子操作次数。DPDK rte_ring_dequeue_burst 即此。

缓存行伪共享（false sharing）

r_idx 和 w_idx 若在同一 cache line，生产者写 w_idx 和消费者写 r_idx 互相使对方的 cache line 失效，性能崩塌。解决：padding 强制两个索引在不同 cache line：

struct Ring {
    void **buf;
    size_t cap, mask;
    char pad1[64 - sizeof(size_t) * 3];   /* 填充到 64 字节边界 */
    volatile size_t r_idx;                 /* 独占 cache line */
    char pad2[64 - sizeof(size_t)];        /* 填充 */
    volatile size_t w_idx;                 /* 独占 cache line */
    char pad3[64 - sizeof(size_t)];
};

DPDK rte_ring 用 __rte_cache_aligned 宏做此对齐。这是无锁队列性能的关键。

环形缓冲区的 cache 友好性

buf 连续内存，顺序访问模式命中 prefetcher。但环形绕回时（w_idx 从 cap-1 跳到 0）可能跨 cache line，引发短暂 miss。cap 是 2 的幂时绕回点固定，prefetcher 可学习。

HFT 关联

  • rte_ring 原型：本节描述的就是 DPDK rte_ring 的核心思想
  • SPSC 无锁：单生产者单消费者场景的最高性能队列，无锁无等待
  • cache line 对齐：r_idx/w_idx 分离 cache line 避免伪共享
  • 2 的幂 + mask：位与替代取模，10-20x 加速
  • 批处理 burst：一次取多个 mbuf，减少原子操作开销
  • 行情分发：收包线程 SPSC 入队，策略线程出队，零锁
  • 订单下发：策略线程入队，发单线程批量出队发送
  • 日志异步：数据面批量入队，日志线程批量出队落盘
  • 背压：环形满即丢弃 + 告警，绝不阻塞生产者

题目 1： 以下数组队列实现有什么问题？

int queue[MAX];
int front = 0, rear = 0;
void enqueue(int val) {

17.3

.3 用链表实现队列

本节讲什么

链表队列：head 指针出队、tail 指针入队，O(1) 双端操作，无容量上限。这是变长场景的标准队列实现，配合 mempool 可用于 HFT 控制面。本节重点讲 head/tail 双指针维护、空队列入队的特殊处理、与环形队列的选型。

要点

结构定义

struct Node {
    void *payload;
    struct Node *next;
};

struct Queue {
    struct Node *head;   /* 队头, 出队端 */
    struct Node *tail;   /* 队尾, 入队端 */
    size_t len;
};

相比链表栈（只需 head），队列多一个 tail 指针——入队在尾端 O(1)，否则要遍历到尾 O(n)。

enqueue：尾插

int queue_enqueue(Queue *q, void *data)
{
    struct Node *n = malloc(sizeof *n);
    if (!n) return -1;
    n->payload = data;
    n->next = NULL;   /* 新节点是尾, next 为 NULL */

    if (!q->tail) {
        /* 空队列: head 和 tail 都指向新节点 */
        q->head = q->tail = n;
    } else {
        /* 非空: 接到 tail 后, tail 前移 */
        q->tail->next = n;
        q->tail = n;
    }
    q->len++;
    return 0;
}

空队列的特殊处理是关键——q->tail 为 NULL 时没有 tail->next 可写，必须同时设 head 和 tail。

dequeue：头删

void *queue_dequeue(Queue *q)
{
    if (!q->head) return NULL;   /* 空队 */
    struct Node *n = q->head;
    void *data = n->payload;
    q->head = n->next;   /* head 后移 */

    if (!q->head) {
        /* 队列空了, tail 也要置 NULL, 否则悬垂 */
        q->tail = NULL;
    }

    free(n);
    q->len--;
    return data;
}

关键细节：删到最后一个节点时，head 变 NULL，tail 必须同步置 NULL。否则 tail 仍指向已 free 的节点，下次 enqueue 访问 tail->next 是 UAF。

peek 与 destroy

void *queue_peek(const Queue *q)
{
    return q->head ? q->head->payload : NULL;
}

void queue_destroy(Queue **q, void (*free_cb)(void *))
{
    if (!q || !*q) return;
    Queue *qu = *q;
    struct Node *cur = qu->head;
    while (cur) {
        struct Node *next = cur->next;
        if (free_cb) free_cb(cur->payload);
        free(cur);
        cur = next;
    }
    free(qu);
    *q = NULL;
}

链表队列 vs 环形队列

维度 链表队列 环形队列
容量 无上限 固定
内存 节点分散 连续
enqueue 延迟 malloc 不确定 O(1) 稳定
cache 差 好
碎片 长跑易碎片 无碎片
多线程 mutex 或复杂无锁 SPSC 无锁简单
满处理 不满（无上限） 丢弃/背压
变长场景 适合 需预估容量
HFT 数据面 慎用 首选
HFT 控制面 可用 可用

链表队列的 MS-Queue 无锁

链表队列的无锁版本是 MS-Queue（Michael & Scott, 1996），用 CAS 操作 head 和 tail：

  • enqueue：CAS 预留 tail 位置 + CAS 掐着 tail->next 接上新节点 + CAS 推进 tail
  • dequeue：CAS 推进 head

MS-Queue 比 SPSC 环形复杂得多，且 ABA 问题严重。HFT 数据面倾向用环形 SPSC 避免无锁链表队列的复杂性。

哨兵节点（dummy head）

简化边界处理的技巧——用一个永远存在的 dummy 节点作为 head，真实数据从 head->next 开始：

struct Queue {
    struct Node *head;   /* 永远指向 dummy */
    struct Node *tail;   /* 指向最后真实节点 */
};

/* 初始化时创建 dummy */
Queue *q = malloc(sizeof *q);
q->head = q->tail = calloc(1, sizeof(struct Node));   /* dummy, payload=NULL */
q->len = 0;

/* enqueue: 永远接在 tail 后, 不用判空 */
n->next = NULL;
q->tail->next = n;
q->tail = n;
q->len++;

/* dequeue: 取 head->next, head 前移, 旧 head 释放 */
struct Node *old = q->head;
q->head = old->next;
void *data = q->head->payload;
free(old);
q->len--;
/* 空队时 head==tail, head->next==NULL, dequeue 返回 NULL */

哨兵节点消除"空队列"特殊分支，代码更简洁。无锁队列常用此技巧简化 CAS 逻辑。

配合 mempool

把 malloc/free 换成 mempool：

/* enqueue: 从 mempool 取节点 */
struct Node *n = rte_mempool_get(node_pool);
n->payload = data;
n->next = NULL;
if (!q->tail) q->head = q->tail = n;
else { q->tail->next = n; q->tail = n; }

/* dequeue: 节点归还 mempool */
struct Node *old = q->head;
void *data = old->payload;
q->head = old->next;
if (!q->head) q->tail = NULL;
rte_mempool_put(node_pool, old);   /* 不 free, 归还池 */

零运行时分配，但 cache 局部性仍不如环形（节点分散在 mempool）。

链表队列的内存开销

每元素额外 16 字节（payload 指针 + next 指针）：

  • 100 万元素：16MB 额外开销
  • 环形队列：8MB（仅 payload 指针）
  • 链表是环形的 2x 内存

长跑 HFT 进程倾向环形，避免链表碎片 + 内存翻倍。

HFT 关联

  • 控制面可用：会话管理、慢路径处理用链表队列可接受
  • 数据面慎用：malloc 延迟不确定 + cache 差，除非配 mempool
  • mempool 改造：链表队列 + mempool 消除运行时分配
  • MS-Queue 无锁：MPMC 无锁链表队列，但 ABA 问题复杂
  • 哨兵节点：简化边界处理，无锁队列常用
  • 订单簿事件队列：事件数量不可预估时用链表队列变长
  • 避免长跑碎片：链表队列长跑 malloc/free 产生碎片，定期重启或换环形
  • rte_ring 优先：HFT 数据面队列首选环形，链表仅控制面备用

typedef struct Queue {

参考答案

17.4

树

本节讲什么

二叉搜索树（BST）：有序 ADT，支持 O(log n) 插入/删除/查找/范围查询。本节概览 BST 与有序数组、哈希表的选型，以及 BST 在 HFT 场景的应用——合约索引、订单簿价格档位、会话管理。具体操作在 17.4.1-17.4.4。

要点

BST 性质

对每个节点 N：

  • 左子树所有节点 key < N.key
  • 右子树所有节点 key > N.key
  • 左右子树各自也是 BST

这条性质让查找可以像二分一样剪枝——每次比较排除一半子树。

节点结构

struct TreeNode {
    void *key;
    void *payload;            /* 可选, 关联数据 */
    struct TreeNode *left, *right;
};

或内嵌 key（避免 void* 间接）：

struct TreeNode {
    uint64_t key;             /* 直接存 key, 省 void* 间接 */
    struct TreeNode *left, *right;
};

内嵌 key 省 void* 间接访问，cache 友好，但失去泛型性。

三种有序结构对比

结构 查找 插入 删除 范围查询 内存 适用
BST（平衡） O(log n) O(log n) O(log n) O(k+log n) 节点分散 动态有序
有序数组 + bsearch O(log n) O(n) O(n) O(log n + k) 连续 静态/少更新
哈希表 O(1) 均摊 O(1) 均摊 O(1) 均摊 不支持 桶+链 精确查找

HFT 选型：

  • 合约/会话映射：哈希表，O(1) 精确查找
  • 静态配置表：有序数组 + bsearch，cache 友好
  • 订单簿价格档位：BST 或专用结构，需范围查询
  • 动态有序集：平衡 BST（AVL/RB/跳表）

BST 的退化问题

不平衡的 BST 退化为链表，查找 O(n)：

插入 1, 2, 3, 4, 5  →  全在右子树, 退化成链表
    1
     \
      2
       \
        3
         \
          4
           \
            5

平衡 BST 解决：

平衡树 平衡条件 旋转代价
AVL 左右子树高度差 ≤ 1 严格，查找最优
红黑树 路径黑节点数相同 宽松，插入/删除快
Treap 随机优先级堆性质 简单，期望平衡
跳表 概率多层索引 简单，无锁友好

Linux 内核用红黑树（struct rb_node），C++ std::map 也是红黑树。HFT 对延迟敏感时用更紧凑的专用结构（如 B+ 树、跳表）。

BST 的典型应用

1. 符号表

编译器/解释器用 BST 存变量名 → 类型和值。HFT 策略引擎的参数表类似。

2. 优先队列

BST 按优先级组织，取最高/最低优先级 O(log n)。但堆（数组实现）更紧凑，实际优先队列用堆更多。

3. 范围查询

/* 查询 key 在 [low, high] 的所有节点 */
void range_query(TreeNode *root, uint64_t low, uint64_t high,
                 void (*handler)(TreeNode *))
{
    if (!root) return;
    if (root->key > low)  range_query(root->left, low, high, handler);
    if (root->key >= low && root->key <= high) handler(root);
    if (root->key < high) range_query(root->right, low, high, handler);
}

BST 的中序遍历天然有序，范围查询 O(log n + k)（k 是结果数）。这是 BST 相比哈希表的核心优势。

4. 订单簿价格档位

/* 按价格组织的订单簿 */
struct PriceLevel {
    int64_t price;            /* key */
    struct Order *orders;      /* 该价位挂单链表 */
};

struct TreeNode *bid_tree;   /* 买单按价格降序 */
struct TreeNode *ask_tree;   /* 卖单按价格升序 */
  • 插入挂单：BST 插入 PriceLevel
  • 撤单：BST 查找 + 删除
  • 撮合：取最优价格档位（BST 最左/最右节点）
  • 范围查询：查某价格区间所有挂单

实际 HFT 订单簿用更紧凑的专用结构（如数组和链表混合），但思想同 BST。

BST 与堆的对比

维度 BST 堆
结构 二叉搜索树 完全二叉树
查找任意 O(log n) O(n)
取最值 O(log n)（最左/右） O(1)（根）
插入 O(log n) O(log n)
删除最值 O(log n) O(log n)
范围查询 支持 不支持
实现 指针 数组

堆是"只关心最值"的专用结构，BST 是"需要全序访问"的通用结构。订单簿取最优价用堆更快，但需要范围查询时用 BST。

节点分配与 mempool

BST 节点动态创建，每次插入 malloc。HFT 数据面用 mempool 预分配节点：

struct TreeNode *n = rte_mempool_get(tree_node_pool);
n->key = key;
n->left = n->right = NULL;

零运行时分配，节点归还 mempool 不 free。

BST 的线程安全

标准 BST 操作不是线程安全的。多线程共享 BST：

  • 加读写锁（读多写少场景）
  • 无锁 BST（极复杂，研究级）
  • 每线程独立 BST + 定期合并

HFT 订单簿通常单线程处理（核心策略线程独占），避免 BST 加锁。

HFT 关联

  • 合约/会话索引：哈希表 O(1) 精确查找，BST 次选
  • 订单簿价格档位：BST 或专用结构，支持范围查询
  • 策略参数表：BST 按参数名有序，配置加载时建树
  • 历史 tick 索引：按时间戳 BST，支持时间范围查询
  • 平衡树选型：红黑树（Linux 内核风格）、跳表（无锁友好）
  • mempool 节点：BST 节点从预分配池获取，零运行时分配
  • 单线程独占：订单簿 BST 通常单线程处理，避免加锁
  • 范围查询优势：BST 相比哈希表的核心价值——支持有序范围查询

void insert(Node *root, int val) {

17.4

.1 插入节点

本节讲什么

BST 的插入：按 cmp 递归找到空位，创建新节点挂上。这是 BST 维护有序性的基础操作，也是理解 BST 查找路径的钥匙。本节重点讲递归与迭代两种实现、重复键策略、退化与平衡。

要点

递归插入

struct TreeNode {
    void *key;
    struct TreeNode *left, *right;
};

TreeNode *tree_insert(TreeNode *root, void *key,
                      int (*cmp)(const void *, const void *))
{
    if (!root) {
        /* 空位, 创建新节点 */
        TreeNode *n = calloc(1, sizeof *n);
        if (!n) return NULL;
        n->key = key;
        return n;
    }

    int c = cmp(key, root->key);
    if (c < 0)
        root->left = tree_insert(root->left, key, cmp);
    else if (c > 0)
        root->right = tree_insert(root->right, key, cmp);
    /* c == 0: 重复键, 按策略处理 */

    return root;   /* 返回当前子树根 */
}

递归插入的逻辑：

  1. 当前子树为空 → 创建新节点返回
  2. key < root.key → 递归左子树
  3. key > root.key → 递归右子树
  4. key == root.key → 重复键，按策略处理

返回值与重建链接

递归插入的精妙在于返回值——每层返回"当前子树的根"，父层用 root->left = tree_insert(root->left, ...) 重新挂接。空子树插入时，新节点通过返回值"长"出来，父层的 root->left 指向它。

这是函数式风格的树修改——不改变原树结构，而是返回新树。但在 C 里实际是原地修改（通过指针重新链接），不是真正的持久化结构。

迭代插入

int tree_insert_iter(Tree *t, void *key, cmp_fn cmp)
{
    TreeNode *n = calloc(1, sizeof *n);
    if (!n) return -1;
    n->key = key;

    if (!t->root) {
        t->root = n;
        return 0;
    }

    TreeNode *cur = t->root;
    while (1) {
        int c = cmp(key, cur->key);
        if (c < 0) {
            if (!cur->left) { cur->left = n; return 0; }
            cur = cur->left;
        } else if (c > 0) {
            if (!cur->right) { cur->right = n; return 0; }
            cur = cur->right;
        } else {
            /* 重复键, 按策略 */
            free(n);
            return -1;   /* 或插入右子树等 */
        }
    }
}

迭代版避免递归栈开销，深树不怕爆栈。HFT 倾向迭代版——报文解析嵌套深度不可控时递归有风险。

递归 vs 迭代

维度 递归 迭代
代码 简洁 稍长
栈开销 每层一帧 无
深度限制 受栈大小 仅受堆
可读性 高 中
HFT 控制面可用 数据面首选

平衡树深度 O(log n)，递归安全。但极端不平衡退化为 O(n)，n 很大时栈溢出。HFT 数据面用迭代避免风险。

重复键策略

cmp == 0 时三种策略：

策略 A：拒绝插入

if (c == 0) {
    /* 已存在, 拒绝 */
    return root;   /* 或返回错误 */
}

适用于"键唯一"的集合（如合约代码表）。

策略 B：放右子树

if (c <= 0)
    root->left = tree_insert(root->left, key, cmp);   /* <= 而非 < */
else
    root->right = tree_insert(root->right, key, cmp);

重复键当"稍大"处理，放右子树。查找时会找到所有重复。但树可能因重复键退化。

策略 C：节点存链表

struct TreeNode {
    void *key;
    struct Node *duplicates;   /* 同 key 的多个载荷链表 */
    struct TreeNode *left, *right;
};

/* 插入时 key 已存在, append 到 duplicates 链表 */

每个 key 对应一个链表存所有重复载荷。订单簿同价位多笔挂单用此模式——价格档位是 key，挂单链表是 duplicates。

cmp 函数的严格弱序

cmp 必须满足严格弱序（详见 16.1）：

  • cmp(a, b) < 0 和 cmp(b, a) > 0 不能同时真
  • cmp(a, b) == 0 等价 cmp(b, a) == 0
  • 传递性：cmp(a, b) < 0 && cmp(b, c) < 0 → cmp(a, c) < 0

违反会导致 BST 性质破坏，查找/删除行为未定义。常见错误：

  • 浮点 cmp 含 NaN（NaN 比较恒 false，破坏传递性）
  • 整数减法溢出（return a - b 当 a=INT_MAX, b=-1 时溢出）

退化与平衡

顺序插入 1,2,3,4,5 → 全在右子树，退化成链表，查找 O(n)。

平衡树的旋转：

插入 3 后右子树过高, 左旋:
    1                 2
     \               / \
      2      →      1   3
       \
        3

AVL 在插入后检查高度差，超 1 就旋转。红黑树用颜色约束近似平衡。Treap 用随机优先级。HFT 平衡树选型：

  • 红黑树：Linux 内核、C++ std::map 标准，通用
  • AVL：查找密集，插入/删除少
  • Treap：实现简单，期望平衡
  • 跳表：无锁友好，Redis 用

插入的内存分配

每次插入 calloc 新节点。HFT 数据面用 mempool：

TreeNode *n = rte_mempool_get(tree_node_pool);
n->key = key;
n->left = n->right = NULL;

零运行时分配。节点归还 mempool 不 free。

插入的复杂度

情况 复杂度
平衡 BST O(log n)
随机插入 O(log n) 期望
顺序插入（退化） O(n)
平衡树旋转 O(1) 每次, 总共 O(log n)

HFT 订单簿插入要求 O(log n) 稳定，必须平衡树或专用结构。

HFT 关联

  • 订单簿挂单：插入价格档位 O(log n)，平衡树保证延迟稳定
  • 合约表：启动时批量插入合约，运行时只读
  • 会话表：新连接插入会话节点，断开删除
  • mempool 节点：BST 节点从预分配池获取，零运行时分配
  • 迭代版优先：数据面用迭代插入避免递归爆栈风险
  • 重复键策略：订单簿同价位多笔挂单用"节点存链表"策略
  • 平衡树选型：红黑树通用，AVL 查找优，跳表无锁友好
  • cmp 严格弱序：订单簿按价格 cmp 必须无溢出、无 NaN

17.4

.2 删除节点

本节讲什么

BST 的删除：分叶子、单子、双子三种情况，双子情况用中序后继替换。这是 BST 最复杂的操作——指针改写多、容易写错。本节重点讲三种情况的处理、中序后继的查找、载荷所有权、以及 HFT 订单簿撤单的删除路径。

要点

三种删除情况

情况 1：叶子节点（无子节点）

直接 free：

    parent
       |
       N        →    parent
                     |
                    NULL

if (!n->left && !n->right) {
    /* 叶子, 父节点对应指针置 NULL */
    if (parent->left == n) parent->left = NULL;
    else parent->right = NULL;
    free(n);
}

情况 2：单子节点

用子节点顶替：

    parent              parent
      |                   |
      N          →        child
     /
   child

TreeNode *child = n->left ? n->left : n->right;
if (parent->left == n) parent->left = child;
else parent->right = child;
free(n);

情况 3：双子节点（最复杂）

用中序后继（右子树最小节点）替换 N 的 key，然后删除后继：

    parent              parent
      |                   |
      N        →        succ
     / \                 / \
    L   R               L   R'
       /                   /
      ...                 ...
       \
        succ  ← 右子树最小, 删除后 R' 是 succ 原右子树

中序后继 succ 是右子树最左节点，它一定没有左子树（否则更左的节点才是后继）。删除 succ 是"情况 1 或 2"。

TreeNode *succ = find_min(n->right);   /* 右子树最左 */
void *succ_key = succ->key;
void *succ_payload = succ->payload;

/* 递归删除 succ (它一定无左子树, 走情况 1 或 2) */
n->right = tree_delete(n->right, succ->key, cmp);

/* 用 succ 的 key/payload 覆盖 n */
n->key = succ_key;
n->payload = succ_payload;
/* succ 节点已在 tree_delete 里 free */

递归删除完整实现

TreeNode *tree_delete(TreeNode *root, const void *key, cmp_fn cmp,
                      void (*free_cb)(void *))
{
    if (!root) return NULL;   /* 未找到 */

    int c = cmp(key, root->key);
    if (c < 0) {
        root->left = tree_delete(root->left, key, cmp, free_cb);
    } else if (c > 0) {
        root->right = tree_delete(root->right, key, cmp, free_cb);
    } else {
        /* 找到, 三种情况 */
        if (!root->left && !root->right) {
            /* 叶子 */
            if (free_cb) free_cb(root->key);
            free(root);
            return NULL;
        }
        if (!root->left) {
            /* 只有右子 */
            TreeNode *r = root->right;
            if (free_cb) free_cb(root->key);
            free(root);
            return r;
        }
        if (!root->right) {
            /* 只有左子 */
            TreeNode *l = root->left;
            if (free_cb) free_cb(root->key);
            free(root);
            return l;
        }
        /* 双子: 找中序后继 */
        TreeNode *succ = root->right;
        while (succ->left) succ = succ->left;

        /* 交换 key/payload (或覆盖) */
        void *old_key = root->key;
        root->key = succ->key;
        root->payload = succ->payload;
        succ->key = old_key;   /* 让 tree_delete 释放 old_key */

        /* 删除后继 (succ 在右子树, 一定无左子) */
        root->right = tree_delete(root->right, succ->key, cmp, free_cb);
    }
    return root;
}

中序后继 vs 中序前驱

双子删除可用后继（右子树最小）或前驱（左子树最大）：

  • 后继：右子树最左节点
  • 前驱：左子树最右节点

两者都能保持 BST 性质。选择策略：

  • 交替使用（平衡子树高度）
  • 固定选后继（实现简单）
  • 按子树大小选（选更大的子树的前驱/后继，减少不平衡）

平衡树删除后需要重平衡，选后继还是前驱影响旋转次数。

载荷所有权

删除节点时，节点本身 free，但载荷（key/payload）由谁释放？

  • free_cb 非空：调用 free_cb(root->key) 释放载荷
  • free_cb 为 NULL：载荷由外部管理，不释放

双子情况最微妙——succ 的 key 被搬到 root，root 的原 key 要释放。代码里通过"交换 key 再递归删除 succ"实现——递归删除时 free_cb 会释放"原 root key"（现在在 succ 节点）。

删除的平衡维护

普通 BST 删除不维护平衡，可能让树越来越歪。平衡树（AVL/红黑）删除后需要重平衡：

  • AVL：检查高度差，旋转
  • 红黑：颜色调整 + 旋转

删除的平衡维护比插入复杂——可能触发多次旋转向上传播。红黑树删除实现是数据结构课程最难的代码之一。

删除的复杂度

情况 复杂度
叶子 O(log n) 查找 + O(1) free
单子 O(log n) 查找 + O(1) 链接
双子 O(log n) 查找 + O(log n) 找后继 + O(log n) 删后继
平衡维护 O(log n) 旋转

最坏 O(log n)，但常数因子比插入大（多次指针改写）。

HFT 订单簿撤单

/* 撤单: 按 order_id 查找并删除 */
void cancel_order(OrderBook *book, uint64_t order_id)
{
    TreeNode *level = tree_find(book->levels, &order_id, cmp_order);
    if (!level) return;   /* 未找到 */

    /* 从价位挂单链表删除 */
    list_remove(&level->orders, &order_id, cmp_order);

    if (list_empty(level->orders)) {
        /* 价位空了, 删除价位节点 */
        book->levels = tree_delete(book->levels, &level->price, cmp_price, free_level);
    }
}

撤单路径：BST 查找价位 → 链表删除挂单 → 价位空则 BST 删除价位节点。

删除与并发

BST 删除的指针改写多，多线程并发删除极易破坏结构。HFT 订单簿通常单线程处理（策略线程独占），避免并发删除。若必须并发，用读写锁或无锁 BST（极复杂）。

HFT 关联

  • 订单簿撤单：BST 查找价位 + 链表删挂单 + 价位空则 BST 删节点
  • 会话断开：BST 删除会话节点，free_cb 释放连接资源
  • mempool 节点归还：删除的节点归还 mempool 而非 free
  • 单线程独占：订单簿 BST 单线程处理，避免并发删除破坏
  • 平衡维护：订单簿频繁插入/删除，必须平衡树，否则退化 O(n)
  • 中序后继选择：订单簿按价格组织，后继是"次优价位"，删除最优价位后后继顶上
  • 载荷所有权：删除价位节点时，挂单链表通过 free_cb 释放
  • 延迟稳定：平衡树删除 O(log n) 稳定，HFT 撤单延迟可预测

17.4

.3 查找特定值的节点

本节讲什么

BST 的查找：按 cmp 递归/迭代剪枝，O(log n) 定位节点。本节重点讲查找的实现、与有序数组 bsearch 的对比、以及 HFT 微秒级 ID 检索的选型。

要点

递归查找

TreeNode *tree_find(TreeNode *root, const void *key, cmp_fn cmp)
{
    if (!root) return NULL;
    int c = cmp(key, root->key);
    if (c == 0) return root;
    return c < 0 ? tree_find(root->left, key, cmp)
                 : tree_find(root->right, key, cmp);
}

简洁但递归开销。查找路径是根到目标节点的唯一路径，长度等于树高。

迭代查找（HFT 首选）

TreeNode *tree_find_iter(TreeNode *root, const void *key, cmp_fn cmp)
{
    while (root) {
        int c = cmp(key, root->key);
        if (c == 0) return root;
        root = c < 0 ? root->left : root->right;
    }
    return NULL;
}

无递归栈开销，热路径首选。编译器能把 cmp 内联（若类型已知），进一步加速。

查找的剪枝原理

BST 性质保证：key < root.key 时目标只可能在左子树，key > root.key 时只可能在右子树。每次比较排除一半子树，类似二分查找。

查找 key=5:
        8
       / \
      3   10    cmp(5,8)<0 → 左
     / \    \
    1   6    14   cmp(5,3)>0 → 右
       / \       cmp(5,6)<0 → 左
      4   7      cmp(5,4)>0 → 右
                  cmp(5,6)... 找到 6? 不, 5 应在 4 右子树

查找路径长度 = 树高。平衡树 O(log n)，退化树 O(n)。

BST 查找 vs 有序数组 bsearch

维度 BST 查找 bsearch
复杂度 O(log n) O(log n)
内存 节点分散 连续数组
cache 差（节点跨页） 好（连续访问）
指针追逐 是（每节点一次） 否（数组索引）
插入 O(log n) O(n)（搬移）
删除 O(log n) O(n)
静态数据 次选 首选
动态数据 首选 次选

BST 查找的指针追逐（pointer chasing）是性能瓶颈——每节点访问可能 cache miss。有序数组 bsearch 连续访问，prefetcher 友好，实际比 BST 快 2-3x（同数据量）。

HFT 查找选型

场景 选型 理由
合约代码表（静态） 有序数组 + bsearch 启动加载后不变，bsearch cache 友好
会话表（动态） 哈希表 O(1) 精确查找，连接/断开频繁
订单簿价格档位 BST 或专用结构 需范围查询 + 动态插入/删除
订单 ID 查找 哈希表 O(1) 精确查找
历史回放按 seq 有序数组 + bsearch 历史文件排序后只读

HFT 微秒级 ID 检索：哈希表 > bsearch > BST。BST 的指针追逐在纳秒级延迟场景是负担。

查找的变体

lower_bound / upper_bound

/* 第一个 >= key 的节点 */
TreeNode *tree_lower_bound(TreeNode *root, const void *key, cmp_fn cmp)
{
    TreeNode *result = NULL;
    while (root) {
        int c = cmp(root->key, key);
        if (c >= 0) {
            result = root;   /* 候选 */
            root = root->left;   /* 尝试找更小的 */
        } else {
            root = root->right;
        }
    }
    return result;
}

C++ std::lower_bound/std::upper_bound 的 BST 版本。订单簿"找最优买价"就是 lower_bound。

范围查找

void tree_range_find(TreeNode *root, const void *low, const void *high,
                     cmp_fn cmp, void (*handler)(TreeNode *))
{
    if (!root) return;
    int cl = cmp(root->key, low);
    int ch = cmp(root->key, high);
    if (cl > 0) tree_range_find(root->left, low, high, cmp, handler);
    if (cl >= 0 && ch <= 0) handler(root);
    if (ch < 0) tree_range_find(root->right, low, high, cmp, handler);
}

O(log n + k)，k 是结果数。哈希表无法做范围查找，这是 BST 的核心优势。

最值

TreeNode *tree_min(TreeNode *root)
{
    while (root->left) root = root->left;   /* 最左节点 */
    return root;
}

TreeNode *tree_max(TreeNode *root)
{
    while (root->right) root = root->right;  /* 最右节点 */
    return root;
}

订单簿取最优买价（最高）= bid tree 的 max，取最优卖价（最低）= ask tree 的 min。O(log n) 或 O(1)（若维护指针）。

查找未找到的处理

tree_find 返回 NULL 表示未找到。调用者必须检查：

TreeNode *node = tree_find(book->levels, &price, cmp_price);
if (!node) {
    /* 价位不存在, 创建新价位 */
    node = create_price_level(price);
    book->levels = tree_insert(book->levels, node, cmp_price);
}

不检查直接访问 node->payload 是空指针解引用，UB。

查找与并发的只读安全

只读查找在"无插入/删除"的前提下可并发——多个线程同时查找不互相干扰。但若有线程在插入/删除，查找可能读到中间状态（指针半改完）。HFT 订单簿用读写锁或单线程独占。

HFT 关联

  • 合约表查找：有序数组 + bsearch，启动加载后只读
  • 会话表查找：哈希表 O(1)，连接/断开频繁
  • 订单簿价格档位查找：BST lower_bound 找最优价，范围查找做市场深度
  • 订单 ID 查找：哈希表，撤单时 O(1) 定位
  • 历史回放：按 seq 的有序数组 + bsearch 跳读
  • 最值查询：订单簿取最优买/卖价，维护指针可 O(1)
  • BST vs bsearch：静态选 bsearch（cache 友好），动态选 BST
  • 范围查询：BST 独有优势，订单簿深度查询用
  • 单线程独占：订单簿查找通常单线程，避免读写锁开销

17.4

.4 树的遍历

本节讲什么

BST 的三种深度优先遍历（前序/中序/后序）和层序遍历（BFS），以及用回调函数做 foreach 处理。本节重点讲三种遍历的语义、应用场景、递归与迭代的实现，以及 HFT 订单簿快照、destroy 清理的遍历选择。

要点

三种深度优先遍历

/* 前序: 根 → 左 → 右 */
void tree_preorder(TreeNode *root, void (*visit)(TreeNode *))
{
    if (!root) return;
    visit(root);
    tree_preorder(root->left, visit);
    tree_preorder(root->right, visit);
}

/* 中序: 左 → 根 → 右 */
void tree_inorder(TreeNode *root, void (*visit)(TreeNode *))
{
    if (!root) return;
    tree_inorder(root->left, visit);
    visit(root);
    tree_inorder(root->right, visit);
}

/* 后序: 左 → 右 → 根 */
void tree_postorder(TreeNode *root, void (*visit)(TreeNode *))
{
    if (!root) return;
    tree_postorder(root->left, visit);
    tree_postorder(root->right, visit);
    visit(root);
}

三种遍历的语义

对 BST：

        4
       / \
      2   6
     / \ / \
    1  3 5  7
遍历 顺序 用途
前序 4,2,1,3,6,5,7 复制树、序列化
中序 1,2,3,4,5,6,7 有序输出（BST 特性）
后序 1,3,2,5,7,6,4 destroy 清理（先子后根）

中序遍历 BST 得到有序序列——这是 BST 最有用的性质。前序用于序列化（先存根再存子树，反序列化时先读根）。后序用于 destroy（先释放子节点再释放根，避免访问已释放内存）。

中序遍历的有序性

BST 中序遍历天然有序，无需排序：

void export_sorted(TreeNode *root, void (*emit)(void *))
{
    if (!root) return;
    export_sorted(root->left, emit);
    emit(root->key);   /* 按 cmp 升序输出 */
    export_sorted(root->right, emit);
}

这是 BST 相比哈希表的核心优势——有序遍历 O(n) 输出全部，哈希表需额外排序。

遍历的回调模式

void tree_foreach(TreeNode *root, void (*handler)(void *key, void *arg), void *arg)
{
    if (!root) return;
    tree_foreach(root->left, handler, arg);
    handler(root->key, arg);   /* 用户回调 + 上下文 */
    tree_foreach(root->right, handler, arg);
}

handler 接受 key 和 void *arg 上下文。arg 是闭包模拟——C 没有闭包，用 void* 传递上下文。这是 C 语言 ADT 遍历的标准模式。

中序遍历的迭代实现

void tree_inorder_iter(TreeNode *root, void (*visit)(TreeNode *))
{
    Stack *s = stack_create(256);
    TreeNode *cur = root;

    while (cur || !stack_empty(s)) {
        /* 一路向左, 全部入栈 */
        while (cur) {
            stack_push(s, cur);
            cur = cur->left;
        }
        /* 弹出并访问 */
        cur = stack_pop(s);
        visit(cur);
        /* 转向右子树 */
        cur = cur->right;
    }
    stack_destroy(&s, NULL);
}

迭代中序用显式栈模拟递归。避免递归栈开销，栈深度可控（最坏 O(h)，h 是树高）。

Morris 遍历（O(1) 空间）

void tree_morris_inorder(TreeNode *root, void (*visit)(TreeNode *))
{
    TreeNode *cur = root;
    while (cur) {
        if (!cur->left) {
            visit(cur);
            cur = cur->right;
        } else {
            /* 找前驱, 建临时链接 */
            TreeNode *pred = cur->left;
            while (pred->right && pred->right != cur) pred = pred->right;

            if (!pred->right) {
                pred->right = cur;   /* 临时链接 */
                cur = cur->left;
            } else {
                pred->right = NULL;  /* 恢复 */
                visit(cur);
                cur = cur->right;
            }
        }
    }
}

Morris 遍历用临时修改树结构（前驱的 right 指针）实现 O(1) 空间中序遍历。遍历后树恢复原状。理论价值高，实际因修改树 + 常数大少用。

层序遍历（BFS）

void tree_levelorder(TreeNode *root, void (*visit)(TreeNode *))
{
    if (!root) return;
    Queue *q = queue_create(256);
    queue_enqueue(q, root);

    while (!queue_empty(q)) {
        TreeNode *n = queue_dequeue(q);
        visit(n);
        if (n->left) queue_enqueue(q, n->left);
        if (n->right) queue_enqueue(q, n->right);
    }
    queue_destroy(&q, NULL);
}

用队列实现层序——每层从左到右访问。用于按深度处理（如打印树形结构）。

destroy 的后序遍历

void tree_destroy(TreeNode **root, void (*free_cb)(void *))
{
    if (!root || !*root) return;
    tree_destroy(&(*root)->left, free_cb);    /* 先释放左子树 */
    tree_destroy(&(*root)->right, free_cb);   /* 再释放右子树 */
    if (free_cb) free_cb((*root)->key);       /* 释放载荷 */
    free(*root);                               /* 最后释放节点 */
    *root = NULL;
}

后序是 destroy 的唯一正确顺序——先释放子节点再释放根。若先释放根，子节点指针丢失，无法继续遍历，内存泄漏。

遍历与并发的只读安全

只读遍历在"无插入/删除"时多线程安全。但遍历期间若有线程修改树，可能读到中间状态或访问已 free 节点。HFT 订单簿快照通常：

  • 单线程独占遍历
  • 或用读写锁（遍历持读锁，修改持写锁）
  • 或用 RCU（读无锁，写等读者完成）

遍历的中断

int tree_foreach_stop(TreeNode *root, int (*pred)(void *, void *), void *arg)
{
    if (!root) return 1;   /* 继续 */
    if (tree_foreach_stop(root->left, pred, arg) == 0) return 0;
    if (pred(root->key, arg) == 0) return 0;   /* 用户要求停止 */
    return tree_foreach_stop(root->right, pred, arg);
}

回调返回 0 表示停止遍历。用于"找到第一个满足条件的就停"等场景。

范围遍历

void tree_range_foreach(TreeNode *root, const void *low, const void *high,
                        cmp_fn cmp, void (*handler)(void *))
{
    if (!root) return;
    int cl = cmp(root->key, low);
    int ch = cmp(root->key, high);
    if (cl > 0) tree_range_foreach(root->left, low, high, cmp, handler);
    if (cl >= 0 && ch <= 0) handler(root->key);
    if (ch < 0) tree_range_foreach(root->right, low, high, cmp, handler);
}

利用 BST 性质剪枝——不在范围内的子树不遍历。O(log n + k)，k 是结果数。

HFT 关联

  • 订单簿快照：中序遍历导出全量订单簿到文件，重启恢复
  • destroy 清理：后序遍历释放订单簿所有价位节点 + 挂单
  • 市场深度查询：范围遍历输出某价格区间所有挂单
  • 批量通知：中序遍历所有会话，发送行情广播
  • 序列化：前序遍历存树结构，反序列化时按前序重建
  • 回调 + void* arg：C 遍历的闭包模拟，DPDK rte_hash_iterate 同模式
  • 迭代版避免爆栈：深树递归遍历可能爆栈，数据面用迭代版
  • RCU 读无锁：订单簿遍历用 RCU，读不加锁，写等读者完成

// 前序：根 -> 左 -> 右

参考答案

前序：先访问根，再递归左右。中序：先递归左，再访问根，再递归右——BST 中序遍历得到有序序列。后序：先递归左右，最后访问根——常用于释放树（先释放子节点再释放根）。选择哪种取决于应用：表达式树求值用后序，复制树用前序，排序用中序。

17.5

实现的改进

本节讲什么

ADT 的泛型化与工程化：void* 通用载荷、三大回调（cmp/handler/free_cb）统一接口、命名前缀防冲突、条件编译切换底层实现。这是 ch17 全章的收尾——把前几节的栈/队列/树抽象成可复用的通用容器库，这是从"会写数据结构"到"能工程化交付"的关键一步。

要点

从专用到通用的进化

前面几节的栈/队列/树都是"专用"的——某种特定载荷、特定比较逻辑。工程上需要"通用"容器：

  • 一套链表/队列/哈希管所有类型载荷
  • 载荷用 void* 抽象
  • 类型特定逻辑（比较、哈希、释放）用回调注入

这是 C 语言泛型的核心模式——void* + 回调函数。C++ 用模板，C 用 void* + 函数指针。

三大回调

回调 签名 用途
cmp int (*)(const void *, const void *) 查找、删除、排序
handler void (*)(void *) 或 void (*)(void *, void *arg) 遍历处理
free_cb void (*)(void *) destroy 释放载荷
hash（哈希表） unsigned long (*)(const void *) 哈希函数
dup（可选） void *(*)(void *) 深拷贝载荷

回调是 C 语言 ADT 的"策略注入"机制——容器逻辑固定，类型特定行为通过回调变化。

通用链表 API（回顾）

/* list.h */
typedef struct List List;

List   *list_create(void);
int     list_push_front(List *l, void *data);
int     list_push_back(List *l, void *data);
void   *list_pop_front(List *l);
void   *list_pop_back(List *l);
void   *list_find(List *l, const void *key, cmp_fn cmp);
int     list_remove(List *l, const void *key, cmp_fn cmp);
size_t  list_len(const List *l);
void    list_foreach(List *l, handler_fn h, void *arg);
void    list_destroy(List **l, free_cb_fn free_cb);

一套 API 管任意类型载荷——行情、订单、设备、会话，全用同一套容器。

通用哈希表 API

typedef struct Hash Hash;

Hash  *hash_create(size_t nbuckets, hash_fn hash, cmp_fn cmp);
int    hash_insert(Hash *h, void *key, void *value);
void  *hash_find(Hash *h, const void *key);
int    hash_remove(Hash *h, const void *key);
void   hash_foreach(Hash *h, handler_fn h, void *arg);
void   hash_destroy(Hash **h, free_cb_fn free_key, free_cb_fn free_val);

hash_create 接受 hash_fn 和 cmp_fn——不同类型用不同哈希和比较函数，容器逻辑统一。

条件编译切换底层

/* queue.h */
#ifdef HFT_USE_RING_QUEUE
#include "queue_ring.h"   /* 环形数组实现 */
#else
#include "queue_list.h"   /* 链表实现 */

编译时用 -DHFT_USE_RING_QUEUE=1 切换数据面/控制面实现，业务代码零修改。这是 ADT 接口稳定的最大收益。

运行时切换（更高级）

typedef struct QueueOps {
    Queue *(*create)(size_t cap);
    int    (*enqueue)(Queue *, void *);
    void  *(*dequeue)(Queue *);
    void   (*destroy)(Queue **);
} QueueOps;

static const QueueOps ring_ops = {
    ring_create, ring_enqueue, ring_dequeue, ring_destroy
};
static const QueueOps list_ops = {
    list_create, list_enqueue, list_dequeue, list_destroy
};

/* 运行时按配置选 */
const QueueOps *ops = use_ring ? &ring_ops : &list_ops;
Queue *q = ops->create(cap);
ops->enqueue(q, data);

运行时切换通过函数指针表（vtable）。代价是每次操作间接调用（无法内联）。HFT 数据面倾向编译时切换（零间接），控制面可接受运行时切换。

泛型化的代价

void* + 回调的代价：

  1. 类型安全丧失：void* 接受任何指针，类型错误编译不报错
  2. 间接访问：每次操作多一次 void* 解引用
  3. 回调开销：函数指针调用无法内联
  4. 载荷所有权复杂：容器不知载荷类型，释放策略全靠回调

C++ 模板解决 1-3（编译期生成类型特定代码，内联优化），但 C 没有。HFT 数据面有时手写专用容器（内嵌 key、内联 cmp）换性能。

专用 vs 通用的权衡

维度 专用容器 通用容器（void* + 回调）
类型安全 强 弱（void* 无类型）
性能 最优（内联） 有回调开销
复用性 差（每类型一套） 好（一套管所有）
开发效率 低 高
HFT 数据面 首选 慎用
HFT 控制面 次选 首选

HFT 数据面订单簿用专用容器（内嵌价格 key、内联 cmp、连续内存），控制面用通用容器（void* + 回调）。

宏生成类型特定容器

C 的一种"伪泛型"——用宏生成类型特定的容器代码：

/* 定义一个类型特定的链表 */
#define DEFINE_LIST(NAME, TYPE) \
    typedef struct NAME##_Node { TYPE data; struct NAME##_Node *next; } NAME##_Node; \
    typedef struct NAME { NAME##_Node *head; size_t len; } NAME; \
    static inline NAME *NAME##_create(void) { return calloc(1, sizeof(NAME)); } \
    static inline void NAME##_push_front(NAME *l, TYPE d) { \
        NAME##_Node *n = malloc(sizeof *n); n->data = d; n->next = l->head; l->head = n; l->len++; \
    } \
    /* ... */

/* 生成 OrderList 和 QuoteList */
DEFINE_LIST(OrderList, Order*)
DEFINE_LIST(QuoteList, Quote*)

类型安全 + 内联优化，但代码膨胀、调试难。Linux 内核 list_head + container_of 是另一种思路——侵入式链表避免 void* 间接。

17.5

.1 拥有超过一种的类型

本节讲什么

void* 通用载荷的完整设计：三大回调的语义、通用链表/哈希表的完整 API、链地址法哈希的实现要点、与内核 list_head 侵入式设计的对比、条件编译切换底层。这是 ADT 泛型化的核心——一套容器管所有类型。

要点

三大回调详解

cmp：比较函数

int cmp(const void *a, const void *b);
  • 返回 < 0：a < b
  • 返回 0：a == b
  • 返回 > 0：a > b

用于 BST 插入/查找/删除、qsort、bsearch、list_find、hash 链冲突时比较。

常见错误：

  • 整数减法溢出（return *(int*)a - *(int*)b）
  • 浮点 NaN 破坏传递性
  • 不满足严格弱序（<= 而非 <）

handler：遍历回调

void handler(void *data, void *arg);
  • data：当前元素载荷
  • arg：上下文（闭包模拟）

用于 foreach 批量处理、导出、过滤。arg 让回调能访问外部状态（如累加器、输出缓冲）。

free_cb：释放回调

void free_cb(void *data);

destroy 时对每个载荷调用。传 free 释放堆内存，传 mempool_put 归还池，传 NULL 不释放。

通用链表完整 API

/* list.h */
typedef struct List List;
typedef int  (*cmp_fn)(const void *, const void *);
typedef void (*handler_fn)(void *, void *);
typedef void (*free_cb_fn)(void *);

List   *list_create(void);
int     list_push_front(List *l, void *data);
int     list_push_back(List *l, void *data);
void   *list_pop_front(List *l);
void   *list_pop_back(List *l);
void   *list_front(const List *l);
void   *list_back(const List *l);
void   *list_find(const List *l, const void *key, cmp_fn cmp);
int     list_remove(List *l, const void *key, cmp_fn cmp);
size_t  list_len(const List *l);
int     list_empty(const List *l);
void    list_foreach(const List *l, handler_fn h, void *arg);
void    list_destroy(List **l, free_cb_fn free_cb);

一套 API 管任意类型——行情、订单、设备、会话，全用同一套容器。

链地址法哈希表

struct Hash {
    List **buckets;      /* 每个桶是一条链表 */
    size_t nbuckets;
    hash_fn hash;        /* 哈希函数 */
    cmp_fn  cmp;         /* 键比较 */
    size_t len;          /* 总元素数 */
};

Hash *hash_create(size_t nbuckets, hash_fn hash, cmp_fn cmp)
{
    Hash *h = calloc(1, sizeof *h);
    h->buckets = calloc(nbuckets, sizeof(List *));
    h->nbuckets = nbuckets;
    h->hash = hash;
    h->cmp = cmp;
    for (size_t i = 0; i < nbuckets; i++)
        h->buckets[i] = list_create();
    return h;
}

int hash_insert(Hash *h, void *key, void *value)
{
    unsigned long idx = h->hash(key) % h->nbuckets;
    /* 检查是否已存在 (链上查找) */
    if (list_find(h->buckets[idx], key, h->cmp)) return -1;
    /* 插入链头 */
    list_push_front(h->buckets[idx], make_entry(key, value));
    h->len++;
    return 0;
}

void *hash_find(Hash *h, const void *key)
{
    unsigned long idx = h->hash(key) % h->nbuckets;
    Entry *e = list_find(h->buckets[idx], key, h->cmp);
    return e ? e->value : NULL;
}

链地址法：每桶一条链表，冲突元素挂链。简单、稳定、负载因子可超 1。

哈希函数选择

函数 特点 适用
除留余数 key % prime 简单 整数 key
FNV-1a 字节串通用，质量好 字符串 key
MurmurHash3 速度+质量均衡 通用
CityHash/xxHash 极快，Google 出品 大数据
Identity key key 本身是好的哈希 已均匀分布

HFT 合约代码是整数，用除留余数够用。会话 ID 若是字符串，用 FNV-1a。

负载因子与扩容

负载因子 = len / nbuckets
  • 负载因子 > 0.75 → 链变长，查找退化 → 扩容（rehash）
  • 扩容：分配 2x 桶，所有元素重新哈希搬到新桶
  • rehash 是 O(n) 操作，瞬间延迟尖峰

HFT 数据面哈希表预分配足够大，避免运行时 rehash。控制面可接受 rehash。

哈希表 vs BST vs 有序数组

结构 查找 插入 范围查询 有序遍历 内存 HFT 用途
哈希表 O(1) 均摊 O(1) 均摊 不支持 不支持 桶+链 合约/会话表
BST O(log n) O(log n) 支持 支持 节点分散 订单簿价位
有序数组 O(log n) O(n) 支持 支持 连续 静态表

HFT 微秒级精确查找用哈希表，需要范围/有序用 BST 或有序数组。

内核 list_head 侵入式设计对比

通用容器的 void* 包裹模式：

struct Node { void *payload; struct Node *next; };
/* 载荷被 Node 包裹, 通过 payload 指针访问 */

内核 list_head 侵入式模式：

struct list_head { struct list_head *next, *prev; };

struct Order {
    uint64_t id;
    int64_t price;
    struct list_head node;   /* 嵌入链表节点 */
};

/* 通过 container_of 从 node 反向定位 Order */
#define container_of(ptr, type, member) \
    ((type *)((char *)(ptr) - offsetof(type, member)))

list_for_each(pos, &order_list) {
    Order *o = container_of(pos, Order, node);
    process(o);
}

侵入式优势：

  • 无 void* 间接，载荷直接内嵌
  • 一个结构可挂多个链表（多个 list_head 成员）
  • 零额外内存开销（节点就是结构的一部分）
  • 类型安全（container_of 编译期类型检查）

侵入式劣势：

  • 载荷必须侵入式修改（加 list_head 成员）
  • 不能用同一载荷挂不同类型链表
  • C++ 不友好（侵入式破坏封装）

HFT 订单簿挂单链表常用侵入式（struct Order 内嵌 list_head），通用容器用 void*。

private_data：void* 闭包

内核回调常带 void *private_data（或 priv）：

void callback(void *data, void *private_data)
{
    MyContext *ctx = private_data;
    /* 用 ctx 访问闭包状态 */
}

这是 C 语言的闭包模拟——void* 携带上下文，回调内转型使用。DPDK rte_mempool 的 ctor/dtor 钩子、Linux 内核的 file_operations 都用此模式。

17.5

.2 名字冲突

本节讲什么

ADT 库的命名空间隔离：模块前缀、static 内部函数、不透明类型、头文件 guard。C 语言没有命名空间（C++ 的 namespace），全局符号必须用前缀防冲突。本节重点讲大型工程的命名规范、符号可见性控制、以及 DPDK/内核的命名惯例。

要点

C 的命名空间问题

C 所有全局符号（函数、全局变量、typedef）在链接时共享一个扁平命名空间。两个 .c 定义同名函数 → 链接错误。两个头文件定义同名 typedef → 编译错误。

/* a.c */
void push(int x) { ... }   /* a 模块的 push */

/* b.c */
void push(int x) { ... }   /* b 模块的 push */

/* 链接: multiple definition of `push' */

C++ 用 namespace 解决，C 只能靠前缀。

模块前缀规范

/* hft_queue.h */
typedef struct hft_queue hft_queue_t;

hft_queue_t *hft_queue_create(size_t cap);
int          hft_queue_enqueue(hft_queue_t *q, void *data);
void        *hft_queue_dequeue(hft_queue_t *q);
void         hft_queue_destroy(hft_queue_t **q);

前缀 hft_queue_ 让符号全局唯一。命名规范：

库 前缀 例子
DPDK rte_ rte_ring_enqueue
Linux 内核 linux_/__ list_for_each
glibc __/无 malloc
OpenSSL SSL_/BIO_ SSL_new
自研 HFT hft_ hft_queue_create

模块内函数也加模块名前缀：hft_queue_create、hft_list_push、hft_hash_find。

static：文件作用域隔离

/* queue.c */
static struct Node *alloc_node(void *data)
{
    struct Node *n = malloc(sizeof *n);
    if (n) { n->payload = data; n->next = NULL; }
    return n;
}

static void free_node(struct Node *n)
{
    free(n);
}

static 修饰函数 → 只在本 .c 可见，不导出到全局符号表。好处：

  • 内部辅助函数不占全局命名空间
  • 编译器能内联优化（跨 .c 边界不能内联）
  • 链接时不会被其他 .c 的同名 static 函数冲突

static 修饰全局变量 → 文件作用域，类似效果。

不透明类型防成员访问

/* queue.h */
typedef struct hft_queue hft_queue_t;   /* 只有前向声明 */

/* queue.c */
struct hft_queue {
    struct Node *head, *tail;
    size_t len;
};

结构体定义藏在 .c，使用者只能通过 hft_queue_t * 句柄操作，无法直接访问 q->head。好处：

  • 强制封装，防止误用
  • 内部结构可重构不改 ABI
  • 编译依赖最小化

头文件 guard

/* hft_queue.h */
#ifndef HFT_QUEUE_H
#define HFT_QUEUE_H

/* ... 内容 ... */

#endif /* HFT_QUEUE_H */

或 #pragma once：

#pragma once

/* ... 内容 ... */

防止头文件被重复包含。详见 ch14。

命名规范约定

函数命名

<模块前缀>_<动词>_<对象>
  • hft_queue_create ✓
  • hft_queue_enqueue ✓
  • queue_create ✗（太短，易冲突）
  • create ✗（绝对冲突）

类型命名

<模块前缀>_<名词>_t
  • hft_queue_t ✓
  • hft_order_t ✓
  • queue_t ✗（POSIX 已有 queue 相关）

宏命名

全大写 + 下划线：

  • HFT_MAX_ORDERS ✓
  • HFT_QUEUE_DEFAULT_CAP ✓
  • hft_max_orders ✗（宏应全大写）

全局变量

g_ 前缀 + 模块前缀：

  • g_hft_stats ✓
  • g_hft_log_fp ✓

或单例风格：

  • hft_stats（无 g_，靠模块前缀）

避免短名

/* 禁用 */
int push(int);        /* 与任何其他 push 冲突 */

int top(void);

/* 改用 */

短名在大型工程必然冲突。即使当前不冲突，未来引入新库也可能撞。

符号可见性控制（GCC 扩展）

/* 默认所有全局符号可见, 链接时全局 */
__attribute__((visibility("hidden"))) int internal_func(void);
__attribute__((visibility("default")))  int api_func(void);
  • hidden：符号不导出到动态符号表，.so 外不可见
  • default：正常导出

Linux 编译 .so 时用 -fvisibility=hidden 默认隐藏，只显式导出 API。减少符号污染 + 加载速度 + 优化空间。

头文件自包含

每个头文件应自包含——包含它需要的所有依赖头，不依赖使用者预先包含其他头：

#define HFT_QUEUE_H

/* ... */

#endif

不依赖"使用者必须先 #include <stddef.h>"。这让头文件可被任意顺序包含。

/* hft_order.h */
typedef struct hft_order hft_order_t;   /* 前向声明 */

/* 不 include hft_queue.h, 只用指针 */
