16.1

整型函数

本节讲什么

<stdlib.h> 里与整数相关的工具：字符串转整数的 atoi 族与 strtol 族、伪随机数 rand/srand、排序与查找 qsort/bsearch、简单算术 abs/div。这是配置解析、订单排序检索的基础工具集，也是 C 程序员最容易写出"看似能用实际有坑"代码的地方——atoi 静默失败、rand 全局状态、qsort 比较函数溢出，每一个都是生产事故源。

要点

字符串转整数：atoi 禁用，strtol 必选

int atoi(const char *nptr);           /* 静默失败, 返回 0 */
long atol(const char *nptr);
long long atoll(const char *nptr);

long strtol(const char *nptr, char **endptr, int base);
long long strtoll(const char *nptr, char **endptr, int base);
unsigned long strtoul(...);
unsigned long long strtoull(...);

atoi 的三大罪状：

  1. 无错误检测：atoi("abc") 返回 0，与 atoi("0") 无法区分
  2. 无溢出处理：atoi("99999999999999") 行为未定义，可能返回任意值
  3. 无尾指针：无法知道解析到哪停，atoi("123abc") 返回 123 但不告诉你后面有垃圾

strtol 的完整错误检测：

char *end;
errno = 0;
long long v = strtoll(s, &end, 10);
if (end == s) {
    /* 没有任何数字被解析 */
} else if (*end != '\0') {
    /* 解析了部分, 后面有非数字字符 */
}
if (errno == ERANGE) {
    /* 溢出, v 被钳位到 LLONG_MAX 或 LLONG_MIN */
}
输入 atoi strtoll endptr 指向
"123" 123 123 '\0'
"123abc" 123 123 'a'
"abc" 0 0 'a'（== s）
"99999999999999999999" UB LLONG_MAX 末尾，errno=ERANGE
" -42" -42 -42 '\0'（跳前导空白）
"0x1A" 0 0（base=10）或 26（base=16） 取决于 base

base 参数与自动检测

strtol(s, &end, 0) 自动根据前缀判断进制：0x 开头按 16 进制，0 开头按 8 进制，其余 10 进制。HFT 配置文件一般显式 base=10 避免 "08" 被当 8 进制报错。

随机数：rand 的全局状态陷阱

srand((unsigned)time(NULL));
int r = rand();   /* [0, RAND_MAX], 典型 32767 */

问题：

  1. 全局状态：rand 内部维护全局种子，多线程调用需加锁，争锁成为瓶颈
  2. 周期短质量差：rand 常用线性同余，周期 2^31，统计性质差，不适合 Monte Carlo
  3. 可预测：知道种子就能复现整个序列，加密不安全
  4. RAND_MAX 小：16 位平台只有 32767，32 位平台通常 2^31-1

替代方案：

接口 特点 适用
rand_r(unsigned *seed) 可重入，POSIX 多线程压测
drand48_r / nrand48 48 位 LCG，质量略好 POSIX 系统
arc4random / getrandom 内核熵源，加密安全 安全场景
DPDK rte_rand 无锁，每核种子，性能高 HFT 数据面
xorshift / PCG 用户态实现，周期长质量好 回测/模拟

HFT 压测随机订单生成用每线程独立种子的 xorshift128+，避免 rand 锁。

qsort：通用排序与比较函数陷阱

void qsort(void *base, size_t nmemb, size_t size,
           int (*compar)(const void *, const void *));

比较函数的三大坑：

1. 直接减法溢出

/* 错误: 大数相减溢出 */
int cmp(const void *a, const void *b) {
    return *(int*)a - *(int*)b;   /* INT_MIN - INT_MAX 溢出 UB */
}

正确写法：

int cmp(const void *a, const void *b) {
    int x = *(const int *)a, y = *(const int *)b;
    return (x > y) - (x < y);   /* 无溢出, 返回 -1/0/1 */
}

2. 不满足严格弱序

比较函数必须满足：a < b 和 b < a 不能同时为真，a == a 必须返回 0。如果用 <= 或 >= 会破坏 qsort 的内部不变式，导致越界或死循环。

3. 类型双关严格别名

*(const uint64_t *)a 在 a 实际指向 uint32_t 数组时是 UB。qsort 回调里务必保证类型一致，或用 memcpy 安全转换。

qsort 的性能特征

  • 标准没规定算法，glibc 用 mergesort+insertion sort 混合，平均 O(n log n)
  • 比较函数通过函数指针调用，无法内联，每次比较有间接调用开销
  • void* + size 元素大小，swap 时按字节拷贝，无法用类型特化的 memcpy
  • 海量数据（百万级）HFT 排序常手写专用排序：定长元素 + 内联比较 + 类型特化 swap，比 qsort 快 2-5x

bsearch：二分查找

void *bsearch(const void *key, const void *base, size_t nmemb, size_t size,
              int (*compar)(const void *, const void *));
  • 数组必须已排序
  • 返回指向匹配元素的指针，未找到返回 NULL
  • 多个匹配元素时返回哪个未指定
  • 比较函数必须与排序时一致

abs/div 等辅助

abs(INT_MIN);   /* UB! INT_MIN 的绝对值超出 int 范围 */
labs(LLONG_MIN); /* 同样 UB */
div_t d = div(17, 5);   /* d.quot=3, d.rem=2, 一次操作同时取商和余 */

div/ldiv/lldiv 在一条指令同时取商和余，编译器能优化成单条 idiv，比分开写 / 和 % 快。

HFT 关联

  • 配置解析：gateway.conf 里 port=8125 用 strtoll 解析，errno + endptr 双重校验
  • 订单 ID 排序：回测按 seq 排序历史 tick，qsort 通用但慢，百万级用手写 radix sort 或 std::sort
  • 订单簿查找：按价格档位二分查找，bsearch 或自写 lower_bound
  • 随机订单生成：压测每线程独立 xorshift 种子，避免 rand 全局锁
  • 时间戳取模：纳秒时间戳对齐到微秒用 div，编译器优化成单条指令
  • 价格溢出检测：strtoll 解析价格字符串时检查 ERANGE，防止配置错误导致天量订单
  • DPDK rte_rand：数据面随机退避、负载均衡哈希扰动用无锁 rte_rand

  • ch11 malloc 与 rand 同为 <stdlib.h>，全局状态与锁的话题相通

代码自测

题目 1： 以下代码中 abs 的返回值有什么问题？

int x = INT_MIN;
int y = abs(x);
printf("%d\n", y);
参考答案

未定义行为。INT_MIN（如 -2147483648）的绝对值 2147483648 超出了 int 的范围（最大 2147483647）。abs(INT_MIN) 的结果是实现定义的——通常返回 INT_MIN 本身或溢出。正确做法：用 long long 类型或 labs/llabs，或在调用前检查。

16.2

浮点型函数

本节讲什么

<math.h> 的浮点运算：基础运算（sqrt/pow/exp/log）、取整（floor/ceil/round/trunc）、绝对值（fabs）、三角函数、特殊值处理（isnan/isinf/fpclassify）。HFT 场景里浮点主要用于回测统计与风控计算，绝不能用来存储订单价格或数量——这是铁律。

要点

函数分类速查

类别 函数 用途
幂对数 sqrt/cbrt/pow/exp/log/log2/log10 回测统计
取整 floor/ceil/round/trunc/rint 价量边界
绝对值 fabs/fabsf/fabsl 盈亏统计
三角 sin/cos/tan/atan2 极少用（可能期权定价）
特殊值 isnan/isinf/fpclassify/signbit 防御性检查
误差函数 erf/erfc/tgamma/lgamma 统计分布
浮点控制 fegetround/fesetround 舍入模式控制

float/double/long double 三精度

float sqrtf(float x);
double sqrt(double x);
long double sqrtl(long double x);
  • f 后缀：单精度，32 位，精度约 7 位有效数字
  • 无后缀：双精度，64 位，精度约 15-16 位
  • l 后缀：扩展精度，x86 80 位 / 其他平台可能等同 double

HFT 回测默认 double，单精度累积误差不可接受。long double 在 x86-64 是 80 位扩展，精度更高但慢且跨平台不一致。

取整函数的细微差异

floor(2.7)   /* 2.0, 向负无穷取整 */
ceil(2.7)    /* 3.0, 向正无穷取整 */
round(2.7)   /* 3.0, 四舍五入到最近整数 */
trunc(2.7)   /* 2.0, 向零取整 */
rint(2.7)    /* 3.0, 按当前舍入模式, 默认 round-to-nearest-even */
输入 floor ceil round trunc rint(默认)
2.7 2 3 3 2 3
-2.7 -3 -2 -3 -2 -3
0.5 0 1 1 0 0（banker's）
2.5 2 3 3 2 2（banker's）

rint 默认 round-to-nearest-even（银行家舍入），统计场景避免累积偏差。HFT 价量取整用 floor/ceil 明确方向，不用 round 避免 0.5 歧义。

NaN 与 Inf 的传播

double x = 0.0 / 0.0;   /* NaN */
double y = 1.0 / 0.0;   /* +Inf */
double z = -1.0 / 0.0;  /* -Inf */
  • NaN 参与任何运算结果都是 NaN，且 NaN != NaN（唯一不等于自己的值）
  • Inf 参与运算遵循极限规则：Inf + 1 = Inf，Inf - Inf = NaN
  • 检测：isnan(x) / isinf(x) / fpclassify(x)
double pnl = compute_pnl(...);
if (isnan(pnl) || isinf(pnl)) {
    /* 统计出错, 丢弃这条记录 */
}

HFT 回测每条 tick 计算后必须检查 NaN/Inf，否则一个坏值会污染整个统计。

errno 与数学函数

#include <errno.h>
errno = 0;
double r = sqrt(-1.0);   /* 返回 NaN, errno = EDOM */
if (errno == EDOM) { /* 域错误 */ }

errno = 0;
double r = pow(2.0, 1e308);  /* 返回 HUGE_VAL, errno = ERANGE */
if (errno == ERANGE) { /* 溢出 */ }

部分数学函数通过 errno 报告域错误（EDOM）和溢出（ERANGE）。检查 errno 是检测异常的可靠方式，但要注意 errno 是线程局部的且可能被中间调用覆盖。

浮点异常标志

#include <fenv.h>
feclearexcept(FE_ALL_EXCEPT);
double r = x / y;
if (fetestexcept(FE_DIVBYZERO)) { /* 除零发生 */ }
if (fetestexcept(FE_OVERFLOW)) { /* 溢出 */ }
if (fetestexcept(FE_INVALID)) { /* 非法操作, 如 sqrt(-1) */ }

<fenv.h> 提供细粒度的浮点异常标志，比 errno 更精确。但开启 -ftrapping-math 才能可靠捕获，默认编译器假设不抛异常。

HFT 价格存储铁律

订单价格和数量绝不能用浮点存储，必须用整数定点小数。

存储 精度 问题
float 7 位有效 0.1 + 0.2 = 0.3000000119...
double 15-16 位 累积万次仍有偏差
uint64_t 单位 0.0001 精确 3500000 = 350.0000，无误差
int64_t 单位 0.0001 精确 带符号，支持价差负数 
typedef int64_t price_t;   /* 单位 0.0001 元 */
price_t bid = 3500000;     /* 350.0000 元 */
price_t ask = 3500100;     /* 350.0100 元 */
price_t spread = ask - bid; /* 100 = 0.0100 元, 精确 */

浮点仅用于：回测统计（均值/方差/夏普）、风控指标（VaR/Greeks）、可视化，且每次运算后检查 NaN/Inf。

浮点可重复性陷阱

double a = 0.1 + 0.2;
double b = 0.3;
/* a == b? 可能不等, 也可能等, 取决于编译器优化和 FPU 模式 */
  • -ffast-math 会重排浮点运算，破坏结合律，结果不可重复
  • x87 80 位扩展精度与 SSE 64 位双精度结果不同
  • 多线程浮点累积顺序不同导致结果微差

回测要可重复必须：固定 -std=c11 -O2（不开 fast-math）、固定 -mfpmath=sse、单线程或确定性归约顺序。

HFT 关联

  • 价格存储：int64_t 定点，单位 0.0001，全链路无浮点
  • 数量存储：uint64_t 或 int64_t，单位手数或最小变动单位
  • 价差统计：double 计算均值/方差，每步检查 NaN/Inf
  • VaR/Greeks：期权定价用 exp/log/erf，结果检查有限性
  • 夏普比率：sqrt/pow 计算年化，注意 -ffast-math 破坏可重复性
  • 回测可重复性：固定编译选项、固定 FPU 模式、确定性归约
  • 浮点 SIMD：<immintrin.h> 的 AVX 指令批量算价差，但仅用于统计非订单存储
  • DPDK 数学：数据面几乎不用 <math.h>，所有计算预整理为定点整数运算

代码自测

题目 1： 以下代码输出什么？为什么？

double x = -3.7;
printf("%.1f\n", ceil(x));
printf("%.1f\n", floor(x));
printf("%.1f\n", round(x));
参考答案

输出 -3.0、-4.0、-4.0。ceil 向上取整（向正无穷方向）=-3.0。floor 向下取整（向负无穷方向）=-4.0。round 四舍五入（远离零方向）=-4.0（因为 -3.7 的小数部分 .7 >= 0.5，向远离零方向取整为 -4.0）。注意负数的取整方向。

16.3

日期和时间函数

本节讲什么

<time.h> 的时间接口：time 拿秒级墙钟、clock 拿 CPU 时间、gmtime/localtime/strftime 格式化、difftime 算差。POSIX 扩展的 clock_gettime/CLOCK_MONOTONIC 才是 HFT 纳秒级延迟测量的核心。本节重点讲清各时钟的语义差异、线程安全性、NTP 回拨陷阱，以及为什么 HFT 永远用 CLOCK_MONOTONIC 测延迟。

要点

时间 API 全景

API 精度 类型 线程安全 HFT 用途
time(time_t*) 秒 墙钟（CALENDAR） 是 日志时间戳
clock() 微秒级 CPU 时间（PROCESS） 是 函数微基准
clock_gettime(CLOCK_REALTIME) 纳秒 墙钟 是 偶发事件打点
clock_gettime(CLOCK_MONOTONIC) 纳秒 单调时钟 是 延迟测量主力
clock_gettime(CLOCK_MONOTONIC_RAW) 纳秒 硬件原始时钟 是 极致场景
clock_gettime(CLOCK_PROCESS_CPUTIME_ID) 纳秒 进程 CPU 时间 是 性能剖析
clock_gettime(CLOCK_THREAD_CPUTIME_ID) 纳秒 线程 CPU 时间 是 线程级剖析
gettimeofday 微秒 墙钟 是 已弃用，用 clock_gettime
rdtsc / rdtscp 周期 TSC 是 用户态最低延迟计时

time：秒级墙钟

time_t now = time(NULL);   /* 返回自 1970-01-01 00:00:00 UTC 的秒数 */
  • time_t 通常是 long 或 long long，Y2038 问题在 32 位系统严重
  • 受 NTP 调整影响，可能回拨或跳跃
  • 仅用于日志时间戳、过期检查等粗粒度场景

clock：CPU 时间

clock_t t0 = clock();
do_work();
clock_t t1 = clock();
double cpu_sec = (double)(t1 - t0) / CLOCKS_PER_SEC;
  • 测的是进程使用的 CPU 时间，不是墙钟时间
  • 多线程程序 clock 返回所有线程 CPU 时间之和（glibc），可能比墙钟大
  • CLOCKS_PER_SEC 通常是 1000000，精度微秒但实际分辨率可能更粗
  • 适合函数级微基准，不适合多线程延迟测量

clock_gettime：纳秒级主力

#include <time.h>
struct timespec {
    time_t   tv_sec;    /* 秒 */
    long     tv_nsec;   /* 纳秒 [0, 999999999] */
};

struct timespec ts;
clock_gettime(CLOCK_MONOTONIC, &ts);
uint64_t ns = (uint64_t)ts.tv_sec * 1000000000ULL + ts.tv_nsec;

各时钟语义：

CLOCK_REALTIME

  • 系统墙钟时间，受 NTP/adadjtime 调整
  • 可能回拨（NTP 修正时钟回退）
  • 可能跳跃（settimeofday 手动设置）
  • 用于日志时间戳、跨机器时间对齐
  • 不适合测延迟——两次读取之间时钟可能跳变

CLOCK_MONOTONIC

  • 单调递增，永不回拨
  • 受 NTP 的 adjtimex 微调（频率调整，不是跳变）
  • HFT 延迟测量的唯一正确选择
  • 跨 fork 不重置，跨进程语义一致

CLOCK_MONOTONIC_RAW

  • 硬件原始时钟，不受 NTP 频率调整
  • 最纯粹的单调时钟，但分辨率可能较粗
  • 极致场景用，一般 CLOCK_MONOTONIC 足够

CLOCK_BOOTTIME

  • 含系统休眠时间（Linux 特有）
  • 适合需要包含休眠期的场景

gettimeofday 为什么弃用

struct timeval tv;
gettimeofday(&tv, NULL);   /* 微秒精度, 已弃用 */
  • 精度只到微秒，clock_gettime 到纳秒
  • POSIX.1-2008 标记为弃用
  • 语义同 CLOCK_REALTIME，受 NTP 影响
  • 历史代码保留，新代码用 clock_gettime

gmtime/localtime 与线程安全

struct tm *gmtime(const time_t *timep);     /* 返回静态缓冲区, 非线程安全! */
struct tm *localtime(const time_t *timep);  /* 同上 */

struct tm *gmtime_r(const time_t *timep, struct tm *result);    /* POSIX 线程安全 */
struct tm *localtime_r(const time_t *timep, struct tm *result);

gmtime/localtime 返回指向内部静态 struct tm 的指针，多线程调用会互相覆盖。HFT 必须用 _r 版本：

time_t now = time(NULL);
struct tm tm_buf;
localtime_r(&now, &tm_buf);
char buf[64];
strftime(buf, sizeof buf, "%Y-%m-%d %H:%M:%S", &tm_buf);

strftime：格式化时间

size_t strftime(char *s, size_t max, const char *format, const struct tm *tm);

常用占位符：

符 含义
%Y 四位年
%m 月 01-12
%d 日 01-31
%H 时 00-23
%M 分 00-59
%S 秒 00-60（含闰秒）
%s Unix 时间戳（非标准，常用）
%T 等价 %H:%M:%S
%F 等价 %Y-%m-%d
%z 时区偏移 +0800
%Z 时区名 CST

返回值：写入字符数（不含 \0），若 max 不够返回 0 表示失败。

difftime

double diff = difftime(end, start);   /* 秒, double */

计算两个 time_t 的差，返回 double 秒。纳秒级延迟测量不用这个，直接 (uint64_t)ts.tv_sec * 1e9 + ts.tv_nsec 转整数比较。

rdtsc：用户态最快计时

static inline uint64_t rdtsc() {
    unsigned hi, lo;
    __asm__ __volatile__("rdtsc" : "=a"(lo), "=d"(hi));
    return ((uint64_t)hi << 32) | lo;
}
  • 读 CPU 时间戳计数器，周期级精度（~0.3ns on 3GHz CPU）
  • 不经过 syscall，延迟个位数纳秒
  • 但 TSC 频率需校准（cpuid 或 clock_gettime 对照）
  • 多核 TSC 可能不同步（现代 CPU 有 invariant TSC 解决）
  • HFT 内层热路径用 rdtsc，外层用 clock_gettime
uint64_t t0 = rdtsc();
process_packet(pkt);
uint64_t t1 = rdtsc();
uint64_t cycles = t1 - t0;
double ns = (double)cycles / tsc_ghz;   /* tsc_ghz 需启动时校准 */

HFT 关联

  • 延迟测量主力：CLOCK_MONOTONIC 测端到端延迟，纳秒精度，不受 NTP 回拨
  • 热路径 rdtsc：数据面内层循环用 rdtsc，避免 clock_gettime 的 syscall 开销（虽然 vDSO 后已很快）
  • 时间戳字段：行情 packet 内嵌交易所时间戳（纳秒 uint64），与本地 CLOCK_MONOTONIC 配对计算网络延迟
  • 日志时间戳：CLOCK_REALTIME + localtime_r + strftime 生成人类可读时间，便于运维排查
  • 跨机器对齐：分布式系统用 PTP/NTP 同步 CLOCK_REALTIME，订单时间戳用同步后的墙钟
  • 回拨防御：测延迟永远用 CLOCK_MONOTONIC，永不用 CLOCK_REALTIME——NTP 回拨会让延迟变负
  • TSC 校准：启动时用 clock_gettime 对照 rdtsc 算出 TSC 频率，运行期直接用 rdtsc 换算
  • rdtscp 串行化：rdtscp 比 rdtsc 多了 CPU ID 序列化，避免乱序执行导致的时间戳错位

16.4

非本地跳转

本节讲什么

setjmp / longjmp：跨函数的"栈回溯"——在一个函数里保存栈上下文，在另一个深层调用的函数里跳回，绕过正常的 return 链。这是 C 语言里最接近"异常"的机制，也是最容易写出 UB 的特性之一。现代工程代码极少用，HFT 热路径完全禁用，但理解它对阅读老代码、协议解析器、错误恢复模式有重要价值。

要点

基本用法

#include <setjmp.h>

jmp_buf env;

void deep_func() {
    if (error) longjmp(env, 1);   /* 跳回 setjmp 处, 返回值 1 */
}

if (setjmp(env) == 0) {
    /* 首次调用 setjmp 返回 0, 正常路径 */
    deep_func();
} else {
    /* longjmp 跳回这里, 返回 longjmp 的第二参数 (非 0) */
    /* 错误恢复路径 */
}

setjmp 的特殊性：同一次调用返回两次。首次调用返回 0，longjmp 跳回时返回 longjmp 的 val 参数（若 val 为 0 则返回 1）。

longjmp 的栈语义

longjmp(env, val) 做的事：

  1. 从 env 恢复栈指针、指令指针、寄存器
  2. "展开"调用栈，直接跳回 setjmp 处
  3. 跳过的中间函数没有 return，局部对象的析构/free 不会执行

这与 C++ 异常的栈展开（unwinding）不同——C++ 会调用析构函数，C 的 longjmp 不会。

局部变量的 volatile 陷阱

int x = 1;
if (setjmp(env) == 0) {
    x = 2;
    longjmp(env, 1);
} else {
    /* x 是 1 还是 2? UB! */
}

setjmp 返回后，非 volatile 局部变量如果在 setjmp 之后被修改，其值是未定义的。编译器可能把变量放在寄存器里，longjmp 只恢复 setjmp 时刻的寄存器，不恢复之后的修改。

规则：在 setjmp 之后、longjmp 之前修改的局部变量，必须在 setjmp 之前声明为 volatile 才能在 longjmp 后安全读取。

volatile int x = 1;
if (setjmp(env) == 0) {
    x = 2;
    longjmp(env, 1);
} else {
    /* x 一定是 2 */
}

setjmp 的使用限制

setjmp 的返回值只能用在两种上下文：

  1. if / switch / while 的条件表达式（整个表达式就是 setjmp(...)）
  2. 与常数的比较（setjmp(env) == 0）
/* 合法 */
if (setjmp(env)) { ... }
switch (setjmp(env)) { ... }
while (!setjmp(env)) { ... }
if (setjmp(env) == 0) { ... }

/* 非法 / UB */
int x = setjmp(env) + 1;        /* 嵌入复杂表达式 */
foo(setjmp(env));               /* 函数参数 */
int *p = &setjmp(env);          /* 取地址 */

这是标准要求，编译器会检查并报错或警告。

典型用例：解析器错误恢复

jmp_buf parse_env;

void parse_error(const char *msg) {
    fprintf(stderr, "parse error: %s\n", msg);
    longjmp(parse_env, 1);
}

void parse_config(const char *text) {
    if (setjmp(parse_env) == 0) {
        parse_section(text);   /* 深层递归, 任意层出错都跳回 */
    } else {
        /* 错误已报告, 跳过本配置块, 继续下一个 */
    }
}

这是 setjmp 的经典场景——深层递归解析器，任何一层发现错误都能立即跳出，不用层层 return 检查。

longjmp 与资源清理的矛盾

void leaky_func() {
    char *buf = malloc(1024);
    FILE *fp = fopen("data", "r");

    if (error) longjmp(env, 1);   /* buf 和 fp 泄漏! */

    fclose(fp);
    free(buf);
}

longjmp 跳过的函数里，已 malloc 的内存、已 fopen 的文件、已 lock 的互斥锁都不会被清理。这是 setjmp/longjmp 在工程代码里被弃用的主要原因。

解决方案：

  1. 避免用 longjmp：用错误码层层 return + goto cleanup
  2. 资源注册表：维护一个全局资源列表，longjmp 后遍历清理（丑陋且易错）
  3. C++ 异常：RAII 析构自动清理，但 C 代码无此机制

longjmp 与信号处理

jmp_buf sig_env;

void on_sigsegv(int sig) {
    longjmp(sig_env, 1);   /* 从信号处理跳回, 极其危险 */
}

从信号处理 longjmp 是未定义行为（除非用 sigsetjmp/siglongjmp 且信号屏蔽正确恢复）。即使能工作，也可能留下信号屏蔽状态不一致、半截系统调用等烂摊子。现代代码用 sigaction 的 SA_NODEFER + 显式恢复，或干脆让进程崩溃转 core。

sigsetjmp/siglongjmp

#include <setjmp.h>
sigjmp_buf env;
if (sigsetjmp(env, 1) == 0) {   /* 1 = 保存信号屏蔽 */
    /* ... */
} else {
    /* siglongjmp 跳回, 信号屏蔽也恢复 */
}

sigsetjmp 的第二参数 savesigs 非零时保存当前信号屏蔽字，siglongjmp 跳回时恢复。这是从信号处理跳转的"合法"方式，但仍不推荐用于复杂逻辑。

C++ 交互：禁止

longjmp 跨越包含 C++ 对象（有析构函数）的栈帧是未定义行为。C++ 异常机制和 longjmp 完全不兼容——混用必然崩溃或资源泄漏。C++ 代码必须用 try/catch/throw。

HFT 关联

  • 热路径禁用：setjmp/longjmp 在数据面绝不允许，错误用错误码 + goto cleanup 显式处理
  • 配置解析可接受：启动时读 gateway.conf，用 setjmp 做错误恢复可接受，但仍倾向错误码层层 return
  • 协议解析老代码：历史 FIX 解析器可能用 setjmp，新代码改用结构化错误处理
  • 信号处理不用 longjmp：SIGSEGV 后用 siglongjmp 跳回看似优雅，实则留下半截状态，HFT 宁可崩溃转 core 重启
  • 协程实现：某些协程库（如 libco）用 setjmp/longjmp 做上下文切换，但更现代的实现用 ucontext 或汇编
  • 异常模拟：C 代码模拟 OOP 异常机制用 setjmp/longjmp，但 RAII 缺失让资源管理极其脆弱

与后续衔接

  • ch16.5 信号处理 + siglongjmp 的危险组合
  • ch11 malloc/free 与 longjmp 的资源泄漏矛盾
  • ch18 ucontext/makecontext/swapcontext 是更安全的上下文切换

代码自测

题目 1： 以下代码中 setjmp/longjmp 实现了什么功能？

jmp_buf env;
void handler(int sig) {
    longjmp(env, 1);
}
int main() {
    if (setjmp(env) == 0) {
        signal(SIGINT, handler);
        while (1) { }
    } else {
        printf("caught interrupt\n");
    }
}
参考答案

实现了非本地跳转——从信号处理函数直接跳回 main 中的 setjmp 位置。setjmp 第一次返回 0，longjmp 后 setjmp 第二次返回 val（此处为 1）。注意事项：(1) longjmp 不能跳到已返回的函数；(2) 局部变量的值在 longjmp 后可能不确定（volatile 变量除外）；(3) 这是 C 的异常处理机制，比 C++ try/catch 更底层。

16.5

信号

本节讲什么

<signal.h> 的异步信号机制：signal/raise/abort，POSIX 扩展的 sigaction/sigprocmask/sigsuspend/signalfd。信号是 Unix 最古老的 IPC 机制，也是最容易写出 UB 的地方——信号处理函数里能做的事极少，违反约束就是未定义行为。HFT 用信号做优雅退出、崩溃诊断、配置重载触发，必须严格遵守异步信号安全规则。

要点

基本接口

#include <signal.h>

typedef void (*sighandler_t)(int);

sighandler_t signal(int signum, sighandler_t handler);   /* 简单但不可移植 */
int raise(int signum);                                    /* 给自己发信号 */
int kill(pid_t pid, int sig);                             /* 给进程发信号 */

signal 的语义在不同 Unix 实现不一致（BSD vs System V），生产代码用 sigaction 替代。

常见信号速查

信号 默认行为 常见触发原因
SIGSEGV 终止+core 野指针、栈溢出、写只读区
SIGABRT 终止+core abort()、assert 失败、double free
SIGFPE 终止+core 整数除零、INT_MIN 取负
SIGBUS 终止+core 内存对齐错误、mmap 文件被 truncate
SIGILL 终止+core 非法指令、栈损坏返回到非代码地址
SIGINT 终止 Ctrl-C
SIGTERM 终止 kill 默认信号，运维停止进程
SIGKILL 终止（不可捕获） kill -9，最后手段
SIGSTOP 暂停（不可捕获） kill -STOP
SIGPIPE 终止 向已关闭的 socket 写
SIGCHLD 忽略 子进程退出
SIGUSR1/SIGUSR2 终止 用户自定义，配置重载
SIGALRM 终止 alarm() 超时
SIGXCPU 终止 CPU 时间超限
SIGXFSZ 终止 文件大小超限

sigaction：生产标准

struct sigaction {
    void (*sa_handler)(int);              /* 简单处理函数 */
    void (*sa_sigaction)(int, siginfo_t *, void *);  /* 带信息版本 */
    sigset_t sa_mask;                     /* 处理期间屏蔽的信号集 */
    int sa_flags;                         /* SA_RESTART / SA_SIGINFO / ... */
};

struct sigaction sa = {0};
sa.sa_handler = on_sigterm;
sa.sa_flags = SA_RESTART;   /* 被信号中断的 syscall 自动重启 */
sigemptyset(&sa.sa_mask);
sigaction(SIGTERM, &sa, NULL);

sigaction 相比 signal 的优势：

  • 行为跨平台一致
  • 可指定处理期间屏蔽哪些信号
  • SA_RESTART 控制中断的 syscall 是否自动重启
  • SA_SIGINFO 拿到 siginfo_t（发送者 PID、UID 等）
  • SA_NODEFER 控制处理期间是否屏蔽自身

异步信号安全（async-signal-safe）

这是信号处理最核心的约束。信号可能在任意指令打断主程序，如果 handler 调用了非可重入函数，而主程序恰好在执行该函数的中间状态，就是 UB。

POSIX 列出的 async-signal-safe 函数极少：

安全 不安全（常见误用）
write printf/fprintf（有锁 + 缓冲）
read malloc/free（全局堆锁）
_exit exit（跑 atexit + flush stdio）
signal/sigaction syslog
waitpid 大多数 stdio 函数
open/close 任何持有锁的函数
stat strerror（静态缓冲）

exit 不安全是因为它调用 atexit 回调 + 刷 stdio 缓冲，这些可能持锁。信号处理里必须用 _exit。

handler 里的正确做法

/* 信号处理的标准模式 */
static volatile sig_atomic_t g_should_exit = 0;
static volatile sig_atomic_t g_reload_config = 0;

void on_sigterm(int sig) {
    (void)sig;
    g_should_exit = 1;   /* 只置标志, 不做复杂操作 */
}

void on_sigusr1(int sig) {
    (void)sig;
    g_reload_config = 1;
}

/* 主循环检查标志 */
while (!g_should_exit) {
    if (g_reload_config) {
        g_reload_config = 0;
        reload_config();   /* 在主循环里做, 不在 handler 里 */
    }
    poll(...);
}

volatile sig_atomic_t 是信号标志的标准类型：

  • volatile 防止编译器把变量优化到寄存器，确保每次读内存
  • sig_atomic_t 保证读写是原子的（通常 int）
  • 仍然是单向标志，不构成同步原语（内存序问题见后）

信号屏蔽与 sigprocmask

sigset_t mask, oldmask;
sigemptyset(&mask);
sigaddset(&mask, SIGTERM);

sigprocmask(SIG_BLOCK, &mask, &oldmask);   /* 屏蔽 SIGTERM */
/* 临界区, SIGTERM 不会打断 */
sigprocmask(SIG_SETMASK, &oldmask, NULL);  /* 恢复 */

sigprocmask 控制当前线程的信号屏蔽字。被屏蔽的信号不会立即递送，而是挂起（pending），解除屏蔽后才递送。

sigsuspend：等待信号

sigset_t mask;
sigfillset(&mask);
sigdelset(&mask, SIGUSR1);
sigsuspend(&mask);   /* 原子: 换屏蔽 + 挂起, 直到信号到达 */

sigsuspend 解决"检查标志 + sleep"之间的竞态。直接用 sleep 可能错过信号，sigsuspend 保证原子切换。

自管道技巧（self-pipe trick）

信号处理里直接做事太受限，经典技巧是用 pipe + write 一个字节到管道，主循环 poll 管道读端：

int sig_pipe[2];
pipe(sig_pipe);

void on_sigterm(int sig) {
    char byte = 1;
    write(sig_pipe[1], &byte, 1);   /* write 是 async-signal-safe */
}

/* 主循环 */
struct pollfd pfd = { .fd = sig_pipe[0], .events = POLLIN };
poll(&pfd, 1, -1);
if (pfd.revents & POLLIN) {
    /* 在主循环上下文安全处理信号 */
    reload_config();
}

Linux 2.6.22+ 有 signalfd 直接把信号变成 fd，更优雅：

int sfd = signalfd(-1, &mask, 0);
struct pollfd pfd = { .fd = sfd, .events = POLLIN };
poll(&pfd, 1, -1);
/* read(sfd, &siginfo, sizeof siginfo) 拿到信号信息 */

SIGPIPE 陷阱

向已关闭的 socket write 默认触发 SIGPIPE 终止进程。HFT 网关必须忽略或捕获：

signal(SIGPIPE, SIG_IGN);   /* 忽略, write 返回 EPIPE */

或用 send/recv 的 MSG_NOSIGNAL 标志。

信号与 EINTR

慢系统调用（read/write/poll/accept）被信号打断时返回 -1，errno = EINTR。两种处理方式：

/* 方式1: sigaction 设 SA_RESTART, 自动重启 */
struct sigaction sa = {0};
sa.sa_handler = handler;
sa.sa_flags = SA_RESTART;   /* 关键 */
sigaction(SIGTERM, &sa, NULL);

/* 方式2: 手动重试 */
while ((n = read(fd, buf, sizeof buf)) < 0) {
    if (errno == EINTR) continue;   /* 被信号打断, 重试 */
    /* 真错误 */
    break;
}

SA_RESTART 不对所有 syscall 生效（poll 仍可能返回 EINTR），关键路径手动重试更稳。

信号发送的方向

  • kill(pid, sig)：给指定进程发
  • raise(sig)：给自己（当前线程）发
  • pthread_kill(tid, sig)：给同进程内指定线程发
  • tgkill(tgid, tid, sig)：Linux 特有，更精确
  • sigqueue(pid, sig, value)：带附加数据的信号

多线程程序里信号递送语义复杂：信号可能发给任意线程。用 pthread_sigmask 控制每线程屏蔽，配合 signalfd 让指定线程处理。

HFT 关联

  • 优雅退出：SIGTERM → handler 置 g_should_exit → 主循环停止收单 → flush 日志 → dump 订单簿快照 → _exit(0)
  • 配置热加载：SIGUSR1 → handler 置 g_reload_config → 主循环重新读配置（不在 handler 里读文件）
  • 崩溃诊断：SIGSEGV handler 里用 write + backtrace_symbols_fd 输出栈帧到文件，然后 _exit(1) 转核心转储
  • SIGPIPE 忽略：网关启动即 signal(SIGPIPE, SIG_IGN)，避免对端关闭导致进程被杀
  • 数据面无信号：数据线程用 pthread_sigmask 屏蔽所有信号，避免行情收发被信号打断
  • EINTR 处理：控制面 syscall 用 SA_RESTART 或手动重试，数据面用 PMD 完全绕过 syscall
  • signalfd 集成：控制面把信号纳入 epoll 事件循环，与 socket 事件统一处理
  • SIGABRT 排查：abort 常因 double free 或 assert 失败，core dump + ASan 定位
  • CPU 亲和与信号：数据线程绑核后，信号递送给该核，避免跨核中断抖动

参考答案

printf 不是异步信号安全的——它在信号处理函数中调用是未定义行为。printf 内部使用缓冲区和锁，如果信号打断的主程序正在执行 printf，会导致缓冲区损坏或死锁。信号处理函数中只能调用异步信号安全函数（如 write、_exit）。正确做法：在 handler 中只设置标志变量，在主循环中检查并处理。

16.6

打印可变参数列表

本节讲什么

<stdarg.h> 的 va_list / va_start / va_arg / va_end / va_copy，以及配合 vfprintf / vsnprintf / vprintf 实现自定义可变参数函数。这是 C 语言实现 printf 风格日志接口的底层机制，DPDK rte_log、glibc syslog、所有现代日志库都建立在它之上。本节重点讲 ABI 相关的微妙之处、va_list 的所有权语义、以及为什么 va_copy 在某些平台必不可少。

要点

基本接口

#include <stdarg.h>

void foo(const char *fmt, ...) {
    va_list ap;
    va_start(ap, fmt);          /* 绑定最后一个固定参数 */

    int x = va_arg(ap, int);    /* 取下一个 int */
    double d = va_arg(ap, double);
    char *s = va_arg(ap, char *);

    va_end(ap);                 /* 清理 */
}
宏 作用 调用时机
va_start(ap, last) 初始化 va_list，绑定最后一个有名参数 取参数前
va_arg(ap, type) 取下一个参数并推进 每次取参数
va_end(ap) 清理（某些平台释放在栈上的状态） 函数返回前
va_copy(dest, src) 复制 va_list 状态 需要二次遍历时

va_list 是什么

va_list 是一个不透明类型，在不同平台实现差异巨大：

平台 va_list 实现形式
x86-64 System V 结构体（寄存器保存区 + 溢出区指针）
x86 cdecl char *，指向栈上参数
ARM struct __va_list
Itanium 复杂结构

所以 va_list 不能直接赋值复制（va_list a = b 在某些平台 UB），必须用 va_copy。

整数提升与默认参数提升

va_arg(ap, type) 的 type 受"默认参数提升"约束：

  • char/short → 提升为 int
  • unsigned char/unsigned short → 提升为 int 或 unsigned int
  • float → 提升为 double
void foo(...) {
    va_list ap;
    va_start(ap, fmt);
    char c = va_arg(ap, int);      /* 不是 char! */
    short s = va_arg(ap, int);     /* 不是 short! */
    float f = va_arg(ap, double);  /* 不是 float! */
    va_end(ap);
}

用 va_arg(ap, char) 是 UB——编译器可能不报错，但取出的值是错的。

va_start 的第二参数

va_start(ap, last) 的 last 是函数参数列表里最后一个有名参数。编译器用它定位可变参数在栈上的起点：

void log_msg(int level, const char *fmt, ...) {
    va_list ap;
    va_start(ap, fmt);   /* fmt 是最后一个有名参数 */
    /* ... */
}

如果函数被声明为 (...) 没有任何有名参数（C23 之前非法，C23 允许），va_start 无法工作。C 标准 ... 前必须有至少一个有名参数。

va_end 为什么必要

某些平台（如 x86-64）的 va_list 是栈上结构，va_start 可能分配了动态资源（罕见但存在）。va_end 释放这些资源。即使在不需要的平台上，遗漏 va_end 也是 UB——标准要求每个 va_start 必须有匹配的 va_end。

va_copy：二次遍历

void log_both(FILE *f1, FILE *f2, const char *fmt, ...) {
    va_list ap1, ap2;
    va_start(ap1, fmt);
    va_copy(ap2, ap1);   /* 复制状态, ap2 独立 */

    vfprintf(f1, fmt, ap1);
    vfprintf(f2, fmt, ap2);   /* 第二次遍历 */

    va_end(ap1);
    va_end(ap2);
}

va_list 被 vfprintf 消费后状态不确定（某些平台 ap 被改到末尾，某些平台不变）。要二次遍历必须 va_copy 复制一份。这是 C99 引入 va_copy 的原因。

vfprintf / vsnprintf / vprintf

int vfprintf(FILE *stream, const char *fmt, va_list ap);
int vsnprintf(char *str, size_t size, const char *fmt, va_list ap);
int vprintf(const char *fmt, va_list ap);

v 前缀版本接受 va_list 而不是 ...。这是实现"自定义 printf"的关键——你的函数收 ...，用 va_start 转 va_list，再转发给 vfprintf。

自定义日志函数模板

#include <stdarg.h>
#include <stdio.h>
#include <time.h>

static FILE *g_log_fp = NULL;
static int g_log_level = LOG_INFO;

void log_init(FILE *fp, int level) {
    g_log_fp = fp;
    g_log_level = level;
}

void log_msg(int level, const char *fmt, ...) {
    if (level < g_log_level) return;
    if (!g_log_fp) return;

    /* 时间戳 */
    struct timespec ts;
    clock_gettime(CLOCK_REALTIME, &ts);
    struct tm tm_buf;
    localtime_r(&ts.tv_sec, &tm_buf);
    char timebuf[32];
    strftime(timebuf, sizeof timebuf, "%H:%M:%S", &tm_buf);

    fprintf(g_log_fp, "[%s.%03ld] ", timebuf, ts.tv_nsec / 1000000);

    /* 用户消息 */
    va_list ap;
    va_start(ap, fmt);
    vfprintf(g_log_fp, fmt, ap);
    va_end(ap);

    fputc('\n', g_log_fp);
}

printf 风格宏包装

#define LOG(level, fmt, ...) \
    log_msg(level, "[%s:%d] " fmt, __FILE__, __LINE__, ##__VA_ARGS__)

LOG(LOG_INFO, "connected to %s:%d", host, port);
/* 展开为:
 * log_msg(LOG_INFO, "[%s:%d] connected to %s:%d", __FILE__, __LINE__, host, port);
 */

__FILE__/__LINE__ 是预处理符号，自动注入源码位置。##__VA_ARGS__ 处理无参数时去掉前导逗号（GNU 扩展，C23 __VA_OPT__ 标准化）。

va_list 的所有权与 ABI 跨界

va_list 的 ABI 因平台而异，不能跨函数边界传递 va_list 本身的指针然后期望另一函数 va_arg——除非该函数签名声明接受 va_list*。直接传 va_list 值在某些平台是按值传递（复制），某些平台按引用（指针），行为不一致。跨函数转发用 va_list 值传递 + 被调函数用 va_copy 保留副本最安全。

HFT 关联

  • 日志宏核心：HFT 网关统一日志 API LOG(level, fmt, ...) 内部就是 va_start + vsnprintf + 队列入队
  • DPDK rte_log：DPDK 日志接口 rte_log(level, fmt, ...) 同模式，内部 vfprintf 到注册的流
  • 异步日志：数据面 LOG 宏把格式化后的字符串入队（vsnprintf 到栈缓冲 + memcpy 到 ring），后台线程 write 落盘——避免数据面直接 syscall
  • 崩溃栈打印：信号 handler 里用 vsnprintf 格式化栈帧到固定缓冲，write(STDERR_FILENO, ...) 输出（async-signal-safe）
  • 可变参数避免数据面：数据面热路径不用可变参数，固定字段直接 memcpy 到日志结构体，比 vsnprintf 快十倍
  • format string 注入：外部数据绝不能直接当 fmt，必须 LOG("%s", user_data)
  • va_list 跨线程：va_list 不能跨线程传递（栈状态），日志异步队列存的是格式化后的字符串，不是 va_list

void my_printf(const char *fmt, ...) {

16.7

执行环境

本节讲什么

<stdlib.h> 里与进程环境相关的接口：exit/abort/atexit/_exit 的终止语义、system 为什么 HFT 禁用、getenv/setenv 环境变量、posix_memalign/aligned_alloc 对齐分配、quick_exit/at_quick_exit（C11）。这是进程生命周期管理的核心，也是 HFT 启停、配置加载、资源清理的设计依据。

要点

进程终止全景

void exit(int status);        /* 标准终止: 跑 atexit + flush stdio */
void _exit(int status);       /* 立即终止: 不跑 atexit, 不 flush */
void quick_exit(int status);  /* C11: 跑 at_quick_exit, 不 flush stdio */
void abort(void);             /* 异常终止: SIGABRT + core dump, 不跑 atexit */
接口 atexit 回调 flush stdio 临时文件 core dump
exit ✓ 逆序 ✓ ✓ 删除 ✗
_exit ✗ ✗ ✗ ✗
quick_exit at_quick_exit 逆序 ✗ ✗ ✗
abort ✗ ✗（部分实现 flush） ✗ ✓（若 ulimit 允许）

atexit 注册顺序

int atexit(void (*func)(void));   /* 注册退出回调, 返回 0 成功 */
  • 多次注册的回调逆序执行（LIFO，栈式）
  • 至少保证 32 个回调（ATEXIT_MAX）
  • atexit 在 exit 或 main return 时触发
  • abort/_exit/quick_exit 不触发 atexit
  • 回调内不能再注册 atexit（UB）
void cleanup_log(void) { fclose(g_log_fp); }
void cleanup_shm(void) { shm_unlink("/hft_orderbook"); }
void cleanup_socket(void) { close(g_sock); }

/* 注册顺序 */
atexit(cleanup_log);     /* 最后执行 */
atexit(cleanup_shm);     /* 中间执行 */
atexit(cleanup_socket);  /* 最先执行 */
/* 退出时: cleanup_socket → cleanup_shm → cleanup_log */

注册顺序与执行顺序相反——最先注册的最后执行。这模仿"构造/析构"对称：先建立的资源最后释放（栈式生命周期）。

fork 后用 _exit

pid_t pid = fork();
if (pid == 0) {
    /* 子进程 */
    do_child_work();
    _exit(0);   /* 不用 exit! */
}

fork 后子进程继承父进程的 stdio 缓冲区副本。如果子进程用 exit，会 flush 缓冲区导致输出重复；用 _exit 跳过 flush。父进程的 exit 仍会正常 flush 自己的缓冲。

exit 的刷新顺序

exit 做的事（标准顺序）：

  1. 调用 atexit 注册的回调（逆序）
  2. 刷新所有 stdio 输出流（fflush(NULL) 语义）
  3. 删除 tmpfile 创建的临时文件
  4. 关闭所有 stdio 流
  5. _exit(status) 真正终止

如果 atexit 回调里 fprintf，这些输出会在步骤 2 被刷新——但若回调 crash，后续步骤跳过，缓冲丢失。关键日志在回调里 fflush 显式落盘。

abort 与 core dump

void abort(void);   /* 等价 raise(SIGABRT) */
  • 默认 SIGABRT 处理是终止 + core dump
  • 如果 SIGABRT 被捕获且 handler longjmp 出去，abort 语义被打破——POSIX 要求 abort 必然终止进程，捕获后若不调 _exit 或再次 raise(SIGABRT) 行为未定义
  • core dump 大小受 ulimit -c 限制，生产常设为 unlimited 或用 systemd 自动转储
  • assert 失败内部调 abort

system：HFT 绝对禁用

int system(const char *command);   /* /bin/sh -c command */

system 的三大问题：

  1. fork + exec + shell：极慢，毫秒级，且 fork 复制页表
  2. shell 注入：system(user_input) 若 user_input 含 ; rm -rf / 就是灾难
  3. 环境依赖：PATH / shell / 环境变量都可能影响行为

HFT 替代方案：

需求 替代
运行外部程序 fork + execvp（无 shell）
简单 shell 命令 运维脚本，不在数据面
字符串拼接命令 严禁，用 exec 数组参数

getenv / setenv

char *getenv(const char *name);          /* 返回指向值的指针, 不新增, 只读 */
int setenv(const char *name, const char *value, int overwrite);   /* POSIX */
int putenv(char *string);                /* string 形式 "NAME=VALUE" */
int unsetenv(const char *name);          /* POSIX */
  • getenv 返回的指针指向 environ 数组内部，修改它是 UB
  • setenv 复制参数，安全；putenv 直接把传入字符串塞进 environ，字符串必须长生命周期
  • 多线程 setenv 不安全（glibc 全局锁但行为复杂），HFT 通常启动时读一次环境变量后不再改
const char *port_str = getenv("HFT_PORT");
int port = port_str ? atoi(port_str) : 8080;   /* atoi 仅此处可接受, 配置错误启动失败 */

environ 全局变量

extern char **environ;   /* 全局环境变量数组, 以 NULL 结尾 */

直接遍历 environ 可看到所有环境变量。main 的第三参数 envp 同 environ，但 POSIX 推荐用 environ 全局。

posix_memalign / aligned_alloc

int posix_memalign(void **memptr, size_t alignment, size_t size);   /* POSIX */
void *aligned_alloc(size_t alignment, size_t size);                  /* C11 */
  • alignment 必须是 2 的幂且是 sizeof(void *) 的倍数
  • posix_memalign 返回值在 memptr，函数返回 0/错误码
  • aligned_alloc 返回指针或 NULL
  • 释放都用 free

HFT 用途：

  • DMA 缓冲：网卡 DMA 要求 buffer 起始地址对齐到 cache line（64B）或页（4KB）
  • SIMD：AVX-512 要求 64 字节对齐才能用对齐 load/store
  • hugepage：2MB 对齐的内存配合 madvise(MADV_HUGEPAGE) 减少 TLB miss
void *dma_buf;
posix_memalign(&dma_buf, 64, 4096);   /* cache line 对齐 */
/* ... 用作网卡 DMA 缓冲 ... */
free(dma_buf);

quick_exit（C11）

void quick_exit(int status);
int at_quick_exit(void (*func)(void));

C11 引入，用于不需要完整清理的场景：

  • 不刷 stdio（避免慢）
  • 不删 tmpfile
  • 只跑 at_quick_exit 注册的回调

适用场景：atexit 回调里出了问题需要快速退出，或程序状态已损坏不能信任完整清理。HFT 极少用，更倾向 _exit 直接终止。

内存分配回顾

void *malloc(size_t size);
void *calloc(size_t nmemb, size_t size);   /* 清零 + 溢出检查 */
void *realloc(void *ptr, size_t size);
void free(void *ptr);

void *aligned_alloc(size_t alignment, size_t size);   /* C11 */
int posix_memalign(void **memptr, size_t align, size_t size);

详见 ch11，这里强调：

  • malloc 全局锁，多线程争用是 HFT 性能瓶颈
  • calloc 自动检查 nmemb * size 溢出，比 malloc(n*m) 安全
  • realloc 失败返回 NULL，原指针仍有效——必须用临时变量保存
  • DPDK rte_mempool 预分配 + 无锁 per-lcore cache，数据面完全不用 malloc

HFT 关联

  • 优雅退出：atexit 注册订单簿 dump、日志 flush、共享内存清理、socket 关闭，按逆序执行
  • fork 后 _exit：DPDK secondary 进程 fork 后立即 _exit 不走完整清理
  • abort + core dump：致命错误（double free、断言失败）abort 转 core，运维脚本自动收集
  • system 禁用：数据面绝不调 system，控制面也倾向 fork+execvp 避免 shell 注入
  • 环境变量配置：getenv("HFT_CONFIG_PATH") 启动时读一次，热加载用信号触发不用改环境
  • DMA 对齐分配：posix_memalign 分配 64B 对齐的 mbuf 数据区，配合网卡 DMA 零拷贝
  • mempool 替代 malloc：数据面用 rte_mempool 预分配 + 无锁获取，避免 malloc 锁
  • 退出顺序设计：先停收单 → flush 订单 → dump 快照 → close 连接 → 关日志，每步 atexit 或显式调用
  • SIGTERM 触发退出：SIGTERM handler 置标志，主循环检查后调 exit(0) 走完整 atexit 链

16.8

locale

本节讲什么

<locale.h> 的区域设置：setlocale/localeconv/LC_* 分类，以及宽字符 <wchar.h>/<wctype.h>。HFT 与嵌入式系统几乎不碰这层——日志用 ASCII、报文用二进制、价格用定点整数，locale 改变行为反而是隐患。但理解 locale 对跨平台代码、UI 国际化、避免 printf 小数点格式被 locale 污染有重要价值。

要点

setlocale 与 LC_* 分类

#include <locale.h>

char *setlocale(int category, const char *locale);

category 控制影响范围：

分类 影响
LC_ALL 所有分类
LC_COLLATE strcoll/strxfrm 字符串排序
LC_CTYPE ctype.h 字符分类（isalpha/toupper）
LC_MONETARY localeconv 货币格式
LC_NUMERIC printf/strtod 小数点符号
LC_TIME strftime 日期月份名
LC_MESSAGES 系统消息语言（GNU 扩展） 
setlocale(LC_ALL, "C");         /* 默认, 最小化行为可预期 */
setlocale(LC_ALL, "");          /* 设为环境变量 LANG/LC_ALL 指定的 */
setlocale(LC_ALL, "en_US.UTF-8");
setlocale(LC_NUMERIC, "C");     /* 仅小数点用 C, 其余跟随环境 */

"C" locale：HFT 的默认选择

程序启动时默认 LC_ALL="C"：

  • 小数点是 .（不是欧陆的 ,）
  • 字符分类 ASCII（isalpha('A') 为真，isalpha(0xC3) 为假）
  • strtod 用 . 作小数点
  • strftime 月份是 January 等

HFT 代码永远保持 LC_ALL="C"，确保行为可预期。某些发行版默认 LANG=zh_CN.UTF-8，若代码不小心 setlocale(LC_ALL, "")，printf("%.2f", 3.14) 可能输出 3,14——破坏日志解析。

localeconv：格式信息

struct lconv *lc = localeconv();
/* lc->decimal_point: "." 或 "," */
/* lc->thousands_sep: "," 或 "." 或 " " */
/* lc->mon_decimal_point: 货币小数点 */

返回指向静态结构的指针，多线程不安全。HFT 不用，固定 "." 小数点。

strtod 与 locale

double d = strtod("3.14", NULL);   /* C locale 下解析为 3.14 */

strtod 用 LC_NUMERIC 决定小数点符号。在 de_DE.UTF-8 locale 下 strtod("3.14") 可能返回 3（只解析 3，. 不是合法小数点）。HFT 配置文件含浮点字段时，确保 LC_NUMERIC="C" 或用定点整数避免。

宽字符：wchar_t / wint_t

#include <wchar.h>
#include <wctype.h>

wchar_t wc = L'中';          /* 宽字符常量 */
wint_t wch = getwc(stdin);   /* 宽字符 I/O */
iswalpha(wc);                /* 宽字符分类 */
towupper(wc);                /* 宽字符大写 */

wchar_t 的宽度因平台而异：

平台 sizeof(wchar_t)
Linux glibc 4（UTF-32）
Windows 2（UTF-16）
AIX 2

跨平台宽字符代码极其痛苦——HFT 完全不用，所有字符串用 UTF-8 字节流当 binary 处理。

多字节字符 vs 宽字符

类型 存储 例子
多字节（UTF-8） 1-6 字节/字符 "中" = 3 字节 0xE4 0xB8 0xAD
宽字符（UTF-32） 固定 4 字节/字符 L'中' = 0x00004E2D

UTF-8 优势：

  • 向后兼容 ASCII（"hello" 字节同 ASCII）
  • 字节流友好，可当 binary 处理
  • 网络协议标准编码
  • 无字节序问题（UTF-16/32 有 BOM 麻烦）

HFT 协议字段用 UTF-8，日志用 ASCII，UI 本地化交给前端。

mbs / wcs 转换

size_t mbstowcs(wchar_t *dest, const char *src, size_t n);
size_t wcstombs(char *dest, const wchar_t *src, size_t n);

size_t mbrtowc(wchar_t *pwc, const char *s, size_t n, mbstate_t *ps);   /* 可重入 */

mbstowcs/wcstombs 内部有全局状态，多线程不安全；mbrtowc/wcrtomb 用 mbstate_t 参数可重入。HFT 极少用，需要时选可重入版本。

setlocale 的线程安全

POSIX setlocale 不是线程安全——改变全局 locale 会影响所有线程。多线程程序若必须改 locale：

  • 启动时设一次，之后只读
  • 或用 uselocale（POSIX.1-2008）创建 per-thread locale
locale_t loc = newlocale(LC_ALL_MASK, "C", (locale_t)0);
uselocale(loc);   /* 当前线程用 loc, 不影响其他线程 */
freelocale(loc);

HFT 通常启动固定 LC_ALL="C" 后永不变，避免所有线程安全顾虑。

HFT 关联

  • 日志用 ASCII：所有日志消息、字段名、时间格式都用 ASCII，避免 locale 影响 printf 和 strftime
  • 配置文件 LC_NUMERIC=C：解析 price=3.14 用 strtod，确保 . 被识别为小数点
  • 协议字段 UTF-8：FIX 标签值可能含中文公司名，按 UTF-8 字节流处理，memcpy 不 strcpy（避免宽字符假设）
  • 价格定点整数：完全绕开 locale，int64_t 单位 0.0001，无小数点歧义
  • 避免 setlocale(LC_ALL, "")：HFT 程序永不跟随系统 locale，显式 "C" 固定行为
  • DPDK 无 locale：DPDK 库本身不依赖 locale，rte_log 输出固定 ASCII
  • 跨机房部署：不同机房系统 locale 可能不同（上海 zh_CN，芝加哥 en_US），代码必须 locale-independent
  • 回测可重复性：locale 影响浮点格式化，回测日志解析要求 locale 固定 C

题目 1： 以下代码在不同 locale 下输出可能不同，为什么？

setlocale(LC_ALL, "");
printf("%.2f\n", 1234.56);
参考答案

在 C locale 下输出 1234.56（小数点用 .）。在德语 locale 下可能输出 1234,56（小数点用 ,）。setlocale(LC_ALL, "") 设置为系统默认 locale。locale 影响数字格式、日期格式、货币符号、字符分类等。如果不希望 locale 影响，保持 C locale（默认）。
