# 10.3 结构的存储分配

## 本节讲什么

**内存对齐、padding、sizeof** 是 struct 章节最关键的内容——网络协议解析错位、跨平台移植 bug、共享内存不一致的**头号根源**。struct 不是字段的简单拼接，编译器会按**对齐规则**插入 padding 字节，导致 `sizeof` 大于字段宽度之和。HFT/网络代码必须用 `__attribute__((packed))` 或显式偏移，才能让 struct 布局与线格式一致。

本节是 ch10 的**重点章**，详细剖析对齐规则、padding 计算、packed 权衡、跨平台陷阱。

## 要点

### 对齐规则（x86-64 Linux 典型）

**三条铁律**：

1. **成员起始偏移** = 该成员**自身宽度**的整数倍
2. **struct 总大小** = **最大成员宽度**的整数倍（末尾可能补 padding）
3. 不足处编译器自动插入 **padding 字节**

### 实例分析

```c
struct test1 {
    char a;     /* 1 字节，偏移 0 */
                /* 3 字节 padding */
    int  b;     /* 4 字节，偏移 4 */
};
/* sizeof = 8，不是 5 */

struct test2 {
    int  b;     /* 4 字节，偏移 0 */
    char a;     /* 1 字节，偏移 4 */
                /* 3 字节 padding（满足规则 2） */
};
/* sizeof = 8，不是 5 —— 末尾 padding */

struct test3 {
    char a;     /* 1 字节，偏移 0 */
    char b;     /* 1 字节，偏移 1 */
    char c;     /* 1 字节，偏移 2 */
    char d;     /* 1 字节，偏移 3 */
};
/* sizeof = 4，无 padding */

struct test4 {
    uint8_t  a;   /* 1 字节，偏移 0 */
    uint32_t b;   /* 4 字节，偏移 4（3 字节 padding 后） */
    uint8_t  c;   /* 1 字节，偏移 8 */
};
/* sizeof = 12，不是 6 —— 头尾 padding */
```

### 字段重排减少 padding

```c
/* 反例：字段顺序混乱，padding 多 */
struct bad {
    uint8_t  a;     /* 1 */
                  /* 7 padding */
    uint64_t b;     /* 8 */
    uint8_t  c;     /* 1 */
                  /* 3 padding */
    uint32_t d;     /* 4 */
};   /* sizeof = 24 */

/* 正例：按宽度降序排列 */
struct good {
    uint64_t b;     /* 8 */
    uint32_t d;     /* 4 */
    uint8_t  a;     /* 1 */
    uint8_t  c;     /* 1 */
                  /* 2 padding */
};   /* sizeof = 16，省 8 字节 */
```

**工程铁律**：struct 字段**按宽度从大到小排列**，可显著减少 padding。Google C++ Style Guide 和 Linux 内核都强调这一点。

### 对齐的原因

CPU 访问内存按**对齐粒度**进行（x86-64 通常 8/16 字节）：

- 对齐访问：单次总线事务，1 周期
- 非对齐访问：跨缓存行/页，x86 上 2-3 周期，ARM 上可能 **SIGBUS**
- padding 让字段落在自然边界，换取访问速度

### sizeof 与对齐

```c
printf("%zu\n", sizeof(struct test1));   /* 8 */
printf("%zu\n", _Alignof(struct test1)); /* 4（最大成员对齐） */
```

- `sizeof` 是 struct 占用的总字节数（含 padding）
- `_Alignof`（C11）是 struct 的对齐要求
- 二者关系：`sizeof % _Alignof == 0`

### packed：紧凑布局

```c
struct __attribute__((packed)) quote_hdr {
    uint32_t seq;       /* 4，偏移 0 */
    uint16_t price;     /* 2，偏移 4 */
    uint8_t  pkt_type;  /* 1，偏移 6 */
};
/* sizeof = 7，无 padding —— 与线格式一致 */
```

- GCC/Clang：`__attribute__((packed))`
- MSVC：`#pragma pack(1)` 或 `__declspec(align(1))`
- **取消所有 padding**，字段紧挨
- 用于协议头、共享内存、持久化二进制——布局必须与线格式一致

### packed 的代价

```c
struct __attribute__((packed)) bad {
    uint8_t  a;
    uint32_t b;   /* 偏移 1，非对齐 */
};

struct bad x;
x.b = 42;   /* x86：3 周期（跨缓存行）；ARM：SIGBUS */
```

- **非对齐访存**：x86 允许但有性能惩罚，ARM/MIPS/SPARC 上是**硬件异常**
- HFT 热路径：packed struct 的字段访问比普通慢 2-10 倍
- **权衡**：协议头用 packed（布局正确性优先），运行时数据用普通 struct（性能优先）

### 正确加载线格式

**方案 1：packed struct + memcpy**

```c
struct __attribute__((packed)) quote_hdr {
    uint32_t seq;
    uint16_t price;
    uint8_t  pkt_type;
};
_Static_assert(sizeof(struct quote_hdr) == 7, "quote_hdr must be 7 bytes");

struct quote_hdr hdr;
memcpy(&hdr, payload, sizeof hdr);    /* 一次性载入 */
uint32_t seq = ntohl(hdr.seq);        /* 大端转小端 */
uint16_t price = ntohs(hdr.price);
```

**方案 2：手动偏移解析（最可移植）**

```c
uint32_t seq = ntohl(*(uint32_t *)(payload + 0));   /* UB：未对齐 */
/* 正确：memcpy 到局部变量 */
uint32_t seq;
memcpy(&seq, payload + 0, 4);
seq = ntohl(seq);
```

`memcpy` 是**唯一**对齐安全的结构体读取方式，编译器优化为单条 `mov` 或 `movups`，零开销。

### 共享内存的致命陷阱

```c
struct shm_data {
    uint32_t seq;
    time_t   ts;      /* 32 位系统 4 字节，64 位系统 8 字节 */
    uint64_t order_id;
};
```

- 32 位进程和 64 位进程共享此 struct 时，`time_t` 宽度不同 → 偏移错位
- 修复：所有字段用 `uint32_t/uint64_t` 定长类型 + `packed`
- `_Static_assert` 锁定大小

### 持久化二进制的陷阱

```c
/* 进程 A 写入文件 */
struct config cfg = /* ... */;
write(fd, &cfg, sizeof cfg);

/* 进程 B（不同编译器/平台）读取 */
struct config cfg;
read(fd, &cfg, sizeof cfg);   /* 偏移可能不一致 */
```

- 不同编译器的 padding 策略可能不同
- 同一编译器 32/64 位模式不同
- **铁律**：持久化二进制必须用 `packed` 或显式偏移序列化

### 位段对齐（详见 10.5）

```c
struct flags {
    uint32_t a : 1;
    uint32_t b : 31;
};
/* sizeof = 4，位段在 uint32_t 内紧凑排列 */
```

- 位段按 bit 分配，但仍受对齐约束
- 位段顺序**平台相关**，禁用于线格式

## HFT 关联

- **协议头**：`struct eth_hdr`、`struct ip_hdr`、`struct tcp_hdr` 必须 `packed` + `_Static_assert`
- **DPDK mbuf**：`struct rte_mbuf` 字段精心重排，cache 行友好
- **订单簿**：`struct order` 按 `order_id`(8) → `price`(4) → `qty`(4) 排列，64 字节对齐填满一个缓存行
- **共享内存**：跨进程 struct 必须 `packed` + 定长类型 + `_Static_assert`
- **性能铁律**：HFT 热路径 struct 设计要考虑 cache 行（64 字节），热门字段放前 64 字节

### 实操：协议头 packed

```c
struct __attribute__((packed)) eth_hdr {
    uint8_t  dst[6];
    uint8_t  src[6];
    uint16_t type;
};
_Static_assert(sizeof(struct eth_hdr) == 14, "eth_hdr must be 14 bytes");

struct __attribute__((packed)) ip_hdr {
    uint8_t  ver_ihl;
    uint8_t  tos;
    uint16_t total_len;
    uint16_t id;
    uint16_t flags_frag;
    uint8_t  ttl;
    uint8_t  protocol;
    uint16_t checksum;
    uint32_t src_ip;
    uint32_t dst_ip;
};
_Static_assert(sizeof(struct ip_hdr) == 20, "ip_hdr must be 20 bytes");
```

### 实操：cache 行对齐

```c
struct order {
    uint64_t order_id;    /* 8 */
    uint32_t price;       /* 4 */
    uint32_t qty;         /* 4 */
    uint8_t  side;        /* 1 */
    /* 3 padding */
    uint64_t ts;          /* 8 */
    /* 总 32 字节，2 个填一个 64 字节 cache 行 */
} __attribute__((aligned(64)));   /* 强制 64 字节对齐 */
```

`__attribute__((aligned(64)))` 让 struct 起点对齐 cache 行，减少 false sharing。

### 实操：跨平台共享内存

```c
struct __attribute__((packed)) shm_order {
    uint64_t order_id;   /* 定长 8 字节 */
    uint32_t price;      /* 定长 4 字节 */
    uint32_t qty;        /* 定长 4 字节 */
    uint64_t ts;         /* 定长 8 字节 */
};
_Static_assert(sizeof(struct shm_order) == 24, "shm_order must be 24 bytes");
```

32/64 位、x86/ARM 都一致，可安全跨进程共享。
