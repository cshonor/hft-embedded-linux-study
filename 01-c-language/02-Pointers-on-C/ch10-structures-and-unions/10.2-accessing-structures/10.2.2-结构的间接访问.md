# 10.2.2 结构的间接访问

## 本节讲什么

对**struct 指针**用 **`->`** 运算符访问字段，称为"间接访问"。这是 DPDK、Linux 内核、HFT 代码**最常用**的访问方式——因为大 struct 几乎总是以指针传递，避免按值拷贝。本节剖析 `->` 的语义、与 `(*p).field` 的等价关系、空指针陷阱、以及 `const` 修饰的层次。

## 要点

### 基本用法

```c
QuoteHdr pkt;
QuoteHdr *p = &pkt;       /* p 指向 struct */
p->seq      = 10001;      /* 间接访问 */
p->price    = 9999;
p->pkt_type = PKT_QUOTE;

/* 等价写法 */
(*p).seq = 10001;         /* 啰嗦，但等价 */
```

- `p->seq` 等价 `(*p).seq`，但**更简洁**，是惯用写法
- `->` 是运算符，不是语法糖——C 标准定义的独立运算符
- 访问开销：1 次指针解引用 + 1 次 `mov`，约 4-5 周期（cache 命中）

### 汇编视角

```c
struct point { int x; int y; } *p;
p->y = 42;
```

```
movq -8(%rbp), %rax    ; 取 p 的值（指向 struct 的地址）
movl $42, 4(%rax)      ; 写 *(p + 4) = 42
```

- 先从 `p` 取出 struct 地址（1 次访存）
- 再用基址 + 编译期偏移（`+4`）写字段（1 次访存）
- 比 `.` 多一次访存——取指针本身

### 常见指针来源

```c
/* 1. 取栈上 struct 地址 */
QuoteHdr pkt;
QuoteHdr *p = &pkt;

/* 2. 堆对象 */
QuoteHdr *p = malloc(sizeof *p);

/* 3. DPDK mbuf */
struct rte_mbuf *m = rte_pktmbuf_alloc(pool);
uint32_t len = m->pkt_len;

/* 4. 报文指针强转 */
const struct eth_hdr *eth = (const struct eth_hdr *)pkt_data;
uint16_t type = ntohs(eth->type);

/* 5. 链表节点 */
struct node *n = head;
n->next->next = /* ... */;
```

### 空指针陷阱

```c
QuoteHdr *p = NULL;
p->seq = 1001;   /* UB：解引用空指针，通常 SIGSEGV */
```

- x86-64 Linux：地址 0 所在页是 unmapped，访问触发 SIGSEGV
- 内核态：NULL 解引用是 kernel oops
- **铁律**：解引用前检查 `if (p) p->seq = ...;`
- DPDK/内核有 `RTE_ASSERT(p)` 等宏做断言

### 多级 `->` 链

```c
struct node *head;
head->next->next->value = 42;
```

- 链式 `->` 每一级都是一次指针解引用
- 任一中间指针为 NULL → SIGSEGV
- cache miss 时性能急剧下降：每级 100+ 周期
- 链表遍历是 HFT 性能敏感操作，定长数组通常更优

### `->` 与 `.` 混合

```c
struct pkt_head {
    uint32_t magic;
    struct quote_hdr quote;   /* 嵌套实体 */
};

struct pkt_head *p = /* ... */;
p->quote.seq = 1001;   /* -> 然后 . */
```

- `p->quote` 返回内层 struct 实体（左值）
- 再 `.` 访问其字段
- 指针路径用 `->`，实体路径用 `.`

```c
struct outer {
    struct inner *p;   /* 指针成员 */
};

struct outer o;
o.p->field = 42;       /* . 然后 -> */
```

### 结构体含指针成员的访问链

```c
struct B { int val; };
struct A { struct B *pb; };   /* A 只存 B 的指针，不含 B 实体 */

struct B b_obj = { .val = 666 };
struct A a_obj;
a_obj.pb = &b_obj;

struct A *pa = &a_obj;
pa->pb->val = 999;   /* 两级指针解引用 */
```

内存布局：

```
pa (0x100)
 ↓
struct A [ pb = 0x200 ]      ← A 只存一个地址
0x200 → struct B { val }     ← B 本体在别处
```

- `pa->pb` 取出 `0x200`（B 的地址）
- `pa->pb->val` 跳到 `0x200` 再取 `val`
- 等价写法：`(*(pa->pb)).val`

**野指针陷阱**：`struct A` 里的 `pb` 不会自动指向有效 B 内存。如果只定义 `struct A a;` 不初始化 `a.pb`，`a.pb` 是垃圾地址，`pa->pb->val` 直接 `SIGSEGV`。

### 浅拷贝陷阱

```c
struct A a1;
a1.pb = &b_obj;

struct A a2 = a1;     /* 结构体赋值 = 浅拷贝 */
/* a2.pb 和 a1.pb 指向同一个 B！ */
a2.pb->val = 999;     /* a1.pb->val 也变成 999 */
```

结构体赋值拷贝了 `pb` 指针值（`0x200`），但两个指针指向**同一个 B 对象**。修改一个，另一个也跟着变。要独立修改，需**深拷贝**（为 `a2.pb` 分配新的 B 内存并复制内容）。

**函数参数同理**：传 `struct A *pa` 进函数，`pa->pb->val = 999` 改的就是原始 B——因为 `pb` 存的是 B 的地址，不是副本。即使值传递 `struct A a`，`a.pb` 还是指向同一个 B。

```c
const QuoteHdr *p1 = &pkt;        /* 指向 const struct：不能改 struct */
QuoteHdr *const p2 = &pkt;        /* const 指针：不能改 p，能改 struct */
const QuoteHdr *const p3 = &pkt;  /* 两者都 const */

p1->seq = 1001;   /* 编译错误：const struct */
p2->seq = 1001;   /* OK */
p2 = &other;      /* 编译错误：const 指针 */
p3->seq = 1001;   /* 编译错误 */
p3 = &other;      /* 编译错误 */
```

**经验法则**：函数参数用 `const T *` 表示"只读"，是 API 契约的一部分。

### restrict 修饰

```c
void process(QuoteHdr *restrict a, QuoteHdr *restrict b);
```

- `restrict` 承诺 `a` 和 `b` 不别名
- 允许编译器更激进优化（向量化、重排）
- 详见 ch06 指针章节

### 指针算术与 `->`

```c
struct order *base = /* 数组首地址 */;
struct order *p = base + 3;   /* 指针算术：偏移 3 个 struct */
p->seq = 1001;                /* 等价 base[3].seq */

/* 等价 */
(base + 3)->seq = 1001;
base[3].seq = 1001;
```

- `base + 3` 是 `struct order *`，指向第 3 个元素
- 指针算术按 `sizeof(struct order)` 步进

## HFT 关联

- **DPDK rte_mbuf**：几乎所有 mbuf 操作都是 `m->field`，因为 mbuf 从 mempool 分配，只有指针
- **协议头解析**：`eth->type`、`ip->protocol` 是热路径标准访问
- **订单簿条目**：`order->price`、`order->qty`，订单从池分配
- **链表节点**：`node->next`、`node->value`，链表遍历
- **性能**：`->` 比 `.` 多一次访存，cache miss 时差距 10-100 倍。HFT 数据结构设计要考虑 cache 局部性。

### 实操：DPDK 报文解析

```c
void parse_pkt(struct rte_mbuf *m) {
    void *data = rte_pktmbuf_mtod(m, void *);
    uint32_t len = m->data_len;   /* -> 访问 */

    const struct eth_hdr *eth = (const struct eth_hdr *)data;
    uint16_t eth_type = ntohs(eth->type);   /* -> 访问 */

    if (eth_type == 0x0800 && len >= 14 + 20) {
        const struct ip_hdr *ip = (const struct ip_hdr *)((uint8_t *)data + 14);
        uint8_t proto = ip->protocol;   /* -> 访问 */
        /* ... */
    }
}
```

### 实操：空指针检查

```c
void process(QuoteHdr *p) {
    if (!p) return;   /* 防御性检查 */
    /* 或 RTE_ASSERT(p); */

    p->seq = next_seq++;
    /* ... */
}

/* 调用方 */
QuoteHdr *p = lookup(seq);
if (p) process(p);   /* 先判 NULL */
```

### 实操：链表遍历的 cache 代价

```c
/* 链表遍历：每次 next 跳转可能 cache miss */
for (struct node *p = head; p; p = p->next) {
    process(p->value);
}

/* 数组遍历：连续内存，预取器有效 */
for (size_t i = 0; i < count; i++) {
    process(arr[i].value);
}
```

100 万元素遍历，链表比数组慢 5-20 倍（取决于 cache 行为）。
