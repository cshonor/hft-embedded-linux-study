# 10.2.3 结构的自引用

## 本节讲什么

struct 可以包含**指向自身类型的指针**（不能包含自身实体——大小无限递归）。这是链表、树、图等递归数据结构的根基，也是 ch12（结构体与指针）和 ch17（经典 ADT）的前置知识。本节剖析自引用的合法性、不完整类型在其中的作用、以及链表的基本操作。

## 要点

### 合法与非法自引用

```c
/* 合法：指针成员 */
typedef struct node {
    uint64_t order_id;
    struct node *next;   /* 指针，大小已知（8 字节） */
} Node;

/* 非法：实体成员 */
struct bad {
    uint64_t id;
    struct bad next;     /* 错误：大小无限递归 */
};
```

**根因**：

- 指针大小与所指类型**无关**（x86-64 上 8 字节），编译器无需知道 `struct node` 完整定义即可确定 `struct node *` 的大小
- 实体成员要求编译器已知其大小，但 `struct bad` 的大小依赖 `struct bad` 本身——无限递归

### 不完全类型的作用

```c
struct node;   /* 前置声明：不完全类型 */
typedef struct node Node;

struct node {          /* 完整定义 */
    uint64_t order_id;
    Node *next;        /* 此时 Node 仍可作指针类型 */
};
```

- 前置声明让 `struct node *` 可用
- 完整定义后才能定义实体、求 `sizeof`、访问成员
- 自引用 struct 在定义体内部，`struct node` 是不完全类型，但 `struct node *` 合法

### 链表节点

```c
typedef struct node {
    uint64_t order_id;
    uint32_t price;
    uint32_t qty;
    struct node *next;
} Node;
```

内存布局（x86-64）：

```
偏移  0    8    16   20   24
     +----+----+----+----+----+
     | id |price|qty | next |   （假设 8 字节对齐）
     +----+----+----+----+----+
                      |
                      v
                   下一个 Node
```

### 单向链表基本操作

**头插法**：

```c
Node *head = NULL;

void push_front(Node **head, uint64_t id) {
    Node *n = malloc(sizeof *n);
    if (!n) return;
    n->order_id = id;
    n->next = *head;
    *head = n;
}
```

- `head` 是 `Node **`（二级指针），让函数能修改调用方的 `head`
- 时间复杂度 O(1)

**遍历**：

```c
for (Node *p = head; p; p = p->next) {
    printf("%lu\n", p->order_id);
}
```

**查找**：

```c
Node *find(Node *head, uint64_t id) {
    for (Node *p = head; p; p = p->next) {
        if (p->order_id == id) return p;
    }
    return NULL;
}
```

**删除**：

```c
void remove(Node **head, uint64_t id) {
    Node **pp = head;
    while (*pp) {
        if ((*pp)->order_id == id) {
            Node *victim = *pp;
            *pp = victim->next;
            free(victim);
            return;
        }
        pp = &(*pp)->next;
    }
}
```

注意用 `Node **pp`（指向指针的指针）技巧，避免单独处理头节点。

### 双向链表

```c
typedef struct dnode {
    uint64_t id;
    struct dnode *prev, *next;
} DNode;
```

- 支持双向遍历
- 删除 O(1)（给定节点指针）
- Linux 内核 `list_head` 是侵入式双向链表的标准实现

### 侵入式链表（Linux 内核风格）

```c
struct list_head {
    struct list_head *prev, *next;
};

struct order {
    uint64_t id;
    struct list_head list;   /* 嵌入链表节点 */
};

/* 通过 list 字段反推 order 指针 */
#define container_of(ptr, type, member) \
    ((type *)((char *)(ptr) - offsetof(type, member)))

struct order *o = container_of(node, struct order, list);
```

- 链表节点嵌入数据结构内部，不持有数据指针
- 一个对象可挂多个链表（多个 `list_head` 成员）
- Linux 内核、DPDK 都用此模式
- `container_of` 是核心宏，通过 `offsetof` 反算外层结构

### 树与图

```c
typedef struct tree_node {
    uint64_t key;
    void *value;
    struct tree_node *left, *right;   /* 二叉树 */
} TreeNode;

typedef struct graph_node {
    uint64_t id;
    struct graph_node **neighbors;   /* 邻接表 */
    size_t degree;
} GraphNode;
```

- 树：每个节点多个子指针
- 图：邻接表用指针数组
- 都基于自引用 struct

### 循环引用与内存

自引用结构易导致**内存泄漏**：链表节点互相引用，忘记 free 整链。HFT 通常用内存池（DPDK mempool）避免 malloc/free 开销，且池有上限防止泄漏。

## HFT 关联

- **订单簿**：买卖盘链表，每个价位一个链表头
- **DPDK mempool**：空闲块用链表管理，自引用 struct
- **内核 task_struct**：进程链表、子进程链表都是自引用
- **定时器**：定时器事件用链表或最小堆，自引用节点
- **性能铁律**：链表遍历 cache 不友好，HFT 热路径优先用定长数组 + 索引

### 实操：订单簿链表

```c
typedef struct order {
    uint64_t order_id;
    uint32_t price;
    uint32_t qty;
    struct order *next;
} Order;

Order *bid_head = NULL;   /* 买盘 */

void add_bid(uint64_t id, uint32_t price, uint32_t qty) {
    Order **pp = &bid_head;
    while (*pp && (*pp)->price > price)   /* 按价格降序 */
        pp = &(*pp)->next;
    Order *o = pool_alloc();   /* 从池分配，不用 malloc */
    o->order_id = id;
    o->price = price;
    o->qty = qty;
    o->next = *pp;
    *pp = o;
}
```

### 实操：container_of 宏

```c
#include <stddef.h>

struct order {
    uint64_t id;
    struct list_head list;
};

void process_node(struct list_head *node) {
    struct order *o = container_of(node, struct order, list);
    printf("order %lu\n", o->id);
}
```

`container_of` 让链表代码与数据结构解耦——链表操作只需 `list_head *`，不关心外层类型。
