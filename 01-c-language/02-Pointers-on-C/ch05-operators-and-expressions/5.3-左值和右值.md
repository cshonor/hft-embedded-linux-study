# 5.3 左值和右值

## 本节讲什么

**左值(lvalue)** 是"有对象标识、可取址、可出现在赋值左侧"的表达式;**右值(rvalue)** 是"临时值、常出现在赋值右侧"的表达式。这个区分决定了哪些表达式能被赋值、能取址、能做 `++` 操作数 —— 也解释了为什么 `3 = x` 非法、`&(a+b)` 非法。本节讲 lvalue/rvalue、副作用、以及它们如何与序列点交互产生 UB。

## 要点

### 左值 vs 右值

| 维度 | 左值(lvalue) | 右值(rvalue) |
|------|---------------|---------------|
| 例子 | 变量 `x`、`*p`、`arr[i]`、`s.field` | 字面量 `42`、`a+b`、函数返回值 |
| 赋值左侧 | 合法 `x = 1` | 非法 `3 = x` |
| 取址 | 合法 `&x` | 非法 `&(a+b)` |
| `++`/`--` 操作数 | 合法 `x++` | 非法 `(a+b)++` |
| 本质 | 命名了内存中的对象 | 临时计算结果,无持久存储 |

- **lvalue** = "locator value",指代一块内存(可定位)
- **rvalue** = "read value",读取的值(临时)
- C 标准把 lvalue 细分为**可修改左值**(modifiable lvalue)和不可修改左值(const 对象、数组名、位域等);只有可修改左值能被赋值

### 哪些是左值

| 表达式 | 左值? | 说明 |
|--------|--------|------|
| `x`(变量) | 是 | 命名对象 |
| `*p` | 是 | 解引用得到对象 |
| `arr[i]` | 是 | 等价 `*(arr+i)` |
| `s.field` | 是 | 结构体成员 |
| `p->field` | 是 | 等价 `(*p).field` |
| `42`(字面量) | 否 | 常量,无存储 |
| `a + b` | 否 | 算术结果,临时 |
| `a == b` | 否 | 比较结果,临时 int |
| `f()`(返回非数组) | 否(通常) | 返回值临时,见下 |
| `arr`(数组名) | 是(不可修改) | 数组本身是左值,但不能赋值 |
| `s.bitfield` | 是(不可取址) | 位域是左值但 `&` 非法 |

### 函数返回值与左值

```c
int f(void){ return 42; }
int *g(void){ static int x; return &x; }

f() = 1;        /* 非法: f() 是右值 */
*g() = 1;       /* 合法: *g() 解引用返回的指针, 是左值 */
```

- 函数返回非引用类型 → 右值,不能赋值
- 函数返回指针 → 解引用后是左值,可赋值(C 没有引用,靠指针实现"返回可赋值对象")

### 副作用(side effect)

**副作用** = 求值过程中改变了环境状态:修改变量、写文件、改 `volatile` 对象等。

| 运算符 | 是否有副作用 |
|--------|--------------|
| `=` `+=` 等 | 是(改左值) |
| `++` `--` | 是(改左值) |
| `*p = ...` | 是(通过指针改对象) |
| 函数调用 | 可能(取决于函数) |
| `a + b` | 否(纯计算) |
| `a == b` | 否 |

```c
a = b;          /* 副作用: a 被改 */
a++;            /* 副作用: a 自增 */
printf("hi");   /* 副作用: 输出 */
a + b;          /* 无副作用, 死代码, -Wunused-value 警告 */
```

### 序列点与 UB(5.4.3 预告)

```c
arr[i++] = i;        /* UB: i 被修改一次但读取一次, 顺序未定义 */
a = a++ + ++a;       /* UB: 两次修改, 无序列点隔开 */
printf("%d", a++ + a++);   /* UB */
```

- 两个**序列点**之间,同一变量**最多修改一次**,且若修改则不能同时读取
- 违反 → UB,编译器可任意处理(gcc/clang 结果常不同)
- 详见 5.4.3

### 不可修改左值

```c
const int ci = 10;
int arr[10];
struct { int f : 4; } s;

ci = 20;        /* 非法: const 不可修改 */
arr = ...;      /* 非法: 数组不可赋值(但 arr[i] 可) */
&s.f;           /* 非法: 位域不可取址 */
```

- `const` 对象是左值但不可修改
- 数组名是左值但不可赋值(数组不能整体赋值)
- 位域是左值但不可取址(地址最小粒度是字节)

## 与 HFT/DPDK

### 通过指针返回可修改对象

```c
/* DPDK mempool get: 返回指针, 调用者解引用后是左值 */
struct rte_mbuf *m = rte_pktmbuf_alloc(pool);
m->data_len = 64;          /* *(&m->data_len) = 64, 左值赋值 */
m->pkt_len  = 64;
```

- C 没有"引用",靠"返回指针 + 解引用"实现可修改返回
- 这是 DPDK/Libevent 等库 API 的常见模式

### 位域与硬件寄存器

```c
struct nic_regs {
    uint32_t tx_enable : 1;
    uint32_t rx_enable : 1;
    uint32_t link_mode : 3;
    /* ... */
} __attribute__((packed));
volatile struct nic_regs *nic = (volatile struct nic_regs *)0xFB000000;

nic->tx_enable = 1;        /* 位域是左值, 可赋值 */
/* &nic->tx_enable; */     /* 非法: 位域不可取址 */
```

- 位域让硬件寄存器位字段可读可写,但不能取址(地址粒度是字节)
- 实际驱动更倾向用位掩码 + 整体读写,位域有可移植性问题(ch10)

### 副作用与优化

```c
volatile uint32_t *flag = (volatile uint32_t *)0x1000;
while (!*flag) ;           /* 副作用: 每次读 *flag, volatile 保证不被优化掉 */
```

- 无副作用的纯计算表达式会被编译器消除(死代码消除)
- `volatile` 访问是有副作用的,编译器不能消除/合并

## 常见误区

| 误区 | 真相 |
|------|------|
| `3 = x` 合法 | 非法,3 是右值不可赋值 |
| `&(a+b)` 合法 | 非法,a+b 是右值无地址 |
| 数组名可赋值 | 不可,数组名是不可修改左值 |
| 位域可取址 | 不可,地址最小粒度是字节 |
| 函数返回值总能赋值 | 返回非指针类型是右值,不能赋值 |
| `a++ + a++` 是 2a+1 | UB,序列点内两次修改 |

## 实操

```bash
cat > t.c <<'EOF'
#include <stdio.h>
int x = 10;
int *ret_ptr(void){ return &x; }   /* 返回指针, 解引用是左值 */
int ret_val(void){ return 42; }    /* 返回值, 右值 */
int main(void){
  *ret_ptr() = 20;                  /* 合法 */
  printf("x=%d\n", x);              /* 20 */
  /* ret_val() = 1; */              /* 非法: 非左值 */
  /* &(ret_val()); */               /* 非法: 右值取址 */
  int a = 1;
  /* a = a++ + ++a; */              /* UB, 注释掉 */
  return 0;
}
EOF
gcc -std=c11 -Wall t.c -o t && ./t
```

## 代码自测

**题目 1：** 以下哪些是合法的左值？
```c
int x = 1, arr[5] = {0};
// A: x
// B: x + 1
// C: arr[2]
// D: &x
// E: *(&x)
```

<details>
<summary>参考答案</summary>

A、C、E 是左值。A x 是变量，可被赋值。C arr[2] 是数组元素，可被赋值。E *(&x) 解引用后等价于 x，是左值。B x + 1 是算术表达式的结果，是右值。D &x 是地址值，是右值。左值是可以出现在赋值号左边的表达式。

</details>
