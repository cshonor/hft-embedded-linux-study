# 5.4 表达式求值

## 本节讲什么

表达式如何**求值** —— 隐式转换、算术转换、优先级、结合性、副作用与序列点。这一节是 ch05 的核心,也是线上网关"逻辑错乱、数值溢出、死循环"的头号理论来源。三个小节分别讲隐式转换、算术转换、优先级与求值顺序。

## 要点

### 表达式的组成

表达式 = 运算符 + 操作数 + 求值规则。求值规则决定:

1. **类型转换**:操作数先转成共同类型(5.4.1 / 5.4.2)
2. **结合顺序**:优先级 + 结合性决定运算符如何配对(5.4.3)
3. **求值顺序**:操作数左右谁先求值(多数未指定!)、副作用何时生效(序列点)
4. **溢出/UB**:有符号溢出、序列点内多次修改 → 未定义行为

### 副作用与序列点(关键概念)

- **副作用**:求值过程中改变状态(`=`、`++`、`--`、函数调用写文件等)
- **序列点(sequence point)**:程序执行的某些点,此前所有副作用已生效,此后尚未开始
  - `;` 语句结尾
  - `&&` `||` 左右操作数之间(短路保证)
  - `?:` 第一与第二/三操作数之间
  - 逗号 `,` 左右操作数之间
  - 函数调用:参数求值完成、进入函数体前(C99 前);C11 改为"参数求值与函数体执行间有序列点"
- **规则**:两个序列点之间,同一对象**最多修改一次**,且若修改则不能在该区间内被读取(除计算新值)
  - 违反 → **UB**

```c
arr[i++] = i;          /* UB: i 修改一次, 但读取一次, 顺序未定 */
a = a++ + ++a;         /* UB: 两次修改, 无序列点 */
printf("%d", a++ + a++);   /* UB */
```

### 常见 UB 速查

| 表达式 | 问题 |
|--------|------|
| `a++ + a++` | 序列点内两次修改 a |
| `arr[i++] = i` | i 修改一次, 但读取顺序未定 |
| `a = a++ + ++a` | 两次修改 |
| `i = i++` | 修改一次 + 赋值, UB |
| `1 << 32`(int 32 位) | 移位 ≥ 位宽 |
| `INT_MAX + 1`(signed) | 有符号溢出 |
| `*(int *)0` | 空指针解引用 |

> **规范**:单表达式内对同一变量**最多一次修改**,不依赖未指定求值顺序。复杂副作用拆成多语句。

### 求值顺序未指定的场景

```c
int i = 1;
printf("%d %d\n", i, i++);    /* 求值顺序未指定, 输出可能是 "1 1" 或 "2 1" */

f(i, i++);                    /* 参数求值顺序未指定 */
a[i] + a[i++];                /* UB, 序列点问题 */
```

- 函数参数求值顺序**未指定**(不是 UB,是未指定行为,结果任一合法)
- 但若参数有副作用导致同一变量多次修改 → UB

## 与 HFT/DPDK

### 数值溢出的实战事故

```c
/* 反例: 价格累加溢出 */
int32_t total = 0;
for (int i = 0; i < n; i++)
    total += prices[i];       /* 累加可能溢出 INT_MAX → UB */

/* 正解: 用 int64_t 或检查 */
int64_t total = 0;
for (int i = 0; i < n; i++) {
    if (total > INT64_MAX - prices[i]) {
        /* 溢出检查 */
        return -EOVERFLOW;
    }
    total += prices[i];
}
```

- 有符号溢出是 UB,编译器可假定"不溢出"做激进优化 → 结果与预期差很远
- HFT 价格累加用 int64_t 留足余量,或用 __int128 临时累加

### 序列号环绕

```c
uint32_t seq = 0;
uint32_t next(void){ return ++seq; }   /* uint 溢出环绕, 定义良好 */

/* 比较序列号大小要考虑环绕 */
bool before(uint32_t a, uint32 b) {
    return (int32_t)(a - b) < 0;   /* 有符号差判断 */
}
```

- TCP 序列号、报文序号常 uint32,会环绕;比较"先后"用有符号差
- 无符号溢出是定义良好的环绕,不是 UB

### 移位 UB 的实战

```c
/* 反例: 32 位 int 移 32 位 */
uint64_t mask = (1 << 32) - 1;    /* UB! 1 是 int, <<32 超出 */
/* 正解 */
uint64_t mask = (1ULL << 32) - 1;  /* 用 ULL 避免窄类型 */

/* 反例: 循环里移位变量 */
for (int s = 0; s <= 32; s++) {
    uint32_t v = 1u << s;          /* s==32 时 UB */
}
/* 正解: s < 32 或用 64 位 */
for (int s = 0; s < 32; s++) {
    uint32_t v = 1u << s;
}
```

### 编译器警告

```bash
-Wconversion              # 隐式转换可能丢信息
-Wsign-compare            # 有符号/无符号比较
-Wsequence-point          # 序列点 UB(a++ + a++)
-Wshift-count-overflow    # 移位 ≥ 位宽
-Wstrict-overflow        # 有符号溢出优化假定
-Wall -Wextra -Wpedantic # 综合基础
```

## 常见误区

| 误区 | 真相 |
|------|------|
| `a++ + a++` 是 2a+1 | UB,gcc/clang 结果常不同 |
| 有符号溢出"环绕" | UB,编译器可激进优化 |
| 函数参数从左到右求值 | 未指定,顺序任意 |
| `1 << 32` 合法 | UB(int 32 位);要 `1ULL << 32` |
| 序列点只在 `;` | 还有 `&&` `||` `?:` `,` 函数调用边界 |

## 实操

```bash
# 1. 序列点 UB, 不同编译器不同结果
cat > t.c <<'EOF'
#include <stdio.h>
int main(void){
  int a = 1;
  printf("%d %d\n", a, a++);    /* 求值顺序未指定 */
  int b = 1;
  int c = b++ + b++;            /* UB */
  printf("c=%d\n", c);
  return 0;
}
EOF
gcc -std=c11 -Wall -Wsequence-point t.c -o t && ./t
clang -std=c11 -Wsequence-point t.c -o t2 && ./t2   # 结果可能不同

# 2. 移位 UB
cat > s.c <<'EOF'
#include <stdint.h>
int main(void){
  uint32_t v = 1u << 32;     /* UB */
  return (int)v;
}
EOF
gcc -std=c11 -Wall -Wshift-count-overflow s.c
```

## 代码自测

**题目 1：** 以下代码的行为是定义的还是未定义的？为什么？
```c
int i = 1;
printf("%d %d\n", i++, i++);
```

<details>
<summary>参考答案</summary>

未定义行为。i++ 的副作用（自增）何时发生取决于编译器。在同一个表达式中多次修改同一个变量且没有序列点分隔，是 UB。不同编译器可能输出 1 2 或 2 1 或其他值。函数参数的求值顺序也是未指定的。

</details>
