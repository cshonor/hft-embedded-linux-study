# 5.4.3 优先级和求值顺序

## 本节讲什么

**优先级**决定运算符谁先结合;**结合性**决定同级从左还是从右;**求值顺序**决定操作数左右谁先算、副作用何时生效。三者里**求值顺序**是最坑的 —— C 故意不指定多数运算符的求值顺序,导致 `a++ + a++` 这类 UB。本节讲优先级表、结合性、序列点与 UB,以及工程上"不背表加括号"的规范。

## 要点

### 优先级表(自高到低,15 级)

| 级 | 运算符 | 结合性 | 备注 |
|----|--------|--------|------|
| 1 | `()` `[]` `.` `->` `++`(后置) `--`(后置) | 左 | 后缀 |
| 2 | `!` `~` `++`(前置) `--`(前置) `+` `-` `*` `&` `sizeof` `(type)` `_Alignof` | **右** | 一元 |
| 3 | `*` `/` `%` | 左 | 乘除模 |
| 4 | `+` `-` | 左 | 加减 |
| 5 | `<<` `>>` | 左 | 移位 |
| 6 | `<` `<=` `>` `>=` | 左 | 关系 |
| 7 | `==` `!=` | 左 | 判等 |
| 8 | `&` | 左 | 位与 |
| 9 | `^` | 左 | 位异或 |
| 10 | `\|` | 左 | 位或 |
| 11 | `&&` | 左 | 逻辑与(**短路**) |
| 12 | `\|\|` | 左 | 逻辑或(**短路**) |
| 13 | `?:` | **右** | 三元(**短路**) |
| 14 | `=` `+=` `-=` 等 | **右** | 赋值 |
| 15 | `,` | 左 | 逗号 |

### 易错优先级(常被误记)

| 表达式 | 实际结合 | 常见误解 |
|--------|----------|----------|
| `a & b == c` | `a & (b == c)` | `(a & b) == c` —— 位与比判等**低**! |
| `a + b << 1` | `(a + b) << 1` | `a + (b << 1)` —— 加法比移位**高** |
| `*p++` | `*(p++)` | `(*p)++` —— 后置 ++ 优先级高 |
| `a < b && c < d` | `(a < b) && (c < d)` | 关系比逻辑与高,符合直觉 |
| `p->f++` | `(p->f)++` | 后缀同级,左结合 |

> ⚠️ **`a & b == c` 是最经典陷阱**:位与 `&` 优先级低于 `==`,所以是 `a & (b==c)`。要 `(a & b) == c` 必须加括号。

### 结合性

| 类型 | 结合性 | 例子 |
|------|--------|------|
| 多数双目算术/关系/逻辑/位 | **左** | `a-b-c` = `(a-b)-c` |
| 一元、赋值、`?:` | **右** | `a=b=c` = `a=(b=c)`,`*p++` 中 ++ 先 |
| 后缀 `() [] . ->` | 左 | `a.b.c` = `(a.b).c` |

```c
a = b = c = 0;        /* 右结合: a = (b = (c = 0)) */
*p++;                 /* *(p++), 后置 ++ 先, 不是 (*p)++ */
*++p;                 /* *(++p) */
arr[i++];             /* arr[(i++)] */
```

### 求值顺序(关键)

**C 不指定多数运算符的操作数求值顺序**(除少数例外):

| 运算符 | 求值顺序 |
|--------|----------|
| `&&` `||` | **左到右,短路**(保证) |
| `?:` | 条件先,再求被选分支 |
| `,`(逗号) | **左到右**(保证) |
| 函数调用 | 参数求值顺序**未指定**,但都在调用前完成 |
| `+` `-` `*` `/` 等双目 | **未指定**左右谁先 |
| 赋值 `=` | 右操作数先求?**未指定**;副作用何时生效靠序列点 |

```c
int i = 1;
printf("%d %d\n", i, i++);   /* 参数求值顺序未指定, 输出可能是 "1 1" 或 "2 1" */

f(g(), h());                 /* g/h 谁先未指定 */
a[i] + i++;                  /* UB: 序列点内修改+读取 i */
```

### 序列点与 UB(5.4 详)

**序列点**(sequence point)是"此前副作用全生效、此后未开始"的执行点:

- `;` 语句结尾
- `&&` `||` `?:` `,` 操作数之间
- 函数调用:参数求值完成、进入函数体前(C99);C11 改为"完整表达式求值"

**规则**:两序列点间,**同一对象最多修改一次**,且若修改则不能同时被读取(除计算新值)。违反 → **UB**。

```c
a++ + a++;            /* UB: 两次修改, 无序列点隔开 */
arr[i++] = i;          /* UB: 修改 i 一次, 读取一次, 顺序未定 */
a = a++;               /* UB: 修改两次(自增 + 赋值) */
i = i++ + 1;           /* UB */
printf("%d", a++ + a++);   /* UB */
```

> **规范**:单表达式内对同一变量**最多一次修改**;有依赖顺序的副作用拆成多语句。

### 短路求值

```c
if (p && p->len > 0)   /* p==NULL 时短路, 不解引用 p->len */
if (q || cached)        /* q 真时短路, 不求 cached */
```

- `&&` 左假 → 不求右;`||` 左真 → 不求右
- 短路是"安全空指针检查"的语义基础,**不能重排序**
- 这是 `&&`/`||` 求值顺序被**保证**的原因(其他双目未保证)

## 与 HFT/DPDK

### 复杂表达式加括号

```c
/* 反例: 位与比判等低 */
if (flags & MASK == EXPECTED)   /* 实为 flags & (MASK == EXPECTED) */

/* 正解: 显式括号 */
if ((flags & MASK) == EXPECTED)
```

- HFT 协议字段提取常 `flags & MASK`,与 `==` 比较时**必须加括号**
- 规范:位运算、移位、三元混用时一律加括号,不靠背优先级表

### 短路保障安全

```c
if (pkt && pkt->len >= HDR_MIN && pkt->data[0] == SYNC) {
    parse(pkt);
}
```

- 链式 `&&` 短路:任一假则后面不求值,安全
- 顺序:从便宜到昂贵(指针非空 < 长度检查 < 字节比较)

### 序列点 UB 的真实事故

```c
/* 反例: 日志里 i 被两次修改 */
log("port %d queue %d", port++, queue++);   /* 参数求值顺序未定, port/queue 哪个先 ++ 不确定 */

/* 正解: 先取值再自增 */
int p = port++, q = queue++;
log("port %d queue %d", p, q);
```

- 函数参数有副作用时,顺序未定 → 行为不可预测
- 拆成多语句,显式控制顺序

### 编译器警告

```bash
-Wsequence-point          # 序列点 UB(a++ + a++)
-Wparentheses             # 优先级可能不符直觉(位与/移位/赋值)
-Wshift-parentheses       # 移位需括号
-Wsign-compare            # 有符号/无符号比较
-Wconversion              # 隐式转换丢信息
```

## 常见误区

| 误区 | 真相 |
|------|------|
| `a & b == c` 是 `(a & b) == c` | 不,是 `a & (b == c)`,位与比判等低 |
| `*p++` 是 `(*p)++` | 不,是 `*(p++)`,后置 ++ 先 |
| `a + b << 1` 是 `a + (b << 1)` | 不,是 `(a + b) << 1`,加法比移位高 |
| 双目运算符左右求值顺序保证 | 不,未指定(除 `&&`/`||`/`?:`/`,`) |
| `a++ + a++` 是 2a+1 | UB,gcc/clang 结果常不同 |
| 函数参数从左到右求值 | 未指定,顺序任意 |

## 实操

```bash
cat > t.c <<'EOF'
#include <stdio.h>
int main(void){
  /* 优先级陷阱 */
  int flags = 0x6, MASK = 0x2, EXPECTED = 0x2;
  printf("(flags & MASK) == EXPECTED: %d\n", (flags & MASK) == EXPECTED);  /* 1 */
  printf("flags & MASK == EXPECTED: %d\n", flags & MASK == EXPECTED);      /* 0! */

  /* 求值顺序 UB */
  int i = 1;
  printf("%d %d\n", i, i++);    /* 未指定, 可能 "1 1" 或 "2 1" */
  /* int bad = i++ + i++; */    /* UB */
  return 0;
}
EOF
gcc -std=c11 -Wall -Wparentheses -Wsequence-point t.c -o t && ./t

# 位掩码函数
cat > mask.c <<'EOF'
#include <stdint.h>
static inline void set_bit(uint32_t *f, int b){ *f |= (1u << b); }
static inline void clr_bit(uint32_t *f, int b){ *f &= ~(1u << b); }
static inline int  tst_bit(uint32_t f, int b){ return (f >> b) & 1u; }
EOF
gcc -std=c11 -O2 -S mask.c -o mask.s   # 看是否优化成 bts/btr 指令
```

## 代码自测

**题目 1：** 以下代码输出什么？
```c
int a[5] = {10, 20, 30, 40, 50};
int i = 1;
printf("%d\n", a[i++] + a[i++]);
```

<details>
<summary>参考答案</summary>

未定义行为。i++ 的副作用顺序未定义——两个 a[i++] 的求值顺序取决于编译器，且 i 被修改两次。可能输出 30 或 50 或其他值。不要在同一个表达式中对同一变量多次自增。

</details>
