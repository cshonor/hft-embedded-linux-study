# 17.4.2 删除节点

## 本节讲什么

BST 的删除：分叶子、单子、双子三种情况，双子情况用中序后继替换。这是 BST 最复杂的操作——指针改写多、容易写错。本节重点讲三种情况的处理、中序后继的查找、载荷所有权、以及 HFT 订单簿撤单的删除路径。

## 要点

### 三种删除情况

#### 情况 1：叶子节点（无子节点）

直接 free：

```c
    parent
       |
       N        →    parent
                     |
                    NULL
```

```c
if (!n->left && !n->right) {
    /* 叶子, 父节点对应指针置 NULL */
    if (parent->left == n) parent->left = NULL;
    else parent->right = NULL;
    free(n);
}
```

#### 情况 2：单子节点

用子节点顶替：

```c
    parent              parent
      |                   |
      N          →        child
     /
   child
```

```c
TreeNode *child = n->left ? n->left : n->right;
if (parent->left == n) parent->left = child;
else parent->right = child;
free(n);
```

#### 情况 3：双子节点（最复杂）

用中序后继（右子树最小节点）替换 N 的 key，然后删除后继：

```c
    parent              parent
      |                   |
      N        →        succ
     / \                 / \
    L   R               L   R'
       /                   /
      ...                 ...
       \
        succ  ← 右子树最小, 删除后 R' 是 succ 原右子树
```

中序后继 `succ` 是右子树最左节点，它一定没有左子树（否则更左的节点才是后继）。删除 `succ` 是"情况 1 或 2"。

```c
TreeNode *succ = find_min(n->right);   /* 右子树最左 */
void *succ_key = succ->key;
void *succ_payload = succ->payload;

/* 递归删除 succ (它一定无左子树, 走情况 1 或 2) */
n->right = tree_delete(n->right, succ->key, cmp);

/* 用 succ 的 key/payload 覆盖 n */
n->key = succ_key;
n->payload = succ_payload;
/* succ 节点已在 tree_delete 里 free */
```

### 递归删除完整实现

```c
TreeNode *tree_delete(TreeNode *root, const void *key, cmp_fn cmp,
                      void (*free_cb)(void *))
{
    if (!root) return NULL;   /* 未找到 */
    
    int c = cmp(key, root->key);
    if (c < 0) {
        root->left = tree_delete(root->left, key, cmp, free_cb);
    } else if (c > 0) {
        root->right = tree_delete(root->right, key, cmp, free_cb);
    } else {
        /* 找到, 三种情况 */
        if (!root->left && !root->right) {
            /* 叶子 */
            if (free_cb) free_cb(root->key);
            free(root);
            return NULL;
        }
        if (!root->left) {
            /* 只有右子 */
            TreeNode *r = root->right;
            if (free_cb) free_cb(root->key);
            free(root);
            return r;
        }
        if (!root->right) {
            /* 只有左子 */
            TreeNode *l = root->left;
            if (free_cb) free_cb(root->key);
            free(root);
            return l;
        }
        /* 双子: 找中序后继 */
        TreeNode *succ = root->right;
        while (succ->left) succ = succ->left;
        
        /* 交换 key/payload (或覆盖) */
        void *old_key = root->key;
        root->key = succ->key;
        root->payload = succ->payload;
        succ->key = old_key;   /* 让 tree_delete 释放 old_key */
        
        /* 删除后继 (succ 在右子树, 一定无左子) */
        root->right = tree_delete(root->right, succ->key, cmp, free_cb);
    }
    return root;
}
```

### 中序后继 vs 中序前驱

双子删除可用后继（右子树最小）或前驱（左子树最大）：

- **后继**：右子树最左节点
- **前驱**：左子树最右节点

两者都能保持 BST 性质。选择策略：

- 交替使用（平衡子树高度）
- 固定选后继（实现简单）
- 按子树大小选（选更大的子树的前驱/后继，减少不平衡）

平衡树删除后需要重平衡，选后继还是前驱影响旋转次数。

### 载荷所有权

删除节点时，节点本身 free，但载荷（key/payload）由谁释放？

- `free_cb` 非空：调用 `free_cb(root->key)` 释放载荷
- `free_cb` 为 NULL：载荷由外部管理，不释放

双子情况最微妙——`succ` 的 key 被搬到 `root`，`root` 的原 key 要释放。代码里通过"交换 key 再递归删除 succ"实现——递归删除时 `free_cb` 会释放"原 root key"（现在在 succ 节点）。

### 删除的平衡维护

普通 BST 删除不维护平衡，可能让树越来越歪。平衡树（AVL/红黑）删除后需要重平衡：

- AVL：检查高度差，旋转
- 红黑：颜色调整 + 旋转

删除的平衡维护比插入复杂——可能触发多次旋转向上传播。红黑树删除实现是数据结构课程最难的代码之一。

### 删除的复杂度

| 情况 | 复杂度 |
|------|--------|
| 叶子 | O(log n) 查找 + O(1) free |
| 单子 | O(log n) 查找 + O(1) 链接 |
| 双子 | O(log n) 查找 + O(log n) 找后继 + O(log n) 删后继 |
| 平衡维护 | O(log n) 旋转 |

最坏 O(log n)，但常数因子比插入大（多次指针改写）。

### HFT 订单簿撤单

```c
/* 撤单: 按 order_id 查找并删除 */
void cancel_order(OrderBook *book, uint64_t order_id)
{
    TreeNode *level = tree_find(book->levels, &order_id, cmp_order);
    if (!level) return;   /* 未找到 */
    
    /* 从价位挂单链表删除 */
    list_remove(&level->orders, &order_id, cmp_order);
    
    if (list_empty(level->orders)) {
        /* 价位空了, 删除价位节点 */
        book->levels = tree_delete(book->levels, &level->price, cmp_price, free_level);
    }
}
```

撤单路径：BST 查找价位 → 链表删除挂单 → 价位空则 BST 删除价位节点。

### 删除与并发

BST 删除的指针改写多，多线程并发删除极易破坏结构。HFT 订单簿通常单线程处理（策略线程独占），避免并发删除。若必须并发，用读写锁或无锁 BST（极复杂）。

## HFT 关联

- **订单簿撤单**：BST 查找价位 + 链表删挂单 + 价位空则 BST 删节点
- **会话断开**：BST 删除会话节点，free_cb 释放连接资源
- **mempool 节点归还**：删除的节点归还 mempool 而非 free
- **单线程独占**：订单簿 BST 单线程处理，避免并发删除破坏
- **平衡维护**：订单簿频繁插入/删除，必须平衡树，否则退化 O(n)
- **中序后继选择**：订单簿按价格组织，后继是"次优价位"，删除最优价位后后继顶上
- **载荷所有权**：删除价位节点时，挂单链表通过 free_cb 释放
- **延迟稳定**：平衡树删除 O(log n) 稳定，HFT 撤单延迟可预测

## 代码自测

**题目 1：** 以下 BST 删除节点操作中，删除有两个子节点的节点时用什么策略？
```c
// 删除节点 node（有两个子节点）
// 策略：用右子树的最小值替换 node 的值，然后删除右子树的最小值节点
```

<details>
<summary>参考答案</summary>

用右子树的最小值（或左子树的最大值）替换被删除节点的值，然后删除右子树最小值节点。右子树最小值节点最多有一个右子节点，删除简单。这种策略保持 BST 性质：左 < 根 < 右。另一种选择是用左子树最大值替换——两种都可以，保持一致即可。

</details>
