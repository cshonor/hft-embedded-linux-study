# 17.5.1 拥有超过一种的类型

## 本节讲什么

`void*` 通用载荷的完整设计：三大回调的语义、通用链表/哈希表的完整 API、链地址法哈希的实现要点、与内核 `list_head` 侵入式设计的对比、条件编译切换底层。这是 ADT 泛型化的核心——一套容器管所有类型。

## 要点

### 三大回调详解

#### cmp：比较函数

```c
int cmp(const void *a, const void *b);
```

- 返回 `< 0`：a < b
- 返回 `0`：a == b
- 返回 `> 0`：a > b

用于 BST 插入/查找/删除、`qsort`、`bsearch`、`list_find`、`hash` 链冲突时比较。

常见错误：

- 整数减法溢出（`return *(int*)a - *(int*)b`）
- 浮点 NaN 破坏传递性
- 不满足严格弱序（`<=` 而非 `<`）

#### handler：遍历回调

```c
void handler(void *data, void *arg);
```

- `data`：当前元素载荷
- `arg`：上下文（闭包模拟）

用于 `foreach` 批量处理、导出、过滤。`arg` 让回调能访问外部状态（如累加器、输出缓冲）。

#### free_cb：释放回调

```c
void free_cb(void *data);
```

destroy 时对每个载荷调用。传 `free` 释放堆内存，传 `mempool_put` 归还池，传 `NULL` 不释放。

### 通用链表完整 API

```c
/* list.h */
typedef struct List List;
typedef int  (*cmp_fn)(const void *, const void *);
typedef void (*handler_fn)(void *, void *);
typedef void (*free_cb_fn)(void *);

List   *list_create(void);
int     list_push_front(List *l, void *data);
int     list_push_back(List *l, void *data);
void   *list_pop_front(List *l);
void   *list_pop_back(List *l);
void   *list_front(const List *l);
void   *list_back(const List *l);
void   *list_find(const List *l, const void *key, cmp_fn cmp);
int     list_remove(List *l, const void *key, cmp_fn cmp);
size_t  list_len(const List *l);
int     list_empty(const List *l);
void    list_foreach(const List *l, handler_fn h, void *arg);
void    list_destroy(List **l, free_cb_fn free_cb);
```

一套 API 管任意类型——行情、订单、设备、会话，全用同一套容器。

### 链地址法哈希表

```c
struct Hash {
    List **buckets;      /* 每个桶是一条链表 */
    size_t nbuckets;
    hash_fn hash;        /* 哈希函数 */
    cmp_fn  cmp;         /* 键比较 */
    size_t len;          /* 总元素数 */
};

Hash *hash_create(size_t nbuckets, hash_fn hash, cmp_fn cmp)
{
    Hash *h = calloc(1, sizeof *h);
    h->buckets = calloc(nbuckets, sizeof(List *));
    h->nbuckets = nbuckets;
    h->hash = hash;
    h->cmp = cmp;
    for (size_t i = 0; i < nbuckets; i++)
        h->buckets[i] = list_create();
    return h;
}

int hash_insert(Hash *h, void *key, void *value)
{
    unsigned long idx = h->hash(key) % h->nbuckets;
    /* 检查是否已存在 (链上查找) */
    if (list_find(h->buckets[idx], key, h->cmp)) return -1;
    /* 插入链头 */
    list_push_front(h->buckets[idx], make_entry(key, value));
    h->len++;
    return 0;
}

void *hash_find(Hash *h, const void *key)
{
    unsigned long idx = h->hash(key) % h->nbuckets;
    Entry *e = list_find(h->buckets[idx], key, h->cmp);
    return e ? e->value : NULL;
}
```

链地址法：每桶一条链表，冲突元素挂链。简单、稳定、负载因子可超 1。

### 哈希函数选择

| 函数 | 特点 | 适用 |
|------|------|------|
| 除留余数 `key % prime` | 简单 | 整数 key |
| FNV-1a | 字节串通用，质量好 | 字符串 key |
| MurmurHash3 | 速度+质量均衡 | 通用 |
| CityHash/xxHash | 极快，Google 出品 | 大数据 |
| Identity `key` | key 本身是好的哈希 | 已均匀分布 |

HFT 合约代码是整数，用除留余数够用。会话 ID 若是字符串，用 FNV-1a。

### 负载因子与扩容

```
负载因子 = len / nbuckets
```

- 负载因子 > 0.75 → 链变长，查找退化 → 扩容（rehash）
- 扩容：分配 2x 桶，所有元素重新哈希搬到新桶
- rehash 是 O(n) 操作，瞬间延迟尖峰

HFT 数据面哈希表预分配足够大，避免运行时 rehash。控制面可接受 rehash。

### 哈希表 vs BST vs 有序数组

| 结构 | 查找 | 插入 | 范围查询 | 有序遍历 | 内存 | HFT 用途 |
|------|------|------|----------|----------|------|----------|
| 哈希表 | O(1) 均摊 | O(1) 均摊 | 不支持 | 不支持 | 桶+链 | 合约/会话表 |
| BST | O(log n) | O(log n) | 支持 | 支持 | 节点分散 | 订单簿价位 |
| 有序数组 | O(log n) | O(n) | 支持 | 支持 | 连续 | 静态表 |

HFT 微秒级精确查找用哈希表，需要范围/有序用 BST 或有序数组。

### 内核 list_head 侵入式设计对比

通用容器的 `void*` 包裹模式：

```c
struct Node { void *payload; struct Node *next; };
/* 载荷被 Node 包裹, 通过 payload 指针访问 */
```

内核 `list_head` 侵入式模式：

```c
struct list_head { struct list_head *next, *prev; };

struct Order {
    uint64_t id;
    int64_t price;
    struct list_head node;   /* 嵌入链表节点 */
};

/* 通过 container_of 从 node 反向定位 Order */
#define container_of(ptr, type, member) \
    ((type *)((char *)(ptr) - offsetof(type, member)))

list_for_each(pos, &order_list) {
    Order *o = container_of(pos, Order, node);
    process(o);
}
```

侵入式优势：

- 无 `void*` 间接，载荷直接内嵌
- 一个结构可挂多个链表（多个 `list_head` 成员）
- 零额外内存开销（节点就是结构的一部分）
- 类型安全（`container_of` 编译期类型检查）

侵入式劣势：

- 载荷必须侵入式修改（加 `list_head` 成员）
- 不能用同一载荷挂不同类型链表
- C++ 不友好（侵入式破坏封装）

HFT 订单簿挂单链表常用侵入式（`struct Order` 内嵌 `list_head`），通用容器用 `void*`。

### private_data：void* 闭包

内核回调常带 `void *private_data`（或 `priv`）：

```c
void callback(void *data, void *private_data)
{
    MyContext *ctx = private_data;
    /* 用 ctx 访问闭包状态 */
}
```

这是 C 语言的闭包模拟——`void*` 携带上下文，回调内转型使用。DPDK `rte_mempool` 的 ctor/dtor 钩子、Linux 内核的 `file_operations` 都用此模式。

### 条件编译切换底层

```c
/* config.h */
#ifdef HFT_DATA_PLANE
#define HFT_USE_RING_QUEUE 1
#define HFT_USE_MEMPOOL    1
#else
#define HFT_USE_RING_QUEUE 0
#define HFT_USE_MEMPOOL    0
#endif

/* queue.h */
#if HFT_USE_RING_QUEUE
#include "queue_ring.h"
#else
#include "queue_list.h"
#endif
```

数据面编译时切到环形 + mempool，控制面用链表 + malloc，业务代码不变。

## HFT 关联

- **合约代码表**：哈希表，启动加载，运行时只读
- **会话表**：哈希表，连接/断开频繁，O(1) 查找
- **订单 ID 查找**：哈希表，撤单时 O(1) 定位
- **订单簿价位**：BST 或专用结构，需范围查询
- **挂单链表**：侵入式 list_head，零 void* 开销
- **rte_hash**：DPDK 哈希表，无锁读 + CAS 写
- **free_cb 与 mempool**：容器 destroy 传 mempool_put 归还载荷
- **条件编译切换**：数据面环形+mempool、控制面链表+malloc
- **private_data 闭包**：回调 + void* arg 模拟闭包，DPDK/内核通用
