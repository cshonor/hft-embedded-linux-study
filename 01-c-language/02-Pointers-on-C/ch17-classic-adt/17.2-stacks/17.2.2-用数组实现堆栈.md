# 17.2.2 用数组实现堆栈

## 本节讲什么

栈的数组实现：固定容量或动态扩容的连续缓冲区 + `top` 索引。这是 HFT 数据面最友好的栈实现——无 per-push malloc、cache 友好、延迟可预测。本节重点讲 `top` 索引语义、扩容策略、与环形缓冲区的对比。

## 要点

### 结构定义

```c
struct Stack {
    void **buf;      /* 指针数组, 每个元素是 void* 载荷 */
    size_t cap;      /* 容量 */
    size_t top;      /* 栈顶, 指向下一个空位 */
};
```

`top` 语义：指向下一个空位。栈空时 `top == 0`，栈满时 `top == cap`。元素 `buf[0]` 是栈底，`buf[top-1]` 是栈顶。

### push 实现

```c
int stack_push(Stack *s, void *data)
{
    if (s->top >= s->cap) {
        /* 固定容量: 返回错误 */
        if (s->cap == 0) return -1;
        
        /* 动态扩容: realloc */
        size_t newcap = s->cap * 2;
        void **newbuf = realloc(s->buf, newcap * sizeof(void *));
        if (!newbuf) return -1;
        s->buf = newbuf;
        s->cap = newcap;
    }
    s->buf[s->top++] = data;   /* 先写入, 再自增 */
    return 0;
}
```

关键点：

- 先检查 `top >= cap`，满了才扩容或报错
- `realloc` 必须用临时指针（17.1 详述）
- `s->buf[s->top++] = data` 是后自增——先写入当前 top 位置，再 top+1

### pop 实现

```c
void *stack_pop(Stack *s)
{
    if (s->top == 0) return NULL;   /* 空栈 */
    return s->buf[--s->top];        /* 先自减, 再读出 */
}
```

关键点：

- `--s->top` 是前自减——先把 top 减 1，再读 `buf[top]`
- 不清零 `buf[top]`（可选，帮助 ASan 检测 use-after-pop，但增加开销）
- 空栈返回 NULL，注意 NULL 歧义（17.2.1）

### peek 实现

```c
void *stack_peek(const Stack *s)
{
    if (s->top == 0) return NULL;
    return s->buf[s->top - 1];   /* 读 top-1 位置, 不改 top */
}
```

### create 与 destroy

```c
Stack *stack_create(size_t cap)
{
    Stack *s = malloc(sizeof *s);
    if (!s) return NULL;
    s->cap = cap;
    s->top = 0;
    s->buf = cap ? malloc(cap * sizeof(void *)) : NULL;
    if (cap && !s->buf) {
        free(s);
        return NULL;
    }
    return s;
}

void stack_destroy(Stack **s, void (*free_cb)(void *))
{
    if (!s || !*s) return;
    Stack *stk = *s;
    if (free_cb) {
        for (size_t i = 0; i < stk->top; i++) {
            free_cb(stk->buf[i]);   /* 释放仍在栈内的载荷 */
        }
    }
    free(stk->buf);
    free(stk);
    *s = NULL;
}
```

### top 索引 vs 指针

数组栈有两种风格：

#### 风格 A：索引 `top`

```c
struct Stack { void **buf; size_t cap, top; };
/* push: buf[top++] = data */
/* pop:  return buf[--top] */
```

#### 风格 B：指针 `sp`（stack pointer）

```c
struct Stack { void **base, **sp, **end; };
/* push: *sp++ = data */
/* pop:  return *--sp */
```

风格 B 用指针直接操作，省一次 `buf +` 加法。但 `sp == end` 的满栈检查仍需要。现代编译器对索引和指针优化后差别极小，风格 A 更易读。

### 扩容策略

| 策略 | 扩容倍数 | 特点 |
|------|----------|------|
| 倍增 | 2x | 摊还 O(1)，内存峰值 2x |
| 1.5x | 1.5x | 摊还 O(1)，内存峰值 1.5x，可能复用旧块 |
| 固定增量 | +N | 最坏 O(n)，不推荐 |
| 预分配固定 | 不扩容 | HFT 数据面首选 |

倍增的摊还分析：n 次 push 总拷贝量 1+2+4+...+n ≈ 2n，摊到每次 push 是 O(1)。但单次扩容瞬间延迟尖峰（memcpy 大块）。HFT 数据面禁用动态扩容，启动时预分配足量。

### 固定容量与溢出

```c
Stack *s = stack_create(4096);   /* 固定 4096 */
if (stack_push(s, data) < 0) {
    /* 栈满, 业务必须处理: 丢弃、告警、或 fatal */
    log_warn("stack overflow");
}
```

HFT 数据面栈溢出是设计错误——预分配大小应覆盖最坏场景。运行时溢出说明容量估算错了，必须告警 + 排查。

### cache 友好性

数组栈的 `buf` 是连续内存，`push`/`pop` 访问 `buf[top]` 命中同一 cache line 的概率高。相比链表栈每次 push 访问新 malloc 的节点（可能跨页），数组栈 cache miss 少一个数量级。

### 数组栈 vs 环形缓冲区

数组栈用 `top` 索引线性增长，环形缓冲区用 `r_idx`/`w_idx` 取模循环。区别：

| 维度 | 数组栈 | 环形缓冲区 |
|------|--------|------------|
| 语义 | LIFO | FIFO |
| 索引 | top 线性 | r/w 循环取模 |
| 满 | top == cap | len == cap |
| 空 | top == 0 | len == 0 |
| HFT | 栈 ADT | 队列 ADT |

栈不需要取模（top 只增不减），队列需要（r/w 循环）。这是栈比队列简单的根本原因。

### 线程安全

数组栈的 `push`/`pop` 不是原子操作（读 top、写 buf、改 top 三步）。多线程共享栈必须加锁：

```c
pthread_mutex_lock(&s->mtx);
stack_push(s, data);
pthread_mutex_unlock(&s->mtx);
```

无锁栈用 CAS 操作链表头（Treiber stack），但实现复杂且 ABA 问题。HFT 倾向每线程独占栈避免锁。

## HFT 关联

- **数据面首选**：预分配固定容量数组栈，零运行时分配，延迟可预测
- **cache 友好**：连续 `buf` 访问模式命中 cache，相比链表栈快数倍
- **thread-local 栈**：每线程独占数组栈，无锁无争用
- **容量预分配**：启动时按最坏场景分配，运行时溢出即告警排查
- **mbuf 解析栈**：DPDK 报文解析嵌套隧道（VXLAN-in-IP）用数组栈保存各层 header 指针
- **订单簿回滚栈**：订单修改前 push 旧状态，失败时 pop 回滚，数组栈延迟稳定
- **避免 realloc 抖动**：数据面栈永不扩容，控制面栈扩容可接受
- **SIMD 友好**：连续内存可被 AVX 批量处理（如批量 pop N 个元素）
