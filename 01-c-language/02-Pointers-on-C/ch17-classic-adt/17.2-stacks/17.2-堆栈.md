# 17.2 堆栈

## 本节讲什么

栈 ADT（LIFO 后进先出）的设计：栈顶 push/pop/peek 三操作，数组与链表两种实现选型。栈是计算机科学最基础的 ADT 之一——函数调用栈、表达式求值、递归转迭代、错误回滚都依赖它。HFT 场景里栈用于报文递归解析、事务回滚、深度优先遍历。

## 要点

### 栈的核心操作

| 操作 | 语义 | 复杂度 |
|------|------|--------|
| `push(data)` | 入栈顶 | O(1) |
| `pop()` | 出栈顶并返回 | O(1) |
| `peek()` | 读栈顶不弹出 | O(1) |
| `len()` | 元素个数 | O(1) |
| `destroy(free_cb)` | 释放栈 + 载荷 | O(n) |

LIFO 语义：最后 push 的最先 pop，像一摞盘子。

### 两种实现选型

| 维度 | 数组实现（17.2.2） | 链表实现（17.2.3） |
|------|-------------------|-------------------|
| 内存 | 连续，cache 友好 | 节点分散 |
| 分配 | 预分配或 realloc | 每次 push malloc |
| 容量 | 固定或动态扩容 | 无上限 |
| push 延迟 | 稳定 O(1) | malloc 不确定 |
| HFT 数据面 | 首选 | 慎用 |
| 适用 | 定长、热路径 | 变长、控制面 |

### 栈的典型应用

#### 1. 函数调用栈

硬件栈就是 LIFO——`call` 压返回地址，`ret` 弹出。递归本质是隐式用硬件栈。

#### 2. 表达式求值

中缀转后缀、后缀求值都用操作数栈和运算符栈：

```c
/* 后缀表达式求值 */
for each token:
    if 数字: push(stack, token)
    if 运算符: b=pop, a=pop, push(a op b)
结果 = pop(stack)
```

#### 3. 递归转迭代

```c
/* 递归 */
void tree_inorder(Node *n) {
    if (!n) return;
    tree_inorder(n->left);
    visit(n);
    tree_inorder(n->right);
}

/* 迭代, 用显式栈 */
void tree_inorder_iter(Node *root) {
    Stack *s = stack_create();
    Node *cur = root;
    while (cur || !stack_empty(s)) {
        while (cur) {
            stack_push(s, cur);
            cur = cur->left;
        }
        cur = stack_pop(s);
        visit(cur);
        cur = cur->right;
    }
    stack_destroy(&s, NULL);
}
```

显式栈避免递归过深爆栈，且栈大小可控。

#### 4. 错误回滚（undo 栈）

事务操作前 push 回滚信息，失败时 pop 并执行回滚：

```c
stack_push(undo, make_rollback_record(state));
if (do_action() < 0) {
    rollback_record *r = stack_pop(undo);
    r->rollback(r);   /* 撤销 */
    free(r);
}
```

内核文件系统、数据库事务、HFT 订单修改都用类似模式。

#### 5. 括号匹配

```c
for each char c:
    if c 是开括号: push(stack, c)
    if c 是闭括号:
        if stack_empty: 错误
        top = pop(stack)
        if not match(top, c): 错误
if !stack_empty: 错误
```

### 栈与递归的关系

任何递归都能用显式栈转成迭代。递归的隐式代价：

- 每层调用压栈帧（返回地址 + 局部变量 + 寄存器保存）
- 栈帧大小固定，深递归可能爆栈（默认栈 8MB，每帧百字节就是几万层）
- 函数调用开销（`call`/`ret` + 栈帧建立）

迭代 + 显式栈的优势：

- 栈大小可控（可分配大块堆内存）
- 栈帧只存必要数据，更紧凑
- 可中断/恢复（协程基础）

HFT 报文解析的深层嵌套用显式栈避免递归爆栈。

### 空栈与溢出处理

- 空栈 pop：返回 NULL 或错误码，不能 UB
- 数组栈溢出：返回 -1 或 realloc 扩容
- 链表栈溢出：malloc 失败返回 -1

API 设计必须在文档里说明空栈/溢出行为，调用者必须检查。

### 栈的线程安全

标准栈不是线程安全的——并发 push/pop 会破坏链表或数组索引。HFT 场景：

- 每线程独占栈（thread-local），无锁
- 共享栈加 mutex（控制面可接受）
- 无锁栈用 CAS（数据面，但实现复杂）

## HFT 关联

- **报文递归解析**：FIX/二进制协议嵌套结构用显式栈解析，避免递归爆栈
- **错误回滚栈**：订单修改失败时按 undo 栈逆序回滚，保证一致性
- **表达式求值**：策略引擎的条件表达式（`price > 100 && qty < 50`）用栈求值
- **深度优先遍历**：订单簿按价格树 DFS 遍历，显式栈避免递归
- **硬件栈与爆栈**：递归过深触发 SIGSEGV（栈溢出），HFT 数据面禁用深递归
- **thread-local 栈**：每线程预分配栈容器，无锁无争用
- **DPDK 无栈 ADT**：DPDK 库本身不提供通用栈，HFT 自行实现或用 ring 替代

## 代码自测

**题目 1：** 以下用数组实现的栈有什么问题？
```c
#define MAX 100
int stack[MAX];
int top = 0;
void push(int val) {
    stack[top++] = val;
}
```

<details>
<summary>参考答案</summary>

没有检查栈满。如果 top >= MAX 还继续 push，会越界写入 stack 数组之后的内容——缓冲区溢出。正确做法：void push(int val) { if (top >= MAX) { /* error */ return; } stack[top++] = val; }。防御性编程要求检查所有边界条件。

</details>
