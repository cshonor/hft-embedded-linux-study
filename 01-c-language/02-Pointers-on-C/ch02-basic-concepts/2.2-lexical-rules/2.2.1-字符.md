# 2.2.1 字符

## 本节讲什么

**字符集**与**字面量**：整型、字符、字符串在词法层的表示。硬件地址、寄存器读写、报文解析——所有底层操作的字面量表示都从这一节开始。本节重点是各种**进制**的整型字面量、字符常量的类型陷阱、字符串字面量的存储语义。

## 字符与编码

### `char` 的本质

- C 的 `char` 是**最小整型**，占 1 字节（8 bit）
- `char` 是 `signed char` 还是 `unsigned char`？**由实现定义**——x86/gcc 默认 `signed`，ARM 默认 `unsigned`
- 跨平台代码不应依赖 `char` 的符号——要明确写 `signed char` 或 `unsigned char`
- 定宽用 `<stdint.h>`：`int8_t`/`uint8_t`

### 字符常量 `'A'`

```c
char c = 'A';        /* 'A' 的 ASCII 值是 65 */
int  x = 'A' + 1;    /* x = 66 */
```

| 要点 | 说明 |
|------|------|
| `'A'` 的类型 | **`int`**，不是 `char`！（C 标准规定） |
| `'A'` 的值 | 实现定义的字符编码值（ASCII 下为 65） |
| `sizeof('A')` | 在 C 中是 `sizeof(int)` = 4；在 C++ 中是 `sizeof(char)` = 1（著名的 C/C++ 差异） |
| 转义序列 | `'\n'` `'\t'` `'\0'` `'\\'` `'\''` `'\x41'`（十六进制）`'\101'`（八进制） |

> **陷阱**：`'A'` 是 `int` 不是 `char`。`sizeof('A')` 在 C 里是 4——这是 C/C++ 的一个经典差异，面试常考。

### 转义序列

| 转义 | 含义 | 转义 | 含义 |
|------|------|------|------|
| `\n` | 换行 | `\\` | 反斜杠 |
| `\t` | 制表 | `\'` | 单引号 |
| `\r` | 回车 | `\"` | 双引号 |
| `\0` | 空字符（NUL） | `\?` | 问号 |
| `\xHH` | 十六进制 | `\OOO` | 八进制（最多 3 位） |

报文解析常见：`'\x00'` 表示 NUL、`'\xff'` 表示全 1 字节。

### 四个"零"：`'\0'`、`'0'`、`0`、`NULL`

| 写法 | 类型 | 值 | 用途 |
|------|------|----|------|
| `'\0'` | `int` | 0 | 字符串终止符——语义上是"字符"，本质是值为 0 的 int |
| `'0'` | `int` | **48**（ASCII） | 字符 '0'，不是数值 0！ |
| `0` | `int` | 0 | 整数零 |
| `NULL` | 指针（实现定义，glibc 为 `((void*)0)`） | 空地址 | **只**用于指针的赋值/比较，别拿它当整数或字符用 |

经典 bug：`if (c == '0')` 想判字符串结尾——永远匹配的是字符 `'0'`（48）而不是 NUL。判结尾必须 `'\0'` 或直接 `!c`。

### 多字符常量 `'ab'`（实现定义陷阱）

```c
int magic = 'ab';   /* 合法，但值实现定义：gcc 小端下 = 'a'<<8 | 'b' = 0x6162 */
```

- C 标准允许 `'ab'` 这种 2~4 字符的**多字符常量**，但**值实现定义**
- gcc 小端下**后写的字符在高位**：`'ab'` = 0x6162（注意和直觉相反）
- 内核/DRM/v4l2 里常见 fourcc 魔数就这么写——读内核代码要认识
- 自己代码里报文魔数建议用十六进制 + 注明端序，更可移植：`0x4D5A /* "MZ", little-endian */`

## 整型字面量

### 进制

| 形式 | 前缀 | 示例 | 值（十进制） |
|------|------|------|-------------|
| 十进制 | 无 | `123` | 123 |
| 八进制 | `0`（前导零） | `0123` | 83 |
| 十六进制 | `0x`/`0X` | `0xFF` | 255 |
| 二进制（C99 不支持，GCC 扩展） | `0b`/`0B` | `0b1010` | 10 |

### 八进制陷阱（常见）

```c
int a = 0123;    /* 八进制！= 83，不是 123 */
int b = 09;      /* 编译错误：八进制不能有数字 9 */
int c = 010;     /* 八进制 = 8，不是 10 */
```

- 前导 `0` = 八进制——这是词法规则，不是"前导零被忽略"
- **最容易踩的场景**：对齐写 `int codes[] = { 001, 002, 010, 020 };`——你以为 1/2/10/20，实际是 1/2/8/16
- HFT/硬件：硬件地址几乎都用十六进制 `0x...`，不会误用八进制；但"对齐前导零"是真实陷阱

### 十六进制（HFT/硬件高频）

```c
uint32_t reg = 0xFFFF0000;      /* 寄存器掩码 */
uint64_t addr = 0xFFFFFFFF80000000ULL;  /* 内核虚拟地址 */
uint8_t  byte = 0xFF;           /* 全 1 字节 */
```

- 寄存器定义、内存地址、位掩码、报文魔数——全用十六进制
- DPDK/内核头文件里铺天盖地的 `0x...`

### 后缀（指定宽度/符号）

| 后缀 | 含义 | 示例 |
|------|------|------|
| `U`/`u` | `unsigned` | `100U` |
| `L`/`l` | `long` | `100L` |
| `LL`/`ll` | `long long`（C99） | `100LL` |
| `UL`/`ull` 等 | 组合 | `0xFFFFFFFFULL` |

- 不加后缀时，整型字面量的类型由值大小决定（`int` → `long` → `long long`）
- **64 位常量必须加 `ULL`**：`0xFFFFFFFFFFFFFFFF` 不加后缀可能被截断成 `int`
- 位掩码 `0xFFFFFFFF`：32 位系统上是 `unsigned int`（4 字节），64 位系统上仍是 `unsigned int`——要 64 位掩码用 `0xFFFFFFFFFFFFFFFFULL`

## 字符串字面量

```c
char *s = "abc";    /* "abc" 存储为 'a' 'b' 'c' '\0'，4 字节 */
```

| 要点 | 说明 |
|------|------|
| 末尾自动 `'\0'` | 字符串字面量末尾自动加 NUL 终止符 |
| 存储位置 | **`.rodata`**（只读数据段）——写它是 UB，通常 SIGSEGV |
| 类型 | `char[]`（静态存储期），但**不可修改**——修改是 UB |
| 相同字面量 | 可能合并（编译器优化），可能不合并——不要依赖地址 |
| 生命周期 | 整个进程——不会"函数返回就失效" |

### `"hello"[0] = 'x'` 为什么崩溃

```c
char *s = "hello";
s[0] = 'H';    /* UB：写 .rodata，通常 SIGSEGV */
```

- `"hello"` 在 `.rodata`（只读）
- `s` 指向 .rodata 的地址
- `s[0] = 'H'` 试图写只读内存 → SIGSEGV

**修复**：用数组（栈上副本）：

```c
char s[] = "hello";   /* 复制到栈上，可修改 */
s[0] = 'H';           /* OK */
```

> 这是 ch06/ch09 的重要前置：`char *s = "..."` 和 `char s[] = "..."` 的本质区别——前者指向只读 .rodata，后者在栈上复制一份。

### 字符串拼接

```c
char *s = "hello" " " "world";   /* 等价 "hello world" */
```

相邻字符串字面量自动拼接——常用于宏和长字符串分行书写。

## HFT / 硬件视角

| 场景 | 字面量用法 |
|------|-----------|
| 寄存器定义 | `#define REG_CTRL 0x40000000`（十六进制地址） |
| 位掩码 | `0xFFFF0000`（高低 16 位） |
| 报文魔数 | `0xDEADBEEF`、`0x4D5A`（MZ） |
| 字节操作 | `uint8_t b = 0xFF;`（全 1） |
| 字符判断 | `if (c >= 'A' && c <= 'Z')`（ASCII 范围） |

## 常见误区

| 误区 | 纠正 |
|------|------|
| `0123` 是 123 | 是八进制，= 83 |
| `'A'` 的类型是 `char` | 是 `int`，`sizeof('A')` = 4 |
| `"hello"` 可以修改 | 在 .rodata，修改是 UB → 通常 SIGSEGV |
| `0xFFFFFFFF` 是 64 位 | 是 `unsigned int`（32 位）；要 64 位加 `ULL` |
| `char` 一定是 signed | 实现定义，x86 默认 signed，ARM 默认 unsigned |
| `06` 合法 | 八进制不能有 9 → 编译错误 |

## 实操

1. `printf("%d %d\n", 'A', sizeof('A'))` 看 65 和 4
2. `int a = 0123; printf("%d\n", a)` 看 83
3. `char *s = "hello"; s[0]='H';` 运行看 SIGSEGV
4. `char s[] = "hello"; s[0]='H';` 运行看正常
5. `printf("%zu\n", sizeof(0xFFFFFFFF))` 看 4；`sizeof(0xFFFFFFFFULL)` 看 8
6. `gcc -E` 看字符串拼接是否生效

## 代码自测

**题目 1：** 以下哪个不是合法的 C 字符常量？为什么？
```c
char a = '\\';
char b = '\n';
char c = '\0x41';
char d = '\x41';
```

<details>
<summary>参考答案</summary>

C 不合法。\0x41 不是标准的转义序列——\0 是八进制转义（值为 0），后面 x41 是普通字符。\x41 才是十六进制转义（值为 65，即 A）。\\ 是反斜杠本身，\n 是换行。

</details>

**题目 2：** 以下判断哪里错了？
```c
char buf[64] = "hello";
if (buf[5] == '0')     /* 判断字符串结尾 */
    return;
```

<details>
<summary>参考答案</summary>

`'0'` 是 ASCII 字符零，值为 **48**；字符串结尾是 NUL，应写 `'\0'`（值为 0）。`buf[5]` 是 NUL（0），`48 == 0` 永远为假——这个判断永远不成立。正确写法：`if (buf[5] == '\0')` 或 `if (!buf[5])`。

</details>
