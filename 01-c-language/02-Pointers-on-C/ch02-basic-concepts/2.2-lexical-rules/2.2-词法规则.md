# 2.2 词法规则

## 本节讲什么

编译器的**词法分析**（lexical analysis）是翻译的第一步：把源码字符流切成一个个 **Token（记号）**。C 有五类基础 Token；**最长匹配（贪心法）**原则决定如何切分。这一节是《C 陷阱与缺陷》ch01/ch02 的核心——很多"诡异"的 bug（`a+++b` 怎么切、`06` 为什么非法、`/*` 在字符串里算不算注释）都源于词法规则。

## 词法分析在编译中的位置

```
源码字符流
  │ 词法分析（本节）── 切成 Token 流
  ▼
Token 流
  │ 语法分析 ── 按语法规则建语法树
  ▼
语法树
  │ 语义分析 ── 类型检查
  ▼
中间表示 → 优化 → 生成汇编
```

- 词法分析**不懂语法**——它只认字符模式，不关心 `int = ;` 这种语法错误
- 词法分析**不懂类型**——`a + b` 它只切出 `a` `+` `b` 三个 token，不管 a/b 是什么类型
- 一个 token 是"不可分割的最小词法单元"——`++` 是一个 token，不是两个 `+`

## 五类 Token

| 类别 | 例子 | 说明 |
|------|------|------|
| **标识符** | `count`、`rte_mbuf`、`main` | 程序员起的名字（2.2.4） |
| **关键字** | `int`、`static`、`struct`、`if` | 语言保留词，约 32 个，不可作标识符 |
| **字面量** | `123`、`0xFF`、`'A'`、`"abc"` | 常量值（2.2.1） |
| **操作符** | `+`、`*`、`&`、`->`、`==`、`<<=` | 运算符（ch05 优先级） |
| **分隔符** | `()` `{}` `[]` `,` `;` `.` `#` | 标点，分隔/分组 |

### 关键字（C89 约 32 个）

```
auto      break    case      char     const    continue  default   do
double    else     enum      extern   float    for       goto      if
int       long     register  return   short    signed    sizeof    static
struct    switch   typedef   union    unsigned void      volatile  while
```

C99 增加：`_Bool` `_Complex` `_Imaginary` `inline` `restrict`
C11 增加：`_Alignas` `_Alignof` `_Atomic` `_Generic` `_Noreturn` `_Static_assert` `_Thread_local`

> 关键字不能当标识符——`int int = 5;` 是语法错误。注意 `_` 开头的关键字是 C99/C11 加的。

## 最长匹配（贪心法/Maximal Munch）

**编译器在切 token 时，总是读尽可能长的合法 token。**

这是词法分析的核心规则，也是很多"诡异"行为的根源：

### 经典例子

```c
a+++b
```

怎么切？

| 切法 | 是否合法 |
|------|---------|
| `a` `+` `++` `b` | ❌ `+` `++` 之间——贪心法先读 `++` 还是 `+`？ |
| `a` `++` `+` `b` | ✅ 贪心法从左到右读最长：先 `a`，再 `++`（比 `+` 长），再 `+`，再 `b` |

所以 `a+++b` = `(a++) + b`，不是 `a + (++b)`。

### 更多例子

| 表达式 | 实际切分 | 不是 |
|--------|---------|------|
| `a+++b` | `a` `++` `+` `b` | `a` `+` `++` `b` |
| `a---b` | `a` `--` `-` `b` | `a` `-` `--` `b` |
| `a+++++b` | `a` `++` `++` `+` `b` → `((a++)++) + b` → **编译错误**（a++ 不是左值） | — |
| `x/*y` | `x` `/*y...`（开始注释！） | `x` `/` `*` `y` |
| `n+++++m` | `n` `++` `++` `+` `m` → 错误 | — |

### 陷阱：除法和指针解引用

```c
int a = 10;
int *p = &a;
int b = a/*p;    /* 想做 a / (*p)，但 /* 被当成注释开始！ */
```

`/*` 是注释起始 token，贪心法先匹配它。结果后面全被注释掉，`b` 成了 `int b = a` 后面什么都没有 → 语法错误。

**修复**：`int b = a / *p;`（加空格）或 `int b = a / (*p);`。

> 《C 陷阱与缺陷》ch1.3 的经典案例。贪心法不是"聪明"而是"机械"——它不懂你的意图。

### 陷阱：八进制字面量

```c
int a = 0123;    /* 八进制！= 1*64 + 2*8 + 3 = 83，不是 123 */
int b = 09;      /* 错误：八进制不能有 9 */
```

前导 `0` 表示八进制——这是词法规则，不是"前导零被忽略"。详见 2.2.1。

## 贪心法的边界：空白的作用

空白（空格/制表/换行）是 **token 分隔符**——它强制词法分析器在空白处"断开"：

```c
a + ++b      /* 空白断开：a + (++b) */
a+++b        /* 无空白：贪心 → (a++) + b */
```

所以**加空格能控制 token 切分**——这是解决贪心法陷阱最简单的方法。

## 为什么词法规则对 HFT/内核重要

| 场景 | 词法规则的影响 |
|------|--------------|
| 寄存器位操作 `reg >> shift` | `>>` 是一个 token，`> >` 会报错（C++ 模板更常见） |
| 宏展开后的表达式 | 宏参数替换后可能产生意外 token 组合（ch14） |
| `/*` 在表达式里 | 除法×指针解引用被误注释——罕见但致命 |
| 八进制字面量 | 硬件地址 `0x...` 是十六进制，别和八进制 `0...` 混 |
| 跨行宏续行 `\` | 预处理行的续行规则（ch14） |
