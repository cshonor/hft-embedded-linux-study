# 2.2.4 标识符

## 本节讲什么

**标识符**（identifier）的命名规则、**关键字**（keyword）、**保留标识符**、以及内核/DPDK/HFT 的工程命名惯例。本节是词法层"什么能当名字"的规则——理解它，能避免"用了保留名导致诡异 bug"和"命名冲突导致链接失败"。

## 命名规则

### 合法标识符

- **首字符**：**字母**（`a-z`/`A-Z`）或**下划线** `_`
- **后续字符**：字母、数字、下划线
- **区分大小写**：`count`、`Count`、`COUNT` 是三个不同的标识符
- **不能是关键字**：`int`、`static`、`struct` 等

```c
int count;       /* 合法 */
int _count;      /* 合法 */
int count2;      /* 合法 */
int 2count;      /* 非法：数字不能开头 */
int count-2;     /* 非法：- 不是字母/数字/下划线 */
int class;       /* C 合法（class 是 C++ 关键字，不是 C 关键字） */
int int;         /* 非法：int 是关键字 */
```

### 长度限制

- C89：保证前 31 个字符有效（外部链接前 6 个）
- C99：保证前 63 个字符有效（外部链接前 31 个）
- 现代编译器（gcc/clang）：**无实际长度限制**，全部有效
- 但太长的标识符影响可读性——工程上控制在合理范围

## 保留标识符（不能用的名字）

这是最容易踩的坑——有些名字虽然不是关键字，但标准**保留给实现**，用了是 UB：

| 保留模式 | 例子 | 保留给 |
|---------|------|-------|
| **双下划线开头** | `__foo`、`__UINT32_TYPE__` | 实现（编译器/库） |
| **单下划线 + 大写** | `_Foo`、`_GNU_SOURCE` | 实现 |
| **单下划线 + 小写** | `_foo`（文件作用域） | 实现（文件作用域内保留） |
| **标准库名** | `printf`、`malloc`、`strncpy` | 标准 `<stdio.h>` 等 |
| **`<stdint.h>` 类型** | `int32_t`、`uint64_t` | 标准（include 后保留） |

> **工程铁律**：不要用 `_` 开头 + 大写、不要用双 `_` 开头的名字。自己写的标识符用**字母开头**，避免和编译器内部/标准库冲突。

## 关键字

### C89 关键字（32 个）

```
auto      break    case      char     const    continue  default   do
double    else     enum      extern   float    for       goto      if
int       long     register  return   short    signed    sizeof    static
struct    switch   typedef   union    unsigned void      volatile  while
```

### C99 增加

```
_Bool  _Complex  _Imaginary  inline  restrict
```

### C11 增加

```
_Alignas  _Alignof  _Atomic  _Generic  _Noreturn  _Static_assert  _Thread_local
```

> 注意 C99/C11 新增的关键字大多是 `_` 开头 + 大写——这就是为什么 `_` 开头的标识符要小心。

### `class` 在 C 中合法

C++ 的 `class`、`new`、`delete`、`template` 等**不是 C 关键字**——在纯 C 中可以当标识符。但为了 C/C++ 混合代码的可移植性，工程上避免使用。

## 工程命名惯例（内核/DPDK）

| 对象 | 惯例 | 例子 |
|------|------|------|
| 函数 | snake_case，动词开头，模块前缀 | `rte_mbuf_refcnt_update`、`read_column_numbers` |
| 变量 | snake_case | `packet_count`、`order_id` |
| 全局变量 | `g_` 前缀或模块前缀 | `g_config`、`rte_config` |
| 宏 / 枚举 | **全大写 + 下划线** | `RTE_PKTMBUF_HEADROOM`、`MAX_ORDERS` |
| 类型 | snake_case + `_t` 后缀 | `struct rte_mbuf`、`uint32_t` |
| 私有函数 | `static` + snake_case | `static int parse_hdr(...)` |

### 命名的好习惯

- **函数名动词开头**：`read_` `init_` `parse_` `send_` `alloc_`
- **布尔返回加 `is_`/`has_`/`can_`**：`is_valid()`、`has_data()`
- **避免缩写到歧义**：`cnt` 是 count 还是 center？写全 `count`
- **避免单字母**（除循环计数 `i/j/k`）：`o` 和 `0`、`l` 和 `1` 容易混
- **作用域越大名字越长**：局部变量可以 `i`，全局变量要 `g_packet_count`

## 标识符与链接

标识符的**链接属性**（linkage）决定它在多个翻译单元中是否指同一个实体——这是 ch03.6 的核心，这里先建立直觉：

| 链接属性 | 含义 | 例子 |
|---------|------|------|
| **外部链接** | 全程序唯一，其他 `.o` 可见 | 全局函数、非 `static` 全局变量 |
| **内部链接** | 仅本翻译单元可见 | `static` 函数/全局变量 |
| **无链接** | 仅当前作用域 | 局部变量、函数参数 |

> 同名标识符在不同翻译单元：外部链接会冲突（`multiple definition`）；内部链接互不影响。`static` 是"隐藏"私有符号的关键。

## 常见误区

| 误区 | 纠正 |
|------|------|
| `_Foo` 可以随便用 | 单下划线+大写是保留标识符，UB |
| `__foo` 可以随便用 | 双下划线开头保留给实现，UB |
| 关键字当变量名 `int if = 5` | 语法错误，`if` 是关键字 |
| `class` 在 C 不能用 | C 能用（不是 C 关键字），但混合 C++ 会出错 |
| 标识符大小写不敏感 | C 区分大小写，`Count` ≠ `count` |
| 命名不影响性能 | 不影响运行性能，但严重影响**可维护性**和**review 效率** |

## 代码自测

**题目 1：** 以下哪些是合法的 C 标识符？
```c
int 2val;    // A
int _count;  // B
int $amount; // C
int typedef; // D
```

<details>
<summary>参考答案</summary>

只有 B 合法。标识符必须以字母或下划线开头，后续可以是字母、数字、下划线。A 以数字开头非法；C 中的 $ 不是标准 C 标识符字符（某些编译器扩展允许）；D 中的 typedef 是关键字。

</details>
