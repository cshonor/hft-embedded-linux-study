# 2.2.5 程序的形式

## 本节讲什么

**声明 vs 定义**、**语句分类**、**作用域**、**存储类**——本章的核心，也是多文件 DPDK/内核工程和内存生命周期的理论基础。90% 的链接报错、符号冲突、变量生命周期 bug，根源都在本节没搞清楚。

## 声明 vs 定义（链接的核心）

| | 声明 | 定义 |
|---|------|------|
| 作用 | 告知类型/签名，不分配 | 分配存储或生成代码 |
| 可出现次数 | 多次（只要一致） | 整个程序**一次**（外部链接） |
| 变量 | `extern int g_val;` | `int g_val = 10;` |
| 函数 | `void func(int x);`（原型） | `void func(int x) { ... }`（带函数体） |
| 结构体 | `struct rte_mbuf;`（不完整类型） | `struct rte_mbuf { ... };`（完整定义） |

### 工程铁律：头文件放声明，.c 放定义

```c
/* config.h —— 放声明 */
#ifndef CONFIG_H
#define CONFIG_H
extern int g_port;              /* 声明 */
void init_server(int port);     /* 声明：函数原型 */
struct rte_mbuf;                /* 声明：不完整类型 */
#endif

/* config.c —— 放定义 */
#include "config.h"
int g_port = 8000;              /* 定义：分配存储 */
void init_server(int port) {    /* 定义：生成代码 */
    g_port = port;
}

/* main.c —— 用声明 */
#include "config.h"
int main(void) {
    init_server(g_port);        /* 链接时找到 config.c 的定义 */
    return 0;
}
```

> 为什么头放声明：头被多个 `.c` include，放定义会多处定义→`multiple definition`。详见 2.1.1。

## 语句分类

C 的语句分四类：

| 类型 | 形式 | 例子 |
|------|------|------|
| **表达式语句** | 表达式 + `;` | `a = 10;`、`printf("hi");`、`i++;` |
| **复合语句（块）** | `{ 语句列表 }` | `if/for` 的函数体 |
| **空语句** | `;` | 循环体什么都不做 |
| **控制语句** | if/for/while/do/switch/goto | 改变执行流（ch04） |

### 分号陷阱（《C 陷阱与缺陷》经典）

```c
if (a > b);          /* ← 多了分号！这是空语句 */
{
    /* 这块永远执行，不受 if 控制 */
    printf("always\n");
}
```

- `if (a > b);` 的 `;` 是**空语句**——if 控制的是这个空语句
- 后面的 `{ ... }` 成了独立块，无条件执行
- `-Wall -Wparentheses` 会警告空 body

### 空语句的合法用途

```c
while (*dst++ = *src++);   /* 复制字符串，循环体是空语句 */
```

- 这种"所有工作在条件里做完"的写法是合法的空语句用法
- 但可读性差，现代代码倾向用显式循环体

## 作用域（Scope）

作用域决定标识符**在哪段代码可见**：

| 作用域类型 | 范围 | 例子 |
|-----------|------|------|
| **文件作用域** | 函数外声明，从声明点到文件末 | 全局变量、函数 |
| **块作用域** | `{}` 内，从声明点到块末 | 局部变量、`for` 的 `i` |
| **函数原型作用域** | 函数原型参数名，仅声明处 | `void f(int x);` 的 `x` |
| **函数作用域** | 整个函数，只有 **label** | `goto` 的目标标签 |

### 嵌套与遮蔽

```c
int a = 10;                /* 文件作用域 */
void test(void) {
    int a = 20;            /* 块作用域，遮蔽外层 */
    printf("%d\n", a);     /* 20 */
    {
        int a = 30;        /* 更内层，遮蔽中间层 */
        printf("%d\n", a); /* 30 */
    }
    printf("%d\n", a);     /* 20 */
}
```

- 内层可访问外层
- **内层同名遮蔽外层**——内核/工程规范常**禁止**局部与全局同名，避免误用
- C 没有作用域解析符（C++ 有 `::`）——一旦遮蔽，无法访问外层同名

### `for` 循环变量作用域（C99）

```c
for (int i = 0; i < n; i++) { ... }
/* i 在这里不可见（C99+） */
```

- C99 起 `for` 的 `i` 作用域限于循环体内
- C89 的 `i` 必须在循环外声明——作用域到函数末

## 存储类（Storage Class）

存储类决定变量的**存储位置、生命周期、链接属性**：

| 说明符 | 存储位置 | 生命周期 | 链接 | 用途 |
|--------|---------|---------|------|------|
| **auto**（默认局部） | 栈 | 块结束销毁 | 无 | 普通局部变量（现代几乎不写 `auto`） |
| **register** | 建议寄存器 | 块结束销毁 | 无 | 优化提示；不能 `&` 取址；现代编译器忽略 |
| **static**（局部） | .data/.bss | 整个进程 | 无 | 函数内"记忆"变量，只初始化一次 |
| **static**（文件） | .data/.bss | 整个进程 | **内部** | 私有全局/函数，仅本 `.c` 可见 |
| **extern** | （声明，不分配） | （引用外部定义） | **外部** | 声明别处定义的符号 |

### `static` 的双重含义（重要）

`static` 在**局部**和**文件级**语义不同：

```c
/* 文件级 static —— 内部链接，仅本 .c 可见 */
static int g_private = 0;          /* 私有全局 */
static int helper(void) { ... }   /* 私有函数 */

void counter(void) {
    static int count = 0;          /* 局部 static —— 整个进程存活，只初始化一次 */
    count++;
    printf("%d\n", count);
}
```

| `static` 用在哪 | 存储位置 | 生命周期 | 链接 |
|---------------|---------|---------|------|
| 局部变量 | .data/.bss | 整个进程（但作用域仍限块内） | 无 |
| 文件级变量/函数 | .data/.bss | 整个进程 | **内部**（仅本翻译单元） |

> 两种 `static` 共同点：都改"默认行为"——局部改生命周期，文件级改链接可见性。

### `static` 局部：只初始化一次

```c
void init_pool(void) {
    static void *pool = NULL;       /* 只在第一次调用时初始化 */
    if (!pool)
        pool = alloc_hugepage();
}
```

- `static` 局部变量的初始化在**程序启动时**完成（不是每次函数调用）
- 默认初始化为 0（.bss 清零机制）
- DPDK/内核常用于"一次性初始化"、"单例池"

### `extern`：跨文件引用

```c
/* a.c */ int g_cfg = 1;           /* 定义 */
/* b.c */ extern int g_cfg;        /* 声明：引用 a.c 的定义 */
```

- `extern` 声明**不分配内存**——告诉编译器"这个符号在别处定义"
- 链接时解析到真正的定义
- 如果找不到定义 → `undefined reference`

## 内存生命周期对照表

| 声明方式 | 存储位置 | 创建 | 销毁 | 初始值 |
|---------|---------|------|------|--------|
| `int x;`（局部 auto） | 栈 | 进入块 | 离开块 | 不定值（UB 读取） |
| `static int x;`（局部） | .bss/.data | 程序启动 | 程序结束 | 0 |
| `int x;`（全局） | .bss/.data | 程序启动 | 程序结束 | 0 |
| `int x = 5;`（全局） | .data | 程序启动 | 程序结束 | 5 |
| `extern int x;` | （引用） | — | — | 引用别处 |
| `malloc(sizeof(int))` | 堆 | malloc 时 | free 时 | 不定值 |

## 专属价值（内核/DPDK/HFT）

1. **链接报错**：90% 的 `multiple definition`/`undefined reference` 根源在本节——声明vs定义、extern、static
2. **内存生命周期**：`static` 单例池、一次性硬件 init、配置全局
3. **符号隔离**：`static` 私有 helper，不污染全局符号空间
4. **隐蔽 bug**：遮蔽、if 分号空语句、static 局部只初始化一次
5. **HFT 配置**：全局配置变量 + extern 声明，多线程共享——注意加锁或用原子

## 常见误区

| 误区 | 纠正 |
|------|------|
| `extern` 分配内存 | 只是声明，不分配；定义在别处 |
| `static` 局部每次调用都初始化 | 只在程序启动时初始化一次 |
| 头文件放变量定义 | 被多处 include → 多重定义；改 `extern` 声明 |
| `static` 函数能被其他文件调用 | `static` = 内部链接，仅本翻译单元 |
| `if (a > b);` 的分号无害 | 空语句陷阱，if 不控制后面的块 |
| 遮蔽外层变量没关系 | 内核规范常禁止，避免误用全局 |
| `register` 还能优化 | 现代编译器忽略；不能 `&` 取址已无意义 |

## 实操

1. 多文件 `static` vs 全局，故意制造 `multiple definition` 和 `undefined reference`
2. `static` 局部循环调用多次，验证只初始化一次
3. 制造局部遮蔽全局，打印内外层值
4. `if (a > b); { ... }` 加分号，看块是否无条件执行
5. `readelf -S ./app` 看 .text/.data/.bss，对照变量声明方式
6. `nm a.o` 看符号表，区分 `T`（text 已定义外部）、`t`（text 已定义内部 static）、`U`（未定义）

## 代码自测

**题目 1：** 以下代码有什么问题？
```c
int main(void) {
    int x = f(3);
    return 0;
}
int f(int n) { return n * 2; }
```

<details>
<summary>参考答案</summary>

f 在调用前没有声明（C99 前的隐式声明会假设返回 int，但此处碰巧匹配；C99 起隐式声明是错误的）。更严格地说，如果 f 返回非 int 类型，隐式声明会导致 UB。正确做法是在 main 前加 int f(int n); 原型声明，或者把 f 的定义放在 main 之前。

</details>
