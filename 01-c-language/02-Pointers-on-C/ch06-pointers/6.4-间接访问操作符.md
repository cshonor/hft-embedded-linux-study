# 6.4 间接访问操作符

## 本节讲什么

**`*` 解引用**：通过指针访问其所指对象。C 里同一个 `*` 在声明和表达式里语义完全不同——这是新手第一道坎，也是理解"指针即地址 + 类型语义"的钥匙。本节还把解引用落到汇编层，看清"间接访问"在 CPU 上究竟是什么。

> **入门速记：** [6.0 星号两场景](./6.0-星号两场景.md)（声明 `*` vs 表达式 `*` · `&`/`*` 配对 · 自测）

## 要点

```c
int num = 100;
int *ptr = &num;

printf("%d", *ptr);   /* 读 num：*ptr 求值为 100 */
*ptr = 200;           /* 写 num：*ptr 是左值，可被赋值 */
```

| 上下文 | `*` 含义 | 例子 |
|--------|----------|------|
| 声明 `T *p` | 类型修饰符："p 是指向 T 的指针" | `int *p;` |
| 表达式 `*p` | 解引用运算符：取 p 所指对象 | `*p = 1;` |
| 类型名 `T*` | 类型的一部分 | `sizeof(int*)` |

- 解引用前指针必须**有效**：非 NULL、非悬垂、非野、在合法范围内
- `*p` 的结果是**左值**（可赋值、可取地址），类型为 `T`
- 对 `p` 本身取地址 `&(*p)` 等价于 `&num`（在有效指针上）

## 底层映射

### 解引用 = 一条访存指令

`*ptr` 读 → `mov` 从 `[reg]` 加载；`*ptr = ` 写 → `mov` 存储。

```c
int num = 100;
int *ptr = &num;
*ptr = 200;        /* 解引用写 */
int x = *ptr;      /* 解引用读 */
```

```
; x86-64 -O1
    mov     DWORD PTR [rsp+4], 100        ; num = 100
    lea     rax, [rsp+4]                  ; ptr = &num
    mov     DWORD PTR [rax], 200          ; *ptr = 200  (store)
    mov     eax, DWORD PTR [rax]          ; x = *ptr    (load)
```

核心：**一条访存指令**。指针在寄存器（`rax`）里存地址，CPU 用 `[rax]` 去内存（或 cache）取数。延迟取决于该地址在不在 cache（**6.1** 内存层级）。

### 别名分析（编译器优化的核心）

```c
void f(int *a, int *b) {
    *a = 1;
    *b = 2;              /* 编译器要问：b 会不会指向 a？ */
    return *a;           /* 若可能别名，必须重新 load *a；否则保持 1 */
}
```

- 若编译器能证明 `a != b`（如 `restrict` 承诺，**6.9**），`*a` 直接常量折叠成 1
- 若不能证明，每次写 `*b` 后都要重新 `load *a`——这就是 `restrict` 提速的原理

## HFT / DPDK

| 场景 | 解引用模式 |
|------|-----------|
| 改调用者变量 | `*out = value;`（输出参数） |
| 链表遍历 | `p = p->next;`（`->` 等价 `(*p).member`，**ch10**） |
| 报文字段 | `pkt->ether_type` |
| 批量改结构体 | `for (...) { p[i].flag = 1; }` |

`->` 是 `*` + `.` 的语法糖：`p->m` ≡ `(*p).m`。优先级：`->` 和 `.` 高于 `*`，所以 `*p.m` 实际是 `*(p.m)`，要写 `(*p).m`——这就是 `->` 存在的理由。

## 常见误区

| 误区 | 事实 |
|------|------|
| "声明 `int *p` 里的 `*` 和 `*p = 1` 里的 `*` 一样" | 完全不同：前者类型修饰，后者运算符 |
| "解引用一定快" | 取决于所指地址是否在 cache；miss 一次 200 cycle |
| "`*p` 总能取地址" | 悬垂/野指针解引用本身已是 UB |
| "写 `*p = x` 就一条指令" | 是，但前面可能有 null 检查、边界检查的开销 |

## 实操

```bash
# 看解引用生成的访存指令
gcc -O1 -S t.c -o -       # 找 mov [reg], imm / mov reg, [reg]
# 看 restrict 如何消除重复 load
gcc -O1 -S -DRESTRICT t.c -o -
# ASan 检测无效解引用
gcc -fsanitize=address t.c -o t && ./t
```
