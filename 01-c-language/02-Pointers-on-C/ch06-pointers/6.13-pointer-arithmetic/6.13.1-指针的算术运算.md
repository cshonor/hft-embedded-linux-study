# 6.13.1 指针的算术运算

## 本节讲什么

**`p + n`** / **`p - n`** 的精确语义：地址移动 **n 个元素**（即 `n × sizeof(T)` 字节），**不是 n 字节**。这是报文偏移、ring buffer、批量遍历的核心，也是"指针加一到底加多少"误区的终结篇。

## 要点

```c
int  *ip;   ip + 1;   /* 地址 + 4 字节（sizeof(int)） */
char *cp;   cp + 1;   /* 地址 + 1 字节 */
struct big *bp; bp + 1; /* 地址 + sizeof(struct big) */
```

**核心公式**：`p + n` 的地址值 = `(char *)p + n * sizeof(T)`。

### 合法范围（C99 6.5.6）

- 结果必须仍指向**同一数组对象内**，或**尾后一位**（one-past-end）
- 越界解引用 → **UB**（线上随机崩溃，ASan 可抓）
- 形成尾后合法，比较合法，**解引用非法**

```c
int arr[10];
int *p = arr;
int *end = arr + 10;   /* 尾后一位：合法形成、合法比较 */
*end;                  /* UB：解引用尾后 */
arr + 11;              /* UB：越界形成都不行 */
```

### 步长由类型决定

```c
char buf[64];
struct eth_hdr *h = (struct eth_hdr *)(buf + 14);   /* buf+14 是字节偏移 */
/* 注意：buf 是 char*，+14 是 14 字节；不是 14 个 struct */
```

报文解析里最常见模式：`char *` base 做字节级偏移，再 cast 到结构体指针。**字节级偏移必须用 `char *` 或 `uint8_t *`**，避免类型带来的步长陷阱。

## 底层映射

### 汇编：步长是比例因子

```c
int arr[100];
int *p = arr;
int x = p[5];          /* *(p+5) */
```

```
; x86-64 -O2
mov     eax, DWORD PTR [rdi + 5*4]   ; 比例变址：scale=4
```

硬件 SIB（Scale-Index-Base）寻址原生支持 1/2/4/8 倍率，编译期把 `sizeof(T)` 编进 scale，**不用 imul**。所以：

| 类型 | scale | 寻址模式 |
|------|-------|---------|
| `char*` / `uint8_t*` | 1 | `[reg + idx]` |
| `int16_t*` | 2 | `[reg + idx*2]` |
| `int*` / `float*` | 4 | `[reg + idx*4]` |
| `int64_t*` / `double*` / 指针 | 8 | `[reg + idx*8]` |

`struct` 大小不是 1/2/4/8 时，`p[i]` 会拆成 `imul` 或 `lea + add`——这是结构体数组比基本类型数组略慢的原因之一（但常被向量化掩盖）。

### `++p` 与 `p++` 的差异

```c
*p++;      /* 解引用 p 的旧值，然后 p 前进（后缀++优先级高） */
(*p)++;    /* 解引用 p，然后把所指对象 +1 */
*++p;      /* 先前进 p，再解引用新位置 */
```

`*p++` 是报文遍历的经典惯用法：`for (end = p + n; p < end; ) c = *p++;`。

## HFT / DPDK

| 场景 | 用法 |
|------|------|
| 报文头部偏移 | `struct eth_hdr *h = (struct eth_hdr *)(pkt + 14);` |
| 字段定位 | `uint32_t *seq = (uint32_t *)(pkt + 4);` |
| ring buffer 环绕 | `(p + 1) == end ? base : (p + 1)` |
| 批量收包 | `for (i = 0; i < n; i++) decode(pkts + i);` |
| 长度计算 | `size_t n = (char *)end - (char *)base;` |

### 报文偏移的正确写法

```c
/* 错：pkt 是 struct pkt*，+14 是 14 个 struct */
struct pkt *bad = pkt + 14;

/* 对：先转 char* 做字节偏移，再 cast */
struct eth_hdr *h = (struct eth_hdr *)((char *)pkt + 14);

/* 或用 offsetof（ch10） */
struct eth_hdr *h = (struct eth_hdr *)((char *)pkt + offsetof(...));
```

## 常见误区

| 误区 | 事实 |
|------|------|
| "`p + 1` 加 1 字节" | 加 sizeof(T) 字节 |
| "`pkt + 14` 是 14 字节偏移" | 取决于 pkt 类型——`struct pkt*` 时是 14 个结构体 |
| "尾后一位解引用没事" | UB，可能 SIGSEGV 或踩别人 |
| "`*p++` 和 `(*p)++` 一样" | 完全不同：前者改 p，后者改所指对象 |
| "结构体数组 p[i] 和 int 数组一样快" | 非常规步长可能拆成 imul，略慢 |

## 实操

```bash
# 看不同类型的步长汇编
cat > t.c << 'EOF'
int fi(int *p)     { return p[5]; }
int fc(char *p)    { return p[5]; }
int fl(long *p)    { return p[5]; }
EOF
gcc -O2 -S t.c -o -      # 对比 scale: 1, 4, 8
# ASan 抓越界
gcc -g -fsanitize=address t.c -o t && ./t
# perf 看结构体数组 vs int 数组 cache 行为
perf stat -e cache-misses ./struct_walk
```

## 代码自测

**题目 1：** 以下代码合法吗？输出什么？
```c
int arr[5] = {1, 2, 3, 4, 5};
int *p = arr;
printf("%d\n", *(p + 3));
printf("%d\n", p[3]);
```

<details>
<summary>参考答案</summary>

合法。两者都输出 4。*(p + 3) 和 p[3] 完全等效——a[i] 在 C 中就是 *(a + i) 的语法糖。这也是为什么数组名作为指针使用时可以用下标语法。反过来 3[p] 也是合法的，因为它等价于 *(3 + p)。

</details>
