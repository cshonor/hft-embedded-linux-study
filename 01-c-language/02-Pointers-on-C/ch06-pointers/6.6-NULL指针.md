# 6.6 NULL 指针

## 本节讲什么

**NULL** 表示指针"不指向任何对象"。它是 C 里"空值"的标准写法——初始化、比较、函数"无可返回"语义都靠它。这一节把 NULL 的定义、解引用为什么崩、内核/错误码扩展用法讲清。

## 要点

```c
#define NULL ((void *)0)   /* 常见定义，C99 起 */

int *p = NULL;
if (p == NULL) { /* ... */ }
if (p != NULL && p->len > 0) { /* 短路：p 为 NULL 不会解引用 */ }
```

- `*NULL` → **段错误**（见下"零页保护"）
- C11 可选 `nullptr`（`<stddef.h>`，若定义 `__STDC_VERSION__ >= 202311L`）；C++ 用 `nullptr`
- 释放后置 NULL 使二次 `free` 安全（标准要求 `free(NULL)` 是 no-op），但**不应依赖此"安全"**——double-free 本身就是 bug

### NULL 的定义演变

| 标准 | 典型定义 |
|------|---------|
| C89/C90 | `((void *)0)` 或 `0` |
| C99 | `((void *)0)`，整数常量 0 也可作空指针 |
| C23 | 引入 `nullptr` 关键字（如启用） |

`0` 和 `((void*)0)` 在比较时**等价**：`p == 0` 和 `p == NULL` 都判空。但传参时 `0` 给 `va_arg` 的 `void*` 在某些 ABI 上会出问题，推荐始终用 `NULL` 或显式 `(void*)0`。

### 整数转指针：`(T *)整数`

C 语言**语法上允许把整型数字强制转型成指针**，含义：**把这个整数的值当作虚拟内存地址编号**。

```c
uintptr_t addr = 0x10000;
int *p = (int *)addr;   /* 把数字 0x10000 当作虚拟地址 */
```

| 转法 | 判定 | 原因 |
|------|------|------|
| ✅ 整数 → 指针 | 合法语法 | 指针本质是地址编号，整数有同构性 |
| ❌ `float`/`double` → 指针 | **语法报错** | 地址编号没有浮点概念 |
| ⚠️ 负数 → 指针 | 语法可过但几乎必错 | 指针是无符号地址空间，负数转过来变成巨大无符号地址，几乎必然无效 |

> **语法允许 ≠ 地址合法**：随便写 `(int *)0x123456` 编译通过，但这个地址没有映射，一解引用就崩溃。

### 四件东西，一张表分清

| 记号 | 本质 | 语义 |
|------|------|------|
| `0` | 普通 `int` 整数 | 就是数字零 |
| `NULL`（`(void *)0`） | **空指针常量** | C 语言逻辑上的空指针标记：**不指向任何有效对象** |
| 虚拟地址 0（0 号页） | 一块受保护的内存页 | OS 设为禁止访问，用户态不可读写 |
| `(int *)0xaaaa` | 整数强转指针 | 把数字直接当作虚拟地址用 |

**机器层面的巧合与标准的边界**：空指针在机器层面的地址编码就是数值 0；但 C 标准并不定义"空指针 = 可访问虚拟地址 0"——**这只是数值巧合**。空指针的全部语义是逻辑标记，不是"指向 0 号页的指针"。

> **补充规则**：`(void *)0` 是特殊的**空指针常量**；而 `(void *)1`、`(void *)0x2000` 就是普通整数转指针——**不会获得空指针的特殊语义**，单纯把数字当地址。空指针常量的"特权"只属于整数常量 `0` 及其 `(void *)0` 形式。

## 底层映射

### 零页保护

x86-64 Linux：低地址（典型 0–4KB，可配 `/proc/sys/vm/mmap_min_addr`）映射为**不可读不可写页**。`*NULL` → CPU 发出 `mov [0]` → MMU 检查权限失败 → `SIGSEGV`。

```
NULL 解引用路径:
  *p (p=NULL=0)
  → mov eax, [0]            ; CPU 访存
  → MMU 查页表，0 地址页无权限
  → page fault → 内核送 SIGSEGV
```

"零页"是特意留出来的——让 NULL 解引用**确定性崩溃**而非踩随机数据。某些嵌入式系统不设零页，NULL 解引用会写到向量表 → 死机。

### 用户态规则与内核边界

- **用户态现实规则**：普通进程永远不会把真实内存映射到虚拟地址 0，所以日常写代码里"指针机器值等于 0"就等价于 NULL 空指针。
- **内核边界**：内核里可以手动建立映射（如 `fixmap`/手动 `ioremap`），让虚拟地址 0 真正映射到物理内存。这时指针机器值是 0，但**它不是 C 语言意义的空指针**，可以正常解引用。用户态碰不到这种情况。

```c
int *p = NULL;
p;      /* OK：指针本身，存数值 0，代表空 */
*p;     /* ❌ UB：解引用空指针，访问 0 号页 → SIGSEGV */
```

### 内核错误码编码（`IS_ERR` 模式）

内核指针的低端不用，高端一段（典型 `(unsigned long)-4095` ~ `-1`）编码错误码：

```c
/* 内核源码模式 */
static inline bool IS_ERR(const void *ptr) {
    return (unsigned long)ptr >= (unsigned long)-4095;
}
static inline long PTR_ERR(const void *ptr) {
    return (long)ptr;
}

void *p = kmalloc(...);
if (IS_ERR(p)) {
    int err = PTR_ERR(p);   /* 取回负错误码 */
    /* 处理 */
}
```

返回值既是指针也是错误码——内核惯用手法。用户态 HFT 不常用，但理解它对读内核代码、DPDK 移植有帮助。

## HFT / DPDK

| 用法 | 例子 |
|------|------|
| 报文不存在 | `if (!pkt) return;` |
| 链表尾哨兵 | `for (; p != NULL; p = p->next)` |
| 配置缺失 | `config->cb = NULL;` 表示未设回调 |
| 可选资源 | `struct ring *r = NULL;` 按需创建 |

## 常见误区

| 误区 | 事实 |
|------|------|
| "NULL 一定是 0" | 实现可定义，但主流都是全零位模式 |
| "free 后 p 自动变 NULL" | 不会，必须手动 `p = NULL` |
| "判 NULL 用 `!p` 是偷懒" | 合法且常见，等价于 `p == NULL` |
| "C++ 的 NULL 和 C 一样" | C++ 推荐用 `nullptr`，类型安全（不会和 0 歧义） |
| "语法上能 `(int *)0x123456` 就代表地址合法" | 语法通过 ≠ 地址已映射，解引用就崩 |
| "`(void *)1` 也是某种空指针" | 只有 `0`/`(void *)0` 是空指针常量，其余整数转指针只是把数字当地址 |
| "空指针机器值是 0，所以 0 号页可访问" | 数值巧合；0 号页被 OS 设为禁止访问，访问即 SIGSEGV |

## 实操

```bash
# 看零页保护
cat /proc/sys/vm/mmap_min_addr       # 通常 65536
# 写个小程序故意 *NULL，看 SIGSEGV
cat > t.c << 'EOF'
int main(void) { int *p = NULL; return *p; }
EOF
gcc -g t.c -o t && ./t; echo $?     # Segmentation fault (139)
# gdb 看崩在哪
gdb ./t -ex r -ex bt
```

## 代码自测

**题目 1：** 以下代码哪个更安全？为什么？
```c
// A
int *p = NULL;
*p = 42;
// B
int *p;
*p = 42;
```

<details>
<summary>参考答案</summary>

A 相对更安全——解引用 NULL 在大多数系统上会立即 segfault（因为地址 0 通常不可写），错误能被快速发现。B 中 p 是随机地址，可能写到合法地址上，错误难被发现。但两者都是 UB——正确做法是确保指针指向有效内存后再解引用。

</details>

**题目 2：** 逐行判定，哪些语法过、哪些能跑、哪些崩？
```c
int *p1 = (int *)0x2000;   // 行 1：定义
float f = 1.5f;
// int *p2 = (int *)f;    // 行 2：注释着的这行
int *p3 = (int *)-1;       // 行 3：定义
void *vp1 = (void *)0;     // 行 4：定义
void *vp2 = (void *)0x2000;// 行 5：定义
*p1;                       // 行 6：解引用
```

<details>
<summary>参考答案</summary>

- 行 1 ✅ 语法合法：把数字 0x2000 当虚拟地址存入指针。但地址未映射，解引用才崩。
- 行 2 ❌ 语法报错：浮点数不能转指针——地址没有浮点概念。
- 行 3 ⚠️ 语法可过：-1 转成巨大的无符号地址（64 位下 0xFFFF...FFFF），几乎必然无效，解引用大概率 SIGSEGV。
- 行 4 ✅ `(void *)0` 是**空指针常量**，vp1 是空指针。
- 行 5 ⚠️ `(void *)0x2000` 不是空指针，只是把数字当地址——没有 NULL 的特殊语义。
- 行 6 ❌ UB：解引用未映射地址 → SIGSEGV。

核心：**语法合法 ≠ 地址合法**；**空指针常量的特权只属于 0**。

</details>
