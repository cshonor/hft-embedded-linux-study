# 6.1 内存和地址

## 本节讲什么

**内存 = 可字节寻址的数组 + 地址**：每个变量占连续若干字节，**地址**标识其起始字节。指针就是「存放地址的变量」—— DPDK mbuf、内核 `task_struct`、HFT 报文缓冲的共同语言。这一节把"地址"在硬件、操作系统、C 语言三个层面讲透，后面 14 节都建立在这之上。

## 要点

- **虚拟地址**：进程看到的地址，经 MMU/页表翻译成物理地址（**ch18** 详）
- x86-64 Linux：用户态通常 **48 位有效**（高 16 位必须全 0 或全 1，否则 `SIGSEGV`），5 级页表可到 57 位
- **指针变量占 8 字节**（64 位），与指向类型无关：`sizeof(int*) == sizeof(char*) == sizeof(void*) == 8`
- **普通变量**存数据；**指针变量**存"另一对象的首地址"
- `&` 取址；`*` 解引用（**6.4**）

```c
int val = 10;
int *p = &val;   /* p 的内容 = val 的首地址 */
```

### 地址空间布局（x86-64 Linux 用户态）

```
高地址  ┌─────────────────────┐ 0x7fff_ffff_ffff (栈底，48 位上限)
        │  栈 ↓ 向下增长       │  局部变量、帧指针、返回地址
        │  ...                │
        │  ↕ 共享库 mmap 区    │  libc.so / vdso
        │  堆 ↑ 向上增长       │  malloc/mmap
        ├─────────────────────┤
        │  .bss  (未初始化全局) │  运行时清零
        │  .data (已初始化全局) │
        │  .rodata (只读字面量) │  "FIX.4.2" 在这
        │  .text  (代码)       │
低地址  └─────────────────────┘ 0x400000 (non-PIE 典型基址；现代默认 PIE+ASLR 随机化)
```

`&val` 在栈区；字符串字面量在 `.rodata`；`malloc` 返回在堆或 mmap 区。

## 底层映射

### 内存层级与延迟（HFT 必背）

| 层级 | 容量 | 延迟（约） | 备注 |
|------|------|-----------|------|
| 寄存器 | ~16×64B | 0 cycle | 编译器尽量常驻 |
| L1 d-cache | 32 KB/核 | ~4 cycle | cache line 64B |
| L2 | 1 MB/核 | ~12 cycle | 私有 |
| L3 | 数十 MB | ~40 cycle | 全核共享 |
| DRAM | GB 级 | ~200 cycle（~60ns） | 主存 |
| NVMe | TB 级 | ~10μs | 持久化 |

HFT 关键路径数据必须在 L1/L2。一次 DRAM 访问 ≈ 50 次 L1，"指针跳转链表"慢就慢在每次 `next` 都可能 miss。

### L1/L2 cache vs NUMA node：两个正交尺度，别混为一谈

上表是**单核纵向**视角（寄存器→L1→L2→L3→DRAM）。多核服务器还要叠一个**横向**维度——NUMA node。两者名字都带"内存加速"味，但**完全两码事**：

- **L1/L2 cache** = CPU **核心内部**的硬件缓存，**每核私有**，存的是 DRAM 数据的**副本**（最近访问的 cache line）。
- **NUMA node** = **主板级**的内存分组，一个 node = 一堆核心 + 本地内存控制器 + 本地 DRAM，存的是数据的**本体**（物理内存归哪块）。

一句话记忆：**L1/L2 是「缓存副本」，NUMA node 是「内存归属」**。前者回答"数据离核心多近"，后者回答"数据放在哪块物理内存"。

```
        ┌────────────── NUMA node 0 ──────────────┐
        │  core 0           core 1        ...      │
        │  ┌──────────┐    ┌──────────┐            │
        │  │ L1 │ L2  │    │ L1 │ L2  │  ← 核内私有 │
        │  └────┬─────┘    └────┬─────┘            │
        │       └────── L3 (node 内共享) ────┘      │
        │                 │                        │
        │          本地 DRAM (local ≈ 60ns)         │
        └─────────────────┬────────────────────────┘
                          │  UPI/QPI 互连 (remote ≈ 100+ns)
        ┌─────────────────┴────────────────────────┐
        │  NUMA node 1（结构同上，自有 DRAM）        │
        └──────────────────────────────────────────┘
```

| 维度 | L1/L2 cache | NUMA node |
|------|-------------|-----------|
| 层级 | 核内硬件缓存 | 主板级内存分组 |
| 归属 | 每核私有 | node 内核心共享本地 DRAM |
| 本质 | 数据**副本**（缓存） | 数据**本体**（物理内存归属） |
| 延迟 | L1 ~4cyc / L2 ~12cyc | 本地 ~60ns，跨 node ~100+ns |
| 谁控制 | 硬件自动，程序员只能影响访存模式 | OS 调度 + 内存分配（`numactl`/`mbind`） |

> **容易混的点**：L3 是"node 内多核共享"的缓存，NUMA 是"node 内多核共享本地 DRAM"——两个"共享"不是一回事。L3 共享的是**副本**，NUMA 共享的是**本体**的归属权。

HFT 关联：**光绑核不够，还得就近分配内存**。`taskset`/`isolcpus` 只保证线程跑在某个核上；若它访问的数据页落在**远端 node 的 DRAM**，每次访存都跨 UPI 总线，延迟从 ~60ns 飙到 ~100+ns。正确姿势是 `numactl --membind=<node>`（或 `mbind`/`set_mempolicy`）把内存页锁定到**本地 node**，与绑核同 node，实现"核与数据共处一 node"。

### 地址对齐

- **自然对齐**：地址是其类型宽度的整数倍（`int*` 的地址 % 4 == 0）
- x86-64 允许非对齐访问但有性能代价；某些 ISA（ARM 旧版）直接 `SIGBUS`
- SIMD（`__m256`）**要求 32 字节对齐**，否则 `movaps` 崩溃
- `alignof(T)` 查询；`_Alignas(64)` / `__attribute__((aligned(64)))` 强制 cache line 对齐

## mmap：指针与后备存储（先画区、后填页）

`mmap` 返回的 `void *`，指向的是一块**被内核绑定了「后备」的虚拟地址**——后备可以是磁盘文件、设备 DMA 缓冲区、或匿名页。它和 `malloc` 的关键区别在「数据什么时候到位」：

| | 返回的指针指向 | 数据何时到位 |
|--|----------------|--------------|
| `malloc` | 虚拟地址，后备是**零页 + COW** | 首次写触发缺页，分配真实页并清零 |
| `mmap` | 虚拟地址，后备可显式指定（文件/设备/匿名） | **访问**时触发缺页，内核从文件/设备填页 |

> **先画区、后填页**：`mmap` 只建立「虚拟地址 ↔ 物理/磁盘」的映射关系，**不立刻把数据拷进内存**。解引用 `*p` 才会触发**缺页中断**（page fault）——这是 CPU 的内存管理机制，**不等于 mmap**。

### 两个进程的指针，能否指向同一物理页？

`mmap` 的 `flags` 决定映射关系的共享程度，本质是「两个进程的虚拟地址，翻译后落在**同一块物理页**，还是各自一块」：

```c
/* 共享：两个进程的 p/q 指向同一物理页 */
void *p = mmap(NULL, sz, PROT_READ|PROT_WRITE, MAP_SHARED, fd, 0);   /* 进程 A */
void *q = mmap(NULL, sz, PROT_READ|PROT_WRITE, MAP_SHARED, fd, 0);   /* 进程 B */
/* A 写 *p，B 读 *q 立刻看到变化 —— 同一物理页 */

/* 私有：各自一份副本，首写 COW */
void *r = mmap(NULL, sz, PROT_READ|PROT_WRITE, MAP_PRIVATE, fd, 0);  /* 进程 A */
void *s = mmap(NULL, sz, PROT_READ|PROT_WRITE, MAP_PRIVATE, fd, 0);  /* 进程 B */
/* A 写 *r 触发写时复制(COW)，只改自己的物理页，B 的 *s 不变 */
```

| `flags` | 物理页 | 写语义 | 典型场景 |
|---------|--------|--------|----------|
| `MAP_SHARED` | 多进程**同一物理页** | 一改全可见（文件映射可回盘） | 共享文件、设备缓冲区 |
| `MAP_PRIVATE` | 每进程**各自副本** | 首写 COW，互不影响 | 加载 text 段、私有匿名分配 |

### 指针可以直接指向设备内存

设备的 DMA 缓冲区也能 `mmap` 进用户态——此时指针指向的是**设备内存**（网卡 DMA 环形缓冲区、采集卡寄存器），访存即碰外设，省掉 read/write 的一次拷贝：

```c
/* 网卡零拷贝：报文被 DMA 直写进用户态可访问的缓冲区 */
struct pkt_ring *ring = mmap(NULL, ring_sz, PROT_READ|PROT_WRITE,
                             MAP_SHARED, dev_fd, 0);
/* 直接解引用读报文，不经过内核协议栈拷贝 */
```

### 独占设备：锁在驱动，不在 mmap

**独占设备**（麦克风、独占采集卡）❌ 不是给每个进程各做一份 mmap；✅ 是**设备驱动里做独占锁**——同一时刻只允许一个进程 `mmap` 成功，别的进程调用 `mmap` 失败/阻塞：

```c
/* 驱动侧：独占设备同一时刻只允许一个进程映射 */
static int mic_mmap(struct file *filp, struct vm_area_struct *vma)
{
    if (!atomic_add_unless(&mic_open, 1, 1))
        return -EBUSY;             /* 已被独占 → mmap 失败 */
    return remap_pfn_range(vma, vma->vm_start,
                           mic_dma_paddr >> PAGE_SHIFT,
                           vma->vm_end - vma->vm_start,
                           vma->vm_page_prot);
}
```

> **关键**：互斥逻辑写在**设备驱动**里，`mmap` 只是「给指针一块能碰到设备的虚拟地址」，本身不提供任何互斥。设备能不能让你映射，由驱动说了算。

## HFT / DPDK

| 场景 | 地址含义 | 要点 |
|------|----------|------|
| DPDK mbuf | `rte_mbuf` 结构体起始 | data 指针指向报文负载 |
| MMIO | 寄存器映射的虚拟地址 | `volatile` + 非 cache，访存即触外设 |
| 物理地址 iova | DMA 用的真实物理地址 | `rte_mbuf_data_iova`，零拷贝给网卡 |
| hugepage | 2MB/1GB 页 | 减少 TLB miss，HFT 报文池常驻 |

`virt2phy` 转换是 DPDK 零拷贝的前提——网卡只认物理地址，CPU 只用虚拟地址。

## 常见误区

| 误区 | 事实 |
|------|------|
| "地址就是数字，能随便算" | 必须在合法范围内算（**6.13** UB 边界） |
| "32 位程序指针 4 字节很正常" | 64 位系统上指针 8 字节，混用模型会错 |
| "非对齐访问一定能跑" | x86 能跑但慢；SIMD 直接崩 |
| "栈地址固定" | ASLR 每次运行随机化栈/堆/库基址 |
| "mmap 会立刻把文件/设备数据搬进内存" | 只是建立映射；访问才触发缺页中断填页 |
| "绑核（taskset）就能让数据就近" | 绑核只定 CPU；内存页可能仍落在远端 NUMA node，需 `numactl`/`mbind` 就近分配 |

### 实验：用户态亲手做 VA→PFN 翻译（衔接 ch18 / MMU）

`/proc/self/pagemap` 暴露每页的 PFN，可验证"同一虚拟地址每次映射到不同物理页"：

```c
#define _GNU_SOURCE
#include <stdio.h>
#include <stdint.h>
#include <fcntl.h>
#include <unistd.h>

uint64_t vaddr_to_pfn(void *vaddr) {
    uint64_t page = (uint64_t)vaddr / 4096, entry;
    int fd = open("/proc/self/pagemap", O_RDONLY);
    pread(fd, &entry, 8, page * 8);
    close(fd);
    return entry & 0x7fffffffffffffULL;  /* bit 63=present，低 57 位=PFN */
}

int main(void) {
    int x = 42;
    printf("&x=%p pfn=0x%lx\n", &x, vaddr_to_pfn(&x));
    return 0;
}
```

- 需 root 或 `CAP_SYS_ADMIN`（4.0 起普通用户的 PFN 被清零——地址泄露侧信道）
- 连跑两次观察：`&x` 每次不同（栈 ASLR）；pfn 每次不同（内核分配任意空闲页帧）
- 这就是"每进程独占地址空间幻觉"的可观测证据：**虚拟连续 ≠ 物理连续**，`arr[1000]` 的物理页可以散落 DRAM 任意位置

## 代码自测

**题目 1：** 以下代码中 p 的值和 &x 的值有什么关系？
```c
int x = 42;
int *p = &x;
```

<details>
<summary>参考答案</summary>

p 的值等于 &x——p 存储了 x 的地址。&x 是取地址操作符，得到 x 在内存中的地址。p 是一个变量，它存储的值就是那个地址。所以 p == &x 为真。

</details>
