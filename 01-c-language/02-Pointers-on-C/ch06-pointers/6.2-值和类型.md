# 6.2 值和类型

## 本节讲什么

**类型**决定三件事：占多少字节、位模式如何解释、指针 `+1` 的步长。同一地址，换个类型解读，读出的内容完全不同——这是协议解析、序列化的基础，也是严格别名规则的雷区。

## 要点

- **类型 = 语义**：地址相同，`int*` 读 4 字节按补码解释，`float*` 读 4 字节按 IEEE 754 解释，`char*` 读 1 字节
- `sizeof(T)` 得对象字节数（编译期常量）
- 指针类型 `T*` 表示"指向 T 的指针"，`T* + 1` 移动 `sizeof(T)` 字节（**6.13.1**）

### 声明陷阱（经典面试题）

```c
int *a, b;      /* a 是 int*，b 是 int —— * 只跟最近一个名字 */
int *a, *b;     /* 两个都是 int* */
```

C 的声明语法是"声明符"逐个修饰，`*` 是前缀修饰单个声明符。推荐一行一个指针：

```c
int *a;
int *b;
```

### 类型双关（type punning）

同一块内存，用不同类型读：

```c
float f = 1.0f;
uint32_t bits = *(uint32_t *)&f;   /* 读出 IEEE 754 位模式 */
```

这种"指针 cast 后解引用"在**严格别名**下是 **UB**（见下）。安全做法是用 `union` 或 `memcpy`：

```c
union { float f; uint32_t u; } u;
u.f = 1.0f;
uint32_t bits = u.u;              /* 合法：union 保证可读任意成员 */

/* 或者 memcpy，编译器优化成寄存器移动，无开销 */
uint32_t bits;
memcpy(&bits, &f, sizeof bits);
```

## 底层映射

### 严格别名规则（Strict Aliasing）

C99 6.5/7：通过类型 T 的左值访问对象，对象的实际类型必须与 T 兼容（或 char/void 的特例）。违反 → **UB**，`-O2` 起编译器会做"两个不同类型指针必不指向同一对象"的假设，导致静默错误结果。

```c
int    x = 0x40490FDB;   /* 1.0f 的位模式，但 x 是 int */
float *fp = (float *)&x;
*fp = 2.0f;              /* 严格别名 UB：通过 float* 改 int 对象 */
printf("%d\n", x);       /* -O2 下可能仍是旧值（编译器认为没人改它） */
```

例外：`char*` / `unsigned char*` / `void*` 可以别名任意类型（所以 `memcpy` 的实现合法）。

```bash
# 开启严格别名检查（gcc）
gcc -O2 -fstrict-aliasing -Wstrict-aliasing=3
# 关闭（某些遗留代码需要）
gcc -O2 -fno-strict-aliasing
```

### 协议解析的合法路径

```c
struct __attribute__((packed)) eth_hdr {
    uint8_t  dst[6];
    uint8_t  src[6];
    uint16_t ether_type;
};

const uint8_t *pkt = ...;   /* char* 别名任意，合法 */
const struct eth_hdr *h = (const struct eth_hdr *)pkt;
uint16_t etype = ntohs(h->ether_type);
```

`pkt` 是 `uint8_t*`（字符类型特例），cast 到结构体指针后解引用——只要布局对齐合法即可。HFT 协议栈大量用 `packed` 结构体 + 字符指针 base。

## HFT / DPDK

| 场景 | 类型语义 |
|------|----------|
| 报文头部解析 | `uint8_t*` base + `packed` 结构体 cast |
| 价格定点 | `int64_t` 存价格 × 1e9，避免浮点 |
| 序列号 | `uint32_t`，依赖无符号环绕（**ch05**） |
| IEEE 754 位操作 | 用 `union`/`memcpy`，不用指针 cast |

## 常见误区

| 误区 | 事实 |
|------|------|
| "指针 cast 后随便解引用" | 严格别名下多数是 UB |
| "`*(float*)&i` 没问题，能跑" | `-O0` 能跑，`-O2` 可能给错误结果 |
| "`union` 也是 UB" | C99 起 union 类型双关是**合法**的 |
| "所有平台 `int` 都是 4 字节" | 嵌入式/16 位机常是 2 字节，用 `int32_t` |

## 实操

```bash
# 看编译器对严格别名的优化差异
gcc -O0 t.c -o t0 && gcc -O2 t.c -o t2
# 比较输出
./t0; ./t2
# 用 -Wstrict-aliasing 找可疑代码
gcc -O2 -Wstrict-aliasing=3 -c t.c
```

## 代码自测

**题目 1：** 以下代码中 p 和 q 有什么区别？
```c
double d = 3.14;
double *p = &d;
char *q = (char *)&d;
```

<details>
<summary>参考答案</summary>

p 是 double*，通过 *p 访问 8 字节的 double。q 是 char*，通过 *q 只访问 1 字节。两者存的地址值相同（都是 &d），但类型不同决定了解引用时读取多少字节以及如何解释。

</details>
