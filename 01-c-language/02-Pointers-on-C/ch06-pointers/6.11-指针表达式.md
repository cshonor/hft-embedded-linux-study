# 6.11 指针表达式

## 本节讲什么

**指针与数组的等价关系**、**指针数组 vs 数组指针**、**字符串与字符指针**——这三组概念是"数组 ≠ 指针"误区的总根源，也是协议解析、字符串处理正确性的前提。本节把它们一次讲透。

## 要点

### `arr[i]` ≡ `*(arr + i)`（核心等价）

```c
char buf[64];
buf[3] == *(buf + 3);     /* 永远相等 */
3[buf] == *(3 + buf);     /* 也合法但禁止写 —— 交换律的副产品 */
```

C 标准把 `E1[E2]` 定义为 `*((E1)+(E2))`，加法可交换，所以 `3[buf]` 合法。工程上从不这么写，但理解它揭示了下标的本质。

### 数组名的三种语义（最易错）

| 表达式 | 含义 | 类型 |
|--------|------|------|
| `buf`（多数上下文） | 首元素地址 `&buf[0]` | `char *` |
| `sizeof(buf)` | 整个数组的大小 | 编译期常量 64 |
| `&buf` | "指向整个数组的指针" | `char (*)[64]` |
| `&buf[0]` | 首元素地址 | `char *` |

```c
char buf[64];
char *p = buf;            /* buf 退化为 &buf[0]，char* */
char (*arrptr)[64] = &buf;/* &buf 是"指向 64 元数组的指针" */
size_t n = sizeof(buf);   /* 64，不退化 */
```

数组名在 `sizeof`、`&`、字符串字面量初始化的 `[]` 之外，**都退化为首元素指针**。

### 指针数组 vs 数组指针（经典区分）

```c
struct rte_mbuf *pkts[32];        /* 指针数组：32 个 mbuf*，pkts 是 struct rte_mbuf**(退化后) */
struct rte_mbuf (*row)[32];       /* 数组指针：1 个指针，指向 32 元数组 */
```

| 声明 | 类型 | 含义 |
|------|------|------|
| `T *arr[N]` | `T *[N]` → 退化为 `T **` | N 个 T* 摆一起 |
| `T (*p)[N]` | `T (*)[N]` | 一个指针，指向 T[N] |

读法（**螺旋法则**，ch13 详）：从变量名出发，先右后左，遇 `()` 跳出。

### 字符串与字符指针

```c
char *s = "rodata";        /* 字符串字面量在 .rodata，只读 */
s[0] = 'R';                /* SIGSEGV —— 改只读段 */

char t[] = "writable";     /* t 是栈数组，字面量被拷贝进来 */
t[0] = 'W';                /* OK */

const char *proto = "FIX.4.2";  /* 推荐：const 标记只读意图 */
```

| 形式 | 存储 | 可改 | 用途 |
|------|------|------|------|
| `char *s = "abc"` | `.rodata` | 否（改崩） | 只读常量 |
| `char t[] = "abc"` | 栈/全局 | 是 | 可改缓冲 |
| `const char *s = "abc"` | `.rodata` | 否（编译器拦） | 只读常量（推荐） |

`char *s = "abc"` 在 C89 合法但 C11 起 deprecated，C23 起 UB——应一律用 `const char *`。

## 底层映射

### `buf[3]` 的汇编

```c
char buf[64];
char c = buf[3];
```

```
; x86-64 -O2
movsx   eax, BYTE PTR [rsp+3]    ; 直接 [rsp+3]，编译期算好偏移
```

数组在栈上，`buf[3]` 编译期已知偏移 = 3 字节，直接 `[rsp+3]`。若是指针：

```c
char *p = ...;
char c = p[3];
```

```
movsx   eax, BYTE PTR [rdi+3]    ; p 在 rdi，运行期地址 + 3
```

差异：数组偏移编译期定，指针偏移运行期加。`-O2` 后两者常归一，但数组大小信息会丢（退化）。

### 数组退化的边界

```c
void f(int arr[10]) { sizeof(arr); }   /* 退化成 int*，sizeof = 8，不是 40 */
```

函数参数里的 `int arr[10]` 完全等价于 `int *arr`，长度信息丢失——这是 `sizeof(arr)` 在函数内返回指针大小的根因。所以数组函数必须**额外传长度**。

## HFT / DPDK

| 场景 | 用法 |
|------|------|
| 批量收包 | `rte_eth_rx_burst(port, q, pkts, BURST)`：`pkts` 是指针数组 |

## 常见误区

| 误区 | 事实 |
|------|------|
| "数组就是指针" | 不是——数组有大小信息，多数表达式里退化为指针 |
| "`sizeof(arr)` 在函数内能拿数组大小" | 退化成指针，拿到 8 |
| "`char *s = "abc"; s[0]='X';` 没事" | `.rodata` 只读，`SIGSEGV` |
| "`3[buf]` 是错的" | 标准合法（`*(3+buf)`），但禁止写 |
| "`T *a[N]` 和 `T (*a)[N]` 一样" | 完全不同：前者 N 个指针，后者 1 个指向数组的指针 |

## 实操

```bash
# 看 buf[3] 和 p[3] 的汇编差异
gcc -O2 -S t.c -o -
# 看字符串字面量在 .rodata
objdump -s -j .rodata ./prog
# 看数组退化
cat > t.c << 'EOF'
#include <stdio.h>
void f(int arr[10]) { printf("%zu\n", sizeof(arr)); }
int main(void) { int a[10]; f(a); return 0; }
EOF
gcc t.c -o t && ./t   # 打印 8（指针大小），不是 40
```
