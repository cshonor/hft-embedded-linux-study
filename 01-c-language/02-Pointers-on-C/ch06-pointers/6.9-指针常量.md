# 6.9 指针常量

## 本节讲什么

`const` 与指针的**四种组合** + `void*` 通用指针 + `restrict` 别名承诺（**ch03** 延伸，本章落地）。`restrict` 是 HFT 性能优化的核心关键字——它触发向量化，本节给出汇编证据。

## 要点

### const 四层（读法：const 修饰它左边紧邻的 `*`；若在最左则修饰基类型）

| 声明 | 指向对象 | 指针自身 | 读法 |
|------|----------|----------|------|
| `int *p` | 可改 | 可改 | 普通指针 |
| `const int *p` | 只读 | 可改 | "指向 const int 的指针" |
| `int *const p` | 可改 | 只读 | "指向 int 的 const 指针" |
| `const int *const p` | 只读 | 只读 | 两边都锁 |
| `const char *restrict p` | 只读 + 无别名 | 可改 | 只读字面量专用 |

```c
const int *p = &a;
p = &b;      /* OK：改指针自身 */
*p = 1;      /* 编译错误：改所指对象 */

int *const q = &a;
q = &b;      /* 编译错误：改指针自身 */
*q = 1;      /* OK：改所指对象 */
```

**记忆口诀**：`const` 在 `*` 左边 → 锁内容；`const` 在 `*` 右边 → 锁指针本身。

### void* 通用指针（无类型指针）

```c
void *raw = rte_malloc(NULL, 1024, 64);
struct quote_pkt *q = (struct quote_pkt *)raw;
```

- 任意对象地址可赋给 `void*`（无需 cast）
- **不能** `*raw`：不知宽度
- **不能** `raw++`：不知步长（GCC 扩展按 1 字节算，但非标准）
- `malloc` 返回 `void*`；使用前 cast 到具体类型
- `void*` 与其他对象指针转换无损；但与函数指针互转在非 POSIX 平台非可移植

#### 把 void* 讲透

**`void*` 的 `void` 含义：指向的内存没有绑定具体的数据类型**——不是"没有返回结果"（那是函数返回值 `void` 的语义，两码事）。

| 指针类型 | 能指向谁 |
|----------|----------|
| `int*` | 只能指向 `int` |
| `float*` | 只能指向 `float` |
| **`void*`** | **任意变量的地址都能放进来** |

```c
int a = 10;
float f = 3.14f;
void *p;
p = &a;   /* OK：int 地址放进 void* */
p = &f;   /* OK：float 地址也行 */
```

**⚠️ 重点：`void*` 不能直接解引用。**

```c
*p;      /* 编译报错！ */
```

编译器不知道 p 指向的内存是 int？float？还是 char？——**不知道要读几个字节，所以不允许写 `*p`**。想要读内容，必须**强制转换成具体类型指针之后，才能解引用**。

#### 回到 memcpy 的原型：为什么入参是 void*

```c
void *memcpy(void *dest, const void *src, size_t n);
```

memcpy 要拷贝**任意类型**的内存，它不在乎你存的是 int、float 还是结构体。所以入参用 `void*` 接收各种各样的地址；**函数内部从不对 `void*` 解引用**——它按字节，用 `unsigned char*` 去访问内存：

```c
/* memcpy 内部伪代码：把 void* 转成 char*，逐字节拷贝 */
unsigned char *d = dest;
const unsigned char *s = src;
for (size_t i = 0; i < n; i++)
    d[i] = s[i];
```

**`char*`/`unsigned char*` 是严格别名规则的豁免**，可以读取任意内存的原始字节——这就是 memcpy 安全的根源（→ 6.11 严格别名，ch09 9.9 机制详解）。

#### printf 里的 `(void *)` 是什么

```c
printf("%p", (void *)&a);
```

`%p` 格式化符，标准规定**必须传入 `void*` 类型的指针**。这不是说"打印就安全"，是 **C 标准要求参数类型必须匹配 `%p`**——直接传 `int*` 在某些编译器上报警告、按标准是 UB。所以习惯上强转成 `(void *)` 再丢给 printf。

#### 两个易混点

| ❌ 错误理解 | ✅ 正解 |
|------------|--------|
| "`void*` 代表没有返回结果" | `void` 作**函数返回值**才代表无返回值；`void*` 是**指针类型**，代表指向的内存没有绑定具体类型 |
| "`void*` 指针本身访问就安全" | `void*` 本身**不能解引用**；真正安全的是 memcpy 内部转成 `char*` 按字节复制 |

## 底层映射

### restrict 与向量化（汇编证据）

`restrict` 承诺"在我生命周期内，这块内存只能通过我这个指针访问"——编译器据此假设无别名，可激进优化。

```c
void add(int *restrict a, const int *restrict b, int n) {
    for (int i = 0; i < n; i++) a[i] += b[i];
}
```

```bash
gcc -O3 -mavx2 -S add.c -o -
```

```
; 有 restrict：一条 paddd 处理 8 个 int（向量化）
.L1:
    vmovdqu  ymm0, [rdi+rax*4]      ; 加载 a[i..i+7]
    vpaddd   ymm0, ymm0, [rsi+rax*4]; 一次加 8 个
    vmovdqu  [rdi+rax*4], ymm0      ; 写回
    add      rax, 8
    cmp      rax, rdx
    jl       .L1

; 无 restrict（删掉 restrict）：标量循环 + 每次重新 load
; 编译器怕 a 和 b 重叠，不敢批量读写
.L1:
    mov     eax, [rdi+rcx*4]
    add     eax, [rsi+rcx*4]
    mov     [rdi+rcx*4], eax
    inc     rcx
    ...
```

`restrict` 让循环从 8 倍提速到极致——这是 HFT 信号处理的常见手法。

### const 的段映射

| 声明 | 内容存哪 |
|------|---------|
| `const int g = 5;` | `.rodata`，写会 `SIGSEGV` |
| `const int *p = &g;` | p 在栈，指向 `.rodata` |
| 函数内 `const int x = 5;` | 可能折叠成立即数，无访存 |

## HFT / DPDK

| 场景 | 用法 |
|------|------|
| 只读报文 | `const uint8_t *pkt` 表示"我不改它" |
| 拷贝去别名 | `memcpy(void *restrict dst, const void *restrict src, ...)` |
| 通用句柄 | `void *private_data` 存任意上下文 |
| 配置不变 | `const struct config *cfg` 全函数只读 |

## 常见误区

| 误区 | 事实 |
|------|------|
| "restrict 是优化提示，违反也没事" | 违反 `restrict` 是 **UB**，结果不可预测 |
| "`const int *p` 表示 p 是常量" | p 可改指向，`*p` 才是只读 |
| "void* 能 `++`" | 标准不允许（不知步长） |
| "`void*` 代表没有返回结果" | 那是函数返回值 `void`；`void*` 是指针类型，代表未绑定具体类型 |
| "`void*` 本身访问安全" | `void*` 不能解引用；安全的是 memcpy 内部转 `char*` 按字节复制 |
| "const 一定在 .rodata" | 函数内 const 常折叠成立即数，不入段 |
| "restrict 检查靠运行时" | 纯编译期承诺，运行时不检查 |

## 实操

```bash
# 对比 restrict 开关的汇编差异
cat > t.c << 'EOF'
void add(int *a, const int *b, int n) {
    for (int i=0;i<n;i++) a[i]+=b[i];
}
EOF
gcc -O3 -mavx2 -S t.c -o no_restrict.s
sed 's/int \*a/int *restrict a/;s/int \*b/int *restrict b/' t.c > t2.c
gcc -O3 -mavx2 -S t2.c -o with_restrict.s
diff no_restrict.s with_restrict.s   # 看是否出现 paddd
# 看 .rodata 段
objdump -s -j .rodata ./prog
```

## 代码自测

**题目 1：** 以下三种声明有什么区别？
```c
const int *p1;      // A
int *const p2;      // B
const int *const p3; // C
```

<details>
<summary>参考答案</summary>

A：p1 指向的值是 const（不能通过 *p1 修改），但 p1 本身可以指向别处。B：p2 本身是 const（不能指向别处），但指向的值可以修改。C：两者都是 const。记忆口诀：const 在 * 左边修饰值，在 * 右边修饰指针。

</details>

**题目 2：** 绕一层 `void*` 再强转，还 UB 吗？
```c
float f = 1.0f;
void *vp = &f;
*(uint32_t *)vp;   // 这一行？
```

<details>
<summary>参考答案</summary>

**依然触发严格别名 UB。**

拆开看：`vp = &f` 合法（任意地址都能放进 `void*`）；`(uint32_t *)vp` 这一步 cast 也合法（只改指针类型不碰内存）；但最后的 `*` 解引用时，**是用 `uint32_t` 类型的 lvalue 去访问一块有效类型为 `float` 的内存**——和直接写 `*(uint32_t *)&f` 一模一样。

判定关键：严格别名规则只看**最终以什么类型解引用**。中间经过 `void*` 中转、经过几次指针类型转换，都不影响判定——`void*` 只是地址的"通用容器"，不是别名豁免的通道（豁免只给 `char*`/`unsigned char*`）。

要安全取位模式：`memcpy(&bits, &f, 4)`（→ 6.11）。

</details>
