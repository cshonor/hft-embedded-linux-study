# 6.5 未初始化和非法的指针

## 本节讲什么

**野指针**与**悬垂指针**——生产环境段错误、堆破坏、数据损坏的 **Top 原因**。这一节把这几类坏指针的成因、表现、检测手段、编译期防护讲全。HFT 系统里一次 UAF 可能让订单重复成交，必须从写第一行代码就建立纪律。

## 要点

### 野指针（未初始化）

```c
int *p;        /* 自动存储期，未初始化 → 栈帧上的垃圾值 */
*p = 1;        /* 把垃圾当地址写 → SIGSEGV 或踩坏别人 */
```

局部变量在栈帧上，内容是上一个函数留下的残值。这个值可能碰巧落在可写页 → 静默踩数据，可能落在不可写页 → `SIGSEGV`。**最坏情况是"碰巧能跑"**，因为问题被掩盖到很远的地方才爆。

**规范**：局部指针声明即 `= NULL`，或立即赋有效地址。

### 悬垂指针（use-after-free）

```c
int *p = malloc(sizeof(int));
free(p);
/* p 仍存旧地址 —— 悬垂 */
*p = 10;       /* UAF：堆破坏，可能写到别人 malloc 的块上 */
```

`free` 不改 `p` 的内容（它不知道 `p` 在哪），只是把堆块标记为可再分配。UAF 的恐怖在于：内存可能已被 `malloc` 给了别人，`*p = 10` 写到别人对象上，**不崩，但数据错乱**。

**规范**：`free(p); p = NULL;` —— 让悬垂指针解引用变成可预测的 `SIGSEGV`（解 NULL）而非静默踩数据。

### 非法指针的其他来源

- **越界**：`arr + 100` 后解引用（**UB**，**6.13**）
- **栈局部返回**：`int *f() { int x; return &x; }`（**ch07**，返回即失效）
- **修改只读字面量**：`char *s = "abc"; s[0] = 'X';`（**6.11**，`.rodata` 段，`SIGSEGV`）
- **未对齐的 cast**：`int *p = (int *)((char *)malloc(1) + 1);`（某些平台 `SIGBUS`）

## 底层映射

### 栈垃圾值演示

```c
void leak(void) {
    int *p;          /* 不初始化 */
    /* 这里 p 的值是上一个栈帧的残留 */
}

int main(void) {
    int arr[4] = {0xdead, 0xbeef, 0xcafe, 0xbabe};
    leak();          /* leak 的栈帧复用 arr 的位置 */
}
```

不开优化时，`p` 很可能指向 `arr` 区域——解引用"能跑"但语义全错。这就是野指针最阴险之处。

### 编译期防护

```bash
# gcc 把局部变量自动初始化为零（牺牲少许性能换安全）
gcc -ftrivial-auto-var-init=zero t.c
# 或初始化为 pattern（0xAA...，更易识别）
gcc -ftrivial-auto-var-init=pattern t.c
# Clang 同名选项
clang -ftrivial-auto-var-init=zero t.c
```

这是 Linux 内核、Chrome 等已采用的硬化选项，HFT 生产构建强烈建议开。

### 运行期检测

| 工具 | 检测范围 | 开销 |
|------|---------|------|
| **ASan** (`-fsanitize=address`) | UAF / 堆越界 / 栈越界 / 返回栈地址 | 2x 速度，3x 内存 |
| **Valgrind/memcheck** | 同上 + 未初始化读 | 20x 速度 |
| **MSan** (`-fsanitize=memory`) | 未初始化读 | 仅 Clang，需全程序 |
| **UBSan** (`-fsanitize=undefined`) | 越界、空解引用等 UB | 低 |

```bash
# ASan 抓 UAF（开发/测试环境标配）
gcc -g -fsanitize=address,undefined t.c -o t && ./t
# 报告会精确指出 "heap-use-after-free" 和调用栈
```

## HFT / DPDK

| 场景 | 风险 | 纪律 |
|------|------|------|
| mbuf 复用 | 释放后仍引用 | `rte_pktmbuf_free` 后立刻置 NULL |
| 报文缓冲返回 | 调用者拿到指针但缓冲已还 | API 文档明确生命周期 |
| 订单对象池 | UAF 改到别人的订单 | 池化 + 句柄而非裸指针 |
| 多线程 | 释放与访问竞态 | RCU / 引用计数（**ch13**） |

## 常见误区

| 误区 | 事实 |
|------|------|
| "`free(p)` 会把 `p` 置 NULL" | 不会，`p` 内容不变，需手动 `p = NULL` |
| "野指针一定立刻崩" | 最怕的是"碰巧能跑"，掩盖问题 |
| "Valgrind 抓得到所有 UAF" | 栈对象、内存池复用未必覆盖 |
| "开了优化就没事" | `-O2` 反而更危险：未初始化值被任意假设 |

## 实操

```bash
# 1. 看未初始化指针的垃圾值
gcc -O0 t.c -o t && gdb ./t -ex 'b f' -ex r -ex 'p p'
# 2. 开编译期初始化
gcc -ftrivial-auto-var-init=pattern -O2 t.c
# 3. ASan 抓 UAF
gcc -g -fsanitize=address t.c -o t && ./t
# 4. CI 里把 -Wuninitialized -Wmaybe-uninitialized 开成 error
gcc -Werror=uninitialized -Werror=maybe-uninitialized
```
