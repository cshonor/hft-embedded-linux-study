# 1.2 补充说明

## 本节讲什么

本章提到但未展开的主题的**速览**：变量与类型、存储位置、分支循环、工程规范。每个都是后续章节的引子——本节是"地图概览"，不是详细讲解。目的是让你在读后面章节前，先有一个**全局坐标系**。

## 基础类型（极简预览，详见 ch03）

| 类型 | 用途 | HFT 关注点 |
|------|------|-----------|
| `char` | 字符/最小整型 | 1 字节；`signed`/`unsigned` 平台相关 |
| `short` | 短整型 | 2 字节；省内存用 |
| `int` | 整型（最自然宽度） | 4 字节；循环计数、标志位 |
| `long` | 长整型 | LP64 下 8 字节；指针/大数 |
| `long long` | 更长整型（C99） | 8 字节；时间戳、计数器 |
| `float` | 单精度浮点 | 4 字节；HFT 几乎不用浮点 |
| `double` | 双精度浮点 | 8 字节；行情计算偶尔用 |
| `void` | 无类型 | 函数无返回值/无参声明/`void *` 通用指针 |

### 定宽整型（HFT 必备）

平台相关的 `int`/`long` 宽度不一，跨平台代码用 **`<stdint.h>`**（C99）：

```c
#include <stdint.h>
int8_t   x;    /* 恰好 8 位有符号 */
uint32_t y;    /* 恰好 32 位无符号 */
int64_t  z;    /* 恰好 64 位有符号 */
```

- DPDK/内核/HFT 代码大量用 `uint32_t`/`uint64_t`——**宽度确定，行为可预测**
- `size_t`：`sizeof` 的返回类型，足以容纳任何对象大小（64 位下 8 字节）
- `ptrdiff_t`：两指针相减的类型
- 详见 **ch03.1**。

## 存储位置：内存布局速览

程序加载后，不同变量住在内存的不同区域：

```
高地址
┌──────────────┐
│ 栈 stack ↓    │  局部自动变量、函数调用帧
│              │  生命周期：函数返回即销毁
├──────────────┤
│ (空闲，向下生长)│
├──────────────┤
│ 堆 heap ↑    │  malloc/calloc 分配
│              │  生命周期：free 才回收
├──────────────┤
│ .bss         │  未初始化全局/静态，启动时清零
├──────────────┤
│ .data        │  已初始化全局/静态
├──────────────┤
│ .rodata      │  字符串字面量、const 全局（只读，写→SIGSEGV）
├──────────────┤
│ .text        │  机器码（只读、可执行）
└──────────────┘
低地址
```

| 声明方式 | 落在 | 生命周期 | 初始化 |
|---------|------|---------|--------|
| `int x;`（函数内） | 栈 | 函数返回即销毁 | **未初始化**（值不定，UB 读取） |
| `static int x;`（函数内/外） | .bss/.data | 整个进程 | 默认 0 |
| `int x;`（函数外，全局） | .bss/.data | 整个进程 | 默认 0 |
| `int x = 5;`（全局） | .data | 整个进程 | 5 |
| `malloc(sizeof(int))` | 堆 | `free` 才回收 | **未初始化** |
| `calloc(...)` | 堆 | `free` 才回收 | 清零 |
| `"hello"`（字符串字面量） | .rodata | 整个进程 | "hello"，只读 |

### 踩坑：栈上大数组

```c
void f(void) {
    char buf[1024 * 1024];   /* 1MB 局部数组 */
    /* ... */
}
```

- 栈默认 8MB（`ulimit -s` 查看），1MB 数组 + 函数调用链 → 可能溢出 → **SIGSEGV**
- DPDK/嵌入式：在 worker 栈小的场景更危险
- **解法**：大缓冲改 `static`（全局）或 `malloc`（堆）

### 踩坑：返回栈变量地址

```c
int *bad(void) {
    int x = 42;
    return &x;   /* 悬垂指针！函数返回后 x 被销毁 */
}
```

栈帧在函数返回后被回收，返回的地址指向**已失效的内存**——读取是 UB，可能拿到垃圾值，可能恰好正常数月后崩溃。详见 **ch06/ch11**。

## 分支与循环（速览，详见 ch04）

- **if / else if / else**：多路选择
- **for**：已知次数的迭代
- **while**：条件驱动的迭代
- **do-while**：至少一次的迭代
- **switch**：多值选择（ch04.8，注意 fall-through 陷阱）
- **goto**：受限使用，错误处理/状态机/跳出嵌套循环（ch04.9）

本章示例已覆盖 if/for/while；运算符优先级、求值顺序在 **ch05**。

## 工程规范（仓库配套）

1. **格式化**：统一缩进与大括号，用 `clang-format` 强制
2. **Makefile**：各章通用模板，可复用到 DPDK Demo（见 1.3）
3. **注释**：团队约定 `//` vs `/* */`；公共 API 必文档化（见 1.1.1）
4. **编译选项**：`-Wall -Wextra -Werror` 警告全开、警告当错误（HFT 工程标配）
5. **命名**：函数/变量命名一致风格（snake_case 是 C 主流）
6. **单文件单职责**：大程序拆多个 `.c`/`.h`，不要一个文件几千行

### `-Wall -Wextra -Werror` 为什么是铁律

| 选项 | 作用 | 不开的后果 |
|------|------|-----------|
| `-Wall` | 常见问题警告（未用变量、`=` 写成 `==`、格式串不匹配） | 这些 bug 潜伏数月才爆发 |
| `-Wextra` | 更严格的额外警告（空参 `()`、隐式转换） | 默默引入可移植性 bug |
| `-Werror` | 警告当错误，编译直接失败 | 警告被忽略，逐渐积累成系统性问题 |

> HFT/内核代码库几乎都 `-Werror`。开发时嫌烦可以临时 `-Wno-error=xxx`，但提交前必须清零。

## 常见误区

| 误区 | 纠正 |
|------|------|
| `int` 到处是 4 字节 | LP64/ILP64/LLP64 模型下 long 宽度不同；定宽用 `stdint.h` |
| 局部变量默认清零 | 只有 .bss 的全局/静态清零；局部自动变量不清零，读取是 UB |
| `malloc` 返回的内存清零 | `malloc` 不清零，要清零用 `calloc` 或 `memset` |
| 字符串字面量可修改 | 在 .rodata，修改是 UB，通常 SIGSEGV |
| 栈很大随便用 | 默认 8MB，大数组/深递归容易溢出 |
| `void main()` 也行 | 非标准，见 1.1.3 |

## 代码自测

**题目 1：** 以下代码在 32 位和 64 位系统上输出可能不同，为什么？
```c
printf("%d\n", sizeof(int *));
```

<details>
<summary>参考答案</summary>

32 位系统上指针大小通常是 4 字节，64 位系统通常是 8 字节。sizeof 返回 size_t 类型，用 %d 打印在 64 位系统上可能截断（因为 size_t 是 8 字节而 %d 只读 4 字节）。正确做法是用 %zu（C99）或强制转换为 unsigned long 配合 %lu。

</details>
