# 1.1 简介

## 本节讲什么

全书开篇：用一个**完整但极简**的 C 程序（列宽排序示例）走通「写代码 → 编译 → 运行 → 退出」全链路。本章是**铺垫章**，不深入语法，只建立**从源码到 CPU 执行**的最小认知模型——这个模型是后续指针、内存、结构体、ABI 所有话题的地基。

## 为什么这一章对 HFT 学习者特别重要

很多写出过能跑的 C 程序的人，其实说不清下面这条链路的每一步：

```
.c 源文件
  │ 预处理 (-E)        ← 1.1.2 #include/#define 在此展开
  ▼
.i 纯 C 文本
  │ 编译 (-S)          ← 语法分析、优化、生成汇编
  ▼
.s 汇编文本
  │ 汇编 (-c)          ← 翻译成机器码，产物是 ELF 可重定位目标文件
  ▼
.o 目标文件
  │ 链接               ← 解析 printf 等未定义符号，合并各 .o 的段
  ▼
ELF 可执行文件
  │ 加载 (execve)      ← 内核建进程、映射虚拟内存、跳转入口
  ▼
进程运行 → main → return → 退出码
```

**HFT 的现实**：DPDK 应用、行情解析程序、内核模块，本质都走这条路。看懂这条链路，是看懂 meson/Makefile 构建系统、`ld` 链接错误、`dlopen` 动态加载、core dump 栈回溯的前提。本章不是"Hello World 练习"，而是**把整条工具链摸一遍**。

## 最简骨架（仓库标准模板）

```c
#include <stdio.h>

int main(void)
{
    printf("Hello Low Latency & Kernel\n");
    return 0;
}
```

| 部分 | 底层含义（HFT/内核视角） |
|------|--------------------------|
| `#include <stdio.h>` | 预处理阶段把头文件**声明**文本插入；`printf` 的**实现**在 **libc**，链接时解析 |
| `int main(void)` | 唯一入口；`(void)` 显式无参，工程规范——避免旧式 `main()` 的隐式参数陷阱 |
| `printf` | libc 封装，底层走 **`write(2)`** syscall，最终陷入内核 |
| `return 0` | 退出码；shell **`echo $?`** 可读；交易程序用退出码区分正常/异常退出 |

## 内存布局预览（整章贯穿）

程序加载后，虚拟地址空间大致如此（详见 ch03/ch18）：

```
高地址
┌──────────────┐
│ 栈 stack ↓    │  局部自动变量、调用帧（ch18.1.3 栈帧）
├──────────────┤
│              │
├──────────────┤
│ 堆 heap ↑    │  malloc 分配（ch11）
├──────────────┤
│ .bss         │  未初始化全局/静态，启动时清零
├──────────────┤
│ .data        │  已初始化全局/静态
├──────────────┤
│ .rodata      │  字符串字面量、const（写它 → SIGSEGV）
├──────────────┤
│ .text        │  机器码（只读、可执行）
└──────────────┘
低地址
```

**口诀**：局部变量在栈、全局/静态在 data/bss、`malloc` 在堆、代码在 text、字符串字面量在 rodata。现在记不住没关系，ch03/ch11/ch18 会逐一展开——但**先有这张地图**，后面读到"返回局部变量地址是悬垂指针"才不会懵。

## 本章程序结构（书中示例）

1. **main** — 控制流程，调用读写与排序
2. **read_column_numbers** — 从 stdin 读入列宽（首次引入 **`&` 取地址**，1.1.4）
3. **rearrange** — 对读入数据重排（熟悉 if/for，1.1.5）

三个函数串起"输入 → 处理 → 输出"的最小工程结构，也示范了**main 协调、子函数单一职责**的代码组织原则。

## 本章你应建立的三个直觉

1. **C 程序不是"运行就完事"** —— 它有明确的构建链路、加载过程、退出语义；每一步都可能出错，每一步都有工具（`gcc -E/-S/-c`、`file`、`ldd`、`gdb`）。
2. **指针从第一章就出现了** —— `scanf("%d", &val)` 里的 `&` 就是取地址，`scanf` 要指针才能写入变量。这不是"高级特性"，是 C 的基本运作方式。
3. **底层工具先于语法** —— gdb、Makefile、`-Wall -Wextra` 这些工程习惯，从第一章就养成，比后面补容易得多。

## 实操（本章）

1. 编译示例，用 `-E/-S/-c` 查看各阶段产物（见 1.3）
2. 对比动态链接与 `-static` 二进制大小（`ls -lh`、`ldd`）
3. gdb 在 `main` 打断点，`print &val` 观察栈上地址
4. scanf 故意省略 `&` 制造段错误，gdb `bt` 定位
