# 15.2 终止执行

## 本节讲什么

程序遇到不可恢复的错误时需要终止——`exit` 做正常清理退出，`abort` 做异常崩溃退出。这一节给出两者的行为差异、`atexit` 回调机制、退出时的 stdio 刷新顺序，以及 HFT 工程里数据面与控制面对「退出」的不同态度。

认知锚点：`exit` 和 `abort` 不是「同一件事的两种写法」，而是**语义完全不同**——`exit` 是「我知道出错了，但还能有序收尾」，`abort` 是「状态已损坏，不能再信任任何代码」。HFT 数据面绝不能因 I/O 错误退出，控制面启动失败可以 exit。

## 要点

### exit：正常退出

```c
#include <stdlib.h>

void exit(int status);
```

`exit(status)` 做以下事情，按顺序：

1. **调用 `atexit` 注册的回调**（按注册的逆序）。
2. **刷新并关闭所有 stdio 流**：`fflush` 所有打开的 `FILE *`，包括 stdout/stderr。
3. **删除 `tmpfile` 创建的临时文件**。
4. **调用 `_exit`**（POSIX）：关闭文件描述符，释放资源，结束进程。
5. **返回 status 给父进程**（`$?` 获取）。

```c
atexit(cleanup_func);   /* 注册退出回调 */
exit(EXIT_SUCCESS);     /* 0 */
exit(EXIT_FAILURE);     /* 1 */
```

### abort：异常退出

```c
void abort(void);
```

`abort()` 做以下事情：

1. **向自己发送 `SIGABRT` 信号**。
2. **不调用 `atexit` 回调**。
3. **不刷新 stdio 缓冲**（实现相关，部分实现会刷新）。
4. **生成 core dump**（若系统启用）。
5. **返回 `SIGABRT` 给父进程**（退出码 134）。

`abort` 用于**程序状态已损坏，不能再信任任何代码**的场景。断言失败（`assert` 在 NDEBUG 未定义时）内部调用 `abort`。

### exit vs abort 对比

| 维度 | `exit(status)` | `abort()` |
|------|----------------|-----------|
| 调用 atexit 回调 | 是（逆序） | 否 |
| 刷新 stdio 缓冲 | 是 | 否（实现相关） |
| 关闭 FILE * | 是 | 由 OS 回收 fd |
| 生成 core dump | 否 | 是（若启用） |
| 信号 | 无 | SIGABRT |
| 退出码 | status | 134（128 + SIGABRT） |
| 语义 | 有序收尾 | 异常崩溃 |
| 适用 | 可恢复错误 | 不可恢复错误 |

### atexit 回调

```c
#include <stdlib.h>

void cleanup_logs(void)    { flush_log_buffer(); }
void cleanup_shm(void)     { unlink_shm_files(); }
void cleanup_network(void) { close_sockets(); }

int main(void) {
    atexit(cleanup_logs);      /* 第三个执行 */
    atexit(cleanup_shm);       /* 第二个执行 */
    atexit(cleanup_network);   /* 第一个执行（逆序） */

    /* ... */

    if (fatal_error)
        exit(EXIT_FAILURE);    /* 触发回调 */

    return 0;                  /* return 从 main 等价 exit */
}
```

`atexit` 注册的回调在 `exit` 或 `return from main` 时按**注册的逆序**执行。用于资源清理：日志刷新、共享内存释放、网络关闭。

- **注册上限**：标准保证至少 32 个，实际通常更多。
- **回调签名**：`void (*)(void)`，无参无返回。
- **回调中调用 exit**：UB，可能导致死循环。

### _exit：直接退出（POSIX）

```c
#include <unistd.h>

void _exit(int status);   /* 不刷新缓冲，不调 atexit */
```

`_exit` 是最底层的退出，直接进入内核：

- 不调用 `atexit` 回调。
- 不刷新 stdio 缓冲。
- 关闭文件描述符（由内核完成）。
- 用于 `fork` 后的子进程，避免污染父进程缓冲。

```c
pid_t pid = fork();
if (pid == 0) {
    /* 子进程 */
    _exit(127);   /* 不用 exit，避免刷新从父进程继承的 stdio 缓冲 */
}
```

### stdio 刷新顺序

```
exit(status)
   |
   | 1. atexit 回调（逆序）
   v
   | 2. fflush 所有 FILE *（含 stdout/stderr）
   v
   | 3. fclose 所有 FILE *
   v
   | 4. _exit(status) → 内核回收资源
```

**关键**：`exit` 会刷新所有 stdio 缓冲。如果崩溃前想确保日志落盘，用 `exit` 而非 `abort`。但若状态已损坏，`exit` 的回调可能再次触发错误，此时用 `abort` + core dump 更安全。

### return from main vs exit

```c
int main(void) {
    /* ... */
    return 0;   /* 等价 exit(0)，触发 atexit 回调 */
}
```

`return` 从 `main` 返回**等价于 `exit`**——都会调用 `atexit` 回调、刷新 stdio。但 `return` 会先析构 main 的局部变量（C++ 有析构函数，C 无）。C 中两者基本等价。

## HFT 关联

### 控制面启动失败用 exit

```c
int main(int argc, char **argv) {
    if (load_config("hft.conf") < 0) {
        fprintf(stderr, "config load failed\n");
        exit(EXIT_FAILURE);   /* 启动失败，有序退出 */
    }

    FILE *fp = fopen("/data/quote.dat", "rb");
    if (!fp) {
        perror("fopen");
        exit(EXIT_FAILURE);   /* 数据文件不可用，退出 */
    }

    /* ... 启动数据面 ... */
    run_dataplane();
    return 0;
}
```

控制面启动阶段遇到不可恢复错误（配置错、数据文件缺失、依赖库初始化失败），用 `exit` 有序退出，刷新日志、释放资源。

### 数据面热路径避免 exit/abort

```c
/* 数据面处理报文 */
void on_packet(struct rte_mbuf *m) {
    if (parse_failed(m)) {
        stats_inc(STATS_PARSE_ERR);
        rte_pktmbuf_free(m);
        return;   /* 继续处理下一个，不退出 */
    }

    /* 即使严重错误也不退出 */
    if (orderbook_corrupted()) {
        stats_inc(STATS_OB_CORRUPT);
        alert_admin();   /* 告警，但继续运行 */
        return;
    }
}
```

HFT 数据面对「退出」零容忍——行情不能停、订单不能丢。即使发生严重错误，也要降级运行、告警、继续处理。`exit`/`abort` 只用于启动阶段或人工主动停止。

### abort 用于断言失败

```c
#define ASSERT(cond) do { \
    if (!(cond)) { \
        fprintf(stderr, "ASSERT failed: %s at %s:%d in %s\n", \
                #cond, __FILE__, __LINE__, __func__); \
        fflush(stderr); \
        abort();   /* 生成 core dump 供调试 */ \
    } \
} while (0)

ASSERT(orderbook->levels > 0);   /* 不变式破坏，崩溃调试 */
```

断言失败意味着程序状态已损坏，继续运行可能导致更严重后果（错单、资损）。`abort` 生成 core dump 供事后调试。**HFT 工程通常保留断言在生产环境**——宁可崩溃也不能错单。

### atexit 清理共享内存

```c
static void cleanup_shm(void) {
    shm_unlink("/hft_orderbook");
    shm_unlink("/hft_strategy_state");
}

int main(void) {
    atexit(cleanup_shm);
    /* ... */
}
```

HFT 进程间通过共享内存通信，退出时要清理 `/dev/shm` 下的文件。`atexit` 确保正常退出时清理。**异常崩溃（abort/segfault）不触发 atexit**，需要运维脚本兜底清理。

### fork 后子进程用 _exit

```c
pid_t pid = fork();
if (pid == 0) {
    /* 子进程：执行辅助工具 */
    execl("/usr/bin/tcpdump", "tcpdump", "-i", "eth0", NULL);
    _exit(127);   /* execl 失败才到这里，用 _exit 避免刷新父进程缓冲 */
}
```

`fork` 后子进程继承父进程的 stdio 缓冲副本。若子进程用 `exit`，会刷新这份副本，导致缓冲内容重复输出。`_exit` 不刷新，安全。

## UB 边界

| 情形 | 后果 | 防护 |
|------|------|------|
| `atexit` 回调中调用 `exit` | UB，可能死循环 | 回调只做清理，不调用 exit |
| `exit` 后继续执行 | 不可能，exit 不返回 | 不要期望 exit 后的代码执行 |
| `abort` 不生成 core | ulimit 限制 | `ulimit -c unlimited` |
| `fork` 后子进程用 `exit` | 父进程缓冲重复输出 | 子进程用 `_exit` |
| 回调中取锁但持有者已退出 | 死锁 | atexit 回调避免取锁 |

### atexit 回调的注册上限

```c
/* 标准保证至少 32 个 atexit 回调 */
/* 超过返回非 0 */
if (atexit(my_cleanup) != 0) {
    fprintf(stderr, "atexit registration failed\n");
}
```

大型项目可能注册几十个清理回调，超过实现限制时 `atexit` 返回非 0。**关键清理逻辑应在主退出路径显式调用**，不完全依赖 atexit。

### abort 与 core dump

```bash
# 启用 core dump
ulimit -c unlimited

# 设置 core 路径（Linux）
echo "/var/core/core.%e.%p.%t" > /proc/sys/kernel/core_pattern

# 分析 core
gdb ./my_app core.12345
```

`abort` 生成的 core dump 是事后调试的关键。HFT 生产环境通常配置 core dump 路径，崩溃后自动收集供分析。
