# 15.10 格式化的行 I/O

## 本节讲什么

`printf` 族：`printf` / `fprintf` / `sprintf` / `snprintf` / `vfprintf` 等，以及对应的 `scanf` 族。这是 C 程序员最熟也最常踩坑的接口——格式串与参数类型不匹配、缓冲区溢出、格式串注入攻击。HFT 场景里日志几乎全靠这一族，掌握它等于掌握了控制面输出主力。

## 要点

### printf 族输出目标对照

| 函数 | 输出目标 | 长度限制 | 用途 |
|------|----------|----------|------|
| `printf` | stdout | 无 | 控制台 |
| `fprintf(fp, ...)` | 指定流 | 无 | 落盘日志 |
| `sprintf(buf, ...)` | 数组 | **无界** | **禁用** |
| `snprintf(buf, size, ...)` | 数组 | **限长** | **生产强制** |
| `asprintf(...)`（GNU） | malloc 堆 | 自动 | 调用者负责 free |
| `vfprintf(fp, fmt, ap)` | 指定流 | 无 | 可变参数转发 |
| `vsnprintf(buf, size, fmt, ap)` | 数组 | 限长 | 日志宏核心 |

### snprintf 返回值的反直觉

```c
int n = snprintf(buf, size, "seq=%llu", seq);
```

- `n < 0`：编码错误
- `n < size`：实际写入字节数（不含 `\0`）
- `n >= size`：**被截断**，返回值是"如果缓冲区够大会写多少"

利用这一点可以两次调用：第一次 `snprintf(NULL, 0, fmt, ...)` 拿长度，malloc 后再写。但 HFT 数据面忌讳 malloc，常用栈上固定缓冲 + 截断接受。

### scanf 族的返回值

`scanf` / `fscanf` / `sscanf` 返回**成功匹配并赋值的字段数**，遇文件尾返回 `EOF`。这是判断解析成功的关键，但被无数初学者忽略：

```c
int n = fscanf(fp, "%u %u %u", &seq, &bid, &ask);
if (n != 3) {
    /* 字段不全，可能是格式错或 EOF */
    if (n == EOF) break;
    fprintf(stderr, "bad line, got %d fields\n", n);
    continue;
}
```

### 常用占位符速查

| 符 | 用途 | HFT 典型 |
|----|------|----------|
| `%u` / `%llu` | 无符号整型 | 订单 ID、时间戳 |
| `%d` / `%lld` | 有符号整型 | 价差、数量 |
| `%x` / `%X` | 十六进制 | 标志位、寄存器值 |
| `%p` | 指针 | 调试输出 |
| `%s` | 字符串 | **仅 `\0` 终止文本** |
| `%.10s` | 限长字符串 | 防越界读 |
| `%c` | 单字符 | 协议字段 |
| `%f` / `%lf` | 浮点 | 价位（不推荐用浮点存价格） |
| `%zu` | `size_t` | 字节数 |
| `%jd` / `%ju` | `intmax_t`/`uintmax_t` | 跨平台大整数 |

### 长度修饰符陷阱

`%u` 对应 `unsigned int`，`%llu` 对应 `unsigned long long`。在 64 位 Linux 上 `long` 是 8 字节但 Windows LLP64 上 `long` 是 4 字节——跨平台代码不要用 `%lu` 表示 64 位，统一用 `%llu` 或 PRId64 宏（`inttypes.h`）：

```c
#include <inttypes.h>
uint64_t ts = ...;
printf("ts=%" PRIu64 "\n", ts);   /* 跨平台安全 */
```

### %s 的三大风险

1. **必须 `\0` 终止**：二进制 buf 里没有 `\0` 会一直读到越界
2. **无长度限制**：`%s` 不限长，攻击者可构造超长字符串导致缓冲区溢出（`snprintf` 也只保护 buf，不保护读取源）
3. **格式串注入**：`fprintf(fp, user_input)` 若 `user_input` 含 `%x` 会读栈数据——格式串必须是字面量或受信字符串

```c
/* 错误：user_msg 可能含 %s */
fprintf(log_fp, user_msg);
/* 正确 */
fprintf(log_fp, "%s", user_msg);
```

### 整数溢出与 %d

```c
int bid = 3500000;   /* 单位 0.0001 */
printf("bid=%d\n", bid * 100);   /* 可能溢出 int */
```

HFT 价格常用定点小数（`uint64_t` 或 `int64_t`，单位 0.0001），打印时务必用 `%llu` 或 `%lld`，并考虑溢出。

### scanf 为什么少用

`scanf` 对错误输入极其脆弱：输入 `abc` 给 `%d` 会留下输入流污染，需要手动清空。生产代码通常 `fgets` 整行再 `sscanf` 或 `strtol` 解析，错误恢复更可控。

## HFT 关联

- **日志核心**：`rte_log` 内部就是 `vsnprintf` + `fputs`/`write`，HFT 控制面日志全靠这一族
- **行情落盘**：`snprintf` 拼一行再 `fputs`，比直接 `fprintf` 更易控制缓冲和原子性
- **崩溃前 fflush**：信号处理里 `vsnprintf` 拼栈帧信息后立即 `fflush(stderr)`，确保崩溃栈不丢
- **避免数据面 printf**：每条日志的 `vsnprintf` 解析格式串 + 多次 va_arg 是微秒级开销，数据面禁止 `printf`，日志走异步队列由专门线程消费
- **格式串攻击面**：外部输入绝不能直接当格式串，FIX/二进制协议字段必须用 `"%s"` 包一层
- **时间戳格式化**：`%lld` + `uint64_t` 或 `PRIu64` 打印纳秒时间戳，注意时区与本地时间转换用 `localtime_r`（线程安全版本）

## 代码自测

**题目 1：** 以下 printf 调用有什么问题？
```c
int x = 42;
printf("%s\n", x);
```

<details>
<summary>参考答案</summary>

格式串 %s 期望 char* 参数，但传入 int。printf 会把 x 的值 42 当作地址，尝试读取该地址处的字符串——未定义行为，可能导致 segfault。printf 不做类型检查（C 的可变参数特性），所以编译器可能不报错。GCC/Clang 可以通过 -Wformat 检查。

</details>
