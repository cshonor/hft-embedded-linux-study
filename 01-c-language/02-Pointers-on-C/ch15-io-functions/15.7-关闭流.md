# 15.7 关闭流

## 本节讲什么

`fclose(fp)` 是 stdio 的出口——刷新缓冲、关闭底层 fd、释放 `FILE` 结构。这一节给出 `fclose` 的完整行为、忘记关闭的后果（句柄泄漏）、`goto cleanup` 模式，以及 HFT 长跑进程的句柄管理。

认知锚点：`fclose` 不是「可选的清理」，而是**必须的收尾**——未 `fclose` 的流缓冲区数据丢失，fd 泄漏。长跑进程（HFT 网关 7×24 运行）不 `fclose` 会在数小时/数天内耗尽 fd，无法新建文件或套接字。

## 要点

### fclose 的行为

```c
fclose(fp);
```

`fclose` 按顺序做：

1. **`fflush` 该流的用户态缓冲**：把未写数据 `write` 到底层 fd。
2. **`close(fd)`**：关闭底层文件描述符。
3. **释放缓冲区**：归还 `FILE` 内部缓冲区内存。
4. **从全局 FILE 链表移除**：避免 `exit` 时重复刷新。
5. **释放 `FILE` 结构**：归还结构体内存。

### 忘记 fclose 的后果

```c
void bad_func(void) {
    FILE *fp = fopen("log.txt", "a");
    fprintf(fp, "something\n");
    /* 忘记 fclose */
}
```

| 后果 | 说明 |
|------|------|
| **缓冲数据丢失** | 未 `fflush` 的数据在程序崩溃时丢失 |
| **fd 泄漏** | 每次调用泄漏一个 fd，长跑进程耗尽 fd |
| **文件锁不释放** | 某些系统对打开的文件加锁，不关闭不释放 |
| **磁盘空间不释放** | 已 `unlink` 但未 `fclose` 的文件 inode 不释放 |

### fd 泄漏的阈值

```c
/* 查看进程 fd 限制 */
ulimit -n    /* 通常 1024，可调到百万 */

/* 查看进程打开的 fd */
ls -la /proc/$(pidof my_app)/fd/
```

默认 fd 上限 1024。长跑进程每天泄漏 100 个 fd，10 天后耗尽，无法 `fopen` 新文件或 `socket` 新连接。**HFT 进程通常把 fd 上限调到百万级**（`ulimit -n 1000000`），但泄漏仍要修复。

### goto cleanup 模式

```c
int process_file(const char *path) {
    FILE *fp1 = NULL, *fp2 = NULL, *fp3 = NULL;
    int ret = -1;

    fp1 = fopen(path, "rb");
    if (!fp1) goto cleanup;

    fp2 = fopen("temp.tmp", "wb");
    if (!fp2) goto cleanup;

    fp3 = fopen("index.idx", "wb");
    if (!fp3) goto cleanup;

    /* ... 处理逻辑 ... */
    if (error) goto cleanup;

    ret = 0;   /* 成功 */

cleanup:
    /* 逆序关闭，NULL 安全 */
    if (fp3) fclose(fp3);
    if (fp2) fclose(fp2);
    if (fp1) fclose(fp1);
    return ret;
}
```

**`goto cleanup` 是 C 工程处理多资源释放的标准模式**：

1. 所有资源指针初始化为 `NULL`。
2. 分配失败或处理错误时 `goto cleanup`。
3. `cleanup` 标签后逆序释放，`if (ptr) fclose(ptr)` 保证 NULL 安全。

详见 ch11.6 动态内存的 goto cleanup。

### fclose 后置 NULL

```c
fclose(fp);
fp = NULL;   /* 防止后续误用 */

/* 后续误用会被立即捕获 */
if (fp) {
    fprintf(fp, "...");   /* 不会执行 */
}
```

`fclose` 后置 NULL 是防御性编程——防止后续代码误用已关闭的 `FILE *`（UAF）。

### fclose 与 exit 的关系

```c
/* exit 会自动 fclose 所有打开的流 */
atexit(cleanup_func);
exit(0);   /* 触发 atexit 回调 + fflush 所有流 + fclose 所有流 */
```

`exit` 会遍历全局 FILE 链表，`fflush` + `fclose` 所有打开的流。**正常退出不依赖手动 fclose**，但**异常退出（abort/segfault）不触发**。关键数据仍需手动 `fflush`。

## HFT 关联

### 长跑进程的 fd 管理

```c
/* HFT 网关 7×24 运行，fd 泄漏是致命问题 */
/* 规范：每个 fopen 路径必须对应 fclose */

/* 用 goto cleanup 管理多文件 */
int load_market_data(const char *dir) {
    FILE *meta_fp = NULL, *data_fp = NULL, *idx_fp = NULL;
    int ret = -1;

    char path[512];
    snprintf(path, sizeof(path), "%s/meta.json", dir);
    meta_fp = fopen(path, "rb");
    if (!meta_fp) goto cleanup;

    snprintf(path, sizeof(path), "%s/data.dat", dir);
    data_fp = fopen(path, "rb");
    if (!data_fp) goto cleanup;

    /* ... 处理 ... */
    ret = 0;

cleanup:
    if (idx_fp) fclose(idx_fp);
    if (data_fp) fclose(data_fp);
    if (meta_fp) fclose(meta_fp);
    return ret;
}
```

HFT 工程强制 `goto cleanup` 模式，CI 检查每个 `fopen` 是否有对应 `fclose`。

### 日志文件的定时 fclose

```c
/* 日志按小时滚动，每小时 fclose 旧文件、fopen 新文件 */
void log_rotate(void) {
    if (log_fp) {
        fflush(log_fp);
        fclose(log_fp);
        log_fp = NULL;
    }
    char path[256];
    snprintf(path, sizeof(path), "/var/log/hft_%ld.log", time(NULL));
    log_fp = fopen(path, "a");
}
```

日志滚动时显式 `fclose` 旧文件，释放 fd。**长跑进程的定时 `fclose` 是 fd 管理的关键**。

### 崩溃前的 fflush

```c
/* 致命错误处理：先 fflush 再 abort */
void fatal_handler(int sig) {
    if (log_fp) {
        fflush(log_fp);   /* 确保日志落盘 */
        fclose(log_fp);
    }
    signal(sig, SIG_DFL);
    raise(sig);   /* 重新发送信号，生成 core dump */
}
```

信号处理函数里 `fflush` + `fclose` 关键日志，确保崩溃前的最后状态落盘。**`abort` 不触发 `fflush`**，需手动处理。

### 句柄泄漏检测

```c
/* 运维脚本：监控进程 fd 数 */
/* watch -n 1 'ls /proc/$(pidof my_app)/fd | wc -l' */

/* valgrind 检测 fd 泄漏 */
valgrind --track-fds=yes ./my_app

/* ASan 也可检测部分 fd 泄漏 */
```

HFT 生产环境监控进程 fd 数，异常增长告警。`valgrind --track-fds` 在测试环境检测泄漏。

## UB 边界

| 情形 | 后果 | 防护 |
|------|------|------|
| 忘记 `fclose` | 缓冲丢失、fd 泄漏 | `goto cleanup` 模式 |
| 重复 `fclose` | UB，可能崩溃 | `fclose` 后置 NULL |
| `fclose` 后用 `FILE *` | UAF | 置 NULL + 判空 |
| `fclose(NULL)` | UB（部分实现允许） | `if (fp) fclose(fp)` |
| 多线程并发 `fclose` 同一流 | 数据竞争 | 加锁或单线程关闭 |

### 重复 fclose 的危险

```c
fclose(fp);
/* ... 其他代码 ... */
fclose(fp);   /* UB：fp 已释放，可能崩溃或损坏堆 */
```

`fclose` 后 `fp` 指向已释放内存，再次 `fclose` 是 UAF。**置 NULL + 判空**是标准防护。
