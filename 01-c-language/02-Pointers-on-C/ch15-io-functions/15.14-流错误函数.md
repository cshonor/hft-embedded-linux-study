# 15.14 流错误函数

## 本节讲什么

`feof` / `ferror` / `clearerr`：在 `fread`/`fgetc` 短读或 `EOF` 之后，区分"正常到尾"与"真出错"。这层判别在长跑 HFT 进程里关系到磁盘满、坏道、网络断的自动降级——把错误当 EOF 会静默丢数据，把 EOF 当错误会卡死读循环。

## 要点

### 三个函数的语义

```c
int feof(FILE *stream);
int ferror(FILE *stream);
void clearerr(FILE *stream);
```

| 函数 | 返回非 0 的条件 | 持续性 |
|------|----------------|--------|
| `feof(fp)` | 读操作遇到 EOF | 持续，直到 `clearerr`/`rewind`/`fseek` |
| `ferror(fp)` | 读/写操作发生错误 | 持续，直到 `clearerr`/`rewind`（部分实现） |
| `clearerr(fp)` | — | 清除 EOF 和错误两个标志 |

注意：**EOF 和错误是两个独立标志**，可以同时为真（极少见）也可能都不为真。

### feof 的反直觉：滞后性

`feof` 只有在某次读操作**尝试读过 EOF** 之后才返回真。在尚未尝试读之前，即使文件指针已经在末尾，`feof` 也返回假：

```c
fseek(fp, 0, SEEK_END);
feof(fp);   /* 返回 0！还没尝试读过 */

int c = fgetc(fp);   /* 尝试读，失败返回 EOF */
feof(fp);   /* 现在返回 1 */
```

这是为什么"用 `feof` 作 while 前置条件"是经典错误：

```c
/* 错误：会多读一次或漏判错误 */
while (!feof(fp)) {
    fread(&pkt, sizeof pkt, 1, fp);
    process_quote(&pkt);   /* 最后一次读失败时 pkt 是旧数据或未初始化 */
}
```

正确模式是**用读操作的返回值作循环条件**：

```c
while (fread(&pkt, sizeof pkt, 1, fp) == 1) {
    process_quote(&pkt);
}
/* 循环退出后再用 feof/ferror 区分原因 */
if (ferror(fp)) perror("fread");
/* feof 为真表示正常读完 */
```

### ferror 的常见触发

- 磁盘满（fwrite 时）
- 坏道/IO 错误
- 网络流断开（pipe 对端关闭）
- 文件被外部 truncate（fread 时位置失效）

`ferror` 不会自动清除——一次错误后，后续所有 I/O 都会立即失败返回 EOF/0，直到 `clearerr`。这避免在错误状态下继续操作，但也意味着**重试必须显式 `clearerr`**。

### clearerr 的两个用途

1. **重试**：网络瞬时断开后 `clearerr` + `fseek` 重新定位继续读
2. **复用 EOF 流**：从 stdin 读到 EOF 后，如果想再读（比如交互式 shell 等下一个命令），`clearerr(stdin)` 重置

```c
/* 交互式 REPL */
while (fgets(buf, sizeof buf, stdin)) {
    handle(buf);
}
/* EOF（Ctrl-D） */
clearerr(stdin);   /* 重置，可以继续读 */
```

### perror 配合 ferror

```c
size_t n = fread(buf, 1, sizeof buf, fp);
if (n < sizeof buf && ferror(fp)) {
    perror("fread quote file");   /* 输出 "fread quote file: <strerror(errno)>" */
    clearerr(fp);
    /* 降级处理或重试 */
}
```

`perror` 读 `errno`，而 `errno` 只在错误发生那一刻有效——所以必须在 `ferror` 判定后**立即**调 `perror`，中间不要做其他可能改 errno 的系统调用。

### 区分短读的决策树

```
fread/fgetc 返回短读或 EOF
        │
        ├─ ferror(fp) 为真?
        │     ├─ 是 → 真出错, perror + clearerr + 重试或降级
        │     └─ 否 → feof(fp) 为真?
        │             ├─ 是 → 正常到尾, 继续后续逻辑
        │             └─ 否 → 理论不该发生, 防御性 abort
```

### 文本 vs 二进制流的 EOF

二进制流读到文件物理末尾就 EOF。文本流在某些平台有特殊 EOF 标记（如 Windows 的 Ctrl-Z = 0x1A），读到这个字节就被当作 EOF——这是历史遗留，现代代码用二进制模式打开可避免。HFT 二进制 `.dat` 务必 `"rb"`/`"wb"` 打开。

## HFT 关联

- **磁盘满降级**：`ferror` 触发后切换到备用盘或内存缓冲，clearerr 后重试 `fwrite`
- **网络断线重连**：行情源 TCP 断开后 `clearerr` + 重连 + `fseek` 对齐 seq 继续
- **日志磁盘坏道**：日志 `ferror` 触发告警 + 切换到 stderr 兜底，避免日志阻塞数据面
- **回放引擎校验**：`fread` 短读后 `ferror` 为真说明历史文件损坏，需校验 checksum 重定位
- **避免把 EOF 当错误**：正常读完文件时 `feof` 为真，不应触发告警，只记录"replay done"
- **多线程流的错误标志**：stdio 流的错误标志是流级别的，多线程共享同一 `FILE*` 时 `ferror` 状态可能被其他线程的 I/O 改变——HFT 通常每流单线程独占
