# 15.13 改变缓冲方式

## 本节讲什么

`setvbuf` / `setbuf` / `setbuffer`（BSD）/ `setlinebuf`（BSD）：在流打开后、第一次 I/O 前，调整 stdio 的缓冲模式与缓冲区大小。这层调优在 HFT 日志抖动排查里是常用工具——同一份 `fprintf` 日志代码，缓冲模式不同可能差出 10x 的延迟方差。

## 要点

### setvbuf 三参数

```c
int setvbuf(FILE *stream, char *buf, int mode, size_t size);
```

| mode | 行为 | 典型场景 |
|------|------|----------|
| `_IONBF` | 无缓冲，每次 I/O 立即 syscall | stderr、调试流、崩溃日志 |
| `_IOLBF` | 行缓冲，遇 `\n` 或缓冲满才 flush | 终端 stdout、交互式日志 |
| `_IOFBF` | 全缓冲，缓冲满才 flush | 文件日志、批量写盘 |

- `buf == NULL`：stdio 自己 malloc 缓冲区
- `buf != NULL`：用调用者提供的缓冲，**该缓冲在流关闭前必须有效**（典型用法：static 数组或长生命周期堆缓冲）
- 返回值：成功 0，失败非 0（通常因为流已经有 I/O 发生）

### 调用时机铁律

`setvbuf` **必须在流打开后、第一次 I/O 前**调用。一旦发生任何 `fread`/`fwrite`/`fgetc`，再调 `setvbuf` 是未定义行为。常见错误：

```c
fp = fopen("log.txt", "w");
fprintf(fp, "started\n");      /* 已经 I/O 了 */
setvbuf(fp, NULL, _IONBF, 0);  /* UB！可能静默失败也可能崩溃 */
```

正确顺序：

```c
fp = fopen("log.txt", "w");
if (!fp) { perror("fopen"); exit(1); }
setvbuf(fp, NULL, _IONBF, 0);  /* 先设缓冲 */
fprintf(fp, "started\n");      /* 再 I/O */
```

### setbuf / setbuffer / setlinebuf 速记

```c
setbuf(fp, NULL);          /* 等价 setvbuf(fp, NULL, _IONBF, 0) */
setbuf(fp, big_buf);       /* 等价 setvbuf(fp, big_buf, _IOFBF, BUFSIZ) */
setbuffer(fp, big_buf, n); /* BSD，全缓冲 + 自定义大小 */
setlinebuf(fp);            /* BSD，等价 setvbuf(fp, NULL, _IOLBF, 0) */
```

`BUFSIZ` 通常 8192，可跨平台查询 `<stdio.h>`。

### 默认缓冲模式

| 流 | 终端 | 重定向到文件/管道 |
|----|------|-------------------|
| stdout | 行缓冲 `_IOLBF` | 全缓冲 `_IOFBF` |
| stderr | 无缓冲 `_IONBF` | 无缓冲 `_IONBF` |
| 普通 fopen | 全缓冲 `_IOFBF` | 全缓冲 `_IOFBF` |

stderr 永远无缓冲——这是设计，保证错误信息立即输出。stdout 在重定向时切到全缓冲，这导致 `printf` 调试重定向到文件时数据不立即出现，需要 `fflush(stdout)` 或 `setvbuf(stdout, NULL, _IONBF, 0)`。

### 缓冲大小对性能的影响

```c
static char big_buf[1 << 16];   /* 64KB */
setvbuf(log_fp, big_buf, _IOFBF, sizeof big_buf);
```

- 缓冲越大，syscall 越少，吞吐越高
- 但缓冲越大，崩溃丢失的数据越多（未 flush 的部分）
- 缓冲越大，单次 flush 延迟越高（写 64KB 比写 8KB 慢）
- HFT 日志常用 4KB-64KB，平衡 syscall 频次与延迟方差

### HFT 日志抖动调优实例

症状：高频 `fprintf` 到 stdout，延迟偶发尖峰到 100us。

排查：
1. stdout 重定向到文件 → 全缓冲，平时攒 8KB 才写，但偶尔 flush 时阻塞
2. `setvbuf(stdout, NULL, _IONBF, 0)` → 每次 fprintf 都 syscall，平均延迟升但方差降
3. 改 `fputs` 到 stderr（无缓冲） → 同样每次 syscall
4. 用大缓冲 + 后台线程周期 flush → 平均最低，方差最小（异步日志模式）

最终方案：自定义日志队列，前台线程 `memcpy` 到 ring buffer（亚微秒），后台线程批量 `write` + `fsync`。这是 DPDK `rte_log` + 自建日志库的通用思路。

### 自定义缓冲的生命周期陷阱

```c
void bad_init() {
    char buf[4096];
    setvbuf(fp, buf, _IOFBF, sizeof buf);
}   /* buf 离开作用域，stdio 仍引用它 → UB */
```

`setvbuf` 不复制 buf，只存指针。buf 必须是 `static`、全局、或堆分配且在 `fclose` 前 `free`。

### 缓冲与 fork

`fork` 后子进程继承 stdio 缓冲区的副本。如果缓冲区有未 flush 的数据，子进程 `exit` 时会再 flush 一次，导致输出重复。`fork` 前显式 `fflush(NULL)` 冲洗所有输出流是标准做法。

## HFT 关联

- **控制面日志调优**：`setvbuf` 调大缓冲 + 后台 flush，前台 `fprintf` 接近 `memcpy` 速度
- **崩溃日志零丢失**：关键流设 `_IONBF`，每条 `fprintf` 立即 syscall，崩溃也不丢
- **DPDK rte_openlog_stream**：DPDK 允许把日志流换成自定义 FILE*，可对其 `setvbuf` 调优
- **数据面完全绕过 stdio**：数据面用 PMD + ring + 无锁队列，`setvbuf` 仅影响控制面
- **多线程日志的锁开销**：glibc `stdio` 函数内部有锁，高频多线程 `fprintf` 会争锁抖动；改用每线程缓冲 + 合并 flush，或 lockfree ring + 单写线程
- **mmap 日志**：极致场景用 `mmap` 映射日志文件，`memcpy` 写 + `msync` 落盘，完全绕过 stdio
