# 15.8 字符 I/O

## 本节讲什么

逐字节读写流的最薄一层：`fgetc` / `fputc` 与它们的 stdin/stdout 特化版 `getchar` / `putchar`，再加上宏实现 `getc` / `putc` 与回退接口 `ungetc`。这是 stdio 离底层 `read(2)` 最近的一层，也是 C 程序员最常踩 EOF 陷阱的地方。

## 要点

### 函数族对照

| 函数 | 原型 | 备注 |
|------|------|------|
| `fgetc(FILE*)` | `int fgetc(FILE *stream);` | 真函数，可取地址 |
| `getc(FILE*)` | `int getc(FILE *stream);` | **可能是宏**，不能取地址作回调 |
| `getchar(void)` | `int getchar(void);` | 等价 `getc(stdin)` |
| `fputc(int,FILE*)` | `int fputc(int c, FILE *stream);` | 写一字节，返回 c 或 EOF |
| `putc(int,FILE*)` | `int putc(int c, FILE *stream);` | 可能是宏 |
| `putchar(int)` | `int putchar(int c);` | 等价 `putc(c, stdout)` |
| `ungetc(int,FILE*)` | `int ungetc(int c, FILE *stream);` | 回退一字节，仅保证 1 层 |

### 返回值必须用 int，绝不能用 char

这是字符 I/O 头号陷阱。`fgetc` 读到一个字节后返回 `unsigned char` 值（0..255）扩展为 `int`，遇到结尾或错误返回 `EOF`（宏定义为 `-1`）。如果把返回值塞进 `char`，三个分支会被压缩成两个：

```c
/* 错误示范 */
char c = fgetc(fp);          /* 0xFF 会被截成 -1，与 EOF 撞车 */
if (c == EOF) break;         /* 二进制 0xFF 字节直接被当作结束 */
```

正确写法：

```c
int c;
while ((c = fgetc(fp)) != EOF) {
    /* c 是 0..255，可安全当 unsigned char 用 */
    process_byte((unsigned char)c);
}
if (ferror(fp)) perror("read");
```

| 存储 | 0xFF 字节表现 | 与 EOF(-1) 比较 |
|------|---------------|-----------------|
| `int` | 255 | 不相等 ✓ |
| `signed char` | -1 | 相等 ✗ 误判结束 |
| `unsigned char` | 255 | 永不相等 ✗ 永不结束 |

### EOF 的双重含义

`EOF == -1` 同时表示两种情况：到达文件尾，或发生读错误。要区分必须配合 `feof()` / `ferror()`（见 15.14）。循环结束后的判别模板：

```c
while ((c = fgetc(fp)) != EOF) { ... }
if (ferror(fp))  { /* 真出错了 */ perror("fgetc"); }
else if (feof(fp)) { /* 正常读完 */ }
```

### getchar / putchar 是 stdin/stdout 特化

`getchar()` 等价于 `getc(stdin)`，`putchar(c)` 等价于 `putc(c, stdout)`。当 stdin 是行缓冲（终端）时，`getchar()` 会阻塞到用户按回车，缓冲区一次灌入整行，再逐字节返回——这点对交互程序和管道理解很关键。

### getc/putc 可能是宏

POSIX 允许 `getc` / `putc` 实现为宏（带参数、可能多次求值 stream 参数）。后果：

- 不能 `&getc` 取地址传给 `qsort` 之类的回调
- `getc(f++)` 这类带副作用的 stream 参数可能被求值多次
- 想要真函数行为，用 `fgetc` / `fputc`；性能差异在 stdio 已缓冲的情况下极小

### ungetc：回退一字节

```c
int c = fgetc(fp);
if (isdigit(c)) { ungetc(c, fp); parse_number(fp); }
```

- 只保证回退 1 字节有效（实现通常允许更多但不保证）
- 回退不改变底层文件偏移（影响 stdio 内部缓冲）
- `ungetc(EOF, fp)` 行为由实现定义，应避免
- 成功后 `feof` 标志被清除

### 性能模型：stdio 已缓冲

`fgetc` 并不是每次都 syscall。当流是 `_IOFBF` 全缓冲时，底层 `read(2)` 一次性填满整块缓冲区（典型 4KB-64KB），`fgetc` 只是从内存缓冲区取一字节。所以"逐字节 = 慢"在 stdio 下并不成立，瓶颈在 syscall 次数而不是字节次数。真要极致时绕过 stdio 直接 `read` + 自己管理缓冲（见 15.4.1）。

## HFT 关联

- **协议头逐字节解析**：定长头未知长度时常用 `fgetc` 读 magic + 版本号 + 长度字段再切到 `fread` 读 body；`ungetc` 在向前看一字节判断分支时很方便
- **pcap 文件头解析**：pcap 全局头是 24 字节定长，魔数 `0xa1b2c3d4` 用 `fread` 一次读更优，但若需要兼容大小端探测则逐字节读 magic 更直观
- **回放引擎**：从历史 `.dat` 重建 tick 流时，逐字节定位分隔符后切 `fread` 读整条 quote，是典型的混合用法
- **避免在数据面用**：行情收发路径每秒百万包级，fgetc 的函数调用 + stdio 锁开销都不可接受，必须 PMD + 零拷贝
- **stdin 控制命令**：控制面读取 operator 命令用 `getchar`/`fgets`，与数据面完全分离线程

## 代码自测

**题目 1：** 以下代码有什么问题？
```c
int c;
while (c = getchar() != EOF) {
    putchar(c);
}
```

<details>
<summary>参考答案</summary>

运算符优先级错误。!= 优先级高于 =，所以 c = (getchar() != EOF)，c 的值是 0 或 1，不是读取的字符。putchar(c) 输出的是 0 或 1 对应的控制字符。正确写法：while ((c = getchar()) != EOF)。这也是为什么 getchar 返回 int 而非 char——EOF 通常是 -1，不能用 char 表示。

</details>
