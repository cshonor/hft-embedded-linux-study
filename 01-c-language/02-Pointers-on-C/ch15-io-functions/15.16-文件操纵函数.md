# 15.16 文件操纵函数

## 本节讲什么

`remove` / `rename`：文件系统级别的删除与重命名。这俩看似简单，但 `rename` 的原子性、跨文件系统行为、与已打开 fd 的交互，是 HFT 滚动日志、配置热加载、原子切换数据文件的核心。

## 要点

### remove

```c
int remove(const char *path);
```

- 删除文件路径（等价 `unlink(2)`）
- 删除空目录（等价 `rmdir(2)`）
- 成功返回 0，失败返回非 0 并设 errno
- **不释放已打开的 fd**：Linux 允许文件被 unlink 后仍可通过 fd 读写，直到所有 fd 关闭才真正释放空间

### rename

```c
int rename(const old, const char *new);
```

语义：

- 原子地把 `old` 改名成 `new`
- `new` 已存在 → **覆盖**（POSIX，前提是同文件系统且同为文件或同为空目录）
- 跨文件系统 → 失败，errno = `EXDEV`
- 成功返回 0，失败返回非 0 并设 errno

### rename 的原子性是金矿

`rename` 在同文件系统内是原子的——要么成功要么完全没发生，观察者永远看不到中间状态。这使它成为原子更新文件的标配模式：

```c
/* 原子写文件的标准模式 */
FILE *fp = fopen("config.tmp", "w");
fwrite(new_config, 1, len, fp);
fflush(fp);
fsync(fileno(fp));   /* 确保落盘 */
fclose(fp);

rename("config.tmp", "config.dat");   /* 原子替换 */
```

这样 `config.dat` 永远是完整有效的——要么是旧版本要么是新版本，不会出现"写到一半"的损坏状态。HFT 配置热加载、订单簿快照切换、pcap 滚动都用这个模式。

### rename 跨文件系统的 EXDEV

`/tmp` 通常是 tmpfs（内存），`/data` 是磁盘文件系统。`rename("/tmp/x", "/data/x")` 会失败 `EXDEV`。替代方案：

1. `cp` 跨 FS 复制 + `rename` 同 FS 替换
2. `link` + `unlink`（但 `link` 也要求同 FS）
3. 数据拷贝无法原子跨 FS，必须接受"短暂窗口期"

HFT 设计上把临时文件和最终文件放同一 FS（如都在 `/data/hft`），避免 EXDEV。

### rename 与已打开 fd

```c
FILE *fp = fopen("log.txt", "w");
rename("log.txt", "log.1");   /* 旧路径没了, 但 fp 仍指向原文件 */
fprintf(fp, "...");           /* 写到的是 log.1, 不是新的 log.txt */
```

`rename` 不影响已打开的 fd——fd 指向 inode 而不是路径，改名不改变 inode。这意味着滚动日志必须 `fclose` 旧 fd 再 `fopen` 新路径，否则写到的还是旧文件（已改名）。

### 滚动日志标准模式

```c
void rotate_log(FILE **fp, const char *path, int max_keep) {
    fclose(*fp);
    *fp = NULL;
    
    /* 滚动: log.4 -> log.5 (删), log.3 -> log.4, ..., log -> log.1 */
    char old[256], new[256];
    snprintf(old, sizeof old, "%s.%d", path, max_keep - 1);
    remove(old);   /* 删最老的 */
    for (int i = max_keep - 2; i >= 1; i--) {
        snprintf(old, sizeof old, "%s.%d", path, i);
        snprintf(new, sizeof new, "%s.%d", path, i + 1);
        rename(old, new);
    }
    snprintf(new, sizeof new, "%s.1", path);
    rename(path, new);   /* 当前 -> .1 */
    
    *fp = fopen(path, "w");   /* 新建当前 */
    if (!*fp) { perror("fopen"); /* 降级 */ }
}
```

### tmpfile 与 remove

`tmpfile` 内部已经 `unlink`，不需要 `remove`。`mkstemp` 创建的文件不自动删除，需要显式 `remove` 或 `unlink`。

### remove 与目录

`remove` 删空目录，非空目录返回失败 errno `ENOTEMPTY`。递归删目录需要自己实现或用 `nftw` + `unlink` + `rmdir`。HFT 场景下递归删目录通常交给运维脚本（`rm -rf`），不在数据面做。

### stdio vs POSIX vs syscall 分层

```
应用层
  │
  ├─ stdio (FILE*)   fopen/fread/fwrite/fclose   ← 跨平台, 带缓冲
  │
  ├─ POSIX (fd)      open/read/write/close/lseek  ← Unix 系调用, 无缓冲
  │
  └─ syscall         openat/pread/pwrite/sendfile/ splice
                       ← Linux 专用, 零拷贝/异步
```

HFT 数据面常直接用最底层：

| 层 | 接口 | HFT 用途 |
|----|------|----------|
| stdio | `fprintf`/`fread` | 控制面日志、配置 |
| POSIX | `open`/`write`/`fsync` | 数据面日志（绕过 stdio 缓冲） |
| syscall | `writev`/`sendfile`/`splice` | 零拷贝转发 |
| mmap | `mmap`/`msync` | 行情文件内存映射 |

### remove/rename 与权限

- `remove` 需要对父目录有写权限，不需要对文件本身有权限
- `rename` 需要对 `old` 和 `new` 的父目录都有写权限
- HFT 运维：进程以 `hft` 用户跑，日志目录属主设 `hft`，配置目录只读避免误删

### rename 的目录覆盖语义

POSIX 规定 `rename(dir, newdir)` 当 `newdir` 存在且为空目录时覆盖，非空时失败。这与文件的"无条件覆盖"不同，容易踩坑。Linux 上 `rename` 目录还有缓存一致性陷阱（其他进程可能仍看到旧路径），生产代码倾向 `renameat2` + `RENAME_EXCHANGE`。

## HFT 关联

- **滚动日志**：`rename` + `fopen` 是标准日志轮转模式，原子切换保证日志不丢
- **配置热加载**：写 `config.tmp` + `fsync` + `rename` 原子替换 `config.dat`，进程监测 inode 变化重新加载
- **订单簿快照**：周期 dump 到 `snapshot.tmp`，`rename` 为 `snapshot.dat`，重启时读 `snapshot.dat` 必然完整
- **pcap 滚动**：抓包到 `trace.pcap`，满大小后 `rename` 为 `trace.<ts>.pcap`，新建 `trace.pcap` 继续
- **避免跨 FS rename**：日志/配置/快照放同一 FS，避开 EXDEV
- **rename 后 fd 行为**：运维写脚本时常踩"改名后进程仍写到旧文件"的坑，需 `lsof` + 信号触发重开
- **DPDK 完全绕过**：数据面 0 文件操作，`remove`/`rename` 仅用于控制面运维
