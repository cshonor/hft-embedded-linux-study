# 15.9 未格式化的行 I/O

## 本节讲什么

按"行"读写文本流：`fgets` / `fputs`。这是配置文件、日志解析、协议文本行的标准接口——既不像 `fgetc` 那样逐字节低效，也不像 `fscanf` 那样有格式串风险。本节重点讲 `fgets` 的安全语义、`fputs` 不加换行的反直觉行为，以及 `gets` 为什么被 C11 彻底移除。

## 要点

### fgets：唯一安全的整行读取

```c
char *fgets(char *s, int size, FILE *stream);
```

语义：

- 最多读 `size - 1` 字节，遇 `\n` 停下，**`\n` 也算进缓冲区**
- 末尾自动追加 `\0`
- 成功返回 `s`，遇 EOF 无数据返回 `NULL`，出错返回 `NULL`
- 缓冲区不够大时，行被截断，但**保证 `\0` 终止**

```c
char buf[256];
if (fgets(buf, sizeof buf, fp) == NULL) {
    if (ferror(fp)) perror("fgets");
    /* EOF 正常结束 */
} else {
    /* buf 含一行（可能无 \n，说明被截断或最后一行无换行） */
    size_t len = strlen(buf);
    int truncated = (len > 0 && buf[len-1] != '\n');
}
```

### 判断截断 vs 正常一行

`fgets` 不告诉你"这行是否完整"。要判断必须看末尾：

```c
size_t len = strlen(buf);
if (len == 0) { /* 异常，不该发生 */ }
else if (buf[len-1] == '\n') {
    buf[len-1] = '\0';   /* 去掉换行，方便后续处理 */
    /* 完整一行 */
} else {
    /* 行被截断，或文件最后一行没有 \n */
    /* 需要继续 fgets 读完剩余部分，或按需丢弃 */
}
```

### fputs：写字符串，不加换行

```c
int fputs(const char *s, FILE *stream);
```

- 不在末尾加 `\n`，与 `puts`（加 `\n`）不同
- 不写结尾 `\0`，只写字符串内容
- 成功返回非负数，失败返回 `EOF`
- 写 `\0` 中间的字符串？做不到——`fputs` 在第一个 `\0` 就停

```c
fputs("[TRACE] new quote\n", fp);   /* 手动带 \n */
```

### puts 的陷阱

`puts(s)` 等价 `fputs(s, stdout) + putchar('\n')`。多了一个 `\n`，写日志时容易重复换行。生产代码统一用 `fputs` 显式控制。

### gets 为什么被移除

```c
char *gets(char *s);   /* C99 弃用，C11 移除 */
```

`gets` 不接受长度参数，无法防止缓冲区溢出——经典缓冲区溢出漏洞源（Code Red 蠕虫就是 gets 类问题）。C11 标准正式从库里删除。代码里看到 `gets` 必须立即换成 `fgets`，注意 `fgets` 会保留 `\n` 而 `gets` 不保留，迁移时要手动去掉。

### 行缓冲与终端

当 stream 是终端时，stdio 通常是行缓冲（`_IOLBF`），用户按回车后整行才进入 stdio 缓冲区，`fgets` 才能返回。重定向到管道或文件时，stdio 切到全缓冲，`fgets` 会在缓冲区空时阻塞等 `read(2)` 填充。

## HFT 关联

- **配置文件解析**：网关 `gateway.conf` 一行一个键值对，`fgets` + `strtok`/`strtol` 是标准模式；用 `fscanf` 反而难处理注释和空行
- **文本日志读取**：崩溃后回放 `gateway.log`，`fgets` 逐行解析比 `fread` 整块再切行更省内存
- **FIX 协议文本行**：FIX 是 `\001` 分隔的文本协议，单条消息可能很长，`fgets` 按 `\n` 切不一定合适，但许多实现仍用 `fgets` 读定长块再自己切字段
- **二进制 buf 禁止当 %s 打印**：行情 packet 含 `\0` 字节，`fprintf("%s", pkt)` 会在第一个 `\0` 截断，必须用 `fwrite(pkt, 1, len, fp)`
- **滚动日志写**：高频写日志用 `fputs` 比 `fprintf` 快（无格式串解析），但格式化需求大时仍用 `fprintf`/`snprintf`

## 代码自测

**题目 1：** 以下代码有什么安全风险？
```c
char buf[10];
gets(buf);
```

<details>
<summary>参考答案</summary>

缓冲区溢出。gets 不检查缓冲区大小，输入超过 9 个字符就会溢出 buf。gets 已在 C11 中被完全移除。正确做法：用 fgets(buf, sizeof(buf), stdin)——它会读取最多 sizeof(buf)-1 个字符并自动添加终止符。

</details>
