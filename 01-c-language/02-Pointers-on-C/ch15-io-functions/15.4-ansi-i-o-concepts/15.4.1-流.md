# 15.4.1 流

## 本节讲什么

**流（stream）** 是 stdio 的核心抽象——`FILE *` 类型封装了文件描述符、用户态缓冲区、读写位置、错误/EOF 标志。这一节给出 `FILE` 结构的内部组成、三个预定义标准流（`stdin`/`stdout`/`stderr`）的缓冲特性，以及 HFT 工程里绕过 stdio 的原因。

认知锚点：`FILE *` 不是「文件指针」，而是**流对象指针**。流可以绑定到磁盘文件、管道、设备、套接字——任何能读写的东西。理解流的内部结构，才能理解缓冲行为、错误判断、性能调优。

## 要点

### FILE 结构（典型实现）

```c
/* glibc 的 FILE 结构（简化） */
struct _IO_FILE {
    int     _flags;            /* 标志位：_IO_READ|_IO_WRITE|_IO_UNBUFFERED 等 */
    char   *_IO_read_ptr;      /* 当前读位置（缓冲区内） */
    char   *_IO_read_end;      /* 已读数据末尾 */
    char   *_IO_read_base;     /* 读缓冲区起始 */
    char   *_IO_write_base;    /* 写缓冲区起始 */
    char   *_IO_write_ptr;     /* 当前写位置 */
    char   *_IO_write_end;     /* 写缓冲区末尾 */
    char   *_IO_buf_base;      /* 缓冲区起始 */
    char   *_IO_buf_end;       /* 缓冲区末尾 */
    int     _fileno;           /* 底层文件描述符 fd */
    int     _chain;            /* 链表下一个 FILE */
    int     _mode;             /* 文本/二进制 */
    /* ... 更多字段 ... */
};
```

每个 `FILE` 封装：

| 组件 | 作用 |
|------|------|
| **文件描述符 `_fileno`** | 底层 POSIX fd，最终 I/O 通过它 |
| **用户态缓冲区** | 减少 syscall，提高吞吐 |
| **读位置指针** | 当前读到哪里 |
| **写位置指针** | 当前写到哪里 |
| **错误/EOF 标志** | `ferror`/`feof` 查询 |
| **缓冲模式** | 全缓冲/行缓冲/无缓冲 |

### 三个预定义标准流

```c
#include <stdio.h>

extern FILE *stdin;    /* 标准输入，fd=0 */
extern FILE *stdout;   /* 标准输出，fd=1 */
extern FILE *stderr;   /* 标准错误，fd=2 */
```

| 流 | fd | 默认缓冲 | 典型用途 |
|----|----|----------|----------|
| `stdin` | 0 | 行缓冲（终端）/ 全缓冲（文件） | 读取用户输入 |
| `stdout` | 1 | 行缓冲（终端）/ 全缓冲（文件） | 正常输出 |
| `stderr` | 2 | **无缓冲** | 错误日志、调试输出 |

**stderr 无缓冲**是关键——每次 `fprintf(stderr, ...)` 立即输出，崩溃前的最后一条日志不会丢失。**致命错误日志必须用 stderr**。

### 缓冲模式

```c
/* stdio 三种缓冲模式 */
_IOFBF   /* 全缓冲：缓冲区满才 flush */
_IOLBF   /* 行缓冲：遇 \n 或满才 flush */
_IONBF   /* 无缓冲：每次 fwrite 立即 syscall */
```

| 模式 | 触发 flush 的条件 | 适用场景 |
|------|-------------------|----------|
| 全缓冲 `_IOFBF` | 缓冲区满、`fflush`、`fclose` | 磁盘文件、批量数据 |
| 行缓冲 `_IOLBF` | 遇 `\n`、缓冲区满、`fflush` | 终端输出（stdout 默认） |
| 无缓冲 `_IONBF` | 每次操作立即 flush | stderr、调试输出 |

默认规则：

- **stderr**：永远无缓冲。
- **stdout/stderr 指向终端**：行缓冲。
- **stdout/stderr 指向文件/管道**：全缓冲（重定向时自动切换）。

### 缓冲的可见性陷阱

```c
printf("step 1\n");     /* 行缓冲，遇 \n flush */
printf("step 2");       /* 未 flush，可能看不到 */
fprintf(stderr, "error\n");  /* stderr 无缓冲，立即输出 */
/* 程序崩溃：step 2 可能丢失 */
```

**stdout 行缓冲**：遇 `\n` 才 flush。若输出不含 `\n`（如 `printf("step 2")`），崩溃时缓冲数据丢失。**调试输出加 `\n` 或用 stderr**。

### FILE 的生命周期

```
fopen(path, mode)
   |
   | 1. 调用 open(path, flags) 得到 fd
   | 2. 分配 FILE 结构
   | 3. 分配用户态缓冲区（默认 4KB）
   | 4. 初始化读/写指针、标志
   v
FILE *（可用）
   |
   | fread/fwrite/fprintf/... 操作缓冲
   v
fclose(fp)
   |
   | 1. fflush：把缓冲区剩余数据 write 到 fd
   | 2. close(fd)
   | 3. 释放缓冲区
   | 4. 释放 FILE 结构
   v
（fp 悬空，不可再用）
```

### fdopen：从 fd 创建流

```c
#include <stdio.h>

int fd = open("data.txt", O_RDONLY);
FILE *fp = fdopen(fd, "r");   /* 把已打开的 fd 包装成 FILE * */
/* fclose(fp) 会同时 close(fd) */
```

`fdopen` 把底层 fd 包装成 stdio 流，用于需要 stdio 接口但 fd 来自其他途径（socket、pipe、open 等）的场景。**`fclose` 会关闭底层 fd**，不要重复 close。

## HFT 关联

### DPDK 绕过 stdio 的原因

```c
/* stdio 路径：4 次拷贝 + 2 次系统调用 */
应用 fwrite → stdio 缓冲 → write syscall → 内核页缓存 → 磁盘

/* DPDK 路径：0 次系统调用，用户态直接操作网卡 */
应用 rte_eth_rx_burst → 网卡环形队列（内存映射）→ 用户态缓冲
```

| 维度 | stdio | DPDK |
|------|-------|------|
| 系统调用 | 每次 flush 一次 | 零系统调用 |
| 缓冲层 | 用户态缓冲 | 直接操作硬件 |
| 延迟 | 微秒级 | 纳秒级 |
| 吞吐 | 受 syscall 限制 | 受硬件限制 |
| 适用 | 控制面、日志 | 数据面报文 |

DPDK 完全绕过 stdio 和内核网络栈，用用户态网卡驱动（PMD）直接操作硬件。**这是 HFT 数据面的标准做法**。

### stderr 用于致命错误

```c
#define LOG_FATAL(fmt, ...) do { \
    fprintf(stderr, "[FATAL %s:%d] " fmt "\n", \
            __FILE__, __LINE__, ##__VA_ARGS__); \
    fflush(stderr); \
} while (0)

LOG_FATAL("orderbook corrupted, seq=%lu", seq);
exit(EXIT_FAILURE);
```

stderr 无缓冲，致命错误立即输出。**即使后续 exit 触发 stdio 刷新，stderr 的内容也已先输出**，不会因缓冲丢失。

### stdout 重定向到文件时的缓冲变化

```bash
./hft_app > log.txt
# stdout 指向文件，自动切换为全缓冲
# 崩溃时缓冲区数据可能丢失

./hft_app 2>&1 | tee log.txt
# stdout 指向管道，全缓冲
# tee 实时输出，但程序崩溃仍可能丢缓冲
```

HFT 生产环境日志建议：① 直接用文件 + `fprintf` + 定期 `fflush`；② 或用专门的日志线程 + 内存环形缓冲。**不要依赖 stdout 重定向**（缓冲行为不可控）。

### 自定义缓冲调优

```c
/* 日志文件用大缓冲区减少 syscall */
static char log_buf[64 * 1024];   /* 64KB 缓冲 */
FILE *log_fp = fopen("hft.log", "a");
setvbuf(log_fp, log_buf, _IOFBF, sizeof(log_buf));
/* fprintf 积累到 64KB 才一次 write syscall */
```

`setvbuf` 自定义缓冲区大小。大缓冲减少 syscall，但崩溃丢失更多数据。详见 15.13。

## UB 边界

| 情形 | 后果 | 防护 |
|------|------|------|
| `FILE *` 未初始化使用 | 野指针，崩溃 | `fopen` 后判空 |
| `fclose` 后用 `FILE *` | UAF | `fclose` 后置 NULL |
| 多线程并发用同一 `FILE *` | 数据竞争 | 加锁或 `flockfile` |
| 直接操作 `FILE` 内部字段 | 实现相关，UB | 只通过公开 API 操作 |
| 缓冲区指针越界 | 内存损坏 | 用 `fread`/`fwrite`，不手动操作缓冲 |

### stdio 的线程安全

```c
/* glibc 的 FILE 默认加锁 */
fputs("hello\n", fp);   /* 内部自动加锁解锁 */

/* 手动控制锁（减少重复加锁开销） */
flockfile(fp);
fputs("hello ", fp);
fputs("world\n", fp);
funlockfile(fp);

/* 不加锁版本（需外部保护） */
fputs_unlocked("hello\n", fp);   /* 快但不安全 */
```

stdio 默认线程安全（内部锁），但锁开销在热路径显著。HFT 高频日志可用 `_unlocked` 版本 + 外部锁，或每线程独立缓冲。

### FILE 链表

```c
/* glibc 维护所有打开的 FILE 链表 */
/* exit() 时遍历链表 fflush 所有流 */
/* _IO_list_all 是链表头 */
```

`exit` 通过遍历 FILE 链表刷新所有打开的流。这也是为什么 `fclose` 会从链表移除——避免 exit 重复刷新已关闭的流。
