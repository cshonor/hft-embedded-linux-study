# 15.4.2 文件

## 本节讲什么

**文件（file）** 在 stdio 语境下是 `fopen` 打开的路径对象——可以是磁盘文件、管道、设备、套接字。这一节给出文件与流的绑定关系、文本 vs 二进制的平台差异、`fopen` 多次打开同一路径的行为，以及 HFT 工程里行情数据文件、pcap 文件的实际形态。

认知锚点：「文件」是操作系统层面的概念，「流」是 stdio 层的抽象。一个文件可被多个流打开（各自独立），一个流可通过 `freopen` 切换文件。理解这种分离，才能理解 `fopen` 的语义和 stdio 的灵活性。

## 要点

### 文件与流的绑定

```c
FILE *fp = fopen("quote.dat", "rb");
/*  "quote.dat"  →  文件（操作系统对象）
    fp           →  流（stdio 抽象）
    fopen        →  把文件绑定到流 */
```

`fopen` 做两件事：

1. **调用底层 `open(path, flags)`** 得到文件描述符 fd。
2. **分配 `FILE` 结构**，封装 fd + 缓冲 + 状态，返回 `FILE *`。

文件与流是多对多关系：

```c
/* 一个文件可被多个流打开 */
FILE *fp1 = fopen("data.txt", "r");
FILE *fp2 = fopen("data.txt", "r");
/* fp1、fp2 各自独立，缓冲和读写位置不共享 */

/* 一个流可切换文件 */
freopen("new.txt", "r", fp1);
/* fp1 现在指向 new.txt，原 data.txt 的 fd 关闭 */
```

### 文件的类型

stdio 的 `fopen` 可以打开多种「文件」：

| 文件类型 | 路径示例 | 说明 |
|----------|----------|------|
| 磁盘文件 | `/data/quote.dat` | 普通文件 |
| 设备文件 | `/dev/null`、`/dev/urandom` | 特殊设备 |
| 命名管道 | `/tmp/mypipe` | FIFO，进程间通信 |
| 套接字 | （需 `fdopen`） | 网络通信 |
| 符号链接 | `symlink -> target` | 跟随链接到目标 |
| /proc 文件 | `/proc/cpuinfo` | 内核虚拟文件系统 |

```c
FILE *null_fp = fopen("/dev/null", "w");    /* 丢弃输出 */
FILE *rand_fp = fopen("/dev/urandom", "rb"); /* 随机数 */
FILE *cpu_fp = fopen("/proc/cpuinfo", "r");  /* CPU 信息 */
```

所有这些都能用 stdio 接口操作——这是「文件」抽象的威力。

### 文本文件 vs 二进制文件

| 维度 | 文本文件 | 二进制文件 |
|------|----------|------------|
| 内容 | 可打印字符 + 换行 | 任意字节 |
| 换行 | 平台相关（`\n` / `\r\n`） | 无换行概念 |
| 打开模式 | `r`/`w`/`a` | `rb`/`wb`/`ab` |
| stdio 行为 | 平台换行转换 | 原样读写 |
| 适合 | 配置、日志、源码 | 行情数据、pcap、结构体 |

#### 平台换行差异

```
Linux/macOS:   \n    (LF)
Windows:       \r\n  (CRLF)
旧 Mac:         \r    (CR)
```

```c
/* 文本模式打开，Windows 上 fread 会把 \r\n 转成 \n */
FILE *t = fopen("data.txt", "r");    /* 文本模式 */

/* 二进制模式打开，不转换 */
FILE *b = fopen("data.dat", "rb");   /* 二进制模式 */
```

**Linux 下 `r` 和 `rb` 行为相同**（换行就是 `\n`，无需转换）。**Windows 下 `r` 会把 `\r\n` 转成 `\n`**，破坏二进制数据。

### 跨平台统一用 `b`

```c
/* 推荐：所有文件都用二进制模式打开 */
FILE *fp = fopen("data.dat", "rb");   /* 读二进制 */
FILE *fp = fopen("log.txt", "wb");    /* 写文本也用 wb */
FILE *fp = fopen("config.cfg", "rb"); /* 读配置也用 rb */
```

**跨平台代码统一加 `b`**，避免 Windows 换行转换破坏数据。Linux 下 `b` 无影响，Windows 下保证二进制一致。HFT 工程强制 `b` 模式。

### 文件大小与 ftell 技巧

```c
/* 获取文件大小（二进制模式） */
FILE *fp = fopen("quote.dat", "rb");
fseek(fp, 0, SEEK_END);
long size = ftell(fp);
rewind(fp);
/* size 是文件字节数 */
```

**此技巧只在二进制模式可靠**——文本模式下 `ftell` 返回的值可能因换行转换而不准确。C 标准未保证 `ftell` 对二进制流返回字节数，但 POSIX 保证。

### 文件描述符与 FILE 的对应

```c
FILE *fp = fopen("data.txt", "r");
int fd = fileno(fp);   /* 获取底层 fd */

/* 反向：fd → FILE * */
int fd = open("data.txt", O_RDONLY);
FILE *fp = fdopen(fd, "r");
```

| 函数 | 作用 |
|------|------|
| `fileno(fp)` | 获取 `FILE *` 对应的 fd |
| `fdopen(fd, mode)` | 把 fd 包装成 `FILE *` |

`fdopen` 用于 fd 来自其他途径（socket、pipe）但想用 stdio 接口的场景。**`fclose(fp)` 会同时关闭底层 fd**，不要重复 close。

### 同一文件多次打开

```c
FILE *fp1 = fopen("data.txt", "r");
FILE *fp2 = fopen("data.txt", "r");

/* fp1 和 fp2 各自独立 */
fgetc(fp1);   /* fp1 读第 1 字节 */
fgetc(fp2);   /* fp2 读第 1 字节（独立位置） */

/* 各自的缓冲不共享 */
fclose(fp1);  /* 不影响 fp2 */
```

同一文件多次 `fopen` 得到独立的流，各自有缓冲和读写位置。**多线程读同一文件时，每线程独立 `fopen` 比共享一个流更安全**（避免锁竞争）。

## HFT 关联

### 行情数据文件

```c
/* 行情数据用二进制文件存储，packed 结构 */
#pragma pack(push, 1)
struct quote_record {
    uint64_t timestamp_ns;
    uint32_t symbol_id;
    uint32_t bid_price;
    uint32_t bid_qty;
    uint32_t ask_price;
    uint32_t ask_qty;
};
#pragma pack(pop)

_Static_assert(sizeof(struct quote_record) == 32, "size mismatch");

FILE *fp = fopen("market_20240101.dat", "wb");
struct quote_record rec = { ... };
fwrite(&rec, sizeof(rec), 1, fp);
fclose(fp);
```

HFT 行情数据用 `packed` 结构 + 二进制 `fwrite`，保证跨平台字节布局一致。`_Static_assert` 锁定大小，防止误改。

### pcap 文件格式

```c
/* pcap 全局头（24 字节） */
#pragma pack(push, 1)
struct pcap_hdr {
    uint32_t magic_number;   /* 0xa1b2c3d4 */
    uint16_t version_major;
    uint16_t version_minor;
    int32_t  thiszone;
    uint32_t sigfigs;
    uint32_t snaplen;
    uint32_t network;
};

struct pcap_record_hdr {
    uint32_t ts_sec;
    uint32_t ts_usec;
    uint32_t incl_len;
    uint32_t orig_len;
};
#pragma pack(pop)

FILE *fp = fopen("capture.pcap", "rb");
struct pcap_hdr hdr;
fread(&hdr, sizeof(hdr), 1, fp);

struct pcap_record_hdr rec;
while (fread(&rec, sizeof(rec), 1, fp) == 1) {
    char pkt_data[65535];
    fread(pkt_data, rec.incl_len, 1, fp);
    /* 解析报文 */
}
```

pcap 是网络抓包标准格式，HFT 回放引擎常读 pcap 文件重现报文序列。二进制 `fread` + packed 结构是标准读法。

### 历史行情索引文件

```c
/* 索引文件：按 seq 跳转 */
struct index_entry {
    uint64_t seq;
    uint64_t offset;   /* 在数据文件中的偏移 */
};

FILE *idx_fp = fopen("market.idx", "rb");
FILE *dat_fp = fopen("market.dat", "rb");

/* 按 seq 查找 */
uint64_t target_seq = 12345;
struct index_entry ie;
while (fread(&ie, sizeof(ie), 1, idx_fp) == 1) {
    if (ie.seq == target_seq) {
        fseek(dat_fp, ie.offset, SEEK_SET);
        struct quote_record q;
        fread(&q, sizeof(q), 1, dat_fp);
        break;
    }
}
```

历史行情回放按 seq 跳转，索引文件记录每个 seq 在数据文件中的偏移。`fseek` + `fread` 实现随机访问。

### 滚动日志文件

```c
/* 日志按天滚动 */
char path[256];
time_t now = time(NULL);
struct tm *tm = localtime(&now);
snprintf(path, sizeof(path), "/var/log/hft_%04d%02d%02d.log",
         tm->tm_year + 1900, tm->tm_mon + 1, tm->tm_mday);

FILE *log_fp = fopen(path, "a");   /* 追加模式 */
setvbuf(log_fp, NULL, _IOLBF, 0);  /* 行缓冲，崩溃少丢 */
```

日志按天滚动，每天一个文件。`a` 追加模式不覆盖旧日志。行缓冲保证每行 `\n` 后落盘。

## UB 边界

| 情形 | 后果 | 防护 |
|------|------|------|
| 文本模式读二进制文件 | Windows 换行转换破坏数据 | 统一用 `rb`/`wb` |
| `ftell` 在文本流 | 返回值可能不准确 | 用二进制模式 + `fseek/ftell` |
| `fclose` 后用 `FILE *` | UAF | `fclose` 后置 NULL |
| 多个 `FILE *` 写同一文件 | 数据交错、覆盖 | 用锁或单写者 |
| `fdopen` 后重复 close fd | double close | `fclose` 会关 fd，不要手动 close |
| 打开已删除文件（Linux） | 仍可读写，直到所有 fd 关闭 | 理解 Linux unlink 语义 |

### Linux 的 unlink 语义

```c
FILE *fp = fopen("data.txt", "w");
remove("data.txt");   /* unlink */
/* 文件已从目录删除，但 fp 仍可读写 */
/* 直到 fclose，inode 才真正释放 */
fprintf(fp, "still works\n");   /* 成功 */
fclose(fp);
```

Linux 下 `unlink` 只删除目录项，若仍有进程打开该文件，inode 保留到所有 fd 关闭。这一特性用于临时文件安全（`tmpfile` 利用此机制）。
