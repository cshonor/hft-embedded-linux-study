# 6.2 指定初始化

> 一句话概括这一节：**指定初始化是 C 语言里唯一「按名字而不是按位置」写数据的语法**，
> 它把「结构体里剩下的字段怎么办」从程序员的责任变成了编译器的责任。

## 本节讲什么

先看一组数字。Linux v6.6 的 `struct file_operations`（`include/linux/fs.h:1852`）：

| 项目 | 数字 |
|------|------|
| 成员个数 | **34 个**（含 `#ifndef CONFIG_MMU` 下的 `mmap_capabilities`）|
| 尾部属性 | `__randomize_layout`（**编译时随机重排成员顺序**）|
| 典型驱动实现的成员 | 3～6 个 |

用位置初始化写这张表意味着：你要记住 34 个成员的**精确顺序**，而内核每次升级都可能往中间插一个新回调；更糟的是 `__randomize_layout` 让顺序在编译期就变了。所以内核里没有任何一处用位置初始化写 `file_operations`——**全部是指定初始化**。

这一节把指定初始化的**规则边界、方言差异、内存代价、与 C++ 的分歧**全部实测钉死（gcc 13.3 / clang 18.1.3，六轮测试，脚本见 `D:\.kernel-ref\demo-desig\`）。

**它属于 CH1 而不是 CH2 的理由**：写错了立刻编译报错（下标越界、成员不存在、designator 非常量），不会静默出错。这是「源码表面看得见」的语法。

## 核心语法速览

| 写法 | 作用 | 例子 | 标准地位 |
|------|------|------|----------|
| `[N] = v` | 数组按下标 | `int a[] = {[3]=1};` | C99 |
| `[A ... B] = v` | 数组按范围 | `int a[] = {[0 ... 9]=1};` | **GNU 扩展** |
| `.member = v` | 结构体按成员 | `struct S s = {.b=2};` | C99 |
| `.a.b = v` | 嵌套成员链 | `{.geo.x = 5}` | **GNU 扩展**（实测 `-pedantic-errors` 下两个编译器都干净）|
| `member: v` | 老式 GNU 冒号写法 | `{a: 1}` | **已废弃** |
| `{}` | 空初始化器 | `struct S s = {};` | **C23** 才标准 |
| `[N] = v` 用于枚举下标 | 名字当下标 | `color_name[RED] = "red"` | C99（枚举常量是常量表达式）|

**方言支持总表**（实测，`D:\.kernel-ref\demo-desig\run.sh` / `run2.sh`）：

| 写法 | gcc gnu11 | gcc c11 `-pedantic` | gcc `-pedantic-errors` | clang gnu11 `-pedantic` |
|------|-----------|---------------------|------------------------|--------------------------|
| `[N] = v` | ✅ | ✅ | ✅ | ✅ |
| `[A ... B] = v` | ✅ | ⚠️ `ISO C forbids specifying range` | ❌ 硬错误 | ⚠️ `-Wgnu-designator` |
| `.member = v` | ✅ | ✅ | ✅ | ✅ |
| `.a.b = v` | ✅ | ✅ 干净 | ✅ 干净 | ✅ 干净 |
| `member: v` | ✅ | ⚠️ | ❌ `obsolete use of designated initializer with ':'` | ⚠️ `-Wgnu-designator` |
| `{}` | ✅ | ⚠️ | ❌ `ISO C forbids empty initializer braces before C2X` | ⚠️ C23 extension |
| C89 / gnu89 下任何指定初始化 | — | — | ❌ `ISO C90 forbids specifying subobject` | — |

## 一、数组的「当前位置」规则

初始化器有一个隐藏的**游标**：处理完一个 designator 后，游标停在它的下一位，后续的普通值从这里继续填。

实测（`d1-array.c`，gcc / clang、c99 / c11 / gnu11 六组结果完全一致）：

```c
int a1[] = { [5] = 1 };                  /* -> 0 0 0 0 0 1        ，长度 6  */
int a2[] = { [3] = 10, 20, 30 };         /* -> 0 0 0 10 20 30     ，长度 6  */
int a3[] = { 1, 2, [5] = 50, 6, 7 };     /* -> 1 2 0 0 0 50 6 7   ，长度 8  */
int a4[] = { [0 ... 9] = 1 };            /* -> 十个 1             ，长度 10 */
int a5[] = { [2] = 2, [2] = 222 };       /* -> 0 0 222            ，长度 3  */
```

三条规则：

| 规则 | 实测证据 |
|------|----------|
| **长度 = 最大指定下标 + 1**（不是写了几个值）| `a1` 只写 1 个值，长度却是 6 |
| **游标推进**：指定后的普通值从指定下标 +1 开始落 | `a2[4]=20`（接着 `[3]`）、`a3[6]=6`（接着 `[5]`）|
| **重复指定取最后一个** | `a5[2]=222`，编译器给 `-Woverride-init` |

**下标可以倒着写**（实测 `run3.sh` §9）：

```c
int a[] = { [5] = 1, [2] = 2 };      /* -> 0 0 2 0 0 1，长度 6，合法 */
int b[] = { [2] = 20, 30, [0] = 10 };/* -> 10 0 20 30，长度 4，合法 */
```

结构体同理（游标停在指定成员之后）：

```c
struct S { int x; int y; int z; };
struct S s = { .y = 2, 1 };          /* -> x=0 y=2 z=1 ，那个 1 落给了 z */
```

> ⚠️ **这条规则是「部分位置初始化」的坑源**：`struct S s = { 1 };` 只初始化 `x`，而 `struct S s = { .y = 2, 1 };` 里的 `1` 根本不是给 `x` 的。混用指定与位置初始化时，读代码的人必须自己维护游标。

## 二、范围语法 `[A ... B]`（GNU 扩展）

内核里最常见的用途是**枚举下标数组**：

```c
enum { RED, GREEN, BLUE, YELLOW, COLOR_NR };

static const char *const color_name[] = {
    [RED]    = "red",
    [GREEN]  = "green",
    [YELLOW] = "yellow",
    /* BLUE 没写 -> NULL，长度仍是 4 */
};

static int flags[COLOR_NR] = {
    [RED ... BLUE] = 1,        /* -> 1 1 1 0 */
};
```

### 两个实测出来的语法陷阱

| 写法 | 结果 |
|------|------|
| `[0 ... 3] = 1` | ✅ 正常 |
| `[0...3] = 1`（**省略空格**）| ❌ `error: too many decimal points in number` —— 预处理器把 `0...3` 当成一个浮点数 |
| `[3 ... 0] = 1`（**倒序**）| ❌ `error: empty index range in initializer` |

第一条是**必踩坑**：`...` 两侧必须有空格，否则词法分析阶段就被切成数字字面量了。

### 标准符合性

范围语法是纯 GNU 扩展，在 `-pedantic` 下 gcc 给 warning、`-pedantic-errors` 下变**硬错误**（`ISO C forbids specifying range of elements to initialize`），clang 则始终是 warning（`-Wgnu-designator`）。内核用 `-std=gnu11` 不开 pedantic，所以可以放心用。

## 三、结构体：未指定成员去哪了

**全部零初始化**——不是「不初始化」，是编译器负责填 0。实测 `d3-struct.c`：

```c
static struct cfg c1 = {
    .cb   = NULL,
    .name = "dpdk0",
    .geo  = { .y = 7 },          /* 标准嵌套写法：只给 y，x 为 0 */
};
/* 实测输出：port=0 name=dpdk0 ratio=0.000000 geo.x=0 geo.y=7 cb=NULL */
```

指针变 `NULL`、浮点变 `0.0`、嵌套结构体的未指定成员继续递归清零。栈上的局部结构体也一样（实测：40 字节的 `struct cfg x = {.port=1}`，除 port 的 4 字节外**全部为 0**）。

### 3.1 嵌套两种写法

```c
/* 标准 C99：一层一层套括号 */
struct cfg c = { .geo = { .x = 5, .y = 6 } };

/* GNU 扩展：designator 链直接指到内层 */
struct cfg c = { .geo.x = 5, .geo.y = 6 };
```

后者在两个编译器、`-std=c99 -pedantic-errors` 下**都是干净的**（实测 `run2.sh` §4）——虽然 GCC 手册把它列为扩展，但实测 `-pedantic-errors` 不报错，可以放心用。

### 3.2 union 与位域

```c
union u_t { int i; float f; char buf[8]; };
static union u_t u1 = { .f = 3.14f };     /* 实测 u1.i = 1078523331（同一块内存的 int 视图）*/
static union u_t u2 = { .buf = "hi" };    /* 实测 u2.i = 0x00006968 */

struct bits { unsigned a:3; unsigned b:5; unsigned c:24; };
static struct bits b1 = { .b = 0x1f, .c = 0x1234 };   /* 实测 a=0 b=31 c=0x1234，sizeof=4 */
```

**union 的指定初始化只会初始化你命名的那一个成员**，其余成员是同一块内存的别名视图（不是 0！）。这条和 struct 的行为完全不同。

### 3.3 padding 也被清零——这是免费的信息泄露防护

这是本轮最值得记住的一条。实测 `run5.sh` §20：

```c
struct hole { char a; /* 3 字节 padding */ int b; };
```

| 初始化方式 | -O0 下 padding | -O2 下 padding |
|------------|----------------|----------------|
| `struct hole h = { .a = 1, .b = 2 };` | `00 00 00` | `00 00 00` |
| `struct hole h = { 0 };` | `00 00 00` | `00 00 00` |
| `struct hole h; h.a=1; h.b=2;`（逐字段）| `00 00 00` | **`76 57 1a`（栈上的垃圾！）**|

`-O2` 下逐字段赋值**不会**清 padding，编译器只写 `a` 和 `b` 两个字段。如果这个结构体随后被 `write()` 出去、`copy_to_user()` 拷给用户、或写进日志文件，**3 字节栈内容就泄露了**——这是内核历史上反复出现的一类 CVE。

而指定初始化（和 `{0}`）强制编译器把整个对象清零，天然免疫。

> **推论**：凡是会离开进程边界的结构体（网络报文头、ioctl 参数、日志、持久化格式），用指定初始化或 `= {0}`，不要用逐字段赋值。

## 四、稀疏不稀疏：静态数据的真实代价

`int a[1000] = { [999] = 1 };` 会不会像 Python 字典那样只存一个元素？**不会。** 实测 `run2.sh` §6：

```c
const int big[1001] = { [1000] = 1 };   /* 实测 sizeof = 4004 字节，nm 显示 size=0xfa4，段 R */
```

### 段布局完整矩阵（实测 `run3.sh` §8，每个数组 4096 个 int = 16 KB）

| 声明 | 段 | 占目标文件？ | 实测 size |
|------|-----|------------|-----------|
| `const int A[4096] = {0};` | `.rodata`（**R**）| ✅ 全量 16 KB | 16384 |
| `int B[4096] = {0};` | `.bss`（**B**）| ❌ 不占 | 16384 |
| `const int C[4096] = {[0]=1};` | `.rodata`（**R**）| ✅ 全量 | 16384 |
| `int D[4096] = {[0]=1};` | `.data`（**D**）| ✅ 全量 | 16384 |
| `const int E[4096] = {[4095]=1};` | `.rodata`（**R**）| ✅ 全量 | 16384 |
| `int F[4096] = {[4095]=1};` | `.data`（**D**）| ✅ **全量 16 KB** | 16384 |

**只有「可写 + 全 0」能进 `.bss`。** 加 `const`、或只要有**任何一个**非 0 值（哪怕在末尾），整块数据就实打实进文件。

放大版实测（`run2.sh` §6b）：`int zw2[100000] = { [99999] = 1 };` → `.data` 400 000 字节，目标文件 **801 584 字节**。

> ⚠️ **嵌入式第一坑**：在 Flash 只有几百 KB 的 MCU 上写一句 `static const uint32_t tbl[65536] = {[65535] = 1};`，256 KB 就没了。
> 指定初始化是**静态数据布局工具**，不是稀疏容器。真要稀疏，得用运行时构建（哈希表 / 按需分配）。

## 五、const 表真的只读吗：段归属

函数指针跳转表实测（`run3.sh` §11 / `run4.sh` §15）：

```c
static int (*const handlers[OP_NR])(int,int) = { [ADD]=op_add, [SUB]=op_sub, [MUL]=op_mul };
```

```text
nm -S:  0000000000000000 0000000000000028 d handlers     <- 小写 d，不是 r！
size -A: .data.rel.ro.local   40
```

**它不在 `.rodata`，在 `.data.rel.ro.local`。** 原因：函数指针的值在链接/加载时才能确定，需要**重定位**，所以这一页必须先可写、重定位完再由动态链接器 `mprotect` 成只读（这就是 RELRO）。

纯数据的 const 表没有这个问题（实测 `run5.sh` §21：`static const int T_di[256]` → `r`，落在 `.rodata`）。

### 顺带的实测性能数据

| 表 | 段 | 2 亿次累加（20 万轮 × 256 项）|
|----|-----|------|
| `static const int T_di[256]` 编译期常量 | `.rodata`（r）| **0.008890 s** |
| `static int T_rt[256]` 运行期填 | `.bss`（b）| 0.013672 s |

const 表快 35%——编译期已知内容让编译器能做常量传播，而运行期填的表每次都可能被别名改写。

## 六、C 与 C++ 的分歧矩阵

同一份代码在 C 和 C++ 下命运完全不同。实测 `run2.sh` §5 / `run3.sh` §5b：

| 情形 | C（c99/c11/gnu11）| g++ 17/20 | clang++ 20 |
|------|-------------------|-----------|------------|
| `.a=1, .c=3`（跳过 b）| ✅ | ✅ 干净 | ✅ 干净 |
| `.c=3, .a=1`（**乱序**）| ✅ | ❌ `designator order for field does not match declaration order` | ⚠️ warning |
| `[3]=1`（**数组下标**）| ✅ | ❌ **`sorry, unimplemented: non-trivial designated initializers not supported`** | ⚠️ `-Wc99-designator` |
| `.a=1, .a=2`（**重复**）| ✅ 取最后 + `-Woverride-init` | ❌ `designator used multiple times in the same initializer list` | ⚠️ warning |
| `[0 ... 3]=1`（**范围**）| ✅ GNU | ❌ `expected identifier before numeric constant` | ⚠️ `-Wc99-designator` |

三条要点：

1. **C++ 要求按声明顺序**（C++20 标准引入的 designated initializer 明确规定），乱序在 g++ 是硬错误。所以给 C/C++ 双用头文件写默认值时，**必须按结构体声明顺序逐个写**。
2. **g++ 至今不支持数组下标 designator**——报的是 `sorry, unimplemented`，这是 GCC C++ 前端长期未实现项，不是你写错了。clang++ 作为扩展支持。
3. **C 里重复指定是 warning，C++ 里是 error**。这一条决定了：C 项目必须依赖 `-Woverride-init` 来抓（见 §10）。

## 七、C89 完全不支持，连 gnu89 也不行

实测 `run4.sh` §14：

```text
gcc -std=c89   -pedantic-errors: error: ISO C90 forbids specifying subobject to initialize
gcc -std=c90   -pedantic-errors: error: （同上）
gcc -std=gnu89 -pedantic-errors: error: （同上）
```

指定初始化是 **C99** 特性，GNU 扩展**没有**把它回植到 gnu89。这和 GNU 的一贯做法不同（大部分 GNU 扩展在 gnu89 下可用）。

> 影响面：内核从 **v5.18 起把 `-std=gnu89` 换成了 `-std=gnu11`**（本仓库缓存的 v6.x Makefile:560 就是 `KBUILD_CFLAGS += -std=gnu11`）。
> 也就是说：**5.18 之前的内核源码里不会出现 C99 指定初始化**；读老驱动时看到的位置初始化表，是方言限制而不是作者偷懒。

## 八、designator 必须是常量表达式

实测 `run4.sh` §13：

```c
int n = 3;
int a[] = { [n] = 1 };              /* ❌ error: nonconstant array index in initializer */

int main(void){
    int k = 2;
    int a[8] = { [k] = 5 };         /* ❌ 同样 error，块作用域也不行 */
}
```

**文件作用域和块作用域都要求常量**。想「按下标动态初始化」只能改用运行时赋值：

```c
int a[8] = {0};
a[k] = 5;                            /* 运行期 */
```

枚举常量、sizeof、常量算术都是合法的（它们都是常量表达式），所以 `[COLOR_NR] = 0`、`[NR_CPUS] = 1` 这类写法没问题。

### 另外三个边界情形（实测 `run4.sh` §17）

| 代码 | 结果 |
|------|------|
| `int a[4] = { [4] = 1 };` | ❌ `array index in initializer exceeds array bounds` |
| `struct S {int a;}; struct S s = {.b=1};` | ❌ `struct S has no member named 'b'` |
| `int a[] = {[1]=1, [1]=2, [1]=3};` | ⚠️ 三次 `-Woverride-init`，最终 `a[1]=3` |

前两条是**编译期硬错误**，这正是把 6.2 划进 CH1 的理由：写错立刻发现。

## 九、成本：部分初始化会付整块 memset 的钱

「未指定成员自动清零」不是免费的。实测 `run5.sh` §19，结构体含 4096 字节 payload：

```c
struct big { int hdr; char payload[4096]; int tail; };

static int f_di(void)     { struct big x = { .tail = 7 }; return x.tail; }   /* 部分初始化 */
static int f_manual(void) { struct big x; x.tail = 7;     return x.tail; }   /* 逐字段 */
```

| 优化级别 | 部分初始化 | 逐字段 | 全零 + 赋值 |
|----------|-----------|--------|-------------|
| **-O0** | **0.025447 s** | 0.000707 s | 0.016459 s |
| -O2 | 0.000750 s | 0.000886 s | 0.000839 s |

`-O0` 下**部分初始化比逐字段慢 36 倍**。看下汇编就明白了：

```asm
; f_di, -O0
movl    $513, %ecx      # 513 个 quad word = 4104 字节
rep stosq               # 整块 memset
movl    $7, -12(%rbp)   # 再写 tail
```

而 `-O2` 下三者同速——因为 `x.tail` 是唯一被用到的字段，编译器把整个结构体删掉了：

```asm
; f_di, -O2
movl    $7, %eax
ret
```

> **给 HFT / 热路径的建议**：
> - `-O2` 且结构体不 escape 时无所谓，编译器会删掉。
> - 一旦结构体**取地址传给外部函数**（-O0 调试构建、跨 TU 调用），`struct big x = {.tail=7}` 每次进函数都要 memset 整块——此时该改成逐字段赋值 + 显式写关键字段。
> - 反过来，如果**正确性依赖其余字段为 0**（见 §3.3 的 padding 泄露），这个 memset 就是必须付的钱。

## 十、编译器开关：三个相关的 -W

| 开关 | 抓什么 | gcc | clang | 备注 |
|------|--------|-----|-------|------|
| `-Woverride-init` | 同一元素/成员被指定两次 | ✅ 默认就在 `-Wall` 之外，需显式开（实测 `-Wall -Wextra` 也抓到 1 条）| 对应 `-Winitializer-overrides`（`-Wall -Wextra` 自带）| 名字不同，**跨编译器 CI 要写两个** |
| `-Wmissing-field-initializers` | 部分**位置**初始化 | ✅ | ✅ | **指定初始化不触发**（实测：只报 `{1}` 那行，`.b=2` 和 `{0}` 都不报）|
| `-Wgnu-designator` / `-Wpedantic` | GNU 扩展（范围语法、冒号写法）| 走 `-Wpedantic` | 专用 `-Wgnu-designator` | clang 分得更细 |

实测 `run2.sh` §7 的重复初始化用例：

```c
static struct ops o = {
    .open = my_open,
    .read = my_read,
    .open = my_open,     /* 复制粘贴导致的重复 */
};
/* gcc -Woverride-init:  warning: initialized field overwritten */
/* clang -Wall:          warning: initializer overrides prior initialization */
```

这在内核这种「30+ 成员的接口表」里是高频错误——复制一行改个名字，结果把上一行覆盖了，而**因为两个值一样（同一个函数），功能测试根本发现不了**（§11 的 HFT 案例里如果 `min_len` 被覆盖才会暴露）。

**`-Wmissing-field-initializers` 不报指定初始化**是它的一大实用优势：你可以用 `-Wextra` 抓「忘了初始化某字段」，同时用指定初始化只写关心的那几个，两者不冲突（实测：`{1}` 报警，`.b=2` 和 `{0}` 都不报；数组完全不触发该警告）。

## 十一、实战：跳转表 / 接口表 / sentinel / 复合字面量

### 11.1 稀疏跳转表（HFT 协议分发）

实测 `run6.sh` §24，完整可跑：

```c
enum { OP_LOGIN=1, OP_ORDER=2, OP_CANCEL=3, OP_QUOTE=5, OP_NR=8 };

struct opdesc {
    const char *name;
    int  (*handler)(const void*, int);
    unsigned min_len;
    unsigned flags;
};

static const struct opdesc OPS[OP_NR] = {
    [OP_LOGIN]  = { .name="LOGIN",  .handler=h_login,  .min_len=16, .flags=F_AUTH },
    [OP_ORDER]  = { .name="ORDER",  .handler=h_order,  .min_len=32, .flags=F_AUTH|F_HOT },
    [OP_CANCEL] = { .name="CANCEL", .handler=h_cancel, .min_len=12 },
    [OP_QUOTE]  = { .name="QUOTE",  .min_len=4,        .flags=F_HOT },  /* 无 handler */
    /* opcode 0/4/6/7 全部为 0 —— 包括 name=NULL */
};

static int dispatch(unsigned op, const void *pkt, int len, int authed)
{
    if (op >= OP_NR)                     return -1;   /* 越界 */
    const struct opdesc *d = &OPS[op];
    if (!d->name)                        return -2;   /* 未定义 opcode */
    if ((d->flags & F_AUTH) && !authed)  return -3;   /* 需要认证 */
    if (!d->handler)                     return -4;   /* 已定义但不可处理 */
    if (len < (int)d->min_len)           return -5;   /* 长度不足 */
    return d->handler(pkt, len);
}
```

实测输出：`LOGIN ok→0` / `LOGIN 未认证→-3` / `ORDER 太短→-5` / `QUOTE 无处理→-4` / `opcode 0→-2` / `opcode 99→-1`，表 192 字节落在 `.data.rel.ro.local`。

**这张表把「哪些 opcode 存在、要不要认证、最小长度、有没有处理函数」四件事放在一处**，新增 opcode 只需加一行，不碰 `dispatch`。位置初始化做不到这件事——你没法只写第 5 项。

### 11.2 sentinel 表（内核 `of_device_id` 模式）

实测 `run3.sh` §12：

```c
static const struct dev_entry table[] = {
    { .name = "dev-a", .id = 0x10, .probe = p_a },
    { .name = "dev-b", .id = 0x20, .flags = 0x3 },   /* 无 probe */
    { .name = "dev-c", .id = 0x30, .probe = p_c },
    { },                                              /* sentinel：全 0 */
};

for (int i = 0; table[i].name; i++)  ...              /* 靠 name==NULL 停 */
```

实测 sentinel：`name=(NULL) id=0 probe=无 flags=0`。`{ }` 是 C23 的空初始化器（在 gnu11 下无 flag 时 gcc/clang 都接受，实测 `run6.sh` §22），等价于全 0。

内核的 `of_device_id`、`pci_device_id`、`platform_device_id` 全是这个模式——末尾一个全 0 项当终止哨兵，遍历代码不需要知道表长。

### 11.3 复合字面量 + 指定初始化 = 全零重置

实测 `run3.sh` §10：

```c
struct cfg c = { .port = 1, .name = "a", .retries = 9 };
c = (struct cfg){ .port = 2 };      /* 其余字段被清零，不是保留！ */
```

实测输出：`port=2 name=(NULL) retries=0`。这是 C 里「重置一个结构体」的标准写法——比 `memset(&c, 0, sizeof c); c.port = 2;` 更不容易漏字段。

也常用于传参：`apply(&(struct cfg){ .port = 8080 });`（未指定成员自动 0）。

### 11.4 内核里的位置：file_operations

回到开头那张表。v6.6 `include/linux/fs.h:1852` 的 `file_operations` 有 34 个成员，尾部是 `__randomize_layout`：

```c
static const struct file_operations demo_fops = {
    .owner  = THIS_MODULE,
    .open   = demo_open,
    .read   = demo_read,
    /* 其余 31 个成员自动为 NULL */
};
```

三条指定初始化在这里的价值：

1. **只写实现的 3 个**，其余 31 个自动 NULL，不用背顺序。
2. **内核升级插新成员不影响**——位置初始化插一个成员就会整体错位。
3. **`__randomize_layout` 让位置初始化在物理上不可能**（顺序是编译期随机的）。

更多内核案例见 [6.2.3 Linux 内核驱动注册](./6.2.3-Linux内核驱动注册.md)。

## 误区速查表

| 误区 | 实测真相 |
|------|----------|
| 「`int a[1000]={[999]=1}` 只占一个 int 的空间」| ❌ 实打实 4004 字节进 `.rodata`/`.data`。**只有「可写 + 全 0」进 `.bss`** |
| 「`const` 数组全 0 不占空间」| ❌ `const int A[4096]={0}` 仍占 16 KB `.rodata`。const 不能进 bss |
| 「范围语法 `[0...3]` 可以不加空格」| ❌ `error: too many decimal points in number` |
| 「范围语法可以倒着写」| ❌ `error: empty index range in initializer` |
| 「同一成员写两次，编译会报错」| ❌ C 下取最后一个，只给 warning；**C++ 下才是 error** |
| 「指定初始化能按下标变量初始化」| ❌ designator 必须是常量表达式，块作用域也一样 |
| 「C89 项目用 GNU 扩展也能写指定初始化」| ❌ gnu89 照样是硬错误，C99 起才有 |
| 「C++ 支持和 C 一样的指定初始化」| ❌ 乱序在 g++ 是 error；**数组下标 designator 在 g++ 是 `sorry, unimplemented`** |
| 「含函数指针的 const 表在 `.rodata`」| ❌ 在 `.data.rel.ro.local`（要重定位，加载后 RELRO 保护）|
| 「逐字段赋值和指定初始化等价」| ❌ `-O2` 下逐字段**不清 padding**，可能泄露栈内容 |
| 「热路径上 `struct big x = {.a=1}` 没有代价」| ❌ `-O0` 下每次调用 `rep stosq` 整块清零，实测慢 36 倍 |
| 「`-Wmissing-field-initializers` 会抱怨我只写了几个字段」| ❌ 指定初始化不触发该警告（位置初始化才会）|

## 代码自测

**题目 1：** 写出以下初始化的完整内容和数组长度，并说明 `20` 落在哪里。
```c
int a[] = { [3] = 10, 20, [1] = 5 };
```

<details>
<summary>参考答案</summary>

`0 5 0 10 20`，长度 5。

游标规则：`[3]=10` 把游标推到下标 4，紧接着的 `20` 落在 `a[4]`；然后 `[1]=5` 回退覆盖 `a[1]`。
长度取最大指定下标 +1 = 4，但 `a[4]=20` 又把它推到 5。

实测同类用例（`run3.sh` §9）：`int b[] = {[2]=20, 30, [0]=10}` → `10 0 20 30`，长度 4。

</details>

**题目 2：** 这段代码能编译吗？`a[2]` 是多少？想动态指定下标该怎么办？
```c
void f(int k) { int a[8] = { [k] = 5 }; (void)a; }
```

<details>
<summary>参考答案</summary>

不能。`error: nonconstant array index in initializer`——**designator 必须是常量表达式，块作用域也一样**（实测 `run4.sh` §13，文件作用域和块作用域都报这个错）。

想动态指定只能改成运行时赋值：

```c
void f(int k) { int a[8] = {0}; a[k] = 5; (void)a; }
```

枚举常量、`sizeof`、常量算术都是合法的（都是常量表达式），所以 `[COLOR_NR] = 0` 这类写法没问题。

</details>

**题目 3：** 一个 256 项的函数指针表，只实现了其中 3 项。用指定初始化和不用它，在**占用空间**上有区别吗？这个表会落在哪个段？

<details>
<summary>参考答案</summary>

**占用空间没有区别**——指定初始化不产生稀疏存储。实测 `const int big[1001] = {[1000]=1}` 是 4004 字节，`int F[4096] = {[4095]=1}` 是完整 16 KB 且落在 `.data`。差别只在于**源代码可读性**和「未指定项自动 NULL」这个语义保证。

段归属取决于**表的内容**而不是写法：

- 纯数据（int / 字符串指针常量）的 `static const` 表 → `.rodata`（实测 `nm` 显示 `r`）
- **含函数指针**的 `static ... const` 表 → `.data.rel.ro.local`（实测 `nm` 显示小写 `d`，`size -A` 有该段 40/192 字节）

原因：函数指针的值要等加载时重定位，所以这一页必须先可写，重定位完再由动态链接器 `mprotect` 成只读（RELRO）。

顺带一提，实测静态 const 表比运行期填充的可写表快 35%（0.008890 s vs 0.013672 s），因为编译期已知内容让编译器能做常量传播。

</details>

**题目 4：** 下面两个函数，谁更安全？为什么？
```c
struct hole { char a; int b; };          /* a 后面有 3 字节 padding */
void f1(void) { struct hole h = { .a = 1, .b = 2 }; send_out(&h, sizeof h); }
void f2(void) { struct hole h; h.a = 1; h.b = 2;    send_out(&h, sizeof h); }
```

<details>
<summary>参考答案</summary>

`f1` 安全，`f2` 有信息泄露风险。

实测（`run5.sh` §20，`-O2`）：

| 方式 | padding 内容 |
|------|-------------|
| `f1` 指定初始化 | `01 00 00 00 02 00 00 00` ← padding 全 0 |
| `f2` 逐字段赋值 | `01 76 57 1a 02 00 00 00` ← **padding 是栈上的垃圾** |

指定初始化强制编译器把整个对象清零（`-O0` 下生成 memset，`-O2` 下也保证 padding 为 0）；逐字段赋值只写 `a` 和 `b`，padding 保持未初始化状态。`-O2` 下 gcc 还会给 `f2` 报 `-Wuninitialized`。

`send_out` 把整个 `sizeof h`（含 padding）送出去时，`f2` 就把 3 字节栈内容泄露给了对端/用户空间/日志。这是内核历史上反复出现的一类 CVE。

规则：**凡是会离开进程边界的结构体（网络报文头、ioctl 参数、日志、持久化格式），用指定初始化或 `= {0}`。**

</details>

**题目 5：** 一个 `-O0` 编译的调试构建里，热路径上这两行哪个快？差多少？
```c
struct big { int hdr; char payload[4096]; int tail; };
struct big x1 = { .tail = 7 };     /* A */
struct big x2; x2.tail = 7;        /* B */
```

<details>
<summary>参考答案</summary>

B 快得多，实测（20 万次调用，`run5.sh` §19）：

| 方式 | -O0 | -O2 |
|------|-----|-----|
| A 部分初始化 | **0.025447 s** | 0.000750 s |
| B 逐字段 | 0.000707 s | 0.000886 s |
| 全零 + 赋值 | 0.016459 s | 0.000839 s |

`-O0` 下 A 慢 **36 倍**：汇编是 `movl $513,%ecx; rep stosq`（清 4104 字节）再 `movl $7`。

`-O2` 下三者同速，因为 `x.tail` 是唯一被用到的字段，编译器把整个结构体删了（A 直接变成 `movl $7,%eax; ret`）。

**所以这条只在「结构体真的被用到了 / escape 了 / -O0 调试构建」时才成立。** 判断依据：如果结构体的地址传给了外部函数（跨 TU、取地址），编译器不敢删，那个 memset 就是实打实的。

反过来，如果正确性依赖其余字段为 0（padding 不泄露），这个 memset 是必须付的钱——见题目 4。

</details>
