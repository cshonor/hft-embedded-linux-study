# 7.9.2 数组名的本质

## 本节讲什么

数组名是**非指针常量**：表示整个数组，在表达式中通常**衰变**为指向首元素的指针。

严格说，标准的退化规则**主语是「数组类型的表达式」**（不只数组名，字符串字面量、复合字面量也算），**例外条款约束的是「上下文」**——C11 6.3.2.1p3 文本列 **4 项**（`sizeof`、`_Alignof`、一元 `&`、字符串字面量用于初始化数组），但 `_Alignof` 标准只吃 type-name（`_Alignof(int[16])`），对表达式实际生效的是 **3 项**。详解见 [02 书 8.1.1 数组名](../../../../02-advanced-pointers-and-memory/ch08-arrays/8.1-one-dimensional-arrays/8.1.1-数组名.md)。

传参衰变是 `sizeof` 陷阱与 `ARRAY_SIZE` 失效的根源。

## 要点

```c
char buf[16];
char *p = buf;        /* decay: buf → &buf[0] */

&buf;                 /* 类型 char (*)[16] */
buf;                  /* decay 后类型 char *，值常等于 &buf[0] */

sizeof buf;           /* 16 */
void f(char a[16]) { sizeof a; }  /* 8，形参是指针 */
```

| 表达式 | 类型（典型） | 值 |
|--------|--------------|-----|
| `buf` | `char *`（decay） | 首元素地址 |
| `&buf` | `char (*)[16]` | 数组地址 |
| `&buf[0]` | `char *` | 首元素地址 |

```c
#define ARRAY_SIZE(a) (sizeof(a) / sizeof((a)[0]))
/* 仅用于实体数组，指针参数无效 */

int *hp = malloc(n * sizeof *hp);
/* ARRAY_SIZE(hp) 错误！ */
```

```bash
./demo01   # 观察 buf、p、&buf 打印
```

```gdb
(gdb) print buf
(gdb) print &buf
(gdb) print sizeof(buf)
```

- **字符串字面量**：类型 `char[N]`，decay 为 `char *`，存储只读
- **static 数组形参**：`void f(char a[static 16])` C99 优化提示
- **VLA**：运行时大小，仍 decay

## 代码自测

**题目 1：** 数组名在什么情况下不退化为指针？`&arr` 和 `arr` 的区别是什么？
```c
int arr[5] = {1, 2, 3, 4, 5};
printf("%p %p %p\n", arr, &arr[0], &arr);
printf("%zu %zu\n", sizeof(arr), sizeof(&arr));
```
<details>
<summary>参考答案</summary>

前三个地址值相同，但类型不同。

数组名不退化的三种情况：
1. `sizeof(arr)`：结果是整个数组大小 20，不是指针大小
2. `&arr`：结果是数组指针 `int (*)[5]`，不是 `int **`
3. 字符串字面量初始化 `char s[] = "hello"`：s 是数组不是指针

`arr` vs `&arr[0]` vs `&arr`：
- `arr`：退化为 `int *`，指向 arr[0]
- `&arr[0]`：`int *`，指向 arr[0]，与 arr 相同
- `&arr`：`int (*)[5]`，指向整个数组的地址

地址值相同，但类型不同：
- `arr + 1`：增加 4 字节（跳过一个 int）
- `&arr + 1`：增加 20 字节（跳过整个数组）

`sizeof(arr)` = 20，`sizeof(&arr)` = 4/8（指针大小）。

</details>
