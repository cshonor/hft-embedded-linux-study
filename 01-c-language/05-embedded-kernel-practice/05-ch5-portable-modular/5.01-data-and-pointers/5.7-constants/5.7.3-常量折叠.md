# 5.7.3 常量折叠

## 本节讲什么

**常量折叠**是编译器在编译期计算常量表达式的优化：如 `3 + 5` 直接变为 `8`，数组大小、`case` 标签、`enum` 初值依赖此特性。`__builtin_constant_p`（ch06 **2.5.4**）让宏区分编译期常量与运行期值。理解折叠有助于写高效宏与静态断言。

## 要点

```c
#define SIZE (1024 * 4)
char buf[SIZE];              /* SIZE 编译期可知 */

int n = 10;
char bad[n];                 /* VLA，C99；C11 可选，非折叠 */

_Static_assert(sizeof(int) >= 4, "int too small");
```

```c
/* 折叠 vs 运行期 */
enum { MASK = (1u << 3) | (1u << 5) };   /* 编译期 0x28 */

int shift(int x) { return 1 << x; }      /* 运行期 */
```

**汇编证据（Compiler Explorer 实测：GCC 13.3 / Clang 18.1.0）**：

```c
int folded(void)      { return 3 * 4 + 5; }
int not_folded(int x) { return x * 2 + 1; }
```

```asm
folded:                        ; gcc -O2 x86-64 (Intel 语法)
        mov     eax, 17        ; 3*4+5 编译期算完，无 imul/add
        ret
not_folded:
        lea     eax, [rdi+1+rdi]  ; x 未知折不了，优化成一条 lea（强度削减）
        ret
```

aarch64 上折叠结果是 `mov w0, #17; ret`（clang `-O2`），乘法指令同样消失。

**三个易混概念**：

| 概念 | 行为 | 例子 |
|------|------|------|
| 常量折叠 folding | 表达式全是常量，编译期求值 | `3 * 4 + 5` → `17` |
| 常量传播 propagation | 把变量替换为其已知常量值，再触发折叠 | `enum { A = 5 }; return A * 2;` → `10` |
| 强度削减 strength reduction | 折不了时换廉价指令 | `x * 2 + 1` → 一条 `lea` |

**`-O0` 并不等于「不折叠」（实测对照）**：

| 表达式 | GCC 13.3 `-O0` | Clang 18.1.0 `-O0` | 两者 `-O2` |
|--------|----------------|--------------------|-----------|
| `3*4+5`（纯字面量） | 折叠 `mov eax, 17` | 折叠 `mov eax, 17` | 折叠 |
| `const int a = 3; return a * 4 + 5;` | **不折叠**：栈存储 + `sal eax, 2` + `add eax, 5` | 折叠 `mov w0, #17`（aarch64；仍保留栈槽供调试） | 折叠 |

- 纯字面量由**前端常量求值**处理，与优化等级无关——C 标准要求编译期可求值
- 想学汇编时看「原样翻译」的算术指令：用 **GCC `-O0` + `const` 局部变量**，能看到真实的栈存取与 `sal`/`add`
- **浮点不随便折**：`3.0 * 4.0` 是否折叠受舍入模式与浮点异常约束，激进折叠要 `-ffast-math`；IEEE 语义下编译器默认保守

| 工具 | 用途 |
|------|------|
| `gcc -E` | 查看宏展开后是否仍为常量 |
| `__builtin_constant_p(x)` | 宏分支选择 |
| `static_assert` / `_Static_assert` | 编译期约束 |

```bash
echo 'int a[2+3];' | gcc -c -xc - -o /dev/null -Wall
gcc -E const.c | less    # 查看折叠结果
```

```c
/* ch06 风格 */
#define IS_CONST(x) __builtin_constant_p(x)
#define OPTIMIZED_MAX(a, b) \
    (__builtin_constant_p((a) & (b)) ? ((a) > (b) ? (a) : (b)) : max_func(a, b))
```

- **未折叠副作用**：`#define SQR(x) ((x)*(x))` 中 `x` 有副作用会重复求值
- **内核 `ARRAY_SIZE(arr)`**：要求编译期已知长度，指针非数组时陷阱 → **5.9**

## 代码自测

**题目 1：** 什么是常量折叠？以下代码中 x 的值在编译后还存在吗？
```c
const int SIZE = 10;
int arr[SIZE];  // C99 VLA? 还是常量折叠?
int main(void) {
    int x = SIZE * 2;  // x = ?
    printf("%d\n", x);
}
```
<details>
<summary>参考答案</summary>

常量折叠（Constant Folding）：编译器在编译期计算常量表达式的值，直接用结果替换。

`int x = SIZE * 2` → 编译器知道 SIZE=10 是 const，直接计算 `x = 20`，不生成乘法指令。

但注意：
1. **C 语言中 const 不是真正的常量表达式**。`int arr[SIZE]` 在 C89 中不合法（SIZE 是只读变量不是常量表达式）。C99 中作为 VLA 处理（运行时分配）
2. **C++ 中 const 是常量表达式**。`int arr[SIZE]` 在 C++ 中合法
3. GCC 可能对全局 const 做常量折叠（优化），但不保证

验证：
```c
const int n = 10;
int *p = (int *)&n;
*p = 20;          // UB: 修改只读内存
printf("%d\n", n); // 可能输出 10（常量折叠）或 20（实际读取）
```

常量折叠使得修改 const 变量后，读取值可能不变——编译器直接用编译期常量替换了读取操作。

</details>

**题目 2：** GCC `-O0`（不优化）下，下面两个函数生成的汇编一样吗？
```c
int f(void) { return 3 * 4 + 5; }
int g(void) { const int a = 3; return a * 4 + 5; }
```
<details>
<summary>参考答案</summary>

不一样（GCC 13.3 实测）：

- `f`：纯字面量表达式由**前端常量求值**处理，与优化等级无关 → `mov eax, 17`
- `g`：`const` 局部变量在 GCC `-O0` 下**不折叠** → 栈存储 + `sal eax, 2` + `add eax, 5`，开 `-O1` 以上才折掉

两个推论：

1. **`-O0` ≠ 不优化**。常量求值、指令选择（`*4` → `sal`）这类变换在 `-O0` 照样发生。
2. 编译器行为不统一：Clang 18.1.0 在 `-O0` 下连 `g` 也折成 `mov w0, #17`（aarch64），但仍保留 `a` 的栈槽供调试器观察。「折叠与否」不能凭直觉断言，要看具体编译器 + 优化等级 + 表达式形态。

</details>
