# 3.6 C语言和汇编语言混合编程

## 本节讲什么

同一工程里 C 与汇编的三条交汇路径：**C 调汇编函数**、**C 内嵌汇编**、**汇编调 C**。三者都必须共同遵守一套 **ABI（调用约定）**——参数在哪、返回值在哪、哪些寄存器要保存、栈怎么排——否则参数错位、返回值丢失、栈帧崩坏。内核 `asm/`、驱动、裸机启动代码里全是这三条路径。

本篇是总纲。内联汇编的语法（四段式、操作数约束、clobber、`volatile`、`asm goto`）是 GNU C 扩展里最硬核、最容易出静默 bug 的一块——**编译器无法检查你的汇编模板和约束是否匹配**，写错要么编译期炸（算你运气好），要么运行时静默 corrupt。全部结论经 WSL x86-64 实测（gcc 13.3 / clang 18.1.3 / binutils 2.42），ARM 部分讲原理并标注"未实测"（无 aarch64 交叉工具链）。

| 方式 | 场景 | 小节 |
|------|------|------|
| C → 汇编函数（`.S` 文件） | 热点优化、平台原语 | [3.6.1](./3.6.1-ATPCS规则.md) |
| C 内嵌汇编（`asm` 关键字） | 读写协处理器/系统寄存器、屏障、原子操作 | [3.6.2](./3.6.2-在C程序中内嵌汇编代码.md) |
| 汇编 → C（`bl main` / `call`） | 启动代码、异常向量、裸机 reset | [3.6.3](./3.6.3-在汇编程序中调用C程序.md) |

## 一、三种路径总览

### 1. C 调汇编函数

C 侧 `extern` 声明，汇编侧 `.global` 导出，按 ABI 传参：

```c
/* C 侧 */
extern int add_asm(int a, int b);   /* 声明 */
int sum = add_asm(3, 5);            /* 调用 */
```

```asm
/* x86-64 SysV ABI: a->edi, b->esi, return->eax */
        .text
        .globl add_asm
        .type  add_asm, @function
add_asm:
        mov    %esi, %eax      /* eax = b */
        add    %edi, %eax      /* eax += a */
        ret
```

```arm
/* ARM AAPCS: a->r0, b->r1, return->r0 (未实测，无交叉工具链) */
        .global add_asm
        .type  add_asm, %function
add_asm:
        add    r0, r0, r1      @ r0 = a + b (ARM 是三操作数)
        bx     lr
```

### 2. C 内嵌汇编（核心，本篇重点）

```c
int add_inline(int a, int b)
{
    int s;
    asm volatile (
        "mov %1, %0\n\t"        /* x86 两操作数：先 mov 再 add */
        "add %2, %0"
        : "=r" (s)              /* 输出：写一个寄存器 */
        : "r" (a), "r" (b)      /* 输入：各读一个寄存器 */
    );
    return s;
}
```

四种要素：`volatile`、模板字符串、操作数约束、clobber。下面逐个拆解。

### 3. 汇编调 C

```asm
        .global _start
_start:
        mov    $3, %edi          /* x86-64: 第一个参数 -> edi */
        mov    $5, %esi          /* 第二个参数 -> esi */
        call   c_add             /* 调 C 函数，返回值在 eax */
        ...
```

## 二、内联汇编四段式语法

### 完整形式

```c
asm [volatile] [goto] (
    "汇编模板"           // 指令字符串，%0/%[name] 是操作数占位符
    : 输出操作数         // 逗号分隔，"=r"(x) 或 [name]"=r"(x)
    : 输入操作数         // 逗号分隔，"r"(a) 或 [name]"r"(a)
    : clobber 列表       // "memory"/"cc"/寄存器名
    : 标签列表           // 仅 asm goto，放 C 标签名
);
```

### basic asm vs extended asm

| 特性 | basic asm `asm("...")` | extended asm `asm("..." : ...)` |
|------|----------------------|--------------------------------|
| 操作数段 | 无（没有 `:`） | 有（至少一个 `:`） |
| `%` 的含义 | **字面量**（直接输出 `%`） | **操作数引用**（`%0`/`%[name]`），字面 `%` 要写 `%%` |
| 能引用 C 变量 | 不能 | 能（通过约束绑定） |
| 典型用途 | 单条无副作用的裸指令 | 与 C 变量交互、有输入输出 |

> **坑**：basic asm 里写 `.ascii "%"` 会把 `%` 字节注入 `.text` 段 → 运行时 `Illegal instruction`。basic asm 应只用于无害指令（如 `nop`）。

### 命名约束 `%[name]` vs 位置约束 `%0`

```c
/* 位置约束：%0=out, %1=a, %2=b — 顺序敏感 */
asm volatile ("mov %1, %0\n\tadd %2, %0"
    : "=r"(s) : "r"(a), "r"(b));

/* 命名约束： %[sum] %[x] %[y] — 重排操作数不用改模板 */
asm volatile ("mov %[x], %[sum]\n\tadd %[y], %[sum]"
    : [sum]"=r"(s) : [x]"r"(a), [y]"r"(b));
```

命名约束更稳健（加/删/重排操作数不影响模板），内核新代码倾向用命名。**混用位置和命名约束**在文档里说"不允许"，但实测 gcc 13.3 / clang 18.1 **都不报错**（静默通过，行为未定义）——不要依赖这个"宽容"。

## 三、操作数约束矩阵

约束是内联汇编的核心——它告诉 gcc/clang"这个操作数放在哪里"。

### 输出约束（`=` / `+`）

| 约束 | 含义 | 模板里 | 典型场景 |
|------|------|--------|----------|
| `=r` | 只写寄存器 | 写 `%0` | 计算结果放寄存器 |
| `=m` | 只写内存 | 写 `%0`（生成 store） | 强制写回特定地址 |
| `+r` | 读写寄存器 | 读旧值 + 写新值 | `add $5, %0`（原地修改） |
| `+m` | 读写内存 | 读旧值 + 写新值 | 原子操作的目标 |
| `=&r` | earlyclobber 只写 | 写 `%0`（见下节 `&`） | 输出在输入消费完之前就写 |

> **bug**：用 `=r` 但模板里**也读** `%0` 的旧值 → gcc 以为 `%0` 是只写，可能把它和某个输入别名到同一寄存器 → 输入被覆盖。正确写法是 `+r`（告诉 gcc 这个操作数既读又写）。

### 输入约束

| 约束 | 含义 | gcc 行为 |
|------|------|----------|
| `r` | 任意通用寄存器 | gcc 选一个空闲寄存器 |
| `m` | 内存操作数 | 生成 load（地址在栈/全局） |
| `i` | 立即数常量（编译期已知） | 值烘焙进指令 |
| `n` | 立即数（某些架构限制大小） | 同 `i`（x86 上等价） |
| `g` | 通用（reg 或 mem 或 imm） | 最宽松 |
| `0`–`9` | 绑定到另一个操作数（同约束） | 输入与输出用同一寄存器 |
| `D` | x86 的 `di`/`edi`/`rdi` | 强制放 `di` 系列寄存器 |
| `a`/`b`/`c`/`d` | x86 的 `ax`/`bx`/`cx`/`dx` | 强制特定寄存器 |

> **gcc vs clang 差异**：clang 18 **不接受** `"0"` 绑定约束配 `"+r"`（报 `invalid input constraint '0' in asm`），gcc 接受。`+r` 本身已携带读写，`"0"` 绑定是冗余的——避开即可。

### 修饰符

| 修饰符 | 位置 | 含义 |
|--------|------|------|
| `&` | 约束字母前（`=&r`） | earlyclobber：输出在所有输入消费完之前就写，不能与输入别名 |
| `%` | 约束字母前（`"%r"`） | commutative：此操作数与下一个可交换，给寄存器分配器更多自由 |
| `!` | 约束字母前 | 偏好内存操作数 |

## 四、earlyclobber `&`——最容易 corrupt 的约束

### 问题场景

```c
/* BUG: 没有 & */
int bug_no_amp(int a, int b) {
    int out;
    asm volatile (
        "mov %2, %0\n\t"    /* 先写 out = b（early!）*/
        "add %1, %0"        /* 再 out += a */
        : "=r"(out)         /* gcc 以为 out 只写，可能和 a 别名 */
        : "r"(a), "r"(b)
    );
    return out;
}
```

如果 gcc 把 `out` 和 `a` 分配到同一个寄存器（比如 `eax`），那么 `mov %2,%0`（`mov b, eax`）会把 `a` 的值覆盖掉，后续 `add %1,%0`（`add eax, eax`）读到的 `a` 已经是 `b` 了 → 结果变成 `2*b` 而不是 `a+b`。

### 实测反汇编（gcc -O0 -fno-inline）

```
--- bug_no_amp (=r, 可能别名) ---
  mov -0x14(%rbp),%eax     ; eax = a  (操作数 %1 = a -> eax)
  mov -0x18(%rbp),%edx     ; edx = b  (操作数 %2 = b -> edx)
  mov %edx,%eax            ; asm: mov %2,%0 -> out = b  (eax 被覆盖！a 没了)
  add %eax,%eax            ; asm: add %1,%0 -> out += a... 但 %1 也是 eax
                           ; 结果 = 2*b = 10 (应为 8)

--- fix_amp (=&r, 保证不别名) ---
  mov -0x14(%rbp),%edx     ; edx = a
  mov -0x18(%rbp),%ecx     ; ecx = b
  mov %ecx,%eax            ; asm: mov %2,%0 -> out = b  (eax)
  add %edx,%eax            ; asm: add %1,%0 -> out += a (edx，没被破坏)
                           ; 结果 = a+b = 8 ✓
```

`=&r` 让 gcc 给输出分配一个**不与任何输入重合**的寄存器。

### -O0 vs -O2 的不可预测性

| 编译 | `bug_no_amp(3,5)` 结果 | 原因 |
|------|----------------------|------|
| gcc -O0 | 10（错） | a 放在 eax，被 asm 覆盖 |
| gcc -O2 | 8（对，巧合） | -O2 的寄存器分配把 a 放在别的寄存器，eax 没冲突 |
| clang -O2 | 8（对，巧合） | 同上 |

> **教训**：漏 `&` 在 -O0 下会出错，在 -O2 下**可能**恰好不出错。**只在 -O0 测试过的内联汇编 = 没测。** 内核永远 -O2，但你的 -O2 测试通过不代表所有代码上下文都安全——换个调用点，寄存器分配变了，bug 可能就冒出来。

## 五、clobber 列表

clobber 告诉编译器"这段 asm 会弄脏这些东西，超出输出操作数的范围"。

| clobber | 含义 | x86 上 |
|---------|------|--------|
| `"memory"` | asm 读写了你无法追踪的内存 | 强制重载所有 live 内存（编译器屏障） |
| `"cc"` | 条件标志被改 | x86 的 EFLAGS；ARM 的 NZCV |
| `"rax"`/`"rbx"`/... | 特定寄存器被破坏 | 必须声明，否则 gcc 可能把重要变量放在那里 |

### 漏 clobber 的后果——实测

```c
/* demo_bug: asm 用了 eax 当 scratch，没声明 "rax" clobber */
int demo_bug(int a, int b) {
    int x = a;
    asm volatile (
        "movl %2, %%eax\n\t"   /* eax = b  (clobbers eax!) */
        "addl %1, %%eax\n\t"   /* eax += a */
        "movl %%eax, %0"       /* x = eax */
        : "=r"(x)
        : "r"(a), "r"(b)
        /* 缺少 "rax" */
    );
    return x;
}
```

| 编译器 | -O 级别 | `demo_bug(3,5)` 结果 | 原因 |
|--------|---------|---------------------|------|
| gcc 13.3 | -O2 | **8**（对，巧合） | gcc 把 `a` 放在 `esi`，eax 被破坏不影响 |
| clang 18.1 | -O2 | **10**（**错！**） | clang 把 `a` 放在 `eax`（`mov $0x3,%eax`），asm 的 `movl %2,%%eax` 把 a 覆盖成 b=5，后续 `addl %1,%%eax` 读到的 a 已经是 5 → 5+5=10 |

**同一份代码，gcc 返回 8，clang 返回 10。** 这就是漏 clobber 的本质——**后果取决于编译器的寄存器分配，而你无法控制**。

### `-O0` vs `-O2` 对 clobber 的影响

| -O 级别 | 变量存放 | 漏 clobber 的后果 |
|---------|---------|-------------------|
| -O0 | 全在栈上（每次用都从栈加载到临时寄存器） | 通常**不触发**（变量不在寄存器里跨 asm 存活） |
| -O2 | 可能留在寄存器里跨语句存活 | **直接破坏**寄存器里的值 |

> **教训**：-O0 测试通过的内联汇编**不能**证明 clobber 声明正确。必须用 -O2 测。

## 六、`volatile` 的真正语义——最大的误解

### 三个"不是"

| 误解 | 真相 |
|------|------|
| `volatile` 是 CPU 内存屏障 | ❌ 它不生成任何 fence 指令。CPU 屏障要 `mfence`/`dmb`/`sfence` |
| `volatile` 禁止编译器重排所有代码 | ❌ 它只禁止把 asm **跨跳转**移动；不阻止其他语句的常规重排 |
| 不写 `volatile` 的 asm 一定被删 | ❌ 只在"输出未被使用 **且** 无副作用"时才删 |

### `volatile` 做什么

1. **不删除**：即使 asm 的输出没被使用，也保留这段 asm。
2. **不跨跳转移动**：不能把 asm 移到 jump 的另一侧（影响控制流分析）。

### 实测：`-O2` 下的差异

```c
/* dead_asm: 没有 volatile, 输出 unused */
static int dead_asm(int a) {
    int unused;
    asm ("mov %1, %0" : "=r"(unused) : "r"(a));   /* 无 volatile */
    return a;   /* unused 没用 */
}

/* kept_asm: 有 volatile, 输出 unused */
static int kept_asm(int a) {
    int unused;
    asm volatile ("mov %1, %0" : "=r"(unused) : "r"(a));
    return a;
}
```

gcc -O2 反汇编：

```
--- dead_asm (无 volatile, 输出未用) ---
  mov %edi,%eax    ; 直接 return a，asm 被完全删除！
  ret

--- kept_asm (有 volatile, 输出未用) ---
  mov %edi,%eax    ; eax = a (return value)
  mov %edi,%edx    ; asm 保留了！(mov %1,%0 翻译成 mov edi, edx)
  ret
```

**dead_asm 的 asm 被完全删除**（只剩 `return a`）；**kept_asm 的 asm 被保留**（多了一条 `mov`）。这就是 `volatile` 的核心作用。

### 内核的 `barrier()` 是什么

```c
#define barrier() asm volatile("" ::: "memory")
```

| 要素 | 作用 |
|------|------|
| `""`（空模板） | 不生成任何指令 |
| `volatile` | 保留这个空 asm（不被删） |
| `"memory"` clobber | 告诉 gcc "我读写了你不知道的内存" → 重载所有 live 内存变量 |

三者合起来 = **编译器屏障**（compiler barrier）：不生成指令，但阻止 gcc 把内存读写跨越这个点重排。**注意：这不是 CPU 屏障**——CPU 仍然可能乱序执行。要 CPU 屏障得加 `mfence`/`dmb`。

## 七、ARM vs x86 指令语法差异

在 x86-64 上实测 ARM 汇编时最容易踩的坑：

| 差异点 | ARM (A32/A64) | x86-64 (AT&T) |
|--------|---------------|---------------|
| `add` 操作数数量 | **三操作数** `add dst, src1, src2` | **两操作数** `add src, dst`（dst += src） |
| `mov` 操作数 | `mov dst, src` | `mov src, dst`（AT&T 顺序：源在前，目的在后） |
| 寄存器名 | `r0`/`x0`/`w0` | `%rax`/`%edi`/... |
| 立即数前缀 | `#` | `$` |
| 注释 | `@` | `#`（GNU as）/ `//` |
| 条件执行 | `addeq`/`addne`（后缀） | `jz`/`jnz`（单独跳转指令） |

> **实测翻车**：在 x86 上写 `add %0, %1, %2`（ARM 三操作数语法）→ GNU as 不报错，但生成的机器码是非法的 → 运行时 `Illegal instruction (core dumped)`。跨平台内联汇编必须注意操作数数量。x86 要用 `mov %1, %0; add %2, %0` 模拟 ARM 的一条 `add`。

## 八、ABI 对照——x86-64 SysV vs ARM AAPCS

### x86-64 System V ABI（Linux/macOS 通用）

| 角色 | 寄存器 | 说明 |
|------|--------|------|
| 整型参数（前 6 个） | `rdi, rsi, rdx, rcx, r8, r9` | 多余的入栈（右往左压） |
| 返回值 | `rax`（+ `rdx` 给 128 位） | `__int128` 用 `rdx:rax` |
| 浮点参数（前 8 个） | `xmm0`–`xmm7` | — |
| callee-saved | `rbx, rbp, r12, r13, r14, r15` | 被调函数必须保存 |
| caller-saved | `rax, rcx, rdx, rsi, rdi, r8-r11` | 调用者负责 |
| 栈对齐 | 调用前 16 字节对齐 | `call` 压入 8 字节返回地址后变成 `8 mod 16` |
| red zone | `rsp` 下方 128 字节 | 叶子函数可免 reservation（-O2） |

### ARM AAPCS（A32 / AArch64）

| 角色 | A32 | AArch64 |
|------|------|---------|
| 整型参数（前 4/8 个） | `r0-r3` | `x0-x7` |
| 返回值 | `r0` | `x0` |
| callee-saved | `r4-r11` | `x19-x29` |
| 栈指针 | `r13 (sp)`，满递减 | `sp`，16 字节对齐 |
| 返回地址 | `r14 (lr)` | `x30 (lr)` |

> ARM 部分标注"未实测"——本机无 aarch64 交叉工具链。

## 九、约束写错的后果分层

编译器无法检查你的汇编模板和约束是否匹配。写错的后果分三个层次，**越往后越危险**：

| 层次 | 触发时机 | 表现 | 示例 |
|------|---------|------|------|
| 编译期错误 | 汇编阶段（`-c`） | `as` 报 error | `movl` 配 64 位操作数 → `incorrect register '%rdx' used with 'l' suffix` |
| 运行时数据错误 | 程序运行 | 值不对但不崩 | `movl` 搬 32 位 → `0x100000005` 变成 `0x5`（高 32 位丢） |
| 静默 corrupt | 程序运行 | 垃圾值/UB | `=r` 但模板不写 → 输出是栈上残留（gcc 恰好 7，clang 是 92846224） |

> **坑**：`-fsyntax-only` **不检查** asm 约束的合法性（它只做语法分析，跳过汇编生成阶段）。要用 `-c`（编译到目标文件）才能抓到约束错误。

### gcc vs clang 对约束错误的差异

| 错误类型 | gcc | clang |
|----------|-----|-------|
| `movl` + 64 位操作数 | `Error: incorrect register '%rdx' used with 'l' suffix` | `error: invalid operand for instruction` + `movl %rax, %rax` |
| `"i"` + 运行时变量 | 汇编阶段 error | 汇编阶段 error |
| `=r` 不写但输出未用 | 不报（asm 可能被删） | 不报 |
| 输出垃圾值 | 恰好是 7（栈残留巧合） | 92846224（真垃圾） |

## 十、`asm goto`——从汇编跳到 C 标签

```c
asm goto (
    "bt $0, %%rax\n\t"      /* 测试 rax 的 bit 0 */
    "jc %l[yes]"            /* 如果 set，跳到 C 标签 yes */
    :: "a"(1)               /* 输入：rax = 1 */
    : "cc"                  /* clobber: 条件标志 */
    : yes                    /* 标签列表 */
);
/* fallthrough: bit 未 set */
return 0;
yes:
return 1;
```

实测反汇编（gcc -O0 -fno-inline）：

```
  mov $0x1,%eax            ; 输入 a(1)=1
  bt  $0x0,%rax            ; 测试 bit 0
  jb  27 <try_feature+0x27>; 条件跳转到 yes 标签
  ; fallthrough path
  movl $0x0,-0x4(%rbp)
  ...
27:
  movl $0x1,-0x4(%rbp)
  ...
```

| 要素 | 说明 |
|------|------|
| 第 5 段（`:` 后） | 放 C 标签名，`%l[label]` 在模板里引用 |
| 无输出操作数 | 经典形式（gcc 4.5+）不允许输出 |
| 带输出 | gcc 14+ / clang 18+ 才支持 |
| 典型用途 | 锁获取重试、特性检测的条件分支 |

## 十一、内核实例实测

### barrier / rmb / wmb / mb

```c
#define barrier() asm volatile("" ::: "memory")
static inline void mb(void)  { asm volatile("mfence" ::: "memory"); }
static inline void rmb(void) { asm volatile("lfence" ::: "memory"); }
static inline void wmb(void) { asm volatile("sfence" ::: "memory"); }
```

| 宏 | 生成的指令 | 作用 |
|----|----------|------|
| `barrier()` | 无指令（空 asm） | 编译器屏障（阻止 gcc 重排） |
| `mb()` | `mfence` | CPU 全屏障（读+写） |
| `rmb()` | `lfence` | CPU 读屏障 |
| `wmb()` | `sfence` | CPU 写屏障 |

### rdtsc

```c
static inline uint64_t rdtsc(void) {
    unsigned lo, hi;
    asm volatile("rdtsc" : "=a"(lo), "=d"(hi));
    return ((uint64_t)hi << 32) | lo;
}
```

`rdtsc` 把时间戳计数器的低 32 位放 `eax`、高 32 位放 `edx`。约束 `=a`/`=d` 强制输出到这两个寄存器。

### xchg / cmpxchg（原子操作）

```c
static inline long xchg(volatile long *p, long v) {
    long out;
    asm volatile("xchg %0, %1"
        : "=r"(out), "+m"(*p) : "0"(v) : "memory");
    return out;
}

static inline int cmpxchg(volatile int *p, int old, int new) {
    int cur;
    asm volatile("lock cmpxchg %2, %1\n\tmov %3, %0"
        : "=r"(cur) : "m"(*p), "r"(new), "a"(old)
        : "cc", "memory");
    return cur == old;
}
```

实测反汇编确认：`xchg` 生成 `xchg` 指令（隐含 lock 前缀，x86 上是全屏障）；`cmpxchg` 生成 `lock cmpxchg %ecx,(%rdx)`（`f0 0f b1 0a`）。

### cpuid

```c
asm volatile("cpuid"
    : "=a"(*eax), "=b"(*ebx), "=c"(*ecx), "=d"(*edx)
    : "a"(0));
```

实测输出：`max_leaf=28 vendor=GenuineIntel`（Intel CPU）。`cpuid` 用 `eax` 作输入（leaf 号），`eax/ebx/ecx/edx` 作输出。约束 `"=b"` 强制输出到 `rbx`——在 PIC 代码里 `rbx` 是保留的，需要 `-fno-pie`。

## 十二、.S 文件调 C

```asm
/* t12_asm_calls_c.S — 大写 .S 会跑预处理 */
        .text
        .globl asm_call_c
        .type  asm_call_c, @function
asm_call_c:
        mov %edi, %eax     ; 保存 a
        mov %esi, %ecx     ; 保存 b
        mov %ecx, %edi     ; 第一个参数 = b (交换)
        mov %eax, %esi     ; 第二个参数 = a
        call c_add          ; 调 C 函数, 返回值在 eax
        ret
```

实测反汇编确认：`call 401170 <c_add>` 成功链接到 C 函数。

> **坑**：.S 文件缺 `.note.GNU-stack` section → 链接器 warning `implies executable stack`。在 .S 里加 `.section .note.GNU-stack,"",@progbits` 消除。Linux 内核的所有 .S 文件都有这行。

## 十三、HFT / 嵌入式关联

| 场景 | 用到的内联汇编 | 为什么 |
|------|---------------|--------|
| 内存序保证 | `mfence`/`lfence`/`sfence` + `volatile` + `"memory"` | HFT 要求精确控制读写顺序，编译器屏障不够，还要 CPU 屏障 |
| 原子操作 | `lock cmpxchg`/`xchg` | 无锁数据结构（ring buffer、MPSC 队列） |
| 时间戳 | `rdtsc`/`rdtscp` | 延迟测量（纳秒级），`rdtscp` 是 serializing 版本 |
| CPU 特性检测 | `cpuid` | 运行时探测 SIMD 指令集（AVX2/AVX-512） |
| 自旋锁 | `asm goto` + `lock cmpxchg` | 获取失败跳到重试标签，避免函数调用开销 |
| 编译器屏障 | `barrier()` | 阻止 gcc 把关键路径的内存读写重排（配合 `READ_ONCE`/`WRITE_ONCE`） |
| 裸机/内核启动 | `.S` 调 `main` | SP 初始化、BSS 清零后 `bl main`/`call main` |
| volatile MMIO | `volatile` 指针 + `barrier()` | 寄存器读写不能被 gcc 优化掉或重排 |

> **HFT 最重要的教训**：如果你关了日志但还慢——检查你的日志宏是不是只关了打印、没关参数求值。`if (log_level >= level) printk(fmt, args)` 在 log_level 不够时**仍会求值 args**（`compute_expensive_thing()` 照跑）。正确写法用 `__builtin_constant_p` 或宏在编译期裁掉整个调用链（见 [6.12 变参宏](../../01-ch1-gnu-c-basics/6.12-vararg-macro/6.12-可变参数宏.md) 的零开销日志）。

## 误区表

| 误区 | 真相 | 实测证据 |
|------|------|----------|
| `volatile` 是 CPU 内存屏障 | ❌ 不生成 fence 指令 | `barrier()` 反汇编只有 `push/mov/ret`，无 fence |
| 不写 `volatile` 的 asm 一定被删 | ❌ 只在"输出未用 且 无副作用"时删 | `dead_asm` 被删，`kept_asm` 保留 |
| `-O0` 测过就行 | ❌ -O0 变量在栈上，漏 clobber 不触发 | `demo_bug` -O0 返回 8（对），-O2 clang 返回 10（错） |
| gcc 过了 clang 就过 | ❌ 两者寄存器分配不同 | `demo_bug` gcc-8 clang-10；`bad_nowrite` gcc=7 clang=92846224 |
| 约束写错一定编译报错 | ❌ 只有大小不匹配报错；`=r` 不写是静默垃圾 | `bad_nowrite` 编译通过，返回垃圾值 |
| `-fsyntax-only` 能查 asm | ❌ 跳过汇编生成阶段 | DEMO_BAD 用 `-fsyntax-only` 不报错，用 `-c` 才报 |
| ARM 三操作数 add 在 x86 也能跑 | ❌ 生成非法指令 | `add %0,%1,%2` → `Illegal instruction` |
| `"0"` 绑定约束两编译器都支持 | ❌ clang 不接受配 `+r` | clang 报 `invalid input constraint '0'` |

## 代码自测

**题目 1：** 内联汇编的 `volatile` 关键字的作用是什么？它和 C 语言的 `volatile` 限定符是同一个东西吗？

<details>
<summary>参考答案</summary>

不是同一个东西。

- **C 语言的 `volatile` 限定符**（`volatile int *p`）：告诉编译器"这个变量可能被外部修改，每次访问都要真正读写内存，不要缓存到寄存器"。用于 MMIO、信号处理、`setjmp`/`longjmp`。

- **内联汇编的 `asm volatile`**：告诉编译器"这段汇编有副作用，不要删除它（即使输出未使用），不要跨跳转移动它"。它不生成任何 fence 指令，不是 CPU 内存屏障。

两者完全独立：C 的 `volatile` 管变量访问，asm 的 `volatile` 管汇编块的存留。

</details>

**题目 2：** 以下代码有什么 bug？在什么条件下会出错？

```c
int bad(int a, int b) {
    int out;
    asm volatile (
        "mov %2, %0\n\t"
        "add %1, %0"
        : "=r"(out)
        : "r"(a), "r"(b)
    );
    return out;
}
```

<details>
<summary>参考答案</summary>

**漏了 earlyclobber `&`。** `=r` 让 gcc 可以把 `out` 和某个输入（比如 `a`）分配到同一个寄存器。`mov %2,%0` 先把 `out` 写成 `b`，如果 `out` 和 `a` 共用寄存器，`a` 的值就被覆盖了，后续 `add %1,%0` 读到的 `a` 已经是 `b` 了 → 结果变成 `2*b` 而不是 `a+b`。

- **触发条件**：gcc 恰好把 `out` 和 `a` 分配到同一个寄存器（取决于代码上下文和 -O 级别）。
- **-O0**：变量在栈上，可能触发（实测返回 `2*b`）。
- **-O2**：可能恰好不触发（gcc 选了不同寄存器）。
- **修复**：`"=&r"(out)`，强制输出寄存器不与任何输入别名。

</details>

**题目 3：** `barrier()` 宏（`asm volatile("" ::: "memory")`）生成的指令是什么？它和 `mfence` 有什么区别？

<details>
<summary>参考答案</summary>

- **生成的指令**：无（空模板 `""` 不产生任何机器码）。
- **作用**：编译器屏障——告诉 gcc"我读写了你不知道的内存"（`"memory"` clobber），强制 gcc 在这个点之后重新加载所有可能被修改的内存变量，阻止 gcc 把内存读写跨越这个点重排。
- **与 `mfence` 的区别**：
  - `barrier()` 是**编译器**屏障——只管 gcc 的指令调度，CPU 仍可能乱序执行。
  - `mfence` 是 **CPU** 屏障——在 CPU 流水线里插入栅栏，阻止 CPU 乱序。
  - 要同时阻止两者，得 `barrier()` + `mfence`（或内核的 `mb()` = `asm volatile("mfence" ::: "memory")` 两者合一）。

</details>

**题目 4：** 以下代码在 gcc -O2 和 clang -O2 下行为不同，为什么？

```c
int demo_bug(int a, int b) {
    int x = a;
    asm volatile (
        "movl %2, %%eax\n\t"
        "addl %1, %%eax\n\t"
        "movl %%eax, %0"
        : "=r"(x)
        : "r"(a), "r"(b)
        /* 缺少 "rax" clobber */
    );
    return x;
}
```

<details>
<summary>参考答案</summary>

**漏了 `"rax"` clobber。** asm 用 `%%eax` 作为 scratch 寄存器，但没告诉 gcc `eax` 会被破坏。

- **gcc -O2**：把 `a` 分配到 `esi`（不在 `eax`）→ `eax` 被破坏不影响 `a` → 返回 8（正确，巧合）。
- **clang -O2**：把 `a` 分配到 `eax`（`mov $0x3,%eax`）→ asm 的 `movl %2,%%eax` 把 `a` 覆盖成 `b=5` → `addl %1,%%eax` 读到的 `a` 已经是 5 → 返回 10（错误）。

**根本原因**：漏 clobber 的后果取决于编译器的寄存器分配策略，而你无法控制。修复：加 `"rax"` 到 clobber 列表。

</details>

**题目 5：** 以下两段代码在 -O2 下生成的汇编有什么区别？

```c
/* A: 无 volatile */
asm ("mov %1, %0" : "=r"(unused) : "r"(a));

/* B: 有 volatile */
asm volatile ("mov %1, %0" : "=r"(unused) : "r"(a));
```

<details>
<summary>参考答案</summary>

（假设 `unused` 在后续代码中没有被使用）

- **A（无 volatile）**：gcc 判定 asm 的输出 `unused` 未被使用且无副作用 → **删除整个 asm**。反汇编只剩 `return a`（`mov %edi,%eax; ret`）。
- **B（有 volatile）**：gcc 保留 asm。反汇编多一条 `mov %edi,%edx`（asm 的 `mov %1,%0` 翻译）。

`volatile` 的核心作用就是"不要删我"。

</details>
