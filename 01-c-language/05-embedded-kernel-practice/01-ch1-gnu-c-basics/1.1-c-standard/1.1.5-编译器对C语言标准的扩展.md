# 1.1.5 编译器对C语言标准的扩展

> 完整总纲与实测数据见 [1.1 C 语言标准、编译器与 gnu11 方言](1.1-C语言标准和编译器.md)。

## 本节讲什么

**GNU C 扩展** 是 GCC（及兼容前端）在 ISO C 之外提供的语法与语义，Linux 内核、U-Boot、Glibc、DPDK 深度依赖。本章 **1.2–1.7** 逐项展开；此处给出总览地图。

## 要点

### 本章覆盖的主要扩展

| 类别 | 示例 | 小节 |
|------|------|------|
| **属性** | `packed` `aligned` `section` `weak` `format` | 2.1–2.4 |
| **语句表达式** | `({ int x=1; x+1; })` | 1.3 |
| **typeof** | `typeof(*ptr) tmp` | 1.4 |
| **零长度数组** | `char buf[0]` | 1.5 |
| **指定初始化** | `[3]=1` `.name=` | 1.2 |
| **内联控制** | `inline` `always_inline` `noinline` | 1.6 |
| **内建函数** | `__builtin_expect` | 2.5 |
| **可变参数宏** | `#define LOG(fmt, ...) ... ##__VA_ARGS__` | 1.7 |

### 其他常见扩展（全书 scattered）

```c
__extension__ ({ ... })              /* 在 -pedantic 下压制扩展警告 */
__asm__ volatile ("mrs %0, cpsr" : "=r"(cpsr))
__attribute__((constructor)) void init(void) { }
__attribute__((noreturn)) void die(void);
__attribute__((deprecated("use foo2"))) void foo(void);
__attribute__((unused)) static int placeholder;
```

- **`__builtin_constant_p(n)`**：编译期常量分支（**2.5.4**）
- **Case range** `case 1 ... 5:`：GNU 扩展，内核 switch 常见
- **Compound literal** `(struct foo){ .x = 1 }`：C99 标准，GNU 早支持

> ⚠️ **上表里的东西不是「都得切 `gnuXX` 才能用」。** 三类必须分清楚（完整实测与官方原文见
> [1.1 §网传说法逐条勘误](1.1-C语言标准和编译器.md)）：
>
> | 类别 | 例子 | `-std=cXX` 下 | `-pedantic-errors` 下 |
> |---|---|---|---|
> | **双下划线形态**（保留标识符） | `__attribute__` `__typeof__` `__asm__` `__builtin_*` | ✅ 可用 | ✅ **仍然可用** |
> | **裸关键字形态** | `asm` `typeof` `inline` | ❌ 不可用 | ❌ |
> | **非 ISO 但语法合法** | 零长数组、`case 1 ... 5`、语句表达式 | ✅ 可用（无诊断） | ❌ 报错 |
>
> 「用了扩展就一定要 `-std=gnuXX`」是过度反应——只有第二类才真的需要 GNU 方言。

```bash
# 列出常见内建
gcc -dM -E - < /dev/null | grep __builtin | head
```

### 内核/DPDK 视角

- 内核 `include/linux/compiler_attributes.h` 封装 `__attribute__`
- DPDK `rte_branch_prediction.h`：`likely`/`unlikely` → `__builtin_expect`
- 写可移植用户态库：扩展放 **internal header**，对外 API 用标准 C

## 代码自测

**题目 1：** GCC 扩展和标准 C 的关系是什么？使用扩展有什么风险？
<details>
<summary>参考答案</summary>

GCC 扩展 = GCC 在标准 C 之外添加的语法和功能。

常见扩展：`__attribute__`、`typeof`、语句表达式、零长数组、`__builtin_*`、内联汇编、case 范围 `case 1 ... 5:`。

风险：
1. **不可移植**：换编译器（MSVC/ICC）可能编译失败
2. **标准进化覆盖**：某些扩展后来被标准采纳（如 `_Static_assert` 替代 `BUILD_BUG_ON`）
3. **版本依赖**：不同 GCC 版本扩展行为可能不同

好处：
- 精确控制代码生成（段/对齐/内联）
- 实现标准 C 无法表达的功能（container_of/typeof）
- 性能优化（__builtin_expect/ prefetch）

建议：应用层代码尽量用标准 C；底层/内核代码大胆用扩展。

</details>
