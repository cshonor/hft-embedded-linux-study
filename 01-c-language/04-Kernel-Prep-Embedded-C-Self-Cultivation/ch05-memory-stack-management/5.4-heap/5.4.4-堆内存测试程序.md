## 本节讲什么

通过 **循环 malloc/free**、不等长块、多线程（拓展）观察 **堆增长、碎片、峰值 RSS**；配合 `size`、`/proc`、Valgrind 量化行为。

## 要点

### 测试思路

```c
/* 碎片：交替分配大小块再释放一半 */
for (int i = 0; i < N; i++) ptr[i] = malloc(i % 2 ? 64 : 1024);
for (int i = 0; i < N; i += 2) free(ptr[i]);
```

```bash
gcc -g -O0 -o heap_test heap_test.c
/usr/bin/time -v ./heap_test          # Max RSS
size heap_test

```

## 代码自测

**题目 1：** 以下代码存在什么问题？如何检测？
```c
int main(void) {
    int *p = malloc(sizeof(int));
    *p = 42;
    // 忘记 free(p)
    return 0;
}
```
<details>
<summary>参考答案</summary>

**内存泄漏**：`malloc` 分配的内存没有 `free`，程序退出前丢失了指针，无法释放。

单次泄漏在进程退出时由 OS 回收（所有映射被清除）。但在长期运行的服务程序中，反复泄漏会导致内存耗尽。

检测工具：
1. **Valgrind**：`valgrind --leak-check=full ./a.out`，精确报告泄漏位置
2. **AddressSanitizer**：`gcc -fsanitize=address -g`，编译时插桩，运行时检测
3. **mtrace**：glibc 内置，设置 `MALLOC_TRACE` 环境变量
4. **/proc/PID/status**：监控 VmRSS（物理内存使用）增长趋势

修复：`free(p);` 在使用完毕后立即释放。

</details>
