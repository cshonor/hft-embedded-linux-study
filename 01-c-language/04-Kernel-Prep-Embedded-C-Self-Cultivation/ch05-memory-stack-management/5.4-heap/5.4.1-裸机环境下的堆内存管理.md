# 5.4.1 裸机环境下的堆内存管理

## 本节讲什么

无 OS 时没有 `sbrk`/`mmap`，堆是链接脚本划出的 **`.heap` 区间**（或 `_end` 到 RAM 顶）。分配器在 **固定物理/虚拟地址** 上维护空闲链表；与 **5.2 Linux MMU** 对比：裸机常 **无保护**，越界直接踩硬件。

## 要点

### 典型布局

```
Flash: .text .rodata
RAM:   .data .bss → heap → stack（相向生长，中间留 guard）
```

- 链接脚本：`__heap_start` / `__heap_end`；`_sbrk` 在 `__heap_start` 上 bump
- **newlib** `_sbrk`：向链接器符号要下一字节

```c
extern char __heap_start;
static char *heap_ptr = &__heap_start;
void *_sbrk(int incr) { char *prev = heap_ptr; heap_ptr += incr; return prev; }
```

### 简单 first-fit

- 空闲块头：`size + next` 指针；`malloc` 遍历分割，`free` 合并相邻
- **碎片**：频繁不等长 alloc/free 产生外碎片
- **嵌入式**：常改用 **固定块内存池**（网络 mbuf、DMA 缓冲区）

### 与 Linux

| 裸机 | Linux |
|------|-------|
| 物理地址固定 | VMA + 页对齐 |
| 无 double-free 检测 | glibc 可能 abort |
| 堆栈相撞 → 静默损坏 | 通常 SIGSEGV |

## 与后续衔接

- **5.4.5** 自研堆管理器算法
- **ch04 4.14** 链接脚本 RAM 划分
- **DPDK** `rte_malloc` 基于 hugepage 池，思路类似静态池

## 代码自测

**题目 1：** 裸机环境下如何实现简单的堆内存管理？以下代码有什么问题？
```c
static unsigned char heap[4096];
static int offset = 0;
void *my_malloc(int size) {
    void *p = &heap[offset];
    offset += size;
    return p;
}
```
<details>
<summary>参考答案</summary>

这是一个"分配不释放"的简单堆（bump allocator）。

问题：
1. **无法释放**：offset 只增不减，内存用完就没了
2. **无对齐**：size 可能不是 4/8 字节对齐，导致未对齐访问异常（ARM 上某些指令要求对齐）
3. **无边界检查**：offset 超过 4096 会越界
4. **碎片化**：即使能释放，频繁 alloc/free 会导致外部碎片

改进：
- 对齐：`offset = (offset + 3) & ~3;`（4 字节对齐）
- 边界检查：`if (offset + size > sizeof(heap)) return NULL;`
- 完整实现：空闲链表法（free list）或内存池法（memory pool）

嵌入式常用：TLSF、memkipool 等实时内存分配器。

</details>
