# 5.4.5 实现自己的堆管理器

## 本节讲什么

在 **固定字节数组** 上实现 **first-fit / best-fit** 空闲链表：`malloc` 分割块、`free` 合并相邻空闲块。理解 glibc chunk 的简化版，适合裸机、Bootloader、内核 early alloc。

## 要点

### 最小设计

```c
typedef struct block {
    size_t size;           /* 不含头 */
    int free;
    struct block *next;
} block_t;

static char heap[HEAP_SIZE];
static block_t *free_list;
```

- 对齐：8/16 字节；用户指针指向 **payload**，头在下方
- **合并**：`free` 时检查 `prev/next` 物理相邻且 free → 减碎片
- **realloc**：能原地扩大则扩，否则拷贝

### 必查错误

- 重复 `free`、释放非堆指针、越界写破坏 `size` 字段
- 用 **canary** 或 magic 校验块完整性

```bash
gcc -g -fsanitize=address -o myheap test_myheap.c myheap.c
./myheap
```

### 对比

| | 自研 | glibc |
|--|------|-------|
| 体积 | 可控 | 大 |
| 线程安全 | 需自加锁 | arena+mutex |
| 调试 | 简单 | mtrace/valgrind |

- **Linux 内核** slab 更复杂但思想类似：按对象大小分级缓存

## 代码自测

**题目 1：** 实现一个简单的空闲链表堆管理器，分配和释放的核心逻辑是什么？
```c
struct block {
    int size;
    struct block *next;  // 空闲链表
};
struct block *free_list = NULL;
```
<details>
<summary>参考答案</summary>

空闲链表法核心逻辑：

**分配**（malloc）：
1. 遍历 free_list 找到 size >= 请求大小的块
2. 若块远大于请求，分裂为两块（返回一块，剩余放回 free_list）
3. 从 free_list 移除该块，返回数据区指针

**释放**（free）：
1. 将释放的块加回 free_list
2. 检查相邻块是否空闲，合并（避免碎片）

关键问题：
- **合并**：free 时需检查前后块是否空闲，合并为大块
- **对齐**：每块大小需对齐到 8/16 字节
- **线程安全**：多线程需加锁或使用线程局部堆
- **元数据**：block header 存 size 和 next，如何找到 header？（free 传入的是数据指针，往前偏移 sizeof(struct block) 即 header）

Linux glibc 的 ptmalloc 用 bins（按大小分桶）+ 合并策略。

</details>
