# 5.3.5 栈与作用域

## 本节讲什么

**自动变量**（局部非 static）在函数每次调用时在 **栈** 上分配，离开作用域即失效。**静态局部** 存 **`.bss`/`.data`**，只初始化一次，生命周期贯穿整个程序——与 **ch04 BSS** 机制相同。

## 要点

### 存储类别对比

| 声明 | 存储位置 | 生命周期 |
|------|----------|----------|
| 局部 `int x` | 栈 | 函数调用期间 |
| `static int c`（函数内） | .bss/.data | 程序全程 |
| 全局 | .bss/.data | 程序全程 |

```bash
cd demo && make demo05_static && ./demo05_static
# static=1,2,3 累加；local 每次为 1
size demo05_static
nm demo05_static | grep counter
```

### demo05 行为

- `static int c`：第一次为 0，之后保留上次值
- `int local`：每次调用重新分配（值未定义除非赋值），打印恒为 1

### 嵌入式注意

- 大数组放栈 → **栈溢出**；改 `static`、全局或堆
- ISR 中避免大栈帧；RTOS 任务栈需按 **最坏调用深度** 估算
- **DPDK**：per-lcore 变量用 `RTE_PER_LCORE` 或 TLS，避免栈上大对象

```bash
readelf -S demo05_static | grep -E 'bss|data'
```

## 代码自测

**题目 1：** 以下代码有什么问题？返回局部变量地址的后果是什么？
```c
int *get_ptr(void) {
    int local = 42;
    return &local;
}
int main(void) {
    int *p = get_ptr();
    printf("%d\n", *p);
    return 0;
}
```
<details>
<summary>参考答案</summary>

**未定义行为**：返回局部变量的地址，函数返回后栈帧被销毁，该地址变为无效。

- `get_ptr()` 返回时，`local` 所在的栈空间被回收
- `*p` 访问已释放的栈内存，可能读到 42（碰巧没被覆盖），也可能读到垃圾值
- 若后续有其他函数调用，该栈空间被复用，`*p` 的值会被改变

正确做法：
- 传指针参数让 caller 分配：`void func(int *out) { *out = 42; }`
- 用 static：`static int local = 42; return &local;`（但非线程安全）
- 用 malloc：`int *p = malloc(sizeof(int)); *p = 42; return p;`

</details>
