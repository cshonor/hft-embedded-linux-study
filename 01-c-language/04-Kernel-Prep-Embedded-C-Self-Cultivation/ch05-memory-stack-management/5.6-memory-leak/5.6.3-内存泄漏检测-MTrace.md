# 5.6.3 内存泄漏检测：MTrace

## 本节讲什么

glibc **mtrace** 钩住 `malloc/free`，把分配记录写入日志，程序结束或 `muntrace()` 时输出 **未释放块** 及调用栈（需 `-rdynamic` 才有符号）。

## 要点

```c
#include <mcheck.h>
int main(void) {
    mtrace();          /* 或环境变量 MALLOC_TRACE=file */
    ...
    muntrace();
}
```

```bash
gcc -g -rdynamic -o leak leak.c
export MALLOC_TRACE=./mtrace.log
./leak
muntrace-leaks ./mtrace.log    # 部分发行版
# 或 mtrace ./leak $MALLOC_TRACE 解析
```

| 工具 | 特点 |
|------|------|
| mtrace | 轻量、glibc 专用、开销小 |
| Valgrind | 全面、慢 10–50x |
| ASAN leak | `-fsanitize=leak` |

- 生产环境常用 **抽样 + 离线分析**；开发期 Valgrind/ASAN
- **内核 kmemleak**：扫描未引用 kmalloc 块（需配置 `CONFIG_KMEMLEAK`）

## 代码自测

**题目 1：** mtrace 的工作原理是什么？如何使用？
```c
#include <mcheck.h>
int main(void) {
    mtrace();  // 开启跟踪
    char *p = malloc(100);
    // 忘记 free
    muntrace();
    return 0;
}
```
<details>
<summary>参考答案</summary>

mtrace 是 glibc 内置的内存泄漏检测工具。

原理：
- `mtrace()` 安装 malloc/free/realloc 的钩子函数
- 每次 malloc 时记录调用地址和大小
- 每次 free 时从记录中删除
- `muntrace()` 时输出未释放的记录到 `MALLOC_TRACE` 指定的文件

使用步骤：
1. 设置环境变量：`export MALLOC_TRACE=output.log`
2. 代码中调用 `mtrace()` / `muntrace()`
3. 运行程序
4. 分析：`mtrace a.out output.log`（mtrace 是 perl 脚本，将地址翻译为源码行号）

局限：只能检测通过 malloc 系列分配的内存，不支持 mmap；性能开销大；非实时（需程序正常退出才能报告）。

</details>
