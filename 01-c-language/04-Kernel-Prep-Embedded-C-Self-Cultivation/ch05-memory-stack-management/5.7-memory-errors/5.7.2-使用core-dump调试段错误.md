# 5.7.2 使用 core dump 调试段错误

## 本节讲什么

进程因 **SIGSEGV/SIGABRT** 等异常终止时，内核可写 **core 文件**（进程内存快照）。用 **GDB 加载可执行文件 + core** 在崩溃点 **bt**、查变量、反汇编。

## 要点

### 开启 core

```bash
ulimit -c unlimited
cat /proc/sys/kernel/core_pattern    # core 路径模板
# systemd: /var/lib/systemd/coredump/ 或当前目录 core

gcc -g -O0 -o crash crash.c
./crash                            # SIGSEGV
gdb ./crash core                   # 或 core.crash.PID
(gdb) bt
(gdb) bt full
(gdb) frame 0
(gdb) list
(gdb) info registers
(gdb) x/16wx $sp
```

### 无 core 时

```bash
gdb ./crash
(gdb) run
# 崩溃后直接 bt
(gdb) bt
```

### 技巧

- 发布版保留 **未 strip** 符号或单独 **debuginfo** 包
- **ARM 交叉**：`arm-linux-gnueabihf-gdb` + `set sysroot`
- 内核：**kdump/vmcore** + `crash` 工具，思路相同

| 信号 | 常见原因 |
|------|----------|
| SIGSEGV | 非法地址读写 |
| SIGABRT | assert、heap corruption |

## 代码自测

**题目 1：** 函数调用栈帧（stack frame）的结构是什么？
```c
void f(int a, int b) {
    int local = a + b;
}
```

<details>
<summary>参考答案</summary>

栈帧包含：1) 返回地址（调用方的下一条指令）；2) 旧的帧指针（RBP/FP）；3) 局部变量（local）；4) 保存的寄存器；5) 参数（如果不在寄存器中传递）。`SP` 指向栈顶，`FP` 指向当前帧基址。函数序言（prologue）建立帧，函数结语（epilogue）恢复帧。栈溢出：递归太深或局部变量太大。用 `-fomit-frame-pointer` 省略帧指针（多一个寄存器，但调试困难）。

</details>
