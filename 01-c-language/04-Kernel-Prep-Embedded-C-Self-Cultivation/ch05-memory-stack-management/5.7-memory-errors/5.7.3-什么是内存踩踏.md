# 5.7.3 什么是内存踩踏

## 本节讲什么

**内存踩踏（memory stomp）**：写入 **合法对象边界之外**，破坏相邻对象、堆 metadata、返回地址。读踩踏可能 SIGSEGV；写踩踏可能 **延迟崩溃**（corruption 后才 abort）。

## 要点

### 典型场景

```c
char buf[8];
strcpy(buf, "0123456789");     /* 越界写 */
int *p = malloc(16);
free(p);
*p = 1;                        /* use-after-free 写 */
free(p);                       /* double free */
```

- **堆**：覆盖相邻 chunk 的 `size` → `malloc` 后续崩溃
- **栈**：覆盖 saved LR（**5.3.6**）
- **数组下标**：`a[-1]`、`a[n]` 在循环 off-by-one

```bash
valgrind --tool=memcheck ./prog
# Invalid write of size 1 at 0x...
gcc -fsanitize=address -g -O0 -o prog prog.c
```

### 内核

- **buffer overrun** in `copy_from_user` 长度检查不严
- **SLUB RED_ZONE** / `CONFIG_DEBUG_PAGEALLOC` 辅助检测

## 代码自测

**题目 1：** 函数调用栈帧（stack frame）的结构是什么？
```c
void f(int a, int b) {
    int local = a + b;
}
```

<details>
<summary>参考答案</summary>

栈帧包含：1) 返回地址（调用方的下一条指令）；2) 旧的帧指针（RBP/FP）；3) 局部变量（local）；4) 保存的寄存器；5) 参数（如果不在寄存器中传递）。`SP` 指向栈顶，`FP` 指向当前帧基址。函数序言（prologue）建立帧，函数结语（epilogue）恢复帧。栈溢出：递归太深或局部变量太大。用 `-fomit-frame-pointer` 省略帧指针（多一个寄存器，但调试困难）。

</details>
