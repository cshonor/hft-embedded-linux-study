# 1.5 GDB 源码级调试

## 本节讲什么

**gdb** 断点、单步、看内存、backtrace、**core** —— 定位空指针/栈溢出。

## 要点

### 基本流程

```bash
gcc -g -O0 -Wall main.c -o app
gdb ./app
```

```
(gdb) break main
(gdb) run
(gdb) next          # 单步跳过
(gdb) step          # 单步进入
(gdb) print p
(gdb) print *ptr
(gdb) x/16xb &buf   # 16 字节十六进制
(gdb) disassemble main
(gdb) bt            # 调用栈
(gdb) quit
```

### core 转储

```bash
ulimit -c unlimited
./app    # 崩溃生成 core
gdb ./app core
(gdb) bt
```

| 命令 | 作用 |
|------|------|
| **break** | 断点 |
| **x** | 检查内存 |
| **bt** | 栈回溯 |

- 编译须 **-g**；发布 **-O2** 仍可调试但变量可能被优化掉

## 代码自测

**题目 1：** 以下 GDB 调试流程中，每个命令的作用是什么？
```c
gcc -g main.c -o main   # 编译
gdb ./main              # 启动
(gdb) break main         # ?
(gdb) run                # ?
(gdb) next               # ?
(gdb) print x            # ?
(gdb) backtrace          # ?
```
<details>
<summary>参考答案</summary>

- `gcc -g`：生成调试信息（DWARF 格式嵌入 ELF）
- `break main`：在 main 函数入口设断点
- `run`：运行程序直到断点
- `next`（`n`）：单步执行，不进入函数内部（step 进入）
- `print x`（`p x`）：打印变量 x 的值
- `backtrace`（`bt`）：打印调用栈，定位段错误位置

段错误调试：`gdb ./main` → `run` → 段错误时 `bt` 查看崩溃调用栈。

</details>
