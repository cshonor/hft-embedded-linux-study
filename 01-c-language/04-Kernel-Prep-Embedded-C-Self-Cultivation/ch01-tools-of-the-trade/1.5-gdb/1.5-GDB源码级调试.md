# 1.5 GDB 源码级调试

## 本节讲什么

**gdb** 断点、单步、看内存、backtrace、**core** —— 定位空指针/栈溢出。

## 要点

### 基本流程

```bash
gcc -g -O0 -Wall main.c -o app
gdb ./app
```

```
(gdb) break main
(gdb) run
(gdb) next          # 单步跳过
(gdb) step          # 单步进入
(gdb) print p
(gdb) print *ptr
(gdb) x/16xb &buf   # 16 字节十六进制
(gdb) disassemble main
(gdb) bt            # 调用栈
(gdb) quit
```

### core 转储

```bash
ulimit -c unlimited
./app    # 崩溃生成 core
gdb ./app core
(gdb) bt
```

| 命令 | 作用 |
|------|------|
| **break** | 断点 |
| **x** | 检查内存 |
| **bt** | 栈回溯 |

- 编译须 **-g**；发布 **-O2** 仍可调试但变量可能被优化掉  

## 实操

Demo03：故意空指针 → **bt** 定位行号。

## 代码自测

**题目 1：** gcc 编译的四个阶段是什么？
```bash
gcc hello.c -o hello
```

<details>
<summary>参考答案</summary>

1) 预处理（cpp）：展开宏、包含头文件、条件编译 → `hello.i`
2) 编译（cc1）：语法分析、优化 → 汇编代码 `hello.s`
3) 汇编（as）：汇编代码 → 目标文件 `hello.o`
4) 链接（ld）：目标文件 + 库 → 可执行文件 `hello`
对应命令：`gcc -E` / `gcc -S` / `gcc -c` / `gcc`（全部）。理解编译流程对调试编译错误、分析二进制、优化至关重要。

</details>
