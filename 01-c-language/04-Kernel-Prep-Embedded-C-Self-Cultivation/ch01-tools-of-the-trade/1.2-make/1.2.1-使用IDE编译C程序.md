# 1.2.1 使用 IDE 编译 C 程序

## 本节讲什么

对比 **IDE 一键编译**与**命令行工具链** —— 底层开发必须看见每一步。

## 要点

| IDE | 命令行 |
|-----|--------|
| 隐藏预处理/链接 | **gcc -E/-S/-c** 可拆解 |
| 难复现 CI/板端 | 脚本/Makefile 一致 |
| 绑定 GUI | SSH 到板卡只有 Shell |

### 底层思维

- 编译 = **预处理 → 编译 → 汇编 → 链接**（**1.2.2**）  
- 产物 = **ELF**（**1.4** readelf/objdump）  
- 崩溃 = **gdb + core**（**1.5**）  

## 与后续衔接

全书 ch02–ch10 均假设命令行环境。

## 代码自测

**题目 1：** IDE（如 VS Code）和命令行编译各有什么优缺点？

<details>
<summary>参考答案</summary>

IDE 优点：图形界面、自动补全、调试方便、项目管理直观。缺点：隐藏编译细节、配置文件复杂、不便于 CI/CD。命令行优点：可控性强、易于自动化、理解编译过程。缺点：需要手动管理依赖、调试需额外工具（gdb）。嵌入式开发通常两者结合——IDE 写代码，命令行编译调试。

</details>
