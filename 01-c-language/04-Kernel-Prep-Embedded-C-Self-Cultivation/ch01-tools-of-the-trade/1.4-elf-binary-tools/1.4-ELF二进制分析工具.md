# 1.4 ELF 二进制分析工具

## 本节讲什么

**objdump / readelf / nm / size / hexdump** —— 查看段布局、反汇编、符号表；ch04/ch05 内存分析前置。

## 要点

### objdump

```bash
objdump -dS app          # 反汇编 + 源码（需 -g）
objdump -h app           # 段头摘要
objdump -t app           # 符号表
```

### readelf

```bash
readelf -h app           # ELF 头
readelf -S app           # 节 .text .rodata .data .bss
readelf -l app           # 程序头 / LOAD 段
```

### nm / size

```bash
nm app | grep main
size app                 # text data bss 十进制
```

### 原始字节

```bash
hexdump -C app | head
xxd app | head
```

| 工具 | 典型问题 |
|------|----------|
| **readelf -S** | 各段多大？ |
| **objdump -d** | 函数对应哪些指令？ |
| **nm** | 全局变量地址？ |

## 代码自测

**题目 1：** gcc 编译的四个阶段是什么？
```bash
gcc hello.c -o hello
```

<details>
<summary>参考答案</summary>

1) 预处理（cpp）：展开宏、包含头文件、条件编译 → `hello.i`
2) 编译（cc1）：语法分析、优化 → 汇编代码 `hello.s`
3) 汇编（as）：汇编代码 → 目标文件 `hello.o`
4) 链接（ld）：目标文件 + 库 → 可执行文件 `hello`
对应命令：`gcc -E` / `gcc -S` / `gcc -c` / `gcc`（全部）。理解编译流程对调试编译错误、分析二进制、优化至关重要。

</details>
