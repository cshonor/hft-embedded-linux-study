# 1.6 环境脚本 buildenv.sh

## 本节讲什么

**`source buildenv.sh`** 在当前 Shell 注入 **PROJECT_ROOT、CC、CFLAGS** 与快捷函数 —— 隔离项目编译环境。

## 要点

### source vs bash

```bash
source ../devenv/buildenv.sh   # 当前 shell 生效
bash ../devenv/buildenv.sh     # 子 shell，变量丢失
```

### 脚本内容（仓库已提供）

路径：`04-Kernel-Prep-Embedded-C-Self-Cultivation/devenv/buildenv.sh`

| 导出 | 作用 |
|------|------|
| **PROJECT_ROOT** | 工程根目录 |
| **CC / CROSS_COMPILE** | 本地或交叉 gcc |
| **CFLAGS** | -Wall -Wextra -std=c11 -g |
| **build / clean** | 封装 make |

```bash
cd 04-Kernel-Prep-Embedded-C-Self-Cultivation
source devenv/buildenv.sh
build ch01-tools-of-the-trade/demo
```

### 永久加载（可选）

```bash
echo 'source ~/path/to/devenv/buildenv.sh' >> ~/.bashrc
```

### 交叉编译

```bash
export CROSS_COMPILE=arm-linux-gnueabihf-
source devenv/buildenv.sh
echo $CC    # arm-linux-gnueabihf-gcc
```

## 代码自测

**题目 1：** gcc 编译的四个阶段是什么？
```bash
gcc hello.c -o hello
```

<details>
<summary>参考答案</summary>

1) 预处理（cpp）：展开宏、包含头文件、条件编译 → `hello.i`
2) 编译（cc1）：语法分析、优化 → 汇编代码 `hello.s`
3) 汇编（as）：汇编代码 → 目标文件 `hello.o`
4) 链接（ld）：目标文件 + 库 → 可执行文件 `hello`
对应命令：`gcc -E` / `gcc -S` / `gcc -c` / `gcc`（全部）。理解编译流程对调试编译错误、分析二进制、优化至关重要。

</details>
