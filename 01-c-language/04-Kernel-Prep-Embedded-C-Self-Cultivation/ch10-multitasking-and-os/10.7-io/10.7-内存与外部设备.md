# 10.7 内存与外部设备

## 本节讲什么

CPU 通过 **内存总线** 访问 **RAM 与外设**；理解 **内存层次、设备分类、MMIO** 是驱动开发与 **10.8 寄存器操作** 的前置。本节总览 **10.7.1–10.7.3**，连接 **RTOS 驱动** 与 **Linux 设备模型**。

## 要点

**内存层次**（**10.7.1**）：

```
寄存器 ──► SRAM ──► DRAM ──► eMMC/Flash（外存）
  最快      快       较大      持久、慢
```

**外部设备**（**10.7.2**）：

- **字符设备**：UART 字节流
- **块设备**：eMMC 扇区
- **网络设备**：MAC/PHY
- **GPIO/ADC/PWM**：控制与采样

**访问方式**：

| 环境 | 访问外设 |
|------|----------|
| 裸机/RTOS | 直接 `*(volatile *)REG` |
| Linux 内核 | `readl/writel(ioremap)` |
| Linux 用户 | `read/write/ioctl` 设备节点 |

**与多任务/中断**：

- 外设 **中断** 唤醒任务（**10.3**）
- 多任务共享 UART → **mutex**（**10.2.4**、**demo04**）

**DPDK 旁路**：

- **UIO/VFIO** 把 NIC 寄存器映射到用户态；**lcore 轮询** 不用中断驱动 RX

## 代码自测

**题目 1：** 以下代码轮询等待硬件就绪，有什么问题？如何改进？
```c
volatile uint32_t *status_reg = (uint32_t *)0x40000008;
void wait_ready(void) {
    while ((*status_reg & 0x01) == 0) {
        // 等待 bit0 置位
    }
}
```
<details>
<summary>参考答案</summary>

问题：
1. 忙等待浪费 CPU：轮询期间 CPU 一直在读寄存器，无法做其他工作
2. 如果硬件永远不就绪：程序死锁，整个系统卡死
3. 高功耗：CPU 全速运行

改进方案：
1. 中断驱动（推荐）：ISR 中设标志位，主循环用 __WFI() 休眠等待中断
2. 轮询 + 超时 + 让出：加超时判断，超时返回错误码，循环中调用 schedule() 让出 CPU

选择原则：实时性要求高用中断，简单场景可用轮询但必须加超时保护。

</details>
