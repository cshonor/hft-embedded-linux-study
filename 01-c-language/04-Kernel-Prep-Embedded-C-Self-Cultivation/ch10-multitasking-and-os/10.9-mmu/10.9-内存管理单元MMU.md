# 10.9 内存管理单元MMU

## 本节讲什么

**MMU（Memory Management Unit）** 实现 **虚拟地址到物理地址** 的转换，并附带 **访问权限、cache 属性**。本节说明 MMU 在 **Linux 进程隔离** 与 **RTOS MPU** 中的角色，对比 **10.4 syscall** 与 **10.10 进程**，是理解现代 OS 的硬件基础。

## 要点

**无 MMU（多数 M0/M3）**：

- 平坦地址；任务共享整个空间 → **野指针全局后果**
- 保护靠 **编码 + MPU（可选）**

**有 MMU（A 核 Linux）**：

```
CPU 读 VA 0x00400000
  → MMU 查 TLB/页表
  → 得 PA 0x8fc00000
  → 检查 AP（用户只读？）→ 违例则 data abort
```

**与多任务关系**：

| | RTOS + MPU | Linux + MMU |
|---|------------|-------------|
| 隔离粒度 | 几个区域/任务 | 每进程完整地址空间 |
| 切换开销 | 改 MPU 寄存器 | 换页表 ASID/TTBR |
| 栈保护 | guard region | guard page + NX |

**页 fault**：

- 合法：按需 **分配物理页**（匿名 mmap grow）
- 非法：`SIGSEGV` 杀进程

**与 **10.4.2** 权限**：

- 用户态不能写内核页 → syscall 必须 **copy_from_user**
- **NX bit**：栈不可执行，缓解 shellcode

**嵌入式 Linux**：

- **mmap** 映射 **/dev/fb**、**dma-buf**
- **10.6.2** 设备内存属性在页表设 Device

## 代码自测

**题目 1：** 裸机多任务（无 OS）如何实现？有什么限制？
```c
void task1() { while (1) { work1(); yield(); } }
void task2() { while (1) { work2(); yield(); } }
```

<details>
<summary>参考答案</summary>

裸机多任务通过协作式调度实现：每个任务主动调用 `yield()` 让出 CPU，调度器切换到下一个任务。`yield()` 需要保存/恢复寄存器和栈——通常用 `setjmp`/`longjmp` 或汇编实现。限制：1) 协作式（任务不 yield 就独占 CPU）；2) 无抢占（不能强制切换）；3) 无内存保护（一个任务崩溃影响全部）；4) 栈空间有限。有 OS 后用线程/进程替代。

</details>
