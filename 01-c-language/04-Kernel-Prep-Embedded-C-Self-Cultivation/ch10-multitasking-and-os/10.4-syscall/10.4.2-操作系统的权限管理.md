# 10.4.2 操作系统的权限管理

## 本节讲什么

操作系统通过 **权限管理** 限制程序能访问的资源：哪些内存可读写的、哪些指令可执行、哪些设备节点可打开。本节从 **用户/内核**、**UID/GID**、**MPU/MMU** 角度建立模型，衔接 **10.4.3 特权模式** 与 **10.9 MMU**。

## 要点

**权限的目标**：

- **隔离**：进程 A 不能读进程 B 密码
- **稳定**：用户程序 bug 不拖垮内核
- **安全**：非授权不能操作硬件寄存器

**Linux 用户态权限**：

| 机制 | 作用 |
|------|------|
| **UID/GID** | 文件 rwx、进程身份 |
| **`capability`** | 细分 root 能力（`CAP_NET_RAW` 等） |
| **seccomp** | 限制可用 syscall 集合 |
| **namespace/cgroup** | 容器资源边界 |

```bash
ls -l /dev/mem          # 通常 root 才能 rw
getuid(); open("/etc/shadow", O_RDONLY);  # EACCES
```

**RTOS / 裸机**：

- 通常 **无 UID**；所有任务 **同一特权**（或 TrustZone 分世界）
- **MPU**（Cortex-M）：最多 8 区域，限制任务访问 RAM 范围
- 权限靠 **编码规范 + 模块划分**（**ch09**），而非硬件进程隔离

**内存权限**（**10.9.2**）：

| 区域 | 典型权限 |
|------|----------|
| 代码 `.text` | RX |
| 数据 `.data/.bss` | RW |
| 外设 | 仅内核/驱动 RW |
| 用户栈 | RW，不可执行（NX） |

**从 syscall 视角**：

- 用户传指针 → 内核 **copy_from_user** 验证地址是否在用户映射且可写
- 非法指针 → `EFAULT` 而非内核崩溃

**嵌入式 Linux 启动**：

- 应用以普通用户运行；驱动 **内核模块** 或 **udev** 规则授权设备节点

## 代码自测

**题目 1：** 以下代码尝试直接访问物理地址 0x40000000 读取硬件寄存器，在 Linux 用户态会发生什么？
```c
// 尝试直接读写物理地址
volatile unsigned int *reg = (volatile unsigned int *)0x40000000;
unsigned int val = *reg;
```
<details>
<summary>参考答案</summary>

会触发 Segmentation fault（段错误），程序崩溃。

原因：
1. 虚拟内存保护：Linux 用户进程使用虚拟地址，0x40000000 这个虚拟地址没有映射到物理页
2. MMU 拦截：CPU 访问该地址时触发缺页异常
3. 内核终止进程：内核发现该地址不在进程的合法地址空间内，发送 SIGSEGV 信号

在用户态访问硬件寄存器的正确方法：通过 /dev/mem + mmap 映射物理地址，或通过内核驱动提供的 ioctl/read/write 接口，或通过 sysfs。用户态不能直接访问物理硬件，必须通过内核提供的接口。

</details>
