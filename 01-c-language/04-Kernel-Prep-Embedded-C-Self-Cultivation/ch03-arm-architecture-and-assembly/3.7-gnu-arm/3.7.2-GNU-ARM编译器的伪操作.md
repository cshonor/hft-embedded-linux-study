# 3.7.2 GNU ARM编译器的伪操作

## 本节讲什么

GNU `as` 特有伪操作：控制 ARM/Thumb、literal 池、CPU 特性——写启动代码与内联汇编外围 `.S` 时常用。

## 要点

```arm
.syntax unified
.arm                    @ 后续为 ARM 32 位指令
.thumb                  @ Thumb-2
.ltorg                  @ 在此放置 literal pool
.cpu cortex-a7
.fpu vfpv3-d16
.arch armv7-a
```

| 伪操作 | 作用 |
|--------|------|
| `.ltorg` | 防止 `ldr =` 跳转过远 |
| `.arm` / `.thumb` | 切换指令集 |
| `.code 32` / `.code 16` | 同义切换 |
| `.fnstart` / `.fnend` | 栈展开元数据（异常处理） |

- 内核 `ENTRY(vector)` 宏展开含 `.type`、`.align`
- DPDK 裸机移植 seldom 手写，但读 U-Boot 需认识 `.arch`

## 代码自测

**题目 1：** ARM 的 RISC 设计与 x86 的 CISC 有什么区别？对 C 编程有什么影响？

<details>
<summary>参考答案</summary>

RISC（ARM）：定长指令（4 字节）、load-store 架构（内存访问只用 LDR/STR，运算只在寄存器间）、大量寄存器（R0-R30）。CISC（x86）：变长指令、内存操作数可直接参与运算。影响：1) ARM 对齐要求更严格（非对齐访问可能异常）；2) ARM 的函数调用约定不同（前 4 个参数用 R0-R3 传递）；3) 内联汇编语法不同。跨平台代码应避免假设特定架构行为。

</details>
