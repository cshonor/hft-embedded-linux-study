# 2.6.3 big.LITTLE 结构

## 本节讲什么

**大核（性能）+ 小核（能效）** 同片 —— ARM 移动端与部分嵌入式 SoC 的异构多核。

## 要点

```
big:   深流水线、高 IPC、高功耗  → 突发负载
LITTLE: 浅流水线、低功耗       → 后台/待机
```

- **全局调度**：Linux **EAS** 按负载迁移线程  
- 同 ISA 不同微架构；**频率/Cache** 差异大  
- 服务器 x86 少见；**Ampere/ARM 云实例** 需了解核类型差异  
- DPDK 绑核时避免把 **polling 线程** 放小核

## 与后续衔接

**2.7.1** 更广义的异构；**2.6.4** 另一种「逻辑核」扩展。

## 代码自测

**题目 1：** ARM big.LITTLE 架构的设计目标是什么？大小核如何分工？

<details>
<summary>参考答案</summary>

目标：兼顾高性能和低功耗。大核（A78/X4）处理重负载任务，小核（A55/A720）处理轻负载任务。操作系统通过调度器动态迁移任务——负载高时用大核，负载低时迁移到小核。异构调度是手机 SoC 的核心技术，显著延长续航。

</details>
