# 2.4.1 Cache 的工作原理

## 本节讲什么

**局部性原理**与 Cache 命中/失效 —— 数组性能、HFT/DPDK  cache line 优化基础。

## 要点

### 存储金字塔（快到慢）

```
寄存器 → L1 → L2 → L3 → RAM → Flash → 磁盘
  ns      │              μs      ms
```

### 局部性

| 类型 | 含义 | 代码示例 |
|------|------|----------|
| **时间** | 刚用过的还会再用 | 循环内变量 |
| **空间** | 相邻地址会一起用 | **数组顺序扫描** |

### Cache 行

- 主流 **64B/行**；一次载入整行  
- **miss** → 访问 RAM，延迟跳变  
- **抖动**：工作集 > Cache → 反复驱逐  

### 嵌入式优化

- 顺序遍历 `arr[i]`，避免随机跳地址  
- 结构体数组优于指针数组（空间局部性）  
- 多线程：**伪共享** — 同 cache line 不同变量（DPDK padding）

## 代码自测

**题目 1：** 以下代码两种遍历方式的性能差异原因是什么？
```c
#define N 1024
int matrix[N][N];
// 方式A
for (i = 0; i < N; i++)
    for (j = 0; j < N; j++)
        sum += matrix[i][j];
// 方式B
for (j = 0; j < N; j++)
    for (i = 0; i < N; i++)
        sum += matrix[i][j];
```
<details>
<summary>参考答案</summary>

方式 A 远快于方式 B。

C 语言二维数组按行存储（row-major），`matrix[i][j]` 和 `matrix[i][j+1]` 在内存中相邻。方式 A 顺序访问，利用**空间局部性**，一个 Cache Line（通常 64 字节 = 16 个 int）只需从内存加载一次。方式 B 跳跃访问（每次跨 N*4 字节），每次访问都 Cache Miss，性能差 10 倍以上。

Cache 工作原理：CPU 访问内存时先查 Cache，命中则直接使用，未命中则从内存加载一个 Cache Line。

</details>
