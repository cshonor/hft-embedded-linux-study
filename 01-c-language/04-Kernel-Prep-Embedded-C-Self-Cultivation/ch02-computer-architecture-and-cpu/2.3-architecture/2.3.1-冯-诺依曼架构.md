# 2.3.1 冯·诺依曼架构

## 本节讲什么

**五大部件 + 统一存储** —— 现代通用计算机骨架；指令与数据同存于内存，总线分时复用。

## 要点

| 部件 | 作用 |
|------|------|
| **ALU** | 算术/逻辑运算 |
| **CU** | 取指、译码、控制时序 |
| **存储器** | RAM 运行态 + ROM/Flash 固件 |
| **输入** | 按键、串口、传感器 |
| **输出** | 屏、PWM、电机 |

### 数据流

```
取指(PC) → 译码 → 读操作数(内存/寄存器) → ALU → 写回 → 更新 PC
```

- **C 赋值 `a = b + c`**：Load 到寄存器 → Add → Store 回内存（**2.2.2**）

### 特性与代价

- 指令/数据**同一内存** → 结构简单  
- 指令与数据争用总线 → 带宽瓶颈  

## 与后续衔接

对比 **2.3.2 哈佛**；**ch03** ARM 取指/load/store。

## 代码自测

**题目 1：** 冯·诺依曼架构和哈佛架构的核心区别是什么？对 C 编程有什么影响？
<details>
<summary>参考答案</summary>

**冯·诺依曼架构**：指令和数据共享同一存储器和总线。简化硬件设计，但取指和取数据不能同时进行（瓶颈）。

**哈佛架构**：指令和数据有独立的存储器和总线。可以同时取指和取数据，吞吐量更高。

对 C 编程的影响：
- 哈佛架构（如 AVR 单片机）需要 `pgm_read_byte()` 等特殊宏读取 Flash 中的常量
- 冯·诺依曼架构（如 x86/ARM AArch64）中函数指针和数据指针大小相同
- 嵌入式 MCU 常用改进型哈佛架构（L1 缓存分 I-cache/D-cache）

</details>
