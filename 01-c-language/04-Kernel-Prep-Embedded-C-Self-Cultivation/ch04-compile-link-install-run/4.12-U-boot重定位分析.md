# 4.12 U-boot重定位分析

## 本节讲什么

**U-Boot** 常先由 ROM 加载到 **低地址 SRAM/DRAM 临时区**，再 **自拷贝** 到链接脚本指定的高地址并 **修正重定位项**——因为初始 PC 与链接 VMA 不一致。这是 **4.4.3 重定位** 在嵌入式 Bootloader 中的手工版，与内核解压后重定位同类。

## 要点

### 为何重定位

- 链接时假设运行在 `TEXT_BASE`（如 `0x40200000`）
- 上电时可能在 `0x00000000` 或另一 RAM 区执行
- 必须拷贝代码/数据并修补 **相对/绝对地址引用**

### 典型步骤（概念）

1. `relocate_code`：拷贝 `.text/.data` 到目标区
2. 遍历 `__rel_dyn_start`…`__rel_dyn_end` 修补
3. 跳转至重定位后地址继续执行

```bash
# 分析 U-Boot ELF（交叉工具链）
arm-linux-gnueabihf-readelf -S u-boot
arm-linux-gnueabihf-nm u-boot | grep relocate
arm-linux-gnueabihf-objdump -d u-boot | grep relocate
```

### 与链接脚本

- `u-boot.lds` 定义 `TEXT_BASE`、`__image_copy_start`
- **4.14** `MEMORY` 区分 Flash 与 RAM

### 对照 Linux 启动

| 阶段 | 重定位者 |
|------|----------|
| U-Boot | 自身 `board_init_f` / `relocate` |
| Linux 内核 | `head.S` + 解压桩 |
| 用户程序 | `ld.so`（**4.8**） |

## 代码自测

**题目 1：** U-Boot 为什么要做重定位（relocate）？以下代码完成什么操作？
```c
/* U-Boot relocate */
ulong relocaddr = gd->relocaddr;
memcpy((void *)relocaddr, (void *)CONFIG_SYS_TEXT_BASE, gd->mon_len);
relocate_code(relocaddr, gd->reloc_off, relocaddr);
```
<details>
<summary>参考答案</summary>

U-Boot 重定位原因：
- U-Boot 初始加载到固定地址（CONFIG_SYS_TEXT_BASE，如 0x87800000）
- 但该地址可能被 Linux 内核占用，需将自身复制到更高地址运行
- 重定位后修正所有绝对地址引用（通过 reloc_off 偏移量）

流程：
1. `memcpy`：将整个 U-Boot 代码和数据复制到新地址 relocaddr
2. `relocate_code`：修正 GOT 表、所有绝对地址符号（加上 reloc_off）
3. 跳转到新地址继续执行

这是嵌入式启动的常见模式：Bootloader 先在低端地址运行，然后搬自己到高端地址，腾出空间给内核。

</details>
