# 4.9 插件的工作原理

## 本节讲什么

**插件** 本质是运行期用 **`dlopen/dlsym/dlclose`** 装入的 **共享库**，主程序在编译期不必链接插件，通过函数指针调用。Firefox/Nginx 模块、DPDK **PMD 动态驱动** 同属此模式。

## 要点

### 基本 API

```c
void *h = dlopen("./libplugin.so", RTLD_LAZY);
int (*init)(void) = dlsym(h, "plugin_init");
init();
dlclose(h);
```

```bash
gcc -fPIC -shared -o libplugin.so plugin.c
gcc -o host host.c -ldl
LD_LIBRARY_PATH=. ./host
```

### 与 4.8 的关系

- 插件必须是 **PIC 的 `.so`**
- 符号须 **导出**（`nm -D libplugin.so`）
- 延迟绑定同样适用（**4.8.3**）

```bash
readelf -d libplugin.so
ldd libplugin.so
```

### 常见约定

- 固定入口符号：`plugin_register`、`rte_pmd_init` 等
- 版本协商结构体，避免 ABI 不匹配

### 排错

```bash
dlerror()                        # 代码中打印
LD_DEBUG=bindings ./host       # 观察加载
```

## 与后续衔接

- **4.8.4** 共享库构建；**4.5** 插件安装路径
- DPDK：`--enable-shared`、EAL 扫描 PMD；内核模块用 `insmod` 非 `dlopen`
- **ch09** C 模块化设计思想

## 代码自测

**题目 1：** 插件机制如何实现？以下代码中 dlopen/dlsym 各完成什么功能？
```c
void *handle = dlopen("./plugin.so", RTLD_NOW);
if (!handle) { fprintf(stderr, "%s\n", dlerror()); return -1; }
typedef int (*func_t)(int);
func_t func = (func_t)dlsym(handle, "process");
func(42);
dlclose(handle);
```
<details>
<summary>参考答案</summary>

插件机制基于动态链接的运行时加载：

- `dlopen("./plugin.so", RTLD_NOW)`：运行时加载共享库到进程地址空间。`RTLD_NOW` 立即解析所有符号（`RTLD_LAZY` 延迟解析）
- `dlsym(handle, "process")`：在已加载的库中查找符号 `process` 的地址，返回函数指针
- 调用 `func(42)`：通过函数指针调用插件函数
- `dlclose(handle)`：卸载共享库（引用计数归零时真正卸载）

编译需 `-ldl`。插件 .so 必须用 `-fPIC -shared` 编译。

应用：浏览器插件、GStreamer 编解码器、Nginx 模块、编辑器扩展。

</details>
