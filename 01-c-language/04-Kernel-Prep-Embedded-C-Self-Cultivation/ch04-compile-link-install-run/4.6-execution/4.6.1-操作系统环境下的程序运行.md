# 4.6.1 操作系统环境下的程序运行

## 本节讲什么

Linux 运行 ELF 可执行文件时，内核解析 **程序头（Program Header）**，将 `PT_LOAD` 段映射到进程虚拟地址空间，**物理页** 按需分配；`ld-linux.so` 处理动态段、重定位与初始化，再跳转到用户入口。

## 要点

### execve 装载

```bash
readelf -l ./prog
# LOAD 段：/bin 或 /lib 文件偏移 → 虚拟地址 VMA
strace -e execve,mmap ./prog 2>&1 | head -30
```

### 虚拟内存布局（典型 x86-64）

```
高地址  栈 ↓
        mmap / 堆 ↑
        共享库 .so
        .bss / .data / .rodata / .text
低地址
```

```bash
cat /proc/self/maps              # 运行中查看
pmap -x $(pidof prog)
```

### 动态链接器

- `.interp` 段指定 `/lib64/ld-linux-x86-64.so.2`
- `ld.so` 读取 `.dynamic`：`NEEDED`、`REL`、`INIT`

```bash
readelf -d ./prog
readelf --dyn-syms ./prog | head
```

### ASLR 与 PIE

```bash
gcc -pie -fPIE -o prog main.c
readelf -h prog | grep Type       # DYN（位置无关可执行）
```

## 代码自测

**题目 1：** 静态库（.a）和动态库（.so）的链接时机有什么区别？
```bash
gcc main.c -lfoo -o main  # 什么时候链接？
```

<details>
<summary>参考答案</summary>

静态库（.a）：链接时（link time）从库中提取用到的目标文件，复制到可执行文件中。动态库（.so）：链接时只记录依赖信息，运行时（load time 或 runtime）由动态链接器加载库代码。静态库文件大但自包含；动态库小但依赖运行时环境。`ldd main` 查看动态库依赖。`-Wl,-rpath` 指定运行时搜索路径。

</details>
