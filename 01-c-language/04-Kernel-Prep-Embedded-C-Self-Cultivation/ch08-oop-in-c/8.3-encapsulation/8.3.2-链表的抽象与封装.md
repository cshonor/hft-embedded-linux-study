# 8.3.2 链表的抽象与封装

## 本节讲什么

内核**侵入式链表**（intrusive list）把 `struct list_head` 嵌入宿主对象，通过 **`list_entry` / `container_of`** 遍历。链表操作被封装进 `list_add`、`list_del`、`list_for_each_entry` 宏，驱动作者无需手写 `next/prev` 指针逻辑——这是 C 里「容器类」的经典抽象。

## 要点

**嵌入与遍历**：

```c
struct uart_port {
    struct list_head list;   /* 链表节点 — 「成员」 */
    int              port_id;
    void __iomem    *membase;
};

static LIST_HEAD(uart_ports);   /* 链表头 */

/* 注册：封装 add */
void uart_port_register(struct uart_port *port) {
    list_add_tail(&port->list, &uart_ports);
}

/* 遍历：封装 iterator */
struct uart_port *p;
list_for_each_entry(p, &uart_ports, list) {
    pr_info("port %d\n", p->port_id);
}
```

**`container_of` 本质**（**ch06 6.4**）：

```c
#define list_entry(ptr, type, member) \
    container_of(ptr, type, member)

/* ptr 指向 list 成员 → 算出 uart_port 首地址 */
```

| API | 作用 |
|-----|------|
| `INIT_LIST_HEAD` | 初始化空链 |
| `list_add` / `list_add_tail` | 头插 / 尾插 |
| `list_del` | 摘除节点（需再 INIT 或 add） |
| `list_empty` | 判空 |
| `list_for_each_entry_safe` | 遍历中可删除 |

**封装收益**：

- 同一套 list 代码驱动 `task_struct`、`file`、`device` 等所有子系统
- 宿主 struct 可有多个 `list_head` 成员，挂到不同链表（如 `device` 的 `bus_list` 与 `driver_list`）
- **hlist**（单指针哈希链）是变种，用于大哈希表

- 摘除后节点：`list_del` + `INIT_LIST_HEAD` 防 use-after-free
- 用户态 demo 可复刻 mini `list.h` 理解宏展开

## 代码自测

**题目 1：** Linux 内核的 list_head 如何实现与具体数据类型解耦的泛型链表？
```c
struct list_head {
    struct list_head *next, *prev;
};
struct my_data {
    int value;
    struct list_head node;  // 嵌入链表节点
};
// 遍历
struct list_head *pos;
list_for_each(pos, &head) {
    struct my_data *d = container_of(pos, struct my_data, node);
    printf("%d\n", d->value);
}
```
<details>
<summary>参考答案</summary>

内核 list_head 泛型链表的核心：

1. **侵入式设计**：链表节点 `struct list_head` 嵌入到任意结构体中，而非外部维护指针
2. **container_of**：从 `list_head *` 反推包含它的结构体指针
3. **与数据类型解耦**：list_head 不知道也不关心包含它的数据类型

对比传统链表：
```c
// 传统：链表包含数据指针
struct node { void *data; struct node *next; };
// 内核：数据包含链表节点
struct my_data { int value; struct list_head node; };
```

优势：
- 无需 void* 转换，类型安全（container_of 用 typeof 推导）
- 一个结构体可以挂在多个链表上（嵌入多个 list_head）
- 零额外内存分配（链表节点就在结构体内）
- 通用操作函数（list_add/list_del/list_for_each）只依赖 list_head

这是 C 语言 OOP 的经典范例：通过组合+container_of 实现泛型容器。

</details>
