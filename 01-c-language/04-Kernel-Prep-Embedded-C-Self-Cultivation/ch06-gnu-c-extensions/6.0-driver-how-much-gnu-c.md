# 驱动向：GNU C 扩展学多少够用？

> 结论优先 · 对齐 [ch06 GNU C 全章](./README.md) · Primer 驱动 FAQ：[8.1](../../../08-embedded-boot-build/primer-system-overview/chapter-08-device-driver-basics/8.1-dts-driver-relationship.md)  
> **速查表：** [DRIVER-GNU-C-CHEATSHEET.md](./DRIVER-GNU-C-CHEATSHEET.md)

---

## 结论

**必须了解 GNU C 扩展，但不必专门啃完整本 GNU C 手册。**  
标准 C 是根基；GNU 扩展是内核/驱动里的「附加语法」——**高频就那几类**，其余遇查即可。

---

## 1. 两个概念

| | **标准 C（C89/C99…）** | **GNU C 扩展（GCC）** |
|--|------------------------|----------------------|
| 是什么 | 变量、指针、结构体、函数、数组、控制流… | GCC 额外语法；纯标准模式可能编不过 |
| 和驱动 | **必须熟练** | 内核基本只用 GCC；源码里到处是扩展 |
| 学法 | 系统练（K&R / 指针书 / 本仓库 01） | **跟驱动源码认高频**；冷门现查 |

Linux 内核：**C + 少量 GNU 扩展**；**不用 C++，不用用户态 libc 那套**（内核自有 API）。

---

## 2. 驱动里最高频的几类（范围很小）

详见速查表。口头名单：

1. **`__attribute__`** — 尤其 `packed`（寄存器布局）、`section`、`unused`  
2. **零长 / 柔性数组成员** — 缓冲尾随数据（内核多见 `[0]` 历史写法；C99 为 `[]`）  
3. **语句表达式 + `typeof`** — `min`/`max`/`container_of` 一类宏  
4. **指定初始化** — `of_device_id`、`.probe =`、`.compatible =`（**驱动超高频**；C99 已标准化，内核风格仍当「必会阅读」）  
5. **`asm` 内嵌汇编** — 底层、原子、架构相关（先认得出，深挖按需）

---

## 3. 误区

❌「写驱动要系统学完全部 GNU 扩展」  
✅ **标准 C ≫ 上表高频 ≫ 其余现查**

笔试很少默写扩展名词；**面试读驱动片段**时，看不懂 `.compatible =` / `packed` 会立刻露馅。

---

## 4. 极简路线

1. 夯实标准 C：指针、数组、结构体、内存布局  
2. 读简单 platform / `of_device_id` 驱动，对照 [速查表](./DRIVER-GNU-C-CHEATSHEET.md)  
3. 深挖时打开本目录 **6.x** 小节与 `demo/`，**不要**先通读全部冷门属性

## 代码自测

**题目 1：** 以下 GNU C 扩展各有什么用途？
```c
__attribute__((aligned(64))) int cache_line;
__attribute__((packed)) struct S { char a; int b; };
__attribute__((weak)) void handler(void) {}
typedef typeof(int) my_int;
```

<details>
<summary>参考答案</summary>

`aligned(64)`：指定缓存行对齐，避免 false sharing。
`packed`：取消结构体填充，节省空间（但可能影响性能和可移植性）。
`weak`：弱符号，允许被其他同名强符号覆盖——用于可选钩子。
`typeof`：获取表达式类型，用于泛型宏（如 `container_of`）。
这些扩展在 Linux 内核中大量使用。非标准 C，但 GCC/Clang 支持。

</details>
