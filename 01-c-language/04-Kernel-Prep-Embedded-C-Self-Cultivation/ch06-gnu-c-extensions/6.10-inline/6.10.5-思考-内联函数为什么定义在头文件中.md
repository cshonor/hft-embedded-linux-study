# 6.10.5 思考：内联函数为什么定义在头文件中

## 本节讲什么

**定义放头文件** 是为让 **每个编译单元** 都看到函数体，从而 **就地 inline**。若只在 `.c` 定义，其他 TU 只能 **extern 调用**（除非 LTO）。

## 要点

```c
/* helper.h */
static inline int add(int a, int b) { return a + b; }
```

| 模式 | 说明 |
|------|------|
| **`static inline` in .h** | 最常见 |
| **单 .c + 普通函数** | 无 inline（除非 LTO） |

- DPDK **`static __rte_always_inline`** in **`rte_*.h`**

## 代码自测

**题目 1：** 为什么 `static inline` 函数通常定义在头文件中而不是 `.c` 文件中？如果把以下代码放在 `.c` 文件中会有什么问题？
```c
// util.h
static inline int max(int a, int b) { return a > b ? a : b; }
```

<details>
<summary>参考答案</summary>

原因：(1) 内联函数需要在调用点看到完整定义才能展开，头文件被所有 `.c` 包含；(2) `static` 保证每个翻译单元有自己的副本，不会链接冲突。如果放在 `.c` 中：(1) 其他 `.c` 文件看不到函数体，无法内联；(2) 只能通过函数声明调用，退化为普通函数调用。`static` 是关键——不加 `static` 的 `inline` 在多个 `.c` 中包含会导致链接期多重定义错误。内核头文件中大量 `static inline`。

</details>
