# 6.5.1 什么是零长度数组

## 本节讲什么

零长度数组是 **不完整类型数组** 放在结构体末尾的 GNU 写法；C99 标准化为 **flexible array member**（`[]` 无长度）。语义：结构体是 **头部**，实际对象大小 = 头 + 变长尾部。

## 要点

```c
/* GNU */
struct blob_gnu {
    int count;
    char items[0];
};

/* C99 FAM — 推荐新代码 */
struct blob_std {
    int count;
    char items[];
};
```

| 特性 | 说明 |
|------|------|
| **sizeof** | 仅头部，不含 FAM |
| **位置** | 必须是最后一个成员 |
| **C99 前** | ISO 不允许 `[0]`；GNU 扩展 |
| **C11** | FAM 正式入标准 |

```c
/* 非法：中间零长度 */
/* struct bad { char a[0]; int b; }; */
```

- 与 **指针成员** `char *items` 对比：FAM 与头 **同块连续**，缓存友好、一次 free
- **VLA（变长数组）** 不同：在栈上，FAM 在堆/静态自定义大小

## 代码自测

**题目 1：** 零长度数组 `int arr[0]` 和指针 `int *arr` 在结构体末尾有什么区别？
```c
struct buf1 { int len; int data[0]; };  // 零长数组
struct buf2 { int len; int *data; };        // 指针

// 使用
struct buf1 *b1 = malloc(sizeof(struct buf1) + 100);
struct buf2 *b2 = malloc(sizeof(struct buf2));
b2->data = malloc(100);
```
<details>
<summary>参考答案</summary>

**零长度数组**（`int data[0]`）：
- `data` 紧跟在 `len` 后面，不占结构体大小（`sizeof(struct buf1) == 4`）
- 一次 malloc 分配结构体 + 数据，内存连续
- `data` 的地址 = `&b1->len + 4`，无需额外指针

**指针**（`int *data`）：
- `data` 占 8 字节（64 位），`sizeof(struct buf2) == 16`
- 需要两次 malloc（结构体 + 数据），内存不连续
- 需要两次 free

零长数组优势：
1. 一次分配，内存连续（Cache 友好）
2. 一次释放，简化内存管理
3. 节省指针 8 字节

内核用法：`struct sk_buff`、`struct usb_request` 等。C99 标准化为柔性数组 `int data[]`（无 0）。

</details>
