# 6.5.4 思考：指针与零长度数组

## 本节讲什么

结构体末尾放 **`char *ptr`** 还是 **`char data[]`**？涉及 **一次 vs 两次分配**、**cache 局部性**、**序列化/on-wire 布局**、**ABI 稳定性**。本节对比决策树。

## 要点

| 方案 | 优点 | 缺点 |
|------|------|------|
| **FAM / [0]** | 一次 alloc；连续内存 |  realloc 变长需 memcpy 新块 |
| **指针成员** | 头大小固定；payload 可独立 realloc | 两次 alloc；指针占 4/8 字节 |
| **固定数组 `char buf[N]`** | 最简单 | 浪费或 N 不够 |

```c
/* 指针版 — 适合 payload 生命周期独立 */
struct msg_ptr {
    uint32_t len;
    uint8_t *data;   /* 另 malloc(len) */
};

/* FAM — 适合 netlink/ioctl 一次拷贝到用户态 */
struct msg_fam {
    uint32_t len;
    uint8_t  data[0];
};
```

```c
/*  wire 格式常要 FAM 思想：头后面紧跟字节 */
/*  不能直接把含指针的结构体 send() 出去 */
```

- **内核 copy_to_user**：FAM 结构 **线性** 更好算长度
- **DPDK**：mbuf 数据区在 pool 中，用 offset 而非 FAM，避免频繁 realloc
- **realloc FAM 对象**：`new = realloc(old, sizeof(*h)+newlen)` 可能移动块，注意悬挂指针

## 代码自测

**题目 1：** 零长度数组 `arr[0]`、柔性数组 `arr[]` 和指针 `*arr` 三者在结构体末尾的区别是什么？
```c
struct A { int len; int data[0]; };   // GNU 扩展
struct B { int len; int data[]; };     // C99 标准
struct C { int len; int *data; };      // 指针
```
<details>
<summary>参考答案</summary>

| 特性 | `data[0]` | `data[]` | `*data` |
|------|-----------|---------|--------|
| 标准 | GNU 扩展 | C99 标准 | 标准 C |
| sizeof(A/B) | 不含 data | 不含 data | 含指针(8B) |
| 内存分配 | 一次 malloc | 一次 malloc | 两次 malloc |
| 内存布局 | 连续 | 连续 | 不连续 |
| 释放 | 一次 free | 一次 free | 两次 free |
| 可赋值 | 否 | 否 | 是（data=ptr）|

`data[0]` 和 `data[]` 基本等价，但 `data[]` 是 C99 标准。`data[0]` 在 GCC 中可用但非标准。

`*data` 最灵活（可指向任意位置），但开销最大（两次分配、不连续、两次释放）。

内核新代码推荐用 `data[]`（标准柔性数组成员），旧代码用 `data[0]`（历史遗留）。

</details>
