# 9.8.2 框架

## 本节讲什么

**框架**提供应用运行的「骨架」——任务调度、设备注册、配置系统——你的模块作为**插件**接入，而非重写 main。本节对比自研轻量框架与 Zephyr/FreeRTOS/Linux 驱动框架的模块化接入方式，强调 **注册回调 / ops / 设备树** 等扩展点，与 **ch08 device/bus** 模型呼应。

## 要点

**框架 vs 库**：

| | 库 (lib) | 框架 |
|---|----------|------|
| 控制流 | 你调它 | 它调你（回调/ops） |
| 示例 | `ringbuf_push()` | `device_register()` |
| 模块关系 | 平级 | 核心 + 插件 |

**自研轻量框架骨架**：

```c
/* framework.h */
typedef struct {
    const char *name;
    err_t (*init)(void);
    err_t (*start)(void);
    void  (*stop)(void);
} app_module_t;

#define APP_MODULE_REGISTER(mod) \
    static const app_module_t * const _mod_##mod __attribute__((used)) = &mod

err_t framework_run_all(void);  /* 遍历链接段或显式表 */
```

- 各业务模块提供 `app_module_t` 实例，main 只调 `framework_run_all()`
- 类似 Linux `module_init` / constructor 段（高级）

**RTOS 框架接入**：

```
FreeRTOS: 每个模块一个 Task，入口 module_task(void *)
Zephyr:   DEVICE_DEFINE / SYS_INIT 宏注册
```

| 原则 | 做法 |
|------|------|
| 模块不 include 内核头到 app | 经 `osal.h` 包装 |
| 栈/优先级配置 | `config.h` 或 Kconfig |
| 同步 | OSAL mutex/semaphore（**ch10**） |

**Linux 驱动框架**（**ch08 8.3.3–8.3.4**）：

```
platform_driver_register → probe → uart_ops 绑定
```

- 驱动是框架插件；**file_operations** 是 ops 接口
- 用户态模块化可模仿：`bus_register` + `match` + `probe`

**中间件框架（MQTT/HTTP）**：

- 协议栈当 **middleware 模块**；网络 I/O 经 **platform socket 抽象**
- TLS 作为可选 `libmbedtls.a`，CMake `option(WITH_TLS)`

**避免框架过度设计**：

| 信号 | 动作 |
|------|------|
| 框架代码 > 业务代码 | 简化为 module 表 + 顺序 init |
| 10 层回调才到硬件 |  flatten |
| 宏魔法不可调试 | 显式注册数组 |

**install 与第三方集成**：

```
out/
├── lib/libmod_uart.a
├── include/mod_uart.h
└── pkg-config/mod_uart.pc   /* 可选 */
```

- 框架消费方只需 `-lmod_uart -Iout/include`
- 版本号写在 `mod_uart.h`：`#define MOD_UART_API_VERSION 1`

## 代码自测

**题目 1：** 什么是软件框架？C 语言如何实现一个简单的框架？
<details>
<summary>参考答案</summary>

框架（Framework）：定义了应用骨架和调用流程，用户填充具体逻辑。

区别：
- **库**（Library）：用户调用库函数（控制反转未发生）
- **框架**（Framework）：框架调用用户代码（控制反转 IoC）
- "Don't call us, we'll call you"（好莱坞原则）

C 框架实现要素：
1. **主循环**：框架控制主循环，调用用户注册的回调
2. **注册机制**：用户通过注册函数将自己的处理逻辑告诉框架
3. **统一接口**：框架定义接口（函数指针表），用户实现
4. **生命周期管理**：框架管理对象的创建/销毁

简单框架示例：
```c
// 框架定义
struct app_ops { void (*init)(void); void (*loop)(void); void (*exit)(void); };
void framework_run(struct app_ops *ops) {
    ops->init();
    while (running) ops->loop();
    ops->exit();
}
// 用户代码
static void my_init(void) { ... }
static void my_loop(void) { ... }
struct app_ops my_app = { my_init, my_loop, NULL };
int main(void) { framework_run(&my_app); }
```

内核框架：driver model、input subsystem、VFS。驱动开发者只需实现接口，框架管理注册/调用。
