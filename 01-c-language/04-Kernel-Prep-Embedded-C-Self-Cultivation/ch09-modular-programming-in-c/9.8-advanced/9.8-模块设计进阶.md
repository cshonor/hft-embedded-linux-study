# 9.8 模块设计进阶

## 本节讲什么

掌握 **9.1–9.7** 的基础模块化后，真实产品还面临**多平台移植**、**第三方框架集成**、**长期演进**。本节作为 **9.8.1 跨平台** 与 **9.8.2 框架** 的导读，建立进阶主题地图：何时引入抽象层、如何对接 RTOS/中间件而不破坏模块边界。

## 要点

**进阶主题矩阵**：

| 主题 | 核心问题 | 小节 |
|------|----------|------|
| **跨平台** | 同一 app 如何跑 STM32 / Linux / PC 仿真 | **9.8.1** |
| **框架** | 模块如何接入已有 OS/协议栈骨架 | **9.8.2** |
| **插件化** | 可选 `.a`、动态加载（Linux） | weak + CMake option |
| **版本与 ABI** | 模块升级不破坏调用方 |  opaque API、semver |
| **文档与 install** | 他人如何用你的 `lib*.a` | **9.2.3** install 目标 |

**进阶不等于更复杂**：

```
基础版：app → driver → 寄存器          （9.1–9.3 足够）
进阶版：app → framework → HAL → BSP   （多平台时才有价值）
```

- 评估标准：**第二块板子/第二个 OS** 是否 2 周内能 port
- 若否，检查 platform 层与 weak/ops 是否到位（**demo04_weak**）

**与 AIoT 生态**（**9.9**）：

- 云 SDK、蜂窝模组 AT 层、TLS 库——均以**独立 middleware 模块**接入
- 不把 MQTT 代码散进 driver

**质量门禁**：

| 检查 | 工具 |
|------|------|
| 模块间循环依赖 | include-what-you-use、自定义脚本 |
| 符号泄露 | `nm -g lib*.a` 应只有公开 API |
| 单测 | mock platform + PC gcc 构建 |
| 静态分析 | cppcheck、clang-tidy |

## 代码自测

**题目 1：** C 模块设计的进阶技巧有哪些？如何设计一个可扩展的模块框架？
<details>
<summary>参考答案</summary>

模块设计进阶技巧：

1. **插件架构**：用函数指针表实现可扩展接口
```c
struct driver_ops { int (*probe)(void); int (*remove)(void); };
void register_driver(struct driver_ops *ops);
```

2. **依赖注入**：通过参数传入依赖，而非全局变量
```c
struct logger *log = logger_create();
struct device *dev = device_create(log);  // 注入 logger
```

3. **配置表驱动**：用数据结构代替 switch-case
```c
struct cmd_entry { const char *name; void (*handler)(void); };
cmd_table[] = { {"start", start_handler}, {"stop", stop_handler} };
```

4. **状态机**：用函数指针表实现状态转换
5. **链表注册机制**：运行时动态注册模块

可扩展框架设计：
- 定义统一接口（ops 结构体）
- 框架维护注册列表
- 模块通过 init 函数注册自己
- 框架通过 ops 表调用模块

内核框架：driver model、VFS、netdev、input subsystem 都是此模式。

</details>
