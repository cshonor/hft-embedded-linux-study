本章讲什么

算术运算、操作符优先级、布尔上下文、三元操作符、求值顺序与序列点。 操作符优先级 K&R Ch2 已覆盖；本章重点在 C23 的布尔关键字和 求值顺序 UB。

一、C23 布尔关键字：true / false / bool

标准 写法 说明
C89 int flag = 1; 没有 bool 类型
C99 _Bool flag = 1; 新增 _Bool，但名字不好看
C99 + <stdbool.h> bool flag = true; 宏包装：bool→_Bool，true→1，false→0
C23 bool flag = true; bool/true/false 成为真正的关键字，不需要 #include <stdbool.h> 
/* C23 写法：bool 是关键字 */
bool running = true;
bool ready   = false;

if (!ready) {
    return;
}

/* C99 写法：需要头文件 */
#include <stdbool.h>
bool running = true;

迁移建议：C23 项目里直接用 bool/true/false，删掉 #include <stdbool.h>（保留也不报错，宏与关键字兼容）。

二、操作符优先级速查（常用）

从高到低（同行同级，从左到右）：

优先级 操作符 说明
1 () [] -> . ++(后) --(后) 后缀
2 ! ~ ++(前) --(前) +(一元) -(一元) *(解引用) &(取地址) sizeof 一元
3 * / % 算术
4 + - 算术
5 << >> 移位
6 < <= > >= 关系
7 == != 相等
8 & ^ \| 位运算（分三级）
9 && \|\| 逻辑（分两级）
10 ?: 三元
11 = += -= *= /= %= <<= >>= &= ^= \|= 赋值
12 , 逗号

口诀：一元 > 算术 > 移位 > 关系 > 相等 > 位 > 逻辑 > 三元 > 赋值 > 逗号。 位移优先级低于算术但高于关系——x << 2 + 3 是 x << (2+3) 不是 (x<<2)+3。

三、求值顺序与序列点（UB 重灾区）

核心规则

C 标准不规定大多数表达式的求值顺序（除了 &&、||、?:、,、函数调用分隔）。 在序列点之间修改同一对象两次 = UB。

int i = 0;

/* ❌ 全部是 UB：序列点之间修改 i 两次以上 */
a[i] = i++;           // 先读还是先写？UB
i++ + ++i;            // 两次修改，UB
i = i++;              // 修改两次，UB
printf("%d %d", i, i++);  // 参数求值顺序未指定 → 可能 UB

安全写法

/* ✅ 拆成独立语句 */
a[i] = a[i] + 1;     // 或者 i++; a[i-1] = ...;
i++;
j = i + 1;

/* ✅ && 和 || 有序列点：左边先求值，右边只在需要时求值 */
if (p != NULL && p->value > 0) {  // p != NULL 先求值，p->value 只在 p 非空时才读
    ...
}
有序列点的操作符 保证
&& \|\| 左操作数先求值完毕，再求值右操作数（短路求值）
,（逗号） 左操作数先求值，结果丢弃，再求值右操作数
?: 条件先求值，只求值被选中的分支
函数调用 所有参数求值完毕后才进入函数体

HFT 代码评审红线

/* ❌ HFT 代码评审直接打回 */
order->price = prices[i++];   // i++ 和 prices[i] 的求值顺序未指定
                                // 多线程下更是灾难

/* ✅ 分两步 */
int idx = i++;
order->price = prices[idx];

《C 陷阱与缺陷》详细讲了这类问题，但 Modern C 从标准角度给出更系统的"为什么"。

四、C23：constexpr 关键字

C23 引入 constexpr（从 C++ 借来，但语义不同）：

/* C23: 编译期常量 */
constexpr int BUFFER_SIZE = 4096;
constexpr double PI = 3.14159265358979;

/* C89/99: 只能用宏或 enum */
#define BUFFER_SIZE 4096
enum { BUFFER_SIZE = 4096 };    // 无类型
写法 类型安全 作用域 调试可见 地址可取
#define ❌（纯文本替换） 文件 ❌（预处理消失） ❌
enum ❌（总是 int） 文件/块 ✅ ❌
constexpr（C23） ✅（有类型） 块/文件 ✅ ✅（取地址会生成变量）

HFT 场景：消息头 magic number、缓冲区大小、协议常量——用 constexpr 替代 #define，类型安全且调试器可见。

五、复合赋值与副作用

x += y;    // 等价于 x = x + y，但 x 只求值一次
x op= y;   // 通式：x = x op y（x 只求值一次）

x 只求值一次在指针表达式中有意义：

arr[func()] += 1;   // func() 只调用一次
arr[func()] = arr[func()] + 1;  // func() 可能调用两次！

HFT / DPDK 关联

  • 求值顺序 UB 是 HFT 代码评审重点：i++ + ++i 类写法零容忍，多线程下可能变成数据竞争
  • constexpr 改善消息结构定义：magic number、固定偏移量用 constexpr 而非 #define
  • bool 关键字：C23 后不再需要 <stdbool.h>，HFT 项目可逐步清理
  • 短路求值：if (p && p->field) 是防御性编程基础，避免空指针解引用

章节自测

1. a[i] = i++; 为什么是 UB？

i 在两个子表达式中被修改（i++）和读取（a[i]），且它们之间没有序列点。 标准不规定先执行 i++ 还是先读 a[i]——可能先自增再索引（a[1]），也可能先索引再自增（a[0]）， 甚至可能发生完全不可预测的行为。正确写法：i++; a[i-1] = i; 或拆成两行。

2. C23 的 constexpr 和 #define 有什么区别？

#define 是预处理器的文本替换：无类型、无作用域、调试器看不到。 constexpr 声明一个有类型的编译期常量：有作用域（块/文件级）、类型安全、调试器可见、可取地址。 HFT 项目中消息结构的 magic number、固定偏移量应优先用 constexpr。

3. x && y 中，如果 x 为假，y 会求值吗？

不会。&& 是短路求值：左操作数为假时，右操作数不求值，整个表达式为假。 这在 if (p != NULL && p->field > 0) 中至关重要——p->field 只在 p 非空时才解引用。 || 对称：左操作数为真时右不求值。

4. x << 2 + 3 的值是什么？

是 x << (2+3) = x << 5，不是 (x<<2)+3。因为 + 的优先级高于 <<。 移位操作符的优先级低于算术但高于关系，这是常见的优先级陷阱。建议：位运算表达式一律加括号。
