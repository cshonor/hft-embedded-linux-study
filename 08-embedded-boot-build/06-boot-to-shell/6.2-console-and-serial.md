# 控制台从哪来：console= / /dev/console / 串口

> **本节讲什么：** 你看到的启动信息是怎么出来的、串口控制台怎么配、`/dev/console` 到底是什么。bring-up 阶段**没有串口等于瞎子**，这是必须搞懂的一节。

## 三件事别搞混

| 概念 | 是什么 | 谁在用 |
|------|--------|--------|
| **内核 console** | 内核 `printk` 输出的**目的地** | 内核（`printk`、panic 信息、Oops） |
| **/dev/console** | 一个**设备节点**（字符设备 5:1） | 用户态程序的 stdin/stdout/stderr |
| **tty** | 终端（物理串口 / 虚拟终端 / SSH pty） | 登录会话 |

**关键理解**：内核 console 和 `/dev/console` 是**两件独立的配置**，只是恰好通常指向同一个地方。

## 内核 console：printk 往哪打

```
printk("...")  →  内核 console 链表  →  每个注册的 console 驱动
                                        ├─ ttyAMA0（串口）
                                        ├─ tty0  （虚拟终端/屏幕）
                                        └─ netconsole（UDP 网络）
```

**由 `console=` 内核参数指定：**

```
console=ttyAMA0,115200          # 串口 0，波特率 115200
console=tty0                    # 当前虚拟终端（HDMI 屏幕）
console=ttyAMA0,115200 console=tty0    # 两个都要（最后一个才是 /dev/console）
```

⭐ **`console=` 可以出现多次**，所有列出的都会收到 printk 输出。但 **`/dev/console` 只绑定最后一个** `console=` 指定的设备 —— 这个是规定，记住就行。

### Pi 5 上的实际配置

Pi 5 的串口是 **`ttyAMA0`**（PL011，在 40pin 排针的 GPIO14/15 上）。

```bash
# /boot/firmware/cmdline.txt（必须一整行）
console=serial0,115200 console=tty1 root=/dev/mmcblk0p2 rootfstype=ext4 rootwait
#      ↑ serial0 是固件提供的别名，通常指向 ttyAMA0
```

```bash
# /boot/firmware/config.txt
enable_uart=1          # 启用串口（Pi 5 默认可能关闭以省电）
```

⚠️ **Pi 5 常见坑**：`enable_uart=1` 不加，串口完全没输出，你会以为"内核没起来"。

## earlycon：在驱动初始化之前就有输出

```
内核启动 → console 驱动还没注册 → 这期间的 printk 去哪了？
                                    ↓
                          存在 printk 缓冲区里，驱动就绪后**补打**
```

**这意味着"启动早期崩溃"你可能什么都看不到**（缓冲区里的东西来不及输出）。

解决：`earlycon`

```
earlycon console=ttyAMA0,115200
```

`earlycon` 提供一个**极简的、写死寄存器地址的输出通道**，不需要完整驱动、不需要设备树解析，能在内核解压缩之后立刻工作。

### 用 `boot_delay` 排查"刷屏看不到"

```
boot_delay=100        # 每条 printk 之间延迟 100ms
```

启动信息刷太快看不清时用；代价是启动变慢（100 条消息 = 10 秒）。

## /dev/console：用户态的"标准输出"

内核在 `init/main.c:1504`：

```c
/* Open /dev/console, for stdin/stdout/stderr, this should never fail */
void __init console_on_rootfs(void)
{
        struct file *file = filp_open("/dev/console", O_RDWR, 0);
        ...
        pr_err("Warning: unable to open an initial console.\n");
}
```

**PID 1 的 fd 0/1/2 就是这个文件**，之后所有子进程继承。

⚠️ **失败不 panic，只打一行 Warning** —— 后果是：

- 系统"起来了"，但**一个字都不打印**
- 你以为死机了，其实 init 跑得好好的
- 这是 bring-up 阶段最折磨人的故障之一

**所以 rootfs 里必须有 `/dev/console`**（`mknod dev/console c 5 1`，或开 devtmpfs）。

## 串口接线与工具

### 硬件

| 信号 | Pi 5 引脚 | 接 USB-TTL 的 |
|------|----------|--------------|
| GND | Pin 6 | GND |
| TXD (GPIO14) | Pin 8 | **RXD** |
| RXD (GPIO15) | Pin 10 | **TXD** |

⭐ **TX 接 RX、RX 接 TX**，交叉接。接反了完全没输出（这是新手最常见的错误，没有之一）。

⚠️ **电平**：Pi 是 **3.3V**，不要接 5V 的串口模块（会烧 GPIO）。买标注 "3.3V/5V 可切换" 的，拨到 3.3V。

### 主机侧工具

```bash
# Linux / WSL
sudo apt install picocom
picocom -b 115200 /dev/ttyUSB0            # 退出：Ctrl-A Ctrl-X

# 或用 screen
screen /dev/ttyUSB0 115200

# Windows
#   PuTTY → Serial → COM3, 115200, 8N1, 无流控
```

| 参数 | 值 |
|------|-----|
| 波特率 | **115200**（Pi 默认） |
| 数据位/校验/停止位 | 8 / N / 1 |
| 流控 | **None**（必须关，否则无输出） |

## 有日志之后：看什么

```bash
# 内核环形缓冲区（含 early boot）
dmesg -T | head -80                  # -T 转成可读时间（注意是相对启动的秒数）
dmesg -T --level=err,warn            # 只看错误警告

# 持续跟踪
dmesg -w

# 当前控制台是谁
cat /sys/devices/virtual/tty/console/active      # → ttyAMA0
cat /proc/consoles                                # 带是否启用、是否 bootconsole

# 内核命令行（确认参数真的传进去了）
cat /proc/cmdline
```

⭐ **第一件事永远是 `cat /proc/cmdline`** —— 确认你以为传进去的参数真的在。很多时候改了 `cmdline.txt` 但改错了分区（Pi 5 的 boot 分区是 `/boot/firmware/`，不是 `/boot/`）。

## HFT / 嵌入式关联

- **"不致命的 Warning 让你看起来像死机"** —— 这条在 HFT 里对应**告警静默失效**。监控链路自己挂了却没告警，是最危险的状态。所以生产系统要有 **dead man's switch**（心跳缺失即告警），不能依赖"出问题会有人喊"。
- **串口是唯一不依赖网络、不依赖文件系统、不依赖驱动的观测通道**。HFT 生产机的等价物是**独立的管理网口 / IPMI / 带外管理**：交易网断了、系统卡死了，你还能进去看。这条通道必须**事先验证可用**，不能等出事才发现没接。
- `earlycon` 的思路（**在完整机制就绪前先给一个最小可用通道**）值得借鉴：任何复杂系统都应该有一个"最小可观测层"，它简单到几乎不可能坏。

<details>
<summary>Q1：为什么我加了 <code>console=ttyAMA0,115200</code> 还是没输出？</summary>

按概率排查：

1. **TX/RX 接反了**（最常见）→ 交换试试
2. **电平不匹配**（5V 模块接 3.3V）→ 换模块或确认拨到 3.3V
3. **Pi 5 的 `enable_uart=1` 没加**（`config.txt`）
4. **波特率不对**（不是 115200）
5. **流控没关**（终端软件里 Flow Control 要设 None）
6. **内核参数没生效** → `cat /proc/cmdline` 确认（改了 `/boot/cmdline.txt` 而不是 `/boot/firmware/cmdline.txt`）

判据：**如果连 U-Boot/固件的启动信息都看不到**，问题在 1–5（硬件层）；**如果固件信息看得到、内核的看不到**，问题在 6 或内核配置。
</details>

<details>
<summary>Q2：<code>/dev/console</code> 和 <code>/dev/ttyAMA0</code> 有什么区别？</summary>

- `/dev/ttyAMA0` 是**具体的串口设备**
- `/dev/console` 是**系统控制台的别名**（字符设备 5:1），它指向哪个实际设备，由**最后一个 `console=` 参数**决定

直接往 `/dev/ttyAMA0` 写，永远写到那个串口；往 `/dev/console` 写，写到"当前系统控制台"。

**好处**：程序不需要知道自己跑在什么硬件上，写 `/dev/console` 就对了。这是**间接层**的典型用法。
</details>

<details>
<summary>Q3：printk 的日志级别和"为什么有的消息没打出来"？</summary>

每条 printk 有级别（0 emerg … 7 debug）。内核只把**级别 ≤ `console_loglevel`** 的消息送到 console：

```bash
cat /proc/sys/kernel/printk
#   7    4    1    7
#   ↑    ↑    ↑    ↑
#  控制台级别  默认消息级别  最低允许  启动时默认
```

第一个数是 `console_loglevel`：只有级别比它**更紧急**（数值更小）的消息才会显示。

调试时临时放开：`echo 8 > /proc/sys/kernel/printk`（显示全部，含 debug）。
或用 `dmesg -n 8`。
</details>
