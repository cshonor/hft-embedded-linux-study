学习重心：绝大多数嵌入式项目盯 SoC

选型 / 求职优先级 · 锚定 Primer Ch3
分类标准：notes.md · 树莓归类：3.2-raspberry-pi-is-soc.md

结论

普通嵌入式 Linux：重心放在 SoC。
独立处理器（+南北桥）只作拓展；除高端电信/刀片等赛道，不必当核心课。

一、约九成以上项目：SoC（必学）

典型产品

域 例子
消费 树莓派、手机/平板、路由、机顶盒、相机、车机、智能屏
工业 HMI、小型网关、采集终端、运动控制主板
通信中端 家用 / 中小企业交换类
开发板 Beagle（OMAP）、i.MX、树莓、全志 / 瑞芯微等

为何行业押 SoC

  1. BOM / PCB：单片集成 CPU、内存控制器、网/USB/显示/串口等，免经典南北桥，成本与面积友好
  2. 周期：原厂 BSP（U-Boot、内核、驱动）齐，少从零啃芯片组
  3. 匹配需求：低功耗、小体积；GPU/多媒体/以太正好喂 Linux 图形与网络
  4. 贴合本书：i.MX、OMAP、Broadcom MIPS、AMCC PPC440 等案例都是 SoC；U-Boot / 裁核 / rootfs / 驱动主线按 SoC 讲

工程师日常（几乎都围着 SoC）

  • U-Boot、设备树
  • 内核裁剪、外设驱动（网、USB、LCD、SD、Camera…）
  • rootfs（BusyBox、Buildroot / Yocto）
  • 应用 / GUI / 网络 / 多媒体
  • 功耗、启动时间、（软）实时调优

本仓库对齐：11 Primer→MELP · 09 驱动·DT · 13 Pi Labs · 07 ARM。

二、独立处理器 + 芯片组：小众高端

适用 代表（书中年代）
ATCA 机架、大型刀片、高性能信号处理、高端工控主机 Atom / Pentium M、MPC7448、IBM 970FX 等

中小项目少选的原因： 板子复杂（北桥+南桥）、调试面大（内存/PCI/总线）、功耗与尺寸不友好。
谁做： 大型通信设备等高端团队；消费 / 常规工业岗基本碰不到。Ch3 §3.1、§3.4（cPCI/ATCA）→ 速览 / 按需 即可。

三、学习与求职优先级

通用嵌入式 Linux（主流岗位）

全力吃透 SoC：

  1. 硬件：ARM（及下面 RISC-V）SoC、片内外设
  2. 软件：U-Boot、DT、内核配置、闪存/MTD 或 eMMC/SD、BusyBox、交叉编译、GDB
  3. 板子：树莓派、i.MX、全志等上手

工控、车载、网关、AI 终端等招聘叙事，绝大多数基于 SoC。

特殊赛道（高端通信 / 服务器工控）

再补：独立 CPU + 芯片组、ATCA/cPCI、PCIe 与桥片总线——细分技能，非通用刚需。

四、新趋势：仍是 SoC

RISC-V SoC（各家应用处理器）是新增主流，分类仍是集成 SoC；学习逻辑与 ARM SoC 同构（工具链 / DT / U-Boot / 内核），继续当重点，不必退回南北桥课。

3.2

原厂 BSP：开箱能跑，量产仍要大量改

FAQ · 锚定 Primer Ch3（SoC）· Ch4（内核工程）· Ch7（Boot / DT）
重心 SoC：3.0-focus-on-soc.md · 树莓归类：3.2-raspberry-pi-is-soc.md

结论

原厂确实给完整 BSP（内核、U-Boot、驱动、参考 DTS、工具链 / Yocto·Buildroot…），
但只保证 官方评估板 / 参考设计 开箱可用。
自研 PCB = 以 BSP 为模板做二次开发；不是「拷贝即量产」。

一、原厂会交什么（BSP 常见内容）

SoC 厂（NXP i.MX、TI、Broadcom、全志、瑞芯微等）板级支持包通常含：

  1. Linux 内核（源码和/或预编译）
  2. U-Boot（或厂商等价 boot）
  3. 片内外设驱动：USB、以太、SD、LCD、Camera、I2C/SPI/UART、编解码、PMIC…
  4. 参考设备树（绑在评估板原理图上）
  5. 工具链、Buildroot / Yocto 脚本、rootfs 模板
  6. 原理图、寄存器/TRM 类文档

评估板现实： i.MX / Beagle 等 — 按文档编镜像烧录，外设基本通。
树莓派： 官方镜像 + 内核树；不改板则刷机即用（Pi Labs）。

二、自研硬件：改在哪里（工作量主战场）

原厂 DTS/驱动对齐的是他们的板，不是你的原理图。

1. 设备树 — 几乎必改（Ch7 / 09 DT）

常见差异：

  • GPIO / 串口 / LED / 按键换脚
  • 存储：eMMC → NAND（MTD 分区重配）或换 SD 方案
  • 网：PHY 型号、复位脚不同
  • 屏 / Camera 换料
  • PMIC 电压与上电时序
  • 删掉不用的节点（多余 USB、音频）省资源与攻击面

改一脚也要动 DTS；严重时驱动时序一起调。

2. 驱动 — 分三档

类型 你通常做什么
片内模块（MAC、SDHC、UART、GPU…） 少重写；DTS 配引脚、时钟、DMA
板级外接芯片（PHY、屏、Codec、传感器） 原厂驱动当参考；换料就改驱动或重移植
自研外设 无现成驱动 → 字符/平台驱动从零写（本书 Ch8 · 12）

3. 内核裁剪与产品化（Ch4）

原厂 .config 求「演示全绿」→ 体积大、模块杂。量产常要：关无用驱动/协议/调试；可选 PREEMPT_RT；开机 logo / 日志策略；分区与 Flash FS 参数（JFFS2/UBIFS 等）。

4. U-Boot（Ch7）

DDR 颗粒、Flash/eMMC、环境变量、启动介质一变，就要改初始化与分区/env；不是「评估板 u-boot.bin 直接量产」。

三、两种人，两种工作量

路径 底层改动量 日常重心
只用不画板（树莓 / 原厂 EVK） 极小 应用、业务、偶尔 overlay
自研 PCB（同款 SoC 也一样） U-Boot + DTS + 部分驱动 + 内核配置 大规模 硬件适配 = 嵌入式 Linux 岗核心产出

四、两个误区

  1. 「SoC 内部固定 → 软件不用改」
    片内互联固定；引脚接到 PCB 的方式由原理图决定。换脚 = 改 DTS（常还要改时序/驱动）。

  2. 「厂家给了内核 → 不用懂底层」
    量产要抠启动时间、功耗、实时、磨损、安全。默认 BSP 达不到指标时，不懂内核 / DT / 存储 / FS 就无法调优。

五、和本仓库怎么用

你现在 含义
Project #1 跟树莓官方镜像 走「开发板用户」路径；先闭环应用与驱动课
以后自研板 / 改原理图 把现用 BSP 当模板；主课变成 DT + U-Boot + 驱动 + 裁核
读 Primer Ch3–4–7 先建立「BSP 从哪来、改什么」心智，再进 MELP 实操

总结

  1. 原厂 BSP 完整且能跑自家评估板
  2. 自研硬件：DTS 必改；外接驱动常改；Boot/内核必裁剪适配
  3. 工程师价值 = 在模板上做 板级适配 + 系统定制 + 缺件驱动，不是只会 dd 官方镜像
