> **本节讲什么：** `.config` 是怎么生成的、`=y` / `=m` / `=n` 的区别、以及**裁剪内核到底在裁什么**。

## 配置从哪来

```
arch/arm64/configs/defconfig        ← 架构默认（通用，很大）
arch/arm64/configs/bcm2712_defconfig  ← 厂商基线（Pi 5，★ 从这里开始）
        │  make bcm2712_defconfig
        ▼
     .config                        ← 实际生效的配置（隐藏文件）
        │  make menuconfig 修改
        ▼
     .config（更新） → make savedefconfig → defconfig（最小化回写）
```

**永远从厂商 `defconfig` 开始，不要从 `make defconfig` 或 `allnoconfig` 起步。** 前者是"能跑的基线"，后者是"学术练习"。

## 三种符号

| 符号 | 含义 | 产物 | 后果 |
|------|------|------|------|
| `=y` | **编进内核镜像** | 代码进 `Image`，启动时就在 | 功能一定可用；镜像变大 |
| `=m` | **编成可加载模块** | 生成 `.ko`，需要 `insmod` 或自动加载 | 镜像小；但依赖 rootfs 里有对应 `.ko` |
| `=n` | 不编译 | — | 功能不存在 |

**关键判断：哪些必须 `=y`？**

```
内核启动 → 挂载 rootfs → 才能读 .ko 文件
                    ↑
        这一步之前需要的功能，必须编进内核（=y）
```

所以这些**必须 `=y`**：

| 类别 | 例子 |
|------|------|
| 存储/文件系统 | MMC/SD 控制器、ext4、NVMe（若根分区在 NVMe） |
| 块设备层 | `CONFIG_BLK_DEV_*` |
| 控制台 | 串口驱动（`8250` / `amba-pl011`）、`CONFIG_SERIAL_*` |
| 网络启动相关 | NFS root 时需要网卡驱动 + `CONFIG_IP_PNP` |

**反例：** 把 ext4 编成 `=m`，内核启动挂载 rootfs 时找不到模块文件（因为 rootfs 还没挂上）→ **Kernel panic - not syncing: VFS: Unable to mount root fs**。这是新手最经典的启动失败原因。

## 常用配置命令

| 命令 | 作用 |
|------|------|
| `make bcm2712_defconfig` | 载入厂商基线 |
| `make menuconfig` | 交互式（ncurses）修改 |
| `make nconfig` | 新版交互界面（支持跳转搜索） |
| `make oldconfig` | 基于旧 `.config` 补问**新增**选项 |
| `make olddefconfig` | 同上，新增选项全取默认值（**脚本/CI 用这个**） |
| `make savedefconfig` | 把当前 `.config` 最小化后回写 `defconfig` |
| `make localmodconfig` | 只保留**当前已加载**的模块（裁剪利器） |

```bash
# 裁剪流程（本机已跑着目标系统的前提下）
make localmodconfig     # 按当前加载的模块大幅裁剪
make menuconfig         # 手工确认
make savedefconfig      # 回写成最小 defconfig
cp defconfig arch/arm64/configs/my_custom_defconfig
```

> `menuconfig` 里按 `/` 可以搜索符号名，显示结果里有 `Symbol: XXX [=y]` 和**依赖关系**。  
> 找不到某个选项，99% 是它的**依赖没满足** —— 看搜索结果里的 `Depends on:`。

## 裁剪到底在裁什么

| 裁掉的东西 | 收益 |
|-----------|------|
| 用不到的驱动 | 镜像变小；**少一次 probe**；少一份代码占内存 |
| 用不到的子系统（如 `CONFIG_BT`、`CONFIG_WIRELESS`） | 启动更快；攻击面更小 |
| 调试选项（`CONFIG_DEBUG_*`、`CONFIG_KASAN`） | **显著提升性能**，但丢掉调试能力 |
| `CONFIG_MODULES=n`（全静态） | 无模块加载开销；但失去灵活性 |

**反面：`=m` 不是万能的。** 模块相比 `=y`：

- ✅ 不占内核镜像空间
- ✅ 可以单独更新
- ❌ 有加载开销（启动时 `udev` 遍历 + 加载）
- ❌ 依赖 rootfs 里有对应文件（版本还必须匹配，见 [4.3](./4.3-modules-and-version-magic.md)）

## HFT / 嵌入式关联

- **裁剪 = 减少不确定性。** 每少一个驱动，就少一个可能在中断上下文跑、抢锁、制造延迟尖刺的代码路径。HFT 生产内核基本都是"什么都不开"的极简配置。
- **PREEMPT_RT 是配置层的第一个大抉择**：`CONFIG_PREEMPT_RT` 把大部分自旋锁变成可抢占的 rt_mutex、把中断线程化。**用吞吐换延迟确定性** —— 这是"延迟 vs 吞吐"权衡在配置层的体现（深入见 [05.5-modern-kernel](../../05.5-modern-kernel)）。
- **配置即契约**：`.config` 决定了内核 ABI，模块必须与之匹配。这个"版本一致"的思路在容器镜像、在 HFT 的部署包里都是同一条纪律。

## 代码自测

<details>
<summary>Q1：把根文件系统所在的磁盘驱动编成 <code>=m</code> 会怎样？</summary>

启动失败：`Kernel panic - not syncing: VFS: Unable to mount root fs`。
因为加载 `.ko` 需要先挂载 rootfs，而挂载 rootfs 需要该驱动 —— **死锁**。
解决：用 **initramfs/initrd** 先加载模块再挂载真 rootfs，或者干脆把驱动改回 `=y`。
</details>

<details>
<summary>Q2：<code>menuconfig</code> 里搜不到某个配置项，最常见原因是什么？</summary>

**依赖未满足。** 按 `/` 搜索，看结果里的 `Depends on: XXX`，先把依赖项打开（且依赖项自身也要满足其依赖）。
其次是搜索时用了错的名字（不带 `CONFIG_` 前缀搜）。
</details>

<details>
<summary>Q3：<code>make oldconfig</code> 和 <code>make olddefconfig</code> 的区别？</summary>

- `oldconfig`：遇到 `.config` 里**没有的新选项**时，**逐个交互式询问**；
- `olddefconfig`：新增选项**全部取默认值**，不问。

脚本/CI 里必须用 `olddefconfig`，否则会卡在交互提示上。
</details>
