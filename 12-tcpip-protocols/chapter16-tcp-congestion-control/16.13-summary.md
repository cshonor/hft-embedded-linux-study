## 核心知识矩阵

| 维度 | 要点 |
|------|------|
| 公式 | **W = min(cwnd, awnd)** |
| 经典 | 慢启动、拥塞避免、AIMD、Tahoe vs Reno |
| 改进 | NewReno、SACK、Limited Transmit、CWV |
| 高速 | **CUBIC**；BBR（扩展阅读） |
| 网络侧 | Bufferbloat、RED、**ECN** |
| 伪超时 | Eifel + 时间戳 |

---

## 易混速记

| 问题 | 要点 |
|------|------|
| **rwnd** vs **cwnd** | rwnd=接收方限制，cwnd=网络限制 |
| **发送窗口** | min(rwnd, cwnd) |
| **慢启动** | 指数增长（每 RTT 翻倍），"慢"是相对旧协议 |
| **拥塞避免** | 线性增长（每 RTT +1） |
| **超时 vs 快速重传** | 超时 cwnd=1（狠）；快速恢复 cwnd/2（温和） |

---

## HFT 核心关联

| 拥塞控制机制 | HFT 策略 |
|-------------|---------|
| AIMD 降速 | 行情走 UDP 不受影响 |
| 慢启动 | 预热 TCP 控制面连接 |
| CUBIC/BBR | 控制面够用，热路径不依赖 |
| ECN | 数据中心可启用，减少丢包 |
| Bufferbloat | 交换机小缓冲 + AQM |

**核心结论**：TCP 拥塞控制为"公共资源公平"设计，与 HFT"最低延迟优先"理念冲突。HFT 热路径用 UDP + QoS 隔离。
