# 11.9 DNS 与 IPv6 过渡

> 章级精读：[../study.md#ch11-9](../study.md#ch11-9)

## 本节核心目标

理解双栈环境下的 DNS 查询策略和 **Happy Eyeballs** 机制。

---

## 双栈 DNS

| 记录类型 | 地址 | 查询顺序 |
|----------|------|----------|
| A | IPv4 | 递归器并行或先查 |
| AAAA | IPv6 | 递归器并行或后查 |

双栈主机同时发起 A + AAAA 查询，选择策略因实现而异。

---

## Happy Eyeballs (RFC 6555)

问题：IPv6 查询先返回但连接失败 → 白等 IPv6 超时再回退 IPv4。

解决方案：

```text
1. 并行解析 A + AAAA
2. 优先尝试 IPv6 连接（如有 AAAA 记录）
3. 设短超时（~250ms）→ v6 失败快速回退 v4
4. 后续连接优先使用成功的地址族
```

```c
// getaddrinfo 的 RFC 6555 实现
struct addrinfo *result;
getaddrinfo("example.com", "443", &hints, &result);
// 现代系统在 connect 时实现 Happy Eyeballs
// 幕后: 并行尝试 v6 + v4，先连上的赢
```

---

## NAT64/DNS64

IPv6-only 客户端访问 IPv4-only 服务：

```
DNS64 合成: example.com → AAAA 64:ff9b::93.184.216.34
                                    ↑ NAT64 前缀
客户端连接 NAT64 网关 → 网关翻译为 IPv4 → 连接原始服务器
```

---

## HFT 关联

| IPv6 特性 | DNS 影响 |
|-----------|---------|
| AAAA 记录 | 递归器需支持双栈查询 |
| Happy Eyeballs | 首次连接有 ~250ms 延迟开销 |
| NAT64 | 不适合 HFT——翻译增加延迟 |

**HFT 建议**：固定使用 IPv4 或 IPv6，不做 Happy Eyeballs fallback。
