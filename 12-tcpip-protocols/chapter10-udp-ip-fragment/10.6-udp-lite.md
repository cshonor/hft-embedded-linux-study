# 10.6 UDP-Lite

> 章级精读：[../study.md#ch10-3](../study.md#ch10-3) · RFC 3828

## 本节核心目标

理解 UDP-Lite 的**部分校验**语义及其在音视频场景中的价值。

---

## 核心概念

标准 UDP 校验和覆盖**整个报文**（首部 + 全部载荷）。UDP-Lite 允许只校验**前 N 字节**：

```
┌──────────────────────────────────────────┐
│ UDP-Lite Header (8 bytes)                │
│   Coverage Length = N (校验覆盖的字节数)   │
├──────────────────────────────────────────┤
│ ←── 校验覆盖区域 (N bytes) ──→│ 未校验  │
└──────────────────────────────────────────┘
```

| 字段 | UDP | UDP-Lite |
|------|-----|----------|
| 长度字段 | UDP 报文总长 | **Coverage Length**（校验覆盖的字节数） |
| 校验范围 | 首部 + 全部载荷 | 首部 + 前 N 字节载荷 |
| 协议号 | 17 | **136** |

---

## 适用场景

- **音视频会议**：包尾若干字节损坏可接受（编解码器容错），但包头必须正确
- **无线链路**：误码率高，部分校验避免整包丢弃
- **卫星通信**：高延迟 + 误码，UDP-Lite 提高有效吞吐

---

## 代码示例

```c
// 创建 UDP-Lite socket
int fd = socket(AF_INET, SOCK_DGRAM, IPPROTO_UDPLITE);  // 136

// 设置校验覆盖范围（仅前 8 字节 = 首部）
int val = 8;
setsockopt(fd, SOL_UDPLITE, UDPLITE_SEND_CSCOV, &val, sizeof(val));
setsockopt(fd, SOL_UDPLITE, UDPLITE_RECV_CSCOV, &val, sizeof(val));
```

---

## HFT 关联

UDP-Lite 在 HFT 中**几乎不使用**——行情数据不允许任何字节损坏。但理解部分校验概念有助于设计应用层 FEC 策略：只保护关键头部（序号/时间戳），数据部分用冗余编码恢复。
