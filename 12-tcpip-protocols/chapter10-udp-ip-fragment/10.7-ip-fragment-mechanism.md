# 10.7 IP 分片

> 章级精读：[../study.md#ch10-5](../study.md#ch10-5) · [§10.7 算例](../study.md#ch10-6) · MTU：[ch03 §3.8](../../chapter03-link-layer/3.8-mtu.md)

## 本节核心目标

掌握 IPv4 **Identification、MF、Fragment Offset** 字段，理解「任一片丢失 → 整报文报废」的放大效应。

---

## 为何危险（UDP 开发者必背）

- 应用一次发送 **> MTU − IP头 − UDP头** → IPv4 路由器**可分片**
- 接收端重组：**一片丢失 → 全部片超时丢弃** → 应用看到**整包丢失**
- 丢包放大率：N 片中丢 1 片 = 100% 丢包（从应用视角）

---

## 关键字段

| IPv4 Header 字段 | 位宽 | 作用 |
|------------------|------|------|
| **Identification** | 16 | 同一原始报文的各片共享同一 ID |
| **Flags — DF** | 1 | Don't Fragment：超限则发 ICMP PTB |
| **Flags — MF** | 1 | More Fragments：1=后续还有片，0=最后一片 |
| **Fragment Offset** | 13 | 片在原始报文中的位置，单位 **8 字节** |

**为什么偏移以 8 字节为单位？** 13 位最大表示 8191，×8 = 65528，覆盖最大 IP 载荷。若用 1 字节单位则 13 位只能表示 8191 字节。

---

## 分片算例

条件：IP 总长 4020B（20B IP头 + 4000B UDP），MTU=1500

| 片# | MF | Offset（×8） | IP载荷 | 内容 |
|-----|-----|-------------|--------|------|
| 1 | 1 | 0 | 1480B | UDP头(8) + 应用数据(1472) |
| 2 | 1 | 185 | 1480B | 应用数据续 |
| 3 | 0 | 370 | 1040B | 应用数据尾 |

各片链路帧长：1500 + 1500 + 1060 = 4060B（额外 60B 来自 3 次 IP 头）

---

## IPv4 vs IPv6 分片

| | IPv4 | IPv6 |
|--|------|------|
| 谁分片 | **路由器**可分片（DF=0 时） | **仅源端**（扩展头） |
| 路由器行为 | 超限 → 分片或 ICMP PTB | 超限 → **直接丢弃** + ICMPv6 PTB |
| 应用影响 | 透明（但危险） | 必须自己 PMTUD 或控制包大小 |

---

## 现代实践

- **避免 IP 分片**：单 UDP ≤ **~1200–1400 B**（QUIC 常用 1200）
- **设置 DF 位**：`IP_MTU_DISCOVER = IP_PMTUDISC_DO`
- **PMTUD**：探测路径最小 MTU，应用层分包
- **v6**：路径用 PTB → [10.8](10.8-udp-pmtud.md)

---

## HFT 关联

| 风险 | HFT 影响 |
|------|---------|
| 分片丢失放大 | 行情包分片 → 丢一片 = 丢全部 → 延迟尖峰 |
| 重组缓冲消耗 | 大量分片占用内存 → 影响其他处理 |
| 重组延迟 | 多片到达间隔 → 增加抖动 |

**最佳实践**：行情包大小 ≤ 1400B，设置 DF 位，应用层分包 + 序号重组。
