# 20.1 单线程 Web 服务器

← [20 章节导读](./20-章节导读.md) · → [20.2 多线程与线程池](./20.2-多线程与线程池.md)

## 核心结论

1. `TcpListener::bind("127.0.0.1:7878")` 拿到监听器；`incoming()` 返回**阻塞迭代器**
2. 每个 `TcpStream` 用 `BufReader` 包一层，`lines()` 逐行读到空行即 header 结束
3. 响应格式必须是 `HTTP/1.1 200 OK\r\n\r\n` + body，**回车换行一个都不能少**
4. 单线程的天花板：**队头阻塞**

---

## 最小骨架

```rust
use std::io::prelude::*;
use std::net::TcpListener;

fn main() {
    let listener = TcpListener::bind("127.0.0.1:7878").unwrap();

    for stream in listener.incoming() {
        let mut stream = stream.unwrap();
        let mut buf = [0; 1024];
        stream.read(&mut buf).unwrap();

        let response = "HTTP/1.1 200 OK\r\n\r\n<html>hi</html>";
        stream.write_all(response.as_bytes()).unwrap();
        stream.flush().unwrap();
    }
}
```

### 为什么要用 `BufReader`

`TcpStream::read` **不保证一次读满**，TCP 是字节流没有消息边界。
按行解析必须用 `BufReader::lines()`：它内部缓冲，直到遇到 `\n` 才返回一行。

```rust
let mut reader = BufReader::new(&mut stream);
let request: Vec<String> = reader
    .by_ref()
    .lines()
    .map(|l| l.unwrap())
    .take_while(|l| !l.is_empty())   // 空行 = header 结束
    .collect();
```

HTTP 请求行以 `\r\n` 结束，`lines()` 会顺带把 `\r` 也吃掉。

## 致命缺陷：队头阻塞

```text
客户端A（慢，sleep 10s）──┐
客户端B ──────────────────┼──> 单线程服务器：串行处理
客户端C ──────────────────┘        B、C 必须等 A 处理完
```

`handle_connection` 是同步阻塞调用，只要有一个连接不返回，
**后面所有连接全部卡住**。这不是吞吐问题，是**延迟尾部分布**问题——
P99 会被最慢的那个请求拖爆。

> **HFT 视角**：这正是为什么低延迟系统里「任何一个 handler 都不允许阻塞」。
> 单线程事件循环（如 Redis、或 tokio 的单线程 runtime）能避免上下文切换，
> 但代价是**该线程上任何阻塞操作都会毁掉整个循环的延迟**。
> 生产上的两种选择：
> - 单线程 + 严格无阻塞（busy-poll、绑核）
> - 多线程/线程池 + 任务切分（本章 20.2 的路子）

## 易错点

| 现象 | 原因 / 修法 |
|------|-------------|
| 浏览器一直转圈 | 响应缺少结尾的 `\r\n\r\n`，或没 `flush()` |
| `lines()` 报 `InvalidData` | 请求含非 UTF-8 字节；改用 `read_until(b'\n')` 处理字节 |
| 读完 body 后卡住 | `lines()` 会一直等；用 `take_while(|l| !l.is_empty())` 停在空行 |
| 端口被占用 | 上一进程没退出；`SO_REUSEADDR` 或换端口 |

## 速记

```text
bind → incoming() 阻塞迭代 → BufReader::lines() → take_while 非空行 → 拼响应 → write_all + flush
                    ↑
              单线程 = 队头阻塞（P99 被最慢请求拖垮）
```
