5.1

定义并实例化结构体

结构体（struct）与元组类似：都能把多个值组合在一起；不同的是结构体为每一部分命名字段，不依赖位置顺序。

对应 demo：5.1-structs-demo

定义结构体

struct User {
    active: bool,
    username: String,
    email: String,
    sign_in_count: u64,
}

实例化与访问

字段顺序不要求与定义一致：

let user1 = User {
    email: String::from("someone@example.com"),
    username: String::from("someusername123"),
    active: true,
    sign_in_count: 1,
};

println!("{}", user1.email);

改字段、更新语法 → 见 5.1.1 / 5.1.2（不在此重复）。

函数返回结构体

fn build_user(email: String, username: String) -> User {
    User {
        email,
        username,
        active: true,
        sign_in_count: 1,
    }
}

字段初始化简写：变量名与字段名相同时可写 email, username。

元组结构体（tuple struct）

struct Color(i32, i32, i32);
struct Point(i32, i32, i32);

let black = Color(0, 0, 0);
  • Color 与 Point 是不同类型
  • 访问：black.0

类单元结构体（unit-like struct）

struct AlwaysEqual;
let subject = AlwaysEqual;

无字段；常用于实现 trait 但不存数据（第 10 章）。

5.2

使用结构体的代码例子：计算长方形面积

目标：计算长方形面积，并逐步重构代码，让数据更有“意义”。

对应 demo 项目：00-Book/05-structs/5.2-rectangles-demo/

版本 1：分别用变量表示宽高

fn area(width: u32, height: u32) -> u32 {
    width * height
}
  • 问题：width 与 height 是“关联数据”，但函数签名看不出来它们必须成对出现

版本 2：用元组组合宽高

fn area(dimensions: (u32, u32)) -> u32 {
    dimensions.0 * dimensions.1
}
  • 优点：只传 1 个参数，宽高被组合起来
  • 缺点：0/1 索引没语义，容易弄混（特别是后续做绘制、打印等）

版本 3：用结构体命名字段

struct Rectangle {
    width: u32,
    height: u32,
}

fn area(rectangle: &Rectangle) -> u32 {
    rectangle.width * rectangle.height
}
  • width/height 字段名让代码更清晰
  • 传 &Rectangle（借用）避免移动所有权：main 仍可继续使用 rect1
    这与第 4 章「引用与借用」一致

调试打印：Debug trait

结构体默认没有 Display（{}）也没有 Debug（{:?}）。详见 5.1.4 Debug / Display 与 Trait 约束（含 vs Python 鸭子类型）。

使用 {:?} / {:#?}

  1. 先派生 Debug：
#[derive(Debug)]
struct Rectangle { ... }
  1. 再用调试格式打印：
println!("rect1 is {:?}", rect1);
println!("rect1 is {:#?}", rect1); // 更漂亮的格式

dbg! 宏

dbg! 会打印： - 文件名与行号 - 表达式的值（Debug 格式） - 并返回该表达式的值

let scale = 2;
let rect1 = Rectangle {
    width: dbg!(30 * scale),
    height: 50,
};
dbg!(&rect1);

注意：dbg! 输出到 stderr，println! 输出到 stdout。

下一步

当前 area 还是一个独立函数。下一节会把它重构为 Rectangle 的方法（impl Rectangle { fn area(&self) -> u32 { ... } }）。

5.3

方法语法

在 impl 块里为类型定义方法（第一个参数是 self）和关联函数（无 self）。

对应 demo：5.3-method-syntax-demo（cargo run）

节 主题

三 无 ->、. 自动补引用、其它参数手动 &

五 实例方法 / 关联函数 vs Python
六 压缩版总表

一、从函数到方法

#[derive(Debug)]
struct Rectangle {
    width: u32,
    height: u32,
}

impl Rectangle {
    fn area(&self) -> u32 {
        self.width * self.height
    }
}
概念 说明
impl Type { ... } 该类型的实现块
方法 impl 内、第一个参数是 self 的函数
&self self: &Self 简写；Self = 当前类型
调用 rect.area()，不是 area(&rect)

二、三种 self

签名 含义 调用方 调用后实例
&self 不可变借用，只读 不必 mut 仍可用
&mut self 可变借用，可改字段 须 mut 仍拥有
self 拿走所有权 任意 move 失效 
impl Rectangle {
    fn area(&self) -> u32 { self.width * self.height }
    fn set_size(&mut self, w: u32, h: u32) { self.width = w; self.height = h }
    fn destroy_to_tuple(self) -> (u32, u32) { (self.width, self.height) }
    fn new(w: u32, h: u32) -> Self { Self { width: w, height: h } }
}

let mut rect = Rectangle::new(10, 20);
let _ = rect.area();                    // rect 仍可用
rect.set_size(50, 60);
let (w, h) = rect.destroy_to_tuple();   // rect 此后不可用

完整可运行示例 → demo 第一节。

三、自动引用与调用

为什么没有 ->

C：ptr->f() = (*ptr).f()。Rust 统一用 .，编译器按方法签名给 self 接收者 自动补 & / &mut：

方法签名 你写 编译器等价
fn area(&self) r.area() (&r).area()
fn set(&mut self, ...) r.set(30, 40) (&mut r).set(...)
fn into_data(self) r.into_data() 直接 move，不加引用 
r1.can_hold(&r2);
(&r1).can_hold(&r2); // 等价

口诀：点号左边（self）自动加引用；括号里其它参数不自动加 &。

带其它参数：can_hold

impl Rectangle {
    fn can_hold(&self, other: &Rectangle) -> bool {
        self.width > other.width && self.height > other.height
    }
}

rect1.can_hold(&rect2); // other 须手写 &

getter：方法名与字段同名

impl Rectangle {
    fn width(&self) -> bool { self.width > 0 }
}
// rect.width()  → 方法
// rect.width    → 字段

Rust 不自动生成 getter；字段私有时常用手写 getter 作只读 API。

四、关联函数与多 impl

关联函数（无 self）

不是方法；用 类型名::函数名 调用（如 String::from）。

impl Rectangle {
    fn square(size: u32) -> Self {
        Self { width: size, height: size }
    }
}

let sq = Rectangle::square(3);

多个 impl 块

同一类型可拆成多块，编译等价于一个大 impl，便于按功能分组：

impl Rectangle { /* 只读：area, can_hold */ }
impl Rectangle { /* 修改：set_size */ }
impl Rectangle { /* 关联：new, square */ }

demo 的 main.rs 即三块 impl。

五、对照 Python

Rust 调用 Python 近似
fn f(&self) u.greet() def f(self)
fn f(&mut self) mut u.set(...) 改实例属性
fn f(self) u.into_...() 无（消费对象）
无 self User::new() @staticmethod 
impl User {
    fn greet(&self) { /* ... */ }
    fn new(name: String) -> Self { User { name } }
}
Python Rust
self 隐式传入 显式第一个参数
区分静态/实例 @classmethod / @staticmethod 有无 self 参数
内存 无借用规则 & / &mut / self 绑定所有权

Trait 方法 → 10.2 trait。

六、记忆卡片

  1. 方法 = impl 里第一个参数是 self；关联函数 = 无 self → Type::f()。
  2. 三种 self：只读 &self · 改字段 &mut self（须 mut）· 消费 self（move）。
  3. 调用：统一 .；self 自动 & / &mut；其它参数手动 &。
  4. 多 impl：同类型可拆分，仅组织代码。

5.4

结构体与持久化（HFT 向）

← 结构体基础：5.1 · Serde/JSON：3.2 JSON 与编码

一句话：落地存盘/入库的结构化数据几乎都用 struct 规整字段；定义放 model/，读写放 db/（或 storage/）。

对应 demo：5.4-persist-json-demo（结构体 → JSON 文件 → 读回）

一、为什么持久化优先用结构体？

持久化 = 内存里的结构化数据 → 字节（JSON / Protobuf / 自定义二进制）→ 磁盘或数据库。

/// HFT 成交记录：入库、写日志文件时常用这样一个 struct 打包字段
struct Trade {
    order_id: u64,
    code: String,      // 持久化用 String；协议常量可用 &'static str
    price: f64,
    volume: u64,
    timestamp: u64,
}
  • 零散变量不好整体序列化；一张表 / 一条记录 = 一个 struct，列 ↔ 字段一一映射。
  • 不是只能用 struct：单个标量可直接写；一批关联字段必用 struct。

二、工程里 struct 放哪？

规范目录（HFT 常见）

src/
├── model/          # 只放数据模型 struct，不写 IO
│   ├── trade.rs
│   ├── quote.rs
│   └── mod.rs
├── db/             # SQL、文件 IO、序列化、落地
└── main.rs
层 职责
model Trade、Quote 等字段定义
db import model::*，序列化后写 MySQL / 文件

小工具/练习：struct 写在当前 *.rs 顶部，下面跟读写逻辑即可（见 demo）。

三、完整链路

  1. 收行情 → 填进 Quote（内存 struct）
  2. 序列化：serde / Protobuf → 字节
  3. db 层：写字节到文件或数据库 → 持久化
  4. 重启：反序列化 → 还原为 struct

四、派生宏（工业标配）

use serde::{Deserialize, Serialize};

#[derive(Debug, Clone, Serialize, Deserialize)]
struct Quote {
    stock_id: String,
    bid: f64,
    ask: f64,
}
  • Serialize：struct → JSON/二进制
  • Deserialize：字节 → struct

本地文件示例见 demo：cargo run 生成 trade.json 再读回。

六、编码：Rust UTF-8 ↔ 数据库 / 文件

Rust 端（硬性）

String / &str / str 语言层固定 UTF-8；serde_json、写文件输出的文本字节默认就是 UTF-8。Rust 里不能把字符串改成 GBK 存储，只能在字节边界用 encoding_rs 等转码（见 3.2 JSON 与编码）。

#[derive(Serialize, Deserialize)]
struct Trade {
    stock_name: String, // 内存 UTF-8 → JSON/入库全程 UTF-8 字节
}

数据库（推荐统一 utf8mb4）

项 建议
MySQL utf8mb4 + utf8mb4_unicode_ci（勿用阉割 3 字节 utf8）
PostgreSQL / SQLite 多数默认 UTF-8，一般开箱即用
建表 CHARSET=utf8mb4
连接串 charset=utf8mb4，驱动传输 UTF-8 
CREATE TABLE trade (
    order_no   VARCHAR(32),
    stock_name VARCHAR(64)
) CHARSET=utf8mb4;

三层统一：实例默认编码 → 表 CHARSET → 客户端连接 charset，与 Rust 对齐 → 零转码。

非 UTF-8 库（GBK 等）？

技术上可在入库前 UTF-8→GBK、出库再转回，但不推荐：易乱码、多一次转码、HFT 日志/中文备注增加线上风险。工业项目：库表连接全 utf8mb4。

文件

JSON / 文本日志：直接写 String（UTF-8）即可；二进制协议字段用 Vec<u8> / &[u8]，与文本编码无关。

七、HFT 提醒

  • 热路径日志/入库：model 定义清晰，冷路径再序列化；热路径避免频繁 clone 整包。
  • 线上报文解析多用 &[u8] 零拷贝（见 4.3）；落地存档再用 struct + 序列化。

八、和 C struct 的区别

C struct Rust struct
布局 内存排列 同样可控制布局（#[repr(C)] 等）
持久化 手写序列化 常配 serde 等派生，一键互转
