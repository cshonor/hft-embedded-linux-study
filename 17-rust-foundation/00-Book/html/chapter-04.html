4.1

Rust `const` 常量 vs `static` 静态变量

核心结论：const 是编译期字面替换，无独立内存；static 是运行时全局内存变量，有专属内存地址。二者语法、用途、规则差异很大。

对应 demo：00-Book/04-ownership/4.1-ownership-demo/（§0.6）
所有权背景见：4.1-什么是所有权.md

一、基础语法与位置

1. const 常量

  • 写法：const 名称: 类型 = 值;
  • 定义位置：全局顶层、函数内、代码块内都可以
  • 命名惯例：全大写，下划线分隔
const MAX: i32 = 100;

fn main() {
    const MSG: &str = "hello";
    println!("{}", MAX);
    println!("{}", MSG);
}

2. static 静态变量

  • 写法：static 名称: 类型 = 值;，可变需 static mut
  • 定义位置：只能在模块/文件顶层，禁止写在函数、代码块内部
  • 命名惯例：同样推荐全大写
static GLOBAL_NUM: i32 = 200;
static mut GLOBAL_MUT: i32 = 0;

fn main() {
    println!("{}", GLOBAL_NUM);

    unsafe {
        GLOBAL_MUT = 10;
        println!("{}", GLOBAL_MUT);
    }

    // ❌ 非法：函数内不能定义 static
    // static INNER: i32 = 99;
}

二、核心本质（最大区别）

const

编译阶段直接把值嵌入代码，运行时没有独立的全局内存地址。
相当于代码里的「文本替换」——用到它的地方，编译器直接塞对应值。

static

程序加载时分配一块全局内存，运行时存在唯一内存地址，整个程序共享，直到程序退出才释放。

const = 试卷上直接写死的标准答案；
static = 教室角落的公共储物柜，所有人都能读写。

三、可变性

const static
默认 永远不可变，无 const mut 默认不可变
可变 不支持 static mut，访问/修改须 unsafe（全局可变有线程安全风险）

四、取值与引用

const static
内存地址 无固定的 global 存储，编译期内联 有唯一全局地址
持久引用 需要 &'static T 时应改用 static &GLOBAL_NUM 为 &'static T
生命周期 无独立生命周期实体 数据生命周期固定为 'static

语义上：const 没有「专属 static 存储」；static 的引用始终指向那块全局固定内存。

五、赋值规则

初始值必须是编译期可计算的常量表达式，不能用运行时变量：

let a = 10;
const B: i32 = a;  // ❌ a 是运行时变量
static C: i32 = a; // ❌ 同样报错

六、作用域与访问

const：遵循普通作用域——定义在代码块内，出块后不能再访问；无内存释放，只是「看不见了」。

static：全局可见，整个项目任意位置都能访问，不受局部 {} 限制。

七、使用场景

用 const

  • 固定配置、魔法数字、固定文本
  • 只需固定值，不需要全局共享内存、不需要稳定 global 地址
  • 想放在函数内部局部使用

用 static

  • 需要全局共享同一块内存（全局状态、全局配置）
  • 需要获取数据地址、创建 &'static 引用
  • 极少数全局可变（优先线程安全类型，少用 static mut）

八、速查表

对比项 const 常量 static 静态变量
内存 无独立内存，编译期内联 全局独立内存，有内存地址
定义位置 全局/函数/代码块均可 仅文件/模块顶层
可变性 永久不可变 可 static mut（需 unsafe）
持久引用 无 global 存储，需 'static 时用 static &VAR → &'static T
生命周期 无独立实体 'static
访问范围 受局部作用域限制 全局任意访问

结合所有权

  • const：无栈/堆运行时内存，完全不涉及所有权、借用规则
  • static：全局内存，不属于任何局部变量，没有常规所有权转移，仅有借用/访问限制

九、const vs 字符串字面量 &'static str

结论：二者不是一回事。都不占用栈/堆常规内存，但存储与行为不同。

统一概念

字符串字面量 "abc"（&'static str） const 常量
存储 只读数据段（程序加载时载入，有固定地址） 编译期文本替换，运行时无专属内存
运行时 真实存在的只读内存 用到处直接替换成值，无单独「const 变量」实体

字符串字面量：只读段有真实内存

fn main() {
    let s = "hello";
    println!("{:p}", s); // 可以打印地址，指向只读段
}
  • "hello" → 只读数据段（有内存、有地址、运行时常驻）
  • s 是栈上引用，指向这块只读内存

数值 const：编译期内联

const NUM: i32 = 100;

fn main() {
    let a = NUM;
    println!("{}", a);
}

编译后等价于：

fn main() {
    let a = 100;
    println!("{}", a);
}

全程没有一块叫 NUM 的运行时内存，只是字面替换。

&NUM 在 Rust 里有时能编译，但引用的是编译器生成的临时副本，不是 NUM 的专属固定地址——因为 NUM 本身就不占独立存储。

const 存字符串：两层拆解

const TXT: &str = "rust";

fn main() {
    let s = TXT;
    println!("{:p}", s);
}
  1. 底层 "rust" 本体：仍在只读数据段（和普通字面量一样）
  2. const TXT 本身：编译期替换；写 TXT 编译后直接变成 &"rust"

是字符串字面量在只读段，不是 const 在只读段。
const 只是别名，帮你简写代码。

核心区别

对比项 &'static str 字面量 const
存储本质 运行时有独立只读内存，有地址 编译期替换，无自身内存
取地址 引用可打印地址，指向只读段 无专属存储可指
生命周期 自带 'static 无独立生命周期实体

通俗比喻： - 只读段的字符串 = 书里印好的固定文字 - const = 给这段文字起的外号——喊外号直接对应原文，外号本身不是新文字

一句话：字符串字面量真真切切在只读数据段；const 只是编译期名字替换。哪怕 const 包裹字符串，也只是引用已存在的只读段数据，const 自身依然无独立内存。

相关：4.1-什么是所有权.md §3 字符串字面量

4.2

引用与借用

用引用 (&) 使用值但不获取所有权，称为借用（borrowing）。

对应 demo 项目：00-Book/04-ownership/4.2-references-demo/
生命周期（'a、'static）详见：10.3 生命周期与引用有效性 悬垂引用专题：10.3.1 悬垂引用

有 & vs 无 &：move 还是借用（总览）

分界：赋值/传参右边不带 & → 所有权转移（move，对 String 等）；带 & / &mut → 只造引用，原变量仍拥有数据。

赋值

let a = String::from("hello");
let b = a;    // 无 &：move，a 失效
// let r = &a;  // 若 b=a 之后，a 已不能再用

let a = String::from("hello");
let b = &a;   // 有 &：b 借用 a，a 仍有效
println!("{a}");
右边 效果 原变量
a（无 &） 移交所有权 失效（String 等）
&a 不可变借用 仍可用
&mut a 可变借用（a 须 mut） 仍拥有；独占修改权

字面量：let s = "abc" 等价 let s: &str = "abc"，天生是引用，不是 String。

i32 等 Copy 类型赋值是拷贝而非 move → 4.1 什么是所有权 §Copy / Move / clone 对照表。

函数传参（同一套逻辑）

fn take(_s: String) {}       // 调用 take(s) → s 移入函数，外面 s 失效
fn borrow(_s: &String) {}     // 调用 borrow(&s) → 只借，外面 s 仍有效
fn touch(_s: &mut String) {}  // 调用 touch(&mut s) → 可变借，可改内容，仍不拿走所有权

let mut s = String::from("a");
take(s);
// borrow(&s); touch(&mut s);

两类变量（记忆）

  1. 所有者：String、Vec、String::from(...) — 手里有所有权；无 & 的赋值/传参会 move。
  2. 引用：&String、&str、&[u8] — 只借用；永远不单独拥有那份堆数据。

&mut 仍是借用，但能改原数据；同一时刻只能有一个活跃 &mut（互斥见下文）。Move 详解见 4.1 §移动。

引用语法

let s1 = String::from("hello");
let len = calculate_length(&s1);  // &s1 创建引用
println!("'{}' 长度 {}", s1, len);  // s1 仍有效

fn calculate_length(s: &String) -> usize {
    s.len()
}  // s 离开作用域，但不丢弃指向的数据（没有所有权）
  • &s1：指向 s1 的引用，不拥有数据
  • * 解引用：见第 8、15 章

引用赋给引用：&T 本身是 Copy

let src = String::from("abc");
let r1: &String = &src;
let r2 = r1;        // 复制栈上的指针值，不是 Move src
println!("{r1} {r2}"); // r1、r2 都有效，同时不可变借用 src
  • &T 实现了 Copy：赋值只多拷一个指针，不转移 src 的所有权。
  • 效果：多个不可变引用共存，指向同一数据源（借用规则仍禁止在有 & 时 &mut）。

三类赋值对照

写法 行为 src / 原变量
let b = src;（String） Move src 失效
let r = &src; 新建借用 src 仍拥有
let r2 = r;（r: &String） Copy 指针，多一个 & src 不变

&mut 赋值对比：&mut T 也实现 Copy（同样只拷指针），但同一时刻只能有一个活跃的 &mut，不能有两个可变引用同时写：

let mut s = String::from("a");
let m1 = &mut s;
// let m2 = m1;   // 若 m1 仍活跃，再 let m2 = m1 会复制指针——但第二行 &mut 会与规则 1 冲突
// 正确：在一个作用域里只保留一个 &mut，或用 `{}` 结束 m1 后再借

不可变 let r2 = r1 允许多份；可变借用靠互斥规则限制，不是靠「引用不能 Copy」。

两个 &：造引用（表达式）vs 引用类型（标注）

位置 写法 含义
变量/实参前 &s、&mut s 取值运算符，生成引用实例
冒号后 : &String、: &str 类型，表示变量/形参存的是引用 
let s = String::from("abc");   // s：拥有所有权
let r = &s;                    // 表达式 &s → 造出 &String
let r: &String = &s;           // 左：类型 &String；右：&s 赋值

函数同理：形参 arg: &str 是类型声明；调用 func(&st) 里 &st 是生成引用实参。

三行对照（一眼分清）

let r = &s;                 // ① 变量前的 &：造引用（表达式）
let r: &String = &s;          // ② 冒号后的 &：引用类型 + 右侧再造引用
let lit = "hello";            // ③ 字面量：等价 let lit: &str = "hello"; 编译器隐式当借用

口诀：变量前的 & 造引用；冒号后的 & 是类型；双引号字面量自动变成 &str（静态区 str 不能直接当变量类型，只能借）。

str 是 DST 本体；&str 是对 str 的借用，可存变量、可做参数。切片场景见 4.3.3 str 与 &str；借用互斥见 4.3.2。

不可变引用

默认引用是不可变的，不能通过引用修改数据：

fn change(some_string: &String) {
    some_string.push_str(", world");  // ❌ 错误
}
// cannot borrow `*some_string` as mutable, as it is behind a `&` reference

可变引用 &mut

要修改借用来的值，使用可变引用：

let mut s = String::from("hello");
change(&mut s);

fn change(some_string: &mut String) {
    some_string.push_str(", world");
}
  • 变量需为 mut
  • 传参用 &mut s
  • 函数签名为 &mut String

借用规则

规则 1：同一时间只能有一个可变引用

let r1 = &mut s;
let r2 = &mut s;  // ❌ 错误: cannot borrow `s` as mutable more than once
  • 避免数据竞争（多指针写、无同步）
  • 可用大括号限定作用域，错开可变借用：
{
    let r1 = &mut s;
}  // r1 离开作用域
let r2 = &mut s;  // ✓

规则 2：不可变与可变引用不能同时存在

let r1 = &s;
let r2 = &s;
let r3 = &mut s;  // ❌ 错误: cannot borrow as mutable (已有不可变引用)
  • 多个不可变引用可以共存（let r2 = r1 复制指针也算多份 &）
  • 只要还有存活的不可变借用，就不能再拿 &mut

案例：s.clear() 需要 &mut self（与 4.3.2 切片与借用规则 同源）

clear 签名：fn clear(&mut self) → 调用 s.clear() 等于向 s 申请可变借用。

let mut s = String::from("hello world");
let word = first_word(&s); // word: &str，占用 s 的不可变借用
s.clear();                 // ❌ E0502：word 还活着，不能再 &mut s
println!("{word}");

报错链：word 存活 → 不可变借用未结束 → clear 要的 &mut 被拒绝。

何时能 clear？ 不可变借用先结束，例如：

let mut s = String::from("hello world");
{
    let word = first_word(&s);
} // word 出作用域，不可变借用失效
s.clear(); // ✓

本地验证：rustc --edition 2021 compile_fail/slice_blocks_clear.rs（见 4.3-slices-demo）。

对比 usize 下标（4.3）：let idx = first_word_usize(&s) 返回纯数字，不产生借用 → s.clear() 能通过编译，但 &s[0..idx] 可能运行时越界——借用规则管不到数字。

&mut 互相冲突（补充小例）

let mut s = String::from("a");
let m1 = &mut s;
let m2 = &mut s;  // ❌ 规则 1：两个同时活跃的 &mut

let r = &s;
let m = &mut s;   // ❌ 规则 2：已有不可变 r 时不能 &mut

引用的作用域与 NLL

引用的作用域到最后一次使用为止（非词法作用域 NLL）：

let r1 = &s;
let r2 = &s;
println!("{} {}", r1, r2);  // r1、r2 最后一次使用
let r3 = &mut s;  // ✓ r1、r2 已“结束”，不重叠

悬垂引用

Rust 保证引用不会指向已释放的内存（悬垂指针）：

fn dangle() -> &String {  // ❌ 错误
    let s = String::from("hello");
    &s  // s 离开作用域被释放，返回的引用无效
}
  • 错误：missing lifetime specifier，返回值借用的数据不存在

  • 显式生命周期时，编译器用 'a 校验——局部数据无法满足约束（见 10.3）

  • 正确做法：返回拥有所有权的值，如 String：

fn no_dangle() -> String {
    let s = String::from("hello");
    s  // 转移所有权
}

引用规则小结

  1. 任意时刻：要么只有一个可变引用，要么只有多个不可变引用
  2. 引用必须有效：不能悬垂

与所有权的对比

方式 所有权 原变量
传值 移动 失效
不可变引用 &T 借用 仍可用
可变引用 &mut T 借用并可能修改 仍可用

二、字符串切片 &str（语法）

Range（左闭右开）

写法 等价
[0..5] 0～4
[..2] [0..2]
[3..] [3..len]
[..] 全切片 
let s = String::from("hello world");
let hello = &s[0..5];
let world = &s[6..11];

⚠️ 边界须在 UTF-8 字符边界，否则 panic。

first_word 返回 &str

fn first_word(s: &String) -> &str {
    let bytes = s.as_bytes();
    for (i, &item) in bytes.iter().enumerate() {
        if item == b' ' {
            return &s[0..i];
        }
    }
    &s[..]
}

as_bytes() 用来找下标 i；返回 &s[0..i] 而不是 i。
为何 s.clear() 会报错 → 只看 4.3.2，不在此重复。

let arr = [1, 2, 3, 4, 5];
let sl: &[i32] = &arr[1..3]; // [2, 3]

4.3

.1 `usize` 下标与悬空索引

← 主笔记：4.3 切片 · demo：4.3-slices-demo

旧方案：返回 usize

fn first_word_index(s: &String) -> usize {
    let bytes = s.as_bytes();
    for (i, &b) in bytes.iter().enumerate() {
        if b == b' ' {
            return i;
        }
    }
    s.len()
}

let mut s = String::from("hello world");
let idx = first_word_index(&s);
s.clear(); // 清空原字符串
// idx 仍是 5，但字符串已空 —— 悬空索引，编译器查不出（The Book 4.3 原话）

为啥 idx 是「裸数字」

  1. usize 只是栈上的普通整数：不存指针、不绑定 s、不带生命周期。
  2. 借用检查只管 &，不管普通数字：编译器不会追踪「5 对应哪段串、串有没有被 clear()」。

澄清：数字 5 本身不是悬空；在 clear() 后用 &s[0..idx] 访问才是悬空访问（类似 C：pos=5 后 memset 再 arr[pos]）。

char arr[] = "hello world";
int pos = 5;
memset(arr, 0, sizeof(arr));
// pos 仍是 5；arr[5] 越界

什么是悬空索引

  • 当初 5 表示：原串第 5 字节处是空格；
  • s.clear() 后 len() == 0，数字仍是 5，语义已失效；
  • 再 &s[0..idx] → 越界；clear 与 idx 可同存编译通过，常到运行时才 panic。

对照：usize vs 切片

对比 usize 裸下标 &str / &[u8]
本质 普通整数 绑定原容器的引用
原数据被改 数字不变，编译器不管 有切片存活时禁止可变修改
出错时机 往往运行时 往往编译期

&str 为何更安全 → 4.3.2 切片与借用规则。

HFT：Vec 报文缓冲区

// ❌ 裸 usize
let mut buf: Vec<u8> = receive_udp();
let split_pos: usize = 16;
buf.clear(); // split_pos 仍是 16 → 后续按下标解析悬空

// ✅ &[u8] 子切片
let part: &[u8] = &buf[0..16];
// buf.clear(); // part 仍存活 → 编译错误

小结

要点 一句
usize 只是数；用来访问已清空数据 → 悬空访问
切片 绑定原内存，编译期拦非法修改
4.3

.2 切片与借用规则（`&` / `&mut`）

← 主笔记：4.3 切片 · 通用规则：4.2 引用与借用 · demo：4.3-slices-demo

本章只讲：切片场景下，不可变借用和可变借用怎么互斥（first_word / clear 那条线）。

两条铁则（复习）

借用 数量 能做什么
&T 不可变 可多个 只读
&mut T 可变 同时最多一个 独占写

同一时刻：不能既有存活的 &，又申请 &mut 指向同一块数据。

完整条文、NLL、&mut 互斥小例 → 4.2。

切片活着，能不能改？

结论：切片存活期间，不能对「它借的那块数据」做需要 &mut 的修改；等借用结束（出作用域或 NLL 判定最后使用之后）才能改。

不是「因为有切片类型就不能改」，而是 切片 = 不可变借用 &；有存活的 &，就不能再对同一块数据申请 &mut。

哪些操作被挡住

let mut s = String::from("hello");
let slice: &str = &s[..];   // 不可变借用 s 堆上的字节

s.clear();    // ❌ 要 &mut self
s.push('!');  // ❌ 要 &mut self
// slice 还活着 → s 的堆内容被「只读锁」

凡是要 &mut self / &mut T 的写操作（clear、push、truncate、arr[i] = ... 等），在切片借用未结束前都会被编译器拒绝。

「取消掉」= 借用结束（不是手动 API）

Rust 没有「手动取消切片」的接口。借用会在下面情况自动结束：

方式 例子
出作用域 { let slice = &s[..]; } 花括号结束 → 可以 s.clear()
NLL（最后使用之后） println!("{slice}"); s.clear(); — 若 slice 之后再没用到，编译器可能认为借用已结束 
let mut s = String::from("hello world");
{
    let slice = &s[..];
    println!("{slice}");
} // slice 出作用域 → 借用结束
s.clear(); // ✓

能改 vs 不能改

情况 能不能改
没有存活 &str / &[T] 借这块数据 ✅ 可以 &mut 修改
有存活 &str = &s[..] ❌ 不能 clear / push 等要 &mut 的操作
多个 &str 同时借同一块 ✅ 可以（多个只读借用允许）
let idx: usize = 5（只是数字） ⚠️ 编译能过，但 clear 后按下标切可能 panic → 4.3.1
let p: &str = "abc"（静态字面量） ✅ 不借 s，不影响 s 的修改

数组切片同理

let mut arr = [1, 2, 3];
let sl: &[i32] = &arr[..];

arr[0] = 99; // ❌ 要 &mut arr，和 sl 冲突
// sl 出作用域或最后使用之后：
arr[0] = 99; // ✓

数据源在栈还是堆不影响规则——看谁在被借、谁在被改。

为什么要这样设计

若允许 clear 而 slice 仍指着堆里的旧字节 → slice 悬空。编译器在修改发生之前就拦住，比 C 里「改完才发现指针失效」安全。

案例：word: &str 挡住 s.clear()

fn first_word(s: &String) -> &str { /* &s[0..i] */ }

let mut s = String::from("hello world");
let word = first_word(&s); // 不可变借用 s 的堆字节
s.clear();                 // ❌ E0502
println!("{word}");

clear() 在要什么

fn clear(&mut self) → s.clear() = 向 s 申请整段堆数据的独占可变借用。

报错链（一步步）

  1. word 活着 → 占用 s 堆内存的不可变借用；
  2. clear() 要 &mut s；
  3. 不可变借用未结束 → 编译器拒绝。

何时能 clear

let mut s = String::from("hello world");
{
    let word = first_word(&s);
} // word 出作用域，不可变借用结束
s.clear(); // ✓

验证：rustc --edition 2021 compile_fail/slice_blocks_clear.rs。

关键：&str 借的是堆字节，不是「不算借用」

let mut s = String::from("hello world");
let word: &str = &s[0..5];
  • s：栈上 ptr/len/cap，字节在堆；
  • word：胖指针指向 s 在堆里的那一段。

借用检查看谁在用这块堆内存，不看表面类型：

写法 阻碍 clear？
let r: &String = &s ✅
let word: &str = &s[..] ✅ 一样
let idx: usize = 5 ❌ 不拦（见 4.3.1）

&str 切片 ≈ 给 s 挂上不可变借用；word 活着就拿不到 &mut 去 clear。

若 word 仍指着堆里的旧内容就清空 → word 会悬空 → 编译器提前禁止。

&String vs &str（效果）

let r: &String = &s;      // 借整个串对象
let word: &str = &s[..];   // 借堆里一段字节

对 clear 而言：二者都会锁 s 的堆数据，只要还有一个不可变借用存活，clear 就失败。

与 usize 的对比（一句话）

idx: usize 不产生借用 → clear 能通过 → 后面 &s[0..idx] 可能运行时越界。
word: &str 产生借用 → clear 编译失败 → 从根上避免悬空切片。

小结

要点 一句
切片活着 不能 &mut 改它借的那块数据，等借用结束才能改
铁则 有存活 & 就不能再 &mut 同数据
clear 要 &mut self，与 &str 切片冲突
&str 借堆字节，和 &String 一样挡 clear
usize 不借，规则管不到

4.3

.3 `str`、`&str` 与字面量

← 主笔记：4.3 切片 · & 语法：4.2 · demo：4.3-slices-demo

两层概念

概念 含义
str DST，不定长 UTF-8，不能 let x: str
&str 胖指针（地址 + 长度），可存变量、可当参数
"abc" 字面量进 .rodata 只读段 
let s = "abc"; // 多为 &'static str

背诵版：String vs &str 能不能改？

String 拥数据，能改内容；&str 只引用，不能改本体（最多换指向）。

String &str
关系 拥有堆数据 借用视图
改内容 ✅ push / push_str / clear 等 ❌ s[0] = ... 非法
换指向 N/A（不是指针变量） let mut r: &str = "a"; r = "b"; ✅
要改原串 直接 mut String 需 &mut str（长度仍不能变）→ 8.2 String 
let mut s = String::from("abc");
s.push('d'); // ✅ 变长修改

let mut r: &str = "abc";
r = "bcd";   // ✅ 换指向
// r.make_ascii_uppercase(); // ❌ &str 只读

let mut src = String::from("abc");
let m: &mut str = &mut src;
m.make_ascii_uppercase(); // ✅ 通过可变切片改 src 堆内容（ASCII 等）

let mut 变量：&str 换指向（不改只读区内容）

&str = 指针 + 长度。s = "你好" 只改变量里存的地址/长度，不碰原先 "hello" 在 .rodata 里的字节。

let mut s: &str = "hello";
println!("{s}"); // 指向静态区 "hello"

s = "你好";      // ✅ 换指向另一段静态 UTF-8
println!("{s}"); // "hello" 仍在只读段，内容未改

// s[0] = 'a';   // ❌ 不能改指向内存的内容

结构体字段同理 → 5.1.3 字段所有权。

struct User { name: &'static str }

let mut user = User { name: "zhangsan" };
user.name = "lisi"; // ✅ 只换 name 的指针；不改 "zhangsan" 字节

从 String 借出的 &str：let r: &st 只读；r = "abc" 若 r 是 mut &str 则换指向，不影响 st 堆上数据。

UTF-8：str / &str / String 全是 UTF-8

Rust 强制字符串语义为 UTF-8 字节序列（&[u8] 无此约束，HFT 二进制用 &[u8]）。

切片按字节下标，边界必须在 UTF-8 字符边界上，否则 运行时 panic（一般不是编译期报错）：

let text = "你好"; // 各 3 字节，共 6 字节
// let sub = &text[0..2]; // ❌ 运行 panic：切在「你」的中间
let sub = &text[0..3];    // ✅ 完整一个「你」
&str &[u8]
编码 必须合法 UTF-8 任意字节
切片 须在字符边界 任意切

安全切分：用 .chars()、.char_indices() 或 crate unicode-segmentation（ grapheme 更复杂时）。

两类 &str（类型相同，内存不同）

① &s[0..2] ② "hello"
数据在哪 String 的堆 .rodata 静态段
生命周期 绑 s 'static
s.clear() part 活着 → ❌（见 4.3.2） 与 s 无关 
let mut s = String::from("hello");
let part: &str = &s[0..2]; // 临时借用堆

let lit: &str = "hello";   // 静态只读，程序同寿

HFT：let tag: &str = "LOGIN" 零堆开销；&buf[..] 借 Vec 缓冲零拷贝。

字面量 vs String::from

let s = "abc"; String::from("abc")
类型 &'static str String（拥堆）
堆 不拷到堆 从静态区拷一份到堆
可改 否 是（push / clear）

为何不默认把 "abc" 变成 String？常量只读场景多，隐式堆分配浪费；要可变再显式 String::from。

内存布局（极简）

字面量：胖指针在栈，字节在 .rodata。

栈 (lit)                    .rodata
ptr,len ──────────►         a b c   （不 drop）

String::from：栈三元组 + 堆字节（drop 释堆）。

函数不能返回 str

// ❌ E0277：size not known at compile time
fn bad() -> str { "hello" }

fn good() -> &str { "hello" }                    // 常 &'static str
fn owned() -> String { String::from("hello") }   // 拥所有权

验证：rustc --edition 2021 compile_fail/return_str_dst.rs。

返回 场景
&str 字面量或 &s[0..2]（绑 s）
String 调用方独立持有、可改
str 非法

函数参数：优先 &str

fn first_word(s: &str) -> &str { /* ... */ }

first_word(&st);       // &String → &str（deref）
first_word(&st[..]);
first_word("lit");

详见 ER Item 05。

小结

要点 一句
str / &str DST 本体 vs 引用包装
两类 &str 堆切片 vs 静态字面量
返回值 不能 -> str；要实体用 String
4.3

.4 DST 与 Sized（动态大小类型）

← 主笔记：4.3 切片 · struct 栈/堆：5.1.5 · 4.3.3 str/&str

一句话：DST 本体不能直接当栈变量；栈上只能放 指针 / 胖指针 / Box，本体在堆、静态区或别处。

1. Sized vs DST

Sized DST
编译期大小 固定 未知（运行时才定）
例子 u32、Rect、String str、[T]、dyn Trait
裸变量 let r = Rect { ... }; ✅ let s: str; ❌ 
struct Rect { w: u32, h: u32 } // Sized，8 字节
let r = Rect { w: 1, h: 2 };   // 栈上整块实体

// let x: str = ...;            // ❌ 不能单独绑定 DST
let s: &str = "abc";            // ✅ 栈上胖指针，指向 .rodata

2. DST 的三种包装（栈里是指针）

胖指针 &str / &[T]（ptr + len，常见 16 字节）

let s: &str = "abc123";           // 本体：.rodata；栈：胖指针
let st = String::from("abc");
let s2: &str = &st[..];           // 本体：堆；栈：胖指针

let buf = vec![1u8, 2, 3];
let sl: &[u8] = &buf;              // 本体：堆 Vec；栈：胖指针

Box<str> / Box<[u8]>（栈上窄指针，本体在堆）

let b: Box<str> = Box::from("hello"); // 堆上 str 字节，栈上 Box 指针

Box<dyn Trait>（trait 对象，同样 DST + 堆）

数据本体在堆（或堆上 vtable 布局），栈上指针。

→ 为何必须 & / Box（Fn 示例 · 静态 vs 动态）：10.2.5 §一 !Sized 铁律

3. 与结构体字段对上

User { name: String } — String 是 Sized（栈上 ptr+len+cap），故 User 整体 Sized，变量 u 在栈；字符在堆。

User { name: &str } — &str 是 Sized 的胖指针，User 仍固定大小；name 只是栈上 16 字节指针，指向静态区或堆。

→ 5.1.5 三种布局

3.1 &String vs &str vs &[T]（胖指针指哪）

let s = String::from("abc");
// 栈：s { ptr, len, cap }  →  堆："abc" 字节

let p1 = &s;       // &String：指向【栈上 String 外壳】的引用
let p2 = &s[..];    // &str：【胖指针 ptr+len】→ 堆上 "abc" 字节
let p3: &str = "x"; // &str：胖指针 → .rodata（不是堆）
类型 指针形态 指向
&String 普通引用（单地址） 栈上的 String 变量
&str 胖指针（地址 + 长度） 堆 / .rodata / 任意 str 数据源
&[T] 胖指针 数据源在哪指哪（栈数组、堆 Vec 等） 
let arr = [1, 2, 3, 4];        // 数组在栈
let sl: &[i32] = &arr[..];      // 胖指针 → 栈里 arr 的元素

let v = vec![1, 2, 3];
let sl2: &[i32] = &v[..];        // 胖指针 → 堆上 Vec 缓冲区

规律：&T[..] / &str 永远是胖指针；不拥有底层数据，只是借用（s drop 后 &s[..] 悬空）。

4. 对比小代码

// Sized：栈实体
let r = Rect { w: 1, h: 2 };

// DST：只能包一层
let lit: &str = "hi";                    // 胖指针 → .rodata
let owned = String::from("hi");
let borrow: &str = &owned;               // 胖指针 → 堆
let on_heap: Box<str> = Box::from("hi"); // 窄指针 → 堆上 str 本体

// 函数返回
fn f() -> &str { "ok" }       // ✅ 借 static
fn g() -> String { owned }    // ✅ Sized，拥堆
// fn bad() -> str { ... }     // ❌ DST 不能作返回值类型

5. 记忆卡片

要点 一句
Sized let x = T 栈上可放实体（含 String 壳）
DST 不能 let x: str；要 &str / Box<str> 等
&str / &[T] 栈胖指针；数据在堆 / 静态区 / 栈（看来源）
&String 普通引用 → 栈上 String 壳
Box<str> 栈窄指针；str 本体在堆

小结

  1. Sized：变量可以是整块实体（全栈字段时全在栈；含 String 时壳栈、字堆）。
  2. DST：栈上只有指针；str/[T] 本体在堆 / .rodata / 借用处。
  3. 前后说法一致：纯 Rect 全栈；User{String} 壳栈字堆；&str 字段 = 栈上胖指针。
