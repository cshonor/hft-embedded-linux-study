8.1

Vector：用 `Vec<T>` 储存一系列的值

← 集合章入口 · 下一节：8.2 字符串（hub + 8.2.1–8.2.4 子笔记）

对应 demo：00-Book/08-collections/8.1-vector-demo/

一句话

Vec<T> = 堆上动态连续数组 — 同类型元素、自动扩容。对标 Java ArrayList、C++ vector。

一、三种创建方式

1. 空 Vec：Vec::new()

let mut v: Vec<i32> = Vec::new();

无元素时编译器无法推断 T；刚创建时通常不分配堆内存，第一次 push 才向堆申请空间。

Vec::new() 类型推断详解

核心：看「上下文」，不是看单行

let mut v = Vec::new(); 本身没错 —— Rust 会结合同作用域里前后代码一起推断 v 的类型。
只要某处能确定 T（常见是后面 push(5i32)），就不必写 Vec<i32>；整段上下文都推不出 T 才报错。

① 没有任何推断线索 → 必须标注

// let mut v = Vec::new();              // ❌ 后面不用、前面也没有线索 → E0282
let mut v: Vec<i32> = Vec::new();       // ✅ 手动指定泛型
  • Vec::new() 创建空动态数组，创建时通常还没有元素；
  • 这一行单独看不出要存 i32 还是 String —— 要靠标注，或靠上下文推断。

② 后面有明确类型操作 → 可省略标注

let mut v = Vec::new();
v.push(5i32); // 编译器从 push 的值反推 Vec<i32>
v.push(20);

③ 前面/别处已有类型线索 → 也可省略标注

fn takes_vec(v: Vec<i32>) {}

let mut v = Vec::new();
takes_vec(v); // 从函数参数反推 v 必须是 Vec<i32>

（同理：赋给已标注类型的变量、匹配带类型的模式等，都能提供线索。）

④ 已手动标注后 push → 不用改标注

let mut v: Vec<i32> = Vec::new();
v.push(10); // 验证标注正确；只能继续 push i32

⑤ vec![] 自带元素 → 永远不用标注

let mut v = vec![1, 2, 3]; // 元素是 i32 → 自动推断 Vec<i32>
场景 要不要写 Vec<i32>
Vec::new() 且前后都没有类型线索 要（否则编译报错）
Vec::new() 后 push(5i32) 等能定类型的操作 不用
Vec::new() 后 传给 fn(Vec<i32>) 等 不用
vec![1, 2, 3] 不用

2. 初始化赋值：vec![] 宏（最常用）

let v = vec![1, 2, 3];   // 自动推导 Vec<i32>
let v2 = vec![0; 5];     // [0, 0, 0, 0, 0] — 仅 Copy 类型可用

vec! 编译期展开为 Vec::new() + 多次 push，是简写语法糖。

3. 预分配容量：Vec::with_capacity(N)（性能优化）

let mut v = Vec::with_capacity(10);
// 预先预留 10 个元素的空间，前 10 次 push 通常不触发扩容

关键概念：len vs capacity

含义
len() 当前真实存了多少个元素
capacity() 堆上已申请、能容纳多少元素（不扩容的前提下）

当 len == capacity 时再 push → 触发 realloc 扩容（申请更大块 → 拷贝 → 释放旧块）。

二、修改 Vec：push 追加尾部

修改必须 mut — Rust 不可变变量不能改内容。

let mut v = Vec::new();
v.push(5);
v.push(6);

三、生命周期：离开作用域自动销毁

{
    let v = vec![1, 2, 3];
} // v 调用 Drop：堆内存 + 所有元素释放，无泄漏

四、两种读取：[] 下标 vs .get()（必考）

代码原样

let v = vec![1, 2, 3, 4, 5];

// ① [] 下标取值
let third = &v[2];
println!("{}", third); // 输出 3

// ② get() 取值，返回 Option<&T>
match v.get(2) {
    Some(val) => println!("{}", val),
    None => println!("无该元素"),
}

核心区别

写法 越界（如 v[10]） 返回类型 使用场景
&v[下标] panic 崩溃、程序终止 &T（元素引用） 100% 确定下标合法；追求简洁；出错直接崩
v.get(下标) 不崩溃，返回 None Option<&T> 下标来自用户输入、不确定越界；需容错

可变版本：get_mut()

let mut v = vec![1, 2, 3];
if let Some(val) = v.get_mut(1) {
    *val = 99; // Option<&mut T>
}
// v == [1, 99, 3]

越界一眼看懂

let v = vec![1, 2, 3];
// &v[10];  // ❌ 运行 panic

assert!(v.get(10).is_none()); // ✅ 返回 None，程序继续

确定下标没问题 → [] · 下标不确定、可能越界 → 必用 get()，靠 Some/None 处理

选型口诀（必背）

场景 读 改
下标确定合法 &v[i] v[i] = x（v 须 mut）
下标不确定 v.get(i) v.get_mut(i)

确定下标用 []，不确定用 get / get_mut。

五、经典报错：有不可变引用时不能 push（核心难点）

let mut v = vec![1, 2, 3, 4, 5];
let first = &v[0];
v.push(6); // ❌ 编译报错 E0502
println!("{}", first);

底层原理（扩容）

  1. first 保存堆上某个地址的不可变借用；
  2. 若 len == capacity，push 可能 realloc： - 堆上开更大新块 - 拷贝所有元素到新地址 - 释放旧堆内存
  3. 原 first 指向的旧内存已无效 → 悬垂引用；
  4. 借用检查器编译期拦截，杜绝野指针。

✅ 规避：引用用完再 push

let mut v = vec![1, 2, 3];
{
    let first = &v[0];
    println!("{}", first);
} // first 生命周期结束
v.push(6); // ✅

六、常用拓展方法

let mut v = vec![1, 2, 3];
v.pop();            // 弹出末尾 Option<T>
v.remove(0);        // 删除指定下标（后面元素前移，O(n)）
v.clear();          // 清空元素，capacity 通常保留
v.shrink_to_fit();  // 释放多余空闲内存，让 capacity ≈ len

七、遍历

不可变遍历

let v = vec![100, 32, 57];
for i in &v {
    println!("{}", i);
}

可变遍历并修改

let mut v = vec![100, 32, 57];
for i in &mut v {
    *i += 50;
}

*i 解引用 → 第 15 章

八、用枚举在 Vec 中存多种类型

Vec 只能存同一类型；混合类型用 enum 包装：

enum SpreadsheetCell {
    Int(i32),
    Float(f64),
    Text(String),
}

let row = vec![
    SpreadsheetCell::Int(3),
    SpreadsheetCell::Text(String::from("blue")),
    SpreadsheetCell::Float(10.12),
];

编译期无法确定类型集合时 → trait 对象（第 17 章）。

cd 00-Book/08-collections/8.1-vector-demo
cargo run

8.2

.1 `str`、DST 与定长规则

← 主笔记：8.2 字符串 · 下一篇：8.2.2 不定长放哪

结论：三个核心问题（一次拆干净）

# 结论
1 str 是 DST：编译期不知占多大 → 不能 let s: str 放栈；只能靠 &str 胖指针（栈上）间接访问
2 字面量 "abc" 的字节在 .rodata 只读常量段，既不在栈也不在堆
3 只有 String 把字符数据放堆；&str 永远是栈上胖指针，指向别处的 str 数据

→ 放哪详解：8.2.2 · 'static 与 .rodata：8.2.2 §五

结论（两句）

  1. str 是 DST（不定长）：不能 let s: str，要用 &str 等定长外壳。
  2. 「不定长」≠「一定在堆」 → 8.2.2

一、定长 vs 不定长

栈的规则

栈上不能直接放不定长类型（str、[T]）当独立变量——编译期不知道占多少字节。

定长（可直接放栈）

类型 说明
i32、bool 大小固定
[u8; 4] 长度写死在类型里 
let a: i32 = 10;
let buf: [u8; 4] = [0; 4];

不定长（str、[T]）

str = 连续 UTF-8 字节；不同文本长度不同 → DST，与 [u8] 同类。

二、为什么不能用 let s: str？

// let s: str = "abc"; // ❌
  1. 编译器不知道栈上留多少字节；
  2. Rust 禁止编译期大小未知的类型当栈变量。

规定： 必须搭配带长度的引用 → &str（胖指针：ptr + len，本身定长）。

str = 不定长毛坯字符块（尺寸飘忽，没法单独装箱放栈）
&str = 固定大小的小纸条（ptr + len），纸条在栈上，指向别处数据

let s: &str = "abc"; // ✅ 栈上是「书签」，不是整本书

栈:  &str { ptr, len }  ──►  [ a b c ]

三、极简背诵

  1. str：不定长；不能 let s: str。
  2. 铁律：栈上不能直接存不定长变量 → 用 &str、String 等定长外壳。
  3. &str：栈上定长胖指针，指向别处的 str 数据。

→ 数据在静态/栈/堆：8.2.2 · String：8.2.3 · 底层布局：8.2.5

8.2

.2 不定长数据放哪（静态 / 栈 / 堆）

← 8.2.1 str 与 DST · 主笔记：8.2 · 下一篇：8.2.3 str 与 String

核心三句

  1. 字面量 "abc"：字节在 .rodata 只读常量段，不在栈、不在堆
  2. String::from(...)：堆上存 UTF-8 字节（本体类型仍是 str）
  3. &str：永远只是栈上胖指针，指向 .rodata / 堆 / 栈数组中的某段 str

场景 1：字面量 → .rodata 只读常量段

let s: &str = "abc";
  1. 字节 [97, 98, 99] 编译期打进二进制 .rodata；运行时 OS 映射进进程，只读、全程存活
  2. 不在栈：栈是函数临时区，函数结束即回收；字面量全局存活
  3. 不在堆：堆是运行时 alloc 动态申请；字面量内容编译期已定，无需堆

变量 s 在栈：类型常为 &'static str，只存 ptr + len（3）：

字段 指向
ptr .rodata 里 'a' 的地址
len 3

场景 2：String → 堆；as_str() → 借堆

let owned = String::from("abc"); // 栈：String{ptr,len,cap}；堆：[97,98,99]
let borrow: &str = owned.as_str(); // 栈：&str 胖指针 → 指向 owned 的堆字节
  • 堆上字节本体类型本质是 str（DST）
  • 不能直接持有「堆上裸 str」，只能通过 &str 访问

场景 3：数组切片 → 本体常在栈

let arr = [1, 2, 3];
let slice: &[i32] = &arr;

定长数组在栈；&[i32] 指向的数据常跟数组一起在栈上。

总结表

写法 本体 str 数据在哪 栈上有什么
"hello" .rodata 只读段 无（仅字面量）；let x: &str = "hello" → x（胖指针）在栈
String::from("hello") 堆 String { ptr, len, cap }
owned.as_str() 同 String（堆） &str 胖指针在栈

五、'static 与 .rodata

字面量的 'static 从哪来？

对。 字符串字面量 "abc" 的类型是 &'static str，因为：

  • 数据在 .rodata，程序整个生命周期有效
  • 引用 'static = 「活得和整个程序一样长」

'static 不只来自 .rodata

来源 例子
字面量 "hello" → &'static str（数据在 .rodata）
泄漏到堆 Box::leak(s.into_boxed_str()) → &'static str（数据在堆，但永不释放）
全局 static static S: &str = "x";

口诀：字面量 'static 因为 数据在 .rodata；但 'static 含义是生命周期，不限于 .rodata 一种来源。

DST 通用规律（不止 str）

本体（DST） 胖指针（栈上定长）
str &str
[T] &[T]

裸 [T] / str 不能单独当栈变量；靠胖指针借。

规律小结

  1. str 本体：不单独上栈（长度不确定）
  2. 字面量：数据在 .rodata，不走堆
  3. 动态字符串：数据在 String 的堆，靠 &str 借用

→ 底层布局：8.2.5 · String 互转：8.2.3

.3 `str` 与 `String`：区分与互转

← 8.2.2 不定长放哪 · 主笔记：8.2 · 下一篇：8.2.4 UTF-8 实操

demo：8.2-string-demo/（§1–§4 偏 String 操作）

一、str / &str
本质 UTF-8 字符序列（本体）
大小 不定长（DST）
栈变量 ❌ let x: str；✅ let x: &str
所有权 借用 
let s: &str = "hello world";

二、String
本质 定长 struct（ptr / len / cap）
指向 通常堆上 UTF-8（可扩容）
栈变量 ✅ let s: String
所有权 有；出作用域 drop 堆 
let mut s = String::from("hello");
s.push_str(" world");

对照

&str String
栈上 定长引用 定长管理头
数据 只读段 / 某堆块 自己的堆
扩容 ❌ ✅

三、常见疑问

str 是本体，String 是包装？

✅ str = 纯数据；String = 定长容器，常见用法是堆上扩容。

str 只读吗？

形态 改内容 改长度
字面量 &'static str ❌ 只读段 ❌
从 String 借的 &str ❌ 共享借用 ❌
&mut str ✅ 原地改 ❌ 不能加长
String ✅ ✅

要变长、追加 → String。

口语「字符串变量」

  • 业务常说「一个 String」；
  • &str 多用于只读参数、fn foo(s: &str)。

四、三条链路 + 互转

let s1: &str = "hello";              // 静态段 + &str
let s2: String = String::from("hello"); // 拷到堆
let s3: &str = &s2;                  // 借 String 的视图

let s = String::from("rust");
let r: &str = &s;                    // 零拷贝借

let r: &str = "rust";
let s = String::from(r);             // 或 r.to_string()
写法 说明
&s 零拷贝借用
String::from / to_string 新堆 + 拷贝
format!(...) 得到 String

背诵

  • &str：定长书签在栈；指向静态/栈/堆上的 str。
  • String：定长头在栈；动态内容多在堆。

8.2

.4 UTF-8 字符串实操

← 8.2.3 str 与 String · 主笔记：8.2 · 下一节：8.3 HashMap

demo：8.2-string-demo/（§5–§7）

核心

String / &str 内容都是 UTF-8；.len()、切片按字节，不是「字符个数」。

新建与更新

let mut s = String::new();
let s = String::from("initial contents");
s.push_str("bar");
s.push('l');

let s1 = String::from("Hello, ");
let s2 = String::from("world!");
let s3 = s1 + &s2; // s1 被 move
操作 说明
push_str(&str) 追加 UTF-8 片段
push(char) 追加单个 Unicode 标量
s1 + &s2 s1 被 move；s2 仍可用
format!(...) 得到 String，不 move 参数

为什么不能用 s[i]？

// let h = s[0]; // ❌

类似 Vec<u8>；「第 i 个」是字节还是 char 语义不清，且不能保证 O(1) 随机访问。

字符串 slice（字节 range）

let hello = "Здравствуйте";
let s = &hello[0..4]; // "Зд" — 须在 UTF-8 字符边界上
// &hello[0..1]; // ❌ 运行 panic

遍历

for c in "नमस्ते".chars() { /* Unicode 标量 */ }
for b in "नमस्ते".bytes() { /* 字节 u8 */ }

记忆卡片

要点 一句话
.len() 字节数，不是字符数
索引 无 s[i]；用 .chars() / 字节 slice
slice range 必须在 UTF-8 边界上
拼接 + move 左操作数；format! 更灵活

8.2

.5 四种类型底层：`String` / `&str` / `[T;N]` / `&[T]`

← 8.2.1 str 与 DST · 8.2.2 不定长放哪 · 主笔记：8.2

demo：8.2-string-demo/ §8（size_of + 地址验证）

核心结论

# 规则
1 &str、 [T;N]、 &[T] 不是 struct，是编译器内置原生类型
2 String 是标准库用 struct 实现的堆字符串，能写出源码结构
3 切片（&str / &[T]）= 胖指针（ptr + len），无专属 struct，编译器语法糖
4 定长数组 [T; N] = 栈上连续内存块，编译期布局，不是 struct

一、String（标准库 struct，简化源码）

pub struct String {
    ptr: *mut u8,   // 堆上 UTF-8 字节起始地址
    len: usize,     // 有效字节数（非字符数）
    cap: usize,     // 已分配容量，cap ≥ len
}
位置 内容
栈 String 本身（64 位通常 24 字节 = 3×usize）
堆 ptr 指向连续 u8 UTF-8 字节 
let s = String::from("abc");
// ptr → 堆 [97, 98, 99]；len = 3, cap ≥ 3

二、&str：不是 struct，胖指针

逻辑等价（不能在 Rust 里真这么定义 &str）：

// 仅理解用
struct StrFatPtr {
    data: *const u8,
    len: usize,
}
// &str ≈ (data, len)，64 位通常 16 字节

&str 永远借用别处内存：

来源 数据在哪
"abc" 字面量 只读程序段（&'static str）
&s[..] 借 String 的堆 
let s = String::from("hello");
let slice: &str = &s[..];
// slice 的 ptr/len 指向 s 的堆字节

三、[T; N]：编译器原生栈连续内存

let arr: [i32; 3] = [1, 2, 3];
// 栈上连续 3 个 i32，无 ptr/len/cap 字段
  • 定长、编译期知 N；
  • 不能扩容；
  • 不是 struct 封装。

四、&[T]：与 &str 同源的通用胖指针

// 逻辑等价
struct SliceFat<T> {
    start: *const T,
    len: usize,   // 元素个数（非字节）
}

let arr = [1, 2, 3, 4];
let slice: &[i32] = &arr[1..3]; // 元素 [2, 3]，len = 2

五、对照表

类型 底层实现 数据常见位置 栈上占多少（64 位典型）
String struct {ptr,len,cap} 结构体在栈，数据在堆 24 B
&str 胖指针 (ptr, len) 数据：静态段/堆；切片在栈 16 B
[T; N] 原生连续内存 全在栈（或静态） N × size_of::<T>()
&[T] 胖指针 (ptr, len) 依附原数组；切片在栈 16 B

补充：Vec<T> 与 String 同源

pub struct Vec<T> {
    ptr: *mut T,
    len: usize,
    cap: usize,
}

String ≈ Vec<u8>，额外保证内容为合法 UTF-8。

→ 见 8.1 Vector

String（栈 24B）          堆
┌ ptr ──────────────────► [ u8 u8 u8 ... ]

8.3

.1 `zip` → `collect` → `HashMap`

← 主笔记：8.3 HashMap · demo：8.3-hashmap-demo/ §2

一句话

两个 Vec 用 zip 拼成 (key, val) 元组迭代器 → collect 按类型标注装进 HashMap 集合。

角色 是什么
zip 迭代器方法，配对两个迭代器（不属于集合本身）
collect 迭代器终结者，把数据打包成 Vec / HashMap / …
HashMap std::collections 里的最终容器

1. zip：两个迭代器一对一配对

let k_list = vec!["A", "B"];
let v_list = vec![10, 20];

// k_list.iter().zip(v_list.iter())
// 产出：(&"A", &10), (&"B", &20)  — 元组迭代器
  • 左 + 右捆成 (左, 右) 元组
  • 长短不一以短的为准，多余丢弃

2. collect：按类型标注决定容器

.collect() 能把迭代器收进任意集合 —— 靠左侧类型标注：

// 收进 HashMap
let map: HashMap<_, _> = k.iter().zip(v.iter()).collect();

// 不收进 HashMap，默认思路是 Vec<(K,V)>
let pairs: Vec<_> = k.iter().zip(v.iter()).collect();

没写 HashMap<_, _>，编译器不知道你要字典，必须标注（或靠上下文推断）。

HashMap<_, _> 里的 _

_ = 让编译器自动推导 K、V 类型，不必手写 HashMap<String, i32>。

3. 与 Collection（集合）的关系

std::collections = Rust 标准库集合包：

HashMap · Vec · HashSet · BTreeMap … 都是 Collection

zip（迭代器配对）
    ↓
collect（按标注选容器）
    ↓
HashMap / Vec / …（集合载体）
  • zip：只负责配对（迭代器层）
  • collect：负责存入集合
  • HashMap：键值字典这种具体容器

完整代码

use std::collections::HashMap;

let keys = vec![String::from("蓝"), String::from("黄")];
let vals = vec![10, 50];

// iter → (&String, &i32)；into_iter → (String, i32) 所有权
let map: HashMap<_, _> = keys.iter().zip(vals.iter()).collect();

iter vs into_iter（常混）

链 Map 里存的 K/V
keys.iter().zip(vals.iter()) &String, &i32
keys.into_iter().zip(vals) String, i32（move 进 Map）

→ demo 用 into_iter().zip() 便于 map["A"] 用 &str 查。

流程图

Vec keys ──iter/into_iter──┐
                          ├── zip() ──► (K,V) 迭代器 ──collect()──► HashMap
Vec vals ──iter/into_iter──┘              ▲
                                          │
                              类型标注 HashMap<_,_>

.2 创建与删除

一、四种创建方式

1. new() + 逐个 insert

let mut scores = HashMap::new();
scores.insert(String::from("Blue"), 10);
scores.insert(String::from("Yellow"), 50);

insert(k, v) -> Option<V>：

情况 返回值
key 不存在 None
key 已存在 Some(旧值)，新值覆盖 
let old = scores.insert(String::from("Blue"), 99); // Some(10)

insert 的所有权规则、更新策略 → 8.3.3 §一、§四

2. 两 Vec + zip + collect

→ 完整原理：8.3.1 zip → collect → HashMap

let teams = vec![String::from("Blue"), String::from("Yellow")];
let init_score = vec![10, 50];
let scores: HashMap<_, _> = teams.iter().zip(init_score.iter()).collect();

3. HashMap::from([...])（Rust 1.56+）

let map = HashMap::from([("Blue", 10), ("Yellow", 50)]);

4. with_capacity 预分配

let mut map = HashMap::with_capacity(10);

已知大约要插多少条时，少几次扩容。

二、删除

let mut map = HashMap::from([("A", 1), ("B", 2)]);
let val = map.remove("A");       // Option<V> → Some(1)，只删 value
let kv = map.remove_entry("B");  // Option<(K,V)> → Some(("B", 2))，K+V 一起拿走
方法 返回 用途
remove(&K) Option<V> 只要 value
remove_entry(&K) Option<(K,V)> key 也要 reuse

8.3

.3 核心 API：insert · get · 遍历 · Entry

← 主笔记：8.3 HashMap · demo：8.3-hashmap-demo/ §3–§5 §7

官方 Ch.8.3 日常操作四条线：怎么插 · 怎么查 · 怎么遍历 · 怎么更新。

一、insert 与所有权

let field_name = String::from("Favorite color");
let field_value = String::from("Blue");
let mut map = HashMap::new();
map.insert(field_name, field_value);
// field_name、field_value 移入 map → 后续不能用，编译报错
类型 insert 行为 原变量
无 Copy（String、自定义 struct） move 进 Map 失效
实现 Copy（i32、bool、u8） 拷贝 进 Map 仍可用 
let num = 10;
map.insert("A", num);
println!("{}", num); // ✅ i32 拷贝

想保留原数据：insert(&field_name, &field_value)，Map 存借用（生命周期须合规）。

二、get 取值：Option<&V>

三种写法（对标 Vec [] / get）

写法 返回 无 key 时 场景
map["key"] &V panic key 一定存在
map.get(&key) Option<&V> None key 不确定
map.get_mut(&key) Option<&mut V> None 修改 value 
let team_name = String::from("Blue");
let score = scores.get(&team_name); // Option<&i32>
  1. get(&key) 传键的引用，不消耗 key 所有权
  2. 存在 → Some(&V) 借用 Map 内数据；不存在 → None，不 panic
  3. contains_key(&key) 只判存在，不取值

常用链

let n = scores.get(&team_name).copied().unwrap_or(0);
// .copied()：Option<&i32> → Option<i32>（V: Copy）
// .unwrap_or(0)：取不到给默认值

if let Some(v) = scores.get_mut("Blue") {
    *v += 5;
}

三、遍历

for (key, value) in &scores {
    println!("{key}: {value}");
}
写法 元素类型 Map 之后
&scores / scores.iter() (&K, &V) 仍可用
for (k,v) in scores（无 &） (K, V) move 整个 Map，遍历后失效
scores.iter_mut() (&K, &mut V) 可改 value 
for k in map.keys() { /* … */ }
for v in map.values() { /* … */ }
for (_, v) in scores.iter_mut() { *v += 1; }
  • HashMap 无序，打印顺序随机

四、Entry：四种更新策略

map.entry(key) 只哈希查找一次 → Occupied（有键）/ Vacant（无键）。

1. insert — 无脑覆盖

scores.insert(String::from("Blue"), 10);
scores.insert(String::from("Blue"), 25); // 覆盖 → 25
// 返回 Option<V>：Some(旧值) 或 None

2. entry + or_insert — 缺则插，有则不动

scores.entry(String::from("Yellow")).or_insert(50);
scores.entry(String::from("Blue")).or_insert(50); // 已有 → 不改

or_insert(x) → 始终返回 &mut V。

3. 词频统计 — 基于原值累加

let text = "apple pear apple banana apple";
let mut map = HashMap::new();
for word in text.split_whitespace() {
    let count = map.entry(word).or_insert(0);
    *count += 1;
}

4. 链式 and_modify（拓展）

map.entry("k").and_modify(|v| *v *= 2).or_insert(10);
// 存在 → 翻倍；不存在 → 插 10
方法 作用
or_insert_with(\|\| …) 不存在时闭包延迟生成值
and_modify(\|v\| …) 仅当键已存在时修改

总结表

操作 写法 特点
全覆盖 insert(k, v) 覆盖旧值
缺则插 entry(k).or_insert(v) 存在不动
基于原值改 *entry(k).or_insert(0) += 1 词频
安全查 get(&k) Option<&V>

8.3

.4 Hasher 与 BuildHasher

← 主笔记：8.3 HashMap · demo：8.3.4-hasher-demo/

对应原文：默认 hasher 偏安全抗 DoS，不一定最快；瓶颈时可换 BuildHasher（crates 现成库）。

一、两个核心 Trait

1. Hasher — 单次哈希计算器

std::hash::Hasher：对数据分段写入，最后算出 u64 哈希值。一个实例只算一次。

方法 作用
write(&mut self, bytes: &[u8]) 灌入字节
finish(&self) -> u64 收尾，返回哈希值

还有 write_u32 / write_usize 等便利方法。

use std::hash::{Hash, Hasher};
use std::collections::hash_map::DefaultHasher;

let mut h = DefaultHasher::new();
123u32.hash(&mut h);
let hash_val = h.finish();

2. BuildHasher — Hasher 工厂（HashMap 第三个泛型 S）

std::hash::BuildHasher：生产 Hasher 实例的工厂。

pub struct HashMap<K, V, S = RandomState> { /* … */ }
//                          ↑ S: BuildHasher
方法 作用
build_hasher(&self) -> impl Hasher 每次 insert / get 时生成全新 Hasher

默认 S = RandomState（标准库默认哈希工厂）。

二、标准库默认：RandomState + SipHash 1-3

  1. 算法：SipHash-1-3 - 安全：进程启动时随机 seed，同 key 每次运行哈希值不同 → 攻击者难批量构造冲突 key，防 HashDoS（恶意冲突使表退化成链表、O(n) 卡死） - 性能：中等长度字符串较优；小 key（u32/i32）、超长字符串偏慢
  2. DefaultHasher = RandomState 产出的 Hasher 实现
// 默认 HashMap：S = RandomState，底层 SipHash
let mut map: HashMap<u32, u32> = HashMap::new();

原文要点：默认 hasher 安全优先，不一定最快； profiling 显示哈希是瓶颈时，换 BuildHasher 实现。

三、主流高性能替换（crates.io）

牺牲 DoS 抗性换速度 — 仅适合可信输入（见 §五）。

crate 算法 适用场景 优缺点
fnv FNV-1a 小 key：数字、短字符串 整数极快；超长字符串一般；无防 DoS
rustc_hash（FxHash） FxHash 编译器、内存缓存、内部索引 rustc 原生；小键性能顶尖
ahash AHash 大数据、高频 HashMap CPU 有 AES 指令时极快
hashbrown FoldHash 等 drop-in 替换 std 表 瑞士表 + 快哈希

四、替换 HashMap 哈希器（两种写法）

写法 1：BuildHasherDefault + type 别名（单 Map 替换）

以 fnv 为例：

# Cargo.toml
fnv = "1.0"

use std::collections::HashMap;
use std::hash::BuildHasherDefault;
use fnv::FnvHasher;

type FnvHashMap<K, V> = HashMap<K, V, BuildHasherDefault<FnvHasher>>;

let mut map: FnvHashMap<u64, &str> = FnvHashMap::default();
map.insert(42, "ok");

写法 2：HashMap::with_hasher 运行时指定工厂

use std::collections::HashMap;
use rustc_hash::FxBuildHasher;

let mut map: HashMap<u64, i32> =
    HashMap::with_hasher(FxBuildHasher::default());

rustc_hash 也提供现成别名：

use rustc_hash::FxHashMap;
let mut map: FxHashMap<u64, i32> = FxHashMap::default();

五、选型准则

场景 建议
外网不可控 key（HTTP 参数、用户自定义字符串） 必须默认 SipHash（HashMap::new()）
程序内部数据（枚举、自增 id、固定配置） 可换 FxHash / AHash / FNV
百万级高频读写，profiling 显示哈希占 CPU 优先考虑 FxHash / AHash
离线计算、本地缓存、量化内存索引 FxHash / AHash 常见选择

六、Hash trait 与 Hasher 的关联

键要能进 HashMap，必须 Hash + Eq：

pub trait Hash {
    fn hash<H: Hasher>(&self, state: &mut H);
}

流程：key.hash(&mut hasher) → 把自身字节写入 Hasher → finish() 得 u64 → 寻址桶位。

自定义 struct：

#[derive(Hash, Eq, PartialEq)]
struct MyKey { id: u64 }

附录：可直接复制的 type 别名模板

// ── FNV ──────────────────────────────────────
use std::collections::HashMap;
use std::hash::BuildHasherDefault;
use fnv::FnvHasher;
type FnvHashMap<K, V> = HashMap<K, V, BuildHasherDefault<FnvHasher>>;

// ── FxHash（rustc_hash）──────────────────────
use rustc_hash::FxHashMap; // 或 FxBuildHasher + with_hasher

// ── AHash ────────────────────────────────────
use ahash::AHashMap; // crate 提供的别名

// ── 默认（抗 DoS）────────────────────────────
type SafeHashMap<K, V> = HashMap<K, V>; // S = RandomState
