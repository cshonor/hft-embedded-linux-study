3.1

变量和可变性

Rust 中变量默认不可变（immutable），可充分利用安全性和简单并发。需要时可声明为可变（mutable）。

对应 demo 项目：00-Book/03-common-concepts/3.1-variables-demo/

不可变变量

一旦值绑定到变量名，就不能更改。

fn main() {
    let x = 5;
    println!("The value of x is: {}", x);
    x = 6;  // ❌ 编译错误！
    println!("The value of x is: {}", x);
}

错误：cannot assign twice to immutable variable 'x'

  • 编译器提示：consider making this binding mutable: mut x
  • 不可变性有助于避免 bug：某处假设值不变，另一处却改了它
  • Rust 编译器在编译期就保证「声明不变的值真的不变」

可变变量 mut

在变量名前加 mut 使其可变：

fn main() {
    let mut x = 5;
    println!("The value of x is: {}", x);
    x = 6;  // ✓ 允许
    println!("The value of x is: {}", x);
}
  • 输出：5 然后 6
  • mut 也提示读者：该变量的值会在别处被修改
  • 大型数据结构时，原地修改可能比复制更快；小结构时函数式风格通常更清晰

常量 const

常量与不可变变量的区别：

特性 常量 const 不可变变量 let
可变性 永远不可变，不能用 mut 默认不可变
声明 const 关键字 let 关键字
类型 必须显式标注 可推导
赋值 仅常量表达式（编译期可算） 可为运行时计算结果
作用域 可在全局等任意作用域 一般局部
命名 全大写 + 下划线 snake_case 
const THREE_HOURS_IN_SECONDS: u32 = 60 * 60 * 3;
  • 常量名：全大写，如 THREE_HOURS_IN_SECONDS
  • 不能是函数调用的结果或运行时才能算出的值
  • 适合硬编码值（最高分、光速等），便于维护和修改

遮蔽 shadowing

用 let 再次声明同名变量，新变量会遮蔽旧变量：

fn main() {
    let x = 5;
    let x = x + 1;        // x = 6
    {
        let x = x * 2;    // 内部 x = 12
        println!("inner scope: {}", x);  // 12
    }
    println!("outer: {}", x);  // 6，内部遮蔽结束
}
  • 遮蔽是新变量，不是修改原变量
  • 除非再用 let，否则不能重新赋值（仍遵守不可变规则）
  • 转换完成后，变量保持不可变
  • 本质：创建了一个全新的变量，只是复用了 spaces 这个名字，旧变量被隐藏（无法再访问）。
  • 特性：新变量可以拥有完全不同的类型，内存位置也可能不同。

遮蔽可改变类型

let spaces = "   ";      // &str
let spaces = spaces.len(); // usize，遮蔽后类型改变

用 mut 则不能改变类型：

let mut spaces = "   ";
spaces = spaces.len();   // ❌ 错误：expected `&str`, found `usize`

❌ 编译报错：mut 仅允许修改同一个变量的值，类型必须严格一致。

  • 本质：在同一个内存地址上修改值，变量的类型在声明时就已固定，无法更改。

  • 特性：只能修改同类型的值，不能改变变量的类型。

特性 变量遮蔽 (Shadowing) mut 可变变量
本质 创建新变量，复用名称，旧变量被隐藏 修改同一个变量的值，内存地址不变
类型变更 ✅ 允许（可从 &str 变为 usize） ❌ 禁止（类型在声明时固定）
可变性 新变量默认不可变（需 let mut 才可变） 声明时需 mut 才允许修改
作用域 遮蔽仅在当前作用域生效，作用域结束后旧变量恢复 作用域内始终是同一个变量
内存操作 可能分配新内存，旧变量在作用域结束后销毁 直接修改原内存，无新分配

未初始化 vs Default 默认值

核心结论

函数内 let x: T; 声明后不赋值，没有隐式默认值，不能直接使用（除非编译器能证明所有代码路径上都已赋值）：

// fn main() {
//     let num: i32;
//     let flag: bool;
//     let ch: char;
//     let pi: f64;
//     println!("{}", num);  // ❌ 未初始化
//     println!("{}", flag); // ❌
// }

所有基础类型的局部变量（i32、bool、char、f64 等）规则相同：在函数（含 main）里用 let 声明后，不赋值就读取，编译必报错。Rust 不会自动补 0 / false 等。

main 与普通函数规则相同

main 只是程序入口函数，局部变量规则与其它函数完全一致。

先声明、后赋值可以，但必须：

  1. 使用 let mut（不可变 let 不能写 num = 66）；
  2. 在第一次读取之前，每条代码路径都已赋值。
fn main() {
    let mut num: i32;
    num = 66;
    println!("{}", num); // 66
}

想拿类型默认值须 Default::default() 或 Type::default()，与是否在 main 无关。

何时能拿到「默认值」

需要显式构造，常见方式：

方式 示例
Default::default() let n: i32 = Default::default(); → 0
类型简写 let v: Vec<i32> = Vec::default(); → 空 Vec
数组 [0; 5] 或 [T; N]::default()（需 T: Default）
#[derive(Default)] 结构体 各字段按自身 Default 填充

常用类型的 Default 值

类型 默认值
整型 i8…i128 / u8…u128 0
f32 / f64 0.0
bool false
char '\0'（U+0000）
String ""（空串）
(T1, T2, …) 各元素各自的 Default
Option<T> None
&T / &mut T 无 Default 
let num: i32 = Default::default();
let flag: bool = Default::default();
let s: String = String::default(); // 与 Default::default() 等价
let mut v: Vec<i32> = Vec::default();

记忆：局部变量无自动默认值；要默认值，手动 Default / Type::default()。

区分：static 等与局部 let 的初始化规则不同；见 Rust 参考手册。

小结

概念 关键字 要点
不可变变量 let 默认，不能二次赋值
可变变量 let mut 可修改值
常量 const 必须标类型，仅常量表达式
遮蔽 let 同名 新建变量，可换类型
默认值 Default::default() 局部变量无隐式默认，须显式初始化

延伸：下划线占位符 _（let _ =、for _ in）

3.1.1

下划线占位符 `_`

结论：_ 是匿名占位符——表示「这里有个值，但我不打算用」。用来消掉未使用变量告警，或明确「故意丢弃」返回值。

与 3.1 变量和可变性 配套；控制流里 for 见 3.5 控制流。

一句话记住三条

# 用法 含义
1 _ 作绑定名 定义了但不用；编译器不报 unused
2 let _ = x 接住返回值后直接扔掉，不存可用变量
3 for _ in 0..n 只要循环 n 次，不要迭代元素

1. 匿名占位，忽略未使用告警

let _ = some_fn();  // 必须调用，但不要结果
  • 若写 let x = some_fn(); 却从不使用 x，会有 unused variable 警告。
  • _ 不是普通变量：不能 println!("{}", _)，也不能在后面再引用。

2. let _ = x：接收后丢弃

let _ = h.await;  // 必须 await 完成；不要 Future 的输出
写法 说明
h.await 单独一行 仍会求值；Result 等有时仍需处理
let _ = h.await 明确：故意不要这个结果

适合：必须执行副作用 / 必须 poll 完，但返回值无意义或已在别处处理错误。

3. for _ in 0..n：只要次数

for _ in 0..3 {
    println!("tick");
}
  • 循环 3 次，不需要 0、1、2 这些值。
  • 若写 for i in 0..3 却不用 i，会触发 unused；用 _ 是惯用写法。

模式匹配里的 _（顺带）

在 match / 解构里，_ 同样表示「匹配到了，但不要里面的值」：

match opt {
    Some(_) => println!("有值"),
    None => {},
}

与 let _ 同一思想：占位、不绑定可用名字。

记忆卡片

场景 写法
不要返回值 let _ = f();
只要循环次数 for _ in 0..5 {}
match 忽略内容 Some(_)
需要再用这个值 用正常名字 let x = ...，别用 _

数据类型

Rust 是静态类型语言，编译期必须知道所有变量类型。编译器可推导类型，歧义时需显式标注。

对应 demo 项目：00-Book/03-common-concepts/3.2-data-types-demo/

let guess: u32 = "42".parse().expect("Not a number!");
// 无标注会报错: type annotations needed

标量类型 (Scalar)

标量类型代表单个不可分割的值，Rust 标量类型共 4 种：整型、浮点、布尔、字符。

整数类型

长度 有符号 无符号 范围 (有符号) 范围 (无符号)
8 位 i8 u8 -128~127 0~255
16 位 i16 u16 -(2^15)~2^15-1 0~2^16-1
32 位 i32 u32 -(2^31)~2^31-1 0~2^32-1
64 位 i64 u64 -(2^63)~2^63-1 0~2^64-1
128 位 i128 u128 ... ...
arch isize usize 取决于架构 (32/64位) 用作索引
  • 默认：i32
  • isize/usize：集合索引

整型字面量

形式 示例
十进制 98_222
十六进制 0xff / 0xFF_AA_00
八进制 0o77
二进制 0b1010_1100
字节(u8) b'A'

数字里的下划线 _

  1. 仅作视觉分隔，编译器直接忽略，不改变数值。
  2. 分组位数自由：98_222（千分位习惯）与 9_8222（万位习惯）完全等价。
  3. 非法写法：开头/结尾 _（_123、123_）、连续 __（12__34）。
let n1 = 98222;
let n2 = 98_222;
let n3 = 9_8222;
assert!(n1 == n2 && n2 == n3);

let bin = 0b1010_1100;
let hex = 0xFF_AA_00;

类型后缀如 57u8；也可用 _ 作模式中的占位符（与字面量分隔符不同，见第 18 章）。

整型溢出

  • debug 模式：溢出会 panic
  • release 模式：二进制补码包裹 (wrapping)，如 u8 的 256→0（由 overflow-checks = false 控制；Rust 只是把 C 的「构建配置」做进了语言层——对照 C/C++ 侧的 release 模式、-DNDEBUG 与 -O2 下的 UB，见 03.6 §2.7）
  • 显式处理：wrapping_*、checked_*、overflowing_*、saturating_*

浮点类型

类型 大小 精度
f32 32 位 单精度
f64 64 位 双精度（默认）
  • 遵循 IEEE-754
  • 默认 f64，在现代 CPU 上与 f32 速度相近但精度更高

数字运算

加 +、减 -、乘 *、除 /、取模 %

  • 整数除法向下取整：2 / 3 → 0

布尔类型

let t = true;
let f: bool = false;
  • 值：true / false
  • 大小：1 字节

字符类型 char

let c = 'z';
let z = 'ℤ';
let heart_eyed_cat = '😻';
let zhong = '中';
  • 单引号（区别于字符串双引号 "..."）
  • 4 字节，表示 Unicode 标量值（不是完整 grapheme；组合 emoji 等可能需多个 char 或 str）
  • 支持 ASCII、中文、emoji 等

常见错误（编译期）：

// let c = "z";   // 错误：期望 char，得到 &str
// let c = 'ab';  // 错误：char 只能是一个 Unicode 标量

与 str 区分：'a' 是单个标量；"a" 是 UTF-8 字符串切片（长度可能 > 1 字节）。

延伸阅读：3.2.2-Unicode与字符串.md + 3.2-unicode-demo/（字节 vs 字符、截取/翻转模板）。

复合类型 (Compound)

元组 (tuple)

  • 固定长度，元素类型可不同（异构）
  • 小括号创建
let tup: (i32, f64, u8) = (500, 6.4, 1);

// 解构：一次性绑定所有元素
let (x, y, z) = tup;

// 索引：tup.0、tup.1…（从 0 开始，字面量索引）
let five_hundred = tup.0;
  • 单元类型 ()：无元素元组；无返回值的表达式隐式得到 ()

常见错误：

// let (a, b) = tup;           // 错误：元素个数不匹配
// let fourth = tup.3;         // 错误：只有 .0 .1 .2
// let bad: (i32, i32) = (1,); // 错误：单元素元组要写成 (1,)

运行 demo：cd 00-Book/03-common-concepts/3.2-data-types-demo && cargo run

Playground：把 3.2-data-types-demo/src/main.rs 里「§6 char」「§7 tuple」两段复制到 Rust Playground 即可单文件运行（无需 Cargo.toml）。

数组 (array)

  • 固定长度，元素类型相同
  • 分配在栈上
  • 方括号创建
let a = [1, 2, 3, 4, 5];
let a: [i32; 5] = [1, 2, 3, 4, 5];  // 类型标注
let a = [3; 5];  // [3, 3, 3, 3, 3]

// 访问
let first = a[0];
let second = a[1];
  • 越界访问：运行时 panic，Rust 会检查索引
  • 需动态大小用 Vec（第 8 章）

小结

分类 类型 要点
标量 i8~i128, u8~u128, isize, usize 默认 i32
标量 f32, f64 默认 f64
标量 bool true/false
标量 char 单引号，Unicode
复合 tuple 解构或 .0/.1 访问
复合 array 固定长度，栈分配
3.2.1

JSON、UTF-8 与 GB 编码

结论：标准 JSON（RFC 8259）要求文档为 UTF-8；Rust String 也是 UTF-8，正常 serde_json 序列化无需转码。仅在与老旧客户端约定 GB2312/GBK 时，在网络字节层用 encoding_rs 互转；Rust 内部 String 仍保持 UTF-8。

对应 demo：00-Book/03-common-concepts/3.2-json-encoding-demo/
Unicode 基础见：3.2.2-Unicode与字符串.md

核心结论

  1. 标准前后端 JSON：Rust UTF-8 String → JSON UTF-8 字节，直接返回，零转码。
  2. 对方强制 GB2312/GBK：只在收发字节时 UTF-8 ↔ GB 互转；不要把 String 改成别的编码存储。
  3. 最优：全链路 UTF-8；GB 系字符集小，生僻字/emoji 易丢失。

一、为什么正常不用转

  • JSON 标准：整个文档必须是 UTF-8。
  • 浏览器 / JS / 现代 API 默认 UTF-8；JS 字符串基于 Unicode，与 UTF-8 JSON 兼容。
  • Rust serde_json::to_string / to_vec 输出的是 UTF-8 文本字节。

需要 GB 编码的多为老系统、工控、部分桌面客户端，业务上少见。

二、真遇到 GB2312/GBK

使用 encoding_rs（encoding_rs::GBK 覆盖 GB2312 常用字；也可用 Encoding::for_label(b"gb2312")）。

依赖

[dependencies]
encoding_rs = "0.8"
serde = { version = "1.0", features = ["derive"] }
serde_json = "1.0"

场景 A：UTF-8 字符串 ↔ GB 字节

use encoding_rs::GBK;

let s = "测试中文内容";
let (gb_bytes, _, had_errors) = GBK.encode(s);
assert!(!had_errors);

let (utf8_cow, _, had_errors) = GBK.decode(&gb_bytes);
assert!(!had_errors);
println!("{}", utf8_cow); // 测试中文内容

场景 B：JSON 响应体整体转为 GB 字节

正确流程：先得到 UTF-8 JSON 字节 → 按 UTF-8 文本理解 → encode 成 GB 字节。

use encoding_rs::GBK;
use serde::Serialize;
use serde_json::to_vec;

#[derive(Serialize)]
struct Resp { name: String, msg: String }

let data = Resp { name: "张三".into(), msg: "后端返回内容".into() };
let json_utf8 = to_vec(&data).unwrap();
let json_str = std::str::from_utf8(&json_utf8).unwrap();

let (json_gb, _, had_errors) = GBK.encode(json_str);
// json_gb 作为 HTTP body 返回；Header: Content-Type: application/json; charset=GBK

常见笔误：对已是 UTF-8 的 JSON 字节调用 GBK.decode(...)——那是 GB → UTF-8，方向反了。

场景 C：收到 GB 编码的 JSON body

let (utf8_cow, _, had_errors) = GBK.decode(&gb_body_bytes);
let resp: Resp = serde_json::from_str(&utf8_cow)?;

三、注意点

  1. 字符丢失：GB2312/GBK 不含生僻字、emoji；encode 可能 had_errors == true 或替换，需检查并尽量推动 UTF-8。
  2. HTTP Header：返回 GB body 时必须声明，例如
    Content-Type: application/json; charset=GBK（或与对方约定一致）。
  3. 边界：Rust String / &str 始终 UTF-8；转码只发生在 &[u8] / Vec<u8> 与外部系统之间。

运行 demo

cd 00-Book/03-common-concepts/3.2-json-encoding-demo
cargo run
3.2.2

Rust 与 Unicode 核心要点

先分清 「编号体系」 和 「存盘格式」，再看 Rust 里的 char / String。

对应 demo：00-Book/03-common-concepts/3.2-unicode-demo/
更深入字符串 API 见：00-Book/08-collections/8.2-string.md

核心结论（先记这四条）

  1. String / &str：底层字节序列必须是合法 UTF-8（语言硬性规定）。
  2. char：内存里存 Unicode 标量（码点），本质是 u32（4 字节），不是 UTF-8 字节流。
  3. char 拼进字符串（如 push）：自动 码点 → UTF-8 字节，追加到 String 末尾。
  4. 从字符串读 char（如 .chars()）：自动 UTF-8 字节 → 码点 解码。

零、Unicode 与编码（概念层）

1. Unicode：只定编号，不管二进制

给全球字符分配唯一数字编号（码点 / code point），规定「这个字是几号」，不规定在磁盘里用几个字节、字节长什么样。

例：中 → U+4E2D（十进制 20013）。

2. UTF-8、GB2312、GBK：编码规则

把「编号」翻译成一串二进制字节写进文件/内存的规则，都叫编码：

名称 说明
UTF-8 Unicode 码点的主流编码；变长 1~4 字节/标量
GB2312 / GBK 国内旧编码；另一套独立编号/映射，不是 Unicode 全集

同一个字，编码不同 → 字节不同：

  • 中 在 UTF-8 里常见为 3 字节（如 E4 B8 AD）
  • 在 GB2312 里往往是 另外 2 字节（与 UTF-8 无对应关系）

3. Rust 里怎么对应

Rust 类型 存的是什么
char 一个 Unicode 标量值（码点），内存上约 4 字节 u32
String / &str 强制按 UTF-8 把文本编成字节序列

char ↔ UTF-8 字符串之间的转换由标准库完成（如 chars()、encode_utf8）；在类型正确、来源确实是 UTF-8 的前提下，不会出现「Rust 自己把编号和字节搞混」的乱码。

4. 乱码从哪来

乱码 = 字节的真实编码 与 程序按什么规则解码 不一致。

例：文件实际是 GB2312 字节，程序却当 UTF-8 去 String::from_utf8 / 读入 str → 规则对不上，显示异常（或 from_utf8 直接报错）。

读外部文件、网络、旧系统接口时，要先确认或转换编码；Rust 默认世界假设是 UTF-8。

JSON 与 GB 编码：标准 JSON 强制 UTF-8，见 3.2.1-JSON与编码.md + 3.2-json-encoding-demo/。

一、char（Unicode 标量值）

  1. 本质：单个 Unicode 标量值，内存上为 4 字节（u32）
  2. 语法：单引号 '…'，且只能一个标量 rust let ch1 = 'a'; let ch2 = '中'; let ch3 = '😀';
  3. 范围：合法标量大致为 U+0000..=U+D7FF 与 U+E000..=U+10FFFF（由 char::from_u32 等 API 校验）
  4. 常用 rust println!("{}", '中' as u32); // 码点 20013 if let Some(c) = char::from_u32(20013) { println!("{}", c); // 中 } let c = '\u{4E2D}'; // 转义写法 println!("{}", c.is_ascii_digit()); // false println!("{}", c.is_alphabetic()); // true（Unicode 字母类）

注意：人眼的一个「字」有时是多个标量（组合 emoji、部分印地语等）；chars() 按标量切，不是按字形簇 (grapheme)。

二、String / &str（UTF-8）

  • 字符串在 Rust 里是 UTF-8 字节序列，不是 char 数组。
  • 每个标量在 UTF-8 中占 1~4 字节（ASCII 1、中文通常 3、部分 emoji 4）。
  • s[i] 取的是第 i 个字节，不是第 i 个字符；从多字节字符中间切会 panic。

字节 vs 字符

let s = "中文";
println!("字节数: {}", s.len());           // 6，不是 2
for b in s.bytes() { /* 每个 u8 */ }
for c in s.chars() { /* 每个 char */ }     // 正确按标量遍历

按「第 n 个字符」访问

不能 s[n]，要先收集或迭代：

let s = "Rust编程";
let third = s.chars().nth(2).unwrap();     // 第 3 个标量
let chars: Vec<char> = s.chars().collect();

四、对比表

类型 含义 单位 常用访问
char Unicode 标量 固定 4 字节 '中'，as u32
&str / String UTF-8 文本 1~4 字节/标量 .chars()、.len() 为字节数
bytes() 原始 UTF-8 字节 u8 .bytes()

三、char 与 String 合并时发生什么

底层各存什么

  • char：直接存码点，例如 '中' → 0x4E2D（u32），不做 UTF-8/GBK 等编码。
  • String / &str：存 UTF-8 编码后的 u8 序列。

拼接到字符串（push / push_str / format! 等）

let c: char = '国';
let mut s = "中".to_string(); // 已是 UTF-8 字节
s.push(c);                    // 码点 → UTF-8 字节 → 追加
println!("{}", s);            // 中国

流程：char('国') 取出码点 → 按 UTF-8 规则编码（国 通常 3 字节）→ 写入 String 的 Vec<u8>。对开发者透明，无需手写编码。

从字符串取出 char（.chars()）

反向：按 UTF-8 规则扫描字节，解码为码点，每次迭代得到一个 char。

最后一个疑问：char 到底「有没有编码」？

场景 存什么
单独的 char 变量 码点（u32），固定 4 字节，无 UTF-8
char 进入 String / 写入文件等 UTF-8 文本 必须变成 UTF-8 字节

五、高频操作

字符个数（标量个数）

let s = "Hello 世界 😂";
let count = s.chars().count();   // 不是 s.len()

Unicode 转义

let c = '\u{4E2D}'; // 中

六、实用模板（切割 / 截取 / 翻转）

见 demo 中函数：char_at、take_chars、skip_chars、reverse_chars。
按字节切安全子串（必须在字符边界上）用 get(start..end) 或 &s[start..end]，边界可用：

fn is_char_boundary(s: &str, index: usize) -> bool {
    if index == 0 || index == s.len() {
        return true;
    }
    s.is_char_boundary(index)
}

更完整的「按字形簇」处理可用 crate unicode-segmentation（本 demo 不引入依赖，仅用 chars()）。

七、常见踩坑

  1. str[i] 当字符 → 实际是字节；多字节字符会 panic 或逻辑错误。
  2. len() 当字符数 → len() 是 UTF-8 字节长度。
  3. "a" 当 char → 字符串用双引号，标量用单引号。
  4. 切片范围未对齐字符边界 → &s[0..2] 对 "中" 会 panic（"中" 占 3 字节）。

函数

Rust 用 fn 声明函数。函数名和变量名使用蛇形命名法（snake_case）：全小写，单词间用下划线。

对应 demo 项目：00-Book/03-common-concepts/3.3-functions-demo/

核心结论

  1. 函数若要返回非 () 的值，必须显式写 -> 类型（Rust 不支持函数返回类型自动推导）。
  2. 函数体最后一行是表达式且不带 ; → 该表达式的值就是返回值；加了 ; 变成语句 → 该处等价于 ()。
  3. 只返回 () 的函数可省略 -> ()（如 fn foo() { ... }）。

函数定义与调用

fn main() {
    println!("Hello, world!");
    another_function();
}

fn another_function() {
    println!("Another function.");
}
  • 定义顺序无所谓，只要在作用域内定义即可
  • 调用：函数名()

参数 (Parameters)

函数签名中必须为每个参数标注类型。

fn another_function(x: i32) {
    println!("The value of x is: {}", x);
}

// 多参数用逗号分隔
fn print_labeled_measurement(value: i32, unit_label: char) {
    println!("The measurement is: {}{}", value, unit_label);
}
  • 形参 (parameter)：函数定义中的变量
  • 实参 (argument)：调用时传入的具体值
  • Rust 要求在定义处显式标注类型，方便推导

语句与表达式

类型 说明 返回值
语句 (statement) 执行操作，不返回值 无
表达式 (expression) 计算并产生值 有
  • let y = 6; 是语句，不能写 let x = (let y = 6); 赋值给别的变量
  • 5 + 6、函数调用、宏调用都是表达式
  • 代码块 {} 也是表达式，其值为最后一个表达式的结果
let y = {
    let x = 3;
    x + 1   // 注意：末尾无分号！有分号就变成语句，不返回值
};
// y = 4

要点：表达式末尾不加分号；加分号会变成语句，不再返回值。

带返回值的函数

必须写返回类型（硬性规则）

与变量不同，Rust 不会为函数推断返回类型。要返回 i32 等具体类型，签名里必须写 -> i32：

fn add(a: i32, b: i32) -> i32 {
    a + b   // 末尾无分号
}

省略返回类型且函数体实际产生非 () 的值会编译失败：

// fn add(a: i32, b: i32) {
//     a + b   // ❌ expected `()`, found integer
// }

两种返回形式

1. 末尾无分号 → 返回表达式结果

fn one() -> i32 {
    100
}

2. 末尾有分号 → 语句，该位置贡献 ()

只打印、无有意义返回值时，返回类型为 ()，通常省略不写：

fn print_msg() {
    println!("hello");
}

// 等价于
fn print_msg() -> () {
    println!("hello");
}

若声明了 -> i32 却在末尾写 x + 1;，会得到 expected i32, found ()。

return 提前返回

同样须写 -> 类型；return 后也可跟表达式：

fn max(a: i32, b: i32) -> i32 {
    if a > b {
        return a;
    }
    b
}

基础示例

fn five() -> i32 {
    5
}

fn plus_one(x: i32) -> i32 {
    x + 1
}

常见错误：末尾加分号

fn plus_one(x: i32) -> i32 {
    x + 1;   // ❌ 语句，返回 ()
}
// expected `i32`, found `()`

小结

概念 要点
命名 snake_case
参数 必须标注类型
语句 不返回值，如 let x = 6;
表达式 返回值，末尾无分号
返回值 非 () 须写 -> 类型；最后表达式无 ;，或 return
无返回值 省略 -> ()，语句正常加 ;

注释

编译器会忽略注释，但能帮助阅读源码的人理解代码。

对应 demo 项目：00-Book/03-common-concepts/3.4-comments-demo/

行注释

以 // 开头，到行尾结束：

// Hello, world.

多行注释

每行都以 // 开头：

// 我们在这里处理一些复杂事情，需要足够长的解释，使用
// 多行注释可做到这点。我们希望这个注释将解释接下来
// 要实现的内容。

行尾注释

注释放到代码同一行后面：

fn main() {
    let lucky_number = 7; // I'm feeling lucky today
}

推荐写法

把注释放到上一行，单独成行，更清晰：

fn main() {
    // I'm feeling lucky today
    let lucky_number = 7;
}

文档注释

Rust 还支持文档注释 ///，用于生成 API 文档，在第 14 章会详细说明。

/// 计算两数之和
fn add(a: i32, b: i32) -> i32 {
    a + b
}
3.5

控制流

控制执行流的两种主要结构：if 表达式 和 循环。

对应 demo 项目：00-Book/03-common-concepts/3.5-control-flow-demo/

if 表达式

核心规则：条件必须是 bool

Rust 不支持隐式布尔转换（与 Java/JS 的「非 0 即真」不同）。
if、while 等控制流的条件位置只能是 bool（true / false）。

let num = 1;
// if num { }           // ❌ expected `bool`, found integer
if num != 0 { }         // ✅ 显式比较得到 bool
语言 if (1)
Java / JS 合法（非 0 → true）
Rust 编译错误

设计意图：避免手误、隐式转换带来的隐蔽 bug；条件必须写清楚。

常见正确写法

let num = 1;
if num != 0 { }
if num == 0 { }

let flag = true;
if flag { }

let s = "";
if s.is_empty() { }

let opt: Option<i32> = Some(5);
if opt.is_some() { }
if let Some(v) = opt { }
// 不能写 if opt { }

基本语法

if condition {
    // 条件为 true 时执行
} else {
    // 条件为 false 时执行
}
  • 条件必须是 bool，Rust 不会自动转换
  • 分支代码块叫 arm（与 match 类似）

条件必须是 bool

let number = 3;
if number { }           // ❌ 错误: expected `bool`, found integer
if number != 0 { }      // ✓ 正确

else if 多重条件

if number % 4 == 0 {
    println!("divisible by 4");
} else if number % 3 == 0 {
    println!("divisible by 3");
} else {
    println!("not divisible by 4 or 3");
}
  • 只执行第一个为真的分支
  • 过多 else if 建议用 match（第 6 章）

在 let 中使用 if

if 是表达式，可赋值给变量：

let number = if condition { 5 } else { 6 };

要点：if 与 else 分支的返回值类型必须相同！

let n = if condition { 5 } else { "six" };  // ❌ 类型不兼容

循环

1. loop — 无限循环

loop {
    println!("again!");
    // break; 退出循环
    // continue; 跳过本次，进入下一次
}
  • 需用 break 或 ctrl+c 退出

循环标签 (loop label)

嵌套循环时，用标签指定 break/continue 作用于哪层：

'counting_up: loop {
    loop {
        break;           // 只退出内层
        break 'counting_up;  // 退出外层
    }
}

从 loop 返回值

let result = loop {
    counter += 1;
    if counter == 10 {
        break counter * 2;  // 返回值
    }
};
// result = 20

2. while — 条件循环

while number != 0 {
    println!("{}!", number);
    number -= 1;
}

3. for — 遍历集合

推荐：安全、简洁，Rust 最常用循环。

let a = [10, 20, 30, 40, 50];
for element in a {
    println!("the value is: {}", element);
}

Range 倒计时：

for number in (1..4).rev() {
    println!("{}!", number);
}
// 输出: 3!, 2!, 1!
// LIFTOFF!!!
  • 1..4：1, 2, 3（不含 4）
  • 1..=4：1, 2, 3, 4（含 4）
  • .rev()：反转区间

小结

结构 用途
if / else if / else 条件分支，条件必须 bool
loop 无限循环，break 返回值
while 条件循环
for 遍历集合，最常用
