各节考点速览

19.1 不安全 Rust

  • unsafe ≠ 关闭检查：程序员承诺自行维护安全不变式；借用检查等对 &T/&mut T 仍有效
  • 五大 unsafe 操作： 1. 解引用裸指针 *const T / *mut T 2. 调用 unsafe fn / unsafe 方法 3. 读写 static mut 4. unsafe impl 不安全 trait 5. 访问 union 字段
  • 典型场景：FFI、底层数据结构、安全 API 封装（缩小 unsafe 块）
  • → ER：Item 16 避免 unsafe · Item 34 FFI

19.2 高级 Trait

  • 关联类型 vs 泛型 trait：关联类型每类型只能 impl 一次；泛型 trait 可多次 impl
  • 默认泛型参数：如 trait Add<Rhs = Self>
  • 完全限定语法：<Type as Trait>::method() 消歧义
  • supertrait：trait T: Debug — 实现 T 须先实现 Debug
  • newtype：孤儿规则绕过 — 包装外部类型以 impl 外部 trait
  • → 入门：10.2.4 关联类型

19.3 高级类型

  • 类型别名 type：同义词，不创建新类型（vs newtype struct）
  • 永不类型 !：发散表达式，可 coerce 为任意类型
  • DST：str、[T]、dyn Trait — 编译期大小未知，须放指针后
  • Sized / ?Sized：泛型默认 T: Sized；接受 DST 写 ?Sized
  • ZST：大小为 0（()、空 struct），不占内存但参与类型系统
  • → 延伸：17.2 trait 对象（DST）

19.4 高级函数与闭包

  • fn 函数指针：不捕获环境；实现了 Fn/FnMut/FnOnce
  • 闭包 trait：Fn（&self）· FnMut（&mut self）· FnOnce（消耗 self）
  • 返回值：闭包匿名类型 → Box<dyn Fn(...)> 或 impl Fn
  • 高阶函数：map/filter 接收函数或闭包

19.1

不安全 Rust（unsafe Rust）

← 19 章导读 · 19.2 高级 trait · demo：19.1-unsafe-rust-demo/

ER：Item 16 避免 unsafe · Item 34 FFI

cd 00-Book/19-advanced-features/19.1-unsafe-rust-demo
cargo run

核心结论（先背）

  1. unsafe ≠ 关闭安全检查 — 程序员主动承担不变式责任；&T/&mut T 借用规则仍有效
  2. 仅 5 种操作需要 unsafe：裸指针解引用 · unsafe fn · static mut · unsafe impl · union 字段
  3. 原则：缩小 unsafe 块，封装为安全 API（如 split_at_mut）
  4. 裸指针无生命周期/借用检查 — 空指针、野指针 → UB（未定义行为）

一、核心概念

unsafe 的真实含义

常规 Rust 在编译期检查内存安全。unsafe 允许编译器无法代为证明安全的五类操作，由开发者向编译器承诺：你会自己维护安全不变式。

静态分析偏保守：宁可拒绝部分合法程序，也不误放行 UB。

五大 unsafe 超能力

# 操作 说明
1 解引用裸指针 *const T / *mut T 安全代码可创建，解引用须 unsafe
2 调用 unsafe fn / unsafe 方法 如 std::ptr::write
3 读/写 static mut 多线程极易数据竞争
4 unsafe impl 不安全 trait 如手动 Send/Sync
5 访问 union 字段 C 互操作常见

其他要点

  • unsafe 块范围有限：只影响块内直接操作，不会自动扩展到内部安全函数
  • Send/Sync：标记 trait，手动 unsafe impl 须确保线程安全
  • 典型场景：FFI、底层数据结构、安全 API 内部实现

二、代码示例

裸指针 + unsafe 函数

let mut y = 20;
let r1: *const i32 = &y;      // 安全代码可创建裸指针
let r2: *mut i32 = &mut y;

unsafe {
    println!("裸指针解引用：{}", *r1);
    std::ptr::write(r2, 30);  // unsafe 函数
}
println!("修改后 y: {}", y);  // 30

安全封装：split_at_mut 思路

借用检查器无法证明两段可变 slice 不重叠；在 mid <= len 已证明时，用裸指针构造（见 demo split_at_mut_i32）。

FFI · 静态变量 · union · unsafe trait

demo 还演示：extern "C" { fn abs(...) }、static mut COUNTER、union IntOrFloat、unsafe trait UnsafeMarker。

→ 完整可运行代码：19.1-unsafe-rust-demo/src/main.rs

三、分节详解

裸指针

  • 不保证有效、可为 null、可同时存在多个可变指针
  • 解引用空指针/野指针 → UB

unsafe fn

调用者须满足额外契约；须在 unsafe { } 或 unsafe fn 体内调用。

FFI：extern "C"

外部函数在 Rust 侧一律 unsafe 调用。导出给 C：pub extern "C" fn + #[no_mangle]。

static mut

读/写均须 unsafe；多线程优先用第 16 章并发原语（Mutex 等）。

四、易错点

# 易错 正确理解
1 unsafe = 关闭所有检查 借用检查等对 &T/&mut T 仍有效
2 裸指针像引用一样安全 无生命周期、无借用检查；空/野指针 → UB
3 unsafe 块“传染”子函数 只影响直接包含的 unsafe 操作
4 随意 unsafe impl Send 须证明线程安全，否则运行时数据竞争
5 static mut 随便用 多线程 UB；优先 Mutex/Atomic*
6 在生产照搬任意地址示例 demo 仅示意，勿对非法地址解引用

五、速记

  1. unsafe = 承诺不变式，不是关检查
  2. 五超能力：裸指针 · unsafe fn · static mut · unsafe impl · union
  3. 裸指针：创建安全，解引用 unsafe
  4. 封装原则：最小 unsafe 块 + 安全 API 对外

高级 trait

核心结论（先背）

  1. 关联类型：trait 内 type，实现方指定 — 一个类型仅 impl 一次（Iterator::Item）
  2. 泛型 trait：同一类型可多次 impl（不同泛型参数）— 调用易歧义
  3. 默认泛型参数：trait Add<Rhs = Self> — 运算符重载常用
  4. 完全限定语法：<Type as Trait>::func() — 消歧义
  5. supertrait：trait A: B — 实现 A 必先实现 B
  6. newtype：包装外部类型 — 绕过孤儿规则，零运行时开销

一、关联类型（Associated Types）

核心回顾

Trait 内部用 type 定义关联类型，由实现方指定具体类型；同一类型只能对该 trait 实现一次（对比泛型 trait）。

标准参考：简化版 Iterator

trait Iterator {
    type Item;  // 迭代产出的元素类型
    fn next(&mut self) -> Option<Self::Item>;
}

完整 Demo：Container

trait Container {
    type Elem;
    fn push(&mut self, val: Self::Elem);
    fn pop(&mut self) -> Option<Self::Elem>;
}

struct IntBag(Vec<i32>);

impl Container for IntBag {
    type Elem = i32;
    fn push(&mut self, val: Self::Elem) {
        self.0.push(val);  // 委托内部 Vec，避免与 trait 方法同名递归
    }
    fn pop(&mut self) -> Option<Self::Elem> {
        self.0.pop()
    }
}

易错：直接 impl Container for Vec<i32> 且方法名也叫 push，方法体内 self.push(val) 会无限递归。应用 newtype 包装或换方法名。

关联类型 vs 泛型 Trait

写法 1：泛型 trait Trait<T> — 可多次 impl

trait Iterable<T> {
    fn next(&mut self) -> Option<T>;
}

struct MyIter;
impl Iterable<i32> for MyIter { /* ... */ }
impl Iterable<String> for MyIter { /* ... */ }  // 同一类型，不同 T

调用处可能需要类型标注，容易歧义。

写法 2：关联类型 — 只能 impl 一次

同一类型对 trait Container 只能有一种 Elem，无歧义 — 这也是标准库 Iterator 选关联类型的原因。

关联类型 泛型 trait
impl 次数 一次 可多次
调用 无需再选 Item 可能需类型标注
典型 Iterator::Item 少见，特殊多态需求

二、默认泛型类型参数 + 运算符重载

语法

Trait<Param = DefaultType> — 给泛型参数默认值，简化常规使用。

trait Add<RHS = Self> {
    type Output;
    fn add(self, rhs: RHS) -> Self::Output;
}

场景 1：同类型相加（默认 RHS = Self）

#[derive(Debug, PartialEq)]
struct Point { x: i32, y: i32 }

impl Add for Point {  // 等价 impl Add<Point> for Point，使用默认 RHS
    type Output = Point;
    fn add(self, rhs: Point) -> Self::Output {
        Point { x: self.x + rhs.x, y: self.y + rhs.y }
    }
}

// p1 + p2 → Point { x: 4, y: 6 }

场景 2：不同类型相加（显式 RHS）

struct Millimeters(u32);
struct Meters(u32);

impl Add<Meters> for Millimeters {
    type Output = Millimeters;
    fn add(self, rhs: Meters) -> Self::Output {
        Millimeters(self.0 + rhs.0 * 1000)  // 1m = 1000mm
    }
}

// Millimeters(500) + Meters(2) → Millimeters(2500)

作用总结

  • 大部分场景用默认类型，代码简洁
  • 特殊场景显式指定泛型参数，向下兼容旧代码

三、完全限定语法（消歧义）

多个同名方法/关联函数时，明确指定调用哪一个。

1. 同名方法（带 self）

trait Pilot { fn fly(&self); }
trait Wizard { fn fly(&self); }
struct Human;
impl Human { fn fly(&self) { /* 人类 */ } }
impl Pilot for Human { fn fly(&self) { /* 飞行员 */ } }
impl Wizard for Human { fn fly(&self) { /* 法师 */ } }

let person = Human;
person.fly();           // 类型自身方法（优先）
Pilot::fly(&person);    // Pilot 的 fly
Wizard::fly(&person);   // Wizard 的 fly

2. 同名关联函数（无 self）— 必须完全限定

编译器无法从「接收者」推断，须 <Type as Trait>::func()：

trait Animal { fn baby_name() -> String; }
struct Dog;
impl Dog { fn baby_name() -> String { "小狗崽".into() } }
impl Animal for Dog { fn baby_name() -> String { "幼犬".into() } }

Dog::baby_name();                  // Dog 自身
<Dog as Animal>::baby_name();      // Animal trait 实现

四、父 Trait（Supertrait）

语法：trait A: B — 要实现 A，必须先实现 B；A 的方法可使用 B 的能力。

trait OutlinePrint: Display {
    fn outline_print(&self) {
        let s = self.to_string();  // 依赖 Display
        println!("{}", "*".repeat(s.len() + 2));
        println!("*{}*", s);
        println!("{}", "*".repeat(s.len() + 2));
    }
}

impl OutlinePrint for i32 {}  // i32 已实现 Display

五、Newtype 模式（绕过孤儿规则）

孤儿规则

不能为外部类型实现外部 trait（两者都不在本 crate）。

// impl Display for Vec<String> {}  // E0117 违反孤儿规则

解决方案

元组结构体包装 → 创造本地新类型：

struct Wrapper(Vec<String>);

impl fmt::Display for Wrapper {
    fn fmt(&self, f: &mut fmt::Formatter) -> fmt::Result {
        write!(f, "[{}]", self.0.join(", "))
    }
}

补充

  1. 无运行时开销 — 编译期包装，优化后与直接使用内部类型等价
  2. 需手动转发方法，或 Deref 部分暴露内部 API
  3. #[repr(transparent)] 用于 FFI/ABI，不是性能优化手段

六、易错点 & 编译报错

# 易错 说明
1 impl Container for Vec 方法名 push 递归 须 newtype 或 Vec::push(self, v) 全路径
2 关联类型与泛型 trait 混用场景 关联类型 = 一种；泛型 = 多种 impl
3 FQS 只写 Animal::baby_name() 无 self 时须 <Dog as Animal>::baby_name()
4 impl OutlinePrint for T 未 impl Display supertrait 不满足 → 编译失败
5 直接 impl Display for Vec<String> E0117 孤儿规则
6 newtype「有性能开销」 零运行时开销

七、速记

  1. 关联类型：type Item，一次 impl，Iterator 经典
  2. 默认泛型：Add<Rhs = Self>，运算符重载
  3. FQS：<Type as Trait>::func()
  4. supertrait：A: B，先 B 后 A
  5. newtype：绕过孤儿规则，零开销

二、newtype 模式：类型安全与封装

1. 核心定义

单元素元组结构体包装已有类型 → 完全独立的新类型，与原类型不互通。

2. 两大用途

（1）类型安全 — 区分语义相同、底层一致的值

struct Millimeters(u32);
struct Meters(u32);

let mm = Millimeters(1000);
let m = Meters(1);
// let sum = mm + m;  // E0308：类型不匹配

（2）封装抽象 — 隐藏内部实现

struct People(HashMap<i32, String>);  // 字段默认私有

impl People {
    fn new() -> Self { Self(HashMap::new()) }
    fn add(&mut self, id: i32, name: String) { self.0.insert(id, name); }
    fn get_name(&self, id: i32) -> Option<&str> {
        self.0.get(&id).map(|s| s.as_str())
    }
}
// people.0;  // E0616：私有字段

（3）结合孤儿规则

为外部类型 impl 外部 trait → newtype 包装（见 19.2 §五）。

三、类型别名 type

1. 基础语法

type 别名 = 原类型; — 不创建新类型，编译器完全互通。

type Kilometers = i32;

let a: Kilometers = 10;
let b: i32 = 20;
let c = a + b;  // OK

2. 常用场景

简化超长类型：

type Thunk = Box<dyn Fn() + Send + 'static>;
type ClosureBox = Box<dyn Fn(u32) -> u32>;

统一 Result 错误类型（标准库经典）：

// std::io::Result<T> 等价于：
type Result<T> = std::result::Result<T, std::io::Error>;

3. newtype vs 类型别名

特性 newtype type 别名
创建新类型 ✅ 是 ❌ 否
类型互通 完全不互通 完全互通
主要用途 类型安全、封装、孤儿规则 简化书写、统一接口

四、永不类型 !（Never Type）

1. 定义

空类型，无合法值 — 表达式永不正常返回（发散）。

2. 典型场景

  • panic!()
  • 无限 loop {}
  • continue / break（部分分支）
fn diverge() -> ! {
    panic!("程序终止，永不返回");
}

3. 核心特性

! 可隐式转换为任意类型 → match/if 分支类型统一：

let num = Some(5);
let res = match num {
    Some(n) => n,
    None => panic!("无值"),  // ! → i32
};

let val = if choice { 100 } else { crash() };  // else 分支 ! → i32

五、DST & Sized / ?Sized

1. 什么是 DST

编译期无法确定大小的类型：

  • [T]（非 &[T]）
  • str（非 &str）
  • dyn Trait（trait 对象底层）

2. 黄金规则

DST 不能单独使用，必须包裹在指针/智能指针中：

合法 非法
&str、Box<str> let s: str = ...
&[T]、Box<[T]> let a: [i32] = ...
&dyn Trait、Box<dyn Trait> let v: Vec<str>

3. Sized 与 ?Sized

fn normal<T>(t: T) {}           // 等价 fn normal<T: Sized>(t: T)
fn accept_dst<T: ?Sized>(t: &T) {}  // 可接收 str、dyn Trait 等
  • Sized：编译期已知固定大小（默认约束）
  • ?Sized：放宽约束，允许 DST — 参数必须用 &T / Box<T> 等

4. 典型应用

通用工具函数同时兼容定长类型与 DST：

fn print_content<T: ?Sized>(val: &T)
where
    T: std::fmt::Display,
{

}

高级函数与闭包

核心结论（先背）

  1. fn(...)：函数指针类型（具体类型，非 trait）；不捕获环境
  2. Fn/FnMut/FnOnce：trait；闭包与函数指针均可实现
  3. 日常 API：优先 F: Fn(...) — 兼容闭包 + 函数指针
  4. 返回闭包：匿名类型不能直接写 → impl Fn（单一类型）或 Box<dyn Fn>（多分支）
  5. map：可传闭包、方法项、构造器

一、函数指针 fn

核心概念

  1. 语法：fn(参数) -> 返回值 — 具体类型，不是 trait
  2. 普通函数、关联函数可转为函数指针，作为参数传递
  3. 函数指针自动实现 Fn/FnMut/FnOnce → 接收 F: Fn 的 API 也能传函数指针
  4. 选型： - 日常：F: Fn(...) 泛型 — 灵活性最高 - 特殊：FFI / C 回调 — 强制 fn 类型

1. 基础用法

fn calc(num: i32, func: fn(i32) -> i32) -> i32 {
    func(num)
}

fn double(x: i32) -> i32 { x * 2 }

fn main() {
    let res = calc(10, double);  // 函数名 → 函数指针
    // calc(10, |x| x * 2)  // 闭包不是 fn 类型，此处不行
}

2. 函数指针 vs 泛型 F: Fn

fn run_func<F: Fn(i32) -> i32>(x: i32, f: F) -> i32 {
    f(x)
}

fn add_one(x: i32) -> i32 { x + 1 }

run_func(5, add_one);    // 函数指针 OK
run_func(5, |x| x - 1);  // 闭包 OK
fn(i32) -> i32 F: Fn(i32) -> i32
接受闭包 ❌ ✅
接受函数指针 ✅ ✅
典型场景 FFI 标准库迭代器

二、迭代器 map：传函数 / 方法项

Iterator::map 参数是 Fn，除闭包外还可传方法项、构造器。

1. 方法项 ToString::to_string

let nums = vec![1, 2, 3];
let s1: Vec<_> = nums.iter().map(|n| n.to_string()).collect();
let s2: Vec<_> = nums.iter().map(ToString::to_string).collect();
// s1 == s2

2. 结构体 / 枚举构造器

struct Wrapper(u32);
enum Status { Value(u32), Stop }

(0u32..3).map(Wrapper).collect::<Vec<_>>();
(0u32..5).map(Status::Value).collect::<Vec<_>>();
// Wrapper / Status::Value 符合 fn(T) -> U 签名

三、返回闭包

问题根源

  • 闭包是编译器生成的匿名独有类型
  • 每个闭包类型不同
  • 不能直接写 fn bad() -> (i32) -> i32 { |x| x + 1 }

解决方案：Box<dyn Fn>

  1. 闭包 impl Fn/FnMut/FnOnce
  2. 装箱为 Box<dyn Fn(...) -> ...>（DST + 胖指针）
  3. 支持运行时多态 — 多分支返回不同闭包

1. 基础返回

fn return_closure() -> Box<dyn Fn(i32) -> i32> {
    Box::new(|x| x + 1)
}

2. 多分支返回不同闭包（dyn 核心优势）

fn select_closure(flag: bool) -> Box<dyn Fn(i32) -> i32> {
    if flag {
        Box::new(|x| x * 2)
    } else {
        Box::new(|x| x / 2)
    }
}
// impl Fn 无法做到 — 两个分支是不同匿名类型

3. 区分 Fn / FnMut / FnOnce 返回

行为 返回类型
只读，多次调用 Box<dyn Fn()>
修改捕获变量 Box<dyn FnMut()>
消耗捕获 Box<dyn FnOnce()> 
fn get_fnmut() -> Box<dyn FnMut()> {
    let mut cnt = 0;
    Box::new(move || {
        cnt += 1;
        println!("计数: {cnt}");
    })
}

impl Fn vs Box<dyn Fn>

impl Fn(...) Box<dyn Fn(...)>
分发 静态 动态（vtable）
多分支不同闭包 ❌ ✅
性能 更优 微小开销

四、闭包 trait 速查

Trait 调用 典型捕获
Fn &self 共享借用 / Copy
FnMut &mut self 可变借用
FnOnce self 移动

函数指针不捕获 → 同时 impl 三个 trait。

五、易混点 & 易错点

# 易混/易错 正确理解
1 fn vs Fn fn = 指针类型；Fn = trait
2 calc(10, \|x\| x*2) 传给 fn 参数 闭包不是 fn 类型 → 用 F: Fn 或装箱
3 impl Fn 多分支返回 只能单一类型 → Box<dyn Fn>
4 Box<dyn Fn> 零开销 有 vtable 动态分发
5 返回 FnMut 闭包却用 Box<dyn Fn> 会修改捕获 → Box<dyn FnMut>
6 thread::spawn 闭包 常需 Send + 'static，注意捕获生命周期

六、速记（背诵版）

  1. fn：函数指针，具体类型，FFI 场景；日常用 F: Fn
  2. map：闭包 / ToString::to_string / 构造器
  3. 返回闭包：不能直接写 → Box<dyn Fn> 或 impl Fn
  4. 多分支闭包：只有 Box<dyn Fn> 可行
  5. fn(...) 存函数 · Fn(...) 是 trait

核心结论（先背）

  1. 宏 = 编译期元编程 — 写「生成代码的代码」，编译期展开，运行时无宏调用开销
  2. 声明宏 macro_rules! — Token 模式匹配 + $(...),* 重复
  3. 过程宏 — 独立 proc-macro crate；TokenStream → TokenStream
  4. 三类过程宏：derive · 属性 · 函数式

一、宏核心总览

1. 定义

宏属于编译期元编程：在编译阶段展开为目标 Rust 代码，运行时无「调用宏」的额外逻辑。

2. 两大分类

类型 语法 特点
声明宏 macro_rules! Token 模式匹配，入门简单
过程宏 #[proc_macro_*] 解析 TokenStream，能力更强

过程宏三子类：

  • 派生宏：#[derive(MyTrait)]
  • 属性宏：#[my_attr]
  • 函数式宏：my_macro!()

3. 宏 vs 函数

对比项 宏 普通函数
执行时机 编译期展开 运行期调用
参数 任意 Token 流、可变结构 固定签名、类型、个数
能力 可生成 struct/impl/代码块 仅执行业务逻辑
调试 报错绕、难读 栈追踪清晰
作用域 先定义/导入，后使用 顺序宽松

选型：优先函数；函数做不到再考虑宏。

二、声明宏 macro_rules!

1. 核心原理

匹配源代码 Token 流（非运行时值），成功后替换为展开代码：

macro_rules! 宏名 {
    (匹配模式) => { 展开代码 };
    // 多个分支，从上到下匹配
}

2. 捕获标识 & 重复语法

片段说明符（常用）

说明符 捕获
$var:expr 表达式
$var:ident 标识符（变量/函数/类型名）
$var:ty 类型
$var:stmt 语句
$var:tt 单个 token 树

重复规则

写法 含义
$( 内容 ),* 0 个或多个，逗号分隔
$( 内容 ),+ 1 个或多个
$( 内容 )? 0 或 1 个

3. 实战：my_vec!

macro_rules! my_vec {
    () => { Vec::new() };
    ( $( $x:expr ),* $(,)? ) => {
        {
            let mut temp_vec = Vec::new();
            $( temp_vec.push($x); )*
            temp_vec
        }
    };
}

// my_vec![]        → []
// my_vec![1, 2, 3] → [1, 2, 3]

→ 完整可运行：19.5-macros-demo/decl_macro_demo/

4. 关键特性

  1. 卫生宏（Hygienic）：宏内局部变量不污染外部命名空间
  2. 分支从上到下匹配，首个成功即展开
  3. 宏须在使用之前定义或 use 导入

三、过程宏（Proc-Macro）

1. 整体架构

TokenStream（输入） → syn 解析 AST → quote 生成 → TokenStream（输出）

工程约束：

  1. 过程宏必须独立 crate
  2. Cargo.toml：[lib] proc-macro = true
  3. 主项目通过 path/workspace 依赖引入

标配依赖：syn（解析 AST）+ quote（生成 Token）

2. 三类过程宏

类型 写法 用途
派生宏 #[derive(XXX)] 自动生成 trait impl
属性宏 #[xxx] 修饰/包裹 item
函数式宏 xxx!() 类似声明宏，能力更强

3. Workspace 结构（Demo）

hello_macro — trait 定义

pub trait HelloMacro {
    fn hello_macro();
}

hello_macro_derive — 派生宏

#[proc_macro_derive(HelloMacro)]
pub fn hello_macro_derive(input: TokenStream) -> TokenStream {
    let ast = parse_macro_input!(input as DeriveInput);
    let name = ast.ident;
    quote! {
        impl hello_macro::HelloMacro for #name {
            fn hello_macro() {
                println!("Hello, Macro! My name is {}", stringify!(#name));
            }
        }
    }.into()
}

pancakes — 使用方

use hello_macro::HelloMacro;
use hello_macro_derive::HelloMacro;

#[derive(HelloMacro)]
struct Pancakes;

fn main() {
    Pancakes::hello_macro();  // Hello, Macro! My name is Pancakes
}

cargo run -p pancakes

# 易错 正确理解
1 宏分支顺序无关 从上到下，通用分支放最后
2 $(...) 括号/逗号写错 须成对；, 位置错误 → 编译失败

  3. 区分：简单重复 → 声明宏；复杂 AST/derive → 过程宏
  4. 调试：cargo expand
  5. 原则：函数优先，宏兜底
