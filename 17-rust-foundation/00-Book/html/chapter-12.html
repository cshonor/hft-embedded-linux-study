12.1

接受命令行参数

我们要做一个简化版 minigrep，先让程序能接受两个命令行参数：

  • query：要搜索的字符串
  • filename：要搜索的文件路径

对应 demo 项目：00-Book/12-cli-project/12.1-minigrep-args-demo/

读取参数：std::env::args

std::env::args() 返回一个迭代器，常见做法是 collect() 成 Vec<String>：

use std::env;

fn main() {
    let args: Vec<String> = env::args().collect();
    println!("{args:?}");
}

注意：

  • args[0] 通常是程序名（例如 target/debug/minigrep）
  • 我们真正需要的两个参数在 args[1] 与 args[2]
  • 如果参数里包含无效 Unicode，args() 会 panic；需要更底层兼容时可用 args_os()

保存参数到变量

let query = &args[1];
let filename = &args[2];

之后就能在程序其它部分使用 query 与 filename。

运行 demo（Windows 重点）

Cargo 传递参数给程序时，需要在参数前加 --：

cd 00-Book/12-cli-project/12.1-minigrep-args-demo

# 不带参数
cargo run

# 带参数（注意这个 --）
cargo run -- needle haystack.txt

读取文件

在拿到命令行参数 query 和 filename 后，下一步是读取 filename 指定的文件内容（先把内容打印出来，验证流程正确）。

对应 demo 项目：00-Book/12-cli-project/12.2-minigrep-readfile-demo/

准备测试文件 poem.txt

在 demo 项目根目录创建 poem.txt，内容是多行文本（后续用于搜索功能）。

读取文件：fs::read_to_string

标准库的 fs::read_to_string(filename) 会返回 Result<String, io::Error>：

  • Ok(contents)：文件内容
  • Err(e)：读取失败（文件不存在、权限不足等）

示例里先用 expect(...) 简化错误处理（后续会重构）。

运行 demo（Windows 记得 --）

cd 00-Book/12-cli-project/12.2-minigrep-readfile-demo
cargo run -- the poem.txt
12.3

重构改进模块性和错误处理

这一节的目标是把 main 里杂糅的职责拆开，并把错误处理变得更“对用户友好”：

  • 关注分离：main.rs 只负责启动程序；具体逻辑放到 lib.rs
  • 配置聚合：用 Config 结构体表达 query/filename 的关系
  • 错误集中处理：Config::new 与 run 返回 Result，让 main 统一打印错误并用非零状态码退出

对应 demo 项目：00-Book/12-cli-project/12.3-minigrep-refactor-demo/

二进制项目的关注分离（惯用结构）

  • src/main.rs
  • 收集参数
  • 构建 Config
  • 调用 run
  • 处理错误并 process::exit(1)
  • src/lib.rs
  • Config 定义与 Config::new
  • run(config)：真正的业务逻辑

这样 lib.rs 里的逻辑更容易测试与复用；main 也更小、更清晰。

demo 运行（Windows 记得 --）

cd 00-Book/12-cli-project/12.3-minigrep-refactor-demo

# 参数不足：友好错误 + 非零退出码
cargo run

# 文件读取成功：打印内容
cargo run -- the poem.txt

采用测试驱动开发完善库的功能

这一节用 TDD（测试驱动开发）方式把 minigrep 的核心“搜索”能力补齐，并让它可以被单元测试直接覆盖。

对应 demo 项目：00-Book/12-cli-project/12.4-minigrep-search-demo/

TDD 基本循环

  • 写一个会失败的测试（失败原因要符合预期）
  • 写/改最少的代码让测试通过
  • 重构代码，确保测试仍通过
  • 重复

search(query, contents) 的期望行为

  • 输入：查询字符串 query + 待搜索文本 contents
  • 输出：所有包含 query 的行（借用自 contents）

签名采用书里的形式（显式生命周期）：

pub fn search<'a>(query: &str, contents: &'a str) -> Vec<&'a str>

demo 运行

cd 00-Book/12-cli-project/12.4-minigrep-search-demo

# 运行测试
cargo test

# 运行搜索
cargo run -- frog poem.txt
cargo run -- body poem.txt

处理环境变量

我们为 minigrep 增加一个可选功能：通过环境变量控制是否大小写敏感搜索。

  • 默认：大小写敏感
  • 当设置 CASE_INSENSITIVE 环境变量时：大小写不敏感

对应 demo 项目：00-Book/12-cli-project/12.5-minigrep-env-demo/

TDD：为大小写不敏感搜索补测试

在原有 search（大小写敏感）基础上：

  • 把原测试改名为 case_sensitive
  • 新增 case_insensitive 测试，对 search_case_insensitive 进行约束

Config 增加开关：case_sensitive

let case_sensitive = std::env::var("CASE_INSENSITIVE").is_err();
  • 没设置环境变量 → is_err() 为 true → 大小写敏感
  • 设置了环境变量（任何值）→ is_err() 为 false → 大小写不敏感

运行 demo

cd 00-Book/12-cli-project/12.5-minigrep-env-demo

# 跑测试
cargo test

# 默认：大小写敏感（只匹配小写 to）
cargo run -- to poem.txt

PowerShell 开启大小写不敏感（两步）：

$env:CASE_INSENSITIVE=1
cargo run -- to poem.txt

将错误信息输出到标准错误而不是标准输出

命令行程序通常把正常输出写到 stdout，把错误信息写到 stderr。这样用户把 stdout 重定向到文件时，仍然能在屏幕上看到错误信息。

对应 demo 项目：00-Book/12-cli-project/12.6-minigrep-stderr-demo/

println! vs eprintln!

  • println!：写到 stdout
  • eprintln!：写到 stderr

我们把 main.rs 里打印错误的地方从 println! 改为 eprintln!。

PowerShell 重定向验证

在 PowerShell 里：

  • > 只重定向 stdout（成功输出流）
  • 2> 重定向 stderr

在 demo 目录里运行：

cd 00-Book/12-cli-project/12.6-minigrep-stderr-demo

# 触发“缺少参数”的错误：stdout 写入 output.txt，stderr 仍显示在屏幕
cargo run --quiet > output.txt

# 正常运行：stdout 写入 output.txt
cargo run --quiet -- to poem.txt > output.txt
