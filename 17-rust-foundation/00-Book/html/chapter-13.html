一、核心定义

闭包是可存入变量、可作为函数参数的匿名函数。与普通 fn 的核心区别：能捕获定义处外层作用域的变量 → 行为延后执行、惰性求值。

fn 闭包
捕获环境 ❌ ✅
类型 函数指针 / 具名 匿名类型，编译器推导
参数/返回类型 通常须标注 可选，上下文推断

基础语法

→ 四段式演变详解：13.1.1

let add = |x: i32| -> i32 { x + 1 }; // 完整标注
let add = |x| x + 1;                 // 最简：单行可省略 {}
add(5);
  1. 参数：|参数列表|``（不是()`）
  2. 体：单语句可省略 {}；多语句必须 {}
  3. 类型可选 — 不像 fn 强制标注

类型锁定（易错）

→ 完整讲解 · 速查表：13.1.3 类型推导易错点

同一闭包首次调用推导参数类型后永久锁定；只定义不调用且无标注 → E0282：

let cl = |x| x;
cl(5);      // 推导 x: i32
// cl("abc"); // ❌ 编译报错

二、业务场景：惰性 + 缓存（Cacher）

1. 提前存变量 — 浪费

let res = simulated_expensive_calc(10); // 立刻算，无用分支也白跑
if flag { println!("{}", res); }

2. 闭包存行为 — 惰性

let calc = |n| simulated_expensive_calc(n); // 只存逻辑
if flag { calc(10); }                          // 需要才算

3. Cacher — 泛型 + Fn trait

闭包是匿名类型，结构体字段不能直接写类型 → T: Fn(...) 约束。

简易版：只缓存一次结果

struct Cacher<T>
where
    T: Fn(u32) -> u32,
{
    calc: T,
    val: Option<u32>,
}

缺陷：只缓存第一次入参；换参数仍返回旧值 → demo CacherOnce。

通用版：HashMap 多参数缓存

struct Cacher<T, Arg, Ret>
where
    T: Fn(Arg) -> Ret,
    Arg: Eq + Hash,
{
    calc: T,
    cache: HashMap<Arg, Ret>,
}

→ demo CacherMap。

三、三大捕获 Trait：Fn / FnMut / FnOnce

→ 完整讲解 · 推导规则 · 传参铁律 · 速查表：13.1.4 Fn / FnMut / FnOnce

由闭包如何使用捕获变量自动决定 impl 哪几个；所有闭包至少实现 FnOnce — 不是三个都自动 impl。

→ 完整讲解：13.1.4 Fn / FnMut / FnOnce

Trait 捕获 闭包实际 impl
Fn 只读 &T Fn + FnMut + FnOnce
FnMut &mut T FnMut + FnOnce（无 Fn）
FnOnce move / 消耗 至少 FnOnce；消耗时往往仅 FnOnce

层级：Fn ⊂ FnMut ⊂ FnOnce（继承 · bound 由严到宽）→ 13.1.4 §二

四、move 闭包

→ 详解 · 默认捕获 vs move · 线程：13.1.5 move 闭包

move |args| { /* ... */ }

强制把捕获变量 move 进闭包，绑定闭包自身生命周期。

经典：跨线程

use std::thread;

let s = String::from("hello");
let handle = thread::spawn(move || println!("{s}"));
handle.join().unwrap();
// s 已 move，此处不可用（非 Copy 类型）
类型 move 后原变量
Copy（i32） 仍可用（拷贝）
非 Copy（String） 失效

五、易错点汇总

  1. 闭包类型不能显式书写 → 编译器自动 impl Fn 系列；API 用 bound 限定 → 13.1.4 §三
  2. 只定义不调用 → E0282；首次调用锁定类型 → 13.1.3
  3. CacherOnce 只缓存单参数；多参数要 HashMap
  4. move = 强制所有权，不是借用 → 13.1.5
  5. FnMut 不能降级为 Fn 传参 → 13.1.4

.1 闭包四段式语法演变

← 13.1 闭包 hub · 下一条 13.1.2 参数 vs 捕获 · demo：13.1-closures-demo/（syntax_examples）

从全标注到最简，以及省略规则。

一、四段式对照（add 为例）

fn add(x: i32) -> i32 { x + 1 }           // 普通 fn 对照

let add = |x: i32| -> i32 { x + 1 };      // 1. 完整：参数 + 返回 + {}
let add = |x: i32| { x + 1 };             // 2. 省略 ->，保留参数类型
let add = |x: i32| x + 1;                  // 3. 单表达式，省略 {}
let add = |x| x + 1;                      // 4. 最简：全靠推断

add(5); // 6

二、省略规则（核心考点）

1. 参数类型可省

|x| 不写 x: i32 — 第一次调用实参确定类型后永久固定：

let add = |x| x + 1;
add(5i32);   // x 锁定 i32
// add(5u64); // ❌ 编译报错

→ 完整讲解：13.1.3 类型推导易错点

2. 返回值 -> T 可省

形式 规则
单表达式 \|x\| x + 1 不用写 ->，返回自动推导
多语句 {} 须显式 -> T，否则编译报错 
let add = |x: i32| -> i32 {
    let tmp = x + 2;
    tmp - 1
};

3. 单表达式可省 {}

  • 一条表达式：|x| x + 1
  • 多条语句 / 带分号语句：必须 {}

三、闭包 vs fn

fn 闭包
类型标注 签名须全标注 可推断
捕获环境 ❌ ✅ 
let base = 10;
let add = |x| base + x; // 捕获外层 base
println!("{}", add(5)); // 15

→ 形参 vs 捕获详解：13.1.2

13.1

.2 参数 vs 捕获（两套独立能力）

← 13.1.1 四段式语法 · 13.1 hub · 下一条 13.1.3 类型推导 · demo：13.1-closures-demo/（syntax_examples §参数/捕获）

无参闭包照样能捕获外部变量 — 有没有形参与抓不抓外部变量是两回事，互不干扰。

一、分清两个概念

闭包形参 \|n\| 外部捕获
写在哪 \|\| 里面 \|\| { … } 体内直接用外层已有变量
谁提供 调用时外部传入 从当前作用域抓进来
与无参关系 无参 = 形参列表为空 与有没有形参无关，无参也能捕获

二、无参闭包 + 外部捕获（三种常见）

① 不可变捕获（只读 → Fn）

let num = 100;
let cb = || println!("{}", num);

cb();
cb(); // 可多次调用

② 可变捕获（修改外部 → FnMut，&mut 借用）

无 move 永远拿不到所有权 — 改的是外面的变量 → 13.1.5 §一

let mut num = 0;
let mut cb = || num += 1; // &mut 借用，所有权仍在外面

cb();
println!("{}", num); // 1

③ move 捕获（所有权进闭包，无参也生效）

想要所有权必须写 move → 13.1.5 §二–§三

let s = String::from("hello");
let cb = move || println!("{}", s);

cb();
// println!("{}", s); // ❌ 外层 s 已 move（非 Copy）

→ 捕获规则 · Fn trait：13.1.4 Fn 系列 · move 详解：13.1.5

三、有参 + 捕获（最常见）

let base = 10;
let cb = |n: i32| base + n;

println!("{}", cb(5)); // 15

只有参数、无捕获

let add = |n: i32| n + 1;
println!("{}", add(2)); // 3
println!("{}", add(5)); // 6

只有捕获、无参数

let base = 10;
let add = || base + 1;
println!("{}", add()); // 11

四、一句话

  • 有没有参数，不影响抓取外部变量 — 无参闭包就是 || { 直接用外面的变量 }，编译器按借用 / move 规则自动处理捕获。
  • 有参数：动态入参、逻辑更复用；无参数：依赖固定环境。

闭包形参 ≠ 捕获 — Fn trait 只看捕获怎么用 → 13.1.4 §三.4

.3 闭包类型推导易错点

← 13.1.2 参数 vs 捕获 · 13.1 hub · 下一条 13.1.4 Fn 系列 · demo：13.1-closures-demo/（type_inference_examples）

Rust 闭包默认不写类型，靠第一次调用 / 使用上下文推导参数与返回类型。

一、错误：只定义，不调用、不标注

let add = |x| x + 1;
// ❌ E0282: type annotations needed — 无法推断 x 的类型

原因

闭包 |x| x + 1 里 x 可以是 i32、i64、f64……编译器没有任何上下文，不知道选哪种，直接拒绝编译。

二、正确方式一：至少调用一次

let add = |x| x + 1;
add(5i32); // ✅ 推导出 x: i32，返回 i32

一旦用 i32 调用过，add 就被固定为接受 i32 的闭包，再传别的类型会报错：

// add(3.14); // ❌ expected i32, found floating-point

→ 与 13.1 §一 · 13.1.1 §二 同一机制：首次使用锁定类型。

三、正确方式二：直接写全类型标注（最稳妥）

let add = |x: i32| -> i32 { x + 1 }; // ✅ 明确，无需调用也能编译
add(5);

参数类型、返回类型、多语句体 — 四段式演变见 13.1.1。

四、类比（好记）

场景 空上下文 解决
let v = Vec::new(); ❌ 不知元素类型 Vec<i32> 或立刻 push(5)
let add = \|x\| x + 1; ❌ 不知 x 类型 \|x: i32\| 或立刻 add(5i32)

空上下文 → 无法推导 → 必须标注或调用一次。

五、速查表

情况 能否编译 做法
只写 \|x\| x + 1，从不调用 ❌ 加类型或调用一次
调用 add(5i32) 后再 add(3.14) ❌ 类型已锁 i32
\|x: i32\| -> i32 { x + 1 } ✅ 最稳妥
传给 Fn(i32) -> i32 参数 ✅ 签名提供上下文，可不写闭包类型
存入 Cacher<T: Fn(u32) -> u32> ✅ 泛型 bound 提供上下文

13.1

.4 三大捕获 Trait：Fn / FnMut / FnOnce

← 13.1.3 类型推导 · 13.1 hub · 下一条 13.1.5 move 闭包 · demo：13.1-closures-demo/（closure_capture_examples · fn_trait_examples）

先拆开两大概念（互不绑定）
- 捕获规则：默认借用（&T / &mut T）；move = 强制所有权进闭包 → 13.1.5
- Fn / FnMut / FnOnce：编译器看怎么用捕获变量（只读 / 修改 / 调用时消耗），自动 impl

核心结论
1. Fn / FnMut 绝大多数只用借用，不拿所有权；只有调用时消耗捕获才往往只剩纯 FnOnce。
2. move ≠ FnOnce — 只转移所有权进闭包，不决定 trait。
3. 不加 move = 默认借用，通常得到 Fn 或 FnMut。

一、三个 trait 区别（按捕获规则）

Trait 语义 触发条件 闭包实际 impl
FnOnce 至少能调用一次；消耗捕获时只能一次 拿走所有权 / 消耗不可复制变量；默认所有闭包都有 必有
FnMut 可多次调用，能改捕获变量 可变借用 &mut T 捕获 FnMut + FnOnce，不含 Fn
Fn 可多次调用，只读捕获 不可变借用 / 无捕获 / 只捕获 Copy Fn + FnMut + FnOnce

Trait 层级 → 详见 §二 Trait 继承

二、Trait 继承：约束由严到宽

不是「权限高低」，而是 trait 继承 + 调用能力契约：参数 bound 由严到宽；FnOnce 是最底层父 trait（要求最少、适用范围最广）。

标准库定义（源码）

trait FnOnce() {}
trait FnMut(): FnOnce() {}
trait Fn(): FnMut() {}

人话：

继承 含义
Fn : FnMut impl Fn → 自动满足 FnMut
FnMut : FnOnce impl FnMut → 自动满足 FnOnce

反过来：

  • 是 Fn → 一定也是 FnMut、FnOnce
  • 是 FnMut → 一定也是 FnOnce
  • 是 纯 FnOnce → 未必是另外两个
Fn  ⊂  FnMut  ⊂  FnOnce     （子 trait 约束更严 · 父 trait bound 更宽）

三个 trait 的「调用能力契约」

与有没有所有权是两回事 — 描述允许多少次、怎样调用：

Trait 契约（允许多少）
FnOnce 至少能调用一次（门槛最低）
FnMut 可反复调用，且调用时可修改捕获
Fn 可反复调用，且调用时不修改捕获

核心逻辑：可多次调用 ⊇ 可调用一次

为什么 FnMut 也必然 impl FnOnce？

FnMut 靠可变借用，变量不被消耗，可以 f(); f(); …
→ 能调无数次 → 当然也能调至少一次 → 满足 FnOnce 契约。

let mut x = 0;
let mut f = || x += 1; // FnMut：可变借用，无所有权转移

f(); // 第 1 次 → 符合 FnOnce
f(); // 第 2 次 → 符合 FnMut
// 自动 impl：FnMut + FnOnce（不含 Fn）

Q：FnMut 没拿所有权，为啥还要 FnOnce？
A：捕获方式决定闭包属于哪一类；trait 继承描述调用能力包含关系 — 能多次 ⇒ 必能一次。

为什么 Fn 也 impl FnMut + FnOnce？

  • 能无限次只读调用 → 满足「可多次调用」→ FnMut
  • 能多次 → 也满足「至少一次」→ FnOnce

类比：

Trait 类比
Fn 公共阅览室：反复来、不能乱动书
FnMut 自习室：反复来、能写写画画
FnOnce 临时落脚点：能进来坐一次就行

能当阅览室 → 当然也能当自习室、临时落脚点。

let a = 10;
let f = || println!("{}", a); // Fn

f(); // 一次 → FnOnce ✓
f(); // 多次只读 → Fn / FnMut ✓

捕获方式 ≠ Trait 继承（再强调）

维度 决定什么
捕获（借用 / move / 是否消耗） 闭包属于 Fn / FnMut / 纯 FnOnce
继承（语法父子关系） impl 子 trait 时连带 impl 父 trait
  • 纯 FnOnce：move || drop(s) — 调一次消耗，不能当 FnMut/Fn
  • Fn / FnMut：借用、可多次 → 必然连带 impl FnOnce

一句话：「只能用一次」是最低门槛；「能用很多次」一定包含「能用一次」。

反向验证

闭包类型 能当 FnOnce？ 能当 FnMut？ 能当 Fn？
纯 FnOnce ✅ ❌ ❌
FnMut ✅ ✅ ❌
Fn ✅ ✅ ✅

三、捕获规则 vs Fn trait（分开看）

日常对照表（够用）

写法 捕获方式 最终 trait 多次调用
无 move，只读外部 不可变借用 &T Fn 全套 ✅
无 move，修改外部 可变借用 &mut T FnMut + FnOnce ✅
move，内部只读 所有权在闭包内 Fn 全套 ✅
move，调用时消耗变量 所有权 + 消耗 仅 FnOnce ❌ 一次

1. 不加 move（默认：借用，不拿所有权）

let s = String::from("hi");
let c = || println!("{}", s); // &T 只读借用
c(); c();
// Fn 全套 — 全程没拿 s 的所有权，外面 s 仍可用

let mut x = 0;
let mut c = || x += 1; // &mut T 可变借用
c(); c();
// FnMut + FnOnce — 也没拿所有权

👉 借用 → Fn / FnMut（主流路径）

2. 加 move（所有权进闭包 — 仍不直接等于 FnOnce）

情况 A：move + 只读，调用不消耗 → 仍是 Fn，可多次调

let s = String::from("hi");
let c = move || println!("{}", s);
c(); c(); // ✅ 有 move、所有权在闭包里，但不是纯 FnOnce
// 外面 s 不可用；闭包内 s 每次调用都还在

情况 B：move + 调用时消耗（drop / 返回 / 转移）→ 仅 FnOnce

let s = String::from("hi");
let c = move || drop(s);
c();
// c(); // ❌ 仅 FnOnce

👉 move + 调用就消耗 → 纯 FnOnce（日常最常见的纯 FnOnce 组合）

3. 两个常见问题

Q1：三个 trait 都必须拿所有权吗？

不是。 Fn / FnMut 主流是借用；只有调用时销毁/转移捕获，才往往变成纯 FnOnce（此时才一定涉及所有权消耗）。

Q2：纯 FnOnce 一定绑 move 吗？

语法上不等价；但日常几乎总是 move + 消耗 才出现纯 FnOnce — 因为默认借用不会被「调一次就失效」。不加 move 也能 FnOnce（极少），了解即可。

4. 其他误区（与 capture 无关）

误区 正解
无参闭包 = Fn 看捕获，不看形参 — 详见 13.1.2
在循环里 = Fn 能循环调 → 至少 Fn/FnMut；纯 FnOnce 进不了 
let mut x = 0;
let mut c = |v: &mut i32| { x += *v; }; // 改捕获 x → FnMut

5. 一句话理顺

  1. 不加 move → 永远是借用（&T / &mut T），永远拿不到所有权。
  2. 无 move + 修改 → 改原作用域变量，靠 &mut → 通常 FnMut。
  3. move + 修改 → 改闭包内副本/自有变量（Copy 外面仍可用但值不变；非 Copy 外面失效）。
  4. move = 所有权进闭包，与 Fn/FnMut/FnOnce 无强制绑定。
  5. move + 调用时销毁/转移 → 纯 FnOnce。

四、通用判断流程（编译器同逻辑）

① 调用时会消耗捕获的所有权？  → 仅 FnOnce
        ↓ 否
② 会修改捕获的外部变量？      → FnMut + FnOnce（无 Fn）
        ↓ 否
③ 无捕获 / 只读借用 / Copy / move 后只读  → Fn + FnMut + FnOnce
步骤 条件 impl 结果
① drop(捕获)、返回捕获值、传给要所有权的函数等 仅 FnOnce
② 对捕获变量赋值、+= 等修改 FnMut + FnOnce
③ 既不消耗也不修改 Fn 全套

五、代码速查（与 §三 对照）

1. 无捕获 / 只读 → 实现 Fn（连带 FnMut + FnOnce）

let x = 10;
let c = || println!("{}", x); // 不可变借用
c();
c();
// c：Fn + FnMut + FnOnce

2. 可变捕获 → 实现 FnMut + FnOnce，不实现 Fn

let mut x = 10;
let mut c = || x += 1; // 可变借用
c();
c();
// c：FnMut + FnOnce，**没有 Fn**

3. move + 消耗 → 仅 FnOnce（§三.2B）

let s = String::from("hi");
let c = move || drop(s);
c();

口诀

借用 → Fn / FnMut · move+消耗 → 纯 FnOnce · move 单独 ≠ FnOnce

六、编译器自动 impl（底层逻辑）

编译器分析闭包的变量捕获方式和内部行为，为每个闭包的匿名类型自动生成对应 impl，规则：

编译器 impl 连带 impl 不 impl
Fn FnMut + FnOnce —
FnMut FnOnce Fn
仅 FnOnce — FnMut · Fn

判断依据

1. 是否 impl Fn

  • 不可变借用外部变量、无捕获、或只捕获 Copy 类型
  • 闭包体内不修改任何捕获值
    → 编译器自动 impl Fn（连带 FnMut + FnOnce）

2. 是否 impl FnMut（且无 Fn）

  • 通过 &mut T 可变借用捕获，体内会修改捕获值
    → 自动 impl FnMut + FnOnce，不 impl Fn

3. 是否仅 impl FnOnce

  • 调用时会消耗捕获的所有权（drop、返回捕获值、转移给要 T 的函数等）
    → 只 impl FnOnce

move 本身不够 — 必须再结合「调用时是否消耗」；move 后只读打印 → 仍可能是 Fn（§三.2A）。

→ trait 继承为何 FnMut 连带 FnOnce：§二

补充三点

① 闭包是匿名类型 — 无法手写 impl

let c = || println!("hi");
// ❌ 不存在：impl Fn() for ??? { ... }
// 闭包类型由编译器生成，trait impl 全自动

② 普通函数也实现这三个 trait

独立 fn、方法默认 impl Fn（连带 FnMut / FnOnce），与无捕获闭包表现一致：

fn greet() { println!("hi"); }
// greet 可当 Fn() 传给 take_fn(greet)

③ 开发者能「主动控制」的只有泛型 bound

不用写 impl，但在接收闭包时限定要哪一类：

fn take_fn<F: Fn()>(f: F) {
    f();
} // 只读、可多次

fn take_fnmut<F: FnMut()>(mut f: F) {
    f();
} // 可改捕获值 — 注意 mut f

fn take_fnonce<F: FnOnce()>(f: F) {
    f();
} // 最宽，Fn / FnMut / FnOnce 都能传

→ 传参升级/降级规则见 §七（与 §二 继承一致）。

一句话：只写闭包逻辑，捕获规则决定 impl 哪几个 trait，编译器代劳；你在 API 上用 Fn / FnMut / FnOnce 做约束即可。

七、传参约束（易错：Trait 不能降级）

函数泛型 bound 决定能传哪种闭包 — 与 §二 继承链一致：只能从子 trait 升级到父 trait（bound 变宽），不能降级。

参数要求 可传 不可传
Fn 只读闭包（Fn） FnMut · 仅 FnOnce
FnMut FnMut · Fn 仅 FnOnce
FnOnce Fn · FnMut · FnOnce（最宽） —

错误：降级失败

fn need_fn<F: Fn()>(f: F) {
    f();
}

let mut x = 0;
let f = || {
    x += 1;
}; // FnMut
// need_fn(f); // ❌ expected Fn, found FnMut

正确：升级允许

fn need_fnonce<F: FnOnce()>(f: F) {
    f();
}

let s = String::from("a");
let f = || println!("{}", s); // Fn（只读）
need_fnonce(f); // ✅ Fn 自动满足 FnOnce

铁律：Fn → FnMut → FnOnce 方向可传；反向不行。

八、move 与 trait（补充）

→ move 语法：13.1.5

关键：move 解决谁拥有捕获变量；Fn 系列看怎么用捕获变量。

13.1

.5 `move` 闭包：强制捕获所有权

← 13.1.4 Fn 系列 · 13.1 hub · 13.2 迭代器 · demo：13.1-closures-demo/

先给结论：不加 move，永远拿不到所有权；修改外部变量靠的是可变借用 &mut T。
想要所有权 → 必须显式写 move。
move 管捕获规则；Fn 系列管怎么用捕获 — 二者互不绑定 → 13.1.4 §三

一、不加 move：只有借用，无所有权

Rust 闭包默认借用捕获：

闭包内用法 捕获方式 典型 trait
只读 &T 不可变借用 Fn
修改 &mut T 可变借用 FnMut

全程变量所有权还在原作用域，闭包只是「借过来用」。

let mut a = 1;
let mut f = || a += 1; // 无 move：&mut 借用，改的是外面的 a
f();
println!("{}", a); // 2 — 所有权始终在外面

let s = String::from("hello");
let f = || println!("{}", s);
f();
println!("{}", s); // ✅ 只读借用，s 仍可用

「消耗捕获 → FnOnce」看调用时是否销毁/转移，不是默认借用路径 — 详见 13.1.4。

二、想拿所有权，必须写 move

move 强制把变量所有权转移进闭包，与改不修改无关：

let s = String::from("hello");
let f = move || println!("{}", s);
f();
// println!("{}", s); // ❌ E0382：非 Copy，外面已不可用
类型 move 后原变量
Copy（i32） 仍可用 — 拷贝进闭包，原值还在
非 Copy（String） 失效，不能再读

→ move 不直接等于 FnOnce — 只读 move 仍可能是 Fn：13.1.4 §三.2A

三、关键区分：改的是「外面」还是「闭包内」

修改行为分两种场景：

场景 实际改谁 机制
无 move 原作用域的变量 &mut 借用，无所有权转移
有 move + Copy 闭包内部的副本 拷贝进闭包；外面仍能用，但值不变
有 move + 非 Copy 闭包内部拥有的那份 所有权已归闭包；外面不可用 
// 无 move：改外面的 a
let mut a = 1;
let mut f = || a += 1;
f();
assert_eq!(a, 2);

// move + Copy：改闭包内副本，外面 a 仍是 1
let mut a = 1;
let mut f = move || a += 1;
f();
assert_eq!(a, 1); // 外面没被改

// move + 非 Copy：外面彻底失效
let mut s = String::from("hi");
let f = move || s.len();
f();
// s 已不可用

铁律：不写 move → 一定是借用；想要所有权 → 必须显式 move。

联动 Fn trait

写法 典型 trait
无 move + 修改外部变量 FnMut（&mut 借用）
move + 修改内部变量、不消耗 仍是 FnMut
move + 调用时销毁/转移变量 FnOnce

→ 完整对照表：13.1.4 §三

四、什么时候必须用 move？

场景 原因
跨线程 thread::spawn 线程可能比栈上变量活得更久，必须拥有数据
返回闭包 闭包要带走的变量不能借外层栈
FnOnce / 消耗捕获 如 move \|\| v 把 Vec 整个拿走

经典：线程必须 move

use std::thread;

fn main() {
    let v = vec![1, 2, 3];

    // ❌ 不 move：闭包只借 &v，主线程结束 v 可能已销毁 — 编译器通常直接报错
    // let h = thread::spawn(|| println!("{:?}", v));

    // ✅ move：v 所有权进线程，生命周期独立
    let h = thread::spawn(move || println!("{:?}", v));
    h.join().unwrap();
}

五、move 与 Fn trait（消耗场景）

  • move || { ... } 常见为 FnOnce（所有权被拿走，语义上可能只跑一次）
  • 若捕获的是 Copy 且闭包内只读，仍可能同时满足 Fn
let v = vec![1, 2, 3];
let consume = move || v; // FnOnce：返回 v，消耗捕获
assert_eq!(consume(), vec![1, 2, 3]);
// consume(); // ❌ 第二次调用可能报错（FnOnce）

→ Fn 系列详解：13.1.4 Fn / FnMut / FnOnce

六、小结（直接背）

要点 一句话
默认捕获 不写 move = 借用（&T / &mut T），永远拿不到所有权
修改外部 无 move 靠 &mut 改原变量 → 通常 FnMut
move 强制所有权进闭包；Copy 是拷贝副本，非 Copy 外面失效
跨线程 几乎总是 thread::spawn(move \|\| ...)

一、概念

迭代器：实现了 Iterator trait 的类型，逐个产生序列元素。

  • 是 Rust 处理集合的零成本抽象
  • 核心：只定义规则，不立即执行（惰性）

二、要点总览（先背这几句）

  • 惰性：map/filter 只存规则；collect/sum/for 才真正跑
  • Iterator trait：只必须实现 next + 关联类型 Item
  • 适配器：返回新迭代器，仍然惰性（map/filter/zip…）
  • 消费器：拿走迭代器、用完作废（collect/sum/count/for…）
  • iter / iter_mut / into_iter：对应 &T / &mut T / T，所有权不同
  • 返回迭代器：
  • 单一类型：impl Iterator<Item = T>
  • 分支异构：Box<dyn Iterator<Item = T>>

三、惰性（Lazy）——最关键

定义迭代器 ≠ 执行；只有消费时才计算。

let v = vec![1, 2, 3];
let it = v.iter().map(|x| x * 2);
// ⚠️ 惰性：此时什么都不算，只存「乘 2」规则

// 到这里才真正遍历、计算
let res: Vec<_> = it.collect();
  • 适配器（map/filter/skip）：不干活，只包一层规则
  • 消费器（collect/sum/for/while let … next()）：触发 next()，真正执行

→ Filter 伪实现 · 更多例子：13.2.1 §一–§三 · 分步打印 demo：13.2.4（cargo run -- lazy）

四、Iterator Trait（极简）

pub trait Iterator {
    type Item;                // 关联类型：元素类型
    fn next(&mut self) -> Option<Self::Item>;
}
  • 唯一必须实现：next()
  • next()：每次调用推进状态，返回 Some(值) 或 None（结束）
  • 所有其他方法（map/filter/fold…）都是默认实现，基于 next

→ next 须 mut · Item 与 iter 三件套：13.2.1 §二

五、适配器 vs 消费器（对照表）

1）迭代器适配器（返回新迭代器，惰性）

方法 作用
map(f) 每个元素应用 f，映射新值
filter(f) 保留 f 返回 true 的元素
zip(it2) 与另一个迭代器配对
take(n) 只取前 n 个
enumerate() 产出 (索引, 值)

2）消费器（拿走迭代器，立即执行）

方法 作用
collect::<C>() 收集到集合 C（Vec/HashSet…）
sum() 求和
count() 计数
for x in it 循环遍历（本质：反复 next）
while let Some(x) = it.next() 手动逐个 next()（最底层消费）
fold(init, f) 自定义累加

一句话：适配器 = 链式加工；消费器 = 收尾出结果。

六、iter / iter_mut / into_iter（所有权核心）

方法 元素类型 所有权 原集合还能用？
iter() &T 不可变借用 ✅ 可以继续用
iter_mut() &mut T 可变借用 ✅ 可以继续用（但不能同时借用）
into_iter() T 拿走所有权 ❌ 原集合失效 
let v = vec![1, 2, 3];

// iter：只读借用
for x in v.iter() {
    println!("{}", x);
}
println!("{:?}", v); // ✅ 还能用

// into_iter：拿走所有权
for x in v.into_iter() {
    println!("{}", x);
}
// println!("{:?}", v); // ❌ 报错，所有权已转移

七、返回迭代器怎么写

1）单一类型（推荐：impl Trait）

fn double_it(v: &[i32]) -> impl Iterator<Item = i32> {
    v.iter().map(|x| x * 2)
}
  • 优点：静态分发、零成本
  • 适用：返回确定、单一迭代器类型

2）分支 / 多种迭代器（必须 Box<dyn …>）

fn make_it(flag: bool) -> Box<dyn Iterator<Item = i32>> {
    if flag {
        Box::new((1..=5).into_iter())
    } else {
        Box::new(vec![10, 20, 30].into_iter())
    }
}
  • 适用：不同分支返回不同迭代器类型
  • 代价：堆分配、动态分发（小开销）

→ 10.2.5 impl vs dyn · demo get_iter / get_dyn

  • 惰性：map/filter 只记规则，collect/for 才跑
  • Iterator：只有 next + Item 是必须的
  • 适配器：返回新迭代器、不消费
  • 消费器：拿走迭代器、算出结果
  • 三迭代方法：iter = &、iter_mut = &mut、into_iter = 拿走
  • 返回迭代器：单一用 impl，异构用 Box<dyn>

一、迭代器基础定义

迭代器 = 对序列遍历逻辑的封装，自动维护游标与边界终止，不用手写 i、不用 i < len。

惰性 Lazy（第一核心特征）

只写链式逻辑（map/filter）= 只保存规则，不运算；只有消费（next/for/collect/sum）才真正逐个执行。

let arr = [1, 2, 3];
let iter = arr.iter().map(|&x| x * 2).filter(|&v| v > 2);
println!("走到这里，map、filter 完全没执行");
let res: Vec<i32> = iter.collect();
// res = [4, 6]

二、Iterator trait 拆解

pub trait Iterator {
    type Item; // 关联类型 → [10.2.4 type Item](../10-generics-traits-lifetimes/10.2.4-type关键字与关联类型.md)

① type Item

一个迭代器从头到尾只产出同一种 Item。

生成方式 Item
arr.iter() &i32（不可变借用）
arr.into_iter() i32（所有权）

② fn next(&mut self) -> Option<Self::Item>

  1. &mut self：修改内部游标 → 迭代器变量必须 mut
  2. 返回规则：
返回值 含义
Some(val) 取出元素，游标 +1

assert_eq!(iter.next(), None);

三、适配器（惰性）+ 消费器（触发执行）

1. 适配器 Iterator Adaptors

惰性、返回新迭代器、不消耗原迭代器 — 只包装规则。

Filter 伪实现原理：

struct Filter<I, P> { inner: I, pred: P }

impl<I: Iterator, P> Iterator for Filter<I, P> {
    type Item = I::Item;
    fn next(&mut self) -> Option<Self::Item> {
        loop {
            match self.inner.next() {
                Some(v) if (self.pred)(&v) => return Some(v),
                Some(_) => continue,
                None => return None,
            }
        }
    }
}

let chain = vec![1, 2, 3, 4, 5].iter()
    .map(|&x| x + 1)
    .filter(|x| *x % 2 == 0);
// 此时仍无运算

2. 消费器 Consuming Adaptors

消耗迭代器、触发 next、用完作废：

let s: i32 = chain.sum();
// chain 已消费，不能再次 collect
消费器 说明
collect / sum / count / fold 显式消费
for x in iter 编译器自动循环 next() 直到 None

六、自定义迭代器：CounterRange

struct CounterRange { curr: usize, max: usize }

impl Iterator for CounterRange {
    type Item = usize;
    fn next(&mut self) -> Option<Self::Item> {
        if self.curr < self.max {
            let res = self.curr;
            self.curr += 1;
            Some(res)
        } else {
            None
        }
    }
}

// CounterRange { curr: 0, max: 3 } → 0, 1, 2, None
// CounterRange { curr: 1, max: 5 }.map(|x| x * 2).sum() → 20

.2 适配器与消费器详解（比喻 · 定义 · 对照）

← 13.2.1 迭代器精讲 · 13.2 hub · 下一条 13.2.3 调用链路 · demo：cargo run -- lazy

一、通俗比喻

把原始集合（Vec/数组） 比作原材料仓库，迭代器就是一条加工流水线：

角色 比喻 Rust 里
适配器 流水线上的加工工位（打磨、筛选、裁切） map / filter / skip / take …
消费器 启动开关 + 成品收纳箱 collect / sum / for / count …
  • 适配器：只加装加工规则，流水线搭完，不开机、不处理原料
  • 消费器：按下开关，原料逐个加工，产出成品；流水线走完就空了

二、迭代器适配器（Adapter）

定义

对现有迭代器再包装、追加处理逻辑，返回一个新迭代器。

核心特征

  1. 惰性执行：只记录「要做什么」，不会立刻遍历、计算元素
  2. 链式包装：每加一个适配器 = 多包一层规则（底层仍是「等 next 才动」）
  3. 支持链式调用：map → filter → skip … 组成复杂流程
  4. 本质：修改产出元素的规则，不触发遍历

常见适配器

方法 作用
map(f) 对每个元素做转换
filter(f) 按条件过滤
skip(n) 跳过前 n 个
take(n) 只取前 n 个
zip(it2) 与另一迭代器两两配对
enumerate() 产出 (索引, 元素)

代码印证（只搭流水线，不运行）

let v = vec![1, 2, 3, 4, 5];
let pipeline = v.iter()
    .map(|x| x * 2)
    .filter(|&x| x > 5);
// 👉 仅搭建规则，map/filter 内部逻辑一次都没跑

println!("流水线搭建完成，还没有开始加工！");

→ demo：cargo run -- lazy 里 §2 之前会先打印「规则组装完成，未执行」

三、迭代器消费器（Consumer）

定义

启动迭代器、触发遍历，逐个调用 next()，执行所有适配器规则，最终产出结果。

核心特征

  1. 触发执行：让前面所有适配器的逻辑真正运行
  2. 消耗迭代器：游标走到末尾，彻底失效（不能指望再产出元素）
  3. 负责收尾：把元素转成集合、数字、打印等最终结果

常见消费器

方法 / 写法 作用
collect() 收集到 Vec / HashSet 等（最常用）
sum() 数值求和
count() 统计剩余元素个数
fold(init, f) 自定义累加 / 聚合
for x in iter 逐个遍历（语法糖，底层反复 next()）
while let Some(x) = iter.next() 手动逐个 next()，最底层、最灵活的消费

代码印证（按下开关，流水线开工）

let pipeline = v.iter()
    .map(|x| {
        println!("执行 map：{} * 2", x);
        x * 2
    })
    .filter(|&x| {
        println!("执行 filter：判断 {} > 5", x);
        x > 5
    });

println!("流水线搭建完成，准备启动...");

let result: Vec<_> = pipeline.collect(); // 消费器：从这里才跑
println!("最终成品：{:?}", result);    // [6, 8, 10]

典型输出顺序：先「搭建完成」→ 再逐条 map/filter 日志 → 最后成品。

→ 完整分步输出：13.2.4 §二

四、while let Some(x) = iter.next()（手动消费）

一句话：手动、逐个地消费迭代器，直到 next() 返回 None 为止。它是 Rust 的模式匹配循环语法糖，专门用来遍历迭代器或处理 Option。

1. 先回忆：next()

所有迭代器都有核心方法：

fn next(&mut self) -> Option<Item>
  • 有元素 → Some(元素)
  • 没元素了 → None

→ trait 定义：13.2 hub §四

2. 本质 = loop + match + break

while let Some(x) = iter.next() {
    // 使用 x
}

完全等价于：

loop {
    match iter.next() {
        Some(x) => {
            // 使用 x
        }
        None => break,
    }
}

while let 把「无限循环 + 匹配 + 中断」收成一行。

3. 适配器 + while let（完整可运行）

fn main() {
    let v = vec![1, 2, 3, 4, 5];

    // 适配器：只搭流水线，不执行
    let mut iter = v.iter()
        .map(|x| x * 2)
        .filter(|&x| x > 5);

    // 消费器：每次 next() 驱动整条链前进一步
    while let Some(x) = iter.next() {
        println!("拿到元素：{}", x);
    }
}

输出：6、8、10（各一行）。

关系：

  • map / filter → 适配器，惰性，返回新迭代器
  • while let … next() → 消费器，每次调用 next() 才跑流水线
  • 与 for、collect()、sum() 同属消费器，只是更底层、更灵活

4. while let vs for（效果相同）

// A：手动
while let Some(x) = iter.next() {
    println!("{}", x);
}

// B：语法糖（自动 next + 遇 None 退出）
for x in iter {
    println!("{}", x);
}
  • for：更常用；for x in v 还涉及 IntoIterator → 13.2.5 §二
  • while let：可控制每次何时 next()，中途做别的事、提前 break

→ 三种消费器同链逐步对比：13.2.4 §五（cargo run -- lazy §5）

五、两大核心区别（对照表）

对比项 适配器 消费器
核心行为 追加规则，返回新迭代器 启动遍历，产出最终结果
执行时机 惰性，定义时不运行 调用时执行所有前置规则
迭代器状态 可继续链式拼接 被耗尽，不能再次产出
链中位置 中间，可无限拼接 最后一步，收尾

六、两个关键补充

1. 链式执行顺序

书写顺序 = 元素处理顺序：

v.iter().map(...).filter(...).collect()
// 原始元素 → map 转换 → filter 过滤 → collect 收集

2. 迭代器只能消费一次

消费后游标在末尾，再次 collect 得到空结果（变量若仍持有已耗尽的迭代器）：

let mut iter = v.iter().map(|x| x * 2);

let res1: Vec<_> = (&mut iter).collect();
println!("第一次: {:?}", res1); // [2, 4, 6]

let res2: Vec<_> = iter.collect();
println!("第二次: {:?}", res2); // [] — 已空

第一次若写 iter.collect() 会直接 move 走迭代器；演示「二次 collect」用 &mut iter → 13.2.4 §五

七、一句话总结

  1. 适配器：搭加工流水线，只定规则，不开工
  2. 消费器：启动流水线，加工原料，出成品（for / collect / while let … next()）
  3. 写代码：适配器中间串联，消费器最后收尾

→ Filter 底层怎么包一层规则：13.2.1 §三 Filter 伪实现

一、整体关系总览

角色 是什么 核心
迭代器 基础主体 next() 逐个产出元素
适配器 基于旧迭代器，包装出新迭代器 本身也是迭代器；惰性、只包装、不主动取值
消费器 作用在迭代器之上 反复调用 next()，汇总成 Vec/数字等；触发执行、耗尽链路

串起来：原始迭代器 → 适配器层层包装 → 消费器驱动整条链路

→ 流水线比喻：13.2.2 §一

二、分步拆解

1. 生成「原始迭代器」

iter() / iter_mut() / into_iter() 得到最基础迭代器 — 工作只有一件：被 next() 时从集合取元素。

let v = vec![1, 2, 3];
let base_iter = v.iter(); // 尚未遍历

此时：只有迭代器，无处理逻辑，未开始遍历。

2. 适配器包装（仍是迭代器）

let base_iter = v.iter();
let map_iter = base_iter.map(|x| x * 2);
// map_iter 是新迭代器：内部持有 base_iter + map 规则
// 全程惰性，不调用 next，不处理元素

链式 = 多层嵌套：

let final_iter = v.iter()
    .map(|x| x * 2)      // 第一层：Map<Iter, …>
    .filter(|&x| x > 3); // 第二层：Filter<Map<…>, …>

结构示意：

final_iter (Filter)
  └─ 内层 map_iter (Map)
       └─ base_iter (Iter) → 集合 v

本质：适配器返回值永远是「新迭代器」 — 能链式的根本原因。

3. 消费器驱动整条链路

调用 collect / sum / for 时：

  1. 消费器循环调用最外层迭代器的 next()
  2. 外层 next() 调用内层的 next() … 直到原始迭代器取元素
  3. 元素从内到外经过 map、filter 等规则
  4. 合格元素交给消费器汇总
  5. 原始迭代器返回 None → 结束；整条链路耗尽

三、完整代码 + 运行输出

let v = vec![1, 2, 3];

let iter = v.iter()
    .map(|x| {
        println!("【map】处理元素: {}", x);
        x * 2
    })
    .filter(|&x| {
        println!("【filter】判断元素: {}", x);
        x > 3
    });

println!("=== 所有适配器包装完毕，等待消费 ===");

let result: Vec<_> = iter.collect();
println!("最终结果: {:?}", result);

典型输出：

=== 所有适配器包装完毕，等待消费 ===
【map】处理元素: 1
【filter】判断元素: 2
【map】处理元素: 2
【filter】判断元素: 4
【map】处理元素: 3
【filter】判断元素: 6
最终结果: [4, 6]

单次 next() 链路（以第一个元素为例）

sequenceDiagram
    participant C as collect
    participant F as filter 迭代器
    participant M as map 迭代器
    participant B as iter 原始迭代器
    participant V as Vec

    F->>M: next()（循环直到 filter 通过）

文字版六步：

  1. collect 调最外层 next()
  2. filter → 调 map 的 next()
  3. map → 调原始 iter 的 next()，拿到 1
  4. 元素走 map → 2 → filter 判断 → 不通过，filter 继续要下一个
  5. 合格元素（4、6）交给 collect 写入 Vec
  6. 原始 next() 返回 None → 结束

四、核心关系总结

1. 身份关系

  • 适配器返回值 = 新迭代器 → 可无限链：iter().a().b().c()
  • 消费器作用对象 = 迭代器 → 写在链最后；返回 Vec/数字等，不再是迭代器

2. 行为关系

阶段 状态
停在适配器 惰性休眠 — 只存规则
调用消费器 唤醒整条链路 — 逐元素 next()

3. 生命周期

  • 适配器：逻辑嵌套，旧迭代器被新迭代器持有（包装，不「销毁」语义上的数据源）
  • 消费器：跑完后整条链路耗尽，不能再次产出 → 13.2.4 §五

五、结构图示

原始集合 (Vec)
    ↓

    ↓  ↑ next 回溯

    ↓  ↑

    ↓

    ↓

六、两个常见误区

误区 纠正

消费器会生成新迭代器？ 不会。返回普通数据，链式到此结束

七、一句话

迭代器是主体，适配器是「套娃式新迭代器」，消费器是「按 next 把套娃拆开并收尾」。

多个适配器连续调用 = 层层包装规则，依然惰性：

let iter = v.iter()
    .map(|x| {
        println!("map 处理: {}", x);
        x * 2
    })
    .filter(|&x| {
        println!("filter 判断: {}", x);
        x > 5
    });

println!("===== 规则组装完成，未执行 =====");
let res: Vec<_> = iter.collect();

典型输出（节选）：

===== 规则组装完成，未执行 =====
map 处理: 1
filter 判断: 2
map 处理: 2
filter 判断: 4
...
筛选结果: [6, 8, 10]

→ 消费时按流水线顺序逐个元素执行（filter 可能提前跳过，见 Filter 伪实现 13.2.1 §三）。

三、skip / take

适配器 作用
skip(n) 跳过前 n 个
take(n) 只取前 n 个 
let v = vec![10, 20, 30, 40];

let iter = v.iter().skip(2);
println!("组装完成，未执行");
let res: Vec<_> = iter.collect(); // [30, 40]

let iter = v.iter().take(2);
let res: Vec<_> = iter.collect(); // [10, 20]

四、不同消费器（都触发执行）

消费器 作用
collect() 收集到集合
sum() 求和
for x in iter 循环（反复 next()）
while let Some(x) = iter.next() 手动逐个 next()（最底层）
count() 计数

let iter = v.iter().map(|x| x * 2);
let total: i32 = iter.sum(); // 2+4+6 = 12

// for
for num in iter { println!("元素: {}", num); }

// count
let cnt = v.iter().filter(|&&x| x % 2 == 0).count(); // 偶数个数

五、三种消费器同链对比（while let / for / collect）

同一条 map + filter 流水线，分别用三种消费器收尾——观察谁触发执行、输出长什么样。

let v = vec![1, 2, 3, 4, 5];

// 闭包里 println!，看清每次 next() 驱动 pipeline 走一步
fn traced(v: &Vec<i32>) -> impl Iterator<Item = i32> + '_ {
    v.iter()
        .map(|x| { println!("  map: {}", x); x * 2 })
        .filter(|&x| { println!("  filter: {}", x); x > 5 })
}

// A) while let — 每轮循环显式 next()，中间可 println
let mut iter = traced(&v);
while let Some(x) = iter.next() {
    println!("  while let 拿到: {}", x);
}

// B) for — 语法糖，内部等价于反复 next()
for x in traced(&v) {
    println!("  for 拿到: {}", x);
}

// C) collect — 内部循环 next() 直到 None，只出最终 Vec
let res: Vec<_> = traced(&v).collect();
println!("  collect 成品: {:?}", res);

结论（背下来）：

消费器 本质 特点
while let … next() 手动驱动 最灵活，可控制每步时机
for x in iter while let 语法糖 写法最简，日常首选
collect() 内部 while 收齐全部 一次出集合，中间不插手

三种方式都会逐元素跑完适配器链；差别只在你怎么写循环、要不要中途插手。

→ 概念拆解：13.2.2 §四

六、消费后不能复用

迭代器被消费（collect/sum/for/while let）后耗尽，不能二次使用：

let mut iter = v.iter().map(|x| x * 2);

let res1: Vec<_> = (&mut iter).collect(); // 耗尽迭代器，但变量仍在
println!("第一次: {:?}", res1);

let res2: Vec<_> = iter.collect();
println!("第二次: {:?}", res2); // [] — 已空

七、极简总结

  1. 适配器（map/filter/skip/take）：只写逻辑、不运行 — 搭流水线
  2. 消费器（collect/sum/for/while let … next()/count）：按开关 — 启动流水线
  3. 核心规则：流水线搭好不动，按下开关（消费）才开工

表格 + 方法签名

方法 产出 Item 借用/所有权 调用后原 Vec 签名本质
.iter() &T 不可变借用 &self ✅ 完整可用 fn iter(&self) -> Iter<'_, T>
.iter_mut() &mut T 可变借用 &mut self（独占） 迭代器存活期间被锁住；销毁后恢复 fn iter_mut(&mut self) -> IterMut<'_, T>
.into_iter() T move self，消费容器 ❌ 所有权移走，变量失效 fn into_iter(self) -> IntoIter<T>（IntoIterator）

一、逐段实例 + 踩坑

let mut v = vec![10, 20, 30];

// 1. iter：不可变借用
{
    let val: Vec<&i32> = v.iter().collect();
    dbg!(val); // [&10, &20, &30]
} // val 释放后，才能对 v 再 mut 借用
println!("{:?}", &v); // ✅

// 2. iter_mut：独占可变借用
{
    let mut refs: Vec<&mut i32> = v.iter_mut().collect();
    for x in refs {
        *x *= 2;
    }
} // 迭代器/引用 vec 销毁后 v 恢复
dbg!(&v); // [20, 40, 60]

// 3. into_iter：move
let owned: Vec<i32> = v.into_iter().collect();
dbg!(owned);
// println!("{:?}", &v); // ❌ E0382：v 已 move

底层原因

方法 本质
iter(&self) 栈上 Vec 仍在，只借元素地址
iter_mut(&mut self) 可变独占 — 同一时刻不能另有 &v / 第二个 iter_mut
into_iter(self) 传值 move — 控制权交给 IntoIter，原变量作废

踩坑：v.iter().collect::<Vec<&i32>>() 得到的引用存活期间，不能再 v.iter_mut() — 须用 {} 缩小 val 作用域。

二、for x in v ⇔ into_iter()（IntoIterator）

for A in B 语法糖 ≈：

let mut iter = B.into_iter();
while let Some(x) = iter.next() { /* 使用 x */ }

标准库三套 IntoIterator（决定 for 行为）

写法 实现 Item 等价
for x in v IntoIterator for Vec<T> T v.into_iter() — move，v 报废
for x in &v IntoIterator for &Vec<T> &T v.iter() — 只读
for x in &mut v IntoIterator for &mut Vec<T> &mut T v.iter_mut() — 原地改

for _ in v {}           // v move

三、与 zip / collect 的所有权

collect 按目标类型决定收的是引用还是值：

let v = vec![1, 2, 3];

// a、b 仍可用

四、高频易错总结

  1. 只读、保留原数组 → .iter() / for x in &v
  2. 原地改元素、保留原数组 → .iter_mut() / for x in &mut v
  3. 要元素所有权、不再用原数组 → .into_iter() / for x in v
  4. 既要遍历又要保留原 Vec 的所有权 → for x in &v，或 v.clone().into_iter() 克隆再消耗

五、自测（3 道改错题）

  1. rust let mut v = vec![1, 2, 3]; let r: Vec<&i32> = v.iter().collect(); for x in v.iter_mut() { *x += 1; }
  2. rust let v = vec![1, 2]; for x in v { println!("{x}"); } v.push(3);
  3. rust let v = vec![1, 2, 3]; let a: Vec<i32> = v.iter().collect();
参考答案

1. 三个结构体是什么

// v.iter() 返回
pub struct Iter<'a, T>;

// v.into_iter() 返回
pub struct IntoIter<T>;
类型 含义
Iter<'_, T> 匿名生命周期 '_ = 借用 Vec 的时长；内部指针指向堆数组，只借不拥有
IterMut<'_, T> 可变借用指针，独占
IntoIter<T> 接管堆数组所有权，原 Vec 作废
调用 返回类型 Item
v.iter() Iter<'_, T> &T
v.iter_mut() IterMut<'_, T> &mut T
v.into_iter() IntoIter<T> T

方法签名：

fn iter(&self) -> Iter<'_, T>;
fn iter_mut(&mut self) -> IterMut<'_, T>;
fn into_iter(self) -> IntoIter<T>; // IntoIterator trait

2. 编译报错：iter + iter_mut 同时存活

let mut v = vec![10, 20, 30];
let _it1 = v.iter();     // 不可变借用 &v
let _it2 = v.iter_mut(); // ❌ 已有不可变借用，不能再可变借用
let _it3 = v.into_iter();

Rust 借用规则：同一数据上，不可变引用与可变引用不能重叠（_it1 存活期间锁住了 v）。

修正：作用域分开，迭代器销毁 = 借用释放

let mut v = vec![10, 20, 30];
{ let _it1 = v.iter(); }      // 结束 → 释放不可变借用
{ let _it2 = v.iter_mut(); }   // OK
let _it3 = v.into_iter();     // move v
// 此后不能访问 v

3. for in 与 IntoIterator（三句话）

let v = vec![1, 2, 3];

// 1. for x in v → into_iter，move，v 失效
for _ in v {}
// println!("{v:?}"); // ❌

// 2. for x in &v → 等价 iter，只读，v 保留

// 3. for x in &mut v → 等价 iter_mut，原地改

for x in &mut v3 { *x += 1; }

for B in A ≈ A.into_iter() 再循环 next()。
标准库为 Vec<T> / &Vec<T> / &mut Vec<T> 各实现一套 IntoIterator，故三种 for 效果不同。

5. '_ 匿名生命周期

Iter<'_, T> = Iter<'a, T> 简写，'_ 由编译器推导：

  • 迭代器不能活得比被借用的 Vec 更久
  • Vec 销毁 → 基于它的 Iter / IterMut 立刻失效

{
    let v = vec![1, 2];
    let it = v.iter();

}

（正确做法：在 v 存活期间用完迭代器，或 collect 成 owned 数据。）

6. 实战：什么时候用 Iter vs IntoIter

场景 选用 原因
只读扫描、统计、打印 iter() / for x in &v 保留 Vec，可多次遍历
原地改元素 iter_mut() / for x in &mut v 不分配新 Vec
过滤/transform 成新集合且不再需要原 Vec into_iter() 避免 clone；元素 move 进新容器

还要用原 Vec 做别的事 iter() 或 v.clone().into_iter() 克隆再消耗
与另一集合 zip 只读配对 双方 iter() 两个源都保留

}

13.4

性能对比：循环 VS 迭代器

对应 demo 项目：00-Book/13-iterators-closures/13.4-iterators-performance-demo/

本节关心一个现实问题：写 for 循环更快，还是写迭代器链更快？

结论（从 Rust 的设计目标与实际基准结果看）：迭代器通常不会比手写循环慢，很多情况下还可能一样快甚至略快。原因是 Rust 的迭代器属于 零成本抽象（zero-cost abstractions）：抽象层在编译期会被优化掉，不引入额外运行时开销。

为什么迭代器不慢：零成本抽象

迭代器看起来“高级”，但编译器会把它们优化成与手写循环非常接近的底层代码： - 迭代器适配器（map/filter/zip/skip）是惰性的，本质上描述“做什么”，而不是“怎么写循环控制” - LLVM 会进行内联、消除边界检查、常量传播等优化 - 在某些固定长度循环里，编译器甚至可能 展开（unroll）循环，移除循环控制开销

这和 C++ 领域常说的 zero-overhead 原则一致：不用的就不付费；用到的也很难手写得更好。

基准测试结果怎么解读

书中举了一个例子：在大文本里搜索单词 "the"，for 循环与迭代器版的 search 性能非常接近，迭代器版甚至略快。

你不需要把结果理解成“迭代器永远更快”，更关键的是： - 两者通常等价或非常接近 - 选择迭代器风格往往能获得更清晰的表达，同时不牺牲性能

现实例子：迭代器链表达数学计算（音频解码器风格）

在一些对性能敏感的场景，也常用迭代器链表达“配对、映射、求和”等模式，例如： - coefficients.iter().zip(window).map(...).sum()

这类写法通常同样能被编译器优化成高效的机器码。
