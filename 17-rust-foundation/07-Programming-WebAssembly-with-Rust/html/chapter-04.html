4.1

Creating a Better Hello, World

第 4 章索引：README · 后：4.2-rogue-wasm-game

一句话

引入 wasm-bindgen：用 #[wasm_bindgen] 自动生成 JS 包装器，字符串与复杂类型可跨边界传递，再配合 npm + webpack 走现代前端脚手架——告别 Ch3 手写 extern "C" 与纯 i32。

原书要点

为何需要 wasm-bindgen

Ch3 痛点 bindgen 解决
手写 #[no_mangle] + extern "C" 宏 + CLI 自动生成 JS glue
只能传 数字 String、结构体、方法可映射到 JS
手动 linear memory 分配/指针 模板代码处理 分配、释放、指针
JS env import 易错 生成类型安全的 wrapper

wasm-bindgen 组成

部分 作用
#[wasm_bindgen] 宏 标记 export/import 函数、impl、类型
wasm-bindgen CLI 读 rustc 元数据，产出 .js + 辅助 wasm
wasm-pack（常用） 封装 build + 发布到 npm 本地包

典型 Hello（概念）：

use wasm_bindgen::prelude::*;

#[wasm_bindgen]
pub fn greet(name: &str) -> String {
    format!("Hello, {}!", name)
}

→ JS 侧可直接 greet("Wasm")，无需自己写 UTF-8 进 linear memory。

突破数据类型限制

方向 bindgen 行为
&str / String 自动 copy 进/出 Wasm 线性内存
结构体 + 方法 生成 JS class 包装（见 4.2）
复杂类型 仍受 Wasm 类型系统约束；更复杂场景用 4.3 · serde

现代前端工程化

工具 用途
Node.js + npm 依赖与脚本
webpack 打包 JS + 加载 Wasm
package.json npm run start 开发服务器

典型流程：

wasm-pack build --target web    # 或 bundler / nodejs
# webpack 引入 pkg/rogue_wasm.js

↔ Layer 2 订单簿页同样用 wasm-pack + 最小 HTML → layer02

WAT / 工具 / 代码锚点

项 说明
依赖 Cargo.toml: wasm-bindgen = "0.2"
对比 3.5 · 手写 FFI vs 本章生成 glue
检视 wasm-objdump -i — import/export 仍可读，但 JS 侧不再手写

4.2

Building the Rogue WebAssembly Game

第 4 章索引：README · 前：4.1-better-hello-world · 后：4.3-experimenting-further

一句话

用 Rot.js（JS）做迷宫/A 与键盘输入，Rust Wasm 做引擎/玩家/战斗 — 通过 wasm_bindgen 双向绑定：Rust import ROT.Display.draw，export* PlayerCore / Engine 给 JS 实例化。

原书要点

真实项目中的职责分离

层 语言 负责
表现 + 算法库 JavaScript 键盘事件 · Rot.js 随机迷宫 · A* 寻路等
核心模拟 Rust (Wasm) 引擎状态 · 玩家 · 战斗 · 胜负逻辑

原则：每种语言做它最擅长的事 — 与 Layer 2「JS fetch 订单簿、Wasm 解析」同构 → layer02

Rot.js 整合

点 说明
Rot.js 开源 JS Roguelike / 终端 库（Display、Map 等）
Rust import JS 类 #[wasm_bindgen(module = "...")] 绑定 ROT.Display
调用 Rust 内直接 .draw(x, y, char, fg, bg) 等 — bindgen 生成跨边界调用

概念（方向示意）：

#[wasm_bindgen]
extern "C" {
    #[wasm_bindgen(js_class = ROT.Display, js_namespace = ROT)]
    type Display;
    #[wasm_bindgen(method, js_name = draw)]
    fn draw(this: &Display, x: i32, y: i32, /* ... */);
}

（实际以书中 / wasm-bindgen 导出的 JS 类型为准。）

Rust 结构体暴露给 JavaScript

Rust 类型 JS 侧
PlayerCore new PlayerCore() · 方法调用
Engine 游戏主循环、状态机

#[wasm_bindgen] 在 struct / impl 上 → 生成 JS class，替代 Ch3 纯 i32 export。

趣味设定（原书）

元素 含义
宝藏 一个 WebAssembly 模块
终极 BOSS「Checko」 Borrow Checker（借用检查器） — Rust 开发者梗

WAT / 工具 / 代码锚点

项 说明
npm 依赖 rot-js（或书中版本）
webpack 同时 bundle Rot.js 与 pkg/*.wasm
对照 Ch2 Checkers UI 在 JS · 逻辑在 Wasm — Rogue 分工更细

4.3

Experimenting Further

第 4 章索引：README · 前：4.2-rogue-wasm-game · 后：4.4-wrap-up

一句话

在 Rogue 基础上继续实验：serde JSON 把 Rust 状态序列化给 JS；js_sys 绑定原生 JS 全局 API；web_sys 绑定浏览器 DOM/Web API — 无需再手写 extern 块。

原书要点

引入 serde 进行 JSON 序列化

场景 做法
向 JS 发送复杂更新 玩家 HP、步数、背包等结构体
serde + serde_json Rust struct → JSON 字符串 → JS JSON.parse
与 bindgen 关系 简单字段用 bindgen 直接暴露；批量状态快照用 JSON 更省事

概念：

use serde::Serialize;
use wasm_bindgen::prelude::*;

#[derive(Serialize)]
pub struct Stats { pub hp: u32, pub steps: u32 }

#[wasm_bindgen]
pub fn stats_json(stats: &Stats) -> String {
    serde_json::to_string(stats).unwrap()
}

Layer 2 订单簿：Go API 返回 JSON → Wasm 内 serde 反序列化 → 固定档位 struct → layer02

js_sys — 原生 JavaScript 全局对象

能力 示例
已生成的 JS 内置绑定 不必手写 extern "C"
常用 js_sys::console::log_1(&val) · js_sys::eval(...) · Array / Object 
use wasm_bindgen::JsValue;
js_sys::console::log_1(&JsValue::from_str("from Rust Wasm"));

↔ 替代 Ch3 3.5 里为 console.log 写 import 签名。

web_sys — 浏览器 Web API

能力 示例
DOM / Web API 绑定 web_sys::window() · document() · HtmlElement
粒度 crate feature 按需开启（减小 wasm 体积）

→ Rust 在 Wasm 内可直接操作 DOM（仍受同源/安全策略约束），与 1.1「DOM 须宿主代劳」 的 1.0 叙述相比，bindgen 生态已大幅简化路径。
