8.2

Designing the WARoS API

第 8 章索引：README · 前：8.1-homage-crobots · 后：8.3-match-engine

一句话

WARoS API = 把 Crobots 内置函数（scan / cannon / drive / damage / 三角函数 等）变成机器人 Wasm 的 extern "C" import — 宿主实现、模块调用，形成标准 FFI 契约。

原书要点

机器人模块 ↔ 宿主：FFI 契约

方向 内容
Wasm import 机器人调用宿主提供的 API（感知战场、开火、移动）
Wasm export 机器人入口（如每帧 robot() / main — 以书为准）
ABI extern "C" · 参数多为 f64 / i32 等 Wasm 原生类型

典型 import（概念，名称以原书为准）

API 用途
scan 雷达扫描 · 角度 → 距离
cannon 指定角度与射程开火
drive 速度 + 方向 · 驱动马达
damage 查询自身受损
三角函数 sin / cos / … — 瞄准与几何 
// 机器人 Wasm 侧（概念）
#[link(wasm_import_module = "env")]
extern "C" {
    fn scan(angle: f64) -> f64;
    fn cannon(angle: f64, range: f64) -> i32;
    fn drive(speed: f64, direction: f64);
    fn damage() -> i32;
}

章节 FFI 方式

Ch3 extern "C" + wasmi/JS
Ch4 wasm-bindgen
Ch8 WARoS 大规模标准化 import 表 — 多模块共享同一 API

8.3

Building the WARoS Match Engine

第 8 章索引：README · 前：8.2-waros-api · 后：8.4-wasm-robots

一句话

比赛引擎 = Game Loop 给每个 Wasm 机器人分配时间片；初版「每 Wasm 一线程 + 全局状态数组」触发 RwLock 死锁与 Borrow Checker 地狱 → 用 ECS 拆状态、限写锁，实现安全高并发。

原书要点

Game Loop 与并发痛点

初版方案 问题
每个 Wasm 机器人一个线程 多线程同时读写 共享机器人状态数组
RwLock 全局状态 读写冲突 · 卡死 · 借用检查器 compile/runtime 痛苦

→ 对照 05-atomic · 锁与并发

ECS（Entity-Component-System）架构

概念 WARoS 中的含义
Entity 实体 一个 Wasm 机器人实例 的唯一 ID
Component 组件 极细状态碎片：运动 · 伤害 · 扫描 · …
System 系统 只修改特定组件的逻辑；唯一持写锁的入口 
Entity (robot #2)
  ├─ MotionComponent      ← DriveSystem 独占写
  ├─ DamageComponent      ← CombatSystem 独占写
  └─ ScanComponent        ← RadarSystem 独占写

规则：没有「全局 RobotState 大锁」— 只有系统级细粒度锁
ECS 收益 说明
并发安全 系统之间减少锁竞争
Borrow Checker 友好 拆分后 Rust 可证明互斥访问
可扩展 新行为 = 新 Component + System

引擎 Runtime（wasmi）

职责 说明
加载 多个 .wasm 机器人 → 各自 ModuleInstance
Satisfy imports 实现 8.2 WARoS API · 读/写 ECS 组件
Execute 每帧调用机器人 export · trap 隔离单机器人

↔ 6.2 wasmi · 6.1 五职责

8.4

Creating WebAssembly Robots

第 8 章索引：README · 前：8.3-match-engine · 后：8.5-robots-cloud

一句话

编写 dumbotrs（标靶）与 Rook（巡逻战车）两个 Wasm 机器人，用 consolerunner 在终端跑 10 万帧 对战，经 channel 录事件 并支持 控帧回放 — 验证引擎与 wasmi 多实例加载。

原书要点

机器人一：dumbotrs（标靶）

行为 目的
10% 速度向北 drive 简单运动
循环 damage 等状态查询 压测宿主 并发读
撞墙后不动 测试边界与停止条件

→ 引擎 读多写少、锁粒度是否足够的压力测试。

机器人二：Rook（战车）

行为 说明
移动到 战场中心 几何 + drive
东西向巡逻 固定模式
scan 四周 发现敌人
cannon 直到消灭 完整 感知→决策→开火 闭环

→ 调用全套 8.2 WARoS API。

编译与加载

robot logic (Rust) → wasm32-unknown-unknown → dumbotrs.wasm / rook.wasm
  → wasmi 加载 N 个实例 → 同一 import 表指向引擎 ECS

consolerunner 与回放

组件 作用
consolerunner CLI · 将多个 .wasm 投入竞技场
100,000 帧 长对战 · 压测性能
Channels 录事件 导弹 · 碰撞 · 死亡等 → 可序列化
控帧回放 调节 FPS 重放赛况（类似 demo 播放器）

↔ 7.4 · mpsc 与 FPS · Layer 3 回测 tick 回放

与 Layer 3

WARoS Layer 3
dumbotrs 固定策略 smoke test
Rook 简单 MA 交叉 策略原型
consolerunner 100k 帧 CSV 回测 + 权益曲线
事件 channel 成交/信号日志

→ layer03/demo/fixtures/sample_ticks.csv

Robots in the Cloud

第 8 章索引：README · 前：8.4-wasm-robots · 后：8.6-wrap-up

一句话

WARoS 可上 云端：开发者上传 任意语言编译的 .wasm 机器人，后台 Serverless/FaaS 跑匹配引擎，经 Kafka / WebSocket 把战况推到网页 — 与 附录 A1 · Serverless 呼应。

原书要点

云端架构愿景

开发者上传 robot.wasm (Rust/C/Go/… 编译)
        ↓
云端 WARoS Match Engine（多租户 · 沙箱）
        ↓
Kafka / WebSocket 事件流
        ↓
Web 观众页（Yew / JS · 实时回放）
组件 说明
上传门户 网站接收 .wasm · 校验签名 A2
后台引擎 同 8.3 ECS + wasmi · 水平扩展
Serverless / FaaS 单场对战 = 一次函数/容器 invocation
Kafka 持久化事件流 · 多订阅者
WebSocket 前端 实时 观战

与 Ch5 Yew 的衔接

能力 组合
Yew 聊天/SPA 换成 观战仪表盘
ChatEngine 推送 WebSocket 战报

实时推送 监控面板 · 非实盘下单
