1.1

Introducing WebAssembly

第 1 章索引：README · 后：1.2-wasm-architecture

一句话

Wasm 是面向栈式虚拟机的便携式二进制指令格式——高级语言的编译目标，不是转译目标、不是 JS 替代品、也不是独立编程语言；必须依附宿主沙盒，I/O 全听宿主指挥。

原书要点

它是什么

点 说明
本质 基于栈式虚拟机的便携式二进制指令格式
编译目标 C++、Rust、Go 等高级语言可编译到此格式
可移植 同一模块可在不同 OS / CPU 架构上运行，无需改源码
不限于 Web 名字带 Web，但只要有宿主 (Host)，控制台、嵌入式、云端都能跑

常见误解（它「不是」什么）

误解 纠正
= JS 的转译目标 转译是高级语言→高级语言（如 TS→JS）；Wasm 是高级语言→低级指令（类似机器码层级）
会取代 JavaScript Wasm 1.0 在浏览器里仍依赖 JS 作宿主配合加载与胶水代码
= 一门独立编程语言 像没有主机的游戏卡带——必须进宿主沙盒；模块自身不能随意 I/O
= 只在浏览器里跑 浏览器只是最常见宿主之一；Part III 第 6 章 起会讲非 Web 宿主

宿主与模块边界

┌────────────── 宿主 (Host) ──────────────┐
│  JS / Rust / 控制台 … 提供 I/O、内存视图   │
│       ▲ import / export                   │
│  ┌────┴──── Wasm 模块 (.wasm) ────┐      │
│  │  纯计算 · 线性内存 · 无直接 DOM  │      │
│  └────────────────────────────────┘      │
└──────────────────────────────────────────┘
  • 模块不能直接访问宿主内存或 DOM；「操作 DOM」= 通过导入函数或共享线性内存 + 宿主代劳（见 1.2）。

项 说明

1.2

Understanding WebAssembly Architecture

第 1 章索引：README · 前：1.1-introducing-wasm · 后：1.3-building-wasm-app

一句话

Wasm 用栈式机器 + 四种数值类型 + 结构化控制流 + 线性内存 换便携与安全——没有堆、没有 GC、没有原生字符串；有符号/无符号只在具体操作时区分。

原书要点

基于栈的机器 (Stack Machine)

与日常 基于寄存器 (Register) 的 CPU 不同，Wasm 用 LIFO 栈 做运算：

i32.const 1    ;; 压栈 → [1]
i32.const 2    ;; 压栈 → [1, 2]
i32.add        ;; 弹出两数，结果压栈 → [3]
优势 说明
二进制小 指令编码紧凑
易移植 虚拟机实现简单，不绑定具体寄存器文件
与 LLVM 栈式 IR 有亲缘 对照 06 Learn LLVM 17 里 SSA/栈混合直觉

↔ Crafting Interpreters · VM

极其有限的数据类型 (Wasm 1.0 MVP)

只有四种：

类型 含义
i32 32 位整数
i64 64 位整数
f32 32 位浮点
f64 64 位浮点
  • 没有原生字符串、结构体、指针类型（指针在源码层是 i32 偏移）。
  • 有符号 / 无符号不是类型属性，而是 i32.add vs i32.add_s 等指令在操作时才区分。

HFT / Rust 对照：Rust 编译到 Wasm 时，String、Vec 都在线性内存 + 运行时辅助里实现；热路径若要保持可预测，需像 2.2 位布局 那样自己管布局。

安全的控制流

Wasm 没有汇编式「盲跳 (blind jump)」到任意地址；控制流结构化：

指令 用途
block / loop 带标签的块与循环
if / else 条件分支
br / br_if 跳转到已知块标签

→ 验证器可证明控制流合法，利于沙箱安全（与 附录 A2 衔接）。

线性内存 (Linear Memory)

特性 说明
模型 一块可按 64KB 页 (page) 增长的连续字节
没有 传统 heap、new、垃圾回收 (GC)（1.0 MVP）
安全边界 宿主可读写这块内存；模块不能访问宿主内存
「直接 DOM」 错觉——实际是共享线性内存 + 宿主 (JS) 代为操作 DOM 
Wasm 模块                    宿主
┌─────────────────┐         ┌──────────────┐
│ linear memory   │ ◄──────►│ JS / Rust    │
│ (i32 偏移寻址)   │  import │ 读写字节视图  │
└─────────────────┘         └──────────────┘

↔ Rust 侧：Nomicon · 布局 · RFR Ch2 类型布局

WAT / 工具 / 代码锚点

项 说明
最小加法 WAT 见 1.3 手写示例
memory 段 (memory 1) 声明至少 1 页；(data (i32.const 0) "hi") 初始化

示例片段（概念）：

(module
  (func $add (param i32 i32) (result i32)
    local.get 0
    local.get 1
    i32.add)
  (export "add" (func $add)))

1.3

Building a WebAssembly Application

第 1 章索引：README · 前：1.2-wasm-architecture · 后：1.4-wrap-up

一句话

用 wabt 工具链手写 WAT (S-表达式) → wat2wasm 得到 .wasm → wasm2wat / wasm-objdump 做往返编译与检视——理解底层，后续 Rust 编译到 Wasm 才不当黑盒。

原书要点

WebAssembly 二进制工具包 (wabt)

常用命令：

工具 作用
wat2wasm .wat 文本 → .wasm 二进制
wasm2wat .wasm → .wat（反汇编为可读文本）
wasm-objdump 检查模块段、导入/导出、代码结构
wasm-interp 解释执行（调试小模块）

安装（示例）：

# Windows: choco install wabt  /  scoop install wabt
# 或从 https://github.com/WebAssembly/wabt/releases 下载
wat2wasm --version

WebAssembly 文本格式 (WAT)

  • 文件扩展名 .wat
  • 语法：S-表达式 (S-expressions)，Lisp 式树状结构
  • 现代流程里编译器自动生成 WAT/wasm，但手写一遍能看清 1.2 里的栈操作与 export

最小流程：

# 1. 编辑 add.wat
# 2. 编译
wat2wasm add.wat -o add.wasm
# 3. 反汇编验证
wasm2wat add.wasm -o add.roundtrip.wat
# 4. 结构 dump
wasm-objdump -x add.wasm

往返编译 (Round-trip compilation)

add.wat  ──wat2wasm──►  add.wasm  ──wasm2wat──►  add.roundtrip.wat
启示 说明
便携性 二进制可在不同平台间传递、反解为等价 WAT
无秘密 任何人都能 wasm2wat 反汇编你的模块 → 商业逻辑不能靠「二进制 obscurity」
设计后果 敏感算法需配合 附录 A2 · 签名/加密；策略逻辑假设可被逆向

Rust 源码 → wat（经 wasm 反解）  与  Rust 源码 → .ll（llvm_insight_lab）
