3.1

Introducing Rust

第 3 章索引：README · 后：3.2-installing-rust

一句话

前两章手写 wast 之后，本章引入 Rust：用强类型、内存安全与表达力写 Wasm——Safety · Expressivity · Performance 三件套，特别适合做 Wasm 模块的源语言。

原书要点

本章转折点

之前（Ch1～2） 之后（Ch3+）
纯 WAT/wast · 手动 offset / 位运算 Rust + Cargo · struct/enum/迭代器
~853B 跳棋模块 更大体积，但开发效率与可维护性大幅提升
直接理解 VM 清楚编译器在背后做了什么（与 Ch2 对比）

Rust 为何适合 WebAssembly

特性 说明 Wasm 侧收益
Safety 安全性 无 null；所有权防数据竞争；无 GC 泄漏典型模式 模块边界更可控；FFI 处仍须 unsafe（见 3.5）
Expressivity 表现力 模式匹配、解构、迭代器、代数类型 跳棋 legal_moves 等规则可读（见 3.4）
Performance 性能 零 GC 运行时；可接近 C 级性能 适合计算密集 Wasm；体积仍大于手写 wast（含 panic/allocator 等）

与仓库 Rust 主线

已学 本章用法

Nomicon Ch3.5 的 extern "C" / unsafe
RFR Ch11 FFI import/export 宿主函数

Installing Rust

第 3 章索引：README · 前：3.1-introducing-rust · 后：3.3-hello-wasm-rust

一句话

用 rustup target add wasm32-unknown-unknown 为工具链添加 Wasm 编译目标，即可在本地把 Rust 直接编译成跨平台 .wasm 模块。

原书要点

安装 WebAssembly 编译目标

rustup target add wasm32-unknown-unknown
rustup target list --installed   # 确认含 wasm32-unknown-unknown
项 说明
triple wasm32-unknown-unknown — 32 位 Wasm，无特定 OS（unknown-unknown）
与 host 区别 默认 x86_64-pc-windows-msvc 等编译本机 exe；此 target 产出 .wasm
std 仍链接 Rust 标准库（除非 #![no_std]）→ 体积大于 Ch2 手写模块

常用编译命令（预览）

cargo build --target wasm32-unknown-unknown --release
# 产物通常在 target/wasm32-unknown-unknown/release/*.wasm

与 Layer 1 对齐

Layer 1 在同一 target 上并排：

cargo rustc --target wasm32-unknown-unknown -- --emit=llvm-ir   # 可选：对照 06 IR

3.3

Building Hello WebAssembly in Rust

第 3 章索引：README · 前：3.2-installing-rust · 后：3.4-rusty-checkers

一句话

Cargo 库 + cdylib，写 add_one 并 #[no_mangle] 导出 → cargo build --target wasm32-unknown-unknown → 用 wasm-objdump 检视线性内存与 export。

原书要点

使用 Cargo 创建库项目

cargo new hello_wasm --lib

Cargo.toml 关键配置：

[lib]
crate-type = ["cdylib"]
crate-type 作用
cdylib 生成 C 风格动态库 → Wasm 工具链产出 .wasm 模块（含 export）
默认 rlib 仅 Rust 静态链接，不适合直接给 JS 加载

编写与导出函数

#[no_mangle]
pub extern "C" fn add_one(x: i32) -> i32 {
    x + 1
}
属性 / 关键字 原因
#[no_mangle] 防止 rustc 改名（如 _ZN...），宿主按 add_one 查找 export
pub extern "C" C ABI，参数/返回值映射为 Wasm i32 等简单类型
i32 参数 与 1.2 · 四种 Wasm 类型 一致

编译与验证

cargo build --target wasm32-unknown-unknown --release
wasm-objdump -x target/wasm32-unknown-unknown/release/hello_wasm.wasm

检查项：

段 / 项 期望
Export add_one
Memory 通常有线性内存（即使用 std 也可能分配）
Code 大小 远大于 Ch2 853B — 含 runtime 片段

↔ 1.3 · wasm-objdump

3.4

Creating Rusty Checkers

第 3 章索引：README · 前：3.3-hello-wasm-rust · 后：3.5-rusty-checkers-ffi

一句话

用 struct / enum / 迭代器 / 模式匹配 重写 Ch2 跳棋逻辑，并把领域代码与 Wasm 边界分离——引擎可脱离 Wasm 单测，Wasm 层只做薄封装。

原书要点

与第 2 章对比

Ch2 · wast Ch3 · Rust
offset = (x+y*8)*4 手动计算 Coordinate { x, y }
位标志 0/1/2/4 GamePiece / PieceColor enum
手写 $move 验证 legal_moves 迭代器 + match
~853B 更大 .wasm（std + 抽象成本）

利用高级数据结构

书中典型类型（名称随源码略有出入）：

类型 用途
PieceColor enum 黑 / 白
Coordinate 棋盘坐标
Move 一次走子（from / to，或含跳吃）
GamePiece 颜色 + 是否加冕等

底层仍可映射回 i32 位标志（与 Ch2 兼容），但源码层不再手写 AND/OR。

迭代器与模式匹配

能力 跳棋中的用法
迭代器 .filter / .map 枚举当前玩家所有 legal_moves
match / if let 分支：普通走 vs 跳吃 vs 加冕
组合子风格 wast 里需数十条 br_if 的逻辑，Rust 数行可读

隔离核心逻辑（重要设计模式）

┌─────────────────────────────────────┐
│  domain/   CheckersEngine           │  ← 纯 Rust，无 wasm 属性
│            单元测试 cargo test       │
└─────────────────┬───────────────────┘
                  │ 薄适配层
┌─────────────────▼───────────────────┐
│  wasm_api/  export get_piece, move  │  ← [3.5](./3.5-rusty-checkers-ffi.md)
└─────────────────────────────────────┘

Layer 2 订单簿 同样拆分：

  • orderbook/ — 解析快照、best bid/ask（可 cargo test）
  • wasm_api/ — extern "C" export → layer02

3.5

Coding the Rusty Checkers WebAssembly Interface

第 3 章索引：README · 前：3.4-rusty-checkers · 后：3.6-rusty-checkers-js

一句话

用 lazy_static + 读写锁 持有全局引擎、Into<i32> 把 GamePiece 压成 Wasm 类型、extern "C" export/import 对接 JS — Rust 严格可变全局与 Wasm 单例状态之间的桥梁。

原书要点

处理全局可变状态

问题 书中方案
Wasm 模块需全局棋盘 单例 CheckersEngine
Rust 禁止随意 static mut lazy_static + RwLock（书中亦提到 mut_static 等等价思路）
并发 宿主单线程调用 export 时 read() / write() 即可

概念代码：

lazy_static! {
    static ref ENGINE: RwLock<CheckersEngine> = RwLock::new(CheckersEngine::new());
}

#[no_mangle]
pub extern "C" fn get_piece(x: i32, y: i32) -> i32 {
    let engine = ENGINE.read().unwrap();
    engine.get_piece(x, y).into()  // Into<i32>
}

现代替代（笔记用）：std::sync::OnceLock<RwLock<...>>（Rust 1.70+）— 原书 2019 年版用 lazy_static 仍有效。

类型转换与导出

方向 做法
Rust → Wasm export 复杂 GamePiece 实现 Into<i32>，export 只暴露 i32（与 Ch2 位标志兼容）
参数 get_piece(x,y)、move_piece(...) — 全 i32，与 JS Number 对接
隐藏内部 不 export set_piece 等 — 同 2.5 防御性 export

导入宿主函数

extern "C" {
    fn notify_piecemoved(x: i32, y: i32);
    fn notify_piececrowned(x: i32, y: i32);
}

// 在 move 逻辑成功后：
unsafe { notify_piecemoved(to_x, to_y); }
点 说明
extern "C" 声明 import，链接时期望宿主提供
unsafe call 外部函数 Rust 无法验证 — 见 Nomicon · FFI
命名空间 链接到 JS 的 env 模块（见 3.6）

↔ ER Item 34 · FFI 边界

与第 4 章预告

本章用手写 extern "C" + #[no_mangle]；第 4 章 引入 wasm-bindgen 自动生成胶水 → 4.1

WAT / 工具 / 代码锚点

项 说明
Cargo.toml lazy_static = "1"（或 OnceLock）
检视 import wasm-objdump -i rusty_checkers.wasm → import env.*

Playing Rusty Checkers in JavaScript

第 3 章索引：README · 前：3.5-rusty-checkers-ffi · 后：3.7-wrap-up

一句话

JS 宿主 fetch 加载 Rust 版 .wasm，在 env 命名空间挂上 notify_* import，实例化模块后即可驱动 Rust 跳棋引擎 — 完成 Ch2 wast 同款 UI 链路。

原书要点

加载 Rust 编译的 Wasm

步骤 说明
构建 cargo build --target wasm32-unknown-unknown --release
部署 将 .wasm 放到静态资源路径
fetch fetch('rusty_checkers.wasm') → arrayBuffer()

WebAssembly 实例化（概念）

const imports = {
  env: {
    notify_piecemoved: (x, y) => { /* 更新 UI */ },
    notify_piececrowned: (x, y) => { /* 音效等 */ },
  },
};

WebAssembly.instantiateStreaming(fetch('rusty_checkers.wasm'), imports)
  .then(({ instance }) => {
    instance.exports.init_board();
    instance.exports.move_piece(/* ... */);
  });

命名空间：env

Ch2 wast Ch3 Rust
自定义 import 模块名 Rust extern "C" 默认链到 env
JS 需与 wast 一致 前端 import 对象键改为 env: { ... }

若 instantiate 报 「 unknown import」，对照 wasm-objdump -i 的 module 名与 JS imports 键。

与 Layer 2 同构

跳棋 Ch3 Layer 2 订单簿
JS fetch .wasm JS fetch Go 订单簿 API
Wasm 算走子 Wasm parse + best bid/ask
env.notify_* 可选回调 / console 更新

→ layer02
