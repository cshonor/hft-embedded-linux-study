7.1

Overview of the Generic Indicator Module

第 7 章索引：README · 后：7.2-creating-indicators

一句话

GIMS（通用指示器模块系统）：用 Wasm 插件封装「指示器逻辑」，与 Blinkt LED 等硬件解耦 — 宿主/模块通过 sensor_update / apply / set_led 等标准 import/export 契约协作。

原书要点

从 Ch6 控制台到 IoT

Ch6 Ch7
控制台宿主 · wasmi ARM / 树莓派 宿主 · 真实 LED
跳棋 .wasm 不变 指示器 .wasm 可热替换
读 linear memory 画 ASCII set_led import 驱动硬件

↔ 6.1 · 宿主五职责

硬件解耦问题

传统 IoT GIMS + Wasm
换外设（单色 LED → 彩灯带）→ 大规模重构 换 Wasm 指示器模块 · 宿主 API 稳定
逻辑与 GPIO 耦合 传感器处理 在 Wasm · 物理输出 在宿主 import

GIMS API 契约（概念）

方向 函数 职责
宿主 → 模块 sensor_update(...) 喂传感器/电量等输入
宿主 → 模块 apply() 按帧率驱动动画步进（关键帧）
模块 → 宿主 (import) set_led(index, r, g, b) Wasm 请求宿主点亮某颗 LED 
┌──────────── Pi Host (Rust) ────────────┐
│  mpsc · 10 FPS · blinkt / 终端 mock     │
│  import: set_led                        │
│       ▲                    export:      │
│  ┌────┴──── indicator.wasm ─────────┐  │
│  │  sensor_update · apply · 动画逻辑  │  │
│  └───────────────────────────────────┘  │
└─────────────────────────────────────────┘

与 Layer 3 / HFT

GIMS Layer 3 边缘
热替换 indicator.wasm 热替换 ma_strategy.wasm（同类插件模型）
固定 apply 帧率 固定 tick 调度（勿在 Wasm 内 busy-loop）
宿主 set_led 宿主 下单/告警（策略只 export 信号）

7.3

Building Rust Applications for ARM Devices

第 7 章索引：README · 前：7.2-creating-indicators · 后：7.4-raspberry-pi-host

一句话

在 PC 上用 rustup target add armv7-unknown-linux-gnueabihf 交叉编译，产出可在 树莓派 Linux 上运行的 ARM 宿主可执行文件（加载 indicator Wasm 的那层 Rust 程序）。

原书要点

为何交叉编译

事实 做法
开发机在 x86_64 PC 目标机在 ARM 树莓派
宿主是 native Rust 二进制（非 Wasm） 需要 ARM Linux triple
Wasm 模块仍用 wasm32-unknown-unknown 宿主 与 插件 两个 target

配置步骤（书中）

rustup target add armv7-unknown-linux-gnueabihf

cargo build --release --target armv7-unknown-linux-gnueabihf
项 说明
triple armv7-unknown-linux-gnueabihf — 32 位 ARM · Linux · gnueabihf ABI
链接器 交叉链接有时需 ~/.cargo/config.toml 指定 linker = arm-linux-gnueabihf-gcc
部署 scp 二进制 + .wasm 到 Pi

双 target 工作流

indicator logic  →  wasm32-unknown-unknown  →  *.wasm
Pi host program  →  armv7-unknown-linux-gnueabihf  →  pi_host (ELF)

↔ Layer 3：边缘节点 native 宿主 + ma_strategy.wasm → layer03

与 no_std / 嵌入式

本章宿主用 std（线程、mpsc、文件监控）；更深层嵌入式见 ER Item 33 no_std · RFR Ch12

项 说明

可选 cross crate 简化 Docker 交叉构建

7.4

Hosting Indicator Modules on a Raspberry Pi

第 7 章索引：README · 前：7.3-rust-arm · 后：7.5-hardware-list

一句话

树莓派 Rust 宿主：mpsc + 超时 锁 10 FPS 动画、#[cfg] 在 ARM 上链 blinkt / 在 PC 上 println 调试，并实现 Wasm 模块热重载（覆盖 .wasm 文件即切换指示器）。

原书要点

宿主并发架构

需求 实现
传感器输入 · 动画 · 硬件 IO 并发 多线程
线程间消息 mpsc channel
固定 10 FPS channel recv_timeout — 超时则推进下一帧 / 调用 apply()
避免锁死 用 超时驱动 而非复杂锁（对照 05-atomic 并发模型） 
Thread A: 读传感器 → sensor_update → 发 Msg
Thread B: 10 FPS tick → apply() → set_led → blinkt
Thread C: 文件监控 → 热重载 wasm

条件编译 #[cfg(...)]

编译目标 行为
ARM + 特性 hardware 链接 blinkt · 真实 8 LED RGB
PC 开发机 println! 模拟 LED 颜色 — 无需硬件即可跑宿主 
#[cfg(all(target_arch = "arm", feature = "hardware"))]
fn set_led_hw(i: u8, r: u8, g: u8, b: u8) { /* blinkt */ }

#[cfg(not(all(target_arch = "arm", feature = "hardware")))]
fn set_led_hw(i: u8, r: u8, g: u8, b: u8) {
    println!("LED {} = ({},{},{})", i, r, g, b);
}

热重载 (Hot Reloading)

步骤 说明
文件系统监控 监视 indicator .wasm 路径
检测到新文件 安全暂停 当前模块
加载新实例 如 battery → pulsing 切换
继续运行 无需重启 Pi 或宿主进程 
运行中: battery_indicator.wasm
  → 覆盖为 pulsing_indicator.wasm
  → 宿主 reload
  → Knight Rider 动画（进程不退出）

Layer 3 映射：边缘节点 热换策略 wasm 而不重启撮合/风控进程 — 须配合 附录 A2 签名。

与 Ch6 宿主模式对比

Ch6 跳棋控制台 Ch7 树莓派
wasmi · Externals 同类 runtime + set_led import
读 memory 画 ASCII import 驱动硬件
静态 wasm 热重载

WAT / 工具 / 代码锚点

项 说明
FPS Duration::from_millis(100) ≈ 10 FPS
监控 notify crate 或 inotify 风格 API（以书为准）
demo Layer 3 host_wasmtime 可先 PC 模拟热重载

7.6

Endless Possibilities

第 7 章索引：README · 前：7.5-hardware-list · 后：7.7-wrap-up

一句话

Wasm 作为 安全、轻量、可移植的二进制插件，在 PLC、无人机、机器人 等 IoT 场景可解耦逻辑与硬件 — GIMS 只是最小示范；热重载 + 沙箱 对工业/边缘策略同样适用。

原书要点

GIMS 模式的可推广性

领域 Wasm 插件做什么 宿主做什么
PLC / 工业控制 逻辑图/规则编译为 Wasm I/O · 安全联锁 · 实时调度
无人机 飞行模式/指示算法 传感器融合 · 电机驱动
机器人 行为树片段 硬件抽象层（→ Ch8 WARoS）
HFT 边缘 均线/风控规则 Layer 3 行情接入 · 下单网关

本章已验证的能力

能力 章节
硬件解耦 7.1 GIMS
无硬件测试 7.2
交叉编译部署 7.3
并发宿主 + cfg 7.4
热重载 7.4

限制与 HFT 边界（笔记必写）

适合 Wasm 插件 不适合
可替换业务规则 · 指示/策略 · 沙箱隔离 亚毫秒撮合 · 无 GC 仍不等于裸 metal
热更新 · 跨设备同二进制 硬实时内核里直接跑解释型 Wasm（需测延迟）
