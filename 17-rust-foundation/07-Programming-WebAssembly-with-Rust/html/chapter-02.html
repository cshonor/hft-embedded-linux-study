2.2

Coping with Data Structure Constraints

第 2 章索引：README · 前：2.1-checkers-board-game · 后：2.3-game-rules

一句话

Wasm 没有数组/结构体/枚举——用线性内存把 8×8 棋盘扁平化为 offset = (x + y * 8) * 4，再用 32 位整数的位标志打包「空 / 黑 / 白 / 加冕」状态。

原书要点

线性内存与二维数组扁平化

事实 做法
无内置数组、结构体、元组 在 linear memory 里自己布局
8×8 棋盘，每格一个状态 每格 i32（4 字节）
二维坐标 (x, y) 一维偏移： 
offset = (x + y * 8) * 4

(x,y) 逻辑棋盘          线性内存 [byte]
┌───┬───┬ … ──┐         [0..3]   (0,0)
│   │   │     │         [4..7]   (1,0)
└───┴───┴ … ──┘           …
                          [252..255] (7,7)
  • 共 64 × 4 = 256 字节 → 整模块运行时线性内存约 256 字节（2.5）。

位标志与位掩码 (Bit Flags & Bit Masking)

无法用「对象 / 枚举」表示棋子 → 用一个 i32 的比特位 打包：

值（位） 含义
0 空位
1 黑棋
2 白棋
4 已加冕 (Crowned)

组合示例：

棋子 计算 值
加冕黑棋 Crowned(4) + Black(1) 5
加冕白棋 4 + 2 6

位运算（查询 / 修改而不破坏其它位）：

操作 典型用法
AND 检测是否含某标志：piece & 4 → 是否加冕
OR 加标志：piece | 4 → 加冕
XOR 切换标志（慎用，需配合掩码）

与 Rust / HFT 对照

Wasm 本章 Rust / 交易侧
i32 位打包棋子 订单簿档位 occupancy 位图、flags 字段
固定 8×8 网格 固定 N 档 深度，避免 Wasm 内动态扩容
手动 offset 公式 #[repr(C)] 数组或 [Price; N] 线性布局

→ Layer 2 · 订单簿快照布局

WAT / 工具 / 代码锚点

项 说明
存取 $getPiece / $setPiece — 见 2.4 前驱 与边界 $inRange
常量 书中用 (i32.const 0/1/2/4) 或 global 定义 EMPTY/BLACK/WHITE/CROWNED

概念 WAT（读格）：

;; offset = (x + y*8) * 4  → 需 mul/add/shl 组合实现
;; $getPiece(x, y) → load 线性内存

2.3

Implementing Game Rules

第 2 章索引：README · 前：2.2-data-structure-constraints · 后：2.4-moving-players

一句话

在扁平内存 + 位标志之上，实现跳棋规则函数（如 $shouldCrown）和 回合全局变量 $currentTurn，并配合 $getPiece / $setPiece / $inRange 操纵棋盘。

原书要点

操纵棋盘：存取与边界

函数 作用
$getPiece(x, y) 按 offset = (x + y*8)*4 从线性内存 load
$setPiece(x, y, value) 向对应地址 store
$inRange(x, y) 手动边界检查 — Wasm 不会像高级语言那样自动抛越界异常

越界访问 linear memory 在 Wasm 里是 trap（模块 abort），但逻辑上仍须保证坐标在 0..7，避免脏读/写相邻状态。

追踪当前回合

机制 说明
(global $currentTurn (mut i32)) 可变全局：黑方 / 白方
查询 / 更新函数 模块内封装，供 $move 等逻辑调用

规则示例：$shouldCrown

条件 行为
棋子到达对手底线 应加冕 → 对棋子值 OR 4（Crowned 位）
实现 依赖当前玩家方向 + y 坐标（黑/白底线不同）

其它规则（与 2.4 重叠）：

  • 目标格必须为空
  • 移动的棋子须属于 $currentTurn
  • 斜走距离 / 跳吃合法性（书中在 $move 路径里验证）

宿主通知（import）

规则触发后模块 import 宿主函数，让 JS 更新 UI / 音效：

import 时机
$notify_piececrowned 加冕完成
$notify_piecemoved 移动完成

→ Wasm 不能直接操作 DOM；通知 = 1.1 宿主边界 的标准模式。

WAT / 工具 / 代码锚点

项 说明
(import "env" "notify_piecemoved" (func ...)) 宿主实现；模块 (call $notify_piecemoved)
$initBoard 初始化棋子布局 → 2.5

2.4

Moving Players

第 2 章索引：README · 前：2.3-game-rules · 后：2.5-testing-wasm-checkers

一句话

$move 在验证合法后更新棋盘（源格清空、目标格写入，必要时加冕），切换 $currentTurn，并 call 宿主 import 通知 UI——整条路径演示「纯 Wasm 状态机 + 宿主 I/O」。

原书要点

移动流程（概念）

$move(fromX, fromY, toX, toY)
  ├─ $inRange(…)           边界
  ├─ 棋子 ∈ $currentTurn   归属
  ├─ 目标格为空            $getPiece(to)==0
  ├─ 斜向距离 / 跳吃规则   书中合法性检查
  ├─ $setPiece 更新棋盘    源→0，目标→piece（或 crowned）
  ├─ $shouldCrown → OR 4   加冕时 call $notify_piececrowned
  ├─ call $notify_piecemoved
  └─ 更新 $currentTurn

验证项（原书强调）

检查 失败时
坐标在棋盘内 不执行 / trap 前返回错误码（依实现）
移动距离正确（斜走一格或跳吃） 拒绝移动
目标位置为空 拒绝移动
被移动棋子属于当前玩家 拒绝移动

状态更新

  1. 原位置 $setPiece(fromX, fromY, 0)
  2. 新位置 写入棋子值（若 $shouldCrown 则 piece | 4）
  3. 回合 翻转 $currentTurn

与宿主通信

方向 函数 用途
import $notify_piecemoved 宿主：动画、重绘棋盘
import $notify_piececrowned 宿主：加冕特效、音效

这与 Layer 2「Wasm 算 spread、JS fetch 订单簿」同构：计算在模块，I/O 在宿主。

WAT / 工具 / 代码锚点

项 说明
export $move 暴露给宿主 — 见 2.5
不 export $setPiece 等保持私有，防作弊

2.5

Testing Wasm Checkers

第 2 章索引：README · 前：2.4-moving-players · 后：2.6-wrap-up

一句话

通过 $initBoard + export/import 边界 测试跳棋模块；纯手工 WAT 引擎约 853 字节 二进制、256 字节 线性内存——演示 Wasm 体积极小与防御性 export 实践。

原书要点

初始化与导出策略

函数 可见性 说明
$initBoard export 宿主启动时摆子
$move export 合法走子入口
$getCurrentTurn 等 export（若书中有） 宿主读状态
$setPiece 私有 防止宿主直接改盘 作弊
底层内存写 私有 仅 $move / 内部逻辑可改状态

→ 防御性编程：只 export「业务 API」，隐藏可破坏不变量的 primitive。

测试方式

方式 说明
wabt wasm-interp 加载模块，call export，检查 memory/global
宿主 JS 测试页 import 通知函数里 console.log / assert
wat2wasm + 浏览器 与 Part II 第 3 章 JS 游玩衔接

体积与内存（书中数据）

指标 数值 含义
.wasm 文件 ~853 字节 纯手工引擎，无 runtime 膨胀
线性内存占用 256 字节 64 格 × 4 字节，无额外堆

对比：同逻辑用 Rust + std 编译到 Wasm 往往 KB～MB 级——第 3 章会讨论编译器为你加了什么。

编译与检视命令

wat2wasm checkers.wat -o checkers.wasm
wasm-objdump -h checkers.wasm    # 段大小
wasm-objdump -x checkers.wasm    # export/import
ls -l checkers.wasm              # ~853 bytes
