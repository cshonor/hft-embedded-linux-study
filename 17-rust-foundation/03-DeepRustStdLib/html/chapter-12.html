本章总览 · 分层架构与跨平台对照

章索引：第 12 章 · 后：12.1 · OS 层

一句话

第 12 章 = std::path + std::fs — 延续 Ch9～11 双层（+ 平台扩展）架构，在 OsStr 编码隔离 之上抹平 Unix 字节路径 vs Windows UTF-16 差异；File RAII Drop 与 Ch10 管道 fd 同源。

三层结构（同进程/并发模块）

OS 底层适配 sys::{unix,windows}::fs · sys::path unsafe · fd/HANDLE · open/stat/readdir
平台扩展 std::os::unix::fs · std::os::windows::fs 扩展 Trait · Unix mode · Windows 共享/属性 
业务  File::open(path) / fs::read_dir()
  └── std::fs / path（stable）
        └── sys::fs / sys::path（SYSCALL）
        └── os::unix::fs（按需 OpenOptionsExt 等）

跨平台对照

特性 Unix Windows std 抹平
分隔符 / \ Path::join/push
路径编码 原生 字节（常 UTF-8） UTF-16 WCHAR OsString/OsStr
权限 rwx mode ACL / 只读隐藏 Metadata + unix 扩展
软链接 symlink 文件/目录链区分 fs::symlink 适配
句柄 fd HANDLE File.inner
目录遍历 opendir/readdir FindFirstFileW ReadDir/DirEntry

前置 / 后置

方向 关联
Ch9 Read/Write/Seek · FD 所有权 · OsString
Ch10 管道 = 特殊 fd · Drop 关闭
Ch11 多线程文件竞态 · TOCTOU
Ch13 File: Read + Write · stdin/网络 I/O 同 IO 体系

实战示例

use std::fs::{self, File, OpenOptions};
use std::path::PathBuf;
use std::io::{Read, Write};

fn main() -> std::io::Result<()> {
    let mut p = PathBuf::from("./data");
    p.push("test.txt");

    let mut f = OpenOptions::new()
        .create_new(true)  // 原子创建，规避 TOCTOU
        .write(true)
        .open(&p)?;
    f.write_all(b"rust fs test")?;

    let mut buf = Vec::new();
    File::open(&p)?.read_to_end(&mut buf)?;

    for entry in fs::read_dir("./")? {
        println!("{:?}", entry?.path());
    }
    println!("size: {}", fs::metadata(&p)?.len());
    Ok(())
}

.1 路径名类型分析

章索引：第 12 章 · 前：12.1 · 后：12.1.2 · 文件操作

一句话

路径底层 = OS 原生字节/宽字符 — String/str → OsString/OsStr → PathBuf/Path 四层包装；禁止 把非 UTF-8 路径当 &str 用，从类型层面杜绝跨平台乱码。

原书要点

平台编码根本差异（本章难点）

平台 原生表示 SYSCALL 入参
Unix 字节流 &[u8] · 主流 UTF-8 非强制 open(path_bytes, …)
Windows UTF-16 WCHAR CreateFileW 等仅宽字符 API

四层关系

层 Unix 内部 Windows 内部 角色
OsString Vec<u8> Vec<u16> 平台原生 拥有
OsStr &[u8] &[u16] 借用 · 等同 str
PathBuf 包 OsString 同左 可改 · join/push
Path 包 OsStr 同左 只读 · 轻量 
let p = Path::new("/var/log/app.log");
p.file_name();
p.extension();
p.components(); // Root / CurDir / ParentDir / Normal

底层核心逻辑

机制 说明
分隔符抹平 join/push 自动 / 或 \ · 禁止硬编码
components() 根、..、普通段 → Component 枚举 · 逻辑在 sys::path
无损转换 OsStr::to_str() → Option<&str> · 非 UTF-8 返回 None
fs 入口 impl AsRef<Path> → OsStr → 平台字节/宽字符 → syscall

HFT

策略 Linux 部署 · 日志路径 PathBuf::from · 避免硬编码 \。

12.4

Unix `sys::fs::File` 精简走读

章索引：第 12 章 · 前：12.1.2 · 文件 OS 层 · 对照：10.4 · 进程 unsafe

一句话

对照 library/std/src/sys/fs/unix.rs 的 概念骨架 — open → OwnedFd → read/write → Drop close；非 rustc 逐字拷贝，便于与 12.1.2 并排刷源码。

A. open 路径

// sys/unix/fs.rs — 逻辑骨架
pub fn open(path: &Path, opts: &OpenOptions) -> io::Result<File> {
    let path = cstr_path(path)?; // Path → OsStr → CString/CStr 字节
    let flags = opts.get_flags(); // O_RDONLY | O_CREAT | ...
    let mode = opts.get_mode();   // 仅 create 时有效

    let fd = unsafe {
        // SAFETY: path 指针有效 NUL 结尾；flags/mode 合法
        cvt(libc::open(path.as_ptr(), flags, mode))?
    };
    Ok(File { fd: fd as RawFd })
}
步骤 说明
Path → C 字符串 Unix syscall 要 const char*
cvt errno → io::Error
返回 fd 上层 std::fs::File 再包一层

B. read / write

impl File {
    pub fn read(&self, buf: &mut [u8]) -> io::Result<usize> {
        let ret = unsafe {
            cvt(libc::read(self.fd, buf.as_mut_ptr() as *mut _, buf.len()))?
        };
        Ok(ret as usize)
    }

    pub fn write(&self, buf: &[u8]) -> io::Result<usize> {
        let ret = unsafe {
            cvt(libc::write(self.fd, buf.as_ptr() as *const _, buf.len()))?
        };
        Ok(ret as usize)
    }
}

Read/Write trait 在 std::fs::File 层调用 inner 并处理 WouldBlock 等（依平台）。

C. Drop 关闭 fd

impl Drop for File {
    fn drop(&mut self) {
        let _ = unsafe { libc::close(self.fd) };
        // 与 pipe/Child stdout 相同：fd 生命周期由 Rust Drop 管理
    }
}

↔ 9.5.1 · FD 所有权 · 10.1 · 管道 fd

D. 上层 std::fs::File 包装

// library/std/src/fs/file.rs — 示意
pub struct File {
    inner: sys::fs::File,
}

impl Drop for File {
    fn drop(&mut self) {
        // 委托 inner Drop → close
    }
}

impl Read for File {
    fn read(&mut self, buf: &mut [u8]) -> io::Result<usize> {
        self.inner.read(buf) // 或经 Read 适配层
    }
}

开发者 仅见 safe API · unsafe 仅在 sys。

E. OpenOptions → flags/mode

// 概念：上层 builder
OpenOptions::new()
    .read(true)
    .write(true)
    .create(true)
    .truncate(true)
    .mode(0o644)  // unix 扩展 PermissionsExt / mode via OpenOptionsExt

// sys 层合并为 libc::open 的 flags + mode_t

Windows 侧对应 CreateFileW 的 dwDesiredAccess / dwCreationDisposition — 见 sys/fs/windows.rs。

12.5

Path / PathBuf 编码转换极简走读

章索引：第 12 章 · 前：12.1.1 · 路径类型

一句话

Path 不存 UTF-8 假设 — 所有 fs syscall 前 Path → OsStr → 平台原生序列；Unix &[u8] · Windows &[u16] → 宽字符 API。

类型栈（拥有 → 借用）

PathBuf  ──Deref──►  Path
   │                    │
   └─ inner: OsString ──┴─ inner: OsStr
            │                      │
         Unix: Vec<u8>         &[u8]
         Win:  Vec<u16>        &[u16]

let mut pb = PathBuf::from("/tmp");
pb.push("日志");           // join 自动分隔符
let p: &Path = pb.as_path();

A. join / push（分隔符抹平）

// path.rs — 概念
impl PathBuf {
    pub fn push<P: AsRef<Path>>(&mut self, path: P) {
        self.inner.push(path.as_ref().inner); // OsString::push
        // sys::path 或 path 模块：Unix 补 '/' · Windows 补 '\\'（规则更细）
    }
}

业务禁止 "dir" + "\\" + "file" · 统一 Path::new("dir").join("file")。

B. Path → syscall 字节（Unix）

fn path_to_cstring(path: &Path) -> io::Result<CString> {
    let os = path.as_os_str();
    // OsStr → 字节切片（可能非 UTF-8）
    let bytes = os.as_encoded_bytes(); // 示意 API 名因版本而异
    CString::new(bytes).map_err(|_| io::Error::new(InvalidInput, "path contains NUL"))
}

// open 时：
libc::open(c_path.as_ptr(), flags, mode);

OsStr::to_str() 仅当 合法 UTF-8 才 Some — 用于 打印/日志，不用于 syscall。

C. Path → UTF-16（Windows）

fn path_to_wide(path: &Path) -> io::Result<Vec<u16>> {
    let os = path.as_os_str();
    let wide: Vec<u16> = os.encode_wide().chain(Some(0)).collect(); // NUL 结尾
    Ok(wide)
}

// CreateFileW(wide.as_ptr(), ...);

Windows OsString 内部即 Vec<u16> · 与 Unix Vec<u8> 在 ffi/os_str 用 cfg 分派。

D. 与 String 互转（显式、可能失败）

// String → Path（UTF-8 路径）
let p = Path::new("/home/user/文件.txt");

// Path → String（仅 UTF-8 路径）
if let Some(s) = p.to_str() {
    println!("{}", s);
} else {
    // 非 UTF-8 文件名：用 OsStr 或 lossy 显示
    println!("{:?}", p);
}
转换 安全性
&str → &Path UTF-8 str 必是合法 Path 字节（Unix）
Path → &str Option · 非 UTF-8 → None
OsString from 字节 保留 任意 系统文件名

E. AsRef<Path> 作为 fs API 边界

pub fn metadata<P: AsRef<Path>>(path: P) -> io::Result<Metadata> {
    imp::metadata(path.as_ref())
}
// 故 &str、String、PathBuf、&Path 均可传入
