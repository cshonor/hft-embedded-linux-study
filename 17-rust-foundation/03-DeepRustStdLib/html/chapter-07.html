7.1

Borrow / BorrowMut 分析

章索引：第 7 章 · 后：7.2 · Cell 总览

一句话

Borrow<T> / BorrowMut<T>（core::borrow）描述 「等价键/等价视图」 的借用规则 — 为 HashMap/HashSet 查找 与 RefCell 系列 API 命名 提供 Trait 基础；内部可变性章从这里过渡到 UnsafeCell 栈。

原书要点

Trait 契约
Borrow<B> &self 可等价于 &B（如 String → str）
BorrowMut<B> 可变等价视图（较少见） 
// HashMap 查找：k 不必与存储键同型
map.get("hello");  // String key · &str 查找 · Borrow

与内部可变性的关系

层 类型
编译期借用 &T / &mut T
Trait 等价 Borrow — 集合与智能指针
运行期借用 RefCell::borrow → Ref guard（7.3）

注意：RefCell 的 borrow() 返回 Ref<'b, T>，与 std::borrow::Borrow 是 不同概念 — 7.3.1 讨论的是 RefCell 的运行期借用 guard。

源码锚点

位置 说明

7.2

Cell<T> 类型分析

章索引：第 7 章 · 前：7.1 · 后：7.2.1 · UnsafeCell

一句话

Cell<T> 族建立在 UnsafeCell<T> 之上 — 在持有 &Cell<T>（不可变引用）时仍可用 set/get 替换/读取内部值；无 &T/&mut T 指向内部，故 !Sync、单线程 内部可变。

原书要点

7.2.1 UnsafeCell  ──►  7.2.2 Cell  ──►  7.3 RefCell（要 &T 引用时用）
对比 Cell<T> RefCell<T>
访问方式 值拷贝 get/set borrow() → &T
运行期计数 无 BorrowFlag
T: Copy 常见 非必须
跨线程 禁止（!Sync） 禁止

设计定位（原书）

内部可变性 不是 绕过编译器的「补丁」— 是 Rust 有意 提供的架构空间：在 编译期证明太难 的场景（图、回调计数）把检查 下推 到 API 设计或运行期。

源码锚点

位置 说明

7.3

RefCell<T> 类型分析

章索引：第 7 章 · 前：7.2.2 · 后：7.3.1 · borrow guard

一句话

RefCell<T> = UnsafeCell<T> + BorrowFlag 运行期借用计数器 — 在 &RefCell<T> 上 borrow()/borrow_mut() 动态执行 读写互斥；违规则 panic!（非 UB），把部分 编译期 借用检查 推迟到运行期。

原书要点

不是编译器补丁

误解 原书立场
RefCell = hack 有意架构 — 树/图/观察者 共享 &self 仍要改子节点
与 &mut 等价 运行期 才检查 · 有 panic 成本

BorrowFlag（直觉）

状态 含义
0 未借用
>0 N 个 共享 borrow（Ref）
-1 唯一 borrow_mut（RefMut） 
borrow()     → flag +1   → Ref  guard drop 时 -1
borrow_mut() → flag = -1  → 与任何 borrow 互斥
冲突         → panic!    （try_borrow 返回 Err）

子节

节 内容
7.3.1 Ref / borrow()
7.3.2 RefMut / borrow_mut()
7.3.3 try_* · replace · map_split

与 Cell

需要 &T 指向内部字段（大结构、非 Copy）→ RefCell；仅改 Copy 标量 → Cell 更轻。

源码锚点

位置 说明

7.4

Pin<T> / Unpin<T> 类型分析

章索引：第 7 章 · 前：7.3.3 · 后：7.5 · Lazy

一句话

Pin<P> 钉住 堆/栈上值 禁止安全移动 — 解决 自引用结构（成员指针指向同结构体内存）在 搬家后变悬垂 的问题；Unpin 是 Auto Marker：无自引用 的普通类型 可自由 move，不受 Pin 约束。

原书要点

痛点：自引用

struct State {
  buf: [u8; N],
  ptr: *const u8,   // 指向 buf 内部
}
// mem::swap / move 后 ptr 仍指旧地址 → 悬垂
场景 需要 Pin
async 状态机 编译器生成的 自引用 Future
** intrusive 链表节点** 指针嵌在结构体内
C 互操作 固定地址回调 user_data

Pin 语义

点 说明
Pin<Ptr<T>> 对 T 施加 「不可 unpinned move」 invariant
堆 Pin Box::pin(t) — 常见
Unpin 默认 所有类型 除含 !Unpin 字段 — 可 Pin::get_unchecked_mut 等
!Unpin 显式 PhantomPinned 或编译器生成 
Pin  ≠  不可变
Pin  =  地址稳定（仍可通过 Pin + unsafe 或 Pin<&mut T> 改内容）

↔ 4.3.1 · Marker · Unpin

与内部可变性

Pin 解决 位置；Cell/RefCell 解决 &self 下改值 — async 常组合 Pin<&mut Self>。

源码锚点

位置 说明

library/core/src/future/ Future + Pin

7.5

Lazy<T> 类型分析

章索引：第 7 章 · 前：7.4 · 后：第 8 章 · 智能指针

一句话

OnceCell<T> 保证 全局仅初始化一次；Lazy<T> 在其上封装 闭包延迟初始化 — 首次 Deref 时才执行 init，优化 启动时间 与 按需占内存（符号表、配置、regex 编译等）。

原书要点

OnceCell

方法 行为
get() Option<&T> — 未 init 则 None
set(val) 仅首次 Ok · 再次 Err
get_or_init(f) 原子/线程安全变体见 OnceLock（std） 
程序生命周期内  ──►  最多一个 T 实例被写入

Lazy

static CONFIG: Lazy<HashMap<…>> = Lazy::new(|| {
    load_heavy_config()  // 第一次访问才跑
});
fn use_cfg() { CONFIG.get("key"); }
点 说明
延迟 闭包 第一次解引用 时运行
Once 底层 OnceCell — 只 init 一次
线程 std::sync::LazyLock / once_cell crate 历史

HFT

场景 用法
合约元数据表 首次订阅时加载
regex / 解析器 避免冷启动全量编译

↔ 与 static mut / 手写 init 相比 — 安全且单次

位置 说明
