3.1

裸指针——不安全的根源

章索引：第 3 章 · 后：3.1.1 · 具体实现

一句话

*const T / *mut T 只表示「可能存在的内存地址+元数据」，不保证对齐、初始化或有效性 — 与 &T / &mut T 的借用检查相对；~90% 的 unsafe 根源 是把裸指针 转成引用。

原书要点

概念与区别

裸指针 安全引用
语法 *const T · *mut T &T · &mut T
有效性 不保证 指向合法、已初始化、对齐的内存 编译器 借用检查 保证
生命周期 无 有 · 防悬垂
解引用 unsafe 安全 
&T / &mut T  ──编译器证明──►  安全使用
*const / *mut ──程序员证明──►  unsafe 解引用 / 转 &T

Unsafe 的核心（原书）

约 90% 的 unsafe 代码根源：裸指针 → 引用（&*ptr / ptr.as_ref() 等）。

风险 说明
** invented 生命周期** 转引用时生命周期由 返回值/上下文 决定，须 手动 证明仍有效
未初始化 / 已释放 指针仍「存在」但指向 UB
别名违规 同时 &mut 与读同一地址

3.1

.1 裸指针具体实现

章索引：第 3 章 · 前：3.1-raw-pointers · 后：3.1.2-raw-pointer-inherent-fns

一句话

裸指针通过 Pointee trait + Metadata 区分 瘦指针（仅地址，Sized 类型）与 胖指针（地址 + 长度或 vtable 等元数据，DST）。

原书要点

Pointee 与 Metadata

概念 说明
Pointee 被指向类型 · 决定指针是否带 元数据
Metadata 附加在指针上的 第二字（概念上）— 切片长度、dyn Trait 的 vtable 等

瘦指针 vs 胖指针

类型 指针形态 元数据
i32 · Struct 等 Sized 瘦指针 无（仅地址）
[T] 切片 DST 胖指针 长度
dyn Trait 胖指针 vtable 指针等
str 胖指针 字节长度 
瘦:  [*const i32]     →  地址
胖:  [*const [T]]     →  地址 + len
     [*const dyn Debug] →  地址 + vtable

与引用

&[T]、&dyn Trait 在内存表示上也是 胖指针 — 安全引用携带 编译器校验过的 元数据与生命周期。

3.2

.1 MaybeUninit\<T\> 定义

章索引：第 3 章 · 前：3.2-maybeuninit · 后：3.2.2-manuallydrop-definition

一句话

MaybeUninit<T> 是 union 式封装 — 告诉编译器「内部 可能尚未初始化」，从而 禁止 在未初始化时按 T 做安全读取；初始化后用 assume_init()（unsafe）取出 T。

原书要点

能力 API 方向
创建未初始化槽 MaybeUninit::<T>::uninit()
写入初始化 write(self, val) · ptr.write(val)
取出已初始化 T assume_init() · assume_init_read() 等 — unsafe
获取指针 as_ptr() / as_mut_ptr() — 仍须保证初始化后再解引用

安全边界

  • MaybeUninit 本身 safe — 不能 safe 地读出未初始化的 T。
  • assume_init — 程序员证明 已完整初始化，否则 UB。
let mut slot = MaybeUninit::<String>::uninit();
slot.write(String::from("tick"));
let s = unsafe { slot.assume_init() };

.2 ManuallyDrop\<T\> 定义

章索引：第 3 章 · 前：3.2.1-maybeuninit-definition · 后：3.2.3-maybeuninit-constructors

一句话

ManuallyDrop<T> 告诉编译器：生命周期结束时不要自动 drop — 防止对 未初始化 内容误 drop（UB），或在 take/replace 浅拷贝转移 后 双重释放。

原书要点

问题 ManuallyDrop 作用
未初始化内存被当作 T drop 包在 MaybeUninit + ManuallyDrop 流程中控制 drop 时机
mem::replace / 所有权转移 原槽位 不应 再 drop 已移走的值
手动释放 ManuallyDrop::drop() — 显式触发

与 mem::forget

ManuallyDrop mem::forget
语义 包装类型 · 仍拥有 T 直到手动 drop 泄漏 — 永不 drop
典型 自定义容器内部 极少数 intentional leak

智能指针的基座——Unique\<T\>

章索引：第 3 章 · 前：3.4.3-nonnull-other-fns · 后：3.6-mem-module

一句话

Unique<T>（内部/nightly 概念）在 NonNull<T> 上叠加 PhantomData<T> — 逻辑声明独占所有权，生命周期结束时应对应 释放 所指向资源；是 Box / Vec 底层 的常见模式。

原书要点

与 NonNull 对比

NonNull<T> Unique<T>
非空 ✅ ✅
所有权语义 无（仅地址约束） PhantomData<T> 表 拥有 T
drop 含义 不自动释内存 类型 析构 表示 独占资源应释放（由外层容器实现）

在标准库中的体现

现代 Box/Vec 实现用 Unique/NonNull + 分配器 组合 — 读 alloc::boxed::Box 源码可见。

Box<T>  ≈  Unique/NonNull  +  Allocator  +  Drop 释堆

mem::take 与 mem::replace 在 不能用 = 转移 的场景（如 &mut 结构体字段）用 浅拷贝/替换 安全 移出或交换 T 的所有权。

原书要点

API 行为
mem::take(&mut place) T: Default — 用 默认值替换 place，返回 旧值
mem::replace(&mut place, new) 存入 new，返回 被替换掉的旧 T 
fn reset(opt: &mut Option<Heavy>) {
    let old = opt.take(); // Option 专属；通用场景用 take/replace
}

为何需要

  • &mut T 不能 move 出 T（否则留下未初始化位）
  • 浅拷贝语义 — 对 String/Vec 是 指针所有权转移，非 deep clone

3.10

Rust 所有权、生命周期、借用探讨

章索引：第 3 章 · 前：3.9-drop-summary · 后：3.11-recap

一句话

底层内存工具之上，Rust 安全理念可归结为：所有权（值唯一定位）· 生命周期（类型 = 结构 + 生命周期）· 变异性（协变/逆变/不变 — 解释生命周期子类型为何有时通过、有时被拒）。

原书要点

所有权（Ownership）

原书观点 含义
本质 值在内存块之间 转移（浅拷贝指针/位模式） 时，维持 「值唯一定位」 的标志
move 旧位置 失效 · 新位置 负责 drop
与 C++ Rust 默认 move + 编译期 禁止 use-after-move

↔ 第 2 章 · 安全封装

生命周期（Lifetime）

原书观点 含义
动机 防止 悬垂引用（借用 outlives 被借数据）
升格 生命周期成为 类型系统一部分 — 概念上变量类型 = 「数据结构类型 + 生命周期」
标注 'a 约束 引用有效区间

↔ _supplement/legacy-lifetimes · Nomicon 03 型变

变异性（Variance）

种类 直觉（简化）
协变 (covariant) 生命周期 更长 的引用可当作 更短 使用（在 safe 子类型方向）
逆变 (contravariant) 函数参数等 反向 子类型方向
不变 (invariant) &mut T、含 &mut 的容器 — 长度必须完全一致

理解 为何 'long: 'short 有时能赋给短引用、有时 &mut 不行 — 泛型生命周期推导的核心。

与裸指针章节的闭环

裸指针无生命周期 → 转 &T 时「发明」生命周期
  → 所有权/借用/型变 是 safe Rust 对同一内存问题的上层答案
