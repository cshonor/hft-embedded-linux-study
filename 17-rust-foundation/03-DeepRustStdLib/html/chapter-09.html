9.2

代码工程中的一个技巧

章索引：第 9 章 · 前：9.1.4 · 后：9.3 · STD 内存

一句话

std 的工程技巧：用 cfg(unix) / cfg(windows) 与 std::sys 私有模块 把 OS 相关实现 压到最底层 — 对外 std::fs / net 等 API 稳定，对内 按平台换 libc / 直接 syscall。

原书要点

分层（惯用结构）

pub API（fs · net · process）
  └── sys::unix / sys::windows / sys::hermit …
        └── libc 或 inline asm syscall
技巧 收益
#[cfg(...)] 分文件 编译期只编当前 OS
sys 不 stable 自由改底层 · 用户依赖 stable std
统一 error 映射 io::Error 包装 errno / Win32 码

与后续章节

9.4 · SYSCALL · 9.5 · FD 均建在 sys 层之上。

9.3

内存管理之 STD 库

章索引：第 9 章 · 前：9.2 · 后：9.4 · SYSCALL

一句话

Box/Vec 用的 Global / GlobalAlloc 在 用户态 std 中落地为 System 分配器 — 封装 malloc/free（或 Windows Heap / mmap 类 OS 接口），把 3.7 · 堆分配 接到真实 OS。

原书要点

从 alloc 到 std

层 分配器
core / alloc Global trait · 可 自定义 #![global_allocator]
std 默认 System implements GlobalAlloc 
Vec::push → RawVec grow → Global::allocate
  └── std 中 Global 默认 = System
        └── libc malloc 或 platform heap

与内核对比

环境 堆来源
内核 / no_std 自写 GlobalAlloc · 无 malloc
用户态 std OS/C 运行时 提供堆

↔ 8.2 · RawVec · 1.2 · alloc

自定义

#[global_allocator]
static A: MyAllocator = MyAllocator;
// HFT：jemalloc/mimalloc 替换 System

9.4

系统调用（SYSCALL）的封装

章索引：第 9 章 · 前：9.3 · 后：9.5 · FD

一句话

用户态使用 硬件/内核资源 的唯一合法路径是 SYSCALL — std::sys 对 Linux syscall! / libc、Windows Win32 API 等做 平台抽象，上层 fs / net / process 均建在此 安全封装 之上。

原书要点

为何需要封装

裸 syscall std 封装
寄存器/参数 架构相关 统一 io::Result
unsafe 边界集中 · API safe
errno / GetLastError io::Error 
std::fs::File::open
  └── sys::unix::fs::open  (path → OsStr → C bytes)
        └── libc::open  或  syscall(SYS_openat, …)

与 FFI 关系

SYSCALL 层往往经 C 运行时（libc） — 与 9.1 · FFI 衔接。

9.5

文件描述符及句柄

章索引：第 9 章 · 前：9.4 · 后：9.5.1 · FD 所有权

一句话

Unix 一切皆文件 — socket / pipe / 普通文件 在底层均为 整数 FD；Windows 用 HANDLE。std 把这些 OS 句柄 包装进 Rust 类型，交给 所有权 + Drop 自动 close，避免 C 式 泄漏/双重 close。

原书要点

统一抽象

OS 内核对象标识
Linux 等 fd: RawFd（i32）
Windows HANDLE 
File · TcpStream · UnixStream · Stdio
  └── 内部 OwnedFd / Handle（平台类型）
        └── Drop → close(2) / CloseHandle

节 主题

9.5.2 Read/Write · BufReader 逻辑层

原书典范

不仅内存安全，系统资源（FD）也自动化、唯一释放。

进程管理

一句话

9.6 作为 第 9 章收束与第 10 章预告 — 进程同样经 SYSCALL + FD 所有权 管理（Command · stdin/stdout 管道 FD · wait）；完整源码剖析见 第 10 章 · 进程管理。

原书要点

与本章链条

FFI + OsString  ──►  System 堆  ──►  SYSCALL  ──►  FD Drop
                                              └──►  进程/子进程 FD 继承
概念 std 侧
创建进程 Command::spawn → fork+exec / CreateProcess
标准 IO 子进程 FD 0/1/2 · Stdio::piped()
等待退出 Child::wait → waitpid

资源安全

Child 与 File 同类 — Drop 时回收（避免 zombie 须 wait 或 kill 策略）。
