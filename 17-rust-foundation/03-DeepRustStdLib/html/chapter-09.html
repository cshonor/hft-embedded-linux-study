一句话

C 字符串 = 以 \0 结尾的字节序列、无长度前缀；Rust 用 CStr / CString 适配 — 前者 借用 NUL 结尾缓冲，后者 拥有 并在末尾 写入 \0 供 FFI 传出。

let c = CString::new("hello")?;  // 内部含 \0
let ptr = c.as_ptr();             // *const c_char

鸿沟

C Rust
任意字节到 \0 UTF-8 验证（CString::new 拒绝内部 \0）
无编码约定 str 必 UTF-8

路径/系统串 往往 非 UTF-8 → 9.1.4 · OsString

一句话

Windows 不适用 UTF-16 宽串 
use std::ffi::OsStr;
let path = OsStr::new("/tmp/log");  // 平台编码
std::fs::read(path);                 // open  syscall 前转换

API 作用
Path / PathBuf 基于 OsStr 的路径语义
into_vec / from_* 与字节/宽字符缓冲互转

9.5

.1 文件描述符所有权设计

章索引：第 9 章 · 前：9.5 · 后：9.5.2 · 逻辑层

一句话

OwnedFd / File 等 独占 一个 FD — Drop 恰好 close 一次；try_clone → 新 FD · into_raw_fd 转移 后 Rust 不再 负责关闭 — 用类型系统复刻 唯一 owner 语义。

原书要点

C/C++ 痛点

错误 后果
忘记 close(fd) FD 泄漏
重复 close UB / 误关他人 FD
use-after-close 悬垂 fd 号

Rust 设计

{
    let f = File::open("log.txt")?;  // open → OwnedFd
    // … read/write …
}  // Drop → close 一次
机制 说明
OwnedFd 构造即 取得 FD 所有权
Drop close syscall
FromRawFd（unsafe） 外部 FD 接管 — 程序员保证有效
IntoRawFd 泄漏关闭责任给 C

与内存类比

Box<T>  Drop → free          OwnedFd  Drop → close
Rc  不适用于 FD（无 dup 计数在 Rust 层统一）→ 多 owner 用 try_clone 得新 FD

HFT

socket fd 生命周期绑定 TcpStream Drop — 避免热路径异常路径漏关。

位置 说明
