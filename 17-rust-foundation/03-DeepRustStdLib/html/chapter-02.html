2.1

Rust 核心特性与 `std` 的结合

章索引：第 2 章 · 前：附录 · 读源码 · 后：2.2 Trait

一句话

RFR 里学的 所有权、借用、移动 不是语法习题 — 它们直接决定 Vec::push、String::clone、HashMap::insert 在标准库里的 API 形状与实现方式。

所有权 → 标准库 API

语言规则 std 中的体现
移动默认 Vec<T> 进函数消耗所有权；append / extend 拿走对方 Vec
Copy 例外 小标量、IpAddr 等按位复制；大对象（String）必须显式 clone
单一所有者 Box<T> 独占堆数据；Vec 独占缓冲区
共享读 Arc<T> + 不可变引用；写路径另加 Mutex 等 
// std 设计：push 取得 T 的所有权，不借 &T 长期悬挂在 vec 里
let mut v = vec![1, 2];
v.push(3); // T moved into vec's buffer

读源码：alloc::vec::Vec::push — 扩容时 旧缓冲区整体 drop 或 relocate，依赖 唯一所有权 不变量。

借用 → 标准库 API

借用规则 std 中的体现
&T 共享读 slice::iter、HashMap::get 返回 Option<&V>
&mut T 独占写 Vec::as_mut_slice、get_mut；Mutex::lock → MutexGuard
不可同时存在冲突借用 RefCell 运行时检查；违反则 panic

与 RFR 衔接：你在 RFR Ch01 学的「共享不可变、可变独占」，在 std::collections 与 std::sync 里变成 具体类型分工 — & 遍历 vs &mut 修改 vs Arc<Mutex<_>> 跨线程。

移动 + RAII → 资源类型

标准库大量类型 析构 = 释放资源：

类型 Drop 时做什么
File 关闭 fd
MutexGuard 解锁
Vec 释放堆缓冲区
TcpStream 关闭 socket

→ Book 15.3 Drop · Nomicon 06 OBRM

读源码时的检查清单

  1. 这个方法是 拿走 self、&self 还是 &mut self？
  2. 返回值是 owned 还是 引用？引用生命周期绑在谁上？
  3. 内部有没有 unsafe 在「拉长」借用 — 通常伴随 unsafe 块与 invariant 注释。

2.1

.1 基于泛型的函数及 Trait

章索引：第 2 章 · 前：2.1-generics-overview · 后：2.1.2-generic-constraint-layers

一句话

泛型函数 与 trait 上的泛型方法 是标准库与业务代码的主干 — 用 T: Trait / where 表达约束，而不是复制粘贴具体类型版本。

原书要点

泛型函数

fn max<T: Ord>(a: T, b: T) -> T {
    if a > b { a } else { b }
}
要素 作用
<T> 类型参数
T: Ord trait bound — 保证可比较
单态化 max::<i32>、max::<f64> 各生成一份机器码

基于泛型的 Trait

形式 示例方向
泛型 trait Iterator<Item = T>
trait 上泛型方法 impl<T> Vec<T> { pub fn push(&mut self, value: T) }
关联类型 一种类型参数固定为 trait 内别名（第 4～5 章深入）

为何「离开泛型无法写程序」

标准库 API 几乎全是 Option<T>、Result<T,E>、Vec<T>、impl Iterator<Item=T> — 不理解泛型约束，读 std 签名会处处卡住。

源码锚点

位置 说明
core/src/iter/traits/iterator.rs 泛型 trait 范本
alloc/src/vec/mod.rs impl<T> Vec<T> 方法群

2.1

.2 泛型约束的层次

章索引：第 2 章 · 前：2.1.1-generic-functions-and-traits · 后：2.2-memory-safety-overview

一句话

Rust 泛型约束形成 从一般到特殊 的层次：基层 ?Sized → 一级（固定大小、指针、切片、引用、T: Trait、元组）→ 二级（具体类型或嵌套如 *const [T]）。

原书要点

层次结构（自顶向下）

基层：T: ?Sized          ← 最大集合（含 DST：str、[T]、trait object…）
  │
一级子层
  ├─ T                     固定大小类型（默认 T: Sized）
  ├─ *const T / *mut T     裸指针
  ├─ [T]                   切片 DST
  ├─ &T / &mut T           引用
  ├─ T: SomeTrait          额外 trait 约束
  └─ (T, U) / 复合类型     元组等
  │
二级子层
  ├─ *const u8             一级 + 具体类型
  └─ *const [T]            一级 + 嵌套（T 仍可为泛型）

基层：T: ?Sized

点 说明
Sized 编译期已知大小 — 默认泛型 T 隐含 T: Sized
?Sized opt-out — 允许 str、[T]、dyn Trait 等 DST
意义 写 fn foo<T: ?Sized>(x: &T) 才能统一接受 sized 与 unsized 借用

一级子层（常见）

形式 约束含义
T 固定大小 · 可栈分配 · 可 memcpy 式移动
*const T / *mut T 裸指针 — unsafe 解引用（第 3 章）
[T] 切片 — 长度运行时已知
&T / &mut T 借用 — 生命周期 + 别名规则
T: Trait 能力约束（Clone、Send…）

二级子层（实例）

写法 读法
*const u8 字节裸指针
*const [T] 指向 切片头 的裸指针（仍含 T 泛型）
&'a [u8] 一级引用 + 具体元素类型

与读 std 的关系

读 Vec<T>、Box<T>、Iterator<Item=T> 时，先问：T 默认 Sized 吗？有没有 ?Sized？ — 避免对 str / trait object 误用。

源码锚点

位置 说明
core/src/marker.rs Sized trait
core/src/ptr/mod.rs *const T / *mut T API

Rust 内存安全杂述

章索引：第 2 章 · 前：2.1.2-generic-constraint-layers · 后：2.3-extracting-from-wrappers

一句话

编译器只提供 有限安全规则 + 明确 unsafe；Rust 真正的内存安全靠程序员用 所有权、生命周期、Drop、Deref 构建的 安全封装类型 — 外部 API 无 unsafe 仍保证安全。

原书要点

编译器直接提供的安全（有限）

安全侧 示例
变量必须初始化 禁止读未定义值
严格类型检查 禁止隐式错误转换
借用检查 互斥可变 / 共享不可变
不安全侧（显式） 示例
裸指针解引用 *const T / *mut T
FFI extern "C" 调用

→ 第 3 章展开 · Nomicon

安全封装：真正的基石

模式：标准库内部大量 unsafe 实现 · 对外 safe API 承诺不变式。

封装类型 解决的问题
Option<T> 值可能 不存在
Rc<T> / Arc<T> 一块内存 多处引用（单线程 / 多线程）
Box<T> 堆 所有权
Mutex<T> 线程间 临界区（std）

借用 / 可变借用封装

类型 配合 机制
RefCell<T> Ref<T> / RefMut<T> 运行时借用计数 · Drop 释放
Mutex<T> MutexGuard<T> 加锁 guard · Drop 解锁 
安全闭环：
  unsafe 块内建立不变式
    → 封装类型对外 safe API
      → Ref/Guard 等 RAII · Drop 自动清理
        → 计数/锁释放 · 无泄漏

与第 1 章、第 7～8 章

层 封装
core Option/Result/Cell/RefCell
alloc Box/Rc/Arc/Vec
std Mutex/RwLock

位置 说明

量化 / 实盘语境

场景 封装选择
订单簿单线程 UI 回调 RefCell
跨线程行情快照 Arc + 必要时 Mutex

一句话

业务代码常要操作 封装内部的 T — 标准库提供 五种安全范式：? · Deref 自动解引用 · 闭包/map · as_ref/as_ptr · take/replace 移所有权。

原书要点

为何需要「解封装」

现实 做法
API 返回 Option<T>、MutexGuard<T> 要拿到 T 或 &T 才能计算
直接 .unwrap() everywhere 粗暴 — 五种模式按场景选

五种模式（索引）

# 模式 笔记

目标 优先

2.3

.1 使用 `?` 运算符解封装

章索引：第 2 章 · 前：2.3-extracting-from-wrappers · 后：2.3.2-deref-coercion

一句话

对实现 Try（如 Result / Option）的封装类型，用 ? 在成功时 解出内部值，失败时 早返回 — 替代层层 match / unwrap。

原书要点

? 做什么

fn parse_port(s: &str) -> Result<u16, ParseIntError> {
    let n: u16 = s.parse()?;  // Ok 则解封装为 u16；Err 则 return Err(...)
    Ok(n)
}
点 说明
解封装 ? 从 Result/Option 取出 Ok/Some 内的 T
错误传播 Err/None 自动 return（或 None 传播规则依上下文）
Try trait 统一 ? 语义的可扩展基础

适用封装类型

类型 典型场景
Result<T, E> IO、解析、业务错误
Option<T> 可空链（函数返回 Option 时）

与暴力解包对比

? unwrap()
失败 传播错误 panic
策略代码 ✅ 推荐 ❌ 生产慎用

2.3

.2 函数调用 + 自动解引用

章索引：第 2 章 · 前：2.3.1-unwrap-with-try-operator · 后：2.3.3-closures-for-inner-access

一句话

实现 Deref / DerefMut 的封装类型（Box、String、MutexGuard…）在 方法调用 时由编译器 自动解引用 — 无需手动 (*x) 即可调用内部 T 的方法。

原书要点

自动解引用（Deref coercion）

let s = String::from("hi");
s.len();              // 实际：Deref → str → len()
let b = Box::new(42);
*b + 1;               // 或依赖 Deref 到 i32 的上下文
机制 说明
Deref trait type Target = ... · fn deref(&self) -> &Target
编译器插入 找方法时自动 &* 链直到匹配
透明用法 写起来像直接操作 T

常见实现 Deref 的类型

类型 Target
Box<T> T
String str
Vec<T> [T]（通过 Deref 到切片）
MutexGuard<T> T
Ref<T> T

注意

  • 自动解引用 ≠ 获得所有权 — 仍是借用内部。
  • 过度依赖可能 隐藏分配/锁 — 读签名知类型。

.3 采用闭包（函数式编程）

章索引：第 2 章 · 前：2.3.2-deref-coercion · 后：2.3.4-getting-references

一句话

当 自动解引用不够用 时，用 Option/Result 的 map、filter、and_then 等 — 在 仍留在封装内 的前提下变换内部值，避免手动解包再重包。

原书要点

闭包 / 组合子模式

let port: Option<u16> = Some("8080".to_string())
    .as_ref()
    .and_then(|s| s.parse().ok());

let doubled = Some(21).map(|x| x * 2);  // Some(42)
API 作用
map(f) Some/Ok 内 映射 T → U，容器不变
filter(pred) 条件保留
and_then(f) 链式 flatMap — T → Option<U> / Result
unwrap_or / unwrap_or_else 提供默认值（闭包延迟计算）

与 ? / Deref 的分工

场景 选用
函数体内 早返回错误 ?
调用 T 的方法 Deref
一行链式 变换、仍 optional map / and_then
需要 &T 且不消费 as_ref + 闭包

标准库半标准化函数

Option / Result / Iterator 共享 函数式风格 — 与 2.4 闭包与 Iterator（补充） 一脉。

章索引：第 2 章 · 前：2.3.3-closures-for-inner-access · 后：2.3.5-getting-ownership

一句话

智能指针与封装类型提供 as_ref / as_mut / as_ptr / as_mut_ptr — 在 不转移所有权 的前提下取得内部 &T / &mut T 或裸指针（后者供 unsafe 边界使用）。

原书要点

标准函数族

方法 得到 消费外层？
as_ref() Option<&T> → &T 视图 ❌
as_mut() Option<&mut T> ❌
as_ptr() *const T ❌
as_mut_ptr() *mut T ❌ 
let mut opt = Some(String::from("x"));
if let Some(s) = opt.as_mut() {
    s.push('y');
}
let p: *const String = opt.as_ref().map(|s| s as *const _).unwrap_or(std::ptr::null());

典型类型

类型 常用 API
Option<T> as_ref / as_mut
Box<T> as_ref · as_mut · as_ptr
Vec<T> as_ptr / as_mut_ptr · as_slice
String as_ptr · as_bytes

与 Deref 区别

Deref 自动 as_ref 等
触发 方法解析时隐式 显式调用

2.3

.5 获取所有权

章索引：第 2 章 · 前：2.3.4-getting-references · 后：2.4-recap

一句话

当 T: !Copy 且不能把内部 T 用 = 移出 封装时，用 mem::take / mem::replace 或 Option::take — 通过 浅拷贝占位 + 移所有权 安全掏空容器。

原书要点

问题场景

// 不行：不能从 &mut Option<String> 里「复制出」String 又保留 Option
// let s = opt.unwrap(); // 消费整个 Option

需要：外层封装仍存在（或变为空状态），内层 T 归调用者所有。

take / replace

use std::mem;

let mut slot = Some(String::from("order"));
let owned = slot.take();           // slot → None, owned → Some(String)
let old = mem::replace(&mut slot, Some(String::from("new"))); // 返回旧值
API 行为
Option::take(&mut self) self → None，返回原 Option<T>
mem::take(&mut T) T: Default — 用默认值 替换 并返回旧值
mem::replace(&mut T, new) 放入 new，返回被替换掉的旧 T

「浅拷贝」含义（原书）

replace/take 不 deep clone T — 是 移动语义 交换槽位内容；对 String/Vec 是 指针所有权转移。

其它「移出」API（补充）

API 类型
Box::into_inner（nightly/部分类型） Box<T> → T
Mutex::into_inner 取得锁内 T（无 poison 时）

2.4

闭包与 `Iterator`：标准库中的落地

章索引：第 2 章 · 前：2.3 生命周期 · 后：2.5 模式匹配

一句话

Iterator trait + 闭包 撑起了标准库里绝大部分「遍历与变换」— for、map、filter、collect 是同一套零成本抽象的不同面孔。

Iterator 如何支撑迭代器设计

核心契约（简化）

2.5

模式匹配在 `std` 源码中的常用场景

章索引：第 2 章 · 前：2.4 闭包与 Iterator · 后：2.6 错误处理

一句话

标准库源码里 match / if let / while let 无处不在 — 用来处理 Option/Result、枚举状态机、I/O 返回值，是读 libstd 时第二常见的控制流（第一是 ?）。

高频场景

1. Option / Result 分支

// 典型：next()、read()、get()
match self.inner.next() {
    Some(item) => { ... }
    None => { ... }
}

// 等价简写
while let Some(x) = iter.next() { ... }
if let Ok(n) = parse::<i32>(s) { ... }

Vec、HashMap、io::Read 内部大量 「有值继续 / 无值结束」 结构。

2. 枚举状态机

类型 匹配什么
Poll<T> Ready vs Pending（async 底层）
ControlFlow 提前 break 遍历
Ordering Less / Equal / Greater 比较
IpAddr V4 vs V6 分支

3. match 解构 + 绑定

match entry {
    Occupied(mut o) => { ... o.get_mut() ... }
    Vacant(v) => { v.insert(value); }
}

HashMap::entry API 把 「存在 / 不存在」 变成 穷尽枚举，避免 TOCTOU。

4. 守卫与 @ 绑定

源码里偶见 match x { n if n > 0 => ..., _ => ... } — 复杂条件仍保持穷尽。

与 Book / RFR 衔接

  • 穷尽匹配保证 漏分支 = 编译错误 — std 用枚举表达 协议状态，减少非法组合。
  • if let 单分支 适合「只关心一种情况」— 如 if let Some(e) = err.source() 挖错误链 → RFR Ch04 错误链

→ Book 06 枚举与模式匹配

读源码习惯

见到 match on Result → 区分 可恢复错误（返回 Err）vs 不变量破坏（panic / unwrap 仅 invariant 路径）。

2.6

错误处理的标准库规范

章索引：第 2 章 · 前：2.5 模式匹配 · 后：2.7 泛型

一句话

std 把 可恢复失败 统一成 Result<T, E> + ? + Error::source() 链 — 与你在 RFR Ch04 学的分层错误设计同源，I/O 则固定用 io::Error。

标准库错误分层

调用方看到的业务 / 库 enum（上层，你的代码）
        │ ? / From
        ▼
std::io::Error / 其他官方 Error（底层）
        │ source()
        ▼
OS 错误码 / 自定义根因
层次 类型 典型场景
泛型结果 Result<T, E> 所有可恢复 API
I/O io::Error / io::Result<T> fs、net、Read
格式化 fmt::Error write! 失败（少见）
线程 JoinError join 时 panic
不可恢复 panic! / unwrap 编程错误、不变量破坏

规范要点（读 std / 写库时对齐）

  1. Result 表可恢复 — 文件不存在、连接重置 → Err；逻辑 bug → panic 或 debug_assert。
  2. E: Error + 'static — 库类型实现 Display + source()，便于日志与 anyhow 链。
  3. From 抬升 — io::Error → 你的 enum 变体，? 自动转换（thiserror 生成）。
  4. Option vs Result — 「没有值」不一定是错误（HashMap::get）；失败语义明确时用 Result。

read、write、flush 等层层 ? 传播 io::Error — 读模块时跟一条调用链即可看懂错误如何冒泡到用户 main。

2.7

泛型编程的标准库规范

章索引：第 2 章 · 前：2.6 错误处理

一句话

标准库是 泛型风格指南 — T 约束、impl Trait、关联类型、默认类型参数一起用，在 不付运行时多态代价 的前提下复用算法；读完本章可把零散语法 收成一套读码习惯。

常用泛型手法（std 示范）

手法 例子 目的
类型参数 T Vec<T>、Option<T> 同一结构多种元素类型
约束 T: Trait sort_by_key 要求 K: Ord 编译期验证能力
impl Trait 参数/返回 fn collect<B: FromIterator<A>>(self) -> B 简洁边界，单态化
关联类型 Iterator::Item 每个实现固定一项输出类型
默认类型参数 Result<T, E> 默认 E 各异 API 简洁
where 子句 复杂边界分行写 可读性

与零成本抽象的关系

  • 泛型函数 单态化 → 每种 T 一份机器码，常可内联。
  • dyn Trait 用于 运行时多态（如 fmt::Display 擦除、Box<dyn Error>）— 付 vtable 成本，std 只在需要类型擦除时用。

→ RFR Ch02 布局与 DST · 附录 · 设计哲学

写库 / 读库规范（对齐 std）

  1. 约束尽量紧 — 只要求 T: Clone，不要无谓 T: 'static。
  2. 优先 impl Trait 于返回位置，隐藏长类型（迭代器适配器链）。
  3. 用关联类型表达「一个实现一个输出」 — 如 Iterator::Item。
  4. From / Into 做构造弹性 — String::from("a")、Vec::from([1,2])。
