5.1

三种迭代器

章索引：第 5 章 · 后：5.2 · Iterator Trait

一句话

集合遍历的三种入口 into_iter / iter / iter_mut 分别对应 消费所有权、&T、&mut T — 由 IntoIterator 统一抽象，与 Rust 所有权/借用 规则一一绑定。

原书要点

方法 产出 所有权 迭代后容器
into_iter() IntoIter（按值） 转移 元素所有权 被消费（部分类型仍可用，如 Vec 变空）
iter() Iter<'_, T> &T 借用 容器 保留
iter_mut() IterMut<'_, T> &mut T 可变借用 容器 保留 · 可原地修改 
let v = vec![1, 2, 3];
for x in v.into_iter() { /* x: i32 */ }   // v 不可用
let v = vec![1, 2, 3];
for x in v.iter()       { /* x: &i32 */ }
for x in v.iter_mut()   { /* x: &mut i32 */ }

for 语法糖

for item in collection { body }
  ══►  IntoIterator::into_iter(collection)
       └── Iterator::next() 循环

选择原则

需求 选用
只读扫描 iter()
原地更新元素 iter_mut()
拆容器、移元素到新结构 into_iter()

5.2

Iterator Trait 分析

章索引：第 5 章 · 前：5.1 · 后：5.3 · collect

一句话

Iterator 的统一接口是 fn next(&mut self) -> Option<Self::Item> — 标准库在其上提供 fold/count/last/… 等大量 默认方法；Iterator + 闭包 + 适配器 构成 Rust 函数式编程底座。

原书要点

核心定义

pub trait Iterator {
    type Item;
    fn next(&mut self) -> Option<Self::Item>;
    // fold, map, filter, … 均为 default methods
}
要点 说明
Item 每次 next 产出的元素类型
None 迭代结束
惰性 适配器链在 next/collect/消费端 才真正执行

常用消费端（default methods）

方法 作用
fold 累积归约
count / sum / product 统计与算术
last / nth 按序取元素
all / any / find 谓词搜索
collect → 见 5.3

与闭包

map(|x| …)、filter(|x| …) 等接收 闭包 — 捕获环境、零成本抽象依赖 单态化 + 内联。

5.3

Iterator 与其他集合类型转换

章索引：第 5 章 · 前：5.2 · 后：5.4 · Range

一句话

collect() 将迭代器 聚合 为目标容器 — 底层依赖 FromIterator（及 Extend）；不同集合间 「遍历 → 重建」 因此极为方便（如 Vec → HashSet、过滤后新 Vec）。

原书要点

逆向转换（收集）

let v: Vec<i32> = (0..10).filter(|x| x % 2 == 0).collect();
let s: HashSet<_> = v.iter().cloned().collect();
Trait 角色
FromIterator<A> collect() 的目标类型须实现 — 从迭代器构造
Extend<A> 向已有集合 追加 迭代器元素
Iterator::collect 语法糖：FromIterator::from_iter(self)

类型推断

.collect::<Vec<_>>()   // turbofish 指定容器
let v: Vec<i32> = …    // 注解指定 Item 与容器

常见转换

源 目标 示例
Range Vec (0..n).collect()
Iter 新 Vec v.iter().map(f).collect()
键值对 iter HashMap map.into_iter().collect()

5.4

范围类型迭代器

章索引：第 5 章 · 前：5.3 · 后：5.5 · 切片

一句话

for i in 0..10 底层是 Range<T>: Iterator — 步进依赖 Step Trait（forward/backward 计算下一元素），与 4.3.4 · RangeBounds 衔接。

原书要点

语法 → 迭代

for i in 0..10 { … }   // Range<i32> implements Iterator
for i in 0..=9 { … }   // RangeInclusive — 单独 impl
类型 迭代方式
Range<T> start 每次 Step::forward 直到 end（左闭右开）
RangeInclusive<T> 含末端 · 用 bool exhausted 等 状态

Step Trait

方法 作用
steps_between 两值间步数（若可计算）
forward / backward 从当前值 安全 步进

实现 Step 的类型：整数、char 等 — 自定义类型需自行 impl 才能 a..b 迭代。

性能

无容器分配 · 寄存器级计数 — 热路径 for 常完全内联。

5.5

切片类型迭代器

章索引：第 5 章 · 前：5.4 · 后：5.6 · 字符串

一句话

切片 Iter / IterMut 用 两个裸指针（当前元素 + 尾后边界）实现 C 式指针步进 — 在 safe Rust 中封装，边界由 尾指针比较 保证，效率接近手写循环。

原书要点

结构（原书）

Iter<'a, T> {
  ptr: NonNull<T>,      // 当前元素
  end: NonNull<T>,      // one-past-last（尾后）
  _marker: PhantomData<&'a T>,
}
步骤 行为
next ptr == end → None；否则取 *ptr，ptr = ptr.add(1)
IterMut 同上 + &mut 别名规则由借用检查保证

设计要点

项 说明
双指针 避免维护 index + len 两次边界检查（可优化为单次比较）
NonNull 非空 invariant · 3.4 · NonNull
零分配 仅两个指针宽度的状态机

HFT

订单簿 深度档 [PriceLevel; N] 或 slice 扫描 — iter() 常编译为 与索引 for 等价的机器码。

源码锚点

位置 说明

5.6

字符串类型迭代器

章索引：第 5 章 · 前：5.5 · 后：5.7 · 数组

一句话

String/str 本质是 UTF-8 字节序列 — chars() 等迭代器在 [u8] 切片迭代 之上用 适配器模式 动态 解码 UTF-8 → char，每次 next 可能跨多个字节。

原书要点

层次

str / String  ──as_bytes()──►  [u8] 切片
                    │
                    ├── bytes()     ── 逐字节 Iter<u8>
                    ├── chars()     ── 解码 Unicode 标量 Chars
                    └── char_indices() ── (byte_offset, char)
迭代器 Item 注意
bytes() u8 快 · 非 Unicode 边界
chars() char 合法 UTF-8 假设下安全 · 无效 UTF-8 在 str 类型上不可构造
split/lines 子串 组合适配器

适配器模式（原书）

Chars 内部持有 &[u8] 剩余切片（或等价指针）— 每次读取 变长 UTF-8 码元序列 → char — 重用 切片遍历逻辑 + 上层解码。

易错

陷阱 说明
字节索引 ≠ 字符索引 s[i] 按 字节 · 勿用 chars().nth(i) 当 O(1)
len() vs chars().count() 字节长 vs 字符数

5.7

数组类型迭代器

章索引：第 5 章 · 前：5.6 · 后：5.7.1 · 按值

一句话

定长数组 [T; N] 的迭代分 按值移出 与 按引用借用 两条路径 — 按值迭代须防 panic 中途泄漏 / 双重释放，标准库 重度使用 MaybeUninit<T> 精细控制每槽位的初始化与 drop（3.2）。

原书要点

子节

节 主题
5.7.1 IntoIter — 逐个 move 元素
5.7.2 Iter / IterMut — &T / &mut T

为何数组按值迭代更复杂

[T; N] 在栈上连续存放 N 个 T
  ── into_iter 逐个 move 出元素
  ── 若第 k 个 move 后 panic：前 k-1 已 drop，后 N-k 未初始化？
  ── 解决方案：MaybeUninit 数组 + 手动 drop 剩余
切片 数组按值
元素已在堆/别处 元素 嵌入 数组本体
双指针即可 须 部分初始化 状态机

Iterator 适配器

章索引：第 5 章 · 前：5.7.2 · 后：5.8.1 · Map

一句话

Iterator 适配器（map/filter/chain/…）接收一个迭代器、返回新迭代器结构体 — 惰性求值，逻辑仅在 next/collect/消费端 执行；与 闭包 链式组合构成 Rust 函数式风格。

原书要点

惰性模型

iter.map(f).filter(p).take(3)
  │
  ├── 构建阶段：仅堆叠结构体，几乎无计算
  └── 消费阶段：每次 next 自外向内  pull 一层
对比 eager（如立即 Vec） lazy 适配器
内存 中间集合 无中间分配（理想情况）
短路 需手写 take/find 可早停

5.9

Option<T> 适配器

章索引：第 5 章 · 前：5.8.3 · 后：第 6 章

一句话

Option<T> 也可视为 0 或 1 个元素 的迭代器 — 标准库为其提供 iter/into_iter 及 transpose/flatten 等，使 Optional 值完美融入 map/and_then/链式函数式写法。

原书要点

作为迭代器

调用 等价长度 Item
None.iter() 0 —
Some(x).iter() 1 &T
Some(x).into_iter() 1 T 
let o = Some(42);
let sum: i32 = o.into_iter().map(|x| x + 1).sum(); // 43
// None.into_iter().sum() → 0（空迭代）

与 Iterator 互操作

API 作用
Iterator::flatten Iter<Item=Option<T>> → Iter<Item=T> 跳过 None
Iterator::collect::<Option<Vec<_>>> 短路与 transpose 思想相关
Option::transpose Option<Result<T,E>> ↔ Result<Option<T>,E>
Option::flatten Option<Option<T>> → Option<T>

↔ 4.2.3 · Option

设计意图

非集合类型  ──►  统一 Iterator 接口  ──►  同一套 map/chain/collect 思维

减少 match 嵌套 — 与 ? 互补（值层 vs 错误层）。
