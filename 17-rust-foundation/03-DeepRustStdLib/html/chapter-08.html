8.1

Box<T> 类型分析

章索引：第 8 章 · 后：8.2 · RawVec

一句话

Box<T> 是最基础的 堆上独占 智能指针 — Box::new 经 Global 分配器 申请固定大小堆块，Drop 自动 dealloc；Box::leak 主动放弃管理权，得到 'static 引用。

原书要点

定位

项 说明
用途 大对象上堆 · 递归类型（链表节点）· trait 对象（Box<dyn Trait>）
所有权 唯一 owner — 非 Rc/Arc
层 alloc crate · 依赖 3.7 · Global

构造与释放

Box::new(v)
  └── Global::allocate(Layout::new::<T>())
  └── 写入 T
Drop
  └── ptr::drop_in_place + Global::deallocate
对比 C/C++ Rust
释放 手动 free Drop 自动
GC 部分语言 无 GC · 确定性析构

↔ 3.5 · Unique — Box 逻辑上的独占堆基座

Box::leak（资源泄漏 · 有意为之）

let static_ref: &'static mut [u8] = Box::leak(vec![0; N].into_boxed_slice());
场景 说明
全局/static 初始化 程序全程存活
FFI 交出所有权 C 侧负责释放（须契约）
代价 永不 drop — 内存直到进程结束

图/树

Box<Node> — 单父单孩或单向边 · 独占 子树所有权。

RawVec<T> 类型分析

章索引：第 8 章 · 前：8.1 · 后：8.3 · Vec

一句话

RawVec<T> 是 Vec/VecDeque 的底层引擎 — 只管理 连续堆缓冲的 ptr + cap，不跟踪 len、不保证 槽位已初始化；扩容 grow_amortized 封装 realloc + 拷贝。

原书要点

职责边界

RawVec Vec
cap · ptr（NonNull/Unique） len + RawVec
申请/扩容/释放 容量 追踪 有效元素个数
MaybeUninit 语义 — 未用槽位可能未初始化 push 时才 write 初始化 
RawVec:  「这块堆上有 cap 个 T 大小的空间」
Vec:     「其中前 len 个是合法 T」

扩容 grow_amortized

步骤 说明
新 cap 通常 倍增 · 摊还 O(1) push
alloc 新块 Global / 自定义 Allocator
拷贝旧数据 ptr::copy / copy_nonoverlapping
释放旧块 旧 RawVec drop

↔ 6.5 · 切片 mem copy · 3.2 · MaybeUninit

设计拆分意义

容量管理 与 长度/初始化 分离 — VecDeque 复用 RawVec 模式 · 减少重复 unsafe 扩容逻辑。

8.3

.1 Vec<T> 基础分析

章索引：第 8 章 · 前：8.3 · 后：8.3.2 · Iterator

一句话

Vec 的 insert / remove / append 等需在缓冲区内 挪动元素 — 标准库用 unsafe + ptr::copy / copy_nonoverlapping 批量直拷，避免逐个 move + drop 的性能灾难。

原书要点

典型操作

API 底层直觉
push len 处 write · 可能 RawVec 扩容
insert(i, x) [i..len] 右移 一格 · 写入 x
remove(i) 取出 i · [i+1..] 左移
append 追加另一 Vec 全部元素 · 可能一次 memcpy

unsafe 直拷（原书 · 极致性能）

安全逐元素 move:  每步 drop 旧位 + 所有权链
copy_nonoverlapping:  整块内存 bitwise 复制（T 须 valid 且无重叠）
条件 std 内证明
索引合法 i <= len
不重叠 源/目标区间分离或算法保证
对外 用户只见 &mut Vec<T> safe API

↔ 6.5 · 切片排序

HFT

实践 说明
reserve(n) 订单批处理前一次分配
少 insert(0, …) 头插 O(n) · 用 VecDeque 或 ring

Rc<T> 类型分析

章索引：第 8 章 · 前：8.3.2 · 后：8.4.1 · 构造/析构

一句话

Rc<T>（Reference Counted）实现 单线程多 owner 共享堆对象 — 内部 RcBox<T> 含 data + strong/weak 双计数；纯 Rc 环 会泄漏 → Weak<T> 打破（8.4.2）。

原书要点

双计数器模型

RcBox<T> {
  strong: usize,   // Rc clone +1 · drop -1 → 0 则释放 data
  weak:   usize,   // Weak clone +1 · 不影响 data 存活
  value:  T,
}
指针 strong weak 持有 data?
Rc<T> +1 — 是
Weak<T> — +1 否（须 upgrade）

适用场景

适合 不适合
图/树 多入边 · 单线程 跨线程 → Arc
Rc<RefCell<T>> 多线程 mutate → Arc<Mutex<T>>

8.4

.1 Rc<T> 类型的构造函数及析构函数

章索引：第 8 章 · 前：8.4 · 后：8.4.2 · Weak

一句话

Rc::new 堆分配 RcBox { strong:1, weak:0, value } · clone 仅 strong+1（浅拷贝指针）· 最后一个 Rc drop 时 strong→0 → drop T + 释放 box（weak 仍可能存活）。

原书要点

构造

let a = Rc::new(data);  // strong = 1, weak = 0
let b = Rc::clone(&a);  // strong = 2, 同一块堆
操作 strong weak data
Rc::new 1 0 初始化
clone (Rc) +1 — —
drop 最后一个 Rc →0 — drop(T) + 释放（若无 weak 或 weak 亦清理）

析构链

strong 归零  ──►  drop value T
              ──►  若 weak 也为 0 → 释放 RcBox 壳
weak 最后归零 ──►  仅释放控制块（value 已不存在）

非线程安全

计数器为 普通 usize — 非原子 · 多线程 clone 数据竞争 → 须 Arc。

源码锚点

位置 说明

.2 Weak<T> 类型分析

章索引：第 8 章 · 前：8.4.1 · 后：8.4.3 · 其他函数

一句话

Weak<T> 只增 weak 计数、不增 strong — 打破 Rc 循环引用导致的 泄漏；使用前须 upgrade() → Option<Rc<T>> 判断 data 是否仍在。

原书要点

循环引用问题

A ──Rc──► B
B ──Rc──► A     strong 均 ≥1  →  永不 drop  →  泄漏（非悬垂，是占着堆）
解决 做法
弱边 一侧改为 Weak — 不阻止 strong 归零
树 父 Rc 子 · 子 Weak 父

Weak 语义

方法 行为
Rc::downgrade(&rc) 从 Rc 得 Weak · weak+1
weak.upgrade() strong>0 → Some(Rc) · 否则 None
Weak::clone weak+1 · 不 延长 data 寿命 
if let Some(rc) = weak_parent.upgrade() {
    // data 仍存活
} else {
    // 已被释放
}

与悬垂对比

问题 表现
悬垂指针 非法读 · Rust 编译期/类型系统防
Rc 环泄漏 内存合法但 永不回收 · Weak 防环

Arc<T> 类型分析

章索引：第 8 章 · 前：8.4.3 · 后：8.5.1 · 构造/析构

一句话

Arc<T>（Atomic Reference Counted）= Rc 的多线程版 — ArcInner 用 AtomicUsize 维护 strong/weak；API 与 Rc 几乎一致，但 Arc 只保证计数原子安全，不保证 T 内部并发安全。

原书要点

与 Rc 对比

Rc<T> Arc<T>
计数 usize AtomicUsize
线程 !Send 计数逻辑 · 单线程 clone/drop 计数线程安全
T 并发 单线程 assumed 仍须 Mutex/RwLock 等

原书安全边界（重要）

Arc<T>: Send + Sync  （在 T: Send + Sync 时自动）
  │
  ├── 保证的是：引用计数操作的线程安全
  └── 不保证：多个 &T 同时改 T 的内容

多线程可变 → Arc<Mutex<T>> / Arc<RwLock<T>> · 第 11 章
