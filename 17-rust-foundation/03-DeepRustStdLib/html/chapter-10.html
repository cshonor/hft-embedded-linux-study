10.1

匿名管道

章索引：第 10 章 · 后：10.2 · 重定向

一句话

匿名管道 = 父子/协作进程 IPC 的 单向字节流 — OS 提供一对 读/写 fd（或 Handle）；std 用 PipeReader/PipeWriter（或 AnonPipe → Stdio）做 RAII，是 10.2 重定向与 10.3 spawn 的 通信载体。

原书要点

本章逻辑链

10.1 匿名管道（IPC 载体）
  → 10.2 Stdio 把管道接到 fd 0/1/2
  → 10.3 Command 双层架构统一 spawn/wait

顶层安全入口 std::io::pipe()

pub fn pipe() -> Result<(PipeReader, PipeWriter)> {
    let (read, write) = imp::pipe()?; // imp = sys 平台适配
    Ok((PipeReader(read), PipeWriter(write)))
}
要点 说明
RAII 两端离开作用域自动 close，杜绝 fd/Handle 泄漏
半双工 读端阻塞等数据 · 写端满则阻塞
EOF 全部写端销毁后，读端 read 返回 0
与 Command Stdio::piped() 内部同样走 imp::pipe()

Unix 底层（sys/unix/pipe.rs，unsafe 集中）

pub fn pipe() -> io::Result<(AnonPipe, AnonPipe)> {
    let mut fds = [0; 2];
    unsafe {
        cvt(libc::pipe(fds.as_mut_ptr()))?; // 直接 libc，无 Rust 安全校验
    }
    let read = AnonPipe::from_raw_fd(fds[0]);
    let write = AnonPipe::from_raw_fd(fds[1]);
    Ok((read, write))
}

AnonPipe 关键方法：

方法 用途
read_fd() / write_fd() 取出裸 fd，供 spawn 前 dup2 / 继承
into_stdio() 转为 Stdio，挂到 Command.stdin/stdout/stderr

Windows 差异

Unix Windows
libc::pipe → 两个 fd CreatePipe → 两个 RawHandle
fd 号 + dup2 bInheritHandle 控制子进程继承

适配层统一为 AnonPipe，上层 pipe() / Stdio::piped() 零 cfg 分支。

与第 9 章衔接

管道本质是 特殊 IO 流 — 复用 9.5 · Read/Write + FD 所有权 · 9.4 · SYSCALL。

子进程跑 回放/风控脚本 · 管道传 控制命令（非热路径 tick 流）。

10.2

重定向实现分析

章索引：第 10 章 · 前：10.1 · 后：10.3 · 进程管理

一句话

重定向 = spawn 前把子进程 fd 0/1/2 换成 继承 / 管道 / 空设备 / 文件 — 上层 Stdio 枚举配置 Command，底层 sys 层 dup2（Unix）或句柄继承（Windows） 完成绑定；10.1 的管道经此接到 stdout/stdin。

原书要点

Stdio 上层接口

pub struct Stdio {
    inner: imp::Stdio, // 平台私有实现
}
impl Stdio {
    pub fn inherit() -> Self;           // 沿用父进程同 fd/句柄
    pub fn null() -> Self;              // /dev/null · NUL
    pub fn piped() -> Self;             // 自动 pipe()，父子通信
    pub fn from_file(file: File) -> Self;
}
变体 子进程效果
inherit() 与父进程 同 fd 号 / 句柄
piped() 新建管道 · 父持一端 · 子接 0 或 1/2
null() 丢弃 IO
文件 / 自定义 fd 指定路径或 OwnedFd

Command.spawn() 重定向链路（以 stdout(Stdio::piped()) 为例）

1. 配置阶段：底层 pipe() → 得 read_fd + write_fd
2. spawn 前：适配层 fd/句柄继承
     · 父进程保留 read 端 → 稍后 ChildStdout 读取
     · 子进程仅 write 端 → dup2 到 stdout (fd 1)
3. 子进程 exec/CreateProcess：输出写入管道
4. 父进程：child.stdout.take() → Read trait 读数据

Command::new("grep")
    .arg("ERROR")
    .stdin(Stdio::piped())
    .stdout(Stdio::inherit())
    .spawn()?;

shell 管道 vs Rust

shell:  cmd1 | cmd2
Rust:   cmd1.stdout(piped) + cmd2.stdin(piped from cmd1.stdout)

unsafe 风险点（原书底层重点）

机制 风险 / 标准库对策
FromRawFd / FromRawHandle 裸句柄 不受所有权管控 → trait 本身 unsafe · 调用者保证有效、不 double-free
Unix pre_exec 闭包 fork 后、exec 前 · 仅单线程 · 闭包 禁止持锁 / 堆分配 · std 限制捕获
Windows 句柄继承 须 bInheritHandle · 适配层内部设置 · 上层不可见
多余 pipe 端未关 父 ChildStdin/ChildStdout Drop · 子进程侧 spawn 逻辑 关闭未用端

10.4

高频 unsafe 源码走读（Unix / Windows 分块）

章索引：第 10 章 · 汇总：10.1 · 10.2 · 10.3.1

一句话

本章 所有 UB 风险 集中在 sys 层 — 下列片段为 对照 library/std 的精简注释版（非逐字拷贝），按 Unix → Windows 分块，便于刷书时并排打开源码。

Unix 分块

A. 创建匿名管道

// sys/unix/pipe.rs — 逻辑骨架
pub fn pipe() -> io::Result<(AnonPipe, AnonPipe)> {
    let mut fds = [0i32; 2];
    unsafe {
        // SAFETY: fds 指向合法栈数组；pipe(2) 写入两个有效 fd
        cvt(libc::pipe(fds.as_mut_ptr()))?;
    }
    // from_raw_fd: 接管内核返回的 fd 所有权
    Ok((
        AnonPipe::from_raw_fd(fds[0]),
        AnonPipe::from_raw_fd(fds[1]),
    ))
}

B. spawn 前 stdio → dup2（子进程视角）

// sys/unix/process — exec 前 fd 表 setup（概念代码）
fn setup_stdio(stdin: &imp::Stdio, stdout: &imp::Stdio, ...) -> io::Result<()> {
    // 若 stdout 为 piped：write_end 已通过 pipe() 创建
    if let Some(fd) = stdout.pipe_write_fd() {
        unsafe {
            // SAFETY: fd 为有效 open fd；1 为 stdout 标准号
            cvt(libc::dup2(fd, libc::STDOUT_FILENO))?;
        }
        // 关闭 dup2 后多余的原始 write fd（保留 fd 1）
    }
    // stdin / stderr 同理 → fd 0 / 2
    Ok(())
}

C. fork + pre_exec + exec

// 概念：父进程调 fork，子进程分支
match unsafe { libc::fork() } {
    -1 => return Err(io::Error::last_os_error()),
    0 => {
        // ── 子进程：从 fork 返回后仅单线程 ──
        setup_stdio(...)?;           // dup2、关多余 pipe 端
        pre_exec_closures.run()?;    // 用户 pre_exec：禁止锁/分配
        unsafe {
            libc::execvp(prog, argv); // 失败则 _exit
        }
        unreachable!();
    }
    child_pid => {
        // ── 父进程：关闭子侧 pipe 端，保留读端给 ChildStdout ──
        Ok(child_pid)
    }
}
约束 原因
pre_exec 无锁/无堆 fork 后 仅 async-signal-safe 函数安全
关「错端」pipe 否则 read 永不 EOF（经典 bug）

D. wait 回收

unsafe {
    // SAFETY: child_pid 为本进程 spawn 的有效 pid
    cvt(libc::waitpid(pid, &mut status, 0))?;
}
// status → ExitStatus（退出码 + 是否 signal）

Windows 分块

A. CreatePipe（无 Unix pipe syscall）

// sys/windows/pipe.rs — 逻辑骨架
pub fn pipe() -> io::Result<(AnonPipe, AnonPipe)> {
    let mut read = null_mut();
    let mut write = null_mut();
    unsafe {
        // SAFETY: 输出指针有效；SECURITY_ATTRIBUTES 设 bInheritHandle
        cvt(CreatePipe(&mut read, &mut write, &sa, 0))?;
    }
    Ok((
        AnonPipe::from_raw_handle(read),
        AnonPipe::from_raw_handle(write),
    ))
}

B. CreateProcess + 句柄继承

// 概念：STARTUPINFO 指定 hStdInput/hStdOutput/hStdError
let mut si: STARTUPINFOW = ...;
si.dwFlags |= STARTF_USESTDHANDLES;
si.hStdOutput = stdout_write_handle; // piped 时绑定管道写端
// bInheritHandles = TRUE 时子进程继承已标记可继承的 Handle

unsafe {
    CreateProcessW(
        app, cmd_line, ..., /* bInheritHandles */ TRUE, ..., &mut si, &mut pi,
    )?;
}
// 父进程 CloseHandle 子侧已复制的端，保留读端
WaitForSingleObject(pi.hProcess, INFINITE);
与 Unix 对照
无 fork 一次 CreateProcess 即新进程
Handle ≠ fd 号 dup2 等价物 由 STARTUPINFO 完成
继承标志 bInheritHandle · 适配层内部设置

上层 safe 边界（对照用）

// 开发者只写 safe API — unsafe 不泄漏
let mut child = Command::new("cat")
    .stdin(Stdio::piped())
    .stdout(Stdio::piped())
    .spawn()?; // 内部：imp::pipe + imp::spawn + fd/Handle 表
