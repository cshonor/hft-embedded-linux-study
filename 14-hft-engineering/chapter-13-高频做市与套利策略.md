## 1. 做市（Market Making）：赚价差，背库存

### 核心等式

```
做市 PnL = 成交量 × 价差（spread 收入）
          − 逆向选择损失（ adverse selection ）
          − 库存风险成本（ inventory risk ）
```

三者的取舍就是全部做市策略。

### 1.1 逆向选择：为什么成交太快不是好事

限价单排队，最愿意让你成交的时刻，往往是你最不该成交的时刻：

| 事件 | 你的单 | 结果 |
|------|--------|------|
| 新信息到达前（大单吃穿盘口） | 排队成交在旧价 | **买在天花板 / 卖在地板** |
| 无信息流（噪音单） | 正常轮流成交 | 赚价差 |

**对抗手段：**

- **报价偏斜（quote skew）**：库存偏多 → 买价下移、卖价上移——用不对称报价让市场帮你减仓
- **事件撤单**：检测到大单/盘口异动信号 → **在被打掉之前撤单**。这本质是**延迟竞赛**：`行情到达 → 判断 → 撤单指令到达交易所 < 对方吃单到达`
- **快市模式**：波动率突增 → 拉宽报价甚至单边停报（风控联动 → [chapter-11 §4](./chapter-11-风控合规与滑点控制.md#4-风控降级什么时候故意失效)）

### 1.2 库存风险管理（Avellaneda-Stoikov 直觉）

经典模型的工程直觉：**最优报价 = 公允价 ± (半价差 + 库存惩罚项)**

```
bid = mid − (γ/2)·σ²·(T−t) − δ·inventory     … inventory > 0 时 bid 更低
ask = mid + (γ/2)·σ²·(T−t) + δ·inventory
        ↑ 波动率越大，报价越宽（保护自己）
                          ↑ 持仓越多，越急着卖（偏斜）
```

| 参数 | 冷路径更新（每秒级） |
|------|---------------------|
| `σ`（波动率） | EWMA 估计，快市检测联动 |
| `inventory` | 热路径原子计数（→ [chapter-11 持仓上限](./chapter-11-风控合规与滑点控制.md)） |
| `γ`（风险厌恶） | 日内常数，风控下发 |

**注意**：模型计算全部在冷路径，热路径只执行「查表拿报价 ± tick」——和风控同一个模式（→ [chapter-11 §1 热路径预算](./chapter-11-风控合规与滑点控制.md#1-pre-trade-风控本地拒单链)）。

### 1.3 排队位置经济学

限价单成交概率取决于**队列位置**（→ [chapter-03 LOB](./chapter-03-订单簿深度与行情解析.md)）：

- 早到 = 排前 = 成交概率高 = 但逆向选择暴露也高
- **改单 = 撤到队尾**——改价 1 个 tick 的代价是整个队列位置，不是免费操作
- 工程含义：`撤单→改价→重报` 的整链延迟直接决定改单策略可行性——这就是把 T2T 当 KPI 的原因（→ [chapter-10 测量](./chapter-10-延迟测量与基准压测.md)）

## 2. 延迟套利（Latency Arbitrage）

### 2.1 原理：慢交易所上的陈旧报价

```
交易所 A（快，如期货/领先市场）  价格变动
        │
        │  你先看到（低延迟链路）
        ▼
交易所 B（慢，报价还停在旧价）→ 你吃掉 B 的陈旧报价 → B 跟随变动 → 你赚差价
```

本质：**你的信息到达速度 > B 上其他参与者的反应速度**。赚的是「B 的做市商来不及撤单」的钱——所以它是对手方的逆向选择损失（§1.1 的另一面）。

### 2.2 延迟决定可行性

| 环节 | 典型预算 |
|------|---------|
| A 行情到达你 | 链路 RTT（colo 内 ~μs 级，跨城取决于光速） |
| 判断（B 报价陈旧） | 本地热路径（→ T2T） |
| 订单到达 B | 链路 RTT |
| **窗口** | B 做市商撤单延迟（对手的 T2T） |

**你是赚是亏，取决于你的总延迟 vs 对手撤单延迟。** 这不是「快就好」，是「比对手快」——延迟优势的边际价值在对手也提速后归零，所以要持续投入（→ [chapter-15 FPGA](./chapter-15-fpga-与加密货币高频.md)：ns 级竞争的终点）。

### 2.3 跨所套利 vs 延迟套利

| | 延迟套利 | 跨所/跨品种套利 |
|---|---------|----------------|
| 持仓 | 瞬时（delta 中性对冲后 ~0） | 两腿同时持有 |
| 风险 | 腿风险（一腿成交一腿失败） | 价差收敛风险 + 腿风险 |
| 延迟敏感度 | 极高（核心资产） | 中（腿间滑点仍关键） |
| 关键工程 | T2T + 队列位置 | **双腿原子性**：A 成交则 B 必须发——腿管理状态机 |

**腿风险管理：** 第一腿成交、第二腿失败 = 裸敞口。工程上：第一腿回报到达（热路径）→ 立即补发/对冲第二腿，任何延迟都是风险敞口时间。这也是为什么订单回报处理必须在热路径。

## 3. 策略与工程的接口约定

策略代码跑在热路径上，但它不该做重活——**接口模式与风控/做市参数下发完全一致：**

```
冷路径（研究/参数计算/慢信号）          热路径（Strategy 线程）
────────────────────────────          ─────────────────────────
信号模型（毫秒级重算）    ──无锁环──→  读信号快照（一次 load）
做市参数（σ、γ、skew）   ──指针切换──→  读参数生成报价
风控限额                 ──指针切换──→  O(1) 检查（→ Ch11）
                                      决策 → OMS → Gateway OUT
```

**三条纪律：**

1. 策略热路径代码 **不查慢数据结构**（不遍历、不 hash 大表、不查数据库快照的深字段）
2. 信号/参数发布 **版本化**——replay 时才能还原当时策略用的参数（→ [chapter-12 capture/replay](./chapter-12-实盘上线与运维进阶.md#4-capture-replay复盘的基础)）
3. 策略 bug 的爆炸半径由 Ch11 风控硬检查兜底——**策略永远不可信，风控闸门独立存在**

## 本章小结

| 策略 | 收入来源 | 核心风险 | 最重要的工程能力 |
|------|---------|---------|-----------------|
| 做市 | 价差 | 逆向选择 + 库存 | 撤单延迟、队列位置、参数快照下发 |
| 延迟套利 | 对手的陈旧报价 | 延迟优势消失 | 端到端 T2T、colo 链路 |
| 跨所套利 | 价差收敛 | 腿风险 | 双腿状态机、回报热处理 |

**一句话：策略赚钱的上限由市场给，下限由工程决定——延迟、丢包、腿失败，每一个工程缺陷都直接换成亏损。**
