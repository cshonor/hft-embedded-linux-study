## 本章定位

风控不是热路径的**对立面**，而是热路径的**一部分**——区别在于：**检查逻辑在热路径内 O(1) 完成，参数更新在冷路径完成**。理解这个分工是本章的主线。

```
冷路径线程                          热路径（每个订单必过）
─────────────────────              ─────────────────────────────
风控参数计算/下发  ── 无锁环 ──→   ① 价格带检查（查表）
限频窗口重置                      ② 数量上限（比较）
合规规则加载                      ③ 持仓上限（读原子计数）
                                  ④ 累计撤单比（读原子计数）
                                  任一失败 → 本地拒单，不发 Gateway OUT
```

## 1. Pre-Trade 风控：本地拒单链

**原则：违规订单在本地杀死，绝不占用到交易所的 RTT。**

| 检查项 | 防的事故 | 热路径实现 |
|--------|----------|-----------|
| **价格带** | 乌龙指（fat finger）：错价单瞬间吃穿盘口 | 与参考价（最新成交/中间价）比较，带宽由冷路径下发 |
| **数量上限** | 单笔巨量单 | 单次 `if` 比较 |
| **持仓上限** | 累计敞口失控 | `_Atomic` 计数器读 + 比较 |
| **累计撤单率** | 监管指标（撤单/申报比） | 原子计数，冷线程定期清算 |
| **自成交预防** | 自己的单和自己成交（违规/操纵嫌疑） | 本地订单簿 hash 查重 |
| **流速限制** | 超过交易所 permit 速率被断连 | 令牌桶——冷路径补令牌，热路径只扣 |

**乌龙指案例（为什么价格带必须硬编码兜底）：** 光大 2013「乌龙指」——订单生成系统缺陷导致巨量市价单瞬间生成，234 亿元申报。教训：**策略层限单不可信，风控层必须有独立于策略的硬检查**——策略 bug 再大，风控这道闸是独立代码路径。

### 热路径预算

全部检查必须 **< 200ns**：

- 无系统调用、无锁、无 malloc
- 参数快照用 **seqlock 或 RCU 风格指针切换** 读（冷路径发布新参数 → 原子换指针 → 热路径一次 load）
- 失败路径同样要快——拒单回执也走无锁环给冷线程记日志

## 2. 滑点度量：执行质量的标尺

**滑点（slippage）= 实际成交价 − 决策基准价。** 关键是"基准"怎么选：

| 基准 | 定义 | 适用 |
|------|------|------|
| **Arrival Price** | 信号触发瞬间的中间价 | HFT 标准——衡量"决策到成交"的全部损耗 |
| **决策时盘口可成交价** | 触发时对手价（可吃单深度） | 衡量**排队延迟**损耗 |
| **VWAP / TWAP** | 时段成交量加权均价 | 低频大单执行 |

**Implementation Shortfall 分解：**

```
总滑点 = 信号延迟成本 + 排队成本 + 市场冲击 + 逆向选择
         ↑ 代码快不快    ↑ 在队首吗    ↑ 自己推动价格  ↑ 被人先跑
```

- **信号延迟成本**：决策用旧价格，成交时价格已变——**直接由 T2T 延迟决定**（→ [chapter-10 测量](./chapter-10-延迟测量与基准压测.md)）
- **排队成本**：限价单排在队尾，成交靠别人吃你——**队列位置 = 延迟的另一面**（→ [chapter-03 LOB](./chapter-03-订单簿深度与行情解析.md)）
- **逆向选择**：总是立刻成交的单，往往是你最不该成交的时候（adverse selection）

**工程含义：滑点是延迟的货币化度量。** 压测时别只看 p99 延迟，把延迟分布换算成"在波动率 σ 下的期望滑点"——这才能向老板解释为什么省 1μs 值得花 10 万。

## 3. 合规：审计日志与监管报送

| 要求 | 工程实现 |
|------|---------|
| **全订单生命周期留痕** | 每个状态转换（生成/发送/成交/撤销/拒单）打时间戳 + **单调钟**（`CLOCK_MONOTONIC`，禁用墙钟排序） |
| **日志不可抵赖** | 冷路径消费无锁环 → 追加写（append-only）+ 定期归档校验和 |
| **时钟同步** | PTP 对时（→ [chapter-06 §PTP](./chapter-06-低延迟网络与协议优化.md)）——监管要求订单时间戳误差 ≤ 100μs（MiFID II 类要求） |
| **可重放** | capture/replay（→ [chapter-12](./chapter-12-实盘上线与运维进阶.md)） |
| **熔断合规** | 交易所断连/限速 → 自动降频而不是硬扛被禁 |

**审计日志 ≠ 调试日志：** 审计日志是**结构化定长二进制记录**（每条 ~64B，冷线程落盘），调试日志才允许格式化字符串。两者分开，别混在一个 logger 里。

## 4. 风控降级：什么时候故意失效

风控不是越严越好——**极端行情下过严的风控 = 无法平仓 = 更大的风险**：

| 场景 | 动作 |
|------|------|
| 行情中断 | 冻结价格带基准（用最后有效价 + 放宽带宽），不自动撤掉全部报价 |
| 需要紧急清仓 | 持仓上限检查让位于**清仓模式**（预置开关，双人授权） |
| 风控服务超时 | **fail-open 还是 fail-close 由策略地位决定**：做市策略 fail-close（停报），套利腿 fail-close（两腿都停） |

**Kill Switch 分级** → [chapter-12 §3](./chapter-12-实盘上线与运维进阶.md#3-kill-switch-分级)
