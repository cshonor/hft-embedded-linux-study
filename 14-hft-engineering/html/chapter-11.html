本章定位

回测赚钱 ≠ 实盘赚钱——中间隔着运维。HFT 系统的运维本质：在故障发生前看到它，在事故扩大前杀掉它。三大支柱：上线门禁（不达标不上）、监控（看得见）、降级（坏得可控）。

本章小结

目标 手段
不上有病的系统 上线门禁清单，一项不过不上
故障可见 分层监控 + 静默失败检测 + 独立报警通道
坏得可控 Kill Switch 四级 + watchdog 独立于策略进程
出事可查 Capture/Replay + 确定性时间戳驱动
死了有备 双机热备 + 升主前强制对账

11.2

监控：看什么、怎么报警

最危险的故障是没有报错的失败 — 静默失败检测

← 上一节：11.1 上线门禁清单 · 下一节：11.3 Kill Switch 分级

监控分层

层 指标 采集方式（不能干扰热路径）
系统层 CPU 占用（独占核应 ~100%）、软中断、网卡丢包（ethtool -S）、RSS/缺页 冷核上的 agent（node_exporter 等）
进程层 心跳（每 N ms 写一个序列号）、线程存活、fd 泄漏 共享内存心跳序列，冷线程检查
业务层 行情流断续（gap 计数）、订单回报延迟、成交率、持仓 热路径原子计数器 → 冷路径读
延迟层 T2T 分段打点（→ chapter-09） 硬件时间戳优先

报警哲学

  • 报症状不报原因：「行情 gap > 3」而不是「网卡驱动可能丢包」——症状可执行（立即降级），原因留给排查
  • 分级：P1（自动 kill switch）资金风险 / P2（人工介入）性能退化 / P3（记录）统计异常
  • 报警本身要冗余：报警通道挂了要有第二通道（交易机 → 手机短信直连）

关键盲区：静默失败

最危险的故障是没有报错的失败——行情流还在但内容是旧的（TCP 半开）、订单发了但回报永远不来。对策：每个流都带单调递增序列号 + 期望速率，冷线程检测「太安静」本身。

11.3

Kill Switch 分级 🔴

L1 停新单 → L2 全撤 → L3 清仓 → L4 断链 — 全系统唯一允许「丑但稳」的模块

← 上一节：11.2 监控与报警 · 下一节：11.4 Capture 与 Replay

级别 触发 动作 恢复
L1 停新单 延迟尖峰 / 策略异常 停止发新订单，存量单保留 人工确认后重启
L2 全撤 风控越限 / 行情中断 撤掉全部挂单 人工
L3 清仓 重大事故（账户/合规/系统不可控） 撤单 + 市价平掉全部持仓 双人授权
L4 断链 最后手段（连撤单都发不出去） 主动断开交易所连接，靠交易所侧超时撤单 交易所流程

工程要点

  • Kill switch 代码路径要最简单、最老、测试最充分——它是全系统唯一允许「丑但稳」的模块
  • 触发通道独立于策略进程：watchdog 进程持有关联交易进程的权限（SIGUSR/共享内存标志位），策略挂死也能触发 L1/L2
  • 演练：上线前每级真实触发一次，包括「热路径线程死循环时 L2 能否生效」

11.4

Capture / Replay：复盘的基础

回测 = 假设的行情；replay = 真实发生过的自己

← 上一节：11.3 Kill Switch 分级 · 下一节：11.5 故障降级矩阵

实盘:  行情/信号/订单/回报 ──→ 定长二进制记录 ──→ 冷线程落盘 (与审计流分开)
复盘:  读记录 ──→ 按时间戳重放行情 ──→ 策略离线跑 ──→ diff 实盘决策
要点 说明
确定性 策略逻辑必须是时间戳驱动（不用墙钟、不用随机数种子未固定）——否则 replay 结果对不上
全覆盖 不只录行情——内部信号、风控参数变更也要录，否则复盘缺上下文
与回测的区别 回测 = 假设的行情；replay = 真实发生过的自己——排查「为什么当时发了这单」的唯一手段
体积管理 定长记录 + lz4 压缩 + 按交易日分片，冷路径异步写

11.5

故障降级矩阵与双机热备

脑裂比宕机更危险 — 升主前必须先对账

← 上一节：11.4 Capture 与 Replay · 下一节：11.6 运维日常

故障降级矩阵

故障 自动动作 人工动作
行情流中断 L1（价格带基准冻结，不撤存量单） 判断是上游断还是本地断
订单回报超时 L1 + 报警 查订单状态（交易所 API 查询）
热路径线程 CPU 异常 延迟监控报警 决定 L2 还是观察
内存泄漏 RSS 告警 计划内重启（低风险时段，先 L2）
整机宕机 备机心跳接管（见下） 事后复盘

灾备双机模式

主机: 交易进程（主用）      备机: 交易进程（standby, 只监听不交易）
       │                          │
       └──── 心跳共享/专线 ────────┘
主机心跳消失 N ms → 备机升主（先查交易所未成交单 → 撤 → 再启策略）

注意： 备机升主前必须先对账（拉取交易所订单状态）——否则重复报单。脑裂（两边都以为自己是主）比宕机更危险，心跳判断要留给第三方仲裁（交易所网关连接状态）。

11.6

运维日常

清单不是写完的，是事故喂出来的

← 上一节：11.5 故障降级矩阵 · 返回：本章索引

  • 变更纪律：交易日不改代码不调参；变更走灰度（新版本先跑单进程 shadow 模式——收行情发假单，对比决策）
  • 日志巡检：每日开盘前检查前日 P3 统计异常、捕获文件完整性
  • 容量演练：季度性演练 L3 清仓 + 备机切换（用小仓位真做，不是纸面推演）
  • 复盘文化：每次 P1/P2 事件产出「时间线 + 根因 + 清单项补充」——清单不是写完的，是事故喂出来的
