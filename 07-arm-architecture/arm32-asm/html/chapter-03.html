3.2

section-3.2-arm-thumb-compare

Ch 3 · 指令集简介 · 章导读

三种指令集形态

指令集 宽度 典型平台 特点
ARM 32 bit ARM7TDMI（v4T） 全功能 32 bit 运算；代码体积较大
Thumb 16 bit v4T 的 Thumb 状态 ARM 的子集；代码密度高，仍处理 32 bit 数据
Thumb-2 16 + 32 bit 混合 Cortex-M4 等 v7-M 超集 — 密度与性能兼顾；M 系只执行 Thumb-2 
代码密度：Thumb/Thumb-2  >  纯 ARM
表达能力：Thumb-2  ≈  ARM + 更多 16/32 混合编码
Cortex-M4：不再切 ARM 状态 — 向量表地址 LSB=1（Ch2）

为什么要有 Thumb

  • 嵌入式 Flash/RAM 有限 — 16 bit 指令多 → 同样功能占更少字节。
  • 仍用 32 bit 寄存器 — 不是退化成 8 bit MCU；只是编码更短。
  • 状态切换（ARM7 时代） — BX 等切换 ARM/Thumb（→ Ch17）；M 系无此烦恼。

Thumb-2 与本书实验

读者路径 重点
ARM7TDMI 示例 可见 32 bit ARM 指令 + 条件后缀 EQ/GT 等于后缀
Cortex-M4 示例 Thumb-2 + IT 块 代替部分条件后缀习惯
AArch64（奔跑吧） 固定 32 bit A64 — 另一套助记符，Load/Store 思想相同

与 x86 / CSAPP 对照

x86-64 ARM v4T / v7-M
指令长度 变长 1–15 字节 ARM 32 固定；Thumb 16/32
条件执行 几乎总是 分支 ARM 模式可 条件后缀；M 用 IT
代码密度 相对低 Thumb 系更高

可复述要点

  1. ARM=32b，Thumb=16b 子集，Thumb-2=16/32 超集。
  2. Cortex-M4 只跑 Thumb-2 — 本书 MCU 实验默认这一支。
  3. 选指令集 = 在 Flash 占用 vs 单条表达能力 间权衡；M 系已替你选好 Thumb-2。

section-3.3-example-shift

Ch 3 · 指令集简介 · 章导读

本程序学什么

目标 内容
汇编程序骨架 段/入口/结束 — 第一次见完整 .s 结构
常数进寄存器 MOV 加载立即数
移位 LSL 逻辑左移 — 等价于 ×2ⁿ

典型程序框架（Keil/ARM 语法风格）

        AREA    Prog1, CODE, READONLY   ; 命名代码段
        ENTRY                           ; 告诉链接器入口符号
start
        MOV     r0, #5                  ; r0 ← 5
        MOV     r1, r0, LSL #2          ; r1 ← r0 << 2  (= 20)
        ; ...
        END                             ; 源文件结束
伪指令 作用 详述
AREA 定义代码/数据块名与属性 → Ch4
ENTRY 指定程序入口标签 链接器设 Reset/启动 PC
END 源文件结束 不再汇编其后内容

GNU 对照： .section .text · .global _start · 无 END — 语法不同，角色相同。

核心指令 · MOV 详解

指令 含义 备注
MOV Rd, Op2 复制到寄存器（不做算术） 源 = 寄存器或合法立即数
LSL Logical Shift Left 低位补 0；可写 MOV r1, r0, LSL #n

MOV — 数据传送（核心）

        MOV     Rd, Operand2    ; Rd ← Op2（纯搬运，不运算）
Rd 目标寄存器
Op2 源：另一寄存器，或 可编码立即数；也可带移位：MOV r1, r0, LSL #2

基础示例：

        MOV     r0, #5          ; r0 = 5
        MOV     r1, r0          ; r1 = r0（寄存器拷贝）
        MOV     r2, #0          ; 清零常用（亦常见 EOR r2,r2,r2）

与阶乘联动（→ §3.4）：

        MOV     r1, #1          ; 累乘初值
        MOV     r0, #6          ; 算 6!
loop
        CMP     r0, #1
        MULGT   r1, r1, r0
        SUBGT   r0, r0, #1
        BGT     loop

限制（ARM32 / Thumb）

点 说明
立即数 经典 ARM：#imm 须落在 8 bit + 偶数旋转 可编码集合（不是「任意 32 位数」）
大常数 MOVW/MOVT 拼 32 位，或 LDR Rd, =const（→ Ch6）
不能碰内存 内存 → 寄存器用 LDR；寄存器 → 内存用 STR。MOV 只管寄存器↔立即数/寄存器
条件后缀 ARM32：MOVGT / MOVEQ…（M4 放 IT 块） 
        CMP     r0, #1
        MOVGT   r2, r0          ; 仅 r0>1 时拷贝

MOV vs LDR vs STR

指令 方向
MOV 立即数/寄存器 → 寄存器
LDR 内存 → 寄存器（加载）
STR 寄存器 → 内存（存储）

口诀： MOV 做「寄存器桌面上的搬运」；过内存必须 LDR/STR。

Ch7： MOVS 可刷 N/Z；移位还有 LSR、ASR、ROR。

调试习惯

  • 单步后看 r0、r1 — 验证 5 → 20。
  • 对照 Ch2 §2.3：PC 递增、寄存器即状态。

可复述要点

  1. 汇编程序 = 段声明 + 入口标签 + 指令序列 + END。
  2. MOV + 移位 是第一批「不用访存就算数」的工具。
  3. 伪指令是 给汇编器看的 — 不一定对应一条机器指令。

section-3.4-example-factorial

Ch 3 · 指令集简介 · 章导读

本程序学什么

目标 内容
循环 递减计数直到条件满足
比较与标志 CMP 设置 N/Z/C/V
条件执行 ARM7：MULGT/SUBGT 等 · M4：IT 块

算法：n! = n × (n−1) × … × 1，或累乘循环。

CMP 与标志位

        CMP     r0, #1          ; 伪：r0 - 1，只改标志不改 r0
        ; r0 == 1 → Z=1（EQ）
        ; r0 >  1 → GT（有符号）
        ; r0 <  1 → LT
标志 阶乘里常见用途
Z 是否减到 / 等于 1（结束）
N / V 有符号 GT/LT
C 无符号比较（本例多用有符号 GT）

CMP ≠ SUB： SUB 改 r0；CMP 只刷标志。系统展开 → Ch7 §7.3

与循环搭配：

loop
        CMP     r0, #1
        MULGT   r1, r1, r0
        SUBGT   r0, r0, #1
        BGT     loop

ARM7TDMI：条件后缀 · MULGT / SUBGT

ARM 32-bit 模式几乎所有通用指令可加 条件后缀：

指令助记符 + 条件码
例：MUL + GT → MULGT · SUB + GT → SUBGT · B + GT → BGT
条件成立 执行该指令（写寄存器 / 跳转）
不成立 当作 NOP — 不运算、不改任何寄存器

条件读的是 当前 CPSR 的 N/Z/C/V（通常刚被前面的 CMP / SUBS / ADDS 等更新）。

GT 含义
GT Greater Than — 有符号大于
标志条件 Z=0 且 N == V
CMP 后语义 若刚做了 CMP Rn, Op2 → Rn > Op2（有符号）

SUBGT

        CMP     r0, #1
        SUBGT   r0, r0, #1      ; 仅 r0>1 时：r0 = r0 − 1
  • 基础：SUB Rd, Rn, Op2
  • SUBGT：满足 GT 才减；r0==1 或 r0<1 时本条作废

MULGT

        CMP     r0, #1
        MULGT   r1, r1, r0      ; 仅 r0>1 时：r1 = r1 × r0
  • 基础：MUL Rd, Rm, Rs → Rd = Rm × Rs
  • MULGT：不是新指令，只是 带 GT 的 MUL

阶乘整段串起来

        MOV     r0, #5          ; 算 5!
        MOV     r1, #1          ; 乘积初值
loop
        CMP     r0, #1          ; 刷标志
        MULGT   r1, r1, r0      ; r0>1 才乘
        SUBGT   r0, r0, #1      ; r0>1 才减
        BGT     loop            ; r0>1 才跳回
; 结束时 r1 = 120
阶段 行为
r0=5…2 CMP → GT 成立 → MUL/SUB/B 全执行
r0=1 CMP 后 不满足 GT → MULGT/SUBGT/BGT 全作废 → 循环结束

常用条件后缀（背）

后缀 含义
EQ 相等（Z=1）
NE 不等（Z=0）
GT / GE 有符号 > / ≥
LT / LE 有符号 < / ≤
AL 永远执行（默认；不加后缀 = AL）

核心三点

  1. 后缀看的是 已有标志（多来自上一条 CMP 等），不是指令自己比
  2. MULGT / SUBGT = 条件版 MUL / SUB，不是新 opcode 族
  3. 条件假 → 零副作用

优势： 短 if 少分支 → 少冲刷流水线（经典 ARM 卖点）。
系统化 → Ch8 §8.4

Cortex-M4：IT 块 (IF-THEN)

Thumb-2 没有 所有指令都带条件后缀；用 IT 修饰后续 1–4 条：

        CMP     r0, #1
        IT      GT
        MULGT   r1, r1, r0      ; IT 块内条件执行
        SUBGT   r0, r0, #1
要点 说明
IT 掩码 ITTE EQ 等指定后续几条是否条件执行
块内指令 必须带与 IT 一致的条件后缀
密度 替代 ARM 模式整条指令条件位

易错： IT 块中间不能插入无关指令；调试时 单步看清 IT 掩码。

与 C 对照

while (n > 1) {
    result *= n;
    n--;
}

编译器生成 CMP + 条件分支；ARM 条件后缀/IT 是 把分支折叠进指令 的手写优化（现代 C 编译器也会选 B.cond）。

可复述要点

  1. CMP 只改标志 — 比较的两操作数之一常用立即数。
  2. ARM7：指令后缀条件执行；M4：IT 块 包装 Thumb 指令。
  3. 阶乘 = 循环 + 比较 + 乘法 — Ch3 第一个「小算法」。

section-3.5-example-register-swap

Ch 3 · 指令集简介 · 章导读

本程序学什么

目标 内容
无临时寄存器交换 三次 EOR 互换 rA、rB
大立即数 LDR rd, =constant 伪指令

XOR 交换技巧

        EOR     r0, r0, r1      ; r0 ^= r1
        EOR     r1, r0, r1      ; r1 ^= r0  (原 r0)
        EOR     r0, r0, r1      ; r0 ^= r1  (完成交换)
性质 说明
无需 r2 / 内存 省寄存器 — 极端 constrained 时有用
前提 r0、r1 不是同一物理寄存器；且地址 distinct
现代实践 寄存器够用时 MOV + 临时寄存器 更清晰 — 编译器常如此

Ch7： EOR 也是通用按位逻辑；与 AND/ORR/BIC 同族。

LDR = 大常数 伪指令

        LDR     r2, =0x12345678   ; 汇编器展开为 MOVW/MOVT 或 literal pool
MOV #imm LDR rd, =expr
范围 小立即数（8 bit 旋转等） 任意 32 bit 常数/地址
实现 单条（若可编码） 可能 PC 相对 load 文字池（→ Ch6）

驱动/MMIO： 外设基址 0x40000000 类常数几乎总是 LDR = 或 MOVW/MOVT。

可复述要点

  1. 三次 XOR 可交换两寄存器 — 面试/习题经典。
  2. LDR rd,=imm 是伪指令，汇编器负责展开。
  3. 可读性优先时，用临时寄存器交换 往往更好。

section-3.6-example-float

Ch 3 · 指令集简介 · 章导读
标签： 选做 — 嵌入式 Linux 主线可跳过（见 OUTLINE Ch9–11）

本程序学什么

目标 内容
启用 FPU 写 CPACR 打开 CP10/CP11
浮点寄存器 s0–s31 单精度
基础浮点指令 VMOV.F · VADD.F

硬件： Cortex-M4F（带 F 后缀）；无 FPU 的 M4 不应跑本例。

激活 FPU — CPACR

协处理器访问控制寄存器 CPACR（0xE000ED88 附近，系统控制空间）：

开启 CP10、CP11 的 Full Access
        ↓
否则 VFP 指令触发 UsageFault / Undefined

Ch2 回顾： 写系统寄存器需 特权 Handler/Thread privileged。

Ch9 详述： FPSCR、浮点异常、舍入模式。

单精度与指令

指令 作用
VMOV.F32 Sd, #imm 浮点立即数/寄存器移动
VADD.F32 Sd, Sn, Sm 单精度加法

格式： IEEE 754 32 bit — Ch1 §1.5 已建直觉。

与嵌入式 Linux 路径

MCU 本书 (M4F) 应用处理器 (Cortex-A + Linux)
手写 VADD.F 浮点多在 C/NEON；内核 kernel_fpu_begin()
CPACR 使能 用户态 硬件 FP lazy context

飞控姿态：23 章 用 C + libm/NEON 更常见；本程序建立「FPU 存在且需使能」直觉即可。

可复述要点

  1. M4F 用前必须配置 CPACR 打开 CP10/11。
  2. 浮点寄存器 s0–s31 与 r0–r12 分离。
  3. 主线可 跳过 §3.6–3.7，不影响 Load/Store/中断学习。

section-3.7-example-int-float-xfer

Ch 3 · 指令集简介 · 章导读
标签： 选做 — 同 §3.6，FPU 路线

本程序学什么

目标 内容
整 ↔ 浮 搬运 通用寄存器与 s 寄存器之间传比特模式
浮点常数加载 VLDR.F 从内存加载（如阿伏伽德罗常数）

VMOV 在整数与浮点间

        VMOV    S0, R0          ; 将 r0 的位模式拷到 s0（reinterpret）
        VMOV    R0, S0          ; 反向
注意 说明
不是类型转换 多数形式是 位拷贝；VCVT 才是 int↔float 转换（Ch9）
ABI 函数返回值 float 在 s0/r0 等约定 — Ch13 APCS / AAPCS

VLDR.F — 加载浮点常数

        VLDR    S1, =6.022e23   ; 伪：从 literal pool 加载 32-bit float 编码
VMOV.F #imm VLDR.F
常数大小 有限编码范围 任意单精度（经内存池）
类比整数 MOV #small LDR =big（§3.5）

Ch6 文字池： 整数与浮点 literal pool 机制相同 — PC 相对取常数。

五程序递进关系

§3.3 MOV/LSL     → 整数基础
§3.4 CMP/循环    → 控制流
§3.5 EOR/LDR=    → 逻辑 + 大常数
§3.6 CPACR/VADD  → 启用 FPU + 运算
§3.7 VMOV/VLDR   → 两套寄存器文件协作

可复述要点

作者强调的两条习惯

1. 复杂逻辑先画流程图

为什么 说明
汇编 无结构化语法 没有 if/for 块，只有标签与分支
先算法后指令 流程图 → 基本块 → 标签名/B/BL
与 Ch8 衔接 循环结构（While/For/Do-While）在 Ch8 系统化

HFT 对照： 热路径手写汇编前同样先 控制流图 — 与 14 HFT 优化流程一致。

2. 高度重视初始化

对象 风险
通用寄存器 复位后 未定义 — 第一次使用前 MOV #0 或已知值
RAM 变量 .bss 未清零若链接脚本遗漏 → 随机初值
内存映射外设寄存器 复位后位域可能 随机/上电默认值 — 直接读改写可能 锁死硬件（→ Ch16 MMIO）

典型启动序列：

设置 SP（向量表/启动代码）
    ↓
清零 BSS / 拷贝 DATA（C 运行时）
    ↓
初始化时钟/GPIO 等外设
    ↓
进入 main 或主循环

Linux 内核/U-Boot： 同样 early init — 时钟、DRAM、串口；概念与 MCU reset handler 平行（→ 20 构建）。

习惯 来源

可复述要点

  2. 寄存器、变量、外设 使用前必须有 已知初态。
  3. uninitialized MMIO = 驱动里 最难查的 bug 之一。
