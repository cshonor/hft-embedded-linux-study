8.2

section-8.2-branches

Ch 8 · 分支与循环 · 章导读

流水线与分支代价

取指 → 译码 → 执行 …
         ↑
    分支改 PC → 前面已预取的指令作废（pipeline flush / bubble）

软件 必须用分支实现 if/loop；优化 = 少分支、可预测分支、用条件执行代替短分支。

ARM7TDMI（v4T · ARM/Thumb 状态）

指令 作用
B label 直接跳转；范围约 ±32MB（ARM 模式）
B{cond} label 条件分支 — 读 CPSR N,Z,C,V（→ Ch7 §7.2）
BX Rm 间接跳转；Rm 的 LSB 决定 ARM/Thumb 状态（→ Ch17）
BL label Branch with Link — LR ← 返回地址，跳子程序（→ Ch13）
BL{cond} 条件调用

返回： BX lr 或 MOV pc, lr（模式相关）。

Cortex-M4（v7-M · Thumb-2 only）

指令 作用
B / B{cond} 32 bit 分支约 ±16MB
BX / BLX Rm 间接跳；BLX = 带链接的间接分支
BL 调用；返回地址在 LR，异常时 LR 为 EXC_RETURN（Ch2）

无 ARM 32 bit 状态 — BX 的 LSB 仍标记 Thumb，但始终 Thumb-2。

CBZ / CBNZ — M 系循环优化

        CBZ     r0, done          ; if r0==0 → done（不改 APSR）
        CBNZ    r1, loop_top      ; if r1!=0 → loop_top
属性 说明
范围 短跳 约 4–130 字节（向前/向后）
寄存器 仅 r0–r7
标志 不更新 N,Z,C,V — 与后续 CMP 独立
限制 不能在 IT 块内 使用

用途： 紧凑 inner loop 测试 — 省一条 CMP+BEQ。

常见条件后缀（与 CMP 配对）

组 后缀 何时用
相等 EQ / NE Z=1 / Z=0
有符号 GT / GE / LT / LE 可负整数比较
无符号 HI / HS / LO / LS 地址、长度、size_t

日常背三个： EQ / GT / LT（有符号）。完整口述表 → Ch7 §7.2。

Ch3 阶乘 已用 GT / IT。

可复述要点

  1. BL 调子程序写 LR；BX/BLX 间接跳。
  2. 条件分支 = B + 条件码，消费 Ch7 标志。
  3. CBZ/CBNZ = 短跳、不改标志、仅 r0–r7、禁 IT 块内。
8.3

section-8.3-loops

Ch 8 · 分支与循环 · 章导读

While — 先判条件

while (cond) { body; }

        B       exit_when_false    ; 或先 CMP + B{cond} 到 exit
loop
        ; body
        CMP     r0, #limit
        BLT     loop               ; 仍满足则继续
exit_when_false

模式： 入口比较 → 不满足 跳过整个循环 → 体 → 尾部比较跳回。

For — 向下计数（书中推荐）

for (i = n; i != 0; i--) { body; }

        MOV     r1, #n
loop
        ; body
        SUBS    r1, r1, #1        ; 减 1 且更新 Z
        BNE     loop              ; Z=0? 否 → 继续
为何向下计数 说明
SUBS + BNE 一条减法带标志 — 省单独 CMP r1,#0
代码更小更快 For 热循环常用 idiom
向上计数 需 ADDS+CMP 上限或 SUBS 算剩余

Ch3 阶乘 即 递减 + 条件 变体 — 本章给出 通用 For 模板。

Do-While — 至少执行一次

do { body; } while (cond);

loop
        ; body
        CMP     r0, #0
        BNE     loop              ; 条件真则回顶

用途： 读硬件直到 ready、至少读一次 FIFO 等。

与 C 编译器

现代编译器对 已知次数小循环 也会 向下计数 或 完全展开（§8.5）。读反汇编时认 SUBS; BNE 模式。

可复述要点

  1. While = 前测 + 体 + 回跳。
  2. For 汇编优选 SUBS 向下 + BNE — 少一条 CMP。
  3. Do-While = 体在前、条件在后。
8.4

section-8.4-conditional

Ch 8 · 分支与循环 · 章导读

动机：少分支，少 flush

条件执行： 指令 进入流水线，条件不满足时 当作 NOP 执行（不写寄存器/不改内存）— 避免 B 跳过 整条指令槽。

适合 短 if 分支（1–4 条）— 长分支仍用 B。

v4T / ARM7 — 指令条件后缀

32 bit ARM 指令 高 4 bit = 条件码（默认 AL=Always）：

        CMP     r0, r1
        SUBGT   r2, r2, #1        ; 仅 GT 时 r2--
        ADDLE   r3, r3, #1        ; 仅 LE 时 r3++
        STRNE   r0, [r4]          ; 仅 NE 时存
优点 限制
单条指令粒度条件化 Thumb 16 bit 多数无条件
历史 ARM 性能亮点 M 系主用 Thumb-2 + IT

Ch3 阶乘 ARM 版： MULGT / SUBGT — 下面展开 GT 规则。

深挖：MULGT / SUBGT（阶乘用的那对）

指令 = 假时
MULGT Rd, Rm, Rs 仅 有符号 > 时 Rd = Rm×Rs 不乘、不写 Rd
SUBGT Rd, Rn, Op2 仅 GT 时做减法 不减、不写 Rd
BGT label 仅 GT 时跳转 顺序下一条

GT 标志条件： Z==0 && N==V（CMP a,b 后 ≈ 有符号 a > b）。

        CMP     r0, #1
        MULGT   r1, r1, r0
        SUBGT   r0, r0, #1
        BGT     loop
; r0==1 时三条全“空过”，循环自然结束

勿混： M4 / Thumb-2 不能 像 ARM32 那样每条指令随意加后缀 — 须包在 IT 块里（下节）。

v7-M — IT 块 (IF-THEN)

Thumb-2 16/32 bit 混编 — 不能每条带 4 bit 条件 → 用 IT 修饰接下来 1–4 条：

        CMP     r0, r1
        IT      GT
        SUBGT   r2, r2, #1
        IT      LE
        ADDLE   r3, r3, #1

IT 掩码字母：

字母 含义
T (Then) 条件 真 时执行
E (Else) 条件 假 时执行

例：ITTE LT

条件 LT 成立 → 第 1、2 条执行 (TT)
条件 LT 不成立 → 第 3 条执行 (E，等价 GE)
第 4 条：由掩码第 4 位决定

规则（书中强调）： E 的条件 = T 条件的逻辑非 — 如 LT 配 GE，EQ 配 NE。

IT 块约束

约束 说明
最多 4 条 含 IT 后指令
块内指令必须带匹配条件后缀 与 IT 掩码一致
块内勿插入分支/IT 调试困难
无 CBZ/CBNZ §8.2
M3+ 调试 单步 IT 需看清掩码

Ch3 M4 阶乘 — 已见 IT GT + MULGT/SUBGT。

何时 IT vs B

选 IT / 条件后缀 选 B
1–4 条 小分支 长 basic block
避免 predict miss 的小代价 远距离跳
热路径 micro-optimization 清晰控制流优先可读性

HFT： 极短 critical section 偶见条件 mov；多数仍靠 无分支算法 + 展开。

可复述要点

  1. ARM 模式：每条可带 EQ/GT/… 后缀。
  2. M 模式：IT + 最多 4 条条件后缀指令；T/E 掩码。
  3. 目的：减少分支 flush — 不是取消分支需求。

section-8.5-straight-line

Ch 8 · 分支与循环 · 章导读

问题：循环尾分支仍贵

即使 SUBS+BNE 已优化，每次迭代末尾的 BNE 仍可能：

  • 清空流水线
  • 分支预测失败（取决于数据/次数）
  • 引入 非确定性 周期（对 DSP/控制环路不友好）

循环展开 — 以空间换时间

做法： 不跳回 loop top — 复制 loop body N 次，用 固定次数 或 剩余次数展开 + 小尾循环。

        ; 原：10 次迭代 body
        ; 展开：body × 10 直线排列，无 BNE
        ; body
        ; body
        ; … (重复 10 遍)
收益 代价
消除或大幅减少分支 Flash/ICache 占用↑
周期可预测 (Deterministic) 维护性差
ILP 更好（编译器/CPU 可调度） 代码体积大时不 cache-friendly

典型场景

场景 说明
DSP FIR 内 tap 固定 tap 数 — 全展开
小矩阵固定维 3×3 运算展开
HFT 解析固定字段 已知步长 unpack
内核已知小 copy memcpy 8/16 byte 展开

部分展开： 每次迭代做 4 次 body + 计数减 4 — 平衡体积与分支。

与编译器

-funroll-loops、pragma — C 层自动展开；手写汇编在 已知边界极小 时用。

Ch7 shift-add + Ch8 展开 = 经典 embedded hot loop 工具箱。

可复述要点

  1. 展开 = 复制 body，去掉回跳分支。
  2. 确定性周期 — 实时/信号处理卖点。
  3. Flash vs 周期 — 与 HFT「latency vs icache」同 tradeoff。
