5.2

section-5.2-memory

Ch 5 · 加载、存储与寻址 · 章导读

内存 = 字节寻址阵列

概念 说明
基本单位 字节 (8 bit) — 每个字节一个地址
连续性 逻辑上 0 … 2³²−1（32 bit 地址空间）连续编号
访问 Load/Store 指定 宽度（byte/half/word）+ 起始地址

Ch1/Ch2： 半字/字对齐要求 — 错宽度或错对齐 → fault 或读错值。

内存映射 (Memory Map)

SoC 把 Flash、SRAM、外设 钉死在地址空间的固定区间 — 程序员用 同一套 LDR/STR 访问 RAM 与 MMIO 寄存器。

Tiva 微控制器（书中示例）典型布局：

高地址
    ┌─────────────────┐
    │  外设 (MMIO)     │  UART · Timer · GPIO …
    │  0x40000000 区   │
    ├─────────────────┤
    │  SRAM (数据/栈)   │
    ├─────────────────┤
    │  Flash (代码)    │  复位后 PC 从此执行
低地址 0x00000000
区域 内容 访问
Flash/ROM 只读代码、常量 LDR 取指；常量池
SRAM 变量、堆、栈 LDR/STR 读写
外设 控制/状态寄存器 MMIO — 特定地址 = 硬件（→ Ch16）

与嵌入式 Linux / 飞控

MCU 本书 应用处理器
查 数据手册 Memory Map 设备树 (DT) 描述基址/中断（→ 21 驱动/DT）
EQU UART_BASE 0x4000xxxx ioremap() / devm_ioremap_resource()
4GB 平面地址 同上 — Load/Store 或 MMIO 映射后读写

Cortex-A Linux： 用户态不直接 STR 到 0x40000000 — 经 内核驱动 映射；指令语义相同。

可复述要点

  1. 内存 = 按字节编号 的大数组；Load/Store 选 宽度 + 地址。
  2. Memory Map 决定 Flash/RAM/外设各在哪段地址。
  3. 驱动 = 对 正确地址 做 正确宽度 的 Load/Store。
5.3

section-5.3-load-store

Ch 5 · 加载、存储与寻址 · 章导读

RISC 铁律

内存 ──LDR──→ 寄存器 ──ALU──→ 寄存器 ──STR──→ 内存

不能直接 ADD [mem1], [mem2]（与 x86 对比 → Ch1 §1.2 RISC）。

按宽度的指令对

宽度 Load Store 寄存器效果
字 32 bit LDR STR 整字
半字 16 bit LDRH STRH 低 16 bit（高 16 见符号扩展）
字节 8 bit LDRB STRB 低 8 bit

语法骨架：

        LDR     r0, [r1]          ; r0 ← Mem32[r1]
        STRB    r2, [r3, #4]      ; Mem8[r3+4] ← r2 低 8 位

带符号扩展 Load

读取 有符号 8/16 bit 到 32 bit 寄存器时，需 符号扩展（MSB 复制到高半部）：

指令 作用
LDRSB 有符号 字节 → 32 bit
LDRSH 有符号 半字 → 32 bit 
Mem8 = 0xFF  (有符号 −1)
LDRB  → r0 = 0x000000FF  (255 无符号)
LDRSB → r0 = 0xFFFFFFFF  (−1 有符号) ✓

C 对照： (int8_t)byte vs (uint8_t)byte — 汇编要选对接指令。

无符号半字/字节： LDRH/LDRB 零扩展高位。

MMIO 宽度（预告 Ch16）

外设寄存器常为 32 bit 字 — 用 LDR/STR 字访问；若手册规定 半字/字节 必须匹配，否则 UNPREDICTABLE 或 bus fault。

AArch64 对照（奔跑吧 Ch3）

v4T/v7-M AArch64
LDR r0, [r1] LDR W0, [X1] / LDR X0, [X1]
LDRB/LDRH LDRB/LDRH + SXTB/SXTH 或专用加载

可复述要点

  1. LDR* 进寄存器，STR* 出寄存器 — 成对记忆。
  2. 有符号小数据 → LDRSB/LDRSH；无符号 → LDRB/LDRH。
  3. MMIO 先查手册 寄存器宽度，再选对指令。
5.4

section-5.4-addressing

Ch 5 · 加载、存储与寻址 · 章导读

有效地址 (Effective Address)

        LDR/STR  Rt, [Rn, #offset]    ; 多种形式

Rn = 基址寄存器；offset = 立即数或 寄存器 ± 移位。

前变址 (Pre-Indexed)

先 用 Rn ± offset 作地址访问，可选 写回 Rn：

        STR     r0, [r1, #12]!      ; EA = r1+12；然后 r1 ← r1+12
        LDR     r2, [r1, -#4]!       ; EA = r1-4 ；然后 r1 ← r1-4
要素 说明
! 后缀 Pre-indexed with write-back — 访问后基址更新
用途 栈 push/pop、顺序写数组、构造链表指针

栈增长（满递减栈常见）：

        STR     r0, [sp, #-4]!        ; 先减 sp，再存 — 压栈
        LDR     r0, [sp], #4          ; 先读，再增 sp — 出栈（后变址）

→ Ch13 系统化 PUSH/POP 与 APCS。

后变址 (Post-Indexed)

先 用 Rn 原值 作地址，再 Rn ← Rn ± offset：

        STR     r0, [r1], #12         ; Mem[r1]←r0；然后 r1←r1+12
        LDR     r0, [r1], #4          ; r0←Mem[r1]；然后 r1←r1+4
对比 Pre (!) Post (, #off)
地址计算 访问 前 加偏移 访问 后 加偏移
遍历数组 两者皆可；post 常像 for 里先读 *p 再 p++

数组扫描模式：

        ; r1 = &arr[0], 循环
        LDR     r0, [r1], #4          ; 读 word，指针自动 +4

寄存器偏移 + 移位

偏移不必是常数 — 可用 另一寄存器经移位：

        LDR     r0, [r1, r2, LSL #2]  ; EA = r1 + (r2<<2) — 字索引 i
场景 偏移形式
arr[i] (word) r2, LSL #2
查表 table[i] 同上 + 基址 = 表头
结构体 field 基址 + #offsetof 立即数

Ch12 查表 直接依赖此模式。

可复述要点

  1. Pre + !：先算新地址再访问，并 写回基址。
  2. Post ], #n：先用旧基址访问，再 基址 += n。
  3. [Rn, Rm, LSL #2] = 数组下标 × 元素大小 — 驱动/内核遍历常用。
5.5

section-5.5-endianness

Ch 5 · 加载、存储与寻址 · 章导读

问题：一个 Word 占 4 个连续字节，谁在低地址？

32 bit 值 0x12345678 在地址 0x1000 起：

小端 Little-Endian（多数 ARM 默认）：

地址:    0x1000  0x1001  0x1002  0x1003
字节:      78      56      34      12
           ↑ LSB 在最低地址

大端 Big-Endian：

地址:    0x1000  0x1001  0x1002  0x1003
字节:      12      34      56      78
           ↑ MSB 在最低地址
模式 记忆
Little 低地址存低位字节 — x86、ARM 默认
Big 低地址存高位字节 — 网络字节序、部分通信协议

对 Load 的影响

操作 注意
LDR 字 CPU 按 当前 endian 设置 组装 32 bit 到寄存器
LDRB/LDRH 只读 指定地址 的 1/2 字节 — 与字内字节序无关
跨平台协议 线上常 Big；主机常 Little — 需 显式转换

网络编程对照： htonl/ntohl — 与 REV 同类问题。

字节序转换 — REV 等（Cortex-M）

在寄存器内 翻转字/半字 字节序，无需多次 LDRB/STRB：

指令 作用
REV 字内 4 字节反转
REV16 各半字内字节反转
REVSH 低半字符号扩展 + 字节反转

软件法（无 REV）： 移位 + AND/ORR 手动重排 — Ch7 位操作。

ARM7 时代： 可能靠 CP15 配置 endian 状态；M 系启动后通常 固定 little。

驱动 / HFT 场景

场景 Endian
MMIO 寄存器 按 SoC 手册 — 勿假设与 CPU 相同
DMA 缓冲区 设备与 CPU 不一致时要 REV 或 swab
网络报文 Big-endian 字段 — 与 13 DPDK 同类

可复述要点

  1. Little = 低地址存 LSB — ARM 主机默认。
  2. LDRB 读单字节不受「字内序」影响；LDR 字 受系统 endian 影响。
  3. 跨 endian 通信用 REV 或 htons 类函数。
5.6

section-5.6-bit-banded

Ch 5 · 加载、存储与寻址 · 章导读
标签： 选读 — Cortex-M3/M4 专用；Linux/Cortex-A 无 此机制

传统问题：改 1 bit = 读-改-写

        LDR     r0, [GPIO_BASE]       ; 读整字
        ORR     r0, r0, #BIT3         ; 改一位
        STR     r0, [GPIO_BASE]       ; 写回整字
风险 说明
非原子 中断插在 R-M-W 中间 → 丢写
副作用 某些寄存器 写 1 清 0 — 读回再写会误清其他位
周期 3 条指令 + 2 次总线访问

位带 (Bit-Banding) 思路

硬件把 SRAM / 外设 某区域内 每一个 bit 映射到 独立的一个 32 bit 别名地址：

真实 bit 地址空间          别名区（每 bit → 一个 word 地址）
     │                              │
     └──────── 硬件映射 ────────────┘
              STR alias, #1   →  硬件只置位对应那 1 bit
              STR alias, #0   →  硬件只清零那 1 bit

程序员： 对 别名地址 做一次 STR 字 — 等价 单 bit 写，无需 R-M-W。

映射公式（概念）

Cortex-M 位带别名区 与 位带位区 有固定线性关系（见 ARM 文档 / Tiva 手册）：

alias_addr = bit_band_base + (byte_offset × 32) + (bit_number × 4)

仅特定区域可位带 — 不是任意地址；需查 Memory Map。

与 Linux / 飞控路径

MCU 本书 Cortex-A + Linux
位带 GPIO set-bit/clear-bit MMIO、或 写 1 置位寄存器 (BSRR)
无 OS 驱动仍常用 专用 W1S/W1C 寄存器 代替 R-M-W

结论： 理解 R-M-W 问题 必记；位带 为 M3/M4 优化手段，应用处理器笔记可跳过实现细节。

可复述要点

  1. 位带 = 1 bit ↔ 1 个 32 bit 别名地址，单 STR 改一位。
  2. 解决 R-M-W 非原子与 W1C 误写 — M 系特色。
  3. Cortex-A/Linux 用 别的硬件机制（BSRR、shadow reg）达同类目的。

汇编器/链接器在幕后做什么

源码里的 SPACE 留栈、AREA 代码、DCD 常量 最终必须落到芯片 真实 Flash / SRAM 地址 — 由 链接器 + 配置文件 决定。

.s / .c  →  .o（段 + 重定位）
              ↓
链接器 + Scatter / Linker Command File
              ↓
.axf / .elf — 各段 VMA/LMA（Flash 里存什么、RAM 里跑什么）
概念 说明
Scatter-Loading (Keil) 分散加载 — 指定 RO → Flash、RW/ZI → RAM
Linker Command File (CCS) TI 的 .cmd — 同样语义
GNU 链接脚本 .ld（→ Ch4 §4.4 · 奔跑吧 Ch9）

典型放置

段 内容 物理位置
RO (Code + RO Data) 指令、只读常量 Flash / ROM
RW (Initialized Data) 有初值全局变量 RAM（启动时从 Flash 拷贝）
ZI (BSS) 零初始化变量、SPACE 栈 RAM
Stack / Heap SPACE 或链接脚本 _stack_top RAM 高端

启动代码职责： 拷贝 .data、清零 .bss、设 SP — 然后才 main（→ U-Boot/head.S 同类）。

与 Ch4/Ch5 指令的衔接

源码写法 链接后
my_var SPACE 256 RAM 中占 256 字节 — LDR/STR 用 &my_var
code AREA CODE Flash 中 — CPU 取指
DCD 0x40001000 常数池 — LDR = 加载到寄存器再 STR 到外设

错链接脚本后果： 变量写到 不存在的 RAM、栈与堆重叠 — 运行随机 fault。

嵌入式 Linux 尺度

MCU Linux
Scatter / .ld 定 SRAM 设备树 报内存 @0x80000000, size
单镜像 U-Boot + kernel + dtb 各段加载地址
20 构建 Yocto/Buildroot 打包同一逻辑

可复述要点

  1. Load/Store 的地址 来自链接器分配的符号 — 不是魔法数字（除非 MMIO EQU）。
  2. Scatter/链接脚本 = Flash 放代码、RAM 放数据/栈。
  3. 启动代码在 第一条 LDR 业务数据前 必须设好 SP 与内存初始化。
