§1.2 · RISC vs CISC · ARM 史 · Cortex 三线

CISC 痛点（VAX、8086、68000 等）

变长指令、译码重；单指令可「访存+运算」；微码占面积功耗；复杂指令使用率低。

RISC 准则（伯克利 / 斯坦福脉络）

  1. 定长指令、译码简单
  2. 基础指令倾向单周期 / 流水线友好
  3. 仅 Load/Store 访存 — 加减移位只碰寄存器（全书核心习惯）
  4. 少/无微码，硬连线实现
  5. 指令集精简、易验证
  6. 代价：复杂任务指令条数多，靠频率与流水线补

ARM 简史

Acorn → ARM1（Furber / Wilson，1985）→ 1990 ARM Ltd（卖 IP 授权，不卖芯片）→ ARM7TDMI 里程碑。

Cortex 三线（必背）

系列 场景 要点
Cortex-A 手机、平板、树莓派等 有 MMU，跑 Linux/Android — 本书只科普
Cortex-R 汽车、医疗等 硬实时 — 本书只对比
Cortex-M 家电、传感器 MCU 常无 MMU；全书实操主线

讲 A、不练 A： CORTEX-A-SCOPE.md。本目录主练 v4T / v7-M；Pi5 Linux → 奔跑吧 AArch64。

§1.5 · 整数 · 浮点 · ASCII

整数

编码 现状
符号幅值 少用

ASCII

section-1.2-risc-history

Ch 1 · 计算机系统概述 · 章导读

RISC 与 CISC 对比

特征 RISC（精简指令集） CISC（复杂指令集，如 x86）
指令长度 固定长度（ARM 常见 32 位；Thumb 16/32 位） 变长（x86 1–15 字节）
执行模型 倾向 单周期 / 流水线友好 Historically 微码、复杂寻址
访存 只有 Load/Store 能访问内存；运算在寄存器间 指令可直接 add [mem], eax 等
微代码 无微代码（或极简） 大量复杂指令靠微码实现
设计哲学 硬件简单、编译器优化空间大 单条指令表达力强

汇编直觉： 写 ARM 汇编时，算数 ≠ 访存 — 先 LDR 进寄存器，算完再 STR 写回。这与 01 CSAPP x86 的「内存操作数」习惯不同。

ARM 处理器演进（书中脉络）

ARM1 → … → ARM7TDMI（本书 v4T 代表）
                ↓
         Cortex 家族（按场景分线）
                ↓
    ┌───────────┼───────────┐
    │           │           │
Cortex-A    Cortex-R    Cortex-M
应用处理器   实时/安全     微控制器
(手机/Linux) (汽车/存储)   (本书重点, 如 M4)
系列 典型用途 与本书 / 你的路径
Cortex-A 智能手机、树莓派、无人机应用处理器 嵌入式 Linux → 奔跑吧 ARM64 · 20 构建
Cortex-R 硬盘控制器、汽车 ECU、硬实时 本书仅背景提及
Cortex-M STM32 等 MCU、传感器节点 本书正文主战场（Ch2–18 大量 v7-M 示例）

为什么 Smith 从 ARM7TDMI + Cortex-M 讲起

  • ARM7TDMI：经典 v4T — 理解 ARM/Thumb 双状态、历史向量表。
  • Cortex-M4：现代 v7-M — Thumb-2 为主、NVIC 中断、可选 FPU（Ch9–11 浮点章）。
  • 不是 AArch64：64 位 A 架构语法在 奔跑吧 另学；概念（Load/Store、栈、异常）可一一映射。

可复述要点

  1. RISC 核心：固定指令 + Load/Store 访存 + 寄存器运算。
  2. ARM 公司产品线按 A / R / M 切场景；本书练 M，你的 Linux/飞控退路靠 A。
  3. ARM7TDMI 与 Cortex-M 是 两代 ISA 风格，Ch2 会并排对比寄存器与模式。

section-1.3-computing-devices

Ch 1 · 计算机系统概述 · 章导读

存储程序计算机（Stored-program computer）

经典模型三要素：

        ┌─────────────┐
        │  处理器 CPU  │  取指 → 译码 → 执行
        └──────┬──────┘
               │ 总线 (Address / Data / Control)
        ┌──────┴──────┐
        │    内存 RAM   │  指令 + 数据 同存于地址空间
        └─────────────┘
组件 作用
处理器 按 PC 从内存取指令，修改寄存器与内存
内存 统一存放程序（指令序列）与数据 — 「程序即数据」
总线 地址线选单元、数据线传内容、控制线协调读写时序

与 MikanOS 对照： 08 MikanOS 里 UEFI 加载 kernel.elf 到内存再跳转 — 同样是「内存里先有比特，CPU 从某入口地址开始执行」。

计算机技术层级（自底向上）

物理层     晶体管 → 逻辑门
           ↓
微架构     流水线、缓存、分支预测（[19 Hennessy](../../../../15-computer-architecture/) Ch2）
           ↓
ISA        指令集架构 ← 【汇编程序员工作在这一层】
           ↓
高级语言   C / C++（[02 C](../../../../01-c-language/)）
           ↓
操作系统   Linux / RTOS（[04 LKD](../../../../05-linux-kernel/)）
层级 你写什么 例子
ISA 汇编 .S LDR r0, [r1] · ADD r2, r0, r3
高级语言 .c x = a + b; — 编译器生成 ISA
OS 系统调用 read() → 内核帮你在用户态/内核态间切换

Ch1 要点： 汇编不是「比 C 低级一点的语法糖」，而是 直接描述 ISA 层 — 每条助记符对应（或展开为）确定的比特模式（→ §1.6）。

「计算设备」在本书语境

  • 从 嵌入式 MCU 板（Tiva Launchpad 等）到 通用存储程序机，硬件形态不同，模型相同。
  • 外设（UART、GPIO）在 Cortex-M 上通常 内存映射 — 特定地址读写即控制硬件（→ Ch16）。

可复述要点

  1. 冯·诺依曼：指令和数据共用内存 + 顺序（或分支）改 PC。
  2. 汇编站在 ISA 层 — 之上是 C/ OS，之下是微架构与晶体管。
  3. 总线连接 CPU 与内存/外设；MMIO 外设也占用地址空间。

section-1.4-number-systems

Ch 1 · 计算机系统概述 · 章导读

为什么汇编程序员必须熟练进制转换

计算机内部 一切皆为比特；调试寄存器、内存 dump、地址、机器码时，十六进制是日常语言，二进制用于理解位域，十进制用于心算验证。

三种进制

进制 基数 典型用途
二进制 2 硬件电平、标志位、掩码
十进制 10 人类直觉、文档中的数量
十六进制 16 汇编清单默认显示 — 4 bit 一组，与字节对齐

对应关系：

1 字节 = 8 bit = 2 个十六进制 digit

例：0xFF = 1111 1111₂ = 255₁₀
    0x100 = 256₁₀（常见对齐边界）

转换要点（书中练习常考）

方向 方法
十 → 二 除 2 取余（逆序）或凑 2 的幂
二 → 十 按位加权求和
二 ↔ 十六 4 bit 一组直接查表（0–F）
十 ↔ 十六 先转二进制或直接用除 16

汇编场景：

  • 地址 0x40000000 — Cortex-M 外设区常见基址风格。
  • 掩码 0x000000FF — 取低 8 位（→ Ch7 位操作）。

与 §1.5 的分工

本节 §1.4 下一节 §1.5
进制本身 — 怎么写、怎么换 用比特编码数与字符 — 补码、IEEE754、ASCII

可复述要点

  1. 调试 ARM 程序：寄存器/内存以 hex 为主。
  2. 记住 1 hex digit = 4 bits，字节边界在 hex 里一目了然。
  3. 进制转换是 Ch1 练习题核心 — 熟练后可快速读 0x 常量与位掩码。

section-1.5-representation

Ch 1 · 计算机系统概述 · 章导读

整数表示

方式 要点 现代地位
无符号 纯 magnitude，范围 0 … 2ⁿ−1 地址、计数、位图
原码 (Sign-magnitude) 最高位符号，其余绝对值 历史/概念；±0 问题
反码 (One's complement) 正数不变，负数按位取反 几乎仅教学
补码 (Two's complement) 负数 = 对应正数取反 + 1 ARM 有符号整数默认

补码为何是核心：

  • 唯一零；加减可同一套硬件（减法变加法）。
  • 溢出时 N/V/C/Z 标志位 有明确定义（→ Ch7）。
  • 位宽固定：ARM 32 位寄存器里 0xFFFFFFFF 作为 有符号 是 −1。
例（8 bit 示意）：+3 = 0000 0011
                  −3 = 1111 1101  （取反+1）

与 C 对照： int32_t x = -1; 在内存里就是全 1 比特模式 — 02 C 与汇编读同一块内存。

浮点数表示（IEEE 754 简介）

解决 极大/极小 与 小数 的动态范围问题；Ch9–11 整章展开，Ch1 只建立直觉。

单精度（32 bit）结构：

| S |   指数 E (8)   |        尾数 / 分数 F (23)        |
 1 bit     偏置 127              隐含 leading 1
字段 含义
S 符号 0/1
E 指数（偏置编码，非补码）
F 有效数字的小数部分

特殊值（Ch1 预告，Ch9 详述）： ±0、次正规数、±∞、NaN。

本书路径： 嵌入式 Linux / 飞控若用 Cortex-A + NEON，浮点主要在 C/NEON；Cortex-M4F 才强依赖 Ch9–11 — 可 跳过 浮点三章（见 OUTLINE）。

字符表示 — ASCII

要点 说明
7 bit ASCII 'A'=0x41 · '0'=0x30 · 可打印字符 + 控制符
汇编用法 数据段 .byte 'H','i',0 或 .ascii / .string（→ Ch4 伪指令）
扩展 UTF-8 等是字节序列上的超集；裸机常先 ASCII

调试： 内存里看到 48 65 6C 6C 6F → Hello 的 ASCII hex。

附录 C — ASCII 表 可速查。

可复述要点

  1. 有符号整数 = 补码 — 与 ARM 算术、标志位一体。
  2. 浮点 = 符号 + 指数 + 尾数 — Ch1 建立框图即可。
  3. 字符 = 整数比特模式 — 'A' 就是 0x41，字符串即字节数组。

section-1.6-bits-to-commands

Ch 1 · 计算机系统概述 · 章导读

从比特模式到操作

处理器不做「读 ADD」，只认 固定宽度的比特模式（ARM 常见 32 位；Thumb 16/32 位）：

32 bit 比特模式  →  译码器  →  控制信号  →  ALU/访存/分支…
机器层 人类可读层
E3A00005（示例 hex，随 ISA/指令而变） MOV r0, #5
字段拆分：操作码 + 寄存器编号 + 立即数… 助记符 (Mnemonic) + 操作数

汇编语言定义： 用 助记符 代替裸比特，由 汇编器 翻译回机器码 — 仍是 ISA 层，一行（通常）对应一条或几条机器指令。

为什么是「命令」而不是「数据」

同一串比特，取决于 PC 指向哪里：

  • 取指路径 → 指令
  • Load 路径 → 数据

存储程序模型下，指令和数据都在内存 — 权限与 Harvard/Modified Harvard 是微架构细节（Cortex-M 指令缓存 vs 数据侧）。

与高级语言的边界

汇编 C
抽象 寄存器名、显式 Load/Store 变量、表达式
控制流 B / BL / 条件码 if / for
谁生成机器码 汇编器（+ 链接器） 编译器 先出汇编或直接出目标码

Ch3 起： 五个示例程序让你 单步看寄存器 — 把本节「比特→助记符」变成肌肉记忆。

可复述要点

  1. CPU 只执行 比特模式；助记符是给人看的 ISA 文本形式。
  2. 汇编器职责：助记符 → 目标文件中的机器码（→ §1.7 完整工具链）。
  3. 读 listing / 反汇编 = 把机器码 译回 助记符 — 调 bug 必备技能。
