6.2

section-6.2-rotate-constants

Ch 6 · 常量与文字池 · 章导读

问题：一条指令里能带多大的立即数？

MOV r0, #0x12345678 若真写 32 bit 常数 — 操作码 + 寄存器编号 没位了。
ARM7 数据处理指令 用 12 bit 立即数字段 编码常数（不可能是任意 32 bit）。

12 bit = 8 bit 常数 + 4 bit 循环移位

机器码立即数字段 (12 bit)
├── [11:8]  循环移位量 rot（×2 → 偶数位 0,2,4…30）
└── [7:0]   无符号字节 imm8 (0–255)

硬件桶形移位器 (Barrel Shifter)： 对 imm8 做 循环右移 rot×2 位（偶数位），得到最终 32 bit 常数。

示例（概念）：

imm8 rot 效果（示意）
0x40 0 0x00000040
0x01 8 0x00010000（常用来造 64K 对齐掩码）

能表示： 大量掩码、小整数、许多 0x4000xxxx 风格 的「稀疏」常数。
不能表示： 任意 32 bit（如 0x12345678 往往不行）。

MVN — 按位取反扩展可表示集合

        MVN     r0, #0          ; 若 #0 可编码 → r0 = 0xFFFFFFFF

思路： 对「可旋转 8 bit 表示的值」取反 → 得到另一族常数（全 1、某些补码边界）。

指令 关系
MOV 加载 旋转后的 imm8
MVN 加载 NOT(旋转后的 imm8)

与汇编器 / 伪指令的关系

手工判断「这个数能不能 MOV 编码」极烦 — 故 LDR r0,=constant 交给汇编器：

  1. 能编码 → 替换成 MOV/MVN
  2. 不能 → 文字池（→ §6.3–6.4）

调试： 反汇编见一条 MOV vs LDR [pc,#…] — 可知常数是否「可旋转立即数」。

AArch64 对照

A64 用 movz/movk 16 bit 拼 64 bit — 思想类似 MOVW/MOVT（§6.4），不再用 ARM7 旋转立即数。

可复述要点

  1. 12 bit 立即数 = 8 bit + 偶数循环右移 — 非任意 32 bit。
  2. MVN 扩大 可表示常数集合。
  3. 程序员用 LDR =，不必手算旋转字段。
6.3

section-6.3-load-constants

Ch 6 · 常量与文字池 · 章导读

语法（捷径）

        LDR     r0, =0x40001000        ; 任意 32 bit 常数或表达式
        VLDR    S0, =3.14159           ; 浮点常数（M4F，→ Ch3 §3.7）

这是伪指令 — CPU 不识别 =；汇编器 展开 为真实指令序列。
小立即数优先真实 MOV（→ Ch3 §3.3）；编码不下才走本伪指令 / MOVW·MOVT。

汇编器决策流程

LDR Rd, =expr
    ↓
expr 能否用 §6.2 旋转/MVN 单条 MOV/MVN 表示？
    ├─ 是 → 替换为 MOV/MVN（无内存访问，最快）
    └─ 否 → 在文字池放 .word expr
              替换为 PC 相对 LDR Rd, [pc, #offset]（→ §6.4）
展开结果 特征
MOV r0, #imm 单周期、无额外 Flash
LDR r0, [pc, #n] 多一次内存读；池在附近

Ch5 关联： 真 LDR 从 文字池地址 取 32 bit 到寄存器 — 与从 RAM 读变量同一指令。

常见用途

场景 示例
MMIO 基址 LDR r1, =UART0_BASE
位掩码 LDR r2, =0x000000FF
大常数 LDR r3, =0x12345678 → 几乎必走文字池

Ch16 驱动： 基址进寄存器 → LDR/STR [r1,#off] 访问寄存器 — 本章 + Ch5 合体。

与 MOVW/MOVT 的分工

路径 何时
LDR = 通用；汇编器自动优化
MOVW/MOVT Thumb-2 显式 两条拼 32 bit，不依赖文字池（§6.4）

GNU：ldr r0, =sym 同样行为；movw/movt 或 mov32 宏。

可复述要点

  1. LDR rd,=cst = 伪指令；汇编器 MOV 或 文字池+LDR。
  2. 读 listing 区分 单 MOV vs LDR [pc,#…]。
  3. 外设基址/大掩码 — 嵌入式最高频写法之一。
6.4

section-6.4-literal-pools

Ch 6 · 常量与文字池 · 章导读

文字池 (Literal Pool) 是什么

当常数 无法 用 §6.2 单条 MOV/MVN 编码时，汇编器在 代码段附近 插入一块 只读数据：

        LDR     r0, =0x12345678
        ; ... 汇编器在池里生成 ...
        ; Literal pool:
        ;   DCD 0x12345678
        ; 并生成: LDR r0, [pc, #offset_to_pool]
属性 说明
位置 通常 当前段末尾 或 LTORG 强制处
内容 DCD / .word 形式的 32 bit 常数
访问 PC 相对 LDR — offset 有限

PC 相对寻址的 ±4KB 限制

ARM 经典 LDR [pc, #imm12] 偏移范围约 ±4KB（具体视指令与对齐）。

问题： 代码很长时，默认堆在文件末尾的文字池 可能离某条 LDR = 太远 → 汇编 报错（offset 溢出）。

LTORG — 强制就近建池

        B       skip_pool      ; 无条件跳，避免 CPU 执行池里数据
        LTORG                  ; 在此插入 literal pool
skip_pool
        ; 继续代码...
习惯位置 原因
无条件分支之后 池不会被当作指令执行
子程序末尾 本函数内常数就近
长函数中间 分段建池

Ch4 回顾： §4.4 LTORG · GNU .ltorg

MOVW / MOVT — 无文字池加载任意 32 bit（Thumb-2 / M4）

        MOVW    r0, #0x5678        ; r0[15:0]  ← 0x5678
        MOVT    r0, #0x1234        ; r0[31:16] ← 0x1234  → r0 = 0x12345678
指令 作用
MOVW Move Wide — 16 bit 立即数 → 寄存器 低 16 位（高 16 清零）
MOVT Move Top — 16 bit 立即数 → 高 16 位（低 16 保留）

优点： 任意 32 bit 常数 两条指令、无文字池、无 PC 相对距离问题。
代价： 占 8 字节指令空间 vs 池+单 LDR 可能更省或更费 — 视密度而定。

ARM7 纯 ARM 状态： 无 MOVW/MOVT — 更依赖 LDR = + 池。

AArch64： movz x0, #0x5678 · movk x0, #0x1234, lsl #16 — 同模式 64 bit。

三种方式对比

方式 指令数 需要池 典型平台
MOV/MVN 旋转立即数 1 否 小常数，全架构
LDR = → 池 1+LDR 是 任意常数，通用
MOVW+MOVT 2 否 Cortex-M / Thumb-2

可复述要点

  1. 文字池 = 汇编器放的 .word 常数表 + PC 相对 LDR。
  2. 代码过长用 LTORG 分段建池，避免 ±4KB 溢出。
  3. MOVW/MOVT = 两条指令拼任意 32 bit — M4 常用，替代池。

section-6.5-load-addresses

Ch 6 · 常量与文字池 · 章导读

数值 vs 地址

需求 典型写法
数值 0x40001000 LDR r0, =0x40001000
变量 buffer 的地址 LDR r0, =buffer 或 ADR r0, buffer
跨段外部符号 常 LDR =label（链接后绝对/相对地址进池）

Ch5： 地址进寄存器后 → LDR/STR [r0] 访问内存/MMIO。

ADR — PC 相对算地址（伪指令）

        ADR     r0, my_table       ; r0 ← 与 PC 相关的 label 地址
my_table
        DCD     1, 2, 3

汇编器： 计算 label − PC（经对齐修正），展开为 ADD rd, pc, #offset 或 SUB。

优点 限制
不占用文字池 偏移范围 小（同一段、近距离标签）
位置无关代码 (PIC) 友好 太远则不够用

适用： 同文件内 表格/字符串 — ADR r0, msg 再 LDRB。

ADRL — 扩展范围（伪指令）

标签 太远，单条 ADD/SUB 不够 → ADRL 展开为 两条 ADD/SUB 组合，扩大 offset。

ADR ADRL
展开 通常 1 条 2 条
距离 短 较长
仍可能失败 是 极远则仍用 LDR =

LDR = label — 经文字池取地址

        LDR     r0, =extern_buf     ; 池里放链接后的完整地址
        LDR     r1, =GPIO_BASE      ; 外设基址 — 常跨文件/绝对地址
场景 为何用 LDR =
外部标签 链接前地址未知，池在链接时重定位
绝对 MMIO 基址 常数太大或 ADR 够不着
与数值常数统一 同一套伪指令习惯

链接器： 修正文字池里的 重定位项 — 与 .o 符号解析一体（→ Ch5 §5.7）。

GNU gas 对照

Keil GNU
ADR r0, lab adr r0, lab 或 add r0, pc, #offset
LDR r0, =sym ldr r0, =sym（同样伪指令）
— ldr r0, sym（若 sym 在链接范围内有时直接）

Linux 内核： 大量 adr/adrp（A64）与 ldr = 加载符号地址。

可复述要点

  1. 近标签用 ADR — 无池、PC 相对。
  2. 远标签/外部符号用 LDR =label — 走文字池 + 链接重定位。
  3. 地址进 rX 后 — Ch5 的 Load/Store 才真正访问数据。
