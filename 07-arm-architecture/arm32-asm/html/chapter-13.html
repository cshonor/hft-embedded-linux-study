13.1

section-13.1-intro

Ch 13 · 子程序与堆栈 · 章导读 · 本章概述

为什么需要子程序

复杂汇编若全写在一个 线性流程 里：

  • 难以阅读、测试、复用
  • 同一算法（sin、延时、串口发字节）重复出现

分而治之： 把任务拆成 专注的小块，用 BL 调用；每块有 单一入口、明确返回。

堆栈的角色

子程序往往 暂时借用 寄存器；调用者期望返回后 r4、LR 等仍原样。

机制 作用
堆栈 (Stack) LIFO — 后压入的先弹出
SP (r13) 指向当前栈顶（依 Full/Empty 定义略有不同）
压栈/出栈 保存 LR、callee-save 寄存器、局部变量

没有堆栈，递归、中断打断子程序、嵌套调用 都会破坏返回地址。

本章两条线

1. 硬件/指令：LDM · STM · PUSH · POP · 四种栈类型
2. 软件契约：传参方式 + AAPCS（与 C 互调）

与前置/后续

章节 关系
Ch8 BL 子程序 入口指令
Ch12 查表/二分宜封装为 BL LookupSin
Ch14 异常 硬件自动压栈 — 与子程序 软件压栈 对照
Ch18 C 调用 asm、asm 调用 printf — 必须 AAPCS

可复述要点

  1. 子程序 = BL + 堆栈保存上下文。
  2. 本章是从「会写循环」到「会写 可复用、可重入模块」的门槛。
  3. 与 C 混编时，AAPCS 比指令细节更重要（§13.5）。
13.2

section-13.2-stacks

Ch 13 · 子程序与堆栈 · 章导读 · 本章概述

SP 与 LIFO

  • r13 固定作 堆栈指针 (SP)（Ch2 程序员模型）。
  • 概念：后进先出 — 最后 PUSH 的项，第一个 POP 弹出。
  • 物理：SP 指向 RAM 中一段连续区域；满递减 时向 低地址 生长（C 默认）。

LDM / STM — 多寄存器传输

相对单字的 LDR/STR：

指令 含义
STM Store Multiple — 多个 Rt 写入内存
LDM Load Multiple — 从内存读回多个 Rt

好处： 一条指令完成 保存/恢复 8 个寄存器 — 代码更小、常更快（一次取指）。

语法示例：

    STMDB   sp!, {r4, r5, r6, lr}   ; 压栈（事前递减）
    LDMIA   sp!, {r4, r5, r6, pc}   ; 出栈并返回

! — 写回基址（SP 随操作更新）。

寻址后缀：IA · IB · DA · DB

基址寄存器（常为 SP）相对存取时刻如何变化：

后缀 全称 行为
IA Increment After 传送 后 基址 +
IB Increment Before 传送 前 基址 +
DA Decrement After 传送 后 基址 −
DB Decrement Before 传送 前 基址 −

ARM7TDMI： 四种全支持。
Cortex-M3/M4： 为精简仅 IA + DB — 恰好对应 POP/PUSH 所需。

PUSH 与 POP（汇编器助记符）

助记符 实际指令 典型用途
PUSH {…} STMDB sp!, {…} 压栈
POP {…} LDMIA sp!, {…} 出栈

口述： 写 PUSH/POP 即可；反汇编时看到 STMDB/LDMIA 不要陌生。

13.2.3 堆栈的四种类型

两个维度组合：

维度 选项
方向 递增 (Ascending) — 向高地址长 · 递减 (Descending) — 向低地址长
SP 含义 满 (Full) — SP 指向 最后有效项 · 空 (Empty) — SP 指向 下一空闲槽
类型 助记符后缀 说明
Full Descending FD ARM C/C++ 默认
Empty Descending ED
Full Ascending FA
Empty Ascending EA

配对示例（FD）：

    STMFD   sp!, {r4-r7, lr}    ; 压栈 ≡ PUSH（满递减）
    LDMFD   sp!, {r4-r7, pc}    ; 出栈；pc←lr 返回

满递减口述： SP 初始指向栈区 高地址一端；每次压栈 SP 先减 再写 — 栈向低地址 长。

与 Ch5 单字访问的关系

  • 小数据、随机访问 → LDR/STR + 偏移
  • 函数序言/尾声、异常保存 → STM/LDM 批量

内核 push {r0-r12, lr}（AArch32）思想相同。

可复述要点

  1. SP = r13；PUSH = STMDB，POP = LDMIA。
  2. C 用 满递减 (FD) — STMFD/LDMFD 成对。
  3. M 系只有 IA/DB — 不影响正常栈操作。
  4. 列表里写 pc 等价于 POP 返回地址到 PC — 子程序尾声常用。
13.3

section-13.3-subroutines

Ch 13 · 子程序与堆栈 · 章导读 · 本章概述

调用：BL

    BL      DelayMs        ; LR ← 下一条指令地址；PC ← DelayMs
寄存器 调用后
LR (r14) 返回地址（BL 的下一条）
PC 子程序入口

返回（简单情形）： 子程序未再调用他人、未改 LR：

    BX      lr             ; 或 MOV pc, lr

一旦子程序内部还有 BL，LR 会被覆盖 — 必须先 保存 LR（通常压栈）。

可重入性 (Reentrant)

可重入 子程序满足：

  • 可被 中断 打断，返回后继续正确
  • 可被 递归 或 嵌套 调用（同一函数在栈上有多帧）
  • 不依赖固定 RAM 全局 作唯一状态（或用栈上局部）

入口铁律： 在使用前，把 将要改写的寄存器 + LR 压栈：

DelayMs
    STMDB   sp!, {r4-r7, lr}    ; 序言 (prologue)
    ; … 使用 r4-r7，可能 BL 其他函数 …
    LDMIA   sp!, {r4-r7, pc}    ; 尾声 (epilogue) — pc 从栈取原 LR

pc 在寄存器列表中： 硬件把弹出的 LR 值写入 PC — 一条指令返回。

序言 / 尾声模板

调用者 BL Foo
        ↓
Foo:    保存 callee-save + LR
        读参数 (r0-r3 / 栈)
        计算
        恢复寄存器 + PC←LR
        ↓
调用者继续

错误示范： 在 Foo 里用 r4 但不保存 — 返回后调用者的 r4 被破坏（违反 AAPCS）。

嵌套调用与 LR

main  BL  A      ; LR = 返回 main
A:      保存 LR
        BL  B    ; LR = 返回 A（覆盖 A 的入口 LR！）
B:      … BX lr
A:      恢复 LR，返回 main

口述： 只要子程序里还有 BL，LR 必须进栈（或换用其他保存策略）。

与 Ch12 / Ch11 示例

示例 结构
Ch12 查表 sin BL LookupSin — 象限逻辑在子程序内
Ch11 泰勒 sin 浮点 BL + 参数在 s0

可复述要点

  1. BL 设 LR；复杂子程序 入口压栈 LR + 用到的 r4-r11。
  2. LDMIA sp!, {…, pc} = 恢复 + 返回，一条搞定。
  3. 可重入 = 状态在 栈帧 上，而非偷偷改调用者寄存器。

section-13.4-parameters

Ch 13 · 子程序与堆栈 · 章导读 · 本章概述

三种传参方式

方式 做法 优点 缺点
寄存器 调用者 MOV r0, arg0 再 BL 最快 寄存器数量有限
指针（引用） r0 = &struct 或 &buffer[0] 大对象、字符串 不拷贝 需约定读写权限
堆栈 调用者 PUSH 参数 再 BL 参数 任意多 慢；要算 SP 偏移

实际 ABI（AAPCS）= 前几个用寄存器，其余用栈（§13.5）。

1. 寄存器传参

    MOV     r0, #1000       ; 延时毫秒
    BL      DelayMs
    ; 返回值可在 r0
  • 子程序从 r0–r3（及浮点 s0–s15）读入。
  • 适合 标量、小整数、指针本身。

2. 指针（按引用）

    LDR     r0, =BigBuffer   ; r0 = 缓冲区首地址
    MOV     r1, #256         ; 长度
    BL      ParseNMEA
  • 子程序通过 LDR/STR [r0, #off] 读写内存。
  • **C 里数组、struct *** 就是这种模式。
  • 调用者与子程序须约定：谁分配、谁释放、是否修改。

3. 堆栈传参

调用者：

    MOV     r0, #3
    PUSH    {r0}            ; 第 2 个参数（假设约定栈传）
    MOV     r0, #1          ; 第 1 个参数仍可能在 r0
    BL      AddTwo
    ADD     sp, sp, #4      ; 调用者清理栈（若约定 caller-pops）

被调用者 在序言后读栈：

AddTwo
    STMDB   sp!, {lr}
    LDR     r1, [sp, #4]    ; 偏移依序言压栈字数而定
    ADD     r0, r0, r1
    LDMIA   sp!, {pc}

结果写回栈： 子程序可把 返回值覆盖 到栈上参数槽，调用者 POP 读取 — 较少见，多数用 r0。

偏移计算的坑

子程序 STMDB sp!, {…} 后，参数相对 SP 的偏移 随 保存寄存器个数 变化：

SP_after_prologue = SP_entry - 4×(saved_regs)
参数在 [SP_entry + 4] 或更高 — 需按帧布局手算或画栈图

口述： 栈传参 灵活但易错 — 生产环境优先 AAPCS 寄存器+固定栈布局。

与 AAPCS 的衔接

参数序号 AAPCS (32-bit)
1–4 r0–r3
5+ 栈（降序压入，8 字节对齐）
返回值 r0（64 bit 用 r0+r1）

详见 §13.5。

可复述要点

  1. 快 → 寄存器；大 → 指针；多 → 栈。
  2. 栈传参要画 栈帧图 才算对偏移。
  3. 与 C 互调时 不要自创传参顺序 — 跟 AAPCS。

section-13.5-apcs

Ch 13 · 子程序与堆栈 · 章导读 · 本章概述

为什么需要调用标准

场景 要求
C 调 asm C 编译器按标准放参数；asm 必须同规则读
asm 调 C printf 等期望 r0 = format
多编译器 / 静态库 目标文件 可链接

APCS / ATPCS（旧称）→ AAPCS（ARM Application Procedure Call Standard）— 本书 §13.5 讲同一 契约；AArch64 有 AAPCS64（奔跑吧 用 x0–x7）。

合规汇编例（C 五参、栈上第 5 参、返回 r0） → CSAPP · ABI 实战例

核心寄存器分工（32-bit ARM）

寄存器 AAPCS 角色
r0–r3 参数 + 返回值；调用者保存（callee 可随意改写）
r4–r8, r10, r11 被调用者保存 — 子程序若使用，序言压栈、尾声恢复
r9 平台相关（部分为 TLS）；慎作长期临时
r12 IP — 内部跳转/scratch；调用间可破坏
r13 SP — 必须 8 字节对齐
r14 LR
r15 PC

口述： r0–r3 随便用；r4–r11 用了就要还。

浮点（Cortex-M4 / VFP）

寄存器 角色
s0–s15 参数 + 返回值 + 临时 — 调用者保存
s16–s31 被调用者保存 — 浮点子程序若用须 VPUSH/VPOP 或等价

与 Ch9–11 浮点例程一致：sin 在 s0 进、出。

栈对齐

AAPCS 要求 SP 在 公共接口 处 8 字节对齐**（双字）。

原因
LDRD/STRD、64 bit 参数 需要 8 对齐
调用 C 库 未对齐可能 HardFault 或性能损失

技巧： 奇数个 32 bit 栈参数时，编译器常插 padding 保 8 对齐。

汇编 ↔ C 最小示例

C 侧：

int add(int a, int b);
/* 调用：r0=a, r1=b → 返回 r0 */

Asm 侧：

    .global add
    .type   add, %function
add:
    ADD     r0, r0, r1      ; 只改 r0-r3，无需保存 r4+
    BX      lr

Asm 调 C：

    LDR     r0, =fmt_string
    BL      printf          ; 按 AAPCS 传参；可能破坏 r0-r3,r12

完整 extern、.global、.type → Ch18 混合编程。

与 Linux 内核 / U-Boot

环境 约定
内核 ARM32 内核自有宏 ENTRY/-save，思想同 callee-save
U-Boot 板级 .S 设 SP，bl board_init_f
AArch64 内核 x0–x5 参数；x19–x28 callee-save

→ 20 构建 · 04 LKD

可复述要点

  1. r0–r3：参 + 返；r4–r8,r10,r11：用了必还。
  2. M4：s16–s31 callee-save；s0–s15 随便用。
  3. SP 8 字节对齐 — 调 C 前检查。
  4. 混 C/asm 不是可选 — 违反 AAPCS = 静默数据损坏。
