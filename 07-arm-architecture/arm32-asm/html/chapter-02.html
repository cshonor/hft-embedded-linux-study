2.2

section-2.2-data-types

Ch 2 · 程序员模型 · 章导读

核心先分清：「32 位」≠「内存格子是 32 位」

一句话： 32 位 ARM = 通用寄存器 32 bit + 地址常 32 bit；内存最小单元 永远是 1 字节（8 bit），不是 32 位。

① ARM32 两点（运算块 = 寄存器宽）

  1. CPU 单次通用运算标准粒度 = 32 bit — 加减、逻辑、普通寄存器运算，默认一块就是 32 比特。
  2. 通用寄存器最大宽度 = 32 bit — r0–r15 每个最多存 32 比特；放不下超过 32 位的数 时，用 两个寄存器拼接（惯例：低 32 位在 r0、高 32 位在 r1，如 long long / UMULL 结果）。
概念 是什么 ARM32 上多大
寄存器位宽 临时容器；也是 ALU 一次算多宽 r0–r15 = 32 bit = 4 字节
地址位宽 给内存编号 → 寻址上限 典型 32 bit → (2^{32}) ≈ 4 GB
内存存储单元 每个地址对应的最小格子 永远 1 字节（8 bit） — 与 32/64 无关 
地址 0x00000000 → 1 字节
地址 0x00000001 → 下 1 字节
……连续 4 个地址拼起来 → 才是一个 32 位「字」进 r0

不要说「32 位内存」 — 「32 位」指 寄存器/运算块（+ 常含地址宽），不是每个地址存 32 bit。

ldr  r0, [r1]   @ 读连续 4 字节 → 32 位数进 r0
ldrb r0, [r1]   @ 只读 1 字节到 r0 低 8 位

② 「几位 CPU」怎么判定？

口语里 「32 位 / 64 位 CPU」 的核心标准：

通用寄存器位宽 = CPU 通用整数运算单次处理的数据宽度。

架构 通用寄存器位宽 单次标准运算块 单寄存器最大比特
ARM32（AArch32） 32 32 32
x86-32（IA-32） 32 32 32
x86-64 64 64 64
ARM64（AArch64） 64 64 64

→ 64 位分段细节（rax/eax/ax/al）：CSAPP §3.3

32 位架构的「自然字长」

对象 宽度
基础整数标量上限 32 bit（1 word）
通用寄存器 r0–r12（及 r13–r15） 32 bit
典型 ALU / LDR/STR 主通路 32 bit

口述： 开发者默认 「一个 r 寄存器 = 一个字的数据」；更窄类型用 LDRB/LDRH 读入后再 零扩展/符号扩展 到 32 bit 参与运算（→ Ch5）。

三种基本长度（byte / halfword / word）

类型 一次访问占多少 bit 占多少 byte 典型 C 对应
Byte（字节） 8 bit 1 byte char / uint8_t
Halfword（半字） 16 bit 2 byte short / uint16_t
Word（字） 32 bit 4 byte int / uint32_t · 指针

易混点（口述必清）： 说「8 位字节」= 1 个 byte = 8 个 bit — 不是 8 个 byte。
「8 / 16 / 32」在 ARM 书里通常指 bit 宽度，不是 byte 个数。

Ch1 回顾： 内存与寄存器里都是比特；类型只约定 读多少位、如何解释（有符号/无符号 → Ch1 §1.5）。

对标 x86-64：b/w/l/q ↔ ARM32 的 LDR*/STR*

x86 靠 指令后缀 定宽度；ARM32 没有后缀，靠 不同助记符。C 类型宽度两边一致，硬件写法不同。

C 类型（ARM32 / ILP32） 字节 x86-64 后缀 ARM32 读 ARM32 写 说明
char 1 b ldrb / ldrsb strb Byte
short 2 w ldrh / ldrsh strh Halfword
int / 指针 4 l ldr str Word（ARM32 自然字）
long long 8 q ldrd strd 双字 → 两个 32 位寄存器

符号扩展（读窄类型进 32 位 r）：

无符号（高位补 0） 有符号（符号扩展）
字节 ldrb ldrsb
半字 ldrh ldrsh

x86 用 movz/movs；ARM 直接换指令名。→ 详表见上节 s8/u8…；访存细节 → Ch5。

无 %al/%ax/%eax 分段别名

x86-64 ARM32
同一槽拆分 %al / %ax / %eax / %rax 无 — r0–r15 始终是完整 32 位
取 1 字节 可对 %al 直接运算 用 ldrb/ldrsb 从内存装入；或装入后再移位/掩码（无硬件「低 8 位别名」）

操作数寻址对标（CSAPP §3.4.1）

含义 x86-64（AT&T） ARM32
立即数 $0x4 #0x4 → mov r0, #0x4
寄存器 %rax r0
绝对/全局 0x601000 / xxx(%rip) 少裸地址；常 ldr r1, =var 再访
间接 (%rax) [r0] → ldr r1, [r0]
基址+偏移 8(%rbp) [r1, #8] → ldr r0, [r1, #8] 
/* int a = *(fp + 8); */
/* x86-64 */  movl  8(%rbp), %eax
/* ARM32  */  ldr   r0, [r11, #8]    /* 帧指针常用 r11（fp）；Thumb 可能是 r7 */

/* char c = *p; */
/* x86-64 */  movb  (%rbx), %al
/* ARM32  */  ldrb  r0, [r1]

浮点（VFP）： float → s0–s31；double → d0–d15（两 s 视图）；vldr/vstr — 与 r0–r15 分开（见下节 f32/f64）。

极简： 宽度用 不同 LDR/STR；寄存器 不拆别名；寻址逻辑与 x86 通，语法是 # / []。完整 x86 表 → CSAPP §3.3 · §3.4.1

开发者标量命名：s8/u8 … s32/u32

Smith / 嵌入式资料常用 s = signed、u = unsigned 前缀 + bit 宽度：

类型 bit byte 存储粒度 C 典型 整数 Load/Store
s8 8 1 字节 int8_t LDRSB / LDRB + 扩展
u8 8 1 字节 uint8_t LDRB
s16 16 2 半字 int16_t LDRSH / LDRH + 扩展
u16 16 2 半字 uint16_t LDRH
s32 32 4 字 int32_t LDR
u32 32 4 字 uint32_t LDR

要点：

  • s/u 不改变占用的 byte 数 — 同 8/16/32 bit 比特，解释不同（补码 vs 无符号，→ Ch1 §1.5）。
  • 对齐规则看访问宽度，不看 s/u — u32 与 s32 一样要 4 字节对齐 才能 LDR。
  • Q 定点（Ch7 §7.7）常把 s32 解释成 [-1, 1) 小数 — 仍是 32 bit 字，无 FPU 时的 f32 替代。

对齐 (Alignment)

字对齐（Word alignment）口述： 32 bit 的 字 用 LDR/STR 访问时，起始地址必须是 4 的倍数 — 如 0x0000、0x0004、0x0008；不能放在 0x0001、0x0002、0x0003（ARM7 上常 Data Abort）。

访问宽度 对齐要求 合法地址例 非法地址例
字节 无 0x0001 任意 —
半字（16 bit） 2 的倍数（偶地址） 0x0000、0x0002、0x0006 0x0001、0x0003
字（32 bit） 4 的倍数（地址低 2 bit = 0） 0x0000、0x0004、0x0008 0x0001、0x0002、0x0003

关系： 半字 = 字的一半（2 byte / 16 bit vs 4 byte / 32 bit）。
规定原因： 匹配 CPU 单次处理宽度 — LDRH 一次 16 bit、LDR 一次 32 bit，对齐则 一条指令读满，非对齐则 多次访问或 fault。

ARM7TDMI： 半字/字 非对齐 → 常触发 Data Abort。
Cortex-M4： 部分配置下可容忍非对齐访问（CCR 等），仍建议 默认按上表对齐写。

为何要对齐（效率逻辑）

32 位 CPU 一次总线/Load 操作目标是 32 bit（4 byte）；内存 每个地址 = 1 byte。

字对齐地址 0x0004：
  0x0004 │ 0x0005 │ 0x0006 │ 0x0007  →  一条 LDR 进寄存器（完整一字）

非对齐 0x0003：
  0x0003 │ 0x0004 │ 0x0005 │ 0x0006  →  硬件要么拒绝（Abort），要么拆成多次访问（慢）

口述： 从 4 的倍数 起读，一次 拉满 32 bit 进寄存器；非对齐 = 零散、多周期或 fault — 所以 ARM7 硬要求对齐，M4 虽可放宽，习惯仍按对齐写。

与 C 对照： 02 C 里结构体 padding 就是为对齐；uint32_t *p = (uint32_t*)0x1001 在严格 ARM7 上可能 fault。

内存地址存放示例（Smith §2.2 思路 + 权衡）

原书 §2.2 会用 具体地址 说明：何种 LDR/LDRH/LDRB 合法、何种会 Abort（与上表 0x0004 / 0x0003 同类）。通常 不会 单独算「char 浪费 75%」—— 那是把 访问对齐 和 变量占坑 合在一起时的推论；下面补上这一层，方便和 C 结构体对照。

关键区分：

概念 含义
存放（存储） char 占 1 byte，可以紧挨着放 — 不要求 每个变量都从 4 的倍数起
访问（Load/Store） 用 LDR 读 32 bit 时，起始地址 必须 4 对齐；用 LDRB 读字节则 任意地址

紧凑存放示例（字节可连续，不浪费）：

地址     内容              说明
0x1000   'A'  (char)       LDRB [0x1000] ✓
0x1001   'B'  (char)       LDRB [0x1001] ✓
0x1002   'C'  (char)       LDRB [0x1002] ✓
0x1003   (填充/padding)    若下一项是 int，编译器常留 1 字节 pad
0x1004   0x12345678 (int)  LDR  [0x1004] ✓  ← 字从 4 的倍数起

三个 char 只占 3 byte；int 从 0x1004 做 LDR — 效率与密度兼顾。

若错误地「所有数据都按 4 byte 槽位存 char」（仅作对比，实际不会这样设计）：

0x1000   'A'   + 3 byte 空洞
0x1004   'B'   + 3 byte 空洞
0x1008   'C'   + 3 byte 空洞
→ 3 个 char 占 12 byte，有效数据 3 byte ≈ 利用率 25%（浪费约 75%）

口述： ARM 按 访问宽度 定对齐，不是「每个 char 变量都必须占 4 byte」；LDRB 让字节能密排，LDR 让字能一次读满 — 正是你说的 权衡。

Smith 后续： Ch5 §5.1 用 LDRB/H/STR** 在 **连续地址** 上操作；[Ch16](../../chapter-16-memory-mapped-peripherals/) DAC 用 **STRH` 写 16 bit 寄存器域 — 宽度与对齐跟硬件手册一致。

浮点类型：f32 · f64（VFP / M4F）

§2.2 正文 以 整数 byte/halfword/word 为主；浮点不在 Ch2 展开，而在 Ch9–11（本仓库 OUTLINE 标 跳过，但类型映射在此写全）。

类型 bit byte 内存布局 计算寄存器 全书位置
f32 32 4 1 word，4 字节对齐 s0–s31（单精度） Ch9 §9.4
f64 64 8 双字，起始 4 对齐 d0–d15（= 两 s 拼 64 bit） 同上 · §9.7

和整数的关系：

        ↓

        ↓

f64 / VFP：

  • Cortex-M4F：f32 硬件算 为主；f64 常 软件 libm 或弱支持 — d 寄存器是 s 的 64 bit 视图*（s0+s1 → d0）。

Load/Store 指令关联（预告 Ch5）

  • LDRB / STRB — 字节；LDRSB — 有符号字节
  • LDRH / STRH — 半字；LDRSH — 有符号半字
  • LDR / STR — 字（4B）
  • LDRD / STRD — 双字（8B → 两寄存器）

可复述要点

  1. 「32 位」= 寄存器宽 + 运算块（+ 常含地址宽）；内存格子永远 1 字节 — 别说「32 位内存」。
  2. 64 位整数在 ARM32 上要两个 r 寄存器拼接（ldrd/strd）；判定「几位 CPU」看 GPR/通用运算宽度。
  3. 宽度：x86 用后缀 b/w/l/q，ARM32 用 ldrb/h / ldr / ldrd — C 类型一一对应，无寄存器分段别名。
  4. s8/u8 … s32/u32 映射 byte / halfword / word；s/u 只改解释，不改宽度；窄读用 ldrsb/ldrsh vs ldrb/ldrh。
  5. 32 bit = 字 = r 寄存器自然宽度；LDR 一次拉连续 4 字节。
  6. f32 内存占 4 byte，算在 s；f64 占 8 byte，算在 d**（要 VFP/M4F）。
  7. 对齐 按 访问指令宽度；char 可密排，LDR 字访问 须 4 对齐。
  8. 浮点细节 → Ch9–11；无 FPU → Q 定点 / 查表（Ch7/12/16）。

核心概念：什么是处理器模式？

ARM32（ARM7TDMI / v4T）用 CPSR 低 5 位 M[4:0] 区分当前 7 种模式。

本质两件事：

机制 作用
权限隔离 User 唯一 非特权；其余 6 种全特权 — 可访问 NVIC/MMU/外设/关中断等
异常专用寄存器分组（Bank） 各模式可有 私有 r13/r14、SPSR — 中断进来 不必立刻保存全部寄存器，降低切换开销 
CPSR.M[4:0] 决定「当前模式」
        ↓
换模式 → 换可见的 SP/LR/SPSR 银行（FIQ 还换 r8–r12）
        ↓
异常返回：SPSR → CPSR，LR → PC（→ Ch14 SUBS pc,lr,#n）

与 Cortex-M4 勿混： M4 只有 Thread/Handler + 特权位（§2.4），没有 这套 7 模式。

七种模式总表

模式 缩写 特权 典型触发
User usr 非特权 应用程序正常运行
System sys 特权 内核 手动 写 CPSR 切换
Supervisor svc 特权/异常 Reset · SWI/SVC 系统调用
IRQ irq 特权/异常 普通外设中断
FIQ fiq 特权/异常 高速实时中断
Undefined und 特权/异常 无法识别的指令
Abort abt 特权/异常 预取/数据中止（MMU fault）

逐条拆解

1. User（usr）— 用户模式

项 说明
特权 唯一非特权
用途 上层应用、业务代码
限制 不能关中断、配 MMU、直接碰外设；要硬件服务 → SVC/SWI 进内核
SPSR 无（User 不保存 SPSR）

2. System（sys）— 系统模式

项 说明
特权 特权
用途 OS 内核后台任务 — 与 User 共用同一套 r0–r12、r13、r14（相对 User 视图）
特点 不切 bank 的 r0–r12，又有 完整硬件权限 — 内核线程省上下文切换
触发 内核 写 CPSR 模式位 主动进入；不会 由硬件异常自动进 System

3. Supervisor（svc）— 管理模式

项 说明
特权 特权 / 异常模式
触发 ① 上电 Reset（ARM7 复位进 SVC，非 User）② 执行 SWI/SVC #imm
用途 内核主态、驱动 init、系统调用处理（open/read/write 底层）
寄存器 banked SP_svc、LR_svc、SPSR_svc

4. IRQ — 普通中断模式

项 说明
特权 异常特权
触发 定时器、UART、GPIO 等 普通优先级 外设 IRQ 线
特点 优先级 低于 FIQ；r0–r7 与 User 共用（不 bank）；r13/r14 为 IRQ 私有
软件 ISR 须 手动压栈 会被破坏的 r0–r12 等（→ Ch13/Ch14）

5. FIQ — 快速中断模式

项 说明
特权 异常特权
触发 高速 ADC、DMA、雷达等 低延迟 需求
核心优势 私有 r8–r12（5）+ SP/LR/SPSR（3）= 8 个物理副本 — 少压栈、更快
向量 表末 0x1C 可紧接 handler（→ Ch14 §14.5）

FIQ 专属备份拆解（考点）： → 下文 Bank · FIQ

6. Undefined（und）— 未定义指令模式

项 说明
触发 CPU 译码失败 — 非法 opcode、Thumb/ARM 状态错
用途 ① 崩溃/调试 ② 软件浮点/协处理器仿真（无 VFP 时 trap 进 handler 用整数库算）
关联 Ch14 §14.3

7. Abort（abt）— 中止模式

项 说明
分两类 预取中止（取指非法）· 数据中止（Load/Store 越界、MMU 权限、缺页）
用途 缺页 fault、保护违规 — Linux 用户态缺页 在特权 Abort 路径处理（概念 → 04 LKD）
返回 修复页表后 SUBS pc, lr, #4/#8 重试（Ch14）

极简分类（背诵用）

类 模式
普通运行 User（应用）· System（内核后台）
内核/复位/ syscall SVC
中断 IRQ（普通）· FIQ（快）
错误 UND（非法指令）· ABT（内存/取指 fault）

七种模式 · 手机类比速记（口述版）

教材 ARM7 模型 + 手机比喻 — 便于背诵；真机多为 ARM64/GIC，FIQ 等待遇以概念为准。

# 模式 你的类比 核对
1 User 微信刷朋友圈 — 普通 APP，权限最低 ✓ 唯一非特权
2 System ~~高权限用户程序 / 桌面渲染~~ → 见下修正 ⚠ 易错
3 SVC 装 APP、改设置 — SVC 进内核 ✓ 同步 syscall；Reset 也进 SVC
4 IRQ 音量键、短信通知 — 外设 硬件自动 切入 ✓ 普通中断
5 FIQ 来电、紧急数据传输 — 优先级更高，r8–r12 副本 ✓ 快中断
6 ABT 读已回收内存 — 访问非法地址 ✓ 数据/预取中止

2. System — 需要修正的一条

常见误解 正确理解
「给 高权限的用户程序 用」 System 是 内核代码 用的模式，不是 加强版 APP
「桌面渲染进程从 User 切过来」 现代手机 桌面/渲染多在 User（userspace）；System 典型是 内核线程 — 要 特权，又要和 User 共用 r13/r14（不单独 bank 栈）
「用户程序发指令切换」 只有内核 写 CPSR 模式位 才能进 System；无硬件异常 自动进入

System 一句话： 特权 + 共用 User 那套 r13/r14 — 内核后台跑活，省 bank 切换，又 不污染 各异常模式的专属栈。

User 能直接切哪些模式？System 是中转吗？

你说对的一半：

说法 结论
User 可以直接 进 IRQ（按音量键） ✓ 硬件 异步 异常，不经过 System
User 可以直接 进 SVC（SVC 调接口） ✓ 同步 trap，不经过 System
User 还可 直接 进 FIQ / ABT / UND ✓ 外设中断、内存 fault、非法指令 — 均 无 System 中转
System 不是必经中转站 ✓ 日常路径 User ↔ IRQ / SVC / …，不绕 System 
常见路径（均无 System 中转）：
  User ──音量键 IRQ──→ IRQ ──返回──→ User
  User ──SVC #n──────→ SVC ──返回──→ User
  User ──非法访问────→ ABT ──…────→ User

仍需纠正的一半：

说法 实际
System 是 User 的「高权限升级版」 像 User（共用 r13/r14），但 只有内核 能进 — 不是 APP 自我升级
「特定 用户进程 先切 System 再转其他模式」 用户进程无权写 CPSR — 不能自己进 System；syscall 是 User → SVC 直达
System → 再转 IRQ/SVC 极少这么设计；System 是内核 长时间驻留 跑内核线程，不是进 IRQ 前的跳板

System 与 User 的「像」与「不像」：

User System
谁在用 微信、游戏等 APP 内核线程（内核代码）
特权 非特权 特权
r13/r14 共用 _usr 那对 同一对 _usr（寄存器视图像 User）
怎么进入 正常运行 / 从异常返回 仅内核 写 CPSR；无 专用异常向量
典型路径 APP 主循环 内核后台；不 夹在 User→SVC 中间

口述定稿：

User 可以直跳 IRQ、SVC 等，System 不是中转站。
但 System 也不是用户进程升级用 — 是内核专用的「共用 User 栈视图的特权模式」，只有内核能切进去。

七条口述（定稿版）

  1. User — 最常用；微信、游戏、浏览器；不能直接碰硬件。
  2. System — 内核线程；内核写 CPSR 进入；特权但共用 User 栈视图。
  3. SVC — 内核 syscall 入口；SVC #n 或 Reset；装 APP、改设置底层走这儿。
  4. IRQ — 音量键、短信、定时器；硬件异步切入；压 IRQ 栈。
  5. FIQ — 来电级紧急任务；r8–r12_fiq 免压栈；比 IRQ 快。
  6. ABT — 越界/权限违例/缺页；可杀进程或修复后重试。
  7. UND — 非法 opcode；崩溃或 软件仿真（如无硬件浮点）。

端到端例子：User 打字 → 按键 IRQ → 保存 → 回到 User

模式本质 = CPU「身份切换」： 不同身份 → 不同 权限 + 专属资源（bank）。下面用 Smith 教材最常见的 ARM7 裸机/经典模型 串一遍（Linux 上按键还会经 SVC 系统调用 进内核，那是 Ch14 之后的事；这里先抓 模式 + bank + 压栈）。

七种身份一句话（复习）：

模式 身份角色
User 普通程序 — 权限最低，不能直接改硬件
System 特权 但 与 User 共用 r13/r14 — 跑 内核线程 等需要「用户寄存器视图 + 硬件权限」的代码（不是「高权限版用户 APP」）
SVC 内核主态 — Reset、系统调用、特权指令
IRQ / FIQ 中断服务 — 外设打断正常执行
ABT 内存/取指 fault
UND 非法指令 trap

场景： User 模式在文档程序里打字 → 按 保存 键 → 键盘控制器拉高 IRQ。

① 异常前（User 模式）
   PC 指向打字代码；CPSR.M = User；SP/LR 用 User 那对 r13/r14

② 硬件自动（进 IRQ 身份）
   CPSR.M[4:0]  → IRQ
   LR_irq       ← 返回地址（被打断处 PC，Ch14 再减 #4 修正流水线）
   SPSR_irq     ← CPSR 快照（含原 User 模式位、N/Z/C/V、I/F…）
   SP 视图      ← 换用 r13_irq（中断专用栈，与 User 栈隔离）

③ 软件（IRQ_Handler 开头）
   r0–r7 与 User 共用 → 若 handler 会改它们，须 STMFD 压进 **IRQ 栈**
   （本例只写 r0–r7；若还用 r8–r12，IRQ 下同样要压 — FIQ 才免 r8–r12）

④ 执行保存文件的中断处理代码（特权、可访问外设/驱动）

⑤ 返回 User（软件 + 一条特殊指令）
   从 IRQ 栈 LDMFD 弹出 r0–r7
   SUBS pc, lr, #4  （或 LDMFD …, {…, pc}^）
   → PC 回到打字处；^ / SUBS 副作用：SPSR_irq → CPSR，模式回到 User

为何比「全手动存」快： Bank 已替你 换好中断栈、存好返回地址、快照 CPSR — 不必再把 旧 SP、旧 LR、旧 CPSR 压进内存。软件只需管 仍共用的 GPR（r0–r7 等）。

口述一句：

按保存键 = User 身份被打断 → 切 IRQ 身份用专属栈和状态副本 → 压共用寄存器 → 干完活 → 弹栈 + 写回 CPSR/PC → 继续打字。

端到端例子 2：刷视频 → 来电 FIQ → 挂电话 → SVC 改设置

同一套「身份切换」讲法，换成手机日常 — 串起 User、FIQ、SVC 三种身份：

阶段 模式 在干什么
刷短视频 User APP 业务代码；r0–r12 + User 的 r13 当栈
来电响铃 FIQ 基带等 高优先级 外设打断（教材用 FIQ 讲「快中断」）
挂电话 User 从 FIQ 返回，继续刷视频
改后台设置 SVC APP 执行 SVC/SWI → 同步 trap 进内核做特权操作

现实手机： 多为 ARM64 + GIC，来电未必走 FIQ（Linux 常把 FIQ 留给安全世界或不用）。此处是 ARM7 经典模型 的连贯比喻 — 抓 FIQ 比 IRQ 少压 r8–r12 即可。

① 刷视频（User）

CPSR.M = User
可见：r0–r12，SP = r13（User 栈），PC 在解码/渲染循环里

② 基带拉高 FIQ — 硬件自动

CPSR.M[4:0]  → FIQ
SP 视图      ← r13_fiq（FIQ 专属栈，与用户栈隔离）
SPSR_fiq     ← CPSR（含 User 模式位 — 挂电话后要恢复）
LR_fiq       ← 返回地址（Ch14：返回前 SUBS lr, #4）

③ FIQ_Handler — 软件只压「仍共用」的 r0–r7

r8–r12 已是 r8_fiq–r12_fiq 副本 → 不必压栈（FIQ 快的核心）
r0–r7 仍与 User 共用           → STMFD sp!, {r0-r7}（或更小 live 集）
执行：摘机/振铃/与基带通信等高优先级逻辑

④ 挂电话 — 回到 User 刷视频

LDMFD   sp!, {r0-r7}
SUBS    pc, lr, #4        ; PC 回视频代码，CPSR ← SPSR_fiq → 回 User

不是 单纯 LR_fiq → PC — SUBS/^ 才把 SPSR_fiq 写回 CPSR，模式位一并恢复。

⑤ 系统要改后台设置 — SVC（同步切换，不是外设打断）

User 里 APP 调 settings API
    → 编译器生成 SVC #imm（系统调用号）
    → CPU 同步进 SVC 模式（不是 FIQ 那种异步中断）

硬件：SPSR_svc ← CPSR；LR_svc ← 返回址；SP ← r13_svc（内核栈）
内核：在 SVC 栈上处理 ioctl/write 等特权路径
返回：SUBS pc, lr, #0 或 #4（SVC 流水线偏移与 IRQ 不同 → Ch14）
    → 回到 User，APP 继续跑

与 FIQ 对比（本例要点）：

FIQ（来电） SVC（改设置）
触发 外设 异步 中断 程序 主动 SVC 指令
优先级故事 高 — 少压栈、快返回 同步 trap — 走内核 syscall 路径
Bank r13_fiq, r14_fiq, SPSR_fiq + r8–r12_fiq r13_svc, r14_svc, SPSR_svc
软件压栈 通常只 r0–r7 内核按 AAPCS 保存（Ch13）

口述一句：

刷视频 = User 身份；来电 = 硬件切 FIQ 身份 + 只压 r0–r7；挂电话 = 弹栈 + SUBS 回 User；改设置 = APP 发 SVC 进内核身份，做完再回 User。 每次切换，Bank 替硬件「无缝交接」SP、返回地址、CPSR 快照 — 不必全靠软件逐寄存器搬。

副本寄存器（Bank）核心作用

目标： 减少中断时的压栈/出栈，降低 中断延迟。

若所有模式 共用同一套 r13、r14、r8–r12，一进中断就得把正在用的 全部通用寄存器 先 压栈，返回再 弹出 — 大量内存访问拖慢响应。
硬件为异常模式准备 副本寄存器：切模式 = 换一组硬件实体，不必立刻写内存。

0. 副本的本质 — 物理单元 + 名称映射

你的理解对： Bank 不是「软件复制一份数据」，而是硅片里 独立的物理存储单元；CPSR.M[4:0] 一改，硬件 把当前模式的副本映射到寄存器名上 — 读 r13 在 IRQ 下就是读 r13_irq 那个实体，无需额外持久化到内存。

逻辑名 r13  ──映射──→  User 模式：r13_usr 物理单元
                 ──→  IRQ 模式：r13_irq 物理单元
                 ──→  FIQ 模式：r13_fiq 物理单元

「天然留存」分两类：

副本 切走再切回 说明
r13_*（SP） 还在 IRQ 栈顶上次停在哪，下次进 IRQ 仍从那儿长栈 — 典型「硬件帮你记住」
r8–r12_fiq 还在 FIQ handler 可把 r8_fiq 当 常驻工作区，下次来电不必从栈恢复
r14_、SPSR_ 物理单元在，但 每次进异常硬件会覆写 新 LR ← 返回 PC；新 SPSR ← 当前 CPSR — 不是「上次的 LR 还留着」
r0–r7 无副本 全模式共用同一物理单元 — 必须压栈（上一节）

与共用寄存器对比：

Bank 副本 共用 r0–r7
存储 每模式 独立物理单元 一套 全局单元
切模式 硬件 换映射，旧模式数据 留在原物理单元 映射不变，IRQ handler 一改就 覆盖 User 里的值
持久化 不必 为 SP/FIQ-r8–r12 做栈持久化 必须 STMFD/LDMFD

嵌套异常 caveat（Ch14）： 若 IRQ 里又进 IRQ（或 FIQ 打断 IRQ），新的异常入口会 再次覆写 SPSR_irq / LR_irq — 此时要把 旧的 SPSR/LR 压 IRQ 栈，否则嵌套返回丢上下文。Bank 省的是 常态单次异常 的栈操作，不是无限嵌套免保存。

口述一句：

副本 = 硬件里的「模式专属抽屉」；切模式只是换抽屉，抽屉里东西还在。SP 和 FIQ 的 r8–r12 最像「天然留存」；LR/SPSR 则是每次进门硬件往抽屉里塞一张新纸条（返回址、CPSR 快照）。

Bank ≠ Cache（勿混）：

副本寄存器（Bank） Cache（高速缓存）
是什么 CPU 内核寄存器堆里的 专用物理单元（r13_irq、SPSR_fiq…） CPU 与主存之间的 内存数据缓冲（L1/L2 行）
存什么 模式相关的 SP / LR / SPSR / FIQ-r8–r12 内存地址 上的指令/数据 副本
生命周期 通电即留，直到 同模式被新写入覆盖 或 掉电 临时 — LRU/替换策略 随时 evict，与程序逻辑无关
会不会被「清」 不会 因 Cache miss/替换而丢 — 与 Cache 无关的两个子系统 命中加速；未命中去内存取；行可被踢出
类比 模式 专属小仓库（寄存器级、纳秒级） 内存数据的 临时驿站（加速访存）

下文若写「上下文 保存」指 Bank 帮硬件留上下文 — 不是 Cache 那个「缓存」。

无 Bank（假想）          有 Bank（ARM7）
─────────────────       ─────────────────
异常 → 压满栈保存        异常 → 换 SP/LR/SPSR 视图
     → 慢、易混栈             → FIQ 连 r8–r12 都不用存

1. 独立栈空间 — r13 (SP) 副本

每种异常模式有 专属 SP：r13_svc、r13_irq、r13_fiq、r13_abt、r13_und；User/System 共用 _usr 栈。

场景 用的栈
User 跑应用 用户栈（r13_usr）
进 IRQ 硬件切 r13_irq → 中断栈

好处： 中断 不篡改用户栈；栈 隔离，避免 ISR 把应用栈打爆；不用 进中断前手动改 SP。

→ 启动代码须为 各模式 SP 赋初值（Ch14 Reset）

2. 自动保存返回地址 — r14 (LR) 副本

r14 存 返回地址。异常入口硬件把 带修正的 PC 写入 当前模式的 LR_*。
有副本 中断处理完 SUBS pc, lr, #n 或 BX lr — LR 已是 该模式私有
无副本 须先把 PC 压栈 才能用 LR 做别的事

→ Ch14 §14.4 硬件四步

3. 保存异常前 CPU 状态 — SPSR 副本

CPSR 全局唯一（N/Z/C/V、I/F 屏蔽、T、M 模式位）。
每种 异常模式 有 SPSR_*：

进入异常：SPSR ← CPSR（快照）
退出异常：CPSR ← SPSR（SUBS 写 PC 时附带）

无 SPSR 副本时 须 手动把 CPSR 压栈 — 多指令、易错。
User/System 无 SPSR — 它们不是「从异常返回」的模式。

4. FIQ 专属 r8–r12 — 「5 + 3 = 8」考点拆解

公共基础：

范围 谁用
r0–r7 所有模式共用 同一套物理单元 — 无副本

FIQ 场景（ADC/DMA/雷达）： r0–r7 若够用可 少压栈；r8–r12 完全不用保存 — FIQ 比 IRQ 快的核心硬件原因之一（另：更高优先级、向量可紧接 handler，Ch14）。

5. 稳定性 — 上下文硬件隔离

ABT（内存 fault）、UND（非法指令）各自 SP/LR/SPSR 副本 — 崩溃路径 少污染 正常业务寄存器；与 User 栈隔离 同理，异常间 也靠 不同 bank 减少互相踩数据。

注意： Bank 不替代 全部保存 — r0–r7（及 IRQ 的 r8–r12） ISR 仍常 PUSH（Ch13/Ch14）；Bank 是 硬件已做的那一层。

6. 压栈分工 — 硬件 Bank vs 软件 PUSH

切换模式时硬件自动做的（不靠栈）：

动作 说明
CPSR → SPSR_* 进异常前状态 快照
LR_* ← 返回地址 异常发生点 PC（Ch14 再减 #4/#8）
SP 视图切换 用当前模式的 banked r13
M[4:0] 改写 进入 IRQ/FIQ/SVC/…

硬件不会替你保存的 — 若 ISR 会用到，须 PUSH 到当前模式栈，返回前 POP 恢复：

寄存器 IRQ / SVC / UND / ABT FIQ
r0–r7 共用 → 必须手动压栈（若会破坏） 同左
r8–r12 共用 → 必须手动压栈 r8_fiq–r12_fiq 已 bank → 不必压栈
r13 (SP) 已换 bank，不用压 同左
r14 (LR) 已换 bank 且存返回址，不用压旧 LR 同左
CPSR 已在 SPSR，不用压 同左

常见误区 — 不是压到 A（User）的栈：

错误想法 实际顺序
切到 B 之前，用 A 的 r13 把 r0–r7 压进 User 栈 IRQ 线一拉高，硬件已先切到 B — handler 里 sp 已是 r13_irq
回 A 时从 User 栈 弹出 从 IRQ 栈 弹出，再 SUBS pc,lr,#4 回 User 
错：  User ──压 r0-r7 到 User栈──→ 切 IRQ ──处理──→ 切 User ──从 User栈 弹
对：  User 跑着 ──IRQ 触发──→ 硬件切 IRQ（SP=r13_irq）
                              ──STMFD 压 r0-r7 到 IRQ栈──→ 处理 ──LDMFD 从 IRQ栈 弹──→ SUBS 回 User

为何必须用 B 的栈： 进 IRQ 后 看不见 User 的 r13（bank 已切换）；STMFD sp!, {r0-r7} 里的 sp = r13_irq。User 栈 全程不被 ISR 碰 — 回来 User 的 r13 仍指向原来的用户栈顶，和进中断前一致。

口述纠正：

共用 GPR 存进「当前异常模式的栈」（IRQ 栈 / FIQ 栈），不是进中断前那个 User 栈。 Bank 给 B 专属 r13；软件把 r0–r7 压在这个 r13 指向的 B 栈空间。

口述对照：

Bank 管「换栈、存返回地址、存 CPSR 快照」；栈管「剩下的共用 GPR」。
FIQ 比 IRQ 快，部分是因为 5 个 r8–r12 免压栈 — 少 5 次 Store、少 5 次 Load。

典型 IRQ 入口骨架（Ch13/Ch14 展开）：

IRQ_Handler
    SUB     lr, lr, #4          ; 修正返回 PC
    STMFD   sp!, {r0-r12, lr}   ; 软件保存共用 GPR + 旧 lr（若用 AAPCS 可能只压子集）
    ; ... 处理中断 ...
    LDMFD   sp!, {r0-r12, pc}^  ; 恢复并 SUBS 写 PC → CPSR ← SPSR

FIQ 若 只用 r0–r7 + r8_fiq–r12_fiq，可 只压 r0–r7（甚至更小子集），handler 更短。

一句话

副本寄存器 = 硬件自带的快速上下文保存（Bank，非 Cache） — 用少量额外硅片，换 少堆栈访问、低延迟中断、栈/返回地址/状态隔离。

Cortex-M4 是什么（定位）

Cortex-M4 = ARM 32 位嵌入式内核（ARMv7-M），主打 控制 + 适度 DSP。比 M3 多 更强 DSP 指令；FPU 可选（带则为 M4F）。常见于手表、工控、汽车电子；STM32F4 多用此内核。

M4 ≠ ARM7 换皮：模型从 7 模式 Bank → Thread/Handler + 硬件压栈（下文 + Ch15）。

一、运行模型：2 种模式 + 2 级特权

1. 两种运行模式

模式 说明
Thread Mode 普通应用 / 用户任务正常执行；上电默认进入
Handler Mode 任意中断/异常 自动进入；固定特权；异常返回自动回 Thread

2. 两级访问特权

级别 能力
Privileged 可操作 NVIC、MPU、CONTROL、系统控制块 等；内核与异常处理默认特权
Unprivileged (User) 访问内核寄存器受限 — RTOS 隔离业务任务，防篡改内核配置

组合关系（口述）：

Handler Mode  →  永远 Privileged
Thread Mode   →  Privileged 或 Unprivileged（由 CONTROL 决定）

上电复位后典型：Thread + Privileged + MSP；跑 RTOS 时再切 Thread Unprivileged + PSP。

2）两大核心作用

(1) MSP / PSP 双栈

4. 两个独立概念：执行模式 vs 特权等级

勿混： Thread/Handler 是 「此刻在跑什么场景」；特权/用户是 「Thread 里这张权限标签」。

① 执行模式（全局只有 2 种，不是每个任务专属一套）

模式 何时 特权
Handler 进中断/异常 自动切 永久 Privileged，不可改成用户态
Thread 正常跑业务代码 特权等级 可切换（CONTROL）

所有任务 共用 这套划分：CPU 同一时刻只有一种执行模式；切任务不「自创第三种模式」。

② 特权等级（Privileged / Unprivileged）
作用域 主要约束 Thread（Handler 锁死特权）
Privileged 可碰 NVIC / MPU / CONTROL / 系统控制寄存器 — 内核、初始化默认
Unprivileged 硬件限制上述访问 — 普通业务任务，防篡改内核配置

1. 运行模式

ARM7（v4T） Cortex-M4（v7-M）

4. M4 相对 ARM7 五大优势（口述）

  1. OS 友好 — CONTROL：双栈 + 权限，少写汇编保护
  2. 中断更实时 — 硬件压帧，延迟更可量化
  3. 代码更小 — 向量表指针；C ISR 少装配
  4. 任务隔离 — Thread Unprivileged + MPU（可选）收紧用户任务（ARM7 有 User，但 无 MSP/PSP + CONTROL 这套 RTOS 接口）
  5. 模型更简 — 两种顶层模式，无 7 模式迷宫

1. 数据宽度与对齐（§2.2）

知识点

LDR Rd,[Rn] 读 32 位字。经典 ARM 严格对齐：地址须为 4 的倍数（低 2 位 = 00，addr % 4 == 0）。非对齐直接字访问 → fault / 未定义行为（教材按严格对齐判）。

M4 可配置允许非对齐；本考点按 §2.2 / ARM7 严格规则答。

0x20000004 4 % 4 = 0 可以
0x20000001 1 % 4 = 1 不可以

3. CPSR · N/Z/C/V（§2.3）

标志定义

位 含义
N 结果最高位 = 1（有符号负）→ 1
Z 结果全 0 → 1
C 加法：进位；减法：C = ¬借位（有借位则 C=0）
V 有符号溢出 → 1

⚠ ARM 减法 C 标志陷阱： 「产生借位」≠「C=1」。有借位时 C 清 0。

例题

SUBS r0, r0, #1，r0 初值 0x00000000：

  1. 运算：0 - 1 = 0xFFFFFFFF
  2. 标志：
位 值 理由
N 1 最高位 1
Z 0 结果非 0
C 0 发生借位 → ARM 规定 C=0（不是 1）
V 0 有符号 0→−1，无溢出

易错：把「有借位」写成 C=1。背：减法有借位 → C=0。

5. MSP / PSP 双堆栈（§2.4）

例题

Q1. 什么场景用 MSP？什么场景用 PSP？
MSP 复位初始化、Handler（中断/异常）、内核代码
PSP Thread 下普通用户 / RTOS 业务任务

Q2. RTOS 切任务口述（双栈视角）：

  1. 当前任务触发 PendSV → Handler，强制 MSP
  2. 内核把任务现场保存到 该任务的 PSP（硬件已可能压过 8-word 帧；软件再存 R4–R11 等 → Ch15）
  3. OS 改 PSP 指向下一就绪任务栈
  4. 异常返回 → Thread，新任务用自己的 PSP 跑
  5. 内核 / 中断全程靠 MSP，任务栈彼此隔离
