Ch3 完整总结 · 加载与存储 LDR / STR

《ARM64体系结构编程与实践》 · 奔跑吧Linux社区 · 精读
章导读 · OUTLINE · 全书总结 · Pi5 适配

本章定位

AArch64 是 Load-Store 架构：只有 LDR/STR（及变体）能碰内存；ALU 只能操作寄存器。
实验： 优先 QEMU -M virt -cpu cortex-a76，不必上 Pi5 裸机。

3.1 Load-Store 核心规则

  1. 算术 / 移位 / 位运算 → 只能操作寄存器，不能直接读写内存地址。
  2. LDR：从内存读入寄存器。
  3. STR：把寄存器写入内存。
  4. A64 指令 固定 32-bit 定长。

对比 x86：x86 可「内存直接参与加减」；ARM64 必须先 LDR → 运算 → 再 STR。

3.2 寄存器宽度与访存宽度

名字 含义
Xn 64 位完整寄存器
Wn 低 32 位；写 Wn → 高 32 清零
指令 作用 宽度
LDR x0, [x1] 读 8 字节 → x0 64
LDR w0, [x1] 读 4 字节 → w0，x0 高 32 清零 32
LDRB 读 1 字节 8
LDRH 读半字 16

记法：B=Byte(8)、H=Half(16)、Word≈32、X=64。
带 S：LDRSB / LDRSH = 符号扩展；不带 S = 零扩展。
（同一字节、不同指令 → 见 SIGNED-UNSIGNED.md。）
（勿与 ADDS 末尾 S 混淆：那边是 Set flags → S-SUFFIX.md。）

3.3 五大寻址模式 ⭐

基址 Xn，偏移 #offset。

1. 基址偏移（最常用，基址不变）

ldr x0, [x1, #8]   ; 地址 = x1+8；x1 本身不变

2. 前变基（!，先算地址再访问，并写回基址）

ldr x0, [x1, #16]! ; 地址=x1+16；结束后 x1 = x1+16

3. 后变基（先访问，再改基址）

ldr x0, [x1], #24  ; 地址=x1；结束后 x1 = x1+24

前变基：先加再访；后变基：先访再加。

4. 无符号负偏移 · LDUR / STUR

ldur x0, [x1, #-8] ; 支持负偏移（栈上下访问常用）

5. 寄存器偏移

ldr x0, [x1, x2]           ; 地址 = x1+x2
ldr x0, [x1, x2, lsl #3]   ; x2<<3，适合 8 字节元素数组

3.4 LDP / STP（栈操作主力）

AArch64 没有 PUSH / POP；栈靠 STP / LDP。

; 压栈：保存 FP(x29)、LR(x30)；栈向下长，sp 减小
stp x29, x30, [sp, #-16]!
; 出栈
ldp x29, x30, [sp], #16
  • 一对 64 位寄存器 = 16 字节
  • 函数入口保存 FP+LR = AAPCS64 标准写法

3.5 LDR 伪指令 ldr x0, =label ⭐易踩坑

写法 是什么
ldr x0, [x1] 真机器指令，访存
ldr x0, =val GNU 伪指令；汇编器把常量放进 .litpool，再生成真 LDR 从文字池读

MOV 限制： 大体只能 16 位立即数，或移位 16/32/48 位；多数 64 位大常量 → ldr x0, =xxx。

3.6 特殊访存（多核 / 内核会见到）

指令 用途
LDXR / STXR 独占加载/存储；监视器 + 失败返回非 0 → CAS / 自旋锁原语
LDAR / STLR Load-Acquire / Store-Release（自带内存序语义）
LDTR / STTR 非特权访问；EL1 可用 EL0 权限碰用户地址

（独占与屏障细节在 Ch18–20 展开。）

3.7 典型实操

  1. memcpy 骨架： 循环 LDR 源 → STR 目标
  2. 函数栈帧： STP/LDP 保存 x29、x30
  3. 数组： [base, index, lsl #3]（8 字节元素）

GDB：info registers、x 看内存；单步对比前/后变基与 STP/LDP。

3.8 易错点清单

  1. ALU 不能碰内存（Load-Store）。
  2. 真 LDR vs ldr = 伪指令 / litpool。
  3. ! 前变基 vs 后变基 —— 基址会不会改。
  4. 无 PUSH/POP → STP/LDP。
  5. LDRSB 符号扩展 vs LDRB 零扩展。

书中思考题（自测）

  1. 为什么叫 Load-Store 架构？
  2. ldr x0,[x1,#8] 与 ldr x0,[x1,#8]! 区别？
  3. 没有 push/pop，函数入口怎么保存 FP 与 LR？
  4. ldr x0,=0x12345678deadbeef 是真机器指令吗？底层怎么实现？
  5. LDRSB 与 LDRB 读 1 字节差异？

参考答案：

  1. 只有加载/存储访存；运算只在寄存器。
  2. 前者地址=x1+8，x1 不变；后者访问后 x1+=8。
  3. stp x29, x30, [sp, #-16]!（再配合出栈 ldp ... [sp], #16）。
  4. 不是；伪指令 → 文字池 + 真 LDR。
  5. LDRSB 符号扩展；LDRB 零扩展。

3.1

Load-Store 核心规则

来源：§3.1 · 精读 · 章总览

本节讲什么

AArch64 是 Load-Store 架构——只有 LDR/STR 能访存，ALU 只能操作寄存器。本节澄清两个新手最常困惑的点：中括号 [x1] 到底代表什么、LDR 指令操作数的左右含义。

核心要点

  1. 算术/移位/位运算 → 只能操作寄存器，不能直接读写内存
  2. LDR：内存→寄存器；STR：寄存器→内存
  3. A64 指令 固定 32-bit 定长

对比 x86：x86 可 add eax, [mem]（内存直接参与运算）；ARM64 必须先 LDR → 运算 → STR。

中括号 [x1] 的语义：寄存器内容 = 内存地址

[x1] 中括号内的 x1 是寄存器编号，不是变量名，不是数据段符号。

ldr x0, [x1]
; [x1] 的含义：把 x1 寄存器里面存的数值当作内存地址
; 去这个内存地址读 64bit 数据，放到 x0 寄存器
  • x1（不带括号） = 寄存器本身，代表寄存器里面的值 asm mov x0, x1 ; 把 x1 的值复制给 x0，不访问内存
  • [x1]（带中括号） = 把 x1 里面的值当成内存地址，去内存读/写 asm ldr x0, [x1] ; 访问内存！x1 存的是地址，读该地址的数据到 x0

LDR 指令操作数含义

LDR  Rd, <address>
     │╰───────────── 左边：目标寄存器，存放读出来的数据
     ╰────────────── 右边：内存地址（放在[]），不是数据

执行流程（3 步）： 1. 取出寄存器 x1 里面的值，当作内存地址 A 2. 从内存地址 A 读出 8 字节（64 位）数据 3. 将读出的数据存入寄存器 x0

带偏移的例子：

ldr x0, [x1, #8]
; 右边地址 = x1 的值 + 8；从该内存地址读数据送入 x0

mov vs ldr：最大的新手坑

指令 操作 访问内存？
mov x0, x1 复制寄存器值 ❌ 不碰内存
ldr x0, [x1] x1 存地址，去内存读 ✅ 访问内存

访问数据段变量：ADRP + LDR 两步走

AArch64 的 LDR 中括号内部只能放寄存器 + 立即数/另一个寄存器，不能直接放 C 语言变量名/符号。不能写 ldr x0, [my_var]。

; ❌ 错误：AArch64 不支持直接把符号放中括号
ldr x0, [my_var]

; ✅ 正确：先用 ADRP 把变量地址读到寄存器，再用寄存器访问
adrp x1, my_var   ; 把 my_var 变量的地址加载进 x1
ldr  x0, [x1]     ; [x1]，x1 存着变量地址，读变量的值到 x0

STR：LDR 的反向操作

str x0, [x1]
; 把左边寄存器 x0 的数据，写入右边 [x1] 代表的内存地址
指令 数据流向 左操作数 右操作数
LDR x0, [x1] 内存 → 寄存器 目标寄存器 内存地址
STR x0, [x1] 寄存器 → 内存 源寄存器 内存地址

HFT 关联

Load-Store 架构对 HFT 性能的影响：

方面 影响 HFT 策略
更多指令 每次内存运算需 LDR→ALU→STR 三步 热路径数据尽量保持在寄存器中
简单解码 定长 32-bit 指令，流水线可预测 IPC 稳定，延迟确定性优于 x86 变长指令
显式访存 程序员/编译器可精确控制 cache 行为 手动预取 prfm 配合 LDR
寄存器压力 31 个通用寄存器，溢出时 spill 到栈 热路径函数控制局部变量数量
ADRP+LDR 两步 访问全局变量需先取地址 HFT 热路径避免全局变量，用寄存器传参

自测题

  1. 为什么 ARM64 叫 Load-Store 架构？
答案

因为只有 LDR/STR 指令能访问内存，所有算术/逻辑运算只能在寄存器之间进行。内存数据必须先加载到寄存器才能参与运算。

  1. 以下 x86 代码在 ARM64 上需要几条指令？
add eax, [rbx]
答案

3 条：ldr w1, [x2] → add w0, w0, w1 → str w0, [x2]（如果需要写回）。ARM64 不能内存直接参与运算。

  1. A64 指令为什么是 32 位定长？
答案

简化指令解码和流水线设计。定长指令不需要对齐检测和变长解码逻辑，减少解码延迟，适合高频流水线。

  1. 假设 x1 = 0x4000，内存 0x4000 处存放数值 0x1234。执行 ldr x0, [x1] 后，x0 和 x1 分别是什么？
答案

x0 = 0x1234（从内存地址 0x4000 读出的数据）；x1 不变，仍然是 0x4000（基址偏移模式不写回基址寄存器）。

  1. mov x0, x1 和 ldr x0, [x1] 的区别是什么？
答案

mov x0, x1：寄存器间复制，把 x1 的值赋给 x0，不访问内存。 ldr x0, [x1]：把 x1 的值当作内存地址，去该地址读数据到 x0，访问内存。 核心区别：中括号 [] 的有无决定了是否触发内存访问。

  1. 要访问数据段中的变量 my_var，为什么不能直接写 ldr x0, [my_var]？应该怎么写？
答案

AArch64 的 LDR 中括号内只能放寄存器 + 立即数/寄存器偏移，不能直接放符号名。正确做法是两步：

adrp x1, my_var   ; 第一步：把变量地址加载到寄存器
ldr  x0, [x1]     ; 第二步：用寄存器作为地址访问内存

这是因为 A64 指令固定 32 位，无法在一条指令内同时编码符号地址和访存操作。

  1. str x0, [x1] 执行后，数据流向是什么？
答案

寄存器 → 内存。左边 x0 是源数据（寄存器），右边 [x1] 是目标地址（内存）。x0 的值被写入 x1 所指向的内存地址。与 LTR 方向相反：LDR 是内存→寄存器，STR 是寄存器→内存。

3.2

寄存器宽度与访存宽度

来源：§3.2 · 精读 · 章总览

本节讲什么

LDR/STR 家族的宽度变体（B/H/W/X）、符号扩展 vs 零扩展的区别、LDUR 负偏移支持。附中括号 [] 内部合法写法汇总。

核心要点

命名规则

后缀 含义 说明
B Byte 8bit 读/写 1 字节
H Halfword 16bit 读/写 2 字节
W Word 32bit 读/写 4 字节（ldr w0）
X 64bit 读/写 8 字节（ldr x0）
S Sign-extend 符号扩展 不带 S = 零扩展
UR Unscaled offset 非缩放偏移 支持有符号负立即数
  • 没有 "LDRU" 这条指令——是 LDUR（UR = unscaled offset）
  • 没有 "LDRS" 独立指令——S 是后缀：LDRSB / LDRSH / LDRSW

内存基本铁律：每个地址存 1 字节

硬件铁律：内存每一个地址，存 1 个字节（8bit），永远不变。

那为什么会有 LDRH（2 字节）、LDR W（4 字节）、LDR X（8 字节）？

→ 一条 load 指令，可以一次从连续多个内存地址批量读出多个字节，拼成一个大数放进寄存器。

地址 0x1000：字节 #0
地址 0x1001：字节 #1
地址 0x1002：字节 #2
地址 0x1003：字节 #3
指令 起始地址 读取哪些地址 共几字节 结果宽度
ldrb w0, [x2, #0x1000] 0x1000 仅 0x1000 1 字节 8bit
ldrh w0, [x2, #0x1000] 0x1000 0x1000, 0x1001 2 字节 16bit 半字
ldr w0, [x2, #0x1000] 0x1000 0x1000~0x1003 4 字节 32bit 字
ldr x0, [x2, #0x1000] 0x1000 0x1000~0x1007 8 字节 64bit 双字

关键澄清： - ✔ 每个内存地址 = 1 字节，永远不变 - ✔ LDRH / LDRW / LDRX 不是"一个地址存多字节" - ✔ 而是：给一个起始地址，指令自动向后读连续 N 个地址，把一堆字节拼成一个大数放到寄存器

大小端：多字节拼接的顺序问题

读连续多字节时，CPU 要决定：起始地址的字节，是数字的低位还是高位？

  • 小端（Little-Endian）：起始地址 = 最低字节。树莓派 5（AArch64）默认小端。
  • 大端（Big-Endian）：起始地址 = 最高字节。
内存：
0x1000: 0x11
0x1001: 0x22

ldrh w0, [x0, #0x1000]
小端 → w0 = 0x2211   （起始地址 0x1000 的字节 0x11 是最低位）
大端 → w0 = 0x1122   （起始地址 0x1000 的字节 0x11 是最高位）

对齐要求（AArch64）

指令 读取宽度 起始地址对齐要求
LDRB 1 字节 无要求（任意地址）
LDRH 2 字节 偶数（2 字节对齐）
LDR W 4 字节 4 字节对齐
LDR X 8 字节 8 字节对齐
STP/LDP (X) 16 字节 16 字节对齐（ABI 强制）
  • 不对齐会触发对齐异常（Synchronous Exception，ESR 记录）
  • 可以通过 SCTLR_ELx.A 位开启非对齐访问，但性能受损（可能拆成多次总线事务）
  • STP/LDP 的 16 字节对齐是 AAPCS64 ABI 硬性要求，SP 必须永远保持 16 字节对齐

S 后缀与内存无关

S（符号扩展）是在数据读到寄存器之后才做的操作，跟内存本身无关：

内存只存原始字节 → LDR 读出 N 字节 → S 后缀决定如何扩展到目标宽度
                                    ├─ 不带 S：零扩展（高位补 0）
                                    └─ 带 S：  符号扩展（高位补符号位）
  • 内存本身只存原始字节，不关心你用 LDRB 还是 LDRSB 读
  • S 后缀只影响读出后的扩展行为和目标寄存器（W vs X）

中括号 [] 内部可以放什么

[] 整体含义：括号内部表达式计算出一个内存有效地址，去这个地址读写内存。只允许以下 5 种写法：

# 写法 语法示例 有效地址 说明
1 单个基址寄存器 [x1] X1 最基本形式
2 基址 + 正立即数偏移 [x1, #16] X1 + 16 只支持正数
3 基址 + 立即数 + ! 预索引 [x1, #16]! X1 + 16 访问后写回 X1
4 基址 + 偏移寄存器 [x1, x2] X1 + X2 寄存器偏移
5 基址 + 偏移寄存器 + 移位 [x1, x2, lsl #3] X1 + (X2<<3) lsl 只能 0/1/2/3

! vs 后索引的区别： - ! 写在中括号里面末尾 → 预索引（前变基），属于中括号语法 - #16 写在中括号外面 → 后索引（后变基），不属于中括号内部

ldr x0, [x1, #16]!   ; 预索引：地址=X1+16，访问后 X1=X1+16
ldr x0, [x1], #16    ; 后索引：地址=X1（[]内只算X1），读完 X1+=16
  • ❌ 中括号不能直接放 C 变量符号：ldr x0, [my_var] 语法错误
  • 要先 adrp x1, my_var 再 ldr x0, [x1]

LDR 家族完整指令表（读内存 → 寄存器）

指令 示例 读取宽度 扩展行为 目标寄存器 注意点
LDR ldr x0, [x1] 64bit 直接 64 位加载 X 寄存器
LDR ldr w0, [x1] 32bit 零扩展，高 32 位清零 W 寄存器
LDRB ldrb w0, [x1] 8bit 零扩展到 32 位 只能 Wn 不能写 Xn
LDRH ldrh w0, [x1] 16bit 零扩展到 32 位 只能 Wn 不能写 Xn
LDRSB ldrsb x0, [x1] 8bit 符号扩展到 64bit X 寄存器 有符号 int8_t
LDRSB ldrsb w0, [x1] 8bit 符号扩展到 32bit W 寄存器 有符号 int8_t
LDRSH ldrsh x0, [x1] 16bit 符号扩展到 64bit X 寄存器 有符号 int16_t
LDRSH ldrsh w0, [x1] 16bit 符号扩展到 32bit W 寄存器 有符号 int16_t
LDRSW ldrsw x0, [x1] 32bit 符号扩展到 64bit X 寄存器 有符号 int32_t
LDUR ldur x0, [x1, #-8] 64bit 同 LDR X 寄存器 支持负立即数偏移

3.3

五大寻址模式

来源：§3.3 · 精读 · 章总览

本节讲什么

AArch64 LDR/STR/LDP/STP 通用的五种内存寻址模式。基址寄存器 Xn 配合偏移量计算有效地址；! 代表写回基址寄存器（前变基）。栈操作大量使用前变基（压栈）和后变基（出栈）。

核心要点

五大寻址模式总表

# 模式 语法示例 有效地址 基址 Xn 变化 典型用途
1 基址偏移（偏移模式） ldr x0, [x1, #8] X1 + 8 不变 结构体成员访问，数组，最常用
2 前变基（预索引，!写回） ldr x0, [x1, #16]! X1 + 16 写回 X1+16 栈压栈 stp x0,x1,[sp,#-16]!
3 后变基（后索引） ldr x0, [x1], #24 X1 写回 X1+24 数组循环遍历，出栈 ldp x0,x1,[sp],#16
4 LDUR/STUR 负偏移 ldur x0, [x1, #-8] X1 + (-8) 不变 栈帧内部访问栈上局部变量
5 寄存器偏移（可移位） ldr x0, [x1, x2, lsl #3] X1 + (X2 << 3) 不变 数组索引：X1 基地址，X2 下标

前变基 vs 后变基口诀

  • 前变基 !：先算地址，再访问，写完回写基址
  • 后变基：先访问，后改基址；偏移写在方括号外面

LDR vs LDUR 关键区别

普通 LDR/STR 立即数偏移只支持正数；要负立即偏移，必须用 LDUR / STUR。

ldur x0, [sp, #-8]    // 正确：允许负偏移
ldr  x0, [sp, #-8]    // 语法错误！汇编报错

立即数范围对比：

指令 立即数类型 范围 说明
LDR/STR 无符号 0 ~ 32760（64位，8的倍数） 只支持正偏移
LDUR/STUR 有符号 -256 ~ +255 支持负偏移，设计用于栈帧小范围访问

寄存器偏移的 LSL 移位选项

寄存器偏移只支持 lsl（逻辑左移），移位量 0~3，对应元素大小：

移位量 元素大小 适用数组类型 示例
lsl #0（或省略） 1 字节 char / uint8_t ldr x0, [x1, x2]
lsl #1 2 字节 short / uint16_t ldrh w0, [x1, x2, lsl #1]
lsl #2 4 字节 int / uint32_t ldr w0, [x1, x2, lsl #2]
lsl #3 8 字节 long / uint64_t / 指针 ldr x0, [x1, x2, lsl #3] 
// long long arr[]; arr[x2] 的地址 = arr_base + x2 * 8
ldr x0, [x1, x2, lsl #3]

混淆案例：同一初始值，三种模式对比

初始：x1 = 0x1000

// 1. 基址偏移
ldr x0, [x1, #8]      // 访问 0x1008；x1 依旧 = 0x1000

// 2. 前变基 !
ldr x0, [x1, #16]!    // 访问 0x1010；执行完 x1 = 0x1010

// 3. 后变基
ldr x0, [x1], #24     // 访问 0x1000；执行完 x1 = 0x1018

STP/LDP 栈操作：前变基与后变基的标准实践

STP/LDP 就是前变基、后变基在函数序言/结语中的直接应用：

// 函数序言 (prologue) — 前变基：先 sp-=16，再压入 FP+LR
stp x29, x30, [sp, #-16]!
mov x29, sp              // 设置新帧指针

// 函数体...

// 函数结语 (epilogue) — 后变基：先读出 FP+LR，再 sp+=16
ldp x29, x30, [sp], #16
ret                      // ret = br x30（跳回 LR）

这是每个 AArch64 函数的标准骨架：前变基分配栈帧，后变基释放栈帧。

补充：PC 相对寻址（ADR / ADRP，第六种，独立一类）

不属于上面 5 种 Load-Store 寻址，用于位置无关代码（PIC），计算地址本身（不访问内存）：

adr  x0, label    // 小范围 PC 相对，±1MB
adrp x0, label    // 4KB 页粒度，大范围，±4GB
  • ADR：当前 PC ± 1MB，返回精确标签地址
  • ADRP：当前 PC 所在 4KB 页基址 + 页偏移，范围 ±4GB，低位清零
  • 用途：PIC 代码、内核页表构建、全局变量地址加载

HFT 关联

寻址模式选择影响代码密度和性能：

场景 推荐模式 原因
数组遍历 后变基 [x1], #8 一条指令完成"取值+指针前进"，无额外 ADD
结构体字段 基址偏移 [x1, #16] 编译器自动算字段偏移，零开销
数组随机索引 寄存器偏移 [x1, x2, lsl #3] arr[i] 一条指令，i 在寄存器中
栈帧分配/释放 前变基/后变基 ! 省掉单独的 add/sub sp 指令
栈帧局部变量 LDUR [sp, #-8] 向下访问栈帧，支持负偏移
  • HFT 热路径中，后变基遍历比"LDR + ADD 两指令"少一条指令，减少流水线气泡
  • 寄存器偏移的 lsl #3 让定宽数组访问无需乘法指令，对 tick 数组、订单簿数组至关重要
  • PC 相对寻址（ADRP）在共享库热路径中避免 GOT 间接跳转，减少一次数据 Cache miss

自测题

  1. ldr x0, [x1, #8] 和 ldr x0, [x1, #8]! 执行后 x1 的值相同吗？
答案

不同。前者 x1 不变（基址偏移模式）。后者 x1 = x1 + 8（前变基模式，! 表示写回）。

  1. 写出遍历 8 字节数组元素的代码，每次取一个元素并前进指针。
答案 
loop:
    ldr x0, [x1], #8   // 取 x1 处的 8 字节到 x0，然后 x1 += 8（后变基）
    // 处理 x0...
    b loop
  1. 为什么 LDUR 要单独存在？ldr x0, [x1, #-8] 不行吗？
答案

LDR 的立即数偏移是无符号的，不支持负偏移。LDUR（Unscaled）支持有符号立即数（-256 ~ +255），常用于栈帧向下访问（如访问调用者的局部变量）。

  1. 初始 x1 = 0x1000，执行 ldr x0, [x1, #16]! 后 x0 访问的地址和 x1 的新值分别是什么？
答案

x0 访问地址 = 0x1000 + 16 = 0x1010（十进制 16 = 十六进制 0x10）。x1 新值 = 0x1010（前变基写回）。注意不是 0x1016——立即数 #16 是十进制。

  1. 数组元素是 32 位 int，基址在 X0，下标在 X1，写出寄存器偏移指令。
答案 
ldr w0, [x0, x1, lsl #2]   // lsl #2 对应 4 字节元素（32位）

lsl #2 等价于乘以 4。用 w0 而非 x0 因为是 32 位加载。

  1. stp x29, x30, [sp, #-16]! 属于哪一种寻址模式？为什么函数序言用它而不是后变基？
答案

前变基（预索引）。函数序言需要先减小 SP 再写入——栈向下生长，必须先 sp -= 16 腾出空间，然后才能把 FP/LR 写入新栈顶。如果用后变基 stp x29,x30,[sp],#-16，会先写当前 SP 位置（覆盖调用者栈帧），再减小 SP，导致数据写错位置。

3.4

LDP / STP 栈操作主力

来源：§3.4 · 精读 · 章总览

本节讲什么

AArch64 没有 PUSH/POP 指令，栈压栈弹栈全部用 STP/LDP 实现。STP（Store Pair）把两个寄存器存入连续内存，LDP（Load Pair）从连续内存读出到两个寄存器。本节详解三种寻址模式、内存排布规则和硬性约束。

核心要点

基本概念

  • STP：Store Pair，把两个寄存器存入连续内存
  • LDP：Load Pair，从连续内存读出到两个寄存器
  • 64 位 X 寄存器版本：一次操作 16 字节（8+8）
  • 32 位 W 寄存器版本：一次操作 8 字节（4+4）

三种寻址模式

⚠️ 重要限制：LDP/STP 不支持寄存器偏移寻址 [x1, x2, lsl #3]，只支持基址立即偏移、预索引 !、后索引。

1）普通偏移模式（基址不变）

stp x0, x1, [sp, #16]
; [sp+16] = x0，[sp+24] = x1；sp 的值不改变

ldp x2, x3, [sp, #16]
; x2 ← [sp+16]，x3 ← [sp+24]；sp 不变

2）预索引（前变基，! 写在中括号内）——压栈标准写法

stp x0, x1, [sp, #-16]!
; 1. sp = sp - 16
; 2. [sp] = x0，[sp+8] = x1
; 等价 PUSH {x0,x1}，AArch64 压栈标准写法

3）后索引（后变基，立即数写在中括号外面）——弹栈标准写法

ldp x0, x1, [sp], #16
; 1. x0 ← [sp]，x1 ← [sp+8]
; 2. sp = sp + 16
; 等价 POP {x0,x1}，弹栈标准写法

内存排布规则

stp xA, xB, [x1]
; 内存[x1]     = xA（第一个寄存器存在低地址）
; 内存[x1 + 8] = xB（第二个寄存器存在高地址）

为什么第二个寄存器是 +8？

+8 的来源是 X 寄存器的宽度：

  • X 寄存器是 64 位 = 8 字节
  • 第一个寄存器 xA 占 x1 ~ x1+7（8 字节）
  • 第二个寄存器 xB 紧接其后，起始地址就是 x1 + 8，占 x1+8 ~ x1+15（8 字节）
  • 整个 STP 一口气写 16 字节内存，正好两个 X 寄存器

完整内存布局示例（sp = 0x8000，执行 stp x0, x1, [sp]）：

地址        内容
0x8000      x0 低字节    ← [sp]
0x8001      ...
0x8002      ...
...
0x8007      x0 高字节    (8字节)
0x8008      x1 低字节    ← [sp + 8]
0x8009      ...
...
0x800F      x1 高字节    (8字节)

寄存器宽度 → 相邻元素地址差速查表

寄存器 位宽 占用字节数 相邻元素地址差 对应 Load-Store 后缀
X（64bit） 64 8 +8 LDR/STR
W（32bit） 32 4 +4 LDR W/STR W
H（16bit）半字 16 2 +2 LDRH/STRH
B（8bit）字节 8 1 +1 LDRB/STRB

同理看普通 LDR 的 +8：

ldr x0, [x1, #8]
; #8 就是 +8，访问地址 = x1 + 8
; 从 x1+8 开始读 8 字节（1个X寄存器）到 x0

W 寄存器版本就不同——stp w0, w1, [sp] 中第二个寄存器在 [sp + 4]（4 字节偏移），总共写 8 字节。

⚠️ 常见混淆：STP 用 X 寄存器时第二参数偏移是 +8（不是 +16），+16 是整个 STP 操作的总字节数。

硬性约束（考试高频坑）

# 约束 说明
1 64 位 STP/LDP 必须 16 字节对齐 栈 SP 必须永远保持 16 字节对齐，AAPCS64 ABI 强制要求
2 偏移立即数范围 -256 ~ +256 超出范围需要先用 ADD 计算地址
3 不支持寄存器偏移寻址 stp x0, x1, [x1, x2] 汇编报错
4 可用 XZR 凑齐 16 字节 异常现场保存常用 stp x30, xzr, [sp, #-16]!
5 X 版本 16 字节，W 版本 8 字节 ldp w0, w1, [sp] 一次读写 8 字节

LDR/STR vs STP/LDP 对比

指令 一次访问字节数 支持寄存器偏移 [xn, xm, lsl #n] 典型用途
LDR / STR 8 字节 (X) ✅ 支持 普通内存读写
STP / LDP 16 字节 (X) ❌ 不支持 栈操作，成对寄存器保存恢复

最经典实际例子

函数开头保存 FP 帧指针与 LR 返回地址：

; 函数序言 (prologue)
stp x29, x30, [sp, #-16]!   ; 压栈保存 FP、LR
mov x29, sp                 ; 建立栈帧

函数结尾恢复：

; 函数结语 (epilogue)
ldp x29, x30, [sp], #16     ; 弹栈恢复 FP、LR
ret                         ; 用 X30 返回 (ret = br x30)

异常处理入口批量保存寄存器：

stp x0, x1, [sp, #-16]!
stp x2, x3, [sp, #-16]!
stp x4, x5, [sp, #-16]!
; ... 继续保存 x6-x30

补充：LDPSW

成对有符号 32 位加载到 X 寄存器，了解即可，极少用。

HFT 关联

方面 影响 HFT 策略
函数调用开销 每次调用至少 STP+LDP x29,x30 = 2 条内存指令 热路径减少调用层级
寄存器保存 callee-saved 寄存器(x19-x28)跨函数调用需保存恢复 热路径函数避免使用过多 callee-saved 寄存器
叶子函数 不调用其他函数，可完全省略栈帧 HFT 热路径核心函数标记 __attribute__((leaf))
-fomit-frame-pointer 省掉 x29 保存，但 x30(LR) 仍需保存 调试不需要时开启，减少 1 条 STP/LDP
栈对齐 SP 必须 16 字节对齐 裸金属 HFT 初始化时确保 SP 对齐
异常现场保存 IRQ 打断时批量 STP 保存全部寄存器 HFT 禁用 IRQ 可消除这段保存恢复开销

自测题

  1. AArch64 为什么没有 PUSH/POP？
答案

PUSH/POP 只操作一个寄存器且隐式修改 SP。STP/LDP 一次操作两个寄存器更高效，且显式控制 SP 变化（用前/后变基），设计更灵活统一。

  1. 以下函数入口代码保存了什么？栈帧多大？
func:
    stp x29, x30, [sp, #-16]!
    mov x29, sp
答案

保存了 FP(x29) 和 LR(x30)。栈帧 16 字节。mov x29, sp 设置帧指针指向当前栈顶，便于调试回溯。

  1. 叶子函数（不调用其他函数）可以省略 STP x29,x30 吗？
答案

可以省略 x30(LR) 的保存（因为不会被 BL 覆盖）。x29(FP) 的保存取决于是否需要帧指针。叶子函数可以完全没有栈帧。

  1. stp x0, x1, [sp, #-16]! 是什么寻址模式？执行后 sp 如何变化？
答案

预索引（前变基）。#-16 在中括号内且带 !，先计算地址 sp-16，再访问内存存储 x0/x1，最后 sp = sp - 16。这是 AArch64 压栈标准写法，等价于 x86 的 push。

  1. AArch64 能不能写 push {x0, x1}？
答案

不能。AArch64 没有 PUSH 指令（也没有伪指令），必须写 stp x0, x1, [sp, #-16]!。ARMv7 有 PUSH/POP，但 AArch64 移除了它们，统一用 STP/LDP 替代。

  1. 以下哪条语法错误？为什么？
A: stp x0, x1, [x2]
B: stp x0, x1, [x2, x3]
C: stp x0, x1, [x2, #8]!
答案

B 错误。LDP/STP 不允许寄存器偏移寻址 [x2, x3]，只能用基址立即偏移（A）、预索引（C）或后索引。这是因为 STP/LDP 指令编码中没有寄存器偏移字段，需要用 LDR/STR 才支持 [xn, xm, lsl #n]。

  1. stp xA, xB, [x1] 执行后，xA 和 xB 分别存在哪个内存地址？
答案
  • xA 存在 低地址 [x1]（第一个寄存器 → 低地址）
  • xB 存在 高地址 [x1 + 8]（第二个寄存器 → 高地址）

这是 AAPCS64 的固定规则，不能搞反。栈向下生长时，低地址 = 栈顶方向。

  1. 64 位 STP/LDP 的偏移立即数范围是多少？超出范围怎么办？
答案

范围 -256 ~ +256（以字节为单位）。如果需要更大偏移，先用 add x1, x1, #offset 计算目标地址，再用 stp x0, x1, [x2]（偏移为 0）访问。或者用多条 STP 逐步推进。

  1. sp = 0x1000，执行 stp x2, x3, [sp]，x3 存到哪个内存地址？占用哪些字节？
答案

x3 存到 0x1008（0x1000 + 8），占用 0x1008 ~ 0x100F（8 字节）。

x2 存在 0x1000 ~ 0x1007（低地址），x3 紧接其后在 0x1008 ~ 0x100F（高地址）。整个 STP 写 16 字节，0x1000 ~ 0x100F。

  1. stp w0, w1, [sp] 中，w1 存在哪个偏移？总共写多少字节？
答案

w1 存在 [sp + 4]（W 寄存器 32bit = 4 字节，所以第二个寄存器偏移 +4 而非 +8）。总共写 8 字节（4+4），不是 16 字节。

X 版本：第二参数 +8，总 16 字节；W 版本：第二参数 +4，总 8 字节。

3.5

LDR 伪指令 ldr =label vs 真 LDR 机器指令

来源：§3.5 · 精读 · 章总览

本节讲什么

区分真正的 LDR 机器指令和 ldr x0, =val GNU 汇编伪指令，理解文字池（literal pool）机制，以及 AArch64 MOV 立即数编码限制。

核心要点

区分关键点：有没有等号 =

写法 类型 含义 CPU 行为
ldr x0, [x1] 真正机器指令（CPU 原生指令） 把内存地址 x1 处的数据读入 x0 一定会访问内存；中括号算出内存地址，访存读取数据
ldr x0, =val GNU 汇编伪指令（不是 CPU 指令） 把常量/地址 val 送入 x0 寄存器 不一定访存，汇编器帮你做转换；= 是伪指令标记

⚠️ 伪指令是给汇编器看的，CPU 硬件根本没有这条指令。汇编阶段就被替换成真实指令流。

ldr x0, =val 伪指令底层原理（文字池 literal pool）

ldr x0, =0x123456789ABCDEF0

汇编器做三件事：

  1. 在代码段末尾生成一块文字池（litpool），把常量 0x123456789ABCDEF0 以 .quad 存进去
  2. 生成真实机器指令：ldr x0, [pc, #offset]（PC 相对加载）
  3. 链接器计算：当前 PC 距离文字池里这个常量的偏移 offset，填进指令

等价展开示意：

; 伪指令 ldr x0, =0x123456789ABCDEF0 被翻译成：
    ldr x0, [pc, #xxx]        ; 真实 LDR，PC 相对加载
    ...
.ltorg                        ; 文字池标记
    .quad 0x123456789ABCDEF0  ; 常量放在文字池

运行时 CPU 执行真实 LDR，从 PC + offset 这个内存位置读出常量到 x0。

特殊情况：如果这个常量刚好是 MOV 可以直接编码的立即数，汇编器会直接优化成一条 mov x0, #val，不会生成文字池，也不会访存。

AArch64 MOV 立即数硬限制（RISC 指令编码约束）

mov xd, #imm 单条指令可以直接编码的立即数：

  • 16 位立即数（0 ~ 0xFFFF）
  • 16 位立即数，左移 0 / 16 / 32 / 48 位

合法示例：

mov x0, #0x1234           ; 16 位，移位 0
mov x0, #0x1234, lsl #16  ; 0x0000_1234_0000
mov x0, #0x1234, lsl #32  ; 0x1234_0000_0000
mov x0, #0x1234, lsl #48  ; 0x1234_0000_0000_0000

非法示例（单条 MOV 做不到）：

mov x0, #0x12345678       ; 不能编码，汇编报错！

凡是单条 MOV 写不了的 64 位大常量/地址，就用 ldr x0, =xxx 伪指令，靠文字池解决。

三句对比（最容易混淆）

mov x0, #0x1234        ; 寄存器赋值，不访问内存，硬件原生指令
ldr x0, [x1]           ; 原生 LDR，x1 是内存地址，读内存数据进 x0
ldr x0, =0x12345678    ; 伪指令，把 0x12345678 这个值送入 x0；多数情况会生成文字池 + 访存

MOVZ/MOVK 组合加载大常量（替代文字池方案）

如果大常量可以用 16 位分段表示，用 MOVZ + MOVK 两条指令即可，不需要文字池：

; 加载 0x12345678
movz x0, #0x5678          ; 低 16 位
movk x0, #0x1234, lsl #16 ; 高 16 位（保留低 16 位不变）
; 结果：x0 = 0x0000_0000_1234_5678

; 加载 0xDEADBEEFCAFEBABE
movz x0, #0xBABE
movk x0, #0xCAFE, lsl #16
movk x0, #0xBEEF, lsl #32
movk x0, #0xDEAD, lsl #48
指令 作用 是否保留其他位
MOVZ 写入 16 位立即数到指定移位位置，其余位清零 ❌ 全部清零
MOVK 写入 16 位立即数到指定移位位置，保留其他位 ✅ 保留

ADR / ADRP / ldr= 三者区分

写法 类型 作用 访存 文字池 范围
adr x0, label 真指令 PC 相对取标签地址 ❌ ❌ ±1MB
adrp x0, label 真指令 取标签所在 4KB 页基地址 ❌ ❌ ±4GB
ldr x0, =label 伪指令 靠文字池访存拿到标签地址 ✅ ✅ 取决于文字池距离

AArch64 没有 ADRL 伪指令（ARMv7 有）。要加载大地址就用 ADRP，或者 ldr x0, =xxx 伪指令。

易踩坑

  1. ldr x0, =label 取的是 label 标签的地址（x0 = &label），不是 label 里面存的数据

如果要读 label 里面存储的数据，要两步： asm ldr x0, =my_var ; 伪指令，x0 得到 my_var 的地址 ldr x1, [x0] ; 真实 LDR，访问内存读出 my_var 里面的值

  1. 文字池距离不能太远：PC 相对偏移有范围限制（±1MB），文字池一般放在函数末尾；跨太远会汇编报错。可在函数中间用 .ltorg 指示手动放置文字池。

  2. MOV 立即数判断：写 mov x0, #imm 报错时，说明该立即数无法编码，改用 ldr x0, =imm 或 MOVZ/MOVK 组合。

HFT 关联

伪指令的性能影响：

场景 推荐 原因
热路径中的小常量（≤16 位） mov x0, #imm 单条指令，无访存，最快
热路径中的大常量（可分段） MOVZ + MOVK 组合 2-4 条指令，无访存，无 cache miss 风险
热路径中的大常量（不可分段） ldr x0, =imm 会产生额外内存访问（文字池），有 cache miss 风险
加载全局变量地址 adrp x0, var + add x0, x0, :lo12:var 位置无关，无文字池，无访存
加载标签地址（近距离） adr x0, label 单条指令，无访存
  • ldr = 会产生额外的内存访问（从文字池加载）→ 比立即数 MOV 多一个 cache miss 风险
  • 如果文字池不在 L1 cache → 额外 ~12 cycles (L2) 的延迟
  • 编译器通常自动选择最优方式，但内联汇编中需注意
  • HFT 热路径中应避免 ldr = 伪指令，优先用 MOVZ/MOVK 或 ADRP

自测题

  1. ldr x0, =0x123456789ABCDEF0 是 CPU 硬件指令吗？
答案

不是。它是 GNU 汇编伪指令。汇编器会把这个 64 位常量放进文字池，然后生成一条真 LDR 指令从文字池（PC 相对地址）加载。如果该常量恰好可被 MOV 编码，则直接生成 mov 指令。

  1. mov x0, #0x12340000 合法吗？为什么？
答案

合法。0x1234 是 16 位立即数，左移 16 位（lsl #16）得到 0x12340000，属于 MOV 允许的编码格式（16 位立即数 + 移位 0/16/32/48）。

  1. ldr x0, =my_buf 执行后 x0 是什么？
答案

x0 = my_buf 的内存起始地址（&my_buf），不是 my_buf 里面存放的数据。如果要读取 my_buf 里的内容，需要再执行 ldr x1, [x0]。

  1. 如何用 MOV 系列指令加载 0x12345678？
答案 
movz x0, #0x5678          ; 低 16 位
movk x0, #0x1234, lsl #16 ; 高 16 位（保留低 16 位）

两条 MOV 指令即可，不需要文字池。MOVZ 写低 16 位并清零其余，MOVK 写高 16 位并保留低 16 位。

  1. 为什么 A64 不支持任意 64 位立即数的单条 MOV？
答案

A64 指令固定 32 位编码，其中操作码占用若干位，剩余位不足以编码完整 64 位立即数。只能编码 16 位立即数 + 移位选项（0/16/32/48），所以大常量需要 MOVK 组合或文字池。这是 RISC 架构的典型定长指令编码约束。

  1. mov x0, #0x1234 / ldr x0, [x1] / ldr x0, =0x12345678 三条指令的区别？
答案
  • mov x0, #0x1234：寄存器赋值，不访问内存，硬件原生指令，直接把常量写入寄存器
  • ldr x0, [x1]：原生 LDR，x1 是内存地址，读内存数据进 x0，访问内存
  • ldr x0, =0x12345678：伪指令，把 0x12345678 这个值送入 x0；多数情况会生成文字池 + PC 相对 LDR 访存
  1. adr x0, label / adrp x0, label / ldr x0, =label 三者的区别？
答案
  • adr x0, label：真指令，PC 相对取标签地址，不访问内存，不生成文字池，范围 ±1MB
  • adrp x0, label：真指令，取标签所在 4KB 页基地址，不访问内存，范围 ±4GB
  • ldr x0, =label：伪指令，靠文字池访存拿到标签地址，会访问内存，范围取决于文字池距离

注意：ADR/ADRP 取的是地址本身（不访存），ldr = 取的也是地址但需要访存（从文字池加载）。

  1. 在函数中文字池离使用 ldr = 的地方太远会怎样？
答案

PC 相对偏移有范围限制（LDR literal 的偏移范围 ±1MB）。如果文字池距离太远，汇编器会报错。解决方法：在函数中间用 .ltorg 指示手动放置文字池，让文字池更靠近使用点。

3.6

特殊访存指令：LDXR/STXR、LDAR/STLR、LDTR/STTR

来源：§3.6 · 精读 · 章总览

本节讲什么

ARMv8 三组特殊 Load/Store 指令——独占访存（原子操作基础）、Acquire/Release 访存（内存序）、非特权访存（内核安全访问用户空间）。Linux 内核锁、copy_from_user 底层大量使用。

快速对照表

指令组 名称 核心作用 典型内核场景
LDXR / STXR 独占加载存储 LL-SC 原子操作，失败返回状态码 自旋锁、CAS、原子变量
LDAR / STLR Acquire-Release 访存 硬件自带内存序，替代 DMB 屏障 内核同步、std::atomic
LDTR / STTR 非特权加载存储 EL1 内核以 EL0 用户权限访问地址 copy_from_user、copy_to_user

后缀 R 含义

后缀 全称 含义
XR eXclusive Register 独占（LL-SC 原子）
AR AcquiRe / Release 获取/释放内存序
TR Translate-unpRivileged 非特权翻译（强制 EL0 权限）

一、LDXR / STXR —— 独占加载-存储（LL-SC 无锁原子）

指令 语法 含义
LDXR LDXR Rd, [Xn] 独占方式读内存，同时硬件标记监视地址 Xn
STXR STXR Rs, Rd, [Xn] 尝试把 Rd 写入被监视的内存地址

STXR 状态码： - Rs = 0：写入成功（独占监视仍有效） - Rs ≠ 0：写入失败（期间内存被别的 CPU 改动过，独占监视被打破）

用途： 实现 CAS（比较交换）、自旋锁、信号量，ARM64 硬件原子原语。

LL-SC 伪代码（CAS 实现）

; CAS: 比较x1地址的值是否等于w2，等于则写入w4
retry:
    ldxr  w0, [x1]       ; 独占加载，开启硬件监视
    cmp   w0, w2         ; 比较当前值与期望值
    b.ne  exit           ; 不相等，直接退出
    stxr  w3, w4, [x1]   ; 尝试独占写
    cmp   w3, #0         ; 检查写入状态
    b.ne  retry          ; 写失败（监视被打破），重新来
exit:

关键规则

  • LDXR 和 STXR 必须成对使用
  • LDXR 和 STXR 中间不能随便访问别的内存（可能打破独占监视器）
  • 多核之间靠硬件独占监视器（Exclusive Monitor）协调
  • STXR 的第一个寄存器 Rs 是状态码输出（不是数据），0=成功
  • ARMv8.1 LSE 原子指令（CAS/LDADD 等）可替代 LL-SC，低争用时更快

详见 Ch20 原子操作。

二、LDAR / STLR —— Acquire / Release 内存序指令

指令 全称 语义
LDAR Load-Acquire 加载，自带 acquire 语义：这条加载之后的读写，不能跑到这条指令前面
STLR Store-Release 存储，自带 release 语义：这条存储之前的读写，不能跑到这条指令后面

内存序可视化

// acquire (LDAR) — 后面的不能往前跑
[其他读写]  ──→  不能跑到 LDAR 前面
                  LDAR x0, [x1]   ← 屏障
[后续读写]  ──→  正常执行

// release (STLR) — 前面的不能往后跑
[之前的读写] ──→ 正常执行
                  STLR x0, [x1]   ← 屏障
[其他读写]  ──→  不能跑到 STLR 前面

用途

  • ARMv8 弱内存模型的同步指令，实现 C++ std::memory_order_acquire / release
  • 内核读写锁、RCU 大量使用
  • 对比 DMB 内存屏障：LDAR/STLR 把内存屏障和 load/store 合并成单条指令，性能更好——DMB 会过度排序不相关的访问，LDAR/STLR 只排序相关访问

LDR vs LDAR 区别

特性 LDR（普通加载） LDAR（Acquire 加载）
内存序保证 无（可被重排） acquire 语义（后续读写不能前移）
等价语义 普通读 读 + 内存屏障
性能 最快 略慢（但有屏障效果）
适用场景 无并发要求 需要同步的并发场景

详见 Ch18 内存屏障 和 §18.4 acquire/release。

三、LDTR / STTR —— 非特权访问指令（内核访问用户空间）

指令 语法 含义
LDTR LDTR w0, [x1] EL1 执行，访问 x1 地址，使用 EL0 权限检查
STTR STTR w0, [x1] EL1 执行，写内存，使用 EL0 权限检查

核心场景：copy_from_user / copy_to_user

内核 EL1 要读写用户态地址。普通 LDR 在 EL1 会直接绕过用户权限检查；用 LDTR/STTR，即使在内核，硬件依然检查：这个地址用户态是否有权读写。如果用户地址非法、不可访问，直接触发异常。

LDR vs LDTR 对比

特性 LDR（EL1 下） LDTR（EL1 下）
权限检查级别 EL1 内核权限 EL0 用户权限（强制降级）
用户空间 PXN/PAN 跳过检查 检查（违规则触发异常）
典型用途 内核数据访问 copy_from_user / copy_to_user
安全性 可能绕过用户权限限制 确保用户权限约束 
; 内核安全读取用户空间数据
; 普通 LDR: 内核权限，跳过用户权限检查
ldr  w0, [x1]     ; ❌ 危险：可能绕过用户页表权限

; LDTR: 强制使用 EL0 用户权限校验
ldtr w0, [x1]     ; ✅ 安全：硬件检查用户权限

HFT 关联

这些指令对无锁编程和内核-用户态数据传递至关重要：

场景 推荐指令 原因
无锁 SPSC 队列 LDXR/STXR 避免 mutex 上下文切换，但 SPSC 模式争用为 0
无锁 MPSC 队列 LDXR/STXR + CAS 多生产者需要 CAS 争用，重试成本需评估
内存序同步 LDAR/STLR 比显式 DMB 精确，只排序相关访问，减少不必要屏障
交易指令传入 LDTR/STTR 内核安全复制用户态交易数据，防止绕过权限
低争用原子 LSE（ARMv8.1） 比 LDXR/STXR 更快，无重试循环
高争用原子 每核独立数据 完全避免原子操作，HFT 最优方案
  • LDXR/STXR 在争用激烈时重试成本高 → HFT 中用单生产者-单消费者模式避免争用
  • LDAR/STLR 比 DMB 屏障更精确 → 减少不必要的屏障开销
  • LDTR 用于内核安全地复制用户数据（如交易指令从用户态传入），防止绕过权限检查

自测题

  1. LDXR/STXR 如何实现原子操作？
答案

LDXR 设置独占监视器标记该地址。STXR 尝试写回：如果监视器仍持有独占标记则写入成功（返回 0）；如果中间有其他核写了该地址则失败（返回非 0）。通过循环重试实现原子 read-modify-write。

  1. LDAR 和 LDR 的区别是什么？
答案

LDAR = Load-Acquire，保证 LDAR 之后的读写不会重排到 LDAR 之前。LDR 是普通加载，没有内存序保证。LDAR 用于需要 acquire 语义的场景（如读取标志后访问对应数据）。

  1. 为什么内核用 LDTR 而不是 LDR 来访问用户空间地址？
答案

LDTR 以 EL0（用户）权限执行访问，即使用户空间的页表设置了 PXN（特权不可执行）等限制，内核也能正确检测到权限违规。用普通 LDR 则以内核权限访问，可能绕过用户空间的访问限制。

  1. STXR 的第一个寄存器 Rs 输出什么？0 和非 0 分别代表什么？
答案

Rs 是状态码（不是数据）：Rs = 0 表示独占写入成功（监视器仍有效）；Rs ≠ 0 表示失败（LDXR 和 STXR 之间有其他核写了该地址，监视器被打破）。需要重新 LDXR → 修改 → STXR 重试。

  1. LDAR 相比普通 LDR 多了什么？
答案

Acquire 内存序语义——LDAR 之后的读写不能重排到 LDAR 前面。等价于"加载 + 内存屏障"。普通 LDR 没有内存序保证，可被 CPU 乱序执行重排。

  1. EL1 内核想访问用户地址并做用户权限检查，用哪条指令？
答案

LDTR / STTR。普通 LDR 在 EL1 下以内核权限访问，跳过 EL0 用户权限检查。LDTR 强制使用 EL0 权限校验——如果用户地址非法或不可访问，直接触发异常。这是 copy_from_user / copy_to_user 的底层机制。

  1. LDXR 和 STXR 之间能随便访问其他内存地址吗？为什么？
答案

不能。LDXR 和 STXR 之间对其他地址的内存访问可能打破独占监视器（Exclusive Monitor）。ARMv8 的独占监视器是粒度性的——对同一监视区域内的任何访问都可能清除独占标记，导致 STXR 无谓失败。LL-SC 临界区应尽量短，只做寄存器运算。

  1. LDAR/STLR 相比 DMB 屏障有什么优势？
答案

LDAR/STLR 把内存屏障和 load/store 合并成单条指令，只排序与该指令相关的访问。DMB 是全局屏障，会过度排序不相关的访问，性能开销更大。LDAR/STLR 更精确，在现代乱序执行 CPU 上性能更好。

典型实操模式

来源：§3.7 · 精读 · 章总览

本节讲什么

全部基于前面讲的寻址模式：后变基、预索引 !、寄存器移位偏移 lsl #n，是内核高频汇编范式。本节通过三个典型代码片段，把前面学的寻址模式串起来，看到真实代码中怎么用。

① memcpy 骨架（大块内存拷贝，后变基寻址）

; x0=dst 目标地址, x1=src 源地址, x2=count 总字节数
memcpy:
    cbz x2, done         ; count=0 直接退出
loop:
    ldr x3, [x1], #8     ; ✅ 后变基：读 [x1]，读完 x1 += 8（源指针前进8字节）
    str x3, [x0], #8     ; ✅ 后变基：写入 [x0]，写完 x0 += 8（目标指针前进8字节）
    subs x2, x2, #8      ; count -= 8，设置状态标志位
    b.gt loop            ; 大于0继续循环
done:
    ret

C 等价：

while (count > 0) {
    *dst++ = *src++;
    count -= 8;
}

关键点

  • [x1], #8：#8 写在中括号外面，后索引寻址（post-index）
  • 访问完内存后，寄存器自增 8（一个 X 寄存器 = 8 字节）
  • subs 而非 sub：需要设置标志位供 b.gt 判断

执行流程举例

初始 x1 = 0x1000

ldr x3, [x1], #8：
  1. 读取地址 0x1000 处的 8 字节 → x3
  2. x1 = 0x1000 + 8 = 0x1008（指针前进）

str x3, [x0], #8：
  1. 将 x3 写入 [x0] 处
  2. x0 += 8（目标指针前进）

subs x2, x2, #8：
  count -= 8，同时设置 NZCV 标志位
  若 count > 0 → Z=0, 继续循环
  若 count = 0 → Z=1, 退出循环

⚠️ 这个简化版本只支持 8 字节对齐，工业级 memcpy 还会处理尾部不足 8 字节、非对齐情况。

② 函数栈帧（Stack Frame，STP/LDP 预索引 + 后索引）

func:
    stp x29, x30, [sp, #-16]!   ; ✅ 预索引!：sp = sp - 16，把 x29(FP帧指针)、x30(LR返回地址) 压栈
    mov x29, sp                  ; 建立栈帧，FP 指向当前栈顶
    ; -------- 函数体，局部变量就在 x29 帧指针的负偏移位置，用 LDUR 访问 --------
    ldp x29, x30, [sp], #16      ; ✅ 后索引：恢复 x29/x30；sp += 16 释放栈空间
    ret                          ; 用 x30 返回调用方

关键点

要素 说明
AArch64 ABI 强制 栈 sp 必须永远 16 字节对齐
成对保存 x29 + x30 刚好 16 字节，满足对齐要求
x29 帧指针 FP（Frame Pointer），指向当前栈帧顶部
x30 链接寄存器 LR（Link Register），保存函数返回地址
开头 stp ...! 前变基（预索引）：先 sp -= 16，再存储
结尾 ldp ...,#16 后变基（后索引）：先加载，再 sp += 16
局部变量访问 ldur w0, [x29, #-4]，负偏移读取栈帧上的局部变量

开头 vs 结尾对比

函数开头（压栈）：                    函数结尾（弹栈）：
stp x29,x30,[sp,#-16]!              ldp x29,x30,[sp],#16
    ↓                                    ↓
1. sp = sp - 16（先改寄存器）        1. 从 [sp] 加载 x29, x30（先访存）
2. 存 x29 → [sp], x30 → [sp+8]     2. sp = sp + 16（后改寄存器）
    ↓                                    ↓
预索引：! 在 [] 内部                  后索引：偏移在 [] 外部

③ 数组索引模式（寄存器移位偏移寻址）

; x0 = 数组基地址 base；x1 = index 下标
; 取 arr[index]，每个元素 8 字节（long long）
ldr x2, [x0, x1, lsl #3]
; 有效地址 = x0 + (x1 << 3) = base + index * 8
  • lsl #3 等价乘以 8，对应 64 位 X 寄存器，每个数组元素占 8 字节
  • 这就是寄存器偏移 + 移位缩放，移位只能 0–3

拓展练习

C 类型 元素大小 指令 移位
long long arr[] 8 字节 ldr x2, [x0, x1, lsl #3] lsl #3（×8）
uint32_t arr[] 4 字节 ldr w2, [x0, x1, lsl #2] lsl #2（×4）
uint16_t arr[] 2 字节 ldrh w2, [x0, x1, lsl #1] lsl #1（×2）
uint8_t arr[] 1 字节 ldrb w2, [x0, x1] 无移位（×1）

三种模式对应寻址对照表

代码片段 寻址模式 核心特征
ldr x3, [x1], #8 后变基（后索引） 偏移在 [] 外面；访存之后更新基址
stp x29, x30, [sp, #-16]! 预索引（前变基） ! 写在 [] 内部；先修改寄存器，再访存
ldr x2, [x0, x1, lsl #3] 寄存器移位偏移 [] 内，基址 + 偏移寄存器 + 移位；基址不会被修改

三种模式一眼区分

后变基：  [Xn], #imm      →  偏移在外面，先访存后改基址    →  指针自增场景
前变基：  [Xn, #imm]!     →  感叹号在里面，先改基址后访存  →  压栈/开辟空间
寄存器偏移：[Xn, Xm, lsl #n] → 无感叹号，基址不变          →  数组下标访问

HFT 关联

这些模式在 HFT 代码中无处不在：

  • memcpy 骨架：市场数据拷贝 → 用后变基减少指令数，每次 8 字节搬运
  • 函数栈帧：热路径函数的调用开销 → 叶子函数省栈帧可省 2 条指令
  • 数组索引：订单簿数组访问 → lsl #3 一条指令完成索引计算，无需额外乘法
  • GDB 调试：info registers、x/8gx $sp 验证内存布局

Quiz 巩固

Q1: memcpy 循环中 ldr x3, [x1], #8，中括号内部计算的地址是 x1 旧值还是 x1+8？

答案

旧的 x1；读完内存之后 x1 才 +8。后变基的核心就是"先用旧地址访存，再更新寄存器"。

Q2: stp x29, x30, [sp, #-16]! 执行后 sp 如何变化？

答案

sp = sp - 16。预索引（!）先修改寄存器再访存，所以 sp 先减 16，然后把 x29/x30 存入新 sp 位置。

Q3: long long arr[]；base 在 x0，下标 x1，请写出加载 arr[index] 的指令？

答案 
ldr x2, [x0, x1, lsl #3]

lsl #3 = 左移 3 位 = 乘以 8，因为 long long 占 8 字节。

Q4: 以下 memcpy 代码有什么问题？

loop:
    ldr x3, [x1], #8
    str x3, [x0], #8
    subs x2, x2, #8
    b.gt loop
答案

如果 count 不是 8 的倍数，会多读/多写越界字节。需要先处理对齐余数，或者用字节拷贝处理尾部。真实内核 memcpy 会做剩余字节处理。

Q5: 函数栈帧开头为什么用 stp 而不是两次 str？

答案

两个原因：(1) AArch64 ABI 强制 sp 必须 16 字节对齐，stp 一次存 16 字节天然满足对齐；(2) stp 一条指令完成两次存储，比两条 str 更高效。

补充易错

  1. memcpy 尾部问题：简化版每次拷贝 8 字节，如果 count 不是 8 整数倍，尾部字节会漏拷贝；真实内核 memcpy 会做剩余字节处理（先按 8 字节批量拷贝，再按 1 字节处理尾部）
  2. LDP/STP 不支持寄存器移位寻址：数组索引不能用 LDP，只能 LDR
  3. 栈向下增长：sp 往数值变小方向开辟空间，所以压栈写 #-16（减不是加）
  4. subs vs sub：循环计数必须用 subs（设置标志位），否则 b.gt 无法判断
  5. mov x29, sp 的时机：必须在 stp 之后，此时 sp 已经指向新栈帧底部

5 大易错点

  1. ALU 不能碰内存（Load-Store 架构）
  2. 真 LDR vs ldr = 伪指令（前者访存，后者文字池）
  3. ! 前变基 vs 后变基（基址会不会改）
  4. 无 PUSH/POP → STP/LDP

自测题

  1. 以下两条指令哪个是真机器指令？
ldr x0, [x1]
ldr x0, =0x80000000
答案

第一条 ldr x0, [x1] 是真机器指令（访存）。第二条是伪指令，汇编器会生成文字池 + 真 LDR。

  1. stp x0, x1, [sp, #-16]（没有 !）执行后 sp 变了吗？
答案

没变。没有 ! 表示基址偏移模式，只访问 [sp-16] 地址但不写回 sp。要修改 sp 需要加 !：stp x0, x1, [sp, #-16]!。

  1. 读取有符号字节 -1，用 LDRB 会得到什么？
答案

LDRB 是零扩展，读 0xFF → 0x000000FF(255) 而非 -1。要正确读取有符号负数必须用 LDRSB（符号扩展）→ 0xFFFFFFFF(-1)。
