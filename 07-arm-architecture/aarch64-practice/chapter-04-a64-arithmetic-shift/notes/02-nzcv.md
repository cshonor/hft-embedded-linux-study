# 4.2 NZCV 四个条件标志

> 来源：§4.2 · 精读 · [章总览](section-0-本章完整概述.md) · [NZCV 专篇](../../NZCV.md)

## 本节讲什么

NZCV 四个条件标志的含义、设置规则，以及有符号/无符号比较的区别——补码运算的核心。

---

## 补码与 NZCV 的关系

ARM64 用补码存放有符号数。一条 `ADDS` 指令**同时**产出两套溢出信息，软件按自己的类型选一套：

```
ADDS x0, x1, x2          ; 一次加法，同时设置 C 和 V

你把操作数当…     →     看哪个标志
──────────────────────────────────
无符号               →    C（Carry，无符号进位/借位）
有符号（补码）       →    V（oVerflow，补码溢出）
```

> 这是补码的妙处：同一条加法指令，同一次二进制运算，C 和 V 同时给出无符号和有符号两种溢出判定。**不需要**单独的"有符号加法"或"无符号加法"指令。

### 新手关键澄清：NZCV 不是"只给补码用的附属品"

> **常见误区**：以为 N、V 是补码专属的"附属标志"，无符号运算不需要 NZCV。
>
> **真相**：硬件每次做 ADDS/SUBS/CMP，**都会同时设置全部 4 个标志**——不管你心里想的是有符号还是无符号。硬件根本不知道你的数是有符号还是无符号，它只看到一串 0 和 1，算完之后把 4 个标志全设上。然后**由你选择读哪几个**。

| 标志 | 有符号用？ | 无符号用？ | 说明 |
|------|-----------|-----------|------|
| **Z** | ✅ 用 | ✅ 也用 | 结果是否为零，有符号无符号含义一样（0 就是 0） |
| **N** | ✅ 用 | ❌ 不用 | 有符号看最高位判断正负；无符号不看 |
| **V** | ✅ 用 | ❌ 不用 | 有符号溢出标志；无符号不关心 |
| **C** | ❌ 不用 | ✅ 用 | 无符号进位/借位；有符号不关心 |

```
         有符号视角          无符号视角
         ──────────          ──────────
  Z  →   结果==0？          结果==0？        ← 两者共用
  N  →   结果是负数？        （不看）          ← 有符号专属
  V  →   补码溢出？          （不看）          ← 有符号专属
  C  →   （不看）            无符号进位/借位？ ← 无符号专属
```

> **一次 CMP，四盏灯全亮**，你根据自己是有符号还是无符号，去看对应的灯。N 和 V 不是"附属"——它们对有符号运算是主角；C 对无符号是主角。Z 是唯一两者共用的。

#### 完整示例：同一份 NZCV，两种读法

```
CMP x0, x1    ; x0 = 0xFFFFFFFFFFFFFFFF, x1 = 0x0000000000000003
              ; x0 - x1 = 0xFFFFFFFFFFFFFFFC

N=1  →  有符号：结果是负的 ✓（-1 - 3 = -4，确实是负数）
Z=0  →  两者：结果不是零 ✓
C=1  →  无符号：没借位 ✓（极大数减 3 还是大数，够减）
V=0  →  有符号：没溢出 ✓（-1-3=-4 在 int64 范围内）

有符号结论：-1 < 3  → 看 N≠V → B.LT 成立 ✓
无符号结论：极大数 > 3 → 看 C=1 → B.HS 成立 ✓
```

---

## 四个标志详解

| 标志 | 全称 | 含义 | 设置条件 |
|------|------|------|----------|
| **N** | Negative | 结果最高位为 1 | 结果 MSB = 1 → N=1 |
| **Z** | Zero | 结果为全 0 | 结果 = 0 → Z=1 |
| **C** | Carry | **无符号**进位/借位 | 加法进位 → C=1；减法借位 → C=0 |
| **V** | oVerflow | **有符号**溢出 | 补码运算超出有符号范围 → V=1 |

### 谁会改 NZCV？

| 指令类型 | 改 NZCV？ | 例子 |
|---------|----------|------|
| 带 **S** 的算术 | ✅ | `ADDS`, `SUBS`, `NEGS`, `ADCS`, `SBCS` |
| 带 **S** 的位运算 | ✅ | `ANDS`, `ORRS`, `EORS`, `BICS` |
| CMP / CMN | ✅ | `CMP` ≡ `SUBS XZR`, `CMN` ≡ `ADDS XZR` |
| 不带 S 的运算 | ❌ | `ADD`, `SUB`, `AND`, `MUL`, `SDIV` |
| 条件跳转 | ❌（只读） | `B.EQ`, `B.NE`, `B.LT` 等 |
| LDR / STR | ❌ | 加载存储不改 NZCV |

> 口诀：**带 S 改标志；不带 S 只算数值。**

## 具体示例

### 示例 1：`1 - 3`（小减大）

```asm
mov  w0, #1
mov  w1, #3
subs w2, w0, w1         ; 1 - 3
```

```
  0x00000001  (1)
- 0x00000003  (3)
────────────────
  0xFFFFFFFE  (-2 的补码)
```

| 标志 | 值 | 原因 |
|------|---|------|
| N | 1 | 结果最高位（bit 31）= 1 |
| Z | 0 | 结果不为零 |
| C | 0 | 无符号 1 < 3，有借位 → C=0 |
| V | 0 | 有符号 1-3=-2，未溢出 |

### 示例 2：`全1 + 1`（最大值溢出）

```asm
mov  x0, #0xFFFFFFFFFFFFFFFF   ; = -1（补码）或 18446744073709551615（无符号）
adds x0, x0, #1
```

```
  0xFFFFFFFFFFFFFFFF  (-1 有符号 / 极大无符号)
+ 0x0000000000000001  (1)
─────────────────────
  0x0000000000000000  (0，进位溢出)
```

| 标志 | 值 | 原因 |
|------|---|------|
| N | 0 | 结果最高位 = 0 |
| Z | 1 | 结果为零 |
| C | 1 | 无符号进位（极大正数 +1 溢出） |
| V | 1 | 有符号溢出（-1 + 1 = 0 没溢出？不对！） |

> **修正**：V=0。`-1 + 1 = 0` 在有符号范围内，没有溢出。V 的判定规则是：两个正数相加得到负数，或两个负数相加得到正数。这里 -1 和 +1 相加得 0，正常。

### 示例 3：两大正数相加溢出（`INT64_MAX + 1`）

```asm
mov  x0, #0x7FFFFFFFFFFFFFFF   ; = INT64_MAX = 2^63 - 1
adds x0, x0, #1
```

```
  0x7FFFFFFFFFFFFFFF  (INT64_MAX, 最大正数)
+ 0x0000000000000001  (1)
─────────────────────
  0x8000000000000000  (INT64_MIN, 变成负数！)
```

| 标志 | 值 | 原因 |
|------|---|------|
| N | 1 | 结果最高位 = 1（看起来是负数） |
| Z | 0 | 非零 |
| C | 0 | 无符号没有进位（没超出 2^64） |
| V | 1 | **有符号溢出**！正数 + 正数 = 负数 |

> 这就是 C 和 V 的区别：C=0（无符号没溢出），V=1（有符号溢出了）。

### 示例 4：`-1 - 1`（负数减正数）

```asm
mov  x0, #-1                    ; 0xFFFFFFFFFFFFFFFF
subs x0, x0, #1                 ; -1 - 1 = -2
```

```
  0xFFFFFFFFFFFFFFFF  (-1)
- 0x0000000000000001  (1)
─────────────────────
  0xFFFFFFFFFFFFFFFE  (-2 的补码)
```

| 标志 | 值 | 原因 |
|------|---|------|
| N | 1 | 最高位 = 1 |
| Z | 0 | 非零 |
| C | 1 | 无符号 -1(极大) - 1 = 极大-1，没借位 → C=1 |
| V | 0 | 有符号 -1-1=-2，在范围内 |
