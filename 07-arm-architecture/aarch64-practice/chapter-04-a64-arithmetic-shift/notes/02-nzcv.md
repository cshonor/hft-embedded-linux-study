# 4.2 NZCV 四个条件标志

> 来源：§4.2 · 精读 · [章总览](section-0-本章完整概述.md) · [NZCV 专篇](../../NZCV.md)

## 本节讲什么

NZCV 四个条件标志的含义、设置规则，以及有符号/无符号比较的区别——补码运算的核心。

---

## 补码与 NZCV 的关系

ARM64 用补码存放有符号数。一条 `ADDS` 指令**同时**产出两套溢出信息，软件按自己的类型选一套：

```
ADDS x0, x1, x2          ; 一次加法，同时设置 C 和 V

你把操作数当…     →     看哪个标志
──────────────────────────────────
无符号               →    C（Carry，无符号进位/借位）
有符号（补码）       →    V（oVerflow，补码溢出）
```

> 这是补码的妙处：同一条加法指令，同一次二进制运算，C 和 V 同时给出无符号和有符号两种溢出判定。**不需要**单独的"有符号加法"或"无符号加法"指令。

---

## 四个标志详解

| 标志 | 全称 | 含义 | 设置条件 |
|------|------|------|----------|
| **N** | Negative | 结果最高位为 1 | 结果 MSB = 1 → N=1 |
| **Z** | Zero | 结果为全 0 | 结果 = 0 → Z=1 |
| **C** | Carry | **无符号**进位/借位 | 加法进位 → C=1；减法借位 → C=0 |
| **V** | oVerflow | **有符号**溢出 | 补码运算超出有符号范围 → V=1 |

### 谁会改 NZCV？

| 指令类型 | 改 NZCV？ | 例子 |
|---------|----------|------|
| 带 **S** 的算术 | ✅ | `ADDS`, `SUBS`, `NEGS`, `ADCS`, `SBCS` |
| 带 **S** 的位运算 | ✅ | `ANDS`, `ORRS`, `EORS`, `BICS` |
| CMP / CMN | ✅ | `CMP` ≡ `SUBS XZR`, `CMN` ≡ `ADDS XZR` |
| 不带 S 的运算 | ❌ | `ADD`, `SUB`, `AND`, `MUL`, `SDIV` |
| 条件跳转 | ❌（只读） | `B.EQ`, `B.NE`, `B.LT` 等 |
| LDR / STR | ❌ | 加载存储不改 NZCV |

> 口诀：**带 S 改标志；不带 S 只算数值。**

---

## 具体示例

### 示例 1：`1 - 3`（小减大）

```asm
mov  w0, #1
mov  w1, #3
subs w2, w0, w1         ; 1 - 3
```

```
  0x00000001  (1)
- 0x00000003  (3)
────────────────
  0xFFFFFFFE  (-2 的补码)
```

| 标志 | 值 | 原因 |
|------|---|------|
| N | 1 | 结果最高位（bit 31）= 1 |
| Z | 0 | 结果不为零 |
| C | 0 | 无符号 1 < 3，有借位 → C=0 |
| V | 0 | 有符号 1-3=-2，未溢出 |

### 示例 2：`全1 + 1`（最大值溢出）

```asm
mov  x0, #0xFFFFFFFFFFFFFFFF   ; = -1（补码）或 18446744073709551615（无符号）
adds x0, x0, #1
```

```
  0xFFFFFFFFFFFFFFFF  (-1 有符号 / 极大无符号)
+ 0x0000000000000001  (1)
─────────────────────
  0x0000000000000000  (0，进位溢出)
```

| 标志 | 值 | 原因 |
|------|---|------|
| N | 0 | 结果最高位 = 0 |
| Z | 1 | 结果为零 |
| C | 1 | 无符号进位（极大正数 +1 溢出） |
| V | 1 | 有符号溢出（-1 + 1 = 0 没溢出？不对！） |

> **修正**：V=0。`-1 + 1 = 0` 在有符号范围内，没有溢出。V 的判定规则是：两个正数相加得到负数，或两个负数相加得到正数。这里 -1 和 +1 相加得 0，正常。

### 示例 3：两大正数相加溢出（`INT64_MAX + 1`）

```asm
mov  x0, #0x7FFFFFFFFFFFFFFF   ; = INT64_MAX = 2^63 - 1
adds x0, x0, #1
```

```
  0x7FFFFFFFFFFFFFFF  (INT64_MAX, 最大正数)
+ 0x0000000000000001  (1)
─────────────────────
  0x8000000000000000  (INT64_MIN, 变成负数！)
```

| 标志 | 值 | 原因 |
|------|---|------|
| N | 1 | 结果最高位 = 1（看起来是负数） |
| Z | 0 | 非零 |
| C | 0 | 无符号没有进位（没超出 2^64） |
| V | 1 | **有符号溢出**！正数 + 正数 = 负数 |

> 这就是 C 和 V 的区别：C=0（无符号没溢出），V=1（有符号溢出了）。

### 示例 4：`-1 - 1`（负数减正数）

```asm
mov  x0, #-1                    ; 0xFFFFFFFFFFFFFFFF
subs x0, x0, #1                 ; -1 - 1 = -2
```

```
  0xFFFFFFFFFFFFFFFF  (-1)
- 0x0000000000000001  (1)
─────────────────────
  0xFFFFFFFFFFFFFFFE  (-2 的补码)
```

| 标志 | 值 | 原因 |
|------|---|------|
| N | 1 | 最高位 = 1 |
| Z | 0 | 非零 |
| C | 1 | 无符号 -1(极大) - 1 = 极大-1，没借位 → C=1 |
| V | 0 | 有符号 -1-1=-2，在范围内 |

## 条件后缀完整速查

### 相等/不等（看 Z）

| 后缀 | 条件 | 含义 |
|------|------|------|
| `EQ` | Z=1 | 相等 |
| `NE` | Z=0 | 不等 |

### 无符号比较（看 C）

| 后缀 | 条件 | 含义 |
|------|------|------|
| `HS` (=`CS`) | C=1 | 无符号 ≥（Higher or Same） |
| `LO` (=`CC`) | C=0 | 无符号 <（LOwer） |
| `HI` | C=1 AND Z=0 | 无符号 >（HIgher） |
| `LS` | C=0 OR Z=1 | 无符号 ≤（Lower or Same） |

### 有符号比较（看 N 和 V）

| 后缀 | 条件 | 含义 |
|------|------|------|
| `GE` | N==V | 有符号 ≥ |
| `LT` | N!=V | 有符号 < |
| `GT` | Z=0 AND N==V | 有符号 > |
| `LE` | Z=1 OR N!=V | 有符号 ≤ |

### 正/负/零（看 N 和 Z）

| 后缀 | 条件 | 含义 |
|------|------|------|
| `MI` | N=1 | 负数（MInus） |
| `PL` | N=0 | 正数或零（PLus） |

### 溢出（看 V）

| 后缀 | 条件 | 含义 |
|------|------|------|
| `VS` | V=1 | 有符号溢出发生 |
| `VC` | V=0 | 无溢出 |

---

## 无符号 vs 有符号：同一比特流，不同结论

```asm
; 场景：比较 0xFFFFFFFF (-1 有符号 / 4294967295 无符号) 和 0
cmp  w0, w1               ; w0 = 0xFFFFFFFF, w1 = 0
```

| 你想要的结果 | 用什么后缀 | 会跳转吗？ | 原因 |
|-------------|----------|----------|------|
| 有符号：-1 < 0 → 跳 | `B.LT` | ✅ 跳 | N=1, V=0, N≠V → LT 成立 |
| 无符号：4294967295 > 0 → 不跳 | `B.LO` | ❌ 不跳 | C=1（无借位）→ LO 不成立 |

> **数据不变，软件选不同标志 → 两种大小比较。**这就是补码的精髓。

---

## C 标志在减法中的特殊性

ARM 的 `SUBS` 中，**C = NOT(借位)**：

| 情况 | 借位 | C 标志 | 含义 |
|------|------|--------|------|
| 够减（x0 ≥ x1） | 无借位 | C=1 | HS（≥）成立 |
| 不够减（x0 < x1） | 有借位 | C=0 | LO（<）成立 |

> 这种设计让 `HS`/`LO` 的语义与 C 的值一致：C=1 → 大于等于，C=0 → 小于。
> 注意 x86 的 CF 在减法中是直接借位标志，与 ARM **相反**。

---

## 读取 NZCV

```asm
; 方式 1：MRS 读 PSTATE 到通用寄存器
mrs  x0, nzcv              ; x0[31:28] = N, Z, C, V

; 方式 2：GDB 调试
(gdb) info registers pstate
```

---

## HFT 关联

NZCV 是条件执行的基础：
- 比较价格 `cmp x0, x1; b.gt buy` 判断是否触发交易
- 无符号比较用于地址/大小比较（地址永远 ≥ 0）→ 必须用 `HS`/`LO`
- 有符号比较用于价格/数量比较（可为负）→ 必须用 `GE`/`LT`
- 条件后缀选择错误（`LT` vs `LO`）会导致隐蔽的逻辑 bug

## 自测题

1. 有符号 -1 和无符号 0 比较，CMP 设置的标志是什么？用 `B.LT` 和 `B.LO` 分别会跳转吗？
<details><summary>答案</summary>

-1 (0xFFFFFFFF) - 0 = 0xFFFFFFFF。N=1, Z=0, C=1(无借位), V=0(无溢出)。
B.LT (N≠V) → 1≠0 → 跳转（-1 < 0 成立）。
B.LO (C=0) → C=1 → 不跳转（无符号看 -1 是大数 0xFFFFFFFF，不小于 0）。

</details>

2. C 标志在减法中为什么是"借位取反"？
<details><summary>答案</summary>

ARM 的 SUBS 中 C = NOT(Borrow)。即无借位时 C=1，有借位时 C=0。这样 HS(C=1) = 大于等于，LO(C=0) = 小于，语义一致。注意 x86 的 CF 在减法中是直接借位标志，与 ARM **相反**。

</details>

3. `INT64_MAX + 1` 后 NZCV 各是什么？
<details><summary>答案</summary>

`0x7FFFFFFFFFFFFFFF + 1 = 0x8000000000000000`。
N=1（最高位变 1），Z=0，C=0（无符号没进位），V=1（有符号溢出！正数+正数=负数）。
关键：C=0 但 V=1 → 无符号没溢出，有符号溢出了。

</details>

4. 如何同时判断"结果为零且无溢出"？
<details><summary>答案</summary>

检查 Z=1 AND V=0。没有单一条件后缀组合这两个。可以用两个条件分支：`B.NE skip; B.VS skip`（都不跳则满足条件）。或者用 MRS 读 NZCV 再位测试。

</details>

5. `B.HI` 和 `B.HS` 的区别是什么？
<details><summary>答案</summary>

`HS` = 无符号 ≥（C=1）。`HI` = 无符号 >（C=1 AND Z=0）。区别在于相等时：`HS` 包含相等（Z=1 也跳），`HI` 不包含相等（Z=1 不跳）。

</details>

6. 为什么 `ADD`（不带 S）后用 `B.EQ` 会得到错误结果？
<details><summary>答案</summary>

`ADD` 不更新 NZCV，`B.EQ` 读的是**上一次**带 S 指令设的标志，不是这次加法的结果。必须用 `ADDS` 或在 `ADD` 后加 `CMP`。

</details>
