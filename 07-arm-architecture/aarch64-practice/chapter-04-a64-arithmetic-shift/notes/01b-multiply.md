## 乘法指令

### 128 位乘积的概念

AArch64 两个 64 位寄存器相乘 `Rn * Rm`，完整结果是 **128 位**。硬件把结果分成高低两半：

```
┌──────────────────────────────────────────────────────────────┐
│                    128 位完整乘积                             │
├────────────────────────┬─────────────────────────────────────┤
│    高 64 bit            │       低 64 bit                     │
│  ← SMULH / UMULH       │  ← MUL                            │
│  （有符号 / 无符号分开）│  （有符号无符号相同）               │
└────────────────────────┴─────────────────────────────────────┘
```

| 指令 | 计算 | 拿到哪一部分 | 是否区分有符号 |
|------|------|-------------|---------------|
| `MUL` | `Rn × Rm` | 低 64 bit | ❌ 不需要 |
| `MADD` | `Ra + Rn × Rm` | 低 64 bit | ❌ 不需要 |
| `MSUB` | `Ra − Rn × Rm` | 低 64 bit | ❌ 不需要 |
| `SMULH` | `Rn × Rm` | 高 64 bit | ✅ 有符号补码乘法 |
| `UMULH` | `Rn × Rm` | 高 64 bit | ✅ 无符号乘法 |

### 乘法是怎么算出来的？—— 两种算法思路

> **数学本质**：A × B，B 的第 k 位为 1，等价于加上 A << k。不管哪种算法，都是这句话。

用 A = 1101 (13)、B = 101 (5) 做例子，结果 = 111101 (65)。

**方式 1：竖式乘法（教科书手写）**

把 B 每一位拆开，每遇到 bit=1，就把 A 左移对应位数，全部生成完后最后一次性相加。

```
bit0=1 → A << 0 →     1101
bit1=0 → A << 1 →     0000  （丢弃不加）
bit2=1 → A << 2 →  110100

最后：1101 + 110100 = 111101  ✓
```

> **特点**：先产生一堆移位后的分项，全部生成完，最后统一求和。

**方式 2：迭代累加算法（移位-累加，早期 CPU 软件模拟乘法）**

算一位 → 累加 → 左移 → 再处理下一位，循环逐步滚出结果，不是先存全部分项。

```
结果 = 0, A = 1101, B = 101

第一轮（B 的 bit0 = 1）：结果 += A → 结果 = 1101
                         A <<= 1  → A = 11010
                         B >>= 1  → B = 10

第二轮（B 的 bit0 = 0）：跳过（不加）
                         A <<= 1  → A = 110100
                         B >>= 1  → B = 1

第三轮（B 的 bit0 = 1）：结果 += A → 结果 = 1101 + 110100 = 111101  ✓
                         A <<= 1  → A = 1101000
                         B >>= 1  → B = 0  → 循环结束
```

> **特点**：每一轮 A 不断左移，结果逐步累加，一步一步滚出最终值。

**关键区分**

| | 竖式乘法 | 迭代累加 |
|---|---|---|
| **分项生成** | 全部先写出来 | 逐个生成 |
| **求和时机** | 最后一次性相加 | 每轮立即累加 |
| **用途** | 手写做题 | 早期 CPU 软件模拟 |

**现代 AArch64 硬件：都不是上面那个循环**

现代 CPU 用**硬件阵列乘法器**——并行同时算出所有 bit 对应的移位项，内部一次性完成全部加法，直接输出完整 128 位乘积，没有循环。对外你看到的就是一条 `MUL` 指令直接出结果，通常 3-5 个 cycle。

> **一句话总结**：做题手写 → 竖式（全部分项最后一起加）；老 CPU 软件模拟 → 循环（判断 bit、左移、累加）；AArch64 硬件 → 并行阵列乘法器，一条指令直接出 128 位结果。

### 为什么低 64 位有符号 = 无符号？（补码数学原理）

> **核心命题**：两个 64 位数相乘，无论按有符号（补码）还是无符号解读，**结果的低 64 位完全相同**。

**第一步：有符号和无符号的差异是什么？**

设 A 是 64 位数，`a₆₃` 是最高位（符号位）：

```
无符号值：A_u =  a₆₃·2⁶³ + a₆₂·2⁶² + ... + a₀·2⁰
有符号值：A_s = -a₆₃·2⁶³ + a₆₂·2⁶² + ... + a₀·2⁰

差异：A_u − A_s = 2·a₆₃·2⁶³ = a₆₃·2⁶⁴

结论：A_u = A_s + a₆₃·2⁶⁴
       （符号位为 1 时，无符号值 = 有符号值 + 2⁶⁴）
```

**第二步：乘法的差异全在 2⁶⁴ 的倍数上**

同理 `B_u = B_s + b₆₃·2⁶⁴`，展开乘法：

```
A_u × B_u = (A_s + a₆₃·2⁶⁴) × (B_s + b₆₃·2⁶⁴)

           = A_s × B_s                          ← 有符号乘积
           + (A_s·b₆₃ + B_s·a₆₃) × 2⁶⁴         ← 低 64 位不受影响
           + a₆₃·b₆₃ × 2¹²⁸                    ← 更高位

结论：A_u × B_u ≡ A_s × B_s  (mod 2⁶⁴)
```

> **一句话：补码设计使得 `A_u ≡ A_s (mod 2⁶⁴)`，乘法保持同余，所以低 64 位必然相同。** 这和加法不需要区分有符号/无符号是同一个道理。

**第三步：具体例子验证**

```asm
; x0 = -1 = 0xFFFFFFFFFFFFFFFF（补码）
; x1 = 3   = 0x0000000000000003

; 有符号解读：(-1) × 3 = -3
;   -3 的补码 = 0xFFFFFFFFFFFFFFFD

; 无符号解读：18446744073709551615 × 3 = 55340232221128654845
;   = 0x2_FFFFFFFFFFFFFFFD
;   低 64 位 = 0xFFFFFFFFFFFFFFFD  ← 和有符号一样！
;   高 64 位 = 0x0000000000000002  ← 这里有差异

mul    x2, x0, x1     ; x2 = 0xFFFFFFFFFFFFFFFD（低 64 位，两者相同）
smulh  x3, x0, x1     ; x3 = 0xFFFFFFFFFFFFFFFF（有符号高位 = -1 符号扩展）
umulh  x4, x0, x1     ; x4 = 0x0000000000000002（无符号高位，不同！）
```

> **回答两个问题：**
> 1. **MUL 做的是补码乘法吗？** 硬件做的是纯二进制乘法，但因为补码的数学性质，低 64 位对有符号和无符号都正确。不需要专门的"补码乘法器"。
> 2. **为什么低 64 位相同？** 有符号和无符号的差异 = 2⁶⁴ 的整数倍，取低 64 位（mod 2⁶⁴）后差异消失。高位才有区别，所以 SMULH/UMULH 要分开。

### 1. MUL — 取低 64 位

```asm
mul  x0, x1, x2          ; x0 = (x1 × x2) 的低 64 位
```

只取 128 位乘积的低一半（低 64 bit）。

> **补码特性关键点**：不管把 Rn、Rm 当成有符号还是无符号数，**低 64 位结果完全相同**。丢掉高 64 位，相当于自动对 2^64 取模。

```asm
; 负数乘法示例
mov  x0, #-2
mov  x1, #3
mul  x2, x0, x1          ; (-2)*3 = -6
                          ; 128 位结果的低 64 位 = -6 的补码，存入 x2
                          ; x2 = 0xFFFFFFFFFFFFFFFA
```

> `MUL` 等价于 `MADD Rd, Rn, Rm, XZR`（加数填零寄存器）。

### 2. MADD — 乘加（Multiply-Add）⭐ HFT 高频

```asm
madd x0, x1, x2, x3      ; x0 = x3 + x1 * x2
                           ;       Ra  + Rn  * Rm
                           ; 先乘后加，只保留低 64 位
```

一条指令完成乘加。HFT 交易计算：`总价 = 手续费 + 单价 × 数量`，比 `MUL + ADD` 少一条指令，延迟更低。

```asm
; x0 = fee + price * quantity
madd x0, x1, x2, x3      ; x0 = x3 + x1 * x2
```

```c
// C 代码 → 编译器自动生成 MADD
int64_t total = fee + (price * quantity);  // gcc -O2 → madd
```

### 3. MSUB — 乘减（Multiply-Subtract）

```asm
msub x0, x1, x2, x3      ; x0 = x3 - x1 * x2
                           ;       Ra  − Rn  * Rm
                           ; 先乘，再用 Ra 减去乘积，取低 64 位
```

### 4. SMULH / UMULH — 取高 64 位

MUL 只拿低 64 位。如果需要完整 128 位乘积，高 64 位必须用这两条。

> ⚠️ **高位有符号、无符号结果不一样，必须选对指令！**

```asm
; 完整 128 位有符号乘法
; x1:x0 = x2 * x3  （x1=高 64 位，x0=低 64 位）
mul    x0, x2, x3        ; 低 64 位
smulh  x1, x2, x3        ; 有符号乘法的高 64 位

; 完整 128 位无符号乘法
mul    x0, x2, x3
umulh  x1, x2, x3
```

### 关键考点（必记）

1. **64 位 × 64 位 = 128 位结果**
2. **低 64 位**：有符号、无符号结果完全相同，`MUL` 一条搞定
3. **高 64 位必须区分**：`SMULH`（有符号）/ `UMULH`（无符号）
4. `MADD` 可以替代 `MUL`：`mul x0, x1, x2` = `madd x0, x1, x2, xzr`

### 思考题

> 两个 64 位寄存器相乘，如果只用 MUL，高 64 位去哪里了？

<details>
<summary>答案</summary>

直接被硬件丢弃，只保留低 64 位，等价模 2^64。如果业务需要完整高精度结果，必须搭配 `SMULH`（有符号）或 `UMULH`（无符号）。

</details>

## HFT 实战视角

### MADD / MSUB 优先（价格计算）

```asm
; 总价 = 基础费 + 单价 × 数量
; x1 = price, x2 = qty, x3 = base_fee
madd x0, x1, x2, x3       ; x0 = base_fee + price * qty
                           ; 一条指令完成，比 mul + add 少一条

; 净额 = 总额 - 手续费率 × 数量
; x1 = fee_rate, x2 = qty, x3 = total
msub x0, x1, x2, x3       ; x0 = total - fee_rate * qty
```

```c
// C 代码对应
// 编译器会自动把 a + b * c 优化为 MADD
int64_t total = base_fee + price * qty;  // → madd
int64_t net   = total - fee_rate * qty;  // → msub
```
