## 8 大易错点

### 1. 有符号 vs 无符号比较用错条件后缀（`LT` vs `LO`）

```asm
; ❌ 错误：地址比较用了有符号 LT
cmp  x0, x1
b.lt skip                  ; 地址是有符号？错！如果高位为 1 会被当负数

; ✅ 正确：地址用无符号比较
cmp  x0, x1
b.lo skip                  ; LO = 无符号 <
```

| 比较对象 | 正确后缀 | 错误后缀 | 原因 |
|---------|---------|---------|------|
| 地址 | `LO`/`HS`（无符号） | `LT`/`GE`（有符号） | 地址高位为 1（如内核地址 `0xFFFF...`）会被当负数 |
| 大小/长度 | `LO`/`HS` | `LT`/`GE` | 同上 |
| 价格/盈亏 | `LT`/`GE`（有符号） | `LO`/`HS` | 可能为负 |
| 下标 vs 上限 | `LO`/`HS` | `LT`/`GE` | 下标和上限都是无符号 |

### 2. `ASR` vs `LSR` 选择错误

```asm
; ❌ 错误：有符号负数右移用了 LSR
mov  x0, #-8               ; 0xFFFFFFFFFFFFFFF8
lsr  x1, x0, #1            ; → 0x7FFFFFFFFFFFFFFC (大正数，错误!)

; ✅ 正确：有符号用 ASR
asr  x1, x0, #1            ; → 0xFFFFFFFFFFFFFFFC (-4，正确)
```

| 数据类型 | 右移指令 | 高位补 | 效果 |
|---------|---------|--------|------|
| 无符号 | `LSR` | 补 0 | 正确除以 2^n |
| 有符号（补码） | `ASR` | 补符号位 | 保持符号的除以 2^n |

> **一句话**：左移都用 LSL；右移有符号用 ASR、无符号用 LSR。

### 3. `SUBS` 的 C 标志是借位取反

```asm
subs x0, x1, x2            ; C = NOT(Borrow)
```

| 情况 | 借位 | C 标志 | 含义 |
|------|------|--------|------|
| x1 ≥ x2（够减） | 无 | **C=1** | HS（≥）成立 |
| x1 < x2（不够减） | 有 | **C=0** | LO（<）成立 |

> ⚠️ ARM 的 C 标志在减法中是**取反的借位**，与 x86 CF 相反！x86 中 x86 CF=借位（不够减时 CF=1），ARM 中 C=NOT(借位)（不够减时 C=0）。

### 4. `UBFX` vs `SBFX` 选错

```asm
; 场景：提取有符号 8 位偏移量
; ❌ 错误
ubfx x1, x0, #0, #8        ; 零扩展，负偏移变成大正数

; ✅ 正确
sbfx x1, x0, #0, #8        ; 符号扩展，保持负值
```

| 字段语义 | 用哪个 | 原因 |
|---------|--------|------|
| 类型码/索引（≥ 0） | `UBFX` | 无符号，高位补 0 |
| 偏移量/差值（可能 < 0） | `SBFX` | 有符号，高位补符号位 |

### 5. 忘加 S 后缀 → NZCV 不更新

```asm
; ❌ 错误：ADD 不设标志
add  x0, x1, x2
b.eq equal                  ; 读的是旧标志！不是这次加法的结果

; ✅ 正确：ADDS 设标志
adds x0, x1, x2
b.eq equal                  ; Z=1 → 加法结果为零
```

> 口诀：**带 S 改标志；不带 S 只算数值。**

### 6. `MUL` 不支持立即数

```asm
; ❌ 不存在
mul  x0, x1, #8            ; 编译报错！MUL 只支持寄存器操作数

; ✅ 方案 1：用移位（2 的幂）
lsl  x0, x1, #3            ; x0 = x1 * 8

; ✅ 方案 2：用 MADD + XZR
mov  x2, #8
madd x0, x1, x2, xzr       ; x0 = 0 + x1 * 8

; ✅ 方案 3：非 2 的幂用 MADD
mov  x2, #7
madd x0, x1, x2, xzr       ; x0 = x1 * 7
```

### 7. `SDIV` 向零截断 ≠ 向下取整

```asm
; -7 / 2:
sdiv x0, x1, x2            ; x0 = -7 / 2 = -3

; 向零截断: -3.5 → -3 (丢小数)
; 向下取整: -3.5 → -4 (数学上的 floor)
```

| 方式 | -7/2 结果 | 说明 |
|------|----------|------|
| SDIV（向零截断） | -3 | 丢掉小数部分 |
| floor（向下取整） | -4 | 数学上的取整 |
| C 语言整数除法 | -3 | 与 SDIV 一致（C99 标准向零截断） |

> C 语言的 `/` 整数除法与 ARM64 `SDIV` 行为一致（C99 起统一向零截断）。

### 8. 除零不报错

```asm
; ARM64 除零 → 结果 0，不 crash
mov  x0, #10
mov  x1, #0
udiv x2, x0, x1            ; x2 = 0 (不产生异常)

; x86 除零 → 触发 #DE 异常 (crash)
```

> ⚠️ 必须自行检查除数是否为 0！ARM64 不帮你报错。

## 补码常见误区

### 误区 1：补码 = "取反加一" 只是计算方法

> 补码的**本质**是"模运算"：`-x = 2^N - x`（mod 2^N）。取反加一只是快速计算方法。
> 补码的**优势**是加减统一：`a + (-b) = a + (2^N - b) = a + (~b + 1)`。

### 误区 2：ADD 指令区分有符号无符号

> ❌ `ADD` 指令**不区分**。同一条 ADD 对补码和无符号都正确。
> 只有**溢出检测**不同：C 标志检测无符号溢出，V 标志检测有符号溢出。

### 误区 3：MUL 指令区分有符号无符号

> ❌ `MUL` 取低 64 位时**不区分**。补码乘法低 64 位 = 无符号乘法低 64 位。
> 只有**高 64 位**不同（`SMULH` vs `UMULH`），以及**除法**完全不同（`SDIV` vs `UDIV`）。

## 易错速查表

| 易错点 | 错误 | 正确 |
|--------|------|------|
| 地址比较 | `B.LT`（有符号） | `B.LO`（无符号） |
| 负数右移 | `LSR`（补 0） | `ASR`（补符号位） |
| 减法 C 标志 | C=1 是进位 | C=1 是**无借位**（够减） |
| 有符号位段提取 | `UBFX`（零扩展） | `SBFX`（符号扩展） |
| 条件分支前 | `ADD`（不改标志） | `ADDS`（改 NZCV） |
| 立即数乘法 | `mul x0, x1, #8` | `lsl x0, x1, #3` |
| 负数除法 | 以为 `-7/2 = -4` | `SDIV` = -3（向零截断） |
| 除零 | 以为会 crash | 结果 = 0，不报错 |

## 自测题

1. 比较两个地址 x0 和 x1 应该用 B.LT 还是 B.LO？
<details><summary>答案</summary>

`B.LO`（无符号小于）。地址是无符号数，不能用有符号比较 LT。如果地址高位为 1（如内核地址 0xFFFF...），有符号比较会把它们当成负数，结果错误。

</details>

2. `-8 >> 1` 用 LSR 结果是什么？应该用什么？
<details><summary>答案</summary>

LSR 逻辑右移补 0 → -8(0xFFFFFFFFFFFFFFF8) >> 1 = 0x7FFFFFFFFFFFFFFC（大正数，错误）。应该用 ASR 算术右移补符号位 → 0xFFFFFFFFFFFFFFFC（-4，正确）。

</details>

3. SUBS x0, x1, x2 后 x1 < x2（无符号），C 标志是什么？
<details><summary>答案</summary>

C = NOT(Borrow) = NOT(1) = 0。因为有借位（x1 < x2）。所以 B.LO(C=0) 会跳转，B.HS(C=1) 不跳转。

</details>

4. 为什么 `mul x0, x1, #8` 会报错？
<details><summary>答案</summary>

因为 `MUL` 指令**不支持立即数操作数**，只接受寄存器。乘以 2 的幂应该用 `lsl`，或者先 `mov` 到寄存器再用 `madd`。

</details>

5. `-7 / 2` 在 ARM64 SDIV 中结果是多少？为什么不是 -4？
<details><summary>答案</summary>

结果 = **-3**。SDIV 向零截断（truncation toward zero），丢掉小数部分 0.5 → -3。不是数学上的向下取整 floor(-3.5) = -4。C 语言整数除法行为相同。

</details>

6. `adds x0, x1, x2` 后 `b.vs overflow` 检测什么？
<details><summary>答案</summary>

`VS` = V=1 = 有符号溢出。检测补码有符号加法是否溢出（如两个大正数相加变负数）。如果是无符号溢出要用 `b.cs`（C=1）。

</details>
