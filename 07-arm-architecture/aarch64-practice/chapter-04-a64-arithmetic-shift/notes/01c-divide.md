## 除法指令

| 指令 | 作用 | 有符号？ | 除零行为 |
|------|------|---------|---------|
| `SDIV` | `Rd = Rn / Rm` | ✅ 有符号 | 结果为 0 |
| `UDIV` | `Rd = Rn / Rm` | ❌ 无符号 | 结果为 0 |

> ⚠️ **除法是加减乘除中唯一必须区分有符号/无符号的指令。**

### 除法 vs 乘法：为什么除法慢？

> **核心区别**：乘法可以并行，除法必须串行。

**乘法**：每一位的分项互相独立，硬件阵列乘法器可以同时算出全部移位分项，一次性相加，3-4 周期完成。

**除法**：和手写长除法一模一样——逐位试商，每一步依赖上一步的余数：

```
例子：1101(13) ÷ 101(5)

每一轮：
  1. 余数左移一位
  2. 拿余数和除数做减法
  3. 够减（余数 ≥ 除数）→ 商这位写 1，保存新余数
  4. 不够减 → 商这位写 0，余数不变
  5. 重复，算完所有 bit

👉 必须先算出当前位的余数，才能算下一位。
   前面结果不知道，后面就没法算。
```

| | 乘法 | 除法 |
|---|---|---|
| **硬件实现** | 并行阵列，一次性算出全部分项再求和 | 串行迭代，一步试一位商，余数传给下一步 |
| **数据依赖** | 各位互相独立 | 下一轮强依赖上一轮余数 |
| **周期数** | ~3-4 cycle | ~7-20 cycle |
| **流水线** | 可重叠 | 不能重叠，上一条没做完下一条不能开始 |

> **一句话**：乘法可以全部同时算；除法必须一步一步试商，前面没算完，后面不能算。

### SDIV 向零截断

```asm
; 有符号除法
mov  x0, #-7
mov  x1, #2
sdiv x2, x0, x1           ; x2 = -7 / 2 = -3（向零截断，不是 -4！）

; 无符号除法
mov  x0, #0xFFFFFFFFFFFFFFF9  ; = -7 的补码，但当作无符号 = 18446744073709551609
mov  x1, #2
udiv x2, x0, x1           ; x2 = 18446744073709551609 / 2 = 9223372036854775804
```

| 被除数 | 除数 | SDIV 结果 | 说明 |
|--------|------|----------|------|
| 7 | 2 | 3 | 3.5 → 截断 → 3 |
| -7 | 2 | -3 | -3.5 → 向零截断 → -3（不是 -4） |
| 7 | -2 | -3 | 3.5 → 截断 → -3 |
| -7 | -2 | 3 | -3.5 → 向零截断 → 3 |

> **向零截断**（truncation toward zero）= 丢掉小数部分，不四舍五入。

### 除零不抛异常 ⚠️

ARM64 除法**不产生异常**，除零时结果为 0（不 trap）：

```asm
mov  x0, #10
mov  x1, #0
udiv x2, x0, x1           ; x2 = 0（不 crash，不 trap）
```

> ⚠️ 这跟 x86 不同（x86 除零触发 #DE 异常）。软件必须自行检查除数是否为 0。

```c
// HFT 业务代码必须手动校验除数
inline int64_t safe_div(int64_t a, int64_t b) {
    if (b == 0) return 0;          // ARM64 除零返回 0，但业务上要明确处理
    return a / b;                   // 编译器生成 sdiv
}
```

### UDIV / SDIV 只返回商，不返回余数

除法指令只给商，想要余数要用 MSUB 单独算：

```asm
udiv x2, x0, x1        ; x2 = x0 / x1（商）
msub x3, x2, x1, x0    ; x3 = x0 − x2 * x1（余数 = 被除数 − 商 × 除数）
```

> 对比 x86：x86 的 `IDIV` 同时返回商和余数到两个寄存器；ARM64 需要两条指令。

### 除法不更新 NZCV ⚠️

除法指令**完全不碰 NZCV 标志位**。除零、商溢出都不会自动设置标志。

| 指令 | 更新 NZCV？ | 除零行为 |
|------|-----------|---------|
| `ADDS` / `SUBS` | ✅ 自动更新 | — |
| `MUL` / `MADD` | ❌ 不更新 | — |
| `UDIV` / `SDIV` | ❌ 不更新 | 返回 0，不 trap |

> 软件必须自行检查除数是否为 0、商是否溢出，硬件不给任何提示。

## 取负指令

```asm
neg  x0, x1               ; x0 = -x1 ≡ sub x0, xzr, x1
negs x0, x1               ; 同上 + 设置 NZCV
ngc  x0, x1               ; x0 = -x1 - NOT(C)（带借位取负）
```

> `NEG` 是伪指令，汇编器展开为 `SUB XZR, ...`。

## 补码运算总结表（必背）

| 运算 | 有无符号是否共用指令 | 备注 |
|------|---------------------|------|
| **加法 ADD** | ✅ 共用 | 看 V 判断有符号溢出，C 判断无符号进位 |
| **减法 SUB** | ✅ 共用 | 同上 |
| **乘法（低64位）MUL** | ✅ 共用 | 补码数学性质决定 |
| **乘法（高64位）** | ❌ 分开 | `SMULH`（有符号）/ `UMULH`（无符号） |
| **除法** | ❌ 分开 | `SDIV`（向零截断）/ `UDIV`，除零不报错 |

> **一句话**：加减乘（低位）不需要区分有符号无符号；除法必须选。

## HFT 实战视角

### SDIV 精度陷阱（百分比计算）

```c
// HFT 价格变动百分比计算
int64_t price_change = new_price - old_price;   // 可能为负
int64_t result = price_change / old_price;       // SDIV 向零截断

// ⚠️ 陷阱：-7 / 2 = -3，不是 -4
// 做净值/百分比计算时，向零截断会带来系统性偏差
// 如果需要向下取整，要用额外逻辑：
int64_t floored_div(int64_t a, int64_t b) {
    int64_t q = a / b;
    int64_t r = a % b;
    if ((r != 0) && ((r < 0) != (b < 0)))
        q--;                    // 向下取整修正
    return q;
}
```

### 除零安全检查

```c
// ARM64 除零不会 crash，但会静默返回 0
// HFT 代码必须校验，否则会导致错误的交易决策

inline int64_t safe_pct(int64_t num, int64_t denom) {
    if (denom == 0) {
        // 不能静默返回 0，要记录告警
        // log_warn("division by zero: num=%ld", num);
        return 0;
    }
    return num / denom;
}
```

### 除法很慢，尽量避开热路径 💡

除法 7-20 周期且不能流水线重叠，是加减乘除中最慢的。HFT 热路径应尽量少用。

**编译器自动优化**：如果除数是编译期常量，编译器会换成"乘以魔数 + 右移"，用快速乘法模拟除法，完全避开 UDIV/SDIV：

```c
int64_t x = a / 8;    // 编译器不会生成 UDIV
                      // 而是生成：ASR x0, x0, #3（算术右移3位）

int64_t y = a / 3;    // 编译器生成：乘以魔数 0x5555555555555556 + 右移
                      // 仍然不生成 SDIV
```

> **工程启示**：除数是常量 → 编译器帮你优化掉；除数是变量 → 没办法，只能 UDIV/SDIV 硬扛。金融代码做定点除法要特别小心除零和商溢出，硬件不会帮你检测。

## 思考题

> 为什么编译器遇到 `x / 8`，根本不会生成 `UDIV`，直接变成右移 3 位？

<details><summary>答案</summary>

因为除以 8 = 除以 2³，在二进制中等于右移 3 位。右移只需要 1 个周期，而 UDIV 需要 7-20 个周期。编译器对 2 的幂次除法一律优化为移位。

对于非 2 的幂常量除数（如 `/ 3`），编译器使用"魔数乘法"（magic number multiplication）——用乘法 + 移位来模拟除法，仍然比 UDIV 快得多。

只有当除数是运行时变量时，编译器才不得不生成真正的 UDIV/SDIV 指令。

</details>

## 自测题

1. `SDIV` 和 `UDIV` 有什么区别？`-7 / 2` 分别得多少？
<details><summary>答案</summary>

- `SDIV`：有符号除法，向零截断。`-7 / 2 = -3`（不是 -4，向零截断丢小数）
- `UDIV`：无符号除法。同样的比特流 `0xFFFF...FFF9 / 2` = 极大正数

**除法是加减乘中唯一必须显式选择有符号/无符号的运算。**

</details>

2. ARM64 除零会产生异常吗？
<details><summary>答案</summary>

**不会**。ARM64 除零结果为 0，不产生异常也不 trap。软件必须自行检查除数是否为 0。这与 x86 不同（x86 除零触发 #DE 异常）。

</details>

3. `NEG x0, x1` 等价于哪条指令？`NEGS` 呢？
<details><summary>答案</summary>

`NEG x0, x1` ≡ `SUB x0, XZR, x1`（零寄存器减去 x1）。
`NEGS` 同理 ≡ `SUBS x0, XZR, x1`，额外更新 NZCV 标志。

</details>
