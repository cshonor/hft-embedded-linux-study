# 7.2 字符串加载陷阱

> 来源：§7.2 · 精读 · [章总览](section-0-本章完整概述.md)

## 本节讲什么

加载字符串常量到寄存器的陷阱——字符顺序和内存布局的混淆。

## 核心要点

```asm
; 想加载 "ABCD" (0x44434241) 到 x0
ldr x0, ='ABCD'    ; 小端模式：x0 = 0x44434241
```

小端模式下字符串的字节顺序：
- 内存中：A(0x41) B(0x42) C(0x43) D(0x44)
- 加载到 64 位寄存器：x0 = 0x44434241（D 在高位）

常见错误：
- 以为 `ldr x0, ='ABCD'` 得到 0x41424344 → 实际是小端 0x44434241
- 字符串超过 8 字节无法用单条 LDR 加载

## HFT 关联

字符串加载在协议标记识别中有用：
- 快速比较 4/8 字节的协议标记（如 "FIXT", "ITCH"）
- 用 LDR 加载常量字符串后与数据比较 → 一条指令完成 8 字节对比
- 但需注意端序——小端模式下字符顺序反转
- 更推荐用 C 代码 `memcmp`，编译器自动处理端序

## 自测题

1. `ldr x0, ='AB'` 执行后（小端模式），x0 的值是什么？
<details><summary>答案</summary>
'A'=0x41, 'B'=0x42。小端存储：内存 [0x41, 0x42, 0, 0, 0, 0, 0, 0]。加载到 x0 = 0x0000000000004241。注意 B 在高位。
</details>

2. 如何快速检查 4 字节字符串是否为 "FIXT"？
<details><summary>答案</summary>
```asm
ldr x1, ='FIXT'      ; 加载常量（小端：0x54584946）
ldr w0, [x2]         ; 读数据（4字节）
cmp w0, w1
b.eq match
```
用 32 位比较一次检查 4 个字符。注意小端模式下 'F' 在低位。
</details>

3. 为什么字符串超过 8 字节不能单条 LDR 加载？
<detail><summary>答案</summary>
LDR 最多加载 64 位（8 字节）。超过 8 字节的字符串需要多条 LDR 或用循环加载。更实际的做法是用 C 代码 `strcmp/memcmp`，让编译器生成高效的比较代码。
</details>
