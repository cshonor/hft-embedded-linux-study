# §13.5 中断触发类型

> **来源：** [Ch13 完整概述](section-0-本章完整概述.md) · [章导读](../README.md)

## 本节讲什么

GIC 支持两种中断触发类型：边沿触发（Edge，信号跳变时触发）和电平触发（Level，信号保持高电平触发）。通过 GICD_ICFGR 寄存器配置，每中断 2 位。触发类型选择直接影响中断的可靠性和 ISR 中的清除逻辑。

## 核心要点

### 触发类型对比

| 类型 | 说明 | GICD_ICFGR 值 | 信号要求 | 适用场景 |
|------|------|-------------|----------|----------|
| **边沿触发** (Edge) | 信号跳变时触发 | 0b10 | 上升沿/下降沿 | GPIO 按键、脉冲信号 |
| **电平触发** (Level) | 信号保持高电平触发 | 0b00 | 持续高电平 | 通用定时器、UART |

### 设置代码

```c
// 设置中断 30 为边沿触发
// ICFGR 每 16 个中断一组，每中断 2 位
// 先清除原值，再设新值
GICD->ICFGR[30/16] &= ~(0x3 << (2 * (30 % 16)));  // 清除
GICD->ICFGR[30/16] |=  (0x2 << (2 * (30 % 16)));  // 设为边沿（0b10）

// 设置中断 33 为电平触发（默认值，通常不需要设）
GICD->ICFGR[33/16] &= ~(0x3 << (2 * (33 % 16)));  // 清除为 0b00 = 电平
```

### ICFGR 分组规则

| 项目 | 值 |
|------|----|
| 分组大小 | 每 16 个中断一组 |
| 每中断位数 | 2 位 |
| 索引 | `ICFGR[irq/16]` |
| 位域定位 | `2*(irq%16)` |
| 值 0b00 | 电平触发（Level-sensitive, active-high） |
| 值 0b01 | 保留（不要使用） |
| 值 0b10 | 边沿触发（Edge-triggered, rising edge） |
| 值 0b11 | 保留（不要使用） |

### 边沿 vs 电平：关键区别

| 特性 | 边沿触发 | 电平触发 |
|------|----------|----------|
| 触发条件 | 信号跳变（上升沿） | 信号保持高电平 |
| 丢失风险 | 处理中又来跳变可能丢失 | 不会丢失（只要电平保持） |
| 清除方式 | 自动（边沿是瞬态的） | 需要在 ISR 中清除中断源 |
| ISR 必做 | 无特殊要求 | **必须清除中断源**（重设 TVAL/清标志位） |
| 重复触发 | 一次跳变只触发一次 | 未清除会持续触发 |
| 典型场景 | GPIO 按键 | 定时器、UART |

### 电平触发 ISR 清除流程

```
定时器中断（电平触发）处理流程：
┌──────────────────────────────────────┐
│ 1. 定时器倒计到 0 → 中断信号拉高     │
│ 2. GIC 标记 pending → 送 CPU          │
│ 3. CPU 读 IAR → 获取中断号 30         │
│ 4. ISR 执行：                         │
│    a. 重设 TVAL → 定时器重新倒计      │
│    b. （此时中断信号拉低）            │
│    c. 处理定时器逻辑                  │
│ 5. 写 EOIR → 中断结束                 │
└──────────────────────────────────────┘

关键：步骤 4a 必须在 EOIR 之前执行！
如果 EOIR 先写 → 中断信号仍高 → GIC 立即再发中断 → ISR 重入
```

### 边沿触发丢失场景

```
时间线（边沿触发）：
T0: 第一个跳变 → GIC pending → CPU 开始处理
T1: ISR 执行中（中断被屏蔽）
T2: 第二个跳变 → GIC 已 pending，不记录
T3: ISR 结束，EOIR 写入
T4: GIC pending 已清，第二个跳变丢失！

电平触发不会丢：T2 时电平仍高 → T3 后 GIC 重新 pending
```

> 通用定时器中断通常是**电平触发**。
> GPIO 按键中断通常用**边沿触发**。

## HFT 关联

触发类型选择影响 HFT 系统的中断可靠性。电平触发的定时器中断在 ISR 中必须清除中断源（重设 TVAL），否则中断会持续触发（因为电平保持高）。边沿触发的 GPIO 中断适合一次性事件（如按键），但如果在 ISR 处理期间有多个跳变，可能只记录一次——这在 HFT 中可能导致丢失事件。选择触发类型时，要考虑中断源的物理特性：定时器/UART 用电平（保证不丢），GPIO 事件用边沿（只关心变化）。

## 自测题

1. **通用定时器中断通常用什么触发类型？为什么？**

<details>
<summary>答案</summary>

**电平触发**。定时器倒计到 0 后，中断信号保持高电平直到软件清除（重设 TVAL 或禁定时器）。用电平触发确保：只要中断条件未清除，GIC 会持续通知 CPU。如果用边沿触发，可能只触发一次后就不再通知。
</details>

2. **如何将中断号 30 从电平触发改为边沿触发？**

<details>
<summary>答案</summary>

```c
// ICFGR 每 16 个中断一组，每中断 2 位
// 先清除原值，再设新值
GICD->ICFGR[30/16] &= ~(0x3 << (2 * (30 % 16)));  // 清除
GICD->ICFGR[30/16] |=  (0x2 << (2 * (30 % 16)));  // 设为边沿（0b10）
// 30/16 = 1（第 1 组），30%16 = 14（第 14 个 2 位槽）
```
</details>

3. **边沿触发和电平触发哪个更容易丢失中断？为什么？**

<details>
<summary>答案</summary>

**边沿触发更容易丢失**。边沿触发在信号跳变时触发一次，如果在 ISR 处理期间（中断被屏蔽）又发生跳变，GIC 可能不记录第二次跳变（取决于是否支持 pending 状态）。电平触发只要信号保持高电平，GIC 会持续标记为 pending，不会丢失。
</details>

4. **电平触发定时器中断的 ISR 中，如果先写 EOIR 再重设 TVAL，会发生什么？**

<details>
<summary>答案</summary>

写 EOIR 后 GIC 认为中断结束。但此时 TVAL 还没重设，定时器中断信号仍为高电平 → GIC 立即检测到新的 pending → **立刻再发同一个中断** → ISR 重入 → 死循环。

正确顺序：先重设 TVAL（中断信号拉低）→ 再写 EOIR。确保 EOIR 写入时中断信号已经清除。
</details>
