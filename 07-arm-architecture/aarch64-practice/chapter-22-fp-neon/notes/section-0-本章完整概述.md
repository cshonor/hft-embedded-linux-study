## 本章定位

ARMv8 的浮点（FP）和 SIMD（NEON）指令。用于图像处理、矩阵运算、信号处理加速。选读——姿态解算（Kalman 滤波）可后接。

---

## 22.1 浮点寄存器

ARMv8 有 **32 个 128 位 SIMD/FP 寄存器** V0-V31：

| 视角 | 宽度 | 名称 |
|------|------|------|
| 128 位 | 全宽 | Vn / Qn |
| 64 位 | 低半 | Dn |
| 32 位 | 低四分之一 | Sn |
| 16 位 | 低八分之一 | Hn |
| 8 位 | 低十六分之一 | Bn |

```
V0 [127:0]  ← 128 bit (Q0)
   [63:0]   ← 64 bit  (D0)
   [31:0]   ← 32 bit  (S0)
   [15:0]   ← 16 bit  (H0)
   [7:0]    ← 8 bit   (B0)
```

---

## 22.2 NEON 向量寄存器

128 位 V 寄存器可拆分为**并行通道**（Lanes）：

| 指令后缀 | 通道数 | 每通道宽度 | 类型 |
|----------|--------|-----------|------|
| `.16b` | 16 | 8 bit | 字节 |
| `.8h` | 8 | 16 bit | 半字 |
| `.4s` | 4 | 32 bit | 单字 |
| `.2d` | 2 | 64 bit | 双字 |

```
V0 = | B15| B14| B13| B12| B11| B10| B9 | B8 | B7 | B6 | B5 | B4 | B3 | B2 | B1 | B0 |
     ←──────────────────── 16B ────────────────────→
     ←─────── 8H ───────→←─────── 8H ───────→
     ←── 4S ──→←── 4S ──→←── 4S ──→←── 4S ──→
```

---

## 22.3 常用 NEON 指令

| 指令 | 行为 |
|------|------|
| `LD1 {V0.4s}, [X0]` | 加载 4×32bit 到 V0 |
| `LD2 {V0.4s, V1.4s}, [X0]` | 交错加载 2 通道（RGB 解交织） |
| `ST1 {V0.4s}, [X0]` | 存储 V0 |
| `ADD V0.4s, V1.4s, V2.4s` | 4 路并行加法 |
| `MUL V0.4s, V1.4s, V2.4s` | 4 路并行乘法 |
| `FADD V0.4s, V1.4s, V2.4s` | 4 路浮点加法 |
| `FMUL V0.4s, V1.4s, V2.4s` | 4 路浮点乘法 |
| `FMLA V0.4s, V1.4s, V2.4s` | 4 路浮点乘加（V0 += V1 × V2） |

> **FMLA 是矩阵乘法的核心**：一条指令完成 4 路乘加，吞吐量是标量的 4 倍。

## 22.4 RGB → BGR 转换示例

```c
// 标量 C 版本
void rgb_to_bgr_c(uint8_t *dst, const uint8_t *src, int n) {
    for (int i = 0; i < n; i += 3) {
        dst[i]   = src[i+2];  // B
        dst[i+1] = src[i+1];  // G
        dst[i+2] = src[i];    // R
    }
}
```

```asm
// NEON 版本（一次处理 16 像素 × 3 = 48 字节）
// 使用 LD3 交错加载（自动分离 R/G/B 到不同寄存器）
rgb_to_bgr_neon:
    // LD3 交错加载：R→V0, G→V1, B→V2
1:  ld3 {v0.16b, v1.16b, v2.16b}, [x0], #48
    // 交换 R 和 B（V0 和 V2）
    // ST3 交错存储：B→V2, G→V1, R→V0
    st3 {v2.16b, v1.16b, v0.16b}, [x1], #48
    subs x2, x2, #48
    b.gt 1b
    ret
```

> **LD3/ST3 自动解交织/交织**：RGB 数据是 R0G0B0R1G1B1...，LD3 自动分离成 R0R1...V0、G0G1...V1、B0B1...V2。

## 22.5 矩阵乘法加速

```c
// 4×4 矩阵乘 C = A × B（float）
// 标量：64 次乘法 + 48 次加法
// NEON：16 条 FMUL/FMLA 指令（4 路并行）
```

```asm
; NEON 4×4 矩阵乘（简化版）
; A 在 v0-v3（每行一个 .4s）
; B 列在 v4-v7
    ; C 的第 0 列
    fmul v8.4s, v0.4s, v4.s[0]     ; A[0] × B[0][0]
    fmla v8.4s, v1.4s, v4.s[1]     ; += A[1] × B[1][0]
    fmla v8.4s, v2.4s, v4.s[2]     ; += A[2] × B[2][0]
    fmla v8.4s, v3.4s, v4.s[3]     ; += A[3] × B[3][0]
    ; ... 其他列同理
```

> **Kalman 滤波**：状态更新和协方差更新都是矩阵运算，NEON 可加速 3-4 倍。

## 22.6 NEON 内建函数（Intrinsics）

```c
#include <arm_neon.h>

// 4 路浮点加法
float32x4_t a = vld1q_f32(ptr_a);
float32x4_t b = vld1q_f32(ptr_b);
float32x4_t c = vaddq_f32(a, b);  // c = a + b (4路并行)
vst1q_f32(ptr_c, c);

// 矩阵乘加
float32x4_t acc = vdupq_n_f32(0.0f);  // 清零
acc = vfmaq_f32(acc, a, b);           // acc += a * b
```

> **Intrinsics vs 汇编**：Intrinsics 可读性更好，编译器可以寄存器分配优化。  
> **C++ NEON**：跨平台可用 `#ifdef __ARM_NEON` 条件编译。

## 22.8 易错点清单

1. **NEON 寄存器在异常中没保存** → 中断/异常处理中用了 V 寄存器，会破坏用户态浮点状态。Linux 在切换时保存/恢复。
2. **FPEN 没开** → CPACR_EL1.FPEN 控制浮点使能，没开会触发 traps。
3. **通道数不匹配** → `ADD V0.4s, V1.8h, V2.4s` 会报错。
4. **LD3 对齐** → 交错加载要求地址对齐到通道宽度。

## 书中思考题（自测）

1. V 寄存器有几种视角（宽度）？128 位怎么拆？
2. `.4s` 后缀代表什么？一条 ADD .4s 能同时做几次加法？
3. LD3 / ST3 在 RGB 数据处理中有什么优势？
4. FMLA 指令做什么？为什么适合矩阵乘法？
5. NEON intrinsics 和汇编相比有什么优缺点？

**参考答案：**

1. Q(128)/D(64)/S(32)/H(16)/B(8)，低位是高位的一部分。  
2. **4 通道 × 32 bit**。一条 ADD .4s 做 **4 次** 32 位加法。  
3. **自动解交织/交织**：RGB 交织数据自动分离到不同寄存器，省去手动重组。  
4. **乘加**（V0 += V1 × V2），4 路并行。矩阵乘法核心操作，减少指令数。  
5. Intrinsics 可读性好、编译器可优化寄存器分配；汇编控制力更强但难维护。
