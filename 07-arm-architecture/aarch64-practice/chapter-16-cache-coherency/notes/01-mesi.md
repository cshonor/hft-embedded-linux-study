# §16.1 MESI 协议

> **来源：** [Ch16 完整概述](section-0-本章完整概述.md) · [章导读](../README.md)

## 本节讲什么

MESI 是多核 Cache 一致性协议，四个状态：Modified（已修改，内存过期）、Exclusive（独占，=内存）、Shared（共享，=内存，多核有副本）、Invalid（无效）。理解 MESI 是分析多核性能问题和伪共享的基础。

## 核心要点

### 四个状态

| 状态 | 名称 | Cache vs 内存 | 其他核有副本？ | evict 时 |
|------|------|--------------|---------------|----------|
| **M** | Modified | Cache 有最新数据，内存过期 | 无 | 必须写回内存 |
| **E** | Exclusive | Cache = 内存（一致） | 无 | 直接丢弃 |
| **S** | Shared | Cache = 内存（一致） | 有（也是 S） | 直接丢弃 |
| **I** | Invalid | Cache 行无效 | — | 无操作 |

### MESI 速记

| 状态 | 一句话记忆 | 写操作 |
|------|-----------|--------|
| M | 改了，只有我有，内存过期 | 直接写（无需广播） |
| E | 只有我有，内存是最新的 | 直接写变 M（无需广播） |
| S | 大家都有，都是最新的 | 广播 Invalidate → 变 M |
| I | 我的副本无效 | 需从内存加载 |

### 状态转换图

```
                  读 miss (无其他核有)
              ┌──────────────────────────┐
              |                          |
              v                          |
┌─────────┐ 读 miss    ┌─────────┐ 写命中  ┌─────────┐
| Invalid | ────────→ |Exclusive| ──────→ |Modified |
|   (I)   |           |   (E)   |        |   (M)   |
└─────────┘           └─────────┘        └─────────┘
    |                      |                   ^
    | 读 miss(其他核有)     | 读 miss(其他核有)  | 写命中
    v                      v                   |
┌─────────┐           ┌─────────┐              |
| Shared  | ─写命中─→ |Modified | ←─写 miss──┘
|   (S)   | (广播Inv) |   (M)   |
└─────────┘           └─────────┘
    |                      |
    | 读命中               | 读命中
    v                      v
  不变(S)                 不变(M)
```

### 关键状态转换

| 操作 | 原状态 | 新状态 | 总线活动 | 说明 |
|------|--------|--------|----------|------|
| 读命中 | M/E/S | 不变 | 无 | 直接读 cache |
| 写命中 | M | M | 无 | 直接写（已独占） |
| 写命中 | S | M | **广播 Invalidate** | 其他核变 I |
| 写命中 | E | M | 无 | 直接变 M（无需广播） |
| 读 miss | I | E/S | 总线读 | 从内存或其他核加载 |
| 写 miss | I | M | 总线读+Invalidate | 加载后写 |
| M evict | M | I | **写回内存** | 脏数据写回 |

### MESI 性能影响

| 操作 | 延迟 | 原因 |
|------|------|------|
| E 状态写 | 0 cycle 额外 | 直接变 M，无总线活动 |
| S 状态写 | 50-100ns | 广播 Invalidate + 等待确认 |
| M evict | 100ns+ | 写回内存 |
| 读 miss（其他核 M 有） | 100ns+ | 从其他核的 cache 拉取 |

### ARM 的 MESI 变体

| 协议 | 用于 | 特点 |
|------|------|------|
| MESI | 基本协议 | 四状态 |
| MOESI | ARM Cortex-A | 加 O（Owned）状态：已修改但可被其他核读 |
| MESIF | Intel | 加 F（Forward）：S 中只有一个转发者 |

> ARM Cortex-A 使用 MOESI（多一个 O 状态）。O 状态表示"已修改但其他核可读"——避免每次 S→M 都要写回内存。

## HFT 关联

理解 MESI 对 HFT 多核优化至关重要。E（独占）状态的写不需要广播——如果数据只有一个核访问，写操作零额外开销。S（共享）状态的写需要广播 Invalidate，增加延迟。HFT 系统应尽量让每个核有独占数据（如每核独立的订单队列），避免共享变量的写竞争。M 状态的 cache 行被 evict 时需要写回内存（~100ns），应避免频繁 evict 热数据。

## 自测题

1. **M 和 E 状态的区别是什么？**

<details>
<summary>答案</summary>

- **M**（Modified）：Cache 有最新数据，**内存已过期**（不一致）。被 evict 时必须写回内存。
- **E**（Exclusive）：Cache = 内存（**一致**）。被 evict 时不需要写回（直接丢弃）。

两者都是"只有一个核有副本"，但 M 的内存不是最新的，E 的内存是最新的。
</details>

2. **S 状态的 cache 行被写时发生什么？**

<details>
<summary>答案</summary>

广播 **Invalidate** 给所有拥有该 cache 行副本的核 → 其他核的该行变 **I** → 本核变 **M**。这个过程有总线开销（广播+等待确认），比 E 状态的写（直接变 M，无广播）慢。
</details>

3. **为什么 E 状态的写比 S 状态的写快？HFT 如何利用这一点？**

<details>
<summary>答案</summary>

E 状态只有一个核有副本，写操作直接变 M，**不需要广播 Invalidate**。S 状态有多个核有副本，写操作需要广播 Invalidate 给所有持有副本的核并等待确认，有总线延迟。

HFT 利用：每核维护独立的数据（如每核的订单队列、统计计数器），让数据处于 E 状态（只一个核有），写操作零额外开销。避免共享变量的写——共享写触发 MESI 广播开销（50-100ns）。
</details>

4. **ARM 的 MOESI 中的 O（Owned）状态解决什么问题？**

<details>
<summary>答案</summary>

O 状态表示"数据已修改（与内存不一致），但其他核可以有 Shared 副本"。没有 O 状态时，M 状态的 cache 行如果被其他核读取，需要先写回内存（~100ns）再让其他核从内存加载。有了 O 状态，其他核可以直接从 O 状态的 cache 行读取（cache-to-cache 传输），省去写回内存的步骤。

O 状态 = Modified + 可共享，优化了"一个核修改后其他核读"的场景。
</details>
