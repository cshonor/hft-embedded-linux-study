# §14.5 访问权限（AP）

> **来源：** [Ch14 完整概述](section-0-本章完整概述.md) · [章导读](../README.md)

## 本节讲什么

页表项的 AP[2:1] 字段控制 EL0/EL1 的读写权限，UXN/PXN 控制可执行性。内核页设 UXN=1，用户页设 PXN=1（防 ret2usr）。理解权限矩阵是配置安全内存隔离的基础。

## 核心要点

### AP 权限矩阵

| AP[2:1] | EL0 | EL1+ | 说明 | 典型用途 |
|---------|-----|------|------|----------|
| 00 | R/W | R/W | 全部可读写 | 用户数据页 |
| 01 | None | R/W | 仅内核可读写 | 内核数据页 |
| 10 | R/O | R/O | 全部只读 | 代码段/只读数据 |
| 11 | R/O | R/W | 内核读写，用户只读 | 共享配置页 |

### UXN / PXN

| 位 | 名称 | 含义 | 典型设置 |
|----|------|------|----------|
| UXN | User eXecute Never | 用户态不可执行此页 | 内核页=1（用户不能执行内核代码） |
| PXN | Privileged eXecute Never | 内核态不可执行此页 | 用户页=1（内核不能执行用户代码） |

### 安全配置规则

```
┌──────────────────────────────────────────────────────┐
│                  安全页面配置规则                       │
├──────────────────┬──────────────────────────────────────┤
│  内核代码页       │  AP=10(RO) UXN=1 PXN=0             │
│                  │  用户不可执行也不可读写，内核可执行    │
├──────────────────┼──────────────────────────────────────┤
│  内核数据页       │  AP=01(KR/W) UXN=1 PXN=1           │
│                  │  用户完全不可访问，内核可读写不可执行  │
├──────────────────┼──────────────────────────────────────┤
│  用户代码页       │  AP=00(R/W) UXN=0 PXN=1             │
│                  │  用户可执行可读写，内核不可执行       │
├──────────────────┼──────────────────────────────────────┤
│  用户数据页       │  AP=00(R/W) UXN=1 PXN=1             │
│                  │  用户可读写不可执行，内核不可执行     │
├──────────────────┼──────────────────────────────────────┤
│  MMIO 寄存器页   │  AP=01(KR/W) UXN=1 PXN=1           │
│                  │  仅内核可读写，都不可执行             │
├──────────────────┼──────────────────────────────────────┤
│  只读数据段       │  AP=10(RO) UXN=1 PXN=1              │
│  (const 全局变量) │  全部只读，都不可执行                 │
└──────────────────┴──────────────────────────────────────┘
```

> **UXN/PXN 安全铁律：**
> - 内核页：UXN=1（用户不可执行）+ PXN=0（内核可执行）
> - 用户页：PXN=1（内核不可执行，防止 ret2usr）+ UXN=0（用户可执行）

### AP 违规触发异常

| 违规类型 | 异常类型 | ESR EC 值 | 说明 |
|----------|----------|----------|------|
| 用户写只读页 | Permission fault | 0b100100 | 同步异常 |
| 用户执行 UXN=1 页 | Permission fault | 0b100100 | 同步异常 |
| 内核执行 PXN=1 页 | Permission fault | 0b100100 | 同步异常 |
| 用户访问 AP=01 页 | Permission fault | 0b100100 | 同步异常 |

### PanN（Privileged Access Never）

| 特性 | 说明 |
|------|------|
| PSTATE.PAN | ARMv8.1+ 引入，禁止内核态默认访问用户页 |
| PAN=1 | 内核不能直接访问用户空间（必须用 STTR/LDTR 或先 set PAN=0） |
| PAN=0 | 内核可以访问用户空间（旧模式） |

> Linux 4.3+ 默认开启 PAN，防止 ret2usr 攻击。
> 内核需要访问用户数据时用 `copy_to_user()`/`copy_from_user()` 临时关 PAN。

## HFT 关联

在 HFT 裸金属系统中，通常所有代码运行在 EL1 内核态，不需要 EL0/EL1 权限分离。但理解 AP 仍然重要：只读数据段应设 AP=10（防止意外写入），代码段应设 UXN=0/PXN=0（可执行）+ AP=10（只读）。如果 HFT 系统有管理进程（如监控进程运行在 EL0），AP 控制可以实现隔离——管理进程只能访问自己的页面，不能读写交易数据。

在裸金属 HFT 中可以简化：所有页 AP=00（全部可读写），但代码段仍设 UXN=0/PXN=1 防止数据被执行。

## 自测题

1. **AP=01 的页面，EL0 和 EL1 分别能做什么？**

<details>
<summary>答案</summary>

AP=01：EL0 = **无访问**（None），EL1+ = **读写**（R/W）。这是典型的内核数据页权限——用户态完全不能访问，内核可以读写。
</details>

2. **为什么用户页要设 PXN=1？不设会有什么安全风险？**

<details>
<summary>答案</summary>

PXN=1 防止**内核执行用户态代码**。如果不设（PXN=0），攻击者可以在用户页中注入恶意代码（shellcode），然后通过系统调用或漏洞让内核跳转到该地址执行——这就是 **ret2usr 攻击**。设 PXN=1 后内核无法执行用户页的代码，阻断了这种攻击路径。
</details>

3. **一个只读数据段（如 const 全局变量）应该怎么设 AP？**

<details>
<summary>答案</summary>

AP=**10**（全部只读）。EL0 和 EL1 都是只读。配合 UXN=1（不可执行，数据段不是代码）和 PXN=1。这样任何尝试写入该页的操作都会触发 Permission fault，防止意外修改常量数据。
</details>

4. **PAN（Privileged Access Never）机制解决什么问题？**

<details>
<summary>答案</summary>

PAN 解决**内核直接访问用户空间数据**的安全风险。默认 PAN=1 时，内核态（EL1）不能直接读写用户页（AP=00 的页面），即使 AP 允许。必须通过 `copy_to_user()`/`copy_from_user()` 等专用接口访问，这些接口会临时关 PAN 并做安全检查。

这防止了内核漏洞（如 buffer overflow）被利用来直接读写用户空间恶意数据。如果 HFT 裸金属系统不用 EL0，PAN 无影响。
</details>
