# §14.2 四级页表

> **来源：** [Ch14 完整概述](section-0-本章完整概述.md) · [章导读](../README.md)

## 本节讲什么

48 位 VA = 4 级页表 × 9 位索引 + 12 位页内偏移。每级 512 表项 × 8 字节 = 4KB（恰好一页）。L1/L2 可用 Block descriptor 直接映射大块，省一层查找。理解页表层级是配置地址翻译的基础。

## 核心要点

### VA 分解（48 位 VA, 4KB 页）

```
 63        47  46  39  38  30  29  21  20  12  11       0
┌───┬───┬─────┬─────┬─────┬─────┬─────┬─────┬──────────┐
│   │   │ L0  │ L1  │ L2  │ L3  │     │     │  Page    │
│   │   │ idx │ idx │ idx │ idx │     │     │  Offset  │
└───┴───┴─────┴─────┴─────┴─────┴─────┴─────┴──────────┘
  └─┬─┘ └─────────┬──────────────────────┘ └─────┬────┘
    │             │                              │
  canonical      4 × 9 = 36 位索引            12 位偏移
  检查位         (512 表项 × 4 级)            (4KB 页内)
```

### 各级映射大小

| 级别 | 索引位 | 每表项映射 | 表大小 | 深度 |
|------|--------|-----------|--------|------|
| L0 | [47:39] | 512GB | 4KB (512×8B) | 1 |
| L1 | [38:30] | 1GB | 4KB (512×8B) | 2 |
| L2 | [29:21] | 2MB | 4KB (512×8B) | 3 |
| L3 | [20:12] | 4KB | 4KB (512×8B) | 4 |

> 每级 512 表项 × 8 字节 = 4KB，恰好一页。
> 可用 **Block descriptor** 在 L1(1GB) 或 L2(2MB) 层直接映射大块，省一层查找。

### Block vs Table descriptor

| 类型 | bit[1:0] | 可用层级 | 映射大小 | 说明 |
|------|----------|----------|----------|------|
| Table | 0b11 | L0/L1/L2 | 指向下一级页表 | 4 级完整查找 |
| Block | 0b01 | L1/L2 | 1GB(L1) / 2MB(L2) | 直接映射，省 1-2 级查找 |
| Page | 0b11 | L3 | 4KB | L3 专用（也叫 Table，但映射页） |

### 页表查找流程（4KB 页, 完整 4 级）

```
VA = 0x0000_0000_0040_0000 (4MB 处)

1. 从 TTBR0_EL1 取 L0 表基址
2. L0 index = VA[47:39] = 0 → L0[0] → 得到 L1 表地址
3. L1 index = VA[38:30] = 0x01 → L1[1] → 得到 L2 表地址
4. L2 index = VA[29:21] = 0x00 → L2[0] → 得到 L3 表地址
5. L3 index = VA[20:12] = 0x00 → L3[0] → 得到 PA (4KB 页)
6. PA = L3[0].PA + VA[11:0] = 页基址 + 页内偏移

最坏情况：4 次内存访问 (4 × ~100ns = ~400ns)
L2 Block：2 次内存访问 (L0 → L1 → L2 Block, ~200ns)
```

### 大页优势对比

| 方案 | TLB 条目数 | 页表 walk | 适用场景 |
|------|-----------|-----------|----------|
| 4KB 小页 (L3) | 512 个 | 4 级查找 | 精细控制 |
| 2MB 大页 (L2 Block) | 1 个 | 3 级查找 | 代码段/数据段 |
| 1GB 巨页 (L1 Block) | 1 个 | 2 级查找 | 大块连续内存 |

```
2MB 内存区域：
4KB 页方案：需要 512 个 TLB 条目（可能 TLB 溢出）
2MB 大页方案：只需 1 个 TLB 条目（永不溢出）
```

### 页表内存开销

| 映射大小 | 4KB 页方案 | 2MB 大页方案 |
|----------|-----------|-------------|
| 4MB | 4KB(L0)+4KB(L1)+4KB(L2)+4KB×512(L3) = ~2MB | 4KB(L0)+4KB(L1)+4KB(L2) = 12KB |
| 1GB | ~2MB 页表 | 4KB(L0)+4KB(L1) = 8KB |

> 大页不仅省 TLB，还省页表内存。2MB 大页映射 1GB 只需 8KB 页表，4KB 小页需要 ~2MB。

## HFT 关联

HFT 系统应尽量使用大页（2MB Block descriptor）减少 TLB 压力。一个 2MB 大页只占 1 个 TLB 条目，而同样大小的 4KB 小页需要 512 个 TLB 条目。在 HFT 交易引擎中，将订单簿数据用 2MB 大页映射可以显著减少 TLB miss。另外，页表 walk 的 4 级查找在最坏情况下需要 4 次内存访问（~400ns），大页将 walk 减少到 2-3 级。

HFT 中推荐：代码段用 2MB 大页、订单簿/行情数据用 2MB 大页、MMIO 用 4KB 页（精确控制属性）。

## 自测题

1. **48 位 VA 的 4 级页表，每级用多少位做索引？页内偏移多少位？**

<details>
<summary>答案</summary>

每级用 **9 位**做索引（9×4=36 位），页内偏移 **12 位**（4KB）。总计 36+12=48 位。每级 2^9 = 512 个表项。
</details>

2. **L1 的 Block descriptor 映射多大？L2 的 Block descriptor 映射多大？**

<details>
<summary>答案</summary>

- L1 Block：**1GB**（VA[38:30] 共 30 位，2^30 = 1GB）
- L2 Block：**2MB**（VA[29:21] 共 21 位，2^21 = 2MB）

L3 不能用 Block，只能用 Page（4KB）。
</details>

3. **为什么每级页表恰好是 4KB？**

<details>
<summary>答案</summary>

每级 512 表项 × 8 字节/表项 = 4096 字节 = **4KB**。这恰好是一个页的大小，方便内存分配和管理——分配一页就是一张页表。这是 ARMv8 架构的精心设计。
</details>

4. **映射 2MB 内存，用 4KB 页和用 2MB 大页分别需要多少 TLB 条目？**

<details>
<summary>答案</summary>

- 4KB 页：2MB / 4KB = 512 个 TLB 条目（可能超出 TLB 容量导致 miss）
- 2MB 大页：1 个 TLB 条目（永不 miss）

差距 512 倍。HFT 中对热数据使用大页可以消除 TLB miss 延迟（~100ns/次）。
</details>
