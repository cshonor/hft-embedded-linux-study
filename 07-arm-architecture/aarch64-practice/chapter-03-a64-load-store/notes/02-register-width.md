# 3.2 寄存器宽度与访存宽度

> 来源：§3.2 · 精读 · [章总览](section-0-本章完整概述.md)

## 本节讲什么

LDR/STR 家族的宽度变体（B/H/W/X）、符号扩展 vs 零扩展的区别、LDUR 负偏移支持。附中括号 `[]` 内部合法写法汇总。

## 核心要点

### 命名规则

| 后缀 | 含义 | 说明 |
|------|------|------|
| B | Byte 8bit | 读/写 1 字节 |
| H | Halfword 16bit | 读/写 2 字节 |
| W | Word 32bit | 读/写 4 字节（`ldr w0`） |
| X | 64bit | 读/写 8 字节（`ldr x0`） |
| S | Sign-extend 符号扩展 | 不带 S = 零扩展 |
| UR | Unscaled offset 非缩放偏移 | 支持有符号负立即数 |

- 没有 "LDRU" 这条指令——是 **LDUR**（UR = unscaled offset）
- 没有 "LDRS" 独立指令——S 是后缀：**LDRSB / LDRSH / LDRSW**

### 内存基本铁律：每个地址存 1 字节

**硬件铁律：内存每一个地址，存 1 个字节（8bit），永远不变。**

那为什么会有 LDRH（2 字节）、LDR W（4 字节）、LDR X（8 字节）？

→ 一条 load 指令，可以一次从**连续多个内存地址**批量读出多个字节，拼成一个大数放进寄存器。

```
地址 0x1000：字节 #0
地址 0x1001：字节 #1
地址 0x1002：字节 #2
地址 0x1003：字节 #3
```

| 指令 | 起始地址 | 读取哪些地址 | 共几字节 | 结果宽度 |
|------|---------|-------------|---------|---------|
| `ldrb w0, [x2, #0x1000]` | 0x1000 | 仅 0x1000 | 1 字节 | 8bit |
| `ldrh w0, [x2, #0x1000]` | 0x1000 | 0x1000, 0x1001 | 2 字节 | 16bit 半字 |
| `ldr w0, [x2, #0x1000]` | 0x1000 | 0x1000~0x1003 | 4 字节 | 32bit 字 |
| `ldr x0, [x2, #0x1000]` | 0x1000 | 0x1000~0x1007 | 8 字节 | 64bit 双字 |

**关键澄清：**
- ✔ 每个内存地址 = 1 字节，永远不变
- ✔ LDRH / LDRW / LDRX **不是**"一个地址存多字节"
- ✔ 而是：给一个起始地址，指令自动向后读连续 N 个地址，把一堆字节拼成一个大数放到寄存器

### 大小端：多字节拼接的顺序问题

读连续多字节时，CPU 要决定：起始地址的字节，是数字的**低位**还是**高位**？

- **小端（Little-Endian）**：起始地址 = 最低字节。树莓派 5（AArch64）默认小端。
- **大端（Big-Endian）**：起始地址 = 最高字节。

```
内存：
0x1000: 0x11
0x1001: 0x22

ldrh w0, [x0, #0x1000]
小端 → w0 = 0x2211   （起始地址 0x1000 的字节 0x11 是最低位）
大端 → w0 = 0x1122   （起始地址 0x1000 的字节 0x11 是最高位）
```

### 对齐要求（AArch64）

| 指令 | 读取宽度 | 起始地址对齐要求 |
|------|---------|----------------|
| LDRB | 1 字节 | 无要求（任意地址） |
| LDRH | 2 字节 | **偶数**（2 字节对齐） |
| LDR W | 4 字节 | **4 字节对齐** |
| LDR X | 8 字节 | **8 字节对齐** |
| STP/LDP (X) | 16 字节 | **16 字节对齐**（ABI 强制） |

- 不对齐会触发**对齐异常**（Synchronous Exception，ESR 记录）
- 可以通过 `SCTLR_ELx.A` 位开启非对齐访问，但性能受损（可能拆成多次总线事务）
- STP/LDP 的 16 字节对齐是 AAPCS64 ABI 硬性要求，SP 必须永远保持 16 字节对齐

### S 后缀与内存无关

**S（符号扩展）是在数据读到寄存器之后才做的操作**，跟内存本身无关：

```
内存只存原始字节 → LDR 读出 N 字节 → S 后缀决定如何扩展到目标宽度
                                    ├─ 不带 S：零扩展（高位补 0）
                                    └─ 带 S：  符号扩展（高位补符号位）
```

- 内存本身只存原始字节，不关心你用 LDRB 还是 LDRSB 读
- S 后缀只影响读出后的扩展行为和目标寄存器（W vs X）

### 中括号 `[]` 内部可以放什么

`[]` 整体含义：括号内部表达式计算出一个内存有效地址，去这个地址读写内存。只允许以下 5 种写法：

| # | 写法 | 语法示例 | 有效地址 | 说明 |
|---|------|----------|----------|------|
| 1 | 单个基址寄存器 | `[x1]` | X1 | 最基本形式 |
| 2 | 基址 + 正立即数偏移 | `[x1, #16]` | X1 + 16 | 只支持正数 |
| 3 | 基址 + 立即数 + `!` 预索引 | `[x1, #16]!` | X1 + 16 | 访问后写回 X1 |
| 4 | 基址 + 偏移寄存器 | `[x1, x2]` | X1 + X2 | 寄存器偏移 |
| 5 | 基址 + 偏移寄存器 + 移位 | `[x1, x2, lsl #3]` | X1 + (X2<<3) | lsl 只能 0/1/2/3 |

**`!` vs 后索引的区别：**
- `!` 写在中括号**里面**末尾 → 预索引（前变基），属于中括号语法
- `#16` 写在中括号**外面** → 后索引（后变基），不属于中括号内部

```asm
ldr x0, [x1, #16]!   ; 预索引：地址=X1+16，访问后 X1=X1+16
ldr x0, [x1], #16    ; 后索引：地址=X1（[]内只算X1），读完 X1+=16
```

- ❌ 中括号不能直接放 C 变量符号：`ldr x0, [my_var]` 语法错误
- 要先 `adrp x1, my_var` 再 `ldr x0, [x1]`

### LDR 家族完整指令表（读内存 → 寄存器）

| 指令 | 示例 | 读取宽度 | 扩展行为 | 目标寄存器 | 注意点 |
|------|------|---------|---------|-----------|--------|
| LDR | `ldr x0, [x1]` | 64bit | 直接 64 位加载 | X 寄存器 | |
| LDR | `ldr w0, [x1]` | 32bit | 零扩展，高 32 位清零 | W 寄存器 | |
| LDRB | `ldrb w0, [x1]` | 8bit | 零扩展到 32 位 | **只能 Wn** | 不能写 Xn |
| LDRH | `ldrh w0, [x1]` | 16bit | 零扩展到 32 位 | **只能 Wn** | 不能写 Xn |
| LDRSB | `ldrsb x0, [x1]` | 8bit | **符号扩展**到 64bit | X 寄存器 | 有符号 int8_t |
| LDRSB | `ldrsb w0, [x1]` | 8bit | **符号扩展**到 32bit | W 寄存器 | 有符号 int8_t |
| LDRSH | `ldrsh x0, [x1]` | 16bit | **符号扩展**到 64bit | X 寄存器 | 有符号 int16_t |
| LDRSH | `ldrsh w0, [x1]` | 16bit | **符号扩展**到 32bit | W 寄存器 | 有符号 int16_t |
| LDRSW | `ldrsw x0, [x1]` | 32bit | **符号扩展**到 64bit | X 寄存器 | 有符号 int32_t |
| LDUR | `ldur x0, [x1, #-8]` | 64bit | 同 LDR | X 寄存器 | 支持负立即数偏移 |
