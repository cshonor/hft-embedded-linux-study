# 3.7 典型实操模式

> 来源：§3.7 · 精读 · [章总览](section-0-本章完整概述.md)

## 本节讲什么

全部基于前面讲的寻址模式：**后变基**、**预索引 `!`**、**寄存器移位偏移 `lsl #n`**，是内核高频汇编范式。本节通过三个典型代码片段，把前面学的寻址模式串起来，看到真实代码中怎么用。

---

## ① memcpy 骨架（大块内存拷贝，后变基寻址）

```asm
; x0=dst 目标地址, x1=src 源地址, x2=count 总字节数
memcpy:
    cbz x2, done         ; count=0 直接退出
loop:
    ldr x3, [x1], #8     ; ✅ 后变基：读 [x1]，读完 x1 += 8（源指针前进8字节）
    str x3, [x0], #8     ; ✅ 后变基：写入 [x0]，写完 x0 += 8（目标指针前进8字节）
    subs x2, x2, #8      ; count -= 8，设置状态标志位
    b.gt loop            ; 大于0继续循环
done:
    ret
```

**C 等价：**
```c
while (count > 0) {
    *dst++ = *src++;
    count -= 8;
}
```

### 关键点

- `[x1], #8`：`#8` 写在中括号**外面**，后索引寻址（post-index）
- 访问完内存后，寄存器自增 8（一个 X 寄存器 = 8 字节）
- `subs` 而非 `sub`：需要设置标志位供 `b.gt` 判断

### 执行流程举例

```
初始 x1 = 0x1000

ldr x3, [x1], #8：
  1. 读取地址 0x1000 处的 8 字节 → x3
  2. x1 = 0x1000 + 8 = 0x1008（指针前进）

str x3, [x0], #8：
  1. 将 x3 写入 [x0] 处
  2. x0 += 8（目标指针前进）

subs x2, x2, #8：
  count -= 8，同时设置 NZCV 标志位
  若 count > 0 → Z=0, 继续循环
  若 count = 0 → Z=1, 退出循环
```

> ⚠️ 这个简化版本只支持 8 字节对齐，工业级 memcpy 还会处理尾部不足 8 字节、非对齐情况。

## ② 函数栈帧（Stack Frame，STP/LDP 预索引 + 后索引）

```asm
func:
    stp x29, x30, [sp, #-16]!   ; ✅ 预索引!：sp = sp - 16，把 x29(FP帧指针)、x30(LR返回地址) 压栈
    mov x29, sp                  ; 建立栈帧，FP 指向当前栈顶
    ; -------- 函数体，局部变量就在 x29 帧指针的负偏移位置，用 LDUR 访问 --------
    ldp x29, x30, [sp], #16      ; ✅ 后索引：恢复 x29/x30；sp += 16 释放栈空间
    ret                          ; 用 x30 返回调用方
```

### 栈帧布局图

```
高地址
┌──────────────────┐
│ 调用方栈帧        │
├──────────────────┤ ← stp 前 sp 指向这里
│ x30 (LR 返回地址) │  sp+8
│ x29 (FP 帧指针)   │  sp+0
├──────────────────┤ ← stp 后 sp 指向这里（sp = sp - 16）
│ 局部变量          │  [x29, #-4] 等
│ ...               │
└──────────────────┘
低地址
```

### 关键点

| 要素 | 说明 |
|------|------|
| **AArch64 ABI 强制** | 栈 sp 必须永远 **16 字节对齐** |
| **成对保存** | x29 + x30 刚好 16 字节，满足对齐要求 |
| **x29** | 帧指针 FP（Frame Pointer），指向当前栈帧顶部 |
| **x30** | 链接寄存器 LR（Link Register），保存函数返回地址 |
| **开头 `stp ...!`** | 前变基（预索引）：先 `sp -= 16`，再存储 |
| **结尾 `ldp ...,#16`** | 后变基（后索引）：先加载，再 `sp += 16` |
| **局部变量访问** | `ldur w0, [x29, #-4]`，负偏移读取栈帧上的局部变量 |

### 开头 vs 结尾对比

```
函数开头（压栈）：                    函数结尾（弹栈）：
stp x29,x30,[sp,#-16]!              ldp x29,x30,[sp],#16
    ↓                                    ↓
1. sp = sp - 16（先改寄存器）        1. 从 [sp] 加载 x29, x30（先访存）
2. 存 x29 → [sp], x30 → [sp+8]     2. sp = sp + 16（后改寄存器）
    ↓                                    ↓
预索引：! 在 [] 内部                  后索引：偏移在 [] 外部
```

## ③ 数组索引模式（寄存器移位偏移寻址）

```asm
; x0 = 数组基地址 base；x1 = index 下标
; 取 arr[index]，每个元素 8 字节（long long）
ldr x2, [x0, x1, lsl #3]
; 有效地址 = x0 + (x1 << 3) = base + index * 8
```

- `lsl #3` 等价乘以 8，对应 64 位 X 寄存器，每个数组元素占 8 字节
- 这就是**寄存器偏移 + 移位缩放**，移位只能 0–3

### 拓展练习

| C 类型 | 元素大小 | 指令 | 移位 |
|--------|---------|------|------|
| `long long arr[]` | 8 字节 | `ldr x2, [x0, x1, lsl #3]` | `lsl #3`（×8） |
| `uint32_t arr[]` | 4 字节 | `ldr w2, [x0, x1, lsl #2]` | `lsl #2`（×4） |
| `uint16_t arr[]` | 2 字节 | `ldrh w2, [x0, x1, lsl #1]` | `lsl #1`（×2） |
| `uint8_t arr[]` | 1 字节 | `ldrb w2, [x0, x1]` | 无移位（×1） |

---

## 三种模式对应寻址对照表

| 代码片段 | 寻址模式 | 核心特征 |
|----------|---------|---------|
| `ldr x3, [x1], #8` | 后变基（后索引） | 偏移在 `[]` 外面；**访存之后**更新基址 |
| `stp x29, x30, [sp, #-16]!` | 预索引（前变基） | `!` 写在 `[]` 内部；**先修改**寄存器，再访存 |
| `ldr x2, [x0, x1, lsl #3]` | 寄存器移位偏移 | `[]` 内，基址 + 偏移寄存器 + 移位；基址**不会被修改** |

### 三种模式一眼区分

```
后变基：  [Xn], #imm      →  偏移在外面，先访存后改基址    →  指针自增场景
前变基：  [Xn, #imm]!     →  感叹号在里面，先改基址后访存  →  压栈/开辟空间
寄存器偏移：[Xn, Xm, lsl #n] → 无感叹号，基址不变          →  数组下标访问
```

## HFT 关联

这些模式在 HFT 代码中无处不在：

- **memcpy 骨架**：市场数据拷贝 → 用后变基减少指令数，每次 8 字节搬运
- **函数栈帧**：热路径函数的调用开销 → 叶子函数省栈帧可省 2 条指令
- **数组索引**：订单簿数组访问 → `lsl #3` 一条指令完成索引计算，无需额外乘法
- **GDB 调试**：`info registers`、`x/8gx $sp` 验证内存布局

## Quiz 巩固

**Q1:** memcpy 循环中 `ldr x3, [x1], #8`，中括号内部计算的地址是 x1 旧值还是 x1+8？

<details><summary>答案</summary>

**旧的 x1**；读完内存之后 x1 才 +8。后变基的核心就是"先用旧地址访存，再更新寄存器"。

</details>

**Q2:** `stp x29, x30, [sp, #-16]!` 执行后 sp 如何变化？

<details><summary>答案</summary>

**sp = sp - 16**。预索引（`!`）先修改寄存器再访存，所以 sp 先减 16，然后把 x29/x30 存入新 sp 位置。

</details>

**Q3:** `long long arr[]`；base 在 x0，下标 x1，请写出加载 `arr[index]` 的指令？

<details><summary>答案</summary>

```asm
ldr x2, [x0, x1, lsl #3]
```

`lsl #3` = 左移 3 位 = 乘以 8，因为 `long long` 占 8 字节。

</details>

**Q4:** 以下 memcpy 代码有什么问题？
```asm
loop:
    ldr x3, [x1], #8
    str x3, [x0], #8
    subs x2, x2, #8
    b.gt loop
```

<details><summary>答案</summary>

如果 count 不是 8 的倍数，会**多读/多写越界字节**。需要先处理对齐余数，或者用字节拷贝处理尾部。真实内核 memcpy 会做剩余字节处理。

</details>

**Q5:** 函数栈帧开头为什么用 `stp` 而不是两次 `str`？

<details><summary>答案</summary>

两个原因：(1) AArch64 ABI 强制 sp 必须 16 字节对齐，`stp` 一次存 16 字节天然满足对齐；(2) `stp` 一条指令完成两次存储，比两条 `str` 更高效。

</details>

## 补充易错

1. **memcpy 尾部问题**：简化版每次拷贝 8 字节，如果 count 不是 8 整数倍，尾部字节会漏拷贝；真实内核 memcpy 会做剩余字节处理（先按 8 字节批量拷贝，再按 1 字节处理尾部）
2. **LDP/STP 不支持寄存器移位寻址**：数组索引不能用 LDP，只能 LDR
3. **栈向下增长**：sp 往数值变小方向开辟空间，所以压栈写 `#-16`（减不是加）
4. **`subs` vs `sub`**：循环计数必须用 `subs`（设置标志位），否则 `b.gt` 无法判断
5. **`mov x29, sp` 的时机**：必须在 `stp` 之后，此时 sp 已经指向新栈帧底部
