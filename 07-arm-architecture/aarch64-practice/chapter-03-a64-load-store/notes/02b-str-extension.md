## 零扩展 vs 符号扩展：一个例子看清

读同一字节 `0x80`，两种扩展的结果完全不同：

| 指令 | 扩展方式 | 64 位寄存器结果 | 含义 |
|------|---------|----------------|------|
| `ldrb w0, [x1]` | 零扩展 | `0x0000000000000080` | 高位补 0 → 正数 128 |
| `ldrsb x0, [x1]` | 符号扩展 | `0xffffffffffffff80` | 高位补 1 → 负数 -128 |

**核心规则：**

- **零扩展**（LDRB / LDRH / LDR W）：只把内存数据拿出来，高位全补 0
- **符号扩展**（LDRSB / LDRSH / LDRSW）：把读到数据的最高位当符号位，高位全填充符号位
- ⚠️ **零扩展只能写 Wn，符号扩展才能写 Xn**——不能对 8/16bit 数据做零扩展直接写入 X 寄存器

---

## C 类型对照表

| 指令 | 对应 C 类型 | 读几字节 | 扩展行为 |
|------|-----------|---------|---------|
| `LDRSB` | `int8_t` | 1 | 符号扩展到 64bit |
| `LDRSH` | `int16_t` | 2 | 符号扩展到 64bit |
| `LDRSW` | `int32_t` | 4 | 符号扩展到 64bit |
| `LDRB` | `uint8_t` | 1 | 零扩展到 32bit |
| `LDRH` | `uint16_t` | 2 | 零扩展到 32bit |
| `LDR W` | `uint32_t` | 4 | 零扩展到 32bit |
| `LDR X` | `int64_t` / `uint64_t` | 8 | 无需扩展 |

一句话总结：**宽度后缀决定从内存拿几个字节；S 后缀决定做符号扩展还是零扩展，同时决定目标用 W 还是 X 寄存器。**

---

## STR 家族（寄存器 → 内存）

STR 没有符号扩展概念，存储只截取对应宽度：

| 指令 | 示例 | 存储宽度 | 说明 |
|------|------|---------|------|
| STR | `str x0, [x1]` | 64bit | 存完整 X 寄存器 |
| STR | `str w0, [x1]` | 32bit | 存低 32 位 |
| STRB | `strb w0, [x1]` | 8bit | 取最低字节写入内存 |
| STRH | `strh w0, [x1]` | 16bit | 取低 16 位写入内存 |
| STUR | `stur x0, [sp, #-8]` | 64bit | 支持负立即偏移，栈帧局部变量用 |

---

## 成对指令 LDP / STP（Load Pair / Store Pair）

一次读写两个 64 位寄存器，16 字节，栈操作专用，必须 16 字节对齐：

```asm
stp x0, x1, [sp, #-16]!   ; 预索引压栈：sp-=16，存 x0+x1
ldp x0, x1, [sp], #16     ; 后索引出栈：读 x0+x1，sp+=16
```

## 关键易错点汇总

| # | 易错点 | 正确做法 |
|---|--------|---------|
| 1 | `ldrb`/`ldrh` 只能写 W 寄存器，不能写 X | 硬件零扩展到 32 位，写 W 自动清零 X 高 32 位 |
| 2 | 有符号 32 位 int 读到 64 位 X 寄存器 | 必须用 `ldrsw`；普通 `ldr w0` 只是零扩展 |
| 3 | `ldr x0, [sp, #-8]` 语法报错 | 负立即偏移用 `ldur`/`stur` |
| 4 | `!` 在 `[]` 内 = 预索引；立即数在 `[]` 外 = 后索引 | 看清偏移在括号内还是外 |
| 5 | 中括号内全部算内存地址 | LDR：从右边 `[]` 地址读数据到左边寄存器 |

---

## HFT 关联

| 场景 | 推荐指令 | 原因 |
|------|---------|------|
| 读市场数据 1 字节价格类型 | `LDRB` | 比 `LDR`+移位更快，一步完成 |
| 读有符号 int8_t / int16_t | `LDRSB` / `LDRSH` | 符号扩展一步完成，避免额外 `SXTB`/`SXTH` |
| 读有符号 int32_t 到 64 位 | `LDRSW` | 零扩展 `ldr w0` 会丢失负号 |
| 栈帧局部变量访问 | `LDUR` / `STUR` | 支持负偏移，如 `[sp, #-8]` |
| 函数序言/结语 | `STP` / `LDP` | 一条指令存/取两个寄存器，减少指令数 |
| 热路径数据结构遍历 | `LDR` + 寄存器偏移 `lsl #3` | 一步完成数组索引计算 |

误用 `LDRB` 读取有符号负数会导致高位为 0 而非 1 → 数值错误（如读 -1 得到 255）。

## 自测题

1. `LDRSB w0, [x1]` 和 `LDRB w0, [x1]` 读同一个字节 0xFF，结果分别是什么？
<details><summary>答案</summary>
LDRSB（符号扩展）：w0 = 0xFFFFFFFF（-1）。LDRB（零扩展）：w0 = 0x000000FF（255）。
</details>

2. `LDRH x0, [x1]` 执行后，x0 的高 48 位是什么？
<details><summary>答案</summary>
全 0。LDRH 读取 2 字节并零扩展到 64 位，高位自动清零。
</details>

3. 为什么 `LDRSB` 的 S 不要和 `ADDS` 的 S 混淆？
<details><summary>答案</summary>
LDRSB 的 S = Sign-extend（符号扩展），控制读入数据如何扩展到目标宽度。ADDS 的 S = Set flags（设置条件标志 NZCV）。两者完全不同。
</details>

4. `ldrsb x2, [x3]` 读几字节？做什么扩展？写入哪个寄存器？
<details><summary>答案</summary>
读 **1 字节**（8bit），**符号扩展到 64 位**，写入 **x2**（X 寄存器）。LDRSB = LDR + Sign-extend + Byte。目标寄存器是 x2（64 位），所以符号扩展到 64 位。
</details>

5. 栈上 sp 向下 8 字节读取 64 位数据，用哪条指令？
<details><summary>答案</summary>
`ldur x0, [sp, #-8]`。普通 `ldr` 不支持负立即偏移，必须用 LDUR。`[sp, #-8]` 表示地址 = SP - 8，读取 8 字节（64 位）到 x0。
</details>

6. `ldr w0, [x1]` 执行完，x0 的高 32 位是什么？
<details><summary>答案</summary>
**全 0**。写 Wn 时硬件自动清零 Xn 的高 32 位（AArch64 寄存器规则）。即使 x0 原来高 32 位有值，执行 `ldr w0` 后也被清零。
</details>

7. 有符号 32 位 int 变量存在内存中，要读到 64 位寄存器做运算，用 `ldr w0` 还是 `ldrsw x0`？为什么？
<details><summary>答案</summary>
必须用 **`ldrsw x0`**。`ldr w0` 做零扩展——如果 int 是负数（最高位为 1），零扩展后变成大正数，丢失符号。`ldrsw` 做符号扩展——负数扩展后仍然是负数（高位补 1），数值正确。
</details>

8. `ldr x0, [x1, #16]!` 和 `ldr x0, [x1], #16` 有什么区别？
<details><summary>答案</summary>
- `[x1, #16]!`：**预索引**（前变基），`#16` 在中括号内，有效地址 = X1+16，访问后 X1 写回 X1+16
- `[x1], #16`：**后索引**（后变基），`#16` 在中括号外，有效地址 = X1（不变），访问后 X1 写回 X1+16
- 区别：预索引先算地址再访问，后索引先访问再更新基址
</details>

9. 内存中 1 字节值为 `0x80`，分别用 `ldrb w0` 和 `ldrsb x0` 读取，结果各是多少？
<details><summary>答案</summary>
- `ldrb w0`：零扩展，w0 = `0x00000080`（正数 128）
- `ldrsb x0`：符号扩展，x0 = `0xffffffffffffff80`（负数 -128）

0x80 最高位是 1，符号扩展时高位全补 1，结果是一个 64 位负数。
</details>

10. 能不能写 `ldrb x0, [x1]`（零扩展到 X 寄存器）？
<details><summary>答案</summary>
**不能**。LDRB/LDRH 零扩展只能写 **W 寄存器**（w0-w30），不能直接写 X 寄存器。如果需要零扩展结果在 X 寄存器中，写 Wn 即可——写 Wn 时硬件自动清零 Xn 高 32 位，效果等同于零扩展到 64 位。

只有**符号扩展**指令（LDRSB/LDRSH/LDRSW）才允许直接写 Xn 寄存器。
</details>

11. C 语言 `int32_t` 变量存在内存中，要读到 64 位寄存器参与运算，为什么不能用 `ldr w0`？
<details><summary>答案</summary>
`ldr w0` 做的是**零扩展**——如果 int32_t 是负数（最高 bit = 1），零扩展后高位补 0，变成一个大正数，丢失了符号。

必须用 `ldrsw x0` 做符号扩展——负数的最高位 1 会扩展填充到 64 位，数值保持为负数。

对照 C 类型表：`int32_t` → LDRSW，`uint32_t` → LDR W。
</details>

12. 内存 0x2000 存 `0x44`，0x2001 存 `0x33`，0x2002 存 `0x22`，0x2003 存 `0x11`。执行 `ldr w0, [x1]`（x1=0x2000，小端模式），w0 的值是多少？
<details><summary>答案</summary>
小端模式下，起始地址存最低字节：

```
0x2000 → 0x44（最低字节）
0x2001 → 0x33
0x2002 → 0x22
0x2003 → 0x11（最高字节）
```

w0 = **0x11223344**

小端 = "低地址存低字节"，读出来从高到低排列就是 0x11223344。
</details>

13. `ldrh w0, [x1]` 时 x1 = 0x1001（奇数地址），会发生什么？
<details><summary>答案</summary>
LDRH 要求 **2 字节对齐**（起始地址为偶数）。0x1001 是奇数，不对齐。

- 如果 `SCTLR_ELx.A = 1`（默认）：触发**对齐异常**（Synchronous Exception），程序崩溃
- 如果 `SCTLR_ELx.A = 0`（开启非对齐访问）：硬件会正确读取，但可能拆成多次总线事务，**性能下降**

实际编程中应始终保持对齐访问，避免性能损失和异常。
</details>

14. S 后缀（如 LDRSB 中的 S）影响内存中存储的字节数吗？
<details><summary>答案</summary>
**不影响**。S 后缀只决定读到寄存器后的**扩展方式**（符号扩展 vs 零扩展），跟内存无关。

- LDRB 和 LDRSB 都从内存读 **1 字节**
- LDRH 和 LDRSH 都从内存读 **2 字节**
- 内存本身只存原始字节，不关心你用什么指令读

S 后缀影响的是：① 读出后的扩展行为（补 0 还是补符号位）② 目标寄存器（零扩展只能 Wn，符号扩展可以 Xn）
</details>
