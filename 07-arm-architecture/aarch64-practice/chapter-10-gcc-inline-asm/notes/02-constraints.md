# 10.2 约束字符

> 来源：§10.2 · 精读 · [章总览](section-0-本章完整概述.md)

## 本节讲什么

GCC 内联汇编的操作数约束字符（Constraint Characters）：寄存器约束、立即数约束、内存约束，以及修饰符 `=`/`+`/`&`。

## 约束分类总览

| 类别 | 约束 | 含义 | AArch64 示例 |
|------|------|------|------------|
| 寄存器 | `r` | 通用寄存器 | X0-X30 / W0-W30 |
| 立即数 | `i` | 任意立即数 | `"i"(42)` |
| 立即数 | `I` | 12 位无符号 (0-4095) | `"I"(0x1000)` |
| 立即数 | `J` | 0（特殊零寄存器优化） | `"J"(0)` |
| 内存 | `m` | 内存地址 | `"m"(*ptr)` |
| 内存 | `Q` | 内存地址（偏移为 0） | 单寄存器加载 |
| 浮点 | `w` | 向量/浮点寄存器 | V0-V31 / D0-D31 |
| 特殊 | `n` | 负立即数 | 极少用 |

## 寄存器约束

| 约束 | 分配范围 | 用法 |
|------|---------|------|
| `r` | X0-X30（64 位）或 W0-W30（32 位） | `"r"(x)` |
| `w` | V0-V31（SIMD/浮点） | `"w"(f)` |
| 具体寄存器 | `"x0"` 指定 X0 | 极少用（破坏编译器寄存器分配） |

```c
/* 编译器自动选择寄存器 */
asm("mov %0, %1" : "=r"(out) : "r"(in));

/* 编译器可能生成：
   mov x5, x6     ; %0=x5, %1=x6
   具体寄存器由编译器决定 */
```

## 立即数约束

| 约束 | 含义 | 范围 |
|------|------|------|
| `i` | 通用立即数 | 任意整数常量 |
| `I` | AArch64 ADD/SUB 立即数 | 0-4095（12 位无符号） |
| `J` | 特殊零值 | 0（可用 ZR 寄存器） |
| `K` | AArch64 位操作 | 特定位掩码 |
| `L` | AArch64 逻辑立即数 | 特定模式 |

```c
/* I 约束：0-4095 */
asm("add %0, %1, %2" : "=r"(y) : "r"(x), "I"(0x100));  /* ✓ */
/* asm("add %0, %1, %2" : "=r"(y) : "r"(x), "I"(0x5000)); */  /* ✗ 超范围 */

/* i 约束：任意值 */
asm("movz %0, %1" : "=r"(y) : "i"(0x1234));  /* ✓ */
```

## 内存约束

| 约束 | 含义 |
|------|------|
| `m` | 内存操作数（编译器计算地址） |
| `Q` | 内存地址（基址+0 偏移，单寄存器加载） |
| `o` | 偏移内存操作数 |

```c
int x = 42;
int result;

/* m 约束：编译器生成 ldr/str */
asm("ldr %0, %1" : "=r"(result) : "m"(x));

/* 等价于 C：result = x; */
```

## 修饰符

| 修饰符 | 含义 | 用法 |
|--------|------|------|
| `=` | 只写（write-only） | `"=r"(out)` |
| `+` | 读写（read-write） | `"+r"(var)` |
| `&` | early clobber | `"=&r"(out)` |
| `%` | 可交换操作数（极少用） | |

### = vs +

```c
/* = 只写：汇编不读旧值 */
asm("mov %0, #42" : "=r"(x));  /* x = 42 */

/* + 读写：汇编先读再写 */
asm("add %0, %0, #1" : "+r"(x));  /* x = x + 1 */
```

### &（early clobber）

```c
/* ✗ 危险：编译器可能让 %0 和 %1 共用寄存器 */
asm(
    "mov %0, %1\n\t"    /* 写 %0 */
    "add %0, %0, %2\n"  /* 读 %1（可能已被覆盖！） */
    : "=r"(out)
    : "r"(a), "r"(b)
);

/* ✓ 正确：& 声明 %0 在输入使用前就被写入 */
asm(
    "mov %0, %1\n\t"
    "add %0, %0, %2\n"
    : "=&r"(out)           /* & = early clobber */
    : "r"(a), "r"(b)
);
```

**early clobber 的含义**：输出寄存器在所有输入寄存器使用完毕前就被写入。GCC 默认假设输出在所有输入读完后才写，可能复用寄存器。`&` 强制编译器给输出分配不同寄存器。

## AArch64 常用约束组合

| 约束 | 用途 | 示例 |
|------|------|------|
| `"=r"(x)` | 输出到通用寄存器 | 读系统寄存器结果 |
| `"+r"(x)` | 读写通用寄存器 | 自增/自减 |
| `"=&r"(x)` | early clobber 输出 | 原子操作（ldxr/stxr） |
| `"r"(x)` | 输入通用寄存器 | 传参 |
| `"I"(n)` | 12 位立即数 | ADD/SUB 偏移 |
| `"m"(x)` | 内存地址 | LDR/STR |
| `"memory"` | 内存 clobber | 编译器屏障 |

## HFT 关联

- **`r` 让编译器自由分配寄存器** → 最灵活，编译器做寄存器分配优化
- **`=&r` 防止输入输出共用寄存器** → 原子操作（ldxr/stxr）必须用
- **`I` 约束限制立即数范围** → 编译期检查，超出范围报错
- **`"memory"` clobber** → 编译器屏障，阻止内存访问重排

## 自测题

1. `"=r"` 和 `"+r"` 的区别？
<details><summary>答案</summary>
`"=r"` 是 write-only（只写），汇编不读旧值直接写入。`"+r"` 是 read-write（读写），汇编先读旧值再修改写回。需要先读再改（如自增 `add %0, %0, #1`）用 `"+r"`。
</details>

2. 什么时候需要 `&`（early clobber）？
<details><summary>答案</summary>
输出寄存器在所有输入使用完前就被写入时。例如 `mov %0, %1` 先写 %0，后面还有指令读 %1。如果不加 `&`，编译器可能让 %0 和 %1 共用同一寄存器，mov 后 %1 的值被覆盖。`&` 强制编译器给输出和输入分配不同寄存器。
</details>

3. `"I"(0x1000)` 和 `"i"(0x1000)` 的区别？
<details><summary>答案</summary>
`I` 是 AArch64 特有约束，限制 0-4095 范围（12 位无符号立即数，用于 ADD/SUB 指令的 imm12 字段）。`i` 是通用立即数约束，不限制范围。`"I"(0x1000)` 等于 4096，正好在范围内；`"I"(0x5000)` 会报错。
</details>

4. `"m"(x)` 内存约束和 `"r"(x)` 寄存器约束在 LDR 指令中有什么区别？
<details><summary>答案</summary>
`"m"(x)` 让编译器传 x 的内存地址，汇编用 `ldr %0, %1` 直接从内存加载。`"r"(x)` 让编译器先把 x 加载到寄存器，汇编操作的是寄存器而非内存。用 `"m"` 可以减少一条 mov 指令，但要求汇编指令支持内存操作数。
</details>

5. 为什么 AArch64 内联汇编很少用具体寄存器约束（如 `"x0"`）？
<details><summary>答案</summary>
指定具体寄存器（如 `"x0"`）破坏编译器的寄存器分配，导致额外的 mov 指令在约束寄存器和编译器选的寄存器间搬运。用 `"r"` 让编译器自由选择，性能更好。只有在 ABI 要求特定寄存器（如系统调用）时才用具体约束。
</details>
