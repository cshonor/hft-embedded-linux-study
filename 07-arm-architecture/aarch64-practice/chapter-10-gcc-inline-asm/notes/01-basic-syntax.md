# 10.1 基本语法

> 来源：§10.1 · 精读 · [章总览](section-0-本章完整概述.md)

## 本节讲什么

GCC 内联汇编（Inline Assembly）的基本语法：`asm` 关键字、输入/输出操作数、约束字符串、clobber 列表、`volatile` 修饰符。

## 基本语法格式

```c
asm volatile (
    "汇编指令模板\n\t"      /* 汇编代码（字符串） */
    : 输出操作数列表          /* 结果写回 C 变量 */
    : 输入操作数列表          /* C 变量传入汇编 */
    : clobber 列表           /* 被修改的寄存器/内存 */
);
```

### 语法四要素

| 部分 | 作用 | 可省略 |
|------|------|--------|
| 汇编模板 | 具体指令，用 `%0`/`%1` 引用操作数 | ✗ |
| 输出操作数 | `=` 开头，结果写回 C 变量 | 可省 |
| 输入操作数 | 从 C 变量读值传入 | 可省 |
| clobber | 被修改但不在输入输出中的寄存器 | 可省 |

### 最简示例

```c
/* 一条加法指令 */
int result;
asm volatile (
    "add %w0, %w1, %w2\n\t"    /* w0 = w1 + w2 */
    : "=r"(result)              /* 输出：写回 result */
    : "r"(a), "r"(b)            /* 输入：a 和 b */
);
```

GCC 编译后会生成类似：
```asm
mov w1, #a_value
mov w2, #b_value
add w0, w1, w2     ; 内联汇编插入的指令
str w0, [result]  ; 写回 result
```

## 操作数引用

| 语法 | 含义 | 示例 |
|------|------|------|
| `%0` | 第 0 个操作数（输出+输入统一编号） | `"add %0, %1, %2"` |
| `%1` | 第 1 个操作数 | 同上 |
| `%w0` | 32 位视图（W 寄存器） | `"add %w0, %w1, %w2"` |
| `%x0` | 64 位视图（X 寄存器） | `"mov %x0, %x1"` |
| `%%` | 字面 `%` | `"mov %0, #100\n\t"` |

### 操作数编号规则

```c
asm volatile (
    "add %0, %1, %2"
    : "=r"(out)        // %0 = out（输出）
    : "r"(in1), "r"(in2)  // %1 = in1, %2 = in2（输入）
);
```

**编号规则**：输出操作数在前，输入操作数在后，连续编号。如果有 1 个输出 + 2 个输入，则 `%0`=out, `%1`=in1, `%2`=in2。

## volatile 修饰符

| 有无 volatile | 行为 | 适用场景 |
|--------------|------|---------|
| `asm volatile(...)` | 不会被优化掉 | 有副作用：读寄存器、屏障、I/O |
| `asm(...)` | 输出未使用时可能被删 | 纯计算（输出一定会用） |

```c
/* ✓ 必须加 volatile：有副作用 */
asm volatile("mrs %0, cntvct_el0" : "=r"(t));

/* ✗ 不加 volatile：可能被删 */
asm("nop");  /* 可能被优化掉 */
asm volatile("nop");  /* 保留 */

/* 纯计算可以不加 volatile（输出被使用就不会删） */
asm("add %0, %1, #1" : "=r"(y) : "r"(x));
```

## 多条指令

```c
/* ✗ 错误：多条指令挤在一行，as 可能报错 */
asm("mov x0, #1 mov x1, #2");

/* ✓ 正确：用 \n\t 或 ; 分隔 */
asm volatile(
    "mov x0, #1\n\t"
    "mov x1, #2\n\t"
    "add x0, x0, x1\n\t"
);
```

| 分隔方式 | 说明 |
|---------|------|
| `\n\t` | 最常用，换行 + Tab（GNU as 格式） |
| `;` | 单行分隔，部分架构支持 |
| `\n` | 只换行也可以 |

> **推荐**：用 `\n\t`（换行+Tab），编译后代码格式整齐，`objdump` 反汇编可读性好。

## 命名操作数（GCC 扩展）

```c
/* 数字引用 */
asm("add %0, %1, %2" : "=r"(y) : "r"(a), "r"(b));

/* 命名引用（可读性更好） */
asm("add %[result], %[a], %[b]"
    : [result] "=r"(y)
    : [a] "r"(a), [b] "r"(b));
```

命名操作数在复杂内联汇编中更清晰，不用担心编号错位。

## __asm__ 和 __volatile__

```c
/* ISO C 标准写法（-std=c99 -pedantic 下用） */
__asm__ __volatile__("nop");

/* GCC 扩展写法（内核和 -std=gnu99 下常用） */
asm volatile("nop");
```

| 写法 | 来源 |
|------|------|
| `asm` / `volatile` | GCC 扩展 |
| `__asm__` / `__volatile__` | ISO C（可移植） |
| `__asm__ __volatile__` | 最兼容 |

## HFT 关联

- **读取时间戳 `mrs x0, cntvct_el0`** → 精确计时，测量延迟纳秒级
- **手动优化关键指令序列** → 编译器不优化的场景（如精确控制指令顺序）
- **内联汇编屏障** → `dmb`/`dsb`/`isb` 必须用内联汇编，C 无对应语法
- **原子操作** → `ldxr`/`stxr` 实现无锁数据结构

## 自测题

1. `asm` 和 `asm volatile` 的区别？
<details><summary>答案</summary>
`asm` 如果输出操作数未被使用，编译器可能优化掉整段汇编。`asm volatile` 告诉编译器有副作用，不能删除。读系统寄存器（mrs）、屏障（dmb/dsb/isb）、I/O 操作必须加 volatile。
</details>

2. `"=r"` 中的 `=` 和 `r` 分别代表什么？
<details><summary>答案</summary>
`=` 是修饰符，表示输出（write-only，汇编只写不读）。`r` 是约束，表示通用寄存器。组合 `"=r"` 意思是「输出到通用寄存器」。`"+r"` 则是 read-write（先读后写）。
</details>

3. 为什么多条指令要用 `\n\t` 分隔？
<details><summary>答案</summary>
GCC 把字符串原样传给汇编器（GNU as）。`\n` 换行让每条指令单独一行，`\t` 缩进对齐。GNU as 按行解析指令，多条指令不分行会解析错误。`;` 也能分隔但不如 `\n\t` 通用。
</details>

4. 操作数 `%0`、`%1` 的编号规则是什么？
<details><summary>答案</summary>
输出操作数在前，输入操作数在后，连续编号。例如 1 个输出 + 2 个输入：`%0` = 输出，`%1` = 第 1 个输入，`%2` = 第 2 个输入。编号从 0 开始，按声明顺序递增。
</details>

5. `%w0` 和 `%x0` 的区别是什么？
<details><summary>答案</summary>
`%w0` 引用 W 寄存器（32 位视图，如 W0），`%x0` 引用 X 寄存器（64 位视图，如 X0）。两者是同一物理寄存器的不同宽度视图。用 `%w0` 时指令操作 32 位，`%x0` 操作 64 位。
</details>
