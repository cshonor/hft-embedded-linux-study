# 0.1 内核调试为什么难：与用户态调试的六个不同

> 🟢 零起点 · 先建立「为什么不能照搬用户态经验」的心智模型

## 本节讲什么

你在 03.6 学过的调试手段（gdb 单步、valgrind、coredump）到内核里**要么不能用、要么要换姿势**。
这一节用一张对照表 + 六个「为什么」，把这条鸿沟讲清楚。表里每一行都直接决定
本模块后面哪一章在解决它。

## 对照表：同一个动作，两个世界

| 你想干什么 | 用户态怎么做 | 内核态为什么不能照搬 | 内核态的姿势（本模块哪章） |
|-----------|--------------|----------------------|---------------------------|
| 打印调试信息 | `printf`（走 libc，最终 syscall write） | 内核里没有 libc，`printf` 会链接失败；内核自己向终端打印的机制是 **printk** | [Ch3](../chapter-03-printk/) |
| 单步调试 | `gdb ./a.out` 直接跑 | 用户态 gdb 靠 ptrace 系统调用「附着」进程——ptrace 不能附着内核；内核是「别的进程的地基」 | [Ch11 KGDB](../chapter-11-kgdb/)（要第二台机器+串口/网线） |
| 崩溃后看现场 | coredump 落盘 → 事后 gdb 尸检 | 内核崩 = 全系统死，**没人负责写盘**；现场只能当场打印（Oops）或靠 kdump 抓快照 | [Ch7 Oops](../chapter-07-oops/) / [Ch10 panic](../chapter-10-panic-lockup/) |
| 查内存越界 | valgrind / ASan，程序照跑 | valgrind 是用户态虚拟机方案，进不了内核；内核要在**编译时插桩**（KASAN），且必须重编内核 | [Ch5 内存调试](../chapter-05-memory-debug-1/) |
| 查竞态/死锁 | TSan / gdb 看线程栈 | 同样要内核内建检查器：LOCKDEP（锁规则）、KCSAN（数据竞争），同样要重编内核 | [Ch8 锁调试](../chapter-08-lock-debug/) |
| 看函数调用流程 | ltrace / perf | 内核函数不经过 PLT，ltrace 看不见；用 **ftrace**（内核自带）或 kprobes 动态插桩 | [Ch9 ftrace](../chapter-09-ftrace/) / [Ch4 kprobes](../chapter-04-kprobes/) |

## 六个「为什么」，每个一句话

1. **没有 libc**：内核是 libc 的**供给方**（syscall 的实现端），不可能反过来依赖它。
   内核有自己的打印（printk）、内存分配（kmalloc）、字符串函数（在 `lib/` 下自备一套）。
2. **崩溃没有「尸检」**：coredump 依赖内核活着把内存写到盘上——内核自己死了就没人写了。
   所以内核的哲学是**当场倾倒**（Oops 打印一屏现场），或者提前配好 kdump（用一小块备用内存
   抓快照，重启后分析，Ch10 讲）。
3. **权限是反的**：用户态调试器（gdb/ptrace）是内核提供的**服务**；内核自己没有更高一层，
   所以「调试内核」必须用第二台机器（KGDB + 串口）或者让内核**自我观测**（ftrace/kprobes）。
4. **一个 bug 全系统买单**：用户态段错误死一个进程，浏览器崩了重开就行；内核 bug 轻则 Oops
   杀掉一个任务，重则 panic 全机重启——你的 SSH 会话、你的数据、别人的服务都在同一具尸体上。
5. **观测手段要预先编进内核**：ASan/TSan 是编译期插桩，内核同理——KASAN、LOCKDEP 都是
   `CONFIG_*` 选项，**发行版默认内核一般没开**，要自己重编（Ch1 的 04 节讲 debug kernel vs
   production kernel 的取舍）。这是内核调试「侵入性高」的根源。
6. **成本不对称**：改一行用户态代码重新编译 3 秒；改内核要重编 + 重启（几分钟起步）。
   所以内核调试更依赖**动态手段**——printk 的 dynamic debug（不重编开关打印）、kprobes
   （运行时插探针）、ftrace（运行时追踪），本模块精读章节的重心都在这里。

## 一张图记住

```console
用户态：程序 ──崩──> coredump ──> gdb 尸检（事后）      ← 人有后悔药
内核态：内核 ──崩──> Oops 当场打印 ──> panic 全机死     ← 死前只喊一嗓子
              ↑ 崩之前                              ↑ 崩之后
        printk / ftrace / kprobes               Oops 解读 / kdump
        （Ch3/4/9，主动观测）                    （Ch7/10，现场分析）
```

新手路径就是顺着这张图：先学「崩之前的 printk」（最安全），再学「崩之后的 Oops 解读」，
最后才碰 kprobes/ftrace/KGDB 这些高级观测。
