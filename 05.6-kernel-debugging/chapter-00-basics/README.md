## 三句话版本

1. **内核没有护栏**：用户态程序崩，死一个进程；内核代码崩，全系统陪葬（panic）——所以内核调试的功夫花在「崩之前」的观测手段上（printk / ftrace / kprobes）。
2. **Oops 是内核版的段错误报告**：用户态段错误给你一行 `Segmentation fault`，内核 Oops 给你**一整屏现场**（出错指令地址、寄存器、调用链）——学会读它就入门了一半。
3. **学习顺序：printk → 读 Oops → 再上工具**（ftrace / KASAN / KGDB）。不要一上来就装 KGDB。
