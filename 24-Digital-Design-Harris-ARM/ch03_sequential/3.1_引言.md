## 笔记

### 为何需要时序？

组合逻辑能算，但：

| 问题 | 后果 |
|------|------|
| **存不住** | 输入一撤，结果没了；无法「记住上次算到哪」 |
| **一直在变** | 毛刺、中间态乱飞；后级若当最终结果用会出错 |
| **无法对齐多块** | 多条路径延迟不同，没有统一节拍就无法可靠拼大系统 |

→ 引入 **存储（锁存/触发器）** + 工业上再用 **统一时钟** 把更新切成拍。

### 两大基础电路

| | **组合逻辑** | **时序逻辑** |
|--|--------------|--------------|
| 存储 | **无** 触发器/锁存器 | **有**（记忆单元） |
| 输出决定 | **仅当前输入** | **当前输入 + 过去保存的状态** |
| 并行 | 天然多路同时算 | 可在时钟节拍内多路同时算（受控） |
| 缺陷 / 能力 | 有 tp、毛刺；**存不住** | 能锁存稳定结果，可规模化搭系统 |

组合细节（延迟、毛刺）→ [2.9](../ch02_combinational/2.9_时序.md)。  
「立刻决定」是 **逻辑关系**；物理上仍要等传输延迟才稳定。

时序再分：

| | **同步时序** | **异步时序** |
|--|--------------|--------------|
| 时钟 | **全体 FF 共用同一 CLK**，边沿统一更新 | 无统一时钟，信号互相触发 |
| 分析 | setup/hold 清晰 | 竞态难穷举 |
| 工业 | CPU / MCU **主流** | 仅局部特殊；通用处理器不做大规模异步 |

### 本章主线（按学习顺序）

```
3.2  怎么存 1 bit？     SR → D 锁存 → 主从 D-FF → 寄存器
3.3  怎么规模化？       全体 FF 共 CLK；FF → 组合 → FF
3.4  怎么做控制？       FSM = 状态寄存器 + 次态/输出组合逻辑
3.5  怎么保证对？       setup / hold · 频率上限 · 亚稳态 · 同步器
3.6  并行是什么？       拍内多路组合，边沿统一采集
```

| 你以后看到的东西 | 本章对应 |
|------------------|----------|
| CPU 通用寄存器、流水线级间寄存器 | D-FF / 寄存器堆 |
| 单周期/流水线「一拍算完」 | 同步范式 + 关键路径 |
| UART/SPI/总线控制器 | FSM |
| 跨时钟 GPIO、网卡 | 亚稳态 + 同步器 |
| 超标量多通道 | 可控并行 |

> **一句话：** 组合负责算；触发器负责记；时钟负责对齐；FSM 用「记+算」做控制。
