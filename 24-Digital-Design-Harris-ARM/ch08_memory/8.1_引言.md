## 笔记

处理器速度涨得远快于 **DRAM** → 裸接主存会把整机拖死。  
Ch7 教学 CPU 常假设「访存一拍完」——真实系统靠 **层次结构** 才接近这个假象。

对策依赖 **局部性原理**，把「常用」放进离 CPU 近的快存：

| 局部性 | 含义 | Cache 怎么用 |
|--------|------|--------------|
| **时间局部性** | 刚用过的很快再用 | 留下最近访问的块 |
| **空间局部性** | 附近地址也快要用 | **按块（block）** 整段搬入 |

```
寄存器  ≪  L1/L2 Cache(SRAM)  ≪  DRAM  ≪  磁盘/Flash
快·贵·小                              慢·便宜·大
```

### 对嵌入式 Linux

| 场景 | 直觉 |
|------|------|
| 驱动热路径反复摸同一描述符 | 吃时间局部性 → 少 miss |
| 顺序扫缓冲区 / 环形队列 | 吃空间局部性 → 按 cache line 对齐有时有益 |
| DMA 大块搬运 | 绕过或弄脏 Cache → 要一致性协议（→ [8.3](./8.3_高速缓存.md)） |
| `ioremap` 的 device memory | 往往 **不走** 普通 Cache 语义 |

层次结构 = 用局部性兑换「接近 SRAM 的平均速度 + 接近磁盘的容量/价格」。
