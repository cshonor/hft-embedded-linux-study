## ④ MSVC 明确不支持的 C 特性

| 特性 | 检测宏（`__STDC_NO_*__`） | 替代 |
|------|--------------------------|------|
| VLA | `__STDC_NO_VLA__` | `malloc` / 固长数组 |
| `<threads.h>` | `__STDC_NO_THREADS__` | `_beginthreadex` / `std::thread` |
| `_Atomic` | `__STDC_NO_ATOMICS__` | `Interlocked*` / `std::atomic` |
| `_Complex` | `__STDC_NO_COMPLEX__` | 自建结构体 |
| `aligned_alloc` | —— | **`_aligned_malloc`** |

支持起点：VS 2019 16.8 起 `/std:c11` / `/std:c17`。

## ⑤ Windows ↔ POSIX 缺失对照

| POSIX | Windows |
|-------|---------|
| `fork()` | ❌ 无（`CreateProcess`） |
| `pthread_*` | ❌ 无（`CreateThread` / SRWLOCK） |
| `mmap()` | ❌ 无（`CreateFileMapping` + `MapViewOfFile`） |
| `<unistd.h>` | ❌ 无（`<io.h>` / `<process.h>` 部分） |
| `<sys/socket.h>` | `<winsock2.h>` + `WSAStartup()` 前置 |
| `read(fd)` on socket | `recv(s, ...)` |
| `close(fd)` | 文件 `CloseHandle` / socket `closesocket` |
| `fcntl(O_NONBLOCK)` | `ioctlsocket(FIONBIO)` |
| `errno` | `GetLastError()` / `WSAGetLastError()` |
| `sleep(sec)` | `Sleep(ms)` |
| `scanf` | MSVC 报 C4996 → 加 `_CRT_SECURE_NO_WARNINGS`；**别用 `scanf_s`**（非标准） |

## ⑥ GNU 扩展 ↔ MSVC 写法（详见 [5.5](../05-boundary/5.5-MSVC不吃GNU扩展怎么办.md)）

| GNU 写法 | gcc/clang | MSVC | MSVC 替代 |
|---|---|---|---|
| `int a[] = {[0 ... 5] = 7};` 范围初始化 | ✅ | ❌ | 逐项赋值 / 循环 |
| `({ ... })` 语句表达式 | ✅ | ❌ | 抽成静态内联函数 |
| `__attribute__((packed))` | ✅ | ❌ 不认该关键字 | `#pragma pack(push,1)` / `__pragma(pack(pop))` |
| `__attribute__((unused))` | ✅ | ❌ | `__declspec(unused)` / `(void)x;` |
| `char buf[0];` 零长数组 | ✅ | ❌ | 柔性数组成员 `char buf[];` |
| `__typeof__(x)` | ✅ | ❌ | C23 `typeof` / 手写类型 |
| `char buf[];` 柔性数组（C99 标准） | ✅ | 视版本 | —— |

**GNU 扩展是两层**（实测，`-pedantic-errors` 下的表现）：

| 层 | 例子 | `-std=c11 -pedantic-errors` |
|---|---|---|
| 保留命名空间层（双下划线） | `__attribute__` / `__typeof__` / `__builtin_*` | ✅ 仍通过 |
| 新语法层 | 范围初始化 / 语句表达式 / 零长数组 | ❌ 报 **ISO C forbids ...** |

> 想检查代码有没有偷偷依赖 GNU 语法，**`-std=c11` 不够**（实测照样通过），
> 必须加 `-pedantic-errors`。

**判断编译器用谁：** `_MSC_VER`（MSVC）/ `__GNUC__`（GCC）/ `__clang__`（Clang）。
⚠️ **不要用 `__STRICT_ANSI__` 判断** —— 它是 GCC/Clang 在 `-std=c11/c17`（非 gnu*）下定义的
模式宏，MSVC 从不定义（MSVC 严格模式用 `/Za` + `__STDC__`）。

## ⑦ UB 速查：同一份越界读，四套编译器三种答案

`sum_n(buf, 8)` 读只有 4 个元素的数组，导出链路丢掉了长度信息。

| 编译器 | 平台 | `-O0` | `-O2` |
|---|---|---|---|
| LLVM clang 23.1.0 | macOS arm64 | 正常 | ❌ **死循环卡住** |
| Apple clang 21.0.0 | macOS arm64 | 正常 | ✅ 正常 |
| clang 19.1.7 | Linux aarch64 | 正常 | ✅ 正常 |
| gcc 14.2.0 | Linux aarch64 | 正常 | ✅ 正常 |

**三道防线的沉默情况（实测）：**

| 防线 | 结果 |
|---|---|
| `-Wall -Wextra` | 零告警 |
| `-fanalyzer`（gcc 14） | 零告警 |
| `-D_FORTIFY_SOURCE` | 对**手写下标**无效（只对库函数越界写有效） |
| `-fsanitize=address` | ✅ 抓现行：`global-buffer-overflow ... ptrbug.c:34 in sum_n` |

→ 工程纪律：**两个编译器 + 至少一路 ASan**。详见 [4.2](../04-linux-gnu/4.2-三道防线全部沉默.md)。

## ⑨ 内核模块实验速查（详见 [5.6](../05-boundary/5.6-内核模块要真Linux吗.md)）

| 命令 | 干什么 |
|---|---|
| `uname -r` | 当前运行内核的完整发行串，`vermagic` 必须与之逐字相同 |
| `ls -d /lib/modules/$(uname -r)/build` | 内核构建树在不在 —— **编模块的头号前提** |
| `sudo apt install linux-headers-$(uname -r)` | 缺就装（Debian/Ubuntu 系） |
| `zcat /proc/config.gz \| grep CONFIG_MODULES` | 内核支不支持可加载模块（`=y` 才有戏） |
| `make -C /lib/modules/$(uname -r)/build M=$(pwd) modules` | 模块 Makefile 的本质那一句 |
| `modinfo xxx.ko \| grep vermagic` | 核对版本串，加载前先看这个 |
| `sudo insmod xxx.ko` | 加载（不处理依赖） |
| `sudo modprobe xxx` | 加载并自动处理依赖（需先 `depmod`） |
| `rmmod xxx` / `modprobe -r xxx` | 卸载 |
| `lsmod` / `cat /proc/modules` | 看已加载模块 |
| `dmesg -wH` | 实时看内核日志（`pr_info` 的输出在这里） |
| `cat /proc/sys/kernel/tainted` | taint 位图 |

**taint 常用位**（kernel.org 官方表）：

| 值 | 位 | 字母 | 含义 |
|---|---|---|---|
| 1 | 0 | `P` | 加载了专有许可模块 |
| 1024 | 10 | `C` | 加载了 staging 驱动 |
| **4096** | **12** | **`O`** | **加载了 out-of-tree 模块（自编模块的常态）** |
| 8192 | 13 | `E` | 加载了未签名模块 |

> 注意：**taint 卸载也清不掉**，只能重启。
