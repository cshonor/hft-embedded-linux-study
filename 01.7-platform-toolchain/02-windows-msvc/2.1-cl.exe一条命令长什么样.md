# 2.1 `cl.exe` 一条命令长什么样

[← CH2 MSVC 编译器与选项](./README.md) · 下一节：[2.2 选项对照全表 →](./2.2-选项对照全表.md)

## 本节讲什么

先看一条最小的 MSVC 编译命令，和你每天都在敲的 `clang main.c -o app` 摆在一起。
差别不大 —— 主要三个：`/` 代替 `-`、输出文件名闭合写、还有一个隐含陷阱（CRT）。

## 要点

### 最小对照

| | MSVC | clang / gcc |
|---|------|-------------|
| 最小编译链接 | `cl hello.c` | `clang hello.c -o hello` |
| 指定输出名 | `cl /Fe:hello.exe hello.c` | `clang hello.c -o hello` |
| 只编译不链接 | `cl /c hello.c` → 得 `hello.obj` | `clang -c hello.c` → 得 `hello.o` |
| 带调试信息 | `cl /Od /Zi hello.c` | `clang -g -O0 hello.c -o hello` |
| 开警告 | `cl /W4 /WX hello.c` | `clang -Wall -Wextra -Werror ...` |
| 指定 C 标准 | `cl /std:c17 hello.c` | `clang -std=c17 ...` |

**注意 `cl hello.c` 不写 `/Fe:` 时**，输出的可执行文件名取自**第一个源文件名**（`hello.exe`），
这和 gcc/clang 默认输出 `a.out` 的习惯不同。

### 编译 + 链接分开写法（更能看清四件套）

MSVC 侧（⚠️ 按官方文档整理，本机不可执行）：

```bat
cl /c /Zi /W4 /Od /std:c17 file1.c file2.c    :: → file1.obj file2.obj + vc140.pdb
link /OUT:app.exe /DEBUG file1.obj file2.obj  :: → app.exe + app.pdb
```

clang 侧（✅ 本机实测）：

```bash
clang -c -g -Wall -Wextra -O0 -std=c17 file1.c file2.c   # → file1.o file2.o
clang -g -o app file1.o file2.o                          # → app
```

> 结构**完全一致**：一段先各自编译成目标文件，第二段把目标文件拼起来。
> 差别只在拼写和中间产物后缀（`.obj` vs `.o`）。

### MSVC 命令行的两个反直觉之处

**① 不需要`-o`的语法，靠冒号粘参数**

MSVC 用 `/项:值` 的写法，值和开关之间没有空格：`/Fe:hello.exe`、`/Fo:obj\hello.obj`、`/Iinclude`。
这和 Unix 系的 `-o hello` 不同。混用会写成 `/Fe hello.exe`（错）。

**② `cl.exe` 的行为受环境变量强烈影响**

`cl.exe` 必须知道 Windows SDK 和 CRT 的头文件在哪，这些信息通常在
**Developer Command Prompt**（`vcvarsall.bat` 跑起来之后）里由环境变量提供：

| 环境变量 | 决定什么 |
|----------|----------|
| `INCLUDE` | 头文件搜索路径（相当于一堆 `-I`） |
| `LIB` | 库搜索路径（相当于一堆 `-L`） |
| `PATH` | `cl.exe` / `link.exe` 自己在哪里 |

所以同一条 `cl /c hello.c` 在普通 PowerShell 里会报"找不到 `stdio.h`"，
在 **Developer Command Prompt** 里就正常。这是 MSVC 新手最高频的第一个坑。

对比 `/I` 与 `-I`：两者语义相同，但 MSVC 少了环境就整个不能工作，
而 clang/gcc 有系统内置默认搜索路径，裸奔也能编 hello world。

### 你 Mac 上的位置在这基本一致（✅ 实测）

```text
$ clang -c -g -O0 -Wall -Wextra -std=c11 ptrbug.c -o ptrbug.o
$ ls -l ptrbug.o
-rw-r--r--  1 a0000  staff  3800 Sep 26 16:23 ptrbug.o
```

`clang` 不需要任何环境变量就能找到自己的头文件和 libc —— 这就是为什么你在 Mac 上
从没为"去哪找 stdio.h"操过心，而 Windows 新手几乎人人撞过。
