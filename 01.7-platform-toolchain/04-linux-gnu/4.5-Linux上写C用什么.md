# 4.5 Linux 上写 C 用什么：没有 VS 的日子

[← 4.4 ELF 与 DWARF](./4.4-ELF与DWARF.md) · 下一节：[CH5 Windows ↔ POSIX 边界 →](../05-boundary/README.md)

## 本节讲什么

Windows 有 Visual Studio，Mac 有 Xcode。**Linux 没有官方 IDE。**
新手最容易在这里卡住：装完系统、打开终端，然后不知道该敲什么。

答案不是"装某个 IDE"，而是理解 Linux 上的分工方式：

```
编辑器 / IDE      ← 负责让你写代码看得舒服（可选，随时可换）
      ↓ 调用
构建系统 CMake    ← 负责生成 make/ninja 规则（见 01.5）
      ↓ 调用
编译器 gcc/clang  ← 负责真的编译
      ↓ 调用
调试器 gdb        ← 负责让你看清运行时
```

**每一层都能独立更换，这就是 Unix 哲学。** 代价是新手要自己把它们拼起来。

## 要点

### 四个主流选项

| 方案 | 装什么 | 优点 | 代价 |
|---|---|---|---|
| **① VS Code + C/C++ 扩展** | 跨平台的编辑器 + Microsoft 官方调试适配 | 免费、最通用；你在 Mac / Windows 上能用同一套键位；远程 SSH 到 Pi 开发体验成熟 | 它**本质是编辑器**，要自己配 `tasks.json` / `launch.json`；CMake Tools 扩展几乎是必备 |
| **② CLion**（JetBrains） | 商业 IDE | 开箱即用 CMake 工程、重构能力强、调试 UI 完整 | 收费（有学生/开源许可）；内存占用大 |
| **③ Neovim / Vim + clangd + LSP** | 编辑器 + 语言服务器 | 轻量、远程到 Pi 上（几十 MB 内存）、长期最舒服 | 配置门槛最高；初学阶段会把精力耗在配环境上 |
| **④ 纯命令行 + Makefile** | gcc + gdb + make（**你现在在 Pi 上的状态**） | 零依赖、最能看清工具链本体 | 没有代码补全/跳转 |

### 我的建议：这个阶段先把 ④ 用扎实

理由很实际：

1. 你正在**学 TLPI**，每章的示例代码都是单文件 + `gcc xxx.c -o xxx` 就能跑；
2. 本书的目的之一就是让你建立"编译器 + 链接器 + 调试器"的心智模型 —— VS Code 的
   一键运行会把这些藏起来，反而影响理解；
3. `01.5-cmake-build` 那本已经教 CMake 了，等你开始写多文件工程时自然会用到。

**具体怎么在 Pi 上写：**

```bash
# 方案 A：本地在 Pi 上写（vim/nano），来回 scp
scp demo/ptrbug.c wzp@192.168.31.109:~/demo-msvc/

# 方案 B：VS Code Remote-SSH 直接改 Pi 上的文件（推荐过渡）
#        本地编辑体验 + 远程编译调试，两头都不用拷贝
```

> **一个很实用的组合：** VS Code 装 Remote-SSH 扩展，直接打开 Pi 上的目录。
> 你在 Mac 上敲键盘，文件即时落在 Pi 上，`Ctrl+~` 切出来的终端就是 Pi 的 shell，
> 于是 `gcc` 用的就是 Pi 的 gcc 14.2。这是目前"Mac 上写 Linux C"最省心的形态。

### VS Code 到底是不是「VS」

必须说清楚（详见 [1.0](../01-common-core/1.0-先分清三个产品.md)）：

| | Visual Studio 2022 | VS Code |
|---|---|---|
| 出生 | 1997 年，Windows 专用 | 2015 年，Electron 跨平台应用 |
| 本质 | 完整 IDE + MSVC 工具链 + MSBuild | **文本编辑器** + 插件市场 |
| C 编译器 | 自带 cl.exe | **一个都不带**，要你自己装 gcc/clang |
| 工程文件 | `.sln` / `.vcxproj`（私有格式） | 无（靠 `tasks.json`/`launch.json`/`CMakeLists.txt`） |
| 调试器 | 自带 VS Debugger | 靠扩展调 gdb / lldb |

**它们是同名不同物的两个产品。** 你在 Mac 上从官网搜到的 "Visual Studio" 下载项，
大概率会引导到 **VS Code**（Mac 版的 VS 已于 2024-08-31 退役）。
这不是降级版，是另一个东西。

### 最小可用配置（VS Code + C/C++）

`.vscode/tasks.json`（构建）与 `.vscode/launch.json`（调试）的核心字段：

```jsonc
// tasks.json：等价于命令行 gcc -g *.c -o app
{
  "tasks": [{
    "type": "shell",
    "label": "build",
    "command": "gcc",
    "args": ["-g", "-O0", "-Wall", "-Wextra", "${file}", "-o",
             "${fileDirname}/${fileBasenameNoExtension}"]
  }]
}
```

```jsonc
// launch.json：告诉 VS Code 去驱动 gdb
{
  "configurations": [{
    "name": "gdb launch",
    "type": "cppdbg",
    "request": "launch",
    "program": "${fileDirname}/${fileBasenameNoExtension}",
    "MIMode": "gdb",
    "preLaunchTask": "build"          // ← 先跑上面的 build 任务
  }]
}
```

配完这两份，你按下 F5 时发生的事情和你在 Windows 上按 F5 **完全同构**：
编译 → 启动调试器 → 下断点 → 暂停。**工具换了，心智模型一行代码都没变。**

<details>
<summary>Q&amp;A：那我还有个疑问：Mac 上练 C 行不行？</summary>

行，但要清楚边界：

- ✅ 语言本身（指针、结构体、内存布局、UB）：Mac/Linux 都练得动，
  `01-c-language` 那六本书的内容基本平台无关；
- ⚠️ 构建（CMake / Make）：大同小异，注意 macOS 与 Linux 的路径、库命名差异；
- ❌ 系统调用（`fork` / `epoll` / `mmap` 行为 / `/proc`）：**必须在 Linux 上**，
  原因是 [CH5](../05-boundary/README.md) 整章的内容。

所以分工建议是：**C 语言用 Mac 练手感，系统调用用 Pi 练真功夫**，
两边共用一份 git 仓库，正好把两边都跑得通当成"代码没踩 UB"的第一道检验。
</details>
