# 4.4 结论：TLPI 为什么必须在 Linux 上跑

[← 5.3 编码行尾与路径](./5.3-编码行尾与路径.md) · [CH4 边界](./README.md)

## 本节讲什么

把前面三节的碎片拼成一个判断，然后落到**你现在这几台机器上具体怎么排**。

## 要点

### 判断标准：看主题是不是"系统调用"

判断一件事能不能在 VS/MSVC 上做，标准很简单 —— **看它的主题是不是「系统调用」**：

| 你的主线 | 主题 | 能不能在 VS/MSVC 上学 | 原因 |
|----------|------|----------------------|------|
| [01 C 语言](../01-c-language/)（K&R / Pointers on C / Modern C） | C 语法、指针、内存模型 | ✅ **可以** | 标准库部分三边通用 |
| [01.5 CMake](../01.5-cmake-build/) | 构建系统描述 | ✅ **可以** | CMake 本来就能生成 VS 工程 |
| [03 TLPI](../03-linux-userspace-api/) | **Linux 系统调用 API** | ❌ **不行** | `open`/`read`/`fork`/`mmap`/`signal` 全套 POSIX 接口 |
| [03.5 UNP](../03.5-unix-network-api/) | **Socket API** | ❌ **不行** | Winsock 是另一套 API，`read()` 读 socket 不成立 |
| [05 LKD / 05.5](../05-linux-kernel/) | **Linux 内核** | ❌ 更不行 | 内核源码本身就是 Linux 的 |
| [13 DPDK](../13-dpdk/) | 用户态高速网络 | ❌ Windows 支持有限，路径完全不同 | — |

一句话：**TLPI 这本书的名字里就写着 Linux。** 它每一章都在讲某个 syscall 的行为、
边界条件、`errno` 取值。这些内容在 Windows 上没有对应概念，硬搬等于把书重写一遍。

### 你现在三台机器的分工

| 机器 | 适合做什么 | 备注 |
|------|-----------|------|
| **Mac（主力）** | C 语言 / 指针 / Modern C / 算法 / 概念层学习；CMake 练习；**lldb 调试**（CH3 已实跑通） | clang 23.1.0 + Xcode 自带 lldb；**不能**跑 TLPI 示例代码 |
| **树莓派 5（Debian 13 / kernel 6.18）** | **TLPI / UNP / eBPF 的主战场**；aarch64 顺便让你看见和 x86 的差异 | gcc 14.2 / clang 19 / gdb；真实 Linux syscall |
| **Windows（已不具备）** | MSVC 对照 —— 只能靠本模块做认知层面的了解 | 需要时再考虑虚拟机 |

### 所以 VS 那段经历的价值在哪

你已经用 VS 学会了 C 的核心 —— 这是真实收获。**但它的价值分布不均：**

| 从 VS 学到的 | 迁移价值 | 说明 |
|-------------|---------|------|
| 变量、指针、数组、结构体 | ✅ 100% | 属于语言本身 |
| 「暂停 → 看变量 → 看调用栈」的调试直觉 | ✅ **接近 100%** | 这就是 CH3 的核心论点 |
| 「编译 → 链接 → 生成可执行」的流程感 | ✅ 高 | 四件套在哪都一样 |
| "要开警告、要看警告"的习惯 | ✅ 中高 | 概念通用，拼写要换（`clang -Wall` vs MSVC `/W4`） |
| `/MD` vs `/MT`、`.vcxproj` 写法、属性页在第几层 | ❌ 低 | 出 Windows 就没用 |

> **一句话总结：** VS 帮你迈过了"不知道程序是怎么跑起来的"这道坎，
> 但它让你最熟悉的那些**具体操作**，恰恰是最不能被带走的那部分。
> 能带走的是**心智模型** —— 本模块所有章节写的都是能带走的那一半。

### 行动建议（按优先级）

1. **现在就能做**：把 CH3 在你的 Mac 上跑一遍（[3.3](./../03-macos-xcode/3.3-实测lldb.md)），
   建立"调试四件事"的肌肉记忆。这份能力直接服务于后面所有章节。
2. **顺手解锁**：`sudo xcodebuild -license` —— 让 `xcrun` 体系可用，Apple 官方工具链到手。
3. **TLPI 学习路径**：示例代码一律在**树莓派 5** 上编译运行，Mac 只做笔记和阅读。
   不要在 Windows 侧试图模拟。
4. **写跨平台代码时**：回避 VLA、不用 `_s` 后缀函数、按**能力宏**检测而不是**平台宏**检测。

## 模块收尾

回到开头那个问题 —— **"我在 VS 里学到的要不要记下来？"**

要记，但只记两种方法 🙂：

| 记 | 不记 |
|----|------|
| 工具链四件套的概念（编译器 / 链接器 / 构建系统 / 调试器） | 属性页在第几层菜单 |
| 调试四件事与命令对照表 | VS 某个版本 UI 的截图 |
| 三条工具链的互译关系 | —— |
| Windows 与 POSIX 的边界清单 | —— |

这也正是本模块的内容取舍原则：

> **概念层永远有效，操作层三个版本一作废。**
