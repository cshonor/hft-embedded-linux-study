# CH5 · Windows ↔ POSIX 边界：为什么 TLPI 的代码在 VS 里跑不起来

> **这一章解决什么困惑：** 我明明在 VS 里把 C 学得挺顺了，为什么学长都说
> "要学 Linux 系统编程你得换环境"？
>
> 因为 Windows 和 POSIX 不是"同一套东西换到另一个系统"，而是**两套不同的 API 世界观**，
> 交界处从 `#include` 那一行就开始断裂。

---

## 本章的收获

1. MSVC 对 C 标准的支持边界在哪 —— 官方白纸黑字说不打算支持的那些东西
2. `unistd.h` / `sys/socket.h` 为什么不存在，以及 Windows 的对应物叫什么
3. 编码、行尾、路径这些"不致命但烦死人"的差异
4. 一个明确的行动方案：你的三条主线各自该在哪个环境上跑

## 一句话结论

> **MSVC 不是"缺了一点的 gcc"，它是有意选择了一条不同的路线。**
> 这不代表它差 —— 它对 VLA 的拒绝有明确的安全理由；但它确实意味着
> 「在 VS 里学 C」和「在 Linux 上学系统编程」**是两件不同的事**，不能互相替代。
