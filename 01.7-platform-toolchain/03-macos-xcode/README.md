# CH3 · macOS / Xcode：另一套 clang，另一套账

> **这一章解决什么困惑：** 我明明在 Mac 上，`gcc` 却是 clang；两份 clang 版本号对不上；
> `-g` 编译完想调试，调试信息不知道去了哪里。
>
> 原因是苹果在工具链上叠了三层，而且每层都和你在 Linux 学到的不一样。

## 这节的三个结论

1. **Mac 上没有 GNU gcc。** `/usr/bin/gcc` 是一个 200KB 的转发 shim，
   大小和内容都与 `/usr/bin/clang` 相同。真正的选择发生在 `xcode-select` 那一层。

2. **这台机器当前是"许可未同意"状态**，所以 shim 和 `xcrun` 全线报错。
   绕过方法是直接用完整路径点名 Xcode 内的二进制并在编译时带 `-isysroot`；
   根治方法是你本人执行 `sudo xcodebuild -license`。

3. **两套 clang 不是同一个编译器。** 同一台 Mac、同一份源码、同样的 `-O2`，
   Apple clang 21 正常退出，LLVM clang 23 生成死循环卡住。
