⑥ GNU 扩展 ↔ MSVC 写法（详见 5.5）

GNU 写法 gcc/clang MSVC MSVC 替代
int a[] = {[0 ... 5] = 7}; 范围初始化 ✅ ❌ 逐项赋值 / 循环
({ ... }) 语句表达式 ✅ ❌ 抽成静态内联函数
__attribute__((packed)) ✅ ❌ 不认该关键字 #pragma pack(push,1) / __pragma(pack(pop))
__attribute__((unused)) ✅ ❌ __declspec(unused) / (void)x;
char buf[0]; 零长数组 ✅ ❌ 柔性数组成员 char buf[];
__typeof__(x) ✅ ❌ C23 typeof / 手写类型
char buf[]; 柔性数组（C99 标准） ✅ 视版本 ——

GNU 扩展是两层（实测，-pedantic-errors 下的表现）：

层 例子 -std=c11 -pedantic-errors
保留命名空间层（双下划线） __attribute__ / __typeof__ / __builtin_* ✅ 仍通过
新语法层 范围初始化 / 语句表达式 / 零长数组 ❌ 报 ISO C forbids ...

想检查代码有没有偷偷依赖 GNU 语法，-std=c11 不够（实测照样通过）， 必须加 -pedantic-errors。

判断编译器用谁： _MSC_VER（MSVC）/ __GNUC__（GCC）/ __clang__（Clang）。 ⚠️ 不要用 __STRICT_ANSI__ 判断 —— 它是 GCC/Clang 在 -std=c11/c17（非 gnu*）下定义的 模式宏，MSVC 从不定义（MSVC 严格模式用 /Za + __STDC__）。

⑩ 错误编号速查：VS 的 Cxxxx / LNKxxxx（详见 2.6）

前缀 = 出问题的工具。 先看前缀就知道该去哪一步找：

前缀 谁报的 阶段
C cl.exe 编译器 编译期（单个翻译单元）
LNK link.exe 及 lib.exe / dumpbin.exe / editbin.exe 链接期 / 库工具
D8 cl.exe 命令行驱动 还没开始编译
MSB MSBuild 构建脚本层
RC / MIDL / CVT 资源 / IDL / 资源转换 各自的编译步骤

C 段内部：C1xxx = fatal（如 C1083 找不到头文件）· C2xxx = error（如 C2065 未声明标识符）· C4xxx = warning（如 C4013 隐式函数声明，默认不终止编译）。

LNK 段内部：

编号 性质 一句话
LNK2019 error 未解析的外部符号（被引用但找不到定义）
LNK2005 error 符号重复定义（后跟 fatal LNK1169）
LNK1104 fatal 打不开文件（.lib 找不到）
LNK1120 fatal 只是计数行，N unresolved externals
LNK1561 fatal 没定义入口点（没写 main）

判定一句话：

编译期 链接期
出错后 该 TU 不出 .obj（别的文件照出） .obj 都在，不出 .exe/.dll
修的方向 改语法、补 #include、加声明 补实现 / 补 .lib / 删重复定义 / 查 CRT 一致性

两个必须记住的例外：

  • C4013 是警告不是错误（官方标题 Compiler Warning (level 3) C4013）。 想升级用 /we4013（比 /WX 温和）。
  • 声明了没定义，只要没人调用就不会报 LNK2019。触发条件是"被引用且找不到定义"。

clang / gcc 侧对照（本机实测，Apple clang 23.1.0 + ld64 —— 它们没有编号体系， 只给文字描述，这也是 MSVC 编号的优势）：

现象 VS clang / ld64 实测输出
未声明标识符 C2065 error: use of undeclared identifier 'counter'
隐式函数声明 C4013 （警告） error: ... ISO C99 and later do not support implicit function declarations
头文件不存在 fatal C1083 fatal error: 'xxx.h' file not found
声明了没定义 LNK2019 Undefined symbols: "_add", referenced from: _main in x.o
重复定义 LNK2005 duplicate symbol '_g' in: d1.o / d2.o
缺 main LNK1561 Undefined symbols: "_main", referenced from: implicit entry/start
库找不到 LNK1104 ld: library not found for -lfoo
警告升错误 /WX -Werror（输出里带 [-Werror,-Wuninitialized]）

⚠️ C++ 下 LNK2019 报的是 mangled 符号名（?compute@@YAHNHPEBD@Z）， 用 undname（MSVC）/ c++filt（LLVM）解调。头文件缺 extern "C" { } 会让 C 库 在 C++ 里满屏 LNK2019。

noble 专属坑：bpftool 没有独立包（23.x 起并入 linux-tools，apt 只显示虚拟包）。 装完软链出来：

sudo ln -sf $(find /usr/lib -name bpftool -type f 2>/dev/null | head -1) /usr/local/bin/bpftool

验证四连：

perf --version && bpftool version | head -1 && bpftrace --version
ls /sys/kernel/btf/vmlinux    # 有输出 = BTF 在 = CO-RE 能跑
arm-none-eabi-gcc --version | head -1
sudo tuned-adm profile latency-performance   # 低延迟档
