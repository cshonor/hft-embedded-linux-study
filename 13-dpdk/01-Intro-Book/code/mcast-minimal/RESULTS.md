## R1 · 2026-10-04 · 内核栈对照版（lo 自发自收）

**环境**

| 项 | 值 |
|---|---|
| CPU | Intel Core 7 240H（最大 5.2GHz，**powersave 调速器，未锁频**） |
| 内核 | 7.0.0-38-generic |
| 内存 | 32 GB |
| 路径 | **loopback 组播自发自收**（无物理网卡、无 PCIe、无交换机） |
| 发送端 | Python UDP 洪泛，实测 ~128k pps（发送端是瓶颈） |
| 隔离 | **无**（未 isolcpus / nohz_full，桌面环境有干扰） |
| 样本 | ~30 万包/档（p999/p9999 统计意义有限） |
| 时钟基线开销 | p50 ≈ 64ns |

**结果（ns，直方图读数，未扣除基线）**

| `-v`（对应 BURST_SIZE） | 平均批量 | recvmmsg p50 | p99 | p999 | burst p50 | p99 | p999 |
|---|---|---|---|---|---|---|---|
| 1 | 1.0 | 2624 | 3968 | 6400 | 2624 | 4032 | 6464 |
| 8 | 1.3 | 2752 | 5312 | 9152 | 3136 | 5632 | 26240 |
| 32 | 1.3 | 2752 | 4416 | 6720 | 3136 | 4864 | 70144 |

**读数与局限**

1. **方向性结论成立**：burst 尾延迟随 vlen 增大明显右移（p999：6.4μs → 26μs → 70μs），
   与 [chapter-03-PMD与轮询模式](../../notes/chapter-03-PMD与轮询模式.md) 第二节
   "队头等待 ≈ 批次内位置 × 单包处理时间"的预测**定性一致**。
2. **批次远未压满**：发送端只有 ~128k pps，接收端处理更快，平均批量 1.0–1.3，
   远没到 vlen 上限。三档的 recvmmsg 差异因此不大；要看到真正的队头等待，
   需要硬件发包器或内核 pktgen 把批次压满。
3. **lo 路径的先天缺失**：数字只反映"系统调用 + 协议栈 + 拷贝"，
   不含 NIC 中断/NAPI/DMA——所以这里的 recvmmsg p50 ≈ 2.7μs 是内核栈成本的**下界**，
   物理网卡路径只会更高。
4. 各档有 4–160 个样本超出直方图量程（>262μs，桌面调度干扰所致），
   p999 读数偏乐观；p9999 全部超量程，不可引用。

**待复测（升级条件后追加 R2）**

- [ ] 锁频 + isolcpus + 绑核后复测
- [ ] pktgen 或第二台机器硬件发包，把平均批量压到 vlen 的 80% 以上
- [ ] 物理网卡 + 交换机环境跑 DPDK 版（E0），与 R1 相减得"旁路净收益"
- [ ] 样本量 ≥ 100 万，调大 `HIST_TICKS_PER_BUCKET` 覆盖 p9999
