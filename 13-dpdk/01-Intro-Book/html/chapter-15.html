section-2-传统以太网存储瓶颈

现代网络存储（iSCSI、NAS、RESTful、FCoE 等）高度依赖以太网 — 传统 内核路径 开销集中。

一、典型写请求路径（内核态）

应用（用户态）
    ↓ write() / send()
内核 TCP/IP 栈 ──► 网卡（拷贝 ①②：用户↔内核）
    ↓
网络传输
    ↓
内核 TCP/IP 栈 ◄── 网卡（拷贝 ③④）
    ↓
存储驱动（内核）──► 物理盘 / SSD（拷贝 ⑤⑥：用户↔内核）
阶段 问题
网络前端 网卡 → 内核 → 用户态：至少两次拷贝
存储后端 用户态 → 内核存储驱动 → 设备： again 拷贝
合计 一次写请求经历 多次内存拷贝

→ 与 Ch1 旁路动机 · 零拷贝 stub 对照

二、上下文切换

交互 开销
应用 ↔ 网络栈 系统调用、用户态↔内核态切换
应用 ↔ 存储驱动 同上
高 QPS 存储 切换频率 与吞吐成反比

三、内核协议栈锁竞争

内核 TCP/IP 栈中大量 共享数据结构 需锁保护：

层次 典型共享资源
L4 UDP/TCP 控制块、连接表
L3 IP 层、路由表
多核并发 锁争用 → 扩展性急剧下降

→ Ch4 同步互斥 — DPDK/SPDK 用 per-core 无锁 设计规避

四、为何存储比纯转发更痛

纯 L2/L3 转发（DPDK） 网络存储（iSCSI 等）
DPDK 覆盖数据面 还需 可靠 L4（TCP） + 块设备 I/O
单方向拷贝可优化 双向 网络 + 存储 叠加 拷贝与切换

结论： 仅 DPDK 接管网卡不够 — 需 前端用户态 TCP + 后端用户态 NVMe（见 3. 全栈优化）

section-3-全栈用户态优化思路

全栈用户态： 从 网络前端 到 存储后端 消除内核与多余拷贝。

一、总体架构

┌─────────────────────────────────────────────────────────┐
│                    用户态（SPDK 栈）                      │
│  PMD 收包 → 用户态 TCP/IP → iSCSI 解析 → 用户态 NVMe 驱动 │
│       ↑           ↑              ↑              ↑        │
│     DPDK        L4 栈         存储协议        轮询 NVMe   │
└─────────────────────────────────────────────────────────┘
         │                                      │
    物理网卡                               NVMe SSD
    （绕过内核 net stack）                  （绕过内核 block 层）

目标： 网卡到落盘 全程用户空间轮询，逼近 零拷贝。

二、网络前端优化

手段 说明
DPDK PMD 轮询收包 — 无中断、无内核 netdevice
用户态 TCP/IP 绕过内核协议栈 — 无 syscall、无栈内锁
独立内存池 / 队列 per-core 资源 — Ch2 mempool · Ch4 ring

DPDK 边界： 原生 DPDK 处理 OSI L2/L3 — 不含 TCP/UDP；存储场景必须 叠加 L4 用户态栈（见 4. SPDK）。

三、存储后端优化

手段 说明
用户态 NVMe 驱动 直接映射 PCIe BAR、轮询 completion queue
摒弃中断与内核锁 与 PMD 同构 — 绑核 + 无锁 I/O 队列
队列亲和 DPDK 线程与 NVMe I/O Queue Pair 一一绑定

→ Ch6 PCIe 与 DMA — NVMe 同为 PCIe 设备

四、数据流（理想路径）

NIC ──PMD──► mbuf 池 ──► 用户态 TCP ──► iSCSI Target 逻辑
                                              │
                                              ▼
                                         NVMe 提交队列
                                              │
                                              ▼
                                         SSD 落盘
消除项 效果
内核网络拷贝 ↓ 延迟、↑ 吞吐
内核存储拷贝 ↓ CPU 占用
上下文切换 稳态 纯轮询

section-4-SPDK架构与核心组件

SPDK（Storage Performance Development Kit） — Intel 基于 DPDK 框架 的开源存储加速方案，面向 iSCSI 等以太网存储应用。

一、SPDK 在 DPDK 生态中的位置

DPDK（EAL / PMD / mempool / ring / 绑核）
    ↓ 扩展
SPDK（用户态 L4 + NVMe + 存储 Target 应用）
层级 负责方
L2/L3 报文 I/O DPDK
L4 TCP/UDP SPDK 集成的用户态协议栈
块设备 I/O SPDK NVMe 驱动
存储协议 iSCSI Target 等示例应用

二、用户态 TCP/IP 栈

DPDK 不直接支持 TCP — SPDK 需集成 L4 实现。本书重点提及：

栈 要点
Libuns（书中命名） 截获标准 Socket 操作 — 兼容现有应用；网络处理转入用户态；DPDK 队列 + 独立内存池 → 纯轮询、无锁流转
mTCP 高性能用户态 TCP 研究/生产实现
OpenFastPath（OFP） 另一用户态协议栈选项

设计共性： per-core 连接/缓冲、轮询 RX/TX、避免内核锁 — 与 Ch7 poll 模式 一致。

三、用户态 NVMe 驱动

特性 说明
轮询 completion 无中断风暴 — 延迟可预测
无内核锁 每队列独立 — 多核 近线性扩展
线程↔队列绑定 DPDK lcore 与 NVMe QP 亲和
性能 频繁读写下，单核 IOPS 远超内核 NVMe 驱动（书中测试结论）

→ NVMe 命令集走 PCIe — 与 Ch6 网卡 PMD 同属 用户态 PCIe 驱动 范式

四、高性能 iSCSI Target 实例

SPDK 提供 iSCSI Target 参考实现 — 端到端路径：

网卡 (DPDK PMD)
    → 用户态 TCP/IP 栈
    → iSCSI 协议解析（Target）
    → 用户态 NVMe 驱动
    → SSD 落盘

全程： 用户空间、轮询、无内核 block/TCP 路径。

五、与其他用户态栈选型（概念）

需求 倾向
最小改动现有 socket 应用 Libuns 类 socket 截获 方案
全新存储服务 直接链接 SPDK API / mTCP
多协议 NFV 可与 Ch14 OVS 分域 — OVS 管虚拟交换，SPDK 管存储面

section-5-性能量化

本章引用 Intel/SPDK 测试数据 — 具体数值随硬件与版本变化；相对倍数与扩展趋势 具有参考价值。

一、iSCSI 4KB 随机读（单核）

方案 相对性能
内核态 LIO iSCSI（基线） 1×
SPDK iSCSI Target 7×（约 +650%）
观察 含义
同核对比 全栈用户态消除 拷贝 + 切换 + 锁 的收益集中体现
小包随机读 IOPS 敏感场景 — 与 NVMe 队列深度、TCP 栈效率强相关

二、多核扩展性

指标 SPDK 表现
IOPS vs 核数 近乎线性增长
CPU 利用率 同等吞吐下 低于 传统内核方案
时延 显著降低 — 轮询路径无中断/sched 抖动

→ 与 Ch3 并行扩展 · Ch13 闭环调优 方法论一致：绑核 → 测 baseline → 找瓶颈 → 迭代

三、与 Ch14 OVS 倍数对照（量级）

场景 书中倍数 域
OVS PHY-PHY（256B） ~11× 虚拟交换
OVS PHY-VM-PHY 双核 ~13× NFV 互联
SPDK iSCSI 4KB 随机读 ~7× 网络存储

共性： DPDK 系 用户态 + 轮询 + 无锁 在不同垂直领域均带来 数量级 提升 — 非偶然，是架构级差异。

四、调优维度（落地 checklist）

层 项
DPDK 大页、PMD 绑核、NUMA 对齐、mempool 预分配
L4 栈 连接分片、每核 TCP 状态、零拷贝 send/recv
NVMe QP 数量 = 活跃核数、队列深度、PCIe 带宽
应用 iSCSI 会话与核映射、避免跨核共享

section-6-小结与全书收束

一、本章总结

DPDK 理念不限于 CT（通信）— 同样适用于 IT（存储）。

传统内核存储路径 SPDK 用户态路径
多次拷贝（网卡↔内核↔用户↔驱动） 网卡 → 用户态 TCP → NVMe 尽量零拷贝
syscall + 上下文切换 纯轮询 稳态
内核 TCP/block 锁 per-core 无锁队列

SPDK 三板斧：

用户态 TCP/IP（Libuns / mTCP / OFP）
    +
用户态 NVMe 驱动（轮询 QP）
    +
iSCSI Target 等应用（端到端示范）
    ↓
4KB 随机读 iSCSI：~7× vs LIO；多核近线性 IOPS
