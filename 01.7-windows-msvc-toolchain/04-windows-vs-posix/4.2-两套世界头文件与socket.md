# 4.2 头文件与 socket：两套完全不重叠的世界

[← 4.1 MSVC 的 C 标准边界](./4.1-MSVC的C标准边界.md) · 下一节：[4.3 编码行尾与路径 →](./4.3-编码行尾与路径.md)

## 本节讲什么

你在 VS 里 `#include <stdio.h>` 一切正常，但你翻开 TLPI 的示例代码，
第一行 `#include <unistd.h>` 就编译不过。

**这不是你的问题，是两个操作系统各自的 API 世界观不同。**

## 要点

### POSIX 头文件 → Windows 的对应物

| POSIX / Linux 头文件 | 提供什么 | Windows 的对应 |
|---------------------|----------|----------------|
| `<unistd.h>` | `read`/`write`/`fork`/`exec`/`pipe`/`getpid` | ❌ **没有**；散落在 `<io.h>` `<process.h>` `<windows.h>` |
| `<sys/socket.h>` | `socket`/`bind`/`listen`/`accept` | `<winsock2.h>` + `-lws2_32` |
| `<netinet/in.h>` | `sockaddr_in`、`htons` | `<winsock2.h>`（合并提供） |
| `<arpa/inet.h>` | `inet_pton`、`inet_ntop` | `<ws2tcpip.h>` |
| `<fcntl.h>` | `open`、文件状态标志 | `<io.h>`（不同语义），`nonblock` 用 `ioctlsocket` |
| `<sys/stat.h>` | `stat` 结构体 | `<sys/stat.h>` 存在但内容不同 |
| `<pthread.h>` | 线程、互斥、条件变量 | ❌ 没有；`CreateThread` / SRWLOCK / CONDITION_VARIABLE |
| `<sys/mman.h>` | `mmap` | ❌ 没有；`CreateFileMapping` + `MapViewOfFile` |
| `<sys/wait.h>` | `waitpid` | ❌ 没有 `fork` 就没有 `waitpid` |
| `<errno.h>` | `errno` | 存在，但**大多数 Windows API 不设置它**，用 `GetLastError()` |

> 一句话记住：**Windows 上没有 `fork`、`pthread`、`mmap`、`unistd` 这四个东西的任何等价物。**
> 它们是 POSIX 世界观的地基，而 Windows 的地基是 `HANDLE` + `CreateProcess` + `WaitForSingleObject`。

### 三套"句柄"模型，别混着用

这是最要命的一处：

| | POSIX | Windows |
|---|-------|---------|
| 文件 | `int fd`（小整数，0/1/2 是标准流） | `HANDLE`（指针大小的句柄） |
| socket | `int fd`（**和文件同类型**） | `SOCKET`（typedef，**和 HANDLE 也不同**） |
| 能不能用同一个函数读写？ | ✅ `read(fd)` / `write(fd)` 通用 | ❌ 文件用 `ReadFile`，socket 用 `recv`/`send` |

**后果：** 这段 Linux 代码在 Windows 上没有等价写法：

```c
int fd = open("file.txt", O_RDONLY);
read(fd, buf, sizeof buf);          /* Linux: 文件和 socket 都能 read */
```

Winsock 必须用具名函数 `recv()` / `send()`，`read()` 对 socket 是无效的。

### socket 程序的差异（对照一张表）

| 步骤 | POSIX | Windows (Winsock) |
|------|-------|-------------------|
| 初始化 | 不需要 | **必须先 `WSAStartup(MAKEWORD(2,2), &wsaData)`** |
| 头文件 | `<sys/socket.h>` 等 | `<winsock2.h>` (+ `<ws2tcpip.h>`) |
| 链接 | 通常不需要额外库 | `-lws2_32`（VS 里 `#pragma comment(lib, "ws2_32.lib")`） |
| 创建 | `socket(AF_INET, SOCK_STREAM, 0)` | 同（返回值类型是 `SOCKET`） |
| 关闭 | `close(fd)` | **`closesocket(s)`** —— 写 `close(s)` 会出错 |
| 设非阻塞 | `fcntl(fd, F_SETFL, O_NONBLOCK)` | `ioctlsocket(s, FIONBIO, &mode)` |
| 取错误 | `errno` | **`WSAGetLastError()`** |
| 收尾 | 不需要 | `WSACleanup()` |

> **忘了 `WSAStartup` 是 Winsock 新手第一坑**：不调用的话所有 socket 调用都返回
> `WSANOTINITIALISED` (10093)，而且看起来"函数都存在、就是跑不通"。

### 另一个 MSVC 特有现象：`_CRT_SECURE_NO_WARNINGS`

```c
char buf[16];
scanf("%s", buf);          /* MSVC: warning C4996: 'scanf': This function may be unsafe */
```

MSVC 默认会对一批标准 C 函数发 `C4996` 弃用警告（`scanf`/`strcpy`/`sprintf`/`localtime`…），
推荐改成 `scanf_s` / `strcpy_s` 等 **`_s` 后缀的安全版本**。

三种处理方式的取舍：

| 做法 | 适用场景 |
|------|----------|
| `#define _CRT_SECURE_NO_WARNINGS`（在所有 include 之前） | 写**跨平台**代码、或学教材代码时最省事 |
| 改用 `scanf_s` 等 | 只写 Windows 且希望保留安全增强 |
| `/D_CRT_SECURE_NO_WARNINGS`（命令行 / CMake） | 整个项目统一关闭，推荐用于 CI |

> ⚠️ **`_s` 系列不是标准 C 的一部分**（它们源自 C11 Annex K，但 glibc 基本没实现）。
> 用了 `scanf_s` 你的代码就再也无法在 Linux 上编译。**跨平台代码不要碰 `_s`。**
