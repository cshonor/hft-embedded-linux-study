## 5.4 消除循环的低效率

> **Ch5 §5.4** · [章导读](../README.md) · 上节 [§5.3 ←](./section-5.3-程序示例.md) · 下节 [§5.5 →](./section-5.5-减少过程调用.md)

---

**典型杀手：循环内重复计算**

```c
// 慢：每次迭代 strlen
for (i = 0; i < strlen(s); i++) ...

// 快：不变量外提
int len = strlen(s);
for (i = 0; i < len; i++) ...
```

- **归纳变量优化** — 编译器常做，但依赖 `-O` 与可见性
- HFT：循环边界、buffer 长度 **在循环外算好**；tick 处理别每包 `vector.size()` 若可缓存

---

### 常见陷阱

1. **循环内重复调用函数求边界** — `for (i=0; i<strlen(s); i++)` 每轮都调 `strlen`（O(n) 扫描），整体变成 O(n²)。提取到循环外 `int len = strlen(s);`。
2. **以为编译器一定会做不变量外提** — 如果函数有副作用或指针别名，编译器不敢假设返回值不变。HFT 中 `vector.size()` 虽然通常可内联，但跨编译单元/虚函数不一定。
3. **循环内构造/析构** — C++ 中循环内创建临时对象（如字符串拼接），每次迭代都分配/释放。移到循环外复用。

### 自测题

<details>
<summary>1. for (i=0; i<strlen(s); i++) 有什么性能问题？</summary>

`strlen(s)` 是 O(n) 扫描，在循环条件里每轮都调用，整体变成 **O(n²)**。提取到循环外 `int len = strlen(s); for (i=0; i<len; i++)` 降为 O(n)。这叫**循环不变量外提**。
</details>

<details>
<summary>2. 编译器会自动做不变量外提吗？什么情况不会？</summary>

如果函数是**纯函数**（无副作用）且编译器能确认返回值不变，`-O2` 以上通常能自动外提。但如果函数有副作用、有指针别名、或跨编译单元无 LTO，编译器不敢假设返回值不变，**不会外提**。
</details>

<details>
<summary>3. HFT 热循环中还有哪些类似的「隐式重复计算」？</summary>

- `vector.size()` 跨编译单元可能不内联
- 循环内反复解引用结构体指针求字段（如 `order->price.level`）
- 循环内构造临时字符串/对象
- 循环内调用 `log()` / `printf()` 等 IO 函数
</details>
