大白话 · 本章一条线

CPU 不只会顺序执行你的 main — 中断、缺页、syscall、信号都会「插队」改控制流。

用户态程序
  → syscall / 异常 → 内核态处理 → 返回用户态
  → 信号异步到达 → 信号处理函数 → 返回被打断点
  → fork 复制地址空间 → 父子并发

HFT 三件事：

  1. 热路径少 syscall、少信号 — 收包用 DPDK/ busy poll；别在 tick 里 fork
  2. 懂上下文切换代价 — 绑核、少跨进程；线程优于多进程共享内存（→ Ch 12）
  3. 优雅停机 — SIGTERM/SIGINT 处理、子进程回收、EINTR 重试

8.1

section-8.1-异常

8.1.1 异常处理

  • 异常 (exception) — 控制流突变，由 事件 触发，经 异常表 跳内核处理程序
  • 处理完 返回 到被中断指令（故障）或下一条（陷阱）或终止进程

8.1.2 异常的类别

类 同步/异步 返回行为 例子
中断 (interrupt) 异步 下一条 定时器、网卡、磁盘 I/O 完成
陷阱 (trap) 同步 下一条 syscall、int
故障 (fault) 同步 可能重试 同一条 缺页、保护违例
终止 (abort) 同步 不返回 硬件错误

8.1.3 Linux/x86-64 中的异常

  • 除零、段错误、页错误 (#PF) — 熟悉名字即可
  • 系统调用 — syscall 指令 → 陷阱进内核

HFT：

  • 高频收包 — 硬中断 + NAPI + softirq（→ 09 内核网络）
  • 缺页 on tick — 灾难；mlock、预 fault（→ Ch 9）
  • perf 可看 page-faults、context-switches

→ Ch 1.7 进程/OS

自测题

1. 异常的四种类别是什么？各自的返回行为？
类 同步/异步 返回
中断 异步 下一条指令
陷阱 同步 下一条指令
故障 同步 可能重试同一条
终止 同步 不返回

中断是异步的（外部硬件触发），其余三种是同步的（指令执行触发）。系统调用 = 陷阱，缺页 = 故障。

2. HFT 场景中，缺页发生在 tick 处理时为什么是灾难？如何避免？

缺页触发异常 → 内核介入 → 磁盘 I/O（如果页在 swap）或至少分配物理页 → 延迟数十微秒到毫秒级，远超 HFT 的微秒级预算。避免手段：mlockall(MCL_CURRENT|MCL_FUTURE) 锁定所有页、预 fault（启动时 touch 所有热内存）、禁用 swap、大页（hugepage 减少 TLB miss）。

8.2

section-8.2-进程

8.2.1 逻辑控制流

  • 每个进程 独立逻辑控制流 — 仿佛独占 CPU（时间片轮转 / 多核并行）

8.2.2 并发流

  • 多进程 并发 — 交错执行；需 同步 共享资源（文件、锁、IPC）

8.2.3 私有地址空间

  • 每进程 独立虚拟地址空间 — 代码、数据、堆、栈、映射区（→ Ch 9）

8.2.4 用户模式与内核模式

模式 权限
用户态 受限指令；通过 syscall 请求内核
内核态 全硬件访问
  • 环保护 — 防止应用直接碰设备/MMIO

8.2.5 上下文切换

进程上下文： PC、寄存器、VM 状态、打开文件表等

运行进程 A → 定时器中断 → 内核调度 → 换到进程 B
  • 代价： 刷新 TLB、cache 冷、微秒级 — HFT 热路径 避免频繁切换

HFT 模型：

模式 典型
单进程多线程 行情+策略+发单共享地址空间、无锁队列
多进程 隔离（风控、网关、监控）；IPC 有成本
绑核 isolcpus 减少无关进程与中断抢核（→ 14-HFT）

自测题

1. 进程的两个关键抽象是什么？

1. 逻辑控制流：每个程序好像独占 CPU（通过时间片轮转+上下文切换实现）。2. 私有地址空间：每个进程好像独占内存（通过虚拟内存+页表实现）。这两个抽象让程序之间互不干扰。

2. 上下文切换的开销有哪些？HFT 如何减少？

开销包括：保存/恢复寄存器、切换页表（TLB flush）、cache 污染（新进程的冷 cache）、分支预测器重置。HFT 减少手段：CPU 绑定（sched_setaffinity）避免迁移、独占核（isolcpus）、轮询模式避免睡眠/唤醒切换、SCHED_FIFO 实时调度减少抢占。

8.3

section-8.3-系统调用错误处理

  • 大多数 syscall 包装函数 失败时返回 -1，错误码在 errno
  • 必须检查返回值；perror / strerror 打印
if ((fd = open(path, O_RDONLY)) < 0) {
    perror("open");
    exit(1);
}

EINTR — HFT 网络代码常见

慢 syscall（read/write/accept）可能被 信号打断，返回 -1 且 errno == EINTR：

ssize_t n;
do {
    n = read(fd, buf, len);
} while (n < 0 && errno == EINTR);
  • 非阻塞 + epoll 路径 EINTR 仍会出现 — 重试或交给事件循环

包装习惯： 本书 unix_error / app_error 宏 — 生产用统一日志 + 指标。

自测题

1. 为什么系统调用要检查返回值？CSAPP 的包装函数做了什么？

系统调用可能失败（返回 -1，设 errno），不检查会导致静默错误——程序继续跑但行为错误。CSAPP 包装函数（如 unix_error）在系统调用返回 -1 时打印错误信息并 exit(1)，确保错误不被忽略。HFT 注意：生产系统不能直接 exit，需要更精细的错误恢复策略。

2. errno 是什么？它是线程安全的吗？

errno 是一个全局变量（实为线程局部存储 TLS），记录最近一次系统调用的错误码。是线程安全的——每个线程有自己的 errno 副本。但如果同一线程连续调用多个系统调用而不检查 errno，后者会覆盖前者的值。

8.4

section-8.4-进程控制

8.4.1 获取进程 ID

pid_t getpid(void);   // 本进程
pid_t getppid(void);  // 父进程

8.4.2 创建和终止进程

pid_t fork(void);     // 子进程返回 0，父返回子 pid
void exit(int status);
  • fork — 写时复制 (COW) 复制地址空间；子继承 fd 表副本
  • exit — 内核记录 退出状态，进程变 僵尸 直到被回收

8.4.3 回收子进程

pid_t wait(int *status);
pid_t waitpid(pid_t pid, int *status, int options);
  • 僵尸 (zombie) — 已 exit 但未 wait；占 pid 不释放
  • 孤儿 — 父先死，由 init/systemd 收养并回收
  • SIGCHLD — 子状态变化时通知父（常配合非阻塞 waitpid）

8.4.4 让进程休眠

unsigned sleep(unsigned seconds);
int pause(void);           // 直到信号
int sigsuspend(...);       // 原子地阻塞并等待

8.4.5–8.4.6 加载运行：execve 与 shell 模式

int execve(const char *path, char *const argv[], char *const envp[]);
  • 替换 当前进程映像；不创建新进程 — 成功则不返回
  • 典型：fork + execve — shell 启动命令
if ((pid = fork()) == 0) {
    execve("/bin/ls", argv, envp);
    _exit(1);
}
waitpid(pid, NULL, 0);

HFT：

  • 不在 tick 路径 fork/exec — 毫秒级、cache 冷、不可控
  • 用于 守护进程化、子进程跑脚本、隔离工具；主引擎 长期运行单进程
  • 理解 execve → 与 Ch 7 加载 衔接

自测题

1. fork() 之后父子进程的关系？哪些是共享的哪些是复制的？

fork 后子进程获得父进程的副本（地址空间、文件描述符表、信号处理函数）。但用的是 COW（Copy-On-Write）——只复制页表不复制物理页，首次写才分配新页。文件描述符表是复制的（共享 offset），但引用计数 +1。父子进程各自返回——子进程返回 0，父进程返回子进程 PID。

2. execve() 做了什么？它和 fork() 的关系？

execve 在当前进程的上下文中加载并运行一个新程序——替换代码段、数据段、堆、栈，但保留 PID、打开的文件描述符（除非设了 FD_CLOEXEC）。典型模式：fork() 创建子进程 → execve() 替换为新程序。fork 负责复制，execve 负责替换，两者组合实现「启动新程序」。

3. waitpid() 的作用是什么？为什么需要它？

waitpid 让父进程等待子进程结束并回收其资源（避免僵尸进程）。子进程结束后如果父进程没调用 wait，子进程变成僵尸进程（Z 状态）——PCB 仍占用，直到父进程 wait 或父进程退出被 init 接管。

8.5

section-8.5-信号

8.5.1 信号术语

  • 信号 — 软件层 异步 ECF；通知进程「某事件发生了」
  • 每种信号有 默认动作：终止、停止、忽略、转储 core

常见：

信号 默认 HFT 用途
SIGINT 终止 Ctrl+C，开发调试
SIGTERM 终止 优雅停机
SIGKILL 终止 强杀，不可捕获
SIGCHLD 忽略 子进程退出
SIGPIPE 终止 写断开的 socket
SIGUSR1/2 终止 自定义（reload 配置等）

8.5.2 发送信号

kill(pid, SIGTERM);
raise(SIGINT);
alarm(seconds);  // SIGALRM
  • Shell Ctrl+C → 内核发 SIGINT 给前台进程组

8.5.3 接收信号

  • 内核把信号标为 待处理 (pending)；到达时 强制跳转 到处理函数或默认动作
  • signal() 过时；用 sigaction 指定 handler、标志

8.5.4 阻塞和解除阻塞

  • 信号掩码 — sigprocmask 阻塞某类信号；阻塞期间 pending，解除后交付
  • sigpending 查询待处理信号

8.5.5 编写信号处理程序

规则（异步信号安全）：

  • 只能调 async-signal-safe 函数（见 man 7 signal）
  • 禁止： printf, malloc, pthread_mutex_lock（非安全列表很长）
  • handler 里宜 置 volatile sig_atomic_t 标志，主循环处理
volatile sig_atomic_t stop = 0;
void handler(int sig) { stop = 1; }

struct sigaction sa = { .sa_handler = handler, .sa_flags = SA_RESTART };
sigemptyset(&sa.sa_mask);
sigaction(SIGTERM, &sa, NULL);

8.5.6 同步流避免并发错误

  • 信号可在 任意指令间 插入 — 与主程序 真并发，共享全局变量需 sig_atomic_t 或阻塞信号 保护
  • 经典 bug：handler 与 main 同时改链表

8.5.7 显式等待信号

sigsuspend(&mask);   // 原子等待
sigwait(&set, &sig); // 专用线程等信号 — HFT 更干净

HFT 实践：

  • 热路径无 signal handler — 用 专用线程 sigwait 处理 SIGTERM 触发 orderly shutdown
  • SA_RESTART — 自动重启被中断的 syscall；或自己处理 EINTR
  • 生产：SIGTERM 停收新单、flush 日志、join 线程，再 exit

自测题

1. 信号是同步的还是异步的？接收信号时会发生什么？

信号是异步的——可以在进程执行的任何时刻到达。内核在从内核态返回用户态前检查 pending 信号，如果有就修改栈帧让返回后跳转到信号处理函数。处理完通过 sigreturn 恢复原始执行流。

2. 信号处理函数中哪些函数是安全使用的？为什么不能在信号处理函数中调用 malloc？

只有异步信号安全（async-signal-safe）的函数可用（如 write, _exit, read）。malloc 不安全因为它操作全局堆数据结构，如果信号打断主线程正在 malloc 的代码，会导致堆损坏。HFT 实践：信号处理函数只设 flag（volatile sig_atomic_t），主循环检查 flag 处理。

3. HFT 系统中 SIGALRM 和 timer 有什么关系？

SIGALRM 由 alarm()/setitimer() 定时触发，可用于心跳检测或超时控制。但 HFT 通常不用信号做定时（信号处理有延迟且不可预测），而是用 clock_gettime(CLOCK_MONOTONIC) 主动轮询时间，或用 timerfd_create 把定时器变成 fd 用 epoll 统一管理。

section-8.6-非本地跳转

#include <setjmp.h>
jmp_buf env;
if (setjmp(env) == 0) {
    // 正常路径
} else {
    // longjmp(env, 1) 跳回此处
}
longjmp(env, 1);
  • 不还原栈展开 — 与 C++ 异常、RAII 不兼容；跳过析构
  • 用途：深层错误快速回退（老代码）；现代 C++ 用 异常 或 Result 类型

HFT： 新代码 避免 setjmp；协程/状态机用显式枚举更清晰。

自测题

1. setjmp/longjmp 的作用是什么？它和 goto 有什么区别？

setjmp 保存当前寄存器/栈上下文到一个 jmp_buf，longjmp 恢复该上下文——实现跨函数跳转。和 goto 的区别：goto 只能函数内跳转，longjmp 可以跨多层函数调用栈「弹回」。常用于错误恢复（如深层解析失败直接跳回主循环）。

2. longjmp 后局部变量的值是否可靠？

不可靠。setjmp 之后、longjmp 之前被修改的非 volatile 局部变量，在 longjmp 后的值是未定义的（编译器可能把变量优化到寄存器，longjmp 恢复的是旧寄存器值）。解决：对需要在 longjmp 后保留的局部变量加 volatile。

自测题

1. Linux 中查看和管理进程的常用工具有哪些？

ps（快照）、top/htop（实时）、pgrep/pkill（按名查找/杀）、strace（追踪系统调用）、lsof（查看打开的文件/fd）、/proc/<pid>/（进程信息伪文件系统，可看 maps/status/fd 等）。HFT 调试常用 perf stat 看硬件计数器、/proc/<pid>/status 看内存和切换次数。

2. /proc//maps 能看到什么？HFT 调试中有什么用？

显示进程的虚拟地址空间映射——每段的地址范围、权限(rwxp)、映射文件(如 .so)、offset。HFT 调试中用于：确认 hugepage 是否生效、检查是否有意外的内存映射、排查段错误地址落在哪个映射区。/proc/<pid>/smaps 还提供每段的 RSS/PSS 等详细内存统计。

自测题

1. 异常控制流的三种形式是什么？各自的作用？

1. 异常/中断：硬件级控制流突变（缺页、系统调用、定时器中断）。2. 进程上下文切换：OS 调度器在不同进程间切换（时间片、阻塞、优先级）。3. 信号：软件级异步通知（kill、SIGALRM、SIGSEGV）。三者层层递进：硬件异常是基础，进程切换管理多任务，信号提供进程间异步通信。

2. HFT 系统中如何最小化异常控制流的影响？
  1. 避免缺页：mlockall + 预 fault + hugepage
  2. 减少上下文切换：CPU 绑定 + 独占核 + 轮询模式
  3. 避免信号：用 timerfd 替代 SIGALRM，信号处理只设 flag
  4. 减少系统调用：批量处理、用户态网卡（DPDK）
  5. SCHED_FIFO 实时调度：减少被抢占的概率
