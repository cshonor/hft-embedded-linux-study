## 2. 三种内存地址与 MMU

> 80x86 上必须区分三种地址；MMU 分两阶段完成翻译

---

### 一、三种地址

| 类型 | 英文 | 是什么 |
|------|------|--------|
| **逻辑地址** | Logical address | 机器指令里的地址；**段 + 偏移量** |
| **线性地址** | Linear / Virtual address | 32 位无符号整数；可寻址 **4 GB** 空间 |
| **物理地址** | Physical address | 内存芯片上的真实地址；送到**内存总线**的电信号 |

---

### 二、MMU 翻译流水线

```
逻辑地址
  ↓ 分段单元（Segmentation）
线性地址
  ↓ 分页单元（Paging）
物理地址
```

- **分段单元：** 查 GDT/LDT 中的段描述符 + 偏移 → 线性地址  
- **分页单元：** 查页目录/页表 → 物理地址；非法访问 → **缺页异常（Page Fault）**

→ 分段详 [section-3](./section-3-分段机制.md) · 分页详 [section-4](./section-4-硬件分页.md)

### 常见陷阱

1. 把「逻辑地址」和「虚拟地址」混为一谈——逻辑地址是段机制时代的概念（段选择符:偏移），虚拟地址是分段后的线性地址
2. 以为 `__pa()` 宏在所有架构上都一样——x86 上是简单的减去 `PAGE_OFFSET`，ARM64 上可能需要查表
3. 在内核模块中直接用物理地址——内核 API 用的是虚拟地址（`__va()`/`__pa()` 转换），直接操作物理地址会 panic

<details>
<summary>自测题（点击展开）</summary>

**Q1.** 逻辑地址、线性地址（虚拟地址）、物理地址三者的转换链路是什么？

<details><summary>答案</summary>

逻辑地址 →（分段）→ 线性地址/虚拟地址 →（分页）→ 物理地址。在 x86-64 flat model 下，逻辑地址 == 线性地址（段 base=0），所以实际只有一级转换：虚拟地址 →（页表）→ 物理地址。

</details>

**Q2.** `__pa(x)` 和 `virt_to_phys(x)` 有什么区别？

<details><summary>答案</summary>

`__pa()` 是 x86 架构特定的宏，直接做算术减法（`x - PAGE_OFFSET`）。`virt_to_phys()` 是通用 API，内部调用架构相关的实现。在驱动代码中应始终用 `virt_to_phys()` 而非 `__pa()`，保证可移植性。

</details>

**Q3.** 为什么 HFT 代码要避免在热路径上做 `virt_to_phys()` 转换？

<details><summary>答案</summary>

`virt_to_phys()` 本身开销很小（算术运算），但它暗示你在用直接映射区（direct map）的地址。如果涉及 vmalloc 区或模块区地址，转换需要查页表，开销大。更重要的是，频繁的地址转换说明代码在设计上没有区分好物理连续和虚拟连续的内存使用。

</details>

</details>
