# 5.6 IP 数据报的主机处理

## 本节核心目标

掌握 **强/弱主机模型**（RFC 1122）对多网卡/VPN/环回收发的影响，以及 IPv6 **源/目的地址选择**（RFC 6724）的优先级规则与开发绑定要点。

<a id="ch05-6-strong-weak"></a>

## 一、强主机 vs 弱主机模型（RFC 1122，IPv4/IPv6 通用）

**核心差异**：接收/发送是否**绑定接口** — 直接决定多网卡、VPN、环回场景的包收发规则。

### 1. 强主机模型（Strong Host）

| 规则 | 说明 |
|------|------|
| **接收** | 仅当 **目的 IP = 接收接口的地址** 时，才接收该包 |
| **发送** | 仅当 **源 IP = 出站接口的地址** 时，才允许从该接口发包 |
| **特点** | 接口隔离、**安全性高**；多网卡/VPN 需严格匹配接口与 IP |
| **典型系统** | **Windows Vista+**、**Linux**、**所有 IPv6 栈默认** |

### 2. 弱主机模型（Weak Host）

| 规则 | 说明 |
|------|------|
| **接收** | 只要 **目的 IP 属于本机任一接口**，无论从哪个接口收到都接收 |
| **发送** | 源 IP 可与出站接口 IP 不同，仅需 **属于本机** |
| **特点** | **连通性好**、配置简单；易受**多宿主欺骗**（外网口收到内网目的 IP 的包） |
| **典型系统** | **Windows XP**、**Windows Server 2003**（IPv4 默认） |

### 3. 对比表（必考）

| 维度 | 强主机 | 弱主机 |
|------|--------|--------|
| **接收条件** | 目的 IP = **接收接口** IP | 目的 IP ∈ **本机所有**接口 IP |
| **发送条件** | 源 IP = **出站接口** IP | 源 IP ∈ 本机所有接口 IP |
| **安全性** | **高**（接口隔离） | **低**（易被欺骗） |
| **连通性** | 一般（需匹配接口） | **好**（跨接口通） |
| **默认系统** | Win7+ / Linux / **IPv6** | Win XP/2003（IPv4） |

### 4. 场景影响（多网卡 / VPN / 环回）

| 场景 | 强主机 | 弱主机 |
|------|--------|--------|
| **多网卡** | eth0 的 IP 包**只能从 eth0 收** | 可从**任意**接口收 |
| **VPN** | 须 VPN 接口 IP **匹配**目的 IP 才收 | 可能导致**流量泄露**到错误接口 |
| **环回** | 通常仅 **lo** 收 `127.0.0.1` | 物理接口也可能收（异常路径） |

## 二、IPv6 地址选择（RFC 6724）

IPv6 主机常有多地址（全球 / ULA / 链路本地）、多前缀；**出站**时内核自动选**源 IP + 目的 IP**。开发跨接口服务需**显式绑定**或策略路由。

### 1. 核心目标

- 多地址/多前缀下选**最优源/目的 IP**（范围、隐私、前缀匹配）
- 避免内核自动选错源（如用**链路本地**访问全球网络）

### 2. 源地址选择规则（按优先级，必考）

| # | 规则 |
|---|------|
| 1 | **同地址优先**：候选源 IP = 目的 IP → 直接选中 |
| 2 | **匹配范围**：源 IP 范围 ≥ 目的 IP 范围（链路本地→全球，**不能跨范围**） |
| 3 | **避免废弃地址**：优先首选生命周期 > 0；不选 **Deprecated** |
| 4 | **移动 IPv6 主地址**：优先 Home Address（固定网络几乎不用） |
| 5 | **优先出站接口**：优先**路由选出站接口**上的地址 |
| 6 | **匹配标签**：源/目的 **addrlabel** 一致（策略路由常用） |
| 7 | **优先临时地址**：优先 RFC 4941 **隐私临时地址**（防溯源） |
| 8 | **最长前缀匹配**：与目的 IP **前缀匹配最长**的源 IP |

### 3. 目的地址选择（RFC 6724 补充）

优先：**可用 + 匹配范围 + 非废弃 + 本地前缀 + 原生 IPv6**；避免 **6to4 / Teredo** 等隧道地址（若存在更优候选）。

## 三、开发 / 运维要点（Go / Rust / 跨接口服务）

| 要点 | 做法 |
|------|------|
| **多接口必显式绑定** | Go：`net.Dialer.LocalAddr`；Rust：`SocketAddr` 指定源 IP/接口 |
| **策略路由兜底** | 多 VPN/多专线：`ip rule` / `iptables` 锁定出站接口 |
| **IPv4 收紧入站** | Win：`netsh interface ipv4 set interface …`；Linux：`rp_filter`、相关 `sysctl`（与接口绑定策略配合） |

→ 发送路径排障：`ip route get <dst>` · `ip -6 route get <dst>`

## 四、考点速记

| # | 要点 |
|---|------|
| 1 | **强主机**：接口绑定收发，**安全**；**弱主机**：本机全局收发，**连通性好** |
| 2 | **IPv6 默认强主机**；RFC **6724** 定义 **8 条**源地址选择规则 |
| 3 | 多网卡/VPN：**强主机**须 **接口–IP 严格匹配**，否则**丢包** |
| 4 | 跨接口服务：**必须显式**指定源 IP / 出站接口 |

| 易错 | 正确 |
|------|------|
| Linux 默认弱主机 | **Linux / Win7+ / IPv6 默认强主机** |
| 多地址 IPv6 内核总选对 | 须理解 **RFC 6724** 或 **bind** |
| 弱主机更安全 | **强主机**更安全；弱主机易**跨接口欺骗** |

---

## Go / Rust

- **Go**：`net.InterfaceAddrs()` 列接口；`Dialer{LocalAddr: &net.TCPAddr{IP: src}}` 绑源  
- **Rust**：`socket2` / `std::net` + `bind` 到具体 `SocketAddr`；容器多网卡注意 **policy routing**  
- **实践**：`ip route get` 验证内核选的源与出接口是否与预期一致

---

## 疑问与总结

**背：强=接口绑定（默认现代栈）；弱=本机任一接口；IPv6 出站看 RFC 6724 八条 + 开发必 bind。**
