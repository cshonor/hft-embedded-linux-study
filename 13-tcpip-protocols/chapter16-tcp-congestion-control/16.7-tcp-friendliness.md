# 16.7 TCP 友好性

> 章级精读：[../study.md#ch16-5](../study.md#ch16-5)

## 本节核心目标

理解非 TCP 流量为何需要自律，以及"TCP 友好"的含义。

---

## 问题

非 TCP（如 UDP 视频流、实时流）若不降速 → **饿死** TCP 流（TCP 丢包就减半，UDP 不减）。

---

## TCP 友好定义

非 TCP 流量的长期吞吐**不超过**同条件下 TCP 流的吞吐。即模拟 **AIMD** 自律。

```
UDP 流量: 监测丢包 → 主动降速（类似 TCP AIMD）
→ 与 TCP 公平共享带宽
```

---

## 实践

| 协议 | 友好策略 |
|------|---------|
| **RTP/RTCP** | 基于 RTCP 反馈调整编码速率 |
| **WebRTC** | GCC (Google Congestion Control) |
| **QUIC** | 内置拥塞控制（CUBIC 或 BBR） |

---

## HFT 关联

HFT UDP 组播行情**不做 TCP 友好**——行情必须以最低延迟送达，不能因网络拥塞而降速。但应通过 QoS/DSCP 标记和专用带宽隔离，避免影响其他流量。
