# 16.3 对标准算法的改进

> 章级精读：[../study.md#ch16-3](../study.md#ch16-3)

## 本节核心目标

了解 NewReno、SACK+CC、FACK、Limited Transmit、CWV 等改进。

---

## NewReno

**问题**：Reno 在多包同窗丢失时可能多次减半。

**解决**：用**部分 ACK（Partial ACK）**在快速恢复中连续补洞，不退出直到所有丢失段确认。

```
Reno: 丢3个包 → 3次快速恢复 → cwnd 减半3次 = 1/8
NewReno: 丢3个包 → 1次快速恢复 → cwnd 减半1次 = 1/2
```

---

## SACK + 拥塞控制

**Scoreboard** 精确定位空洞 → 少无效重传 → 丢包期维持较高有效利用率。

---

## FACK (Forward ACK)

用 SACK 信息更激进推断丢包 → 更快调整 cwnd。

---

## Rate Halving

拥塞后**每 2 ACK 发 1 新包** → 平滑替代 Reno 瞬时 cwnd 跳变。

---

## Limited Transmit

窗口小、dup ACK **1–2 个**时允许**发 1 新段** → 凑够 3 dup ACK → 触发快速重传 → **避免 RTO**。

---

## CWV (Congestion Window Validation)

长闲置连接 **缩小陈旧 cwnd**，避免闲置后突发冲击。

```bash
# Linux: 闲置后 cwnd 验证
sysctl net.ipv4.tcp_slow_start_after_idle  # 默认 1
# 设为 0 可禁用闲置后慢启动（HFT 可能需要）
```

---

## HFT 关联

| 改进 | HFT 价值 |
|------|---------|
| NewReno | 多包丢失恢复更好 |
| SACK | 高 BDP 链路必备 |
| Limited Transmit | 小窗口场景避免 RTO |
| CWV | 预热连接后保持 cwnd |
