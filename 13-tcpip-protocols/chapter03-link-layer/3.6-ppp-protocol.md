# 3.6 点到点协议（PPP）与 HDLC 对照

> 章级精读：[../study.md#ch03-6](../study.md#ch03-6) · [§3.8 MTU](./3.8-mtu.md) · [ch06 PPPoE](../chapter06-dhcp-config/study.md)

## 本节核心目标

分清 **HDLC / PPP** 定位与对比；掌握 **LCP + 认证 + NCP** 建立顺序；理解 **PPP 未废止** 与 **PPPoE** 为何仍主流。

---

<a id="ch03-6-ppp-alive"></a>

## 一、PPP 没有被「废掉」

| 说法 | 事实 |
|------|------|
| 老式 **电话线 + Modem 拨号** | 基本淘汰 ✓ |
| **PPP 协议本身** | **仍在大量使用** ✗ 没废止 |

**仍在用的场景**

- 家庭/小区 **PPPoE**（网线/光猫拨号，底层仍是 PPP）
- **4G/5G**、物联网拨号、运营商专线、部分 **VPN**
- **跨厂商**路由器串口互联（兼容性优于 HDLC）

> **一句**：PPP 告别了老式电话线，**换了封装（如 PPPoE）继续当广域网点到点主力**。

<a id="ch03-6-hdlc"></a>

## 二、HDLC（高级数据链路控制）

### 1）是什么

**ISO** 制定的**面向比特**链路层协议；早期标准**点到点/点到多点**；常用于**广域网串行链路**（运营商专线、路由器串口）。

### 2）核心特点

| 点 | 说明 |
|----|------|
| **面向比特** | 按**二进制比特**处理，不是按字节拆 |
| 拓扑 | 全双工；标准版**无丰富寻址**（默认两端直连） |
| 定界 | 标志位 **`01111110`（0x7E）**；**比特填充（bit stuffing）** 避免数据和标志冲突 |
| 版本 | **标准 HDLC**：无多协议、**无认证** · **思科私有 HDLC**：可载多协议，思科串口**默认** |

### 3）优缺点与现状

| ✅ | ❌ |
|----|-----|
| 结构简单、开销小、效率高 | **通用性差**（厂商版常不互通） |
| 链路层可带**序号/确认/流控** | **无认证、无 IP 自动协商** |

**现在**：多见于**同厂商路由器串行专线**、电信 **SDH/E1、帧中继**；民用几乎见不到。

### HDLC 帧（复习）

```text
| Flag 0x7E | Address | Control | Info | FCS | Flag |
```

**Control**：**I 帧**（带序号/确认）· **S 帧** · **U 帧**。

<a id="ch03-6-ppp"></a>

## 三、PPP（点到点协议）

### 1）定位

**IETF** · **面向字节** · 点到点 · **全双工**；专门补强 HDLC：**跨厂商兼容、认证、灵活协商、多网络层协议**（IP、历史 IPX 等）。

### 2）三大组件（必考：LCP + 认证 + NCP）

| 组件 | 干什么 | 大白话 |
|------|--------|--------|
| **LCP** 链路控制 | 建立/配置/检测/拆除链路 | **先把「路」修好、规则定好**（MRU、是否认证、压缩等） |
| **认证** | PAP / CHAP | **验身份**，防非法接入（LCP 协商开启后） |
| **NCP** 网络控制 | 各层参数；**IPCP** 最常见 | **路通且验完身份 → 分 IP、DNS** |

**认证对比**

| | **PAP** | **CHAP** |
|---|---------|----------|
| 密码 | **明文** | **挑战-响应**，不传明文 |
| 安全 | 低 | **高**，工业主流 |

**NCP 举例**：**IPCP** 为双方协商 **IP、DNS**（宽带拨号拿地址就是它）。

### 3）建立顺序（固定背）

```text
物理链路 up
  → ① LCP 协商链路参数
  → ② PAP/CHAP 认证（若开启）
  → ③ NCP/IPCP 协商网络层（分配 IP）
  → ④ 传业务数据
  → ⑤ LCP 拆除链路
```

### 4）PPP 帧格式（基于 HDLC 改造）

```text
| Flag 0x7E | Addr 0xFF | Ctrl 0x03 | Protocol 2B | Info | FCS 2B | Flag 0x7E |
```

| 字段 | 说明 |
|------|------|
| **Protocol** | PPP **特有**；如 **`0x0021` = IPv4**、LCP、IPCP |
| **Addr/Ctrl** | 固定 **FF / 03**（点到点无多站） |

**要 MAC 吗？** **不需要**。

### 5）PPP 特点（考点）

| ✅ | ❌ |
|----|-----|
| 异步 + 同步；**跨厂商通用** | **无链路层序号/确认**（可靠靠 **TCP 等上层**） |
| PAP/CHAP、IPCP、链路检测 | |
| 可扩展 → **PPPoE** | |

<a id="ch03-6-compare"></a>

## 四、HDLC vs PPP（背诵表）

| 对比项 | **HDLC** | **PPP** |
|--------|----------|---------|
| 处理方式 | **面向比特** | **面向字节** |
| 制定 | **ISO**（电信） | **IETF**（互联网） |
| 兼容性 | 差（厂商私有版常不互通） | **极强**，各厂商通用 |
| 认证 | **无** | **PAP / CHAP** |
| 核心组件 | 无 LCP/NCP 分层 | **LCP + 认证 + NCP** |
| 多协议 | 标准版不支持 | **Protocol 字段** 支持多上层 |
| 链路可靠 | **有**（序号/确认） | **无**（靠上层） |
| 典型场景 | 同厂商串行专线、SDH/E1 | **PPPoE 宽带**、移动网、**跨厂商 WAN** |

**关系**：PPP 帧**脱胎 HDLC** — 简化 Addr/Ctrl，**增加 2B Protocol**。

## 五、PPPoE（现在 PPP 为啥还常见）

家用宽带多是**网线 + 光猫**，不是电话线直连 → **PPPoE**：

> **在以太网帧里封装 PPP**

| 表象 | 底层 |
|------|------|
| 路由器/电脑**拨号**、输账号密码 | 仍是 **LCP → CHAP 认证 → IPCP 分 IP** |

→ 运营商接入：[ch06](../chapter06-dhcp-config/study.md) · **MTU/MRU**：[3.8](./3.8-mtu.md)

## 六、极简背诵 + 易错

### 四句话专抄

1. **HDLC**：面向**比特**，老式串口/专线，**无认证**，同厂商多。  
2. **PPP**：面向**字节**，**LCP + 认证 + NCP**，跨厂商通用。  
3. PPP **没废止**：Modem 少了，**PPPoE/移动网/跨厂商 WAN** 仍主流。  
4. 顺序：**LCP → 认证 → NCP(分IP) → 数据**。

### 帧口诀

```text
PPP：  7E FF 03 [协议2B] 数据 FCS 7E     0x0021 = IPv4
HDLC： 7E 地址 控制 数据 FCS 7E         控制里带序号/ACK
```

### 易错 5 条

| # | 陷阱 | 正解 |
|---|------|------|
| 1 | PPP 有链路层重传 | **无**；靠 IP/TCP |
| 2 | HDLC 能自动拿 IP | **不能**；无 NCP |
| 3 | PAP 比 CHAP 安全 | **CHAP** |
| 4 | PPP 需要 MAC | **不需要** |
| 5 | PPP 已废止 | **否**；**PPPoE 等仍大量用** |

### 与全书衔接

- **MTU**：LCP 协商 MRU → [3.8](./3.8-mtu.md)  
- **TCP 可靠**：补 PPP 链路无确认 → [ch12 TCP](../chapter12-tcp-basic/study.md)
