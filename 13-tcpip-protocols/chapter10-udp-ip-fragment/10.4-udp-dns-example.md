# 10.4 UDP DNS 抓包示例

> 章级精读：[../study.md#ch10-3](../study.md#ch10-3) · DNS 协议：[ch11](../../chapter11-dns-domain-resolve/study.md)

## 本节核心目标

通过 DNS 查询的 UDP 报文实例，理解 UDP 在真实流量中的行为。

---

## 典型 DNS 查询流程

```text
Client (192.168.1.100:54321) → DNS Server (8.8.8.8:53)

1. UDP Datagram: src=54321 dst=53
   Payload: DNS Query (~30 bytes)
   UDP Length = 8 + 30 = 38

2. Server → Client: UDP Response
   Payload: DNS Response (A record, ~50 bytes)
   UDP Length = 8 + 50 = 58
```

**特点**：一问一答、短报文、无连接、UDP 校验和覆盖。

---

## Wireshark 分析

```

  Source Port: 54321
  Destination Port: 53
  Length: 40

```

**过滤器**：`udp.port == 53 && dns.qry.name == "example.com"`

---

## 为什么 DNS 用 UDP 而非 TCP

| 因素 | UDP | TCP |
|------|-----|-----|
| 延迟 | 1 RTT（查询+响应） | 3 RTT（握手 + 查询 + 响应） |
| 状态 | 无 | 需维护连接 |
| 开销 | 8B 头 | 20B+ 头 + 选项 |
| 缺点 | 大响应被截断（TC=1） | 大响应完整但更慢 |

当 DNS 响应 > 512B（无 EDNS0）或区域传输时，自动切换到 TCP/53。

---

## 代码示例

```python
# Python: 发送 DNS 查询并观察 UDP 行为
import socket

sock = socket.socket(socket.AF_INET, socket.SOCK_DGRAM)
sock.settimeout(2)
sock.sendto(b'\x12\x34\x01\x00\x00\x01\x00\x00\x00\x00\x00\x00\x07example\x03com\x00\x00\x01\x00\x01',
            ('8.8.8.8', 53))
data, addr = sock.recvfrom(512)
print(f"Response from {addr}, {len(data)} bytes")
# UDP 保留报文边界：一次 recvfrom = 一个完整 DNS 响应
```

## HFT 关联

HFT 系统中 DNS 解析应**最小化**：
- 预解析对端 IP，启动时缓存
- 用 `connect()` 固定 UDP 五元组，避免每次 `sendto` 的路由查找
- 行情/交易服务器 IP 几乎不变，DNS 不是热路径
