## DHCP 是什么（通俗速记）

**DHCP**（Dynamic Host Configuration Protocol，**动态主机配置协议**）核心：**自动给内网设备分配 IP 地址**。

### 主要功能

| # | 功能 | 说明 |
|---|------|------|
| 1 | **自动分配 IP** | 手机、电脑等开机后，**不用手动填** IP、子网掩码、网关、DNS — DHCP 服务器自动下发 |
| 2 | **地址租期管理** | IP **不是永久占用**；到期**续租**，避免多台设备 IP 冲突 |
| 3 | **统一下发网络参数** | 顺带配置 **网关、DNS 服务器** — 设备拿到参数即可上网 |

### 常见场景

家里/公司的 **路由器** 默认开启 DHCP，所有连 **Wi‑Fi、插网线** 的设备都靠它分配地址。

**一句总结**：**帮你自动配上网地址，省去手动设置网络的麻烦。**

## 一、为什么不能一直手动配？

手动填写 **IP、子网掩码、默认网关、DNS** 的问题：

| 问题 | 说明 |
|------|------|
| **规模化** | 易出错、难维护、管理成本高 |
| **移动化** | 手机/笔记本频繁换网，**无法静态写死** |
| **用户能力** | 企业/家庭设备多，用户无专业知识 |

**一句话**：**规模化 + 移动化 → 手动配置不可扩展**。

<a id="ch06-1-pnp"></a>

## 二、目标：即插即用（Plug-and-Play）

设备接入网线/Wi‑Fi 后，**自动获得**：

- 地址（IPv4 / IPv6）
- **网关、DNS、NTP** 等

无需人工干预 — **开机就能上网**。

---

<a id="ch06-1-bootstrap"></a>

## 三、协议栈自举顺序（关键逻辑）

网络启动是**分层递进**的：

```mermaid
flowchart LR
  L2[L2 链路接通] --> L3[L3 参数自动获取]
  L3 --> DNS[DNS 解析]
  DNS --> APP[应用层业务]
```

1. **L2 链路接通**（以太网 / Wi‑Fi 连接建立）
2. **L3 参数自动获取**：**DHCP（IPv4）** / **SLAAC + DHCPv6（IPv6）** → 地址、网关、DNS
3. **DNS → 应用**：解析域名，开始上网/业务

> 没有 L3 自动配置，上层 TCP/UDP/应用都是「无源之水」。

## 四、本章两条主线

### 1）DHCP（IPv4 主流，有状态）

| 项 | 说明 |
|----|------|
| **机制** | 服务器集中管理地址池，分配 **IP + 掩码 + 网关 + DNS + 租期** 等 |
| **特点** | 服务器**记录绑定状态**（**有状态**） |
| **场景** | 企业内网、家庭路由器、运营商宽带、IPv4 全网标准 |

→ 详：[6.2 DHCP 协议](6.2-dhcp-protocol.md)

### 2）SLAAC / APIPA（无服务器自动配置）

| 机制 | 说明 | 场景 |
|------|------|------|
| **APIPA（IPv4 备用）** | DHCP 失败时自动生成 **169.254.0.0/16** 链路本地地址；仅内网互通，**不能跨路由** | Windows 等「自动专用 IP」 |
| **SLAAC（IPv6 原生，无状态）** | 路由器发 **RA（路由通告）** 给前缀；主机用「前缀 + 接口 ID」拼地址；**无需 DHCP 服务器**，路由器不记录谁用了哪个地址 | IPv6 零配置、智能家居、物联网 |

→ 详：[6.3 SLAAC](6.3-slaac-autoconfig.md)

<a id="ch06-1-compare"></a>

## 五、DHCP vs SLAAC（一句话）

| | **DHCP（有状态）** | **SLAAC（无状态）** |
|--|-------------------|---------------------|
| 谁给地址 | **服务器分配** + 全套参数 | 设备**自己生成**；路由器只给**前缀** |
| 适合 | 集中管理、需审计的网络 | **零配置、高扩展** |
| 典型 | IPv4 主流 | **IPv6 标配** |
