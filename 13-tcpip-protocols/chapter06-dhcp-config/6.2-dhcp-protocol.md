## 一、历史与传输载体

### 1. 协议演进

| | **BOOTP** | **DHCP** |
|---|-----------|----------|
| 关系 | 引导程序协议（RFC 951） | **BOOTP 的增强扩展** |
| 报文 | 二者格式**向下兼容** | 在 BOOTP 基础上增加**选项**与租期 |
| 分配 | **静态**绑定 IP（表项预配置） | **动态**从地址池分配 + **租期管理** |
| 回收 | 无租期，地址长期占用 | 到期释放 → **地址循环复用** |

**一句**：BOOTP =「发一张固定票」；DHCP =「租一张可续期的票」。

→ 演进链：[6.1 引言](6.1-introduction.md) · RARP/BOOTP/DHCP

### 2. 传输层与端口（IPv4）

基于 **UDP**（应用层协议，却在**网络层初始化**阶段起决定性作用）：

| 角色 | 端口 |
|------|------|
| **DHCP 客户端** | **68** |
| **DHCP 服务器** | **67** |

### 3. 收发方式

| 阶段 | 方式 | 原因 |
|------|------|------|
| **初期（Discover/Request 等）** | **广播** | 客户端**尚无 IP**（`0.0.0.0`），无法单播 |
| **续租 Renew（T1）** | 通常 **单播** 原服务器 | 已有 IP，已知服务器地址 |
| **重绑定 Rebind（T2）** | **广播** | 原服务器无响应，向**任意**可用服务器求助 |

→ 跨网段：**DHCP Relay** 把广播转为单播，`giaddr` 标识中继 → [study §6.2.5 中继](./study.md#ch06-2-ext)

## 二、地址池与租期 (Lease)

### 1. 地址池

DHCP 服务器预先维护一段**空闲 IP 范围（地址池 / scope）**；客户端申请时，服务器从池中选取**未占用**地址分配。

| 概念 | 说明 |
|------|------|
| **地址池** | 可分配网段，如 `192.168.1.100–200` |
| **保留/静态绑定** | 按 MAC/`client-id` 固定映射（仍走 DHCP 流程，但总是同一 IP） |

### 2. 租期机制（核心三时间点）

分配的 IP **并非永久**；附带有效租期 **T**。

| 定时器 | 时机 | 行为 | 俗称 |
|--------|------|------|------|
| **T1** | **≈ 0.5T**（50%） | 客户端向**原分配 DHCP 服务器****单播**续租（Renew） | **续租** |
| **T2** | **≈ 0.875T**（87.5%） | T1 失败 → 向**全网任意 DHCP 服务器****广播**续租（Rebind） | **重绑定** |
| **到期** | **T** | 客户端**停用**当前 IP，释放；地址**回归地址池** | — |

```text
0 ─────── T1(50%) ─────── T2(87.5%) ─────── T(100%)
         续租原服务器      广播找任意服务器      释放，重新 DORA
```

**续租失败后果**：T1、T2 均失败 → 租期到期 → 停用 IP → **重新发起 DORA** 申请新地址。

**通俗**：IP 像**短租公寓** — 过半先找原房东续；房东不在就满世界问；到期搬出，房间给别人。

<a id="ch06-2-dora"></a>

## 三、IPv4 经典 DORA 四步交互

客户端从零获取 **IP、掩码、网关、DNS、租期** 等参数的完整流程；**初始阶段全程广播**。

| 步骤 | 报文 | 行为与含义 |
|------|------|------------|
| **1** | **DISCOVER**（发现） | 客户端**广播**：「谁是 DHCP 服务器？」（源 IP **`0.0.0.0`**） |
| **2** | **OFFER**（提供） | 服务器从地址池**预留** IP，**广播/单播**回复地址及配置参数（可能多台同时 Offer） |
| **3** | **REQUEST**（请求） | 客户端**选定一台**，**广播** Request：「我要这个 IP，其他服务器请释放」 |
| **4** | **ACK**（确认） | 被选服务器**最终确认**，下发完整参数（IP、掩码、网关、DNS、租期 T 等） |

**补充**：服务器拒绝分配 → **NAK**（Not Acknowledged）。

### 二层 / 三层（抓包对照）

| 步骤 | L3 IP（典型） | L2 目的 MAC |
|------|---------------|-------------|
| **Discover** | `0.0.0.0 → 255.255.255.255` | **广播** `FF:FF:…` |
| **Offer** | Server → `255.255.255.255` 或单播 | 广播或客户端 MAC |
| **Request** | `0.0.0.0 → 255.255.255.255` | **广播** |
| **ACK** | Server → 广播或单播 | 客户端 MAC |

**Request 为何也广播？** 让网内**所有**曾 Offer 的服务器知道客户端**选了谁**，释放未中标地址，避免池被占死。

→ 消息格式（BOOTP 兼容）：[study §6.2.2](./study.md#ch06-2-msg) · 常用 Option：[study §6.2.3](./study.md#ch06-2-options)

## 四、DHCPv6 核心要点

IPv6 地址配置方式与 IPv4 **差异大**；DHCPv6 定位需与 **SLAAC** 对照。

### 1. 地址分配方式区分

| 方式 | 机制 | 是否需要 DHCPv6 |
|------|------|-------------------|
| **SLAAC**（无状态自动配置） | 路由器 **RA** 报文 → 主机自动生成地址 | **否**（仅地址）→ [6.3](6.3-slaac-autoconfig.md) |
| **DHCPv6 有状态** | 服务器**统一分配** IPv6 地址 + DNS 等 | **是** |
| **DHCPv6 无状态** | **不分配地址**（SLAAC 已有），只下发 **DNS/域名** 等选项 | **部分**（Information-Request） |

### 2. 客户端标识 DUID

| | **IPv4 DHCP** | **DHCPv6** |
|---|---------------|------------|
| 客户端标识 | 硬件地址 **`chaddr`**（网卡 MAC） | **DUID**（DHCP Unique Identifier） |
| 特点 | 换网卡可能变 | **永久稳定**，不受网卡/地址变化影响 |

### 3. 端口与交互名称

| 项 | 值 |
|----|-----|
| 客户端端口 | **546** |
| 服务器端口 | **547** |
| 四步（类比 DORA） | **Solicit → Advertise → Request → Reply** |
| 寻址 | 少用广播；常用**组播** `ff02::1:2`（All_DHCP_Relay_Agents_and_Servers） |

## 六、易混考点

| 易混 | 正确 |
|------|------|
| DHCP 是网络层协议 | **UDP 应用层**，但在**获取 IP 之前**运行 |
| 初期为何必须广播 | 客户端**无 IP**（`0.0.0.0`），无法单播寻址 |
| BOOTP vs DHCP | BOOTP **静态**、无租期；DHCP **动态池 + 租期 + 选项** |
| T1 vs T2 | T1 → **原服务器**单播；T2 → **任意服务器**广播 |
| 续租失败 | 到期释放 IP → **重新 DORA** |
| v6 只靠 DHCPv6 | 常见 **SLAAC + RA**；DHCPv6 可有状态或**仅下发 DNS** |
| v4 标识 vs v6 | **chaddr (MAC)** vs **DUID** |

| # | 考点速记 |
|---|----------|
| 1 | **UDP 67/68**；DORA；**T1≈50% / T2≈87.5%** |
| 2 | Request **广播** = 通知未选中服务器释放 Offer |
| 3 | **DHCPv6：546/547**；**DUID**；Solicit/Advertise/Request/Reply |
| 4 | **SLAAC 无状态** vs **DHCPv6 有状态** → [6.3](6.3-slaac-autoconfig.md) |
