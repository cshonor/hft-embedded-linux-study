## 1. 体系结构原则：设计初衷与权衡

### 战略意义

体系结构原则是理解 TCP/IP 演进的**罗盘**。目标不是单一维度性能最优，而是在**生存性、灵活性、经济性**之间找最大公约数——这使互联网在硬件更迭与流量激增时仍具极强适应力。

### Clark 的分层目标体系（1988）

| 层级 | 目标 |
|------|------|
| **首要** | 发展一种**重复利用已有互联网络**的高效技术 |
| **二级（7 项）** | 见下表 |

| # | 二级目标 | 要点 |
|---|----------|------|
| 1 | **生存性** | 网络/网关失效时通信仍可持续 → **命运共享** |
| 2 | 多样性 | 多种通信服务 |
| 3 | 兼容性 | 多种物理网络（**IP-on-everything**） |
| 4 | 分布式管理 | 非集中式资源管理 |
| 5 | 成本效率 | 经济可行 |
| 6 | 易接入性 | 主机接入门槛低 |
| 7 | 可审计性 | 资源使用可核算 |

### 核心设计哲学

**命运共享（Fate Sharing）** — 本章技术灵魂

- 连接**状态**（TCP 序号、窗口等）保存在**通信端点**，而非中间网络节点。
- 只要两端存活，路径因故障切换，连接仍可延续。
- 与电路交换「网络智能化、中间存状态」思路相反 → **极高鲁棒性**。

**端到端论点（End-to-End Argument）** — 「智能端点，哑网络」

- 差错控制、加密等**核心功能在端点**实现。
- 网络层**极简**：尽力而为（Best-effort）转发。
- 直接促成互联网**爆炸式扩展**；现代 TLS/DNSSEC 仍在此原则下于高层补安全。

### 分组交换 vs 电路交换

互联网选**分组交换**；电路交换 / X.25 依赖 **LCI** 在交换机维护虚电路状态。

| 维度 | 分组交换 | 电路交换 |
|------|----------|----------|
| 资源利用率 | 高：统计复用 | 低：专用路径空闲也占带宽 |
| 延迟预测 | 不确定（排队/拥塞） | 极佳、恒定 |
| 可靠性 | 强：动态路由、无状态转发 | 弱：路径单点故障即断 |
| 成本 | 低：核心设备简单 | 高：维护海量连接状态 |

### 消息边界三种场景（图 1-1）

| 场景 | 发送 | 接收 | 典型 |
|------|------|------|------|
| **保留边界** | 3 次 write（W1,W2,W3） | 3 次 read 还原 3 条消息 | **UDP** |
| **不保留（合并）** | 3 次小写 | 1 次读得全部 | TCP 字节流 |
| **不保留（拆分）** | 3 次写 | 6+ 次读才收齐 | TCP + MTU/缓冲限制 |

**架构师点评**：**TCP = 字节流**，应用层须用**长度字段/协议帧**解决粘包、分帧。→ 精读 [§3.3 UDP 报文边界](../../top_down/03_transport_layer/study.md#ch3-3-features)

## 2. 分层架构与协议封装

### 战略意义

分层 = **逻辑解耦**：下层物理从以太网→光纤，上层从 HTTP/1→HTTP/3，中间 **IP** 保持稳定（**沙漏模型**）。

### OSI vs TCP/IP

| | OSI 7 层 | TCP/IP |
|--|----------|--------|
| 特点 | 理论完整，会话/表示层常并入应用 | **实用主义**，强调实现效率 |
| 边界 | 层界绝对 | 层界可淡化 |

### 封装（Encapsulation，图 1-3）

```text
应用层：     原始数据
    ↓ +TCP/UDP 首部
传输层：     段 Segment / 用户数据报 Datagram
    ↓ +IP 首部（可能因 MTU 触发 IP 分片）
网络层：     分组 Packet / 数据报 Datagram
    ↓ +以太网首部 + CRC 尾部
链路层：     帧 Frame
    ↓
物理层：     比特流
```

### 分用（Demultiplexing，图 1-6）

> 核心一句话：**每层只负责自己的寻址/类型，各司其职，互不替代** — 以太网、IP 都有「类型」字段，**用途完全不一样**。

#### 1）以太网帧：**EtherType**（二层）

只判断**载荷属于哪一种网络层（三层）协议**；二层**不关心**里面是 ICMP、TCP 还是 UDP。

| 值 | 三层协议 |
|----|----------|
| **0x0800** | **IPv4** |
| **0x86DD** | **IPv6** |
| **0x0806** | **ARP** |

| 项 | 说明 |
|----|------|
| **位置** | 以太网头部 **第 13、14 字节**（源/目的 MAC 之后） |

→ 精读：[ch03 §3.2 EtherType](../chapter03-link-layer/3.2-ethernet-ieee802-encapsulation.md#ch03-2-frame)

#### 2）IP 首部：**Protocol**（三层）

判断 **IP 载荷里是什么**：

| 值 | 载荷 | 所属层次 |
|----|------|----------|
| **1** | **ICMP** | **网络层**（附属） |
| **6** | **TCP** | 传输层 |
| **17** | **UDP** | 传输层 |

| 项 | 说明 |
|----|------|
| **位置** | IPv4 头部 **第 9 字节**（TTL 之后）；IPv6 为 **Next Header** |

→ 精读：[ch05 §5.2 Protocol](../chapter05-ip-protocol/5.2-ipv4-header.md#ch05-2-protocol)

**口诀**：**二层定三层，三层定内层（ICMP / TCP / UDP）**

#### 3）为什么两层都要有？

TCP/IP **每层独立封装/解封装，只识别紧邻上层**。

**收包（自底向上）**：

```text
网卡 → 读 EtherType → 是 IPv4 → 剥以太网头 → 交给网络层
网络层 → 读 Protocol → 是 TCP → 剥 IP 头 → 交给传输层
网络层 → 读 Protocol → 是 ICMP(1) → 交给 ICMP 模块（仍属网络层逻辑）
```

| 字段 | 路标 | 只区分 |
|------|------|--------|
| **EtherType** | **二层 → 三层** | IPv4 / IPv6 / ARP 等 |
| **IP Protocol** | **三层 → 上层** | ICMP、TCP、UDP 等 |

**不能互相省略** — 快递类比：

- **外箱标签（EtherType）**：箱子里是「文件袋」（IP 包）
- **文件袋标签（Protocol）**：袋子里是「信件」（TCP）、「便签」（UDP）或「回执单」（ICMP）

外箱管外层分类，内袋管内层分类，**缺一不可**。

<a id="ch01-layering-icmp"></a>

#### 3.1）特例：ICMP 仍是网络层，却靠 Protocol 识别

ICMP **本身就是网络层协议**，但标准设计里**必须封装在 IP 里传输**，所以：

- **不会**写到以太网 EtherType 里  
- 依然靠 IP 的 **Protocol = 1** 识别  

**完整封装 + 识别链路（ICMP 举例）**：

```text
以太网头 (EtherType=0x0800) + IP 头 (Protocol=1) + ICMP 数据
        ↓                           ↓
  二层判定：里面是 IPv4        三层判定：里面是 ICMP
```

→ [ch08 ICMP 引言](../chapter08-icmpv4-icmpv6/8.1-introduction.md#ch08-1-demux)

#### 4）运输层再分用

| 层级 | 查什么 | 示例 |
|------|--------|------|
| 链路层 | **EtherType** | 0x0800 → IPv4；0x86DD → IPv6 |
| 网络层 | **Protocol / Next Header** | 1 ICMP，**6 TCP**，**17 UDP** |
| 运输层 | **目的端口号** | 交给对应进程 |

**补充**：早期以太网曾用**长度字段**（&lt; 1536）区分 802.3 + LLC/SNAP；现代以太网 II 以 **EtherType ≥ 0x0600** 为主 → [ch03 §类型 vs 长度](../chapter03-link-layer/study.md#ch03-2)。这也是**协议分层解耦**：二层不关心 TCP/UDP，三层不关心以太网细节。

→ 精读 [§3.2 多路复用/分用](../../top_down/03_transport_layer/study.md#ch3-2)

### 协议栈路径（图 1-4）

| 设备 | 数据上至 |
|------|----------|
| **多宿主主机** | 物理 → 链路 → 网络 → 运输 → **应用** |
| **路由器** | 上至**网络层**查目的 IP、转发表，再下行链路/物理发往下一跳 |

**易混**：**路由器 = L3**；**交换机/桥接器 = L2**。

## 3. TCP/IP 协议族成员

### 沙漏核心

- **网际层**：**IP（IPv4/IPv6）** 为核心；**ICMP** 差错；**IGMP/MLD** 组播成员。
- **运输层**：
  - **TCP**：面向连接、可靠、**字节流**、拥塞控制。
  - **UDP**：无连接、不可靠、**消息/报文**、最轻量。
  - **SCTP**：多宿主、多流（电信信令等）。
  - **DCCP**：不可靠数据报 + 类 TCP 拥塞控制。

### 端口号

- **16 bit**；早期 **NCP** 单工 → 奇偶端口对（历史遗迹）。
- **0–1023**：熟知端口（特权进程）。
- **1024–49151**：注册端口。
- **49152–65535**：临时端口（客户端动态分配）。

→ 与 [§3.2 端口划分](../../top_down/03_transport_layer/study.md#ch3-2-ports) 一致

**DNS**：分布式「黄页」，主机名 → 可路由 IP（非必然 1:1，负载均衡/反向代理）。

## 7. 本章考点汇总

| 考点 | 内容 |
|------|------|
| **分用标识符** | **二层定三层，三层定内层** — EtherType → Protocol → Port |
| **端到端 vs 命运共享** | 前者定**功能放哪**；后者定**状态存哪** |
| **封装顺序** | 应用 → 段/报 → IP 分组 → 以太网帧 |

### 易混淆陷阱（5 条）

1. **路由器 vs 交换机**：路由器 **L3**；交换机/桥 **L2**。
2. **TCP 字节流**：不保证应用 write 次数 = 对端 read 次数。
3. **MTU 与分片**：帧受链路 **MTU** 限制；IP 超长且未设 **DF** 时 **IP 分片**（TCP 应用应控制 **MSS** 避免）。
4. **UDP 可靠性**：UDP 本身不可靠；可靠可由应用或 **QUIC** 实现。
5. **DNS 映射**：主机名与 IP **非 1:1**（负载均衡 1:N、反向代理 N:1）。
