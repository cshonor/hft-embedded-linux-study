## ① 可移植 OS 与 Linux 移植史

| 路线 | 说明 |
|------|------|
| **折中** | 核心接口尽量 **架构无关 C** |
| 性能路径 | **`arch/`** 下 **高度优化** 甚至 **汇编** |

| 历史 | 始于 **i386** → **Alpha、MIPS、SPARC、ARM、PowerPC…**（20+ 架构） |

```
通用内核代码（mm/ fs/ net/…）
        │
        ▼
arch/arm64/  arch/x86/  …  — 启动、页表、原子、屏障实现
```

→ **Ch 2** `arch/` 目录 · **Ch 12** per-arch 页大小

**HFT 对照：** 用户态协议解码（行情二进制）同样 **显式字节序、固定宽度类型** — 与内核规则同构。

<summary>自测题（点击展开）</summary>

**Q1.** Linux 能移植到不同架构的关键设计是什么？

<details><summary>答案</summary>

1) arch/ 目录隔离架构相关代码（中断入口/页表/原子操作/字节序）；2) 可移植类型（u32/s64 不依赖 int/long 大小）；3) 宏抽象（__raw_readl → 各架构实现）；4) 构建系统按架构选择正确代码。用户态代码移植性靠 ABI 兼容层；内核移植性靠 arch/ 层。HFT 代码从 x86 迁到 ARM64 需要关注字节序/对齐/cache line 大小差异。
