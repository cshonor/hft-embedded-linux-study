section-1.1-Unix-的历史

事实 说明
起源 1969 · 贝尔实验室 · Dennis Ritchie、Ken Thompson
成功因素 见下表
Unix 优势 含义
设计简洁 仅 ~几百个系统调用 — 接口少而稳

自测题（点击展开）

Q1. Unix 只有几百个系统调用，这为什么对 HFT 有利？

答案

系统调用少意味着 syscall 入口审计面小、热路径可预测。HFT 网关热路径只用 read/write/mmap/send 等十几个 syscall，减少调度器与 VFS 层分支。少而稳的接口 = 内核版本升级时 ABI 兼容性好。

Q2. Unix「一切皆文件」设计哲学对现代网络编程有什么局限？

答案

一切皆文件让 socket/fd 统一接口，但网络包仍需从内核拷贝到用户态（除非用 zero-copy）。HFT 用 AF_XDP/DPDK 绕过 VFS 直接从网卡取包，就是因为「文件抽象」对纳秒级延迟仍有开销。

section-1.2-Linux-的诞生

项 内容
时间 1991 · 赫尔辛基大学 · Linus Torvalds
动机 当时 缺乏强大且免费的 Unix
性质 非商业 · 互联网协作 开发
许可证 GNU GPL 2.0 — 自由 / 开源软件

与 HFT 实盘： 生产内核多为 发行版稳定内核 + 厂商补丁 — 理解 GPL 与源码可得 有助于合规使用 定制内核/驱动。

自测题（点击展开）

Q1. Linux 采用 GPL v2 许可证，这对商用 HFT 公司有什么影响？

答案

GPL v2 要求修改后的内核代码必须开源。HFT 公司的定制内核调度器/网卡驱动如果分发给客户就需要开源；但只在内部使用不分发则不触发 GPL 义务。许多 HFT 公司选择只在内部维护定制内核。

Q2. Linus 为什么选择宏内核而非微内核？

答案

宏内核性能好：syscall 不需要跨进程消息传递，直接函数调用。微内核的理论优势（模块化、隔离）在实践中被 Linux 的动态模块加载（insmod/rmmod）和命名空间部分弥补。Linus 务实优先于理论纯粹性。

自测题（点击展开）

Q1. 内核态和用户态切换的代价是什么？HFT 如何减少这种切换？

答案

一次 syscall 需要：保存用户态寄存器 → 切换栈 → 进入内核态执行 → 恢复寄存器返回。x86_64 约 100-200ns。HFT 减少 syscall 的方法：批量 IO（io_uring）、内存映射（mmap 替代 read）、绑定 CPU 避免调度、busy-polling 替代中断等待。

Q2. 内核有哪些基本职责？为什么 HFT 工程师必须理解它们？

答案

内核管理 CPU 调度、内存分配、文件系统、网络协议栈、设备驱动、安全隔离。HFT 的每纳秒延迟都与这些子系统相关：调度器决定你的线程何时运行、内存分配器决定 TLB miss 率、网络栈决定包处理路径。不理解内核就无法做极限优化。

section-1.4-Linux-与经典-Unix-内核对比

两派设计

类型 特点
宏内核（Monolithic） 单地址空间 内核态 · 性能好
微内核（Microkernel） 服务拆进程 · 消息传递 · 更模块化、理论更「干净」

Linux = 宏内核 — 但 务实借鉴微内核优点：

Linux 特性 说明
可加载内核模块 动态扩展驱动/功能
内核线程 内核态执行后台工作
内核抢占（preemption） 低延迟调度 · 减少「内核跑太久」
SMP 对称多处理器
线程 ≈ 进程 clone() — 统一任务模型

HFT： 绑核、PREEMPT_RT、模块调优网卡驱动 — 都站在「宏内核 + 可抢占 + 模块」这条线上。

自测题（点击展开）

Q1. 宏内核和微内核在 syscall 性能上的根本区别是什么？

答案

宏内核：syscall 是同一地址空间内的函数调用，无上下文切换开销。微内核：syscall 需要通过 IPC 消息传递给服务进程，至少两次上下文切换 + 数据拷贝。这就是 Linux 选择宏内核的核心原因。

Q2. Linux 虽然是宏内核，但借鉴了微内核的哪些优点？

答案

动态加载模块（可卸载驱动/文件系统，类似微内核的服务进程）、命名空间/容器（进程隔离）、eBPF（安全沙箱内运行内核代码）。但核心子系统（调度/内存/VFS）仍在内核态，不是微内核。

section-1.5-Linux-内核版本

类型 说明
稳定版（Stable） 生产可用
开发版（Development） 新特性实验

传统版本号（如 2.6.30.1）：

段 含义（经典规则）
次版本号 第二位 偶数 → 稳定 · 奇数 → 开发

注：现行主线已长期 3.x / 4.x / 5.x / 6.x，「奇偶」规则 概念仍常考，但以 kernel.org 分支政策 为准。

自测题（点击展开）

Q1. Linux 内核版本号 5.15.0-25-generic 中每段代表什么？

答案

5 = 主版本号（Linus 每次发布递增）；15 = 次版本号（偶数=稳定版，奇数=开发版，但 2.6 后此规则已废弃）；0 = 修订号（bug fix）；25 = 发行版补丁计数；generic = 发行版 flavor。HFT 生产应选 LTS（Long Term Support）版本。

Q2. 为什么 HFT 生产环境通常选择 LTS 内核而非最新版？

答案

LTS 内核有 2-6 年维护周期，bug fix 回溯稳定。最新版可能有性能改进但也引入回归。HFT 需要可预测的行为，LTS + 厂商验证补丁是安全选择。例如 PREEMPT_RT（实时补丁）通常需要 1-2 年才能从 mainline 回归到 LTS。

自测题（点击展开）

Q1. LKML（Linux Kernel Mailing List）在内核开发中扮演什么角色？

答案

LKML 是内核开发的唯一官方论坛。所有补丁必须发到 LKML 接受 review，Linus 和子系统维护者在此决策。HFT 工程师如果发现内核 bug 或需要新特性，正确路径是：读源码确认问题 → 写补丁 → 发 LKML → 回应 review → 通过 maintainer 进入 mainline。

Q2. 为什么「读源码 + 动手改」比只啃概念书更有效？

答案

内核代码是最终的 ground truth。LKD 书基于 2.6 内核，现代 5.x/6.x 已大改（如 CFS→EEVDF 调度器、io_uring、BPF）。只读书会停留在过时认知；读源码能发现实际数据结构和算法，改代码能验证理解是否正确。
