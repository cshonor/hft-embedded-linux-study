# 1.5.1 类的使用与头文件分离

> 第 1 章 · 上一节：[1.5 类简介](./1.5-类简介.md) · 下一节：[1.5.2 链接、编译产物与示例](./1.5.2-链接编译产物与示例.md)

## 本节讲什么

`Sales_item` 的用法，以及类的声明（`.h`）和实现（`.cpp`）为什么要分开写。

## 通俗理解：数据盒子 + 工具包

把 **class** 想成一个定制的「数据盒子 + 工具包」：

| `Sales_item`（书） | 以后 HFT 里的 `Order`（单） |
|--------------------|----------------------------|
| 盒子里：书号、销量、收入 | 盒子里：委托价、数量、订单号 |
| 工具：`isbn()` 取书号 | 工具：`send()` 发单、`cancel()` 撤单 |
| `>>` 读一条销售记录 | 从网关读入一笔委托 |
| `+` 合并两笔销售 | 合并/汇总订单 |

**不用自己拆盒子找数据**——定义好对象后，用 `.` 调方法就行，比零散传一堆参数清晰。

`Sales_item` 是入门的「友好型例子」：先学会**怎么用**盒子，后面章节再学**怎么造**盒子。

## 头文件与实现文件

类不必全写在头文件里。常见做法是分开写：

| 文件 | 放什么 | 作用 |
|------|--------|------|
| **`Sales_item.h`** | 类的**声明**（有哪些方法、长什么样） | 给别人看「怎么调用」 |
| **`Sales_item.cpp`** | 方法的**具体实现**（函数体里怎么写） | 藏实现细节，减少重复编译 |

HFT 项目里常把核心策略实现藏在 `.cpp` 或静态库/动态库里，**对外只暴露头文件接口**——既保护代码，又不影响别人调用。

## 和 C 的区别

C 程序员对 `.h`/`.c` 分工不陌生，但 C++ 的类让分工更彻底：

| 对比点 | C | C++ |
|--------|---|-----|
| 头文件放什么 | 函数声明、`struct` 定义 | 类声明（数据+函数原型） |
| 实现文件放什么 | 函数定义 | 类的成员函数定义（要写 `Class::method`） |
| 数据与函数 | 分离（`struct` 和函数各自声明） | 绑定（都在类里） |
| 访问控制 | 无，谁都能改 `struct` 字段 | `private` 藏起来，只能通过方法改 |

```c
/* C：数据和函数分离 */
/* book.h */
struct Book { char isbn[16]; int sold; };
char* get_isbn(struct Book* b);   /* 函数声明，和 struct 没绑定关系 */

/* book.c */
char* get_isbn(struct Book* b) { return b->isbn; }
```
```cpp
// C++：数据和方法绑定，还能控制访问
// Sales_item.h
class Sales_item {
public:                          // 外部能调的
    std::string isbn() const;
private:                         // 外部碰不到的
    std::string bookNo;
};

// Sales_item.cpp
std::string Sales_item::isbn() const { return bookNo; }  // 要带 Class::
```

**关键：** C++ 的成员函数定义在 `.cpp` 里要写 `Sales_item::isbn()`，这个 `Class::` 前缀告诉编译器"这是类的成员函数"。C 没有这个概念。

## 常见错误

**1. `.cpp` 里忘写 `Class::` 前缀**
```cpp
// Sales_item.cpp
std::string isbn() const { return bookNo; }  // 错：编译器以为是普通函数
```
报错：`bookNo` 未声明。要写成 `std::string Sales_item::isbn() const { ... }`。

**2. 头文件里直接写函数体（可能多重定义）**
```cpp
// Sales_item.h
class Sales_item {
public:
    std::string isbn() const { return bookNo; }  // 类内定义，隐式 inline
};
```
类内直接给函数体是合法的（隐式 `inline`），但如果这个头文件被多个 `.cpp` 包含，每个都生成一份定义——`inline` 函数允许这样。**非 inline 的成员函数定义放头文件会链接报错（重复定义）。** 安全做法：声明放 `.h`，定义放 `.cpp`。

**3. `private` 成员外部直接访问**
```cpp
Sales_item item;
item.bookNo = "123";  // 编译错误：bookNo 是 private
```
`private` 就是"外面碰不到"，只能通过 `public` 方法间接操作。这是 C++ 相对 C 的核心保护机制。

## 自测题

**1（选择）** 成员函数的定义应该放在哪里？
- A. 只能放 `.h`
- B. 只能放 `.cpp`
- C. 声明放 `.h`，定义放 `.cpp`（推荐）；类内定义的隐式 inline 可放 `.h`

**2（踩坑）** 下面代码错在哪？
```cpp
// Sales_item.cpp
std::string isbn() const { return bookNo; }
```

**3（概念）** 为什么 C++ 要分 `public`/`private`？C 的 `struct` 没有这个，会带来什么问题？

<details><summary>参考答案</summary>
1. C。声明（告诉编译器"有这个函数"）放 `.h`，定义（具体实现）放 `.cpp`。类内直接写函数体算隐式 `inline`，也可放 `.h`，但不推荐复杂逻辑这样做。
2. 缺 `Sales_item::` 前缀。编译器会把它当普通自由函数，`bookNo` 就找不到（不在作用域）。正确写法：`std::string Sales_item::isbn() const { return bookNo; }`。
3. `private` 把内部数据藏起来，外部只能通过 `public` 方法操作——这样类的作者能控制"怎么改才安全"（比如 `set_price` 里校验非负）。C 的 `struct` 全公开，任何人都能直接改字段，容易破坏不变式（比如把价格设成负数）。
</details>
