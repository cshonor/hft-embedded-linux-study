# 2.3.1 引用

## 本节讲什么

为什么需要引用、T& 与 const T&。

## 为什么 C++ 还要有引用？

已有指针，再引入引用，是为了解决指针在**业务代码**里的常见痛点。

### 指针的缺点

1. **可为空**（`nullptr`）→ 必须判空，漏了可能崩溃（HFT 里直接宕机）
2. **可随意改指向** → 逻辑容易乱
3. **语法繁琐** → `*p` 解引用、`*`/`&` 混用
4. **可做算术**（`p++`）→ 容易越界

```cpp
int a = 1, b = 2;
int *p = &a;
p = &b;   // 随时换指向
```

### 引用：受约束的「安全版指针」

编译器实现上，引用常类似 **`T* const`**（指向 `T` 的**常量指针**——地址绑死不能改）：

| 特性 | 指针 `int*` | 引用 `int&` |
|------|-------------|-------------|
| 可为空 | ✅ `nullptr` | ❌ 必须绑定对象 |
| 改指向 | ✅ `p = &other` | ❌ 绑定后不能换 |
| 使用语法 | `*p` | 直接当变量用 |
| 指针运算 | ✅ | ❌ |

```cpp
int a = 10;
int &ref = a;
ref = 20;              // 直接改 a，不用 *

// 底层直觉（概念模型，不是你要写的代码）：
// int *const p = &a;  // 地址固定，通过 *p 访问
```

**一句话**：引用 = **受限制、更安全、语法更简洁**的间接访问；日常业务优先引用，底层内存/DPDK 才用裸指针。

### 取舍标准（HFT 编码习惯）

**优先用引用：**

- 函数传参、避免拷贝：`void f(const OrderBook &book);`
- 运算符重载（语法要求）：`operator+`、`operator<<` 等

**必须用指针：**

- 后期要**改变指向**
- 对象**可能不存在**（可选）
- 数组、内核、DPDK 等需要**地址偏移**

## 引用：`T&` 与 `const T&`

### 1. 可变引用（可修改原对象）

```cpp
int a = 10;
int &ref = a;
ref = 20;        // ✅ 通过 ref 修改 a
// a 现在是 20
```

- `int&`：绑定原变量，**可读可写**

### 2. 常量引用（只读）

```cpp
int a = 10;
const int &ref = a;
// ref = 20;     // ❌ 编译错误，不能通过 ref 修改
std::cout << ref; // ✅ 只读
```

- `const int&`：**只能读**，不能通过引用改原对象
- 可绑定到字面量：`const int &r = 42;`（普通 `int&` 不能绑字面量）

### 3. 引用的硬性规则（C++ 独有）

1. **必须初始化**，不能空着
2. **绑定后不能改绑**到其他对象（Rust 的引用可以重新绑定）
3. 不存在「空引用」

### 4. 工程习惯（HFT / 日常 C++）

```cpp
// 传参优先：不拷贝 + 只读
void process(const std::string &s);

// 需要改入参时才用可变引用
void adjust(int &value);
```

| 场景 | 用法 |
|------|------|
| 只读、避免拷贝 | `const T&` |
| 需要修改原对象 | `T&` |
| 可选/可为空 | 用指针或 `std::optional`（指针章节） |

## 和 C 的区别（重点：引用是 C++ 独有）

**C 没有引用**——所有间接访问都靠指针。引用是 C++ 给 C 程序员的"安全糖"：

| 对比点 | C（只有指针） | C++（有引用） |
|--------|--------------|---------------|
| 间接访问 | `void f(int* p)` 调用要 `f(&x)` | `void f(int& r)` 调用直接 `f(x)` |
| 判空 | 必须判 `p != NULL` | 引用不能为空，不用判 |
| 改指向 | `p = &other` 随时改 | 引用绑定后不能换 |
| 解引用 | `*p` | 直接用 `r`，像普通变量 |
| 指针运算 | `p++` 可越界 | 引用没有运算 |

```c
/* C：传参要取地址，函数里要解引用 */
void bump(int *p) { (*p)++; }
int x = 5;
bump(&x);          // 调用方要写 &，容易忘
```
```cpp
// C++：引用让传参像普通变量
void bump(int &r) { r++; }
int x = 5;
bump(x);           // 调用方不用写 &，更自然
```

**给 C 程序员的关键转变：**
1. 函数参数优先用 `const T&`（只读不拷贝），替代 C 的 `const T*`
2. 要修改入参用 `T&`，替代 C 的 `T*`
3. 只有"可选/可为空/要改指向/数组"才用指针
4. C 里 `&x` 是取地址，C++ 里 `int &r = x` 是声明引用——同一个 `&` 符号，**位置决定含义**（声明里 `&` 在类型后=引用，表达式里 `&x`=取地址）

## 常见错误

**1. 引用不初始化**
```cpp
int &ref;   // 编译错误：引用必须初始化
```
引用没有"空状态"，定义时必须绑定。

**2. 引用绑定后试图改绑**
```cpp
int a = 1, b = 2;
int &ref = a;
ref = b;    // 这不是改绑！是把 b 的值赋给 a（a 变成 2）
```
`ref = b` 是赋值，不是重新绑定。引用一旦绑定 `a`，一辈子就是 `a` 的别名。

**3. 局部引用返回悬空**
```cpp
int& bad() {
    int x = 42;
    return x;   // 悬空引用：x 出函数就销毁
}
```
返回引用要确保被引用的对象生命周期够长（如类的成员、静态变量、堆对象）。

## 自测题

**1（选择）** 下面代码执行后 `a` 是多少？
```cpp
int a = 1, b = 2;
int &ref = a;
ref = b;
```
- A. 1
- B. 2
- C. 编译错误

**2（判断）** `const int &r = 42;` 合法，`int &r = 42;` 不合法。

**3（踩坑）** 下面函数有什么问题？
```cpp
int& get_value() {
    int local = 100;
    return local;
}
```

<details><summary>参考答案</summary>
1. B。`ref = b` 是赋值（把 b 的值 2 赋给 ref 引用的 a），不是改绑。引用绑定 a 后不能换，a 变成 2。
2. 对。`const int&` 可绑定到字面量（编译器生成临时量）；`int&` 不能绑字面量（字面量不可寻址、不能改）。这是 `const T&` 能延长临时量生命周期的特殊规则。
3. 悬空引用。`local` 是局部变量，函数返回时销毁，返回的引用指向无效内存。调用者用这个引用是 UB。返回引用要保证对象存活（成员、静态、堆）。
</details>
