# 3.3.6 HFT 实践与示例

## 本节讲什么

`vector` 在 HFT 里的工程习惯、综合示例与本章背诵极简版。

## 工程习惯 checklist

| 项 | 做法 |
|----|------|
| 增元素 | **`push_back` / `emplace_back`**，不用下标「添加」 |
| 下标 | `0 <= i < size()`；**`v[v.size()]` 永远错** |
| 初始化 | `v(n)` 要 n 个槽位；`v{a,b}` 只要列表里那些 |
| 扩容 | 容量可估 → **`reserve(n)`**（见 [3.2.3](../3.2-library-type-string/3.2.3-拼接与内存优化.md)） |
| 元素类型 | 热路径 POD；大对象 `unique_ptr` |
| 验证 | `assert(v.size() == expected)` |

## 和 C 的区别（HFT 工程习惯对照）

C 程序员写 HFT 的"动态数组"工程习惯，迁移到 `vector` 时有几个转变：

| 工程项 | C 习惯 | C++ vector 习惯 |
|--------|--------|------------------|
| 预留容量 | `malloc(N * sizeof(T))` 一次到位 | `v.reserve(N);` 一次到位，size 仍为 0 |
| 追加元素 | `arr[n++] = x;` 自己管 n | `v.push_back(x);` 自动管 size |
| 越界保护 | `assert(i < n);` 自己加 | `v.at(i)` 自动抛异常 |
| 释放 | `free(arr);` 必须记得 | 析构自动 |
| 复用 | 不能复制，得重新 malloc+memcpy | `v2 = v;` 整体拷贝 |
| 大对象数组 | `T**` + 逐个 malloc | `vector<unique_ptr<T>>` |

**给 C 程序员的关键提醒：**
1. **`reserve(n)` 不等于 `v(n)`**——`reserve` 只开容量不开 size（size 还是 0，下标访问仍越界）；`v(n)` 直接开 n 个元素（size=n，值初始化为 0）。HFT 要"先开槽"用 `v(n)`，要"边加边长但避免扩容"用 `reserve`。
2. **`vector` 不能像 C 数组那样"假设连续内存就当 C 数组用"**——技术上 `v.data()` 返回连续指针可以传给 C 接口，但要保证 `vector` 在 C 接口调用期间不被改动（否则扩容让指针失效）。
3. **HFT 热路径常"用 `vector` 持有 + 预分配"**：启动时 `reserve(max_size)`，运行时只 `push_back` 不扩容，等价于 C 的"预 malloc 一大块"。

## 背诵极简版

```
vector=容器/动态数组，≠ host 宿主
v(10) 十个默认值；v{1,2,3} 三个元素；v{10,5} 只有两个！
下标 0..size()-1；v[v.size()] 越界；追加用 push_back
T 可自定义类/指针/嵌套 vector；扩容靠拷贝或移动
浅拷贝类含指针要深拷贝；HFT 热路径 POD + reserve
禁拷贝留移动：=delete 拷贝；或 vector<unique_ptr<T>>
```

## 示例

```cpp
#include <iostream>
#include <vector>

struct MarketData {
    double bid{0}, ask{0};
};

int main() {
    std::vector<int> v(10);           // 10 个 0
    std::vector<int> v_paren(10, 5);  // 10 个 5
    std::vector<int> v_list{1, 2, 3}; // 3 个元素
    // vector<int> trap{10, 5};       // 坑：size=2

    for (int i = 1; i <= 5; ++i)
        v.push_back(i);

    std::vector<MarketData> ticks;
    ticks.push_back({100.5, 100.6});

    std::vector<std::vector<int>> book(5);  // 5 档
    book[0].push_back(100);

    for (std::size_t i = 0; i != v_list.size(); ++i)
        std::cout << v_list[i] << " ";
    std::cout << std::endl;

    // v[10] = 100;  // ❌ 越界

    return 0;
}
```

## 常见错误

### 1. `vector` 当 C 数组用，传 `&v[0]` 给 C 接口后又改了 vector

```cpp
std::vector<int> v = {1, 2, 3};
c_api_process(&v[0], v.size());   // ✅ 暂时安全
v.push_back(4);                    // ❌ 可能扩容，&v[0] 失效
c_api_process(&v[0], v.size());   // 重取没问题，但若 C 接口持有指针就悬垂
```

C 程序员习惯了"数组地址稳定"（`int arr[N]` 地址不变）。`vector` 扩容会**搬家**，地址变。传给 C 接口后，**确保 vector 不被改动**，或每次重取 `v.data()`。

### 2. 拿 `v.data()` 当空 vector 的指针用

```cpp
std::vector<int> v;            // 空
int* p = v.data();             // 可能是 nullptr
c_api_process(p, v.size());    // 若 C 接口不解引用 0 长度的 p，OK；否则崩
```

空 `vector` 的 `data()` 行为：C++11 起保证返回一个**有效但不可解引用**的指针（可能就是 nullptr）。传给 C 接口前先判 `!v.empty()`。

### 3. HFT 热路径忘了 `reserve`，每次 `push_back` 都扩容

```cpp
std::vector<Tick> ticks;
while (running) {
    ticks.push_back(receive_tick());   // 偶尔扩容 → 延迟尖刺
}
```

HFT 对延迟敏感，**一次扩容 = 一次 malloc + memcpy**，可能几十微秒。启动时 `ticks.reserve(估计上限)`，运行时只追加不扩容。C 里相当于"预先 malloc 一大块"。

## 自测题

**1. 选择题**　HFT 热路径上要"预分配 1000 个槽位但 size 仍为 0"，应该用：

- A. `std::vector<int> v(1000);`
- B. `std::vector<int> v; v.reserve(1000);`
- C. `std::vector<int> v{1000};`
- D. `std::vector<int> v; v.resize(1000);`

<details><summary>答案</summary>

**B**。`reserve` 只改容量不改 size。A 和 D 都会让 `size() == 1000`（开 1000 个值为 0 的元素）；C 是列表初始化，得到一个只有 1 个元素（值为 1000）的 vector。要"容量足但不占 size"只有 `reserve`。

</details>

**2. 判断题**　`std::vector<int> v;` 之后，`v.data()` 一定返回非空指针。

<details><summary>答案</summary>

**错**。空 vector 的 `data()` 可能返回 `nullptr`（C++11 起保证返回"有效但不可解引用"的指针，实现上常就是 nullptr）。把空 vector 的 `data()` 传给 C 接口前要判 `!v.empty()`，否则 C 接口解引用 nullptr 会崩。

</details>

**3. 踩坑题**　下面这段代码把 `vector` 传给 C 接口，哪里有问题？

```cpp
std::vector<char> buf;
buf.resize(256);
char* p = buf.data();
c_api_fill(p, 256);
buf.push_back('\0');          // 加结尾符
c_api_print(p);               // 打印填充的内容
```

<details><summary>答案</summary>

**`p` 可能失效**。`push_back('\0')` 若触发扩容，`buf` 搬家，`p` 指向已释放的旧内存。`c_api_print(p)` 是 use-after-free。

**修复**：要么先 `reserve(257)` 保证不扩容，要么 `push_back` 后**重取** `buf.data()`：

```cpp
buf.push_back('\0');
c_api_print(buf.data());   // 重取
```

C 程序员的肌肉记忆是"数组地址不变"，到 `vector` 这要改——**任何可能扩容的操作后，旧指针都失效**。

</details>

**4. 应用题**　设计一个 HFT 行情缓冲：最多缓存 1024 条 tick，循环覆写（环形缓冲）。用 `vector` 怎么写？

<details><summary>答案</summary>

```cpp
struct Tick { double price; int qty; };

class RingBuffer {
    std::vector<Tick> buf_;
    size_t head_ = 0, count_ = 0;
public:
    RingBuffer() : buf_(1024) {}   // 预分配 1024 个槽，size=1024
    void push(const Tick& t) {
        buf_[head_] = t;                       // 覆写
        head_ = (head_ + 1) % 1024;
        if (count_ < 1024) ++count_;
    }
    size_t size() const { return count_; }
    const Tick& at(size_t i) const {
        // i=0 是最新，i=count-1 是最旧
        size_t idx = (head_ - 1 - i + 1024) % 1024;
        return buf_[idx];
    }
};
```

要点：
- `buf_(1024)` 一次分配，运行时**不扩容**，无延迟尖刺
- 下标覆写，等价于 C 的 `Tick buf[1024];`，但自带 RAII 和边界检查（用 `at` 时）
- C 程序员会写 `Tick buf[1024];`，`vector` 版本等价但更安全

</details>
