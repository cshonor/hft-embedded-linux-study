# 3.5.5 易错点与示例

## 本节讲什么

教材高频易错点、背诵极简版与完整示例代码。

## 高频易错点汇总

1. **维度不能用普通变量**，须 `constexpr` 等常量表达式  
2. **`char` 数组接字符串字面量**要预留 **`'\0'`** 空间：`"abc"` 需要 4 字节  
3. **数组传参退化为指针**，函数内 `sizeof` 得到的是指针大小，**丢失长度**  
4. **`&arr` 与 `&arr[0]`**：地址数值可能相同，**类型不同**，`+1` 步长不同  
5. **数组不能整体复制**，只能循环逐元素拷贝  
6. **越界无报错**，属于隐蔽 UB——与 `vector[]` 同类风险  

## 背诵极简版

```
内置数组：编译期固定大小，不能扩容、不能整体拷贝赋值
T a[N] 或 T a[]={...}；维度须常量；char "abc" 占 4 含 \0
下标 0..N-1；arr[i]==*(arr+i)；越界 UB，无检查
数组名多数退化为 &a[0]；例外 sizeof(a) &a 初始化
&arr 类型 int(*)[N]；&arr[0] 类型 int*
begin/end 遍历数组；优先 vector/string
传参丢长度；业务用 vector，C 接口/固定缓冲才用数组
```

## 完整示例

```cpp
#include <iostream>
#include <iterator>
#include <string>

int main() {
    int arr[3] = {1, 2, 3};

    // 下标
    arr[0] = 10;
    std::cout << arr[0] << "\n";

    // 退化：数组名 → 指针
    int *p = arr;
    std::cout << *p << " " << *(p + 1) << "\n";

    // sizeof / 地址类型
    std::cout << "sizeof(arr)=" << sizeof(arr)
              << " sizeof(p)=" << sizeof(p) << "\n";

    // begin/end 遍历
    for (auto it = std::begin(arr); it != std::end(arr); ++it)
        std::cout << *it << " ";
    std::cout << "\n";

    // 字符数组
    char msg[] = "FIX";   // 'F','I','X','\0'
    std::cout << msg << "\n";

    return 0;
}
```

## 课后核心考点

1. 数组 vs `vector`：固定大小、不能拷贝、传参退化  
2. 列表初始化、字符数组与 `'\0'`  
3. 下标与指针等价、`arr[i]` ≡ `*(arr+i)`  
4. 退化规则与 **3 种例外**  
5. `std::begin`/`std::end` 遍历  
6. **现代 C++**：优先 `vector`/`string`  

## 和 C 的区别（数组章节总结：C++ 给了更安全的替代）

整个 3.5 章节的数组语法，C 和 C++ **几乎完全一致**——定义、初始化、下标、退化、`'\0'`、不能整体拷贝，这些都是 C 遗产。C++ 的进步在于提供了**更安全的替代品**：

| 场景 | C（只有裸数组） | C++ 现代写法 |
|------|-----------------|---------------|
| 固定大小容器 | `int arr[N];` | `std::array<int, N>;`（自带 size、可拷贝） |
| 动态大小容器 | `malloc`/`realloc` 手动 | `std::vector<int>;`（RAII 自动管理） |
| 字符串 | `char str[N];` | `std::string;`（自动扩容、运算符重载） |
| 遍历 | `for (p=arr; p<arr+n; ++p)` | `for (x : arr)` 范围 for |
| 取长度 | `sizeof(arr)/sizeof(arr[0])`（传参失效） | `.size()`（始终有效） |
| 边界检查 | 无 | `.at(i)` 抛异常 |
| 算法库 | 手写循环 | `std::sort`/`std::find` 接 begin/end |

**给 C 程序员的总结建议：**
1. **业务代码优先 `vector`/`string`/`array`**——只在 C 接口、固定缓冲、极热路径才用裸数组
2. **必须用裸数组时**用 `std::begin`/`std::end` 遍历，少手写指针算术
3. **HFT 热路径**仍用裸数组/`std::array`（栈上、零分配），但要严格管边界

## 常见错误

### 1. 用 C 的 VLA 习惯写 C++

```cpp
int n = read_config();
int buf[n];   // ❌ C++ 标准 VLA 不支持（GCC 扩展能过）
```

C99 的 VLA 在 C++ 不是标准。要运行时大小用 `vector`，要编译期常量用 `constexpr`。

### 2. 字符数组忘了 `\0` 占位

```cpp
char tag[3] = "FIX";   // ❌ "FIX" 实际 4 字节，3 字节装不下
```

字符串字面量自动追加 `\0`。`char tag[] = "FIX";`（让编译器算维度=4）或 `char tag[4] = "FIX";` 才对。

### 3. 数组传参后当数组用

```cpp
void f(int arr[]) {
    size_t n = sizeof(arr) / sizeof(arr[0]);   // ❌ 退化后是指针，n 算错
}
```

传参退化丢长度。要么另传 `n`，要么用 `std::array`/`vector`，要么用模板引用 `int (&arr)[N]`。

## 自测题

**1. 选择题**　下列关于 C++ 内置数组的描述，**错误**的是：

- A. 数组大小必须是编译期常量表达式
- B. 数组不能整体拷贝赋值
- C. 数组传参时会退化为指针
- D. 数组有成员函数 `size()` 返回长度

<details><summary>答案</summary>

**D**。内置数组**没有成员函数**，`arr.size()` 是编译错误。要 `size()` 用 `std::array` 或 `vector`，或用 `std::size(arr)`（C++17）或 `sizeof(arr)/sizeof(arr[0])`（传参前）。

</details>

**2. 判断题**　`char msg[] = "FIX";` 创建的数组 `msg` 长度是 3。

<details><summary>答案</summary>

**错**。长度是 4——`'F'`、`'I'`、`'X'`、`'\0'`。字符串字面量自动追加结尾 `\0`，`msg` 数组要装下它。`sizeof(msg) == 4`，但 `strlen(msg) == 3`（不含 `\0`）。

</details>

**3. 踩坑题**　C 程序员写下面这段配置读取代码，迁移到 C++ 后想"现代"一点，有什么问题？

```cpp
int n = 0;
read_config(&n);
int* buf = (int*)malloc(n * sizeof(int));
for (int i = 0; i < n; ++i) buf[i] = i;
// ... 使用 buf ...
free(buf);
```

<details><summary>答案</summary>

能用但失去了 C++ 的优势。**更现代的写法**：

```cpp
int n = 0;
read_config(&n);
std::vector<int> buf(n);   // 自动分配，RAII 释放
for (int i = 0; i < n; ++i) buf[i] = i;
// 或：std::iota(buf.begin(), buf.end(), 0);
// 无需 free，离开作用域自动析构
```

改进点：
- 无 `malloc`/`free`，RAII 自动管理
- 无 `sizeof(int)` 那种字节数计算（容易算错）
- 自带 `size()`，传参不丢长度
- 异常安全（`malloc` 失败返回 NULL 要检查，`vector` 抛异常）

</details>

**4. 应用题**　HFT 启动时读 64 个合约代码（每个最多 16 字符），运行时只读不写。用内置数组、`std::array`、`std::vector` 各写一版，对比选型。

<details><summary>答案</summary>

```cpp
// 版本 1：内置数组（C 风格）
char codes[64][16];   // 64 行 16 列
// 传参：void f(char codes[][16], size_t n);  退化、丢长度

// 版本 2：std::array（C++ 推荐，固定大小）
std::array<std::array<char, 16>, 64> codes;
// 或 std::array<std::string, 64> codes;  若用 string
// 自带 size()、可拷贝、接口友好

// 版本 3：std::vector（动态大小）
std::vector<std::string> codes;
codes.reserve(64);   // 预留容量
// 启动时 push_back，运行时只读
```

**选型**：
- 大小编译期确定（64×16 固定）→ `std::array`（栈上、零堆分配、自带 size）
- 大小运行时才知 → `vector`
- 要和 C 接口对接 → 内置数组（`codes[i]` 是 `char*` 可传 C 函数）

HFT 启动配置这种"固定大小、运行时只读"场景，`std::array<std::string, 64>` 或 `std::array<char[16], 64>` 最合适。

</details>
