# 3.5.2 下标访问与越界

## 本节讲什么

数组下标规则、`arr[i]` 与指针运算的关系，以及越界为何是隐蔽 UB。

## 下标规则

1. 下标从 **`0`** 开始：`arr[0]` 首元素，`arr[N-1]` 末元素（`N` 为数组长度）
2. **`arr[i]` 等价 `*(arr + i)`**——下标访问本质是**指针算术**（见 [3.5.3](./3.5.3-数组退化与指针.md)）
3. **无数组边界检查**：下标超出 `0 … N-1` → **未定义行为**，可能静默踩内存或崩溃
4. 对比 `vector`：**`at(i)`** 会越界抛异常；**`operator[]`** 与数组一样**不检查**（见 [3.3.3](../3.3-library-type-vector/3.3.3-下标与增删.md)）

```cpp
int arr[3] = {10, 20, 30};
arr[0] = 1;           // ✅
// arr[3] = 99;       // ❌ UB，无编译/运行报错
```

## HFT 注意

固定 `char buf[N]` 写合约码、订单号时，**必须**保证写入长度 `< N` 且保留 `'\0'`；越界写与 `vector` 一样可能**静默错价**（见 [3.2.4 固定缓冲](../3.2-library-type-string/3.2.4-string与C风格字符串.md)）。

## 和 C 的区别（下标访问：C/C++ 一致，越界都是 UB）

下标访问是 C 和 C++ **完全一致**的部分——`arr[i]` 等价 `*(arr + i)`，下标从 0 开始，越界都是 UB，无数组边界检查。C 程序员这部分无需转变，但要记住：

| 对比点 | C | C++ |
|--------|----|------|
| `arr[i]` ≡ `*(arr + i)` | ✅ 一致 | ✅ 一致 |
| 下标从 0 开始 | ✅ | ✅ |
| 越界 UB，无检查 | ✅ | ✅ |
| 有边界检查的替代 | 无（C 没标准容器） | `std::array::at(i)` 抛异常，`std::vector::at(i)` 抛异常 |
| 负下标 | `arr[-1]` UB（罕见但合法语法） | 同 UB |

**给 C 程序员的关键提醒：**
1. **`at(i)` 是 C++ 独有的"安全下标"**——越界抛 `std::out_of_range` 异常，不静默 UB。调试阶段用 `at`，热路径用 `[]`（异常有开销）。
2. **C 的 `assert(i < N)` 习惯在 C++ 也有效**——`assert(arr[i])` 前加 `assert(i < N)`。但 `assert` 在 Release 编译（`NDEBUG`）会消失，别依赖它做生产保护。
3. **`arr[i]` 和 `i[arr]` 在 C/C++ 都合法**（因为 `*(arr+i) == *(i+arr)`），但别写 `i[arr]`——可读性差，是 C 的历史包袱。

## 常见错误

### 1. `arr[N]` 越界写无报错

```cpp
int arr[5] = {0};
for (int i = 0; i <= 5; ++i)   // 注意 <=，i=5 时越界
    arr[i] = i;                 // ❌ UB，可能静默踩栈
```

C 程序员对这个循环边界错误再熟不过——`<` 写成 `<=` 就越界。C++ 同样 UB。**用范围 for 避开手写边界**：

```cpp
int i = 0;
for (int& x : arr) x = i++;
```

### 2. 误以为 `vector` 的 `[]` 有边界检查

```cpp
std::vector<int> v = {1, 2, 3};
std::cout << v[10];   // ❌ UB，和数组一样不检查
```

`vector::operator[]` 和数组一样**不检查边界**，越界是 UB。要检查用 `v.at(10)`（抛 `std::out_of_range`）。C 程序员以为 C++ 容器"更安全"会自动检查，这是个误区——`[]` 仍是零开销，`at` 才检查。

### 3. 负下标或下标回绕

```cpp
int arr[5];
size_t i = some_function();   // 可能返回大值
arr[i] = 0;                    // 若 i >= 5，UB

int j = -1;
arr[j] = 0;                    // ❌ 负下标 UB
```

`size_t` 是无符号，`i - 1` 当 `i == 0` 时回绕成巨大正数，越界。C 和 C++ 都有这个坑。**用有符号 `int` 或 `ptrdiff_t` 做下标**，或先判边界。

## 自测题

**1. 选择题**　`std::vector<int>::operator[]` 越界访问时行为是：

- A. 返回 0
- B. 抛 `std::out_of_range` 异常
- C. 未定义行为（UB）
- D. 编译错误

<details><summary>答案</summary>

**C**。`operator[]` **不检查边界**，越界是 UB（可能踩内存、可能崩、可能静默错）。要抛异常用 `at(i)`。C 程序员常误以为 C++ 容器自动安全，其实 `[]` 和 C 数组一样裸奔。

</details>

**2. 判断题**　`arr[i]` 和 `i[arr]` 在 C++ 中都合法且等价。

<details><summary>答案</summary>

**对**。因为 `arr[i]` 定义为 `*(arr + i)`，而 `*(arr + i) == *(i + arr)`，所以 `i[arr]` 也合法。这是 C 遗留的语法包袱，C++ 继承了。但**生产代码别写 `i[arr]`**——可读性极差。

</details>

**3. 踩坑题**　下面这段 HFT 代码用 `size_t` 做下标，有什么隐患？

```cpp
void process(std::vector<int>& v) {
    for (size_t i = v.size() - 1; i >= 0; --i) {
        if (v[i] == target) { /* ... */ }
    }
}
```

<details><summary>答案</summary>

**死循环**。`size_t` 是无符号，`i >= 0` 永远为 true（无符号数总是 >= 0）。当 `i` 减到 0 再 `--i` 会回绕成 `SIZE_MAX`（巨大正数），`v[i]` 越界 UB，循环不停。

**修复**：

```cpp
// 方法 1：用有符号
for (int i = static_cast<int>(v.size()) - 1; i >= 0; --i) { ... }

// 方法 2：用迭代器反向
for (auto it = v.rbegin(); it != v.rend(); ++it) { ... }

// 方法 3：判断 i 是否到 0 后 break
for (size_t i = v.size(); i > 0; ) {
    --i;
    if (v[i] == target) { ... }
}
```

C 程序员用 `int i` 习惯了负数判断，到 `size_t` 要换思路。

</details>

**4. 应用题**　写一个安全的数组访问函数，越界时返回错误码而不是 UB。

<details><summary>答案</summary>

```cpp
#include <array>
#include <optional>

template <typename T, size_t N>
std::optional<T> safe_get(const std::array<T, N>& arr, size_t i) {
    if (i < N) return arr[i];      // 边界检查
    return std::nullopt;            // 越界返回空
}

// 用法
std::array<int, 5> arr = {1,2,3,4,5};
auto x = safe_get(arr, 3);   // optional(4)
auto y = safe_get(arr, 10);  // nullopt
if (x) std::cout << *x;
```

或直接用 `arr.at(i)`（越界抛异常），调用方 try/catch：

```cpp
try { std::cout << arr.at(10); }
catch (const std::out_of_range& e) { /* 处理越界 */ }
```

C 等价是手写 `if (i < N) return arr[i]; else return -1;`——C++ 的 `at`/`optional` 更规范。

</details>
