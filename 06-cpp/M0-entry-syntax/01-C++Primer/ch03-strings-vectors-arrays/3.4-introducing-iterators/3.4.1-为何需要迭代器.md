# 3.4.1 为何需要迭代器

> 第 3 章 · 上一节：[3.3 vector](../3.3-library-type-vector/3.3-标准库类型vector.md) · 下一节：[3.4.2 begin、end 与常量迭代器](./3.4.2-begin-end与常量迭代器.md)

## 本节讲什么

下标的局限与迭代器的通用性——全书 STL 遍历的基础。

## 下标不够通用

| 访问方式 | `vector` / `string` | `list` | `map` / `set` |
|----------|---------------------|--------|---------------|
| **下标 `v[i]`** | ✅ | ❌ | ❌ |
| **迭代器** | ✅ | ✅ | ✅ |

下标只适合随机访问、连续序列；迭代器是**所有容器的通用句柄**。

## 迭代器是什么

- 类似**指针**：指向容器内某个元素（或尾后位置）
- 通过 **`*it`** 间接访问元素
- 通过 **`++it`** 在元素间移动
- `string` **不是**容器类型，但接口上**完整支持**与容器相同的迭代器操作

## 和 C 的区别（迭代器 ≈ 泛型指针）

**C 程序员对迭代器不会陌生**——它就是"泛型化的指针"。C 用指针遍历数组，C++ 用迭代器遍历所有容器：

| 对比点 | C（指针遍历数组） | C++（迭代器遍历容器） |
|--------|-------------------|----------------------|
| 起始 | `int *p = arr;` | `auto it = v.begin();` |
| 结束 | `int *end = arr + n;` | `auto end = v.end();` |
| 解引用 | `*p` | `*it` |
| 前进 | `++p` | `++it` |
| 比较 | `p != end` | `it != end` |
| 适用范围 | 只有连续数组 | **所有容器**（list/map/set...） |

```c
/* C：指针遍历数组 */
int arr[] = {1, 2, 3};
for (int *p = arr; p != arr + 3; ++p)
    printf("%d ", *p);
```
```cpp
// C++：迭代器遍历 vector（写法和 C 指针几乎一样）
std::vector<int> v{1, 2, 3};
for (auto it = v.begin(); it != v.end(); ++it)
    std::cout << *it << " ";
// 或用范围 for（底层也是迭代器）
for (int x : v) std::cout << x << " ";
```

**给 C 程序员的关键转变：**
1. 迭代器就是"升级版指针"——`*`、`++`、`!=` 的用法和 C 指针完全一样。
2. C 指针只能遍历连续内存（数组）；迭代器能遍历**所有容器**（包括 `list`、`map` 这种不连续的），统一了遍历语法。
3. `end()` 是"尾后"位置（类似 C 的 `arr + n`），**不指向有效元素**，不能解引用。

## 自测题

**1（选择）** 下面哪个容器不能用下标 `v[i]` 访问？
- A. `vector`
- B. `string`
- C. `list`
- D. `array`

**2（判断）** 迭代器的 `*it`、`++it` 用法和 C 指针完全一样。

**3（概念）** 为什么说迭代器比下标更通用？

<details><summary>参考答案</summary>
1. C。`list` 是链表，元素不连续存储，不能用下标随机访问。`vector`/`string`/`array` 都是连续存储，支持下标。所有容器都支持迭代器。
2. 对。迭代器重载了 `*`（解引用）、`++`（前进）、`!=`（比较），用法和 C 指针几乎一样。可以说迭代器就是"泛型化的指针"。
3. 下标只适合连续存储的容器（vector/string/array），`list`/`map`/`set` 不支持。迭代器是所有容器的统一接口——同一套 `*it`/`++it`/`it!=end` 语法能遍历任何容器，算法也能通用。
</details>
