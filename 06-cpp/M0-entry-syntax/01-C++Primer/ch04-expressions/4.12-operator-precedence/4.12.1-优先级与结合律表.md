# 4.12.1 优先级与结合律表

## 本节讲什么

C++ 运算符优先级（**从高到低**）与结合方向——教材考点 + 日常查表用。

## 速记口诀（粗粒度）

```
作用域 :: 
后缀 ++ -- () [] . ->
前缀 ++ -- ! ~ 一元 * &
乘除模 * / %
加减 + -
移位 << >>
关系 < <= > >=
相等 == !=
位与 &
位异或 ^
位或 |
逻辑与 &&
逻辑或 ||
三元 ?:
赋值 = += -= ...
逗号 ,
```

## 完整优先级表（Primer 核心）

| 优先级 | 运算符 | 名称 | 结合律 |
|:------:|--------|------|--------|
| 1 | `::` | 作用域解析 | 左 |
| 2 | `++` `--` `()` `[]` `.` `->` `typeid` `const_cast` 等 | 后缀 / 成员 / 下标 / 调用 | 左 |
| 3 | `++` `--` `+` `-` `!` `~` `*` `&` `sizeof` `static_cast` 等 | 前缀一元 | **右** |
| 4 | `*` `/` `%` | 乘、除、模 | 左 |
| 5 | `+` `-` | 加、减 | 左 |
| 6 | `<<` `>>` | 移位 | 左 |
| 7 | `<` `<=` `>` `>=` | 关系 | 左 |
| 8 | `==` `!=` | 相等 | 左 |
| 9 | `&` | 按位与 | 左 |
| 10 | `^` | 按位异或 | 左 |
| 11 | `\|` | 按位或 | 左 |
| 12 | `&&` | 逻辑与 | 左 |
| 13 | `\|\|` | 逻辑或 | 左 |
| 14 | `?:` | 条件三元 | **右** |
| 15 | `=` `+=` `-=` `*=` `/=` `%=` `<<=` `>>=` `&=` `^=` `\|=` | 赋值 | **右** |
| 16 | `,` | 逗号 | 左 |

> 同一单元格内运算符优先级相同；不同编译器文档可能把 `<<` 与 `<` 的相对关系再细分，考试以教材表为准。

## 经典例题

### `*` 高于 `+`

```cpp
int a = 2, b = 3;
std::cout << a + b * 4 << std::endl;  // 2 + 12 = 14，不是 20
```

### `.` 高于 `*`

```cpp
// *p.size();     // ❌ 等价 *(p.size())
(*p).size();      // ✅ 或 p->size()
```

### `?:` 低于 `<<`

```cpp
std::cout << (grade < 60 ? "fail" : "pass");  // ✅
```

### 赋值右结合

```cpp
a = b = c = 0;    // a = (b = (c = 0))
```

### 逻辑 vs 位运算

```cpp
a & b && c;       // 先 & 再 &&
a && b || c;      // && 高于 ||
```

各运算符细节见 [4.2–4.10](../4.2-4.10-operators/4.2-4.10各种运算符详解.md)。

## 和 C 的区别（优先级表：C/C++ 几乎一致，C++ 多了几个运算符）

C 程序员对 C 的运算符优先级表已经倒背如流——`*` 高于 `+`、`&&` 高于 `||`、赋值右结合、逗号最低，这些 C++ **完全继承**。C++ 只是多了几个新运算符：

| 运算符 | C | C++ | 优先级位置 |
|--------|----|------|------------|
| `::` 作用域解析 | 无 | ✅ | **最高**（1 级） |
| `.*` `->*` 成员指针 | 无 | ✅ | 高（2 级，后缀类） |
| `static_cast`/`const_cast`/... | 无 | ✅ | 后缀类（2 级）或前缀（3 级） |
| `typeid` | 无 | ✅ | 2 级 |
| `new`/`delete` | 无 | ✅ | 3 级（前缀） |
| 算术/关系/逻辑/位运算 | ✅ 一致 | ✅ 一致 | 4-13 级完全相同 |
| `?:` 三元 | ✅ 一致 | ✅ 一致 | 14 级 |
| 赋值 `=` `+=` 等 | ✅ 一致 | ✅ 一致 | 15 级右结合 |
| 逗号 `,` | ✅ 一致 | ✅ 一致 | 16 级最低 |

**给 C 程序员的关键提醒：**
1. **C 学的优先级表 95% 直接用**——算术、关系、逻辑、位运算、赋值、逗号，优先级和结合律完全一致。`a + b * c`、`a < b && b < c`、`a = b = c` 这些 C 的肌肉记忆到 C++ 不用改。
2. **C++ 多了 `::`（最高优先级）**——作用域解析运算符，如 `std::cout`、`MyClass::method`。它优先级最高，不会和别的运算符混淆。
3. **C++ 多了 `.*` `->*`（成员指针）**——用于通过成员指针访问类成员，优先级较高（后缀类）。日常很少用，第 7 章详讲。
4. **C++ 的 `static_cast<...>(...)` 等"看起来像函数"**——优先级当后缀看，`static_cast<int>(d) + 1` 先算 cast 再加 1，不会出错。
5. **复杂表达式别靠背表，多加括号**——C 和 C++ 共同建议。优先级表是"查"的，不是"背"的。

## 常见错误

### 1. 位运算与关系运算混用不加括号

```cpp
if (flags & mask == 0) { ... }   // ❌ 等价 flags & (mask == 0)
```

`==` 优先级高于 `&`，先算 `mask == 0` 得 `bool`（0/1），再 `flags & 0/1`。**正确**：`if ((flags & mask) == 0)`。C 程序员也踩这个，C++ 同样坑。

### 2. `<<` 与 `?:` 混用不加括号

```cpp
std::cout << x > 0 ? "pos" : "neg";   // ❌ 等价 (cout << x) > 0 ? ...
```

`<<` 优先级高于 `?:`，先算 `cout << x`，再和 0 比。**正确**：`std::cout << (x > 0 ? "pos" : "neg")`。C 里 `printf` 没这个坑，C++ 的 `<<` 容易踩。

### 3. 以为优先级决定求值顺序

```cpp
int side_effect();
int x = side_effect() + 1;   // 以为 side_effect 一定先调？
```

优先级只决定"谁跟谁结合"（语法结构），**不决定求值顺序**。`side_effect() + 1` 中 `+` 决定结合方式，但 `side_effect()` 和 `1` 哪个先算未指定（这里没影响，但 `f() + g()` 就有影响）。C 和 C++ 都这样。

## 自测题

**1. 选择题**　`a & b && c` 的求值顺序（结合方式）是：

- A. `(a & b) && c`（先位与再逻辑与）
- B. `a & (b && c)`（先逻辑与再位与）
- C. `a & b && c` 未指定
- D. 编译错误

<details><summary>答案</summary>

**A**。`&`（位与，9 级）优先级**高于** `&&`（逻辑与，12 级），所以 `a & b && c` 等价 `(a & b) && c`。先算 `a & b`（位与，无短路），再和 `c` 逻辑与（有短路）。C 也是同样优先级。

</details>

**2. 判断题**　`std::cout << x < 0 ? "neg" : "pos";` 能正确打印 `x` 的正负。

<details><summary>答案</summary>

**错**。`<<` 优先级高于 `<`，`<` 高于 `?:`，所以等价 `((std::cout << x) < 0) ? "neg" : "pos"`——先输出 `x`，再把 `cout` 和 0 比（无意义），最后条件判断。**修复**：`std::cout << (x < 0 ? "neg" : "pos");`，加括号。C 里 `printf` 没这个坑。

</details>

**3. 踩坑题**　下面这段代码想测试 `flags` 的第 3 位是否为 1，哪里有问题？

```cpp
unsigned flags = 0x08;   // 二进制 1000，第 3 位是 1
if (flags & 0x08 == 0x08) {
    std::cout << "bit 3 is set";
}
```

<details><summary>答案</summary>

**`==` 优先级高于 `&`**，等价 `flags & (0x08 == 0x08)` → `flags & true` → `flags & 1`。`flags = 0x08` 的最低位是 0，所以 `flags & 1 == 0`，条件 false，不打印——但逻辑上第 3 位确实为 1。

**修复**（加括号）：

```cpp
if ((flags & 0x08) == 0x08) { ... }
// 或更简单：
if (flags & 0x08) { ... }   // 非 0 即真
```

C 程序员也踩这个——位运算和关系混用必加括号。

</details>

**4. 应用题**　不用查表，判断 `a < b == c < d` 的结合方式（假设 `a,b,c,d` 是 int）。

<details><summary>答案</summary>

`<` 和 `==` 同级（关系/相等运算符，7/8 级），**左结合**，所以 `a < b == c < d` 等价 `((a < b) == (c < d))`——先算 `a < b` 得 `bool`，再算 `c < d` 得 `bool`，最后比较两个 `bool` 是否相等。

这种写法虽然合法，但**可读性差**，建议加括号：`((a < b) == (c < d))` 或拆成 `(a < b) && (c < d)`（若想表达"两个条件都成立"）。C 也是同样优先级。

</details>
