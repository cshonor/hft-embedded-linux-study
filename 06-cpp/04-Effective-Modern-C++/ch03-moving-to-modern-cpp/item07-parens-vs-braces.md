# Item 7：区别 () 和 {} 创建对象

> 第 3 章 移步现代 C++ · Item 7 · 下一节：[Item 8 nullptr](item08-nullptr.md)

## 这节讲什么

C++11 的大括号初始化 `{}` 几乎能初始化一切，但和小括号 `()` 有微妙差异——尤其是 `{}` 会优先匹配 `initializer_list` 构造函数，导致反直觉的行为。

---

## () vs {} 对比

| 特性 | `()` | `{}` |
|------|------|------|
| 窄化转换 | 允许（`int(3.14)`） | **禁止**（`int{3.14}` 编译失败） |
| 最烦人解析 | 会中招（`Widget w();` 被解析成函数声明） | 免疫 |
| `initializer_list` 构造函数 | 不优先 | **优先匹配** |

### initializer_list 优先陷阱

```cpp
std::vector<int> v1(10, 20);   // 10 个 20 → {20,20,...,20}
std::vector<int> v2{10, 20};   // 2 个元素 → {10, 20}  匹配 initializer_list 构造
```

`{}` 会**优先**匹配 `initializer_list` 构造函数，哪怕有更优匹配。空 `{}` 则调用默认构造。

---

## 新手要点（和 C 的区别）

- **C 只有小括号/等号初始化**：`int x = 42;` 或 `int x(42);`。C++ 多了 `{}`，且 `{}` 防窄化是安全优势。
- **最烦人解析**：`Widget w();` 在 C++ 里不是构造对象，而是声明了一个函数。用 `Widget w{};` 或 `Widget w;` 避免。
- **建议**：对内置类型用 `{}` 防窄化；对容器先查它有没有 `initializer_list` 构造再决定。

---

## HFT 关联

- **防窄化**：`int64_t qty{order.qty()}` 比 `int64_t qty(order.qty())` 安全——后者在 `qty()` 返回 `double` 时不报错但截断。
