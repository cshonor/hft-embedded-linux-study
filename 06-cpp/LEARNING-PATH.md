## 三、M1 · 现代 C++ 门槛 🔴（硬门槛 · 全书精读）

### 04 Effective Modern C++

> **这是整个学习链的转折点。** C++11/14 是分水岭，老 C++ 和现代 C++ 是两种写法。这 42 条不过，后面 muduo 的回调、移动语义、智能指针全部看天书。

| 项目 | 说明 |
|------|------|
| **定位** | 现代 C++（11/14）最佳实践，42 条 |
| **怎么读** | **逐条精读**，每条都要写代码验证 |
| **不能跳** | 全书都是重点 |
| **验收** | 能读 muduo 里 `shared_ptr`/回调/移动语义不懵 |
| **预计时间** | 4–6 周（42 条，每天 1–2 条） |
| **何时读** | 07 TLPI 之后、10 PNP（网络编程）之前 |

### 章节重点（8 章，按读序）

#### Ch1 · 类型推导（条款 1–4）
- **条款 1** 模板类型推导三规则 —— `T`、`T&`、`T&&` 三种形参如何推导
- **条款 2** `auto` 推导 —— 和模板几乎一样，但 `auto` 对 `{}` 推导出 `initializer_list`
- **条款 3** `decltype` —— `decltype(x)` vs `decltype((x))`（后者返回引用，巨坑）
- **条款 4** 查看推导结果的三种方法 —— IDE、编译错误、`std::type_info`

**新手要点：** `auto` 用起来爽，但要记住 `auto x = {1}` 推出的是 `initializer_list<int>` 不是 `int`。

#### Ch2 · auto（条款 5–6）
- **条款 5** 优先用 `auto` —— 少写类型、避免未初始化、避免类型不匹配
- **条款 6** `auto` 的陷阱 —— `vector<bool>` 代理类型、显式类型初始化习惯 `auto b = static_cast<bool>(vb[0])`

**新手要点：** `vector<bool>` 不是存 `bool`，是存 bit，`[]` 返回代理类型。用 `auto` 接会拿到悬垂引用。

#### Ch3 · 移步现代 C++（条款 7–10）
- **条款 7** `{}` 初始化 —— 防窄化，但会优先匹配 `initializer_list` 构造函数（陷阱）
- **条款 8** `nullptr` 替代 `0`/`NULL` —— 指针就是指针，别和整数混淆
- **条款 9** `using` 替代 `typedef` —— 别名模板更清晰
- **条款 10** `enum class` —— 强类型枚举，不污染外层命名空间

#### Ch4 · 智能指针（条款 11–22）⭐ 核心
- **条款 18–22** 是重点：`unique_ptr` 零开销、`shared_ptr` 控制块 + 原子计数代价、`weak_ptr` 破环、`make_unique`/`make_shared` 异常安全
- **Pimpl 惯用法** —— 指针实现，降低编译依赖

**新手要点：** 优先 `unique_ptr`，需要共享才用 `shared_ptr`。`shared_ptr` 的原子计数有开销，HFT 热路径别用。

#### Ch5 · 右值/移动/转发（条款 23–30）⭐ 核心
- **条款 23** `std::move` 不移动任何东西，只是个 cast
- **条款 24** 万能引用 `T&&` —— 右值引用不是万能引用
- **条款 25** 对万能引用用 `std::forward`，对右值引用用 `std::move`
- **条款 28** 引用折叠四规则 —— `& + && = &`，`&& + && = &&`
- **条款 29** 假定移动操作不存在/不便宜/不做用

**新手要点：** `move` 只是申请移动，对方接不接是另一回事。`const` 对象没法移动，会退化成拷贝。

#### Ch6 · Lambda（条款 31–34）
- **条款 31** lambda 捕获 `[=]` 捕获 `this` 的隐患（C++17 用 `[*this]`）
- **条款 32** 初始化捕获 —— C++14，`[p = std::move(ptr)]`
- **条款 33** 泛型 lambda —— `auto` 参数，C++14
- **条款 34** lambda vs `bind` —— 优先 lambda

#### Ch7 · 并发 API（条款 35–38）
- **条款 35** `async` 默认策略延迟执行 —— 不一定真异步
- **条款 36** `future` 析构会阻塞（`async` 启动的）
- **条款 37** `atomic` vs `volatile` —— `volatile` 不保证线程安全，`atomic` 才保证
- **条款 38** 线程句柄析构行为

**新手要点：** `volatile` 是给硬件寄存器/信号处理用的，**不是给多线程用的**。多线程用 `atomic`。这点和 Java 的 `volatile` 完全不同，别混淆。

#### Ch8 · 杂项（条款 39–42）
- **条款 41** 按值传参的条件 —— 可拷贝、移动便宜、可复制构造
- **条款 42** `emplace` vs `insert` —— `emplace` 避免临时对象，但有异常安全陷阱

### 07 深度探索 C++ 对象模型

| 项目 | 说明 |
|------|------|
| **定位** | 编译器实现视角，讲 C++ 对象在内存里长什么样 |
| **怎么读** | **精读 Ch1–Ch6**，Ch7 模板实例化可略读 |
| **不能跳** | Ch1 对象模型、Ch2 构造语义、Ch3 数据语义、Ch4 函数语义 |
| **验收** | 能解释"空类 sizeof 是 1"、"多继承怎么调 this"、"虚函数代价" |
| **预计时间** | 3–4 周 |
| **何时读** | 与 08 并发**并行或略前** |

#### 章节重点

##### Ch1 · 对象模型
- **对象模型三规则** —— 成员变量在对象内、成员函数不在对象内
- **vptr/vtable** —— 虚函数怎么实现，每个对象多一个指针
- **继承布局代价** —— 单继承零开销，多继承需要 this 调整
- **封装零运行开销** —— public/private 是编译期约束，运行时无代价

**新手要点：** `sizeof(空类)` = 1，不是 0。因为不同对象地址必须不同。有虚函数的类 `sizeof` 多 8 字节（64 位 vptr）。

##### Ch2 · 构造语意学
- **编译器合成默认构造的四种情况** —— 含成员有默认构造、基类有默认构造、有虚函数、有虚基类
- **按位 vs 逐成员拷贝** —— 什么时候编译器自己生成拷贝构造
- **初始化列表三必须** —— const 成员、引用成员、无默认构造的成员
- **NRVO** —— 命名返回值优化，避免拷贝

**新手要点：** 别以为"没写构造函数就没有构造函数"。编译器会在 4 种情况下偷偷给你合成一个。

##### Ch3 · 数据语意学
- **成员布局** —— 成员按声明顺序排列，对齐填充
- **多继承 this 调整** —— 派生类指针转基类指针可能要加减偏移
- **虚继承偏移表** —— 解决菱形继承，运行期查偏移
- **指向成员的指针** —— 本质是偏移量，不是地址

##### Ch4 · 函数语意学
- **vtable 间接代价** —— 虚函数多一次内存访问
- **thunk** —— 多继承下调整 this 的小函数
- **指向成员函数的指针** —— 虚函数和非虚函数大小不同
- **CRTP 静态多态** —— `template<class D> struct Base`，编译期多态，零运行开销 ⭐ HFT 必备

**新手要点：** HFT 热路径用 CRTP 替代虚函数，省掉 vtable 间接跳转，对分支预测友好。

##### Ch5 · 构造/析构/拷贝
- **构造析构顺序对称** —— 基类构造→成员构造→派生类构造；析构反之
- **存储期** —— auto/static/heap/static-local 四种
- **new/delete 两步** —— operator new 分配内存 + 构造函数；析构函数 + operator delete 释放
- **placement new** —— 在已有内存上构造，HFT mempool 必备 ⭐

##### Ch6 · 运行期语意学
- **new[] 头部存元素数** —— `delete[]` 要知道析构几次
- **dynamic_cast RTTI 代价** —— 运行期类型识别，有开销
- **table-based EH 零开销** —— 异常处理表，不抛异常时零运行开销

##### Ch7 · 高级对象模型（可略读）
- 模板实例化代码膨胀、extern template

### 08 C++ 并发编程实战

| 项目 | 说明 |
|------|------|
| **定位** | C++11/14 多线程全流程，从 thread 到无锁结构 |
| **怎么读** | **全书精读**，尤其内存模型章 |
| **不能跳** | Ch1–Ch5 是核心，Ch7 无锁结构 HFT 必读 |
| **验收** | 能写 mutex/condition_variable、理解 data race、能解释 6 种内存序 |
| **预计时间** | 5–6 周 |
| **何时读** | 10–14 网络栈进行中或之后、17 HFT 之前 |

#### 章节重点

##### Ch1 · 你好并发
- 并发 vs 并行 —— 并发是多任务切换，并行是真同时
- 并发风险：数据竞争、死锁、悬垂引用、开销

##### Ch2 · 管理线程
- `std::thread` 生命周期 —— join/detach 必须二选一，否则 terminate
- 传参 —— 默认拷贝，要引用用 `std::ref`
- RAII 守卫 —— 防止线程对象析构时 terminate
- `hardware_concurrency()` —— 查硬件并发数

**新手要点：** 线程对象析构前必须 join 或 detach，不然程序直接 `std::terminate` 崩溃。

##### Ch3 · 共享数据
- `mutex` + `lock_guard` —— RAII 锁
- 死锁四条件 + `scoped_lock` 原子锁多个资源
- 接口级竞争 —— `if(!empty()) top(); pop();` 错误示例
- `call_once` / Meyers singleton —— C++11 起局部 static 变量线程安全
- `shared_mutex` —— 读写锁

**新手要点：** `stack.top()` 在并发下有 race condition：A 检查非空→B pop 走→A top 取空栈。解决：把 top+pop 合成一个原子操作。

##### Ch4 · 同步操作
- `condition_variable` —— 等待/通知
- `future`/`promise` —— 一次性同步
- `async` —— 异步任务，注意默认策略是延迟执行
- C++20 `latch`/`barrier` —— 倒计时/循环同步

##### Ch5 · 内存模型与原子操作 ⭐⭐⭐ HFT 核心
- **6 种内存序** —— `memory_order_relaxed/acquire/release/acq_rel/seq_cst/consume`
- **acquire-release 配对** —— 释放-获取序，HFT 无锁队列标配
- **CAS** —— compare_exchange_weak/strong，无锁编程原语
- **ABA 问题** —— 值从 A→B→A，CAS 误以为没变过
- **atomic vs volatile** —— `atomic` 保证原子+可见性，`volatile` 只禁优化不保证原子

**新手要点：** 无锁队列用 `acquire`（读端）+ `release`（写端）配对，比 `seq_cst` 快很多。HFT SPSC 队列就靠这个。

##### Ch6 · 基于锁的并发容器
- 细粒度锁、分层锁
- 并发栈/队列/哈希表设计

##### Ch7 · 无锁数据结构 ⭐ HFT 必读
- **Treiber 栈** —— 无锁栈经典实现
- **SPSC 环形队列** —— 单生产者单消费者，HFT 热路径标配 ⭐
- ABA 问题的解决方案 —— 标签指针、 hazard pointer

##### Ch8 · 设计并发代码
- 数据并行 vs 任务并行
- 流水线模式
- Amdahl 定律 —— 加速比上限由串行部分决定
- 减少共享 —— 临界区越小越好

##### Ch9 · 高级线程管理
- 线程池
- work-stealing 调度
- C++20 `jthread`/`stop_token` —— 可取消线程

##### Ch10 · 并行算法
- 执行策略 —— `seq/par/par_unseq`
- 并行 STL

##### Ch11 · 测试与调试
- TSan —— 线程 sanitizer，检测 data race
- 死锁检测
- Heisenbug —— 一加调试就消失的 bug

### 08 验收自测

## 七、新手最常踩的 3 个坑

### 坑 1：把 01 Primer 当教材从头啃
**症状：** 啃了 3 个月还在 Part I，没碰到现代写法
**纠正：** 01 是字典，只读 Part I + 标准库基础，模板章跳过

### 坑 2：先读 02/03 老 Effective
**症状：** 条目过时且与现代写法冲突，学了一堆被取代的写法
**纠正：** 先过 04 Effective Modern C++（M1），02/03 碰到问题再查

### 坑 3：跳过 08 并发直接碰 HFT
**症状：** data race 让程序"时好时坏"，调试到崩溃
**纠正：** 08 必须在开 HFT 前读完，尤其内存模型章
