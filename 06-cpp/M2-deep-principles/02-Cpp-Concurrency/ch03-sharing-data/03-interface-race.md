# 3.3 接口级竞争

> 第 3 章 · 上一节：[3.2 死锁及避免](02-deadlock.md) · 下一节：[3.4 初始化保护](04-init-protection.md)

## 这节讲什么

保护要覆盖**整个逻辑操作**，而非单步。`if(!empty()) top(); pop();` 是经典错误——三步之间有竞争窗口。

---

## 经典错误

```cpp
// 错误：get 和 pop 各自加锁，中间窗口被其他线程插入
if (!stack.empty()) {     // 加锁→解锁
    auto v = stack.top();  // 加锁→解锁（可能此时已被其他线程 pop！）
    stack.pop();           // 加锁→解锁（pop 空栈 UB）
}
// 正确：用一个原子操作或持锁覆盖整个检查+取
```

每个成员函数各自加锁——但函数之间的间隙没有锁保护。其他线程可以在 `empty()` 和 `top()` 之间 `pop()` 掉元素。

---

## 新手要点

- **锁要覆盖完整操作**：不是每个函数各自加锁，而是整个逻辑操作持一把锁。
- **设计线程安全接口**：要么提供原子的"检查+取"操作（持锁），要么返回值+弹出合并为一个操作。

---

## HFT 关联

- **订单簿操作**：检查最优价 + 取单必须原子，否则多策略线程竞争时可能取到不一致数据。
