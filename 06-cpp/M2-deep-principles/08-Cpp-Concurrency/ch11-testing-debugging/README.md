# 第 11 章 多线程应用的测试和除错

**Testing and Debugging Multithreaded Applications**

## 本章讲什么

并发 bug 是最难抓的——不可复现、时序依赖、在特定调度下才暴露。本章讲数据竞争和死锁的定位手段、并发测试策略、以及工具链（ThreadSanitizer、死锁检测、压力测试）。

## 要点

### 并发 bug 的特征

| 特征 | 说明 |
|------|------|
| 不可复现 | 跑 1000 次才出现一次 |
| 时序依赖 | 只在特定线程交错下触发 |
| 环境敏感 | 换机器/编译器/负载就消失 |
| Heisenbug | 加 print 就不复现（改变了时序） |

### 数据竞争的检测

数据竞争 = 至少一个写操作 + 无同步 + 跨线程访问同一位置。

**工具**：
- **ThreadSanitizer (TSan)**：编译时加 `-fsanitize=thread`，运行时检测数据竞争。代价：10-20 倍减速，但能抓到肉眼找不到的竞争。
- **Helgrind (Valgrind)**：类似 TSan，更慢但不需要重新编译。
- **AddressSanitizer (ASan)**：主要查内存错误（use-after-free、越界），但也覆盖部分并发问题。

```cpp
// TSan 会报警的例子
int x = 0;
std::thread t1([&]{ x = 1; });   // 写
std::thread t2([&]{ std::cout << x; });  // 读，无同步
t1.join(); t2.join();
```

### 死锁的检测

- **静态分析**：`clang -analyzer`、Coverity 扫描锁序。
- **运行时检测**：TSan 能检测潜在死锁（锁序反转）。
- **调试技巧**：gdb 附着后 `info threads` 看各线程在哪，`thread apply all bt` 看全栈——都在 `__lock` 就是死锁。

### 并发测试策略

| 策略 | 说明 |
|------|------|
| 压力测试 | 大量并发跑，提高 bug 暴露概率 |
| 随机调度 | 随机 sleep/yield 打乱时序 |
| 模型检查 | 穷举所有线程交错（小规模） |
| 断言不变式 | 每次操作后检查结构不变式（如栈 size ≥ 0） |
| 有界重试 | 测试固定跑 N 次，看是否稳定 |

### 定位技巧

1. **加 `assert` 查不变式**：如队列出队后 `size >= 0`、链表无环。
2. **日志带线程 ID 和时间戳**：`[T=12345 ts=... ]` 方便重建时序。
3. **`std::this_thread::sleep_for` 强制交错**：测试时人为插入 sleep，放大竞争窗口。
4. **缩小复现范围**：二分注释代码，找到最小复现用例。
5. **核验内存序**：怀疑无锁代码时，把 `relaxed` 临时换成 `seq_cst`——如果 bug 消失，大概率是内存序写错。

### 常见陷阱

- **双重检查锁定（DCLP）的错误写法**：
```cpp
// 错误！p 的读取和 new 可能被重排
if (p == nullptr) {
    lock(m);
    if (p == nullptr) p = new Obj();   // new = alloc + construct，可能重排
    unlock(m);
}
// 正确：用 atomic + acquire/release 或 call_once
```
- **构造函数泄漏 this**：构造期间把 `this` 存到全局变量，其他线程可能访问到未完全构造的对象。
- **析构后访问**：线程 A 持有对象引用，线程 B 析构了对象——join 之后再析构共享对象。

## HFT 关联

- **TSan 在 CI 必备**：回测引擎、风控逻辑在 CI 跑 TSan，抓数据竞争。热路径代码 TSan 减速太大，用单元测试 + 随机调度。
- **生产环境禁用 TSan**：TSan 有 10-20 倍减速，生产用不了。生产靠 TSan 覆盖测试 + 在线监控（延迟尖刺、队列堆积报警）。
- **延迟尖刺定位**：生产出现延迟 P99 飙高，排查方向：锁竞争（perf top 看 `__lock`）、cache 伪共享（`perf c2c`）、NUMA 跨节点、GC/调度抖动。
- **无锁代码的内存序验证**：无锁队列改用 `seq_cst` 测试，若 bug 消失说明 acquire/release 用错——这是定位内存序 bug 的标准手段。
- **构造期间不泄漏 this**：策略对象构造完成后再注册到分发器，避免收行情时策略还没构造好。
- **确定性测试**：HFT 要求可复现——回测用固定种子 + `seq` 执行策略，生产 bug 用录制的行情流回放复现。
