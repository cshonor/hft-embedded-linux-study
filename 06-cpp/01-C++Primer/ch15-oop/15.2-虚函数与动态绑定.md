# 虚函数与动态绑定

## 本节讲什么

本节讲解 OOP 的核心机制——**虚函数（virtual function）**和**动态绑定（dynamic binding）**：为什么通过基类指针/引用调用 `virtual` 函数时，运行期会根据对象的实际类型选择正确的版本；vtable 是怎么工作的；`override`/`final` 如何帮你写出安全的虚函数覆盖；以及一个隐蔽但致命的坑——构造/析构期间调虚函数不走动态绑定。

> **一句话定位**：虚函数 = "这个行为派生类可以改写，调用时按实际对象类型决定执行哪版"。这是多态（polymorphism）的实现基础。

## 核心用法

### 1. virtual 声明虚函数

```cpp
class Base {
public:
    virtual void f1() const { }      // 虚函数
    virtual int  f2(int) { return 0; }
    void f3();                       // 非虚——派生类无法"覆盖"，只能"隐藏"
    virtual ~Base() = default;
};
class Derived : public Base {
public:
    void f1() const override { }     // 覆盖（签名必须完全一致）
    int  f2(int) override { return 1; }
};
```

规则：
- `virtual` 只在类内声明时写，类外定义不写
- 一旦声明 `virtual`，所有派生层的同名同签名函数都自动是虚的（不管有没有再写 `virtual`）
- 派生类覆盖时**签名必须完全一致**（参数列表、const 属性、返回类型都要匹配），否则是"隐藏"而非"覆盖"
- **例外**：返回类型可以是基类返回类型的协变（covariant）——基类返回 `Base*`，派生类返回 `Derived*` 合法

### 2. 动态绑定的触发条件

动态绑定**只在通过引用或指针调用虚函数时发生**：

```cpp
Base b;
Derived d;

Base &r = d;          // 引用
r.f1();               // ✅ 动态绑定 → Derived::f1

Base *p = &d;
p->f1();              // ✅ 动态绑定 → Derived::f1

d.f1();               // 静态绑定（对象类型已知）→ Derived::f1
b.f1();               // 静态绑定 → Base::f1

Base obj = d;         // ❌ 拷贝！d 被切掉，obj 是一个 Base
obj.f1();             // 静态绑定 → Base::f1（对象切片，见 15.5）
```

> 为什么值对象不动态绑定？因为 `Base obj = d;` 会把 `d` 的 Base 部分拷贝过来，派生部分被"切掉"——`obj` 在编译期就是纯粹的 `Base`，没有派生信息可绑定了。这就是为什么多态总是用**指针或引用**。

### 3. vtable：虚函数表的工作原理

每个含虚函数的类，编译器都会生成一张**虚函数表（vtable）**——一个函数指针数组，每个槽位对应该类的一个虚函数实现：

```
   Base 对象              Derived 对象
  ┌──────────┐           ┌──────────┐
  │ vptr ────┼──┐        │ vptr ────┼──┐
  └──────────┘  │        └──────────┘  │
                ▼                      ▼
        Base vtable             Derived vtable
        ┌─────────┐             ┌──────────┐
        │ &Base::f1│            │ &Derived::f1│  ← 覆盖了
        │ &Base::f2│            │ &Base::f2  │  ← 未覆盖，继承基类版本
        └─────────┘             └──────────┘
```

调用 `p->f1()` 编译器生成类似这样的代码：
```asm
mov  rax, [p]          ; 取对象首地址
mov  rax, [rax]        ; 取 vptr（vtable 地址）
mov  rax, [rax + 0]    ; 取 vtable 第 0 槽（f1 的地址）
call rax               ; 间接调用
```

所以虚调用比普通调用多一次内存访问（读 vptr + 读槽位）。现代 CPU 分支预测器对 vtable 间接调用的预测相当好，**绝大多数场景开销可忽略**。

### 4. override 和 final（C++11）

**`override`**：显式告诉编译器"我要覆盖基类的虚函数"，编译器会检查签名是否匹配。**永远写 `override`**：

```cpp
class Base { public: virtual void f(int) const; };
class Derived : public Base {
public:
    void f(int) const override { }     // ✅ 正确覆盖
    void f(int) override { }           // ❌ 漏 const → 编译错误（不是 override）
    void f(double) const override { }  // ❌ 参数类型不同 → 编译错误
};
```

**`final`**：禁止进一步覆盖（用在虚函数上）或禁止进一步继承（用在类上）：

```cpp
class Base {
public:
    virtual void f() final;        // 派生类不能再覆盖 f
};
class Derived : public Base {
public:
    void f() override;             // ❌ 错误：f 是 final
};
class Last final : public Base { };  // Last 不能被继承
class Wrong : public Last { };        // ❌ 错误
```

### 5. 虚函数的默认实参坑

虚函数可以有默认实参，但**默认实参是静态绑定的**——按指针/引用的静态类型决定：

```cpp
class Base {
public:
    virtual void f(int x = 10) { std::cout << x << "\n"; }
};
class Derived : public Base {
public:
    void f(int x = 20) override { std::cout << x << "\n"; }
};
Derived d;
Base *p = &d;
p->f();   // 输出 10！不是 20
// 调用 Derived::f（动态绑定），但默认实参取 Base 的（静态绑定）
```

**最佳实践**：基类和派生类的同名虚函数用**相同的默认实参**，避免这个坑。

### 6. 虚函数与内联

虚函数可以被声明 `inline`，但**只有当编译器能确定静态类型时**才会内联（此时不需要动态绑定）：

```cpp
class Base { public: virtual void f() { } };
Base b;
b.f();              // ✅ 编译器知道静态类型是 Base，可内联
Base *p = &b;
p->f();             // ❌ 动态绑定，无法内联（除非去虚化）
```

现代编译器有**去虚化（devirtualization）**优化——若能证明动态类型唯一，会把虚调用转为直接调用并内联。但这依赖编译器分析能力，不要主动依赖。

## 和 C 的区别

C 没有虚函数，要实现"按类型分发"只能**手动维护函数指针表 + switch**：

| 维度 | C | C++ |
|------|---|-----|
| 多态分发 | 函数指针 + `switch(type)` 手动写 | `virtual` + vtable 自动 |
| 添加新类型 | 改所有 switch（漏改即 bug） | 只需新增派生类，无需改已有代码 |
| 类型安全 | 强转 `void*`，无检查 | `dynamic_cast` 运行期检查 |
| 默认实现 | 手动调"基类"函数指针 | 基类虚函数提供默认实现，派生类按需覆盖 |
| 性能 | switch 可被优化，函数指针可内联 | vtable 间接调用，同样可去虚化 |

### C 模拟虚函数的典型写法

```c
// C：手动模拟虚函数表
struct Shape;
struct ShapeVTable {
    double (*area)(const struct Shape*);
    void (*draw)(const struct Shape*);
};
struct Shape {
    const struct ShapeVTable *vtable;   // 手动维护的"vtable"
    /* 公共数据 */
};
struct Circle {
    struct Shape base;     // 第一个成员，地址对齐
    double radius;
};
static double circle_area(const struct Shape *s) {
    const struct Circle *c = (const struct Circle*)s;
    return 3.14159 * c->radius * c->radius;
}
static const struct ShapeVTable circle_vtable = { circle_area, circle_draw };
struct Circle* circle_new(double r) {
    struct Circle *c = malloc(sizeof(*c));
    c->base.vtable = &circle_vtable;
    c->radius = r;
    return c;
}
// 调用：s->vtable->area(s)
```

```cpp
// C++：语言层面
struct Shape {
    virtual double area() const = 0;
    virtual void draw() const = 0;
    virtual ~Shape() = default;
};
struct Circle : Shape {
    double radius;
    Circle(double r) : radius(r) { }
    double area() const override { return 3.14159 * radius * radius; }
    void draw() const override { }
};
// 调用：s->area()
```

C 版本全靠程序员手动维护 vtable 指针、首成员对齐约定、强转安全——一旦漏掉 `vtable =` 赋值就是空指针解引用崩溃。C++ 把这一切交给编译器，且 `override` 让签名错误在编译期暴露。

> **HFT 视角**：vtable 间接调用有一次内存访问 + 一次间接跳转，对分支预测敏感。在超低延迟热路径上，可用 **CRTP（Curiously Recurring Template Pattern）** 在编译期分发，零运行开销：
> ```cpp
> template <typename Derived>
> struct ShapeBase {
>     double area() { return static_cast<Derived*>(this)->area_impl(); }
> };
> struct Circle : ShapeBase<Circle> {
>     double area_impl() { return 3.14159 * r * r; }
> };
> ```
> 这样编译器能完全内联，无 vtable 开销。

## 常见错误

### 错误 1：忘记 `virtual` → 隐藏而非覆盖

```cpp
class Base {
public:
    void f() { std::cout << "Base"; }   // ❌ 忘了 virtual
};
class Derived : public Base {
public:
    void f() { std::cout << "Derived"; }
};
Derived d;
Base *p = &d;
p->f();   // 输出 "Base"——非虚，静态绑定
```

非虚函数永远静态绑定。若希望多态，**基类必须声明 `virtual`**。

### 错误 2：签名不匹配导致隐藏（`override` 救命）

```cpp
class Base {
public:
    virtual void f() const { }      // 注意 const
};
class Derived : public Base {
public:
    void f() { }                    // ❌ 漏了 const → 隐藏！
    void f() override { }           // 加 override → 编译器报错救你
};
```

**永远写 `override`**，让编译器替你检查签名。

### 错误 3（隐蔽致命）：构造/析构期间调虚函数

```cpp
class Base {
public:
    Base() { init(); }              // ❌ 构造期间调虚函数
    virtual void init() { std::cout << "Base init"; }
};
class Derived : public Base {
public:
    void init() override { std::cout << "Derived init"; }
};
Derived d;   // 输出 "Base init"！不是 "Derived init"
```

**原因**：构造 `Derived` 时先构造 `Base` 子对象，此时对象的动态类型是 `Base`（`Derived` 还没开始构造），虚调用走 `Base::init`。析构同理（先析构派生部分，此时动态类型已变回 `Base`）。

**教训**：构造/析构期间**永远不要调虚函数**——它不会按你期望的多态分发。若要"构造时按派生类方式初始化"，让派生类构造函数显式传递参数给基类构造函数。

### 错误 4：虚函数默认实参不一致

见上文"核心用法 5"。`p->f()` 调用 `Derived::f` 但用 `Base` 的默认实参，输出令人困惑。**统一默认实参值**。

## 自测题

**1. 选择题**：以下哪种调用会触发动态绑定？

A. `d.f()` 其中 `d` 是 `Derived` 类型的对象
B. `Base& r = d; r.f();` 其中 `f` 是虚函数
C. `Base b = d; b.f();` 其中 `f` 是虚函数
D. `Base::f()` 显式限定调用

<details>
<summary>答案</summary>

**B**。动态绑定只在**通过引用或指针调用虚函数**时发生。A 是值对象调用（静态类型已知，静态绑定）；C 发生对象切片，`b` 是纯 `Base`，静态绑定；D 是显式限定（`Base::`），强制静态绑定。

</details>

**2. 判断题**：派生类覆盖虚函数时，如果基类版本有 `const` 限定而派生类版本没有，代码能编译通过（不写 `override` 时）。

<details>
<summary>答案</summary>

**对**（这是危险之处）。不写 `override` 时，签名不匹配会被当作"派生类定义了一个新函数，隐藏了基类版本"——编译能过，但行为是错的（通过基类指针调用走的是基类版本）。**写 `override` 后编译器会报错**——这正是 `override` 的价值。所以铁律：**凡是要覆盖的函数都写 `override`**。

</details>

**3. 踩坑题**：以下代码输出什么？为什么？

```cpp
class Base {
public:
    Base() { log(); }
    virtual void log() const { std::cout << "Base\n"; }
};
class Derived : public Base {
public:
    void log() const override { std::cout << "Derived\n"; }
};
int main() {
    Derived d;
}
```

<details>
<summary>答案</summary>

输出 **`Base`**。构造 `Derived d` 时先执行 `Base` 的构造函数，此时对象的动态类型仍是 `Base`（`Derived` 部分还没构造），所以 `log()` 走 `Base::log`。这是"构造期间调虚函数"的经典陷阱——它**不会**多态到 `Derived::log`。教训：构造/析构期间不要调虚函数。

</details>

**4. 应用题**：用虚函数设计一个简单的 `Logger` 体系——基类 `Logger` 提供 `log(msg)` 虚函数（默认打印到 stdout），派生类 `FileLogger` 覆盖它写入文件。要求：
- 基类析构安全
- 派生类用 `override` 标注
- 能通过 `Logger*` 多态调用

<details>
<summary>答案</summary>

```cpp
#include <iostream>
#include <fstream>
#include <string>
class Logger {
public:
    virtual ~Logger() = default;                         // 虚析构
    virtual void log(const std::string &msg) const {     // 虚函数，默认实现
        std::cout << "[stdout] " << msg << "\n";
    }
};
class FileLogger : public Logger {
public:
    explicit FileLogger(const std::string &path) : ofs_(path) { }
    void log(const std::string &msg) const override {    // override 标注
        if (ofs_) ofs_ << "[file] " << msg << "\n";
    }
private:
    mutable std::ofstream ofs_;   // log 是 const，文件流用 mutable
};
// 多态调用：
void run(Logger *lg) { lg->log("hello"); }   // 动态绑定到实际类型
```

要点：基类虚析构、`virtual` 声明、`override` 标注、`const` 成员函数 + `mutable` 文件流、通过基类指针多态调用。

</details>
