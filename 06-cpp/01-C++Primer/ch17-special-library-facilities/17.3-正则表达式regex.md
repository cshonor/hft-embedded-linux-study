# 正则表达式 regex

## 本节讲什么

本节讲解 C++11 `<regex>` 库——正则表达式全套工具：`std::regex`（正则对象）、`std::smatch`（匹配结果）、三大操作 `regex_match`/`regex_search`/`regex_replace`，以及迭代器遍历所有匹配。正则是文本处理的瑞士军刀——校验邮箱、提取数字、替换模式。

> **一句话定位**：`regex` = "用模式串描述文本结构，编译器/库帮你匹配、提取、替换"。

## 核心用法

### 1. 基本三件套

```cpp
#include <regex>
#include <string>
std::regex pat(R"(\d+)");         // 匹配连续数字
std::string s = "order 42 items";
std::smatch m;

// regex_search：查找第一个匹配（子串）
if (std::regex_search(s, m, pat)) {
    std::cout << m.str();          // "42"
    std::cout << m.position();     // 6（匹配起始位置）
}

// regex_match：完整匹配（整个字符串要符合模式）
std::regex email_pat(R"(\w+@\w+\.\w+)");
std::regex_match(std::string("a@b.com"), email_pat);    // true
std::regex_match(std::string("a@b.com extra"), email_pat); // false（未完整匹配）

// regex_replace：替换
std::string result = std::regex_replace(s, pat, std::string("##"));
// "order ## items"
```

### 2. 捕获组

用括号 `()` 捕获子匹配，`smatch` 用 `[i]` 访问：

```cpp
std::regex pat(R"((\w+)=(\d+))");    // 两个捕获组：键和值
std::string s = "count=42";
std::smatch m;
if (std::regex_search(s, m, pat)) {
    m[0];    // 整个匹配 "count=42"
    m[1];    // 第一组 "count"
    m[2];    // 第二组 "42"
}
```

### 3. 遍历所有匹配

```cpp
std::string s = "a1 b2 c3 d4";
std::regex pat(R"((\w)(\d))");
for (std::sregex_iterator it(s.begin(), s.end(), pat), end; it != end; ++it) {
    std::smatch m = *it;
    std::cout << m[1] << "->" << m[2] << "\n";   // a->1, b->2, c->3, d->4
}
```

### 4. 原始字符串字面量

正则里反斜杠多，用**原始字符串** `R"(...)"` 避免双重转义：

```cpp
std::regex r1("\\d+");        // 普通字符串：\\ 转义成 \，正则看到 \d+
std::regex r2(R"(\d+)");      // 原始字符串：直接写 \d+，无需转义
// 更复杂的：匹配 \w+@\w+\.\w+
std::regex r3("\\w+@\\w+\\.\\w+");    // 普通字符串，反斜杠地狱
std::regex r4(R"(\w+@\w+\.\w+)");     // 原始字符串，清晰
```

### 5. 正则语法选择

C++ 默认用 ECMAScript 语法（和 JavaScript 一样），也可选 POSIX 扩展等：

```cpp
std::regex r(R"(\d+)", std::regex::ECMAScript);           // 默认
std::regex r2(R"([0-9]+)", std::regex::extended);         // POSIX 扩展
std::regex r3(R"(\d+)", std::regex::ECMAScript | std::regex::icase);  // 忽略大小写
```

## 和 C 的区别

C 标准库**没有**正则——要靠 POSIX `regex.h` 或第三方库（PCRE）：

| 维度 | C（POSIX regex） | C++ `<regex>` |
|------|---------------|-------------|
| 标准化 | POSIX 非普遍（Windows 无） | C++11 标准，跨平台 |
| API 风格 | C 函数 + 手动管理 `regex_t` | RAII 对象，自动释放 |
| 匹配结果 | `regmatch_t` 数组 | `smatch` 对象，支持迭代 |
| 语法 | POSIX BRE/ERE | ECMAScript（更熟悉） |

```c
// C：POSIX regex（Linux 有，Windows 要额外库）
#include <regex.h>
regex_t re;
regcomp(&re, "[0-9]+", REG_EXTENDED);
regmatch_t match[1];
if (regexec(&re, "order 42", 1, match, 0) == 0) {
    // match[0].rm_so ... rm_eo 是匹配范围
}
regfree(&re);    // 手动释放
```

```cpp
// C++：RAII，自动释放
std::regex re(R"(\d+)");
std::smatch m;
if (std::regex_search(std::string("order 42"), m, re)) {
    std::cout << m.str();
}
// re 自动析构，无需手动 free
```

> **性能提示**：`std::regex` 构造开销大（编译正则），**不要在循环里反复构造**——把它做成 `static const` 或成员变量，只构造一次。极致性能场景可考虑 `re2` 库（线性时间匹配）。

## 常见错误

### 错误 1：`regex_match` vs `regex_search` 混淆

```cpp
std::regex pat(R"(\d+)");
std::regex_match(std::string("abc 42"), pat);     // false！整个字符串不全是数字
std::regex_search(std::string("abc 42"), pat);    // true，找到子串 "42"
```

`regex_match` 要求**整个字符串**匹配；`regex_search` 只要有**子串**匹配即可。这是最常踩的坑。

### 错误 2：循环里反复构造 regex

```cpp
for (auto &line : lines) {
    std::regex pat(R"(\d+)");    // ❌ 每次循环都编译正则，极慢
    std::regex_search(line, m, pat);
}
// 修复：提到循环外
std::regex pat(R"(\d+)");        // ✅ 只编译一次
for (auto &line : lines) {
    std::regex_search(line, m, pat);
}
```

### 错误 3：反斜杠转义错误

```cpp
std::regex r("\d+");      // ❌ \d 在 C++ 字符串里不是合法转义，警告或报错
std::regex r("\\d+");     // ✅ \\ 转义成 \，正则看到 \d
std::regex r(R"(\d+)");   // ✅ 原始字符串，最清晰
```

### 错误 4：贪婪匹配非预期

```cpp
std::regex r(R"(<.*>)");           // 贪婪：从第一个 < 匹配到最后一个 >
std::regex r(R"(<.*?>)");          // 非贪婪：匹配最近的 >
std::string s = "<a><b>";
std::regex_search(s, m, std::regex(R"(<.*>)"));   // m = "<a><b>"（贪婪）
std::regex_search(s, m, std::regex(R"(<.*?>)"));  // m = "<a>"（非贪婪）
```

`*`/`+` 默认贪婪，加 `?` 变非贪婪。

## 自测题

**1. 选择题**：以下哪个函数要求**整个字符串**都符合正则模式才算匹配？

A. `regex_search`
B. `regex_match`
C. `regex_replace`
D. `regex_find`

<details>
<summary>答案</summary>

**B**。`regex_match` 要求整个字符串从头到尾完整匹配；`regex_search` 只需找到子串匹配；`regex_replace` 是替换。`regex_find` 不存在。

</details>

**2. 判断题**：`std::regex` 对象构造一次后可重复用于多次匹配，无需每次重新构造。

<details>
<summary>答案</summary>

**对**。`regex` 对象内部编译了正则，构造开销大但匹配快。正确做法是构造一次、匹配多次。把它做成 `static const` 或类成员，避免循环里反复构造。

</details>

**3. 踩坑题**：以下代码期望提取 "42"，实际输出什么？

```cpp
std::regex pat(R"(\d+)");
std::string s = "abc 42 def";
std::smatch m;
if (std::regex_match(s, m, pat)) {
    std::cout << m.str();
} else {
    std::cout << "no match";
}
```

<details>
<summary>答案</summary>

输出 **"no match"**。`regex_match` 要求整个字符串 `s` 完全是数字，但 `s` 是 "abc 42 def"，不完整匹配。应改用 `regex_search`（查找子串）：
```cpp
if (std::regex_search(s, m, pat)) {  // ✅ 找到子串 "42"
    std::cout << m.str();            // 42
}
```

</details>

**4. 应用题**：写一个函数 `extract_emails(text)`，用正则提取文本中所有形如 `user@domain.com` 的邮箱，返回 `vector<string>`。

<details>
<summary>答案</summary>

```cpp
#include <regex>
#include <string>
#include <vector>
std::vector<std::string> extract_emails(const std::string &text) {
    std::vector<std::string> result;
    std::regex pat(R"([\w.]+@[\w.]+\.\w+)");    // 简化版邮箱正则
    for (std::sregex_iterator it(text.begin(), text.end(), pat), end; it != end; ++it) {
        result.push_back(it->str());
    }
    return result;
}
// 用法：
auto emails = extract_emails("contact: a@b.com or c@d.org");
// emails = {"a@b.com", "c@d.org"}
```

要点：`sregex_iterator` 遍历所有匹配、`it->str()` 取匹配文本、原始字符串避免转义地狱。注意这是简化正则，生产环境邮箱正则更复杂。

</details>
