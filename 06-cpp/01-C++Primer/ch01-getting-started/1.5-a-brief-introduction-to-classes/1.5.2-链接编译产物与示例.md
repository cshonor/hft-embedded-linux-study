# 1.5.2 链接、编译产物与示例

## 本节讲什么

编译链接流程、.o/.exe/.lib、示例代码。

## 链接：编译器怎么找到实现？

```
main.cpp  #include "Sales_item.h"
    ↓ 编译：编译器从头文件知道 isbn() 存在 → 能通过编译
    ↓
Sales_item.cpp  → 单独编译成目标文件
    ↓ 链接：把 item.isbn() 的调用点和 .cpp 里的实现「绑」在一起
    ↓
可执行文件 → 运行时正确执行 isbn() 里的代码
```

你在 `main` 里写 `item.isbn()` 时：
1. **编译阶段**：只看 `.h`，确认 `isbn()` 名字、参数对得上就行
2. **链接阶段**：去 `.cpp` 编译出的模块里找到 `isbn()` 的真正代码并接上

所以：**头文件给编译器看，实现文件给链接器接。**

## 编译产物：从 .cpp 到「成品」

GCC、Clang、MSVC、TCC 等编译器做的事一样：**把人写的代码翻译成机器码**。步骤拆开看：

```
Sales_item.cpp  ──编译──►  Sales_item.o     （目标文件：机器码，还不能单独跑）
main.cpp        ──编译──►  main.o
                              │
                              ▼ 链接（把 .o 和库绑在一起）
                         ┌────┴────┐
                         ▼         ▼
                    book.exe    libSales.a / Sales.dll
                  （可执行程序）  （给别人用的库）
```

| 产物 | 常见后缀 | 是什么 | 给谁用 |
|------|----------|--------|--------|
| **目标文件** | `.o` / `.obj` | 单个 `.cpp` 编译出的机器码片段 | 链接器内部用，一般不单独给别人 |
| **可执行文件** | `.exe`（Windows）/ 无后缀（Linux） | 能直接运行的完整程序 | **终端用户**双击/命令行运行 |
| **静态库** | `.lib`（MSVC）/ `.a`（GCC/Clang） | 实现代码打包进库，链接时拷进你的程序 | **开发者**在自己的项目里链接 |
| **动态库** | `.dll`（Windows）/ `.so`（Linux） | 实现代码在单独文件里，运行时加载 | **开发者**链接 + 运行时带上 dll |

### 给别人当「模块」调用，给什么？

**不是** `.exe` + `.h`。

- **`.exe`**：成品程序，给**用户运行**的，不能当 SDK 让别人链接。
- **给别人调用你的类/函数**，应提供：

| 场景 | 给别人什么 |
|------|------------|
| **静态库** | `.h` + `.lib`（或 `.a`） |
| **动态库** | `.h` + `.lib`（导入库）+ `.dll`（运行时要有） |

对方在自己的项目里 `#include "Sales_item.h"`，链接你的 `.lib`，就能调 `isbn()` 等方法，**全程看不到你的 `.cpp` 源码**。

### Windows 上记一句

```
想让别人「调用你的模块」  →  .h + .lib（+ .dll）
想让别人「直接跑你的程序」  →  .exe（一般不需要给 .h）
```

HFT 里核心策略/行情解析常做成 **静态库或动态库 + 头文件**，交易主程序只链接接口，实现藏在二进制里。

## 头文件长什么样？（`Sales_item.h` 极简版）

```cpp
#pragma once              // 防止头文件被重复包含（也可用 #ifndef 守卫）

#include <string>

class Sales_item {
public:
    std::string isbn() const;   // 声明：有这个方法，具体实现在 .cpp
    // ... 其他 public 接口（>>、<<、+ 等）

private:
    std::string bookNo;         // 数据成员：外部不能直接改
    unsigned units_sold = 0;
    double revenue = 0.0;
};
```

别人 `#include "Sales_item.h"` 之后就知道怎么调 `isbn()`，但**看不到**函数体，也**碰不到** `private` 里的 `bookNo`。

**`Sales_item.cpp`（实现放这里）：**

```cpp
#include "Sales_item.h"

std::string Sales_item::isbn() const {
    return bookNo;              // 具体怎么取书号，写在这里
}
```

## 示例

```cpp
// 需配合书中 Sales_item 头文件使用；此处为用法示意
#include <iostream>
#include "Sales_item.h"

int main() {
    Sales_item item;
    std::cin >> item;                          // 从输入读取一条销售记录
    std::cout << item << std::endl;            // 打印该记录
    std::cout << item.isbn() << std::endl;     // 调用成员函数获取书号

    Sales_item item2;
    std::cin >> item2;
    Sales_item sum = item + item2;             // 两笔销售记录相加
    std::cout << sum << std::endl;
    return 0;
}
```

## 和 C 的区别

编译链接流程 C 和 C++ 基本一样，但有几个 C++ 特有的坑：

| 对比点 | C | C++ |
|--------|---|-----|
| 编译产物 | `.o` / `.exe` / `.a` / `.so` | 完全一样 |
| 函数符号名 | 就是函数名（`isbn`） | **名字改编**（`_ZN10Sales_item4isbnEv`） | 
| 混合编程 | — | C++ 调 C 要 `extern "C"` |
| 头文件守卫 | `#ifndef` 守卫 | `#ifndef` 或 `#pragma once` |

**名字改编（name mangling）：** C++ 支持重载（同名函数不同参数），编译器要把参数信息编进符号名才能区分。所以 `Sales_item::isbn()` 在 `.o` 里不叫 `isbn`，而是一串带类名和参数的符号。

**`extern "C"` 的用途：** C 的符号名就是函数名（不改编）。C++ 要调 C 的库，得告诉编译器"这个函数按 C 规则找符号"：
```cpp
extern "C" {
    #include "some_c_library.h"   // 按 C 规则链接，不做名字改编
}
```
HFT 里常碰：行情网关是 C 写的，C++ 策略层调它就要 `extern "C"`。

## 常见错误

**1. 头文件循环包含 / 重复包含**
```cpp
// a.h 包含 b.h，b.h 又包含 a.h → 死循环
```
用头文件守卫：
```cpp
#ifndef SALES_ITEM_H
#define SALES_ITEM_H
// ... 类声明
#endif
```
或更简洁的 `#pragma once`（主流编译器都支持）。

**2. 链接时找不到实现（undefined reference）**
```
undefined reference to `Sales_item::isbn() const'
```
原因：`.cpp` 没参与编译，或忘写 `Sales_item::` 前缀，或实现和声明签名不一致。检查 `g++ main.cpp Sales_item.cpp`（两个都要列上）。

**3. C++ 调 C 库忘加 `extern "C"`**
```cpp
#include "c_lib.h"           // C 头文件
c_function();                // 链接报错：找不到 _Z11c_functionv
```
C++ 默认按改编后的名字找，但 C 库里是原名。要 `extern "C" { #include "c_lib.h" }`。

## 自测题

**1（选择）** 下面哪个是 C++ 相对 C 在编译链接上的特有问题？
- A. 头文件重复包含
- B. 函数名字改编导致调 C 库要 `extern "C"`
- C. `.o` 文件格式不同

**2（判断）** `#pragma once` 和 `#ifndef` 守卫作用相同，都是防头文件重复包含。

**3（踩坑）** 编译命令 `g++ main.cpp` 报 `undefined reference to Sales_item::isbn()`，最可能的原因是什么？

<details><summary>参考答案</summary>
1. B。名字改编是 C++ 独有（因重载），C 没有这个问题。头文件重复包含两边都有，`.o` 格式也通用。
2. 对。两者都防重复包含。`#pragma once` 更简洁但非标准（虽主流支持）；`#ifndef` 是标准 C/C++，可移植性最好。
3. `Sales_item.cpp` 没参与编译/链接。要写 `g++ main.cpp Sales_item.cpp`，或分开 `g++ -c main.cpp`、`g++ -c Sales_item.cpp` 再 `g++ main.o Sales_item.o`。
</details>
