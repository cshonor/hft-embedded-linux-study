# 9.1 容器概览与操作

## 本节讲什么

C++ 标准库的**顺序容器**：`vector`、`deque`、`list`、`forward_list`、`array`、`string`。本节概览各容器特性、选型建议，以及公共操作（增删改查、大小管理）。**C 没有任何标准容器**——这是 C 程序员转 C++ 最直接的红利。

## 核心用法

### 顺序容器一览

| 容器 | 底层结构 | 随机访问 | 头尾增删 | 中间增删 | 迭代器失效 |
|------|---------|---------|---------|---------|-----------|
| `vector` | 动态数组 | O(1) | 尾 O(1) | O(n) | 扩容/插入/删除全失效 |
| `string` | 动态数组（char） | O(1) | 尾 O(1) | O(n) | 同 vector |
| `deque` | 分段连续 | O(1) | 头尾 O(1) | O(n) | 部分失效 |
| `array` | 固定数组 | O(1) | ❌ 不能 | O(n) | — |
| `list` | 双向链表 | ❌ | 头尾 O(1) | O(1)（已知位置） | 仅被删元素失效 |
| `forward_list` | 单向链表 | ❌ | 头 O(1) | O(1)（已知位置） | 仅被删元素失效 |

### 选型建议（关键！）

- **默认用 `vector`**：连续内存，cache 友好，绝大多数场景最优
- 频繁头尾增删 → `deque`
- 频繁中间增删（且已持有迭代器）→ `list`/`forward_list`
- 大小固定 → `array`（替代 C 数组）
- 字符串 → `string`（替代 `char[]`）

### 公共操作

```cpp
std::vector<int> v = {1, 2, 3};

v.push_back(4);          // 尾部添加
v.pop_back();            // 尾部删除
v.emplace_back(5);       // 尾部原地构造（避免临时对象）
v.size();                // 元素数
v.empty();               // 是否空
v.clear();               // 清空
v.erase(v.begin());      // 删除指定位置
v.insert(v.begin(), 0);  // 指定位置插入
v.resize(10);            // 改变大小
```

### 迭代器遍历

```cpp
for (auto it = v.begin(); it != v.end(); ++it) { /* *it */ }
for (auto& x : v) { /* x 是引用，可修改 */ }       // 范围 for，更简洁
```

## 和 C 的区别

| 维度 | C | C++ |
|------|---|-----|
| 动态数组 | 手写 `malloc`/`realloc` + 手动管理大小 | `vector` 自动管理 |
| 链表 | 手写 struct + 指针操作 | `list` 现成 |
| 队列/栈 | 手写或调非标准库 | `queue`/`stack` |
| 边界检查 | ❌ 全靠自觉 | `at()` 有检查，`[]` 无（同 C） |
| 内存管理 | 手动 malloc/free | RAII 自动释放 |
| 通用算法 | 自己写 | `<algorithm>` 提供排序/查找等 |

**C 程序员最该体会的**：

C 里"动态数组"要手写 realloc + memcpy + 大小管理，几十行易错代码：
```c
/* C：手写动态数组 */
int* arr = NULL;
size_t size = 0, cap = 0;
void push(int x) {
    if (size == cap) {
        cap = cap ? cap * 2 : 4;
        arr = realloc(arr, cap * sizeof(int));   // 忘了检查返回值就 UB
    }
    arr[size++] = x;
}
// 还要记得 free(arr)，忘了就泄漏
```

C++ 的 `vector` 一行搞定，且析构自动释放：
```cpp
std::vector<int> v;
v.push_back(x);    // 自动扩容，自动管理
// 析构自动释放，不泄漏
```

这是从"手写基础设施"到"直接用现成"的飞跃——省下的精力用于业务逻辑。

## 常见错误

1. **用 `[]` 越界访问不报错**：`v[v.size()]` 越界但 `[]` 不检查，UB（可能看似正常，可能崩溃）。**修正**：需要检查用 `v.at(i)`（越界抛 `out_of_range`），或严格保证不越界。
2. **迭代器失效后继续用**：`v.push_back` 触发扩容后，之前存的迭代器全失效，再用 UB。**修正**：扩容后重新获取迭代器；HFT 热路径用 `reserve` 预留避免扩容。
3. **选错容器**：频繁中间插入用 vector（O(n) 移动），应该用 list；需要随机访问用 list（O(n) 遍历），应该用 vector。选型错误导致性能差。

## 自测题

**1. 选择题**：下面哪种场景 `std::list` 比 `std::vector` 更合适？
- A) 需要随机访问 `arr[i]`
- B) 频繁在尾部追加
- C) 频繁在中间插入/删除，且已持有迭代器
- D) 数据量小，要 cache 友好

<details><summary>答案</summary>

C。list 是链表，中间插入/删除（已知位置）是 O(1)，vector 是 O(n) 移动元素。A 要随机访问用 vector；B 尾部追加 vector 更优（连续内存）；D 小数据 vector cache 友好更快。实践中 list 用得少——vector 的连续内存优势通常盖过 list 的插入优势，除非插入极频繁。

</details>

**2. 判断题**：`std::vector<int> v; v[0] = 1;` 在 v 为空时是未定义行为。

<details><summary>答案</summary>

正确。`[]` 不做边界检查，空 vector 访问 `v[0]` 越界，UB（可能崩溃、可能写坏内存）。要安全访问用 `v.at(0)`（抛异常）或先 `push_back`/`resize`。这是 C/C++ 共同坑——C 数组越界也是 UB。

</details>

**3. 踩坑题**：下面代码想删除所有偶数，但结果不对，为什么？
```cpp
std::vector<int> v = {1, 2, 3, 4, 5, 6};
for (auto it = v.begin(); it != v.end(); ++it) {
    if (*it % 2 == 0) v.erase(it);
}
```

<details><summary>答案</summary>

`erase` 返回下一个有效迭代器，但循环里 `++it` 在 erase 后用的是已失效的迭代器，导致跳过元素或 UB。**正确写法**：
```cpp
for (auto it = v.begin(); it != v.end(); ) {
    if (*it % 2 == 0) it = v.erase(it);   // erase 返回下一个，不 ++it
    else ++it;
}
```
或更简洁用 erase-remove 惯用法：`v.erase(std::remove_if(v.begin(), v.end(), [](int x){return x%2==0;}), v.end());`

</details>

**4. 应用题**：实现一个简单的"最近 N 条消息"缓冲区——保存最近 N 条，超出自动丢弃最旧的。选什么容器？写出关键代码。

<details><summary>答案</summary>

用 `std::deque`（头尾 O(1)）或环形 buffer。deque 版本：
```cpp
#include <deque>
std::deque<std::string> recent;
size_t N = 100;
void add(const std::string& msg) {
    recent.push_back(msg);
    if (recent.size() > N) recent.pop_front();   // 丢弃最旧
}
```
vector 也可（erase 头部 O(n)），但 N 大时 deque 头部弹出更高效。HFT 实战常用固定大小环形 buffer（vector 预留 N + 取模索引）避免任何动态分配。

</details>
