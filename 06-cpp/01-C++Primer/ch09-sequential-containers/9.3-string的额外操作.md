# 9.3 string 的额外操作

## 本节讲什么

把 `string` 视作"元素的 char 特化容器"之外，它还有大量**额外操作**：子串、拼接、替换、搜索、与数值互转。本节梳理这些 C 字符串函数（`str*` 族）的 C++ 现代替代品。

## 核心用法

### 构造与子串

```cpp
std::string s("hello world");
std::string sub = s.substr(0, 5);    // "hello"（位置 0 起 5 个字符）
std::string s2(s, 6);                 // "world"（位置 6 到末尾）
```

### 拼接与追加

```cpp
std::string s = "hello";
s += " world";                       // 追加
s.append("!!!");                     // 等价
s.push_back('!');                    // 追加单字符
```

### 替换与插入

```cpp
std::string s = "hello world";
s.replace(6, 5, "C++");              // 位置 6 起 5 个字符替换为 "C++" → "hello C++"
s.insert(5, ",");                    // 位置 5 插入 "," → "hello, C++"
s.erase(5, 1);                       // 位置 5 起删 1 个字符
```

### 搜索

```cpp
std::string s = "hello world";
auto pos = s.find("world");          // 6（找到返回位置）
auto pos2 = s.find("xyz");           // std::string::npos（没找到）
if (pos != std::string::npos) { /* 找到 */ }

s.rfind("o");                        // 从后往前找，7
s.find_first_of("aeiou");            // 找第一个元音，1
s.find_last_of("o");                 // 最后一个 o，7
```

### 数值与字符串互转（C++11）

```cpp
std::to_string(42);                  // "42"
std::to_string(3.14);                // "3.140000"
std::stoi("42abc");                  // 42（解析到非数字停）
std::stod("3.14xyz");                // 3.14
size_t idx;
int n = std::stoi("42abc", &idx);    // n=42, idx=2（消耗字符数）
```

## 和 C 的区别

| 维度 | C | C++ |
|------|---|-----|
| 字符串类型 | `char[]` + `'\0'` | `std::string`（带长度，不靠 '\0'） |
| 长度 | `strlen` O(n) 遍历 | `s.size()` O(1) |
| 拼接 | `strcat`/`strncat`（易溢出） | `+=`/`append`（自动扩容） |
| 子串 | `strncpy` + 手动算偏移 | `substr` |
| 查找 | `strstr`/`strchr` | `find`/`rfind`/`find_first_of` |
| 数值转换 | `atoi`/`sprintf`/`sscanf`（不安全/易错） | `stoi`/`to_string`（类型安全） |
| 内存管理 | 手动 malloc/free | RAII 自动 |
| 溢出风险 | 高（strcat/sprintf 易溢出） | 无（自动扩容） |

**C 程序员最该体会的**：

1. **不溢出 + 自动管理内存**：C 的字符串操作是安全重灾区（`strcat`/`strcpy`/`sprintf` 都易溢出，导致安全漏洞）。`std::string` 自动扩容，从根本上消除溢出。

```c
/* C：strcat 溢出风险 */
char buf[10] = "hi";
strcat(buf, " world");    // 超过 10 字节，溢出 UB，可能被利用
```
```cpp
// C++：自动扩容，不溢出
std::string s = "hi";
s += " world";            // 自动扩容，安全
```

2. **长度 O(1)**：C 的 `strlen` 要遍历到 `'\0'`，O(n)。`string::size()` 直接读存的长度，O(1)。循环里频繁取长度时差异明显。

3. **数值转换类型安全**：C 的 `atoi("abc")` 返回 0（无法区分"0"和"错误"），`sprintf` 格式串易错。C++ 的 `stoi` 可通过 `idx` 和异常区分错误。

## 常见错误

1. **`find` 不检查 `npos` 就用结果**：`s[s.find("x")]` —— 没找到时返回 `npos`（一个很大的数，通常 size_t 最大值），用作下标越界 UB。**修正**：`auto pos = s.find("x"); if (pos != npos) {...}`。
2. **`stoi` 不检查异常**：`stoi("")` 或 `stoi("99999999999999")`（溢出）会抛 `invalid_argument`/`out_of_range`。不 catch 就崩溃。**修正**：try/catch 或先校验。
3. **混用 `string` 和 C 字符串接口**：把 `string` 传给要 `char*` 的 C 函数，要用 `s.c_str()`（返回 const char*）。修改 C 函数的内容要用 `&s[0]`（C++17 起保证连续）且确保有 `'\0'`。

## 自测题

**1. 选择题**：`std::string("hello").find("xyz")` 的返回值是？
- A) 0
- B) -1
- C) `std::string::npos`
- D) 抛异常

<details><summary>答案</summary>

C。`find` 没找到返回 `std::string::npos`（一个特殊值，通常等于 `size_t(-1)`，是个很大的无符号数）。不返回 -1（int 的 -1），不抛异常。**关键**：判断找到与否必须 `pos != npos`，不能 `pos != -1`（虽然数值常相等，但类型不同，习惯要正确）。

</details>

**2. 判断题**：`std::string s; std::cout << s.size();` 输出 0，且 s 内部没有 '\0'。

<details><summary>答案</summary>

前半正确（size 是 0），后半"没有 '\0'"不准确。`std::string` 不靠 '\0' 计长度（靠存的 size 成员），但 `c_str()` 返回的 C 字符串保证以 '\0' 结尾，所以内部通常有个 '\0' 在末尾（C++11 起保证连续且 '\0' 结尾）。但这个 '\0' 不计入 size。

</details>

**3. 踩坑题**：下面代码想取 "world" 子串，但结果是空串，为什么？
```cpp
std::string s = "hello world";
std::string sub = s.substr(6, 5);    // 想取 "world"
std::cout << sub;   // 实际输出 "world"，没问题？
```
等等，再看这个：
```cpp
std::string s = "hello world";
std::string sub = s.substr(6, 11);   // 想取位置 6 到末尾
```

<details><summary>答案</summary>

第一个是对的，输出 "world"。第二个的 `substr(6, 11)` 中第二个参数是**长度**不是结束位置，"hello world" 从位置 6 到末尾只有 5 个字符（"world"），请求 11 个但只有 5 个，`substr` 不会越界，自动取到末尾返回 "world"。但如果你以为第二个参数是结束下标（像 Python 的切片），会困惑。**记法**：`substr(pos, len)`，pos 是起始，len 是长度。

</details>

**4. 应用题**：写一个安全的"解析配置行 `key=value`"函数，把 key 和 value 分离。对比 C 的 `strtok` 方案。

<details><summary>答案</summary>

```cpp
#include <string>
bool parse(const std::string& line, std::string& key, std::string& val) {
    auto pos = line.find('=');
    if (pos == std::string::npos) return false;    // 没找到 =
    key = line.substr(0, pos);                     // = 之前
    val = line.substr(pos + 1);                    // = 之后到末尾
    return true;
}
```
对比 C 的 `strtok`：
```c
/* C：strtok 破坏原串、非线程安全、要可变缓冲 */
char buf[256];
strcpy(buf, line);            // strtok 要修改，得先拷贝
char* key = strtok(buf, "=");
char* val = strtok(NULL, "");
```
C++ 版：1) 不破坏原串（const 引用）；2) 线程安全；3) 不用管缓冲区大小；4) 类型安全。strtok 的"非重入"是 C 字符串处理的经典坑。

</details>
