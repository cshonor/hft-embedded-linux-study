# 9.4 容器适配器

## 本节讲什么

**容器适配器**（adapter）：`stack`（栈）、`queue`（队列）、`priority_queue`（优先队列）。它们不是独立容器，而是对底层容器（默认 `deque`/`vector`）的接口包装，只暴露特定行为。C 没有标准库提供这些，全靠手写。

## 核心用法

### stack（栈，LIFO）

```cpp
#include <stack>
std::stack<int> s;       // 默认底层 deque
s.push(1); s.push(2);
s.top();                 // 2（看栈顶，不弹出）
s.pop();                 // 弹出栈顶（无返回值！）
s.size(); s.empty();
```
| 操作 | 复杂度 |
|------|--------|
| push/pop | O(1) |
| top | O(1) |

### queue（队列，FIFO）

```cpp
#include <queue>
std::queue<int> q;       // 默认底层 deque
q.push(1); q.push(2);
q.front();               // 1（队首）
q.back();                // 2（队尾）
q.pop();                 // 弹出队首
```

### priority_queue（优先队列，最大堆）

```cpp
#include <queue>
std::priority_queue<int> pq;    // 默认 vector + 最大堆
pq.push(3); pq.push(1); pq.push(2);
pq.top();                // 3（最大值在顶）
pq.pop();                // 弹出最大值

// 最小堆：用 greater 作比较器
std::priority_queue<int, std::vector<int>, std::greater<int>> min_pq;
min_pq.push(3); min_pq.push(1);
min_pq.top();            // 1（最小值在顶）
```
| 操作 | 复杂度 |
|------|--------|
| push/pop | O(log n) |
| top | O(1) |

### 自定义底层容器

```cpp
// stack 默认用 deque，可换 vector 或 list
std::stack<int, std::vector<int>> s;    // 底层 vector
std::stack<int, std::list<int>> s2;     // 底层 list
```

## 和 C 的区别

| 维度 | C | C++ |
|------|---|-----|
| 栈 | 手写数组 + top 指针 | `stack` 现成 |
| 队列 | 手写数组（环形 buffer）或链表 | `queue` 现成 |
| 优先队列 | 手写堆（极繁琐） | `priority_queue` 现成 |
| 边界保护 | ❌ 全靠自觉 | 有 empty() 检查 |
| 内存管理 | 手动 | RAII |

**C 程序员最该体会的**：

C 里栈/队列要手写几十行，优先队列（堆）更繁琐易错：
```c
/* C：手写栈 */
int stack[100], top = -1;
void push(int x) { stack[++top] = x; }
int pop(void) { return stack[top--]; }   // 空栈时越界 UB
int peek(void) { return stack[top]; }
// 没有边界检查，没有泛型，每个类型重写一遍
```

C++ 一个模板类搞定，类型安全，边界可查：
```cpp
std::stack<int> s;
s.push(1);
if (!s.empty()) s.pop();    // 安全检查
// 想要 stack<string>？改一个字就行
```

优先队列差距更大——C 手写堆（sift up/down）极繁琐，C++ 的 `priority_queue` 一行声明。

## 常见错误

1. **空栈/空队列调 top/front**：`std::stack<int> s; s.top();` —— 空栈访问 top 是 UB。**修正**：先 `if (!s.empty())`。
2. **以为 pop 返回元素**：`int x = s.pop();` —— C++ 的 stack/queue 的 `pop` 返回 **void**（不返回弹出值）。要先 `top()`/`front()` 取值再 `pop()`。这是与某些其他语言（Java 的 `pop` 返回值）的区别。
3. **priority_queue 想要最小堆写错比较器**：默认是 `less`（最大堆），要最小堆用 `greater`。容易搞反——`less` 反直觉地对应最大堆，因为"less"描述的是父子关系。

## 自测题

**1. 选择题**：`std::priority_queue<int>` 默认是？
- A) 最小堆（top 是最小值）
- B) 最大堆（top 是最大值）
- C) 按插入顺序
- D) 随机

<details><summary>答案</summary>

B。默认 `priority_queue` 用 `less<int>` 作比较器，top 是最大值（最大堆）。要最小堆用 `std::greater<int>`：`std::priority_queue<int, std::vector<int>, std::greater<int>>`。这个"less 对应最大堆"反直觉，记法：比较器定义的是"父节点应优于子节点"的序，less 意味着父应不小于子→父最大。

</details>

**2. 判断题**：`std::stack<int> s; int x = s.pop();` 能正确取出栈顶元素。

<details><summary>答案</summary>

错误。C++ 标准库的 `stack::pop()` 返回 **void**，不返回弹出值（出于异常安全考虑——若 pop 先拷贝再删除，拷贝抛异常则元素既没取出也没了）。要先 `int x = s.top();` 再 `s.pop();`。这是 C++ 容器适配器的设计哲学，与 Java 的 Stack.pop() 返回值不同。

</details>

**3. 踩坑题**：下面代码用优先队列处理任务，但发现每次取的不是最紧急的，为什么？
```cpp
struct Task { int priority; std::string name; };
std::priority_queue<Task> pq;     // 想优先级高的先处理
pq.push({1, "low"});
pq.push({5, "high"});
auto t = pq.top();                // 期望拿到 high，但...
```

<details><summary>答案</summary>

`priority_queue<Task>` 默认用 `less<Task>`，但 `Task` 没定义 `operator<`，编译错误或行为未定义。需要自定义比较器：
```cpp
auto cmp = [](const Task& a, const Task& b){ return a.priority < b.priority; };
std::priority_queue<Task, std::vector<Task>, decltype(cmp)> pq(cmp);
```
或给 Task 定义 `operator<`（按 priority 排）。自定义类型用 priority_queue 必须提供比较方式，否则编译失败。

</details>

**4. 应用题**：用 `priority_queue` 实现一个"实时求中位数"的结构：随时插入数字，随时能查当前中位数。提示：用两个堆。

<details><summary>答案</summary>

```cpp
#include <queue>

class MedianFinder {
    std::priority_queue<int> left;     // 最大堆，存较小的一半
    std::priority_queue<int, std::vector<int>, std::greater<int>> right;  // 最小堆，较大的一半
public:
    void addNum(int num) {
        left.push(num);
        right.push(left.top()); left.pop();    // 平衡
        if (left.size() < right.size()) {      // 维持 left >= right
            left.push(right.top()); right.pop();
        }
    }
    double findMedian() {
        if (left.size() > right.size()) return left.top();
        return (left.top() + right.top()) / 2.0;
    }
};
```
思路：最大堆 left 存较小半，最小堆 right 存较大半，保持 left.size >= right.size。中位数在 left.top（奇数个）或两堆 top 平均（偶数个）。C 手写两个堆极繁琐，C++ 直接用 priority_queue。O(log n) 插入，O(1) 查中位数。

</details>
