# 3.2.6 HFT 场景拓展

## 本节讲什么

FIX 报文切分、日志拼接、合约/订单文本字段；本章背诵极简版与综合示例。

## 1. FIX 报文（简化示意）

FIX 是交易所常见的**键值对 + 分隔符**文本（`|` 或 `\001` SOH）。`string` 适合整段持有报文，再 `find` / `substr` 取字段：

```cpp
#include <string>

// 简化：用 '|' 代替 SOH
std::string fix = "8=FIX.4.2|35=D|11=OID1001|55=IF2406|38=10|";

std::string tag_11;   // ClOrdID
auto pos = fix.find("11=");
if (pos != std::string::npos) {
    auto start = pos + 3;
    auto end = fix.find('|', start);
    tag_11 = fix.substr(start, end - start);   // "OID1001"
}
```

生产环境会用专业 FIX 库；这里说明 **`string` 是报文容器 + 字段切分的基础**。

## 2. 日志拼接

```cpp
std::string log;
log += "[";
log += std::to_string(order_id);   // C++11
log += "] send ";
log += symbol;
log += " qty=";
log += std::to_string(qty);
// 或一次拼接："[123] send IF2406 qty=10"
```

热路径上若频繁拼接，用 **`reserve` + `append`**（见 [3.2.3](./3.2.3-拼接与内存优化.md)）；固定长度字段用 **`char[N]` / `std::array`** 避免动态分配（见 [3.2.4](./3.2.4-string与C风格字符串.md)）。

## 3. 合约 / 订单文本

- 合约代码：`"IF2406"`、`"600519.SH"` —— `string` 比较、哈希、作 map 键
- 与 [2.6 Sales_data](../ch02-variables-and-basic-types/2.6-custom-data-structures/2.6.1-Sales_data入门与聚合.md) 的 `bookNo` 同类：**业务文本字段用 `string`，数值用算术类型**

## 和 C 的区别（HFT 场景下的对照）

C 程序员写 FIX 解析、日志拼接这些活，习惯的"家伙事"是 `char[]` + `strtok`/`strstr`/`strncpy` + `sprintf`。改用 `std::string` 后，**心智负担**和**出错面**都明显小：

| 场景 | C 写法 | C++ 写法（string） |
|------|--------|---------------------|
| 持有报文 | `char buf[256];` 固定大小，怕溢出 | `std::string fix = "...";` 自动扩容 |
| 找子串 | `strstr(fix, "11=")` 返回 `char*` 或 NULL | `fix.find("11=")` 返回 `size_t` 或 `npos` |
| 取字段 | `strncpy(out, p+3, len);` 手算长度+末尾 `\0` | `fix.substr(start, end - start);` 自动管理 |
| 拼数字到字符串 | `sprintf(buf, "[%d] send %s qty=%d", ...)` 怕缓冲不够 | `log += std::to_string(id);` 自动扩容 |
| 字符串比较 | `strcmp(s1, s2) == 0` | `s1 == s2` |
| 内存释放 | 函数里 `malloc` 的 `char*` 必须 `free` | 析构自动释放（RAII） |

**给 C 程序员的关键提醒：**
1. `strtok` 是**破坏性**切分（往原串塞 `\0`），且非线程安全；C++ 用 `find` + `substr` 不动原串
2. `strstr` 返回的指针**指向原串内部**，原串销毁就悬垂；`string::find` 返回位置索引，`substr` 返回新串（拷贝）
3. HFT 热路径上 `string` 也有代价：`+=`/`+`/`substr` 可能触发堆分配。固定字段用 `char[N]`，可变长用 `string` + `reserve`

## 背诵极简版

```
C 字符串：裸内存+手动；string：封装+RAII+运算符
HFT 一般 string；热路径固定 char[N]/array + RAII 折中
HFT 热路径：reserve+append 代替 +；少临时、少碎片
s3=s1+s2：至少 1 临时 + 多次分配；+= 改 s1 更省
C char*：指首字符；声明用 char *p（勿写 char* p,q 坑）
const int*p 指向常量；int*const p 常量指针（见 2.4.1）
读：>> 连续空白当分隔符，逐字段；getline 保留空格读到换行
HFT：cin>> 拆订单号/价/量；getline 读备注与日志
拼接 +/+=  比较 ==  长度 size/empty
vs char*：string 安全；C 接口用 c_str() 过渡
cctype：isalpha/isdigit；参数 unsigned char→int
HFT：校验合约全字母、价格全数字
```

## 示例

```cpp
#include <iostream>
#include <string>
#include <cctype>

int main() {
    std::string s1 = "hello", s2;
    s2 = s1;
    s1 = "world";
    std::cout << s1 << " " << s2 << std::endl;  // world hello

    std::string greeting = s1 + ", " + s2;
    std::cout << greeting << std::endl;

    std::string line;
    std::getline(std::cin, line);

    for (unsigned char c : s1) {
        if (std::isalpha(c))
            std::cout << static_cast<char>(std::toupper(c));
    }
    std::cout << std::endl;

    return 0;
}
```

## 常见错误

### 1. `find` 不判断 `npos` 直接用返回值

```cpp
auto pos = fix.find("11=");
auto end = fix.find('|', pos + 3);   // 若 pos == npos，pos+3 溢出
tag_11 = fix.substr(pos + 3, ...);   // 越界，行为未定义
```

**正确**：必须 `if (pos != std::string::npos)` 再用。C 里 `strstr` 返回 NULL 还能靠 `if (p)` 挡一下，`find` 返回的是 `size_t`（无符号），不判就会变成一个大数。

### 2. `to_string` 拼接产生大量临时 string

```cpp
log = "[" + std::to_string(id) + "] " + symbol;   // 3 个临时串
```

热路径上每个 `+` 都可能分配一次堆。**改用 `+=` 或 `reserve + append`**，见 [3.2.3](./3.2.3-拼接与内存优化.md)。C 程序员的 `sprintf` 写进固定 `char[]` 也是一种"零分配"思路，知道何时选用。

### 3. 拿到 `c_str()` 后又改了原 string

```cpp
const char* p = s.c_str();
s += "tail";        // p 可能失效（string 重新分配）
printf("%s", p);    // ❌ 悬垂指针
```

`c_str()` 返回的指针**只在 string 不变时有效**。要长期持有，先 `strcpy` 到自己的缓冲，或保留 string 本身。

## 自测题

**1. 选择题**　用 `std::string` 做 FIX 报文字段切分，相比 C 的 `strtok`，下列哪条**不是** string 的优势？

- A. 不破坏原串内容
- B. 线程安全
- C. 自动管理内存，无需手动 free
- D. 切分速度比 strtok 快一个数量级

<details><summary>答案</summary>

**D**。`string::find` + `substr` 每次切出一个新 string 会拷贝；`strtok` 直接在原内存上塞 `\0`，单看切分本身 `strtok` 通常更快。string 的优势是**安全和易用**，不是切分速度。

</details>

**2. 判断题**　`std::string::find` 找不到子串时返回 `-1`，可以直接用 `if (pos < 0)` 判断。

<details><summary>答案</summary>

**错**。`find` 返回 `size_t`（无符号整数），找不到时返回 `std::string::npos`（一个很大的正数，通常是 `size_t(-1)`）。`pos < 0` 永远为 false。必须用 `pos != std::string::npos` 判断。

</details>

**3. 踩坑题**　下面这段 HFT 日志拼接代码，问题出在哪？

```cpp
std::string make_log(int id, const char* sym, int qty) {
    return "[" + std::to_string(id) + "] send " + sym + " qty=" + std::to_string(qty);
}
```

<details><summary>答案</summary>

热路径上**每次调用产生多个临时 string**：`"["` 提升为临时 string、`+ to_string` 产生临时、再 `+ sym` 又产生临时……总共可能 4-5 次堆分配。延迟敏感场景应改：

```cpp
std::string log;
log.reserve(64);
log += "["; log += std::to_string(id); log += "] send ";
log += sym; log += " qty="; log += std::to_string(qty);
return log;   // NRVO 或移动，无深拷贝
```

</details>

**4. 应用题**　写一段代码，从 `std::string fix = "8=FIX.4.2|35=D|55=IF2406|38=10|";` 中**安全**地提取 tag `55`（合约代码）的值。要求处理"找不到"的情况。

<details><summary>答案</summary>

```cpp
std::string get_tag(const std::string& fix, const std::string& tag) {
    std::string key = tag + "=";           // 如 "55="
    auto pos = fix.find(key);
    if (pos == std::string::npos) return "";   // 找不到返回空
    auto start = pos + key.size();
    auto end = fix.find('|', start);
    if (end == std::string::npos) end = fix.size();  // 末尾无 '|'
    return fix.substr(start, end - start);
}
// get_tag(fix, "55") → "IF2406"
```

**C 程序员易踩**：忘记处理末尾无 `|` 的情况——C 里 `strtok` 也会在最后一段处理上出问题。

</details>
