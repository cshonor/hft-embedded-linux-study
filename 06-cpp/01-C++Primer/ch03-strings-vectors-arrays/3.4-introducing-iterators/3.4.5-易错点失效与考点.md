# 3.4.5 易错点、失效与考点

## 本节讲什么

教材重点易错点、迭代器失效、`vector` 与 HFT 热路径的关系，及课后考点总结。

## 教材重点易错点

### 1. 尾后迭代器禁止解引用

```cpp
auto e = v.end();
// *e;   // ❌ 未定义行为，可能崩溃
```

`end()` 只是**结束标记**，不是最后一个元素。最后一个元素是 `*(v.end() - 1)`（非空时）。

### 2. 容器修改导致迭代器失效

| 操作 | `vector` / `string` 常见后果 |
|------|------------------------------|
| **`push_back` 等触发扩容** | 所有迭代器、指针、引用**全部失效** |
| **`erase` 删除元素** | 被删位置及之后的迭代器失效 |
| **`insert` 中间插入** | 插入点及之后可能失效 |

```cpp
std::vector<int> v{1, 2, 3};
auto it = v.begin();
v.push_back(4);        // 若扩容，it 失效
// *it;                // ❌ 危险

// 正确：重新获取
it = v.begin();
```

**HFT**：行情缓冲 `vector` 在热路径 `push_back` 后，**不要**继续用旧的 `begin()`/`end()` 缓存迭代器遍历——应重新取或改用下标 + 已知 `size()`（见 [3.3.3](../3.3-library-type-vector/3.3.3-下标与增删.md)、[3.3.5](../3.3-library-type-vector/3.3.5-拷贝移动与扩容.md)）。

### 3. 只读遍历用 `cbegin` / `cend`

防止循环里误写 `*it = ...` 改坏数据。

### 4. 空容器判断

```cpp
if (v.begin() == v.end())   // 等价 v.empty()
```

### 5. 自增用前置 `++it`

后置 `it++` 多一次临时拷贝，热路径避免。

## 课后核心考点

1. 迭代器 vs 下标：**通用性**，适配全部 STL 容器  
2. `begin` / `end`、`cbegin` / `cend` 的**返回类型**与读写权限  
3. 标准 `for` 遍历模板：`it != end()`、`++it`  
4. `*`、 `->`、`++` / `--`、`==` / `!=`  
5. **随机访问**专属：`+`、`-`、`-` 得距离、`<` 比较  
6. **尾后**特性、空容器、`vector` **失效**基础概念  

## 背诵极简版

```
下标不通用；迭代器全容器通用，string 也支持
begin 首元素；end 尾后勿解引用；空则 begin==end
cbegin/cend 只读；只遍历用 cbegin
遍历 it!=end()，不用 <；++it 优于 it++
*it  it->成员  == !=
vector/string：it+n  end-begin 得个数；list/map 不支持
push_back 扩容、erase 后迭代器失效，勿用旧 it
```

## 完整示例

```cpp
#include <iostream>
#include <vector>
#include <string>

int main() {
    std::vector<std::string> vec = {"apple", "banana", "pear"};

    // 读写迭代器
    for (auto it = vec.begin(); it != vec.end(); ++it) {
        *it = "fruit:" + *it;
        std::cout << *it << "\n";
    }

    // 只读 cbegin/cend
    for (auto cit = vec.cbegin(); cit != vec.cend(); ++cit) {
        std::cout << *cit << " ";
        // *cit = "xxx";  // 编译报错
    }
    std::cout << "\n";

    // 迭代器算术
    auto first = vec.begin();
    auto last  = vec.end();
    std::cout << "元素总数：" << last - first << "\n";

    return 0;
}
```

## 和 C 的区别（迭代器失效 vs 指针失效）

C 程序员对"指针失效"也有经验——`realloc` 后旧指针可能悬垂，`free` 后指针悬垂。C++ 迭代器失效本质相同，但**触发场景更隐蔽**：

| 失效场景 | C（指针） | C++（迭代器） |
|----------|-----------|---------------|
| 容器扩容 | `realloc` 后旧指针可能失效 | `push_back` 触发扩容 → 全部失效 |
| 删除元素 | `free` 单个对象后指针悬垂 | `erase` 后被删及之后失效 |
| 插入元素 | 很少做（C 数组不动态） | `insert` 后插入点及之后可能失效 |
| 检测难度 | 通常崩溃明显（野指针解引用） | 可能不崩但行为错（HFT 静默错价） |

**给 C 程序员的关键转变：**
1. **C 的"数组地址稳定"在 `vector` 上不成立**——`int arr[N]` 地址永远不变，但 `vector` 扩容会搬家。**任何可能扩容的操作后，旧迭代器/指针/引用都视为失效**。
2. **C 的 `realloc` 你会主动检查返回值**；C++ `push_back` 扩容是隐式的，容易忘。HFT 热路径上要么 `reserve` 保证不扩容，要么扩容后**重取**迭代器。
3. **`end()` 也可能失效**——不只是 `begin()`。扩容后整个内部缓冲都搬了，`end()` 指向的新尾后位置和旧的不同。循环里缓存的 `end()` 要重取：
   ```cpp
   for (auto it = v.begin(), end = v.end(); it != end; ++it) { ... }   // ❌ end 缓存了
   // 应该：
   for (auto it = v.begin(); it != v.end(); ++it) { ... }              // 每次重取 end
   ```

## 常见错误

### 1. 循环里缓存 `end()` 又改容器

```cpp
auto end = v.end();
for (auto it = v.begin(); it != end; ++it) {
    if (condition) v.push_back(x);   // 扩容 → end 失效，it 也失效
}
```

C 程序员写 `for (p=arr; p!=arr+n; ++p)` 习惯了 `n` 不变，缓存 `end` 像缓存 `arr+n`。但 `vector` 扩容后 `end()` 变了。**每次循环重取 `v.end()`**，或保证循环内不扩容。

### 2. `erase` 后继续用旧迭代器

```cpp
for (auto it = v.begin(); it != v.end(); ++it) {
    if (*it == target) {
        v.erase(it);
        // ++it;   // ❌ erase 后 it 失效，++it 是 UB
    }
}
```

`erase` 返回**下一个有效迭代器**，正确写法：

```cpp
for (auto it = v.begin(); it != v.end(); ) {
    if (*it == target) it = v.erase(it);   // erase 返回下一个
    else ++it;
}
```

C 里删除数组元素要"后移 + 减长度"，没有"迭代器失效"概念，但本质一样——删除后位置变了。

### 3. 解引用尾后迭代器

```cpp
auto e = v.end();
std::cout << *e;   // ❌ UB，尾后是结束标记不是元素
```

`end()` 是"最后一个元素的下一个位置"，不可解引用。最后一个元素是 `*(v.end() - 1)`（非空时）。C 里 `arr + n` 同样不可解引用，但 C 程序员很少写出 `*(arr + n)`，因为心智上清楚 `n` 是越界——`vector` 的 `end()` 容易让人误以为是"最后一个"。

## 自测题

**1. 选择题**　下列哪种操作**不会**导致 `vector` 的迭代器失效？

- A. `v.push_back(x)` 触发扩容
- B. `v.reserve(100)` 当 `v.capacity() < 100`
- C. `v.erase(v.begin())`
- D. `v.clear()`

<details><summary>答案</summary>

**B**。`reserve` 只增容量不动元素，**已有迭代器/指针/引用仍有效**（标准保证）。A 扩容全部失效；C 被删及之后失效；D 全部失效（size 变 0）。`reserve` 是少数"安全扩容"操作，HFT 用它预热。

</details>

**2. 判断题**　`v.end()` 指向 `vector` 的最后一个元素。

<details><summary>答案</summary>

**错**。`v.end()` 是**尾后迭代器**（past-the-end），指向"最后一个元素的下一个位置"，不可解引用。最后一个元素是 `*(v.end() - 1)` 或 `v.back()`。这个设计让 `[begin, end)` 是半开区间，`end - begin` 等于元素个数。

</details>

**3. 踩坑题**　下面这段循环删除 `vector` 中所有偶数，哪里有问题？

```cpp
std::vector<int> v = {1, 2, 3, 4, 5, 6};
for (auto it = v.begin(); it != v.end(); ++it) {
    if (*it % 2 == 0)
        v.erase(it);
}
```

<details><summary>答案</summary>

**两个问题**：
1. **`erase` 后 `it` 失效**，`++it` 是 UB
2. **跳过下一个元素**：即使没崩，`erase` 后元素前移，`++it` 会跳过被删位置的新元素

**正确写法**：

```cpp
for (auto it = v.begin(); it != v.end(); ) {
    if (*it % 2 == 0) it = v.erase(it);   // erase 返回下一个
    else ++it;
}
```

或更高效（C++20 起）用 `std::erase_if`：

```cpp
std::erase_if(v, [](int x) { return x % 2 == 0; });
```

</details>

**4. 应用题**　HFT 行情缓冲：主线程 `push_back` 写入 tick，另一线程用迭代器遍历。这个设计安全吗？为什么？

<details><summary>答案</summary>

**不安全**，至少两个问题：

1. **迭代器失效**：写线程 `push_back` 扩容时，读线程持有的迭代器/指针/引用全部失效 → UB
2. **数据竞争**：即使不扩容，`push_back` 改 `size()`，读线程读 `size()` 或访问末尾元素时可能读到半写状态 → UB

**修复**方向：
- 加锁（`std::mutex`）保护 `vector`，但热路径加锁有延迟
- 用无锁环形缓冲（固定大小数组 + 原子下标），避开 `vector` 扩容
- 用双缓冲：写线程写 `vector A`，定期 swap 给读线程的 `vector B`（`swap` 是 O(1) 指针交换）

HFT 实战几乎不用 `vector` 做跨线程共享缓冲——固定大小数组 + 原子索引更常见。详见第 6 章并发。

</details>
