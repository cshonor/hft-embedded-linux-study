# 8.2 管理条件状态

## 本节讲什么

每个 IO 流对象维护一组**条件状态标志**，记录流是否处于有效、EOF、失败等状态。本节讲如何查询和复位这些状态——这是健壮 IO 处理的基础，C 程序员对应的是 `feof`/`ferror`/`errno`。

## 核心用法

### 四种状态标志

| 标志 | 含义 | 查询函数 |
|------|------|---------|
| `goodbit` | 一切正常 | `good()` |
| `eofbit` | 到达文件尾 | `eof()` |
| `failbit` | 操作失败（如格式不匹配），可恢复 | `fail()` |
| `badbit` | 严重错误（如流损坏），不可恢复 | `bad()` |

### 流作为条件

```cpp
int x;
while (std::cin >> x) {     // operator>> 返回流引用，流可转 bool（查 !fail()）
    std::cout << x;
}
// 循环退出：遇到 EOF 或读取失败
if (std::cin.eof()) std::cout << "正常结束";
else std::cout << "格式错误";
```

### 复位状态

```cpp
std::cin.clear();           // 清除所有错误标志，恢复 good 状态
std::cin.ignore(10000, '\n');  // 丢弃缓冲区残留
```
`clear()` 用于从 `failbit` 恢复（如读错类型后清状态继续读）。

## 和 C 的区别

| 维度 | C | C++ |
|------|---|-----|
| 状态查询 | `feof()`/`ferror()` | `eof()`/`fail()`/`bad()`/`good()` |
| 错误区分 | 只有 EOF 和 error 两类 | 区分 fail（可恢复）和 bad（不可恢复） |
| 错误码 | `errno`（全局，易被覆盖） | 状态标志在流对象内，不冲突 |
| 状态复位 | 无标准方式（clearerr） | `clear()` |
| 作为循环条件 | `while (fscanf(...)!=EOF)` | `while (cin >> x)` 更简洁 |

**C 程序员的认知转变**：

C 检查 IO 错误靠返回值 + `feof`/`ferror`，比较繁琐：
```c
/* C：靠返回值和 feof/ferror 判断 */
int x;
while (fscanf(stdin, "%d", &x) == 1) {
    printf("%d\n", x);
}
if (feof(stdin)) printf("EOF\n");
else if (ferror(stdin)) printf("error\n");
else printf("format mismatch\n");   // fscanf 没读到完整 int
```

C++ 流对象自带状态，且流可直接当条件用，更简洁：
```cpp
// C++：流当条件，状态在对象内
int x;
while (std::cin >> x) std::cout << x << "\n";
if (std::cin.eof()) std::cout << "EOF\n";
else if (std::cin.fail()) std::cout << "format mismatch\n";
```

**关键区别**：C++ 区分 `failbit`（格式不匹配，可恢复）和 `badbit`（流损坏，不可恢复）。C 的 `ferror` 不区分，恢复更难。

## 常见错误

1. **读取失败后不清状态继续读**：`cin >> x` 失败后流进入 fail 状态，后续所有 `>>` 直接返回失败，陷入死循环或读到垃圾。**修正**：失败后 `cin.clear()` 清状态 + `cin.ignore()` 丢弃坏输入，再继续。
2. **用 `!cin.eof()` 作循环条件**：`while (!cin.eof()) { cin >> x; use(x); }` —— EOF 是在**尝试读取失败后**才设置的，所以最后一次 `use(x)` 会用未定义的 x。**修正**：`while (cin >> x) use(x);`，把读取和判断合并。
3. **混淆 `fail()` 和 `bad()`**：`bad()` 是不可恢复错误（如设备损坏），`fail()` 是可恢复的（格式不匹配）。对 `bad()` 调 `clear()` 后流仍不可用（底层已坏）。

## 自测题

**1. 选择题**：输入 `abc` 时，`std::cin >> x`（x 是 int）后，`cin` 的状态是？
- A) goodbit
- B) eofbit
- C) failbit
- D) badbit

<details><summary>答案</summary>

C) failbit。`abc` 不是整数，`>>` 解析失败，设置 failbit（可恢复错误）。不是 eof（没到文件尾），不是 bad（流没损坏）。可调 `clear()` 恢复。

</details>

**2. 判断题**：`while (!std::cin.eof()) { std::cin >> x; process(x); }` 是安全的读取循环。

<details><summary>答案</summary>

错误。这是经典 bug：EOF 标志在**读取失败后**才设置，所以当输入最后一个有效数据后，`eof()` 还是 false，循环再进一次，`cin >> x` 失败（这次才设 eof），但 `process(x)` 已经用未定义的 x 执行了。**正确写法**：`while (std::cin >> x) process(x);`，把读取和条件判断合并，失败时不进循环体。

</details>

**3. 踩坑题**：下面代码想"读错就跳过继续读"，但进入死循环，为什么？
```cpp
int x;
while (true) {
    if (std::cin >> x) {
        std::cout << x;
    }
    // 失败了想跳过继续
}
```
（输入 `abc`）

<details><summary>答案</summary>

`cin >> x` 读 `abc` 失败，进入 fail 状态。之后循环里每次 `cin >> x` 都立即返回失败（流在 fail 状态时不读任何东西），且没清状态 → 死循环。**修正**：
```cpp
if (std::cin >> x) { std::cout << x; }
else {
    if (std::cin.eof()) break;
    std::cin.clear();                    // 清错误状态
    std::cin.ignore(1000, '\n');         // 丢弃坏输入
}
```

</details>

**4. 应用题**：写一个健壮的"读整数"循环：从 cin 读整数直到 EOF，遇到非整数输入时打印提示并跳过继续，不崩溃不死循环。

<details><summary>答案</summary>

```cpp
int x;
while (true) {
    std::cout << "Enter int: ";
    if (std::cin >> x) {
        std::cout << "Got: " << x << "\n";
    } else if (std::cin.eof()) {
        break;                            // 正常结束
    } else {
        std::cout << "Not an int, skip\n";
        std::cin.clear();                 // 清 failbit
        std::cin.ignore(10000, '\n');     // 丢弃本行坏输入
    }
}
```
关键：失败时先 `clear()` 恢复流状态，再 `ignore()` 丢弃导致失败的输入，否则流卡在 fail 状态死循环。C 要用 `fscanf` 返回值 + 手动清缓冲区，更繁琐。

</details>
