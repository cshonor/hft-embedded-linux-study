# 8.1 IO 类体系

## 本节讲什么

C++ 的 IO 类层次：`iostream`（控制台）、`fstream`（文件）、`sstream`（内存 string）。重点是**继承关系让它们可互换**——一个接受 `istream&` 的函数既能读 cin，也能读文件、读 string。这是 C 的 `FILE*` 做不到的多态。

## 核心用法

### 三大头文件

| 头文件 | 类 | 用途 |
|--------|-----|------|
| `<iostream>` | `istream`/`ostream`/`iostream` | 控制台 IO（`cin`/`cout`/`cerr`/`clog`） |
| `<fstream>` | `ifstream`/`ofstream`/`fstream` | 文件 IO |
| `<sstream>` | `istringstream`/`ostringstream`/`stringstream` | 内存 string IO |

### 继承层次（简化）

```
        ios_base
            │
          ios
         ╱   ╲
    istream   ostream
       ╲       ╱
       iostream
       ╱   ╲   ╱
ifstream  stringstream  fstream ...
```

`ifstream` 继承自 `istream`，`istringstream` 也继承自 `istream`。所以一个 `istream&` 参数可以接收 `cin`、`ifstream`、`istringstream`——**多态**。

### 多态的好处

```cpp
// 一个函数，能从任意输入流读
void process(std::istream& in) {
    int x;
    while (in >> x) std::cout << x << " ";
}

process(std::cin);                              // 读控制台
std::ifstream f("data.txt");
process(f);                                     // 读文件
std::istringstream iss("1 2 3");
process(iss);                                   // 读 string
```

## 和 C 的区别

| 维度 | C (`stdio`) | C++ (`iostream`) |
|------|-------------|------------------|
| 控制台 | `scanf`/`printf` | `cin`/`cout` |
| 文件 | `fopen`/`fread`/`fprintf` | `ifstream`/`ofstream` |
| 内存 | `sscanf`/`sprintf` | `istringstream`/`ostringstream` |
| 类型安全 | ❌ 格式串手动对齐类型，易错 | ✅ 编译器按类型重载 `<<`/`>>` |
| 多态 | ❌ `FILE*` 无继承，函数各写各的 | ✅ 继承层次，`istream&` 通用 |
| 资源管理 | 手动 `fclose` | RAII 析构自动关闭 |
| 扩展自定义类型 | ❌ 要自己写 printf 格式 | ✅ 重载 `operator<<` 支持任意类型 |

**C 程序员最该体会的**：

1. **类型安全**：C 的 printf 格式串和参数类型不匹配时，编译器不查（GCC 有 `-Wformat` 但不强制），运行 UB。C++ 的 `<<`/`>>` 按类型重载，编译期保证类型正确。

```c
/* C：格式串和类型不匹配，运行 UB，编译器不一定警告 */
int x = 42;
printf("%f\n", x);        // 用 %f 打 int，UB！
```
```cpp
// C++：编译器按类型选 operator<<，类型安全
int x = 42;
std::cout << x << "\n";   // 调 operator<<(ostream&, int)，安全
```

2. **多态**：C 的读文件、读控制台、读内存是三套不同函数（`fscanf`/`scanf`/`sscanf`），无法统一。C++ 一个 `istream&` 参数全搞定。

3. **RAII**：C 的 `FILE*` 必须手动 `fclose`，忘了就泄漏。C++ 的 `fstream` 析构自动关闭。

## 常见错误

1. **忘了检查流状态**：`in >> x; use(x);` —— 如果读取失败（EOF、格式错），`x` 未定义却继续用。**修正**：`if (in >> x) { use(x); }` 或 `while (in >> x)`。
2. **复制流对象**：`ifstream f2 = f;` —— 流对象不可复制（防止多个对象管同一资源）。只能传引用或移动。
3. **混用 C stdio 和 C++ iostream 不同步**：同时用 `printf` 和 `std::cout` 输出可能交错。**修正**：调 `std::ios::sync_with_stdio(false);` 关同步（性能提升，但不能再混用）或保持默认同步。

## 自测题

**1. 选择题**：下面函数参数类型最通用（能接收 cin/ifsteam/istringstream）的是？
- A) `void f(std::iostream in)`
- B) `void f(std::istream& in)`
- C) `void f(std::ifstream& in)`
- D) `void f(FILE* in)`

<details><summary>答案</summary>

B。`istream&` 是基类引用，`cin`/`ifstream`/`istringstream` 都派生自 `istream`，可多态接收。A 流不可复制，不能值传递；C 只能接收 ifstream；D 是 C 的 FILE*，与 iostream 无关。

</details>

**2. 判断题**：C++ 的 `std::cout << x` 比 C 的 `printf("%d", x)` 更安全。

<details><summary>答案</summary>

正确。`<<` 按类型重载，编译器根据 `x` 的类型选对应 `operator<<`，类型不匹配编译错误。`printf` 的格式串是运行期字符串，编译器默认不检查与参数类型的匹配，`printf("%d", 3.14)` 编译过但运行 UB。C++ 的类型安全在编译期消除整类错误。

</details>

**3. 踩坑题**：下面代码想读完整数后继续读，但读取失败后陷入死循环，为什么？
```cpp
int x;
while (true) {
    std::cin >> x;
    std::cout << x;
}
```
（输入 `abc`）

<details><summary>答案</summary>

输入 `abc` 不是整数，`cin >> x` 失败，流进入失败状态，`x` 未赋值，且后续 `>>` 都直接返回失败不读取——死循环打印垃圾。**修正**：检查流状态，失败时 break 并 clear：
```cpp
while (std::cin >> x) std::cout << x;
// 退出循环说明失败（EOF 或格式错）
```

</details>

**4. 应用题**：写一个 `count_words` 函数，能从 cin、文件、string 任意来源统计单词数。用 `istream&` 参数实现多态。

<details><summary>答案</summary>

```cpp
#include <iostream>
#include <fstream>
#include <sstream>
#include <string>

size_t count_words(std::istream& in) {
    size_t n = 0;
    std::string word;
    while (in >> word) ++n;   // >> 按空白分割
    return n;
}

// 三种来源都能用：
// count_words(std::cin);
// std::ifstream f("a.txt"); count_words(f);
// std::istringstream iss("hello world foo"); count_words(iss);
```
C 要写三个函数（`count_stdin`/`count_file`/`count_string`），C++ 一个 `istream&` 参数全搞定——这是继承多态的直接收益。C 的 `FILE*` 没有这种统一接口（`scanf`/`fscanf`/`sscanf` 是三个不同函数）。

</details>
