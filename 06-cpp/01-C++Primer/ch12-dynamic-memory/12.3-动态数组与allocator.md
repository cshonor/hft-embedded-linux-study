# 12.3 动态数组与 allocator

## 本节讲什么

C++ 分配动态数组的几种方式：`new[]`/`delete[]`、智能指针管理数组（`unique_ptr<T[]>`）、`vector`（首选）、`allocator`（内存分配与对象构造分离，高性能场景）。重点是为什么 `vector` 几乎总是比 `new[]` 好。

## 核心用法

### new[] / delete[]

```cpp
int* arr = new int[10];    // 10 个未初始化 int
int* arr2 = new int[10](); // 10 个 0（值初始化）
delete[] arr;              // 数组用 delete[]
```

### 智能指针管理数组

```cpp
std::unique_ptr<int[]> up(new int[10]);   // 自动 delete[]
up[0] = 42;                               // 支持 []
// 出作用域自动 delete[]，不泄漏

// shared_ptr 管理数组要自定义删除器（C++17 前）
std::shared_ptr<int> sp(new int[10], std::default_delete<int[]>());
```

### vector（首选！）

```cpp
std::vector<int> v(10);          // 10 个 0
v.resize(20);                    // 可变大小
v.push_back(42);                 // 追加
// 析构自动释放，RAII
```

### allocator（内存与构造分离）

```cpp
#include <memory>
std::allocator<int> alloc;
int* p = alloc.allocate(10);     // 只分配内存，不构造
alloc.construct(p, 42);          // 在 p 处构造
// ... 用 ...
alloc.destroy(p);                // 析构
alloc.deallocate(p, 10);         // 释放内存
```
`allocator` 把"分配内存"和"构造对象"分开——先分配一大块内存，按需构造，适合"先预留内存、按需构造"的高性能场景（如 vector 内部就用 allocator 实现 reserve 时不构造）。

## 和 C 的区别

| 维度 | C | C++ |
|------|---|-----|
| 动态数组 | `malloc(n*sizeof(T))` | `new T[n]` / `vector` |
| 构造 | ❌ malloc 不构造 | new[] 构造每个元素 |
| 可变大小 | `realloc`（手动，元素可能是浅拷贝） | `vector` 自动安全扩容 |
| 内存/构造分离 | 无概念 | `allocator` |
| 释放 | `free` | `delete[]` / RAII |

**C 程序员最该体会的：vector 几乎总是比 new[] 好**

C 的动态数组是 `malloc` + 手动管理大小 + `realloc`，繁琐易错：
```c
/* C：手动动态数组 */
int* arr = malloc(10 * sizeof(int));
size_t size = 10;
// 要扩容
int* tmp = realloc(arr, 20 * sizeof(int));   // realloc 可能移动内存
if (!tmp) { /* 处理失败 */ }
arr = tmp;
size = 20;
// ... 还要记着 free(arr)
```

C++ 的 `vector` 把这一切自动化，且更安全：
```cpp
std::vector<int> v(10);
v.resize(20);    // 自动扩容，自动处理拷贝/移动
// 析构自动释放
```

**只有在以下情况才考虑 new[]/allocator**：
- 与 C 接口互操作（C 要裸指针）
- 性能极致优化（allocator 分离分配与构造，避免无谓构造）
- 固定大小且不想用 vector 的容量管理开销

## 常见错误

1. **`new[]` 配 `delete`（非 `delete[]`）**：UB，必须 `delete[]`。用 `unique_ptr<T[]>` 可避免记错。
2. **`allocator` 忘了 destroy**：`allocate` 后 `construct`，用完必须 `destroy` 再 `deallocate`，否则对象析构没调用，资源泄漏。
3. **用 `vector` 还是 `new[]` 纠结**：99% 情况用 vector。new[] 的唯一理由是与 C 互操作或极致性能优化。

## 自测题

**1. 选择题**：下面哪种方式管理动态数组最推荐？
- A) `int* a = new int[10]; ... delete[] a;`
- B) `std::unique_ptr<int[]> a(new int[10]);`
- C) `std::vector<int> a(10);`
- D) `int* a = (int*)malloc(10*sizeof(int));`

<details><summary>答案</summary>

C。`vector` 最推荐：自动管理大小、RAII 释放、接口丰富、安全。B 是次选（固定大小、要裸指针语义时）。A 裸 new[] 要手动 delete[] 易错。D 是 C 方式，不调用构造/析构，C++ 中不推荐。现代 C++ 应用层动态数组默认 vector。

</details>

**2. 判断题**：`std::allocator` 的 `allocate` 会调用对象的构造函数。

<details><summary>答案</summary>

错误。`allocator::allocate` 只**分配原始内存**，不构造对象；要构造需调 `construct`。这正是 allocator 的设计目的——分离"分配"与"构造"，让你先开一大块内存（reserve），按需在指定位置构造，避免无谓的默认构造开销。C++17 起 `construct`/`destroy` 被弃用，推荐用 `std::construct_at`/`std::destroy_at`。

</details>

**3. 踩坑题**：下面代码用 allocator，但有 bug，找出来。
```cpp
std::allocator<std::string> alloc;
auto p = alloc.allocate(3);
p[0] = "a"; p[1] = "b"; p[2] = "c";   // 直接赋值
// ... 用 ...
alloc.deallocate(p, 3);               // 释放
```

<details><summary>答案</summary>

`allocate` 只分配内存未构造对象，直接 `p[0] = "a"` 是对未构造内存赋值（调用 operator=，但对象还没构造），UB。**正确流程**：allocate → construct（每个）→ 用 → destroy（每个）→ deallocate：
```cpp
auto p = alloc.allocate(3);
std::construct_at(p, "a");
std::construct_at(p+1, "b");
std::construct_at(p+2, "c");
// 用
std::destroy_at(p); std::destroy_at(p+1); std::destroy_at(p+2);
alloc.deallocate(p, 3);
```
这就是为什么应用层用 vector——它内部正确处理了这些。

</details>

**4. 应用题**：HFT 场景需要一个"预分配 N 个 Msg 对象的内存池，按需构造/析构，绝不运行期分配"。用 allocator 设计，说明为什么不直接用 vector。

<details><summary>答案</summary>

```cpp
class MsgPool {
    std::allocator<Msg> alloc;
    Msg* mem;
    size_t cap;
public:
    MsgPool(size_t n) : cap(n) {
        mem = alloc.allocate(n);   // 启动时一次分配，不构造
    }
    Msg* acquire(const Args&... args) {
        // 找一个空闲槽位（用位图标记），construct_at 构造
        size_t slot = find_free_slot();
        std::construct_at(mem + slot, args...);
        return mem + slot;
    }
    void release(Msg* p) {
        std::destroy_at(p);        // 析构，不释放内存
        mark_free(p - mem);
    }
    ~MsgPool() { alloc.deallocate(mem, cap); }
};
```
不用 vector 因为：1) vector 的 reserve 仍可能触发扩容（HFT 禁止运行期分配）；2) vector 要求元素可构造/移动，内存池想完全控制何时构造；3) allocator 分离分配与构造，启动时分配一大块，运行期零分配只构造/析构。这是 HFT/游戏引擎常见的对象池模式。

</details>
