# 4.11.2 显式转换与四种 cast

## 本节讲什么

老式 C 风格强转 vs C++ 四种命名强制转换：`static_cast`、`const_cast`、`reinterpret_cast`、`dynamic_cast`。

## 老式转换（不推荐）

```cpp
double d = 3.14;
int i1 = (int)d;     // C 风格
int i2 = int(d);     // 函数式
```

**缺点**：一次写法可同时完成**去 const、指针重解释**等多种语义，难以审查，易埋雷。

## C++ 命名转换（推荐）

统一语法：**`转换名<目标类型>(表达式)`**

### ① `static_cast`（最常用）

**温和、相对安全**的编译期转换：

- 基础算术互转（`double`↔`int`、`float`↔`long`）
- `void*` 与普通指针互转
- 继承体系父子类指针**上行/下行**（编译期检查有限）

**不能**修改 `const` 属性。

```cpp
double d = 3.14;
int i = static_cast<int>(d);   // 3，截断小数
```

### ② `const_cast`（唯一能增删 const/volatile）

仅修改**常量限定**，不改变底层类型。

```cpp
const char *str = "test";
char *p = const_cast<char*>(str);   // 去掉 const（仍须谨慎使用）

const int ci = 100;
const int *cp = &ci;
int *p2 = const_cast<int*>(cp);
// *p2 = 200;  // ❌ 若 ci 原本真是 const，这是 UB
```

**警告**：通过 `const_cast` 修改**原本就是 const** 的对象 → **未定义行为**。合法典型场景：调用只接受非 `const` 指针的遗留 API，而对象本身可变。

### ③ `reinterpret_cast`（底层比特重解释，极高风险）

把内存**二进制位**直接当成另一种类型，**无类型安全检查**：

- 指针与整数互转
- 不相关类型指针互转

```cpp
int num = 0x1234;
char *pc = reinterpret_cast<char*>(&num);
```

**HFT**：解析二进制报文、对齐字段时偶见；日常业务尽量少用，优先 `memcpy` + 明确布局（见 [2.1 基本类型](../ch02-variables-and-basic-types/2.1-基本内置类型.md)）。

### ④ `dynamic_cast`（运行时多态转换）

仅用于**带虚函数**的多态类；基类指针/引用 → 派生类，**运行时**校验，失败指针版返回 `nullptr`。

本章仅提及；详见第 7 / 15 章继承与多态。

## 四种 cast 速查

| cast | 用途 | 风险 |
|------|------|------|
| `static_cast` | 算术、`void*`、继承转换 | 低～中（浮点截断等） |
| `const_cast` | 增删 `const`/`volatile` | 改真 const → UB |
| `reinterpret_cast` | 比特重解释 | **极高** |
| `dynamic_cast` | 多态向下转型 | 低（失败可检测） |

## 和 C 的区别（显式转换：C++ 的四种 cast 替代 C 风格强转）

这是 C 转 C++ **最该改变习惯**的部分之一。C 只有一种强转 `(type)expr`，C++ 提供**四种命名 cast**，让转换意图更明确、更易审查：

| 对比点 | C | C++ |
|--------|----|------|
| 算术转换 | `(int)d` 或 `int(d)` | `static_cast<int>(d)` |
| 去 const | `(int*)cp`（同一写法） | `const_cast<int*>(cp)` |
| 指针重解释 | `(char*)&num` | `reinterpret_cast<char*>(&num)` |
| 多态向下转型 | 无（C 无继承） | `dynamic_cast<Derived*>(bp)` |
| `void*` → 其他指针 | `int* p = (int*)vp;` 或 `int* p = vp;`（隐式） | `static_cast<int*>(vp)`（必须显式） |
| 审查难度 | `(type)expr` 一眼看不出意图 | cast 名字暴露意图 |

**给 C 程序员的关键转变：**
1. **`static_cast` 替代 C 的 `(type)expr` 用于算术/指针转换**——`static_cast<int>(d)` 比 `(int)d` 更显眼、更易搜索（grep `static_cast` 一搜一个准）。语义等价，但意图清晰。
2. **`const_cast` 是 C++ 独有的"去 const"方式**——C 里 `(int*)cp` 一行就能去 const，C++ 必须用 `const_cast<int*>(cp)`。这是**有意**的设计——去 const 是危险操作，命名 cast 让它在代码审查时更醒目。
3. **`reinterpret_cast` 替代 C 的指针重解释**——`(char*)&num` 在 C++ 用 `reinterpret_cast<char*>(&num)`。`reinterpret_` 这个名字本身就在警告"我在重新解释比特"。
4. **`dynamic_cast` 是 C++ 独有**——C 没有继承/多态，没有这种转换。运行时检查向下转型是否安全。
5. **C 风格 `(type)expr` 在 C++ 仍合法但不推荐**——它"什么都能干"（同时去 const + 重解释），难以审查。**用四种命名 cast 替代**是 C 转 C++ 的重要习惯转变。

## 常见错误

### 1. 用 `static_cast` 去 const

```cpp
const int ci = 100;
const int* cp = &ci;
int* p = static_cast<int*>(cp);   // ❌ 编译错误：static_cast 不能去 const
```

`static_cast` **不能修改 const**——去 const 必须用 `const_cast`。这是 C++ 有意的设计——去 const 是危险操作，要用专门的 cast 名字暴露意图。C 里 `(int*)cp` 一行搞定，C++ 要分清。

### 2. `const_cast` 修改原本就是 const 的对象

```cpp
const int ci = 100;
const int* cp = &ci;
int* p = const_cast<int*>(cp);
*p = 200;   // ❌ UB：ci 原本是 const，改它是未定义行为
```

`const_cast` 只是"骗编译器"（去掉 const 检查），但**运行期**对象是否真可改取决于它原本是否 const。原本 `const` 的对象可能存在只读内存，改它 UB。**合法场景**：对象本身非 const，但被 const 接口返回，调用者知道可改。

### 3. 用 `reinterpret_cast` 做不相关类型转换

```cpp
double d = 3.14;
int i = reinterpret_cast<int>(d);   // ❌ 编译错误：reinterpret_cast 不能用于算术类型
```

`reinterpret_cast` 只用于**指针/引用**的比特重解释，不用于算术类型转换。算术转换用 `static_cast`。C 里 `(int)d` 既可用于算术也可用于指针（一锅烩），C++ 分得清。

## 自测题

**1. 选择题**　要去掉指针的 `const` 限定，应该用哪种 cast？

- A. `static_cast`
- B. `const_cast`
- C. `reinterpret_cast`
- D. `dynamic_cast`

<details><summary>答案</summary>

**B**。`const_cast` 是**唯一**能增删 `const`/`volatile` 的 cast。`static_cast` 不能改 const（编译错误）；`reinterpret_cast` 改的是比特解释不是 const；`dynamic_cast` 用于多态向下转型。C 里 `(int*)cp` 一行能去 const，C++ 要用 `const_cast` 暴露意图。

</details>

**2. 判断题**　C 风格的 `(int)d` 在 C++ 中是编译错误。

<details><summary>答案</summary>

**错**。C 风格 `(int)d` 在 C++ 仍**合法**（向后兼容），但**不推荐**——它"什么都能干"（同时去 const、重解释指针、算术转换），难以审查。C++ 推荐 `static_cast<int>(d)` 这种命名 cast，意图清晰、易搜索。

</details>

**3. 踩坑题**　C 程序员写下面这段 C++ 代码，哪里有问题？

```cpp
const char* s = "hello";
char* p = (char*)s;        // C 风格强转去 const
p[0] = 'H';                 // 想改成 "Hello"
```

<details><summary>答案</summary>

**两个问题**：
1. **C 风格强转不推荐**——C++ 应该用 `const_cast<char*>(s)`，暴露"去 const"的意图
2. **修改字符串字面量是 UB**——`"hello"` 是字符串字面量，存在只读内存，`p[0] = 'H'` 可能崩溃（段错误）

**修复**（若真要改字符串）：

```cpp
char buf[] = "hello";      // 数组，可改
buf[0] = 'H';              // ✅ "Hello"
// 或用 std::string
std::string s = "hello";
s[0] = 'H';                // ✅
```

C 里这种写法也是 UB（字符串字面量只读），但 C++ 的 `std::string` 更安全——赋值就拷贝一份可改的。

</details>

**4. 应用题**　HFT 代码要从 `void*` 缓冲读 `int` 数据。C 写法 `(int*)buf`，C++ 应该怎么写？

<details><summary>答案</summary>

```cpp
// C 写法（C++ 也能编译，但不推荐）
void* buf = malloc(100 * sizeof(int));
int* ip = (int*)buf;

// C++ 推荐：static_cast
void* buf = malloc(100 * sizeof(int));
int* ip = static_cast<int*>(buf);

// C++ 更推荐：new 或 vector
int* ip = new int[100];
// 或
std::vector<int> v(100);
int* ip = v.data();
```

要点：
- `void*` → `int*` 用 `static_cast`（C++ 必须显式，不能隐式）
- `reinterpret_cast` 也能用但过头——`static_cast` 足够且更安全
- C++ 推荐 `new`/`vector` 替代 `malloc`（类型安全、RAII）

C 程序员的 `(int*)buf` 习惯要改成 `static_cast<int*>(buf)`。

</details>
