# 4.11.1 隐式类型转换

## 本节讲什么

编译器**无提示、自动完成**的类型转换——发生在运算、赋值、初始化、传参等场景。

## 1. 整型提升（最基础）

小于 `int` 的小整型（`char` / `short` / `bool`）参与运算时，先提升为 **`int`**；若 `int` 放不下则提升为 **`unsigned int`**。

```cpp
char c = 'a';
auto res = c + 10;   // c 先提升为 int 再计算
```

HFT 解析单字节字段时，`char` 参与算术前几乎总会先变 `int`——与 [3.2.5 `unsigned char`](../ch03-strings-vectors-arrays/3.2-library-type-string/3.2.5-cctype字符校验.md) 配合，避免符号扩展坑。

## 2. 常用算术转换（混合运算）

**向范围更大、精度更高的类型转换**，尽量避免精度丢失：

- 有浮点 → 全部转浮点（`int + double` → `int` 转 `double`）
- 全整型：无符号优先级常高于有符号；宽度小的转宽度大的

```cpp
int a = 3;
double b = 3.14;
auto sum = a + b;    // a 隐式转为 double
```

## 3. 数组 → 指针（高频）

绝大多数场景数组名**退化为首元素指针**。

**不退化**例外：`sizeof(arr)`、`&arr`、用字符串字面量初始化 `char` 数组（见 [3.5.3](../ch03-strings-vectors-arrays/3.5-arrays/3.5.3-数组退化与指针.md)）。

```cpp
int arr[5];
int *p = arr;        // 等价 &arr[0]
```

## 4. 指针相关隐式转换

| 转换 | 说明 |
|------|------|
| `0` / `nullptr` → 任意指针 | 空指针 |
| 非 `const` 对象指针 → `void*` | 通用指针 |
| 非 `const` 指针/引用 → 对应 **`const`** 版 | **只加 const，不能反向** |

```cpp
int i = 10;
const int &r = i;    // ✅ 普通引用 → const 引用
// int &r2 = r;      // ❌ 不能去掉 const
```

与 [2.4.1 底层 const](../ch02-variables-and-basic-types/2.4-const-qualifier/2.4.1-const基础与constexpr.md) 一致。

## 5. 布尔转换（条件判断）

标量（数字、指针）在条件上下文转 `bool`：

- `0`、空指针 → `false`
- 非 0、有效指针 → `true`

```cpp
int x = 5;
if (x) { /* true */ }

int *p = nullptr;
while (p) { /* false，不进入 */ }
```

## 6. 赋值 / 初始化 / 传参

右侧、实参自动转为左侧、形参类型：

```cpp
double d = 3.99;
int i = d;           // double → int，**截断小数**，i == 3（非四舍五入）
```

**HFT**：价格 `double` 隐式赋给 `int` 会**静默丢小数**——业务层应显式处理或统一用定点/整数价位。

## 和 C 的区别（隐式类型转换：C/C++ 几乎一致，C++ 对 `bool` 更严格）

隐式类型转换是 C 和 C++ **高度共享**的部分——整型提升、算术转换、数组退化、指针转换、布尔转换，两边规则几乎一字不差：

| 对比点 | C | C++ |
|--------|----|------|
| 整型提升（char/short → int） | ✅ 一致 | ✅ 一致 |
| 算术转换（向更宽/浮点转） | ✅ 一致 | ✅ 一致 |
| 数组 → 指针退化 | ✅ 一致 | ✅ 一致 |
| `0` → 空指针 | ✅ 一致 | ✅ 一致，但推荐 `nullptr` |
| 指针 → `void*` | ✅ 一致 | ✅ 一致 |
| 加 `const` | ✅ 一致 | ✅ 一致 |
| 非 0 → `true`、0 → `false` | ✅（C89 用 int） | ✅（C++ 有原生 bool） |
| 浮点 → 整型截断 | ✅ 一致 | ✅ 一致 |
| `void*` → 其他指针 | ✅ 隐式转换 | ❌ **必须 `static_cast`** |

**给 C 程序员的关键提醒：**
1. **隐式转换规则两边几乎一致**——整型提升、算术转换、数组退化这些 C 学的"坑"全部迁移。C 程序员的警惕心直接用。
2. **C++ 比 C 严格的地方：`void*` 不能隐式转其他指针**——C 里 `int* p = malloc(...)`（`malloc` 返回 `void*`）合法，C++ 里 `int* p = malloc(...)` 编译错误，必须 `int* p = static_cast<int*>(malloc(...));` 或用 `new`。这是 C++ 类型系统更严格的体现。
3. **C++ 推荐 `nullptr` 替代 `0`/`NULL`**——`0` 在 C++ 里既是整数又是空指针（重载歧义），`nullptr` 是专门的空指针字面量（类型 `nullptr_t`），不会和整数混淆。详见 [2.3.2](../../ch02-variables-and-basic-types/2.3-compound-types/2.3.2-指针与nullptr.md)。

## 常见错误

### 1. 浮点转整型静默截断

```cpp
double price = 3750.99;
int rounded = price;   // 3750，不是 3751（截断非四舍五入）
```

C 程序员也踩这个——两边都是截断小数，不是四舍五入。**要四舍五入**用 `std::lround(price)` 或 `static_cast<int>(price + 0.5)`（正数）。HFT 价格通常用定点整数（如"厘"为单位），避开浮点。

### 2. 有符号和无符号混用导致负数变大正数

```cpp
int i = -1;
unsigned n = 10;
if (i < n) { ... }   // ❌ false！i 转为 unsigned 变成 4294967295
```

有符号和无符号比较时，有符号隐式转为无符号——`-1` 变成 `UINT_MAX`（巨大正数），`< n` 为 false。C 和 C++ 都有这个坑。**用 `size_t` 时尤其小心**，下标和负数比较容易踩。

### 3. `char` 符号扩展

```cpp
char c = 0x80;          // 有符号 char，值为 -128
int i = c;              // 符号扩展，i = -128（不是 128）
unsigned char uc = 0x80;
int j = uc;             // 零扩展，j = 128
```

`char` 是否有符号**实现相关**（x86 通常有符号，ARM 通常无符号）。`char` 转 `int` 时若有符号会**符号扩展**（高位补 1）。处理二进制字节用 `unsigned char` 或 `std::byte`。C 程序员也踩这个，C++ 同样坑。

## 自测题

**1. 选择题**　`int i = -1; unsigned u = 1;` 下列哪个表达式为 `true`？

- A. `i < u`
- B. `i > u`
- C. `i == u`
- D. 编译错误

<details><summary>答案</summary>

**B**。`i < u` 比较时，`i`（int -1）隐式转为 `unsigned`，变成 `UINT_MAX`（4294967295），`UINT_MAX > 1` 为 true，所以 `i > u` 为 true。这是有符号/无符号混用的经典坑。C 也是同样行为。**避免混用**，或显式 `static_cast<int>(u)` 比较。

</details>

**2. 判断题**　`double d = 3.99; int i = d;` 之后 `i` 的值是 4（四舍五入）。

<details><summary>答案</summary>

**错**。浮点转整型是**截断小数**（向零取整），不是四舍五入。`i = 3`，不是 4。要四舍五入用 `std::lround(d)` 或 `static_cast<int>(d + 0.5)`（正数）。C 程序员也踩这个，两边一致。

</details>

**3. 踩坑题**　C 程序员写下面这段 C++ 代码，哪里编译失败？

```cpp
void* p = malloc(100);
int* ip = p;   // 想用 malloc 分配 int 数组
```

<details><summary>答案</summary>

**`int* ip = p;` 编译错误**——C++ 不允许 `void*` 隐式转 `int*`（C 允许）。C 程序员的 `int* ip = malloc(...)` 习惯到 C++ 要改。

**修复**（三种）：

```cpp
// 方法 1：C++ 显式转换
int* ip = static_cast<int*>(malloc(100 * sizeof(int)));

// 方法 2：用 new（C++ 推荐）
int* ip = new int[100];

// 方法 3：用 vector（最推荐）
std::vector<int> v(100);
```

C++ 的 `new`/`vector` 比 `malloc` 更安全（类型安全、调用构造函数、RAII），优先用。

</details>

**4. 应用题**　HFT 代码读一个 `unsigned char` 字节，想转成 `int` 做算术，如何避免符号扩展坑？

<details><summary>答案</summary>

```cpp
unsigned char byte = read_byte();   // 0..255
int value = byte;                    // ✅ 零扩展，value = 0..255

// 对比：若用 char
char c = read_byte();               // 若 byte >= 128，c 是负数
int wrong = c;                      // ❌ 符号扩展，可能变负数
int fixed = static_cast<unsigned char>(c);  // ✅ 先转 unsigned char 再转 int
```

要点：
- 处理二进制字节用 `unsigned char`（或 C++17 的 `std::byte`），不用 `char`
- `unsigned char` 转 `int` 是**零扩展**，不会变负数
- `char` 转 `int` 是**符号扩展**，可能变负数

C 程序员也踩这个——`<cctype>` 函数（`isalpha` 等）要求 `unsigned char` 转 `int` 参数，传 `char` 可能 UB。

</details>
