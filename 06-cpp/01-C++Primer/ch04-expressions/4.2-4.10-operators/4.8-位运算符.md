# 4.8 位运算符

## 本节讲什么

`~` `<<` `>>` `&` `|` `^`——教材建议**只对无符号整数**使用。

## 各运算符

| 运算符 | 含义 |
|--------|------|
| `~` | 按位取反 |
| `<<` | 左移：右侧丢弃，左侧补 0；等价 × 2ⁿ（无溢出时） |
| `>>` | 右移：**无符号**左侧补 0；**有符号**补符号位（实现相关，不推荐） |
| `&` | 按位与（掩码） |
| `|` | 按位或 |
| `^` | 按位异或 |

```cpp
unsigned flags = 0x01;
flags |= 0x02;           // 置位
if (flags & 0x01) { }    // 测位
```

## 与逻辑运算符区别

- `&` `|` `^`：**无短路**，两侧都求值  
- `&&` `||`：短路（见 [4.3](./4.3-关系与逻辑运算符.md)）

## HFT 典型用途

协议标志位、权限掩码、快速 ×2 / ÷2（无符号左移/右移）；解析二进制字段时常与 `unsigned` 掩码配合。

## 和 C 的区别（位运算符：C/C++ 完全一致）

位运算符是 C 和 C++ **完全共享**的部分——`~` `<<` `>>` `&` `|` `^` 的语义、整型提升、有符号右移实现相关，两边一字不差：

| 对比点 | C | C++ |
|--------|----|------|
| `~ & \| ^` 按位运算 | ✅ 一致 | ✅ 一致 |
| `<<` 左移补 0 | ✅ | ✅ 一致 |
| `>>` 有符号补符号位（实现相关） | ✅ | ✅ 一致 |
| `>>` 无符号补 0 | ✅ | ✅ 一致 |
| 整型提升（char/short → int） | ✅ | ✅ 一致 |
| `&`/`\|` 无短路 | ✅ | ✅ 一致 |
| 有符号左移溢出 UB | ✅ | ✅ 一致 |

**给 C 程序员的关键提醒：**
1. **位运算符无需任何转变**——C 学的"位运算心法"直接用。掩码、置位、测位、异或交换、`x & (x-1)` 消最低位 1 这些技巧两边通用。
2. **教材建议"只对无符号用位运算"**两边都适用——有符号右移补符号位是**实现相关**（不同编译器可能不同），有符号左移溢出是 UB。**用 `unsigned`/`uint32_t` 做位运算**是跨平台安全的做法。
3. **C++ 多了 `std::bitset`**——固定大小位集合，比手写 `unsigned flags` 更安全（自带边界检查、`[]` 访问位、`to_string`/`to_ulong` 转换）。但 HFT 热路径仍用 `uint64_t` + 位运算（零开销）。

## 常见错误

### 1. 对有符号整数右移

```cpp
int x = -8;
int y = x >> 1;   // 实现相关：可能是 -4（算术右移）或大正数（逻辑右移）
```

有符号右移补符号位（算术右移）还是补 0（逻辑右移）是**实现相关**——x86/GCC/Clang 补符号位，某些嵌入式平台补 0。**用 `unsigned`** 保证补 0。C 和 C++ 都有这个坑。

### 2. `&` 误用为 `&&`

```cpp
if (flags & 0x01) { ... }      // ✅ 测位：flags 和 0x01 按位与，非 0 为真
if (flags && 0x01) { ... }     // ❌ 逻辑与：flags 非 0 且 0x01 非 0（恒真）
```

`&` 是位与，`&&` 是逻辑与。测位用 `&`，逻辑判断用 `&&`。C 程序员分得清，但 C++ 里 `bool` 和 `int` 隐式转换更容易混。

### 3. 移位位数超过类型宽度

```cpp
int x = 1;
int y = x << 32;   // ❌ UB（int 通常 32 位，移 32 位未定义）
```

移位位数 `>=` 类型位宽是 UB（C 和 C++ 都一样）。`int` 32 位时 `<< 32`、`<< 33`、`<< 100` 都是 UB。**确保移位位数 `< sizeof(T)*8`**。

## 自测题

**1. 选择题**　`unsigned x = 0xF0; x & 0x0F` 的结果是：

- A. `0xF0`
- B. `0x0F`
- C. `0xFF`
- D. `0x00`

<details><summary>答案</summary>

**D**。`0xF0`（11110000）和 `0x0F`（00001111）按位与，每位都不同，结果是 `0x00`。这是"掩码取低位"的反例——`x & 0x0F` 取 `x` 的低 4 位，但 `x = 0xF0` 的低 4 位是 0。C 也是同样运算。

</details>

**2. 判断题**　`int x = -1; x >> 1` 的结果在所有 C++ 实现上都相同。

<details><summary>答案</summary>

**错**。有符号右移是**实现相关**——x86/GCC/Clang 补符号位（算术右移），`-1 >> 1` 还是 `-1`；某些嵌入式平台补 0（逻辑右移），`-1 >> 1` 是大正数。**用 `unsigned`** 保证补 0，跨平台一致。C 也有同样问题。

</details>

**3. 踩坑题**　HFT 代码用位运算快速除以 2，哪里有问题？

```cpp
int qty = -10;
int half = qty >> 1;   // 想得到 -5
```

<details><summary>答案</summary>

**结果实现相关**。`qty` 是 `int`（有符号），`>> 1` 在 x86/GCC/Clang 上补符号位（算术右移）得 `-5`，但在补 0 的平台上得大正数。**修复**：

```cpp
// 方法 1：用除法（编译器会优化为右移）
int half = qty / 2;   // 总是 -5，跨平台一致

// 方法 2：用 unsigned（但会改变负数语义）
// unsigned 不能表示 -10，要先转

// 方法 3：HFT 常用定点小数，用 int64_t + 显式除法
```

C 程序员习惯用 `>> 1` 替代 `/ 2`（快），但**对负数不安全**。现代编译器会把 `/ 2` 优化成右移，无需手写 `>>`。

</details>

**4. 应用题**　用位运算实现"置位、清位、测位、翻转位"四个操作，操作 `flags` 的第 `n` 位。

<details><summary>答案</summary>

```cpp
unsigned flags = 0;
int n = 3;   // 操作第 3 位（0-indexed）

flags |= (1u << n);       // 置位：或上 1<
flags &= ~(1u << n);      // 清位：与上 ~(1<
bool set = flags & (1u << n);   // 测位：与 1<
flags ^= (1u << n);       // 翻转位：异或 1<<
```

要点：
- 用 `1u`（unsigned）避免有符号移位问题
- `n` 必须 `< sizeof(unsigned)*8`（通常 32），否则 UB
- C 程序员的位运算心法直接迁移，C++ 无差异

C++ 还可用 `std::bitset`：

```cpp
std::bitset<32> flags;
flags.set(n);      // 置位
flags.reset(n);    // 清位
flags.test(n);     // 测位
flags.flip(n);     // 翻转
```

更安全但稍有开销，HFT 热路径仍用 `unsigned` + 位运算。

</details>
