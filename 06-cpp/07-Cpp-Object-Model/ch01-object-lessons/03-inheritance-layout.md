# 1.3 继承布局

> 第 1 章 · 上一节：[1.2 虚函数与 vptr](02-vptr-vtable.md) · 下一节：[1.4 封装的代价](04-encapsulation-cost.md)

## 这节讲什么

单继承、多继承、虚继承的对象布局有何不同？每种继承都有代价——vptr 数量、this 调整、额外指针。

---

## 三种继承的布局

| 继承 | 布局 | 代价 |
|------|------|------|
| 单继承 | 派生成员追加在基类之后 | 一个 vptr（复用基类的） |
| 多继承 | 多个基类子对象，多个 vptr | this 调整（访问非首基类） |
| 虚继承 | 虚基类指针/偏移表 | 额外间接（运行时定位虚基类） |

```
单继承: [Base vptr | Base data | Derived data]
多继承: [Base1 vptr | Base1 data | Base2 vptr | Base2 data | Derived data]
虚继承: [vptr | vbptr | data | ... | virtual base (共享一份)]
```

---

## 新手要点（和 C 的区别）

- **C 没有继承**：C 用结构体嵌套模拟"继承"（`struct Derived { Base base; int extra; }`），但需手动管理。C++ 的继承让编译器自动布局。
- **多继承的 this 调整**：调非首基类的成员时，`this` 要偏移到对应基类子对象——这是多继承的隐藏代价。
- **虚继承解决菱形继承**：`D` 继承 `B` 和 `C`，`B`/`C` 都继承 `A`——没有虚继承 `A` 存两份；有虚继承 `A` 存一份但需通过偏移表定位。

---

## HFT 关联

- **避免多继承/虚继承**：布局膨胀 + this 调整 + 额外指针让对象变大、访问变慢。HFT 热路径数据结构用单继承或组合（has-a）替代。
