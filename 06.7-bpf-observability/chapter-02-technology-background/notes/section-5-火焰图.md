# 2.5 火焰图（读法 / 特性 / 变体）

> 底本：《BPF之巅》第 2 章技术背景，2.5 节（印刷 p42–45，含 2.5.1–2.5.5）

火焰图是 Brendan Gregg 的招牌发明，本节讲它如何从调用栈数据生成、怎么读、有哪些变体。

## 2.5.1–2.5.2 调用栈信息 → 剖析

采样得到的调用栈（每栈若干帧）按"栈底→栈顶"逐帧拼接计数。例如采样两次 `main→func_a→func_c`、一次 `main→func_a`，得到每帧的计数。这一步把海量栈数据压缩成可画的树。

工作示例（务必亲手推一遍）：

```text
采样 1: main → func_a → func_c
采样 2: main → func_a → func_c
采样 3: main → func_a

逐帧计数（父帧计数 = 包含它的采样数）:
main       : 3     ← 3 次采样都在 main 里
func_a     : 3     ← 3 次都经过 func_a
func_c     : 2     ← 2 次深入到 func_c

含义: main 的 CPU 时间里，100% 在 func_a；其中 2/3 深入 func_c。
     func_a 自身（不含子调用）占 1/3。
```

这个"**父帧宽度 = 子帧宽度之和 + 自身宽度**"的关系是读图的核心不变量。

## 2.5.3 火焰图怎么画

- 每个帧一个矩形；**宽度 ∝ 该帧出现次数（频率）**；Y 轴是栈深（上=被调者）。
- 同层帧按**字母序**排列（不是时间序！）。
- 颜色随机（暖色系），仅为了区分相邻矩形，无数据含义。

## 2.5.4 读法要点（书中的核心经验）

1. **先看最宽的"塔"**——占比最大的代码路径最值得优化。
2. **自顶向下找宽 plateau（平顶）**——顶部无子帧的宽矩形是叶子函数，直接热点。
3. X 相邻不代表时间相邻；比较两个矩形宽度才有意义。
4. 火焰图显示的是**采样占比**（on-CPU 时间份额），不是单次调用耗时。

补充两条实战读法：

- **宽塔 ≠ 慢函数**：宽度是时间份额。一个函数宽可能因为"单次慢"，也可能因为"调得频"——火焰图区分不了，要看下一层结构（子帧多 = 调了好多东西；无子帧且宽 = 自身计算重）或配合 call count 工具（如 funccount）。
- **栈深突然变化**是线索：某条路径比邻居深好几层，常意味着框架层误用（重复包装、递归）——横着扫一遍深度突变点。

## 2.5.5 变体

| 变体 | 数据源 | 回答的问题 |
|---|---|---|
| CPU 火焰图（on-CPU） | PMC/定时采样 | CPU 时间去哪了 |
| off-CPU 火焰图 | 调度器事件 | 阻塞/等待时间去哪了 |
| 内存火焰图 | malloc/free/页错误 | 谁分配/占用了内存 |
| 差分火焰图 | 优化前后两图对比 | 优化生效了吗 |
| 冰柱图 | 火焰图倒置 | 视觉偏好 |

变体的生成逻辑：**火焰图 = 栈数据 + 计数的可视化**，换掉"数据源"就得到新变体——这与 2.1 节"事件源可插拔"完全同构。off-CPU 图的数据源是调度器事件（线程被切下 CPU 时抓栈 + 记录唤醒它的线程），所以它的"宽度"是**离开 CPU 的时间份额**。

## HFT 关联

- HFT 延迟分析两大杀手锏：**on-CPU 火焰图**（交易线程热路径、找宽塔=最耗时函数）+ **off-CPU 火焰图**（行情线程为何被挂起：锁、page fault、futex 等待）。两者合起来覆盖"在跑"和"没在跑"的全部时间。
- 差分火焰图用于验证调优：改动前各抓一份，对比确认热点迁移。
- 注意：perf 采样对被观测进程有微开销，HFT 生产机上建议短窗口、低频率（如 49Hz）采样。
- 延迟尖刺复盘的取图顺序：先 on-CPU 看常态热点（宽塔），无异常再上 off-CPU 查阻塞——"尖刺"多数在 off-CPU 图里（等锁/换页/调度）。

## 陷阱

- 把 X 轴当时间轴读（"左边先执行"）——错，是字母序。
- on-CPU 火焰图看不到睡眠/阻塞：交易系统"线程闲着但延迟高"要看 off-CPU 图。
- 采样频率与目标工作负载频率锁相（如都恰好 100Hz）会引入偏差 → 用 99Hz 这类质数频率。
- 宽塔直接当"慢函数"修：先分清"单次慢"还是"调用频"（看子帧结构/配合计数工具），否则优化方向可能完全反了。
- off-CPU 图的"时间份额"含正常等待（如等下一条行情的空转）——先按等待时长过滤（offcputime -K）再画，否则图被闲等淹没。

## 自测

<details>
<summary>1. 火焰图中矩形的宽度、高度、颜色各代表什么？</summary>

宽度=该帧在采样中的出现频率（时间占比）；高度=调用深度（Y 轴向上是被调者）；颜色无数据含义，仅视觉区分。
</details>

<details>
<summary>2. 为什么用 99Hz 而不是 100Hz 采样？</summary>

避免与负载固有周期（如 100Hz 的定时器）锁步采样（lockstep sampling），造成系统性偏差。
</details>

<details>
<summary>3. off-CPU 火焰图解决什么问题？</summary>

展示线程不在 CPU 上运行时的时间分布（等锁、IO、调度延迟等），与 on-CPU 图互补。
</details>

<details>
<summary>4. 一个宽矩形，如何判断它是"单次耗时长"还是"调用频率高"？</summary>

看下一层：有大量子帧 → 时间花在子调用上（继续下钻）；无子帧且宽 → 自身计算重；还要配合调用计数工具（funccount）区分"频次 × 单次成本"。宽度只给乘积，拆开乘积要靠结构和其他工具。
</details>

<details>
<summary>5. 为什么"父帧宽度 = 子帧宽度之和 + 自身宽度"？违反它的图说明什么？</summary>

父帧计数 = 包含该帧的采样数，每个采样必然同时计入父帧与其中一条子路径（或父帧自身叶子），所以守恒。违反说明可视化或数据有 bug（如栈截断、递归合并错误），读数不可信。
</details>
