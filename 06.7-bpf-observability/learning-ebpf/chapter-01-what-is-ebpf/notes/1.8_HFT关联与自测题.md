## 1.8 HFT 关联

> 本节讲什么：第 1 章的概念怎么落到 HFT 工程上——不是"能做什么"的罗列，而是三个具体武器。

## 1. 内核态过滤 = 低开销观测的物理来源

交易系统全链路上每秒百万级事件（syscall、网卡包、调度事件）。观测这些事件的传统做法（每事件拷到用户态再筛）会直接把系统拖垮；eBPF 在内核里**先过滤/聚合，只让结果出内核**：

```
   事件洪流(1M/s) ──▶ [内核: eBPF 过滤/聚合] ──只有感兴趣的事件(1k/s)──▶ 用户态工具
```

这就是 HFT 观测栈（Pixie、Parca、Hubble、Cilium）敢宣称"低到可以常开"开销的机制根源——不是优化技巧，是架构位置带来的。

**工程含义**：观测工具本身不能再成为延迟抖动源。给交易机常开观测，eBPF 是唯一现实选项。

## 2. XDP 2.5×/4.3×：评估旁路方案时的基准锚点

HFT 网络常讨论 DPDK/内核旁路（kernel bypass）——把网卡从内核手里抢过来自己轮询。对比维度：

| | DPDK 旁路 | eBPF/XDP |
|---|---|---|
| 收益 | 最高（完全绕开内核栈） | 接近（快 2.5×/4.3× 的量级） |
| 代价 | 整网卡被独占、丢通用性（tcpdump/常规工具全瞎）、开发重 | 网卡还在内核管理，**保留全部常规工具链** |
| 可移植 | 特定 NIC + 大量定制 | CO-RE 跨内核 |

XDP 论文的数字是决策锚点：**eBPF 拿到接近旁路的收益，却保留内核栈的通用性**。对不是极致裸金属的场景（行情接入前处理、风控前置过滤），XDP 是性价比甜点。

## 3. 延迟毛刺狩猎：抓 perf 抓不到的东西

HFT 最痛的不是平均延迟，是 **p99.9 的偶发毛刺**——来源往往是：

- 调度被抢（CFS 语义，参见你 kernel/2.8 调度类笔记）
- 软中断/硬中断插队
- 页回收（kswapd）扫了你的页
- 内核锁竞争（cgroup、文件系统）

这些全发生在内核里，且**不可复现、频率极低**——传统采样式 perf（统计采样）大概率漏采。eBPF 的做法是**事件触发**：挂 sched:sched_switch、irq tracepoint、网卡队列事件，无条件记录每一次发生，事后回放时间线。你在 lab01 已经跑过 `@[comm] = count()` 的雏形；进阶版是给每次调度切换记时间戳算 off-cpu 时间——第 5 阶段（延迟观测）的主菜。

1. 1993 BPF 论文的"伪机器"解决什么问题？为什么说它比抓包过滤器的意义大？
2. 3.18 (2014) 引入的 eBPF 五大变化是什么？各自解决什么？
3. 为什么说"改内核源码"从想法到生产要数年？各阶段瓶颈在哪？
4. 内核模块的两大安全顾虑是什么？eBPF 验证器分别怎么应对？
5. echo "hello" 为什么有 100+ 次系统调用？这个事实对 eBPF 观测意味着什么？
6. sidecar 模型的四个缺陷，eBPF 分别怎么消除？

<details>
<summary>参考答案</summary>

**1.** 解决抓包的两次拷贝问题：过滤器跑用户态时每个包（包括被丢弃的）都要付"内核→用户态"拷贝+切换成本；伪机器让过滤器在内核里就地判决，不要的包零成本丢弃。意义在于确立了"自定义程序在内核里执行"的思想——包过滤只是第一个场景，指令集+内核执行环境这两个要素后来长成了 eBPF。

**2.** ①64 位指令集+寄存器——能处理现代内核的 64 位指针/数据；②maps——有地方存状态、和用户态交换结构化数据；③`bpf()` 系统调用——统一的加载/操作入口；④helper 白名单——有限的内核功能访问（拿 pid、读内存…）；⑤验证器——加载前证明安全，内核因此"敢"执行外来代码。（口诀：能算、能存、能加载、能访问、敢让你跑。）

**3.** 三个阶段各有瓶颈：写补丁（3000 万行代码门槛）→ 评审（仅 1/3 被接受，3-6 个月）→ 等发行版采纳（RHEL 8.5 还在用 3 年前的 4.18）。叠加起来以年计。

**4.** 顾虑一：模块崩溃=整机崩溃（内核态无页保护兜底）→ verifier 证明所有内存访问有界、程序必终止。顾虑二：模块有全部特权、可当 rootkit → verifier 限制只能调用白名单 helper 且参数类型正确，无法任意访问内核内存。

**5.** 因为动态链接：加载 ld.so.cache、libselinux、libc 等 30 次 openat + 20 次 mmap……（lab02 里亲眼见过这条链）。对 eBPF 的意义：syscall 边界是应用全部外部行为的必经之路，在这设卡=看穿一切进程且无感知、不可绕过。

**6.** ①要重启 Pod → eBPF 动态加载即时生效；②注入漏标漏观测 → 挂内核上没有"漏标"概念，全进程覆盖；③ready 顺序竞态 → 没有 sidecar 就没有顺序问题；④流量绕路加延迟 → 逻辑在内核原地执行零绕路。

</details>
