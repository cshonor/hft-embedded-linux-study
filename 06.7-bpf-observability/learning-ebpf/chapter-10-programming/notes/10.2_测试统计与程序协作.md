## 10.4 测试与性能统计

- **BPF_PROG_RUN**：用户态直接运行 eBPF 程序做测试（目前主要支持网络类程序类型）
- 运行时统计：

```sh
sysctl -w kernel.bpf_stats_enabled=1
bpftool prog list     # 多出 run_time_ns / run_cnt 字段
# 例：run_time_ns 316876 run_cnt 4 → 4 次执行共 ~300μs
```

## 10.5 多 eBPF 程序的协作

- 一个 eBPF 程序 = 一个函数 + 一个事件；真实应用（如 opensnoop）需要**多个程序协同**
- 程序之间**本质独立，靠 map 协调**（entry 写 map，exit 读删 map）
- 进阶形态：程序数量**动态变化**——Cilium 给每个虚拟网卡挂程序，Pod 增减时接口来去
- 骨架类工具（libbpf / ebpf-go）一条调用加载全部程序与 map，也提供单个对象的细粒度操作

## 10.6 选型速查（作者结论）

| 场景 | 选择 |
|---|---|
| 快速收集 trace 信息 | bpftrace |
| Python 快速原型、不在乎运行时编译 | BCC |
| 生产分发、跨内核版本可移植（CO-RE） | C: libbpf；Go: cilium/ebpf 或 libbpfgo；Rust: Aya |
| Rust 全栈（内核+用户态同语言、无 LLVM 依赖） | Aya |
