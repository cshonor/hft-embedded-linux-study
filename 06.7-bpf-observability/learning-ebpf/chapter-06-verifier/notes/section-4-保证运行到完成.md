# 保证"运行到完成"

### 4.1 循环限制的演进

| 内核版本 | 规则 |
|---|---|
| < 5.3 | **禁止向后跳转** = 禁止一切循环；程序员用 `#pragma unroll` 让编译器把循环展开成重复指令序列 |
| ≥ 5.3 | 验证器跟踪向前+向后分支，接受**有界循环**，前提是路径探索不超 100 万指令上限 |
| ≥ 5.17 | `bpf_loop()` helper：第一个参数给最大迭代次数，每轮调回调函数——**回调体只需验证一次**，无论实际跑多少轮；回调返回非零可提前终止 |
| — | `bpf_for_each_map_elem()`：对 map 每个元素调回调，同样是回调式 |

坑：`for (i=0; i < c; i++)` 其中 c 是**全局变量**（无上限静态信息）→ 验证器展开探索直到撞 100 万上限拒绝。循环边界必须让验证器能推出常数上界。

### 4.2 返回值检查

- 程序返回值放 R0，没初始化就结束 → `R0 !read_ok`
- 反直觉：注释掉 return 但留一个 `bpf_printk()` 反而**能过**——helper 的返回值也存 R0，调用过 helper 后 R0 就算"已初始化"了（尽管值是垃圾）

### 4.3 其他

- 无效指令（未知 opcode）：编译器 bug 才会出现，除非手写字节码；但**新指令在老内核上不过**（如原子操作指令）
- 不可达指令：拒绝（通常编译器已优化掉）
