> 底本：《BPF之巅》第 14 章 内核，14.1 节（印刷 p665–668）

内核是整个系统的心脏，也是一套复杂软件。前面章节用内核插桩理解**应用程序**行为；本章用内核插桩理解**内核软件内部运行**，对内核代码定位故障、辅助开发。

> 子系统专项先看前章：sched→第6章、mm→第7章、fs→第8章、block→第9章、net→第10章。本章研究内核**本身**而非资源。

## 14.1.1 内核基础知识

### 唤醒（wakeup）

- 线程阻塞脱离 CPU 等事件，事件完成后由**唤醒事件**触发返回 CPU（如：线程阻塞在文件系统读的磁盘 I/O 上，被处理完成中断的工作线程唤醒）
- **唤醒依赖链**：线程 A 唤醒 B，B 再唤醒 C……直到阻塞的应用程序被唤醒（图 14-1：应用线程 → 系统调用 → 阻塞 ← 资源线程 ← 依赖线程）
- **跟踪唤醒事件可揭示 off-CPU 事件持续时间的更多信息**

### 内核内存分配

| 分配器 | 用途 | 机制 |
|--------|------|------|
| **slab/slub 分配器** | 固定大小对象的通用分配 | 分配请求的缓存与回收提高效率；slub 基于 slab 论文（Bonwick94）简化而来 |
| **页分配器** | 分配内存页 | **伙伴算法**找相邻空闲页合并分配；支持 NUMA |

API：小块 `kmalloc()`/`kzalloc()`/`kmem_cache_alloc()`（slab）；大块 `vmalloc()`/`vzalloc()`；页 `alloc_pages()`。

### 内核锁

第 13 章讲了用户态锁；内核支持**自旋锁、互斥锁、读写锁**。锁会阻塞线程，常是性能问题来源。

获取 Linux 内核互斥锁的三条路径（按序尝试）：

1. **fastpath**：cmpxchg（比较并交换）指令
2. **midpath**：锁持有者正在运行 → **乐观自旋**，期待很快释放
3. **slowpath**：阻塞直到可用

**RCU（读-复制-更新）**：允许多个读操作的同时进行更新，对读多写少的数据提高性能和伸缩性。

### 小任务（tasklet）与工作队列

设备驱动分两部分：**上半部分**快速处理中断（常在禁止中断模式下运行，运行过久会导致延迟问题），工作调度到**下半部分**稍后处理——下半部分可用：

- **小任务（tasklet）**：软件中断上下文执行，不可睡眠
- **工作队列（workqueue）**：可被内核调度的**线程**，必要时可睡眠（图 14-2）

## 14.1.2 BPF 的分析能力

BPF 可回答：线程为什么离开 CPU、等多久？在等什么事件？谁在用 slab？NUMA 是否在迁页？什么工作队列事件、延迟多少？内核开发者关心的函数调用/参数/返回值/延迟？

### 事件源（表 14-1）

| 事件类型 | 事件源 |
|----------|--------|
| 内核函数执行 | kprobes |
| 调度器事件 | sched 跟踪点 |
| 系统调用 | syscalls / raw_syscalls 跟踪点 |
| 内核内存分配 | kmem 跟踪点 |
| 页面换出守护进程扫描 | vmscan 跟踪点 |
| 中断 | irq / irqvectors 跟踪点 |
| 工作队列执行 | workqueue 跟踪点 |
| 计时器 | timer 跟踪点 |
| IRQ 和抢占禁用 | preemptirq 跟踪点（需 CONFIG_PREEMPTIRQ_EVENTS） |

查看内核支持的跟踪点：`bpftrace -l 'tracepoint:*'` 或 `perf list tracepoint`。

## HFT 关联

- 唤醒链 = 延迟归因的关键：行情网卡中断 → softirq → 唤醒读线程 → 唤醒策略线程，offwaketime（14.4.4）能把这条链串起来
- 互斥锁三路径中 **midpath 乐观自旋耗 CPU 但不睡眠**——CPU 剖析里看到的自旋时间即来源于此（14.4.6 自旋锁一节的处理方法）
- 内核通常编译了栈支持（帧指针或 ORC）→ **内核态栈遍历开箱即用**，不像用户态受 libc 帧指针之苦

1. 内核互斥锁获取的三条路径按什么顺序尝试？
   <details><summary>答</summary>fastpath（cmpxchg）→ midpath（持有者在运行则乐观自旋）→ slowpath（阻塞等待）。</details>

2. 小任务与工作队列的区别？
   <details><summary>答</summary>小任务在软中断上下文执行、不可睡眠；工作队列是可调度的内核线程、必要时可睡眠。</details>

3. slab 与页分配器各管什么？对应哪些 API？
   <details><summary>答</summary>slab 管固定大小对象（kmalloc/kzalloc/kmem_cache_alloc）；页分配器管内存页（alloc_pages，伙伴算法）；大块区域用 vmalloc。</details>
