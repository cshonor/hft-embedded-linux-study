# 1.1 BPF 和 eBPF 是什么

> 底本：《BPF之巅》中文版 1.1 节（PDF p41–42）

## 一句话定义

BPF 提供了一种**在各种内核事件和应用程序事件发生时运行一段小程序的机制**。

作者用的类比很精准：JavaScript 允许网站在浏览器事件（鼠标单击）发生时运行小程序，由此催生了 Web 应用生态；BPF 允许内核在系统和应用事件（如磁盘 I/O）发生时运行小程序，由此把**内核变得完全可编程**——而且不需要你是内核开发人员。

## BPF 的组成（三件套）

| 组成 | 说明 |
|---|---|
| **指令集** | 虚拟指令集规范，因此 BPF 可视作一种虚拟机实现 |
| **存储对象** | map 等 |
| **辅助函数** | helper functions |

执行方式两种：**解释器** + **JIT 编译器**（把 BPF 指令动态翻译成本地指令）。执行之前必须过**验证器（verifier）**安全检查——保证程序自身不会崩溃或损坏内核，但**不保证程序合乎逻辑**（可以写出能跑但没意义的程序）。

## 名字辨析：BPF vs eBPF

- 1992 年的 BPF = Berkeley Packet Filter（伯克利数据包过滤器），冷门的包过滤技术
- 2014 年，Alexei Starovoitov 提交重新实现 BPF 的内核补丁，与 Daniel Borkmann 共同完善后并入主线——BPF 变成**通用执行引擎**
- 扩展后的 BPF 常缩写为 **eBPF**，但**官方缩写仍然是不带 e 的 BPF**
- 内核中只有一个执行引擎，同时支持"扩展版"和"经典"程序；经典 BPF 程序由内核自动迁移到扩展引擎执行，经典 BPF 开发已停止
- 本书（以及如今社区惯例）用 **BPF 指代扩展后的 BPF**

## 三大应用领域

网络、可观测性、安全。本书聚焦**可观测性（跟踪）**。

### HFT 关联

- "事件发生时运行一段小程序"= 行情包到达、订单回调、定时器到期时**现场计算统计**，而不是把原始事件全部搬运到用户态再处理——这是 HFT 延迟观测零拷贝思路的根源
- 验证器"保证不崩内核但不保证逻辑正确"：写 BPF 观测程序时，**数值错误不会搞挂交易机，但可能让数据悄悄失真**——上线前要对照已知基准验证输出
