# 5.10 bpftrace 的控制流

> 底本：《BPF之巅》第 5 章 bpftrace（印刷 p137–190），5.10 节（印刷 p163–164）

## 内容详解

bpftrace 支持 3 种测试：**过滤器、三元运算符、if 语句**。布尔运算符：`==`、`!=`、`>`、`<`、`>=`、`<=`、`&&`、`||`；表达式可用括号分组。

**循环支持有限**：BPF 验证器出于安全拒绝可能无限循环的代码；bpftrace 支持**循环展开**，未来支持有界循环。

### 三种测试的选型（同一件事的三种写法，开销和适用面不同）

| 写法 | 形式 | 每事件开销 | 适用 |
|------|------|-----------|------|
| 过滤器 | `probe /test/ {...}` | **最低**——不满足直接跳过整个动作块 | 单一条件、整段动作都依赖它时**永远首选** |
| 三元 | `test ? a : b` | 低 | 单个表达式的二选一（求绝对值、选单位） |
| if | `if (test) {...} else {...}` | 低 | 多语句分支（IPv4/IPv6 各处理一段） |

纪律（与 5.5 呼应）：**能用过滤器的绝不写进 if**。过滤器在动作块之前判断，命中失败的连块都不进；if 是进了块再分支。对高频探针，"大部分事件都不命中"的场景，过滤器版本把不命中路径压到最短。

### 5.10.1 过滤器

```
probe/filter/{ action }
```

`/pid == 123/` 只有 pid 等于 123 才执行动作（内核态过滤，便宜）。

### 5.10.2 三元操作符

```
test ? true_statement : false_statement
```

经典用例——求绝对值：`$abs = $x > 0 ? $x : -$x;`

（注意：书中此例在"全部 64 位无符号"的语义下要小心——`-$x` 的结果仍按无符号解释，见 5.11 陷阱。真正安全的绝对值要先把被比较量想清楚是否可能"逻辑为负"。）

### 5.10.3 if 语句

```
if (test) { true_statements }
if (test) { true_statements } else { false_statements }
```

用例：IPv4/IPv6 分支处理 `if ($inetfamily == AF_INET) {...} else {...}`。**不支持 else if**（可嵌套 if 代替）：

```awk
// 没有 else if，多分支只能嵌套：
if ($f == 1) { ... } else {
    if ($f == 2) { ... } else {
        if ($f == 3) { ... }
    }
}
// 三层以上就该重构：换 map 查表或拆成多个探针/过滤器
```

### 5.10.4 循环展开

```
unroll(count) { statements }
```

- count 是**编译期常量**，最大 **20**；不能传变量——循环次数必须在 BPF 编译阶段确定；
- 背景：BPF 运行在受限环境，验证器必须能证明程序可终止；

### unroll 的机理：为什么"常量、≤20"

unroll 不是"执行循环"，而是**编译期把循环体复制 N 份**：

```
unroll(4) { printf("%d", $i); }
        │ 编译期展开（bpftrace 里 $i 逐次代换）
        ▼
printf("%d", 0); printf("%d", 1); printf("%d", 2); printf("%d", 3);
        │ 一份源码 → 4 倍指令数
        ▼
BPF 字节码：指令数 × 4（上限 BPF_MAXINSNS = 4096）
```

三个限制全是这套机制的直接后果：

| 限制 | 原因 |
|------|------|
| 必须编译期常量 | 展开发生在编译阶段，运行时才知道的次数没法展开 |
| 上限 20 | 指令数膨胀 ×N，4096 指令上限很容易被 20 份循环体+主逻辑顶穿（书取 20 是保守值） |
| 没有循环变量运算 | 展开后的"每次迭代"其实是独立指令序列，不是真的跳转回边 |

**Linux 5.3 起内核支持 BPF 有界循环**（验证器对后向跳转做状态分析，证明循环计数器单调收敛到退出），bpftrace 后续版本在 unroll() 之外提供 for/while——真正的循环，指令不膨胀，但要求验证器能推断上界。

## HFT 关联

- 内核态过滤（`/.../`）永远优先于用户态过滤——把条件写进探针行，事件不过滤就不出内核；
- 需要遍历数组/链表的场景在老版本上只能 unroll(20) 硬展开，新内核+新版 bpftrace 才有真正的 for/while——写脚本前先确认版本支持；
- 多分支嵌套 vs map 查表：行情解码类脚本（按 msg type 分支）在 bpftrace 里更地道的写法是 `@[msgtype] = count()` 先看分布、再对可疑 type 单独开探针——**用聚合代替分支**，把"程序逻辑"降级成"数据统计"。

## 陷阱

- ⚠️ 无 else if；无 while(true)；普通 for/while 在 5.3 内核之前不可用（unroll 上限 20 且必须常量）。
- ⚠️ 三元/if 里的复杂表达式同样受验证器约束（除法、指针访问规则），编译报错时先简化表达式。
- ⚠️ unroll(20) × 大循环体 → 验证器报 "program too large / 指令数超限"：这不是循环写错了，是展开后的指令数爆了——减小循环体或拆分。
