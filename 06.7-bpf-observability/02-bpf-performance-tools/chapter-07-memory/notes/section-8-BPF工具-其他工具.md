# 7.3 BPF 工具（六）：其他工具

> 底本：《BPF之巅》第 7 章 内存，7.3.12 节（印刷 p287–288）。

本章场景下值得使用的"外来"工具（详见第 6 章）：

| 工具 | 来源章 | 内存场景用途 |
|------|--------|--------------|
| **llcstat(8)** | BCC，Ch6 | 按进程的 LLC 命中率 — 缓存效率视角的内存分析（PMC 溢出采样） |
| **profile(8)** | BCC，Ch6 | 定时采样调用栈 — **粗粒度、低成本**获取"哪些路径在调 malloc"的替代方案（避开 memleak 的高开销） |

内核内存方向的更多工具在第 14 章：kmem(8)、kpages(8)、slabratetop(8)、numamove(8)。

## profile 替代 memleak 的思路

memleak 跟踪每次 malloc/free（每秒百万次、开销巨大）；profile 定时采样（49Hz）在 CPU 上运行的栈 — 分配密集的代码路径自然被高频采样到。得到的是"哪些路径在做分配"的粗粒度画像，足够指导优化方向，且开销可忽略。精细到字节级的泄漏定位再上 memleak（测试环境 + `-S` 采样）。

### 两者对比（同为"找分配路径"，模型完全不同）

| | memleak | profile |
|--|---------|---------|
| 观测模型 | 逐事件记账（malloc/free 配对） | 定时采样在跑的栈 |
| 回答的问题 | "哪些分配**没有还**" | "哪些路径**在做**分配" |
| 漏检风险 | 无（全量时） | 低频路径可能采不到（0.1% 占比的分配路径在 49Hz 下平均 ~20 分钟才一帧） |
| 误报方向 | 把正常长期内存列为悬账 | 把"常在 CPU 上"误当"常在分配"（要人工看栈里是不是分配路径） |
| 开销 | 与分配频率成正比（可 >10×） | 固定 49Hz 税 |
| 定位 | 需要 | 演示/回测机 |

两段式工作流的判据：**先问"量对不对"（growth 曲线/RSS 趋势），再问"路径在哪"**。量没问题的机器连 profile 都不用挂——crontab 里的 RSS 采样就够。

## HFT 关联

- 策略进程的分配热点画像：`profile -F 49 -u -p <pid>` 跑一段回测，栈里 malloc/operator new 占比高的路径就是改造对象（arena/对象池/预分配）
- llcstat 监控数据结构缓存友好性（与 Ch6 呼应）

## 常见陷阱

1. **一上来就 memleak 找分配热点** — 先用 profile 采样画像（零成本），确认有问题的路径后再精准跟踪
2. **内存问题只在应用层找** — 内核 slab/NUMA 迁移同样吃内存与延迟（第 14 章工具）
