## 一、IP 欺骗（IP Spoofing）——核心攻击

### 1）根因（必考）

- **IP 协议不校验源 IP 真实性**：源地址由发送端填写，网络层**默认信任**  
- **UDP、ICMP** 等无连接/弱状态最易伪造；**TCP** 有三次握手相对难，仍有 **SYN Flood、RST 劫持** 等  

### 2）原理

攻击者构造**源 IP 被伪造**的 IP 包：

- 伪装**受信任主机**（内网 IP、白名单服务器 IP）  
- 或**伪造受害者 IP 为源**，发动**反射攻击**  

### 3）典型危害

| # | 危害 | 说明 |
|---|------|------|
| 1 | **身份伪装/越权** | 绕过基于 IP 的 ACL |
| 2 | **反射型 DDoS（放大）** | 伪造受害者 IP 向 DNS/NTP/SSDP/Memcached 发请求 → 大流量响应打向受害者 |
| 3 | **会话劫持/中断** | 伪造 **TCP RST** 断开合法连接 |
| 4 | **溯源困难** | 真实攻击源被隐藏 |

## 二、主流防护手段（考试必背）

### 1）BCP 38 —— 边界入站过滤

| 项 | 说明 |
|----|------|
| 全称 | **Best Current Practice 38**（IETF 推荐） |
| 做法 | ISP/企业边界**丢弃源地址不属于本 AS/本网段**的入站包 |
| 一句话 | **你家的 IP 只能从你家接口进来** |

### 2）uRPF —— 单播反向路径转发

| 项 | 说明 |
|----|------|
| 原理 | 以**源 IP** 查路由：若**回包应走的接口 ≠ 入接口** → 丢弃（伪造） |
| **Strict** | 严格：回包接口必须 = 入接口（常用） |
| **Loose** | 宽松：只查是否存在路由，不校验接口 |
| 地位 | BCP 38 的**标准实现之一** |

### 3）应用层加固

- **不依赖 IP 做身份**：**TLS、会话令牌、API Key、MFA**  
- **监控**：源 IP 突变、流量突增、告警  
- **反射服务**：DNS/NTP 等 **源校验、限速、白名单**  

→ 深化：[ch18 TLS](../chapter18-network-security/study.md) · [§8.5 防火墙](../../top_down/08_network_security/study.md#ch8-9)

## 三、易混概念

| 易混 | 纠正 |
|------|------|
| IP 欺骗 vs 改目的 IP | 只伪造**源 IP**，目的 IP 正常 |
| 反射攻击 | **IP 欺骗 + 放大**；第三方当放大器 |
| IPv4 vs IPv6 欺骗门槛 | v6 有 IPsec、SLAAC/RA-Guard 等，**更难**但非不可能 |
| IP 欺骗 vs 扫描/嗅探 | 本节侧重**源地址伪造**；扫描见章级表 |

## 四、30 秒写卷子

- **根因**：网络层**不验源 IP**  
- **危害**：伪装、**反射 DDoS**、RST 劫持、难溯源  
- **BCP 38**：边界丢弃**非本网段源**入站包  
- **uRPF**：反向路径与入接口一致性  
- **核心**：网络层（BCP38/uRPF）+ 应用层（**不信 IP 身份**）

## 五、自测（2 题）

1. 反射型 DNS 放大攻击中，攻击者通常伪造的是**源 IP 还是目的 IP**？为什么？  
2. BCP 38 和 uRPF 的关系用一句话说？

<details>
<summary>答案</summary>

1. 伪造**源 IP = 受害者**；DNS 服务器把**大响应**发往「源地址」→ 打向受害者。  
2. **BCP 38 是策略原则**（过滤非法源）；**uRPF 是路由器上实现该思路的技术之一**。

</details>
