# 4.11 与 ARP 相关的攻击

> 章级精读：[study.md#ch04-11](./study.md#ch04-11) · [ch04 §4.9 管理命令](study.md#ch04-9) · [ch18 安全](../chapter18-network-security/study.md) · [ch03 §链路层安全](../chapter03-link-layer/3.10-link-layer-security.md#ch03-10-arp)

## 本节核心目标

掌握 **ARP 欺骗/中毒** 的原理、危害，以及工程落地的防护方案，同时明确**开发侧安全规范**。

---

<a id="ch04-11-basics"></a>

## 一、前置基础回顾

1. **ARP 核心逻辑**：根据 IP 查询对应 MAC，维护本机 **ARP 邻居表** → [4.2](4.2-arp-basic-operation.md) · [4.3 缓存](4.3-arp-cache.md)  
2. **协议致命缺陷**：**无身份认证、无校验**；主机默认信任收到的 ARP 报文，**后到的应答直接覆盖**原有表项  
3. **生效范围**：ARP 是二层广播协议，**仅在同一广播域（局域网）内**生效，**无法跨路由器**攻击  

---

<a id="ch04-11-spoof"></a>

## 二、ARP 欺骗 / ARP 中毒（Spoofing / Poisoning）

### 1）攻击原理

攻击者伪造 **ARP 应答**，向局域网内主机篡改 ARP 表：

- 伪造映射：`目标 IP → 攻击者 MAC`  
- 受害者后续访问该 IP 的流量 → 发往攻击者 → **中间人攻击（MITM）**

### 2）常见攻击形式

| 形式 | 做法 | 效果 |
|------|------|------|
| **单向欺骗** | 仅欺骗终端 | 终端流量经攻击者，可窃听**上行** |
| **双向欺骗（完整 MITM）** | 同时欺骗**终端**与**网关** | 终端侧：网关 IP → 攻击者 MAC；网关侧：终端 IP → 攻击者 MAC → **双向流量全程劫持** |

→ 链路层大白话：[ch03 §ARP 欺骗](../chapter03-link-layer/3.10-link-layer-security.md#ch03-10-arp-spoof)

<a id="ch04-11-impact"></a>

## 三、攻击后果

| 后果 | 说明 |
|------|------|
| **流量窃听** | 明文 HTTP、FTP、Telnet 的账号、密码、数据可被抓取 |
| **数据篡改** | 改内容、劫持下载、植入恶意程序 |
| **会话劫持** | 窃取 Cookie、冒充合法用户 |
| **组合攻击** | 搭配 **DHCP 劫持**，改网关/DNS，引流全网流量 → [ch06](../chapter06-dhcp-config/study.md) |

> **TLS/HTTPS** 可抵御**明文窃听**与内容篡改，但**不能阻止**流量被中转、断网等基础破坏。

→ 纵深防御：[ch18 网络安全](../chapter18-network-security/study.md)

<a id="ch04-11-mitigation"></a>

## 四、工程级缓解 / 防护方案

| 防护手段 | 作用说明 | 部署位置 |
|----------|----------|----------|
| **DAI（动态 ARP 检测）** | 交换机校验 ARP 合法性；结合 **DHCP Snooping** 绑定 IP–MAC，拦截伪造 ARP | **接入交换机**（企业/园区主流） |
| **静态 ARP 绑定** | 网关、核心服务器、关键终端固定 IP–MAC，拒绝动态更新 | 服务器、网关、关键终端 |
| **802.1X 端口认证** | 接入前身份认证，非法设备无法进网 | **接入交换机** |
| **TLS / IPsec** | 端到端加密；劫持也无法解密、篡改 | 应用层 / 网络层，**全业务推荐** |

<a id="ch04-11-dev"></a>

## 五、Go / Rust 开发侧安全规范

1. **严禁默认信任局域网邻居** — 不要依托二层「可信环境」做安全设计  
2. **敏感数据、凭证、业务报文** → 强制 **TLS**  
3. **内网服务间**也建议统一加密通道，规避 ARP 欺骗风险

<a id="ch04-11-tips"></a>

## 补充要点（易混 / 实操）

| 要点 | 说明 |
|------|------|
| **攻击层级** | 利用**协议设计漏洞**，属**二层攻击**；**防火墙（三层）无法直接拦截** |
| **家用环境** | 一般无 DAI、802.1X → 最有效：**静态 ARP 绑定 + 全程 HTTPS** |
| **异常征兆** | 突然断网、网速异常、抓包见大量陌生 ARP 应答 → 疑 ARP 欺骗 |

## 疑问与总结

**ARP 的效率来自局域网互信 — 同一机制也是 L2 最大风险之一；应用层必须自带 TLS，不能指望内网「天然安全」。**
