# 9.4 IGMP 和 MLD：加入组播组与 Snooping

> 章级精读：[study.md#ch09-4](./study.md#ch09-4) · 广播 vs 组播：[9.1 §LAN 区别](9.1-broadcast-multicast-concept.md#ch09-1-lan-diff) · 组播地址段：[9.3 §传播](9.3-multicast-mac-mapping.md#ch09-3-scope) · UDP socket：[ch10](../chapter10-udp-ip-fragment/study.md) · ND/MLD：[ch08 §8.5](../chapter08-icmpv4-icmpv6/8.5-ipv6-ndp.md)

## 本节核心目标

掌握 **加入组播组**（IGMP Join / `IP_ADD_MEMBERSHIP`）、**Report/Query** 软状态、**IGMPv3 SSM**、**IGMP Snooping** 及排障。

<a id="ch09-4"></a>

**一句**：**加入组播组 = 告诉系统/网卡「我要收这个组的流量」** — 底层靠 **IGMP** 跟路由器打招呼。

---

<a id="ch09-4-join-principle"></a>

## 一、加入组播组原理

| 项 | 说明 |
|----|------|
| **组播地址** | **`224.0.0.0` ~ `239.255.255.255`** |
| **你要收某组**（如 `239.1.1.1`） | 见下三步 |

```text
① 应用/系统发 IGMP Join（Report）：「我要 239.1.1.1」
② 路由器记录：该端口有人要这个组
③ 发往 239.1.1.1 的流量 → 只转给加了组的主机
```

### 与广播的区别

| | **广播** | **组播** |
|---|----------|----------|
| **接收** | **强制所有人收**，不管要不要 | **只有主动加入的才收** |
| **过滤** | 网卡/栈都要处理 | 未加组者**网卡底层过滤**，**不占 CPU** |

→ [9.1 广播 vs 组播](9.1-broadcast-multicast-concept.md#ch09-1-compare)

### 地址段回顾

| 段 | 说明 |
|----|------|
| **`224.0.0.0/24`** | 链路本地，**路由器不转发**，仅 LAN — 类似广播但**可 selective join** |
| **`239.0.0.0/8`** | **私有组播**，企业/局域网内，**公网不路由** |

<a id="ch09-4-join-win"></a>

## 二、Windows 命令行加入（临时，测试）

**管理员** cmd：

```cmd
:: 1. 看网卡名
netsh interface ipv4 show interfaces

:: 2. 加入组（网卡名按实际改：以太网 / Ethernet / Wi-Fi）
netsh interface ipv4 add joinmulticastgroup name="以太网" group=239.1.1.1

:: 3. 查看已加入的组
netsh interface ipv4 show joins

:: 4. 退出组
netsh interface ipv4 delete joinmulticastgroup name="以太网" group=239.1.1.1
```

---

<a id="ch09-4-join-linux"></a>

## 三、Linux 命令行加入（临时）

```bash
# 1. 看网卡
ip a    # eth0 / enp0s3 等

# 2. 确保组播开启（默认通常已开）
sudo ip link set eth0 multicast on

# 3. 加入组
sudo ip maddr add 239.1.1.1 dev eth0

# 4. 查看
ip maddr show dev eth0

# 5. 退出组
sudo ip maddr del 239.1.1.1 dev eth0
```

<a id="ch09-4-join-code"></a>

## 四、程序里怎么加（实际工作）

Python / C++ / Java / Go / Rust 本质相同：

1. 创建 **UDP socket**
2. `setsockopt`：**`IP_ADD_MEMBERSHIP`**（指定组播 IP + 网卡）
3. 内核**自动发 IGMP Report** 给路由器

### Python 极简例子

```python
import socket

mc_ip = "239.1.1.1"
mc_port = 1234

s = socket.socket(socket.AF_INET, socket.SOCK_DGRAM)
s.bind(("", mc_port))

# 加入组播组（0.0.0.0 = 默认网卡；生产环境指定本机接口 IP）
mreq = socket.inet_aton(mc_ip) + socket.inet_aton("0.0.0.0")
s.setsockopt(socket.IPPROTO_IP, socket.IP_ADD_MEMBERSHIP, mreq)

# 收包 ...
# 离开：IP_DROP_MEMBERSHIP（同 mreq 结构）
```

| 选项 | 作用 |
|------|------|
| **`IP_ADD_MEMBERSHIP`** | 加入组 → 触发 **IGMP Join** |
| **`IP_DROP_MEMBERSHIP`** | 离开组 |
| **`IP_MULTICAST_IF`** | 指定从哪块网卡发/收组播 |

→ 详：[ch10 UDP 组播](../chapter10-udp-ip-fragment/study.md)

<a id="ch09-4-igmp"></a>

## 五、IGMP (IPv4) / MLD (IPv6) 报文

| 报文 | 方向 | 作用 |
|------|------|------|
| **Report（Join）** | 主机 → 路由器 | **加入**组播组 |
| **Query** | 路由器 → 子网 | 还有谁在看？**刷新软状态** |
| **Leave**（v2+） | 主机 → 路由器 | 快速离组（v2） |

- 路由器维护**组播转发表（软状态）**；超时无 Report → 停止向 LAN 转发该组。

<a id="ch09-4-snooping"></a>

## 七、IGMP Snooping（交换机）

| 项 | 说明 |
|----|------|
| **作用** | 交换机**偷听 IGMP** → 只向**有订阅者**的端口转发组播 |
| **无 Snooping** | 组播可能被当**广播泛洪** → [9.1 §误区](9.1-broadcast-multicast-concept.md#ch09-1-myth) · [9.7 交换机分工](9.7-lan-switch-router-multicast.md#ch09-7-igmp-snooping) |

<a id="ch09-4-troubleshoot"></a>

## 八、实战：「别人收得到我收不到」

| # | 排查 |
|---|------|
| 1 | **未 Join** / 未 `IP_ADD_MEMBERSHIP` |
| 2 | **未指定网卡** Join 组播 |
| 3 | **未响应 Query** → 几分钟后被 Snooping **掐流** |
| 4 | Wi‑Fi/AP **未透传组播** |

定期 **Report** 或由栈自动响应 Query。

<a id="ch09-4-cheat"></a>

## 考点速记

| # | 要点 |
|---|------|
| 1 | **加组** = IGMP **Join/Report**；内核 **`IP_ADD_MEMBERSHIP`** |
| 2 | 路由器靠 Report 建**软状态**；Query 刷新 |
| 3 | **Snooping** = 交换机按 IGMP **精准转发** |
| 4 | 无 Join **不收**；广播**强制全员收** |
| 5 | **`239.x`** 私有；**`224.0.0/24`** 链路本地不跨路由 |

| 易错 | 正确 |
|------|------|
| 绑 UDP 端口就能收组播 | 须 **`IP_ADD_MEMBERSHIP`** 触发 IGMP |
| 加组 = 改 IP 地址 | 加组是**订阅**，不改变主机单播 IP |
| Linux `ip maddr add` 永久生效 | **临时**；程序退出或 del 即离组 |

---

## 疑问与总结

**背：加组=IGMP Join；Win netsh / Linux ip maddr / 程序 IP_ADD_MEMBERSHIP；Snooping 精准转发；没加组不收。**
