# 9.3 组播：MAC 与 IPv4 单播/组播/广播

> 章级精读：[../study.md#ch09-3](../study.md#ch09-3) · IPv4 特殊地址：[ch02 §2.5](../../chapter02-ip-address-architecture/2.5-special-address.md) · PAUSE 二层组播（与 IP 无关）：[3.3 §五](../../chapter03-link-layer/3.3-full-duplex-autoneg.md#ch03-3-pause) · UDP 绑定：[ch10](../../chapter10-udp-ip-fragment/study.md)

## 本节核心目标

分清 **MAC 层** 与 **IPv4 层** 的单播/组播/广播判定规则；理解二者**不是一一绑定**，以及 **IPv4 组播 → MAC 组播** 的标准映射；区分 **IP 组播 MAC** 与 **纯二层控制帧 MAC**（如 PAUSE）。

> 名词：**单播、组播、广播**（不用「主播」）。

---

<a id="ch09-3-mac"></a>

## 一、MAC 地址（48 bit，二层）

### 1）单播 / 组播：只看首字节最低位

MAC 格式：`字节1 : 字节2 : 字节3 : 字节4 : 字节5 : 字节6`

| 规则 | 判定 |
|------|------|
| **第 1 字节最低位（bit 0）= 0** | **MAC 单播**（唯一设备） |
| **第 1 字节最低位 = 1** | **MAC 组播**（一组设备） |

**例子**

- 单播：`00:1a:2b:3c:4d:5e` → 首字节 `00` = `00000000`，末位 **0**
- 组播：`01:80:C2:00:00:01`（PAUSE）→ 首字节 `01` = `00000001`，末位 **1**

### 2）MAC 广播

固定 **`FF:FF:FF:FF:FF:FF`**，视为**特殊组播**，本网段所有端口都会处理。

### 3）MAC 6 字节怎么理解

| 部分 | 位数 | 作用 |
|------|------|------|
| **前 3 字节（OUI）** | 24 bit | 厂商编号，出厂固化 |
| **后 3 字节** | 24 bit | 厂商自定义，全球唯一单播 MAC |

**单播/组播标识**只在**第 1 字节最低 1 bit**，与 OUI、后 3 字节无关。

> **背一句**：MAC 只靠**首字节末位**分单播/组播；广播 = 全 F。

---

<a id="ch09-3-ipv4"></a>

## 二、IPv4 地址（32 bit，三层）

分**网络位 + 主机位**；判定靠**地址段、主机位取值**，与 MAC **完全不同**。

### 1）IPv4 组播（D 类）

**范围**：`224.0.0.0` ~ `239.255.255.255`（**224.0.0.0/4**）

用途：一对多（视频、路由协议、设备发现等）→ [2.5 特殊地址](../../chapter02-ip-address-architecture/2.5-special-address.md)

**核心结论**：**224.0.0.0～239.255.255.255 是 IPv4 组播地址段**；**大部分默认仅在局域网传播**，只有特定范围 + **组播路由（PIM 等）** 配置后才可跨网段/公网。

---

<a id="ch09-3-scope"></a>

### 2）分段划分 & 传播范围

IPv4 组播整体 **`224.0.0.0/4`**，按用途与路由规则分三类：

#### ① 本地链路组播 `224.0.0.0` ~ `224.0.0.255`（`224.0.0.0/24`）

| 项 | 说明 |
|----|------|
| **规则** | **路由器一律不转发** — 严格限制在**当前局域网（二层网段）** |
| **用途** | 邻居发现、路由协议、局域网设备交互 |
| **典型地址** | **`224.0.0.1`** 所有组播主机 · **`224.0.0.2`** 所有组播路由器 · **`224.0.0.5/6`** OSPF |
| **场景** | 同网段设备能收到；**跨路由器直接阻断** |

```text
ping 224.0.0.1 → 同交换机/Wi‑Fi 能收到 → 经路由器到另一网段 → 收不到
```

#### ② 全网组播 `224.0.1.0` ~ `224.0.1.255`

| 项 | 说明 |
|----|------|
| **规则** | **默认允许路由器转发**，可跨网段、跨公网传播 |
| **用途** | 互联网全局服务、公共设备发现 |

#### ③ 机构/私有组播 `224.0.2.0` ~ `239.255.255.255`

| 子段 | 规则 |
|------|------|
| **`224.0.2.0` ~ `238.255.255.255`** | **通用组播** — 须网络设备开启 **PIM 等组播路由** 才能跨网段；家用/普通企业路由**默认不转发**，**仅局域网内生效** |
| **`239.0.0.0` ~ `239.255.255.255`** | **管理/本地组播（admin-scope）** — 类比私网 IP，**禁止公网路由**，仅企业/园区/局域网内部 |

### 3）单播 / 广播 / 组播 传播对比

| 类型 | 跨路由行为（默认） |
|------|-------------------|
| **单播** | 一对一，**正常跨路由**全网转发 |
| **广播** | `255.255.255.255` 等 — 路由器**不转发**，限局域网 → [9.2](9.2-ipv4-broadcast-address.md) |
| **组播** | **`224.0.0.0/24` 天生不跨路由**；其余段**依赖 PIM 等配置** |

### 4）日常场景总结

| # | 要点 |
|---|------|
| 1 | 家用/普通局域网：**未配组播路由** → **组播基本只在当前 LAN 内** |
| 2 | 运营商/大型专网**手动开启组播路由**后，部分地址段才可跨网段 |
| 3 | **`239.x`** 仅组织内；**`224.0.0.x`** 仅链路本地 |

→ IGMP/PIM：[9.4](9.4-igmp-mld-snooping.md) · [study §9.4](../study.md#ch09-4)

---

### 5）IPv4 广播

**核心**：**主机位全部置 1**

| 类型 | 规则 | 例 |
|------|------|-----|
| **子网广播**（常用） | 本网段主机位全 1 | `192.168.1.0/24` → **`192.168.1.255`** |
| **有限广播** | 固定 | **`255.255.255.255`**（通常不路由，限本网） |

### 6）IPv4 单播

除组播、广播、网络号、保留地址外，常规主机地址；**主机位不能全 0 或全 1**（子网内）。

<a id="ch09-3-mapping"></a>

## 三、MAC 组播 与 IPv4 组播：一一对应吗？

### 结论

**不是自由一一绑定**，而是**三层包封装进二层帧**的承载关系：

1. 上层发 **IPv4 组播包** → 下层须封装为 **MAC 组播帧** 才能在以太网上传；
2. **一个 IPv4 组播地址**按 **IANA 规则**映射到 **固定前缀的 MAC 组播**，不是任意配对。

### 标准映射（必背）

| 项 | 值 |
|----|-----|
| IPv4 组播段 | `224.0.0.0/4` |
| 以太网 MAC 组播前缀 | **`01:00:5E`**（IANA） |
| 映射 | 取 IPv4 的**低 23 bit**，填入 MAC 后 23 bit |

**例：`224.0.0.1`**

```text
IPv4:  11100000.00000000.00000000.00000001
       └─ D类 ─┘
取低 23 bit: 0000000 00000000 00000001
MAC:   01:00:5E : 00 : 00 : 01  →  01:00:5E:00:00:01
```

**碰撞**：32 个不同 IPv4 组播 IP 可能映射到**同一 MAC** → 网卡/驱动可能收到未订阅组，靠 **IGMP + 套接字 Join** 在三层丢弃 → 见下文「三层过滤」。  
→ 交换机转发全流程：[9.7 §IP→MAC 流程](9.7-lan-switch-router-multicast.md#ch09-7-ip-mac)

### 与 PAUSE 等二层组播的区别

| MAC 组播地址 | 归属 |
|--------------|------|
| **`01:00:5E:xx:xx:xx`** | **IPv4 组播 IP 映射**（承载三层组播包） |
| **`01:80:C2:00:00:01`** | **802.3x PAUSE**，**纯二层控制**，**与 IP 组播无关** |
| **`FF:FF:FF:FF:FF:FF`** | **广播** |

<a id="ch09-3-compare"></a>

## 四、判定规则对比表

| 维度 | MAC（二层 48 bit） | IPv4（三层 32 bit） |
|------|-------------------|---------------------|
| **单播** | 首字节**最低位 = 0** | 常规地址；主机位不全 0 / 不全 1 |
| **组播** | 首字节**最低位 = 1** | **`224.0.0.0` ~ `239.255.255.255`** |
| **广播** | 固定 **`FF:FF:FF:FF:FF:FF`** | 子网**主机位全 1** / **`255.255.255.255`** |
| **区分方式** | **单个比特位** | **整段范围 + 主机位** |
| **关系** | 硬件按 MAC 转发/过滤 | 路由、IGMP、套接字按 IP 处理 |

---

## 五、三层过滤（组播收包）

```text
1. 网卡硬件过滤器（按 MAC 粗筛，不完美）
2. 驱动
3. IP / 套接字 — JoinGroup 后丢弃未订阅的组播包
```

| 坑 | 说明 |
|----|------|
| **32→1 MAC 碰撞** | 收到未订阅 IP 的组播帧 |
| **多网卡** | `JoinMulticast` 须指定 **Interface** |
| **未 Join** | 收不到；Join 错网卡 → IGMP Report 发错口 |

→ Go/Rust：`JoinMulticast` / `join_multicast_v4`

## 六、考点：组播地址段与传播

| # | 要点 |
|---|------|
| 1 | 组播段：**224.0.0.0/4**（224～239） |
| 2 | **`224.0.0.0/24`**：**不跨路由**，OSPF/`224.0.0.1` 等 |
| 3 | **`239.x`**：**私有组播**，不进公网 |
| 4 | 其余跨网段需 **PIM**；家用默认**仅 LAN** |
| 5 | vs 单播可全网 vs 广播不路由 vs 组播看段 |

| 易错 | 正确 |
|------|------|
| 所有组播都能跨公网 | **大部分默认仅局域网** |
| 224.0.0.1 能 ping 到别的网段 | **路由器不转发** `/24` 链路本地 |
| 239.x 与 224.0.0.x 一样 | **239=组织内私有**；**224.0.0.x=链路本地** |

## 八、一句话总结

1. MAC 靠**首字节最低位**分单播/组播；广播 = **全 F**。  
2. IPv4 靠 **224/4** 分组播，靠**主机位全 1** 分子网广播。  
3. 规则**独立**；IP 组播包**封装**进 MAC 组播帧传输，按 **`01:00:5E` + 低 23 bit** 映射，**非任意绑定**。  
4. **PAUSE** 等 **`01:80:C2:…`** 是**纯二层控制 MAC**，与 IP 组播无关。

## 疑问与总结

- **ARP 请求**用 **广播 MAC** + 目标 IP 单播/未知，不是组播映射。  
- **子网广播 IP** 帧目的 MAC 常为 **`FF:FF:FF:FF:FF:FF`**。  
- 考试：先判 **IP 是组播还是广播**，再写 **对应 MAC**；PAUSE 只背 **`01:80:C2:00:00:01`**，不要和 `01:00:5E` 混。
