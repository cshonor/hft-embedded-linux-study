导读

本节讲什么： 让驱动去跟板子外面的芯片说话——点灯、读传感器、驱动 SPI 屏。 对应动手： P5 · C2（I2C 或 SPI 从设备驱动，compatible 匹配、reg/interrupts 来自 DT）

三条路的分工

总线 速率量级 典型用途 内核框架
GPIO 单比特 点灯、按键、片选、复位线 gpiod（gpiod_get / gpiod_set_value）
I2C 100k–1M bps 传感器（温湿度、IMU）、EEPROM、RTC i2c_driver / i2c_client
SPI 几十 Mbps 高速 ADC、显示屏、Flash spi_driver / spi_device

GPIO（现代 gpiod 接口）

struct gpio_desc *led;

led = devm_gpiod_get(&pdev->dev, "led", GPIOD_OUT_LOW);
gpiod_set_value(led, 1);

DTS 侧：

mydev {
    compatible = "wzp,my-device";
    led-gpios = <&gpio 17 GPIO_ACTIVE_HIGH>;   /* gpiod_get(..., "led") 找的就是 led-gpios */
};

别再用老的 gpio_request + 整数编号 API，也别用 /sys/class/gpio（已废弃）。

I2C 从设备

static int my_probe(struct i2c_client *client,
                    const struct i2c_device_id *id)
{
    /* client->addr 就是 DTS 里的 reg */
    u8 val;
    i2c_smbus_read_byte_data(client, 0x00);
    /* 多寄存器场景用 regmap（Madieu Ch9），别手撕 i2c_transfer */
    return 0;
}

static const struct of_device_id my_of_match[] = {
    { .compatible = "wzp,my-sensor" }, { }
};

DTS 侧挂在控制器下：

&i2c1 {
    sensor@48 {
        compatible = "wzp,my-sensor";
        reg = <0x48>;          /* I2C 地址 */
    };
};

HFT / 嵌入式关联

  • 传感器采集是"退路"也是"入口"：工业网关 / 飞控要接 SPI/I2C 传感器，这是嵌入式最稳的就业面。
  • 速率对比值得记：I2C 慢但省引脚，SPI 快但占 4 根线。选型本质是引脚预算 vs 带宽预算的权衡，和 HFT 里"网卡带宽 vs PCIe 通道数"是同一类问题。
  • 高频采样（IMU）会直接进 06-dma-mmap 和 10-motion-control 的地盘。

4.1

GPIO 通俗讲解（Linux · 设备树 · 驱动）

基础外设 · 对齐 Primer Ch8 FAQ · Pi Labs / Project #1
相关：8.0 只配 DTS · 8.4 主线复用 · 8.3 中断

一、全称

GPIO = General Purpose Input/Output
SoC 引出的可编程通用引脚，嵌入式最基础、最简单的一类「外设」。

二、两大模式 + 常用配置

模式 做什么 例子
输出 软件拉高/拉低 LED、继电器、给别的芯片拉复位
输入 读外部电平 按键、简单传感器高低电平

额外常见：

  • 上拉 / 下拉：默认电平，减少悬空抖动
  • 边沿/电平中断：变化时 IRQ（按键用中断，不必死轮询）— 见 8.3

三、硬件层

  • 一块 SoC（树莓派、i.MX…）常有几十～上百 GPIO
  • 常分组：如 gpio1 组里的第 5 脚 → 口语 GPIO1_5
  • 每脚可独立配方向、上下拉、中断

Pi5：应用核 + RP1 管大量用户 GPIO — 查官方 GPIO/RP1，勿死背 Pi4 寄存器课。Pi Labs §0

四、Linux：通用驱动 + 设备树（多数不用自写驱动）

内核有现成框架（如 gpio-keys、leds-gpio、gpiolib）。
板级差在哪根脚 → 改 DTS，逻辑在主线驱动里（8.4）。

示意（按键）：

gpio_keys {
    compatible = "gpio-keys";
    key1 {
        gpios = <&gpio1 5 GPIO_ACTIVE_LOW>;
        label = "user_btn";
    };
};

含义：gpio1 第 5 脚，低有效；gpio-keys 匹配后 probe，常自动走中断路径。

片内 GPIO 控制器节点一般在原厂 dtsi 里已有；你加的是消费者节点（keys/leds/…）。

五、用户态怎么碰（仍经内核）

常见路径：

  • sysfs（老）：/sys/class/gpio 导出后读写
  • 字符设备 / libgpiod（更推荐的现代路）：/dev/gpiochipN

APP 读写的是内核接口；真正改引脚电平的是内核 GPIO 子系统，不是用户态直写 MMIO（8.2）。

六、和 UART / I2C / SPI 的差别

GPIO UART/I2C/SPI
协议 无固定报文协议，软件自由定高低 有标准时序/帧格式
复杂度 最低 控制器 + 协议驱动更重

GPIO = 最简单的「一根线」；总线 = 带协议的专用口。

七、开发例子

  1. 板载 LED → 输出（或 leds-gpio）
  2. 功能键 → 输入 + 中断（gpio-keys）
  3. 外设复位脚 → 输出脉冲
  4. 插拔检测 → 输入（可中断）

八、一句话

GPIO = 可自由编程的芯片引脚：能出电平、能读电平、能中断。
Linux 上多数场景：主线 GPIO 驱动 + DTS 配脚，应用走 sysfs/libgpiod，不必从零写驱动。

与 8.6 合读：板边排针是物理引出；DTS 声明你用了哪一根。

Project #1 验收里的「GPIO 用户态可观测」对齐本页 + 官方 RP1/GPIO 文档。

4.2

GPIO 排针 ↔ 设备树：物理接线与软件声明

承接 8.5 GPIO 基础 · 8.0 加外设
板级：Pi Labs（Pi 40-pin header）

一、板子上那两排针是什么？

行业常称 GPIO Header / 扩展排针：把 SoC（及伴随 I/O 芯片）里的信号 引到板边，方便杜邦线外接 LED、按键、传感器等。

针上常见内容 说明
多数：GPIO 可编程输入/输出/中断
电源 / GND 如 3.3V、5V、地 — 不是 GPIO
复用脚 默认可当 UART/I2C/SPI 等；也可再配成普通 GPIO（视 SoC/引脚复用）

例：树莓派 40-pin 双排 — GPIO + 电源/地 + 串口/I2C 等复用。
做成双排：省 PCB 面积、高密度引出几十根脚。

结论： 不是每根针都是 GPIO；但多数简单外设确实用排针上的 GPIO 针 接到板子。

二、硬件接线 ↔ 设备树（缺一不可）

层 你做什么
硬件 杜邦线：排针某脚 ↔ LED/按键/…，电路连通
软件（DTS） 声明用了 哪一组、第几号 GPIO，通用驱动才能认、才能控

例：排针对应 GPIO1 第 5 脚接按键（对 GND，低有效）：

user_key {
    compatible = "gpio-keys";
    /* … 子节点里： */
    gpios = <&gpio1 5 GPIO_ACTIVE_LOW>;
};
  • 排针 = 物理引线（把芯片脚露出来）
  • 设备树 = 软件配置（告诉内核「你用了哪一根」）

只接线不改树 → 内核不知道；只改树不接线 → 电气没通。

三、三类针脚，别混

  1. GPIO：可配方向/上下拉/中断；DTS 里作 gpios = <&gpioX N …>
  2. 电源 / GND：只供电；不能当 GPIO 写进消费者节点乱控
  3. 复用总线脚：优先作 I2C/SPI/UART；改成 GPIO 要查复用/overlay，避免和总线冲突

查脚图：以该板官方 pinout 为准（Pi5 查官网 + RP1 说明，勿混用别板编号）。

四、外接 LED 最短闭环

  1. 硬件： LED（经电阻）接到某 GPIO 针 + 合适电源/地（极性与电路按原理图，勿短路 5V 进 3.3V GPIO）
  2. 软件： DTS 增加 leds / gpio-leds 类节点，指定同一 gpioX N
  3. 内核 leds-gpio（等）匹配
  4. 用户态：/sys/class/leds/… 或 libgpiod 控亮灭

→ 典型「只改 DTS、不写驱动」场景（8.4）。

五、回答你的两点

  1. 外接简单件（键、灯）：经排针 GPIO 物理连接，并在 DTS 声明同一脚
  2. 双排金属针 = 扩展插座，引出 GPIO / 电源 / 总线；针 ≠ 全是 GPIO

与 8.5 合读：先懂 GPIO 是什么，再懂「板边那排针」只是把它接到你手里。
