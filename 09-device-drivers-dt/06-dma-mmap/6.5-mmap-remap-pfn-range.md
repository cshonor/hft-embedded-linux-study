# 6.5 · mmap：让用户态直接看到内核内存

> **本节讲什么：** `mmap()` 怎么把内核/设备内存映射到用户态地址空间、`remap_pfn_range` 到底做了什么、以及三种 mmap API 该怎么选。**重点是一个容易错的点：`dma_mmap_*` 会替你处理缓存属性，手写 `remap_pfn_range` 不会——漏了就数据错乱。**

---

## 零拷贝的价值：先算一笔账

高频采集场景，用户态要拿到 DMA 缓冲里的数据，两条路：

```
① read() 路径：  用户 buf ←──copy── 内核 buf ←──DMA── 设备
                       ↑ 每次都要拷贝
② mmap  路径：  用户态虚拟地址 ──页表── 同一块物理页 ──DMA── 设备
                       ↑ 零拷贝，设备直接写用户能读的内存
```

采样率 1 MHz × 2 字节 × 8 通道 ≈ 16 MB/s，`read()` 多一次拷贝在 MHz 级采样下**不只是 CPU 占用，还引入延迟抖动**。这就是 [HFT 里 mmap 做零拷贝](../../06.6-systems-performance/) 的同一套动机。

---

## 调用链

```
用户态 mmap(NULL, len, PROT_READ|PROT_WRITE, MAP_SHARED, fd, offset)
        │  sys_mmap → ksys_mmap_pgoff
        ▼
do_mmap()   ← 分配一段用户虚拟地址区间，建 vm_area_struct（VMA）
        │
        ▼
file->f_op->mmap(file, vma)     ← ★ 驱动实现的回调
        │
        ▼
remap_pfn_range() / dma_mmap_*() / 只填 vma->vm_ops->fault
        │
        ▼
建立页表项：用户虚拟地址 → 物理页帧
```

**驱动要做的唯一一件事：把 `vma` 这段虚拟地址范围填上页表。**

VMA 提供的信息：

| 字段 | 含义 |
|------|------|
| `vma->vm_start` / `vm_end` | 用户虚拟地址区间（已按页对齐） |
| `vma->vm_pgoff` | 用户传的 `offset` 右移 PAGE_SHIFT（**常用作"映射第几块"的索引**） |
| `vma->vm_page_prot` | 页保护属性（**能不能改缓存策略就看这里**） |
| `vma_pages(vma)` | 区间页数 |

---

## `remap_pfn_range`：一次建完所有页表

v6.6 `mm/memory.c:2496`：

```c
int remap_pfn_range(struct vm_area_struct *vma, unsigned long addr,
                    unsigned long pfn, unsigned long size, pgprot_t prot)
{
    int err;

    err = track_pfn_remap(vma, &prot, pfn, addr, PAGE_ALIGN(size));
    if (err)
        return -EINVAL;

    err = remap_pfn_range_notrack(vma, addr, pfn, size, prot);
    ...
}
```

参数含义：

```
remap_pfn_range(vma, 起始虚拟地址, 起始物理页帧号, 长度, 页保护)

物理地址 → pfn：  phys_addr >> PAGE_SHIFT
                  或 page_to_pfn(page)   （有 struct page 时）
```

典型用法：

```c
static int my_mmap(struct file *filp, struct vm_area_struct *vma)
{
    struct my_dev *m = filp->private_data;
    unsigned long size = vma->vm_end - vma->vm_start;

    if (size > m->buf_size)
        return -EINVAL;

    /* 关掉这段映射的缓存（MMIO / DMA 场景必需，见 6.6） */
    vma->vm_page_prot = pgprot_noncached(vma->vm_page_prot);

    return remap_pfn_range(vma, vma->vm_start,
                           m->phys_addr >> PAGE_SHIFT,
                           size, vma->vm_page_prot);
}

static const struct file_operations my_fops = {
    .owner = THIS_MODULE,
    .mmap  = my_mmap,
    ...
};
```

**注意那行 `pgprot_noncached`** —— 手写路径必须自己设，见下节。

## ★ 三种 API 怎么选（这是本节的核心表）

| 场景 | 用哪个 | 说明 |
|------|--------|------|
| **MMIO 寄存器 / 保留内存 / CMA**（无 struct page） | `remap_pfn_range` | 物理地址已知且连续，**要自己设 pgprot** |
| **`dma_alloc_coherent` 分配的缓冲** | **`dma_mmap_coherent`** | **自动设对缓存属性** |
| **`dma_alloc_noncontiguous` / scatter-gather** | `dma_mmap_noncontiguous` | 内部走 `vm_map_pages`（离散页数组） |
| **普通内核内存（有 struct page）** | `vm_insert_page` / `vm_map_pages` | 逐页插入，别用 `remap_pfn_range` 强来 |

### 为什么 `dma_mmap_*` 更正确

看 `dma_mmap_attrs` 的下游（v6.6 `kernel/dma/mapping.c:417`）：

```c
pgprot_t dma_pgprot(struct device *dev, pgprot_t prot, unsigned long attrs)
{
    if (dev_is_dma_coherent(dev))
        return prot;                        /* 硬件保证一致 → 保持缓存 */
#ifdef CONFIG_ARCH_HAS_DMA_WRITE_COMBINE
    if (attrs & DMA_ATTR_WRITE_COMBINE)
        return pgprot_writecombine(prot);
#endif
    return pgprot_dmacoherent(prot);        /* ★ 非 coherent 设备：关缓存 */
}
```

**`dma_mmap_*` 会自动把用户态映射的缓存属性设成与 DMA 语义匹配的值**（通常是 noncached 或 writecombine）。

而手写 `remap_pfn_range` 时传的 `vma->vm_page_prot` **默认是 cached**：

```
dma_alloc_coherent 分配      → 内核侧映射已经是 noncached
手写 mmap 用默认 prot        → 用户侧映射是 cached  ★ 两侧属性不一致
结果                          → 用户读到的是缓存里的旧数据，或写出去没到内存
```

**症状是"数据偶尔不对"，而不是"必崩"** —— 这种 intermittent bug 极难查。所以：

> **DMA 缓冲做 mmap，优先用 `dma_mmap_coherent` / `dma_mmap_noncontiguous`。**
> 只有映射 MMIO 寄存器或保留内存时才手写 `remap_pfn_range`，且**必须显式设 pgprot**。

`dma_mmap_pages` 内部其实也是 `remap_pfn_range`（`mapping.c:609`），但它传的是**已被 `dma_pgprot` 修正过的** `vma->vm_page_prot`——差别就在这一层。

---

## 生命周期：一个容易漏的约束

`dma_mmap_attrs` 的内核注释写得很明确：

> *"The coherent DMA buffer must not be freed by the driver until the user space mapping has been released."*

**驱动不能在用户映射还活着的时候释放缓冲。** 实践做法：

| 做法 | 说明 |
|------|------|
| **最简单** | 用 `devm_*` / `dma_alloc_coherent` 在 probe 里分配，remove 时释放——模块卸载本身会解除映射 |
| **需要动态时** | 在 `vm_ops->close` 里计数，配合 refcount |
| **别做** | 在 `release()` 里无条件 free，而用户还 mmap 着 |

## 完整骨架（MMIO 场景）

```c
static int my_mmap(struct file *filp, struct vm_area_struct *vma)
{
    struct my_dev *m = filp->private_data;
    unsigned long off = vma->vm_pgoff << PAGE_SHIFT;
    unsigned long size = vma->vm_end - vma->vm_start;

    /* ① 边界检查：越界必须拒绝，否则用户能读到别的物理内存 */
    if (off + size > m->region_size)
        return -EINVAL;

    /* ② 缓存属性：MMIO 必须 noncached（见 6.6） */
    vma->vm_page_prot = pgprot_noncached(vma->vm_page_prot);

    /* ③ 建页表 */
    return remap_pfn_range(vma, vma->vm_start,
                           (m->phys_addr + off) >> PAGE_SHIFT,
                           size, vma->vm_page_prot);
}
```

**第 ① 步的边界检查不能省**——`vm_pgoff` 是用户可控的，不做检查等于把整个物理地址空间暴露给用户态。这是**提权漏洞**，不是小问题。

## HFT / 嵌入式关联

- **mmap 零拷贝是 HFT 与嵌入式采集的共同语言**：DPDK 用 hugepage + mmap 旁路内核；网卡驱动的 ring buffer 也常 mmap 给用户态。见 [13 DPDK](../../13-dpdk/)。
- **`vm_pgoff` 当索引用**是内核惯例：同一个设备有多块缓冲时，用户 `mmap(fd, N * PAGE_SIZE)` 第 N 块。但**必须校验上界**。
- **属性不一致的 bug 值得警惕**：内核态和用户态看到同一块物理内存、但缓存策略不同，是"两边数据对不上"类问题的经典根因。这类 bug 不会崩溃，只会**偶尔算错**——在控制系统里比崩溃更危险。

<details>
<summary>参考答案</summary>

1. **给 `vma` 描述的这段用户虚拟地址区间建立页表**，让它指向目标物理内存。内核已经分配好了 VMA（虚拟区间），驱动只需填页表——通过 `remap_pfn_range` 一次性建、或 `dma_mmap_*`、或只提供 `vm_ops->fault` 惰性建。

2. `pfn = phys_addr >> PAGE_SHIFT`；有 `struct page` 时用 `page_to_pfn(page)`。注意 `remap_pfn_range` 要的是**页帧号**不是字节地址，传错表现为映射到了完全无关的物理页（能"跑"但数据全错）。

3. 因为 `dma_mmap_*` 内部会通过 `dma_pgprot()` **自动把用户态映射的缓存属性设成与 DMA 语义一致**（通常是 noncached/writecombine）。手写 `remap_pfn_range` 若不显式设 `pgprot`，用的 `vma->vm_page_prot` 默认是 **cached**，与内核侧 `dma_alloc_coherent` 的 noncached 映射**属性不一致**，症状是用户读到缓存里的旧数据——表现为"偶尔不对"，极难定位。

4. `dev_is_dma_coherent(dev)` 为真时（设备与 CPU 间硬件保证缓存一致性）。否则根据 `DMA_ATTR_WRITE_COMBINE` 返回 writecombine 或 `pgprot_dmacoherent(prot)`。

5. 落在 **`vma->vm_pgoff`**（= 用户 `offset >> PAGE_SHIFT`）。必须检查上界，因为它是**用户完全可控**的，不做越界检查等于允许用户映射任意物理内存（包括其它进程/内核的内存），是提权漏洞。

6. **不能。** `dma_mmap_attrs` 的注释明确要求 coherent DMA buffer 在用户映射释放前不得被驱动释放。实践上最简单是用 `devm_*`/probe 分配、remove 释放（模块卸载会解除映射）；需要动态生命周期则在 `vm_ops->close` 里做引用计数。
