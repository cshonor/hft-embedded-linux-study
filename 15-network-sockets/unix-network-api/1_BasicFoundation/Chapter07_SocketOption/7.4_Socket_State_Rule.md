# 7.4 套接字状态

> [7.5 通用选项](../7.5_Common_Socket_Option.md) · accept 继承：Ch 4.6

---

## 核心主旨

部分选项行为依赖套接字**当前状态**；TCP **监听套接字 → 已连接套接字** 的**选项继承**极易踩坑。

---

## 状态继承原则（极其关键）

`accept` 返回的 **connfd** 从 **listenfd** **继承**诸多选项，例如：

- `SO_KEEPALIVE`  
- `SO_RCVBUF` / `SO_SNDBUF`  
- `TCP_MAXSEG`  
- 等  

---

## 设置时机陷阱

| 目标 | 正确时机 |
|------|----------|
| 影响**所有**将来 accept 的连接 | 在 **`listen` 之前** 对 **listenfd** `setsockopt` |
| 只改某一个 connfd | 对该 **connfd** 单独设置（accept 之后） |

### TCP 缓冲区与窗口规模

- **`SO_RCVBUF`** 与 **Window Scale** 协商有关  
- 协商发生在 **SYN**（三次握手）  
- 故：**服务器**在 `listen` 前设；**客户**在 **`connect` 前**设 `SO_RCVBUF`

---

## 易错细节与重点结论

| 错误 | 后果 |
|------|------|
| accept 后才给 listenfd 设 SO_KEEPALIVE | **已建立连接不继承**新值 |
| 客户 connect 后才设 SO_RCVBUF | 窗口协商可能已错过最佳时机 |

**考试一句**：要影响 accept 出来的连接 → **先设监听套接字，再 listen**。
