# 1.2 / 1.5 附录 · 为何固定端口 13（Daytime / RFC 865）

> 客户端 [1.2](./1.2_SimpleTimeClient.md) · 服务端 [1.5](./1.5_SimpleTimeServer.md) · 标准服务表 [Ch 2.12](../Chapter02_TCP_UDP_SCTP/2.12_StandardInternetService.md)

<a id="ch1-daytime-port"></a>

## 结论

**没错：13 是 Daytime 的官方标准端口，TCP（及 UDP）均为 13。**

| 依据 | 说明 |
|------|------|
| **RFC 865** | 定义 **Daytime** 服务 → **TCP/UDP 端口 13** |
| 行为 | 客户端连上后，服务端返回**人类可读的日期+时间字符串**，发完常关连接 |
| 与 UNP 1.2/1.5 | 正是书上「时间获取」示例 |

```text
客户端：connect  目标 IP : 13
服务端：bind     0.0.0.0 : 13   （INADDR_ANY + htons(13)）
```

两端必须**同一端口**；改一端不改另一端会连不上。

## UNP 入门常用标准端口（对照）

| 端口 | 服务 | 作用 |
|------|------|------|
| **13** | **Daytime** | 返回时间字符串（**本章**） |
| 7 | Echo | 回显收到的数据 |
| 19 | Chargen | 持续发送字符流（测吞吐） |
| 37 | Time | 自 1900 起的秒数（二进制，非本章） |

## 关键细节

### 1. 知名端口 / 特权端口（&lt; 1024）

| 事实 | 影响 |
|------|------|
| **13 &lt; 1024** | Linux 上**普通用户**默认 **不能 `bind(13)`**（需 **root** 或 `CAP_NET_BIND_SERVICE`） |
| 书上示例 | 常假设有权限，或 root 跑服务端 |

### 2. 改成非标准端口（如 8888、10013）

| 项 | 说明 |
|----|------|
| 能否跑通 | **能** — 服务端 `bind` 某端口，客户端 `connect` **同一端口** 即可 |
| 协议含义 | **不再是** IANA 标准 Daytime 端口，只是你自己的 TCP 时间服务 |
| 改法 | C：`htons(13)` → `htons(10013)`；Rust：`"IP:13"` → `"IP:10013"` **两边一起改** |

### 3. 现代 Linux 与系统自带 Daytime

多数发行版**默认不启**系统 `daytime`（13）服务（安全/无用）。  
因此 **1.5 自写服务端监听 13** 才能和 **1.2 客户端** 联调；与系统服务冲突时再换端口或停系统服务。

## 非 root 本地测试：改用 10013（可选）

**仓库默认保持 13**，与 UNP / RFC 一致。无 root 时可**自行改端口**：

| 位置 | 修改 |
|------|------|
| C 客户端 `daytimetcpcli.c` | `htons(13)` → `htons(10013)`；或 `getaddrinfo` 服务名 `"10013"` |
| C 服务端 `daytimesrv.c` | `htons(13)` → `htons(10013)` |
| Rust 客户端 | `format!("{host}:13")` → `:10013` |
| Rust 服务端 | `bind("0.0.0.0:13")` → `0.0.0.0:10013` |

```bash
# 示例（改完后）
./daytimesrv          # 监听 10013，普通用户可 bind
./daytimetcpcli 127.0.0.1   # 客户端也要连 10013（需同步改代码或传参）
```

> 若要做「命令行指定端口」可留到 Ch 11 `getservbyname` / 自练拓展；1.2 原书写死 13 是为对齐标准服务。

## 速记

**RFC865 → 13/TCP → 人读时间串；客户端连 IP:13，服务端 bind :13；&lt;1024 要权限；系统常无 daytime，自写 1.5 测。**
