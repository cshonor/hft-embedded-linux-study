## ① trap：信号与退出钩子

```bash
trap '命令' SIGNAL...     # 收到信号时执行命令
```

**本仓脚本在用的三个**：

| 钩子 | 触发时机 | 实战用途 |
|---|---|---|
| `trap cleanup EXIT` | 无论怎么退出（正常/错误/Ctrl-C 后 exit） | **有副作用脚本必备**——netem-lab 恢复网卡、mktemp 目录清理 |
| `trap '...' INT` | Ctrl-C（SIGINT） | 自定义中断消息 + `exit 130`（128+2，标准退出码） |
| `trap '...' ERR` | 任何命令返回非零 | 错误定位打印——**但见下面的坑** |

**⚠ ERR trap 的坑（实测）**：ERR trap 只是钩子，**不会中断脚本**：

```bash
$ bash -c 'trap "echo ERR于行$LINENO" ERR; trap "echo EXIT码=$?" EXIT; false; echo 不会到这'
ERR于行1
不会到这        ← false 触发 ERR 后脚本照样往下跑！
EXIT码=0
```

要让"失败即退出"还是得 `set -e`（ERR trap 负责在 -e 退出前打印现场，
所以 1.1 ① 的写法是 `set -e` + `trap ... ERR` **组合**，单用 ERR 不管事）。
另外 ERR 钩子默认不进函数/子 shell，需要 `set -E`（errtrace）。

**INT trap 里要记得 exit**：trap 住 Ctrl-C 执行完清理后不显式 `exit 130`，
信号就被"吞"了，外层脚本以为你正常跑完。

## ② exec 的两种用法（完全不同！）

**用法一：替换进程**（不 fork）——容器 entrypoint / 包装脚本收尾：

```bash
exec "$@"        # 当前 shell 被替换成目标命令，PID 不变，
                 # 信号（docker stop 的 SIGTERM）直达真进程
```

**用法二：fd 重定向**（不带命令的 exec）——日志分身术（实测）：

```bash
exec 3>&1              # fd3 = 终端的副本（存档）
exec 1>/tmp/ex.log     # stdout 改道进文件
echo 进文件             # → 文件
echo 回终端 >&3         # → 终端（经 fd3）
exec 1>&3 3>&-         # 恢复 stdout，关闭 fd3
```

整个脚本输出同时落盘+上屏的另一种写法（更常用）：

```bash
exec > >(tee build.log) 2>&1     # 进程替换 + tee，一行解决
```

**注意顺序**：`cmd > out 2>&1` 正确；`cmd 2>&1 > out` 里 stderr 仍指向旧终端
（重定向从左到右生效，`2>&1` 复制的是"当时的" stdout）——1.1 ⑨ 节同款表格。

## ③ eval：把字符串当命令再解析一遍（最后一招）

```bash
cmd='echo $((2+3))'; eval $cmd              → 5     # 变量里的表达式被执行
pipe='| wc -l'; eval "printf 'a\nb\n' $pipe" → 2     # 动态拼管道——eval 的主战场
```

**为什么需要它**：管道符、重定向、引号是**解析阶段**处理的，变量里的 `|` 只是字符——
`printf 'a\nb\n' $pipe` 会把 `|` 当字面参数传给 printf。eval 把拼好的字符串**重新走一遍
解析流水线**，`|` 才变回管道。

**纪律**（eval 是注入温床）：

- 拼进去的片段**必须是自己构造的**，任何用户输入进 eval = 命令注入
- 能用数组就不用 eval：`cmd=(sudo perf stat -a); "${cmd[@]}"`（1.1 ⑧）覆盖了
  "动态命令"九成的场景，eval 只在需要**动态语法结构**（管道/重定向/引号）时才必要

## ④ getopts：短选项解析（轻量够用）

（1.1 ⑦ 有完整骨架，这里补三个实测细节）

```bash
while getopts ":i:o:v" opt; do ... done
#            ↑        ↑
#      开头冒号=自己处理错误   字母后冒号=该选项带参数
```

- 开头的 `:`：缺参数时 opt 得 `:`、`$OPTARG` 是选项字母；未知选项得 `?`——
  自己报中文错误，不加则 getopts 打英文默认错误
- `OPTIND`：处理完 `shift $((OPTIND-1))`，剩下的位置参数继续用 `"$@"`
- **getopts 只认短选项**（`-i`）；要 `--input` 长选项，手写 case 循环或上 Python——
  别为了长选项引入 `getopt(1)` 外部命令（GNU/BSD 行为分裂，比手写还坑）

## ⑤ `:` 与 `.` 两个最朴素的内建

```bash
: "${CONFIG:?必填}"      # : 是空命令，借它触发参数展开做检查（1.5 ④）
. ./lib.sh              # = source，dash 里只有这个写法（坑点 #14）
```
