# 1.4 shell 环境与启动文件

[← 模块首页](../README.md)

> 对应参考书（Kochan & Wood《Shell Programming in Unix, Linux and OS X》4/e）**Ch3 + Ch11**。
> 本篇回答三个实际问题：① 我的脚本跑起来的时候，环境（PATH、变量、alias、函数）从哪来？
> ② 为什么"终端里好使，cron/CI 里就找不到命令"？③ 改动该写进 `.bashrc` 还是 `.profile`？
> 全部结论已在**本机 Ubuntu 24.04 / bash 5.2.21 实测**（2026-10-06）。

---

## ① shell 的四种启动形态（决定加载什么）

| | 交互（有终端） | 非交互（跑脚本） |
|---|---|---|
| **登录**（`bash -l`、tty 登录、ssh 登录） | ① 读 `/etc/profile` → `~/.bash_profile` → `~/.bash_login` → `~/.profile`（取第一个存在的） | 同左 |
| **非登录**（终端里再敲 `bash`、tmux 新窗格） | ② 只读 `~/.bashrc` | ③ **什么都不读**——除非 `$BASH_ENV` 指向一个文件 |

**本机实测验证**：

```bash
# 形态③：非交互非登录——.bashrc 根本没被读，PATH 是编译默认值
$ env -i HOME=$HOME bash -c 'echo $PATH'
/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin

# 形态③的例外：BASH_ENV 指向的文件会被 source（export 后才能影响子脚本）
$ echo 'Z=from_env' > /tmp/benv.sh
$ BASH_ENV=/tmp/benv.sh bash -c 'echo $Z'
from_env
```

**Ubuntu 的实际布局**（本机实证）：

- 无 `~/.bash_profile`、无 `~/.bash_login`，只有 `~/.profile` —— 登录走第 ① 链的最后一站
- `~/.profile` 末尾有段标准样板：`if [ -f "$HOME/.bashrc" ]; then . "$HOME/.bashrc"; fi`
  ——**登录 shell 也会间接读 .bashrc**，所以日常"改哪里都生效"的错觉来自这里
- `~/.bashrc`（本机 97 行）开头有 `case $- in *i*) ;; *) return;; esac`——
  **非交互 shell 读了也会立即返回**，这是发行版给 .bashrc 上的保险

**改动写哪里**（决策规则）：

| 改什么 | 写哪里 | 为什么 |
|---|---|---|
| alias、交互专属函数、`shopt`、PS1 提示符 | `~/.bashrc` | 只对交互 shell 有意义 |
| PATH 增补、环境变量（`export GOPATH=...`） | `~/.profile` | 登录一次设定，整个会话（含图形会话）继承 |
| 脚本需要的变量 | **不写启动文件**——脚本内自设或 `VAR=x script.sh` 显式传 | 依赖启动文件的脚本换台机器就死（坑点 #16） |

## ② 环境的继承规则（export 是唯一门票）

```bash
$ X=plain; export Y=exported
$ bash -c 'echo "X=[$X] Y=[$Y]"'
X=[] Y=[exported]        ← 只有 export 的进了子 shell（本机实测）
```

- 子 shell 拿到的是父进程**环境变量**（`export` 过的）的**副本**——改副本不影响父进程
- alias、普通变量、`shopt` 设置**不继承**——脚本环境里 `ll` 不存在（坑点 #16 实测）
- 函数要继承得 `export -f func`（bash 特有，Shellshock 那个洞就在这机制上，日常别用）

## ③ PATH 与"终端好使 cron 不好使"

脚本在 cron / systemd / CI 里 PATH 是**最小默认值**（`/usr/bin:/bin` 级别），
你在交互终端里加的 `~/.local/bin`、brew、nvm 全都不在。三种解法按场景选：

```bash
# ① 脚本内自给自足（推荐——脚本可移植性第一）
export PATH="$HOME/.local/bin:$PATH"

# ② 用绝对路径（个别命令）
/opt/homebrew/bin/bash script.sh

# ③ cron 行首设（只对 cron 场景）
PATH=/home/wzp/.local/bin:/usr/bin:/bin
```

**sudo 是另一个世界**：`sudo` 用 `/etc/sudoers` 的 `secure_path` 替换 PATH，
root 跑脚本时你用户的 PATH 增补全部失效——`sudo which mytool` 找不到不等于没装。

## ④ 两个容易混淆的内建

| 内建 | 干什么 | 什么时候用 |
|---|---|---|
| `source file`（= `. file`） | **在当前 shell** 执行 file（变量/函数留下） | 加载函数库、让配置立即生效；dash 只有 `.` 没有 `source`（坑点 #14） |
| `exec cmd` | 用 cmd **替换**当前 shell 进程（不 fork） | 包装脚本的最后一行：`exec "$@"` 让信号直达真进程（容器 entrypoint 标配） |
