导读

这个模块回答一个问题： 06.6 / 06.6.5 / 06.7 三个模块里有 73 个 .sh 脚本—— 工作里到底用 shell 还是 C？shell 值不值得专门学？

答案：都用，各管各的层。C/C++ 是执行路径的语言（微秒纳秒预算，shell 起一次进程就要几毫秒， 物理上不可能）；shell 是工作台语言——排查、观测、实验编排、构建链、CI 的母语。 前者是武功，后者是手艺，两个都要。

模块定位

  • 薄模块，不做书式精读：shell 没有内核/TLPI 那种机制深度，逐章做笔记是挂积分
  • 学习路径是"用会"不是"学会"：① TLPI 前几章把 shell 当 REPL 用（文件描述符、管道、重定向 就是 Ch5/Ch44 的内容）；② 敲过三遍的命令固化成 .sh；③ 卡住查 man bash
  • 判断三问：主体是调外部命令 → shell；有数据结构/算法/性能预算 → C/C++； 逻辑复杂但本质是文本/数据胶水 → Python。经验法则：脚本开始需要数组、复杂错误处理、 函数返回值，就是它在求你换语言（约 100 行是道坎）
  • 为什么在 01.8 而不在 01.7 里当一章：01.7 的主题是"三套 C 工具链互译"， shell 不是 C 工具链的方言；且坑点清单和注解语料要长期生长，独立模块有空间 （先例：01.5-cmake-build、03.6-userspace-debugging）

1.1

shell 一页速查

← 模块首页

一页纸（详版）。只放日常脚本里真会用的；解释和翻车现场往 1.2 坑点清单 跳。 这里的"shell"= bash（#!/usr/bin/env bash），不追求 POSIX sh 兼容——你的脚本都在 Linux 上跑。 ⚠ 版本基线先看 ⓪；另注意 /bin/sh 不是 bash（Ubuntu 上是指向 dash 的软链，坑点 #14，✅实测）。

⓪ 版本基线（本机实测：Ubuntu 24.04 / bash 5.2.21）

环境 bash 版本 影响
本机（Lenovo，Ubuntu 24.04） 5.2.21（2026-10 实测） 全特性：关联数组、\|&、mapfile、coproc、${var,,}
Pi 5 / WSL Ubuntu 24.04 5.2.x 同上
⚠ /bin/sh（Ubuntu） 不是 bash，是 dash 无数组、[[、<( )、source——shebang 写错全炸（坑点 #14）
跨 Mac 才看：macOS 自带 /bin/bash 3.2.57（2007，GPLv2 末版） 无关联数组等 4.x+ 特性（坑点 #6 备忘）

判断：echo $BASH_VERSION（当前 shell）；readlink -f /bin/sh（看 sh 指向谁——本机实测 = dash）。 你的仓库脚本目标平台是 Linux，放心写 5.2 语法。

① 头部纪律（每个脚本前两行）

#!/usr/bin/env bash
set -euo pipefail
标志 作用 没有它会怎样
-e 任何命令失败立即退出 错误被吞，脚本带着坏状态继续跑
-u 引用未定义变量即报错 打错变量名 = 静默拿到空字符串
pipefail 管道中任一环节失败都算失败 cmd1 \| grep x 里 cmd1 挂了脚本照样成功（坑点 #3）

可选加强（按需要加，别默认全抄）：

shopt -s nullglob     # glob 无匹配时展开为空，而不是字面量 "*.log"（坑点 #8）
shopt -s failglob     # 更狠：无匹配直接报错（二选一）
IFS=$'\n\t'           # 分词只按换行/制表符——防御性写法，会改变 $* 等行为，谨慎
trap 'echo "失败于第 $LINENO 行" >&2' ERR   # -e 触发退出时带行号

② 变量与引号（90% 的 bug 在这）

写法 含义 记法
"$var" 引用变量（永远加双引号） 不加引号 = 单词分割 + glob 展开，文件名带空格必碎（坑点 #7，✅实测）
'$var' 字面量，不展开 单引号里什么都不会发生
$(cmd) 命令替换 别再用反引号 `cmd`，不能嵌套、可读性差；$() 会剥掉全部尾部换行（坑点 #10）
"$@" 全部参数（保持各自边界） 转发参数的唯一正确写法；$* 不加引号会拍平
$# / $1 / shift 参数个数 / 第 N 个 / 左移 —
${var:-默认} 空/未设则用默认值 可选参数：ENV=${1:-prod}
${var:=默认} 同上，且顺手赋值 之后 $var 就是默认值了
${var:?消息} 空/未设则报错退出 必填参数检查，配 set -u 外的显式提示
${var:+替代} 非空才展开 构造可选 flag：${VERBOSE:+-v}

③ 展开顺序（bash 处理一行的固定流水线）

大括号 {a,b} → 波浪号 ~ → 参数/变量 $x → 算术 $(( )) → 命令替换 $( )
→ 单词分割（按 IFS）→ 路径通配 glob（* ? [...]）→ 执行

为什么重要：引号在解析阶段决定后面哪些步骤被跳过——"$var" 展开后不再分词不再 glob； 不加引号则一路走到底。坑点 #2/#7/#8 全是这条流水线的不同切面。

大括号展开（生成序列，不是 glob）：

mkdir -p lab/{bin,src,build}     # 一次建三个目录
cp f.c{,.bak}                    # = cp f.c f.c.bak
echo {1..10}                     # 序列；{01..10} 保留前导零

④ 字符串操作（bash 内建，别为这点事起 sed）

写法 作用 例子（f=dir/app.log）
${#f} 长度 11
${f#*/} 删最短前缀匹配 app.log
${f##*/} 删最长前缀匹配 app.log（取 basename 标准写法）
${f%.*} 删最短后缀匹配 dir/app（去扩展名）
${f%%.*} 删最长后缀匹配 dir/app
${f/log/txt} 替换第一个 dir/app.txt
${f//o/0} 替换全部 dir/app.l0g
${f:0:3} 子串（偏移:长度） dir
${f^^} / ${f,,} 大小写（bash 4+） DIR/APP.LOG

⑤ 判断（[ 是命令，[[ 是关键字）

if cmd; then ... fi                    # 直接用退出码判断，不要 if [ $? -eq 0 ]
[[ -f "$f" ]]     # 普通文件存在    [[ -d "$d" ]]  # 目录存在
[[ -e "$p" ]]     # 存在（任意类型） [[ -r/-w/-x ]] # 可读/可写/可执行
[[ -s "$f" ]]     # 存在且非空       [[ -z "$s" ]]  # 字符串为空（-n 非空）
[[ "$a" = "$b" ]] # 字符串相等       [[ "$n" -gt 3 ]] # 数值比较用 -gt -ge -eq -ne -lt -le
[[ "$s" =~ ^[0-9]+$ ]]              # 正则（右侧不要加引号，加了变字面量）
[[ "$a" = "$b" && "$n" -gt 3 ]]     # 内部用 && ||，外部用 && 连接两个 [[ ]]
(( n > 3 ))                          # 纯数值比较的另一选择，支持 > < == C 风格

优先 [[ ]]：bash 关键字，内部不做单词分割和 glob，比 [ 安全（坑点 #4）。 例外：[[ $a = $b ]] 右侧不加引号是 glob 模式匹配，纯比较写 [[ $a = "$b" ]]（坑点 #11，✅实测）。

⑥ 循环与读行

for f in *.log; do ... done            # glob 直接展开，每个文件名是一个词，空格安全（✅实测）
for i in {1..10}; do ... done          # 固定次数
for ((i=0; i<10; i++)); do ... done    # C 风格
while IFS= read -r line; do ... done < file     # 逐行读文件的唯一正确姿势

逐行读的三要素：IFS=（保留行首行尾空白）、-r（禁止反斜杠转义吃掉 \）、< file 重定向。 陷阱：cmd | while read ...; done 的 while 跑在子 shell 里，循环内改的变量外面看不见 （坑点 #9，✅实测）——解法用进程替换 while ... done < <(cmd)。

反模式：for f in $(ls *.log) —— 见坑点 #2。

⑦ 函数与参数

die() { echo "ERROR: $*" >&2; exit 1; }        # 统一的死法
need() { command -v "$1" >/dev/null || die "缺 $1"; }

myfunc() {
    local src=$1 dst=${2:-/tmp}      # local 必须！否则变量全局泄漏
    ...
    echo "$result"                   # 返回值用 echo 输出，调用方 $(myfunc a b) 接
    # return 只能返回 0-255 的退出码，不是返回值
}
myfunc "in.txt" || die "处理失败"     # 函数退出码照常走

命令行参数解析（轻量版，够 90% 脚本用）：

while getopts ":i:o:v" opt; do
  case $opt in
    i) in=$OPTARG ;; o) out=$OPTARG ;; v) verbose=1 ;;
    :) die "-$OPTARG 缺参数" ;; \?) die "未知选项 -$OPTARG" ;;
  esac
done
shift $((OPTIND-1))                  # 剩下的是位置参数 "$@"

⑧ 数组（bash 4+ 全可用；本机 5.2 已实测，dash 一律不支持）

files=(*.c)                    # glob 直接灌进数组
files+=("new.c")               # 追加
echo "${#files[@]}"            # 元素个数
for f in "${files[@]}"; do ... done    # 遍历的引用必须这么写
"${cmd[@]}"                    # 命令数组展开执行：cmd=(sudo perf stat -a); "${cmd[@]}"

declare -A last_seen           # 关联数组（bash 4+，坑点 #6）
last_seen[eth0]=$(date +%s)

⑨ 重定向与文件描述符

写法 作用 注意
cmd > out 2>&1 stdout+stderr 都进文件 顺序不能反：2>&1 > out 只把 stdout 送进文件
cmd &> out 同上，bash 简写 日志收集常用
cmd >> log 2>&1 追加 triage 脚本落盘的标准形态
cmd 2>/dev/null 只丢错误输出 探测性命令
exec 3<> fifo 打开 fd 3 读写 需要双向通信时才用，日常见不到
cmd \| tee log 既看又存 tee -a 追加
cmd1 \| grep pat \| awk '{print $2}' 三剑客最小集 grep 挑行，awk 取列，sed 改写
sed -i 's/旧/新/g' file 就地替换（GNU 后缀可选） Linux 直接这么写（✅本机实测）；跨 Mac 才要写 -i.bak（坑点 #12 备忘）
<<< "$str" here-string 把变量喂给读 stdin 的命令
<<'EOF' here-doc，引号阻止变量展开 写嵌入脚本/远端执行时用；不加引号则展开
<<-EOF here-doc，吃掉行首 TAB 让 heredoc 能缩进对齐（只认 TAB 不认空格）
< <(cmd) 进程替换：命令输出当文件 解子 shell 变量丢失（坑点 #9）；diff <(ls a) <(ls b)

⑩ 退出码与错误处理

cmd || die "步骤 X 失败"                # 单行兜底最常用
cmd && echo ok                          # 成功才执行
if ! cmd; then ... fi                   # 显式取反
rc=$?                                   # 紧随命令之后取，隔一行就被别的命令覆盖
trap cleanup EXIT                       # 无论怎么退出都跑 cleanup——有副作用脚本必备（netem-lab 模式）
trap 'echo "Ctrl-C，清理中" >&2; exit 130' INT

退出码约定：0=成功，1=通用错误，2=误用，126=不可执行，127=命令不存在，128+N=被信号 N 杀死（130=Ctrl-C）。

⑪ 算术与数值

n=$((n+1))             # 整数算术，$ 可省：((n++))
(( n > 3 )) && ...     # C 风格比较
printf '%.2f\n' "$(echo "scale=2; 10/3" | bc)"     # 浮点 bash 不会，外包给 bc/awk
awk 'BEGIN{printf "%.2f\n", 10/3}'

⑫ 常用外部命令（脚本里反复出现的）

命令 场景 关键选项
printf 比 echo 可移植、可控 printf '%s\n' "$var"；echo 的 -e/-n 各系统不一致
mktemp -d 临时目录 用完 trap 'rm -rf "$tmp"' EXIT
xargs 参数太多/逐条喂 文件名安全版：find . -print0 \| xargs -0 rm
find 找文件 -name/-mtime/-size/-exec ... +
date +%s / date -Iseconds 时间戳 日志命名、耗时统计（$SECONDS 也行）
timeout 30 cmd 限时 GNU coreutils 自带，Linux 直接用（✅本机实测）；macOS 没有（坑点 #1 备忘）
nproc 核数 coreutils 自带；macOS 对应物是 sysctl -n hw.ncpu
command -v 探测命令存在 比 which 可靠（内建，不吃 PATH 别名干扰）

⑬ 调试

bash -x script.sh     # 每条命令展开后打印再执行（首选）
bash -n script.sh     # 只查语法不执行（CI 里跑一遍很值）
set -x / set +x       # 脚本内局部开关
PS4='+${LINENO}: ' bash -x script.sh    # trace 带行号
shellcheck script.sh  # 静态检查器，能装就装（`sudo apt install shellcheck`）；它报的每条都值得看

坑点清单

← 模块首页

每踩一个坑记一条。标注诚实分级：✅实测 = 在你的机器上真实踩过/验证过（附复现）； 📖文档级 = bash FAQ / 手册公认结论，未逐字复现；经验级 = 工程经验，无单一权威出处。 主实测环境：本机 Ubuntu 24.04 / bash 5.2.21（#1–#13 于 2026-10-06 全部复验）；

1/#6/#12 是 macOS 特有坑，本机不构成问题，降级为「跨 Mac 备忘」保留。

#1 ✅实测（备忘）：macOS 没有 timeout 命令——Linux 直接用

  • 本机现状（Linux）：timeout 是 GNU coreutils 自带命令，timeout 1 sleep 0.1 实测可用， 脚本放心写
  • 备忘：macOS 用户态是 FreeBSD 系，没有 timeout（装了 coreutils 也是 gtimeout）—— 哪天脚本要跨 Mac 才需要兼容写法：command -v timeout >/dev/null && T=timeout || T=gtimeout
  • 来源：2026-09 跑 hft 构建时在 Mac 踩中；2026-10-06 本机 Linux 复验无碍

#2 📖文档级：for f in $(ls *.log) 是 shell 第一反模式

  • 为什么碎：$(ls ...) 的输出先按空白单词分割，文件名带空格被切成好几个"文件"； 而且 ls 的输出还可能被 glob 二次展开、带颜色码、本地化格式……bash FAQ #1 头号反模式
  • 正解：for f in *.log —— glob 由 shell 自己展开，每个文件名是一个词，永不分割（见 #7 实测）； 再配 shopt -s nullglob 防止无匹配时循环体拿到字面量 *.log（见 #8）
  • 同类：cat file | while read 能跑但多一个进程；while read ... done < file 更干净

#3 📖文档级：set -e 有三个不触发的洞

洞 例子 后果
管道只看最后一个命令 false \| true 退出码 0，-e 不拦 → 所以必须配 pipefail
条件上下文整体豁免 if cmd; then、cmd \|\| ...、cmd && ... 里的 cmd 失败不退出（这是设计，不是 bug）
命令替换（老 bash） x=$(false) bash < 4.4 不继承失败；显式查 $? 或拆开写
  • 结论：set -euo pipefail 三件套一起用；但不要同时用 $? 手动判断又指望 -e 兜底，两套语义会打架

#4 📖文档级：[ 是命令，[[ ]] 才是语法

  • [ 真实身份是 /usr/bin/[ 这个命令（也是 shell 内建），所以它后面必须有空格， 参数像普通命令一样经历单词分割和 glob：[ $a = 1 ] 在 $a 为空时变成 [ = 1 ]，语法错误
  • [[ ]] 是 bash 关键字，解析阶段就处理：内部不分割、不 glob，空变量安全， 还支持 =~ 正则、< 字典序
  • 结论：bash 脚本里一律 [[ ]]；[ ] 只在写 POSIX sh 兼容脚本时才需要
  • 一个例外要知道：[[ $a = $b ]] 右边是模式匹配（glob），不是纯字符串相等——见 #11 实测

#5 经验级：ssh host 'cmd "$var"' 的引号层级

  • 问题：单引号里 $var 在远端展开（远端 shell 没有你这个变量）；双引号则在本地先展开再送过去
  • 记法：先想清楚"这个变量活在哪一侧"。本地值送过去：ssh host "cmd '$var'"； 远端展开：ssh host 'cmd "$var"'
  • 复杂命令别硬拼引号，用 here-doc：ssh host bash -s <<'EOF' ... EOF—— 整段脚本喂给远端 bash，引号层级消失（pi_exec.py 那条 paramiko 通道同理）

#6 ✅实测（备忘）：macOS 自带 bash 3.2 无关联数组——Linux 5.2 全可用

  • 本机现状（Linux）：bash 5.2.21 实测 declare -A m; m[k]=v、|&、mapfile、${var,,} 全部可用，脚本放心写 4.x+ 特性
  • 备忘：macOS 自带 /bin/bash 是 3.2.57（2007，GPLv2 末版，苹果避 GPLv3 永远停更）， 4.x+ 特性全炸。哪天要跨 Mac：brew install bash + shebang 用 #!/usr/bin/env bash， 或先 echo $BASH_VERSION 确认自己站在哪
  • 注意别混淆：Linux 上的"特性缺失"坑不是 bash 老，而是 /bin/sh 是 dash——见 #14

#7 ✅实测：变量不加引号 = 分词 + glob 双连击

  • 复现：

```bash f="a b.txt" for x in $f; do echo "[$x]"; done # [a] # [b.txt] ← 一个文件名被劈成两个"文件"

touch "a b.txt" c.txt for x in *.txt; do echo "[$x]"; done # [a b.txt] ← glob 展开的结果不再分词，空格安全 # [c.txt] ```

  • 机制：见 1.1 ③ 展开顺序——变量展开的结果会继续走"单词分割"和"glob"两站； 而 glob 自身展开的结果是终点，不再分割
  • 结论：变量引用永远 "$var"；遍历文件永远 glob 直写，别过 $()

#8 ✅实测：glob 无匹配时，模式原样穿过

  • 复现：

bash for x in *.nope; do echo "[$x]"; done # [*.nope] ← 没匹配到任何文件，循环体拿到的是字面量 "*.nope" shopt -s nullglob for x in *.nope2; do echo "[$x]"; done # 什么都不输出——正确

  • 后果：不处理的话，循环体会对不存在的文件 *.nope 动手，rm -f 之类还算温和， mkdir/mv 就会造出名字带星号的怪物目录
  • 解法：shopt -s nullglob（无匹配 → 空）或 failglob（无匹配 → 报错），二选一

#9 ✅实测：管道喂的 while 跑在子 shell 里，变量改了个寂寞

  • 复现：

```bash n=0 printf "a\nb\n" | while read -r l; do n=$((n+1)); done echo "n=$n" # n=0 ← 循环明明跑了两次！

n=0 while read -r l; do n=$((n+1)); done < <(printf "a\nb\n") echo "n=$n" # n=2 ← 进程替换 < <( ) 把循环留在本 shell ```

  • 机制：管道两端各是一个子进程；子进程改父进程的变量？Unix 进程模型说不行
  • 解法：< <(cmd) 进程替换（首选）；或 bash 4.2+ shopt -s lastpipe（有前提：关掉作业控制）
  • 什么时候无所谓：循环里只做输出、不积累状态（cpu-triage 的 perf stat | grep ... 就是这种）

#10 ✅实测：$( ) 命令替换剥掉全部尾部换行

  • 复现：

bash x=$(printf "line\n\n") echo "[$x]" # [line] ← 两个尾换行都没了

  • 影响：① 想保留精确字节流别用 $()（用重定向到文件）；② 想数行数， $(cmd | wc -l) 不受影响（wc 数的是流不是替换结果），但 x=$(cmd); echo "$x" | wc -l 会少数
  • 另一面：这特性经常帮倒忙变帮忙——$(cat file) 后比较字符串不用担心尾部 \n

#11 ✅实测：[[ $a = $b ]] 右侧不加引号是 glob 模式匹配

  • 复现：

bash b="*.txt" [[ "a.txt" = $b ]] && echo 匹配 # 匹配 ← $b 被当 glob 模式，不是字面字符串 [[ "a.txt" = "$b" ]] || echo 不相等 # 不相等 ← 加了引号才是纯字符串比较

  • 结论：想要"相等"就永远写 [[ $a = "$b" ]]；想要模式匹配是有意为之就裸写—— 两者语法一样、语义不同，全靠引号区分，review 时重点盯
  • 同类：=~ 正则匹配右侧也不能加引号（加了变字面量，正则失效）——方向正好相反，别记混

#12 ✅实测（备忘）：BSD sed 的 -i 必须带后缀——GNU sed 随意

  • 本机现状（Linux）：GNU sed -i 后缀可选，sed -i 's/old/new/' s.txt 实测直接可用
  • 备忘：macOS 的 BSD sed 会把 -i 后第一个参数当后缀（sed -i 's/old/new/' s.txt 报 unterminated substitute pattern——它把脚本当后缀、把文件名当脚本了）。 跨平台写法 -i.bak（GNU/BSD 都接受，代价是多个 .bak 文件，用完删掉）
  • 同类坑：macOS 的 date、readlink（无 -f）、stat（-c vs -f）都和 GNU 不同—— 写跨平台脚本时 coreutils 差异是重灾区；纯 Linux 脚本全部不用管

#13 📖文档级：cd 不检查后果自负

  • 场景：cd "$BUILD" && rm -rf * —— 如果 $BUILD 为空或目录不存在， cd 失败后 rm 在当前目录执行。set -e 能拦住 cd 失败（命令失败即退出）， 但只在 cd 单独成行时可靠；cd x && rm ... 里 cd 失败整体短路，反而安全
  • 纪律：① cd 单独成行 + set -e；② 或 cd "$dir" || exit 1； ③ 销毁性操作用绝对路径，别依赖"我 cd 过来了"

#14 ✅实测：Ubuntu 的 /bin/sh 是 dash，不是 bash

  • 复现（2026-10-06 本机）：

bash $ readlink -f /bin/sh /usr/bin/dash $ sh -c 'arr=(1 2); echo ${arr[0]}' dash: 1: Syntax error: "(" unexpected

  • 影响面：shebang 写 #!/bin/sh 却用 bash 语法——数组、[[ ]]、<( )、source、 |&、`${var,,}` 全部炸；cron / systemd / make 默认 shell 也是 /bin/sh
  • 为什么 Ubuntu 这么干：dash 小（~130KB）且快，Debian 政策要求系统脚本只依赖 POSIX 特性， 开机/包安装脚本提速明显
  • 解法：① 自己的脚本 shebang 永远写 #!/usr/bin/env bash（明确要 bash）； ② 拿到报错 "Syntax error: ... unexpected" 先想"是不是被 dash 跑了"； ③ 真要写 POSIX sh 兼容（给嵌入式/BusyBox 用），全程 dash -n 语法检查
  • 同类：source 在 dash 里不存在（用 .）；echo -e 行为不同（见 #15）

#15 📖文档级：echo 不可移植，脚本里用 printf

  • 问题：echo -e "a\tb" 在 bash 内建 echo 里默认不解释 \t（除非 shopt -s xpg_echo）， 在 dash 的 echo 里却解释；echo -n 各家一致但 echo "\c" 又是另一套—— 同一个脚本换 shell 输出就变
  • 解法：脚本里一律 printf '%s\n' "$var"、printf 'a\tb\n'—— printf 是 POSIX 强格式化的，所有 shell 行为一致（1.1 ⑫ 节同源结论）
  • 什么时候 echo 没事：echo "纯字面量"（无选项无反斜杠）随便用

#16 ✅实测：非交互 shell 没有 alias，也不加载 .bashrc

  • 复现（2026-10-06 本机）：

bash $ type ll # 交互终端里：ll 是 'ls -alF' 的 alias $ bash -c 'll /tmp' # 脚本环境里：ll: command not found $ env -i HOME=$HOME bash -c 'echo $PATH' /usr/local/sbin:... # 编译默认 PATH——~/.bashrc 根本没被读

  • 机制：alias 只在交互 shell 展开；.bashrc 只在交互非登录 shell 加载 （登录 shell 走 .profile 系，脚本是非交互非登录，两个都不沾——加载矩阵见 1.4）
  • 解法：① 脚本里别用 alias，写全命令；② 脚本需要的环境变量用 export 显式传 （VAR=x bash script.sh）或在脚本内自己设；③ 共享函数库用 source lib.sh 显式加载

衔接：新增坑按同样的格式往后编（现象 → 复现/原因 → 解法 → 来源 + 分级）。 速查表的对应行在 1.1。

注解正文

注解格式约定：按"段"而不是按"行"——脚本的自然段（空行分隔的逻辑块）就是注解单元。 每段回答三个问题：这段做什么 / 为什么这么做 / 有什么可以偷的写法。

一、cpu-triage.sh（排查固化类范本）

文件：06.6.5-systems-performance/chapter-06-cpus/code/scripts/cpu-triage.sh（34 行）

段 0：shebang + 注释头 + set -u

#!/bin/bash
# cpu-triage.sh — CPU 排查六连 + PSI（ch06 §6.5/6.6）
# 出自: notes/section-6.5-性能分析方法论.md 块3、section-6.6-6.7 块4/5
set -u
  • 注释头第二行直接给笔记出处（哪篇笔记的哪个代码块）——脚本和笔记互为索引，改一边能找到另一边。这个"出自"行值得所有脚本抄。
  • 只用 set -u 不用 -e：排查脚本不该一步失败就全停——mpstat 不在的机器上， 你希望它跳过继续跑后面的，而不是整个脚本死掉。-e 的取舍要看脚本性质： 构建脚本要 -e（半成品比报错更危险），排查/采集脚本不要 -e（拿到多少是多少）。

段 1–5：五个固定拍节的采集块

echo "===== ① uptime —— load 相对核数（核数=$(nproc)） ====="
uptime
  • 每块都是同一个三件套：带圈号标题 echo（内含判读线索）→ 空行 → 命令本体。 标题里嵌 $(nproc) 这种命令替换，把判读需要的上下文直接印在分隔线上—— 看输出时不用另外查核数。
  • 节奏是先宽后窄：uptime（全系统概览）→ mpstat per-CPU（定位到核）→ vmstat（队列/切换） → pidstat（定位到线程）→ PSI（stall 量化）→ perf（微架构 IPC）。这就是 Gregg 的 USE/下钻法在脚本里的形状。
  • cat /proc/pressure/cpu 后面跟一行纯 echo 的判读阈值（some avg10 持续 >10 = CPU 真的不够）： 脚本不光采数据，还把"怎么看"印在数据旁边——这是它和裸命令清单的本质区别。

段 6：优雅降级的标准写法

perf stat -a -- sleep 5 2>&1 | grep -E "insn per cycle|GHz|cpus-migrated" || \
    echo "（跳过：perf_event_paranoid=$(cat /proc/sys/kernel/perf_event_paranoid)，需 sudo 调低）"
  • cmd | grep ... || echo "（跳过：原因）"：grep 没匹配到（perf 被 paranoid 挡住）退出码非 0， || 兜底打印带诊断信息的跳过说明——不中断、不误导，还顺手告诉你怎么修。
  • 注意这里管道只在最后一步 grep 上判断成败（没用 pipefail，perf 本身失败也会走到 ||）， 对采集脚本来说这正是想要的行为。
  • ⚠ 小细节：perf stat ... | grep 里 grep 拿到的行被过滤了，但 perf 的进度输出（2>&1 合流） 会全进 grep——所以用 -E 精确挑三行，而不是全放出来。

段 7：不执行的命令用 echo 印出来

echo "sudo runqlat-bpfcc 10   # 直方图尾部 >1ms 要紧张"
  • 需要 root 的命令不自动 sudo，而是打印出来让人决定——生产环境脚本的安全感： 脚本永远不该替你提权。同时行尾注释带判读阈值，复制跑完知道看什么。

可以偷的写法清单：① "出自"注释行；② 带圈号+判读线索的分隔标题；③ 先宽后窄的块序； ④ || echo "（跳过：原因）" 降级；⑤ root 命令只印不跑。

二、linux-60s.sh（60 秒分析法脚本化）

文件：06.7-bpf-observability/chapter-03-performance-analysis/code/scripts/linux-60s.sh（19 行）

核心就两行"框架代码"，其余全是命令清单：

set -u
I="${1:-1}"
  • I="${1:-1}"：可选参数的标准吃法——采样间隔默认 1 秒，允许 ./linux-60s.sh 5 覆盖。 ${1:-1} 而不是 $1 直接引用，配 set -u 才不会在没传参时报错。 （坑点对照：这正是 1.1 ② 里 ${var:-默认} 的活例。）

十条命令的排版手法：

echo; echo "===== ② dmesg | tail（内核异常） ====="; dmesg 2>/dev/null | tail -5 || sudo dmesg | tail -5
  • 和 cpu-triage 的"一块一段"不同，这里一条命令一行搞定（echo; echo 标题; 命令 用分号串一行）—— 因为 60 秒清单是扫不是钻，视觉密度要高，一屏看全十条。 同一个作者两种排版：清单型脚本紧凑排版，钻取型脚本分段排版。
  • dmesg 2>/dev/null | tail -5 || sudo dmesg | tail -5：无权限时静默失败（2>/dev/null） → grep 不到东西 tail 输出空 → || 升级到 sudo 重试。三级容错压在一行里。 ⚠ 严格说 dmesg | tail 里 dmesg 失败 tail 照样退出 0，|| 拦的是"输出为空"的错觉—— 这里实际生效的是 2>/dev/null 让失败静默，|| 分支靠 tail 继承不到退出码…… 准确机制：dmesg 2>/dev/null 失败 → 管道退出码 = tail 的 0 → || 其实不会触发。 这是原脚本的一个小瑕疵，正确写法是 dmesg 2>/dev/null | tail -5 || ... 想要生效得加 set -o pipefail 或改成 dmesg 2>/dev/null || sudo dmesg | tail -5。注解的第一个战利品： 已回流到坑点 #3 的"管道只看最后一个命令"。
  • top -b -n 1 | head -20：批处理模式取一帧再截头——top 交互模式进不了脚本，-b 就是为此存在。

和 cpu-triage 的关系：60s 是第一滴血（到机器上先跑它），triage 是确诊（60s 说 CPU 有问题再跑 cpu-triage）。 两个脚本合起来就是 Gregg 方法论的实体化——这也是"排查固化类"存在的意义。

三、build-core.sh（构建链范本级）

文件：06.6-ebpf-foundation/chapter-05-core-btf-libbpf/code/scripts/build-core.sh（43 行）

段 0：构建脚本的安全配置（和排查脚本相反！）

set -eu
cd "$(dirname "$0")/.."
BUILD=.build
mkdir -p "$BUILD"
  • set -eu：构建脚本必须一步失败立即停——半成品 .o 比报错危险得多。 对照 cpu-triage 的 set -u 单配置，体会"脚本性质决定头部配置"。
  • cd "$(dirname "$0")/.."：定位锚。$0 是脚本被调用的路径，dirname 取目录， 不管从哪调用（仓库根 / cron / 别的脚本）都先站到固定位置（code/ 目录）， 后面所有相对路径才有意义。构建脚本没有这一行就是定时炸弹（坑点 #13 的近亲）。
  • BUILD=.build 变量化输出目录：产物集中、.gitignore 好配、清理一句话。

段 1：前置依赖检查 + 指路

[ -f /sys/kernel/btf/vmlinux ] || { echo "内核无 BTF！运行 scripts/check-btf.sh 诊断"; exit 1; }
  • 报错信息里附带下一步动作（运行哪个诊断脚本）——好报错不是"出错了"而是"怎么办"。
  • 用 [ ] 单括号：POSIX 写法在简单文件测试上没坑，这里刻意保守（构建脚本可能被各种 sh 解析器碰）。
  • { ...; exit 1; } 花括号组：|| 后面要多条命令时的标准结构（注意 { 后空格、; 收尾）。

段 2–3：流水线式编译，每步一句"生成了什么"

clang -O2 -g -target bpf ... -c hello-buffer-config.bpf.c -o "$BUILD/hello-buffer-config.bpf.o"
echo "生成 $BUILD/hello-buffer-config.bpf.o"
  • 每个编译步骤后跟一句 echo 报产物——构建日志的自文档化：失败时最后一条"生成"之前的步骤就是凶手。
  • $(wc -l < "$BUILD/vmlinux.h")：< file 喂 stdin 而不是 wc -l file， 输出里不带文件名，拿到纯数字。小细节，但日志里好看。

段 4：here-doc 收尾使用说明

cat <<EOF
完成。运行（需 root）：
  sudo $BUILD/hello-buffer-config
EOF
  • cat <<EOF（不加引号）让 $BUILD 展开成真实路径——用户复制就能跑。 对照：如果说明里有 $ 开头的字面量（比如打印一段示例代码），就要 <<'EOF' 防止展开。
  • 构建脚本的最后一步是教用户下一步干什么——strace-vs-bpftrace.sh 的"对比要点"同理。 这类脚本的输出本身就是教程。

可以偷的写法清单：① cd "$(dirname "$0")/.." 定位锚；② 前置检查带"怎么办"； ③ 每步报产物；④ wc -l < file 纯数字；⑤ here-doc 收尾教程（展开与否看引号）。

注解进度：3/12（cpu-triage、linux-60s、build-core）。 注解时顺手把发现的坑回流到 1.2，通用写法提炼回 1.1——三件事是同一个循环。

对应参考书（Kochan & Wood《Shell Programming in Unix, Linux and OS X》4/e）Ch3 + Ch11。 本篇回答三个实际问题：① 我的脚本跑起来的时候，环境（PATH、变量、alias、函数）从哪来？ ② 为什么"终端里好使，cron/CI 里就找不到命令"？③ 改动该写进 .bashrc 还是 .profile？ 全部结论已在本机 Ubuntu 24.04 / bash 5.2.21 实测（2026-10-06）。

① shell 的四种启动形态（决定加载什么）

交互（有终端） 非交互（跑脚本）
登录（bash -l、tty 登录、ssh 登录） ① 读 /etc/profile → ~/.bash_profile → ~/.bash_login → ~/.profile（取第一个存在的） 同左
非登录（终端里再敲 bash、tmux 新窗格） ② 只读 ~/.bashrc ③ 什么都不读——除非 $BASH_ENV 指向一个文件

本机实测验证：

# 形态③：非交互非登录——.bashrc 根本没被读，PATH 是编译默认值
$ env -i HOME=$HOME bash -c 'echo $PATH'
/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin

# 形态③的例外：BASH_ENV 指向的文件会被 source（export 后才能影响子脚本）
$ echo 'Z=from_env' > /tmp/benv.sh
$ BASH_ENV=/tmp/benv.sh bash -c 'echo $Z'
from_env

Ubuntu 的实际布局（本机实证）：

  • 无 ~/.bash_profile、无 ~/.bash_login，只有 ~/.profile —— 登录走第 ① 链的最后一站
  • ~/.profile 末尾有段标准样板：if [ -f "$HOME/.bashrc" ]; then . "$HOME/.bashrc"; fi ——登录 shell 也会间接读 .bashrc，所以日常"改哪里都生效"的错觉来自这里
  • ~/.bashrc（本机 97 行）开头有 case $- in *i*) ;; *) return;; esac—— 非交互 shell 读了也会立即返回，这是发行版给 .bashrc 上的保险

改动写哪里（决策规则）：

改什么 写哪里 为什么
alias、交互专属函数、shopt、PS1 提示符 ~/.bashrc 只对交互 shell 有意义
PATH 增补、环境变量（export GOPATH=...） ~/.profile 登录一次设定，整个会话（含图形会话）继承
脚本需要的变量 不写启动文件——脚本内自设或 VAR=x script.sh 显式传 依赖启动文件的脚本换台机器就死（坑点 #16）

② 环境的继承规则（export 是唯一门票）

$ X=plain; export Y=exported
$ bash -c 'echo "X=[$X] Y=[$Y]"'
X=[] Y=[exported]        ← 只有 export 的进了子 shell（本机实测）
  • 子 shell 拿到的是父进程环境变量（export 过的）的副本——改副本不影响父进程
  • alias、普通变量、shopt 设置不继承——脚本环境里 ll 不存在（坑点 #16 实测）
  • 函数要继承得 export -f func（bash 特有，Shellshock 那个洞就在这机制上，日常别用）

③ PATH 与"终端好使 cron 不好使"

脚本在 cron / systemd / CI 里 PATH 是最小默认值（/usr/bin:/bin 级别）， 你在交互终端里加的 ~/.local/bin、brew、nvm 全都不在。三种解法按场景选：

# ① 脚本内自给自足（推荐——脚本可移植性第一）
export PATH="$HOME/.local/bin:$PATH"

# ② 用绝对路径（个别命令）
/opt/homebrew/bin/bash script.sh

# ③ cron 行首设（只对 cron 场景）
PATH=/home/wzp/.local/bin:/usr/bin:/bin

sudo 是另一个世界：sudo 用 /etc/sudoers 的 secure_path 替换 PATH， root 跑脚本时你用户的 PATH 增补全部失效——sudo which mytool 找不到不等于没装。

④ 两个容易混淆的内建

内建 干什么 什么时候用
source file（= . file） 在当前 shell 执行 file（变量/函数留下） 加载函数库、让配置立即生效；dash 只有 . 没有 source（坑点 #14）
exec cmd 用 cmd 替换当前 shell 进程（不 fork） 包装脚本的最后一行：exec "$@" 让信号直达真进程（容器 entrypoint 标配）

① 四种引号，一张总表（Ch6 精华）

bash 解析一行命令时，引号决定后续哪些展开步骤被跳过（流水线见 1.1 ③）：

形式 变量 $x 命令 $( ) 通配 * 分词 记忆
"双引号" ✅ 展开 ✅ 展开 ❌ ❌ 保护 默认值——不确定就用它
'单引号' ❌ ❌ ❌ ❌ 字面量保险箱，连 \' 都塞不进
无引号 ✅ ✅ ✅ ✅ 分词 坑的源泉（坑点 #7）
\反斜杠 转义下一个字符 只保一个字符

实测对照（v="a b"）：

echo "$v 原样 $v"     → a b 原样 a b      # 空格被保护
echo '$v 字面'        → $v 字面           # 什么都不发生
echo 前"$v"后          → 前a b后           # 引号可以只包一段
echo \$v               → $v               # 反斜杠只转义 $

混合拼接是日常最强技巧："前缀"'"$var"''后缀' 三种引号可以无缝拼在同一个词里， shell 按段处理再粘起来——写 awk/sed 内嵌变量时靠它活命：

awk -v th="$threshold" '$3 > th' data      # 正解：-v 传参
awk '$3 > '"$threshold"'' data             # 拼接法（能跑但脆，优先 -v）

② 命令替换：$( ) 的三个要点

  1. 别用反引号——`cmd` 不能嵌套、引号里行为微妙，POSIX 保留它只为兼容老脚本
  2. 可嵌套：echo $(echo $(echo 内层)) → 内层（实测）
  3. 剥掉全部尾部换行（坑点 #10）：x=$(printf "line\n\n"); echo "[$x]" → [line] ——想保留精确字节流就重定向到文件，别过 $()

③ $@ 与 $*：四种形态全实测（Ch12 最容易挂的部分）

set -- "x y" z 之后：

写法 实测结果 词数 语义
"$@" x y z 2 参数各自独立——转发参数唯一正确写法
$@（裸写） x y z 3 先分词再传递，边界丢失
"$*" x y-z（IFS=- 时） 1 全部参数用 IFS 首字符拼成一个词
$*（裸写） x y z 3 拼接完再分词，等于裸写 $@，一样糟

经验法则：写函数包装器（wrapper）转发参数只有两种合法姿势：

wrapper() { real_cmd "$@"; }              # 99% 的情况
log_and_run() { echo "运行: $*"; "$@"; }  # 打印用 $*（拼一起好看），执行用 "$@"

$* 裸写和 $@ 裸写出现在任何代码里都是 bug 候选——review 时重点盯。

④ 参数扩展 ${...} 八形态（Ch12 表格化）

${var:-word} 族里 冒号的有无 = "空值算不算未设"——实测（v="" vs unset v）：

写法 v="" unset v 用途
${v:-默认} 默认 默认 空也算没给——可选参数默认值
${v-默认} （空） 默认 只有完全未设才算——区分"空"与"没给"
${v:=默认} 默认且赋值 默认且赋值 顺手把默认值写回变量
${v:?消息} 报错退出 报错退出 必填参数检查，比 set -u 报错友好
${v:+替代} （空） （空） 有才展开——构造可选 flag ${VERBOSE:+-v}

场景速记：

ENV=${1:-prod}                          # 可选参数带默认
: "${CONFIG:?必须设 CONFIG}"            # 必填检查（: 是空命令，只触发展开）
cmd ${VERBOSE:+-v} ${DRY:+--dry-run}    # flag 按需出现，不出现连空格都不留

⑤ 模式删除/替换（bash 扩展，POSIX 书没讲全的）

实测（p=/a/b/c.tar.gz）：

${p##*/}   → c.tar.gz      # 删最长前缀 = basename（## 贪婪）
${p#*/}    → a/b/c.tar.gz  # 删最短前缀
${p%.*}    → /a/b/c.tar    # 删最短后缀 = 去一层扩展名
${p%%.*}   → /a/b/c        # 删最长后缀（%% 贪婪）

批量改名实战：

for f in *.jpeg; do mv -- "$f" "${f%.jpeg}.jpg"; done    # 不起外部进程，bash 内建解决

⑥ 一个 Ch6 的经典陷阱：ssh / su -c 的引号层级

（坑点 #5 同款，书 Ch6 收尾案例）——变量在哪一侧展开取决于引号：

ssh host "ls '$dir'"      # $dir 本地展开，单引号保护到远端（值送过去）
ssh host 'ls "$dir"'      # $dir 远端展开（远端没这变量，大概率空）
ssh host bash -s <<'EOF'  # 复杂命令别拼引号：整段脚本喂远端，引号问题消失
cd /data && ./process.sh
EOF

① trap：信号与退出钩子

trap '命令' SIGNAL...     # 收到信号时执行命令

本仓脚本在用的三个：

钩子 触发时机 实战用途
trap cleanup EXIT 无论怎么退出（正常/错误/Ctrl-C 后 exit） 有副作用脚本必备——netem-lab 恢复网卡、mktemp 目录清理
trap '...' INT Ctrl-C（SIGINT） 自定义中断消息 + exit 130（128+2，标准退出码）
trap '...' ERR 任何命令返回非零 错误定位打印——但见下面的坑

⚠ ERR trap 的坑（实测）：ERR trap 只是钩子，不会中断脚本：

$ bash -c 'trap "echo ERR于行$LINENO" ERR; trap "echo EXIT码=$?" EXIT; false; echo 不会到这'
ERR于行1
不会到这        ← false 触发 ERR 后脚本照样往下跑！
EXIT码=0

要让"失败即退出"还是得 set -e（ERR trap 负责在 -e 退出前打印现场， 所以 1.1 ① 的写法是 set -e + trap ... ERR 组合，单用 ERR 不管事）。 另外 ERR 钩子默认不进函数/子 shell，需要 set -E（errtrace）。

INT trap 里要记得 exit：trap 住 Ctrl-C 执行完清理后不显式 exit 130， 信号就被"吞"了，外层脚本以为你正常跑完。

② exec 的两种用法（完全不同！）

用法一：替换进程（不 fork）——容器 entrypoint / 包装脚本收尾：

exec "$@"        # 当前 shell 被替换成目标命令，PID 不变，
                 # 信号（docker stop 的 SIGTERM）直达真进程

用法二：fd 重定向（不带命令的 exec）——日志分身术（实测）：

exec 3>&1              # fd3 = 终端的副本（存档）
exec 1>/tmp/ex.log     # stdout 改道进文件
echo 进文件             # → 文件
echo 回终端 >&3         # → 终端（经 fd3）
exec 1>&3 3>&-         # 恢复 stdout，关闭 fd3

整个脚本输出同时落盘+上屏的另一种写法（更常用）：

exec > >(tee build.log) 2>&1     # 进程替换 + tee，一行解决

注意顺序：cmd > out 2>&1 正确；cmd 2>&1 > out 里 stderr 仍指向旧终端 （重定向从左到右生效，2>&1 复制的是"当时的" stdout）——1.1 ⑨ 节同款表格。

③ eval：把字符串当命令再解析一遍（最后一招）

cmd='echo $((2+3))'; eval $cmd              → 5     # 变量里的表达式被执行
pipe='| wc -l'; eval "printf 'a\nb\n' $pipe" → 2     # 动态拼管道——eval 的主战场

为什么需要它：管道符、重定向、引号是解析阶段处理的，变量里的 | 只是字符—— printf 'a\nb\n' $pipe 会把 | 当字面参数传给 printf。eval 把拼好的字符串重新走一遍 解析流水线，| 才变回管道。

纪律（eval 是注入温床）：

  • 拼进去的片段必须是自己构造的，任何用户输入进 eval = 命令注入
  • 能用数组就不用 eval：cmd=(sudo perf stat -a); "${cmd[@]}"（1.1 ⑧）覆盖了 "动态命令"九成的场景，eval 只在需要动态语法结构（管道/重定向/引号）时才必要

④ getopts：短选项解析（轻量够用）

（1.1 ⑦ 有完整骨架，这里补三个实测细节）

while getopts ":i:o:v" opt; do ... done
#            ↑        ↑
#      开头冒号=自己处理错误   字母后冒号=该选项带参数
  • 开头的 :：缺参数时 opt 得 :、$OPTARG 是选项字母；未知选项得 ?—— 自己报中文错误，不加则 getopts 打英文默认错误
  • OPTIND：处理完 shift $((OPTIND-1))，剩下的位置参数继续用 "$@"
  • getopts 只认短选项（-i）；要 --input 长选项，手写 case 循环或上 Python—— 别为了长选项引入 getopt(1) 外部命令（GNU/BSD 行为分裂，比手写还坑）

⑤ : 与 . 两个最朴素的内建

: "${CONFIG:?必填}"      # : 是空命令，借它触发参数展开做检查（1.5 ④）
. ./lib.sh              # = source，dash 里只有这个写法（坑点 #14）
