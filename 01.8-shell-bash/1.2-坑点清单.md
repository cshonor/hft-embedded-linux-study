## #1 ✅实测：macOS 没有 `timeout` 命令

- **现象**：构建脚本里写 `timeout 30 make ...`，macOS 报 `command not found`
- **原因**：`timeout` 是 GNU coreutils 的命令，macOS 用户态是 FreeBSD 系，没有它
- **解法**：① 这条命令只在 Linux（Pi / Lenovo / WSL）上用；② 非要本机用就装 coreutils
  得到 `gtimeout`；③ 脚本里做兼容：`command -v timeout >/dev/null && T=timeout || T=gtimeout`
- **来源**：2026-09 跑 hft 构建时实测踩中（Debian/Pi 上有，Mac 上没有）

## #2 📖文档级：`for f in $(ls *.log)` 是 shell 第一反模式

- **为什么碎**：`$(ls ...)` 的输出先按空白**单词分割**，文件名带空格被切成好几个"文件"；
  而且 ls 的输出还可能被 glob 二次展开、带颜色码、本地化格式……bash FAQ #1 头号反模式
- **正解**：`for f in *.log` —— glob 由 shell 自己展开，**每个文件名是一个词，永不分割**（见 #7 实测）；
  再配 `shopt -s nullglob` 防止无匹配时循环体拿到字面量 `*.log`（见 #8）
- **同类**：`cat file | while read` 能跑但多一个进程；`while read ... done < file` 更干净

## #3 📖文档级：`set -e` 有三个不触发的洞

| 洞 | 例子 | 后果 |
|---|---|---|
| 管道只看**最后一个**命令 | `false \| true` | 退出码 0，`-e` 不拦 → 所以必须配 `pipefail` |
| 条件上下文整体豁免 | `if cmd; then`、`cmd \|\| ...`、`cmd && ...` 里的 `cmd` | 失败不退出（这是设计，不是 bug） |
| 命令替换（老 bash） | `x=$(false)` | bash < 4.4 不继承失败；显式查 `$?` 或拆开写 |

- **结论**：`set -euo pipefail` 三件套一起用；但不要同时用 `$?` 手动判断又指望 `-e` 兜底，两套语义会打架

## #4 📖文档级：`[` 是命令，`[[ ]]` 才是语法

- `[` 真实身份是 `/usr/bin/[` 这个**命令**（也是 shell 内建），所以它后面**必须有空格**，
  参数像普通命令一样经历单词分割和 glob：`[ $a = 1 ]` 在 `$a` 为空时变成 `[ = 1 ]`，语法错误
- `[[ ]]` 是 bash **关键字**，解析阶段就处理：内部不分割、不 glob，空变量安全，
  还支持 `=~` 正则、`<` 字典序
- **结论**：bash 脚本里一律 `[[ ]]`；`[ ]` 只在写 POSIX sh 兼容脚本时才需要
- **一个例外要知道**：`[[ $a = $b ]]` 右边是**模式匹配**（glob），不是纯字符串相等——见 #11 实测

## #5 经验级：`ssh host 'cmd "$var"'` 的引号层级

- **问题**：单引号里 `$var` 在**远端**展开（远端 shell 没有你这个变量）；双引号则在**本地**先展开再送过去
- **记法**：先想清楚"这个变量活在哪一侧"。本地值送过去：`ssh host "cmd '$var'"`；
  远端展开：`ssh host 'cmd "$var"'`
- **复杂命令别硬拼引号**，用 here-doc：`ssh host bash -s <<'EOF' ... EOF`——
  整段脚本喂给远端 bash，引号层级消失（pi_exec.py 那条 paramiko 通道同理）

## #6 ✅实测：macOS 自带 bash 是 3.2.57（2007），没有关联数组

- **复现**（2026-10-06，本机 `/bin/bash`）：

  ```
  $ /bin/bash --version | head -1
  GNU bash, version 3.2.57(1)-release (arm64-apple-darwin26)
  $ declare -A m
  declare: -A: invalid option          ← 关联数组 bash 4.0 才有
  ```

- **影响面**：`declare -A`（关联数组）、`|&`（stderr 进管道简写）、`mapfile`、`;&`/`;;&`、
  `coproc`、`` `${var,,}` `` 大小写变换——全是 4.x+ 特性
- **背景**：bash 3.2 是 GPLv2 最后一版，苹果为了避开 GPLv3 永远停在 3.2
- **解法**：① 脚本目标平台是 Linux 就放心写 5.x 语法，Mac 本机别用 `/bin/bash` 调试；
  ② `brew install bash`（装到 `/opt/homebrew/bin/bash`）+ shebang 用 `#!/usr/bin/env bash`；
  ③ 先 `echo $BASH_VERSION` 确认自己站在哪

## #7 ✅实测：变量不加引号 = 分词 + glob 双连击

- **复现**：

  ```bash
  f="a b.txt"
  for x in $f; do echo "[$x]"; done
  # [a]
  # [b.txt]        ← 一个文件名被劈成两个"文件"

  touch "a b.txt" c.txt
  for x in *.txt; do echo "[$x]"; done
  # [a b.txt]      ← glob 展开的结果不再分词，空格安全
  # [c.txt]
  ```

- **机制**：见 1.1 ③ 展开顺序——变量展开的结果会继续走"单词分割"和"glob"两站；
  而 glob 自身展开的结果是终点，不再分割
- **结论**：变量引用永远 `"$var"`；遍历文件永远 glob 直写，别过 `$()`

## #8 ✅实测：glob 无匹配时，模式原样穿过

- **复现**：

  ```bash
  for x in *.nope; do echo "[$x]"; done
  # [*.nope]       ← 没匹配到任何文件，循环体拿到的是字面量 "*.nope"
  shopt -s nullglob
  for x in *.nope2; do echo "[$x]"; done   # 什么都不输出——正确
  ```

- **后果**：不处理的话，循环体会对不存在的文件 `*.nope` 动手，`rm -f` 之类还算温和，
  `mkdir`/`mv` 就会造出名字带星号的怪物目录
- **解法**：`shopt -s nullglob`（无匹配 → 空）或 `failglob`（无匹配 → 报错），二选一

## #9 ✅实测：管道喂的 while 跑在子 shell 里，变量改了个寂寞

- **复现**：

  ```bash
  n=0
  printf "a\nb\n" | while read -r l; do n=$((n+1)); done
  echo "n=$n"        # n=0 ← 循环明明跑了两次！

  n=0
  while read -r l; do n=$((n+1)); done < <(printf "a\nb\n")
  echo "n=$n"        # n=2 ← 进程替换 < <( ) 把循环留在本 shell
  ```

- **机制**：管道两端各是一个子进程；子进程改父进程的变量？Unix 进程模型说不行
- **解法**：`< <(cmd)` 进程替换（首选）；或 bash 4.2+ `shopt -s lastpipe`（有前提：关掉作业控制）
- **什么时候无所谓**：循环里只做输出、不积累状态（cpu-triage 的 `perf stat | grep ...` 就是这种）

## #10 ✅实测：`$( )` 命令替换剥掉**全部**尾部换行

- **复现**：

  ```bash
  x=$(printf "line\n\n")
  echo "[$x]"        # [line] ← 两个尾换行都没了
  ```

- **影响**：① 想保留精确字节流别用 `$()`（用重定向到文件）；② 想数行数，
  `$(cmd | wc -l)` 不受影响（wc 数的是流不是替换结果），但 `x=$(cmd); echo "$x" | wc -l` 会少数
- **另一面**：这特性经常帮倒忙变帮忙——`$(cat file)` 后比较字符串不用担心尾部 `\n`

## #11 ✅实测：`[[ $a = $b ]]` 右侧不加引号是 glob 模式匹配

- **复现**：

  ```bash
  b="*.txt"
  [[ "a.txt" = $b ]]  && echo 匹配      # 匹配 ← $b 被当 glob 模式，不是字面字符串
  [[ "a.txt" = "$b" ]] || echo 不相等   # 不相等 ← 加了引号才是纯字符串比较
  ```

- **结论**：想要"相等"就永远写 `[[ $a = "$b" ]]`；想要模式匹配是有意为之就裸写——
  两者语法一样、语义不同，全靠引号区分，review 时重点盯
- **同类**：`=~` 正则匹配右侧也**不能**加引号（加了变字面量，正则失效）——方向正好相反，别记混

## #12 ✅实测：macOS 的 BSD sed，`-i` 必须带后缀参数

- **复现**：

  ```bash
  sed -i 's/old/new/' s.txt
  # sed: 1: "s.txt": unterminated substitute pattern   ← -i 把 s.txt 当成了后缀，
  #                                                    #   把 's/old/new/' 当成了文件名
  sed -i.bak 's/old/new/' s.txt && cat s.txt           # new ✓（留 .bak 备份）
  ```

- **跨平台写法**：GNU sed 是 `-i`（后缀可选），BSD sed 是 `-i 后缀`（必填）。
  要两头兼容写 `-i.bak`（GNU 接受、BSD 接受，代价是多一个 .bak 文件，用完删掉）
- **同类坑**：macOS 的 `date`、`readlink`（无 `-f`）、`stat`（`-c` vs `-f`）都和 GNU 不同——
  写跨平台脚本时 coreutils 差异是重灾区

## #13 📖文档级：`cd` 不检查后果自负

- **场景**：`cd "$BUILD" && rm -rf *` —— 如果 `$BUILD` 为空或目录不存在，
  `cd` 失败后 `rm` 在**当前目录**执行。`set -e` 能拦住 `cd` 失败（命令失败即退出），
  但只在 `cd` 单独成行时可靠；`cd x && rm ...` 里 cd 失败整体短路，反而安全
- **纪律**：① `cd` 单独成行 + `set -e`；② 或 `cd "$dir" || exit 1`；
  ③ 销毁性操作用绝对路径，别依赖"我 cd 过来了"
