# 5.11 accept 返回前连接中止

> [5.2 服务器 main](../5.2_Server_Main.md) · 全连接队列：[Ch 4.5](../../Chapter04_BasicTCPSocket/4.5_Listen_Function.md)

---

## 核心主旨与关键论据

**极端时序**：三次握手完成，连接已进入**已完成连接队列**，但在父进程 **`accept` 取出之前**，客户端发送 **RST** 中止连接。不同内核行为不同；服务器必须**防御性编程**，不能把 `ECONNABORTED` 当致命错误。

---

## 逻辑脉络

```text
客户 SYN → 服务器 SYN+ACK → 客户 ACK（连接 ESTABLISHED，在队列里）
→ 客户立刻 RST（或崩溃发 RST）
→ 父进程仍在 accept() 睡眠
→ accept 返回：成功 / 或 错误
```

### 内核实现差异

| 实现族 | 行为 |
|--------|------|
| **Berkeley 系** | 内核丢弃已中止连接，`accept` **不返回**该连接，父继续睡 |
| **SVR4 / POSIX 系** | `accept` **返回 -1**，`errno` 常为 **`ECONNABORTED`**（软件导致的中止）或 **`EPROTO`** |

---

## 易错细节与重点结论

### 服务器主循环必须这样写

```c
for (;;) {
    clilen = sizeof(cliaddr);
    if ( (connfd = accept(listenfd, (SA *)&cliaddr, &clilen)) < 0) {
#ifdef EPROTO
        if (errno == EPROTO || errno == ECONNABORTED)
#else
        if (errno == ECONNABORTED)
#endif
            continue;          /* 忽略，重新 accept */
        else
            err_sys("accept error");
    }
    /* fork ... */
}
```

| 要求 | 原因 |
|------|------|
| **`ECONNABORTED` → `continue`** | 瞬时异常，**不能 `err_sys` 退出整个服务器** |
| 与 EINTR 区分 | EINTR 常由信号引起，包裹 Accept 可能重启；ECONNABORTED 是「坏连接」 |
