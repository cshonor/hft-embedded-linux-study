# 5.7 正常终止

> [5.6 正常启动](../5.6_Normal_Start.md) · TIME_WAIT：[Ch 2.7](../../Chapter02_TCP_UDP_SCTP/2.7_TIME_WAIT_State.md) · 僵尸：[5.9](../5.9_SIGCHLD_Process.md)

---

## 核心主旨与关键论据

客户在终端输入 **EOF（Ctrl+D）** 触发**正常 TCP 终止序列**（四次挥手）。同时演示：子进程 `exit` 后若无父进程回收，会出现 **僵死进程（Zombie）** —— 为 5.8～5.10 埋钩子。

---

## 逻辑脉络：四路挥手逐步对应程序

| 步 | 谁 | 程序/内核行为 | TCP 状态（典型） |
|----|-----|---------------|------------------|
| 1 | **客户** | `str_cli` 结束 → `main` **`exit`** → 关闭套接字 → 发 **FIN** | 客户 `FIN_WAIT_1` → … |
| 2 | **服务器** | 内核收 FIN → **ACK**；子进程 **`read` 返回 0** | 服务器半关闭；`str_echo` 的 while 结束 |
| 3 | **服务器子** | `str_echo` 返回 → **`exit(0)`** → 关闭 connfd → 发 **FIN** | 客户收 FIN |
| 4 | **客户** | 内核回 **ACK** | 主动关闭方 **`TIME_WAIT`（2MSL）** |

### 与代码的对应

- 客户：**主动关闭方**（先 EOF → exit → FIN）  
- 服务器子：**被动关闭方**先 ACK 客户 FIN，处理完后再发自己的 FIN  
- 父进程通常仍在 `accept`，**不参与**该连接的四次挥手（已 close connfd）

---

## 核心知识点：僵死进程

- 子进程 `exit` 后进入 **`Zombie`（`<defunct>`，`ps` 状态 Z）**  
- 仍占 **进程表项**（PID、退出状态），直到父 **`wait/waitpid`**  
- 父忽略 **`SIGCHLD`** 或从不 wait → 僵尸堆积 → **无法再 fork**（5.9～5.10 解决）

---

## 易错细节与重点结论

| 易错 | 纠正 |
|------|------|
| 以为子 exit 后进程表立刻清空 | 需父 **wait**；否则僵尸 |
| TIME_WAIT 在服务器 | **主动关连接的一方**（此处常是**客户**）进 TIME_WAIT |
| read 返回 0 是错误 | **正常 EOF**，表示对端关闭写方向 |
| 父 close connfd 导致无法挥手 | 父已 close 只减引用；**子**仍持有 connfd 完成子侧挥手 |
