# 6.2 I/O 模型

> [6.3 select](../6.3_Select_Function.md) · 非阻塞：Ch 16

---

## 核心主旨与阶段划分

理解多路复用前，须厘清 Unix **5 种 I/O 模型**。网络输入含**两阶段**：

| 阶段 | 含义 |
|------|------|
| **1** | **等待数据准备好** — 报文进内核接收缓冲区 |
| **2** | **内核 → 用户空间复制** — `read`/`recvfrom` 等 |

---

## 五种 I/O 模型详细拆解

### 6.2.1 阻塞式 I/O（Blocking I/O）

- 最常见：`recvfrom` 直到数据就绪并复制到用户缓冲（或出错）**才返回**  
- **两阶段进程均阻塞**

### 6.2.2 非阻塞式 I/O（Nonblocking I/O）

- 套接字设非阻塞；不能立即完成 → 立即返回 **`EWOULDBLOCK`**  
- 应用须**轮询** — 浪费 CPU，特殊场景用（Ch 16）

### 6.2.3 I/O 复用（Multiplexing）

- 进程阻塞在 **`select`/`poll`**，而非 `recvfrom`  
- 就绪后再 `recvfrom`  
- **优势**：一次 `select` **等多个描述符**

### 6.2.4 信号驱动 I/O

- 开启信号驱动；数据就绪（阶段 1）→ 内核发 **`SIGIO`**  
- 阶段 1 不阻塞主循环；在信号处理函数里 `recvfrom`（Ch 25）

### 6.2.5 异步 I/O（AIO）

- 如 **`aio_read`**（POSIX）  
- 内核在**整个操作（含阶段 2）完成**后通知进程  

| 对比 | 信号驱动 | 异步 I/O |
|------|----------|----------|
| 通知含义 | 「**可以开始**」读 | 「**已经完成**」 |

---

## 6.2.6 & 6.2.7 同步 vs 异步（严格口径）

| 分类 | 包含模型 |
|------|----------|
| **同步 I/O** | 阻塞、非阻塞、**I/O 复用**、信号驱动 — 因 **`recvfrom` 复制时仍阻塞** |
| **异步 I/O** | AIO — **两阶段都不阻塞**请求进程 |

**考试一句**：`select` + `read` = **同步**；不是「异步网络编程」的 async/await 那种语义。

| 易混 | 纠正 |
|------|------|
