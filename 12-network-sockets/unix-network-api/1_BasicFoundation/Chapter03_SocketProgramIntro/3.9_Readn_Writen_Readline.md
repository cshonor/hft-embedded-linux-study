# 3.9 readn、writen 和 readline 函数

> TCP 无边界：[Ch 2.4](../../Chapter02_TCP_UDP_SCTP/2.4_TCP_Protocol.md) · Ch [1.2 循环 read](../../Chapter01_Introduction/1.2_SimpleTimeClient.md#ch1-2-api)

---

## 核心主旨与关键论据

**TCP 字节流无记录边界**。单次 `read`/`write` 可能返回**少于请求的字节（短计数）** — **正常现象，非错误**。固定长度协议必须用 **`readn`/`writen`**。

---

## readn / writen 逻辑

```c
/* 伪逻辑 */
while (nleft > 0) {
    if ( (nread = read(fd, ptr, nleft)) < 0) {
        if (errno == EINTR)
            continue;      /* 信号中断，重试 */
        else
            return -1;
    } else if (nread == 0)
        return count - nleft;  /* EOF，可能短读 */
    nleft -= nread;
    ptr += nread;
}
return count;
```

| 要点 | 说明 |
|------|------|
| **while** | 直到读/写满 n 或出错/EOF |
| **EINTR** | **continue**，非真错 |
| **writen** | 对称，保证 n 字节全部写入 |

---

## readline 演进

| 实现 | 问题 |
|------|------|
| 每次 `read` 1 字节 | 1KB 行 ≈ 1000 次系统调用，极慢 |
| **内部缓冲 `my_read`** | 一次读大块，再逐字节找 `\n` |
| **陷阱** | **静态缓冲 → 非线程安全**；与 `select` 混用可能状态错乱 |

---

## 易错细节

| 易错 | 纠正 |
|------|------|
| 一次 read 读满协议 | TCP 必须循环或 readn |
| stdio `fgets` 用于双工 socket | 易**死锁**（Ch 5） |
| readline 多线程 | 需每线程独立缓冲或加锁 |
