## 统一首部：`rt_msghdr`

进程与路由套接字交换的消息均以 **`rt_msghdr`** 打头：

| 字段 | 含义 |
|------|------|
| `rtm_msglen` | 整条消息长度 |
| 版本 | 协议版本 |
| **`rtm_type`** | `RTM_ADD` / `RTM_DELETE` / `RTM_GET` / 通知类型等 |
| **`rtm_addrs`** | 后续紧跟哪些 `sockaddr` 的**位掩码** |

读写 API 与普通套接字相同：**`write` / `read`**（或 `send` / `recv`）。

---

## `rtm_addrs` 与紧凑打包

一次路由操作常需多个地址（目的、网关、掩码等）。内核用 **掩码 + 连续排列** 省内存：

```text
rt_msghdr
  [ 若 RTA_DST  → sockaddr 目的 ]
  [ 若 RTA_GATEWAY → sockaddr 网关 ]
  [ 若 RTA_NETMASK → 可能被压缩的掩码 ]
  ...
```

---

## 解析难点

| 问题 | 后果 |
|------|------|
| IPv4 `sockaddr_in` vs IPv6 `sockaddr_in6` 长度不同 | 指针步进必须按**实际 sa_len** |
| 掩码可能被“压缩” | 不能假设固定 16 字节 |
| 夹杂 `sockaddr_dl` | 需按 `AF_LINK` 分支 |

书中用宏逐步“挖出”每个地址 — **C 指针与对齐的终极练习**。

---

## 内核 → 进程：事件广播

路由表因 **ICMP 重定向**、守护进程更新等变化时，内核向**所有**打开 `AF_ROUTE` 的进程发送通知消息 — `ioctl` 无法做到。
