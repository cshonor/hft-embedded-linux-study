## 核心主旨与架构演进

用 **单进程 + `select`** 替代 **`fork`**，一个进程管理 **listenfd + 所有 connfd**，避免每连接 fork 开销。

---

## 核心数据结构

| 变量 | 作用 |
|------|------|
| **`client[]`** | 长度 `FD_SETSIZE`，存活跃 connfd，空闲为 **-1** |
| **`maxfd`** | 当前最大 fd 值 → `select` 的 **maxfdp1** |
| **`maxi`** | `client[]` 最大使用下标 → 优化遍历 |

---

## 主循环工作流

```text
1. FD_ZERO；FD_SET(listenfd)；对每个 client[i]>=0 → FD_SET
2. select(maxfd+1, &rset, ...) 阻塞
3. listenfd 就绪 → accept → 放入 client[] 第一个 -1 槽 → 更新 maxfd/maxi
4. 遍历 i=0..maxi：
     client[i] 就绪 → read
       n > 0  → writen 回射
       n == 0 → close；client[i]=-1；FD_CLR（下次重建 rset）
```

---

## 易错细节：DoS 与阻塞 read（重点结论）

| 攻击/缺陷 | 机制 |
|-----------|------|
| 恶意客户**连接后少发数据即停** | 服务器 **`read` 阻塞**在该 connfd |
| 后果 | **整个进程卡住**，其他客户饿死 |

**铁律**：单进程 select 服务器中，**read/write/accept 必须非阻塞**（Ch 16），否则生产不可用。

| 对比 | fork 服务器 | select 单进程 |
|------|-------------|---------------|
| 慢客户 | 只阻塞该子进程 | **阻塞全体** |
| 开销 | fork 贵 | 无 fork，但需非阻塞 |
