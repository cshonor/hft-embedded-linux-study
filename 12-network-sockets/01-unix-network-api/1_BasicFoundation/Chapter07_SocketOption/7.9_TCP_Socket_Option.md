## 2. TCP_NODELAY（极度重要）

### Nagle 算法

- 若连接上有**未确认数据**，**缓冲小分节**，等 ACK 再合并发送  
- 目的：减少 WAN **小分组泛滥**

### 与延迟 ACK 的死锁

```text
客户发小包1 → 等 ACK（Nagle）
服务器收包1 → 延迟 ACK（想捎带回射）
→ 双方互等 → 可达 ~200ms 无谓延迟
```

### 适用场景

**SSH、X11、实时游戏**等需**即时发出小数据** → **必须 `TCP_NODELAY`**

| 设置 | 效果 |
|------|------|
| 默认（Nagle 开） | 交互延迟可能大 |
| **TCP_NODELAY=1** | 禁用 Nagle，小包立刻发 |

---

## 易错细节

| 易混 | 纠正 |
|------|------|
| NODELAY = 更快总是好？ | 高吞吐 bulk 传输可能**更差**（更多小报文） |
| Linux TCP_CORK | 与 NODELAY 相反方向聚合（留白） |
