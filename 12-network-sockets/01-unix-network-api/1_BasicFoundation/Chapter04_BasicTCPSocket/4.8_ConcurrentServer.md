## 核心主旨与关键论据

标准 **TCP 并发服务器**流程 — Ch 5 Echo 的骨架。

---

## 执行流程（逐步）

1. 父：`socket` → `bind` → `listen`  
2. 父：循环 **`accept`** → 得 **`connfd`**  
3. 父：**`fork`**  
4. **子**：**`close(listenfd)`** → 处理 `connfd`（如 `str_echo`）→ **`exit`**  
5. **父**：**`close(connfd)`** → 回到 **`accept`**

---

## 易错细节：描述符泄露（必考）

| 问题 | 机制 |
|------|------|
| 为何不关 connfd | `fork` 后引用计数 **2** |
| 子 exit 后 | 子侧 close → 计数 **1** |
| 父若不 close | 计数永不为 0 → **TCP 不断开**、**fd 泄漏** |
| 表现 | 高并发 EMFILE、连接挂死 |

**父必须 `close(connfd)`** — 与 Ch 5.2 铁律同源。

---

## 重点结论

| 模型 | 特点 |
|------|------|
| **迭代** | 无 fork；一客户慢则全员阻塞 |
| **并发 fork** | 每连接一子进程；父只 accept |
