## 核心主旨与关键论据

本章通过构建一个完整且可运行的 **TCP 回射（Echo）客户/服务器程序**，把前一章的基本套接字 API **组合成可运行系统**。但在真实网络环境中，程序不仅要处理正常通信，更要应对各种**网络异常和边界条件**。

本章的核心目的：展示如何使程序变得 **健壮（robust）**，以应对：

- 进程崩溃、主机崩溃  
- 信号中断、僵死进程  
- 连接在半路上被 RST 中止  
- 单线程阻塞 I/O 无法同时感知键盘与网络  

---

## 核心知识点与逻辑脉络

### 系统架构（三角色数据流）

| 步骤 | 行为 |
|------|------|
| 1 | **客户端**从标准输入读入一行文本，经套接字发给服务器 |
| 2 | **服务器**从网络接收数据，**原样回射**给客户端 |
| 3 | **客户端**接收回射数据，输出到标准输出 |

这是全书第一个「端到端业务闭环」：不再是 Ch 1 的固定 26 字节时间串，而是**任意长度的行文本**双向流动。

### 边界条件防御（本章主线）

单纯实现收发极易在真实环境中**死锁或崩溃**。本章系统梳理：

| 类别 | 典型场景 | 对应小节 |
|------|----------|----------|
| 正常路径 | 启动、正常 EOF 终止 | 5.6、5.7 |
| 进程管理 | 僵尸、`SIGCHLD`、`waitpid` | 5.8～5.10 |
| 连接异常 | accept 前 RST、`ECONNABORTED` | 5.11 |
| 对端终止 | 子进程 kill、FIN/RST、`SIGPIPE` | 5.12～5.13 |
| 主机级故障 | 断电、重启、关机 | 5.14～5.16 |
| 数据表示 | 跨平台 struct 二进制 | 5.18 |
| 架构天花板 | 阻塞 stdin + 阻塞 socket | 5.5、5.17 → **Ch 6** |

## 易错细节与重点结论

| 易混 | 纠正 |
|------|------|
| Echo = 时间服务器？ | 时间程序是**定长读循环**；Echo 服务器是 **read+writen 回射**，客户用 **readline 按行** |
| 写完 Echo 就「会网络编程」？ | 不加 5.8～5.16 的防御，生产环境**必崩**（僵尸、SIGPIPE、感知不到断线） |
| 健壮 = 多写 try-catch？ | Unix 网络健壮核心是 **信号、waitpid、EINTR、忽略 SIGPIPE、多路复用** |
