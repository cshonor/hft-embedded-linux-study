## 本节要会什么

**TCP 服务端六步法** + 分清 **`listenfd`（只 accept）** 与 **`connfd`（只读写一路客户）**；**迭代服务器** = 串行，同一时刻只服务一个客户端。

**端口 13（Daytime / RFC865）**：`bind` **`htons(13)`** → [端口说明](./1.2_Appendix_Daytime端口13.md) · **与图 1-5 客户端联合流程** → [C/S 完整时序](./1.12_Appendix_DaytimeCS联合流程.md)

<a id="ch1-5-flow"></a>

## 一、整体流程（服务端六步）

| # | 步骤 | API / 行为 |
|---|------|------------|
| 1 | 创建监听套接字 | `Socket` → **`listenfd`** |
| 2 | 绑定地址端口 | **`Bind`**：`INADDR_ANY` + **`htons(13)`** |
| 3 | 被动监听 | **`Listen(listenfd, LISTENQ)`** |
| 4 | 等客户连入 | **`Accept`** 阻塞 → 返回 **`connfd`** |
| 5 | 发时间字符串 | `time` / `ctime` / **`snprintf`** → **`Write(connfd, …)`** |
| 6 | 关本会话 | **`Close(connfd)`** → 回到步骤 4 |

```text
socket → bind(0.0.0.0:13) → listen → for(;;) { accept → write → close(connfd) }
```

> **迭代**：新连接必须等上一客户 **`close(connfd)`** 后，下一次 `accept` 才会处理它（排队）。

---

<a id="ch1-5-fd"></a>

## 二、listenfd vs connfd（核心）

| | **listenfd** | **connfd** |
|---|--------------|------------|
| **创建** | `Socket` 一次 | 每次 `Accept` 一个新 fd |
| **用途** | **只** `Accept` 新连接 | **只** 本会话的 `read`/`write` |
| **生命周期** | 进程全程不关 | 处理完该客户就 **`Close`** |
| ❌ 禁止 | 在 listenfd 上 read/write | 用 connfd 去 accept |

**绑定谁？** `sin_addr = htonl(INADDR_ANY)` → **0.0.0.0**，本机**所有网卡**的 13 端口都可连（不必写死 `192.168.x.x`）。

---

<a id="ch1-5-api"></a>

## 三、关键 API 对照

| API | 要点 |
|-----|------|
| **`Bind`** | `INADDR_ANY` + `htons(13)`；端口网络序 |
| **`Listen(fd, LISTENQ)`** | **backlog** ≈ 全连接队列上限；`listenfd` 进入被动监听 |
| **`Accept(listenfd, …)`** | 阻塞；三次握手完成后返回**新** `connfd` |
| **`snprintf`** | 限长写 buff；**禁用 `sprintf`** 防溢出 |
| **`Write(connfd, …)`** | TCP 流式发出时间串 |
| **`Close(connfd)`** | 只关本会话；**不要** `close(listenfd)` |

半连接 / 全连接 → [附录·listen 队列](./1.5_Appendix_listen队列.md#ch1-5-listenq)（**不重复**展开）

<a id="ch1-5-runtime"></a>

## 四、逻辑时序

```text
listenfd = socket → bind → listen →
  accept 阻塞 → 握手完成得 connfd →
  组时间串 → write → close(connfd) →
  回到 accept（下一客户）
```

<a id="ch1-5-cheat"></a>

## 五、易错陷阱

| ❌ | ✅ |
|----|-----|
| 在 **listenfd** 上 read/write | 只用 **connfd** 做 I/O |
| **sprintf** | **snprintf(buff, sizeof(buff), …)** |
| **close(listenfd)** | 只 **Close(connfd)** |
| 以为迭代能同时服务多人 | 串行；并发见 Ch 4/5 **fork** |

<a id="ch1-5-summary"></a>

## 九、个人学习总结

1. **listenfd** 只 accept；**connfd** 只服务一次会话。  
2. **INADDR_ANY** = 全网卡监听，服务端常规写法。  
3. **迭代** 串行；全连接队列可堆满 → 生产用 fork / 多路复用（见 listen 附录）。  
4. **snprintf** 限长；禁用 sprintf。

**30 字**：bind 全零地址、listen、循环 accept、写时间、关 connfd。

**链路**：1.2 客户五步法 ↔ 1.5 服务六步 · 1.4 大写包裹 · Ch4/5 并发。
