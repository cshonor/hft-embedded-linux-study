## 笔记

用磁盘/SSD 等作层次底部，让程序以为有「远大于物理内存」的地址空间；并 **隔离进程**。

### 8.4.1 地址转换

CPU 发 **虚地址 VA** → MMU 映射为 **物理地址 PA**：

```
VPN（虚页号） → PPN（物理页号）  +  页内偏移（通常直接穿过）
```

常见页大小：4 KiB（大页 2 MiB/1 GiB 等减 TLB 压力）。

### 8.4.2 页表

- 放在**主存**；记录 VPN→PPN、有效位、**读写执行权限** 等。  
- 每次老实查表 ≈ **多次访存** → 太贵 → 要 TLB。  
- **多级页表**：只为用到的虚址范围分配页表页，省物理内存（ARM Linux 常见 3/4 级，视架构）。

### 8.4.3 TLB

**TLB** = 页表项的专用小 Cache。  
命中 → 快出 PPN；缺失 → 走页表硬件/软件填充；再不行 → **缺页异常** 进 OS。

```
VA → TLB → PA → Cache →（可能）DRAM
         ↘ miss → 页表漫步 →（可能）page fault
```

### 8.4.4 保护与权限

每进程自己的页表 → **独立地址空间**。  
权限位：读/写/执行；内核还可区分用户可否执行（UXN 等）。  
非法访问 → 异常 → Linux `segfault` / 内核 oops（视上下文）。

### 8.4.5 缺页与 swap

| 情况 | 后果 |
|------|------|
| 首次碰匿名页 / 文件映射未驻留 | 缺页 → OS 分配/读入 |
| 物理页紧张 | 可能换出到 swap（嵌入式常关 swap） |
| 驱动在原子上下文碰会缺页的用户地址 | **危险** → 先 `copy_from_user` / 锁页 |

### 8.4.6 对嵌入式 Linux 驱动（必抓）

| API / 概念 | 和 VM 的关系 |
|------------|----------------|
| **用户指针** | 是 VA；内核不能当 PA 解引用（要用 `copy_*_user`） |
| **`ioremap` / `devm_ioremap`** | 把 **设备物理 MMIO** 映到内核 VA；属性常为 Device |
| **`mmap` 到用户态** | 建立用户 VA→（页/设备）映射；要设对缓存/权限 |
| **DMA** | 外设要的是总线可见地址；`dma_map_*` / IOMMU 管 VA/IOVA/PA 关系 |
| **无 MMU 的 MCU** | 物理编址或简单 **MPU**；不是 Linux MMU 那套 |

| ❌ | ✅ |
|----|-----|
| 把用户指针直接当内核可解引用地址 | `copy_from_user` / `get_user` |
| 以为 `virt_to_phys` 到处乱用就安全 | 高端/线性映射区才有简单关系；驱动优先官方 DMA/ioremap API |
| 忽略 TLB/Cache 与 DMA | 改映射或 DMA 前后要维护（→ [8.3](./8.3_高速缓存.md)） |
