## 笔记

Cache = 主存常用子集的 **高速小容量**（多为 SRAM）副本。

### 8.3.1 存什么

按 **块（block / line）** 从主存搬入 —— 吃时间局部性 + 空间局部性，降 miss rate。  
常见 line：32/64 B（看 SoC）。

### 8.3.2 怎么找（映射）

地址拆成：

| 字段 | 作用 |
|------|------|
| **Tag** | 这一块是不是我要的那份 |
| **Set（组号）** | 映射到哪一组 |
| **Offset** | 块内字节/字偏移 |

| 组织 | 规则 | 代价 |
|------|------|------|
| **直接映射** | 每地址只进唯一一组/一路 | 硬件简单；冲突多 |
| **N 路组相联** | 进某组，组内 N 路任选 | 折中常用 |
| **全相联** | 可放任意位置 | 冲突最少；比较器贵 |

### 8.3.3 替换

组满时：常用 **LRU**（或近似）决定踢谁。

### 8.3.4 写策略与多级 · 三 C

| 主题 | 要点 |
|------|------|
| **直写 write-through** | 写 Cache 同时写下级 → 简单、总线忙 |
| **回写 write-back** | 只标脏，换出时写回 → 省带宽、控制复杂 |
| **多级 Cache** | L1、L2… 进一步压 AMAT |
| **三 C 缺失** | **强制**（第一次）· **容量** · **冲突**（映射撞车） |

### 8.3.5 ARM / SoC 常见形态

| 点 | 直觉 |
|----|------|
| **I-Cache / D-Cache 分离（L1）** | 哈佛：取指与数据各一套，减冲突 |
| 统一 L2 | 共享容量 |
| **设备内存 vs 普通内存** | MMIO 区域通常标成 Device / Strongly-ordered，**禁止**当普通 Cacheable 乱缓存 |

### 8.3.6 对驱动：正确性 > 性能口号

CPU 写的数据在 D-Cache 里；DMA 引擎读的是 **总线看到的内存**。两者不一致 → 经典 bug。

| 场景 | 要做什么（概念） |
|------|------------------|
| CPU 填缓冲 → 外设 DMA 读 | 把相关 Cache **写回/清干净** 再启动 DMA（或用非缓存/一致性缓冲） |
| 外设 DMA 写 → CPU 读 | **无效化** 对应 Cache 行，再读（或用一致性 API） |
| Linux | 优先用 `dma_alloc_coherent` / streaming DMA API，让内核帮你做维护 |

| ❌ | ✅ |
|----|-----|
| 当「开了 Cache 就一定更快、不用管」 | Cache 开了更要管 **一致性** |
| 用缓存的 VA 随便给外设当 DMA 地址 | 外设要的是 **总线/物理（或 IOVA）** 地址 |

伪共享（false sharing）：两核改同一 cache line 不同字段 → 来回作废，性能像死锁。驱动环形队列、每 CPU 计数要注意对齐。
