8.1

引言

笔记

处理器速度涨得远快于 DRAM → 裸接主存会把整机拖死。
Ch7 教学 CPU 常假设「访存一拍完」——真实系统靠 层次结构 才接近这个假象。

对策依赖 局部性原理，把「常用」放进离 CPU 近的快存：

局部性 含义 Cache 怎么用
时间局部性 刚用过的很快再用 留下最近访问的块
空间局部性 附近地址也快要用 按块（block） 整段搬入 
寄存器  ≪  L1/L2 Cache(SRAM)  ≪  DRAM  ≪  磁盘/Flash
快·贵·小                              慢·便宜·大

对嵌入式 Linux

场景 直觉
驱动热路径反复摸同一描述符 吃时间局部性 → 少 miss
顺序扫缓冲区 / 环形队列 吃空间局部性 → 按 cache line 对齐有时有益
DMA 大块搬运 绕过或弄脏 Cache → 要一致性协议（→ 8.3）
ioremap 的 device memory 往往 不走 普通 Cache 语义

层次结构 = 用局部性兑换「接近 SRAM 的平均速度 + 接近磁盘的容量/价格」。

存储器系统性能分析

笔记

指标 含义
命中率 hit rate 在本级找到的比例
缺失率 miss rate 1 − hit rate
AMAT 平均存储器访问时间 
AMAT = HitTime + MissRate × MissPenalty

要点：即使 MissRate 很小，若 MissPenalty 极大（主存、磁盘），AMAT 仍可炸穿。

数量级直觉（示意，非某芯片标称）

层级 大约延迟量级
L1 hit 数拍 ~ 十来拍
L2 hit 十几 ~ 几十拍
DRAM 上百 ~ 数百拍
缺页进磁盘/Flash 百万拍级（数量级）

例：HitTime=1，MissRate=2%，MissPenalty=100 → AMAT = 1 + 0.02×100 = 3（平均已是 hit 的 3 倍）。
MissRate=0.1% 但 MissPenalty=10⁶（缺页）→ 贡献仍巨大。

对嵌入式 Linux / 驱动

做法 为何
热路径少乱跳、少大范围扫冷内存 降 miss rate
DMA 缓冲对齐、连续物理页（若需要） 降 TLB/Cache 压力
避免在中断里碰会缺页的用户缓冲 MissPenalty 不可控
性能分析先看 cache-miss / cycles 比只看「代码行数」更接近硬件

一句话： 平均延迟由「偶尔一次的大罚」主导时，优化 miss 与缺页比抠几个 ALU 指令更值。

8.3

高速缓存

Link Target: Ch5 SRAM · 驱动 DMA · HFT 数据布局 · ↔ CSAPP §6.4.2 直接映射 · ↔ Hennessy §2.1 存储器层次 档位: 精读

  • [x] 已写要点
  • [x] Linux 驱动：I/D Cache、写策略、DMA 一致性

笔记

Cache = 主存常用子集的 高速小容量（多为 SRAM）副本。

8.3.1 存什么

按 块（block / line） 从主存搬入 —— 吃时间局部性 + 空间局部性，降 miss rate。
常见 line：32/64 B（看 SoC）。

8.3.2 怎么找（映射）

地址拆成：

字段 作用
Tag 这一块是不是我要的那份
Set（组号） 映射到哪一组
Offset 块内字节/字偏移
组织 规则 代价
直接映射 每地址只进唯一一组/一路 硬件简单；冲突多
N 路组相联 进某组，组内 N 路任选 折中常用
全相联 可放任意位置 冲突最少；比较器贵

8.3.3 替换

组满时：常用 LRU（或近似）决定踢谁。

8.3.4 写策略与多级 · 三 C

主题 要点
直写 write-through 写 Cache 同时写下级 → 简单、总线忙
回写 write-back 只标脏，换出时写回 → 省带宽、控制复杂
多级 Cache L1、L2… 进一步压 AMAT
三 C 缺失 强制（第一次）· 容量 · 冲突（映射撞车）

8.3.5 ARM / SoC 常见形态

点 直觉
I-Cache / D-Cache 分离（L1） 哈佛：取指与数据各一套，减冲突
统一 L2 共享容量
设备内存 vs 普通内存 MMIO 区域通常标成 Device / Strongly-ordered，禁止当普通 Cacheable 乱缓存

8.3.6 对驱动：正确性 > 性能口号

CPU 写的数据在 D-Cache 里；DMA 引擎读的是 总线看到的内存。两者不一致 → 经典 bug。

场景 要做什么（概念）
CPU 填缓冲 → 外设 DMA 读 把相关 Cache 写回/清干净 再启动 DMA（或用非缓存/一致性缓冲）
外设 DMA 写 → CPU 读 无效化 对应 Cache 行，再读（或用一致性 API）
Linux 优先用 dma_alloc_coherent / streaming DMA API，让内核帮你做维护
❌ ✅
当「开了 Cache 就一定更快、不用管」 Cache 开了更要管 一致性
用缓存的 VA 随便给外设当 DMA 地址 外设要的是 总线/物理（或 IOVA） 地址

伪共享（false sharing）：两核改同一 cache line 不同字段 → 来回作废，性能像死锁。驱动环形队列、每 CPU 计数要注意对齐。

对你

方向 带走
嵌入式 Linux Cache 维护 · DMA API · device memory 属性
HFT 热数据对齐块大小、避免伪共享；miss 代价按 8.2 想
细节公式 → CSAPP Ch6；此处够用的是行为与驱动接口
8.4

虚拟存储器

  • [x] 已读（口述巩固）
  • [x] 已写要点
  • [x] Linux：用户/内核、缺页、ioremap、DMA 映射

笔记

用磁盘/SSD 等作层次底部，让程序以为有「远大于物理内存」的地址空间；并 隔离进程。

8.4.1 地址转换

CPU 发 虚地址 VA → MMU 映射为 物理地址 PA：

VPN（虚页号） → PPN（物理页号）  +  页内偏移（通常直接穿过）

常见页大小：4 KiB（大页 2 MiB/1 GiB 等减 TLB 压力）。

8.4.2 页表

  • 放在主存；记录 VPN→PPN、有效位、读写执行权限 等。
  • 每次老实查表 ≈ 多次访存 → 太贵 → 要 TLB。
  • 多级页表：只为用到的虚址范围分配页表页，省物理内存（ARM Linux 常见 3/4 级，视架构）。

8.4.3 TLB

TLB = 页表项的专用小 Cache。
命中 → 快出 PPN；缺失 → 走页表硬件/软件填充；再不行 → 缺页异常 进 OS。

VA → TLB → PA → Cache →（可能）DRAM
         ↘ miss → 页表漫步 →（可能）page fault

8.4.4 保护与权限

每进程自己的页表 → 独立地址空间。
权限位：读/写/执行；内核还可区分用户可否执行（UXN 等）。
非法访问 → 异常 → Linux segfault / 内核 oops（视上下文）。

8.4.5 缺页与 swap

情况 后果
首次碰匿名页 / 文件映射未驻留 缺页 → OS 分配/读入
物理页紧张 可能换出到 swap（嵌入式常关 swap）
驱动在原子上下文碰会缺页的用户地址 危险 → 先 copy_from_user / 锁页

8.4.6 对嵌入式 Linux 驱动（必抓）

API / 概念 和 VM 的关系
用户指针 是 VA；内核不能当 PA 解引用（要用 copy_*_user）
ioremap / devm_ioremap 把 设备物理 MMIO 映到内核 VA；属性常为 Device
mmap 到用户态 建立用户 VA→（页/设备）映射；要设对缓存/权限
DMA 外设要的是总线可见地址；dma_map_* / IOMMU 管 VA/IOVA/PA 关系
无 MMU 的 MCU 物理编址或简单 MPU；不是 Linux MMU 那套
❌ ✅
把用户指针直接当内核可解引用地址 copy_from_user / get_user
以为 virt_to_phys 到处乱用就安全 高端/线性映射区才有简单关系；驱动优先官方 DMA/ioremap API
忽略 TLB/Cache 与 DMA 改映射或 DMA 前后要维护（→ 8.3）

方向 带走
嵌入式 Linux VA≠PA；缺页；ioremap；DMA 映射；用户/内核隔离
HFT TLB miss、大页、锁页避 swap
