汇编语言

  • [x] 已读（口述巩固）
  • [x] 已写要点

笔记

汇编 = 机器语言的人类可读形式。本书主线 AArch32（32 位 ARM 状态）。

6.2.1 指令长什么样

助记符   目的, 源…
例: ADD  R0, R1, R2     ; R0 = R1 + R2
    LDR  R0, [R1, #4]   ; R0 = Mem[R1+4]
    BL   foo            ; 调用，LR←返回地址

工具：arm-linux-gnueabihf-objdump -d / aarch64-linux-gnu-objdump -d。

6.2.2 操作数在哪

位置 说明
寄存器 16×32-bit：R0–R15
存储器 只能经 LDR/STR（load/store 架构）
立即数 嵌在指令里（大常数 → 文字池，见 6.6）

6.2.3 寄存器银行（读反汇编必认）

编号 别名 角色（驱动/启动常见）
R0–R3 — 参数 / 返回值（AAPCS）；临时
R4–R11 — 被调者常需保存
R12 IP 过程内临时（约定相关）
R13 SP 栈指针（向下长）
R14 LR 返回地址（BL 写入）
R15 PC 程序计数器
— CPSR 状态：NZCV、模式位等

异常时还有 banked 寄存器 / SPSR（→ 6.6），读 IRQ/SVC 入口时会碰到。

6.2.4 对嵌入式 Linux

你在看 认什么
head.S / 异常入口 谁被压栈、LR/SPSR 怎么存
内联汇编 约束里哪些是输入输出寄存器
oops 里的 PC/LR 崩溃点与返回链

对照：x86 见 6.8；AArch64（X0–X30、SP、PC）→ 19-ARM64。

编程

Link Target: Ch5 ALU Flags · CSAPP §3.x · 驱动反汇编
档位: 精读

状态

  • [x] 已读（口述巩固）
  • [x] 已写要点

笔记

高级语言结构如何落到 ARM 汇编（AArch32）。

6.3.1 数据处理指令

类 例子
算术/逻辑 ADD SUB AND ORR EOR …
移位 LSL LSR ASR ROR（可与数据处理同条）
乘法 MUL 等

与 Ch5 ALU/移位器硬件对应。

6.3.2 条件标志（NZCV）

CPSR 中：

位 含义 软件常见
N Negative 有符号比较
Z Zero beq / 判零
C Carry 无符号进位/借位
V oVerflow 有符号溢出

许多指令带 S 后缀才更新标志（ADDS、CMP=SUBS 不写回）。
条件分支 / 条件执行看这些位。

6.3.3–6.3.5 分支 · 循环 · 调用入口

高级语言 汇编手段
if / else 比较 + BEQ/BNE… 或条件执行
while / for 比较 + 回跳
调用 BL（LR←返回地址）
返回 BX LR / MOV PC, LR 等

6.3.6 存储器：LDR / STR

指令 作用
LDR Mem → Reg
STR Reg → Mem

寻址：[Rn, #imm]、[Rn, Rm]、预/后索引写回等。
ARM = load/store：算术一般不直接吃内存操作数（对照 x86）。

6.3.7 函数调用（AAPCS 直觉）

约定
参数 R0–R3，更多走栈
返回值 R0（宽返回再扩）
返回地址 LR
栈 SP 向下；对齐要求看版本

被调者保存 vs 调用者保存：跨调用必须活着的寄存器 → 进函数压栈；临时寄存器调用方自己保。

6.3.8 对驱动 / 内核

场景
读 oops 反汇编 认 R0–R3 参数、LR 返回链、SP 栈帧
MMIO C 里 readl/writel 或 volatile 指针 → 编译器生成 LDR/STR；禁止被优化掉
内联汇编 约束列出破坏的寄存器，避免与编译器打架

细节以 AAPCS / Procedure Call Standard 为准。

6.4

机器语言

Core Concept: 定长 32 位；三大格式；寻址；存储程序 · Fetch
Link Target: Ch7 取指/译码 · objdump · 6.2
档位: 精读

状态

  • [x] 已读（口述巩固）
  • [x] 已写要点
  • [x] 字段直觉 + 驱动侧用途

笔记

汇编 → 0/1，电路才能执行。经典 ARM：固定 32 位指令字（Thumb/Thumb-2 见 6.7）。

6.4.1–6.4.3 三大指令类

字段大致：cond、op、funct、Rn、Rd、立即/偏移等（位域以书图为准，不必默背每一位）。

大类 例子 编码要表达
数据处理 ADD、AND 操作、寄存器、立即/移位
存储器 LDR、STR 基址、偏移、升降址、写回
分支 B、BL 相对偏移、是否写 LR

cond： 几乎每条可带条件 → 条件执行（少分支；现代更多用条件分支）。

6.4.4 寻址直觉

模式 用途
寄存器 操作数在 Rn/Rm
立即 小数在指令里
基址±偏移 LDR/STR 算有效地址
PC 相对 分支、文字池 LDR

6.4.5 存储程序

Fetch（按 PC 取 32 位字）→ Decode（拆字段）→ Execute …

同一套硬件跑不同二进制 → 通用计算机。Ch7 把环路变成数据通路。

对嵌入式 Linux

用途
读 objdump -d 对照助记符与地址，查启动/驱动汇编
不必手写编码 知道「定长 32、三大类、译码吃字段」即可
安全/漏洞直觉 可执行页、指令与数据同存 → W^X、PXN 等保护（接 8.4）

练习（可选）：任取一条 e3a00000 类机器码，对照书图拆 cond/op/Rd，建立「位域→助记符」一次即可。

笔记

6.6.1 加载文字（Literal）

32 位指令塞不下任意大立即数 → 文字池：附近内存放常数，PC 相对 LDR 装入寄存器。
反汇编里常见 ldr r0, [pc, #xx] 指向池中立即数/地址。

6.6.2 NOP

空操作：对齐、延时占位、流水线填充。优化时可能被去掉；调试用「插 NOP」要小心。

6.6.3 异常与中断（嵌入式重点）

概念 直觉
异常 Exception 迫使 CPU 离开当前流：复位、未定义指令、SVC、数据/预取中止、IRQ、FIQ…
中断 外设/定时器等异步请求（常归入异常一类处理）
模式 / 权限 User vs 特权；不同异常可进不同模式，部分寄存器 banked
向量表 入口地址表：哪类异常 → 跳哪段入口代码
SPSR 进入异常前备份的程序状态；返回时恢复（和 LR_mode 等一起）

简化时间线：

正在跑用户/内核代码
  → 异常发生（IRQ / 缺页 / SVC…）
  → 硬件切模式、存 SPSR/LR，PC ← 向量入口
  → 汇编入口保存通用寄存器
  → C 处理（Linux：IRQ handler / do_page_fault / syscall）
  → 恢复上下文，从 SPSR 返回

对嵌入式 Linux

你读的东西 对应本节
entry-armv.S / entry.S 向量入口、压栈、调 C
request_irq 最终挂到某 IRQ 线 → 控制器（如 GIC）→ CPU
系统调用 SVC / svc → 内核入口
缺页 数据中止 → do_page_fault（接 VM）
启动早期 复位向量、关 MMU 前的物理地址跑法
❌ ✅
在硬中断里随便睡眠、拿互斥锁 原子上下文规则
忽略「返回要用 SPSR」 入口汇编配对保存/恢复

一句话： 向量表决定「谁来了去哪」；SPSR+入口汇编决定「怎么进怎么出」——驱动与启动汇编都围着它转。

（AArch64 用 Exception Level EL0–EL3、VBAR_ELx 等，名词不同、故事同构 → 19-ARM64。）

经典 ARM 之上的重要扩展（扫过建立地图）：

扩展 目的

另一个视角：x86 体系结构

Link Target: HFT x86 路径 · hft_x86_timing · ↔ CSAPP §3.3 数据格式 档位: 精读 · HFT

笔记

把 ARM（RISC）和 Intel 主导的 x86（CISC）并排看差异。

维度 ARM（本章主线） x86
哲学 精简、规整 复杂、历史堆积
通用寄存器 多（16×32，AArch32） 更少 GPRs（经典可见集合）
操作数形态 三操作数常见；load/store 双操作数常见；算术可直接访存
指令长度 定长 32 位（经典 ARM） 变长约 1–15 字节
兼容 相对干净演进 强后向兼容 → ISA 越积越杂，仍主导 PC/服务器

为什么对你重要

方向 带走
HFT 交易侧几乎全是 x86；变长解码、复杂寻址、微码路径影响延迟直觉——细节在 CSAPP Ch3
嵌入式 板子多为 ARM；用本节反向理解「为什么启动代码和 x86 反汇编长得不像」
学习 同一「体系结构」抽象，两种合同；Ch7 用 ARM 教微结构更干净，再映射回 x86

市场现实：技术上「乱」不等于失败——兼容性与生态往往压过 ISA 优雅。
