## 2.1 内核（Kernel）

1. OS 核心：管 CPU、内存、磁盘、网卡、外设。  
2. Linux = **宏内核（monolithic）** — 驱动可编进内核，或动态加载 `.ko`。  
   - 对比：macOS XNU 混合内核；QNX 微内核。  
3. 运行在 **内核态**，拥有完整硬件权限。

---

## 2.2 用户态 / 内核态 / 系统调用

| 空间 | 谁 | 权限 |
|------|-----|------|
| **用户空间 User Space** | 普通应用 | 受限；不能直接碰硬件 |
| **内核空间 Kernel Space** | 内核代码 | 全权 |

**系统调用**：用户程序进入内核的 **唯一正规入口**。  
例：`open` / `read` / `write` / `mmap` / `fork`

```
用户程序 → glibc 封装 → CPU 陷入（syscall 等）
         → 内核态执行服务 → 返回用户态
```

> **面试 / HFT 高频：** 系统调用有 **上下文切换开销**；低延迟路径要 **尽量少 syscall**。

### glibc 角色

| | |
|--|--|
| 作用 | 封装原始 syscall，提供友好接口 |
| 注意 | 有的函数内部会 **多次** syscall；少数纯用户态（不进内核） |

→ [LKD §5.1 libc ≠ syscall](../../04-Linux-Kernel-Development/00_Book_3rd_Notes/chapter-05-system-calls/notes/section-5.1-与内核通信.md)

## 2.3 进程（Process）

**进程 = 正在运行的程序实例**，带着：代码/数据/堆/栈、fd 表、PID、映射、信号掩码、权限等。

| 要点 | |
|------|--|
| **独立虚拟地址空间** | 进程 A 不能直接碰进程 B；内核隔离（CSAPP VM） |
| 创建 | 基础接口 `fork()` |
| **线程** | 同进程多执行流；**共享**地址空间；各有独立栈 |

→ LKD：[task_struct / fd](../../04-Linux-Kernel-Development/00_Book_3rd_Notes/chapter-03-process-management/notes/section-3.8-身份PID与资源FD.md)

---

## 2.4 文件与文件描述符（FD）

**一切皆文件**：磁盘文件、管道、socket、串口、设备节点 → 统一用 `read`/`write` 等。

| | |
|--|--|
| **fd** | 进程内 **非负整数**；内核打开文件对象的索引 |
| 默认 | **0** stdin · **1** stdout · **2** stderr |
| `fork` | fd **默认继承**（共享/`dup` 语义见 LKD §3.8） |

---

## 2.5 文件系统与 inode

| | |
|--|--|
| 文件名 | ≠ 文件本体 |
| **inode** | 元数据：大小、权限、所有者、块指针、时间戳；**不含文件名** |
| **硬链接** | 多个名字 → **同一 inode** |
| **软链接（symlink）** | 存另一路径字符串 |

---

## 2.6 权限模型

| | |
|--|--|
| 文件权限 | user / group / other × **r w x** |
| **RUID/RGID** | 真实身份：谁启动 |
| **EUID/EGID** | 有效身份：做权限检查时用；**setuid** 程序原理在此 |

---

## 2.7 IPC（进程间通信）

进程内存隔离 → 靠内核机制交换数据。  
后续章：管道、FIFO、共享内存、消息队列、信号量、Socket。

---

## 2.8 信号（Signal）

内核或其他进程发给目标进程的 **异步通知**。  
例：`SIGINT`(Ctrl+C)、`SIGKILL`、`SIGSEGV`。

| 特点 | 异步；需小心处理 |
|------|------------------|
| HFT | 常屏蔽/规避，防交易路径被意外打断 |

---

## 2.9 时间（两类时钟）

| 类型 | 含义 | 注意 |
|------|------|------|
| **墙上时钟 real time** | 日历时间；可被 NTP 改 | **会跳变**；**不适合**测耗时 |
| **CPU 时间** | 进程占用 CPU 时长 | 性能统计用 |

---

## 双线提炼

### 嵌入式 Linux 应用

- fd、权限、进程继承、`/dev` 设备文件 = 应用与驱动交互基础  
- 用户态 **不能** 绕过 syscall 直接操作硬件  

### HFT 低延迟

1. 少 syscall、少线程切换（上下文切换成本）  
2. 测耗时：**别用墙上时钟**  
3. 信号要管控，避免异步打断热路径  
4. 理解 VA 隔离 → 后续 `mlock` 防换页  

---

## 自测（答案）

1. **为何进程不能直接访问对方内存？靠什么隔离？**  
   各有独立 **虚拟地址空间**；由 **内核 + MMU/页表** 隔离保护。

2. **系统调用为何有性能开销？**  
   特权级切换、保存/恢复上下文、进内核执行路径 — **上下文切换** 成本。

3. **stdin/stdout/stderr 编号？**  
   **0 / 1 / 2**。

4. **硬链接 vs 软链接？**  
   硬链接：多名字 → **同一 inode**；软链接：存 **路径字符串**（可指不存在目标）。

5. **测代码耗时用哪种时钟？**  
   用 **单调/CPU 相关计时**（如 `CLOCK_MONOTONIC` 一类）；**不要**用会跳变的墙上日历时间当唯一依据。书中「CPU 时间」适合看占核；测墙钟耗时用 **单调时钟** 更稳妥。
