# AArch64 名字从哪来？为什么不笼统叫「ARM」

> FAQ · 对齐《ARM64体系结构编程与实践》· [README](./README.md)  
> 对照：[arm32-asm · Cortex-A 边界](../arm32-asm/CORTEX-A-SCOPE.md)（Hohl/Hinds = M 核实操，不是本书）

---

## 结论

**ARMv8-A** 为兼容旧软件，规定两种**执行状态**；64 位那一套官方叫 **AArch64**，其指令集叫 **A64**。  
笼统说「ARM」会和公司名、老 32 位 ARM、Thumb 搅在一起，所以文档用精确名；口语常说 **ARM64**（≈ AArch64）。

---

## 1. ARMv8 里的两套状态

| 名字 | 是什么 |
|------|--------|
| **ARMv8-A / ARMv9-A** | **架构规范版本**（整本「说明书」） |
| **AArch64** | **64 位执行状态**（64 位地址空间 / 寄存器视图） |
| **A64** | 在 AArch64 下用的 **汇编指令集** |
| **AArch32** | **32 位执行状态**（跑老 32 位世界） |
| **A32 / T32** | AArch32 下的老 ARM / Thumb-2 指令 |

记法：

> **ARMv8 ≈ 大规范 = AArch64 环境 +（可选）AArch32 环境**

---

## 2. 为什么不能只说「ARM」

「ARM」太泛，可能指：

1. ARM 公司  
2. 老 32 位 ARM 指令（如 ARMv7-A、Pi4 的 32 位系统）  
3. 新的 64 位模式  

行业写法：

- 64 位：**AArch64** + 指令 **A64**  
- 32 位（在 v8 芯片上跑 32 位）：**AArch32**  

### 树莓派

| 板 | 典型 |
|----|------|
| **Pi 4** | 可 AArch64（64 位 OS / A64）或 AArch32（32 位 OS / A32·T32） |
| **Pi 5**（Cortex-A76，ARMv**9**-A） | **默认只有 AArch64**；**无 AArch32**，不能跑老 32 位 ARM 用户程序那条路径 |

---

## 3. 名词对照（勿混）

| 名词 | 含义 |
|------|------|
| ARMv8-A / ARMv9-A | 架构规范版本 |
| AArch64 | 64 位运行状态 |
| A64 | AArch64 下的指令集 |
| AArch32 | 32 位运行状态（v8 引入；部分 v9 实现已去掉） |
| A32 | 经典 32 位 ARM 指令 |
| T32 | Thumb-2 |
| **ARM64** | **俗称** ≈ AArch64（内核树 `arch/arm64`） |

| 说法 | 性质 |
|------|------|
| 文档严谨 | **AArch64** / **A64** |
| 口头 / 目录名 | arm64、ARM64 |

---

## 4. 对你学习的意义

1. 《ARM64体系结构编程与实践》= **全程 AArch64 / A64**，对齐 **Pi5**  
2. [arm32-asm](../arm32-asm/)（Hohl/Hinds：v4T / v7-M）语法 **不能直接搬** 到 Pi5  
3. Linux 源码：  
   - `arch/arm` → 偏 AArch32 / 老 32 位 ARM  
   - `arch/arm64` → AArch64  

---

## 一句话

ARMv8 用 **AArch64** 命名 64 位执行状态、用 **A64** 命名其指令，避免和几十年 32 位「ARM」混淆；大家口语叫 ARM64。  
**树莓派 5 = AArch64，只认 A64。**
