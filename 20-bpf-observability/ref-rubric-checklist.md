# Rubric 评审校验清单 — 19 SysPerf × 20 BPF 联动

> 性能分析工作评审用：一次排障 / 一次优化 / 一份性能报告，按本清单逐项打勾。
> 标记说明：🔴 必须通过 · 🟡 建议通过 · ⚪ 加分项

---

## A. 方法论合规（19 Ch1–2）

| # | 级别 | 检查项 | 通过标准 |
|---|------|--------|----------|
| A1 | 🔴 | 是否先建立了 **基线** | 有 incident 前正常态的延迟/吞吐/CPU 数值 |
| A2 | 🔴 | 是否用了 **USE 方法** 定位资源饱和 | CPU/内存/磁盘/网络 至少覆盖 3 项 |
| A3 | 🔴 | 是否区分了 **利用率 vs 饱和度** | 不只看 %CPU，还看了运行队列长度 / runqlat |
| A4 | 🟡 | 是否做了 **60 秒检查清单** | vmstat/iostat/mpstat/sar 至少跑过一轮 |
| A5 | 🟡 | 是否有 **假设→验证** 闭环 | 记录了至少 1 个可证伪的假设及验证结果 |
| A6 | ⚪ | 是否用了 **排队论** 解释拐点 | 给出 M/M/1 或 USL 拐点分析 |

## B. 工具选型合理性（19 Ch4 + 20 Ch3–5）

| # | 级别 | 检查项 | 通过标准 |
|---|------|--------|----------|
| B1 | 🔴 | 传统工具 → BPF 的 **分层递进** | 先传统工具看现象，再 BPF 钻取根因 |
| B2 | 🔴 | BPF 工具 **限时运行** | 每次采集 ≤ 60s，未长期挂载 |
| B3 | 🔴 | kprobe vs tracepoint **选择正确** | 优先 tracepoint；用 kprobe 时注明内核版本依赖 |
| B4 | 🔴 | 高频探针 **有限流 / 过滤** | 限定 PID/CPU/comm，未全量采集 |
| B5 | 🟡 | profile 采样率 **合理** | 99Hz 或 49Hz（避开 100Hz 谐波） |
| B6 | 🟡 | off-CPU 分析 **覆盖了睡眠态** | CPU 不高时用了 offcputime 而非只看 on-CPU |
| B7 | ⚪ | 使用了 **USDT** 而非纯 uprobe | 有 USDT 点时优先用了它 |

## C. BPF 安全与边界约束（20 Ch2 + Ch18）

| # | 级别 | 检查项 | 通过标准 |
|---|------|--------|----------|
| C1 | 🔴 | 热路径核 **未挂重探针** | 交易核心 CPU 未挂 kprobe/tracepoint |
| C2 | 🔴 | 生产环境 **有回滚方案** | 记录了如何停止采集、清理 BPF 程序 |
| C3 | 🔴 | 无 **uretprobe 高频** 陷阱 | Go 等语言未用 uretprobe（会改二进制） |
| C4 | 🔴 | bpftrace 脚本 **无无限循环** | 无 `while(1)`；有循环的标注了 verifier 限制 |
| C5 | 🔴 | BPF map **无无限增长** | 用了 `clear()` / 有退出清理；或限定了采集时长 |
| C6 | 🟡 | 二进制 **带帧指针** | 编译用了 `-fno-omit-frame-pointer` |
| C7 | 🟡 | debuginfo **可获取** | 能解出用户态符号名，非 `[unknown]` |
| C8 | ⚪ | cgroup-BPF **按容器隔离** | 多租户场景下按 cgroup 过滤 |

## D. 输出工件质量（20 Ch3）

| # | 级别 | 检查项 | 通过标准 |
|---|------|--------|----------|
| D1 | 🔴 | 延迟数据 **是直方图而非平均值** | 输出了 `hist()` 分布，能看到长尾 |
| D2 | 🔴 | 给出了 **百分位** 而非只有 P50 | 至少 P50/P90/P99，HFT 场景有 P99.9 |
| D3 | 🔴 | 栈回溯 **能解符号** | 非大量 `[unknown]`；内核栈完整 |
| D4 | 🟡 | 有 **时间对齐** | BPF 输出与业务 histogram 时间窗对齐 |
| D5 | 🟡 | 有 **对照组** | 优化前/后，或问题机/健康机对比 |
| D6 | ⚪ | 有 **火焰图** | on-CPU 或 off-CPU 栈做了火焰图可视化 |

## E. HFT 专项（19 Ch6 + 20 Ch6/10）

| # | 级别 | 检查项 | 通过标准 |
|---|------|--------|----------|
| E1 | 🔴 | 绑核核 **未受邻居干扰** | 检查了 `runqlat -P <core>` 和 `/proc/interrupts` 中断分布 |
| E2 | 🔴 | 调度延迟 **在预算内** | runqlat P99 < 业务延迟预算的 10% |
| E3 | 🔴 | 网络重传 **已排查** | tcpretrans 跑过；无 SYN drop / backlog 溢出 |
| E4 | 🟡 | NUMA **跨节点访问已排除** | numastat 确认热路径内存在本地 NUMA |
| E5 | 🟡 | 内存 **无 cgroup 节流** | 确认无 memory stall（PSI / perf stat） |
| E6 | 🟡 | 页错误 **major fault = 0** | 热路径启动后无 major page fault |
| E7 | ⚪ | 有 **微基准** 对照 | 用 custom benchmark 复现并量化了改善 |

## F. 文档与可复现

| # | 级别 | 检查项 | 通过标准 |
|---|------|--------|----------|
| F1 | 🔴 | 记录了 **内核版本** | `uname -r` 和 BPF 工具版本 |
| F2 | 🔴 | 记录了 **复现命令** | 他人可凭文档复现排查过程 |
| F3 | 🟡 | 给出了 **根因结论** | 不是"工具输出"，而是"为什么慢"的因果链 |
| F4 | 🟡 | 有 **后续 action** | 记录了修复方案或监控加固计划 |

---

## 评分用法

- 🔴 不通过 → **阻断发布**，必须补做
- 🟡 不通过 → **建议补做**，可在下一轮迭代
- ⚪ 不通过 → 不影响，但做到加分

> 经验阈值：🔴 全通过 + 🟡 通过率 ≥ 70% → 可交付。
