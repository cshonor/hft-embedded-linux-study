# Ch 14 §3 本书的核心目的

> **Understanding the Linux Virtual Memory Manager** · Mel Gorman · **跳过 ⚪** · 收尾章

---

## 本节讲什么

原书 §3 讲 Mel Gorman 的写作动机：**弥合「内存管理理论」与「Linux VM 真实代码」之间的鸿沟**。本书前半（Ch1–14）讲理论，后半（附录 A–M Code Commentary）做源码走读，且尽量**架构无关**地讲清机制。

本节把这条「弥合鸿沟」的意图，放到**现代资料生态**里重新定位，并说明本仓库笔记在其中的位置。

---

## 1. 那条鸿沟还在，而且更宽了

```
   内存管理理论                     Linux VM 真实代码
  （教科书/Belady/                 （v6.6 的 mm/*.c，
    工作集模型）        ←鸿沟→       100+ 源文件、机制层层叠加）
```

原书（2004）弥合的鸿沟，到 2026 年**只增不减**：

| 鸿沟的表现 | 具体例子 |
|------------|----------|
| 理论教材停在上世纪 | 讲 LRU，但不讲 active/inactive 双链表（Ch10）、multi-gen LRU |
| 内核代码演进飞快 | v6.6 已删 HIGHMEM（Ch9）、bootmem→memblock（Ch5）、`rw_swap_page` 拆两入口（Ch11） |
| 文档碎片化 | `Documentation/mm/`、`admin-guide/`、LWN 文章分散各处，无统一入口 |

**本书的价值**在于它示范了一种**读内核的方法论**（理论章节 ↔ 代码注释章节一一对应），这套方法论到今天依然有效——**只是代码本身得重新核对了**（这正是本仓库「每章下沉到 v6.6 源码 + 行号」的由来）。

| 资料 | 定位 | 与本书关系 |

**本仓库笔记的定位**：以本书为骨架，用 **v6.6 源码 + 行号** 逐章校准，并**额外加一条 HFT/嵌入式 关联线**——这是原书没有、但对振鹏最有价值的一维。

## 3. 本书的局限（诚实评估）

「尽量架构无关」是本书的优点，**也是它的代价**：

| 局限 | 后果 |
|------|------|
| 写于 2.6 早期 | 大量机制已删除/重写（HIGHMEM、bootmem、`badness()` 算法、`PF_MEMDIE`） |
| 架构无关 | 不讲 x86_64 的 5 级页表、PCID、TSO 等**具体架构优化** |
| 无 HFT 视角 | 不关心「回收/换出/THP 对低延迟意味着什么」 |

**所以**：把本书当**方法论**读（它教你「理论怎么落到代码」），别当**事实源**读（事实以 v6.6 源码为准）。本仓库每章开头标注「源码核验：Linux v6.6」正是为了守住这条边界。

## 4. HFT / 嵌入式关联

| 维度 | 落地 |
|------|------|
| 读法 | 理论章（Ch1–14）建立因果链，附录 A–M 验证具体实现，**两者必须对读** |
| 版本意识 | 任何「原书说的」都要过一遍 v6.6 核对，别把 2004 的结论当 2026 的事实 |
| 输出 | 每篇笔记的 HFT 关联，是把「机制」翻译成「对低延迟意味着什么」——这是本书没做、但 HFT 工程最需要的一步 |
