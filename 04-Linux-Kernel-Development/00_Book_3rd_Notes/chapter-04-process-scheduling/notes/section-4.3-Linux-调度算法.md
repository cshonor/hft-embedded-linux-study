## ③ Linux 调度算法 · CFS

**CFS = Completely Fair Scheduler，完全公平调度器**  
Linux **2.6.23** 起，默认调度 **普通分时进程**（`SCHED_OTHER` / `SCHED_NORMAL`）。淘汰了古老的 **O(1)** 调度器。

---

### 一句话理念（背诵）

老式调度：给每个进程 **固定时间片** 轮流跑。  
CFS：假想一个 **完美 CPU**，所有就绪进程 **按权重瓜分 CPU 时间**。权重越高，分到的物理 CPU 时间越多。

例子：A 权重 1024，B 权重 512 → 总 1536 → A 约 **2/3**，B 约 **1/3**。

CFS 靠 **`vruntime` 标准化运行时间**，红黑树持续挑 **虚拟时间最小** 的任务跑，用权重做比例公平。

---

### 核心对象逐个拆

| 概念 | 是什么 |
|------|--------|
| **`sched_entity`** | 调度实体。嵌在 `task_struct` 里。CFS **不直接操作** `task_struct`，统一操作 `sched_entity`（进程/线程/组调度任务都可挂实体） |
| **`cfs_rq`** | **CFS RunQueue** — **每个 CPU 一条** 独立 CFS 就绪队列，放该 CPU 上可运行的普通调度实体 |
| **`vruntime`** | **虚拟运行时间**（重中之重）— 实际运行时间按权重标准化后的记账 |
| **红黑树** | `cfs_rq` 里组织所有就绪 `sched_entity`；**排序 key = vruntime 升序**；最左 = vruntime 最小 |

#### `vruntime` 公式（先记住）

```
vruntime ≈ 实际运行时间 × (1024 / 权重)
```

| | |
|--|--|
| 默认权重 | **1024**（nice = 0） |
| nice 越小 | 权重 **越高**（nice −20 最高；+19 最低） |

规则：

| 权重 | 同样物理跑一段时间 | 效果 |
|------|---------------------|------|
| **高**（nice 低） | `vruntime` 涨得 **慢** | 更能继续占 CPU |
| **低**（nice 高） | `vruntime` 涨得 **快** | 很快「虚拟时间领先」→ 更易让出 |

直观：低权重跑一小会儿虚拟时间就飙升，让出 CPU；高权重可跑更久，虚拟时间增加缓慢。

```
权重高（nice 低）──► 同样物理时间，vruntime 涨得慢 ──► 更常被选中
权重低（nice 高）──► vruntime 涨得快 ──► 更少被选中
```

---

### 选谁跑（调度选择逻辑）

1. 每次调度：拿红黑树 **最左节点**（`vruntime` 最小）投入运行；
2. 任务运行时：持续累加它的 `vruntime`；
3. 时机到来（目标延迟窗口 / 被抢占等）：进程放回红黑树；
4. 再挑新的最小 `vruntime` 任务。

长期被亏待（相对欠账、`vruntime` 偏小）的进程，会被优先调度 — 天然「公平」。

| 规则 | 实现 |
|------|------|
| **选 `vruntime` 最小者** | 最「欠账」、最该分到 CPU |
| 数据结构 | **红黑树** |
| 下一个任务 | 树 **最左节点** |
| 复杂度 | 选下一个 **O(log n)**（相对旧 O(1) 调度器） |

```
        红黑树（按 vruntime）
              ┌───┐
           ┌──┤   ├──┐
           │  └───┘  │
    最左 ◄─┤  最小 vruntime  ──► 下次运行
           └─────────┘
```

红黑树为何不用链表/堆、内核 `rb_node` 内嵌 + `container_of`、`rb_first` 语义 → **[Ch6 §6.5](../../chapter-06-kernel-data-structures/notes/section-6.5-二叉树.md)**

### 必须配套理解（笔记外补齐）

#### 1. 调度周期（`sched_latency` 一类目标延迟）

CFS 设定一个 **目标延迟窗口**：窗口内所有就绪进程都至少轮到一次。  
就绪进程越多，每个人分到的时间片越短。  
→ **没有** 每人固定绝对毫秒片；用目标延迟 / 粒度控制「多久重新挑一次」，记账靠 `vruntime`。

可在 `/proc/sys/kernel/sched_*` 看到现代调参项（名随版本变）— 先懂 **`vruntime` 语义**，再碰数字。

#### 2. 唤醒抢占

新进程唤醒时，若其 `vruntime` 比当前运行任务 **小足够多**，可 **直接抢占** 当前进程 — 适合交互（桌面、shell）流畅响应。  
细节见 [§4.5](./section-4.5-抢占与上下文切换.md)。

#### 3. 不属于 CFS 的：实时类

| 类 | 策略 | 队列 |
|----|------|------|
| **CFS** | `SCHED_OTHER`（及 BATCH 等变体） | `cfs_rq` + 红黑树 |
| **RT** | `SCHED_FIFO` / `SCHED_RR` | **独立** 实时队列，**压过全部 CFS** |

```
有可运行 RT 任务？──是──► RT 类接管 CPU（CFS 靠边）
        │否
        ▼
      CFS 选最小 vruntime
```

→ [§4.2 策略](./section-4.2-调度策略.md) · [§4.6 RT](./section-4.6-实时调度策略.md)

### 与「时间片」的关系

| 旧直觉 | CFS |
|--------|-----|
| 每人固定 N ms | **没有** 固定绝对片长 |
| 「片用完再切」 | 目标延迟 / 粒度 + `vruntime` 记账 |

### 组调度 / cgroup（知道存在即可）

| 概念 | 用途 |
|------|------|
| **组调度** | 容器/服务按组分 CPU 份额 |
| **HFT 含义** | 交易进程常 **绑独立核**，少依赖 cgroup 份额精细调 |

**HFT：** 热路径线程若进 RT，**CFS 公平性不再保护它们**；抖动源往往变成 **中断、softirq、同核争用、锁**，而不是 nice。
