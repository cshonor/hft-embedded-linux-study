## ③ Linux 调度算法 · CFS

**理念：** 模拟 **理想、完美的多任务 CPU** — 每个可运行任务按 **权重比例** 分到 CPU 时间，而不是固定「每人一片」。

#### 核心对象

| 字段/概念 | 作用 |
|-----------|------|
| **`sched_entity`** | CFS 调度实体（进程/线程在运行队列中的表示） |
| **`cfs_rq`** | 每 CPU 的 CFS 运行队列 |
| **`vruntime`** | **虚拟运行时间** — 实际运行时间按权重 **标准化** 后的记账 |
| **红黑树** | 按 `vruntime` 排序所有可运行实体 |

```
权重高（nice 低）──► 同样物理运行时间，vruntime 涨得慢 ──► 更常被选中
权重低（nice 高）──► vruntime 涨得快 ──► 更少被选中
```

#### 选谁运行

| 规则 | 实现 |
|------|------|
| **选 `vruntime` 最小者** | 最「欠账」、最该分到 CPU |
| 数据结构 | **红黑树** |
| 下一个任务 | 树 **最左节点**（最小 key） |
| 复杂度 | 选下一个 **O(log n)**（相对 O(1) 调度器） |

```
        红黑树（按 vruntime）
              ┌───┐
           ┌──┤   ├──┐
           │  └───┘  │
    最左 ◄─┤  最小 vruntime  ──► 下次运行
           └─────────┘
```

#### 与「时间片」的关系

| 旧直觉 | CFS |
|--------|-----|
| 每人固定 N ms | **没有** 固定绝对片长 |
| 「片用完再切」 | 用 **目标延迟 / 粒度** 等参数控制 **多久重新挑一次**；记账靠 `vruntime` |

可在 `/proc/sys/kernel/sched_*` 看到现代调参项（具体名随版本变）— 先理解 **`vruntime` 语义**，再碰数字。

#### 组调度 / cgroup（知道存在即可）

| 概念 | 用途 |
|------|------|
| **组调度** | 容器/服务按组分 CPU 份额 |
| **HFT 含义** | 交易进程常 **绑独立核**，少依赖 cgroup 份额精细调 |

#### 和 RT 的边界

```
有可运行 RT 任务？──是──► RT 类接管 CPU（CFS 靠边）
        │否
        ▼
      CFS 选最小 vruntime
```

**HFT：** 热路径线程若进 RT，**CFS 公平性不再保护它们**；抖动源往往变成 **中断、softirq、同核争用、锁**，而不是 nice。
