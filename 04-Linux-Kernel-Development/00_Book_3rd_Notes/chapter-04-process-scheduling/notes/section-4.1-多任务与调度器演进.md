## ① 多任务与调度器演进

Linux = **抢占式多任务（Preemptive Multitasking）**：调度器可在任意安全点 **强制** 换下当前任务，不必等它自愿 `yield`。

| 概念 | 含义 |
|------|------|
| **调度器（scheduler）** | 决定 **哪个任务运行、何时、多久** |
| **抢占（preemption）** | 强制停掉当前任务，换另一个上 CPU |
| **运行队列（runqueue）** | 每 CPU（或共享）上「可运行」任务的集合 |
| **时间片 / 份额** | 旧调度器用固定片；CFS 用 **虚拟运行时间份额** |

#### 为何必须抢占

| 若不抢占 | 后果 |
|----------|------|
| 计算型任务死循环 | 其他任务（含网络收包、日志）饿死 |
| 交互/低延迟任务 | 只能「等别人做完」→ 尾延迟爆炸 |

**协作式多任务**（任务自己 `schedule()`）只适合玩具 OS；生产 Linux 必须抢占。

#### 历史脉络

```
早期简单调度器（线性扫描 / 简单轮询）
    │
    ▼
O(1) 调度器（2.5 / 2.6 前期）
    │  每 CPU 优先级数组 · 选下一个 O(1)
    │  大机扩展性好；交互与「公平感」常被诟病
    │
    ▼
CFS（2.6.23+，Completely Fair Scheduler）
    │  默认公平调度 · 按权重分 CPU 比例
    │
    ▼
现代：CFS + 独立 RT 类 +（可选）Deadline / 带宽控制
```

| 调度器 | 选下一个 | 强项 | 弱项 |
|--------|----------|------|------|
| **O(1)** | 优先级位图 · **O(1)** | 海量任务、服务器吞吐 | 交互延迟、公平性争议 |
| **CFS** | 红黑树最左 · **O(log n)** | 交互响应、公平比例 | 极端 RT 仍靠独立 RT 类 |

#### 和「你看到的」工具对应

| 用户态现象 | 内核侧 |
|------------|--------|
| `top`/`htop` 里切换、运行态 | 调度器在跑谁 |
| `perf sched`、延迟尖刺 | 抢占点、唤醒延迟、锁持有 |
| `chrt` / `nice` | 进不同调度类 / 改权重 |

**HFT：** 不要指望「调一下 nice」解决微秒级抖动；主路径通常是 **隔离核 + RT/FIFO + 关无关中断**，CFS 只负责「其余世界别饿死」。
