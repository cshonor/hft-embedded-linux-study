# U-Boot · BIOS · UEFI：能类比，不能等同

> FAQ · 锚定 Primer Ch2 §2.1.2 BIOS vs Bootloader  
> 章摘要：[notes.md](./notes.md) · 深挖 Boot → [Ch7](../chapter-07-bootloaders/notes.md)

---

## 1. 核心结论

| 说法 | 对不对 |
|------|--------|
| U-Boot 与 **UEFI** 都是「上电固件 → 交权给内核」 | 功能**同源可类比** |
| U-Boot **等于** UEFI | **否** — 定位、标准、运行时、体积、生态都不同 |
| BIOS 是老 x86 固件，UEFI 是其现代化替代 | **是** |
| 书中「BIOS ↔ Bootloader」今天改读「**UEFI ↔ U-Boot**」 | **逻辑仍成立** |

---

## 2. 三者共性（都是引导固件一类）

1. 上电极早执行：初始化 CPU / 内存 / 关键外设  
2. 常有命令行、存储读写、网络拉镜像等能力（具体强弱差很多）  
3. 最终加载 OS 内核并移交控制权  
4. 向内核递硬件描述：UEFI 侧常见 **ACPI**；嵌入式 U-Boot 侧常见 **Device Tree**

---

## 3. 关键区别

### （1）适用硬件

| 固件 | 典型平台 |
|------|----------|
| **传统 BIOS** | 老旧 x86 PC（已淘汰叙事） |
| **UEFI** | 现代 PC/服务器；部分 ARM/RISC-V **通用计算**板 |
| **U-Boot** | 嵌入式 SoC（ARM/MIPS/Power…）：路由、工控、车载、开发板 |

### （2）标准化

- **UEFI**：统一规范（驱动模型、Runtime、Secure Boot、GPT 等）  
- **U-Boot**：开源实现，**无**等同强制国际规范；各 SoC 厂移植，命令与内存布局差异大  

### （3）内核起来之后还在不在

| | 内核启动后 |
|--|------------|
| **UEFI** | 可保留 **Runtime Services**（运行中仍可能调固件接口） |
| **U-Boot** | 交权后固件资源**通常丢弃**；要再进 U-Boot 多半只能复位 — 与书中对 BIOS/Bootloader 的对比一致 |
| **BIOS** | 亦非「像 UEFI Runtime 那样」长期给 OS 当服务总线 |

### （4）体积与生态

| | 体量 | 嵌入式相关 |
|--|------|------------|
| UEFI | 常很大（可达百 MB 级叙事），可有图形、安全启动、分区管理 | 对小 Flash 不友好 |
| U-Boot | 可裁到很小（KB～MB 级视配置） | 原生贴近 NAND/JFFS2/UBIFS、**TFTP/NFS** 开发流 |

### （5）硬件描述

- UEFI 世界：ACPI 表为主  
- U-Boot + 嵌入式 Linux：device tree（DTS/DTB）  
- **DT ≠ UEFI**（DT 是图纸，U-Boot 是工具箱）— [7.0 FAQ](../chapter-07-bootloaders/7.0-device-tree-vs-uefi.md) · [12 驱动·DT](../../../12-device-drivers-dt/)

## 4. 书为何拿 BIOS 比 Bootloader（2010 语境）

当年 PC 主流叙事仍是 BIOS：

1. PC 有相对标准的固件，开发者很少从零写 BIOS  
2. 自定义嵌入式板 **没有** 统一固件，必须移植 U-Boot 等  
3. **今天**：把参照物换成 UEFI，对比逻辑不变 — 通用计算板吃标准固件；自定义 SoC 板吃 U-Boot 移植  

---

## 5. 嵌入式何时会碰到 UEFI？

- 高端 ARM 服务器、部分工控/国产计算平台、要 Windows+Linux 双系统等  
- **绝大多数**消费/工控小系统（路由、传感器网关、Pi 类开发板启动链）仍是 **U-Boot 或厂商精简 boot 链**，不上笨重 UEFI  

树莓派：官方固件 + `config.txt` 路径与经典「纯 U-Boot 板」不完全相同，但 **「固件阶段 → 内核 → rootfs」** 四阶段骨架仍适用（见 [notes 2.2.3](./notes.md)）。
