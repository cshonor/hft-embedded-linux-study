## 一、全称

**GPIO = General Purpose Input/Output**  
SoC 引出的**可编程通用引脚**，嵌入式最基础、最简单的一类「外设」。

---

## 二、两大模式 + 常用配置

| 模式 | 做什么 | 例子 |
|------|--------|------|
| **输出** | 软件拉高/拉低 | LED、继电器、给别的芯片拉复位 |
| **输入** | 读外部电平 | 按键、简单传感器高低电平 |

额外常见：

- **上拉 / 下拉**：默认电平，减少悬空抖动  
- **边沿/电平中断**：变化时 IRQ（按键用中断，不必死轮询）— 见 [8.3](./8.3-driver-lifecycle-and-irq.md)

---

## 三、硬件层

- 一块 SoC（树莓派、i.MX…）常有几十～上百 GPIO  
- 常分组：如 `gpio1` 组里的第 5 脚 → 口语 **GPIO1_5**  
- 每脚可独立配方向、上下拉、中断  

Pi5：应用核 + **RP1** 管大量用户 GPIO — 查官方 GPIO/RP1，勿死背 Pi4 寄存器课。[Pi Labs §0](../../../13-embedded-projects/RASPBERRY-PI5-LABS.md)

---

## 四、Linux：通用驱动 + 设备树（多数不用自写驱动）

内核有现成框架（如 **`gpio-keys`**、**`leds-gpio`**、gpiolib）。  
板级差在哪根脚 → **改 DTS**，逻辑在主线驱动里（[8.4](./8.4-why-most-drivers-are-shared.md)）。

示意（按键）：

```dts
gpio_keys {
	compatible = "gpio-keys";
	key1 {
		gpios = <&gpio1 5 GPIO_ACTIVE_LOW>;
		label = "user_btn";
	};
};
```

含义：`gpio1` 第 5 脚，低有效；`gpio-keys` 匹配后 `probe`，常自动走中断路径。

片内 GPIO 控制器节点一般在原厂 dtsi 里已有；你加的是**消费者**节点（keys/leds/…）。

---

## 五、用户态怎么碰（仍经内核）

常见路径：

- **sysfs**（老）：`/sys/class/gpio` 导出后读写  
- **字符设备 / libgpiod**（更推荐的现代路）：`/dev/gpiochipN`  

APP 读写的是内核接口；**真正改引脚电平的是内核 GPIO 子系统**，不是用户态直写 MMIO（[8.2](./8.2-why-drivers-in-kernel.md)）。

---

## 六、和 UART / I2C / SPI 的差别

| | GPIO | UART/I2C/SPI |
|--|------|----------------|
| 协议 | **无**固定报文协议，软件自由定高低 | 有标准时序/帧格式 |
| 复杂度 | 最低 | 控制器 + 协议驱动更重 |

GPIO = 最简单的「一根线」；总线 = 带协议的专用口。

---

## 七、开发例子

1. 板载 LED → 输出（或 `leds-gpio`）  
2. 功能键 → 输入 + 中断（`gpio-keys`）  
3. 外设复位脚 → 输出脉冲  
4. 插拔检测 → 输入（可中断）  

---

## 八、一句话

GPIO = 可自由编程的芯片引脚：能出电平、能读电平、能中断。  
Linux 上多数场景：**主线 GPIO 驱动 + DTS 配脚**，应用走 sysfs/libgpiod，不必从零写驱动。
