# 新增外设：DTS 必改，驱动分三档

> FAQ · 锚定 Primer Ch7（DTB）· Ch8（驱动入门）· [12 驱动·DT](../../../12-device-drivers-dt/)  
> 相关：[DT ≠ UEFI](../chapter-07-bootloaders/7.0-device-tree-vs-uefi.md) · [BSP 模板](../chapter-03-processor-basics/3.2-bsp-is-template-not-product.md)

---

## 核心结论（两层分开）

1. **板子新加硬件 → 几乎 100% 要改/增 DTS 节点**（启用片内模块则常是改 `status`，见下）。  
2. **不等于一定要从零写驱动** — 有现成驱动就只配 DTS；要适配就改几行；没有才写完整驱动。

---

## 一、为什么必须动设备树？

内核靠 DTB 里的信息认硬件：`compatible`、`reg`（物理基址）、中断、供电、时钟、复位等。  

U-Boot 负责 DDR/Flash 等上电初始化，**不会**把「你焊了什么外设」完整交给内核；启动后内核的主硬件清单来源就是 **DTB**（现代 ARM 嵌入式主路径）。

### 例：GPIO 按键

- 硬件：键接 GPIO ↔ GND  
- DTS：加 `gpio-keys`（或等价）节点 — GPIO、键名、触发电平  
- 驱动：内核 **`gpio_keys` 等通用驱动** → **可零行自写驱动**，只写 DTS  

### 例：板外独立 GPU / 显示控制器（非 SoC 内置）

- DTS：`compatible`、`reg`、电源、时钟、复位、总线（PCIe/I2C…）  
- 驱动：  
  - 内核已有 → 只 DTS  
  - 冷门/自研 → DTS + **完整平台/字符驱动**（Ch8 入门 → [12](../../../12-device-drivers-dt/) 深挖）

## 二、三档工作量

| 场景 | DTS | 驱动 |
|------|-----|------|
| **1. 内核已有标准驱动**（LED、gpio-keys、常见 I2C 传感器、多数屏/PHY/UART…） | 必写节点：`compatible` / `reg` / `interrupts` / `clocks` / regulator / reset… | **不写**；编 DTB、替换启动用的 dtb |
| **2. 有通用驱动，参数略不同**（同系列屏分辨率/时序等） | 必写接线 | **少量改**驱动或用 DT 属性吃参数，不从头造 |
| **3. 无现成驱动**（自研采集、冷门芯片） | 先建节点写地址/中断/电源 | **完整开发**；驱动从 DT 读资源再做读写/IRQ |

操作骨架（场景 1）：改 `.dts` → 出新 `.dtb` → boot 加载新 DTB（多数情况 **不必** 重编 U-Boot，见下）。

**为何场景 1 这么多：** 标准协议 + 厂商合入主线/BSP — [8.4](./8.4-why-most-drivers-are-shared.md)。

## 三、片内模块 vs 外挂器件

| 类型 | DTS 常见动作 |
|------|----------------|
| **SoC 片上**（内置 UART/ETH MAC/内置 GPU…） | 原厂 dtsi/dts **已有节点**；多用 `status = "okay"` / `"disabled"`，不必从零「发明」节点 |
| **板外新挂**（按键、外置 GPU、I2C 模组、外接 Flash…） | 评估板 dts **没有** → **新增完整节点** |

## 四、和 U-Boot 的联动（承接 DT FAQ）

| 你加的东西 | U-Boot |
|------------|--------|
| 普通外设：按键、传感器、屏（内核阶段才用） | **通常只改 DTS**，不重编 U-Boot |
| 影响启动期：DDR、NAND/启动介质、U-Boot 就要用的 PHY/串口时序 | **还要改 U-Boot** — [7.0 场景 B](../chapter-07-bootloaders/7.0-device-tree-vs-uefi.md) |

---

## 五、一句话

**多焊硬件 → DTS 必动；写驱动看内核有没有货。**  
有货只配树；没货先写树再写驱动。
