# 设备树与驱动：分工、compatible、probe、启动链路

> 相关：[加外设三档](./8.0-new-hw-dts-vs-driver.md) · [DT ≠ UEFI](../chapter-07-bootloaders/7.0-device-tree-vs-uefi.md)

---

## 一、定位：配置表 vs 操作代码

| | **设备树（DTS→DTB）** | **驱动** |
|--|----------------------|----------|
| 本质 | 静态数据，无可执行逻辑 | C 代码：读写寄存器、IRQ、协议、业务 |
| 内容 | 地址、中断、时钟、电源、复位、`compatible`、拓扑、板级参数 | 初始化、收发、ISR、`/dev` / sysfs |
| 目的 | **接线/资源与驱动解耦** — 换板多半只改树 | **真正操作外设** |

**比喻：** 驱动 = 电器说明书；设备树 = 插座分布图（位置、电压）。换插座位置改图即可，不必重写说明书。

## 二、绑定钥匙：`compatible`

1. DTS 节点：`compatible = "vendor,part"`（可多字符串，按优先匹配）  
   例：`compatible = "fsl,imx6ul-uart";`  
2. 驱动：`of_match_table` 注册**相同**字符串，挂到 `platform_driver`（或同类）上：

```c
static const struct of_device_id uart_of_match[] = {
	{ .compatible = "fsl,imx6ul-uart" },
	{ /* sentinel */ }
};
MODULE_DEVICE_TABLE(of, uart_of_match);

static struct platform_driver uart_drv = {
	.probe = uart_probe,
	.driver = {
		.name = "imx6-uart",
		.of_match_table = uart_of_match,
	},
};
```

3. 内核：解析 DTB → 对每个节点的 `compatible` 在已注册驱动里找匹配 → 命中则调 **`probe()`**。

`probe` = 驱动读树、申请资源、初始化硬件的入口。

---

## 三、`probe` 里怎么读树（`of_*`）

| API（示意） | 用途 |
|-------------|------|
| `of_address_to_resource` / `platform_get_resource` | `reg` → 物理/IO 资源 |
| `of_irq_get` / `platform_get_irq` | 中断号 |
| `of_clk_get` | 时钟 |
| `of_property_read_u32` 等 | 自定义属性（分辨率、速率…） |
| `of_get_named_gpio` / gpiod 族 | GPIO |

### 例：只加按键（不改驱动）

```dts
gpio_keys {
	compatible = "gpio-keys";
	key1 {
		gpios = <&gpio1 5 GPIO_ACTIVE_LOW>;
		label = "user_btn";
	};
};
```

内核自带 `gpio-keys` 驱动匹配 `"gpio-keys"` → `probe` → `of_*` 读 GPIO/标签 → 申请中断、上报按键。  
**全程只改 DTS**（场景见 [8.0](./8.0-new-hw-dts-vs-driver.md)）。

## 四、分工边界

### 设备树只填数据（不做操作）

- MMIO 基址、IRQ、时钟、供电、复位  
- 总线拓扑（I2C 下挂哪些从设备）  
- 板级参数（屏时序、波特率、分区大小）  
- `status = "okay"` / `"disabled"`

### 驱动只写逻辑（不把板级地址写死）

- 寄存器/中断/上下电与初始化  
- 协议与数据路径  
- 用户态接口（`/dev`、sysfs、net…）

**解耦收益：** 同驱动多板复用，改地址/引脚改树即可。  
无 DT 的老做法：地址硬编码在 `.c` → 换板改驱动重编。

## 五、新增硬件时的联动（摘要）

| 场景 | DTS | 驱动 |
|------|-----|------|
| 内核已有标准驱动 | 增/改节点 | 不写 |
| 无驱动 | 先建节点（含 `compatible`） | 写 `of_match_table` + `probe` + `of_*` |

片内模块：原厂节点多已在，常只改 `status`。  
板外新芯片：常需**新建**完整节点；无驱动再开发。详表 → [8.0](./8.0-new-hw-dts-vs-driver.md)。

## 六、启动交互链路（极简）

```
U-Boot 加载 DTB → 交给内核
    → 内核展开设备节点
    → compatible ↔ of_match_table
    → probe()
    → of_* 取资源 → 初始化硬件 → 暴露 /dev 等
```

U-Boot **不**替代 DTB 当「完整外设清单」；它负责启动期硬件初始化并把 DTB 指针交给内核（[7.0](../chapter-07-bootloaders/7.0-device-tree-vs-uefi.md)）。

---

## 七、一句话

**DT = 静态资源清单；驱动 = 操作逻辑。**  
靠 `compatible` 绑在一起，靠 `of_*` 在 `probe` 里读树 — 板级移植成本主要落在改树上，而不是改遍驱动源码。
