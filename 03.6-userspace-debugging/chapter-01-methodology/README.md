## 为什么调试要「方法论先行」

工具手册（gdb / strace / valgrind 的官方文档）教你「怎么用」，但**不教你「遇到问题时该用哪个、按什么顺序」**。这正是 LDD Ch4（Greg Kroah-Hartman 合著）把调试分成 `Printing → Querying → Watching → System Faults → Debuggers` 五类方法的原因：**先分类，再选工具**。

本模块后面 5 个问题类型章，每章开头都会先写一句「**这一章解决什么症状**」，让你从症状反查工具，而不是背完工具清单却不知道何时用。

## HFT 关联

- **快速分诊**：生产环境报错时，先判断「崩了 / 内存涨了 / 结果时对时错 / 卡住 / 太慢」五选一，决定上 coredump / valgrind / TSan / strace / perf——比「上来就 gdb」高效得多；
- **复现即正义**：交易系统很多 bug 只在特定行情时序下出现，能复现就赢了一半（见 1.3）；
- **收敛而非乱试**：HFT 延迟敏感，每次「改一处猜一处」都会引入新变量，1.4 的科学方法帮你少走弯路。
