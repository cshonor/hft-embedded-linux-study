section-2-IO体系结构

80x86 视角的 硬件 I/O 基础

一、总线与设备

计算机通过 系统总线 连接外设：

总线示例 典型设备
PCI / PCIe 网卡、显卡、NVMe
ISA（遗留） 老 DMA 限制（→ Ch 8 ZONE_DMA）
USB 外设

CPU 不直接「摸」设备芯片，经 I/O 接口 与 设备控制器 通信。

二、CPU 如何寻址设备

方式 说明
I/O 端口 (Port I/O) 独立端口地址空间；x86 用 in / out 汇编读写控制/状态/数据寄存器
内存映射 I/O (MMIO) 设备寄存器映射到 物理内存地址 — 像访存一样读写

现代 PCI 设备 多为 MMIO；legacy 芯片仍可能用端口 I/O。

三、接口 vs 控制器

组件 角色
I/O 接口 硬件电路 — 在 CPU 侧端口/MMIO 与设备侧信号之间 翻译 命令与数据
设备控制器 设备内部微芯片 — 实际执行 I/O（如磁盘寻道、NIC 发包）

驱动程序通过读写 寄存器 向控制器下命令，再等待完成。

section-3-设备驱动程序模型

Linux 2.6 统一驱动模型 + sysfs

一、sysfs 与硬件拓扑

sysfs（挂载于 /sys）将 硬件拓扑与设备状态 映射为 目录树 — 用户态可直接读写在驱动模型中注册的对象属性。

→ VFS 特殊 FS：Ch 12 section-5

二、底层：kobject / kset / subsystem

对象 作用
kobject 驱动模型 基础 — 对应 sysfs 中一个 目录；引用计数、层次链接
kset 同类型 kobject 的 集合
subsystem 多个 kset 的 上层分组

生命周期：注册 → sysfs 出现 → 引用归零 → 释放。

深潜可选： kobject_init、kobject_put — 见 lib/kobject.c。

三、四大高层组件

内核用统一模型抽象 整个硬件世界：

组件 含义
Device（设备） 物理或逻辑硬件实例
Driver（驱动） 与该设备匹配的 驱动程序
Bus（总线） 挂载与 匹配 device ↔ driver（如 PCI、USB）
Class（类） 逻辑功能 分组（如「网卡」「块设备」）— 与用户看到的 /dev 类型相关

匹配流程（概念）： 设备注册到总线 → 内核尝试绑定已有驱动 → probe → 创建设备节点。

section-4-设备文件

「一切皆文件」 — I/O 设备也在 /dev 下

一、设备即文件

应用程序对设备使用与普通文件 相同的 syscall：

open("/dev/sda1") → read / write / ioctl …

VFS file 对象 最终通过 file_operations 进入 字符或块驱动（见 section-6）。

→ VFS 四大对象：Ch 12 section-3

二、主次设备号

号码 含义
主设备号 (Major) 标识 设备类型 / 驱动程序
次设备号 (Minor) 同类型下 具体实例（如第 2 块盘、第 3 分区）

内核用 (major, minor) 唯一识别 设备文件对应的驱动与实例。

三、32 位扩展与动态分配

演进 说明
传统 8 位 主次号易 耗尽
2.6 扩展 32 位 dev_t — 12 位 major + 20 位 minor
动态分配 驱动加载时 alloc_chrdev_region() 等向内核 申请可用号 — 不必依赖静态官方号表

udev 用户态守护进程常根据 sysfs 事件 自动创建 /dev 节点。

section-5-驱动通用特性

一、监控 I/O 完成：轮询 vs 中断

硬件操作 耗时不确定，驱动需知道何时完成：

模式 行为 适用
轮询 (Polling) 循环读 状态寄存器 直到完成 极快设备、或可接受占 CPU
中断 (Interrupts) 设备完成后发 IRQ — CPU 做别的事，中断时再处理 主流 — 更高效

→ IRQ 框架：Ch 4 section-6 · Ch 4 section-8 返回路径

HFT：高 PPS 网卡常 NAPI / 批量 poll — 在中断与纯轮询之间折中（modern，ULK 2.6 已有中断主导模型）。

二、直接内存访问 (DMA)

大块数据传输时，让 设备控制器 直接与 RAM 交换数据，减轻 CPU 逐字节拷贝。

内核提供 架构无关 的 DMA 辅助 API，并区分两类映射：

类型 用途
一致性 DMA (Coherent) CPU 与设备 共享 同一份内存视图 — 适合小控制结构；处理 缓存一致性
流式 DMA (Streaming) 单次传输 映射/解除 — 适合 scatter-gather 大数据流；方向明确（to/from device）

→ ZONE_DMA 低端内存：Ch 8 — 部分老设备 DMA 只能寻址低 16MB。

深潜可选： dma_alloc_coherent vs dma_map_single — 总线是否 I/O coherent 决定是否需要 bounce buffer。

section-6-字符设备驱动

顺序字节流 — 内核对设备的最小支持级别之一

一、字符 vs 块（预告）

类型 访问模型 下一章
字符设备 顺序 字节流 — 不可随机寻址（或能力有限） 本章
块设备 固定大小块、可 seek、常带缓存 Ch 14 块设备

例：键盘、串口、部分控制设备 → 字符；磁盘 → 块。

二、cdev 描述符

每个字符设备在内核由 struct cdev 描述：

  • 关联 dev_t（主次号）
  • 指向 file_operations（open/read/write/ioctl …）

三、注册设备号

API 用途
alloc_chrdev_region() 动态 申请一段主次号
register_chrdev() 较老接口 — 注册 major 与操作表

卸载驱动时 释放 设备号、删除 cdev。

四、打开设备时 VFS 如何挂钩

用户 open("/dev/xxx")
    ↓
VFS 查 inode（字符设备特殊 inode）
    ↓
def_chr_fops（默认字符操作表）
    ↓
根据 inode 中的 cdev → 驱动自定义 file_operations
    ↓
驱动 .open / .read / .write …

即 Ch 12 VFS 多态 在字符设备上的具体实例。

→ file_operations：Ch 12 section-3
