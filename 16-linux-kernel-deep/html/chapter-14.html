section-1-本章定位

ULK Ch 14 Block Device Drivers · 硬盘等 块设备 的 I/O 路径

一、本章讲什么

块设备（硬盘、软驱、CD-ROM …）与 CPU 速度 差距极大 — 磁头 寻道 极慢。内核在 多层抽象 上合并、排序、缓存请求：

主题 要点
层次 VFS → 映射层 → 通用块层 → I/O 调度 → 驱动
数据单位 扇区 / 块 / 段（DMA scatter-gather）
核心结构 bio、gendisk、request_queue
调度 Noop、CFQ、Deadline 电梯算法
完成 DMA 结束 → 中断 → 释放 bio、派发下一请求

二、小节导航

节 主题
2 五层 I/O 路径
3 sector / block / segment
4 bio、gendisk、分区
5 request_queue、Noop/CFQ/Deadline
6 block_device、初始化、IRQ 完成

三、在 Linux 链上的位置

Ch 12 VFS read/write
Ch 14 块层 + 调度（本章）
Ch 15 页高速缓存 — 多数读写在 RAM 完成，减少落盘
Ch 16 文件访问 — 完整 read 路径
Ch 13 DMA / 中断基础

HFT：交易热路径少碰 旋转磁盘；日志/快照落盘仍受 调度与 fsync 影响。NVMe 时代 elevator 已大幅简化（modern 对照）。

section-2-块设备层次结构

一次 read/write 穿越的内核组件

一、自上而下五层

进程 syscall（read / write）
    ↓
① VFS              — 系统调用、file 对象
    ↓
② Mapping Layer    — 文件偏移 → 磁盘 **逻辑块号**
    ↓
③ Generic Block Layer — 统一块 I/O 抽象；构造 **bio**
    ↓
④ I/O Scheduler    — 合并、排序 **request**
    ↓
⑤ Block Device Driver — DMA / 控制器命令 → 磁盘

每层 隐藏下层细节，上层只面对统一接口。

二、为何需要这么多层

问题 哪层解决
文件语义 vs 裸扇区 Mapping Layer + 具体 FS
不同磁盘/控制器差异 Generic Block Layer
磁头频繁寻道 I/O Scheduler
硬件命令与 IRQ Block Driver

→ VFS：Ch 12 · 页缓存减少穿透：Ch 15

三、与字符设备对比

字符设备 (Ch 13) 块设备 (本章)
单位 字节流 固定块、可随机寻址
缓存 通常无块层缓存 页缓存 + 请求队列
典型 串口、键盘 硬盘、SSD（仍走块层）

section-3-扇区块与段

统一 硬件 / FS / DMA 各层对「一块数据」的叫法

一、扇区 (Sector)

属性 说明
层级 磁盘 硬件 最小传输单位
典型大小 512 字节（现代也有 4K 扇区）
视角 控制器把盘看成 扇区数组

二、块 (Block)

属性 说明
层级 VFS / 文件系统 逻辑单位
大小 扇区的 整数倍；须能放进 一个物理页框（如 1KB、4KB）
关系 FS 按 块 组织；块层再映射到 扇区

→ 页框：Ch 8

三、段 (Segment)

为 scatter-gather DMA 引入：

含义 单次 DMA 中 内存连续、且对应磁盘 相邻扇区 的一段
目的 一次 DMA 传 多段 不连续物理页 — 减少 CPU 拷贝

→ DMA 概念：Ch 13 section-5

四、三者关系简图

文件 read()
    ↓ 以 block 为单位（FS / 页缓存）
bio 描述若干 sector
    ↓ bio_vec[] 每段 = 连续物理页 + 扇区范围
DMA scatter-gather 到磁盘

section-4-通用块层与bio

Generic Block Layer 的 核心数据结构

一、bio — 一次块 I/O 操作

bio 代表 正在进行 的块设备 I/O：

字段类 内容
磁盘位置 起始 扇区号、扇区 数量
内存描述 bio_vec[] — 每元素描述参与 I/O 的 一段物理内存（页 + 偏移 + 长度）

多个 bio 可被 合并 进同一 request（见 section-5）。

深潜可选： bio 合并条件 — 相邻扇区 + 可合并的 bio_vec。

二、磁盘与分区表示

结构 含义
gendisk 表示 整盘 — 容量、操作表、分区表指针等
hd_struct 数组 跟踪 各逻辑分区 的起止与统计

用户看到的 /dev/sda、/dev/sda1 最终都挂到 block_device + gendisk 体系。

三、与设备文件的关系

→ 主次设备号：Ch 13 section-4

块设备 inode 走 块设备专用 路径，而非 def_chr_fops。

section-5-IO调度程序

合并 + 排序 — 减少磁头移动，提高吞吐量

一、为何不能「一扇区一请求」

若每个扇区单独 I/O → 磁头 来回寻道 → 性能 崩溃。

通用块层把多个 bio 包装进 request，交给 I/O 调度器 排队、合并、排序后再下发驱动。

二、请求队列 request_queue

概念 说明
request_queue 每个块设备 一条 队列 — 挂未完成的 I/O
request 请求描述符 — 可包含 多个磁盘上相邻 的 bio

调度器从队列头/按算法取 request → 驱动 → DMA。

三、电梯算法 (Elevator)

ULK 2.6 典型三种（elevator 可插拔）：

算法 行为 特点
Noop 基本 合并 + FIFO 最简单；SSD/低寻道代价场景
CFQ 按进程 分队列，轮询 派发 公平 分配带宽 — 桌面默认之一
Deadline 按 截止时间 排序 读默认 500ms、写 5s 过期 — 防 饿死（远端磁道久等）

饿死问题： 纯按物理位置排序时，某些 远端 请求可能长期得不到服务 — Deadline 用 时间上限 强制优先。

Modern 对照： NVMe + mq 块层后，传统单队列 elevator largely 被 blk-mq 与 none/none 取代；读 ULK 理解 合并/排序动机 即可。

四、HFT 相关

  • fsync / 日志写 仍经块层 — 调度延迟影响 持久化尾延迟
  • 数据库/交易日志常 专用盘 + noop/none + 绕过 cache 的写（应用层策略）

section-6-块设备驱动与中断

一、block_device 描述符

统一表示 块设备 — 整盘或 分区：

  • 链接到 gendisk
  • 与 VFS inode、主次设备号 对应

不管 /dev/sda 还是 /dev/sda3，同一套抽象。

二、驱动初始化（概要）

块驱动使用前通常：

  1. 分配 / 初始化 gendisk
  2. 注册 主设备号（→ Ch 13 动态分配）
  3. 设置 media_changed 等底层方法（可移动介质换盘检测）
  4. 注册到 设备驱动模型（sysfs / udev）

三、DMA 完成与中断

传输由 DMA 执行（→ Ch 13 DMA）；结束时 磁盘控制器发 IRQ：

IRQ → 块驱动 interrupt handler
    ↓
end_that_request_first()  — 更新 request 进度
end_that_request_last()   — 完成 request、释放 bio
    ↓
唤醒等待该 I/O 的进程；派发队列中下一 request

→ IRQ 框架：Ch 4 section-6

深潜可选： I/O 完成 回调（bio_endio）— 页缓存写回、read 填充页 在此衔接 Ch 15。

四、本章小结

read/write → VFS → 映射层 → bio
    ↓
request_queue + elevator（合并/排序）
    ↓
块驱动 + DMA
    ↓ IRQ 完成
唤醒进程 / 触发 bio 回调

多数 读 在到达块层前已被 页缓存 命中 — Ch 15。
