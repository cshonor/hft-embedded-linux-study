# 2.2 在集线器连接网络中嗅探

> 本章：[chapter-summary.md](./chapter-summary.md) · 全书：[../README.md](../README.md) · 回顾：[§1.2 Hub](../chapter-01-network-basics/02-network-communication-basics.md)

**核心主旨**：Hub 环境下的监听原理，以及该架构因半双工与碰撞在现代网络中被淘汰的原因。

## 核心知识点

### 工作原理

- **集线器（Hub）**：L1 设备，将收到的帧**盲目中继到每一个端口**（共享冲突域）。
- **嗅探部署**：嗅探器接 Hub **任意空闲端口** → 获得本地网段**几乎不受限制的可视范围**（无需端口镜像）。
- 仍需网卡 **混杂模式**，以便处理「目的 MAC 为他人」的帧。

### 性能缺陷与碰撞

| 特性 | 后果 |
|------|------|
| **半双工（Half-duplex）** | 同一时刻只允许一台设备发送 |
| **冲突碰撞（Collision）** | 多机同时发 → 线路上冲突 → **丢包** |
| **重传** | 设备退避后重传；高负载下可能重传 3–4 次，性能急剧下降 |

**CSMA/CD（载波侦听多路访问 / 冲突检测）**：发送前侦听线路；冲突后随机退避再试。抓包可见重传、延迟抖动；现代以太网接入几乎全用交换机全双工，Hub 场景少见。

### 现存场景

- 老旧布线、实验室、部分 **工业控制系统（ICS）** 仍可能使用 Hub 或类 Hub 拓扑。

## 抓包/实操记录

| 实验 | 说明 |
|------|------|
| 验证 Hub | 两台 PC + 嗅探器接同一 Hub，A ping B，嗅探器应同时看到请求/应答（双向单播） |
| 对比交换机 | 改接交换机普通口 → 通常只能看到广播 + 本机流量（为 §2.3 做对照） |

## 疑问与总结

- Hub 嗅探「简单」但**拖慢全网**；生产排障优先 **SPAN 镜像 / TAP**，而非人为加 Hub。
- 市面「假 Hub」实为交换机，互嗅测试失败 → 见 §2.3.2。
