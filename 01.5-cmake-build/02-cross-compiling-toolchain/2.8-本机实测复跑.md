# 2.8 本机实测复跑：clang 路线（不装 arm-none-eabi-gcc）

[← CH2 toolchain file](./README.md)

## 本节讲什么

2.4 的演示用的是 `arm-none-eabi-gcc`——**这台 Mac 上并没有装它**（labs/00 笔记
验证过不需要装）。本节做两件事：①指出 2.4 演示在本机的真实可复现版本；
②用 clang 路线把 **Cortex-M 裸机交叉构建完整跑通**，产物与
`STM32-/labs/00` 的 Makefile 版逐字节核对。实测环境：macOS 26.6.2 +
cdev 环境（clang 23.1.0 / CMake 4.4.3），无板依赖。

## 要点

### 2.4 演示在本机的现实

`arm-none-eabi-gcc` 属于 GNU 交叉工具链，每个目标三元组一套独立发行版。
而 **LLVM 路线不需要它**：宿主的 clang 自带全部 ARM 后端，"交叉"只是一个
`--target` 参数——这正是 labs/00 笔记的核心结论，本章 demo 里的
`cortex-m-clang/` 子目录就是它的 CMake 版。

### clang 路线 toolchain file（`demo/cortex-m-clang/arm-clang-cortex-m3.cmake`）

与 2.3 的 GNU 版四处不同，每处都有原因：

```cmake
set(CMAKE_SYSTEM_NAME Generic)
set(CMAKE_SYSTEM_PROCESSOR arm)
set(CMAKE_C_COMPILER clang)                       # ③ 编译器还是宿主那个 clang
set(CMAKE_C_COMPILER_TARGET armv7m-none-eabi)     # ④ "交叉"在这里发生
set(CMAKE_TRY_COMPILE_TARGET_TYPE STATIC_LIBRARY) # ⑤ 与 GNU 版相同：救命行
```

- **③④ 合起来读**：GNU 版"编译器名字带三元组"，clang 版"编译器名字不变、
  三元组单独给"。`CMAKE_C_COMPILER_TARGET` 设好后，CMake 自动往**每条**
  编译/链接命令最前面注入 `--target=armv7m-none-eabi`（实测：
  `cmake --build build --verbose` 可见，且它不在 flags.make 的 C_FLAGS 里——
  在 build.make 的编译规则里）
- **⑤** 与 GNU 版同理：裸机链不出宿主可执行文件，探测改静态库

### 工程侧与 2.4 的两处差异

| 事项 | GNU 路线（2.3） | clang 路线（本节） |
|---|---|---|
| 链接发起者 | `arm-none-eabi-gcc` 驱动 + 系统 ld | clang 驱动 + `-fuse-ld=lld`（macOS 系统 ld 是 Mach-O 的，吃不了 ELF 脚本） |
| 链接选项写法 | `target_link_options(-T ...)`（gcc 驱动认识） | 必须 `-Wl,` 前缀（`-Wl,-T,... -Wl,--entry=...`），clang 只透传认识的选项 |
| 产物后缀 | 可执行文件默认无后缀的问题同样存在 | `set_target_properties(... SUFFIX ".elf")` 显式补回 |
| `-mcpu` 归属 | `CMAKE_C_FLAGS_INIT`（工具链信息不泄进工程） | 同理可用 `_INIT`；本 demo 为教学对比放进了 target_compile_options |

### 实测输出（原样）

```bash
$ cd demo/cortex-m-clang && cmake -B build -DCMAKE_BUILD_TYPE=MinSizeRel && cmake --build build
[100%] Linking C executable blink.elf
objcopy -> blink.bin
[100%] Built target blink

$ llvm-readelf -h build/blink.elf | grep -E "Class|Machine|Entry"
  Class:                ELF32
  Machine:              ARM
  Entry point address:  0x8000041      # 0x08000040 | 1：Thumb 位

$ llvm-size -A build/blink.elf
.text            292   134217728      # 0x08000000 Flash
.data              4   536870912      # 0x20000000 RAM
.bss               4   536870916

$ ls -l build/blink.bin               # 与 labs/00 Makefile 版逐字节同尺寸
296 bytes
```

**产物与 Makefile 版完全一致（296 字节）**——再次验证：构建系统的价值在
组织与防错，不在产物。

### 复跑时踩到的坑（本章正文的活例子）

1. **坑：探测链接失败** → 2.3 灵魂行 ⑤，实测再次命中
2. **坑：`-Wl,` 前缀** → `-T linker.ld` 直接写不生效，见 `link.txt` 核实
3. **坑：Generic 无后缀** → 第一版跑完 `blink.elf` 不存在（llvm-size 报
   No such file），补 `SUFFIX ".elf"` 后解决
4. **坑：toolchain 写缓存** → 改 toolchain file 必须删 build/ 重配
