# 1.3 三级台阶：同一个工程的三种构建法

[← CH1 最小工程](./README.md) · [1.2](./1.2-构建系统只管两件事.md) · 下一节：[1.4 两条命令拆解](./1.4-两条命令每一步发生了什么.md)

## 本节讲什么

`demo/` 是同一个三文件工程（`main.c` + `math_utils.c` + `math_utils.h`，
算一个移动平均再夹到风控区间——刻意带点 HFT 味）。这一节把它用三种方式各构建一遍。

## 要点

**台阶一：手动编译**（见 [1.1](./1.1-编译命令什么时候失控.md)，一条长命令，全量、无依赖管理）

**台阶二：Makefile**——你要手写依赖规则：

```makefile
demo: main.o math_utils.o
	gcc main.o math_utils.o -o demo
main.o: main.c math_utils.h      # ← 依赖要自己写对
	gcc -Wall -std=c11 -c main.c
math_utils.o: math_utils.c math_utils.h
	gcc -Wall -std=c11 -c math_utils.c
```

增量编译解决了，但规则是**手写的、平台绑定的**。`STM32-/labs/00` 的 Makefile
你见过它的完全体：`--target=armv7m-none-eabi` 一大串交叉编译 flag 全写死在里面。

**台阶三：CMake**——你只描述"目标是什么"：

```cmake
cmake_minimum_required(VERSION 3.16)   # ① 语法基准线
project(demo C)                        # ② 工程名 + 语言
add_executable(demo main.c math_utils.c)  # ③ 一切皆 target
target_compile_options(demo PRIVATE -Wall -Wextra)  # 属性挂在 target 上
set_target_properties(demo PROPERTIES C_STANDARD 11 C_STANDARD_REQUIRED ON)
```

逐行说：

- `cmake_minimum_required`：声明"我的语法按 3.16 为准"——没有它 CMake 会告警，
  因为老版本和新版本语法有差异
- `project(demo C)`：工程名 + 语言。CMake 在这一步触发**编译器探测**
- `add_executable`：声明"我要一个叫 demo 的可执行文件，源文件是这些"——
  这就是现代 CMake 的核心动作：**创建 target**
- `target_compile_options`：把编译选项**挂在这个 target 上**（PRIVATE=只它自己用）
- `-Wall -Wextra` 这些警告开关具体在干什么、`-Werror` 为什么被当门禁——
  详见附注 [1.3b 警告开关](./1.3b-警告开关-Wall与Werror.md)
- `set_target_properties`：声明 C 标准，`REQUIRED` 表示标准不支持就直接报错而不是静默降级

对比一下心智负担的转移：

| | Makefile | CMakeLists |
|---|---|---|
| 依赖关系 | **自己写**（写错不报错） | 编译器扫描自动生成（`.o.d` 文件，见 [1.5](./1.5-拆开build目录.md)） |
| 编译命令 | 自己拼 | CMake 按探测到的编译器自动拼 |
| 换平台 | 重写 | 重新 `-B` 生成一遍 |
| 找库 | 自己写 `-I`/`-L`/`-l` | `find_package` / `target_link_libraries` |
