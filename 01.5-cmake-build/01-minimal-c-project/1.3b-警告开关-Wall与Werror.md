# 1.3b 附注：警告开关 —— `-Wall` 和 `-Werror` 到底在干什么

[← CH1 最小工程](./README.md) · 上一节：[1.3 三级台阶](./1.3-三级台阶.md) · 下一节：[1.4 两条命令拆解](./1.4-两条命令每一步发生了什么.md)

## 本节讲什么

1.3 的编译命令里出现了 `-Wall`，CMakeLists 里出现了 `-Wall -Wextra`，很多开源工程的
README 还会让你加 `-Werror`。这三个 `-W` 开头的开关是新手最容易"照抄但不理解"的东西。
这一节用 `demo/warn_demo.c`（一个故意养了三个经典小毛病的文件）逐级实测，
看每个开关到底多管了什么、不管什么。

**先分清两个词：**

| | 编译器反应 | 产物 |
|---|---|---|
| **error（错误）** | 拒绝编译，直接停 | 没有 `.o` |
| **warning（警告）** | "我觉得这地方可疑，但语法合法，我继续编" | 照样产出 `.o` |

警告的麻烦就在第二行：**它不拦你**。代码带着"变量没初始化就相乘"这种 bug 一样能编出
可执行文件，然后等到某个运行时刻给你一个垃圾值。警告开关做的事，就是把编译器
"可疑但不违法"的检查项打开——默认它为了兼容历史代码，绝大多数检查是关着的。

## 要点

### 1. `-Wall`：开"常用警告"，名字有坑

`-Wall` 字面像 "all warnings"，**实际并不是全部**——它是编译器作者筛选过的
"高性价比警告集"：误报少、几乎总能查出真问题。里面包括：

- 用了未初始化的变量
- 该返回值的函数分支没写 `return`
- 类型转换会悄悄丢信息（如 `double` 隐式截断成 `int`）
- 永远为真/假的条件、无法到达的代码
- 声明了却没用的变量（gcc 视角；见下文实测差异）

### 2. `-Wextra`：在 `-Wall` 之上再拧一圈

多出来的都是"有时正常写法也会踩到"的检查，最典型的是
`-Wsign-compare`：**有符号数和无符号数比较**。这类 bug 在嵌入式里极其致命：

```c
unsigned len = 1;
int n = -1;
if (len > n)   /* 你以为 false，实际 true！n 被转成巨大的无符号数 */
```

配套实验见 [`warn_demo.c`](./demo/warn_demo.c)，一编即现形。

### 3. `-Werror`：把警告升级成错误

加了它，上一节表里的"警告"一栏整体变性质：

| | 无 `-Werror` | 有 `-Werror` |
|---|---|---|
| 可疑代码 | 打印 warning，继续编 | 变成 **error**，编译中断 |
| 产物 | 有 `.o` | 没有 `.o` |
| 退出码 | 0 | 非 0 |

它的价值不在"多查出 bug"，而在**强制你当场处理**：没有它，警告会在满屏输出里
一闪而过，没人看，日积月累几百条"背景噪音"，真正要命的那条就淹没了。所以
`-Werror` 的实际含义是纪律：**警告数量必须为零**，新警告一出现构建就红。

### 4. 实测：四个等级逐级对比

对 [`demo/warn_demo.c`](./demo/warn_demo.c)（毛病：①`if (qty = 5)` 把赋值当比较；
②`price` 未初始化就参与风控乘法；③`unsigned` 与 `int` 比较）逐级编译
（clang 23.1.0，cdev 环境实测）：

```console
$ cc -c warn_demo.c                      # 默认：几乎静默
warn_demo.c:23:13: warning: ... [-Wparentheses]        # ① 只有 1 条（clang 默认就开）

$ cc -Wall -c warn_demo.c                # -Wall：+1
warn_demo.c:23: warning: ... [-Wparentheses]           # ①
warn_demo.c:30: warning: variable 'price' is uninitialized when used here
                                                       # ② 查出未初始化！

$ cc -Wall -Wextra -c warn_demo.c        # -Wextra：再 +1
warn_demo.c:23: warning: ... [-Wparentheses]           # ①
warn_demo.c:27: warning: comparison of integers of different signs
                                          [-Wsign-compare]   # ③
warn_demo.c:30: warning: variable 'price' is uninitialized ...  # ②

$ cc -Wall -Wextra -Werror -c warn_demo.c  # -Werror：全部变 error
warn_demo.c:23:13: error: ... [-Werror,-Wparentheses]
warn_demo.c:27:17: error: ... [-Werror,-Wsign-compare]
warn_demo.c:30:13: error: ... [-Werror,-Wuninitialized]
2 errors generated        # 退出码 1，没有产出 .o，构建失败
```

注意 `-Werror` 的输出格式：`[-Werror,-Wparentheses]`——警告名还在，
只是性质从 warning 换成了 error。

> **gcc 与 clang 的差异**（本套笔记 gcc 视角书写、clang 实测，两者在 CMake 场景逐行等价，
> 但警告集不是逐条相等）：
> - gcc **默认**比 clang 更安静——上面的毛病①④ gcc 默认一条都不报；
> - gcc 的 `-Wall` **不含** `-Wuninitialized`（它需要优化器的数据流分析，
>   实际要 `-O1` 以上才完整工作）；
> - 结论：**别赌默认值，显式写 `-Wall -Wextra`**，两个编译器下都是最稳的日常配置。

### 5. 在 CMake 里怎么写

```cmake
target_compile_options(demo PRIVATE
    -Wall
    -Wextra
    $<$<C_COMPILER_ID:Clang,AppleClang,GNU>:-Werror>)   # 可选：本地也当门禁
```

日常写法更简单：`-Wall -Wextra` 常开，`-Werror` 放在 CI/发布构建里开
（本机调试期偶尔想"先编过再说"，两者分开更灵活）。工程级配置怎么随
`CMAKE_BUILD_TYPE` / preset 固化，第 5 章 [5.6](../05-hft-compile-options/5.6-CMakePresets固化进git.md) 讲。

## HFT/嵌入式关联

- `warn_demo.c` 里那个未初始化的 `price`，位置就在**风控金额计算**里——
  这不是巧合：HFT 最怕的恰是"能跑但值不对"的静默 bug，一笔垃圾价的订单发出去
  就是真金白银。警告开关注化成门禁（`-Werror` + CI）后，这类代码根本进不了主干。
- 嵌入式同理且更狠：没有 stderr 给你看运行期崩溃，`unsigned/int` 比较错一次，
  缓冲区边界就错了，直接越界写。STM32 工程把 `-Wall -Wextra -Werror` 写进
  CMakeLists 是标准动作（Zephyr 内部就是这么配的，见第 4 章）。

## 代码自测

<details><summary>Q1：`-Wall` 是"所有警告"吗？</summary>

不是。它是编译器筛选后的常用集。真正的全家桶是 clang 的 `-Weverything`（官方
自己都不建议日常用，误报多），日常标配是 `-Wall -Wextra`。
</details>

<details><summary>Q2：既然 warning 不拦编译，为什么还要开？直接忽略不行吗？</summary>

警告指向的多数是"语法合法但几乎必定是笔误"的代码：`= `当 `==`、变量没初始化、
符号比较。这些 bug 编译期修是 1 分钟，运行期查可能是几天——警告就是编译器
免费送你的 code review。
</details>

<details><summary>Q3：`-Werror` 会不会太严格，导致正常代码编不过？</summary>

偶尔会（某些三方头文件自带警告）。所以工程实践是分层：本地 `-Wall -Wextra`，
CI/发布加 `-Werror`；对确属三方代码的警告用 `-Wno-xxx` 或把三方目录隔离成
独立 target 单独放宽，而不是全局关警告。
</details>

<details><summary>Q4：怎么知道某个警告属于哪个开关、想单独关掉它？</summary>

每条警告尾部方括号里就是它的名字（如 `[-Wsign-compare]`）。想单独关就是
`-Wno-sign-compare`；想单独开（不在 -Wall 里）直接写 `-Wsign-compare`。
警告名即开关名，一一对应。
</details>
