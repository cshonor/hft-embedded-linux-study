## 12.1 基准测试的背景与挑战

> 章节导航：[本章导读](../README.md) · 下一篇 [12.2 基准测试的类型](./section-12.2-基准测试的类型.md)

**本节讲什么**：为什么要做基准测试（五个真实目的）、有效基准与无效基准的分界线、六大失败模式的机制级解释——每个失败模式都不是「粗心」，而是有具体的系统原因。

### 要点

| # | 要点 | 一句话 |
|---|------|--------|
| 1 | 跑分高 ≠ 生产快 | 基准是**实验**，不是电竞排名 |
| 2 | 有效性三支柱 | **相关**（像生产）、**可复现**（环境文档化）、**可解释**（带 profile） |
| 3 | 六大失败模式各有机制 | 测错层是最常见也最隐蔽的 |
| 4 | 报分布不报均值 | 均值把 tail 抹平 |
| 5 | 结论的作用域要标明 | 实验室结论 ≠ 生产结论 |

---

### 一、为什么要做基准测试（五个真实目的）

| 目的 | 例子 | 关键要求 |
|------|------|---------|
| **容量规划** | 新机器能扛多少行情 pps | 阶梯负载找拐点（12.3） |
| **回归检测** | 策略改一行，P99 是否变差 | 固定环境 + 固定数据 + 固定判读 |
| **对比选型** | NIC A vs B、内核栈 vs DPDK | 单变量对照 |
| **验证调优** | sysctl/绑核/中断亲和前后 | 改一项测一项 |
| **SLA 证明** | 对交易所/托管方交付证据 | 报分布 + 测量点声明 |

注意：这五个目的对「像生产」的要求不同——容量规划可以接受合成负载（外推时打折），回归检测必须用完全一致的环境与数据（否则差异来源不可判），SLA 证明必须用生产级观测口径。

### 二、有效基准 vs 无效基准

| 有效 | 无效 | 差别本质 |
|------|------|---------|
| 目标明确（测什么、为谁、决策是什么） | 「跑个 fio 看快不快」 | 没有决策的测试是娱乐 |
| 环境文档化、可复现 | 未说明内核/驱动/邻居 | 差一个 sysctl 结果就能翻倍 |
| 与**生产 workload 相关** | 纯 synthetic 且形状完全不同 | 访问模式决定走哪条内核路径 |
| 报告**分布**（P50/P95/P99/P999） | 只报一个平均值 | [排队论](../../chapter-02-methodologies/)：均值对 tail 盲 |
| 结合**观测**解释瓶颈 | 只有数字无 profile | 不知道瓶颈在哪层 = 不知道测了什么 |
| 结论带作用域 | 实验室结论直接外推生产 | 过度推广是最贵的错误 |

**「可复现」的最低配置清单**（照抄进 runbook）：

```
□ 硬件：型号/固件/BIOS 版本
□ 内核版本 + 关键 sysctl/cmdline（isolcpus/irqaffinity/nohz_full）
□ 驱动与固件版本（NIC/RAID/NVMe）
□ 工具完整命令行（一个字符都不能省）
□ 负载参数（大小/并发/时长/随机种子）
□ 环境状态（邻居负载/云实例类型/温度策略）
□ 预热协议（跑几轮丢弃）
```

### 三、六大失败模式的机制解释

失败模式不是「粗心」，每个都有具体的系统原因——理解机制才能在结果里识别出它的味道。

**① 测到 cache 而非磁盘**

```
文件大小 < RAM → page cache 全命中 → 你在测内存，不是盘
```
机制：Linux 读路径先查 page cache（[ch8](../../chapter-08-file-systems/)），命中即返回。1GiB 测试文件在 128GiB 机器上永远热。对策：文件 >> RAM，或 `O_DIRECT` 绕过 cache，或每次 `echo 3 > /proc/sys/vm/drop_caches`（注意这本身会扰动系统——测试间隔里做）。

**② 测到空闲 CPU 而非真瓶颈**

单线程 micro-bench 在 64 核空机上跑——测的是单核极限，不是生产并发下的锁竞争、cache 争用、NUMA 远端访问。机制：生产的瓶颈常常在**共享资源**（锁、内存带宽、LLC），空机单线程根本碰不到。对策：并发度对齐生产，或阶梯加载找拐点。

**③ 冷启动 vs 稳态混淆**

JIT 预热、page cache 冷热、连接建立、分支预测器学习——前 10 秒和第 10 分钟的数字差一个数量级。对策：固定预热轮数并丢弃，报告「稳态从第 N 秒起」。

**④ 邻居/云 steal**

多租户共享物理机，hypervisor 把你的 vCPU 调度走（`%steal`，[ch11](../../chapter-11-cloud-computing/)）。机制：噪声注入随机延迟尖刺——P999 会烂掉但 P50 完好，形成「平均看起来正常」的假象。对策：同机型同 AZ 多跑几轮看方差；裸金属对比。

**⑤ 工具 bug / 错误用法**

fio 的 ioengine 选错（sync vs io_uring）、块大小和队列深度不匹配、iperf3 单流 vs 多流测的是不同东西。对策：[12.3 sanity check](./section-12.3-基准测试方法论.md)——用第二种工具或观测交叉验证。

**⑥ 过度外推**

实验室 100G 回环 → 生产混合流量 + 交易所共置 RTT。机制：线性外推假设瓶颈随负载平移，实际瓶颈会**切换**（CPU → 内存带宽 → NIC 队列）。对策：结论永远标注作用域。

### 四、失败的味道识别表

| 结果特征 | 首先怀疑 |
|---------|---------|
| IOPS 高得离谱（>盘规格） | 测到 page cache |
| P50 正常、P999 烂 | 邻居/steal 或周期性干扰 |
| 前后两轮差 >20% | 预热不足或环境漂移 |
| 单工具结果，换工具翻倍 | 工具用法错误 |
| 单核跑满、多核无提升 | 锁/单线程瓶颈，不是平台问题 |
| 数字完美无 tail | 样本太少或测错层 |

### HFT / 嵌入式关联

- **「testpmd 跑满 100G」≠「order book 更新 P99」**——中间隔着驱动 → 内核栈/DPDK → 解码 → 策略的整条路径，micro 数字只做 capacity baseline。
- **回归检测是 HFT 最常用的基准形态**：每次发版前固定 replay 数据 + 固定环境跑一遍，比对新旧 P99 分布（全分布对比，不是均值对比）——和 [ch16 的 baseline 纪律](../../chapter-16-case-studies/notes/section-16.0-案例背景An-Unexplained-Win.md)是同一套方法论。
- **专用机的意义**：HFT 生产是裸金属 + 隔离核，基准环境必须同构——云虚机上测出的调优结论搬到裸机经常反转。
- **嵌入式**：板卡算力基准（stream/lmbench）要标注温控状态——热降频会让第 10 分钟的数字变成另一台机器。

### 常见陷阱

1. **均值思维**——HFT 一切看 P99/P999，均值会把邻居噪声和周期性尖刺全部抹平。
2. **环境不记录**——三个月后无法复现的数字等于没测过。
3. **把 micro 结论直接上报**——「机器很快」要拆成「哪个组件在什么条件下快」。
4. **预热轮丢弃不标注**——冷热混合的数字无法和下一轮比较。
