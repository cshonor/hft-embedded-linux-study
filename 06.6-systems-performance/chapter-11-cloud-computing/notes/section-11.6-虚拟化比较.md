### 表 11.7 虚拟化技术性能对比

| 属性 | 硬件虚拟化 (KVM) | OS 虚拟化 (容器) | 轻量虚拟化 (Firecracker) |
|------|-------------------|-------------------|--------------------------|
| **CPU 性能** | 高（CPU 支持） | 高 | 高（CPU 支持） |
| **CPU 分配** | 固定到 vCPU | 灵活（shares + bandwidth） | 固定到 vCPU |
| **I/O 吞吐** | 高（含 SR-IOV） | 高（无内在开销） | 高（含 SR-IOV） |
| **I/O 延迟** | 低（SR-IOV + 无 QEMU） | 低（无内在开销） | 低（SR-IOV） |
| **内存访问开销** | 有（EPT/NPT 或影子页表） | 无 | 有（EPT/NPT） |
| **内存损失** | 有（额外内核、页表） | 无 | 有（额外内核、页表） |
| **内存分配** | 固定（可能双重缓存） | 灵活（闲置 guest 内存可用作文件系统缓存） | 固定（可能双重缓存） |
| **资源控制** | 最多（内核 + hypervisor） | 多（取决于内核） | 最多（内核 + hypervisor） |
| **宿主机观测** | 中（资源/hypervisor 统计，看不到 guest 内部） | 高（看到一切） | 中（同 KVM） |
| **客户机观测** | 高（完整内核 + 虚拟设备） | 中（仅用户态，内核计数器受限） | 高（完整内核 + 虚拟设备） |
| **观测优势方** | 终端用户 | 宿主机运维 | 终端用户 |
| **Hypervisor 复杂度** | 最高 | 中（OS 级） | 高 |
| **不同 OS guest** | 是 | 通常不支持 | 是 |

> 注意：此表仅关注性能。其他差异如安全性（容器安全隔离较弱 [Agache 20]）不在此表范围内。

---

### 关键洞察

**微基准比较虚拟化技术是常见但易错的做法** — 只看性能而忽视 **可观测性**，可能错过最大的性能收益。

> *Observability often makes it possible to identify and eliminate unnecessary work, making possible performance wins far greater than minor hypervisor differences.* — Gregg

| 角色 | 最佳选择 | 原因 |
|------|----------|------|
| **云运营商** | 容器 | 宿主机能看到所有进程及其交互 |
| **终端用户** | 虚拟机 | 有内核访问权限，可运行 perf/ftrace/BPF |
| **自托管** | 容器 + 内核访问 | 运维和用户都全可见（但缺安全隔离） |

**轻量级硬件虚拟化**（如 Firecracker）是近年新趋势 — 兼顾终端用户可观测性和快速启动，预计使用量将增长。

---

### HFT 视角

| 维度 | HFT 选择 | 原因 |
|------|----------|------|
| **CPU 性能** | 裸机 > 一切 | 任何虚拟化开销在 μs 级都是致命的 |
| **I/O 延迟** | 裸机 + SR-IOV 或 DPDK | SR-IOV 可接近裸机但仍有 hypervisor 开销 |
| **可观测性** | 裸机 | 完整内核访问 — perf/ftrace/eBPF 全可用 |
| **隔离性** | 裸机独占 | noisy neighbor 在 HFT 不可接受 |

**HFT 不用虚拟化** — 但理解此表有助于：
1. 云上回测/开发环境选型（容器够用）
2. 共置服务器上隔离不同策略进程（cgroup/namespace ≈ 容器思路）
3. 评估未来轻量虚拟化是否可能用于 HFT（Firecracker + SR-IOV 的延迟已在接近裸机）
