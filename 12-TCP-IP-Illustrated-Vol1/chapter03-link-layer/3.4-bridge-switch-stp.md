## 零、核心笔记总览（大白话 · 可直接抄）

### 1）交换机怎么知道 MAC？（MAC 地址表）

交换机**自己学**，不是手配表。

1. 帧头自带**源 MAC**  
2. 交换机：这个 MAC 从**这个端口**进来  
3. 记录 **`MAC ↔ 端口`** → **MAC 地址表**  
4. 以后再找该 MAC → **查表单端口转发**

> **听谁从哪个口来，就记下来。**

### 2）802 系列都是啥？（一句话地图）

> **IEEE 802** = 局域网标准大集合 · **802.3** = 以太网本身 · **802.1** = 交换机侧控制（VLAN、优先级、聚合…）

| 标准 | 干什么 | 详读 |
|------|--------|------|
| **802.3** | 以太网帧、速率、CSMA/CD、全双工 | [3.2](./3.2-ethernet-ieee802-encapsulation.md) |
| **802.1Q** | **VLAN 标签**（4 B），**隔离广播域** | [3.2 TCI](./3.2-ethernet-ieee802-encapsulation.md#ch03-2-vlan-tci) |
| **802.1p** | **3 bit 优先级 0–7**，QoS；**嵌在 802.1Q 标签里** | 同上 TCI 的 **PCP** |
| **802.1AX** | **链路聚合 LACP**，多线捆一条，带宽+冗余 | [3.2 §三](./3.2-ethernet-ieee802-encapsulation.md#ch03-2-advanced) |
| **802.3x** | **PAUSE 帧**，二层逐跳流控 | [3.3](./3.3-full-duplex-autoneg.md#ch03-3-pause) |

- **802.1Q**：帧里插标签，划**虚拟局域网**  
- **802.1p**：给流量打分（语音高、普通低），**不是单独一头**，在 Q 的 Tag 里  
- **802.1AX**：几根网线**捆成一根粗的**，断一根还能用  

### 3）全双工 vs 冲突域（复习）

- **Hub 半双工**：大家抢**一条总线** → **全网一大冲突域** → CSMA/CD 监听**整网**  
- **Switch 全双工**：每端口**发线 + 收线**分开 → 端口 1 与 2 **永不冲突** → 域缩到**单端口小盒子**；仅**同主机在端口内乱发**才可能端口内干扰 → [§1.1](#ch03-4-collision-plain)

### 4）端口双向 + 泛洪铁律（复习）

- 端口**可进可出**，入/出由**当前帧**决定 → [§1.2](#ch03-4-port-bidir)  
- 泛洪：**本帧**不向**本帧入端口**回发 → [§1.3](#ch03-4-flood-plain)

### 考试四行总结

1. **MAC 学习**：源 MAC + 入端口 → 自动生成 **MAC–端口表**。  
2. **全双工**：冲突域 → **单端口**；端口间无冲突；**CSMA/CD 失效**。  
3. **802**：**Q**=VLAN 广播域 · **p**=优先级在 Tag 内 · **AX**=LACP 聚合 · **3x**=PAUSE。  
4. **端口双向**；**本帧**泛洪**不回本帧入端口**。

→ 交换芯片/矩阵、MAC表 vs 路由表：[3.12 硬件转发](3.12-switch-router-hardware.md#ch03-12-cheat)

## 一、交换机工作原理（考试标准版）

### 1）学习（Learning）

→ 大白话：[§零.1](#ch03-4-core-summary)

- 每收到一帧：提取 **源 MAC + 入端口**
- 写入/更新 **MAC 地址表**（**MAC ↔ 端口** 映射）

### 2）转发 / 过滤（Forwarding / Filtering）

查 **目的 MAC**：

| 目的类型 | 行为 |
|----------|------|
| **已知单播** | 仅从**对应唯一端口**转发 |
| **未知单播** | **泛洪**（**本帧**除入端口外所有口）→ [§1.3](#ch03-4-flood-plain) |
| **广播、组播** | **泛洪**（**本帧**除入端口外所有口） |

→ 端口双向：[§1.2](#ch03-4-port-bidir)

### 3）隔离冲突域

- **每个端口 = 独立冲突域**
- **全双工**下基本**无冲突**，**不用 CSMA/CD** → 大白话：[§1.1](#ch03-4-collision-plain) · [3.2](./3.2-ethernet-ieee802-encapsulation.md#ch03-2-mac-evolution)

### 4）广播域

- 默认：**所有端口同一广播域**
- 划分：**VLAN（802.1Q）** 隔离广播域 → [3.2 VLAN](./3.2-ethernet-ieee802-encapsulation.md#ch03-2-vlan-tci)

> **一句话**：**查 MAC 表精准转发，隔离冲突域，VLAN 隔离广播域。**

### 简答题标准答案（可直接抄）

1. **学习**：收帧记 **源 MAC–入端口**，维护 **MAC 地址表**。  
2. **转发**：查目的 MAC — **已知单播** → **单端口转发**；**未知单播/广播/组播** → **泛洪**（不含入端口）。  
3. **冲突域**：**每端口独立**；全双工**无 CSMA/CD**。  
4. **广播域**：默认**同一广播域**；**802.1Q VLAN** 划分隔离。  
5. 总结：交换机 = **L2 按 MAC 转发**；**拆冲突域、VLAN 拆广播域**。

<a id="ch03-4-collision-plain"></a>

### 1.1 大白话：为什么冲突域变成「每个端口」？

#### 以前：集线器 Hub（半双工）

- 所有电脑**共享一条总线**，**抢一条路**说话  
- 两人同时发 → **全网冲突**  
- 必须 **CSMA/CD 监听整网** → **整个网络 = 一个大冲突域**

#### 现在：交换机 + 全双工

每个端口是**物理分开的一对线**：

```text
  主机 ──发线──▶ 交换机端口
  主机 ◀──收线──  交换机端口
```

- **发、收两条线分开**，互不抢信道  
- A 走**端口 1**、B 走**端口 2** → **A、B 之间不会冲突**（不同线、不同端口）

**为什么冲突只在「端口内部」？**

- 只有**同一台主机**在自己端口的**发/收线对上**同时乱发，才可能在**该端口内部**产生信号问题  
- **端口 1 与端口 2**：线路**完全独立** → **永远不会互相冲突**  
- **冲突域** = 每个端口一个**独立小盒子**；不再是整网一个大域

**结论**：冲突从「**整网/整条通道**」→「**单端口内部**」；**CSMA/CD 失效**。

---

<a id="ch03-4-port-bidir"></a>

### 1.2 大白话：端口是「双向」的（输入/输出看当前这一帧）

> **核心**：**对！入端口完全可以变成出端口。**  
> 端口**不固定**叫输入或输出——**这一帧从哪进、从哪出，才决定谁是入/出**。

**例子：端口 1、端口 2**

| 时刻 | 发生的事 | 端口 1 | 端口 2 |
|------|----------|--------|--------|
| A → B | A 发帧给 B | **输入**（帧从 1 进） | **输出**（从 2 发出） |
| B → A | B 回复 A | **输出**（从 1 发出） | **输入**（帧从 2 进） |

**所以**：端口 1 **一会儿输入、一会儿输出**；MAC 表记的是 **`MAC ↔ 端口`**，不管上一帧是进还是出，**要发给该 MAC 时，这个口就是输出**。

> **终极一句**：端口**双向**；**仅对当前这一帧**，不向**本帧的入端口**泛洪/回发。

---

<a id="ch03-4-flood-plain"></a>

### 1.3 大白话：泛洪发给谁？（补牢）

> **考试铁律**：**这一帧**从哪个口进来，**这一帧**绝不从该口再发出去；发给**其余所有口**。

- 每一帧**只有一个入端口**（本帧的 ingress）  
- **不存在**同一帧多个入端口

**和「双向」不矛盾**

- 帧从**端口 1 进** → 泛洪时**不发回 1**（刚进来再发回无意义，还可能环路）  
- **不代表端口 1 永远不能输出**——**下一帧**完全可以从端口 1 **输出**给别的口

**例子**：交换机 **端口 1、2、3、4**

```text
情况 A — 已知单播
  帧从 端口1 进，目的 MAC 在 端口3
  → 只转发到 端口3

情况 B — 未知单播 / 广播 / 组播（泛洪）
  帧从 端口1 进
  → 发给：端口2、端口3、端口4
  → 绝不发回 端口1
```

| 你的疑问 | 答案 |
|----------|------|
| 入端口几个？ | **每帧只有 1 个**（从哪进就是哪） |
| 泛洪发给谁？ | **除入端口外所有其他口** |
| 会发回进来的口吗？ | **绝对不会** |

**三句背诵**

1. **全双工**：每端口收发分离 → 冲突域 → **单端口**；端口间不冲突。  
2. **端口双向**：入/出看**当前帧**；MAC 表记 **MAC↔端口**。  
3. **泛洪**：**本帧**从某口进 → **本帧**不发回该口；**下一帧**可从该口出。

## 二、STP / RSTP 生成树（考试极简背诵版）

<a id="ch03-4-loop-hazards"></a>

### 1）物理环路的 3 个危害（同一拓扑例子）

**拓扑**：**S1 ↔ S2** 用**两根网线**互联（冗余），形成**物理环路**；电脑 **A** 接在 S1，发**广播帧**（如 ARP）。

```text
        [A]──S1══链路1══S2
              ╲        ╱
               ╲链路2╱
                ╲    ╱
                 S1─S2  （环路）
```

#### 危害 1：帧无限泛洪（无限转圈）

1. A 发广播 → 到 **S1**  
2. S1 经**链路 1** → **S2**  
3. S2 经**链路 2** → 又回 **S1**  
4. S1 再发 S2、S2 再发 S1……  
→ **同一帧在两台交换机之间永远转圈**，无限复制、无限转发

#### 危害 2：广播风暴（网络卡死）

- 广播帧本来就要**泛洪所有端口**  
- 环路里**每转一圈复制一遍** → 包越来越多  
→ **带宽占满、CPU 爆满**，局域网瘫痪，大家都上不了网

#### 危害 3：MAC 地址表震荡

1. S1 先学到：**A 的 MAC 在端口 1**  
2. 环路转一圈，A 的帧又从**另一根线**进来  
3. S1 又记：**A 在端口 2**  
→ **一会儿端口 1、一会儿端口 2**，表疯狂刷新 → **转发出错、交换机混乱**

<a id="ch03-4-stp-plain"></a>

### 2）STP / RSTP 到底是什么？（全程用 S1–S2 例子）

> **STP**：交换机之间的规则，自动把环路里**其中一根网线逻辑关掉**——**线还插着、灯还亮，数据不许走**。  
> **RSTP**：**更快版 STP**，干的事一样。

**同一拓扑**（与 [§1](#ch03-4-loop-hazards) 相同）：

```text
  链路1：S1 端口1 ═════ S2 端口1
  链路2：S1 端口2 ═════ S2 端口2
        （物理上是环 → 会风暴/泛洪）
```

**STP 目标**：两根线**只让一根通**，另一根**逻辑堵掉** → 环变树。

#### 四步选举（通俗版 + 例子）

| 步 | 干什么 | 本例（假设 S1 赢） |
|----|--------|-------------------|
| **① 根桥** | **Bridge ID 最小** = 优先级 + MAC，**越小越优**（默认优先级 32768） | **S1 = 根桥（老大）**，S2 是小弟 |
| **② 根端口 RP** | 非根交换机上，**到根桥路径开销最小**的口（回家最近的门） | **S2 端口 1** = RP（经链路 1 回 S1 最近） |
| **③ 指定端口 DP** | 每条链路上，**离根更近**的一侧负责转发 | **链路 2**：**S1 端口 2** = DP（更靠近根） |
| **④ 阻塞端口 BP** | **剩下**的口 → **逻辑关掉**，不转发 | **S2 端口 2** = BP（既不是 RP 也不是 DP） |

**选完后的文字拓扑图**（角色标注）

```text
        [A]── S1（根桥 Root）
              │
    链路1 通 │ S1:P1 ═══ S2:P1  (S2 的 RP 根端口)
              │
    链路2     │ S1:P2 ═══ S2:P2
         S1:P2=DP(转发)   S2:P2=BP(阻塞✕)
```

#### 什么叫「逻辑阻断」？

| | 说明 |
|---|------|
| **物理** | 网线插着、链路 UP、灯亮 |
| **逻辑** | 交换机软件**禁止该端口转发/学习帧** |

> 像**门还在，但锁死不让进**——线没拔，**数据不许走**。  
> 本例：**链路 1 工作**；**链路 2 物理在，S2 端口 2 被 STP 锁死** → 环路消失。  
> **链路 1 断了**，STP/RSTP 会**打开备份口**顶上（收敛时间 STP 慢、RSTP 快）。

#### STP vs RSTP（大白话）

| | **STP 802.1D** | **RSTP 802.1w** |
|---|----------------|-----------------|
| 干啥 | 堵环路、留备份 | **一样** |
| 收敛 | **30～50 秒**（断线切换慢） | **1～2 秒**（几乎无感） |
| 机制 | 计时器多、偏死板 | **握手协商**，少傻等 |
| 兼容 | — | **兼容老 STP** |

**一句**：**STP 慢，RSTP 快；都是堵环路、保冗余。**

| 术语 | 说明 |
|------|------|
| **BPDU** | 交换机之间交换 STP/RSTP 信息的报文（约 2 s 一发）→ 大白话与伪造攻击：[3.10 §BPDU](../3.10-link-layer-security.md#ch03-10-bpdu) |

#### 四句话写笔记

1. 有物理环时，STP/RSTP **逻辑阻塞一条冗余链路**，消环。  
2. 四步：**选根桥 → 根端口 RP → 指定端口 DP → 阻塞 BP**。  
3. **逻辑阻断** = 线还插着，软件禁止转发。  
4. **STP 慢、RSTP 快**。  
→ 两台入门见上；**四台大环精讲**见 [§3](#ch03-4-stp-4switch)。

<a id="ch03-4-stp-4switch"></a>

### 3）四台交换机完整选举（S0–S3，重点 RP / DP）

#### 拓扑与前置规则

**交换机**：S0、S1、S2、S3（物理上**大环 + 冗余**）

| 链路 | 连接 |
|------|------|
| 1 | S0 ↔ S1 |
| 2 | S0 ↔ S2 |
| 3 | S1 ↔ S3 |
| 4 | S2 ↔ S3 |

```text
           S0（本例根桥）
          /  \
    链路1/    \链路2
        /      \
      S1        S2
        \      /
    链路3\    /链路4
          \  /
           S3
```

| 前置 | 本笔记约定 |
|------|------------|
| **桥 ID** | 优先级 + MAC，**数值越小越优** |
| 本例排序 | **S0 < S1 < S2 < S3**（S0 最小 → 当根桥） |
| **路径开销** | 每跨**一段链路**记 **1**（同类型线，简化） |
| **目标** | 唯一根桥 → 每台非根桥一个 **RP** → 每条链路一个 **DP** → 其余 **BP** |

---

#### ① 选根桥

全网 **Bridge ID 最小** = 根桥 → **S0 = 根桥**。  
S1、S2、S3 都是**非根桥**，必须找**回 S0 最近**的口。

---

#### ② 选根端口 RP（非根桥各一个）

> **根端口 RP**：该交换机上，**到根桥路径总开销最小**的端口；**有且只有一个**；默认**经此口回根桥**。  
> **根桥 S0 没有 RP**。

| 交换机 | 到 S0 怎么走 | 总开销 | **RP** |
|--------|--------------|--------|--------|
| **S0** | 自己就是根 | — | **无** |
| **S1** | S1 → S0 直连 | **1** | **连 S0 的口** |
| **S2** | S2 → S0 直连 | **1** | **连 S0 的口** |
| **S3** | ① S3→S1→S0 开销 **2**；② S3→S2→S0 开销 **2** | 相等 | 比**对端桥 ID**：S1 < S2 → 选 **连 S1 的口** 为 RP |

✅ **第二步记法**：每台非根桥挑**回家（去根桥）最近**的那一个口。

---

#### ③ 选指定端口 DP（每条链路一个）

> **指定端口 DP**：这一段网线两端，**离根桥更近**（到根路径开销更小）的那一侧；**负责这条链路上的转发**。  
> **根桥的所有端口天生都是 DP**。

| 链路 | S0 侧开销 | 对端开销 | **DP 在哪一侧** |
|------|-----------|----------|-----------------|
| **1** S0↔S1 | **0**（根上） | S1→根=1 | **S0** |
| **2** S0↔S2 | **0** | S2→根=1 | **S0** |
| **3** S1↔S3 | S1→根=**1** | S3→根=**2** | **S1**（更近） |
| **4** S2↔S3 | S2→根=**1** | S3→根=**2** | **S2**（更近） |

✅ **第三步记法**：**一根线拿出来**，比两端谁离根近，近的那边 = DP。

---

#### ④ 阻塞端口 BP

**规则**：既不是 **RP**，也不是 **DP** → **逻辑阻塞**。

本例唯一被堵的口：**链路 4 上 S3 连 S2 的那一侧**

| 链路 4 端口 | 角色 |
|-------------|------|
| **S2 侧** | **DP**（转发） |
| **S3 侧** | 不是 S3 的 RP（RP 在连 S1），也不是本链 DP → **BP ✕** |

**选完后的角色总图**

```text
           S0 [根]  两口皆 DP
          /  \
    DP   /    \   DP
        S1      S2
   RP↗ /        \ ↖RP
      /   DP  DP  \
     S3──RP──┘    └──(S3连S2)=BP阻塞✕
         (经S1回根)
```

数据不能再沿 **S3→S2→S0→S1→S3** 转圈；**物理环还在，逻辑无环**。

---

#### 逻辑阻断（四台场景）

| 层面 | 说明 |
|------|------|
| **物理** | 线插着、灯亮、没拔线 |
| **逻辑** | 软件**不转发业务帧**；仍可收发 **BPDU** 监测链路 |
| **本例** | **S3↔S2** 被堵；主路径经 **S3↔S1** |
| **冗余** | **S3↔S1** 断了 → STP/RSTP 检测故障 → **解开 S3↔S2 阻塞**，备份顶上（STP **30～50 s**，RSTP **1～2 s**） |

---

#### STP vs RSTP（选举规则相同）

| 对比 | **STP 802.1D** | **RSTP 802.1w** |
|------|----------------|-----------------|
| 选根/RP/DP/阻塞 | **完全一样** | **完全一样** |
| 收敛 | **30～50 s**，计时器死板 | **1～2 s**，**握手协商** |
| 端口角色 | 较简，状态多 | 增**替代/备份**口等，更细 |
| 兼容 | 老设备常见 | **向下兼容 STP** |

**一句**：规则一样堵环；**STP 切换慢，RSTP 切换快**。

#### 六句话复盘（四台版笔记）

1. 桥 ID 最小 → **S0 根桥**。  
2. 非根桥各一个 **RP**：S1、S2 直连 S0；S3 开销相同时 **选桥 ID 小的邻居（S1）**。  
3. 每条链路 **DP** 在离根近的一侧；**S0 各口皆 DP**。  
4. **S3 连 S2** = **BP**，逻辑阻断。  
5. 逻辑阻断 = 硬件正常、**业务数据不许转发**。  
6. **RSTP** = 同样选举，**故障切换更快**。  
→ **RP 和 DP 会不会是同一个口？** 见 [§4](#ch03-4-stp-rp-dp)。

<a id="ch03-4-stp-rp-dp"></a>

### 4）RP / DP / 转发 / 开销：角色分清（四台拓扑）

#### 基础概念（用词统一）

| 词 | 大白话 |
|----|--------|
| **端口转发** | 帧从**入端口**进，从**另一端口**出；能转发**业务数据** = 工作口 |
| **路径开销** | 到根桥的「路程」；**越小越优**（本笔记每段链路 = 1） |
| **阻塞** | **不转发业务帧**（仍可收发 **BPDU**） |

> **先记死一句**  
> **RP**：站在**单台非根交换机**上 → **往根桥走**（回中心），**全机只有 1 个**  
> **DP**：站在**单条物理链路**上 → **这条线往外传的负责人**，**每条线只有 1 个**

非根桥上：**1 个 RP** + **可有多个 DP**（连不同邻居的若干条线各有一个 DP 侧在「对端」或本机，见下表）。

**小区类比**：S0 = 小区大门（根桥）· **RP** = 每栋楼的**主楼道（回家最近）** · **DP** = 楼间通道的**通行口（负责递话）**

---

#### 根桥 S0：为什么「所有口都是 DP」？

| 事实 | 说明 |
|------|------|
| 根桥到根的路径开销 | **= 0**，全网最小 |
| 任意连着根的链路 | 比两端开销，**根桥侧永远更小** → 该侧必为 **DP** |
| 本例 S0 | 连 S1、连 S2 的两个口 **全是 DP**（正常转发），**没有 RP** |

```text
  S0 [根] ──DP── S1   （S1 对端 = S1 的 RP）
       └──DP── S2   （S2 对端 = S2 的 RP）
```

根桥是全网**数据集散中心**：各口都负责和周边交换机**双向互通**。

#### 易混两点

| 误区 | 正解 |
|------|------|
| **DP = 只出不进？** | **否**。DP 端口**双向转发**（能收能发），只是这条链路上 STP 认定的**主导转发口**。 |
| **只有根桥才有 DP？** | **否**。**非根桥也可以有 DP**。例：链路 **S1↔S3** → **S1 侧 = DP**（非根 S1 上的口），**S3 侧 = S3 的 RP**。 |

**各机端口角色一览（本例）**

| 交换机 | RP | DP | BP |
|--------|----|----|-----|
| **S0 根桥** | 无 | **全部端口** | 无 |
| **S1、S2** | 连 S0 的口 | 连 S3 的口（S1）/ 连 S3 的口（S2） | 无 |
| **S3** | 连 S1 的口 | 无 | 连 S2 的口 |

---

#### 四条链路：逐段看 RP 与 DP（同一拓扑 [§3](#ch03-4-stp-4switch)）

| 链路 | 到根开销 | **DP（链路负责人）** | 对端常见角色 |
|------|----------|----------------------|--------------|
| **S0↔S1** | S0=0，S1=1 | **S0 侧** | **S1 侧 = S1 的 RP** |
| **S0↔S2** | S0=0，S2=1 | **S0 侧** | **S2 侧 = S2 的 RP** |
| **S1↔S3** | S1=1，S3=2 | **S1 侧** | **S3 侧 = S3 的 RP** |
| **S2↔S3** | S2=1，S3=2 | **S2 侧** | **S3 侧 = BP**（既非 S3 的 RP，也非本链 DP） |

**关键（链路 3）**：S3 连 S1 的口 —— 在 **S3 上**是 **RP**；在 **S1↔S3 这条线**上 **DP 在 S1 侧**。  
👉 **RP 和 DP 不是同一个物理口**；是**链路两端两个不同交换机上的两个口**。

---

#### 核心疑问：本机的 RP 会不会变成本机的 DP？

| 情况 | 结论 |
|------|------|
| **同一台交换机、同一个口** | **不会**。RP = 向上回根；DP = 向下/向邻居主导转发，**方向相反，互斥**。例：S3 连 S1 的口**只是 S3 的 RP**，**不会是 S3 的 DP**。 |
| **一条链路的两端** | **一端多为 DP，对端多为 RP**（S0↔S1、S1↔S3 等）。这是**两个设备上的两个口**，不是「一个口变身」。 |
| **根桥 S0** | **没有 RP**；**所有口都是 DP**（向外转发）。 |

**一句话**：**同一物理口，不能既是本机 RP 又是本机 DP**；链路上**一端 DP、一端常是 RP**（或一端 BP）。

---

#### 转发举例（S3 下的电脑）

| 方向 | 路径 |
|------|------|
| **S3 终端 → 全网** | 进 S3 → 经 **RP（连 S1）** → S1 → … → 根 **S0** |
| **S0 回包 → S3 终端** | S0 → S1 → 经 **DP（S1 连 S3 一侧）** → S3 → 终端 |
| **备份线 S2↔S3** | S3 连 S2 口 **BP**，**不转发业务**；**S1↔S3 断了** 后该口可重新选举（常升为 **新 RP**），RSTP 更快 |

---

#### 五句极简笔记（RP/DP 专抄）

1. **根桥**：到根开销 **0** → **所有端口都是 DP**（集散中心，双向转发）。  
2. **非根桥**：**1 个 RP**（回根）+ **可有 DP**（向邻居，如 S1 连 S3）+ 其余或 **BP**。  
3. **DP**：每条链路**唯一**、**双向**；到根开销更小的一侧当选。  
4. **同口不能既本机 RP 又本机 DP**；链路上常 **一端 DP、一端 RP**（不同设备的两口）。  
5. **BP**：既非 RP 也非 DP → **逻辑阻断**。

<a id="ch03-4-stp-exam"></a>

### 简答题标准答案（可直接抄）

1. **环路危害**（S1–S2 双链路）：无限转圈 · 广播风暴 · MAC 震荡。  
2. **STP 是什么**：自动**逻辑堵一条冗余线**，物理环变**无环树**。  
3. **四步**（两台 S1 根）：根桥 → **RP** → **DP** → **BP**（例：S2:P2 阻塞）。  
4. **四步**（四台 S0 根）：S0 根 · S1/S2 **RP 指 S0** · S3 **RP 指 S1**（开销同比桥 ID）· 链路 4 **S3 侧 BP**。  
5. **RP**：非根桥**唯一**，到根开销最小，**回中心**；**不能与本机 DP 同口**。  
6. **DP**：每条链路**唯一**、**双向转发**；离根更近一侧当选；**根桥全部 DP**（开销 0）。  
7. **非根也有 DP**：如 S1↔S3 上 **S1 侧 DP**、**S3 侧 RP**（两端不同口，不是变身）。  
8. **DP ≠ 只出不进**：能收能发，是链路**主导口**。  
9. **逻辑阻断**：既非 RP 也非 DP；网线正常，**业务不转发**。  
10. **STP** 收敛 **30–50 s**；**RSTP** **1–2 s**，选举规则同。  
11. **BPDU**：交换机间交换 STP/RSTP 拓扑信息。

## 三、交换机 L2 vs 路由器 L3（边界精准版）

### 1）交换机 = 二层（L2，数据链路层）

- 只看 **MAC 地址**
- 管**同一局域网内部**（同一广播域 / 常同一 VLAN 内）
- 例：公司**一个部门**、一个 VLAN 里电脑互访

### 2）路由器 = 三层（L3，网络层）

- 看 **IP 地址**（会改 **TTL** 等）
- 管**不同网段、不同 VLAN、内网与外网**
- 例：
  - 部门 A（**VLAN 10**）↔ 部门 B（**VLAN 20**）
  - 公司内网 ↔ **互联网**
  - 大型园区、不同 **AS** 之间

### 3）必背区分

| | **交换机 L2** | **路由器 L3** |
|---|----------------|---------------|
| 寻址 | **MAC** | **IP** |
| 范围 | **局域网内部** | **跨网段 / 外网 / 不同 AS** |
| 广播域 | 默认**不分割**（靠 VLAN） | **分割**广播域 |
| 大型内网 | 同 VLAN 内互访 | **不同 VLAN 互通也要三层设备**（路由器或**三层交换机**） |

> **交换机管局域网内部；路由器管跨网段、跨外网；大内网 VLAN 互通靠路由器/三层交换机。**

→ [ch01 易混](../chapter01-overview/study.md) · 自顶向下：[§6.4](../../top_down/06_link_layer_and_lan/6.4_ethernet_arp_switch_vlan/study.md)

### 极简笔记（环路 + STP + L2/L3）

1. **环路危害**：无限泛洪 · 广播风暴 · MAC 震荡  
2. **STP/RSTP**：逻辑阻塞冗余口 → 无环树；STP 慢、RSTP 快  
3. **L2 vs L3**：交换机 MAC/局域网内；路由器 IP/跨网段外网

## 五、自测（9 题）

1. 交换机收到目的 MAC 不在表中的单播帧，如何处理？  
2. 交换机能否隔离广播域？默认情况下呢？  
3. 为何交换端口一般不需要 CSMA/CD？全双工后冲突域为何缩小到端口？  
4. 帧从端口 2 进入，需要泛洪时，会发给哪些端口？会发回端口 2 吗？  
5. 端口 1 能否既是输入又是输出？和「不发回入端口」矛盾吗？  
6. 物理环路会导致哪三种危害？（各一句）  
7. STP 解决什么问题？四步选举各选什么？  
8. 部门 VLAN10 访问 VLAN20，靠二层交换机还是路由器？  
9. STP 与 RSTP 在收敛时间上的主要区别？

<details>
<summary>答案</summary>

1. **泛洪**到除入端口外的**所有端口**（未知单播）。  
2. **能**（用 **VLAN**）；**默认不能**，所有端口**同一广播域**。  
3. **每端口独立线对** + **全双工**，端口间不抢总线；冲突域从整网 → **单端口**。  
4. **端口 1、3、4…（除 2 外所有其他口）**；**本帧绝不发回端口 2**。  
5. **能**；端口双向。矛盾的是**同一帧**不能从入端口再发出；**下一帧**可从端口 1 输出。  
6. ① 帧在交换机间**无限转圈** ② **广播风暴** ③ **MAC 表**端口映射**震荡**。  
7. **二层环路**三大危害；**根桥 → RP → DP → BP 阻塞**成树。  
8. **路由器或三层交换机**（跨 VLAN 要 **L3**）。  
9. **STP** 约 **30–50 s**；**RSTP** 约 **1–2 s**。
