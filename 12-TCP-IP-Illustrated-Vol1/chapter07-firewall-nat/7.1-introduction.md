## 本节核心目标

理解 **防火墙与 NAT** 作为现代网络边界「守门员」的定位、作用与代价，认清它们如何**破坏端到端透明**却又**不可或缺**。

---

<a id="ch07-1-middlebox"></a>

## 一、背景：为何需要 Middlebox（中间设备）

早期互联网设计是**端到端透明**：

- 网络只负责转发，不修改包、不过滤  
- 双方直接用真实 IP 通信 — 对等、简单、可扩展  

现实两大压力：

| 压力 | 后果 |
|------|------|
| **IPv4 地址枯竭** | 公网 IP 不够，大量设备无法直接获得公网地址 |
| **安全威胁激增** | 内网主机漏洞多、易被攻击，需要边界防护 |

→ 必须在网络边缘部署 **防火墙 + NAT** 等中间设备，**打破端到端透明**，换取 **安全 + 地址复用**。

→ [ch01 端到端原则](../chapter01-overview/study.md#ch01-e2e) · [ch02 私网地址](../chapter02-ip-address-architecture/study.md)

<a id="ch07-1-roles"></a>

## 二、核心角色：防火墙 vs NAT

```mermaid
flowchart LR
  INET[Internet] <-->|过滤| FW[防火墙]
  FW <-->|地址翻译| NAT[NAT]
  NAT <--> LAN[内网主机]
```

### 1）防火墙（Firewall）

| 项 | 说明 |
|----|------|
| **定位** | 网络边界的「**流量警察**」 |
| **过滤** | 按规则（源/目的 IP、端口、协议）放行/丢弃 |
| **隔离** | 阻止非法外网访问内网，减少攻击面 |
| **集中策略** | 不必每台主机单独防护 |

**一句话**：防火墙 = **受限连通 + 策略过滤** → [7.2](7.2-packet-filter-firewall.md)

### 2）NAT（网络地址转换）

| 项 | 说明 |
|----|------|
| **定位** | 地址「**翻译官**」 |
| **地址复用** | 私网（10/8、172.16/12、192.168/16）多主机共享少量公网 IP |
| **隐藏内网** | 外网只见 NAT 公网 IP，不见内网真实地址 |
| **PAT** | 同一公网 IP 用**不同端口**区分不同内网连接 |

**一句话**：NAT = **私网→公网地址转换 + 共享公网 IP** → [7.3](7.3-nat-napt.md)

| 设备 | 主要作用 |
|------|----------|
| **防火墙** | 受限连通、策略过滤 |
| **NAT** | 私网多主机共享少量公网地址 |

<a id="ch07-1-cost"></a>

## 三、核心代价：破坏端到端透明

| 代价 | 说明 |
|------|------|
| **身份不透明** | 地址/端口被改写；对端看不到真实源 IP/端口 |
| **主动连接受限** | 外网默认无法主动访问内网 → **P2P/自托管服务困难** |
| **应用兼容** | 需 **ALG**（FTP、IPsec、SIP 等）；P2P/VoIP 需 **STUN/TURN/ICE** |
| **状态开销** | NAT/防火墙维护会话表 → 延迟与故障点 |

→ [7.4 NAT 穿透](7.4-nat-traversal.md)

<a id="ch07-1-assumptions"></a>

## 四、开发与架构的默认前提

现代应用**必须假设存在 NAT/防火墙**：

- 不能依赖固定公网 IP  
- 须实现**保活（心跳）**，防 NAT 会话超时  
- 服务端需**端口映射/DMZ** 或 P2P 穿透  
- 排障更复杂（真实 IP 隐藏、映射端口不定）

---

<a id="ch07-1-why-necessary"></a>

## 五、为何「明知破坏透明，却仍必需」

| 原因 | 说明 |
|------|------|
| **IPv4 枯竭** | 无 NAT 则无法支撑海量设备联网 |
| **安全边界** | 防火墙是中小企业/家庭最经济的边界防护 |
| **现实妥协** | 端到端理想 vs 安全+成本 → **NAT+防火墙是折中** |
