# 12.2 TCP 的引入

> 章级精读：[../study.md#ch12-2](../study.md#ch12-2) · 自顶向下：[§3.1](../../../top_down/03_transport_layer/study.md#ch3-1-tcp-conn)

## 本节核心目标

理解 TCP **面向连接、全双工、可靠字节流** 与 **序列号** 作用。

---

## 服务模型

| 特性 | 含义 |
|------|------|
| 面向连接 | 数据传输前需**建立连接**（ch13 握手） |
| 全双工 | 两端可同时发/收 |
| 可靠 | 无丢失、无重复、按序交付（对字节流语义） |
| **字节流** | **不保留**应用 `write` 的消息边界 |

---

## 与 UDP 对比

- UDP：一次 `sendto` = 一个 datagram，有边界。
- TCP：多次 `write` 可能被对端一次 `read` 读完（**粘包**），或一次 `write` 被多次 `read`（**拆包**）。

---

## 可靠性手段

- **序列号 / 确认号** 标定字节位置 → 去重、排序、重传依据。
- 结合 12.1 的 ARQ、窗口、RTO。

---

## 应用层必做：封包/拆包

- 常用 **长度前缀**（4 字节 Length + Body）、分隔符、Protobuf 等。
- **不要**指望 TCP 帮你分消息。

---

## Go/Rust

- `net.TCPConn` / `TcpStream`：`Read`/`Write` 是**字节流**，非消息。
