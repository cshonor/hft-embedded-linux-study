# 4.3 ARP 缓存

理解 ARP **缓存表** 是什么、为何能**避免每次广播**；掌握 **动态/静态**、**Linux 邻居状态**、**老化**与查看命令。

<a id="ch04-3-what"></a>

## 一、ARP 缓存是什么？

每台**主机 / 路由器 / 三层交换机**在**内存**里都有一张表：

| 叫法 | 场景 |
|------|------|
| **ARP 缓存表** | IPv4 常用说法 |
| **邻居表（Neighbor Table）** | Linux `ip neigh`、IPv6 ND 也沿用「邻居」概念 |

**存什么**：**IP 地址 ↔ MAC 地址** 映射。

```text
192.168.1.1  →  aa:bb:cc:dd:ee:ff   （网关）
192.168.1.10 →  11:22:33:44:55:66   （某台电脑）
```

### 为什么要有缓存？

| | 无缓存 | 有缓存 |
|---|--------|--------|
| 每次发包 | 都要 **ARP 广播** | **命中**则直接用 MAC |
| 后果 | 广播多、延迟大 | 快、省带宽 |

**一句**：**ARP 缓存 = 局域网 IP–MAC 的「临时通讯录」**。

---

## 二、基本特点

| 特点 | 说明 |
|------|------|
| **只在本机有效** | 每台设备**自己维护**；别人改表**不影响**你 |
| **动态 / 静态** | **动态**（默认）：协议学习，**会老化** · **静态**：手工绑定，常**重启才丢** |
| **工作范围** | **同广播域（同 LAN）**；跨网段靠**路由（IGP/BGP）**，不靠 ARP 穿全程 → [4.2 广播域](../chapter04-arp-protocol/4.2-arp-basic-operation.md#ch04-2-broadcast-boundary) |

## 三、怎么查看？

### Windows / 传统

```bash
arp -a
```

### Linux（推荐，带状态）

```bash
ip neigh
# 或
ip neigh show
```

输出含：**IP、接口、MAC、状态**（REACHABLE / STALE / INCOMPLETE…）

<a id="ch04-3-states"></a>

## 四、Linux `ip neigh` 常见状态

### 核心三种（考点）

| 状态 | 含义 |
|------|------|
| **INCOMPLETE** | 已发 ARP 请求，**还没收到应答**；MAC 未拿到，待发 IP 包常**排队等待** |
| **REACHABLE** | **最近确认可达**；直接用 MAC 发包，**最快** |
| **STALE** | 曾是 REACHABLE，**久未通信**；条目暂留，**下次发包前会探测验证** |

### 其他（了解）

| 状态 | 含义 |
|------|------|
| **DELAY** | 准备探测，先短暂等待 |
| **PROBE** | 正在发 ARP 探测 |
| **FAILED** | 多次探测失败，视为不可达 |

```text
INCOMPLETE →（收到应答）→ REACHABLE →（超时无通信）→ STALE
                                              ↓ 再发包
                                         PROBE / DELAY → REACHABLE 或 删除
```

## 五、超时 / 老化机制

动态条目**不会永久保存**（软状态）→ 详解 [4.6](4.6-arp-cache-timeout.md)

| 系统 | 常见老化（示意） |
|------|------------------|
| **Windows** | 约 **2 分钟** 不用可过期 |
| **Linux / macOS** | 完整条目约 **20 分钟**（与内核参数有关，区间数分钟～20 min） |

**典型生命周期**

1. 首次通信 → ARP 请求/应答 → 写入缓存 → **REACHABLE**  
2. 长时间不用 → **STALE**  
3. 再要发包 → **探测** → 成功回到 REACHABLE；失败则**删条目**  
4. 长期无动静 → 系统自动清理  

**目的**：设备下线、换网卡、IP 变更后，**不长期保留错误映射**。

**不完整条目（INCOMPLETE）**：未收到应答 → **约 3 分钟**即丢弃，避免占表 → [4.6 §INCOMPLETE](4.6-arp-cache-timeout.md#ch04-6-incomplete)

## 六、与 ARP 欺骗的关系

| 点 | 说明 |
|----|------|
| **信任模型** | 收到 ARP **应答**往往**直接更新**本机缓存 |
| **攻击** | 伪造应答：把「网关 IP → 攻击者 MAC」写进你的表 |
| **后果** | 流量经攻击者 → **MITM** |

→ [3.10 ARP 欺骗大白话](../chapter03-link-layer/3.10-link-layer-security.md#ch03-10-arp-spoof) · [4.11 防护](4.11-arp-spoof-defense.md)

<a id="ch04-3-cheat"></a>

## 七、一句话总结（背）

**ARP 缓存 = 本机内存里的 IP–MAC 临时表；同广播域有效；命中免广播；会老化；Linux 有 REACHABLE/STALE/INCOMPLETE；既要省广播，也要防伪造篡改。**

### 三行笔记

```text
1. 缓存 = 临时通讯录；动态会老化，静态手工绑。
2. 命中直接用 MAC；未命中才广播；跨网段不靠 ARP 表穿全程。
3. REACHABLE 最快；STALE 待验证；INCOMPLETE 等应答。
```

## 自测

1. ARP 缓存存在哪？为何需要它？  
2. STALE 和 INCOMPLETE 区别？  
3. 跨网段通信会往 ARP 表里写远端公网 IP 吗？

<details>
<summary>参考答案</summary>

1. **本机内存**；避免**每次**都 ARP 广播。  
2. **INCOMPLETE** = 还没拿到 MAC；**STALE** = 有过映射但需再验证。  
3. **不会**；主机通常只缓存**本网段/下一跳**相关映射，远端靠路由。
