# 6.4 DHCP 和 DNS 交互

> 章级精读：[study.md#ch06-4](./study.md#ch06-4) · DHCP 基础：[6.2](6.2-dhcp-protocol.md) · DNS 动态更新：[ch11 §11.5](../chapter11-dns-domain-resolve/11.5-dns-packet-structure.md) · 公共 DDNS：[ch11 §11.7](../chapter11-dns-domain-resolve/11.7-opendns-dyndns.md)

## 本节核心目标

理解 **DDNS（动态 DNS 更新）** — 联动 DHCP 与 DNS，在 IP 变动时维持**域名 ↔ IP** 映射可用。

<a id="ch06-4"></a>

---

<a id="ch06-4-pain"></a>

## 一、业务痛点

| 现象 | 后果 |
|------|------|
| **DHCP 动态分配**地址 | 租约续期、重连、漫游 → 客户端 **IP 频繁变动** |
| DNS **A/AAAA** 仍为旧 IP | **域名与 IP 映射失效** |
| 用户按**主机名**访问 | 解析到错误地址 → **无法连通** |

```text
DHCP 换 IP → DNS 记录未更新 → ping host.name 仍指向旧地址 → 访问失败
```

**核心矛盾**：DHCP 让 IP **变**；业务希望主机名 **不变**且始终可达。

---

<a id="ch06-4-ddns"></a>

## 二、DDNS（动态 DNS 更新）

### 1. 作用

IP 变更时，**自动同步更新** DNS 的 **A（IPv4）/ AAAA（IPv6）** 记录，维持域名与当前 IP 的对应关系。

### 2. 执行主体

| 发起方 | 场景 |
|--------|------|
| **DHCP 服务器** | 分配/续租/释放地址后，代客户端向 DNS 提交更新（企业常见） |
| **客户端** | 主机自行向 DNS 发送动态更新（RFC 2136 等） |

二者均可；具体取决于网络策略与 DHCP/DNS 集成方式。

### 3. 安全要求

| 项 | 说明 |
|----|------|
| **风险** | 无认证时，攻击者可**恶意篡改** A/AAAA → 劫持、投毒 |
| **缓解** | 必须配置**身份认证**，如 **TSIG**（Transaction SIGnature）、GSS-TSIG（AD 域常见） |
| **原则** | 仅授权主体可更新指定 FQDN 记录 |

→ DNS 动态更新报文：[ch11 §11.5](../chapter11-dns-domain-resolve/11.5-dns-packet-structure.md)

---

<a id="ch06-4-practice"></a>

## 三、实际应用

| 场景 | 说明 |
|------|------|
| **企业 AD 域** | 域内 PC 获 DHCP 地址后自动注册 **A/AAAA + PTR**，主机名即 FQDN |
| **家用路由器** | 内网设备主机名自动注册到本地 DNS / mDNS 类服务 |
| **公网动态 IP** | 家庭宽带 IP 变化时，客户端向 DynDNS 等服务商更新（思路同源） → [ch11 §11.7](../chapter11-dns-domain-resolve/11.7-opendns-dyndns.md) |

<a id="ch06-4-cheat"></a>

## 考点速记

| # | 要点 |
|---|------|
| 1 | **DDNS 核心**：联动 DHCP 与 DNS，**动态刷新域名–IP 映射**（A/AAAA） |
| 2 | **执行主体**：**DHCP 服务器**或**客户端**均可发起更新 |
| 3 | **安全要点**：必须做**身份认证**（如 **TSIG**），避免记录被篡改 |

| 易错 | 正确 |
|------|------|
| DDNS 只更新 PTR | 主要更新 **A/AAAA**（正向）；PTR 反向常一并维护 |
| 任何人可改 DNS | 需 **TSIG/ACL** 等认证授权 |
| IP 变了 DNS 自动跟 | **需 DDNS 机制**主动推送更新 |

---

## 疑问与总结

**背：DHCP 换 IP 致 DNS 失效 → DDNS 刷 A/AAAA；服务器或客户端发起；必须 TSIG 认证。**
