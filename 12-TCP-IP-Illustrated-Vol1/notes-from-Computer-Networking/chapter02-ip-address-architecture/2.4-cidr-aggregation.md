# 2.4 CIDR 与路由聚合

> 章级精读：[../study.md#ch02-4](../study.md#ch02-4) · [编址演进](./2.3-basic-ip-structure.md#ch02-evolution) · [2.6 分配](./2.6-address-allocation.md)  
> 控制平面：[§5 BGP](../../top_down/05_network_layer_control_plane/5.3_bgp_inter_as_routing/study.md) · 精编：[§4.3 CIDR](../../top_down/04_network_layer_data_plane/4.3_ipv4_ipv6_nat/study.md#ch4-3)

## 本节核心目标

搞懂两件事：**CIDR** 让前缀可以按需变长；**路由聚合** 把一堆小网段打包成一条大路由，路由器少记很多条。

> **一句话**  
> **CIDR** = 前缀随便变长（`/24`、`/25`、`/26` 都行，不再死磕 A/B/C 类）  
> **路由聚合** = 一堆小网段打包成一个大网段，路由器**只记 1 条**，路由表变短

## 一、大白话 + 城市小区类比（IPv4）

### 1）CIDR（无分类编址）

不再固定「A 类一定 /8、C 类一定 /24」，**前缀长度可以灵活变长**，大网段、小区按需切，少浪费地址。

### 2）往下分：城市 → 区 → 小区

| 层级 | 比喻 | 例子 | 说明 |
|------|------|------|------|
| **城市** | 一大片 | `192.168.1.0/24` | 前缀 **24 位**，整块城市 |
| **区** | 城市拆两半 | `192.168.1.0/25`、`192.168.1.128/25` | 前缀变 **/25**，每块更小 |
| **小区** | 区再拆 | `192.168.1.0/26`、`192.168.1.64/26` … | 前缀变 **/26**，更小 |

👉 **越往下分：前缀数字越大（/24 → /25 → /26），网段越小**

> **`/数字` = 前多少个二进制位是网络部分**（和 [2.7 IPv6 `/3`](./2.7-unicast-allocation.md#ch02-7-ipv6-prefix) 同一套规则）

### 3）往上聚：小区 → 区 → 城市（路由聚合 / 超网）

运营商那边**不记**一堆 `/26`、一堆 `/25`，而是**打包汇总**成一条，例如：

```text
路由器只记：192.168.1.0/24  →  这一片都往这儿走
不用记：     一堆 /25、一堆 /26
```

**效果**：路由表条目**大幅减少**，转发更快、更省内存。

### 口诀（必背）

| 方向 | 规律 |
|------|------|
| **往下分** | 前缀变大 `/24` → `/25` → `/26`，**网段变小** |
| **往上聚** | 前缀变小 `/26` → `/25` → `/24`，**网段变大，路由变少** |

## 二、笔记可直接抄（标准大白话）

1. **CIDR（无分类编址）**  
   不再固定 A/B/C 类，**前缀可以灵活变长**：大网段用 `/24`，往下分区用 `/25`，分小区用 `/26`，按需划分，不浪费地址。

2. **路由聚合（超网）**  
   把下面一堆小网段（`/25`、`/26`）**汇总成一个大网段 `/24`**，路由器只存这一条路由，**大幅减少路由表数量**，提高转发效率。

<a id="ch02-4-bgp"></a>

## 三、和 BGP 怎么串起来？（CIDR 绑定版）

> **BGP = AS 和 AS 之间，互相交换「CIDR 聚合后的大网段」**  
> 它**不会**把小区 `/26`、区 `/25` 发到全球，只传**城市 `/24` 这种最外层汇总路由**。

### 用城市例子走一遍

```text
企业内网：  小区 /26 → 区 /25 → 城市 /24（CIDR 聚合汇总）
                    ↓
对外宣告：  用 BGP 告诉其他运营商：
            「这个 x.x.x.0/24 大段，在我这里」
```

| 层级 | 谁管 | 发不发全球 |
|------|------|------------|
| `/26`、`/25` | 企业/园区**内部** | ❌ 不往外发 |
| `/24`（聚合后） | **边界 + BGP** | ✅ **只发这种大前缀** |

> 教学用 `192.168.1.0/24` 当比喻；**真实互联网 BGP 宣告的是公网前缀**（PA/PI），私网不会进全球 BGP 表。

### 笔记可直接抄（概念对齐）

| | 干什么 |
|---|--------|
| **CIDR** | **内部划分** + **向上聚合**（小网段打包成 `/24`） |
| **BGP** | **AS 之间**的协议，**只传递聚合后的大前缀**（最外层汇总地址） |

**逻辑链条（必背）**

```text
内网细分（/26、/25） → CIDR 聚合（/24） → BGP 对外宣告（/24）
```

**终极一句**：**CIDR 负责打包汇总，BGP 负责把汇总后的大网段，在互联网上发给其他运营商。**

→ 边界宣告在 [2.7](./2.7-unicast-allocation.md#ch02-7-enterprise) · 分得地址≠全球可达：[2.6](./2.6-address-allocation.md) · BGP 详解：[§5.3 BGP](../../top_down/05_network_layer_control_plane/5.3_bgp_inter_as_routing/study.md)

### CIDR 专业要点

**Classless Inter-Domain Routing** — 无类前缀，废除 A/B/C 刚性边界

| 要点 | 说明 |
|------|------|
| 格式 | **网络前缀 + 主机位**，`/x` 任意 |
| 掩码 | `/24` ↔ `255.255.255.0` |
| 解决问题 | **地址枯竭** + 为**聚合**打基础（缓解 **ROAD**） |

| 前缀 | 用途 |
|------|------|
| **`/32`** | 主机路由 |
| **`/31`** | 点对点（2 地址） |
| **`/0`** | 默认路由 |

### 路由聚合原理

- 多条**连续、前缀高位相同**的小路由 → **一条更短前缀（超网）**
- 找**最长公共前缀（LCP）**；聚合后前缀**变短**、覆盖变大

**三步**：① 转二进制 ② 从左找相同位 → 新前缀长度 ③ 网络地址 = 公共前缀 + 主机位全 0

**例题**：`192.1.12.0/24`～`192.1.15.0/24` 四个

```text
第三字节 12–15 前 6 bit 相同 → /22
→ 192.1.12.0/22
```

**聚合条件**：连续 · 高位相同 · 聚合后前缀变短

**BGP**：ISP 向上游常只通告**聚合路由** → [2.6](./2.6-address-allocation.md)

### 拓扑敏感（易聚合 vs 难聚合）

```text
难聚合：核心多条 /24 各指不同路由器
易聚合：核心一条 /22 覆盖 .24–.27
```

→ 章级图：[study.md §2.4](../study.md#ch02-4)

### 30 秒 + 自测

| 概念 | 一句话 |
|------|--------|
| CIDR | 无类 `IP/x`，按需分前缀 |
| 聚合 | 连续小前缀 → 更短一条，表项少 |

1. 能否把 `10.1.0.0/24` 与 `10.2.0.0/24` 聚合成一条？  
2. 单条 `172.16.0.0/16` 能随意「聚成」`/8` 吗？

**答案**：1）一般**不能**（第三字节不连续/公共前缀不够）。2）**不能**——聚合是合并**多条连续小路由**，不是把单条随意缩短。
