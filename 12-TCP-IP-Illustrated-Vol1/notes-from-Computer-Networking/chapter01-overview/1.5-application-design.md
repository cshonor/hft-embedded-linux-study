# 1.5 设计应用 (Designing Applications)

> 章级导读：[../study.md](../study.md) · Socket：[#ch1-socket](#ch1-socket)

## 本节核心目标

理解 **C/S** 与 **P2P** 架构差异，以及应用如何通过 **API（套接字）** 使用协议栈。

---

## 客户机 / 服务器 (C/S)

- **服务器**：被动监听、长期运行，处理并发请求（多进程/多线程/事件驱动）。
- **客户端**：主动发起连接/请求。
- 典型：Web、邮件、数据库访问。

→ **C/S → B/S 演进、HTTP 对齐**：[1.1 §四](./1.1-architecture-principles.md#ch1-1-cs-bs)

---

## 对等 (P2P)

- 节点**既消费又提供服务**（如 Skype、BitTorrent）。
- 优势：去中心、扩展性好、分担带宽与存储。
- 代价：NAT 穿透、成员管理、内容可用性更复杂。

| | C/S | P2P |
|--|-----|-----|
| 中心性 | 明确服务器 | 常无固定中心 |
| 扩展 | 服务器可能成为瓶颈 | 节点越多资源越多 |
| 运维 | 集中升级 | 版本/信誉分散 |

## API 与套接字 (Socket)

- 应用程序不直接操作网卡，通过 **Socket API** 与内核协议栈交互（`socket` / `bind` / `listen` / `connect` / `send` / `recv` 等）。
- 套接字 = **IP + 端口 + 协议** 在主机上的抽象端点。
- 与 [Computer Networking 2.7](../../../top_down/02_application_layer/2.7_socket_programming_tcp.md) 编程章可交叉练习。
