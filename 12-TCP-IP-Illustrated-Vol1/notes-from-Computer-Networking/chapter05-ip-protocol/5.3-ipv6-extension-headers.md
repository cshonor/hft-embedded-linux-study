# 5.3 IPv6 扩展头部

> 章级精读：[study.md#ch05-3](./study.md#ch05-3) · IPv6 固定头：[5.2 §三](5.2-ipv4-header.md#ch05-2-ipv6) · 分片：[ch10](../chapter10-udp-ip-fragment/study.md) · IPsec：[ch18](../chapter18-network-security/study.md) · ICMPv6：[ch08](../chapter08-icmpv4-icmpv6/study.md)

## 本节核心目标

理解 IPv6 **菊花链（daisy-chaining）** 扩展头设计、**Next Header** 串联规则，以及各常见扩展头的用途与转发语义。

---

<a id="ch05-3-design"></a>

## 一、核心设计思想

| # | 要点 |
|---|------|
| 1 | **基础头部固定 40 字节**，无可变选项字段 → 主干路由器**仅解析主头**，转发效率高 |
| 2 | 附加功能（路由、分片、安全、逐跳控制等）剥离为**扩展头部**，**菊花链（链式）**依次串联 |
| 3 | 扩展头**按需添加**；无对应功能则不携带 → 兼顾**转发性能**与**功能扩展性** |

**背景**：IPv4 **Options** 内嵌主头、变长解析、每跳校验和 → 拖慢路由器；IPv6 将「非每跳必需」功能**下沉**到扩展头 → [5.2 对比](5.2-ipv4-header.md#ch05-2-overview)

<a id="ch05-3-chain"></a>

## 二、链式规则 & Next Header 字段

### 报文结构

```text
IPv6 主头 → 扩展头1 → 扩展头2 → … → 上层协议（TCP/UDP/ICMPv6）
```

### Next Header（下一个头部）

位于**每个头部**中，标识**紧随其后的头部类型** — 串联扩展链的**核心字段**。

| 位置 | Next Header 指向 |
|------|------------------|
| **主头** | 第一个扩展头，或**直接**指向上层协议（无扩展头时） |
| **每个扩展头** | 下一个扩展头，或最终**上层协议** |
| **链末扩展头** | 承载的**传输层 / ICMPv6** 等协议 |

### 链式示意

```text
[ IPv6 固定头 NH=0 ] → [ 逐跳选项 NH=43 ] → [ 路由头 NH=44 ] → [ 分片头 NH=6 ] → [ TCP ] → Data
```

IPv4 的 **Protocol** 字段在 IPv6 中由 **Next Header** 承担分用职责（含扩展头链）→ [5.2 §Protocol](5.2-ipv4-header.md#ch05-2-protocol)

<a id="ch05-3-types"></a>

## 三、常见扩展头及用途

| 扩展头 | NH 值* | 主要作用 | 补充说明 |
|--------|--------|----------|----------|
| **逐跳选项头** (Hop-by-Hop) | **0** | 全网**所有转发节点**必须解析处理 | **唯一**要求沿途路由器**逐跳读取**的扩展头 |
| **路由头** (Routing Header) | **43** | IPv6 **源路由**，指定转发路径节点列表 | 控制报文途经的网络节点；移动性等场景 |
| **分片头** (Fragment Header) | **44** | 报文**分片与重组** | **仅源主机**负责分片；**中间路由器不分片** |
| **目标选项头** (Destination Options) | **60** | **仅最终目的节点**解析生效 | 存放目的端才处理的附加选项 |
| **ESP** | **50** | IPsec **加密** | 网络层安全 → [ch18](../chapter18-network-security/study.md) |
| **AH** | **51** | IPsec **认证** | 完整性校验，不加密载荷 |

\* Next Header 协议号；上层常见：**6**=TCP、**17**=UDP、**58**=ICMPv6

### 分片行为（必考）

| | IPv4 | IPv6 |
|---|------|------|
| 分片位置 | 主头字段；**路由器可分片** | **分片头**扩展头；**仅源节点**分片 |
| 过大报文 | 路由器可能分片转发 | 路由器**丢弃** + **ICMPv6 Packet Too Big** → 源主机调整 MTU 后**端到端分片** |

→ 详：[ch10 分片](../chapter10-udp-ip-fragment/study.md) · [ch08 ICMPv6](../chapter08-icmpv4-icmpv6/study.md)

<a id="ch05-3-compare"></a>

## 四、IPv4 vs IPv6（易混）

| 维度 | IPv4 | IPv6 |
|------|------|------|
| 主头 | **可变**（含 Options，20–60 B） | **固定 40 B**，无内嵌选项 |
| 附加功能 | Options **内嵌**主头 | **扩展头**按需链式挂载 |
| 路由器分片 | **可以** | **不可以** |
| 中间节点解析 | 可能需解析 Options | 默认**只读主头**；除 **Hop-by-Hop** 外多数扩展头**透明转发** |

---

<a id="ch05-3-cheat"></a>

## 五、考点速记

| # | 要点 |
|---|------|
| 1 | IPv6 主头**固定 40 字节**，无变长选项，主干转发开销远低于 IPv4 |
| 2 | 扩展头以**菊花链**串联，靠 **Next Header** 标识后继头部 |
| 3 | 扩展头**按需携带**，非必选；中间路由器**默认不解析**大部分扩展头 |
| 4 | IPv6 分片：**仅源节点**用分片头；转发设备**不执行分片** |
| 5 | **Hop-by-Hop（NH=0）** 是唯一要求**每台**路由器处理的扩展头 |

| 易错 | 正确 |
|------|------|
| 所有扩展头每台路由器都解析 | 仅 **逐跳选项** 必须逐跳处理 |
| IPv6 路由器仍可分片 | **仅源主机**分片；过大 → **Packet Too Big** |
| Next Header 只在主头里 | **每个**头部都有 Next Header，形成链 |

## 六、Lab / 抓包

| 过滤器（Wireshark） | 用途 |
|---------------------|------|
| `ipv6` | 所有 IPv6 |
| `ipv6.nxt == 0` | 逐跳选项头 |
| `ipv6.nxt == 44` | 分片头 |
| `ipv6.nxt == 6` | 主头后直接 TCP（无扩展头或链末为 TCP） |

展开 IPv6 包时沿 **Next Header** 字段**逐层下钻**，可验证扩展头链顺序。
