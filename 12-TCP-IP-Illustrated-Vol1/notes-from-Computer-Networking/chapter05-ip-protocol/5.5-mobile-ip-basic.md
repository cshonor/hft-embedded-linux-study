## 零、易混辨析：住宅 IP（Residential）≠ 移动 IP 里的家乡地址

**结论先说**：日常说的 **「住宅 IP」** 与移动 IP 协议里的 **MN / 家乡地址（HoA）** **完全两个体系** — 只是中文都带「住宅/家乡」，极易混。

### 1）日常说的「住宅 IP」（Residential IP）

| 项 | 说明 |
|----|------|
| **一句** | **运营商分给普通家庭宽带的公网 IP** |
| **来源** | 电信/联通/移动家宽拨号（如 `113.xxx.xxx.xxx`） |
| **特点** | 对应**真实家庭用户**出口；风控常当**真人**；可**静态**或**动态**（重拨会变） |
| **归属** | 公网 IP 的**用途/归属地分类**（相对机房 IP、数据中心 IP） |
| **与移动 IP** | **无关** — 不参与 MN/HA/CoA 协议 |

你在家里上网，对外出口就是一个 **住宅 IP**。

### 2）移动 IP 里的 MN、家乡地址 HoA、CoA

| 术语 | 含义 |
|------|------|
| **移动 IP** | 设备跨网漫游时**保持同一逻辑 IP、连接不断**（公司 Wi‑Fi → 家 → 4G） |
| **MN** | **Mobile Node** = 会跑的终端（手机、笔记本）— **是设备，不是 IP** |
| **家乡地址 HoA** | MN 的**永久逻辑 IP**（「身份证号」）；对外**长期用 HoA**；属**家乡网络** |
| **CoA** | **Care-of Address** = 当前接入网的**临时 IP**（外地位置） |

**数据路径（在外地）**：

```text
通信方 → 发往 HoA（家乡）→ HA 截获 → 隧道 → CoA（当前位置）→ MN
```

> 课本有时把 HoA 译成「归属地址/住宅地址」→ 勿与 **Residential 住宅 IP** 混为一谈。

### 3）一句话对比

| | **住宅 IP（日常）** | **家乡地址 HoA（移动 IP）** |
|---|---------------------|------------------------------|
| **强调** | 我家宽带的**公网出口**，来源是**家庭** | 这台设备的**固定身份 IP**，**位置可动** |
| **体系** | 公网 IP **类型/风控分类** | **Mobile IP 协议**逻辑概念 |
| **是否一定是家宽** | **是**（定义即家庭宽带） | **否** — HoA 可是内网或公网，≠ 家宽 IP |

### 4）极简对照表（考试/理解）

| 名词 | 属于什么 | 核心意思 |
|------|----------|----------|
| **住宅 IP（Residential）** | 公网 IP 类型 | 家庭宽带分配的 IP，真实用户 |
| **MN** | 移动 IP 协议 | 会移动的终端（手机/笔记本） |
| **家乡地址 HoA** | 移动 IP 协议 | MN 的永久固定 IP（**身份**） |
| **转交地址 CoA** | 移动 IP 协议 | MN 当前网络的临时 IP（**位置**） |

### 5）移动 IP 工作流程简图

```mermaid
flowchart LR
  CN[通信方] -->|目的=HoA| HA[HA 家乡代理]
  HA -->|IP-in-IP 隧道 外层目的=CoA| MN[MN @ 外地网络]
  MN -.->|注册 CoA| HA
```

| 步骤 | 说明 |
|------|------|
| ① | MN 在外地获 **CoA**，向 **HA** **注册** |
| ② | HA 维护 **HoA ↔ CoA** 映射 |
| ③ | 发往 **HoA** 的包到家乡网 → **HA 隧道** → **CoA** → MN |

→ 在家无 CoA、直连：[§四 在家 vs 外地](#ch05-5-home-away) · 角色详解：[§一](#ch05-5-roles)

## 一、核心角色

| 术语 | 全称 | 作用 |
|------|------|------|
| **MN** | 移动节点（Mobile Node） | 可跨网络漫游的终端；对外**固定使用家乡地址**通信 |
| **HA** | 家乡代理（Home Agent） | 部署在 MN **家乡网络**；**注册中心 + 数据转接点**（见下） |
| **CoA** | 转交地址（Care-of Address） | MN 接入**外地网络**时获得的**临时 IP**；标识当前物理位置 |

### HA 的双重角色（易漏考点）

| 角色 | 做什么 |
|------|--------|
| **① 注册中心** | MN 在外地拿到 **CoA** 后**注册**给 HA；HA 建立 **`家乡地址 → CoA`** 映射表 |
| **② 数据转接** | 外部仍发往**老家乡地址**的包到达 HA → 查映射 → **隧道封装**转发到当前 **CoA** → MN 在外地收到 |

**一句**：HA **不光登记** MN 在哪，还要靠 **CoA 映射帮 MN 转接数据**，让外面的人**不用改目的地址**就能找到**已经移走**的 MN。

```text
外部 ──(目的仍是 10.0.0.2)──► HA ──查表 10.0.0.2→20.1.1.3──► 隧道 ──► MN @ CoA
```

```text
通信方 ──(目的=家乡地址)──► 家乡网络 ──► HA 截获
                                              │
                                    IP 隧道封装（外层目的=CoA）
                                              ▼
                                         MN @ 外地网络
```

### 大白话：三个词各指什么？（易混）

| 词 | 指什么 | 不是什么 |
|----|--------|----------|
| **MN** | **移动节点** = 那台会跑来跑去的**设备本身**（手机、笔记本） | 不是「一个 IP 号码」；IP 是挂在 MN 上的 |
| **家乡地址** | MN **归属**的逻辑 IP（如 `10.0.0.2`），对外**长期不变** | 在家时 MN **直接用这个地址**上网 |
| **CoA** | **同一台 MN** 在外地网络拿到的**临时 IP**（如 `20.1.1.3`） | **不是另一台主机**；是「这台设备**此刻**在哪、从哪接入」的地址 |
| **HA** | 家乡网络里的**注册中心 + 转发枢纽** | 不是 MN 本人；是**替所有归属本网的 MN** 做登记和隧道转接的设备/网关 |

**对照你的说法**：  
- ✅ HA = **注册 + 转发**，没错。  
- ⚠️ MN = **设备**；「本地注册的主机**地址**」更准确叫 **家乡地址**；CoA 是**同一设备**在外地的临时地址。

### HA 有多少台？一用户一台吗？

| 问题 | 答案 |
|------|------|
| 一用户一 HA？ | **否** — 不会给每个 MN 单独配一台 HA |
| 实际部署 | 通常 **一个区域 / 一个运营商网络 / 一个校园网** 部署 **一台（或一套）HA** |
| 管谁 | 管理**所有归属该家乡网络**的 MN 的 **CoA 注册表** 与 **隧道转发** |
| 例子 | 某高校校园网设 **一个 HA** → 管全校师生笔记本、手机漫游 |

→ 蜂窝网里「漫游锚点」也是类似思路：**运营商级**共享设施，不是一人一锚点。

<a id="ch05-5-design"></a>

## 二、核心设计思路

| # | 要点 |
|---|------|
| 1 | **通信地址不变**：无论 MN 漫游到哪，对外始终用**家乡地址** → 上层应用**无感知** |
| 2 | **流量转发机制**：HA 与 MN 间建立**双向 IP 隧道** → 往来流量经隧道转发至 MN 当前 **CoA** |
| 3 | **核心思想**：**地址间接寻址（indirection）** — 屏蔽终端网络位置变化 |

**与常规路由对比**：正常 IP 寻址 = 目的地址即物理可达位置；Mobile IP = 目的地址**固定在家乡**，真实位置由 **CoA + 隧道**间接到达。

→ 隧道封装：[ch03 §3.9 隧道基础](../chapter03-link-layer/3.9-tunnel-basics.md)

<a id="ch05-5-flow"></a>

## 三、基础工作流程

| # | 步骤 |
|---|------|
| 1 | MN 在**外地网络**上线，获取本地 **CoA**，向 **HA 注册**当前 CoA |
| 2 | HA 记录映射：**家乡地址 ↔ CoA** |
| 3 | 通信方发往 MN **家乡地址**的报文，路由至家乡网络，由 **HA 截获** |
| 4 | HA 将报文**封装进 IP 隧道**（如 IP-in-IP），外层目的 = **CoA**，转发至外地 |
| 5 | MN **回程**报文可**直连**通信方，或同样经隧道回传（**双向隧道**） |

### 咖啡馆案例（MN 离开公司）

1. MN 在外地通过 DHCP 获 **CoA**，向 **HA** 注册  
2. 外部仍发往 MN **原 IP（家乡地址）** 的包被 **HA** 拦截  
3. HA **IP-in-IP 隧道**封装，外层目的 = **CoA** → MN 在外地收到内层原报文

## 四、在家 vs 在外地（必分清）

**关键**：CoA 与隧道**只在 MN 离开家乡网络时才启用**；在家时 HA 就是普通网关，**不走 Mobile IP 隧道**。

### 场景 A：MN 在家（本地，无 CoA）

| 项 | 说明 |
|----|------|
| **MN 地址** | 家乡地址 **`10.0.0.2`**（就在家乡子网内） |
| **CoA** | **无** — MN 物理就在家乡网，不需要转交地址 |
| **HA 角色** | 正常当**默认网关**（或子网内直连） |
| **数据路径** | 通信方 ↔ **`10.0.0.2`** **直接来回**，与普通主机无异 |

```text
通信方 ──► 10.0.0.2 (MN 在家乡 LAN)     直接交付，无隧道
         HA 仅作网关时：MN 出网经 HA 转发，但不截获「发往 10.0.0.2」的包做隧道
```

### 场景 B：MN 在外地（漫游，启用 CoA + 隧道）

| 项 | 说明 |
|----|------|
| **MN 逻辑地址** | 对外仍是 **`10.0.0.2`**（家乡地址不变） |
| **CoA** | 在外地外网拿到临时地址，如 **`20.1.1.3`** |
| **注册** | MN 把 **CoA 20.1.1.3** 报给 **HA** |
| **HA 映射** | **`10.0.0.2 → 20.1.1.3`** |
| **入向数据** | 发往 **`10.0.0.2`** 的包 → HA 截获 → **隧道封装** → 外层目的 **`20.1.1.3`** → MN 在外地收到 |
| **回程** | MN 发往外部的包常可**直连**（源 IP 仍可用 `10.0.0.2` 或经 HA，视实现） |

```text
通信方 ──(目的 10.0.0.2)──► 家乡网 HA
                              │ 查表：10.0.0.2 → CoA 20.1.1.3
                              └── 隧道 ──► 20.1.1.3 ──► MN @ 外地
```

### 对照表（考点）

| | **在家（本地）** | **在外地（漫游）** |
|---|------------------|---------------------|
| **CoA** | **不需要** | **必须有**（如 `20.1.1.3`） |
| **HA** | 普通**网关** | **锚点 + 隧道端点** |
| **发往 10.0.0.2 的包** | **直连** MN | HA **截获并隧道**到 CoA |
| **隧道** | **无** | **有** |

**一句**：在家 = 普通 IP 上网；外出 = 注册 CoA → HA 维护映射 → **隧道间接投递**。

| 点 | 说明 |

## 七、实例：手机蜂窝跨省漫游（对照模型）

用**湖北手机号出省上网**理解课本 Mobile IP — 好记、也对应考点。

### 1. 理论对应（Mobile IP ↔ 手机漫游）

| 移动 IP | 手机漫游（例：湖北卡） |
|---------|------------------------|
| **MN** 移动节点 | **手机** |
| **家乡网络** | **湖北**运营商网络（归属地） |
| **家乡地址** | 运营商分配、**逻辑归属湖北**的 IP / 用户身份 |
| **HA** 家乡代理 | 湖北运营商核心网关 / **漫游锚点** |
| **外地网络** | 出差所在**外省**基站网络 |
| **CoA** 转交地址 | 在外省基站拿到的**本地临时 IP** |

### 2. 网络层面（全国通用流量时代）

| # | 步骤 |
|---|------|
| 1 | 到外省，手机连当地基站 → 获**本地 CoA 临时 IP** |
| 2 | 当地基站将位置、临时 IP 上报**归属地（湖北）漫游锚点**（≈ **HA**） |
| 3 | 外网数据 → 先路由到**湖北归属网络** → 归属地**隧道封装** → 转发至当前外省 **CoA** |

```text
外网 ──► 湖北归属网(HA) ──隧道──► 外省 CoA ──► 手机(MN)
```

**一句**：工程上就是 Mobile IP 的 **间接寻址 + 隧道转发**（实现多为 **LTE/5G / PMIPv6** 类架构，非 RFC 3344 原教旨）。

### 3. 流量计费 & 归属（常问）

| 项 | 现行（三大运营商主流） |
|----|------------------------|
| **全国通用流量** | 在湖北或**任意省份**使用，**统一扣套餐通用流量**，**无额外漫游费** |
| **不存在** | 「到外地单独算一种漫游流量费」（早年规则已取消） |

| 对比 | 早年 | 现在 |
|------|------|------|
| 套餐 | **省内流量** + **国内漫游流量** 分开；出省优先扣漫游，用完加价 | 多数套餐标注**全国通用** |
| 老套餐残留 | — | 少数仍有**省内专属流量** → 出省**不能用省内包**，自动走**全国通用** |

### 4. IP 表现小细节

| 观察 | 说明 |
|------|------|
| **公网 IP 归属地** | 人在外地，上网 IP 常显示为**当前省份**出口（用当地 CoA/当地 PGW） |
| **账号 / 资费归属** | 仍是**湖北**（归属地不变）→ 对应「**逻辑家乡地址 / 身份不变**」 |

### 5. 串起来（考点）

| # | 要点 |
|---|------|
| 1 | 手机漫游 = **工程化 Mobile IP**：位置变（**CoA 变**），归属身份 / 逻辑地址**不变** |
| 2 | 运营商核心网 **HA 锚点 + 隧道** → 无缝上网 |
| 3 | 资费：**国内无跨省流量漫游额外收费**（通用流量全国通） |
| 4 | 协议演进：**PMIPv6、LTE/5G 代理移动** — 思想同课本，实现更轻量 |

**一句话**：湖北卡去外地上网，扣套餐**全国流量**不加漫游费；网络上靠运营商**漫游隧道**转发，与课本 Mobile IP **逻辑一致**。

## 八、家乡地址 HoA 何时绑定网卡？（蜂窝工程视角）

**一句话**：系统网卡绑定**家乡地址 HoA**，是在设备**第一次接入「自己的家乡网络」**时，由运营商/网络侧分配、写入网卡配置，**长期固定不变**（卡/号不变则基本终身不变）。

> 课本：**MN** = 设备；**HoA（Home Address）** = 家乡地址。下文「APP 看到的 MN」指 **HoA 这个逻辑身份 IP**。

### 分阶段时间线

| 阶段 | 何时 | 发生什么 |
|------|------|----------|
| **① 永久绑定** | **第一次**在**归属地（家乡）**开机入网（办号、首次注册运营商） | 核心网分配**长期固定 HoA** → 写入系统/蜂窝网卡配置 → **网卡 ↔ HoA 绑定完成**；此后系统**永远对外宣称**此地址 |
| **② 在家重连** | 在家乡重启、飞行模式、断网重连 | **自动复用**已绑定的 HoA，**不重新分配**；APP 新建连接仍用 HoA 作源地址 |
| **③ 外地漫游** | 出省/出国，拿到底层 **CoA** | **HoA 绑定不动**；CoA 仅底层路由/隧道用；**APP 仍只认 HoA**，不知道 CoA |
| **④ 关机换网** | 正常关机、换 Wi‑Fi、换基站 | **HoA 不变**；仅 **换号/换卡/运营商重分配** 才会换 HoA |

### APP 怎么「记住」HoA？

| 易混 | 事实 |
|------|------|
| APP 自己缓存 MN | **否** — **系统网卡**从首次在家入网就绑定了 HoA |
| APP 每次拿本机地址 | 调系统接口 → 拿到的**永远是 HoA**；对端记录的源地址也是 HoA |
| 漫游后 APP 要改地址 | **否** — 全程 **运营商分配 → 系统绑定 → APP 直接用 → 漫游也不变** |

### 三句话精炼（可插总结）

1. **HoA 在首次在家乡网络入网时由运营商分配并写入网卡，卡不变则终身不变。**  
2. **漫游只加底层 CoA，HoA 绑定与 APP 可见的本机地址都不变。**  
3. **不是 APP 记地址，是系统网卡从第一次就固定了对外身份。**

## 九、速记要点

| # | 要点 |
|---|------|
| 1 | 三大角色：**MN**（设备）、**HA**（注册+转接）、**CoA**（外地临时 IP，**同一设备**） |
| 2 | **家乡地址永久不变**，靠 **隧道 + CoA** 完成漫游转发 |
| 3 | 底层逻辑：**间接寻址（indirection）** |
| 4 | 现代：**LTE / PMIPv6** 演进；HA/锚点多为**区域/运营商级**，非一用户一台 |

| 易错 | 正确 |
|------|------|
| CoA 是对外通信地址 | 对外仍是**家乡地址**；CoA 仅**当前位置**（**在家无 CoA**） |
| 在家也用隧道 | **仅在外地**注册 CoA 后才走 HA 隧道；在家**直连** |
| HA 只是注册中心 | **注册 + 转接**：靠 **CoA 映射**隧道转发，外部仍用**家乡地址**寻址 |
| HA 转发所有回程流量 | 回程常可**直连**；**入向**才经 HA 隧道转接 |
| 手机 4G/5G = 传统 Mobile IP | 多为 **LTE/PMIPv6** 等，概念相通实现不同 |
| 出省上网加漫游流量费 | 现行**全国通用流量**统一扣费，**无额外漫游费**（见 [§七 蜂窝实例](5.5-mobile-ip-basic.md#ch05-5-cellular)） |
| APP 漫游后要换本机 IP | **系统网卡**首次在家绑定 **HoA**；APP 永远拿 HoA，**CoA 对 APP 不可见** → [§八](5.5-mobile-ip-basic.md#ch05-5-hoa-bind) |
| 住宅 IP = 移动 IP 家乡地址 | **无关** — 住宅 IP=家宽公网类型；HoA=协议**逻辑身份** → [§零](5.5-mobile-ip-basic.md#ch05-5-residential) |

---

## 疑问与总结

**背：MN+HA+CoA；家乡地址不变；HA 隧道到 CoA；indirection。**
