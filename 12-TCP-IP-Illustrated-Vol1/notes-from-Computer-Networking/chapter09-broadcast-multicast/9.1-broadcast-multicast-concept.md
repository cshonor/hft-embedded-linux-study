# 9.1 引言：单播 / 广播 / 组播

> 章级精读：[study.md#ch09-1](./study.md#ch09-1) · 广播详：[9.2](9.2-ipv4-broadcast-address.md) · 组播地址/MAC：[9.3](9.3-multicast-mac-mapping.md) · IGMP Snooping：[9.4](9.4-igmp-mld-snooping.md)

## 本节核心目标

区分 **单播 / 广播 / 组播** 的定义、**局域网内本质差异**与**本地链路**范围 — 澄清「LAN 里看起来一样」的误区。

<a id="ch09-1"></a>

**核心结论**：局域网二层环境下**观感可能相似**，但**本质、机制、使用场景完全不同** — **并非没有区别**。

---

<a id="ch09-1-def"></a>

## 一、基础定义

### 1. 广播（Broadcast）

| 项 | 说明 |
|----|------|
| **IPv4** | 主机位全 1（如 `192.168.1.255`）或 **`255.255.255.255`** 受限广播 |
| **语义** | **一对全体** — 本子网所有主机 |
| **二层 MAC** | **`FF:FF:FF:FF:FF:FF`** |
| **规则** | 本网段**所有主机网卡都会接收、上送协议栈** — **无法选择性拒绝** |
| **路由** | 路由器**默认不转发** |

→ 详：[9.2 广播](9.2-ipv4-broadcast-address.md)

### 2. 组播（Multicast）

| 项 | 说明 |
|----|------|
| **IPv4** | **`224.0.0.0/4`**（224～239） |
| **语义** | **一对多（指定群体）** |
| **二层 MAC** | **组播 MAC**，IPv4 映射前缀 **`01:00:5E`** |
| **规则** | **只有加入对应组播组的主机才接收**；未加入者网卡/栈可**直接丢弃** |
| **路由** | **`224.0.0.0/24` 不跨路由**；其余段可配 **PIM** 跨网段 → [9.3 §传播](9.3-multicast-mac-mapping.md#ch09-3-scope) |

### 3. 单播（对照）

| 模式 | 语义 | 典型范围 |
|------|------|----------|
| **单播** | 一对一 | 全球路由 |
| **广播** | 一对子网内**全部** | **不跨路由器** |
| **组播** | 一对**订阅组** | LAN + 可控域；Internet 组播另论 |

<a id="ch09-1-lan-diff"></a>

## 二、局域网内核心区别（重点）

### 1. 接收对象不同（最关键）

| | **广播** | **组播** |
|---|----------|----------|
| **发给谁** | **网段内所有设备** — 不管需不需要 | **主动加入该组的设备** |
| **无关设备** | 也要收帧、上送协议栈处理 | 底层**直接过滤**，开销极小 |
| **例** | **ARP**、**DHCP Discover** — 全网收到 | 视频流、服务发现 — 仅订阅者 |

### 2. 底层 MAC 与过滤机制不同

| | **广播** | **组播** |
|---|----------|----------|
| **MAC** | 固定 **`FF:FF:FF:FF:FF:FF`** | **`01:00:5E` + 映射** |
| **交换机** | **泛洪**到所有端口 | **IGMP Snooping** 可只转发到**有成员的端口** → [9.4 加组/IGMP](9.4-igmp-mld-snooping.md#ch09-4-join-principle) |

### 3. 设计初衷不同

| | **广播** | **组播** |
|---|----------|----------|
| **用途** | **地址解析、初始发现**（尚无 IP/未建立通信）— **兜底** | **一对多数据流**（直播、监控、路由同步）— **批量分发** |
| **典型** | ARP、DHCP、NetBIOS | OSPF 组播、IPTV、视频会议 |

### 4. 扩展能力不同

| | **广播** | **组播** |
|---|----------|----------|
| **跨网段** | **永远无法**（路由器隔离） | 配置 **IGMP + PIM** 等**可跨路由器** |
| **链路本地** | 限本网段 | **`224.0.0.0/24`** 同样限本网段，与广播「范围感」相近 |

<a id="ch09-1-myth"></a>

## 三、误区：「局域网里看起来没区别」

### 为何观感相似？

| 场景 | 说明 |
|------|------|
| **① 低端交换机无 IGMP Snooping** | 组播帧被**像广播一样泛洪**到所有端口 → **行为表现一致**，**协议本质未变** |
| **② 链路本地组播 `224.0.0.0/24`** | 路由器不转发，与广播一样**限本网段** → 加深「差不多」错觉 |

### 处理逻辑仍不同（考点）

| | **广播** | **组播** |
|---|----------|----------|
| **未订阅设备** | **系统层都要解析**报文（至少到 L3/L4 判丢弃） | **没加组的主机**，网卡/驱动可**硬件丢包**，**CPU 不参与** |

**一句**：交换机泛洪是**实现偷懒**；广播 vs 组播的**语义与主机处理路径**仍然不同。

<a id="ch09-1-compare"></a>

## 四、极简对比总结

| 特性 | **广播** | **组播** |
|------|----------|----------|
| **通信模型** | 一对**全部** | 一对**指定群组** |
| **接收权限** | **强制接收**，无法拒绝 | **主动加组**才接收 |
| **跨路由** | **不支持** | 配置组播路由**可支持** |
| **设备开销** | **高** — 全网都要处理 | **低** — 仅组成员 |
| **典型用途** | ARP、DHCP、全网通知 | 视频流、路由协议、群组数据 |

<a id="ch09-1-why-local"></a>

## 五、为何强调「本地」

- 广播/无控组播若全球转发 → **风暴**、路由器状态爆炸。
- 本章聚焦 **LAN 上的 IGMP/MLD + 交换机行为**。

→ 地址段：[ch02 §2.5](../chapter02-ip-address-architecture/2.5-special-address.md)

<a id="ch09-1-cheat"></a>

## 考点速记

| # | 要点 |
|---|------|
| 1 | LAN 里**观感可似**，**本质不同** — 广播=全员；组播=订户 |
| 2 | 广播 MAC **FF:FF…** 泛洪；组播 **01:00:5E** + **Join/IGMP** |
| 3 | 无 Snooping 时组播**表现像**广播，但**未加组可硬件丢** |
| 4 | 广播**永不跨路由**；组播**可配 PIM 跨网** |
| 5 | 广播=发现兜底；组播=一对多流 |

| 易错 | 正确 |
|------|------|
| 局域网广播组播没区别 | **接收对象、MAC、跨路由、CPU 开销**均不同 |
| 组播一定比广播省交换机带宽 | **无 IGMP Snooping** 时交换机仍可能**泛洪** |
| 组播和广播都不能跨路由 | **组播可**（非 `224.0.0/24` + PIM）；广播**永远不能** |

---

## 疑问与总结

**背：广播=全员强制收；组播=加组才收；无 Snooping 表现像广播但主机逻辑不同；广播不跨路由，组播可跨。**
