<a id="ch03-3-duplex"></a>

## 一、双工模式：半双工 vs 全双工

### 1）半双工（Half-duplex）

| 项 | 说明 |
|----|------|
| 行为 | 同一时刻**只能发或只能收**，不能同时进行 |
| 机制 | 依赖 **CSMA/CD** 防碰撞 |
| 场景 | **Hub**、老旧**共享式**以太网 |

### 2）全双工（Full-duplex）

| 项 | 说明 |
|----|------|
| 行为 | 收发**物理分离**，**可同时发+收** |
| 冲突 | 交换机**点对点**链路，**CSMA/CD 基本失效、冲突消失** |
| 场景 | 现代**交换机 + 网线**默认全双工；**千兆及以上**几乎只用全双工 |

<a id="ch03-3-autoneg"></a>

## 二、自动协商（Auto-negotiation）

### 1）协商什么

两端自动匹配共同支持的：

- **速率**：10 / 100 / 1000 Mbps  
- **双工**：半双工 / 全双工  
- **流控**（可选）

**优先级（速率越高越优；同速率下全双工 > 半双工）**

```text
1000M 全双工 > 1000M 半双工 > 100M 全双工 > 100M 半双工 > 10M 全双工 > 10M 半双工
```

### 2）标准规定

| 速率 | 自动协商 |
|------|----------|
| **10/100M** | **可选**（可关） |
| **1000M（千兆）** | **强制开启**，**不能关闭** |

### 3）核心规则（考试必背）

| 情况 | 结果 |
|------|------|
| **两端都自动协商** | 通常协商到**最优**（多为**全双工**） |
| **一端强制全双工、另一端自动协商** | 自动协商端常降级为**半双工** → **双工不匹配** → **大量丢包、延迟高** |
| **光纤以太网** | **不支持**自动协商 → **必须手动**配速率/双工 |

<a id="ch03-3-cheat"></a>

## 三、10 行极简背诵版

1. **半双工**：收发不能同时；要 **CSMA/CD**；Hub 时代。  
2. **全双工**：可同时收发；交换点对点**无经典冲突**。  
3. **自动协商**：匹配 **10/100/1000M + 半/全双工 + 流控**。  
4. 优先级：**速率优先，同速率全双工 > 半双工**。  
5. **千兆**：自动协商**强制开**。  
6. 两端自协商 → 通常**全双工最优**。  
7. 一端强全双工、一端自协商 → **半双工不匹配** → **丢包**。  
8. **光纤**：**手动配置**，不自协商。  
9. 全双工交换网：**CSMA/CD 基本消失**。  
10. 一句话：**自协商配速率双工；全双工交换无冲突。**

## 四、省电与唤醒（考点完整版）

<a id="ch03-3-magic-packet"></a>

### 1）WoL 与魔术包（Magic Packet）— 考试标准答案

#### 前置硬件条件

1. 电脑**关机/休眠**：**CPU、内存断电**，系统不运行  
2. 主板电源仍给**网卡待机低压电** → 网卡**超低功耗监听**  
3. **BIOS/UEFI + 网卡 + 系统**均开启 **WoL**

#### 魔术包结构（核心 · 固定 102 B）

```text
6 B 全 FF（FF FF FF FF FF FF） + 目标 MAC 重复 16 次（16 × 6 B = 96 B）
```

- 常通过 **UDP 端口 9**、**以太网广播帧** 发送  
- **二层（数据链路层）**；**不依赖 IP、不依赖 OS**

#### 完整工作流程

1. 发送端构造**魔术广播包**，在局域网内广播  
2. 关机主机**仅网卡**监听（CPU 不参与）  
3. 网卡识别：**6×FF 前缀** + **自身 MAC 连续 16 次**  
4. 网卡向主板**电源管理芯片**发**唤醒电信号**  
5. 主板上电 → 整机启动（等同按电源键）

#### 关键特点（必背）

| # | 要点 |
|---|------|
| 1 | **二层硬件触发**，OS **不必运行** |
| 2 | 靠**广播**，一般仅**同一局域网**可唤醒 |
| 3 | 只校验 **MAC**，不校验 IP |
| 4 | 识别与唤醒由**网卡硬件**完成，**CPU 不参与** |

#### 简答题 10 行背诵版

1. 关机/休眠：CPU、内存停；**网卡待机供电**监听。  
2. 须开 **BIOS + 网卡 WoL**。  
3. 魔术包 = **6×FF + MAC×16**（共 **102 B**）。  
4. 常用 **UDP/9**、**广播帧**、**二层**。  
5. 发送端发广播魔术包。  
6. 网卡独立监听，**系统不运行**。  
7. 匹配 **FF 前缀 + 本机 MAC×16**。  
8. 网卡触发**主板电源芯片**。  
9. 整机唤醒。  
10. **同网段广播**；**纯硬件、不认 IP**。

### 2）IEEE 802.3az（EEE，高效节能以太网）

- 链路**空闲** → 端口**低功耗休眠**（收发电路降耗）  
- **有流量** → 快速唤醒，恢复 **100M/1000M** 等协商速率  
- 交换机常见：**Auto-Power-Down** — 无链路/空闲时**停供端口电**

### 3）Wi‑Fi 省电（补充）

- **802.11 Power Save**：STA 定时休眠，**AP 缓存**待发数据，终端定期唤醒收包 → [3.5](./3.5-wireless-80211.md)

### 填空 / 简答精简版

1. **WoL**：休眠靠**网卡低功耗监听**；**6×FF + MAC×16** 魔术包唤醒  
2. **EEE（802.3az）**：端口**空闲休眠、有流唤醒**  
3. **核心**：省电 = 设备/端口**低功耗**；唤醒 = **二层特殊帧**触发

## 五、802.3x 流量控制（考试完整版）

> **与 Hub 无关**：802.3x / PAUSE 是**交换机、全双工网卡**的二层机制；Hub 是半双工一层设备，**不支持、也发不了 PAUSE** → [3.2 Hub 现状](./3.2-ethernet-ieee802-encapsulation.md#ch03-2-hub)

### 1）在哪完成？（标准定位）

**对，完全是交换机（二层）的事**（交换机 ↔ 交换机、交换机 ↔ 主机网卡均可发/收）。

| 项 | 说明 |
|----|------|
| **标准** | **IEEE 802.3x** 全双工流量控制 |
| **工作层** | **数据链路层（MAC 控制子层）** |
| **设备** | **交换机**、支持流控的**网卡** |
| **不用** | **Hub**（半双工、一层）、半双工以太网（靠 **CSMA/CD**） |

### 2）什么时候发 PAUSE？

**一句话**：**接收端**端口缓冲区**快满了** → 向**直连的发送端**发 PAUSE。

| 场景 | 谁可能发 |
|------|----------|
| 交换机 ↔ 交换机 | 任一侧端口拥塞都可发 |
| 交换机 ↔ 服务器/主机 | 交换机或网卡（若开启流控） |

**方向**：**谁要被“撑爆”，谁就发 PAUSE**（不是固定只有交换机发）。

### 3）PAUSE 帧机制（五步流程）

1. 接收端（交换机端口 / 网卡）**缓冲区将满**  
2. 向**直连**对端发 **PAUSE 帧**（见下节结构）  
3. 帧内 **Pause Time**：暂停时长，单位 = **512 bit 时间**（0～65535）  
4. 发送端收到后**暂停该链路发送**一段时间，等对端清空缓存  
5. **逐跳（hop-by-hop）**：只控**相邻一跳**，**不能跨多台交换机**传播

### 4）Type 字段：0x8808 是什么？

以太网帧 **2 字节 Type/Length**：

| Type | 含义 |
|------|------|
| **0x0800** | 普通数据 · **IPv4** |
| **0x0806** | **ARP** |
| **0x8808** | **MAC 控制帧**（再看 Opcode 区分种类） |
| **0x8809** | LACP（链路聚合，见 [3.2](./3.2-ethernet-ieee802-encapsulation.md#ch03-2-advanced)） |

**PAUSE**：Type = **`0x8808`** + Opcode = **`0x0001`** → 表示「请暂停发送」。

### 5）目的 MAC 为何是「组播」？

MAC 分三类：

| 类型 | 特征 | 示例 |
|------|------|------|
| **单播** | 给一个设备 | `00-xx-xx-xx-xx-xx` |
| **组播** | 给一组设备；**首字节最低位 = 1** | PAUSE、IPv4 组播映射等 |
| **广播** | 所有人 | `ff:ff:ff:ff:ff:ff` |

→ MAC 与 IPv4 组播/广播**判定规则不同、非一一绑定**：[ch09.3 完整对照](../../chapter09-broadcast-multicast/9.3-multicast-mac-mapping.md)

**PAUSE 固定目的 MAC（保留组播，与 IP 无关）**：

```text
01-80-C2-00-00-01
```

支持 802.3x 的设备识别该 DA；**开启流控的端口才响应**。

### 6）PAUSE 帧完整结构（按字节）

最小以太网帧 **64 字节**（不含前导码时常记载荷部分）：

| 字段 | 长度 | 值 / 说明 |
|------|------|-----------|
| 前导码 + SFD | 8 | 7 B 前导 + 1 B 帧起始（硬件用） |
| **目的 MAC（DA）** | 6 | **`01-80-C2-00-00-01`**（固定组播） |
| **源 MAC（SA）** | 6 | 发送方端口 MAC |
| **Type** | 2 | **`0x8808`**（MAC 控制帧） |
| **Opcode** | 2 | **`0x0001`**（= PAUSE） |
| **Pause Time** | 2 | 暂停时间（×512 bit 时间） |
| **Padding** | 42 | **全 0**，凑满最小帧 |
| **FCS** | 4 | CRC 校验 |

> **三数必背**：DA **`01-80-C2-00-00-01`** · Type **`0x8808`** · Opcode **`0x0001`**

### 7）关键特点（必背）

| 项 | 说明 |
|----|------|
| 工作层 | **二层 MAC 控制**，与上层协议无关 |
| 范围 | **只控直连链路**，**不能跨设备** |
| 粒度 | 暂停**整条链路所有流量**（不能只停某业务） |
| 扩展 | **802.1Qbb（PFC）**：按 **802.1p PCP** 优先级**单独暂停**某类流量 |

### 8）与 TCP 拥塞控制（高频）

| | **802.3x PAUSE** | **TCP 拥塞控制** |
|---|------------------|------------------|
| 层次 | **二层**，链路/MAC | **四层**，端到端 |
| 范围 | **逐跳**，相邻端口 | **全网**，主机之间 |
| 目的 | 防**端口缓存**溢出 | 防**网络整体**拥塞 |
| 关系 | 与 TCP **独立**；可同时存在 |

### 5）简答题 10 行标准答案

1. **802.3x**：**全双工**以太网**二层**流控。  
2. 仅**点对点直连**；半双工用 CSMA/CD。  
3. 接收端拥塞 → 发 **PAUSE**（**0x8808**，MAC **01:80:C2:00:00:01**）。  
4. 携带暂停时间（**512 bit 时间**单位）。  
5. 发送端**暂停整条链路发送**。  
6. **逐跳**防缓冲区溢出。  
7. **不能跨交换机**传播控制。  
8. **不能**只停某一业务（PFC 除外）。  
9. **≠ TCP**：TCP 是**四层端到端**拥塞控制。  
10. 一句：**二层 PAUSE 逐跳停链路；TCP 四层端到端控拥塞。**

### 10）六问速记（你问的六个点）

| # | 问题 | 答案 |
|---|------|------|
| 1 | 在交换机上完成？ | **是**，二层；**Hub 不行** |
| 2 | 何时发？ | 接收端缓冲**快满** → 对**直连**发送端发 PAUSE |
| 3 | Type 多少？ | **`0x8808`**（MAC 控制帧） |
| 4 | 目的 MAC？ | 固定组播 **`01-80-C2-00-00-01`** |
| 5 | Opcode？ | **`0x0001`** = PAUSE |
| 6 | 与 TCP？ | PAUSE **逐跳链路**；TCP **端到端**拥塞 |

1. 全双工交换端口还需要 CSMA/CD 吗？为什么？
