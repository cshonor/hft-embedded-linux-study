# 13.5 TCP 状态转换

> 章级精读：[../study.md#ch13-5](../study.md#ch13-5) · 自顶向下状态机：[§3.1](../../../top_down/03_transport_layer/study.md#ch3-1-tcp-conn)

## 本节核心目标

熟记核心状态与 **TIME_WAIT（2MSL）**；理解端口耗尽。

---

## 常见状态

| 状态 | 含义 |
|------|------|
| **LISTEN** | 服务端等待连接 |
| **SYN_SENT / SYN_RCVD** | 握手中间态 |
| **ESTABLISHED** | 可传数据 |
| **FIN_WAIT_1/2** | 主动关闭方 |
| **CLOSE_WAIT** | 被动方已收 FIN，应用未 close |
| **TIME_WAIT** | 主动关闭方等待 **2MSL** |
| **CLOSED** | 结束 |

---

## TIME_WAIT 为何存在

1. 确保最后 **ACK** 可达（若丢对端会重 FIN）
2. 让旧连接**迷途段**在网络中消亡，避免串入**同四元组新连接**

---

## 实战痛点（Go/Rust）

| 现象 | 原因 | 解法 |
|------|------|------|
| `Address already in use` | 监听端口在 TIME_WAIT | **SO_REUSEADDR** |
| `cannot assign requested address` | 客户端大量短连接占满**临时端口** TIME_WAIT | **Keep-Alive 复用连接**、调 `tcp_tw_reuse`（Linux 策略视场景） |

---

## CLOSE_WAIT 堆积

- 应用**未 close** 已 FIN 的连接 → 泄漏；查代码/FD 泄漏。
