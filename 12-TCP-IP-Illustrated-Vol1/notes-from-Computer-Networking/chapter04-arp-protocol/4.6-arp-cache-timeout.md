# 4.6 ARP 缓存超时

> 章级精读：[study.md#ch04-6-timeout](./study.md#ch04-6-timeout) · 缓存与状态：[4.3 §四 状态](4.3-arp-cache.md#ch04-3-states) · [4.3 §五 老化](4.3-arp-cache.md#ch04-3-timeout) · 抓包对照：[4.5 §超时](4.5-arp-tcpdump-example.md#ch04-5-timeout)

## 本节核心目标

理解 ARP 条目的**软状态**本质，以及**完整 / 不完整（INCOMPLETE）**两类条目的超时差异与刷新机制。

<a id="ch04-6-timeout"></a>

---

<a id="ch04-6-soft-state"></a>

## 一、核心概念：ARP 缓存为**软状态**

| 特性 | 说明 |
|------|------|
| **非永久** | 条目有生命周期，超时**自动删除** |
| **可刷新** | 通信触发可**重置**存活时间（完整条目） |
| **动态适配** | 终端上下线、网卡更换、IP/MAC 变更后，不长期保留错误映射 |

**一句**：ARP 缓存是**临时通讯录**，不是永久配置表（**手工静态绑定** `arp -s` / `ip neigh add` 除外）。

→ 缓存表结构与 Linux 状态机：[4.3](4.3-arp-cache.md#ch04-3-states)

---

<a id="ch04-6-complete"></a>

## 二、完整条目（已成功解析）

**状态**：已拿到目标 MAC，ARP 表正常显示 IP ↔ MAC 映射（Linux 常为 **REACHABLE** / **STALE**）。

| 项 | 典型值 / 行为 |
|----|----------------|
| **超时时长** | **默认约 20 分钟**（Linux/macOS 主流实现；不同系统略有浮动，区间 **数分钟～20 分钟**） |
| **Windows** | 常见约 **2 分钟**闲置可过期（短于 Linux） |
| **机制** | 条目**闲置倒计时**；期间再次通信会**重置超时计时器** |
| **STALE 路径** | 久未通信 → **STALE** → 下次发包前**探测** → 成功回 REACHABLE，失败则删条目 |
| **目的** | 淘汰离线、地址变更的**老旧映射** |

```text
首次 ARP 成功 → 写入完整条目 → 通信中刷新计时
                    ↓ 长期不用
              STALE → 再发包探测 → REACHABLE 或删除
                    ↓ 到期未刷新
                 自动删除 → 下次访问重新 ARP
```

→ 触发重新 ARP 的场景：[4.1 §三 触发条件](4.1-introduction.md#ch04-1-trigger)

<a id="ch04-6-incomplete"></a>

## 三、不完整条目（INCOMPLETE）

**状态**：已发送 ARP 请求，**尚未收到应答**；待发 IP 包常**排队等待**解析结果。

| 项 | 典型值 / 行为 |
|----|----------------|
| **超时时长** | **约 3 分钟**（远短于完整条目） |
| **重传** | 一般 **3 次** ARP 请求，间隔约 **1 s**（见 [4.5 抓包](4.5-arp-tcpdump-example.md#ch04-5-timeout)） |
| **机制** | 多次重传仍无响应 → **快速清理**无效条目 |
| **目的** | 避免无效条目占用内存 / 邻居表；减少无用重试 |

```text
缓存 Miss → 发 ARP 请求 → 写入 INCOMPLETE
                ↓ 无应答，~1 s 重试 ×3
           仍无应答 → ~3 min 后删除
                ↓ 上层
         ping 超时 / 可能 ICMP Host Unreachable
```

---

<a id="ch04-6-compare"></a>

## 四、两类条目对照

| 对比 | **完整条目** | **INCOMPLETE** |
|------|-------------|----------------|
| MAC | 已解析 | **未知** |
| 超时 | **长**（~20 min 为主） | **短**（~3 min） |
| 刷新 | 通信可**重置**计时 | 无（等应答或超时删） |
| 典型场景 | 正常通信 | 目标不存在 / 链路静默 |

<a id="ch04-6-lab"></a>

## 五、Lab：验证状态与超时

### 查看 ARP / 邻居表

```bash
# Linux：含 REACHABLE / STALE / INCOMPLETE 等状态
ip neigh
ip neigh show

# Windows
arp -a
```

### 观察 INCOMPLETE

```bash
# 同网段 ping 不存在的 IP
ping -c 1 192.168.1.99

# 立即查看（Linux）
ip neigh show 192.168.1.99
# 可能见：192.168.1.99 dev eth0  INCOMPLETE
```

### 观察完整条目老化（可选）

```bash
# 先建立条目
ping -c 1 192.168.1.1
ip neigh show 192.168.1.1   # REACHABLE

# 停止通信，等待 → STALE → 最终删除（时间因内核参数而异）
```

Linux 相关 sysctl（了解）：`net.ipv4.neigh.default.base_reachable_time_ms` 等。

<a id="ch04-6-cheat"></a>

## 六、考点速记

| # | 要点 |
|---|------|
| 1 | ARP 缓存是**软状态**；无永久动态条目（**静态绑定**除外） |
| 2 | **完整**：超时**长**（20 min 为主），支持**刷新** |
| 3 | **INCOMPLETE**：超时**极短**（~3 min），**快速清理** |
| 4 | 超时本质：**动态适配**网络设备地址变化 |

| 易错 | 正确 |
|------|------|
| 所有系统都是 20 min | **Windows 常更短**；Linux 可调内核参数 |
| INCOMPLETE 也会存 20 min | **约 3 min** 即删 |
| 超时 = 立即删表 | 完整条目常先经 **STALE + 探测** 再删 |

---

## 疑问与总结

**软状态 + 两类超时：成功映射养得久、失败解析清得快。**
