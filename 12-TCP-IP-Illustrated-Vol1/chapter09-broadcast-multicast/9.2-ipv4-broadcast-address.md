# 9.2 广播（Broadcast）

> 章级精读：[study.md#ch09-2](./study.md#ch09-2) · 单播/组播/MAC 映射：[9.3](9.3-multicast-mac-mapping.md) · Smurf：[ch08 §8.7](../chapter08-icmpv4-icmpv6/8.7-icmp-attacks.md) · DHCP/ARP：[ch06 §6.2](../chapter06-dhcp-config/6.2-dhcp-protocol.md) · ND 组播：[ch08 §8.5](../chapter08-icmpv4-icmpv6/8.5-ipv6-ndp.md)

## 本节核心目标

掌握 **IPv4 受限广播 vs 定向广播** 的区别与转发规则；理解 **IPv6 无广播、用组播替代** 的设计原因与典型地址。

<a id="ch09-2-limited"></a>

## 一、IPv4 广播类型

### 1. 受限广播（Limited Broadcast）

| 项 | 说明 |
|----|------|
| **地址** | **`255.255.255.255`** |
| **范围** | **仅本地链路（LAN）**；路由器**永不转发** |
| **用途** | 主机启动时**未知自身 IP/掩码** → **DHCP Discover**、**ARP 请求** |
| **二层** | 目的 MAC = **`FF:FF:FF:FF:FF:FF`**；交换机**泛洪**到所有端口 |

```text
DHCP Discover / ARP Request → 255.255.255.255 → 不跨路由 → 本网所有主机收到
```

→ [ch06 DORA](../chapter06-dhcp-config/6.2-dhcp-protocol.md#ch06-2-dora) · [ch04 ARP](../chapter04-arp-protocol/study.md)

---

<a id="ch09-2-directed"></a>

### 2. 定向广播（Directed Broadcast）

| 项 | 说明 |
|----|------|
| **地址** | **网络前缀 + 主机位全 1**（如 `192.168.1.255/24`） |
| **计算** | `定向广播 = IP \| (~subnet_mask)` |
| **范围** | 特定子网；**现代路由器默认丢弃**（防 **Smurf** 攻击） |
| **用途** | 早期跨子网管理、远程唤醒（WOL）；**现网极少用** |

**例**：`192.168.1.100/24` → 定向广播 **`192.168.1.255`**

→ Smurf：[ch08 §8.7](../chapter08-icmpv4-icmpv6/8.7-icmp-attacks.md)

---

<a id="ch09-2-compare"></a>

### 3. 对比表

| 特性 | **受限广播** | **定向广播** |
|------|-------------|-------------|
| **地址** | `255.255.255.255` | 子网主机位全 1（如 `192.168.1.255`） |
| **转发** | **不跨路由器** | **默认不转发**（可配置开启，现网禁） |
| **典型场景** | **DHCP、ARP** | 传统子网广播（**已淘汰**） |
| **安全风险** | 低（本地） | **高**（易被放大攻击） |
| **二层 MAC** | `FF:FF:FF:FF:FF:FF` | 通常同为 `FF:FF:FF:FF:FF:FF` |

<a id="ch09-2-impact"></a>

## 二、广播的影响

| 影响 | 说明 |
|------|------|
| **二层泛洪** | 所有端口收到 → **所有主机必须接收并处理**（至少到 L3 判丢弃） |
| **资源浪费** | 无关主机也耗 **CPU 与带宽** |
| **广播风暴** | 环路/异常流量 → 全网瘫痪；网络越大越严重 |
| **典型依赖** | **DHCP、ARP、NetBIOS** 等 |

**一句**：广播的代价是「**子网内每台机器都要碰一下**」— 组播用过滤把成本压到订户 → [9.3](9.3-multicast-mac-mapping.md)

<a id="ch09-2-v6"></a>

## 三、IPv6：无广播，用组播替代

### 1. 核心设计

| 项 | 说明 |
|----|------|
| **取消广播** | 避免「无差别全网推送」的低效与风险 |
| **组播替代** | 前缀 **`FF00::/8`** |
| **原理** | **只对感兴趣的节点发送** — 非组成员不处理 |

### 2. 关键组播地址（链路本地 `FF02::/16`）

| 地址 | 作用 |
|------|------|
| **`FF02::1`** | **所有节点** — 替代 IPv4 子网广播 |
| **`FF02::2`** | **所有路由器** |
| **`FF02::1:FFXX:XXXX`** | **请求节点组播**（Solicited-Node）— 替代 **ARP** |

### 3. 替代逻辑

| IPv4 | IPv6 |
|------|------|
| 子网广播 | **`FF02::1`** 等特定组播 |
| ARP 广播 | **NS** + Solicited-Node 组播 |

→ ND/MLD：[ch08 §8.5](../chapter08-icmpv4-icmpv6/8.5-ipv6-ndp.md) · [ch02 IPv6](../chapter02-ip-address-architecture/study.md)

<a id="ch09-2-cheat"></a>

## 四、考点 / 面试速记

| # | 要点 |
|---|------|
| 1 | **受限广播**：**`255.255.255.255`**，**不路由**，用于 **DHCP/ARP** |
| 2 | **定向广播**：主机位全 1，**默认丢弃**，防 **Smurf** |
| 3 | **IPv6 无广播** → **`FF02::1`** 等组播替代 |
| 4 | 广播危害：**泛洪 → CPU 浪费 → 风暴**；IPv6 组播更高效 |

| 易错 | 正确 |
|------|------|
| 定向广播可随意跨网转发 | **现代默认禁止**转发 |
| IPv6 有 255.255.255.255 等价物 | **无广播**；用 **FF02::/16** 链路组播 |
| 广播 MAC 随 directed/limited 变化 | 以太网目的 MAC **均为 FF:FF:FF:FF:FF:FF** |
| 组播 = 广播的 IPv6 版 | 组播是**按需订阅**，非全员洪泛 |

---

## Lab

```bash
# 受限广播（需 OS 允许）
ping 255.255.255.255

# 定向广播（现代 OS/路由常拒）
ping 192.168.1.255

# IPv6 全体节点（替代广播 ping）
ping ff02::1%eth0   # Linux 需指定接口
```

---

## 疑问与总结

**背：255.255.255.255 不路由→DHCP/ARP；x.x.x.255 定向默认禁；v6 无广播→FF02::1；广播=全员泛洪。**
